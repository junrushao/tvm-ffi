# d0d0e2f — feat: add Rust binding for `Array<T>` (#348)

## TL;DR
- Adds Rust `Array<T>` container type with full FFI compatibility with C++ `ffi::Array`
- Implements `AnyCompatible` trait for `Array<T>` enabling type-erased roundtrips through `Any`/`AnyView`
- Provides iterator support (`iter()`, `IntoIterator`, `FromIterator`) and `Index<usize>`
- Includes a fix to `Any::into_raw_ffi_any` to prevent double-drop via `ManuallyDrop`

## Why (intent / motivation)
- Enable Rust code to work with TVM-FFI's `Array` container, which is widely used for passing collections across language boundaries
- Complete the Rust binding story for core container types (Shape and Tensor were already supported)

## What changed (facts from diff)
- New file `rust/tvm-ffi/src/collections/array.rs` (341 lines):
  - `ArrayObj` repr(C) struct matching C++ layout: `object`, `data`, `size`, `capacity`, `data_deleter`
  - `Array<T>` generic wrapper with `ObjectArc<ArrayObj>` storage and `PhantomData<T>`
  - `ObjectRefCore` implementation for proper object lifecycle
  - `new()`, `new_with_capacity()`, `len()`, `is_empty()`, `get()`, `iter()` methods
  - `Index<usize>` returning `&AnyView<'static>`
  - `ArrayIterator` with `Iterator` impl
  - `FromIterator<T>` and `IntoIterator` impls
  - Full `AnyCompatible` impl with strict type checking that validates all elements
  - `TryFrom<Any>` and `TryFrom<AnyView>` conversions
- `rust/tvm-ffi/src/any.rs`: Fixed `into_raw_ffi_any` to wrap `this` in `ManuallyDrop` before extracting `.data` to prevent double-drop
- `rust/tvm-ffi/src/collections/mod.rs`: Added `pub mod array`
- `rust/tvm-ffi/src/lib.rs`: Added `pub use crate::collections::array::Array`
- New file `rust/tvm-ffi/tests/test_array.rs` (132 lines): Tests for core ops, Any conversions, recursive type checking, and parametric types
