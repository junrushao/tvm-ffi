# c51e519 — [Feature] support C++ dtype_trait and Python-side mapping to C++ dtype (#374)

## TL;DR
- Added `include/tvm/ffi/extra/dtype.h` with `dtype_trait<T>` template specializations mapping C++ types (int, float, CUDA, HIP) to DLPack `DLDataType`.
- Added `python/tvm_ffi/cpp/dtype.py` with `to_cpp_dtype()` for converting Python/torch dtype strings to C++ type names, with auto-detection of CUDA/ROCm backends.
- Exported `to_cpp_dtype` from `tvm_ffi.cpp`.

## Why (intent / motivation)
- Kernel libraries and extensions need a standard way to map between C++ types (including CUDA/HIP vendor types like `__half`, `__nv_fp8_e4m3`, `__hip_bfloat16`) and DLPack dtype codes. Similarly, Python-side code generation needs to translate dtype strings into the correct C++ type names depending on the target backend.

## What changed (facts from diff)
- New `include/tvm/ffi/extra/dtype.h`: Defines `tvm_ffi::dtype_trait<T>` with `constexpr DLDataType value` for all standard integer types, float/double, bool, CUDA types (`__half`, `__nv_bfloat16`, `__nv_fp8_e4m3`, `__nv_fp8_e5m2`, `__nv_fp8_e8m0`, `__nv_fp4_e2m1`, `__nv_fp4x2_e2m1`), and HIP types (`__hip_bfloat16`, `hip_bfloat16`, `__hip_fp8_e4m3`, `__hip_fp8_e4m3_fnuz`, `__hip_fp8_e5m2`, `__hip_fp8_e5m2_fnuz`, `__hip_fp4_e2m1`, `__hip_fp4x2_e2m1`). Uses forward declarations to avoid requiring CUDA/HIP headers.
- New `python/tvm_ffi/cpp/dtype.py`: `to_cpp_dtype()` converts dtype strings (e.g., `"float32"`, `"torch.bfloat16"`) to C++ type names. Uses `CPU_DTYPE_MAP`, `CUDA_DTYPE_MAP`, and `ROCM_DTYPE_MAP`. Backend auto-detection via `torch.cuda.is_available()` with LRU caching.
- `python/tvm_ffi/cpp/__init__.py`: Added `to_cpp_dtype` to imports and `__all__`.

## Public surface changes (if any)
- API: New C++ header `<tvm/ffi/extra/dtype.h>` with `tvm_ffi::dtype_trait<T>`. New Python function `tvm_ffi.cpp.to_cpp_dtype()`.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
