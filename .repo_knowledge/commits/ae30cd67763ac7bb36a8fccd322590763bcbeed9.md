# ae30cd6 -- fix: out-of-bounds read in StringViewToDLDataType_ with non-null-terminated strings (#387)

## TL;DR
- Fixes a critical out-of-bounds read bug in `StringViewToDLDataType_` caused by using `strtoul()` on non-null-terminated `std::string_view` data.
- Replaces `strtoul()` with a manual bounded digit parser (`parse_digits` lambda) that respects `string_view` boundaries.
- Adds a `parse_lanes` helper for lane specification parsing (including scalable vectors).
- Comprehensive test coverage with 10 test cases for non-null-terminated buffers.

## Why (intent / motivation)
- `strtoul()` requires null-terminated strings and reads beyond `string_view` bounds, causing undefined behavior. This particularly manifests in Electron applications due to aggressive memory reuse in Chromium's allocators.

## What changed (facts from diff)
- Introduced `parse_digits` lambda that parses decimal digits within bounded `[ptr, end)` range, with `uint32_t` overflow check.
- Introduced `parse_lanes` lambda that handles `x<N>` and `xvscale<N>` lane specifications within bounded range.
- Replaced `strtoul(scan + 1, &endpt, 10)` in `parse_float` with `parse_lanes(&endpt, str_end, str)`.
- Replaced `strtoul(scan, &xdelim, 10)` for bits parsing with `parse_digits(&xdelim, str_end)`.
- Replaced the manual `strncmp(xdelim, "xvscale", 7)` + `strtoul` sequence with `parse_lanes(&endpt, str_end, str, /*allow_scalable=*/true)`.
- Added overflow checks: bits > `UINT8_MAX`, lanes > `UINT16_MAX`, digits > `UINT32_MAX`.
- Added `TEST(DType, NonNullTerminatedStringView)` with 10 sub-tests.
