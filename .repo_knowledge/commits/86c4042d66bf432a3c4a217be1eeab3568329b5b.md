# 86c4042 -- feat: add `ffi.GetInvalidObject` global function for MISSING singleton (#447)

## TL;DR
- Renames `ffi.MapGetMissingObject` to `ffi.GetInvalidObject` for a clearer, more general name.
- Initializes the `MISSING` singleton in `core.pyx` during Cython module load via `_get_global_func`.
- Re-exports `MISSING` from `container.py` via import from `core`, and adds it to `core.pyi` type stubs.
- Adds Python test verifying `MISSING` singleton identity and `Map.get()` integration.

## Why (intent / motivation)
- The `MISSING` sentinel object was previously created by calling `ffi.MapGetMissingObject`, which was Map-specific. Renaming to `ffi.GetInvalidObject` makes it a general-purpose sentinel available from `core`, usable beyond just Map operations.

## What changed (facts from diff)
- `python/tvm_ffi/_ffi_api.py`: Removed `MapGetMissingObject` stub, added `GetInvalidObject` stub.
- `python/tvm_ffi/container.py`: Changed `MISSING` from `_ffi_api.MapGetMissingObject()` to import from `core`.
- `python/tvm_ffi/core.pyi`: Added `MISSING: Object` type stub.
- `python/tvm_ffi/cython/core.pyx`: Initializes `MISSING = _get_global_func("ffi.GetInvalidObject", False)()`.
- `src/ffi/container.cc`: Renamed `ffi.MapGetMissingObject` to `ffi.GetInvalidObject`, reformatted registration block.
- `tests/python/test_container.py`: Added `test_missing_object` testing singleton identity across imports and Map.get() usage.

## Public surface changes (if any)
- API: `ffi.MapGetMissingObject` removed, replaced by `ffi.GetInvalidObject`. Python `MISSING` now available from `tvm_ffi.core.MISSING`.
