# e1bd421 — [FIX] Fix the error propagation in the case of tensor arguments (#409)

## TL;DR
- Fixes error propagation when calling FFI functions with tensor arguments that use DLPack managed tensor allocator
- Bug was hidden before v0.1.8 and revealed by a fix in that release
- Adds regression test for error propagation with torch tensor arguments

## Why (intent / motivation)
- When an FFI function raised an error while using tensor arguments (which set up a DLPack managed tensor allocator context), the error was not properly propagated back to Python
- The root cause was twofold: (1) `TVMFFIEnvSetDLPackManagedTensorAllocator` recovery could overwrite the error code, and (2) `EnvContext` was returning the global allocator instead of the cached local one

## What changed (facts from diff)
- `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`: Changed the DLPack allocator recovery path to check the return value of `TVMFFIEnvSetDLPackManagedTensorAllocator` separately (setting `PyErr_SetString` on failure) instead of writing to `c_api_ret_code[0]` which would overwrite the original error
- `src/ffi/extra/env_context.cc`: `EnvContext::SetDLPackManagedTensorAllocator` now returns the cached local `dlpack_allocator_` instead of calling `GetDLPackManagedTensorAllocator()` (which could return the global allocator), ensuring correct state restoration
- `include/tvm/ffi/c_api.h`: Version patch bumped from 9 to 8 (note: this is a version adjustment, likely correcting the version for this release line)
- `tests/python/test_tensor.py`: New test `test_tensor_auto_dlpack_with_error` that converts a function that raises `ValueError` and calls it with a torch tensor, verifying the error propagates correctly
