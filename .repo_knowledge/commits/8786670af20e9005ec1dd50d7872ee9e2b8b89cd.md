# 8786670 — feat: Add `tvm_ffi.Function.__init__` (#395)

## TL;DR
- Enables creating `tvm_ffi.Function` objects directly from Python callables via `tvm_ffi.Function(func)`.
- Adds a `__init__` method to the Cython `Function` class that wraps a Python callable or copies an existing `Function`.
- Improves Doxygen documentation for `TVM_FFI_STATIC_INIT_BLOCK` and `TVM_FFI_DEFAULT_COPY_MOVE_AND_ASSIGN` macros.

## Why (intent / motivation)
- Previously there was no direct constructor for `tvm_ffi.Function` from a Python callable. Users had to rely on implicit conversion at ABI boundaries or use `tvm_ffi.convert()`. This change provides a more intuitive and explicit way to create Function objects.

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`: Added `__init__(self, func)` method that accepts any Python callable, validates it, and converts it to an FFI function handle. If the input is already a `Function`, it increments the ref count.
- `python/tvm_ffi/core.pyi`: Added type stub `def __init__(self, func: Callable[..., Any]) -> None`.
- `tests/python/test_function.py`: Added `test_pyfunc_init()` test verifying `tvm_ffi.Function(add)` works correctly.
- `include/tvm/ffi/base_details.h`: Repositioned `\endcond` Doxygen markers and added proper Doxygen documentation for `TVM_FFI_STATIC_INIT_BLOCK` and `TVM_FFI_DEFAULT_COPY_MOVE_AND_ASSIGN` macros. Removed a trailing `\endcond` at end of file.
