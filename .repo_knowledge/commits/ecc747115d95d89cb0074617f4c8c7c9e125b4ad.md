# ecc7471 — feat: Add `tvm_ffi.Function.__init__` (#28)

## TL;DR
- Adds a `__init__` constructor to `tvm_ffi.Function` (Cython) so users can create a `Function` directly from a Python callable or an existing `Function` instance.
- Updates the `.pyi` stub to expose the new constructor signature.
- Adds comprehensive tests covering callable wrapping, copy-from-Function, moved-from error, and non-callable TypeError.

## Why (intent / motivation)
- Previously, `tvm_ffi.Function` could not be instantiated directly from a Python callable via its constructor; users had to go through lower-level conversion APIs. This commit provides a natural `tvm_ffi.Function(my_func)` constructor pattern.

## What changed (facts from diff)
- **`python/tvm_ffi/cython/function.pxi`**: Added `__init__(self, func)` method to the `Function` Cython class. Three code paths:
  1. If `func` is already a `Function`, increments the ref count on its `chandle` (with a guard against moved-from / NULL handles).
  2. If `func` is a generic callable, delegates to `_convert_to_ffi_func_handle`.
  3. Otherwise raises `TypeError`.
- **`python/tvm_ffi/core.pyi`**: Added `def __init__(self, func: Callable[..., Any]) -> None` stub to the `Function` class.
- **`tests/python/test_function.py`**: New `test_pyfunc_init` test function exercising all four scenarios (callable, existing Function, moved-from ValueError, non-callable TypeError).

## Public surface changes (if any)
- API: `tvm_ffi.Function` now accepts a positional `func` argument in its constructor. This is a new public API surface — previously the constructor took no arguments.
- Flags/config: none
- Data formats/schemas: none
