# 0a9d4b6 — feat: add ffi::Expected<T> for exception-free error handling (#399)

## TL;DR
- Adds `Expected<T>` class for Rust-like `Result<T, Error>` / C++23 `std::expected` exception-free error handling
- Adds `Function::CallExpected<T>()` method for exception-free function invocation
- Includes full `TypeTraits` specialization so `Expected<T>` integrates with the Any type system
- Comprehensive GoogleTest coverage (345 lines)

## Why (intent / motivation)
- Enable exception-free C++ API as requested in issue #234
- Allow callers to handle errors without try/catch, similar to Rust's `Result` or C++23's `std::expected`
- Useful for performance-sensitive paths where exception handling overhead matters

## What changed (facts from diff)
- New header `include/tvm/ffi/expected.h` with `Expected<T>` and `Unexpected<E>` classes
- `Expected<T>` can hold either a success value `T` or an `Error`, backed by an `Any` internally
- `Unexpected<E>` wrapper for explicit error-state construction with CTAD deduction guide
- `Expected<T>` provides `is_ok()`, `is_err()`, `has_value()`, `value()`, `error()`, `value_or()` methods
- `Function::CallExpected<T>()` added to `function.h` - uses `safe_call` path and catches exceptions into `Expected`
- Forward declaration of `Expected<T>` added to `function_details.h`
- `expected.h` included in the umbrella header `tvm_ffi.h`
- Full `TypeTraits<Expected<T>>` specialization: `CopyToAnyView`, `MoveToAny`, `CheckAnyStrict`, `CopyFromAnyViewAfterCheck`, `MoveFromAnyAfterCheck`, `TryCastFromAnyView`, `TypeStr`, `TypeSchema`

## Public surface changes (if any)
- API: New `tvm::ffi::Expected<T>`, `tvm::ffi::Unexpected<E>`, and `Function::CallExpected<T>()` public API
- Flags/config: none
- Data formats/schemas: New TypeSchema `{"type":"Expected","args":[...,{"type":"ffi.Error"}]}`

## Tests & verification
- Added/updated tests: `tests/cpp/test_expected.cc` (345 lines, ~25 test cases)
- How to verify manually: Build C++ tests and run `test_expected` suite
- CI impact: New test file added to C++ test suite

## Risk & rollout notes

- Rollout/migration: none required; opt-in usage
- Follow-ups: Python and Rust bindings for Expected<T> may follow
