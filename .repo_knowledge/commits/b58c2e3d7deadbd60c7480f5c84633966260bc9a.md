# b58c2e3 — feat(stubgen): Package generation with `--init-*` flags (#295)

## TL;DR
- Adds `--init-pypkg`, `--init-lib`, and `--init-prefix` flags to `tvm-ffi-stubgen` CLI for bootstrapping new packages
- Generates `_ffi_api.py` and `__init__.py` files automatically with proper loader, stubs, and `__all__` exports
- Introduces `tvm_ffi.testing` subpackage, moving test helpers from `tvm_ffi.testing` module into a proper package
- Major refactoring of the stubgen internals: new `lib_state.py` module, expanded `codegen.py`, `file_utils.py`, and `utils.py`

## Why (intent / motivation)
- Creating a new TVM-FFI extension package required manually writing `_ffi_api.py` and `__init__.py` boilerplate
- A single `tvm-ffi-stubgen` command should bootstrap a complete package structure from registered C++ functions/objects
- The tool needed to be idempotent: re-running should detect existing generated sections and not duplicate them

## What changed (facts from diff)
- `python/tvm_ffi/stub/cli.py`: added `--init-pypkg`, `--init-lib`, `--init-prefix` CLI flags; added `_stage_2()` for generating missing `_ffi_api.py`/`__init__.py`; refactored main pipeline into stages
- `python/tvm_ffi/stub/codegen.py`: added `generate_ffi_api()`, `generate_init_py()`, `generate_all()`, `generate_export()` functions for new file generation; expanded `generate_global_block()` and `generate_import_section()`
- `python/tvm_ffi/stub/consts.py`: added constants for new stubgen block types (`STUB_ALL`, `STUB_EXPORT`, `STUB_IMPORT_OBJECT`, `STUB_TY_MAP`)
- `python/tvm_ffi/stub/file_utils.py`: added `ManagedFile` class for transactional file reads/writes with diff preview
- `python/tvm_ffi/stub/lib_state.py`: new module for `InitConfig`, `FuncInfo`, `ObjectInfo`, topology sorting, and global function/type collection
- `python/tvm_ffi/stub/utils.py`: expanded with `ParsedDirective`, `FuncInfo`, `ObjectInfo`, `TypeSchema` integration
- Deleted `python/tvm_ffi/stub/analysis.py` (logic moved to `lib_state.py`)
- `python/tvm_ffi/testing/__init__.py`: new testing subpackage (renamed from `python/tvm_ffi/testing.py`)
- `python/tvm_ffi/testing/_ffi_api.py`: new generated FFI API file for testing subpackage
- `examples/packaging/python/my_ffi_extension/__init__.py`: replaced handwritten Python wrappers with auto-generated stubgen blocks
- `examples/packaging/python/my_ffi_extension/_ffi_api.py`: updated with auto-generated stubs
- Added ty-map and import-object directives in several Python source files

## Public surface changes (if any)
- API: new CLI flags `--init-pypkg`, `--init-lib`, `--init-prefix` for `tvm-ffi-stubgen`
- Flags/config: new stubgen block types (`export/`, `__all__`, `import-section`, `ty-map`, `import-object`)
- Data formats/schemas: auto-generated `_ffi_api.py` and `__init__.py` file structure

## Tests & verification
- Added/updated tests: `tests/python/test_stubgen.py` — extensive new tests for `generate_ffi_api`, `generate_init_py`, `generate_all`, `generate_export`, `generate_import_section`, object handling, and parent imports
- How to verify manually: `uv run pytest -vvs tests/python/test_stubgen.py`; `uv run tvm-ffi-stubgen examples/packaging/python --dlls <lib> --init-pypkg my-ffi-extension --init-lib my_ffi_extension --init-prefix "my_ffi_extension."`
- CI impact: none

- Rollout/migration: users relying on `from tvm_ffi.testing import ...` may need to update imports
