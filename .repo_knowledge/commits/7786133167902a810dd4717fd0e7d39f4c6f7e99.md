# 7786133 -- feat(stub): use distinct container type origins in type schema and stub generation (#469)

## TL;DR
- TypeSchema now emits distinct origins (`Array`, `List`, `Map`, `Dict`) instead of collapsing to `list`/`dict`
- Generated stubs use correct Python ABCs: `Sequence`/`Mapping` for immutable, `MutableSequence`/`MutableMapping` for mutable containers
- New `docs/concepts/containers.rst` page documenting all five container types
- Stub codegen collision avoidance for function names that shadow type imports

## Why (intent / motivation)
- Previously, all sequence types were collapsed to `list` and all mapping types to `dict` in type schemas, losing the immutable vs mutable distinction
- This caused incorrect type annotations in generated stubs (e.g., `list` instead of `Sequence` for `Array` parameters)
- Downstream type checkers would produce false positives or miss type errors

## What changed (facts from diff)
- `_TYPE_SCHEMA_ORIGIN_CONVERTER` in `type_info.pxi`: maps `ffi.Array` to `Array`, `ffi.List` to `List`, `ffi.Map` to `Map`, `ffi.Dict` to `Dict`
- `TY_MAP_DEFAULTS` in `stub/consts.py`: `Array` maps to `Sequence`, `List` to `MutableSequence`, `Map` to `Mapping`, `Dict` to `MutableMapping`
- Stub codegen (`stub/codegen.py`): collision avoidance when function names match type import suffixes (adds alias prefix)
- D105 (undocumented-magic-method) added to global ruff ignore list in `pyproject.toml`
- New `DeepCopy` and `__ffi_shallow_copy__` stubs appear in generated FFI API files
- New documentation page `docs/concepts/containers.rst` with overview table, mutability semantics, thread safety
- Updated `docs/concepts/any.rst`, `docs/guides/cpp_lang_guide.md`, `docs/guides/python_lang_guide.md` with List/Dict sections
- Updated `CLAUDE.md` and `.claude/skills/devtools/SKILL.md` with stub generation workflow

## Public surface changes (if any)
- API: Generated stub annotations changed from `list`/`dict` to `Sequence`/`MutableSequence`/`Mapping`/`MutableMapping`
- Flags/config: none
- Data formats/schemas: TypeSchema origin values changed for container types
