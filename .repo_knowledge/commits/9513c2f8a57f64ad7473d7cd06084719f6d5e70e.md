# 9513c2f — feat: Introduce List as Mutable Sequence (#443)

## TL;DR
- Introduces `List<T>`, a mutable sequence container alongside the existing immutable `Array<T>`, with full C++ and Python support
- Extracts `SeqBaseObj` as a shared base class for `ArrayObj` and `ListObj`, consolidating sequence operations and reducing code duplication
- Adds cycle detection in serialization, structural hash/equal, and JSON writer for `List` (which can form reference cycles unlike `Array`)
- New C ABI type code `kTVMFFIList = 75` and `TVMFFISeqCell` struct added to the stable C API

## Why (intent / motivation)
- The existing `Array<T>` is immutable (copy-on-write), which is insufficient for use cases requiring in-place mutation of sequences
- A mutable sequence container (`List<T>`) fills this gap, enabling Python-like list semantics (append, insert, pop, etc.) while sharing underlying infrastructure with `Array`

## What changed (facts from diff)
- New header `include/tvm/ffi/container/list.h` with `ListObj` and `List<T>` classes implementing mutable sequence with push_back, pop_back, insert, erase, resize, Set, clear, reverse, and iterator support
- New header `include/tvm/ffi/container/seq_base.h` extracting `SeqBaseObj` as shared base for `ArrayObj` and `ListObj`, consolidating iteration, element access, and reverse operations
- `ArrayObj` refactored to inherit from `SeqBaseObj`, significantly reducing code duplication while preserving copy-on-write semantics
- New C ABI enum value `kTVMFFIList = 75` in `c_api.h`
- New C ABI struct `TVMFFISeqCell` with `data`, `size`, `capacity`, and `data_deleter` fields
- `stl.h` updated so `TypeTraits<std::vector<T>>` accepts both `kTVMFFIArray` and `kTVMFFIList`
- Python `container.py` adds `List` class with full `MutableSequence` protocol (indexing, slicing, append, insert, pop, extend, del, contains, iteration, reverse, len, pickle)
- Serialization (`serialization.cc`) updated with cycle detection for `List`
- Structural equal/hash updated with `List` support and cycle detection
- JSON writer updated with `List` support and cycle detection
- New testing FFI functions registered for `List` in `src/ffi/testing/testing.cc`

## Public surface changes (if any)
- API: New `List<T>` C++ container class and `tvm_ffi.List` Python class; new `SeqBaseObj` base class; `kTVMFFIList` type code
- Flags/config: none
- Data formats/schemas: New `TVMFFISeqCell` C ABI struct; serialization format extended for List

## Tests & verification
- Added/updated tests:
  - `tests/cpp/test_list.cc` (277 lines): construction, push_back, pop_back, insert, erase, resize, Set, clear, iterator, reverse, COW-free mutation
  - `tests/cpp/extra/test_structural_equal_hash.cc`: List equality, List-vs-Array type mismatch
  - `tests/cpp/extra/test_serialization.cc`: empty/single-element list, round-trip, cycle detection
  - `tests/python/test_container.py` (244 lines added): construction, indexing, slicing, append, insert, pop, extend, delitem, setitem, contains, iteration, reverse, len, pickle round-trip
- How to verify manually: `uv run pytest -vvs tests/python/test_container.py` and rebuild C++ tests
- CI impact: New test files picked up automatically by existing pytest/ctest configs

## Risk & rollout notes
- Risk level: high — Adds new type code to stable C ABI (`kTVMFFIList = 75`), introduces `TVMFFISeqCell` struct, and refactors `ArrayObj` inheritance hierarchy
- Rollout/migration: Existing code using `Array` continues to work unchanged; `List` is additive. The `SeqBaseObj` refactor changes the class hierarchy of `ArrayObj`
- Follow-ups: none noted
