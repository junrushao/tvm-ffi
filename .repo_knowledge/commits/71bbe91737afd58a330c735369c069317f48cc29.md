# 71bbe91 -- Fix TVMFFIEnvSetDLPackManagedTensorAllocator to correctly return the original allocator (#371)

## TL;DR
- Fixes `TVMFFIEnvSetDLPackManagedTensorAllocator` to return the **previous** allocator before overwriting it, rather than returning the **new** allocator.
- Adds a test verifying the returned previous allocator matches what was set before.

## Why (intent / motivation)
- Before this fix, `TVMFFIEnvSetDLPackManagedTensorAllocator(NewAllocator, 0, &pre_allocator)` would incorrectly set `pre_allocator` to the newly assigned allocator (because the write to `dlpack_allocator_` happened before reading it into `opt_out_original_allocator`). Callers expecting to save/restore the original allocator would get the wrong value.

## What changed (facts from diff)
- In `EnvContext::SetDLPackManagedTensorAllocator`: moved the `if (opt_out_original_allocator != nullptr)` block **before** the assignment to `dlpack_allocator_`, and changed it to call `GetDLPackManagedTensorAllocator()` (which checks thread-local then falls back to global) rather than reading `dlpack_allocator_` directly.
- Removed the duplicate `dlpack_allocator_ = allocator;` line (the second assignment was redundant after reordering).
- Added `TEST(CEnvAPI, TVMFFIEnvSetDLPackManagedTensorAllocator)` that verifies `pre_allocator == old_allocator` after calling set.

## Public surface changes (if any)
- API: Behavioral fix to `TVMFFIEnvSetDLPackManagedTensorAllocator` C API -- the `opt_out_original_allocator` output now correctly returns the allocator that was active before the call.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/extra/test_c_env_api.cc` -- new `TEST(CEnvAPI, TVMFFIEnvSetDLPackManagedTensorAllocator)`.
- How to verify manually: Build and run C++ tests.
- CI impact: none

## Risk & rollout notes
- Risk level: medium -- fixes a behavioral bug in a public C API. Any code that relied on the (incorrect) previous behavior of getting the new allocator back would break, but that usage would itself have been buggy.
- Rollout/migration: none
