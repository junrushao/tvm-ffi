# 38914fa — fix: TypeStr support for Any type in reflection Init (#393)

## TL;DR
- Fixes a compilation error when using `refl::init<Any>()` or `refl::init<AnyView>()` in the reflection system.
- Adds missing `Type2Str` specializations for `Any&&` and `AnyView&&` rvalue reference types.

## Why (intent / motivation)
- The reflection system internally converts `Any` to `Any&&` (rvalue reference) when processing constructor parameters. Without a `Type2Str<Any&&>` specialization, using `refl::init<Any>()` failed to compile because there was no way to stringify the `Any&&` type.

## What changed (facts from diff)
- `include/tvm/ffi/any.h`: Added `Type2Str<Any&&>` and `Type2Str<AnyView&&>` template specializations, both returning `"Any"` and `"AnyView"` respectively.
- `include/tvm/ffi/type_traits.h`: Added a forward declaration `class Any;` so that `type_traits.h` can reference `Any` without a circular include.
- `tests/cpp/test_reflection.cc`: Added two new test objects (`TestObjWithAny`, `TestObjWithAnyView`) and corresponding tests (`Reflection.InitWithAny`, `Reflection.InitWithAnyView`) that verify constructors accepting `Any` and `AnyView` parameters work correctly through the reflection system.
