# 37d0485 -- ROCm: fix DLPack current_work_stream and force addon override for Torch exchange API (#466)

## TL;DR
- Fixed ROCm `current_work_stream` callback to use `HIPStreamMasqueradingAsCUDA` instead of the CUDA stream API
- Forced tvm-ffi addon override on ROCm even when PyTorch already has `__dlpack_c_exchange_api__`
- Added GPU test for stream identity verification across `kDLCUDA` and `kDLROCM` device types

## Why (intent / motivation)
- On ROCm, the DLPack exchange API was returning wrong stream handles because it used the CUDA stream API instead of the HIP-masquerading-as-CUDA API
- This caused HIP graph empty-capture warnings and stream mismatch behavior in downstream callers like SGLang JIT kernels
- Even when PyTorch already exposes `__dlpack_c_exchange_api__`, ROCm needs the tvm-ffi addon to provide the corrected callback

## What changed (facts from diff)
- `_build_optional_torch_c_dlpack.py`: Added `#include <ATen/hip/impl/HIPStreamMasqueradingAsCUDA.h>` for ROCm builds; ROCm path now calls `c10::hip::getCurrentHIPStreamMasqueradingAsCUDA(device_id).stream()`; CUDA path narrows its condition to only `kDLCUDA` (no longer handles `kDLROCM`)
- `_optional_torch_c_dlpack.py`: Added `prefer_rocm_override` flag that skips the early-return when ROCm is detected, forcing the tvm-ffi addon to load even if PyTorch already has the exchange API
- New test `test_current_work_stream_gpu.py`: Verifies that `current_work_stream` returns the correct stream handle for both `kDLCUDA` and `kDLROCM` device types by comparing against a non-default torch stream
