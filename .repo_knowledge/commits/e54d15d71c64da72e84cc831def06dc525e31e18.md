# e54d15d — fix: add bounds checking for size() and stride() methods (#375)

## TL;DR
- Added bounds checking to `Tensor::size()`, `Tensor::stride()`, `TensorView::size()`, and `TensorView::stride()` after adjusting for negative indices.
- Added C++ and Python tests for out-of-bounds index access.
- Minor type annotation improvements in Python test file.

## Why (intent / motivation)
- The `size()` and `stride()` methods on both `Tensor` and `TensorView` accepted negative indices (converting them to positive) but did not validate the resulting index against the tensor's number of dimensions. Invalid indices would silently access out-of-bounds memory.

## What changed (facts from diff)
- `include/tvm/ffi/container/tensor.h`: All four methods (`Tensor::size`, `Tensor::stride`, `TensorView::size`, `TensorView::stride`) now compute `adjusted_idx` and check `adjusted_idx < 0 || adjusted_idx >= ndim`, throwing `IndexError` with a descriptive message on failure.
- `tests/cpp/test_tensor.cc`: Added `TEST(Tensor, SizeStrideOutOfBounds)` verifying both positive and negative out-of-bounds indices throw for both `Tensor` and `TensorView`.
- `tests/python/test_tensor.py`: Added `npt.NDArray[Any]` type annotations to numpy arrays to improve type safety.

## Public surface changes (if any)
- API: `Tensor::size()`, `Tensor::stride()`, `TensorView::size()`, `TensorView::stride()` now throw `IndexError` for out-of-bounds indices instead of accessing invalid memory.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification

- How to verify manually: Build and run C++ tests: `ctest -V -C Debug --test-dir build_test -R SizeStrideOutOfBounds`
