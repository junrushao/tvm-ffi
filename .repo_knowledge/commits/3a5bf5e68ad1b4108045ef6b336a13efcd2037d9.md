# 3a5bf5e — feat: add kw_only support for dataclass init generation (#384)

## TL;DR
- Adds `kw_only` parameter to `@c_class` decorator and `field()` function for keyword-only `__init__` args
- Adds `KW_ONLY` sentinel class for marking subsequent fields as keyword-only (mirroring Python 3.10 dataclasses)
- New C++ test class `TestCxxKwOnly` and comprehensive Python tests
- Resolves part of #356 (dataclass feature parity)

## Why (intent / motivation)
- Python's standard `dataclasses` supports `kw_only` parameter to make fields keyword-only in `__init__`, but this feature was missing from the `@c_class` decorator
- Needed for dataclass feature parity (#356)

## What changed (facts from diff)
- `field()` gains a `kw_only` parameter (default `MISSING`, inherits from class-level or sentinel)
- `Field` class gets a new `kw_only` slot
- `c_class()` gains a `kw_only` parameter (default `False`) with `kw_only_default=False` in `@dataclass_transform`
- `_inspect_c_class_fields` now returns a tuple `(fields, kw_only_start_idx)` to track `KW_ONLY` sentinel position
- `fill_dataclass_field` now resolves kw_only precedence: field-level > KW_ONLY sentinel > class-level
- `method_init` splits parameter lists into positional and keyword-only categories, inserting `*` separator in generated signature
- `KW_ONLY` sentinel imported from `dataclasses` (Python 3.10+) or defined as a custom sentinel class for older Python
- New C++ class `TestCxxKwOnly` registered with `ObjectDef` reflection for testing
- New Python proxy `_TestCxxKwOnly` with `kw_only=True`
- 7 new test functions covering class-level kw_only, field-level kw_only, defaults, positional rejection, and sentinel existence

## Public surface changes (if any)
- API: `KW_ONLY` exported from `tvm_ffi.dataclasses`; `kw_only` parameter added to `c_class()` and `field()`
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_dataclasses_c_class.py` (7 new test functions)
- How to verify manually: `uv run pytest -vvs tests/python/test_dataclasses_c_class.py`
- CI impact: none (additive)

## Risk & rollout notes
- Risk level: medium — changes generated `__init__` signature logic and field resolution order; could affect existing `@c_class` users if field resolution interacts unexpectedly
- Rollout/migration: none; default `kw_only=False` preserves backward compatibility
- Follow-ups: remaining #356 features (e.g., `__eq__`, `__hash__`, `order`, `frozen`)
