# bd12b26 -- feat: add find and substr methods to String (#383)

## TL;DR
- Adds `find()` and `substr()` methods to the `String` class in C++, plus the `npos` constant.
- Adds C++ and Python tests covering find, substr, and Python slicing.

## Why (intent / motivation)
- The `String` class lacked essential string manipulation methods (`find`, `substr`) that are commonly expected in standard library equivalents, forcing users to convert to `std::string` for basic operations.

## What changed (facts from diff)
- Added `static constexpr size_t npos = static_cast<size_t>(-1)` to `String`.
- Added 3 overloads of `find()`: `find(const String&, pos)`, `find(const char*, pos)`, `find(const char*, pos, count)`. Implementation delegates to `std::string_view::find`.
- Added `substr(pos, count)` with bounds checking (throws `std::out_of_range` if `pos > size()`).
- Added `TEST(String, Find)` and `TEST(String, Substr)` in `tests/cpp/test_string.cc`.
- Added `test_string_find_substr()` in `tests/python/test_string.py` testing `find()` and Python slice syntax.

## Public surface changes (if any)
- API: New `String::npos`, `String::find(...)` (3 overloads), `String::substr(pos, count)`.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_string.cc` (+37 lines), `tests/python/test_string.py` (+18 lines).
- How to verify manually: Build and run C++ tests; run `uv run pytest -vvs tests/python/test_string.py`.
- CI impact: none

## Risk & rollout notes
- Risk level: low -- purely additive API, no existing behavior changed.
- Rollout/migration: none
- Follow-ups: The `substr` default parameter uses `size_t(-1)` which was later fixed in commit 4a8a0b0 to use `npos`.
