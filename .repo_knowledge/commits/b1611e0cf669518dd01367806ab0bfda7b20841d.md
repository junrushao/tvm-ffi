# b1611e0 — [Error] Unify EnvErrorAlreadySet to error.kind (#425)

## TL;DR
- Replaces the `EnvErrorAlreadySet` C++ exception struct with an `Error` object having `kind == "EnvErrorAlreadySet"`
- Removes error code `-2` from the ABI; all errors now use code `-1` with TLS-based error retrieval
- Updates Python/Cython bindings to detect `EnvErrorAlreadySet` via error kind string instead of return code
- Maintains backward compatibility with `-2` return code during transition period

## Why (intent / motivation)
- Simplify error handling by removing the special `-2` error code path
- Make error handling more consistent: all errors now go through the same `-1` + TLS mechanism
- Remove boilerplate in C++ exception handling (no more separate `catch (EnvErrorAlreadySet)` block)
- The only use case for `-2` was propagating `KeyboardInterrupt` from Python through C++ autotuning

## What changed (facts from diff)
- `include/tvm/ffi/error.h`: Removed `EnvErrorAlreadySet` struct (was `std::exception` subclass); replaced with `inline Error EnvErrorAlreadySet()` function returning `Error("EnvErrorAlreadySet", "", "")`
- `include/tvm/ffi/function.h`: Removed `catch (EnvErrorAlreadySet)` block from `TVM_FFI_SAFE_CALL_END`; removed `-2` check from `TVM_FFI_SAFE_CALL_CHECK_RETURN`
- `include/tvm/ffi/c_api.h`: Removed `-2` from documented return codes
- `python/tvm_ffi/cython/error.pxi`: `CHECK_CALL` now checks `error.kind == "EnvErrorAlreadySet"` after `move_from_last_error()`; keeps `-2` backward compat with TODO to remove
- `python/tvm_ffi/cython/function.pxi`: `Function.__call__` now checks error kind instead of return code; backward compat for `-2` preserved
- `python/tvm_ffi/cython/type_info.pxi`: `FieldSetter` updated with same pattern
- `examples/abi_overview/example_code.c`: Removed `-2` handling branch
- `docs/concepts/func_module.rst`: Removed `-2` references; added note about `EnvErrorAlreadySet` kind
- `docs/guides/python_lang_guide.md`: Updated traceback example to match new code paths

## Public surface changes (if any)
- API: `tvm::ffi::EnvErrorAlreadySet` changed from a struct to a function returning `Error`; same call syntax `throw EnvErrorAlreadySet()` still works
- Flags/config: none
- Data formats/schemas: Error code `-2` removed from C ABI (backward compat maintained temporarily)

## Tests & verification
- Added/updated tests: none (existing tests cover the paths)
- How to verify manually: Trigger a KeyboardInterrupt during a long-running C++ function called from Python
- CI impact: none

## Risk & rollout notes
- Risk level: medium — ABI-level change removing error code `-2`; however, backward compat is maintained in Python bindings with TODO to remove later
- Rollout/migration: Downstream C++ code using `catch (EnvErrorAlreadySet)` must switch to catching `Error` and checking `kind == "EnvErrorAlreadySet"`
- Follow-ups: Remove backward-compat `-2` handling after a few versions (marked with TODO)
