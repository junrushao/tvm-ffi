# 4fec972 — [Feat] Support lower PyTorch versions in dtype handling (#414)

## TL;DR
- Moves newer PyTorch dtype entries (uint16/32/64, float8 variants, float4) from direct dict initialization to a `hasattr`-guarded loop
- Enables `import tvm_ffi` to succeed with older PyTorch versions (tested with 1.10.2, 1.14.0a0, 2.0)

## Why (intent / motivation)
- Older PyTorch versions (pre-2.x) do not have `torch.uint16`, `torch.uint32`, `torch.uint64`, or `torch.float8_*` attributes
- Directly referencing these in the dtype mapping dict caused `AttributeError` at import time, preventing `tvm_ffi` from being used with older PyTorch
- Related to discussion in #381

## What changed (facts from diff)
- In `python/tvm_ffi/cython/dtype.pxi`, the `TORCH_DTYPE_TO_DL_DATA_TYPE` dict initialization now only includes universally available dtypes (int8-int64, uint8, float16-float64, bfloat16, bool)
- A new `extra_types` list with `(attr_name, DLDataType)` tuples covers: uint16, uint32, uint64, float8_e4m3fn, float8_e4m3fnuz, float8_e5m2, float8_e5m2fnuz, float8_e8m0fnu, float4_e2m1fn_x2
- A loop uses `hasattr(torch, attr_name)` to conditionally add each extra dtype
- Previous approach had `torch.uint16`/`torch.uint32`/`torch.uint64` inline and only `float8_e8m0fnu`/`float4_e2m1fn_x2` guarded by `hasattr`
