# 7619669 — chore: Switch from mypy to ty (#432)

## TL;DR
- Replaces mypy with Astral's `ty` as the Python type checker in pre-commit hooks and CI
- Adds `ty` configuration to `pyproject.toml` including environment, source paths, and allowed unresolved imports
- Updates ~38 Python files to replace mypy `type: ignore` comments with `ty: ignore` equivalents

## Why (intent / motivation)
- Astral's `ty` (from the same team behind `uv` and `ruff`) is significantly faster and more accurate than mypy
- Consolidating on Astral's toolchain (`uv`, `ruff`, `ty`) provides a more cohesive and performant developer experience

## What changed (facts from diff)
- `.pre-commit-config.yaml`: Replaced `mirrors-mypy` hook (with numpy, ml-dtypes, pytest, typing-extensions dependencies) with a local `ty check` hook using `uvx ty check`
- `.github/workflows/ci_test.yml`: Added `astral-sh/setup-uv` step and `uv sync --group dev --no-install-project` before pre-commit action, so ty can find dependencies
- `CONTRIBUTING.md`: Updated mention from "mypy" to "ty"
- `pyproject.toml`: Removed `[tool.mypy]` section; added `[tool.ty.environment]` (python-version 3.9, extra-paths), `[tool.ty.src]` (include/exclude patterns), and `[tool.ty.analysis]` (allowed-unresolved-imports for torch, triton, ml_dtypes, etc.)
- Multiple Python source files (~30+): Replaced `# type: ignore[...]` comments with appropriate `# ty: ignore[...]` comments (e.g., `type: ignore[no-any-return]` -> `ty: ignore[return-type]`, `type: ignore[assignment]` -> `ty: ignore[invalid-assignment]`, etc.)
- Some type annotations refined (e.g., `Callable` -> `Callable[..., Any]`, removing unnecessary casts)

## Public surface changes (if any)
- API: none
- Flags/config: mypy removed from pre-commit; ty added; `[tool.ty]` config in pyproject.toml
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: No new tests; existing type-ignore comments updated across test files
- How to verify manually: `pre-commit run ty --all-files` or `uvx ty check`
- CI impact: CI lint job now runs `ty` instead of `mypy`; requires `uv sync` step before pre-commit

## Risk & rollout notes
- Risk level: medium — Switches type checker, which may surface new errors or miss previously caught ones; affects all Python contributors' workflow
- Rollout/migration: Contributors need to use `ty: ignore` instead of `type: ignore` for type suppressions; mypy config no longer needed
- Follow-ups: ty version not pinned in this commit (pinned in later commit #441)
