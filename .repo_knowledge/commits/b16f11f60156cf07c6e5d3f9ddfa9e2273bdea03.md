# b16f11f -- [Enhancement] Refactor cubin launcher (#300)

## TL;DR
- Major refactor of CUBIN launcher utilities: new macros, unified CUDA Driver/Runtime API abstraction, modernized CMake functions, and restructured examples.
- Introduces `TVM_FFI_LOAD_LIBRARY_FROM_BYTES` macro for loading CUBINs from byte arrays (supports C++23 `#embed` and `bin2c`).
- New `include/tvm/ffi/extra/cuda/internal/unified_api.h` providing a unified abstraction over CUDA Driver and Runtime APIs.
- Replaces old imperative CMake functions (`tvm_ffi_generate_cubin`/`tvm_ffi_embed_cubin`) with declarative target-based functions (`add_tvm_ffi_cubin`, `add_tvm_ffi_fatbin`, `tvm_ffi_embed_bin_into`).

## Why (intent / motivation)
- Resolves issue #292. The existing CUBIN launcher infrastructure was inflexible and tightly coupled to specific embedding techniques.
- The refactor enables modern embedding approaches (C++23 `#embed`, `bin2c` headers) alongside the existing CMake object-linking approach.
- A unified CUDA API abstraction layer simplifies switching between CUDA Driver and Runtime APIs.

## What changed (facts from diff)
- **`cmake/Utils/EmbedCubin.cmake`**: Rewritten (~269 lines changed). Defaults `CMAKE_CUDA_RUNTIME_LIBRARY` to `Shared`. New functions: `add_tvm_ffi_cubin`, `add_tvm_ffi_fatbin`, `tvm_ffi_embed_bin_into`. Removed old `tvm_ffi_generate_cubin` and `tvm_ffi_embed_cubin`.
- **`cmake/Utils/ObjectCopyUtil.cmake`**: New file (+48 lines) providing a cross-platform CMake helper for binary object embedding via `objcopy`-like operations.
- **`include/tvm/ffi/extra/cuda/internal/unified_api.h`**: New file (+206 lines) with unified CUDA Driver/Runtime API wrappers, unified handle types (`LibraryHandle`, `KernelHandle`, `StreamHandle`, `ResultHandle`), and a unified error checking macro `TVM_FFI_CHECK_CUDA_ERROR`.
- **`include/tvm/ffi/extra/cuda/base.h`**: `dim3` struct definition refactored/moved here; added `TVM_FFI_LOAD_LIBRARY_FROM_BYTES` macro.
- **`include/tvm/ffi/extra/cuda/cubin_launcher.h`**: Simplified to focus on `CubinModule` and `CubinKernel`. `CubinModule` constructor now accepts `const unsigned char*` for byte arrays.
- **Examples restructured**: `examples/cubin_launcher/embedded_cubin/` split into sub-examples: `embed_with_tvm_ffi/`, `cpp_embed/`, `include_bin2c/`. Dynamic cubin example updated to use unified API.
- **`docs/guides/cubin_launcher.rst`**: Updated to document new CMake functions, `TVM_FFI_LOAD_LIBRARY_FROM_BYTES`, and embedding approaches.
- **`.gitignore`**: Added `*.cubin` and `*.fatbin` patterns.

## Public surface changes (if any)
- API: New macro `TVM_FFI_LOAD_LIBRARY_FROM_BYTES(name, imageBytes)`. `CubinModule` constructor signature changed to accept `const unsigned char*`. New unified CUDA API header. Old CMake functions `tvm_ffi_generate_cubin`/`tvm_ffi_embed_cubin` removed and replaced.
- Flags/config: New CMake define `TVM_FFI_CUBIN_LAUNCHER_USE_DRIVER_API` to select CUDA API backend.
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: No automated tests added; verified manually by running cubin launcher examples on CUDA 13.1 with both Runtime and Driver API.
- How to verify manually: Build and run the cubin launcher examples in `examples/cubin_launcher/`.
- CI impact: none (CUDA examples are not in standard CI pipeline).

## Risk & rollout notes
- Risk level: medium -- significant API and CMake function changes that break backward compatibility for downstream users of the old `tvm_ffi_generate_cubin`/`tvm_ffi_embed_cubin` CMake functions and old `CubinModule` constructor.
- Rollout/migration: Users of the old CMake CUBIN embedding functions must migrate to the new target-based approach.
- Follow-ups: none noted.
