# 639cc63 — chore(ci): Run wheel testing per-mainline-commit (#337)

## TL;DR
- Extracts wheel build logic into a reusable composite action `.github/actions/build-wheel-for-publish/action.yml`
- Adds `build-wheels` job to `ci_mainline_only.yml` to test wheel building on every mainline commit
- Refactors `publish_wheel.yml` to use the composite action, removing duplicated logic and the separate `build_sdist` job
- Changes publish workflow trigger from nightly cron to manual `workflow_dispatch` with a `tag` input

## Why (intent / motivation)
- Nightly wheel builds were wasteful on days without commits and missed regressions on days with multiple commits
- Per-commit wheel testing catches build issues immediately
- Deduplicating wheel build logic into a composite action reduces maintenance burden

## What changed (facts from diff)
- `.github/actions/build-wheel-for-publish/action.yml`: new composite action with inputs for `os`, `arch`, `linux_image`, `checkout_ref`, `build_wheels`, `build_sdist`; runs C++ tests, builds wheels via cibuildwheel, optionally builds sdist
- `.github/workflows/ci_mainline_only.yml`: added `build-wheels` job using the composite action across 6 platform/arch combinations
- `.github/workflows/publish_wheel.yml`: replaced inline build steps with composite action; removed `schedule` trigger; changed `workflow_dispatch` input from `branch` to `tag`; merged `build_sdist` into the matrix; removed separate `build_sdist` job
- `.gitignore`: added exceptions for `.github/actions/build-wheel-for-publish/` to avoid `build-*` ignore pattern
