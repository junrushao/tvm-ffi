# 438f643 — feat: Fix perf issue in `Map.get` (#341)

## TL;DR
- Adds a C++ `MapGetItemOrMissing` function that returns a sentinel object instead of throwing on missing keys
- Replaces Python-side `Map.get()` try/except pattern with a single FFI call, eliminating exception overhead for missing keys
- Also optimizes `ItemsView.__contains__` to use `Map.get()` instead of `__getitem__` with try/except

## Why (intent / motivation)
- `Map.get(key, default)` was implemented as a try/except around `Map.__getitem__`, which is expensive when keys are missing because it involves C++ exception creation, backtrace capture, and Python exception handling
- Issue #326 reported this performance problem

## What changed (facts from diff)
- `src/ffi/container.cc`: added `GetMissingObject()` which returns a static singleton `ObjectRef`; registered `ffi.MapGetMissingObject` and `ffi.MapGetItemOrMissing` global functions; `MapGetItemOrMissing` catches `tvm::ffi::Error` and returns the sentinel instead of propagating
- `python/tvm_ffi/container.py`: added `MISSING = _ffi_api.MapGetMissingObject()` sentinel; `Map.get()` now calls `_ffi_api.MapGetItemOrMissing(self, key)` and checks `MISSING.same_as(ret)` instead of try/except; `ItemsView.__contains__` uses `self._backend_map.get(key, MISSING)` pattern
- `python/tvm_ffi/_ffi_api.py`: added stubs for `MapGetItemOrMissing` and `MapGetMissingObject`

## Public surface changes (if any)
