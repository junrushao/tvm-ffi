# 731955b — refactor: Get `compiled_kernel` from Triton Call Directly (#423)

## TL;DR
- Simplifies CUBIN extraction in Triton examples by using the return value of the Triton kernel call directly
- Removes fragile cache-based lookup of compiled kernels via `device_caches`

## Why (intent / motivation)
- The previous code searched for the compiled kernel by traversing Triton's internal `device_caches` dictionary, which was unnecessary and not robust across Triton versions
- Triton kernel calls return the `CompiledKernel` object directly, making the cache lookup redundant

## What changed (facts from diff)
- `examples/cubin_launcher/benchmark_overhead.py`: Replaced 7-line `device_caches` lookup with single-line assignment `compiled_kernel = empty_kernel[1,](a_dummy, b_dummy, c_dummy, n)`
- `examples/cubin_launcher/example_triton_cubin.py`: Same refactor — replaced 7-line cache lookup with `compiled_kernel = square_kernel[1, 1](x_dummy, y_dummy, 1024)`
