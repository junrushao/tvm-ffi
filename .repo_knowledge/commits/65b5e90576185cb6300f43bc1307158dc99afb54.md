# 65b5e90 -- [Feature] Support AMD HIP for cpp extension (#460)

## TL;DR
- Added AMD HIP/ROCm backend support to the `tvm_ffi.cpp` extension build system
- Auto-detects GPU backend (CUDA vs HIP) based on available toolchain; configurable via `TVM_FFI_GPU_BACKEND` env var
- All public APIs (`build`, `load`, `build_inline`, `load_inline`) gain a `backend` parameter

## Why (intent / motivation)
- The C++ extension build system (`tvm_ffi.cpp`) only supported NVIDIA CUDA; AMD ROCm/HIP users could not compile GPU kernels
- This enables the same API surface to work on both CUDA and HIP platforms

## What changed (facts from diff)
- `python/tvm_ffi/cpp/extension.py` (+155/-18):
  - New `_detect_gpu_backend()`: auto-detects `"hip"` if ROCm is found, else `"cuda"`; cached via `@lru_cache`
  - New `_resolve_gpu_backend(backend)`: validates explicit backend or delegates to auto-detection
  - New `_find_rocm_home()`: discovers ROCm install via `ROCM_HOME`/`ROCM_PATH` env vars, `hipcc` in PATH, or `/opt/rocm` default
  - New `_get_rocm_target()`: detects GPU arch via `TVM_FFI_ROCM_ARCH_LIST` env var, `rocm_agent_enumerator`, or `rocminfo`
  - `_generate_ninja_build()`: replaced `with_cuda` bool with `backend` parameter; generates `hipcc` rules for HIP, `nvcc` for CUDA; HIP gets `-D__HIP_PLATFORM_AMD__=1 -fno-gpu-rdc` and `--offload-arch=` flags; links `-lamdhip64`
  - `_build_impl()`: passes resolved backend through the build pipeline
  - `build_inline()`, `load_inline()`, `build()`, `load()`: all gain `backend: str | None` parameter with docstrings
  - New `BACKEND_STR = Literal["cuda", "hip"]` type alias
  - HIP compile rule omits nvcc-specific `--generate-dependencies-with-compile` flag

## Public surface changes (if any)
- API: New `backend` parameter on `build()`, `load()`, `build_inline()`, `load_inline()` accepting `"cuda"` or `"hip"`
- Flags/config: `TVM_FFI_GPU_BACKEND` env var for explicit backend selection; `TVM_FFI_ROCM_ARCH_LIST` env var for ROCm target architectures; `ROCM_HOME`/`ROCM_PATH` for ROCm installation path
