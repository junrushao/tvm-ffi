# 35cbc32 -- [ERROR] Complete support of CHECK macros (#465)

## TL;DR
- Generalized CHECK macros to accept a custom error kind (e.g., `TVM_FFI_CHECK_EQ(x, y, ValueError)`)
- Redefined existing `ICHECK` macros as thin wrappers around the new generalized `CHECK` macros with `InternalError`
- Added `DCHECK` (debug check) macros that are stripped in release builds (`NDEBUG`)

## Why (intent / motivation)
- Previously, only `ICHECK` macros existed, which always threw `InternalError`
- Users needed the ability to throw specific error types (e.g., `ValueError`, `IndexError`, `TypeError`) from check macros
- Debug-only checks (`DCHECK`) are needed for assertions that should be compiled out in release builds for performance

## What changed (facts from diff)
- `include/tvm/ffi/error.h`: Introduced generalized `TVM_FFI_CHECK_BINARY_OP(name, op, x, y, ErrorKind)` macro
- Added `TVM_FFI_CHECK_EQ/NE/LT/GT/LE/GE(x, y, ErrorKind)` macros that accept custom error kinds
- Added `TVM_FFI_CHECK_NOTNULL(x, ErrorKind)` macro
- Redefined `TVM_FFI_ICHECK*` macros as wrappers around `TVM_FFI_CHECK*` with `InternalError`
- Added `TVM_FFI_DCHECK*` macros: active in debug builds, compiled out with `NDEBUG`
- `TVM_FFI_CHECK(cond, ErrorKind)` macro added for single-condition checks with custom error types
- `tests/cpp/test_error.cc`: Added `CheckBinaryOps` test for all generalized CHECK macros with custom error kinds; added `DCheck` test for debug/release behavior
