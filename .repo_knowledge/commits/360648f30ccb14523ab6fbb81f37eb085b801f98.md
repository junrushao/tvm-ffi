# 360648f — feat: Add __repr__ generation support for @c_class dataclasses (#411)

## TL;DR
- Adds `repr` parameter to `c_class()` decorator (default: `True`) and `field()` function (default: `True`)
- Implements `method_repr()` to auto-generate `__repr__` methods in the format `ClassName(field1=value1, ...)`
- Fields with `repr=False` are excluded from the generated representation
- Refactors `_get_all_fields` into a shared helper and fixes method override handling in `_add_method`

## Why (intent / motivation)
- Part of #356 (dataclass feature parity): Python's standard dataclasses generate `__repr__` by default, but `@c_class` lacked this feature
- Users needed readable string representations of c_class instances for debugging

## What changed (facts from diff)
- `Field` class gains `repr` slot (default `True`)
- `field()` gains `repr` parameter with validation
- `c_class()` gains `repr` parameter (default `True`); skips generation if class already defines `__repr__`
- New `method_repr(type_cls, type_info)` function generates `__repr__` via f-string code generation
- `_get_all_fields(type_info)` extracted as shared helper (was inlined in `method_init`)
- `_add_method` in `type_info_to_cls` changed to always add to `attrs` dict (removing early return for already-defined methods and `setattr` call), enabling override of base class methods like `Object.__repr__`
- `c_class` decorator passes both `__init__` and `__repr__` in the `methods` dict to `type_info_to_cls`
- 3 new test functions: `test_cxx_class_repr`, `test_cxx_class_repr_default`, `test_cxx_class_repr_derived_derived`

## Public surface changes (if any)
- API: `c_class(repr=True)` parameter; `field(repr=True)` parameter; auto-generated `__repr__` on c_class instances
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_dataclasses_c_class.py` (3 new test functions)
- How to verify manually: `uv run pytest -vvs tests/python/test_dataclasses_c_class.py`
- CI impact: none (additive)

## Risk & rollout notes
- Risk level: low — new behavior is opt-out (default `True`), but classes that already define `__repr__` are skipped; the `_add_method` refactor changes override behavior but is tested
- Rollout/migration: none; existing classes without `__repr__` will now get one automatically
- Follow-ups: remaining #356 features
