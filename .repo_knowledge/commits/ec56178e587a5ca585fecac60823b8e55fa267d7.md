# ec56178 — fix: add negative index bounds check in ArrayObj (#376)

## TL;DR
- Added `i < 0` check to `ArrayObj::operator[]` and `ArrayObj::SetItem` to prevent undefined behavior on negative indices.
- Added C++ tests verifying `IndexError` is thrown for negative indices.

## Why (intent / motivation)
- `ArrayObj::operator[]` and `ArrayObj::SetItem` only checked `i >= size_` but not `i < 0`. Negative indices would bypass the bounds check and cause undefined behavior (out-of-bounds memory access). The higher-level `Array<T>` wrapper already handled negative indices, but the underlying `ArrayObj` did not.

## What changed (facts from diff)
- `include/tvm/ffi/container/array.h`: Changed bounds check from `if (i >= size_)` to `if (i < 0 || i >= size_)` in both `operator[]` and `SetItem`.
- `tests/cpp/test_array.cc`: Added `NegativeIndexThrows` test that verifies both `ArrayObj::at(-1)` and `ArrayObj::SetItem(-1, ...)` throw `IndexError`.

## Public surface changes (if any)
- API: `ArrayObj::operator[]` and `ArrayObj::SetItem` now throw `IndexError` for negative indices instead of silently accessing invalid memory.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_array.cc` (`TEST(Array, NegativeIndexThrows)`)
- How to verify manually: Build and run C++ tests: `cmake --build build_test && ctest -V -C Debug --test-dir build_test -R NegativeIndexThrows`
- CI impact: none
