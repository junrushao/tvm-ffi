# a7ebc65 — Allow `tvm_ffi.device(..., id)` where id is numpy or torch scalar (#347)

## TL;DR
- Extends `tvm_ffi.device()` to accept `numpy` scalars and `torch` tensors as the device index argument
- Uses `numbers.Integral` ABC and `.item()` fallback to coerce non-Python-int device IDs
- Adds test coverage for `numpy.int32` device index

## Why (intent / motivation)
- PyTorch's `torch.device("cuda", numpy.int32(1))` works, but `tvm_ffi.device("cuda", numpy.int32(1))` raised a `TypeError`
- Users mixing NumPy/Torch integer types with tvm_ffi device creation hit unnecessary friction
- Aligning behavior with `torch.device()` improves interoperability

## What changed (facts from diff)
- `python/tvm_ffi/cython/device.pxi`: changed `index` type hint from `Optional[int]` to `Optional[Integral]`; added `from numbers import Integral`; added `.item()` fallback for objects not matching `Integral` (e.g., torch scalar tensors)
- `tests/python/test_device.py`: added `numpy.int32(1)` parametrized test case for `test_device_with_dev_id`; added comment for torch case (dependency not yet available in test env)

## Public surface changes (if any)
- API: `tvm_ffi.device(device_type, index)` now accepts any `numbers.Integral` or object with `.item()` method as `index`
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_device.py` — new parametrized case `("cpu", numpy.int32(1), kDLCPU, 1)`
- How to verify manually: `uv run pytest -vvs tests/python/test_device.py::test_device_with_dev_id`
- CI impact: none
