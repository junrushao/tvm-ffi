# 91fcaa8 — Revert "feat: Add `tvm_ffi.Function.__init__`" (#406)

## TL;DR
- Reverts PR #395 which added `tvm_ffi.Function.__init__` constructor accepting a callable
- Removes `Function.__init__` from Cython, type stubs, and tests
- Cleans up Doxygen comment markers in `base_details.h` that were misplaced in the reverted PR

## Why (intent / motivation)
- PR #395 broke a downstream (incorrect) use case
- Decision was to revert and revisit later

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`: Removed `__init__` method that accepted a callable and converted it to an FFI function handle (21 lines removed)
- `python/tvm_ffi/core.pyi`: Removed `def __init__(self, func: Callable[..., Any]) -> None` stub
- `tests/python/test_function.py`: Removed `test_pyfunc_init` test (9 lines)
- `include/tvm/ffi/base_details.h`: Cleaned up `/// \endcond` and `/*! ... */` Doxygen markers — moved `\endcond` closer to the appropriate block, changed a `/*!` doc comment to a plain `/*` comment for `TVM_FFI_DEFAULT_COPY_MOVE_AND_ASSIGN`, and added `/// \endcond` before `#endif` at end of file

## Public surface changes (if any)
- API: `tvm_ffi.Function(callable)` constructor removed; users must use `tvm_ffi.convert()` instead
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_function.py::test_pyfunc_init` removed
- How to verify manually: `uv run pytest -vvs tests/python/test_function.py` — `test_pyfunc_init` should not exist
- CI impact: none

## Risk & rollout notes
- Risk level: medium — removes a public API that was just added; downstream users who adopted `Function.__init__` will break, but the feature was very new
- Rollout/migration: use `tvm_ffi.convert(func)` instead of `tvm_ffi.Function(func)`
- Follow-ups: revisit `Function.__init__` design to handle the downstream use case
