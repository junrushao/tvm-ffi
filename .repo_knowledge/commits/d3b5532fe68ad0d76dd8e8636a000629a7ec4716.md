# d3b5532 — fix: handle UTF-8 bytes correctly in JSON parser control character check (#442)

## TL;DR
- Fixes a bug where non-ASCII UTF-8 strings were rejected as invalid control characters in the JSON parser
- Casts `*cur_` to `uint8_t` before comparing against space (0x20) to handle platforms where `char` is signed

## Why (intent / motivation)
- On platforms where `char` is signed, bytes >= 0x80 (valid UTF-8 continuation/lead bytes) were misinterpreted as negative values
- This caused all non-ASCII strings (e.g., Chinese characters) to be incorrectly rejected with "Invalid control character" errors

## What changed (facts from diff)
- `src/ffi/extra/json_parser.cc`: Two comparisons `*cur_ < ' '` changed to `*reinterpret_cast<const uint8_t*>(cur_) < ' '` — one in the fast path and one in `NextStringWithFullHandling`
- New regression test `RawUTF8Bytes` in `test_json_parser.cc` that parses a JSON string containing raw UTF-8 bytes for Chinese characters

## Public surface changes (if any)
- API: none
- Flags/config: none
- Data formats/schemas: none (existing JSON parsing now correctly handles UTF-8)
