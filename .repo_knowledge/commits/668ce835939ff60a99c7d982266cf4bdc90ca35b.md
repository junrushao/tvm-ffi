# 668ce83 — fix: handle empty metadata in get_global_func_metadata (#417)

## TL;DR
- Fixes `JSONDecodeError` when calling `get_global_func_metadata()` on Python-registered functions without metadata
- Returns empty dict instead of attempting to parse an empty string with `json.loads()`
- Adds regression test for Python functions without metadata

## Why (intent / motivation)
- Python-registered global functions without C++ metadata cause `json.loads("")` to raise `JSONDecodeError`
- Fixes issue #208

## What changed (facts from diff)
- `python/tvm_ffi/registry.py`: Changed `get_global_func_metadata()` to first capture the metadata string, then only call `json.loads()` if the string is truthy; otherwise returns empty dict
- `tests/python/test_metadata.py`: Added `test_metadata_empty_for_python_func()` that registers a plain Python function, calls `get_global_func_metadata()`, and asserts the result is `{}`; cleans up with `remove_global_func`

## Public surface changes (if any)
- API: `get_global_func_metadata()` now returns `{}` instead of raising `JSONDecodeError` for functions without metadata
- Flags/config: none
