# b508698 — Fix two issues that undefined behavior sanitizer caught (#419)

## TL;DR
- Guards `std::memcpy` calls with size > 0 check to avoid passing null source pointer
- Replaces null pointer arithmetic in `GetObjectOffsetToSubclass` with `__builtin_offsetof`
- Fixes UBSan violations reported in issue #413

## Why (intent / motivation)
- The undefined behavior sanitizer (UBSan) flagged two issues:
  1. `std::memcpy` with a null source pointer and size 0 is technically undefined behavior per the C++ standard
  2. Null pointer member access (`static_cast<Class*>(nullptr)->header_`) is undefined behavior
- These are correctness fixes that prevent potential issues on strict compilers/platforms

## What changed (facts from diff)
- `include/tvm/ffi/string.h`: Added `if (size > 0)` guard around `std::memcpy` in both `Bytes::InitData` and `String::InitData` methods
- `include/tvm/ffi/object.h`: `GetObjectOffsetToSubclass<Class>()` now uses `__builtin_offsetof(Class, header_)` instead of null pointer arithmetic; added `#pragma GCC diagnostic` to suppress `-Winvalid-offsetof` warning for non-standard-layout types
