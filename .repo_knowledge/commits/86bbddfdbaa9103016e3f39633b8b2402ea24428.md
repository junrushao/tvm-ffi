# 86bbddf -- feat: Add overflow check for uint64_t/size_t in TypeTraits<Int>::CopyToAnyView (#370)

## TL;DR
- Adds runtime overflow detection when converting `uint64_t`/`size_t` to `int64_t` in `TypeTraits<Int>::CopyToAnyView`, throwing `OverflowError` for values exceeding `INT64_MAX`.
- Updates `structural_hash.cc` to explicitly cast `uint64_t` hash results to `int64_t` to avoid triggering the new overflow check.
- Changes the FFI-exposed `ffi.StructuralHash` to return `int64_t` instead of `uint64_t`.

## Why (intent / motivation)
- TVM-FFI's `Any`/`AnyView` stores integers as `int64_t`. Converting a `uint64_t` value larger than `INT64_MAX` silently produced incorrect values. This adds explicit overflow detection with a clear error message.

## What changed (facts from diff)
- In `include/tvm/ffi/type_traits.h`: Added a `constexpr if` guard in `CopyToAnyView` for unsigned types of `sizeof >= sizeof(int64_t)` that throws `OverflowError` when `src > numeric_limits<int64_t>::max()`.
- Added `#include <limits>` to `type_traits.h`.
- In `src/ffi/extra/structural_hash.cc`: All `uint64_t` return values from `StableHashCombine` are now explicitly cast to `int64_t` via `static_cast<int64_t>()`.
- Created a new `FFIStructuralHash` wrapper function returning `int64_t` instead of `uint64_t`, registered as `"ffi.StructuralHash"`.
- The hash value passed to custom `__s_hash__` callbacks is now `int64_t` instead of `uint64_t`.
- In `tests/cpp/testing_object.h`: Updated `TCustomFuncObj::SHash` signature from `uint64_t` to `int64_t`.
- Added test in `tests/cpp/test_any.cc` verifying `OverflowError` is thrown for `uint64_t(INT64_MAX + 1)`.

## Public surface changes (if any)
- API: `ffi.StructuralHash` global function now returns `int64_t` instead of `uint64_t`. Custom `__s_hash__` method signatures must use `int64_t` instead of `uint64_t`.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_any.cc` (overflow check test), `tests/cpp/testing_object.h` (signature update).
- How to verify manually: Build and run C++ tests. Try assigning `uint64_t(INT64_MAX + 1)` to an `AnyView` and verify `OverflowError` is thrown.
- CI impact: none

## Risk & rollout notes
- Risk level: medium -- Changes the type signature of `ffi.StructuralHash` and custom hash callbacks from `uint64_t` to `int64_t`. Any existing custom `__s_hash__` implementations using `uint64_t` will need updating.
- Rollout/migration: Update custom `__s_hash__` method signatures from `uint64_t` to `int64_t`.
- Follow-ups: 128-bit signed integers are not considered (noted in PR description).
