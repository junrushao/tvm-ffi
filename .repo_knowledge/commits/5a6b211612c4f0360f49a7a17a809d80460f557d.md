# 5a6b211 -- [REACTOR] Cleanup and improve map array containers (#462)

## TL;DR
- Removed `InplaceArrayBase` CRTP class (no longer needed)
- Extracted `MapObj` internals into `map_base.h` so the base class can be reused by Dict and other map variants
- Reorganized `SmallBaseMapObj` after `DenseMapObj` in the source for future refactor readiness
- Simplified `ArrayObj` to inherit only from `SeqBaseObj`

## Why (intent / motivation)
- `InplaceArrayBase` was a complex CRTP pattern that added unnecessary indirection; `ArrayObj` can compute inplace addresses directly
- The map implementation needed to be split so `MapBaseObj` could serve as a shared base for both immutable `Map` and a future mutable `Dict`
- Reorganizing the map internals reduces code duplication and prepares for future container variants

## What changed (facts from diff)
- `include/tvm/ffi/container/container_details.h`: Removed entire `InplaceArrayBase<ArrayType, ElemType>` template class (~128 lines)
- `include/tvm/ffi/container/array.h`: `ArrayObj` no longer inherits from `InplaceArrayBase`; removed `using` declarations for `SeqBaseObj` members; inplace address computation uses `reinterpret_cast<char*>(p.get()) + sizeof(ArrayObj)` directly
- `include/tvm/ffi/container/map.h`: Gutted to ~30 lines; all map internals moved to `map_base.h`; now just includes `map_base.h` and defines `MapObj` and `Map<K, V>`
- `include/tvm/ffi/container/map_base.h`: New file (+1444 lines) containing `SmallBaseMapObj`, `DenseMapObj`, `MapBaseObj`, and all map iteration/hashing infrastructure; reordered so `DenseMapObj` appears before `SmallBaseMapObj`
- `include/tvm/ffi/extra/stl.h`: Minor adjustments to includes

## Public surface changes (if any)
- API: `InplaceArrayBase` removed from public headers (was `details::` namespace, unlikely external use)

- Data formats/schemas: none
