# 83daf69 -- feat: Restrict `__slots__=()` for subclasses of `tvm_ffi.Object` by default (#27)

## TL;DR
- Splits the Cython `Object` class into `CObject` (internal base) and `Object` (public class with `__slots__` enforcement)
- All Cython extension types (ByteArrayArg, Device, DataType, Error, Tensor, etc.) now declare `__slots__ = ()`
- Python subclasses of `tvm_ffi.Object` are required to have `__slots__ = ()` to prevent accidental instance dict creation
- Adds `__init_handle_by_constructor__` helper method to `Object`

## Why (intent / motivation)
- TVM FFI Object subclasses should not allow arbitrary attribute assignment since their state lives in C++ objects
- Without `__slots__`, Python would create an instance `__dict__` for each object, wasting memory and creating confusing behavior where Python-side attributes would silently diverge from C++-side fields
- This enforces a consistent memory model across all Object subclasses

## What changed (facts from diff)
- Renamed the Cython `Object` class to `CObject` (internal base with chandle and ref-counting logic)
- Created a new `Object(CObject)` class that enforces `__slots__ = ()` via `__init_subclass__`
- Added `__slots__ = ()` to all existing Cython extension types: `ByteArrayArg`, `Device`, `DataType`, `Error`, `Function`, `Tensor`, `String`, etc.
- Updated `core.pyi` stub to reflect the `CObject`/`Object` split
- Updated all internal Cython casts from `<Object>` to `<CObject>` where accessing `chandle` directly
- `module.py` updated to use `__init_handle_by_constructor__` and `__move_handle_from__` from `CObject`
- `docs/conf.py` updated to map `CObject` back to `Object` in documentation links
- Added `_move`, `__move_handle_from__`, `__init_handle_by_constructor__` to `_autodoc_always_show`

## Public surface changes (if any)
