# 0d157dc — [CMAKE] Allow threads to be not found for cross compilation (#397)

## TL;DR
- Makes the Threads library linkage optional so TVM-FFI can build on cross-compilation targets where threads are unavailable.
- Moves `find_package(Threads)` from a top-level REQUIRED call to a conditional check near the link step.

## Why (intent / motivation)
- On some cross-compilation platforms, the Threads library may not be available. Making it optional allows the library to still be built, with downstream projects providing their own thread alternatives via the source bundle.

## What changed (facts from diff)
- Removed `find_package(Threads REQUIRED)` from the top of CMakeLists.txt.
- Added `find_package(Threads)` (non-REQUIRED) near the link step, guarded by `if (Threads_FOUND)`.
- Thread library linkage to `tvm_ffi_shared` and `tvm_ffi_static` is now conditional on `Threads_FOUND`.

## Public surface changes (if any)
- API: none
- Flags/config: Threads linkage is now optional (was previously required)
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: Cross-compile on a platform without pthreads; the build should succeed without thread linkage.
- CI impact: none (standard platforms will find Threads as before)

## Risk & rollout notes
- Risk level: low — relaxes a requirement; existing platforms where Threads is found are unaffected
- Rollout/migration: none
- Follow-ups: Superseded by commit 3b4a532 which adds an explicit `TVM_FFI_USE_THREADS` option
