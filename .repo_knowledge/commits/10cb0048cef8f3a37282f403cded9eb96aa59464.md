# 10cb004 — [CUDA] Isolate unified api to only in cubin launcher (#408)

## TL;DR
- Splits CUDA error checking into two macros: `TVM_FFI_CHECK_CUDA_ERROR` (runtime API only, in `base.h`) and `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR` (unified driver/runtime API, in `internal/unified_api.h`)
- `device_guard.h` now includes `base.h` instead of `internal/unified_api.h`, removing driver API dependency for non-cubin-launcher code
- All cubin launcher examples and tests updated to use `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`
- CI clang-tidy path filter changed from file-extension matching to directory-based matching

## Why (intent / motivation)
- Mixing CUDA driver and runtime API is error-prone; the unified API switch was only meant for cubin launcher in a narrow CUDA version range (~12.8 to 13.0)
- Generic macros like `TVM_FFI_CHECK_CUDA_ERROR` should be specific to the runtime API for safety and clarity
- The driver API dependency should be isolated to the cubin launcher subsystem

## What changed (facts from diff)
- `include/tvm/ffi/extra/cuda/base.h`: New `TVM_FFI_CHECK_CUDA_ERROR` macro added, using `cudaError_t`/`cudaGetErrorName`/`cudaGetErrorString` (runtime API); now includes `<cuda_runtime.h>` and `<tvm/ffi/error.h>`
- `include/tvm/ffi/extra/cuda/internal/unified_api.h`: `TVM_FFI_CHECK_CUDA_ERROR` renamed to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`; NOLINT annotations added
- `include/tvm/ffi/extra/cuda/device_guard.h`: Include changed from `internal/unified_api.h` to `base.h`
- `include/tvm/ffi/extra/cuda/cubin_launcher.h`: All `TVM_FFI_CHECK_CUDA_ERROR` usages changed to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`; `#include <cuda.h>` gets NOLINT; doc examples updated
- All cubin launcher examples (`dynamic_cubin`, `embedded_cubin/*`, `example_nvrtc_cubin.py`, `example_triton_cubin.py`) updated to use `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR` macro
- `tests/python/test_cubin_launcher.py`: Updated macro usage and changed `cudaError_t result` to `auto result`
- `.github/workflows/ci_test.yml`: clang-tidy file detection changed from extension-based globbing to directory-based (`src/` `tests/`) with grep filter
- `docs/guides/cubin_launcher.rst`: Doc example updated to use new macro name

## Public surface changes (if any)
- API: `TVM_FFI_CHECK_CUDA_ERROR` macro semantics changed — it now only works with `cudaError_t` (runtime API); the old unified version is renamed to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`
- Flags/config: none
- Data formats/schemas: none

## Tests & verification

## Risk & rollout notes
- Risk level: high — breaks any downstream code using `TVM_FFI_CHECK_CUDA_ERROR` with driver API result types (from `unified_api.h`); also changes what `device_guard.h` transitively includes
- Rollout/migration: downstream users of `TVM_FFI_CHECK_CUDA_ERROR` in cubin launcher contexts must switch to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`
- Follow-ups: consider deprecating driver API usage entirely for maintainability
