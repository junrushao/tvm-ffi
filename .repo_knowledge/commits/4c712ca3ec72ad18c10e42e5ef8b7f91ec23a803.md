# 4c712ca — [RFC][Error][ABI] Update Error to enable future compact to cause chaining (#396)

## TL;DR
- Extends `TVMFFIErrorCell` with two new optional fields: `cause_chain` and `extra_context` for error chaining.
- Adds new C API `TVMFFIErrorCreateWithCauseAndExtraContext` and a new `Error` C++ constructor accepting cause chain and extra context.
- Backward compatible: existing code ignores the new fields (they default to nullptr).

## Why (intent / motivation)
- Enable future support of cause chaining in TVM-FFI's error system, allowing errors to carry references to the original error that caused them and to attach opaque context objects (e.g., Python exception info).

## What changed (facts from diff)
- `TVMFFIErrorCell` struct gains two new `TVMFFIObjectHandle` fields: `cause_chain` and `extra_context`.
- `ErrorObj` constructor now zero-initializes these fields; destructor decrements their reference counts if non-null.
- New `Error` constructor: `Error(kind, message, backtrace, optional<Error> cause_chain, optional<ObjectRef> extra_context)`.
- New accessor methods: `Error::cause_chain()` and `Error::extra_context()` returning `std::optional`.
- New C API function `TVMFFIErrorCreateWithCauseAndExtraContext` in `c_api.h` and implemented in `error.cc`.
- New C++ test `Error.CauseChain` validates cause chain creation and retrieval.

## Public surface changes (if any)
- API: New C ABI function `TVMFFIErrorCreateWithCauseAndExtraContext`; new C++ `Error` constructor and accessors `cause_chain()`, `extra_context()`
- Flags/config: none
- Data formats/schemas: `TVMFFIErrorCell` struct extended (fields appended; backward compatible for ABI)

## Tests & verification
- Added/updated tests: `tests/cpp/test_error.cc` — new `Error.CauseChain` test
- How to verify manually: Build and run C++ tests: `ctest -V -C Debug --test-dir build_test -R test_error`
- CI impact: none (additive change)

## Risk & rollout notes
- Risk level: medium — extends a C ABI struct (`TVMFFIErrorCell`) by appending fields. While backward compatible (old code ignores new fields), any code that hard-codes the struct size or copies it by value could break.
- Rollout/migration: No migration needed. Old code that only reads `kind`/`message`/`backtrace` will continue to work.
- Follow-ups: Python-side cause chaining support is not yet implemented.
