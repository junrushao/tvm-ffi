# 37f45c3 — Reliability update (#435)

## TL;DR
- Fixes torch_c_dlpack_ext build to not bail out when torch is not installed
- Handles `AttributeError` from ABI mismatch between torch_c_dlpack_ext and torch when loading via ctypes

## Why (intent / motivation)
- The build backend for `torch_c_dlpack_ext` would crash with an `ImportError` if torch was not installed, preventing wheel builds in torch-free environments
- When the pre-built `torch_c_dlpack_ext` shared library has different ABI symbols than the installed torch, `ctypes.CDLL` raises an `AttributeError` instead of the expected `ImportError`, causing unhandled crashes

## What changed (facts from diff)
- `addons/torch_c_dlpack_ext/build_backend.py`: Changed torch import to be wrapped in `contextlib.suppress(ModuleNotFoundError)` so the build proceeds even without torch; only attempts to compile the extension when torch is actually available
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Added `except AttributeError` handler in the extension loading flow to gracefully fall through to JIT compilation when ABI mismatch occurs
