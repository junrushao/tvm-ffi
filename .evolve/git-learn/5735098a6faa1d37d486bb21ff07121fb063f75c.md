# Skill /git-learn - Self-Evolution
- **Grouping parameters**: Parameters were appropriate. The 24-group partition at MAX_LOC=7500/MAX_COMMITS=100 produced groups of 1-59 commits, with most in the 5-42 range. Group 11 (59 commits) was the largest but still manageable. No groups mixed unrelated work or split related work inappropriately.
- **Pipeline bottleneck**: The `/commit-distill` phase was consistently the slowest step per group (700-1000s vs 250-400s for ledger fan-out), because it must read all ledgers sequentially and make many design doc edits. For large groups (59 commits), distillation took ~13 minutes.
- **Cross-skill patterns**: No recurring friction from downstream skills. The worktree isolation worked reliably (only 1 worktree lock failure out of ~500 spawns). The batching of Groups 16-17 ledger into a single agent (which then internally spawns subagents) was ~2x faster per commit than the orchestrator spawning individual agents, suggesting the skill should recommend this pattern for groups with many commits.
- **Distillation coverage**: Coverage looks complete. All 18 design docs, 19 ADRs, and 17 API indexes were created or updated incrementally across the 24 groups. The group-then-distill structure worked well -- no design fell through the cracks.
- **Suggested skill changes**: Consider adding a "batch ledger" mode to `/git-learn` that allows groups 16+ to use a single agent to internally parallelize `/commit-ledger` calls, reducing orchestrator overhead. The consolidated distill for Groups 18-24 (41 commits in one pass) worked well and could be the default for the final ~25% of any large range.
