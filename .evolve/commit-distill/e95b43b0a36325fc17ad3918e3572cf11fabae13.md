# Skill /commit-distill - Self-Evolution
- **Template mismatch**: None — templates fit well for this batch of 31 commits spanning reflection system evolution, API renames, container ABI stabilization, and function registration migration.
- **Upstream skill gap**: None — ledger inputs were comprehensive and accurate. All 31 ledgers had complete Key Exports, Design Elements, and Usage Examples sections.
- **Quality bar friction**: The "evolution timeline" requirement was highly valuable for the reflection system (0009) which evolved across 10+ commits; less useful for design docs with only 1-2 supporting commits. Consider making it conditional on >= 3 commits touching the same design doc rather than >= 3 evolution commits in evidence.
- **Procedure friction**: With 31 commits and 9 design docs + 4 ADRs + 4 API indexes to update, the batch size tested the limits of context management. The planner phase could benefit from explicit guidance on prioritizing depth (fewer docs, fully rewritten) vs breadth (all docs, targeted edits).
- **Suggested skill change**: Add a "batch size guidance" note in Step 2 (Planner): for batches > 20 commits, recommend identifying the top-3 design docs by commit density and doing full rewrites on those, with targeted edits on the rest.
