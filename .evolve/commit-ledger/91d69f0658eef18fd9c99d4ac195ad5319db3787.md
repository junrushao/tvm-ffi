- **Template gap**: The Impact section has "API" and "Behavioral" but no explicit "Backwards compatibility" field. This commit subtly changes `convert()` from raising `TypeError` to succeeding silently, which is a backwards-incompatible behavioral change that does not fit neatly into "API" (no signature change) or "Behavioral" (usually implies same inputs, different outputs). A dedicated "Breaking / backwards-incompatible" field would make this clearer.

- **Suggested skill change**: Add a "Breaking changes" sub-bullet under Impact in `template-commit-ledger.md`, e.g., `- Breaking: {{none OR describe callers that may break}}`. This would separate intentional contract changes from additive API/behavioral changes.
