# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: Step 3.5 Key Exports asks for pseudocode of new/changed API surface, but for a pure annotation commit the "change" is adding types to existing signatures. The guidance to show "old -> new as comments" works but generates a very long listing for 37 files of mechanical annotation additions. A shape-level shortcut for "annotation-only" commits would reduce output size.
- **Template gap**: None.
- **Wasted effort**: Step 3.4 cross-layer consistency check was skipped (single layer, Python only) which is correct, but the mental overhead of evaluating it is nonzero for an obviously single-layer commit. The fast-skip rule worked well here.
- **Suggested skill change**: Consider adding a `linting` or `annotation` shape for commits that only add linter rules and their mechanical fixes (type annotations, formatting). These are not trivial (they can touch many files) but the per-file analysis depth should be capped at "list affected modules + note any behavioral side-effects."
