# fix: Compatibility with torch <= 2.8 (#54)
## TL;DR
- Expands `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` guards in the JIT'd C++ extension to cover `Float8_e8m0fnu` (in addition to Float4 types) and the lanes-check `if` block that references `kDLFloat4_e2m1fn`.
- In Cython `dtype.pxi`, uses `hasattr(torch, ...)` checks for `float8_e8m0fnu` and `float4_e2m1fn_x2` instead of unconditionally accessing them, preventing `AttributeError` on older torch versions.

## Impact
- API: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Version-gated dtype support pattern established in commit b03cc78 (#53)

Design elements this commit produces:
- Extended version-guard coverage: all three new dtype families (`Float8_e8m0fnu`, `Float4_e2m1fn`, `Float4_e2m1fn_x2`) are now fully gated in both JIT C++ and Cython

## Reflection
- Commit b03cc78 (#53) was an incomplete fix -- it only guarded Float4 types in one direction (DL-to-torch) but missed Float8_e8m0fnu in `getDLDataTypeForDLPackv1` and the lanes-check preamble in `toScalarTypeForDLPackv1`. This commit completes the backward-compat story.
- The Cython side uses runtime `hasattr` checks because Cython code is compiled ahead of time against torch's Python API, not the C++ headers.
