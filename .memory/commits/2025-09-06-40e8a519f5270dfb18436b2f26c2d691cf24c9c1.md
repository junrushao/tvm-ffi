# [FFI][ABI] Append symbol prefix for ffi exported functions (#18273)
## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` now emits C symbols with `__tvm_ffi_` prefix (e.g., `__tvm_ffi_ExportName`) instead of bare `ExportName`.
- Internal/special library symbols gain an extra `_` separator (`__tvm_ffi__library_ctx`, `__tvm_ffi__library_bin`, `__tvm_ffi__metadata_`) to avoid collision with user-exported names.
- `Library` base class gains `GetSymbolWithSymbolPrefix` virtual, so `LibraryModuleObj::GetFunction` transparently prepends the ffi prefix during symbol lookup.
## Impact
- API: `TVM_FFI_DLL_EXPORT_TYPED_FUNC` changes the emitted C symbol name (ABI-breaking for downstream .so consumers). Python `Module.entry_name` changes from `"__tvm_ffi_main__"` to `"main"` (prefix applied internally).
- Flags/config: none
- Data formats/schemas: symbol names in shared libraries change
## Design Elements
Design elements this commit consumes:
- `symbol::` namespace constants in `module.h`
- `Library` / `SystemLibrary` / `DSOLibrary` hierarchy in `module_internal.h`
Design elements this commit produces:
- `symbol::tvm_ffi_symbol_prefix` constant (`"__tvm_ffi_"`)
- `Library::GetSymbolWithSymbolPrefix` virtual method (default prepends prefix, overridden by `SystemLibrary`)
- Convention: user-facing names are prefix-free; prefix is applied at symbol lookup layer
## Reflection
- This separates user-visible function names from C symbol names, making the module system cleaner and reducing the chance of symbol collisions in shared libraries.
- The double-underscore convention (`__tvm_ffi__`) for internal symbols vs single-underscore (`__tvm_ffi_`) for user functions is a simple but effective namespacing strategy.
