# [experimental] Initial bringup of rust support (#80)

## TL;DR
- Adds a complete Rust crate workspace (`rust/`) with three crates: `tvm-ffi-sys` (raw C ABI), `tvm-ffi-macros` (proc-macros), and `tvm-ffi` (safe ergonomic API).
- Mirrors the C++/Python object model in Rust: `Any`/`AnyView` type-erased containers, `ObjectArc<T>` ref-counted objects, `Function` packed calling convention, `String`/`Bytes`/`Tensor`/`Shape` containers.
- Supports both consuming FFI libraries from Rust and exposing Rust libraries as FFI-compatible shared objects.

## Impact
- API: Introduces a brand-new language surface. No changes to existing C++ or Python APIs. Rust types are `#[repr(C)]` and ABI-compatible with the C types in `include/tvm/ffi/c_api.h`.
- Flags/config: `tvm-ffi-sys/build.rs` discovers the native library via a `tvm-ffi-config` CLI tool (produced by the Python package install). Sets `DYLD_LIBRARY_PATH`/`LD_LIBRARY_PATH` for cargo test/run.
- Data formats/schemas: None changed. The Rust `TVMFFIAny`, `TVMFFIObject`, DLPack structs are hand-written `#[repr(C)]` mirrors of the C headers, not bindgen-generated.

## Design Elements

Design elements this commit **consumes**:
- The stable C ABI surface (`TVMFFIAny`, `TVMFFIObject`, `TVMFFIFunctionCell`, `TVMFFIByteArray`, DLPack structs) defined in `include/tvm/ffi/c_api.h`.
- The ref-counting protocol: `combined_ref_count` with strong/weak split and three-phase deleter flags (`kTVMFFIObjectDeleterFlagBitMask{Strong,Weak,Both}`). Rust reimplements `inc_ref`/`dec_ref` natively rather than calling the C functions, for efficiency. Evidence: `rust/tvm-ffi/src/object.rs` `unsafe_::dec_ref` faithfully reproduces the C++ `ObjectInternal::DecRef` logic including the two-phase weak-ref cleanup.
- The packed function calling convention `(const TVMFFIAny* args, int num_args, TVMFFIAny* rv) -> int` and the global function registry (`TVMFFIFunctionGetGlobal` / `TVMFFIFunctionSetGlobal`).
- The module loading mechanism (`TVMFFIModuleLoadFromFile`) and `__tvm_ffi_<name>` symbol convention.

Design elements this commit **produces**:
- **`ObjectCore` trait** (`rust/tvm-ffi/src/object.rs`): Unsafe trait that all Rust object types implement. Provides `TYPE_KEY`, `type_index()`, `object_header_mut()`. Two flavors: `ObjectCore` for simple objects, `ObjectCoreWithExtraItems` for variable-length objects (String, Bytes).
- **`ObjectRefCore` trait** (`rust/tvm-ffi/src/object.rs`): Trait for ref-wrapper types (like C++ `ObjectRef`). Provides `data()`, `into_data()`, `from_data()`.
- **`AnyCompatible` trait** (`rust/tvm-ffi/src/type_traits.rs`): The central type-erasure interface. Requires 7 methods: `copy_to_any_view`, `move_to_any`, `check_any_strict`, `copy_from_any_view_after_check`, `move_from_any_after_check`, `try_cast_from_any_view`, `type_str`. Implemented for all primitive types, DLDataType, DLDevice, String, Bytes, ObjectRef, and `Option<T>`.
- **Proc-macro derives** (`rust/tvm-ffi-macros/`): `#[derive(Object)]` with `#[type_key]` / `#[type_index]` attrs generates `ObjectCore` impl. `#[derive(ObjectRef)]` generates `ObjectRefCore` + `AnyCompatible` impls for ref wrappers.
- **`register_global_func!` macro** (`rust/tvm-ffi/src/macros.rs`): Registers a Rust closure as a global FFI function using `#[ctor]` for static initialization, mirroring `TVM_FFI_REGISTER_GLOBAL` in C++.
- **`into_typed_fn!` macro** (`rust/tvm-ffi/src/macros.rs`): Wraps an untyped `Function` into a typed Rust closure `Fn(A, B, ...) -> Result<R>`.
- **`CallbackFunctionObjImpl<F>`** (`rust/tvm-ffi/src/function.rs`): Pattern for wrapping arbitrary `Fn(&[AnyView]) -> Result<Any>` closures as `FunctionObj`. Uses `#[repr(C)]` struct inheritance: `{FunctionObj, callback: F}` with a custom deleter so the correct `F` destructor runs.
- **`String`/`Bytes` containers** (`rust/tvm-ffi/src/string.rs`): Dual representation -- small-string optimization in inline `TVMFFIAny` for short strings, heap-allocated `StringObj`/`BytesObj` with `ObjectCoreWithExtraItems` for long strings. Deref to `&str` / `&[u8]`.
- **`Tensor` / `Shape`** (`rust/tvm-ffi/src/collections/`): `Tensor` wraps `DLManagedTensor` with `NDAllocator` trait; `Shape` is a fixed-size inline shape or heap-allocated shape object.
- **Test suite** (`rust/tvm-ffi/tests/`): 8 test files covering any, device, dtype, error, function, object, shape, string, tensor.
- **CI integration** (`.github/workflows/ci_test.yml`): `cargo test` step added after Python pip install.

## Reflection
- The Rust crate manually mirrors C ABI structs rather than using bindgen. This is intentional: the ABI is small and stable, and hand-written `#[repr(C)]` structs give precise control over atomics (`AtomicU64` for `combined_ref_count`) and alignment.
- Ref-counting is reimplemented natively in Rust (`object::unsafe_::inc_ref`/`dec_ref`) instead of calling through the C API. This avoids FFI call overhead on every clone/drop, which is critical since object lifetimes are pervasive.
- The `ObjectCoreWithExtraItems` pattern (variable-length allocation trailing the object header) for String/Bytes is a direct port of the C++ pattern and requires careful manual allocation/deallocation with `std::alloc::alloc`/`dealloc` and custom deleters.
- The `tvm-ffi-sys` build.rs depends on `tvm-ffi-config` CLI tool, meaning `cargo test` requires the Python package to be installed first. This coupling is acknowledged and reflected in CI ordering.
