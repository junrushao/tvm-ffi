# [FFI] Support Opaque PyObject (#18270)
## TL;DR
- Introduces `kTVMFFIOpaquePyObject` type index (74) and `TVMFFIOpaqueObjectCell` struct for wrapping arbitrary Python objects as ref-counted FFI objects.
- Adds C API `TVMFFIObjectCreateOpaque(handle, type_index, deleter, out)` and C++ `OpaqueObjectImpl` to manage the lifecycle of opaque handles.
- In the Cython layer, unrecognized Python types are now automatically converted to opaque objects instead of raising `TypeError`; on return they are unwrapped back to the original Python object.
## Impact
- API: New C API function `TVMFFIObjectCreateOpaque`. New Python class `OpaquePyObject` with `.pyobject()` method. Previously, passing an unsupported Python type to an FFI function raised `TypeError`; now it is silently wrapped as an opaque object.
- Flags/config: none
- Data formats/schemas: New type index `kTVMFFIOpaquePyObject = 74` in the static type index enum.
## Design Elements
Design elements this commit consumes:
- Object system (`Object`, `ObjectPtr`, `make_object`)
- Cython FFI argument packing (`make_args`) and return handling (`make_ret`)
- `TVMFFIObjectDeleterFlagBitMask` from the weak-rc commit
Design elements this commit produces:
- `OpaqueObjectImpl` -- C++ object wrapping an opaque `void*` handle with a custom deleter
- `OpaquePyObject` -- Cython wrapper exposing `.pyobject()` to retrieve the original Python object
- Transparent round-trip: Python -> opaque FFI object -> Python (identity preserved via PyObject* pointer)
## Reflection
- The opaque object mechanism enables Python callbacks and containers to hold arbitrary Python objects through the FFI boundary without requiring explicit type registration, which is important for interop with frameworks that define their own types.
- The deleter is shared (`tvm_ffi_pyobject_deleter`, renamed from `tvm_ffi_callback_deleter`) between Function callbacks and opaque objects, both of which wrap PyObject* handles.
