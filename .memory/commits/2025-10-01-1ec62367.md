# [FEAT] Introduce TensorView for non-owning view (#81)
## TL;DR
- Adds `ffi::TensorView`, a non-owning lightweight view over a `DLTensor`, for use in FFI function signatures where callers cannot provide an owning `Tensor` reference
- `TensorView` stores a copy of `DLTensor` struct, provides `shape()`, `strides()`, `data_ptr()`, `ndim()`, `numel()`, `dtype()`, `IsContiguous()` accessors
- Registers `TypeTraits<TensorView>` mapping to `kTVMFFIDLTensorPtr` type index; supports `TryCastFromAnyView` from both `DLTensor*` and owned `Tensor`
- Adds `StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"` to `object.h`
- Updates examples and docs to use `TensorView` in kernel op signatures

## Impact
- API: New public class `ffi::TensorView` in `container/tensor.h`; new static type key `kTVMFFIDLTensorPtr` in `object.h`. Existing `Tensor` API unchanged. Kernel ops recommended to use `TensorView` for broader input support.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeTraits` specialization pattern for custom FFI types
- `AnyView` / `TVMFFIAny` type-erasure system (`kTVMFFIDLTensorPtr` type index)

Design elements this commit produces:
- `ffi::TensorView` non-owning tensor view pattern, reusable for future non-owning views
- Move-from-owned explicitly deleted (`TensorView(Tensor&&) = delete`) as a safety pattern

## Reflection
- Deliberate design: `TensorView` does NOT support `MoveToAny`/`MoveFromAny` since it does not retain ownership -- this prevents accidental ownership promotion
- The class copies the `DLTensor` struct (not the data), making it safe to pass around as long as the underlying data outlives the view
