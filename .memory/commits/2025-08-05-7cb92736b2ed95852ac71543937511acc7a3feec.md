# [FFI][REFACTOR] Migrate the Save/Load JSON to the new reflection (#18188)

## TL;DR
- Introduces `reflection::ObjectCreator` (`include/tvm/ffi/reflection/creator.h`), a new header that constructs objects from a `Map<String, Any>` of field values using reflection metadata (creator callback + `ForEachFieldInfo` field walk).
- Adds `Shape` serialization/deserialization support to `src/ffi/extra/serialization.cc`, encoding shapes as `{"type": "ffi.Shape", "data": [dims...]}`.
- Relaxes `CreateObjectData` return type from `json::Object` to `json::Value` to support custom `__data_to_json__` functions that return non-object JSON values.
- Renames `tests/cpp/test_reflection_accessor.cc` to `tests/cpp/test_reflection.cc` and adds `ObjectCreator` test; adds `TIntObj() = default` to enable reflection-based default construction.

## Impact
- API: New public header `include/tvm/ffi/reflection/creator.h` with `reflection::ObjectCreator` class. `CreateObjectData` private return type changed from `json::Object` to `json::Value` (internal to serialization.cc, no public API break).
- Flags/config: none
- Data formats/schemas: JSON serialization format extended with `ffi.Shape` node type. This is an additive format change; existing node types are unchanged.

## Design Elements
Design elements this commit consumes:
- Reflection system (`ObjectDef<T>`, `ForEachFieldInfo`, `TVMFFITypeMetadata.creator`) -- [.memory/designs/0006-reflection-system.md](.memory/designs/0006-reflection-system.md)
- Extra API isolation (serialization lives in `src/ffi/extra/`) -- [.memory/ADRs/0009-extra-api-isolation.md](.memory/ADRs/0009-extra-api-isolation.md)

Design elements this commit produces:
- `reflection::ObjectCreator`: a standalone, reusable reflection-based object factory that validates required fields, applies defaults, and detects extra fields. This is a higher-level alternative to `MakeObjectFromPackedArgs` (which uses positional keyword-arg pairs) -- the creator takes a typed `Map<String, Any>` instead.

## Reflection
- The commit message says it "migrates Save/Load JSON to the new reflection," but the diff shows the serialization code was already largely reflection-based. The concrete changes are: (1) adding the `ObjectCreator` header, (2) adding `Shape` as a built-in serializable type, and (3) relaxing `CreateObjectData`'s return type. The "migration" likely refers to a larger upstream PR where the bulk of the reflection-based serialization was introduced; this commit captures the tail-end refinements.
- `ObjectCreator` overlaps with `MakeObjectFromPackedArgs` (registered as `ffi.reflection.MakeObjectFromPackedArgs`). The creator uses `Map<String, Any>` while `MakeObjectFromPackedArgs` uses packed positional args with alternating key-value pairs. Both walk `ForEachFieldInfo` in the same parent-to-child order. This duality is a design choice favoring call-site ergonomics: packed args for C API callers, typed map for C++ callers.
- Adding `TIntObj() = default` to `testing_object.h` was necessary because the reflection creator calls `TVMFFITypeMetadata.creator`, which invokes `make_object<T>()` (no-arg), requiring a default constructor.
