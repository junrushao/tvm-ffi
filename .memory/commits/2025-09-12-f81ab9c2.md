# [FFI][ABI][REFACTOR] Enhance DLPack Exchange Speed and Behavior (#18306)
## TL;DR
- Introduces a `DLPackTensorAllocator` C callback type in `c_api.h` and a `Tensor::FromDLPackAlloc` factory, enabling thread-local custom tensor allocators via `TVMFFIEnvSetTensorAllocator`.
- Renames the DLPack C-exporter protocol from `__dlpack_c_exporter__` to `__c_dlpack_exporter__` and adds symmetric `__c_dlpack_importer__` / `__c_dlpack_tensor_allocator__` protocols on Python objects, enabling zero-copy round-trip DLPack exchange (export and import) without Python capsule overhead.
- Converts `Function` from a Python class to a `cdef class` with a `release_gil` property (env-default `TVM_FFI_RELEASE_GIL_BY_DEFAULT=1`), allowing per-call GIL control during packed-function invocation.
- Adds `_optional_torch_c_dlpack.py` (403 lines) for optional PyTorch C-level DLPack integration, plus PyTorch license files.
- Removes `with nogil:` blocks from several DLPack conversion calls in `tensor.pxi` (GIL release now handled at the `Function.__call__` level).
- Renames `stream_context.cc` to `env_context.cc`, consolidating environment/stream/allocator APIs.
## Impact
- API: `__dlpack_c_exporter__` renamed to `__c_dlpack_exporter__`; callers using the old protocol name must update. `Function` is now a Cython extension type (subclasses in pure Python may need adjustment). New `Function.release_gil` property.
- Flags/config: New env vars `TVM_FFI_RELEASE_GIL_BY_DEFAULT` and `TVM_FFI_SKIP_C_DLPACK_EXPORTER`.
- Data formats/schemas: New `DLPackTensorAllocator` C callback typedef added to ABI.
## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetter` dispatch pattern from commit 38d2cdaa
- DLPack v1/v1.1 capsule protocol
Design elements this commit produces:
- `__c_dlpack_exporter__` / `__c_dlpack_importer__` / `__c_dlpack_tensor_allocator__` symmetric C-level DLPack exchange protocol
- `DLPackTensorAllocator` callback type for pluggable tensor memory allocation
- `TVMFFIEnvSetTensorAllocator` / `TVMFFIEnvGetTensorAllocator` thread-local allocator APIs
- `Function.release_gil` per-function GIL control
## Reflection
- Moving GIL release from individual DLPack calls to the Function.__call__ level simplifies code and centralizes GIL policy.
- The symmetric exporter/importer protocol allows framework-to-framework tensor passing (e.g. TVM <-> PyTorch) entirely in C without touching Python capsules.
