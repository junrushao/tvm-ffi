# [FFI][ABI] Better String and Nested Container handling (#18311)
## TL;DR
- Adds C API functions `TVMFFIStringFromByteArray` and `TVMFFIBytesFromByteArray` to construct FFI String/Bytes directly from byte arrays, replacing the old `kTVMFFIRawStr` / `kTVMFFIByteArrayPtr` pass-by-pointer approach with proper ownership.
- Introduces nested container conversion in the Cython fast-path: new `TVMFFIPyArgSetterTuple_`, `TVMFFIPyArgSetterTupleLike_` (for lists), and `TVMFFIPyArgSetterMap_` setters that recursively call `ConstructorCall` for `ffi.Array` / `ffi.Map` constructors.
- Adds `TVMFFIPyConstructorCall` that propagates call context (device, stream, allocator, importer) from nested constructor calls back to the parent call context.
- Removes `_FUNC_CONVERT_TO_OBJECT` global callback and `_STR_CONSTRUCTOR` / `_BYTES_CONSTRUCTOR` globals; replaced by direct C API calls and cdef globals `_CONSTRUCTOR_ARRAY` / `_CONSTRUCTOR_MAP`.
## Impact
- API: New C API functions `TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`. Removed `_set_func_convert_to_object`. `ConstructorCall` signature changed to accept `PyObject*` and optional `TVMFFIPyCallContext*`.
- Flags/config: none
- Data formats/schemas: Strings/bytes now go through `TVMFFIStringFromByteArray`/`TVMFFIBytesFromByteArray` which may produce SmallStr or heap-allocated String depending on size, instead of passing raw C string pointers.
## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetter` dispatch pattern and `TVMFFIPyCallManager` from prior commits
- `ffi.Array` and `ffi.Map` constructor functions from the global registry
Design elements this commit produces:
- `TVMFFIPyConstructorCall` for nested argument conversion with context propagation
- Direct C API string/bytes construction eliminating the need for Python-side temporary objects
- `PyNativeObject` type-specific dispatchers (`TVMFFIPyArgSetterPyNativeObjectStr_`, `TVMFFIPyArgSetterPyNativeObjectBytes_`, `TVMFFIPyArgSetterPyNativeObjectGeneral_`)
## Reflection
- The nested container conversion via recursive `ConstructorCall` is key for performance: previously, list/dict/tuple arguments triggered a Python-level `_FUNC_CONVERT_TO_OBJECT` round-trip. Now conversion stays in C/Cython with call context propagation.
- Temp object cleanup switched from direct deleter call to `TVMFFIObjectDecRef`, which is safer and respects ref-counting invariants.
