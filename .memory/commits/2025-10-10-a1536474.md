# [CYTHON] Expose API to construct Function from extern c (#99)
## TL;DR
- Adds `Function.__from_extern_c__(c_symbol, keep_alive_object=None)` static method that constructs an FFI `Function` from a raw C function pointer (as int) and an optional keep-alive object
- The C function pointer must match `TVMFFISafeCallType` signature and ignore the first argument (function handle)
- Uses `TVMFFIPyObjectDeleter` for the keep-alive reference
- Adds `testing.get_add_one_c_symbol` test helper that returns the address of a C `__add_one_c_symbol` function
- Adds Python test exercising the roundtrip: get C symbol -> construct Function -> call it

## Impact
- API: New static method `Function.__from_extern_c__(c_symbol: int, keep_alive_object=None) -> Function`
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIFunctionCreate` C API
- `TVMFFIPyObjectDeleter` from #98

Design elements this commit produces:
- Pattern for constructing FFI Functions from JIT-compiled function pointers (useful for LLVM/MLIR execution engines)

## Reflection
- Designed to enable DSLs that use JIT compilation (e.g. LLVM execution engine) to expose compiled functions as FFI Functions
- The keep-alive object pattern ensures the execution engine stays alive as long as the function is in use
