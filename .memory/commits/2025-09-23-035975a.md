# feat: Improve Critical Path Perf in Cython `make_ret_object` (#47)
## TL;DR
- Adds a parallel `TYPE_INDEX_TO_CLS` cdef list alongside `TYPE_INDEX_TO_INFO`, enabling `make_ret_object` to skip the `type_info.type_cls` attribute lookup on the hot path.
- `make_ret_object` now indexes directly into `TYPE_INDEX_TO_CLS[tindex]` instead of `TYPE_INDEX_TO_INFO[tindex].type_cls`, removing one Python attribute access per FFI object return.
- Exposes a new `_set_type_cls` function for updating the class mapping after initial registration (used by `c_class` decorator).

## Impact
- API: New internal function `_set_type_cls(type_index, type_cls)` added to `core.pyi`; no public API change.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Cython `cdef list` for O(1) index-based lookup as a fast-path cache
- Object registration pattern via `_register_object_by_index`

Design elements this commit produces:
- Pattern: parallel cache list (`TYPE_INDEX_TO_CLS`) kept in sync with `TYPE_INDEX_TO_INFO` for critical-path performance

## Reflection
- The change trades a small amount of memory (one extra list) for eliminating a Python attribute access on every FFI object return, which is on the critical path for packed function calls.
- The `_set_type_cls` function exists because `c_class` registers a placeholder first and sets the real class later; the new cache list must be updated at both points.
