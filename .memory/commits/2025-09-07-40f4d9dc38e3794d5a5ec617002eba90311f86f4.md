# [FFI][REFACTOR] Cleanup tvm_ffi python API and types (#18277)
## TL;DR
- Renamed public API functions: `register_func` -> `register_global_func`, `_init_api` -> `init_ffi_api`, `ObjectGeneric` -> `ObjectConvertible`.
- Restructured internal modules: `tensor.py` -> `_tensor.py`, `convert.py` -> `_convert.py`, `dtype.py` -> `_dtype.py` (underscore prefix = private).
- Removed per-device shorthand exports (`cpu`, `cuda`, `rocm`, etc.) and `ModulePropertyMask` from `__init__.py`; added `DLDeviceType` enum, Sphinx docstrings, and API reference docs.
## Impact
- API: Breaking renames of `register_func`, `_init_api`, `ObjectGeneric`, `DataTypeCode`, `String`, `Bytes`. Device shortcuts removed from top-level namespace.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- Existing `tensor.py`, `convert.py`, `dtype.py` modules
- `registry.py` function signatures
Design elements this commit produces:
- Clean public API surface with consistent naming (`register_global_func`, `init_ffi_api`)
- `_tensor.py` with `Shape`, `Device`, `DLDeviceType`, `device()`, `from_dlpack` as the tensor public surface
- `docs/reference/python/index.rst` for Sphinx API reference
- Rich docstrings with examples on `Array`, `Map`, `Module`, `register_global_func`, `init_ffi_api`, `load_module`
## Reflection
- The underscore prefix convention for internal modules (`_tensor.py`, `_convert.py`, `_dtype.py`) makes it clear which modules are implementation details vs. public API.
- Removing per-device shortcuts (e.g., `tvm_ffi.cuda`) in favor of `tvm_ffi.device("cuda")` reduces API surface and avoids namespace pollution as new device types are added.
