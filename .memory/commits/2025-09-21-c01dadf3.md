# feat: Introduce `tvm_ffi::reflection::init<>` (#32)
## TL;DR
- Adds `tvm::ffi::reflection::init<T, Args...>`, a template helper that constructs an object of type `T` (or `T::ContainerType` for ref types) and returns an `ObjectRef`, simplifying `__ffi_init__` registration.
- Migrates `TestIntPairObj` from a lambda-based `__create__` to `refl::init<TestIntPairObj, int64_t, int64_t>` and renames it to `__ffi_init__`.
- Adds `TestIntPair` Python wrapper with `__init__` calling `__ffi_init__`, plus C++ and Python tests.
- Adds `[[maybe_unused]]` to `_type_is_nullable` in object ref macros to suppress compiler warnings.
## Impact
- API: New public C++ API `reflection::init<T, Args...>()`. `__create__` renamed to `__ffi_init__` for test objects (convention change).
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `ffi::make_object<T>` for heap allocation
- `refl::ObjectDef<T>.def_static` for method registration

Design elements this commit produces:
- `tvm::ffi::reflection::init<T, Args...>`: canonical way to register constructors via reflection
- `__ffi_init__` naming convention for reflected constructors
## Reflection
- The `init<>` helper supports both `Object` subclasses and `ObjectRef` subclasses (via `T::ContainerType` dispatch), making it flexible for different registration patterns.
- The `__ffi_init__` convention aligns with the upcoming `c_class` / dataclass integration.
