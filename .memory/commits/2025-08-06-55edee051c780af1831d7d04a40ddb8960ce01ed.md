# [FFI][REFACTOR] Phase out getattr based attribute handling (#18189)

## TL;DR
- Adds two new convenience functions `FromJSONGraphString` and `ToJSONGraphString` that accept/return `String` instead of `json::Value`.
- Registers these as global FFI functions `ffi.FromJSONGraphString` and `ffi.ToJSONGraphString`.
- Reformats the existing `GlobalDef()` chain for readability.

## Impact
- API: Two new global FFI functions (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`) exposed to all language bindings. No existing APIs changed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Global function registration via `refl::GlobalDef().def(...)` pattern
- Existing `ToJSONGraph` / `FromJSONGraph` (json::Value variants) and `json::Parse` / `json::Stringify` utilities

Design elements this commit produces:
- String-typed JSON graph round-trip API, enabling callers (e.g. Python) to serialize/deserialize without needing the internal `json::Value` type

- The commit message references "phase out getattr based attribute handling" but the diff only adds string convenience wrappers for JSON graph serialization. The actual getattr phase-out likely happened in the broader upstream PR (#18189) and only this slice landed in the FFI repo.
