# [FFI][REFACTOR] Introduce TypeAttr in reflection (#18160)

## TL;DR
- Renames `TVMFFITypeExtraInfo` to `TVMFFITypeMetadata` across the C ABI and all internal usage (pure rename, no semantic change).
- Introduces a new **TypeAttr** system: a column-oriented store in `TypeTable` that maps `(attr_name, type_index) -> Any` value, with C API (`TVMFFITypeRegisterAttr`, `TVMFFIGetTypeAttrColumn`) and C++ API (`TypeAttrDef<T>`, `TypeAttrColumn`, `EnsureTypeAttrColumn`).
- The TypeAttr column store is independent from the per-type `TVMFFITypeMetadata`; it provides open-ended, user-defined per-type attributes without modifying the core metadata struct.

## Impact
- API: **C ABI breaking** -- `TVMFFITypeExtraInfo` renamed to `TVMFFITypeMetadata`; `TVMFFITypeRegisterExtraInfo` renamed to `TVMFFITypeRegisterMetadata`; `TVMFFITypeInfo::extra_info` field renamed to `metadata`. Two new C API functions added: `TVMFFITypeRegisterAttr`, `TVMFFIGetTypeAttrColumn`. New C struct `TVMFFITypeAttrColumn`. Callers referencing `extra_info` or `TVMFFITypeExtraInfo` must update.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Reflection system architecture: `ObjectDef<T>`, `TypeTable`, `TVMFFITypeInfo` struct layout (`.memory/designs/0006-reflection-system.md`)
- `ReflectionDefBase::GetMethod` dispatch for wrapping member functions (`.memory/designs/0006-reflection-system.md`)

Design elements this commit produces:
- **`TVMFFITypeAttrColumn`** C struct: column-array of `TVMFFIAny` values indexed by `type_index`, with `data` pointer and `size`.
- **`TypeAttrDef<T>`** C++ builder (in `reflection/registry.h`): fluent API with `.def(name, method)` for function-valued attrs and `.attr(name, value)` for constant-valued attrs. Follows the same `ReflectionDefBase` pattern as `ObjectDef<T>`.
- **`TypeAttrColumn`** C++ accessor (in `reflection/accessor.h`): wraps `TVMFFIGetTypeAttrColumn` with `operator[](type_index)` returning `AnyView`.
- **`EnsureTypeAttrColumn`** helper: registers a column slot (with `type_index = kTVMFFINone`) without storing a value, ensuring the column exists for later reads.
- **Column store in `TypeTable`**: `type_attr_columns_` (vector of unique_ptr to `TypeAttrColumnData`) + `type_attr_name_to_column_index_` (Map<String, int64>). Columns auto-resize to accommodate new type indices; unset slots default to `Any(nullptr)`.
- **Duplicate guard**: registering the same `(attr_name, type_index)` pair twice throws `RuntimeError`.

## Reflection
- The rename from `TypeExtraInfo` to `TypeMetadata` is a clarity improvement; the design doc (0006) uses `TVMFFITypeExtraInfo` extensively and will need updating.
- The TypeAttr column store is the "extension point" mentioned in 0006 under "New reflection builders": `TypeAttrDef` inherits from `ReflectionDefBase` for domain-specific registration, exactly as predicted.
- The column-oriented layout (one vector per attr name, indexed by type_index) is cache-friendly for scans over all types for a given attribute, which is the expected access pattern (e.g., "find all types with `__ffi_eq__` override").
- The `EnsureTypeAttrColumn` helper with `kTVMFFINone` sentinel is a bootstrapping mechanism: it lets accessor code guarantee a column exists before any type has registered an attribute, avoiding null-pointer checks on every read.
