# [FFI] Introduce small string/bytes (#18185)

## TL;DR
- `String` and `Bytes` are rewritten from `ObjectRef` subclasses to standalone value types backed by a new `details::BytesBaseCell` wrapper around `TVMFFIAny`. Short strings (<=7 bytes) are stored inline (SSO); longer strings still heap-allocate `StringObj`/`BytesObj`.
- All `CopyToAnyView`/`MoveToAny` paths now explicitly zero `zero_padding` to maintain the invariant that non-small-string `TVMFFIAny` values have `zero_padding == 0`.
- `AnyHash`/`AnyEqual` and structural hash/equal are updated to treat `kTVMFFISmallStr`/`kTVMFFIStr` (and `kTVMFFISmallBytes`/`kTVMFFIBytes`) as equivalent when comparing or hashing.

## Impact
- API: **Breaking.** `String` and `Bytes` no longer inherit from `ObjectRef`. Methods like `get()`, `use_count()`, `defined()`, `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` are removed. Callers that relied on `ObjectRef` interface (e.g., `String` -> `ObjectRef` implicit conversion, `r.defined()`) must switch to value semantics (`data()`, `size()`, comparison operators). Default-constructed `String` is now an empty small string (type index `kTVMFFISmallStr`), not null. `TVMFFIDataTypeToString` C API signature changes from `TVMFFIObjectHandle*` to `TVMFFIAny*` output.
- Flags/config: none
- Data formats/schemas: `TVMFFIAny` union gains `zero_padding`/`small_str_len` union at offset 4 (replacing the former `small_len` field). Two new type indices `kTVMFFISmallStr=11`, `kTVMFFISmallBytes=12` are registered in the type table.

## Key Changes by File

### `include/tvm/ffi/string.h` (+422/-145)
- New `details::BytesBaseCell`: a 16-byte cell wrapping `TVMFFIAny` that manages refcounting for heap strings and provides `data()`/`size()` that dispatch on type index (small vs heap). Provides `InitSpaceForSize` for allocating inline or heap backing, `MoveToAny`/`CopyToTVMFFIAny`/`CopyFromAnyView`/`MoveFromAny` for FFI boundary transitions.
- `Bytes` rewritten: no longer `ObjectRef`. Holds `BytesBaseCell data_`. Default constructor sets `kTVMFFISmallBytes`. `InitSpaceForSize` returns `char*` for memcpy. `std::string&&` constructor delegates to `InitFromStd`. `memequal` signature generalized from `const char*` to `const void*`.
- `String` rewritten: no longer `ObjectRef`. Holds `BytesBaseCell data_`. Default constructor sets `kTVMFFISmallStr` (empty string). `String(nullptr_t) = delete` preserved. `Concat` rewritten to use `InitSpaceForSize` directly (avoids intermediate `std::string`), with GCC diagnostic suppression for false-positive `-Wstringop-overflow`/`-Wrestrict`.
- Custom `TypeTraits<String>` and `TypeTraits<Bytes>`: `field_static_type_index = kTVMFFIAny` (since the value can be either small or heap). `CheckAnyStrict` checks both small and heap type indices. `TryCastFromAnyView` handles `kTVMFFIRawStr`->`String` and `kTVMFFIByteArrayPtr`->`Bytes` fallback conversions. Replaces the old `ObjectRefWithFallbackTraitsBase`-based traits.
- Deleted comparison operators with `nullptr` (`operator==`, `!=`, `<`, `>`, `<=`, `>=` for `String` vs `nullptr_t`).
- `std::hash<String>`/`std::hash<Bytes>` changed from `StableHashBytes` to `std::hash<std::string_view>`.

### `include/tvm/ffi/any.h` (+84/-30)
- All `AnyView`/`Any` constructors and move/reset paths now explicitly set `data_.zero_padding = 0`.
- `Any::same_as` now compares `zero_padding` in addition to `type_index` and `v_int64` (needed because small strings store length in `zero_padding`/`small_str_len`).
- `InplaceConvertAnyViewToAny`: `kTVMFFIRawStr`->`String` and `kTVMFFIByteArrayPtr`->`Bytes` promotion now uses `TypeTraits<String>::MoveToAny` / `TypeTraits<Bytes>::MoveToAny` instead of direct `ObjectRef` manipulation (so the result can be a small string).
- `AnyHash::operator()`: adds branches for `kTVMFFISmallStr` and `kTVMFFISmallBytes`, hashing them with the same type-key as their heap counterparts (`kTVMFFIStr`/`kTVMFFIBytes`) so small and heap strings hash identically.
- `AnyEqual::operator()`: adds 16-byte fast path (memcmp via `int64_t` reinterpret). Adds cross-type-index equality for small-str vs heap-str and small-bytes vs heap-bytes.

### `include/tvm/ffi/c_api.h` (+34/-14)
- `TVMFFIAny` struct: `small_len` replaced by `union { uint32_t zero_padding; uint32_t small_str_len; }`.
- `kTVMFFISmallStr=11` and `kTVMFFISmallBytes=12` added to `TVMFFITypeIndex`.
- `TVMFFIDataTypeToString` signature changed: output is `TVMFFIAny*` instead of `TVMFFIObjectHandle*`.
- New inline helper `TVMFFISmallBytesGetContentByteArray`.

### `include/tvm/ffi/base_details.h` (+16/-1)
- `StableHashBytes` parameter generalized from `const char*` to `const void*`.
- New `StableHashSmallStrBytes` for fast small-string hashing (fast path on little-endian: `v_uint64 % kMod`).

### `include/tvm/ffi/optional.h` (+115/-1)
- New `Optional<T>` partial specialization for `T = String` or `T = Bytes`. Uses `BytesBaseCell` null state (`kTVMFFINone`) as the `nullopt` sentinel. `sizeof(Optional<String>) == sizeof(String)` (16 bytes, no wrapper overhead).

### `include/tvm/ffi/type_traits.h` (+15/-1)
- All `CopyToAnyView`/`MoveToAny` specializations (nullptr, bool, int, float, void*, DLDevice, DLTensor*, ObjectRef, Object*) now set `result->zero_padding = 0`.
- `#include <tvm/ffi/optional.h>` removed (dependency inversion: optional.h now includes string.h).

### `src/ffi/object.cc` (+21/-5)
- `TypeTable::ReserveBuiltinTypeIndex` now registers `kTVMFFISmallStr` and `kTVMFFISmallBytes`.
- `TypeTable::CopyString` uses explicit `MakeInplaceString` (new private helper) instead of `String` (because `String` is no longer an `ObjectRef` whose pointer is stable across moves).

### `src/ffi/extra/structural_equal.cc` (+33/-2) / `src/ffi/extra/structural_hash.cc` (+13/-0)
- Structural equal: cross-type-index comparison for small-str/heap-str and small-bytes/heap-bytes. POD comparison now includes `zero_padding`. Uses `memequal` instead of `memncmp`.
- Structural hash: small strings hashed with `kTVMFFIStr` type key (via `StableHashSmallStrBytes`) for consistency with heap strings.

### `src/ffi/dtype.cc` (+2/-2)
- `TVMFFIDataTypeToString` output type changed from `TVMFFIObjectHandle*` to `TVMFFIAny*`, using `TypeTraits<String>::MoveToAny`.
- `StringToDLDataType` constructs `TVMFFIByteArray` from `str.data()`/`str.size()` instead of `str.get()`.

### Tests
- `test_any.cc`: new `AnyEqualHash` test verifying small-str/heap-str cross-type equality and hash consistency.
- `test_optional.cc`: new tests for `Optional<String>` and `Optional<Bytes>` with `sizeof` static assertions.
- `test_string.cc`: updated type index expectations (`kTVMFFISmallStr`/`kTVMFFISmallBytes`), `ObjectRef` casts replaced with `Any`, new `StdHash` test, empty `Bytes` test, `CAPIAccessor` simplified.
- `test_rvalue_ref.cc`: two rvalue-ref-to-String test cases commented out (String is no longer ObjectRef).
- `test_variant.cc`: `same_as` test uses longer string to force heap allocation.
- `test_reflection_accessor.cc`: removed `use_count()` assertion (String has no use_count).

## Design Elements
Design elements this commit consumes:
- [ADR-0003: Inline Small String Optimization in TVMFFIAny](.memory/ADRs/0003-small-string-optimization-in-any.md) -- this commit is the full realization: String/Bytes become value types that directly embed the SSO rather than always wrapping an ObjectRef.
- [Design-0004: Container Library](.memory/designs/0004-container-library.md) -- String/Bytes section is structurally changed.

Design elements this commit produces:
- A new invariant: **String and Bytes are value types, not ObjectRef.** Their `TypeTraits::field_static_type_index` is `kTVMFFIAny` (not `kTVMFFIStr`/`kTVMFFIBytes`), because the runtime representation can be either a small on-stack value or a heap object.
- A new invariant: **`zero_padding` must be zeroed for all non-small-string `TVMFFIAny` values.** All type traits set this explicitly.
- `Optional<String>` and `Optional<Bytes>` have zero overhead (same size as `String`/`Bytes`), using `kTVMFFINone` as the null sentinel in the backing `BytesBaseCell`.

## Reflection
- ADR-0003 described the SSO layout but assumed String/Bytes would remain ObjectRef wrappers with SSO only applying at the `Any`/`AnyView` level. This commit goes further: String/Bytes themselves become `TVMFFIAny`-backed value types, eliminating the ObjectRef indirection entirely for short strings. ADR-0003 should be updated to reflect this.
- The `zero_padding` zeroing discipline is pervasive (touches every `TypeTraits` specialization). This is fragile -- a new type trait that forgets to zero `zero_padding` would break `same_as` and hash consistency. A centralized helper or compile-time check would reduce this risk.
- Two `test_rvalue_ref.cc` cases are commented out rather than deleted or adapted, suggesting RValueRef + String interaction needs follow-up.
- `std::hash<String>` changed from `StableHashBytes` to `std::hash<std::string_view>`. This means the std::hash and `AnyHash`/`StableHash` now use different hash functions. This is intentional (std::hash is for C++ containers, StableHash is for cross-platform determinism), but worth noting.
- Design-0004's description of StringObj ("Zero-copy `data()`/`size()` access") and the control flow for String creation need updating to reflect the new `BytesBaseCell`-based paths.
