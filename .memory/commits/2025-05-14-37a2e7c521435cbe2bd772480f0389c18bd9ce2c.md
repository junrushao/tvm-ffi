# Distinguish as() (strict) from cast()/try_cast() (converting) in Any/AnyView API

## TL;DR
- Splits the previous `as<T>()` into two distinct operations: `as<T>()` now performs a strict type check only (no conversion), while `cast<T>()` and the new `try_cast<T>()` perform type conversion (e.g., int to float).
- Renames the `TypeTraits<T>` protocol: `CheckAnyStorage` -> `CheckAnyStrict`, `CopyFromAnyStorageAfterCheck` -> `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` -> `MoveFromAnyAfterCheck`, `TryConvertFromAnyView` -> `TryCastFromAnyView`.
- All container types (Array, Map, Tuple, Variant) and downstream call sites updated to use the new naming consistently.

## Impact
- API: **Breaking change** to the C++ public API surface. Every call site using `AnyView::as<T>()` or `Any::as<T>()` that relied on implicit type conversion now gets `std::nullopt` instead. Callers must switch to `try_cast<T>()` or `cast<T>()` for converting behavior. The `TypeTraits<T>` protocol method names change for all custom type trait specializations (`CheckAnyStorage` -> `CheckAnyStrict`, `CopyFromAnyStorageAfterCheck` -> `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` -> `MoveFromAnyAfterCheck`, `TryConvertFromAnyView` -> `TryCastFromAnyView`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0001-type-erased-any-value-system.md](.memory/designs/0001-type-erased-any-value-system.md) -- the Any/AnyView value system and TypeTraits protocol that this commit refines

Design elements this commit produces:
- Clarified semantic contract for `as<T>()` vs `cast<T>()`/`try_cast<T>()`: `as` = "is this already the exact type?" (reinterpret), `cast`/`try_cast` = "can this be converted to the target type?" (convert). This distinction is now explicit in the API rather than conflated.
- New `Any::as<T>() &&` rvalue overload on `Any` (previously only `const&` existed), enabling strict-check-and-move semantics.
- `DLTensor*` type traits gain `CheckAnyStrict` and `CopyFromAnyViewAfterCheck` (previously missing, only had `TryConvertFromAnyView`).

## Reflection
- Design doc [0001](.memory/designs/0001-type-erased-any-value-system.md) listed TypeTraits operations using the old names (`CheckAnyStorage`, `CopyFromAnyStorageAfterCheck`, etc.). The design doc has already been updated to reflect the new naming (`CheckAnyStrict`, `CopyFromAnyViewAfterCheck`, `TryCastFromAnyView`), indicating the doc was maintained in sync with this rename.
- The rename from "Storage" to "Strict"/"View" is semantically more accurate: `CheckAnyStrict` conveys "strict type match without conversion", while the old `CheckAnyStorage` name implied it was about storage format.
- The rename from `TryConvertFromAnyView` to `TryCastFromAnyView` aligns the trait method name with the public API name `try_cast<T>()`.
- Container slow paths (Array, Map) now call `try_cast<T>()` instead of `as<T>()` for element-by-element conversion, which preserves the previous converting behavior in the contexts where conversion is actually desired.
- The `as<T>()` -> strict-only change in containers' `GetMismatchTypeInfo` (diagnostic paths) similarly switches to `try_cast<T>()`, maintaining the same diagnostic behavior.
