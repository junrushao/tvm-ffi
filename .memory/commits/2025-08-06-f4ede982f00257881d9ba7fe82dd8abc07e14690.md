# [FFI][REFACTOR] Refactor AccessPath to enable full tree repr (#18191)

## TL;DR
- Replaces `AccessPath = Array<AccessStep>` (flat alias) with a dedicated `AccessPathObj` class using a parent-pointing tree structure, enabling compact memory representation when multiple paths share a common prefix.
- Renames `AccessKind::kObjectField` to `kAttr` and adds `kAttrMissing`; changes `AccessStep::ObjectField()` factory to `AccessStep::Attr()`.
- Moves `MakeObjectFromPackedArgs` and AccessStep/AccessPath reflection registration from core (`src/ffi/object.cc`, `src/ffi/reflection/access_path.cc`) into `src/ffi/extra/reflection_extra.cc`, gated behind `TVM_FFI_USE_EXTRA_CXX_API`.
- Removes unused `Class` template parameter from `ReflectionDefBase::GetMethod` and eliminates the redundant `GlobalDef::GetMethod_` overloads.

## Impact
- API: `AccessPath` is no longer a type alias for `Array<AccessStep>`. It is now an `ObjectRef` wrapping `AccessPathObj` with a parent-pointing tree. All callers constructing paths must use `AccessPath::Root()->Attr(...)->ArrayItem(...)` chaining or `AccessPath::FromSteps(...)` instead of direct `Array` construction. `AccessStep::ObjectField()` renamed to `AccessStep::Attr()`. `AccessStep::_type_key` changed from `"tvm.ffi.reflection.AccessStep"` to `"ffi.reflection.AccessStep"`.
- Flags/config: `reflection_extra.cc` added to the `TVM_FFI_USE_EXTRA_CXX_API` CMake section; `access_path.cc` removed from core build.
- Data formats/schemas: `AccessPathObj` has fields `parent` (Optional<ObjectRef>), `step` (Optional<AccessStep>), `depth` (int32_t). `AccessKind` enum gains `kAttrMissing = 3`, shifts `kArrayItemMissing` to 4, `kMapItemMissing` to 5.

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0006-reflection-system.md]: `ObjectDef<T>`, `GlobalDef`, `ReflectionDefBase::GetMethod`, `ForEachFieldInfo`, `MakeObjectFromPackedArgs`
- [.memory/designs/0007-structural-equal-hash-system.md]: `AccessPath`/`AccessStep` for mismatch diagnostics, `StructuralEqual::GetFirstMismatch`
- [.memory/ADRs/0009-extra-api-isolation.md]: `TVM_FFI_USE_EXTRA_CXX_API` gating pattern for non-core C++ APIs

Design elements this commit produces:
- **Parent-pointing `AccessPathObj`**: tree node with `parent`, `step`, `depth` fields. Methods: `Extend`, `Attr`, `AttrMissing`, `ArrayItem`, `ArrayItemMissing`, `MapItem`, `MapItemMissing`, `ToSteps`, `PathEqual`, `IsPrefixOf`, `GetParent`. Space-efficient for prefix-shared paths.
- **`AccessPath::FromSteps(iter, iter)` and `AccessPath::FromSteps(Array<AccessStep>)`**: factory methods to reconstruct tree from flat step sequences.
- **`AccessPath::Root()`**: creates a root node with depth 0 and no parent/step.
- **Consolidated `reflection_extra.cc`**: single extra/ translation unit containing AccessStep reflection, AccessPath reflection (with exposed methods `_root`, `_extend`, `_attr`, `_array_item`, `_map_item`, `_attr_missing`, `_array_item_missing`, `_map_item_missing`, `_is_prefix_of`, `_to_steps`, `_path_equal`), and `MakeObjectFromPackedArgs`.
- **Simplified `GetMethod`**: single non-class-templated overload in `ReflectionDefBase` replaces both the templated version and the `GlobalDef::GetMethod_` overload set.

## Reflection
- The parent-pointing tree design directly addresses the open question in [.memory/designs/0007-structural-equal-hash-system.md] about whether AccessPath should use more efficient allocation. While not arena-allocated, the parent-pointing structure avoids duplicating shared prefixes, which is the dominant cost pattern during tree comparisons where many paths branch from a common ancestor.
- Moving `MakeObjectFromPackedArgs` to `extra/` further extends the isolation pattern from [.memory/ADRs/0009-extra-api-isolation.md]. This is notable because `MakeObjectFromPackedArgs` was previously in core `object.cc` -- its relocation means minimal builds without `TVM_FFI_USE_EXTRA_CXX_API` lose reflection-based object construction.
- The `GetMethod` template simplification (removing the `Class` parameter) is a bugfix -- the prior `GlobalDef::GetMethod_` overloads for member function pointers dispatched to the class-templated `GetMethod<Class>`, but the non-member overload did not. The new unified `GetMethod` uses `Function::FromTyped` which already handles member function pointers via its own overload set, making the class template parameter redundant.
- The `AccessStep::_type_key` prefix change from `"tvm.ffi.reflection."` to `"ffi.reflection."` aligns with the project's namespace convention for FFI-level types (not TVM-specific).
