# Guard dsymutil step behind TVM_FFI_USE_LIBBACKTRACE flag
## TL;DR
- The `add_dsymutil` CMake function previously ran `dsymutil` on all Apple builds; now it only runs when `TVM_FFI_USE_LIBBACKTRACE` is enabled.
- This avoids an unnecessary (and potentially error-causing) post-build step when libbacktrace is not in use.
## Impact
- API: none
- Flags/config: `add_dsymutil` now requires `TVM_FFI_USE_LIBBACKTRACE=ON` in addition to `APPLE` to invoke `dsymutil`. Builds that do not enable libbacktrace will skip the dSYM generation step.
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- CMake option `TVM_FFI_USE_LIBBACKTRACE` (controls whether libbacktrace is linked for symbolized backtraces)
- `add_dsymutil` helper in `cmake/Utils/Library.cmake`

Design elements this commit produces:
- (none new; tightens an existing guard condition)
## Reflection
- The original commit message references a Metal runtime fix (PR #18034 from upstream TVM); the actual diff in this repo is a cmake-only change. The message was likely carried over during a cherry-pick or rebase from upstream and does not match the code change.
- The change is trivial (1 line, condition widened from `if(APPLE)` to `if(APPLE AND TVM_FFI_USE_LIBBACKTRACE)`), low risk.
