# Fix system library symbol lookup to handle names with or without prefix
## TL;DR
- Fixes `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` to try both the prefixed and unprefixed name when looking up symbols, since callers may pass names that already contain the symbol prefix.
- Both methods now attempt lookup with prefix first, and fall back to the bare name if the prefixed lookup returns `nullptr`.
## Impact
- API: none (behavior fix, no signature change)
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- [Module system](/.memory/designs/0009-module-system.md): `SystemLibrary` implements the `Library` interface for statically linked modules. `GetSymbol` and `GetSymbolWithSymbolPrefix` are the two lookup methods.
- [ADR: Module-scoped C API naming](/.memory/ADRs/0013-module-scoped-c-api-naming.md): The `symbol_prefix_` and `symbol::tvm_ffi_symbol_prefix` constants that define the naming convention for module symbols.

Design elements this commit produces:
- **Prefix-tolerant symbol lookup**: Establishes the invariant that symbol lookup methods in `SystemLibrary` are idempotent with respect to the prefix: calling `GetSymbol("prefix_foo")` works whether or not the implementation adds `prefix_` again. This prevents double-prefixing bugs.
