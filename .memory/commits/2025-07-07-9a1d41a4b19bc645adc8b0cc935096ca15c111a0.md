# Revert "[FFI] Replace `Arg2Str` with a more powerful `for_each`" (#18121)

## TL;DR
- Reverts commit ad328f5 which replaced `Arg2Str` with an overloaded `for_each` dispatcher.
- Restores the original `Arg2Str` template struct in `function_details.h` for building function signature strings.
- Simplifies `for_each_dispatcher::run` back to accepting only `F(size_t, Arg)`, removing the `std::conjunction_v` multi-overload dispatch and the `always_false` helper.

## Impact
- API: Internal C++ detail only (`details::for_each`, `details::Arg2Str`). No public API change.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `for_each` fold-expression utility in `base_details.h`
- `Type2Str` trait used to render C++ types as strings for error messages

Design elements this commit produces:
- Restores `Arg2Str` as the canonical pattern for building typed argument signature strings (index-expanding via `TExpander` trick)
- `for_each` is narrowed to a single calling convention: `F(size_t index, Arg)` only

## Reflection
- The reverted commit (ad328f5) tried to generalize `for_each` to accept three overload forms (with `std::integral_constant`, plain `size_t`, or no index). This revert suggests the generalization introduced issues (likely compile-time or correctness) and the simpler `Arg2Str` + single-form `for_each` was preferred.
- The `TExpander` pack-expansion trick (`(void)TExpander{0, (Apply<I>(os), 0)...}`) is a C++14 idiom; the reverted code used C++17 fold expressions. The revert favors the older idiom for `Arg2Str` while keeping fold expressions in `for_each` itself.
