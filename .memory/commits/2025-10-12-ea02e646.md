# feat: stub generation (#101)
## TL;DR
- Adds `tvm-ffi-stubgen`, a CLI tool that scans `.py`/`.pyi` files for special begin/end markers and fills them with generated `TYPE_CHECKING`-guarded stubs (global functions, object fields, methods) from the TVM FFI registry.
- Replaces the manually maintained `_ffi_api.pyi` with inline stub blocks in `_ffi_api.py`.
- Supports per-block `ty_map` directives, skip-file directive, and deterministic output.
## Impact
- API: New CLI entry point `tvm-ffi-stubgen`. Removes `python/tvm_ffi/_ffi_api.pyi` in favor of inline stubs in `.py` files.
- Flags/config: New `[project.scripts]` entry in pyproject.toml.
- Data formats/schemas: Introduces marker comment protocol (`tvm-ffi-stubgen(begin/end/ty_map/skip-file)`) as a convention.
## Design Elements
Design elements this commit consumes:
- `tvm_ffi.registry.get_global_func_metadata` and `list_global_func_names` for runtime introspection
- `tvm_ffi.core.TypeSchema` and `_lookup_or_register_type_info_from_type_key` for object metadata
Design elements this commit produces:
- `python/tvm_ffi/stub/stubgen.py` -- the core stub generation engine (528 lines)
- Marker-based stub block protocol for any downstream package
- Inline stubs in `_ffi_api.py` and `testing.py` as reference examples
## Reflection
- This is the foundation for static typing across the entire TVM FFI Python surface. Any downstream extension can adopt the same markers.
- The `__ffi_init__` -> `__c_ffi_init__` renaming in stubs avoids collision with Python `__init__`.
