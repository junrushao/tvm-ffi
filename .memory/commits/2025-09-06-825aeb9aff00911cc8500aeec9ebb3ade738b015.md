# [FFI] Update the interface of `ffi.load_inline` to match torch (#18274)
## TL;DR
- Renamed `cpp_source`/`cuda_source` to `cpp_sources`/`cuda_sources` (accepting `str | Sequence[str]`).
- Replaced separate `cpp_functions`/`cuda_functions` mappings with a unified `functions` parameter (`Sequence[str] | Mapping[str, str]`) -- exported name now equals function name in source.
- Added `build_directory` parameter for explicit build path control; expanded tests with docstring, multi-source, and build-dir cases.
## Impact
- API: Breaking change to `tvm_ffi.cpp.load_inline` keyword arguments (`cpp_source` -> `cpp_sources`, `cuda_source` -> `cuda_sources`, `cpp_functions`/`cuda_functions` -> `functions`).
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro (from commit 40e8a51 which added `__tvm_ffi_` prefix)
- Module loading infrastructure
Design elements this commit produces:
- Simplified `load_inline` API where export name == source function name (no renaming dict needed)
- `build_directory` parameter for reproducible builds
## Reflection
- The API now mirrors `torch.utils.cpp_extension.load_inline` more closely, lowering friction for PyTorch users transitioning to TVM FFI.
- CUDA function declarations must now appear in `cpp_sources` as forward declarations since `functions` only decorates the cpp source with `TVM_FFI_DLL_EXPORT_TYPED_FUNC`.
