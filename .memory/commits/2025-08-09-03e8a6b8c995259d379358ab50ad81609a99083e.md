# [FFI][REFACTOR] Update Map ABI to enable flexible smallMap switch (#18200)
## TL;DR
- Introduces a MSB (bit 63) tag in `MapObj::slots_` to distinguish SmallMap from DenseMap, replacing the prior heuristic of comparing `slots_ <= SmallMapObj::kMaxSize`.
- Adds `IsSmallMap()`, `NumSlots()`, `SetSlotsAndSmallLayoutTag()`, and `SetSlotsAndDenseLayoutTag()` helper methods to encapsulate the tag protocol.
- Rewrites `TVM_FFI_DISPATCH_MAP` macros and `InsertMaybeReHash` to use the new tag-based dispatch instead of slot-count comparison.
## Impact
- API: ABI-level change -- the `slots_` field now carries a tag bit. Any code that reads `slots_` directly to determine map type or capacity must use the new accessors (`NumSlots()`, `IsSmallMap()`). All such call sites are updated within this commit (single file, `map.h`).
- Flags/config: none
- Data formats/schemas: In-memory ABI of `MapObj` changes; serialized maps are unaffected (Map serialization goes through iterators, not raw fields).
## Design Elements
Design elements this commit consumes:
- Map dual-layout architecture: `SmallMapObj` (linear scan, small N) vs `DenseMapObj` (robin-hood hash table) sharing the `MapObj` base with `slots_` / `size_` / `data_` fields.
- `TVM_FFI_DISPATCH_MAP` / `TVM_FFI_DISPATCH_MAP_CONST` macros for polymorphic dispatch without virtual functions.

Design elements this commit produces:
- Tag-in-field pattern: MSB of `slots_` (`kSmallTagMask = 1ULL << 63`) indicates SmallMap. This decouples the SmallMap/DenseMap boundary from a fixed constant, enabling future changes to `kMaxSize` without ABI breakage.
- Accessor protocol: `IsSmallMap()` on base, `NumSlots()` on each subclass (SmallMap masks off tag; DenseMap returns raw value), and private `Set*Tag` setters that enforce invariants (DenseMap asserts MSB clear).
## Reflection
- The previous dispatch compared `slots_ <= SmallMapObj::kMaxSize`. This conflated capacity with type identity, making it impossible to change the small-map threshold without breaking the dispatch logic. The tag bit cleanly separates these two concerns.
- `DenseMapObj::SetSlotsAndDenseLayoutTag` includes `TVM_FFI_ICHECK` that MSB is clear, providing a runtime guard against accidentally tagging a DenseMap as small.
- `InsertMaybeReHash` is restructured to nest the `NumSlots() == kMaxSize` check inside the `IsSmallMap()` branch, which is logically cleaner and avoids the previous three-way comparison on raw `slots_`.
