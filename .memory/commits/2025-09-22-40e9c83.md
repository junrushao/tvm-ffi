# feat: Enable mypy type checking (#35)
## TL;DR
- Adds `mirrors-mypy` (v1.17.0) to `.pre-commit-config.yaml` with four separate hooks covering `python/`, `tests/`, and example directories.
- Adds `[tool.mypy]` config in `pyproject.toml` (`allow_redefinition=true`, `ignore_missing_imports=true`).
- Fixes type annotations across ~30 files: adds `from __future__ import annotations`, replaces `Optional[X]` with `X | None`, adds `.pyi` stub for `_ffi_api`, fixes function signatures in `registry.py`, `container.py`, `load_inline.py`, `error.py`, `libinfo.py`, and others.
## Impact
- API: No runtime API changes. `_ffi_api.pyi` stub added for mypy to understand dynamic FFI bindings.
- Flags/config: New `[tool.mypy]` section in `pyproject.toml`. New pre-commit hooks.
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- Existing `_ffi_api` dynamic module pattern (attribute access triggers FFI global function lookup).
Design elements this commit produces:
- `_ffi_api.pyi` type stub listing all known FFI API functions with `(*args: Any) -> Any` signatures.
- `dataclass_transform` import order fix (try `typing_extensions` first, then `typing`).
- Consistent use of `from __future__ import annotations` for PEP 604 union syntax.
## Reflection
- The `_ffi_api.pyi` stub is manually maintained; it must be updated when new FFI functions are added.
- `load_inline.py` received significant refactoring to satisfy mypy: sequence parameters are now properly typed as `Sequence[str]` with internal `list[str]` conversions.
