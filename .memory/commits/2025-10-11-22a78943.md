# [DLPack] C Functions for DLPack Speed Exchange and Stream Handling (#96)
## TL;DR
- Replaces separate function pointers (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) with a unified `DLPackExchangeAPI` struct exposed via `__c_dlpack_exchange_api__` on `torch.Tensor`.
- Adds non-owning `DLTensor` conversion (`dltensor_from_py_object_no_sync`) and a `current_work_stream` callback for explicit stream synchronization.
- Updates `3rdparty/dlpack` submodule to incorporate the latest DLPack proposal (dlpack#174/175).
## Impact
- API: Breaking -- replaces three class attributes (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) with a single `__c_dlpack_exchange_api__` pointer. All Cython callers updated. Renames C functions to `*NoSync` variants.
- Flags/config: none
- Data formats/schemas: Adopts `DLPackExchangeAPI` struct layout from DLPack v1.2 proposal.
## Design Elements
Design elements this commit consumes:
- DLPack proposal #175 (`DLPackExchangeAPI` struct convention)
- DLPack PR #174 (C header changes)
Design elements this commit produces:
- `DLPackExchangeAPI` struct-based fast exchange protocol available on any Python class via `__c_dlpack_exchange_api__` class attribute
- Non-owning DLTensor path for zero-copy, zero-refcount tensor access
## Reflection
- The shift from individual function pointers to a single struct pointer is a cleaner ABI: one attribute lookup instead of three, and the struct is extensible.
- Stream handling is now explicit via `current_work_stream` instead of being baked into the from-object path.
