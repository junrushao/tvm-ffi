# [FFI] Construct NDArray.strides by default (#18272)
## TL;DR
- `NDArrayObjFromNDAlloc` and `NDArrayObjFromDLPack` now always populate the `strides` field with contiguous (row-major) strides instead of leaving it as `nullptr`.
- Adds `details::MakeStridesFromShape(ndim, shape)` utility in `shape.h` to compute contiguous strides from a shape array.
- Adds `stride_data_` field to `NDArrayObj` to own the backing `Shape` object for the strides pointer.
## Impact
- API: `NDArray::strides` is now always non-null (previously null for contiguous arrays). Code that checked `strides == nullptr` as a proxy for contiguity will need updating.
- Flags/config: none
- Data formats/schemas: DLPack export (`ToDLPack`) now emits non-null strides.
## Design Elements
Design elements this commit consumes:
- `Shape` container and `MakeEmptyShape` allocation pattern
- `NDArrayObj` protected fields (`shape_data_`, `Optional<Shape>`)
Design elements this commit produces:
- `details::MakeStridesFromShape()` -- utility to compute row-major strides from shape
- `stride_data_` field on `NDArrayObj` for lifetime management of computed strides
## Reflection
- Many DLPack consumers (e.g., NumPy, PyTorch) expect non-null strides. Defaulting to populated strides reduces special-case handling downstream and aligns with DLPack best practices.
- The `NDArrayObjFromDLPack` path previously cleared strides to null for contiguous tensors; now it only computes strides when the incoming DLPack tensor had null strides, preserving any non-trivial strides from the source.
