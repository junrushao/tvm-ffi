# [FFI][REFACTOR] Hide StringObj/BytesObj into details (#18184)
## TL;DR
- Moves `BytesObjBase`, `BytesObj`, `StringObj` class definitions into `namespace details` in `string.h`, hiding them from public API surface.
- Updates all references in `any.h`, `structural_equal.cc`, and `structural_hash.cc` to use the `details::` prefix.
- No behavioral or ABI changes; purely a namespace-scoping refactor preparing for future SmallStr support.
## Impact
- API: `StringObj` and `BytesObj` are no longer directly in `tvm::ffi`; downstream code referencing these Obj types by unqualified name must add `details::`. The `String` and `Bytes` ref wrappers remain unchanged.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- Object pattern: `FooObj` (data) + `Foo` (ref wrapper) where the ref wrapper is the primary public API
- `details` namespace convention for implementation internals

Design elements this commit produces:
- Establishes precedent that `*Obj` types for String/Bytes are implementation details, not public API; consumers should use `String`/`Bytes` ref wrappers exclusively
- Prepares the abstraction boundary needed for future SmallStr optimization (mentioned in commit message)
## Reflection
- The 4 files changed with symmetric add/remove counts (26 added, 28 removed) confirm this is a pure move-to-namespace refactor with no logic changes.
- `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` macro usage in `Bytes` and `String` now references `details::BytesObj` / `details::StringObj`, showing these macros accept fully-qualified Obj types.
