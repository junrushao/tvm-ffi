# [FFI][REFACTOR] Update registry to have complete meta-data (#18062)

## TL;DR
- Enriches `TVMFFIFieldInfo` with `type_schema`, `size`, `alignment` (replaces bare `byte_offset` with `offset`+`size`+`alignment`), and enriches `TVMFFIMethodInfo` with `type_schema`; adds new `TVMFFITypeExtraInfo` struct with `creator`, `doc`, and `total_size` for future reflection-based object construction.
- Replaces `std::unordered_map` with `Map<String, ...>` in both `GlobalFunctionTable` (function.cc) and `TypeTable` (object.cc), making the registry self-hosting on TVM FFI containers.
- Introduces `TVM_FFI_STATIC_INIT_BLOCK` macro and templatized `ObjectDef<Class>` to replace the old `ReflectionDef`/`TVM_FFI_REFLECTION_DEF` macro pattern, yielding simpler registration syntax.

## Impact
- API:
  - **C ABI breaking**: `TVMFFIFieldInfo.byte_offset` renamed to `offset`; new fields `size`, `alignment`, `type_schema` added. `TVMFFIMethodInfo` gains `type_schema`. Field flag enum constants renamed from `TVMFFIFieldFlagBitMask*` to `kTVMFFIFieldFlagBitMask*`. New struct `TVMFFITypeExtraInfo` and C function `TVMFFITypeRegisterExtraInfo`. `TVMFFITypeGetMethod` removed and replaced by `TVMFFITypeRegisterExtraInfo`.
  - **C ABI breaking**: `TVMFFIErrorSetRaisedByCStr` renamed to `TVMFFIErrorSetRaisedFromCStr`.
  - **C ABI addition**: `TVMFFIFunctionSetGlobalFromMethodInfo` added for registering global functions with full metadata.
  - **C ABI addition**: `TVMFFIObjectCreator` function pointer typedef added.
  - **C++ API breaking**: `ReflectionDef` class replaced by `ObjectDef<Class>` template. `TVM_FFI_REFLECTION_DEF` macro removed. `namespace refl = reflection` alias removed.
  - **C++ API addition**: `TVM_FFI_STATIC_INIT_BLOCK(Body)` macro in `base_details.h`.
  - **Build**: `TVM_FFI_BUILD_REGISTRY` cmake option removed (registry is now always built).
  - Callers: All C++ reflection registrations must migrate from `TVM_FFI_REFLECTION_DEF(T)` to `TVM_FFI_STATIC_INIT_BLOCK({ reflection::ObjectDef<T>()... })`. All users of `TVMFFIFieldInfo.byte_offset` must use `.offset`. All users of `TVMFFIErrorSetRaisedByCStr` must use `TVMFFIErrorSetRaisedFromCStr`. Foreign bindings using `TVMFFITypeGetMethod` must migrate to using `TVMFFITypeInfo.extra_info`.
- Flags/config: `TVM_FFI_BUILD_REGISTRY` cmake option removed; registry support is unconditional.
- Data formats/schemas: `TVMFFITypeInfo` struct layout changed (`type_key_hash` moved after `type_acenstors`, `fields`/`methods` made `const*`, new `extra_info` pointer appended). `TVMFFIFieldInfo` and `TVMFFIMethodInfo` struct layouts changed with new fields.

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md): extends `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, `TVMFFITypeInfo` structs and adds new C functions
- [.memory/designs/0003-packed-function-and-global-registry.md](.memory/designs/0003-packed-function-and-global-registry.md): replaces `std::unordered_map<String, Function*>` with `Map<String, Any>` in `GlobalFunctionTable`, adds `Entry` class carrying `TVMFFIMethodInfo` metadata alongside the function

Design elements this commit produces:
- `TVMFFITypeExtraInfo` struct: new reflection primitive enabling future object construction from reflection data (creator callback + total_size)
- `TVMFFIFunctionSetGlobalFromMethodInfo`: new C API allowing global functions to be registered with full metadata (name, doc, type_schema, flags)
- `ObjectDef<Class>` template: new C++ reflection API that infers `type_index` and `type_key` from the class, removing boilerplate
- `TVM_FFI_STATIC_INIT_BLOCK`: general-purpose static initialization macro replacing ad-hoc static variable patterns
- `GlobalFunctionTable::Entry`: internal class (extends `Object` + `TVMFFIMethodInfo`) storing function + metadata in the global table

## Reflection
- This commit materially changes the C ABI structs documented in design 0005. The design doc's struct definitions (`TVMFFIFieldInfo`, `TVMFFIMethodInfo`, `TVMFFITypeInfo`) and C function list need updating to reflect the new fields, renamed constants, added functions, and removed function (`TVMFFITypeGetMethod`).
- Design 0003 describes `GlobalFunctionTable` as `Map<String, Entry>` -- this commit makes that accurate by replacing the previous `std::unordered_map<String, Function*>` implementation.
- The `TVMFFITypeExtraInfo.creator` callback and `total_size` field lay groundwork for reflection-based object construction (e.g., Python `c_class` creating C++ objects without explicit `__init__` packed functions).
- The shift from `std::unordered_map` to `Map<String, ...>` in both registries dogfoods TVM FFI's own containers at the infrastructure level, reducing external stdlib dependencies.
- Minor cleanup: `optional.value()` calls replaced with `*optional` (operator*), fixing potential issues and aligning with modern C++ style; `DemangleName` in traceback.cc fixed to avoid double-free by separating null-check from status-check.
