# [FFI][REFACTOR] Stablize container ABI and implementation (#18076)

## TL;DR
- Adds explicit `void* data_` and `void (*data_deleter_)(void*)` fields to `ArrayObj` and `MapObj`, decoupling element storage from the inplace-array base class and enabling separate allocation with safe cross-library deletion.
- Rewrites `DenseMapObj` hash table sizing from `slots_ = n - 1` (bitmask) to `slots_ = n` (modulus), fixing probing arithmetic to use `%` instead of `&` for slot wrapping.
- Renames internal dispatch macros from `TVM_DISPATCH_MAP` to `TVM_FFI_DISPATCH_MAP` for namespace consistency.

## Impact
- API: `ArrayObj` gains new fields (`data_`, `data_deleter_`) before `size_` and `capacity_`, changing the struct layout. `MapObj` similarly gains `data_`, reorders `size_`/`slots_`, and adds `data_deleter_`. This is a **breaking ABI change** for any code that accesses these fields by offset. The `Array::emplace_back` method is newly added. `ArrayObj::at()` now returns `const Any&` instead of `const Any` (avoids copy). `SmallMapObj::KVRawStorageType` introduced to separate raw storage from the C++ `KVType` (avoids implicit constructors in inplace storage).
- Flags/config: none
- Data formats/schemas: The in-memory layout of `ArrayObj`, `MapObj`, `SmallMapObj`, and `DenseMapObj` changes. `DenseMapObj` slot count semantics change from `n-1` to `n`, affecting hash table capacity and probe calculations.

## Design Elements

Design elements this commit consumes:
- [.memory/designs/0004-container-library.md](.memory/designs/0004-container-library.md): Array and Map container architecture, `InplaceArrayBase`, COW semantics
- [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md): Struct layout stability contract (this commit intentionally modifies layouts to reach a more stable target)

Design elements this commit produces:
- Establishes the `data_ + data_deleter_` pattern as the canonical way containers reference their element storage, matching the `TVMFFISeqCell` contract described in design 0004 (`data`, `size`, `capacity`, `data_deleter`)
- `DenseMapObj::BlockDeleter` static function: ensures safe cross-shared-library deallocation by binding the `delete[]` call to the same translation unit that did the `new[]`

## Reflection
- This commit resolves a latent ABI fragility: previously `ArrayObj` and `SmallMapObj` relied solely on `InplaceArrayBase::AddressOf(0)` to locate element data, with no stored data pointer. Foreign language bindings (Python/Rust) that need to read container contents through the C ABI required a data pointer at a known offset. Adding `data_` makes the layout self-describing.
- The `data_deleter_` field addresses a real cross-boundary bug class: if a container's backing buffer is allocated in one shared library and freed in another (with different allocators), memory corruption can result. The deleter captures the correct deallocator at allocation time.
- The `DenseMapObj` slot arithmetic change (bitmask to modulus) is a correctness fix: the old `& slots_` assumed `slots_ + 1` was a power of two, but the `CalcNumBlocks` and rehash logic did not consistently maintain this invariant. Using `% slots_` with `slots_` as the actual count is simpler and correct regardless of power-of-two alignment.
- The macro rename `TVM_DISPATCH_MAP` -> `TVM_FFI_DISPATCH_MAP` aligns with the project convention that all public macros use the `TVM_FFI_` prefix (per design 0005).
- `Tuple` construction is simplified to delegate to `ArrayObj::Empty()` instead of duplicating inplace-array setup, reducing code duplication and ensuring the new `data_` field is always initialized.
