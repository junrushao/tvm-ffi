# [FFI] Improve string equal/hash handling (#18176)

## TL;DR
- Adds a dedicated `Bytes::memequal` fast path for equality checks, replacing the slower three-way `memncmp` comparison with `std::memcmp` when only equality is needed.
- Optimizes `StableHashBytes` to use direct 8-byte aligned loads when pointer alignment allows, falling back to byte-by-byte copy for unaligned data.
- Inlines `Bytes::memncmp` and `String::compare(const char*)` into the header, specializing the `const char*` overload to avoid calling `strlen`.

## Impact
- API: New static method `Bytes::memequal` added. `Bytes::memncmp` moved from out-of-line (bottom of `string.h`) to inline within the class body. No signatures removed; fully backward-compatible.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- String/Bytes container design and `memncmp` utility: [.memory/designs/0004-container-library.md](.memory/designs/0004-container-library.md)
- `StableHashBytes` used for string hashing in the type-erased value system: [.memory/designs/0001-type-erased-any-value-system.md](.memory/designs/0001-type-erased-any-value-system.md)
- `AnyEqual` struct dispatching on type index for string equality: `include/tvm/ffi/any.h`

Design elements this commit produces:
- `Bytes::memequal`: a purpose-built equality check that short-circuits on length mismatch and delegates to `std::memcmp`, avoiding per-byte less-than/greater-than comparisons that `memncmp` performs.
- `StableHashBytes` aligned-load optimization: on little-endian platforms, when the data pointer is 8-byte aligned, the hash loop uses `*reinterpret_cast<const uint64_t*>(it)` directly instead of byte-by-byte copy into the union. The `result = ...` accumulation is moved inside each branch to keep the logic per-branch rather than shared after the if-constexpr.
- `String::compare(const char*)` now walks the `other` C string without calling `strlen` first, checking for `'\0'` terminator inline. This avoids a full pass over `other` before comparison begins.

## Reflection
- The `operator==` overloads for `String` vs `String`, `String` vs `std::string`, and `std::string` vs `String` are updated to call `Bytes::memequal` instead of `compare() == 0`. The `operator==` for `String` vs `const char*` still uses `compare() == 0` because `memequal` requires a known length.
- `AnyEqual::operator()` in `any.h` similarly switches from `Bytes::memncmp(...) == 0` to `Bytes::memequal(...)` for the `kTVMFFIStr`/`kTVMFFIBytes` branch.
- The `StableHashBytes` change is purely a performance optimization; the hash values produced are identical (verified by the new `BytesHash` test that checks aligned vs unaligned data produce the same hash).
- Two new C++ tests added: `String::Compare` exercises the reworked `compare(const char*)` path with shorter/longer/equal/mismatching strings; `String::BytesHash` verifies hash stability across aligned and unaligned pointers.
