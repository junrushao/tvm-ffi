# Support enum types in TypeTraits and allow base-class member pointers in reflection
## TL;DR
- Add `TypeTraits` specialization for C++ enum types backed by integral types, enabling enums to be stored/retrieved via `Any`/`AnyView` as int64 values.
- Generalize `ObjectDef::def_ro`, `def_rw`, and `RegisterField` to accept member pointers to base classes (not just the exact `Class`), with a `static_assert` ensuring the pointed-to class is actually a base of `Class`.
- Add `TEST(Any, Enum)` covering round-trip conversion of a scoped enum through `AnyView`.
## Impact
- API: `ObjectDef::def_ro`/`def_rw` now accept `T BaseClass::*` member pointers where `BaseClass` is any ancestor of `Class`. This is a backwards-compatible generalization -- existing code using `T Class::*` still compiles. Callers that inherit fields from a base `Obj` class and register them in a derived `ObjectDef` no longer need casts.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `TypeTraits` SFINAE dispatch pattern (`std::enable_if_t` on type category) from `type_traits.h`
- `ObjectDef` reflection builder pattern from `reflection.h`

Design elements this commit produces:
- `TypeTraits<IntEnum>` specialization gated on `std::is_enum_v<IntEnum> && std::is_integral_v<std::underlying_type_t<IntEnum>>` -- enums are stored as `kTVMFFIInt` and cast back on retrieval
- Base-class member pointer support in reflection field registration, enforced by `static_assert(std::is_base_of_v<BaseClass, Class>)`
## Reflection
- The enum `TypeTraits` uses the same `kTVMFFIInt` type index as plain integers; there is no distinct enum type index. `TryCastFromAnyView` also accepts `kTVMFFIBool`, mirroring the integer traits pattern.
- The base-class member pointer change is motivated by the upstream TVM VisitAttrs-to-reflection migration (PR #18096), where derived node classes need to register fields declared in parent `Obj` classes.
