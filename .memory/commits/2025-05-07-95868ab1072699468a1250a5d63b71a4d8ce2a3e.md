# Add AutoDLPack benchmark script for measuring Python FFI call overhead

## TL;DR
- Adds `scripts/benchmark_dlpack.py` (345 lines), a standalone benchmark script that measures the per-call overhead of Python FFI invocations through various DLPack paths.
- Compares baselines (numpy.add, torch.add, cupy.add) against TVM FFI NOP calls with manual `from_dlpack`, legacy `torch.utils.dlpack.to_dlpack`, and the new AutoDLPack auto-conversion path.
- Also benchmarks the raw `__dlpack__()` and `__dlpack__(max_version=(1,1))` export overhead for torch, numpy, and TVM tensors.

## Impact
- API: None. This is a new script file in `scripts/`; no library code is added or changed.
- Flags/config: None.
- Data formats/schemas: None.

This commit has zero impact on the library itself. It is a developer-facing benchmarking tool that accompanies the AutoDLPack feature (introduced in the same PR #17927). The script uses `tvm_ffi.get_global_func("testing.nop")` and `tvm_ffi.from_dlpack` to measure FFI overhead and requires torch and numpy at runtime.

## Design Elements

Design elements this commit consumes:
- **Packed function calling convention** ([.memory/designs/0003-packed-function-and-global-registry.md](.memory/designs/0003-packed-function-and-global-registry.md)): The benchmark calls `tvm_ffi.get_global_func("testing.nop")` which resolves through the global function registry and invokes via the packed calling convention `(const AnyView* args, int32_t num_args, Any* rv)`. The NOP function is a zero-work target that isolates FFI marshalling overhead.
- **C ABI boundary layer** ([.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md)): The `TVMFFITensorFromDLPack` C ABI function underpins `tvm_ffi.from_dlpack` used throughout the benchmark.
- **AutoDLPack feature**: The `bench_tvm_ffi_nop_autodlpack` functions test the auto-conversion path where torch.Tensor / numpy.ndarray objects are passed directly to packed functions without explicit `from_dlpack` calls. The FFI runtime detects `__dlpack__` protocol support and converts automatically.

Design elements this commit produces:
- None. This is a measurement tool, not a design artifact.

## Reflection

- The script contains a duplicate function definition: `bench_ffi_nop_from_dlpack` appears twice (lines ~126 and ~175 in the diff). Both have identical signatures and bodies. This is likely a copy-paste artifact that does not affect correctness (Python simply uses the second definition), but it is worth noting for cleanup.
- The commit message body references "continuguous" (sic) and alignment requirements imposed by the underlying DSL compiler, but the benchmark script itself does not exercise or validate these constraints. This gap between the stated motivation and the benchmark coverage is minor but worth noting.
- The script requires `torch` and `numpy` as hard dependencies (imported unconditionally at the top), with `cupy` as an optional soft dependency. It is placed in `scripts/` rather than `tests/` since it is not intended for CI but for manual performance investigation.
