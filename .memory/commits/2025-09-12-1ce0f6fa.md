# [FFI] Update `load_inline` interface (#18307)
## TL;DR
- Allows `load_inline` to export functions defined in `cuda_sources` when no `cpp_sources` are provided, removing the prior requirement of a C++ forward declaration for CUDA-only modules.
- Updates docstring to clarify the new behavior.
## Impact
- API: `load_inline` now auto-routes the `functions` parameter to `cuda_sources` when `cpp_sources` is empty. Existing callers that provided both `cpp_sources` (with forward declarations) and `cuda_sources` still work but can now drop the redundant C++ forward declarations.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `_decorate_with_tvm_ffi` helper that wraps source code with TVM FFI export boilerplate
Design elements this commit produces:
- none (behavioral change only)
## Reflection
- Small quality-of-life improvement: users writing CUDA-only inline modules no longer need a stub `.cpp` source just to declare the exported function signature.
