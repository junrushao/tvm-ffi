# [FFI][ABI] Refactor the naming of DLPack speed converter (#18308)
## TL;DR
- Renames the C-level DLPack fast-path types and Python dunder attributes for clarity: `DLPackPyObjectExporter` -> `DLPackFromPyObject`, `DLPackPyObjectImporter` -> `DLPackToPyObject`, `__c_dlpack_exporter__` -> `__c_dlpack_from_pyobject__`, `__c_dlpack_importer__` -> `__c_dlpack_to_pyobject__`.
- Corresponding renames in the Torch C++ helpers: `TorchDLPackPyObjectExporter` -> `TorchDLPackFromPyObject`, `TorchDLPackPyObjectImporter` -> `TorchDLPackToPyObject`.
- Bumps package version from `0.1.0a11` to `0.1.0a12`.
## Impact
- API: All uses of the old `__c_dlpack_exporter__` / `__c_dlpack_importer__` dunder names must be updated to `__c_dlpack_from_pyobject__` / `__c_dlpack_to_pyobject__`. Internal C typedef names also changed.
- Flags/config: Env var `TVM_FFI_SKIP_C_DLPACK_EXPORTER` renamed to `TVM_FFI_SKIP_c_dlpack_from_pyobject` (note: inconsistent casing, likely a bug).
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `__c_dlpack_exporter__` / `__c_dlpack_importer__` protocol from commit f81ab9c2
Design elements this commit produces:
- Stabilized naming: `DLPackFromPyObject` / `DLPackToPyObject` / `__c_dlpack_from_pyobject__` / `__c_dlpack_to_pyobject__`
## Reflection
- Pure naming refactor with no behavioral changes. The new names (From/To PyObject) read more naturally as directional converters than the old Exporter/Importer names.
- The env var `TVM_FFI_SKIP_c_dlpack_from_pyobject` has mixed case, which looks unintentional and may be corrected in a later commit.
