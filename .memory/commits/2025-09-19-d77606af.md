# feat: Enable torch/numpy/ml_dtypes dtype as ffi input (#25)
## TL;DR
- Adds Cython-level dispatch (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) so `torch.dtype`, `numpy.dtype`, and `ml_dtypes` dtype objects are automatically converted to `DLDataType` when passed as FFI arguments.
- Adds `_convert_torch_dtype_to_ffi_dtype` / `_convert_numpy_dtype_to_ffi_dtype` for use in the Python `convert()` path.
- Adds `kDLBool` case to `DLDataTypeCodeAsCStr` in C++ header.
- Comprehensive test coverage in `test_dtype.py` for torch, numpy, and ml_dtypes conversions.
## Impact
- API: Users can now pass `torch.float32`, `np.dtype(np.float32)`, or `ml_dtypes.bfloat16` directly into any FFI function expecting a dtype.
- Flags/config: `TVM_FFI_BUILD_DOCS` environment variable gates optional imports to avoid import errors during doc builds.
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `DLDataType` struct and `DLDataTypeCode` enum from DLPack
- Cython `TVMFFIPyArgSetterFactory_` dispatch mechanism

Design elements this commit produces:
- `TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE` lookup tables in Cython
- Cython arg setters for torch/numpy dtype types
## Reflection
- The mapping tables are static and must be updated manually when new dtypes are added upstream. Coverage of float8/float4/float6 variants from ml_dtypes is thorough.
