# [BUILD] Enable free threaded python build (#98)
## TL;DR
- Detects free-threaded Python at CMake configure time and disables `USE_SABI` (Stable ABI) for it, since free-threaded Python is not compatible with limited API
- Introduces `TVMFFIPyObjectDeleter` in C++ helpers that properly acquires/releases GIL when needed (no-op for free-threaded builds via `Py_GIL_DISABLED`)
- Replaces Cython `tvm_ffi_pyobject_deleter` (which used `with gil`) with the C++ `TVMFFIPyObjectDeleter` for both function and opaque object creation
- Simplifies `tvm_ffi_callback` return code handling (direct return instead of branching)
- Fixes `OpaqueObject` type registration: uses `GetOrAllocTypeIndex` with `type_depth=1` and `parent_type_index=kTVMFFIObject` instead of `ReserveBuiltinTypeIndex`, so it's properly recognized as an Object subtype

## Impact
- API: `TVMFFIPyObjectDeleter` replaces `tvm_ffi_pyobject_deleter`; `TVMFFIPyWithGILIfNotFreeThreaded` helper class introduced. OpaqueObject now properly part of Object type hierarchy.
- Flags/config: New CI matrix entry for free-threaded Python; CMake auto-detects `Py_GIL_DISABLED`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none
Design elements this commit produces:
- `TVMFFIPyWithGILIfNotFreeThreaded` pattern for GIL-safe C++ code that works with both standard and free-threaded Python
- `TVMFFIPyObjectDeleter` as the canonical Python object reference decrement function

## Reflection
- The OpaqueObject fix is orthogonal to free-threading but was caught by the ref count test -- `ReserveBuiltinTypeIndex` did not set up the type hierarchy correctly
- Free-threaded Python requires careful attention to GIL acquisition in C++ code that calls Python APIs
