# Introduce FFI reflection support for Python

## TL;DR
- Refactors `ObjectDef` to support a new `ReflectionDefBase` base class, extracting field getter/setter, method wrapping, and trait-application helpers into shared code for reuse across reflection types.
- Adds `TVMFFITypeExtraInfo` registration (object creator, total size, doc) via the `ObjectDef` constructor, enabling Python-side object creation from type metadata.
- Introduces `ffi.MakeObjectFromPackedArgs` global function that creates objects by type key, iterating ancestor fields in parent-to-child order and applying defaults for unset fields.
- Adds `String::compare(TVMFFIByteArray)` overload and replaces deprecated `std::aligned_storage` with a conforming `alignas` struct in `SimpleObjAllocator`.

## Impact
- API: New C API surface -- `TVMFFITypeRegisterExtraInfo` is now called during `ObjectDef` construction. New global packed function `ffi.MakeObjectFromPackedArgs` allows cross-language object construction by type key + keyword-style field arguments. `def_rw` now has a `static_assert` enforcing `_type_mutable` on the class.
- Flags/config: Types must declare `static constexpr bool _type_mutable = true` to use `def_rw` (writable fields). Test types updated accordingly (e.g., `struct A` in test_reflection.cc gains `_type_mutable`; `TFloatObj.value` changed from `def_rw` to `def_ro`; `TPrimExprObj.dtype` changed from `def_ro` to `def_rw`).
- Data formats/schemas: `TVMFFITypeExtraInfo` is a new struct stored per type containing `total_size`, `creator` function pointer, and `doc`. This extends the `TVMFFITypeInfo` metadata available at runtime.

## Design Elements
Design elements this commit consumes:
- Object system pattern (`FooObj` + `Foo` ref wrapper, `TypeTable` singleton, type index allocation) from [0002-object-system-and-reference-counting](./../designs/0002-object-system-and-reference-counting.md)
- Packed function calling convention (`const AnyView* args, int32_t num_args, Any* rv`) from [0003-packed-function-and-global-registry](./../designs/0003-packed-function-and-global-registry.md)
- Type-erased `Any`/`AnyView` value system from [0001-type-erased-any-value-system](./../designs/0001-type-erased-any-value-system.md)

Design elements this commit produces:
- **Reflection-driven object construction**: A new pattern where `ObjectDef<T>` registers a default creator (`make_object<T>`) and extra type info at construction time, enabling runtime object instantiation by type key without compile-time knowledge of the concrete type.
- **`ReflectionDefBase` helper base class**: Centralizes `FieldGetter`, `FieldSetter`, `ObjectCreatorDefault`, `GetMethod`, and trait-application logic so future reflection builders (beyond `ObjectDef`) can reuse them.
- **Ancestor-ordered field initialization**: `MakeObjectFromPackedArgs` walks `type_acenstors` from index 1 (skipping root `Object`) to the leaf type, setting fields in parent-to-child order. Unset fields with defaults are auto-filled; missing required fields raise `TypeError`.
- **Mutability enforcement via `_type_mutable`**: `def_rw` now requires `_type_mutable = true` at compile time, preventing accidental writable fields on immutable object types.

## Reflection
- This commit is the C++ foundation for the Python reflection system described in the commit message. The Python side (property/method attachment to class objects) is implied but not included in the diff -- it likely lives in the Python package or a companion commit.
- The `std::aligned_storage` replacement in `memory.h` is a forward-looking fix: `std::aligned_storage` is deprecated in C++23. The new `alignas(T) struct StorageType` pattern is the standard replacement.
- The `MakeObjectFromPackedArgs` function uses a linear scan to match keyword arguments to fields. This is adequate for typical object sizes (few fields) but could become a bottleneck for types with many fields and many constructor arguments.
- Test changes flip `def_rw`/`def_ro` on `TFloatObj` and `TPrimExprObj` to match the new `_type_mutable` constraint, showing that immutable types (no `_type_mutable`) can only have `def_ro` fields.
