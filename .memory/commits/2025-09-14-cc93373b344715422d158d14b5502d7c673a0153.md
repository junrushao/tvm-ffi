# Commit: cc93373b — refactor: Prefer `bytearray_to_str|bytes` to raw Python API

- **Date**: 2025-09-14
- **Author**: Junru Shao
- **Scope**: `python/tvm_ffi/cython/base.pxi`, `dtype.pxi`, `function.pxi`, `object.pxi`, `string.pxi`

## Summary
Introduces two centralized Cython helper functions (`bytearray_to_str` and
`bytearray_to_bytes`) and replaces all scattered inline uses of
`py_str(PyBytes_FromStringAndSize(...))` and bare `PyBytes_FromStringAndSize(...)` with
calls to these helpers. This eliminates code duplication and provides a single
conversion path from `TVMFFIByteArray*` to Python `str` or `bytes`.

## Key Changes
- **New helper** `bytearray_to_bytes(const TVMFFIByteArray* x)` in `base.pxi` returning
  `bytes` (the existing `bytearray_to_str` was already present, returning `str`).
- **dtype.pxi**: `DataType.__str__()` now uses `bytearray_to_str(&bytes)` instead of
  `py_str(PyBytes_FromStringAndSize(bytes.data, bytes.size))`.
- **function.pxi**: `make_ret_small_str`, `make_ret_small_bytes`,
  `_add_class_attrs_by_reflection` (field name/doc, method name/doc) all use the new
  helpers.
- **object.pxi**: `_type_index_to_key` uses `bytearray_to_str`.
- **string.pxi**: `_string_obj_get_py_str` and `_bytes_obj_get_py_bytes` use the helpers.

## Architectural Impact
- **Medium**: Consolidates a common pattern across the entire Cython binding layer. Every
  path that converts C byte arrays to Python strings now goes through a single function,
  making future encoding changes (e.g., error handling policy) a one-line fix.

## Invariants
- `bytearray_to_str` always decodes as UTF-8.
- `bytearray_to_bytes` returns raw bytes without decoding.
