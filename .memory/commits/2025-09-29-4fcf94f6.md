# [Utils] Add `build_inline` utility (#73)
## TL;DR
- Refactored `load_inline` into `build_inline` (returns path to compiled shared library) and `load_inline` (calls `build_inline` then `load_module`).
- `build_inline` is now exported from `tvm_ffi.cpp` and documented in Sphinx reference.
- Added `test_build_inline.py` with a test that compiles and loads a C++ module separately.
- Added `autodoc_typehints = 'description'` to Sphinx config.
## Impact
- API: new public function `tvm_ffi.cpp.build_inline()` returning `str` (path to .so/.dll).
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `load_inline` compilation pipeline (ninja, cmake detection, caching)

Design elements this commit produces:
- `build_inline` as the lower-level build-only API
- `load_inline` as a thin wrapper over `build_inline` + `load_module`
## Reflection
- Clean separation of build and load concerns. Users who want to manage module loading separately (e.g., caching, lazy loading) can use `build_inline`.
