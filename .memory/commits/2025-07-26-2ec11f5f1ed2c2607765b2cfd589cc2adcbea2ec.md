# [FFI][REFACTOR] Enable custom s_hash/equal (#18165)

## TL;DR
- Introduces `kTVMFFISEqHashKindCustomTreeNode = 6` enum value in the C ABI, allowing object types to provide custom `__s_equal__` and `__s_hash__` functions registered via `TypeAttrDef` instead of relying on automatic field-by-field comparison.
- Refactors `StructEqualHandler` and `StructuralHashHandler` to dispatch through lazily-initialized `ffi::Function` callbacks when the type declares `kTVMFFISEqHashKindCustomTreeNode`, while also fixing FreeVar/DAG post-processing to apply uniformly regardless of dispatch path.
- Moves structural equal/hash source files and tests behind a new `TVM_FFI_USE_EXTRA_CXX_API` CMake option (default ON), enabling minimal builds that exclude the reflection-heavy structural comparison infrastructure.

## Impact
- API: New C ABI enum value `kTVMFFISEqHashKindCustomTreeNode = 6` in `TVMFFISEqHashKind`. New TypeAttr columns `__s_equal__` and `__s_hash__` registered via `refl::TypeAttrDef<T>`. Existing code using other `SEqHashKind` values is unaffected.
- Flags/config: New CMake option `TVM_FFI_USE_EXTRA_CXX_API` (default ON). When OFF, `structural_equal.cc`, `structural_hash.cc`, and `access_path.cc` are excluded from the shared library, and tests in `tests/cpp/extra/` are skipped.
- Data formats/schemas: None.

## Key Changes

### 1. New SEqHashKind enum value (`c_api.h`)
`kTVMFFISEqHashKindCustomTreeNode = 6` with documented callback signatures:
- `__s_equal__(self, other, cmp)` where `cmp` is `TypedFunction<bool(AnyView, AnyView, bool def_region, string field_name)>`
- `__s_hash__(self, type_key_hash, hash)` where `hash` is `TypedFunction<uint64_t(AnyView, bool def_region)>`
The `def_region` boolean controls whether the callback temporarily enables `map_free_vars_` for that sub-comparison (used for binding-site parameters).

### 2. Custom dispatch in structural_equal.cc
When `structural_eq_hash_kind == kTVMFFISEqHashKindCustomTreeNode`, the handler looks up `__s_equal__` from a static `TypeAttrColumn` and calls the user's function through a lazily-initialized `s_equal_callback_` that wraps `CompareAny` with `def_region` support and mismatch path tracking.

FreeVar handling was refactored: previously FreeVar short-circuited before field traversal; now all kinds (including custom) do field/custom comparison first, then FreeVar/DAG mapping is applied as a post-step on success.

### 3. Custom dispatch in structural_hash.cc
Analogous to equal: looks up `__s_hash__` from `TypeAttrColumn`, calls user function through lazily-initialized `s_hash_callback_`. FreeVar counter and DAG counter logic moved to a shared post-step after the kind-specific hash computation.

### 4. Bug fix in object.cc TypeAttr column lookup
Fixed `EnsureTypeAttrColumn` / `TVMFFIRegisterTypeAttr`: when a column already existed, `column_index` was left uninitialized (the `else` branch was missing). Now correctly sets `column_index = (*it).second`.

### 5. CMake: optional extra C++ API
Reflection structural comparison files (`access_path.cc`, `structural_equal.cc`, `structural_hash.cc`) are gated behind `TVM_FFI_USE_EXTRA_CXX_API`. Test files moved to `tests/cpp/extra/` and conditionally included.

### 6. Test object additions (`testing_object.h`)
- `TCustomFuncObj` / `TCustomFunc`: new test object with `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode` that registers `SEqual`/`SHash` methods via `TypeAttrDef`. Deliberately skips `comment` field in custom hash/equal (same semantic as `TFunc` which uses `SEqHashIgnore` flag on `comment`).
- `TVarObj::RegisterReflection` now marks `name` field with `AttachFieldFlag::SEqHashIgnore()`, so Var equality is purely by identity (matching TVM's `FreeVar` semantics where the name is annotation-only).

## Design Elements
Design elements this commit consumes:
- Reflection system's `TypeAttrDef` and `TypeAttrColumn` for per-type attribute storage (design [0006-reflection-system](.memory/designs/0006-reflection-system.md))
- `ForEachFieldInfo` / `ForEachFieldInfoWithEarlyStop` for field-by-field traversal in the non-custom path
- `TVMFFISEqHashKind` enum taxonomy (UniqueInstance, DAGNode, FreeVar, etc.)

Design elements this commit produces:
- `kTVMFFISEqHashKindCustomTreeNode` pattern: a type declares `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode` and registers `__s_equal__`/`__s_hash__` via `TypeAttrDef<T>().def(...)`. The handler provides `cmp`/`hash` callbacks that recurse into the structural comparison infrastructure with `def_region` control.
- `def_region` protocol: when `def_region=true`, the comparison/hash callback temporarily sets `map_free_vars_=true`, allowing binding-site parameters (like function params) to be structurally compared by content rather than identity.

## Reflection
- The custom tree node pattern complements the existing reflection-driven field traversal. It is needed for types where structural comparison requires non-trivial logic (e.g., skipping fields conditionally, reordering comparisons, or applying domain-specific normalization) that cannot be expressed via field flags alone.
- The `def_region` mechanism is a direct encoding of TVM IR's "define region" concept (e.g., function parameters define variables that are then referenced in the body). This was previously handled implicitly by field ordering in the reflection traversal; custom tree nodes make it explicit.
- The FreeVar/DAG post-processing refactor is a correctness improvement: previously FreeVar objects short-circuited before custom field comparison, meaning custom tree nodes with FreeVar kind would not work. Now the pipeline is: (1) compute field/custom equality, (2) apply FreeVar/DAG mapping if successful.
- The `object.cc` fix for `column_index` initialization is a latent bug: `EnsureTypeAttrColumn` (and possibly `TVMFFIRegisterTypeAttr`) would fail to find an existing column and instead create a duplicate, corrupting the column registry.
