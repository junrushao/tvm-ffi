# [FFI] AutoDLPack compatible with torch stream context (#18217)
## TL;DR
- Adds stream-aware benchmark path to `tvm_ffi_nop_autodlpack_from_torch` (runs within a non-default `torch.cuda.Stream`)
- Introduces `load_torch_get_current_cuda_stream` using `torch.utils.cpp_extension.load_inline` with a C++ snippet that calls `at::cuda::getCurrentCUDAStream` for fast stream queries
- Adds `bench_torch_get_current_stream` to compare the cpp-extension approach vs native Python `torch.cuda.current_stream` on both default and non-default streams
## Impact
- API: none -- only the benchmark script is changed (68 lines added, 2 modified)
- Flags/config: new optional `stream=True` parameter on `tvm_ffi_nop_autodlpack_from_torch`
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- AutoDLPack path for converting `torch.Tensor` to TVM via `__dlpack__`
- `torch.utils.cpp_extension.load_inline` JIT compilation for efficient CUDA stream queries
- `c10::cuda::CUDAStream` / `at::cuda::getCurrentCUDAStream` C++ API

Design elements this commit produces:
- Benchmark evidence that stream context adds overhead to AutoDLPack calls
- Pattern for using `cpp_extension.load_inline` to create a fast stream query function (first call JIT-compiles, subsequent calls use cached module)
## Reflection
- This commit touches only the benchmark script; no runtime or API code is modified. The title says "compatible" but the actual change is measuring overhead, not fixing compatibility -- the real FFI stream-context changes likely live in a companion commit in the main TVM repo.
- The cpp-extension approach uses `reinterpret_cast<int64_t>(cudaStream_t)` with a fast-path for the default stream (id==0 returns 0), avoiding the Python-level overhead of `torch.cuda.current_stream().cuda_stream`.
