# [ABI] Stablize doc and metadata for functions (#79)
## TL;DR
- Renamed `type_schema` field to `metadata` in `TVMFFIFieldInfo` and `TVMFFIMethodInfo` C ABI structs, clarifying that it stores structured JSON metadata (not just type schema).
- Added `GetFunctionDoc` virtual method to `ModuleObj` for retrieving unstructured docstrings separately from structured metadata.
- Added `ffi.ModuleGetFunctionDoc` packed function registration.
- Updated `GlobalFunctionTable::Entry` to use `metadata_data` instead of `type_schema_data`.
## Impact
- API: `TVMFFIFieldInfo.type_schema` and `TVMFFIMethodInfo.type_schema` renamed to `metadata` (C ABI change). `ModuleObj` gains `GetFunctionDoc` virtual method (C++ ABI change for ModuleObj subclasses).
- Flags/config: none
- Data formats/schemas: field/method info `type_schema` renamed to `metadata` in C structs.
## Design Elements
Design elements this commit consumes:
- `TVMFFIFieldInfo` / `TVMFFIMethodInfo` reflection ABI
- `ModuleObj` virtual interface

Design elements this commit produces:
- Separation of `doc` (unstructured docstring) vs `metadata` (structured JSON) in function/field/method info
- `ModuleObj::GetFunctionDoc` API
## Reflection
- The PR notes that `ModuleObj` C++ ABI change only affects the `extra` layer, and Python users access functions via the packed registry, so it remains ABI compatible for Python-side consumers.
