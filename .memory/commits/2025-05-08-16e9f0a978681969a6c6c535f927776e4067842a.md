# Expose core ffi container types and utilities into the tvm namespace via using-declarations
## TL;DR
- Adds `using ffi::X` declarations inside `namespace tvm` for commonly used types (`Array`, `Map`, `String`, `Bytes`, `Tuple`, `Variant`, `Optional`) and utilities (`Downcast`, `GetRef`, `make_object`).
- Fixes a doc comment in `Map::Get` (`NullOpt` -> `std::nullopt`).
- Adds a blank line before the closing `}  // namespace ffi` in `function.h` (whitespace-only).

## Impact
- API: Callers can now write `tvm::Array`, `tvm::String`, `tvm::make_object`, etc. instead of `tvm::ffi::Array`. The `tvm::ffi::` qualified names remain valid. This is a purely additive, non-breaking change.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0004-container-library.md](.memory/designs/0004-container-library.md) — the container types being re-exported are defined here

Design elements this commit produces:
- Establishes a namespace aliasing convention: types in `tvm::ffi` that are unambiguous and widely used get a `using` declaration in `tvm`. The rationale ("convenience and no ambiguity") is stated inline in each header.

## Reflection
- The commit message references the original TVM `runtime/` header paths (e.g., `runtime/container/array.h => ffi/container/array.h`), indicating this is part of a larger migration from the `tvm::runtime` namespace to `tvm::ffi`. The using-declarations soften the migration by letting downstream code use `tvm::Array` without the `ffi` qualifier.
- Nine files changed with only additions (35 lines added, 1 line changed). All changes are in public headers under `include/tvm/ffi/`.
- The "no ambiguity" rationale in each comment is important: these using-declarations would be unsafe if there were other `Array`, `Map`, etc. types already in `namespace tvm`.
