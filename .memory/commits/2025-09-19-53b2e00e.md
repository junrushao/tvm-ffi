# feat: Introduce Python-side TypeInfo Metadata (#30)
## TL;DR
- Adds `TypeField`, `TypeMethod`, and `TypeInfo` dataclasses in a new `type_info.pxi` Cython include, capturing reflected field/method metadata as first-class Python objects.
- Replaces the monolithic `_add_class_attrs_by_reflection` Cython function with a two-phase approach: `_register_object_by_index` now returns a `TypeInfo`, and a pure-Python `_add_class_attrs` in `registry.py` applies fields/methods to the class.
- Replaces `OBJECT_TYPE` list with `TYPE_INDEX_TO_INFO` / `TYPE_KEY_TO_INFO` lookup tables keyed by index and type key.
- Adds `_lookup_type_info_from_type_key` for on-demand TypeInfo creation without a registered Python class.
## Impact
- API: `_register_object_by_index` now returns `TypeInfo`. `_add_class_attrs_by_reflection` removed, replaced by `_lookup_type_info_from_type_key`. Downstream code using these internal APIs must update.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- C-level `TVMFFITypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo` structs
- `FieldGetter`/`FieldSetter` Cython extension types

Design elements this commit produces:
- `TypeField`, `TypeMethod`, `TypeInfo` Python dataclasses exposing reflection metadata
- `TYPE_INDEX_TO_INFO` / `TYPE_KEY_TO_INFO` global registries
- `_lookup_type_info_from_type_key` for lazy TypeInfo resolution
## Reflection
- This is a key stepping stone toward the `c_class` / dataclass support later in the commit chain; it decouples metadata extraction from class decoration.
