# Replace GCC/MSVC `__attribute__` with C++ standard attributes

## TL;DR
- Replaces all compiler-specific `__attribute__((always_inline))`, `__attribute__((noinline))`, `__attribute__((unused))`, `__forceinline`, and `__declspec(noinline)` with C++ standard attributes: `[[gnu::always_inline]]`, `[[msvc::forceinline]]`, `[[gnu::noinline]]`, `[[msvc::noinline]]`, and `[[maybe_unused]]`.
- Reorders `TVM_FFI_INLINE` / `TVM_FFI_ATTRIBUTE_UNUSED` to appear before `static` / `inline` on all static member functions and variables, matching the C++ standard requirement that attributes precede the declaration specifiers they modify.
- Pure mechanical refactor across 16 header files with no behavioral change.

## Impact
- API: none -- macro names (`TVM_FFI_INLINE`, `TVM_FFI_NO_INLINE`, `TVM_FFI_ATTRIBUTE_UNUSED`) are unchanged; only their definitions changed.
- Flags/config: none
- Data formats/schemas: none

## Reflection
- The key change in `base_details.h` is replacing platform-specific compiler intrinsics with vendor-specific C++ standard attributes (`[[gnu::...]]`, `[[msvc::...]]`). This is a step toward standard C++17 compliance while still relying on vendor extensions for `always_inline`/`forceinline`/`noinline`, since C++ has no standard attribute for these.
- `[[maybe_unused]]` is a fully standard C++17 attribute, so the `TVM_FFI_ATTRIBUTE_UNUSED` macro now works on all compilers (previously it was a no-op on MSVC).
- The reordering of `TVM_FFI_INLINE static` (was `static TVM_FFI_INLINE`) is required because C++ standard attributes must appear before the declaration-specifier-seq. With the old GCC `__attribute__` form, placement after `static` was accepted as a compiler extension; with `[[gnu::always_inline]]`, placing it after `static` would be ill-formed or trigger warnings.
- The same reordering applies to `TVM_FFI_ATTRIBUTE_UNUSED static inline` in the `TVM_FFI_STATIC_INIT_BLOCK_VAR_DEF` macro.
- This is a low-risk, high-breadth refactor (88 lines changed in `type_traits.h` alone, all mechanical swaps of `static TVM_FFI_INLINE` to `TVM_FFI_INLINE static`). No logic changes anywhere.
