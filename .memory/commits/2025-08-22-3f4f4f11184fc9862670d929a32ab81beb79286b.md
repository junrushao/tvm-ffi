# [FFI] Fix JSON parser/writer for the fast-math flag (#18221)
## TL;DR
- Replace `reinterpret_cast` type-punning between `double` and `uint64_t` with union-based type punning to avoid `-Werror=strict-aliasing` under `-ffast-math`.
- Five call sites changed: three in `json_parser.cc` (PosInf, NegInf, NaN construction) and two in `json_writer.cc` (IsNaN, IsInf bit inspection).
## Impact
- API: none -- internal implementation detail only.
- Flags/config: builds with `-ffast-math` / `__FAST_MATH__` now compile without strict-aliasing errors on GCC.
- Data formats/schemas: none.
## Design Elements
Design elements this commit consumes:
- IEEE 754 bit patterns for NaN (`0x7FF8...`), +Inf (`0x7FF0...`), -Inf (`0xFFF0...`) used to bypass compiler fast-math optimizations that would eliminate `std::isnan`/`std::isinf`.

Design elements this commit produces: none.
## Reflection
- The union-based approach is well-defined in C (C99 6.5.2.3) and accepted by major C++ compilers (GCC, Clang, MSVC) as a practical extension, even though C++ technically only guarantees `memcpy`/`std::bit_cast` (C++20). This is a pragmatic choice that avoids a C++20 dependency.
- Pattern is consistent: every site uses `union { typeA from; typeB to; } u; u.from = ...; return u.to;` with a comment explaining the direction.
