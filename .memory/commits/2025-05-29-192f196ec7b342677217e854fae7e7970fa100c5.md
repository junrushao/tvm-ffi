# Cleanup PackedFunc redirections and introduce TVM_FFI_DLL_EXPORT_TYPED_FUNC macro

## TL;DR
- Adds `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro to `function.h`, enabling typed C++ functions to be exported as C ABI `SafeCallType` symbols from shared libraries.
- Introduces `TVM_FFI_DLL_EXPORT` macro in `c_api.h` (always marks a symbol as DLL export, unlike `TVM_FFI_DLL` which switches between import/export based on `TVM_FFI_EXPORTS`). Defined for all three platform paths: Emscripten, MSVC, and GCC/Clang.
- Promotes `Any` and `AnyView` into the `tvm` namespace via `using` declarations in `any.h` for ergonomic use outside `tvm::ffi`.

## Impact
- API: New public macro `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function)` for module/DSO authors to export typed functions through the C ABI. New `TVM_FFI_DLL_EXPORT` visibility macro. `tvm::Any` and `tvm::AnyView` are now valid (previously only `tvm::ffi::Any`). No existing API is broken.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0003-packed-function-and-global-registry.md](.memory/designs/0003-packed-function-and-global-registry.md): The new `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro uses `FunctionInfo`, `unpack_call`, `TVM_FFI_SAFE_CALL_BEGIN/END` from the packed function system to wrap typed callables into `SafeCallType` extern "C" symbols.
- [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md): The new `TVM_FFI_DLL_EXPORT` macro extends the existing visibility machinery (`TVM_FFI_DLL`) in c_api.h.

Design elements this commit produces:
- Establishes the `TVM_FFI_DLL_EXPORT` / `TVM_FFI_DLL_EXPORT_TYPED_FUNC` pattern for the module system. Downstream DSOs can now export typed functions as C ABI entry points without manually writing `extern "C"` wrappers, which is a prerequisite for the `load_module` mechanism described in design 0003 (extension point: "Module system discovers functions via `__tvm_ffi_<name>` symbol prefix").
- The `tvm::Any` / `tvm::AnyView` namespace promotion sets a convention for surfacing core types at the `tvm` level.

## Reflection
- The commit message mentions `TVM_DLL_EXPORT_TYPED_FUNC => TVM_FFI_DLL_EXPORT_TYPED_FUNC` renaming. This is a namespace cleanup from the upstream TVM project (`TVM_DLL_*` -> `TVM_FFI_DLL_*`) to keep the FFI self-contained. The old name is noted as removable once downstream bindings update.
- The distinction between `TVM_FFI_DLL` (import or export depending on `TVM_FFI_EXPORTS`) and `TVM_FFI_DLL_EXPORT` (always export) is important for module authors who are building DSOs that link against the FFI library but need to export their own symbols. Design 0005 previously only documented `TVM_FFI_DLL`; the evidence matrix there should be updated to include `TVM_FFI_DLL_EXPORT`.
- The `using tvm::ffi::Any` / `using tvm::ffi::AnyView` in `any.h` is a convenience change. It sits outside `namespace ffi` but inside `namespace tvm`, making these core types accessible as `tvm::Any`. This is a stylistic choice that reduces verbosity without polluting the global namespace.
