# [FFI][REFACTOR] Cleanup API locations (#18218)

## TL;DR
- Moves `TVMFFIEnvCheckSignals`, `TVMFFIEnvRegisterCAPI`, and `EnvCAPIRegistry` class from `src/ffi/function.cc` (core) to `src/ffi/extra/env_c_api.cc` (extra).
- Reorders C API declarations in `c_api.h`: moves core user-facing APIs (object, function, error, DLPack, dtype) earlier in the file (right after struct/enum definitions), while removing the env-specific APIs (`TVMFFIEnvCheckSignals`, `TVMFFIEnvRegisterCAPI`) from `c_api.h` entirely -- they now live in `extra/c_env_api.h`.
- Renames three module-scoped C API symbols: `TVMFFIEnvLookupFromImports` -> `TVMFFIEnvModLookupFromImports`, `TVMFFIEnvRegisterContextSymbol` -> `TVMFFIEnvModRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol` -> `TVMFFIEnvModRegisterSystemLibSymbol`.
- Changes `TVMFFIEnvRegisterCAPI` parameter from `const TVMFFIByteArray*` to `const char*`.
- Moves `src/ffi/testing.cc` to `src/ffi/extra/testing.cc`, gated under `TVM_FFI_USE_EXTRA_CXX_API`.

## Impact
- API: **Breaking** for C ABI consumers that call `TVMFFIEnvCheckSignals`, `TVMFFIEnvRegisterCAPI` (now in `extra/c_env_api.h` instead of `c_api.h`; `TVMFFIEnvRegisterCAPI` takes `const char*` instead of `const TVMFFIByteArray*`), or any of the three renamed module symbols (`TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`). Foreign language bindings (Python/Cython, Rust) that call these symbols need updating.
- Flags/config: `testing.cc` now requires `TVM_FFI_USE_EXTRA_CXX_API=ON` to compile (it was previously always built).
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- [ADR-0009: Extra API isolation](.memory/ADRs/0009-extra-api-isolation.md) -- follows the established pattern of moving non-core APIs into `extra/` with `TVM_FFI_USE_EXTRA_CXX_API` gating.
- [Design-0005: Stable C ABI boundary layer](.memory/designs/0005-c-abi-boundary-layer.md) -- refines the layering of `c_api.h` by removing env-specific APIs from the core header.

Design elements this commit produces:
- Naming convention for module-scoped env APIs: `TVMFFIEnvMod*` prefix distinguishes module-context symbols from environment-level symbols (`TVMFFIEnv*`).
- `TVMFFIEnvRegisterCAPI` simplified parameter: `const char*` instead of `const TVMFFIByteArray*`, reducing ceremony for callers that already have a C string.

## Reflection
- This commit is a direct continuation of ADR-0009. The `EnvCAPIRegistry` (Python signal checking, GIL management) is inherently environment-specific and belongs in `extra/`.
- The `TVMFFIEnvMod*` rename creates a clearer taxonomy: `TVMFFIEnv*` for host-environment interaction (signals, C API registration), `TVMFFIEnvMod*` for module-scoped operations (import lookup, context/system-lib symbol registration). This distinction was previously implicit.
- Moving `testing.cc` to `extra/` means minimal builds without `TVM_FFI_USE_EXTRA_CXX_API` lose the test utility registrations, which is correct since those utilities are not core functionality.
- The reordering of declarations in `c_api.h` (core APIs earlier, reflection/registration APIs later) improves readability but does not change the ABI -- all symbols remain exported with the same signatures (except the three renames and the one parameter type change).
