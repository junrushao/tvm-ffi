# fix: `self` overlooked in schema of member functions (#91)
## TL;DR
- Fixes `FunctionInfo` for pointer-to-member functions to include `Class*`/`const Class*` as the first argument in the type schema, matching the actual FFI calling convention where `self` is passed as the first arg
- Changes `FunctionInfo<R (Class::*)(Args...)>` from `FuncFunctorImpl<R, Args...>` to `FuncFunctorImpl<R, Class*, Args...>`
- Relaxes `TypeSchema` validation: `list` allows 0 or 1 args, `dict` allows 0 or 2 args (to handle type-erased containers)
- Updates all expected test outputs to include the `self` argument in method schemas

## Impact
- API: Schema output for member functions now includes the `self` type as the first argument. Any downstream tooling consuming method type schemas will see an additional argument.
- Flags/config: none
- Data formats/schemas: Method schema JSON now includes self type (e.g. `"testing.SchemaAllTypes"` as first arg)

## Design Elements
Design elements this commit consumes:
- `TypeSchema<T>` and `FunctionInfo` from #36

Design elements this commit produces: none

## Reflection
- The bug was that C++ member function pointers have an implicit `this` parameter, but the schema generation was stripping it. This matters because the FFI calling convention passes `self` explicitly as the first packed argument.
