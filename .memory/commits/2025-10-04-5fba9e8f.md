# [COMPILE] Fixed error compile when using compiler gcc 8.x (#85)
## TL;DR
- Introduces `is_integeral_enum_v<T>` helper trait that first checks `is_enum_v<T>` before evaluating `underlying_type_t<T>`, avoiding undefined behavior on non-enum types with GCC 8.x
- Replaces the previous `enable_if` condition `is_enum_v<IntEnum> && is_integral_v<underlying_type_t<IntEnum>>` with the two-phase trait

## Impact
- API: none (internal trait change)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none
Design elements this commit produces:
- `is_integeral_enum_v<T>` two-phase SFINAE pattern to safely query `underlying_type_t` only for enums

## Reflection
- GCC 8.x evaluates `underlying_type_t<T>` even when `is_enum_v<T>` is false in a conjunction, causing a hard error. The fix uses partial specialization to guard the inner check.
