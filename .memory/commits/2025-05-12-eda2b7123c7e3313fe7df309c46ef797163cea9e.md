# Fix clang-20 compilation error: qualify nullptr_t with std:: in String constructor delete

## TL;DR
- Changed `nullptr_t` to `std::nullptr_t` in the deleted `String` constructor declaration at `include/tvm/ffi/string.h:404`, fixing a compilation error with clang-20.
- This is a one-line bugfix (1 addition, 1 deletion) with no behavioral change.

## Impact
- API: None. The deleted constructor remains deleted; only the type spelling changed.
- Flags/config: None.
- Data formats/schemas: None.

This commit has zero behavioral impact. It fixes a strict standards-conformance issue introduced by clang-20, which no longer permits unqualified `nullptr_t` in certain contexts. The C++ standard requires `std::nullptr_t` (defined in `<cstddef>`); earlier compilers accepted the unqualified form as an extension.

## Design Elements

Design elements this commit consumes:
- **`String` class** (`include/tvm/ffi/string.h`): The `String` class is a core FFI container that wraps `ObjectRef` and provides string semantics. The deleted `String(std::nullptr_t)` constructor is part of a deliberate design decision to prevent null `String` values (unlike `Optional<String>` or `ObjectRef` which accept `nullptr`). All other `nullptr_t`-bearing signatures in the codebase (e.g., `ObjectPtr`, `Function`, `Optional`, comparison operators in `string.h:1096-1171`) already used the qualified `std::nullptr_t` form. This single site was an inconsistency.

Design elements this commit produces:
- None. No new design elements are introduced.
