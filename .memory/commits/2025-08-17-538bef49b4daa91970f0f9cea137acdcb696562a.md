# [FFI] Formalize ffi.Module (#18213)
## TL;DR
- Introduces `ffi::Module` (`ModuleObj` / `Module`) as a new first-class object in `include/tvm/ffi/extra/module.h`, with a reserved static type index `kTVMFFIModule = 73` and type key `"ffi.Module"`. The class provides a virtual interface for dynamically loadable function modules (kind, GetFunction, ImportModule, WriteToFile, SaveToBytes, etc.).
- Adds three implementation source files: `module.cc` (core Module logic + reflection + global functions), `library_module.cc` (LibraryModuleObj wrapping a `Library` abstraction + binary import-tree deserialization + ContextSymbolRegistry), `library_module_dynamic_lib.cc` (DSOLibrary via dlopen/LoadLibraryW), `library_module_system_lib.cc` (SystemLibrary backed by a global symbol table).
- Provides a C-level environment API in `include/tvm/ffi/extra/c_env_api.h` with three functions: `TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`.
- Fixes two bugs in `object.h` mutable ref macros: wrong macro name (`TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` -> `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN`) and trailing semicolons causing double-semicolon issues.

## Impact
- API: adds `ffi::Module`, `ffi::ModuleObj`, `ffi::Library` (internal), plus 10 global functions (`ffi.ModuleLoadFromFile`, `ffi.ModuleGetFunction`, `ffi.ModuleImplementsFunction`, `ffi.ModuleGetPropertyMask`, `ffi.ModuleInspectSource`, `ffi.ModuleGetKind`, `ffi.ModuleGetWriteFormats`, `ffi.ModuleWriteToFile`, `ffi.ModuleImportModule`, `ffi.ModuleClearImports`, `ffi.SystemLib`). Three new C ABI functions in `c_env_api.h`.
- Flags/config: none new. The module source files are gated by the existing `TVM_FFI_USE_EXTRA_CXX_API` CMake flag (4 new `.cc` files added to the conditional list).
- Data formats/schemas: defines a binary import-tree layout for embedded library modules (`<nbytes:u64> <import_tree_CSR> <kind:str> <bytes>...`). This is a wire format consumed by `ProcessLibraryBin`.
- Type system: reserves `TypeIndex::kTVMFFIModule = 73`; adds `StaticTypeKey::kTVMFFIModule`; reorders `kTVMFFISmallStr`/`kTVMFFISmallBytes` before `kTVMFFIBytes` in `StaticTypeKey` (cosmetic, no ABI impact since these are C++ constexpr strings, not enum values).

## Design Elements
Design elements this commit consumes:
- ADR-0009 extra/ API isolation: the entire Module subsystem is placed under `include/tvm/ffi/extra/` and `src/ffi/extra/`, gated by `TVM_FFI_USE_EXTRA_CXX_API`, following the pattern established in [.memory/ADRs/0009-extra-api-isolation.md](.memory/ADRs/0009-extra-api-isolation.md).
- Object system (design-0002): `ModuleObj` extends `Object`, `Module` extends `ObjectRef` via `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS`. Uses `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` for the static type index variant, consistent with other built-in types (`StringObj`, `ArrayObj`, etc.).
- Packed function and global registry (design-0003): all Module methods are exposed as global functions via `refl::GlobalDef().def(...)` / `.def_method(...)`. The `LoadFromFile` dispatches to `ffi.Module.load_from_file.<format>` in the global registry.
- Reflection system (design-0006): `ModuleObj::InternalUnsafe::RegisterReflection()` registers `imports_` as a read-only reflected field via `refl::ObjectDef<ModuleObj>().def_ro(...)`.

Design elements this commit produces:
- **Module architecture**: Virtual `ModuleObj` base class with `kind()`, `GetFunction()`, `GetPropertyMask()`, `ImportModule()`, `WriteToFile()`, `SaveToBytes()`, `InspectSource()`, `GetWriteFormats()`, and `ImplementsFunction()`. Import graph stored as `Array<Any> imports_` with cycle detection on import.
- **Library abstraction**: Internal `Library` base class (no type key, ref-counted only) with `GetSymbol(const char*)`. Concrete implementations: `DSOLibrary` (dlopen/LoadLibraryW) and `SystemLibrary` (global symbol table).
- **LibraryModuleObj**: Wraps a `Library` into a Module. Functions looked up by symbol name; each returned `ffi::Function` captures a strong ref to the Module to prevent premature unloading.
- **Import lookup caching**: `ModuleObj::import_lookup_cache_` (Map<String, Function>) caches results of `TVMFFIEnvLookupFromImports`, guarded by a static mutex.
- **ContextSymbolRegistry**: Singleton that stores `(name, void*)` pairs; on library load, patches matching symbol addresses into the library. Enables late-binding of context functions without explicit link dependency.
- **SystemLibModuleRegistry**: Singleton mapping symbol prefix to a cached `Module` instance, ensuring each prefix produces exactly one module for the process lifetime.
- **Binary import-tree format**: CSR-based serialization format for module dependency graphs (`indptr` + `child_indices` arrays), with `"_lib"` as a sentinel kind for the DSO module placeholder.
- **BufferInStream**: Internal utility (`buffer_stream.h`) for reading length-prefixed strings, vectors, and arithmetic types from a byte buffer with endian awareness.
- **Well-known symbols**: `symbol::tvm_ffi_library_ctx`, `symbol::tvm_ffi_library_bin`, `symbol::tvm_ffi_main` in the `ffi::symbol` namespace.
- **ModulePropertyMask**: Bitmask enum (`kBinarySerializable = 0b001`, `kRunnable = 0b010`, `kCompilationExportable = 0b100`) for querying module capabilities.

## Reflection
- This commit formalizes the original `runtime::Module` from the main TVM project into the FFI layer, making it a standalone module system. The commit message explicitly states the goal is to "stabilize the Module API as extra API."
- The `object.h` macro fix (`TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` -> `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN`) corrects a reference to a macro that does not exist in the FFI codebase (it was the old TVM macro name). The trailing-semicolon fix prevents `-Wpedantic` double-semicolon warnings. Both fixes were likely discovered while using `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` for the `Module` class.
- The `Library` class intentionally has no type index or type key -- the comment explains this is because no dynamic type downcasting is needed, only ref-counting. This is a deliberate deviation from the standard ObjectObj pattern.
- The `imports_` field uses `Array<Any>` rather than `Array<Module>` to avoid circular header dependencies (since `Module` is defined in the same header as `ModuleObj`).
- The `GetFunctionFromImports` path uses a static `std::mutex` for thread-safety of the import lookup cache. This is a coarse lock; under contention from many threads calling into different modules, this could become a bottleneck. However, the common case is single-threaded module loading.
- ADR-0009 now has a fourth category of extra/ content: Module. Previous categories were structural equal/hash, JSON, and serialization. The growing set of extra APIs is worth monitoring per the ADR's follow-up actions.
