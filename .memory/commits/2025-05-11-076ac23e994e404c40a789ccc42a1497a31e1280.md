# Fix DLDataType ABI safety in C API and add configurable log-before-throw

## TL;DR
- Changed `TVMFFIDataTypeToString` C ABI signature to accept `const DLDataType*` (pointer) instead of `DLDataType` (by-value), preventing ABI incompatibility across compilers that may pass small structs differently in registers vs. stack.
- Added `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` compile-time flag (default 0) to `TVM_FFI_THROW`, allowing builds to force stderr logging of every thrown error for debugging scenarios (e.g., web runtime where exceptions may be silently swallowed).

## Impact
- API: **Breaking C ABI change** -- `TVMFFIDataTypeToString` signature changed from `(DLDataType, TVMFFIObjectHandle*)` to `(const DLDataType*, TVMFFIObjectHandle*)`. All callers of this C symbol (foreign language bindings) must update. The C++ wrapper `DLDataTypeToString` in `dtype.h` absorbs the change by passing `&dtype`.
- Flags/config: New compile-time macro `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` (default 0). When set to 1 at compile time, every `TVM_FFI_THROW` invocation will log the error to stderr before throwing. No runtime config change.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md): The C ABI stability contract. This commit intentionally breaks the ABI for `TVMFFIDataTypeToString` to fix a correctness issue (struct-by-value in `extern "C"` is implementation-defined for register passing).
- [.memory/ADRs/0004-tls-error-propagation.md](.memory/ADRs/0004-tls-error-propagation.md): `TVM_FFI_THROW` macro extended with the log-before-throw flag, building on the existing `ErrorBuilder` and its `log_before_throw` parameter.

Design elements this commit produces:
- **ABI pattern**: Passing small C structs (like `DLDataType`, 4 bytes) by pointer rather than by value across `extern "C"` boundaries. This is a reusable convention for future C ABI additions.
- **Debug flag pattern**: `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` establishes the pattern for compile-time debug toggles in the error subsystem.

## Reflection
- The `DLDataType` struct is only 4 bytes (`uint8_t code, uint8_t bits, uint16_t lanes`), but passing it by value across the C ABI is problematic because different compilers/platforms may disagree on whether it goes in a register or on the stack (especially relevant for Emscripten/WASM). The fix to pass by pointer is consistent with how `TVMFFIDataTypeFromString` already accepts its output via `DLDataType*`.
- The commit message references "Upgrade Web Runtime to new FFI" (#17946), suggesting the `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` flag was motivated by web runtime debugging where exceptions may be lost. This is a practical need for the Emscripten target documented in [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md).
- The change to `error.h` replaces the hardcoded `false` in `TVM_FFI_THROW` with the new macro, which is backward-compatible (default 0 = `false`). `TVM_FFI_THROW_LOG` remains unchanged (still passes `true`), keeping the two macros as the non-logging and always-logging variants.
