# feat(typing): Parameterizable `Array[T]` and `Map[K, V]` (#37)
## TL;DR
- Rewrites `Array` and `Map` classes to accept generic type parameters (`Array[T]`, `Map[K, V]`) using `TypeVar` and ABCs (`Sequence[T]`, `Mapping[K, V]`).
- `KeysView`, `ValuesView`, `ItemsView` are now generic (`KeysView[K]`, `ValuesView[V]`, `ItemsView[K, V]`) with proper `cast()` calls.
- `getitem_helper` is now generic, uses `operator.index()` for proper `__index__` protocol support, and delegates slice range computation to `slice.indices()`.
- `Array.__getitem__` with a slice now returns a new `Array` (was returning a plain `list`). Adds explicit `__iter__` method.
- `Map.get()` gains proper `@overload` signatures. `ItemsView.__contains__` now handles `(key, value)` tuple checking correctly.
## Impact
- API: `Array[T]` and `Map[K, V]` are now parameterizable for type checkers. `Array.__getitem__(slice)` now returns `Array[T]` instead of `list`. `Map.__contains__` parameter type widened to `object`.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `_ffi_api.ArrayGetItem`, `_ffi_api.ArraySize`, `_ffi_api.MapGetItem`, `_ffi_api.MapForwardIterFunctor` FFI functions.
Design elements this commit produces:
- Generic container types usable with mypy/pyright: `Array[int]`, `Map[str, Object]`, etc.
- `@overload` pattern on `Map.get()` and `Array.__getitem__` for precise return types.
## Reflection
- Changing `Array.__getitem__(slice)` from returning `list` to `Array` is a behavioral change that could affect downstream code expecting a plain list.
- The `KeysView`/`ValuesView`/`ItemsView` iteration now uses a bounded `for _ in range(size)` loop instead of an unbounded `while True`, which is more defensive.
