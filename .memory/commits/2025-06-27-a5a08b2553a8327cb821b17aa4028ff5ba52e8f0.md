# Migrate attrs object definitions to use new reflection and harden TypeTable
## TL;DR
- Adds a duplicate-registration guard in `TypeTable::RegisterTypeExtraInfo` that throws a `RuntimeError` with diagnostic hints if `extra_info` is already set for a type index.
- Registers a base `TVMFFITypeExtraInfo` for `Object` itself during `TypeTable` initialization, so the root type participates in the reflection system.
- Allows `MakeObjectFromPackedArgs` to accept a type index (`int32_t`) in addition to a type key (`String`) as the first argument, removing the dependency on a string lookup when the index is already known.
- Zeroes the padding bits of `TVMFFIAny::v_uint64` before writing `v_dtype` in `DLDataType` `CopyToAnyView`/`MoveToAny`, ensuring equality checks on the raw `v_uint64` are not poisoned by uninitialized padding.
## Impact
- API: `MakeObjectFromPackedArgs` now accepts `int32_t` type index as its first argument (previously only `String`). Callers passing a string key are unaffected. Internal error messages switch from using the caller-supplied `type_key` variable to `TypeIndexToTypeKey(type_index)`, which is functionally identical.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- The `TVMFFITypeExtraInfo` / `TypeTable` reflection infrastructure introduced in prior commits.
- The `ObjectDef<T>` builder pattern for registering type extra info (the guard protects against double registration from this path).
Design elements this commit produces:
- A fail-fast invariant that each type index may only have `extra_info` registered once, catching common mistakes (duplicate `ObjectDef<T>()`, missing `_type_key` override in subclass, key collision).
- `Object` (the root type) now has an `extra_info` entry (with `creator = nullptr`), making reflection queries uniform across the hierarchy.
- `DLDataType` AnyView/Any storage now guarantees zero-padding, a prerequisite for safe bitwise equality via `v_uint64`.
## Reflection
- The duplicate-registration guard is a defensive measure that turns a silent data-corruption bug (overwriting extra_info) into an immediate, actionable error with root-cause hints. This is especially valuable during the migration period where attrs classes are being moved to the new reflection system.
- Accepting `int32_t` type index in `MakeObjectFromPackedArgs` avoids a redundant key-to-index lookup when the caller already has the index, which is the common case for C++ callers and the reflection machinery itself.
- The `v_uint64 = 0` padding fix in `dtype.h` is a subtle correctness issue: `DLDataType` is a 32-bit struct stored in a 64-bit union slot, so the upper 32 bits could contain stack garbage, causing spurious inequality when compared via the fast `v_uint64` path.
