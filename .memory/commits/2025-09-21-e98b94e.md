# feat: Introduce Experimental `tvm_ffi.dataclasses.c_class` (#8)
## TL;DR
- Adds `tvm_ffi.dataclasses` package with `c_class` decorator, `field()` helper, and internal utilities to mirror C++ reflected types as Python dataclass-style classes.
- Adds `__ffi_init__` method to `Object` (Cython) to forward construction to the C++-registered `__init__` method.
- Registers test C++ classes (`TestCxxClassBase`, `TestCxxClassDerived`, `TestCxxClassDerivedDerived`) with `ObjectDef` reflection for end-to-end testing.
## Impact
- API: New public decorator `@c_class(type_key)` and `field(default=..., default_factory=...)`. New `__ffi_init__` on all `Object` instances. New `__c_ffi_init__` class attribute convention.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- C++ reflection system (`ObjectDef`, `def_field`, `def_method`, `TypeInfo`, `TypeField`) to discover fields/methods at runtime.
- `register_object` pattern and `__init_handle_by_constructor__` Cython path.
Design elements this commit produces:
- `c_class` decorator: reads C++ reflection metadata, synthesizes `__init__` with proper signature, binds fields as properties, supports `__post_init__`, default values, and inheritance.
- `Field` / `field()` API mirroring `dataclasses.field`.
- `_utils.type_info_to_cls` helper for constructing proxy classes from `TypeInfo`.
## Reflection
- The decorator intentionally mirrors `dataclasses.dataclass` semantics (field ordering, default-last, `__post_init__`) to lower the learning curve for Python users.
- `__ffi_init__` is renamed to `__c_ffi_init__` as a class attribute to avoid clashing with the instance method on `Object`.
