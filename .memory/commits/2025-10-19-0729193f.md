# feat: Automatically add `__init__` method if available (#174)
## TL;DR
- When a registered object class has no `__init__`, the system now auto-generates one: if `__ffi_init__` is defined, it becomes `__init__`; otherwise, `__init__` raises `RuntimeError`
- Prevents silent creation of objects with `chandle=None` that would segfault on field access
- Minor fix in `object.pxi`: changed `dict(cls.__dict__)` to `cls.__dict__.copy()`
## Impact
- API: objects without `__init__` now raise RuntimeError instead of silently creating broken instances (behavioral breaking change for code relying on the old silent behavior)
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `__ffi_init__` reflection method convention
Design elements this commit produces:
- Auto-init pattern: `__ffi_init__` -> `__init__` mapping in `_add_class_attrs`
## Reflection
- Critical safety fix; the old behavior was a footgun leading to segfaults
