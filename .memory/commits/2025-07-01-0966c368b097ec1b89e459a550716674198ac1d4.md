# Formalize namespace for all objects from object.* to ffi.*

## TL;DR
- Renames all built-in object type keys from the `object.*` namespace to `ffi.*` (e.g. `object.String` -> `ffi.String`, `object.Object` -> `ffi.Object`).
- Adds previously missing `StaticTypeKey` constants for `Object`, `Function`, `Array`, and `Map`, centralizing all type key strings in one place.
- Replaces inline string literals in `_type_key` fields with references to `StaticTypeKey` constants where applicable.

## Impact
- API: **Breaking** for any code that matches on type key strings (e.g. `"object.String"` becomes `"ffi.String"`). Affects all registered built-in objects: `Object`, `String`, `Bytes`, `Shape`, `NDArray`, `Error`, `Function`, `Array`, `Map`.
- Flags/config: none
- Data formats/schemas: Serialized type keys change from `object.*` to `ffi.*`; any persisted type information using old keys will not match.

## Design Elements
Design elements this commit consumes:
- `StaticTypeKey` struct in `object.h` as the central registry of well-known type key strings
- Object registration pattern: `_type_key` static constexpr on each `*Obj` class

Design elements this commit produces:
- `ffi.*` as the canonical namespace prefix for all FFI-layer built-in objects
- Four new `StaticTypeKey` constants: `kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`
- Pattern of referencing `StaticTypeKey::k*` instead of inline string literals for `_type_key`

## Reflection
- This is a namespace hygiene commit: `object.*` was an ad-hoc prefix that did not clearly convey these types belong to the FFI layer. `ffi.*` aligns with the C++ namespace (`tvm::ffi`) and the Python package name (`tvm_ffi`).
- The commit also fixes an inconsistency: `ErrorObj` and `FunctionObj` used inline string literals while others (like `Bytes`, `String`) used `StaticTypeKey` constants. Now most use `StaticTypeKey`, except `ErrorObj` which still uses an inline `"ffi.Error"` literal (no constant was added for it).
