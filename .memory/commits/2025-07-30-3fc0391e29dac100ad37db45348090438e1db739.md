# [FFI][REFACTOR] Isolate out extra API (#18177)

## TL;DR
- Introduces `include/tvm/ffi/extra/` directory with `base.h` as the root header, and moves structural equal/hash from `reflection/` to `extra/`. The `TVM_FFI_EXTRA_CXX_API` macro moves from `c_api.h` to `extra/base.h`.
- Promotes `access_path.cc` from the conditional `TVM_FFI_USE_EXTRA_CXX_API` build into the always-compiled core sources in `CMakeLists.txt`.
- Renames `AccessKind` enum values: `kArrayIndex` -> `kArrayItem`, `kMapKey` -> `kMapItem` (and their `Missing` variants), plus corresponding factory methods on `AccessStep`.

## Impact
- API: **Breaking rename** of `AccessKind` enums and `AccessStep` factory methods (`ArrayIndex` -> `ArrayItem`, `MapKey` -> `MapItem`, etc.). Any C++ caller using `AccessStep::ArrayIndex()`, `AccessStep::MapKey()`, or matching on `AccessKind::kArrayIndex`/`kMapKey` must update. The structural equal/hash headers move from `tvm/ffi/reflection/` to `tvm/ffi/extra/` (include paths change).
- Flags/config: `TVM_FFI_USE_EXTRA_CXX_API` cmake flag now only gates `extra/structural_equal.cc` and `extra/structural_hash.cc`; `access_path.cc` is always built.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- [0006-reflection-system.md](.memory/designs/0006-reflection-system.md): structural equal/hash were part of the reflection subsystem; this commit re-categorizes them as "extra" (non-core) APIs.

Design elements this commit produces:
- Establishes the `extra/` directory convention: non-core C++ APIs that depend on core FFI but are not required for basic object/function operations. The `extra/base.h` header defines `TVM_FFI_EXTRA_CXX_API` and documents the rationale (reduce compile-time, ABI note about MSVC/Itanium).
- `access_path.cc` promoted to core: access paths are now considered essential (not extra), since they are used by the reflection accessor read path.

## Reflection
- The separation clarifies a layering boundary: core FFI (always built) vs extra C++ APIs (conditionally built). Structural equal/hash are convenience features for deep comparison and are not needed by the core object/function/container machinery.
- Renaming `kArrayIndex`/`kMapKey` to `kArrayItem`/`kMapItem` is a terminology normalization -- "item" is more consistent with the Python container protocol and avoids implying that the step is an integer index (maps use arbitrary keys).
- `access_path.cc` being always-compiled suggests that the `AccessPath`/`AccessStep` types are becoming part of the core reflection contract, not just a helper for structural comparison.
