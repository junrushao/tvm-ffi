# [CORE] Update logic to use combined ref count (#58)
## TL;DR
- Merged `strong_ref_count` (u32) and `weak_ref_count` (u32) into a single `uint64_t combined_ref_count` in `TVMFFIObject`. Strong is lower 32 bits, weak is upper 32 bits.
- All IncRef/DecRef/IncWeakRef/DecWeakRef operations now use a single 64-bit atomic, enabling a fast path in DecRef where both counters reach zero simultaneously (one atomic op instead of two).
- `use_count()` return type changed from `int32_t` to `uint64_t` (masked to lower 32 bits).
- Version bumped to 0.1.0b8.
## Impact
- API: ABI-breaking change to `TVMFFIObject` header layout. All compiled code must be recompiled.
- Flags/config: none
- Data formats/schemas: `TVMFFIObject` field `{strong_ref_count, weak_ref_count}` replaced by `{combined_ref_count}`.
## Design Elements
Design elements this commit consumes:
- Ref-count-first layout from #57 (13436f0)
- `kTVMFFIObjectDeleterFlagBitMaskBoth` fast-path deletion

Design elements this commit produces:
- `kCombinedRefCountWeakOne`, `kCombinedRefCountStrongOne`, `kCombinedRefCountBothOne`, `kCombinedRefCountMaskUInt32` constants
- Single-atomic combined ref count pattern (inspired by torch)
## Reflection
- The combined ref count optimization avoids a separate atomic read of the weak counter during strong-count-goes-to-zero, which is the common deletion path.
