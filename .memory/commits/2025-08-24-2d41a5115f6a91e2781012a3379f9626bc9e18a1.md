# [FFI][REFACTOR] Establish tvm_ffi python module (#18226)

## TL;DR
- Creates `tvm_ffi` as a standalone pip-installable Python package (via `pyproject.toml` + scikit-build-core + Cython), decoupling the FFI layer from the main TVM compiler.
- Adds the full Cython binding layer (`python/tvm_ffi/cython/*.pxi`), pure-Python modules (registry, container, module, ndarray, error, dtype, etc.), and a comprehensive Python test suite.
- Reworks CMake to support dual-mode: subproject inclusion (header-only or object library) and standalone root build with Cython module compilation, install targets, and a `tvm_ffi-config.cmake` for downstream `find_package` consumption.
- Improves `TVMFFITraceback` C API to accept a `cross_ffi_boundary` flag, enabling FFI-boundary-aware stack trace truncation and frame skipping.

## Impact
- API: New `TVMFFITraceback` signature adds a 4th parameter (`int cross_ffi_boundary`). All callers of `TVM_FFI_THROW` / `TVM_FFI_LOG_AND_THROW` are updated transparently via macro changes. The removed `TVM_FFI_TRACEBACK_HERE` internal macro is no longer exposed.
- Flags/config: New CMake options `TVM_FFI_BUILD_PYTHON_MODULE`, `TVM_FFI_ATTACH_DEBUG_SYMBOLS`. Build system functions renamed with `tvm_ffi_` prefix (`add_target_from_obj` -> `tvm_ffi_add_target_from_obj`, etc.).
- Data formats/schemas: none.
- Packaging: `apache-tvm-ffi` is now a proper Python package (version 0.1.0a0) with `tvm-ffi-config` CLI entry point, zero runtime dependencies, and `scikit-build-core` as build backend. Python Stable ABI (SABI 3.12) used when available.

## Design Elements
Design elements this commit consumes:
- Module system design: the Python `Module` class (`python/tvm_ffi/module.py`) is the Python-side counterpart of C++ `ffi::Module` (see [.memory/designs/0009-module-system.md](.memory/designs/0009-module-system.md))
- Object registration pattern: `register_object("ffi.Module")` decorator wires Python class to C++ type index
- Global function registry: `_ffi_api` module pattern (`python/tvm_ffi/_ffi_api.py`) for lazy global function lookup
- Packed function calling convention: Cython `function.pxi` implements full argument marshaling for all type indices (None, Int, Bool, Float, DataType, Device, Object, NDArray, String, Bytes, etc.)

Design elements this commit produces:
- **Standalone Python package architecture**: `tvm_ffi` can be installed independently (`pip install ./ffi`), enabling lightweight downstream packages that depend only on the FFI layer without the full TVM compiler toolchain
- **`tvm-ffi-config` CLI**: provides `--includedir`, `--libdir`, `--cmakedir`, `--cxxflags`, `--ldflags` for downstream C++ integration (analogous to `pkg-config`)
- **`cmake/tvm_ffi-config.cmake`**: enables `find_package(tvm_ffi CONFIG)` in downstream CMake projects, auto-discovering paths via `tvm_ffi.config` Python module
- **Dual CMake mode**: when used as subproject (via `add_subdirectory`), only library targets are defined; when used as root project, test/python/install targets are added
- **FFI-boundary-aware traceback**: `cross_ffi_boundary=0` stops trace at FFI boundary (used by `TVM_FFI_THROW`); `cross_ffi_boundary=1` crosses it (used by segfault handler). Frame skipping via `skip_frame_count` removes `TVMFFITraceback` and caller from trace.
- **`examples/get_started/`**: end-to-end example showing how to compile a kernel library (.so), load it from Python via `tvm_ffi.load_module()`, and from C++ via `ffi::Module::LoadFromFile()`

## Reflection
- This commit is the foundational packaging step that makes the FFI layer independently distributable. All subsequent Python-side features (dataclasses, reflection, serialization) build on top of this package structure.
- The Cython binding layer is substantial (~1900 lines across 8 `.pxi` files) and handles all type index marshaling, error propagation (C++ exception -> Python exception with traceback stitching), torch tensor auto-conversion, and DLPack interop.
- The traceback improvement (boundary detection + frame skipping) is a quality-of-life change that produces cleaner stack traces by removing internal FFI dispatch frames and optionally stopping at the Python/C++ boundary.
- MSVC pragma fix (`#pragma disagnostic` -> `#pragma warning`) and `[[maybe_unused]]` on final object info are minor portability fixes bundled into this commit.
- The `cmake/Utils/Library.cmake` renames (`add_target_from_obj` -> `tvm_ffi_add_target_from_obj`) are a namespace-safety measure to avoid collisions when tvm_ffi is included as a subproject.
