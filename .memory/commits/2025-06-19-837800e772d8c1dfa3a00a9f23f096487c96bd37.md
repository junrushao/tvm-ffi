# Update TypeInfo to store ancestor pointers instead of indices, add ForEachFieldInfo helper

## TL;DR
- Changed `type_acenstors` in `TVMFFITypeInfo` from `const int32_t*` (array of type indices) to `const struct TVMFFITypeInfo**` (array of pointers to parent TypeInfo structs), eliminating runtime `TVMFFIGetTypeInfo` lookups when walking the ancestor chain.
- Added `reflection::ForEachFieldInfo()` utility that iterates through all fields of a type including inherited parent fields, using the new ancestor pointers for direct traversal.
- Restructured `IsObjectInstance<T>()` to use explicit `if constexpr / else` chains, helping the compiler eliminate dead branches earlier during template instantiation.

## Impact
- API: **C ABI breaking change**. The `TVMFFITypeInfo::type_acenstors` field type changed from `const int32_t*` to `const struct TVMFFITypeInfo**`. All code that reads ancestor entries must dereference a pointer to get the `TypeInfo` struct instead of using the index with `TVMFFIGetTypeInfo()`. Affected callers: `IsObjectInstance<T>()` in `object.h`, `MakeObjectFromPackedArgs` in `object.cc`, `TypeTable` debug printing in `object.cc`, and any downstream code accessing the C ABI `type_acenstors` field.
- API: New `reflection::ForEachFieldInfo(const TypeInfo*, callback)` function template added in `reflection.h`. New `String(TVMFFIByteArray)` explicit constructor added in `string.h`.
- Flags/config: none
- Data formats/schemas: `TVMFFITypeInfo` struct layout changed (pointer width vs int32 for ancestor array elements)

Design elements this commit consumes:

- Type index partitioning and child-slot reservation -> [.memory/ADRs/0001-type-index-partitioning.md](.memory/ADRs/0001-type-index-partitioning.md)
- Reflection `ObjectDef<T>` builder with `def_field`/`def_method` -> design 0002, Extension Points section

Design elements this commit produces:
- **Ancestor pointer invariant update**: `type_acenstors[i]` now holds a `const TVMFFITypeInfo*` pointing directly to the ancestor's `TypeInfo` entry rather than an `int32_t` index. This allows O(1) field/method access on ancestors without a `TVMFFIGetTypeInfo` lookup. Updates the "Ancestor array invariant" in design 0002.
- **ForEachFieldInfo pattern**: A new reusable traversal pattern for walking all fields (parent + child) of a reflected type. Used in `MakeObjectFromPackedArgs` and available for future reflection consumers (serialization, Python `c_class` init, etc.).

## Reflection
- The ancestor pointer change is a performance optimization that trades slightly larger ancestor arrays (pointers vs int32) for eliminating hash-table lookups during `IsInstance` slow-path and parent-field iteration. On 64-bit platforms, each ancestor entry grows from 4 bytes to 8 bytes.
- The `if constexpr` restructuring in `IsObjectInstance` is a compile-time optimization: wrapping the non-leaf branch in an explicit `else` allows the compiler to skip template instantiation of the inner code when the outer `if constexpr` is true. The `_type_child_slots_can_overflow` check is also converted from a runtime `if (!...)` to `if constexpr`, enabling full branch elimination for final types and types without overflow.
- The removal of `TVM_FFI_ICHECK(type_info->type_acenstors[0] == TypeIndex::kTVMFFIObject)` in `MakeObjectFromPackedArgs` is safe because the root ancestor is always `Object` by construction (enforced by `TypeTable` registration logic).
- The `ForEachFieldInfo` helper consolidates duplicated parent-field iteration logic that was previously inlined in `MakeObjectFromPackedArgs`. The test `Reflection.ForEachFieldInfo` validates it with a two-level hierarchy (`TestObjA` -> `TestObjADerived`).
- The `String(TVMFFIByteArray)` constructor is a convenience addition that enables constructing a `String` directly from C ABI byte arrays (e.g., field names in `TVMFFIFieldInfo`).
