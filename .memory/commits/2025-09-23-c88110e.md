# fix(Map): `Map.get` should never throw when element is missing (#48)
## TL;DR
- Changes `DenseMapObj::At` to throw `KeyError` instead of `IndexError` when a key is not found. This fixes `Map.get(key)` in Python, which catches `KeyError` but was seeing `IndexError` leak through.
- Adds a test for `Map.get` on a large map (100 entries) to verify correct behavior for both missing and present keys.

## Impact
- API: C++ `DenseMapObj::At` now throws `KeyError` instead of `IndexError`; callers catching `IndexError` from Map lookups will need to update. Python `Map.get()` now works correctly (returns `None` for missing keys instead of propagating an exception).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none

Design elements this commit produces:
- Correct error type mapping: C++ `KeyError` maps to Python `KeyError`, enabling `dict`-like `.get()` semantics

## Reflection
- The bug was that Python's `Map.get` wraps the lookup in a `try/except KeyError`, but C++ was throwing `IndexError`, so the exception was never caught and instead propagated to the caller.
- Single-line fix with high correctness impact.
