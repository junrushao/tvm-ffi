# Enhance reflection to support nanobind/pybind-style def_ro/def_rw/def/def_static API with field metadata and method registration
## TL;DR
- Rewrites the `ReflectionDef` builder from `def_readonly`/`def_readwrite` to a pybind/nanobind-style API: `def_ro`, `def_rw`, `def`, `def_static`, with variadic extra args for docstrings and default values.
- Adds full method registration infrastructure: new `TVMFFIMethodInfo` fields (`doc`, `flags`, stored as `TVMFFIAny`), new C API `TVMFFITypeRegisterMethod`, and C++ helpers `GetMethodInfo`/`GetMethod`.
- Extends `TVMFFIFieldInfo` with `doc`, `flags` bitmask (`TVMFFIFieldFlagBitMask`), and `default_value` fields; renames C API from `TVMFFIRegisterTypeField` to `TVMFFITypeRegisterField` and `TVMFFIGetOrAllocTypeIndex` to `TVMFFITypeGetOrAllocIndex`.

## Impact
- API: **Breaking C ABI changes**. `TVMFFIFieldInfo` struct layout is rearranged (fields reordered, `readonly` int32 replaced by `flags` int64 bitmask, new `doc`/`default_value` fields). `TVMFFIMethodInfo.method` changes from `TVMFFIObjectHandle` to `TVMFFIAny`. Three C API functions renamed: `TVMFFIRegisterTypeField` -> `TVMFFITypeRegisterField`, `TVMFFIGetOrAllocTypeIndex` -> `TVMFFITypeGetOrAllocIndex`, new `TVMFFITypeRegisterMethod` added. The C++ reflection API renames `def_readonly`/`def_readwrite` to `def_ro`/`def_rw` and moves from `details` namespace to `reflection` (aliased as `refl`). All downstream reflection registrations and callers of `GetReflectionFieldInfo`/`ReflectionFieldGetter` must update.
- Flags/config: New `TVMFFIFieldFlagBitMask` enum with `Writable`, `HasDefault`, `IsStaticMethod` bits.
- Data formats/schemas: `TVMFFIFieldInfo` gains `doc` (TVMFFIByteArray), `flags` (int64), `default_value` (TVMFFIAny) fields. `TVMFFIMethodInfo` gains `doc` (TVMFFIByteArray), `flags` (int64) fields, and `method` changes to `TVMFFIAny` storage.

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md): extends the C ABI with richer reflection structs and new registration functions
- [.memory/designs/0002-object-system-and-reference-counting.md](.memory/designs/0002-object-system-and-reference-counting.md): adds `_type_mutable` flag to Object for controlling non-const pointer extraction from Any/AnyView

Design elements this commit produces:
- **Reflection builder API pattern**: The `ReflectionDef` class now follows the nanobind/pybind `def_ro`/`def_rw`/`def`/`def_static` convention with variadic extra arguments (docstrings, `DefaultValue` trait objects). This is the canonical pattern for registering object fields and methods in C++.
- **FieldInfoTrait extensibility pattern**: The `FieldInfoTrait` base class with `Apply(TVMFFIFieldInfo*)` method enables adding new field metadata without changing `ReflectionDef` itself. `DefaultValue` is the first concrete trait.
- **Method registration via `TVMFFITypeRegisterMethod`**: Methods are stored as `Function` objects inside `TVMFFIAny` in the TypeTable, accessed via `reflection::GetMethod("type.key", "method_name")`.
- **`_type_mutable` object property**: New `static constexpr bool _type_mutable = false` on `Object` base class. When set to `true` on a subclass, enables `TObject*` (non-const) extraction from Any/AnyView. Enforced via `static_assert` at compile time.
- **Namespace reorganization**: Reflection internals move from `tvm::ffi::details` to `tvm::ffi::reflection` with `namespace refl = reflection` alias.

## Reflection
- The `TVMFFIFieldInfo` struct layout reordering is a **breaking ABI change**: all existing compiled bindings (Python Cython, Rust FFI) that read field info must be recompiled. The `readonly` -> `flags` bitmask change is not just a rename; it inverts semantics (old: `readonly=1` meant read-only; new: `flags & Writable` means writable).
- The `string_pool_` in TypeTable is replaced by a general `any_pool_` (`vector<Any>`), which now owns both strings and default values. This is a good simplification but means the pool grows unboundedly for the lifetime of the process.
- The `_type_mutable` flag is a safety gate for the `TObject*` (non-const raw pointer) extraction from `Any`/`AnyView`. The `static_assert` in `TypeTraits<TObject*>` makes violations compile-time errors. `TPrimExprObj` in tests is the first type to opt in. This is a prerequisite for reflection methods that need to mutate object fields.
- The `GetMethod` helper has three overloads: member function pointer (non-const), const member function pointer, and generic callable. The non-const member function overload uses `const_cast`, which is safe only when `_type_mutable` is set -- but this invariant is not enforced at the reflection registration site, only at the Any extraction site.
- The C API function renaming (`TVMFFIRegisterTypeField` -> `TVMFFITypeRegisterField`, `TVMFFIGetOrAllocTypeIndex` -> `TVMFFITypeGetOrAllocIndex`) adopts a `TVMFFIType*` prefix convention for type-related operations, improving discoverability.
- The `field_static_type_index` default is moved from individual `TypeTraits` specializations to `TypeTraitsBase` (defaulting to `kTVMFFIAny`), and `char[N]`/`const char*` traits lose their `field_static_type_index = kTVMFFIRawStr` override. This means raw string fields will now report `kTVMFFIAny` as their static type index, which may affect serializers that relied on the previous `kTVMFFIRawStr` distinction.
- `std::forward<Args>(params)...` fix in `function.h` method wrappers corrects a latent perfect-forwarding bug that would have caused unnecessary copies of move-only arguments.
