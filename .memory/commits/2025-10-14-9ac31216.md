# [CPP] Remove static line based object reg in favor of ObjectDef (#116)
## TL;DR
- Removes the `static inline int32_t _register_type_index` / `_type_index` auto-registration from `TVM_FFI_DECLARE_OBJECT_INFO*` macros.
- Type index registration now requires explicit `reflection::ObjectDef<T>()` or a manual call to `_GetOrAllocRuntimeTypeIndex()`.
- Rationale: static inline registration caused binary size overhead in every DLL that includes the header, even if the class is unused.
## Impact
- API: Breaking for C++ users -- objects that rely on dynamic casting must now be explicitly registered via `ObjectDef`. Static-indexed objects are unaffected.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `reflection::ObjectDef<T>` registration mechanism
Design elements this commit produces:
- Explicit-registration-only model for dynamic object types
- Added `StaticTypeKey::kTVMFFIError` for `ffi.Error`
## Reflection
- Trade-off: slightly more boilerplate (one `ObjectDef<T>()` call per type) for reduced binary bloat. Since reflection already requires `ObjectDef`, the extra burden is minimal for well-structured code.
- The `[[maybe_unused]]` on `tindex` in `_GetOrAllocRuntimeTypeIndex` acknowledges that the side effect (registration) is what matters, not the return value.
