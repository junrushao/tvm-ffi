# fix(Array): Make array slicing behavior to return list (#50)
## TL;DR
- `Array.__getitem__(slice)` now returns a plain `list[T]` instead of wrapping the result back into an `Array[T]`.
- Removes the `isinstance(result, list)` check and `type(self)(result)` re-wrapping from `__getitem__`.
- Updates type annotations from `Array[T]` to `list[T]` for slice return type; adds test assertion.

## Impact
- API: Breaking change for callers that relied on `array[start:stop]` returning an `Array`. It now returns a `list`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none

Design elements this commit produces:
- Convention: Array slicing returns Python `list`, consistent with the idea that Array is an immutable FFI container and slicing produces a local Python copy.

## Reflection
- This avoids an unnecessary round-trip through the FFI constructor for slice results, which are typically used locally in Python.
- The change is a deliberate API break, communicated via the PR title prefix `fix(Array)`.
