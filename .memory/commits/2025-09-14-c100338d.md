# [DOCS] Add C example (#15)
## TL;DR
- Adds `examples/quick_start/src/add_one_c.c`: a pure C implementation of the FFI ABI with `ReadDLTensorPtr` helper and `__tvm_ffi_add_one_c` symbol
- Fixes `c_api.h` for C compiler compatibility: moves `DLPackTensorAllocator` typedef inside `extern "C"` block, adds forward declaration of `DLManagedTensorVersioned`, removes `char32_t v_char32[2]` from `TVMFFIAny` union
- Adds `--cflags` flag to `tvm-ffi-config` CLI (C flags without `-std=c++17`)
- Extends quick start docs with the C ABI section and `gcc` compilation command
## Impact
- API: `TVMFFIAny` union loses `v_char32` field (breaking for anyone referencing it directly, but it was unused)
- Flags/config: new `--cflags` option in `tvm-ffi-config`
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `TVMFFISafeCallType` calling convention (`void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result`)
- `__tvm_ffi_` symbol prefix convention
- `TVMFFIEnvGetStream` and `TVMFFIErrorSetRaisedFromCStr` C env APIs

Design elements this commit produces:
- Reference C implementation of an FFI-compatible function (useful as codegen target spec)
- `tvm-ffi-config --cflags` for pure-C compilation (no C++17 flag)
- C-compatible `c_api.h` header (can now be included from `.c` files)
## Reflection
- Removing `v_char32` from the union is a minor ABI change; it was unused and blocked C compilation (C has no `char32_t` by default without `<uchar.h>`)
- Moving `DLPackTensorAllocator` inside `extern "C"` ensures the typedef has C linkage
