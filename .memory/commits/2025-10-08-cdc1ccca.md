# chore: Clean up libbacktrace-related outputs (#92)
## TL;DR
- Suppresses noisy libbacktrace build output by enabling `LOG_CONFIGURE ON`, `LOG_BUILD ON`, `LOG_INSTALL ON`, `LOG_OUTPUT_ON_FAILURE ON` on the ExternalProject
- Replaces broken `--host=${MACHINE_NAME}` (undefined CMake variable) with `detect_target_triple()` function that auto-detects the target triple
- New `cmake/Utils/DetectTargetTriple.cmake` (303 lines) provides comprehensive target triple detection: queries compiler (`-dumpmachine`/`--print-target-triple`), handles Emscripten, Android, iOS, QNX, Windows, Linux, macOS, FreeBSD, and synthesis fallback

## Impact
- API: none
- Flags/config: New CMake function `detect_target_triple(out_var)` available to downstream CMake users
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none
Design elements this commit produces:
- `detect_target_triple()` CMake function -- reusable for any cross-compilation scenario

## Reflection
- The previous `--host=${MACHINE_NAME}` was silently broken (undefined variable), meaning libbacktrace was building without a proper host triple. The new detection makes cross-compilation more reliable.
