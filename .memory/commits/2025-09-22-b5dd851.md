# fix(c_class): Fix mypy warnings on `dataclasses.field(...)` (#43)
## TL;DR
- Changes `field()` return type from `Field` to `_FieldValue` (generic TypeVar) using `cast()`, so mypy treats `field(default=0.0)` as the correct value type in class bodies.
- Uses `_MISSING_TYPE` from `dataclasses` for precise typing of `default` and `default_factory` parameters.
- Adds `typing-extensions` as a runtime dependency in `pyproject.toml`.
## Impact
- API: `field()` return type annotation changes from `Field` to the inferred field value type (via `@dataclass_transform`). Runtime behavior unchanged.
- Flags/config: New runtime dependency `typing-extensions`.
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `@dataclass_transform(field_specifiers=...)` PEP 681 protocol.
- `dataclasses._MISSING_TYPE` (semi-private but stable) for sentinel typing.
Design elements this commit produces:
- `cast(_FieldValue, ret)` pattern to satisfy mypy's `@dataclass_transform` expectations.

- Removes `# type: ignore[assignment]` from `testing.py` test classes, confirming the fix works end-to-end.
