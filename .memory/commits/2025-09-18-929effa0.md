# [DLPACK] Update dlpack conversion to enable f4 (#22)
## TL;DR
- Adds a custom `toScalarTypeForDLPackv1` function in the embedded torch C DLPack extension that maps all DLPack dtype codes (including the new `kDLFloat4_e2m1fn`) back to PyTorch `ScalarType`.
- Fixes the `getDLDataTypeForDLPackv1` export path for `Float4_e2m1fn_x2` to correctly set `lanes=2` and `bits=4`.
- Moves `tvm_ffi_python_helpers.h` install into the Python-module install block and bumps version to `0.1.0b4`.
## Impact
- API: The DLPack import path (`fromDLPackImpl`) now uses the new `toScalarTypeForDLPackv1` instead of upstream `toScalarType`, enabling round-tripping of f4/float8 types through DLPack v1.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- DLPack v1 protocol and `DLDataTypeCode` enum from `3rdparty/dlpack`
- PyTorch ScalarType definitions (torch >= 2.8 for `Float4_e2m1fn_x2`)

Design elements this commit produces:
- `toScalarTypeForDLPackv1`: complete mapping from DLPack dtype to torch ScalarType including float8 and float4 variants
## Reflection
- The approach embeds a full copy of the dtype-to-ScalarType mapping rather than patching upstream PyTorch's `toScalarType`, which keeps the extension self-contained at the cost of duplication.
