# Phase out legacy C API in favor of new FFI C API; add TVM_FFI_WEAK macro

## TL;DR
- Adds `TVM_FFI_WEAK` macro to `c_api.h` for cross-platform weak linking (`__attribute__((weak))` on GCC/Clang, `__declspec(selectany)` on MSVC).
- Fixes a stale `TVM_REGISTER_GLOBAL` reference in a doc comment in `function.h`, replacing it with the canonical `TVM_FFI_REGISTER_GLOBAL`.
- Part of the broader effort (PR #18010) to phase out the legacy `tvm/runtime/` C API and consolidate everything under the `tvm/ffi/` namespace.

## Impact
- API: The `TVM_FFI_WEAK` macro is a new public symbol in `c_api.h`. Downstream code that relied on the legacy `TVM_REGISTER_GLOBAL` macro name needs to migrate to `TVM_FFI_REGISTER_GLOBAL` (the doc comment fix here reflects that rename, though the actual macro rename happened elsewhere in the same PR).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md): `c_api.h` symbol naming convention (`TVM_FFI_` prefix for macros), visibility macros section
- [.memory/designs/0003-packed-function-and-global-registry.md](.memory/designs/0003-packed-function-and-global-registry.md): `TVM_FFI_REGISTER_GLOBAL` macro convention

Design elements this commit produces:
- `TVM_FFI_WEAK` macro: new cross-platform weak-linking facility in the C ABI header, enabling optional symbol resolution patterns (e.g., addon libraries providing default implementations that can be overridden)

## Reflection
- The `TVM_FFI_WEAK` macro follows the same platform-branching pattern as the existing `TVM_FFI_DLL` / `TVM_FFI_DLL_EXPORT` macros in `c_api.h`, keeping all platform-specific linking concerns co-located.
- The doc comment fix (`TVM_REGISTER_GLOBAL` -> `TVM_FFI_REGISTER_GLOBAL`) is a consistency cleanup; the actual macro rename was the substantive change in the broader PR, and this commit ensures documentation matches the new canonical name.
- This commit is a small slice of the larger PR #18010 migration. The two files changed (+8 lines) reflect a surgically scoped commit within a larger refactor.
