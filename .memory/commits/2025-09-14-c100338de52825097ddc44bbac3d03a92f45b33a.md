## Summary
Adds a pure C example (`add_one_c.c`) demonstrating how to implement a TVM FFI-compatible
function using only the C ABI. Also cleans up `c_api.h` by moving `DLPackTensorAllocator`
inside the `extern "C"` block and removing the `v_char32` field from `TVMFFIAny`.

## Key Changes

### Pure C Example (`examples/quick_start/src/add_one_c.c`)
- Implements `__tvm_ffi_add_one_c()` following the FFI packed function signature:
  `int(void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result)`.
- Includes `ReadDLTensorPtr()` helper showing how to extract `DLTensor*` from a
  `TVMFFIAny` value (handling both `kTVMFFIDLTensorPtr` and `kTVMFFITensor` type indices).
- Demonstrates `TVMFFIErrorSetRaisedFromCStr()` for error propagation from C.
- Shows `TVMFFIEnvGetStream()` for stream context retrieval (needed for GPU codegen).
- Serves as a reference for compiler codegen backends targeting TVM FFI.

### C ABI Cleanup (`include/tvm/ffi/c_api.h`)
- **Moved** `DLPackTensorAllocator` typedef inside `extern "C" {}` block (was above it,
  causing issues with pure C compilers).
- **Added** forward declaration `typedef struct DLManagedTensorVersioned DLManagedTensorVersioned;`
  as a temporary fix until dlpack.h is updated.
- **Removed** `v_char32` field from `TVMFFIAny` union. This field (`char32_t v_char32[2]`)
  was unused and its removal simplifies the ABI. The union still contains `v_bytes[8]` for
  small string optimization and `v_uint64` for hashing.

## Architectural Impact
- **Medium-High**: The `v_char32` removal is a breaking C ABI change (changes the union
  layout documentation, though `v_char32` overlapped with `v_bytes` in practice). The
  C example establishes a canonical pattern for compiler codegen targeting TVM FFI.

## Invariants
- `TVMFFIAny` union size remains 8 bytes (same as `int64_t`). The `v_char32` field
  was an alias over the same storage; its removal does not change the binary layout.
- The `__tvm_ffi_` prefix convention for module-exported symbols is demonstrated.
