# [FFI] Structural equal and hash based on reflection (#18156)
## TL;DR
- Introduces `StructuralEqual` and `StructuralHash` classes that traverse object fields via reflection metadata, replacing the need for per-type manual `SEqualReduce`/`SHashReduce` registrations.
- Adds `TVMFFISEqHashKind` enum to the C ABI with five comparison modes (Unsupported, TreeNode, FreeVar, DAGNode, ConstTreeNode, UniqueInstance), stored per-type in `TVMFFITypeExtraInfo.structural_eq_hash_kind`.
- Introduces `AccessPath`/`AccessStep` objects for precise mismatch diagnostics: `GetFirstMismatch` returns the exact field/index/key path where two values diverge.

## Impact
- API: New C ABI enum `TVMFFISEqHashKind` and two new field flag bits (`kTVMFFIFieldFlagBitMaskSEqHashIgnore`, `kTVMFFIFieldFlagBitMaskSEqHashDef`) in `TVMFFIFieldFlagBitMask`. New `TVM_FFI_EXTRA_CXX_API` visibility macro for non-core C++ APIs. `TVMFFITypeExtraInfo.total_size` narrowed from `int64_t` to `int32_t` with `structural_eq_hash_kind` field added. `Object` base class gains `_type_s_eq_hash_kind = kTVMFFISEqHashKindUnsupported` static constexpr.
- New C++ headers: `reflection/structural_equal.h`, `reflection/structural_hash.h`, `reflection/access_path.h`.
- New reflection trait: `AttachFieldFlag` for annotating fields with SEqHash semantics (Def region, Ignore).
- `Bytes::memncmp` moved from private to public for use by structural equal.
- Registered global functions: `ffi.reflection.GetFirstStructuralMismatch`, `ffi.reflection.StructuralHash`.
- Flags/config: none.
- Data formats/schemas: `TVMFFITypeExtraInfo` layout changed (ABI-breaking: `total_size` shrunk to `int32_t`, new `structural_eq_hash_kind` field appended).

## Design Elements
Design elements this commit consumes:
- Reflection system `ObjectDef<T>`, `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`, `FieldGetter` from [.memory/designs/0006-reflection-system.md](.memory/designs/0006-reflection-system.md)
- `TVMFFITypeExtraInfo` struct and `TVMFFIFieldInfo.flags` bitmask from the C ABI layer [.memory/designs/0005-c-abi-boundary-layer.md](.memory/designs/0005-c-abi-boundary-layer.md)
- `StableHashCombine` and `StableHashBytes` hash utilities from `ffi/base_details.h`
- Container types (Array, Map, Shape, NDArray) and their type indices for special-case comparison/hashing

Design elements this commit produces:
- `TVMFFISEqHashKind` enum: per-type metadata controlling how structural equal/hash traverses objects (tree vs DAG vs free-variable vs pointer-equality)
- `StructuralEqual` / `StructuralHash` classes: generic reflection-driven comparison and hashing
- `AccessPath` / `AccessStep` diagnostic types: structured mismatch reporting with object-field, array-index, and map-key steps
- `TVM_FFI_EXTRA_CXX_API` macro: visibility annotation for non-core C++ APIs that are only available via direct C++ linkage (not through C ABI)
- `AttachFieldFlag` reflection trait: mechanism to annotate fields with semantic flags (SEqHash Def/Ignore) at registration time
- Test object types `TVarObj`/`TFuncObj` demonstrating FreeVar and Def/Ignore field patterns

## Reflection
- This commit extends the reflection system (design 0006) from a metadata-only registry into an active computation engine. The `ForEachFieldInfo` traversal, originally designed for object construction and introspection, now drives equality comparison and hashing. This validates the design's extension point for "accessor extensions" noted in the design doc.
- The `TVMFFISEqHashKind` enum captures IR-specific semantics (tree vs DAG, free variables, def regions) that go beyond generic structural comparison. This ties the FFI reflection layer to compiler IR conventions, which is intentional for TVM but narrows the generality of the reflection system.
- The `TVM_FFI_EXTRA_CXX_API` macro establishes a new category of APIs that are "extra" -- available only through C++ linkage, not the C ABI. The comment notes potential MSVC/Itanium ABI issues. The same functionality is also exposed through reflection-based global functions (`ffi.reflection.GetFirstStructuralMismatch`, `ffi.reflection.StructuralHash`) for cross-language access.
- The `TVMFFITypeExtraInfo.total_size` field type change from `int64_t` to `int32_t` is an ABI-breaking change to make room for the new `structural_eq_hash_kind` field without growing the struct size.
- The test file `test_reflection.cc` was renamed to `test_reflection_accessor.cc` and a new `test_reflection_structural_equal_hash.cc` was added, reflecting the accessor/structural-eq split in the implementation.
