# [FFI][REFACTOR] Migrate StructuralEqual/Hash to new reflection (#18166)

## TL;DR
- Removes the `kTVMFFISEqHashKindCustomTreeNode` enum value from C ABI; custom equal/hash is now dispatched by checking `TypeAttrColumn("__s_equal__")`/`("__s_hash__")` at runtime instead of a dedicated enum kind.
- Adds NaN-safe handling in both structural equal and hash: NaN floats compare equal and hash to a canonical `quiet_NaN` representation.
- Tightens error reporting: missing metadata or unsupported eq/hash kind now throws `TypeError` instead of silently falling back to pointer comparison.

## Impact
- API: **Breaking C ABI change** -- `kTVMFFISEqHashKindCustomTreeNode` (value 6) is deleted from `TVMFFISEqHashKind` enum in `c_api.h`. Any downstream code referencing this enum value must switch to `kTVMFFISEqHashKindTreeNode` and register `__s_equal__`/`__s_hash__` via `TypeAttrColumn`. The test object `TCustomFuncObj` demonstrates the migration: `_type_s_eq_hash_kind` changes from `kTVMFFISEqHashKindCustomTreeNode` to `kTVMFFISEqHashKindTreeNode`.
- The `__s_hash__` callback signature changes: the second parameter is now `uint64_t init_hash` (the accumulator), and the callback returns the combined hash directly. Previously the caller had to manually call `StableHashCombine` around the callback result.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- Reflection system's `TypeAttrColumn` for runtime attribute lookup ([.memory/designs/0006-reflection-system.md](../designs/0006-reflection-system.md))
- `ForEachFieldInfo` / `ForEachFieldInfoWithEarlyStop` for field-level structural traversal
- `TVMFFITypeInfo::metadata->structural_eq_hash_kind` enum for dispatch

Design elements this commit produces:
- Unified dispatch model: custom eq/hash is now an overlay on top of `kTVMFFISEqHashKindTreeNode` rather than a separate enum kind. The presence of `__s_equal__`/`__s_hash__` in the `TypeAttrColumn` is the sole signal for custom dispatch.
- NaN canonicalization invariant: `StructuralHash(NaN) == StructuralHash(NaN)` and `StructuralEqual(NaN, NaN) == true` regardless of NaN bit pattern.
- Strict error semantics: types without metadata or with `kTVMFFISEqHashKindUnsupported` now throw `TypeError` instead of falling back to pointer identity.

## Reflection
- The removal of `kTVMFFISEqHashKindCustomTreeNode` simplifies the dispatch logic: instead of a three-way branch (field-based / custom-kind / pointer), there is now a two-way branch (has `TypeAttrColumn` attribute -> custom, otherwise -> field-based), checked after the pointer/unique-instance fast paths.
- The `__s_hash__` callback signature change (adding `init_hash` parameter, returning combined hash) pushes the `StableHashCombine` into the callback itself, making the custom hash protocol more composable -- callers chain hashes by passing the accumulator through rather than post-combining.
- The NaN handling is a correctness fix for the structural hash/equal contract: without it, different bit representations of NaN could produce different hashes and fail equality, violating the invariant that structurally identical IR trees must hash/compare identically.
