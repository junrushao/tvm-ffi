# Commit: 4383b1a6 — [Bugfix] Run ninja build command in MSVC dev env (#11)

- **Date**: 2025-09-14
- **Author**: Community contributor
- **Scope**: `python/tvm_ffi/cpp/load_inline.py`, `tests/python/test_load_inline.py`

## Summary
Fixes `tvm_ffi.cpp.load_inline()` on Windows by running the ninja build step inside
the Visual Studio Developer Command Prompt environment. Previously, ninja invocations
on Windows failed because MSVC compiler tools were not on PATH.

## Key Changes
- **New helper** `_run_command_in_dev_prompt(args, cwd, capture_output)` in `load_inline.py`:
  - Uses `vswhere.exe` to locate the latest Visual Studio installation.
  - Constructs the path to `VsDevCmd.bat`.
  - Chains `VsDevCmd.bat -arch=x64 & <command>` via `cmd.exe` with `shell=True`.
  - Wraps `FileNotFoundError` and `CalledProcessError` into a descriptive `RuntimeError`.
- **`_build_ninja()`**: On Windows (`IS_WINDOWS`), routes ninja through
  `_run_command_in_dev_prompt` instead of bare `subprocess.run`.
- **Tests**: Removes `@pytest.mark.xfail(sys.platform.startswith("win"), ...)` markers
  from all four `test_load_inline_cpp*` tests, enabling them on Windows CI.

## Architectural Impact
- **Medium**: Unblocks the `load_inline` workflow on Windows, which is essential for
  compiler integration scenarios. The `vswhere.exe` approach is the standard way to
  locate MSVC tools and is robust across VS versions (2017+).

## Platform Considerations
- The `VsDevCmd.bat` approach sets up the full MSVC environment (cl.exe, link.exe,
  lib paths). This is necessary because ninja itself does not locate compilers.
- `shell=True` is used intentionally for `cmd.exe` chaining on Windows.
