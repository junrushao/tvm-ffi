# [FIX] Fix device type override (#40)
## TL;DR
- Fixes `tvm_ffi.device()` to reference `core._CLASS_DEVICE` dynamically instead of importing the class at module load time, so that `_set_class_device()` overrides take effect.
- Adds tests for `_set_class_device` (custom `MyDevice` subclass) and `_set_class_tensor` (custom `MyTensor` subclass) overrides.
## Impact
- API: none (bugfix to existing override mechanism)
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `_set_class_device` / `_set_class_tensor` override pattern in `core`.
Design elements this commit produces:
- Correct late-binding pattern: `core._CLASS_DEVICE(...)` instead of captured `_CLASS_DEVICE(...)`.
## Reflection
- Classic Python import-time vs. runtime binding bug. The `from .core import _CLASS_DEVICE` captured the original class at import time, so later overrides had no effect.
