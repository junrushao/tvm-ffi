# Specialize Variant storage for all-ObjectRef type lists
## TL;DR
- When every type parameter of `Variant<V...>` derives from `ObjectRef`, the variant is now backed by `ObjectRef` (single pointer) instead of `Any` (16-byte tagged union). This halves the storage size and makes such variants directly usable wherever `ObjectRef` is expected.
- Introduces `VariantBase<bool>` template with a specialization for the all-object case (`VariantBase<true>` inherits `ObjectRef`) and a general case (`VariantBase<false>` wraps `Any`).
- Adds `all_object_ref_v<T...>` compile-time trait and `AnyUnsafe::MoveFromAnyStorageAfterCheck` helper. Fixes macro hygiene issue in `TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY`.

## Impact
- API: `Variant<T1, T2, ...>` where all `Ti` derive from `ObjectRef` now inherits from `ObjectRef`. This means it gains `ObjectRef` members (e.g., `data_`, `defined()`, `get()`) and can be passed directly to APIs expecting `ObjectRef`. The `same_as` method remains but its implementation changes. The internal `data_` member is removed in favor of the inherited storage. Code that relied on `Variant` having an `Any data_` member will break (this was private, so only friend classes and `TypeTraits` specialization are affected -- both updated in this commit).
- Flags/config: none
- Data formats/schemas: `sizeof(Variant<ObjectRef types...>)` shrinks from `sizeof(Any)` (16 bytes) to `sizeof(ObjectRef)` (8 bytes on 64-bit).

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0004-container-library.md](.memory/designs/0004-container-library.md) -- Variant section (tagged union over ObjectRef subtypes, uses type_index as discriminant)
- [.memory/designs/0001-type-erased-any-value-system.md](.memory/designs/0001-type-erased-any-value-system.md) -- AnyUnsafe helper pattern, TypeTraits framework

Design elements this commit produces:
- `VariantBase<true>` specialization pattern: when all variant members are ObjectRef, inherit ObjectRef directly and use `ObjectPtr<Object>` as backing storage. Convert to `AnyView` on-demand for type queries (`as`, `get`, `cast`).
- `all_object_ref_v<T...>` compile-time trait in `container_details.h` for checking if all types derive from ObjectRef.
- `AnyUnsafe::MoveFromAnyStorageAfterCheck<T>` helper for moving out of `Any` storage with type dispatch.

## Reflection
- The key insight is that `Variant<ObjectRef subtypes...>` does not need a full `Any` -- the object pointer already carries the type index via `Object::type_index()`, making the `Any` tag redundant. This aligns with design doc 0004's note that Variant "uses the object's type_index as the discriminant (no extra tag field needed)."
- The `ToAnyView()` method in `VariantBase<true>` manually constructs a `TVMFFIAny` from the object pointer, handling the null case (maps to `kTVMFFINone`) and the padding-clearing concern on 32-bit platforms. This is the cost of the optimization: every `as`/`get`/`cast` now creates a temporary `AnyView` instead of reading from an existing `Any`.
- The macro fix for `TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY` (adding parentheses around `result`) is a defensive hygiene fix to prevent operator-precedence surprises when the macro argument is a complex expression; this was likely caught because the new `ToAnyView()` passes `&any_data` which includes an address-of operator.
- The test name fix (`ffi::FunctionGetItem` -> `FunctionGetItem`) in `test_map.cc` is unrelated cleanup -- the `::` in the test name is invalid per GoogleTest naming rules.
- Design doc 0004 should be updated: Variant is no longer always 198 LOC / backed by Any. The section should note the ObjectRef specialization and the reduced `sizeof`.
