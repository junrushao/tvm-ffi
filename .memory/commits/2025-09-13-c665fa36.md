# [REFACTOR] Update torch to optionally depend on cuda

## TL;DR
- Guards CUDA-specific C++ code in the torch DLPack extension behind `#ifdef BUILD_WITH_CUDA` preprocessor checks (CUDAStream include, CUDA stream retrieval in `TorchDLPackFromPyObject`).
- Dynamically sets `-DBUILD_WITH_CUDA` flag and adds CUDA include paths only when `torch.cuda.is_available()` returns true.
- Rewrites `test_load_inline_with_env_tensor_allocator` test from CUDA-only to CPU-based, removing the CUDA skip requirement.

## Impact
- API: none -- the torch DLPack extension public interface is unchanged.
- Flags/config: The inline extension compile name changes from `"to_dlpack"` to `"c_dlpack"`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `tvm_ffi._optional_torch_c_dlpack` torch integration module
- `tvm_ffi.cpp.load_inline` for JIT C++ compilation

Design elements this commit produces:
- CUDA-optional torch DLPack extension: works on CPU-only machines without CUDA toolkit

## Reflection
- This enables CI to run torch interop tests on all platforms (macOS, Linux without GPU) without skipping.
- The test now validates the `env_tensor_allocator` path using CPU tensors and a simple loop instead of a CUDA kernel, which still exercises the FFI container round-trip logic.
