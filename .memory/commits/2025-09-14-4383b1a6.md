# [Bugfix] Run ninja build command in MSVC dev env (#11)
## TL;DR
- Adds `_run_command_in_dev_prompt()` which locates `vswhere.exe`, finds VS install path, and runs commands through `VsDevCmd.bat -arch=x64`
- `_build_ninja()` now dispatches to `_run_command_in_dev_prompt` on Windows instead of bare `subprocess.run`
- Removes `@pytest.mark.xfail` on all 4 Windows-marked `test_load_inline` tests
## Impact
- API: none
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `_build_ninja` function for invoking ninja builds in `load_inline.py`
- Visual Studio `vswhere.exe` discovery mechanism

Design elements this commit produces:
- `_run_command_in_dev_prompt`: reusable helper to run any command inside the MSVC Developer Command Prompt environment on Windows
## Reflection
- Without the dev prompt, MSVC compiler (`cl.exe`) and linker (`link.exe`) are not on PATH, causing ninja builds to fail on Windows
- The fix chains `VsDevCmd.bat -arch=x64 & <command>` via `cmd.exe /c` with `shell=True`
