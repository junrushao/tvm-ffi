# Commit: 0bc968d1 — chore: Basic Ruff rule coverage (#20)

- **Date**: 2025-09-17
- **Author**: Junru Shao
- **Scope**: `pyproject.toml`, across 41 files (Python source, tests, examples, lint scripts)

## Summary
Enables a comprehensive set of Ruff lint rules, expanding from minimal linting to
systematic coverage of Python code quality. Removes the legacy `black` and `isort`
configurations and replaces them with ruff equivalents.

## Key Changes

### Ruff Configuration (`pyproject.toml`)
New lint rules enabled:
- **UP**: pyupgrade (modernize Python syntax to target version 3.9+)
- **PL**: pylint (static analysis, max-args=10)
- **I**: isort (import sorting, replaces standalone isort)
- **RUF**: Ruff-specific rules
- **NPY**: numpy-specific rules
- **F**: pyflakes (unused imports, undefined names)
- **PTH**: flake8-use-pathlib (prefer `pathlib` over `os.path`)
- **D**: pydocstyle (Google-style docstrings)

Ignored rules:
- **PLR2004**: magic-value-comparison (too noisy for test code)
- **ANN401**: any-type (reserved for next commit)
- **D203/D213**: conflicting pydocstyle rules

Per-file ignores for tests: `D100`, `D101`, `D103`, `D107`, `D205` (docstring rules
relaxed in test files).

### Ruff Format Configuration
- `quote-style = "double"`, `indent-style = "space"`, `line-ending = "auto"`.
- Replaces `[tool.black]` and `[tool.isort]` sections entirely.

### Removed
- `[tool.black]` section (100-col, skip-magic-trailing-comma).
- `[tool.isort]` section (profile=black).
- `tests/lint/git-clang-format.sh` (92 lines, replaced by pre-commit clang-format hook).
- `tests/scripts/task_lint.sh` (46 lines, fully replaced by pre-commit).

### Code Fixes (to satisfy new rules)
- Docstrings added to public modules/classes/functions across `python/tvm_ffi/`.
- `os.path` calls migrated to `pathlib.Path` in `config.py`, `libinfo.py`, `lockfile.py`.
- Import ordering normalized by ruff's isort.
- Legacy Python patterns modernized (e.g., `super(Cls, self)` -> `super()`).

## Architectural Impact
- **Medium**: Establishes the Python code quality baseline for the repository. All
  future Python contributions must pass these rules. The docstring requirement (D rules)
  ensures public API documentation.
