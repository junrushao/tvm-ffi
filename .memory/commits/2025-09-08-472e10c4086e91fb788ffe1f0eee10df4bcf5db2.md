# Introduce UnsafeInit tag and tighten ObjectRef null safety
## TL;DR
- Introduces `ffi::UnsafeInit` tag struct: constructing an ObjectRef with `UnsafeInit{}` explicitly marks the initialization as unsafe (may leave `data_` null). Replaces all previous `ObjectPtr<Object>` constructors in non-nullable ref types.
- All four `TVM_FFI_DEFINE_*_OBJECT_REF_METHODS` macros updated: nullable types accept `ObjectPtr<ContainerType>` (typed, not `ObjectPtr<Object>`); non-nullable types only accept `UnsafeInit` (no public `ObjectPtr` ctor).
- All internal code paths (`ObjectRefTypeTraitsBase`, `GetRef`, `Optional::value()`, `RValueRef`, `ObjectRef::as()`) now use `ObjectUnsafe::ObjectRefFromObjectPtr<T>()` instead of `T(ObjectPtr<Object>)`.
- Adds `Shape::StridesFromShape()` static factory, makes `Shape(ObjectPtr<ShapeObj>)` private. Adds `Module(ObjectPtr<ModuleObj>)` with explicit null check.
## Impact
- API: **Breaking** for C++ code that constructs non-nullable ObjectRef subclasses from `ObjectPtr<Object>`. Such code must either use typed `ObjectPtr<ContainerType>` (for nullable types) or go through `ObjectUnsafe::ObjectRefFromObjectPtr`.
- `MakeStridesFromShape` signature changed: `(int64_t ndim, int64_t* shape)` -> `(const int64_t* data, int64_t ndim)`.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- [Object system and reference counting](/.memory/designs/0002-object-system-and-reference-counting.md): The core ObjectRef/ObjectPtr hierarchy, `_type_is_nullable`, and the four `TVM_FFI_DEFINE_*_OBJECT_REF_METHODS` macros.
- [Type-erased Any value system](/.memory/designs/0001-type-erased-any-value-system.md): `ObjectRefTypeTraitsBase` marshaling (CopyFromAnyViewAfterCheck, MoveFromAnyAfterCheck, TryCastFromAnyView).
- [Container library](/.memory/designs/0004-container-library.md): Shape, Array, Map, Tuple, Variant, Tensor, Optional all updated.
- [Module system](/.memory/designs/0009-module-system.md): Module ref gets explicit typed constructor with null check.

Design elements this commit produces:
- **`UnsafeInit` tag pattern**: A sentinel struct `ffi::UnsafeInit` that replaces implicit `ObjectPtr<Object>` constructors. The invariant is: only code that explicitly opts into `UnsafeInit{}` can create a ref with null `data_`, making null-safety violations grep-able.
- **`ObjectUnsafe::ObjectRefFromObjectPtr<T>()`**: New centralized factory that constructs any `T : ObjectRef` from an `ObjectPtr` via the `UnsafeInit` path. All internal marshaling now routes through this single function, eliminating scattered `T(ObjectPtr<Object>)` calls.
- **Typed `ObjectPtr<ContainerType>` in macros**: `TVM_FFI_DEFINE_OBJECT_REF_METHODS` and `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS` now take `ObjectPtr<ObjectName>` (the concrete container), not `ObjectPtr<Object>`. This catches type mismatches at compile time.

Decision: Replace with `UnsafeInit` tag and typed `ObjectPtr<ContainerType>`. Alternatives: runtime null checks in every constructor (overhead), removing nullable entirely (too invasive). Trade-off: Slightly more verbose internal code, but compile-time safety and grep-ability for unsafe usage.
