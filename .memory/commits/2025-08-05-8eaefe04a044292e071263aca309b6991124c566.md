# [FFI][EXTRA] Serialization To/From JSONGraph (#18187)
## TL;DR
- Adds `ToJSONGraph` and `FromJSONGraph` APIs that serialize/deserialize any `ffi::Any` value to/from a JSON object graph format, preserving object identity (shared references serialized once and indexed).
- Adds a header-only base64 encode/decode utility (`extra/base64.h`) used for `Bytes` serialization.
- Comprehensive GoogleTest suite (354 lines) covering all primitive types, containers, custom object serialization via `__data_to_json__`/`__data_from_json__`, metadata attachment, and node order independence.

## Impact
- API: Two new public C++ functions (`ToJSONGraph`, `FromJSONGraph`) exported via `TVM_FFI_EXTRA_CXX_API`. Two new global functions registered (`ffi.ToJSONGraph`, `ffi.FromJSONGraph`). Two new `TypeAttrColumn` names (`__data_to_json__`, `__data_from_json__`) for custom per-type serialization hooks.
- Flags/config: none (reuses existing `TVM_FFI_USE_EXTRA_CXX_API` CMake gate).
- Data formats/schemas: Introduces the JSON object graph format: `{"root_index": <int>, "nodes": [{"type": "<key>", "data": ...}, ...], "metadata": ...}`. For objects with reflection metadata, fields with statically-known primitive types (bool, int, float, DataType) are inlined; all other fields are stored as node indices. Bytes are base64-encoded.

## Design Elements
Design elements this commit consumes:
- [.memory/designs/0007-structural-equal-hash-system.md](.memory/designs/0007-structural-equal-hash-system.md) -- reuses `TypeAttrColumn` pattern for custom dispatch (`__data_to_json__`/`__data_from_json__` mirrors `__s_equal__`/`__s_hash__`), and `reflection::ForEachFieldInfo` for field traversal.
- [.memory/ADRs/0009-extra-api-isolation.md](.memory/ADRs/0009-extra-api-isolation.md) -- serialization placed in `extra/` directory, gated by `TVM_FFI_USE_EXTRA_CXX_API`, following the established pattern.

Design elements this commit produces:
- JSON object graph format specification (documented in `serialization.h` Doxygen). This is a new data contract for round-trippable serialization of the FFI object system.
- `__data_to_json__` / `__data_from_json__` TypeAttrColumn convention for custom serialization hooks (demonstrated in `testing_object.h` for `TIntObj`).
- `Base64Encode`/`Base64Decode` utilities available for reuse.

## Reflection
- The serializer (`ObjectGraphSerializer`) uses `Map<Any, int64_t>` to deduplicate nodes, meaning shared object references are serialized once. The deserializer (`ObjectGraphDeserializer`) lazily decodes nodes, allowing forward references (tested by `ShuffleNodeOrder`).
- The static type index optimization (inlining primitive field values directly instead of referencing node indices) mirrors the same optimization in the structural equal/hash system, where statically-known primitives bypass the generic dispatch path.
- Testing objects (`TVarObj`, `TFuncObj`) gained default constructors to support deserialization via `TVMFFITypeMetadata::creator`. `TFuncObj::comment` changed from `String` to `Optional<String>` to support null round-tripping. These are test-only changes that do not affect the public API.
- The `json.h` file change is a trivial doc comment fix (`tvm/ffi/json/json.h` -> `tvm/ffi/extra/json.h`).
