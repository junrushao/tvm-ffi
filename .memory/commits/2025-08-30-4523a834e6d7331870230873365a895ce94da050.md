# [FFI][DOCS] Wheel Packaging (#18256)
## TL;DR
- Adds a complete `examples/packaging/` project demonstrating how to build an ABI-agnostic wheel for a tvm-ffi extension with scikit-build-core (CMakeLists, pyproject.toml, Python package with `_LIB`/`_ffi_api` pattern)
- Fixes cmake install paths: `cmake/Utils/` trailing slash, `tvm_ffi-config.cmake` destination changed from `lib/cmake/tvm_ffi/` to `cmake/`, and `find_cmake_path` updated to match
- Adds `include(Utils/Library.cmake)` to `tvm_ffi-config.cmake` so downstream projects get `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil`
- Defers `torch_get_current_cuda_stream` initialization to first CUDA tensor encounter instead of module import time
- Bumps version to `0.1.0a5`

## Impact
- API: none (additive example only)
- Flags/config: cmake install directory layout changed for the Python wheel (`cmake/` instead of `lib/cmake/tvm_ffi/`)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- scikit-build-core build pipeline
- `tvm_ffi.load_module` for loading shared libraries
- `tvm_ffi._init_api` for bulk FFI function registration by prefix

Design elements this commit produces:
- Reference packaging example at `examples/packaging/` showing the canonical pattern for tvm-ffi extension wheels
- Lazy `torch_get_current_cuda_stream` initialization pattern (set to `None`, loaded on first CUDA tensor)
- `tvm_ffi-config.cmake` now exposes utility CMake functions (`Library.cmake`) to downstream consumers

## Reflection
- The packaging example demonstrates two build modes: from-source (good for cross-compilation) and pre-built (linking against pip-installed tvm_ffi)
- Lazy torch stream initialization avoids import-time JIT compilation overhead and failures when CUDA is not available
- The cmake path restructuring (`cmake/` instead of `lib/cmake/tvm_ffi/`) simplifies the wheel layout
