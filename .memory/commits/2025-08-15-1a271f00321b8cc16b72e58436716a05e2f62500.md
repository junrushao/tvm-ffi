# [FFI] Make JSON Parser/Write fastmath safe (#18212)
## TL;DR
- Replaces `std::numeric_limits<double>::infinity()`, `std::numeric_limits<double>::quiet_NaN()`, `std::isnan()`, and `std::isinf()` in the JSON parser/writer with bit-level IEEE 754 implementations under `__FAST_MATH__`.
- Adds three static helpers (`FastMathSafePosInf`, `FastMathSafeNegInf`, `FastMathSafeNaN`) to `JSONParserContext` and two (`FastMathSafeIsNaN`, `FastMathSafeIsInf`) to `JSONWriter`.
- Updates test assertions to use the same bit-level helpers so tests pass under `-ffast-math`.

## Impact
- API: none. The JSON parse/write functions (`json::Parse`, `json::Write`) retain identical signatures and behavior.
- Flags/config: no new build flags. The `#ifdef __FAST_MATH__` guard activates only when the compiler defines that macro (e.g., `-ffast-math`, `-Ofast`).
- Data formats/schemas: none. JSON wire format unchanged.

## Design Elements
Design elements this commit consumes:
- ADR-0009 extra/ directory isolation: both modified source files reside in `src/ffi/extra/`, consistent with the extra API layering established in [.memory/ADRs/0009-extra-api-isolation.md](.memory/ADRs/0009-extra-api-isolation.md).

Design elements this commit produces:
- Pattern: bit-level IEEE 754 double helpers gated by `__FAST_MATH__`. The pattern (`reinterpret_cast<const double*>(&bits)` for construction, exponent/mantissa extraction for classification) can be reused wherever NaN/Inf handling is needed under fast-math.

## Reflection
- The helpers are duplicated across three files (parser, writer, test). A shared header could deduplicate them, but the scope is small and each copy is a private static method, so the duplication is reasonable for now.
- The `__FAST_MATH__` guard is compiler-specific (GCC/Clang). MSVC uses `/fp:fast` which does not define `__FAST_MATH__`, so the fallback `std::isnan`/`std::isinf` path is used there. This is correct because MSVC's `/fp:fast` does not eliminate NaN/Inf comparisons as aggressively as GCC/Clang's `-ffast-math`.
