# [FFI] Support inline module (#18271)
## TL;DR
- Adds `tvm_ffi.cpp.load_inline()` that compiles C++/CUDA source code into a shared library and loads it as a TVM FFI `Module`, using ninja for builds and content-hash-based caching in `~/.cache/tvm-ffi`.
- Introduces `tvm_ffi.utils.FileLock` -- a cross-platform (Unix/Windows) file locking utility for build cache concurrency safety.
- Includes tests and an example (`examples/inline_module/main.py`) demonstrating CPU and CUDA inline module compilation.
## Impact
- API: New public function `tvm_ffi.cpp.load_inline(name, cpp_source, cuda_source, cpp_functions, cuda_functions, ...)` returning a `Module`. New utility `tvm_ffi.utils.FileLock`.
- Flags/config: `TVM_FFI_CACHE_DIR` env var controls cache location (default `~/.cache/tvm-ffi`). `TVM_FFI_CUDA_ARCH_LIST` env var controls CUDA target architectures. `MAX_JOBS` env var controls ninja parallelism.
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `tvm_ffi.module.Module` and `load_module()` for dynamic library loading
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro for C symbol export
- `find_include_path()` and `find_dlpack_include_path()` from `tvm_ffi.libinfo`
Design elements this commit produces:
- `load_inline()` -- JIT compilation pipeline: source hashing -> ninja build file generation -> compilation -> module loading
- `FileLock` -- advisory file lock for safe concurrent builds
- `_decorate_with_tvm_ffi()` -- auto-wraps user source with FFI headers and export macros
## Reflection
- The design parallels PyTorch's `torch.utils.cpp_extension.load_inline` but targets the TVM FFI ABI instead. The content-hash-based caching avoids recompilation when sources have not changed.
- The ninja build generator handles both C++ and CUDA compilation with platform-specific flags for Linux/macOS/Windows.
