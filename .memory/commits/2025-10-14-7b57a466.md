# fix: Add schema support for `ObjectRef::MemFn` (#113)
## TL;DR
- Adds `FunctionInfo` template specializations for member function pointers on `ObjectRef`-derived types, passing `Class` by value (not pointer) since ObjectRef types are lightweight handles.
- Distinguishes `Object`-derived classes (pass by pointer) from `ObjectRef`-derived classes (pass by value) using `std::is_base_of_v` SFINAE.
- Fixes downstream compilation errors when registering `ObjectRef` member functions as global functions.
## Impact
- API: Fixes a compilation failure for downstream users; non-breaking for existing callers.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `FunctionInfo` / `FuncFunctorImpl` template machinery for type-erased function metadata
Design elements this commit produces:
- `FunctionInfo<R (Class::*)(Args...), enable_if ObjectRef>` specializations
## Reflection
- Subtle but important: `ObjectRef` member functions receive `this` by value (it is a handle), while `Object` member functions receive `this` by pointer. The SFINAE dispatch ensures correct calling convention.
