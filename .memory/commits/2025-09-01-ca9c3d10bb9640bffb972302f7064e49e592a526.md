# [FFI][ABI] Introduce weak rc support (#18259)
## TL;DR
- Adds weak reference counter (u32) alongside the existing strong reference counter (now u64) to the `TVMFFIObject` header, keeping header size at 24 bytes.
- Introduces `WeakObjectPtr<T>` smart pointer with `lock()` / `TryPromoteWeakPtr()` CAS-based promotion, mirroring `std::weak_ptr` semantics.
- Changes the deleter signature from `void(*)(TVMFFIObject*)` to `void(*)(TVMFFIObject*, int flags)` using a bitmask (`kTVMFFIObjectDeleterFlagBitMaskStrong`, `Weak`, `Both`) to separate destruction from memory deallocation.
## Impact
- API: **Breaking ABI change.** `TVMFFIObjectFree` renamed to `TVMFFIObjectDecRef`; new `TVMFFIObjectIncRef` added. Deleter function pointer signature gains an `int flags` parameter. All allocators (`SimpleObjAllocator`) updated. `ref_counter` (int32) split into `strong_ref_count` (uint64) + `weak_ref_count` (uint32).
- Flags/config: none
- Data formats/schemas: Object header layout changed (type_index i32 + weak_ref_count u32 + strong_ref_count u64 + deleter ptr = 24 bytes).
## Design Elements
Design elements this commit consumes:
- Object system with ref-counted header (`TVMFFIObject`, `ObjectPtr<T>`)
- `SimpleObjAllocator` memory management pattern
Design elements this commit produces:
- `WeakObjectPtr<T>` -- weak pointer with `lock()` returning `ObjectPtr<T>`
- Split deleter protocol: destruction vs memory-free via flag bitmask
- `TVMFFIObjectDeleterFlagBitMask` C enum for deleter behavior control
## Reflection
- The design mirrors `std::shared_ptr`/`std::weak_ptr` and Rust `Arc`/`Weak` semantics. The choice of u32 for weak_ref_count (vs u64 for strong) is a deliberate space trade-off since weak refs are rarely used.
- The common-case optimization in `DecRef` checks weak_ref_count==1 to call the deleter once with `Both` flag, avoiding two separate calls in the typical no-weak-ref scenario.
- CAS loop in `TryPromoteWeakPtr` is required for thread safety when promoting weak to strong.
