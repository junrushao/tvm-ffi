# fix: Type mismatch aborts on OpaquePyObject (#56)
## TL;DR
- Registered `TypeIndex::kTVMFFIOpaquePyObject` as a builtin type index so that `TVMFFIGetTypeInfo` does not abort with `exit(1)` when an `OpaquePyObject` triggers a type mismatch error.
- Added `testing.add_one` global function and a regression test that passes an `OpaquePyObject` where an `int` is expected.
## Impact
- API: none
- Flags/config: none
- Data formats/schemas: none (new builtin type index reservation is internal)
