# [FFI] Robustify the pyproject setup (#18233)
## TL;DR
- Makes numpy an optional import in `dtype.py` so the package can install without numpy present
- Configures RPATH on the Cython extension so it finds `libtvm_ffi_shared` at `lib/` relative path
- Overhauls `cibuildwheel` config: builds cp39-cp312, skips musllinux, tests only on cp312 (abi3), runs pytest correctly
- Bumps version to `0.1.0a2`; defers `torch.utils.cpp_extension` import to first use; softens error test assertions for missing debug symbols

## Impact
- API: none
- Flags/config: `cibuildwheel` build/skip/test-skip lists changed; `test-command` now points to `{package}/tests/python`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- scikit-build-core wheel build pipeline
- Cython extension module linking against `tvm_ffi_shared`

Design elements this commit produces:
- RPATH setup pattern (`@loader_path/lib` on macOS, `$ORIGIN/lib` on Linux) for Cython extension
- numpy-optional `dtype.py` (guarded import with try/except)
- abi3-focused cibuildwheel configuration (build cp39-cp312, test only cp312)

## Reflection
- The numpy guard is important for minimal wheel installs where users may not need tensor operations
- Lazy-loading `torch.utils.cpp_extension` avoids import-time failures when torch is installed but CUDA toolchain is absent
- The test_error change from `@pytest.mark.xfail` to inline `try/except pytest.xfail` gives more granular control: only the symbol-dependent assertions are skipped
