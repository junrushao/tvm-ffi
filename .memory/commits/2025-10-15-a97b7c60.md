# [TEST] Fix the tensor loading order in test (#128)
## TL;DR
- Documents the hazard: when a dynamically-loaded module returns an object, the object's deleter resides in the library; if the module is unloaded before the object is destroyed, the deleter calls an invalid address.
- Fixes affected test cases by wrapping object usage in nested functions that complete before the module goes out of scope.
- Adds a detailed docstring/warning to `Module` class about this lifetime concern.
## Impact
- API: Adds documentation warning to `Module` class (no runtime behavior change).
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes: none
Design elements this commit produces:
- Documented pattern for safe module lifetime management (nested function pattern)
## Reflection
- Classic dynamic library lifetime issue. The fix is test-level (wrapping in nested functions) rather than architectural, but the documentation is valuable for downstream users.
