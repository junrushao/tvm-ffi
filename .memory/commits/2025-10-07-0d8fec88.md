# feat: Address warnings from clang-tidy (#78)
## TL;DR
- Adds `.clang-tidy` config enabling `modernize-*`, `bugprone-*`, `performance-*`, `portability-*`, `google-*` checks with selected exclusions
- Applies modernization fixes: `_v`/`_t` type trait suffixes, `using` instead of `typedef`, `std::move` in captures/constructors, `= default` for trivial constructors
- Adds `noexcept` to move constructors/assignment operators in `AnyView` and `Any`
- Fixes `AnyUnsafe::MoveTVMFFIAnyToAny` to take pointer instead of rvalue ref (avoids dangling reference)
- Adds `tests/lint/clang_tidy_precommit.py` script for manual clang-tidy invocation
- Adds `names.reserve()` call in `Function::ListGlobalNames()`

## Impact
- API: `AnyUnsafe::MoveTVMFFIAnyToAny` signature changed from `TVMFFIAny&&` to `TVMFFIAny*` (internal API). Move ops on `Any`/`AnyView` now `noexcept`.
- Flags/config: New `.clang-tidy` config file
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none
Design elements this commit produces:
- `.clang-tidy` configuration and `clang_tidy_precommit.py` runner script
- Pattern: `noexcept` on move constructors/assignment across core value types

## Reflection
- clang-tidy is NOT added to CI in this PR, only available for manual invocation
- The `MoveTVMFFIAnyToAny` signature change from rvalue-ref to pointer is a correctness fix to prevent use-after-move on the `TVMFFIAny` struct
- Large changeset (60+ files) but mostly mechanical modernization
