# [ABI] Further clarify Function ABI in cpp (#71)
## TL;DR
- Added `void* cpp_call` field to `TVMFFIFunctionCell` C ABI struct alongside `safe_call`. When set, it provides a direct C++ call path (with exception propagation) avoiding the safe_call overhead.
- `FunctionObj::CallPacked` now uses `cpp_call` when available, falling back to `CppCallDedirectToSafeCall` wrapper when `cpp_call` is null.
- Removed `ImportedFunctionObjImpl` and `RedirectCallToSafeCall` CRTP base. External C functions use `ExternCFunctionObjImpl` (with handle) or new `ExternCFunctionObjNullHandleImpl` (without handle).
- Removed `Function::ImportFromExternDLL` (was used to wrap functions from other DLLs).
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` signature corrected to `const TVMFFIAny* args`.
- Version bumped to 0.1.0b12.
## Impact
- API: ABI-breaking change to `TVMFFIFunctionCell` (new `cpp_call` field). `Function::ImportFromExternDLL` removed. `FunctionObj::call` field removed (replaced by `cpp_call`).
- Flags/config: none
- Data formats/schemas: `TVMFFIFunctionCell` gains `void* cpp_call` member.
## Design Elements
Design elements this commit consumes:
- `TVMFFISafeCallType` C calling convention
- `FunctionObjImpl` template pattern

Design elements this commit produces:
- Dual-path call convention: `cpp_call` (fast, C++ exceptions) vs `safe_call` (C ABI safe)
- `ExternCFunctionObjNullHandleImpl` for raw function pointers without closure
## Reflection
- The removal of `ImportFromExternDLL` and `RedirectCallToSafeCall` simplifies the function hierarchy significantly. The `cpp_call`/`safe_call` split is cleaner than the previous inheritance-based approach.
