# feat: Support `field(init=...)` in `@c_class` fields (#52)
## TL;DR
- Adds `init` parameter to `field()`, allowing fields to be excluded from the generated `__init__` signature while still being forwarded to C++ `__ffi_init__` (with a default) or left to C++ to initialize.
- Rewrites `method_init` from `inspect.Signature`/`bind_args` approach to code-generation via `exec`, matching the pattern used by `dataclasses` and `pydantic` for better performance and cleaner signatures.
- Adds C++ test class `TestCxxInitSubsetObj` where only `required_field` is an init param; `optional_field` and `note` are non-init fields with defaults.

## Impact
- API: `field(init=False)` is a new public feature. The generated `__init__` signature changes from `inspect.Signature`-based to `exec`-generated, which should be transparent to callers but changes introspection details.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `dataclasses.MISSING` sentinel for default detection
- `exec`-based function generation pattern (as in stdlib `dataclasses`)

Design elements this commit produces:
- `field(init=False)` semantics: if a default_factory is provided, its value is forwarded to `__ffi_init__`; if not, the field is omitted from the FFI call entirely
- Code-generated `__init__` with proper signature, replacing the `inspect.Signature.bind` approach
- C++ test fixture `testing.TestCxxInitSubset` for testing partial-init patterns

## Reflection
- The `exec`-based `__init__` generation is a significant rewrite of `_utils.py`, replacing ~80 lines of `inspect.Signature` machinery with ~50 lines of code generation. This is both faster (no `bind`/`apply_defaults` overhead per call) and produces better signatures for IDE introspection.
- The `init=False` with `default_factory` pattern allows Python-side defaults for fields that C++ expects but Python users should not set directly.
- Also exports `tvm_ffi.dataclasses` in `__init__.py` and restructures Sphinx docs for the utility section.
