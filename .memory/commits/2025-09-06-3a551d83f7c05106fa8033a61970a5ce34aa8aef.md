# [FFI][REFACTOR][ABI] Rename NDArray to Tensor (#18275)
## TL;DR
- Renamed `NDArray` to `Tensor` across C API (`kTVMFFINDArray` -> `kTVMFFITensor`, `TVMFFINDArray*` -> `TVMFFITensor*`), C++ headers (`ndarray.h` -> `tensor.h`), and Python (`NDArray` -> `Tensor`).
- Updated static type key from `"ffi.NDArray"` to `"ffi.Tensor"`.
- Simplified `Module` class: removed `__new__` / `entry_func` property, `__call__` now delegates to `self.main`.
## Impact
- API: ABI-breaking rename across all language layers. `NDArray` symbol removed from Python `__init__`, replaced by `Tensor`. C API functions like `TVMFFINDArrayFromDLPack` become `TVMFFITensorFromDLPack`.
- Flags/config: none
- Data formats/schemas: type key string changes from `"ffi.NDArray"` to `"ffi.Tensor"`
## Design Elements
Design elements this commit consumes:
- Object system type index enum in `c_api.h`
- `StaticTypeKey` constants in `object.h`
- Cython binding layer (`base.pxi`, `function.pxi`, `ndarray.pxi`)
Design elements this commit produces:
- `Tensor` as the canonical name for the DLPack-backed tensor type throughout the FFI
- Simplified `Module.__call__` that delegates to `self.main` (dynamic attribute lookup via `__getattr__`)
## Reflection
- `Tensor` is a more universally understood name than `NDArray` and aligns with DLPack and PyTorch terminology.
- The `Module` simplification removes the `_entry` caching pattern in favor of dynamic lookup, which is cleaner but may have minor perf implications for hot-path module calls.
- Cython also gains a `TVM_FFI_BUILD_DOCS` env guard around `import torch` to avoid doc build failures.
