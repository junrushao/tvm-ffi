# [REFACTOR][ABI] Update backtrace storage for append-friendly (#39)
## TL;DR
- Renames `traceback` to `backtrace` throughout C ABI (`TVMFFIErrorCell`), C++ (`Error`, `ErrorBuilder`), Cython, and Python layers. Renames source files `traceback.cc` -> `backtrace.cc`, `traceback.h` -> `backtrace_utils.h`.
- Adds `TVMFFIBacktraceUpdateMode` enum with `Replace` and `Append` modes. The `update_backtrace` callback now takes an `int32_t update_mode` parameter.
- Backtrace storage order is now "most recent call first" (reverse of Python convention), making it append-friendly as errors propagate up the stack. A new `TracebackMostRecentCallLast()` method reverses lines for display.
- `TVMFFIErrorCreate` now returns `int` error code + output handle instead of returning the handle directly, improving memory-error safety.
## Impact
- API: **ABI-breaking change**. `TVMFFIErrorCell.traceback` -> `.backtrace`, `update_traceback` -> `update_backtrace(self, backtrace, update_mode)`, `TVMFFITraceback` -> `TVMFFIBacktrace`, `TVMFFIErrorCreate` signature changed.
- Python: `Error.traceback` property -> `Error.backtrace`. Internal helpers renamed (`_WITH_APPEND_TRACEBACK` -> `_WITH_APPEND_BACKTRACE`, `_TRACEBACK_TO_STR` -> `_TRACEBACK_TO_BACKTRACE_STR`).
- Flags/config: none
- Data formats/schemas: Backtrace string storage order reversed (recent-first).
## Design Elements
Design elements this commit consumes:
- Existing error propagation path through `set_last_ffi_error` in Cython and `_convert_to_ffi_error`.
Design elements this commit produces:
- Append-friendly backtrace convention: each boundary appends its frames to the end, then display reverses for Pythonic "most recent call last" output.
- `TracebackMostRecentCallLast()` C++ method for reversing stored backtrace lines.
## Reflection
- The rename from "traceback" (Python-specific term) to "backtrace" (language-neutral) aligns with the cross-language nature of the ABI.
- Append mode avoids expensive string concatenation at each FFI boundary by simply appending new frames.
