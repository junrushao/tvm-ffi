# [CYTHON] Fix potential flaky issue in dispatcher (#63)
## TL;DR
- Added `_DISPATCH_TYPE_KEEP_ALIVE` set (with a threading lock) to prevent garbage collection of Python types registered in the C++ dispatcher, avoiding a use-after-free race where a new type could reuse the memory address of a GC'd type and get the wrong dispatch function.
## Impact
- API: none
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetterFactory_` C++ dispatcher dispatch-by-type-pointer mechanism

Design elements this commit produces:
- `_DISPATCH_TYPE_KEEP_ALIVE` pattern for preventing type GC in dispatcher
## Reflection
- The number of distinct types registered through the dispatcher is expected to be small in practice, so keeping them alive indefinitely is acceptable.
- The lock is forward-looking for free-threaded Python.
