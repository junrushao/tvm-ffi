# [FFI][REFACTOR] Refactor python ffi call mechanism for perf (#18302)
## TL;DR
- Introduces a new C-level helper layer (`tvm_ffi_python_helpers.h`, 447 lines) that moves Python-to-FFI argument conversion into C, bypassing per-argument Cython overhead.
- Adds `TVMFFIPyFuncCall` / `TVMFFIPyCallFieldSetter` / `TVMFFIPyPyObjectToFFIAny` entry points with a pluggable `TVMFFIPyArgSetterFactory` dispatch, plus predefined setters for int/float/bool/None.
- Refactors `function.pxi` (344 added / 194 removed) to route packed-function calls through the new C helpers, and adds a `__dlpack_c_exporter__` fast-path for DLPack tensor conversion that avoids Python capsule round-trips.
## Impact
- API: The Python-visible `from_dlpack` signature is unchanged, but internal Cython calling convention is restructured; downstream Cython code that directly called old internal helpers would break.
- Flags/config: none
- Data formats/schemas: `TensorObj` now caches a `DLManagedTensorVersioned*` (atomic pointer) to avoid repeated allocation on `ToDLPackVersioned`, with proper destructor cleanup.
## Design Elements
Design elements this commit consumes:
- Packed-function calling convention (`(AnyView* args, int num_args, Any* rv)`)
- DLPack v1/v1.1 capsule protocol
Design elements this commit produces:
- `TVMFFIPyArgSetter` / `TVMFFIPyArgSetterFactory` dispatch table pattern for fast Python-to-C type conversion
- `__dlpack_c_exporter__` protocol on Python objects for zero-copy DLPack export without PyCapsule
- Cached `DLManagedTensorVersioned` inside `TensorObj` (atomic, thread-safe)
## Reflection
- The bulk of the performance win comes from batching argument conversion in a single C call (`TVMFFIPyFuncCall`) instead of N individual Cython type-switch calls.
- The cached `DLManagedTensorVersioned` adds an `std::atomic` to every `TensorObj`; acceptable trade-off for hot-path DLPack export.
