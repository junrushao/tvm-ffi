# chore: Enforce type annotation on public APIs (#21)
## TL;DR
- Uncommented `"ANN"` (flake8-annotations) in `[tool.ruff.lint]` select, enforcing type annotations on all public function signatures.
- Added return-type annotations (`-> None`, `-> str`, `-> bool`, `-> int`, `-> Any`, etc.) and parameter-type annotations across all public API methods in container.py, error.py, module.py, registry.py, stream.py, testing.py, lockfile.py.
- Updated `__enter__` methods to return `self` with proper type, `__exit__` to return `None`, context managers to declare `NoReturn` for the Torch-unavailable fallback.
- Added `Iterator`, `Callable`, `Optional`, `NoReturn` imports where needed; used `int | slice`, `Any | None` union syntax.
## Impact
- API: no runtime behavior change; all additions are type annotations only. Static type checkers and IDE autocomplete will now see accurate signatures.
- Flags/config: `"ANN"` rule now enforced in ruff; missing annotations on public functions will fail lint.
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- Ruff rule infrastructure from commits 64e4b7f and 0bc968d
Design elements this commit produces:
- Fully type-annotated public Python API surface
## Reflection
- This is the final step in the 3-commit lint modernization series (64e4b7f -> 0bc968d -> 8f4e044).
- The `ANN401` (any-type) rule is explicitly ignored, allowing `Any` in signatures where FFI type erasure makes it necessary.
- `__enter__` methods now correctly return `self`, which was missing before -- a minor correctness improvement beyond just annotations.
