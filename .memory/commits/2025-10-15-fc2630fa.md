# feat: Add a method to define initializer (#127)
## TL;DR
- Introduces `ObjectDef::def(init<Args...>())` for registering constructors, replacing the previous `def_static("__ffi_init__", refl::init<T, Args...>)` pattern.
- Changes `refl::init` from a free function template to a `struct init<Args...>` with a private `execute<Class>` static method, where `Class` is deduced from the `ObjectDef` context.
- Updates docs, tests, and testing code to use the new syntax.
## Impact
- API: Breaking C++ API -- `refl::init<T, Args...>` (free function) replaced by `refl::init<Args...>` (struct). `def_static("__ffi_init__", ...)` replaced by `def(refl::init<Args...>())`.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- `ObjectDef` reflection registration machinery
Design elements this commit produces:
- `refl::init<Args...>` struct and `ObjectDef::def(init<Args...>)` method -- aligns with nanobind/pybind11 constructor syntax
- Internal constant `INIT_METHOD_NAME = "__ffi_init__"`
## Reflection
- Significant API improvement: the object type is now deduced from `ObjectDef<T>` context instead of being redundantly specified in `init<T, ...>`. This aligns with the pybind11/nanobind convention and is less error-prone.
