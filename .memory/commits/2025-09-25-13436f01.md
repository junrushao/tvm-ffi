# [FFI][ABI] TVMFFIObject ABI to further align with torch intrusive_ptr (#57)
## TL;DR
- Changed `TVMFFIObject` ABI layout: `strong_ref_count` (u32) and `weak_ref_count` (u32) are now first, followed by `type_index` and `__padding`. Previously `type_index` was first.
- Ref counts narrowed from `uint64_t` strong to `uint32_t` strong + `uint32_t` weak packed into the first 8 bytes.
- Removed `test_c_ffi_abi.cc` which asserted the old layout (type_index first, shared with TVMFFIAny).
## Impact
- API: ABI-breaking change to `TVMFFIObject` header layout. All compiled C++/Cython code must be recompiled.
- Flags/config: none
- Data formats/schemas: `TVMFFIObject` struct layout changed from `{type_index, weak_ref_count, strong_ref_count}` to `{strong_ref_count, weak_ref_count, type_index, __padding}`.
## Design Elements
Design elements this commit consumes:
- TVMFFIObject 24-byte header design

Design elements this commit produces:
- Ref-count-first object header layout (aligned with torch `intrusive_ptr`)
- Opens path for combined u64 atomic optimization in a follow-up
## Reflection
- This is a preparatory ABI change; the combined u64 atomic optimization follows in #58 (43d13e8).
- The old test asserting `TVMFFIObject.type_index` shares offset with `TVMFFIAny.type_index` was correctly removed since that invariant no longer holds.
