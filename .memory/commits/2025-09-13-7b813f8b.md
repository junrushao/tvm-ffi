# [FFI][REFACTOR] Update TVM_FFI_STATIC_INIT_BLOCK to fn style
## TL;DR
- Replaces the lambda-based `TVM_FFI_STATIC_INIT_BLOCK(Body)` macro with a function-style `TVM_FFI_STATIC_INIT_BLOCK() { ... }` syntax.
- On GCC/Clang, the new macro uses `__attribute__((constructor))` for reliable static initialization ordering. On other compilers, falls back to the previous `static inline int` variable-initializer pattern but now wraps a named function.
- All 15+ usage sites across `src/ffi/`, `tests/cpp/`, `examples/`, and `docs/` are updated from `TVM_FFI_STATIC_INIT_BLOCK({ ... });` to `TVM_FFI_STATIC_INIT_BLOCK() { ... }`.
- Removes the `TVM_FFI_ATTRIBUTE_UNUSED` macro (replaced by `[[maybe_unused]]` directly).
## Impact
- API: `TVM_FFI_STATIC_INIT_BLOCK` macro signature changed; all downstream C++ code using it must update. `TVM_FFI_ATTRIBUTE_UNUSED` removed.
- Flags/config: none
- Data formats/schemas: none
## Design Elements
Design elements this commit consumes:
- Static initialization pattern for function/type registration
Design elements this commit produces:
- `__attribute__((constructor))`-based static init on GCC/Clang for more predictable init ordering
## Reflection
- The `__attribute__((constructor))` approach avoids the static initialization order fiasco that can occur with the variable-initializer pattern across translation units.
- The function-style braces (`{ ... }`) read more naturally than the old lambda-in-macro pattern and allow standard debugger breakpoints inside the init block.
