# fix: Cython Memory Corruption Reported by ASan (#55)
## TL;DR
- Fixes a use-after-free bug in `_type_info_create_from_type_key`: the `ByteArrayArg` temporary was being destroyed before `TVMFFITypeKeyToIndex` could read its pointer.
- Assigns the `ByteArrayArg` to a named `cdef` local variable (`type_key_arg`) so its lifetime extends through the C API call.

## Impact
- API: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes: none

Design elements this commit produces:
- Bug pattern: In Cython, `SomeType(expr).method()` creates a temporary that may be freed before the C call completes. Always assign to a named `cdef` variable to control lifetime.

## Reflection
- This is a subtle Cython lifetime bug: `ByteArrayArg(c_str(type_key)).cptr()` creates a temporary `ByteArrayArg` whose destructor can fire before the C function reads the pointer. ASan caught it.
- The fix is 2 lines but prevents memory corruption. This pattern should be watched for in all Cython code that passes pointers from temporary wrapper objects to C APIs.
