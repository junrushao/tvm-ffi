# daeb235 — feat: Support `field(init=...)` in `@c_class` fields (#52)

## TL;DR
- `field(init=False)` now excludes a field from the generated `__init__` signature while still forwarding its default value to the C++ constructor
- The `__init__` generator in `_utils.py` is rewritten using `exec`-based code generation (replacing `inspect.Signature` approach) for clearer control flow
- Adds `_TestCxxInitSubset` test class with C++ counterpart `TestCxxInitSubsetObj` demonstrating the feature
- `tvm_ffi.dataclasses` is now exported from `tvm_ffi.__init__`

## Why (intent / motivation)
- Some C++ constructors take a subset of the fields as arguments; Python `__init__` should not expose the remaining fields to callers
- Aligns with Python's `dataclasses.field(init=False)` semantics

## What changed (facts from diff)
- `python/tvm_ffi/dataclasses/field.py`: `Field` gains an `init: bool = True` slot; `field()` accepts `init` parameter; validated as `bool`
- `python/tvm_ffi/dataclasses/_utils.py`: `method_init` rewritten to use `exec`-generated source code; separates init vs non-init fields; non-init fields with defaults are still forwarded to `__ffi_init__`
- `python/tvm_ffi/__init__.py`: `dataclasses` module exported in `__all__`
- `src/ffi/extra/testing.cc`: `TestCxxInitSubsetObj` class registered with `required_field`, `optional_field`, `note`
- `python/tvm_ffi/testing.py`: `_TestCxxInitSubset` proxy class added
- `tests/python/test_dataclasses_c_class.py`: three new tests: signature check, default values, positional arg
- `docs/reference/python/cpp/index.rst` deleted; replaced by inline `autosummary` directive in `docs/reference/python/index.rst`
