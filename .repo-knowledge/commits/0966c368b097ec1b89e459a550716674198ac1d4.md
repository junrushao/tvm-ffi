# 0966c36 — [REFACTOR] Formalize namespace for all objects (#18101)

## TL;DR
- Changes `_type_key` strings for built-in object types from informal `"object.X"` to canonical `StaticTypeKey::kTVMFFIX` constants.
- Renames `ErrorObj::_type_key` from `"object.Error"` to `"ffi.Error"` to place it in the `ffi` namespace.
- Updates `Object` static type metadata (`_type_index`, `_type_key`) to use `StaticTypeKey` constants.
- No behavioral change; type key strings are now consistent with the formal type key namespace.

## Why (intent / motivation)
- Objects with type keys on the root namespace (e.g. `"object.Array"`) lack proper namespacing, making them ambiguous when multiple libraries register types.
- Using `StaticTypeKey::kTVMFFI*` constants centralizes type key management and ensures consistency between the string and the constant.

## What changed (facts from diff)
- `include/tvm/ffi/container/array.h`: `_type_key = "object.Array"` → `StaticTypeKey::kTVMFFIArray`.
- `include/tvm/ffi/container/map.h`: `_type_key = "object.Map"` → `StaticTypeKey::kTVMFFIMap`.
- `include/tvm/ffi/error.h`: `_type_key = "object.Error"` → `"ffi.Error"`.
- `include/tvm/ffi/function.h`: `_type_key = "object.Function"` → `StaticTypeKey::kTVMFFIFunction`.
- `include/tvm/ffi/object.h` (+9/-5): `Object` class metadata updated to use `StaticTypeKey` constants; associated static type metadata fields updated.

## Public surface changes (if any)
- API: none (internal type keys)
- Flags/config: none
- Data formats/schemas: Type key strings changed for `Array`, `Map`, `Function`, `Error` objects — serialized data referencing old type keys (e.g. `"object.Array"`) will no longer match. Breaking for serialization-based workflows.

## Tests & verification
- Added/updated tests: none
- How to verify manually: Run full test suite; verify no type key mismatches.
- CI impact: Serialized data using old type keys must be regenerated.

## Risk & rollout notes
- Risk level: low — Affects type key strings used in serialization; internal build code is fine but any persisted type keys in data files will be stale.
- Rollout/migration: Regenerate any serialized/stored data that includes `"object.Array"`, `"object.Map"`, `"object.Function"`, or `"object.Error"` type keys.
- Follow-ups: none
