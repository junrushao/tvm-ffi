# 42e0612 — Introduce opaque ptr protocol (#147)

## TL;DR
- Introduces the `__tvm_ffi_opaque_ptr__` protocol allowing arbitrary Python objects to pass an opaque C pointer into FFI calls.
- Adds a new Cython argument setter `TVMFFIPyArgSetterFFIOpaquePtrCompatible_` that reads the pointer via the protocol method.
- Bumps the package version from `0.1.0b19` to `0.1.0b20`.

## Why (intent / motivation)
- DSL compilers may need to pass opaque C structs through Python to an internal FFI function without full object wrapping.
- The protocol provides a lightweight, duck-typed mechanism for this without requiring Cython or ctypes boilerplate on the caller side.

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`: new Cython setter `TVMFFIPyArgSetterFFIOpaquePtrCompatible_` that casts `arg.__tvm_ffi_opaque_ptr__()` to `void*` and stores it as `kTVMFFIOpaquePtr`; registered in `TVMFFIPyArgSetterFactory_` when `hasattr(arg_class, "__tvm_ffi_opaque_ptr__")`.
- `tests/python/test_function.py`: adds `test_function_with_opaque_ptr_protocol` verifying that a Python object with `__tvm_ffi_opaque_ptr__` is passed through the echo function as a `ctypes.c_void_p`.
- `pyproject.toml` and `python/tvm_ffi/__init__.py`: version bumped to `0.1.0b20`.

## Public surface changes (if any)
- API: New duck-typed protocol `__tvm_ffi_opaque_ptr__() -> int` on Python objects enables them to be passed as `kTVMFFIOpaquePtr` in FFI calls.
