## TL;DR

Fixes `load_inline` on macOS by adding `-ltvm_ffi` and `-L<tvm_ffi_lib_path>` to the default linker flags for non-Windows platforms. Refactors `find_libtvm_ffi()` to be shared across both Windows and non-Windows paths. Removes `xfail` markers that were blocking macOS and Linux tests.

## Why

On macOS (and Linux), the compiled inline shared library needs to link against `libtvm_ffi.dylib` (or `.so`) to resolve TVM FFI symbols. Without the `-ltvm_ffi` flag, linking would fail with undefined symbol errors. The fix also removes the blanket `xfail` for non-Linux platforms introduced in the previous temporary workaround.

## What changed

- `python/tvm_ffi/cpp/load_inline.py`:
  - Moved `find_libtvm_ffi()` call outside the Windows-only branch so it runs on all platforms.
  - Added `-ltvm_ffi` and `-L{libtvm_ffi_path.parent}` to `default_ldflags` on non-Windows platforms.
  - macOS gets the same linker treatment as Linux.
- `tests/python/test_load_inline.py`:
  - Removed `@pytest.mark.xfail(not sys.platform.startswith("linux"), ...)` decorators. Tests now run (and are expected to pass) on Linux and macOS. Windows still marked separately.

## Public surface changes

None. Internal `load_inline` build machinery change.

## Tests & verification

`load_inline` tests now run without `xfail` on Linux and macOS. Existing test cases exercise compilation and symbol resolution.

## Risk & rollout notes

Low risk. Change is limited to the linker flags for non-Windows platforms. No effect on Windows code path.
