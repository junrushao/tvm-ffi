# b508698 — Fix two issues that undefined behavior sanitizer caught (#419)

## TL;DR
- Fixes two undefined behavior (UB) issues identified by UBSan (issue #413)
- Replaces null-pointer member access with `offsetof` in `object.h` for computing header offsets
- Guards a `std::memcpy` with a size check in `string.h` to avoid passing a null source pointer with size 0

## Why (intent / motivation)
- Deriving pointer offsets via `static_cast<Class*>(nullptr)->member` is UB and flagged by sanitizers
- Calling `std::memcpy` with a null pointer, even with size 0, is technically UB in C++
- Both issues would cause false positives or real failures in sanitizer-enabled builds

## What changed (facts from diff)
- `include/tvm/ffi/object.h`: `ObjectUnsafe::GetObjectOffsetToSubclass<Class>()` now uses `__builtin_offsetof` instead of null-pointer arithmetic; wrapped with `#pragma GCC diagnostic` to suppress `-Winvalid-offsetof` on non-standard-layout types
- `include/tvm/ffi/string.h`: `std::memcpy` call guarded with `if (size > 0)` check to prevent null + 0 UB
