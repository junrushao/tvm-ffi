# 583e4b7 — [misc] support various arg types (#229)

## TL;DR
- Extended the typed function unpacking machinery in `function_details.h` to support all common C++ argument type qualifications: `T`, `const T`, `const T&`, and `T&&`.
- `ArgValueWithContext` is now a template class parameterized by `Type`, replacing the previous non-template class with a template conversion operator.
- Added `ArgTypeSupported` constraint to statically validate which argument type forms are acceptable.

## Why (intent / motivation)
- Previously, template operator conversion on `ArgValueWithContext` caused ambiguous instantiation errors with classes that have template constructors (e.g., `std::optional<T>`).
- Making the class itself a template type eliminates this ambiguity by using a non-template conversion operator.

## What changed (facts from diff)
- `include/tvm/ffi/function_details.h`:
  - Added `ArgTypeSupported<T>` constraint (valid: non-ref, `const T&`, `T&&`; invalid: `T&`).
  - `ArgValueWithContext` is now `template <typename Type>` with `TypeWithoutCR` as a member alias.
  - Conversion operator changed from `template <typename Type> operator Type()` to `operator TypeWithoutCR()`.
  - `unpack_call` now instantiates `ArgValueWithContext<std::tuple_element_t<Is, PackedArgs>>` with explicit template args.

## Public surface changes (if any)
- API: C++ typed function registration now accepts `const T&` and `T&&` argument types in addition to `T`.
- Flags/config: none
- Data formats/schemas: none
