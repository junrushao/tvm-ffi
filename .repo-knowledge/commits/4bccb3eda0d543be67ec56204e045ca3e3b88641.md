# 4bccb3e — [ERROR] Make Error conform more to std (#240)

## TL;DR
- Changes `Error::what()` to return only the plain error message (no traceback or kind prefix), conforming to `std::exception::what()` semantics which must not throw
- Introduces `Error::FullMessage()` to get the full traceback-prefixed message (equivalent to the previous `what()` output)
- Removes the thread-local string storage that `what()` previously used, making the compiled object more JIT-friendly
- Updates tests to use `FullMessage()` for backtrace/kind assertions

## Why (intent / motivation)
- `std::exception::what()` is `noexcept(true)` and should return a simple descriptive string; the previous implementation allocated a thread-local `std::string` with traceback formatting, violating both spirit and letter of the standard
- Thread-local storage (TLS) in headers can cause issues with LLVM JIT compilation contexts
- Separating `what()` from `FullMessage()` clarifies the intended use cases

## What changed (facts from diff)
- `include/tvm/ffi/error.h`:
  - New `FullMessage()` method returns the full `"Traceback (most recent call last):\n{trace}{kind}: {message}\n"` string (previously returned by `what()`)
  - `what()` now returns `obj->message.data` directly (the raw message, no allocation, truly noexcept)
  - `ErrorBuilder::~ErrorBuilder()` now calls `error.FullMessage()` for `std::cerr` logging
  - Doxygen note added to `what()` directing users to `FullMessage()`
- `tests/cpp/test_error.cc`: Updated 4 test cases (`Error/Backtrace`, `CheckError/Backtrace`, `CheckError/ValueError`, `CheckError/IndexError`) to use `error.FullMessage()` instead of `error.what()` for substring assertions

## Public surface changes (if any)
- API: `Error::what()` now returns only the message without kind or traceback — **breaking change** for callers that parse the output of `what()` to extract error kind or stack trace
- Flags/config: none
- Data formats/schemas: none
