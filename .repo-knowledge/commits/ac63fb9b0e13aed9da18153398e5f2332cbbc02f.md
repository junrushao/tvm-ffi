# ac63fb9 — chore(build): Introduce `setuptools_scm` for better versioning (#154)

## TL;DR
- Replaces the hardcoded `version = "0.1.0"` in `pyproject.toml` with `dynamic = ["version"]` driven by `setuptools_scm`.
- Auto-generates `python/tvm_ffi/_version.py` from git tags; falls back to `"0.0.0.dev0"` if not available.
- Extends `tests/lint/check_version.py` to verify C++ and Rust version macros match the SCM-derived version.
- Updates CI workflows to use `actions/checkout@v5` with `fetch-depth: 0` and `fetch-tags: true`.

## Why (intent / motivation)
- Manual version synchronization across Python, C++, and Rust was error-prone. `setuptools_scm` makes Python versioning automatic from git tags and provides the canonical version for cross-language consistency checks.

## What changed (facts from diff)
- `pyproject.toml`: `version = "0.1.0"` removed; `dynamic = ["version"]` added; `setuptools_scm` added to `dev`, `docs`, and `build-system.requires`; `[tool.setuptools_scm] version_file = "python/tvm_ffi/_version.py"`.
- `python/tvm_ffi/__init__.py`: Removed hardcoded `__version__ = "0.1.0"`; now tries `from ._version import __version__, __version_tuple__` with fallback.
- `include/tvm/ffi/c_api.h`: `TVM_FFI_VERSION_PATCH` bumped from `0` to `1`.
- `tests/lint/check_version.py`: Completely rewritten with `setuptools_scm` + `packaging` to check C++ macros and Rust crate versions against SCM version; new `--cpp`/`--rust` flags.
- CI workflows (`.github/workflows/ci_test.yml`, `publish_wheel.yml`): Upgraded to `actions/checkout@v5`; added `fetch-depth: 0` and `fetch-tags: true` to all checkout steps.
- `.gitignore`: Added `python/tvm_ffi/_version.py`.

## Public surface changes (if any)
- API: `tvm_ffi.__version__` now derived from git tags via `setuptools_scm`.
- Flags/config: `--cpp`/`--rust` flags in `tests/lint/check_version.py`; `TVM_FFI_VERSION_PATCH` bumped to 1.
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/lint/check_version.py` (lint-level check).
- How to verify manually: `python tests/lint/check_version.py --cpp --rust`
- CI impact: pre-commit hook `check-version-consistency` now uses `setuptools-scm`; CI checkouts require full history.

## Risk & rollout notes
- Risk level: medium — version derivation changes; any build that lacks git tags will see `0.0.0.dev0` instead of the expected version. Must have `fetch-depth: 0` + `fetch-tags: true` in all CI checkouts.
- Rollout/migration: Ensure CI environments have full git history with tags; Rust bindings version check disabled by default (`--rust` not yet in pre-commit hook).
- Follow-ups: Add `--rust` to pre-commit once Rust binding matures.
