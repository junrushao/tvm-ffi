# 3a5bf5e — feat: add kw_only support for dataclass init generation (#384)

## TL;DR
- Adds `KW_ONLY` sentinel class to mark all following fields as keyword-only in generated `__init__`
- Adds `kw_only` boolean parameter to `field()` for per-field keyword-only control
- Adds `kw_only` parameter to `c_class()` for class-level default
- Mirrors `dataclasses.KW_ONLY` sentinel behavior for familiarity

## Why (intent / motivation)
- Python's standard `dataclasses` support `kw_only` to prevent positional argument misuse
- This was missing from `@c_class`, making it harder to write safe APIs with many optional fields (issue #356)

## What changed (facts from diff)
- `python/tvm_ffi/dataclasses/__init__.py`: Exports new `KW_ONLY` sentinel
- `python/tvm_ffi/dataclasses/field.py`: Adds `KW_ONLY` class + `kw_only: bool = False` parameter to `field()`
- `python/tvm_ffi/dataclasses/_utils.py`: `fill_dataclass_field()` gains `class_kw_only` and `kw_only_from_sentinel` parameters; handles sentinel detection in field list
- `python/tvm_ffi/dataclasses/c_class.py`: Passes `kw_only` through to init generation
- `src/ffi/testing/testing.cc`: Added C++ test helper registrations for the new kw_only scenarios (+20 lines)
- `python/tvm_ffi/testing/testing.py` / `__init__.py`: Expose new test helpers
