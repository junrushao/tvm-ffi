# 37d0485 — ROCm: fix DLPack current_work_stream and force addon override for Torch exchange API (#466)

## TL;DR
- Fixes ROCm stream handling in the Torch DLPack exchange API path by implementing a correct `current_work_stream` callback for `kDLROCM`.
- Forces addon override for the Torch exchange API to ensure the fixed ROCm stream callback takes effect.
- Adds a new Python test `tests/python/test_current_work_stream_gpu.py` verifying stream identity on both CUDA and ROCm.

## Why (intent / motivation)
- On ROCm, graph-capture-sensitive callers (e.g., SGLang JIT kernels) experienced stream mismatch via the Torch DLPack exchange API. The `current_work_stream` callback did not return the correct ROCm stream, causing HIP graph capture warnings and downstream workarounds.

## What changed (facts from diff)
- `python/tvm_ffi/_optional_torch_c_dlpack.py` (+3/-2): adds ROCm `current_work_stream` callback implementation; forces override.
- `python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py` (+8/-1): build-system fix to ensure the addon is rebuilt with the corrected ROCm stream support.
- `tests/python/test_current_work_stream_gpu.py` (+96/-0): new GPU-only test verifying `current_work_stream` returns the correct torch stream on CUDA and ROCm.
