# 024e45c — [FFI] More strict tuple constructor checking (#18023)

## TL;DR
- Tightens the `Tuple<Types...>` constructor SFINAE constraint to prevent ambiguous construction when a single-element Tuple is constructed from another Tuple of the same type.
- Adds `operator+=` and `operator-=` to `IterAdapter` to complete random-access iterator requirements.
- Adds 28 lines of new Tuple constructor tests.

## Why (intent / motivation)
- A bug caused `Tuple<T>` to be constructible from `Tuple<T>&&` via the wrong constructor path (the `UTypes&&...` forwarding constructor instead of the move-from-same-type constructor), leading to type mismatch at runtime.
- The fix adds a SFINAE guard that excludes the variadic constructor when the single-argument is exactly `Tuple<Types>` (same-type), forcing the correct overload.

## What changed (facts from diff)
- `include/tvm/ffi/container/tuple.h` (+7/-4): replaced `static_assert(sizeof...(Types) == sizeof...(UTypes))` with a more precise `enable_if` that additionally excludes `Tuple<T>(Tuple<T>&&)` mis-routing.
- `include/tvm/ffi/container/container_details.h` (+10/-0): added `IterAdapter::operator+=` and `IterAdapter::operator-=` for random-access iterator completeness.
- `tests/cpp/test_tuple.cc` (+28/-0): new test cases exercising the fixed constructor paths.
