# d2e9aa6 — chore(build): Distribute manylinux2014 wheels (#146)

## TL;DR
- Switches the default Linux wheel build image from manylinux2_28 to manylinux2014 for broader glibc compatibility.
- Fixes several Python 3.8 runtime compatibility issues discovered after the previous commit (container imports, `type[T]` annotations, `get_type_hints` with `include_extras`).
- Updates CI matrix to test Python 3.8 on aarch64 and Python 3.9 on Windows.
- mypy `python_version` is bumped back to 3.9 (it targets mypy's inference, not the minimum version).

## Why (intent / motivation)
- Old Linux systems with glibc < 2.28 cannot install manylinux_2_28 wheels.
- manylinux2014 (glibc 2.17+) is supported by most production deployments.

## What changed (facts from diff)
- `pyproject.toml`: adds `manylinux-x86_64-image = "manylinux2014"` and `manylinux-aarch64-image = "manylinux2014"`.
- `.github/workflows/ci_test.yml`: aarch64 test matrix changes from Python 3.10 to 3.8; Windows from 3.12 to 3.9.
- `python/tvm_ffi/container.py`: corrects 3.8 version branching logic (was inverted).
- `python/tvm_ffi/dataclasses/_utils.py`: replaces `type[T]` with `Type[T]` (noqa UP006) for 3.8 compat.
- `python/tvm_ffi/dataclasses/c_class.py`: same `Type[T]` fix; gates `get_type_hints(include_extras=True)` behind `>= 3.9`.
- `tests/python/test_container.py`: version-guards `from collections.abc import Sequence` import.
- `tests/python/test_dtype.py`: guards `torch.float8_e8m0fnu` dtype check with `hasattr` for older Torch.
