## TL;DR

Renames and consolidates the Object declaration and definition macros to embed the type key directly in the macro call and to use more descriptive suffixes. The `_type_key` static member is now set by the macro argument rather than separately. Mutable and immutable `ObjectRef` definition macros are merged.

## Why

The previous macro design required two steps: declaring the object info macro and separately setting `_type_key`. This was error-prone and verbose. Embedding the type key in the macro call makes it impossible to forget, reduces boilerplate, and makes the type key co-located with the type declaration.

## What changed

Macro renames across ~15 files in `include/tvm/ffi/`, `src/ffi/`, `tests/cpp/`, `docs/`:
- `TVM_FFI_DECLARE_BASE_OBJECT_INFO(T, Parent)` + `_type_key = "..."` → `TVM_FFI_DECLARE_OBJECT_INFO("key", T, Parent)`
- `TVM_FFI_DECLARE_FINAL_OBJECT_INFO(T, Parent)` + `_type_key = "..."` → `TVM_FFI_DECLARE_OBJECT_INFO_FINAL("key", T, Parent)`
- `TVM_FFI_DECLARE_STATIC_OBJECT_INFO(T, Parent)` + `_type_key = "..."` → `TVM_FFI_DECLARE_OBJECT_INFO_STATIC("key", T, Parent)`
- `TVM_FFI_DEFINE_OBJECT_REF_METHODS` → `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE`
- `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` → `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NOTNULLABLE`
- Mutable and immutable `ObjectRef` definition macros consolidated using `_type_mutable` static field to choose `const` vs mutable `operator->`.

## Public surface changes

**Breaking for C++ users**: All macro names changed. Any code using the old macros must be updated to the new names and signatures. The type key is now the first argument of the macro instead of a separate `_type_key` assignment.

## Tests & verification

All existing C++ tests and `docs/` code examples updated to use new macro names. Tests compile and pass.

## Risk & rollout notes

Medium risk: widespread mechanical rename. All downstream C++ code using object declaration macros must be updated. Change is purely mechanical and does not affect runtime behavior.
