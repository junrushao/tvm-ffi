# e1bd421 — [FIX] Fix the error propagation in the case of tensor arguments (#409)

## TL;DR
- Fixes a bug in `TVMFFIPyCallManager` where a function call error code was silently overwritten by the return value of `TVMFFIEnvSetDLPackManagedTensorAllocator` when restoring the tensor allocator after a call
- Adds a regression test that passes a PyTorch tensor argument to a function that raises, verifying the error propagates correctly
- Also reverts the version patch from `9` back to `8` (appears to be a minor tracking correction for the in-development branch)

## Why (intent / motivation)
- The bug was introduced in v0.1.8 and revealed by the fix in that release; previously hidden by different control flow, the allocator-restore path wrote its own return code into `c_api_ret_code[0]`, clobbering the actual function error code and causing errors to be silently swallowed

## What changed (facts from diff)
- `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`: In `TVMFFIPyCallManager`, changed the allocator-restore path to check `TVMFFIEnvSetDLPackManagedTensorAllocator` separately (raising a `RuntimeError` if it fails), and only then checking `c_api_ret_code[0]` for the function error; ensures function errors are not overwritten
- `src/ffi/extra/env_context.cc`: In `EnvContext::SetDLPackManagedTensorAllocator`, when `opt_out_original_allocator` is set, returns the cached local allocator (`dlpack_allocator_`) rather than the global allocator; prevents race-condition-like behavior when nested calls occur
- `include/tvm/ffi/c_api.h`: `TVM_FFI_VERSION_PATCH` reverted from `9` to `8`
- `tests/python/test_tensor.py`: Added `test_tensor_auto_dlpack_with_error` that verifies a `ValueError` raised inside a function called with a PyTorch tensor argument propagates out correctly
