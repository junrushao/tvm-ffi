# b5dd851 — fix(c_class): Fix mypy warnings on `dataclasses.field(...)` (#43)

## TL;DR
- The `field()` helper in `tvm_ffi.dataclasses` now returns the declared field type `_FieldValue` instead of `Field`, eliminating mypy `[assignment]` errors
- Achieved via a `TypeVar` + `cast` pattern matching the style used by stdlib `dataclasses`
- Adds `typing-extensions` as a runtime dependency in `pyproject.toml`

## Why (intent / motivation)
- When a `c_class` field was annotated `v_str: str = field(...)`, mypy reported `Incompatible types in assignment (expression has type "Field", variable has type "str")`
- The fix makes the static type of `field()` appear as the declared field type so type checkers are satisfied

## What changed (facts from diff)
- `field.py`: return type of `field()` changed to `_FieldValue` with a `cast` at the return site; `Field.__init__` parameter types tightened using `_MISSING_TYPE`
- `field.py`: imports `_MISSING_TYPE` from `dataclasses` and adds `TypeVar`, `cast` from `typing`
- `testing.py`: removes now-redundant `# type: ignore[assignment]` comment on `v_str` field
- `pyproject.toml`: adds `"typing-extensions"` to project `dependencies`

## Public surface changes (if any)
