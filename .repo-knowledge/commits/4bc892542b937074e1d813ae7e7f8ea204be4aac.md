# 4bc8925 — [CYTHON] Introduce __tvm_ffi_tensor__ protocol (#108)

## TL;DR
- Introduces the `__tvm_ffi_tensor__()` protocol: if a Python object's class has a `__tvm_ffi_tensor__` attribute, it is called to retrieve the underlying `tvm_ffi.Tensor` directly, bypassing DLPack overhead.
- Adds `TVMFFIPyArgSetterFFITensorCompatible_` Cython setter that calls the protocol and handles ref-count edge cases (temporary tensor keeps alive via `TVMFFIObjectIncRef`).
- Adds benchmark entry for the new protocol in `tests/scripts/benchmark_dlpack.py`.
- Imports `Py_REFCNT` in `base.pxi`.

## Why (intent / motivation)
- When a wrapper class holds a `tvm_ffi.Tensor` as a member, going through DLPack is unnecessary overhead. The protocol allows direct handle pass-through for zero-copy calling.

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`: adds `TVMFFIPyArgSetterFFITensorCompatible_`; factory checks `__tvm_ffi_tensor__` on the class before checking `__c_dlpack_exchange_api__`; also changes `hasattr(arg, ...)` to `hasattr(arg_class, ...)` for `__dlpack__` check.
- `python/tvm_ffi/cython/base.pxi`: adds `Py_REFCNT` import.
- `tests/python/test_tensor.py`: adds `test_tvm_ffi_tensor_compatible`.
- `tests/scripts/benchmark_dlpack.py`: adds `TestFFITensor` class and benchmark entry.

## Public surface changes (if any)
- API: Objects implementing `__tvm_ffi_tensor__(self) -> tvm_ffi.Tensor` on the class are now transparently converted when passed to FFI functions.
