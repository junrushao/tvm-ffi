# 82bc7b6 — [FIX] Fix missing static registration for DLTensor* (#239)

## TL;DR
- Added missing `ReserveBuiltinTypeIndex` call for `kTVMFFIDLTensorPtr` in the TypeTable initializer.
- Without this registration, passing a `DLTensor*` to a typed function produced an unclear error instead of a proper `TypeError`.
- Added a C++ test verifying the correct `TypeError` message is emitted.

## Why (intent / motivation)
- `DLTensor*` was not statically registered in the type index table, causing inconsistent or silent failures when it was passed as an FFI argument.
- Proper registration enables accurate type-mismatch error reporting.

## What changed (facts from diff)
- `src/ffi/object.cc`: Added `ReserveBuiltinTypeIndex(StaticTypeKey::kTVMFFIDLTensorPtr, TypeIndex::kTVMFFIDLTensorPtr)` in `TypeTable` constructor.
- `tests/cpp/test_function.cc`: Added test asserting that passing a `DLTensor*` to a typed function expecting `int` raises `TypeError` with message `"Expected `int` but got `DLTensor*`"`.
