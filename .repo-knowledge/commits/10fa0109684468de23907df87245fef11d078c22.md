# 10fa010 — chore(release): Re-enable Python 3.8 Wheel on macOS (#162)

## TL;DR
- Re-enables Python 3.8 wheel builds on macOS arm64 by using `actions/setup-python` (which provides a native arm64 Python 3.8 binary) before `astral-sh/setup-uv`.
- Removes `cp38-macosx_*` from the cibuildwheel `skip` list in `pyproject.toml`.
- Pins `astral-sh/setup-uv` to a specific commit SHA (`b75a909`) instead of `@v4` to avoid the x86_64 build from `setup-uv` conflicting.

## Why (intent / motivation)
- The earlier skip (commit 8831e88) was a workaround; `actions/setup-python` provides a proper ARM64 Python 3.8, so the skip is unnecessary.
- Pinning `setup-uv` prevents regressions from floating tag updates.

## What changed (facts from diff)
- `.github/workflows/publish_wheel.yml`: adds `actions/setup-python@v5` step specifically for `macOS` + `ARM64`; conditions `astral-sh/setup-uv` on non-macOS-arm64; pins `setup-uv` to SHA; applies the same ref fix to the sdist build job.
- `pyproject.toml`: removes `cp38-macosx_*` from `skip`.
