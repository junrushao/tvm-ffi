# 71bbe91 — Fix TVMFFIEnvSetDLPackManagedTensorAllocator to correctly return the original allocator (#371)

## TL;DR
- Fixed `TVMFFIEnvSetDLPackManagedTensorAllocator` to capture the original allocator before overwriting it
- Previously the function set `opt_out_original_allocator` to the new allocator value (because `dlpack_allocator_` had already been updated), not the old one
- Added a regression test

## Why (intent / motivation)
- The function's documented contract is to return the *previous* allocator via `opt_out_original_allocator`; the old code wrote the new allocator back to that pointer, making it impossible to restore the previous allocator after calling this function

## What changed (facts from diff)
- `src/ffi/extra/env_context.cc`: reordered `SetDLPackManagedTensorAllocator` so that `opt_out_original_allocator` is populated from `GetDLPackManagedTensorAllocator()` (the old value) *before* `dlpack_allocator_` is overwritten; the redundant `dlpack_allocator_ = allocator` line at the end was also cleaned up
- `tests/cpp/extra/test_c_env_api.cc`: new `TEST(CEnvAPI, TVMFFIEnvSetDLPackManagedTensorAllocator)` test verifies that the pre-call allocator equals the returned original allocator (+8 lines)

## Public surface changes (if any)
- API: `TVMFFIEnvSetDLPackManagedTensorAllocator` — behavior corrected; `*opt_out_original_allocator` now correctly contains the *old* allocator
- Flags/config: none
