## TL;DR

Overhauls the `load_inline` API to match the `torch.utils.cpp_extension` interface style. Renames singular source parameters to plural (`cpp_source` -> `cpp_sources`, `cuda_source` -> `cuda_sources`), merges the separate `cpp_functions`/`cuda_functions` parameters into a single `functions` parameter, and adds a `build_directory` parameter for controlling the output directory.

## Why

The previous interface used singular parameter names (`cpp_source`, `cuda_source`) and separate per-language function lists (`cpp_functions`, `cuda_functions`). Aligning with the `torch.utils.cpp_extension.load_inline` convention makes the API more familiar to existing PyTorch users, and the unified `functions` parameter simplifies the interface since functions are always exported from the C++ side.

## What changed

- `python/tvm_ffi/cpp/load_inline.py`:
  - `cpp_source` -> `cpp_sources` (accepts `str` or `Sequence[str]`)
  - `cuda_source` -> `cuda_sources` (accepts `str` or `Sequence[str]`)
  - `cpp_functions` + `cuda_functions` -> `functions` (accepts `Mapping[str, str]`, `Sequence[str]`, or `str`)
  - Added `build_directory` parameter
  - Functions are always exported from the `cpp_source` side via `_decorate_with_tvm_ffi()`
- `examples/inline_module/main.py`: Updated to new API.
- `tests/python/test_load_inline.py`: Updated all test calls to use new parameter names.

## Public surface changes

**Breaking**: `tvm_ffi.cpp.load_inline` parameter names changed. Old calls using `cpp_source`, `cuda_source`, `cpp_functions`, or `cuda_functions` must be updated to the new names.

## Tests & verification

Existing `test_load_inline.py` tests updated to use the new interface. No new test cases added.

## Risk & rollout notes

Low risk overall (feature is new, no downstream dependents yet). Breaking change to the `load_inline` API, but the feature was introduced in the same release cycle.
