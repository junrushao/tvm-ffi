# b9a2b92 — fix: More fix of `ml_dtypes<0.5` (#222)

## TL;DR
- Guards the `float4_e2m1fn` dtype registration behind a `hasattr(ml_dtypes, "float4_e2m1fn")` check
- Prevents an `AttributeError` when using `ml_dtypes < 0.5.0` which does not define `float4_e2m1fn`

## Why (intent / motivation)
- `ml_dtypes.float4_e2m1fn` was introduced in `ml_dtypes` 0.5.0; accessing it unconditionally on older versions raised `AttributeError`, breaking import for users on older ml_dtypes

## What changed (facts from diff)
- In `python/tvm_ffi/_dtype.py`, the line `dtype._NUMPY_DTYPE_TO_STR[np.dtype(ml_dtypes.float4_e2m1fn)] = "float4_e2m1fn"` is now wrapped in `if hasattr(ml_dtypes, "float4_e2m1fn"):`

## Public surface changes (if any)
- API: none (behavior on `ml_dtypes >= 0.5.0` unchanged; on older versions `float4_e2m1fn` simply won't be registered)
- Flags/config: none
