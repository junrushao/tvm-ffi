# 22a7894 — [DLPack] C Functions for DLPack Speed Exchange and Stream Handling (#96)

## TL;DR
- Replaces three separate DLPack function pointer fields (`c_dlpack_from_pyobject`, `c_dlpack_to_pyobject`, `c_dlpack_tensor_allocator`) with a unified `DLPackExchangeAPI` struct (following DLPack proposal #175).
- The new struct bundles: `managed_tensor_allocator`, `managed_tensor_from_py_object_no_sync`, `managed_tensor_to_py_object_no_sync`, `dltensor_from_py_object_no_sync`, and `current_work_stream`.
- Updates `TVMFFIPyArgSetter`, `TVMFFIPyCallContext`, and all related Cython/C++ code to use the new struct.
- Torch extension generates a `TorchDLPackExchangeAPI` singleton and exposes it via `torch.Tensor.__c_dlpack_exchange_api__`.
- Updates `3rdparty/dlpack` submodule to latest commit.

## Why (intent / motivation)
- Aligns with the latest DLPack standard (PR #174) that unifies tensor exchange into a single versioned struct.
- Provides non-sync tensor conversion paths and integrated `current_work_stream` querying for safer multi-stream operation.
- Removes the ambiguity of three separate attributes on external tensor types.

## What changed (facts from diff)
- `python/tvm_ffi/cython/base.pxi`: adds `DLPackExchangeAPI` struct binding and all its function pointer type aliases; removes old 3-pointer fields.
- `python/tvm_ffi/cython/function.pxi`: `TVMFFIPyArgSetterDLPackCExporter_` renamed to `TVMFFIPyArgSetterDLPackExchangeAPI_`; stream querying now uses `api->current_work_stream`; `make_ret` takes `DLPackExchangeAPI*` instead of `DLPackToPyObject`.
- `python/tvm_ffi/cython/tensor.pxi`: `DLTensorTestWrapper` implements `_dltensor_test_wrapper_get_exchange_api()` exposing all five function pointers.
- `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`: replaces three separate fields with `c_dlpack_exchange_api` in both `TVMFFIPyCallContext` and `TVMFFIPyArgSetter`.
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: rewrites Torch C extension to expose `TorchDLPackExchangeAPI` struct; adds `TorchDLPackCurrentWorkStream` for CUDA stream integration; changes from three exported functions to one `TorchDLPackExchangeAPIPtr`.

## Public surface changes (if any)
- API: External tensor types must now provide `__c_dlpack_exchange_api__` (class attribute, integer pointer) instead of `__c_dlpack_from_pyobject__` + `__c_dlpack_to_pyobject__` + `__c_dlpack_tensor_allocator__`.
- Flags/config: `TVM_FFI_SKIP_c_dlpack_from_pyobject` env var still honored.
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_load_inline.py` (guard updated to check `__c_dlpack_exchange_api__`)
- How to verify manually: `uv run pytest -vvs tests/python/test_load_inline.py`
- CI impact: none

## Risk & rollout notes
- Risk level: high — breaks external tensor types that used the old three-pointer protocol
- Rollout/migration: External tensor classes must implement `__c_dlpack_exchange_api__` on the class; remove `__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`.
- Follow-ups: `DLTensorTestWrapper` updated; existing Torch extension updated.
