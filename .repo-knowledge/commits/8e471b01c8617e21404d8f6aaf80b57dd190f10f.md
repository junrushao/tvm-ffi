# 8e471b0 — fix: Cython Memory Corruption Reported by ASan (#55)

## TL;DR
- Fixes a read-after-free memory corruption in `_type_info_create_from_type_key` (Cython)
- The fix stores `ByteArrayArg(c_str(type_key))` in a named `cdef` variable so it stays alive across the `TVMFFITypeKeyToIndex` call

## Why (intent / motivation)
- ASan reported a use-after-free: the `ByteArrayArg` temporary was being destructed before `TVMFFITypeKeyToIndex` had finished reading its pointer, because Cython does not defer destruction until after the call expression
- The root cause is a Cython semantic difference from C++ regarding temporary lifetimes

## What changed (facts from diff)
- `python/tvm_ffi/cython/object.pxi`: `ByteArrayArg(c_str(type_key))` is now stored as `cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))` before passing `type_key_arg.cptr()` to `TVMFFITypeKeyToIndex`
