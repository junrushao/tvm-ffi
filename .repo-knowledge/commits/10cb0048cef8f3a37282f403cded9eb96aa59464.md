# 10cb004 — [CUDA] Isolate unified api to only in cubin launcher (#408)

## TL;DR
- Moves `TVM_FFI_CHECK_CUDA_ERROR` from `unified_api.h` (driver/runtime unified API) to `base.h` where it uses only the CUDA runtime API (`cudaError_t`)
- Renames the unified-API error check macro to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR` (scoped to the cubin launcher that can switch between driver and runtime)
- Updates all call sites in examples, tests, and documentation to use the renamed macro
- Reverts `device_guard.h` include back to `base.h` (undoes the fix from #405 in favor of this cleaner separation)
- Narrows the clang-tidy file filter in CI to only `src/` and `tests/` directories

## Why (intent / motivation)
- Mixing CUDA driver and runtime APIs is error-prone; the unified API abstraction was intended only for the cubin launcher (which needs to support both during the CUDA 12.8-13.0 transition); exposing it in `base.h` made general code accidentally depend on driver API headers

## What changed (facts from diff)
- `include/tvm/ffi/extra/cuda/base.h`: Added `TVM_FFI_CHECK_CUDA_ERROR` macro using `cudaError_t` and `cudaGetErrorName/String` from the runtime API only
- `include/tvm/ffi/extra/cuda/internal/unified_api.h`: Renamed `TVM_FFI_CHECK_CUDA_ERROR` to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`; added NOLINT annotations; updated `GetDeviceHandle` call site
- `include/tvm/ffi/extra/cuda/cubin_launcher.h`: Updated all internal call sites from old name to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`; added NOLINT for `cuda.h` include
- `include/tvm/ffi/extra/cuda/device_guard.h`: Reverted include from `unified_api.h` back to `base.h`
- `examples/cubin_launcher/`: All example `.cc` files and Python inline C++ snippets updated to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`
- `tests/python/test_cubin_launcher.py`: Updated test inline code to use new macro name
- `docs/guides/cubin_launcher.rst`: Documentation updated to use new macro name
- `.github/workflows/ci_test.yml`: Narrowed clang-tidy file filter to `src/` and `tests/` directories only

## Public surface changes (if any)
- API: `TVM_FFI_CHECK_CUDA_ERROR` is now a runtime-API-only macro in `base.h`; old `TVM_FFI_CHECK_CUDA_ERROR` in `unified_api.h` is renamed to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_cubin_launcher.py` (macro rename)
- How to verify manually: Build the CUDA examples and run `uv run pytest tests/python/test_cubin_launcher.py`
- CI impact: clang-tidy now only checks `src/` and `tests/` (not `include/` or `examples/`)

## Risk & rollout notes
- Risk level: medium — any code using the old `TVM_FFI_CHECK_CUDA_ERROR` from `unified_api.h` (driver API variant) will get a compile error; code using it from `base.h` continues to work
- Rollout/migration: Replace `TVM_FFI_CHECK_CUDA_ERROR` in cubin launcher code with `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR`
- Follow-ups: Consider deprecating driver API support in the cubin launcher entirely
