# ac7bf68 — feat: Embed metadata for FFI exported functions (#230)

## TL;DR
- Adds `TVM_FFI_DLL_EXPORT_INCLUDE_METADATA` compile-time flag to control metadata export
- New macros `TVM_FFI_DLL_EXPORT_TYPED_FUNC` (updated) and `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` export type schema and docstrings alongside functions
- Python `Module` gains `get_function_metadata()` and `get_function_doc()` methods
- C++ `ModuleObj` and `LibraryModuleObj` gain `GetFunctionMetadata()` / `GetFunctionDoc()` implementations

## Why (intent / motivation)
- Compiler frameworks (JAX/XLA, MLIR-based) need to validate third-party FFI modules at compile time without invoking the function; type schema and docstrings embedded in the shared library enable this

## What changed (facts from diff)
- `include/tvm/ffi/function.h`: Introduced `TVM_FFI_DLL_EXPORT_INCLUDE_METADATA` guard; split `TVM_FFI_DLL_EXPORT_TYPED_FUNC` into an impl macro and a conditional variant; added `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC`
- `include/tvm/ffi/extra/module.h`: Added `tvm_ffi_doc_prefix` symbol constant; improved Doxygen docs on metadata/doc methods
- `src/ffi/extra/library_module.cc`: Implemented `GetFunctionMetadata()` and `GetFunctionDoc()` by looking up `__tvm_ffi__metadata_*` and `__tvm_ffi__doc_*` symbols
- `python/tvm_ffi/module.py`: Added `get_function_metadata()` and `get_function_doc()` Python methods
- `python/tvm_ffi/cpp/extension.py`: Added `_escape_cpp_string_literal` helper; `_decorate_with_tvm_ffi` now emits `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` when docstring is non-empty
- `src/ffi/testing/testing.cc`: Enabled metadata in testing lib; refactored schema test functions to named functions; added `testing_dll_*` DLL exports with docstring example
- Tests added: `tests/cpp/test_metadata.cc`, `tests/cpp/test_function.cc` (StaticLinkingMetadata), `tests/python/test_build.py`

## Public surface changes (if any)
- API: New Python `Module.get_function_metadata(name)` → `dict | None`; `Module.get_function_doc(name)` → `str | None`; C++ `Module::GetFunctionMetadata` / `GetFunctionDoc`
- Flags/config: New `TVM_FFI_DLL_EXPORT_INCLUDE_METADATA` preprocessor flag (default 0)
- Data formats/schemas: Metadata JSON format: `{"type_schema": "<json_string>"}`

## Tests & verification
- Added/updated tests: `tests/cpp/test_metadata.cc` (DLLExportedFuncMetadata, DLLExportedFuncDocumentation), `tests/cpp/test_function.cc` (StaticLinkingMetadata), `tests/python/test_build.py` (test_build_inline_with_metadata, test_build_inline_with_docstrings, test_build_without_metadata)
- How to verify manually: `uv run pytest -vvs tests/python/test_build.py` and run C++ tests
- CI impact: New tests run in C++ and Python CI jobs

## Risk & rollout notes
- Risk level: medium — adds new preprocessor flag and changes `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro structure; metadata is opt-in (default off)
- Rollout/migration: Existing code using `TVM_FFI_DLL_EXPORT_TYPED_FUNC` without the flag is unchanged; opt in with `#define TVM_FFI_DLL_EXPORT_INCLUDE_METADATA 1`
- Follow-ups: C++ const information in metadata (noted as followup)
