## TL;DR

Replaces a custom `load_inline` C++ extension used to query the current CUDA stream with the native `torch._C._cuda_getCurrentRawStream(device_id)` Python API, removing approximately 38 lines of Cython code and bumping the package version from `0.1.0a6` to `0.1.0a7`.

## Why

The previous implementation compiled and loaded a small inline C++ extension (`torch_get_current_stream`) at runtime to retrieve the CUDA raw stream handle. Using the native PyTorch C API directly (`torch._C._cuda_getCurrentRawStream`) is simpler, eliminates the runtime compilation overhead, and removes the dependency on `load_inline` for this internal operation.

## What changed

- `python/tvm_ffi/cython/function.pxi`: Removed the `_load_torch_get_current_stream_func()` helper and the associated `load_inline` call. Replaced the entire block with a one-liner that calls `torch._C._cuda_getCurrentRawStream(device_id)`.
- `pyproject.toml`: Version bumped from `0.1.0a6` to `0.1.0a7`.

## Public surface changes

None. The stream-query behavior is internal to the Python FFI call mechanism. No public APIs were changed.

## Tests & verification

No new tests were added or removed. The change is a refactor of an internal implementation detail.

## Risk & rollout notes

Low risk. The replacement uses an established private PyTorch API (`torch._C._cuda_getCurrentRawStream`) that has been stable across torch versions. Removes ~38 lines of Cython code, reducing maintenance surface.
