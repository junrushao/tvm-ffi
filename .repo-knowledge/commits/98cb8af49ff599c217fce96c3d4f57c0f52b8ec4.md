# 98cb8af — feat: Auto-create Python classes when missing (#49)

## TL;DR
- When an FFI object type has no registered Python class, a stub class is now auto-generated on first encounter instead of emitting a warning and falling back to `Object`
- The generated class inherits from the parent's registered class (recursively created), and exposes all C++ fields and methods from the reflection registry
- Renames the internal `type_acenstors` field to `type_ancestors` (typo fix) throughout C++ and Cython
- `TypeInfo` gains `type_ancestors` list and `parent_type_info` is now populated automatically via `__post_init__`
- `TypeMethod.as_callable` and `TypeField.as_property` helpers centralised in `type_info.pxi`

## Why (intent / motivation)
- Returning a bare `Object` for unregistered types was unhelpful; users could not access fields or methods
- Auto-generation makes TVM FFI "just work" for C++ types that haven't been manually registered in Python

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: `type_acenstors` renamed to `type_ancestors` in `TVMFFITypeInfo`
- `include/tvm/ffi/object.h`: `type_ancestors` used; `kTVMFFIOpaquePyObject` static key added
- `include/tvm/ffi/reflection/accessor.h`: uses `type_ancestors`
- `python/tvm_ffi/cython/object.pxi`: new `make_fallback_cls_for_type_index` that dynamically builds a class; `make_ret_object` calls this on the slow path; `_update_registry` helper extracted; `_lookup_or_register_type_info_from_type_key` replaces `_lookup_type_info_from_type_key`
- `python/tvm_ffi/cython/type_info.pxi`: `TypeInfo` gains `type_ancestors` field and `__post_init__` populating `parent_type_info`; `TypeMethod.as_callable` and `TypeField.as_property` added; `_member_method_wrapper` moved here

- Rollout/migration: External users of `TVMFFITypeInfo.type_acenstors` must update to `type_ancestors`
- Follow-ups: `OpaquePyObject` type registration done in subsequent commit `bdad218`
