# 46ab644 — feat: add __bool__ support for Array and Map (#380)

## TL;DR
- Added `Array.__bool__` returning `len(self) > 0` so that empty arrays are falsy
- Added `Map.__bool__` returning `len(self) > 0` so that empty maps are falsy
- Added parametrized Python tests covering truthy/falsy behavior for both containers

## Why (intent / motivation)
- Python's `list` and `dict` return `False` for empty containers; `tvm_ffi.Array` and `tvm_ffi.Map` previously always returned `True` because they inherit from `Object` without `__bool__`, which evaluates truthiness as "object is not None"
- This inconsistency was surprising and violated the principle of least astonishment for Python developers

## What changed (facts from diff)
- `python/tvm_ffi/container.py`: `Array.__bool__(self) -> bool` added after `__contains__`; `Map.__bool__(self) -> bool` added after `__len__`
- `tests/python/test_container.py`: `test_array_bool` and `test_map_bool` parametrized tests added (+28 lines)

## Public surface changes (if any)
- API: `Array.__bool__` and `Map.__bool__` — new Python dunder methods; `bool(Array([]))` now returns `False` (previously `True`)
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_container.py` (+28 lines)
- How to verify manually: `pytest -vvs tests/python/test_container.py::test_array_bool tests/python/test_container.py::test_map_bool`
- CI impact: new passing tests

## Risk & rollout notes
- Risk level: low — behavior change for `bool(empty_array)` from `True` to `False`; code relying on empty containers being truthy will break (unlikely in practice)
- Rollout/migration: review any code using empty `Array` or `Map` in boolean context
- Follow-ups: none
