# a97b7c6 — [TEST] Fix the tensor loading order in test (#128)

## TL;DR
- Documents in `Module` docstring the danger of returning objects from a locally-scoped module (use-after-unload).
- Wraps tensor-returning test code in a nested `run_check()` function to guarantee objects are destroyed before the module goes out of scope.
- Makes `test_load_inline_with_env_tensor_allocator` require torch (removes optional skip).

## Why (intent / motivation)
- When a module is loaded in local scope and returns an object, the object's deleter resides in the loaded library. If the module is GC'd before the object, the deleter can call an invalid address. Moving the object usage into a nested function ensures proper cleanup order.

## What changed (facts from diff)
- `python/tvm_ffi/module.py`: Added extensive docstring to `Module` class explaining the bad/good patterns for module-scoped objects with code examples.
- `tests/python/test_load_inline.py`: Two tests (`test_load_inline_with_env_tensor_allocator`, `test_cuda_memory_alloc_noleak`) refactored to use inner `run_check()` functions.
