# 86c4042 — feat: add `ffi.GetInvalidObject` global function for MISSING singleton (#447)

## TL;DR
- Renames the internal `ffi.MapGetMissingObject` C++ function to the more general `ffi.GetInvalidObject`.
- Moves `MISSING` singleton initialization from `container.py` into `core.pyx`, so it is available earlier in the module load sequence.
- Adds `MISSING: Object` to `core.pyi` type stub.
- Adds a test verifying `MISSING` identity across imports and its use in `Map.get()`.

## Why (intent / motivation)
- `MISSING` is a general-purpose sentinel, not map-specific. Moving initialization to `core.pyx` ensures it is ready for any module that imports from `core`, avoiding import-order issues.

## What changed (facts from diff)
- `src/ffi/container.cc`: removes `def("ffi.MapGetMissingObject", ...)` and adds `def("ffi.GetInvalidObject", ...)` returning `ObjectRef`.
- `python/tvm_ffi/cython/core.pyx`: adds `MISSING = _get_global_func("ffi.GetInvalidObject", False)()` after `Function` is registered.
- `python/tvm_ffi/container.py`: replaces `MISSING = _ffi_api.MapGetMissingObject()` with `from .core import MISSING`.
- `python/tvm_ffi/core.pyi`: adds `MISSING: Object`.
- `python/tvm_ffi/_ffi_api.py`: replaces `MapGetMissingObject` with `GetInvalidObject` in stubs and `__all__`.
- `tests/python/test_container.py`: new `test_missing_object` test.

## Public surface changes (if any)
- API: `ffi.GetInvalidObject` global function (replaces `ffi.MapGetMissingObject`); `tvm_ffi.MISSING` now exported from `core`
