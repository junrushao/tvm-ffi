# 55edee0 — [FFI][REFACTOR] Phase out getattr based attribute handling (#18189)

## TL;DR
- Adds string-based API wrappers `ToJSONGraphString` and `FromJSONGraphString` to `serialization.cc`, which serialize/deserialize using string I/O rather than `json::Value` objects.
- Registers these two new global functions (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`) alongside the existing graph functions.
- Adds `refl::EnsureTypeAttrColumn` calls for `__data_to_json__` and `__data_from_json__` to ensure the columns are available even when no type registers them.

## Why (intent / motivation)
- String-based round-trip API is simpler to call from Python and other language bindings that don't need to inspect the intermediate `json::Value`.
- Ensuring the type attribute columns exist at init time prevents late-registration races.

## What changed (facts from diff)
- `src/ffi/extra/serialization.cc` (+12/-1): adds `FromJSONGraphString(String)` which calls `FromJSONGraph(json::Parse(value))`, and `ToJSONGraphString(Any, Any)` which calls `json::Stringify(ToJSONGraph(value, metadata))`; extends `TVM_FFI_STATIC_INIT_BLOCK` to register both new functions and add `EnsureTypeAttrColumn` calls for `__data_to_json__` and `__data_from_json__`.

## Public surface changes (if any)
- API: new global functions `ffi.ToJSONGraphString(Any, Any) -> String` and `ffi.FromJSONGraphString(String) -> Any`.
- Flags/config: none.
- Data formats/schemas: none (string wrappers over existing JSONGraph format).
