# 4383b1a — [Bugfix] Run ninja build command in MSVC dev env (#11)

## TL;DR
- Adds `_run_command_in_dev_prompt` helper to `load_inline.py` that locates `VsDevCmd.bat` via `vswhere.exe` and runs the ninja build inside a Developer Command Prompt environment.
- On Windows (`IS_WINDOWS`), `_build_ninja` now calls `_run_command_in_dev_prompt` instead of plain `subprocess.run`.
- Removes `@pytest.mark.xfail(sys.platform.startswith("win"), ...)` markers from four `test_load_inline_cpp*` tests, indicating they should now pass on Windows.

## Why (intent / motivation)
- On Windows, ninja requires MSVC environment variables (set by `VsDevCmd.bat`) to locate the compiler. Running ninja without this environment caused build failures.

## What changed (facts from diff)
- `python/tvm_ffi/cpp/load_inline.py`: New `_run_command_in_dev_prompt` function (62 lines); `_build_ninja` conditionally uses it on Windows.
- `tests/python/test_load_inline.py`: Removed `xfail` markers; removed unused `import sys`.
