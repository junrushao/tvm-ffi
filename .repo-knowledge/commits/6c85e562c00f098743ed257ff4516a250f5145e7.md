# 6c85e56 — [STREAM] Enable compact with cuda-python driver stream (#236)

## TL;DR
- Adds a fallback argument setter for `cuda.bindings.driver.CUstream` objects from the `cuda-python` package, allowing them to be passed directly to FFI functions as opaque pointers
- The fallback treats `CUstream` as an integer pointer until `cuda-python` adds native `__cuda_stream__` protocol support
- Adds a test for `cuda_driver.CUstream` round-trip through the echo function

## Why (intent / motivation)
- `cuda-python`'s `cuda.bindings.driver.CUstream` does not yet implement the `__cuda_stream__` protocol
- Users who pass `CUstream` objects to FFI functions would get a `TypeError`; this PR enables transparent interop via an integer cast

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`:
  - Imports `cuda.bindings.driver as cuda_driver` (with fallback to `None`)
  - Renames `TVMFFIPyArgSetterCUDAStream_` to `TVMFFIPyArgSetterCUDAStreamProtocol_` for clarity
  - Adds new `TVMFFIPyArgSetterCUDADriverStreamFallback_` setter that casts `CUstream` to `long long` and stores as `kTVMFFIOpaquePtr`
  - In `TVMFFIPyArgSetterFactory_`, adds a branch: if `cuda_driver is not None and isinstance(arg, cuda_driver.CUstream)`, use the fallback setter
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: minor type annotation fix (`tuple[int, torch.cuda.Stream]` -> `tuple[int, int]`)
- `tests/python/test_stream.py`: new `test_cuda_driver_stream()` test (skipped if `cuda-python` not installed)
