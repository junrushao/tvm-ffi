# dcacb98 — [METADATA] Always return metadata string as created in main lib (#305)

## TL;DR
- Changes metadata and doc string allocation in `TVM_FFI_DLL_EXPORT_TYPED_FUNC` and `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` to use `TVMFFIStringFromByteArray`, allocating strings in `libtvm_ffi` rather than in the extension module

## Why (intent / motivation)
- Strings created with `::tvm::ffi::String(...)` inside the extension module are allocated in the extension's memory; if the module is unloaded before the string is freed, the deleter becomes invalid (use-after-free / delete-after-module-unload)

## What changed (facts from diff)
- `include/tvm/ffi/function.h`: In `TVM_FFI_DLL_EXPORT_TYPED_FUNC` metadata symbol, replaced `::tvm::ffi::String str(os.str()); TypeTraits<...>::MoveToAny(...)` with `std::string data = os.str(); TVMFFIByteArray data_array{...}; return TVMFFIStringFromByteArray(...)` so the resulting string object is allocated inside `libtvm_ffi`
- Same pattern applied in `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` for the docstring
