# e6a654a — [Feature] Add a function to build c-dlpack for torch (#192)

## TL;DR
- Extracts the large inline C++ source from `_optional_torch_c_dlpack.py` into a standalone build script `python/tvm_ffi/utils/_build_optional_c_dlpack.py` that builds `libtorch_c_dlpack_addon.so/.dll` using Ninja.
- Changes the loading path to use a JIT-cached shared library loaded via `ctypes.CDLL` instead of `torch.utils.cpp_extension.load_inline`.
- Adds `TVM_FFI_DISABLE_TORCH_C_DLPACK` env var to skip the loading.
- Adds Windows CI support for Python tests by locating `VsDevCmd.bat`.

## Why (intent / motivation)
- The old approach using `load_inline` rebuilt the extension on every process start and was not suitable for AOT packaging. Decoupling the build into a separate script enables both JIT caching and AOT distribution of the addon library.

## What changed (facts from diff)
- `python/tvm_ffi/utils/_build_optional_c_dlpack.py` (new, 780 lines): Standalone build script using Ninja to compile `libtorch_c_dlpack_addon`; supports `--build_dir` and `--build_with_cuda`; uses `FileLock` for parallel-safe builds.
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Replaced 573 lines of inline C++ and `load_inline` call with ~43 lines that check cache, run build script as subprocess, load via `ctypes.CDLL`, and return the `lib` reference.
- `python/tvm_ffi/cpp/load_inline.py`: Renamed `_build_ninja` to `build_ninja` (public).
- `pyproject.toml`: Added `setuptools` to `test` dependencies.
- `tests/python/test_optional_torch_c_dlpack.py` (new): Tests `test_build_torch_c_dlpack_extension` and `test_parallel_build`.
- `.github/workflows/ci_test.yml`: Added steps to locate `VsDevCmd.bat` on Windows and run Python tests via `cmd /c call`.
- `.github/workflows/utils/locate_vsdevcmd_bat.py` (new): Locates VS `VsDevCmd.bat` via `vswhere.exe`.

## Public surface changes (if any)
- API: `tvm_ffi.cpp.load_inline.build_ninja` is now public (renamed from `_build_ninja`).
- Flags/config: `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` env var disables the addon loading.
- Data formats/schemas: `libtorch_c_dlpack_addon.so/.dll` cached at `~/.cache/tvm-ffi/torch_c_dlpack_addon/`.

## Tests & verification
- Added/updated tests: `tests/python/test_optional_torch_c_dlpack.py` — build and parallel build tests.
- How to verify manually: `uv run pytest tests/python/test_optional_torch_c_dlpack.py -vvs`
- CI impact: Windows Python test steps now use `VsDevCmd.bat`; Windows DLPack exchange API test is `xfail`.

## Risk & rollout notes
- Risk level: medium — significant refactor of the torch DLPack addon loading path; Windows behavior added.
- Rollout/migration: Users relying on the old inline build will now get a JIT-cached build; first import may be slower on a cold cache.
- Follow-ups: Prebuilt packages per (python-version, torch-version) could be added.
