# d0d0e2f — feat: add Rust binding for `Array<T>` (#348)

## TL;DR
- Introduces a Rust implementation of the TVM FFI `Array<T>` immutable container type
- Correctly manages reference counting (`inc_ref`/`dec_ref`) for `ObjectRef` elements
- Also fixes a double-free bug in `Any::into_raw_ffi_any` by wrapping with `ManuallyDrop`
- Ships 341 lines of implementation and 132 lines of tests

## Why (intent / motivation)
- The Rust bindings lacked `Array<T>`, making it impossible to pass or receive TVM FFI arrays in Rust
- The `inc_ref`/`dec_ref` semantics are subtle and a correct implementation needs careful testing

## What changed (facts from diff)
- `rust/tvm-ffi/src/any.rs`: `into_raw_ffi_any` now wraps `self` in `ManuallyDrop` before accessing `self.data` to prevent double-free
- `rust/tvm-ffi/src/collections/array.rs` (new, 341 lines): Full `Array<T>` implementation with `get()`, element iteration, reference counting, and `FromIterator`/`IntoIterator` traits
- `rust/tvm-ffi/src/collections/mod.rs`: Re-exports new `array` module
- `rust/tvm-ffi/src/lib.rs`: Re-exports `Array` at crate root
- `rust/tvm-ffi/tests/test_array.rs` (new, 132 lines): Integration tests for construction, retrieval, edge cases

## Public surface changes (if any)
- API: `tvm_ffi::Array<T>` type added to Rust crate public surface
