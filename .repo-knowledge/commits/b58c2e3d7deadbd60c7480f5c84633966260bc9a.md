# b58c2e3 — feat(stubgen): Package generation with `--init-*` flags (#295)

## TL;DR
- Adds `--init-pypkg`, `--init-lib`, and `--init-prefix` flags to `tvm-ffi-stubgen` CLI, enabling one-command bootstrapping of `_ffi_api.py` and `__init__.py` for new downstream packages.
- Re-running is idempotent: existing stub blocks are detected and not duplicated.
- Rewrites CLI (`stub/cli.py`, `stub/codegen.py`, `stub/consts.py`, `stub/file_utils.py`), removes `stub/analysis.py`, adds `stub/lib_state.py`.
- Updates `examples/packaging` to use the generated stubs.
- Updates `python/tvm_ffi/testing` package to use the new stub infrastructure.

## Why (intent / motivation)
- Downstream package authors had to manually write `_ffi_api.py` and `__init__.py` boilerplate for every new extension. The new flags automate this from a single command after building the shared library.

## What changed (facts from diff)
- `python/tvm_ffi/stub/cli.py`: +413/-101 — adds `--init-*` argument group, package scaffold logic, idempotent `__all__` and `export` block generation.
- `python/tvm_ffi/stub/codegen.py`: +206/-42 — new codegen paths for `_ffi_api.py` and `__init__.py` scaffolding.
- `python/tvm_ffi/stub/consts.py`: adds new block type constants for `export`, `__all__`, and import sections.
- `python/tvm_ffi/stub/lib_state.py` (new): encapsulates loaded library state for stub generation.
- `python/tvm_ffi/stub/analysis.py` (deleted): logic merged into other modules.

- `tests/python/test_stubgen.py`: updated.
