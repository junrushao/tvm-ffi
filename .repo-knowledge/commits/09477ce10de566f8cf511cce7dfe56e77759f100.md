# 09477ce — [experimental] Initial bringup of rust support (#80)

## TL;DR
- Introduces an experimental Rust crate workspace (`rust/`) with three crates: `tvm-ffi-sys` (C API bindings), `tvm-ffi` (safe ergonomic API), and `tvm-ffi-macros` (proc-macros).
- Provides Rust bindings for core FFI types: `Any`/`AnyView`, `Object`/`ObjectRef`, `Function`, `String`, `Shape`, `Tensor`, `Device`, `DType`, `Error`, and `Module`.
- Adds CI job for Rust tests.

## Why (intent / motivation)
- Rust is a useful system programming language for ML systems; adding it as a third first-class language helps future-proof ABI design and broadens the language ecosystem. The focus remains on Python and C++ polish, but Rust can add value for performance-critical use cases.

## What changed (facts from diff)
- `rust/Cargo.toml`: workspace definition for three crates.
- `rust/tvm-ffi-sys/`: raw C API Rust bindings (`c_api.rs`, `c_env_api.rs`, `dlpack.rs`); `build.rs` links against the TVM FFI shared library.
- `rust/tvm-ffi/`: safe Rust API crate with modules for `any`, `object`, `function`, `string`, `device`, `dtype`, `error`, `collections` (shape, tensor), `extra/module`; `#[tvm_object]` derive macro via `tvm-ffi-macros`.
- `rust/tvm-ffi-macros/`: proc-macro crate providing `#[tvm_object]` attribute to derive `Object`/`ObjectRef` boilerplate.
- `rust/tvm-ffi/examples/load_library.rs`: example loading a pre-built shared library and calling functions from Rust.
- Full integration test suite (`rust/tvm-ffi/tests/`) covering Any, Device, DType, Error, Function, Object, Shape, String, Tensor.
- `.github/workflows/ci_test.yml`: +6 lines adding Rust test job.
