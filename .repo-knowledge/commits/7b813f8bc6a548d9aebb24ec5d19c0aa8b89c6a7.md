# 7b813f8 — [FFI][REFACTOR] Update TVM_FFI_STATIC_INIT_BLOCK to fn style

## TL;DR
- Changes `TVM_FFI_STATIC_INIT_BLOCK({ ... });` syntax to `TVM_FFI_STATIC_INIT_BLOCK() { ... }` (function-body style).
- On GCC/Clang, the macro now uses `__attribute__((constructor))` for true constructor registration; on MSVC and other compilers, falls back to the old lambda variable trick.
- Removes the `TVM_FFI_ATTRIBUTE_UNUSED` macro.
- Applied across all C++ source files, examples, tests, and docs.

## Why (intent / motivation)
- Function-style syntax is cleaner and provides better error reporting — compiler errors point to the specific function rather than inside a lambda.
- Using `__attribute__((constructor))` on GCC/Clang is more robust than the lambda-initialized static variable pattern.

## What changed (facts from diff)
- `include/tvm/ffi/base_details.h`: New platform-branched implementation of `TVM_FFI_STATIC_INIT_BLOCK()` macro; `TVM_FFI_ATTRIBUTE_UNUSED` removed.
- All `.cc` files using `TVM_FFI_STATIC_INIT_BLOCK`: syntax updated from `({...});` to `() {...}`.
- Docs and examples updated to show new syntax.

## Public surface changes (if any)
- API: `TVM_FFI_STATIC_INIT_BLOCK` macro call syntax change. Old `({...});` form is no longer valid.
- Flags/config: none
- Data formats/schemas: none

## Risk & rollout notes
