# f6303b2 — [CYTHON] Enable ffi function creation from MLIR Packed function (#100)

## TL;DR
- Adds `Function.__from_mlir_packed_safe_call__(mlir_packed_symbol, *, keep_alive_object=None)` to wrap MLIR execution-engine function pointers (following MLIR packed call convention `void fn(void**)`) as `tvm_ffi.Function` objects.
- Implements `TVMFFIPyMLIRPackedSafeCall` C++ adapter class in `tvm_ffi_python_helpers.h` that bridges MLIR calling convention to FFI safe-call.
- Also makes `keep_alive_object` keyword-only in `__from_extern_c__` (breaking change in signature).

## Why (intent / motivation)
- MLIR execution engines generate functions in a packed argument convention (`void fn(void**)`) that differs from the FFI safe-call convention. A thin adapter enables wrapping these pointers without requiring MLIR to support extern-C attribute tags directly.

## What changed (facts from diff)
- `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`: adds `TVMFFIPyMLIRPackedSafeCall` class + `TVMFFIPyMLIRPackedSafeCallCreate/Invoke/Deleter` helpers.
- `python/tvm_ffi/cython/function.pxi`: adds `Function.__from_mlir_packed_safe_call__`; makes `keep_alive_object` keyword-only in `__from_extern_c__`.
- `python/tvm_ffi/cython/base.pxi`: exposes `TVMFFIPyMLIRPackedSafeCallCreate/Invoke/Deleter`.
- `python/tvm_ffi/core.pyi`: stub for new method; updates `__from_extern_c__` signature.
- `src/ffi/extra/testing.cc`: adds `_mlir_add_one_c_symbol` and `testing.get_mlir_add_one_c_symbol`.
- `tests/python/test_function.py`: adds `test_function_from_mlir_packed_safe_call`.
