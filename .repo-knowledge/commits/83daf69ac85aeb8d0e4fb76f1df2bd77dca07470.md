# 83daf69 — feat: Restrict `__slots__=()` for subclasses of `tvm_ffi.Object` by default (#27)

## TL;DR
- Enforces `__slots__ = ()` on all Cython-defined FFI object subclasses to prevent accidental Python attribute mutation on objects backed by C++ structs.
- Updates multiple Cython `.pxi` files and Python module code to declare `__slots__`.
- Updates `test_object.py` and `docs/conf.py` to account for the new restriction.

## Why (intent / motivation)
- Without `__slots__`, Python can silently add attributes to FFI objects (e.g., `obj.foo = 1`), which are stored in a Python `__dict__` and not visible to C++ field accessors. This is a footgun for users expecting C++ field semantics.

## What changed (facts from diff)
- Multiple Cython `.pxi` files updated: `base.pxi`, `device.pxi`, `dtype.pxi`, `error.pxi`, `function.pxi`, `object.pxi`, `string.pxi`, `tensor.pxi`, `type_info.pxi` — all add `__slots__ = ()` or equivalent.
- `python/tvm_ffi/module.py`: updated for slots.
- `python/tvm_ffi/core.pyi`: updated type stubs.
- `docs/conf.py` (+6/-1): Sphinx autodoc configuration updated to handle slotted classes.
- `tests/python/test_object.py`: tests updated to reflect the new restriction.

## Public surface changes (if any)
- API: FFI object subclasses no longer accept arbitrary Python attribute assignment by default
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_object.py` updated
- How to verify manually: `uv run pytest -vvs tests/python/test_object.py`
- CI impact: none

## Risk & rollout notes
- Risk level: medium — any existing code that set arbitrary Python attributes on FFI objects will now raise `AttributeError`
- Rollout/migration: Remove or replace any `obj.custom_attr = value` patterns on FFI objects with Python-side wrappers or C++ fields
- Follow-ups: none noted
