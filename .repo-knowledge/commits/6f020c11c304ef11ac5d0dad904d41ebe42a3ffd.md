# 6f020c1 — [REFACTOR][ABI] Update backtrace storage for append-friendly (#39)

## TL;DR
- Changes the internal backtrace storage convention to "most recent call first" (reverse of the previous "most recent call last") to enable O(1) append during error propagation.
- Renames source files `traceback.cc/.h/_win.cc` to `backtrace.cc/backtrace_utils.h/backtrace_win.cc`.
- Updates `TVMFFIErrorCreate` signature and error propagation internals for consistency.
- Rendering and Python-side display still show "most recent call last" (via `TracebackMostRecentCallLast`), so user-visible output is unchanged.
- Bumps version to `0.1.0b5`.

## Why (intent / motivation)
- The old "most recent call last" storage made incremental backtrace building O(n) per frame (prepend). Switching to prepend-friendly "most recent first" storage makes the common propagation path O(1), at the cost of reversing on display.
