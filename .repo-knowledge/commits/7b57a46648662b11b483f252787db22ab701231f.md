# 7b57a46 — fix: Add schema support for `ObjectRef::MemFn` (#113)

## TL;DR
- Adds `FunctionInfo<>` template specializations for `ObjectRef` member functions (both mutable and const).
- Enables registering `ObjectRef::MethodName` as a global FFI function via `def_method`.
- Adds `TestIntPair::Sum` as a concrete example and test case.
- Fixes downstream compilation errors when registering `ObjectRef` member functions.

## Why (intent / motivation)
- In downstream TVM use-cases, member functions of `ObjectRef` types are registered as global functions. The previous `FunctionInfo<>` specializations only handled `Object*` (raw pointer), not `ObjectRef` (value) as the first argument, causing compilation failures.

## What changed (facts from diff)
- `include/tvm/ffi/function_details.h`: Added `void` default template parameter to `FunctionInfo`; added `std::enable_if_t<std::is_base_of_v<ObjectRef, Class>>` specializations for both mutable and const member function pointers, using `Class` (value) rather than `Class*` as the first argument.
- `src/ffi/testing/testing.cc`: Added `TestIntPair::Sum()` method and registered it via `.def("sum", ...)` and `.def_method("testing.TestIntPairSum", ...)`.
- `python/tvm_ffi/testing.py`: Added stub annotation for `sum` method on `TestIntPair`.
- `tests/python/test_metadata.py`: Added `test_mem_fn_as_global_func` which retrieves metadata for the newly registered global function and asserts its type schema.
- `cmake/Utils/AddLibbacktrace.cmake`: Added `LOG_DIR` and `LOG_MERGED_STDOUTERR` options for better build diagnostics.

## Public surface changes (if any)
- API: `FunctionInfo<R (Class::*)(Args...), enable_if<is_base_of<ObjectRef,Class>>>` now supported; `testing.TestIntPairSum` global function available in testing library.
