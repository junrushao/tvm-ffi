# 37f45c3 — Reliability update (#435)

## TL;DR
- Fixes torch-c-dlpack-ext build failure when `torch` is not installed in the build environment
- Handles `AttributeError` when the prebuilt `torch_c_dlpack_ext` library has a different ABI from the current PyTorch installation
- Closes issue #433

## Why (intent / motivation)
- The addon build backend unconditionally imported `torch` which would raise `ModuleNotFoundError` and abort the build even in non-Torch environments
- When the prebuilt extension is built against a different PyTorch ABI (e.g., in NGC containers), `ctypes.CDLL` raises `AttributeError` rather than `ImportError`, which was not caught, preventing fallback to JIT compilation

## What changed (facts from diff)
- `addons/torch_c_dlpack_ext/build_backend.py`: Wraps `import torch` with `contextlib.suppress(ModuleNotFoundError)`; skips compilation if torch is None; build only happens when `torch is not None and not _is_lib_prebuilt()`
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Catches `AttributeError` in the prebuilt library load path and falls through to JIT build (+5 lines)
