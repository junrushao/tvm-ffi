# 4fec972 — [Feat] Support lower PyTorch versions in dtype handling (#414)

## TL;DR
- Removes unconditional references to PyTorch dtype constants that do not exist in older PyTorch versions
- Moves `uint16`, `uint32`, `uint64` and float8 dtype mappings behind `hasattr` guards
- Allows `import tvm_ffi` to succeed on older PyTorch versions without AttributeError

## Why (intent / motivation)
- Older PyTorch versions (before certain releases) do not have `uint16`, `uint32`, `uint64`, `float8_*` dtype attributes
- The previous code would crash on import in those environments, blocking TVM FFI adoption
- Fixes issue #381 partially, enabling graceful degradation for dtype support

## What changed (facts from diff)
- `python/tvm_ffi/cython/dtype.pxi`: removed unconditional `torch.uint16`, `torch.uint32`, `torch.uint64` from the dtype mapping dict
- Float8 variants (`float8_e4m3fn`, `float8_e4m3fnuz`, `float8_e5m2`, `float8_e5m2fnuz`) also removed from the static dict
- All removed mappings are now added conditionally via `hasattr` checks after the main dict is built
- `float8_e8m0fnu` and `float4_e2m1fn_x2` already had `hasattr` guards; the other float8 types now match that pattern
