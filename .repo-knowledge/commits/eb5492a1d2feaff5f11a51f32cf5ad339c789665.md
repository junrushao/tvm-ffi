# eb5492a — fix: Compatibility with torch <= 2.8 (#54)

## TL;DR
- Guards `Float8_e8m0fnu` DLPack code in `_optional_torch_c_dlpack.py` behind `TORCH_VERSION >= 2.8` (extending the fix from #53)
- Also guards the lanes-check assertion for `Float4_e2m1fn` behind the same version gate
- In `dtype.pxi`, switches from unconditional `torch.float8_e8m0fnu` dict entry to `hasattr` guards for both `float8_e8m0fnu` and `float4_e2m1fn_x2`

## Why (intent / motivation)
- `Float8_e8m0fnu` was also introduced in PyTorch 2.8, not just `Float4_e2m1fn`
- Without the guard, building or importing with PyTorch < 2.8 would fail at compile time or import time

## What changed (facts from diff)
- `_optional_torch_c_dlpack.py`: moved `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` guard to wrap `Float8_e8m0fnu` case and the Float4 lanes check
- `dtype.pxi`: removed unconditional `torch.float8_e8m0fnu` entry; replaced with `if hasattr(torch, "float8_e8m0fnu")` and added `if hasattr(torch, "float4_e2m1fn_x2")` guard for the new float4 type

## Public surface changes (if any)
- API: `float8_e8m0fnu` and `float4_e2m1fn_x2` dtypes conditionally available depending on installed PyTorch version
- Flags/config: none
