## TL;DR

Adds a new FFI type `kTVMFFIOpaquePyObject` (type index 74) that wraps arbitrary Python objects as opaque handles in the TVM FFI type system. Unknown Python objects are now wrapped instead of raising a `TypeError`, enabling pass-through of arbitrary Python values across the FFI boundary.

## Why

Previously, passing an unknown Python object through the FFI call mechanism would raise a `TypeError` at the argument conversion step. This blocked use cases where callers need to pass opaque Python objects to functions that accept `Any`. By introducing an opaque wrapper type, arbitrary Python objects can now round-trip through the FFI without conversion errors.

## What changed

- `include/tvm/ffi/c_api.h`: Added `kTVMFFIOpaquePyObject = 74` type index constant. Added `TVMFFIOpaqueObjectCell` struct (`void* handle`). Added `TVMFFIObjectCreateOpaque(void* handle, TVMFFIObjectHandle* out)` C API function.
- `src/ffi/object.cc`: Implemented `TVMFFIObjectCreateOpaque()` — creates an `OpaqueObjectImpl` that stores the handle pointer.
- `python/tvm_ffi/cython/object.pxi`: Added `OpaquePyObject` Cython extension class wrapping the C opaque object handle.
- `python/tvm_ffi/cython/base.pxi`: Extended type-dispatch table to handle `kTVMFFIOpaquePyObject`.
- `python/tvm_ffi/cython/function.pxi`: Updated argument conversion: when all other conversions fail, call `_convert_to_opaque_object()` instead of raising `TypeError`.
- `python/tvm_ffi/convert.py` (now `_convert.py`): Added `_convert_to_opaque_object()` fallback.
- Tests: `test_object.py`, `test_container.py`, `test_function.py` — added tests for opaque round-trip behavior.

## Public surface changes

- New C API: `TVMFFIObjectCreateOpaque(void* handle, TVMFFIObjectHandle* out)`
- New C type constant: `kTVMFFIOpaquePyObject = 74`
- New C struct: `TVMFFIOpaqueObjectCell`
- New Python class: `tvm_ffi.OpaquePyObject`

## Tests & verification

New tests added in `tests/python/test_object.py`, `test_container.py`, and `test_function.py` covering opaque object creation, pass-through, and identity preservation across the FFI boundary.

## Risk & rollout notes

Low risk. The change is purely additive — a new type index and new classes are introduced without modifying existing type handling paths, except for the fallback case in argument conversion (which previously raised `TypeError`).
