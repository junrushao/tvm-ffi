# 0342d85 — [FFI] Fix SmallMapInit with duplicated keys (#18178)

## TL;DR
- Fixes `MapObj::CreateFromRange` so that `SmallMapObj` initialization (for maps with capacity 2-3) properly handles duplicate keys by using `InsertMaybeReHash` instead of bulk initialization.
- Previously, small maps with duplicate keys would retain all key copies; now the last value for a duplicate key wins (consistent with `DenseMapObj` behavior).

## Why (intent / motivation)
- `SmallMapObj::CreateFromRange` directly filled slots without deduplication, so constructing a map from a range with duplicated keys produced incorrect results.

## What changed (facts from diff)
- `include/tvm/ffi/container/map.h`: in `MapObj::CreateFromRange`, for `cap < SmallMapObj::kMaxSize` (but `cap >= 2`), creates an empty `SmallMapObj` and inserts elements one by one via `InsertMaybeReHash`, enabling deduplication.
- `tests/cpp/test_map.cc`: adds `Map::DuplicatedKeysInit` test asserting `map.size() == 1` and `map["a"] == 3`.
