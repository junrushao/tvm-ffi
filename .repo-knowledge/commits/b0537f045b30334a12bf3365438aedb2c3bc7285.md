# b0537f0 — [CYTHON] Support cuda stream protocol (#109)

## TL;DR
- Adds `TVMFFIPyArgSetterCUDAStream_` Cython setter that handles the CUDA stream protocol (`__cuda_stream__()`) when passing Python objects to FFI functions.
- Objects whose class defines `__cuda_stream__()` return `(version, stream_ptr_int)` and the integer is passed as `kTVMFFIOpaquePtr`.
- Adds `test_cuda_stream_handling` in `tests/python/test_device.py`.

## Why (intent / motivation)
- Implements the CUDA Python stream interoperability protocol (https://nvidia.github.io/cuda-python/cuda-core/latest/interoperability.html#cuda-stream-protocol) so arbitrary stream objects can be passed through the TVM FFI without manual casts.

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`:
  - New `TVMFFIPyArgSetterCUDAStream_`: calls `arg.__cuda_stream__()`, extracts `tuple[1]` as a `long long`, stores it as `kTVMFFIOpaquePtr`.
  - `TVMFFIPyArgSetterFactory_`: adds `hasattr(arg_class, "__cuda_stream__")` check (before the `torch.Tensor` fallback) to dispatch to the new setter; also changes `hasattr(arg, "__dlpack__")` to `hasattr(arg_class, "__dlpack__")` for consistency.
- `tests/python/test_device.py`: adds `test_cuda_stream_handling` — creates a `MyDummyStream` returning `("cuda", 1)` from `__cuda_stream__()`, passes it through `testing.echo`, and asserts the result is a `ctypes.c_void_p` with value `1`.

## Public surface changes (if any)
- API: Objects implementing `__cuda_stream__(self) -> tuple[int, int]` on their class are now transparently converted to `kTVMFFIOpaquePtr` when passed to FFI functions.
- Flags/config: none
