# 8fcd924 — feat: Introduce `tvm.registry.get_registered_type_keys()` (#249)

## TL;DR
- Added `tvm_ffi.registry.get_registered_type_keys()` Python API returning all type keys registered in the C++ TypeTable.
- Backed by a new global function `ffi.GetRegisteredTypeKeys` implemented in C++ returning an `Array<String>`.
- Primarily intended for stub generation tooling that needs to enumerate C++-registered object types.

## Why (intent / motivation)
- Stub generation (stubgen) requires knowledge of all object types registered on the C++ end in order to generate complete type annotations.
- No such enumeration API existed before.

## What changed (facts from diff)
- `src/ffi/object.cc`: Added `TypeTable::GetRegisteredTypeKeys()` method and registered it as `ffi.GetRegisteredTypeKeys` via `TVM_FFI_STATIC_INIT_BLOCK`.
- `python/tvm_ffi/registry.py`: Added `get_registered_type_keys()` function; also fixed `get_global_func_metadata` to handle empty/None return gracefully with `or "{}"`.
- `python/tvm_ffi/_ffi_api.py`: Added `GetRegisteredTypeKeys` to TYPE_CHECKING stubs.
- `tests/python/test_object.py`: Added `test_get_registered_type_keys` verifying all primitive type keys and namespace prefixes.

## Public surface changes (if any)
- API: New public function `tvm_ffi.registry.get_registered_type_keys() -> Sequence[str]`.
- Flags/config: none
- Data formats/schemas: Returns sequence of type key strings.
