# 3b26a09 — doc: Properly document `field_static_type_index` and add more tests (#456)

## TL;DR
- Restores and comprehensively documents `TVMFFIFieldInfo::field_static_type_index` in the C API, clarifying its compile-time-only semantics.
- Restores POD field inlining in serialization/deserialization (None, Bool, Int, Float, DataType inlined as values, not node-graph references).
- Adds 40 new C++ serialization tests and 58 new Python serialization tests.
- Adds `TAllFields` and `TWithDefaults` test objects covering all POD field types and default values.

## Why (intent / motivation)
- `field_static_type_index` had incomplete documentation and a missing blank line removal introduced noise. The serializer's POD inlining was under-tested, leading to potential regressions. Comprehensive tests and clear docs were needed.

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: `field_static_type_index` documentation rewritten (+18/-13 lines) with explicit warning against runtime use and explanation of POD inlining.
- `include/tvm/ffi/type_traits.h`: removes spurious blank line after `field_static_type_index = kTVMFFINone` (+0/-1).
- `rust/tvm-ffi-sys/src/c_api.rs`: doc comment updated (+1/-1).
- `tests/cpp/extra/test_serialization.cc`: 364 new lines of serialization tests (integer/float/string/object edge cases, default fields, shared references, nested containers, error cases).
- `tests/cpp/testing_object.h`: new `TAllFieldsObj`/`TAllFields` (+70 lines) and `TWithDefaultsObj`/`TWithDefaults` (+30 lines) test types.
- `tests/cpp/test_reflection.cc`: registers new test types.
- `tests/python/test_serialization.py`: new file (+515 lines) with 58 tests across None, Bool, Int, Float, String, DataType, Device, Array, Map, Shape, Object, JSON structure verification, metadata, and error cases.

## Public surface changes (if any)
- API: none (documentation clarifications only; serializer behavior restored to intended state)
- Flags/config: none
- Data formats/schemas: POD fields (`bool`, `int`, `float`, `DataType`) are inlined in JSON, not emitted as node-graph entries
