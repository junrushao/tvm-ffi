# e6a85e9 — [CYTHON] Fix ctypes.c_void_p for nullptr (#235)

## TL;DR
- Fixes a crash when passing `ctypes.c_void_p(0)` as an FFI argument: `ctypes.c_void_p.value` returns `None` when the pointer value is 0, which previously caused a `TypeError` when the Cython code tried to use it as an integer
- Treats `None` from `c_void_p.value` as 0 (the null pointer)

## Why (intent / motivation)
- Python's `ctypes.c_void_p(0).value` evaluates to `None` (not `0`) by design, representing a null pointer
- The Cython `c_handle()` function was using the value directly as an integer, causing a `TypeError` on null pointers

## What changed (facts from diff)
- `python/tvm_ffi/cython/base.pxi`: in `c_handle()`, changed `v_ptr = handle.value` to `cdef object value = handle.value; v_ptr = 0 if value is None else value`
- `tests/python/test_function.py`: added test case that passes `ctypes.c_void_p(0)` to `fecho` and verifies the result is `None` (the round-trip representation of a null pointer)

## Public surface changes (if any)
- API: passing `ctypes.c_void_p(0)` to FFI functions now works correctly instead of crashing
- Flags/config: none
