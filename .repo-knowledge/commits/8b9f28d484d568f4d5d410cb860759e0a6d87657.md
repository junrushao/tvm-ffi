# 8b9f28d — fix(build): Link dl and pthread dependencies for tvm_ffi (#360)

## TL;DR
- Added explicit `Threads::Threads` linkage for both `tvm_ffi_shared` and `tvm_ffi_static` targets
- Added explicit `${CMAKE_DL_LIBS}` linkage (i.e., `libdl`) for shared and static targets when `TVM_FFI_USE_EXTRA_CXX_API` is enabled
- Fixes linker errors on systems where these are not implicitly linked (e.g., Linux with strict symbol resolution)

## Why (intent / motivation)
- `src/ffi/backtrace.cc` uses `std::mutex` which requires `libpthread` on Linux
- `src/ffi/extra/library_module_dynamic_lib.cc` calls `dlopen`, `dlsym`, etc. which require `libdl`
- Without explicit linkage, builds on certain Linux configurations fail with undefined symbol errors (issue #344)

## What changed (facts from diff)
- `CMakeLists.txt`: `find_package(Threads REQUIRED)` added near top
- `target_link_libraries(tvm_ffi_shared PRIVATE Threads::Threads)` added
- `target_link_libraries(tvm_ffi_static INTERFACE Threads::Threads)` added
- Conditional block added: if `TVM_FFI_USE_EXTRA_CXX_API` and `CMAKE_DL_LIBS` is non-empty, link `${CMAKE_DL_LIBS}` into both shared (PRIVATE) and static (INTERFACE) targets
