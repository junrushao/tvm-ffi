# 9582540 — chore: Add linters for `.rst`, `.md` and `.yaml` (#46)

## TL;DR
- Adds `yamllint`, `markdownlint-cli2`, and `rstcheck` to the pre-commit configuration
- Introduces config files `.yamllint.yaml`, `.markdownlint-cli2.yaml`, and `docs/.rstcheck.cfg`
- Performs initial cleanup passes on all affected Markdown and RST documentation files to satisfy the new linters
- Allows `.cfg` as a permitted file extension in the file-type lint script

## Why (intent / motivation)
- Doc and config files had no style enforcement, leading to inconsistent formatting
- Centralised linter configurations prevent future regressions

## What changed (facts from diff)
- `.pre-commit-config.yaml`: three new hook repos added (`yamllint`, `markdownlint-cli2`, `rstcheck`)
- `.yamllint.yaml`: new config extending `default`, disabling document-start, setting 120-char line limit, specifying truthy values
- `.markdownlint-cli2.yaml`: new config disabling MD013 (line-length rule)
- `docs/.rstcheck.cfg`: new config ignoring common Sphinx directives/roles
- Multiple `.md` files in `docs/` and `examples/` reformatted (blank lines around lists/code blocks, code fences given explicit language tags like `bash` or `text`)
- `.asf.yaml` and `.clang-format` whitespace normalised
- `tests/lint/check_file_type.py`: `"cfg"` added to `ALLOW_EXTENSION`

## Public surface changes (if any)
- API: none
- Flags/config: new linter config files in repo root and `docs/`
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/lint/check_file_type.py` (allow `.cfg`)
- How to verify manually: `pre-commit run --all-files`
- CI impact: linting failures on `.yaml`/`.md`/`.rst` files will now block CI
