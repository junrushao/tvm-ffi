# 0ee6444 — Minor improvement on type hint of `register_object` (#212)

## TL;DR
- Introduces a `TypeVar` `_T` bound to `type` so `register_object` preserves the decorated class's concrete type
- Eliminates false type-checker errors where decorated classes were treated as plain values instead of their original types

## Why (intent / motivation)
- Before this change, applying `@register_object(...)` caused type linters to widen the decorated class to `type`, losing all class-specific attributes and causing lint errors in downstream code

## What changed (facts from diff)
- `_T = TypeVar("_T", bound=type)` added to `registry.py`
- `register_object` signature changed from `Callable[[type], type]` return to `Callable[[_T], _T]`
- Internal helpers `_register`, `_decorator_with_name`, `_decorator_default` updated to use `_T` instead of `type`
- The `type_key` parameter type narrowed from `str | type | None` to `str | None` (non-string direct invocations were already handled by `_decorator_default`)

## Public surface changes (if any)
- API: `register_object` signature change is type-annotation-only; runtime behavior unchanged
- Flags/config: none
