# 1c9b17a — [Metal] Fix `GetFunction` of metal runtime (#18034)

## TL;DR
- Fixes a CMake condition to only run `dsymutil` (debug symbol generation) on macOS when libbacktrace is enabled.
- The original condition `if(APPLE)` caused `dsymutil` to run unconditionally on macOS, which was incorrect.

## Why (intent / motivation)
- The Metal runtime `GetFunction` bug (described in the body) involved a lambda returning early from an `autoreleasepool` block; the fix here is in the CMake build helper that guards `dsymutil` execution behind the `TVM_FFI_USE_LIBBACKTRACE` flag so debug symbols are only generated when libbacktrace is in use.
- This prevents unnecessary `dsymutil` calls when building without libbacktrace.

## What changed (facts from diff)
- `cmake/Utils/Library.cmake`: `if(APPLE)` → `if(APPLE AND TVM_FFI_USE_LIBBACKTRACE)` in the `add_dsymutil` function.

## Public surface changes (if any)
- API: none
- Flags/config: `dsymutil` post-build step now conditional on `TVM_FFI_USE_LIBBACKTRACE`.
- Data formats/schemas: none
