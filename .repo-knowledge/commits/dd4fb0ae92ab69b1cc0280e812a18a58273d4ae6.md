# dd4fb0a — feat: Introduce flexible `TypeSchema.repr(ty_map)` (#94)

## TL;DR
- Adds a new `TypeSchema.repr(ty_map=None)` method that accepts an optional callable to override the string representation of specific type origins (e.g., map `"list"` to `"Sequence"`, `"dict"` to `"Mapping"`).
- Existing `__repr__` delegates to `repr(ty_map=None)` so behavior is unchanged by default.
- `TypeSchema` dataclass is made mutable (removes `frozen=True`) so `list` and `dict` with zero args can have their `args` filled in (`Any` defaults).
- Adds test functions `testing.schema_id_arr` and `testing.schema_id_map` for bare `ArrayObj*` / `MapObj*` types.
- Updates `core.pyi` with rich docstrings for all major FFI types.

## Why (intent / motivation)
- Downstream schema generation tools (e.g., stub generators) need to rename type origins like `list` -> `Sequence` for `collections.abc` compatibility without modifying the underlying schema.

## What changed (facts from diff)
- `python/tvm_ffi/cython/type_info.pxi`: `TypeSchema` loses `frozen=True`; `__repr__` delegates to `repr()`; `repr(ty_map)` method added; `list`/`dict` with empty `args` now default to `(TypeSchema("Any"),)` / `(TypeSchema("Any"), TypeSchema("Any"))`.
- `python/tvm_ffi/core.pyi`: Extensive docstring additions for `Object`, `Function`, `Tensor`, `TypeSchema`, `TypeField`, `TypeMethod`, `TypeInfo`, `Error`, `DataType`, `Device`, etc.
- `src/ffi/extra/testing.cc`: Adds `testing.schema_id_arr` and `testing.schema_id_map` functions.
- `tests/cpp/test_metadata.cc` and `tests/python/test_metadata.py`: New test cases for bare array/map schemas and `repr(ty_map)` with list/dict remapping.

## Public surface changes (if any)
- API: `TypeSchema.repr(ty_map=None) -> str` added; `TypeSchema.__repr__` unchanged semantically.
- Flags/config: none
- Data formats/schemas: Bare `ffi.Array` and `ffi.Map` (no type args) now render as `list[Any]` / `dict[Any, Any]` in Python repr.
