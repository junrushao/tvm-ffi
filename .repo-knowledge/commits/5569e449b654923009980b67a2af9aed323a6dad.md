# 5569e44 — [Minor] Improve tuple functionality (#219)

## TL;DR
- Adds C++17 structured binding support to `tvm::ffi::Tuple<Types...>` via `std::tuple_size` and `std::tuple_element` specializations and ADL-friendly `get()` free functions
- Adds an rvalue overload of `Tuple::get<I>()` that moves out the element when the tuple has unique ownership
- Adds a C++17 deduction guide so `Tuple{1, 2.0f, String{"hello"}}` works without explicit template arguments
- Adds comprehensive tests for all new features

## Why (intent / motivation)
- Improves C++ readability by enabling `auto [a, b, c] = tuple;` structured bindings
- The rvalue `get()` overload allows zero-copy element extraction when the caller is the sole owner

## What changed (facts from diff)
- `include/tvm/ffi/container/tuple.h`:
  - `get() const&` (lvalue) overload unchanged; added `get() &&` (rvalue) overload that calls `AnyUnsafe::MoveFromAnyAfterCheck` if `this->unique()`, otherwise falls back to the copy path
  - Added ADL-friendly free functions `get<I>(const Tuple<...>&)` and `get<I>(Tuple<...>&&)` outside the `tvm::ffi` namespace (inside `tvm::ffi` but with using-guide pattern)
  - Added C++17 deduction guide `Tuple(UTypes&&...) -> Tuple<remove_cv_t<remove_reference_t<UTypes>>...>`
  - Added `std::tuple_size` and `std::tuple_element` specializations in namespace `std`
  - Added `#include <cstddef>` and `#include <type_traits>`
- `tests/cpp/test_tuple.cc`: New `TEST(Tuple, CPPFeatures)` covering deduction guide, structured binding (lvalue), ADL get, rvalue structured binding (move semantics), and ref-count behavior
