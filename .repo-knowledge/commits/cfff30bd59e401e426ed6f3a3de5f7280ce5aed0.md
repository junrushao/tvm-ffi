# cfff30b — [CYTHON] Fix potential flaky issue in dispatcher (#63)

## TL;DR
- Fixes a use-after-free / type confusion bug in the Cython argument dispatcher.
- Registered types could be garbage-collected and their address reused by a different type, causing wrong dispatch.
- The fix retains all registered types in a thread-safe `_DISPATCH_TYPE_KEEP_ALIVE` set.

## Why (intent / motivation)
- The C++ dispatcher keys on `TYPE(obj)` pointer (non-owning). A locally-defined Python type could be GC'd and a new type allocated at the same address, silently misdispatching arguments at runtime.

## What changed (facts from diff)
- Added module-level `_DISPATCH_TYPE_KEEP_ALIVE: set` and `_DISPATCH_TYPE_KEEP_ALIVE_LOCK: threading.Lock` in `function.pxi`.
- In `TVMFFIPyArgSetterFactory_`, every `type(arg)` is now added to the keep-alive set under the lock before proceeding with dispatch selection.
- Lock is used for future thread-free Python ABI compatibility.
