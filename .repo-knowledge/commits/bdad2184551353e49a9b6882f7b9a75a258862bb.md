# bdad218 — fix: Type mismatch aborts on OpaquePyObject (#56)

## TL;DR
- Registers `TypeIndex::kTVMFFIOpaquePyObject` as a built-in type index in the type table, preventing an `exit(1)` crash when a type-mismatch error message attempts to look up the type info for `OpaquePyObject`
- Adds `StaticTypeKey::kTVMFFIOpaquePyObject` constant in `object.h`
- New test verifies that passing an `OpaquePyObject` to a function expecting `int` produces a proper `TypeError` message

## Why (intent / motivation)
- When an `OpaquePyObject` was passed to an FFI function expecting a different type, the error-formatting code called `TVMFFIGetTypeInfo(74)` but type index 74 was not registered, causing the program to call `exit(1)` rather than raising a proper Python exception

## What changed (facts from diff)
- `include/tvm/ffi/object.h`: `StaticTypeKey::kTVMFFIOpaquePyObject = "ffi.OpaquePyObject"` added
- `src/ffi/object.cc`: `ReserveBuiltinTypeIndex(StaticTypeKey::kTVMFFIOpaquePyObject, TypeIndex::kTVMFFIOpaquePyObject)` called in type table initialisation
- `src/ffi/extra/testing.cc`: `testing.add_one` global function registered (`int -> int`)
- `python/tvm_ffi/testing.py`: `add_one(x: int) -> int` helper added
- `tests/python/test_object.py`: `test_opaque_type_error` test added
