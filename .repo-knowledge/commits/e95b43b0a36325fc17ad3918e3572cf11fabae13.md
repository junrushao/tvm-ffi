# e95b43b — [FFI][REFACTOR] Modularize reflection (#18147)

## TL;DR
- Splits `include/tvm/ffi/reflection/reflection.h` into two files: `registry.h` (registration APIs) and a new `accessor.h` (field/method access helpers).
- Accessor utilities (`GetFieldInfo`, `FieldGetter`, `FieldSetter`, `GetMethodInfo`, `GetMethod`, `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`) move to `accessor.h`.
- All source files that previously included `reflection.h` are updated to include `registry.h` (or `accessor.h` where needed).

## Why (intent / motivation)
- `reflection.h` had grown to contain both registration-time definitions and runtime accessor utilities; splitting improves include hygiene and reduces compile-time coupling.

## What changed (facts from diff)
- `include/tvm/ffi/reflection/accessor.h` (new, 198 lines): contains `GetFieldInfo`, `FieldGetter`, `FieldSetter`, `GetMethodInfo`, `GetMethod`, `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`.
- `include/tvm/ffi/reflection/{reflection.h => registry.h}`: renamed; accessor code removed (~162 lines deleted).
- All `.cc` and `.h` consumers updated to `#include <tvm/ffi/reflection/registry.h>` or `accessor.h`.

## Public surface changes (if any)
- API: `tvm/ffi/reflection/reflection.h` is replaced by `tvm/ffi/reflection/registry.h`; downstream code must update includes.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_reflection.cc` — includes both `accessor.h` and `registry.h`.
- How to verify manually: `cmake --build build_test && ctest -V --test-dir build_test`
- CI impact: any code including `reflection.h` directly will fail to compile.

## Risk & rollout notes
- Risk level: medium — breaking include path change for all downstream consumers of `reflection.h`.
- Rollout/migration: Change all `#include <tvm/ffi/reflection/reflection.h>` to `#include <tvm/ffi/reflection/registry.h>` (and optionally `accessor.h`).
- Follow-ups: none
