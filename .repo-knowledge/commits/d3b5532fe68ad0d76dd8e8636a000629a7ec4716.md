# d3b5532 — fix: handle UTF-8 bytes correctly in JSON parser control character check (#442)

## TL;DR
- Casts `*cur_` to `uint8_t` before comparing against space (0x20) in the JSON string parser.
- Fixes a bug where valid UTF-8 multi-byte sequences (bytes >= 0x80) were misinterpreted as negative values on platforms with signed `char`, causing all non-ASCII strings to be rejected as "Invalid control character".
- Adds a regression test covering raw UTF-8 bytes (Chinese characters).

## Why (intent / motivation)
- On platforms where `char` is signed (common on x86 Linux/macOS), bytes >= 0x80 (UTF-8 continuation or lead bytes) produce negative values. Comparing them against space (0x20) with `*cur_ < ' '` incorrectly triggered the control-character fallback path, rejecting valid UTF-8 strings entirely.

## What changed (facts from diff)
- In `NextStringFastPath`: condition changed from `*cur_ < ' '` to `*reinterpret_cast<const uint8_t*>(cur_) < ' '`.
- In `NextStringWithFullHandling`: same fix applied to the control-character error path.
- Added `TEST(JSONParser, RawUTF8Bytes)` in `tests/cpp/extra/test_json_parser.cc` that roundtrips a raw 6-byte UTF-8 Chinese string.
