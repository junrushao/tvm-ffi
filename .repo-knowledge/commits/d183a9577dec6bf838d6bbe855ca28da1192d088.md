# d183a95 — [DLL] Explicit link libtvm_ffi_testing from cython (#132)

## TL;DR
- Links `tvm_ffi_cython` explicitly against `tvm_ffi_testing` to guarantee unloading order (cython unloads before testing library).
- Removes the dynamic `load_module` approach in `testing.py` in favor of static linking.
- Calls `TVMFFITestingDummyTarget()` at Cython module init to ensure the testing library is loaded.

## Why (intent / motivation)
- If `libtvm_ffi_testing` is unloaded before the Cython module (when loaded via `load_module`), global objects registered in the testing library can have invalid deleters. Explicit linking ensures the linker controls the unloading order correctly.

## What changed (facts from diff)
- `CMakeLists.txt`: Added `target_link_libraries(tvm_ffi_cython PRIVATE tvm_ffi_testing)`.
- `python/tvm_ffi/cython/base.pxi`: Declares `TVMFFITestingDummyTarget()` from `tvm_ffi_python_helpers.h`; calls it at module init.
- `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`: Declares `extern "C" TVMFFITestingDummyTarget()`.
- `python/tvm_ffi/testing.py`: Removes dynamic library loading of `tvm_ffi_testing` (now statically linked).
