# 538bef4 — [FFI] Formalize ffi.Module (#18213)

## TL;DR
- Introduces `ffi::Module` / `ffi::ModuleObj` as a formalized extra API for dynamic module loading, replacing ad-hoc runtime::Module usage.
- Adds `Library` base class and concrete implementations: `LibraryModuleObj` (DSO/system-lib wrapper), `DSOLibrary`, `SystemLibrary`.
- Exposes `ffi.ModuleLoadFromFile`, `ffi.ModuleGetFunction`, `ffi.ModuleImportModule`, etc. as global functions.
- Adds `TVMFFIEnvLookupFromImports` and `TVMFFIEnvRegisterContextSymbol` C API functions.
- Adds `BufferInStream` helper for reading module binary blobs embedded in library files.

## Why (intent / motivation)
- Formalizes the module system within the FFI layer so that library plugins can use a stable, minimal API for loading and invoking packed functions from shared libraries.
- Enables embedding serialized binary modules inside `.so` files (via `__tvm_ffi_library_bin` symbol).

## What changed (facts from diff)
- New `include/tvm/ffi/extra/module.h`: `ModuleObj` (abstract virtual base), `Module` (ObjectRef), `ModulePropertyMask` enum (`kBinarySerializable`, `kRunnable`, `kCompilationExportable`), `symbol::` namespace constants.
- New `include/tvm/ffi/extra/c_env_api.h`: C API declarations for module symbol management (`TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`).
- New `src/ffi/extra/module.cc`: Module methods, `Module::LoadFromFile`, global function registrations.
- New `src/ffi/extra/library_module.cc`: `LibraryModuleObj`, `ProcessLibraryBin`, `ContextSymbolRegistry`, `CreateLibraryModule`.
- New `src/ffi/extra/library_module_dynamic_lib.cc`: `DSOLibrary` with platform-specific dlopen/LoadLibrary; registers `ffi.Module.load_from_file.so`.
- New `src/ffi/extra/library_module_system_lib.cc`: `SystemLibrary`, `SystemLibModuleRegistry`; registers `ffi.SystemLib`.
- New `src/ffi/extra/module_internal.h`: `Library` class, `ModuleObj::InternalUnsafe` for internal access.
- New `src/ffi/extra/buffer_stream.h`: `BufferInStream` for reading binary data from memory buffers.
- `include/tvm/ffi/object.h`: Added `kTVMFFIModule` static type key; fixed macro trailing semicolons.
- `CMakeLists.txt`: Added 4 new source files to extra sources list.

## Public surface changes (if any)
- API: New `ffi::Module`, `ffi::ModuleObj` classes. New C API `TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`. New global functions: `ffi.ModuleLoadFromFile`, `ffi.ModuleGetFunction`, `ffi.ModuleImportModule`, `ffi.ModuleClearImports`, `ffi.ModuleGetKind`, `ffi.SystemLib`, `ffi.Module.load_from_file.so`.
- Flags/config: Requires `TVM_FFI_USE_EXTRA_CXX_API=ON` in CMake.
- Data formats/schemas: Library binary format: `<nbytes:u64> <import_tree_indptr:vec<u64>> <import_tree_child_indices:vec<u64>> <kind:str> [<bytes:str>] ...`.

## Tests & verification
- Added/updated tests: none in this commit
- How to verify manually: Build with `TVM_FFI_USE_EXTRA_CXX_API=ON` and call `Module::LoadFromFile("library.so")`.
- CI impact: New extra source files added.

## Risk & rollout notes
- Risk level: medium — Large new surface area; replaces an existing pattern (runtime::Module). Symbol naming (`TVMFFIEnvLookupFromImports` etc.) later renamed in a follow-up commit.
- Rollout/migration: Python bindings for Module will need to use the new global function APIs.
- Follow-ups: API renaming (see commit 023ea44).
