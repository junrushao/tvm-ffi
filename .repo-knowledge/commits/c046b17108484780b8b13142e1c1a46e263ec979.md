# c046b17 — fix: Use `tvm_ffi.dtype` instead of `DataType` in schema (#93)

## TL;DR
- Adds a `"DataType" -> "dtype"` mapping entry to `_TYPE_SCHEMA_ORIGIN_CONVERTER` in the Cython type_info layer.
- This causes `DataType` fields and function arguments to be rendered as `dtype` (the user-facing alias) rather than the internal `DataType` name.
- Two test expectations in `test_metadata.py` updated to match (`"DataType"` -> `"dtype"`).

## Why (intent / motivation)
- `tvm_ffi.core.DataType` is an internal struct; `tvm_ffi.dtype` is the intended Python-facing interface. Schema strings should use the user-facing name for clarity.

## What changed (facts from diff)
- `python/tvm_ffi/cython/type_info.pxi`: `_TYPE_SCHEMA_ORIGIN_CONVERTER` dict gains `"DataType": "dtype"`.
- `tests/python/test_metadata.py`: expectations for `testing.schema_id_dtype` and the `v_dtype` field updated from `DataType` to `dtype`.

## Public surface changes (if any)
- API: `TypeSchema.repr()` for `DataType` types now returns `"dtype"` instead of `"DataType"`.
- Flags/config: none
- Data formats/schemas: Schema JSON origin tag unchanged (`"DataType"` still in JSON); only the rendered `repr()` string changes.
