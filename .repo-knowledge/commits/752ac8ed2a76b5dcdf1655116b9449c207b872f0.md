# 752ac8e — [PyTorch] Allow tensor conversion on rocm backend (#253)

## TL;DR
- Extended the torch-c-dlpack extension build system to support ROCm (HIP) backend in addition to CUDA.
- Detection logic now checks `torch.version.hip` to identify ROCm environments and passes `--build-with-rocm` flag accordingly.
- Added ROCm HIPStream include and `BUILD_WITH_ROCM` define to the AOT C++ source template.

## Why (intent / motivation)
- The previous code only handled CUDA and fell through to a CPU build on ROCm systems, breaking DLPack tensor conversion for PyTorch ROCm tensors.

## What changed (facts from diff)
- `addons/torch_c_dlpack_ext/build_backend.py`: Detect ROCm via `torch.version.hip`; pass `--build-with-rocm` when building AOT wheels.
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Device detection updated: `cuda`, `rocm`, or `cpu`; pass `--build-with-rocm` to JIT build.
- `python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`: Added `--build-with-rocm` CLI arg; added `#include <c10/hip/HIPStream.h>` and `BUILD_WITH_ROCM`; added ROCm HIP flags to compiler invocation; added mutual exclusion guard.
- `tests/python/test_optional_torch_c_dlpack.py`: Updated build test to detect ROCm.
- `tests/python/test_tensor.py`: Added `test_tensor_from_pytorch_rocm` test.
- `tests/scripts/benchmark_dlpack.py`: Added ROCm HIPStream implementation for benchmarking.

## Public surface changes (if any)
