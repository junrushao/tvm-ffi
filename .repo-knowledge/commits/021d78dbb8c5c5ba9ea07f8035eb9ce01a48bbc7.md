# 021d78d — [Test] Add test for filelock utility (#216)

## TL;DR
- Adds comprehensive tests for `FileLock` covering basic acquire/release, context manager usage, re-entrancy protection, exception safety, and concurrent multi-process access
- Fixes `FileLock.acquire()` to return `False` when already held by the same instance instead of raising or re-acquiring
- Adds a `RuntimeError` guard in `blocking_acquire()` when the lock is already held
- Improves docstrings on `acquire()` and `blocking_acquire()`

## Why (intent / motivation)
- `FileLock` lacked any test coverage, creating a risk of regression especially on different platforms (Linux, macOS, Windows)
- `acquire()` had no guard against same-instance double-acquire, which could cause confusion

## What changed (facts from diff)
- `python/tvm_ffi/utils/lockfile.py`: added `_file_descriptor is not None` guard in `acquire()` (returns `False`); added `RuntimeError` in `blocking_acquire()` if already held; docstrings updated to Google style with `Returns`/`Raises` sections; class docstring clarifies re-entrancy behavior
- `tests/python/utils/filelock_worker.py`: new 49-line worker script for multi-process concurrent test
- `tests/python/utils/test_filelock.py`: new 126-line test file with 5 tests: basic acquire/release, context manager, multiple acquire attempts, exception safety, and concurrent access (16 processes)

## Public surface changes (if any)
