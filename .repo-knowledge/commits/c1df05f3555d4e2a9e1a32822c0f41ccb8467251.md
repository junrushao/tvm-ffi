# c1df05f — [PYTHON] Further streamline number handling (#242)

## TL;DR
- Introduced two new protocol dunder methods `__tvm_ffi_int__` and `__tvm_ffi_float__` for custom integer/float conversion in FFI calls.
- Added dedicated Cython setters for `numbers.Integral` and `numbers.Real` subclasses to handle cases where the value is not exactly `int`/`float` (e.g., `numpy.int32`).
- Renamed `TVMFFIPyArgSetterFFIObjectCompatible_` to `TVMFFIPyArgSetterFFIObjectProtocol_` for consistency.

## Why (intent / motivation)
- `numbers.Integral` and `numbers.Real` subclasses (e.g., numpy scalar types) were routed through the generic `int`/`float` setters which required exact types, causing failures for subclasses.
- Adding `__tvm_ffi_int__` / `__tvm_ffi_float__` protocols lets third-party classes participate in FFI numeric dispatch without subclassing Python numeric ABCs.

## What changed (facts from diff)
- `cython/function.pxi`: Added `TVMFFIPyArgSetterIntegral_`, `TVMFFIPyArgSetterReal_`, `TVMFFIPyArgSetterIntProtocol_`, `TVMFFIPyArgSetterFloatProtocol_` setters; updated dispatch factory to use them.
- `_convert.py`: `convert()` now passes through objects with `__tvm_ffi_int__` or `__tvm_ffi_float__` unchanged.
- `tests/python/test_function.py`: Added `test_integral_float_variants_passing` testing numpy scalars and protocol classes.

## Public surface changes (if any)
