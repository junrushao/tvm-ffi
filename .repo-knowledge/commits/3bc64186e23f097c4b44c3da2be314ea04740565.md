# 3bc6418 — doc: Enable Doxygen Build Checks in CI (#42)

## TL;DR
- CI doc stage now installs Doxygen via `apt` and sets `BUILD_CPP_DOCS=1`, enabling full C++ API doc generation
- Doxygen configuration updated with `WARN_AS_ERROR`, additional `PREDEFINED` macros, and improved `EXCLUDE_SYMBOLS`
- Several C++ header files fixed to suppress false-positive Doxygen warnings (anonymous unions guarded, `\return` removed from constructors, etc.)

## Why (intent / motivation)
- C++ documentation was not validated in CI, allowing errors to accumulate unnoticed
- Full `BUILD_CPP_DOCS=1` run with `sphinx-build -W` ensures that Doxygen warnings also block merges

## What changed (facts from diff)
- `ci_test.yml`: `sudo apt install doxygen` added before the Sphinx build; `BUILD_CPP_DOCS=1` env var set
- `docs/conf.py`: expanded `PREDEFINED` macros (`TVM_FFI_DLL_EXPORT`, `TVM_FFI_WEAK`, `TVM_FFI_DOXYGEN_MODE`); `WARNINGS=YES`; `WARN_AS_ERROR=FAIL_ON_WARNINGS_PRINT`; `cpp_id_attributes` and `c_id_attributes` added for Sphinx
- `include/tvm/ffi/c_api.h`: anonymous `union` blocks wrapped in `#if !defined(TVM_FFI_DOXYGEN_MODE)` guards; union members given `/*! \brief ... */` doc comments
- `include/tvm/ffi/container/map.h`: `make_object<MapObj>() = delete` specialisation wrapped in `\cond Doxygen_Suppress`
- `include/tvm/ffi/container/tensor.h`: stray `/// \endcond` removed
- `include/tvm/ffi/reflection/access_path.h`: spurious `\return` removed from constructor doc
- `include/tvm/ffi/reflection/registry.h`: missing `\endcode` added; blank lines in doc comments cleaned up
