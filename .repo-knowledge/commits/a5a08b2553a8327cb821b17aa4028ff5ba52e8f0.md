# a5a08b2 — [FFI][REFACTOR] Migrate attrs to use new reflection (#18095)

## TL;DR
- Migrates the `DLDataType` type traits to clear the padding portion of the `Any` union before writing, ensuring equality checks on the `v_uint64` field are correct.
- Strengthens `TypeTable::RegisterTypeExtraInfo` to throw an error if the same type is registered twice, preventing duplicate `ObjectDef<T>` calls.
- Registers `Object` base type extra info during `TypeTable` initialization.

## Why (intent / motivation)
- `DLDataType` occupies fewer bytes than the `TVMFFIAny` union; without zeroing the padding, two logically equal `DLDataType` values could compare unequal via `v_uint64`.
- Duplicate type registration silently overwrote prior info; now it throws with a helpful diagnostic message.

## What changed (facts from diff)
- `include/tvm/ffi/dtype.h` (+4/-0): both `CopyToAnyView` and `MoveToAny` now zero `result->v_uint64` before setting `v_dtype`, clearing padding.
- `src/ffi/object.cc` (+27/-12): `RegisterTypeExtraInfo` now throws `RuntimeError` if called twice for the same type; adds `Object` base type extra info registration at startup.

## Public surface changes (if any)
- API: `TypeTable::RegisterTypeExtraInfo` throws on duplicate registration (previously silent overwrite).
- Flags/config: none
- Data formats/schemas: `DLDataType` `Any` representation now always has zeroed padding.

## Tests & verification
- Added/updated tests: none
- How to verify manually: Run test suite; verify that duplicate `ObjectDef<T>` definitions now produce a `RuntimeError` instead of silent behavior.
- CI impact: none

## Risk & rollout notes
- Risk level: low — Correctness fix for equality comparison; behavior change only if padding was being relied on (incorrect usage).
- Rollout/migration: Fix any code that registers the same type twice via `ObjectDef<T>()`.
