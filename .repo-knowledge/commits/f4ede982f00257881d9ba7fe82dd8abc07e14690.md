# f4ede98 — [FFI][REFACTOR] Refactor AccessPath to enable full tree repr (#18191)

## TL;DR
- Refactors `AccessPath` from a flat `Array<AccessStep>` alias to a parent-pointing tree structure (`AccessPathObj`/`AccessPath`) for space-efficient representation of paths sharing a common prefix.
- Renames `AccessKind::kObjectField` to `kAttr` and adds `kAttrMissing`, aligning terminology across accessors.
- Moves `MakeObjectFromPackedArgs` and reflection registrations from `src/ffi/object.cc` to a new `src/ffi/extra/reflection_extra.cc`, gating them behind `TVM_FFI_USE_EXTRA_CXX_API`.
- Fixes a bug in the Cython method export (referenced in commit body).

## Why (intent / motivation)
- A flat array representation duplicates shared prefix steps; the tree representation is more compact when multiple paths share a common prefix (e.g., in structural equality mismatch reporting).
- Consolidates reflection-related global registrations into the extra API layer rather than the core object layer.

## What changed (facts from diff)
- `AccessPath` is now a first-class `ObjectRef` wrapping `AccessPathObj` with `parent`, `step`, and `depth` fields.
- New builder methods: `Root()`, `Attr()`, `AttrMissing()`, `ArrayItem()`, `ArrayItemMissing()`, `MapItem()`, `MapItemMissing()`, `Extend()`, `ToSteps()`, `PathEqual()`, `IsPrefixOf()`, `GetParent()`, `FromSteps()`.
- `AccessStep::ObjectField()` renamed to `AccessStep::Attr()`; new `AccessStep::AttrMissing()` factory.
- `src/ffi/reflection/access_path.cc` deleted; content moved to `src/ffi/extra/reflection_extra.cc`.
- `CMakeLists.txt`: removed `src/ffi/reflection/access_path.cc` from core sources; added `src/ffi/extra/reflection_extra.cc` to extra sources.
- Tests updated to use fluent path-builder API (`Root()->Attr("body")->ArrayItem(1)`) instead of array initializer lists.

## Public surface changes (if any)
- API: `AccessPath` is no longer a `Array<AccessStep>` typedef; it is now a distinct `ObjectRef` class. Callers must use `ToSteps()` or the fluent builder. `AccessKind::kObjectField` renamed to `kAttr`.
- Flags/config: none
- Data formats/schemas: Type key changed from `"tvm.ffi.reflection.AccessStep"` to `"ffi.reflection.AccessStep"`; new `"ffi.reflection.AccessPath"` type registered.

## Tests & verification
- Added/updated tests: `tests/cpp/test_reflection.cc` (+104 lines, new `TEST(Reflection, AccessPath)`), `tests/cpp/extra/test_structural_equal_hash.cc` (updated to new API).
- How to verify manually: `cmake . -B build_test -DTVM_FFI_BUILD_TESTS=ON && cmake --build build_test --target tvm_ffi_tests && ctest --test-dir build_test`
- CI impact: Build changes require `TVM_FFI_USE_EXTRA_CXX_API` for reflection extras.

## Risk & rollout notes
- Risk level: medium — Breaks any downstream code that used `AccessPath` as `Array<AccessStep>` directly or referenced `AccessKind::kObjectField` / `AccessStep::ObjectField()`.
- Rollout/migration: Replace `AccessPath({step1, step2})` with `AccessPath::FromSteps({step1, step2})`; replace `kObjectField`/`ObjectField()` with `kAttr`/`Attr()`.
- Follow-ups: Python bindings for `AccessPath` (exposed via `ffi.reflection.AccessPath` methods in reflection_extra.cc).
