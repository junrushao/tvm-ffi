# 80bd4d8 — [TORCH] Patch cuda stream protocol for older torch (#110)

## TL;DR
- Adds `patch_torch_cuda_stream_protocol()` in `python/tvm_ffi/_optional_torch_c_dlpack.py` that monkey-patches `torch.cuda.Stream.__cuda_stream__` on Torch versions that do not provide it natively.

## Why (intent / motivation)
- The CUDA stream protocol (`__cuda_stream__`) was introduced in newer Torch versions. Older versions lack it, so `TVMFFIPyArgSetterCUDAStream_` (added in #109) would not recognize `torch.cuda.Stream` objects. The patch ensures backward compatibility.

## What changed (facts from diff)
- `python/tvm_ffi/_optional_torch_c_dlpack.py`:
  - Defines `patch_torch_cuda_stream_protocol()`: if `torch.cuda` is available and `torch.cuda.Stream` does not already have `__cuda_stream__`, installs a method returning `(0, self.cuda_stream)` (version 0, raw stream pointer).
  - Calls `patch_torch_cuda_stream_protocol()` at module import time.

## Public surface changes (if any)
- API: `torch.cuda.Stream.__cuda_stream__` is added on older Torch if missing.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none (relies on existing stream tests)
- How to verify manually: use an older Torch build without native `__cuda_stream__` support; pass a `torch.cuda.Stream` to an FFI function and verify it is received as an opaque pointer.
- CI impact: none

## Risk & rollout notes
- Risk level: low — patch is guarded by `hasattr` check; no-op on newer Torch
- Rollout/migration: none
- Follow-ups: remove patch once minimum supported Torch includes `__cuda_stream__` natively
