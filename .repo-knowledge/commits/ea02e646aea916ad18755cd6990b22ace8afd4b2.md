# ea02e64 — feat: stub generation (#101)

## TL;DR
- Introduces `tvm-ffi-stubgen`, a CLI tool and Python module (`tvm_ffi.stub.stubgen`) that generates in-place, static type stubs inside specially-marked comment blocks in `.py`/`.pyi` files.
- Supports two stub block types: `global/<prefix>` (generates function signatures from the FFI global registry) and `object/<type_key>` (generates field/method signatures from reflection metadata).
- Deletes the old hand-written `python/tvm_ffi/_ffi_api.pyi` stub file and replaces it with a `tvm-ffi-stubgen` block in `_ffi_api.py`.
- Adds stub blocks to `testing.py`, `access_path.py`, `module.py`, and the packaging example.

## Why (intent / motivation)
- Hand-written stubs become stale; generated stubs derived from runtime FFI metadata are always accurate and eliminate `# type: ignore` annotations.

## What changed (facts from diff)
- `python/tvm_ffi/stub/__init__.py` (new): package init.
- `python/tvm_ffi/stub/stubgen.py` (new, 528 lines): full implementation of the stub generator CLI.
- `python/tvm_ffi/_ffi_api.py`: adds `tvm-ffi-stubgen(begin/end)` block with generated `ffi.*` function stubs.
- `python/tvm_ffi/_ffi_api.pyi`: deleted.
- `python/tvm_ffi/access_path.py`: adds `object/ffi.reflection.AccessStep` and `object/ffi.reflection.AccessPath` blocks; removes `# type: ignore` annotations.

## Public surface changes (if any)

- Data formats/schemas: Comment markers `# tvm-ffi-stubgen(begin): ...` / `# tvm-ffi-stubgen(end)` / `# tvm-ffi-stubgen(ty_map): A -> B` / `# tvm-ffi-stubgen(skip-file)`.

## Risk & rollout notes

- Rollout/migration: Downstream projects can add `tvm-ffi-stubgen` blocks to their own modules.
- Follow-ups: CLAUDE.md documents `uv run tvm-ffi-stubgen python` for regeneration.
