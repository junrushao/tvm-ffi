# 408aa78 — [DTYPE] Include dtype literals (#263)

## TL;DR
- Added pre-constructed `dtype` literal instances for all common ML dtypes directly in `_dtype.py` and re-exported from the top-level `tvm_ffi` namespace.
- `tvm_ffi.convert` now short-circuits for `dtype` instances to avoid redundant conversion.
- Covers: `bool`, int8/16/32/64, uint8/16/32/64, float16/32/64, bfloat16, float8 variants, float4x2.

## Why (intent / motivation)
- Users frequently need to pass standard dtypes to FFI functions; pre-constructed literals avoid repeated string parsing and provide tab-completion in IDEs.
- Aligns with NumPy 2.0 naming (e.g., `bool` instead of `bool_`).

## What changed (facts from diff)
- `python/tvm_ffi/_dtype.py`: Added module-level dtype instances (`bool`, `int8`, ..., `float4_e2m1fnx2`, `float4_e2m1fn_x2` alias).
- `python/tvm_ffi/__init__.py`: Imported all dtype literals from `_dtype` into the top-level namespace.
- `python/tvm_ffi/_convert.py`: Added `_dtype.dtype` to the early-return isinstance check in `convert()`.
- `tests/python/test_dtype.py`: Added `test_builtin_dtype_conversion` checking all 18 literals.

## Public surface changes (if any)
- API: New public attributes `tvm_ffi.bool`, `tvm_ffi.int8`, `tvm_ffi.int16`, `tvm_ffi.int32`, `tvm_ffi.int64`, `tvm_ffi.uint8`, `tvm_ffi.uint16`, `tvm_ffi.uint32`, `tvm_ffi.uint64`, `tvm_ffi.float16`, `tvm_ffi.float32`, `tvm_ffi.float64`, `tvm_ffi.bfloat16`, `tvm_ffi.float8_e4m3fn`, `tvm_ffi.float8_e4m3fnuz`, `tvm_ffi.float8_e5m2`, `tvm_ffi.float8_e5m2fnuz`, `tvm_ffi.float8_e8m0fnu`, `tvm_ffi.float4_e2m1fnx2`.
- Flags/config: none
