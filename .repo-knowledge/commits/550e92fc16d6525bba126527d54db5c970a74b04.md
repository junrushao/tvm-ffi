# 550e92f — [C-API] TVMFFIErrorSetRaisedFromCStrParts (#107)

## TL;DR
- Adds `TVMFFIErrorSetRaisedFromCStrParts` to the C ABI — a new function that concatenates multiple `const char*` parts into a single error message, allowing DSL compilers to reuse common parts (e.g., function signatures) across multiple error messages.
- Bumps the package version from `0.1.0b16` to `0.1.0b17`.
- Updates docs and the quickstart example to reference the new API.

## Why (intent / motivation)
- When DSL compilers report errors, common substrings such as function signatures appear repeatedly. Storing full copies wastes memory in minimal runtimes. `TVMFFIErrorSetRaisedFromCStrParts` lets compilers pass an array of string parts that are concatenated once, reducing duplication.

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: declares `TVMFFIErrorSetRaisedFromCStrParts(const char* kind, const char** message_parts, int32_t num_parts)`; updates docstring of `TVMFFISafeCallType` to reference the new function; fixes doc comment on `TVMFFIErrorSetRaisedFromCStr` (references `TVMFFIErrorMoveFromRaised` correctly).
- `src/ffi/error.cc`: implements `SafeCallContext::SetRaisedByCstrParts` (pre-computes total length, appends each non-NULL part); adds `TVMFFIErrorSetRaisedFromCStrParts` DLL export.
- `src/ffi/backtrace_utils.h`: adds `ShouldExcludeFrame` guard for `TVMFFIErrorSetRaisedFromCStrParts` so it is excluded from backtraces (mirrors the existing guard for `TVMFFIErrorSetRaisedFromCStr`).
- `tests/cpp/test_function.cc`: adds `TEST(SetRaisedFromCStr, ValueError)` and `TEST(SetRaisedFromCStrParts, TypeError)` — the latter verifies that NULL parts are skipped.
- `docs/concepts/abi_overview.md` and `docs/guides/compiler_integration.md`: mention `TVMFFIErrorSetRaisedFromCStrParts`.
- `examples/quick_start/src/add_one_c.c`: updates comment to mention the new API.
- `pyproject.toml` and `python/tvm_ffi/__init__.py`: version bumped to `0.1.0b17`.
