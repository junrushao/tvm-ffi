# 16e9f0a — [REFACTOR][FFI] Cleanup container redirections (#17929)

## TL;DR
- Exposes key FFI types into the `tvm::` namespace via `using` declarations at the bottom of each header.
- Affects `Array`, `Map`, `Tuple`, `Variant`, `String`, `Optional`, `Memory`, `Downcast`, `GetRef`, and `Function` types.
- Updates `Map::Get` doc comment: "NullOpt" → "std::nullopt".
- No behavioral changes; purely usability and namespace ergonomics.

## Why (intent / motivation)
- Allow existing TVM code that uses `tvm::Array`, `tvm::Map` etc. (without the `ffi::` qualifier) to continue working after types moved to the `tvm::ffi` namespace.
- Avoids requiring every downstream file to add `using namespace tvm::ffi` or update qualified names.

## What changed (facts from diff)
- `include/tvm/ffi/cast.h`: added `using ffi::Downcast; using ffi::GetRef;` in `tvm` namespace.
- `include/tvm/ffi/container/array.h`: added `using ffi::Array;` in `tvm` namespace.
- `include/tvm/ffi/container/map.h`: added `using ffi::Map;`, doc fix "NullOpt" → "std::nullopt".
- `include/tvm/ffi/container/tuple.h`: added `using ffi::Tuple;`.
- `include/tvm/ffi/container/variant.h`: added `using ffi::Variant;`.
- `include/tvm/ffi/function.h`: added `using ffi::Function;`.
- `include/tvm/ffi/memory.h`: added `using ffi::make_object;`.
- `include/tvm/ffi/optional.h`: added `using ffi::Optional;`.
- `include/tvm/ffi/string.h`: added `using ffi::String; using ffi::Bytes;`.
