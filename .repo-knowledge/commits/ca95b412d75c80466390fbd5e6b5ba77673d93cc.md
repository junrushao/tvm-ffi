## TL;DR

`NDArrayObjFromNDAlloc` now always computes and stores C-contiguous strides for newly allocated tensors. A new `MakeStridesFromShape()` helper in `shape.h` computes strides from a shape array. Tensors imported from DLPack with `nullptr` strides also have strides filled in automatically.

## Why

Previously, `NDArray.strides` could be `nullptr` for newly allocated tensors (which implied C-contiguous layout by DLPack convention). Making strides explicit at allocation time eliminates the need for callers to handle the `nullptr` strides case, simplifies downstream code, and makes the tensor layout unambiguously represented.

## What changed

- `include/tvm/ffi/container/shape.h`: Added `details::MakeStridesFromShape(ndim, shape_data)` free function that computes row-major (C-contiguous) strides from a shape array.
- `include/tvm/ffi/container/ndarray.h`:
  - `NDArrayObjFromNDAlloc()`: Now calls `MakeStridesFromShape()` and stores strides in the allocated `NDArrayObj`.
  - `NDArrayObjFromDLPack()`: If the incoming `DLTensor.strides` is `nullptr`, fills strides using `MakeStridesFromShape()`.
- `tests/cpp/test_ndarray.cc`: Added tests verifying that allocated tensors have non-null strides equal to the C-contiguous values.

## Public surface changes

- `NDArray.strides` is now guaranteed to be non-`nullptr` for tensors allocated via `NDArrayObjFromNDAlloc` or imported via `NDArrayObjFromDLPack`. Code that previously checked for `nullptr` strides can now assume they are always present.
- New internal helper: `tvm::ffi::details::MakeStridesFromShape()`

## Tests & verification

New C++ tests in `tests/cpp/test_ndarray.cc` verify that strides are populated for freshly allocated tensors.

## Risk & rollout notes

Low risk. Strides are now always populated; downstream code that assumed `nullptr` strides implied C-contiguous still works correctly because the explicit strides encode the same layout. No public API signature changes.
