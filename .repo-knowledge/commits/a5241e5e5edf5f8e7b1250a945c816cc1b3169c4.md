# a5241e5 — [ADDON] Fix import issue (#227)

## TL;DR
- Fixes `torch_c_dlpack_ext/__init__.py` import from bare `import core` to `from . import core` (relative import)
- Adds `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` env var to the wheel build subprocess to prevent cyclic import during AOT build
- Fixes the JIT fallback path in `_optional_torch_c_dlpack.py` to correctly check `torch.Tensor.__c_dlpack_exchange_api__` after the AOT package loads
- Bumps `torch_c_dlpack_ext` version from 0.1.0 to 0.1.1

## Why (intent / motivation)
- The bare `import core` in `__init__.py` failed at runtime because Python 3 requires relative imports within packages
- The AOT build backend was triggering a recursive tvm_ffi import (which itself tries to build the torch DLPack ext), causing infinite recursion

## What changed (facts from diff)
- `addons/torch_c_dlpack_ext/torch_c_dlpack_ext/__init__.py`: `import core` -> `from . import core`
- `addons/torch_c_dlpack_ext/build_backend.py`: adds `env={**os.environ, "TVM_FFI_DISABLE_TORCH_C_DLPACK": "1"}` to the build subprocess call; adds `import os`
- `addons/torch_c_dlpack_ext/pyproject.toml`: version bumped to 0.1.1
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: after `import torch_c_dlpack_ext` succeeds, checks `if hasattr(torch.Tensor, "__c_dlpack_exchange_api__"): return None`; removes the stale `# todo:` comment and incomplete `...` stub
