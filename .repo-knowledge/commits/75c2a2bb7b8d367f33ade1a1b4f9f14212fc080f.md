# 75c2a2b — [ADDON] Improved github action for torch-c-dlpack-ext (#225)

## TL;DR
- Consolidates the multi-step `build_libs` + `build_wheels` jobs into a single `build_wheels` job using a new shell script `build_aot_wheels.sh`
- Adds Python cp314 to the version matrix
- Adds `build_aot_wheels.sh` — a self-contained script that builds torch libs for all supported torch versions and runs auditwheel
- Fixes the PyPI publish guard (`if: github.event_name == 'workflow_dispatch'` was previously commented out)
- Bumps `torch_c_dlpack_ext` version to 0.1.2 in `pyproject.toml`; removes `torch` from `build-system.requires`

## Why (intent / motivation)
- The original workflow had two separate jobs with artifact passing between them, adding complexity and potential for mismatches
- Moving to a single job with a shell script simplifies the matrix and reduces CI time

## What changed (facts from diff)
- `.github/workflows/torch_c_dlpack.yml`: removes per-version build steps (-112 lines); adds single `build torch libs and wheels` step calling `build_aot_wheels.sh`; adds `cp314` to matrix; re-enables PyPI publish guard
- `addons/torch_c_dlpack_ext/build_aot_wheels.sh`: new 109-line shell script with `get_torch_url()` and `check_availability()` helper functions; loops over torch 2.4–2.9, installs each in a fresh venv, builds CPU and CUDA `.so` files, then runs `auditwheel` repair
- `addons/torch_c_dlpack_ext/pyproject.toml`: version 0.1.1 -> 0.1.2; `torch` removed from `build-system.requires` (was redundant)
