# 4c712ca — [RFC][Error][ABI] Update Error to enable future compact to cause chaining (#396)

## TL;DR
- Extends `TVMFFIErrorCell` with two new optional fields: `cause_chain` (chained error) and `extra_context` (opaque object for additional info such as a Python exception)
- Adds `Error` constructors and accessor methods for `cause_chain` and `extra_context`
- Adds a new C API `TVMFFIErrorCreateWithCauseAndExtraContext`
- ABI-backward compatible: new fields are appended at the end of the struct; existing code reading earlier fields is unaffected

## Why (intent / motivation)
- Enable future support for Python-style exception chaining (`raise B from A`) across language boundaries; `extra_context` provides a hook for attaching frontend-specific error objects (e.g., Python exception state) to a TVM-FFI error

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: Added `cause_chain` and `extra_context` fields to `TVMFFIErrorCell`; added `TVMFFIErrorCreateWithCauseAndExtraContext` C API declaration
- `include/tvm/ffi/error.h`: Added `#include <optional>`, default constructor/destructor for `ErrorObj` (managing refcounts for the two new fields), new `Error` C++ constructor taking `optional<Error>` and `optional<ObjectRef>`, and `cause_chain()`/`extra_context()` accessor methods
- `src/ffi/error.cc`: Implementation of `TVMFFIErrorCreateWithCauseAndExtraContext`
- `tests/cpp/test_error.cc`: Added `TEST(Error, CauseChain)` verifying the chained error is stored and retrievable

## Public surface changes (if any)
- API: `TVMFFIErrorCell` struct gains two new fields (ABI-compatible append); new C function `TVMFFIErrorCreateWithCauseAndExtraContext`; new C++ `Error` constructor and `cause_chain()`/`extra_context()` accessors
- Flags/config: none
- Data formats/schemas: Serialized error objects may include `cause_chain` / `extra_context` references

## Tests & verification
- Added/updated tests: `tests/cpp/test_error.cc` (Error.CauseChain)
- How to verify manually: `ctest -V --test-dir build_test -R Error`
- CI impact: none beyond normal test run

## Risk & rollout notes
- Risk level: medium — ABI struct extension; code that uses fixed-size structs or relies on `sizeof(TVMFFIErrorCell)` will break if recompiled without being updated; header-only struct change is backward compatible for library users who do not reinterpret raw memory
- Rollout/migration: Recompile consumer code against new headers; the new fields default to `nullptr` and existing code paths that ignore them remain unaffected
- Follow-ups: Implement Python-side exception chaining using `extra_context`
