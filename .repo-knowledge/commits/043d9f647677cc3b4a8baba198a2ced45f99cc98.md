# 043d9f6 — [FFI][ABI] Better String and Nested Container handling (#18311)

## TL;DR
- Introduces `TVMFFIStringFromByteArray` and `TVMFFIBytesFromByteArray` C API functions for formal string/bytes creation.
- Adds a `TVMFFIPyConstructorCall` helper that propagates stream/device/DLPack context from nested argument conversion up to the parent call context.
- Moves tuple/list/dict and `ObjectConvertible` argument setters into dedicated Cython functions so nested containers preserve the torch stream.
- Fixes a bug in temp-object recycling: replaces incorrect manual deleter call with `TVMFFIObjectDecRef`.
- Bumps version `0.1.0a12` → `0.1.0a13`.

## Why (intent / motivation)
- If a function takes a `list[torch.Tensor]`, the CUDA stream context detected while converting the inner tensor must propagate to the outer function call. The previous implementation lost this context for nested containers.
- Optimizes recursive argument conversion by moving most logic into C++/Cython, reducing Python overhead.
- Fixes a reference-counting bug where temp FFI objects were deleted with the wrong flags.

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: Two new exported functions `TVMFFIStringFromByteArray` and `TVMFFIBytesFromByteArray`.
- `src/ffi/object.cc`: Implementations of the two new functions using `TypeTraits<String/Bytes>::MoveToAny`.
- `tvm_ffi_python_helpers.h`: Renamed `Call` → `FuncCall`; added `ConstructorCall` method that syncs stream/device/DLPack context to parent; added `TVMFFIPyConstructorCall` free function.
- `cython/function.pxi`: New `ConstructorCall` Cython inline; new setters `TVMFFIPyArgSetterTuple_`, `TVMFFIPyArgSetterTupleLike_`, `TVMFFIPyArgSetterMap_`, `TVMFFIPyArgSetterObjectConvertible_`; dedicated `PyNativeObject` str/bytes setters; fallback simplified to opaque object only.
- `python/tvm_ffi/_convert.py`: Removed `_set_func_convert_to_object` call (no longer needed).
- Tests: new `test_string_bytes_passing` and `test_nested_container_passing` tests; updated `test_load_inline_cuda_with_env_tensor_allocator` to demonstrate nested container passing.
