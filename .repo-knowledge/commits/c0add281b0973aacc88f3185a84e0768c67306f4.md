# c0add28 — [FIX] Fix device type override (#40)

## TL;DR
- Fixes `tvm_ffi.device()` so that subclass overrides of `Device` registered via `_set_class_device` are respected.
- The root cause was that `_CLASS_DEVICE` was captured at import time via a local name alias; now the call always goes through `core._CLASS_DEVICE` (module attribute lookup).
- Bumps version to `0.1.0b6`.
- Adds tests for both `Device` and `Tensor` class overrides.

## Why (intent / motivation)
- Users (and downstream frameworks) that subclass `Device` and call `_set_class_device` to register the override expected `tvm_ffi.device(...)` to return the subclass instance. The import-time capture bypassed the override.

## What changed (facts from diff)
- `python/tvm_ffi/_tensor.py`: `device()` now calls `core._CLASS_DEVICE(...)` instead of the cached `_CLASS_DEVICE` local; re-imports `core` module.
- `tests/python/test_device.py`: Added `test_device_class_override` test.
- `tests/python/test_tensor.py`: Added `test_tensor_class_override` test.
- `pyproject.toml`: Version `0.1.0b5` → `0.1.0b6`.

## Public surface changes (if any)
- API: `tvm_ffi.device()` now correctly returns subclass instances after `_set_class_device` override
