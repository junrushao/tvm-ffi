# 889bfb3 — [Minor] use perfect forwarding for template types. (#266)

## TL;DR
- Refactored `FunctionObjImpl<TCallable>` in `function.h` to use perfect forwarding: added separate lvalue and rvalue constructors instead of relying on copy-then-move.
- Added a `static_assert` ensuring `TCallable` is not a const or reference type.
- Added `#include <type_traits>` to support the static assertion.

## Why (intent / motivation)
- Types that are cheap to copy (e.g., `Function`, `std::string`) can use copy construction, while movable-only types (e.g., lambdas with unique_ptr captures) should use move construction.
- Perfect forwarding avoids unnecessary copy/move operations during forwarding chains in callable wrapping.

## What changed (facts from diff)
- `include/tvm/ffi/function.h`:
  - Added `#include <type_traits>`.
  - `FunctionObjImpl`: Added `static_assert` that `TCallable` is not const/reference.
  - Split constructor into `explicit FunctionObjImpl(TCallable&& callable)` (rvalue) and `explicit FunctionObjImpl(const TCallable& callable)` (lvalue).
  - Removed `TStorage` alias; used `TCallable` directly for `callable_` member type.
  - Minor: `mutable TStorage callable_` -> `mutable TCallable callable_`.
