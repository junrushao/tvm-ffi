# 035975a — feat: Improve Critical Path Perf in Cython `make_ret_object` (#47)

## TL;DR
- Introduces a dedicated `TYPE_INDEX_TO_CLS` list that maps `type_index` directly to a Python class, eliminating the intermediate `TypeInfo` lookup in the hot `make_ret_object` path
- Adds a `_set_type_cls` C-level function for updating this list when a class is associated with a pre-existing `TypeInfo`
- The hot path in `make_ret_object` now does a single list index lookup instead of two

## Why (intent / motivation)
- The critical path for every FFI return of an Object previously required looking up `TypeInfo` from `TYPE_INDEX_TO_INFO[tindex]` then accessing `type_info.type_cls`
- Eliminating that indirection reduces per-call overhead on the FFI hot path

## What changed (facts from diff)
- `object.pxi`: new `cdef list TYPE_INDEX_TO_CLS = []` mirrored alongside `TYPE_INDEX_TO_INFO`
- `make_ret_object` simplified to check `TYPE_INDEX_TO_CLS[tindex]` directly
- `_register_object_by_index` now populates both `TYPE_INDEX_TO_INFO` and `TYPE_INDEX_TO_CLS`
- New `_set_type_cls(type_index, type_cls)` function updates both structures; validates that the type isn't already registered
- `core.pyi` updated with `_set_type_cls` stub
