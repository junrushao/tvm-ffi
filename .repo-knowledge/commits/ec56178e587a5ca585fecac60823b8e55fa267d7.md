# ec56178 — fix: add negative index bounds check in ArrayObj (#376)

## TL;DR
- Fixed `ArrayObj::operator[]` and `ArrayObj::SetItem` to reject negative indices with an `IndexError` instead of silently allowing out-of-bounds access
- Added `TEST(Array, NegativeIndexThrows)` C++ test covering both methods

## Why (intent / motivation)
- `ArrayObj::operator[]` and `SetItem` only checked `i >= size_`, meaning negative values like `-1` would be accepted and cause undefined behavior (read/write before the array's backing memory)
- The higher-level `Array<T>` wrapper already had negative index semantics (Python-style wrap-around), but the raw `ArrayObj` methods did not validate the pre-adjusted index

## What changed (facts from diff)
- `include/tvm/ffi/container/array.h`: `if (i >= size_)` → `if (i < 0 || i >= size_)` in both `operator[]` and `SetItem`
- `tests/cpp/test_array.cc`: `TEST(Array, NegativeIndexThrows)` added (+31 lines) testing that `ArrayObj::at(-1)` and `ArrayObj::SetItem(-1, ...)` throw `IndexError`

## Public surface changes (if any)
- API: `ArrayObj::operator[]` and `ArrayObj::SetItem` now throw `IndexError` for negative indices (previously UB)
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_array.cc` (+31 lines)
- How to verify manually: `ctest -V -R Array.NegativeIndexThrows --test-dir build_test`
- CI impact: new passing test
