# b16f11f — [Enhancement] Refactor cubin launcher (#300)

## TL;DR
- Replaced `tvm_ffi_generate_cubin` CMake function with `add_tvm_ffi_cubin` using native CMake CUDA support
- Added `TVM_FFI_LOAD_LIBRARY_FROM_BYTES` macro for registering CUBINs from raw byte arrays (supporting C++23 `#embed` and CUDA Toolkit `bin2c`)
- Reorganized `examples/cubin_launcher/embedded_cubin` into three subdirectories: `cpp_embed`, `embed_with_tvm_ffi`, `include_bin2c`
- Added new internal header `include/tvm/ffi/extra/cuda/internal/unified_api.h` (206 lines) unifying CUDA/HIP device API

## Why (intent / motivation)
- The old `tvm_ffi_generate_cubin` used custom nvcc invocations, bypassing CMake's native CUDA support and `CMAKE_CUDA_ARCHITECTURES`
- Users needed a way to embed CUBINs without relying on `objcopy`; C++23 `#embed` and `bin2c` are now viable options
- The embedded cubin examples were in a flat directory; splitting by technique makes each approach self-contained

## What changed (facts from diff)
- `cmake/Utils/EmbedCubin.cmake`: +93/-176 — `tvm_ffi_generate_cubin` removed; `add_tvm_ffi_cubin(target CUDA src)` added using CMake `CUDA_CUBIN_COMPILATION` object library; `CMAKE_CUDA_RUNTIME_LIBRARY` defaults to `Shared` if unset
- `cmake/Utils/ObjectCopyUtil.cmake`: new file (48 lines) with `add_objcopy_target` utility
- `include/tvm/ffi/extra/cuda/internal/unified_api.h`: new header (206 lines) with unified CUDA/HIP API wrappers
- `include/tvm/ffi/extra/cuda/base.h`: +24/-18 minor cleanup
- `include/tvm/ffi/extra/cuda/cubin_launcher.h`: +68/-62 updated to use `TVM_FFI_LOAD_LIBRARY_FROM_BYTES`
- Three new embedded cubin example sub-projects added under `examples/cubin_launcher/embedded_cubin/`
- Docs updated: `docs/guides/cubin_launcher.rst` +92/-44

## Public surface changes (if any)
- API: `TVM_FFI_LOAD_LIBRARY_FROM_BYTES(name, imageBytes)` — new C++ macro; `tvm_ffi_generate_cubin` CMake function removed (breaking for existing users)
- Flags/config: `add_tvm_ffi_cubin` replaces `tvm_ffi_generate_cubin`; `CMAKE_CUDA_RUNTIME_LIBRARY` now set to `Shared` by default if unset
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: new example projects under `examples/cubin_launcher/embedded_cubin/{cpp_embed,include_bin2c}/`
- How to verify manually: build any embedded cubin example with a CUDA-capable machine and `cmake -DCMAKE_CUDA_ARCHITECTURES=native`
- CI impact: cubin launcher docs and examples updated; requires CUDA to test fully

## Risk & rollout notes
- Risk level: medium — `tvm_ffi_generate_cubin` removed is a breaking CMake API change; `CMAKE_CUDA_RUNTIME_LIBRARY` default change may affect builds that expected static cuda linking
- Rollout/migration: replace `tvm_ffi_generate_cubin(OUTPUT ... SOURCE ... ARCH ... OPTIONS ...)` calls with `add_tvm_ffi_cubin(<target> CUDA <source>)`
- Follow-ups: none noted
