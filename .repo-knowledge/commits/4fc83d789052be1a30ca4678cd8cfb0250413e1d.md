# 4fc83d7 — [Fix] Enhanced check for CUDA availability (#258)

## TL;DR
- Fixed insufficient CUDA availability check: `torch.version.cuda is not None` is necessary but not sufficient; added `torch.cuda.is_available()` as a pre-check.
- Bumped `TVM_FFI_VERSION_PATCH` from `2` to `3` in `c_api.h`.
- Updated all detection sites (JIT loader, AOT build backend, and tests) to use the two-stage check.

## Why (intent / motivation)
- A CUDA-capable PyTorch install (`torch.version.cuda` set) does not guarantee that CUDA is actually available in the current environment (e.g., no GPU, no drivers).
- Using only `torch.version.cuda` caused the build to attempt CUDA compilation in environments where it would fail.

## What changed (facts from diff)
- `addons/torch_c_dlpack_ext/build_backend.py`: Added `torch.cuda.is_available()` guard before checking `torch.version.cuda` / `torch.version.hip`.
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Same two-stage check in JIT loader; added `# noqa: PLR0912`.
- `tests/python/test_optional_torch_c_dlpack.py`: Same guard in test.
- `tests/python/test_tensor.py`: ROCm test skip condition updated to also require `torch.cuda.is_available()`.
- `include/tvm/ffi/c_api.h`: `TVM_FFI_VERSION_PATCH` 2 -> 3.
