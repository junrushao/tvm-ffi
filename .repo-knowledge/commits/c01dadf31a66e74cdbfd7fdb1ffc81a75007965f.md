# c01dadf — feat: Introduce `tvm_ffi::reflection::init<>` (#32)

## TL;DR
- Introduces the `tvm_ffi::reflection::init<ObjectType, Args...>` helper function for registering `__ffi_init__` constructors via `ObjectDef`.
- Replaces the verbose lambda pattern with a concise generic call.
- Updates the `TestIntPair` registration in `testing.cc` from `__create__` + lambda to `__ffi_init__` + `refl::init<>`.
- Adds `TestObjA` and `TestObjADerived` constructors and `__ffi_init__` methods in the C++ test fixture.
- Adds Python-side `TestIntPair.__ffi_init__` invocation and a `test_make_object_via_init` test.

## Why (intent / motivation)
- Previously registering a constructor required writing a full lambda with explicit return type. `refl::init<>` makes this a one-liner and avoids boilerplate for the common case of forwarding arguments directly to `make_object<T>`.

## What changed (facts from diff)
- `include/tvm/ffi/reflection/registry.h`: Added `template <typename T, typename... Args> inline ObjectRef init(Args&&... args)` function (33 lines with docs).

- `python/tvm_ffi/cython/type_info.pxi`: Removed return type annotation from `as_property` method (workaround for ruff ANN rule).
