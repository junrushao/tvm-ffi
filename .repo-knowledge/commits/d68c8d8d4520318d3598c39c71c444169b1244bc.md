# d68c8d8 — fix: Fallback for unregistered object types (#44)

## TL;DR
- `make_ret_object` in Cython now correctly issues a `UserWarning` and falls back to `Object` when a returned object type is not registered, rather than crashing
- Adds a C++ `TestUnregisteredObject` and a `testing.make_unregistered_object` global function for testing
- New Python unit test verifies the warning text and the resulting type

## Why (intent / motivation)
- Previously a subtle bug in `make_ret_object` could silently return `None` instead of `Object` when the type was not found in `TYPE_INDEX_TO_INFO`, because it checked `TYPE_INDEX_TO_INFO[tindex]` which could be `None` without guarding properly
- Proper fallback prevents crashes when third-party types aren't registered

## What changed (facts from diff)
- `object.pxi`: restructured `make_ret_object` to check `type_info is not None` before accessing `type_cls`, ensuring the warning path is reached correctly
- `src/ffi/extra/testing.cc`: added `TestUnregisteredObject` class and `testing.make_unregistered_object` global function returning an `ObjectRef`
- `python/tvm_ffi/testing.py`: added `make_unregistered_object()` helper
- `tests/python/test_object.py`: new `test_unregistered_object_fallback` test using `pytest.warns`

## Public surface changes (if any)
