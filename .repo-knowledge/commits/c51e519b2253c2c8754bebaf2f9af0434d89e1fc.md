# c51e519 — [Feature] support C++ dtype_trait and Python-side mapping to C++ dtype (#374)

## TL;DR
- Added new header `include/tvm/ffi/extra/dtype.h` (206 lines) with `tvm_ffi::dtype_trait<T>` template providing compile-time `DLDataType` mappings for C++ scalar types including CUDA/HIP exotic types
- Added Python module `python/tvm_ffi/cpp/dtype.py` (104 lines) mapping Python/numpy type strings to `DLDataType` codes
- Exported the new `dtype` module from `python/tvm_ffi/cpp/__init__.py`

## Why (intent / motivation)
- C++ code consuming TVM FFI needs a standard, header-only way to convert native C++ types (e.g., `float`, `__half`, `__nv_fp8_e4m3`) to `DLDataType` structs without manual encoding
- Python users needed a mapping from Python type annotations or numpy dtype strings to `DLDataType` for dynamic use

## What changed (facts from diff)
- `include/tvm/ffi/extra/dtype.h`: `dtype_trait<T>` primary template; specializations for `signed/unsigned char/short/int/long`, `float`, `double`, `__half`, `__nv_bfloat16`, `__nv_fp8_e4m3/e5m2/e8m0`, `__nv_fp4_e2m1`, HIP counterparts; uses `integer_trait` and `float_trait` helper structs
- `python/tvm_ffi/cpp/dtype.py`: `DLDataType` mapping dictionary and helper function
- `python/tvm_ffi/cpp/__init__.py`: `from . import dtype` added

## Public surface changes (if any)
- API: `tvm_ffi::dtype_trait<T>::value` — new `constexpr DLDataType` for supported C++ types; `tvm_ffi.cpp.dtype` — new Python module
- Flags/config: none
- Data formats/schemas: none
