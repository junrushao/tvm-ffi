# 368af82 — fix: `self` overlooked in schema of member functions (#91)

## TL;DR
- Fixes a bug where member function schemas generated via reflection omitted the implicit `self` (`this`) argument.
- Both non-const and const pointer-to-member specializations of `FunctionInfo` now include `Class*` / `const Class*` as the first parameter.
- Python `TypeSchema` validation relaxes `list` and `dict` argument count assertions to allow 0 or 1 / 0 or 2 args respectively.
- Adds a test schema for `TypedFunction` and updates all existing method-schema test expectations.

## Why (intent / motivation)
- A member function `MyCls::MyFunc(int a)` registered via `def_method` should have schema `(MyCls, int) -> ret`, not `(int) -> ret`. The original implementation incorrectly omitted the receiver.

## What changed (facts from diff)
- `include/tvm/ffi/function_details.h`: `FunctionInfo` specializations for `R (Class::*)(Args...)` and const variant now inherit from `FuncFunctorImpl<R, Class*, Args...>` / `FuncFunctorImpl<R, const Class*, Args...>`.
- `python/tvm_ffi/cython/type_info.pxi`: `list` assertion changed from `== 1` to `in (0, 1)`; `dict` from `== 2` to `in (0, 2)`.
- `src/ffi/extra/testing.cc`: adds `testing.schema_id_func_typed` test function.
- C++ and Python test expectations for method schemas updated to include the `testing.SchemaAllTypes` self parameter.

## Public surface changes (if any)
- API: `FunctionInfo` template specializations for pointer-to-member now correctly emit the `self` argument — this is a behavioral schema fix, not a calling convention change.
- Flags/config: none
- Data formats/schemas: All method schemas now include the receiver type as the first argument.

## Tests & verification
- Added/updated tests: `tests/cpp/test_metadata.cc`, `tests/python/test_metadata.py`
- How to verify manually: `uv run pytest -vvs tests/python/test_metadata.py`
- CI impact: All method schema tests updated; should pass after fix.

## Risk & rollout notes
- Risk level: medium — any downstream code that consumes method schemas will observe a changed schema (receiver arg prepended).
- Rollout/migration: Downstream schema consumers must expect the self/receiver as first argument of member function schemas.
- Follow-ups: none
