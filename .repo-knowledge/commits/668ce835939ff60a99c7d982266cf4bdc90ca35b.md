# 668ce83 — fix: handle empty metadata in get_global_func_metadata (#417)

## TL;DR
- Fixes a `JSONDecodeError` when calling `get_global_func_metadata()` on a Python-registered function that has no metadata
- The FFI returned an empty string which `json.loads()` could not parse
- Now checks for empty/falsy string before attempting JSON parsing

## Why (intent / motivation)
- Python-registered global functions do not produce metadata JSON, causing the empty string to be passed to `json.loads()`, raising `JSONDecodeError` (issue #208)
- The fix makes the function return an empty dict instead of crashing

## What changed (facts from diff)
- `python/tvm_ffi/registry.py`: Changed `json.loads(... or "{}")` to explicit `if metadata_json: json.loads(metadata_json) else {}` — avoids the case where the string is empty (not just falsy)
- `tests/python/test_metadata.py`: Added test case registering a Python callable and verifying `get_global_func_metadata` returns `{}` without error

## Public surface changes (if any)
- API: none — behavior fix only (was raising exception, now returns `{}`)
