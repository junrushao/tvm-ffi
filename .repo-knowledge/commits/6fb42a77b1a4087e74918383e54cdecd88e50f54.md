# 6fb42a7 — [MEMORY] Use raw alloc for memory (#66)

## TL;DR
- Replaces `new StorageType` / `new StorageType[]` with `AlignedAlloc<align>(size)` + placement-new in the object allocator.
- Reduces over-allocation in `InplaceArray` objects (e.g., `ShapeObj`) by computing exact size instead of rounding to `sizeof(StorageType)`.
- Introduces `AlignedAlloc<align>` / `AlignedFree` helpers in `memory.h` with MSVC/POSIX portability.

## Why (intent / motivation)
- Previously, inplace array allocation had to round up to a multiple of `ArrayType`'s size; raw byte allocation only needs to be a multiple of alignment, reducing wasted memory.

## What changed (facts from diff)
- Added `AlignedAlloc<align>(size)` template function: uses `_aligned_malloc` on MSVC, `malloc` for small alignments, `posix_memalign` otherwise.
- Added `AlignedFree(void*)` function: uses `_aligned_free` on MSVC, `std::free` otherwise.
- `SimpleObjAllocator::Handler::New` and `Deleter` now use `AlignedAlloc/AlignedFree` instead of `new StorageType` / `delete`.
- `SimpleObjAllocator::ArrayHandler` removed the `StorageType = aligned_storage<...>` typedef; element alignment is now checked by `static_assert` at compile time; allocation is `AlignedAlloc<align>(sizeof(ArrayType) + sizeof(ElemType) * num_elems)`.
- `StorageType` intermediate types removed entirely from both `Handler` and `ArrayHandler`.

## Public surface changes (if any)
- API: `AlignedAlloc<align>` and `AlignedFree` added to `tvm::ffi::details` (internal).
- Flags/config: none
- Data formats/schemas: none
