# 38914fa — fix: TypeStr support for Any type in reflection Init (#393)

## TL;DR
- Fixes a compile error: `refl::init<Any>()` and `refl::init<AnyView>()` failed because the reflection system converts `Any` to `Any&&` internally and no `Type2Str<Any&&>` specialization existed
- Adds `Type2Str<Any&&>` and `Type2Str<AnyView&&>` template specializations in `any.h`
- Adds forward declaration of `Any` in `type_traits.h` to break a circular dependency
- Covers the fix with two new reflection test cases

## Why (intent / motivation)
- The reflection `init<>` mechanism appends `&&` to constructor argument types; without `Type2Str<Any&&>`, attempting to register a constructor accepting `Any` would fail to compile with a missing specialization error

## What changed (facts from diff)
- `include/tvm/ffi/any.h`: Added `template<> struct Type2Str<Any&&>` and `template<> struct Type2Str<AnyView&&>` returning `"Any"` and `"AnyView"` respectively
- `include/tvm/ffi/type_traits.h`: Added `class Any;` forward declaration before the `TypeTraits` template to allow `Type2Str` specializations to compile without a full definition
- `tests/cpp/test_reflection.cc`: Added `TestObjWithAny`/`TestObjWithAnyView` object stubs and `TEST(Reflection, InitWithAny)` / `TEST(Reflection, InitWithAnyView)` verifying constructors accepting `Any` and `AnyView` work end-to-end

## Public surface changes (if any)
- API: `refl::init<Any>()` and `refl::init<AnyView>()` now compile and function correctly
