# 076ac23 — [REFACTOR][FFI][Web] Upgrade Web Runtime to new FFI (#17946)

## TL;DR
- Changes `TVMFFIDataTypeToString` C API signature: `DLDataType` argument changed from value to pointer to fix ABI compatibility.
- Adds `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` compile-time flag to `error.h`.
- Updates `TVMFFIDataTypeToString` macro in `TVM_FFI_THROW` to support the new error logging mode.
- Tested via RPC and local Web Runtime tests.

## Why (intent / motivation)
- Passing `DLDataType` by value in a C API function can cause ABI compatibility issues across different compilers and calling conventions (struct-in-register vs. on-stack).
- The Web Runtime migration to the new FFI required this ABI fix and the new error logging option.

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: `TVMFFIDataTypeToString(DLDataType dtype, ...)` → `TVMFFIDataTypeToString(const DLDataType* dtype, ...)`.
- `include/tvm/ffi/dtype.h`: updated `DLDataTypeToString` helper to pass `&dtype` instead of `dtype`.
- `include/tvm/ffi/error.h`: added `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` preprocessor flag (default 0); updated `TVM_FFI_THROW` macro to conditionally log before throwing.
- `src/ffi/dtype.cc`: updated implementation to use pointer argument.

## Public surface changes (if any)
- API: `TVMFFIDataTypeToString` C ABI signature changed — takes `const DLDataType*` instead of `DLDataType`. Breaking change for C callers.
- Flags/config: `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` preprocessor macro (opt-in logging before throw).
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none (tested via Web Runtime RPC tests)
- How to verify manually: Build with WebAssembly target and run Web Runtime RPC tests.
- CI impact: none for standard C++ tests.

## Risk & rollout notes
- Risk level: medium — C ABI break for `TVMFFIDataTypeToString`; all C callers must update to pass a pointer.
- Rollout/migration: Update all call sites of `TVMFFIDataTypeToString` to pass `&dtype`.
- Follow-ups: none
