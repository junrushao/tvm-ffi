# 6897a5f — fix(cython): Make sure `TypeInfo` is properly registered by all classes (#246)

## TL;DR
- Fixed a bug where `parent_type_info` was not correctly propagated for several built-in Cython classes because `_register_object_by_index` calls were scattered after their `include` statements with wrong ordering.
- Consolidated all `_register_object_by_index` calls in `core.pyx` in inheritance order (base class before derived).
- Added `TYPE_CLS_TO_INFO` reverse mapping and `_type_cls_to_type_info()` public helper.

## Why (intent / motivation)
- Registration ordering matters: when a derived class is registered before its base, `parent_type_info` is not populated correctly.
- Several built-in types (Error, String, Bytes, Tensor, Function, DataType, Device, Object) had their registrations interleaved incorrectly.

## What changed (facts from diff)
- `cython/core.pyx`: Removed inline `_register_object_by_index` calls from `.pxi` files; added them explicitly in `core.pyx` in proper inheritance order after each `include`.
- `cython/object.pxi`: Added `TYPE_CLS_TO_INFO` dict; updated `_update_registry` and `_set_type_cls` to populate it; added `_type_cls_to_type_info()`.
- `cython/device.pxi`, `error.pxi`, `function.pxi`, `string.pxi`, `tensor.pxi`: Removed inline `_register_object_by_index` calls.
- `core.pyi`: Replaced `_set_class_object` with `_type_cls_to_type_info` in stubs.
- `tests/python/test_object.py`: Added comprehensive `test_type_info_attachment` parametrized test covering 22 types.

## Public surface changes (if any)
- API: New `tvm_ffi.core._type_cls_to_type_info(type_cls: type) -> TypeInfo | None`.
