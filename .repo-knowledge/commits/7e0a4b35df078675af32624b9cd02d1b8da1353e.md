# 7e0a4b3 — [FFI][REFACTOR] Stablize container ABI and implementation (#18076)

## TL;DR
- Stabilizes `ArrayObj` ABI: backing storage changed from inplace array to a separately managed `data_` pointer with explicit destructor and `data_deleter_`.
- `ArrayObj::operator[]` and `at()` now return `const Any&` (reference) instead of `const Any` (value copy).
- Adds bounds checking to `ArrayObj::operator[]` and `SetItem`.
- Updates `MapObj` internals for ABI stability (+107/-59 in `map.h`).
- Removes `Tuple`'s reliance on inplace array, simplifying its storage model.

## Why (intent / motivation)
- The inplace array storage model tied the ABI of `ArrayObj` to the `InplaceArrayBase` implementation, making it impossible to change without breaking binary compatibility.
- Moving to a `data_` pointer + `data_deleter_` pattern decouples storage from the object header, enabling future ABI-stable changes.
- Returning `const Any&` instead of `const Any` avoids unnecessary copies for read-only access.

## What changed (facts from diff)
- `include/tvm/ffi/container/array.h` (+56/-7):
  - `ArrayObj` storage changed from `InplaceArrayBase<ArrayObj, Any>` to `InplaceArrayBase<ArrayObj, TVMFFIAny>` with explicit destructor.
  - `at()` return type: `const Any` → `const Any&`.
  - `operator[]` added with bounds check.
  - `begin()`/`end()` now use `data_` pointer directly.
  - `SetItem()` adds bounds check.
- `include/tvm/ffi/container/map.h` (+107/-59): updated `MapObj` internals for ABI stability.
- `include/tvm/ffi/container/tuple.h` (+3/-12): removed `InplaceArrayBase` from `TupleObj`, simplified storage.

## Public surface changes (if any)
- API: `ArrayObj::at()` now returns `const Any&` — callers taking by value still work; callers storing references must be careful of dangling.
- Flags/config: none
- Data formats/schemas: `ArrayObj` binary layout changed (ABI break for direct struct access).
