# 3dd7a81 — [REFACTOR][FEAT] Introduce generic value protocol (#312)

## TL;DR
- Introduces `__tvm_ffi_value__()` protocol: any Python object with this method is automatically converted by calling it to get the actual FFI value
- Refactors `TVMFFIPyCallContext` from a nested inner class of `TVMFFIPyCallManager` into a standalone RAII class; separates call stack state into `TVMFFIPyCallStack`
- Adds `TVMFFIPyPushExtraTempPyObject` for keeping alive temporary objects created by the value protocol
- Updates benchmark to use `NamedTuple` instead of `TestFFITensor`

## Why (intent / motivation)
- The value protocol enables Python objects (e.g., `NamedTuple`, custom wrappers) to declare how they convert to TVM FFI values without requiring explicit converter registration; enables transparent use of complex Python types in FFI calls

## What changed (facts from diff)
- `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`: Major refactor — `TVMFFIPyCallContext::CallStack` extracted into standalone `TVMFFIPyCallContext` with RAII constructor/destructor; new `TVMFFIPyCallStack` class with `extra_temp_py_objects_stack` vector; `TVMFFIPyCallManager` now uses `TVMFFIPyCallStack` member; added `TVMFFIPySetArgumentGenericDispatcher` and `TVMFFIPyPushExtraTempPyObject` free functions
- `python/tvm_ffi/cython/function.pxi`: New `TVMFFIPyArgSetterFFIValueProtocol_` setter that calls `__tvm_ffi_value__()` and recursively dispatches; registered in `TVMFFIPyArgSetterFactory_`; declared `TVMFFIPySetArgumentGenericDispatcher` and `TVMFFIPyPushExtraTempPyObject`
- `python/tvm_ffi/cython/base.pxi`: Declared new C functions
- `python/tvm_ffi/cython/tensor.pxi`: Minor type annotation fix on `DLTensorTestWrapper.__c_dlpack_exchange_api__`
- Tests: `test_function.py` adds `test_function_with_value_protocol`; `test_tensor.py` adds NamedTuple and custom `__tvm_ffi_value__` tests; `test_stream.py` minor graph capture fix
