# 181e1b8 — ci: add clang-tidy to ci_test (#389)

## TL;DR
- Adds a new `clang-tidy` job to `.github/workflows/ci_test.yml` that runs on every PR when C++ files are changed
- Detects changed C++ files in the `prepare` job and exposes them as outputs
- Uses `clang-tidy==21.1.1` via `uv run --no-project` to match the mainline-only job

## Why (intent / motivation)
- Previously clang-tidy only ran in `ci_mainline_only.yml` (post-merge), meaning PRs could pass CI but then fail on main; this change catches clang-tidy issues at PR time

## What changed (facts from diff)
- `.github/workflows/ci_test.yml`: Added `cpp_changed` and `cpp_files` outputs to the `prepare` job via a new `Get changed C++ files` step using `git diff --name-only`; added a new `clang-tidy` job that runs only when `cpp_changed == 'true'`, checks out the repo, installs Python 3.13, and runs `tests/lint/clang_tidy_precommit.py` against the changed files

## Public surface changes (if any)
- API: none
- Flags/config: none — new CI job only
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none (CI config change)
- How to verify manually: Open a PR that modifies a `.cc` file and observe the `clang-tidy` check
- CI impact: New required check on PRs with C++ changes; may block merges that were previously allowed

## Risk & rollout notes
- Risk level: low — CI config only; no code changes
- Rollout/migration: PRs with pre-existing clang-tidy warnings will now fail; authors must fix warnings before merging
- Follow-ups: Consider running clang-tidy on the full codebase to baseline the warning count
