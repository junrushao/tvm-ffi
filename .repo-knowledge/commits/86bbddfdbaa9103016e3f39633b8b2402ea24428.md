# 86bbddf — feat: Add overflow check for uint64_t/size_t in TypeTraits<Int>::CopyToAnyView (#370)

## TL;DR
- Adds a compile-time-selected runtime overflow guard when converting unsigned 64-bit integers (`uint64_t` / `size_t`) into `int64_t` inside `TypeTraits<Int>::CopyToAnyView`
- Throws `OverflowError` when the value exceeds `std::numeric_limits<int64_t>::max()`
- Updates `StructuralHash` path and `SHash` callbacks to use explicit `int64_t` casts to avoid triggering the new guard
- Adjusts `TCustomFuncObj::SHash` test helper to use `int64_t` signatures

## Why (intent / motivation)
- TVM FFI stores all integers as `int64_t` in `TVMFFIAny`. Passing a `uint64_t` value larger than `INT64_MAX` would silently produce a negative integer, corrupting data
- Related discussion: issue #357

## What changed (facts from diff)
- `include/tvm/ffi/type_traits.h`: Added `#include <limits>` and a `constexpr if` block in `CopyToAnyView` that checks `std::is_unsigned_v<Int> && sizeof(Int) >= sizeof(int64_t)` and throws `OverflowError` if the value exceeds `INT64_MAX`
- `src/ffi/extra/structural_hash.cc`: All call sites that return or pass `uint64_t` hash values now explicitly `static_cast<int64_t>(...)` to bit-cast rather than overflow-convert; `FFIStructuralHash` wrapper added with the same cast; global registration updated to use the wrapper
- `tests/cpp/test_any.cc`: Added test case that verifies an `OverflowError` is thrown when assigning `INT64_MAX + 1` to an `AnyView`
- `tests/cpp/testing_object.h`: `TCustomFuncObj::SHash` signature changed from `uint64_t` to `int64_t`

## Public surface changes (if any)
- API: `TypeTraits<Int>::CopyToAnyView` now throws `OverflowError` for out-of-range `uint64_t`/`size_t` values — this is a new runtime error that callers assigning large unsigned values must handle
- Flags/config: none
- Data formats/schemas: `ffi.StructuralHash` global function now returns `int64_t` (bit-equivalent to the previous `uint64_t` return)

## Tests & verification
- Added/updated tests: `tests/cpp/test_any.cc` (Any, Int — overflow test), `tests/cpp/testing_object.h` (SHash signature fix)
- How to verify manually: `ctest -V --test-dir build_test -R Any`
- CI impact: none beyond normal test run

## Risk & rollout notes
- Risk level: medium — existing code that passes `uint64_t` values larger than `INT64_MAX` to `AnyView` will now throw at runtime; code relying on `ffi.StructuralHash` returning a large positive `uint64_t` will see a negative `int64_t` (but bit-equivalent)
- Rollout/migration: Review all call sites that convert large unsigned hashes or sizes to `Any`/`AnyView`; use explicit `static_cast<int64_t>` if intentional overflow/bit-cast is desired
- Follow-ups: Consider adding a C API function for safe uint64->int64 bit-cast
