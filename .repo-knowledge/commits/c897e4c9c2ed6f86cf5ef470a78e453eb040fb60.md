# c897e4c — [Feature] Support build and build_and_load. (#213)

## TL;DR
- Adds `tvm_ffi.cpp.build()` and `tvm_ffi.cpp.load()` — file-based companions to `build_inline`/`load_inline` that compile from existing `.cc`/`.cu` file paths instead of raw strings
- Renames `load_inline.py` to `extension.py` and refactors shared logic into `_build_impl()`
- Adds tests exercising `tvm_ffi.cpp.build()` with a real C++ source file

## Why (intent / motivation)
- `build_inline`/`load_inline` required users to embed source as Python strings; many workflows already have `.cc`/`.cu` files on disk
- The new API is analogous to `torch.utils.cpp_extension.load()`

## What changed (facts from diff)
- `python/tvm_ffi/cpp/load_inline.py` renamed to `python/tvm_ffi/cpp/extension.py` (R061); all existing exports remain
- `_generate_ninja_build()` refactored: no longer takes `build_dir`; accepts `cpp_files`/`cuda_files` lists of resolved paths; generates object file targets named `cpp_{i}.o`/`cuda_{i}.o`
- New `_build_impl()` internal function: resolves file paths, computes source hash, creates build directory, writes `build.ninja`, optionally holds `FileLock`
- `build_inline()` refactored to use `_build_impl()` internally; behavior unchanged
- New `build(name, *, cpp_files, cuda_files, ...)` function: returns path to compiled `.so`
- New `load(name, *, cpp_files, cuda_files, ...)` function: returns loaded `Module`
- `python/tvm_ffi/cpp/__init__.py`: exports `build` and `load`; adds `__all__`
- `python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`: updates import from `load_inline` to `extension`
- `docs/reference/python/index.rst`: section renamed to "C++ Extension"; adds `cpp.load` and `cpp.build`
- `tests/python/test_build.cc`, `test_build.h`, `test_build.py`: new test files exercising `tvm_ffi.cpp.build()` with `add_one_cpu` function

## Public surface changes (if any)
- API: New `tvm_ffi.cpp.build()` and `tvm_ffi.cpp.load()` functions added to public API
- Flags/config: none
- Data formats/schemas: cache key for file-based builds uses SHA256 of resolved file paths + flags
