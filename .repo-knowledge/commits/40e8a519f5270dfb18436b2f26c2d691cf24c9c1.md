## TL;DR

All TVM FFI exported function symbols now carry the `__tvm_ffi_` prefix (e.g., `add_one` becomes `__tvm_ffi_add_one`). The `Library` interface gains a `GetSymbolWithSymbolPrefix()` method. The module entry point is renamed from `__tvm_ffi_main__` to `main` (stored unprefixed in Python). This is an ABI-breaking change for previously compiled shared libraries.

## Why

Using a well-known prefix (`__tvm_ffi_`) for all exported function symbols avoids name collisions with host application symbols and makes it unambiguous which symbols belong to the TVM FFI module. The prefix convention also enables the library loader to enumerate only TVM FFI symbols without false positives.

## What changed

- `include/tvm/ffi/function.h`: `TVM_FFI_DLL_EXPORT_TYPED_FUNC(Name, Func)` now emits the symbol `__tvm_ffi_##Name`. New `symbol::tvm_ffi_symbol_prefix = "__tvm_ffi_"` constant.
- `include/tvm/ffi/extra/module.h`: `Library` virtual interface: `GetSymbol(const char*)` changed to `GetSymbol(const String&)`. New pure virtual `GetSymbolWithSymbolPrefix(const String& name)`.
- `src/ffi/extra/library_module.cc`: Updated symbol resolution to use `GetSymbolWithSymbolPrefix()`.
- `src/ffi/extra/library_module_dynamic_lib.cc`: Implements `GetSymbolWithSymbolPrefix()`.
- `src/ffi/extra/library_module_system_lib.cc`: Implements `GetSymbolWithSymbolPrefix()`.
- `src/ffi/extra/module_internal.h`: Module entry renamed: looks for symbol `__tvm_ffi_main` instead of `__tvm_ffi_main__`.
- `python/tvm_ffi/module.py`: Updated symbol lookup to strip/add prefix correctly.

## Public surface changes

**ABI breaking**: All previously compiled `.so`/`.dll` FFI modules must be recompiled. The exported symbol name changes from `Name` to `__tvm_ffi_Name`.
- Macro change: `TVM_FFI_DLL_EXPORT_TYPED_FUNC(Name, Func)` — symbol emitted is now `__tvm_ffi_Name`
- New `Library` virtual method: `GetSymbolWithSymbolPrefix(const String& name)`
- `Library::GetSymbol()` signature: parameter type changed from `const char*` to `const String&`

## Tests & verification

No new tests added. Existing tests exercise the module loading path which validates the symbol resolution change.

## Risk & rollout notes

High risk: ABI breaking change. All shared libraries compiled with the old convention need to be recompiled. Users who have compiled TVM FFI modules (e.g., via `load_inline`) must rebuild them. This change is intentional and expected during the pre-1.0 development phase.
