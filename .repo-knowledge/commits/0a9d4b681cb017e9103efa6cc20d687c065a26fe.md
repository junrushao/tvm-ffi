# 0a9d4b6 — feat: add ffi::Expected<T> for exception-free error handling (#399)

## TL;DR
- Adds `tvm::ffi::Expected<T>` class for exception-free C++ error handling, analogous to Rust's `Result<T,E>` or C++23 `std::expected`
- Adds `Function::CallExpected<T>()` method for calling FFI functions without exceptions
- Supports registering functions that return `Expected<T>` in the global registry
- Ships 236 lines of implementation and 345 lines of tests

## Why (intent / motivation)
- Some C++ consumers (embedded systems, performance-critical code) cannot use exceptions
- Issue #234 requested a C++23 `std::expected`-style API for TVM FFI
- Enables callers to handle errors via value-based control flow rather than try/catch

## What changed (facts from diff)
- `include/tvm/ffi/expected.h` (new, 236 lines): `Unexpected<E>` wrapper class + `Expected<T>` class with `has_value()`, `value()`, `error()`, `value_or()`, and monadic ops
- `include/tvm/ffi/function.h`: Adds `Function::CallExpected<T>()` template method (+54 lines)
- `include/tvm/ffi/function_details.h`: Type trait support for `Expected<T>` return types (+5 lines)
- `include/tvm/ffi/tvm_ffi.h`: Includes `expected.h` (+1 line)
- `tests/cpp/test_expected.cc` (new, 345 lines): GoogleTest tests for all Expected behaviors

## Public surface changes (if any)
- API: New public C++ API — `tvm::ffi::Expected<T>`, `tvm::ffi::Unexpected<E>`, `Function::CallExpected<T>()`
