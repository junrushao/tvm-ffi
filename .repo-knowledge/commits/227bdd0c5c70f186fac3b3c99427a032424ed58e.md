# 227bdd0 — [EXTRA] Improve the Error propagation in alloc (#224)

## TL;DR
- Fixes `TVMFFIEnvTensorAlloc` to check the return code before asserting `dlpack_tensor != nullptr`, allowing allocator error messages to propagate correctly
- Registers `MemoryError` as a mapped FFI error type in Python
- Changes torch DLPack allocator to emit `MemoryError` instead of the non-standard `TorchDLPackManagedTensorAllocator` kind

## Why (intent / motivation)
- Previously, when an allocator returned a non-zero return code (error), the code immediately checked `dlpack_tensor != nullptr` before checking `ret != 0`; this discarded the actual error message and replaced it with a generic internal error
- A new test case exposed this regression by checking both the error kind and message

## What changed (facts from diff)
- `src/ffi/extra/env_context.cc`: In `TVMFFIEnvTensorAlloc`, moved `if (ret != 0) return ret;` before the `TVM_FFI_ICHECK(dlpack_tensor != nullptr)` assertion; changed the assertion to use `TVM_FFI_CHECK` with a `RuntimeError` kind and descriptive message
- `python/tvm_ffi/error.py`: Added `register_error("MemoryError", MemoryError)` to map FFI `MemoryError` to Python's built-in `MemoryError`
- `python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`: Changed `SetError` call from `"TorchDLPackManagedTensorAllocator"` to `"MemoryError"` for consistent error kind
- `tests/cpp/extra/test_c_env_api.cc`: Updated `TVMFFIEnvTensorAllocError` test to verify both `error.kind() == "MemoryError"` and the exact message; test allocator now emits `"MemoryError"`

## Public surface changes (if any)
- API: `MemoryError` is now a registered FFI error kind; torch allocator failures now raise Python `MemoryError` instead of a generic `RuntimeError`
- Flags/config: none
- Data formats/schemas: none
