# 438f643 — feat: Fix perf issue in `Map.get` (#341)

## TL;DR
- Fixes a performance regression in `Map.get` that triggered the C++ error-handling pipeline (and its reference-cycle overhead) for every key-miss.
- Introduces `MapGetItemOrMissing` C++ function that returns a sentinel `ObjectRef` instead of raising a `KeyError`, allowing the Python `get` method to check for miss without exception overhead.
- Adds module-level `MISSING` sentinel that is compared with `same_as` rather than `==` to avoid spurious equality.

## Why (intent / motivation)
- `Map.get(key, default)` was implemented as `try: self[key] except KeyError: return default`, which triggered the C++ error path (and the GC-cycle-causing traceback construction) on every cache miss, hurting performance in hot training loops.

## What changed (facts from diff)
- `src/ffi/container.cc`: Adds `GetMissingObject()` singleton and `ffi.MapGetItemOrMissing` global function that catches `tvm::ffi::Error` and returns the sentinel instead of propagating.
- `python/tvm_ffi/container.py`: `MISSING = _ffi_api.MapGetMissingObject()` at module level; `Map.get` now calls `_ffi_api.MapGetItemOrMissing` and tests `MISSING.same_as(ret)`; `ItemsView.__contains__` uses `Map.get` with `MISSING` sentinel.
- `python/tvm_ffi/_ffi_api.py`: Adds type stubs for `MapGetItemOrMissing` and `MapGetMissingObject`.
