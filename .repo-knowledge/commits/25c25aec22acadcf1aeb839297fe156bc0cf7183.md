# 25c25ae — [C-API] Introduce TVMFFIHandleInitOnce (#317)

## TL;DR
- Adds two new C API functions `TVMFFIHandleInitOnce` and `TVMFFIHandleDeinitOnce` for thread-safe, lazy initialization and deinitialization of static handles.
- Implemented without C++ `std::call_once` so it is usable from DSL runtimes that may not link the C++ stdlib.
- Comprehensive GoogleTest suite added covering idempotency, error propagation, and multithreaded correctness.

## Why (intent / motivation)
- DSL runtimes (e.g., Rust, MLIR-based frontends) often need to lazily initialize C handles once but don't have access to C++ `std::call_once`.
- The new functions provide a portable, thread-safe solution via atomic acquire/release semantics and a static mutex for the slow path.

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: Declares `TVMFFIHandleInitOnce(void** handle_addr, int (*init_func)(void**))` and `TVMFFIHandleDeinitOnce(void** handle_addr, int (*deinit_func)(void*))`.
- `src/ffi/init_once.cc` (new): Implements both functions using `__atomic_load_n`/`__atomic_store_n` (GCC/Clang) or `InterlockedCompareExchangePointerAcquire`/`_InterlockedExchangePointer` (MSVC).
- `CMakeLists.txt`: Registers `src/ffi/init_once.cc` as a build source.
- `tests/cpp/extra/test_c_env_api.cc`: Adds `TVMFFIHandleInitDeinitOnce` and `TVMFFIHandleInitDeinitOnceMultithreaded` test cases.
