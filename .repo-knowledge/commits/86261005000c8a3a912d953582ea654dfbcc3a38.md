# 8626100 — doc: Polish quickstart doc and add Examples (#170)

## TL;DR
- Renames and restructures the `examples/quick_start` directory to `examples/quickstart` with a cleaner split between `compile/` and `load/` sub-directories.
- Polishes `docs/get_started/quickstart.rst` to use `literalinclude` directives referencing real source files instead of inline code blocks.
- Adds new per-framework loading examples: `load_cpp.cc`, `load_numpy.py`, `load_pytorch.py`, `load_cupy.py`.
- Adds `raw_compile.sh` with tagged regions for inclusion in docs, and new CMakeLists.txt with `EXAMPLE_NAME` option.

## Why (intent / motivation)
- The previous quickstart embedded all code inline in the RST file, making it hard to keep in sync with actual working examples. This refactor links the documentation directly to runnable source files.

## What changed (facts from diff)
- Deleted `examples/quick_start/` directory (old monolithic structure with `run_example.py`, `src/add_one_c.c`, etc.).
- Created `examples/quickstart/compile/add_one_cpu.cc` and `add_one_cuda.cu` (refactored from old `src/`).
- Added `examples/quickstart/load/load_cpp.cc`, `load_numpy.py`, `load_pytorch.py`, `load_cupy.py`.
- Added `examples/quickstart/raw_compile.sh` with `[cpp_compile.begin/end]`, `[cuda_compile.begin/end]`, `[load_cpp.begin/end]` tagged regions.
- Added `examples/quickstart/run_all_cpu.sh` and renamed `run_example.sh` to `run_all_cuda.sh`.
- New `examples/quickstart/CMakeLists.txt` supports `EXAMPLE_NAME` option for `compile_cpu`, `compile_cuda`, `load_cpp`.
- `docs/get_started/quickstart.rst` now uses `.. literalinclude::` for all code snippets.
- `pyproject.toml`: Added `[tool.setuptools_scm]` section.
- `.pre-commit-config.yaml`: Added `--indent=2` to `shfmt`.
