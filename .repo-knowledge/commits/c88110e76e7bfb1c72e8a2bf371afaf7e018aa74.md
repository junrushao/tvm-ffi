# c88110e — fix(Map): `Map.get` should never throw when element is missing (#48)

## TL;DR
- Fixes `DenseMapObj::At` to throw `KeyError` instead of `IndexError` when a key is not found in the map
- Adds a Python test that confirms `Map.get()` returns `None` for a missing key on a large (100-element) map

## Why (intent / motivation)
- Python's `Mapping.get()` contract requires returning a default (typically `None`) for absent keys, never raising an exception
- The previous `IndexError` from the C++ side propagated through `Map.__getitem__` and prevented `Map.get()` from catching it, so it would raise instead of returning `None`

## What changed (facts from diff)
- `include/tvm/ffi/container/map.h`: `DenseMapObj::At` throws `TVM_FFI_THROW(KeyError)` instead of `TVM_FFI_THROW(IndexError)`
- `tests/python/test_container.py`: `test_large_map_get` added, asserts `amap.get(101) is None` and `amap.get(3) == 9`

## Public surface changes (if any)
- API: `Map.__getitem__` for missing keys now raises `KeyError` (was `IndexError`) — this is the correct Python mapping behaviour
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_container.py::test_large_map_get`
- How to verify manually: `uv run pytest -vvs tests/python/test_container.py::test_large_map_get`
- CI impact: new test added

## Risk & rollout notes
- Risk level: low — behavioural fix; `KeyError` vs `IndexError` change is a correction per the mapping protocol
- Rollout/migration: callers catching `IndexError` from `Map.__getitem__` need to catch `KeyError` instead
- Follow-ups: none
