# 7f3f872 — [DLPack] Leverage exchange api when possible (#260)

## TL;DR
- `from_dlpack()` now preferentially uses the `__c_dlpack_exchange_api__` fast path when available, falling back to the standard `__dlpack__` protocol.
- Added a new `_from_dlpack_exchange_api()` internal helper in Cython for this path.
- Fixed a memory leak: when `TVMFFITensorFromDLPackVersioned` fails, the managed tensor deleter is now called to reclaim memory.

## Why (intent / motivation)
- The DLPack exchange API (`__c_dlpack_exchange_api__`) provides a faster, C-level conversion path when available (e.g., when torch-c-dlpack-ext is installed).
- Previously `from_dlpack()` always went through the standard Python `__dlpack__` protocol even when a faster path was available.

## What changed (facts from diff)
- `cython/tensor.pxi`:
  - Removed `_from_dlpack_intptr()` helper (unused).
  - Added `_from_dlpack_exchange_api()` helper that calls `managed_tensor_from_py_object_no_sync` directly and handles cleanup on error.
  - `_from_dlpack_universal()` now checks for `__c_dlpack_exchange_api__` first before falling back to `__dlpack__`.
  - All branches now use `return` to propagate results correctly.
- `cython/function.pxi`:
  - Added managed tensor cleanup on `TVMFFITensorFromDLPackVersioned` failure.
  - Renamed local variable `api` -> `exchange_api` for clarity.
