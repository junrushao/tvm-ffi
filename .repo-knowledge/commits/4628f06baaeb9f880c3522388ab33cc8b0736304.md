# 4628f06 — chore(cython): Specify `--module-name` when building Cython (#248)

## TL;DR
- Replaced runtime `__module__` patching in `__init__.py` with the proper `--module-name tvm_ffi.core` compile-time flag for Cython.
- Bumped minimum required Cython version to `>=3.0` in both `pyproject.toml` and build requirements.
- Updated docstrings to use Sphinx cross-reference syntax (`:py:class:`, `:py:meth:`, hyperlinks) rather than double-backtick literals.

## Why (intent / motivation)
- The `_update_module()` function introduced in PR #177 was a workaround that didn't work in lower Python/Cython versions and was not a good practice.
- Using `--module-name` at compile time is the correct Cython mechanism for controlling module naming.

## What changed (facts from diff)
- `CMakeLists.txt`: Added `--module-name "tvm_ffi.core"` to the Cython transpilation command.
- `pyproject.toml`: `cython` dependency updated to `cython>=3.0` in dev and build requirements.
- `python/tvm_ffi/__init__.py`: Removed `_update_module()` function and its call.
- `docs/conf.py`: Added `.replace("tvm_ffi.core.", "tvm_ffi.")` to `_link_inherited_members` to handle the module name normalization for doc generation.
- Various `.py` and `.pxi` files: Docstring improvements (backticks to Sphinx refs, external DLPack hyperlinks).

## Public surface changes (if any)
- API: none — the `__module__` of Cython types now resolves correctly at compile time.
- Flags/config: Cython version requirement bumped to `>=3.0`.
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: `uv pip install --force-reinstall -e . && python -c "import tvm_ffi; print(tvm_ffi.Object.__module__)"`
- CI impact: Cython>=3.0 required in build environment.

## Risk & rollout notes
