## TL;DR

Introduces `struct UnsafeInit {}` as an explicit opt-in tag for unsafe (null/uninitialized) `ObjectRef` construction. Updates all `TVM_FFI_DEFINE_OBJECT_REF_METHODS*` macros to use `UnsafeInit` instead of accepting a raw `ObjectPtr<Object>`. Adds `ObjectUnsafe::ObjectRefFromObjectPtr<T>(ptr)` as a safe downcast utility. Consolidates mutable and immutable `ObjectRef` macros.

## Why

Previously, `ObjectRef` could be constructed from a raw `ObjectPtr<Object>` with an implicit unsafe cast, making accidental null or wrong-type references easy to create. By requiring the `UnsafeInit` tag for unsafe construction paths, the API makes the risk explicit at the call site. The `ObjectUnsafe` namespace and its `ObjectRefFromObjectPtr` utility provide a controlled escape hatch for framework internals.

## What changed

- `include/tvm/ffi/object.h` (and related headers):
  - Added `struct UnsafeInit {}` tag type.
  - Updated `TVM_FFI_DEFINE_OBJECT_REF_METHODS` and related macros: replaced `ObjectPtr<Object>` constructor with `UnsafeInit` + `ObjectPtr<ContainerType>` constructor.
  - Merged mutable/immutable `ObjectRef` definition macros using `_type_mutable` static field to select `const` vs mutable `operator->`.
  - Added `ObjectUnsafe::ObjectRefFromObjectPtr<T>(ObjectPtr<ContainerType>)` utility function.
- `src/ffi/tensor.cc`: Updated to use `UnsafeInit` where needed.
- `tests/cpp/test_object.cc`, `tests/cpp/testing_object.h`: Updated test objects from `TIntObj()` default construct to `TIntObj(UnsafeInit)`.
- ~18 files in `include/tvm/ffi/` updated to use new macro names/signatures.

## Public surface changes

- New type: `tvm::ffi::UnsafeInit` (tag struct)
- New utility: `tvm::ffi::ObjectUnsafe::ObjectRefFromObjectPtr<T>(ptr)`
- `TVM_FFI_DEFINE_OBJECT_REF_METHODS` macro signature changed: no longer accepts `ObjectPtr<Object>` constructor argument
- All `ObjectRef` subclasses need `UnsafeInit` tag for unsafe null construction

## Tests & verification

Existing C++ tests updated to use `UnsafeInit` constructor. All tests compile and pass.

## Risk & rollout notes

Medium risk. All downstream code that constructs `ObjectRef` variants from `ObjectPtr<Object>` directly must be updated to use `UnsafeInit` or `ObjectUnsafe::ObjectRefFromObjectPtr`. The change is mechanical but requires updating all ObjectRef-derived classes.
