# 0729193 — feat: Automatically add `__init__` method if available (#174)

## TL;DR
- Fixes a silent segfault: calling `SomeObject(...)` when `__init__` was not defined returned an object with `chandle=None`.
- Auto-generates `__init__` from `__ffi_init__` when the C reflection exposes it; otherwise injects a method that raises `RuntimeError`.
- Removes the hand-written `__init__` from `TestIntPair` in `testing.py` since it is now auto-generated.

## Why (intent / motivation)
- Previously, `SomeObject(anything)` silently returned an object with `chandle=None`, causing a segfault on any subsequent field access. This makes the error explicit and immediate.

## What changed (facts from diff)
- `python/tvm_ffi/registry.py`: In `_add_class_attrs()`, after attaching methods, if `__init__` is not already in `type_cls.__dict__`, set it to `__ffi_init__` (if `__c_ffi_init__` was registered) or to `__init__invalid` (a new module-level function that raises `RuntimeError`).
- `__init__invalid(self, *args, **kwargs)` raises `RuntimeError("The __init__ method of this class is not implemented.")`.
- `python/tvm_ffi/cython/object.pxi`: Minor fix — `dict(cls.__dict__)` replaced with `cls.__dict__.copy()`.
- `python/tvm_ffi/testing.py`: Removed explicit `TestIntPair.__init__` (now auto-generated).
- `tests/python/test_object.py`: Added `# type: ignore[call-arg]` annotations where mypy would otherwise flag the auto-generated init.

## Public surface changes (if any)
- API: Classes registered via `@register_object` now get an auto-generated `__init__` if `__ffi_init__` is defined; classes without either raise `RuntimeError` on construction.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_object.py` — existing `test_make_object_via_init` and `test_attribute` adjusted.
- How to verify manually: `uv run pytest tests/python/test_object.py -vvs`
- CI impact: none

## Risk & rollout notes
- Risk level: medium — behavioral change: constructing an object without `__init__` now raises instead of silently returning broken object. Downstream code that relied on the old silent behavior (unlikely but possible) would break.
- Rollout/migration: Subclasses that manually define `__init__` calling `self.__ffi_init__(...)` should work unchanged; they now could optionally remove the boilerplate.
- Follow-ups: none
