# f9d2bff — [FFI][REFACTOR] Hide StringObj/BytesObj into details (#18184)

## TL;DR
- Moves `BytesObjBase`, `BytesObj`, and `StringObj` classes into the `tvm::ffi::details` namespace.
- Updates all call sites in `any.h`, `string.h`, `structural_equal.cc`, and `structural_hash.cc` to use `details::BytesObjBase`, `details::BytesObj`, and `details::StringObj`.
- Prepares the codebase for future changes such as `SmallStr` support.

## Why (intent / motivation)
- Hiding the internal object types in `details` prevents accidental direct use by downstream code and makes the internal representation opaque, enabling future changes (e.g., small-string optimization) without breaking the public API.

## What changed (facts from diff)
- `include/tvm/ffi/string.h`: `BytesObjBase`, `BytesObj`, `StringObj` declarations moved inside `namespace details`; constructors in `Bytes` and `String` updated to use `details::BytesObj` and `details::StringObj`; `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` updated.
- `include/tvm/ffi/any.h`: `AnyHash` and `AnyEqual` updated to use `details::BytesObjBase`.
- `src/ffi/extra/structural_equal.cc`, `structural_hash.cc`: string/bytes comparison cases updated to use `details::BytesObjBase`.

## Public surface changes (if any)
- API: `BytesObjBase`, `BytesObj`, `StringObj` are now in `details` namespace; direct use outside of `tvm::ffi::details` breaks.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: `uv pip install --force-reinstall -e . && uv run pytest -vvs tests/python`
- CI impact: downstream C++ code directly using `BytesObj` / `StringObj` will fail to compile.

## Risk & rollout notes
- Risk level: medium — hides internal types; breaks direct use outside `details`.
- Rollout/migration: Replace `BytesObj` → `details::BytesObj`, `StringObj` → `details::StringObj`, `BytesObjBase` → `details::BytesObjBase`.
- Follow-ups: SmallStr implementation.
