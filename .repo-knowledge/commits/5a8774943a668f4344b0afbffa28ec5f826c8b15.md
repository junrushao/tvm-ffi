# 5a87749 — [CYTHON] Improve fallback and dtype convert behavior (#241)

## TL;DR
- Fixed `tvm_ffi.convert` to always return a proper `tvm_ffi.dtype` instance when given a dtype-like input (e.g., objects with `__dlpack_data_type__`).
- Renamed `_create_dtype_from_tuple` to `_create_cdtype_from_tuple` to clarify that it returns the raw Cython `DataType` (not a user-facing `dtype`).
- Added `__hash__` to Cython `DataType`; improved torch fallback logic with a bugfix in device detection (`!= -1` -> `== -1`).
- Improved JIT fallback warning message to guide users toward AOT install.

## Why (intent / motivation)
- `tvm_ffi.convert` was not returning a `tvm_ffi.dtype` subclass instance when converting dtype-protocol objects, breaking isinstance checks.
- The condition for recording CUDA device info in the torch fallback was inverted, preventing device tracking.
- Cleaner separation between the raw Cython `DataType` and the user-facing `dtype` string subclass.

## What changed (facts from diff)
- `cython/dtype.pxi`: Renamed `_create_dtype_from_tuple` -> `_create_cdtype_from_tuple`; added `__hash__`; extracted `make_dtype_from_dl_data_type()` helper; renamed internal dicts from `*_TO_DTYPE` to `*_TO_DL_DATA_TYPE`.
- `cython/function.pxi`: Fixed `ctx.device_type != -1` to `== -1`; renamed internal Cython function; updated torch/numpy setter dict references.
- `_convert.py`: Objects with `__dlpack_data_type__` now return a `dtype` instance; objects with `__tvm_ffi_object__`, `__cuda_stream__`, `__tvm_ffi_opaque_ptr__`, `__dlpack_device__` pass through unchanged.
- `_optional_torch_c_dlpack.py`: Improved JIT failure warning message.
- `core.pyi`: Updated stub for renamed function.
- `docs/index.rst`: Added recommendation to install `torch-c-dlpack-ext`.

## Public surface changes (if any)
- API: `_create_dtype_from_tuple` renamed to `_create_cdtype_from_tuple` (internal Cython function, not public).
- Flags/config: `TVM_FFI_SKIP_c_dlpack_from_pyobject` env var renamed to `TVM_FFI_SKIP_C_DLPACK_EXCHANGE_API`.
