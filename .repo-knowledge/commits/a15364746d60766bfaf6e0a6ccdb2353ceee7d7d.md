# a153647 — [CYTHON] Expose API to construct Function from extern c (#99)

## TL;DR
- Adds `Function.__from_extern_c__(c_symbol, keep_alive_object=None)` static method to construct a `tvm_ffi.Function` from a raw C function pointer (as an integer) and an optional keep-alive object.
- Adds a `testing.get_add_one_c_symbol` global function that returns the address of a test `__add_one_c_symbol`.
- Verifies ownership semantics: `keep_alive_object` ref-count increases when function is alive and decreases when it is released.

## Why (intent / motivation)
- JIT compilers (e.g., LLVM/MLIR execution engines) produce raw function pointers that follow the FFI safe-call ABI. This API enables wrapping those pointers as `tvm_ffi.Function` objects without needing the Python layer to own the symbol.

## What changed (facts from diff)
- `python/tvm_ffi/cython/function.pxi`: adds `Function.__from_extern_c__` with Cython implementation using `TVMFFIFunctionCreate` with `TVMFFIPyObjectDeleter` for keep-alive ref counting.
- `python/tvm_ffi/core.pyi`: stub and docstring for `Function.__from_extern_c__`.
- `python/tvm_ffi/cython/base.pxi`: corrects `deleter` function signature in the `TVMFFIObject` struct binding.
- `src/ffi/extra/testing.cc`: adds `__add_one_c_symbol` C function and `testing.get_add_one_c_symbol` registry entry.
- `tests/python/test_function.py`: adds `test_function_from_c_symbol` covering both null and non-null keep-alive paths.

## Public surface changes (if any)
