# ed56a5e — [FFI] Phase out ObjectPath in favor of AccessPath (#18192)

## TL;DR
- Removes the `using ffi::Tuple;` convenience re-export from the `tvm` namespace in `tuple.h`.
- Part of a broader effort to phase out `ObjectPath` in favor of the refactored `AccessPath`.

## Why (intent / motivation)
- Reduces namespace pollution in `tvm::` by removing a convenience alias that was added for ObjectPath compatibility.
- Aligns with the broader AccessPath refactor (previous commit f4ede98).

## What changed (facts from diff)
- `include/tvm/ffi/container/tuple.h`: removed 4 lines that exposed `ffi::Tuple` into the `tvm` namespace (the `using ffi::Tuple;` declaration and associated comment).

## Public surface changes (if any)
- API: `tvm::Tuple` is no longer available as a direct alias; callers must use `tvm::ffi::Tuple`.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: Rebuild and check that any code using `tvm::Tuple` directly is updated to `tvm::ffi::Tuple`.
- CI impact: Downstream TVM code using `tvm::Tuple` will fail to compile.

## Risk & rollout notes
- Risk level: low — The change is a single alias removal; impact is limited to code that did not qualify with the `ffi::` namespace.
- Rollout/migration: Replace `tvm::Tuple` with `tvm::ffi::Tuple`.
- Follow-ups: none
