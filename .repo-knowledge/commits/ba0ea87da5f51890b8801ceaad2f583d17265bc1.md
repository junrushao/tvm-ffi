# ba0ea87 — [FFI] Improve string equal/hash handling (#18176)

## TL;DR
- Adds a new `Bytes::memequal` helper that uses `std::memcmp` for efficient byte-level equality.
- Replaces `compare(...) == 0` patterns in `String` and `AnyEqual` with `memequal` calls.
- Optimizes `StableHashBytes` to use aligned 64-bit loads when possible, with a separate unaligned path.
- Inlines `Bytes::memncmp` definition into the header; adds `String::compare` coverage tests.

## Why (intent / motivation)
- String equality operations are on the hot path for map lookups and structural equality; `std::memcmp` is faster than the character-by-character loop.
- Aligned loads in the hash function improve throughput on aligned data.

## What changed (facts from diff)
- `include/tvm/ffi/string.h`: `memequal` static method added; `memncmp` inlined; `String::compare(const char*)` rewritten to avoid calling `strlen`; `operator==` overloads updated to use `memequal`.
- `include/tvm/ffi/any.h`: `AnyEqual` string case uses `memequal`.
- `include/tvm/ffi/base_details.h`: `StableHashBytes` splits into aligned and unaligned paths based on `reinterpret_cast<uintptr_t>(it) % 8`.
- `tests/cpp/test_string.cc`: adds `String::Compare` and `String::BytesHash` tests.
