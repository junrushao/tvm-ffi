## TL;DR

Changes `from_dlpack` defaults to be permissive: `require_alignment` defaults to `0` (no alignment check) instead of `8`, and `require_contiguous` defaults to `False` instead of `True`. Renames parameters from `required_*` prefix to `require_*`. Adds `Tensor::IsAligned()` C++ method and `IsDirectAddressDevice()` helper.

## Why

The strict defaults (`required_alignment=8`, `required_contiguous=True`) were causing unnecessary failures when importing tensors from frameworks that use different alignment or non-contiguous layouts. Since TVM FFI's `Tensor` is a thin DLPack wrapper, the alignment and contiguity requirements should be opt-in rather than default, leaving it to the user or downstream code to enforce constraints when needed.

## What changed

- `include/tvm/ffi/container/tensor.h`:
  - Added `IsDirectAddressDevice()` free function (returns true for CPU/CUDA-like devices that use direct memory addresses).
  - Added `Tensor::IsAligned(size_t alignment)` method.
  - Changed `from_dlpack` defaults: `required_alignment` -> `require_alignment=0`, `required_contiguous` -> `require_contiguous=false`.
- `python/tvm_ffi/_convert.py`: Updated `from_dlpack()` call to use `require_alignment=0` and `require_contiguous=False` defaults.
- `python/tvm_ffi/cython/function.pxi`: Updated keyword argument names in DLPack import path.
- `python/tvm_ffi/cython/tensor.pxi`: Updated parameter names in `from_dlpack` Cython binding.

## Public surface changes

- C++ `Tensor::from_dlpack()`: Parameters renamed from `required_alignment`/`required_contiguous` to `require_alignment`/`require_contiguous`, and defaults relaxed.
- Python `from_dlpack()`: Same defaults now permissive (0, False).
- New C++ method: `Tensor::IsAligned(size_t alignment)`
- New C++ free function: `IsDirectAddressDevice(DLDeviceType)`
- Removed: `__dlpack_auto_import_required_alignment__` Python constant.

## Tests & verification

No new tests added. Relaxed defaults mean existing tests that previously required alignment/contiguity still pass.

## Risk & rollout notes

Low risk. Defaults are relaxed (more permissive), so existing code that relied on strict defaults may need to pass the parameters explicitly if enforcement is still desired.
