# 4be1af7 — [FFI][REFACTOR] Move Downcast out of ffi for now (#18198)

## TL;DR
- Removes the `Downcast` family of functions from `include/tvm/ffi/cast.h`, keeping only `GetRef` and `GetObjectPtr`.
- `Downcast` duplicated functionality already available via `Any::cast<T>()` and is being removed to keep the `ffi` layer minimal.
- Updates `tests/cpp/test_string.cc` to use `r.cast<String>()` instead of `Downcast<String>(r)`.

## Why (intent / motivation)
- `Downcast` was added for backward compatibility but duplicates `Any.cast` semantics.
- Keeping `ffi` minimal; moving `Downcast` to a higher layer (`node`) if needed there.

## What changed (facts from diff)
- `include/tvm/ffi/cast.h`: Removed ~82 lines covering four `Downcast` overloads (for `BaseRef->SubRef`, `Any`, `Any&&`, `Optional<Any>`). Removed `using ffi::Downcast;` from `tvm` namespace. Cleaned up unused includes (`dtype.h`, `error.h`, `<utility>`).
- `include/tvm/ffi/any.h`: Minor whitespace cleanup (removed blank line before `}  // namespace ffi`).
- `tests/cpp/test_string.cc`: Replaced `Downcast<String>(r)` with `r.cast<String>()`.

## Public surface changes (if any)
- API: `tvm::ffi::Downcast` and `tvm::Downcast` are removed. Callers should use `.cast<T>()` on `Any`/`AnyView`, or `GetRef<T>()` for raw pointer upcasting.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_string.cc` — one line changed to use `.cast<String>()`.
- How to verify manually: Rebuild all C++ tests and confirm no `Downcast` references remain.
- CI impact: Any downstream code using `Downcast` will need to be updated.

## Risk & rollout notes
- Risk level: medium — Breaking change for all code using `Downcast`. Downstream TVM code will need migration.
- Rollout/migration: Replace `Downcast<T>(ref)` with `ref.cast<T>()` (for `Any` inputs) or `GetRef<T>(ptr)` (for raw pointers).
- Follow-ups: May be reinstated in a higher-level layer (`node`) if needed.
