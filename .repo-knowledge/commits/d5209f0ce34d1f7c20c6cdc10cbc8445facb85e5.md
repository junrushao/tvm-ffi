# d5209f0 — [FFI] Optimize atomic decref in Object (#18077)

## TL;DR
- Inlines the atomic operations (`IncRef`, `DecRef`, `use_count`) directly into the `Object` class instead of calling shared helper functions in `base_details.h`.
- Removes the three helper functions `AtomicIncrementRelaxed`, `AtomicDecrementRelAcq`, `AtomicLoadRelaxed` from `base_details.h`.
- No semantic change; inlining removes the function call overhead for the hot refcount path.

## Why (intent / motivation)
- The `IncRef`/`DecRef` methods are called on every `ObjectPtr` copy/move/destroy. Inlining these hot-path operations eliminates indirection and allows the compiler to optimize them more aggressively.
- The shared helpers were thin wrappers that added no abstraction value.

## What changed (facts from diff)
- `include/tvm/ffi/base_details.h` (+0/-28): removed `AtomicIncrementRelaxed`, `AtomicDecrementRelAcq`, `AtomicLoadRelaxed`.
- `include/tvm/ffi/object.h` (+30/-3): inlined the atomic operations directly in `use_count()`, `IncRef()`, and `DecRef()` with platform ifdefs.
