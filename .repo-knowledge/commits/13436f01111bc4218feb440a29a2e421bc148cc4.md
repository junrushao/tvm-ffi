# 13436f0 — [FFI][ABI] TVMFFIObject ABI to further align with torch intrusive_ptr (#57)

## TL;DR
- Reorders `TVMFFIObject` header fields: `strong_ref_count` and `weak_ref_count` (both `uint32_t`) now come first, followed by `type_index` and `__padding`
- The previous layout had `type_index` first, sharing position with `TVMFFIAny.type_index`; this shared position is intentionally broken
- Windows atomic operations updated from 64-bit to 32-bit intrinsics to match the now-32-bit ref counts
- Removes `tests/cpp/test_c_ffi_abi.cc` which tested the old shared `type_index` position

## Why (intent / motivation)
- Aligns the object header layout with PyTorch's `intrusive_ptr` design, where reference counters come first for better cache performance
- Opens the path for a future optimisation that packs strong and weak counters into a single `uint64_t` atomic (implemented in the immediately following commit 43d13e8)

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: `TVMFFIObject` fields reordered: `uint32_t strong_ref_count`, `uint32_t weak_ref_count`, `int32_t type_index`, `uint32_t __padding`
- `include/tvm/ffi/object.h`: `use_count()`, `IncRef()`, `DecRef()`, `TryPromoteWeakPtr()` updated to 32-bit Windows intrinsics
- `python/tvm_ffi/cython/base.pxi`: struct declaration updated to match new layout
- `docs/concepts/abi_overview.md`: ABI overview updated to reflect new field order
- `tests/cpp/test_c_ffi_abi.cc`: deleted (test asserted old `type_index`-first layout)

## Public surface changes (if any)
- API: none (C API stable callable interface unchanged)
- Flags/config: none
- Data formats/schemas: `TVMFFIObject` struct layout changed — **ABI-breaking** for any code that depends on field offsets

## Tests & verification
- Added/updated tests: `tests/cpp/test_c_ffi_abi.cc` deleted (tested old layout)
- How to verify manually: rebuild all C++ and Python code from source; run full test suite
- CI impact: none (all tests pass with new layout)

## Risk & rollout notes
- Risk level: high — ABI-breaking change to the `TVMFFIObject` struct layout; all consuming code must be rebuilt
- Rollout/migration: Any pre-compiled extension or library using `TVMFFIObject` directly must be rebuilt against the new headers
- Follow-ups: Follow-up commit 43d13e8 merges the two 32-bit counters into a single `uint64_t combined_ref_count`
