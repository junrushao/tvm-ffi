# f7311e4 — [REFACTOR] Transition VisitAttrs to new reflection mechanism in tir/ir_builder/meta_schedule (#18096)

## TL;DR
- Extends `ObjectDef::def_ro`/`def_rw`/`RegisterField` to accept fields from base classes (not just the immediate class), using `BaseClass` as a separate template parameter with a `static_assert` that `BaseClass` is a base of `Class`.
- Adds `TypeTraits` specialization for enum integer types.
- Adds 18 new test lines covering enum type-trait behavior.

## Why (intent / motivation)
- When transitioning `VisitAttrs` to the new reflection, field pointers from base classes (e.g., inherited struct fields) need to be registerable in a derived class's `ObjectDef`.
- Enum types need their own `TypeTraits` specialization so they can be stored/retrieved from `Any` as integers.

## What changed (facts from diff)
- `include/tvm/ffi/reflection/reflection.h` (+7/-6): `def_ro`, `def_rw`, and `RegisterField` now accept `T BaseClass::*` (field pointer to base class member) with `static_assert(std::is_base_of_v<BaseClass, Class>)`.
- `include/tvm/ffi/type_traits.h` (+40/-0): added `TypeTraits<Enum>` specialization for enum types (stores as `int64_t`).
- `tests/cpp/test_any.cc` (+18/-0): new test cases for enum type traits.

## Public surface changes (if any)
- API: `ObjectDef::def_ro` and `def_rw` now accept base-class field pointers (previously only direct-class pointers).
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_any.cc` (+18)
- How to verify manually: `cmake --build build_test && ctest -V --test-dir build_test -R test_any`
- CI impact: none

## Risk & rollout notes
- Risk level: low — Backward-compatible extension (existing code continues to work); `static_assert` will catch incorrect base class usage at compile time.
- Rollout/migration: none
- Follow-ups: Continue migrating remaining VisitAttrs definitions to `ObjectDef`.
