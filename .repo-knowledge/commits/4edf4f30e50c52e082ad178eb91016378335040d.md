# 4edf4f3 — feat(cython): Expose TypeAttr via `_lookup_type_attr` (#247)

## TL;DR
- Added a new C API `TVMFFIGetTypeAttrColumn` and Python binding `_lookup_type_attr(type_index, attr_key)` to query arbitrary per-type attributes from Python.
- Exposed `TVMFFITypeAttrColumn` struct in the Cython base declarations.
- Fixed static registration ordering of built-in type indices in `TypeTable` constructor.

## Why (intent / motivation)
- Future stubgen and dataclass features need a way to query type attributes (e.g., `__repr__`, `__metadata__`) registered on C++ types from Python.
- Currently no type attributes are defined but the API infrastructure is now in place.

## What changed (facts from diff)
- `include/tvm/ffi/c_api.h`: Moved `// more complex objects` comment block to after `kTVMFFIOpaquePyObject`.
- `src/ffi/object.cc`: Added explicit member initializer for `type_attr_columns_` and `type_attr_name_to_column_index_`; reordered `ReserveBuiltinTypeIndex` calls.
- `cython/base.pxi`: Declared `TVMFFITypeAttrColumn` struct and `TVMFFIGetTypeAttrColumn` C function.
- `cython/object.pxi`: Added `_lookup_type_attr(type_index, attr_key)` Python function.
- `core.pyi`: Stub for `_lookup_type_attr`.
- `tests/python/test_metadata.py`: Added `test_class_metadata_none` verifying lookup returns `None` for unregistered attributes.

## Public surface changes (if any)
- API: New public Python function `tvm_ffi.core._lookup_type_attr(type_index: int, attr_key: str) -> Any`.
- Flags/config: none
- Data formats/schemas: none
