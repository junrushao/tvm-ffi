# 6d8b134 — Allow handling of load-bearing compiler flags for dlpack (#231)

## TL;DR
- Adds support for `TVM_FFI_JIT_EXTRA_CFLAGS` and `TVM_FFI_JIT_EXTRA_LDFLAGS` environment variables that inject additional compiler/linker flags when JIT-building the torch C DLPack extension
- Fixes cross-compilation scenarios (e.g., using an x86_64 clang targeting riscv64) where `--sysroot` and `--target` flags are required

## Why (intent / motivation)
- In cross-compilation environments (e.g. QEMU-based CI, embedded targets), the compiler binary may be for a different host arch than the target; passing `--sysroot` and `--target` flags via `CXX` env var works for direct builds but was not passed through when `import tvm_ffi` triggered JIT compilation
- This caused `fatal error: 'bits/libc-header-start.h' file not found` in the FlashInfer project after adding `tvm-ffi` as a dependency

## What changed (facts from diff)
- Added `parse_env_flags(env_var_name: str) -> list[str]` helper function using `shlex.split` to safely parse space-separated flags with fallback to simple split
- In `main()`, after platform-specific ldflags are assembled, reads `TVM_FFI_JIT_EXTRA_LDFLAGS` and extends `ldflags`; reads `TVM_FFI_JIT_EXTRA_CFLAGS` and extends `cflags`

## Public surface changes (if any)
- API: none (internal build script)
- Flags/config: new env vars `TVM_FFI_JIT_EXTRA_CFLAGS` and `TVM_FFI_JIT_EXTRA_LDFLAGS`
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: Set `TVM_FFI_JIT_EXTRA_CFLAGS="--target=riscv64-unknown-linux-gnu --sysroot=/"` and `import tvm_ffi` in a cross-compilation environment
- CI impact: none

## Risk & rollout notes
- Risk level: low — env vars default to empty; no change in standard environments
- Rollout/migration: cross-compilation users must set the new env vars
