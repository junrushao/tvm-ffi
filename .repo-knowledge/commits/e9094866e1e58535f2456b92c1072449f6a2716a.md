# e909486 — [FFI] Introduce FFI reflection support in python (#18065)

## TL;DR
- Adds Python property and method attachment to C++ objects directly via reflection, replacing the older indirect mechanism.
- Introduces `ObjectDef::def_property` and updates `src/ffi/object.cc` with Python-facing registration helpers (+77 lines).
- Adds `src/ffi/testing.cc` testing objects for reflection (+42 lines).
- Replaces deprecated `std::aligned_storage` with a `struct alignas(T)` workaround in `memory.h`.
- Adds `String` constructor helpers for Python interop in `string.h`.

## Why (intent / motivation)
- The new reflection mechanism attaches properties and methods directly to Python class objects via the C++ reflection registry, making attribute access more efficient than the previous approach.
- `std::aligned_storage` is deprecated in C++23; the new `struct alignas(T)` pattern is forward-compatible.

## What changed (facts from diff)
- `include/tvm/ffi/memory.h` (+5/-3): replaced `std::aligned_storage` with explicit `struct alignas(T) { char data[sizeof(T)]; }`.
- `include/tvm/ffi/reflection/reflection.h` (+98/-61): added `def_property`, updated reflection API to support Python-facing property/method registration.
- `include/tvm/ffi/string.h` (+12/-0): added String constructor helpers.
- `src/ffi/object.cc` (+77/-0): Python reflection registration implementation.
- `src/ffi/testing.cc` (+42/-0): test objects for reflection scenarios.
- `tests/cpp/test_reflection.cc` (+6/-4): minor test updates.
