# 14f3c82 — [Fix] fix iterator behavior (#218)

## TL;DR
- Fixes `IterAdapter` and `ReverseIterAdapter` to conform to the C++ named requirement for `InputIterator` (and legacy iterator categories)
- Changes `pointer` and `reference` type aliases to use `const` qualified types and removes the dangling-reference hazard

## Why (intent / motivation)
- According to the C++ standard, the return type of `operator*` must be equivalent to the `reference_type` typedef
- The previous implementation returned `const value_type` (a prvalue) but declared `reference = value_type&`, creating a mismatch that caused undefined behavior when used with STL components like `std::make_move_iterator`

## What changed (facts from diff)
- `IterAdapter::pointer` changed from `Converter::ResultType*` to `const Converter::ResultType*`
- `IterAdapter::reference` changed from `Converter::ResultType&` to `const Converter::ResultType` (non-reference, const value)
- `IterAdapter::operator*` return type changed from `const value_type` to `reference` (consistent with typedef)
- Same changes applied to `ReverseIterAdapter`

## Public surface changes (if any)
- API: `IterAdapter::reference` type changed; callers binding `auto&` to dereferenced iterators may observe behavior changes (the type is now a value, not a reference)
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
