# 7057705 — [Lint] Lint the build torch c dlpack utility (#203)

## TL;DR
- Renames `_build_optional_c_dlpack.py` to `_build_optional_torch_c_dlpack.py` for clarity
- Refactors CLI argument parsing out of module-level scope into the `main()` function to fix lint violations
- Introduces versioned, device-tagged library naming: `libtorch_c_dlpack_addon_torch{major}{minor}-{cpu|cuda}.{ext}`
- Separates build directory (for compilation artifacts) from output directory (for the final `.so`)

## Why (intent / motivation)
- Module-level `argparse.ArgumentParser` definitions triggered lint errors
- Previous library naming did not encode torch version or device, making it impossible to cache multiple variants side-by-side
- Better separation of build and output dirs enables atomic rename pattern

## What changed (facts from diff)
- Script renamed from `_build_optional_c_dlpack.py` to `_build_optional_torch_c_dlpack.py`
- CLI arguments renamed from `--build_dir`/`--build_with_cuda` (underscore) to `--build-dir`/`--build-with-cuda` (hyphen)
- New `--output-dir` argument added; build artifacts go to temp dir, final `.so` moves to output dir
- New `--libname` argument with `auto` default generates versioned filename
- `IS_DARWIN` constant added; Linux no longer links `-lpython3`, only macOS does
- Top-level tvm_ffi imports moved inside `main()` with `# noqa: PLC0415`
- Tests updated to match new argument names and output paths

## Public surface changes (if any)
- API: none (internal script)
- Flags/config: CLI flags renamed (`--build_dir` -> `--build-dir`, `--build_with_cuda` -> `--build-with-cuda`); new `--output-dir`, `--libname` flags added
- Data formats/schemas: Library filename format changed to `libtorch_c_dlpack_addon_torch{N}{M}-{device}.{ext}`
