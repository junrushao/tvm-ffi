# c665fa3 — [REFACTOR] Update torch to optionally depend on cuda

## TL;DR
- Wraps CUDA-specific headers and stream query code in `#ifdef BUILD_WITH_CUDA` guards in the inline Torch DLPack extension.
- At runtime, only adds `-DBUILD_WITH_CUDA` and CUDA include paths if `torch.cuda.is_available()`.
- Renames the compiled extension from `to_dlpack` to `c_dlpack`.
- Converts the CUDA-based `test_load_inline_cuda_with_env_tensor_allocator` test to a CPU-only `test_load_inline_with_env_tensor_allocator` test.

## Why (intent / motivation)
- Users without CUDA should still be able to build and use the Torch DLPack extension; the previous code unconditionally included CUDA headers.

## What changed (facts from diff)
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Added `#ifdef BUILD_WITH_CUDA` around `<c10/cuda/CUDAStream.h>` include and the cuda stream query block; runtime compilation now checks `torch.cuda.is_available()` before adding CUDA flags.
- `tests/python/test_load_inline.py`: Rewrote the test to use `cpp_sources` instead of `cuda_sources`, run on CPU, and not require CUDA availability.

## Public surface changes (if any)
- API: none
- Flags/config: `-DBUILD_WITH_CUDA` added conditionally during JIT compilation
- Data formats/schemas: none

## Tests & verification

- CI impact: test now passes on CPU-only runners
