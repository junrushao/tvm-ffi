# 2002e28 — chore(build): Fix Windows Build (#134)

## TL;DR
- Explicitly links `tvm_ffi_cython` to `Python::SABIModule` (and `Python::Module` for non-Windows) to fix Windows build.
- Adds a fallback macro `_InlineInterlockedAdd64 = InterlockedAdd64` for ARM64 Windows where `_InlineInterlockedAdd64` is not defined.
- Upgrades CI aarch64 Linux test from Python 3.9 to 3.10.

## Why (intent / motivation)
- Windows MSVC requires explicit linking against the Python SABI module; the ARM64 Windows SDK does not define `_InlineInterlockedAdd64` used by the atomic refcount implementation.

## What changed (facts from diff)
- `CMakeLists.txt`: Added `target_link_libraries(tvm_ffi_cython PRIVATE Python::SABIModule)` and `Python::Module` (non-Windows).
- `include/tvm/ffi/base_details.h`: Added `#define _InlineInterlockedAdd64 InterlockedAdd64` for ARM64/ARM64EC when the intrinsic is missing.
- `.github/workflows/ci_test.yml`: aarch64 Linux matrix entry bumped from Python 3.9 to 3.10.
