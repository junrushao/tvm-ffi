## TL;DR

Fixes `SystemLibrary` symbol resolution to handle the case where the symbol name passed to `GetSymbol()` or `GetSymbolWithSymbolPrefix()` may already contain the symbol prefix. Both methods now try the prefixed form first and fall back to the unprefixed form.

## Why

After the symbol prefix change (#18273), some call sites pass names that already include the `__tvm_ffi_` prefix while others pass bare names. `SystemLibrary` was only trying one form, causing lookup failures when the name already carried the prefix or vice versa. The fix makes lookup robust to both input forms.

## What changed

- `src/ffi/extra/library_module_system_lib.cc`:
  - `SystemLibrary::GetSymbol(const String& name)`:
    - Tries `symbol_prefix_ + name` first.
    - If not found, falls back to plain `name`.
  - `SystemLibrary::GetSymbolWithSymbolPrefix(const String& name)`:
    - Tries `tvm_ffi_symbol_prefix + symbol_prefix_ + name` first.
    - If not found, falls back to `tvm_ffi_symbol_prefix + name`.

## Public surface changes

None. Internal symbol resolution behavior change only.

## Tests & verification

No new tests added. Fix is validated by the system library loading path exercised in existing tests.

## Risk & rollout notes

Low risk. The change is a defensive fallback — the primary lookup path is unchanged; the secondary fallback only activates when the primary fails. Cannot cause regressions for symbols that are found on the first try.
