# 360648f — feat: Add __repr__ generation support for @c_class dataclasses (#411)

## TL;DR
- Adds `repr` parameter to `c_class()` decorator and `field()` function (both default `True`)
- Implements auto-generated `__repr__` method returning `ClassName(field=value, ...)` format
- Fields marked `repr=False` are excluded from the generated representation
- Fixes a bug where previously defined methods could not be overridden by generated ones

## Why (intent / motivation)
- `@c_class` dataclasses lacked `__repr__`, making debugging and logging opaque
- Mirrors Python standard `dataclasses.dataclass(repr=True)` behavior for familiarity
- Improves developer experience when printing or inspecting TVM FFI objects

## What changed (facts from diff)
- `python/tvm_ffi/dataclasses/_utils.py`: Added `_get_all_fields()` helper and `method_repr()` generator; changed `_add_method` to always overwrite (remove early-return guard and `setattr` call)
- `python/tvm_ffi/dataclasses/c_class.py`: Plumbed `repr` parameter through `c_class` and calls `method_repr`
- `python/tvm_ffi/dataclasses/field.py`: Added `repr: bool = True` parameter to `Field` and `field()`
- `tests/python/test_dataclasses_c_class.py`: Added 35 lines of tests for `__repr__` behavior

## Public surface changes (if any)
- API: `c_class(repr=True)` and `field(repr=True)` — backward-compatible new parameters
