# 6ccbdb6 — [Feat] Remove reference cycle in error handling for faster GC (#327)

## TL;DR
- Eliminates a CPython reference cycle introduced inside `_with_append_backtrace` in `error.py` that was keeping intermediate tensors (and entire call frames) alive until the cyclic GC ran.
- Uses `try/finally` with explicit `del py_error, tb` to break the cycle at function return.
- Refactors `TracebackManager.append_traceback` to avoid binding the frame object as a local variable.

## Why (intent / motivation)
- During neural network training, GPU tensors allocated inside a call chain that triggered a C++ error were not freed immediately, increasing memory pressure and hurting throughput.
- The cycle: `_with_append_backtrace` frame -> locals (`py_error`, `tb`) -> `BaseException` -> `TracebackType` -> `_get_frame` frame -> back to `_with_append_backtrace` via `f_back`.

## What changed (facts from diff)
- `python/tvm_ffi/error.py`: `append_traceback` now delegates frame construction to a nested function `create()` to avoid holding a frame reference in the outer scope. `_with_append_backtrace` wraps the traceback-building loop in `try/finally` and deletes `py_error` and `tb` in the `finally` block.
- `tests/python/test_error.py`: Adds `test_error_no_cyclic_reference` which disables the GC, triggers a C++ KeyError, and asserts the local object's weak-ref is `None` immediately after the triggering function returns.
