## TL;DR

Introduces `tvm_ffi.cpp.load_inline()` — a function that compiles inline C++/CUDA source code into a shared library via the Ninja build system, caches the result on disk, and loads it as a TVM FFI `Module`. Also adds a cross-platform advisory `FileLock` utility.

## Why

Users need to write small C++ or CUDA kernels and call them from Python without maintaining a separate build system. `load_inline()` provides a `torch.utils.cpp_extension`-style API for compiling and loading inline C++ code directly from Python, with an on-disk build cache keyed to source content to avoid redundant recompilation.

## What changed

- `python/tvm_ffi/cpp/__init__.py` (new): Exposes `load_inline` from the subpackage.
- `python/tvm_ffi/cpp/load_inline.py` (new, 382 lines): Core implementation. Generates a ninja build file, compiles C++ (and optionally CUDA) sources, links a shared library, and loads it via `tvm_ffi.load_module`. Includes `_decorate_with_tvm_ffi()` to inject `TVM_FFI_DLL_EXPORT_TYPED_FUNC` wrappers, `_find_compiler()`, `_find_cuda_path()`, hash-based caching logic, and `FileLock` usage for concurrent safety.
- `python/tvm_ffi/utils/__init__.py` (new): Exports `FileLock`.
- `python/tvm_ffi/utils/lockfile.py` (new, 113 lines): Cross-platform advisory file lock using `fcntl.flock` on Unix and `msvcrt.locking` on Windows.
- `examples/inline_module/main.py` (new): Example demonstrating inline C++ module usage.
- `tests/python/test_load_inline.py` (new): Integration tests for `load_inline` covering single source, multiple sources, and CUDA.

## Public surface changes

- New public function: `tvm_ffi.cpp.load_inline(name, cpp_source, cuda_source, cpp_functions, cuda_functions, extra_cflags, extra_ldflags, build_directory)`
- New public class: `tvm_ffi.utils.FileLock`

## Tests & verification

New integration tests in `tests/python/test_load_inline.py` covering: basic C++ compilation, function export, multi-source compilation, build directory override, and CUDA kernel compilation.

## Risk & rollout notes

Low risk — entirely new code paths, no modifications to existing APIs. Depends on `ninja` being available on `PATH`. Build cache keyed to source content hash avoids stale artifacts. `FileLock` protects concurrent builds.
