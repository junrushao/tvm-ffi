# 5fba9e8 — [COMPILE] Fixed error compile when using compiler gcc 8.x (#85)

## TL;DR
- Fixes a compilation error on GCC 8.x by replacing a compound `enable_if_t` expression involving `std::underlying_type_t` inside `std::is_integral_v` with a two-step trait.
- Introduces a helper `is_integeral_enum_v<T>` to safely test for integral-enum types.

## Why (intent / motivation)
- GCC 8.x does not permit `std::underlying_type_t<T>` to be instantiated when `T` is not an enum type within a single SFINAE expression, causing a hard compile error instead of substitution failure.

## What changed (facts from diff)
- `include/tvm/ffi/type_traits.h`: added `is_integeral_enum_v<T>` two-stage constexpr variable template (primary is `false`, specialization for `is_enum_v<T> == true` evaluates `is_integral_v<underlying_type_t<T>>`). The `TypeTraits<IntEnum>` specialization now uses `enable_if_t<is_integeral_enum_v<IntEnum>>`.
