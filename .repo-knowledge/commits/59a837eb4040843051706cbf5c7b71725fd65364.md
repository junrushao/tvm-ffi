# 59a837e — [FFI][REFACTOR] Migrate StructuralEqual/Hash to new reflection (#18166)

## TL;DR
- Removes `kTVMFFISEqHashKindCustomTreeNode` from the C ABI (its dispatch is now handled via `TypeAttrColumn` lookup regardless of kind).
- `StructEqualHandler` and `StructuralHashHandler` now check `custom_s_equal[type_index]` / `custom_s_hash[type_index]` first; if non-null they use the custom function, otherwise they fall back to field iteration.
- Adds NaN-aware comparison/hashing for float values.
- Error messages on missing metadata or unsupported kind changed from silent fallback to `TVM_FFI_THROW(TypeError)`.

## Why (intent / motivation)
- The `kTVMFFISEqHashKindCustomTreeNode` enum value was introduced temporarily; the cleaner design is to check the `TypeAttrColumn` directly and dispatch unconditionally.
- This migration makes the equal/hash behavior predictable and removes the need for a separate kind enum value.

## What changed (facts from diff)
- `c_api.h`: removes `kTVMFFISEqHashKindCustomTreeNode = 6` and its doc comment.
- `structural_equal.cc`: `CompareObject` now throws `TypeError` if metadata is missing or kind is `Unsupported`; checks `custom_s_equal[type_index]` rather than `kTVMFFISEqHashKindCustomTreeNode`; fixes NaN float comparison; FreeVar mapping moved after success check.
- `structural_hash.cc`: analogous changes; NaN hash normalized to quiet NaN; `s_hash_callback_` signature updated to `(AnyView val, uint64_t init_hash, bool def_region)`.
- `testing_object.h`: `TCustomFuncObj._type_s_eq_hash_kind` changed from `kTVMFFISEqHashKindCustomTreeNode` to `kTVMFFISEqHashKindTreeNode`; `SHash` signature updated.

## Public surface changes (if any)
- API: `kTVMFFISEqHashKindCustomTreeNode` removed from C ABI.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification

## Risk & rollout notes
- Risk level: medium — C ABI removal; NaN handling is a behavioral fix.
- Rollout/migration: Replace `kTVMFFISEqHashKindCustomTreeNode` with `kTVMFFISEqHashKindTreeNode` and ensure `__s_equal__`/`__s_hash__` are registered via `TypeAttrDef`.
- Follow-ups: Phase out SEqualReduce/SHashReduce.
