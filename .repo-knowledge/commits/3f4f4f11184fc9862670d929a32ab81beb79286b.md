# 3f4f4f1 — [FFI] Fix JSON parser/writer for the fast-math flag (#18221)

## TL;DR
- Fixes strict-aliasing violations in the `FastMathSafe*` functions introduced in commit 1a271f0, which caused `-Werror=strict-aliasing` compilation errors.
- Replaces `*reinterpret_cast<const double*>(&bits)` / `*reinterpret_cast<const uint64_t*>(&x)` patterns with C-compliant type-punning via anonymous `union { uint64_t from; double to; }`.

## Why (intent / motivation)
- The previous implementation used pointer-aliasing (`reinterpret_cast`) which is undefined behavior under strict aliasing rules. GCC emits a hard error (`-Werror=strict-aliasing`) for this pattern. Using a union is the correct C++ idiom for type-punning without UB.

## What changed (facts from diff)
- `src/ffi/extra/json_parser.cc`: In `FastMathSafePosInf()`, `FastMathSafeNegInf()`, `FastMathSafeNaN()` — replaced pointer cast with `union { uint64_t from; double to; }` and write-then-read pattern.
- `src/ffi/extra/json_writer.cc`: In `FastMathSafeIsNaN()` and `FastMathSafeIsInf()` — replaced `*reinterpret_cast<const uint64_t*>(&x)` with `union { double from; uint64_t to; }` pattern.
