# 0d157dc — [CMAKE] Allow threads to be not found for cross compilation (#397)

## TL;DR
- Makes `find_package(Threads)` optional (removes `REQUIRED`) to allow building for cross-compilation targets where pthreads may not be available
- Only links `Threads::Threads` when `Threads_FOUND` is set
- Moves `find_package(Threads)` from the top of `CMakeLists.txt` to after the object target setup

## Why (intent / motivation)
- On some bare-metal or WASM cross-compilation targets the host toolchain finds no threads library; making it `REQUIRED` caused a hard CMake configuration failure even when the downstream project could supply its own threading implementation via source bundling

## What changed (facts from diff)
- `CMakeLists.txt`: Moved `find_package(Threads)` to after `tvm_ffi_add_target_from_obj`; wrapped the two `target_link_libraries(... Threads::Threads)` calls in an `if(Threads_FOUND)` guard

## Public surface changes (if any)
- API: none
- Flags/config: none new — behavior change: threads linkage is now conditional
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: Configure with a cross-toolchain that has no pthreads and verify CMake succeeds
- CI impact: none for normal x86/arm64 builds
