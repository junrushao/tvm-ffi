# 53ffe5e — [Fix] Restrict stride normalization to 1D tensors on export (#23)

## TL;DR
- Narrows the stride normalization logic in `toDLPackImpl` so it only applies to 1-D tensors with a single element and a non-unit stride.
- Replaces the previous multi-dimensional loop-based normalization with a one-liner condition.
- References pytorch/pytorch#163274 as the motivation.

## Why (intent / motivation)
- The previous implementation over-eagerly normalized strides for any dimension where `size == 1`, which could produce incorrect DLPack tensors for multi-dimensional tensors with non-standard strides. The fix restricts this to the known-safe case: 1-D, size-1 tensors.

## What changed (facts from diff)
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Replaced ~19-line loop-based stride normalization with `bool need_normalize_strides = src.ndim() == 1 && src.size(0) == 1 && src.stride(0) != 1;` (using `ndim()` — corrected to `dim()` in next commit).
- Simplified `as_strided` call to use `{1}` as the stride.

- Data formats/schemas: DLPack stride handling for size-1 multi-dim tensors corrected
