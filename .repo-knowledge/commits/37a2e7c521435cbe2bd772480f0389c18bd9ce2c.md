# 37a2e7c — [FFI][REFACTOR] Update to distinguish as and cast (#17979)

## TL;DR
- Introduces a clear semantic split: `as<T>()` performs strict type checking without conversion; `cast<T>()` runs full type conversion.
- Adds `try_cast<T>()` as an optional-returning variant of `cast<T>()`.
- Refactors `TypeTraits` to expose `CheckAnyStrict`, `TryCastFromAnyView`, `CopyFromAnyViewAfterCheck` — separating strict check from conversion.
- Adds `as<T>()` Object pointer shortcut overload.

## Why (intent / motivation)
- The previous `as()` was conflated with type conversion, leading to confusion.
- Clear separation: `as` = "is this already this type?" (no conversion), `cast` = "can I get a value of this type?" (may convert).
- Enables callers to distinguish between type checking and type coercion, which is important for correct semantics and performance.

## What changed (facts from diff)
- `include/tvm/ffi/any.h` (+111/-25): `AnyView::as<T>()` now uses `CheckAnyStrict`; added `as<T*>()` Object pointer overload; `cast<T>()` now calls `TryCastFromAnyView`; `Any::as<T>()` and `Any::cast<T>()` updated similarly.
- `include/tvm/ffi/type_traits.h` (+79/-73): split `TryConvertFromAnyView` into `CheckAnyStrict` + `CopyFromAnyViewAfterCheck` (no-conversion) vs `TryCastFromAnyView` (with conversion).
- Container headers (`array.h`, `map.h`, `tuple.h`, `variant.h`, `dtype.h`, `function.h`, `string.h`, `rvalue_ref.h`): updated to use `TryCastFromAnyView` / `CopyFromAnyViewAfterCheck` as appropriate.
- `src/ffi/ndarray.cc`: minor update.
- Tests: `test_any.cc` (+33), `test_string.cc` (+16/-15), `test_dtype.cc` (+2/-2), `test_variant.cc` (-1).

## Public surface changes (if any)
- API: `AnyView::as<T>()` behavior changed — now strict (no conversion); `AnyView::cast<T>()` performs conversion. `try_cast<T>()` added as optional-returning helper.

- Rollout/migration: Audit all `as<T>()` call sites; replace with `cast<T>()` or `try_cast<T>()` where type conversion is intended.
