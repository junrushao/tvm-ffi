# a06d0df — [Fix] Remove python lib during building torch c dlpack ext (#210)

## TL;DR
- Fixes a linker error on Linux by removing the `-lpython3` flag when building the torch C DLPack extension
- On macOS, the Python shared library is still linked because `libtorch_python` requires it
- On Windows, the Python lib path resolution is corrected (uses `sys.base_exec_prefix / "libs"` instead of the include path)

## Why (intent / motivation)
- CI failure at https://github.com/apache/tvm-ffi/actions/runs/18935308302 showed the Linux build was incorrectly linking against the Python shared library
- On Linux, `libtorch_python` is not needed and linking Python introduces symbol conflicts
- On macOS and Windows, `libtorch_python` requires the Python shared library for pybind11 symbols

## What changed (facts from diff)
- Added `IS_DARWIN = sys.platform == "darwin"` constant
- Linux path (`else` branch) removed; now only Darwin (`if IS_DARWIN`) links `-lpython{version}`
- Windows path resolution for Python lib changed from `sysconfig.get_path("include")` to `Path(sys.base_exec_prefix) / "libs"` to find `.lib` files correctly
- Windows branch no longer appends `python_lib` to `ldflags` separately (was a duplicate)
