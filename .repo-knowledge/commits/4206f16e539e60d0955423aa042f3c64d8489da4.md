# 4206f16 — [CORE] Use new for singleton to prevent de-alloc order issues (#133)

## TL;DR
- Changes `TypeTable::Global()` from a stack-allocated static local (`static TypeTable inst`) to a heap-allocated singleton (`static TypeTable* inst = new TypeTable()`).
- The heap-allocated pointer is never deleted; memory is reclaimed by the OS at program exit.

## Why (intent / motivation)
- During shared library unloading, static destructors may run after other libraries that still need the type table. Using `new` ensures the `TypeTable` pointer remains valid for the entire program lifetime even if other statics are destructed first.

## What changed (facts from diff)
- `src/ffi/object.cc`: `TypeTable::Global()` now allocates via `new TypeTable()` and returns the raw pointer, which persists for the process lifetime.
