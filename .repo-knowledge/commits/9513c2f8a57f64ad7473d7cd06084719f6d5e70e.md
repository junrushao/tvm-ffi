# 9513c2f — feat: Introduce List as Mutable Sequence (#443)

## TL;DR
- Introduces `List<T>`, a mutable sequence container alongside the existing immutable `Array<T>`.
- Extracts `SeqBaseObj` as a shared base class for `ArrayObj` and `ListObj`, significantly reducing code duplication.
- Adds cycle detection in serialization, structural hash/equal, and JSON writer for `List` (which can form reference cycles unlike `Array`).
- Updates Python bindings and `stl.h` to accept both `kTVMFFIArray` and `kTVMFFIList`.

## Why (intent / motivation)
- `Array<T>` is immutable (copy-on-write). There was no mutable sequence primitive in the FFI. `List<T>` fills this gap with shared-reference semantics.

## What changed (facts from diff)
- New headers: `include/tvm/ffi/container/list.h` (+527 lines), `include/tvm/ffi/container/seq_base.h` (+365 lines).
- `ArrayObj` refactored to inherit from `SeqBaseObj`; 301 lines removed from `array.h`.
- New type index `kTVMFFIList` added to `c_api.h`.
- `container.cc` and `object.cc` updated to register `ListObj`.
- Structural hash/equal, serialization, JSON writer updated to handle `List` with cycle detection.
- Python: new `List` class in `container.py`; exported from `tvm_ffi.__init__`; stub entries in `_ffi_api.py`.
- C++ tests: new `tests/cpp/test_list.cc`; updates to `test_structural_equal_hash.cc` and `test_serialization.cc`.
- Python tests: new `tests/python/test_list.py`.

## Public surface changes (if any)

- Flags/config: none
