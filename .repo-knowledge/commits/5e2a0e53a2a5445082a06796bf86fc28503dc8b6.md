# 5e2a0e5 — Enable py38 build (#145)

## TL;DR
- Lowers the minimum supported Python version from 3.9 to 3.8 across all project metadata and runtime guards.
- Adds Python 3.8 compatibility shims in `container.py` (using `typing` instead of `collections.abc` generics).
- Adds `from __future__ import annotations` to several Python files to make forward references work on 3.8.
- Adds `"FA"` (flake8-future-annotations) to the ruff lint ruleset to enforce the `__future__` import.
- Guards a Torch scalar type (`ScalarType::Int1` etc.) behind a `TORCH_VERSION` preprocessor check for older Torch compatibility.

## Why (intent / motivation)
- Some deployment environments still run Python 3.8 (e.g., older Linux distros, embedded systems).
- Supporting 3.8 broadens the wheel distribution coverage.

## What changed (facts from diff)
- `pyproject.toml`: `requires-python` changed from `>=3.9` to `>=3.8`; ruff `target-version` set to `py38`; cibuildwheel `build` list adds `cp38-*`; mypy `python_version` updated.
- `python/tvm_ffi/base.py`: Runtime version guard lowered to 3.8.
- `python/tvm_ffi/container.py`: Version-conditional imports for `ItemsView`, `KeysView`, `ValuesView`, `Mapping`, `Sequence` to use `typing` on 3.8.
- Multiple Python files: added `from __future__ import annotations` and replaced `"ClassName"` string annotations with bare class references.
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Wraps `ScalarType::Int1/Int2/...` inside `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 6`.
- `tests/lint/check_asf_header.py`, `check_version.py`: Updated `Optional[T]` to `T | None` style (enabled by `__future__` import).
