# e54d15d — fix: add bounds checking for size() and stride() methods (#375)

## TL;DR
- Added index bounds checking to `Tensor::size()`, `Tensor::stride()`, `TensorView::size()`, and `TensorView::stride()` methods
- Out-of-range access now throws `IndexError` instead of causing undefined behavior
- Added C++ and Python tests for the new bounds checking

## Why (intent / motivation)
- The `size()` and `stride()` methods previously computed an adjusted index but did not validate it before using it to index into `shape`/`strides` arrays, leading to potential out-of-bounds memory access

## What changed (facts from diff)
- `include/tvm/ffi/container/tensor.h`: both `Tensor::size(int64_t idx)` and `Tensor::stride(int64_t idx)` now compute `adjusted_idx` and throw `TVM_FFI_THROW(IndexError)` if `adjusted_idx < 0 || adjusted_idx >= ptr->ndim`; same pattern applied to `TensorView::size()` and `TensorView::stride()`
- `tests/cpp/test_tensor.cc`: new `TEST(Tensor, SizeStrideOutOfBounds)` test (+14 lines)
- `tests/python/test_tensor.py`: updated (+5/-4) to cover out-of-bounds stride/size access

## Public surface changes (if any)
- API: `Tensor::size()`, `Tensor::stride()`, `TensorView::size()`, `TensorView::stride()` now throw `IndexError` for out-of-range indices (previously UB)
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_tensor.cc` (+14), `tests/python/test_tensor.py` (+5/-4)
- How to verify manually: `pytest -vvs tests/python/test_tensor.py` and `ctest -V -R Tensor --test-dir build_test`
- CI impact: existing test suite gains new passing tests
