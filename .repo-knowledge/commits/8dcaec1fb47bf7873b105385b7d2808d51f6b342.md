# 8dcaec1 — feat: Add `keep_module_alive` to `load_module` (#334)

## TL;DR
- Introduces `keep_module_alive: bool = True` parameter to `load_module`, `cpp.load_inline`, and `cpp.load`.
- When `True` (the default), the loaded module is registered in a C++-side `ModuleGlobals` singleton inside `libtvm_ffi.so`, preventing Python from unloading the library while the process runs.
- Fixes issues #264 and #322 (segfaults from destructors called in unloaded libraries).
- Removes the manual `gc.collect()` / `del mod` workarounds from tests.

## Why (intent / motivation)
- Dynamically loaded modules hold destructors in their own .so. If Python GC unloads the module before all objects referencing it are freed, the destructors call invalid memory addresses and segfault.

## What changed (facts from diff)
- `src/ffi/extra/module.cc`: Adds `ModuleGlobals` class (thread-safe `Map<Module, int>` singleton) with `Add`/`Remove` methods; registers `ffi.ModuleGlobalsAdd` and `ffi.ModuleGlobalsRemove` global functions.
- `python/tvm_ffi/module.py`: `load_module` now calls `_ffi_api.ModuleGlobalsAdd(mod)` when `keep_module_alive=True`.
- `python/tvm_ffi/cpp/extension.py`: `load_inline` and `load` accept and forward `keep_module_alive`.
- `python/tvm_ffi/_ffi_api.py`: Adds type stubs for `ModuleGlobalsAdd`/`ModuleGlobalsRemove`.
- Tests: Removed manual GC/delete workarounds from `test_stl.py` and `test_build.py`.

## Public surface changes (if any)
- API: `load_module(path, keep_module_alive=True)`, `cpp.load_inline(..., keep_module_alive=True)`, `cpp.load(..., keep_module_alive=True)`; new globals `tvm_ffi._ffi_api.ModuleGlobalsAdd`, `tvm_ffi._ffi_api.ModuleGlobalsRemove`
