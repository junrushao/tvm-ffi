# 4fcf94f — [Utils] Add `build_inline` utility (#73)

## TL;DR
- Adds `tvm_ffi.cpp.build_inline(...)` which compiles C++/CUDA inline source to a shared library and returns the path without loading it.
- Refactors the existing `load_inline` to call `build_inline` internally.
- Adds `autodoc_typehints = "description"` to Sphinx docs config.

## Why (intent / motivation)
- Users may want to build a module once and load it multiple times or from different processes; `build_inline` separates the build step from loading, enabling caching workflows.

## What changed (facts from diff)
- `python/tvm_ffi/cpp/load_inline.py`: original `load_inline` function renamed to `build_inline` (returns `str` path instead of `Module`); new `load_inline` wrapper calls `build_inline` then `load_module`.
- `python/tvm_ffi/cpp/__init__.py`: exports `build_inline` alongside `load_inline`.
- `tests/python/test_build_inline.py` added (new file, +52 lines) testing `build_inline` and manual `load_module`.
- `docs/conf.py`: `autodoc_typehints = "description"` added.
