# 618c03b — doc: Handle builtin and inheritance (#177)

## TL;DR
- Hides inherited methods from Python built-in types (str, tuple, dict, etc.) from the autodoc output to reduce noise.
- For non-builtin inherited members, replaces their docstring with a link to the defining base class.
- Removes pinned version constraints from docs dependencies in `pyproject.toml`.

## Why (intent / motivation)
- `tvm_ffi.dtype` (a str subclass) was showing all `str` methods in the API docs, adding noise. Inherited non-builtin methods were showing with no links to the actual definition.

## What changed (facts from diff)
- `docs/conf.py`: Added `_filter_inherited_members` (replaces `_never_skip_selected_dunders`) that skips built-in method wrappers and methods whose `__objclass__` is a native type; added `_link_inherited_members` that rewrites docstrings of inherited non-builtin methods to link to the defining class; helper functions `_defining_class` and `_import_cls`.
- `_py_native_classes` tuple lists the native types whose members should be hidden.
- `python/tvm_ffi/__init__.py`: Adds `_update_module()` to set `__module__ = "tvm_ffi"` on all public exports for cleaner autodoc.
- `pyproject.toml`: Removed pinned versions from `sphinx-reredirects`, `sphinx-tabs`, `sphinx-toolbox`, `sphinxcontrib-napoleon`, `sphinxcontrib_httpdomain`, `setuptools`, `urllib3`.
