# 54f527f — feat: Support Array Concat in Python (#45)

## TL;DR
- `tvm_ffi.Array` now supports concatenation via `+` operator with other `Array` instances or any `Iterable`
- Implements `__add__` and `__radd__` using `itertools.chain`
- Widens `Array.__init__` to accept any `Iterable[T]` (not just `Sequence`)
- Comprehensive parametrised tests covering all combination cases

## Why (intent / motivation)
- Standard Python sequence types support `+` for concatenation; `Array` being a sequence should behave consistently
- Useful for downstream code that builds arrays incrementally

## What changed (facts from diff)
- `container.py`: `Array.__add__` and `Array.__radd__` added, both use `itertools.chain` and construct a new `Array`
- `container.py`: `Array.__init__` parameter type widened from `Sequence[T]` to `Iterable[T]`
- `tests/python/test_container.py`: `test_array_concat` added with 10 parametrised cases covering Array+Array, Array+list, list+Array, tuple cases, and empty arrays

## Public surface changes (if any)
- API: `Array.__add__`, `Array.__radd__` added; `Array.__init__` now accepts any iterable
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/python/test_container.py::test_array_concat`
- How to verify manually: `uv run pytest -vvs tests/python/test_container.py::test_array_concat`
- CI impact: new parametrised test

## Risk & rollout notes
- Risk level: low — additive feature; no existing behaviour changed
- Rollout/migration: none
- Follow-ups: PR body notes that many other standard list/dict operations are not yet supported
