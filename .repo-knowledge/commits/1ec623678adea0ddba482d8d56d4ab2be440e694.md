# 1ec6236 — [FEAT] Introduce TensorView for non-owning view (#81)

## TL;DR
- Adds `ffi::TensorView`: a lightweight non-owning DLTensor view class in C++.
- Deprecates `ffi::Tensor` as the recommended argument type for kernel functions in favor of `ffi::TensorView`.
- Updates all examples, docs, and test fixtures to use `TensorView` instead of `Tensor` for function parameters.

## Why (intent / motivation)
- Callers cannot always pass an owning `ffi::Tensor` reference (e.g., when wrapping externally-owned DLTensors). `TensorView` enables accepting both `DLTensor*` and `ffi::Tensor` arguments without requiring ownership transfer.

## What changed (facts from diff)
- `include/tvm/ffi/container/tensor.h`: added `class TensorView` with full `DLTensor`-copying semantics, `shape()`, `strides()`, `data_ptr()`, `ndim()`, `numel()`, `dtype()`, `IsContiguous()`, and `operator->`.
- `TypeTraits<TensorView>` specialization added: `field_static_type_index = kTVMFFIDLTensorPtr`; `TryCastFromAnyView` accepts both `DLTensorPtr` and `Tensor` type indices.
- `include/tvm/ffi/object.h`: added `StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"`.
- All examples (`examples/quick_start/`, `examples/packaging/`, `examples/inline_module/`) updated to use `TensorView`.
- Docs (`quick_start.md`, `packaging.md`, `python_guide.md`) updated.
- Tests (`test_tensor.cc`) added `TEST(Tensor, TensorView)`.
- Python test and build scripts updated to use `TensorView` in inline C++ source strings.
- Version bumped to `0.1.0b13`.

## Public surface changes (if any)
- API: `ffi::TensorView` class added to `include/tvm/ffi/container/tensor.h`; `StaticTypeKey::kTVMFFIDLTensorPtr` added.
- Flags/config: none
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: `tests/cpp/test_tensor.cc` (+24, `TEST(Tensor, TensorView)`); various Python test fixtures updated (+9/-9 in `test_load_inline.py`, +1/-1 in `test_build_inline.py`).
- How to verify manually: `ctest --test-dir build_test -R TensorView`; `uv run pytest -vvs tests/python/test_load_inline.py`
- CI impact: none

## Risk & rollout notes
- Risk level: medium — existing code using `ffi::Tensor` as function parameters continues to work; this is an additive API. However, docs now recommend `TensorView` which may confuse existing users.
- Rollout/migration: Update function signatures from `ffi::Tensor x` to `ffi::TensorView x` where ownership is not needed.
- Follow-ups: none
