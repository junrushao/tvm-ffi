# 731955b — refactor: Get `compiled_kernel` from Triton Call Directly (#423)

## TL;DR
- Simplifies cubin extraction in two Triton example scripts by using the return value of the kernel call directly
- Removes fragile cache-traversal code (~6 lines per file) that searched `device_caches` after a dummy launch
- The Triton kernel call now returns `CompiledKernel` directly, making the cache lookup unnecessary

## Why (intent / motivation)
- The previous approach searched the kernel's `device_caches` dict by iterating keys, which was brittle and depended on internal Triton cache structure
- Triton now returns the `CompiledKernel` directly from the launch call, making the direct approach simpler and more robust

## What changed (facts from diff)
- `examples/cubin_launcher/benchmark_overhead.py`: Removed 6 lines of cache traversal; `compiled_kernel = empty_kernel[1,](...)` used directly
- `examples/cubin_launcher/example_triton_cubin.py`: Same simplification; `compiled_kernel = square_kernel[1, 1](...)` used directly
