# 65b5e90 — [Feature] Support AMD HIP for cpp extension (#460)

## TL;DR
- Adds AMD HIP/ROCm as a second GPU backend alongside CUDA in the inline C++ extension build system.
- Auto-detects HIP vs CUDA based on ROCm installation; allows explicit override via `backend` parameter or `TVM_FFI_GPU_BACKEND` environment variable.
- Discovers GPU architecture via `rocm_agent_enumerator` or `rocminfo` (with fallback to `TVM_FFI_ROCM_ARCH_LIST`).

## Why (intent / motivation)
- The `tvm_ffi.cpp.load_inline` / `build_inline` API previously only supported CUDA. AMD HIP users had no way to compile GPU kernels through this interface.

## What changed (facts from diff)
- `python/tvm_ffi/cpp/extension.py` (+155/-18):
  - New `_detect_gpu_backend()` function: checks `TVM_FFI_GPU_BACKEND` env var, then probes for ROCm, falls back to CUDA.
  - New `_resolve_gpu_backend(backend)`: validates explicit `backend` argument.
  - New `_find_rocm_home()`: searches `ROCM_HOME`, `ROCM_PATH`, `hipcc` in PATH, then `/opt/rocm`.
  - New `_get_rocm_target()`: queries `rocm_agent_enumerator` then `rocminfo` for `gfxXXXX` arch, falls back to `TVM_FFI_ROCM_ARCH_LIST`.
  - `_generate_ninja_build`: `with_cuda` replaced by `with_hip`/`with_cuda`/`with_backend`; HIP path uses `hipcc`, `--offload-arch=`, `-D__HIP_PLATFORM_AMD__=1`.
  - `build_inline`, `load_inline`, `build`, `load`: new `backend` parameter propagated throughout.
  - `_build_impl`: signature updated; `resolved_backend` computed and passed to ninja generator.

## Public surface changes (if any)
- API: `backend: str | None` parameter added to `build_inline`, `load_inline`, `build`, `load`
- Flags/config: `TVM_FFI_GPU_BACKEND` env var (new); `TVM_FFI_ROCM_ARCH_LIST` env var (new); `ROCM_HOME` / `ROCM_PATH` env vars consulted
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none (manual testing on AMD machine described in PR body)
- How to verify manually: Run `tvm_ffi.cpp.load_inline(..., cuda_sources=..., backend="hip")` on a ROCm system

## Risk & rollout notes
- Risk level: medium — significant refactor of the ninja build generator; changes `with_cuda` flag semantics to `with_backend`
- Rollout/migration: `backend` parameter defaults to `None` (auto-detect); existing CUDA callers unaffected
- Follow-ups: May need AMD CI; `rocminfo` parsing is heuristic
