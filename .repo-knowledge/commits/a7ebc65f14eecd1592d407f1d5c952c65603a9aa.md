# a7ebc65 — Allow `tvm_ffi.device(..., id)` where id is numpy or torch scalar (#347)

## TL;DR
- `tvm_ffi.device(device_type, id)` now accepts any `numbers.Integral` subclass or any object with an `.item()` method (e.g., `numpy.int32`, `torch.Tensor` scalar) as the device index.
- Mirrors the behavior of `torch.device(type, id)`.

## Why (intent / motivation)
- Users passing numpy or torch scalars as device indices got a `TypeError: Invalid device index` even though these are semantically integers.

## What changed (facts from diff)
- `python/tvm_ffi/cython/device.pxi`: `Device.__init__` now imports `numbers.Integral`; accepts `Integral` as the index type; calls `.item()` on objects that have that method before re-checking for `Integral`.
- `tests/python/test_device.py`: Adds test case `("cpu", numpy.int32(1), DLDeviceType.kDLCPU, 1)`.

## Public surface changes (if any)
- API: `tvm_ffi.device(type, id)` now accepts numpy/torch scalars as `id`
- Flags/config: none
