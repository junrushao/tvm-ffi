# 66778b5 — doc: Enable Sphinx Build Checks in CI (#38)

## TL;DR
- Adds a new `doc` CI stage that builds Sphinx HTML docs on every commit and treats warnings as errors
- Introduces a C++ API stub RST file so the build succeeds when Doxygen is not run
- Fixes docstring formatting issues in `_tensor.py` and `module.py` to silence Sphinx warnings
- Adds `setuptools<81` to the docs dependency group as a build fix

## Why (intent / motivation)
- Documentation build errors could accumulate unnoticed without CI enforcement
- The `sphinx-build -W --keep-going` flag ensures every warning causes the CI job to fail
- A stub file for the generated C++ API index avoids a Sphinx missing-file error in non-Doxygen builds

## What changed (facts from diff)
- New `doc` job in `ci_test.yml` runs after `lint` and `prepare`, installs docs group, runs `sphinx-build -W --keep-going -b html docs docs/_build/html`
- `docs/_stubs/cpp_index.rst` added as a placeholder for the Doxygen-generated C++ index
- `docs/conf.py` gains `_prepare_stub_files()` and `setup(app)` hook to copy stubs into place when `reference/cpp/generated/index.rst` is absent
- `docs/reference/cpp/index.rst` wraps C++ API `toctree` in an `ifconfig:: build_exhale` guard
- Docstring headers in `_tensor.py` (Shape) and `module.py` (Module) corrected to NumPy style
- `pyproject.toml` docs group gains `setuptools<81`

## Public surface changes (if any)
- API: none
- Flags/config: new `build_exhale` Sphinx config value (boolean, derived from env var `BUILD_CPP_DOCS`)
