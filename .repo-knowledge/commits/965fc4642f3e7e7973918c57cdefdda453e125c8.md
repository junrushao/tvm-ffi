# 965fc46 — [DLPack] Add inline C++ tests for torch DLPack Exchange API protocol (#111)

## TL;DR
- Adds `tests/python/test_dlpack_exchange_api.py` with comprehensive inline C++ tests for `torch.Tensor.__c_dlpack_exchange_api__`, using `torch.utils.cpp_extension.load_inline` to avoid GIL-release issues with `THPVariable_Wrap`.
- Updates `python/tvm_ffi/cython/tensor.pxi` to derive `__dlpack_version__` from the DLPack `DLPACK_MAJOR_VERSION`/`DLPACK_MINOR_VERSION` macros instead of a hardcoded `(1, 1)`.

## Why (intent / motivation)
- The `DLPackExchangeAPI` struct-based fast exchange protocol (introduced in #96) lacked comprehensive C++ validation. Inline C++ tests can call `THPVariable_Wrap`/`THPVariable_Unpack` directly without running into GIL-release issues that ctypes-based tests encounter.

## What changed (facts from diff)
- `tests/python/test_dlpack_exchange_api.py` (new file, 206 lines):
  - `test_dlpack_exchange_api`: skipped if `torch.Tensor.__c_dlpack_exchange_api__` is unavailable; loads an inline C++ test module via `cpp_extension.load_inline`; runs 6 sub-tests:
    1. API struct version and non-NULL function pointers.
    2. `managed_tensor_allocator` — allocate a (3,4,5) float32 CPU tensor.
    3. `managed_tensor_from_py_object_no_sync` — wrap a `torch.Tensor` and verify shape/dtype.
    4. `managed_tensor_to_py_object_no_sync` — round-trip tensor through managed form.
    5. `dltensor_from_py_object_no_sync` — extract `DLTensor` and verify.
    6. `current_work_stream` — call with CPU or CUDA device type.
- `python/tvm_ffi/cython/tensor.pxi`: `__dlpack_version__ = (1, 1)` → `__dlpack_version__ = (DLPACK_MAJOR_VERSION, DLPACK_MINOR_VERSION)`.
