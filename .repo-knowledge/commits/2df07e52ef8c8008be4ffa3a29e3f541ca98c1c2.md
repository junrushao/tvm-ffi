## TL;DR

Fixes `load_inline` compilation on Windows by adding MSVC-specific compiler flags, linking `tvm_ffi.lib`, using MSVC dependency tracking (`/showIncludes` + `msvc` deps mode), using `.dll` as the extension, using OEM encoding for error output, and escaping colons in Windows paths for Ninja.

## Why

The initial `load_inline` implementation targeted Linux only. Windows requires different compiler flags, a different shared library extension, different dependency tracking syntax in Ninja build files, and path escaping (`:` is a special character in Ninja rules and is common in Windows drive paths like `C:\...`).

## What changed

- `python/tvm_ffi/cpp/load_inline.py`:
  - Added Windows-specific MSVC compiler flags: `/MD`, `/EHsc`, and several warning suppression flags.
  - Added `tvm_ffi.lib` to linker inputs on Windows; `find_libtvm_ffi()` now returns the `.lib` import library.
  - Ninja build file: uses `deps = msvc` and `msvcShowIncludes` for dependency tracking on Windows.
  - Uses `.dll` as the shared library extension on Windows (vs `.so` on Linux).
  - Error output decoded with OEM encoding (`charmap` fallback) on Windows.
  - Colons in paths escaped as `$:` in Ninja build files.
- `tests/python/test_load_inline.py`: Removed the `xfail` markers that excluded Windows from certain tests (partially; Windows-specific `xfail` for some tests added in a later commit).

## Public surface changes

None. Internal `load_inline` build machinery only.

## Tests & verification

Existing `test_load_inline.py` tests now expected to pass on Windows (where MSVC is available).

## Risk & rollout notes

Low risk. Changes are isolated to the `load_inline` build pipeline. No effect on Linux or macOS builds.
