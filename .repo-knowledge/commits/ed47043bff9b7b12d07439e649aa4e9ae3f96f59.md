# ed47043 — [CMAKE] Detect endian when possible (#153)

## TL;DR
- CMake now detects host byte order and defines `TVM_FFI_CMAKE_LITTLE_ENDIAN` accordingly.
- `include/tvm/ffi/endian.h` adds musl libc (`__MUSL__`) to the list of platforms that use `<endian.h>` for runtime endian detection.

## Why (intent / motivation)
- Prior to this change, endianness was determined purely at compile time via preprocessor macros; CMake's `CMAKE_CXX_BYTE_ORDER` is more reliable when cross-compiling.
- musl libc is common in Alpine Linux and similar distros used in containerized deployments; it was missing from the endian detection chain.

## What changed (facts from diff)
- `CMakeLists.txt`: adds `if/elseif/else` block that sets `TVM_FFI_CMAKE_LITTLE_ENDIAN=0` or `=1` as a compile definition based on `CMAKE_CXX_BYTE_ORDER`.
- `include/tvm/ffi/endian.h`: adds `|| defined(__MUSL__)` to the `#elif` platform check that includes `<endian.h>`.
