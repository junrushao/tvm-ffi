# f703a0c — feat: Build PyTorch DLPack extension ahead of time (#189)

## TL;DR
- Introduces `addons/torch_c_dlpack_ext/` — a new standalone Python package (`torch_c_dlpack_ext`) that ships the torch C DLPack extension as an AOT-compiled wheel
- When `torch_c_dlpack_ext` is installed, `tvm_ffi` uses the pre-compiled library instead of JIT-compiling at import time
- Backward compatible: default JIT behavior is unchanged; AOT is opt-in by installing the addon package

## Why (intent / motivation)
- JIT compilation of the torch C DLPack extension at import time adds startup overhead and requires a C++ toolchain
- An AOT wheel allows users (and downstream packages like FlashInfer) to avoid JIT compilation entirely

## What changed (facts from diff)
- `addons/torch_c_dlpack_ext/pyproject.toml`: New package `torch_c_dlpack_ext` v0.1.0 with custom build backend
- `addons/torch_c_dlpack_ext/build_backend.py`: Custom PEP 517 build backend that checks for prebuilt `.so`/`.dll`/`.dylib`; if absent, compiles via `tvm_ffi.utils._build_optional_torch_c_dlpack`
- `addons/torch_c_dlpack_ext/torch_c_dlpack_ext/__init__.py`: Imports `core` module on package init
- `addons/torch_c_dlpack_ext/torch_c_dlpack_ext/core.py`: `load_torch_c_dlpack_extension()` selects the correct prebuilt library based on torch version and CUDA availability, loads it via `ctypes.CDLL`, and sets `torch.Tensor.__c_dlpack_exchange_api__`
- `python/tvm_ffi/_optional_torch_c_dlpack.py`: Adds an early-return path that tries `import torch_c_dlpack_ext` before falling back to JIT; if the AOT package is installed and the attribute is already set, loading is skipped
