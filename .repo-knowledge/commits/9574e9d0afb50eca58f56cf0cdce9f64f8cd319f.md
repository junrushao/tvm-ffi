# 9574e9d — feat: support `ml_dtypes<0.5` (#198)

## TL;DR
- Makes ml_dtypes dtype registration backward-compatible with `ml_dtypes<0.5.0` by guarding new dtypes (`int2`, `uint2`, `float8_e3m4`, `float8_e4m3`, `float8_e8m0fnu`, `float6_*`, `float4_*`) behind `hasattr(ml_dtypes, "int2")`.
- Only registers the newer dtype constants when running against `ml_dtypes>=0.5.0`.

## Why (intent / motivation)
- Downstream projects (e.g., TileLang) using `ml_dtypes==0.4.x` would fail on import because `ml_dtypes.int2` and other attributes do not exist in older versions.

## What changed (facts from diff)
- `python/tvm_ffi/cython/dtype.pxi`: `MLDTYPES_DTYPE_TO_DTYPE` dict now only contains types present in all `ml_dtypes` versions (`int4`, `uint4`, `bfloat16`, and float8 variants available since early versions). Newer types are added conditionally under `if hasattr(ml_dtypes, "int2"):`.

## Public surface changes (if any)
- API: `ml_dtypes<0.5.0` is now fully supported; no change in behavior for `ml_dtypes>=0.5.0`.

- Data formats/schemas: none
