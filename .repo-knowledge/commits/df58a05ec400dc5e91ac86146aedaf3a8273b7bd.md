# df58a05 — feat(typing): Parameterizable `Array[T]` and `Map[K, V]` (#37)

## TL;DR
- `Array` and `Map` are now generic Python types (`Array[T]`, `Map[K, V]`) using `TypeVar`
- `getitem_helper` is typed and uses `operator.index` for safer integer conversion
- Iterator methods and `KeysView`/`ValuesView`/`ItemsView` are fully typed with generics
- `Map.get()` gains proper overloads with default-value typing; internally uses `try/except KeyError` instead of `key in self`

## Why (intent / motivation)
- Despite inheriting from `collections.abc.Sequence` and `Mapping`, `Array` and `Map` were not parameterised, making type-checked code using these containers noisy
- Aligns the container API with PEP 484 generic types expected by downstream users

## What changed (facts from diff)
- `container.py`: `Array` now extends `Sequence[T]`; `Map` now extends `Mapping[K, V]`; `KeysView`, `ValuesView`, `ItemsView` parameterised; TypeVars `T`, `K`, `V`, `_DefaultT` added
- `Array.__getitem__` adds `@overload` signatures for integer vs slice; slice now returns `Array[T]` (later reverted in PR #50)
- `Array.__iter__` added explicitly to yield `T`
- Iterator in `KeysView`, `ValuesView`, `ItemsView` refactored to use a `for _ in range(size)` loop (avoids infinite loop on edge cases with old `while True` + `break`)
- `ItemsView.__contains__` added with correct tuple-pair checking
- `Map.__contains__` signature broadened to `object`; `Map.get()` overloads added
- `testing.py`: `v_map: Map[Any, Any]`, `v_array: Array[Any]`

## Public surface changes (if any)
- API: `Array[T]` and `Map[K, V]` now valid as generic type hints; `Map.get()` overloads added
