# 3b4a532 — [CMAKE] Allow explicit turning threads off (#400)

## TL;DR
- Adds a new CMake option `TVM_FFI_USE_THREADS` (default `ON`) that makes threads linkage explicitly controllable
- When `ON`, `find_package(Threads REQUIRED)` is called (hard failure if not found)
- When `OFF`, threads are not linked at all (useful for cross-compilation targets without pthreads)
- Supersedes the softer auto-detect from the previous commit (#397)

## Why (intent / motivation)
- The purely auto-detect approach from #397 could silently produce a binary without threads on a host that simply has a misconfigured toolchain; an explicit opt-out flag is safer and more predictable for build system integrators

## What changed (facts from diff)
- `CMakeLists.txt`: Added `option(TVM_FFI_USE_THREADS ...)` near the top; replaced the `find_package(Threads)` + `if(Threads_FOUND)` guard from #397 with `if(TVM_FFI_USE_THREADS) find_package(Threads REQUIRED) ...`

## Public surface changes (if any)
- API: none
- Flags/config: New CMake option `TVM_FFI_USE_THREADS` (default `ON`)
- Data formats/schemas: none

## Tests & verification
- Added/updated tests: none
- How to verify manually: `cmake . -DTVM_FFI_USE_THREADS=OFF -B build_no_threads && cmake --build build_no_threads`
- CI impact: none for default builds

## Risk & rollout notes
- Risk level: low — default is `ON`; no change for existing build configurations
- Rollout/migration: Cross-compilation users should set `-DTVM_FFI_USE_THREADS=OFF`
- Follow-ups: `TVM_FFI_USE_DL_LIBS` added in the next commit (#401)
