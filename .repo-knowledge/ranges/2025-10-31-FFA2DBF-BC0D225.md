## Architectural changes

### Rust language bindings (experimental)
- New `rust/` crate workspace with three crates: `tvm-ffi-sys` (raw C API bindings), `tvm-ffi` (safe ergonomic API), `tvm-ffi-macros` (proc-macro `#[tvm_object]`). Covers `Any`, `AnyView`, `Object`, `Function`, `String`, `Shape`, `Tensor`, `Device`, `DType`, `Error`, `Module`. (`09477ce`, `9a6ec6e`, `729f971`)
- Rust `build.rs` links against the `libtvm_ffi` shared library; requires Python package installed first for C headers.

### Reflection and metadata system overhaul
- `TypeSchema<T>` template added across all FFI types for JSON-based type schema generation. (`28fe3cc`)
- `Metadata{{...}}` builder allows attaching arbitrary key-value pairs to fields, methods, and global functions. (`28fe3cc`)
- `TVMFFIFieldInfo.type_schema` and `TVMFFIMethodInfo.type_schema` renamed to `metadata` (ABI-breaking). Docstrings separated from metadata via `ModuleObj::GetFunctionDoc`. (`935a5a0`)

### Stub generation tooling
- `tvm-ffi-stubgen` CLI tool and `tvm_ffi.stub.stubgen` module introduced. Generates in-place type stubs inside `# tvm-ffi-stubgen(begin/end)` markers in `.py`/`.pyi` files, consuming metadata from the C++ reflection registry. (`ea02e64`)
- Auto-extraction of type annotations from function definitions added to docs. (`17ff30b`)

### Object registration simplification
- Removed static `_register_type_index` auto-registration from `TVM_FFI_DECLARE_OBJECT_INFO`; static built-in types now explicitly reserved at startup via `ReserveDepthOneObjectTypeIndex`. Dynamic types require explicit `ObjectDef<T>()` registration. (`9ac3121`)
- Constructor registration now uses pybind11-style `ObjectDef::def(refl::init<Args...>())` instead of `def_static("__ffi_init__", refl::init<T, Args...>)`. (`fc2630f`)
- Python `@register_object` classes auto-generate `__init__` from `__ffi_init__` if available; otherwise inject a `RuntimeError`-raising placeholder to prevent silent segfaults. (`0729193`)

### Tensor and DLPack architecture
- `ffi::TensorView` non-owning view type introduced alongside existing `ffi::Tensor`. (`1ec6236`)
- `TVMFFIEnvTensorAllocator` renamed to `TVMFFIEnvSetDLPackManagedTensorAllocator`; new `TVMFFIEnvTensorAlloc` C API keeps tensor metadata allocated inside `libtvm_ffi`. (`f679fe5`)
- DLPack Exchange API unified: three separate function pointers replaced by a single `DLPackExchangeAPI` struct (aligned with DLPack proposal #175). External tensor types must now provide `__c_dlpack_exchange_api__` instead of the old 3-pointer protocol. (`22a7894`)
- DLPack submodule updated to latest. (`22a7894`, `8377011`)
- Zero-dim tensor strides now allowed to be null. (`4fefeb0`)

### Python protocol system
- `__tvm_ffi_tensor__` protocol introduced for zero-copy tensor pass-through, then generalized to `__tvm_ffi_object__` for any FFI object. (`4bc8925`, `8873700`)
- `__tvm_ffi_opaque_ptr__` protocol for passing opaque C pointers through FFI calls. (`42e0612`)
- `__dlpack_data_type__` protocol for automatic dtype conversion from third-party dtype objects. (`5e648f0`)
- `__dlpack_device__` protocol for automatic device conversion. (`0f8bf9f`)
- Internal `__tvm_ffi_object__` attribute renamed to `_tvm_ffi_cached_object` (follows Python naming conventions). (`8873700`)

### Free-threaded Python support
- Cython module annotated as `freethreading_compatible`; GIL acquisition removed from object deletion callbacks for nogil mode. (`b64b46f`)

### Build and release infrastructure
- `setuptools_scm` replaces hardcoded version strings; `_version.py` auto-generated from git tags. (`ac63fb9`)
- `addons/torch_c_dlpack_ext/` introduced: AOT-compiled wheel for PyTorch DLPack extension, avoiding JIT compilation at import time. (`f703a0c`, `bc0d225`)
- Testing library split from `src/ffi/extra/testing.cc` into `libtvm_ffi_testing.so`. (`da7007f`)
- CMake config discovery (`df04392`), endian detection (`ed47043`), manylinux2014 wheel distribution (`d2e9aa6`), Python 3.8 support (`5e2a0e5`), and libbacktrace symbol hiding (`33b3768`).
- `InvokeExternC` utility added for calling extern "C" functions from C++. (`9186b44`)
- `TVMFFIErrorSetRaisedFromCStrParts` C API for setting error messages from C string parts. (`550e92f`)

### Documentation overhaul
- Quickstart guide rewritten from Markdown to RST with expanded examples. (`6e448cf`, `8626100`, `1fb25db`)
- Stable C ABI guide added. (`369ff23`)
- Rust guide and reference documentation added. (`729f971`, `9a6ec6e`)

## Design decisions

- **metadata vs type_schema**: Renamed `TVMFFIFieldInfo.type_schema` to `metadata` to reflect that the field carries arbitrary JSON, not just type schemas. Docstrings separated into `GetFunctionDoc` for unstructured text. (`935a5a0`)
- **Explicit object registration**: Auto-registration from DLL headers removed in favor of explicit `ObjectDef`/`ReserveDepthOneObjectTypeIndex` to reduce binary size and make registration predictable. (`9ac3121`)
- **pybind11-style init**: Constructor registration aligned with `py::init<Args...>()` pattern for consistency. (`fc2630f`)
- **DLPackExchangeAPI unification**: Three separate function pointers collapsed into one versioned struct following DLPack proposal #175, reducing protocol surface area. (`22a7894`)
- **TensorView vs Tensor**: Non-owning `TensorView` added to avoid ref-count overhead when ownership is not needed. Docs recommend `TensorView` for function parameters. (`1ec6236`)
- **Env-side tensor allocation**: `TVMFFIEnvTensorAlloc` keeps metadata allocation in `libtvm_ffi` to avoid deleter-in-unloaded-library bugs. (`f679fe5`)
- **Protocol generalization**: `__tvm_ffi_tensor__` protocol generalized to `__tvm_ffi_object__` to support any FFI object type, not just tensors. (`8873700`)
- **AOT vs JIT for torch extension**: JIT compilation at import time preserved as default; AOT wheel provided as opt-in addon for environments without C++ toolchain. (`f703a0c`)
- **setuptools_scm**: Git-tag-driven versioning eliminates manual cross-language version synchronization. (`ac63fb9`)

## New APIs and breaking changes

### Breaking changes (ABI/API)
- `TVMFFIFieldInfo.type_schema` -> `metadata`; `TVMFFIMethodInfo.type_schema` -> `metadata` (C ABI struct rename). (`935a5a0`)
- `TVMFFIEnvSetTensorAllocator` -> `TVMFFIEnvSetDLPackManagedTensorAllocator`; `TVMFFIEnvGetTensorAllocator` -> `TVMFFIEnvGetDLPackManagedTensorAllocator` (C ABI rename). (`f679fe5`)
- `Tensor::FromDLPackAlloc` removed; replaced by `Tensor::FromEnvAlloc`. (`f679fe5`)
- External tensor types must provide `__c_dlpack_exchange_api__` instead of `__c_dlpack_from_pyobject__` + `__c_dlpack_to_pyobject__` + `__c_dlpack_tensor_allocator__`. (`22a7894`)
- `__tvm_ffi_tensor__` protocol renamed to `__tvm_ffi_object__`. (`8873700`)
- `refl::init<T, Args...>` free function removed; replaced by `refl::init<Args...>` struct + `ObjectDef::def(init<Args...>())`. (`fc2630f`)
- Static `_type_index` auto-registration removed from `TVM_FFI_DECLARE_OBJECT_INFO`; requires explicit `ObjectDef` registration for dynamic casting. (`9ac3121`)

### New APIs
- **C++**: `ffi::TensorView` non-owning tensor view (`1ec6236`); `TypeSchema<T>` template for JSON schema generation (`28fe3cc`); `Metadata{{...}}` builder (`28fe3cc`); `ModuleObj::GetFunctionDoc` virtual method (`935a5a0`); `InvokeExternC` (`9186b44`); `TVMFFIErrorSetRaisedFromCStrParts` (`550e92f`); `TVMFFIEnvTensorAlloc` (`f679fe5`); `EscapeString` utility (`28fe3cc`); `StaticTypeKey::kTVMFFIError` (`9ac3121`); `StaticTypeKey::kTVMFFIDLTensorPtr` (`1ec6236`)
- **Python**: `tvm-ffi-stubgen` CLI tool (`ea02e64`); `tvm_ffi.get_global_func_metadata()` (`28fe3cc`); `TypeSchema` class (`28fe3cc`); `dtype.from_dlpack_data_type()` (`5e648f0`); protocols `__tvm_ffi_object__`, `__tvm_ffi_opaque_ptr__`, `__dlpack_data_type__`, `__dlpack_device__`; `Tensor.strides` exposed (`8377011`); `load_module` accepts `PathLike` objects (`af898a2`); auto-generated `__init__` on registered objects (`0729193`); Version Query API (`f0058a9`)
- **Rust**: Entire `rust/` workspace: `tvm-ffi-sys`, `tvm-ffi`, `tvm-ffi-macros` crates (`09477ce`)
- **Cython**: `Function.from_extern_c()` (`a153647`); MLIR packed function creation (`f6303b2`); CUDA stream protocol (`b0537f0`)
- **Addon**: `torch_c_dlpack_ext` package for AOT PyTorch DLPack extension (`f703a0c`)
