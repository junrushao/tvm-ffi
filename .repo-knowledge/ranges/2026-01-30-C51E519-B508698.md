## Synthesized evidence

### Architectural changes

1. **Error ABI: cause chaining and extra context** (`4c712ca`). `TVMFFIErrorCell` gains two
   optional fields (`cause_chain`, `extra_context`) appended at the end of the C struct.
   A new C API `TVMFFIErrorCreateWithCauseAndExtraContext` and C++ `Error` accessors
   (`cause_chain()`, `extra_context()`) are added. This lays the groundwork for
   Python-style `raise B from A` exception chaining across the FFI boundary.
   ABI-backward-compatible: existing consumers that ignore the new fields are unaffected.

2. **CUDA API isolation** (`10cb004`, `692a41a`). The `TVM_FFI_CHECK_CUDA_ERROR` macro was
   split: a runtime-API-only version stays in `base.h`; the driver/runtime-unified variant
   is renamed `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR` and confined to
   `internal/unified_api.h` and `cubin_launcher.h`. This prevents general code from
   accidentally depending on CUDA driver headers. `device_guard.h` reverts from
   `unified_api.h` to `base.h`.

3. **UBSan correctness fixes** (`b508698`). Two undefined-behavior issues flagged by UBSan
   are resolved: (a) `ObjectUnsafe::GetObjectOffsetToSubclass` now uses `__builtin_offsetof`
   instead of null-pointer member access; (b) `String` copy guards `std::memcpy` against a
   null source pointer when size is 0.

4. **Rust `Array<T>` binding** (`d0d0e2f`). A 341-line Rust implementation of the
   TVM FFI immutable `Array<T>` container with correct `inc_ref`/`dec_ref` management,
   `FromIterator`/`IntoIterator` traits, and 132 lines of integration tests. Also fixes a
   double-free in `Any::into_raw_ffi_any` by wrapping with `ManuallyDrop`.

5. **Comprehensive concept documentation** (`34ad335`, `9422dca`, `e8028e8`, `f173692`,
   `c78e8b4`, `0369a07`, `46cb971`). Five new RST concept pages added:
   - `docs/concepts/any.rst` — Any/AnyView ownership, layout, ABI boundary
   - `docs/concepts/tensor.rst` — Tensor usage with DLPack
   - `docs/concepts/object_and_class.rst` — Object system, class definition
   - `docs/concepts/func_module.rst` — Function calling convention, exception ABI, module system
   - `docs/concepts/abi_overview.rst` — Stable C ABI overview (replaces old MD version)
   - `docs/packaging/cpp_tooling.rst` — C++ toolchain, umbrella header, CMake integration
   Post-creation, `c78e8b4` refactored and deduplicated content across all concept docs.

6. **CMake cross-compilation support** (`0d157dc`, `3b4a532`, `dcd07cf`). Three successive
   commits make `find_package(Threads)` optional with explicit `TVM_FFI_USE_THREADS` and
   `TVM_FFI_USE_DL_LIBS` CMake options, enabling bare-metal / WASM targets.

### Design decisions

1. **Umbrella header pattern** (`8caa0cb`). Introduced `<tvm/ffi/tvm_ffi.h>` following the
   nanobind/pybind11 convention. Reduces boilerplate for users. Individual headers remain
   functional; the umbrella header is optional.

2. **`Function.__init__` added then reverted** (`8786670`, `91fcaa8`). A direct
   `tvm_ffi.Function(callable)` constructor was added (#395) but reverted (#406) because
   a downstream codebase depended on the previous behavior. The API needs further design
   discussion before re-introduction.

3. **Python packaging doc reorder** (`ad195eb`). Reordered the Python packaging tutorial to
   start with "Build wheel" instead of "Export C++", since the build step is the natural
   entry point for Python users.

4. **`@c_class` alignment with Python `dataclasses`** (`360648f`, `3a5bf5e`). Two features
   bring `@c_class` closer to standard `dataclasses`: (a) `repr=True` parameter for
   auto-generated `__repr__`; (b) `kw_only` parameter and `KW_ONLY` sentinel for
   keyword-only fields. Both default to backward-compatible values.

- `TVMFFIErrorCreateWithCauseAndExtraContext` C API (`4c712ca`)
- `Type2Str<Any&&>`, `Type2Str<AnyView&&>` template specializations (`38914fa`)
- `TVM_FFI_CHECK_CUDA_ERROR` runtime-only macro in `base.h` (`10cb004`)

**New Rust APIs:**
- `tvm_ffi::Array<T>` with `get()`, iteration, `FromIterator`, `IntoIterator` (`d0d0e2f`)

**Behavioral changes (previously undefined behavior, now defined errors):**
- `Tensor::size()`, `Tensor::stride()`, `TensorView::size()`, `TensorView::stride()` throw `IndexError` for out-of-range indices (`e54d15d`)
- `ArrayObj::operator[]` and `ArrayObj::SetItem` throw `IndexError` for negative indices (`ec56178`)
- `TypeTraits<Int>::CopyToAnyView` throws `OverflowError` for `uint64_t` > `INT64_MAX` (`86bbddf`)
- `TVMFFIDataTypeFromString` throws `ValueError` for invalid numeric fields instead of OOB read (`ae30cd6`)

**Renamed/relocated:**
- `TVM_FFI_CHECK_CUDA_ERROR` in `unified_api.h` renamed to `TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR` (`10cb004`)

### Other important changes

- **Error propagation fix for tensor arguments** (`e1bd421`): Fixed a bug where `TVMFFIPyCallManager` silently swallowed function errors when the DLPack allocator restore path overwrote the return code. Regression test added.

- **PyTorch version compatibility** (`4fec972`): Improved dtype handling in `torch_c_dlpack_ext` for older PyTorch versions.
