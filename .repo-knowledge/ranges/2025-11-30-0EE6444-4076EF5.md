## Architectural changes

### 1. Vanilla C++ STL support in FFI (`c3fc8f7`, `88d5130`, `4076ef5`)
New header `include/tvm/ffi/extra/stl.h` provides `TypeTraits` specializations for `std::vector`, `std::array`, `std::optional`, `std::variant`, `std::tuple`, `std::map`, `std::unordered_map`, and `std::function`. This allows C++ exported functions to use STL containers directly as argument and return types without converting to native `tvm::ffi::Array`, `Tuple`, `Map`, etc. Required follow-up fixes for use-after-move (`88d5130`) and segfaults (`4076ef5`).

### 2. Function metadata embedding in shared libraries (`ac7bf68`)
New compile-time flag `TVM_FFI_DLL_EXPORT_INCLUDE_METADATA` controls export of type schema JSON and docstrings alongside DLL-exported functions. C++ `ModuleObj`/`LibraryModuleObj` gain `GetFunctionMetadata()`/`GetFunctionDoc()` methods; Python `Module` gains corresponding methods. Metadata is stored as `__tvm_ffi__metadata_*` and `__tvm_ffi__doc_*` symbols in the shared library. Motivated by compiler frameworks (JAX/XLA, MLIR) that need to validate FFI modules at compile time.

### 3. CUDA kernel launcher utility (`d49effd`, `cdfd041`, `803cdc8`)
New header-only CUDA kernel launcher at `include/tvm/ffi/extra/cuda/cubin_launcher.h` with `CubinModule`/`CubinKernel` classes for loading CUBIN from byte buffers or files. Companion `CUDADeviceGuard` RAII struct (`cdfd041`) in `include/tvm/ffi/extra/cuda/device_guard.h` for multi-GPU contexts. Shared error-checking macro extracted to `include/tvm/ffi/extra/cuda/base.h`. Python side adds `tvm_ffi.cpp.nvrtc.nvrtc_compile()` and `tvm_ffi.utils.embed_cubin` plus CMake `EmbedCubin.cmake`.

### 4. Stubgen refactored into staged pipeline (`1af6d9f`, `92e150b`)
Monolithic `stubgen.py` (528 lines) deleted and replaced with modular pipeline: `file_utils.py` (parsing), `consts.py` (constants), `codegen.py` (generation), `analysis.py`, `utils.py`, `cli.py`. New `import` directive auto-generates required imports; new `__all__` directive populates module-level export lists. Enables `--dry-run` and `--verbose` modes.

### 5. C++ extension build API expanded (`c897e4c`)
New `tvm_ffi.cpp.build()` and `tvm_ffi.cpp.load()` functions compile from `.cc`/`.cu` file paths on disk (complementing existing `build_inline`/`load_inline` for source strings). Internal `load_inline.py` renamed to `extension.py` with shared `_build_impl()`.

### 6. DLPack exchange API upgraded to PyCapsule (`7f3bb77`, `7f3f872`)
`__c_dlpack_exchange_api__` attribute changed from raw integer pointer to PyCapsule, with backward compatibility for the integer form. `from_dlpack()` now preferentially uses the fast C-level exchange path when available, falling back to standard `__dlpack__` protocol.

### 7. Error system conformance to std (`4bccb3e`)
`Error::what()` changed to return only the plain message (no traceback or kind prefix), conforming to `std::exception::what()` noexcept semantics. New `Error::FullMessage()` returns the full traceback-prefixed message. Removes thread-local string storage, improving JIT compatibility.

### 8. Cython module naming fix (`4628f06`)
Replaced runtime `__module__` patching (`_update_module()`) with compile-time `--module-name tvm_ffi.core` Cython flag. The previous workaround did not work on lower Python/Cython versions.

## Design decisions

- **STL interop is opt-in via extra header**: `include/tvm/ffi/extra/stl.h` is not included by default; native TVM containers remain preferred for performance. STL types are bridged through `TypeTraits` specializations using a shared `STLTypeTrait` base. (`c3fc8f7`)
- **Metadata export is off by default**: `TVM_FFI_DLL_EXPORT_INCLUDE_METADATA` defaults to 0; existing users of `TVM_FFI_DLL_EXPORT_TYPED_FUNC` are unaffected. (`ac7bf68`)
- **DLPack exchange API backward compatibility**: The PyCapsule upgrade maintains integer-form acceptance via `_get_dlpack_exchange_api()` Cython helper that accepts both. The torch extension still sets integer form; tvm-ffi eagerly upgrades on load. (`7f3bb77`)
- **Error::what() vs FullMessage() split**: `what()` must be noexcept per the C++ standard; the old implementation allocated a thread-local string with traceback, violating the standard and causing issues with LLVM JIT. (`4bccb3e`)
- **Bool dtype aligned to DLPack**: `bool` changed from `kDLUInt(1)/1bit` to `kDLBool(6)/8bits` to match the DLPack standard, accepting the breaking change for interoperability correctness. (`ae346ec`)
- **Stubgen modularization strategy**: Pipeline split into parsing, analysis, codegen, and CLI phases to enable independent testing and dry-run mode, rather than a monolithic approach. (`1af6d9f`)
- **CUDA extension headers are header-only**: `cubin_launcher.h` and `device_guard.h` require no linking against the TVM FFI library; users only need the CUDA driver API. (`d49effd`, `cdfd041`)
- **Symbol visibility hidden by default**: Extension builds now use `-fvisibility=hidden` to prevent symbol leakage from shared libraries. (`7cd2e50`)

### Breaking changes
- **Error::what()** now returns only the plain message; callers needing traceback must use `FullMessage()` (`4bccb3e`)
- **Bool dtype representation** changed from `kDLUInt(1)/1bit` to `kDLBool(6)/8bits` (`ae346ec`)
- **MemoryError** is now a registered FFI error kind; torch allocator failures raise `MemoryError` instead of `RuntimeError` (`227bdd0`)
- **IterAdapter::reference** type changed from `value_type&` to `value_type` (UB fix) (`14f3c82`)
- **DLPack exchange API attribute** `__c_dlpack_exchange_api__` changed from integer to PyCapsule (backward compatible) (`7f3bb77`)
- **Version bump**: `TVM_FFI_VERSION_PATCH` 1 -> 2 (`00a9ad7`), then 2 -> 5 (post-v0.1.4 release bump, `bb653e9`)
