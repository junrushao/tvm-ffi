## Architectural changes

### 1. GlobalDef replaces TVM_FFI_REGISTER_GLOBAL macro (b333288, 26b68b0)

The legacy `TVM_FFI_REGISTER_GLOBAL` macro and `Function::Registry` class were replaced by `reflection::GlobalDef`, a new class that unifies global function registration with the reflection-style API (`ObjectDef`, `def`, `def_packed`, `def_method`). All internal registration sites (`container.cc`, `function.cc`, `ndarray.cc`, `object.cc`, `testing.cc`) were migrated, and then the old macro/class were deleted entirely (144 lines removed from `function.h`). This consolidates function registration to a single mechanism.

### 2. Reflection module split: reflection.h -> registry.h + accessor.h (e95b43b)

The monolithic `include/tvm/ffi/reflection/reflection.h` was split into:
- `registry.h` — registration-time APIs (`ObjectDef`, `GlobalDef`, `TypeAttrDef`, `EnsureTypeAttrColumn`)
- `accessor.h` — runtime accessor utilities (`GetFieldInfo`, `FieldGetter`, `FieldSetter`, `GetMethod`, `ForEachFieldInfo`)

This reduces compile-time coupling by allowing consumers to include only what they need.

### 3. Core/extra boundary: structural equal/hash isolated to `ffi/extra/` (3fc0391)

`StructuralEqual` and `StructuralHash` were moved from `include/tvm/ffi/reflection/` and `src/ffi/reflection/` to `include/tvm/ffi/extra/` and `src/ffi/extra/`, respectively. They were also removed from the `reflection` namespace and placed directly in `ffi` namespace. The `TVM_FFI_EXTRA_CXX_API` macro was moved from `c_api.h` to `extra/base.h`. This establishes a clear boundary: the core FFI API (reflection, type system) vs. optional "extra" functionality (structural comparison).

### 4. TypeAttr column-store for per-type extensible attributes (9445fe7, 162d600)

A new `TVMFFITypeAttrColumn` mechanism was introduced in the C ABI and C++ API. `TypeAttrDef<Class>` registers per-type function or constant attributes (e.g., `__s_equal__`, `__s_hash__`) in a column-array pattern, indexed by type index. This replaces ad-hoc mechanisms and enables extensible type traits without modifying the fixed `TVMFFITypeMetadata` struct.

### 5. Reflection-based StructuralEqual/Hash replaces legacy SEqualReduce/SHashReduce (9445fe7, 2ec11f5, 59a837e, e52aed5)

The old virtual-method `SEqualReduce`/`SHashReduce` mechanism was fully replaced by reflection-driven structural equality and hashing. The new system:
- Iterates fields via the reflection registry for field-by-field comparison/hashing
- Supports custom `__s_equal__`/`__s_hash__` functions registered via `TypeAttrDef` for types needing semantic equality (e.g., binding-site-aware comparison)
- Reports structured mismatch paths via `AccessPath`/`AccessStep`
- Handles NaN-aware float comparison and aligned-load hash optimization

Legacy flags `_type_has_method_sequal_reduce`, `_type_has_method_shash_reduce`, and `_type_has_method_visit_attrs` were all removed from `Object`.

## Design decisions

### 1. Temporary kTVMFFISEqHashKindCustomTreeNode, then removed (2ec11f5 -> 59a837e)

Commit 2ec11f5 introduced `kTVMFFISEqHashKindCustomTreeNode = 6` in the C ABI to allow types to opt into custom structural equal/hash functions. However, commit 59a837e removed it just 2 days later, replacing the kind-based dispatch with a simpler approach: always check the `TypeAttrColumn` for `__s_equal__`/`__s_hash__` first, falling back to field iteration if not found. This eliminated the need for a dedicated enum value, keeping the C ABI cleaner.

### 2. Reverted for_each extension due to cross-platform issues (5a4038f -> 9a1d41a)

An attempt to extend `for_each_dispatcher` with multi-invocation-form dispatch (using `std::conjunction_v` with complex constraints) was reverted within one day because it caused compilation failures on some supported platforms. The simpler C++17 fold expression approach from 84cfbeb was retained.

### 3. C ABI naming: TypeExtraInfo -> TypeMetadata (9445fe7, 162d600)

`TVMFFITypeExtraInfo` was renamed to `TVMFFITypeMetadata` and `TVMFFITypeRegisterExtraInfo` to `TVMFFITypeRegisterMetadata`. This is a breaking C ABI change requiring recompilation of all pre-compiled binaries. The rationale was that "metadata" is more precise than "extra info" for the type information structure.

### 4. AccessKind enum renames for clarity (3fc0391)

`AccessKind::kArrayIndex` was renamed to `kArrayItem`, `kMapKey` to `kMapItem`, etc. The new names better describe what the access path points to (an item in a container) rather than how it is accessed (by index/key).

## Other important changes

### C++17 modernization (fa5e2ac, 84cfbeb)
- All GCC/Clang `__attribute__((...))` annotations replaced with C++ standard attributes (`[[nodiscard]]`, `[[maybe_unused]]`, etc.) across 16 header files (fa5e2ac).
- `for_each_dispatcher` rewritten using C++17 fold expressions instead of recursive template specialization (84cfbeb).

### Performance: string equal/hash optimization (ba0ea87)
- `Bytes::memequal` uses `std::memcmp` for fast byte equality; replaces character-by-character comparison.
- `StableHashBytes` optimized with aligned 64-bit loads when data alignment permits.
- `String::compare(const char*)` rewritten to avoid calling `strlen`.

### Bug fix: SmallMapInit duplicate keys (0342d85)
- `MapObj::CreateFromRange` for small maps (capacity 2-3) now uses `InsertMaybeReHash` instead of bulk initialization, properly deduplicating duplicate keys. Previously, small maps retained all copies of duplicate keys.

### Improved error message for duplicate function registration (5b0cceb)
- `GlobalFunctionTable::Set` now uses `TVM_FFI_LOG_AND_THROW` with a descriptive message listing likely causes when a function is registered twice.
