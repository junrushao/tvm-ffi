## Architectural changes

This range represents a concentrated effort to build a complete reflection system for the FFI layer, spanning the C ABI, C++ API, and Python bindings. The work proceeds in a clear architectural sequence:

1. **C ABI reflection metadata enrichment** (`1a85688`, `a419ed1`): `TVMFFIFieldInfo` was expanded with `doc`, `type_schema`, `flags`, `size`, `alignment`, `offset`, `getter` (TVMFFIFieldGetter), `setter` (TVMFFIFieldSetter), `default_value`, and `field_static_type_index` fields. A separate `TVMFFIMethodInfo` struct was added. A new `TVMFFIFieldFlagBitMask` enum was introduced. `TVMFFITypeExtraInfo` struct and `TVMFFITypeRegisterExtraInfo` C API were added to carry type-level metadata (`doc`, `creator`, `total_size`).

2. **C++ reflection API expansion** (`1a85688`, `e909486`, `837800e`): `ReflectionDef` was refactored into `ReflectionDefBase` + `ObjectDef`, with methods `def_ro`, `def_rw`, `def_static`. The `ForEachFieldInfo` family was added for iterating fields including parent types. `TVMFFITypeInfo::type_acenstors` was changed from `const int32_t*` to `const struct TVMFFITypeInfo**` for O(1) ancestor lookup.

3. **VisitAttrs migration bridge** (`69f2484`, `f7311e4`): `ForEachFieldInfoWithEarlyStop` was added to support the search-and-stop pattern of old `VisitAttrs`. `ObjectDef::def_ro`/`def_rw` were extended to accept base-class field pointers, enabling derived classes to register inherited fields.

4. **Container ABI stabilization** (`7e0a4b3`): `ArrayObj` storage moved from inplace array to a separately managed `data_` pointer with `data_deleter_`. `MapObj` internals were updated. `TupleObj` dropped `InplaceArrayBase` dependency.

5. **Build model simplification** (`a419ed1`): The `TVM_FFI_BUILD_REGISTRY` CMake option was removed; the registry is now always included. `TVM_FFI_STATIC_INIT_BLOCK` macros were added for registration-time initialization.

6. **Module system preparation** (`11a4a02`): `TVMFFISafeCallType` parameter renamed `self` to `handle` to align with opaque-handle semantics, a prerequisite for bringing the module system to the FFI layer.

## Design decisions

1. **Declarative reflection API** (`1a85688`, `e909486`): The `ObjectDef` builder provides `def_ro`, `def_rw`, `def_static` methods for registering fields and static functions declaratively. The API was factored into `ReflectionDefBase` (registration logic) + `ObjectDef` (field-pointer methods), making Python binding generation straightforward from C++ reflection metadata.

2. **Pointer-based ancestor arrays over index-based** (`837800e`): `TVMFFITypeInfo::type_acenstors` was changed from integer type indices to direct `TVMFFITypeInfo*` pointers. This eliminates a table lookup per ancestor during field iteration, trading slightly more memory for O(1) access.

3. **Decoupled container storage from object header** (`7e0a4b3`): `ArrayObj` moved from `InplaceArrayBase` (which tied ABI to implementation) to a `data_` pointer + `data_deleter_` pattern. This allows future storage changes without breaking the object header ABI.

4. **Always-on registry** (`a419ed1`): Removing `TVM_FFI_BUILD_REGISTRY` eliminates a build configuration axis, simplifying the build model. The registry is lightweight enough to always include.

5. **Gradual migration via bridge functions** (`69f2484`): Rather than requiring a big-bang migration of all `VisitAttrs` code, the `ForEachFieldInfoWithEarlyStop` bridge allows incremental transition while preserving the search-and-stop semantics of the old mechanism.

6. **Duplicate registration is an error** (`a5a08b2`): `TypeTable::RegisterTypeExtraInfo` now throws `RuntimeError` on duplicate registration instead of silently overwriting, catching programming errors early.

## Other important changes

- **Refcount inlining optimization** (`d5209f0`): `IncRef`, `DecRef`, `use_count` atomic operations were inlined directly into the `Object` class, removing function call overhead on the hot refcount path. The shared helper functions (`AtomicIncrementRelaxed`, `AtomicDecrementRelAcq`, `AtomicLoadRelaxed`) were removed from `base_details.h`.

- **C++23 forward compatibility** (`e909486`): `std::aligned_storage` (deprecated in C++23) was replaced with `struct alignas(T) { char data[sizeof(T)]; }` in `memory.h`.

- **`if constexpr` compilation optimization** (`837800e`): `IsObjectInstance<T>()` was updated with explicit `else` branches to help compilers eliminate dead code paths earlier.

- **String helper additions** (`e909486`, `837800e`): `String` constructor helpers and literal helpers were added for Python interop and general convenience.

- **Testing infrastructure** (`e909486`): `src/ffi/testing.cc` gained 42 lines of test objects for reflection scenarios, and `test_reflection.cc` grew by +111/-7 lines across the range.
