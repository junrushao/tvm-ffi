## Architectural changes
- - Changes metadata and doc string allocation in `TVM_FFI_DLL_EXPORT_TYPED_FUNC` and `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` to use `TVMFFIStringFromByteArray`, allocating strings in `libtvm_ffi` rather than in the extension module (.repo-knowledge/commits/dcacb98d189241d52ef51c1d63fb0e9f6c98a4b0.md)
- - Strings created with `::tvm::ffi::String(...)` inside the extension module are allocated in the extension's memory; if the module is unloaded before the string is freed, the deleter becomes invalid (use-after-free / delete-after-module-unload) (.repo-knowledge/commits/dcacb98d189241d52ef51c1d63fb0e9f6c98a4b0.md)
- - How to verify manually: Load a module, get metadata, unload the module, verify the string remains valid (.repo-knowledge/commits/dcacb98d189241d52ef51c1d63fb0e9f6c98a4b0.md)
- - `TVMFFIStringFromByteArray` — now used for safe cross-module string allocation (.repo-knowledge/commits/dcacb98d189241d52ef51c1d63fb0e9f6c98a4b0.md)
- - `python/tvm_ffi/utils/__init__.py`: Imports `kwargs_wrapper` module (.repo-knowledge/commits/3115b237d43fa2c7a24157ec88e1a9f9ec403900.md)
- - Risk level: low — new utility module; no existing code changed (.repo-knowledge/commits/3115b237d43fa2c7a24157ec88e1a9f9ec403900.md)
- - Objects created from a dynamically loaded module hold deleters inside that module's code; if the module is unloaded before those objects are GC'd, the destructor calls an invalid address. (.repo-knowledge/commits/79894c32315108e72e2ccc8f7d9e29118ee6919b.md)
- - Forcing a GC pass before releasing the module reference ensures all such objects are destroyed while the library is still mapped. (.repo-knowledge/commits/79894c32315108e72e2ccc8f7d9e29118ee6919b.md)
- - Follow-ups: Superseded by `keep_module_alive` feature in #334 (.repo-knowledge/commits/79894c32315108e72e2ccc8f7d9e29118ee6919b.md)
- - API: `tvm_ffi.LIB` (new public export); `tvm_ffi.libinfo.load_lib_ctypes` (new); `tvm_ffi.libinfo.find_windows_implib` (moved from `config.py`); `tvm_ffi.base` module removed (.repo-knowledge/commits/6887892d888e0f69df8bd0a8167c5ebe98873a0b.md)
- - Introduces `keep_module_alive: bool = True` parameter to `load_module`, `cpp.load_inline`, and `cpp.load`. (.repo-knowledge/commits/8dcaec1fb47bf7873b105385b7d2808d51f6b342.md)
- - When `True` (the default), the loaded module is registered in a C++-side `ModuleGlobals` singleton inside `libtvm_ffi.so`, preventing Python from unloading the library while the process runs. (.repo-knowledge/commits/8dcaec1fb47bf7873b105385b7d2808d51f6b342.md)
- - Dynamically loaded modules hold destructors in their own .so. If Python GC unloads the module before all objects referencing it are freed, the destructors call invalid memory addresses and segfault. (.repo-knowledge/commits/8dcaec1fb47bf7873b105385b7d2808d51f6b342.md)
- - `src/ffi/extra/module.cc`: Adds `ModuleGlobals` class (thread-safe `Map<Module, int>` singleton) with `Add`/`Remove` methods; registers `ffi.ModuleGlobalsAdd` and `ffi.ModuleGlobalsRemove` global functions. (.repo-knowledge/commits/8dcaec1fb47bf7873b105385b7d2808d51f6b342.md)
- - `python/tvm_ffi/module.py`: `load_module` now calls `_ffi_api.ModuleGlobalsAdd(mod)` when `keep_module_alive=True`. (.repo-knowledge/commits/8dcaec1fb47bf7873b105385b7d2808d51f6b342.md)

- - `examples/packaging/python/my_ffi_extension/base.py`: Reduces to `_LIB = tvm_ffi.libinfo.load_lib_module("my-ffi-extension", "my_ffi_extension")`. (.repo-knowledge/commits/f255650b8e5121452dd60805b206a0cb5bcb6525.md)
