# ADR-0022: Inline TYPE_CHECKING Stubs Over Separate .pyi Files

**TL;DR**: Uses inline `if TYPE_CHECKING:` blocks with comment markers instead of separate `.pyi` stub files, keeping generated type stubs co-located with runtime code and derived from the C++ reflection registry.

## Context

The Python package needed type stubs for FFI-generated functions and object fields/methods. Two approaches were considered:
- Separate `.pyi` stub files (the Python standard)
- Inline `TYPE_CHECKING` blocks within `.py` files, generated by a CLI tool

The reflection system already stores type schemas (`TypeSchema`) for all registered functions, fields, and methods. The stub content is therefore derivable from runtime metadata rather than hand-written.

Usecases:
- IDE autocompletion for `_ffi_api` global functions
- Type checking for `@register_object` class fields and methods
- Extension packages that use TVM FFI reflection for their own types

Design Decisions:
- Use comment markers (`# tvm-ffi-stubgen(begin): global/<prefix>` / `# tvm-ffi-stubgen(end)`) to delimit generated regions within `.py` files.
- Generated content is wrapped in `if TYPE_CHECKING:` so it has no runtime cost.
- A CLI tool `tvm-ffi-stubgen` scans files, queries the FFI registry, and fills the delimited regions.
- Support `ty_map` directives for type alias remapping (e.g., `# tvm-ffi-stubgen(ty_map): ffi.Array -> Sequence`).
- Removed the old `_ffi_api.pyi` stub file; stubs are now co-located in `_ffi_api.py`.

## Implementation Notes
- CLI entry point: `tvm-ffi-stubgen` (registered in `pyproject.toml` as `tvm_ffi.stub.cli:__main__`). Refactored from single `stubgen.py` to staged pipeline in 1af6d9f.
- Five directive types: `global/<prefix>`, `object/<type_key>`, `import` (auto-generates imports), `__all__` (auto-generates export list), and `ty-map` (standalone type alias remapping).
- **Fields outside TYPE_CHECKING** (1af6d9f): Field annotations are now emitted as PEP 526 class-level attributes outside `TYPE_CHECKING`, making them runtime-visible for dataclass-like reflection. Method stubs remain inside `TYPE_CHECKING`.
- `__ffi_init__` is renamed to `__c_ffi_init__` in generated stubs (via `FN_NAME_MAP`).
- Staged pipeline: (1) collect ty-maps, (2) generate stubs + track type usage, (3) generate import blocks.
- `FuncInfo`/`ObjectInfo` classes encapsulate per-function/per-object metadata and codegen (92e150b).
- Evidence: ea02e646aea9 (initial), 1af6d9f (staged pipeline), 92e150b (__all__, FuncInfo/ObjectInfo)
