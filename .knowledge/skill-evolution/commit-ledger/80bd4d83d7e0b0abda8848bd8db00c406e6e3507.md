## What could be improved
- For small backward-compat patches like this (21 lines added, 0 removed, single file), the template sections "Key Exports" and "Usage Examples" feel slightly heavy. A lighter-weight template variant for trivial/low-impact patches might reduce noise in the knowledge base while still capturing the essential what/why/where.
- The commit shape classification "standard" is the closest fit, but a "compat-patch" or "polyfill" sub-category would better describe monkey-patching patterns that backport protocol methods onto third-party classes.

## Template suggestions
- Consider adding a `backward_compat: true|false` field to the frontmatter for commits that polyfill missing features on older dependency versions. This would make it easier to query which knowledge entries are version-gated shims vs. new functionality.
- The "Related commits" field could benefit from a typed relationship (e.g., `depends-on`, `enables`, `superseded-by`) rather than a flat list, to capture that this commit is a follow-up enabler for b0537f0.
