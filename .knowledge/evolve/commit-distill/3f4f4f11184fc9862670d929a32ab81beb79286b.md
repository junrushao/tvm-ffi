- **Template mismatch**: The template has no section for "Naming Convention" tables (useful for the env-api doc which had a 7-row rename table). A "Key Renames" or "Symbol Mapping" optional section in the template would help for refactor-heavy batches.
- **Upstream skill gap**: The `ed56a5e` ledger (trivial) correctly flagged `has_design_updates: false` but also mentioned a stale cross-reference in `0009-structural-eq-hash`. Ledgers should surface stale-reference severity > medium as `has_design_updates: true` to avoid missing them in triage.
- **Quality bar friction**: The ≥1 Evolution Timeline requirement for "≥3 evolution commits" triggered for 0010-json-serialization. In that case it fit well. For 0012-env-api (2 commits), the table felt forced but was still useful for the rename mapping.
- **Procedure friction**: Step 1.5 triage used `has_design_updates` as primary signal, but several "trivial" commits (1a271f0, 3f4f4f1) carried important implementation details (fast-math safety) that needed to be folded into the JSON record. The triage should note that "no new public API surface" ≠ "omit from body text" — trivial commits can still provide invariant annotations.
- **Suggested skill change**: Add guidance that trivial-pool commits with `commit_type: bugfix` in a related scope should be checked for constraint/invariant notes and folded into the matching active-pool design record's "Contracts" section, even if not listed in the evidence matrix.
