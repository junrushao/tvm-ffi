# Skill /commit-distill - Self-Evolution
- **Template mismatch**: None. The design-doc template accommodated all artifact types in this batch (env API overhaul, new dispatch subsystem, macro renames) without gaps.
- **Upstream skill gap**: Several commits (db987299 renaming `TVMFFIEnvSetStream` → `TVMFFIEnvSetCurrentStream`, then f81ab9c reverting and adding `TVMFFIEnvGetStream`) had oscillating names. Ledger entries recorded each commit's individual change without flagging the net-zero effect on `TVMFFIEnvSetStream`; the distill step had to manually compute the final settled name. Ledgers for rename-then-revert clusters should flag a `name_oscillation` warning in frontmatter.
- **Quality bar friction**: The "≥1 usage example" bar for 0001-c-abi was met only awkwardly — the C ABI record is not API-user-facing so cross-layer examples feel forced. A carve-out for "wire-level ABI records" (where examples are codegen patterns, not user call-sites) would be cleaner.
- **Procedure friction**: Step 1.5 triage criteria reference `commit_shape: trivial` but some ledgers in this batch used `commit_shape: chore` for trivially small commits with real design impact (bytearray helper, __name__ bugfix). The trivial/chore classification guidance needs a tie-break rule: if `has_design_updates: true`, always promote to active pool regardless of shape.
- **Suggested skill change**: Add a `name_oscillation` detection pass to Step 1: scan all ledger subjects for commit pairs where SHA A renames X→Y and SHA B renames Y→X or Y→Z. Flag these as "settled name" clusters so Step 2 plans artifacts based on the final state rather than requiring manual resolution.
