# Skill /commit-distill - Self-Evolution
- **Template mismatch**: The design doc template has no dedicated section for "Evolution Timeline" — the skill instructions mention including one when ≥3 evolution commits exist, but the template doesn't scaffold it. The 0006-reflection.md overhaul needed a detailed evolution table; had to invent the format inline.
- **Upstream skill gap**: Several ledgers in the reflection cluster listed "Design Elements this commit produces" pointing to the same design record without specifying which section to update. The planner had to cross-reference 6+ ledgers to reconstruct the net state of ObjectDef. A ledger field summarizing "net public API delta" per design record would reduce planner work significantly.
- **Quality bar friction**: The "≥2 genuinely distinct alternatives" requirement for Decision Records felt forced for the TypeAttrColumn design — one alternative was already rejected by the commit history with a clear rationale. Still satisfied the bar but the second alternative was thin.
- **Procedure friction**: No guidance on how to handle a context window interruption mid-Step-4. The summary mechanism worked but made it harder to verify that all planned changes were applied; a checklist per design record in the planner output would help resume verification.
- **Suggested skill change**: Step 2 (Planner) should produce an explicit per-design-record checklist of planned changes (e.g., "0001-c-abi.md: update TVMFFIFieldInfo layout, add TVMFFITypeAttrColumn, rename 3 functions") so Step 4 can tick off items as it applies them and verify completeness at the end.
