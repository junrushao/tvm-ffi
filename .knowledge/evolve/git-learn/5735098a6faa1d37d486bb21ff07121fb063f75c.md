# Skill /git-learn - Self-Evolution
- **Grouping parameters**: MAX_COMMITS_PER_GROUP=100 and MAX_LOC_PER_GROUP=7500 produced 24 groups from 486 commits. Group 11 (59 commits) was the largest; the LOC cap was the binding constraint for most groups. Parameters were appropriate for this range — no group mixed unrelated work.
- **Pipeline bottleneck**: The commit-ledger fan-out phase was the weakest link. Orchestrator agents (spawned to manage parallel subagents) unreliably completed — typically processing only 1 of N commits before returning. Direct parallel agent launches (20 at a time) were far more reliable. The orchestrator pattern should be abandoned in favor of direct launches.
- **Cross-skill patterns**: (1) Worktree checkout failures due to sandbox index.lock restrictions were universal — every subagent hit this on first attempt. The `git show` fallback worked well but wastes time on the retry. (2) The CWD corruption from nested worktrees (worktree-of-worktree) is a systemic issue — `/git-learn` should verify its own CWD is not already a worktree before starting. (3) Background agents (in_progress tasks) that stall without completing consume quota without producing output.
- **Distillation coverage**: All 486/486 commits distilled across all 24 groups after the resume session completed the 34 missing ledgers. The group-then-distill structure worked well. 31 design records created/maintained.
- **Suggested skill changes**: (1) `/git-learn` SKILL.md should mandate direct parallel agent launches (not nested orchestrators) for `run-ledger`. (2) Add a "skip already-completed ledgers" check at launch time to enable efficient retries. (3) Add a post-batch verification step that counts files before proceeding to distill, with automatic re-launch of missing commits. (4) Document the sandbox index.lock workaround as a known issue.
