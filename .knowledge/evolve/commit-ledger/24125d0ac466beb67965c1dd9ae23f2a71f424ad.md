# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: The `multi-concern` shape table lists steps to apply per-concern but doesn't clarify whether the Key Exports section should list all concerns combined or split by concern heading. Mixed doc+ABI commits benefit from a concern-labeled subsection in Key Exports.
- **Template gap**: No section for "docs infrastructure" artifacts (Sphinx extensions, build flags, directory layout conventions). The Key Exports pseudocode format works but feels awkward for pure configuration dicts.
- **Wasted effort**: Step 3.6 Usage Examples produced minimal value here — the only useful examples were a shell command and a before/after deleter pattern. For `chore`+`bugfix` hybrid commits the examples section is nearly vacuous.
- **Suggested skill change**: None — these are minor awkwardnesses, not recurring friction warranting a procedure change.
