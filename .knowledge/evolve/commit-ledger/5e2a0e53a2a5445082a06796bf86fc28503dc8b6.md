# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: None. The steps fit well for a build/compat commit.
- **Template gap**: The template's "Key Exports" section asks for pseudocode, but for pure-config/build commits there's nothing to show. A "Configuration Changes" section (key-value before/after table) would better capture `pyproject.toml` and version-guard changes. As-is, "None" works but doesn't convey the important config deltas.
- **Wasted effort**: Step 3 cross-layer consistency check was minimal for a single-layer Python-only commit with no C++ changes, though the torch JIT C code guard was worth noting.
- **Suggested skill change**: Add an optional "Configuration Delta" subsection under Key Exports (or as a peer section) for commits whose primary content is config/build changes. Format: `key: old_value -> new_value` table. This would cleanly capture `requires-python`, `target-version`, `build`, `test-skip` changes without forcing them into pseudocode or free-text bullets.
