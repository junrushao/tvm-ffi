# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: Step 3.5 cap of ~15 Key Exports for `large-bringup` felt slightly low for a commit that establishes an entire new language binding layer; needed ~20 symbols to fully represent the public API surface. The "15 most architecturally significant" guideline required aggressive trimming that risks losing the `_init_api` and `tvm-ffi-config` conventions which are load-bearing for downstream consumers.
- **Template gap**: No section for "deployment / packaging model" — for bringup commits that introduce a new pip package or build system integration, there is no natural home in the template other than Key Exports. A brief "Packaging / Build Integration" sub-section under Impact would reduce overloading of Key Exports.
- **Wasted effort**: None — all steps were relevant.
- **Suggested skill change**: Add an optional "Packaging" sub-bullet under Impact for commits that introduce or change build-system packaging (pyproject.toml, scikit-build, CMake install rules). Keep it to 2-3 lines: package name, install command, and any breaking change to how downstream projects link.
