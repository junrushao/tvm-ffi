# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: Step 0.3 checkout via `cd "$REPO_WORKTREE" && git checkout "$COMMIT"` fails in sandbox environments where `.git/worktrees/*/index.lock` cannot be created. The procedure should note that `git show $COMMIT:path` and `git show --format="" $COMMIT` are sufficient for analysis and can substitute when checkout is blocked.
- **Template gap**: None — the standard template sections covered this commit's mix of example scaffolding + bugfix + cmake nits cleanly.
- **Wasted effort**: Step 3.3 (breaking changes) required checking for public API breaks; the cmake install path change (`lib/cmake/tvm_ffi/` → `cmake/`) is technically a breaking change for downstream cmake consumers who had hardcoded the old path, but it's hard to classify vs. "additive-only". The procedure's fast-skip criterion ("zero deletions, no modified existing signatures") doesn't map cleanly to cmake path changes.
- **Suggested skill change**: Add a note to Step 0.3 that if `git checkout` fails due to sandbox/lock restrictions, fall back to `git show $COMMIT:path` for all file reads — this is sufficient for all analysis steps and avoids a hard abort on sandbox-locked environments.
