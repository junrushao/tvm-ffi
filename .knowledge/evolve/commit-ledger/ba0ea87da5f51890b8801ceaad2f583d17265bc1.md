# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: Step 0.3 assumes the provided GITSHA is valid and locally present, but the SHA in this run was both incorrect (different full SHA at the prefix) and not locally fetched. The procedure has no explicit step for SHA resolution or `git fetch` fallback before the checkout.
- **Template gap**: None. The performance+bugfix hybrid fit cleanly into the existing secondary_commit_type field.
- **Wasted effort**: None significant for this shape.
- **Suggested skill change**: Add a sub-step in Step 0.3: if `git cat-file -t $COMMIT` fails, run `git fetch origin` and retry. Also recommend prefix-disambiguation (`git rev-parse --verify $GITSHA`) as a standard validation before checkout, to catch the case where a provided SHA prefix resolves to a different full SHA than intended.
