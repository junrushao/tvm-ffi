# Skill /commit-ledger - Self-Evolution
- **Procedure friction**: Step 3.5 "cap Key Exports to ~15 most architecturally significant symbols" conflicts with large-bringup commits that define 8+ orthogonal subsystems (Any, Object, Function, Error, C ABI, TypeTraits, containers, reflection). The cap forces omission of entire design elements rather than trimming within each. A per-subsystem cap (e.g., 3–5 symbols per subsystem group) would be more actionable.
- **Template gap**: None — the template accommodated the large-bringup shape well with the structured (consumed/produced) approach.
- **Wasted effort**: Step 3.3 breaking-change analysis was trivially "None — additive only" for a pure bringup; the additive-only fast-skip worked correctly.
- **Suggested skill change**: For `large-bringup` shape, change the Key Exports cap from "~15 total" to "3–5 per subsystem group identified in Step 1.1 numstat grouping" to avoid artificially truncating multi-subsystem commits.
