# Add Windows CI workflow and build script for torch-c-dlpack-ext wheels
## TL;DR
- Adds a new GitHub Actions workflow (`torch_c_dlpack_windows.yml`) for building `torch-c-dlpack-ext` Windows wheels across Python 3.9--3.14 and torch 2.4--2.9.
- Adds `build_aot_wheels.bat` -- a Windows batch script that iterates over torch versions, creates per-version venvs, AOT-compiles the C DLPack extension DLL (with and without CUDA), and packages platform-tagged wheels.
- Fixes two bugs in `_build_optional_torch_c_dlpack.py`: (a) paths with spaces are now quoted in ninja include flags, and (b) the colon-escaping for ninja is now Windows-only (was previously applied unconditionally). Also adds CUDA link libraries (`torch_cuda`, `c10_cuda`) on both Windows and Unix when `--build-with-cuda` is passed.
- Renames the existing Linux workflow job from `build_wheels` to `build_wheels_linux` and disambiguates artifact names with a `linux-` prefix.

## Design Elements
Design elements this commit consumes:
- **Torch C DLPack AOT build pipeline** (`python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`): The `_generate_ninja_build()` function and `main()` entry point that compile the DLPack C extension ahead-of-time. The new `.bat` script invokes `python -m tvm_ffi.utils._build_optional_torch_c_dlpack` with `--output-dir` and `--build-with-cuda` flags.
- **Addon packaging pattern** (`.knowledge/designs/0013-packaging.md`): The `torch-c-dlpack-ext` wheel follows the extension packaging pattern -- companion wheel with AOT-compiled native code that replaces JIT compilation at import time.

Design elements this commit produces:
- **Windows wheel build script** (`addons/torch_c_dlpack_ext/build_aot_wheels.bat`): Batch script that orchestrates per-torch-version venv creation, CUDA toolkit setup, AOT compilation (CPU + CUDA variants), and wheel packaging with platform tags. Parallel to the existing Linux `build_aot_wheels.sh`.
- **Windows CI workflow** (`.github/workflows/torch_c_dlpack_windows.yml`): Separate workflow for Windows wheel builds, using `windows-latest` runners with CUDA toolkit action.
