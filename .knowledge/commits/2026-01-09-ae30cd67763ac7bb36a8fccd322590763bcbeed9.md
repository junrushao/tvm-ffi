# Fix out-of-bounds read in dtype string parser for non-null-terminated string_view
## TL;DR
- Replaces `strtoul()` calls in `StringViewToDLDataType_` with bounds-checked manual digit parsing (`parse_digits`/`parse_lanes` lambdas) to eliminate undefined behavior when parsing non-null-terminated `std::string_view` inputs.
- Adds overflow validation for bits (uint8), lanes (uint16), and digit values (uint32).
- Adds 10-case test (`TEST(DType, NonNullTerminatedStringView)`) exercising garbage-after-boundary, scalable vectors, and truly non-null-terminated buffers via `TVMFFIDataTypeFromString`.

## Key Exports

## Impact
- API: None -- public API unchanged.
- Behavioral: `StringViewToDLDataType_` no longer reads past `string_view` bounds. Inputs that previously triggered UB (non-null-terminated buffers with trailing digit garbage) now parse correctly. New overflow checks throw `ValueError` for out-of-range bits/lanes values.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

Before/after pattern showing the bug and fix:

```cpp
// BEFORE (buggy): strtoul reads past string_view bounds
// TVMFFIByteArray byte_array{"float16999888777", 7};  // intent: "float16"
// TVMFFIDataTypeFromString(&byte_array, &dtype);
// dtype.bits == 16999888777  <-- UB, strtoul kept reading past position 7

// AFTER (fixed): manual parsing respects string_view boundary
TVMFFIByteArray byte_array{"float16999888777", 7};  // intent: "float16"
TVMFFIDataTypeFromString(&byte_array, &dtype);
// dtype.bits == 16  <-- correct, parse_digits stops at str.data() + str.length()
// dtype.lanes == 1  <-- correct, no 'x' within bounds
```
