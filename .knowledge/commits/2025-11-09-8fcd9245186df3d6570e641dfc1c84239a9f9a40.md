# Add get_registered_type_keys() API for querying all registered type keys
## TL;DR
- Adds `TypeTable::GetRegisteredTypeKeys() -> Array<String>` in C++ that iterates the type table and returns all non-null type keys.
- Registers it as global function `ffi.GetRegisteredTypeKeys` via `GlobalDef`.
- Exposes it as `tvm_ffi.registry.get_registered_type_keys() -> Sequence[str]` in Python.
- Also fixes `get_global_func_metadata` to return `{}` instead of crashing when metadata is empty.

## Key Exports
**C++ method** (on `TypeTable`):
- `Array<String> GetRegisteredTypeKeys() const` -- returns all registered type keys

**Global FFI function**:
- `ffi.GetRegisteredTypeKeys() -> Array[String]` -- no arguments, returns all registered type keys

**Python function** (public API in `tvm_ffi.registry`):
- `get_registered_type_keys() -> Sequence[str]` -- returns list of all registered type keys

**Python stub** (in `_ffi_api.py`):
- `GetRegisteredTypeKeys() -> Sequence[str]`

## Impact
- API: new public function `tvm_ffi.registry.get_registered_type_keys()`
- Behavioral: none (additive)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeTable` singleton and type registration system per `.knowledge/designs/0003-object-system.md`
- `GlobalDef` / `reflection` registration pattern per `.knowledge/ADRs/0008-globaldef-over-register-global.md`
- `Array<String>` container per `.knowledge/designs/0008-containers.md`

Design elements this commit produces:
- Type key enumeration API -- enables tools like stubgen to discover all C++-registered types without parsing C++ source

## Usage Examples
```python
import tvm_ffi

keys = tvm_ffi.registry.get_registered_type_keys()
assert "ffi.Object" in keys
assert "ffi.String" in keys
# All dynamic types have keys like "ffi.*" or "testing.*"
```
