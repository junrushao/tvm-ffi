# Add reflection-based structural equality and hash with AccessPath diagnostics
## TL;DR
- Introduces `StructuralEqual` and `StructuralHash` classes (`include/tvm/ffi/reflection/structural_equal.h`, `structural_hash.h`) that perform deep comparison and hashing of `Any` values by walking the reflection field metadata registered via `ObjectDef<T>`.
- Adds `TVMFFISEqHashKind` enum to the C ABI (`c_api.h`) with five comparison modes (Unsupported, TreeNode, FreeVar, DAGNode, ConstTreeNode, UniqueInstance) and two new field flag bits (`kTVMFFIFieldFlagBitMaskSEqHashIgnore`, `kTVMFFIFieldFlagBitMaskSEqHashDef`), allowing per-type and per-field control over structural comparison semantics.
- Introduces `AccessPath` / `AccessStep` types for first-mismatch diagnostics: `StructuralEqual::GetFirstMismatch` returns the precise path (object fields, array indices, map keys) to the first divergence point.

## Impact
- API: **New public C++ API** -- `StructuralEqual::Equal`, `StructuralEqual::GetFirstMismatch`, `StructuralHash::Hash` (marked `TVM_FFI_EXTRA_CXX_API`). New global FFI functions `ffi.reflection.GetFirstStructuralMismatch` and `ffi.reflection.StructuralHash`. New `TVM_FFI_EXTRA_CXX_API` macro for non-core C++ APIs defined in `.cc` files.
- ABI: **Breaking change to `TVMFFITypeExtraInfo`** -- `total_size` narrowed from `int64_t` to `int32_t` and a new `TVMFFISEqHashKind structural_eq_hash_kind` field is appended. All code reading `TVMFFITypeExtraInfo` must be recompiled.
- ABI: **New C enum `TVMFFISEqHashKind`** and two new `TVMFFIFieldFlagBitMask` constants (bits 3-4).
- Object protocol: **New static constexpr `_type_s_eq_hash_kind`** on `Object` (defaults to `kTVMFFISEqHashKindUnsupported`). Types wanting structural comparison must override this (e.g., `kTVMFFISEqHashKindTreeNode`, `kTVMFFISEqHashKindFreeVar`).
- Flags/config: None.
- Data formats/schemas: None.
- Minor: `Bytes::memncmp` moved from `private` to `public` for reuse in structural equal. `FieldSetter` gains an `Any`-specialization path to avoid double-cast. File `container.cc` comment fixed. Test file renamed from `test_reflection.cc` to `test_reflection_accessor.cc`.

## Design Elements

Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/0006-reflection.md`) -- `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`, `FieldGetter`, `ObjectDef<T>`, `GlobalDef`, `FieldInfoTrait` base class, and `TVMFFIFieldInfo::flags` bitmask are all used as the foundation for field-by-field traversal and per-field flag annotation.
- **C ABI layer** (`.knowledge/designs/0001-c-abi.md`) -- `TVMFFITypeExtraInfo`, `TVMFFIFieldFlagBitMask`, `TVMFFITypeInfo` structs are extended. `TVMFFIAny` type index partitioning is used for POD vs. object dispatch in `CompareAny` / `HashAny`.
- **Object system** (`.knowledge/designs/0003-object-system.md`) -- `Object` base class extended with `_type_s_eq_hash_kind`. `ObjectRef::same_as` used for pointer equality fast paths. `TypeTable` looked up via `TVMFFIGetTypeInfo`. The pre-existing reserved flags `_type_has_method_sequal_reduce` / `_type_has_method_shash_reduce` foreshadowed this feature.
- **Container system** (`.knowledge/designs/0005-containers.md`) -- `Array`, `Map`, `Shape`, `NDArray`, `String`/`Bytes`, `Tuple` are all handled as special cases in the structural comparison/hash dispatch switches.
- **Any system** (`.knowledge/designs/0002-any-system.md`) -- `AnyUnsafe::TVMFFIAnyPtrFromAny`, `MoveFromAnyAfterCheck`, `CopyFromAnyViewAfterCheck` used extensively for zero-copy type dispatch.

Design elements this commit produces:
- **TVMFFISEqHashKind enum** (`c_api.h`) -- New C-level enum with 6 values controlling how objects participate in structural equality: `Unsupported` (pointer-only), `TreeNode` (recursive field comparison), `FreeVar` (alpha-equivalence), `DAGNode` (graph-aware with memoization), `ConstTreeNode` (tree + pointer-equality fast path), `UniqueInstance` (singleton pointer equality). This is a core design element that all user-defined object types will reference.
- **_type_s_eq_hash_kind protocol** (`object.h`) -- Static constexpr field on `Object` that types override to opt into structural comparison. Mirrors the existing `_type_mutable`, `_type_final` pattern. Consumed by `ObjectDef<T>::RegisterExtraInfo` which populates `TVMFFITypeExtraInfo::structural_eq_hash_kind`.
- **SEqHash field flags** (`c_api.h`, `registry.h`) -- `kTVMFFIFieldFlagBitMaskSEqHashIgnore` (bit 3) and `kTVMFFIFieldFlagBitMaskSEqHashDef` (bit 4), applied via the new `AttachFieldFlag` trait class. These enable per-field annotation for ignoring fields during comparison (e.g., comments, span info) and marking variable-definition regions for alpha-equivalence.
- **AttachFieldFlag trait** (`registry.h`) -- New `FieldInfoTrait` subclass for attaching arbitrary flag bits to fields. Factory methods `SEqHashDef()` and `SEqHashIgnore()` provide named constructors for the two structural eq/hash flags.
- **AccessPath / AccessStep** (`access_path.h`, `access_path.cc`) -- New object types `AccessStepObj` / `AccessStep` (type key `tvm.ffi.reflection.AccessStep`) and type aliases `AccessPath = Array<AccessStep>`, `AccessPathPair = Tuple<AccessPath, AccessPath>`. These represent the path from root to the first mismatch point during structural comparison, supporting field, array-index, and map-key access patterns.
- **StructuralEqual / StructuralHash** (`structural_equal.h/cc`, `structural_hash.h/cc`) -- The implementation classes with type-dispatched comparison/hashing over POD, String/Bytes, Array, Map, Shape, NDArray, and generic reflected objects. Key algorithms: DAG/FreeVar memoization via bidirectional `equal_map_lhs_`/`equal_map_rhs_`, order-independent map hashing with tie detection, reverse-path construction for mismatch diagnostics.
- **TVM_FFI_EXTRA_CXX_API macro** (`c_api.h`) -- New visibility macro for "extra" C++ APIs implemented in `.cc` files that are not core to the C ABI but provide convenience C++ entry points. Distinct from `TVM_FFI_DLL` in intent: these are explicitly non-core and may have cross-ABI limitations on MSVC/Itanium boundaries.

## Reflection

### Design docs to write

- **`.knowledge/designs/0009-structural-equal-hash.md`**
  - Should cover: the `TVMFFISEqHashKind` taxonomy (tree vs. DAG vs. free-var semantics with examples), the field flag annotations (`SEqHashIgnore`, `SEqHashDef`), the memoization strategy for DAG/FreeVar nodes, the AccessPath diagnostic model, and the dispatch order in `CompareAny`/`HashAny`.
  - Why: Future commits adding new container types, new object kinds, or Python-side structural comparison will reference these semantics. This is the primary extension point for compiler IR equality.

### ADRs to write

- **`.knowledge/ADRs/0011-total-size-narrowing-in-extra-info.md`**
  - Context: `TVMFFITypeExtraInfo::total_size` was narrowed from `int64_t` to `int32_t` to make room for `structural_eq_hash_kind` without growing the struct. Decision: 4 GB is sufficient for any single object size. Alternatives: grow the struct by 4 bytes, or use a separate registration call. Trade-off: ABI-breaking change but the struct is not yet widely consumed externally.

- **`.knowledge/ADRs/0012-extra-cxx-api-macro.md`**
  - Context: `TVM_FFI_EXTRA_CXX_API` is introduced to mark C++ APIs that are non-core convenience features. Decision: keep them DLL-exported but document they are not ABI-stable across MSVC/Itanium. Alternatives: only expose via C function registry (more portable but less ergonomic), or make them header-only (would increase compile time). Trade-off: convenience for single-ABI consumers at cost of cross-ABI portability.

### Design diagrams to draw

- **Mermaid: SEqHash dispatch flowchart** -- Should depict the decision tree in `StructEqualHandler::CompareAny`: type_index check -> POD path vs. switch on container type vs. generic object path -> SEqHashKind dispatch (Unsupported/UniqueInstance -> pointer, ConstTreeNode -> pointer fast-path then content, TreeNode -> content, DAGNode/FreeVar -> memoization). This clarifies the priority order and when pointer equality is sufficient.

- **Mermaid: AccessPath construction** -- Show how the reverse-path vector is built during recursive comparison and then reversed into a root-to-leaf `AccessPath` in `GetFirstMismatch`. Include field, array-index, and map-key step types.

### Skill evolution (`/commit-ledger`)

- The `TVM_FFI_EXTRA_CXX_API` macro introduces a new category of API surface (non-core C++ APIs) that doesn't fit cleanly into the existing C ABI vs. C++ header taxonomy. Step 3 should be updated to explicitly check for new visibility/linkage macros as a design signal that a new API tier is being introduced.
- This commit changes `TVMFFITypeExtraInfo` in a way that is ABI-breaking (field type change + new field). The skill procedure does not have an explicit step for detecting ABI-breaking changes to C structs. Consider adding a sub-step in Step 4 that flags any modification to structs in `c_api.h` as a potential ABI break and checks whether the change is additive (appending fields) vs. modifying existing fields.
- The test file rename (`test_reflection.cc` -> `test_reflection_accessor.cc`) is a refactoring detail that was interleaved with the feature commit. The skill could note when test restructuring is bundled with feature work, as it complicates diff analysis.

## Self-Evolution of Skill /commit-ledger

- **ABI break detection**: Add an explicit check in Step 4 (Mining Key Implementations) for diffs to `c_api.h` struct definitions. When a struct field changes type or new fields are inserted (not just appended), flag this as a potential ABI break and note it prominently in the Impact section.
- **New macro categorization**: When a new `#define` macro is introduced in `c_api.h` (like `TVM_FFI_EXTRA_CXX_API`), Step 3 should classify it as a potential new "API tier" design element, since macros in the C ABI header tend to establish conventions followed by many subsequent commits.
- **Test restructuring noise**: When a commit renames test files alongside feature additions, consider noting the rename separately from the feature analysis to keep the design element mining focused on behavioral changes.
