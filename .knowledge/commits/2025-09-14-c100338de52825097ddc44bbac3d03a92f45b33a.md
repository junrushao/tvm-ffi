# Add minimal C example for low-level C ABI / compiler codegen integration
## TL;DR
- Adds a pure C example (`add_one_c.c`) demonstrating how to write a TVM FFI compatible function using only the C ABI (`TVMFFISafeCallType`, `TVMFFIAny`, `TVMFFIErrorSetRaisedFromCStr`, `TVMFFIEnvGetStream`), with matching CMake, Python runner, and docs.
- Fixes `c_api.h`: moves `DLPackTensorAllocator` typedef inside `extern "C"` block (was C++ only), removes unused `v_char32` union member from `TVMFFIAny`, adds forward declaration for `DLManagedTensorVersioned`.
- Adds `--cflags` flag to `tvm-ffi-config` CLI (C-only include flags without `-std=c++17`).
- Fixes a bug in `compiler_integration.md`: `ReadDLTensorPtr` was returning `DLTensor*` by value instead of by out-pointer, and had inverted error-condition logic (`== kTVMFFITensor` should have been `!= kTVMFFITensor`).

## Key Exports

**Functions (CLI)**:
- `tvm-ffi-config --cflags` -- prints `-I<include_dir> -I<dlpack_include_dir>` without `-std=c++17` (unlike `--cxxflags`). Defined in `python/tvm_ffi/config.py`.

**ABI changes in `include/tvm/ffi/c_api.h`**:
- `DLPackTensorAllocator` typedef moved inside `extern "C" {}` block, making it usable from C (previously only visible in C++ due to placement before `extern "C"`).
- `DLManagedTensorVersioned` forward-declared as `typedef struct DLManagedTensorVersioned DLManagedTensorVersioned;` inside `extern "C"` (with TODO to remove once dlpack.h is updated).
- `v_char32` (`char32_t[2]`) removed from the `TVMFFIAny` union. This is an ABI-breaking change for any code that accessed this field.

## Impact
- API: `tvm-ffi-config --cflags` added. No existing API changed.
- ABI: `TVMFFIAny` union loses the `v_char32` field (breaking for code using it, though no in-tree consumer existed). `DLPackTensorAllocator` is now C-linkage (was C++ linkage).
- Behavioral: `ReadDLTensorPtr` helper in docs was buggy (returned by value, inverted condition); corrected in both `quick_start.md` and `compiler_integration.md`.
- Flags/config: `--cflags` added to `tvm-ffi-config` for C compilation.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C ABI / `TVMFFISafeCallType`** (`.knowledge/designs/c-abi.md`) -- the new `add_one_c.c` example is an end-to-end consumer of the packed calling convention, demonstrating argument extraction from `TVMFFIAny`, error propagation via `TVMFFIErrorSetRaisedFromCStr`, and stream retrieval via `TVMFFIEnvGetStream`.
- **Module system / `__tvm_ffi_` symbol prefix** (`.knowledge/designs/0013-module-system.md`, `.knowledge/ADRs/016-ffi-symbol-prefix.md`) -- the example function is named `__tvm_ffi_add_one_c`, following the symbol prefix convention for auto-discovery by `LibraryModuleObj::GetFunction`.
- **Type index constants** (`kTVMFFIDLTensorPtr`, `kTVMFFITensor`) -- used by the `ReadDLTensorPtr` helper to discriminate tensor argument types.
- **Python packaging / `tvm-ffi-config`** (`.knowledge/designs/0015-python-packaging.md`) -- extended with `--cflags` for C compilation workflows.

Design elements this commit produces:
- **C-only FFI example pattern** -- a reference implementation showing how a compiler codegen can target the TVM FFI C ABI without any C++ dependencies. This is the first in-tree pure C example and serves as a codegen template.
- **`tvm-ffi-config --cflags`** -- new CLI flag for C (non-C++) compilation.

## Usage Examples

### Writing a C-only FFI function (the primary contribution of this commit)
```c
#include <tvm/ffi/c_api.h>
#include <tvm/ffi/extra/c_env_api.h>

// Function follows __tvm_ffi_<name> naming convention
int __tvm_ffi_add_one_c(
  void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result
) {
  DLTensor *x, *y;
  if (ReadDLTensorPtr(&args[0], &x) == -1) return -1;
  if (ReadDLTensorPtr(&args[1], &y) == -1) return -1;
  for (int i = 0; i < x->shape[0]; ++i) {
    ((float*)(y->data))[i] = ((float*)(x->data))[i] + 1;
  }
  return 0;
}
```

### Compiling with tvm-ffi-config --cflags
```bash
gcc -shared -fPIC `tvm-ffi-config --cflags` \
    src/add_one_c.c -o build/add_one_c.so \
    `tvm-ffi-config --ldflags` `tvm-ffi-config --libs`
```

### Loading and calling from Python
```python
import tvm_ffi
mod = tvm_ffi.load_module("build/add_one_c.so")
mod.add_one_c(x, y)  # logical name "add_one_c" -> symbol "__tvm_ffi_add_one_c"
```
