# Add C example for compiler codegen, fix c_api.h for C compilation, add --cflags support
## TL;DR
- Adds `examples/quick_start/src/add_one_c.c`, a minimal pure-C example demonstrating the raw FFI ABI convention (`__tvm_ffi_add_one_c` symbol) for compiler codegen targeting, including `ReadDLTensorPtr` helper and `TVMFFIErrorSetRaisedFromCStr` error propagation.
- Fixes `c_api.h` for C compilation: moves `DLPackTensorAllocator` typedef inside `extern "C"` block, adds forward declaration for `DLManagedTensorVersioned`, and removes `char32_t v_char32[2]` from `TVMFFIAny` union (not valid in C).
- Adds `--cflags` option to `python/tvm_ffi/config.py` (C flags without `-std=c++17`) and bumps version to `0.1.0b2`.

## Impact
- API: **Breaking ABI change** -- `TVMFFIAny` union loses `v_char32` field (2 chars / 8 bytes). This field was overlapping with `v_bytes[8]` so no data layout change, but code referencing `v_char32` directly would break.
- Flags/config: `python -m tvm_ffi.config --cflags` now available for C (non-C++) compilation.
- Data formats/schemas: none

## Design Elements
Design elements this commit **consumes**:
- **C ABI** (`.knowledge/designs/0001-c-abi.md`): The C example directly implements the FFI ABI calling convention (`void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result`) and demonstrates `TVMFFITypeIndex` checks (`kTVMFFIDLTensorPtr`, `kTVMFFITensor`), `TVMFFIObject` header offset calculation for Tensor data access, and error propagation via `TVMFFIErrorSetRaisedFromCStr`.
- **Module export system** (`.knowledge/designs/0008-module-export-system.md`): Uses the `__tvm_ffi_` symbol prefix convention.

Design elements this commit **produces**:
- **C-language ABI compatibility**: By moving `DLPackTensorAllocator` inside `extern "C"`, adding the `DLManagedTensorVersioned` forward declaration, and removing `char32_t` (C++-only type), `c_api.h` becomes compilable from pure C. This is a prerequisite for C-based compiler backends.
