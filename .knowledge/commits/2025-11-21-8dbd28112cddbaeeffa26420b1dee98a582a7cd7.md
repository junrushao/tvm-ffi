# Fix version guard for f8e8m0 dtype support in torch C DLPack extension
## TL;DR
- Fixes preprocessor version guards in `_build_optional_torch_c_dlpack.py` so that `Float8_e8m0fnu` dtype support compiles on torch >= 2.7 (was incorrectly gated at >= 2.8).
- Corrects the version comparison pattern from `MAJOR >= 2 && MINOR >= N` (broken for major version bumps) to `(MAJOR > 2) || (MAJOR == 2 && MINOR >= N)`.
- Bumps `TVM_FFI_VERSION_PATCH` from 3 to 4.

## Key Exports
None -- no new APIs. Fixes existing preprocessor guards only.

## Impact
- API: None
- Behavioral: `Float8_e8m0fnu` DLPack dtype round-trip now works on torch 2.7.x (previously required torch 2.8+). The incorrect `MAJOR >= 2 && MINOR >= 8` guard would also fail for any future torch 3.x with MINOR < 7, now fixed.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Torch version-guarded dtype dispatch** in `_build_optional_torch_c_dlpack.py` -- the `#if TORCH_VERSION_MAJOR/MINOR` preprocessor pattern for conditional dtype case compilation (see `0012-ffi-python-package` design record, torch DLPack addon section).
- **`TVM_FFI_VERSION_PATCH`** in `c_api.h` -- the patch version constant in the C ABI header (see `0001-ffi-c-abi` design record).

Design elements this commit produces: None -- restores correct behavior of existing guards.

## Usage Examples
Before (broken guard, torch 2.7):
```cpp
// Guard: TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8
// On torch 2.7: 2 >= 2 is true, but 7 >= 8 is false -> Float8_e8m0fnu case excluded
// On torch 3.0: 3 >= 2 is true, but 0 >= 8 is false -> also excluded (wrong!)
```

After (correct guard, torch 2.7):
```cpp
// Guard: (TORCH_VERSION_MAJOR > 2) || (TORCH_VERSION_MAJOR == 2 && TORCH_VERSION_MINOR >= 7)
// On torch 2.7: (2 > 2) is false, (2 == 2 && 7 >= 7) is true -> Float8_e8m0fnu included
// On torch 3.0: (3 > 2) is true -> included
// Float4_e2m1fn_x2 remains gated at >= 2.8 with same corrected pattern
```
