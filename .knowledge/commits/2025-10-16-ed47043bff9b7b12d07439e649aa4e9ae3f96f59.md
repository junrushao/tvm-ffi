# Add CMake endian detection and musl libc support in endian.h
## TL;DR
- Adds CMake-level endian detection using `CMAKE_CXX_BYTE_ORDER`, setting `TVM_FFI_CMAKE_LITTLE_ENDIAN=0|1` as a compile definition on `tvm_ffi_header` interface target.
- Extends `endian.h` preprocessor detection to recognize `__MUSL__` (musl libc), which was previously unsupported and would fall through to the error/unknown case.

## Key Exports

**Macros**:
- `TVM_FFI_CMAKE_LITTLE_ENDIAN` — CMake compile definition set to `1` (little-endian) or `0` (big-endian) when `CMAKE_CXX_BYTE_ORDER` is known. Not set if endianness cannot be determined. This supplements the existing header-level `TVM_FFI_LITTLE_ENDIAN` macro in `endian.h`.

## Impact
- API: none
- Behavioral: Builds on musl-based systems (e.g., Alpine Linux) now correctly detect endianness via `endian.h` instead of falling through to the unknown case.
- Flags/config: New CMake compile definition `TVM_FFI_CMAKE_LITTLE_ENDIAN`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`TVM_FFI_LITTLE_ENDIAN` macro** — the existing preprocessor-level endianness detection in `include/tvm/ffi/endian.h`. See [0001-c-abi-layer.md](../.knowledge/designs/0001-c-abi-layer.md).

Design elements this commit produces:
- **`TVM_FFI_CMAKE_LITTLE_ENDIAN` compile definition** — a CMake-level complement to the header-level detection. Not yet consumed by `endian.h` itself (the header still uses its own preprocessor chain), but available for future use.

## Usage Examples
None — the macro is consumed internally by the build system.
