# Add CMake-level endianness detection and extend endian.h for musl libc

## TL;DR
- `CMakeLists.txt` now uses `CMAKE_CXX_BYTE_ORDER` to set `TVM_FFI_CMAKE_LITTLE_ENDIAN=0/1` as a compile definition when endianness is determinable at configure time; silently skips if unknown.
- `include/tvm/ffi/endian.h` adds `__MUSL__` to the preprocessor chain that includes `<endian.h>` and derives `TVM_FFI_LITTLE_ENDIAN` from `__BYTE_ORDER`, enabling correct endian detection on musl-libc targets.

## Key Exports

```python
# CMake compile definition (pseudocode):
# if CMAKE_CXX_BYTE_ORDER == "LITTLE_ENDIAN":
#     target_compile_definitions(tvm_ffi_header, TVM_FFI_CMAKE_LITTLE_ENDIAN=1)
# elif CMAKE_CXX_BYTE_ORDER == "BIG_ENDIAN":
#     target_compile_definitions(tvm_ffi_header, TVM_FFI_CMAKE_LITTLE_ENDIAN=0)
# # else: not set, fallback to preprocessor chain in endian.h
# Interacts with: include/tvm/ffi/endian.h (TVM_FFI_LITTLE_ENDIAN macro)

# endian.h preprocessor chain (updated):
# #if defined(TVM_FFI_CMAKE_LITTLE_ENDIAN)
#   TVM_FFI_LITTLE_ENDIAN = TVM_FFI_CMAKE_LITTLE_ENDIAN
# elif __APPLE__ or _WIN32:
#   TVM_FFI_LITTLE_ENDIAN = 1
# elif __GLIBC__ or __ANDROID__ or __RISCV__ or __MUSL__:  # __MUSL__ added
#   #include <endian.h>
#   TVM_FFI_LITTLE_ENDIAN = (__BYTE_ORDER == __LITTLE_ENDIAN)
# elif __FreeBSD__ or __OpenBSD__:
#   ...
```

## Impact
- API: None — `TVM_FFI_LITTLE_ENDIAN` macro is internal to headers; no public API change.
- Behavioral: Endian detection now works correctly on musl-libc systems (Alpine Linux, static musl builds). `CMAKE_CXX_BYTE_ORDER` provides a configure-time alternative to preprocessor-only detection.
- Flags/config: New CMake compile definition `TVM_FFI_CMAKE_LITTLE_ENDIAN` may appear in build flags.
- Data formats/schemas: none

## Design Elements

Design elements this commit produces:
