# CMake endian detection and musl libc fallback for TVM_FFI_LITTLE_ENDIAN
## TL;DR
- Wires up CMake's `CMAKE_CXX_BYTE_ORDER` to define `TVM_FFI_CMAKE_LITTLE_ENDIAN` as a compile definition on the `tvm_ffi_header` INTERFACE target, enabling reliable endian detection at configure time.
- Adds `__MUSL__` to the preprocessor fallback chain in `endian.h` so musl-based Linux builds (e.g., Alpine) include `<endian.h>` for runtime detection.

## Key Exports
None — no new public API. The commit activates an existing preprocessor hook (`TVM_FFI_CMAKE_LITTLE_ENDIAN`) that `endian.h` already consumed but CMake never defined.

## Impact
- API: None
- Behavioral: None — endian detection result is the same on all supported platforms; this closes a gap where CMake builds silently fell through to the preprocessor chain without providing the configure-time value.
- Flags/config: New compile definition `TVM_FFI_CMAKE_LITTLE_ENDIAN=0|1` propagated via `tvm_ffi_header` INTERFACE target when `CMAKE_CXX_BYTE_ORDER` is available (CMake 3.20+). Gracefully skipped on older CMake.
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_LITTLE_ENDIAN` / `TVM_FFI_IO_NO_ENDIAN_SWAP` macro pair in `include/tvm/ffi/endian.h` — the endian detection cascade that governs byte-swap behavior in serialization and hashing (see also commit `ba0ea87` ledger for hashing usage).

Design elements this commit produces:
- None — purely activates an existing hook.
