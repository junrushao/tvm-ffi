# Add CMake-based endian detection and musl libc support for endian.h

## TL;DR
- CMakeLists.txt now uses `CMAKE_CXX_BYTE_ORDER` to define `TVM_FFI_CMAKE_LITTLE_ENDIAN` as a compile definition, providing a reliable CMake-level endian detection path.
- `endian.h` gains a `#ifdef TVM_FFI_CMAKE_LITTLE_ENDIAN` fast path that bypasses the platform-specific preprocessor heuristics when CMake detection succeeds.
- The preprocessor fallback in `endian.h` adds `__MUSL__` to the glibc/Android branch so musl-based Linux systems (e.g., Alpine) can use `<endian.h>`.

## Key Exports
N/A -- infrastructure. No new public API symbols introduced.

## Impact
- API: none
- Behavioral: none -- endian detection result is unchanged on all previously-supported platforms; only the detection mechanism is more robust.
- Flags/config: new compile definition `TVM_FFI_CMAKE_LITTLE_ENDIAN` (0 or 1) propagated via `tvm_ffi_header` INTERFACE target when CMake can determine endianness. When CMake cannot determine it, the definition is not set, and the existing preprocessor fallback chain in `endian.h` activates.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_LITTLE_ENDIAN` macro in `include/tvm/ffi/endian.h` -- the existing endian detection mechanism used by serialization/byte-swap code. This commit adds a new upstream source (`TVM_FFI_CMAKE_LITTLE_ENDIAN`) that feeds into it.
- `tvm_ffi_header` CMake INTERFACE target (`CMakeLists.txt`) -- the header-only target that propagates compile features and include paths. This commit adds a compile definition to it.

Design elements this commit produces: none -- no new design elements; only extends the detection mechanism for the existing `TVM_FFI_LITTLE_ENDIAN` macro.
