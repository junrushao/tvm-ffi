# Add CMake-based endianness detection via CMAKE_CXX_BYTE_ORDER
## TL;DR
- CMakeLists.txt now queries `CMAKE_CXX_BYTE_ORDER` and, when available, propagates `TVM_FFI_CMAKE_LITTLE_ENDIAN=0|1` as a compile definition on the `tvm_ffi_header` interface target.
- `endian.h` adds `__MUSL__` to the list of platforms that include `<endian.h>` for runtime detection, fixing builds under musl libc when CMake detection is unavailable.
- Together, these changes ensure that CMake-based builds get reliable endianness detection without relying solely on platform-specific preprocessor guards.

## Key Exports
**Macros**:
- `TVM_FFI_CMAKE_LITTLE_ENDIAN` -- compile definition set to `1` (little-endian) or `0` (big-endian) by CMake when `CMAKE_CXX_BYTE_ORDER` is available. When defined, `endian.h` uses this value directly for `TVM_FFI_LITTLE_ENDIAN`, bypassing all platform-specific `#if` chains.

## Impact
- API: none
- ABI: none -- `TVM_FFI_LITTLE_ENDIAN` resolves to the same value on all previously-supported platforms; this only changes _how_ the value is determined.
- Behavioral: On platforms where CMake can determine `CMAKE_CXX_BYTE_ORDER` (CMake 3.20+), endianness is now detected at configure time rather than relying on preprocessor platform sniffing. Musl-based builds that previously hit the `#error` in `endian.h` can now compile even without the CMake path.
- Flags/config: New implicit compile definition `TVM_FFI_CMAKE_LITTLE_ENDIAN` on `tvm_ffi_header` target (not a user-facing CMake option).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_LITTLE_ENDIAN` / `TVM_FFI_IO_NO_ENDIAN_SWAP` macro chain used by `StableHashBytes` and `StableHashSmallStrBytes` in `include/tvm/ffi/base_details.h` (see `.knowledge/designs/0011-small-string-optimization.md`)
- `ByteSwap` / `TVM_FFI_IO_NO_ENDIAN_SWAP` used by `BufferStream` read/write in `src/ffi/extra/buffer_stream.h`

Design elements this commit produces:
- CMake-level endianness detection pattern: query `CMAKE_CXX_BYTE_ORDER` and propagate via `target_compile_definitions` on the header-only interface target, with graceful fallback when the variable is empty (older CMake or cross-compilation without a test program).

## Usage Examples
None -- this is a build-system configuration change with no new user-facing API. The effect is automatic: when building with CMake 3.20+, `TVM_FFI_CMAKE_LITTLE_ENDIAN` is defined and `endian.h` uses it directly.
