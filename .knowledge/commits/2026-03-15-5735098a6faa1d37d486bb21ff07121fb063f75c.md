# Auto-register __ffi_* dunder methods in @py_class as TypeMethod

## TL;DR
- `@py_class` now detects and registers recognized FFI dunder methods (`__ffi_repr__`, `__ffi_eq__`, `__ffi_hash__`, `__ffi_compare__`, `__s_equal__`, `__s_hash__`, `__data_to_json__`, `__data_from_json__`) defined in Python class bodies, making them callable from C++.
- `_collect_py_methods()` scans class dict against `_FFI_RECOGNIZED_METHODS` allowlist; `TypeInfo._register_py_methods()` calls `TVMFFITypeRegisterMethod` + `TVMFFITypeRegisterAttr` from Cython.
- System methods (`__ffi_init__`, `__ffi_shallow_copy__`) always read back from C even when no Python methods exist.

## Impact
- API: Python-defined FFI dunders now automatically visible from C++.
- Behavioral: `@py_class` types with `__ffi_repr__` etc. work with `ReprPrint`, `RecursiveHash`, `RecursiveEq`, serialization.
- Flags/config: None.

## Usage Examples

```python
@py_class("my.Custom", structure="tree", eq=True, unsafe_hash=True)
class Custom(Object):
    key: int
    label: str

    def __ffi_hash__(self) -> int:
        return hash(self.key)  # Custom hash: only key

    def __ffi_eq__(self, other: Custom) -> bool:
        return self.key == other.key  # Custom eq: only key
```
