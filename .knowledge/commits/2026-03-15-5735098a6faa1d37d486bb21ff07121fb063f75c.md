# Auto-register __ffi_* dunder methods in @py_class as TypeMethod

## TL;DR
- New `_FFI_RECOGNIZED_METHODS` allowlist (frozenset of 8 names) in `py_class.py`; `_collect_py_methods()` scans class `__dict__` for matching callables.
- New `TypeInfo._register_py_methods(py_methods)` in `type_info.pxi`: registers each method via `TVMFFITypeRegisterMethod` + `TVMFFITypeRegisterAttr`, then always re-reads the full method table to pick up system-generated methods (`__ffi_init__`, `__ffi_shallow_copy__`).
- Recognized dunders: `__ffi_repr__`, `__ffi_hash__`, `__ffi_eq__`, `__ffi_compare__`, `__s_equal__`, `__s_hash__`, `__data_to_json__`, `__data_from_json__`.

## Impact
- API: `@py_class` now auto-registers recognized `__ffi_*`/`__s_*`/`__data_*` dunders. `TypeInfo._register_py_methods` added. `TypeInfo._read_back_methods` extracted as separate method.
- Behavioral: C++ recursive operations (`ReprPrint`, `RecursiveHash`, `RecursiveEq`, `StructuralEqual`, `StructuralHash`, `ToJSONGraph`) can now dispatch to Python-defined hooks on `@py_class` types.
- Flags/config: `_FFI_RECOGNIZED_METHODS` allowlist gates which methods are registered; not user-configurable.
- Data formats/schemas: none

- `TypeInfo._read_back_methods()`: extracted helper for reading C-registered methods back to Python

## Usage Examples

```python
from tvm_ffi.core import Object
from tvm_ffi.dataclasses import py_class, field

@py_class("myir.Expr", structure="tree")
class Expr(Object):
    value: int

    def __ffi_repr__(self) -> str:
        return f"Expr({self.value})"

    def __ffi_eq__(self, other: "Expr") -> bool:
        return self.value == other.value

    def __s_equal__(self, other: "Expr", equal) -> bool:
        return equal(self.value, other.value)

# After @py_class: these methods are registered as TypeMethod + TypeAttr
# C++ ReprPrint, RecursiveEq, StructuralEqual can now dispatch to Python hooks
from tvm_ffi import structural_equal
e1 = Expr(value=42)
e2 = Expr(value=42)
assert structural_equal(e1, e2)  # dispatches to __s_equal__
```
