# Unify EnvErrorAlreadySet from special exception type to Error with kind='EnvErrorAlreadySet'
## TL;DR
- Removes the `EnvErrorAlreadySet` C++ exception struct (was a bare `std::exception` subclass) and replaces it with a regular `Error` object whose `kind == "EnvErrorAlreadySet"`.
- Eliminates error code `-2` from the C ABI safe-call convention; `EnvErrorAlreadySet` now returns `-1` like all other errors, with the error kind carrying the signal.
- Python/Cython call sites check `error.kind == "EnvErrorAlreadySet"` after `move_from_last_error()` instead of checking return code `-2`. Backward compatibility with `-2` is temporarily retained with a TODO for removal.

## Key Exports

**Removed**:
- `struct EnvErrorAlreadySet : public std::exception {}` -- deleted from `error.h`
- Error code `-2` semantics removed from `c_api.h` documentation, `TVM_FFI_SAFE_CALL` macro (no longer catches `EnvErrorAlreadySet` separately), `TVM_FFI_CALL_AND_CHECK` macro (no longer checks for `-2`)

**Added**:
```cpp
// error.h -- factory function replacing the struct
inline Error EnvErrorAlreadySet() { return Error("EnvErrorAlreadySet", "", ""); }
```

**Modified C ABI convention**: Return codes are now only `0` (success) and `-1` (error in TLS). The `-2` code is removed from the spec.

## Impact
- API: Breaking for C++ code that catches `tvm::ffi::EnvErrorAlreadySet` as a distinct exception type. Now must catch `tvm::ffi::Error` and check `error.kind() == "EnvErrorAlreadySet"`.
- Behavioral: `TVM_FFI_SAFE_CALL` no longer returns `-2`; always returns `-1` on error. `TVM_FFI_CALL_AND_CHECK` no longer re-throws `EnvErrorAlreadySet`; instead throws the `Error` object which carries the kind.
- Flags/config: none
- Data formats/schemas: C ABI return code `-2` is deprecated (Python still handles it for backward compat).

## Design Elements
Design elements this commit consumes:
- **Error handling** (`.knowledge/designs/0006-error-handling.md`): Modifies the TLS error propagation mechanism and safe-call macros.
- **C ABI layer** (`.knowledge/designs/0001-c-abi-layer.md`): Changes documented return code semantics (removes `-2`).
- **Function system** (`.knowledge/designs/0004-function-system.md`): `TVM_FFI_SAFE_CALL` and `TVM_FFI_CALL_AND_CHECK` macros modified.
- **Python FFI dispatch** (`.knowledge/designs/0015-python-ffi-call-dispatch.md`): Cython `CHECK_CALL`, `Function.__call__`, and `FieldSetter` error handling updated.

Design elements this commit produces:
- **Error-kind-based EnvErrorAlreadySet protocol**: `EnvErrorAlreadySet` is now a regular `Error` object with kind `"EnvErrorAlreadySet"`, flowing through the standard TLS error path rather than a separate exception/return-code channel.

## Usage Examples

Before (C++):
```cpp
try {
    long_running_function();
} catch (const tvm::ffi::EnvErrorAlreadySet&) {
    // special handling for frontend-set error
}
```

After (C++):
```cpp
try {
    long_running_function();
} catch (const tvm::ffi::Error& err) {
    if (err.kind() == "EnvErrorAlreadySet") {
        // frontend-set error
    }
}
```

Throwing the error (unchanged API):
```cpp
if (TVMFFIEnvCheckSignals() != 0) {
    throw tvm::ffi::EnvErrorAlreadySet();  // now returns Error object
}
```
