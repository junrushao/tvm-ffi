# Unify EnvErrorAlreadySet to error.kind
## TL;DR
- Replaces the dedicated `EnvErrorAlreadySet` exception class (which was `std::exception`-based, bypassing the Error object system) with a regular `Error` object whose `kind` is `"EnvErrorAlreadySet"`.
- Eliminates the special error code `-2` from the C ABI. All errors now go through the standard error code `-1` with TLS error transport. The C++ `SAFE_CALL_END` no longer has a separate `catch (const EnvErrorAlreadySet&)` arm.
- Python (Cython) side now checks `error.kind == "EnvErrorAlreadySet"` after retrieving the error from TLS, rather than relying on the return code `-2`. A backward-compatibility shim preserves `-2` handling temporarily.
- `EnvErrorAlreadySet()` is now an inline function returning `Error("EnvErrorAlreadySet", "", "")` instead of a separate exception struct.

## Impact
- ABI: Error code `-2` is deprecated; only `0` (success) and `-1` (error) remain. This simplifies the C ABI contract.
- C++ API: `EnvErrorAlreadySet` changes from a struct to an inline function returning `Error`. Downstream code throwing `EnvErrorAlreadySet()` continues to work but now throws a normal `Error`.
- Python bindings: `CHECK_CALL`, `Function.__call__`, and `FieldSetter.__call__` updated to check error kind instead of return code.
