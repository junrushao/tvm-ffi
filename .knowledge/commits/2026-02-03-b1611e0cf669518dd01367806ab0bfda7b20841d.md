# Unify EnvErrorAlreadySet: replace standalone exception struct with Error(kind='EnvErrorAlreadySet') and remove -2 return code

## TL;DR
- `struct EnvErrorAlreadySet : public std::exception {}` (a bare C++ exception) is removed. Replaced by `inline Error EnvErrorAlreadySet()` which returns a standard `Error` object with `kind = "EnvErrorAlreadySet"`.
- The special return code `-2` from the C ABI (previously meaning "frontend error set") is removed from `TVM_FFI_SAFE_CALL_BEGIN/END` macros in `function.h`; catching `EnvErrorAlreadySet` struct is removed.
- Python/Cython `CHECK_CALL` and `Function.__call__` retain backward-compat `-2` handling (`# TODO: remove after a few versions`) and now also check `error.kind == "EnvErrorAlreadySet"`.
- `c_api.h` removes the `-2` doc comment.

## Key Exports

```python
# Before: separate exception type
struct EnvErrorAlreadySet : public std::exception {};  # REMOVED

# After: factory function returning Error
def EnvErrorAlreadySet() -> Error:
    """Return an Error with kind='EnvErrorAlreadySet' to signal frontend interrupt."""
    return Error("EnvErrorAlreadySet", "", "")
    # Interacts with: Error object system, TVM_FFI_SAFE_CALL_BEGIN/END, TLS error slot
    # Invariant: error.kind == "EnvErrorAlreadySet" triggers raise_existing_error() in Python

# C ABI: -2 return code REMOVED from public API contract
# TVM_FFI_SAFE_CALL_BEGIN no longer catches EnvErrorAlreadySet struct separately
# TVM_FFI_SAFE_CALL_END no longer re-throws on ret_code == -2
```

## Impact
- API: C++ callers using `throw EnvErrorAlreadySet()` (struct) must now use `throw EnvErrorAlreadySet()` (function returning `Error`). The C ABI `-2` return code is removed from the spec (backward compat retained in Python via TODO comment).
- Behavioral: `EnvErrorAlreadySet` is now a standard `Error` object and propagates through the TLS error slot like any other error, simplifying C++ FFI function boilerplate.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

Before (C++):
```cpp
// Catching the struct was a special path
catch (const ::tvm::ffi::EnvErrorAlreadySet&) {
    return -2;  // signal to Python: re-raise existing error
}
// And on C++ call site:
if (ret_code == -2) throw ::tvm::ffi::EnvErrorAlreadySet();
```

After (C++):
```cpp
// EnvErrorAlreadySet is now an Error with kind="EnvErrorAlreadySet"
if (TVMFFIEnvCheckSignals() != 0) {
    throw ::tvm::ffi::EnvErrorAlreadySet();  // returns Error, stored in TLS slot
}
// On call site: same as any other error — throw from TLS slot
throw ::tvm::ffi::details::MoveFromSafeCallRaised();
```

Python backward compat:
```python
# CHECK_CALL still handles old -2 return code + new error.kind check
if ret == -2:
    raise raise_existing_error()  # backward compat
error = move_from_last_error()
if error.kind == "EnvErrorAlreadySet":
    raise raise_existing_error()  # new path
raise error.py_error()
```
