# Unify EnvErrorAlreadySet from standalone exception to Error.kind

## TL;DR
- Replaces the `EnvErrorAlreadySet` C++ exception struct (a plain `std::exception` subclass) with an inline factory function `EnvErrorAlreadySet()` that returns `Error("EnvErrorAlreadySet", "", "")`, unifying all error signaling through the object-based `Error` type.
- Removes the `-2` return code path from the C++ safe-call boundary (`TVM_FFI_SAFE_CALL_END`) and the caller-side re-throw macro (`TVM_FFI_CHECK_SAFE_CALL`). All errors now flow through return code `-1` + TLS.
- Python/Cython retains backward compatibility: checks for legacy `-2` return code (with TODO to remove) and also inspects `error.kind == "EnvErrorAlreadySet"` on the new `-1` path.

## Key Exports

```python
# CHANGED: EnvErrorAlreadySet is no longer a class, now a factory function
# Old: struct EnvErrorAlreadySet : public std::exception {};
# New:
def EnvErrorAlreadySet() -> Error:
    """Factory: create an Error with kind 'EnvErrorAlreadySet'."""
    return Error("EnvErrorAlreadySet", "", "")
    # Interacts with: Error constructor, TVMFFIEnvCheckSignals callers
    # Invariant: returned Error is a normal Error object, propagated via TLS (return -1), not return -2
    # Extension: callers still use `throw EnvErrorAlreadySet()` -- call syntax unchanged

# CHANGED: TVM_FFI_SAFE_CALL_END catch chain
# Old: catch (Error&) { return -1; } catch (EnvErrorAlreadySet&) { return -2; } catch (std::exception&) { return -1; }
# New: catch (Error&) { return -1; } catch (std::exception&) { return -1; }
# EnvErrorAlreadySet() returns Error, so it is caught by the Error& clause

# CHANGED: TVM_FFI_CHECK_SAFE_CALL macro
# Old: if (ret == -2) throw EnvErrorAlreadySet(); if (ret != 0) throw MoveFromSafeCallRaised();
# New: if (ret != 0) throw MoveFromSafeCallRaised();
# The moved error will have kind "EnvErrorAlreadySet", which callers can inspect

# CHANGED: c_api.h return code documentation
# Old: 0=success, -1=error in TLS, -2=frontend error
# New: 0=success, -1=error in TLS
```

## Impact
- API: `EnvErrorAlreadySet` changes from a struct type to an inline factory function returning `Error`. Call-site syntax `throw EnvErrorAlreadySet()` is source-compatible. `catch (EnvErrorAlreadySet&)` clauses in downstream C++ code will fail to compile (type no longer exists as a class). ABI impact limited to downstream C++ code using `EnvErrorAlreadySet` directly; Python DSLs and libraries are not impacted.
- Behavioral: Return code `-2` is no longer produced by C++ safe-call boundaries. Python binding handles both legacy `-2` (backward compat) and new `-1` with `kind == "EnvErrorAlreadySet"`. The semantic outcome (raise frontend error) is identical.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Error object system** ([0005-ffi-error-protocol](../design-records/0005-ffi-error-protocol.md)): Uses `Error(kind, message, backtrace)` constructor to create the replacement `EnvErrorAlreadySet` value.
- **Safe-call boundary macros** ([0004-ffi-function-system](../design-records/0004-ffi-function-system.md)): Modifies `TVM_FFI_SAFE_CALL_END` and `TVM_FFI_CHECK_SAFE_CALL` macro bodies.
- **C ABI return code contract** ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)): Removes `-2` from the documented return code semantics.

Design elements this commit produces/mutates:
- **MUTATED: `EnvErrorAlreadySet` type** -- from `struct : std::exception` to `inline Error EnvErrorAlreadySet()` factory. This is a contract change: the type is no longer catchable independently; it is now an `Error` with a specific `kind` string. Callers that caught `EnvErrorAlreadySet&` must switch to catching `Error&` and inspecting `error.kind()`.
- **MUTATED: Safe-call return code semantics** -- `-2` is no longer produced by the C++ boundary. The two-code error protocol simplifies to single-code (`-1`). Python retains backward compat with `-2` temporarily.
- **MUTATED: `TVM_FFI_CHECK_SAFE_CALL` macro** -- no longer re-throws `EnvErrorAlreadySet`; all non-zero codes retrieve error from TLS.

## Usage Examples

Before (old pattern):
```cpp
// C++ side: EnvErrorAlreadySet was a separate exception type
void LongRunningFunction() {
    if (TVMFFIEnvCheckSignals() != 0) {
        throw ::tvm::ffi::EnvErrorAlreadySet();  // caught as separate branch, returned -2
    }
}
// TVM_FFI_SAFE_CALL_END: catch (EnvErrorAlreadySet&) { return -2; }
// Python: if ret == -2: raise_existing_error()
```

After (new pattern):
```cpp
// C++ side: EnvErrorAlreadySet() now returns Error("EnvErrorAlreadySet", "", "")
void LongRunningFunction() {
    if (TVMFFIEnvCheckSignals() != 0) {
        throw ::tvm::ffi::EnvErrorAlreadySet();  // same call syntax, but now throws Error
    }
}
// TVM_FFI_SAFE_CALL_END: caught by catch (Error& err) { return -1; }
// Python: error = move_from_last_error()
//         if error.kind == "EnvErrorAlreadySet": raise_existing_error()
```
