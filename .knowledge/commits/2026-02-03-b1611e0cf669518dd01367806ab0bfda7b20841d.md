# Unify EnvErrorAlreadySet into error.kind system
## TL;DR
- Removes the standalone `EnvErrorAlreadySet` exception class (previously `struct EnvErrorAlreadySet : public std::exception`)
- Replaces it with an `Error` object whose `kind` is `"EnvErrorAlreadySet"`, unifying it into the standard error system
- Removes error code `-2` from the C ABI — all errors now use code `-1` with TLS error retrieval
- Updates Python Cython bindings to check `error.kind() == "EnvErrorAlreadySet"` instead of catching a separate exception type
- Updates documentation to reflect the unified error code model

## Key Exports
```python
# Before: separate C++ exception type
# struct EnvErrorAlreadySet : public std::exception {};
# safe_call returned -2 for frontend errors

# After: unified into Error with kind="EnvErrorAlreadySet"
class EnvErrorAlreadySet(Error):
    """Error indicating frontend (e.g., Python) already has exception set."""
    # kind() == "EnvErrorAlreadySet"
    # Interacts with: TVMFFIEnvCheckSignals, safe_call convention
    # Invariant: safe_call now always returns -1 for errors (no more -2)
```

## Impact
- API: removes error code `-2` from C ABI (now only `0` success, `-1` error)
- Behavioral: `EnvErrorAlreadySet` is now a proper `Error` object with kind/message/backtrace
- Flags/config: none
- Data formats/schemas: none
