# Add test for subclassing ffi.Function with mixin metadata and handle transfer
## TL;DR
- Adds `test_function_subclass` to `tests/python/test_function.py`, demonstrating how to subclass the Cython `tvm_ffi.Function` cdef class with a Python mixin (`JitFunction`) to attach user metadata.
- Documents the pattern of using `__move_handle_from__` to transfer an FFI function handle into a subclass instance, and the need to explicitly assign `__call__` from the parent cdef class when overriding `__init__`.
- Verifies round-trip identity through `testing.echo`: echoed subclass retains the same underlying C handle (`__chandle__()` equality) and remains callable.

## Design Elements
Design elements this commit consumes:
- **Cython `Function` cdef class** (`.knowledge/designs/0014-python-bindings.md`): The test subclasses `tvm_ffi.Function`, which is a `cdef class(Object)` with a packed-convention `__call__` method.
- **`Object.__move_handle_from__`** (`.knowledge/designs/0014-python-bindings.md`, `object.pxi:194`): Transfers the raw `chandle` pointer from one `Object` instance to another, nulling the source. Used here to graft an existing FFI function handle onto a subclass instance.
- **`Object.__chandle__`** (`.knowledge/designs/0014-python-bindings.md`, `object.pxi:80`): Returns the raw handle as a `uint64`, used for identity comparison after round-tripping through echo.
- **`tvm_ffi.convert`** (`.knowledge/designs/0014-python-bindings.md`): Wraps a Python lambda as an FFI `Function`.
- **`testing.echo` global function** (`.knowledge/designs/function-system.md`): Identity function used to verify that a subclass passed through FFI returns as `tvm_ffi.Function` with the same underlying handle.

Design elements this commit produces:
- **Function subclassing pattern**: Documents a recipe for attaching user metadata (e.g., JIT compilation info) to an FFI function by using multiple inheritance with a Python mixin, explicit `JitFunction.__init__` call (not `super()`), explicit `__call__` re-assignment, and `__move_handle_from__` for handle grafting. This is a new documented usage pattern not previously captured in tests.

## Usage Examples
Subclassing `tvm_ffi.Function` to attach metadata to an FFI function handle:
```python
import tvm_ffi
from typing import Any

class JitFunction:
    def __init__(self, metadata: Any) -> None:
        self.metadata = metadata

class MyFunction(tvm_ffi.Function, JitFunction):
    def __init__(self, metadata: Any) -> None:
        # Cannot use super() because tvm_ffi.Function is a Cython cdef class
        JitFunction.__init__(self, metadata)

    # Must explicitly re-assign __call__ when overriding __init__ on a cdef class
    __call__ = tvm_ffi.Function.__call__  # type: ignore

# Create a function and transfer its handle to the subclass
f = tvm_ffi.convert(lambda x: x)
f_sub = MyFunction(128)
f_sub.__move_handle_from__(f)

assert f_sub.metadata == 128
assert f_sub(2) == 2  # callable through inherited __call__
```
