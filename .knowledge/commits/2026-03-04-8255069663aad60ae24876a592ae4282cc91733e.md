# Fix 3 deny-level clippy lints in Rust bindings
## TL;DR
- Marks `Tensor::data_as_slice_mut` with `#[allow(clippy::wrong_self_convention)]` and documents why `&self` is intentional for mutable data access.
- Marks `device::with_stream` as `unsafe fn` since caller must guarantee stream handle validity.
- Marks `Function::from_extern_c` as `unsafe fn` since caller must guarantee handle lifetime and compatibility.

## Key Exports

```python
# Rust API changes (shown as pseudocode):
# Tensor.data_as_slice_mut(&self) -> &mut [T]  # unchanged signature, added safety docs
# with_stream(device, stream, f) -> Result<T>  # now requires unsafe block
# Function.from_extern_c(handle, safe_call, deleter) -> Function  # now requires unsafe block
```

## Impact
- API: `with_stream` and `Function::from_extern_c` now require `unsafe` blocks in Rust callers. This is a breaking change for Rust consumers.
- Behavioral: None
- Flags/config: Adds `build_cpp/` to `.gitignore`.
