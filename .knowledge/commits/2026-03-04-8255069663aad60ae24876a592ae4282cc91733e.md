# Fix 3 deny-level clippy lints in Rust bindings

## TL;DR
- `data_as_slice_mut(&self)` changed to `data_as_slice_mut(&mut self)` to fix `clippy::mut_from_ref` (aliased mutable references via shared borrows).
- `DLDeviceType::try_from` changed from `impl From<i32>` to `impl TryFrom<i32>` to fix `clippy::fallible_impl_from` (panic in `From` impl).
- `FunctionBase::from_handle` renamed to `from_raw_handle` and takes `NonNull` to fix `clippy::not_unsafe_ptr_arg_deref`.

## Key Exports

```python
# Rust Tensor API change:
# Before: fn data_as_slice_mut(&self) -> &mut [T]
# After:  fn data_as_slice_mut(&mut self) -> &mut [T]
# Invariant: now correctly requires exclusive borrow

# Rust DLDeviceType conversion:
# Before: impl From<i32> for DLDeviceType (panics on unknown)
# After:  impl TryFrom<i32> for DLDeviceType (returns Err on unknown)

# Rust FunctionBase:
# Before: fn from_handle(handle: *mut c_void) -> Self
# After:  fn from_raw_handle(handle: NonNull<c_void>) -> Self
```

## Impact
- API: Breaking Rust API changes (3 signature changes). No C++/Python impact.
- Behavioral: `DLDeviceType` conversion no longer panics on unknown values.
