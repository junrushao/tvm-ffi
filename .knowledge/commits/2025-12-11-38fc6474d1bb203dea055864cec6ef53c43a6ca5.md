# Fix wrong function name in numpy-missing fallback in dtype.pxi

## TL;DR
- The `else` branch of `dtype.pxi` (executed when numpy is not installed) defined a stub function named `_convert_torch_dtype_to_ffi_dtype` instead of the correct `_convert_numpy_dtype_to_ffi_dtype`.
- This rename fixes the function name so that callers using the numpy conversion path get a meaningful `ValueError("numpy not found")` error message with the correct function name rather than a confusing torch-referencing name.
- Single-line fix: 1 deletion, 1 addition in `python/tvm_ffi/cython/dtype.pxi`.

## Key Exports

None

## Impact
- API: none — no public interface changes; the stub is internal to `dtype.pxi`.
- Behavioral: When numpy is absent and `_convert_numpy_dtype_to_ffi_dtype` is called, the error message now correctly references numpy rather than torch.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `dtype.pxi` optional-numpy pattern — `if numpy is not None: ... else:` guard in `python/tvm_ffi/cython/dtype.pxi`; documented in `.knowledge/design-records/0013-python-package.md`.

Design elements this commit produces: none

## Usage Examples

Before (incorrect — wrong function name in stub):
```python
# else branch when numpy is not installed
def _convert_torch_dtype_to_ffi_dtype(torch_dtype):
    raise ValueError("numpy not found")
```

After (correct):
```python
def _convert_numpy_dtype_to_ffi_dtype(numpy_dtype):
    raise ValueError("numpy not found")
```
