# Fix misnamed numpy fallback stub in Cython dtype module
## TL;DR
- Renames the fallback function defined when numpy is not installed from `_convert_torch_dtype_to_ffi_dtype` to `_convert_numpy_dtype_to_ffi_dtype` in `python/tvm_ffi/cython/dtype.pxi`.
- This was a copy-paste error: the `else` branch (numpy absent) defined a stub with the wrong name, so calling `_convert_numpy_dtype_to_ffi_dtype` without numpy would hit an `AttributeError` instead of the intended `ValueError("numpy not found")`.

## Key Exports
None

## Impact
- API: Fixes the fallback stub name so that `_convert_numpy_dtype_to_ffi_dtype` is correctly defined in environments without numpy. Callers that import this function from the Cython `core` module now get the expected `ValueError` rather than an `AttributeError`.
- Behavioral: Error message changes from `AttributeError` (function not found) to `ValueError("numpy not found")` when numpy is unavailable.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DType conversion dispatch** (`python/tvm_ffi/cython/dtype.pxi`): The pattern of defining paired real/fallback functions for optional dependencies (numpy, torch), where the `else` branch raises a descriptive error. Documented in prior commit ledgers (2025-09-19-d77606af, 2025-11-07-5a877494).

Design elements this commit produces:
- None -- this is a name correction, not a new element.

## Usage Examples
Before (broken, numpy absent):
```python
from tvm_ffi import core
# This raised AttributeError because the stub was named _convert_torch_dtype_to_ffi_dtype
core._convert_numpy_dtype_to_ffi_dtype(some_dtype)
```

After (fixed, numpy absent):
```python
from tvm_ffi import core
# Now correctly raises ValueError("numpy not found")
core._convert_numpy_dtype_to_ffi_dtype(some_dtype)
```
