# Add test verifying __doc__ is None for reflection fields without explicit docstring
## TL;DR
- Adds `test_attribute_no_doc` to `tests/python/test_object.py`, asserting that reflection-registered fields without an explicit docstring have `__doc__ is None`.
- Follow-up test for PR #60 (`43ffe57`), which reverted auto-generated docstrings introduced in PR #49 due to Sphinx conflicts.

## Design Elements
Design elements this commit consumes:
- **Reflection field docstring propagation** (`0008-reflection.md`): `ObjectDef::def_rw`/`def_ro` accepts an optional docstring parameter. When provided (e.g., `"i64 field"` for `v_i64`), it surfaces as the Python property's `__doc__`. When omitted (`v_f64`, `v_str`), `__doc__` must be `None` (not an auto-generated string).
- **Python property descriptors** (`0012-python-bindings.md`): C++-reflected fields become Python descriptors on the registered class, each carrying a `__doc__` attribute.
