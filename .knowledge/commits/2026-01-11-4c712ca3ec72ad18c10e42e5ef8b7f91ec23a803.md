# Extend ErrorObj ABI with cause_chain and extra_context fields for future error chaining

## TL;DR
- Appends two new nullable `TVMFFIObjectHandle` fields to `TVMFFIErrorCell` in `c_api.h`: `cause_chain` (optional chained cause error) and `extra_context` (opaque object, e.g. Python exception).
- Change is declared backward-compatible: existing code that only reads the first fields is unaffected; the new fields are appended at the end.
- Adds `TVMFFIErrorCreateWithCauseAndExtraContext` C ABI function and corresponding C++ `Error(kind, message, backtrace, cause_chain, extra_context)` constructor plus `cause_chain()`/`extra_context()` accessors.
- `ErrorObj` gets an explicit destructor to `DecRef` the new handles.

## Key Exports

```python
# C ABI — include/tvm/ffi/c_api.h
class TVMFFIErrorCell:
    """ABI layout (extended, backward-compatible append)."""
    kind: TVMFFIByteArray
    message: TVMFFIByteArray
    backtrace: TVMFFIByteArray
    update_backtrace: Callable  # (self, backtrace, update_mode) -> void
    cause_chain: TVMFFIObjectHandle   # NEW: nullable, owned by ErrorCell
    extra_context: TVMFFIObjectHandle  # NEW: nullable, owned by ErrorCell
    # Invariant: both fields are DecRef'd in ErrorObj destructor

def TVMFFIErrorCreateWithCauseAndExtraContext(
    kind: TVMFFIByteArray*, message: TVMFFIByteArray*, backtrace: TVMFFIByteArray*,
    cause_chain: TVMFFIObjectHandle, extra_context: TVMFFIObjectHandle,
    out: TVMFFIObjectHandle*
) -> int:
    """Create an Error with optional cause chain and extra context.
    # Returns 0 on success, nonzero on failure
    # Interacts with: TVMFFIErrorCreate (simpler variant without new fields)
    """

# C++ API — include/tvm/ffi/error.h
class Error(ObjectRef):
    def __init__(self, kind: str, message: str, backtrace: str,
                 cause_chain: Optional[Error], extra_context: Optional[ObjectRef]): ...
    def cause_chain(self) -> Optional[Error]: ...
    def extra_context(self) -> Optional[ObjectRef]: ...
    # Invariant: cause_chain/extra_context handles owned by ErrorObj; DecRef'd in ~ErrorObj()
    # Interacts with: details::ObjectUnsafe::DecRefObjectHandle (destructor)
    #                  details::ObjectUnsafe::MoveObjectRefToTVMFFIObjectPtr (constructor)
```

## Impact
- API: **additive** — new fields appended to `TVMFFIErrorCell` struct; existing `TVMFFIErrorCreate` unchanged. New `TVMFFIErrorCreateWithCauseAndExtraContext` added.
- Behavioral: `ErrorObj` constructor now zeroes `cause_chain` and `extra_context`; destructor DecRefs them. Existing error objects behave identically (both fields null).
- Flags/config: none
- Data formats/schemas: `TVMFFIErrorCell` ABI struct extended — **consumers reading past known fields without checking size will read new fields** (risk if ABI is version-negotiated, though this is declared backward-compatible).

## Usage Examples

```cpp
// C++: create an error with a cause chain
Error cause = Error("ValueError", "original cause", "");
Error chained = Error("RuntimeError", "wrapping error", "",
                      std::optional<Error>(cause),
                      std::nullopt);

// Access cause chain
if (auto c = chained.cause_chain()) {
    std::cout << c->what() << "\n";
}

// Attach Python exception as extra_context (Python bridge uses this)
Error with_ctx = Error("RuntimeError", "msg", "",
                       std::nullopt,
                       std::optional<ObjectRef>(py_error_obj));
```
