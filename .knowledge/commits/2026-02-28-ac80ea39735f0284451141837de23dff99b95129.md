# Add CMake namespace ALIAS targets so tvm_ffi::header/shared/static are available in source dependency builds

## TL;DR
- Adds `tvm_ffi::header` ALIAS in `CMakeLists.txt` pointing to `tvm_ffi_header`.
- Adds `tvm_ffi::static` and `tvm_ffi::shared` ALIAS targets in `cmake/Utils/Library.cmake` inside `tvm_ffi_add_target_from_obj`, pointing to `tvm_ffi_static` and `tvm_ffi_shared`.
- Fixes a gap where `tvm_ffi_configure_target` (which links against `tvm_ffi::header` / `tvm_ffi::shared`) would `FATAL_ERROR` when tvm-ffi was consumed as a source dependency rather than via `find_package`.

## Key Exports

N/A — infrastructure

The three new CMake ALIAS targets created by this commit:

```python
# CMakeLists.txt (top-level):
# add_library(tvm_ffi::header ALIAS tvm_ffi_header)
#   Invariant: declared immediately after add_library(tvm_ffi_header INTERFACE)
#   Interacts with: tvm_ffi_configure_target (links tvm_ffi::header when TARGET tvm_ffi::header)

# cmake/Utils/Library.cmake — inside tvm_ffi_add_target_from_obj(target_name, obj_target_name):
# add_library(${target_name}::static ALIAS ${target_name}_static)
# add_library(${target_name}::shared ALIAS ${target_name}_shared)
#   Invariant: declared immediately after the corresponding add_library(... STATIC/SHARED ...)
#   Interacts with: tvm_ffi_configure_target (guards link on `if (TARGET tvm_ffi::shared)`)
#   Extension: any future tvm_ffi_add_target_from_obj call auto-gets ::static and ::shared aliases
```

## Impact
- API: None for C++/Python. CMake: downstream `FetchContent`/`add_subdirectory` consumers can now use `tvm_ffi::header`, `tvm_ffi::shared`, `tvm_ffi::static` without a prior `find_package` call.
- Behavioral: `tvm_ffi_configure_target` no longer fails for source dependency builds; the `if (TARGET tvm_ffi::header)` guard in Library.cmake now evaluates to true.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `tvm_ffi_configure_target` CMake function (0021-build-packaging) — this commit unblocks its use in source builds by satisfying its `TARGET tvm_ffi::header/shared` guards.
- `tvm_ffi_add_target_from_obj` CMake function (0021-build-packaging) — the function where `::static` and `::shared` ALIAS targets are now injected.
- CMake config file `cmake/tvm_ffi-config.cmake` (0021-build-packaging) — previously the only place these namespace-qualified targets were defined.

Design elements this commit produces:
- Source-build namespace alias convention: `tvm_ffi::<variant>` is now available in both source and installed-package builds, closing the gap between the two build modes. This extends the invariant in 0021-build-packaging that `tvm_ffi_configure_target` expects namespace targets to exist.

## Usage Examples

Downstream project consuming tvm-ffi via `FetchContent`:

```cmake
# Before this commit — FATAL_ERROR: "tvm_ffi::header does not exist"
include(FetchContent)
FetchContent_Declare(tvm_ffi GIT_REPOSITORY ...)
FetchContent_MakeAvailable(tvm_ffi)
add_library(my_ext SHARED my_ext.cc)
tvm_ffi_configure_target(my_ext)  # <-- would crash: tvm_ffi::header not defined

# After this commit — works correctly
# The ALIAS targets are created during FetchContent's build of tvm-ffi
add_library(my_ext SHARED my_ext.cc)
tvm_ffi_configure_target(my_ext)  # tvm_ffi::header/shared now exist as aliases
```
