# Add CMake namespace aliases for source dependency builds
## TL;DR
- Adds CMake `ALIAS` targets (`tvm_ffi::header`, `tvm_ffi::shared`, `tvm_ffi::static`) that point to the in-tree build targets (`tvm_ffi_header`, `tvm_ffi_shared`, `tvm_ffi_static`), making namespace-qualified target names available in both source (`add_subdirectory`) and package (`find_package`) builds.

## Impact
- **API**: CMake consumers using `add_subdirectory(tvm-ffi)` can now use `tvm_ffi::header`, `tvm_ffi::shared`, and `tvm_ffi::static` -- the same target names created by `tvm_ffi-config.cmake` in installed-package mode. Previously, source-dependency consumers had to use `tvm_ffi_header`/`tvm_ffi_shared`/`tvm_ffi_static` (no namespace), while `tvm_ffi_configure_target` expected the namespace-qualified names.
- **Flags/config**: None.
- **Data formats/schemas**: None.

## Design Elements

Design elements this commit **consumes**:

- **Packaging and Build** ([`.knowledge/designs/0016-packaging-and-build.md`](../designs/0016-packaging-and-build.md)): The dual-mode CMake guard and `tvm_ffi-config.cmake` target creation, which only creates namespace-qualified targets via `add_library(tvm_ffi::shared IMPORTED SHARED ...)` in config mode.

Design elements this commit **produces**:

- **Source-build namespace aliases**: Three `add_library(... ALIAS ...)` calls:
  1. `tvm_ffi::header ALIAS tvm_ffi_header` in top-level `CMakeLists.txt` (alongside the header-only target definition).
  2. `tvm_ffi::static ALIAS tvm_ffi_static` in `cmake/Utils/Library.cmake` (inside `tvm_ffi_add_target_from_obj`).
  3. `tvm_ffi::shared ALIAS tvm_ffi_shared` in `cmake/Utils/Library.cmake` (inside `tvm_ffi_add_target_from_obj`).

  This closes the gap between source and package builds: downstream code can now uniformly link against `tvm_ffi::shared` regardless of how tvm-ffi was integrated. The existing `tvm_ffi_configure_target` function (and any downstream `target_link_libraries` using namespace names) now works without modification in both modes.
