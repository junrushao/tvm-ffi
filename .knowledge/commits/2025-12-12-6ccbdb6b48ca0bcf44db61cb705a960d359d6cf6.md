# Remove CPython reference cycles in error traceback enrichment path for faster GC

## TL;DR
- `_with_append_backtrace` in `error.py` created reference cycles among `py_error`, `tb`, and the call-chain stack frames, preventing CPython's immediate ref-count-based GC from freeing tensors held in those frames.
- Fix uses two complementary techniques: (1) a nested helper function in `TracebackManager.append_traceback` to avoid binding the created `frame` object to a local variable, and (2) explicit `del py_error, tb` in a `finally` block in `_with_append_backtrace`.
- New test `test_error_no_cyclic_reference` verifies the fix by disabling the cyclic GC and checking that a `weakref` to a local object is dead after the call returns.

```python
class TracebackManager:
    """Manages synthetic Python tracebacks for cross-language error enrichment."""

    def append_traceback(
        self,
        tb: types.TracebackType | None,
        filename: str,
        lineno: int,
        func: str,
    ) -> types.TracebackType:
        # CHANGED (commit 6ccbdb6): Wraps frame creation in a nested function `create()`
        # so the FrameType object is never bound to a local variable in append_traceback's
        # own frame. Previously: `frame = self._create_frame(...); return types.TracebackType(tb, frame, ...)`
        # Now: the frame is passed directly as an argument to the nested `create()` call site.
        # Invariant: the returned TracebackType holds a reference to the FrameType, but
        #            append_traceback's own locals do NOT — eliminating one arm of the cycle.
        # Interacts with: _with_append_backtrace (caller), _create_frame, types.TracebackType

        def create(
            tb: types.TracebackType | None, frame: types.FrameType, lineno: int
        ) -> types.TracebackType:
            return types.TracebackType(tb, frame, frame.f_lasti, lineno)

        return create(tb, self._create_frame(filename, lineno, func), lineno)


def _with_append_backtrace(py_error: BaseException, backtrace: str) -> BaseException:
    """Append C++ backtrace frames to a Python exception's traceback.

    CHANGED (commit 6ccbdb6): Uses try/finally with explicit `del py_error, tb`
    to ensure neither object remains in this frame's locals after return.
    Previously retained both in locals, which closed a reference cycle through
    the traceback chain back to the call-chain frames.
    """
    # Invariant: py_error and tb must NOT survive in this frame's locals after return.
    # Invariant: the returned exception has tb chain enriched with C++ frames.
    # Interacts with: TracebackManager.append_traceback, _parse_backtrace, _TRACEBACK_MANAGER
    tb = py_error.__traceback__
    try:
        for filename, lineno, func in _parse_backtrace(backtrace):
            tb = _TRACEBACK_MANAGER.append_traceback(tb, filename, lineno, func)
        return py_error.with_traceback(tb)
    finally:
        del py_error, tb  # Break reference cycle: frame locals → exception → traceback chain → frame
```

## Impact
- API: none — both functions are internal (`_` prefix); no caller-visible signature change.
- Behavioral: CPython now immediately frees objects held in frames that called through the error enrichment path, once the error is handled. Previously such objects required the cyclic GC (`gc.collect()`) to reclaim.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements

Design elements this commit consumes:
- `TracebackManager` and `_with_append_backtrace` in `python/tvm_ffi/error.py` — the Python-side traceback enrichment pipeline documented in [0005-error-system](../design-records/0005-error-system.md) (the "Traceback Enrichment Flow" section).
- `_parse_backtrace` — unchanged helper that converts the C++ backtrace string into `(filename, lineno, func)` tuples.

Design elements this commit produces:
- Mutates `TracebackManager.append_traceback` — new invariant: frame object is not retained in the caller frame's locals after the call returns.
- Mutates `_with_append_backtrace` — new invariant: `py_error` and `tb` are explicitly deleted before the frame is freed, ensuring no reference cycle links call-chain frames to the exception object graph.

## Usage Examples

**Before/after pattern — reference cycle avoidance:**

```python
# BEFORE (creates reference cycle):
def _with_append_backtrace(py_error, backtrace):
    tb = py_error.__traceback__
    for filename, lineno, func in _parse_backtrace(backtrace):
        tb = _TRACEBACK_MANAGER.append_traceback(tb, filename, lineno, func)
    return py_error.with_traceback(tb)
    # On return, py_error and tb remain in this frame's locals until the frame
    # is freed. But py_error.__traceback__ → tb → frame chain → this frame,
    # forming a cycle that CPython's ref-count GC cannot break.

# AFTER (cycle-free):
def _with_append_backtrace(py_error, backtrace):
    tb = py_error.__traceback__
    try:
        for filename, lineno, func in _parse_backtrace(backtrace):
            tb = _TRACEBACK_MANAGER.append_traceback(tb, filename, lineno, func)
        return py_error.with_traceback(tb)
    finally:
        del py_error, tb   # Explicit break; `finally` runs after `return` is evaluated

# Test verification (from tests/python/test_error.py):
gc.disable()
try:
    def may_create_cyclic_reference():
        obj = SampleObject()
        trigger_cpp_side_error()       # raises KeyError from C++, caught internally
        return weakref.ref(obj)

    wref = may_create_cyclic_reference()
    assert wref() is None, "Cyclic reference occurs inside error handling pipeline"
finally:
    gc.enable()
```
