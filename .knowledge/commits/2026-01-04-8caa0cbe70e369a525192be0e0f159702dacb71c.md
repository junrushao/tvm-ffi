# Introduce umbrella header `<tvm/ffi/tvm_ffi.h>` for core C++ APIs
## TL;DR
- Adds `include/tvm/ffi/tvm_ffi.h`, an umbrella header that aggregates all core TVM-FFI C++ headers (excluding `tvm/ffi/extra/`), analogous to `nanobind/nanobind.h` and `pybind11/pybind11.h`.
- Updates all examples and quickstart docs to use `#include <tvm/ffi/tvm_ffi.h>` instead of individual `#include` directives.
- Cleans up `examples/python_packaging/pyproject.toml` scikit-build-core configuration.

## Key Exports

```python
# New file: include/tvm/ffi/tvm_ffi.h
# Umbrella header — single include that transitively provides:
#   any.h, base_details.h, c_api.h, cast.h,
#   container/{array, container_details, map, shape, tensor, tuple, variant}.h,
#   dtype.h, endian.h, error.h, function.h, function_details.h,
#   memory.h, object.h, optional.h,
#   reflection/{access_path, accessor, creator, overload, registry}.h,
#   rvalue_ref.h, string.h, type_traits.h
#
# Interacts with: every core C++ header in tvm/ffi/; does NOT include tvm/ffi/extra/*.
# Invariant: must be kept in sync when new core headers are added to include/tvm/ffi/.
# Extension: tvm/ffi/extra/ headers (module.h, c_env_api.h, stl.h, cuda/) remain
#            separate includes — the umbrella covers the "core" surface only.
```

## Impact
- API: None — purely additive. Existing per-header includes continue to work.
- Behavioral: None.
- Flags/config: `examples/python_packaging/pyproject.toml` switches `build-dir` to `build-wheel`, sets `cmake.build-type` to `Release`, adds `CMAKE_EXPORT_COMPILE_COMMANDS` define, and removes stale `logging`/`minimum-version` keys.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- All core C++ headers listed in design records 0001-0010 (c_api, any, object, function, error, containers, reflection, object macros, structural eq/hash, JSON serialization).

Design elements this commit produces:
- **Umbrella header convention**: `<tvm/ffi/tvm_ffi.h>` as the single recommended C++ include for extension authors. This establishes a new convention: downstream C++ code should prefer the umbrella header over individual includes. The `extra/` namespace remains opt-in.

## Usage Examples

Before (multiple includes):
```cpp
#include <tvm/ffi/container/tensor.h>
#include <tvm/ffi/function.h>
#include <tvm/ffi/object.h>
#include <tvm/ffi/reflection/registry.h>
```

After (single umbrella):
```cpp
#include <tvm/ffi/tvm_ffi.h>
```

For code that also needs extra capabilities (module loading, CUDA, STL bridge), add the extra header alongside:
```cpp
#include <tvm/ffi/tvm_ffi.h>
#include <tvm/ffi/extra/module.h>
```
