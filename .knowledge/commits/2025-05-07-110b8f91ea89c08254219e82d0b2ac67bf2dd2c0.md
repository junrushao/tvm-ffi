# Rename FromUnpacked to FromTyped and purge legacy PackedFunc terminology from docs

## TL;DR
- Renames `Function::FromUnpacked` to `Function::FromTyped` across all headers, source files, and tests. The method signature and behavior are unchanged.
- Replaces all remaining `PackedFunc` / `PackedFuncObj` / `TVMRetValue` references in Doxygen comments with their modern equivalents (`ffi::Function`, `ffi::FunctionObj`, `ffi::Any`).
- Updates the `ffi::Function` class-level doc to clarify that arguments are passed "by packed format via AnyView".
- Test names updated correspondingly (e.g., `TEST(Func, FromUnpacked)` becomes `TEST(Func, FromTyped)`, `TEST(Map, PackedFuncGetItem)` becomes `TEST(Map, ffi::FunctionGetItem)`).

## Changed Files

### `include/tvm/ffi/function.h`
- `Function::FromUnpacked(callable)` and `Function::FromUnpacked(callable, name)` renamed to `Function::FromTyped(callable)` and `Function::FromTyped(callable, name)`. Template body unchanged -- still wraps a typed callable into a packed `void(const AnyView*, int32_t, Any*)` via `details::unpack_call`.
- All 10 call sites within `function.h` updated: `TypedFunction` constructors and assignment operators, `Registry::set_body_typed`, and `Registry::set_body_method` (both const and non-const overloads).
- Doxygen comments updated throughout:
  - `"constructing PackedFuncObj"` -> `"constructing ffi::FunctionObj"`.
  - `"signature is consistent with PackedFunc"` -> `"signature is consistent with ffi::Function"` (3 occurrences).
  - `TypedFunction` anchor doc block: `"A PackedFunc wrapper"` -> `"A ffi::Function wrapper"`, `"backed by a PackedFunc"` -> `"backed by a ffi::Function"`, `"argument of PackedFunc"` -> `"argument of ffi::Function"`, `"assigned to TVMRetValue"` -> `"assigned to ffi::Any"`, `"converted to a type-erased PackedFunc"` -> `"converted to a type-erased ffi::Function"`, `"prefer TypedFunction over PackedFunc"` -> `"prefer TypedFunction over ffi::Function"`.
  - Code example in doc block: `"PackedFunc packed = ftype"` -> `"ffi::Function packed = ftype"`.
  - `"copy assignment operator from PackedFunc"` -> `"copy assignment operator from ffi::Function"`.
  - `"convert to PackedFunc"` / `"return the internal PackedFunc"` -> `"convert to ffi::Function"` / `"return the internal ffi::Function"`.

- Comment `"output TypedPackedFunc signature"` -> `"output typed function signature"`.

## Key Exports

No new types, functions, or APIs are introduced. This is a pure rename:

| Before | After |
|--------|-------|
| `Function::FromUnpacked(callable)` | `Function::FromTyped(callable)` |
| `Function::FromUnpacked(callable, name)` | `Function::FromTyped(callable, name)` |

## Impact
- **API**: Rename of a public static method on `Function`. Any downstream C++ code calling `Function::FromUnpacked` must update to `Function::FromTyped`. No signature or behavioral change.
- **ABI**: No ABI change. `FromTyped`/`FromUnpacked` are template methods resolved at compile time; they do not appear in the C ABI.
- **Documentation**: Removes all remaining `PackedFunc` terminology from the FFI codebase, completing the vocabulary migration to `ffi::Function`.
- **Bug**: The test rename `TEST(Map, ffi::FunctionGetItem)` introduces an invalid GoogleTest identifier (the `::` is not valid); this is corrected in a subsequent cleanup commit.

## Design Elements

Design elements this commit consumes:
- `ffi::Function` and `FunctionObj` (from 7d34eb8).
- `details::unpack_call` / `details::FunctionInfo` template machinery (from 7d34eb8).
- `TypedFunction<R(Args...)>` typed wrapper (from 7d34eb8).

Design elements this commit produces:
- **`Function::FromTyped` naming convention** -- Establishes the canonical name for wrapping a typed C++ callable into a packed `ffi::Function`. The name "FromTyped" better conveys intent: convert from a typed signature to the type-erased packed representation.
- **PackedFunc terminology elimination** -- After this commit, no references to the legacy `PackedFunc` / `PackedFuncObj` / `TVMRetValue` names remain in the codebase. All documentation and comments consistently use `ffi::Function`, `ffi::FunctionObj`, and `ffi::Any`.
