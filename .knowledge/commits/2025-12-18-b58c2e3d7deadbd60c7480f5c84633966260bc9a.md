# Stubgen gains --init-* flags for package bootstrapping
## TL;DR
- Adds `--init-pypkg`, `--init-lib`, `--init-prefix` CLI flags to `tvm-ffi-stubgen` so entire package scaffolding (`_ffi_api.py`, `__init__.py`) can be generated from a single command.
- Refactors stubgen internals: extracts `lib_state.py` for runtime metadata queries, introduces `InitConfig`/`ImportItem` data classes, and splits the pipeline into three stages (collect, init-generate, process).
- Moves `tvm_ffi.testing` into its own subpackage with auto-generated `_ffi_api.py` stubs.

## Impact
- API: New CLI flags (`--init-pypkg`, `--init-lib`, `--init-prefix`, `--imports`) change the public interface of `tvm-ffi-stubgen`. Existing invocations without `--init-*` are unaffected.
- Flags/config: Three new flags; `--imports` flag added for pre-loading Python modules before generation.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Type schema and stubgen** (`.knowledge/designs/0023-type-schema-and-stubgen.md`): The commit heavily extends the stubgen tool, relying on the existing `CodeBlock`, `FuncInfo`, `ObjectInfo`, `TypeSchema` abstractions.
- **Global function registry** (`.knowledge/designs/0004-function-system.md`): Uses `list_global_func_names()` and `get_global_func_metadata()` to discover registered functions.
- **Object system** (`.knowledge/designs/0003-object-system.md`): Uses `GetRegisteredTypeKeys()` and `_lookup_or_register_type_info_from_type_key()` for object discovery and topological sorting by inheritance.
- **Module export system** (`.knowledge/designs/0008-module-export-system.md`): The `--dlls` flag preloads shared libraries via `ctypes.CDLL` to populate the global registry.

Design elements this commit produces:
- **Package initialization workflow**: New `_stage_2` generates `_ffi_api.py` and `__init__.py` for any prefix not already defined in existing files. This is a new scaffolding capability for downstream packages.
- **`lib_state.py` module**: Centralizes runtime metadata queries (`collect_global_funcs`, `collect_type_keys`, `toposort_objects`, `object_info_from_type_key`) with LRU caching. Separates FFI introspection from code generation logic.
- **`ImportItem` / `InitConfig` data classes**: Structured representations for import tracking and init configuration, replacing ad-hoc `set[str]` tracking.
