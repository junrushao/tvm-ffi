# Add --init-* flags to tvm-ffi-stubgen for whole-package stub bootstrapping
## TL;DR
- Adds `--init-pypkg`, `--init-lib`, `--init-prefix` CLI flags to `tvm-ffi-stubgen`, enabling single-command generation of `_ffi_api.py` and `__init__.py` files for an entire extension package.
- Refactors the stubgen pipeline from 2 stages to 3 stages, extracts runtime metadata queries into a new `lib_state.py` module (replacing `analysis.py`), and introduces `ImportItem`, `InitConfig` data classes to formalize import tracking and init configuration.
- Adds new stub block kinds (`import-section`, `import-object`, `export`) and extends the `global/` block syntax with `@import-from` to control where `_FFI_INIT_FUNC` is imported from. Restructures the `tvm_ffi/testing` module as a proper sub-package with generated `_ffi_api.py`.

## Impact
- API: `generate_imports` renamed to `generate_import_section`. `analysis.py` deleted, replaced by `lib_state.py`. `ObjectInfo.from_type_key()` replaced by `ObjectInfo.from_type_info()`. `FuncInfo.from_global_name()` replaced by `FuncInfo.from_schema()`. Stub block kind `"import"` renamed to `"import-section"`. `CodeBlock.param` for `global/` kind changed from `str` to `tuple[str, str]`.
- Behavioral: `global/` block now emits `_FFI_INIT_FUNC(prefix, __name__)` inside the block (was external). `--dlls` now accepts semicolon-separated list (was space-separated via `nargs=*`). New `--imports` flag for pre-loading Python modules. `__all__` ordering changed to CONST > PascalCase > snake_case.
- Flags/config: Three new CLI flags `--init-pypkg`, `--init-lib`, `--init-prefix` (all-or-nothing). New `--imports` flag.
- Data formats/schemas: New `import-object` and `export` stub marker syntaxes. `global/` syntax extended with `@import_from`.

## Design Elements
Design elements this commit consumes:
- **Global function registry** (`list_global_func_names`, `get_global_func_metadata`): used by `lib_state.collect_global_funcs()` to enumerate registered functions. See `.knowledge/designs/0012-python-bindings.md`.
- **Reflection/TypeInfo system** (`_lookup_or_register_type_info_from_type_key`, `TypeSchema`): used by `lib_state.object_info_from_type_key()`. See `.knowledge/designs/0008-reflection.md`.
- **GetRegisteredTypeKeys FFI function**: used by `lib_state.collect_type_keys()` to discover object types. See `.knowledge/designs/0012-python-bindings.md` line 646.
- **Module loading** (`load_lib_module`): consumed by generated code (`_FFI_LOAD_LIB`). See `.knowledge/designs/0011-module-system.md`.

Design elements this commit produces:
- **InitConfig**: new data class formalizing the `--init-*` package generation workflow.
- **ImportItem**: new data class for structured import tracking during codegen, replacing ad-hoc `ty_used: set[str]`.
- **lib_state module**: centralizes runtime metadata queries with LRU caching; replaces `analysis.py`.
- **3-stage stubgen pipeline**: Stage 1 (collect ty-maps), Stage 2 (generate missing files via `--init-*`), Stage 3 (process existing stub blocks).
- **New stub block kinds**: `import-section`, `import-object`, `export` -- extending the marker protocol.
- **`@import-from` syntax on global blocks**: `global/<prefix>@<module>` controls where `_FFI_INIT_FUNC` is imported from.
- **Topological object sorting**: `toposort_objects()` ensures parent classes are emitted before children in generated code.

## Usage Examples

Single-command package bootstrapping for an extension:

```bash
tvm-ffi-stubgen examples/packaging/python \
  --dlls examples/packaging/build/libmy_ffi_extension.dylib \
  --init-pypkg  my-ffi-extension \
  --init-lib    my_ffi_extension \
  --init-prefix "my_ffi_extension."
```

This generates `my_ffi_extension/_ffi_api.py` (with `LIB = _FFI_LOAD_LIB(...)`, global function stubs, object class definitions, `__all__`) and `my_ffi_extension/__init__.py` (with export block re-exporting `_ffi_api`). Re-running is idempotent -- existing blocks are detected and not duplicated.

Generated `_ffi_api.py` structure:

```python
# tvm-ffi-stubgen(begin): import-section
from __future__ import annotations
from tvm_ffi import Object as _ffi_Object, init_ffi_api as _FFI_INIT_FUNC, register_object as _FFI_REG_OBJ
from tvm_ffi.libinfo import load_lib_module as _FFI_LOAD_LIB
# tvm-ffi-stubgen(end)
LIB = _FFI_LOAD_LIB("my-ffi-extension", "my_ffi_extension")

# tvm-ffi-stubgen(begin): global/my_ffi_extension
_FFI_INIT_FUNC("my_ffi_extension", __name__)
if TYPE_CHECKING:
    def raise_error(_0: str, /) -> None: ...
# tvm-ffi-stubgen(end)

@_FFI_REG_OBJ("my_ffi_extension.IntPair")
class IntPair(_ffi_Object):
    # tvm-ffi-stubgen(begin): object/my_ffi_extension.IntPair
    a: int
    b: int
    # tvm-ffi-stubgen(end)
```
