# Add --init-* flags to tvm-ffi-stubgen for bootstrapping new FFI extension packages

## TL;DR
- Adds `--init-pypkg`, `--init-lib`, `--init-prefix` CLI flags to `tvm-ffi-stubgen` so a new downstream FFI extension package can bootstrap its `_ffi_api.py` and `__init__.py` stubs from a single command, without hand-authoring any boilerplate.
- Refactors the stub pipeline: separates runtime metadata querying into a new `lib_state.py` module; promotes `ImportItem` and `InitConfig` to first-class data structures in `utils.py`; expands `CodeBlock.kind` with new block types (`import-section`, `import-object`, `export`); and changes `--dlls` to accept semicolon-separated values instead of nargs.
- Updates `examples/packaging/python/my_ffi_extension/` to use the generated `_ffi_api.py` / `__init__.py` pattern, removing the old hand-authored `__init__.py` with explicit class definitions.

## Impact
- API: `--dlls` argument changed from `nargs="*"` (list of positional args) to `type=str` (semicolon-separated string). Callers using `--dlls lib1.so lib2.so` must switch to `--dlls lib1.so;lib2.so`.
- API: `tvm-ffi-stubgen(begin): import` marker renamed to `tvm-ffi-stubgen(begin): import-section` in the block kind system. Existing files using `import` markers should still parse correctly due to prefix matching, but the canonical name changed.
- API: `generate_imports()` in `codegen.py` renamed to `generate_import_section()`.
- API: `collect_global_funcs()` moved from `analysis.py` to `lib_state.py`; `analysis.py` deleted.
- Behavioral: `generate_global_funcs` now emits `_FFI_INIT_FUNC("prefix", __name__)` into the stub block (inside `# fmt: off`), before the `if TYPE_CHECKING:` guard.
- Behavioral: `TY_MAP_DEFAULTS` in `consts.py` now includes type remappings previously in `TY_TO_IMPORT` (the separate dict is removed). Default remappings like `"Object" -> "ffi.Object"` no longer need `TY_TO_IMPORT` lookup.
- Flags/config: Three new CLI flags: `--init-pypkg`, `--init-lib`, `--init-prefix` (all must be provided together). New `--imports` flag for importlib pre-loading.
- Data formats/schemas: `CodeBlock.param` is now `str | tuple[str, ...]` — `global/` blocks store a `(prefix, import_from)` tuple, `import-object` blocks store a 3-tuple.

## Usage Examples

**Bootstrap a new extension package from scratch (--init-* mode):**

```bash
# After building libmy_ffi_extension.dylib:
tvm-ffi-stubgen examples/packaging/python \
  --dlls examples/packaging/build/libmy_ffi_extension.dylib \
  --init-pypkg  my-ffi-extension \
  --init-lib    my_ffi_extension \
  --init-prefix "my_ffi_extension."
```

This generates `_ffi_api.py` and `__init__.py` under `examples/packaging/python/my_ffi_extension/`.

**Generated `_ffi_api.py` skeleton (produced by `--init-*` mode):**

```python
# tvm-ffi-stubgen(begin): import-section
from __future__ import annotations
from tvm_ffi import Object as _ffi_Object, init_ffi_api as _FFI_INIT_FUNC, register_object as _FFI_REG_OBJ
from tvm_ffi.libinfo import load_lib_module as _FFI_LOAD_LIB
from typing import TYPE_CHECKING
if TYPE_CHECKING:
    from tvm_ffi import Object
# tvm-ffi-stubgen(end)
LIB = _FFI_LOAD_LIB("my-ffi-extension", "my_ffi_extension")
# tvm-ffi-stubgen(begin): global/my_ffi_extension
# fmt: off
_FFI_INIT_FUNC("my_ffi_extension", __name__)
if TYPE_CHECKING:
    def raise_error(_0: str, /) -> None: ...
# fmt: on
# tvm-ffi-stubgen(end)
@_FFI_REG_OBJ("my_ffi_extension.IntPair")
class IntPair(_ffi_Object):
    # tvm-ffi-stubgen(begin): object/my_ffi_extension.IntPair
    # fmt: off
    a: int
    b: int
    if TYPE_CHECKING:
        def get_first(self, /) -> int: ...
    # fmt: on
    # tvm-ffi-stubgen(end)
__all__ = [
    # tvm-ffi-stubgen(begin): __all__
    "LIB", "IntPair", "raise_error",
    # tvm-ffi-stubgen(end)
]
```
