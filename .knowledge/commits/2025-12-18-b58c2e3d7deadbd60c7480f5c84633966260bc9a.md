# Add --init-* flags to tvm-ffi-stubgen for bootstrapping new FFI extension packages
## TL;DR
- Adds `--init-pypkg`, `--init-lib`, `--init-prefix` CLI flags to `tvm-ffi-stubgen` that auto-generate `_ffi_api.py` and `__init__.py` files for new FFI extension packages from registry metadata.
- Refactors the stubgen pipeline from 2 stages to 3: (1) collect ty-maps, (2) generate missing files via init mode, (3) process existing stub blocks. Extracts runtime metadata queries into a new `lib_state.py` module; deletes `analysis.py`.
- Introduces new directive types (`import-object`, `export`, `import-section`) and new data classes (`InitConfig`, `ImportItem`) that extend the stub generation framework.

## Key Exports

**Classes**:
- `InitConfig(pkg: str, shared_target: str, prefix: str)` -- Configuration for `--init-*` mode. `pkg` = Python package name (e.g., `my-ffi-extension`), `shared_target` = CMake target name (e.g., `my_ffi_extension`), `prefix` = registry prefix filter (e.g., `my_ffi_extension.`). Location: `python/tvm_ffi/stub/utils.py`.
- `ImportItem(name: str, type_checking_only: bool = False, alias: str | None = None)` -- Frozen dataclass representing an import statement. Auto-splits `name` into `mod`/`name` on `.`. Properties: `name_with_alias`, `full_name`. `__str__` renders as `from mod import name [as alias]`. Location: `python/tvm_ffi/stub/utils.py`.
- `ObjectInfo` -- Extended with `type_key: str | None` and `parent_type_key: str | None` fields; factory method renamed from `from_type_key(type_key)` to `from_type_info(type_info: TypeInfo)`.
- `FuncInfo` -- Factory method renamed from `from_global_name(name)` to `from_schema(name, schema, *, is_member=False)`.

**Functions (new module `lib_state.py`)**:
- `object_info_from_type_key(type_key: str) -> ObjectInfo` -- LRU-cached ObjectInfo factory.
- `collect_global_funcs() -> dict[str, list[FuncInfo]]` -- Moved from `analysis.py`; now uses `_func_info_from_global_name` helper.
- `collect_type_keys() -> dict[str, list[str]]` -- Queries `GetRegisteredTypeKeys()` to build prefix-to-type_key mapping.
- `toposort_objects(type_keys: list[str]) -> list[ObjectInfo]` -- Topological sort of ObjectInfo by inheritance hierarchy using heapq-based Kahn's algorithm.

**Functions (codegen.py, new)**:
- `generate_export(code: CodeBlock) -> None` -- Generates `from .{mod} import *` + `__all__` extension block for `export/{mod}` directives.
- `generate_ffi_api(code_blocks, ty_map, module_name, object_infos, init_cfg, is_root) -> str` -- Generates full `_ffi_api.py` content: import section, library loading (if root), global function block, object class definitions, `__all__`.
- `generate_init(code_blocks, module_name, submodule="_ffi_api") -> str` -- Generates `__init__.py` with `export/{submodule}` block.
- `generate_import_section(code, imports, opt)` -- Renamed from `generate_imports`; now takes `list[ImportItem]` instead of `set[str]`, separates concrete vs TYPE_CHECKING imports.

**Constants (consts.py, new)**:
- `STUB_IMPORT_OBJECT` = `# tvm-ffi-stubgen(import-object):`
- `STUB_BLOCK_KINDS` -- TypeAlias listing all valid block kinds including new `"import-section"`, `"import-object"`, `"export"`.
- `BUILTIN_TYPE_KEYS` -- Set of built-in type keys (e.g., `ffi.Object`, `ffi.String`, `ffi.Tensor`) excluded from init-mode generation.
- `PROMPT_IMPORT_SECTION`, `PROMPT_ALL_SECTION` -- Template strings for generated file scaffolding.
- `_prompt_globals(mod)`, `_prompt_class_def(type_name, type_key, parent_type_name)`, `_prompt_import_object(type_key, type_name)` -- Helper functions generating directive scaffolding strings.

**Directive renames**:
- `import` -> `import-section` (CodeBlock kind)
- `generate_imports` -> `generate_import_section` (function name)
- `TY_TO_IMPORT` dict merged into `TY_MAP_DEFAULTS`

**CLI flags (new)**:
- `--init-pypkg INIT_PYPKG` -- Python package name.
- `--init-lib INIT_LIB` -- CMake shared library target.
- `--init-prefix INIT_PREFIX` -- Registry prefix filter.
- `--imports IMPORTS` -- Semicolon-separated Python modules to pre-import.
- `--dlls` changed from `nargs="*"` to semicolon-separated string.

**Deleted**:
- `python/tvm_ffi/stub/analysis.py` -- Functionality moved to `lib_state.py`.

**CodeBlock changes**:
- `param` field type widened from `str` to `str | tuple[str, ...]`. For `global` blocks, param is now `(prefix, import_from)` tuple. For `import-object` blocks, param is a 3-tuple `(from, type_checking_only, alias)`.
- `global/prefix@import_from` syntax: the `@import_from` part specifies which module provides `init_ffi_api`.

**Testing module restructured**:
- `python/tvm_ffi/testing/` created as a proper package (was `python/tvm_ffi/testing.py`).
- `python/tvm_ffi/testing/_ffi_api.py` generated with full stub coverage for all `testing.*` global functions.
- `examples/packaging/python/my_ffi_extension/base.py` removed; its `_LIB` pattern replaced by `_FFI_LOAD_LIB()` in `_ffi_api.py`.

## Impact
- API: **Breaking** -- `analysis.py` deleted (import `collect_global_funcs` from `lib_state` instead). `generate_imports` renamed to `generate_import_section` with different signature. `ObjectInfo.from_type_key` renamed to `ObjectInfo.from_type_info`. `FuncInfo.from_global_name` renamed to `FuncInfo.from_schema`. `CodeBlock.param` type changed for `global` blocks. `--dlls` CLI flag changed from space-separated to semicolon-separated.
- Behavioral: The `import` block kind is renamed to `import-section`. Generated `_ffi_api.py` files now include `_FFI_INIT_FUNC("prefix", __name__)` inline instead of at module bottom. `__all__` sorting now groups UPPERCASE, CamelCase, and snake_case separately.
- Flags/config: Three new CLI flags (`--init-pypkg`, `--init-lib`, `--init-prefix`) must be provided together or not at all. New `--imports` flag.
- Data formats/schemas: New directive `# tvm-ffi-stubgen(import-object): <from>; <type_checking_only>; <alias>`. New block kinds `import-section`, `import-object`, `export`.

Design elements this commit produces:
- **Init-mode package generation**: A new workflow where `tvm-ffi-stubgen --init-*` bootstraps an entire Python FFI package from C++ registry metadata. This is the primary extension point for downstream packages.
- **ImportItem protocol**: A frozen dataclass that standardizes how imports are tracked, collected, and rendered across the stub pipeline.
- **3-stage pipeline**: Replaces the 2-stage pipeline. Stage 1: collect ty-maps. Stage 2: generate missing files (init mode). Stage 3: process existing stub blocks.
- **Topological object sorting**: `toposort_objects` ensures generated class definitions appear in inheritance order.
- **`import-object` directive**: Allows injecting custom imports (e.g., library loaders, parent classes) into generated files.
- **`export` directive**: Auto-generates `from .submod import * ; __all__.extend(...)` in `__init__.py`.

## Usage Examples

**Bootstrapping a new FFI extension package**:
```bash
tvm-ffi-stubgen examples/packaging/python \
  --dlls examples/packaging/build/libmy_ffi_extension.dylib \
  --init-pypkg  my-ffi-extension \
  --init-lib    my_ffi_extension \
  --init-prefix "my_ffi_extension."
```
This generates `my_ffi_extension/_ffi_api.py` (with import-section, global function stubs, object class stubs, `__all__`) and `my_ffi_extension/__init__.py` (with export block). Re-running is idempotent.

**Generated `_ffi_api.py` structure** (from `examples/packaging/python/my_ffi_extension/_ffi_api.py`):
```python
# tvm-ffi-stubgen(begin): import-section
from __future__ import annotations
from tvm_ffi import Object as _ffi_Object, init_ffi_api as _FFI_INIT_FUNC, register_object as _FFI_REG_OBJ
from tvm_ffi.libinfo import load_lib_module as _FFI_LOAD_LIB
# tvm-ffi-stubgen(end)
# tvm-ffi-stubgen(import-object): tvm_ffi.libinfo.load_lib_module;False;_FFI_LOAD_LIB
LIB = _FFI_LOAD_LIB("my-ffi-extension", "my_ffi_extension")
# tvm-ffi-stubgen(begin): global/my_ffi_extension
_FFI_INIT_FUNC("my_ffi_extension", __name__)
if TYPE_CHECKING:
    def raise_error(_0: str, /) -> None: ...
# tvm-ffi-stubgen(end)
```
