# Clean up libbacktrace build output and fix broken --host flag with target triple auto-detection
## TL;DR
- Suppresses verbose libbacktrace build output by enabling `LOG_CONFIGURE`, `LOG_BUILD`, `LOG_INSTALL`, and `LOG_OUTPUT_ON_FAILURE` in the `ExternalProject_Add` call.
- Replaces the broken `--host=${MACHINE_NAME}` configure flag (where `${MACHINE_NAME}` was an undefined CMake variable) with `--host=${TVM_FFI_MACHINE_NAME}` populated by a new `detect_target_triple()` CMake function.
- Adds `cmake/Utils/DetectTargetTriple.cmake`, a 303-line CMake module that determines the target machine triple via compiler introspection, platform-specific heuristics, and sensible fallbacks across Linux, macOS, Windows (MSVC/MinGW), iOS, Android, Emscripten, and FreeBSD.

## Key Exports
**Functions (CMake)**:
- `detect_target_triple(out_var)` -- Determines the target machine triple and stores it in `${out_var}`. Resolution order: (1) `CMAKE_{C,CXX}_COMPILER_TARGET`, (2) compiler `-dumpmachine`/`--print-target-triple`, (3) platform-specific construction (Emscripten, Android, iOS, MSVC, MinGW), (4) `CMAKE_LIBRARY_ARCHITECTURE` (Debian multiarch), (5) synthesized from `CMAKE_SYSTEM_PROCESSOR` + OS name.

**Variables (CMake)**:
- `TVM_FFI_MACHINE_NAME` -- Set by calling `detect_target_triple(TVM_FFI_MACHINE_NAME)` in `_libbacktrace_compile()`. Passed to libbacktrace's `./configure --host=` flag.

## Impact
- API: None (internal build system only).
- Behavioral: libbacktrace build logs are now redirected to files instead of stdout. On failure, logs are dumped automatically via `LOG_OUTPUT_ON_FAILURE`. The `--host` flag now receives a valid target triple instead of an empty string, which may fix cross-compilation scenarios where `./configure` needs an explicit host triple.
- Flags/config: None -- no new user-facing CMake options. `TVM_FFI_USE_LIBBACKTRACE` continues to gate the entire libbacktrace build.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **libbacktrace build integration** (`cmake/Utils/AddLibbacktrace.cmake`): The `_libbacktrace_compile()` function using CMake `ExternalProject_Add` to build libbacktrace as a static library. See `.knowledge/designs/0006-error-handling.md` for libbacktrace's role in traceback generation.
- **CMake build system** (`CMakeLists.txt`): Top-level CMake configuration that gates libbacktrace via `TVM_FFI_USE_LIBBACKTRACE`.

Design elements this commit produces:
- **Target triple detection** (`cmake/Utils/DetectTargetTriple.cmake`): A reusable CMake function for cross-platform target triple inference. Currently consumed only by `AddLibbacktrace.cmake`, but designed for general use.

## Usage Examples
```cmake
# In any CMake file that needs the target triple:
include(${CMAKE_SOURCE_DIR}/cmake/Utils/DetectTargetTriple.cmake)
detect_target_triple(MY_TARGET_TRIPLE)
message(STATUS "Building for: ${MY_TARGET_TRIPLE}")
# Example output: "x86_64-unknown-linux-gnu", "arm64-apple-darwin", "x86_64-pc-windows-msvc"
```
