# chore: Clean up libbacktrace-related outputs (#92)
## TL;DR
- Suppress noisy libbacktrace configure/build/install output by redirecting to log files (`LOG_CONFIGURE ON`, `LOG_BUILD ON`, `LOG_INSTALL ON`, `LOG_OUTPUT_ON_FAILURE ON`).
- Fix broken `--host=${MACHINE_NAME}` (undefined variable) by replacing it with `--host=${TVM_FFI_MACHINE_NAME}` populated by a new `detect_target_triple()` CMake function.
- Add `cmake/Utils/DetectTargetTriple.cmake`: a 303-line cascading target-triple detector supporting CMake compiler target, compiler `-dumpmachine`, Emscripten, Android NDK, iOS, Windows MSVC/MinGW, Debian multiarch, and POSIX fallback.

N/A -- infrastructure.

## Impact
- API: none
- Behavioral: libbacktrace `ExternalProject_Add` output is now silenced unless errors occur; `--host` flag now receives a valid target triple instead of an empty string
- Flags/config: none (existing `TVM_FFI_USE_LIBBACKTRACE` option unchanged)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- CMake `ExternalProject_Add` (external) for building vendored libbacktrace
- `TVM_FFI_USE_LIBBACKTRACE` option defined in `CMakeLists.txt` (see `0013-ffi-packaging-and-distribution`)

Design elements this commit produces:
- `detect_target_triple(out_var)` CMake function in `cmake/Utils/DetectTargetTriple.cmake` -- cascading target-triple auto-detection with 5 strategy tiers:
  1. `CMAKE_{C,CXX}_COMPILER_TARGET` (explicit cross-compile)
  2. Compiler `-dumpmachine` / `--print-target-triple`
  3. Platform-specific construction (Emscripten, Android, iOS, Windows MSVC, MinGW)
  4. `CMAKE_LIBRARY_ARCHITECTURE` (Debian multiarch hint)
  5. Synthesis from `CMAKE_SYSTEM_PROCESSOR` + OS name
