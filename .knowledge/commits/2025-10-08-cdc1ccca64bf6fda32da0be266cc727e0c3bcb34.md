# Suppress libbacktrace build noise and replace broken --host flag with auto-detected target triple
## TL;DR
- Redirects libbacktrace ExternalProject configure/build/install output to log files (via `LOG_CONFIGURE`, `LOG_BUILD`, `LOG_INSTALL` flags), only surfacing output on failure.
- Removes the broken `--host=${MACHINE_NAME}` configure argument (where `MACHINE_NAME` was never a valid CMake variable) and replaces it with `--host=${TVM_FFI_MACHINE_NAME}` populated by a new `detect_target_triple()` CMake function.
- Adds `cmake/Utils/DetectTargetTriple.cmake` (303 lines), a comprehensive target-triple detection utility supporting CMake compiler targets, compiler introspection (`-dumpmachine`), and platform-specific synthesis for Emscripten, Android, iOS, Windows/MSVC, MinGW, macOS, Linux, and FreeBSD.

## Key Exports
N/A -- infrastructure. The `detect_target_triple()` CMake function is a build-system utility, not a runtime API.

## Impact
- API: None
- Behavioral: libbacktrace builds are now silent on success (output saved to `<build-dir>/libbacktrace/src/project_libbacktrace-stamp/*.log`). On failure, output is dumped automatically via `LOG_OUTPUT_ON_FAILURE`. The `--host` flag now passes a valid target triple instead of an empty/undefined value.
- Flags/config: No new user-facing CMake options. The `TVM_FFI_MACHINE_NAME` variable is internal to the build.
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- CMake `ExternalProject_Add` pattern in `cmake/Utils/AddLibbacktrace.cmake` -- the existing mechanism for building vendored libbacktrace from a local source directory. See prior ledger entries: `2025-08-28-b245f1f9`, `2025-08-29-7d09d6ae`.
- `TVM_FFI_USE_LIBBACKTRACE` CMake option gating libbacktrace inclusion (`CMakeLists.txt`).

Design elements this commit produces:
- `detect_target_triple(out_var)` CMake function in `cmake/Utils/DetectTargetTriple.cmake` -- a reusable utility for any future CMake code that needs the host/target triple. Detection priority: (1) `CMAKE_<lang>_COMPILER_TARGET`, (2) compiler `-dumpmachine`/`--print-target-triple`, (3) platform-specific synthesis (Emscripten, Android, iOS, MSVC, MinGW), (4) `CMAKE_LIBRARY_ARCHITECTURE` multiarch hint, (5) fallback from `CMAKE_SYSTEM_PROCESSOR` + OS name.

## Usage Examples
None -- infrastructure change. The function is called internally:
```cmake
detect_target_triple(TVM_FFI_MACHINE_NAME)
message(STATUS "Detected target triple: ${TVM_FFI_MACHINE_NAME}")
```
