# Replace JIT-compiled C++ CUDA stream getter with native torch._C._cuda_getCurrentRawStream
## TL;DR
- Removes the `load_torch_get_current_cuda_stream()` function from `function.pxi`, which JIT-compiled a C++ extension via `torch.utils.cpp_extension.load_inline` to query the current CUDA stream using `c10::cuda::CUDAStream`.
- Replaces it with a single call to `torch._C._cuda_getCurrentRawStream(device_id)`, the same internal API used by PyTorch Dynamo and other PyTorch internals.
- Bumps package version from `0.1.0a6` to `0.1.0a7`.

## Key Exports
None. No public API surface is introduced or changed. The removed function (`load_torch_get_current_cuda_stream`) was an internal helper, and the replacement is an inline call to a torch private API.

## Impact
- API: none (internal implementation change only)
- Behavioral: The CUDA stream query path no longer requires JIT compilation of a C++ extension at first use. This eliminates a cold-start latency penalty (the `load_inline` call compiles C++ source with nvcc on first invocation) and removes the dependency on `torch.utils.cpp_extension` and a working CUDA compiler at runtime.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Cython `make_args` packed-function argument marshalling** ([0014-python-package.md](../designs/0014-python-package.md)): The CUDA stream query occurs inside `make_args()` in `function.pxi`, which converts Python arguments (including `torch.Tensor`) into packed `TVMFFIAny` values for FFI calls. When a torch CUDA tensor is the first CUDA argument, the stream is captured and passed via `ctx_stream`.
- **autodlpack torch-to-TVM conversion**: The `from_dlpack(torch.utils.dlpack.to_dlpack(arg))` path converts torch tensors to TVM NDArrays, and the stream capture ensures correct CUDA stream synchronization.
- **torch._C._cuda_getCurrentRawStream**: PyTorch's internal C API (exposed via the `torch._C` extension module) that returns the raw `cudaStream_t` as an integer for a given device. Used by Dynamo and other PyTorch internals. Not a public PyTorch API but stable in practice.

Design elements this commit produces:
- None (pure simplification).

## Usage Examples
None. This is a refactoring commit that simplifies internals without changing external behavior.

## Reflection

### Design docs to write or update
- `.knowledge/designs/NNNN-autodlpack.md`: The autodlpack conversion path (torch Tensor -> DLPack -> TVM NDArray) including CUDA stream capture semantics in `make_args()` remains undocumented. This commit changes the stream acquisition strategy from JIT-compiled C++ to `torch._C._cuda_getCurrentRawStream`. A design doc should cover: (1) when stream capture triggers (`is_cuda and ctx_dev_type[0] == -1`), (2) the stream lifetime assumption (valid for the duration of the FFI call), (3) the fallback behavior if torch is not available. A Mermaid sequence diagram of the torch.Tensor -> DLPack -> NDArray + stream capture flow would be valuable.
