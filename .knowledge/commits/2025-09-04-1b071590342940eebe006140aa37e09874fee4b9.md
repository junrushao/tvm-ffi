# Replace JIT C++ extension for torch CUDA stream query with native torch._C._cuda_getCurrentRawStream
## TL;DR
- Removes the `load_torch_get_current_cuda_stream()` function and the `torch_get_current_cuda_stream` module-level variable from `python/tvm_ffi/cython/function.pxi` (-38 lines). This function JIT-compiled a C++ extension via `torch.utils.cpp_extension.load_inline` to call `c10::cuda::getCurrentCUDAStream`, with a Python fallback via `torch.cuda.current_stream().cuda_stream`.
- Replaces the entire JIT/fallback mechanism with a single call to `torch._C._cuda_getCurrentRawStream(device_id)`, which is the same native C API that PyTorch Dynamo and other internal torch components use.
- Bumps package version from `0.1.0a6` to `0.1.0a7` in `pyproject.toml`.

## Impact
- API: No public Python API change. The JIT extension was an internal implementation detail of the Cython argument packing path for `torch.Tensor` arguments. Callers passing `torch.Tensor` to FFI functions see no behavioral difference.
- Flags/config: None.
- Data formats/schemas: None.
- **Dependency reduction**: Eliminates the runtime dependency on `torch.utils.cpp_extension.load_inline`, which requires a working C++ compiler, CUDA toolkit headers (`c10/cuda/CUDAStream.h`), and triggers JIT compilation on first invocation. The replacement `torch._C._cuda_getCurrentRawStream` is always available when `torch` is installed with CUDA support, with no compilation step.
- **Startup improvement**: The old path had a one-time JIT compilation cost (several seconds) and cached compilation artifacts on disk. The new path has zero startup overhead.

## Design Elements

Design elements this commit **consumes**:

- **Python bindings / Cython argument packing** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The change is within `make_args` in `function.pxi`, specifically the `torch.Tensor` handling branch (priority item 3 in the argument packing order). When a `torch.Tensor` on a CUDA device is detected, the code queries the current CUDA stream, stores it via `ctx_stream[0]`, and the outer `FuncCall` wrapper calls `TVMFFIEnvSetStream` before the C++ function invocation. The invariant that the FFI thread-local stream context is synchronized with PyTorch's current stream is preserved.
- **Thread-local stream context** ([`.knowledge/ADRs/0020-thread-local-stream-context.md`](../ADRs/0020-thread-local-stream-context.md)): The stream value obtained from `torch._C._cuda_getCurrentRawStream` is stored as `TVMFFIStreamHandle` (a `void*`) in the FFI's per-thread stream table via `TVMFFIEnvSetStream`. The new API returns the same raw `cudaStream_t` pointer that the JIT extension was extracting.
- **Extra API tier** ([`.knowledge/designs/0011-extra-api-tier.md`](../designs/0011-extra-api-tier.md)): The stream context APIs (`TVMFFIEnvSetStream`/`TVMFFIEnvGetCurrentStream`) that receive the queried stream handle are part of the extra tier.

Design elements this commit **produces**:

- None. This is a simplification/refactoring of an internal implementation detail. No new abstractions, APIs, or invariants are introduced.

## Key Implementations

### Stream query replacement (`python/tvm_ffi/cython/function.pxi`)

**Before** (in `make_args`, torch.Tensor CUDA branch):
```python
if torch_get_current_cuda_stream is None:
    torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
temp_ptr = torch_get_current_cuda_stream(temp_dltensor.device.device_id)
```

**After**:
```python
# This is an API that dynamo and other uses to get the raw stream from torch
temp_ptr = torch._C._cuda_getCurrentRawStream(temp_dltensor.device.device_id)
```

Key observations:
- **Invariant preserved**: The return value semantics are identical -- both paths return the raw `cudaStream_t` as a Python integer (or 0 for the default stream). The downstream assignment `ctx_stream[0] = <TVMFFIStreamHandle>temp_ptr` is unchanged.
- **Lazy-init pattern eliminated**: The old code used a module-level `torch_get_current_cuda_stream` variable with lazy initialization (check-then-set on first CUDA tensor encounter). The replacement is a direct call with no caching or initialization needed.
- **Error surface simplified**: The old `load_torch_get_current_cuda_stream` could silently fall back to the slower `torch.cuda.current_stream().cuda_stream` Python path if `cpp_extension.load_inline` failed (e.g., missing compiler, missing CUDA headers). The new path has a single code path that either works (torch with CUDA) or raises `AttributeError` (torch without CUDA). This makes failures more deterministic.
- **`torch._C._cuda_getCurrentRawStream` stability**: This is an internal torch C API (note the `_C` and underscore prefix), but it is the same API used by `torch.compiler` (Dynamo) and other core torch components, making it a de-facto stable interface despite the private naming convention.

### Version bump (`pyproject.toml`)

Package version bumped from `0.1.0a6` to `0.1.0a7`. This is a standard pre-release version increment accompanying the behavioral change.

### ADRs to write

- **`.knowledge/ADRs/0023-torch-internal-api-for-stream-query.md`**: Record the decision to use `torch._C._cuda_getCurrentRawStream` (a private/internal torch API) instead of: (1) JIT C++ extension via `load_inline` (eliminated by this commit -- too heavy, requires compiler and CUDA headers at runtime), (2) `torch.cuda.current_stream().cuda_stream` (the original fallback -- higher Python overhead per call), (3) `torch.cuda.current_stream().stream_id` (different semantics -- returns stream ID not raw pointer). Trade-off: reliance on an underscore-prefixed internal API for better performance and zero startup cost, mitigated by the fact that Dynamo uses the same API.
