# Replace JIT-compiled CUDA stream getter with torch native C API
## TL;DR
- Removes `load_torch_get_current_cuda_stream()` which JIT-compiled a C++ extension via `torch.utils.cpp_extension.load_inline` to query CUDA streams.
- Replaces it with a direct call to `torch._C._cuda_getCurrentRawStream(device_id)`, the same native torch C API used by dynamo.
- Bumps package version from `0.1.0a6` to `0.1.0a7`.

## Key Exports

None -- this commit removes internal implementation (`load_torch_get_current_cuda_stream` function and `torch_get_current_cuda_stream` module-level sentinel) and replaces with an inline call. No new public API is introduced.

The behavioral change in `make_args` (function.pxi) is:

```python
# Before (removed):
# torch_get_current_cuda_stream: Optional[Callable] = None  # module-level sentinel
# def load_torch_get_current_cuda_stream() -> Callable[[int], int]:
#     """JIT-compile C++ extension via torch.utils.cpp_extension.load_inline"""
#     ...  # compiles at::cuda::getCurrentCUDAStream wrapper
#     # Fallback: torch.cuda.current_stream(device_id).cuda_stream
#
# In make_args:
#   if torch_get_current_cuda_stream is None:
#       torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
#   stream = torch_get_current_cuda_stream(device_id)

# After (new):
# In make_args:
#   stream = torch._C._cuda_getCurrentRawStream(device_id)
# Interacts with: torch internal C API (same API dynamo uses)
# Invariant: device_id must be a valid CUDA device index
```

## Impact
- API: None -- `load_torch_get_current_cuda_stream` was internal to function.pxi, not importable.
- Behavioral: Eliminates JIT compilation overhead on first CUDA tensor encounter. The old path invoked `torch.utils.cpp_extension.load_inline` which compiles C++ code, writes to disk cache, and links a shared library. The new path calls torch's native C API directly with zero startup cost.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `make_args` argument packing in function.pxi ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md)) -- the DLPack tensor branch that captures CUDA stream context.
- Stream context system `ctx_stream` / `TVMFFIEnvSetStream` ([0011-ffi-module-system](../design-records/0011-ffi-module-system.md)) -- the stream handle obtained from torch is passed downstream via `ctx_stream[0]`.

Design elements this commit produces:
- None -- removes internal implementation, does not introduce new design elements.

## Usage Examples
Before/after pattern showing the change:

```python
# Before: first CUDA tensor triggers JIT compilation (slow, writes to disk)
import tvm_ffi
func(cuda_tensor)  # first call: ~seconds of JIT compile overhead
func(cuda_tensor)  # subsequent: fast (cached .so)

# After: torch native C API, no JIT compilation needed
import tvm_ffi
func(cuda_tensor)  # first call: no overhead, direct C API call
func(cuda_tensor)  # subsequent: same
```
