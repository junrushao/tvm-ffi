# Replace JIT-compiled torch stream getter with native torch._C._cuda_getCurrentRawStream
## TL;DR
- Removes `load_torch_get_current_cuda_stream()` and its `torch.utils.cpp_extension.load_inline` JIT compilation path, replacing it with a single call to `torch._C._cuda_getCurrentRawStream(device_id)`.
- Eliminates the lazy-initialized `torch_get_current_cuda_stream` module-level variable and its on-first-use initialization guard.
- Bumps package version from `0.1.0a6` to `0.1.0a7`.

## Key Exports
None -- this commit removes code and simplifies an internal call site. No new public API surface is introduced.

The behavioral change is internal to `make_args` in `function.pxi`:

```python
# Before (removed):
# torch_get_current_cuda_stream: Optional[Callable] = None  # module-level
#
# def load_torch_get_current_cuda_stream() -> Callable:
#     """JIT-compiles C++ extension via load_inline for fast CUDA stream ID retrieval.
#     Falls back to torch.cuda.current_stream(device_id).cuda_stream on failure."""
#     ...
#
# In make_args:
#     if torch_get_current_cuda_stream is None:
#         torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
#     temp_ptr = torch_get_current_cuda_stream(device_id)

# After (current):
# In make_args:
#     temp_ptr = torch._C._cuda_getCurrentRawStream(device_id)
#     # Interacts with: torch internal C API, same API used by torch.compile/dynamo
#     # Invariant: torch must be imported and CUDA available
```

## Impact
- API: none -- internal implementation change only
- Behavioral: CUDA stream retrieval no longer triggers JIT compilation of a C++ extension on first CUDA tensor encounter. The `torch._C._cuda_getCurrentRawStream` API is the same one used by torch dynamo/compile, making it a stable internal torch API.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **make_args packed argument conversion** (`python/tvm_ffi/cython/function.pxi`) -- the CUDA stream retrieval path within `make_args` that captures the current CUDA stream when a torch tensor is the first CUDA argument. See `0012-python-bindings.md`.
- **StreamContext** (`0011-module-system.md`) -- the stream handle obtained from torch is stored via `ctx_stream[0]` for the FFI call, feeding into the thread-local `StreamContext` system.
- **torch._C._cuda_getCurrentRawStream** (external, torch internal C API) -- native torch API returning raw `cudaStream_t` as int, used by dynamo and other torch internals.

Design elements this commit produces:
- None -- purely removes complexity.

## Usage Examples
Before/after pattern showing the refactored CUDA stream retrieval:

```python
# Before: JIT-compiled C++ extension with fallback
# First CUDA tensor call triggers torch.utils.cpp_extension.load_inline(),
# which compiles a C++ snippet calling at::cuda::getCurrentCUDAStream().
# This adds seconds of latency on first call and requires a C++ compiler at runtime.

# After: Direct call to torch native C API
stream_ptr = torch._C._cuda_getCurrentRawStream(device_id)
# No JIT compilation, no C++ compiler requirement at runtime.
# Same API that torch.compile/dynamo uses internally.
```
