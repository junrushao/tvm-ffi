# Replace JIT-compiled CUDA stream getter with torch native C API

## TL;DR
- Removes `load_torch_get_current_cuda_stream()`, which JIT-compiled a C++ extension via `torch.utils.cpp_extension.load_inline` to call `at::cuda::getCurrentCUDAStream`. Removes the module-level `torch_get_current_cuda_stream` lazy singleton.
- Replaces it with a direct call to `torch._C._cuda_getCurrentRawStream(device_id)`, the same internal API used by torch dynamo.
- Bumps package version from `0.1.0a6` to `0.1.0a7`.

## Key Exports
None. No new public API surface is introduced. The change is internal to the `make_args` implementation in `function.pxi`.

## Impact
- API: none -- no public API changes.
- ABI: none -- Cython internals only.
- Behavioral: Eliminates a JIT compilation step (via `load_inline`) on first CUDA tensor argument, reducing startup latency. The raw CUDA stream pointer returned is semantically identical.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Python binding value marshaling** (`.knowledge/designs/0014-python-bindings.md`, `make_args` in `function.pxi`) -- the CUDA stream capture is part of the torch.Tensor branch in the `make_args` dispatch chain.
- **CUDA stream context protocol** (`.knowledge/designs/function-system.md`) -- `make_args` sets `ctx_stream` for later use by `TVMFFIEnvSetStream` during function calls.
- **torch._C._cuda_getCurrentRawStream** -- undocumented internal torch C API also used by dynamo for raw CUDA stream access.

Design elements this commit produces:
- None. This is a simplification of an existing mechanism, not a new design element.

Design elements this commit removes:
- **`load_torch_get_current_cuda_stream()`** -- the JIT-compiled C++ extension pattern via `torch.utils.cpp_extension.load_inline` that called `at::cuda::getCurrentCUDAStream` is fully removed.
- **`torch_get_current_cuda_stream`** -- the module-level lazy singleton variable is removed.

## Usage Examples
None. The change is internal to `function.pxi`. The user-facing behavior is identical: passing `torch.Tensor` arguments to FFI functions still automatically captures the CUDA stream. The before/after at the implementation level:

**Before** (removed):
```python
# Module-level lazy singleton
torch_get_current_cuda_stream = None

# In make_args torch.Tensor branch:
if torch_get_current_cuda_stream is None:
    torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
temp_ptr = torch_get_current_cuda_stream(device_id)
```

**After**:
```python
# In make_args torch.Tensor branch:
temp_ptr = torch._C._cuda_getCurrentRawStream(device_id)
```
