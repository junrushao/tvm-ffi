# Replace JIT-compiled torch CUDA stream getter with native torch._C._cuda_getCurrentRawStream API

## TL;DR
- Removes the entire `load_torch_get_current_cuda_stream()` function and its module-level `torch_get_current_cuda_stream` variable from `function.pxi`, eliminating the JIT-compiled C++ extension that used `torch.utils.cpp_extension.load_inline` to call `at::cuda::getCurrentCUDAStream`.
- Replaces it with a single call to `torch._C._cuda_getCurrentRawStream(device_id)`, the same internal API used by torch dynamo, removing the need for a C++ compiler at runtime.
- Bumps package version from `0.1.0a6` to `0.1.0a7`.

## Key Exports

No new public API is introduced. The change is internal to `make_args` in the Cython layer.

```python
# In make_args (function.pxi), the CUDA stream retrieval path changed:

# OLD (removed):
# torch_get_current_cuda_stream: Optional[Callable[[int], int]] = None  # module-level lazy cache
# def load_torch_get_current_cuda_stream() -> Callable[[int], int]:
#     """JIT-compile a C++ extension via torch.utils.cpp_extension.load_inline
#     that calls at::cuda::getCurrentCUDAStream(), falling back to
#     torch.cuda.current_stream().cuda_stream on failure."""
#     ...

# NEW (single line):
temp_ptr = torch._C._cuda_getCurrentRawStream(device_id)
# Interacts with: torch internal C API (same as dynamo uses)
# Invariant: device_id must be a valid CUDA device index
# Invariant: returns a raw cudaStream_t as int64; default stream returns 0
```

## Impact
- API: none -- no public API changed
- Behavioral: CUDA stream retrieval no longer requires a C++ compiler at runtime. The previous `load_inline` approach would JIT-compile a C++ snippet on first use (or fall back to slower `torch.cuda.current_stream`). The new approach always uses `torch._C._cuda_getCurrentRawStream`, which is a direct binding to the torch C runtime. This removes the JIT compilation latency on first CUDA tensor encounter and eliminates the `torch.utils.cpp_extension` dependency path.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **make_args torch.Tensor CUDA stream propagation** (`.knowledge/designs/0012-python-bindings.md`, line 284): The core mechanism for recording CUDA stream context when packing torch tensors. This commit changes the stream retrieval implementation but not the propagation protocol.
- **Lazy torch stream loading pattern** (introduced in `4523a83`, documented in `.knowledge/commits/2025-08-30-4523a834e6d7331870230873365a895ce94da050.md`): The lazy-loading pattern is now entirely removed -- no caching or lazy init needed since `torch._C._cuda_getCurrentRawStream` is always available when torch is imported.

Design elements this commit produces:
- None -- this is a simplification, not an addition. The stream propagation protocol is unchanged.

## Usage Examples

**Before/after pattern for CUDA stream retrieval in make_args:**

```python
# BEFORE (load_inline JIT + lazy caching):
# 1. First CUDA tensor encounter triggers JIT compilation of C++ snippet
# 2. Compilation failure falls back to torch.cuda.current_stream().cuda_stream
# 3. Result cached in module-level torch_get_current_cuda_stream variable
torch_get_current_cuda_stream = None  # lazy
# ...
if torch_get_current_cuda_stream is None:
    torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
stream_ptr = torch_get_current_cuda_stream(device_id)

# AFTER (direct torch C API):
# Single call, no JIT, no caching, no fallback needed
stream_ptr = torch._C._cuda_getCurrentRawStream(device_id)
```
