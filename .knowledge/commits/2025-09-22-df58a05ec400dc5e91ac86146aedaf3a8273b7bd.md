# Make Array[T] and Map[K, V] parameterizable with generic type variables

## TL;DR
- Makes `Array` parameterizable as `Array[T]` (inheriting from `Sequence[T]`) and `Map` parameterizable as `Map[K, V]` (inheriting from `Mapping[K, V]`) in `container.py`, enabling standard Python generic subscript syntax.
- Introduces module-level `TypeVar`s (`T`, `K`, `V`, `_DefaultT`) and adds comprehensive type annotations (`overload` signatures, `SupportsIndex`, `cast`) across `Array`, `Map`, `KeysView`, `ValuesView`, and `ItemsView`.
- Refactors `getitem_helper` to use `operator.index()` (matching `list` behavior) and `slice.indices()` for correct slice normalization.
- Changes `Array.__getitem__` for slices to return a new `Array[T]` instead of a plain `list`, and adds an explicit `__iter__` method.
- Refactors view classes (`KeysView`, `ValuesView`, `ItemsView`) to inherit from `collections.abc` generic bases (`KeysViewBase[K]`, `ValuesViewBase[V]`, `ItemsViewBase[K, V]`), replaces infinite `while True` / early-return iteration with bounded `for _ in range(size)` loops, and adds `ItemsView.__contains__` for correctness.
- Adds `overload` signatures to `Map.get` with `_DefaultT` for precise default-value typing, and changes implementation from `key in self` check to `try/except KeyError`.
- Updates `testing.py` to annotate `v_map: Map[Any, Any]` and `v_array: Array[Any]` (previously unparameterized).

## Key Exports
No new public classes or functions. The existing `Array` and `Map` classes gain generic parameterization:

| Symbol | Before | After |
|--------|--------|-------|
| `Array` | `class Array(Object, Sequence)` | `class Array(Object, Sequence[T])` |
| `Map` | `class Map(Object, Mapping)` | `class Map(Object, Mapping[K, V])` |
| `Array.__getitem__(slice)` | Returns `list` | Returns `Array[T]` |
| `Array.__iter__` | Inherited from `Sequence` mixin | Explicit generator yielding `T` |
| `Map.get` | Single signature `(key, default=None) -> Any` | Overloaded `(key) -> V | None` and `(key, default: V | _DefaultT) -> V | _DefaultT` |
| `Map.__contains__` | `(k: Any) -> bool` | `(k: object) -> bool` (matches `Mapping` protocol) |
| `ItemsView.__contains__` | Not implemented | `(item: object) -> bool` with key lookup |
| `getitem_helper` | `idx: int | slice` | `idx: SupportsIndex | slice` with `operator.index()` |
| `KeysView` | `KeysView(collections.abc.KeysView)` | `KeysView(KeysViewBase[K])` |
| `ValuesView` | `ValuesView(collections.abc.ValuesView)` | `ValuesView(ValuesViewBase[V])` |
| `ItemsView` | `ItemsView(collections.abc.ItemsView)` | `ItemsView(ItemsViewBase[K, V])` |

New module-level names: `T = TypeVar("T")`, `K = TypeVar("K")`, `V = TypeVar("V")`, `_DefaultT = TypeVar("_DefaultT")`.

## Impact
- API: `Array[T]` and `Map[K, V]` are now valid subscript expressions at both runtime and type-checking time. Static type checkers can now infer element types from parameterized containers.
- ABI: None -- purely Python-level change.
- Behavioral changes:
  - `Array.__getitem__(slice)` now returns an `Array` instead of a `list`. This is a behavioral change for callers that relied on receiving a plain list from slicing.
  - `getitem_helper` now uses `operator.index(idx)` instead of raw integer comparison, matching `list` behavior for objects implementing `__index__`.
  - `getitem_helper` uses `slice.indices(length)` instead of manual start/stop/step normalization, which correctly handles edge cases.
  - `Map.get` uses `try/except KeyError` instead of `key in self` + `self[key]`, avoiding double lookup.
  - View iteration uses bounded `for _ in range(size)` instead of `while True` with early return for empty maps, which is simpler and avoids creating the functor for empty maps.
  - `ItemsView.__contains__` is now implemented (previously inherited a default that iterated all items for O(n) containment; new version does O(1) key lookup).
  - `ItemsView` uses `_backend_map` (with underscore) instead of `backend_map` for the attribute name, consistent with `KeysView` and `ValuesView`.
- Flags/config: None.
- Data formats/schemas: None.

Design elements this commit produces:
- **Generic container parameterization**: `Array` and `Map` are now generic types that accept type parameters (`Array[T]`, `Map[K, V]`), enabling static type inference of element types. This extends the `collections.abc.Sequence[T]` / `Mapping[K, V]` generic protocol to the FFI container wrappers.
- **SupportsIndex protocol for indexing**: `getitem_helper` accepts any object implementing `__index__()` (via `operator.index`), matching the standard `list` indexing protocol.

## Usage Examples
```python
from tvm_ffi.container import Array, Map

# Type checkers now understand element types
arr: Array[int] = Array([1, 2, 3])
x: int = arr[0]            # inferred as int (was Any)
sub: Array[int] = arr[1:]  # returns Array[int], not list

m: Map[str, int] = Map({"a": 1, "b": 2})
v: int | None = m.get("a")       # inferred as int | None
v2: int | str = m.get("c", "default")  # inferred as int | str via _DefaultT
```
