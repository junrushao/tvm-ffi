# Make Array[T] and Map[K, V] parameterizable generics in Python
## TL;DR
- Makes `Array` and `Map` (and their view helpers `KeysView`, `ValuesView`, `ItemsView`) proper parameterizable generics by inheriting from `Sequence[T]` and `Mapping[K, V]` rather than bare `collections.abc.Sequence`/`Mapping`.
- Adds `@overload` signatures for `Array.__getitem__` (returns `T` for index, `Array[T]` for slice) and `Map.get` (with `_DefaultT` for the default parameter).
- Fixes several behavioral issues: slice returns `Array[T]` instead of `list`, `getitem_helper` uses `operator.index()` for `SupportsIndex` protocol, view iterators use bounded `for _ in range(size)` loops instead of `while True`.

## Key Exports

**TypeVars** (module-level, `container.py`):
```python
T = TypeVar("T")
K = TypeVar("K")
V = TypeVar("V")
_DefaultT = TypeVar("_DefaultT")
```

**`Array[T]`** (parameterized, registered `"ffi.Array"`):
```python
class Array(core.Object, Sequence[T]):
    def __init__(self, input_list: Sequence[T]) -> None: ...
    @overload
    def __getitem__(self, idx: SupportsIndex, /) -> T: ...
    @overload
    def __getitem__(self, idx: slice, /) -> Array[T]: ...
    def __getitem__(self, idx: SupportsIndex | slice, /) -> T | Array[T]: ...
    def __len__(self) -> int: ...
    def __iter__(self) -> Iterator[T]: ...  # new explicit iterator
```

**`Map[K, V]`** (parameterized, registered `"ffi.Map"`):
```python
class Map(core.Object, Mapping[K, V]):
    def __init__(self, input_dict: Mapping[K, V]) -> None: ...
    def __getitem__(self, k: K) -> V: ...
    def __contains__(self, k: object) -> bool: ...
    def keys(self) -> KeysView[K]: ...
    def values(self) -> ValuesView[V]: ...
    def items(self) -> ItemsView[K, V]: ...
    def __len__(self) -> int: ...
    def __iter__(self) -> Iterator[K]: ...
    @overload
    def get(self, key: K) -> V | None: ...
    @overload
    def get(self, key: K, default: V | _DefaultT) -> V | _DefaultT: ...
    def get(self, key: K, default: V | _DefaultT | None = None) -> V | _DefaultT | None: ...
```

**View classes** (parameterized):
```python
class KeysView(KeysViewBase[K]):
    def __iter__(self) -> Iterator[K]: ...
    def __contains__(self, k: object) -> bool: ...

class ValuesView(ValuesViewBase[V]):
    def __iter__(self) -> Iterator[V]: ...

class ItemsView(ItemsViewBase[K, V]):
    def __iter__(self) -> Iterator[tuple[K, V]]: ...
    def __contains__(self, item: object) -> bool: ...  # new
```

**`getitem_helper`** (signature updated):
```python
def getitem_helper(
    obj: Any,
    elem_getter: Callable[[Any, int], T],
    length: int,
    idx: SupportsIndex | slice,
) -> T | list[T]: ...
```

## Impact
- API: `Array.__getitem__` with a slice now returns `Array[T]` instead of `list`. Callers that relied on getting a plain list from `arr[start:stop]` will now get an `Array`. Type checkers will now infer element types from `Array[T]` and `Map[K, V]` subscriptions.
- Behavioral: `getitem_helper` now uses `operator.index()` which accepts any `SupportsIndex` object (e.g., numpy int types), matching `list` behavior. Slice handling delegates to `slice.indices(length)` which correctly handles edge cases the manual implementation may have missed. `Map.get` uses try/except instead of double-lookup (`key in self` then `self[key]`). `ItemsView.backend_map` attribute renamed to `_backend_map` (private).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system** (`.knowledge/designs/0003-object-system.md`) -- `Array` and `Map` inherit from `core.Object`
- **Containers** (`.knowledge/designs/0008-containers.md`) -- Python wrappers for `ffi.Array` and `ffi.Map`
- **Python package** (`.knowledge/designs/0014-python-package.md`) -- `register_object`, `_ffi_api` call convention

Design elements this commit produces:
- **Parameterizable Python containers** -- `Array[T]`, `Map[K, V]` now support generic subscript syntax, enabling static type checkers (mypy, pyright) to infer element types through FFI container operations. This is a new convention: all container type annotations in the codebase should use parameterized forms (e.g., `Array[Any]` instead of bare `Array`).

## Usage Examples

Parameterized container usage with type checking:
```python
import tvm_ffi
from tvm_ffi import Array, Map

# Type checkers infer element types
arr: Array[int] = tvm_ffi.convert([1, 2, 3])
x: int = arr[0]               # T = int
sub: Array[int] = arr[0:2]    # slice returns Array[T], not list

m: Map[str, int] = tvm_ffi.convert({"a": 1, "b": 2})
v: int = m["a"]                # V = int
keys: KeysView[str] = m.keys()

# Map.get with default type
val: int | str = m.get("c", "default")  # _DefaultT = str
```

In dataclass-style definitions (as updated in `testing.py`):
```python
class TestObjectDerived(TestObjectBase):
    v_map: Map[Any, Any]    # was: Map (bare)
    v_array: Array[Any]     # was: Array (bare)
```
