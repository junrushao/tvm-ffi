# Make Python Array[T] and Map[K, V] fully parameterizable generics

## TL;DR
- `Array` now inherits `Sequence[T]` and `Map` inherits `Mapping[K, V]`, enabling `Array[str]`, `Map[str, int]` subscript syntax at the Python type-checker level.
- `Array.__getitem__` gains proper `@overload` stubs: integer index returns `T`, slice returns `Array[T]` (previously returned `list[T]`).
- `getitem_helper` and iteration/view internals hardened with `operator.index()`, `slice.indices()`, explicit `__iter__`, and `ItemsView.__contains__`.

## Impact
- API: Additive type parameterization; `Array[str]`, `Map[str, int]` now valid subscripts at runtime (via `Sequence.__class_getitem__`). Existing unparameterized `Array` / `Map` usage continues to work unchanged.
- Behavioral: `Array.__getitem__(slice)` now returns `Array[T]` instead of a plain `list`. Code that checked `isinstance(arr[0:2], list)` will now get `False` — this is a subtle behavioral change for slice callers.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Array` / `Map` C++ container objects (see [0006-ffi-containers.md](../design-records/0006-ffi-containers.md)) — Python wrapper classes extend these.
- `_ffi_api.ArrayGetItem`, `_ffi_api.ArraySize`, `_ffi_api.MapGetItem`, `_ffi_api.MapCount`, `_ffi_api.MapSize`, `_ffi_api.MapForwardIterFunctor` — C++ global functions exposed via Cython.
- `core.Object` — Cython base class that all Python FFI types extend (see [0012-ffi-python-package.md](../design-records/0012-ffi-python-package.md)).

Design elements this commit produces:
- **Python `Array[T]` generic** — `Array` as a fully parameterizable `Sequence[T]` with typed `__getitem__` overloads and `__iter__`.
- **Python `Map[K, V]` generic** — `Map` as a fully parameterizable `Mapping[K, V]` with typed view classes (`KeysView[K]`, `ValuesView[V]`, `ItemsView[K, V]`) and typed `get()` overloads.
- **`ItemsView.__contains__`** — previously missing; now correctly validates tuple-of-2 and does map key lookup.

## Usage Examples

**Context**: Parameterized usage now passes type-checker scrutiny; runtime behavior unchanged.
```python
import tvm_ffi

# Array[T]: subscript syntax + typed iteration
arr: tvm_ffi.Array[str] = tvm_ffi.Array(["a", "b", "c"])
first: str = arr[0]          # __getitem__(int) -> T
sub: tvm_ffi.Array[str] = arr[0:2]  # __getitem__(slice) -> Array[T]  (was list)
for s in arr:                # __iter__ -> Iterator[str]
    print(s)

# Map[K, V]: subscript syntax + typed views
m: tvm_ffi.Map[str, int] = tvm_ffi.Map({"x": 1, "y": 2})
v: int = m["x"]             # __getitem__ -> V
default: int = m.get("z", 0)  # get(key, default: V | _DefaultT) -> V | _DefaultT
keys: tvm_ffi.container.KeysView[str] = m.keys()
("x", 1) in m.items()       # ItemsView.__contains__ now implemented

# testing.py style: use Map[Any, Any] / Array[Any] for untyped reflection fields

```
