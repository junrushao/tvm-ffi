# Make Python Array and Map generic with proper type parameterization
## TL;DR
- `Array` and `Map` Python classes are now generic: `Array(Sequence[T])` and `Map(Mapping[K, V])`, enabling type checkers to propagate element types through FFI container usage.
- View classes (`KeysView`, `ValuesView`, `ItemsView`) are parameterized and use `typing.cast` for typed iteration; `__getitem__`, `__iter__`, `get`, and `__contains__` signatures updated to use type variables.
- `getitem_helper` improved: accepts `SupportsIndex` (not just `int`), uses `operator.index()` for proper `__index__` protocol support, and delegates slice normalization to `slice.indices()`. `Array.__getitem__` with slice now returns `Array[T]` instead of `list`.

## Impact
- API: `Array.__getitem__` with a slice now returns `Array[T]` instead of `list`; `__contains__` parameters narrowed from `Any` to `object` (compatible). All type annotations are narrowed but remain runtime-compatible with existing unparameterized usage.
- Behavioral: `Map.get` uses try/except instead of `key in self` + `self[key]` (eliminates double lookup). `getitem_helper` uses `operator.index()` for `__index__` protocol compliance and `slice.indices()` for correct negative-index handling. `ItemsView.__contains__` is now implemented (was inherited default that didn't work with FFI maps). Iteration in views uses `for _ in range(size)` with break, replacing fragile `while True` loop.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Container types** (0006-containers): `Array` and `Map` Python classes wrapping C++ `ArrayObj`/`MapObj` via `_ffi_api.*` functions (`ArrayGetItem`, `ArraySize`, `MapGetItem`, `MapCount`, `MapSize`, `MapForwardIterFunctor`)
- **Object system** (0002-object-system): `core.Object` base class for `Array` and `Map`
- **Python bindings** (0012-python-bindings): `register_object` decorator, `__init_handle_by_constructor__` protocol

Design elements this commit produces:
- **Generic parameterization pattern**: `Array[T]` and `Map[K, V]` with `TypeVar` + `typing.overload` for precise static typing of FFI container operations in Python. This is the canonical pattern for making FFI containers work with type checkers (mypy, pyright).
- **`ItemsView.__contains__`**: Proper `(key, value)` membership test that queries the backing map instead of relying on the ABC default (which calls `__iter__` and is O(n)).

## Usage Examples

Parameterized usage with type checkers:
```python
from tvm_ffi.container import Array, Map

# Type checker infers arr has type Array[int]
arr: Array[int] = Array([1, 2, 3])
x: int = arr[0]              # T resolved to int
sub: Array[int] = arr[0:2]   # slice returns Array[T], not list

m: Map[str, int] = Map({"a": 1, "b": 2})
v: int = m["a"]              # V resolved to int
keys: KeysView[str] = m.keys()

# get() with default preserves union type
val: int | None = m.get("missing")
val2: int | str = m.get("missing", "default")
```
