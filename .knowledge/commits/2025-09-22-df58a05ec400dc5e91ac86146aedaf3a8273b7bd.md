# Add generic type parameterization to Python Array[T] and Map[K, V], fixing Sequence/Mapping ABC conformance and hardening iteration/getitem protocol.

## TL;DR
- `Array` now extends `Sequence[T]` and `Map` extends `Mapping[K, V]` with proper `TypeVar` parameters; all view classes (`KeysView`, `ValuesView`, `ItemsView`) are similarly parameterized.
- `Array.__getitem__` gains `@overload` for `SupportsIndex`→`T` vs `slice`→`Array[T]`; slicing now returns a new `Array[T]` instead of a plain `list`. `operator.index()` replaces direct `int` cast for strict `SupportsIndex` protocol; `slice.indices(length)` replaces manual negative-index arithmetic.
- `Map.get` gains two `@overload` signatures; `Map.get` uses `try/except KeyError` (avoids double lookup); `ItemsView.__contains__` is now implemented (was missing in ABC).

## Impact
- API: `Array.__getitem__(slice)` now returns `Array[T]` instead of `list`. Downstream code that relied on `isinstance(arr[1:], list)` will break at runtime.
- Behavioral: `Map.get` now performs a single key lookup instead of two; semantically equivalent but eliminates a race-like double-lookup pattern. `getitem_helper` slice path uses `idx.indices(length)` — handles negative stop values correctly (previously could produce wrong ranges for `arr[-2:]`).
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**Using parameterized Array and Map in Python:**

```python
from tvm_ffi import Array, Map

# Array[int] — explicit type parameter (runtime: still stores Any internally)
arr: Array[int] = Array([1, 2, 3])

# Typed getitem: returns element T
x: int = arr[0]         # → 1

# Slice: returns Array[int], not list
sub: Array[int] = arr[1:]  # → Array[1:] wraps result via Array(list)

# Iteration — now explicit __iter__, not ABC mixin
for v in arr:           # uses Array.__iter__ directly
    print(v)

# Map[str, int] — explicit type parameters
m: Map[str, int] = Map({"a": 1, "b": 2})
v: int | None = m.get("a")         # → 1
v2: int = m.get("c", 0)            # → 0 (single lookup, try/except)

# ItemsView.__contains__ now works
("a", 1) in m.items()              # → True
```
