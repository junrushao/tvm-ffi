# Make Array and Map parameterizable with proper generic type annotations
## TL;DR
- `Array` now inherits `Sequence[T]` and `Map` inherits `Mapping[K, V]`, making both properly parameterizable (e.g., `Array[int]`, `Map[str, int]`) for static type checkers.
- `Array.__getitem__` with a slice now returns a new `Array[T]` instead of a plain `list`, and uses `@overload` to distinguish integer vs slice signatures.
- View classes (`KeysView`, `ValuesView`, `ItemsView`), `Map.get`, and `getitem_helper` all received generic annotations, `operator.index()` compliance, and correctness fixes (e.g., `ItemsView.__contains__`, `slice.indices()`, try/except for `Map.get`).

## Impact
- API: `Array.__getitem__` with slice now returns `Array[T]` instead of `list` -- callers expecting `list` from slices will see a different type. `Map.__contains__` parameter changed from `Any` to `object` (compatible).
- Behavioral: `getitem_helper` now uses `operator.index()` which will raise `TypeError` for non-integer non-slice arguments that lack `__index__`, matching `list` behavior. `Map.get` uses try/except instead of `in` check, avoiding double hash lookup.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

Creating and using parameterized Array and Map with type checkers:

```python
import tvm_ffi
from tvm_ffi import Array, Map

# Type checkers now understand element types
arr: Array[int] = tvm_ffi.convert([1, 2, 3])
x: int = arr[0]              # type: int (via overload)
sub: Array[int] = arr[0:2]   # type: Array[int] (slice returns Array, not list)

m: Map[str, int] = tvm_ffi.convert({"a": 1, "b": 2})
v: int = m["a"]              # type: int (via cast)
d: int | None = m.get("c")   # type: int | None (via overload)
d2: int | str = m.get("c", "default")  # type: int | str (via _DefaultT overload)

# ItemsView containment check
assert ("a", 1) in m.items()
assert ("a", 999) not in m.items()
```
