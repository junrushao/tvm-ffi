# Fix strict-aliasing violations in JSON parser/writer under -ffast-math
## TL;DR
- Replaces `reinterpret_cast` type punning with union-based type punning in 5 private static methods across `json_parser.cc` and `json_writer.cc`.
- Fixes GCC `-Werror=strict-aliasing` compilation errors when building with `-ffast-math`.
- No behavioral change; purely a correctness fix for the type punning technique used to construct/inspect IEEE 754 special values (NaN, Inf).

## Key Exports
None -- all changes are internal to private static methods. No public API surface affected.

## Impact
- API: none
- Behavioral: none -- the bit patterns and IEEE 754 semantics are identical
- Flags/config: fixes compilation under `-ffast-math` / `-fstrict-aliasing` (GCC)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- JSON serialization utilities (`src/ffi/extra/json_parser.cc`, `src/ffi/extra/json_writer.cc`) -- internal infrastructure for reading/writing JSON with special IEEE 754 value handling under `__FAST_MATH__` conditional compilation.

Design elements this commit produces: none

## Usage Examples
Before (strict-aliasing violation, rejected by GCC under `-ffast-math`):
```cpp
// double -> uint64_t (writer: IsNaN, IsInf)
uint64_t bits = *reinterpret_cast<const uint64_t*>(&x);

// uint64_t -> double (parser: PosInf, NegInf, NaN)
const uint64_t inf_bits = 0x7FF0000000000000ULL;
return *reinterpret_cast<const double*>(&inf_bits);
```

After (union-based type punning, strict-aliasing safe):
```cpp
// double -> uint64_t (writer)
union { double from; uint64_t to; } u;
u.from = x;
uint64_t bits = u.to;

// uint64_t -> double (parser)
union { uint64_t from; double to; } u;
u.from = 0x7FF0000000000000ULL;
return u.to;
```
