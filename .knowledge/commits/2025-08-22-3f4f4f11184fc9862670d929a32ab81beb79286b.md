# Fix strict-aliasing violation in JSON fast-math helpers by replacing reinterpret_cast with union-based type punning
## TL;DR
- Replaces `reinterpret_cast`-based type punning between `double` and `uint64_t` with union-based type punning in all five `FastMathSafe*` helpers across `json_parser.cc` (3 functions) and `json_writer.cc` (2 functions).
- Fixes a `-Werror=strict-aliasing` compilation failure under GCC with `-ffast-math` that was introduced by commit `1a271f0`.
- No behavioral change; the IEEE 754 bit patterns and logic are identical.

## Impact
- API: none -- the `json::Parse` and `json::Stringify` public signatures and behavior are unchanged. The change is entirely within private static helper methods of `JSONParserContext` and `JSONWriter`.
- Flags/config: none -- the change is activated only under `__FAST_MATH__`; the `#else` branches are untouched.
- Data formats/schemas: none.

## Design Elements
Design elements this commit **consumes**:

- **JSON module fast-math safety** ([`.knowledge/designs/0012-json-and-serialization.md`](../designs/0012-json-and-serialization.md), "Fast-Math Safety" section): This commit consumes the `FastMathSafe*` helper pattern introduced by `1a271f0`, which uses bit-level IEEE 754 manipulation when `__FAST_MATH__` is defined. The design doc explicitly lists the five helpers and their bit patterns; this commit changes only the type-punning mechanism, not the bit patterns or the control flow.
- **Extra API tier** ([`.knowledge/designs/0011-extra-api-tier.md`](../designs/0011-extra-api-tier.md)): Both modified files live in `src/ffi/extra/`, the extra API tier.

Design elements this commit **produces**:

- **Refinement of the FastMathSafe type-punning idiom**: The prior implementation used `*reinterpret_cast<const T*>(&x)` to alias between `double` and `uint64_t`. This violates C++ strict-aliasing rules (accessing an object through a pointer to a different type is undefined behavior unless via `char*`/`unsigned char*`/`std::byte*`). The new union-based approach (`union { double from; uint64_t to; } u;`) is well-defined in C11 and supported by all major C++ compilers (GCC, Clang, MSVC) as an extension, avoiding the `-Werror=strict-aliasing` diagnostic. This establishes the union idiom as the project's preferred pattern for float-to-int bit reinterpretation. Alternatively, C++20 `std::bit_cast` would be the standards-compliant approach, but the project targets C++17.

## Key Implementations

### The strict-aliasing problem

The GCC error message in the commit description pinpoints the issue: dereferencing a `reinterpret_cast<const uint64_t*>(&x)` where `x` is `double` violates the strict aliasing rule. GCC under `-ffast-math` (which implies `-fstrict-aliasing`) elevates this to a hard error via `-Werror=strict-aliasing`. The fundamental issue is that the C++ standard does not permit accessing a `double` object through a `uint64_t*`.

### The union fix pattern

Five locations are changed, all following the same pattern:

**Writer side** (double -> uint64_t, in `FastMathSafeIsNaN` and `FastMathSafeIsInf`):
```cpp
// Before:
uint64_t bits = *reinterpret_cast<const uint64_t*>(&x);
// After:
union { double from; uint64_t to; } u;
u.from = x;
uint64_t bits = u.to;
```

**Parser side** (uint64_t -> double, in `FastMathSafePosInf`, `FastMathSafeNegInf`, `FastMathSafeNaN`):
```cpp
// Before:
const uint64_t inf_bits = 0x7FF0000000000000ULL;
return *reinterpret_cast<const double*>(&inf_bits);
// After:
union { uint64_t from; double to; } u;
u.from = 0x7FF0000000000000ULL;
return u.to;
```

### Invariants

- **IEEE 754 bit patterns unchanged**: The same bit constants (`0x7FF0000000000000ULL` for +Inf, `0xFFF0000000000000ULL` for -Inf, `0x7FF8000000000000ULL` for quiet NaN) are used. Only the reinterpretation mechanism changes.
- **Round-trip preservation**: `json::Stringify(json::Parse("NaN"))` == `"NaN"` still holds under `-ffast-math`.
- **sizeof guard**: The existing `static_assert(sizeof(double) == sizeof(uint64_t))` in the writer helpers remains in place. The parser helpers rely on the union having the same size for both members.

### Test file not modified

The test file `tests/cpp/extra/test_json_parser.cc` also has duplicated `FastMathSafe*` helpers (noted in the `1a271f0` ledger). This commit does not modify the test file. This may indicate the test helpers already used the union idiom, or that the test is not compiled with `-Werror=strict-aliasing`. The 18+12 = 30 lines changed (across 2 files, net +24 lines) confirm only the production code was updated.

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0012-json-and-serialization.md` -- Fast-Math Safety section**: The design doc currently says "All helpers include `static_assert(sizeof(double) == sizeof(uint64_t))`" but does not specify the type-punning mechanism. Now that the project has settled on union-based type punning (and previously used `reinterpret_cast` which was incorrect), the doc should explicitly state: (1) the union-based idiom as the canonical approach, (2) why `reinterpret_cast` is not acceptable (strict-aliasing UB), and (3) that `std::bit_cast` (C++20) would be the ideal alternative once the project moves to C++20. This helps future contributors avoid reintroducing the `reinterpret_cast` pattern.

### ADRs to write

None -- the choice of union-based type punning over `reinterpret_cast` is a straightforward correctness fix rather than an architectural decision between meaningfully different alternatives.
