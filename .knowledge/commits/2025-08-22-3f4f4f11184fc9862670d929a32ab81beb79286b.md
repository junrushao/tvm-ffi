# Replace reinterpret_cast with union-based type punning in JSON fast-math helpers
## TL;DR
- Replaces `reinterpret_cast<const double*>(&uint64_bits)` / `reinterpret_cast<const uint64_t*>(&double_val)` with anonymous-union-based type punning in all five `#ifdef __FAST_MATH__` code paths across `json_parser.cc` and `json_writer.cc`.
- Fixes GCC `-Werror=strict-aliasing` compilation errors introduced by the parent commit (1a271f0) that added these fast-math helpers.

## Key Exports
No new symbols, no signature changes. This commit modifies only the internal implementation of existing private static methods:

**JSONParserContext (unchanged signatures)**:
- `FastMathSafePosInf() -> double` -- now uses `union { uint64_t from; double to; }` instead of `reinterpret_cast`.
- `FastMathSafeNegInf() -> double` -- same change.
- `FastMathSafeNaN() -> double` -- same change.

**JSONWriter (unchanged signatures)**:
- `FastMathSafeIsNaN(double x) -> bool` -- now uses `union { double from; uint64_t to; }` instead of `reinterpret_cast`.
- `FastMathSafeIsInf(double x) -> bool` -- same change.

## Impact
- API: none -- no public header or function signature changes.
- ABI: none -- only internal `.cc` files modified, no object layout changes.
- Behavioral: Eliminates GCC strict-aliasing warnings/errors (`-Werror=strict-aliasing`) when compiling with `-ffast-math`. Runtime behavior is identical -- both `reinterpret_cast` and union-based punning produce the same bit-level results on all targeted compilers.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Fastmath-safe IEEE 754 helpers pattern** (introduced in commit 1a271f0): The pattern of constructing/detecting NaN/Inf via bit-level manipulation under `#ifdef __FAST_MATH__`. This commit preserves the pattern but changes the type-punning mechanism.
- **IEEE 754 double bit layout**: Same bit constants used (`0x7FF0000000000000` for +Inf, `0xFFF0000000000000` for -Inf, `0x7FF8000000000000` for quiet NaN), same exponent/mantissa extraction logic for detection.

Design elements this commit produces:
- **Union-based type punning for IEEE 754 helpers**: Replaces `reinterpret_cast` with C-style anonymous union type punning (`union { double from; uint64_t to; } u; u.from = x; bits = u.to;`). This avoids undefined behavior under the C++ strict aliasing rule. While technically undefined in C++ (only `memcpy` is standard-conforming), union-based type punning is well-defined in C and is a widely supported compiler extension in GCC and Clang, which explicitly guarantee it works. This makes it a pragmatic choice for code that must compile under GCC's strict-aliasing enforcement (`-Wstrict-aliasing`).

## Usage Examples
No change in public API usage. The internal mechanism change is:

```cpp
// BEFORE (commit 1a271f0): reinterpret_cast -- triggers -Wstrict-aliasing
const uint64_t inf_bits = 0x7FF0000000000000ULL;
return *reinterpret_cast<const double*>(&inf_bits);

// AFTER (this commit): union-based type punning -- no strict-aliasing warning
union {
  uint64_t from;
  double to;
} u;
u.from = 0x7FF0000000000000ULL;
return u.to;
```

```cpp
// BEFORE (commit 1a271f0): reinterpret_cast -- triggers -Wstrict-aliasing
uint64_t bits = *reinterpret_cast<const uint64_t*>(&x);

// AFTER (this commit): union-based type punning
union {
  double from;
  uint64_t to;
} u;
u.from = x;
uint64_t bits = u.to;
```
