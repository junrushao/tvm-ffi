# Fix strict-aliasing violations in JSON parser/writer fast-math helpers
## TL;DR
- Replaces `reinterpret_cast`-based type punning with union-based type punning in 5 `__FAST_MATH__`-guarded helper functions across `json_parser.cc` and `json_writer.cc`.
- Fixes GCC `-Werror=strict-aliasing` compilation failure when building TVM with `-ffast-math`.

## Key Exports
None -- all changed functions are `private static` helpers internal to `JSONParserContext` and `JSONWriter`. No public API surface affected.

## Impact
- API: none
- Behavioral: none -- identical IEEE 754 bit manipulation, just using a compiler-safe idiom
- Flags/config: fixes compilation under `__FAST_MATH__` / `-ffast-math` compiler flag
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **JSON serialization subsystem** (`src/ffi/extra/json_parser.cc`, `src/ffi/extra/json_writer.cc`) -- the FFI's internal JSON parser/writer that handles serialization of `Any`-typed values. These files provide `tvm.ffi.json_loads` / `tvm.ffi.json_dumps` global functions.
- **IEEE 754 special-value handling** -- the `FastMathSafe{IsNaN,IsInf,PosInf,NegInf,NaN}` private static helpers that detect/construct NaN and Infinity via bit-level inspection, required because `-ffast-math` makes `std::isnan`/`std::isinf`/`std::numeric_limits` unreliable.

Design elements this commit produces: none

## Usage Examples
Before (strict-aliasing violation):
```cpp
// json_writer.cc -- GCC rejects this under -ffast-math + -Werror=strict-aliasing
uint64_t bits = *reinterpret_cast<const uint64_t*>(&x);  // UB: violates strict aliasing

// json_parser.cc -- same pattern for constructing special values
const uint64_t inf_bits = 0x7FF0000000000000ULL;
return *reinterpret_cast<const double*>(&inf_bits);       // UB: violates strict aliasing
```

After (union-based type punning):
```cpp
// json_writer.cc -- union idiom avoids strict-aliasing violation
union { double from; uint64_t to; } u;
u.from = x;
uint64_t bits = u.to;

// json_parser.cc -- same idiom for constructing special values
union { uint64_t from; double to; } u;
u.from = 0x7FF0000000000000ULL;
return u.to;
```
