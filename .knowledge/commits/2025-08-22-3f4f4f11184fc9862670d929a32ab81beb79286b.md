# Fix strict-aliasing violations in JSON parser/writer under -ffast-math
## TL;DR
- Replace `reinterpret_cast`-based type punning with union-based type punning in 5 `FastMathSafe*` helper functions across `json_writer.cc` and `json_parser.cc`.
- Fixes GCC compilation error (`-Werror=strict-aliasing`) when building TVM with `-ffast-math`.

## Key Exports
None -- all changes are to `private static` helper functions internal to `JSONWriter` and `JSONParserContext`.

## Impact
- API: none
- Behavioral: none -- same IEEE 754 bit-pattern extraction, now using well-defined union type punning instead of UB-prone `reinterpret_cast`
- Flags/config: fixes compilation under `-ffast-math` (`__FAST_MATH__` preprocessor guard paths)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- JSON serialization infrastructure (`src/ffi/extra/json_writer.cc`, `src/ffi/extra/json_parser.cc`) -- internal to `ffi/extra` scope, not separately documented in `.knowledge/design-records/`

Design elements this commit produces: none

## Usage Examples
Before (compilation error under `-ffast-math`):
```cpp
// reinterpret_cast violates strict-aliasing — GCC -Werror=strict-aliasing rejects this
uint64_t bits = *reinterpret_cast<const uint64_t*>(&x);
```

After (union-based type punning, well-defined in GCC/Clang):
```cpp
union {
  double from;
  uint64_t to;
} u;
u.from = x;
uint64_t bits = u.to;
```

The same pattern is applied in reverse (uint64_t -> double) in the parser's `FastMathSafePosInf`, `FastMathSafeNegInf`, and `FastMathSafeNaN` helpers.
