# Migrate attrs to new reflection with padding fix, duplicate guard, and type-index dispatch
## TL;DR
- Fixes DLDataType padding bug: zeros `v_uint64` before writing `v_dtype` in `CopyToAnyView`/`MoveToAny` so equality checks on the raw 64-bit value are reliable.
- Adds a duplicate-registration guard in `TypeTable::RegisterTypeExtraInfo` -- throws `RuntimeError` if the same type's extra info is registered twice.
- Registers the root `Object` type with `TVMFFITypeExtraInfo` at TypeTable init, and extends `MakeObjectFromPackedArgs` to accept either a string type key or an integer `type_index` as the first argument.

## Impact
- API: `MakeObjectFromPackedArgs` now accepts `int32_t` type index as first arg in addition to string type key. Existing callers passing strings are unaffected.
- Behavioral: DLDataType values stored in Any/AnyView now have deterministic padding (zeroed), fixing potential equality-check false negatives. `RegisterTypeExtraInfo` now throws on duplicate registration instead of silently overwriting.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TypeTraits protocol** ([0006-type-traits.md](../designs/0006-type-traits.md)): Modifies `TypeTraits<DLDataType>` specialization.
- **Any/AnyView union layout** ([0003-any-system.md](../designs/0003-any-system.md)): Relies on `TVMFFIAny.v_uint64` being the full 64-bit union member overlapping `v_dtype`.
- **Reflection system** ([0008-reflection.md](../designs/0008-reflection.md)): `MakeObjectFromPackedArgs` uses reflection field info to set fields on newly created objects.
- **Object system / TypeTable** ([0002-object-system.md](../designs/0002-object-system.md)): Extends `TypeTable` constructor to register root `Object` with extra info.

Design elements this commit produces:
- **Duplicate extra_info registration guard**: New invariant -- calling `RegisterTypeExtraInfo` twice for the same type is now a hard error. Catches misconfigured `ObjectDef<T>` or missing `_type_key` on derived types.
- **Type-index dispatch in MakeObjectFromPackedArgs**: Callers can now pass `int32_t` type index instead of string type key, enabling faster object creation when the index is already known (e.g., from Python `c_class` where the type index is cached).
- **Root Object extra_info registration**: `Object` base type now has `TVMFFITypeExtraInfo` with `total_size=sizeof(Object)` and `creator=nullptr`, ensuring the type table is consistent for ancestor traversal.

## Usage Examples

Before/after for `MakeObjectFromPackedArgs` dispatch:
```cpp
// BEFORE: only string type key accepted
// ffi.MakeObjectFromPackedArgs("my.Point", "x", 1, "y", 2)

// AFTER: also accepts integer type_index (faster when index is cached)
// ffi.MakeObjectFromPackedArgs(type_index, "x", 1, "y", 2)
// where type_index = TVMFFITypeKeyToIndex("my.Point")
```

Before/after for DLDataType padding:
```cpp
// BEFORE: padding bits in v_dtype could be uninitialized
Any a, b;
TypeTraits<DLDataType>::CopyToAnyView(dtype, &a);
TypeTraits<DLDataType>::CopyToAnyView(dtype, &b);
// a.v_uint64 == b.v_uint64 might be FALSE due to stale padding

// AFTER: padding is zeroed, bitwise comparison is safe
// a.v_uint64 == b.v_uint64 is guaranteed TRUE for same dtype
```
