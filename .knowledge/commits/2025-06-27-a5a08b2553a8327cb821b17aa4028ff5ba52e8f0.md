# Harden reflection creation: padding fix, duplicate guard, type_index dispatch
## TL;DR
- Fixes a DLDataType padding bug: clears `v_uint64` before writing `v_dtype` in `CopyToAnyView`/`MoveToAny` so equality checks on the raw uint64 representation are reliable.
- Adds a duplicate-registration guard in `RegisterTypeExtraInfo` that throws a descriptive error if `extra_info` is already set for a type, catching common reflection misconfiguration (duplicate `ObjectDef<T>()`, missing `_type_key`).
- Registers base `Object` type's `extra_info` during `TypeTable` initialization (previously only the type index was registered, not the extra info).
- Extends `MakeObjectFromPackedArgs` to accept either `int32_t` type_index or `String` type_key as the first argument, enabling faster object construction when the caller already has the type index.

## Key Exports
**Functions (changed behavior)**:

`MakeObjectFromPackedArgs(PackedArgs args, Any* ret) -> void` — first argument (`args[0]`) now accepts either:
- `int32_t` type_index (new: fast path, skips type_key -> index lookup)
- `String` type_key (existing: resolves via `TVMFFITypeKeyToIndex`)

Error messages now use `TypeIndexToTypeKey(type_index)` instead of a captured `type_key` variable, so they work correctly for both dispatch paths.

**Internal (changed behavior)**:

`TypeTable::RegisterTypeExtraInfo(int32_t type_index, const TVMFFITypeExtraInfo* extra_info)` — now throws `RuntimeError` if `entry->extra_info != nullptr`, preventing silent override.

`TypeTable::TypeTable()` constructor — now registers `Object`'s `TVMFFITypeExtraInfo` (total_size=`sizeof(Object)`, creator=`nullptr`, doc=empty) immediately after allocating Object's type index.

**TypeTraits<DLDataType> (bugfix)**:

`CopyToAnyView` and `MoveToAny` now zero `result->v_uint64` before setting `type_index` and `v_dtype`, clearing padding bytes that `DLDataType` (3 bytes: code + bits + lanes) does not fill in the 8-byte union.

## Impact
- API: `ffi.MakeObjectFromPackedArgs` now accepts `int32_t` as first arg. Existing callers passing `String` are unaffected. Python/Rust bindings that construct objects via reflection can pass type_index directly for speed.
- Behavioral: `RegisterTypeExtraInfo` now fails loudly on duplicate registration instead of silently overwriting. This is a stricter invariant — code that previously "worked" by accident (double registration) will now throw.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TypeTraits<DLDataType>** (`0005-type-traits.md`) — the `CopyToAnyView`/`MoveToAny` protocol for DLDataType
- **TypeTable / TVMFFITypeExtraInfo** (`0009-reflection.md`, `0003-object-system.md`) — reflection registration infrastructure
- **MakeObjectFromPackedArgs** (`0009-reflection.md`) — packed-args object construction via reflection
- **TVMFFIAny union layout** (`0002-any-value-system.md`, `0001-c-abi-layer.md`) — the `v_uint64` / `v_dtype` union overlap

Design elements this commit produces:
- **Duplicate extra_info guard** — new invariant: `RegisterTypeExtraInfo` is once-only per type_index; violations throw descriptive `RuntimeError`
- **Object base extra_info registration** — `Object` now has extra_info in the type table (total_size, no creator), ensuring ancestor traversal in `MakeObjectFromPackedArgs` does not hit a null `extra_info` for the root type
- **Type-index dispatch in MakeObjectFromPackedArgs** — callers can bypass string-based type lookup by passing `int32_t` directly

## Usage Examples
**Type-index based object construction (new fast path)**:
```cpp
// Before: always string-based
// ffi.MakeObjectFromPackedArgs("my_module.MyAttrs", "field1", val1, "field2", val2)

// After: can also pass type_index directly
int32_t tidx = MyAttrsObj::RuntimeTypeIndex();
// ffi.MakeObjectFromPackedArgs(tidx, "field1", val1, "field2", val2)
```

**DLDataType padding fix (before/after)**:
```cpp
// Before: padding bytes in v_uint64 were uninitialized after CopyToAnyView
TVMFFIAny a, b;
TypeTraits<DLDataType>::CopyToAnyView(dtype, &a);
TypeTraits<DLDataType>::CopyToAnyView(dtype, &b);
// a.v_uint64 == b.v_uint64 could be FALSE due to garbage in padding

// After: v_uint64 is zeroed first, then v_dtype written
// a.v_uint64 == b.v_uint64 is now guaranteed TRUE for same dtype
```
