# Migrate attrs object creation to use new reflection, with padding and guard fixes
## TL;DR
- `MakeObjectFromPackedArgs` now accepts `int32_t` type index as first argument (in addition to string type key), enabling faster object creation by skipping the key-to-index lookup.
- `TypeTable::RegisterTypeExtraInfo` gains a duplicate-registration guard that throws `RuntimeError` with diagnostic hints when `extra_info` is set twice for the same type index.
- `Object` base type now registers a stub `TVMFFITypeExtraInfo` (with `creator=nullptr`) at TypeTable init, preventing null `extra_info` for the root type and enabling the duplicate guard to work for all subclasses.
- `TypeTraits<DLDataType>::CopyToAnyView` and `MoveToAny` now zero the `v_uint64` union member before writing `v_dtype`, eliminating padding-dependent equality mismatches in `AnyEqual`.

## Key Exports
**Functions (modified)**:

- `MakeObjectFromPackedArgs(PackedArgs args, Any* ret)` -- first argument (`args[0]`) now accepts either `String` (type key) or `int32_t` (type index). Dispatches via `args[0].try_cast<int32_t>()`. Error messages use `TypeIndexToTypeKey(type_index)` instead of the now-possibly-absent `type_key` local.

**Internal methods (modified)**:

- `TypeTable::RegisterTypeExtraInfo(int32_t type_index, const TVMFFITypeExtraInfo* extra_info)` -- now checks `entry->extra_info != nullptr` before writing; throws `RuntimeError` with diagnostic message on duplicate registration.

**TypeTraits (modified)**:

- `TypeTraits<DLDataType>::CopyToAnyView(const DLDataType& src, TVMFFIAny* result)` -- zeroes `result->v_uint64 = 0` before setting `type_index` and `v_dtype`.
- `TypeTraits<DLDataType>::MoveToAny(DLDataType src, TVMFFIAny* result)` -- same padding-clearing fix.

## Impact
- API: `MakeObjectFromPackedArgs` (exposed as `"ffi.MakeObjectFromPackedArgs"`) now accepts `int32_t` type index as arg[0]. Existing callers passing a string type key continue to work unchanged.
- ABI: none -- no struct layout or C API signature changes.
- Behavioral: (1) `DLDataType` values stored in `Any`/`AnyView` now have deterministic padding bits, fixing potential false-negative equality comparisons via `AnyEqual`. (2) Duplicate `ObjectDef<T>()` registration now fails loudly instead of silently overwriting.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Any/AnyView system** (`/.knowledge/designs/any-system.md`): The `DLDataType` padding fix directly addresses the `AnyEqual` invariant that equality can compare `v_uint64` for POD types. The `TVMFFIAny` union has `v_uint64` overlapping `v_dtype`, and `DLDataType` is 4 bytes while `v_uint64` is 8 bytes, leaving 4 bytes of padding.
- **TypeTraits protocol** (`/.knowledge/designs/type-traits.md`): `CopyToAnyView` and `MoveToAny` for `DLDataType` specialization.
- **Reflection system** (`/.knowledge/designs/reflection.md`): `TVMFFITypeExtraInfo` and `RegisterTypeExtraInfo` in TypeTable.
- **Object system** (`/.knowledge/designs/object-system.md`): `Object::_type_index`, TypeTable initialization sequence, `MakeObjectFromPackedArgs` as the reflection-based object factory.

Design elements this commit produces:
- **Duplicate extra_info guard**: New invariant that `RegisterTypeExtraInfo` may only be called once per type index. Violations throw `RuntimeError` with diagnostic hints pointing to common causes (duplicate `ObjectDef<T>()`, missing `_type_key`, key collision).
- **Object base extra_info registration**: `Object` itself now has `extra_info` populated (with `creator=nullptr`) at TypeTable construction. This closes the gap where the root type had no extra_info, and ensures the duplicate guard catches all erroneous re-registrations.
- **Type-index-based object creation**: `MakeObjectFromPackedArgs` accepts `int32_t` type index as an alternative to string type key, enabling callers that already have the index to skip the string lookup.

## Usage Examples
Creating an object by type index (new path):
```cpp
// Before: always required string type key
//   ffi.MakeObjectFromPackedArgs("my.Node", "field1", value1)
//
// After: can also pass int32_t type index directly
int32_t idx = MyNodeObj::RuntimeTypeIndex();
Any result;
PackedArgs args = {idx, "field1", value1};
MakeObjectFromPackedArgs(args, &result);
```

DLDataType padding fix -- no user-visible API change, but fixes this scenario:
```cpp
// Before: AnyEqual could return false for identical DLDataType values
// because padding bytes in v_uint64 were uninitialized
Any a(DLDataType{kDLFloat, 32, 1});
Any b(DLDataType{kDLFloat, 32, 1});
AnyEqual eq;
assert(eq(a, b));  // could fail before this fix due to padding mismatch
```
