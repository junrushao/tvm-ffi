# Migrate attrs to use new reflection: harden TypeTable registration, fix DLDataType padding, accept type_index in MakeObjectFromPackedArgs
## TL;DR
- Fixes a padding-induced equality bug in `TypeTraits<DLDataType>`: `CopyToAnyView` and `MoveToAny` now zero the `v_uint64` field before writing `v_dtype`, ensuring that the unused padding bytes in the `TVMFFIAny` union do not cause spurious inequality when comparing via `v_uint64`.
- Hardens `TypeTable::RegisterTypeExtraInfo` with a duplicate-registration guard that throws `RuntimeError` if `extra_info` is already set, catching common mistakes like duplicate `ObjectDef<T>()` calls or missing `_type_key` assignments.
- Extends `MakeObjectFromPackedArgs` to accept either `int32_t` (type_index) or `String` (type_key) as the first argument, enabling callers that already know the type index to skip the string lookup. Error messages now use `TypeIndexToTypeKey` for consistency.
- Bootstraps `Object` (the root type) with `TVMFFITypeExtraInfo` metadata (`total_size = sizeof(Object)`, `creator = nullptr`) during `TypeTable` construction, ensuring every type in the hierarchy has extra info registered.

## Impact
- API: `MakeObjectFromPackedArgs` now accepts `int32_t` as the first packed argument (in addition to `String`). This is a backward-compatible extension -- existing callers passing a `String` type key continue to work. The function is internal (not part of the `extern "C"` API surface), so the change affects C++ callers within the FFI module and downstream reflection-based object construction paths.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Any/AnyView Type Erasure** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): The `DLDataType` padding fix directly involves the `TVMFFIAny` union layout. `DLDataType` is a 3-byte struct (`code` uint8, `bits` uint8, `lanes` uint16) occupying only 4 bytes of the 8-byte `v_dtype` union member. The remaining 4 bytes were left uninitialized, breaking bitwise equality via `v_uint64`. The fix zeros the full 8 bytes before writing.
- **Object System / TypeTable** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): The duplicate-registration guard and `Object` metadata bootstrap both modify `TypeTable` initialization behavior. The guard strengthens the single-registration invariant for `extra_info`. The bootstrap ensures the root `Object` type has metadata from the start.
- **Reflection System** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `MakeObjectFromPackedArgs` is the runtime path for reflection-based object construction (creating objects from field key-value pairs). The type_index-first-argument extension optimizes this path for callers that have already resolved the type index.

Design elements this commit produces:
- **Duplicate-registration guard for `TypeTable::RegisterTypeExtraInfo`**: A new runtime invariant -- calling `RegisterTypeExtraInfo` twice for the same type index now throws `RuntimeError` with diagnostic guidance. This prevents silent override of reflection metadata, which could lead to incorrect field layouts at runtime. This guard is an internal safeguard, not a new public design element, but it strengthens the contract documented in [`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md).
- **Type-index-based object construction**: `MakeObjectFromPackedArgs` now supports a `try_cast<int32_t>` fast path that bypasses `TVMFFITypeKeyToIndex` string lookup. This is a performance-motivated extension point for callers that cache type indices (e.g., Python `c_class` constructors that resolve the type key once at class definition time).

## Reflection

### Design docs to write
- **Update `.knowledge/designs/0002-any-system.md`** to document the padding-zeroing invariant for sub-word POD types (`DLDataType`, `DLDevice`) in `CopyToAnyView`/`MoveToAny`. Specifically, any `TypeTraits<T>` where `sizeof(T) < 8` must zero the full `v_uint64` before writing the value to ensure bitwise equality via `AnyEqual`. This invariant is not currently captured in the design doc and applies to all current and future sub-word POD types. Future commits adding new POD types would benefit from this documentation.

- **Update `.knowledge/designs/0003-object-system.md`** to document that `TypeTable::RegisterTypeMetadata` (formerly `RegisterTypeExtraInfo`) enforces a single-registration invariant. The current design doc describes TypeTable initialization as single-threaded but does not mention that double-registration is a runtime error. This would help classify future commits that encounter or modify registration guards.
