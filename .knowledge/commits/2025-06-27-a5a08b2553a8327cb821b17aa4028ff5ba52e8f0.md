# Migrate attrs to use new reflection: DLDataType padding fix, duplicate registration guard, type-index-based object construction
## TL;DR
- Fix DLDataType padding bug: zero `v_uint64` before writing `v_dtype` in `TypeTraits<DLDataType>` to ensure deterministic equality checks via the `v_uint64` union path.
- Add duplicate registration guard in `TypeTable::RegisterTypeExtraInfo` and register `Object` base type's `TVMFFITypeExtraInfo` in the type table constructor.
- Allow `MakeObjectFromPackedArgs` to accept `int32_t` type index (in addition to `String` type key) as its first argument, avoiding redundant string-based type lookup.

## Impact
- API: `MakeObjectFromPackedArgs` (registered as `ffi.MakeObjectFromPackedArgs`) now accepts `int32_t` type index as first argument -- additive, backward compatible with existing string callers.
- Behavioral: DLDataType equality comparisons via `v_uint64` path are now deterministic (previously could fail due to uninitialized padding). Duplicate `ObjectDef<T>` registration now throws a clear error instead of silently overwriting.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Any/AnyView value system** (`0001`): `v_uint64` union member for equality comparison; `TVMFFIAny` 16-byte layout with padding between `v_dtype` (4 bytes) and `v_uint64` (8 bytes).
- **Object system** (`0002`): `Object::_type_key`, `Object::_type_index`, `Object::_type_depth`, `Object::_type_child_slots` in TypeTable constructor.
- **Reflection system** (`0008`): `TVMFFITypeExtraInfo` (total_size, creator, doc), `TVMFFIFieldInfo` (name, offset, setter, default_value, flags), field iteration via `type_info->fields`.
- **C ABI** (`0007`): `TVMFFITypeKeyToIndex`, `TVMFFIGetTypeInfo`, `TVMFFITypeInfo`, `TypeIndexToTypeKey`.

Design elements this commit produces:
- **Duplicate registration guard** in `RegisterTypeExtraInfo`: new invariant that `extra_info` can only be set once per type index. This catches common mistakes during reflection migration.
- **Type-index path in `MakeObjectFromPackedArgs`**: callers can bypass string-to-index lookup by passing `int32_t` directly.

## Usage Examples
**Type-index-based object construction (new path):**
```python
# Before: MakeObjectFromPackedArgs always required a string type key
ffi.MakeObjectFromPackedArgs("my.TypeKey", "field1", value1, "field2", value2)

# After: can also pass type index directly (e.g., from a cached RuntimeTypeIndex())
ffi.MakeObjectFromPackedArgs(type_index, "field1", value1, "field2", value2)
```

**DLDataType padding fix (before/after):**
```cpp
// Before: padding bytes in v_uint64 were uninitialized
// Two DLDataType values with same (code, bits, lanes) could compare unequal
// via the v_uint64 path because padding differed.
Any a, b;
TypeTraits<DLDataType>::CopyToAnyView(dtype, &a);  // padding = garbage
TypeTraits<DLDataType>::CopyToAnyView(dtype, &b);  // padding = different garbage
// a.v_uint64 != b.v_uint64  -- non-deterministic!

// After: v_uint64 zeroed first, padding is always 0
// a.v_uint64 == b.v_uint64  -- deterministic
```
