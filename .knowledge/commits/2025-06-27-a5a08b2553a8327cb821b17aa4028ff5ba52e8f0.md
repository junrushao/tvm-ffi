# Three targeted fixes to reflection robustness: DLDataType padding zeroing, duplicate extra_info guard, and MakeObjectFromPackedArgs type-index shortcut

## TL;DR
- **Concern A (dtype.h)**: `TypeTraits<DLDataType>::CopyToAnyView` and `MoveToAny` now zero `result->v_uint64` before writing `v_dtype`, ensuring equality comparisons on `TVMFFIAny` via `v_uint64` are not polluted by struct padding bits in `DLDataType`.
- **Concern B (object.cc — guard)**: `TypeTable::RegisterTypeExtraInfo` now throws `RuntimeError` if `extra_info` is already set, catching duplicate `ObjectDef<T>()` registrations and missing `_type_key` overrides at startup.
- **Concern C (object.cc — factory)**: `MakeObjectFromPackedArgs` now accepts either a pre-resolved `int32_t` type index or a string type key as its first argument; error messages use `TypeIndexToTypeKey` instead of a captured string variable; `Object` base type gets `extra_info` registered at `TypeTable` initialization time.

Note: The commit message ("Migrate attrs to use new reflection") describes the caller-side migration (in a different TVM layer), not these C++ fixes. Analysis is scoped to the actual diff.

## Key Exports

```python
# --- Concern A: DLDataType TypeTraits fix ---
# TypeTraits<DLDataType> — dtype.h, before vs after

# BEFORE (broken equality):
def CopyToAnyView(src: DLDataType, result: TVMFFIAny) -> None:
    result.type_index = kTVMFFIDataType
    result.v_dtype = src
    # Bug: DLDataType is 4 bytes; TVMFFIAny union is 8 bytes — padding bits
    # left uninitialized; v_uint64 equality check sees stale memory.

# AFTER (fixed):
def CopyToAnyView(src: DLDataType, result: TVMFFIAny) -> None:
    result.v_uint64 = 0   # clear padding before writing v_dtype
    result.type_index = kTVMFFIDataType
    result.v_dtype = src
    # Invariant: v_uint64 is always fully zero-initialized before field writes,
    #            so Any.__eq__ (which compares v_uint64) is correct for DLDataType.
    # Interacts with: Any.__eq__ in 0002-ffi-any-value-system (v_uint64 comparison)

# Same fix applied to MoveToAny.

# --- Concern B: Duplicate extra_info guard ---
# TypeTable::RegisterTypeExtraInfo — src/ffi/object.cc

def RegisterTypeExtraInfo(type_index: int32, extra_info: TVMFFITypeExtraInfo) -> None:
    entry = GetTypeEntry(type_index)
    # NEW GUARD:
    if entry.extra_info is not None:
        raise RuntimeError(
            f"Overriding {entry.type_key}, possible causes:\n"
            "- two ObjectDef<T>() calls for the same T\n"
            "- forgot to assign _type_key to ObjectRef<Y> that inherits from T\n"
            "- another type with the same key is already registered\n"
            "Cross check the reflection registration."
        )
    # ... write extra_info
    # Invariant: extra_info is set at most once per type_index.
    # Interacts with: ObjectDef<T> constructor (calls RegisterExtraInfo -> TVMFFITypeRegisterExtraInfo)

# Object base type now gets extra_info at TypeTable construction:
# info.total_size = sizeof(Object), info.creator = nullptr
# This prevents the guard from firing when ObjectDef<SomeType> is registered
# for a type inheriting Object (since Object itself is pre-registered).

# --- Concern C: MakeObjectFromPackedArgs type-index shortcut ---
# MakeObjectFromPackedArgs — src/ffi/object.cc

def MakeObjectFromPackedArgs(args: PackedArgs, ret: Any) -> None:
    # BEFORE: args[0] must be String (type_key), always looked up
    # AFTER: args[0] can be int32_t (type_index) OR String (type_key)
    if isinstance(args[0], int32_t):
        type_index = args[0]
    else:
        type_key = args[0].cast[String]()
        type_index = TVMFFITypeKeyToIndex(type_key)
    # ICHECK for odd arg count moved after type resolution
    # Error messages now use TypeIndexToTypeKey(type_index) instead of
    # captured `type_key` variable — works whether caller passed index or string.
    # Interacts with: TVMFFITypeKeyToIndex (C API lookup), TVMFFIGetTypeInfo
    # Interacts with: Python py_class / c_class (which calls MakeObjectFromPackedArgs)
```

## Impact
- API: None — `MakeObjectFromPackedArgs` is an internal C function; Python callers now gain the ability to pass a pre-resolved `int32_t` type index instead of a string, which is a new accepted input form but does not break existing string callers.
- Behavioral: `Any.__eq__` on `DLDataType` values now produces correct results (was silently broken for DLDataType before). Duplicate `ObjectDef<T>()` registrations now raise an explicit error at program startup instead of silently overwriting.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

**Concern A — before/after for DLDataType equality:**
```cpp
// BEFORE: two Any holding identical DLDataType values could compare unequal
DLDataType dt1 = {kDLFloat, 32, 1};
Any a1 = dt1;  // v_uint64 upper bits = garbage from stack
Any a2 = dt1;  // v_uint64 upper bits = different garbage
assert(a1 == a2);  // FAILS intermittently

// AFTER: v_uint64 = 0 before v_dtype write ensures padding is clean
Any a1 = dt1;  // v_uint64 = 0x00000000_00FF2001 (deterministic)
Any a2 = dt1;  // same
assert(a1 == a2);  // PASSES reliably
```

**Concern B — duplicate registration now caught early:**
```cpp
// If two ObjectDef<MyObj>() calls exist (e.g. copy-paste error):
// First call: RegisterTypeExtraInfo -> OK
// Second call: RegisterTypeExtraInfo -> RuntimeError at static init:
//   "Overriding MyObj, possible causes: two ObjectDef<T>() calls..."
```

**Concern C — Python attrs migration pattern (cross-layer):**
```python
# Old call path (string key, resolved on every call):
# args[0] = "my.Type" -> TVMFFITypeKeyToIndex("my.Type") -> type_index

# New call path (type index cached on Python side):
# args[0] = 42  -> MakeObjectFromPackedArgs uses 42 directly
# Avoids hash lookup; useful when Python c_class caches type_index at class definition time.
```
