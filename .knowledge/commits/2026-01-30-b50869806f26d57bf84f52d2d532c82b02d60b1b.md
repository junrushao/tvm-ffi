# Fix two UBSan violations: null memcpy in String/Bytes and null-pointer arithmetic in GetObjectOffsetToSubclass

## TL;DR
- `String::InitData` and `Bytes::InitData`: guard `std::memcpy(dest, data, size)` with `if (size > 0)` to avoid passing a null source pointer with size 0 (UB).
- `ObjectUnsafe::GetObjectOffsetToSubclass<T>`: replace null-pointer arithmetic (`static_cast<T*>(nullptr)->header_`) with `__builtin_offsetof(Class, header_)` (with `#pragma GCC diagnostic ignored "-Winvalid-offsetof"` guards) to avoid UBSan "null pointer dereference" false positive.

## Key Exports

None — bugfix only.

## Impact
- API: none — no signature changes.
- Behavioral: Code is now clean under UBSan (`-fsanitize=undefined`). Functionally equivalent for non-null inputs with size > 0.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0002-object-system`: `ObjectUnsafe::GetObjectOffsetToSubclass<T>` — used for computing byte offset of `header_` between Object and subclass, required for C ABI alignment. Now uses `offsetof` instead of null pointer arithmetic.
- `0007-containers`: `String::InitData` and `Bytes::InitData` — internal initialization helpers.

Design elements this commit produces: None — bugfix only.

## Usage Examples

Before (UB — null pointer dereference when called with size=0, and null pointer arithmetic):
```cpp
// object.h
return (reinterpret_cast<int64_t>(&(static_cast<Class*>(nullptr)->header_)) -
        reinterpret_cast<int64_t>(&(static_cast<Object*>(nullptr)->header_)));

// string.h
std::memcpy(dest_data, data, size);  // UB if data==nullptr && size==0
```

After:
```cpp
// object.h — uses offsetof with diagnostic suppression
return static_cast<int64_t>(__builtin_offsetof(Class, header_)) -
       static_cast<int64_t>(__builtin_offsetof(Object, header_));

// string.h — guards memcpy
if (size > 0) {
    std::memcpy(dest_data, data, size);
}
```
