# Add begin_index to TVMFFITypeAttrColumn for sparse type-index range support

## TL;DR
- Adds `begin_index` field to `TVMFFITypeAttrColumn` C ABI struct, enabling columns to cover only a subrange `[begin_index, begin_index + size)` of type indices instead of starting from 0.
- Changes `size` field from `size_t` to `int32_t` for consistent sizing with `begin_index` (also `int32_t`).
- All column lookups now compute `offset = type_index - begin_index` before indexing. Currently `begin_index` is always 0; sparse storage is planned for 1.0.
- Updates all consumers: `AnyHash`, `AnyEqual` in `any.h`, `FieldAccessor` in `reflection/accessor.h`, Cython bindings, and Rust FFI bindings.

## Key Exports

**`TVMFFITypeAttrColumn`** (C ABI struct, `c_api.h`):
```c
typedef struct {
  const TVMFFIAny* data;    // indexed by (type_index - begin_index)
  int32_t size;             // was size_t; covers [begin_index, begin_index + size)
  int32_t begin_index;      // NEW: starting type index of column data (0 for now)
} TVMFFITypeAttrColumn;
```

**Lookup pattern** (new invariant):
```cpp
int32_t offset = type_index - column->begin_index;
if (offset >= 0 && offset < column->size) {
    // access column->data[offset]
}
```

## Impact
- API: `TVMFFITypeAttrColumn` struct layout changes (`size_t size` -> `int32_t size` + new `int32_t begin_index`). This is an ABI-breaking change.
- Behavioral: None currently (begin_index is always 0). Future versions will use non-zero begin_index for sparse storage.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
```cpp
// Current usage (begin_index=0, unchanged semantics)
const TVMFFITypeAttrColumn* col = GetTypeAttrColumn("__any_hash__");
int32_t offset = type_index - col->begin_index;  // offset == type_index when begin_index==0
if (offset >= 0 && offset < col->size) {
    const TVMFFIAny& attr = col->data[offset];
    // use attr
}
```
