# Add dtype literal constants (tvm_ffi.float32, tvm_ffi.int64, etc.) to Python package
## TL;DR
- Defines 20 pre-constructed `dtype` literal constants in `_dtype.py` and re-exports them from `tvm_ffi.__init__`: `bool`, `int8/16/32/64`, `uint8/16/32/64`, `float16/32/64`, `bfloat16`, `float8_e4m3fn`, `float8_e4m3fnuz`, `float8_e5m2`, `float8_e5m2fnuz`, `float8_e8m0fnu`, `float4_e2m1fnx2` (with alias `float4_e2m1fn_x2`).
- Updates `convert()` to pass `dtype` instances through unchanged (not wrapped in containers).
- Follows numpy 2.0 naming convention: `bool` instead of `bool_`.

## Impact
- API: New public symbols in `tvm_ffi` namespace. `tvm_ffi.bool` shadows Python builtin `bool` within the module.
- Behavioral: `convert()` now treats `dtype` as a pass-through type (returns as-is instead of attempting container wrapping).
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **`dtype` class** ([0014-python-package.md](../designs/0014-python-package.md)): Pre-constructs instances from string names.
- **`convert()` function** ([0014-python-package.md](../designs/0014-python-package.md)): Extended to handle `dtype` pass-through.

Design elements this commit produces:
- **dtype literal convention**: Pre-constructed `dtype` constants accessible as `tvm_ffi.<name>`, following numpy 2.0 naming. This establishes the convention for downstream code to use `tvm_ffi.float32` instead of `tvm_ffi.dtype("float32")`.

## Usage Examples
```python
import tvm_ffi

# Direct dtype literal usage
x = tvm_ffi.Tensor.empty([3, 4], dtype=tvm_ffi.float32)
assert x.dtype == tvm_ffi.float32

# Float8 types
y = tvm_ffi.Tensor.empty([8], dtype=tvm_ffi.float8_e4m3fn)

# Passes through convert() unchanged
result = tvm_ffi.convert(tvm_ffi.int64)
assert result is tvm_ffi.int64
```
