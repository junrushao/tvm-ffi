# Add pre-defined dtype literal constants to tvm_ffi Python package top-level namespace

## TL;DR
- Introduces 20 pre-defined `dtype` literal constants (e.g., `tvm_ffi.float32`, `tvm_ffi.bfloat16`, float8 and float4x2 variants) as module-level attributes in `tvm_ffi/_dtype.py`, exported from `tvm_ffi/__init__.py`.
- Aligns naming with NumPy 2.0 convention: uses `bool` instead of `bool_`.
- Extends `convert()` in `_convert.py` to treat `dtype` instances as pass-through values (alongside `Object`, `bool`, `Number`, `ctypes.c_void_p`), preventing them from being wrapped as `OpaquePyObject`.

## Key Exports

```python
# In python/tvm_ffi/_dtype.py — module-level singletons

# Standard integer dtypes
bool    = dtype("bool")     # type_code=6, bits=8, lanes=1; aligns with numpy 2.0 (not bool_)
int8    = dtype("int8")     # type_code=0, bits=8, lanes=1
int16   = dtype("int16")
int32   = dtype("int32")
int64   = dtype("int64")
uint8   = dtype("uint8")    # type_code=1
uint16  = dtype("uint16")
uint32  = dtype("uint32")
uint64  = dtype("uint64")

# Floating point dtypes
float16   = dtype("float16")   # type_code=2
float32   = dtype("float32")
float64   = dtype("float64")
bfloat16  = dtype("bfloat16")  # type_code=4

# float8 family (ML-specific)
float8_e4m3fn    = dtype("float8_e4m3fn")    # type_code=10
float8_e4m3fnuz  = dtype("float8_e4m3fnuz")  # type_code=11
float8_e5m2      = dtype("float8_e5m2")      # type_code=12
float8_e5m2fnuz  = dtype("float8_e5m2fnuz")  # type_code=13
float8_e8m0fnu   = dtype("float8_e8m0fnu")   # type_code=14

# float4x2 (packed) family
float4_e2m1fnx2  = dtype("float4_e2m1fnx2")  # type_code=17, bits=4, lanes=2
float4_e2m1fn_x2 = float4_e2m1fnx2           # Alias for torch naming convention

# In python/tvm_ffi/_convert.py — convert() passthrough extension:
def convert(value: Any) -> Any:
    if isinstance(
        value, (core.Object, core.PyNativeObject, bool, Number, ctypes.c_void_p, _dtype.dtype)
    ):
        return value
    # Interacts with: _dtype.dtype — dtype now bypasses OpaquePyObject wrapping
    # Invariant: dtype instances are idempotent through convert() (returned as-is)
```

## Impact
- API: `tvm_ffi.bool`, `tvm_ffi.int8`, ..., `tvm_ffi.float4_e2m1fnx2` added as public top-level names; `tvm_ffi.float4_e2m1fn_x2` alias added for torch compatibility.
- Behavioral: `convert(dtype_instance)` now returns the dtype unchanged rather than wrapping it as `OpaquePyObject`. Existing code relying on `isinstance(result, OpaquePyObject)` for dtype inputs would break, but this is unlikely in practice.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `dtype` class (`python/tvm_ffi/_dtype.py`) — existing Cython-backed dtype type; literals are instances constructed via string parsing.
- `convert()` function (`python/tvm_ffi/_convert.py`) — existing conversion dispatch; extended with `_dtype.dtype` isinstance check.
- `tvm_ffi/__init__.py` public namespace — the established pattern of re-exporting submodule names at the top level (see `0012-ffi-python-package`).

Design elements this commit produces:
- **dtype literal constants** — 20 module-level `dtype` singletons at `tvm_ffi.<name>`, covering integers, floats, bfloat16, float8 (5 variants), and float4x2 (1 variant + alias). These become the idiomatic way to reference common dtypes without string construction.

## Usage Examples

**Context**: Using dtype literals to pass dtype to an FFI function without string construction.

```python
import tvm_ffi

# Before this commit: required explicit string construction
t = tvm_ffi.dtype("float32")

# After this commit: idiomatic constant access
t = tvm_ffi.float32
t2 = tvm_ffi.bfloat16
t3 = tvm_ffi.float8_e4m3fn

# dtype instances pass through convert() unchanged (no OpaquePyObject wrapping)
assert tvm_ffi.float32 is tvm_ffi._convert.convert(tvm_ffi.float32)

# float4x2 with torch alias
assert tvm_ffi.float4_e2m1fnx2 == tvm_ffi.float4_e2m1fn_x2
```
