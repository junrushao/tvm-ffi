# NDArray always constructs strides, eliminating null strides for contiguous tensors
## TL;DR
- `NDArrayObj` now always populates `DLTensor::strides` with row-major (C-contiguous) strides, replacing the previous convention of `strides == nullptr` for contiguous tensors.
- New `details::MakeStridesFromShape` helper computes row-major strides from shape. New `stride_data_` field on `NDArrayObj` backs the stride pointer lifetime.
- Both allocation paths (`NDArrayObjFromNDAlloc`) and DLPack import paths (`NDArrayObjFromDLPack`) are updated: allocation always constructs strides, DLPack import fills in strides only when the incoming tensor has `strides == nullptr`.

## Impact
- API: None (no public function signatures changed)
- Behavioral: `NDArray.strides` is now always non-null. Code that checked `strides == nullptr` to detect contiguous tensors must instead compute contiguity from stride values. DLPack export (`ToDLPack`/`ToDLPackVersioned`) will now emit non-null strides to external consumers.
- Flags/config: None
- Data formats/schemas: DLPack tensors exported from TVM FFI now always carry explicit strides, where previously contiguous tensors had `strides == nullptr`. External frameworks receiving these DLPack tensors may observe a behavioral difference.

Design elements this commit produces/mutates:

## Usage Examples
Test-derived example showing that strides are now always populated after NDArray creation:
```cpp
// Create a 3D NDArray with shape [2, 3, 1]
NDArray nd = NDArray::Empty({2, 3, 1}, DLDataType{kDLFloat, 32, 1}, DLDevice{kDLCPU, 0});

// Export to DLPack — strides are always populated (previously nullptr)
DLManagedTensor* dlpack = nd.ToDLPack();
EXPECT_EQ(dlpack->dl_tensor.strides[0], 3);  // 3*1 = 3
EXPECT_EQ(dlpack->dl_tensor.strides[1], 1);  // 1*1 = 1
EXPECT_EQ(dlpack->dl_tensor.strides[2], 1);  // innermost

// Import from DLPack — strides filled in if incoming tensor has nullptr strides
NDArray nd2 = NDArray::FromDLPack(dlpack);
```
