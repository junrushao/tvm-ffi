# NDArray now always constructs explicit strides (row-major) instead of leaving strides as nullptr
## TL;DR
- `NDArrayObj` gains a new protected field `Optional<Shape> stride_data_` to own the strides buffer lifetime.
- Both `NDArrayObjFromNDAlloc` (fresh allocation) and `NDArrayObjFromDLPack` (DLPack import with null strides) now compute and populate row-major contiguous strides via the new `details::MakeStridesFromShape` helper.
- Previous behavior: `DLTensor::strides` was `nullptr` for contiguous tensors. New behavior: `strides` always points to a valid row-major stride array.

## Key Exports

**Functions**:
```cpp
// include/tvm/ffi/container/shape.h  (namespace tvm::ffi::details)
TVM_FFI_INLINE ObjectPtr<ShapeObj> MakeStridesFromShape(int64_t ndim, int64_t* shape);
// Returns a Shape object holding row-major strides: strides[i] = product(shape[i+1:])
```

**Fields**:
```cpp
// include/tvm/ffi/container/ndarray.h  (class NDArrayObj, protected)
Optional<Shape> stride_data_;   // owns the strides buffer; parallels shape_data_
```

## Impact
- API: `DLTensor::strides` returned from `NDArray::ToDLPack()` / `ToDLPackVersioned()` is now always non-null. Downstream callers that tested `strides == nullptr` as a contiguity check will need updating; `IsContiguous()` already handles non-null strides correctly.
- Behavioral: `NDArrayObjFromDLPack` no longer strips strides from contiguous DLPack imports. Previously it set `strides = nullptr` when the incoming tensor was contiguous; now it only synthesizes strides when the incoming tensor had `strides == nullptr`, and preserves the incoming strides otherwise.
- Flags/config: none
- Data formats/schemas: DLPack tensors exported from TVM FFI will always carry explicit strides.

## Design Elements
Design elements this commit consumes:
- **Shape / ShapeObj** (`include/tvm/ffi/container/shape.h`) -- `Shape` is reused to store the strides buffer, leveraging its immutable int64 tuple semantics and trailing inplace allocation. See [0008-containers.md](../designs/0008-containers.md).
- **Optional<T>** -- wraps the stride buffer in the same pattern as `shape_data_`.
- **DLTensor / DLPack protocol** -- the `strides` field of `DLTensor` is the target being populated.
- **details::MakeEmptyShape** -- the underlying allocation primitive used by the new `MakeStridesFromShape`.

Design elements this commit produces:
- **`details::MakeStridesFromShape`** -- new helper function that computes row-major strides from shape dimensions. Reusable anywhere contiguous strides need to be synthesized.
- **`NDArrayObj::stride_data_`** -- new protected field that owns the lifetime of the strides buffer, mirroring the existing `shape_data_` pattern.
- **Invariant: NDArray.strides is always non-null** -- a new behavioral invariant for all NDArrays constructed through TVM FFI.

## Usage Examples

Computing strides from shape (C++ internal usage):
```cpp
// Given shape {1, 2, 3}, MakeStridesFromShape produces strides {6, 3, 1}
NDArray nd = Empty({1, 2, 3}, DLDataType({kDLInt, 16, 1}), DLDevice({kDLCPU, 0}));
DLManagedTensor* dlpack = nd.ToDLPack();
// dlpack->dl_tensor.strides[0] == 6  (2*3)
// dlpack->dl_tensor.strides[1] == 3  (3)
// dlpack->dl_tensor.strides[2] == 1
```

DLPack import with null strides now gets strides synthesized:
```cpp
// Before: FromDLPack would strip strides from contiguous tensors (set to nullptr)
// After:  FromDLPack synthesizes strides only when incoming strides == nullptr
NDArray nd2 = NDArray::FromDLPack(tensor_with_null_strides);
assert(nd2->strides != nullptr);  // always true now
```
