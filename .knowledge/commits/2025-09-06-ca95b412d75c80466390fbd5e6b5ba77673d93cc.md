# Construct NDArray.strides by default

## TL;DR
- NDArray now always populates `DLTensor::strides` with computed row-major (C-contiguous) strides, instead of leaving strides as `nullptr` for contiguous arrays.
- Adds a new `details::MakeStridesFromShape` helper in `shape.h` that computes strides from shape dimensions.
- Adds `Optional<Shape> stride_data_` field to `NDArrayObj` to own the strides memory alongside the existing `shape_data_`.
- Updates `NDArrayObjFromDLPack` to populate strides when the incoming DLPack tensor has `strides == nullptr`, instead of the old behavior of clearing strides to `nullptr` when contiguous.

## Key Changes

### New Helper: `details::MakeStridesFromShape` (`shape.h`)

```cpp
TVM_FFI_INLINE ObjectPtr<ShapeObj> MakeStridesFromShape(int64_t ndim, int64_t* shape);
```

Computes row-major strides from shape dimensions. Iterates from the last dimension backward, accumulating the stride product. Returns an inplace-allocated `ShapeObj` whose data buffer holds the computed strides. This function is placed inside `namespace tvm::ffi::details`.

### `NDArrayObj` changes (`ndarray.h`)

**New protected field:**
- `Optional<Shape> stride_data_` -- owns the backing memory for `DLTensor::strides` when strides are computed by the FFI (i.e., not provided externally). Sits alongside the existing `Optional<Shape> shape_data_` which backs `DLTensor::shape`.

### `NDArrayObjFromNDAlloc` changes (`ndarray.h`)

**Before:** Set `this->strides = nullptr` (indicating contiguous layout per DLPack convention).

**After:** Computes strides via `Shape(details::MakeStridesFromShape(this->ndim, this->shape))`, sets `this->strides` to point into the stride Shape's data buffer, and stores the Shape in `this->stride_data_` to ensure the memory remains valid for the object's lifetime.

### `NDArrayObjFromDLPack` changes (`ndarray.h`)

**Before:** After copying the DLTensor fields from the incoming DLPack tensor, if the tensor was contiguous (`IsContiguous(tensor->dl_tensor)`), strides were forcibly set to `nullptr`.

**After:** If the incoming DLPack tensor has `strides == nullptr`, computes and populates strides via `MakeStridesFromShape`. If the tensor already has strides (whether contiguous or non-contiguous), they are preserved as-is from the source tensor. The old behavior of stripping contiguous strides is removed.

### Test changes (`test_ndarray.cc`)

- `TEST(NDArray, DLPack)`: Previously checked `strides == nullptr`; now verifies concrete stride values `[6, 3, 1]` for a `{1, 2, 3}` shape.
- `TEST(NDArray, DLPackVersioned)`: Previously checked `strides == nullptr`; now verifies `strides[0] == 1` for a `{2}` shape.

## Impact

- **API**: No API changes. All existing public interfaces remain the same.
- **ABI**: Not breaking. The `stride_data_` field is added to `NDArrayObj`'s protected section, but `NDArrayObj` is always heap-allocated via `make_object` and accessed through `ObjectRef`, so the layout change does not affect ABI compatibility at the C API boundary.
- **Behavioral**: Significant change for downstream consumers. Previously, `DLTensor::strides` could be `nullptr` for contiguous arrays (per the DLPack convention where `nullptr` implies row-major contiguous layout). After this change, strides are always populated with explicit values. Code that checks `strides == nullptr` to detect contiguity will no longer see `nullptr` for FFI-created or FFI-imported contiguous arrays -- it must compare stride values instead (or use `IsContiguous()` which already handles both cases).
- **Memory**: Slightly increased per-NDArray allocation for the stride `Shape` object (one additional inplace-allocated `ShapeObj` per NDArray, holding `ndim` int64_t values).

## Design Elements

Design elements this commit **consumes**:

- **Shape as inplace-allocated object** (`shape.h`): Uses `MakeEmptyShape` and the inplace array object pattern to allocate stride data inline with the `ShapeObj` header, avoiding separate heap allocations for the stride array.
- **Optional<T> for owned backing data**: Follows the existing `shape_data_` pattern where `NDArrayObj` owns a `Shape` to back the raw `int64_t*` pointer in the `DLTensor` base class.
- **DLPack interop layer** (`NDArrayObjFromDLPack`): The template class that wraps both legacy `DLManagedTensor` and versioned `DLManagedTensorVersioned` via the same template.

Design elements this commit **produces**:

- **Always-populated strides invariant**: Establishes the invariant that `NDArrayObj::strides` is never `nullptr` after construction, whether the array was freshly allocated or imported via DLPack. This simplifies downstream code that needs to reason about strides, as it eliminates the `nullptr`-means-contiguous special case. The `IsContiguous()` function continues to work correctly since it handles both `nullptr` and explicit contiguous strides.

- **`MakeStridesFromShape` utility**: A reusable helper for computing row-major strides from shape dimensions. Located in `details` namespace in `shape.h`, accessible to any code that needs to synthesize strides from a shape.

## Usage Examples

### Computing strides from a shape
```cpp
// Internal usage -- compute row-major strides
Shape shape({2, 3, 4});
Shape strides = Shape(details::MakeStridesFromShape(shape.size(), const_cast<int64_t*>(shape.data())));
// strides = [12, 4, 1]
```

### Checking contiguity (unchanged API)
```cpp
NDArray nd = Empty({2, 3, 4}, dtype, dev);
// nd->strides is now non-null, but IsContiguous() still works:
assert(nd.IsContiguous());  // true
assert(nd->strides[0] == 12);
assert(nd->strides[1] == 4);
assert(nd->strides[2] == 1);
```

## Reflection

### Design docs to write or update
- `.knowledge/designs/ndarray.md` (or equivalent tensor/NDArray design doc): Should document the "always-populated strides" invariant introduced by this commit. Note that `strides` is never `nullptr` after `NDArrayObj` construction and that `IsContiguous()` is the canonical way to check contiguity rather than checking `strides == nullptr`.

### Stale knowledge references
- Any documentation or commit ledger entries that state or assume `strides == nullptr` for contiguous NDArrays should be updated. The DLPack convention of `nullptr` meaning contiguous still applies to the DLPack protocol itself, but within TVM FFI, strides are now always materialized.
