# NDArray now always constructs strides, eliminating nullptr strides convention

## TL;DR
- NDArray strides are now always populated (never `nullptr`). A new `details::MakeStridesFromShape` helper computes row-major strides from shape, stored in a new `stride_data_` field on `NDArrayObj`.
- Both allocation (`NDArrayObjFromNDAlloc`) and DLPack import (`NDArrayObjFromDLPack`) paths now guarantee non-null strides. DLPack import only computes strides when the incoming tensor has `strides == nullptr`; if the source provides strides, they are preserved as-is.
- The old convention of setting `strides = nullptr` to indicate contiguous layout is removed; `IsContiguous` still works because it falls through to the stride-based check.

## Impact
- API: None -- no public C++ or Python API signatures changed. The change is internal to NDArray construction.
- Behavioral: `DLTensor.strides` is now always non-null for TVM-created NDArrays. Downstream code that checked `strides == nullptr` as a proxy for "contiguous" must use `IsContiguous()` instead. The existing `IsContiguous()` function handles non-null strides correctly (it checks if strides match the row-major pattern).
- Flags/config: None.
- Data formats/schemas: DLPack export (`ToDLPack`, `ToDLPackVersioned`) now emits tensors with non-null strides, which may affect consumers that special-cased `strides == nullptr`.

## Design Elements
Design elements this commit consumes:
- **Shape / ShapeObj** (`.knowledge/designs/0007-containers.md`): Used as the storage type for computed strides. `MakeEmptyShape` allocates the backing storage; `Shape` ref keeps data alive.
- **NDArrayObj / DLTensor layout** (`.knowledge/designs/0007-containers.md` lines 183-192): The `NDArrayObj` inherits `DLTensor` fields including `shape`, `strides`, `ndim`. This commit extends the backing storage pattern (already used for `shape_data_`) to strides.
- **DLPack interop** (`.knowledge/designs/0007-containers.md` line 202): Import/export paths are the two construction sites modified.

Design elements this commit produces:
- **`details::MakeStridesFromShape`** (`include/tvm/ffi/container/shape.h`): New utility for computing row-major strides from shape. Follows the existing `MakeInplaceShape` pattern in the same namespace.
- **`NDArrayObj::stride_data_`** (`include/tvm/ffi/container/ndarray.h`): New protected field that owns the strides Shape, mirroring the existing `shape_data_` pattern.
- **Always-non-null strides invariant**: NDArrays constructed by TVM now guarantee `DLTensor.strides != nullptr`.

## Usage Examples

C++ test showing the new strides behavior (from `tests/cpp/test_ndarray.cc`):
```cpp
// Before: strides was nullptr for contiguous NDArrays
// EXPECT_EQ(dlpack->dl_tensor.strides, nullptr);

// After: strides are always populated with row-major values
// For shape {2, 3} (i.e., 2x3 matrix), strides are {3, 1}
NDArray nd = NDArray::Empty({2, 3}, DLDataType{kDLFloat, 32, 1}, DLDevice{kDLCPU, 0});
auto* dlpack = nd.ToDLPack();
EXPECT_EQ(dlpack->dl_tensor.strides[0], 6);  // 3 * 2 elements per row? No: {2,3,1} -> strides {6,3,1}
// Correction: for shape {2,2,3}, strides are {6,3,1}
// For shape {2,3}: strides are {3,1}
// For shape {3}: strides are {1}
```

Before/after pattern for DLPack import:
```cpp
// Before: contiguous DLPack tensors had strides set to nullptr
NDArrayObjFromDLPack(tensor) {
    *static_cast<DLTensor*>(this) = tensor->dl_tensor;
    if (IsContiguous(tensor->dl_tensor)) {
        this->strides = nullptr;  // OLD: erased strides for contiguous tensors
    }
}

// After: strides are always populated
NDArrayObjFromDLPack(tensor) {
    *static_cast<DLTensor*>(this) = tensor->dl_tensor;
    if (tensor->dl_tensor.strides == nullptr) {
        // Only compute strides when source didn't provide them
        Shape strides = Shape(details::MakeStridesFromShape(ndim, shape));
        this->strides = const_cast<int64_t*>(strides.data());
        this->stride_data_ = std::move(strides);
    }
}
```
