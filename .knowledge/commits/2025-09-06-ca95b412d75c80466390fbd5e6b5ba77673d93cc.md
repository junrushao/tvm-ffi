# Ensure NDArray always constructs contiguous strides instead of leaving strides as nullptr
## TL;DR
- Adds `details::MakeStridesFromShape` helper in `shape.h` that computes row-major contiguous strides from a shape, returning a `Shape` object with trailing inplace storage.
- Changes `NDArrayObjFromNDAlloc` and `NDArrayObjFromDLPack` to always populate `DLTensor::strides` with explicitly computed contiguous strides (backed by a new `stride_data_` member on `NDArrayObj`) instead of leaving `strides = nullptr` as the DLPack convention for contiguous tensors.
- For DLPack imports, only synthesizes strides when the incoming tensor has `strides == nullptr`; if the source already provides strides (possibly non-contiguous), they are preserved as-is.

## Impact
- **API**: Behavioral change -- `NDArray::strides` is no longer `nullptr` for contiguous tensors. Any downstream code that tested `strides == nullptr` as a proxy for "contiguous" must now use `IsContiguous()` or inspect stride values directly. The existing `IsContiguous()` function already handles non-null strides correctly (it checks stride values against expected row-major pattern), so callers using that function are unaffected.
- **Flags/config**: None.
- **Data formats/schemas**: The exported `DLManagedTensor` from `ToDLPack()` / `ToDLPackVersioned()` will now carry non-null strides, which may affect interop with frameworks that special-case `strides == nullptr`. The DLPack spec treats `strides == nullptr` as equivalent to row-major contiguous, so explicit strides should be accepted by compliant consumers, but non-compliant consumers could break.

## Design Elements

Design elements this commit **consumes**:

- **Container System / NDArray** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): `NDArrayObj` extends `Object` and `DLTensor`. The commit leverages the existing `shape_data_` pattern (an `Optional<Shape>` member that owns the backing storage for the `DLTensor::shape` pointer) and mirrors it for strides.
- **Container System / Shape** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): Uses `Shape` as the owning container for stride data, leveraging inplace allocation via `MakeEmptyShape` + trailing `int64_t` storage. The `data()` method provides the raw pointer that `DLTensor::strides` points to.
- **DLPack interop** (`include/tvm/ffi/container/ndarray.h`): The `NDArrayObjFromDLPack` template handles import from both `DLManagedTensor` (legacy) and `DLManagedTensorVersioned`. This commit changes the import behavior: previously, contiguous tensors had their strides *set to nullptr* even if the source provided strides; now, existing non-null strides are preserved, and null strides are synthesized.

Design elements this commit **produces**:

- **NDArray stride invariant**: After this commit, `NDArrayObj::strides` is guaranteed non-null for all NDArrays created via `NDArrayObjFromNDAlloc` or `NDArrayObjFromDLPack`. The `stride_data_` member owns the backing storage when strides are synthesized. This eliminates the `nullptr`-means-contiguous convention internal to TVM's NDArray, making stride access unconditionally safe without null checks.
- **`details::MakeStridesFromShape`** (`include/tvm/ffi/container/shape.h`): A new utility function that allocates a `ShapeObj` with inplace storage and fills it with row-major contiguous strides computed right-to-left (`stride[i] = product of shape[i+1..ndim-1]`). Note: the initial version in this commit takes `(int64_t ndim, int64_t* shape)` as raw parameters; the current codebase has since refactored this to take `ShapeView shape`, adding a separate `FillStridesFromShape` for the raw-pointer use case.
