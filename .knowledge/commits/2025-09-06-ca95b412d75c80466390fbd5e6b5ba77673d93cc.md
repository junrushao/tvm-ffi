# NDArray.strides now always populated: computed C-order strides replace null for new allocations and null-stride DLPack imports

## TL;DR
- `NDArrayObjFromNDAlloc` no longer sets `strides = nullptr`; it now computes explicit row-major (C-order) strides and stores them in a new `stride_data_` field so their lifetime is tied to the object.
- `NDArrayObjFromDLPack` previously zeroed `strides` when `IsContiguous()` was true (discarding source stride info); it now only fills in computed strides when the source `DLTensor.strides` is already `nullptr`, preserving explicit strides from the wrapped tensor.
- A new helper `details::MakeStridesFromShape(ndim, shape)` in `shape.h` computes C-order strides from a shape pointer.

## Impact
- API: None — `NDArrayObj` internal layout change; `DLTensor.strides` field semantics changed for callers who previously assumed `strides == nullptr` means contiguous. Any code that special-cased `strides == nullptr` for C-order assumptions is now affected.
- Behavioral: `DLTensor.strides` is no longer `nullptr` for freshly allocated or imported-null-stride NDArrays. DLPack consumers that check `strides == nullptr` as a contiguity shortcut will no longer trigger that path.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `NDArrayObj` / `NDArray` container (0007-containers) — modifies internal layout by adding `stride_data_` field
- `Shape` / `ShapeObj` (0007-containers) — reuses `ObjectPtr<ShapeObj>` as the stride backing store
- `Optional<Shape>` (0007-containers) — used as `stride_data_` type

Design elements this commit produces:
- `details::MakeStridesFromShape` — new internal utility in `shape.h` (`details` namespace); computes C-order strides
- `NDArrayObj::stride_data_` — new protected field; backs the lifetime of `DLTensor.strides` pointer
- Changed invariant on `DLTensor.strides`: no longer guaranteed `nullptr` for contiguous arrays

## Usage Examples

**Before** (NDArrayObjFromNDAlloc constructor):
```cpp
// Allocated NDArray always had null strides — callers inferred contiguous layout
this->strides = nullptr;
```

**After**:
```cpp
// Explicit C-order strides are always computed and stored
Shape strides = Shape(details::MakeStridesFromShape(this->ndim, this->shape));
this->strides = const_cast<int64_t*>(strides.data());
this->stride_data_ = std::move(strides);
```

**DLPack round-trip test showing changed expectation** (`tests/cpp/test_ndarray.cc`):
```cpp
// NDArray of shape {2, 3, 3}  →  DLPack  →  read strides
// Before: EXPECT_EQ(dlpack->dl_tensor.strides, nullptr);
// After:
EXPECT_EQ(dlpack->dl_tensor.strides[0], 6);  // 3*3
EXPECT_EQ(dlpack->dl_tensor.strides[1], 3);
EXPECT_EQ(dlpack->dl_tensor.strides[2], 1);
```
