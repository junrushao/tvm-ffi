# NDArray now always constructs strides, replacing the nullptr convention for contiguous tensors
## TL;DR
- `NDArray.strides` is now always populated with a `Shape` object containing row-major strides, even for contiguous tensors. The previous convention of `strides = nullptr` for contiguous layout is eliminated at construction time.
- A new helper `details::MakeStridesFromShape(ndim, shape)` computes row-major (C-contiguous) strides from shape dimensions.
- `NDArrayObjFromDLPack` now fills in strides when the incoming DLPack tensor has `strides == nullptr`, rather than stripping strides from contiguous tensors.

## Impact
- API: None -- no public API signatures changed. `NDArray::strides` field type is unchanged (`int64_t*`), but it is now always non-null.
- Behavioral: All code that checks `strides == nullptr` to detect contiguous layout will now take the non-null branch. The `IsContiguous()` helper already handles non-null strides correctly, so callers using it are unaffected. Direct `strides == nullptr` checks in downstream code are now dead code for TVM-constructed NDArrays.
- Flags/config: None
- Data formats/schemas: DLPack export via `ToDLPack()`/`ToDLPackVersioned()` now always includes strides in the exported `DLTensor`, which may affect consumers that interpreted `strides == nullptr` specially.

## Design Elements
Design elements this commit consumes:
- **Shape** (0006-containers): Used as the backing storage type for the new `stride_data_` field, reusing `MakeEmptyShape` for allocation.
- **NDArrayObj/NDArray** (0006-containers): The existing two-subclass construction pattern (`NDArrayObjFromNDAlloc` for fresh allocation, `NDArrayObjFromDLPack` for DLPack import).
- **Optional\<Shape\>** (0006-containers): Used for the new `stride_data_` field, matching the pattern of `shape_data_`.

Design elements this commit produces:
- **`details::MakeStridesFromShape`**: New helper function in `shape.h` that computes C-contiguous strides from shape. Placed in `details` namespace alongside `MakeEmptyShape` and `MakeInplaceShape`.
- **`NDArrayObj::stride_data_`**: New protected field that owns the memory backing `DLTensor::strides`, paralleling `shape_data_`'s role for `DLTensor::shape`.
- **"strides always non-null" invariant**: NDArrays constructed through TVM always have `strides != nullptr`. This replaces the DLPack-inherited convention where `nullptr` meant contiguous.

## Usage Examples
From the test update (`tests/cpp/test_ndarray.cc`), verifying that strides are always populated after construction:
```cpp
// For a shape [2, 3, 1] NDArray, strides are computed as row-major:
// strides[0] = 3*1 = 3 (product of shape[1:])
// Wait -- the test shows [2, 2, 3] -> strides [6, 3, 1]
NDArray nd = NDArray::FromNDAlloc(alloc, Shape({2, 2, 3}), dtype, device);
DLManagedTensor* dlpack = nd.ToDLPack();
// Previously: EXPECT_EQ(dlpack->dl_tensor.strides, nullptr);
// Now:
EXPECT_EQ(dlpack->dl_tensor.strides[0], 6);  // 2*3
EXPECT_EQ(dlpack->dl_tensor.strides[1], 3);  // 3
EXPECT_EQ(dlpack->dl_tensor.strides[2], 1);  // innermost
```
