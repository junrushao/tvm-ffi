# Centralize object creation with CreateEmptyObject/__ffi_new__ fallback; add Python Field descriptor

## TL;DR
- New `CreateEmptyObject` / `HasCreator` in `function.h` unify 5 scattered creator-or-null patterns; falls back to `__ffi_new__` type attribute for Python-defined types.
- New `Field` descriptor class in `python/tvm_ffi/dataclasses/field.py` for Python-defined type fields with `ty: TypeSchema`, `default`, `default_factory`, `repr`, `hash`, `compare`, `init`, `kw_only`.
- `TVMFFITypeMetadata.total_size` field type changes (ABI break).

## Impact
- API: **Breaking**. `TVMFFITypeMetadata.total_size` field type changed (see commit message). `Field` descriptor re-introduced in `tvm_ffi.dataclasses` (was removed in b97ff1a for C++ classes, now for Python-defined types).
- Behavioral: `CreateEmptyObject` fallback enables reflection-based creation/serialization/init for Python-defined types without a C++ creator.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

```cpp
// C++: unified creation
const TVMFFITypeInfo* info = GetTypeInfo(type_index);
if (HasCreator(info)) {
    ObjectPtr<Object> obj = CreateEmptyObject(info);  // works for C++ and Python types
}
```

```python
# Python: field descriptor (for Python-defined FFI types)
from tvm_ffi.dataclasses import Field
from tvm_ffi.core import TypeSchema

fields = [
    Field("x", TypeSchema("int"), init=True, kw_only=False),
    Field("y", TypeSchema("str"), default="hello", init=True, kw_only=True),
]
```
