# Add per-type customizable hash/equality dispatch to AnyHash and AnyEqual via TypeAttrColumn

## TL;DR
- `AnyHash` and `AnyEqual` now consult two new TypeAttr columns (`__any_hash__`, `__any_equal__`) for registered Object types (`type_index >= kTVMFFIStaticObjectBegin`), allowing per-type override of hashing and equality without changing `TypeTraits`.
- Each column slot accepts either a raw C function pointer (`kTVMFFIOpaquePtr`, for zero-overhead fast path) or a `Function` object (`kTVMFFIFunction`, for dynamic registration).
- `MoveFromSafeCallRaised`/`SetSafeCallRaised` moved from `include/tvm/ffi/function_details.h` to `include/tvm/ffi/error.h` to break a layering dependency (secondary refactor); `any.h` now calls these helpers directly without requiring `function.h`.

## Impact
- API: `AnyHash` and `AnyEqual` semantics change for Object types that register `__any_hash__`/`__any_equal__` — previously those types fell through to pointer-identity hash/equality (`v_uint64`), now they invoke the registered handler. No change to types that do not register.
- Behavioral: `Map<Any, Any>` and `Dict` keyed on Objects now get type-specific hash/equality when the type opts in.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **TypeAttr column mechanism** (`__any_hash__`, `__any_equal__`): column-array store and `EnsureTypeAttrColumn`/`TypeAttrDef` registration pattern from `0006-reflection.md`.
- **TVMFFIFunctionCell.cpp_call fast path**: direct C++ ABI call without safe-call overhead, from `0001-c-abi.md`.
- **AnyHash / AnyEqual dispatch logic**: the existing switch over `type_index` in `0003-any-anyview.md`.

Design elements this commit produces:
- **`__any_hash__` TypeAttr column**: new per-type hash customization point for `AnyHash`. Slot value is either `kTVMFFIOpaquePtr` (function pointer) or `kTVMFFIFunction`.
- **`__any_equal__` TypeAttr column**: symmetric customization point for `AnyEqual`.
- **Dual dispatch protocol**: both columns support two registration variants (opaque C ptr for hot paths, Function object for dynamic registration). Hash fn signature: `int64_t(const Any&)`; Equal fn signature: `bool(const Any&, const Any&)`.

## Usage Examples

**Registering a custom hash/equal for an Object type (C++):**

```cpp
// In testing_object.h — OpaquePtr variant (TInt) and Function variant (TFloat):

// TInt: registered as raw function pointer (fast path)
static int64_t CustomAnyHash(const Any& src) {
    return static_cast<int64_t>(src.cast<TInt>()->value + 1024);
}
static bool CustomAnyEqual(const Any& lhs, const Any& rhs) {
    return lhs.cast<TInt>()->value == rhs.cast<TInt>()->value;
}
// In RegisterReflection():
refl::TypeAttrDef<TIntObj>()
    .attr("__any_hash__",  reinterpret_cast<void*>(&TInt::CustomAnyHash))
    .attr("__any_equal__", reinterpret_cast<void*>(&TInt::CustomAnyEqual));

// TFloat: registered as Function objects (dynamic path)
refl::TypeAttrDef<TFloatObj>()
    .def("__any_hash__",  &TFloat::CustomAnyHash)
    .def("__any_equal__", &TFloat::CustomAnyEqual);

// Usage (from test_any.cc):
Any int_src = TInt(7);
uint64_t expected = details::StableHashCombine(
    int_src.type_index(),
    static_cast<uint64_t>(TInt::CustomAnyHash(int_src)));  // == AnyHash()(int_src)
EXPECT_EQ(AnyHash()(int_src), expected);
EXPECT_TRUE(AnyEqual()(TInt(7), TInt(7)));
EXPECT_FALSE(AnyEqual()(TInt(7), TInt(8)));
```
