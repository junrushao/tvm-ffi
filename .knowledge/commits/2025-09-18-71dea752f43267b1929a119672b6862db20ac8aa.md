# Fix PyTorch Tensor API call in embedded C++ DLPack conversion source
## TL;DR
- Fix `src.ndim()` to `src.dim()` in the embedded C++ `toDLPackImpl` template inside `_optional_torch_c_dlpack.py`. The PyTorch C++ `at::Tensor` API uses `dim()`, not `ndim()`, to query the number of dimensions; the old call would fail at JIT compile time.

## Key Exports
None

## Impact
- API: none
- Behavioral: Fixes JIT compilation failure of the optional torch DLPack C extension on PyTorch versions where `at::Tensor::ndim()` is not defined. Without this fix, `load_torch_c_dlpack_extension()` would fail to build the shared library, falling back to slower DLPack conversion paths.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- DLPack exchange protocol: the `toDLPackImpl` C++ template converts PyTorch tensors to DLPack format for zero-copy tensor sharing (see [0014-stream-and-env-context.md](../designs/0014-stream-and-env-context.md) for env context)
- Optional torch C DLPack extension: JIT-compiled C++ addon in `python/tvm_ffi/_optional_torch_c_dlpack.py` that provides `__dlpack_c_exchange_api__` on `torch.Tensor`

Design elements this commit produces: none (bugfix to existing code)
