# Fix torch Tensor dimension query in toDLPackImpl: ndim() → dim()

## TL;DR
- Corrects a PyTorch API call in the embedded C++ source of `_optional_torch_c_dlpack.py`: `src.ndim()` → `src.dim()` inside `toDLPackImpl`.
- `ndim()` does not exist on `at::Tensor`; `dim()` is the correct method returning `int64_t`.
- Affects stride normalization for 1-D scalar tensors (`ndim==1, size(0)==1, stride(0)!=1`).

## Key Exports
None

## Impact
- API: none
- Behavioral: The `need_normalize_strides` guard in `toDLPackImpl` now correctly evaluates for 1-D size-1 torch tensors with non-unit stride; previously the code would fail to compile or silently misbehave depending on the PyTorch ABI version.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `_optional_torch_c_dlpack.py` — the optionally-compiled PyTorch C extension providing fast `torch.Tensor` ↔ DLPack conversion (see [0016-py-ffi-call-dispatch](../design-records/0016-py-ffi-call-dispatch.md))

Design elements this commit produces: none

## Usage Examples
**Before (broken):**
```cpp
bool need_normalize_strides = src.ndim() == 1 && src.size(0) == 1 && src.stride(0) != 1;
// ndim() is not a method on at::Tensor; causes compilation error or wrong result
```

**After (correct):**
```cpp
bool need_normalize_strides = src.dim() == 1 && src.size(0) == 1 && src.stride(0) != 1;
// dim() returns int64_t — the correct PyTorch ATen API
```
