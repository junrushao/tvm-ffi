# Fix PyTorch C++ API call from ndim() to dim() in torch-to-DLPack conversion
## TL;DR
- Fixes a single incorrect method call in `_optional_torch_c_dlpack.py`: `src.ndim()` changed to `src.dim()` in the inline C++ `toDLPackImpl` template.
- `ndim()` is not valid on PyTorch's C++ `at::Tensor`; the correct accessor for number of dimensions is `dim()`.

## Key Exports
None

## Impact
- API: none
- Behavioral: Fixes compilation/runtime correctness of the inline C++ `toDLPackImpl` function used in the torch_c_dlpack addon. Without this fix, the stride normalization guard for 1-D single-element tensors would fail to compile or call the wrong method.
- Flags/config: none
- Data formats/schemas: none
