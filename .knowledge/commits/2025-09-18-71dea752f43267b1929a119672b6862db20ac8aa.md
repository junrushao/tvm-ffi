# Fix PyTorch Tensor API call from ndim() to dim() in torch C DLPack extension
## TL;DR
- Fixes a single incorrect PyTorch C++ API call in the embedded C++ source within `_optional_torch_c_dlpack.py`: `src.ndim()` changed to `src.dim()` in the `toDLPackImpl` template function.

## Key Exports
None

## Impact
- API: none
- Behavioral: Fixes compilation or runtime correctness of the torch C DLPack extension when calling `toDLPackImpl` on a 1-element 1D tensor that needs stride normalization. `at::Tensor::dim()` is the correct PyTorch API for querying number of dimensions; `ndim()` does not exist on the C++ `at::Tensor` class.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Torch C DLPack extension (`_optional_torch_c_dlpack.py`) — embedded C++ source compiled at runtime via `load_inline` (design record 0013).
- DLPack exchange protocol (design record 0006, 0012) — the `toDLPackImpl` function converts PyTorch tensors to DLPack format.
