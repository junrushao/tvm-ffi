# Replace `__attribute__` with C++ standard attributes

## TL;DR
- Replaces all GCC/MSVC compiler-specific attribute syntax (`__attribute__((always_inline))`, `__attribute__((noinline))`, `__attribute__((unused))`, `__forceinline`, `__declspec(noinline)`) with C++ standard attributes (`[[gnu::always_inline]]`, `[[gnu::noinline]]`, `[[maybe_unused]]`, `[[msvc::forceinline]]`, `[[msvc::noinline]]`).
- Reorders `TVM_FFI_INLINE` and `TVM_FFI_ATTRIBUTE_UNUSED` to appear before `static` in all declarations, which is the required position for C++ standard attributes (attributes must precede the declaration specifiers they apply to).
- Pure mechanical refactor across 16 files (15 headers + 1 test header), 197 insertions / 201 deletions. No functional or ABI changes.

## Key Changes

### Macro redefinitions (`include/tvm/ffi/base_details.h`)

**`TVM_FFI_INLINE`:**
- Before (MSVC): `#define TVM_FFI_INLINE __forceinline`
- After (MSVC): `#define TVM_FFI_INLINE [[msvc::forceinline]] inline`
- Before (GCC/Clang): `#define TVM_FFI_INLINE inline __attribute__((always_inline))`
- After (GCC/Clang): `#define TVM_FFI_INLINE [[gnu::always_inline]] inline`

**`TVM_FFI_NO_INLINE`:**
- Before (MSVC): `#define TVM_FFI_NO_INLINE __declspec(noinline)`
- After (MSVC): `#define TVM_FFI_NO_INLINE [[msvc::noinline]]`
- Before (GCC/Clang): `#define TVM_FFI_NO_INLINE __attribute__((noinline))`
- After (GCC/Clang): `#define TVM_FFI_NO_INLINE [[gnu::noinline]]`

**`TVM_FFI_ATTRIBUTE_UNUSED`:**
- Before: platform-conditional `__attribute__((unused))` on GCC/Clang, empty on other compilers
- After: `#define TVM_FFI_ATTRIBUTE_UNUSED [[maybe_unused]]` (unconditional, standard C++17)

### Declaration order change (all affected headers)

Every `static TVM_FFI_INLINE <type> <method>(...)` declaration is rewritten to `TVM_FFI_INLINE static <type> <method>(...)`. This is necessary because C++ standard attributes like `[[gnu::always_inline]]` must appear before the declaration specifiers (`static`, `inline`, etc.), whereas GCC's `__attribute__((always_inline))` could appear after `inline` via the old `inline __attribute__((...))` expansion.

Similarly, `static inline TVM_FFI_ATTRIBUTE_UNUSED` in macro helper definitions (`TVM_FFI_STATIC_INIT_BLOCK_VAR_DEF`, `TVM_FFI_FUNC_REG_VAR_DEF`) is rewritten to `TVM_FFI_ATTRIBUTE_UNUSED static inline`.

## Impact
- **API**: No changes to any public API signatures or behavior.
- **ABI**: No ABI impact. The attribute changes only affect compiler optimization hints (inlining) and do not change symbol mangling, calling conventions, or struct layout.
- **Behavioral**: No runtime behavior change. `[[gnu::always_inline]]` and `__attribute__((always_inline))` have identical semantics on GCC/Clang. `[[msvc::forceinline]]` and `__forceinline` are equivalent on MSVC.
- **Portability**: `[[maybe_unused]]` is standard C++17 and works on all conforming compilers, replacing a GCC-only `__attribute__((unused))` that left MSVC without the annotation.

## Design Elements
Design elements this commit consumes:
- C++17 standard attributes (`[[maybe_unused]]`, `[[gnu::...]]`, `[[msvc::...]]`).
- Vendor-specific attribute namespaces: `gnu::` (GCC/Clang extension in `[[...]]` syntax), `msvc::` (MSVC extension).

Design elements this commit produces:
- **Attribute-first declaration convention** -- Establishes the pattern that `TVM_FFI_INLINE` and `TVM_FFI_ATTRIBUTE_UNUSED` must precede `static`/`inline` in declarations, since they expand to C++ standard attributes which must appear at the beginning of a declaration.
