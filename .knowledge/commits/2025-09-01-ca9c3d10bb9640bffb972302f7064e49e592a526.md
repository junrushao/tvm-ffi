# Introduce weak reference counting support to the FFI ABI

## TL;DR
- Adds weak reference counter support to the `TVMFFIObject` header, growing it from 16 bytes to 24 bytes. The header now contains `int32_t type_index`, `uint32_t weak_ref_count`, `uint64_t strong_ref_count`, and the deleter pointer.
- Changes the deleter signature from `void (*deleter)(TVMFFIObject*)` to `void (*deleter)(TVMFFIObject*, int flags)` with a new `TVMFFIObjectDeleterFlagBitMask` enum controlling whether the call should run the destructor (strong), free memory (weak), or both.
- Renames the C API function `TVMFFIObjectFree` to `TVMFFIObjectDecRef` and adds a new `TVMFFIObjectIncRef` function.
- Introduces a complete `WeakObjectPtr<T>` smart pointer class with `lock()`, `expired()`, `reset()`, `swap()`, copy/move semantics, and inheritance-compatible construction.
- Updates all allocator deleters in `SimpleObjAllocator` to respect the two-phase deletion protocol (destroy object on strong=0, free memory on weak=0).
- Updates Cython bindings (`base.pxi`, `object.pxi`, `dtype.pxi`) to use the renamed `TVMFFIObjectDecRef` API.
- Bumps package version from `0.1.0a5` to `0.1.0a6`.
- Adds comprehensive C++ tests for `WeakObjectPtr` lifecycle, assignment, locking, and expiration.

## Key Exports

### New C ABI Enum: `TVMFFIObjectDeleterFlagBitMask`
Defined in `include/tvm/ffi/c_api.h`:
- `kTVMFFIObjectDeleterFlagBitMaskStrong = 1 << 0` -- destructor action when strong ref count reaches zero (destroy object, keep memory).
- `kTVMFFIObjectDeleterFlagBitMaskWeak = 1 << 1` -- free action when weak ref count reaches zero (free memory block).
- `kTVMFFIObjectDeleterFlagBitMaskBoth = Strong | Weak` -- common case where both counters reach zero simultaneously.

### Changed C ABI Struct: `TVMFFIObject`
Layout changed from 16 bytes to 24 bytes:
```
Offset  Size  Field
0       4     int32_t type_index
4       4     uint32_t weak_ref_count     (was: int32_t ref_counter)
8       8     uint64_t strong_ref_count   (new, was: part of deleter union)
16      8     void (*deleter)(TVMFFIObject*, int flags) | int64_t __ensure_align
```

### Changed C ABI Deleter Signature
```c
// Before:
void (*deleter)(struct TVMFFIObject* self);
// After:
void (*deleter)(struct TVMFFIObject* self, int flags);
```

### Renamed C API Function
```c
// Before:
int TVMFFIObjectFree(TVMFFIObjectHandle obj);
// After:
int TVMFFIObjectDecRef(TVMFFIObjectHandle obj);
```

### New C API Function
```c
int TVMFFIObjectIncRef(TVMFFIObjectHandle obj);
```

### Changed C++ Type Alias
In `include/tvm/ffi/memory.h`:
```cpp
// Before:
typedef void (*FObjectDeleter)(TVMFFIObject* obj);
// After:

```

### New C++ Class Template: `WeakObjectPtr<T>`
Defined in `include/tvm/ffi/object.h`:
- `WeakObjectPtr()` / `WeakObjectPtr(nullptr_t)` -- default/null construction.
- `WeakObjectPtr(const ObjectPtr<T>&)` -- construct from strong pointer (increments weak count).
- `WeakObjectPtr(const WeakObjectPtr<T>&)` -- copy construction (increments weak count).
- `WeakObjectPtr(WeakObjectPtr<T>&&)` -- move construction (transfers ownership).
- Template variants for base-class-compatible `U` types.
- `ObjectPtr<T> lock() const` -- promote weak to strong via `TryPromoteWeakPtr()` CAS loop; returns nullptr if expired.
- `void reset()` -- release weak reference.
- `void swap(WeakObjectPtr<T>&)` -- swap two weak pointers.
- `int use_count() const` -- strong reference count (for debugging).
- `bool expired() const` -- true if object has been destroyed (strong count == 0 or pointer is null).
- Copy/move assignment operators.

### New Private Method: `Object::TryPromoteWeakPtr()`
CAS-based atomic operation that increments `strong_ref_count` only if it is currently > 0. Returns true on success, false if the object is already destroyed. Used by `WeakObjectPtr::lock()`.

### New Private Methods: `Object::IncWeakRef()` / `Object::DecWeakRef()`
Atomic increment/decrement of `weak_ref_count`. `DecWeakRef()` calls `deleter(&header_, kTVMFFIObjectDeleterFlagBitMaskWeak)` when weak count reaches zero.

### Changed Private Method: `Object::DecRef()`
Now implements a two-phase deletion protocol:
1. When `strong_ref_count` reaches 0 and `weak_ref_count == 1` (common case): calls deleter once with `kTVMFFIObjectDeleterFlagBitMaskBoth`.
2. When `strong_ref_count` reaches 0 and `weak_ref_count > 1`: calls deleter with `kTVMFFIObjectDeleterFlagBitMaskStrong` (destroy object), then decrements weak count. If weak count also reaches 0, calls deleter with `kTVMFFIObjectDeleterFlagBitMaskWeak` (free memory).

## Impact
- **ABI**: Breaking. `TVMFFIObject` header grows from 16 to 24 bytes. Deleter signature gains `int flags` parameter. `TVMFFIObjectFree` renamed to `TVMFFIObjectDecRef`. All language bindings and compiled modules that touch the object header must be recompiled.
- **API**: `TVMFFIObjectFree` is removed and replaced by `TVMFFIObjectDecRef`. New `TVMFFIObjectIncRef` added. New `WeakObjectPtr<T>` class available. `FObjectDeleter` typedef signature changed.
- **Behavioral**: Initial `weak_ref_count` is set to 1 (not 0) at object creation -- the strong reference implicitly holds one weak reference. This ensures memory is not freed while any strong reference exists. The common fast path (no weak references held) optimizes by checking `weak_ref_count == 1` before the strong-count-reaches-zero fence and calling the deleter once with both flags.
- **Size**: `TVMFFIObject` grows from 16 to 24 bytes. `ref_counter` (was `int32_t`) is split into `uint32_t weak_ref_count` and `uint64_t strong_ref_count`. The u32 weak counter keeps the header at 24 bytes (with alignment), saving 8 bytes versus two u64 counters.
- **Cython**: `TVMFFIObjectFree` -> `TVMFFIObjectDecRef` in all Cython `.pxi` files.
- **Version**: Package version bumped from `0.1.0a5` to `0.1.0a6`.

## Design Elements

Design elements this commit **consumes**:

- **Object system** (`object.h`): The existing `Object` class with intrusive ref-counting, `ObjectPtr<T>` smart pointer, `IncRef`/`DecRef` methods, and the `TVMFFIObject` header structure. The commit extends this system rather than replacing it.
- **Allocator framework** (`memory.h`): `ObjAllocatorBase`, `SimpleObjAllocator`, and the `Handler` pattern with `New`/`Deleter` static methods. The commit modifies the deleter implementations to support two-phase deletion.
- **C ABI contract** (`c_api.h`): The stable C-level object header layout and the `TVMFFIObjectFree` API. This commit breaks the ABI to add weak RC support before the ABI is frozen.
- **Cython binding layer** (`base.pxi`, `object.pxi`, `dtype.pxi`): The Cython extern declarations and the `Object.__dealloc__` calling `TVMFFIObjectFree`.

Design elements this commit **produces**:

- **Weak reference counting protocol**: A two-counter scheme where `strong_ref_count` controls object lifetime (destructor) and `weak_ref_count` controls memory lifetime (deallocation). When strong reaches 0, the destructor runs but memory persists until weak also reaches 0. The initial `weak_ref_count = 1` at creation means the strong reference implicitly holds a weak reference -- a pattern borrowed from `std::shared_ptr` / `std::weak_ptr` and Rust's `Arc` / `Weak`.

- **Two-phase deleter with flag bitmask**: The deleter function receives a `TVMFFIObjectDeleterFlagBitMask` indicating which phase(s) to execute. The `kTVMFFIObjectDeleterFlagBitMaskBoth` shortcut enables a single deleter call in the common case (no outstanding weak refs), avoiding the overhead of two separate calls. The allocator's `Deleter_` function checks the flag bits independently: strong-bit triggers `tptr->T::~T()`, weak-bit triggers `delete reinterpret_cast<StorageType*>(tptr)`.

- **`WeakObjectPtr<T>` smart pointer**: A non-owning smart pointer that holds a weak reference. Key design: `lock()` uses a CAS loop (`TryPromoteWeakPtr()`) to atomically increment the strong count only if it is > 0, preventing races between `lock()` and `DecRef()`. The pointer stores a raw `Object*` and increments/decrements `weak_ref_count`. Inheritance-compatible via template constructors with `static_assert(is_base_of<T, U>)`.

- **CAS-based weak-to-strong promotion** (`TryPromoteWeakPtr`): An atomic compare-and-swap loop that reads `strong_ref_count`, checks > 0, and attempts to increment. On failure (another thread changed the count), it retries with the new value. On strong count == 0, returns false (object already destroyed). Uses `__ATOMIC_ACQ_REL` on success for full fence semantics. MSVC uses `_InterlockedCompareExchange64`.

- **Optimized common-path DecRef**: The `DecRef()` method checks `weak_ref_count == 1` (relaxed load) before the acquire fence. In the common case where no external weak references exist, it calls the deleter once with `kTVMFFIObjectDeleterFlagBitMaskBoth` and avoids the second atomic decrement of `weak_ref_count`. The slower path (weak references exist) calls the destructor first, then decrements `weak_ref_count` with proper release/acquire fencing.

- **`TVMFFIObjectIncRef` / `TVMFFIObjectDecRef` C API pair**: Replaces the single `TVMFFIObjectFree` with a symmetric IncRef/DecRef pair, making the C API more explicit about reference counting semantics.

## Usage Examples

### Using WeakObjectPtr to break a cycle
```cpp
#include <tvm/ffi/object.h>
using namespace tvm::ffi;

ObjectPtr<MyObj> strong = make_object<MyObj>(42);
WeakObjectPtr<MyObj> weak(strong);

// Check if still alive
if (!weak.expired()) {
  // Promote to strong reference
  if (ObjectPtr<MyObj> locked = weak.lock()) {
    // Use locked->...
  }
}

// After strong is released, weak becomes expired
strong.reset();
assert(weak.expired());
assert(weak.lock() == nullptr);
```

### Deleter implementation with flag dispatch
```cpp
static void Deleter_(TVMFFIObject* objptr, int flags) {
  T* tptr = details::ObjectUnsafe::RawObjectPtrFromUnowned<T>(objptr);
  if (flags & kTVMFFIObjectDeleterFlagBitMaskStrong) {
    tptr->T::~T();  // destroy object
  }
  if (flags & kTVMFFIObjectDeleterFlagBitMaskWeak) {
    delete reinterpret_cast<StorageType*>(tptr);  // free memory
  }
}
```

### ADRs to write or update
- Consider new ADR for the decision to use a split `uint32_t weak_ref_count` + `uint64_t strong_ref_count` (rather than two `uint64_t` counters or a single combined counter). Key factors: 24-byte header size (vs 32 with two u64), weak references are expected to be rare, u32 is sufficient for weak count. The `weak_ref_count = 1` at creation (strong implicitly holds weak) follows the `std::shared_ptr` / Rust `Arc` convention.
