# Introduce weak reference counting to the FFI ABI for future-proof cyclic dependency breaking

## TL;DR
- Adds weak reference counting to the `TVMFFIObject` header, growing it from 16 bytes to 24 bytes: the former `int32_t ref_counter` is split into `uint32_t weak_ref_count` and `uint64_t strong_ref_count`, and the deleter signature gains a `flags` parameter (`TVMFFIObjectDeleterFlagBitMask`) to distinguish strong destruction (call destructor) from weak destruction (free memory).
- Introduces `WeakObjectPtr<T>`, a C++ smart pointer that holds a weak reference, with `lock()` (CAS-based `TryPromoteWeakPtr`), `expired()`, copy/move/swap/reset semantics mirroring `std::weak_ptr`.
- Renames the C API function `TVMFFIObjectFree` to `TVMFFIObjectDecRef` and adds `TVMFFIObjectIncRef`, updating all Python/Cython callsites. Bumps package version to `0.1.0a6`.

## Impact
- **API**:
  - **Breaking C ABI change**: `TVMFFIObject` grows from 16 to 24 bytes. All code with `static_assert(sizeof(TVMFFIObject) == 16)` must be updated. The `deleter` function pointer signature changes from `void(*)(TVMFFIObject*)` to `void(*)(TVMFFIObject*, int flags)`. This is a hard binary-incompatible change -- all shared libraries and language bindings must be rebuilt.
  - **C API rename**: `TVMFFIObjectFree` is renamed to `TVMFFIObjectDecRef`. New `TVMFFIObjectIncRef` is added. Any direct caller of the old name will fail to link.
  - **C++ API**: New `WeakObjectPtr<T>` class in `include/tvm/ffi/object.h`. New private methods on `Object`: `IncWeakRef()`, `DecWeakRef()`, `TryPromoteWeakPtr()`. `FObjectDeleter` typedef in `memory.h` changes signature.
  - **New C enum**: `TVMFFIObjectDeleterFlagBitMask` with values `kTVMFFIObjectDeleterFlagBitMaskStrong` (bit 0), `kTVMFFIObjectDeleterFlagBitMaskWeak` (bit 1), `kTVMFFIObjectDeleterFlagBitMaskBoth` (bits 0+1).
  - **Python/Cython**: `TVMFFIObjectFree` references in `base.pxi`, `dtype.pxi`, `object.pxi` updated to `TVMFFIObjectDecRef`. No Python-level API change -- the weak ref feature is not yet exposed to Python.
- **Flags/config**: Version bump `0.1.0a5` -> `0.1.0a6` in `pyproject.toml`.
- **Data formats/schemas**: None.

## Design Elements

Design elements this commit **consumes**:

- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The commit modifies the core `TVMFFIObject` struct layout, `FObjectDeleter` typedef, and C API function surface. The prior 16-byte header invariant (`sizeof(TVMFFIObject) == 16`) is replaced with a 24-byte layout. The deleter function pointer contract is extended with flag-based dispatch.
- **Object System** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): The `Object::IncRef`/`DecRef` methods are updated to operate on `strong_ref_count` (u64). The `make_object` allocator in `ObjAllocatorBase` now initializes both `strong_ref_count = 1` and `weak_ref_count = 1` (the "implicit weak" design). The `SimpleObjAllocator::Deleter_` is split into flag-gated destructor call vs. memory free.
- **Python Bindings** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): Cython `.pxi` files updated for the `TVMFFIObjectFree` -> `TVMFFIObjectDecRef` rename.

Design elements this commit **produces**:

- **Weak Reference Counting ABI**: A new sub-design within the C ABI and object system:
  - **Header layout**: `TVMFFIObject` is now `{int32_t type_index, uint32_t weak_ref_count, uint64_t strong_ref_count, union{deleter, __ensure_align}}` -- 24 bytes. The `weak_ref_count` is `uint32_t` to keep the header within 24 bytes (avoiding 32-byte alignment waste).
  - **Implicit weak reference**: Every `make_object` call initializes `weak_ref_count = 1`. This implicit weak reference is decremented when `strong_ref_count` reaches zero. The design means a strong-only object (the common case) calls deleter exactly once with `kTVMFFIObjectDeleterFlagBitMaskBoth`, avoiding separate destructor + free calls.
  - **Deleter flag protocol**: Deleter receives `int flags` bitmask. `kTVMFFIObjectDeleterFlagBitMaskStrong` (bit 0) = call destructor. `kTVMFFIObjectDeleterFlagBitMaskWeak` (bit 1) = free memory. Common case: both flags set simultaneously.
  - **Two-phase destruction**: When weak references outlive strong references, the destructor is called (strong flag) when `strong_ref_count` drops to zero, but memory is not freed until `weak_ref_count` also drops to zero (weak flag).

- **`WeakObjectPtr<T>`**: A full weak pointer smart pointer class in `include/tvm/ffi/object.h`:
  - Constructible from `ObjectPtr<T>`, `WeakObjectPtr<T>`, or nullptr.
  - `lock()` -> `ObjectPtr<T>`: atomically attempts to promote the weak reference to a strong reference via `TryPromoteWeakPtr()` (CAS loop on `strong_ref_count`).
  - `expired()`: returns `true` if data is nullptr or `use_count() == 0`.
  - Full copy/move/swap/reset semantics.
  - Template-based inheritance support (base-class weak pointers from derived strong pointers).

- **`TVMFFIObjectIncRef` / `TVMFFIObjectDecRef` C API**: The old `TVMFFIObjectFree` is renamed to `TVMFFIObjectDecRef` for clarity. `TVMFFIObjectIncRef` is added as a symmetric counterpart, both as `extern "C"` functions in `src/ffi/object.cc`.

## Reflection

### Design docs to write

- **`.knowledge/designs/0003-object-system.md` (update)**: The existing object system design doc must be updated to reflect:
  - The 24-byte `TVMFFIObject` header (was 16 bytes)
  - The `weak_ref_count` / `strong_ref_count` split
  - The implicit weak reference convention (`weak_ref_count = 1` at allocation)
  - The `WeakObjectPtr<T>` class and its `TryPromoteWeakPtr` CAS protocol
  - The flag-based deleter contract and two-phase destruction
  - This update is critical because many future commits touching object lifetime, allocators, or language bindings will need to reference the weak RC semantics.

- **`.knowledge/designs/0001-c-abi.md` (update)**: The C ABI design doc must be updated to reflect:
  - `TVMFFIObject` is now 24 bytes (the "16-byte layout invariant" section and multiple references to 16 bytes are now wrong)
  - The new `TVMFFIObjectDeleterFlagBitMask` enum
  - The changed deleter signature: `void(*)(TVMFFIObject*, int flags)`
  - The `TVMFFIObjectFree` -> `TVMFFIObjectDecRef` rename and addition of `TVMFFIObjectIncRef`
  - The "Object cell at offset 16" contract still holds (cell data at `sizeof(TVMFFIObject)` is now 24)

### ADRs to write

- **`.knowledge/ADRs/0023-weak-rc-abi-design.md`**: Record the decision to use split `uint32_t weak_ref_count` + `uint64_t strong_ref_count` rather than alternatives:
  - **Context**: Weak RC needed for future cyclic dependency breaking. Must be ABI-compatible before ABI freeze.
  - **Alternatives**: (1) Single 64-bit ref count with bit-field splitting (torch c10 approach), (2) Separate control block (std::shared_ptr approach), (3) No weak RC (defer to application-level cycle breaking).
  - **Trade-offs**: The chosen approach keeps the header at 24 bytes (vs 32 with a control block), uses `uint32_t` for weak (rarely used) to save space, but grows all objects by 8 bytes universally even though weak RC "is not strongly needed yet" per the commit message. The implicit `weak_ref_count = 1` avoids extra bookkeeping for strong-only objects.

### Design diagrams to draw

- **Mermaid sequence diagram**: Depict the two-phase destruction protocol showing the interplay between `DecRef` (strong) and `DecWeakRef` for three scenarios: (1) common case -- strong and weak go to zero together, (2) weak outlives strong, (3) `TryPromoteWeakPtr` succeeds vs. fails. This would clarify the CAS loop and flag dispatch in `DecRef`.
