# Introduce weak RC support to the FFI ABI with split strong/weak counters and flag-based deleter protocol

## TL;DR
- `TVMFFIObject` header grows from 16 to 24 bytes: `ref_counter: int32` is replaced by `weak_ref_count: uint32` + `strong_ref_count: uint64`; the deleter signature adds an `int flags` parameter using the new `TVMFFIObjectDeleterFlagBitMask` bitmask.
- A new `WeakObjectPtr<T>` smart pointer mirrors `std::weak_ptr`: holds a weak reference, exposes `lock()` (CAS-based promotion), `expired()`, and `reset()`.
- `TVMFFIObjectFree` is renamed to `TVMFFIObjectDecRef`; `TVMFFIObjectIncRef` is added as a new C API function. Both Python Cython bindings and the version string (`0.1.0a5 → 0.1.0a6`) are updated accordingly.

## Impact
- API: **Breaking ABI change** — `sizeof(TVMFFIObject)` changes from 16 to 24 bytes. All bindings that hardcode object offsets (e.g., NDArray → DLTensor at offset 16) must update to offset 24. The `static_assert` in `type_traits.h` and `test_c_ffi_abi.cc` is updated. `TVMFFIObjectFree` is removed; callers (Cython `object.pxi`, C code) must switch to `TVMFFIObjectDecRef`.
- Behavioral: Strong RC semantics unchanged from the caller's perspective. Deleter is now called with flags instead of no args; existing deleters compiled against the old signature will silently misbehave (link-time compat only within a single build).
- Flags/config: Version bumped `0.1.0a5 → 0.1.0a6` in `pyproject.toml`, signaling ABI-incompatible release.
- Data formats/schemas: `TVMFFIObject` struct layout permanently changed (24 bytes). Any serialized binary blobs containing raw object headers are invalidated.

## Usage Examples

**WeakObjectPtr basic usage** (from `tests/cpp/test_object.cc`):
```cpp
ObjectPtr<TIntObj> strong = make_object<TIntObj>(42);
WeakObjectPtr<TIntObj> weak(strong);   // weak RC incremented

// lock() succeeds while strong is alive
ObjectPtr<TIntObj> locked = weak.lock();   // CAS promotes; strong count now 2
assert(locked->value == 42);

// After all strong refs drop, lock() returns nullptr
strong.reset();
locked.reset();
assert(weak.expired());
assert(weak.lock() == nullptr);
```

**Deleter update for custom allocators** — `SimpleObjAllocator::Deleter_` (from `memory.h`):
```cpp
// Old:
static void Deleter_(TVMFFIObject* objptr) {
    T* tptr = ...;
    tptr->T::~T();          // always: destruct
    delete reinterpret_cast<StorageType*>(tptr);  // always: free
}

// New — flags gate which actions to take:
static void Deleter_(TVMFFIObject* objptr, int flags) {
    T* tptr = ...;
    if (flags & kTVMFFIObjectDeleterFlagBitMaskStrong) { tptr->T::~T(); }
    if (flags & kTVMFFIObjectDeleterFlagBitMaskWeak)   { delete reinterpret_cast<StorageType*>(tptr); }
}
// Common case: both flags set simultaneously via kTVMFFIObjectDeleterFlagBitMaskBoth (single deleter call)
```
