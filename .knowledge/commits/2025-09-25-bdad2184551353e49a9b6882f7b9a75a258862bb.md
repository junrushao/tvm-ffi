# Fix type mismatch abort on OpaquePyObject by registering its type index

## TL;DR
- Registers `kTVMFFIOpaquePyObject` as a builtin type index via `ReserveBuiltinTypeIndex`, fixing a crash when type-mismatch errors tried to format the type key for `OpaquePyObject` values.
- Adds `StaticTypeKey::kTVMFFIOpaquePyObject = "ffi.OpaquePyObject"` constant.
- Adds `testing.add_one` helper function and `test_opaque_type_error` test verifying the error message.

## Key Exports

**Constants**:
- `StaticTypeKey::kTVMFFIOpaquePyObject` = `"ffi.OpaquePyObject"` (new static type key)

**Functions**:
- `testing.add_one(int) -> int` -- test-only global function

## Impact
- API: none
- ABI: none (OpaquePyObject type index was already reserved in the enum, just not registered in the TypeTable)
- Behavioral: Type mismatch errors involving `OpaquePyObject` now produce a readable error message instead of aborting.
- Flags/config: none
- Data formats/schemas: none
