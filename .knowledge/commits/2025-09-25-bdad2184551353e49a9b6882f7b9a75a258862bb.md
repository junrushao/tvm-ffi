# Register OpaquePyObject as builtin type index so type-mismatch errors propagate correctly instead of aborting

## TL;DR
- `TypeIndex::kTVMFFIOpaquePyObject` (74) was never registered in `TypeTable` as a builtin type index; when an `OpaquePyObject` argument triggered `GetMismatchTypeInfo`, `TypeTable::GetTypeEntry(74)` returned nullptr, `TVM_FFI_ICHECK` threw `InternalError`, and `TVM_FFI_LOG_EXCEPTION_CALL_END` in `TVMFFIGetTypeInfo` caught it and called `exit(-1)` — causing the whole process to abort instead of raising a Python `TypeError`.
- Fix: add `ReserveBuiltinTypeIndex(StaticTypeKey::kTVMFFIOpaquePyObject, TypeIndex::kTVMFFIOpaquePyObject)` to `TypeTable::InitBuiltinTypeIndex()` and add the matching `StaticTypeKey::kTVMFFIOpaquePyObject = "ffi.OpaquePyObject"` constant.
- A `testing.add_one` C++ / Python helper is added so tests can verify typed-function type-mismatch behavior without relying on existing helpers.

## Impact
- API: None for public API. `StaticTypeKey::kTVMFFIOpaquePyObject` is a new public C++ constant, but is purely additive.
- Behavioral: Feeding an `OpaquePyObject` to a typed FFI function now raises `TypeError` with a proper message (`"Expected 'int' but got 'ffi.OpaquePyObject'"`) instead of aborting the process via `exit(-1)`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- **0014-opaque-pyobject** — `TypeIndex::kTVMFFIOpaquePyObject = 74`; `TVMFFIOpaqueObjectCell`; the `GetMismatchTypeInfo` → `TVMFFIGetTypeInfo` → `TypeTable::GetTypeEntry` call chain.
- **0001-c-abi** — `TypeIndex` static index enumeration; `TVMFFIGetTypeInfo` C ABI function; `TVM_FFI_LOG_EXCEPTION_CALL_END` abort path (the root cause of the crash).
- **0002-object-system** — `TypeTable::ReserveBuiltinTypeIndex` / `InitBuiltinTypeIndex`; `TVM_FFI_ICHECK`.
- **0008-type-traits** — `TypeTraitsBase::GetMismatchTypeInfo` which triggers the bad `TVMFFIGetTypeInfo` call.

Design elements this commit produces:
- **0002-object-system** (mutated): `TypeTable::InitBuiltinTypeIndex` now covers all static `TypeIndex` constants; the invariant "every static type index must be reserved here" is tightened.
- **0014-opaque-pyobject** (mutated): `StaticTypeKey::kTVMFFIOpaquePyObject` is now declared in `object.h` (previously absent), making `"ffi.OpaquePyObject"` a compile-time constant alongside other builtins.

## Usage Examples

**Before (broken):**
```python
import tvm_ffi

obj = MyPythonClass("hello")   # wrapped as OpaquePyObject inside FFI
# Calling a typed function expecting int with an OpaquePyObject:
tvm_ffi.get_global_func("testing.add_one")(obj)
# → TVMFFIGetTypeInfo exit(-1) — process aborts with:
#   "Exception caught during TVMFFIGetTypeInfo: InternalError: Cannot find type info for type_index=74"
```

**After (fixed):**
```python
import tvm_ffi
import pytest

obj = MyPythonClass("hello")
with pytest.raises(TypeError) as e:
    tvm_ffi.testing.add_one(obj)
# → TypeError: Mismatched type on argument #0 when calling:
#   `testing.add_one(0: int) -> int`. Expected `int` but got `ffi.OpaquePyObject`
```

## Reflection

### Design docs / ADRs to write or update
- `.knowledge/design-records/0001-c-abi.md` — document the `TVM_FFI_LOG_EXCEPTION_CALL_END`/`exit(-1)` constraint: functions using this macro (not `TVM_FFI_SAFE_CALL_BEGIN`) will abort on internal errors; list which C-ABI functions use each macro variant. This helps future contributors understand when an internal check failure is recoverable vs fatal.
- `.knowledge/design-records/0002-object-system.md` — add the invariant: "every `TypeIndex` with a static constant must have a corresponding `ReserveBuiltinTypeIndex` call in `TypeTable::InitBuiltinTypeIndex`; omitting one will cause abort on the error-reporting path."
- `.knowledge/design-records/0014-opaque-pyobject.md` — add `StaticTypeKey::kTVMFFIOpaquePyObject` to the documented symbols; note that prior to this commit the type key string was absent from compile-time constants.

### Stale knowledge references
- `.knowledge/design-records/0014-opaque-pyobject.md` — does not mention `StaticTypeKey::kTVMFFIOpaquePyObject`; should be updated to include this constant. Severity: `low` (single file, additive).
- `.knowledge/design-index.md` entry for `0001-c-abi` — does not mention `TVM_FFI_LOG_EXCEPTION_CALL_END`'s `exit(-1)` behavior or which ABI functions use it vs `TVM_FFI_SAFE_CALL_BEGIN`. Severity: `low` (informational gap, single file).
