# Fix abort-on-type-mismatch for OpaquePyObject by registering its builtin type index
## TL;DR
- Registers `kTVMFFIOpaquePyObject` (type index 74, type key `"ffi.OpaquePyObject"`) in the `TypeTable` builtin initialization, fixing an `exit(1)` abort when `GetMismatchTypeInfo` tried to look up the type key for an unregistered OpaquePyObject during type-mismatch error formatting.
- Adds `StaticTypeKey::kTVMFFIOpaquePyObject = "ffi.OpaquePyObject"` constant in `object.h`.
- Adds `testing.add_one` global function and `test_opaque_type_error` test to verify proper `TypeError` message instead of abort.

## Impact
- API: Adds `StaticTypeKey::kTVMFFIOpaquePyObject` constant. No breaking changes.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **TypeTable builtin reservation** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Uses `ReserveBuiltinTypeIndex` to register OpaquePyObject alongside other builtin types (Object, Function, Array, etc.).
- **Type mismatch error formatting** ([`.knowledge/designs/0007-error-handling.md`](../designs/0007-error-handling.md)): The `GetMismatchTypeInfo` path in `type_traits.h` calls `TypeIndexToTypeKey` -> `TVMFFIGetTypeInfo`, which requires the type index to be registered. Without registration, the function called `exit(1)`.

Design elements this commit produces:
- None (bugfix only, registers a previously missing builtin type).
