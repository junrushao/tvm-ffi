# Register OpaquePyObject as builtin type index to fix abort on type mismatch
## TL;DR
- When an `OpaquePyObject` was passed to a TVM-FFI function expecting a different type (e.g. `int`), the type mismatch error path called `TVMFFIGetTypeInfo(74)`, which failed because `kTVMFFIOpaquePyObject` was not registered as a builtin type index, causing `exit(-1)` instead of a proper `TypeError`.
- Fix: add `StaticTypeKey::kTVMFFIOpaquePyObject = "ffi.OpaquePyObject"` and call `ReserveBuiltinTypeIndex` for it during `TypeTable` initialization.
- Adds a `testing.add_one` helper and a regression test verifying the proper error message.

## Key Exports

```python

class StaticTypeKey:
    # ... existing keys ...
    kTVMFFIOpaquePyObject: str = "ffi.OpaquePyObject"
    # Interacts with: TypeTable::ReserveBuiltinTypeIndex(), TypeIndex::kTVMFFIOpaquePyObject
    # Invariant: must be registered at TypeTable init so TVMFFIGetTypeInfo(74) succeeds

# Testing helper (python/tvm_ffi/testing.py + src/ffi/extra/testing.cc):
def add_one(x: int) -> int: ...
    # Interacts with: refl::GlobalDef "testing.add_one", used in test_opaque_type_error
```

## Impact
- API: none -- additive only (new `StaticTypeKey` constant, new test helper)
- Behavioral: `OpaquePyObject` type mismatch now raises `TypeError` with message `"Expected int but got ffi.OpaquePyObject"` instead of aborting the process via `exit(-1)`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TypeTable builtin registration** (`ReserveBuiltinTypeIndex`): the mechanism that pre-populates type metadata for static type indices so `TVMFFIGetTypeInfo` can resolve them. See [0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md) and [0003-ffi-object-system](../design-records/0003-ffi-object-system.md).
- **`TVM_FFI_LOG_EXCEPTION_CALL_END` macro**: the error handling wrapper around `TVMFFIGetTypeInfo` that catches exceptions and calls `exit(-1)` -- this is the code path that caused the abort. See `include/tvm/ffi/base_details.h:140`.
- **`TypeTraitsBase::GetMismatchTypeInfo`**: the C++ function that calls `TypeIndexToTypeKey` -> `TVMFFIGetTypeInfo` to produce the type mismatch error message. See [0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md).
- **`OpaquePyObject`** and `kTVMFFIOpaquePyObject` (type_index=74): the opaque Python object wrapper. See [0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md), [0012-ffi-python-package](../design-records/0012-ffi-python-package.md).

Design elements this commit produces:
- None -- this is a bugfix that fills a gap in an existing registration table. No new design elements are introduced.

## Usage Examples

**Before** (process aborts):
```python
import tvm_ffi

class MyObject:
    pass

obj = MyObject()
# Passing an opaque Python object where int is expected
tvm_ffi.testing.add_one(obj)
# => Process aborts with exit(-1):
#    "Exception caught during TVMFFIGetTypeInfo:
#     InternalError: Check failed: (entry != nullptr) is false:
#     Cannot find type info for type_index=74"
```

**After** (proper TypeError):
```python
import tvm_ffi

class MyObject:
    pass

obj = MyObject()
tvm_ffi.testing.add_one(obj)
# => TypeError: Mismatched type on argument #0 when calling:
#    `testing.add_one(0: int) -> int`. Expected `int` but got `ffi.OpaquePyObject`
```

### Design docs / ADRs to write or update
