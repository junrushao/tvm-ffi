# Fix test object-deletion-before-module-unload ordering in load_inline tests
## TL;DR
- Adds documentation to `Module` class docstring explaining the caller-side invariant: objects returned by module-loaded functions have their deleters in the library, so the module must outlive those objects.
- Restructures two test functions (`test_load_inline_with_env_tensor_allocator`, `test_cuda_memory_alloc_noleak`) to use a nested `run_check()` function, ensuring returned tensors are destroyed before the module goes out of scope.

## Design Elements
Design elements this commit consumes:
- **Module / Library lifetime** ([0011-ffi-module-system](../design-records/0011-ffi-module-system.md)): `LibraryModuleObj::GetFunction` captures a strong ref to `self`, keeping the library loaded while any returned `Function` is alive. However, *objects returned by those functions* may have their own deleters that reside in the loaded library's code segment. This commit documents and enforces the caller-side obligation: the module must remain loaded until all such returned objects are destroyed.
- **load_inline** ([0014-ffi-load-inline](../design-records/0014-ffi-load-inline.md)): Tests use `tvm_ffi.cpp.load_inline()` to compile C++ source and load the resulting shared library as a `Module`.

Design elements this commit produces:
- None. The docstring documents a pre-existing invariant; no new API or contract is introduced.

## Usage Examples
Before/after pattern showing the incorrect vs. corrected test structure:

```python
# BEFORE (incorrect): tensor and mod in same scope, deletion order undefined
def test_load_inline_with_env_tensor_allocator():
    mod = tvm_ffi.cpp.load_inline(source=..., functions=["return_add_one"])
    # tensor's deleter lives in mod's loaded library
    y_cpu = mod.return_add_one({"x": [x_cpu]})
    # When function exits, mod and y_cpu destroyed in arbitrary order
    # If mod destroyed first -> y_cpu's deleter calls into freed memory

# AFTER (correct): nested function ensures tensor is destroyed before mod
def test_load_inline_with_env_tensor_allocator():
    mod = tvm_ffi.cpp.load_inline(source=..., functions=["return_add_one"])
    def run_check():
        y_cpu = mod.return_add_one({"x": [x_cpu]})
        # y_cpu destroyed when run_check() returns
    run_check()
    # mod still alive here; safely destroyed after run_check
```
