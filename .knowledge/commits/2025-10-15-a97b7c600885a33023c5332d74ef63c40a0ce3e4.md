# Fix module-unload-before-object-deletion hazard in load_inline tests and document the invariant in Module

## TL;DR
- Two tests in `test_load_inline.py` had a use-after-unload hazard: objects returned by a module function were created at the same scope level as the `mod` variable, so CPython's refcount destruction order was non-deterministic — the tensor's deleter (which lives in the loaded `.so`) could be called after `dlclose`. Fixed by wrapping the object-using code in a nested `run_check()` function so all returned objects are destroyed before `mod` goes out of scope.
- The `Module` class docstring (`module.py`) gains a `Notes` section with an explicit invariant and a `bad_pattern` / `good_pattern` code example documenting this lifecycle rule.
- The test that previously skipped on `torch is None` now asserts `torch is not None`, making the guard stricter.

## Key Exports

```python
# python/tvm_ffi/module.py — Module class docstring addition (no code change)

class Module(Object):
    """...
    Notes
    -----
    # NEW INVARIANT (this commit): Module must outlive all objects it created.
    # If a module-returned object's deleter lives in the .so, and the .so is
    # unloaded (module goes out of scope) before the object is destroyed,
    # the deleter calls an invalid address → segfault / undefined behavior.
    #
    # Safe pattern: wrap object usage in a nested function so objects are freed
    # before mod goes out of scope.
    #
    # bad_pattern: mod and tensor in same scope — CPython destruction order non-deterministic
    # good_pattern: tensor freed in run_some_tests() before mod's refcount drops to 0
    #
    # Interacts with: DSOLibrary (dlopen/dlclose lifecycle), ModuleObj ref-counting
    # Invariant: caller must ensure Module outlives all objects whose deleters reside in that .so
    """
```

## Design Elements

Design elements this commit consumes:
- **0011-module-system**: `Module` (`ModuleObj`/`Module`) and its DSO lifetime semantics. The invariant being documented is that `DSOLibrary` (`dlopen`-backed) holds a handle that is released when the `Module` ref-count drops to 0. Any object whose deleter address was resolved from the DSO becomes a dangling pointer after that.
- **0015-load-inline**: `load_inline` / `build_inline` produce `Module`-loadable `.so` files; the tests are directly exercising these functions' return values and the module lifecycle.

Design elements this commit produces:
- **Module lifetime invariant** (added to `module.py` docstring): explicit statement that `Module` must outlive all objects it created, with bad/good usage examples. This is a new documented invariant for the `0011-module-system` design record.

## Usage Examples

**Before (incorrect — non-deterministic destruction order):**
```python
def test_load_inline_with_env_tensor_allocator():
    mod = tvm_ffi.cpp.load_inline(...)
    if torch is not None:          # silent skip if torch missing — bug mask
        x_cpu = torch.asarray(...)
        y_cpu = mod.return_add_one({"x": [x_cpu]})
        # `y_cpu` and `mod` both go out of scope together here —
        # CPython may call y_cpu.__del__ AFTER mod.__del__ (dlclose),
        # resulting in a call to a deleter at an invalid address.
```

**After (correct — objects freed before module unloads):**
```python
def test_load_inline_with_env_tensor_allocator():
    mod = tvm_ffi.cpp.load_inline(...)
    assert torch is not None       # fail-fast instead of silent skip

    def run_check() -> None:
        """Must run in a separate function to ensure deletion happens before mod unloads."""
        x_cpu = torch.asarray(...)
        y_cpu = mod.return_add_one({"x": [x_cpu]})
        # y_cpu freed here (end of run_check frame) — before mod's refcount drops
        assert ...

    run_check()
    # mod freed here — after run_check returned, all returned objects already gone
```
