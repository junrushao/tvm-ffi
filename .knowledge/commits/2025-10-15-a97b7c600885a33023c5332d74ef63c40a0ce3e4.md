# Fix test object lifetime ordering and document Module unload hazard
## TL;DR
- Added documentation to `Module` class warning that objects returned by module functions must be destroyed before the module is unloaded, because their deleters reside in the loaded library's code.
- Fixed two tests (`test_load_inline_with_env_tensor_allocator`, `test_cuda_memory_alloc_noleak`) by wrapping test logic in nested `run_check()` functions to guarantee returned tensors are freed before the module goes out of scope.

## Key Exports
None (no new public API surface; documentation-only change to existing `Module` class and test restructuring).

## Impact
- API: none
- Behavioral: none (tests were non-deterministically failing due to undefined destruction order; fix makes them reliable)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Module system: `Module` / `load_module()` -- objects returned from module functions have deleters pointing into the DSO's code segment ([0011-module-system](.knowledge/design-records/0011-module-system.md))
- Object system deleter protocol: `TVMFFIObjectDeleterFlagBitMask` -- the deleter function pointer lives in the DSO ([0002-object-system](.knowledge/design-records/0002-object-system.md))
- load_inline: `tvm_ffi.cpp.load_inline()` compiles and loads DSO at runtime ([0013-load-inline](.knowledge/design-records/0013-load-inline.md))

Design elements this commit produces:
- New documented invariant on `Module` class: **objects returned by module functions must be destroyed before the module is unloaded**. The deleter function address is part of the loaded library's code; if the library is unloaded first, the deleter calls an invalid address. Recommended pattern: use a nested function scope so returned objects are freed before the module variable goes out of scope.

## Usage Examples
Before/after pattern showing incorrect vs corrected usage:

```python
# BEFORE (bad): unload order of `tensor` and `mod` is not guaranteed
def test_something():
    mod = tvm_ffi.cpp.load_inline(name="lib", cpp_sources=..., functions=["create_tensor"])
    tensor = mod.create_tensor(x)  # tensor's deleter lives in mod's DSO
    # When test_something returns, Python may destroy `mod` before `tensor`,
    # causing tensor's deleter to call into unloaded code.

# AFTER (good): nested function ensures tensor is destroyed first
def test_something():
    mod = tvm_ffi.cpp.load_inline(name="lib", cpp_sources=..., functions=["create_tensor"])
    def run_check():
        tensor = mod.create_tensor(x)
        # ... use tensor ...
    run_check()
    # `tensor` is guaranteed destroyed when run_check() returns,
    # `mod` is still alive here.
```
