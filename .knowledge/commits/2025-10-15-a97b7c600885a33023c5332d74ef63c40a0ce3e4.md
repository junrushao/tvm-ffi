# Fix test object-before-module deletion order and document Module lifetime invariant
## TL;DR
- Wraps tensor-returning test code in nested `run_check()` functions in `test_load_inline_with_env_tensor_allocator` and `test_cuda_memory_alloc_noleak` to guarantee returned objects are destroyed before the `Module` goes out of scope.
- Adds a `Notes` docstring section to the `Module` class documenting the "module must outlive returned objects" invariant, with bad/good usage patterns.
- Root cause: when a loaded DSO module returns an object, the object's deleter address resides in the library's code segment; if `dlclose` runs before the deleter, the deleter call jumps to an invalid address (use-after-unload).

## Key Exports
None -- no new public API. The commit documents an existing invariant and restructures tests.

## Impact
- API: none
- Behavioral: Two tests (`test_load_inline_with_env_tensor_allocator`, `test_cuda_memory_alloc_noleak`) now enforce deterministic object lifetime ordering via nested function scoping, preventing nondeterministic use-after-unload crashes.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system / DSOLibrary lifecycle** ([0011-module-system.md](../designs/0011-module-system.md)): `DSOLibrary` calls `dlclose` on destruction. Objects returned by functions in the loaded library have deleters whose code lives in the `.so`. If the `Module` (and thus `DSOLibrary`) is destroyed first, the deleter address becomes invalid.
- **Object ref-counting / deleter protocol** ([ADR 0001](../ADRs/0001-unified-any-object-abi.md), [ADR 0009](../ADRs/0009-weak-reference-counting.md)): The `TVMFFIObject` header contains a `deleter` function pointer set at allocation time. For objects allocated inside a loaded DSO, this pointer points into the DSO's code segment.
- **`load_inline` / `load_module`** ([0011-module-system.md](../designs/0011-module-system.md)): The test pipeline `load_inline -> Module -> mod.func(x)` exercises the full DSOLibrary lifecycle.

Design elements this commit produces:
- **Module lifetime invariant (documentation)**: The `Module` class docstring now formally documents: "Keep the module loaded until all returned objects are deleted." This was an implicit invariant before; it is now explicit with bad/good code patterns.

## Usage Examples
Before/after pattern showing incorrect vs corrected usage:

```python
# BEFORE (bad): object and module destruction order is nondeterministic
def test_foo():
    mod = tvm_ffi.cpp.load_inline(name="hello", cpp_sources="...", functions=["return_tensor"])
    tensor = mod.return_tensor(x)  # tensor's deleter lives in the loaded .so
    # When test_foo returns, Python may GC `mod` before `tensor`,
    # causing dlclose before the tensor deleter runs -> crash

# AFTER (good): nested function guarantees tensor is destroyed first
def test_foo():
    mod = tvm_ffi.cpp.load_inline(name="hello", cpp_sources="...", functions=["return_tensor"])
    def run_check():
        tensor = mod.return_tensor(x)
        # tensor is destroyed when run_check returns
    run_check()
    # mod is destroyed after run_check returns -> safe
```
