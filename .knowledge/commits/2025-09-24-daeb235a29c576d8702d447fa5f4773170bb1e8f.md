# Support `field(init=...)` in `@c_class` fields

## TL;DR
- Adds an `init: bool` parameter to `field()` and `Field`, allowing `@c_class` fields to be excluded from the generated `__init__` signature -- mirroring `dataclasses.field(init=False)` semantics.
- Rewrites `method_init()` in `_utils.py` from an `inspect.Signature`-based approach to a code-generation approach (via `exec`), following the same pattern used by `dataclasses` and `pydantic`. This enables three-way field routing: `init=True` fields appear in `__init__`, `init=False` fields with defaults are computed and forwarded silently, and `init=False` fields without defaults are omitted entirely (left to C++).
- Adds a C++ test object `TestCxxInitSubsetObj` whose constructor takes a subset of its fields, and a corresponding Python proxy `_TestCxxInitSubset` with `field(init=False)` annotations.
- Exposes the `dataclasses` subpackage from `tvm_ffi.__init__` and removes a stale `docs/reference/python/cpp/index.rst` file.

## Key Exports

**`Field` class** (`python/tvm_ffi/dataclasses/field.py`):
```python
class Field:
    __slots__ = ("default_factory", "init", "name")
    def __init__(self, *, name=None, default_factory=MISSING, init: bool = True): ...
```

**`field()` function** (`python/tvm_ffi/dataclasses/field.py`):
```python
def field(*, default=MISSING, default_factory=MISSING, init: bool = True) -> _FieldValue: ...
```

**`method_init()` internal function** (`python/tvm_ffi/dataclasses/_utils.py`):
Rewritten to generate `__init__` via `exec`-based code generation. The generated function has a proper Python signature with only `init=True` fields as parameters.

**`TestCxxInitSubsetObj`** (`src/ffi/extra/testing.cc`):
```cpp
class TestCxxInitSubsetObj : public Object {
 public:
  int64_t required_field;
  int64_t optional_field;
  String note;
  explicit TestCxxInitSubsetObj(int64_t value, String note)
      : required_field(value), optional_field(-1), note(note) {}
  static constexpr bool _type_mutable = true;
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestCxxInitSubset", TestCxxInitSubsetObj, Object);
};
```

**`_TestCxxInitSubset`** (`python/tvm_ffi/testing.py`):
```python
@c_class("testing.TestCxxInitSubset")
class _TestCxxInitSubset:
    required_field: int
    optional_field: int = field(init=False)
    note: str = field(default_factory=lambda: "py-default", init=False)
```

## Impact
- API: `field()` gains a new `init` keyword argument (default `True`). Fully backward-compatible -- existing callers that omit `init` get the same behavior.
- ABI: None. No C ABI changes.
- Behavioral: `method_init()` is completely rewritten. The old implementation used `inspect.Signature` + `bind_args()` at call time; the new implementation generates a concrete `def __init__(...)` function via `exec` at class-creation time. This produces cleaner stack traces and a real Python function signature (visible to `inspect.signature`). The generated `__init__` also now handles the `init=False` field routing logic.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python `c_class` / dataclasses system** (`.knowledge/designs/0014-python-bindings.md`): The `field()` helper, `Field` descriptor, `method_init()` generator, and `fill_dataclass_field()` that together synthesize Python `__init__` methods for `@c_class`-decorated proxy classes.
- **Reflection system** (`.knowledge/designs/reflection.md`): C++ `ObjectDef<Class>` with `def_static("__ffi_init__", refl::init<...>)` for the subset constructor, plus `def_rw` field registration.
- **Python-side TypeInfo metadata** (`TypeInfo`, `TypeField`): The `method_init()` function walks `type_info.fields` and `type_info.methods` to discover fields and verify `__ffi_init__` exists.

Design elements this commit produces:
- **`field(init=False)` pattern for selective __init__ forwarding**: A three-way routing protocol for `@c_class` fields:
  1. `init=True` (default): field appears in `__init__` signature and is forwarded to `__ffi_init__`.
  2. `init=False` with `default`/`default_factory`: field is excluded from `__init__` signature; its default is computed and forwarded to `__ffi_init__` silently.
  3. `init=False` without default: field is excluded from both `__init__` and the `__ffi_init__` call; the C++ constructor must set it.
- **exec-based `__init__` code generation in `method_init()`**: Replaces `inspect.Signature`-based approach with `exec`-based function synthesis (matching `dataclasses` and `pydantic` patterns). The generated function has a real signature, proper defaults (using `MISSING` sentinel for lazy factory invocation), and a flat call to `self.__ffi_init__()`.

## Usage Examples

Defining a C++ class where not all fields appear in the Python constructor:

```cpp
// C++ side: constructor takes a subset of fields
class TestCxxInitSubsetObj : public Object {
  int64_t required_field;
  int64_t optional_field;
  String note;
  explicit TestCxxInitSubsetObj(int64_t value, String note)
      : required_field(value), optional_field(-1), note(note) {}
};
```

```python
# Python side: field(init=False) excludes from __init__
@c_class("testing.TestCxxInitSubset")
class _TestCxxInitSubset:
    required_field: int
    optional_field: int = field(init=False)           # C++ sets to -1
    note: str = field(default_factory=lambda: "py-default", init=False)  # forwarded silently

obj = _TestCxxInitSubset(required_field=42)
assert obj.required_field == 42
assert obj.optional_field == -1   # set by C++ constructor
assert obj.note == "py-default"   # default_factory value forwarded to C++
```

The generated `__init__` signature only exposes `required_field`:
```python
import inspect
sig = inspect.signature(_TestCxxInitSubset.__init__)
assert "required_field" in sig.parameters
assert "optional_field" not in sig.parameters
assert "note" not in sig.parameters
```
