# Support field(init=...) in @c_class fields
## TL;DR
- Adds `init: bool` parameter to `field()` and `Field`, allowing fields to be excluded from the generated `__init__` signature (matching Python `dataclasses.field(init=False)` semantics).
- Rewrites `method_init` in `_utils.py` to use `exec`-based code generation instead of `inspect.Signature.bind()`, generating a proper Python function with explicit parameters for better performance and error messages.
- Fields with `init=False` and a `default_factory` have their defaults forwarded to the C++ constructor; fields with `init=False` and no default are not forwarded (must be initialized by C++).
- Adds C++ testing class `TestCxxInitSubsetObj` and corresponding Python test.

## Impact
- API: `field(init=False)` is now supported in `@c_class` declarations. New `Field.init` attribute.
- Flags/config: none
- Data formats/schemas: none
