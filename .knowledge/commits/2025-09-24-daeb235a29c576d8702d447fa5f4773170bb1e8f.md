# Support field(init=...) in @c_class fields for selective __init__ parameter inclusion

## TL;DR
- Adds `init: bool = True` parameter to `field()` and `Field` class, allowing `@c_class` fields to be excluded from the generated Python `__init__` signature while optionally forwarding defaults to the C++ `__ffi_init__` constructor.
- Rewrites `method_init` from `inspect.Signature`-based argument binding to `exec()`-based code generation (following the `dataclasses`/`pydantic` pattern), which natively supports the three-way `init` x `default` field dispatch.
- Adds `TestCxxInitSubsetObj` C++ test class and Python proxy `_TestCxxInitSubset` demonstrating the feature end-to-end.

## Key Exports

**`field()` function** (`python/tvm_ffi/dataclasses/field.py`) -- updated signature:
```python
def field(
    *,
    default: Any | MISSING = MISSING,
    default_factory: Callable[[], Any] | MISSING = MISSING,
    init: bool = True,  # NEW
) -> Field: ...
```

**`Field` class** (`python/tvm_ffi/dataclasses/field.py`) -- updated:
```python
class Field:
    __slots__ = ("default_factory", "init", "name")  # "init" added
    def __init__(self, *, name=None, default_factory=MISSING, init=True): ...
```

**`method_init` function** (`python/tvm_ffi/dataclasses/_utils.py`) -- rewritten internals:
- Signature unchanged: `method_init(type_cls: type, type_info: TypeInfo) -> Callable[..., None]`
- Implementation changed from `inspect.Signature` + `bind_args` closure to `exec()`-based code generation.
- Three-way field dispatch logic:
  - `init=True, no default` -> positional arg in `__init__`, forwarded to `__ffi_init__`
  - `init=True, has default` -> keyword arg with sentinel in `__init__`, forwarded to `__ffi_init__`
  - `init=False, has default` -> not in `__init__` args, default computed and forwarded to `__ffi_init__`
  - `init=False, no default` -> not in `__init__` args, NOT forwarded to `__ffi_init__` (C++ handles it)

**`TestCxxInitSubsetObj`** (`src/ffi/extra/testing.cc`) -- new test class:
```cpp
class TestCxxInitSubsetObj : public Object {
 public:
  int64_t required_field;
  int64_t optional_field;  // not in __ffi_init__ signature
  String note;             // not in __ffi_init__ signature
  explicit TestCxxInitSubsetObj(int64_t value, String note)
      : required_field(value), optional_field(-1), note(note) {}
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestCxxInitSubset", TestCxxInitSubsetObj, Object);
};
// Reflection: __ffi_init__ takes (int64_t, String) -- only 2 of 3 fields
```

## Impact
- API: `field()` gains a new keyword-only parameter `init: bool = True`. Fully backward-compatible; existing calls without `init=` are unaffected.
- Behavioral: Generated `__init__` methods now use `exec()`-based code generation instead of `inspect.Signature`. External behavior is preserved, but `__init__.__signature__` is no longer explicitly set (it is implicitly correct from the generated function definition). The `DefaultFactory` NamedTuple wrapper is eliminated.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python TypeInfo metadata model** (`TypeInfo`, `TypeField`, `TypeMethod`): traverses `type_info.parent_type_info` chain to collect fields from the type hierarchy. See commit `53b2e00`.
- **`TypeField.dataclass_field`** attribute: reads `dataclass_field.init` and `dataclass_field.default_factory` to determine init/forwarding behavior. Set by `fill_dataclass_field()`.
- **C++ `ObjectDef<T>` reflection** with `__ffi_init__`: the C++ constructor is registered as a static method via `refl::init<T, Args...>`, and the Python `__init__` forwards selected args to it. See [0009-reflection.md](../designs/0009-reflection.md).
- **`c_class` decorator pipeline** (`_utils.py`): `fill_dataclass_field` -> `method_init` -> `type_info_to_cls`. This commit modifies `method_init` and `field.py` within this pipeline.

Design elements this commit produces:
- **`field(init=...)` three-way dispatch protocol**: A cross-language contract governing which fields are forwarded from Python `__init__` to C++ `__ffi_init__`. This is a new design element not yet documented in `.knowledge/designs/`.
- **`exec()`-based `__init__` code generation**: Replaces `inspect.Signature`-based binding. Follows the `dataclasses` stdlib pattern. More flexible for future field descriptor extensions.

## Usage Examples

End-to-end: C++ class with partial constructor, Python proxy with `field(init=False)`:

```cpp
// C++ side (src/ffi/extra/testing.cc)
class TestCxxInitSubsetObj : public Object {
 public:
  int64_t required_field;
  int64_t optional_field;
  String note;
  explicit TestCxxInitSubsetObj(int64_t value, String note)
      : required_field(value), optional_field(-1), note(note) {}
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestCxxInitSubset", TestCxxInitSubsetObj, Object);
};
// Reflection registers __ffi_init__ with (int64_t, String) -- 2 params, not 3
```

```python
# Python side (python/tvm_ffi/testing.py)
@c_class("testing.TestCxxInitSubset")
class _TestCxxInitSubset:
    required_field: int                                             # init=True (default)
    optional_field: int = field(init=False)                         # excluded from __init__, no default -> C++ sets to -1
    note: str = field(default_factory=lambda: "py-default", init=False)  # excluded from __init__, default forwarded to C++

obj = _TestCxxInitSubset(required_field=42)
assert obj.required_field == 42
assert obj.optional_field == -1      # set by C++ constructor
assert obj.note == "py-default"      # default_factory value forwarded to C++
```
