# Support `field(init=...)` in `@c_class` fields

## TL;DR
- Adds `init: bool` parameter to `field()` and `Field` in `python/tvm_ffi/dataclasses/field.py`, allowing `@c_class` fields to be excluded from the generated `__init__` signature (matching Python `dataclasses.field(init=False)` semantics).
- Rewrites `method_init()` in `python/tvm_ffi/dataclasses/_utils.py` from an `inspect.Signature`-based approach to code-generation via `exec()` (the same strategy used by stdlib `dataclasses` and `pydantic`), which naturally supports `init=False` fields with or without default factories.
- Adds C++ test class `TestCxxInitSubsetObj` in `src/ffi/extra/testing.cc` whose constructor only accepts a subset of its reflected fields, plus Python proxy `_TestCxxInitSubset` and three pytest cases validating signature exclusion, default forwarding, and mutability.
- Exposes `tvm_ffi.dataclasses` as a public subpackage in `python/tvm_ffi/__init__.py`.
- Restructures `docs/reference/python/` by inlining the `cpp/index.rst` toctree entry and adding commented-out placeholders for future `dataclasses.c_class` / `dataclasses.field` autodoc entries.

## Key Exports

```python
# python/tvm_ffi/dataclasses/field.py
def field(
    *,
    default: object = MISSING,
    default_factory: Callable[[], object] | None = MISSING,
    init: bool = True,           # <-- NEW
) -> Any:
    """Declare a dataclass-style field on a @c_class proxy.

    Parameters
    ----------
    init : bool, default True
        If True, the field appears in the generated __init__.
        If False, the field is omitted from __init__ input arguments.

        When init=False:
        - With a default/default_factory: the computed value is still
          forwarded to the C++ __ffi_init__ constructor.
        - Without a default/default_factory: the field is NOT forwarded
          to C++ __ffi_init__ and must be initialized by the C++ constructor.
    """

class Field:
    __slots__ = ("default_factory", "init", "name")
    # init: bool  -- NEW slot

# python/tvm_ffi/dataclasses/_utils.py
def method_init(type_cls: type, type_info: TypeInfo) -> Callable[..., None]:
    """Generate __init__ via exec()-based code generation.

    Interacts with: TypeInfo.fields (reflected field list from C++),
                    TypeField.dataclass_field (Field descriptor),
                    Field.init (new flag),
                    Field.default_factory,
                    __ffi_init__ (C++ constructor method),
                    __post_init__ (optional user hook).

    The generated source has the form:
        def __init__(self, <args_no_defaults>, <args_with_defaults>=MISSING):
            if <name> is MISSING: <name> = _default_factory_<name>()  # for init=True with factory
            <name> = _default_factory_<name>()                         # for init=False with factory
            self.__ffi_init__(<ffi_arg_order>)
            try:
                fn_post_init = self.__post_init__
            except AttributeError:
                pass
            else:
                fn_post_init()

    ffi_arg_order includes all init=True fields plus init=False fields
    that have a default_factory. Fields with init=False and no default
    are entirely omitted from the __ffi_init__ call.
    """
```

## Impact
- API: `field()` gains `init` keyword (default `True`); fully backward-compatible. `tvm_ffi.dataclasses` is now importable from the top-level package.
- Behavioral: `__init__` generation switches from `inspect.Signature.bind()` + `DefaultFactory` wrapper to `exec()`-based code generation. Functionally equivalent for `init=True` fields; enables the new `init=False` exclusion. The `import inspect` is removed from `_utils.py`.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`ObjectDef<T>`, `TypeInfo`, `TypeField`): The reflected field list and `__ffi_init__` method info drive `__init__` generation. See [0008-reflection.md](../designs/0008-reflection.md).
- **`@c_class` decorator pipeline** (`_utils.py`, `field.py`): The decorator fills `TypeField.dataclass_field` with a `Field` descriptor, then calls `method_init()` to build `__init__`. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **`refl::init<T, Args...>`**: C++ reflection helper that registers a typed constructor; used in `testing.cc` to register `TestCxxInitSubsetObj(int64_t, String)`.

Design elements this commit produces:
- **`field(init=False)` protocol**: A field marked `init=False` is excluded from the Python `__init__` signature. If it has a `default_factory`, the default value is still forwarded to `__ffi_init__`. If it has no default, it is omitted from the `__ffi_init__` call entirely and the C++ constructor is responsible for initializing it. This enables partial-init patterns where the C++ constructor sets fields that should not be user-visible.
- **`exec()`-based `__init__` generation**: Replaces the `inspect.Signature`-based approach. The generated function source is built from field metadata and `exec()`-ed in a controlled namespace. This is the same pattern used by Python `dataclasses` and `pydantic`.

## Usage Examples

**C++ side**: define a class where `optional_field` is not a constructor parameter:
```cpp
class TestCxxInitSubsetObj : public Object {
 public:
  int64_t required_field;
  int64_t optional_field;
  String note;

  explicit TestCxxInitSubsetObj(int64_t value, String note)
      : required_field(value), optional_field(-1), note(note) {}

  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestCxxInitSubset", TestCxxInitSubsetObj, Object);
};

// Registration: __ffi_init__ only takes (int64_t, String)
refl::ObjectDef<TestCxxInitSubsetObj>()
    .def_static("__ffi_init__", refl::init<TestCxxInitSubsetObj, int64_t, String>)
    .def_rw("required_field", &TestCxxInitSubsetObj::required_field)
    .def_rw("optional_field", &TestCxxInitSubsetObj::optional_field)
    .def_rw("note", &TestCxxInitSubsetObj::note);
```

**Python side**: mark non-constructor fields with `init=False`:
```python
@c_class("testing.TestCxxInitSubset")
class _TestCxxInitSubset:
    required_field: int
    optional_field: int = field(init=False)                                  # excluded from __init__
    note: str = field(default_factory=lambda: "py-default", init=False)      # excluded but default forwarded

obj = _TestCxxInitSubset(required_field=42)
assert obj.required_field == 42
assert obj.optional_field == -1       # set by C++ constructor
assert obj.note == "py-default"       # default_factory value forwarded to C++
```

**Signature verification** (from tests):
```python
import inspect
sig = inspect.signature(_TestCxxInitSubset.__init__)
assert "required_field" in sig.parameters
assert "optional_field" not in sig.parameters
assert "note" not in sig.parameters
```
