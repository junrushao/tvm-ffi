# Add field(init=False) support to @c_class, enabling Python-side fields excluded from __init__ but still forwarded to C++ constructor

## TL;DR

- `field(init=False)` is now accepted; such fields are excluded from the generated `__init__` signature but their `default_factory` value (if any) is still forwarded to the C++ `__ffi_init__` constructor.
- The `method_init` code generator was rewritten from `inspect.Signature`-based dynamic binding to a `exec()`-compiled function string, removing the `inspect` dependency and aligning with the approach used by stdlib `dataclasses` and pydantic.
- A new C++ testing fixture (`TestCxxInitSubsetObj`) with two fields excluded from the Python constructor demonstrates the full C++/Python cross-layer behavior.

## Impact

- API: `field()` gains an `init: bool = True` keyword argument. `Field.__slots__` gains `"init"`. Callers not using the new parameter are unaffected.
- Behavioral: `method_init` now uses `exec()` to build `__init__` rather than `inspect.Signature`. The observable signature differs: previously `__init__.__signature__` was set as an attribute; now the function is genuinely defined with the correct parameter names. Positional argument passing now works correctly (no `bind_args` reordering needed). The `__post_init__` hook behavior is unchanged.
- Flags/config: none.
- Data formats/schemas: `tvm_ffi.dataclasses` is now exported from `tvm_ffi.__init__` top-level (was not previously exported in `__all__`).

## Design Elements

Design elements this commit consumes:
- `Field` / `field()` from `python/tvm_ffi/dataclasses/field.py` — the dataclass-field descriptor; mutated by this commit.
- `method_init` in `python/tvm_ffi/dataclasses/_utils.py` — `__init__` code generator; rewritten.
- `TypeField.dataclass_field` in core reflection — carries `Field` instances from class body to `method_init`.
- `refl::ObjectDef<T>` / `TVM_FFI_DECLARE_OBJECT_INFO` — used to register `TestCxxInitSubsetObj` (consumes 0006-reflection).
- `TypeInfo.methods` / `__ffi_init__` convention — the C++ constructor is always named `__ffi_init__` and must be present (consumes 0006-reflection, 0013-python-package).

Design elements this commit produces:
- `field(init=...)` protocol — new attribute on `Field`; extends the `c_class` dataclass system to support constructor-subset fields. No design record exists yet (see Reflection).
- `exec()`-based `__init__` codegen pattern — replaces `inspect`-based dynamic binding with a source-string compilation approach. This is a change to the `method_init` implementation contract.
- `TestCxxInitSubsetObj` C++ testing fixture — documents the init-subset pattern at the C++ level.

## Usage Examples

End-to-end: C++ object with 3 fields, Python constructor exposes only 1, the rest get C++/factory defaults.

```python
# src/ffi/extra/testing.cc — C++ side
class TestCxxInitSubsetObj(Object):
    # __ffi_init__(int64_t value, String note)  ← only 2 args; optional_field initialized to -1

# python/tvm_ffi/testing.py — Python proxy
@c_class("testing.TestCxxInitSubset")
class _TestCxxInitSubset:
    required_field: int
    optional_field: int = field(init=False)            # hidden from __init__, no Python default
    note: str = field(default_factory=lambda: "py-default", init=False)  # hidden, factory forwarded

# tests/python/test_dataclasses_c_class.py — usage
obj = _TestCxxInitSubset(required_field=42)
assert obj.required_field == 42
assert obj.optional_field == -1        # C++ constructor default
assert obj.note == "py-default"        # Python factory forwarded to C++ __ffi_init__

# Signature check: optional_field and note absent
sig = inspect.signature(_TestCxxInitSubset.__init__)
assert "optional_field" not in sig.parameters
assert "note" not in sig.parameters
```
