# Fix unregistered object type fallback in Cython return path
## TL;DR
- Fixed a crash in `make_ret_object` (Cython) when the type index is allocated in the `TYPE_INDEX_TO_INFO` table but the entry is `None` (type registered in C++ but not in Python); previously the code accessed `.type_cls` on a `None` entry.
- Added `TestUnregisteredObject` C++ type and `testing.make_unregistered_object` global function as test infrastructure.
- Added `test_unregistered_object_fallback` Python test verifying the warning-and-fallback-to-Object behavior.

## Impact
- API: none -- no public API changed
- Behavioral: `make_ret_object` no longer throws `AttributeError` when encountering an object whose type index maps to a `None` entry in `TYPE_INDEX_TO_INFO`; it now correctly falls through to the fallback path that emits a `UserWarning` and returns a base `Object`
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**Before (crash):** When C++ returns an object whose type is allocated in the type table but has no Python `register_object` entry, `TYPE_INDEX_TO_INFO[tindex]` is `None`, and the old code accessed `None.type_cls` causing an `AttributeError`.

**After (correct fallback):**
```python
import tvm_ffi
import warnings

# Object type "testing.TestUnregisteredObject" is registered in C++ but not Python
with warnings.catch_warnings(record=True) as w:
    warnings.simplefilter("always")
    obj = tvm_ffi.testing.make_unregistered_object()

assert type(obj) is tvm_ffi.Object  # falls back to base Object
assert len(w) == 1
assert "not registered via register_object" in str(w[0].message)
```
