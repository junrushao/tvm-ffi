# Fix null-dereference in make_ret_object for unregistered object types
## TL;DR
- Fixed a crash in Cython `make_ret_object()` where `TYPE_INDEX_TO_INFO[tindex]` could be `None` for unregistered object types, causing an `AttributeError` instead of the intended fallback-to-`Object` path.
- Added `TestUnregisteredObject` C++ test type (not Python-registered) and `make_unregistered_object()` helper to exercise the fallback.
- Added `test_unregistered_object_fallback` pytest verifying the fallback emits a `UserWarning` and returns a base `Object`.

## Impact
- API: None -- internal Cython codepath fix.
- Behavioral: C++ objects with no `@register_object` Python binding now correctly fall back to `Object` with a `UserWarning`, instead of crashing with `AttributeError`.

## Usage Examples
Before/after pattern for the bugfix:

```python
# BEFORE: TYPE_INDEX_TO_INFO[tindex] is None for unregistered types
#   cls = TYPE_INDEX_TO_INFO[tindex].type_cls  --> AttributeError on None
#   The code assumed TYPE_INDEX_TO_INFO[tindex] was always a valid TypeInfo

# AFTER: Null check added before attribute access
#   type_info = TYPE_INDEX_TO_INFO[tindex]
#   if type_info is not None:
#       cls = type_info.type_cls
#       ...
#   # Falls through to Object fallback with UserWarning

# Test usage:
import tvm_ffi
with pytest.warns(UserWarning, match=r"Returning type.*not registered"):
    obj = tvm_ffi.testing.make_unregistered_object()
assert type(obj) is tvm_ffi.Object
```
