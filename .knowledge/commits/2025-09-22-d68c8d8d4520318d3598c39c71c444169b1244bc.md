# Guard make_ret_object against None slots in TYPE_INDEX_TO_INFO to allow unregistered C++ types to fall back to Object instead of crashing

## TL;DR

- **Bug fixed**: `make_ret_object` in `object.pxi` would raise `AttributeError` when `TYPE_INDEX_TO_INFO[tindex]` was `None` (a C++ type registered but not registered on the Python side); now the `None` slot is guarded and falls through to the existing `UserWarning` + `Object` fallback.
- **Test fixture added**: `TestUnregisteredObject` in `testing.cc` plus `make_unregistered_object()` in `testing.py` provide a first-class testing handle for this scenario.
- **New test**: `test_unregistered_object_fallback` in `test_object.py` verifies the warning message and that `type(obj) is tvm_ffi.Object`.

## Impact

- API: `tvm_ffi.testing.make_unregistered_object()` is new public testing helper; no existing callers affected.
- Behavioral: `make_ret_object` no longer raises `AttributeError` for C++ types whose `TYPE_INDEX_TO_INFO` slot is `None`; now emits `UserWarning` and returns a plain `Object` (the pre-existing fallback was already there for out-of-range indices, but was unreachable for in-range `None` slots).
- Flags/config: none.
- Data formats/schemas: none.

## Usage Examples

**Before (broken):**
```python
# Any call that returned an object whose C++ type_index mapped to a None slot
# in TYPE_INDEX_TO_INFO would raise:
#   AttributeError: 'NoneType' object has no attribute 'type_cls'
obj = some_func_returning_unregistered_type()  # crash
```

**After (fixed):**
```python
import pytest, tvm_ffi

def test_unregistered_object_fallback():
    with pytest.warns(UserWarning,
                      match=r"Returning type `testing\.TestUnregisteredObject` "
                            r"which is not registered via register_object, fallback to Object"):
        obj = tvm_ffi.testing.make_unregistered_object()
    assert type(obj) is tvm_ffi.Object  # plain Object, not a subclass
```
