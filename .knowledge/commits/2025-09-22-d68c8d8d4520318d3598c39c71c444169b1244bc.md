# Fix Cython fallback for objects whose type index is allocated but not Python-registered

## TL;DR
- Fixed a `NoneType` attribute error in `make_ret_object` (Cython) when an object's type index was within the `TYPE_INDEX_TO_INFO` array bounds but the entry itself was `None` (i.e., type registered in C++ but not in Python via `register_object`).
- Added `TestUnregisteredObject` in C++ testing and `make_unregistered_object()` in Python testing to exercise the fallback path.
- Added `test_unregistered_object_fallback` to verify the fix: unregistered types fall back to `Object` with a `UserWarning`.

## Key Exports

**Functions** (testing only):
- `testing.make_unregistered_object` (C++ global func) — returns an `ObjectRef` wrapping a `TestUnregisteredObject(42)` whose type key `"testing.TestUnregisteredObject"` has no Python-side `register_object`.
- `tvm_ffi.testing.make_unregistered_object() -> Object` (Python) — calls the above global func.

**Types** (testing only, not Python-registered by design):
- `TestUnregisteredObject : public Object` — C++ test class with a single `int64_t value` field. Declared with `TVM_FFI_DECLARE_OBJECT_INFO("testing.TestUnregisteredObject", TestUnregisteredObject, Object)`. Intentionally has no Python `register_object` counterpart.

## Impact
- API: None. No public API signature changed.
- Behavioral: `make_ret_object` no longer crashes with `AttributeError` when encountering an object whose C++ type index is allocated but has no Python registration. It now correctly falls through to the existing fallback path (warning + `Object`).
- Flags/config: None.
- Data formats/schemas: None.

- **Python package — Cython object return path** ([.knowledge/designs/0014-python-package.md](../designs/0014-python-package.md)): The `make_ret_object` function in `cython/object.pxi` that converts C++ `TVMFFIAny` with `kTVMFFIObject` type code into a Python object.
- **Global function registry** ([.knowledge/designs/0004-function-system.md](../designs/0004-function-system.md)): `get_global_func` / `GlobalDef` for registering the test helper.
- **TYPE_INDEX_TO_INFO list**: A Python-side list indexed by `type_index`, entries are `None` for unallocated or unregistered indices, or a type-info object with `.type_cls` for registered types. Extended on demand via `_register_object`.

Design elements this commit **produces**:
- None (bugfix only — restores intended behavior, no new design elements).

## Usage Examples

**Before (crash)**:
```python
# If C++ returns an object with type_index=N where TYPE_INDEX_TO_INFO[N] is None:
#   TYPE_INDEX_TO_INFO[N].type_cls  ->  AttributeError: 'NoneType' has no attribute 'type_cls'
```

**After (correct fallback)**:
```python
import tvm_ffi
# Returns Object with a UserWarning instead of crashing
import warnings
with warnings.catch_warnings(record=True) as w:
    warnings.simplefilter("always")
    obj = tvm_ffi.testing.make_unregistered_object()
    assert type(obj) is tvm_ffi.Object
    assert "not registered via register_object" in str(w[0].message)
```
