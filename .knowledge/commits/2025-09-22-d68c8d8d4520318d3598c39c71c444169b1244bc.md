# fix: Fallback for unregistered object types (#44)
## TL;DR
- Fixed a crash in `make_ret_object` (Cython `object.pxi`) where accessing `.type_cls` on a `None` entry in `TYPE_INDEX_TO_INFO` threw `AttributeError` instead of falling through to the `Object` fallback path.
- Added `TestUnregisteredObject` in C++ and a Python helper `make_unregistered_object()` to exercise the fallback.
- Added `test_unregistered_object_fallback` verifying the fix emits a `UserWarning` and returns a base `Object`.

## Usage Examples
Before/after pattern showing the bug:

```python
# BEFORE (buggy): If a C++ object type is registered in the C++ type table
# but NOT registered via register_object() on the Python side, and its
# type_index falls within len(TYPE_INDEX_TO_INFO), the entry is None.
# The old code did:
#   cls = TYPE_INDEX_TO_INFO[tindex].type_cls
# which raises AttributeError on None.

# AFTER (fixed): The code now checks the entry before accessing .type_cls:
#   type_info = TYPE_INDEX_TO_INFO[tindex]
#   if type_info is not None:
#       cls = type_info.type_cls
#       ...
# If type_info is None, falls through to the warning + Object fallback.

# Test demonstrating correct behavior:
import tvm_ffi
import pytest

with pytest.warns(UserWarning, match=r"testing\.TestUnregisteredObject"):
    obj = tvm_ffi.testing.make_unregistered_object()
assert type(obj) is tvm_ffi.Object  # base Object, not a subclass
```
