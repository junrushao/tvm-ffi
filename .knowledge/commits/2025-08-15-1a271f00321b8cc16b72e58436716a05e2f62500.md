# Fix JSON parser/writer to correctly produce and detect NaN/Infinity values when compiled with -ffast-math

## TL;DR
- Under `-ffast-math` (`__FAST_MATH__`), `std::numeric_limits<double>::infinity()`, `std::numeric_limits<double>::quiet_NaN()`, `std::isnan()`, and `std::isinf()` are either undefined or optimized away by the compiler; this commit adds IEEE 754 bit-manipulation fallbacks for all four cases.
- Three new private helpers are added to `JSONParserContext` (`FastMathSafePosInf`, `FastMathSafeNegInf`, `FastMathSafeNaN`) and two to `JSONWriter` (`FastMathSafeIsNaN`, `FastMathSafeIsInf`).
- Existing tests are updated to use the same bit-level helpers so assertions hold under `-ffast-math`.

## Impact
- API: None — all new helpers are private static methods; public JSON serialization API is unchanged.
- Behavioral: JSON round-trip of `NaN`, `Infinity`, and `-Infinity` values now works correctly when the library is compiled with `-ffast-math`. Previously these values would be silently mishandled.
- Flags/config: `__FAST_MATH__` preprocessor macro gates the new code paths; no user-facing config change.
- Data formats/schemas: None — the JSON text format for `NaN`/`Infinity` is unchanged.

## Usage Examples

Before (broken under `-ffast-math`):
```cpp
// json_parser.cc — std::numeric_limits<double>::quiet_NaN() may return 0.0 under -ffast-math
*out = std::numeric_limits<double>::quiet_NaN();

// json_writer.cc — std::isnan(value) always returns false under -ffast-math
if (std::isnan(value)) { WriteLiteral("NaN", 3); }

// test_json_parser.cc
EXPECT_EQ(std::isnan(json::Parse("NaN").cast<double>()), true);  // may fail under -ffast-math
```

After (correct under all optimization levels):
```cpp
// json_parser.cc
*out = FastMathSafeNaN();  // uses 0x7FF8000000000000ULL bit-cast under __FAST_MATH__

// json_writer.cc
if (FastMathSafeIsNaN(value)) { WriteLiteral("NaN", 3); }

// test_json_parser.cc
EXPECT_EQ(FastMathSafeIsNaN(json::Parse("NaN").cast<double>()), true);
```
