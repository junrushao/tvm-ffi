# Make JSON parser and writer fastmath-safe with IEEE 754 bit-level NaN/Inf handling
## TL;DR
- Replaces `std::numeric_limits<double>::infinity()` and `quiet_NaN()` in JSON parser with bit-pattern construction (`reinterpret_cast` from `uint64_t`) under `__FAST_MATH__`.
- Replaces `std::isnan()`/`std::isinf()` in JSON writer with IEEE 754 bit-level exponent/mantissa checks under `__FAST_MATH__`.
- Updates tests to use the same bit-level helpers for NaN/Inf assertions.

## Impact
- API: none — no public signature changes
- Behavioral: JSON round-trip of NaN/Infinity now works correctly when compiled with `-ffast-math`
- Flags/config: sensitive to `__FAST_MATH__` preprocessor macro (set by `-ffast-math` compiler flag)
- Data formats/schemas: none — JSON wire format unchanged (still uses `NaN`, `Infinity`, `-Infinity` literals)

## Usage Examples
From the test (`tests/cpp/extra/test_json_parser.cc`), showing the round-trip invariant:

```cpp
// NaN round-trip — parse "NaN" and verify the result is NaN
EXPECT_EQ(FastMathSafeIsNaN(json::Parse("NaN").cast<double>()), true);
// Infinity round-trip
EXPECT_EQ(FastMathSafeIsInf(json::Parse("Infinity").cast<double>()), true);
// -Infinity round-trip
EXPECT_EQ(FastMathSafeIsInf(-json::Parse("-Infinity").cast<double>()), true);
```

Before the fix, these assertions used `std::isnan()`/`std::isinf()` which are themselves broken under `-ffast-math`, masking the parser bug. After the fix, both production code and tests use bit-level checks.
