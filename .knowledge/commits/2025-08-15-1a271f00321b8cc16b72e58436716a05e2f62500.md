# Make JSON parser/writer fastmath-safe with IEEE 754 bit-level NaN/Inf helpers
## TL;DR
- Adds private `FastMathSafe{PosInf,NegInf,NaN}` helpers to `JSONParserContext` that construct special IEEE 754 doubles via bit-casting under `-ffast-math`, falling back to `std::numeric_limits` otherwise.
- Adds private `FastMathSafe{IsNaN,IsInf}` helpers to `JSONWriter` that detect NaN/Inf via bit-level inspection under `-ffast-math`, falling back to `std::isnan`/`std::isinf` otherwise.
- Updates tests to use matching `FastMathSafe{IsNaN,IsInf}` free functions so assertions remain valid under `-ffast-math`.

## Key Exports
All new symbols are `private static` methods on internal classes or anonymous-namespace free functions in test code. No public API surface is added or changed.

**JSONParserContext (private static methods)**:
- `FastMathSafePosInf() -> double` -- returns +Inf via bit-cast (`0x7FF0000000000000`) under `__FAST_MATH__`, else `std::numeric_limits<double>::infinity()`.
- `FastMathSafeNegInf() -> double` -- returns -Inf via bit-cast (`0xFFF0000000000000`) under `__FAST_MATH__`, else `-std::numeric_limits<double>::infinity()`.
- `FastMathSafeNaN() -> double` -- returns quiet NaN via bit-cast (`0x7FF8000000000000`) under `__FAST_MATH__`, else `std::numeric_limits<double>::quiet_NaN()`.

**JSONWriter (private static methods)**:
- `FastMathSafeIsNaN(double x) -> bool` -- checks exponent=0x7FF and mantissa!=0 under `__FAST_MATH__`, else `std::isnan(x)`.
- `FastMathSafeIsInf(double x) -> bool` -- checks exponent=0x7FF and mantissa==0 under `__FAST_MATH__`, else `std::isinf(x)`.

**Test helpers (anonymous namespace free functions)**:
- `FastMathSafeIsNaN(double x) -> bool` -- identical logic to JSONWriter's version.
- `FastMathSafeIsInf(double x) -> bool` -- identical logic to JSONWriter's version.

## Impact
- API: none -- no public header or function signature changes.
- ABI: none -- only internal `.cc` files modified.
- Behavioral: JSON parse/write of `NaN`, `Infinity`, `-Infinity` now works correctly when compiled with `-ffast-math` (GCC/Clang `__FAST_MATH__` macro). Without `-ffast-math`, behavior is identical (falls through to `std::` functions).
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **JSON value system** (`tvm::ffi::json::Parse`, `tvm::ffi::json::Write`): The JSON module uses `Any`-typed values and the container system (`Array`, `Map`) to represent parsed JSON. This commit modifies the internal implementation of the parser and writer, not the public JSON API.
- **IEEE 754 double bit layout**: The commit directly encodes the IEEE 754 binary64 format -- exponent bits [62:52], mantissa bits [51:0], sign bit [63]. This is the same bit layout assumed by the `AnyView`/`Any` 16-byte representation for `kTVMFFIFloat`.

Design elements this commit produces:
- **Fastmath-safe IEEE 754 helpers pattern**: A reusable pattern for constructing/detecting special floating-point values (`NaN`, `+Inf`, `-Inf`) via bit-level `reinterpret_cast<const double*>(&uint64_bits)` under `#ifdef __FAST_MATH__`, with `std::numeric_limits`/`std::isnan`/`std::isinf` fallback. This pattern is duplicated across three locations (parser, writer, test) and could be factored into a shared utility.

## Usage Examples
The helpers are all internal, so the public API usage is unchanged:

```cpp
// Parsing special float values (works under -ffast-math after this commit)
Any val = json::Parse("NaN");        // val.cast<double>() is NaN
Any inf = json::Parse("Infinity");   // val.cast<double>() is +Inf
Any ninf = json::Parse("-Infinity"); // val.cast<double>() is -Inf

// Writing special float values (works under -ffast-math after this commit)
// json::Write internally detects NaN/Inf via bit-level checks
```
