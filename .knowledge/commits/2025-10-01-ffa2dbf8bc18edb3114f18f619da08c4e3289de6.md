# Add Trainium (kDLTrn) device type to Python DLDeviceType enum and Device name mappings
## TL;DR
- Adds `kDLTrn = 17` to the `DLDeviceType(IntEnum)` enum in both the Cython implementation (`device.pxi`) and the type stub (`core.pyi`).
- Registers bidirectional string mapping `"trn"` <-> `kDLTrn` in `Device._DEVICE_TYPE_TO_NAME` and `Device._DEVICE_NAME_TO_TYPE`.

## Key Exports

```python
class DLDeviceType(IntEnum):
    # ... existing members ...
    kDLTrn = 17  # NEW — AWS Trainium device
    # Interacts with: DLPack C ABI DLDeviceType enum (dlpack/dlpack.h)
    # Interacts with: Device._DEVICE_TYPE_TO_NAME, Device._DEVICE_NAME_TO_TYPE
    # Extension: add new device by appending enum member + both dicts + .pyi stub
```

## Impact
- API: Additive only — `tvm_ffi.device("trn", 0)` and `DLDeviceType.kDLTrn` now resolve. No existing callers affected.
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `DLDeviceType(IntEnum)` enum — standalone Python enum mirroring DLPack C `DLDeviceType` (see `.knowledge/designs/0012-python-bindings.md`, `.knowledge/api-index/0011-python-bindings.md`)
- `Device._DEVICE_TYPE_TO_NAME` / `Device._DEVICE_NAME_TO_TYPE` — bidirectional lookup dicts in `cython/device.pxi`

Design elements this commit produces:
- `kDLTrn = 17` enum member and `"trn"` string alias — purely additive, follows existing device registration pattern

## Usage Examples

```python
import tvm_ffi

# Create a Trainium device
dev = tvm_ffi.device("trn", 0)
assert dev.device_type == tvm_ffi.DLDeviceType.kDLTrn
```
