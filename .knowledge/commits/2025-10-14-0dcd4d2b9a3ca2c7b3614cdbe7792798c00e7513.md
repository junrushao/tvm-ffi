# Refactor Tensor/TensorView API from operator->() to method-based accessors
## TL;DR
- Replaces `operator->()` on both `Tensor` and `TensorView` with explicit method accessors: `data_ptr()`, `device()`, `ndim()`, `dtype()`, `size(idx)`, `stride(idx)`, `byte_offset()`, `numel()`.
- Adds `Tensor::GetDLTensorPtr()` as the explicit escape hatch for raw `DLTensor*` access; adds overloaded free function `GetDataSize(Tensor)` and `GetDataSize(TensorView)`.
- Updates all call sites across src, tests, docs, examples, and inline C++ source strings in Python tests to use the new method-based API.

## Impact
- API: Breaking change for C++ users who relied on `operator->()` to access `DLTensor` fields on `Tensor` or `TensorView`. All callers must migrate from `tensor->data` to `tensor.data_ptr()`, `tensor->shape[i]` to `tensor.size(i)`, etc. `Tensor::GetDLTensorPtr()` is the explicit replacement for raw pointer access.
- Behavioral: None -- all methods return the same values as the previous `operator->()` access paths.
- Flags/config: None
- Data formats/schemas: None

## Usage Examples
Migrating Tensor access from operator->() to method-based API in C++ kernel code:
```cpp
// Before (operator->() pattern):
void AddOne(ffi::TensorView x, ffi::TensorView y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be 1D";
  TVM_FFI_ICHECK(x->shape[0] == y->shape[0]) << "shape mismatch";
  for (int i = 0; i < x->shape[0]; ++i) {
    static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
  }
}

// After (method-based pattern):
void AddOne(ffi::TensorView x, ffi::TensorView y) {
  TVM_FFI_ICHECK(x.ndim() == 1) << "x must be 1D";
  TVM_FFI_ICHECK(x.size(0) == y.size(0)) << "shape mismatch";
  for (int i = 0; i < x.size(0); ++i) {
    static_cast<float*>(y.data_ptr())[i] = static_cast<float*>(x.data_ptr())[i] + 1;
  }
}
```
