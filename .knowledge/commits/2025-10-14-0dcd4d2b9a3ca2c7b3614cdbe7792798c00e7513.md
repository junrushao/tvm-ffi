# Replace operator->() with method-based API on Tensor and TensorView
## TL;DR
- Replaces `operator->()` (returning `DLTensor*`/`TensorObj*`) with explicit method accessors on both `Tensor` and `TensorView`: `data_ptr()`, `ndim()`, `dtype()`, `device()`, `size(idx)`, `stride(idx)`, `byte_offset()`, `numel()`.
- Adds `Tensor::GetDLTensorPtr()` as the explicit escape hatch for code that needs the raw `DLTensor*`.
- Replaces `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE` macro usage in `Tensor` with explicit constructors, `_type_is_nullable`, `ContainerType`, and a protected `get()` method.
- Updates all examples, docs, tests, and internal callers (structural_equal, structural_hash) to use the new method-based API.

## Key Exports

**Types/Classes**:

`tvm::ffi::Tensor` -- new/changed methods:
- `Tensor() = default` -- default constructor (explicitly declared)
- `explicit Tensor(ObjectPtr<TensorObj> n)` -- construct from ObjectPtr
- `explicit Tensor(UnsafeInit tag)` -- unsafe-init constructor
- `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN(Tensor)` -- copy/move ops
- `void* data_ptr() const` -- was `(*this)->data`, now `get()->data`
- `DLDevice device() const` -- new accessor, was `(*this)->device`
- `int32_t ndim() const` -- was `(*this)->ndim`, now `get()->ndim`
- `DLDataType dtype() const` -- was `(*this)->dtype`, now `get()->dtype`
- `int64_t size(size_t idx) const` -- new, returns `get()->shape[idx]`
- `int64_t stride(size_t idx) const` -- new, returns `get()->strides[idx]`
- `uint64_t byte_offset() const` -- new, returns `get()->byte_offset`
- `const DLTensor* GetDLTensorPtr() const` -- new, explicit access to underlying DLTensor pointer (replaces `operator->()`)
- Protected: `const TensorObj* get() const` -- new, replaces the implicit `operator->()` chain

`tvm::ffi::TensorView` -- new/changed methods:
- `void* data_ptr() const` -- unchanged signature, reordered
- `DLDevice device() const` -- new accessor
- `int32_t ndim() const` -- unchanged signature, reordered
- `DLDataType dtype() const` -- unchanged signature, reordered
- `int64_t numel() const` -- moved from after `ndim` to after `shape`
- `int64_t size(size_t idx) const` -- new, returns `tensor_.shape[idx]`
- `int64_t stride(size_t idx) const` -- new, returns `tensor_.strides[idx]`
- `uint64_t byte_offset() const` -- new, returns `tensor_.byte_offset`

Removed from `TensorView`:
- `const DLTensor* operator->() const` -- removed; callers must use named methods

**Functions**:
- `size_t GetDataSize(const Tensor& tensor)` -- new overload, delegates to `GetDataSize(tensor.numel(), tensor.dtype())`
- `size_t GetDataSize(const TensorView& tensor)` -- new overload, same delegation pattern

**Internal changes to TypeTraits<TensorView>**:
- `CopyToAnyView` now uses `const_cast<DLTensor*>(&(src.tensor_))` instead of `const_cast<DLTensor*>(src.operator->())`, via a new `friend` declaration in `TensorView`.

## Impact
- API: **Breaking for C++ callers** that use `tensor->ndim`, `tensor->data`, `tensor->dtype`, `tensor->shape[i]`, `tensor->device`, or `tensor.operator->()` on `Tensor` or `TensorView`. All such accesses must be rewritten to use the new method-based API (`ndim()`, `data_ptr()`, `dtype()`, `size(i)`, `device()`). For `Tensor`, `GetDLTensorPtr()` provides the escape hatch. The Python bindings and ABI are unaffected.
- ABI: none (C ABI unchanged; only C++ header-level API changes)
- Behavioral: none (all methods return the same values as the prior `operator->()` pattern)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Tensor container** (`.knowledge/designs/containers.md`): The `Tensor` ref wrapper around `TensorObj` and `DLTensor` base. This commit restructures the accessor layer without changing the underlying data model.
- **Object system** (`.knowledge/designs/object-system.md`): The `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE` macro and `ObjectRef::get()` pattern. This commit moves `Tensor` from macro-based ref methods to explicit hand-written equivalents.
- **TensorView** (`.knowledge/commits/2025-10-01-1ec623678adea0ddba482d8d56d4ab2be440e694.md`): The non-owning TensorView type introduced in 1ec6236, whose `operator->()` is now removed in favor of named methods.

Design elements this commit produces:
- **Method-based Tensor/TensorView API convention**: Establishes that `Tensor` and `TensorView` should be accessed exclusively through named methods rather than `operator->()` to a raw `DLTensor*`. This prevents error-prone raw pointer access and creates a uniform API surface between owned (`Tensor`) and non-owning (`TensorView`) tensor types.
- **Explicit `get()` pattern for Tensor**: The protected `get()` method replaces the macro-generated `operator->()`, making the internal pointer access explicit and controllable.

## Usage Examples

### C++ kernel using the new method-based TensorView API
**Context**: The canonical FFI kernel function pattern after this commit. Compare with the `operator->()` pattern from commit 1ec6236.
```cpp
#include <tvm/ffi/container/tensor.h>

namespace ffi = tvm::ffi;

void AddOne(ffi::TensorView x, ffi::TensorView y) {
  TVM_FFI_ICHECK(x.ndim() == 1) << "x must be a 1D tensor";
  DLDataType f32_dtype{kDLFloat, 32, 1};
  TVM_FFI_ICHECK(x.dtype() == f32_dtype) << "x must be float32";
  TVM_FFI_ICHECK(x.size(0) == y.size(0)) << "shape mismatch";
  for (int i = 0; i < x.size(0); ++i) {
    static_cast<float*>(y.data_ptr())[i] = static_cast<float*>(x.data_ptr())[i] + 1;
  }
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne);
```

### Accessing the raw DLTensor pointer via GetDLTensorPtr
**Context**: When code needs the underlying DLTensor pointer (e.g., for memcpy or DLPack interop).
```cpp
ffi::Tensor tensor = ffi::Tensor::Empty({2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
const DLTensor* dl = tensor.GetDLTensorPtr();
// Use dl->data, dl->ndim, etc. directly when needed
```
