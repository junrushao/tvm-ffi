# Restore Array slice to return list[T] instead of Array[T]
## TL;DR
- Reverts a behavioral regression from PR #37 where `Array.__getitem__(slice)` returned `Array[T]` instead of `list[T]`.
- Removes the list-to-Array wrapping in `Array.__getitem__`, letting `getitem_helper`'s native `list[T]` result pass through directly.
- Adds a test assertion confirming `isinstance(a_slice, list)` for array slicing.

## Key Exports

```python
class Array(core.Object, Sequence[T]):
    # Changed signature (old -> new):
    # def __getitem__(self, idx: slice, /) -> Array[T]:  # OLD (PR #37)
    def __getitem__(self, idx: slice, /) -> list[T]: ...  # RESTORED
    # Interacts with: getitem_helper() which already returns list[T] for slices
    # Invariant: slicing always returns a plain Python list, not an Array
```

## Impact
- API: Return type of `Array.__getitem__(slice)` changes from `Array[T]` back to `list[T]`. Callers that relied on the PR #37 behavior (receiving `Array[T]` from slicing) will now get `list[T]`.
- Behavioral: Restores compatibility with the original TVM stack behavior where array slicing produces a Python list.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Array<T>` container and its Python `Array` binding ([0006-ffi-containers](../design-records/0006-ffi-containers.md))
- `getitem_helper` utility function in `python/tvm_ffi/container.py` which dispatches element access and already returns `list[T]` for slices

Design elements this commit produces: none (restores existing behavior, no new design elements)

## Usage Examples
Before/after pattern showing the behavioral fix:

```python
import tvm_ffi

a = tvm_ffi.Array([1, 2, 3])

# BEFORE (PR #37 regression):
a_slice = a[0:2]
type(a_slice)  # -> tvm_ffi.Array  (incorrect, broke existing TVM tests)

# AFTER (this fix):
a_slice = a[0:2]
type(a_slice)  # -> list  (correct, matches original TVM behavior)
assert isinstance(a_slice, list)
assert (a_slice[0], a_slice[1]) == (1, 2)
```
