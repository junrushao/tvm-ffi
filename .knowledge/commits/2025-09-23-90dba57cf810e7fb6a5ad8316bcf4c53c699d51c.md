# Fix Array slicing to return list[T] instead of Array[T], restoring original TVM behavior
## TL;DR
- Reverts `Array.__getitem__` slice behavior from returning `Array[T]` (introduced by PR #37) back to returning `list[T]`, matching the original TVM stack contract.
- Removes the post-slice `list -> Array` wrapping in `container.py` and updates type annotations accordingly.
- Adds a test assertion confirming slice results are `list` instances.

## Key Exports

```python
class Array(Object, Sequence[T]):
    @overload
    def __getitem__(self, idx: SupportsIndex, /) -> T: ...
    @overload
    def __getitem__(self, idx: slice, /) -> list[T]: ...
    # Changed from: def __getitem__(self, idx: slice, /) -> Array[T]: ...
    # Interacts with: getitem_helper (builds list from element-wise ArrayGetItem calls)
    # Invariant: slicing always returns a plain Python list, not an Array
    # Invariant: single-index access still returns T
```

## Impact
- API: Return type of `Array.__getitem__(slice)` changes from `Array[T]` to `list[T]`. Callers relying on `Array`-specific behavior (e.g., passing slices back to FFI expecting `Array`) must now wrap explicitly with `Array(sliced_list)`.
- Behavioral: Restores the original TVM stack's slicing contract. Code written against PR #37's `Array[T]` return type (if any) would break, but this is considered a bugfix since the `list[T]` contract was the long-standing original.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Array.__getitem__` and `getitem_helper` from `python/tvm_ffi/container.py` -- the existing slice dispatch mechanism that already returns `list` from `getitem_helper`, which PR #37 had wrapped back into `Array`.
- Container design (`.knowledge/design-records/0006-containers.md`) -- `Array<T>` immutable array with `ArrayGetItem` FFI call.
- Python bindings container layer (`.knowledge/design-records/0012-python-bindings.md`) -- `Array` Python class backed by `_ffi_api.ArrayGetItem`.

Design elements this commit produces:
- None (restores prior behavior; no new design elements).

## Usage Examples

**Before (PR #37 behavior, now removed):**
```python
arr = tvm_ffi.Array([1, 2, 3])
sliced = arr[0:2]
# sliced was Array[int] -- broken, inconsistent with original TVM stack
```

**After (this fix):**
```python
arr = tvm_ffi.Array([1, 2, 3])
sliced = arr[0:2]
assert isinstance(sliced, list)  # sliced is list[int]
assert sliced == [1, 2]
```
