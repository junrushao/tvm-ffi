# Fix Array.__getitem__ slice to return list[T] instead of Array[T]
## TL;DR
- `Array[start:stop]` now returns `list[T]` again, restoring the historic TVM convention that was broken by PR #37.
- The `Array[T]` wrapping path (`type(self)(result)`) has been removed; `getitem_helper` already returns a `list` for slices.
- A regression test assertion (`isinstance(a_slice, list)`) is added to `test_container.py` to lock in this behavior.

## Key Exports

```python
class Array(Generic[T], ObjectRef):
    """Immutable indexed container of T. Python layer in python/tvm_ffi/container.py."""

    @overload
    def __getitem__(self, idx: SupportsIndex, /) -> T: ...

    # Old signature (PR #37, regression):
    # @overload
    # def __getitem__(self, idx: slice, /) -> Array[T]: ...

    # New signature (restored, matches historic TVM stack):
    @overload
    def __getitem__(self, idx: slice, /) -> list[T]: ...

    def __getitem__(self, idx: SupportsIndex | slice, /) -> T | list[T]:
        """Return one element (int index) or a plain list for a slice."""
        length = len(self)
        result = getitem_helper(self, _ffi_api.ArrayGetItem, length, idx)
        # Invariant: getitem_helper returns list[T] for slice inputs — no re-wrapping needed.
        return result
    # Interacts with: getitem_helper (core utility), _ffi_api.ArrayGetItem (C FFI call)
    # Invariant: slicing an Array always yields a plain Python list, NOT an Array.
    # Extension: if mutable slices are ever needed, use tvm_ffi.List[T] instead.
```

## Impact
- API: `Array.__getitem__(slice)` return type annotation changes from `Array[T]` to `list[T]`. Any code that assumed `a[m:n]` returns an `Array` (introduced in PR #37) will now receive a `list`. Code written against the original TVM stack is unaffected.
- Behavioral: Slicing an `Array[T]` now consistently returns `list[T]`. The intermediate re-boxing step (`type(self)(result)`) is removed — no Array copy is created.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Array` (0007-containers): `getitem_helper` + `_ffi_api.ArrayGetItem` drive slice resolution; the fix removes the re-wrapping step at the Python layer.

Design elements this commit produces:
- Mutates the Python-layer contract of `Array.__getitem__` for `slice` inputs: `Array[T]` → `list[T]` return type.

## Usage Examples

**Before (PR #37 regression):**
```python
a = tvm_ffi.Array([1, 2, 3])
a_slice = a[-3:-1]
assert isinstance(a_slice, tvm_ffi.Array)   # was True — now FAILS
assert isinstance(a_slice, list)             # was False — now PASSES
```

**After (restored behavior):**
```python
a = tvm_ffi.Array([1, 2, 3])
a_slice = a[-3:-1]
assert isinstance(a_slice, list)   # True — plain Python list
assert (a_slice[0], a_slice[1]) == (1, 2)
```
