# Fix Array slicing to return list[T] instead of Array[T], restoring legacy TVM behavior

## TL;DR
- Reverts a behavioral regression from PR #37 where `Array.__getitem__` with a slice returned `Array[T]` instead of `list[T]`.
- Removes the post-slice wrapping (`type(self)(result)`) so `getitem_helper`'s native `list` return is passed through directly.
- Adds an explicit `isinstance(a_slice, list)` assertion in `test_container.py` to prevent future regressions.

## Key Exports

```python
class Array(Generic[T], ObjectRef, Sequence[T]):
    """Immutable typed array."""
    @overload
    def __getitem__(self, idx: SupportsIndex, /) -> T: ...
    @overload
    def __getitem__(self, idx: slice, /) -> list[T]: ...
    # Changed: slice overload return type Array[T] -> list[T]
    # Interacts with: getitem_helper (returns list for slices natively)
    # Invariant: slicing always returns a plain Python list, not an Array
```

## Impact
- API: Return type of `Array.__getitem__(slice)` changed from `Array[T]` to `list[T]`. Callers that relied on the PR #37 behavior (getting `Array[T]` from slicing) will now receive `list[T]`. This restores the original TVM stack contract.
- Behavioral: `getitem_helper` already returned `list`; this commit removes the `Array(result)` re-wrapping that PR #37 added.
- Flags/config: none
- Data formats/schemas: none

- `getitem_helper` utility in `container.py` (`.knowledge/designs/0012-python-bindings.md` area) -- the shared slicing helper that natively returns `list`

## Usage Examples
**Before (PR #37 regression):**
```python
a = tvm_ffi.Array([1, 2, 3])
a_slice = a[0:2]
type(a_slice)  # Array -- unexpected, broke legacy callers
```

**After (this fix):**
```python
a = tvm_ffi.Array([1, 2, 3])
a_slice = a[0:2]
assert isinstance(a_slice, list)  # list -- matches legacy TVM behavior
assert a_slice == [1, 2]
```
