# Add CUBIN launcher utility header and Python embedding toolchain
## TL;DR
- Adds `include/tvm/ffi/extra/cuda/cubin_launcher.h`, a header-only CUDA utility providing `CubinModule` and `CubinKernel` classes for loading CUBIN from memory and launching kernels via CUDA Runtime API.
- Introduces `TVM_FFI_EMBED_CUBIN` / `TVM_FFI_EMBED_CUBIN_GET_KERNEL` macros for compile-time CUBIN embedding using `__tvm_ffi__cubin_<name>` symbol convention.
- Adds Python-side toolchain: `tvm_ffi.utils.embed_cubin` (CLI for binary embedding via `ld`/`objcopy`), `tvm_ffi.cpp.nvrtc` (NVRTC wrapper), and `embed_cubin` parameter in `load_inline`/`build_inline`.
- Adds `cmake/Utils/EmbedCubin.cmake` with `tvm_ffi_generate_cubin` and `tvm_ffi_embed_cubin` CMake functions.

## Impact
- API: New public header `extra/cuda/cubin_launcher.h` (not compiled into libtvm_ffi.so, header-only). New Python modules `tvm_ffi.cpp.nvrtc` and `tvm_ffi.utils.embed_cubin`. `build_inline`/`load_inline` gain `embed_cubin` parameter.
- Behavioral: No changes to existing behavior. CUBIN embedding on Windows raises `NotImplementedError`.
- Flags/config: `cmake/tvm_ffi-config.cmake` now includes `EmbedCubin.cmake`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): `load_inline` returns a `Module`; the embedded CUBIN is loaded into a shared library that becomes a `LibraryModuleObj`.
- **Extra API isolation** ([ADR 0010](../ADRs/0010-extra-api-isolation.md)): Header placed under `include/tvm/ffi/extra/cuda/`, consistent with the extra/ directory convention.
- **Symbol naming convention**: CUBIN symbols use `__tvm_ffi__cubin_<name>` (double-underscore internal prefix), consistent with `__tvm_ffi__library_bin` and `__tvm_ffi__metadata_` conventions documented in 0013-module-system.md.
- **C env API** (`TVMFFIEnvGetStream`): Used in usage examples for obtaining CUDA streams.
- **Error handling** ([0006-error-handling.md](../designs/0006-error-handling.md)): `TVM_FFI_THROW(RuntimeError)` pattern used in `TVM_FFI_CHECK_CUDA_ERROR`.
- **`tvm_ffi.cpp.extension`**: Existing `build_inline`/`load_inline` infrastructure extended with the `embed_cubin` parameter.

Design elements this commit produces:
- **CUBIN launcher** (new): `CubinModule`/`CubinKernel` classes and `TVM_FFI_EMBED_CUBIN` macro system for header-only CUDA kernel loading and launching.
- **CUBIN embedding toolchain** (new): Python CLI (`tvm_ffi.utils.embed_cubin`) and CMake utilities (`tvm_ffi_generate_cubin`, `tvm_ffi_embed_cubin`) for embedding CUBIN binary data into object files via `ld -r -b binary` + `objcopy` symbol renaming.
- **NVRTC compilation wrapper** (new): `tvm_ffi.cpp.nvrtc.nvrtc_compile` for runtime CUDA-to-CUBIN compilation via `cuda.bindings`.

## Usage Examples

**End-to-end: Python compiles CUDA source, embeds CUBIN, and launches kernel**:
```python
from tvm_ffi import cpp
from tvm_ffi.cpp import nvrtc

# Compile CUDA source to CUBIN at runtime
cubin_bytes = nvrtc.nvrtc_compile(cuda_source, name="kernel.cu")

# C++ wrapper uses TVM_FFI_EMBED_CUBIN(my_cubin) and TVM_FFI_EMBED_CUBIN_GET_KERNEL
mod = cpp.load_inline("my_module", cuda_sources=cpp_wrapper,
                       embed_cubin={"my_cubin": cubin_bytes})
mod.add_one(x, y)
```

**C++ kernel launch pattern**:
```cpp
#include <tvm/ffi/extra/cuda/cubin_launcher.h>
TVM_FFI_EMBED_CUBIN(my_cubin);

void AddOne(tvm::ffi::TensorView x, tvm::ffi::TensorView y) {
  static auto kernel = TVM_FFI_EMBED_CUBIN_GET_KERNEL(my_cubin, "add_one");
  int64_t n = x.size(0);
  void* x_ptr = x.data_ptr();
  void* y_ptr = y.data_ptr();
  void* args[] = {&x_ptr, &y_ptr, &n};
  tvm::ffi::dim3 grid((n + 255) / 256), block(256);
  cudaError_t result = kernel.Launch(args, grid, block, stream);
  TVM_FFI_CHECK_CUDA_ERROR(result);
}
```
