# Add JSON type-schema generation and arbitrary key-value metadata to all registered fields, methods, and global functions

## TL;DR

- Introduces `details::TypeSchema<T>` — a compile-time trait that produces a JSON string encoding the type of any FFI-registered field, method parameter, or return type; automatically attached as the `"type_schema"` key in the `metadata` JSON blob serialized into `TVMFFIFieldInfo::metadata` / `TVMFFIMethodInfo::metadata`.
- Adds `reflection::Metadata{{"key", value}, ...}` — an `InfoTrait` subclass that lets callers attach arbitrary `int`/`bool`/`String` key-value pairs alongside the auto-generated type schema during `ObjectDef::def_rw` / `GlobalDef::def` registration.
- Exposes the metadata dict in Python via `TypeField.metadata`, `TypeMethod.metadata`, and the new top-level `get_global_func_metadata(name)` helper; adds `TypeSchema` — a Python frozen dataclass that parses JSON schema strings into a structured, printable Python type annotation.

## Key Exports

```python
# C++ — include/tvm/ffi/type_traits.h (+ container headers, function_details.h)
class TypeTraits[T]:
    # NEW method on every TypeTraits specialization
    @staticmethod
    def TypeSchema() -> str: ...
    # Returns a JSON string: {"type": "<type_key>"} for scalar/object types,
    # {"type": "Optional", "args": [...]} for Optional<T>, etc.
    # Invariant: always valid JSON; never raises; calls details::TypeSchema<T>::v()

# C++ — include/tvm/ffi/base_details.h
template[T]
class TypeSchemaImpl:
    # Forward-declared template; specialized in function_details.h
    @staticmethod
    def v() -> str: ...

# Alias in base_details.h:
# TypeSchema<T> = TypeSchemaImpl<remove_const_t<remove_reference_t<T>>>

# C++ — include/tvm/ffi/function_details.h
class FuncFunctorImpl[R, *Args]:
    @staticmethod
    def TypeSchema() -> str: ...
    # Returns: {"type": "ffi.Function", "args": [ret_schema, arg0_schema, ...]}
    # Interacts with: TypeSchema<T>::v() for each R, Args...
    # Note: first "args" element is the return type

class TypeSchemaImpl[void]:
    @staticmethod
    def v() -> str:
        return '{"type": "ffi.None"}'

class TypeSchemaImpl[Any]:
    @staticmethod
    def v() -> str:
        return '{"type": "ffi.AnyView"}'  # same for AnyView

# C++ — include/tvm/ffi/reflection/registry.h
class InfoTrait:
    # Base class for field/method traits (RENAMED from FieldInfoTrait)
    # Interacts with: DefaultValue, AttachFieldFlag, Metadata (all subclass this)
    # Extension: subclass and implement Apply(FieldInfoBuilder*) / Apply(MethodInfoBuilder*)
    pass

class Metadata(InfoTrait):
    """User-supplied key-value pairs attached to a field, method, or global function."""
    # dict_: list[pair[String, Any]]  (values: int, bool, or String only)
    def __init__(self, dict: InitializerList[pair[String, Any]]): ...
    def Apply(self, info: FieldInfoBuilder | MethodInfoBuilder) -> None: ...
    # Interacts with: FieldInfoBuilder.metadata_, MethodInfoBuilder.metadata_

    @staticmethod
    def ToJSON(metadata: _MetadataType) -> str: ...
    # Invariant: values must be int, bool, or String; TypeError otherwise
    # Output: JSON object string, keys in insertion order

class FieldInfoBuilder(TVMFFIFieldInfo):
    metadata_: list[pair[String, Any]]   # transient; serialized to TVMFFIFieldInfo.metadata

class MethodInfoBuilder(TVMFFIMethodInfo):
    metadata_: list[pair[String, Any]]   # transient; serialized to TVMFFIMethodInfo.metadata

# C++ — include/tvm/ffi/string.h
def EscapeString(value: String) -> String: ...
# Returns JSON-safe double-quoted string with all control chars escaped.
# Interacts with: Metadata.ToJSON, JSONWriter.WriteString (json_writer.cc refactored to use this)
# Invariant: output starts and ends with '"'; handles \uXXXX for control chars

# Python — python/tvm_ffi/cython/type_info.pxi
@dataclass(frozen=True)
class TypeSchema:
    """Structured representation of a JSON type schema string."""
    origin: str                     # Python type name ("list", "dict", "Callable", etc.)
    args: tuple[TypeSchema, ...] = ()
    # Interacts with: TypeField.metadata["type_schema"], TypeMethod.metadata["type_schema"],
    #                 get_global_func_metadata(name)["type_schema"]

    @staticmethod
    def from_json_obj(obj: dict[str, Any]) -> TypeSchema: ...
    @staticmethod
    def from_json_str(s: str) -> TypeSchema: ...
    def __repr__(self) -> str: ...
    # Produces Python-annotation-style string:
    #   Callable[[int, str], bool], list[int], dict[str, Any], int | str | None

# Python — python/tvm_ffi/registry.py
def get_global_func_metadata(name: str) -> dict[str, Any]: ...
# Returns json.loads(ffi.GetGlobalFuncMetadata(name))
# Always contains "type_schema" key; may contain user-supplied keys.
# Interacts with: GlobalFunctionTable (via "ffi.GetGlobalFuncMetadata" global func)
# Raises: RuntimeError if name not registered

# Python — TypeField / TypeMethod gain new field:
# TypeField.metadata: dict[str, Any]   (always present, empty dict if no metadata)
# TypeMethod.metadata: dict[str, Any]  (always present, empty dict if no metadata)

# Python — register_object now sets:
# cls.__tvm_ffi_type_info__ = info   (TypeInfo attached to each @register_object class)
```

## Impact

- API: `TypeField` and `TypeMethod` gain a `metadata` field (additive). All callers constructing `TypeField`/`TypeMethod` directly must pass the new `metadata=` kwarg. `get_global_func_metadata` added to `tvm_ffi` public namespace.
- Behavioral: `FieldInfoTrait` is renamed to `InfoTrait` in C++ (affects any downstream code subclassing `FieldInfoTrait` — but this is a C++-only internal extension point). `DefaultValue` and `AttachFieldFlag` now extend `InfoTrait`; `Metadata` is a new `InfoTrait` subclass. `ApplyFieldInfoTrait`/`ApplyMethodInfoTrait` now accept `FieldInfoBuilder*`/`MethodInfoBuilder*` instead of raw `TVMFFIFieldInfo*`/`TVMFFIMethodInfo*`.
- Flags/config: None.
- Data formats/schemas: `TVMFFIFieldInfo::metadata` and `TVMFFIMethodInfo::metadata` (previously `nullptr,0`) are now always a non-empty JSON object string (at minimum `{"type_schema":"..."}`). Downstream consumers parsing the metadata byte array must expect a JSON object rather than an empty buffer.

## Design Elements

Design elements this commit consumes:
- `0006-reflection`: `ObjectDef`, `GlobalDef`, `RegisterField`, `RegisterMethod`, `RegisterFunc`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, `TVMFFIFunctionSetGlobalFromMethodInfo` — heavily extended.
- `0008-type-traits`: `TypeTraits<T>` specializations — each gains a new `TypeSchema()` static method.
- `0004-function-system`: `GlobalFunctionTable`, `FunctionInfo<T>` — `FunctionInfo::TypeSchema()` is used during `GlobalDef::def()`; `ffi.GetGlobalFuncMetadata` global func registered.
- `0007-containers`: `Array`, `Map`, `Tuple`, `Variant` `TypeTraits` — each gains `TypeSchema()`.
- `0001-c-abi`: `TVMFFIFieldInfo.metadata` / `TVMFFIMethodInfo.metadata` fields (already existed as `TVMFFIByteArray`) — now populated with JSON.
- `0013-python-package`: `TypeField`, `TypeMethod`, `cython/type_info.pxi`, `cython/object.pxi` — `metadata` field added to both.
- `0010-json-serialization`: `JSONWriter.WriteString` refactored to call `EscapeString` from `string.h`.

Design elements this commit produces:
- **`details::TypeSchema<T>` / `TypeSchemaImpl<T>`** — new compile-time trait in `include/tvm/ffi/base_details.h` + `function_details.h` that converts any FFI-compatible C++ type into a JSON schema string. Automatically composed for container/function types.
- **`reflection::Metadata`** — new `InfoTrait` subclass for user-supplied key-value metadata in `include/tvm/ffi/reflection/registry.h`.
- **`FieldInfoBuilder` / `MethodInfoBuilder`** — new builder structs (subclassing the C ABI structs) that carry transient `metadata_` vector before serialization.
- **`InfoTrait`** — rename of `FieldInfoTrait`; now covers both field and method traits.
- **`EscapeString(String) -> String`** — new utility in `include/tvm/ffi/string.h`.
- **`TypeSchema` (Python)** — new frozen dataclass in `python/tvm_ffi/cython/type_info.pxi` with `from_json_str`/`from_json_obj` and Python-annotation `__repr__`.
- **`get_global_func_metadata(name)`** — new Python public function in `python/tvm_ffi/registry.py`.
- **`cls.__tvm_ffi_type_info__`** — `register_object` now sets this attribute, making `TypeInfo` directly accessible on registered Python classes.

## Usage Examples

**End-to-end: C++ registration → Python metadata retrieval**

```python
# C++ side (src/ffi/extra/testing.cc):
# GlobalDef()
#     .def("testing.schema_id_int", [](int64_t x) { return x; },
#          Metadata{{"bool_attr", true}, {"int_attr", 1}, {"str_attr", "hello"}})

# Python side:
from tvm_ffi import get_global_func_metadata
from tvm_ffi.core import TypeSchema

metadata = get_global_func_metadata("testing.schema_id_int")
# metadata == {"type_schema": '{"type":"ffi.Function","args":[{"type":"int"},{"type":"int"}]}',
#              "bool_attr": True, "int_attr": 1, "str_attr": "hello"}

schema = TypeSchema.from_json_str(metadata["type_schema"])
print(schema)  # Callable[[int], int]
```

**Field-level type schema inspection**

```python
from tvm_ffi.core import TypeInfo, TypeSchema
from tvm_ffi.testing import _SchemaAllTypes

type_info: TypeInfo = _SchemaAllTypes.__tvm_ffi_type_info__
for f in type_info.fields:
    schema = TypeSchema.from_json_str(f.metadata["type_schema"])
    print(f.name, "->", schema)
# v_opt_arr_variant -> list[int | str] | None
# v_map_str_arr_int -> dict[str, list[int]]
```
