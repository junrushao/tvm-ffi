# Metadata and JSON-based type schemas for fields, methods and global funcs
## TL;DR
- Introduces a machine-readable metadata mechanism to TVM-FFI's reflection registry, allowing arbitrary key-value metadata (int, bool, string) to be attached to global functions, object fields, and object methods.
- Adds a JSON-based `TypeSchema` system: each `TypeTraits<T>` specialization now provides a static `TypeSchema()` method returning a JSON string describing the type (e.g., `{"type":"ffi.Function","args":[{"type":"int"},{"type":"int"}]}`).
- Type schemas are automatically injected as the `"type_schema"` key in every field, method, and global function metadata entry during registration.
- On the Python side, `TypeField` and `TypeMethod` gain a `metadata: dict[str, Any]` attribute, and a new `TypeSchema` dataclass parses JSON type schemas into structured Python objects with Pythonic `repr` (e.g., `Callable[[int], int]`).
- A new `get_global_func_metadata(name)` Python function retrieves global function metadata.

## Impact
- API: `FieldInfoTrait` renamed to `InfoTrait`. `ApplyFieldInfoTrait` and `ApplyMethodInfoTrait` now take `FieldInfoBuilder*`/`MethodInfoBuilder*` instead of raw C struct pointers. This is a source-breaking change for any external code subclassing `FieldInfoTrait` or calling the internal apply functions.
- API: `TypeField` and `TypeMethod` Python dataclasses gain a `metadata` field (positional), which is a breaking change for code constructing these via positional args.
- API: New `TypeSchema` class and `get_global_func_metadata` function added to public Python API.
- API: Every `TypeTraits<T>` specialization gains a `TypeSchema()` static method. Custom user-defined TypeTraits will need to add this method to participate in schema generation.
- Behavioral: All global function, field, and method registrations now emit metadata JSON. Previously metadata was always empty.
- Data formats: Metadata is JSON with at minimum a `"type_schema"` key. User-supplied metadata appears alongside.

## Design Elements
Design elements this commit consumes:
- **Reflection system** ([0008-reflection.md](../designs/0008-reflection.md)): ObjectDef, GlobalDef, ReflectionDefBase, field/method registration.
- **TypeTraits protocol** ([0006-type-traits.md](../designs/0006-type-traits.md)): All TypeTraits specializations are extended with TypeSchema().
- **JSON serialization** ([0010-json-and-serialization.md](../designs/0010-json-and-serialization.md)): EscapeString refactored from json_writer.cc; JSON parsing used in tests.
- **Python bindings** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): TypeField, TypeMethod, register_object extended.

Design elements this commit produces:
- **TypeSchema system**: A compile-time JSON schema generator for all FFI types. Each TypeTraits<T> provides TypeSchema() returning a JSON string. The schema uses `{"type": "<key>", "args": [...]}` format where `type` matches StaticTypeKey constants.
- **Metadata infrastructure**: `reflection::Metadata` class, `InfoTrait` base, `FieldInfoBuilder`/`MethodInfoBuilder` intermediaries. Enables arbitrary key-value pairs on fields, methods, and global functions.
- **Python TypeSchema**: Frozen dataclass that parses JSON type schemas into structured Python objects with Pythonic repr (Union, Optional, Callable, list, dict notation).
- **`get_global_func_metadata`**: Python API to retrieve metadata for any registered global function.
- **`ffi.GetGlobalFuncMetadata`**: C++ global function exposing function metadata retrieval.
- **`FunctionInfo` member function pointer support**: New partial specializations `FunctionInfo<R (Class::*)(Args...)>` and `FunctionInfo<R (Class::*)(Args...) const>` enabling type schema extraction from member function pointers.

## Usage Examples
**C++ registration with metadata:**
```cpp
TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::GlobalDef()
      .def("my_add", my_add_func,
           refl::Metadata{{"description", "Adds two integers"}, {"version", 1}});
  // Registered metadata JSON: {"type_schema":"...","description":"Adds two integers","version":1}

  refl::ObjectDef<MyObj>()
      .def_rw("value", &MyObj::value,
              refl::Metadata{{"custom_attr", true}})
      .def("compute", &MyObj::Compute,
           refl::Metadata{{"deprecated", false}});
}
```

**Python metadata inspection:**
```python
from tvm_ffi import get_global_func_metadata
from tvm_ffi.core import TypeSchema

metadata = get_global_func_metadata("my_add")
# {"type_schema": '{"type":"ffi.Function","args":[...]}', "description": "...", "version": 1}

schema = TypeSchema.from_json_str(metadata["type_schema"])
print(schema)  # Callable[[int, int], int]

# Field/method metadata via type info:
info = getattr(MyClass, "__tvm_ffi_type_info__")
for f in info.fields:
    print(f.name, f.metadata)  # e.g., "value" {"type_schema": "...", "custom_attr": True}
```
