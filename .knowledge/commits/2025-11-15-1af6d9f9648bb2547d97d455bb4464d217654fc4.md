# Refactor tvm-ffi-stubgen into staged pipeline with new `import` directive

## TL;DR
- Decomposes the monolithic `stubgen.py` (528 lines) into five focused modules: `cli.py` (entry point), `file_utils.py` (parsing), `codegen.py` (generation), `analysis.py` (global func/ty-map collection), `consts.py` (constants), and `utils.py` (shared `Options` dataclass).
- Introduces a new `import` directive (`# tvm-ffi-stubgen(begin): import` / `# tvm-ffi-stubgen(end): import`) that auto-generates the import block needed by generated stubs, including `from __future__ import annotations`, typing imports, and `TYPE_CHECKING`-guarded domain imports.
- Changes stub output layout: fields are now emitted outside `TYPE_CHECKING` guards (as PEP 526 attribute annotations), while methods remain guarded. Instance methods now use `self` as the first parameter instead of positional `_0: ClassName`. The `ty-map` directive is promoted from block-local to file-level scope.

## Impact
- API: Entry point changed from `tvm_ffi.stub.stubgen:__main__` to `tvm_ffi.stub.cli:__main__`. The old `stubgen._main()` and `stubgen.Options` are removed. New CLI flags `--verbose` and `--dry-run` replace `suppress_print`.
- Behavioral: (1) Fields are emitted outside `TYPE_CHECKING` guards as runtime-visible PEP 526 annotations. (2) Instance method stubs now use `self` instead of positional `_0: ClassName`. (3) `ty-map` directives are file-level (applied globally across all files), not block-local. (4) `ty_map` renamed to `ty-map` in the directive syntax. (5) `TY_MAP_DEFAULTS` values changed from bare names (`"Sequence"`) to FQNs (`"collections.abc.Sequence"`).
- Flags/config: `--verbose` and `--dry-run` added. `suppress_print` removed. `pyproject.toml` entry point updated. New mypy override for `_pytest.*`.
- Data formats/schemas: The generated stub output format changed (field placement, method self parameter, import block presence). Existing files with stub blocks need re-generation.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/0008-reflection.md`): Uses `TypeSchema.from_json_str()`, `TypeSchema.repr()`, `_lookup_or_register_type_info_from_type_key()`, `get_global_func_metadata()`, `list_global_func_names()` to drive code generation.
- **Python bindings / tvm-ffi-stubgen** (`.knowledge/designs/0012-python-bindings.md`): Refactors the stubgen tool documented there.
- **Stub block marker protocol** (`.knowledge/commits/2025-10-12-ea02e646aea916ad18755cd6990b22ace8afd4b2.md`): Extends the directive protocol with `import` and `ty-map` (hyphenated) directives.

Design elements this commit produces:
- **Staged pipeline architecture**: Three-stage processing (ty-map collection, codegen, import generation) replaces single-pass line-by-line processing.
- **`import` directive**: New block kind `# tvm-ffi-stubgen(begin): import` that auto-generates all imports needed by generated stubs.
- **`CodeBlock`/`FileInfo` data model**: Replaces the previous implicit line-by-line processing with an explicit block-structured intermediate representation.
- **File-level `ty-map`**: Type mappings are now collected across all files before code generation, enabling cross-file type alias consistency.
- **`self` parameter for instance methods**: Instance methods now show `self` instead of positional `_0: ClassName`, improving readability.

## Usage Examples

### Adding the new `import` directive to a Python source file

```python
# Before (manual imports):
from __future__ import annotations
from typing import TYPE_CHECKING, Any, Callable
if TYPE_CHECKING:
    from collections.abc import Mapping, Sequence
    from tvm_ffi import Module

# After (auto-generated via import directive):
# tvm-ffi-stubgen(begin): import
# fmt: off
# isort: off
from __future__ import annotations
from typing import Any, Callable, TYPE_CHECKING
if TYPE_CHECKING:
    from collections.abc import Mapping, Sequence
    from tvm_ffi import Module
# isort: on
# fmt: on
# tvm-ffi-stubgen(end): import
```

### Instance method stubs now use `self`

```python
# Before:
if TYPE_CHECKING:
    def _extend(_0: AccessPath, _1: AccessStep, /) -> AccessPath: ...

# After:
if TYPE_CHECKING:
    def _extend(self, _1: AccessStep, /) -> AccessPath: ...
```
