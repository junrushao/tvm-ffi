# Refactor stubgen into staged pipeline with new `import` directive
## TL;DR
- Splits the monolithic `stub/stubgen.py` (528 lines) into five modules: `cli.py` (CLI entrypoint), `codegen.py` (code generation), `file_utils.py` (parsing), `analysis.py` (registry queries + ty-map collection), `consts.py` (constants), and `utils.py` (shared `Options` dataclass).
- Introduces a new `import` directive (`tvm-ffi-stubgen(begin): import`) that auto-generates the import block needed by generated stubs, and adopts it across `_ffi_api.py`, `access_path.py`, `module.py`, and `testing.py`.
- Changes stub output format: field annotations are now emitted *outside* `TYPE_CHECKING` (PEP 526 runtime-visible attributes), method stubs remain guarded inside `TYPE_CHECKING`; instance methods use `self` instead of positional `_0: ClassName` parameter.

## Impact
- API: Entry point changed from `tvm_ffi.stub.stubgen:__main__` to `tvm_ffi.stub.cli:__main__` (updated in `pyproject.toml`). Old `test_stubgen.py` deleted (tests import `tvm_ffi.stub.stubgen` which no longer exists).
- Behavioral: (1) Field annotations now emitted at class body level (runtime-visible PEP 526) instead of inside `TYPE_CHECKING`. (2) Instance method signatures use `self` instead of `_0: ClassName`. (3) `ty-map` directives are now file-level, not per-block. (4) `ty_map` renamed to `ty-map` (hyphen vs underscore).
- Flags/config: New `--verbose` and `--dry-run` CLI flags replace `suppress_print`. New mypy override for `_pytest.*` added to `pyproject.toml`.
- Data formats/schemas: Stub marker syntax unchanged except `ty_map` -> `ty-map`.

## Design Elements
Design elements this commit consumes:
- **TypeSchema / TypeInfo / TypeField / TypeMethod** (0015-ffi-python-type-system) -- queried for field types, method signatures during code generation
- **Global function registry** (0004-ffi-function-system) -- `list_global_func_names()`, `get_global_func_metadata()` for global function stub generation
- **`@register_object` / reflection** (0007-ffi-reflection) -- `_lookup_or_register_type_info_from_type_key()` for object type metadata

Design elements this commit produces:
- **Staged pipeline architecture** -- stubgen now runs in explicit stages: (1) parse all files, (2) collect file-level ty-maps, (3) generate global/object stubs while tracking type usage, (4) generate import blocks from collected usage
- **`import` directive** -- new block kind that auto-generates imports needed by generated stubs
- **`CodeBlock` / `FileInfo` data model** -- replaces the implicit line-by-line parsing with structured intermediate representation
- **File-level `ty-map` scope** -- ty-map directives are now collected across all files before generation, not scoped per-block
- **`self` parameter convention** -- instance methods now use `self` instead of positional `_0: ClassName`

## Usage Examples

Using the new `import` directive in a Python source file:
```python
# In your_package/_ffi_api.py:

# tvm-ffi-stubgen(begin): import
# tvm-ffi-stubgen(end): import

# tvm-ffi-stubgen(ty-map): testing.SchemaAllTypes -> _SchemaAllTypes

# tvm-ffi-stubgen(begin): object/testing.SchemaAllTypes
# tvm-ffi-stubgen(end)
```

After running `tvm-ffi-stubgen your_package/`, the import block expands to:
```python
# tvm-ffi-stubgen(begin): import
# fmt: off
# isort: off
from __future__ import annotations
from typing import Any, TYPE_CHECKING
if TYPE_CHECKING:
    from collections.abc import Mapping, Sequence
    from tvm_ffi import Object
# isort: on
# fmt: on
# tvm-ffi-stubgen(end)
```

And the object block now emits fields at class-body level with `self` on methods:
```python
# tvm-ffi-stubgen(begin): object/testing.TestIntPair
# fmt: off
a: int
b: int
if TYPE_CHECKING:
    @staticmethod
    def __c_ffi_init__(_0: int, _1: int, /) -> Object: ...
    def sum(self, /) -> int: ...
# fmt: on
# tvm-ffi-stubgen(end)
```
