# Remove all remaining using-declarations that aliased ffi types into namespace tvm
## TL;DR
- Removes 10 `using ffi::X;` declarations from 7 public headers (`cast.h`, `array.h`, `map.h`, `variant.h`, `memory.h`, `optional.h`, `string.h`), eliminating the `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Variant`, `tvm::Optional`, `tvm::make_object`, `tvm::GetRef`, and `tvm::GetObjectPtr` aliases.
- Also removes a stale `TODO(tvm-team)` comment from `dtype.h`.
- After this commit, all FFI types must be accessed via `tvm::ffi::` (or unqualified within `namespace tvm::ffi`). No `using ffi::*` declarations remain in any FFI header.

## Key Exports
None. This commit only removes existing aliases; it does not introduce any new public API surface.

**Removed aliases** (previously in `namespace tvm`):

| Header | Removed `using` declaration |
|--------|-----------------------------|
| `cast.h` | `using ffi::GetRef;` `using ffi::GetObjectPtr;` |
| `container/array.h` | `using ffi::Array;` |
| `container/map.h` | `using ffi::Map;` |
| `container/variant.h` | `using ffi::Variant;` |
| `memory.h` | `using ffi::make_object;` |
| `optional.h` | `using ffi::Optional;` |
| `string.h` | `using ffi::String;` `using ffi::Bytes;` |

## Impact
- API: **Breaking for C++ callers** using `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Variant`, `tvm::Optional`, `tvm::make_object`, `tvm::GetRef`, or `tvm::GetObjectPtr`. All must migrate to `tvm::ffi::` prefix. This is the final step in a multi-commit migration (16e9f0a introduced aliases, ed56a5e removed `Tuple`, 4be1af7 removed `Downcast` and added `GetObjectPtr`, this commit removes everything remaining).
- ABI: none (using-declarations do not affect ABI)
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Namespace alias convention** (`.knowledge/designs/containers.md` "Namespace Aliases" section): The `using ffi::X;` pattern introduced in 16e9f0a that made FFI types accessible via `tvm::`. This commit terminates that convention entirely.

Design elements this commit produces:
- **Mandatory `tvm::ffi::` qualification**: After this commit, no FFI type is aliased into `namespace tvm`. All C++ code must use `tvm::ffi::Array`, `tvm::ffi::Map`, etc. This is a new convention/invariant for the codebase.

## Usage Examples
**Before** (no longer valid after this commit):
```cpp
tvm::Array<int> arr;
auto obj = tvm::make_object<MyObj>();
auto ref = tvm::GetRef<MyNode>(ptr);
```

**After** (required):
```cpp
tvm::ffi::Array<int> arr;
auto obj = tvm::ffi::make_object<MyObj>();
auto ref = tvm::ffi::GetRef<MyNode>(ptr);
```
