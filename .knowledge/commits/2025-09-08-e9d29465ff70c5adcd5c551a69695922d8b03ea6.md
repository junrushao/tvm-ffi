# Remove all remaining tvm:: namespace re-exports of ffi:: types

## TL;DR
- Removes the last 10 `using ffi::X` declarations from FFI headers, completing the `tvm::` -> `tvm::ffi::` namespace migration. After this commit (combined with ed56a5e for `Tuple`), zero re-exports remain.
- Affected symbols: `GetRef`, `GetObjectPtr`, `Array`, `Map`, `Variant`, `make_object`, `Optional`, `String`, `Bytes`.
- Also removes a stale `TODO(tvm-team): update to latest DLPack types` comment from `dtype.h`.

## Key Exports

None -- this commit only removes existing re-exports. No new API surface.

The removed declarations were:
```python
# REMOVED from cast.h:     namespace tvm { using ffi::GetRef; using ffi::GetObjectPtr; }
# REMOVED from array.h:    namespace tvm { using ffi::Array; }
# REMOVED from map.h:      namespace tvm { using ffi::Map; }
# REMOVED from variant.h:  namespace tvm { using ffi::Variant; }
# REMOVED from memory.h:   namespace tvm { using ffi::make_object; }
# REMOVED from optional.h: namespace tvm { using ffi::Optional; }
# REMOVED from string.h:   namespace tvm { using ffi::String; using ffi::Bytes; }
#
# After this commit, callers must use tvm::ffi::X directly (e.g. tvm::ffi::Array<int>)
```

## Impact
- API: **Breaking** -- downstream C++ code using `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Optional`, `tvm::Variant`, `tvm::make_object`, `tvm::GetRef`, or `tvm::GetObjectPtr` without the `ffi::` qualifier will fail to compile. Must change to `tvm::ffi::X`.
- Behavioral: None -- no runtime behavior changes.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- The `tvm::` namespace re-export convention established in commit 16e9f0a (`commits/2025-05-08-16e9f0a978681969a6c6c535f927776e4067842a.md`). This commit **completes** the reversal of that convention, making `tvm::ffi::` the sole namespace for all FFI types.

Design elements this commit produces:
- None new. This is a removal that finalizes the namespace isolation of the FFI package. The convention is now: all FFI types live exclusively in `tvm::ffi::`, with no shorthand re-exports into `tvm::`.
