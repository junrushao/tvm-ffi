# Remove using-declarations that lifted tvm::ffi types into tvm namespace

## TL;DR
- Removes all `using ffi::X` declarations from 7 public headers, requiring downstream C++ code to use the fully qualified `tvm::ffi::` prefix for `Array`, `Map`, `Variant`, `Optional`, `String`, `Bytes`, `make_object`, `GetRef`, and `GetObjectPtr`.
- This is the exact reversal of the namespace aliasing introduced in commit `16e9f0a` (PR #17929), done to prepare for FFI package isolation.
- Also removes a stale `TODO(tvm-team)` comment from `dtype.h`.

## Key Exports

**Removed namespace aliases** (`using` declarations deleted from `namespace tvm`):

| Header | Symbols no longer in `tvm::` |
|--------|------------------------------|
| `ffi/cast.h` | `GetRef`, `GetObjectPtr` |
| `ffi/container/array.h` | `Array` |
| `ffi/container/map.h` | `Map` |
| `ffi/container/variant.h` | `Variant` |
| `ffi/memory.h` | `make_object` |
| `ffi/optional.h` | `Optional` |
| `ffi/string.h` | `String`, `Bytes` |

After this commit, callers **must** use `tvm::ffi::Array<int>`, `tvm::ffi::String`, etc. The short form `tvm::Array<int>` no longer compiles from these headers alone.

Note: `Tuple` was already removed from the `tvm::` namespace in an earlier commit (`ed56a5e`).

## Impact
- API: **Breaking** for any C++ code that used `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Optional`, `tvm::Variant`, `tvm::Bytes`, `tvm::make_object`, `tvm::GetRef`, or `tvm::GetObjectPtr` through these headers. All such call sites must migrate to `tvm::ffi::` qualification.
- Behavioral: None. Pure namespace cleanup with no semantic change.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Namespace aliasing convention** (introduced in commit `16e9f0a`, documented in [2025-05-08 ledger](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/commits/2025-05-08-16e9f0a978681969a6c6c535f927776e4067842a.md)) -- The pattern of placing `using ffi::X` between `}  // namespace ffi` and `}  // namespace tvm` braces. This commit removes all remaining instances.
- **Containers** ([0008-containers.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0008-containers.md)) -- `Array`, `Map`, `Variant`, `Optional`, `String`, `Bytes` are the types whose aliases are removed.
- **Memory allocation** ([0007-memory-allocation.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0007-memory-allocation.md)) -- `make_object` alias removed.
- **Cast utilities** (`cast.h`) -- `GetRef`, `GetObjectPtr` aliases removed.

Design elements this commit produces:
- **FFI namespace isolation convention**: After this commit, no `tvm::ffi` symbol is re-exported into `tvm::` via `using` declarations in FFI headers. All FFI types must be accessed through `tvm::ffi::`. This is the new convention going forward, preparing for full FFI package isolation.

## Usage Examples

Migration pattern for downstream code:

```cpp
// Before (no longer compiles after this commit):
tvm::Array<int> arr = {1, 2, 3};
auto ptr = tvm::make_object<MyObj>(42);
tvm::String s = "hello";
auto ref = tvm::GetRef<MyRef>(obj_ptr);

// After (required):
tvm::ffi::Array<int> arr = {1, 2, 3};
auto ptr = tvm::ffi::make_object<MyObj>(42);
tvm::ffi::String s = "hello";
auto ref = tvm::ffi::GetRef<MyRef>(obj_ptr);
```
