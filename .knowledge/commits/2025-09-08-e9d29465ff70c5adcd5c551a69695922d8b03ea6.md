# Remove all remaining `using ffi::` namespace aliases from `tvm` namespace
## TL;DR
- Removes `using ffi::Array`, `using ffi::Map`, `using ffi::String`, `using ffi::Bytes`, `using ffi::Optional`, `using ffi::Variant`, `using ffi::make_object`, `using ffi::GetRef`, and `using ffi::GetObjectPtr` from namespace `tvm`.
- After this change, all FFI types must be accessed via `tvm::ffi::` (e.g., `tvm::ffi::Array` instead of `tvm::Array`).
- Completes the namespace cleanup started in ed56a5e7 (which removed `using ffi::Tuple`), preparing the FFI package for isolation.
- Also removes a stale `TODO(tvm-team)` comment about DLPack types in `dtype.h`.

## Key Exports
None -- this commit only removes existing namespace aliases. No new API surface.

The removed aliases were:

```python
# Removed from namespace tvm (all now require tvm::ffi:: prefix):
# using ffi::Array;          # from container/array.h
# using ffi::Map;            # from container/map.h
# using ffi::Variant;        # from container/variant.h
# using ffi::String;         # from string.h
# using ffi::Bytes;          # from string.h
# using ffi::Optional;       # from optional.h
# using ffi::make_object;    # from memory.h
# using ffi::GetRef;         # from cast.h
# using ffi::GetObjectPtr;   # from cast.h
```

## Impact
- API: Breaking change for C++ callers using `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Optional`, `tvm::Variant`, `tvm::make_object`, `tvm::GetRef`, or `tvm::GetObjectPtr`. All must migrate to `tvm::ffi::` prefix. This affects downstream TVM code outside the FFI repo.
- Behavioral: None -- no semantic change.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `Array`, `Map`, `String`, `Bytes`, `Optional`, `Variant` container types (design record [0006-ffi-containers](.knowledge/design-records/0006-ffi-containers.md))
- `make_object` factory function (design record [0003-ffi-object-system](.knowledge/design-records/0003-ffi-object-system.md))
- `GetRef`/`GetObjectPtr` cast utilities (design record [0003-ffi-object-system](.knowledge/design-records/0003-ffi-object-system.md))

Design elements this commit produces:
- **Namespace convention (mutated)**: All FFI symbols now live exclusively in `tvm::ffi::` -- no `using` declarations re-export them into `tvm::`. This is a naming/structural convention change that the entire downstream codebase must adopt. Continues the pattern from ed56a5e7 (`Tuple`), now covering all remaining types.

## Usage Examples
Before/after pattern for callers:

```cpp
// BEFORE (no longer compiles after this commit):
tvm::Array<int> arr;
tvm::Map<tvm::String, int> m;
auto obj = tvm::make_object<FooObj>();
auto ref = tvm::GetRef<Foo>(ptr);

// AFTER (required usage):
tvm::ffi::Array<int> arr;
tvm::ffi::Map<tvm::ffi::String, int> m;
auto obj = tvm::ffi::make_object<FooObj>();
auto ref = tvm::ffi::GetRef<Foo>(ptr);
```
