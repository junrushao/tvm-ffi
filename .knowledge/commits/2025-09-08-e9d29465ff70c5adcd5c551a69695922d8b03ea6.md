# Remove all remaining `using ffi::X` namespace aliases from `tvm::` in FFI headers
## TL;DR
- Removes nine `using ffi::X` declarations across seven headers (`cast.h`, `array.h`, `map.h`, `variant.h`, `memory.h`, `optional.h`, `string.h`), completing the namespace cleanup that began with `ed56a5e` (which removed `using ffi::Tuple`).
- Also removes a stale `TODO(tvm-team): update to latest DLPack types.` comment from `dtype.h`.
- After this commit, no FFI type is implicitly available in the `tvm::` namespace; all must be accessed via `tvm::ffi::`.

## Impact
- API: **Breaking for external code that used short names.** Code referring to `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Variant`, `tvm::Optional`, `tvm::make_object`, `tvm::GetRef`, or `tvm::GetObjectPtr` without the `ffi::` qualifier will fail to compile. The commit message indicates this is a deliberate step toward FFI package isolation. Internal TVM code was updated in the same PR (#18280) or prior PRs.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit **consumes**:

- **Container system** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The `using ffi::Array`, `using ffi::Map`, `using ffi::Variant`, `using ffi::String`, `using ffi::Bytes`, `using ffi::Optional` aliases were convenience re-exports from each container header. No container semantics, storage, or interfaces are changed.
- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `using ffi::make_object`, `using ffi::GetRef`, `using ffi::GetObjectPtr` in `memory.h` and `cast.h` were convenience aliases for object allocation and ref-unwrapping utilities.
- **Namespace scoping convention** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md), "Tuple namespace scoping" invariant): The prior commit `ed56a5e` established the pattern of removing `using ffi::Tuple` and documented the convention that FFI container types live exclusively in `tvm::ffi::`. This commit extends that convention to all remaining FFI types.

Design elements this commit **produces**:

- **Namespace isolation invariant (completed)**: After this commit, zero `using ffi::` declarations remain in `include/tvm/ffi/` headers (confirmed by grep). The invariant documented for `Tuple` in `.knowledge/designs/0005-containers.md` now applies uniformly to all FFI types: `Array`, `Map`, `Variant`, `String`, `Bytes`, `Optional`, `make_object`, `GetRef`, `GetObjectPtr`.

## Key Implementations

**Removed declarations (complete list):**

| Header | Removed `using` declarations |
|---|---|
| `include/tvm/ffi/cast.h` | `using ffi::GetObjectPtr; using ffi::GetRef;` |
| `include/tvm/ffi/container/array.h` | `using ffi::Array;` |
| `include/tvm/ffi/container/map.h` | `using ffi::Map;` |
| `include/tvm/ffi/container/variant.h` | `using ffi::Variant;` |
| `include/tvm/ffi/dtype.h` | (stale TODO comment only) |
| `include/tvm/ffi/memory.h` | `using ffi::make_object;` |
| `include/tvm/ffi/optional.h` | `using ffi::Optional;` |
| `include/tvm/ffi/string.h` | `using ffi::Bytes; using ffi::String;` |

**Pattern**: Each removal is identical -- delete the blank line and `using ffi::X;` statement(s) between the `}  // namespace ffi` and `}  // namespace tvm` closing braces.

**Invariant enforced**: All FFI types must be referenced via `tvm::ffi::` (or from within `namespace tvm::ffi`). The `tvm::` namespace no longer re-exports any FFI symbol from these headers.

**Stale TODO removal**: `dtype.h` had a `TODO(tvm-team): update to latest DLPack types.` comment on `DLExtDataTypeCode`. This is unrelated to the namespace cleanup but was swept up in the same housekeeping commit.

**Connection to FFI isolation**: The commit message states "It will helps to cleanup the ffi package before isolation." This positions the namespace cleanup as a prerequisite for extracting the FFI as a standalone package, where symbols leaking into a parent `tvm::` namespace would be incorrect.
