# Remove remaining tvm:: namespace aliases for ffi:: types

## TL;DR
- Removes all remaining `using ffi::X` re-export declarations from the `tvm` namespace in 7 public headers, completing the namespace cleanup begun with the `tvm::Tuple` removal (commit `ed56a5e7`) and the `tvm::Downcast` removal (commit `4be1af73`).
- After this commit, all FFI types must be accessed as `tvm::ffi::X` — no `tvm::X` shorthand is available for any container, cast helper, or factory.
- Removes a stale `TODO(tvm-team): update to latest DLPack types.` comment from `dtype.h`.

| Old name (removed) | Required name after |
|---|---|
| `tvm::GetObjectPtr` | `tvm::ffi::GetObjectPtr` |
| `tvm::GetRef` | `tvm::ffi::GetRef` |
| `tvm::Array` | `tvm::ffi::Array` |
| `tvm::Map` | `tvm::ffi::Map` |
| `tvm::Variant` | `tvm::ffi::Variant` |
| `tvm::make_object` | `tvm::ffi::make_object` |
| `tvm::Optional` | `tvm::ffi::Optional` |
| `tvm::Bytes` | `tvm::ffi::Bytes` |
| `tvm::String` | `tvm::ffi::String` |

## Key Exports

None — this commit is purely deletive. No new API surface is introduced.

```python
# All of the following tvm:: aliases are now REMOVED (no longer valid):
# tvm::GetObjectPtr  -> use tvm::ffi::GetObjectPtr
# tvm::GetRef        -> use tvm::ffi::GetRef
# tvm::Array<T>      -> use tvm::ffi::Array<T>
# tvm::Map<K,V>      -> use tvm::ffi::Map<K,V>
# tvm::Variant<T...> -> use tvm::ffi::Variant<T...>
# tvm::make_object   -> use tvm::ffi::make_object
# tvm::Optional<T>   -> use tvm::ffi::Optional<T>
# tvm::Bytes         -> use tvm::ffi::Bytes
# tvm::String        -> use tvm::ffi::String
#
# Convention enforced: all public FFI types live exclusively in tvm::ffi::
# Invariant: no using-declarations bridge tvm:: -> tvm::ffi:: in any public header
```

## Impact
- API: Breaking — any caller using `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Optional`, `tvm::Variant`, `tvm::make_object`, `tvm::GetRef`, or `tvm::GetObjectPtr` must be updated to use the `tvm::ffi::` prefix. This completes the namespace-isolation work that started May 2025.
- Behavioral: none — no runtime behavior changes; pure symbol resolution change.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `tvm::ffi::Array`, `tvm::ffi::Map`, `tvm::ffi::String`, `tvm::ffi::Bytes`, `tvm::ffi::Optional`, `tvm::ffi::Variant` — container types (0007-containers)
- `tvm::ffi::GetRef`, `tvm::ffi::GetObjectPtr` — cast helpers (0003-any-anyview, 0002-object-system)
- `tvm::ffi::make_object` — factory (0002-object-system)

Design elements this commit produces:
- **Convention tightened**: The invariant "all FFI public types are accessed exclusively through `tvm::ffi::`" is now complete. The `tvm::` namespace no longer leaks any FFI symbol via `using`. This affects 0002-object-system, 0003-any-anyview, 0007-containers.

## Usage Examples

Before/after pattern (the breaking change):

```cpp
// BEFORE (no longer compiles after this commit):
tvm::Array<tvm::String> names = ...;
tvm::make_object<MyObj>(...);
tvm::GetRef<MyType>(ptr);

// AFTER (required form):
tvm::ffi::Array<tvm::ffi::String> names = ...;
tvm::ffi::make_object<MyObj>(...);
tvm::ffi::GetRef<MyType>(ptr);
```
