# Add kernel library guide documenting Tensor, Stream, and Function export workflows
## TL;DR
- Adds `docs/guides/kernel_library_guide.rst`, a new Sphinx guide for shipping kernel libraries with TVM FFI covering Tensor/TensorView usage, stream context, and function exporting.
- Updates `docs/conf.py` with `torch-cpp` and `dlpack` intersphinx mappings.
- Adds detailed Doxygen doc comments with allocator examples (CPU, CUDA, NVSHMEM) to `Tensor::FromNDAlloc` in `tensor.h`.

## Design Elements
Design elements this commit consumes:
- `Tensor` and `TensorView` (non-owning view) -- documented in [0006-ffi-containers](../design-records/0006-ffi-containers.md). The guide recommends `TensorView` for kernel signatures over `Tensor` for lightweight, framework-agnostic parameter passing.
- `Tensor::FromEnvAlloc` / `TVMFFIEnvTensorAlloc` -- documented in [0011-ffi-module-system](../design-records/0011-ffi-module-system.md). The guide explains how it reuses the calling framework's allocator (e.g., `at::empty` for PyTorch).
- `Tensor::FromNDAlloc` -- documented in [0006-ffi-containers](../design-records/0006-ffi-containers.md). The guide adds lifetime warning: module must outlive allocated tensors since the custom deleter lives in the module.
- `Tensor::FromDLPack` / `Tensor::FromDLPackVersioned` -- documented in [0006-ffi-containers](../design-records/0006-ffi-containers.md). Pre-V1.0 and post-V1.0 DLPack exchange.
- `TVMFFIEnvGetStream` / `TVMFFIEnvSetStream` -- documented in [0011-ffi-module-system](../design-records/0011-ffi-module-system.md). The guide explains implicit stream update (inferred from framework tensor device) and explicit update (`tvm_ffi.use_torch_stream`, `tvm_ffi.use_raw_stream`).
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` -- documented in [0013-ffi-packaging-and-distribution](../design-records/0013-ffi-packaging-and-distribution.md) and [0014-ffi-load-inline](../design-records/0014-ffi-load-inline.md). The guide shows the C++ export + Python `load_module` pattern.
- `tvm_ffi.load_module` -- documented in [0011-ffi-module-system](../design-records/0011-ffi-module-system.md). Used to load compiled `.so`/`.dylib`/`.dll` and call exported functions.

Design elements this commit produces: none

## Usage Examples
None -- the guide itself serves as the usage documentation. Key patterns documented in the guide:

1. **Tensor allocation via env allocator** (C++ side):
```cpp
ffi::Tensor tensor = ffi::Tensor::FromEnvAlloc(TVMFFIEnvTensorAlloc, ...);
```

2. **Stream retrieval** (C++ side):
```cpp
cudaStream_t stream = reinterpret_cast<cudaStream_t>(
    TVMFFIEnvGetStream(device.device_type, device.device_id));
```

3. **Export + load pattern** (C++ export, Python call):
```cpp
// C++ side
void func(ffi::TensorView input, ffi::TensorView output);
TVM_FFI_DLL_EXPORT_TYPED_FUNC(func_name, func);
```
```python
# Python side
mod = tvm_ffi.load_module("lib.so")
mod.func_name(x, y)  # x, y can be torch.Tensor, numpy.ndarray, etc.
```
