# Robustify pyproject setup for cibuildwheel compatibility

## TL;DR
- Reconfigures cibuildwheel to explicitly build cp39-cp312 wheels (instead of skip-listing old versions), adds `*musllinux*` skip, restricts testing to cp312 only, and fixes the test command to point at `{package}/tests/python`.
- Makes `numpy` an optional import in `dtype.py` (deferred into a `try/except ImportError` block) so the package can be imported without numpy installed.
- Adds RPATH settings to the Cython extension on Linux/macOS so it can find `libtvm_ffi.so` at `lib/` relative to the extension.
- Bumps version from `0.1.0a0` to `0.1.0a2`.

## Key Exports

**CMake RPATH configuration** (new, in `CMakeLists.txt`):
- macOS: `INSTALL_RPATH "@loader_path/lib"` on `tvm_ffi_cython` target.
- Linux: `INSTALL_RPATH "$ORIGIN/lib"` on `tvm_ffi_cython` target.
- `BUILD_WITH_INSTALL_RPATH ON` ensures RPATH is embedded at build time.

**`pyproject.toml` changes**:
- `version`: `"0.1.0a0"` -> `"0.1.0a2"`
- `[tool.cibuildwheel].build`: explicit list `["cp39-*", "cp310-*", "cp311-*", "cp312-*"]` (replaces skip-based approach).
- `[tool.cibuildwheel].skip`: simplified to `["*musllinux*"]`.
- `[tool.cibuildwheel].test-skip`: `["cp39-*", "cp310-*", "cp311-*"]` (test only on cp312).
- `[tool.cibuildwheel].test-command`: `pytest {package}/tests/python -vvs` (was broken: `pytest {project}/tests -m `).
- `[project.optional-dependencies].torch`: added `setuptools` (needed by torch JIT).
- `[project.optional-dependencies].test`: added `numpy` and `torch`.

**`dtype.py` lazy numpy import** (behavioral change):
- `NUMPY_DTYPE_TO_STR` class attribute initialized as empty dict `{}`.
- numpy import and dict population deferred to module-level `try/except ImportError` block after the class definition.
- Preserves identical runtime behavior when numpy is available; gracefully degrades when absent.

**`function.pxi` deferred torch import** (behavioral change):
- `from torch.utils import cpp_extension` moved from top of `load_torch_get_current_cuda_stream()` into the `try` block that actually uses it.
- Prevents import-time failure when torch is installed but `cpp_extension` has dependency issues.

## Impact
- API: none -- no public API signatures changed.
- ABI: none -- no C/C++ ABI changes.
- Behavioral: `dtype.py` no longer fails on import if numpy is not installed. `function.pxi` no longer fails on import if torch's `cpp_extension` submodule has issues. Test for `test_error_from_nested_pyfunc` changed from `@pytest.mark.xfail` decorator to inline `try/except` with `pytest.xfail()` for more targeted debug-symbol-dependent assertions.
- Flags/config: cibuildwheel now uses explicit `build` list instead of skip-list; test-only on cp312; version bump to `0.1.0a2`.
- Data formats/schemas: none.

## Design Elements

Design elements this commit **consumes**:

- **Standalone `tvm_ffi` Python package pattern** (`.knowledge/designs/0015-python-packaging.md`): This commit refines the packaging configuration established in `2d41a511`. It adjusts the cibuildwheel strategy, RPATH configuration, and dependency declarations to make wheel distribution robust for actual CI builds.
- **Cython binding layer** (`.knowledge/designs/0014-python-bindings.md`): The RPATH change targets the `tvm_ffi_cython` CMake target (the compiled `core.*.so` Cython extension) so it can locate `libtvm_ffi.so` at wheel-relative paths.
- **`dtype` class** (`python/tvm_ffi/dtype.py`): The `NUMPY_DTYPE_TO_STR` class attribute is part of the dtype conversion pipeline. This commit restructures its initialization without changing the conversion contract.

Design elements this commit **produces**:

- **RPATH-based library discovery for Cython extension**: The Cython extension (`core.*.so`) now embeds RPATH `@loader_path/lib` (macOS) or `$ORIGIN/lib` (Linux), enabling the dynamic linker to find `libtvm_ffi.so` without environment variable manipulation. This is essential for wheel distribution where the shared library lives at `tvm_ffi/lib/` relative to the Cython extension at `tvm_ffi/core.*.so`.
- **Optional numpy dependency pattern**: numpy is no longer required at import time for `tvm_ffi.dtype`. The `NUMPY_DTYPE_TO_STR` dict is populated lazily via a module-level `try/except ImportError` block, establishing a pattern for keeping `tvm_ffi` zero-dependency at runtime.
- **Explicit cibuildwheel build matrix**: Replaces the skip-list approach with an explicit `build` list (`cp39-*` through `cp312-*`), making the set of built wheels explicit and predictable. Combined with `test-skip` to run tests only on cp312 (the abi3 target).

## Usage Examples

### RPATH effect on wheel layout
After building and installing the wheel, the Cython extension finds the shared library via relative RPATH:
```
tvm_ffi/
    core.cpython-312-*.so   # RPATH: @loader_path/lib (macOS) or $ORIGIN/lib (Linux)
    lib/
        libtvm_ffi.so        # found via RPATH without LD_LIBRARY_PATH
```

### Importing tvm_ffi without numpy
```python
# Works even when numpy is not installed
import tvm_ffi
d = tvm_ffi.dtype("float32")
print(d.type_code, d.bits, d.lanes)  # 2 32 1

# numpy dtype conversion only available when numpy is present
try:
    import numpy as np
    d2 = tvm_ffi.dtype(np.float32)  # works if numpy installed
except ImportError:
    pass  # graceful degradation
```
