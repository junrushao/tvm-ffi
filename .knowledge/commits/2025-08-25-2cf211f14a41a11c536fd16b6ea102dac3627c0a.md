# Robustify pyproject setup for cibuildwheel compatibility
## TL;DR
- Make numpy an optional dependency for `tvm_ffi.dtype` by moving the numpy import to a module-level try/except block, allowing the package to load without numpy installed.
- Set RPATH on the Cython extension (`tvm_ffi_cython`) so it finds `tvm_ffi_shared.so` via relative path (`@loader_path/lib` on macOS, `$ORIGIN/lib` on Linux), enabling standalone wheel distribution.
- Reconfigure cibuildwheel to explicitly build cp39-cp312, skip musllinux, test only on cp312 (abi3 wheel), and add numpy/torch as test dependencies.

## Impact
- API: none — `dtype.NUMPY_DTYPE_TO_STR` is preserved when numpy is installed; becomes empty dict when numpy is absent.
- Behavioral: `import tvm_ffi` no longer fails if numpy is not installed. `torch.utils.cpp_extension` import is deferred until CUDA stream JIT compilation is actually attempted.
- Flags/config: version bumped from `0.1.0a0` to `0.1.0a2`. cibuildwheel build matrix changed from exclusion-based to explicit inclusion (cp39-cp312). `test-command` now runs `pytest {package}/tests/python -vvs` instead of `pytest {project}/tests -m `.
- Data formats/schemas: none
