# Robustify pyproject setup for cibuildwheel compatibility
## TL;DR
- Hardens the `pyproject.toml` cibuildwheel configuration: explicitly lists `cp39-cp312` builds, skips musllinux, focuses test-only on `cp312` (the ABI3 wheel), and fixes the test command to point at the correct test directory.
- Makes `numpy` an optional import in `python/tvm_ffi/dtype.py` by moving the `NUMPY_DTYPE_TO_STR` population into a guarded `try/except ImportError` block, and defers the `torch.utils.cpp_extension` import inside `function.pxi` so it only loads when actually needed.
- Adds RPATH settings in `CMakeLists.txt` so the Cython extension (`tvm_ffi_cython`) can locate `tvm_ffi_shared` via a relative `lib/` path at runtime on both macOS (`@loader_path/lib`) and Linux (`$ORIGIN/lib`).

## Impact
- API: none -- no public API changes.
- Flags/config: Version bumped from `0.1.0a0` to `0.1.0a2`. cibuildwheel `build`, `skip`, and `test-skip` lists rewritten. `test-extras` now includes `numpy` and `torch`. `torch` optional-dependency gains `setuptools`.
- Data formats/schemas: none.
- Build behavior: RPATH now baked into the Cython `.so` at build time, enabling the shared library to be found without `LD_LIBRARY_PATH`/`DYLD_LIBRARY_PATH` when the wheel is installed. This is critical for cibuildwheel-produced wheels where the library layout is `tvm_ffi/core.abi3.so` + `tvm_ffi/lib/libtvm_ffi.so`.

## Design Elements

Design elements this commit **consumes**:

- **Packaging and build system** ([`.knowledge/designs/0016-packaging-and-build.md`](../designs/0016-packaging-and-build.md)): The commit operates entirely within the scikit-build-core + cibuildwheel packaging infrastructure. It relies on the existing CMake target `tvm_ffi_cython` and its link dependency on `tvm_ffi_shared`, the `install(TARGETS tvm_ffi_cython DESTINATION .)` rule, and the wheel layout where the shared library lives under `tvm_ffi/lib/`.
- **Python bindings -- dtype module** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The `dtype.py` module's `NUMPY_DTYPE_TO_STR` class variable is part of the dtype conversion pathway. The commit changes its initialization strategy without altering its runtime content.
- **Python bindings -- torch integration** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The `load_torch_get_current_cuda_stream` function in `function.pxi` is part of the CUDA stream auto-detection path. The commit defers the `torch.utils.cpp_extension` import to avoid module-level side effects when torch is installed but CUDA compilation is unavailable.
- **Traceback system** ([`.knowledge/designs/0015-traceback-system.md`](../designs/0015-traceback-system.md)): The `test_error.py` changes relax the traceback assertion from `xfail` to a runtime `try/except` + `pytest.xfail`, reflecting that debug symbols may be absent in cibuildwheel-produced release builds.

Design elements this commit **produces**:

- **RPATH-based library discovery for wheels**: A new mechanism where the Cython extension uses `INSTALL_RPATH` to find `tvm_ffi_shared` at `@loader_path/lib` (macOS) or `$ORIGIN/lib` (Linux). This augments the existing `libinfo.py` discovery logic and is specifically needed for the cibuildwheel workflow where `ctypes.CDLL` loading may not be involved (the Cython module directly links against the shared library). This is an internal build-system detail, not yet documented in any design doc.
- **Lazy numpy/torch import pattern**: The commit establishes a pattern where heavy optional dependencies (`numpy`, `torch.utils.cpp_extension`) are imported lazily (at point-of-use inside `try/except`) rather than at module load time. This enables `tvm_ffi` to be imported in minimal environments (e.g., cibuildwheel test containers) without requiring numpy to be pre-installed.
