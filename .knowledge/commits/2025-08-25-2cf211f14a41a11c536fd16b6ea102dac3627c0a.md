# Robustify pyproject setup for cibuildwheel compatibility
## TL;DR
- Sets RPATH on the Cython extension (`tvm_ffi_cython`) so it can find `libtvm_ffi_shared.so` at `@loader_path/lib` (macOS) or `$ORIGIN/lib` (Linux), enabling wheel-based distribution without `LD_LIBRARY_PATH`.
- Makes `numpy` an optional import in `dtype.py` (deferred into a `try/except ImportError` block) and makes `torch.utils.cpp_extension` a lazy import in `function.pxi`, enforcing the zero-runtime-dependency contract for the base package.
- Overhauls `cibuildwheel` configuration: bumps version to `0.1.0a2`, explicitly lists `cp39`--`cp312` build targets, skips `musllinux`, restricts test runs to `cp312` only, and fixes the `test-command` path to `{package}/tests/python`.

## Key Exports
None. This commit does not introduce new public API surface. It modifies build/packaging configuration and makes existing imports more robust.

## Impact
- API: None. No public API signatures changed.
- Behavioral: `dtype.NUMPY_DTYPE_TO_STR` is now initialized as an empty dict and populated only if `numpy` is importable. Previously, importing `tvm_ffi.dtype` would fail if `numpy` was not installed. After this change, `tvm_ffi` can be imported without `numpy`.
- Flags/config: Package version bumped `0.1.0a0` -> `0.1.0a2`. `cibuildwheel` build matrix changed from skip-list to explicit build-list (`cp39`-`cp312`). `test-extras` includes `numpy` and `torch`. RPATH set on `tvm_ffi_cython` target.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python package zero-dependency contract** ([0014-python-package.md](../designs/0014-python-package.md)): The commit enforces the "zero runtime dependencies" invariant by making `numpy` and `torch.utils.cpp_extension` optional/lazy imports rather than top-level hard dependencies.
- **Library discovery and RPATH** ([0014-python-package.md](../designs/0014-python-package.md)): The RPATH addition in `CMakeLists.txt` complements the `libinfo.find_libtvm_ffi()` discovery mechanism by ensuring the Cython extension can find the shared library via relative path in wheel installs.
- **cibuildwheel packaging** ([0014-python-package.md](../designs/0014-python-package.md)): The `[tool.cibuildwheel]` section is reconfigured to produce wheels for `cp39`-`cp312` and test on `cp312` (abi3).

Design elements this commit produces:
- **RPATH convention for Cython extension**: `@loader_path/lib` (macOS) / `$ORIGIN/lib` (Linux) is now the expected relative layout for `tvm_ffi_cython` to find `libtvm_ffi_shared`. This is a new build-system convention not previously documented.
- **Lazy import pattern for optional heavy deps**: `torch.utils.cpp_extension` is now imported inside the `try` block at call time, not at module scope. This establishes a pattern for guarding optional heavy dependencies.
