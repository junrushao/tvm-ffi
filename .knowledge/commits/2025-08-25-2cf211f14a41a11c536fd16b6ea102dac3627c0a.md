# Robustify pyproject setup for cibuildwheel compatibility
## TL;DR
- Reworked `pyproject.toml` cibuildwheel config: explicit `build` list (cp39-cp312), skip musllinux, test only cp312 (abi3), fix test-command path.
- Set RPATH on `tvm_ffi_cython` target so it finds `tvm_ffi_shared.so` via relative `lib/` path on macOS (`@loader_path/lib`) and Linux (`$ORIGIN/lib`).
- Made `numpy` an optional import in `dtype.py` (lazy-load in `try/except ImportError`) and deferred `torch.utils.cpp_extension` import to first use, reducing hard dependencies.
- Softened `test_error_from_nested_pyfunc` assertion: moved debug-symbol-dependent checks into inner `try/except` with `pytest.xfail` instead of decorating the whole test.

## Key Exports
N/A -- infrastructure. No new public API symbols.

## Impact
- API: none
- Behavioral: `numpy` is no longer a hard import-time dependency of `tvm_ffi.dtype`; the `NUMPY_DTYPE_TO_STR` dict is populated only when numpy is available. Previously, `import tvm_ffi` would fail if numpy was not installed.
- Flags/config: cibuildwheel now builds cp39--cp312 explicitly; tests run only on cp312 (abi3 wheel). Version bumped from `0.1.0a0` to `0.1.0a2`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **dtype class** (`python/tvm_ffi/dtype.py`): `NUMPY_DTYPE_TO_STR` class-level dict mapping numpy dtypes to string names. The dict's population was moved from class-body to module-level try/except.
- **Cython CUDA stream JIT** (`python/tvm_ffi/cython/function.pxi`): `load_torch_get_current_cuda_stream` uses `torch.utils.cpp_extension.load_inline`. Import deferred to point of use.
- **CMake build targets**: `tvm_ffi_cython` shared library target, linked to `tvm_ffi_shared`.

Design elements this commit produces: none (no new design elements).
