# Robustify pyproject setup for cibuildwheel compatibility
## TL;DR
- Makes `numpy` and `torch` optional imports in Python package so the core library can load without them, enabling clean wheel builds via cibuildwheel.
- Adds RPATH configuration in CMake so the Cython extension (`tvm_ffi_cython`) can find the shared library (`tvm_ffi_shared`) via relative paths inside wheel packages.
- Reconfigures cibuildwheel to build cp39-cp312 (abi3-forward), skip musllinux, and run the actual test suite.

## Key Exports
None -- this commit changes build/packaging configuration and makes existing imports lazy. No new public API symbols are introduced.

## Impact
- API: none
- Behavioral: `import tvm_ffi` no longer fails if `numpy` is not installed; `numpy` dtype mappings are populated only when numpy is importable. `torch.utils.cpp_extension` import is deferred to the point of use rather than module load time.
- Flags/config: version bumped from `0.1.0a0` to `0.1.0a2`. `test` optional dependency group now includes `numpy` and `torch`. `torch` optional dependency group now includes `setuptools`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `dtype` class (`python/tvm_ffi/dtype.py`) and its `NUMPY_DTYPE_TO_STR` class variable -- changed from eagerly populated at class definition to lazily populated via try/except ImportError at module level.
- Cython function bridge (`python/tvm_ffi/cython/function.pxi`) -- `load_torch_get_current_cuda_stream` defers `torch.utils.cpp_extension` import to inside try block.
- CMake build targets `tvm_ffi_cython` and `tvm_ffi_shared` -- RPATH relationship configured for wheel layout.

Design elements this commit produces:
- None -- no new design elements. The changes make existing elements more resilient to missing optional dependencies.
