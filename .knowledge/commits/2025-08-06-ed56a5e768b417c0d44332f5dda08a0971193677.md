# Remove `using ffi::Tuple` namespace exposure from tuple.h as part of ObjectPath phase-out
## TL;DR
- Removes the `using ffi::Tuple;` declaration from `namespace tvm` in `include/tvm/ffi/container/tuple.h`, so `Tuple` is no longer implicitly available in the `tvm::` namespace.
- Part of PR #18192 "Phase out ObjectPath in favor of AccessPath." The FFI-side change is a minor cleanup: dropping the convenience alias that leaked `ffi::Tuple` into the parent `tvm` namespace.

## Impact
- API: **Minor** -- Code that previously referred to `tvm::Tuple<...>` (without the `ffi::` qualifier) will fail to compile. However, a grep of the current codebase shows zero uses of `tvm::Tuple` -- all existing usage already uses the fully qualified `tvm::ffi::Tuple` or is within `namespace tvm::ffi`. The remaining `using ffi::` declarations in the repo are limited to `examples/kernel_library/tvm_ffi_utils.h` (for `Optional`, `Tensor`, `TensorView`) and are unaffected.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit **consumes**:

- **Container system / Tuple** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The commit modifies the `Tuple` header but does not change `Tuple`'s semantics, storage, or API. It only removes the namespace re-export.
- **Namespace conventions**: The `using ffi::X;` pattern at the bottom of container headers was a convenience alias that exposed FFI types in the parent `tvm::` namespace. This commit removes it for `Tuple`, aligning with the general trend of keeping FFI types scoped under `tvm::ffi::`.

Design elements this commit **produces**:

- None. This is a pure cleanup with no new design elements.

## Key Implementations

The entire functional change is the removal of four lines from `include/tvm/ffi/container/tuple.h`:

```diff
 }  // namespace ffi
-
-// Expose to the tvm namespace
-// Rationale: convinience and no ambiguity
-using ffi::Tuple;
 }  // namespace tvm
```

**Invariants**: `tvm::ffi::Tuple<Ts...>` remains fully functional and unchanged. The `std::tuple_size` and `std::tuple_element` specializations in `namespace std` use `::tvm::ffi::Tuple` (fully qualified) and are unaffected.

**Connection to PR #18192**: The broader PR phases out `ObjectPath` in favor of `AccessPath`. The `AccessPathPair` type alias is `Tuple<AccessPath, AccessPath>` (documented in [`.knowledge/designs/0009-structural-equal-hash.md`](../designs/0009-structural-equal-hash.md)). Removing the `tvm::Tuple` alias ensures that downstream code referencing `Tuple` through the `tvm::` namespace will not accidentally collide with any other types being reorganized as part of the ObjectPath removal. This is a hygiene measure, not a functional requirement.
