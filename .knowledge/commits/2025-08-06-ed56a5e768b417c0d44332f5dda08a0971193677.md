# Remove tvm::Tuple namespace re-export from tuple.h

## TL;DR
- Removes the `using ffi::Tuple;` declaration from `include/tvm/ffi/container/tuple.h`, so `Tuple` is no longer re-exported into the `tvm::` namespace.
- Part of PR #18192 ("Phase out ObjectPath in favor of AccessPath"), but the FFI-side diff is limited to this single namespace cleanup. The commit message scope is broader than the actual diff -- the ObjectPath/AccessPath migration lives in TVM-proper.
- Other container re-exports (`Array`, `Map`, `Variant`, `Optional`, `String`, `Bytes`, `make_object`, `Downcast`, `GetRef`) remain unchanged.

## Key Exports

None -- this commit only removes an existing re-export. No new API surface.

The removed declaration was:
```python
# REMOVED: namespace tvm { using ffi::Tuple; }
# Previously allowed `tvm::Tuple<T...>` as shorthand for `tvm::ffi::Tuple<T...>`
# After this commit, callers must use `tvm::ffi::Tuple<T...>` directly
```

## Impact
- API: **Minor breaking** -- downstream C++ code using `tvm::Tuple<T...>` (without the `ffi::` qualifier) will fail to compile. Must change to `tvm::ffi::Tuple<T...>`.
- Behavioral: None -- no runtime behavior changes.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- The `tvm::` namespace re-export convention established in commit 16e9f0a (`commits/2025-05-08-16e9f0a978681969a6c6c535f927776e4067842a.md`). This commit partially reverses that convention for `Tuple` only.

Design elements this commit produces:
- None new. This is a removal, narrowing the set of types re-exported into `tvm::`.
