# Remove `using ffi::Tuple` namespace alias from `tvm::` scope
## TL;DR
- Removes the `using ffi::Tuple;` declaration from `namespace tvm` in `include/tvm/ffi/container/tuple.h`, making `Tuple<T...>` accessible only as `tvm::ffi::Tuple<T...>` (no longer `tvm::Tuple<T...>`).
- Part of a broader "ObjectPath -> AccessPath" phase-out (per commit message), but the FFI-repo portion is limited to this single alias removal.
- All other container namespace aliases (`tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Optional`, `tvm::Variant`) remain intact.

**Diff-message alignment note**: The commit message describes phasing out `ObjectPath` in favor of `AccessPath`, but the actual diff in this repo only removes the `using ffi::Tuple;` alias. The broader `ObjectPath` removal likely affects the downstream TVM main repo. Analysis is scoped to the actual diff.

## Impact
- API: Low -- downstream code using `tvm::Tuple<T...>` must switch to `tvm::ffi::Tuple<T...>`. Since `Tuple` is less commonly used directly than `Array`/`Map`, impact is limited. The `AccessPathPair = Tuple<AccessPath, AccessPath>` typedef in the structural equal/hash system uses fully-qualified `tvm::ffi::Tuple`.
- ABI: None -- no struct layout, enum, or symbol changes.
- Behavioral: None.
- Flags/config: None.
- Data formats/schemas: None.
