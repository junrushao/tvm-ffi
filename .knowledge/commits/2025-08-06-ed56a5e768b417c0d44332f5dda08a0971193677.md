# Remove `using ffi::Tuple` convenience alias from `tvm` namespace
## TL;DR
- Removes the `using ffi::Tuple;` re-export from the `tvm` namespace in `include/tvm/ffi/container/tuple.h`.
- Part of a broader effort to phase out `ObjectPath` in favor of `AccessPath` (PR #18192 in main TVM repo); the FFI-specific portion is limited to this namespace alias cleanup.
- After this change, callers must use `tvm::ffi::Tuple` instead of `tvm::Tuple`.

**Diff-message discrepancy**: The commit message describes "Phase out ObjectPath in favor of AccessPath" which is a larger cross-repo change. In this FFI sub-repo, the only diff is the removal of 4 lines (the `using ffi::Tuple;` alias and its comment). Analysis is scoped to the actual diff only.

## Key Exports
None -- this commit only removes a namespace alias; no new API surface is introduced or changed.

**Removed**:
- `using ffi::Tuple;` in `namespace tvm` (file `include/tvm/ffi/container/tuple.h`, lines 272-274) -- previously exposed `tvm::ffi::Tuple` as `tvm::Tuple`.

## Impact
- API: Minor breaking change for any downstream C++ code that used `tvm::Tuple` instead of `tvm::ffi::Tuple`. Other containers (`Array`, `Map`, `String`, `Optional`, `Variant`, `Bytes`) still have their `using ffi::X` aliases and are unaffected.
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none
