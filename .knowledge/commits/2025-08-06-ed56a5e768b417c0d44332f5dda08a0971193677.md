# Remove tvm::Tuple namespace alias from tuple.h (tvm-ffi subset of ObjectPath→AccessPath PR)

## TL;DR
- Removes the 4-line block `using ffi::Tuple;` (and its comment) from inside `namespace tvm` at the bottom of `include/tvm/ffi/container/tuple.h`.
- After this change, callers in the `tvm::` namespace must use the fully qualified `tvm::ffi::Tuple` or include a using-declaration themselves; the implicit `tvm::Tuple` shorthand is gone.
- **Diff-message misalignment**: the commit message says "Phase out ObjectPath in favor of AccessPath (#18192)" — this is the upstream TVM PR title. In this repository only the `tuple.h` cleanup chunk landed; the ObjectPath/AccessPath rename work itself arrived in the preceding commit `f4ede98`.

## Key Exports

None

## Impact
- API: `tvm::Tuple<T...>` is no longer available as a shorthand via this header. Code that used `tvm::Tuple` (outside `tvm::ffi::`) must now write `tvm::ffi::Tuple`. Comparable aliases (`tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Optional`, etc.) remain in their respective headers.
- Behavioral: none — pure name-resolution change.
- Flags/config: none
- Data formats/schemas: none
