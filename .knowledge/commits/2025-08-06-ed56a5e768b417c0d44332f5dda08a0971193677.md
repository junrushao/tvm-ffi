# Remove `using ffi::Tuple` alias from `tvm` namespace
## TL;DR
- Removes the `using ffi::Tuple;` convenience alias from namespace `tvm` in `tuple.h`.
- After this change, `Tuple` is only accessible as `tvm::ffi::Tuple`, not `tvm::Tuple`.
- Part of the broader "Phase out ObjectPath in favor of AccessPath" cleanup (PR #18192).

## Key Exports
None — this commit only removes an existing namespace alias. No new API surface.

The removed alias was:
```cpp
# Removed from namespace tvm:
# using ffi::Tuple;  # was re-exporting tvm::ffi::Tuple as tvm::Tuple
```

## Impact
- API: Minor breaking change for any C++ code using `tvm::Tuple` — must switch to `tvm::ffi::Tuple`. Callers outside the FFI repo (e.g., downstream TVM code) that relied on the alias will fail to compile.
- Behavioral: None — no semantic change.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `Tuple` container (`ffi/containers`, design record `0006-ffi-containers`): the underlying `tvm::ffi::Tuple<T...>` type is unchanged.

Design elements this commit produces:
- Mutates `Tuple` namespace exposure: removes the `tvm::Tuple` alias, tightening the namespace boundary so `Tuple` lives exclusively in `tvm::ffi`.
