# Fix TypeInfo parent_type_info propagation for Cython classes by fixing registration ordering

## TL;DR
- Some Cython classes (Device, Error, Function, String, Tensor) had `parent_type_info` not properly set because `TypeInfo` registration happened before parent classes were registered.
- Fix: moves type registration calls in `cython/core.pyx` to after all base classes are imported; removes redundant re-registrations from per-class `.pxi` files.
- Adds 59 test lines to `tests/python/test_object.py`.

## Key Exports

```python
# No new exports — fix ensures TypeInfo.parent_type_info is correctly populated
# for all Cython-registered classes:
# Device, Error, Function, String, Tensor
# Invariant: TypeInfo.parent_type_info must be set at class registration time,
#   not lazily — registration ordering in cython/core.pyx matters
```

## Impact
- API: none
- Behavioral: Fixes TypeInfo hierarchy for built-in Cython types; downstream consumers of `TypeInfo.parent_type_info` (e.g., stubgen, `@c_class`) now see correct parent chains.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before:
```python
from tvm_ffi import TypeInfo
info = TypeInfo.lookup("device")
print(info.parent_type_info)  # None — WRONG
```

```python

```
