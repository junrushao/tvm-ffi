# Add DFS-based ffi.ReprPrint for unified object repr across all FFI types

## TL;DR
- Adds `ffi.ReprPrint(value) -> String`: a single C++ global that produces human-readable repr for any `Any` value using DFS with 3-state (NotVisited/InProgress/Done) cycle/DAG tracking.
- Removes Python-side exec()-based `__repr__` codegen from `@c_class` (`method_repr` deleted, `repr` param removed from `c_class()` and `field()`); all Python `__repr__` methods now delegate to `ffi.ReprPrint`.
- Extends the reflection system with new `Repr(false)` InfoTrait, `kTVMFFIFieldFlagBitMaskReprOff = 1<<6` C ABI flag, and `type_attr::kRepr = "__ffi_repr__"` TypeAttr column for extensible per-type custom repr.

## Impact
- API: `c_class(type_key, init, kw_only)` — `repr: bool` parameter removed (was `c_class(type_key, init, kw_only, repr)`). Callers passing `repr=False` will get `TypeError` (unknown kwarg). `Field.repr` attribute and `field(repr=...)` removed. `method_repr` deleted from `_utils.py`.
- Behavioral: `Array.__repr__()` format changed from `[1, 2, 3]` (list brackets) to `(1, 2, 3)` (tuple parentheses). `List.__repr__()` and `Map.__repr__()` now delegate to `ffi.ReprPrint` rather than using Python f-string formatting.
- Flags/config: `TVM_FFI_REPR_WITH_ADDR=1` env var (new) — when set, shows object addresses in repr output (`...@0x<addr>` for cycles, `@0x<addr>` appended to Array/List/Tensor/Map, header for generic objects).
- Data formats/schemas: None.

Design elements this commit produces:
- **`ffi.ReprPrint` global function** — single unified entry point for human-readable repr; registered via `GlobalDef`.
- **`ReprPrinter` class** (`src/ffi/extra/repr_print.cc`) — DFS printer with 3-state cycle/DAG tracking; extensible via `__ffi_repr__` TypeAttr column.
- **`kTVMFFIFieldFlagBitMaskReprOff = 1<<6`** — new C ABI field flag bit (`c_api.h`).
- **`Repr(bool)` InfoTrait** (`reflection/registry.h`) — controls per-field repr inclusion at registration time.
- **`type_attr::kRepr = "__ffi_repr__"`** constant (`reflection/registry.h`) — well-known TypeAttr column name for custom repr callbacks.
- **`__ffi_repr__` TypeAttr column** — extensible hook: any C++ type can register a custom `(const T*, const Function&) -> String` callback.

## Usage Examples

**C++→Python end-to-end: basic object repr.**
```python
# C++ registration (src/ffi/testing/testing.cc excerpt):
# refl::ObjectDef<TestCxxClassBase>()
#     .def(refl::init<int64_t, int32_t>())
#     .def_rw("v_i64", &TestCxxClassBase::v_i64, refl::Repr(false))  # excluded from repr
#     .def_rw("v_i32", &TestCxxClassBase::v_i32, refl::Repr(false))  # excluded from repr

# Python (tests/python/test_repr.py):
import tvm_ffi
from tvm_ffi._ffi_api import ReprPrint

# User-defined C++ object with two fields excluded from repr:
obj = tvm_ffi.testing.MyObj(x=1, y="hi")
assert repr(obj) == 'testing.MyObj(x=1, y="hi")'  # uses ffi.ReprPrint via __object_repr__

# Direct call:
assert ReprPrint(42) == "42"
assert ReprPrint(tvm_ffi.Array([1, 2, 3])) == "(1, 2, 3)"
assert ReprPrint(tvm_ffi.List([10, 20])) == "[10, 20]"
```

**Custom `__ffi_repr__` callback in C++.**
```cpp
// Register a custom repr for MyType:
TVM_FFI_STATIC_INIT_BLOCK() {
  // Use TypeAttrDef or the helper RegisterBuiltinRepr pattern:
  Function repr_fn = Function::FromTyped(
      [](const MyTypeObj* obj, const Function& fn_repr) -> String {
          return String("MyType<" + std::to_string(obj->value) + ">");
      });
  TVMFFIByteArray attr_name = {type_attr::kRepr, strlen(type_attr::kRepr)};
  TVMFFIAny attr_val = AnyView(repr_fn).CopyToTVMFFIAny();
  TVMFFITypeRegisterAttr(MyTypeObj::RuntimeTypeIndex(), &attr_name, &attr_val);
}
// fn_repr passed to callback is ReprPrinter::CreateFnRepr() — recurse into any child.
```
