# Fix _get_cuda_target silent sm_70 fallback for Ampere GPUs with old drivers

## TL;DR
- `_get_cuda_target()` in `extension.py` previously fell back silently to `sm_70` when the `compute_cap` field was absent from `nvidia-smi` output (common with older drivers on Ampere-generation GPUs: A10, A100).
- The fix adds a second fallback: query GPU name via `nvidia-smi --query-gpu=name`, match known Ampere names (A100→sm_80, A10→sm_86) to their compute capabilities.
- If both lookups fail, a `RuntimeError` is raised directing the user to set `TVM_FFI_CUDA_ARCH_LIST`, replacing the silent and incorrect `sm_70` default.

## Key Exports

```python
# python/tvm_ffi/cpp/extension.py

def _get_cuda_target() -> str:
    """Return a -gencode nvcc flag for the current GPU's compute capability.
    Detection priority:
      1. nvidia-smi --query-gpu=compute_cap  (primary)
      2. nvidia-smi --query-gpu=name + ampere_arch_map lookup  (new fallback)
      3. RuntimeError → set TVM_FFI_CUDA_ARCH_LIST explicitly  (old: silent sm_70)

    # Old invariant (violated): fallback to "-gencode=arch=compute_70,code=sm_70"
    # New invariant (restored): raise RuntimeError if compute capability cannot be determined
    # Interacts with: _generate_ninja_build (caller), TVM_FFI_CUDA_ARCH_LIST env var
    # Invariant: TVM_FFI_CUDA_ARCH_LIST always takes precedence over auto-detection (unchanged)
    # Invariant: ampere_arch_map covers A100 (8.0) and A10 (8.6) only — extend map for new GPUs
    """
    ...

# Internal constant (inline dict, not exported):
ampere_arch_map = {
    "A100": ("8", "0"),   # sm_80
    "A10":  ("8", "6"),   # sm_86
}
# Interacts with: gpu_name = nvidia-smi --query-gpu=name output (first line)
# Invariant: substring match — "A10" matches "NVIDIA A10" and would also match "A100",
#            but "A100" is checked first so ordering matters
```

## Impact
- API: none — `_get_cuda_target` is a private helper not exposed to callers.
- Behavioral: Ampere GPU users with old drivers (no `compute_cap` in nvidia-smi) now get the correct arch flag instead of `sm_70`. Users with GPUs not in `ampere_arch_map` now get a `RuntimeError` instead of silently compiling for `sm_70` (which would generate invalid code or fail at load time on those GPUs).
- Flags/config: none — `TVM_FFI_CUDA_ARCH_LIST` env var behavior unchanged.
- Data formats/schemas: none.

## Usage Examples

Before/after pattern for the fixed failure mode:

```python

# If nvidia-smi compute_cap query fails (old driver), _get_cuda_target returned:
#   "-gencode=arch=compute_70,code=sm_70"

# suboptimal code.

# AFTER (new behavior — correct sm_86 for A10 GPU):
# First fallback: query gpu name → "NVIDIA A10 G" → "A10" matches → sm_86
#   "-gencode=arch=compute_86,code=sm_86"
# If neither query works:
#   RuntimeError("Could not detect CUDA compute_cap automatically.
#                 Please set TVM_FFI_CUDA_ARCH_LIST environment variable.")

# Explicit workaround (unchanged, still works):
import os
os.environ["TVM_FFI_CUDA_ARCH_LIST"] = "8.6"  # A10
mod = tvm_ffi.cpp.load_inline("my_kernel", cuda_sources=..., functions=["f"])
```
