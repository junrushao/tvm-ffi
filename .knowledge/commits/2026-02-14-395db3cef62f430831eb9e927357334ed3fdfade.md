# Fix _get_cuda_target() for Ampere GPUs with older nvidia-smi lacking compute_cap field
## TL;DR
- Adds a second fallback in `python/tvm_ffi/cpp/extension.py:_get_cuda_target()`: when `--query-gpu=compute_cap` fails (older drivers on Ampere GPUs), queries `--query-gpu=name` and maps known Ampere GPU names (A100→8.0, A10→8.6) to the correct arch string.
- If both fallbacks fail, raises `RuntimeError` with an actionable message pointing to `TVM_FFI_CUDA_ARCH_LIST` env var, instead of silently returning the wrong `compute_70` default.

## Key Exports
None — bugfix restoring existing invariant.

## Impact
- API: none
- Behavioral: `_get_cuda_target()` now correctly returns `compute_80/sm_80` for A100 and `compute_86/sm_86` for A10, instead of the incorrect `compute_70/sm_70` silent fallback. Failure raises informative `RuntimeError`.
- Flags/config: `TVM_FFI_CUDA_ARCH_LIST` env var mentioned as manual override option in error message (pre-existing feature).
- Data formats/schemas: none

Design elements this commit consumes:

## Usage Examples
Before (broken on Ampere + old drivers):
```python
# _get_cuda_target() silently returned "-gencode=arch=compute_70,code=sm_70"
# even when running on A100/A10 — wrong arch, likely silent miscompilation
```
After (fixed):
```python
# _get_cuda_target() returns "-gencode=arch=compute_80,code=sm_80" for A100
# _get_cuda_target() returns "-gencode=arch=compute_86,code=sm_86" for A10
# If unrecognized GPU: raises RuntimeError with TVM_FFI_CUDA_ARCH_LIST hint
```
