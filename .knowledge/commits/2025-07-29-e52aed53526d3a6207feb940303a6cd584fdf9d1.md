# [REFACTOR][FFI] Phase out SEqualReduce/SHashReduce (#18172)

## TL;DR
- Removes `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` static constexpr boolean fields from the `Object` base class in `include/tvm/ffi/object.h`.
- Removes debug `std::cout` statements from `TCustomFuncObj::SEqual` in `tests/cpp/testing_object.h`.
- Completes the migration from legacy per-type boolean flags for structural equality/hash support to the new reflection-based mechanism (`ObjectDef<T>` with `__s_equal__` / `__s_hash__` type attribute methods).

## Key Exports
None. The removed fields were compile-time boolean constants (`static constexpr const bool`) used by legacy plug-in code to detect whether a type supported the old `SEqualReduce` / `SHashReduce` pattern. No runtime symbol, ABI surface, or public API is affected.

## Impact
- API: The `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` static fields are no longer available on `Object` or its subclasses. Any downstream code that reads these fields via `T::_type_has_method_sequal_reduce` or `T::_type_has_method_shash_reduce` will fail to compile. This is intentional -- all such code was already migrated to use the reflection-based `__s_equal__` / `__s_hash__` type attribute mechanism.
- ABI: No change. The fields were `static constexpr` (compile-time only) and never contributed to object layout or exported symbols.
- Behavioral: The `TCustomFuncObj::SEqual` test helper no longer prints to stdout on comparison failure. The `_type_s_eq_hash_kind` field and the `SEqual`/`SHash` methods themselves are retained; only the compile-time detection booleans are removed.

## Design Elements
Design elements this commit consumes:
- `Object` base class (`include/tvm/ffi/object.h`) -- the root of the TVM object hierarchy, which previously carried `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` as plug-in extension points for structural equality and structural hash.
- The new reflection system (`ObjectDef<T>`, `TypeAttrDef<T>`) -- the replacement mechanism where structural equality/hash methods are registered as type attributes (`__s_equal__`, `__s_hash__`) via `TypeAttrDef<T>().def(...)`. See `TCustomFuncObj::RegisterReflection()` in `tests/cpp/testing_object.h` for the canonical example.

Design elements this commit produces:
- None. This is purely a removal of deprecated extension points. The `Object` class still retains `_type_s_eq_hash_kind` (the enum field indicating whether a type supports structural equality/hash). The actual equality/hash dispatch now relies entirely on the reflection-registered `__s_equal__` / `__s_hash__` methods rather than compile-time boolean flags.

## Usage Examples
No usage change. Code that previously relied on these boolean flags should use the reflection-based type attribute system instead:

```cpp
// Old pattern (removed):
// if constexpr (T::_type_has_method_sequal_reduce) { ... }
// if constexpr (T::_type_has_method_shash_reduce) { ... }

// New pattern (use FFI reflection type attributes):
// Structural equality/hash methods are registered via TypeAttrDef<T>:
static void RegisterReflection() {
    namespace refl = tvm::ffi::reflection;
    refl::ObjectDef<MyObj>()
        .def_ro("field1", &MyObj::field1);
    refl::TypeAttrDef<MyObj>()
        .def("__s_equal__", &MyObj::SEqual)
        .def("__s_hash__", &MyObj::SHash);
}
```
