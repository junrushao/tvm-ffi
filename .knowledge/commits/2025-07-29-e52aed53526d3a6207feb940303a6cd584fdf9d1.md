# Remove _type_has_method_sequal_reduce and _type_has_method_shash_reduce flags, completing SEqualReduce/SHashReduce phase-out
## TL;DR
- Deletes the `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` static constexpr flags from `Object` in `include/tvm/ffi/object.h`, removing the last vestiges of the old `SEqualReduce`/`SHashReduce` mechanism from the FFI core.
- Removes stale `std::cout` debug prints from `TCustomFuncObj::SEqual` in `tests/cpp/testing_object.h`, cleaning up test code that was carried over from the migration.
- This is the final commit in a 3-commit migration series (`2ec11f5` #18165, `59a837e` #18166, `e52aed5` #18172) that transitioned structural equality/hashing from the legacy `SEqualReduce`/`SHashReduce` visitor pattern to the new reflection-based `SEqual`/`SHash` methods with `_type_s_eq_hash_kind` and `TVMFFISEqHashKind` enum.

## Impact
- **API**: Removes `Object::_type_has_method_sequal_reduce` and `Object::_type_has_method_shash_reduce` static constants. Any downstream code (in the broader TVM ecosystem, outside this FFI repo) that reads these flags at compile time will fail to compile. Within this FFI repo, no code references these flags -- the prior commits in the series already removed all consumers and migrated to `_type_s_eq_hash_kind`.
- **Flags/config**: None.
- **Data formats/schemas**: None.
- **Behavioral**: The `TCustomFuncObj::SEqual` test helper no longer emits debug output to stdout on comparison failure. This is a test-only cleanup with no production impact.

## Design Elements
Design elements this commit **consumes**:

- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): The `Object` base class in `include/tvm/ffi/object.h` is the site of the change. The class previously declared `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` as compile-time boolean markers for optional structural equality/hashing support. The design doc's "Extension Points" and "Key Classes" sections list these flags as reserved. After this commit, they no longer exist.
- **Reflection system** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): The new reflection-based structural equality/hashing mechanism (`_type_s_eq_hash_kind` + `SEqual`/`SHash` methods registered via `ObjectDef`) is the replacement that made the old compile-time flags obsolete. The `TVMFFISEqHashKind` enum at `include/tvm/ffi/c_api.h:955-993` and the `structural_eq_hash_kind` field on `TVMFFITypeInfo` at `include/tvm/ffi/c_api.h:1118` are the runtime alternatives.
- **`_type_s_eq_hash_kind`** (`include/tvm/ffi/object.h:301`): The `Object` base still declares `static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindUnsupported` as the runtime replacement for the removed flags. Subtypes override this (e.g., `TFuncObj` sets `kTVMFFISEqHashKindTreeNode` at `tests/cpp/testing_object.h:228`).

Design elements this commit **produces**:

- None. This is a pure removal of deprecated code. No new design elements are introduced.

## Key Implementations

**What was removed from `include/tvm/ffi/object.h`**: Two static constexpr declarations in the `Object` base class:
```cpp
static constexpr const bool _type_has_method_sequal_reduce = false;
static constexpr const bool _type_has_method_shash_reduce = false;
```

**What was removed from `tests/cpp/testing_object.h`**: Two `std::cout` debug statements in `TCustomFuncObj::SEqual` that printed diagnostic messages ("custom s_equal failed params", "custom s_equal failed body") on comparison failure. These were leftover debugging aids from the migration work and were not part of the test assertions.

**Migration series context** (commits leading to this one):
1. `2ec11f5` (#18165): Enabled custom `SHash`/`SEqual` methods in the reflection system, providing the runtime alternative to the compile-time flags.
2. `59a837e` (#18166): Migrated `StructuralEqual`/`StructuralHash` implementations to the new reflection-based mechanism.
3. `e52aed5` (#18172): This commit -- removes the old compile-time flags and debug prints, completing the phase-out.

**Parallel with `_type_has_method_visit_attrs` removal**: This commit mirrors the pattern of `da47623` (#18106), which removed `_type_has_method_visit_attrs` as the final step of the `VisitAttrs` phase-out. Together, these two cleanup commits have removed all legacy compile-time method-presence flags from `Object`. The only type-related static flags remaining on `Object` are: `_type_key`, `_type_index`, `_type_final`, `_type_mutable`, `_type_child_slots`, `_type_child_slots_can_overflow`, `_type_depth`, and `_type_s_eq_hash_kind`.

**Invariants**:
- After this commit, `Object` carries no compile-time method-presence flags. All method capability discovery goes through runtime reflection (`TVMFFIGetTypeInfo` -> `methods`/`num_methods`) or the `_type_s_eq_hash_kind` enum.
- No references to `SEqualReduce` or `SHashReduce` remain anywhere in the codebase (confirmed via grep).
- The `_type_s_eq_hash_kind` field on `Object` defaults to `kTVMFFISEqHashKindUnsupported`, meaning types must explicitly opt in to structural equality/hashing by overriding this field.

**Extension point**: Subtypes opt into structural equality/hashing by (1) setting `_type_s_eq_hash_kind` to a non-`Unsupported` value, and (2) defining `SEqual` and/or `SHash` methods registered via `ObjectDef::def`. See `TCustomFuncObj` at `tests/cpp/testing_object.h:250-266` for an example.

## Reflection

### Design docs to write

- **`.knowledge/designs/0003-object-system.md` (update)**: The existing design doc still references `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` in two places: the "Key Classes" section (line 189) lists them as "Reserved flags", and the "Extension Points" section (line 213) describes them as reserved for structural equality/hashing. Both references should be removed and replaced with a note that structural equality/hashing is now handled via `_type_s_eq_hash_kind` (a `TVMFFISEqHashKind` enum) plus `SEqual`/`SHash` methods registered through reflection. This update helps future commit mining by preventing false matches against stale documentation when analyzing structural equality changes.

### ADRs to write

None. The decision to migrate from `SEqualReduce`/`SHashReduce` to the reflection-based `SEqual`/`SHash` mechanism was made in the broader TVM project. The existing reflection design doc and the `TVMFFISEqHashKind` enum documentation in `include/tvm/ffi/c_api.h:955-993` sufficiently capture the new mechanism.

### Design diagrams to draw

None. The change is a pure removal with no new structural relationships.
