# Remove deprecated _type_has_method_sequal_reduce/_type_has_method_shash_reduce capability flags from Object base class
## TL;DR
- Removes `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` static constexpr bool fields from the `Object` base class, completing the phase-out of the old SEqualReduce/SHashReduce plug-in mechanism in favor of `ffi/reflection`.
- Removes two `std::cout` debug print statements from the `TCustomFuncObj::SEqual` test helper in `tests/cpp/testing_object.h`.

## Key Exports
None

## Impact
- API: `Object` base class loses two `static constexpr bool` fields (`_type_has_method_sequal_reduce = false` and `_type_has_method_shash_reduce = false`). Any downstream code that reads or checks these fields (e.g., `T::_type_has_method_sequal_reduce`) will now fail to compile. In practice these fields existed only as default fallbacks and the new reflection mechanism no longer queries them.
- Behavioral: none — both fields were `false` by default and no production logic branched on them after the prior refactor.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0002-object-system` — the `Object` base class whose compile-time capability-flag protocol is being trimmed.
- `0006-reflection` — the replacement mechanism (field/method registration via `ReflectionDef`) that made the SEqualReduce/SHashReduce plug-in flags redundant.

Design elements this commit produces:
- `0002-object-system` — **mutated**: the `Object` metaclass protocol no longer includes `_type_has_method_sequal_reduce` or `_type_has_method_shash_reduce`. The capability-flag list on `Object` is now empty (both prior flags removed; `_type_has_method_visit_attrs` was removed in an earlier commit).
