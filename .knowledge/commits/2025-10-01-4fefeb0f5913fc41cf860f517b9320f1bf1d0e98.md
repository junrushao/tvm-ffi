# Allow strides to be null for zero-ndim tensors in Tensor::strides() and FromDLPack paths

## TL;DR

- The DLPack spec allows `strides == nullptr` for 0-dimensional tensors; TVM FFI was incorrectly rejecting this case with a hard check.
- Fix: relax the precondition in `Tensor::strides()`, `TensorView::strides()`, and all three `FromDLPack` / allocator paths from `strides != nullptr` to `strides != nullptr || ndim == 0`.
- `ShapeView(nullptr, 0)` is already a valid empty view, so the returned value is safe to use.

## Key Exports

```python
class Tensor(ObjectRef):
    def strides(self) -> ShapeView:
        """Non-owning view into strides int64_t[]. Returns empty ShapeView(nullptr, 0) when ndim == 0."""
        # OLD invariant (pre-4fefeb0): DLTensor::strides MUST NOT be nullptr
        # NEW invariant (post-4fefeb0): DLTensor::strides may be nullptr iff ndim == 0
        # Interacts with: ShapeView (returned value), TensorObj.strides (DLTensor field)
        # Invariant: strides is nullptr only when ndim == 0 (DLPack spec allows this)
        ...

    @staticmethod
    def FromDLPack(tensor: DLManagedTensor*, ...) -> Tensor:
        # OLD: strides != nullptr → wrap as-is; else → tail-alloc computed strides
        # NEW: (strides != nullptr || ndim == 0) → wrap as-is; else → tail-alloc computed strides
        # Zero-ndim case wraps the tensor with strides=nullptr directly; tail allocation skipped.
        ...

    @staticmethod
    def FromDLPackVersioned(tensor: DLManagedTensorVersioned*, ...) -> Tensor: ...
    # Same fix as FromDLPack above.

    @staticmethod
    def FromNDAllocVersioned(allocator: NDAllocator*, ...) -> Tensor:
        # Same fix: allocator may return strides=nullptr for ndim==0; wrap as-is.
        ...

class TensorView:
    def strides(self) -> ShapeView:
        # OLD invariant: tensor_.strides MUST NOT be nullptr
        # NEW invariant: tensor_.strides may be nullptr iff tensor_.ndim == 0
        # Interacts with: DLTensor (borrowed struct), ShapeView
        ...
```

## Impact

- API: None — `strides()` return type and callers unchanged.
- Behavioral: `Tensor::strides()` no longer aborts on zero-ndim tensors; returns an empty `ShapeView(nullptr, 0)`. Before this fix, calling `strides()` on a zero-ndim tensor obtained from an external DLPack source would crash with `TVM_FFI_ICHECK` failure.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- `Tensor::strides()` / `TensorView::strides()` — the strides accessor, documented in `.knowledge/design-records/0007-containers.md`
- `ShapeView` — non-owning view returned by strides; `ShapeView(nullptr, 0)` is valid for empty/zero-ndim case
- `FromDLPack` / `FromDLPackVersioned` / allocator path — DLPack ingestion logic in `tensor.h`

Design elements this commit produces:
- Tightened `strides()` invariant: the assertion `strides != nullptr || ndim == 0` replaces the old `strides != nullptr`. This is a contract mutation, not a new element.

## Usage Examples

**Before (incorrect — crashes on zero-ndim external DLPack tensor):**
```cpp
// External DLPack producer sets strides = nullptr, ndim = 0 (valid per spec)
DLManagedTensor* ext = ...;   // ext->dl_tensor.ndim == 0, strides == nullptr
Tensor t = Tensor::FromDLPack(ext);   // was: falls through to strides-compute path — BUG
t.strides();  // was: TVM_FFI_ICHECK(strides != nullptr) → abort
```

**After (correct — zero-ndim tensor handled):**
```cpp
DLManagedTensor* ext = ...;   // ext->dl_tensor.ndim == 0, strides == nullptr
Tensor t = Tensor::FromDLPack(ext);   // now: (strides != nullptr || ndim == 0) → wrap as-is
ShapeView sv = t.strides();           // now: ShapeView(nullptr, 0) — empty, valid
assert(sv.size() == 0);              // true — no dimensions, no strides
```
