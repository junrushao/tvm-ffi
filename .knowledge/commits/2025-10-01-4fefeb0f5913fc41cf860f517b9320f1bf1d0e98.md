# Allow null strides for zero-dim tensors in Tensor and TensorView
## TL;DR
- Fixes edge case where `strides()` accessor and `FromDLPack` methods would fail on zero-dimensional tensors that have null strides pointers.
- Changes 5 guard conditions from `strides != nullptr` to `strides != nullptr || ndim == 0` across `Tensor` and `TensorView`.

## Impact
- API: No signature changes. Behavioral fix: zero-dim tensors no longer trigger assertion failures when accessing strides or importing via DLPack.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Container system / Tensor** (`.knowledge/designs/0005-containers.md`): The DLPack import paths (`FromDLPack` for both `DLManagedTensor` and `DLManagedTensorVersioned`) and the `strides()` accessor on both `Tensor` and `TensorView`.
- **DLPack exchange protocol** (`.knowledge/designs/0020-dlpack-exchange-acceleration.md`): The strides-null convention from DLPack where null strides implies compact/contiguous layout.

Design elements this commit produces:
- **Invariant refinement**: Zero-dim tensors are a valid edge case where `strides == nullptr` is acceptable. This tightens the invariant documentation for `Tensor::strides()` and `TensorView::strides()`.
