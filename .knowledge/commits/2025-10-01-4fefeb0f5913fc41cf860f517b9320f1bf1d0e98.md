# Fix strides null-check to allow zero-dim tensors with null strides
## TL;DR
- Relaxes the `strides != nullptr` assertion in `Tensor::strides()`, `TensorView::strides()`, and three `FromDLPack` variants to also accept `ndim == 0` (zero-dimensional/scalar tensors).
- A zero-dim tensor has no stride values, so `strides == nullptr` is a valid DLPack representation; the previous unconditional null-check would crash on such tensors imported from external DLPack sources.

## Key Exports
No new API surface. The change modifies the precondition of five existing code paths:

| Location | Old precondition | New precondition |
|----------|-----------------|-----------------|
| `Tensor::strides()` | `strides != nullptr` | `strides != nullptr \|\| ndim == 0` |
| `TensorView::strides()` | `strides != nullptr` | `strides != nullptr \|\| ndim == 0` |
| `Tensor::FromExternalAllocator(DLManagedTensorVersioned*)` | `strides != nullptr` | `strides != nullptr \|\| ndim == 0` |
| `Tensor::FromDLPack(DLManagedTensor*)` | `strides != nullptr` | `strides != nullptr \|\| ndim == 0` |
| `Tensor::FromDLPackVersioned(DLManagedTensorVersioned*)` | `strides != nullptr` | `strides != nullptr \|\| ndim == 0` |

## Impact
- API: None -- no signature changes. The behavioral contract of `strides()` is relaxed (accepts a broader set of valid inputs).
- Behavioral: `Tensor::strides()` and `TensorView::strides()` now return an empty `ShapeView` (size 0, possibly null data pointer) for zero-dim tensors instead of crashing. The three `FromDLPack` variants now treat zero-dim tensors with null strides the same as tensors with non-null strides (no synthetic stride allocation needed since there are zero stride values).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Tensor strides invariant** ([0008-containers.md](../designs/0008-containers.md)): The "Tensor strides are always non-null" invariant established in commit ca95b41 and documented in the containers design doc. This commit reveals the invariant was too strict -- it did not account for the zero-dim edge case where null strides are semantically valid.
- **ShapeView** ([0008-containers.md](../designs/0008-containers.md)): `ShapeView(nullptr, 0)` is a valid construction (the default constructor produces exactly this), so the zero-dim case is safe downstream.
- **TVM_FFI_ICHECK macro** ([0006-error-handling.md](../designs/0006-error-handling.md)): Used for the assertion check.
- **DLPack import path** ([0017-dlpack-interop.md](../designs/0017-dlpack-interop.md)): The `FromDLPack`/`FromDLPackVersioned`/`FromExternalAllocator` methods that branch on strides nullity to decide whether to synthesize strides via inplace allocation.

Design elements this commit produces:
- **Relaxed strides invariant for zero-dim tensors**: The new invariant is: "All tensors with `ndim > 0` have non-null strides; zero-dim tensors may have null strides." This is a refinement, not a new design element.

## Usage Examples
**Before (crash on zero-dim tensor with null strides):**
```cpp
// External source provides a zero-dim DLPack tensor with strides == nullptr
DLManagedTensor dlm;
dlm.dl_tensor.ndim = 0;
dlm.dl_tensor.strides = nullptr;  // valid per DLPack spec
auto t = Tensor::FromDLPack(&dlm);  // OK -- no crash in FromDLPack
t.strides();  // CRASH: TVM_FFI_ICHECK(strides != nullptr) fails
```

**After (zero-dim tensor with null strides works correctly):**
```cpp
DLManagedTensor dlm;
dlm.dl_tensor.ndim = 0;
dlm.dl_tensor.strides = nullptr;
auto t = Tensor::FromDLPack(&dlm);  // OK
ShapeView s = t.strides();          // OK: returns ShapeView(nullptr, 0) -- empty view
assert(s.size() == 0);              // zero stride values, as expected for scalar
```
