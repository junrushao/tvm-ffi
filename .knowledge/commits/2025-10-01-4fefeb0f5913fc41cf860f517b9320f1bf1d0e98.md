# Allow null strides for zero-ndim (scalar) tensors in strides accessors and DLPack import

## TL;DR
- Relaxes the strides-non-null invariant (from `ca95b41`) to permit `strides == nullptr` when `ndim == 0`, fixing a crash when accessing strides of scalar (zero-dimensional) DLPack tensors.
- Five identical guard changes across `Tensor::strides()`, `TensorView::strides()`, and three `FromDLPack*` factory methods: `strides != nullptr` becomes `strides != nullptr || ndim == 0`.
- `ShapeView(nullptr, 0)` is valid and returns an empty view, so the relaxed check is safe.

## Key Exports

```python
class Tensor(ObjectRef):
    def strides(self) -> ShapeView: ...
        # Old invariant: strides pointer must be non-null (asserted via TVM_FFI_ICHECK)
        # New invariant: strides pointer must be non-null OR ndim == 0
        # Interacts with: ShapeView (returns ShapeView(nullptr, 0) for scalar tensors)

class TensorView:
    def strides(self) -> ShapeView: ...
        # Same invariant relaxation as Tensor::strides()
        # Interacts with: DLTensor.strides, DLTensor.ndim

# FromDLPack factory methods (3 variants):
# Tensor.FromDLPack(DLManagedTensor*, ...)
# Tensor.FromDLPack(DLManagedTensorVersioned*, TVMFFINDAllocator*, ...)
# Tensor.FromDLPackVersioned(DLManagedTensorVersioned*, ...)
#
# Old: if strides != nullptr -> wrap without tail-allocating strides
#      else -> tail-allocate strides via make_inplace_array_object
# New: if strides != nullptr || ndim == 0 -> wrap without tail-allocating strides
#      else -> tail-allocate strides
# Invariant: for ndim==0, no tail allocation needed regardless of strides pointer value
```

## Impact
- API: none -- no signature changes, only relaxed precondition.
- Behavioral: `Tensor::strides()` and `TensorView::strides()` no longer crash on scalar (zero-ndim) tensors with null strides. They return an empty `ShapeView`.
- Flags/config: none.
- Data formats/schemas: DLPack import now correctly handles zero-ndim tensors where `strides == nullptr`, consistent with the DLPack specification which allows null strides for scalars.

## Design Elements
Design elements this commit consumes:
- **TensorObj / Tensor** ([0007-containers](../designs/0007-containers.md)) -- strides accessor and DLPack factory methods.
- **ShapeView** ([0007-containers](../designs/0007-containers.md)) -- `ShapeView(nullptr, 0)` is valid for empty views.
- **DLPack interop** ([0007-containers](../designs/0007-containers.md)) -- `DLManagedTensor` and `DLManagedTensorVersioned` import paths.
- **Always-non-null strides invariant** (established in `ca95b41`, documented in [ADR 0012](../ADRs/0012-inplace-tail-allocation-for-tensor-metadata.md)).

Design elements this commit produces:
- **Relaxed strides invariant for zero-ndim tensors** (mutates existing invariant): strides may be null when `ndim == 0`. The corrected invariant is: `strides != nullptr` for `ndim > 0` tensors; for `ndim == 0`, strides may be null because there are no dimensions requiring stride values.

## Usage Examples

Before (crashes on scalar tensor with null strides from external DLPack source):
```cpp
// External framework produces a scalar DLManagedTensor with strides=nullptr, ndim=0
DLManagedTensor* ext_scalar = get_external_scalar_tensor();
// ext_scalar->dl_tensor.ndim == 0
// ext_scalar->dl_tensor.strides == nullptr  (valid per DLPack spec for scalars)

Tensor t = Tensor::FromDLPack(ext_scalar);
ShapeView s = t.strides();  // CRASH: TVM_FFI_ICHECK(strides != nullptr) fails
```

After (works correctly):
```cpp
DLManagedTensor* ext_scalar = get_external_scalar_tensor();
Tensor t = Tensor::FromDLPack(ext_scalar);
ShapeView s = t.strides();  // OK: returns ShapeView(nullptr, 0) -- empty view
assert(s.size() == 0);      // scalar has no stride dimensions
```
