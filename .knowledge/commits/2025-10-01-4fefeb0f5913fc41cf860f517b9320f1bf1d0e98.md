# Fix Tensor strides accessor and DLPack import to allow null strides for zero-dim tensors
## TL;DR
- Relaxes the "strides always non-null" invariant (established in ca95b41) for zero-dimensional (scalar) tensors, where `strides == nullptr` is a valid DLPack state.
- Updates five check sites in `tensor.h`: `Tensor::strides()`, `TensorView::strides()`, `Tensor::FromDLPackAlloc`, `Tensor::FromDLPack`, and `Tensor::FromDLPackVersioned`.
- Each site changes the condition from `strides != nullptr` to `strides != nullptr || ndim == 0`, ensuring zero-dim tensors with null strides are accepted rather than triggering assertion failures or being routed to the synthetic-strides code path.

## Key Exports
None -- no new public API surface. This commit modifies the behavior of existing accessors and factory methods.

## Impact
- API: none -- `Tensor::strides()` and `TensorView::strides()` signatures unchanged; callers of zero-dim tensors that previously hit `TVM_FFI_ICHECK` failures will now succeed.
- ABI: none -- no struct/enum/signature changes.
- Behavioral: `Tensor::strides()` and `TensorView::strides()` now return an empty `ShapeView` (length 0) for zero-dim tensors with `strides == nullptr`, instead of failing an internal check. `FromDLPack`/`FromDLPackVersioned`/`FromDLPackAlloc` now route zero-dim tensors with null strides through the direct `TensorObjFromDLPack` path (without synthesizing strides via `make_inplace_array_object`), since there are no strides to synthesize for a scalar.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Always-populated strides invariant** (ca95b41, documented in `.knowledge/designs/containers.md` Tensor section): The commit modifies this invariant by adding a zero-dim exception. Previously the invariant was unconditional: `strides` is never null after construction.
- **DLPack import path** (`.knowledge/designs/0018-dlpack-fast-path.md`): The `FromDLPack` / `FromDLPackVersioned` / `FromDLPackAlloc` factory methods use `strides != nullptr` as the discriminator between direct DLPack wrapping vs. synthetic stride computation via `make_inplace_array_object`.
- **TensorView** (commit 1ec6236, PR #81): The non-owning `TensorView` class introduced in the immediately preceding commit also has a `strides()` accessor with the same check.

Design elements this commit produces:
- **Relaxed strides invariant for zero-dim tensors**: The strides pointer may be null when `ndim == 0`. This is a carve-out from the general "always-populated strides" rule. The condition `strides != nullptr || ndim == 0` must be used at all check sites instead of `strides != nullptr`.

## Usage Examples
Before/after pattern showing the fix:

```cpp
// Before (crashes for zero-dim DLPack tensor with null strides):
DLManagedTensor managed;
managed.dl_tensor.ndim = 0;
managed.dl_tensor.strides = nullptr;  // valid per DLPack spec for scalars
managed.dl_tensor.shape = nullptr;
// ...
Tensor t = Tensor::FromDLPack(&managed);
ShapeView s = t.strides();  // CRASH: TVM_FFI_ICHECK(obj->strides != nullptr) fails

// After (works correctly):
Tensor t = Tensor::FromDLPack(&managed);
ShapeView s = t.strides();  // OK: returns empty ShapeView (length 0)
assert(s.size() == 0);
```
