# Add keep_module_alive flag and ModuleGlobals singleton to prevent use-after-unload
## TL;DR
- Introduces `ModuleGlobals`, a thread-safe C++ singleton that holds strong references to loaded modules so they are never `dlclose`d while `libtvm_ffi.so` is alive. Registered via `ffi.ModuleGlobalsAdd` / `ffi.ModuleGlobalsRemove` FFI methods.
- Adds `keep_module_alive: bool = True` parameter to `load_module`, `cpp.load_inline`, and `cpp.load`. When True (default), the module is pinned in `ModuleGlobals`, eliminating the "module must outlive returned objects" use-after-unload problem.
- Removes all manual lifetime management workarounds from tests (`gc.collect()`, `del mod`, nested `run_check()` scoping pattern), since modules now survive for the process lifetime by default.

## Impact
- API: Additive -- `keep_module_alive` parameter added to `load_module`, `cpp.load_inline`, `cpp.load`. Default is `True`, so existing callers get the new behavior without code changes. Callers who need the old behavior (module unloaded when last Python ref dies) can pass `keep_module_alive=False`.
- Behavioral: Modules loaded via the default path are now pinned in memory for the process lifetime. This changes the destruction semantics -- `dlclose` is deferred indefinitely. This is a trade-off: safety (no use-after-unload) at the cost of memory (loaded `.so` files stay mapped).
- Flags/config: New `keep_module_alive` parameter (default `True`) on 3 Python APIs.
- Data formats/schemas: none

Design elements this commit produces:
- **ModuleGlobals singleton**: New C++ class in `src/ffi/extra/module.cc` providing a thread-safe global registry for pinning module lifetimes. Not yet documented in any design doc.
- **`keep_module_alive` parameter**: New convention across all module-loading Python APIs. Changes the default lifetime semantics from "module dies with last Python ref" to "module lives for the process."

## Usage Examples
**Before** (required manual lifetime management):
```python
mod = tvm_ffi.load_module("my_lib.so")
def run_check():
    tensor = mod.return_tensor(x)  # tensor's deleter lives in the .so
    # tensor is destroyed when run_check returns
run_check()
gc.collect()
del mod
```

**After** (default behavior -- no manual management needed):
```python
mod = tvm_ffi.load_module("my_lib.so")  # keep_module_alive=True by default
tensor = mod.return_tensor(x)
# Safe: mod is pinned in ModuleGlobals, .so never unloaded
```

**Opt-out** (for memory-constrained scenarios):
```python
mod = tvm_ffi.load_module("my_lib.so", keep_module_alive=False)
# Caller must manually ensure Module outlives all returned objects
```
