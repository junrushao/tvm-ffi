# Add keep_module_alive flag to load_module to prevent premature DSO unload
## TL;DR
- Introduces `keep_module_alive: bool = True` parameter to `load_module()`, `cpp.load_inline()`, and `cpp.load()`. When True (default), the loaded module is registered in a C++ `ModuleGlobals` singleton that holds a reference, preventing premature unload.
- Adds C++ `ModuleGlobals` class (mutex-protected `Map<Module, int>` singleton) with `Add`/`Remove` methods, exposed as `ffi.ModuleGlobalsAdd`/`ffi.ModuleGlobalsRemove`.
- Removes all manual `gc.collect()` / `del mod` workarounds from tests, since modules now stay alive for the program's lifetime by default.

## Key Exports

**C++ class** (internal, `src/ffi/extra/module.cc`):
```cpp
class ModuleGlobals {
  void Add(const Module& m);     // thread-safe, adds to map
  void Remove(const Module& m);  // thread-safe, removes from map
  static ModuleGlobals* Get();   // singleton accessor
private:
  Map<Module, int> modules_;
  std::mutex mutex_;
};
```

**Registered FFI functions** (new):
- `ffi.ModuleGlobalsAdd(Module) -> None`
- `ffi.ModuleGlobalsRemove(Module) -> None`

**Python API changes**:
```python
def load_module(path: str | PathLike, keep_module_alive: bool = True) -> Module: ...
def load_inline(..., keep_module_alive: bool = True) -> Module: ...
def load(..., keep_module_alive: bool = True) -> Module: ...
```

## Impact
- API: New optional `keep_module_alive` parameter added to `load_module`, `cpp.load_inline`, `cpp.load`. Default `True` is backward-compatible in terms of API but changes behavior (modules now kept alive).
- Behavioral: Loaded modules are no longer garbage-collected when Python references are dropped. This fixes use-after-free crashes (issues #264, #322) where objects containing destructors from the loaded DSO outlived the module. The trade-off is that DSO memory is not reclaimed until process exit.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system** (`.knowledge/designs/0013-module-system.md`) -- `ModuleObj`, `load_module`, `Module` ref wrapper
- **Reflection registry** -- `def_method` for registering `ModuleGlobalsAdd`/`ModuleGlobalsRemove`

Design elements this commit produces:
- **`ModuleGlobals` singleton** -- thread-safe global registry of modules that should not be unloaded. Lifetime is tied to `libtvm_ffi.so` (static storage duration). This is a new extension point: downstream code can call `ModuleGlobalsRemove` to explicitly allow unloading.
- **`keep_module_alive` convention** -- default-True parameter across all module loading APIs. This establishes the invariant that loaded DSOs survive for the program's lifetime unless explicitly opted out.

## Usage Examples

Default usage (module stays alive):
```python
import tvm_ffi

# Module is kept alive -- no need for gc.collect() before exit
mod = tvm_ffi.load_module("my_kernels.so")
result = mod.my_func(x, y)
# Safe: objects from mod can outlive the `mod` variable
```

Opt-out (allow module unload):
```python
mod = tvm_ffi.load_module("my_kernels.so", keep_module_alive=False)
# Caller is responsible for ensuring all objects from mod are freed before mod is GC'd
```
