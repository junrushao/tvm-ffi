# Add keep_module_alive flag to load_module and JIT APIs with global module registry
## TL;DR
- Introduces a C++ `ModuleGlobals` singleton (thread-safe via `std::mutex`) that holds strong references to loaded modules, preventing unload for the program's lifetime.
- Adds `keep_module_alive: bool = True` parameter to `load_module`, `cpp.load_inline`, and `cpp.load`. Default `True` means modules are pinned globally, eliminating the need for manual object-before-module destruction ordering.
- Tests simplified: removes `gc.collect()` / `del mod` / scoped-function workarounds that previously guarded against use-after-free from premature module unload.

## Impact
- API: Additive -- new `keep_module_alive` parameter with default `True` on `load_module`, `cpp.load_inline`, `cpp.load`. Existing callers with no keyword arg get the new keep-alive behavior automatically.
- Behavioral: Modules loaded via these APIs are now retained globally by default. This relaxes the previous "objects must be destroyed before module unloads" invariant for the common case. Users no longer need `del mod; gc.collect()` patterns.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system** ([0011-ffi-module-system](../design-records/0011-ffi-module-system.md)): `ModuleObj`, `Module`, `_ffi_api.ModuleLoadFromFile`, reflection-based `def_method` registration.
- **FFI containers** ([0006-ffi-containers](../design-records/0006-ffi-containers.md)): `Map<Module, int>` used as a set in `ModuleGlobals`.
- **Reflection** ([0007-ffi-reflection](../design-records/0007-ffi-reflection.md)): `ObjectDef<ModuleObj>::def_method` with lambda for registering `ModuleGlobalsAdd`/`ModuleGlobalsRemove`.

Design elements this commit produces:
- **ModuleGlobals singleton**: New C++ class providing a global keep-alive registry for modules. Thread-safe, static lifetime. Exposed to Python as `_ffi_api.ModuleGlobalsAdd` / `_ffi_api.ModuleGlobalsRemove`.
- **Module keep-alive protocol**: The convention that `keep_module_alive=True` (default) pins a module in `ModuleGlobals`, shifting lifetime management from caller-managed to globally-managed. This relaxes the previous module-object lifetime invariant for default usage.

## Usage Examples
**Context**: Loading a module with the new default keep-alive behavior (no manual cleanup needed).
```python
import tvm_ffi

# Before this commit: required careful destruction ordering
# mod = tvm_ffi.load_module("my_lib.so")
# result = mod.my_func(x)
# del result, x, mod  # must destroy objects before module unloads
# gc.collect()

# After this commit: module stays alive globally, no manual cleanup
mod = tvm_ffi.load_module("my_lib.so")  # keep_module_alive=True by default
result = mod.my_func(x)
# No cleanup needed -- module is pinned in ModuleGlobals
```

**Context**: Explicitly opting out of keep-alive for resource-sensitive scenarios.
```python
mod = tvm_ffi.load_module("temp_lib.so", keep_module_alive=False)
# Caller must manage lifetime manually (old behavior)
```
