# Improve type hint of register_object to preserve decorated class type via TypeVar
## TL;DR
- Introduces `_T = TypeVar("_T", bound=type)` and replaces all `type` annotations in `register_object` with `_T`, so the decorator preserves the original class type in type checkers.
- Removes the bare `type` from the `type_key` parameter union (`str | type | None` becomes `str | None`), narrowing the declared overload surface. The runtime behavior of passing a class directly is unchanged (handled by the `if type_key is None` branch).
- No functional change; purely a type-annotation improvement.

## Key Exports

```python
_T = TypeVar("_T", bound=type)

# Old: def register_object(type_key: str | type | None = None) -> Callable[[type], type] | type
def register_object(type_key: str | None = None) -> Callable[[_T], _T]:
    """Register object type."""
    # Interacts with: core._object_type_key_to_index, core._register_object_by_index, _add_class_attrs
    # Invariant: returned class is the same object as the input class (identity-preserving decorator)
    ...
```

## Impact
- API: Type-hint-only change. Callers using `@register_object("key")` now see the decorated class's type preserved instead of generic `type`. The `type` variant in the `type_key` union is removed from hints, though runtime still accepts it.
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none
