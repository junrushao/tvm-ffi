# Improve register_object type hints to preserve decorated class type identity
## TL;DR
- Introduce `TypeVar("_T", bound=type)` in `registry.py` so that `register_object` decorator preserves the exact class type through the decorator, fixing type-checker errors where the decorated class was treated as a generic `type` value instead of its specific type.
- Remove `type` from the `type_key` union (was `str | type | None`, now `str | None`) — the bare-class overload path is unchanged in behavior but the signature no longer advertises `type` as a valid first argument.

## Key Exports
**Functions** (mutated signature):
- `register_object(type_key: str | None = None) -> Callable[[_T], _T]` — previously returned `Callable[[type], type] | type`, now uses `_T = TypeVar("_T", bound=type)` to preserve the decorated class's type identity.

## Impact
- API: The runtime behavior is unchanged. The type signature narrows `type_key` from `str | type | None` to `str | None`, which could affect static type checkers for callers passing a bare class as positional arg — but the runtime code still handles that case via `isinstance` checks.
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit produces: none (refinement of existing API)

Design elements this commit mutates:
- **`register_object` type signature** — tighter generic return type for better static analysis.

## Usage Examples
```python
# Before: type checker sees `Foo` as `type` after decoration
@register_object("mymod.Foo")
class Foo(Object):
    pass
# reveal_type(Foo) -> type  (loses class identity)

# After: type checker preserves `Foo`'s type
@register_object("mymod.Foo")
class Foo(Object):
    pass
# reveal_type(Foo) -> type[Foo]  (class identity preserved)
```
