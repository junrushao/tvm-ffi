# Improve register_object type hint to preserve decorated class type via TypeVar
## TL;DR
- Introduces a `_T = TypeVar("_T", bound=type)` in `python/tvm_ffi/registry.py` so that `register_object` preserves the decorated class's original type through the decorator, eliminating type-checker lint errors where the return was previously widened to `type`.
- Removes `type` from the `type_key` parameter union (`str | type | None` -> `str | None`) in the public signature, since the bare-class call path is handled internally but not advertised in the annotation.

## Key Exports
**Functions** (signature change only):
- `register_object(type_key: str | None = None) -> Callable[[_T], _T]` -- previously returned `Callable[[type], type] | type`. The `_T` TypeVar (`bound=type`) ensures type checkers narrow the return to the exact subclass passed in.

**Module-level variable** (new):
- `_T = TypeVar("_T", bound=type)` -- private TypeVar in `python/tvm_ffi/registry.py`.

## Impact
- API: Signature of `register_object` changed for type-checking purposes only; runtime behavior is identical. Callers that previously relied on `type` in the `type_key` union at the type-annotation level may see a minor type-checker difference, but the runtime code path (`isinstance(type_key, type)`) is still present.

## Usage Examples
None -- the usage pattern is unchanged. The improvement is purely at the static type-checking level:

```python
@tvm_ffi.register_object("test.MyObject")
class MyObject(Object):
    pass

# Before: type checker infers MyObject as `type` (loses class identity)
# After:  type checker infers MyObject as `type[MyObject]` (preserves class identity)
reveal_type(MyObject)  # Now correctly: type[MyObject]
```
