# Add CUDA stream protocol support to Cython arg setter dispatch

## TL;DR
- Added `TVMFFIPyArgSetterCUDAStream_` Cython setter that converts objects implementing the `__cuda_stream__` protocol into opaque `void*` pointers via the ABI.
- Registered the new setter in `TVMFFIPyArgSetterFactory_`, placed after `__c_dlpack_exchange_api__` and before torch/dlpack fallbacks.
- Fixed `__dlpack__` dispatch to check `arg_class` (the type) instead of `arg` (the instance), aligning it with the `__cuda_stream__` and `__c_dlpack_exchange_api__` class-level checks.

## Key Exports

```python
# --- New Cython setter (python/tvm_ffi/cython/function.pxi) ---

def TVMFFIPyArgSetterCUDAStream_(
    handle: TVMFFIPyArgSetter,
    ctx: TVMFFIPyCallContext,
    py_arg: object,
    out: TVMFFIAny,
) -> int:
    """Convert a __cuda_stream__ object to an opaque void* for ABI passage."""
    # Protocol: py_arg.__cuda_stream__() -> tuple[str, int]
    #   tuple[0] = device kind (e.g. "cuda")
    #   tuple[1] = raw stream pointer as int
    # out.type_index = kTVMFFIOpaquePtr
    # out.v_ptr = <void*>stream_ptr
    # Interacts with: TVMFFIPyArgSetterFactory_ (dispatch), TVMFFIPyCallManager (caller)
    # Interacts with: NVIDIA cuda-python __cuda_stream__ protocol
    #   (https://nvidia.github.io/cuda-python/cuda-core/latest/interoperability.html#cuda-stream-protocol)
    # Invariant: __cuda_stream__() must return a 2-tuple; element [1] must be a valid pointer as int
    # Extension: any Python class implementing __cuda_stream__() is automatically handled
    ...

# --- Modified dispatch order in TVMFFIPyArgSetterFactory_ ---
# Insertion point: after __c_dlpack_exchange_api__ check, before torch.Tensor check
# Priority chain (relevant excerpt):
#   ... -> __tvm_ffi_tensor__ -> __c_dlpack_exchange_api__ -> __cuda_stream__ (NEW)
#        -> torch.Tensor -> __dlpack__ (fix: now checks arg_class, not arg) -> ...
```

## Impact
- API: New -- objects implementing `__cuda_stream__()` are now passable through FFI function calls as opaque pointers. No existing callers broken.
- Behavioral: `__dlpack__` dispatch now checks the class (`arg_class`) instead of the instance (`arg`). This is a consistency fix aligning with how `__c_dlpack_exchange_api__` and `__cuda_stream__` are checked. Should be transparent for correct implementations since `hasattr(type(x), attr)` and `hasattr(x, attr)` agree for dunder methods.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyArgSetter dispatch protocol** ([0012-ffi-python-package.md](../design-records/0012-ffi-python-package.md)) -- follows the established pattern: implement a `TVMFFIPyArgSetter*` C function, register it in `TVMFFIPyArgSetterFactory_`.
- **kTVMFFIOpaquePtr type index** ([0001-ffi-c-abi.md](../design-records/0001-ffi-c-abi.md)) -- the stream pointer is passed as `kTVMFFIOpaquePtr` through the ABI, matching how raw pointers are handled.
- **TVMFFIPyCallContext** ([0012-ffi-python-package.md](../design-records/0012-ffi-python-package.md)) -- setter receives the call context though does not use device/stream fields from it.

Design elements this commit produces:
- **`__cuda_stream__` protocol support in Cython dispatch** -- new setter `TVMFFIPyArgSetterCUDAStream_` and its factory registration. This is the Python-side counterpart to the NVIDIA cuda-python stream interoperability protocol.

## Usage Examples
From the test (`tests/python/test_device.py`):
```python
class MyDummyStream:
    def __init__(self, stream: int) -> None:
        self.stream = stream

    def __cuda_stream__(self) -> tuple[str, int]:
        return ("cuda", self.stream)

stream = MyDummyStream(1)
echo = tvm_ffi.get_global_func("testing.echo")
y = echo(stream)
assert isinstance(y, ctypes.c_void_p)
assert y.value == 1
```
