# Add CUDA stream protocol support to Cython argument setter dispatch
## TL;DR
- Adds a new Cython arg setter (`TVMFFIPyArgSetterCUDAStream_`) that handles objects implementing the `__cuda_stream__` protocol, converting them to `kTVMFFIOpaquePtr` for the C ABI.
- Inserts `__cuda_stream__` dispatch in the `TVMFFIPyArgSetterFactory_` priority chain after DLPack exchange API but before torch and `__dlpack__` checks.
- Fixes a latent bug: the `__dlpack__` hasattr check was on the instance (`arg`) instead of the class (`arg_class`), now corrected to match the pattern used by other protocol checks.

## Key Exports

**Cython setter function (internal, not public Python API):**
- `TVMFFIPyArgSetterCUDAStream_(handle, ctx, py_arg, out)` -- Cython `cdef` function. Calls `arg.__cuda_stream__()` which returns a tuple `(str, int)`. Extracts the integer stream pointer from index 1, sets `out.type_index = kTVMFFIOpaquePtr` and `out.v_ptr = <void*>long_ptr`.

**Protocol:**
- `__cuda_stream__() -> tuple[str, int]` -- Python dunder protocol (defined by [NVIDIA cuda.core](https://nvidia.github.io/cuda-python/cuda-core/latest/interoperability.html#cuda-stream-protocol)). Objects implementing this are automatically converted to opaque pointers when passed as FFI arguments.

## Impact
- API: Objects implementing `__cuda_stream__` are now automatically accepted as FFI function arguments, converted to `void*` (opaque pointer). No new public Python API -- the conversion is transparent during packed function calls.
- ABI: none -- the stream is passed as `kTVMFFIOpaquePtr`, which already exists in the type index enum.
- Behavioral: (1) CUDA stream objects are now dispatched before torch tensors and `__dlpack__` objects in the setter factory priority chain. (2) The `__dlpack__` hasattr check is corrected from `hasattr(arg, "__dlpack__")` to `hasattr(arg_class, "__dlpack__")`, matching the class-level check pattern used by `__c_dlpack_exchange_api__` and now `__cuda_stream__`. This could change behavior for objects where `__dlpack__` is an instance attribute rather than a class attribute (unlikely in practice).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyArgSetter dispatch system** (`.knowledge/designs/0014-python-bindings.md`, Setter Dispatch Table) -- the cached type-dispatch architecture where `TVMFFIPyArgSetterFactory_` creates setters once per Python type and caches them in the thread-local `dispatch_map_`.
- **kTVMFFIOpaquePtr type index** (`.knowledge/designs/any-system.md`) -- the existing type index used to pass raw pointers through the FFI.
- **NVIDIA CUDA stream protocol** (external: `__cuda_stream__() -> tuple[str, int]`) -- the interoperability protocol from cuda.core.

Design elements this commit produces:
- **CUDA stream protocol integration** -- A new setter in the Cython dispatch chain that bridges NVIDIA's `__cuda_stream__` protocol to TVM FFI's opaque pointer passing convention. Stream objects become first-class FFI arguments.

## Usage Examples

Passing a CUDA stream object to an FFI function:

```python
import tvm_ffi

# Any object implementing __cuda_stream__ works
class MyCUDAStream:
    def __init__(self, stream_ptr: int) -> None:
        self.stream_ptr = stream_ptr

    def __cuda_stream__(self) -> tuple[str, int]:
        return ("cuda", self.stream_ptr)

stream = MyCUDAStream(0x7f00deadbeef)
echo = tvm_ffi.get_global_func("testing.echo")
result = echo(stream)  # automatically converted to void* via __cuda_stream__
assert result.value == 0x7f00deadbeef
```
