# Add __cuda_stream__ protocol support to Cython arg setter dispatch

## TL;DR

- Adds `TVMFFIPyArgSetterCUDAStream_` — a new Cython setter that handles objects implementing the [CUDA stream protocol](https://nvidia.github.io/cuda-python/cuda-core/latest/interoperability.html#cuda-stream-protocol) (`__cuda_stream__()` returns `(str, int)` tuple). The stream is passed into the FFI as `kTVMFFIOpaquePtr` (void pointer, numeric value of stream handle).
- Fixes a latent bug in `TVMFFIPyArgSetterFactory_`: `hasattr(arg, "__dlpack__")` was changed to `hasattr(arg_class, "__dlpack__")` so the DLPack check matches the `__cuda_stream__` check (both now operate on the class, not the instance) — consistent with how all other dispatch entries work.
- The `__cuda_stream__` check is placed before the torch.Tensor fallback and the `__dlpack__` check, because CUDA stream objects may be subclasses of `str` and would otherwise be misdispatched.

## Key Exports

```python
# ─── python/tvm_ffi/cython/function.pxi ─────────────────────────────────────

cdef int TVMFFIPyArgSetterCUDAStream_(
    TVMFFIPyArgSetter* handle, TVMFFIPyCallContext* ctx,
    PyObject* py_arg, TVMFFIAny* out
) -> int:
    """Setter for objects that implement the cuda stream protocol."""
    # Protocol: arg.__cuda_stream__() -> tuple[str, int]
    # Returns (type_str, stream_ptr_as_int).  Only [1] (the int) is used.
    # out.type_index = kTVMFFIOpaquePtr (4)
    # out.v_ptr      = <void*>cu_stream_tuple[1]
    # Invariant: arg must have __cuda_stream__ callable, returning a 2-tuple
    # Interacts with: TVMFFIPyArgSetterFactory_ (dispatch ordering), kTVMFFIOpaquePtr

# Dispatch ordering change in TVMFFIPyArgSetterFactory_ (after __c_dlpack_exchange_api__ check):
#   1. hasattr(arg_class, "__cuda_stream__")  → TVMFFIPyArgSetterCUDAStream_  (NEW)
#   2. isinstance(arg, torch.Tensor)          → TVMFFIPyArgSetterTorchFallback_
#   3. hasattr(arg_class, "__dlpack__")       → TVMFFIPyArgSetterDLPack_   (was hasattr(arg, ...))
# Invariant: __cuda_stream__ checked before torch.Tensor because cuda stream objects
#            may be subclasses of str, which is matched later in the chain.

# kTVMFFIOpaquePtr = 4 (include/tvm/ffi/c_api.h TypeIndex enum)
# Stream handle is passed as an opaque void* numeric value.
# The FFI does NOT take ownership; caller must keep the stream alive.
# Interacts with: TypeTraits<void*> (type_traits.h), AnyView::as<void*>() on the C++ side
```

## Impact

- API: New Python protocol — any object with `__cuda_stream__() -> tuple[str, int]` is now passable as an FFI argument. Returned to Python as `ctypes.c_void_p`.
- Behavioral: `hasattr(arg, "__dlpack__")` → `hasattr(arg_class, "__dlpack__")` in factory; for instances where `__dlpack__` is set on the instance (not the class) this is a behavioral change — those instances will no longer match the DLPack setter. This is a fix: class-level attribute lookup is consistent with all other checks in the factory.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `TVMFFIPyArgSetterFactory_` dispatch cache — `0016-py-ffi-call-dispatch.md`, the per-type factory function. The new setter is inserted at a specific position in the factory's ordering logic.
- `kTVMFFIOpaquePtr` (type index 4) — `0001-c-abi.md`. Streams are represented as opaque void pointers in `TVMFFIAny`.
- `TVMFFIPyCallManager` TLS dispatch map — `0016-py-ffi-call-dispatch.md`. The new setter is cached per-type like all other setters.
- `_DISPATCH_TYPE_KEEP_ALIVE` / `_DISPATCH_TYPE_KEEP_ALIVE_LOCK` — `0016-py-ffi-call-dispatch.md`. The cuda stream type is kept alive like any other dispatched type.

Design elements this commit produces:
- **`__cuda_stream__` dispatch protocol** — new Python FFI protocol alongside existing `__dlpack__`, `__tvm_ffi_tensor__`, `__c_dlpack_exchange_api__`. Objects implementing `__cuda_stream__() -> tuple[str, int]` pass their stream handle as `kTVMFFIOpaquePtr` through the packed call. No design record yet.

## Usage Examples

End-to-end: Python protocol definition → FFI call → opaque pointer result.

```python
import ctypes
import tvm_ffi

class MyDummyStream:
    def __init__(self, stream: int) -> None:
        self.stream = stream

    def __cuda_stream__(self) -> tuple[str, int]:
        return ("cuda", self.stream)

stream = MyDummyStream(1)
echo = tvm_ffi.get_global_func("testing.echo")
y = echo(stream)
# TVMFFIPyArgSetterFactory_ detects hasattr(MyDummyStream, "__cuda_stream__")
# → TVMFFIPyArgSetterCUDAStream_ is cached for MyDummyStream
# → out.type_index = kTVMFFIOpaquePtr, out.v_ptr = (void*)1
# FFI returns the opaque pointer back to Python as ctypes.c_void_p
assert isinstance(y, ctypes.c_void_p)
assert y.value == 1
```
