# Initial docs scaffolding with Sphinx site, concept/guide pages, testing examples, and packaging rename

## TL;DR
- Creates the entire `docs/` directory with a Sphinx-based documentation site: `conf.py`, `Makefile`, `requirements.txt`, `index.rst`, and content pages covering ABI overview, installation, quick start, C++ guide, Python guide, and packaging guide.
- Adds `tests/cpp/test_example.cc` (289 lines) with GoogleTest cases that serve as runnable code for the documentation examples (Any, Function, Object, NDArray, String, Array, Tuple, Map, Optional, Variant).
- Adds `src/ffi/extra/testing.cc` additions: a `TestIntPairObj`/`TestIntPair` object with reflection registration (`testing.TestIntPair`), used by the Python guide's "Register Your Own Object" section.
- Renames the `examples/packaging/` project from `tvm_ffi_extension` to `my_ffi_extension` (CMakeLists.txt, pyproject.toml, Python package directory, C++ namespace, global function prefix, README).
- Flattens the `examples/quick_start/get_started/` subdirectory up one level to `examples/quick_start/` (file renames only, no content changes).

## Design Elements

Design elements this commit **consumes**:

- **TVMFFIAny storage format** (`c_api.h`): The ABI overview doc explains the 16-byte tagged union, zero-padding invariant, POD vs object storage. References `kTVMFFIRawStr`, `kTVMFFISmallStr`, `kTVMFFIStr`, `kTVMFFIInt`, `kTVMFFINone`, `kTVMFFIDLTensorPtr`, `kTVMFFINDArray`.
- **TVMFFIObject intrusive header** (`c_api.h`): The ABI overview doc explains the 24-byte header layout (type_index, weak_ref_count, strong_ref_count, deleter), reference counting semantics, and deleter flags.
- **Function packed calling convention** (`function.h`): The ABI overview and C++ guide document `TVMFFISafeCallType`, handle-based closures, result initialization requirement (`kTVMFFINone`).
- **Object system** (`object.h`, `memory.h`): The C++ guide documents `Object`, `ObjectPtr`, `ObjectRef`, `make_object`, `TVM_FFI_DECLARE_FINAL_OBJECT_INFO`, `TVM_FFI_DEFINE_OBJECT_REF_METHODS`.
- **Container system** (`array.h`, `map.h`, `tuple.h`, `optional.h`, `variant.h`): The C++ guide documents all container types with usage examples and performance notes.
- **Reflection system** (`registry.h`): The C++ guide documents `reflection::GlobalDef().def()` for global function registration; the Python guide documents `@register_object` with `__init_handle_by_constructor__` backed by reflection `__create__`.
- **Error system** (`error.h`): The C++ guide documents `TVM_FFI_THROW`, `ffi::Error` kind/message/traceback; the ABI overview documents `TVMFFIErrorSetRaisedFromCStr`, `TVMFFIErrorCell`, Python-style traceback format.
- **Module system** (`module.h`): The quick start and guides document `Module::LoadFromFile`, `GetFunction`, `tvm_ffi.load_module`.
- **DLPack NDArray** (`ndarray.h`): The C++ guide documents `NDArray::FromNDAlloc`, custom allocator pattern, `ToDLPackVersioned`/`FromDLPackVersioned`.
- **Python binding layer** (`tvm_ffi` package from commit 2d41a51): The Python guide documents `load_module`, `get_global_func`, `register_func`, `convert`, `Array`, `Map`, `from_dlpack`, `register_object`, `register_error`.

Design elements this commit **produces**:

- **Sphinx documentation site architecture**: The `docs/` directory establishes the documentation structure with three content sections (Get Started, Guides, Concepts) using MyST-flavored Markdown and RST index. The `conf.py` configures `sphinx_book_theme` with ASF footer, intersphinx mappings to Python/NumPy/PyTorch/Pillow, and support for code tabs, mermaid diagrams, and notebook embedding. This is the authoritative pattern for adding new documentation pages.

- **Test-as-documentation pattern**: `tests/cpp/test_example.cc` establishes the pattern where documentation code examples are maintained as actual GoogleTest test cases. Each documentation code block corresponds to a named function in the test file (e.g., `ExampleAny()` in the test maps to the "Any and AnyView" section in the C++ guide). This ensures documentation examples remain compilable and correct as the API evolves.

- **`testing.TestIntPair` reflection example object**: A minimal Object/ObjectRef pair registered with reflection (`def_ro` fields, `def_static("__create__")`) that serves as the canonical example for the "Register Your Own Object" documentation section. This provides a stable cross-language test fixture for demonstrating Python `@register_object` with `__init_handle_by_constructor__`.

- **Packaging example naming convention**: The rename from `tvm_ffi_extension` to `my_ffi_extension` establishes `my_ffi_extension` as the canonical name used in documentation for the packaging example. All documentation references (packaging guide, README) use this name consistently.

## Usage Examples

### Building the documentation locally
```bash
cd docs
pip install -r requirements.txt
make livehtml
```

### Running the C++ example tests
```bash
cmake . -B build_test -DTVM_FFI_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Debug
cmake --build build_test --config Debug --target tvm_ffi_tests
ctest -V -C Debug --test-dir build_test --output-on-failure
```

### Using the TestIntPair from Python
```python
import tvm_ffi

@tvm_ffi.register_object("testing.TestIntPair")
class TestIntPair(tvm_ffi.Object):
    def __init__(self, a, b):
        self.__init_handle_by_constructor__(TestIntPair.__create__, a, b)

pair = TestIntPair(1, 2)
assert pair.a == 1
assert pair.b == 2
```
