# Add string-based JSON graph serialization wrappers and register via GlobalDef
## TL;DR
- Adds two convenience functions `FromJSONGraphString(String) -> Any` and `ToJSONGraphString(Any, Any) -> String` that compose `json::Parse`/`json::Stringify` with the existing `FromJSONGraph`/`ToJSONGraph`, providing a direct string-in/string-out API for JSON graph serialization.
- Registers all four serialization functions (`ffi.ToJSONGraph`, `ffi.ToJSONGraphString`, `ffi.FromJSONGraph`, `ffi.FromJSONGraphString`) via `GlobalDef` in the `TVM_FFI_STATIC_INIT_BLOCK`, making the string variants accessible cross-language through the global function registry.
- The commit message references phasing out `getattr`-based attribute handling (PR #18189), but the effective diff against the first parent is limited to these serialization additions -- the broader refactor was merged through the second parent (PR #18188).

## Impact
- API: Two new globally registered functions (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`) are added. No existing functions are removed or changed. Callers that previously used `ffi.ToJSONGraph`/`ffi.FromJSONGraph` continue to work unchanged.
- Flags/config: none
- Data formats/schemas: none -- the underlying JSON graph format is unchanged; the new functions are pure wrappers that parse/stringify the same JSON structure.

Design elements this commit **produces**:

- **String-based serialization API**: A new convenience layer for JSON graph serialization that accepts/returns `String` instead of `json::Value`. This eliminates the need for callers (especially from Python or other language bindings) to interact with the internal `json::Value` type, which may not be directly accessible cross-language. The two new functions are thin wrappers: `FromJSONGraphString(s) = FromJSONGraph(json::Parse(s))` and `ToJSONGraphString(v, m) = json::Stringify(ToJSONGraph(v, m))`.

## Key Implementations

### New wrapper functions (`src/ffi/extra/serialization.cc`, lines 411-415)

```cpp
Any FromJSONGraphString(const String& value) { return FromJSONGraph(json::Parse(value)); }

String ToJSONGraphString(const Any& value, const Any& metadata) {
  return json::Stringify(ToJSONGraph(value, metadata));
}
```

These are simple composition functions. The key design choice is to accept `String` (the FFI's own string type, supporting SSO) rather than `std::string`, ensuring the functions are compatible with the packed calling convention and cross-language usage via the global function registry.

### GlobalDef registration reformatting

The `GlobalDef` registration is reformatted from a single-line chained call to a multi-line format and extended with the two new entries. The `TVM_FFI_STATIC_INIT_BLOCK` invocation style also changes from `TVM_FFI_STATIC_INIT_BLOCK({...})` (brace-initialized) to `TVM_FFI_STATIC_INIT_BLOCK() {...}` (function-call style), though both are equivalent.

### Invariants

- The new functions maintain the existing contract that `ToJSONGraph`/`FromJSONGraph` are the canonical serialization/deserialization entry points. The string variants are pure wrappers with no additional logic.
- The `__data_to_json__` and `__data_from_json__` TypeAttrColumn columns are still pre-created via `EnsureTypeAttrColumn`, ensuring custom per-type serializers are available before any type registers them.

### Extension points

- Additional serialization formats (e.g., binary, MessagePack) could follow the same pattern: implement a core function operating on the format-specific value type, then provide a string wrapper and register both via `GlobalDef`.
