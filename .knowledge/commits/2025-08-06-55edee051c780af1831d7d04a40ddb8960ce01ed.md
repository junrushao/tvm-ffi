# Add string-based JSON serialization convenience functions
## TL;DR
- Adds `FromJSONGraphString(String) -> Any` and `ToJSONGraphString(Any, Any) -> String` as convenience wrappers around the existing `json::Value`-based serialization API.
- Registers both as global functions `ffi.FromJSONGraphString` and `ffi.ToJSONGraphString` via `GlobalDef`, enabling direct string-in/string-out serialization from Python and other FFI languages.
- **Diff-message discrepancy**: The commit message describes "phasing out getattr-based attribute handling" but the actual diff only adds these two string convenience functions. The broader getattr removal is likely in other commits of the same PR (#18189) or a future change.

## Key Exports

**Functions** (new):
```cpp
// String-based convenience wrappers for JSON object-graph serialization.
Any FromJSONGraphString(const String& value);
// Parses a JSON string and deserializes the object graph.

String ToJSONGraphString(const Any& value, const Any& metadata);
// Serializes an object graph to a JSON string.
```

**Global function registrations** (new):
- `"ffi.FromJSONGraphString"` -> `FromJSONGraphString`
- `"ffi.ToJSONGraphString"` -> `ToJSONGraphString`

**Global function registrations** (reformatted, existing):
- `"ffi.ToJSONGraph"` -> `ToJSONGraph` (unchanged)
- `"ffi.FromJSONGraph"` -> `FromJSONGraph` (unchanged)

## Impact
- API: Adds two new global functions (`ffi.FromJSONGraphString`, `ffi.ToJSONGraphString`). No existing API changed. Cross-language callers (Python, Rust) can now serialize/deserialize directly with strings instead of needing to parse/stringify JSON themselves.
- Behavioral: None -- the string variants are thin wrappers composing `json::Parse`/`json::Stringify` with the existing `FromJSONGraph`/`ToJSONGraph`.
- Flags/config: None.
- Data formats/schemas: None -- same JSON object-graph format, just string transport.

## Design Elements
Design elements this commit consumes:
- **Global function registration via `GlobalDef`** ([0009-reflection.md](../designs/0009-reflection.md), [ADR 0008](../ADRs/0008-globaldef-over-register-global.md)): Uses `refl::GlobalDef().def(...)` to register both new and existing serialization functions.
- **`json::Parse` / `json::Stringify`**: Internal JSON utilities (introduced in parent commit `de541e3`) for string-to-value and value-to-string conversion.
- **`ToJSONGraph` / `FromJSONGraph`**: The existing `json::Value`-based serialization functions in the same file.
- **`EnsureTypeAttrColumn`** ([0009-reflection.md](../designs/0009-reflection.md)): Pre-creates `__data_to_json__` and `__data_from_json__` TypeAttr columns for custom per-type serialization hooks.

Design elements this commit produces:
- **String-based serialization API surface**: Two new global functions providing a simpler cross-language interface to the JSON object-graph serializer. These are the primary entry points for languages that work with strings natively (Python, Rust).

## Usage Examples
**Context**: Calling the new string-based serialization from Python (via global function lookup).
```python
# Python side
from_json = tvm_ffi.get_global_func("ffi.FromJSONGraphString")
to_json = tvm_ffi.get_global_func("ffi.ToJSONGraphString")

# Serialize an object to a JSON string
json_str = to_json(my_object, None)

# Deserialize back
restored = from_json(json_str)
```

**Context**: C++ usage.
```cpp
// Serialize to string
String json_str = ToJSONGraphString(value, None);
// Deserialize from string
Any restored = FromJSONGraphString(json_str);
```
