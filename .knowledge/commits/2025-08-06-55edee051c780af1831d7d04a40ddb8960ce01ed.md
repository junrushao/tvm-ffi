# Add string-based JSON graph serialization wrappers to phase out getattr attribute handling
## TL;DR
- Adds two new global FFI functions `ffi.ToJSONGraphString` and `ffi.FromJSONGraphString` that accept/return `String` instead of `json::Value`, enabling direct cross-language serialization without `getattr`-based field access.
- Part of a broader refactor to phase out `getattr`-based attribute handling in favor of explicitly registered Python-side objects, improving performance and reducing code paths.

## Impact
- API: Two new global FFI functions added (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`). No existing APIs changed.
- Behavioral: The commit message describes phasing out `getattr`-based attribute handling, meaning unregistered Python objects can no longer access fields by name. The diff itself is purely additive.
- Flags/config: none
- Data formats/schemas: none -- the string wrappers produce the same JSON format as the existing `json::Value`-based functions.

## Design Elements
Design elements this commit consumes:
- **Global function registration** (`reflection::GlobalDef`) from [0008-reflection](../design-records/0008-reflection.md) -- registers the two new functions in the global FFI registry.
- **JSON graph serialization** (`ToJSONGraph`, `FromJSONGraph`) -- existing internal functions in `src/ffi/extra/serialization.cc` that handle object-graph-aware serialization with `__data_to_json__`/`__data_from_json__` type attribute hooks.
- **Type attribute columns** (`EnsureTypeAttrColumn`) from [0008-reflection](../design-records/0008-reflection.md) -- `__data_to_json__` and `__data_from_json__` per-type attributes used by the serializer.

Design elements this commit produces:
- **`ffi.ToJSONGraphString`** -- new global FFI function; a string-returning convenience wrapper around `ToJSONGraph` + `json::Stringify`. Enables Python-side serialization without parsing `json::Value` across the FFI boundary.
- **`ffi.FromJSONGraphString`** -- new global FFI function; a string-accepting convenience wrapper around `json::Parse` + `FromJSONGraph`. Enables Python-side deserialization from a plain string.

## Usage Examples

```python
# Python-side usage (once wrappers are registered):
from tvm_ffi import get_global_func

to_json = get_global_func("ffi.ToJSONGraphString")
from_json = get_global_func("ffi.FromJSONGraphString")

# Serialize an object graph to a JSON string
json_str = to_json(my_object, metadata)

# Deserialize back from JSON string
restored = from_json(json_str)
```
