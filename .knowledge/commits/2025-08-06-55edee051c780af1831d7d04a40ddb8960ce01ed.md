# Add string-based JSON serialization wrappers to support getattr phase-out

## TL;DR
- Adds two new global functions `ffi.ToJSONGraphString` and `ffi.FromJSONGraphString` that wrap the existing `ToJSONGraph`/`FromJSONGraph` serialization API with a `String`-based interface, bypassing the need for `json::Value` interop from foreign languages.
- `FromJSONGraphString(const String& value)` parses a JSON string and deserializes it into an `Any` value. `ToJSONGraphString(const Any& value, const Any& metadata)` serializes an `Any` value to a JSON string.
- These wrappers enable Python (and other FFI callers) to use the JSON graph serialization without needing to construct or consume `json::Value` objects, which is part of phasing out the slower `getattr`-based attribute handling path. With these functions registered globally, foreign language bindings can invoke serialization directly with string arguments.
- The existing `ffi.ToJSONGraph` and `ffi.FromJSONGraph` registrations are preserved alongside the new string variants.

## Key Exports

### New Global Functions (registered via `reflection::GlobalDef`)

**`ffi.FromJSONGraphString`:**
- Signature: `(const String& value) -> Any`
- Parses `value` as JSON via `json::Parse`, then delegates to `FromJSONGraph` to deserialize the object graph.

**`ffi.ToJSONGraphString`:**
- Signature: `(const Any& value, const Any& metadata) -> String`
- Delegates to `ToJSONGraph` to produce a `json::Value`, then stringifies it via `json::Stringify`.

### Changed Global Function Registration

The `TVM_FFI_STATIC_INIT_BLOCK` in `src/ffi/extra/serialization.cc` now registers four functions instead of two:
- `ffi.ToJSONGraph` (unchanged)
- `ffi.ToJSONGraphString` (new)
- `ffi.FromJSONGraph` (unchanged)
- `ffi.FromJSONGraphString` (new)

### New C++ Free Functions (internal, not in header)

- `FromJSONGraphString(const String& value) -> Any` -- Defined in `src/ffi/extra/serialization.cc`. Not declared in the public header `serialization.h`; accessible only through the global function registry.
- `ToJSONGraphString(const Any& value, const Any& metadata) -> String` -- Defined in `src/ffi/extra/serialization.cc`. Not declared in the public header `serialization.h`; accessible only through the global function registry.

## Impact
- **API**: Two new globally registered functions (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`) are available from all FFI languages. No C++ header API changes.
- **ABI**: No change. No C ABI symbols are added or modified. The new functions are registered at static initialization time via the existing global function registry mechanism.
- **Behavioral**: Foreign language callers (Python, Rust) can now serialize/deserialize object graphs using plain strings without interacting with `json::Value`. This is a convenience layer; the underlying serialization logic is unchanged.
- **Flags/config**: None.
- **Data formats/schemas**: None. The JSON format produced/consumed is identical to `ToJSONGraph`/`FromJSONGraph`.

## Design Elements

Design elements this commit consumes:
- **`ToJSONGraph` / `FromJSONGraph`** (`src/ffi/extra/serialization.cc`): The reflection-based JSON object graph serialization/deserialization introduced in commit 8eaefe0. These functions operate on `json::Value` objects.
- **`json::Parse` / `json::Stringify`** (`include/tvm/ffi/extra/json.h`): JSON parsing and stringification utilities that convert between `String` and `json::Value`.
- **`reflection::GlobalDef`** (`include/tvm/ffi/reflection/registry.h`): The builder for registering global functions in the FFI function registry, accessible cross-language via `get_global_func`.

Design elements this commit produces:
- **String-based serialization entry points** -- `ffi.ToJSONGraphString` and `ffi.FromJSONGraphString` provide a pure-string interface to JSON object graph serialization. This enables FFI callers that cannot easily construct `json::Value` objects to use the serialization system directly. These are the primary entry points for cross-language serialization, since `json::Value` is a C++-only type not easily passed across the FFI boundary.

## Usage Examples

### From Python (via global function registry)
```python
import tvm_ffi

to_json = tvm_ffi.get_global_func("ffi.ToJSONGraphString")
from_json = tvm_ffi.get_global_func("ffi.FromJSONGraphString")

# Serialize an object to a JSON string
json_str = to_json(my_object, None)

# Deserialize back from JSON string
restored = from_json(json_str)
```

### From C++ (direct call)
```cpp
// These are internal functions, but can also be called via the registry:
Function to_json = Function::GetGlobalFunc("ffi.ToJSONGraphString").value();
Function from_json = Function::GetGlobalFunc("ffi.FromJSONGraphString").value();

String json_str = to_json(my_value, nullptr).cast<String>();
Any restored = from_json(json_str);
```
