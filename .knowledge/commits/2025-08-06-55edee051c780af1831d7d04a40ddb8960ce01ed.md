# Add string-based JSON graph serialization wrappers to phase out getattr-based field access
## TL;DR
- Adds `ffi.ToJSONGraphString` and `ffi.FromJSONGraphString` global functions — thin convenience wrappers that accept/return `String` instead of `json::Value`.
- Registers them alongside existing `ffi.ToJSONGraph` / `ffi.FromJSONGraph` via `refl::GlobalDef`.
- Part of a broader effort to phase out `getattr`-based attribute handling in Python; these string APIs let callers bypass `json::Value` intermediate objects entirely.

## Key Exports

```python
def ffi_FromJSONGraphString(value: String) -> Any: ...
    # Interacts with: json::Parse, FromJSONGraph (ObjectGraphDeserializer)
    # Invariant: value must be valid JSON string

def ffi_ToJSONGraphString(value: Any, metadata: Any) -> String: ...
    # Interacts with: ToJSONGraph (ObjectGraphSerializer), json::Stringify
    # Invariant: value must be serializable (all objects must have __data_to_json__ attr or reflection-registered fields)

# Registration (pseudocode for TVM_FFI_STATIC_INIT_BLOCK expansion):
# registry["ffi.ToJSONGraph"] = PackedFunc(ToJSONGraph)
# registry["ffi.ToJSONGraphString"] = PackedFunc(ToJSONGraphString)   # NEW
# registry["ffi.FromJSONGraph"] = PackedFunc(FromJSONGraph)
# registry["ffi.FromJSONGraphString"] = PackedFunc(FromJSONGraphString) # NEW
```

## Impact
- API: Two new global functions (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`) added. No existing APIs changed.
- Behavioral: Enables Python-side serialization to use `String` directly instead of routing through `json::Value` objects (which would require getattr-based field traversal). This is a prerequisite for removing the getattr fallback code path.
- Flags/config: none
- Data formats/schemas: none — same JSON format, just a different entry point (String vs json::Value)

## Design Elements
Design elements this commit consumes:
- Global function registration via `refl::GlobalDef` inside `TVM_FFI_STATIC_INIT_BLOCK` (0004-ffi-function-system)
- `Any` type-erased value container (0002-ffi-any-value-system)
- `String` container type (0006-ffi-containers)
- `json::Parse` / `json::Stringify` (lightweight JSON parser, introduced in prior commit)
- `ToJSONGraph` / `FromJSONGraph` existing serialization functions
- `TypeAttrColumn` for `__data_to_json__` and `__data_from_json__` (0007-ffi-reflection)

Design elements this commit produces:
- None — the new functions are thin composition wrappers, not new design elements.

## Usage Examples

```cpp
// C++ — serialize an object to a JSON string directly
String json_str = ToJSONGraphString(my_object, NullOpt);

// C++ — deserialize from a JSON string
Any restored = FromJSONGraphString(json_str);

// Python (via FFI) — the motivation for these wrappers:
// Previously: json_val = get_global_func("ffi.ToJSONGraph")(obj, None)
//             # then traverse json_val fields via getattr (slow, extra code path)
// Now:        json_str = get_global_func("ffi.ToJSONGraphString")(obj, None)
//             # json_str is a plain String, no field traversal needed
```
