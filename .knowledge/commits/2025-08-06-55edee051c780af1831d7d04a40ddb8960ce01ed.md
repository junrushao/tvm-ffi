# Add string-based JSON serialization convenience wrappers for FFI
## TL;DR
- Adds `FromJSONGraphString` and `ToJSONGraphString` convenience functions that accept/return `String` instead of `json::Value`, enabling direct string-based serialization from FFI callers.
- Registers these as global functions `ffi.FromJSONGraphString` and `ffi.ToJSONGraphString` via `GlobalDef`.
- Diff-message discrepancy: commit message describes "phasing out getattr-based attribute handling" but the diff in this repo only adds the string wrapper functions. The getattr removal likely occurred in files outside this repo's extraction boundary.

## Impact
- API: Additive -- two new global functions (`ffi.ToJSONGraphString`, `ffi.FromJSONGraphString`) for cross-language callers that need string-based serialization without constructing `json::Value` objects.
- Behavioral: none -- existing `ffi.ToJSONGraph` and `ffi.FromJSONGraph` are unchanged.
- Flags/config: none
- Data formats/schemas: none -- the JSON format is identical; these wrappers only change the transport type (String vs json::Value).

Design elements this commit produces:
- **String-based serialization FFI functions** -- `ffi.ToJSONGraphString` and `ffi.FromJSONGraphString` as a convenience layer over the json::Value-based API. These enable cross-language callers (Python, Rust) to serialize/deserialize without needing json::Value interop.

## Usage Examples

```cpp
// C++ usage: serialize an object to a JSON string
Any obj = make_object<SomeObj>(...);
String json_str = ToJSONGraphString(obj, Any(nullptr));

// C++ usage: deserialize from a JSON string
Any restored = FromJSONGraphString(json_str);

// Cross-language via FFI (Python pseudocode):
to_json = get_global_func("ffi.ToJSONGraphString")
from_json = get_global_func("ffi.FromJSONGraphString")
json_str = to_json(obj, None)    # returns String
restored = from_json(json_str)   # returns Any
```
