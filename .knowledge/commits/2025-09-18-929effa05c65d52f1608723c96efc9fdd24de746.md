# Update DLPack conversion to enable Float4 (f4) and migrate python header install
## TL;DR
- Adds a full `toScalarTypeForDLPackv1` function to `_optional_torch_c_dlpack.py` that maps DLPack dtype codes (including `kDLFloat4_e2m1fn`) back to PyTorch `ScalarType`, enabling round-trip DLPack conversion for all dtype codes including FP4.
- Fixes `getDLDataTypeForDLPackv1` for `Float4_e2m1fn_x2` to correctly set `dtype.lanes = 2` and `dtype.bits = 4` (previously only `dtype.code` was set).
- Moves the `tvm_ffi_python_helpers.h` install from the always-installed section to the `TVM_FFI_BUILD_PYTHON_MODULE` conditional block in CMakeLists.txt.
- Bumps package version from `0.1.0b3` to `0.1.0b4`.

## Impact
- API: The `fromDLPackImpl` template now calls `toScalarTypeForDLPackv1` instead of `toScalarType`, enabling correct import of DLPack tensors with all modern dtype codes (Float8 variants, Float4_e2m1fn_x2, BFloat16, Complex) back into PyTorch tensors. This completes the C-level DLPack round-trip for new dtypes.
- Flags/config: none
- Data formats/schemas: The DLPack dtype mapping now covers all `DLDataTypeCode` values up to `kDLFloat4_e2m1fn`, including correct handling of the `lanes=2` multi-lane encoding for FP4.

## Design Elements
Design elements this commit consumes:
- **DLPack Exchange Acceleration** (`.knowledge/designs/0020-dlpack-exchange-acceleration.md`): The `_optional_torch_c_dlpack.py` JIT-compiled C++ extension is extended with a new `toScalarTypeForDLPackv1` function that mirrors the forward conversion (`getDLDataTypeForDLPackv1`) in reverse.
- **C-Level DLPack Exchange Protocol** (`.knowledge/ADRs/0034-dlpack-c-level-exchange-protocol.md`): The C-level bypass path (`fromDLPackImpl`) now uses the new V1-aware conversion function.
- **Packaging and Build** (`.knowledge/designs/0016-packaging-and-build.md`): The `tvm_ffi_python_helpers.h` header install is moved to the Python module build conditional, reflecting that it is only needed when building the Python extension.

Design elements this commit produces:
- **Complete DLPack dtype round-trip**: The `toScalarTypeForDLPackv1` function is the missing reverse leg of the DLPack dtype conversion. It handles all modern dtype codes (Float8_e5m2, Float8_e5m2fnuz, Float8_e4m3fn, Float8_e4m3fnuz, Float8_e8m0fnu, Float4_e2m1fn_x2) that the original PyTorch `toScalarType` does not support.
- **FP4 multi-lane encoding**: The `kDLFloat4_e2m1fn` type uses `lanes=2, bits=4` to represent `Float4_e2m1fn_x2`, a non-standard use of the DLPack lanes field. This encoding is now correctly set in both export and import paths.
