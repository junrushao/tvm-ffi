# Fix DLPack f4 dtype round-trip and add custom toScalarTypeForDLPackv1
## TL;DR
- Fix `getDLDataTypeForDLPackv1` to correctly set `lanes=2, bits=4` for `Float4_e2m1fn_x2`, which was previously relying on wrong defaults (`lanes=1, bits=element_size()*8`).
- Add a new `toScalarTypeForDLPackv1` function that replaces PyTorch's `toScalarType` in `fromDLPackImpl`, enabling correct round-tripping of all DLPack v1 dtype codes including sub-byte Float4 and Float8 variants.
- Move `tvm_ffi_python_helpers.h` install into the Python module CMake section; bump version to `0.1.0b4`.

## Key Exports
**Functions**:
- `ScalarType toScalarTypeForDLPackv1(const DLDataType& dtype)` -- converts a DLPack `DLDataType` to a PyTorch `ScalarType`. Handles `kDLUInt`, `kDLInt`, `kDLFloat`, `kDLBfloat`, `kDLComplex`, `kDLBool`, `kDLFloat8_e5m2`, `kDLFloat8_e5m2fnuz`, `kDLFloat8_e4m3fn`, `kDLFloat8_e4m3fnuz`, `kDLFloat8_e8m0fnu`, `kDLFloat4_e2m1fn`. For `kDLFloat4_e2m1fn`, uses `dtype.lanes == 2` to map to `Float4_e2m1fn_x2`.

**Bugfix in existing function**:
- `getDLDataTypeForDLPackv1` (Tensor -> DLDataType direction): `Float4_e2m1fn_x2` case now correctly sets `dtype.lanes = 2; dtype.bits = 4` instead of inheriting the default `lanes=1, bits=element_size()*8`.

## Impact
- API: `fromDLPackImpl` now calls `toScalarTypeForDLPackv1` instead of PyTorch's `at::toScalarType`, enabling f4 round-trip. This is internal to the JIT-compiled C++ extension; no Python API change.
- Behavioral: DLPack tensors with `kDLFloat4_e2m1fn` (4-bit, lanes=2) can now be correctly converted back to PyTorch `Float4_e2m1fn_x2` tensors. Previously, `toScalarType` would fail or produce wrong results for this type code.
- Flags/config: none
- Data formats/schemas: The DLDataType encoding for f4 uses `{code=kDLFloat4_e2m1fn, bits=4, lanes=2}`, matching the DLPack spec for sub-byte types.

## Design Elements
Design elements this commit consumes:
- **DLPack v1 data type codes** (`DLDataTypeCode` enum from `dlpack/dlpack.h`): the full set of type codes including newer Float8 and Float4 variants.
- **PyTorch JIT C++ extension mechanism** (`torch.utils.cpp_extension.load_inline`): used by `_optional_torch_c_dlpack.py` to compile and load the custom DLPack conversion routines at import time.
- **`tvm_ffi_python_helpers.h`** header: installed for Python module builds.

Design elements this commit produces:
- **`toScalarTypeForDLPackv1`**: A standalone DLDataType-to-ScalarType converter that supersedes PyTorch's `at::toScalarType` for DLPack v1 usage, with explicit sub-byte type support (Float4, Float8 variants).

## Usage Examples
Before (broken round-trip for f4):
```cpp
// getDLDataTypeForDLPackv1 set dtype.code = kDLFloat4_e2m1fn but
// left dtype.lanes = 1 (default) and dtype.bits = element_size()*8 (wrong for sub-byte)
// Then fromDLPackImpl called at::toScalarType which didn't know about kDLFloat4_e2m1fn
```

After (correct round-trip):
```cpp
// getDLDataTypeForDLPackv1 now sets: code=kDLFloat4_e2m1fn, lanes=2, bits=4
// fromDLPackImpl calls toScalarTypeForDLPackv1 which dispatches:
//   kDLFloat4_e2m1fn + bits=4 + lanes=2 -> ScalarType::Float4_e2m1fn_x2
```
