# Add toScalarTypeForDLPackv1 for round-trip DLPack f4 dtype conversion, fix f4_e2m1fn encoding, bump version to 0.1.0b4

## TL;DR
- Adds `toScalarTypeForDLPackv1`, a new DLDataType-to-ScalarType conversion function that replaces PyTorch's `toScalarType` in `fromDLPackImpl`, enabling correct round-trip DLPack import for all supported dtypes including `Float4_e2m1fn_x2` (which requires `lanes=2`).
- Fixes `getDLDataTypeForDLPackv1` to set `dtype.lanes=2` and `dtype.bits=4` for `Float4_e2m1fn_x2` (previously only set `dtype.code`; bits/lanes were wrong from the default `lanes=1, bits=element_size()*8`).
- Moves the `tvm_ffi_python_helpers.h` install from the general CMake install block into the Python module install block, and bumps version `0.1.0b3` to `0.1.0b4`.

## Impact
- API: None — no public Python API changes; `toScalarTypeForDLPackv1` is internal to the JIT-compiled C++ extension string.
- Behavioral: DLPack import (`fromDLPackImpl`) now uses the custom `toScalarTypeForDLPackv1` instead of PyTorch's `at::toScalarType`, enabling correct handling of `Float4_e2m1fn_x2` and all float8 types in the DLPack-to-Torch direction. DLPack export for `Float4_e2m1fn_x2` now produces correct `bits=4, lanes=2` encoding.
- Flags/config: None.
- Data formats/schemas: `DLDataType` encoding for `Float4_e2m1fn_x2` corrected: `{code=kDLFloat4_e2m1fn, bits=4, lanes=2}` (was `{code=kDLFloat4_e2m1fn, bits=<element_size*8>, lanes=1}`). Version bumped from `0.1.0b3` to `0.1.0b4`.

## Design Elements

Design elements this commit consumes:
- Torch C DLPack extension pattern (`_optional_torch_c_dlpack.py`) — the JIT-compiled C++ bridge described in [0013-load-inline](../design-records/0013-load-inline.md) and [0012-python-bindings](../design-records/0012-python-bindings.md).
- DLPack dtype encoding protocol (DLDataTypeCode, bits, lanes) — part of the DLPack spec consumed by [0006-containers](../design-records/0006-containers.md) and [0007-c-abi](../design-records/0007-c-abi.md).
- `fromDLPackImpl` / `toDLPackImpl` templates — the DLPack import/export path in the Torch C DLPack extension.

Design elements this commit produces:
- `toScalarTypeForDLPackv1` — a new function that replaces PyTorch's `at::toScalarType` for the DLPack import path, adding support for all float8 types and the multi-lane `Float4_e2m1fn_x2` type. This is internal to the inline C++ extension and not exported as a standalone API.

## Usage Examples

Round-trip DLPack conversion of a float4 tensor (requires PyTorch >= 2.8):

```python
import torch
import tvm_ffi

# Create a float4_e2m1fn_x2 tensor (PyTorch 2.8+)
t = torch.zeros(4, dtype=torch.float4_e2m1fn_x2, device="cpu")

# Export via toDLPackImpl -> getDLDataTypeForDLPackv1 produces {code=kDLFloat4_e2m1fn, bits=4, lanes=2}
# Import via fromDLPackImpl -> toScalarTypeForDLPackv1 maps back to Float4_e2m1fn_x2
# Round-trip now works correctly through the TVM FFI DLPack bridge
arr = tvm_ffi.from_dlpack(t)  # uses the corrected DLPack path
```
