# Add Float4_e2m1fn (f4) DLPack round-trip support and fix getDLDataType metadata for sub-byte types
## TL;DR
- Add `toScalarTypeForDLPackv1()` function to the JIT-compiled torch DLPack extension, replacing upstream `toScalarType()` with full DLPack v1 dtype coverage including Float4_e2m1fn_x2 (4-bit, 2-lane sub-byte type).
- Fix `getDLDataTypeForDLPackv1()` to correctly set `dtype.lanes = 2` and `dtype.bits = 4` for `Float4_e2m1fn_x2` (previously missing, causing corrupted DLPack metadata on Torch-to-DLPack export).
- Bump package version from `0.1.0b3` to `0.1.0b4`; move Python helper header install into the Python build section of CMakeLists.txt.

## Key Exports

```python
# C++ function (JIT-compiled inside _optional_torch_c_dlpack.py)
def toScalarTypeForDLPackv1(dtype: DLDataType) -> ScalarType: ...
    # Interacts with: fromDLPackImpl (sole caller), DLDataTypeCode enum, PyTorch ScalarType enum
    # Invariant: For kDLFloat4_e2m1fn, dtype.lanes must be 2 and dtype.bits must be 4.
    #            For all other codes, dtype.lanes must be 1.
    # Extension: Add new case branches for future DLPack dtype codes.
    # Replaces: at::toScalarType() -- upstream PyTorch version lacks Float4_e2m1fn support

# Bugfix in existing function:
# getDLDataTypeForDLPackv1(tensor) -> DLDataType
#   OLD: Float4_e2m1fn_x2 case only set dtype.code (lanes/bits uninitialized)
#   NEW: Float4_e2m1fn_x2 case sets dtype.code, dtype.lanes=2, dtype.bits=4
```

## Impact
- API: none -- `toScalarTypeForDLPackv1` is internal to the JIT extension; external API surface (`TorchDLPackFromPyObject`, `TorchDLPackToPyObject`) unchanged.
- Behavioral: Torch tensors with `Float4_e2m1fn_x2` dtype now round-trip correctly through DLPack. Previously, export produced incomplete DLDataType metadata (missing lanes/bits) and import would fail (upstream `toScalarType` did not handle `kDLFloat4_e2m1fn`).
- Flags/config: none
- Data formats/schemas: DLDataType.lanes and DLDataType.bits are now correctly populated for sub-byte Float4 types in the Torch interop path.

## Design Elements
Design elements this commit consumes:
- DLPack C fast-path protocols (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) -- see [0012-python-bindings.md](../designs/0012-python-bindings.md)
- DLPack v1 data type codes (`DLDataTypeCode` enum from `3rdparty/dlpack/include/dlpack.h`)
- Python packaging / CMake install rules -- see [0013-packaging.md](../designs/0013-packaging.md)

Design elements this commit produces:
- `toScalarTypeForDLPackv1`: custom DLDataType-to-ScalarType converter replacing upstream PyTorch `toScalarType`, with explicit sub-byte type handling (Float4_e2m1fn_x2 via lanes=2 dispatch).

## Usage Examples

Round-trip usage is implicit through the existing JIT extension entry points:

```python
# After this commit, Float4_e2m1fn_x2 tensors round-trip correctly:
import torch
# Torch -> DLPack (uses getDLDataTypeForDLPackv1, now sets lanes=2, bits=4)
t = torch.zeros(4, dtype=torch.float4_e2m1fn_x2)  # requires torch >= 2.8
# DLPack -> Torch (uses toScalarTypeForDLPackv1, handles kDLFloat4_e2m1fn)
# The conversion happens automatically through __c_dlpack_from_pyobject__
# and __c_dlpack_to_pyobject__ function pointers set on torch.Tensor.
```
