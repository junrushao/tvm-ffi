# Add Float4_e2m1fn (f4) DLPack dtype round-trip in torch C DLPack extension
## TL;DR
- Adds a custom `toScalarTypeForDLPackv1` function to the JIT-compiled torch C DLPack extension, enabling round-trip DLPack conversion for `Float4_e2m1fn_x2` (4-bit float with lanes=2) and all other DLPack dtype codes including float8 variants.
- Fixes `getDLDataTypeForDLPackv1` to correctly set `dtype.lanes = 2` and `dtype.bits = 4` for the f4 case (previously only `dtype.code` was set, leaving bits/lanes at their defaults).
- Bumps package version from `0.1.0b3` to `0.1.0b4` and moves `tvm_ffi_python_helpers.h` install into the Python build section of CMakeLists.txt.

## Impact
- API: None — no public Python API changes. The JIT-compiled C++ functions are internal to the torch DLPack extension.
- Behavioral: `fromDLPackImpl` now uses `toScalarTypeForDLPackv1` instead of ATen's `toScalarType`, enabling correct import of f4 tensors. The export path (`getDLDataTypeForDLPackv1`) now correctly populates all three DLDataType fields for f4.
- Flags/config: None
- Data formats/schemas: DLDataType for `Float4_e2m1fn_x2` now correctly uses `{code=kDLFloat4_e2m1fn, bits=4, lanes=2}` in both directions.

## Design Elements
Design elements this commit consumes:
- **DLPack dtype protocol** (`DLDataType` with code/bits/lanes fields) — from `dlpack.h` vendored in `3rdparty/dlpack/` (see design record `0006-ffi-containers`).
- **`__c_dlpack_from_pyobject__` / `__c_dlpack_to_pyobject__` protocols** — the JIT extension registers function pointers on `torch.Tensor` for zero-overhead C-level DLPack exchange (see design record `0012-ffi-python-package`).
- **`DLPackTensorAllocator` protocol** — `TorchDLPackTensorAllocator` still uses ATen's built-in `toScalarType` (not updated to the new function), so allocator path does not yet support f4 round-trip.

Design elements this commit produces: None — extends coverage of existing conversion functions without adding new protocols or interfaces.

## Usage Examples
Before (broken f4 round-trip):
```python
# getDLDataTypeForDLPackv1 set code=kDLFloat4_e2m1fn but left bits/lanes wrong
# fromDLPackImpl called at::toScalarType which doesn't know kDLFloat4_e2m1fn
# Result: torch f4 tensor -> DLPack -> torch fails or produces wrong dtype
```

After (working f4 round-trip):
```python
import torch
t = torch.zeros(4, dtype=torch.float4_e2m1fn_x2)  # requires torch >= 2.8
# Export: getDLDataTypeForDLPackv1 -> {code=kDLFloat4_e2m1fn, bits=4, lanes=2}
# Import: toScalarTypeForDLPackv1 -> ScalarType::Float4_e2m1fn_x2
# Round-trip through DLPack now preserves dtype correctly
```
