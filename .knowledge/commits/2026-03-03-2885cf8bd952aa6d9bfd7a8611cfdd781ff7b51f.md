# Add CAny owned-value wrapper; TypeSchema.convert now returns CAny

## TL;DR
- New `CAny` Cython extension type (`cdef class CAny`) owns a `TVMFFIAny` value with proper ref-counting for object types.
- `TypeSchema.convert(value)` now returns `CAny` instead of a Python object, allowing downstream callers to pass the value directly to C without boxing.
- `CAny.to_py()` recovers the Python value.

## Key Exports

```python
# python/tvm_ffi/cython/object.pxi
cdef class CAny:
    """Owned TVMFFIAny value; proper ref-counted for object types."""
    cdef TVMFFIAny cdata

    def __init__(self, value=None): ...
        # Packs value via TVMFFIPyPyObjectToFFIAny + TVMFFIAnyViewToOwnedAny
    def type_index(self) -> int: ...     # TVM FFI type index
    def to_py(self) -> object: ...       # Convert back to Python
    # Interacts with: TVMFFIPyArgSetterFactory_, TVMFFIAnyViewToOwnedAny

# TypeSchema.convert now returns CAny:
# OLD: TypeSchema.convert(value) -> object
# NEW: TypeSchema.convert(value) -> CAny
# Invariant: CAny owns the value; call .to_py() to get Python object
```

## Impact
- API: **Breaking**. `TypeSchema.convert()` return type changed from `object` to `CAny`. Callers that used the result directly as a Python object must call `.to_py()`.
- Behavioral: Enables zero-copy value passing to C functions by holding a pre-marshaled `TVMFFIAny` value.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

```python
schema = TypeSchema("int")
cany = schema.convert(42)     # returns CAny
val = cany.to_py()            # recovers Python int: 42
ti = cany.type_index          # kTVMFFIInt
```
