# Reorder static type indices for C/C++ ABI complexity grouping, add ModuleObj metadata API, rename override parameter

## TL;DR
- **Enum reorder**: Static object type indices reordered to group "simple C ABI" types (Shape=69, NDArray=70) before "complex C++ ABI" types (Array=71, Map=72), preparing for ABI freeze.
- **Metadata API**: New `ModuleObj::GetFunctionMetadata(name)` virtual method and `tvm_ffi_metadata_prefix` symbol constant, enabling future retrieval of per-function metadata from dynamically loaded modules.
- **Parameter rename**: `override` renamed to `allow_override` in `TVMFFIFunctionSetGlobal` and `TVMFFIFunctionSetGlobalFromMethodInfo` C API signatures.

## Key Exports

**Enum value reassignment** (`TVMFFITypeIndex` in `c_api.h`):

| Name | Old Value | New Value |
|------|-----------|-----------|
| `kTVMFFIShape` | 71 | 69 |
| `kTVMFFINDArray` | 72 | 70 |
| `kTVMFFIArray` | 69 | 71 |
| `kTVMFFIMap` | 70 | 72 |
| `kTVMFFIModule` | 73 | 73 (unchanged) |

**New virtual method** on `ModuleObj` (`include/tvm/ffi/extra/module.h`):
```cpp
// Single-module query (virtual, overridable by subclasses)
virtual Optional<String> GetFunctionMetadata(const String& name);  // default: returns nullopt

// Import-tree query (non-virtual, walks imports)
Optional<String> GetFunctionMetadata(const String& name, bool query_imports);
```

**New registered global function**:
| Name | Signature | Description |
|------|-----------|-------------|
| `ffi.ModuleGetFunctionMetadata` | `(Module, String, bool) -> Optional<String>` | Get function metadata as JSON string, optionally querying imports |

**New symbol constant** (`tvm::ffi::symbol` namespace):
```cpp
constexpr const char* tvm_ffi_metadata_prefix = "__tvm_ffi_metadata_";
```

**Parameter rename** in C API:
- `TVMFFIFunctionSetGlobal(..., int override)` -> `TVMFFIFunctionSetGlobal(..., int allow_override)`
- `TVMFFIFunctionSetGlobalFromMethodInfo(..., int override)` -> `TVMFFIFunctionSetGlobalFromMethodInfo(..., int allow_override)`

## Impact
- API: **Breaking ABI change**. The `kTVMFFIArray`, `kTVMFFIMap`, `kTVMFFIShape`, `kTVMFFINDArray` enum values are renumbered. Any compiled code, language binding, or serialized data that hardcodes these indices must be recompiled. The Cython bindings (`base.pxi`) are updated in this commit. The parameter rename from `override` to `allow_override` is source-breaking for callers using named parameters but ABI-compatible (same type, same position).
- Behavioral: `ModuleObj` subclasses can now optionally return per-function metadata via `GetFunctionMetadata`. The default returns `nullopt`, so existing subclasses are unaffected unless they override it.
- Flags/config: `scripts/run_tests.sh` changes build type from `Release` to `RelWithDebugInfo` and adds `rm -rf build/CMakeCache.txt` for cache cleanup.
- Data formats/schemas: The metadata is returned as a JSON string (`Optional<String>`), but no schema is defined in this commit -- that is left to future work.

## Design Elements
Design elements this commit consumes:
- **Type index range partitioning** ([ADR 0004-type-index-layout.md](../../.knowledge/ADRs/0004-type-index-layout.md)): The static object range `[64, 128)` is reordered within its existing allocation. The partition boundaries are unchanged.
- **Module system** ([0013-module-system.md](../../.knowledge/designs/0013-module-system.md)): The `ModuleObj` virtual interface, import-tree walking pattern (`GetFunction` with `query_imports`), and symbol namespace conventions are all consumed and extended.
- **C ABI layer** ([0001-c-abi-layer.md](../../.knowledge/designs/0001-c-abi-layer.md)): `TVMFFIFunctionSetGlobal` and `TVMFFIFunctionSetGlobalFromMethodInfo` signatures are modified (parameter rename).

Design elements this commit produces:
- **Complexity-ordered static type indices**: A new sub-convention within the static object range: indices 64-70 are "simple" types with pure C ABI layouts (Object, String, Bytes, Error, Function, Shape, NDArray), while indices 71+ are "complex" types that may require C++ (Array, Map, Module). This grouping is marked by a comment block `// more complex objects` in the enum.
- **Module function metadata protocol**: A new virtual method `GetFunctionMetadata` on `ModuleObj` with a `tvm_ffi_metadata_prefix` symbol convention, enabling library modules to expose per-function metadata (e.g., via `__tvm_ffi_metadata_<funcname>` symbols in `.so` files).

## Usage Examples

### Querying function metadata from a module (C++)
**Context**: After this commit, module subclasses can override `GetFunctionMetadata` to return JSON metadata. The import-tree variant walks imports like `GetFunction` does.
```cpp
#include <tvm/ffi/extra/module.h>
using namespace tvm::ffi;

Module mod = Module::LoadFromFile("my_kernels.so");

// Query metadata for a specific kernel
Optional<String> meta = mod->GetFunctionMetadata("my_kernel");
if (meta.defined()) {
  // meta.value() contains JSON string with kernel metadata
  LOG(INFO) << "Metadata: " << meta.value();
}

// Query across imports
Optional<String> meta2 = mod->GetFunctionMetadata("helper_func", /*query_imports=*/true);
```

### Querying function metadata from Python
**Context**: The registered global function `ffi.ModuleGetFunctionMetadata` exposes the metadata API to Python.
```python
import tvm_ffi
get_metadata = tvm_ffi.get_global_func("ffi.ModuleGetFunctionMetadata")
mod = tvm_ffi.get_global_func("ffi.ModuleLoadFromFile")("my_kernels.so")
metadata_json = get_metadata(mod, "my_kernel", False)
```
