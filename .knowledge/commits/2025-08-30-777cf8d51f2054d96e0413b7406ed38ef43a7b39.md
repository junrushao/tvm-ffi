# Reorder static object type indices for C ABI complexity grouping and add ModuleObj::GetFunctionMetadata

## TL;DR
- Reorders static object type indices in `TVMFFITypeIndex` so "simple" C-ABI objects (Shape=69, NDArray=70) precede "complex" C++-dependent objects (Array=71, Map=72), establishing a complexity ordering within the static object range before ABI freeze.
- Adds `ModuleObj::GetFunctionMetadata(name)` virtual method that returns optional JSON metadata for a module function, with import-tree traversal support and FFI registration as `ffi.ModuleGetFunctionMetadata`.
- Renames `override` parameter to `allow_override` in `TVMFFIFunctionSetGlobal` and `TVMFFIFunctionSetGlobalFromMethodInfo` (documentation-only change in C header, no signature-level ABI break since both are `int`).

## Impact
- API: **ABI-breaking** for the type index enum values -- `kTVMFFIArray` changed from 69 to 71, `kTVMFFIMap` from 70 to 72, `kTVMFFIShape` from 71 to 69, `kTVMFFINDArray` from 72 to 70. Any downstream code that hardcodes these numeric values (serialized data, foreign bindings not yet updated) will misidentify object types. The Cython bindings are updated in the same commit.
- Behavioral: New `GetFunctionMetadata` virtual method has a no-op default (`return nullopt`), so existing `ModuleObj` subclasses are unaffected.
- Flags/config: Version bumped from `0.1.0a2` to `0.1.0a3`.
- Data formats/schemas: Any serialized data containing hardcoded type indices 69-72 is now invalid.

Design elements this commit produces:
- **Complexity ordering convention**: Within the static object range `[64, kTVMFFIStaticObjectEnd)`, types are now ordered by ABI complexity: pure C-layout objects (Shape, NDArray) appear before C++-dependent objects (Array, Map). This convention is new and undocumented.
- **`ModuleObj::GetFunctionMetadata`**: New virtual method for querying function-level metadata from modules.
- **`symbol::tvm_ffi_metadata_prefix`**: New naming convention (`__tvm_ffi_metadata_<name>`) for metadata symbols in loaded libraries.
- **`ffi.ModuleGetFunctionMetadata`**: New registered FFI method.

## Usage Examples

Querying function metadata from a loaded module (C++):
```cpp
#include <tvm/ffi/extra/module.h>
using namespace tvm::ffi;

Module mod = Module::LoadFromFile("my_model.so");
// Query metadata for a specific function
Optional<String> meta = mod->GetFunctionMetadata("forward");
if (meta.defined()) {
    // meta.value() contains JSON string with function metadata
    LOG(INFO) << "Metadata: " << meta.value();
}
// Also supports import-tree traversal
Optional<String> meta2 = mod->GetFunctionMetadata("helper_op", /*query_imports=*/true);
```
