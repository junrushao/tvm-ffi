# Reorder static type indices for ABI future-proofing and add module function metadata API
## TL;DR
- Reorders `TVMFFITypeIndex` static object indices so that simpler C-ABI-only types (Shape=69, NDArray=70) precede more complex C++-dependent types (Array=71, Map=72, Module=73), establishing a complexity-based ordering within the static object range before ABI freeze.
- Adds `ModuleObj::GetFunctionMetadata(name)` virtual method (with `query_imports` overload) returning `Optional<String>` in JSON format, plus a `symbol::tvm_ffi_metadata_prefix` constant (`"__tvm_ffi_metadata_"`) for symbol-level metadata discovery in loaded libraries.
- Renames `override` parameter to `allow_override` in `TVMFFIFunctionSetGlobal` and `TVMFFIFunctionSetGlobalFromMethodInfo` C API declarations for clarity.

## Impact
- **API**:
  - **C ABI (breaking)**: `kTVMFFIArray` changes from 69 to 71, `kTVMFFIMap` changes from 70 to 72, `kTVMFFIShape` changes from 71 to 69, `kTVMFFINDArray` changes from 72 to 70. Any compiled code or language binding that hard-codes these integer values must be updated. The comment on `kTVMFFINDArray` is updated from "NDArray" to "Runtime module" description alignment.
  - **C++ extra-tier API**: New virtual method `ModuleObj::GetFunctionMetadata(const String& name)` (default returns `std::nullopt`). New non-virtual overload `ModuleObj::GetFunctionMetadata(const String& name, bool query_imports)` that searches the import tree.
  - **Global functions**: New `ffi.ModuleGetFunctionMetadata` registered as a module method.
  - **Parameter rename**: `TVMFFIFunctionSetGlobal` and `TVMFFIFunctionSetGlobalFromMethodInfo` rename `override` -> `allow_override` (cosmetic, no ABI break since it is a C function parameter name).
  - **New symbol constant**: `symbol::tvm_ffi_metadata_prefix = "__tvm_ffi_metadata_"` for metadata symbol discovery in library modules.
- **Flags/config**: None.
- **Data formats/schemas**: Package version bumped from `0.1.0a2` to `0.1.0a3`. Build script changed from `Release` to `RelWithDebugInfo` and adds `rm -rf build/CMakeCache.txt` before cmake.

## Design Elements

Design elements this commit **consumes**:

- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Directly modifies the `TVMFFITypeIndex` enum in `c_api.h`, consuming the type-index partitioning scheme (static object range `[64, 128)`). The reordering stays within the partition but changes the specific numeric assignments of `kTVMFFIArray`, `kTVMFFIMap`, `kTVMFFIShape`, `kTVMFFINDArray`. Also modifies the parameter names in `TVMFFIFunctionSetGlobal` / `TVMFFIFunctionSetGlobalFromMethodInfo`.
- **Type Index Partitioning** ([`.knowledge/ADRs/0002-type-index-partitioning.md`](../ADRs/0002-type-index-partitioning.md)): The reordering exploits the fact that specific index assignments within the static range are not yet frozen. This is explicitly stated in the commit message: "These items changes ABI to be future compact before we freeze."
- **Module System** ([`.knowledge/designs/0013-module-system.md`](../designs/0013-module-system.md)): Extends `ModuleObj` with `GetFunctionMetadata` virtual and non-virtual overloads, following the existing pattern of `GetFunction`/`ImplementsFunction` with `query_imports` variants. The new `ffi.ModuleGetFunctionMetadata` global function is registered alongside existing module methods.
- **Module Export System** ([`.knowledge/designs/0008-module-export-system.md`](../designs/0008-module-export-system.md)): The `tvm_ffi_metadata_prefix` constant establishes a naming convention for metadata symbols alongside the existing `__tvm_ffi_` symbol prefix used by `TVM_FFI_DLL_EXPORT_TYPED_FUNC`.
- **Python Bindings** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The Cython `base.pxi` is updated to reflect the new type index assignments, keeping the Python binding layer in sync with `c_api.h`.

Design elements this commit **produces**:

- **Complexity-based static type index ordering**: Establishes a new invariant within the static object range: "simple" types with pure C ABI cell layouts (Object=64, Str=65, Bytes=66, Error=67, Function=68, Shape=69, NDArray=70) are ordered before "complex" types that may require C++ runtime support (Array=71, Map=72, Module=73). This ordering is a preparatory step before ABI freeze. The dividing line is marked by a comment block `// more complex objects` in the enum. Evidence: `include/tvm/ffi/c_api.h` diff, commit message "Orders the current static object into simple objects that have C ABI and more complex one that may need c++."
- **Module function metadata API**: A new extensibility point on `ModuleObj` allowing loaded modules to expose structured metadata (as JSON strings) for their functions. The virtual method defaults to `std::nullopt`, and the import-tree-walking overload follows the same recursive pattern as `GetFunction(name, query_imports)`. The `symbol::tvm_ffi_metadata_prefix` constant provides the naming convention for `LibraryModuleObj` to discover metadata symbols (e.g., `__tvm_ffi_metadata_my_func`) from the underlying `Library`.
- **`allow_override` parameter naming convention**: The rename from `override` to `allow_override` in the C API signatures improves readability and avoids the C++ reserved keyword. This is a documentation-level change only (no ABI impact since C parameter names are not part of the ABI).

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0001-c-abi.md`**: The Type Index Layout diagram currently shows the old ordering (Array=69, Map=70, Shape=71, NDArray=72). It should be updated to reflect the new complexity-based ordering (Shape=69, NDArray=70, Array=71, Map=72) and document the "simple C ABI" vs "complex C++" partition within the static range. This doc is referenced by nearly every commit that touches type indices.

- **Update `.knowledge/designs/0013-module-system.md`**: Add `GetFunctionMetadata` to the `ModuleObj` class diagram and virtual method list. Document the `symbol::tvm_ffi_metadata_prefix` naming convention alongside the existing `tvm_ffi_library_ctx`/`tvm_ffi_library_bin`/`tvm_ffi_main` well-known symbols. Also add `ffi.ModuleGetFunctionMetadata` to the global function registration table. This doc is the primary reference for module-related commits.

### ADRs to write

- **`.knowledge/ADRs/0023-static-type-index-ordering.md`**: Decision to reorder static type indices by complexity (C ABI simplicity) before ABI freeze. Context: the original ordering was chronological (types got indices in the order they were added). The new ordering groups types by their ABI complexity: types whose cell layout is fully described by the C `c_api.h` structs come first, types requiring C++ runtime (vtable, templates) come after. Alternatives: (a) keep chronological order (simpler but no semantic grouping), (b) use sub-ranges with gaps (wastes index space). Trade-off: reordering is a breaking ABI change but is acceptable before freeze; the semantic grouping aids future decisions about which types can be used in pure-C contexts.

### Design diagrams to draw

- **Update the Type Index Layout diagram** (Mermaid, in `0001-c-abi.md`): Should show the two sub-groups within the static object range: "Simple C ABI" (Object=64, Str=65, Bytes=66, Error=67, Function=68, Shape=69, NDArray=70) and "Complex C++" (Array=71, Map=72, Module=73), with a visual separator.
