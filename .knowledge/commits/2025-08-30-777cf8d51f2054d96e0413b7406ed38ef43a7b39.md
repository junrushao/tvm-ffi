# Reorder static object type indices for C ABI simplicity grouping; add ModuleObj::GetFunctionMetadata; rename override -> allow_override

## TL;DR
- **ABI-breaking type index reorder**: Moves `kTVMFFIShape` and `kTVMFFINDArray` before `kTVMFFIArray` and `kTVMFFIMap`, grouping "simple C ABI" objects (Shape=69, NDArray=70) before "more complex" objects (Array=71, Map=72). Module stays at 73.
- **New virtual method**: `ModuleObj::GetFunctionMetadata(name)` returns `Optional<String>` (JSON metadata), with a `query_imports` overload that walks the import chain. Registered as `ffi.ModuleGetFunctionMetadata` global function.
- **Parameter rename**: `TVMFFIFunctionSetGlobal` and `TVMFFIFunctionSetGlobalFromMethodInfo` rename their `override` parameter to `allow_override` (source-level only, no ABI change since the parameter is `int`).
- **Version bump**: `apache-tvm-ffi` version `0.1.0a2` -> `0.1.0a3`.

## Impact
- API: ABI-breaking change to static object type indices. All language bindings that hardcode type index values (Cython `base.pxi`, Rust) must be updated. The Cython binding is updated in this commit; other bindings (Rust) may need separate updates.
- ABI: Type index values for `kTVMFFIShape`, `kTVMFFINDArray`, `kTVMFFIArray`, `kTVMFFIMap` are renumbered. Any persisted type indices (e.g., serialized objects) from prior versions are invalid.
- Behavioral: `ModuleObj` gains a new virtual method `GetFunctionMetadata` with a default no-op implementation. Existing `ModuleObj` subclasses are unaffected unless they override it.
- Flags/config: `scripts/run_tests.sh` changes build type from `Release` to `RelWithDebugInfo` and adds `rm -rf build/CMakeCache.txt` for clean rebuilds.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Type index range partitioning** (`.knowledge/ADRs/003-type-index-ranges.md`): Reorders values within the `[64, 128)` static object range. `kTVMFFIModule` remains at 73; `kTVMFFIStaticObjectEnd` is still computed implicitly.
- **Module system** (`.knowledge/designs/0013-module-system.md`): Extends `ModuleObj` with a new virtual method following the same pattern as `GetFunction` and `ImplementsFunction` (single-module virtual + query_imports non-virtual overload).
- **Cython binding layer** (`.knowledge/designs/0014-python-bindings.md`): Updates the `TVMFFITypeIndex` enum mirror in `base.pxi`.
- **C ABI function signatures** (`.knowledge/designs/c-abi.md`): Renames `override` parameter to `allow_override` in two C API functions.

Design elements this commit produces:
- **C ABI simplicity ordering convention**: Introduces a deliberate ordering within the static object range: "simple" objects with pure C ABI layouts (Shape, NDArray) are grouped at lower indices (69-70), while "more complex" objects that may involve C++ internals (Array, Map) are at higher indices (71-72). This is marked with a `// more complex objects` comment divider.
- **Module function metadata protocol**: `GetFunctionMetadata` + `tvm_ffi_metadata_prefix` symbol constant establish a convention for modules to expose per-function metadata as JSON strings. The `__tvm_ffi_metadata_` prefix suggests a future pattern where metadata for function `foo` would be stored as `__tvm_ffi_metadata_foo` in a library.

## Usage Examples

### Retrieving function metadata from a loaded module
**Context**: Querying metadata from a dynamically loaded module (the metadata is provided by subclass overrides).
```cpp
Module mod = Module::LoadFromFile("my_model.so");
// Query metadata for a specific function, including imports
Optional<String> meta = mod->GetFunctionMetadata("forward", /*query_imports=*/true);
if (meta.defined()) {
  // meta.value() contains JSON string with function metadata
  std::cout << meta.value() << std::endl;
}
```
