# Add stl.h header enabling vanilla C++ STL types in FFI exported functions
## TL;DR
- Introduces `include/tvm/ffi/extra/stl.h`, a new header providing `TypeTraits` specializations for 8 C++ STL types (`std::array`, `std::vector`, `std::optional`, `std::variant`, `std::tuple`, `std::map`, `std::unordered_map`, `std::function`), enabling them as direct parameter and return types in FFI-exported functions.
- STL types are bridged through TVM FFI's existing `ArrayObj` (list-like) and `MapObj` (map-like) containers — values are always copied into/from Objects, never stored directly in `Any`.
- Adds a `friend struct TypeTraits` declaration to `MapObj` so the STL map traits can call `MapObj::CreateFromRange`.

## Key Exports

**Helper types** (in `tvm::ffi::details`):
- `STLTypeMismatch` — exception sentinel (`std::exception` subclass) used for early-return from nested `TryCast` chains inside STL type conversion. Never escapes the conversion boundary.
- `STLTypeTrait` — base class (extends `TypeTraitsBase`) with `storage_enabled = false` and three protected helpers:
  - `MoveToAnyImpl(ObjectPtr<T>&&, TVMFFIAny*)` — moves an ObjectPtr into an Any slot.
  - `CopyFromAnyImpl<T>(const TVMFFIAny*)` — extracts `ObjectPtr<T>` from an Any slot (non-owning copy).
  - `ConstructFromAny<T>(const Any&)` — type-checks and extracts `T` from `Any`, throwing `STLTypeMismatch` on failure.
- `ListTemplate` — tag type; `TypeTraits<ListTemplate>` extends `STLTypeTrait` with `field_static_type_index = kTVMFFIArray` and protected helpers:
  - `CopyToTuple(const Tuple&) -> ObjectPtr<ArrayObj>`
  - `MoveToTuple(Tuple&&) -> ObjectPtr<ArrayObj>`
  - `CopyToArray(const Range&) -> ObjectPtr<ArrayObj>`
  - `MoveToArray(Range&&) -> ObjectPtr<ArrayObj>`
- `MapTemplate` — tag type; `TypeTraits<MapTemplate>` extends `STLTypeTrait` with `field_static_type_index = kTVMFFIMap` and protected helpers:
  - `CopyToMap(const MapType&) -> ObjectPtr<Object>`
  - `MoveToMap(MapType&&) -> ObjectPtr<Object>`
  - `ConstructMap<MapType, CanReserve>(const TVMFFIAny*) -> MapType`

**TypeTraits specializations** (all inherit `STLTypeTrait` indirectly, all have `storage_enabled = false`):

| STL Type | Bridges via | `field_static_type_index` | Notes |
|----------|------------|--------------------------|-------|
| `std::array<T, N>` | `ArrayObj` | `kTVMFFIArray` | Size-checked (`N > 0` static assert) |
| `std::vector<T>` | `ArrayObj` | `kTVMFFIArray` | Dynamic length |
| `std::optional<T>` | Delegates to `TypeTraits<T>` | (from T) | Maps `None`/`kTVMFFINone` to `std::nullopt` |
| `std::variant<Args...>` | Delegates per alternative | (from first match) | First-match semantics on `TryCast` |
| `std::tuple<Args...>` | `ArrayObj` | `kTVMFFIArray` | Size-checked, heterogeneous (`N > 0` static assert) |
| `std::map<K, V>` | `MapObj` | `kTVMFFIMap` | Ordered; no `reserve` |
| `std::unordered_map<K, V>` | `MapObj` | `kTVMFFIMap` | Unordered; `reserve` called |
| `std::function<Ret(Args...)>` | `TypedFunction<Ret(Args...)>` | `kTVMFFIFunction` | Wraps in lambda for type erasure |

Each specialization implements: `CopyToAnyView`, `MoveToAny`, `TryCastFromAnyView`, `TypeStr`, `TypeSchema`. List-like and map-like specializations also implement `CheckAnyStrict` where appropriate. All return `std::nullopt` from `TryCastFromAnyView` on type mismatch (catching `STLTypeMismatch` internally).

**MapObj change**: Added `friend struct TypeTraits` (template with two params) to `MapObj` class, granting map traits access to `CreateFromRange`.

## Impact
- API: Additive only. New header `tvm/ffi/extra/stl.h` users must explicitly include. Existing code unaffected.
- Behavioral: None to existing functions. STL parameters in newly exported functions will be auto-converted through Array/Map intermediaries.
- Flags/config: None.
- Data formats/schemas: `TypeSchema()` returns new JSON type descriptors: `std::array`, `std::vector`, `std::optional`, `std::variant`, `std::tuple`, `std::map`, `std::unordered_map`, `std::function`.

## Design Elements
Design elements this commit consumes:
- **TypeTraits protocol** ([0005-type-traits.md](../designs/0005-type-traits.md)): Extends with 8 new specializations following the established 7+1 method protocol. Uses `TypeTraitsBase`, `STLTypeTrait` base, `CheckAnyStrict`/`TryCastFromAnyView` distinction.
- **ArrayObj** ([0008-containers.md](../designs/0008-containers.md)): Used as the wire format for `std::array`, `std::vector`, `std::tuple`. Calls `ArrayObj::Empty()`, `MutableBegin()`, placement-new construction.
- **MapObj** ([0008-containers.md](../designs/0008-containers.md)): Used as the wire format for `std::map`, `std::unordered_map`. Calls `MapObj::CreateFromRange`.
- **TypedFunction** ([0004-function-system.md](../designs/0004-function-system.md)): `std::function` trait delegates to `TypeTraits<TypedFunction<Ret(Args...)>>`.
- **Extra API isolation** ([ADR 0010-extra-api-isolation.md](../ADRs/0010-extra-api-isolation.md)): File placed in `include/tvm/ffi/extra/` directory per the isolation convention.
- **ObjectUnsafe / ObjectPtr** ([0003-object-system.md](../designs/0003-object-system.md)): Uses `MoveObjectPtrToTVMFFIObjectPtr`, `ObjectPtrFromUnowned` for ownership management in the `STLTypeTrait` base.

Design elements this commit produces:
- **STL-to-FFI bridging layer** (`stl.h`): New extension point allowing vanilla C++ STL types as first-class FFI function parameters/returns. Pattern: STL value -> copy into Object (Array/Map) -> type-erased Any -> cross-language boundary -> reconstruct STL value.
- **`STLTypeMismatch` exception protocol**: Internal sentinel exception for early-return from nested type conversion, caught at the `TryCastFromAnyView` boundary and converted to `std::nullopt`.
- **`STLTypeTrait` base class**: Reusable base for all STL-bridged types with `storage_enabled = false` (cannot be stored directly in Any; must pass through Object intermediary).

## Usage Examples
**C++ side**: Export a function using STL types as parameters and return:
```cpp
#include <tvm/ffi/extra/stl.h>
#include <tvm/ffi/function.h>

auto sum_row(std::optional<std::vector<std::array<int, 2>>> arg)
    -> std::tuple<bool, std::vector<int>> {
  if (arg) {
    std::vector<int> result;
    result.reserve(arg->size());
    for (const auto& row : *arg)
      result.push_back(row[0] + row[1]);
    return {true, result};
  }
  return {false, {}};
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(sum_row, sum_row);
```

**Python side**: Call from Python with native Python types:
```python
mod = tvm_ffi.load_module(lib_path)
mod.sum_row([[1, 2], [3, 4]])   # returns (True, [3, 7])
mod.sum_row(None)                # returns (False, [])
```
