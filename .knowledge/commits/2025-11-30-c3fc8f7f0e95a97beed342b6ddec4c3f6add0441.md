# Add STL container TypeTraits specializations via include/tvm/ffi/extra/stl.h

## TL;DR
- Introduces `include/tvm/ffi/extra/stl.h`, an opt-in header that specializes `TypeTraits<T>` for C++ STL types (`std::vector`, `std::array<T,N>`, `std::tuple`, `std::optional`, `std::variant`, `std::map`, `std::unordered_map`, `std::function`), enabling them as packed-function arguments.
- All STL types go through an intermediate `ArrayObj`/`MapObj`/`FunctionObj` at the ABI boundary — they are never stored natively in `Any`; `storage_enabled = false` for all STL specializations.
- `MapObj` gains a `friend struct TypeTraits` declaration so the STL map path can call internal `MapObj::CreateFromRange`.

## Key Exports

```python
# --- Internal base helpers (details namespace) ---

class STLTypeMismatch(Exception):
    """Thrown internally during STL TryCast; caught and returned as nullopt."""
    ...

class STLTypeTrait(TypeTraitsBase):
    """Base CRTP helper for all STL list/map traits.
    storage_enabled = False — STL types cannot be stored directly in Any.
    """
    storage_enabled: bool = False
    # Converts STL value → ObjectPtr<ArrayObj/MapObj> → TVMFFIAny (via v_obj)
    # Converts TVMFFIAny → ObjectPtr<ArrayObj/MapObj> → STL value

class ListTemplate: ...   # Tag type; TypeTraits<ListTemplate> handles array/vector/tuple
class MapTemplate: ...    # Tag type; TypeTraits<MapTemplate> handles map/unordered_map

# --- Public specializations ---

class TypeTraits_std_array(TypeTraits[ListTemplate]):
    """TypeTraits for std::array<T, Nm>. Fixed-size; checks ABI length == Nm."""
    # Interacts with: ArrayObj (layout), TypeTraits<T> for each element
    # Invariant: Nm > 0; array ABI length must equal Nm or TryCast returns nullopt

class TypeTraits_std_vector(TypeTraits[ListTemplate]):
    """TypeTraits for std::vector<T>. Variable-size; maps to ArrayObj."""
    # Interacts with: ArrayObj (layout), TypeTraits<T> for each element

class TypeTraits_std_optional(TypeTraitsBase):
    """TypeTraits for std::optional<T>. None maps to kTVMFFINone."""
    # Interacts with: TypeTraits<T>, kTVMFFINone
    # Invariant: nullopt <-> kTVMFFINone in Any

class TypeTraits_std_variant(TypeTraitsBase):
    """TypeTraits for std::variant<Args...>. Tries each alternative in order."""
    # Interacts with: TypeTraits<Args>... (first-match wins)
    # Invariant: CheckAnyStrict = OR of CheckAnyStrict over all Args

class TypeTraits_std_tuple(TypeTraits[ListTemplate]):
    """TypeTraits for std::tuple<Args...>. Fixed arity; maps to ArrayObj of size Nm."""
    # Interacts with: ArrayObj, TypeTraits<each element type>
    # Invariant: tuple arity must match ArrayObj size or TryCast returns nullopt

class TypeTraits_std_map(TypeTraits[MapTemplate]):
    """TypeTraits for std::map<K,V>. Ordered; maps to MapObj."""
    # Interacts with: MapObj, TypeTraits<K>, TypeTraits<V>

class TypeTraits_std_unordered_map(TypeTraits[MapTemplate]):
    """TypeTraits for std::unordered_map<K,V>. Hash map; maps to MapObj."""
    # Interacts with: MapObj, TypeTraits<K>, TypeTraits<V>

class TypeTraits_std_function(TypeTraitsBase):
    """TypeTraits for std::function<R(Args...)>. Wraps as FunctionObj <-> Function."""
    # Interacts with: FunctionObj, Function::FromTyped, TypeTraits<Args>...
    # Invariant: round-trip wrapping; arity + types checked at call time
```

## Impact
- API: New opt-in header `include/tvm/ffi/extra/stl.h`. Existing headers unchanged.
- Behavioral: Callers who `#include <tvm/ffi/extra/stl.h>` can now pass STL types transparently into `TVM_FFI_DLL_EXPORT_TYPED_FUNC` exported functions.
- Flags/config: `TVM_FFI_DLL_EXPORT_INCLUDE_METADATA` not relevant here; no new CMake flags.
- Data formats/schemas: STL vectors/arrays serialize over ABI as `ArrayObj`; maps as `MapObj`. `TypeStr()` and `TypeSchema()` added for all specializations (JSON schema strings).

## Design Elements
Design elements this commit consumes:
- `TypeTraits<T>` customization-point protocol (`.knowledge/design-records/0008-type-traits.md`) — adds new specializations for STL types using the established protocol methods `CopyToAnyView`, `MoveToAny`, `TryCastFromAnyView`, `CheckAnyStrict`
- `ArrayObj` / `Array<T>` (`.knowledge/design-records/0007-containers.md`) — STL list types serialize into `ArrayObj` via `ArrayObj::Empty` + in-place construction
- `MapObj` (`.knowledge/design-records/0007-containers.md`) — STL map types serialize via `MapObj::CreateFromRange`; `MapObj` gains `friend struct TypeTraits<...>` for internal access
- `FunctionObj` / `Function` (`.knowledge/design-records/0004-function-system.md`) — `std::function<R(Args...)>` wraps into `FunctionObj` via `Function::FromTyped`
- `AnyView` / `Any` (`.knowledge/design-records/0003-any-anyview.md`) — all STL values transit through `TVMFFIAny` using the standard `v_obj` + type_index path

Design elements this commit produces:
- New sub-protocol: **STL TypeTraits extension point** in `include/tvm/ffi/extra/stl.h`. Introduces `STLTypeTrait` base class with `storage_enabled=false`, providing shared helpers (`CopyToArrayImpl`, `MoveToTuple`, `ConstructMap`, etc.) for list/map families. This is a new convention: STL types are always bridge-copied through intermediate Objects, never stored natively.

## Usage Examples

End-to-end: define a typed C++ function using STL, export it, and call from Python.

```cpp
// tests/python/cpp_src/test_stl.cc
#include <tvm/ffi/extra/stl.h>
#include <tvm/ffi/function.h>

// optional<vector<array<int,2>>> → optional<vector<int>>
auto test_vector(std::optional<std::vector<std::array<int, 2>>> arg)
    -> std::optional<std::vector<int>> {
  if (arg) {
    std::vector<int> result;
    for (const auto& row : *arg)
      result.push_back(row[0] + row[1]);
    return result;
  }
  return std::nullopt;
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(test_vector, test_vector);
```

```python
# tests/python/test_stl.py
import tvm_ffi.cpp
mod = tvm_ffi.load_module(tvm_ffi.cpp.build("test_stl", cpp_files=[...]))
assert list(mod.test_vector([[1, 2], [3, 4]])) == [3, 7]
assert mod.test_vector(None) is None
```
