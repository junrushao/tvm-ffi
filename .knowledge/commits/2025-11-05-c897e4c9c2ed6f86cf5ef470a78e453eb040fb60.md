# Add file-based build() and load() for C++/CUDA extensions via Ninja
## TL;DR
- Add `tvm_ffi.cpp.build()` and `tvm_ffi.cpp.load()` functions that compile C++/CUDA source files (not inline strings) into shared libraries via Ninja, inspired by `torch.utils.cpp_extension.load`.
- Rename `load_inline.py` to `extension.py`, consolidating all build/load functions. Re-export `build`, `build_inline`, `load`, `load_inline` from `tvm_ffi.cpp.__init__`.
- Add comprehensive cross-platform support: Windows MSVC via Developer Command Prompt + `vswhere`, CUDA home auto-detection, GPU compute capability auto-detection via `nvidia-smi`, and `TVM_FFI_CUDA_ARCH_LIST` env var override.

## Key Exports
**Functions** (new):
- `build(name: str, *, cpp_files, cuda_files, extra_cflags, extra_cuda_cflags, extra_ldflags, extra_include_paths, build_directory) -> str` — compiles C++/CUDA files into a shared library, returns the `.so`/`.dll` path. Does NOT auto-export FFI functions (user must use `TVM_FFI_DLL_EXPORT_TYPED_FUNC` manually).
- `load(name: str, *, cpp_files, cuda_files, extra_cflags, extra_cuda_cflags, extra_ldflags, extra_include_paths, build_directory) -> Module` — calls `build()` then `load_module()`, returning a `Module` with callable functions.

**Functions** (existing, refactored):
- `build_inline(...)` and `load_inline(...)` — moved from `load_inline.py` to `extension.py`, now share the same `_build_impl` infrastructure.

**Internal helpers** (new):
- `_find_cuda_home() -> str` — cached CUDA home detection (env > `which nvcc` > default paths).
- `_get_cuda_target() -> str` — auto-detect GPU compute capability via `nvidia-smi` or `TVM_FFI_CUDA_ARCH_LIST` env var.
- `_generate_ninja_build(name, with_cuda, ...) -> str` — generates `build.ninja` content with platform-aware compiler/linker flags.
- `build_ninja(build_dir: str) -> None` — invokes Ninja in the given directory.
- `_run_command_in_dev_prompt(args, cwd, capture_output)` — Windows-specific: locates MSVC Developer Command Prompt via `vswhere.exe` and runs build commands within its environment.

## Impact
- API: New public functions `build` and `load` in `tvm_ffi.cpp`. File rename `load_inline.py` -> `extension.py` (backward compatible via re-exports).
- Behavioral: `build`/`load` differ from `build_inline`/`load_inline` in that they accept file paths instead of inline source strings, and do NOT auto-generate FFI export wrappers.
- Flags/config: `TVM_FFI_CUDA_ARCH_LIST` env var (new) — space-separated CUDA arch list (e.g., "8.9 9.0a"). `CUDA_HOME`/`CUDA_PATH`/`CXX` env vars respected.
- Data formats/schemas: none

## Usage Examples
```python
import tvm_ffi.cpp
from tvm_ffi.module import Module
import numpy as np

# Build from .cc file (user must use TVM_FFI_DLL_EXPORT_TYPED_FUNC in the source)
lib_path = tvm_ffi.cpp.build(name="my_ext", cpp_files=["my_kernel.cc"])

# Or build and load in one step
mod: Module = tvm_ffi.cpp.load(name="my_ext", cpp_files=["my_kernel.cc"])

x = np.array([1, 2, 3], dtype=np.float32)
y = np.empty_like(x)
mod.add_one_cpu(x, y)  # calls the exported function
```
