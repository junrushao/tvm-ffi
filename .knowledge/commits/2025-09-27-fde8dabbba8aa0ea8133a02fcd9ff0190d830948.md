# Fix wrong field check in Cython DLPack stream passing that skipped stream query
## TL;DR
- Fixed `ctx.device_id != -1` -> `ctx.device_type != -1` in `TVMFFIPyArgSetterDLPackCExporter_` (`function.pxi`), which caused stream query to be skipped for all DLPack tensor arguments because `device_id` defaults to `0` (always != `-1`).
- Added regression test in `test_load_inline_cuda` that asserts the stream handle passed through FFI matches the raw stream, covering both default stream and explicit `torch.cuda.Stream`.
- Version bump `0.1.0b10` -> `0.1.0b11`.

## Key Exports
The fix changes no public API surface -- it corrects an internal conditional in the Cython FFI call path.

```python
# TVMFFIPyArgSetterDLPackCExporter_ (Cython, internal)
# Before (broken):
#   if ctx.device_id != -1:   # device_id defaults to 0, so always True -> stream never queried
# After (fixed):
#   if ctx.device_type != -1: # device_type defaults to -1, correctly gates "already queried" branch
# Interacts with: TVMFFIPyCallContext.device_type, TVMFFIPyCallContext.device_id
# Invariant: device_type == -1 means "no device detected yet"; device_id == 0 is a valid device id
```

## Impact
- API: None -- no public API changes.
- Behavioral: Stream passing for DLPack-exported GPU tensors now works correctly. Before this fix, the stream was never propagated because the guard condition was always true.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyCallContext** ([0012-python-bindings](../designs/0012-python-bindings.md)): The per-call context struct with `device_type`, `device_id`, `stream` fields. The bug was a field name confusion between two integer fields with different default semantics (`device_type=-1` vs `device_id=0`).
- **First-non-CPU-device-wins invariant** ([0014-stream-and-env-context](../designs/0014-stream-and-env-context.md)): The protocol where the first non-CPU tensor determines stream context. This invariant was broken by the bug.
- **DLPackFromPyObject callback** ([0014-stream-and-env-context](../designs/0014-stream-and-env-context.md)): The C function pointer `c_dlpack_from_pyobject` that optionally outputs the env stream when the third argument is non-NULL.

Design elements this commit produces:
- None -- purely corrective fix.

## Usage Examples
**Before (broken)**: Passing a CUDA tensor via DLPack to an FFI function, the stream was silently dropped because `ctx.device_id` (default `0`) was never `-1`:

```python
# stream was NOT propagated -- FFI function ran on default stream, not the caller's stream
mod.add_one_cuda(x_cuda, y_cuda)
```

**After (fixed)**: Stream is correctly propagated. The regression test verifies this end-to-end:

```python
# With default stream
mod.add_one_cuda(x_cuda, y_cuda, 0)  # raw_stream=0 matches default CUDA stream

# With explicit torch stream
stream = torch.cuda.Stream()
with torch.cuda.stream(stream):
    mod.add_one_cuda(x_cuda, y_cuda, stream.cuda_stream)
    # Inside C++: TVM_FFI_ICHECK_EQ(reinterpret_cast<int64_t>(
    #     TVMFFIEnvGetStream(device_type, device_id)), raw_stream)
stream.synchronize()
```
