# Fix Cython DLPack speed-converter stream passing by checking device_type instead of device_id

## TL;DR
- Fixed a bug in `TVMFFIPyArgSetterDLPackCExporter_` (Cython) where the stream-already-queried guard checked `ctx.device_id != -1` instead of `ctx.device_type != -1`. Since `device_id` defaults to `0`, the guard was always true, causing the stream to never be queried on the first DLPack tensor argument.
- Added a regression test in `test_load_inline_cuda` that passes `raw_stream` into the CUDA kernel and asserts `TVMFFIEnvGetStream()` returns the same stream, covering both the default stream and a custom `torch.cuda.Stream`.
- Version bump from `0.1.0b10` to `0.1.0b11`.

## Key Exports
None (bugfix only; no new public API surface).

## Impact
- API: None -- no signature or public interface changes.
- Behavioral: **Fix** -- Before this commit, when passing torch CUDA tensors through the DLPack speed-converter path (`TVMFFIPyArgSetterDLPackCExporter_`), the CUDA stream was never captured from the environment because the wrong field (`device_id`, default `0`) was tested against the sentinel value `-1`. After the fix, `device_type` (default `-1`) is tested, so the first CUDA tensor correctly triggers stream query via `DLPackFromPyObject(arg, &tensor, &env_stream)`. This restores correct CUDA stream propagation for all FFI calls involving torch tensors.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
**Before (incorrect):** `ctx.device_id` was checked, which is `0` by default (not `-1`), so the condition was always true. Stream was never queried:
```cython
# BUG: device_id defaults to 0, so this is always True
if ctx.device_id != -1:
    # always takes this branch -- passes NULL for stream
    (this.c_dlpack_from_pyobject)(arg, &temp_managed_tensor, NULL)
```

**After (correct):** `ctx.device_type` is checked, which is `-1` by default (the "unset" sentinel):
```cython
# FIXED: device_type defaults to -1, correctly detecting "not yet queried"
if ctx.device_type != -1:
    # only taken after first tensor already set device context
    (this.c_dlpack_from_pyobject)(arg, &temp_managed_tensor, NULL)
else:
    # first tensor: query stream from environment
    (this.c_dlpack_from_pyobject)(arg, &temp_managed_tensor, &env_stream)
```

**Regression test pattern** (C++ kernel validates stream propagation):
```cpp
// Inside CUDA kernel: assert env stream matches expected raw_stream
cudaStream_t stream = static_cast<cudaStream_t>(
    TVMFFIEnvGetStream(x->device.device_type, x->device.device_id));
TVM_FFI_ICHECK_EQ(reinterpret_cast<int64_t>(stream), raw_stream)
  << "stream must be the same as raw_stream";
```
```python
# Python side: test with default stream (0) and custom stream
mod.add_one_cuda(x_cuda, y_cuda, 0)  # default stream

stream = torch.cuda.Stream()
with torch.cuda.stream(stream):
    mod.add_one_cuda(x_cuda, y_cuda, stream.cuda_stream)  # custom stream
```
