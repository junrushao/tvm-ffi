# Fix Map.get() performance by replacing try/except with C++-side sentinel lookup
## TL;DR
- Replaces the Python-side `try/except KeyError` pattern in `Map.get()` and `ItemsView.__contains__()` with a new C++-side `MapGetItemOrMissing` FFI function that returns a singleton sentinel object on missing keys, avoiding exception-based control flow.
- Adds two new FFI functions: `ffi.MapGetMissingObject` (returns a static singleton `Object`) and `ffi.MapGetItemOrMissing` (returns value or sentinel).
- The sentinel (`MISSING`) is a module-level singleton in `container.py`, identity-compared via `Object.same_as()`.

## Impact
- API: Two new FFI functions (`ffi.MapGetItemOrMissing`, `ffi.MapGetMissingObject`) added to the global registry and `_ffi_api.py` stubs. No existing API signatures changed.
- Behavioral: `Map.get()` no longer raises and catches `KeyError` internally. The performance improvement eliminates Python exception creation/handling overhead on every cache miss. Fixes #326.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Map container** (`.knowledge/designs/0007-containers.md`): `MapObj.at()` for key lookup, `Map.get()` Pythonic API
- **Object identity** (`.knowledge/designs/0002-object-system.md`): `Object.same_as()` for sentinel comparison (pointer identity)
- **Global function registry** (`.knowledge/designs/0004-function-system.md`): `GlobalDef().def()` to register new FFI functions
- **FFI stub generation** (`_ffi_api.py`): type stubs for the two new functions

Design elements this commit produces:
- **Sentinel-based missing-key pattern**: A reusable pattern where a static singleton `Object` serves as a "not found" sentinel, avoiding exception-based control flow. The sentinel is identity-compared via `same_as()`, not equality. This pattern could be reused for other container lookups that currently use try/except.

## Usage Examples

**Before (slow -- exception on every miss):**
```python
# Map.get() previously used try/except internally:
m = tvm_ffi.Map({"a": 1, "b": 2})
val = m.get("c", -1)  # raised KeyError internally, caught it, returned -1
```

**After (fast -- sentinel comparison):**
```python
# Map.get() now uses a single FFI call + identity check:
m = tvm_ffi.Map({"a": 1, "b": 2})
val = m.get("c", -1)  # calls MapGetItemOrMissing, compares with MISSING, returns -1
# No exception created or caught
```

**Cross-layer trace:**
```
Python Map.get(key, default)
  -> FFI call: MapGetItemOrMissing(self, key)
    -> C++ MapObj::at(key)
      -> found? return value
      -> not found? catch ffi::Error, return GetMissingObject()
  -> Python: if MISSING.same_as(ret): return default
```
