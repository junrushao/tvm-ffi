# Replace exception-based Map.get control flow with a sentinel-object protocol to eliminate per-lookup exception overhead

## TL;DR
- Introduces `GetMissingObject()` in C++ (`src/ffi/container.cc`) — a static singleton `ObjectRef` used as an out-of-band "not found" signal, registered as `ffi.MapGetMissingObject`.
- Adds `ffi.MapGetItemOrMissing` global function that returns either the value or the missing sentinel instead of throwing on miss; replaces the `try/except KeyError` path in `Map.get`.
- Python `MISSING` module-level sentinel (singleton) enables `is`-based identity check (`MISSING.same_as(ret)`) in `Map.get` and `ItemsView.__contains__`, avoiding exception construction/propagation on every cache-miss lookup.

## Key Exports

```python
# C++ (src/ffi/container.cc)

def GetMissingObject() -> ObjectRef:
    """Static singleton sentinel for 'key not found' in Map lookups.
    # Invariant: always returns the same ObjectRef instance (static local, initialized once)
    # Interacts with: ffi.MapGetItemOrMissing, Python MISSING global in container.py
    # Extension: call GetMissingObject() in any C++ code that needs an out-of-band 'missing' signal
    """

# Registered as global function via reflection:
# registry["ffi.MapGetMissingObject"] = GetMissingObject  → ObjectRef
# registry["ffi.MapGetItemOrMissing"] = lambda n, k: n->at(k) catch Error → GetMissingObject()

def MapGetItemOrMissing(n: MapObj*, k: Any) -> Any:
    """Lookup key k in map n. Returns value if found; returns GetMissingObject() sentinel on miss.
    # OLD: MapGetItem raises tvm.ffi.Error on miss → Python Map.get catches KeyError
    # NEW: MapGetItemOrMissing returns sentinel → Map.get checks identity with MISSING
    # Invariant: on catch, only tvm::ffi::Error is swallowed — other exceptions propagate
    # Interacts with: DenseMapObj.At(), SmallMapObj.At(), GetMissingObject()
    """

# Python (python/tvm_ffi/container.py)

MISSING: ObjectRef  # = _ffi_api.MapGetMissingObject()
# Module-level singleton; identity is stable for process lifetime
# Interacts with: Map.get, ItemsView.__contains__

class Map(core.Object, Mapping[K, V]):
    def get(self, key: K, default: _DefaultT = None) -> V | _DefaultT:
        """Return value for key, or default if absent.
        # OLD: calls self[key] (→ MapGetItem → KeyError) inside try/except
        # NEW: calls _ffi_api.MapGetItemOrMissing(self, key); returns default iff MISSING.same_as(ret)
        # Invariant: no exception raised for missing keys; only one FFI round-trip per call
        # Interacts with: _ffi_api.MapGetItemOrMissing, MISSING sentinel
        """

class ItemsView(ItemsViewBase[K, V]):
    def __contains__(self, item: object) -> bool:
        """Check if (key, value) pair is in the map.
        # OLD: calls self._backend_map[key] inside try/except KeyError
        # NEW: calls self._backend_map.get(key, MISSING); checks `actual_value is MISSING`
        # Invariant: avoids exception overhead for non-member queries
        """
```

## Impact
- API: None — `Map.get` and `ItemsView.__contains__` signatures are unchanged; two new internal FFI functions (`ffi.MapGetItemOrMissing`, `ffi.MapGetMissingObject`) are added to the global registry.
- Behavioral: `Map.get` for a dense map with a missing key now returns `default` without going through exception construction or stack unwinding. Semantics are identical.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- `0007-containers`: `Map`, `MapObj`, `DenseMapObj.At()`, `ItemsView` — the Python `Map.get` and `ItemsView.__contains__` patterns described in that record. The old pattern (try/except KeyError around `MapGetItem`) is superseded.
- `0004-function-system`: `reflection::GlobalDef().def(name, fn)` inside `TVM_FFI_STATIC_INIT_BLOCK` — used to register the two new FFI globals.
- `0002-object-system`: `make_object<Object>()` and `ObjectRef` — used to create the static singleton sentinel.
- `0003-any-anyview`: `Any` return type of `MapGetItemOrMissing`.

Design elements this commit produces:
- **`MISSING` sentinel protocol** — a new cross-layer pattern: a C++ static singleton `ObjectRef` is exposed via `ffi.MapGetMissingObject()`, cached in Python as a module-level `MISSING`, and tested via `MISSING.same_as(ret)`. This is a novel extension point for any FFI function that needs to signal "absent" without raising.
- Two new registered global functions: `ffi.MapGetMissingObject` and `ffi.MapGetItemOrMissing`.

## Usage Examples

Cross-layer trace (C++ sentinel → Python sentinel check):

```python
# C++ registration (src/ffi/container.cc):
#   GetMissingObject() returns a static ObjectRef — created once, returned on every miss
#   registry["ffi.MapGetMissingObject"] → GetMissingObject
#   registry["ffi.MapGetItemOrMissing"] → lambda (n, k): try n->at(k) catch → GetMissingObject()

# Python (python/tvm_ffi/container.py):
MISSING = _ffi_api.MapGetMissingObject()     # fetched once at module import

# Map.get — hot path, no exception:
amap = tvm_ffi.convert({k: k**2 for k in range(100)})
ret = _ffi_api.MapGetItemOrMissing(amap, 101)   # returns MISSING sentinel
if MISSING.same_as(ret):
    result = None                                # default
else:
    result = ret                                 # found value

# From test (tests/python/test_container.py):
assert amap.get(101) is None   # missing key → default
assert amap.get(3) == 9        # present key → value
```
