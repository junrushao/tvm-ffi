# Enable Doxygen build checks in CI and fix Doxygen warnings across C++ headers
## TL;DR
- Enables `BUILD_CPP_DOCS=1` in the CI doc-build job so that Doxygen output is generated and validated alongside Sphinx, catching C++ documentation errors before merge.
- Installs `doxygen` in the CI environment (`.github/workflows/ci_test.yml`).
- Fixes all Doxygen warnings surfaced by the new check across 5 C++ headers and `docs/conf.py`.

## Key Exports
None (no new public APIs).

Notable changes to existing files:

| File | Change |
|------|--------|
| `.github/workflows/ci_test.yml` | Adds `sudo apt install doxygen` and sets `BUILD_CPP_DOCS=1` before `sphinx-build`. |
| `docs/conf.py` | Adds `TVM_FFI_DLL_EXPORT`, `TVM_FFI_WEAK`, `TVM_FFI_DOXYGEN_MODE` to Doxygen `PREDEFINED`; enables `WARNINGS` and `WARN_AS_ERROR`; adds `cpp_id_attributes` and `c_id_attributes` lists so Sphinx's C/C++ domain ignores TVM FFI macros. |
| `include/tvm/ffi/c_api.h` | Wraps anonymous unions in `TVMFFIObject` and `TVMFFIAny` with `#if !defined(TVM_FFI_DOXYGEN_MODE)` guards so Doxygen sees the members as plain struct fields; adds `\brief` doc comments to each `TVMFFIAny` union member. |
| `include/tvm/ffi/container/map.h` | Adds `\cond Doxygen_Suppress` / `\endcond` around the deleted `make_object<MapObj>` specialization to suppress Doxygen warnings on the deleted template. |
| `include/tvm/ffi/container/tensor.h` | Removes a stray `\endcond` that had no matching `\cond`. |
| `include/tvm/ffi/reflection/access_path.h` | Removes erroneous `\return` tag from `AccessStep` constructor doc comment (constructors have no return value). |
| `include/tvm/ffi/reflection/registry.h` | Removes erroneous `\return` tag from `AttachFieldFlag` constructor; adds missing `\endcode` to close an example code block in `init<T, Args...>()`. |

## Impact
- API: none
- ABI: none -- the `TVM_FFI_DOXYGEN_MODE` guards are compile-time only and never defined during normal builds; they only affect Doxygen parsing.
- Behavioral: none at runtime. CI will now fail if C++ doc comments contain Doxygen warnings (missing tags, unmatched groups, etc.).
- Flags/config: `BUILD_CPP_DOCS=1` is now set in CI. A new Doxygen-only preprocessor symbol `TVM_FFI_DOXYGEN_MODE` is introduced to work around Doxygen's inability to parse anonymous unions.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C ABI layer** (`.knowledge/designs/c-abi.md`): The `TVMFFIObject` and `TVMFFIAny` structs in `c_api.h` are core C ABI types. This commit adds Doxygen-mode guards and per-member doc comments to them without changing their layout.
- **Sphinx/Exhale/Breathe documentation pipeline** (`docs/conf.py`): The existing Exhale+Breathe integration that bridges Doxygen XML output into Sphinx. Extended here with additional predefined macros, warning configuration, and Sphinx C/C++ domain `id_attributes`.

Design elements this commit produces:
- **`TVM_FFI_DOXYGEN_MODE` preprocessor guard**: A convention for conditionally hiding C constructs (anonymous unions) that Doxygen cannot parse. Defined only in the Doxygen `PREDEFINED` list, never in real compilation. Future headers with similar Doxygen-incompatible patterns should use the same guard.

## Usage Examples
None -- this is a CI/documentation infrastructure change with no runtime API impact. Contributors benefit automatically: any future C++ doc comment error will cause CI to fail at the doc-build step.
