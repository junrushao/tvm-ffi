# Enable Doxygen build checks in CI to catch C++ doc errors
## TL;DR
- Enables `BUILD_CPP_DOCS=1` in the CI docs job and installs Doxygen, so C++ API docs are built and validated on every PR.
- Configures Doxygen `WARN_AS_ERROR = FAIL_ON_WARNINGS_PRINT` to promote documentation warnings to CI failures.
- Wraps anonymous unions in `c_api.h` with `#if !defined(TVM_FFI_DOXYGEN_MODE)` guards and fixes stray/incorrect Doxygen comments across headers.

## Key Exports
N/A -- infrastructure.

## Impact
- API: None -- no compiled behavior changes. The `#if !defined(TVM_FFI_DOXYGEN_MODE)` guards in `c_api.h` are transparent to normal builds.
- Behavioral: Doxygen warnings in C++ headers now fail the CI docs build step.
- Flags/config: `BUILD_CPP_DOCS=1` environment variable is now set in `.github/workflows/ci_test.yml` docs job. New `TVM_FFI_DOXYGEN_MODE` macro defined only during Doxygen runs via `PREDEFINED` in `docs/conf.py`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- C ABI structs `TVMFFIObject` and `TVMFFIAny` (`include/tvm/ffi/c_api.h`) -- anonymous unions are wrapped with Doxygen guards. See `.knowledge/designs/0001-c-abi.md`.
- Sphinx/Exhale/Breathe documentation pipeline (`docs/conf.py`) -- extended with `cpp_id_attributes`, `c_id_attributes`, additional `PREDEFINED` macros, and `WARN_AS_ERROR`.
- Preprocessor macros `TVM_FFI_DLL`, `TVM_FFI_DLL_EXPORT`, `TVM_FFI_INLINE`, `TVM_FFI_EXTRA_CXX_API`, `TVM_FFI_WEAK` -- registered as Sphinx C/C++ identity attributes.

Design elements this commit produces:
- `TVM_FFI_DOXYGEN_MODE` preprocessor guard -- a new convention for hiding C constructs (anonymous unions) that Doxygen cannot parse. Defined only in Doxygen's `PREDEFINED` list, never in production builds.
- CI Doxygen validation invariant -- all C++ Doxygen comments must be warning-free (enforced by `WARN_AS_ERROR`).
