# Enable Doxygen build checks in CI and fix Doxygen compatibility across C++ headers

## TL;DR
- CI now installs Doxygen and runs `BUILD_CPP_DOCS=1 sphinx-build` so that Doxygen warnings become build failures (`WARN_AS_ERROR = FAIL_ON_WARNINGS_PRINT`).
- `docs/conf.py` adds missing macro names to `PREDEFINED` (`TVM_FFI_DLL_EXPORT`, `TVM_FFI_WEAK`, `TVM_FFI_DOXYGEN_MODE`) and registers all visibility macros as Sphinx `cpp_id_attributes`/`c_id_attributes` so they are ignored during cross-reference resolution.
- Five C++ headers receive purely cosmetic Doxygen compatibility fixes: anonymous unions in `TVMFFIObject`/`TVMFFIAny` are guarded with `#if !defined(TVM_FFI_DOXYGEN_MODE)`, union fields gain `/*! \brief */` doc comments, and stale doc-comment tags are removed.

## Impact
- API: none — `#if !defined(TVM_FFI_DOXYGEN_MODE)` guards are compile-time no-ops for all non-Doxygen builds; the C ABI struct layouts are unchanged.
- Behavioral: none — no runtime logic is touched.
- Flags/config: `BUILD_CPP_DOCS=1` environment variable now required to trigger Doxygen build; CI sets it unconditionally on the doc build job. `WARN_AS_ERROR = FAIL_ON_WARNINGS_PRINT` in `exhaleDoxygenStdin` makes any Doxygen warning a CI failure.
- Data formats/schemas: none.
