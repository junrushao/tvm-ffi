# Misc Windows compatibility fixups: CMake modernization, Tuple SFINAE fix, ASCII comment cleanup
## TL;DR
- Modernize GoogleTest CMake integration: replace `FetchContent_Populate` + manual `add_subdirectory` with `FetchContent_MakeAvailable`, and remove hardcoded `MSVC_RUNTIME_LIBRARY` property that conflicted with project-level CRT settings.
- Fix Tuple variadic constructor SFINAE guard: change `std::remove_cv_t` to `std::decay_t` so array-to-pointer and function-to-pointer decay is handled correctly on MSVC.
- Replace non-ASCII en-dash characters in json_parser.cc comments with ASCII hyphens to avoid MSVC encoding warnings.

## Impact
- API: none
- Behavioral: The `std::remove_cv_t` to `std::decay_t` change in `Tuple`'s variadic constructor SFINAE could affect overload resolution in edge cases where arguments are arrays or function types, but this is unlikely in practice; the intent is to match `std::decay_t` semantics which is the standard pattern for forwarding constructors.
- Flags/config: Removal of `MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>"` means the test target now inherits the project-level CRT linkage setting instead of forcing static CRT.
- Data formats/schemas: none
