# Windows build compatibility fixups: CMake modernization, MSVC type trait fix, and encoding cleanup
## TL;DR
- Replace deprecated `FetchContent_Populate` + manual `add_subdirectory` with `FetchContent_MakeAvailable` in GoogleTest setup.
- Fix MSVC Tuple variadic constructor SFINAE guard by switching `std::remove_cv_t` to `std::decay_t`, preventing the constructor from shadowing copy/move constructors on MSVC.
- Replace en-dash (`U+2013`) characters with ASCII hyphens in `json_parser.cc` comments to avoid MSVC encoding warnings.
- Remove `MSVC_RUNTIME_LIBRARY` property and change test binary output to `lib/` directory.

## Key Exports
None

## Impact
- API: none
- Behavioral: On MSVC, `Tuple<T>` single-element construction previously could match copy/move argument types via the variadic constructor (because `std::remove_cv_t` doesn't strip references). After this fix, `std::decay_t` correctly strips both cv-qualifiers and references, so the SFINAE guard properly excludes `Tuple<T>` arguments and routes them to copy/move constructors.
- Flags/config: Removed `MSVC_RUNTIME_LIBRARY "MultiThreaded$<$<CONFIG:Debug>:Debug>"` from test target; MSVC runtime library selection now uses CMake default.
- Data formats/schemas: none
