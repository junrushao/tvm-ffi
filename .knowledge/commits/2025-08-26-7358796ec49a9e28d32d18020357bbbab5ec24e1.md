# Misc fixups for Windows compatibility in CMake, Tuple SFINAE, JSON parser, and test build

## TL;DR
- Replaces the manual `FetchContent_Populate` + `add_subdirectory` pattern with `FetchContent_MakeAvailable` for GoogleTest fetching in `cmake/Utils/AddGoogleTest.cmake`, which is the modern idiomatic CMake approach and avoids issues on Windows.
- Fixes a SFINAE guard in `Tuple`'s variadic constructor: changes `std::remove_cv_t<UTypes>` to `std::decay_t<UTypes>` so that reference types (e.g., `Tuple<int>&`) are correctly stripped when checking whether the constructor should be disabled to avoid hijacking the copy/move constructors. This matters on MSVC where template instantiation behavior can differ.
- Replaces en-dash characters (`\xe2\x80\x93`) in comments in `json_parser.cc` with ASCII hyphens (`-`), fixing potential encoding issues on Windows toolchains that do not handle UTF-8 source files well.
- Removes the `MSVC_RUNTIME_LIBRARY` property from the test executable target and changes the runtime output directory from `bin/` to `lib/`, aligning test binary placement with the library output directory. The MSVC runtime library setting removal avoids conflicts when the parent project sets a different runtime library policy.

## Key Exports
None. This commit contains no API additions or removals.

## Impact
- **API**: None -- no public API changes.
- **ABI**: None -- no struct layout, symbol, or calling convention changes.
- **Behavioral**: The `Tuple` variadic constructor SFINAE guard is now slightly broader: `std::decay_t` strips both cv-qualifiers and reference qualifiers (and decays arrays/functions to pointers), whereas `std::remove_cv_t` only strips cv-qualifiers. In practice this only matters when `UTypes` is deduced as a reference type (e.g., `Tuple<T>&`), which is exactly the case that matters for disambiguating from the copy constructor on MSVC.
- **Build**: GoogleTest fetching is simplified. Test binary output moves from `bin/` to `lib/`. `MSVC_RUNTIME_LIBRARY` is no longer explicitly set on the test target, deferring to CMake's default or the parent project's policy.

Design elements this commit **mutates**:

- **Tuple SFINAE guard**: The copy/move constructor disambiguation check now uses `std::decay_t` instead of `std::remove_cv_t`, making it robust against reference-qualified template arguments.
