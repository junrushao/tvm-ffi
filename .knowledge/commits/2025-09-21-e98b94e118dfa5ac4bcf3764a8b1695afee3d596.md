# Introduce experimental `@c_class` decorator for Python dataclass-style FFI proxies
## TL;DR
- Adds `tvm_ffi.dataclasses` sub-package with `c_class` decorator and `field`/`Field` helpers, enabling Python dataclass-style syntax for defining proxies over C++ FFI objects.
- Establishes `__ffi_init__` as the standard C++ constructor method name (registered via `def_static`) and `Object.__ffi_init__` as the Python dispatch entry point, replacing direct `__init_handle_by_constructor__` calls.
- Adds three test C++ classes with inheritance (`TestCxxClassBase` -> `TestCxxClassDerived` -> `TestCxxClassDerivedDerived`) demonstrating field inheritance, default values, and `c_class` decorator usage.

## Key Exports

**`c_class(type_key: str, init: bool = True) -> Callable[[type], type]`** (`python/tvm_ffi/dataclasses/c_class.py`):
Decorator that binds a Python class to a C++ type registered in the FFI reflection registry. Reads `TypeInfo` fields, validates that Python annotations match C++ field names, creates properties for each field, and optionally synthesizes `__init__`. Decorated with `@dataclass_transform(field_specifiers=(field, Field))` for type checker integration.

**`Field`** (`python/tvm_ffi/dataclasses/field.py`):
```python
@dataclass(kw_only=True)
class Field:
    name: str | None = None
    default_factory: Callable[[], Any]
```

**`field(*, default=MISSING, default_factory=MISSING) -> Field`** (`python/tvm_ffi/dataclasses/field.py`):
Factory function mirroring `dataclasses.field`. Exactly one of `default` or `default_factory` may be provided. `default` is wrapped into a `default_factory` closure internally.

**`Object.__ffi_init__(self, *args) -> None`** (`python/tvm_ffi/cython/object.pxi`):
New Cython method on `Object` base class. Dispatches to `type(self).__c_ffi_init__` via `__init_handle_by_constructor__`.

**`TypeField.dataclass_field: object | None`** (`python/tvm_ffi/cython/type_info.pxi`):
New field on `TypeField` (default `None`), set by `c_class` to store the associated `Field` descriptor for `__init__` generation.

**Internal helpers** (`python/tvm_ffi/dataclasses/_utils.py`):
- `get_parent_type_info(type_cls) -> TypeInfo` -- walks `__bases__` for `__tvm_ffi_type_info__`
- `type_info_to_cls(type_info, cls, methods) -> type` -- creates new class with `Object` base, field properties, and methods
- `fill_dataclass_field(type_cls, type_field) -> None` -- resolves RHS annotation to `Field` descriptor
- `method_init(type_cls, type_info) -> Callable` -- synthesizes `__init__` with proper signature, default handling, and `__post_init__` support

**`__ffi_init__` -> `__c_ffi_init__` renaming** (`python/tvm_ffi/registry.py`):
When `_add_class_attrs` encounters a method named `__ffi_init__`, it renames it to `__c_ffi_init__` on the class. This prevents collision with `Object.__ffi_init__` (the dispatch method) and makes the raw C++ constructor available as `cls.__c_ffi_init__`.

## Impact
- API: Adds new public API `tvm_ffi.dataclasses.{c_class, field, Field, MISSING}`. No existing APIs broken.
- Behavioral: `TestIntPair.__init__` now uses `self.__ffi_init__()` instead of `self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, ...)` -- functionally identical.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection system** ([`.knowledge/designs/0009-reflection.md`](../designs/0009-reflection.md)): `ObjectDef<T>`, `def_rw`, `def_static`, `refl::init<T, Args...>`, `TypeInfo`, `TypeField`, `ForEachFieldInfo` (via `type_info.fields` traversal in Python)
- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `Object`, `ObjectRef`, `make_object<T>`, `_type_mutable`, `TVM_FFI_DECLARE_OBJECT_INFO`
- **Python package** ([`.knowledge/designs/0014-python-package.md`](../designs/0014-python-package.md)): `Object.__init_handle_by_constructor__`, `register_object`, `_add_class_attrs`, `TypeInfo.type_cls`

Design elements this commit produces:
- **`c_class` decorator** -- new Python-side pattern for declaring FFI type proxies with dataclass syntax. Alternative to `@register_object` + manual `__init__`.
- **`__ffi_init__` protocol** -- convention where C++ types register `def_static("__ffi_init__", refl::init<T, Args...>)` and Python's `Object.__ffi_init__` dispatches through `type(self).__c_ffi_init__`.
- **`Field` descriptor** -- dataclass-field-like metadata attached to `TypeField.dataclass_field` for default value handling.

## Usage Examples

**End-to-end: C++ type definition -> Python `c_class` proxy with inheritance and defaults**

C++ side (`src/ffi/extra/testing.cc`):
```cpp
class TestCxxClassDerived : public TestCxxClassBase {
 public:
  double v_f64;
  float v_f32;
  TestCxxClassDerived(int64_t v_i64, int32_t v_i32, double v_f64, float v_f32)
      : TestCxxClassBase(v_i64, v_i32), v_f64(v_f64), v_f32(v_f32) {}
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestCxxClassDerived", TestCxxClassDerived, TestCxxClassBase);
};
TVM_FFI_STATIC_INIT_BLOCK() {
  refl::ObjectDef<TestCxxClassDerived>()
      .def_static("__ffi_init__", refl::init<TestCxxClassDerived, int64_t, int32_t, double, float>)
      .def_rw("v_f64", &TestCxxClassDerived::v_f64)
      .def_rw("v_f32", &TestCxxClassDerived::v_f32);
}
```

Python side (`python/tvm_ffi/testing.py`):
```python
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxClassDerived")
class _TestCxxClassDerived(_TestCxxClassBase):
    v_f64: float
    v_f32: float = 8  # literal default wrapped into Field automatically

obj = _TestCxxClassDerived(v_i64=123, v_i32=456, v_f64=4.0)
assert obj.v_f32 == 8.0  # default applied
```

**Custom `__init__` with `__ffi_init__` dispatch:**
```python
@c_class("testing.TestCxxClassBase")
class _TestCxxClassBase:
    v_i64: int
    v_i32: int

    def __init__(self, v_i64: int, v_i32: int) -> None:
        self.__ffi_init__(v_i64 + 1, v_i32 + 2)  # transform args before C++ construction
```
