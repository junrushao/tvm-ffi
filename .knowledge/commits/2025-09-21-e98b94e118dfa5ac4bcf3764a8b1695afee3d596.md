# Introduce experimental `@c_class` decorator for dataclass-style Python proxies of C++ FFI types

## TL;DR
- Adds `tvm_ffi.dataclasses` package with `@c_class(type_key)` decorator and `field()` helper, enabling Python dataclass-like syntax for C++ FFI-backed objects with auto-generated `__init__`, inherited field reflection, and default values.
- Adds `Object.__ffi_init__(*args)` Cython method that delegates to the C++ constructor registered via `ObjectDef.def_static("__ffi_init__", ...)`, bridging the Python dataclass pattern to C++ construction.
- Renames the `__ffi_init__` method to `__c_ffi_init__` when attaching to the class (both in `registry.py` and `_utils.py`), so that `__ffi_init__` on the Python side calls `__c_ffi_init__` on the underlying object via `__init_handle_by_constructor__`.

## Impact
- API: New public `tvm_ffi.dataclasses` module with `c_class`, `field`, `Field`, `MISSING` exports. New `Object.__ffi_init__` method on all Object instances.
- Behavioral: `__ffi_init__` registered methods are now stored as `__c_ffi_init__` on Python classes (both via `@register_object` and `@c_class`). The user-facing `__ffi_init__` method on Object delegates to `__c_ffi_init__` via `__init_handle_by_constructor__`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection system** (0008): Uses `TypeInfo`, `TypeField`, `ObjectDef<T>.def_static("__ffi_init__", ...)`, `ObjectDef<T>.def_rw()` to retrieve C++ field metadata for Python class generation.
- **Object system** (0002): Extends `Object` with `__ffi_init__` method; swaps `object` base to `Object` in generated classes.
- **Python bindings** (0012): Modifies `registry.py` `_add_class_attrs` to rename `__ffi_init__` -> `__c_ffi_init__`; uses `TypeInfo.methods` and `TypeField.as_property`.

Design elements this commit produces:
- **`tvm_ffi.dataclasses` subpackage**: New Python-side pattern for mirroring C++ reflected types with dataclass syntax. Comprises `c_class` decorator, `Field` descriptor, `field()` factory, and internal utilities (`_utils.py`).
- **`Object.__ffi_init__` protocol**: Convention where `__ffi_init__` on an Object calls `__c_ffi_init__` (the C++ constructor), providing a uniform Python-side construction entry point.
- **`__ffi_init__` -> `__c_ffi_init__` rename convention**: Internal naming split so that `__ffi_init__` is the user-facing Python method and `__c_ffi_init__` is the raw C++ constructor binding.

## Usage Examples

C++ registration paired with Python `@c_class` usage (from tests):
```cpp
// C++ side: register type with fields and constructor
TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<TestCxxClassBase>()
      .def_static("__ffi_init__", refl::init<TestCxxClassBase, int64_t, int32_t>)
      .def_rw("v_i64", &TestCxxClassBase::v_i64)
      .def_rw("v_i32", &TestCxxClassBase::v_i32);
}
```

```python
# Python side: mirror with @c_class
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxClassDerived")
class TestCxxClassDerived(TestCxxClassBase):
    v_f64: float
    v_f32: float = 8  # default value via literal

obj = TestCxxClassDerived(v_i64=123, v_i32=456, v_f64=4.0)
assert obj.v_f32 == 8.0  # default applied
obj.v_f64 = 3.14         # property forwards to C++ field
```
