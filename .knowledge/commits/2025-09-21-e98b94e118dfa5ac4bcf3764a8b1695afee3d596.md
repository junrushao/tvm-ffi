# Introduce experimental tvm_ffi.dataclasses.c_class decorator for Python-side FFI dataclasses

## TL;DR

- Adds new subpackage `tvm_ffi.dataclasses` with a `@c_class(type_key)` decorator that mirrors a C++ `ObjectDef<T>` registration as a Python dataclass-style proxy: fields become properties, an `__init__` is auto-generated from C++ reflection metadata.
- Adds `field(default=..., default_factory=...)` helper mirroring `dataclasses.field`, and `Field` descriptor type consumed by the decorator.
- Extends `Object.__ffi_init__` (Cython + stub) and `TypeField.dataclass_field` attribute to bridge the auto-generated `__init__` through to the C++ constructor; adds three test fixture C++ classes (`TestCxxClassBase/Derived/DerivedDerived`) and registers them via `ObjectDef`.

## Impact
- API: New public package `tvm_ffi.dataclasses` with `c_class`, `field`, `Field`, `MISSING`. New method `Object.__ffi_init__(*args)` on all `Object` subclasses. New attribute `TypeField.dataclass_field`. In `registry.py`, the method name `__ffi_init__` is now remapped to `__c_ffi_init__` when installing reflected methods via `_add_class_attrs`.
- Behavioral: `TestIntPair.__init__` in `testing.py` migrated from `__init_handle_by_constructor__` call to `self.__ffi_init__(a, b)` — functionally equivalent but uses new bridge.
- Flags/config: none
- Data formats/schemas: `TypeField` gains a `dataclass_field` slot (default `None`); backward-compatible since existing code does not read it.

## Usage Examples

End-to-end C++ → Python trace for `c_class` with inheritance:

```c++
// 1. C++ side: src/ffi/extra/testing.cc
// Register the class hierarchy
TVM_FFI_STATIC_INIT_BLOCK() {
    namespace refl = tvm::ffi::reflection;
    refl::ObjectDef<TestCxxClassBase>()
        .def_static("__ffi_init__", refl::init<TestCxxClassBase, int64_t, int32_t>)
        .def_rw("v_i64", &TestCxxClassBase::v_i64)
        .def_rw("v_i32", &TestCxxClassBase::v_i32);

    refl::ObjectDef<TestCxxClassDerived>()
        .def_static("__ffi_init__", refl::init<TestCxxClassDerived, int64_t, int32_t, double, float>)
        .def_rw("v_f64", &TestCxxClassDerived::v_f64)
        .def_rw("v_f32", &TestCxxClassDerived::v_f32);
}
```

```python
# 2. Python side: python/tvm_ffi/testing.py
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxClassBase")
class _TestCxxClassBase:
    v_i64: int
    v_i32: int
    def __init__(self, v_i64: int, v_i32: int) -> None:
        self.__ffi_init__(v_i64 + 1, v_i32 + 2)   # custom init, delegates to C++

@c_class("testing.TestCxxClassDerived")
class _TestCxxClassDerived(_TestCxxClassBase):
    v_f64: float
    v_f32: float = 8   # default value — no explicit __init__ needed, auto-generated

# 3. Usage
obj = _TestCxxClassDerived(v_i64=123, v_i32=456, v_f64=4.0)
assert obj.v_f32 == 8.0        # default applied
obj.v_f64 = 3.14               # setter forwards to C++
```
