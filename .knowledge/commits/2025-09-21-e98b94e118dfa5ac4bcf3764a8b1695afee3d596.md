# Introduce experimental `@c_class` decorator for Python dataclass-style C++ object proxies

## TL;DR
- Adds `tvm_ffi.dataclasses` subpackage with `@c_class` decorator, `field()`/`Field`, and `_utils` module that lets Python mirror C++ reflection-registered types using dataclass-style syntax (annotated fields become properties forwarding to C++ objects, `__init__` is auto-generated).
- Introduces `Object.__ffi_init__()` on the Cython base class as the canonical way to call C++ constructors, replacing direct `__init_handle_by_constructor__` usage. The C++ `__ffi_init__` method is renamed to `__c_ffi_init__` on the Python class to avoid name collision.
- Adds `TypeField.dataclass_field` attribute to hold Python-side default metadata, and three test C++ classes (`TestCxxClassBase`, `TestCxxClassDerived`, `TestCxxClassDerivedDerived`) demonstrating single and multi-level inheritance.

## Impact
- API: New public subpackage `tvm_ffi.dataclasses` with `c_class`, `field`, `Field`. New `Object.__ffi_init__()` method. `TypeField` gains `dataclass_field` attribute. The `__ffi_init__` method registered from C++ is now exposed as `__c_ffi_init__` on Python classes (via `registry.py` rename).
- Behavioral: `TestIntPair.__init__` changed from `__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)` to `self.__ffi_init__(a, b)`, switching to the new canonical constructor path.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`ObjectDef<T>`, `def_rw`, `def_static`, `TypeInfo`, `TypeField`) -- [0007-ffi-reflection](../design-records/0007-ffi-reflection.md). The `c_class` decorator reads `TypeInfo.fields` and `TypeInfo.methods` populated by C++ `ObjectDef<T>` registration.
- **Object base class** (`Object`, `__init_handle_by_constructor__`) -- [0012-ffi-python-package](../design-records/0012-ffi-python-package.md). The new `__ffi_init__` method delegates to the existing `__init_handle_by_constructor__`.
- **`register_object` pattern** (`_add_class_attrs`) -- [0012-ffi-python-package](../design-records/0012-ffi-python-package.md). The `__ffi_init__` -> `__c_ffi_init__` rename is added to the existing `_add_class_attrs` function in `registry.py`.
- **`refl::init<T, Args...>`** helper -- used in C++ test registration to create factory constructors.

Design elements this commit produces:
- **`@c_class` decorator** -- new Python-side protocol for dataclass-style C++ object proxies. Validates field correspondence between Python annotations and C++ reflection, generates `__init__`, injects properties.
- **`field()`/`Field`** -- default-value descriptors for `c_class` fields, mirroring `dataclasses.field()` semantics.
- **`Object.__ffi_init__()`** -- canonical Python method for invoking C++ constructors through reflection, replacing direct `__init_handle_by_constructor__` usage.
- **`__ffi_init__` -> `__c_ffi_init__` rename convention** -- C++ methods named `__ffi_init__` are renamed to `__c_ffi_init__` on the Python class to avoid collision with the new `Object.__ffi_init__()` instance method.
- **`TypeField.dataclass_field`** -- new attribute bridging C++ field metadata to Python default-value descriptors.

## Usage Examples

C++ side registers a type with fields and constructor:
```cpp
TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<TestCxxClassBase>()
      .def_static("__ffi_init__", refl::init<TestCxxClassBase, int64_t, int32_t>)
      .def_rw("v_i64", &TestCxxClassBase::v_i64)
      .def_rw("v_i32", &TestCxxClassBase::v_i32);
}
```

Python mirrors the structure with `@c_class`:
```python
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxClassBase")
class TestCxxClassBase:
    v_i64: int
    v_i32: int

@c_class("testing.TestCxxClassDerived")
class TestCxxClassDerived(TestCxxClassBase):
    v_f64: float
    v_f32: float = 8  # default value via literal

obj = TestCxxClassDerived(v_i64=1, v_i32=2, v_f64=3.0)
assert obj.v_f32 == 8.0  # default applied
obj.v_f64 = 9.0           # property setter forwards to C++
```

Custom `__init__` with argument transformation:
```python
@c_class("testing.TestCxxClassBase")
class TestCxxClassBase:
    v_i64: int
    v_i32: int

    def __init__(self, v_i64: int, v_i32: int) -> None:
        self.__ffi_init__(v_i64 + 1, v_i32 + 2)  # transform before C++ init
```
