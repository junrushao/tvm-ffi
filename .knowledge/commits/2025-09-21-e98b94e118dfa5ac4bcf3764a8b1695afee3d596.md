# Introduce experimental tvm_ffi.dataclasses.c_class decorator
## TL;DR
- Adds the `tvm_ffi.dataclasses` package with `c_class` decorator, `field` helper, and `_utils` module, enabling Python dataclass-style syntax for declaring C++ FFI-backed types with annotated fields, defaults, and auto-generated `__init__`.
- `@c_class("type.key")` reads C++ reflection metadata (`TypeInfo`), matches Python annotations against C++ fields, synthesizes an `__init__` that calls the C++ constructor, and installs properties forwarding to the C++ object.
- `field(default=..., default_factory=...)` mirrors `dataclasses.field` semantics for declaring per-field defaults.
- Extends the C++ testing types in `src/ffi/extra/testing.cc` with base/child class examples exercising the decorator.

## Impact
- API: New public module `tvm_ffi.dataclasses` with `c_class`, `field`, `Field` exports. This is a new user-facing API for declaring Python proxies of C++ FFI types.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection** (`.knowledge/designs/0006-reflection.md`): `TypeInfo`, `TypeField`, `TypeMethod` from `type_info.pxi` (introduced in commit `53b2e00`). `_lookup_type_info_from_type_key` for lazy metadata creation.
- **Python Bindings** (`.knowledge/designs/0014-python-bindings.md`): `register_object` pattern, `Object` base class, `__init_handle_by_constructor__`.
- **Object System** (`.knowledge/designs/0003-object-system.md`): `ObjectDef<T>().def_static("__init__", ...)` registration of constructors in C++.

Design elements this commit produces:
- **`c_class` decorator**: The primary decorator that bridges Python annotations with C++ reflection metadata. Key invariants: (1) every Python annotation must match a C++ field (and vice versa), (2) `__init__` is auto-generated only if not already defined, (3) inheritance chains are resolved via `parent_type_info`.
- **`field` / `Field` descriptors**: Placeholder objects consumed by `c_class` during class registration to express per-field defaults. Mirrors `dataclasses.field` API.
- **`_utils` module**: Internal helpers for `method_init` (synthesizes `__init__`), `type_info_to_cls` (applies properties/methods to a class), `fill_dataclass_field` (merges Python defaults into `TypeField`), `get_parent_type_info` (resolves inheritance).
