# Introduce experimental `tvm_ffi.dataclasses.c_class` decorator for Python dataclass-style C++ object proxying

## TL;DR
- Adds a new `tvm_ffi.dataclasses` subpackage with `c_class` decorator and `field`/`Field` helpers that let users define Python classes with dataclass-style annotations that bind to C++ types registered via `ObjectDef`.
- Introduces `Object.__ffi_init__(*args)` on the Cython Object base class, which delegates to `type(self).__c_ffi_init__` (the reflected `__ffi_init__` static method), simplifying constructor invocation from Python.
- Adds `TypeField.dataclass_field` attribute to carry the `Field` descriptor for `c_class`-decorated types, and three C++ test classes (`TestCxxClassBase`, `TestCxxClassDerived`, `TestCxxClassDerivedDerived`) with a three-level inheritance hierarchy for end-to-end testing.

## Key Exports

**Decorator**:
- `c_class(type_key: str, init: bool = True) -> Callable[[type], type]` -- Decorated with `@dataclass_transform`. Reads reflection metadata from the C++ registry, validates Python annotations match C++ fields, synthesizes `__init__` (when `init=True` and class does not define its own), and creates a new class inheriting from `Object`.

**Classes**:
- `Field` (`@dataclass(kw_only=True)`): `name: str | None`, `default_factory: Callable[[], Any]`. Placeholder descriptor consumed by `c_class`.
- `TypeField.dataclass_field: object | None = None` -- New attribute on the existing `TypeField` dataclass in `type_info.pxi`.

**Functions**:
- `field(*, default=MISSING, default_factory=MISSING) -> Field` -- Public factory for `Field`, mirrors `dataclasses.field` semantics.
- `Object.__ffi_init__(self, *args) -> None` -- Cython method on base `Object` class; calls `self.__init_handle_by_constructor__(type(self).__c_ffi_init__, *args)`.

**Internal utilities** (`_utils.py`):
- `get_parent_type_info(type_cls) -> TypeInfo` -- Walks `__bases__` for `__tvm_ffi_type_info__`.
- `type_info_to_cls(type_info, cls, methods) -> type` -- Creates new class with fields as properties, methods attached, bases adjusted to `Object` if needed.
- `fill_dataclass_field(type_cls, type_field) -> None` -- Maps class-body RHS to `Field` descriptor on `TypeField.dataclass_field`.
- `method_init(type_cls, type_info) -> Callable` -- Generates `__init__` with Python `inspect.Signature` built from reflected fields; supports defaults via `DefaultFactory` wrapper; calls `__ffi_init__`; invokes `__post_init__` if present.
- `_inspect_c_class_fields(type_cls, type_info) -> list[TypeField]` -- Validates that Python annotations match C++ fields exactly (no extraneous, no missing); filters `ClassVar`, `InitVar`, and `__tvm_ffi` prefixed names.

**C++ test classes** (in `src/ffi/extra/testing.cc`):
- `TestCxxClassBase(Object)`: `v_i64: int64_t`, `v_i32: int32_t`. Inheritable (`TVM_FFI_DECLARE_OBJECT_INFO`).
- `TestCxxClassDerived(TestCxxClassBase)`: adds `v_f64: double`, `v_f32: float`.
- `TestCxxClassDerivedDerived(TestCxxClassDerived)`: adds `v_str: String`, `v_bool: bool`.
All registered with `__ffi_init__` via `refl::init<>` and `def_rw` fields.

**Name mapping convention**: C++ reflection method `__ffi_init__` is renamed to `__c_ffi_init__` as a class attribute in both `_utils.type_info_to_cls` and `registry._add_class_attrs`. The `Object.__ffi_init__` instance method dispatches to `type(self).__c_ffi_init__` via `__init_handle_by_constructor__`.

## Impact
- API: New public `tvm_ffi.dataclasses` subpackage (`c_class`, `field`, `Field`, `MISSING`). New `Object.__ffi_init__` method. New `TypeField.dataclass_field` attribute.
- ABI: none -- no C ABI struct changes.
- Behavioral: `register_object` now renames reflected `__ffi_init__` methods to `__c_ffi_init__` on the class, consistent with `c_class` behavior. Existing `TestIntPair.__init__` changed from `self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)` to `self.__ffi_init__(a, b)`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/reflection.md`): `ObjectDef<Class>`, `def_static("__ffi_init__", ...)`, `def_rw`, `refl::init<>` template, `TypeInfo`, `TypeField`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`.
- **Object system** (`.knowledge/designs/object-system.md`): `Object` base class, `_type_mutable`, `TVM_FFI_DECLARE_OBJECT_INFO` macro, dual-class pattern, `make_object<T>()`.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): `_add_class_attrs_by_reflection`, `__init_handle_by_constructor__`, `_lookup_type_info_from_type_key`, `OBJECT_TYPE` registry, `register_object` decorator.

Design elements this commit produces:
- **`c_class` decorator protocol**: A Python-side `@c_class(type_key)` decorator that bridges Python dataclass syntax to C++ reflection metadata. Validates that Python type annotations match C++ reflected fields (no extraneous, no missing). Supports `ClassVar`/`InitVar` filtering.
- **`__ffi_init__` calling convention**: A two-part protocol: (1) C++ side registers a static method named `"__ffi_init__"` via `ObjectDef::def_static`, (2) Python side renames it to `__c_ffi_init__` on the class, and the base `Object.__ffi_init__` dispatches through `type(self).__c_ffi_init__`.
- **`Field` descriptor system**: A `dataclasses.field`-compatible system (`Field` class + `field()` factory) that integrates with `TypeField.dataclass_field` to provide default values and default factories for synthesized `__init__` methods.
- **Generated `__init__` with `inspect.Signature`**: `method_init` builds a proper Python `inspect.Signature` from reflected fields, ordering parameters so those without defaults come first. Supports `DefaultFactory` wrapper for lazy evaluation, and calls `__post_init__` if defined.

## Usage Examples

### Defining a C++ type with `c_class` (end-to-end)
**Context**: Register a C++ class with reflection, then mirror it in Python with dataclass syntax.

```cpp
// C++ side: src/ffi/extra/testing.cc
class TestCxxClassDerived : public TestCxxClassBase {
 public:
  double v_f64;
  float v_f32;
  TestCxxClassDerived(int64_t v_i64, int32_t v_i32, double v_f64, float v_f32)
      : TestCxxClassBase(v_i64, v_i32), v_f64(v_f64), v_f32(v_f32) {}
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestCxxClassDerived", TestCxxClassDerived, TestCxxClassBase);
};
// Registration:
refl::ObjectDef<TestCxxClassDerived>()
    .def_static("__ffi_init__", refl::init<TestCxxClassDerived, int64_t, int32_t, double, float>)
    .def_rw("v_f64", &TestCxxClassDerived::v_f64)
    .def_rw("v_f32", &TestCxxClassDerived::v_f32);
```

```python
# Python side: python/tvm_ffi/testing.py
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxClassDerived")
class _TestCxxClassDerived(_TestCxxClassBase):
    v_f64: float
    v_f32: float = 8  # default value

# Usage:
obj = _TestCxxClassDerived(v_i64=123, v_i32=456, v_f64=4.0)
assert obj.v_f64 == 4.0
assert obj.v_f32 == 8.0  # default applied
```

### Using `__ffi_init__` directly (without `c_class`)
**Context**: Simplifying constructor calls in `register_object`-decorated classes.
```python
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    def __init__(self, a: int, b: int) -> None:
        self.__ffi_init__(a, b)  # was: self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)
```
