# Introduce experimental `tvm_ffi.dataclasses.c_class` decorator for Python dataclass-style C++ FFI proxies

## TL;DR
- Adds a new `tvm_ffi.dataclasses` package with `@c_class` decorator, `Field` descriptor, and `field()` helper that mirrors Python `dataclasses` syntax for C++ FFI-registered types.
- Introduces `Object.__ffi_init__()` on the Cython Object class as a unified constructor bridge, replacing direct `__init_handle_by_constructor__` calls for reflected types.
- Adds `TypeField.dataclass_field` attribute to link reflection metadata to Python-side default value descriptors.

## Key Exports

```python
# === tvm_ffi.dataclasses (new package) ===

@dataclass_transform(field_specifiers=(field, Field))
def c_class(type_key: str, init: bool = True) -> Callable[[type], type]:
    """Decorator that binds a Python class to a C++ FFI-registered type using reflection metadata.
    Reads TypeInfo/TypeField from the C++ registry, creates properties for each field,
    and synthesizes an __init__ method that calls the C++ constructor."""
    # Interacts with: _lookup_type_info_from_type_key (Cython core), TypeInfo, TypeField
    # Interacts with: register_object protocol (same OBJECT_TYPE registry)
    # Invariant: type_key must match a C++ type registered via ObjectDef<T>
    # Invariant: Python annotations must exactly match C++ reflected fields (no extra, no missing)
    # Extension: set init=False to provide a custom __init__; __post_init__ is called if defined

class Field:
    """Descriptor placeholder for dataclass-style defaults on c_class fields."""
    name: str | None = None
    default_factory: Callable[[], Any]  # MISSING if no default
    # Interacts with: c_class decorator (consumes Field during class creation)
    # Interacts with: method_init (reads default_factory for signature generation)

def field(*, default: Any = MISSING, default_factory: Any = MISSING) -> Field:
    """Declare a field with optional default/default_factory, mirroring dataclasses.field."""
    # Invariant: cannot specify both default and default_factory
    # Interacts with: c_class decorator

# === Object.__ffi_init__ (new Cython method on Object base class) ===

class Object:
    def __ffi_init__(self, *args: Any) -> None:
        """Initialize instance using the C++-side __init__ method registered via ObjectDef.
        Delegates to __init_handle_by_constructor__(type(self).__c_ffi_init__, *args)."""
        # Interacts with: __c_ffi_init__ (renamed from __ffi_init__ in registry._add_class_attrs)
        # Interacts with: __init_handle_by_constructor__ (existing Cython handle init)

# === TypeField.dataclass_field (new attribute) ===

class TypeField:
    dataclass_field: Field | None = None  # populated by c_class decorator
    # Interacts with: method_init (reads default_factory from dataclass_field)

# === __ffi_init__ -> __c_ffi_init__ renaming convention ===
# In registry._add_class_attrs, reflected methods named "__ffi_init__" are stored
# as "__c_ffi_init__" on the Python class, reserving "__ffi_init__" for the
# Object base class method that handles the constructor dispatch.
# Interacts with: Object.__ffi_init__ (looks up type(self).__c_ffi_init__)
```

## Impact
- API: New public API (`tvm_ffi.dataclasses.c_class`, `field`, `Field`). Existing `register_object` classes are unaffected. `TestIntPair.__init__` now uses `self.__ffi_init__()` instead of direct `__init_handle_by_constructor__`.
- Behavioral: Reflected methods named `__ffi_init__` are now renamed to `__c_ffi_init__` when attached to Python classes by `registry._add_class_attrs`. This enables `Object.__ffi_init__` to serve as the unified constructor bridge.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Reflection system** ([0008-reflection](../designs/0008-reflection.md)): `TypeInfo`, `TypeField`, `ObjectDef<T>.def_static("__ffi_init__", ...)`, `ObjectDef<T>.def_rw()`, `refl::init<T, Args...>` helper.
- **Object system** ([0002-object-system](../designs/0002-object-system.md)): `Object` base class, `__init_handle_by_constructor__`, `ObjectRef`, `make_object<T>`.
- **Python bindings** ([0012-python-bindings](../designs/0012-python-bindings.md)): `register_object`, `_add_class_attrs`, `OBJECT_TYPE` registry, `_lookup_type_info_from_type_key`.

Design elements this commit produces:
- **`c_class` decorator protocol**: A new pattern for defining Python proxies of C++ types using dataclass syntax. Convention: annotate fields in order, use `field()` for defaults, C++ side registers `__ffi_init__` as the constructor via `ObjectDef.def_static`.
- **`Object.__ffi_init__` constructor bridge**: Unified method on all Object subclasses that dispatches to the type-specific `__c_ffi_init__` function. Replaces direct `__init_handle_by_constructor__` calls.
- **`__ffi_init__` -> `__c_ffi_init__` naming convention**: Registry-level renaming that separates the user-facing constructor method (`__ffi_init__`) from the C++-registered implementation (`__c_ffi_init__`).
- **`TypeField.dataclass_field` bridge**: Links C++ reflection field metadata to Python-side default value descriptors.

## Usage Examples

C++ side registers a type with reflection and a constructor:

```cpp
TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<TestCxxClassBase>()
      .def_static("__ffi_init__", refl::init<TestCxxClassBase, int64_t, int32_t>)
      .def_rw("v_i64", &TestCxxClassBase::v_i64)
      .def_rw("v_i32", &TestCxxClassBase::v_i32);
}
```

Python side mirrors with `@c_class` and dataclass-style annotations:

```python
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxClassBase")
class TestCxxClassBase:
    v_i64: int
    v_i32: int

@c_class("testing.TestCxxClassDerived")
class TestCxxClassDerived(TestCxxClassBase):
    v_f64: float
    v_f32: float = 8  # literal default -> field(default=8)

obj = TestCxxClassDerived(v_i64=1, v_i32=2, v_f64=3.0)
assert obj.v_f32 == 8.0  # default applied
obj.v_f64 = 9.9  # property setter forwards to C++ field
```
