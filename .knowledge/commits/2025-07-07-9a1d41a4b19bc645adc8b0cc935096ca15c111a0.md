# Revert enhanced for_each overload resolution, restore Arg2Str for function signature stringification
## TL;DR
- Reverts commit `5a4038f` ("[FFI] Replace `Arg2Str` with a more powerful `for_each`"), which had added three-way overload resolution to `details::for_each` (accepting `F(integral_constant<size_t, I>, Arg)`, `F(size_t, Arg)`, or `F(Arg)`) and used it to replace the `Arg2Str` helper in `FuncFunctorImpl::Sig()`.
- Restores the original `Arg2Str<ArgType>` struct in `function_details.h` for generating human-readable function signature strings, and simplifies `for_each_dispatcher::run` back to the single-form `(f(I, std::forward<Args>(args)), ...)` fold expression introduced in `84cfbeb`.
- Removes `<type_traits>` include and the `always_false` variable template from `base_details.h` that were only needed by the reverted multi-dispatch logic.

## Impact
- API: none. Both `details::for_each` and `Arg2Str` are internal utilities in the `tvm::ffi::details` namespace. No public API changes.
- Flags/config: none.
- Data formats/schemas: none.

**Net effect on `for_each`**: After the three-commit sequence (`84cfbeb` simplify -> `5a4038f` enhance -> `9a1d41a` revert), `for_each` is left in the `84cfbeb` state: a single fold expression `(f(I, std::forward<Args>(args)), ...)` that requires callers to accept `(size_t, Arg)`. The `constexpr`-index and no-index overloads from `5a4038f` are removed.

## Design Elements

Design elements this commit **consumes**:
- **Function system / packed argument setup** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): `Arg2Str` is used exclusively inside `FuncFunctorImpl::Sig()` (`include/tvm/ffi/function_details.h`) to produce human-readable function signature strings (e.g., `"(0: int, 1: String) -> int"`) for error messages during argument mismatch diagnostics. The `Sig()` method is called by `unpack_call` and `unpack_call_by_signature` when argument types do not match, generating descriptive error messages.
- **`for_each` internal utility** ([`.knowledge/commits/2025-07-05-84cfbeb12bc5ef6d9eb434095949c205433c9e35.md`](2025-07-05-84cfbeb12bc5ef6d9eb434095949c205433c9e35.md)): The `details::for_each` fold-expression implementation from `84cfbeb` is preserved as-is by this revert. The enhanced three-way dispatch from `5a4038f` is removed.

Design elements this commit **produces**:
- None. This is a pure revert that restores the prior state. No new design elements are introduced.

**Revert rationale (inferred)**: The commit `5a4038f` attempted to make `for_each` more general by using `std::conjunction_v` + `std::is_invocable` to select among three overload forms at compile time. This introduced:
1. `<type_traits>` dependency in `base_details.h` (a low-level header included transitively by most FFI headers).
2. A `static_assert` with `always_false<F>` for non-invocable combinations.
3. SFINAE/constexpr-if complexity for a utility with exactly one callsite outside of `Sig()` (the `PackedArgsSetter` in `function.h`).

The revert suggests the added generality was not justified by the callsite needs, and the three-way dispatch may have introduced compile-time overhead or compiler compatibility concerns. The `Arg2Str` approach is more explicit and self-contained: it uses `std::tuple_element_t` and the C-style expander `int[]{0, (expr, 0)...}` pattern, which is maximally portable.
