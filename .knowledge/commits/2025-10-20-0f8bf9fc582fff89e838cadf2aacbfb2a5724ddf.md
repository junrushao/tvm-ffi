# Add __dlpack_device__ protocol support for device ingestion from arbitrary types

## TL;DR
- Introduces the `__dlpack_device__` protocol: any Python object whose class defines `__dlpack_device__() -> tuple[int, int]` (and does **not** define `__dlpack__`) is now automatically converted to `DLDevice` when passed as an FFI function argument, via a new Cython arg setter `TVMFFIPyArgSetterDLPackDeviceProtocol_`.
- Mirrors the existing `__dlpack_data_type__` protocol pattern (commit 5e648f0) but targets device rather than dtype.
- Adds a test exercising the protocol with a custom `DLPackDeviceProtocol` class wrapping `tvm_ffi.Device`.

## Key Exports

**Cython arg setter**: `TVMFFIPyArgSetterDLPackDeviceProtocol_` (in `function.pxi`)
- Registered in `TVMFFIPyArgSetterFactory_` for any type whose class has `__dlpack_device__` but not `__dlpack__`.
- Calls `arg.__dlpack_device__()` to get a `(device_type, device_id)` tuple, then converts via `TVMFFIDLDeviceFromIntPair` into `out.v_device` with `type_index = kTVMFFIDevice`.
- Dispatch priority: after `__dlpack_data_type__` check, before `Exception` check in the factory isinstance chain.

**Protocol**: `__dlpack_device__`
- Any Python class implementing `def __dlpack_device__(self) -> tuple[int, int]` (without also implementing `__dlpack__`) can be passed directly to TVM FFI functions expecting a `DLDevice` argument.
- The guard `not hasattr(arg_class, "__dlpack__")` prevents conflict with tensor types (e.g., `torch.Tensor`) that implement both `__dlpack__` and `__dlpack_device__` -- those are handled by the DLPack tensor path instead.

## Impact
- API: Additive. New duck-typing protocol `__dlpack_device__` for automatic device conversion. No breaking changes.
- ABI: None.
- Behavioral: Objects implementing `__dlpack_device__` (but not `__dlpack__`) that were previously handled by the fallback setter will now be converted to `DLDevice`. This is a new dispatch path in the arg setter factory, positioned after `__dlpack_data_type__` and before `Exception`.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Cython arg setter dispatch system** (`.knowledge/designs/0014-python-bindings.md`): The per-type `TVMFFIPyArgSetter` functor cache and `TVMFFIPyArgSetterFactory_` isinstance chain. This commit adds a new entry for the `__dlpack_device__` protocol.
- **`TVMFFIDLDeviceFromIntPair`** (`include/tvm/ffi/c_api.h`, line 1221): Inline C++ helper that constructs a `DLDevice` from `(device_type, device_id)` int pair. Already used by `Device.__init__` and `_create_device_from_tuple`.
- **`__dlpack_data_type__` protocol pattern** (commit 5e648f0): The identical architectural pattern -- duck-typing protocol detected by `hasattr` in the factory, with a dedicated Cython setter. This commit replicates that pattern for device instead of dtype.
- **DLPack device protocol convention**: The `__dlpack_device__() -> tuple[int, int]` dunder is part of the Python array API / DLPack standard, returning `(device_type, device_id)`.

Design elements this commit produces:
- **`__dlpack_device__` protocol for device ingestion**: A duck-typing protocol where any Python type implementing `__dlpack_device__() -> tuple[int, int]` (without `__dlpack__`) is automatically recognized as a device argument by the FFI. This generalizes device support beyond the hardcoded `Device` class to any type that can express itself as a DLPack device tuple. The `not __dlpack__` guard prevents tensor types from being misrecognized as device-only objects.

## Usage Examples

### Passing a custom device object to an FFI function via `__dlpack_device__`
**Context**: Any Python object whose class implements `__dlpack_device__` (but not `__dlpack__`) is automatically converted to `DLDevice` when passed to a TVM FFI function.
```python
import tvm_ffi

class MyDevice:
    def __init__(self, device_type: int, device_id: int) -> None:
        self._device_type = device_type
        self._device_id = device_id

    def __dlpack_device__(self) -> tuple[int, int]:
        return (self._device_type, self._device_id)

fecho = tvm_ffi.get_global_func("testing.echo")
x = MyDevice(2, 1)  # cuda:1
y = fecho(x)  # automatically converted to DLDevice via protocol
assert y == tvm_ffi.device("cuda:1")
```
