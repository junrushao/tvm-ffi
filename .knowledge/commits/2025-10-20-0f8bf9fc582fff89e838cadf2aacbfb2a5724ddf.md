# Introduce Device Protocol via `__dlpack_device__`

## TL;DR
- Introduces `__dlpack_device__` protocol: any Python object with a `__dlpack_device__() -> tuple[int, int]` method (but *without* `__dlpack__`) is automatically converted to a `Device` when passed as an FFI argument, enabling device exchange from third-party objects.
- Adds `TVMFFIPyArgSetterDLPackDeviceProtocol_` Cython setter that unpacks the 2-tuple via `TVMFFIDLDeviceFromIntPair` into a `TVMFFIDevice`.
- The dispatch condition specifically excludes objects that also have `__dlpack__`, preventing tensor-like objects from being misclassified as device-only.

## Key Exports

**Protocol**: `__dlpack_device__`
- Any class implementing `__dlpack_device__(self) -> tuple[int, int]` (and NOT `__dlpack__`) is recognized by the FFI arg setter factory and converted to `Device` via `TVMFFIPyArgSetterDLPackDeviceProtocol_`.
- Dispatch priority: checked after `__dlpack_data_type__` (no `__dlpack__` guard), before `Exception`. Specifically gated on `hasattr(arg_class, "__dlpack_device__") and not hasattr(arg_class, "__dlpack__")`.

**Cython setter**: `TVMFFIPyArgSetterDLPackDeviceProtocol_`
- Signature: `(TVMFFIPyArgSetter* handle, TVMFFIPyCallContext* ctx, PyObject* py_arg, TVMFFIAny* out) -> int`
- Calls `arg.__dlpack_device__()`, unpacks the 2-tuple into `(device_type, device_id)`, then sets `out.type_index = kTVMFFIDevice` and `out.v_device` via `TVMFFIDLDeviceFromIntPair(<int32_t>device_type, <int32_t>device_id)`.

## Impact
- API: New protocol `__dlpack_device__` enables third-party device objects to pass through FFI as `Device` without explicit conversion. Previously such objects would fall through to opaque wrapping or callable dispatch.
- Behavioral: Objects with `__dlpack_device__` (but not `__dlpack__`) are now auto-converted to `Device` in FFI calls.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Type-cached FFI arg dispatch** (`function.pxi`, `TVMFFIPyArgSetterFactory_`): The new setter is registered in the factory dispatch chain. See `.knowledge/designs/0015-python-ffi-call-dispatch.md`.
- **`TVMFFIDLDeviceFromIntPair`** (C API helper): Converts `(int32_t device_type, int32_t device_id)` pair into a `TVMFFIDLDevice` struct. Already declared in `base.pxi`.
- **`kTVMFFIDevice` type index**: The type tag used for Device values in the `TVMFFIAny` union.
- **Existing `TVMFFIPyArgSetterDevice_`**: The setter for native `Device` objects (direct `cdevice` copy). The new protocol setter handles *non-Device* objects that implement the DLPack device protocol.

Design elements this commit produces:
- **`__dlpack_device__` protocol** (for non-tensor objects): A duck-typing protocol for device exchange. Any object implementing `__dlpack_device__() -> tuple[int, int]` (without also implementing `__dlpack__`) can pass through FFI as a `Device`. This parallels `__dlpack_data_type__` for dtype exchange.
- **`TVMFFIPyArgSetterDLPackDeviceProtocol_`**: New entry in the Cython setter catalog.

## Usage Examples

```python
import tvm_ffi

device = tvm_ffi.device("cuda:1")

class DLPackDeviceProtocol:
    def __init__(self, device: tvm_ffi.Device) -> None:
        self.device = device

    def __dlpack_device__(self) -> tuple[int, int]:
        return (self.device.dlpack_device_type(), self.device.index)

fecho = tvm_ffi.get_global_func("testing.echo")
x = DLPackDeviceProtocol(device)
y = fecho(x)  # auto-converted to Device via __dlpack_device__
assert y == device
```
