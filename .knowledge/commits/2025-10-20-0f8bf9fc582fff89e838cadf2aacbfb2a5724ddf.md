# Introduce DLPack device protocol: __dlpack_device__() for Device argument conversion

## TL;DR
- Any Python object with a `__dlpack_device__()` method returning `(device_type, device_index)` and **without** `__dlpack__` is now accepted as a `Device` argument to TVM FFI packed functions.
- The `__dlpack__` exclusion is intentional: objects with `__dlpack__` are already handled as tensors.

# Dispatch priority in TVMFFIPyArgSetterFactory_:
# ... -> __dlpack_data_type__ check -> __dlpack_device__ (NEW, only if no __dlpack__) -> Exception check

## Impact
- API: None — new dispatch path, additive only.
- Behavioral: Any object implementing `__dlpack_device__()` (without `__dlpack__`) is transparently accepted as a Device argument in packed function calls.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetterFactory_` dispatch chain (see `.knowledge/design-records/0016-py-ffi-call-dispatch.md`).
- `TVMFFIDLDeviceFromIntPair` C helper, `kTVMFFIDevice` type index (see `.knowledge/design-records/0001-c-abi.md`).
- DLPack dtype protocol introduced in commit `5e648f052f93` (same session).

Design elements this commit produces:
- **DLPack device protocol**: any object with `__dlpack_device__() -> tuple[int, int]` and no `__dlpack__` method is accepted as a Device argument. Mirrors the dtype protocol pattern.

## Usage Examples

```python
class DLPackDeviceProtocol:
    def __init__(self, device: tvm_ffi.Device) -> None:
        self.device = device

    def __dlpack_device__(self) -> tuple[int, int]:
        return (self.device.dlpack_device_type(), self.device.index)

fecho = tvm_ffi.get_global_func("testing.echo")
x = DLPackDeviceProtocol(tvm_ffi.device("cuda:1"))
y = fecho(x)  # y == tvm_ffi.device("cuda:1")
```
