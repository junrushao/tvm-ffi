# Reorganize and expand Python API docs with additional public symbols
## TL;DR
- Reorganizes the Sphinx Python API reference (`docs/reference/python/index.rst`) into a clearer hierarchy with subsections (Tensor, Function, Module, Containers under Object; new Global Registry and Misc sections) and adds previously undocumented symbols (`DLDeviceType`, `device`, `dtype`, `get_global_func_metadata`, `remove_global_func`, `serialization`, `access_path`, `convert`, `ObjectConvertible`).
- Fixes `__all__` in `python/tvm_ffi/__init__.py` by removing duplicate entries (`Device`, `Object`) and adding missing exports (`StreamContext`, `get_raw_stream`, `use_raw_stream`, `use_torch_stream`).
- Adds `autosummary_generate` and `autosummary_filename_map` to `docs/conf.py` to resolve Sphinx name collisions between `tvm_ffi.device` (function) and `tvm_ffi.Device` (class).

## Key Exports
**`__all__` additions in `python/tvm_ffi/__init__.py`**:
- `StreamContext` -- stream context manager class
- `get_raw_stream` -- retrieves the current raw stream handle
- `use_raw_stream` -- factory for `StreamContext`
- `use_torch_stream` -- factory for `TorchStreamContext`

**Sphinx API sections added/renamed in `docs/reference/python/index.rst`**:
- New subsections: `Tensor`, `Function`, `Module`, `Containers` (under `Object`)
- New top-level sections: `Global Registry`, `Misc`, `Inline Loading` (renamed from `Utility`)
- New documented symbols: `DLDeviceType`, `device`, `dtype`, `get_global_func_metadata`, `remove_global_func`, `serialization`, `access_path`, `convert`, `ObjectConvertible`

## Impact
- API: No runtime API changes. `__all__` now accurately reflects all public symbols already importable from `tvm_ffi`. Four symbols (`StreamContext`, `get_raw_stream`, `use_raw_stream`, `use_torch_stream`) were already importable but not listed in `__all__`.
- ABI: None.
- Behavioral: None.
- Flags/config: `autosummary_generate = True` and `autosummary_filename_map` added to Sphinx config to control stub page generation and avoid naming collisions.
- Data formats/schemas: None.
