# Expose get_raw_stream Python API for querying the current FFI env stream
## TL;DR
- Adds `get_raw_stream(device) -> int` to the public Python API, exposing the existing C ABI `TVMFFIEnvGetStream` to Python callers.
- Bridges the gap via a new Cython wrapper `_env_get_current_stream` and type stub in `core.pyi`.
- Tests verify round-trip consistency: `use_raw_stream` sets a stream, `get_raw_stream` reads it back.

## Impact
- API: Additive -- new public function `tvm_ffi.get_raw_stream()` exported from `__init__.py`. No existing signatures changed.
- Behavioral: none

## Design Elements
Design elements this commit consumes:
- **EnvContext TLS stream table** ([0014-stream-and-env-context.md](../designs/0014-stream-and-env-context.md)) -- reads the per-device stream via `TVMFFIEnvGetStream`.
- **Cython C ABI binding pattern** ([0012-python-bindings.md](../designs/0012-python-bindings.md)) -- follows the existing `_env_set_current_stream` wrapper as a template.
- **`core.Device`** -- used for `dlpack_device_type()` and `index` to map Python device to C ABI `(device_type, device_id)` pair.

Design elements this commit produces:
- **`get_raw_stream` public API** -- read-side complement to `use_raw_stream` (write-side). Completes the Python stream query surface for the EnvContext stream table.

## Usage Examples
From `tests/python/test_stream.py`, showing round-trip consistency with `use_raw_stream`:

```python
import tvm_ffi

device = tvm_ffi.device("cuda", 0)
stream_1 = 123456789

with tvm_ffi.use_raw_stream(device, stream_1):
    # Query the stream that was just set
    assert tvm_ffi.get_raw_stream(device) == stream_1
```
