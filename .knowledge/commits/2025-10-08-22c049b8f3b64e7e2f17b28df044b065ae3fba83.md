# Expose get_raw_stream to query the current FFI environment stream from Python

## TL;DR
- Adds `tvm_ffi.get_raw_stream(device) -> int`, a new public Python function that queries the current FFI thread-local stream for a given device by calling the existing `TVMFFIEnvGetStream` C API.
- Adds `core._env_get_current_stream(device_type, device_id) -> int` as the Cython bridge in `base.pxi`, wrapping `TVMFFIEnvGetStream` and casting the returned `void*` to `uint64`.
- Adds the corresponding type stub in `core.pyi` and extends `test_raw_stream` with three `assert tvm_ffi.get_raw_stream(device) == expected` checks verifying correctness at each nesting level.

## Key Exports

**Functions:**

- `tvm_ffi.get_raw_stream(device: Device) -> int` -- Returns the current FFI thread-local stream handle for the given device. Delegates to `core._env_get_current_stream(device.dlpack_device_type(), device.index)`. Defined in `python/tvm_ffi/stream.py`.

- `core._env_get_current_stream(device_type: int, device_id: int) -> int` -- Cython function in `base.pxi`. Calls `TVMFFIEnvGetStream(device_type, device_id)` and returns the result as `uint64`. This is an internal API consumed by `get_raw_stream`.

## Impact
- API: New public function `tvm_ffi.get_raw_stream` added to the `tvm_ffi` namespace. No existing API changed.
- ABI: None. No C/C++ changes. Only a new Cython wrapper around the existing `TVMFFIEnvGetStream` C API.
- Behavioral: None for existing code. New read-only query functionality only.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **`TVMFFIEnvGetStream` C API** (`.knowledge/designs/c-abi.md` > Extra C Env API) -- The existing C function `TVMFFIEnvGetStream(int32_t device_type, int32_t device_id) -> TVMFFIStreamHandle` declared in `include/tvm/ffi/extra/c_env_api.h`. This commit wraps it in Cython for the first time.
- **`EnvContext` thread-local stream table** (`.knowledge/designs/0018-dlpack-fast-path.md` > EnvContext) -- The C++ `EnvContext` singleton with its 2D `vector<vector<void*>>` table that stores per-device streams. `TVMFFIEnvGetStream` reads from this table.
- **Python stream context protocol** (commit 3197cd0, `.knowledge/commits/2025-09-15-3197cd0949ae9bb9a41eb5a429a4b1519d061db4.md`) -- The `StreamContext`/`use_raw_stream`/`use_torch_stream` pattern introduced in PR #5. This commit complements the write-only `use_raw_stream` with a read-only `get_raw_stream`.
- **Cython `base.pxi` extern declarations** (`.knowledge/designs/0014-python-bindings.md` > Cython Layer) -- The existing `TVMFFIEnvGetStream` extern declaration in `base.pxi` that the new `_env_get_current_stream` function calls.
- **`Device` class** (`.knowledge/designs/0014-python-bindings.md`) -- The `device.dlpack_device_type()` and `device.index` accessors used by `get_raw_stream` to extract the C-level device type and id.

Design elements this commit produces:
- **Python stream query API** -- Completes the stream context protocol by adding a getter (`get_raw_stream`) to match the existing setter (`use_raw_stream`). This enables Python code to inspect the current FFI stream without entering/exiting a context manager, useful for debugging, assertion checks, and forwarding the current stream handle to other systems.

## Usage Examples

Querying the current FFI stream inside a stream context:
```python
import tvm_ffi

device = tvm_ffi.device("cuda:0")
stream_handle = 123456789

with tvm_ffi.use_raw_stream(device, stream_handle):
    # Query the stream that was just set
    current = tvm_ffi.get_raw_stream(device)
    assert current == stream_handle

    with tvm_ffi.use_raw_stream(device, 987654321):
        # Inner context overrides
        assert tvm_ffi.get_raw_stream(device) == 987654321

    # Outer context restored
    assert tvm_ffi.get_raw_stream(device) == stream_handle
```
