# Expose get_raw_stream() Python API backed by TVMFFIEnvGetStream

## TL;DR
- Adds `get_raw_stream(device) -> int` to `tvm_ffi.stream` and re-exports it from `tvm_ffi.__init__`, completing the read counterpart to the existing `use_raw_stream` write API.
- Implements the Cython bridge `_env_get_current_stream(device_type, device_id) -> int` in `base.pxi`, calling `TVMFFIEnvGetStream` (the C env API already present in `extra/c_env_api.h`).
- Adds three assertions to `test_raw_stream` verifying that `get_raw_stream` returns the correct stream handle at each nesting level.

## Impact
- API: `tvm_ffi.get_raw_stream(device)` is a new top-level export — additive, no existing call sites change. Callers of `use_raw_stream` can now read back the active stream handle without keeping a reference to the integer they passed in.
- Behavioral: none to existing functions.
- Flags/config: none.
- Data formats/schemas: none.

## Usage Examples

**Context**: Kernel dispatch library needs to pass the current FFI stream to a low-level C extension without holding a reference to the stream handle that was previously set.

```python
import tvm_ffi

device = tvm_ffi.device("cuda:0")
stream = 0xDEADBEEF  # raw cudaStream_t as integer

with tvm_ffi.use_raw_stream(device, stream):
    # Read back the currently active stream inside the context
    current = tvm_ffi.get_raw_stream(device)
    assert current == stream  # True: get mirrors what use_raw_stream set

    # Pass to a C extension that needs the raw handle
    my_cuda_kernel(tvm_ffi.get_raw_stream(device), ...)
```

**Cross-layer trace** (Cython → C ABI):
```
Python:  tvm_ffi.get_raw_stream(device)
  -> stream.py: core._env_get_current_stream(device.dlpack_device_type(), device.index)
     -> base.pxi: _env_get_current_stream(int device_type, int device_id)
        -> C ABI: TVMFFIEnvGetStream(device_type, device_id)  [extra/c_env_api.h]
           -> C++: EnvContext::ThreadLocal().GetStream(device_type, device_id)
              returns void* cast to uint64_t -> int (Python)
```
