# Fix config-mode import guard to still load libtvm_ffi on Windows

## TL;DR
- Adds `elif sys.platform.startswith("win32")` branch after the config-mode guard introduced in commit 5c0deb94.
- On Windows, `libinfo.load_lib_ctypes` is called even in config mode so the DLL search path is correctly set for Cython extensions (`.pyd`) that may still be loaded by tests.
- No change to non-Windows or normal (non-config) code paths.

## Key Exports

```python
# python/tvm_ffi/__init__.py — amended guard pattern
if TYPE_CHECKING or not _is_config_mode():
    # normal mode: load everything
    ...
elif sys.platform.startswith("win32"):
    # Windows + config mode: still need DLL search path
    from . import libinfo
    LIB = libinfo.load_lib_ctypes("apache-tvm-ffi", "tvm_ffi", "RTLD_GLOBAL")
# Invariant: LIB is always set on Windows; only omitted on non-Windows config-mode invocations
```

## Impact
- API: None — no public API changes.
- Behavioral: On Windows, `LIB` is now always initialized even in config mode; prevents test failures where `.pyd` Cython modules need the DLL loaded before they can be imported.
- Flags/config: `sys.platform.startswith("win32")` is the detection condition.
- Data formats/schemas: none

## Usage Examples

Before (broken on Windows in config mode):
```python
# After 5c0deb94: on Windows in config mode, LIB was never set → DLL not on search path
if TYPE_CHECKING or not _is_config_mode():
    LIB = libinfo.load_lib_ctypes(...)
# BROKEN: .pyd Cython extensions fail to import
```

After (fixed):
```python
if TYPE_CHECKING or not _is_config_mode():
    LIB = libinfo.load_lib_ctypes(...)
elif sys.platform.startswith("win32"):
    LIB = libinfo.load_lib_ctypes(...)  # Windows always needs DLL path setup
```
