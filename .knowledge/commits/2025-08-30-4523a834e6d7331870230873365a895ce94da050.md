# Add wheel packaging example for tvm-ffi extensions, fix cmake install paths, lazy-init torch CUDA stream accessor, and bump version to 0.1.0a5.

## TL;DR
- Adds a complete `examples/packaging/` project showing how to build and distribute a tvm-ffi extension as an ABI-agnostic Python wheel via `scikit-build-core`, covering both pre-built and source-based tvm-ffi inclusion.
- Fixes cmake install destinations (`cmake/Utils` trailing slash removed, `tvm_ffi-config.cmake` moved from `lib/cmake/tvm_ffi/` to `cmake/`) and adds `include(Utils/Library.cmake)` to the installed cmake config so downstream projects can call `tvm_ffi_add_prefix_map`/`tvm_ffi_add_apple_dsymutil`.
- Changes `torch_get_current_cuda_stream` initialization from eager (module-load time, conditioned on `torch is not None`) to lazy (first time a CUDA tensor arg is passed to a packed function).

## Impact
- API: None — `tvm_ffi.config` CLI arguments unchanged; `find_cmake_path()` internal path change is transparent to callers.
- Behavioral: Torch CUDA stream accessor is now JIT-compiled on the first call that passes a CUDA tensor, not at module import. This removes the torch import cost at tvm_ffi load time when CUDA tensors are never passed.
- Flags/config: `TVM_FFI_EXT_FROM_SOURCE` (default ON) and `TVM_FFI_EXT_SHIP_DEBUG_SYMBOLS` (default ON) added as CMake options for extension projects.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **Module system** (`0011-module-system`): `tvm_ffi.load_module` used in `base.py` to load extension `.so`/`.dylib`/`.dll`.
- **Global function registry** (`0004-function-system`): `tvm_ffi._init_api("tvm_ffi_extension", __name__)` in `_ffi_api.py` registers all `tvm_ffi_extension.*` C++ globals into the Python module namespace.
- **StreamContext / env-api** (`0012-env-api`): `torch_get_current_cuda_stream` feeds the cuda stream into the packed function calling convention via `make_args`.
- **`tvm_ffi.config` CLI** (pre-existing, `python/tvm_ffi/config.py`): used by the example `CMakeLists.txt` via `python -m tvm_ffi.config --cmakedir/--sourcedir`.

Design elements this commit produces:
- **Packaging pattern for tvm-ffi extensions**: the `examples/packaging/` directory codifies the canonical two-mode build (source vs pre-built) + scikit-build-core wheel workflow. This is a new documented pattern, not a new design element in the runtime.

## Usage Examples

Cross-layer packaging trace (C++ → Python wheel):

```python
# 1. C++ side (examples/packaging/src/extension.cc — not shown in diff but referenced)
#    Registers functions under "tvm_ffi_extension.*" via TVM_FFI_STATIC_INIT_BLOCK / GlobalDef

# 2. Python base.py — loads the .so at import time
from tvm_ffi_extension.base import _LIB  # triggers tvm_ffi.load_module("tvm_ffi_extension.so")

# 3. Python _ffi_api.py — maps C++ globals into Python namespace
import tvm_ffi
from .base import _LIB  # ensure lib loaded
tvm_ffi._init_api("tvm_ffi_extension", __name__)
# Now: _ffi_api.raise_error, _ffi_api.add_one, etc. are callable

# 4. Public API in __init__.py
from .base import _LIB
from . import _ffi_api

def add_one(x, y):
    return _LIB.add_one(x, y)      # calls via Module.GetFunction path

def raise_error(msg):
    return _ffi_api.raise_error(msg)  # calls via global function registry path

# 5. Build: scikit-build-core invokes CMakeLists.txt
#    CMakeLists.txt calls: python -m tvm_ffi.config --cmakedir → find_package(tvm_ffi CONFIG REQUIRED)
#    or: python -m tvm_ffi.config --sourcedir → add_subdirectory(tvm_ffi_ROOT)
```

Bugfix before/after for lazy torch CUDA stream init:

```python
# BEFORE (eager, module load):
# if torch is not None:
#     torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
# Problem: even if user never passes a CUDA tensor, the JIT compile runs at import

# AFTER (lazy, first CUDA tensor use):
torch_get_current_cuda_stream = None
# ... inside make_args cdef when a CUDA tensor is detected:
if torch_get_current_cuda_stream is None:
    torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()
temp_ptr = torch_get_current_cuda_stream(device_id)
```
