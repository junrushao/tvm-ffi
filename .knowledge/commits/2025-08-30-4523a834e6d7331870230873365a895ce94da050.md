# Add wheel packaging example and fix cmake install paths

## TL;DR
- Adds a complete `examples/packaging/` directory demonstrating how to package a tvm-ffi-based C++ extension as a Python ABI-agnostic wheel using `scikit-build-core`.
- Fixes cmake install path inconsistencies: cmake config file now installs to `cmake/` (was `lib/cmake/tvm_ffi/`), Utils directory drops trailing slash in destination.
- Defers torch CUDA stream JIT compilation in Cython to first use (lazy initialization) instead of eager module-level compilation.
- Updates `find_cmake_path()` in `libinfo.py` to look in `cmake/` instead of `lib/cmake/`.
- Includes `Library.cmake` utility via `tvm_ffi-config.cmake` so downstream projects get `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil`.
- Bumps package version from `0.1.0a3` to `0.1.0a5`.

## Key Exports

### New: `examples/packaging/` -- Wheel packaging example

**`examples/packaging/CMakeLists.txt`**:
- `cmake_minimum_required(VERSION 3.18)`, project `tvm_ffi_extension`.
- Option `TVM_FFI_EXT_FROM_SOURCE` (default ON) -- build tvm_ffi from source for cross-compilation.
- Option `TVM_FFI_EXT_SHIP_DEBUG_SYMBOLS` (default ON) -- ship `.dSYM` bundles on macOS.
- Two tvm_ffi inclusion paths: (1) `add_subdirectory` from source via `tvm_ffi.config --sourcedir`, (2) `find_package(tvm_ffi CONFIG)` via `tvm_ffi.config --cmakedir`.
- Builds `tvm_ffi_extension` shared library from `src/extension.cc` (file not included in this commit; added later).
- Links `tvm_ffi_header` and `tvm_ffi_shared`.
- Uses `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil` for debug symbol handling.

**`examples/packaging/pyproject.toml`**:
- Package: `tvm-ffi-extension` version `0.1.0`, depends on `apache-tvm-ffi`.
- Build system: `scikit-build-core >= 0.10.0` + `apache-tvm-ffi`.
- `wheel.py-api = "py3"` -- ABI-agnostic wheel (no Python version tag).
- `wheel.packages = ["python/tvm_ffi_extension"]`, installed to `tvm_ffi_extension/`.
- `cmake.build-type = "RelWithDebugInfo"`.

**`examples/packaging/python/tvm_ffi_extension/__init__.py`**:
- `add_one(x, y)` -- calls `_LIB.add_one(x, y)` (method on the loaded module).
- `raise_error(msg)` -- calls `_ffi_api.raise_error(msg)` (global registered function).

**`examples/packaging/python/tvm_ffi_extension/_ffi_api.py`**:
- Loads `_LIB` from `base.py`, then calls `tvm_ffi._init_api("tvm_ffi_extension", __name__)` to auto-bind all global functions prefixed by `tvm_ffi_extension.` to the module.

**`examples/packaging/python/tvm_ffi_extension/base.py`**:
- `_load_lib()` -- looks for platform-specific shared library (`tvm_ffi_extension.so`/`.dylib`/`.dll`) in the package directory, loads it via `tvm_ffi.load_module(lib_path)`.
- `_LIB = _load_lib()` -- module-level loaded library handle.

**`examples/packaging/README.md`**:
- Documents install (`pip install .`), auditwheel note (skip `libtvm_ffi_shared.so`), and run instructions for `add_one` and `raise_error` examples.

**`python/tvm_ffi/libinfo.py`** -- `find_cmake_path()`:
- First candidate changed from `<package_dir>/lib/cmake` to `<package_dir>/cmake` (matches new install destination).

### Modified: Cython torch stream initialization

**`python/tvm_ffi/cython/function.pxi`**:
- `torch_get_current_cuda_stream` initialized to `None` at module level (was eagerly JIT-compiled via `load_torch_get_current_cuda_stream()` when torch was available).
- Lazy initialization added inside `make_args()`: the JIT compilation of `get_current_cuda_stream` only triggers on first CUDA tensor argument, with `if torch_get_current_cuda_stream is None: torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()`.

**`pyproject.toml`**: `version` changed from `"0.1.0a3"` to `"0.1.0a5"`.

## Impact

- **API**: No public API changes. New example code is self-contained.
- **ABI**: Not breaking. No C API or object layout changes.
- **Behavioral**:
  - CMake install paths change: downstream projects that hardcode `lib/cmake/tvm_ffi/` to find the config file will break; they should use `cmake/` or (preferred) call `tvm_ffi.config --cmakedir`.
  - `find_cmake_path()` now looks in `<package_dir>/cmake` first instead of `<package_dir>/lib/cmake`.
  - Torch CUDA stream JIT compilation is deferred to first CUDA tensor usage, reducing import time when torch is installed but no CUDA tensors are used. This eliminates the startup cost of JIT-compiling a C++ extension on first `import tvm_ffi` when torch is present.
  - `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil` are now automatically available to downstream CMake projects via `find_package(tvm_ffi)`.
- **Packaging**: Version bumped to `0.1.0a5`. The packaging example provides a reference implementation for third-party extensions.

## Design Elements

Design elements this commit **consumes**:

- **Module system** (`tvm_ffi.load_module`): The packaging example's `base.py` uses `tvm_ffi.load_module(lib_path)` to load the compiled shared library, which discovers and registers `__tvm_ffi_<name>` symbols as global functions.
- **`_init_api` namespace population pattern**: `_ffi_api.py` uses `tvm_ffi._init_api("tvm_ffi_extension", __name__)` to auto-bind registered functions with matching prefix to the module namespace.
- **`tvm_ffi-config.cmake` discovery pattern**: The example CMakeLists.txt uses `python -m tvm_ffi.config --cmakedir` / `--sourcedir` to locate tvm_ffi for both pre-built and source-build paths.
- **`scikit-build-core` wheel packaging** (from commit 2d41a51): The example replicates the same `scikit-build-core` backend pattern with ABI-agnostic wheel configuration.
- **CMake debug symbol utilities** (`tvm_ffi_add_prefix_map`, `tvm_ffi_add_apple_dsymutil`): Used in the example to ship debug symbols and produce relative paths in C++ tracebacks.

Design elements this commit **produces**:

- **Extension wheel packaging reference pattern**: The `examples/packaging/` directory establishes the canonical pattern for packaging a tvm-ffi-based C++ extension as a Python wheel. The pattern includes: (1) `pyproject.toml` with `scikit-build-core` and `py3`-tagged ABI-agnostic wheel, (2) CMakeLists.txt showing both source-build and pre-built tvm_ffi inclusion, (3) Python package with `base.py` for library loading via `tvm_ffi.load_module`, (4) `_ffi_api.py` for automatic function binding via `_init_api`, and (5) debug symbol shipping with `.dSYM` on macOS. This is intended as a template for downstream projects.

- **Lazy torch CUDA stream initialization**: Defers the JIT compilation of the `get_current_cuda_stream` C++ extension from module import time to first CUDA tensor argument. This eliminates unnecessary startup overhead when torch is installed but no CUDA tensors are passed through the FFI. The pattern is: initialize to `None` at module level, check for `None` at the call site inside `make_args()`, and call the loader on first use.

- **Flattened cmake install layout**: The cmake config and utilities are now installed to `<prefix>/cmake/` (flat) rather than `<prefix>/lib/cmake/tvm_ffi/` (nested). The config file includes `Utils/Library.cmake` so that downstream `find_package(tvm_ffi)` automatically gets access to helper functions like `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil`.

## Usage Examples

### Building the packaging example
```bash
# Install the extension as a wheel
cd examples/packaging
pip install .

# Run the example (requires extension.cc and run_example.py from later commits)
python run_example.py add_one
python run_example.py raise_error
```

### Using tvm_ffi_extension from Python
```python
import tvm_ffi_extension

# Call the add_one function exposed by the C++ extension
tvm_ffi_extension.add_one(input_tensor, output_tensor)

# Demonstrate cross-language error propagation
try:
    tvm_ffi_extension.raise_error("test error")
except RuntimeError as e:
    print(e)  # traceback includes C++ frames
```

### Downstream CMake project using tvm_ffi utilities
```cmake
find_package(Python COMPONENTS Interpreter REQUIRED)
execute_process(
  COMMAND "${Python_EXECUTABLE}" -m tvm_ffi.config --cmakedir
  OUTPUT_STRIP_TRAILING_WHITESPACE OUTPUT_VARIABLE tvm_ffi_ROOT)
find_package(tvm_ffi CONFIG REQUIRED)

add_library(my_ext SHARED my_ext.cc)
target_link_libraries(my_ext tvm_ffi_header tvm_ffi_shared)

# Now available via the config include:
tvm_ffi_add_prefix_map(my_ext ${CMAKE_CURRENT_SOURCE_DIR})
tvm_ffi_add_apple_dsymutil(my_ext)
```
