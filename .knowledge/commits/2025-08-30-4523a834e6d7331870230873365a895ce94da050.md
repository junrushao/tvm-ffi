# Add wheel packaging example, fix CMake install paths, lazy-load torch CUDA stream helper

## TL;DR
- Adds a complete `examples/packaging/` project demonstrating how to build and distribute a tvm-ffi-based C++ extension as an ABI-agnostic Python wheel using `scikit-build-core`.
- Fixes CMake install destinations: `cmake/Utils/` no longer double-suffixed, `tvm_ffi-config.cmake` moves from `lib/cmake/tvm_ffi/` to `cmake/`; `find_cmake_path()` in `libinfo.py` updated to match.
- Defers `torch_get_current_cuda_stream` JIT compilation from import-time to first CUDA tensor encounter, eliminating a startup penalty when torch is installed but unused.
- Bumps package version from `0.1.0a3` to `0.1.0a5`.

## Key Exports

**New example project** (`examples/packaging/`):
- `CMakeLists.txt` -- demonstrates two build modes: (a) `TVM_FFI_BUILD_FROM_SOURCE` builds tvm_ffi as a subdirectory, (b) default uses `find_package(tvm_ffi)` from the installed pip package. Uses `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil` from `Library.cmake`.
- `pyproject.toml` -- scikit-build-core config with `wheel.py-api = "py3"` (ABI-agnostic), depends on `apache-tvm-ffi` at both build and runtime.
- `python/tvm_ffi_extension/base.py` -- `_load_lib()` pattern: resolves platform-specific library name (`tvm_ffi_extension.{so,dylib,dll}`), calls `tvm_ffi.load_module(lib_path)`.
- `python/tvm_ffi_extension/_ffi_api.py` -- uses `tvm_ffi._init_api("tvm_ffi_extension", __name__)` to auto-import global functions prefixed with `tvm_ffi_extension.`.
- `python/tvm_ffi_extension/__init__.py` -- public API: `add_one(x, y)` via `_LIB.add_one(x, y)` (direct module function call), `raise_error(msg)` via `_ffi_api.raise_error(msg)` (global registry function call).

**Changed CMake install layout**:
- `cmake/tvm_ffi-config.cmake` now includes `${CMAKE_CURRENT_LIST_DIR}/Utils/Library.cmake`, making `tvm_ffi_add_prefix_map` and `tvm_ffi_add_apple_dsymutil` available to downstream `find_package(tvm_ffi)` consumers.
- Install destination for cmake config changed: `lib/cmake/tvm_ffi/` -> `cmake/`.
- Install destination for Utils: `cmake/Utils/` -> `cmake/Utils` (trailing slash removed to prevent double `Utils/Utils/` nesting).

**Changed Cython behavior** (`function.pxi`):
- `torch_get_current_cuda_stream` initialized to `None` at module level instead of eagerly calling `load_torch_get_current_cuda_stream()`.
- Lazy initialization on first CUDA tensor argument: `if torch_get_current_cuda_stream is None: torch_get_current_cuda_stream = load_torch_get_current_cuda_stream()`.

## Impact
- API: None (example code only; no public API changes to `tvm_ffi` itself).
- Behavioral: `import tvm_ffi` no longer JIT-compiles the torch CUDA stream helper at import time. Startup is faster when torch is installed but no CUDA tensors are used.
- Flags/config: CMake install destinations changed -- downstream projects using `find_package(tvm_ffi)` from a pip-installed package now find the config at `<package>/cmake/tvm_ffi-config.cmake` instead of `<package>/lib/cmake/tvm_ffi/tvm_ffi-config.cmake`. The `--cmakedir` flag of `tvm-ffi-config` CLI was already correct; only the Python `find_cmake_path()` fallback and CMake `install()` directives changed.
- Data formats/schemas: Package version bumped `0.1.0a3` -> `0.1.0a5`.

## Design Elements

Design elements this commit consumes:
- **Module system** (`0013-module-system.md`): The packaging example uses `tvm_ffi.load_module()` to load a shared library, then calls functions via the `Module` interface (`_LIB.add_one(x, y)`).
- **Global function registry** (`0004-function-system.md`): The example uses `tvm_ffi._init_api()` to bulk-import global functions prefixed with `tvm_ffi_extension.` into the `_ffi_api` module.
- **Python package infrastructure** (`0014-python-package.md`): The example depends on `apache-tvm-ffi`, uses `tvm-ffi-config --cmakedir`/`--sourcedir` for CMake discovery, and follows the `scikit-build-core` wheel.py-api="py3" pattern.
- **CMake config targets** (`0014-python-package.md`): The example links against `tvm_ffi_header` and `tvm_ffi_shared` targets from `tvm_ffi-config.cmake`.
- **Library.cmake utilities**: The example uses `tvm_ffi_add_prefix_map()` and `tvm_ffi_add_apple_dsymutil()` for debug symbol handling, now exposed via `tvm_ffi-config.cmake`'s new `include(Utils/Library.cmake)`.

Design elements this commit produces:
- **Packaging example pattern**: A reference architecture for downstream tvm-ffi-based Python wheels, demonstrating the canonical `base.py` -> `_ffi_api.py` -> `__init__.py` layering, `scikit-build-core` config, and two CMake build modes (source vs. pre-built).
- **Lazy torch stream initialization pattern**: Deferred JIT compilation of torch CUDA stream helper, triggered on first CUDA tensor encounter rather than at import time.

## Usage Examples

### Downstream wheel packaging (from the new example)
```python
# python/tvm_ffi_extension/base.py -- canonical pattern for loading a native module
import tvm_ffi, os, sys

def _load_lib():
    file_dir = os.path.dirname(os.path.realpath(__file__))
    if sys.platform.startswith("win32"):
        lib_dll_name = "tvm_ffi_extension.dll"
    elif sys.platform.startswith("darwin"):
        lib_dll_name = "tvm_ffi_extension.dylib"
    else:
        lib_dll_name = "tvm_ffi_extension.so"
    return tvm_ffi.load_module(os.path.join(file_dir, lib_dll_name))

_LIB = _load_lib()
```

```python
# python/tvm_ffi_extension/_ffi_api.py -- bulk import global functions by prefix
import tvm_ffi
from .base import _LIB  # ensure native lib is loaded first
tvm_ffi._init_api("tvm_ffi_extension", __name__)
```

### CMake: two build modes for downstream projects
```cmake
# Option 1: Build tvm_ffi from source (cross-compilation safe)
execute_process(COMMAND "${Python_EXECUTABLE}" -m tvm_ffi.config --sourcedir
  OUTPUT_STRIP_TRAILING_WHITESPACE OUTPUT_VARIABLE tvm_ffi_ROOT)
add_subdirectory(${tvm_ffi_ROOT} tvm_ffi)

# Option 2: Use pre-built tvm_ffi from pip
execute_process(COMMAND "${Python_EXECUTABLE}" -m tvm_ffi.config --cmakedir
  OUTPUT_STRIP_TRAILING_WHITESPACE OUTPUT_VARIABLE tvm_ffi_ROOT)
find_package(tvm_ffi CONFIG REQUIRED)
```
