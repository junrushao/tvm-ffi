# Add wheel packaging example with cmake/install path fixes and lazy torch stream loading

## TL;DR
- Adds `examples/packaging/`: a complete reference project showing how to build a `tvm-ffi`-based C++ extension into an ABI-agnostic Python wheel using scikit-build-core.
- Fixes cmake install destinations (cmake dir moved from `lib/cmake/tvm_ffi/` to `cmake/`, Utils trailing-slash removed) and updates `find_cmake_path` in `libinfo.py` to match.
- Changes `torch_get_current_cuda_stream` initialization from eager (module-import-time) to lazy (first CUDA tensor encounter), avoiding import errors when torch is absent.
- Bumps `apache-tvm-ffi` version from `0.1.0a3` to `0.1.0a5`.

## Impact
- API: None -- all changes are additive or internal path adjustments.
- Behavioral: `torch_get_current_cuda_stream` is now lazy-loaded on first CUDA tensor rather than at Cython module import. This eliminates import-time errors when torch is not installed but `tvm_ffi` is.
- Flags/config: `TVM_FFI_EXT_FROM_SOURCE` and `TVM_FFI_EXT_SHIP_DEBUG_SYMBOLS` cmake options introduced in the example (not in core).
- Data formats/schemas: cmake install layout changed -- `tvm_ffi-config.cmake` now at `<prefix>/cmake/` instead of `<prefix>/lib/cmake/tvm_ffi/`.

## Design Elements
Design elements this commit consumes:
- **Module loading** (`load_module` / `DSOLibrary`): Used by `base.py` to load the co-packaged `.so`. See [0011-ffi-module-system](../design-records/0011-ffi-module-system.md).
- **Global function registry** (`_init_api`): Used by `_ffi_api.py` to auto-register functions from the loaded library into a Python module namespace. See [0004-ffi-function-system](../design-records/0004-ffi-function-system.md).
- **Packed function calling convention**: The example extension's `add_one` and `raise_error` are C++ packed functions callable through the FFI bridge.
- **cmake packaging infrastructure** (`tvm_ffi-config.cmake`, `Utils/Library.cmake`): Used by the example's `CMakeLists.txt` for `find_package(tvm_ffi)` and debug symbol utilities.

Design elements this commit produces: None -- purely consumes existing patterns.

## Usage Examples
**Context**: The packaging example demonstrates the canonical pattern for building a tvm-ffi extension wheel.

```python
# Python side: load a co-packaged native library and call its functions
import tvm_ffi

# 1. Load shared library (base.py pattern)
lib = tvm_ffi.load_module("/path/to/tvm_ffi_extension.so")

# 2. Auto-register "tvm_ffi_extension.*" global functions into module namespace
# (done by _ffi_api.py via tvm_ffi._init_api)

# 3. Call through thin Python wrapper
from tvm_ffi_extension import add_one, raise_error
add_one(input_tensor, output_tensor)
```

```cmake
# CMake side: two modes for linking tvm_ffi
# Mode 1: Build from source (cross-compilation)
execute_process(COMMAND python -m tvm_ffi.config --sourcedir OUTPUT_VARIABLE tvm_ffi_ROOT)
add_subdirectory(${tvm_ffi_ROOT} tvm_ffi)

# Mode 2: Use pre-built pip-installed package
execute_process(COMMAND python -m tvm_ffi.config --cmakedir OUTPUT_VARIABLE tvm_ffi_ROOT)
find_package(tvm_ffi CONFIG REQUIRED)

# Then link as usual
target_link_libraries(my_extension tvm_ffi_header tvm_ffi_shared)
```
