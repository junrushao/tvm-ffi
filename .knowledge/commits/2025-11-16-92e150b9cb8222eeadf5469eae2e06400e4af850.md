# Add __all__ generation to tvm-ffi-stubgen for proper module exporting
## TL;DR
- Adds `__all__` list generation to `tvm-ffi-stubgen`, emitting all auto-generated global functions and classes between `tvm-ffi-stubgen(begin): __all__` / `tvm-ffi-stubgen(end)` markers.
- Refactors stubgen internals: extracts `utils.py` with `StubGenContext`, `StubFileUpdater`, and `StubProcessor` classes; adds comprehensive unit tests for stubgen core without CLI dependency.

## Key Exports

```python
class StubGenContext:
    """Shared context for stub generation holding registry state."""
    # Interacts with: StubProcessor, StubFileUpdater
    # Invariant: must be initialized from a live tvm_ffi registry

class StubFileUpdater:
    """Updates marker-delimited regions in .py files with generated stubs."""
    # Interacts with: StubGenContext, file system

class StubProcessor:
    """Orchestrates stub generation for a package or single file."""

# New marker directive:

#     "Array",

# Interacts with: tvm-ffi-stubgen CLI, Python module __all__ export mechanism
```

## Impact
- API: new `__all__` marker directive for stubgen; no breaking changes
- Behavioral: running `tvm-ffi-stubgen python` now also populates `__all__` blocks
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `tvm-ffi-stubgen` CLI and inline stub generation (0012-python-bindings): extends the existing marker-based system.
- Global function registry (0003-function-system, 0008-reflection): reads registered names to populate `__all__`.

Design elements this commit produces:
- `__all__` marker directive for stubgen — new stub generation target alongside existing type stubs.
- `StubGenContext`/`StubFileUpdater`/`StubProcessor` refactored classes in `python/tvm_ffi/stub/utils.py`.
