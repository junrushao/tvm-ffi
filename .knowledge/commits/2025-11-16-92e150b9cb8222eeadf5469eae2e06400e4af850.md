# Add `__all__` directive to stubgen and refactor codegen into data-oriented FuncInfo/ObjectInfo classes

## TL;DR
- Adds a new `__all__` directive (`# tvm-ffi-stubgen(begin): __all__`) that generates a sorted `__all__` list of all auto-generated global functions and classes for a file, enabling proper Python module exporting.
- Refactors codegen internals: extracts `generate_func_signature` (free function) into `FuncInfo.gen()` (method), creates `ObjectInfo` and `NamedTypeSchema` data classes that encapsulate type introspection, and moves `collect_ty_maps` logic inline into the CLI pipeline. This decouples codegen from direct FFI registry calls, making each piece independently testable.
- Adds comprehensive unit tests (`tests/python/test_stubgen.py`, 361 lines) covering `CodeBlock` parsing, `FuncInfo`/`ObjectInfo` generation, all four `generate_*` codegen functions, and the new `generate_all`.

## Impact
- API: New `__all__` directive kind added to the stubgen marker protocol. `generate_global_funcs` signature changed (takes `list[FuncInfo]` instead of `dict[str, list[str]]`). `collect_global_funcs` return type changed. `generate_func_signature` removed from `codegen.py` (moved to `FuncInfo.gen`). `collect_ty_maps` removed from `analysis.py` (inlined into `cli.py`).
- Behavioral: Files with `# tvm-ffi-stubgen(begin): __all__` markers now get a sorted `__all__` list populated with all generated function and class names. The CLI pipeline now collects `all_defined` names during Stage 2 and writes them in a new Stage 2.4.
- Flags/config: None
- Data formats/schemas: `TypeSchema.__init__` stub added to `core.pyi` for constructor usage in `NamedTypeSchema`.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/0008-reflection.md`): Uses `TypeSchema`, `_lookup_or_register_type_info_from_type_key`, `get_global_func_metadata` via the new `FuncInfo.from_global_name` and `ObjectInfo.from_type_key` wrappers.
- **Python bindings / tvm-ffi-stubgen** (`.knowledge/designs/0012-python-bindings.md`): Extends the stubgen staged pipeline with a new `__all__` directive and Stage 2.4.
- **Stub block marker protocol** (`.knowledge/commits/2025-10-12-ea02e646aea916ad18755cd6990b22ace8afd4b2.md`, `.knowledge/commits/2025-11-15-1af6d9f9648bb2547d97d455bb4464d217654fc4.md`): Adds `__all__` as a new block kind alongside existing `global`, `object`, `import`, `ty-map`.

Design elements this commit produces:
- **`__all__` directive**: New stub block kind enabling Python `__all__` export list generation from FFI metadata. Pattern: `# tvm-ffi-stubgen(begin): __all__` ... `# tvm-ffi-stubgen(end)`.
- **Data-oriented codegen model** (`FuncInfo`, `ObjectInfo`, `NamedTypeSchema`): Encapsulates FFI introspection results as testable data classes, decoupling codegen from runtime registry lookups. This is the foundation for unit-testing stubgen without CLI invocation.
- **`FN_NAME_MAP` convention**: Centralizes FFI-to-Python method name translation (e.g., `__ffi_init__` -> `__c_ffi_init__`).

## Usage Examples

### Adding `__all__` to a module file

```python
# In python/tvm_ffi/_ffi_api.py:
__all__ = [
    # tvm-ffi-stubgen(begin): __all__
    # (after running tvm-ffi-stubgen, this is auto-populated:)
    "Array",
    "ArrayGetItem",
    "Map",
    "String",
    # ... sorted list of all generated names
    # tvm-ffi-stubgen(end)
]
```

### Unit testing codegen without CLI (new pattern enabled by this commit)

```python
from tvm_ffi.core import TypeSchema
from tvm_ffi.stub.codegen import generate_all, generate_global_funcs
from tvm_ffi.stub.file_utils import CodeBlock
from tvm_ffi.stub.utils import FuncInfo, NamedTypeSchema, Options

# Create a FuncInfo without touching the FFI registry:
schema = NamedTypeSchema("pkg.add", TypeSchema("Callable", (TypeSchema("int"), TypeSchema("int"))))
func = FuncInfo(schema=schema, is_member=False)
assert func.gen(lambda x: x, indent=4) == "    def add(_0: int, /) -> int: ..."

# Test __all__ generation:
code = CodeBlock(kind="__all__", param="", lineno_start=1, lineno_end=2,
                 lines=["# begin", "# end"])
generate_all(code, names={"tvm_ffi.Array", "String"}, opt=Options())
# code.lines now contains sorted '"Array",' and '"String",' entries
```
