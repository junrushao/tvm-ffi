# Add `__all__` stub-gen block kind and refactor stubgen internals into FuncInfo/ObjectInfo helpers

## TL;DR
- Adds a new `__all__` block kind to `tvm-ffi-stubgen`, enabling auto-generation of `__all__` lists in stub-managed files (first use: `python/tvm_ffi/_ffi_api.py`).
- Refactors stub internals: extracts `FuncInfo`, `ObjectInfo`, and `NamedTypeSchema` dataclasses into `stub/utils.py`; removes `collect_ty_maps` from `analysis.py` (inlined into `cli.py` stage 1).
- Adds `FN_NAME_MAP` constant to `consts.py` for dunder-name aliasing (`__ffi_init__` -> `__c_ffi_init__`), and adds `TypeSchema.__init__` to `core.pyi` stub.

## Impact
- API: `collect_global_funcs()` return type changed from `dict[str, list[str]]` to `dict[str, list[FuncInfo]]`; `collect_ty_maps()` removed from `analysis.py` (now inlined in `cli.py`). Any direct callers of these internal functions would break.
- Behavioral: stubgen now populates `__all__` lists from registered type/function sets. Stage ordering in `cli.py` clarified: stage 1 = ty-map, stage 2 = global/object/import/`__all__`.
- Flags/config: none
- Data formats/schemas: `CodeBlock.kind` discriminant extended with `"__all__"` literal.

## Design Elements
Design elements this commit consumes:
- `0020-stub-gen`: 5-stage stubgen pipeline (`consts`, `file_utils`, `analysis`, `codegen`, `cli`). This commit refactors `codegen` and `analysis` modules and extends `file_utils.CodeBlock.kind`.
- `0006-reflection`: `_lookup_or_register_type_info_from_type_key` used in `ObjectInfo.from_type_key`.
- `0019-type-schema`: `TypeSchema.from_json_str`, `field.metadata["type_schema"]` consumed by `FuncInfo`/`ObjectInfo`.

Design elements this commit produces:
- **`FuncInfo` / `ObjectInfo` / `NamedTypeSchema`**: New intermediate IR for stubgen codegen. These decouple metadata collection from code rendering.
- **`__all__` block kind**: New stubgen marker allowing auto-generated `__all__` export lists inside any `.py` file.
- **`FN_NAME_MAP`**: Convention for dunder-name aliasing in stubs.
