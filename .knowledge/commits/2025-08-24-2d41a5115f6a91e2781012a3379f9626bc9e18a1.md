# Establish tvm_ffi as standalone Python module with Cython bindings and scikit-build-core packaging

## TL;DR
- Creates the entire `python/tvm_ffi/` package as a standalone, pip-installable Python module decoupled from the main TVM compiler. The package exposes all FFI primitives (Object, Function, NDArray, Array, Map, Module, etc.) to Python via high-performance Cython bindings.
- Introduces `pyproject.toml` with scikit-build-core as the build backend, Cython transpilation integrated into CMake, and a `tvm-ffi-config` CLI entry point for downstream C++ consumers to query include paths, library paths, and compiler flags.
- Adds a complete Python test suite covering containers, device handling, dtype, error propagation, functions, ndarray/dlpack interop, objects, strings, and access paths. Also adds `examples/get_started/` with both Python and C++ usage examples.

## Impact
- API: Entirely new Python public API. The `tvm_ffi` package did not exist before this commit. All Python-side FFI functionality is newly introduced.
- Behavioral: The FFI system is now decoupled into a standalone pip package. Users must install `tvm_ffi` separately (via `pip install ./ffi` or from the wheel). The main TVM compiler and runtime can layer on top with lightweight dependency on `tvm_ffi`.
- Flags/config: New CMake options: `TVM_FFI_BUILD_PYTHON_MODULE` (triggers Cython build and Python module install), `TVM_FFI_ATTACH_DEBUG_SYMBOLS` (adds `-g1` in release builds). New build-system dependency: `scikit-build-core>=0.10.0` and `cython` as build requirements.
- Data formats/schemas: none (Python bindings consume existing C ABI types)

## Design Elements

Design elements this commit consumes:
- C ABI layer (`c_api.h`) — all `TVMFFI*` C functions and struct layouts defined in the initial bringup commit
- Object system (`object.h`) — Object/ObjectRef pattern, type registration, make_object
- Function system (`function.h`) — packed calling convention, global function registry
- Error system (`error.h`) — ErrorObj, TLS error propagation, TVMFFITraceback
- Container types — Array, Map, String, Bytes, Shape, NDArray, Module
- DLPack interop — DLManagedTensor, DLManagedTensorVersioned
- CMake build targets — tvm_ffi_objs, tvm_ffi_shared, tvm_ffi_static, tvm_ffi_header

Design elements this commit produces:
- **Python tvm_ffi package** — standalone pip-installable module exposing the full FFI to Python with Cython-accelerated bindings
- **Cython binding layer** (`cython/*.pxi`) — native extension wrapping the C ABI, with optimized argument packing (`make_args`), result conversion (`make_ret`), and direct C-level object handle management (no ctypes overhead)
- **Object registration protocol** — `register_object(type_key)` decorator maps C++ type keys to Python classes, with automatic field/method attachment via reflection (`_add_class_attrs_by_reflection`)
- **_init_api pattern** — convention where `_ffi_api.py` modules call `_init_api(namespace, __name__)` to auto-populate their attributes from the C++ global function registry
- **Cross-language traceback reconstruction** — `TracebackManager` in `error.py` parses C++ traceback strings and reconstructs Python frame objects for seamless error reporting across the FFI boundary
- **Python-to-FFI value conversion** — `convert()` function handles automatic promotion of Python types (list -> Array, dict -> Map, str -> String, callable -> Function, DLPack objects -> NDArray)
- **PyNativeObject pattern** — classes that subclass both a Python builtin (e.g., tuple for Shape) and have a `__tvm_ffi_object__` backing Object, bridging Python native types with FFI objects
- **Module system Python API** — `Module` class with function lookup, attribute-style access, import management, source inspection, and file I/O
- **scikit-build-core packaging** — `pyproject.toml` configures wheel building with Cython transpilation, SABI support (Python >= 3.12), and source distribution that bundles C++/CMake/3rdparty sources
- **tvm-ffi-config CLI** — Python entry point for querying include paths, library paths, and compiler flags, enabling downstream C++ projects to find the installed package
- **cmake/tvm_ffi-config.cmake** — CMake config module that calls `tvm-ffi-config` to create imported targets (`tvm_ffi_header`, `tvm_ffi_shared`) for downstream `find_package(tvm_ffi)` usage
- **Torch CUDA stream integration** — automatic CUDA stream context propagation when calling FFI functions with torch tensors, using JIT-compiled C++ extension for low overhead
- **CMake build modernization** — functions renamed with `tvm_ffi_` prefix (`tvm_ffi_add_target_from_obj`, `tvm_ffi_add_msvc_flags`, `tvm_ffi_add_apple_dsymutil`, `tvm_ffi_add_prefix_map`, `tvm_ffi_add_cxx_warning`), generator-expression-based include paths for proper install/build interface separation, MSVC PDB file generation

## Usage Examples

**Installing the package:**
```bash
# From source
pip install ./ffi

# Editable install (recommended for development)
uv pip install --force-reinstall --verbose -e .
```

**Basic Python usage:**
```python
import tvm_ffi

# Create and use containers
arr = tvm_ffi.Array([1, 2, 3])
m = tvm_ffi.Map({"key": "value"})

# Register and call a function
@tvm_ffi.register_func("my.add")
def my_add(a, b):
    return a + b

f = tvm_ffi.get_global_func("my.add")
result = f(1, 2)

# Load a compiled module
mod = tvm_ffi.load_module("build/my_kernel.so")
mod.my_function(x, y)
```

**Using tvm-ffi-config in a CMake project:**
```cmake
find_package(tvm_ffi REQUIRED)
target_link_libraries(my_target PRIVATE tvm_ffi_shared)
```

**Loading a module from Python with torch tensors:**
```python
import torch
import tvm_ffi

mod = tvm_ffi.load_module("build/add_one_cuda.so")
x = torch.tensor([1, 2, 3], dtype=torch.float32, device="cuda")
y = torch.empty_like(x)
# Automatic DLPack conversion and CUDA stream propagation
mod.add_one_cuda(x, y)
```

### ADRs to write or update
- `.knowledge/ADRs/005-standalone-python-package.md` — Decision to decouple tvm_ffi into a standalone pip-installable package (separate from the main TVM compiler), enabling lightweight downstream dependencies and independent versioning. Key tradeoffs: separate install step vs monolithic package, scikit-build-core as build backend for Cython integration.
- `.knowledge/ADRs/006-cython-sabi.md` — Decision to use Python Stable ABI (SABI 3.12) for the Cython extension when Python >= 3.12, producing a single `core.abi3.so` that works across Python versions, vs per-version `.cpython-3XX.so` for older Pythons.

- MSVC pragma fix: `#pragma disagnostic` corrected to `#pragma warning` in `error.h`. Prior references to the typo are now stale.
