# Establish tvm_ffi as a standalone pip-installable Python module with Cython bindings and improved traceback infrastructure

## TL;DR

- Introduces the complete `tvm_ffi` Python package (`python/tvm_ffi/`) with Cython bindings (`cython/core.pyx` + seven `.pxi` files) that wrap the C ABI; package is now independently installable via `pip install ./ffi`.
- Adds `pyproject.toml` using `scikit-build-core` + Cython backend; CMake gains `TVM_FFI_BUILD_PYTHON_MODULE` option and a root-project guard so the library can be consumed as a CMake subproject without triggering tests or wheel installs.
- Refactors `TVMFFITraceback` C ABI signature (adds `cross_ffi_boundary` parameter); renames internal helpers `ShouldStopTraceback` → `DetectFFIBoundary`, `backtrace_handler` → `TVMFFISegFaultHandler`, `install_signal_handler` → `TVMFFIInstallSignalHandler`; adds `skip_frame_count` and `stop_at_boundary` fields to `TracebackStorage`.

## Impact

- API: `TVMFFITraceback` gains a 4th parameter `cross_ffi_boundary` — **breaks** any caller that previously called it with 3 args (e.g., language bindings outside this repo that call `TVMFFITraceback` directly via C ABI).
- Behavioral: Traceback now stops at FFI boundary by default when `cross_ffi_boundary=0`; `TracebackStorage.skip_frame_count` skips 2 frames (TVMFFITraceback + caller) to avoid duplicating the injected filename/func in the trace. Symbol-based filtering in `ShouldExcludeFrame` is now the primary check (over filename-based), improving correctness when debug symbols are absent.
- Flags/config: New CMake option `TVM_FFI_BUILD_PYTHON_MODULE` (default OFF); `TVM_FFI_ATTACH_DEBUG_SYMBOLS` (default OFF, adds `-g1`). `TVM_FFI_BUILD_TESTS` moved inside root-project guard.
- Data formats/schemas: none.

## Design Elements

Design elements this commit consumes:
- **0001-c-abi** — `TVMFFITraceback`, `TVMFFIObjectFree`, `TVMFFIFunctionCall`, `TVMFFIAny` wire struct, all DLL-exported functions accessed from Cython.
- **0002-object-system** — `Object` base class mapped to Cython `cdef class Object` (chandle); `@register_object` pattern.
- **0004-function-system** — `Function` wrapped in Cython; global function registry accessed via `get_global_func` / `register_func`.
- **0005-error-system** — `register_error` exposed in public API.
- **0007-containers** — `Array`, `Map`, `String`, `Bytes`, `NDArray`, `Shape`, `Device` all exposed.
- **0011-module-system** — `Module`, `ModulePropertyMask`, `load_module`, `system_lib` exposed.

Design elements this commit produces:
- **Python package layout** — `tvm_ffi` as a standalone pip-installable module (`pyproject.toml` + Cython build); canonical loading order: `base` → `libinfo` → `registry` → domain modules.
- **Library discovery protocol** — `libinfo.py` defines the search path hierarchy (package/lib → ../../build/lib → env vars); `_load_lib()` with `RTLD_GLOBAL`.
- **`_init_api` convention** — auto-populate a Python module from global function names by namespace prefix; used by `_ffi_api.py` and intended for downstream packages.
- **`@register_object` pattern** — decorator that wires a Python class to a C++ type index via reflection; `_SKIP_UNKNOWN_OBJECTS` flag for graceful forward-compatibility.
- **`tvm-ffi-config` CLI** — path discovery tool for downstream C++ consumers building against the installed package.
- **`TVMFFITraceback` v2** — `cross_ffi_boundary` parameter + `TracebackStorage.skip_frame_count` / `stop_at_boundary`; `DetectFFIBoundary` replaces `ShouldStopTraceback`; `TVMFFISegFaultHandler` / `TVMFFIInstallSignalHandler` renamed to public-symbol naming convention.

## Usage Examples

End-to-end: load a kernel .so and call it from Python (from `examples/get_started/run_example.py`):

```python
import tvm_ffi
import numpy

# Load a compiled kernel module
mod = tvm_ffi.load_module("build/add_one_cpu.so")

x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
# Attribute access on Module triggers ModuleGetFunction → packed call
mod.add_one_cpu(x, y)   # DLPack-compatible tensors auto-converted

# Global function registry
fn = tvm_ffi.get_global_func("ffi.FunctionListGlobalNamesFunctor")()
names = [fn(i) for i in range(fn(-1))]

# Register a Python function globally
@tvm_ffi.register_func("my.custom_op")
def custom_op(x: int) -> int:
    return x + 1
```

Object type registration (cross-layer: C++ reflection → Python class):

```python
# C++ side: TVM_FFI_STATIC_INIT_BLOCK { ObjectDef<MyObj>("my.MyType") ... }
# Python side:
import tvm_ffi

@tvm_ffi.register_object("my.MyType")
class MyType(tvm_ffi.Object):
    pass  # fields added via core._add_class_attrs_by_reflection at decoration time
```
