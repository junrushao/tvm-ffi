# Establish tvm_ffi as a standalone installable Python package with Cython bindings and improved traceback control

## TL;DR
- Introduces the `tvm_ffi` Python package (`python/tvm_ffi/`) with full Cython bindings covering Object, Function, NDArray, Device, DataType, String, Error, and Module; adds `pyproject.toml` for `pip install` via `scikit-build-core`.
- Adds `examples/get_started/` with a runnable end-to-end example (CPU add-one and CUDA add-one via shared library loaded at runtime via `tvm_ffi.load_module`).
- Improves traceback control: `TVMFFITraceback` gains a `cross_ffi_boundary` parameter controlling whether to stop at the FFI boundary or capture across it; `TracebackStorage` gains `stop_at_boundary` and `skip_frame_count` fields; `ShouldStopTraceback` is renamed `DetectFFIBoundary`.

## Impact
- API: `TVMFFITraceback` C ABI signature changed — added `int cross_ffi_boundary` parameter. All callers in `TVM_FFI_THROW` and `TVM_FFI_LOG_AND_THROW` macros updated to pass `0`. Any external code calling `TVMFFITraceback` directly must add the new argument.
- Behavioral: `ShouldExcludeFrame` now checks `symbol` prefix first (before `filename`), adding `tvm::ffi::Function` and `tvm::ffi::details::` symbol exclusions. `DetectFFIBoundary` (renamed from `ShouldStopTraceback`) now only fires when `stop_at_boundary=true`. `TVM_FFI_DECLARE_FINAL_OBJECT_INFO` adds `[[maybe_unused]]` on `_type_child_slots` and `_type_final` to suppress MSVC warnings.
- Flags/config: New CMake option `TVM_FFI_BUILD_PYTHON_MODULE=ON` (consumed by `scikit-build-core`). `tvm_ffi_extra_objs_sources` extracted as named list in CMakeLists. Build type changed from `RelWithDebugInfo` to `Release` in `scripts/run_tests.sh`.
- Data formats/schemas: `TVM_FFI_TRACEBACK_HERE` macro removed; its expansion inlined into `TVM_FFI_THROW`. MSVC `#pragma disagnostic` typo fixed to `#pragma warning`.

## Design Elements
Design elements this commit consumes:
- **0001-ffi-c-abi**: `TVMFFIAny`, `TVMFFIObject`, `TVMFFIFunctionCall`, `TVMFFIObjectFree`, `TVMFFIErrorSetRaised` — Cython bindings expose all these via `cython/base.pxi` C declarations.
- **0003-ffi-object-system**: `Object`/`ObjectRef` pattern consumed by Cython `Object` cdef class; `_object_type_key_to_index` / `_register_object_by_index` used in `register_object`.
- **0004-ffi-function-system**: `Function` object and global registry accessed via `get_global_func` / `register_func` / `_init_api`.
- **0005-ffi-error-protocol**: `ErrorObj` consumed by Cython `Error` cdef class; `TVMFFIErrorCreate` / `TVMFFIErrorMoveFromRaised` used directly.
- **0011-ffi-module-system**: `Module`/`ModuleObj` consumed by `module.py`; `load_module` calls `_ffi_api.ModuleLoadFromFile`.

Design elements this commit produces:
- **Python package layout convention**: `python/tvm_ffi/` as standalone pip-installable package with `pyproject.toml` + `scikit-build-core`; `libinfo.py` for library discovery; `base.py` as mandatory first import to load the `.so`.
- **`_init_api` namespace injection pattern**: strips `tvm.` prefix from a namespace, scans global func registry for matching names, injects as module-level attributes. Reused across `_ffi_api.py` and any downstream package that layers atop `tvm_ffi`.
- **Cython extension type hierarchy**: `Object` (base cdef class) → subclasses (`Function`, `Error`, `String`, `NDArray`, `Device`, etc.) all share `void* chandle`; dispatch table keyed by `type_index` from C++ reflection.
- **TracebackManager**: Python-side traceback reconstruction that creates synthetic `FrameType` objects from C++ backtrace strings; attached via `_WITH_APPEND_TRACEBACK` hook.
- **`TVMFFITraceback` cross-boundary flag**: `cross_ffi_boundary` parameter enabling callers to choose boundary-stop vs. full cross-FFI traceback capture.

## Usage Examples

**End-to-end: loading a compiled `.so` and calling a kernel (from `examples/get_started/run_example.py`)**

```python
import tvm_ffi
import numpy

# Load a compiled shared library that exports __tvm_ffi_<name> symbols
mod = tvm_ffi.load_module("build/add_one_cpu.so")

x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)  # numpy arrays auto-converted via DLPack
```

**Registering a Python function and an object type:**

```python
import tvm_ffi

@tvm_ffi.register_func("my.add")
def my_add(a: int, b: int) -> int:
    return a + b

@tvm_ffi.register_object("my.MyNode")
class MyNode(tvm_ffi.Object):
    pass  # reflection attrs injected by register_object

f = tvm_ffi.get_global_func("my.add")
print(f(1, 2))  # 3
```

**Cross-FFI traceback — C++ error surfaced in Python with reconstructed stack:**

```python
# C++ throws TVM_FFI_THROW(ValueError) << "bad input"
# Cython error.pxi catches it, calls Error.py_error()
# TracebackManager reconstructs Python-visible frames from C++ backtrace string
# Result: Python ValueError with both Python and C++ frames in __traceback__
f = tvm_ffi.get_global_func("some.c_func_that_throws")
try:
    f()
except ValueError as e:
    # e.__tvm_ffi_error__ holds the raw Error object
    print(e.__tvm_ffi_error__.traceback)
```
