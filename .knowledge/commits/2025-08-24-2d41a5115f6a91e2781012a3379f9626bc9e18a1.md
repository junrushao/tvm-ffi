# Establish tvm_ffi as a standalone pip-installable Python module with improved traceback
## TL;DR
- Introduces the `tvm_ffi` Python package (`python/tvm_ffi/`) as a standalone pip-installable module with `pyproject.toml`, `scikit-build-core` integration, Cython bindings, and zero required dependencies -- enabling lightweight downstream consumers.
- Refactors `TVMFFITraceback` C API to accept a `cross_ffi_boundary` parameter and caller file/line info, enabling cleaner FFI boundary detection and frame skipping. Removes the `TVM_FFI_TRACEBACK_HERE` macro in favor of direct `TVMFFITraceback()` calls.
- Adds `examples/get_started/` demonstrating the end-to-end workflow: build a C++ kernel library, pip-install `tvm_ffi`, load and call from Python with numpy/torch interop.

## Key Exports

**Python package: `tvm_ffi`** (new top-level module)

Core re-exports from `tvm_ffi/__init__.py`:
- `register_object(type_key: str) -> decorator` -- register Python class for FFI object type
- `register_func(func_name: str, f=None, override=False) -> Function` -- register global packed function
- `get_global_func(name: str, allow_missing=False) -> Function | None` -- look up global function
- `_init_api(namespace: str, target_module_name=None)` -- bulk-import registered functions into a module
- `Module` (class, registered as `"ffi.Module"`) -- runtime module wrapper with `get_function`, `load_module`, attribute-based function access
- `Array` (class, registered as `"ffi.Array"`) -- immutable sequence container
- `Map` (class, registered as `"ffi.Map"`) -- immutable mapping container
- `Shape` (class, registered as `"ffi.Shape"`) -- tuple subclass for shape objects
- `load_module(path: str) -> Module` -- load shared library as Module
- `system_lib(symbol_prefix="") -> Module` -- get system-wide library singleton
- `ModulePropertyMask` (IntEnum) -- `BINARY_SERIALIZABLE=0b001`, `RUNNABLE=0b010`, `COMPILATION_EXPORTABLE=0b100`

**CLI entry point**: `tvm-ffi-config` -> `tvm_ffi.config:__main__` (flags: `--includedir`, `--dlpack-includedir`, `--cmakedir`, `--libdir`, `--libfiles`, `--cxxflags`, `--ldflags`, `--libs`, `--cython-lib-path`, `--sourcedir`)

**C API change**:
```c
// Before:
const TVMFFIByteArray* TVMFFITraceback(const char* filename, int lineno, const char* func);
// After:
const TVMFFIByteArray* TVMFFITraceback(const char* filename, int lineno, const char* func,
                                       int cross_ffi_boundary);
```

**Removed macros**:
- `TVM_FFI_TRACEBACK_HERE` -- replaced by direct `TVMFFITraceback(__FILE__, __LINE__, TVM_FFI_FUNC_SIG, 0)` calls

**Renamed internal C++ functions**:
- `ShouldStopTraceback()` -> `DetectFFIBoundary()`
- `backtrace_handler()` -> `TVMFFISegFaultHandler()`
- `install_signal_handler()` -> `TVMFFIInstallSignalHandler()`

**Renamed CMake functions** (prefixed with `tvm_ffi_`):
- `add_msvc_flags` -> `tvm_ffi_add_msvc_flags`
- `add_target_from_obj` -> `tvm_ffi_add_target_from_obj`
- `add_dsymutil` -> `tvm_ffi_add_apple_dsymutil`

**New CMake function**:
- `tvm_ffi_add_prefix_map(target_name, prefix_path)` -- adds `-ffile-prefix-map` for relative traceback paths

**New CMake config**: `cmake/tvm_ffi-config.cmake` -- enables `find_package(tvm_ffi)` via Python introspection

**C++ object.h**: `TVM_FFI_DECLARE_FINAL_OBJECT_INFO` now annotates `_type_child_slots` and `_type_final` with `[[maybe_unused]]`.

## Impact
- API: **Breaking C ABI change** -- `TVMFFITraceback` gains a 4th parameter `cross_ffi_boundary`. All callers (Cython `base.pxi`, C++ macros) must be updated. The removed `TVM_FFI_TRACEBACK_HERE` macro breaks any external code using it.
- Behavioral: Traceback now supports `cross_ffi_boundary` mode (0 = stop at boundary, 1 = cross boundary). Frame skipping (`skip_frame_count`) ensures caller file/line is accurate rather than showing internal frames. MSVC `#pragma` typo `disagnostic` fixed to `warning`.
- Flags/config: New CMake options `TVM_FFI_BUILD_PYTHON_MODULE`, `TVM_FFI_ATTACH_DEBUG_SYMBOLS`. Minimum CMake bumped from 3.14 to 3.18. Root-project guard (`if (NOT ${PROJECT_NAME} STREQUAL ${CMAKE_PROJECT_NAME}) return()`) separates subproject vs root logic.
- Data formats/schemas: New `pyproject.toml` defines package `apache-tvm-ffi` version `0.1.0a0` with `scikit-build-core` backend.

## Usage Examples

**End-to-end: build C++ kernel, load from Python**
```cpp
// src/add_one_cpu.cc
#include <tvm/ffi/function.h>
void AddOne(DLTensor* x, DLTensor* y) {
  for (int i = 0; i < x->shape[0]; ++i)
    static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne);
```
```python
# run_example.py
import tvm_ffi
import numpy
mod = tvm_ffi.load_module("build/add_one_cpu.so")
x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)   # numpy arrays auto-converted via DLPack
```

**Downstream CMake project using tvm_ffi**
```cmake
find_package(tvm_ffi REQUIRED PATHS "${CMAKE_CURRENT_LIST_DIR}/cmake")
add_library(my_kernel SHARED src/my_kernel.cc)
target_link_libraries(my_kernel PRIVATE tvm_ffi_shared)
```
