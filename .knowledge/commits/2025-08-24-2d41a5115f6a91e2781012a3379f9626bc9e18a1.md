# Establish tvm_ffi as a standalone Python package with Cython bindings, packaging, and traceback improvements
## TL;DR
- Creates the entire `python/tvm_ffi/` package (20+ new Python files, 8 Cython `.pxi` files, ~4400 new lines) as a standalone, pip-installable Python module (`apache-tvm-ffi`) backed by `scikit-build-core` and Cython. The package exposes Object, Function, Array, Map, NDArray, Module, Shape, error handling, serialization, and access-path APIs from the C++ FFI to Python.
- Restructures the CMake build system to support both standalone C++ library use (via `add_subdirectory`) and Python wheel builds (via `TVM_FFI_BUILD_PYTHON_MODULE`), including Cython transpilation, Stable ABI (SABI 3.12+) support, cmake config file for downstream consumers (`tvm_ffi-config.cmake`), and a `tvm-ffi-config` CLI entry point for C++ toolchain discovery.
- Extends `TVMFFITraceback` C API with a `cross_ffi_boundary` parameter, improves traceback frame filtering and FFI boundary detection, fixes MSVC `#pragma` typos in `error.h`, and removes the internal `TVM_FFI_TRACEBACK_HERE` macro in favor of direct `TVMFFITraceback` calls.

## Impact
- **API**:
  - **Python public API**: The entire `tvm_ffi` Python package is new. Top-level exports: `register_object`, `register_func`, `get_global_func`, `convert`, `String`, `Bytes`, `Object`, `Function`, `Array`, `Map`, `NDArray`, `Shape`, `Module`, `load_module`, `Device`, device constructors (`cpu`, `cuda`, `rocm`, etc.), `from_dlpack`, `dtype`, `register_error`, `serialization`, `access_path`, `testing`.
  - **C ABI**: `TVMFFITraceback` signature changes from `(const char*, int, const char*)` to `(const char*, int, const char*, int)` -- the new fourth parameter `cross_ffi_boundary` controls whether the traceback stops at or crosses the FFI call boundary. This is a **breaking** C ABI change for any direct caller of `TVMFFITraceback`.
  - **C++ API**: `TVM_FFI_TRACEBACK_HERE` macro is removed from `error.h`. `TVM_FFI_THROW` and `TVM_FFI_LOG_AND_THROW` now call `TVMFFITraceback` directly with `cross_ffi_boundary=0`. `TVM_FFI_DECLARE_FINAL_OBJECT_INFO` adds `[[maybe_unused]]` to `_type_child_slots` and `_type_final` to suppress warnings.
  - **CMake**: New option `TVM_FFI_BUILD_PYTHON_MODULE`, new option `TVM_FFI_ATTACH_DEBUG_SYMBOLS`. CMake minimum bumped from 3.14 to 3.18. Function names prefixed with `tvm_ffi_` (`tvm_ffi_add_target_from_obj`, `tvm_ffi_add_msvc_flags`, `tvm_ffi_add_apple_dsymutil`, `tvm_ffi_add_prefix_map`).
  - **CLI**: New entry point `tvm-ffi-config` (maps to `tvm_ffi.config:__main__`) exposes `--includedir`, `--libdir`, `--cmakedir`, `--cxxflags`, `--ldflags`, etc.
- **Flags/config**: `TVM_FFI_BUILD_PYTHON_MODULE` (new), `TVM_FFI_ATTACH_DEBUG_SYMBOLS` (new). The `pyproject.toml` defines the package as `apache-tvm-ffi` version `0.1.0a0`.
- **Data formats/schemas**: None.

## Design Elements

Design elements this commit **consumes**:

- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`]): The Cython bindings in `base.pxi` declare all `TVMFFITypeIndex` enums, `TVMFFIAny`, `TVMFFIObject`, `TVMFFIByteArray`, `TVMFFIShapeCell`, `TVMFFIErrorCell`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, `TVMFFITypeInfo`, and all `TVMFFI*` C functions. These are the foundational C ABI symbols that the Python layer wraps.
- **Object System** ([`.knowledge/designs/0003-object-system.md`]): `cython/object.pxi` defines a Cython `Object` extension type holding a `void* chandle`, with ref-counting via `TVMFFIObjectFree`. The `register_object` decorator in `registry.py` maps type keys to Python classes via `_object_type_key_to_index` and `_register_object_by_index`.
- **Function System** ([`.knowledge/designs/0004-function-system.md`]): `cython/function.pxi` wraps `TVMFFIFunctionCall`, `TVMFFIFunctionCreate`, `TVMFFIFunctionSetGlobal`, `TVMFFIFunctionGetGlobal`. The `_init_api` mechanism in `registry.py` auto-populates Python modules with global functions by prefix matching.
- **Error Handling** ([`.knowledge/designs/0007-error-handling.md`]): `cython/error.pxi` wraps `Error` as a Cython extension type with `TVMFFIErrorCreate`, `TVMFFIErrorMoveFromRaised`, `TVMFFIErrorSetRaised`. `error.py` implements `TracebackManager` that synthesizes Python `types.TracebackType` frames from C++ traceback strings, enabling unified cross-language stack traces.
- **Containers** ([`.knowledge/designs/0005-containers.md`]): `container.py` wraps `Array` and `Map` as Python `collections.abc.Sequence` and `collections.abc.Mapping` respectively, delegating to `ffi.ArrayGetItem`, `ffi.ArraySize`, `ffi.MapGetItem`, `ffi.MapCount`, `ffi.MapForwardIterFunctor`.
- **Module System** ([`.knowledge/designs/0013-module-system.md`]): `module.py` wraps `ModuleObj` as `Module(core.Object)`, registered with type key `"ffi.Module"`. Delegates to `ffi.ModuleGetFunction`, `ffi.ModuleLoadFromFile`, `ffi.SystemLib`, etc.
- **Reflection** ([`.knowledge/designs/0006-reflection.md`]): `register_object` calls `core._add_class_attrs_by_reflection(type_index, cls)` to populate Python classes with fields and methods from the C++ reflection registry.
- **Extra API Tier** ([`.knowledge/designs/0011-extra-api-tier.md`]): The `TVM_FFI_USE_EXTRA_CXX_API` flag is restructured in CMake to separate `tvm_ffi_extra_objs_sources` from `tvm_ffi_objs_sources`, then conditionally appended.

Design elements this commit **produces**:

- **Python Package Architecture**: A new standalone pip-installable package `python/tvm_ffi/` with a clear layered import structure:
  - `base.py` loads `libtvm_ffi` via `ctypes.CDLL(lib_path, ctypes.RTLD_GLOBAL)`.
  - `libinfo.py` handles platform-specific library discovery (`find_libtvm_ffi`, `find_include_path`, `find_cmake_path`, etc.).
  - `cython/core.pyx` includes all `.pxi` files for the Cython extension module.
  - `config.py` provides the `tvm-ffi-config` CLI for C++ toolchain integration.
  - `_ffi_api.py` uses `_init_api("ffi", __name__)` to auto-populate with global functions prefixed `"ffi."`.
  - `convert.py` provides `convert()` for Python-to-FFI value conversion, installed via `core._set_func_convert_to_object`.
  - `registry.py` provides `register_object`, `register_func`, `get_global_func`, `_init_api`.

- **Scikit-build-core Packaging** (`pyproject.toml`): Build system based on `scikit-build-core >= 0.10.0` with Cython. Builds Cython module via cmake custom command, links against `tvm_ffi_shared`, produces wheel with SABI 3.12+ support (Python >= 3.12 uses `USE_SABI`, older uses `WITH_SOABI`). Installs headers, cmake config, source, and 3rdparty into the wheel for downstream C++ compilation.

- **CMake Config for Downstream Consumers** (`cmake/tvm_ffi-config.cmake`): A `find_package(tvm_ffi CONFIG)` config file that uses `python -m tvm_ffi.config` to locate include dirs, library files, and dlpack headers. Creates `tvm_ffi_header` (INTERFACE) and `tvm_ffi_shared` (IMPORTED SHARED) targets for downstream CMake projects.

- **Improved Traceback with FFI Boundary Control**: `TVMFFITraceback` now accepts `cross_ffi_boundary` (0 = stop at boundary, non-zero = cross). The traceback logic is moved out of the anonymous namespace into file scope. New features:
  - `TracebackStorage::skip_frame_count` skips N initial frames (used to skip `TVMFFITraceback` itself and the caller when filename/func are provided).
  - `DetectFFIBoundary` (renamed from `ShouldStopTraceback`) detects `TVMFFIFunctionCall`, Python ABI symbols (`slot_tp_call`, `_Py*`, `PyObject*`).
  - Frame exclusion now prioritizes symbol-based checks over filename-based checks, adding `tvm::ffi::Function*`, `tvm::ffi::details::*`, `TVMFFITraceback`, `TVMFFIErrorSetRaisedFromCStr` patterns.
  - On MSVC, `TVMFFIFunctionCall` uses `volatile int ret` to prevent tail-call optimization, ensuring the symbol appears in the call stack for reliable FFI boundary detection.

- **Get-Started Example** (`examples/get_started/`): A complete working example demonstrating the downstream consumer workflow: CMakeLists.txt using `find_package(tvm_ffi CONFIG)`, C++ kernel libraries (`add_one_cpu.cc`, `add_one_cuda.cu`), a C++ runner (`run_example.cc`), a Python runner (`run_example.py`), and a shell script (`run_example.sh`).

- **Python Test Suite** (`tests/python/`): 9 new test files covering access_path, container, device, dtype, error, function, ndarray, object, and string.

### ADRs to write

- **`.knowledge/ADRs/0021-standalone-python-package.md`**: Decision to extract `tvm_ffi` as a standalone pip-installable package separate from the main TVM Python package. Context: the main TVM package has heavy dependencies; downstream library plugins need lightweight FFI access. Alternatives: (a) keep FFI inside `tvm.runtime` (simpler but couples all users to full TVM), (b) publish as separate wheel with no source (loses C++ header distribution for downstream compilation). Trade-off: standalone package adds packaging complexity but enables lightweight plugin development and independent versioning.

- **`.knowledge/ADRs/0022-traceback-boundary-parameter.md`**: Decision to add `cross_ffi_boundary` parameter to `TVMFFITraceback` (breaking C ABI change). Context: when Python calls C++ which calls Python which calls C++, the traceback should either stop at the immediate FFI boundary (for error display) or cross it (for segfault handlers). Alternatives: (a) always stop at boundary (loses context in nested calls), (b) always cross (produces noisy tracebacks with Python interpreter frames). Trade-off: the parameter adds flexibility at the cost of a C ABI break.

### Skill evolution (`/commit-ledger`)

The skill procedure does not account for squashed commits where the commit message contains multiple logical changes. Consider adding a step in Step 1 that detects multi-message commits and creates sub-sections in the analysis for each logical change.

- **Python file categorization heuristic**: For commits that add an entire Python package (20+ new files), the procedure would benefit from a categorization step: separate "binding layer" files (Cython `.pxi`/`.pyx`) from "pure Python wrappers" (`.py` files that delegate to `_ffi_api`) from "standalone logic" files (like `error.py`'s `TracebackManager` or `libinfo.py`'s path discovery). This would help organize the design elements more cleanly.

## Self-Evolution of Skill /commit-ledger

- The procedure focuses heavily on C++ design elements since the repo was historically C++-only. Now that a full Python package exists, Step 3 should explicitly prompt for mining Python-specific design patterns: decorator-based registration (`@register_object`), callback wiring (`core._WITH_APPEND_TRACEBACK = ...`), auto-population via `_init_api`, and the `PyNativeObject` dual-inheritance pattern. These are recurring patterns that future Python-side commits will consume.

- For packaging-related commits, the skill should consider adding a packaging-specific checklist: (a) does the change affect wheel contents? (b) does it affect the `tvm-ffi-config` CLI output? (c) does it affect downstream `find_package(tvm_ffi)` behavior? These are easy to overlook but have high impact on downstream users.

- The `examples/` directory is a valuable signal for "intended usage patterns" that the skill currently ignores. Consider adding guidance in Step 3 to check examples as evidence of how design elements are expected to be composed by downstream consumers.
