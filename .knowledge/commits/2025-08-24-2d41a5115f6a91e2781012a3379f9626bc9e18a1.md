# Establish tvm_ffi as a standalone Python module with Cython bindings

## TL;DR
- Creates the entire `python/tvm_ffi/` package as a standalone, pip-installable Python module backed by Cython bindings to the C shared library.
- Adds a `pyproject.toml` using `scikit-build-core` as build backend to compile C++/Cython and produce a wheel (`apache-tvm-ffi`).
- Provides the full Cython binding layer (8 `.pxi` files + `core.pyx`) covering Object, Function, NDArray, Device, DataType, Error, String handling, and the complete C API surface.
- Creates pure-Python wrapper modules: `registry.py`, `error.py`, `convert.py`, `dtype.py`, `ndarray.py`, `container.py`, `module.py`, `serialization.py`, `access_path.py`, `testing.py`, `config.py`, `libinfo.py`.
- Restructures CMakeLists.txt to support both standalone build and inclusion as a subproject, adds Cython compilation, wheel packaging, and install targets.
- Extends `TVMFFITraceback` C API with a `cross_ffi_boundary` parameter and rewrites traceback collection to be boundary-aware.
- Adds a `tvm_ffi-config.cmake` for downstream C++ projects to discover tvm_ffi via Python.
- Includes `examples/get_started/` with CPU/CUDA add-one examples (C++ and Python).
- Adds 9 Python test files covering functions, objects, containers, NDArray, device, dtype, error, string, and access paths.

### Cython Extension Module: `tvm_ffi.cython.core`

The Cython layer is compiled from `core.pyx` which includes 7 `.pxi` files:

- **`base.pxi`**: C API extern declarations (`TVMFFITypeIndex` enum, `TVMFFIAny`, `TVMFFIObject`, `DLDataType`, `DLDevice`, `DLTensor`, etc.), `ByteArrayArg` helper, `_init_env_api()` registering `PyErr_CheckSignals`/`PyGILState_Ensure`/`PyGILState_Release`.
- **`dtype.pxi`**: `DataType` cdef class wrapping `DLDataType`, with `type_code`/`bits`/`lanes`/`itemsize` properties, `__str__`/`__repr__`/`__eq__`/`__reduce__`.
- **`device.pxi`**: `Device` cdef class wrapping `DLDevice`, with `DEVICE_TYPE_TO_NAME`/`DEVICE_NAME_TO_TYPE` mappings, string parsing (`"cuda:0"`), `__eq__`/`__hash__`/`__reduce__`.
- **`object.pxi`**: `Object` cdef class with `chandle` (`TVMFFIObjectHandle`), ref-counting (`__dealloc__`), `__init_handle_by_constructor__`, type index lookup. `PyNativeObject` base class for Python-native wrappers (e.g. `Shape`). `ObjectGeneric` abstract base. Reflection helpers `_add_class_attrs_by_reflection`, `_object_type_key_to_index`, `_register_object_by_index`.
- **`error.pxi`**: Error handling -- `CHECK_CALL` macro-like function, `_RAISE_LAST_FFI_ERROR()` which reconstructs Python tracebacks from C++ traceback strings, error type registry (`ERROR_NAME_TO_TYPE`/`ERROR_TYPE_TO_NAME`), `_WITH_APPEND_TRACEBACK`/`_TRACEBACK_TO_STR` hooks.
- **`string.pxi`**: `String`/`Bytes` subclasses of `Object`, with lazy Python string/bytes caching, `__str__`/`__repr__`/`__eq__`/`__hash__`.
- **`ndarray.pxi`**: `NDArray` cdef class wrapping DLTensor, with `shape`/`dtype`/`device` properties, DLPack import/export (`from_dlpack`/`__dlpack__`/`__dlpack_device__`), numpy conversion (`numpy()`/`from_numpy()`), `copyfrom`/`copyto`.
- **`function.pxi`**: `Function` cdef class, packed calling convention (`__call__`), argument packing (`make_arg`), return value unpacking (`make_ret_value`), global function get/set (`_get_global_func`/`_register_global_func`), Python-to-FFI function wrapping (`_convert_to_ffi_func`), `_set_func_convert_to_object`.

### C/C++ API Changes

**`TVMFFITraceback` signature change** (ABI-breaking):
```c
// Before:
const TVMFFIByteArray* TVMFFITraceback(const char* filename, int lineno, const char* func);
// After:
const TVMFFIByteArray* TVMFFITraceback(const char* filename, int lineno, const char* func, int cross_ffi_boundary);
```
When `cross_ffi_boundary == 0`, traceback stops at FFI boundaries (Python interpreter frames, `TVMFFIFunctionCall`). When `cross_ffi_boundary == 1`, it captures the full call stack.

**`TVM_FFI_TRACEBACK_HERE` macro removed** -- callers now invoke `TVMFFITraceback(...)` directly.

**`TVM_FFI_THROW` / `TVM_FFI_LOG_AND_THROW` macros updated** to pass `cross_ffi_boundary=0`.

**`TVMFFIErrorSetRaisedFromCStr`** now passes `nullptr` for filename/func (skip caller frame info).

**MSVC pragma fix**: `#pragma disagnostic` corrected to `#pragma warning(push/pop)` in `error.h`.

**`[[maybe_unused]]` added** to `_type_child_slots` and `_type_final` in `TVM_FFI_DECLARE_FINAL_OBJECT_INFO`.

### CMake Changes

- `cmake_minimum_required` raised from 3.14 to 3.18.
- All CMake function names prefixed with `tvm_ffi_` to avoid collisions when used as a subproject (`add_cxx_warning` -> `tvm_ffi_add_cxx_warning`, `add_target_from_obj` -> `tvm_ffi_add_target_from_obj`, etc.).
- New `tvm_ffi_add_prefix_map()` function for `-ffile-prefix-map` to produce relative paths in tracebacks.
- New option `TVM_FFI_ATTACH_DEBUG_SYMBOLS` (adds `-g1`).
- New option `TVM_FFI_BUILD_PYTHON_MODULE` -- triggers Cython compilation, `Python_add_library`, and install rules for the wheel.
- Python 3.12+ uses Stable ABI (`USE_SABI 3.12`), older Python uses `WITH_SOABI`.
- Install targets now ship headers, dlpack headers, cmake config, source, and shared library.
- New `cmake/tvm_ffi-config.cmake` -- a CMake config file that calls `python -m tvm_ffi.config` to discover headers and libraries, enabling `find_package(tvm_ffi)` for downstream projects.
- Root-project-only logic guarded by `if (NOT ${PROJECT_NAME} STREQUAL ${CMAKE_PROJECT_NAME}) return() endif()`.
- MSVC: produces PDB files (`/DEBUG`), changed `/Z7` to `/Zi`.
- Windows: output directory per-config-type fix for MSBuild.

## Impact

- **API**: Major. Creates the entire `tvm_ffi` Python package from scratch. This decouples the FFI as a standalone installable package, enabling lightweight downstream dependencies.
- **ABI**: Breaking. `TVMFFITraceback` gains a 4th parameter (`cross_ffi_boundary`). All callers must be recompiled.
- **Behavioral**: Traceback collection is now boundary-aware: by default (`cross_ffi_boundary=0`) it stops at Python interpreter frames or `TVMFFIFunctionCall`, producing cleaner tracebacks. Frame skip logic added (skip 2 frames for the `TVMFFITraceback` function itself and its caller). Filename/func can now be `nullptr` to skip caller-supplied frame info. New FFI boundary detection patterns: `slot_tp_call`, `object_is_not_callable`, corrected `strncmp` length for `TVMFFIFunctionCall` (14->18) and `PyObject` (9->8).
- **Build**: The project now builds as a Python wheel via `scikit-build-core`. The CMake build supports being included as a subproject (non-root early return). Downstream C++ projects can use `find_package(tvm_ffi)` via the new config file.
- **Testing**: 9 new Python test files with 890 lines covering functions, objects, containers, NDArray, devices, dtypes, errors, strings, and access paths.

## Design Elements

Design elements this commit **consumes**:

- **Object system** (`object.h`): `ObjectObj` ref-counting, `TVM_FFI_DECLARE_OBJECT_INFO`/`TVM_FFI_DEFINE_OBJECT_REF_METHODS` macros. The Cython `Object` class wraps `TVMFFIObjectHandle` with ref-counting via `TVMFFIObjectFree`.
- **Function packed calling convention** (`function.h`, `function_details.h`): `(const AnyView* args, int32_t num_args, Any* rv)`. The Cython `Function` class implements argument packing into `TVMFFIAny` array and result unpacking.
- **C API** (`c_api.h`): All `TVMFFI*` functions are bound in `base.pxi` and called throughout the Cython layer.
- **Type-erased value system** (`TVMFFIAny`): The Cython layer's `make_arg`/`make_ret_value` functions perform the type-index-based dispatch for packing/unpacking Python values to/from `TVMFFIAny`.
- **Global function registry**: `TVMFFIFunctionSetGlobal`/`TVMFFIFunctionGetGlobal` used by `registry.py` and Cython's `_register_global_func`/`_get_global_func`.
- **Reflection system** (`TVMFFITypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`): Used by `_add_class_attrs_by_reflection` to auto-populate Python class attributes from C++ reflection metadata.
- **Container C API**: `ffi.Array`/`ffi.Map` constructors and accessors (`ArrayGetItem`, `ArraySize`, `MapGetItem`, `MapCount`, etc.) consumed by `container.py`.
- **Module system** (`ffi.Module`): Module load/get_function/import consumed by `module.py`.
- **Serialization** (`ToJSONGraphString`/`FromJSONGraphString`): Consumed by `serialization.py`.
- **Error system** (`TVMFFIErrorCreate`, `TVMFFIErrorMoveFromRaised`, `TVMFFIErrorSetRaised`): Consumed by `error.pxi` and `error.py` for cross-language error propagation with traceback reconstruction.

Design elements this commit **produces**:

- **Standalone `tvm_ffi` Python package pattern**: The FFI layer is decoupled into its own pip-installable package with zero Python dependencies, enabling lightweight downstream packages to depend only on `tvm_ffi` rather than the full TVM compiler stack. This is the foundational packaging architecture for the project.

- **Cython-backed Python binding layer**: A complete Cython binding (8 `.pxi` files) providing high-performance Python<->C interop. The layer implements: (1) argument packing/unpacking between Python types and `TVMFFIAny`, (2) ref-counted Object lifecycle management, (3) DLPack tensor interop, (4) cross-language error propagation with traceback reconstruction, (5) global function registry access. The Cython approach avoids ctypes overhead for hot-path function calls.

- **Boundary-aware traceback collection**: The `TVMFFITraceback` API gains the `cross_ffi_boundary` parameter allowing callers to control whether tracebacks stop at FFI boundaries (Python<->C++ transitions) or capture the full stack. Combined with `skip_frame_count` in `TracebackStorage`, this produces clean tracebacks that show only the relevant C++ frames when errors propagate through the FFI. FFI boundary detection recognizes `TVMFFIFunctionCall`, Python interpreter symbols (`_Py*`, `PyObject*`), and CPython slot functions (`slot_tp_call`).

- **Python traceback reconstruction from C++ traceback strings**: `error.py` defines a `TracebackManager` that parses C++ traceback strings (`File "...", line N, in func`) and reconstructs Python `types.TracebackType` chains by synthesizing code objects and frames via `ast.parse`/`compile`/`eval(code, {"_getframe": sys._getframe})`. This allows C++ backtraces to appear as native Python tracebacks in exception handling. Code objects are cached by `(filename, lineno, func)` tuple.

- **`tvm_ffi-config.cmake` discovery pattern**: A CMake config file that calls `python -m tvm_ffi.config` at configure time to discover include directories and library paths. This enables downstream C++ projects to use `find_package(tvm_ffi CONFIG REQUIRED)` and automatically link against the correct tvm_ffi installation.

- **`scikit-build-core` wheel packaging**: Uses `scikit-build-core` as the PEP 517 build backend with Cython compilation, Stable ABI support (Python 3.12+), and bundling of C++ source/headers/libraries into the wheel for downstream compilation use.

- **Python-native object wrappers (`PyNativeObject`)**: A pattern for Python types that subclass both a Python builtin (e.g., `tuple`) and carry a `__tvm_ffi_object__` handle. `Shape(tuple, PyNativeObject)` demonstrates this: the Python-side value (tuple of ints) is the primary representation, but the object also carries a reference to the C++ `ffi.Shape` object for FFI interop.

- **`_init_api` namespace population pattern**: The `registry._init_api(namespace)` function populates a Python module's namespace by scanning all global registered functions with a matching prefix, enabling `from . import _ffi_api` + `_init_api("ffi", __name__)` to auto-bind all C++ registered functions as module attributes.

- **CMake subproject guard pattern**: The `if (NOT ${PROJECT_NAME} STREQUAL ${CMAKE_PROJECT_NAME}) return() endif()` guard allows the CMakeLists.txt to serve dual duty: as a standalone project root (with tests, warnings, python module build) and as a subdirectory inclusion (exporting only the library targets and headers).

## Usage Examples

### Installing tvm_ffi as a standalone package
```bash
pip install -e .
# or build a wheel
pip wheel .
```

### Using tvm_ffi from Python
```python
import tvm_ffi

# Get a global function registered from C++
f = tvm_ffi.get_global_func("testing.echo")
result = f(42)

# Register a Python function into the global registry
@tvm_ffi.register_func("my_func")
def my_func(x, y):
    return x + y

# Create and use containers
arr = tvm_ffi.Array([1, 2, 3])
m = tvm_ffi.Map({"key": "value"})

# Device and NDArray
dev = tvm_ffi.cpu(0)
import numpy as np
nd = tvm_ffi.from_dlpack(np.zeros((2, 3), dtype="float32"))
```

### Using find_package from a downstream C++ project
```cmake
find_package(Python COMPONENTS Interpreter REQUIRED)
execute_process(
  COMMAND "${Python_EXECUTABLE}" -m tvm_ffi.config --cmakedir
  OUTPUT_STRIP_TRAILING_WHITESPACE OUTPUT_VARIABLE tvm_ffi_ROOT)
find_package(tvm_ffi CONFIG REQUIRED)
target_link_libraries(my_lib tvm_ffi_shared)
```

### Loading a compiled module from Python
```python
import tvm_ffi
mod = tvm_ffi.load_module("build/add_one_cpu.so")
add_one = mod["add_one"]
# call with NDArray arguments...
```

  - `.knowledge/designs/error-handling.md` -- Add section on Python traceback reconstruction: `TracebackManager` in `error.py` parses C++ traceback strings and synthesizes Python `TracebackType` chains. Note the boundary-aware `TVMFFITraceback(cross_ffi_boundary)` parameter.
  - `.knowledge/designs/function-system.md` -- Add section on Cython packed function calling: `function.pxi` implements `make_arg`/`make_ret_value` for type-index-based Python<->C++ value marshaling. Note `_convert_to_ffi_func` wrapping Python callables.
  - `.knowledge/designs/object-system.md` -- Add section on Cython Object binding: `object.pxi` wraps `TVMFFIObjectHandle` with ref-counting, `_add_class_attrs_by_reflection` for auto-populating Python class attributes from C++ reflection metadata. Note `PyNativeObject` pattern for hybrid Python-native/FFI objects.
  - `.knowledge/designs/containers.md` -- Add section on Python container wrappers: `Array` and `Map` in `container.py` with `collections.abc.Sequence`/`Mapping` compliance, lazy iteration via `MapForwardIterFunctor`.
  - `.knowledge/designs/0013-module-system.md` -- Add section on Python `Module` class in `module.py` with `get_function`, `entry_func`, `import_module`, `write_to_file`.
  - New design doc `.knowledge/designs/python-packaging.md` should be created covering: `pyproject.toml` structure, `scikit-build-core` integration, Cython compilation flow, Stable ABI targeting, `tvm_ffi-config.cmake` discovery, `libinfo.py` library search, and the `_init_api` namespace population pattern.

### ADRs to write or update
- New ADR for the decision to use `scikit-build-core` + Cython (rather than ctypes, pybind11, or nanobind) for the Python binding layer. Key factors: Cython provides C-level performance for hot-path FFI calls, stable ABI support from Python 3.12+, and compatibility with the existing C API surface.
- New ADR for the `tvm_ffi` standalone packaging decision: decoupling FFI from the main TVM compiler enables lightweight downstream dependencies and independent versioning.

### Stale knowledge references
- `.knowledge/designs/c-abi.md` -- If it documents `TVMFFITraceback` with a 3-parameter signature, it must be updated to show the 4-parameter version (`cross_ffi_boundary` added).
- Any commit ledger entries that reference `TVM_FFI_TRACEBACK_HERE` macro should note it was removed in this commit; callers now invoke `TVMFFITraceback(...)` directly.
