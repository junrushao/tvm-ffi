# Enhance reflection to support nanobind/pybind-style definition with methods, defaults, docs, and flags
## TL;DR
- Redesigns the reflection API from `details::ReflectionDef` to `reflection::ReflectionDef` with nanobind/pybind-style builder methods: `def_ro`/`def_rw` (renamed from `def_readonly`/`def_readwrite`), plus new `def`/`def_static` for instance and static method registration. Fields now accept variadic `Extra...` args for docstrings and `refl::DefaultValue`.
- Extends `TVMFFIFieldInfo` and `TVMFFIMethodInfo` C ABI structs with `flags` bitmask (`TVMFFIFieldFlagBitMask`), `doc` (docstring), and `default_value` fields, replacing the former `readonly` boolean. Adds new C API functions `TVMFFITypeRegisterField` (renamed from `TVMFFIRegisterTypeField`), `TVMFFITypeRegisterMethod`, and `TVMFFITypeGetMethod`.
- Introduces `Object::_type_mutable` static constexpr and adjusts `TypeTraits<TObject*>` to support mutable raw pointer casts from `Any`/`AnyView`, gated by a `static_assert` on `_type_mutable`.

## Impact
- API: **Breaking C ABI changes** -- `TVMFFIFieldInfo` struct layout is reordered and extended (new fields: `doc`, `flags`, `default_value`; removed: `readonly`, `byte_offset` moved). `TVMFFIMethodInfo` gains `doc`, `flags`, and changes `method` from `TVMFFIObjectHandle` to `TVMFFIAny`. C API functions renamed: `TVMFFIRegisterTypeField` -> `TVMFFITypeRegisterField`, `TVMFFIGetOrAllocTypeIndex` -> `TVMFFITypeGetOrAllocIndex`. New functions: `TVMFFITypeRegisterMethod`, `TVMFFITypeGetMethod`. All language bindings (Python/Cython, Rust) must be updated.
- API: **Breaking C++ API changes** -- Namespace moved from `details` to `reflection` (alias `refl`). `ReflectionFieldGetter` -> `reflection::FieldGetter`, `GetReflectionFieldInfo` -> `reflection::GetFieldInfo`. New classes: `reflection::FieldSetter`, `reflection::DefaultValue`, `reflection::GetMethodInfo`, `reflection::GetMethod`. `def_readonly`/`def_readwrite` renamed to `def_ro`/`def_rw` with inverted writable semantics (old `def_readonly` passed `readonly=true`; new `def_ro` passes `writable=false`).
- Flags/config: New `TVMFFIFieldFlagBitMask` enum with `TVMFFIFieldFlagBitMaskWritable`, `TVMFFIFieldFlagBitMaskHasDefault`, `TVMFFIFieldFlagBitMaskIsStaticMethod`.
- Data formats/schemas: `TVMFFIFieldInfo` layout change is ABI-breaking. `TVMFFIMethodInfo` now stores the method as `TVMFFIAny` (inline value) instead of `TVMFFIObjectHandle` (opaque pointer).

## Design Elements

Design elements this commit **consumes**:
- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Extends `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, and `TVMFFITypeInfo` C structs. Adds new `extern "C"` API functions. Renames existing C API functions to follow `TVMFFIType*` naming convention.
- **Object System** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Adds `Object::_type_mutable` static constexpr to control whether raw mutable pointer casts are allowed. The `TypeTable` in `src/ffi/object.cc` is extended with `RegisterTypeMethod` and an `any_pool_` replacing `string_pool_`.
- **Function System** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): Method registration wraps member function pointers as `Function` objects via `Function::FromTyped`. The `Function::Registry::set_body_method` `std::forward` fix is a separate bugfix included in this commit.
- **Reflection System** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): This commit substantially rewrites the reflection system. The prior design doc describes the state before this commit.

Design elements this commit **produces**:
- **Enhanced Reflection Builder API**: `reflection::ReflectionDef` now supports `def_ro`, `def_rw`, `def`, `def_static` with variadic extra args (docstrings, `DefaultValue` trait). The `FieldInfoTrait` base class provides an extensible mechanism for field metadata decoration. The `GetMethod` overloads dispatch member-function-pointer, const-member-function-pointer, and generic callable to `Function::FromTyped`.
- **Method Reflection**: Previously a non-goal (noted in `.knowledge/designs/0006-reflection.md`), now implemented. `TVMFFIMethodInfo` stores a `Function` as `TVMFFIAny`, registered via `TVMFFITypeRegisterMethod`. Methods are stored in `TypeTable::Entry::type_methods_data` with pointer refresh on `entry->methods`. `reflection::GetMethodInfo` and `reflection::GetMethod` provide lookup by type key + method name.
- **Field Default Values**: `TVMFFIFieldInfo::default_value` stores a `TVMFFIAny` copy of the default. `TVMFFIFieldFlagBitMaskHasDefault` flag indicates presence. `TypeTable::RegisterTypeField` copies default values into `any_pool_` for lifetime management.
- **Mutable Object Pointer Casts**: `Object::_type_mutable` (default `false`) gates `TypeTraits<TObject*>::CopyFromAnyViewAfterCheck` with a `static_assert`. Only types opting in (e.g., `TPrimExprObj` in tests) can be cast to non-const raw pointers from `Any`/`AnyView`. This removes the prior `const TObject*`-only specialization.
- **TVMFFIFieldFlagBitMask Enum**: Replaces the boolean `readonly` field with a bitmask. Current bits: `Writable` (bit 0), `HasDefault` (bit 1), `IsStaticMethod` (bit 2). Extensible for future flags without struct layout changes.
- **TypeTable Lifetime Pool Generalization**: `string_pool_` (vector of `unique_ptr<string>`) replaced by `any_pool_` (vector of `Any`). The `CopyString` helper now stores strings as `String` objects in `any_pool_`, and `CopyAny` stores arbitrary `Any` values. This unifies lifetime management for all metadata stored in the type table.

### ADRs to write

- **`.knowledge/ADRs/0006-reflection-flag-bitmask.md`**: Records the decision to replace `int32_t readonly` with `int64_t flags` bitmask in `TVMFFIFieldInfo`. Context: the reflection system needed to carry more metadata (default values, static method markers) without adding new boolean fields for each feature. Alternatives: separate boolean fields (simpler but brittle ABI with each new feature), or a separate metadata struct. Trade-off: bitmask is compact and extensible but requires documentation of bit assignments and careful ABI versioning.

- **`.knowledge/ADRs/0007-mutable-object-pointer-cast.md`**: Records the decision to add `_type_mutable` opt-in for mutable raw pointer casts from `Any`/`AnyView`. Context: some use cases (e.g., in-place mutation of reflected objects) need `TObject*` not `const TObject*`. Alternatives: always allow mutable casts (unsafe by default), or require explicit `const_cast` at call sites. Trade-off: opt-in via static constexpr is zero-cost and safe by default, but requires each mutable type to declare the flag.

### Skill evolution (`/commit-ledger`)

- **Semantic diff for renamed symbols**: This commit renames several C API functions and C++ classes. The skill procedure does not explicitly call out renames as a category of change distinct from additions/removals. Consider adding a sub-step in Step 4 (Key Implementations) to identify renames/moves (by matching old symbol deletions with new symbol additions of similar shape) and note them explicitly, since renames require coordinated updates across all language bindings.

- **ABI-breaking change detection**: The procedure should include a heuristic for detecting ABI-breaking changes in Step 2 (Quick Characterization). If `c_api.h` struct layouts change (field reordering, field addition/removal, type changes), this should be flagged as "ABI-breaking" regardless of whether the commit message says so. This is critical because downstream language bindings may need synchronized updates.

- **Inverted semantics detection**: The `readonly` -> `writable` (flags) inversion is subtle and easy to miss. The skill should note when a boolean's polarity is inverted (e.g., `readonly=true` becomes `flags & Writable == 0`) as this is a common source of bugs in coordinated multi-language updates.

- The procedure's Step 1 `git show --numstat` is good for initial triage, but for commits with many files (13 in this case), reading all diffs sequentially is slow. Consider recommending a priority order: (1) `c_api.h` (ABI surface), (2) main header being changed (here `reflection.h`), (3) implementation files, (4) tests (for invariant discovery). This was the natural order followed in this run and should be codified.
