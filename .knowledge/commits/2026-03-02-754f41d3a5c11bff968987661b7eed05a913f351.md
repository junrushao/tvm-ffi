# Add TypeSchema type converter with function-pointer dispatch

## TL;DR
- New `python/tvm_ffi/cython/type_check.pxi` (1032 lines): `_TypeConverter` cdef class with a C function pointer (`_dispatch_fn_t`) that pre-compiles the dispatch at TypeSchema build time; `convert()`/`check_value()`/`try_convert()`/`try_check_value()` methods added to `TypeSchema`.
- `_ConvertError` sentinel class distinguishes conversion failure from a valid `None` result; `_is_object_instance` walks the C-level `TVMFFITypeInfo.type_ancestors` chain for O(1) subtype checks without Python overhead.
- Segfault fix: `__tvm_ffi_value__` unwrapping changed from recursive cdef to iterative loop with depth limit 64.
- `type_info.pxi` extended with STL type origin mappings (`std::vector`→Array, `std::optional`→Optional, etc.) and `_ORIGIN_TO_TYPE_INDEX` lookup table.

## Impact
- API: `TypeSchema` gains `convert`, `check_value`, `try_convert`, `try_check_value` methods. All 10 FFI marshal protocols accepted.
- Behavioral: Python-side type validation now matches C++ FFI marshal path. `__tvm_ffi_value__` unwrapping is now iterative (depth limit 64) — prevents stack overflow on mutual cycles.
- Flags/config: none
- Data formats/schemas: `_TYPE_SCHEMA_ORIGIN_CONVERTER` in `type_info.pxi` extended with STL type origins.

## Usage Examples

```python
from tvm_ffi.core import TypeSchema

# Get TypeSchema for an int field
schema = TypeSchema.from_json_str('{"type_index": 1, "origin": "int"}')

# convert() raises TypeError on failure
val = schema.convert(42)    # → 42
schema.convert("foo")       # raises TypeError

# check_value() returns bool
schema.check_value(42)      # → True
schema.check_value("foo")   # → False

# try_convert() returns _ConvertError on failure (never raises)
result = schema.try_convert("bad")
if isinstance(result, _ConvertError):
    print(result.message)
```
