# Expose package version via __version__ and add pre-commit version sync check
## TL;DR
- Bumps package version from `0.1.0b8` to `0.1.0b9` in `pyproject.toml` (single source of truth).
- Exposes `__version__` in `tvm_ffi.__init__` so callers can do `import tvm_ffi; tvm_ffi.__version__`.
- Adds a `check-version` pre-commit hook (`tests/lint/check_version.py`) that enforces `pyproject.toml` and `__init__.py` stay in sync, auto-fixing `__init__.py` on mismatch.

## Key Exports
N/A -- infrastructure. The only user-facing addition is `tvm_ffi.__version__`, a standard Python package version string.

```python
# python/tvm_ffi/__init__.py
__version__: str = "0.1.0b9"
# Invariant: must match pyproject.toml [project].version at all times.
# Enforced by: tests/lint/check_version.py (pre-commit hook)
```

## Impact
- API: Adds `tvm_ffi.__version__` to `__all__`. Purely additive; no existing callers affected.
- Behavioral: none
- Flags/config: New pre-commit hook `check-version` runs on every commit; depends on `tomli` package.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Python package layout and `__init__.py` export list (`.knowledge/designs/0012-python-bindings.md`)
- Pre-commit hook infrastructure (`.pre-commit-config.yaml`)

Design elements this commit produces:
- **Version sync invariant**: `pyproject.toml` is the single source of truth for the package version. `__init__.py.__version__` must mirror it. The `check-version` pre-commit hook enforces this and auto-repairs `__init__.py` on mismatch.

## Usage Examples
```python
import tvm_ffi
print(tvm_ffi.__version__)  # "0.1.0b9"
```

The version check runs automatically via pre-commit. If a developer changes the version in `pyproject.toml` but forgets `__init__.py`, the hook auto-updates `__init__.py` and fails the commit (prompting re-stage + re-commit).
