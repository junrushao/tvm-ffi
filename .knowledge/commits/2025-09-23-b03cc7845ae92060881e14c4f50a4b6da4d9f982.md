# Guard kDLFloat4_e2m1fn torch JIT extension code behind TORCH_VERSION >= 2.8 and bump version to 0.1.0b7
## TL;DR
- Wraps the `kDLFloat4_e2m1fn` case in `toScalarTypeForDLPackv1` with `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` / `#endif` guards so the JIT-compiled C++ extension compiles on torch < 2.8 (where `ScalarType::Float4_e2m1fn_x2` does not exist).
- Bumps package version `0.1.0b6` → `0.1.0b7`.

## Key Exports
None

## Impact
- API: None
- Behavioral: `toScalarTypeForDLPackv1` no longer fails to compile on torch < 2.8; on those versions, the `kDLFloat4_e2m1fn` case falls through to the `default:` TORCH_CHECK (i.e., f4 tensors are unsupported on older torch, but the extension can still load).
- Flags/config: None
- Data formats/schemas: None

## Usage Examples
Before/after pattern showing the build compatibility fix:

```python
# Before (0.1.0b6): compilation fails on torch < 2.8
# ScalarType::Float4_e2m1fn_x2 is undefined in torch < 2.8
# case DLDataTypeCode::kDLFloat4_e2m1fn: ... Float4_e2m1fn_x2 ...  <- compile error

# After (0.1.0b7): compiles on all torch versions
# #if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8
#   case kDLFloat4_e2m1fn: ... Float4_e2m1fn_x2 ...
# #endif
# On torch < 2.8: f4 falls to default TORCH_CHECK (runtime error, not compile error)
```
