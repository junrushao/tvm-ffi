# Guard kDLFloat4_e2m1fn DLPack dtype behind TORCH_VERSION >= 2.8 for backward compat
## TL;DR
- Wraps the `kDLFloat4_e2m1fn` / `Float4_e2m1fn_x2` case in the embedded C++ source inside `_optional_torch_c_dlpack.py` with `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` / `#endif` preprocessor guards, so the JIT-compiled torch DLPack extension compiles successfully against PyTorch versions earlier than 2.8 that lack the `ScalarType::Float4_e2m1fn_x2` enum.
- Bumps the package version from `0.1.0b6` to `0.1.0b7` in `pyproject.toml`.

## Key Exports
None. No new public APIs or behavioral changes for supported dtype paths.

## Impact
- API: None.
- ABI: None.
- Behavioral: The `kDLFloat4_e2m1fn` DLPack dtype conversion is now only available when compiling against PyTorch >= 2.8. On earlier PyTorch versions, attempting to convert a tensor with this dtype will fall through to the `default:` case and raise a `TORCH_CHECK` error instead of a compilation failure.
- Flags/config: None.
- Data formats/schemas: None.
- Version: Package version bumped from `0.1.0b6` to `0.1.0b7`.

## Design Elements
Design elements this commit consumes:
- **DLPack fast-path protocol** (`.knowledge/designs/0018-dlpack-fast-path.md`): The JIT-compiled C++ extension in `_optional_torch_c_dlpack.py` that provides `TorchDLPackFromPyObject`/`TorchDLPackToPyObject`/`TorchDLPackTensorAllocator`. The `toScalarTypeForDLPackv1` function inside this embedded source is where the version guard is added.

Design elements this commit produces:
- None. This is a backward-compatibility fix that conditionalizes an existing code path on PyTorch version macros.

## Usage Examples
No usage change. The fix is transparent -- on PyTorch < 2.8, the JIT compilation succeeds where it previously failed; on PyTorch >= 2.8, behavior is unchanged.
