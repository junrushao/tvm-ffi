# Add __tvm_ffi_opaque_ptr__ protocol for passing opaque C pointers from Python
## TL;DR
- Introduces the `__tvm_ffi_opaque_ptr__` Python dunder protocol: any object implementing this method is automatically converted to `kTVMFFIOpaquePtr` when passed as an FFI function argument.
- Adds a new Cython arg setter (`TVMFFIPyArgSetterFFIOpaquePtrCompatible_`) and inserts it into `TVMFFIPyArgSetterFactory_` after `ctypes.c_void_p` but before `callable`.
- Bumps version from `0.1.0b19` to `0.1.0b20`.

## Key Exports

**Cython setter function (internal, not public Python API):**
- `TVMFFIPyArgSetterFFIOpaquePtrCompatible_(handle, ctx, py_arg, out)` -- Cython `cdef` function. Calls `arg.__tvm_ffi_opaque_ptr__()`, casts the result to `long long`, stores it as `kTVMFFIOpaquePtr` with `out.v_ptr = <void*>long_ptr`.

**Protocol:**
- `__tvm_ffi_opaque_ptr__() -> int` -- Python dunder protocol. Objects implementing this method are automatically converted to opaque pointers (`kTVMFFIOpaquePtr`) when passed as FFI function arguments. The method must return an integer representing a C pointer value. The protocol is checked via `hasattr(arg_class, "__tvm_ffi_opaque_ptr__")` in the setter factory.

## Impact
- API: Objects implementing `__tvm_ffi_opaque_ptr__` are now automatically accepted as FFI function arguments, converted to `void*` (opaque pointer). No new public Python API -- the conversion is transparent during packed function calls. This extends the existing `ctypes.c_void_p` support to arbitrary Python objects that wrap C pointers.
- ABI: none -- the value is passed as `kTVMFFIOpaquePtr`, which already exists in the type index enum.
- Behavioral: none for existing callers. New behavior only for objects implementing the new protocol.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyArgSetter dispatch system** (`.knowledge/designs/0014-python-bindings.md`, Setter Dispatch Table) -- the cached type-dispatch architecture where `TVMFFIPyArgSetterFactory_` creates setters once per Python type and caches them in the thread-local `dispatch_map_`.
- **kTVMFFIOpaquePtr type index** (`.knowledge/designs/any-system.md`, `.knowledge/designs/type-traits.md`) -- the existing type index (value 4) used to pass raw `void*` pointers through the FFI.

Design elements this commit produces:
- **`__tvm_ffi_opaque_ptr__` protocol** -- A new Python dunder protocol that allows any Python object to declare itself as carrying an opaque C pointer. This generalizes the existing `ctypes.c_void_p` support to arbitrary wrapper objects, following the same dunder-protocol pattern as `__cuda_stream__`, `__dlpack__`, and `__c_dlpack_exchange_api__`.

## Usage Examples

Passing an object with an opaque pointer to an FFI function:

```python
import ctypes
import tvm_ffi

class MyObject:
    def __init__(self, value: int) -> None:
        self.value = value

    def __tvm_ffi_opaque_ptr__(self) -> int:
        return self.value

fecho = tvm_ffi.get_global_func("testing.echo")
x = MyObject(10)
y = fecho(x)  # automatically converted to void* via __tvm_ffi_opaque_ptr__
assert isinstance(y, ctypes.c_void_p)
assert y.value == 10
```
