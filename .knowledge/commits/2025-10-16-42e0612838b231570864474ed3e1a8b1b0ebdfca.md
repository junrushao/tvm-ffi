# Introduce __tvm_ffi_opaque_ptr__ protocol for passing opaque C pointers through FFI
## TL;DR
- Adds a new Python dunder protocol `__tvm_ffi_opaque_ptr__` that allows any Python object to provide an opaque `void*` pointer for FFI calls, enabling DSLs to pass opaque C struct pointers through the packed calling convention.
- Implements `TVMFFIPyArgSetterFFIOpaquePtrCompatible_` in Cython, which calls the protocol method and packs the result as `kTVMFFIOpaquePtr`.
- Bumps version from `0.1.0b19` to `0.1.0b20`.

## Key Exports

# === New dunder protocol for opaque pointer passthrough ===

class TVMFFIOpaquePtrCompatible(Protocol):
    """Any Python class implementing this protocol can pass an opaque void*
    pointer through FFI calls. The method must return an integer interpretable
    as a pointer value."""
    def __tvm_ffi_opaque_ptr__(self) -> int: ...
    # Interacts with: TVMFFIPyArgSetterFFIOpaquePtrCompatible_ (Cython setter)
    # Interacts with: TVMFFIPyArgSetterFactory_ (dispatch: checked via hasattr on arg_class)
    # Invariant: return value is cast to long long then to void* -- must be a valid pointer or integer
    # Invariant: dispatched AFTER ctypes.c_void_p check, BEFORE callable check in factory order
    # Extension: any DSL wrapper holding an opaque C struct pointer can implement this

def TVMFFIPyArgSetterFFIOpaquePtrCompatible_(
    handle: TVMFFIPyArgSetter,
    ctx: TVMFFIPyCallContext,

    """Setter for objects implementing __tvm_ffi_opaque_ptr__ protocol.

    # Interacts with: make_ret (returns ctypes.c_void_p for kTVMFFIOpaquePtr results)
    ...

## Impact
- API: New protocol `__tvm_ffi_opaque_ptr__` -- additive only, no existing callers broken.
- Behavioral: Objects implementing the protocol are now dispatched to the opaque ptr setter instead of falling through to `callable` check or `OpaquePyObject` fallback.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyArgSetterFactory_ dispatch chain** (0012-python-bindings): The new protocol check is inserted between `ctypes.c_void_p` and `callable` in the factory's type dispatch order.
- **kTVMFFIOpaquePtr type index** (0003-any-system, 0001-c-abi): Uses existing type index 4 for opaque pointer values.
- **TVMFFIPyArgSetter function pointer pattern** (0012-python-bindings): Follows the same cdef function signature as all other per-type setters.

Design elements this commit produces:
- **`__tvm_ffi_opaque_ptr__` dunder protocol**: A new Python protocol for passing opaque C pointers through FFI. Analogous to existing protocols `__tvm_ffi_object__`, `__cuda_stream__`, and `__c_dlpack_exchange_api__` but for raw void pointers. Not yet documented in any design doc.

## Usage Examples

From the test (`tests/python/test_function.py`):

```python
import ctypes
from typing import Any
import tvm_ffi

class MyObject:
    def __init__(self, value: Any) -> None:
        self.value = value

    def __tvm_ffi_opaque_ptr__(self) -> Any:
        return self.value

fecho = tvm_ffi.get_global_func("testing.echo")
x = MyObject(10)
y = fecho(x)  # passes 10 as void* through FFI
assert isinstance(y, ctypes.c_void_p)
assert y.value == 10
```
