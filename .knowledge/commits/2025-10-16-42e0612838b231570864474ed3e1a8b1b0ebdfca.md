# Add __tvm_ffi_opaque_ptr__ protocol for passing opaque C struct pointers through the Python arg-setter dispatch

## TL;DR
- Adds the `__tvm_ffi_opaque_ptr__` dunder protocol: any Python class implementing this method can pass a raw integer pointer directly into FFI calls as `kTVMFFIOpaquePtr`.
- Introduces `TVMFFIPyArgSetterFFIOpaquePtrCompatible_` Cython setter in `function.pxi` and registers it in `TVMFFIPyArgSetterFactory_` (after `ctypes.c_void_p`, before `callable`).
- Version bumped from `0.1.0b19` to `0.1.0b20`.

## Impact
- API: New opt-in protocol. Classes implementing `__tvm_ffi_opaque_ptr__` are automatically converted when passed to FFI functions. No existing callers affected.
- Behavioral: Objects with `__tvm_ffi_opaque_ptr__` now dispatch to the new setter instead of falling through to `callable` or the opaque-object fallback. Classes that are both callable and `__tvm_ffi_opaque_ptr__`-implementing will hit the opaque-ptr path first.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces:
- `__tvm_ffi_opaque_ptr__` protocol — new duck-typed protocol for Python classes wrapping opaque C structs; analogous to `__tvm_ffi_object__` and `__cuda_stream__` protocols in the same dispatch chain

## Usage Examples

**Context**: A DSL defines a Python wrapper for an opaque C struct and passes it through to an FFI function that expects a raw pointer.

```python
import tvm_ffi
import ctypes

class MyObject:
    def __init__(self, value: int) -> None:
        self.value = value  # raw int cast of a void*

    def __tvm_ffi_opaque_ptr__(self) -> int:
        return self.value

fecho = tvm_ffi.get_global_func("testing.echo")
x = MyObject(10)
y = fecho(x)
# y is ctypes.c_void_p with y.value == 10
assert isinstance(y, ctypes.c_void_p)
assert y.value == 10
```
