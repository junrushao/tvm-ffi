# Add stream-context benchmarks and AutoDLPack stream test to DLPack benchmark script
## TL;DR
- Extends `scripts/benchmark_dlpack.py` (+68/-2) with three new capabilities: (1) a `stream=True` mode for `tvm_ffi_nop_autodlpack_from_torch` that exercises AutoDLPack under a non-default `torch.cuda.Stream` context, (2) a `load_torch_get_current_cuda_stream()` helper that JIT-compiles a C++ extension via `torch.utils.cpp_extension.load_inline` to query the current CUDA stream through `c10::cuda::CUDAStream` (bypassing Python overhead), and (3) benchmark functions (`bench_torch_get_current_stream`) that compare the JIT C++ extension vs. native Python `torch.cuda.current_stream` for both default and non-default streams.
- This is a benchmark-only commit. No functional code changes to the FFI library itself. The benchmarks were added to measure the overhead of stream-context queries in preparation for the AutoDLPack stream synchronization feature described in the PR title.
- Adds an unused `import os` at the top of the file.

## Impact

- Data formats/schemas: none.

## Design Elements

Design elements this commit **consumes**:

- **AutoDLPack / Cython arg setter** (not yet documented in `.knowledge/designs/`): The new `stream=True` test path in `tvm_ffi_nop_autodlpack_from_torch` exercises the automatic DLPack conversion (`TVMFFIPyArgSetterDLPack_` / `TVMFFIPyArgSetterTorchFallback_` in `python/tvm_ffi/cython/function.pxi`) under a non-default CUDA stream context. The commit message says AutoDLPack is updated to "automatically update the env stream to be consistent with torch stream context," meaning the runtime conversion path now calls `TVMFFIEnvSetStream` to synchronize the FFI's thread-local stream with PyTorch's current stream. This benchmark measures the overhead of that synchronization.

- **Stream Context API** (`include/tvm/ffi/extra/c_env_api.h`, `src/ffi/extra/stream_context.cc`): Introduced by the immediate parent commit `0daaffe`. The benchmark implicitly validates the stream-aware AutoDLPack path that calls `TVMFFIEnvSetStream`/`TVMFFIEnvGetCurrentStream` under the hood. The `bench_torch_get_current_stream` functions also measure the cost of querying the current CUDA stream -- a key operation the AutoDLPack path must perform on every FFI call when a `torch.Tensor` argument is passed under a non-default stream.

- **Function system / GlobalFunctionTable** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): All benchmarks invoke `testing.nop` through `tvm_ffi.get_global_func("testing.nop")`, exercising the packed calling convention.

- **NDArray / DLPack interop** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The benchmark exercises `tvm_ffi.from_dlpack()` which wraps `TVMFFINDArrayFromDLPack`.

Design elements this commit **produces**:

- None -- this is a benchmark extension, not a functional change. It does not introduce new abstractions, APIs, or invariants.

### ADRs to write

- **`.knowledge/ADRs/0018-jit-cpp-extension-for-stream-query.md`**: The benchmark introduces a pattern of using `torch.utils.cpp_extension.load_inline` to JIT-compile a C++ function that queries `c10::cuda::getCurrentCUDAStream`. The decision context: Python-level `torch.cuda.current_stream()` has non-trivial overhead compared to the C++ path; the JIT extension amortizes build cost (cached after first invocation). Alternatives: (1) ctypes to directly call into libtorch (fragile, version-dependent offsets), (2) accept the Python overhead (simpler but adds measurable latency per FFI call in eager mode). Trade-off: JIT compilation has a one-time startup cost but yields a faster per-call stream query.

### Design diagrams to draw

- **Mermaid: AutoDLPack stream synchronization flow**. Should depict the path from `nop(torch_tensor)` call -> Cython arg setter -> detect non-default CUDA stream -> query torch stream (via JIT extension or Python) -> `TVMFFIEnvSetStream` -> execute packed function -> restore original stream. This captures the new invariant that the FFI's thread-local stream context must be kept in sync with the framework's stream context during AutoDLPack conversions.
