# Fix missing negative index bounds check in ArrayObj::operator[] and SetItem
## TL;DR
- `ArrayObj::operator[]` and `ArrayObj::SetItem` only checked `i >= size_`, allowing negative `int64_t` indices to bypass bounds validation and cause undefined behavior (out-of-bounds memory access).
- Added `i < 0 ||` to both bounds checks so negative indices now throw `IndexError`.
- Added C++ test exercising both methods with index `-1`.

## Key Exports

No new exports. The fix tightens an existing invariant on two internal methods:

```python
class ArrayObj(Object):
    """Variable-length typed array with COW semantics."""
    size_: int64

    def operator_bracket(self, i: int64) -> Any:
        """Read i-th element (bounds-checked)."""
        # Was:    if i >= size_: raise IndexError
        # Now:    if i < 0 or i >= size_: raise IndexError
        # Invariant: 0 <= i < size_
        # Interacts with: ArrayObj::at() delegates here

    def SetItem(self, i: int64, item: Any) -> None:
        """Write i-th element in-place."""
        # Was:    if i >= size_: raise IndexError
        # Now:    if i < 0 or i >= size_: raise IndexError
        # Invariant: 0 <= i < size_
```

## Impact
- API: none -- no signature changes
- Behavioral: negative indices to `ArrayObj::operator[]` and `ArrayObj::SetItem` now throw `IndexError` instead of causing undefined behavior. The `Array<T>` wrapper already had its own negative index handling, so this only affects direct `ArrayObj`-level callers.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

Before (incorrect -- undefined behavior):
```cpp
Array<int> arr = {1, 2, 3};
ArrayObj* obj = arr.GetArrayObj();
// BUG: negative index bypasses bounds check, accesses memory before data_
const auto& val = obj->at(-1);  // no exception, undefined behavior
obj->SetItem(-1, Any(42));      // no exception, corrupts memory
```

After (correct -- throws IndexError):
```cpp
Array<int> arr = {1, 2, 3};
ArrayObj* obj = arr.GetArrayObj();
// FIXED: negative index now caught by bounds check
try {
    const auto& val = obj->at(-1);  // throws IndexError
} catch (const Error& e) {
    // e.kind() == "IndexError"
}
```
