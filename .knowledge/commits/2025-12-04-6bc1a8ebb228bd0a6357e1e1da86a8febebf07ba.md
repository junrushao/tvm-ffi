# Rename kwargs_wrapper parameters for consistency and add exclude_arg_names + keyword validation
## TL;DR
- Renames all public parameters of `make_kwargs_wrapper` and `make_kwargs_wrapper_from_signature` for brevity and consistency: `args_names` -> `arg_names`, `args_defaults` -> `arg_defaults`, `kwargsonly_names` -> `kwonly_names`, `kwargsonly_defaults` -> `kwonly_defaults`, `prototype_func` -> `prototype`.
- Adds `exclude_arg_names` parameter to `make_kwargs_wrapper_from_signature` to skip specified arguments when extracting parameters from a signature.
- Adds validation that rejects Python keywords (e.g. `if`, `for`) as parameter names via `keyword.iskeyword()`.

| Old Name | New Name |
|---|---|
| `args_names` | `arg_names` |
| `args_defaults` | `arg_defaults` |
| `kwargsonly_names` | `kwonly_names` |
| `kwargsonly_defaults` | `kwonly_defaults` |
| `prototype_func` | `prototype` |

## Impact
- API: Breaking rename of all keyword parameters in `make_kwargs_wrapper` and `make_kwargs_wrapper_from_signature`. Any caller using old keyword argument names (`args_names=`, `kwargsonly_names=`, `prototype_func=`, etc.) will get a TypeError. No external callers found in the codebase at this commit -- the module is only imported by tests and benchmarks, all of which were updated.
- Behavioral: `_validate_argument_names` now raises `ValueError` for Python keywords (e.g., `if`, `for`, `class`) in addition to non-identifiers. Previously these would silently pass validation but produce broken generated code at `exec()` time.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `kwargs_wrapper` code-generation pattern: dynamically generating wrapper functions via `exec()` with MISSING sentinel for non-trivial defaults (same pattern as stdlib `dataclasses`)
- `inspect.Signature` / `inspect.Parameter` for parameter introspection

Design elements this commit produces:
- `exclude_arg_names` filtering protocol: a pattern for selectively omitting parameters when generating wrappers from signatures, useful for stripping framework-injected parameters (e.g., `self`, `cls`, or internal args)
- Python keyword rejection invariant: all argument names passed through kwargs_wrapper are now guaranteed to be valid, non-keyword Python identifiers

## Usage Examples

Excluding arguments when generating a wrapper from a signature:

```python
import inspect
from tvm_ffi.utils.kwargs_wrapper import make_kwargs_wrapper_from_signature

def source(a, b, c=10, d=20):
    pass

target = lambda *args: sum(args)

# Generate wrapper that skips parameter "c"
wrapper = make_kwargs_wrapper_from_signature(
    target, inspect.signature(source), exclude_arg_names=["c"]
)
# wrapper has signature (a, b, d=20) -- "c" is excluded
wrapper(1, 2)       # => 23 (1 + 2 + 20)
wrapper(1, 2, d=5)  # => 8  (1 + 2 + 5)
```

Python keyword rejection (before/after):

```python
# Before this commit: no error at validation time, broken exec() at runtime
make_kwargs_wrapper(target, ["a", "if"])  # would fail obscurely in exec()

# After this commit: clear ValueError at validation time
make_kwargs_wrapper(target, ["a", "if"])
# => ValueError: Invalid argument name: 'if' is a Python keyword and cannot be used as a parameter name
```
