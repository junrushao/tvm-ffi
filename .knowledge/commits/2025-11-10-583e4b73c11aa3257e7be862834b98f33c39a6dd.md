# Support const T&, T&&, and const T argument types in C++ exported FFI functions
## TL;DR
- Extends the C++ typed function system to accept `T`, `const T`, `const T&`, and `T&&` as argument types in exported functions (previously only `T` worked reliably).
- Adds `ArgTypeSupported<T>` compile-time predicate that rejects unsupported reference combinations (e.g., non-const lvalue references `T&`).
- Converts `ArgValueWithContext` from a non-template class with a template conversion operator to a template class `ArgValueWithContext<Type>` with a non-template conversion operator. This fixes interaction with classes that have template constructors (e.g., `std::optional<T>`).
- Uses `std::tuple_element_t<Is, PackedArgs>` at the `unpack_call` site to instantiate per-argument `ArgValueWithContext<Arg_i>`.

## Key Exports
**Template variable** (compile-time, in `function_details.h`):
- `ArgTypeSupported<T>` -- `true` if `T` is a valid FFI argument type: non-reference, `const T&`, or `T&&`

**Template class** (changed):
- `ArgValueWithContext<Type>` -- was non-template `ArgValueWithContext`; now parameterized by the expected argument type. Has `using TypeWithoutCR = std::remove_const_t<std::remove_reference_t<Type>>` and `operator TypeWithoutCR()`.

**Template function** (changed):
- `unpack_call<Is...>(...)` -- now uses `FuncInfo::ArgType` (a `std::tuple`) and `std::tuple_element_t<Is, PackedArgs>` to construct correctly-typed `ArgValueWithContext` instances.

## Impact
- API: **breaking for downstream template metaprogramming** that depends on `ArgValueWithContext` being non-template. No impact on typical users who just export functions.
- Behavioral: functions with `const T&`, `T&&`, `const T` arguments now compile and work correctly through FFI
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Typed function system (`Function::FromTyped`, `unpack_call`, `FunctionInfo`) per `.knowledge/designs/0004-function-system.md`
- `TypeTraitsNoCR<T>` and `AnyView::try_cast<T>()` per `.knowledge/designs/0005-type-traits.md`

Design elements this commit mutates:
- `ArgValueWithContext` is now a template class -- any code that mentions it by name must supply a type parameter
- `ArgSupported<T>` now includes `ArgTypeSupported<T>` as an additional constraint

## Usage Examples
```cpp
// These all now work as exported FFI functions:
Function::FromTyped([](int x) { return x; });              // T
Function::FromTyped([](const int x) { return x; });        // const T
Function::FromTyped([](const int& x) { return x; });       // const T&
Function::FromTyped([](String&& x) { return x; });         // T&&
// NOT supported: T& (non-const lvalue reference)
```
