# Fix ArgValueWithContext template conversion operator to support std::optional and other template-constructor types
## TL;DR
- Converts `ArgValueWithContext` from a non-template class with a template conversion operator to a template class with a non-template conversion operator, fixing compile errors when target types have template constructors (e.g., `std::optional<T>`).
- Adds `ArgTypeSupported<T>` compile-time constraint that explicitly whitelist-validates argument qualifiers: `T`, `const T`, `const T&`, and `T&&`.
- `unpack_call` now extracts each argument's expected type from `FunctionInfo::ArgType` tuple and passes it as the template parameter to `ArgValueWithContext<T>`.

## Impact
- API: None -- `ArgValueWithContext` is internal (`details::` namespace), not part of the public API.
- Behavioral: Functions registered via `FromTyped` that accept `std::optional<T>` or other types with template constructors now compile correctly. Previously, the template conversion operator on `ArgValueWithContext` would conflict with the template constructor of the target type, causing ambiguous overload resolution.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `FunctionInfo<F>::ArgType` tuple type (from `FuncFunctorImpl::ArgType`) -- used to extract per-argument types for `ArgValueWithContext` template instantiation. See [0004-ffi-function-system](../design-records/0004-ffi-function-system.md).
- `TypeTraitsNoCR<T>::convert_enabled` -- used in `ArgSupported` to validate argument convertibility. See [0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md).
- `AnyView::try_cast<T>()` -- called inside conversion operator. See [0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md).

Design elements this commit produces:
- `ArgTypeSupported<T>` -- new compile-time boolean constraining which C++ reference/const qualifiers are valid for FFI function arguments. This is a new invariant in the function system.
- `ArgValueWithContext<Type>` mutation -- the class template parameterization strategy changes from template-operator to template-class. This is a design-level change to the argument unpacking mechanism.

## Usage Examples
Before (broken with `std::optional<T>`):
```cpp
// Registering a function that takes std::optional<int>
// would fail to compile because std::optional<T> has template constructors
// that conflict with the template conversion operator of ArgValueWithContext
refl::GlobalDef().def("test.opt", [](std::optional<int> x) { return x.value_or(0); });
// Error: ambiguous conversion from ArgValueWithContext to std::optional<int>
```

After (works):
```cpp
// Now compiles correctly -- ArgValueWithContext<std::optional<int>> has a
// non-template operator std::optional<int>(), which doesn't conflict with
// std::optional<T>'s template constructors.
refl::GlobalDef().def("test.opt", [](std::optional<int> x) { return x.value_or(0); });

// All these argument qualifier forms are also supported:
// f(T val)           -- by value
// f(const T val)     -- by const value
// f(const T& ref)    -- by const lvalue ref
// f(T&& rref)        -- by rvalue ref
// NOT supported: f(T& ref) -- non-const lvalue ref is rejected by ArgTypeSupported
```
