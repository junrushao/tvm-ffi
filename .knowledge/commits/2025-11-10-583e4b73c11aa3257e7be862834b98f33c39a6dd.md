# Support const T&, T&&, and const T argument types in FromUnpacked
## TL;DR
- Extends `Function::FromUnpacked` to support `T`, `const T`, `const T&`, and `T&&` as argument types (previously only `T` was fully supported).
- Introduces `ArgTypeSupported<T>` compile-time check to validate argument type qualifiers.
- Makes `ArgValueWithContext` a template class parameterized on the expected type, fixing interaction with classes that have template constructors (e.g., `std::optional<T>`).

## Key Exports

**Templates (C++):**
- `details::ArgTypeSupported<T>` -- `constexpr bool` that validates `T`, `const T`, `const T&`, or `T&&` are the only accepted argument types.
- `details::ArgValueWithContext<Type>` -- Now a template class (was non-template) for type-safe argument extraction.

## Impact
- API: `FromUnpacked` lambdas/functions can now use `const T&` and `T&&` parameter types.
- ABI: none
- Behavioral: Functions with `const T&` or `T&&` parameters now work correctly with the packed calling convention.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Packed function calling convention and `TypeTraits` protocol
- `Function::FromUnpacked` template machinery

Design elements this commit produces:
- `ArgTypeSupported<T>` -- Compile-time argument type validation for the unpack pipeline.

## Usage Examples
```cpp
// Now valid - const T& parameter:
Function f = Function::FromUnpacked([](const String& s) { return s; });
// Now valid - T&& parameter:
Function g = Function::FromUnpacked([](String&& s) { return std::move(s); });
```
