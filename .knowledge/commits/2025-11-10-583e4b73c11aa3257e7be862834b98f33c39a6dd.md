# Fix arg unpacking to support const/ref/rvalue-ref argument qualifiers in exported functions
## TL;DR
- Templatizes `ArgValueWithContext` from a non-template class with template conversion operator to a template class `ArgValueWithContext<Type>` with non-template conversion operator, fixing compiler errors when argument types have template constructors (e.g., `std::optional<T>`).
- Adds `ArgTypeSupported<T>` compile-time guard restricting exported function arguments to `T`, `const T`, `const T&`, and `T&&` (rejecting `T&` and `const T&&`).
- Updates `unpack_call` to propagate per-argument type information via `std::tuple_element_t<Is, PackedArgs>` into each `ArgValueWithContext<T>` instantiation.

## Impact
- API: None -- `ArgValueWithContext` and `unpack_call` are internal (`details::` namespace), not public API.
- Behavioral: Exported C++ functions can now use `const T&`, `T&&`, and `const T` argument qualifiers without triggering compiler errors. Previously only by-value `T` worked reliably.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Function system** (`.knowledge/designs/0004-function-system.md`): `FunctionInfo<F>`, `FuncFunctorImpl`, `unpack_call`, packed calling convention.
- **Type traits** (`.knowledge/designs/0006-type-traits.md`): `TypeTraitsNoCR<T>::convert_enabled` used in `ArgSupported<T>`, `AnyView::try_cast<T>()` used inside the conversion operator.

Design elements this commit produces:
- **`ArgTypeSupported<T>`**: New compile-time constraint on allowed argument qualifier forms. Codifies the previously implicit assumption that non-const lvalue references and const rvalue references are not meaningful for packed-arg unpacking.
- **`ArgValueWithContext<Type>` (templatized)**: Replaces the non-template class. The template-class-with-non-template-operator pattern avoids ambiguity with types that have template constructors (the motivating case being `std::optional<T>`).

## Usage Examples

Before (would cause compiler errors with `std::optional<T>` or similar template-constructor types):
```cpp
// Old: ArgValueWithContext was non-template, had template<typename Type> operator Type()
// When unpacking f(std::optional<int> x), the compiler sees:
//   ArgValueWithContext has: template<typename Type> operator Type()
//   std::optional<int> has: template<typename U> optional(U&&)
// -> ambiguous overload resolution / unintended instantiation
refl::GlobalDef().def("my.func", [](std::optional<int> x) { return x.value_or(0); });
```

After (works correctly):
```cpp
// New: ArgValueWithContext<std::optional<int>> has non-template operator std::optional<int>()
// No ambiguity -- single conversion path
refl::GlobalDef().def("my.func", [](std::optional<int> x) { return x.value_or(0); });
// Also now works with various qualifiers:
refl::GlobalDef().def("my.func2", [](const String& s) { return s.size(); });
refl::GlobalDef().def("my.func3", [](Any&& val) { return std::move(val); });
```
