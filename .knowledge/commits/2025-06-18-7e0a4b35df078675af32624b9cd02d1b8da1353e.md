# Stabilize container ABI by adding explicit data pointer and deleter to ArrayObj and MapObj
## TL;DR
- Adds explicit `void* data_` and `void (*data_deleter_)(void*)` fields to `ArrayObj` and `MapObj`, decoupling element access from `InplaceArrayBase::AddressOf()` so data can be externally allocated in the future.
- Changes `DenseMapObj` slot semantics: `slots_` now stores the actual slot count (not `n_slots - 1`), probing switches from bitwise AND to modulo, and the `data_` member replaces the direct `Block* data_` pointer.
- Renames dispatch macros from `TVM_DISPATCH_MAP`/`TVM_DISPATCH_MAP_CONST` to `TVM_FFI_DISPATCH_MAP`/`TVM_FFI_DISPATCH_MAP_CONST` for namespace consistency.

## Impact
- API: `ArrayObj::at()` return type changed from `const Any` (by value) to `const Any&` (by reference). Callers that relied on copy semantics from `at()` now get a reference. `Array::emplace_back()` added. Macro names `TVM_DISPATCH_MAP`/`TVM_DISPATCH_MAP_CONST` renamed to `TVM_FFI_DISPATCH_MAP`/`TVM_FFI_DISPATCH_MAP_CONST`.
- Behavioral: `DenseMapObj::slots_` now stores actual slot count instead of `n_slots - 1`. Probing changed from bitwise AND to modulo. `IsFull()` threshold calculation adjusted accordingly. This changes the internal hash table sizing but preserves external semantics.
- Flags/config: none
- Data formats/schemas: The in-memory layout of `ArrayObj` and `MapObj` changed (new fields `data_`, `data_deleter_`, field reordering in `MapObj`). This is an ABI-breaking change for any code that depends on the binary layout of these objects.

## Design Elements
Design elements this commit consumes:
- **InplaceArrayBase** ([0007-containers.md](../designs/0007-containers.md)): Still used for initial allocation, but element access is now decoupled through `data_` pointer.
- **Object system** ([0002-object-system.md](../designs/0002-object-system.md)): `ArrayObj` and `MapObj` remain `Object` subclasses with standard ref-counting.
- **Any/AnyView** ([0003-any-system.md](../designs/0003-any-system.md)): Elements stored as `Any`; new `TVMFFIAny` raw storage type for `KVRawStorageType`.
- **C ABI** ([0001-c-abi.md](../designs/0001-c-abi.md)): The `TVMFFIAny` type used in `KVRawStorageType` is the C-level ABI type.

Design elements this commit produces:
- **Container data pointer pattern**: `void* data_` + `void (*data_deleter_)(void*)` as a standard field pair for containers, decoupling element storage from object allocation. This enables future external/separate allocation while maintaining the same access pattern.
- **KVRawStorageType**: C ABI-compatible raw storage for map key-value pairs using `TVMFFIAny` instead of C++ `Any`.
- **BlockDeleter pattern**: Static deleter functions assigned to `data_deleter_` to ensure cross-shared-library memory safety (allocator and deallocator always from the same library).

## Usage Examples

Before (Tuple creating arrays manually):
```cpp
// Old: manual inplace array construction
ObjectPtr<ArrayObj> p = make_inplace_array_object<ArrayObj, Any>(n);
p->capacity_ = n;
p->size_ = 0;
Any* itr = p->MutableBegin();
```

After (Tuple using ArrayObj::Empty factory):
```cpp
// New: centralized factory handles data_ initialization
ObjectPtr<ArrayObj> p = ArrayObj::Empty(n);
Any* itr = p->MutableBegin();
// data_ is already set to AddressOf(0)
```

Cross-shared-library safety for DenseMapObj:
```cpp
// data_deleter_ ensures the Block[] is freed by the same allocator that created it
ObjectPtr<DenseMapObj> p = DenseMapObj::Empty(fib_shift, n_slots);
// p->data_ = new Block[n_blocks];
// p->data_deleter_ = BlockDeleter;  // static method in same TU
// Later, even if ReleaseMemory() is called from a different shared library:
// p->data_deleter_(p->data_);  // safe: calls the original allocator's delete[]
```
