# Stabilize container ABI: add data_ pointer and data_deleter_ to ArrayObj/MapObj, fix DenseMapObj slot arithmetic

## TL;DR
- Adds an explicit `void* data_` pointer and `void (*data_deleter_)(void*)` callback to `ArrayObj` and `MapObj`, decoupling element storage from the inplace allocation base address. This prepares the ABI for future out-of-band data allocation.
- Fixes `DenseMapObj` slot arithmetic: switches from `slots_ = n_slots - 1` (bitmask-based) to `slots_ = n_slots` (modulo-based), correcting probe wrapping from `& slots_` to `% slots_`.
- Renames internal dispatch macros from `TVM_DISPATCH_MAP` / `TVM_DISPATCH_MAP_CONST` to `TVM_FFI_DISPATCH_MAP` / `TVM_FFI_DISPATCH_MAP_CONST` for namespace consistency.

## Impact
- API: `ArrayObj::at()` return type changed from `const Any` (by value) to `const Any&` (by reference). Callers that relied on copy semantics from `at()` now get a reference. `Array<T>::emplace_back` is a new public method.
- Behavioral: `DenseMapObj` slot arithmetic changed from bitmask (`& slots_`) to modulo (`% slots_`). `slots_` now stores the actual count, not count-minus-one. `IsFull()` and `CalcNumBlocks()` formulas updated accordingly. Rehash growth changed from `slots_ * 2 + 2` to `slots_ * 2`.
- Flags/config: none
- Data formats/schemas: ABI layout of `ArrayObj` and `MapObj` changed -- `data_`, `size_`, `capacity_` (and `data_deleter_`) field ordering differs from the previous version. This is a breaking ABI change for any code that accesses these fields by offset.

## Usage Examples

**ArrayObj with data_ pointer (C++)**:
```cpp
// Empty() now initializes data_ = AddressOf(0) for inplace storage
ObjectPtr<ArrayObj> arr = ArrayObj::Empty(8);
// data_ points to inplace storage; data_deleter_ is nullptr
arr->EmplaceInit(arr->size_++, 42);  // placement-new via data_ pointer

// New emplace_back on Array<T> ref wrapper:
Array<int> a({1, 2, 3});
a.emplace_back(4);  // triggers COW if shared, then EmplaceInit
```

**DenseMapObj with BlockDeleter (C++)**:
```cpp
// DenseMapObj::Empty sets data_deleter_ = BlockDeleter
// This ensures Block[] is freed correctly even across shared-library boundaries
auto p = DenseMapObj::Empty(fib_shift, n_slots);
// p->data_ points to new Block[n_blocks]
// p->data_deleter_ == DenseMapObj::BlockDeleter
// On release: data_deleter_(data_) calls delete[] on the Block array
```
