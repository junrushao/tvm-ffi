# Stabilize container ABI by adding data pointer and deleter fields to ArrayObj and MapObj
## TL;DR
- Adds `data_`, `data_deleter_` fields to `ArrayObj` and `MapObj`, decoupling element access from the inplace array base class and enabling future external allocation.
- Changes `DenseMapObj` slot arithmetic from `slots_ - 1` (mask) to `slots_` (modulo), fixing probing to use `%` instead of `&` for hash table traversal.
- Renames `TVM_DISPATCH_MAP` / `TVM_DISPATCH_MAP_CONST` macros to `TVM_FFI_DISPATCH_MAP` / `TVM_FFI_DISPATCH_MAP_CONST` for namespace consistency.
- Simplifies `Tuple` construction by delegating to `ArrayObj::Empty()` instead of duplicating inplace allocation logic.

## Impact
- API: `ArrayObj::at()` return type changed from `const Any` (value) to `const Any&` (reference). Callers that relied on copy semantics from `at()` now get a reference. `Array::emplace_back()` added as new API.
- Behavioral: `DenseMapObj` slot arithmetic changed from `slots_-1` mask to `slots_` modulo. Hash probing uses `%` instead of `&`, which is correct for arbitrary slot counts (not just power-of-2 minus 1). `CalcNumBlocks` now takes `n_slots` directly instead of `n_slots_m1`.
- Flags/config: none
- Data formats/schemas: `ArrayObj` and `MapObj` field layouts changed (new `data_`, `data_deleter_` fields added before existing fields, field order changed). This is an ABI-breaking change for any code that depends on `ArrayObj` or `MapObj` memory layout.

## Design Elements
Design elements this commit consumes:
- **InplaceArrayBase** (0006-containers): Still used for allocation via `make_inplace_array_object`, but element access now goes through `data_` pointer instead of `AddressOf()`.
- **Any/TVMFFIAny** (0001, 0007): Elements stored as `Any`; `SmallMapObj` now uses `TVMFFIAny` in raw storage type for C ABI alignment.
- **Object system** (0002): All containers remain Object subclasses with ref-counted lifecycle.

Design elements this commit produces:
- **Container data pointer pattern**: `data_` + `data_deleter_` pair on `ArrayObj` and `MapObj` enables future separation of element storage from the object allocation. Initially `data_ = AddressOf(0)` (inplace), but the deleter mechanism supports external storage.
- **DenseMapObj::BlockDeleter**: Static deleter function assigned at allocation time, ensuring cross-DLL safety for block memory.
- **TVM_FFI_DISPATCH_MAP / TVM_FFI_DISPATCH_MAP_CONST**: Renamed macros following `TVM_FFI_` prefix convention.

## Usage Examples
Before (Tuple construction duplicated ArrayObj allocation):
```cpp
// Old: manual inplace allocation in Tuple
ObjectPtr<ArrayObj> p = make_inplace_array_object<ArrayObj, Any>(sizeof...(Types));
p->capacity_ = sizeof...(Types);
p->size_ = 0;
```
After (delegates to ArrayObj::Empty):
```cpp
// New: uses ArrayObj::Empty which sets data_ = AddressOf(0)
ObjectPtr<ArrayObj> p = ArrayObj::Empty(sizeof...(Types));
```

New emplace_back on Array:
```cpp
Array<int> arr;
arr.emplace_back(42);  // variadic forwarding to EmplaceInit
```
