# Stabilize container ABI by adding explicit data pointer, data_deleter, and slots fields to ArrayObj and MapObj
## TL;DR
- Adds an explicit `void* data_` pointer and `void (*data_deleter_)(void*)` callback to `ArrayObj` and `MapObj`, decoupling element storage access from `InplaceArrayBase::AddressOf` and enabling future external/separately-allocated data buffers.
- Changes `DenseMapObj` slot semantics from `slots_ = n-1` (bitmask) to `slots_ = n` (modulo), switching index wrapping from `& slots_` to `% slots_`, which removes the power-of-two constraint on the slot count.
- Renames dispatch macros `TVM_DISPATCH_MAP` / `TVM_DISPATCH_MAP_CONST` to `TVM_FFI_DISPATCH_MAP` / `TVM_FFI_DISPATCH_MAP_CONST` to align with the `TVM_FFI_` prefix convention.

## Key Exports

**Types/Classes (mutated)**:

`ArrayObj` -- new field layout:
```cpp
class ArrayObj : public Object, public details::InplaceArrayBase<ArrayObj, TVMFFIAny> {
  void* data_;                           // NEW: pointer to element storage
  int64_t size_;
  int64_t capacity_;
  void (*data_deleter_)(void*) = nullptr; // NEW: optional deleter for external data
  // Destructor is now explicit (was default via InplaceArrayBase)
  ~ArrayObj();
  // operator[] is now defined directly (bounds-checked, uses data_)
  const Any& operator[](int64_t i) const;
  // at() now returns const Any& (was const Any by value)
  const Any& at(int64_t i) const;
  // EmplaceInit: new placement-new helper
  template <typename... Args> void EmplaceInit(size_t idx, Args&&... args);
  // Empty: now sets data_ = AddressOf(0) after allocation
  static ObjectPtr<ArrayObj> Empty(int64_t n = kInitSize);
};
```

`MapObj` -- new field layout:
```cpp
class MapObj : public Object {
  void* data_;                           // NEW: pointer to data region
  uint64_t size_;
  uint64_t slots_;                       // MOVED: was before size_, now after
  void (*data_deleter_)(void*) = nullptr; // NEW: optional deleter for external data
};
```

`SmallMapObj` -- now inherits `InplaceArrayBase<SmallMapObj, MapObj::KVRawStorageType>` (was `KVType`):
```cpp
struct MapObj::KVRawStorageType {         // NEW: raw C-ABI-safe storage type
  TVMFFIAny first;
  TVMFFIAny second;
};
// Destructor is now explicit (was default)
~SmallMapObj();
```

`DenseMapObj` -- slot semantics changed:
```cpp
// NEW: static deleter + accessor
static void BlockDeleter(void* data);     // deletes Block[]
Block* GetBlock(size_t index) const;      // data_ + index
// Empty() now uses slots_ = n (was n-1), CalcNumBlocks takes n_slots directly
// ReleaseMemory() now uses data_deleter_ instead of raw delete[]
// Rehash growth: slots_ * 2 (was slots_ * 2 + 2)
// IsFull(): size_ + 1 > slots_ * kMaxLoadFactor (was (slots_ + 1) * kMaxLoadFactor)
// Index wrapping: % slots_ (was & slots_)
```

`Array<T>` -- new method:
```cpp
template <typename... Args>
void emplace_back(Args&&... args);        // NEW: variadic emplace into array
```

**Macros (renamed)**:
| Old name | New name |
|---|---|
| `TVM_DISPATCH_MAP` | `TVM_FFI_DISPATCH_MAP` |
| `TVM_DISPATCH_MAP_CONST` | `TVM_FFI_DISPATCH_MAP_CONST` |

## Impact
- API: `ArrayObj::at()` return type changed from `const Any` (by value) to `const Any&` (by reference). Callers relying on the copy semantics may behave differently. `TVM_DISPATCH_MAP`/`TVM_DISPATCH_MAP_CONST` macros are renamed -- any external code using them must update. `ArrayObj` and `MapObj` field layouts changed, breaking binary compatibility with prior versions.
- Behavioral: `DenseMapObj` index wrapping switches from bitwise-AND to modulo, which changes probe sequences. `IsFull()` threshold is subtly different (`slots_` vs `slots_ + 1`). Rehash growth factor changes from `2n+2` to `2n`.
- Flags/config: none
- Data formats/schemas: The in-memory layout of `ArrayObj`, `MapObj`, `SmallMapObj`, and `DenseMapObj` all change due to the new `data_` and `data_deleter_` fields. This is an ABI break for serialized or cross-boundary container objects.

## Design Elements
Design elements this commit consumes:
- **InplaceArrayBase** (`include/tvm/ffi/container/inplace_array_base.h`): Still used for trailing allocation, but `AddressOf()` is now only called once at construction time to initialize `data_`, not at every access.
- **Any/AnyView value system** ([0002-any-value-system](.knowledge/designs/0002-any-value-system.md)): Elements are still stored as `Any` values; the change to `TVMFFIAny` for `InplaceArrayBase` template parameter aligns the raw storage type with the C ABI struct.
- **Object system / make_object / make_inplace_array_object** ([0007-memory-allocation](.knowledge/designs/0007-memory-allocation.md)): Allocation path unchanged; `Empty()` still uses `make_inplace_array_object`.
- **COW semantics** ([0008-containers](.knowledge/designs/0008-containers.md)): `CopyOnWrite` pattern unchanged.

Design elements this commit produces:
- **Explicit data pointer pattern**: `ArrayObj::data_` and `MapObj::data_` decouple element access from `InplaceArrayBase::AddressOf`. This enables a future where container data can be allocated separately (e.g., externally managed memory, mmap'd buffers) and attached via `data_` + `data_deleter_`.
- **data_deleter callback**: A function pointer for custom deallocation of separately-allocated data. `DenseMapObj` already uses this with `BlockDeleter`. `ArrayObj` and `SmallMapObj` set `data_deleter_ = nullptr` when data is inplace (deleter handled by the object's own deleter).
- **KVRawStorageType**: A C-ABI-safe raw storage type for `SmallMapObj` inplace entries, using `TVMFFIAny` instead of `Any` (the C++ wrapper). This ensures the inplace array template computes sizes based on the C struct layout.
- **Modulo-based slot indexing for DenseMapObj**: Replaces bitwise-AND indexing. This removes the assumption that `slots_` is one less than a power of two, making the slot count semantics cleaner.

## Usage Examples

**ArrayObj with data_ pointer (internal pattern)**:
```cpp
// Empty() now initializes data_ to point to inplace storage
ObjectPtr<ArrayObj> p = ArrayObj::Empty(4);
// p->data_ == p->AddressOf(0)  -- points to trailing inplace storage
// p->data_deleter_ == nullptr   -- inplace, no separate deallocation needed

// All access goes through data_:
p->EmplaceInit(0, Any(42));
p->size_++;
const Any& val = (*p)[0];  // reads from static_cast<Any*>(data_)[0]
```

**Array::emplace_back (new API)**:
```cpp
Array<int> arr;
arr.emplace_back(42);       // constructs Any(42) in-place via EmplaceInit
arr.emplace_back(100);
assert(arr.size() == 2);
```

**DenseMapObj with BlockDeleter (internal pattern)**:
```cpp
// DenseMapObj::Empty sets up data_deleter_ for safe cross-library deallocation
ObjectPtr<DenseMapObj> p = DenseMapObj::Empty(fib_shift, n_slots);
// p->data_ = new Block[n_blocks]
// p->data_deleter_ = BlockDeleter
// On destruction or ReleaseMemory(), data_deleter_(data_) is called
// instead of raw delete[] -- safe even if alloc and free happen in different shared libs
```
