# Stabilize container ABI: add data pointer indirection and data_deleter to ArrayObj, MapObj, DenseMapObj

## TL;DR
- Refactors `ArrayObj`, `MapObj`, `SmallMapObj`, and `DenseMapObj` to use an explicit `void* data_` pointer for element storage instead of computing addresses from the inplace array base class. This decouples the data region from the object header, enabling future data reallocation or externally-owned buffers.
- Adds `void (*data_deleter_)(void*)` to `ArrayObj` and `MapObj` for safe cross-shared-library deallocation when data is allocated separately from the object body.
- Changes `DenseMapObj` slot arithmetic from "slots minus 1" (`n_slots - 1`) convention to a direct slot count, fixing hash probing to use modulo (`%`) instead of bitwise-and (`&`) and correcting the `IsFull` / rehash thresholds accordingly.
- Renames internal dispatch macros from `TVM_DISPATCH_MAP` / `TVM_DISPATCH_MAP_CONST` to `TVM_FFI_DISPATCH_MAP` / `TVM_FFI_DISPATCH_MAP_CONST` to follow the project's `TVM_FFI_` prefix convention.
- Simplifies `Tuple` construction by delegating to `ArrayObj::Empty()` instead of manually calling `make_inplace_array_object` and setting fields.

## Key Exports

### ArrayObj (`include/tvm/ffi/container/array.h`)

**New fields:**
- `void* data_` -- Pointer to the first element of the array. Set to `AddressOf(0)` in `Empty()`. Replaces direct use of `InplaceArrayBase::AddressOf(0)` throughout the class.
- `void (*data_deleter_)(void*) = nullptr` -- Optional deleter called in `~ArrayObj()` when data is allocated separately from the object body. Enables safe cleanup when a different allocator (e.g., from another shared library) produced the data region.

**Changed field order (ABI break):** The layout is now `data_`, `size_`, `capacity_`, `data_deleter_` (previously `size_`, `capacity_` only).

**Changed methods:**
- `at(int64_t i)` -- Now returns `const Any&` (reference) instead of `const Any` (value copy).
- `operator[](int64_t i)` -- New explicit implementation with bounds checking and `IndexError` throw; accesses elements via `static_cast<Any*>(data_)[i]`.
- `begin()` -- Returns `static_cast<Any*>(data_)` instead of `InplaceArrayBase::AddressOf(0)`.
- `SetItem(int64_t i, Any item)` -- Adds explicit bounds check before writing via `data_`.
- `MutableBegin()` -- Returns `static_cast<Any*>(this->data_)`.
- `EmplaceInit(size_t idx, Args&&... args)` -- New template method: placement-new at `MutableBegin() + idx`.
- `Empty(int64_t n)` -- Now sets `p->data_ = p->AddressOf(0)` after allocation.
- `~ArrayObj()` -- New explicit destructor: destroys each `Any` element and calls `data_deleter_` if non-null.

**InplaceArrayBase template argument:** Changed from `InplaceArrayBase<ArrayObj, Any>` to `InplaceArrayBase<ArrayObj, TVMFFIAny>` (C struct type for layout correctness).

**New method on `Array<T>`:**
- `emplace_back(Args&&... args)` -- Variadic emplace via `CopyOnWrite(1)` + `EmplaceInit`.

### MapObj (`include/tvm/ffi/container/map.h`)

**New fields:**
- `void* data_` -- Pointer to the data region of the map (replaces implicit inplace base for `SmallMapObj`, replaces `Block* data_` for `DenseMapObj`).
- `void (*data_deleter_)(void*) = nullptr` -- Optional deleter, same semantics as `ArrayObj`.

**Changed field order (ABI break):** Layout is now `data_`, `size_`, `slots_`, `data_deleter_` (previously `slots_`, `size_`).

**New type:**
- `MapObj::KVRawStorageType` -- A struct of two `TVMFFIAny` fields used as the raw storage type in `InplaceArrayBase` for `SmallMapObj`, replacing `KVType` (which contains C++ `Any` objects that would be double-destructed by the inplace array base).

**Renamed macros:**
- `TVM_DISPATCH_MAP` -> `TVM_FFI_DISPATCH_MAP`
- `TVM_DISPATCH_MAP_CONST` -> `TVM_FFI_DISPATCH_MAP_CONST`

### SmallMapObj (`include/tvm/ffi/container/map.h`)

**InplaceArrayBase template argument:** Changed from `InplaceArrayBase<SmallMapObj, MapObj::KVType>` to `InplaceArrayBase<SmallMapObj, MapObj::KVRawStorageType>`.

**Changed methods:**
- `~SmallMapObj()` -- New explicit destructor: manually destroys each `KVType` entry's `first` and `second` `Any` fields, then calls `data_deleter_` if non-null (previously defaulted).
- `find()`, `erase()`, `DeRefItr()`, `CopyFrom()`, `CreateFromRange()`, `InsertMaybeReHash()` -- All switched from `AddressOf(...)` to `static_cast<KVType*>(data_)` or `static_cast<KVType*>(data_) + index`.
- `Empty()` -- Now sets `p->data_ = p->AddressOf(0)`.

### DenseMapObj (`include/tvm/ffi/container/map.h`)

**Removed field:**
- `Block* data_` -- Replaced by the inherited `MapObj::data_` (`void*` type).

**New static method:**
- `BlockDeleter(void* data)` -- `delete[] static_cast<Block*>(data)`. Used as the `data_deleter_` callback to ensure blocks are freed by the same allocator that created them, even across shared library boundaries.

**New private method:**
- `GetBlock(size_t index)` -- Returns `static_cast<Block*>(data_) + index`. Replaces all direct `data_[index]` accesses.

**Slot count convention change:**
- `slots_` now stores the actual number of slots (previously stored `n_slots - 1`).
- `CalcNumBlocks(uint64_t n_slots)` simplified: no longer needs the `n_slots_m1 > 0 ? n_slots_m1 + 1 : 0` conversion.
- `Empty(uint32_t fib_shift, uint64_t n_slots)` -- Sets `p->slots_ = n_slots` (was `n_slots - 1`).
- `IsFull()` -- Changed from `size_ + 1 > (slots_ + 1) * kMaxLoadFactor` to `size_ + 1 > slots_ * kMaxLoadFactor`.
- Rehash in `InsertMaybeReHash` -- Changed from `slots_ * 2 + 2` to `slots_ * 2`.

**Hash probing fix:**
- `ListNode::MoveToNext()` and `ListNode::GetNextEmpty()` -- Changed from `(index + offset) & (self->slots_)` to `(index + offset) % self->slots_`. The old bitwise-and only works correctly when `slots_` is a power-of-two minus one. The new modulo is correct for any slot count.
- `ListNode(uint64_t index, const DenseMapObj* self)` constructor and `CopyFrom` -- Use `self->GetBlock(...)` instead of direct array indexing on the old `data_` field.

**Memory management:**
- `ReleaseMemory()` -- Now checks `data_deleter_ != nullptr` and calls it (was `delete[] data_`). Resets both `data_` and `data_deleter_` to null.
- `Empty()` and `CopyFrom()` -- Set `p->data_deleter_ = BlockDeleter` after allocating blocks.

### Tuple (`include/tvm/ffi/container/tuple.h`)

**Simplified internal helpers:**
- `MakeDefaultTupleNode()`, `MakeTupleNode()`, `CopyIfNotUnique()` -- All now call `ArrayObj::Empty(sizeof...(Types))` instead of manually calling `make_inplace_array_object<ArrayObj, Any>(sizeof...(Types))` and setting `capacity_` and `size_`.

## Impact
- API: `ArrayObj::at()` now returns `const Any&` (was `const Any`). New `Array<T>::emplace_back()`. Internal dispatch macros renamed. All changes are source-compatible for typical downstream code.
- ABI: **Breaking.** `ArrayObj` and `MapObj` field layouts changed (new `data_` and `data_deleter_` fields, reordered members). `DenseMapObj::slots_` semantics changed from "slots minus 1" to actual count. Any code compiled against the old layout must be recompiled.
- Behavioral: `DenseMapObj` hash probing now uses modulo instead of bitwise-and, which is correct for arbitrary slot counts. The old approach only worked correctly for power-of-two slot sizes. `ArrayObj` destructor now explicitly destroys elements and calls the data deleter instead of relying solely on `InplaceArrayBase` destruction.
- Cross-library safety: The `data_deleter_` function pointer ensures that data allocated in one shared library is freed by that same library's allocator, avoiding heap corruption when different shared libraries use different malloc/free implementations.

## Design Elements
Design elements this commit consumes:
- `InplaceArrayBase<T, ElemType>` -- CRTP base for inplace-allocated arrays (from root commit).
- `TVMFFIAny` -- C-level 16-byte type-erased value struct.
- Copy-on-write semantics in `Array<T>` and `Map<K,V>`.
- Fibonacci hashing in `DenseMapObj` for open-addressing hash map.

Design elements this commit produces:
- **Data pointer indirection pattern** -- Containers store an explicit `void* data_` pointer to their element storage rather than computing it from the inplace array base. This enables future use cases where the data region is allocated separately from the object body (e.g., external or reallocated buffers).
- **Cross-library data deleter** -- The `void (*data_deleter_)(void*)` callback pattern ensures safe deallocation when container data is produced by a different shared library with potentially different allocator implementations. `DenseMapObj::BlockDeleter` is the first concrete example.
- **KVRawStorageType for SmallMapObj** -- Using `TVMFFIAny` pairs as the inplace storage type (instead of `Any` pairs) prevents double destruction: the inplace array base manages raw storage while `SmallMapObj::~SmallMapObj()` handles `Any` destructor calls explicitly.
- **Modulo-based probing** -- `DenseMapObj` now uses `% slots_` instead of `& slots_` for probe location wrapping, removing the implicit requirement that slot counts be powers of two minus one.
- **TVM_FFI_ macro prefix convention** -- Map dispatch macros now follow the `TVM_FFI_` prefix convention established for all project macros.

## Usage Examples
No user-facing usage change. The API remains source-compatible. The main observable difference is that `ArrayObj::at()` returns a const reference instead of a copy, which may improve performance for callers that were binding the result to a reference.
