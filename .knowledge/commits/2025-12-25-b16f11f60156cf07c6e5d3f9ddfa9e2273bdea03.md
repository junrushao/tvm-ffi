# Refactor cubin launcher to unified CUDA Driver/Runtime API with declarative CMake

## TL;DR
- Introduces `tvm::ffi::cuda_api` unified abstraction layer (`internal/unified_api.h`) that switches between CUDA Runtime API (>= 12.8) and Driver API at compile time, replacing hardcoded `cudaLibrary_t`/`cudaKernel_t`/`cudaError_t` types throughout `CubinModule`/`CubinKernel`.
- Adds `TVM_FFI_EMBED_CUBIN_FROM_BYTES` macro for loading CUBIN from `unsigned char[]` byte arrays (enables C++23 `#embed` and `bin2c` workflows).
- Replaces imperative CMake functions (`tvm_ffi_generate_cubin`/`tvm_ffi_embed_cubin`) with declarative target-based approach (`add_tvm_ffi_cubin`, `add_tvm_ffi_fatbin`, `tvm_ffi_embed_bin_into`).

## Impact
- API: `CubinModule`/`CubinKernel` public API types changed from `cudaLibrary_t`/`cudaKernel_t`/`cudaStream_t`/`cudaError_t` to `cuda_api::LibraryHandle`/`KernelHandle`/`StreamHandle`/`ResultType`. Direct callers using the old types must update. New `const unsigned char*` constructor on `CubinModule`.
- Behavioral: `TVM_FFI_CHECK_CUDA_ERROR` now dispatches to either Driver or Runtime error-string functions. Error messages prefix changed from `"CUDA Runtime Error:"` to `"CUDA Error:"`.
- Flags/config: New compile-time macro `TVM_FFI_CUBIN_LAUNCHER_USE_DRIVER_API` (0 or 1). `CMAKE_CUDA_RUNTIME_LIBRARY` now defaults to `Shared` when including `EmbedCubin.cmake`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_THROW(RuntimeError)` from error protocol ([0005](../../.knowledge/design-records/0005-ffi-error-protocol.md)) — used in `TVM_FFI_CHECK_CUDA_ERROR`.
- `Bytes` container from ([0006](../../.knowledge/design-records/0006-ffi-containers.md)) — `CubinModule(Bytes)` constructor.
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` from ([0013](../../.knowledge/design-records/0013-ffi-packaging-and-distribution.md)) — examples export kernel wrappers.
- `tvm_ffi.utils.embed_cubin` Python utility ([0019](../../.knowledge/design-records/0019-ffi-cuda-extras.md)) — invoked by `tvm_ffi_embed_bin_into` CMake function.

Design elements this commit produces:
- **`tvm::ffi::cuda_api` namespace** — new unified abstraction layer over CUDA Driver/Runtime APIs with compile-time switching.
- **`TVM_FFI_EMBED_CUBIN_FROM_BYTES` macro** — new embedding path for byte-array CUBIN data.
- **`add_tvm_ffi_cubin` / `add_tvm_ffi_fatbin` / `tvm_ffi_embed_bin_into`** — new declarative CMake functions replacing old imperative ones.
- **`ObjectCopyUtil.cmake`** — helper script for `.cu.o` to `.cubin`/`.fatbin` renaming.

Design elements this commit mutates:
- **`CubinModule`** — `library_` type changed to `cuda_api::LibraryHandle`; new `const unsigned char*` constructor.
- **`CubinKernel`** — `kernel_` type changed to `cuda_api::KernelHandle`; `Launch` return type and `stream` parameter types changed to unified aliases.
- **`TVM_FFI_CHECK_CUDA_ERROR`** — moved from `base.h` to `internal/unified_api.h`, now dispatches to either API.
- **`dim3`** — moved from `cubin_launcher.h` to `base.h`; `base.h` no longer includes any CUDA headers.
- **CMake `EmbedCubin.cmake`** — old functions removed, new target-based functions added.

## Usage Examples

Embedding CUBIN from a C++23 `#embed` byte array:
```cpp
#include <tvm/ffi/extra/cuda/cubin_launcher.h>

constexpr unsigned char image[]{
#embed "kernel_fatbin.fatbin"
};
TVM_FFI_EMBED_CUBIN_FROM_BYTES(env, image);

void Launch() {
  static auto kernel = TVM_FFI_EMBED_CUBIN_GET_KERNEL(env, "add_one_cuda");
  void* args[] = {&x_ptr, &y_ptr, &n};
  tvm::ffi::cuda_api::ResultType result =
      kernel.Launch(args, tvm::ffi::dim3(grid_size), tvm::ffi::dim3(256), stream);
  TVM_FFI_CHECK_CUDA_ERROR(result);
}
```

New declarative CMake workflow:
```cmake
include(cmake/Utils/EmbedCubin.cmake)
add_tvm_ffi_fatbin(kernel_fatbin CUDA src/kernel.cu)

add_library(lib_embedded SHARED src/lib_embedded.cc)
tvm_ffi_embed_bin_into(lib_embedded SYMBOL env BIN "$<TARGET_OBJECTS:kernel_fatbin>")
target_link_libraries(lib_embedded PRIVATE tvm_ffi::header CUDA::cudart)
```
