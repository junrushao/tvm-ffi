# Refactor TVM_FFI_STATIC_INIT_BLOCK to function-style syntax with compiler-specific backends
## TL;DR
- Changes `TVM_FFI_STATIC_INIT_BLOCK` from a statement-macro taking a brace-delimited body argument (`TVM_FFI_STATIC_INIT_BLOCK({...})`) to a function-style macro (`TVM_FFI_STATIC_INIT_BLOCK() {...}`), making the syntax cleaner and improving compiler error reporting by pointing to a named function rather than an anonymous lambda.
- On GCC/Clang, the new macro uses `__attribute__((constructor))` to define a static function that runs before `main()`. On other compilers (MSVC), it falls back to a forward-declared function invoked by a self-executing lambda assigned to a `static inline int` variable.
- Removes the `TVM_FFI_ATTRIBUTE_UNUSED` macro (alias for `[[maybe_unused]]`) and the `TVM_FFI_STATIC_INIT_BLOCK_VAR_DEF` helper, consolidating into the two-branch `TVM_FFI_STATIC_INIT_BLOCK` definition.
- Updates all 18 call sites across `src/ffi/`, `src/ffi/extra/`, `tests/cpp/`, `examples/`, and `docs/` to the new syntax.

## Impact
- API: The public macro `TVM_FFI_STATIC_INIT_BLOCK` changes calling convention. Downstream C++ code that uses the old `TVM_FFI_STATIC_INIT_BLOCK({...})` form will fail to compile and must be updated to `TVM_FFI_STATIC_INIT_BLOCK() {...}`. This is a source-breaking change for any external consumer of the macro.
- Flags/config: None.
- Data formats/schemas: None.
- Runtime behavior: No change. The macro still runs the same code during static initialization. The GCC/Clang path now uses `__attribute__((constructor))` instead of a self-executing lambda, which is functionally equivalent for static init but produces better error messages because the init code lives in a named function (`__TVMFFIStaticInitFunc<N>`) rather than an anonymous lambda.

## Design Elements
Design elements this commit consumes:
- **`TVM_FFI_STATIC_INIT_BLOCK` macro** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): The universal static-initialization mechanism used by all `ObjectDef`, `GlobalDef`, `TypeAttrDef`, and `EnsureTypeAttrColumn` registration sites. This commit modifies the macro definition itself.
- **Reflection registration flow** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): Every `TVM_FFI_STATIC_INIT_BLOCK` call site in `src/ffi/` uses `ObjectDef<T>` or `GlobalDef` to register types and functions. The block body content is unchanged; only the wrapping syntax changes.
- **GlobalDef migration** ([`.knowledge/ADRs/0010-globaldef-replaces-register-global.md`](../ADRs/0010-globaldef-replaces-register-global.md)): All core FFI registrations were migrated to `GlobalDef` within `TVM_FFI_STATIC_INIT_BLOCK` blocks in commit `b333288`. This commit updates the syntax of those same blocks.
- **Documentation and examples** ([`.knowledge/designs/0016-packaging-and-build.md`](../designs/0016-packaging-and-build.md)): `docs/guides/packaging.md`, `docs/guides/python_guide.md`, and `examples/packaging/src/extension.cc` all show user-facing code that uses the macro. These are updated to the new syntax so documentation stays correct.

Design elements this commit produces:
- **Compiler-branched static init** (evolution of existing element): The macro now has two distinct implementations: (1) `__attribute__((constructor))` on GCC/Clang, generating a named function with constructor attribute, and (2) the forward-declared function + variable trick on other compilers. The old implementation used a single lambda-based approach for all compilers. This split is internal to `base_details.h` and transparent to callers, but affects debugging and error reporting behavior.
- **Removal of `TVM_FFI_ATTRIBUTE_UNUSED`**: This macro was previously used by `TVM_FFI_STATIC_INIT_BLOCK_VAR_DEF` and `TVM_FFI_FUNC_REG_VAR_DEF`. Its removal means any remaining references to it in the codebase would break. The replacement is direct use of `[[maybe_unused]]` in the non-GCC fallback path.

None. This is a syntactic refactor of an existing mechanism. The decision to use `__attribute__((constructor))` on GCC/Clang is a minor implementation choice, not an architectural decision warranting an ADR.

## Self-Evolution of Skill /commit-ledger

The procedure worked well for this refactor commit. Two observations:

1. **Stale knowledge base detection**: This commit changes the calling convention of `TVM_FFI_STATIC_INIT_BLOCK`, which is referenced in at least three design docs (`0006-reflection.md`, `0010-type-attr-columns.md`, `0004-function-system.md`) and one diagram (`0004-reflection-registration-flow.md`) with the old syntax. The procedure should add a sub-step to Step 3 or Step 5: "For macro/API renames or calling convention changes, grep `.knowledge/` for the old form and flag stale references as updates needed." This would make the Reflection section more actionable.

2. **Mechanical migration shortcut**: For commits where 16 out of 18 files have identical `s/old-syntax/new-syntax/` changes, the Step 1 per-file diff review is low-value. A fast path could be: "If `git show --stat` shows >10 files and the commit message says 'update' or 'refactor', sample 3 representative files from the diff. If they all show the same pattern, summarize the pattern and focus on outlier files (the header change, test changes, doc changes)."
