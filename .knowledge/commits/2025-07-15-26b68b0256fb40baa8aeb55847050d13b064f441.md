# Phase out TVM_FFI_REGISTER_GLOBAL macro in favor of GlobalDef

## TL;DR
- Removes the entire `Function::Registry` inner class (~100 lines) and the `TVM_FFI_REGISTER_GLOBAL` / `TVM_FFI_FUNC_REG_VAR_DEF` macros (~15 lines) from `include/tvm/ffi/function.h`.
- This is a pure deletion (0 additions, 144 deletions in a single file) that completes the migration to the `GlobalDef` mechanism in `include/tvm/ffi/reflection/registry.h`.
- The replacement `GlobalDef` class provides equivalent functionality (`def`, `def_packed`, `def_method`) plus richer metadata: type schema strings, docstrings, and structured `TVMFFIMethodInfo` registration via `TVMFFIFunctionSetGlobalFromMethodInfo`.

## Impact
- **API**: Breaking change for any downstream C++ code still using `TVM_FFI_REGISTER_GLOBAL(name).set_body_typed(...)` or `.set_body_packed(...)` or `.set_body_method(...)`. Callers must migrate to `reflection::GlobalDef().def(name, func)` / `.def_packed(name, func)` / `.def_method(name, func)`. No new C++ code in the repository references the removed symbols (confirmed by grep).
- **Flags/config**: None.
- **Data formats/schemas**: None. The underlying `Function::SetGlobal` and `GlobalFunctionTable` remain unchanged; only the registration sugar is replaced.

## Design Elements

Design elements this commit **consumes**:
- **Function System** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): The removed `Function::Registry` class was the original builder for `TVM_FFI_REGISTER_GLOBAL`. Its methods (`set_body_typed`, `set_body_packed`, `set_body_method`) all called `Function::SetGlobal` internally. The replacement `GlobalDef::RegisterFunc` calls `TVMFFIFunctionSetGlobalFromMethodInfo` instead, which is a C-ABI-level entry point that also records method metadata.
- **Reflection System** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `GlobalDef` inherits from `ReflectionDefBase` and uses the reflection infrastructure (`MethodInfoBuilder`, `TVMFFIMethodInfo`, metadata JSON) to register global functions with type schema annotations.
- **GlobalFunctionTable** ([`.knowledge/ADRs/0004-global-function-table-leak.md`](../ADRs/0004-global-function-table-leak.md)): The underlying storage is unchanged. Both old (`Function::SetGlobal`) and new (`TVMFFIFunctionSetGlobalFromMethodInfo`) paths ultimately write to the same leaked singleton.

Design elements this commit **produces**:
- **None new.** This is a pure removal commit. The replacement `GlobalDef` class already existed (introduced in a prior commit that added `include/tvm/ffi/reflection/registry.h`). This commit only removes the now-superseded API surface.

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0004-function-system.md`**: The design doc (lines 144-156, 180) still documents `Function::Registry`, `TVM_FFI_REGISTER_GLOBAL`, and `set_body_typed`/`set_body_packed`/`set_body_method` as active APIs. These references should be updated to document `GlobalDef` as the current registration mechanism, noting that `GlobalDef` goes through `TVMFFIFunctionSetGlobalFromMethodInfo` rather than `Function::SetGlobal` directly, enabling richer metadata (type schemas, docstrings). This helps future commit mining because any commit touching global function registration will now reference `GlobalDef` / `registry.h`, not `Function::Registry`.

- **`.knowledge/designs/0006-reflection.md`**: The existing doc focuses on field reflection (`ReflectionDef`, `TVMFFIFieldInfo`). It should be extended to cover `GlobalDef` as a sibling reflection builder for global functions, documenting the `TVMFFIMethodInfo` struct, `TVMFFIFunctionSetGlobalFromMethodInfo` C API, and the metadata JSON format. This bridges the gap between the field-reflection doc and the function-system doc.

### ADRs to write

- **`.knowledge/ADRs/0006-globaldef-over-register-global.md`**: Records the decision to replace `TVM_FFI_REGISTER_GLOBAL` (macro + `Function::Registry` builder) with `reflection::GlobalDef`. Context: the original macro provided no metadata beyond the function name; `GlobalDef` integrates with the reflection system to attach type schemas and docstrings, enabling Python stub generation and introspection. Alternatives: (1) keep both mechanisms (complexity, divergent registration paths), (2) extend `Function::Registry` with metadata support (would duplicate reflection infrastructure). Trade-off: breaking change for existing C++ registrations, but unifies all registration through a single reflection-based path.

### Design diagrams to draw

- **Mermaid: Global function registration flow (old vs new)**. Should depict the two paths side by side:
  - Old: `TVM_FFI_REGISTER_GLOBAL` -> `Function::Registry::set_body_typed` -> `Function::FromTyped` -> `Function::SetGlobal` -> `GlobalFunctionTable`
  - New: `GlobalDef().def(name, func)` -> `Function::FromTyped` + `FunctionInfo::TypeSchema` -> `TVMFFIFunctionSetGlobalFromMethodInfo` -> `GlobalFunctionTable` + type metadata
