# Fix from_dlpack consumer path to use _get_dlpack_exchange_api for PyCapsule-based attribute
## TL;DR
- After 7f3bb77 upgraded `__c_dlpack_exchange_api__` from raw `int` to `PyCapsule`, the `_from_dlpack_universal()` consumer path still did a direct `<DLPackExchangeAPI*><long long>` cast, which crashes on `PyCapsule` objects.
- Fix routes through `_get_dlpack_exchange_api()`, the dual-mode helper that handles both `int` (legacy) and `PyCapsule` (current) attribute types.
- Adds a regression test (`test_from_dlpack_torch`) that exercises `tvm_ffi.from_dlpack(torch_tensor)`.

## Key Exports

```python
# No new exports. Fix is internal to _from_dlpack_universal().

# _from_dlpack_universal (python/tvm_ffi/cython/tensor.pxi) -- CHANGED calling convention:
#
# Before (broken):
#   exchange_api = <DLPackExchangeAPI*><long long>(ext_tensor.__c_dlpack_exchange_api__)
#   _from_dlpack_exchange_api(ext_tensor, exchange_api, ...)
#
# After (fixed):
#   cdef const DLPackExchangeAPI* exchange_api = NULL
#   _get_dlpack_exchange_api(ext_tensor.__c_dlpack_exchange_api__, &exchange_api)
#   _from_dlpack_exchange_api(ext_tensor, exchange_api, ...)
#
# Interacts with: _get_dlpack_exchange_api() (tensor.pxi:36) -- dual-mode int/PyCapsule extraction
# Interacts with: _from_dlpack_exchange_api() -- actual DLPack conversion
# Invariant: exchange_api pointer is now const-qualified, matching _from_dlpack_exchange_api signature

# _from_dlpack_exchange_api (python/tvm_ffi/cython/tensor.pxi) -- CHANGED signature:
#   exchange_api parameter: DLPackExchangeAPI* -> const DLPackExchangeAPI*
# Interacts with: managed_tensor_from_py_object_no_sync (DLPackExchangeAPI struct field)
```

## Impact
- API: None -- no public API change.
- Behavioral: `tvm_ffi.from_dlpack(torch_tensor)` now works correctly when the exchange API attribute is a PyCapsule (the default after 7f3bb77). Previously crashed with a type cast error.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- DLPackExchangeAPI PyCapsule transport ([ADR-0015](../../.knowledge/ADRs/0015-dlpack-exchange-api-struct.md)): the `_get_dlpack_exchange_api()` dual-mode helper introduced in 7f3bb77.
- `_from_dlpack_universal()` priority chain: exchange API path > `__dlpack__` protocol > legacy DLPack.

Design elements this commit produces: None -- purely a bugfix aligning the consumer path with the already-shipped PyCapsule transport.

## Usage Examples
**Before (broken)**: `tvm_ffi.from_dlpack(torch_tensor)` crashes when `torch.Tensor.__c_dlpack_exchange_api__` is a PyCapsule because Cython cannot cast a PyCapsule to `long long`.

**After (fixed)**:
```python
import torch
import tvm_ffi

tensor = torch.arange(24, dtype=torch.float32).reshape(2, 3, 4)
tensor_from_dlpack = tvm_ffi.from_dlpack(tensor)  # works correctly
assert tensor_from_dlpack.shape == tensor.shape
assert tensor_from_dlpack.dtype == tvm_ffi.float32
```
