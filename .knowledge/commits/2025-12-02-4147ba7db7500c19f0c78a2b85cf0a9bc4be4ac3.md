# Fix from_dlpack fallback to use _get_dlpack_exchange_api for PyCapsule-based API attribute
## TL;DR
- Fixes `_from_dlpack_universal` in `tensor.pxi` to properly extract the `DLPackExchangeAPI*` pointer from `__c_dlpack_exchange_api__` via `_get_dlpack_exchange_api()` instead of casting it directly as a raw integer. This broke after the attribute changed from a raw pointer to a PyCapsule.
- Adds `const` qualifier to `DLPackExchangeAPI*` parameter in `_from_dlpack_exchange_api`.
- Adds a `test_from_dlpack_torch` test covering the `from_dlpack` fallback fastpath with a torch tensor.

## Key Exports
None (no new API surface; behavioral fix only).

## Impact
- API: None.
- Behavioral: `tvm_ffi.from_dlpack(torch_tensor)` now works correctly when the tensor has a `__c_dlpack_exchange_api__` attribute that returns a PyCapsule rather than a raw integer pointer.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
**Before** (buggy): `__c_dlpack_exchange_api__` was cast directly as `<DLPackExchangeAPI*><long long>(ext_tensor.__c_dlpack_exchange_api__)`, which fails when the attribute is a PyCapsule.

**After** (fixed): Uses `_get_dlpack_exchange_api(ext_tensor.__c_dlpack_exchange_api__, &exchange_api)` to correctly extract the pointer from the PyCapsule.
