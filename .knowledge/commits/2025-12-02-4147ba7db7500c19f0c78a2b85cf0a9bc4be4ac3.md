# Fix from_dlpack to use _get_dlpack_exchange_api dispatcher instead of raw int cast
## TL;DR
- `_from_dlpack_universal()` was bypassing `_get_dlpack_exchange_api()` and doing a raw `<DLPackExchangeAPI*><long long>` cast on `__c_dlpack_exchange_api__`, which broke when the attribute was a PyCapsule (the standard after commit 7f3bb771's eager int-to-capsule upgrade).
- Fix routes through `_get_dlpack_exchange_api()` which correctly dispatches on both `int` and `PyCapsule` types.
- Adds `const` qualifier to `exchange_api` parameter in `_from_dlpack_exchange_api` for const-correctness.

## Key Exports

```python
# Fixed internal Cython helper (tensor.pxi) — signature change only:
# Old: _from_dlpack_exchange_api(ext_tensor, DLPackExchangeAPI* exchange_api, ...)
# New: _from_dlpack_exchange_api(ext_tensor, const DLPackExchangeAPI* exchange_api, ...)
# Interacts with: _get_dlpack_exchange_api(), _from_dlpack_universal()

# Fixed dispatch in _from_dlpack_universal (tensor.pxi):
# Old (broken): <DLPackExchangeAPI*><long long>(ext_tensor.__c_dlpack_exchange_api__)
# New (correct): _get_dlpack_exchange_api(ext_tensor.__c_dlpack_exchange_api__, &exchange_api)
# Invariant: __c_dlpack_exchange_api__ may be int OR PyCapsule; must always go through _get_dlpack_exchange_api
```

## Impact
- API: None -- `from_dlpack()` public signature unchanged.
- Behavioral: `from_dlpack()` now correctly handles PyCapsule-typed `__c_dlpack_exchange_api__` attributes. Previously, the raw `<long long>` cast on a PyCapsule produced a garbage pointer, causing crashes or silent corruption when using `from_dlpack()` on tensors from frameworks whose exchange API attribute had been eagerly upgraded to PyCapsule at import time.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`__c_dlpack_exchange_api__` protocol** (`int | PyCapsule`, see [0012-ffi-python-package](../design-records/0012-ffi-python-package.md)): the fix ensures `_from_dlpack_universal` respects the dual-type contract introduced by 7f3bb771.
- **`_get_dlpack_exchange_api()` dispatcher** (Cython internal, tensor.pxi): the existing dispatch function that correctly handles both int and PyCapsule, which was being bypassed by the buggy code.
- **`DLPackExchangeAPI` struct** (see [0012-ffi-python-package](../design-records/0012-ffi-python-package.md)): 5-function-pointer struct for zero-overhead C-level DLPack exchange.

Design elements this commit produces: None -- pure bugfix restoring existing protocol contract.

## Usage Examples
Before/after pattern showing the bug:

```python
# BEFORE (broken): raw cast fails when attribute is PyCapsule
import torch, tvm_ffi
t = torch.arange(24, dtype=torch.float32).reshape(2, 3, 4)
# torch.Tensor.__c_dlpack_exchange_api__ is PyCapsule after tvm_ffi import
ffi_t = tvm_ffi.from_dlpack(t)  # CRASH: <long long> cast on PyCapsule

# AFTER (fixed): routes through _get_dlpack_exchange_api dispatcher
ffi_t = tvm_ffi.from_dlpack(t)  # OK: dispatcher extracts ptr from PyCapsule
assert ffi_t.shape == t.shape
assert ffi_t.dtype == tvm_ffi.float32
```
