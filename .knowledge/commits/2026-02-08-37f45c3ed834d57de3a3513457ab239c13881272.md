# Fix torch_c_dlpack_ext build reliability and ABI mismatch handling
## TL;DR
- Prevents build_backend.py from failing when torch is not installed by guarding the import with `contextlib.suppress`
- Catches `AttributeError` in `_optional_torch_c_dlpack.py` when torch_c_dlpack_ext has ABI mismatch with torch, falling through to JIT path

## Key Exports
None -- bugfix only, no new API surface.

## Impact
- API: none
- Behavioral: `build_wheel()` now gracefully skips torch_c_dlpack_ext compilation when torch is absent; `load_torch_c_dlpack_extension()` no longer crashes on ABI-mismatched shared libraries
- Flags/config: none
- Data formats/schemas: none

Design elements this commit consumes:

Design elements this commit produces: none

## Usage Examples
**Before (broken):** `build_wheel()` raises `ModuleNotFoundError` when torch is absent.
**After (fixed):** `build_wheel()` skips compilation, produces a wheel without the prebuilt extension.
