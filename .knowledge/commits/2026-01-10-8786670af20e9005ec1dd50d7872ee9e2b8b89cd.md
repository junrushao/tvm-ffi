# Add `tvm_ffi.Function.__init__` for direct Python callable wrapping
## TL;DR
- Adds `Function.__init__(func)` in Cython so users can construct a `tvm_ffi.Function` directly from any Python callable or existing `Function` instance.
- Two code paths: if `func` is already a `Function`, increments its refcount and reuses the handle; otherwise, delegates to `_convert_to_ffi_func_handle` to wrap the Python callable as an FFI function.
- Adds type stub in `core.pyi` and a test in `test_function.py`. Also fixes Doxygen comment placement in `base_details.h`.

## Key Exports

```python
class Function(Object):
    """Type-erased callable with packed calling convention."""

    def __init__(self, func: Callable[..., Any]) -> None:
        """Construct a Function from a Python callable or existing Function.

        Two paths:
        - isinstance(func, Function): reuse handle with TVMFFIObjectIncRef
        - else: _convert_to_ffi_func_handle wraps the callable
        """
        # Invariant: func must be callable (TypeError otherwise)
        # Interacts with: _convert_to_ffi_func_handle (Cython internal), TVMFFIObjectIncRef (C ABI)
        # Interacts with: Function.__from_extern_c__, Function.__from_mlir_packed_safe_call__ (alternative construction)
        # Extension: this is the idiomatic Python construction path; __from_extern_c__ and
        #   __from_mlir_packed_safe_call__ remain for raw C/MLIR pointer construction
        ...
```

## Impact
- API: Adds a new public constructor `tvm_ffi.Function(callable)`. Previously, users had to rely on implicit conversion via `convert()` or the lower-level `__from_extern_c__` / `__from_mlir_packed_safe_call__` class methods. This is purely additive.
- Behavioral: none -- existing code paths are unchanged.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Function system** ([0004-ffi-function-system](../design-records/0004-ffi-function-system.md)): Uses `TVMFFIObjectIncRef` for the `isinstance(func, Function)` fast path, and `_convert_to_ffi_func_handle` for the general callable wrapping path.
- **Python package Cython dispatch** ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md)): `_convert_to_ffi_func_handle` is the existing Cython helper that wraps a Python callable into an FFI function handle via `TVMFFIPyFuncWrapper`.

Design elements this commit produces:
- **`Function.__init__`**: A new idiomatic Python construction path for `tvm_ffi.Function`. This completes the Python-side Function construction API alongside `__from_extern_c__` and `__from_mlir_packed_safe_call__`. The design record [0004-ffi-function-system](../design-records/0004-ffi-function-system.md) should be updated to document this path.

## Usage Examples
Constructing a `tvm_ffi.Function` from a Python callable:
```python
import tvm_ffi

def add(a: int, b: int) -> int:
    return a + b

# Direct construction via __init__
fadd = tvm_ffi.Function(add)
assert isinstance(fadd, tvm_ffi.Function)
assert fadd(1, 2) == 3

# Also works with an existing Function (copies handle with incref)
fadd2 = tvm_ffi.Function(fadd)
assert fadd2(3, 4) == 7
```
