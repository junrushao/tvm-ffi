# Fix Cython c_handle to handle ctypes.c_void_p(0) returning None
## TL;DR
- `ctypes.c_void_p(0).value` returns `None` (not `0`) in CPython, causing `c_handle()` in Cython to crash when receiving a nullptr.
- The fix checks for `None` and substitutes `0` before casting to `unsigned long long`.
- Adds a regression test for `ctypes.c_void_p(0)` round-trip through `fecho`.

## Key Exports
None (internal Cython helper `c_handle` is not public API)

## Impact
- API: none
- Behavioral: `ctypes.c_void_p(0)` can now be passed through the FFI without error; previously raised a TypeError or produced undefined behavior in Cython
- Flags/config: none
- Data formats/schemas: none

Design elements this commit consumes:

Design elements this commit produces: none

## Usage Examples
Before (broken):
```python
# ctypes.c_void_p(0).value is None, not 0
fecho(ctypes.c_void_p(0))  # TypeError or crash in Cython c_handle
```

After (fixed):
```python
result = fecho(ctypes.c_void_p(0))  # works, returns None (nullptr)
```
