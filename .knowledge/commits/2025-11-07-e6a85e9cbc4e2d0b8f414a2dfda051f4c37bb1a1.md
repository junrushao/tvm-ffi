# Fix ctypes.c_void_p nullptr handling in Cython c_handle()
## TL;DR
- Fixed a corner case where `ctypes.c_void_p(0).value` returns `None` instead of `0` in CPython, causing `c_handle()` in `base.pxi` to crash when converting a nullptr handle.
- Added a `None`-check that maps `None` to `0` before casting to `unsigned long long`.
- Added a regression test for the nullptr round-trip via `fecho(ctypes.c_void_p(0))`.

## Key Exports

```python
# In python/tvm_ffi/cython/base.pxi (Cython, shown as pseudocode):
def c_handle(handle: ctypes.c_void_p) -> void_ptr:
    """Cast ctypes handle to C void*."""
    # Invariant: handle.value may be None when wrapping nullptr (CPython ctypes quirk)
    # Old: v_ptr = handle.value  # crashes when value is None
    # New: guards against None
    value = handle.value
    v_ptr = 0 if value is None else value
    return cast_to_void_ptr(v_ptr)
    # Interacts with: ctypes_handle() (inverse direction), make_args() arg packing
```

## Impact
- API: none
- Behavioral: `ctypes.c_void_p(0)` can now be passed through FFI calls without crashing; previously raised a TypeError in the Cython layer
- Flags/config: none

## Usage Examples
Before (broken):
```python
import ctypes, tvm_ffi

fecho = tvm_ffi.get_global_func("testing.echo")
# Passing nullptr caused TypeError: int expected, got NoneType
result = fecho(ctypes.c_void_p(0))  # CRASH
```

After (fixed):
```python
import ctypes, tvm_ffi

fecho = tvm_ffi.get_global_func("testing.echo")
# nullptr now correctly round-trips through the FFI
result = fecho(ctypes.c_void_p(0))
# result is None (nullptr returned from C side)
```
