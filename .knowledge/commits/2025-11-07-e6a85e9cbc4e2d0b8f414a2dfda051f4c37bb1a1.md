# Fix ctypes.c_void_p returning None for nullptr (value=0) in Cython base.pxi

## TL;DR
- `ctypes.c_void_p(0).value` returns `None` in Python (not `0`), so null pointer checks using `.value` would fail silently. Fix adds an explicit `None` check in `python/tvm_ffi/cython/base.pxi`.
- Adds 4 test lines to `tests/python/test_function.py` covering the nullptr case.

## Key Exports

```python
# C pseudocode (Cython base.pxi fix)
def _convert_ctypes_handle(ptr: ctypes.c_void_p) -> int:
    """Convert ctypes.c_void_p to integer pointer value.
    # Before: if ptr.value == 0: was silently wrong — ptr.value is None for null
    # After: if ptr.value is None or ptr.value == 0: correctly handles null
    # Invariant: ctypes.c_void_p(0).value is None (Python ctypes quirk)
    """
    return 0 if (ptr.value is None) else ptr.value
```

## Impact
- API: none
- Behavioral: Fixes subtle bug where passing `ctypes.c_void_p(0)` (a nullptr) could be mishandled in function dispatch.
