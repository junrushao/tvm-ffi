# Add TypeSchema.repr(ty_map) for customizable type name rendering in schema output
## TL;DR
- Introduces `TypeSchema.repr(ty_map)` method that accepts an optional callable to override type origin names during rendering (e.g., map `list` to `Sequence`, `dict` to `Mapping`).
- Makes `TypeSchema` no longer frozen and normalizes bare `list`/`dict` schemas to include default `Any` type arguments.
- Enriches `core.pyi` with comprehensive Google-style docstrings for all major classes and functions.

## Impact
- API: New `TypeSchema.repr(ty_map)` method. `TypeSchema` is no longer a frozen dataclass, allowing `__post_init__` mutation for default arg normalization.
- Behavioral: Bare `list` schemas now render as `list[Any]` instead of `list`; bare `dict` schemas render as `dict[Any, Any]` instead of `dict`. `__repr__` output is unchanged for schemas that already had type arguments.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

Using `TypeSchema.repr(ty_map)` to customize type names for schema generation:

```python
from tvm_ffi.core import TypeSchema

# Standard rendering
s = TypeSchema.from_json_str('{"type":"dict","args":[{"type":"str"},{"type":"int"}]}')
assert s.repr() == "dict[str, int]"

# Custom mapping: list -> Sequence, dict -> Mapping
def _map(ty: str) -> str:
    return {"list": "Sequence", "dict": "Mapping"}.get(ty, ty)

assert s.repr(_map) == "Mapping[str, int]"

# Bare containers get default Any args
bare_list = TypeSchema("list")
assert bare_list.repr() == "list[Any]"
assert bare_list.repr(_map) == "Sequence[Any]"
```
