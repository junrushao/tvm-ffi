# Add TypeSchema.repr(ty_map) for flexible type-name rendering and enrich core.pyi docstrings
## TL;DR
- Adds `TypeSchema.repr(ty_map)` method that accepts an optional callable to remap type origin names (e.g. `list` -> `Sequence`, `dict` -> `Mapping`) before rendering the schema string.
- Makes `TypeSchema` a mutable dataclass (drops `frozen=True`) so that `__post_init__` can normalize bare `list`/`dict` origins to carry `Any` type arguments.
- Adds comprehensive docstrings and examples to nearly every class and method in `python/tvm_ffi/core.pyi`.

## Key Exports

**Methods**:
- `TypeSchema.repr(ty_map: Callable[[str], str] | None = None) -> str` -- Render a human-readable type representation, optionally remapping origin names through `ty_map`. This is the new public API introduced by this commit.

**Behavioral changes to existing types**:
- `TypeSchema.__repr__` now delegates to `self.repr(ty_map=None)` instead of inline logic.
- `TypeSchema.__post_init__` normalizes bare `list()` -> `list(Any)` and bare `dict()` -> `dict(Any, Any)`.

**Testing functions** (C++):
- `testing.schema_id_arr` -- identity function accepting unparameterized `ArrayObj*`.
- `testing.schema_id_map` -- identity function accepting unparameterized `MapObj*`.

## Impact
- API: New method `TypeSchema.repr(ty_map)` is additive. Existing `repr()` / `str()` behavior unchanged.
- ABI: None. No C ABI or struct changes.
- Behavioral: `TypeSchema` for bare `list`/`dict` (no type args) now normalizes to carry `Any` args in `__post_init__`. `TypeSchema` is no longer frozen (was `frozen=True`, now mutable dataclass), but this is an internal detail; the class was not hashable before due to mutable-looking fields.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- Reflection metadata system: `TypeSchema` is the Python-side representation of C++ `type_schema` JSON emitted by the reflection infrastructure (`.knowledge/designs/reflection.md`).
- Python bindings layer: `core.pyi` stub file and `type_info.pxi` Cython include (`.knowledge/designs/0014-python-bindings.md`).

Design elements this commit produces:
- `TypeSchema.repr(ty_map)` pattern for pluggable type-name rendering, enabling downstream schema generators to customize output (e.g. `list` -> `Sequence`).
- Normalization invariant: bare container schemas (`list`, `dict` with no args) are always expanded to carry `Any` type arguments.

## Usage Examples

Rendering a type schema with custom name mapping:
```python
from tvm_ffi.core import TypeSchema

# Parse a schema from JSON (as emitted by C++ reflection)
schema = TypeSchema.from_json_str('{"type":"dict","args":[{"type":"str"},{"type":"int"}]}')
assert schema.repr() == "dict[str, int]"

# Override list/dict names for stdlib typing collections
def to_abstract(ty: str) -> str:
    return {"list": "Sequence", "dict": "Mapping"}.get(ty, ty)

assert schema.repr(to_abstract) == "Mapping[str, int]"

# Bare container schemas are normalized to carry Any args
bare = TypeSchema.from_json_str('{"type":"list"}')
assert bare.repr() == "list[Any]"
assert bare.repr(to_abstract) == "Sequence[Any]"
```
