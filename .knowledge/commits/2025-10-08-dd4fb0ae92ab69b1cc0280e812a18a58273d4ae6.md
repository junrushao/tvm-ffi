# Add TypeSchema.repr(ty_map) for customizable type name rendering
## TL;DR
- Adds `TypeSchema.repr(ty_map)` method that accepts an optional callable to override type name rendering (e.g., `list` -> `Sequence`, `dict` -> `Mapping`), enabling downstream schema generation with custom type vocabularies.
- Changes `TypeSchema` from `frozen=True` to mutable so that `__post_init__` can normalize bare `list`/`dict` args to `list[Any]`/`dict[Any, Any]`.
- Adds C++ test functions `testing.schema_id_arr` and `testing.schema_id_map` for unparameterized `ArrayObj*`/`MapObj*` schemas, and Python tests exercising the `repr(ty_map)` path.
- Bundles enriched docstrings for `Object`, `Function`, and other stubs in `core.pyi` (documentation only, no functional change).

## Impact
- API: New public method `TypeSchema.repr(ty_map)`. Non-breaking addition.
- API: `TypeSchema` is no longer frozen (`frozen=True` removed). Code that relied on hashability of TypeSchema instances will break, though this is unlikely since TypeSchema contains mutable tuples of sub-schemas. Code that assigned to `.args` in `__post_init__` was previously impossible; now it works.
- Behavioral: Bare `list` (no type args) now normalizes to `list[Any]` in repr; bare `dict` normalizes to `dict[Any, Any]`. Previously these would have rendered as `list` and `dict` without args.
- Flags/config: none
- Data formats/schemas: The underlying JSON schema format is unchanged. The normalization happens at the Python `TypeSchema` level only.

## Design Elements
Design elements this commit consumes:
- **TypeSchema** (introduced in `28fe3cc`): The frozen dataclass for parsing JSON type schemas into structured Python objects. This commit extends it.
- **Reflection system** ([0008-reflection.md](../designs/0008-reflection.md)): `GlobalDef.def_()` used to register new test functions `testing.schema_id_arr` and `testing.schema_id_map`.
- **C++ type traits** ([0006-type-traits.md](../designs/0006-type-traits.md)): `TypeTraits<const ArrayObj*>` and `TypeTraits<const MapObj*>` produce schemas without type args when the container element type is erased.

Design elements this commit produces:
- **`TypeSchema.repr(ty_map)`**: A new rendering method that enables downstream code to customize type name output. This is a minor extension to the existing TypeSchema design element, not a new design element per se.
- **Bare container normalization**: `list()` -> `list(Any)`, `dict()` -> `dict(Any, Any)` in `__post_init__`. This tightens the invariant that `args` is always populated for list/dict schemas.

## Usage Examples
**Custom type name rendering (from test):**
```python
from tvm_ffi.core import TypeSchema

def _replace_list_dict(ty: str) -> str:
    return {"list": "Sequence", "dict": "Mapping"}.get(ty, ty)

schema = TypeSchema.from_json_str(metadata["type_schema"])
# Default: "Callable[[list[int]], list[int]]"
print(schema)
# Custom: "Callable[[Sequence[int]], Sequence[int]]"
print(schema.repr(_replace_list_dict))
```

**Unparameterized container schemas (C++ -> Python):**
```python
# C++ registers: testing.schema_id_arr taking const ArrayObj*
# JSON schema: {"type":"ffi.Function","args":[{"type":"ffi.Array"},{"type":"ffi.Array"}]}
# Python TypeSchema normalizes to: Callable[[list[Any]], list[Any]]
metadata = get_global_func_metadata("testing.schema_id_arr")
schema = TypeSchema.from_json_str(metadata["type_schema"])
assert str(schema) == "Callable[[list[Any]], list[Any]]"
```
