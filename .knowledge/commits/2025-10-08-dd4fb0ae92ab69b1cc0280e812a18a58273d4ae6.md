# Add TypeSchema.repr(ty_map) for customizable type name rendering
## TL;DR
- Adds `TypeSchema.repr(ty_map)` method that accepts an optional callable to override how type origin names are rendered (e.g., `list` -> `Sequence`, `dict` -> `Mapping`).
- Removes `frozen=True` from `TypeSchema` dataclass to allow `__post_init__` to normalize bare `list`/`dict` schemas by defaulting their args to `(TypeSchema("Any"),)` / `(TypeSchema("Any"), TypeSchema("Any"))`.
- Regenerates `core.pyi` with expanded docstrings for `Object`, `Error`, and related stub classes (stub enrichment, not API change).

## Key Exports

**Methods**:
- `TypeSchema.repr(ty_map: Callable[[str], str] | None = None) -> str` -- renders the type schema to a string, applying `ty_map` to each origin name if provided. Delegates to `self.args[i].repr(ty_map)` recursively.

**Behavioral changes to existing APIs**:
- `TypeSchema.__repr__()` now delegates to `self.repr(ty_map=None)` (same output, refactored implementation).
- `TypeSchema.__post_init__()` now normalizes bare `list` (no args) to `list[Any]` and bare `dict` (no args) to `dict[Any, Any]` by mutating `self.args`. This requires the class to be mutable (`frozen=True` removed).

**Test functions (C++ testing helpers)**:
- `testing.schema_id_arr` -- identity function taking `const ArrayObj*` (no element type parameter), producing a schema with bare `ffi.Array`.
- `testing.schema_id_map` -- identity function taking `const MapObj*` (no key/value type parameters), producing a schema with bare `ffi.Map`.

## Impact
- API: New public method `TypeSchema.repr(ty_map)`. Non-breaking addition. Downstream schema generators can now customize type name rendering without string replacement.
- Behavioral: `TypeSchema` for bare `list` / `dict` types (no type args in JSON schema) now always carry `args=(TypeSchema("Any"),)` / `args=(TypeSchema("Any"), TypeSchema("Any"))` after construction. `repr()` output for these types changes from `list` to `list[Any]` and `dict` to `dict[Any, Any]`.
- Flags/config: none
- Data formats/schemas: The JSON wire format for type schemas is unchanged. The normalization happens purely in the Python `TypeSchema` constructor.

## Design Elements
Design elements this commit consumes:
- `TypeSchema` dataclass in `python/tvm_ffi/cython/type_info.pxi` -- the Python-side parser and renderer for type schema JSON. See prior commit [2025-10-07-c046b17](../commits/2025-10-07-c046b17108484780b8b13142e1c1a46e263ec979.md).
- `_TYPE_SCHEMA_ORIGIN_CONVERTER` dict in `type_info.pxi` -- maps C++ type names to Python display names.
- `refl::GlobalDef` builder in C++ for registering test functions (`testing.schema_id_arr`, `testing.schema_id_map`).
- C++ `ArrayObj*` and `MapObj*` raw pointer parameters in function schema -- the type trait system encodes these as bare `ffi.Array` / `ffi.Map` without element type args.

Design elements this commit produces:
- `TypeSchema.repr(ty_map)` method -- a new extension point for customizable type rendering.
- Normalization invariant: `TypeSchema` for `list` always has `len(args) == 1` and `dict` always has `len(args) == 2` after construction.

## Usage Examples
**Custom type name rendering with `repr(ty_map)`** (from `tests/python/test_metadata.py`):
```python
from tvm_ffi.core import TypeSchema

def _replace_list_dict(ty: str) -> str:
    return {"list": "Sequence", "dict": "Mapping"}.get(ty, ty)

schema = TypeSchema.from_json_str(metadata["type_schema"])
# Default rendering
assert str(schema) == "Callable[[list[int]], list[int]]"
# Custom rendering: list -> Sequence
assert schema.repr(_replace_list_dict) == "Callable[[Sequence[int]], Sequence[int]]"
```

**Bare container normalization** (from test expectations):
```python
# C++ function taking const ArrayObj* (no element type) normalizes to list[Any]
schema = TypeSchema.from_json_str('{"type":"ffi.Array"}')
assert str(schema) == "list[Any]"

# C++ function taking const MapObj* (no key/value types) normalizes to dict[Any, Any]
schema = TypeSchema.from_json_str('{"type":"ffi.Map"}')
assert str(schema) == "dict[Any, Any]"
```
