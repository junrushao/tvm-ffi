# Formalize ffi.Module as extra-tier API with library loading infrastructure
## TL;DR
- Introduces `ModuleObj` / `Module` as a first-class object in the FFI extra tier (`include/tvm/ffi/extra/module.h`), with a static type index `kTVMFFIModule = 73` and type key `"ffi.Module"`. `ModuleObj` is an abstract base with virtual methods (`kind`, `GetFunction`, `GetPropertyMask`, `WriteToFile`, `SaveToBytes`, `InspectSource`, `ImportModule`, `ClearImports`).
- Adds the full library-module loading stack: `LibraryModuleObj` wraps a `Library` (abstract symbol-lookup interface) into a `Module`; `DSOLibrary` loads `.so`/`.dll` via `dlopen`/`LoadLibrary`; `SystemLibrary` resolves symbols from a global `SystemLibSymbolRegistry`; `ProcessLibraryBin` deserializes an embedded import tree of sub-modules.
- Fixes two bugs in `object.h` macros: `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS` and `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` had trailing semicolons on the final `using ContainerType` line (preventing use after the macro without warnings), and the latter incorrectly referenced `TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` (missing `FFI` prefix).
## Impact
- API: New public header `include/tvm/ffi/extra/module.h` defining `ModuleObj`/`Module`. New C API header `include/tvm/ffi/extra/c_env_api.h` with `TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`. New global functions registered: `ffi.ModuleLoadFromFile`, `ffi.ModuleImplementsFunction`, `ffi.ModuleGetFunction`, `ffi.ModuleGetPropertyMask`, `ffi.ModuleInspectSource`, `ffi.ModuleGetKind`, `ffi.ModuleGetWriteFormats`, `ffi.ModuleWriteToFile`, `ffi.ModuleImportModule`, `ffi.ModuleClearImports`, `ffi.SystemLib`, `ffi.Module.load_from_file.so`.
- Flags/config: Four new `.cc` files gated behind `TVM_FFI_USE_EXTRA_CXX_API` in CMakeLists.txt.
- Data formats/schemas: `StaticTypeKey::kTVMFFIModule` added to `object.h`. `StaticTypeKey::kTVMFFISmallStr`/`kTVMFFISmallBytes` reordered (before `kTVMFFIBytes`/`kTVMFFIStr`).
## Design Elements
Design elements this commit consumes:
- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `ModuleObj` inherits `Object`, uses `TVM_FFI_DECLARE_STATIC_OBJECT_INFO`, `make_object<T>`, `ObjectPtr<T>`, `GetRef<Module>`. Reserves static type index `kTVMFFIModule = 73` via `ReserveDepthOneObjectTypeIndex` in `TypeTable`.
- **Extra API tier** ([`.knowledge/designs/0011-extra-api-tier.md`](../designs/0011-extra-api-tier.md)): `ModuleObj` uses `TVM_FFI_EXTRA_CXX_API` visibility. All implementation files placed in `src/ffi/extra/` and gated by `TVM_FFI_USE_EXTRA_CXX_API`.
- **Function system** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): `GetFunction` returns `Optional<Function>`. `LibraryModuleObj::GetFunction` wraps `TVMFFISafeCallType` function pointers into `ffi::Function::FromPacked`. Global function registration via `reflection::GlobalDef().def(...)`.
- **C ABI** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Three new `extern "C"` functions (`TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`) follow the `TVM_FFI_SAFE_CALL_BEGIN/END` pattern. `TVMFFISafeCallType` used for library symbol dispatch.
- **Reflection system** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `ObjectDef<ModuleObj>().def_ro("imports_", &ModuleObj::imports_)` registers the imports field for reflection. `GlobalDef` used for all global function registrations.
- **Module export system** ([`.knowledge/designs/0008-module-export-system.md`](../designs/0008-module-export-system.md)): `LibraryModuleObj::GetFunction` discovers `TVMFFISafeCallType` symbols from loaded libraries, the same symbol pattern that `TVM_FFI_DLL_EXPORT_TYPED_FUNC` generates.
- **Safe-call ABI boundary** ([`.knowledge/ADRs/0005-safe-call-abi-boundary.md`](../ADRs/0005-safe-call-abi-boundary.md)): `TVMFFIEnvLookupFromImports` and `TVMFFIEnvRegisterContextSymbol` use `TVM_FFI_SAFE_CALL_BEGIN/END`.
- **Containers** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): `Array<Any>` for `imports_`, `Map<String, Function>` for `import_lookup_cache_`, `Map<String, void*>` for `SystemLibSymbolRegistry`.

Design elements this commit produces:
- **`ModuleObj` / `Module`** (new): Abstract base class for dynamically loadable modules. Virtual interface: `kind()`, `GetFunction(name)`, `GetPropertyMask()`, `WriteToFile()`, `SaveToBytes()`, `InspectSource()`, `ImportModule()`, `ClearImports()`, `GetWriteFormats()`, `ImplementsFunction()`. Has two overloads for `GetFunction`/`ImplementsFunction` that recursively query imports. Property mask bitmask: `kBinarySerializable`, `kRunnable`, `kCompilationExportable`.
- **`Library`** (new, internal): Abstract base class in `module_internal.h` for symbol lookup (`GetSymbol(const char*) -> void*`). Deliberately has no type index or type key (only used for refcounting).
- **`LibraryModuleObj`** (new, internal): Concrete `ModuleObj` that wraps a `Library`. `GetFunction` looks up `TVMFFISafeCallType` symbols from the library and wraps them in `Function::FromPacked` with a captured `Module` strong reference for lifetime.
- **`DSOLibrary`** (new, internal): `Library` subclass using `dlopen`/`LoadLibrary` for dynamic shared library loading. Registered as `ffi.Module.load_from_file.so`.
- **`SystemLibrary`** (new, internal): `Library` subclass resolving symbols from `SystemLibSymbolRegistry`. Supports symbol prefix for namespace isolation. Cached in `SystemLibModuleRegistry`.
- **`ProcessLibraryBin`** (new, internal): Deserializes an embedded binary blob (`__tvm_ffi_library_bin`) into an import tree of modules. CSR-encoded import tree format: `<nbytes:u64><import_tree_indptr:vec<u64>><child_indices:vec<u64>><key:str><bytes:bytes>...`. Special `"_lib"` key denotes the `LibraryModuleObj` position in the tree.
- **`ContextSymbolRegistry`** (new, internal): Singleton that stores `(name, void*)` pairs. On library load, initializes matching symbols in the library. Accessible via `Module::VisitContextSymbols`.
- **C environment API** (`include/tvm/ffi/extra/c_env_api.h`, new): `TVMFFIEnvLookupFromImports` for generated code to resolve imported functions. `TVMFFIEnvRegisterContextSymbol`/`TVMFFIEnvRegisterSystemLibSymbol` for library-level symbol registration.
- **Bugfix in mutable object ref macros** (`object.h`): Removes trailing semicolons from `using ContainerType = ObjectName;` lines in `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS` and `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS`, and fixes `TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` -> `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN`.
- **`symbol::tvm_ffi_library_ctx`**, **`symbol::tvm_ffi_library_bin`**, **`symbol::tvm_ffi_main`**: Well-known symbol names for library module conventions.
## Reflection
### Design docs to write
- **`.knowledge/designs/0013-module-system.md`**: Should cover the `ModuleObj`/`Module` class hierarchy, the `Library` abstraction, `LibraryModuleObj`, `DSOLibrary`, `SystemLibrary`, `ProcessLibraryBin` binary format, `ContextSymbolRegistry`, `SystemLibSymbolRegistry`, the import tree structure, and the `ModulePropertyMask` bitmask. Also document the global function naming convention `ffi.Module.load_from_file.<format>` and `ffi.Module.load_from_bytes.<kind>` for extensible loader registration. This doc would be referenced by any commit touching module loading, serialization, or import resolution.

### ADRs to write
- **`.knowledge/ADRs/0018-module-in-extra-tier.md`**: Decision to place `Module` in the extra API tier rather than core. Context: Module was historically in `runtime::Module` in main TVM. Alternatives: (1) make it core -- increases minimal library size for consumers that only need packed functions, (2) make it a separate CMake target -- more build complexity. Trade-off: keeping it in `extra/` keeps the core FFI minimal while allowing library loading for consumers who opt in.
- **`.knowledge/ADRs/0019-library-binary-format.md`**: Decision to use a custom CSR-encoded binary blob for embedding module import trees in shared libraries. Context: the format packs a DAG of heterogeneous modules (each identified by `kind` string) into a single contiguous byte buffer. Alternatives: (1) JSON-based format -- human-readable but slower to parse and larger, (2) FlatBuffers/protobuf -- external dependency. Trade-off: the custom format is minimal, zero-dependency, and endian-aware via `BufferInStream`.

### Design diagrams to draw
- **Module loading pipeline** (Mermaid): Should depict `Module::LoadFromFile` -> format dispatch -> `ffi.Module.load_from_file.<format>` global function -> `DSOLibrary` (dlopen) -> `CreateLibraryModule` -> `ProcessLibraryBin` (if `__tvm_ffi_library_bin` exists) -> import tree reconstruction. Also show `SystemLibrary` path via `ffi.SystemLib`.
- **Module class hierarchy** (Mermaid class diagram): `Object` -> `ModuleObj` (abstract, extra tier) with `Library` (internal, no type index). `LibraryModuleObj` -> `ModuleObj`. `DSOLibrary` -> `Library`. `SystemLibrary` -> `Library`.
