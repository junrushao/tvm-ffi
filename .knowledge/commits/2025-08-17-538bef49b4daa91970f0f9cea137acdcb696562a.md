# Formalize ffi.Module as extra API for dynamic module loading and library interop
## TL;DR
- Introduces `ModuleObj`/`Module` as a first-class FFI object type (`kTVMFFIModule = 73`) under `include/tvm/ffi/extra/module.h`, providing abstract virtual methods for `GetFunction`, `kind`, serialization, and import management.
- Adds three concrete module backends: `LibraryModuleObj` (wraps a `Library` abstraction), `DSOLibrary` (platform-specific `dlopen`/`LoadLibrary`), and `SystemLibrary` (in-process symbol table), plus a binary deserialization format for embedded module import trees.
- Adds C env API (`c_env_api.h`) with `TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, and `TVMFFIEnvRegisterSystemLibSymbol` for generated code to call back into the module system.

class TVM_FFI_EXTRA_CXX_API ModuleObj : public Object {
public:

  virtual Bytes SaveToBytes() const;

  virtual void ClearImports();
  Optional<Function> GetFunction(const String& name, bool query_imports);
  bool ImplementsFunction(const String& name, bool query_imports);
  const Array<Any>& imports() const;

  static constexpr int32_t _type_index = kTVMFFIModule;         // 73
  static constexpr const char* _type_key = "ffi.Module";

## Impact
- API: Adds a new static object type `ffi.Module` at index 73. Callers using the `StaticTypeKey` enum will see `kTVMFFISmallStr`/`kTVMFFISmallBytes` reordered (moved earlier, cosmetic). The `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` macro fix corrects a broken reference to the non-FFI-prefixed macro name.
- Behavioral: No changes to existing functions. New module loading capabilities are purely additive.
- Flags/config: Module source files are gated by `TVM_FFI_USE_EXTRA_CXX_API` (CMake, default ON), consistent with other extra APIs.
- Data formats/schemas: Introduces a binary format for embedded library modules: `<nbytes:u64> <import_tree_CSR> (<kind:str> <bytes:bytes>)*`.

Design elements this commit produces:
- **Module system**: `ModuleObj`/`Module` abstract class hierarchy for dynamic function loading with import tree, property masks, serialization, and source inspection. Includes `Library` as internal symbol-provider abstraction.
- **C env API for modules**: Three new C ABI functions (`TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`) for generated code and system library registration.
- **Library module infrastructure**: `LibraryModuleObj` wrapping `Library`, `DSOLibrary` for platform dynamic loading, `SystemLibrary`/`SystemLibSymbolRegistry` for statically-linked symbol tables, `ContextSymbolRegistry` for lazy symbol binding.
- **Module binary format**: CSR-based import tree serialization with per-module kind/bytes pairs.
- **Module symbol convention**: Well-known symbol names (`__tvm_ffi_library_ctx`, `__tvm_ffi_library_bin`, `__tvm_ffi_main__`) for library modules.
- **Module property mask enum**: `kBinarySerializable`, `kRunnable`, `kCompilationExportable` bit flags.

## Usage Examples

**Loading a shared library as a Module and calling a function** (C++):
```cpp
// Load a .so file; format is auto-detected from extension
Module mod = Module::LoadFromFile("my_kernels.so");

// Look up a function exported by the library
Optional<Function> func = mod->GetFunction("my_kernel");
if (func.defined()) {
  Any result = (*func)(input_tensor);
}

// Import another module (with cyclic dependency guard)
Module helper = Module::LoadFromFile("helper.so");
mod->ImportModule(helper);

// Query from imports recursively
auto f = mod->GetFunction("helper_func", /*query_imports=*/true);
```

**Registering and using system library symbols** (C, for generated code):
```c
// At load time, compiled kernels register their symbols:
TVMFFIEnvRegisterSystemLibSymbol("__tvm_ffi_my_kernel", (void*)&my_kernel_impl);

// At runtime, look up via SystemLib:
// C++: Module sys = Function::GetGlobalRequired("ffi.SystemLib")().cast<Module>();
// Python: sys = tvm_ffi.get_global_func("ffi.SystemLib")()

// Generated code uses TVMFFIEnvLookupFromImports to resolve dependencies:
TVMFFIObjectHandle func;
TVMFFIEnvLookupFromImports(library_ctx, "needed_function", &func);
```
