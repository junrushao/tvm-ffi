# Formalize ffi.Module as a first-class Object type with library loading infrastructure
## TL;DR
- Introduces `ModuleObj`/`Module` as a new static Object type (`kTVMFFIModule = 73`) in the `ffi::extra` layer, formalizing the concept of a loadable function container with import/export semantics.
- Adds three concrete Module implementations: `LibraryModuleObj` (wraps a `Library` symbol provider), `DSOLibrary` (dynamic shared object via `dlopen`/`LoadLibraryW`), and `SystemLibrary` (static symbol table for embedded/AOT scenarios).
- Registers C ABI entry points (`TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`) and global functions (`ffi.ModuleLoadFromFile`, `ffi.ModuleGetFunction`, etc.) for cross-language module interaction.
- Fixes trailing semicolons in `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS` and `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` macros, and corrects `TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` to `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` in the latter.

## Impact
- API: New public header `include/tvm/ffi/extra/module.h` and C ABI header `include/tvm/ffi/extra/c_env_api.h`. Adds `StaticTypeKey::kTVMFFIModule` to `object.h`. Reorders `kTVMFFISmallStr`/`kTVMFFISmallBytes` (moved earlier in `StaticTypeKey`; no ABI break since these are compile-time constants, not enum values).
- Behavioral: Fixes `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` which previously used `TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` (wrong prefix, likely linking to a legacy macro or missing entirely). Also removes trailing semicolons from both mutable ref macros, preventing potential issues with macros used in certain contexts.
- Flags/config: Requires `TVM_FFI_USE_EXTRA_CXX_API=ON` in CMake to compile the module sources.
- Data formats/schemas: Defines a binary format for embedded library modules: `<nbytes:u64> <import_tree_CSR> <kind:str> <bytes:bytes> ...` read by `ProcessLibraryBin`.

## Design Elements
Design elements this commit consumes:
- **Object system** (`.knowledge/designs/0002-object-system.md`): `ModuleObj` extends `Object`, `Module` extends `ObjectRef`, uses `TVM_FFI_DECLARE_STATIC_OBJECT_INFO` for fixed type index, `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` for mutable non-nullable handle.
- **C ABI** (`.knowledge/designs/0001-c-abi.md`): Adds `kTVMFFIModule = 73` to the static object type index range `[64, 74)`. Uses `TVM_FFI_SAFE_CALL_BEGIN`/`TVM_FFI_SAFE_CALL_END` for C ABI boundary functions. Uses `TVM_FFI_DLL` for C API exports.
- **Function system** (`.knowledge/designs/0004-function-system.md`): Registers global functions via `reflection::GlobalDef().def()`/`.def_method()`. Uses `Function::GetGlobal` for dynamic loader dispatch. Uses `Function::FromPacked` to wrap `TVMFFISafeCallType` function pointers from loaded libraries.
- **Reflection system** (`.knowledge/designs/0008-reflection.md`): Registers `ModuleObj` fields via `ObjectDef<ModuleObj>().def_ro("imports_", ...)`.
- **Containers** (`.knowledge/designs/0007-containers.md`): Uses `Array<Any>` for imports, `Map<String, Function>` for lookup cache, `Map<String, void*>` for system symbol table.

Design elements this commit produces:
- **Module system**: A new design element -- `ModuleObj`/`Module` as the formalized abstraction for loadable function containers with import graph semantics. This is a first-class Object type in the static type index space.
- **Library abstraction**: Internal `Library` base class as the abstract symbol provider interface.
- **Library loading pipeline**: `LoadFromFile` -> format dispatch -> `CreateLibraryModule` -> `ProcessLibraryBin` (for embedded binaries) or direct `LibraryModuleObj` wrapping.
- **Context symbol injection**: `ContextSymbolRegistry` pattern for injecting host-side symbols into loaded libraries without explicit link dependency.
- **System library pattern**: `SystemLibrary` + `SystemLibSymbolRegistry` for AOT/embedded scenarios where symbols are registered at static init time rather than loaded from a DSO.

## Usage Examples

Loading a shared library and calling a function from it (C++ -> cross-language):

```cpp
// C++ side: load a compiled module and call its function
Module mod = Module::LoadFromFile("my_model.so");
// Get a function from the module
Optional<Function> func = mod->GetFunction("forward");
if (func.defined()) {
    Any result;
    (*func)(input_tensor, &result);
}

// Import another module into the root module
Module aux_mod = Module::LoadFromFile("aux_kernels.so");
mod->ImportModule(aux_mod);
// Now functions in aux_kernels are available via query_imports=true
Optional<Function> aux_func = mod->GetFunction("helper_op", /*query_imports=*/true);
```

From generated code, looking up a function from the import tree (C ABI):

```c
// Generated code uses the C ABI to resolve functions from the module's import tree
TVMFFIObjectHandle func = NULL;
int ret = TVMFFIEnvLookupFromImports(library_ctx, "my.imported.func", &func);
// func is a weak reference cached by the module
```
