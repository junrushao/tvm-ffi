# Formalize ffi.Module as the dynamic module abstraction with library loading and serialization

## TL;DR
- Introduces `ffi::Module` / `ffi::ModuleObj` as a first-class abstract object type in the FFI layer for dynamically loading shared libraries and retrieving `ffi::Function` instances by name.
- Provides three concrete module implementations: `LibraryModuleObj` (wraps a `Library` abstraction), `DSOLibrary` (loads `.so`/`.dll`/`.dylib` via `dlopen`/`LoadLibraryW`), and `SystemLibrary` (looks up statically registered symbols).
- Adds C environment APIs (`TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`) for generated code to interact with imported modules and context symbols.
- Adds `kTVMFFIModule` to `StaticTypeKey`, relocates `kTVMFFISmallStr`/`kTVMFFISmallBytes` in the key listing, and fixes trailing-semicolon issues in `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS` and `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` macros (plus fixes a typo referencing `TVM_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` instead of `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN`).
- Includes `BufferInStream`, a lightweight internal stream helper for deserializing binary-embedded module data.

class ModuleObj : public Object {
 public:
  virtual const char* kind() const = 0;
  virtual int GetPropertyMask() const;                     // default: 0b000

  virtual Bytes SaveToBytes() const;
  virtual String InspectSource(const String& format = "") const;
  virtual void ImportModule(const Module& other);          // cyclic-dep check
  virtual void ClearImports();

  // Overloads that optionally query imported modules
  Optional<Function> GetFunction(const String& name, bool query_imports);
  bool ImplementsFunction(const String& name, bool query_imports);

  const Array<Any>& imports() const;

  static constexpr int32_t _type_index = TypeIndex::kTVMFFIModule;
  static constexpr const char* _type_key = StaticTypeKey::kTVMFFIModule; // "ffi.Module"
  TVM_FFI_DECLARE_STATIC_OBJECT_INFO(ModuleObj, Object);

  Array<Any> imports_;

## Impact
- API: Adds the entire Module subsystem as a new public API surface under `tvm::ffi`. This is the first formal module abstraction in the FFI layer (previously existed in `tvm::runtime`).
- ABI: Adds `kTVMFFIModule` as a static type key (`"ffi.Module"`). The `kTVMFFISmallStr` and `kTVMFFISmallBytes` entries are relocated (reordered) in the `StaticTypeKey` struct. Three new C API symbols exported: `TVMFFIEnvLookupFromImports`, `TVMFFIEnvRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol`.
- Behavioral: `Module::LoadFromFile` resolves file extension to a loader name (`ffi.Module.load_from_file.<ext>`) and dispatches through the global function registry. `ImportModule` performs DFS cycle detection before adding to the import list. `TVMFFIEnvLookupFromImports` caches resolved functions in a per-module `Map<String, Function>` under a global mutex.
- Build: Four new source files added to the `TVM_FFI_USE_EXTRA_CXX_API` build target: `module.cc`, `library_module.cc`, `library_module_system_lib.cc`, `library_module_dynamic_lib.cc`.

## Design Elements

Design elements this commit consumes:
- **Object system** (`.knowledge/designs/object-system.md`) -- `Object`, `ObjectRef`, `ObjectPtr`, `make_object`, `TVM_FFI_DECLARE_STATIC_OBJECT_INFO`, `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS`, `GetRef<Module>(this)`.
- **Function system** (`.knowledge/designs/function-system.md`) -- `Function`, `Function::FromPacked`, `Function::GetGlobal`, `TypedFunction`, global registry for loader dispatch.
- **Containers** (`.knowledge/designs/containers.md`) -- `Array<Any>` for imports, `Map<String, Function>` for import lookup cache, `Map<String, void*>` for system lib symbol table, `Optional<Function>` for nullable function returns, `String`, `Bytes`.
- **Reflection** (`.knowledge/designs/reflection.md`) -- `reflection::ObjectDef<T>`, `reflection::GlobalDef` with `.def`, `.def_method`, `.def_packed` for registering module-related global functions.
- **C ABI** (`.knowledge/designs/c-abi.md`) -- `TVM_FFI_SAFE_CALL_BEGIN`/`END` for C API wrappers, `TVMFFISafeCallType` for function call convention in `LibraryModuleObj::GetFunction`, `TVM_FFI_CHECK_SAFE_CALL`.
- **Type index system** (`.knowledge/ADRs/003-type-index-ranges.md`) -- `TypeIndex::kTVMFFIModule` in the static object range `[64, 128)`.

Design elements this commit produces:
- **Module abstraction** -- A new abstract base class `ModuleObj` with virtual methods for function lookup, serialization, source inspection, and import management. The `Module` ref wrapper adds `LoadFromFile` (extension-based loader dispatch) and property bitmask (`kBinarySerializable | kRunnable | kCompilationExportable`). This is the first formal module concept in the FFI layer.
- **Library abstraction** -- An internal `Library` base class (in `module_internal.h`) providing `GetSymbol(const char*) -> void*`, used by `LibraryModuleObj` to wrap both dynamic shared libraries and static symbol tables.
- **Library module binary format** -- The `ProcessLibraryBin` function defines a binary format for embedded module data: `<nbytes:u64> <import_tree_indptr:vec<u64>> <import_tree_child_indices:vec<u64>> (<kind:str> <bytes:bytes>)*`. The import tree is a CSR (Compressed Sparse Row) structure of child indices. The `_lib` sentinel kind indicates where the DSO library module is placed in the tree.
- **Context symbol registry** -- `ContextSymbolRegistry` allows registering name-to-address mappings via `TVMFFIEnvRegisterContextSymbol`. When a library module is loaded, `InitContextSymbols` writes these addresses into matching symbols in the loaded library, enabling runtime initialization without explicit link dependencies.
- **System library module** -- `SystemLibrary` backed by `SystemLibSymbolRegistry` (a global `Map<String, void*>`) allows statically linked code to register symbols via `TVMFFIEnvRegisterSystemLibSymbol`. `SystemLibModuleRegistry` ensures at most one `Module` per symbol prefix.
- **Module import mechanism** -- Modules maintain an `imports_` array and an `import_lookup_cache_` map. `ImportModule` performs DFS cycle detection. `TVMFFIEnvLookupFromImports` provides a C API for generated code to resolve functions from imports (with mutex-protected caching and fallback to global registry).
- **Loader dispatch convention** -- `Module::LoadFromFile` normalizes extensions (`dll`/`dylib`/`dso` to `so`) and dispatches to `ffi.Module.load_from_file.<format>`. Binary deserialization dispatches to `ffi.Module.load_from_bytes.<kind>`. This convention allows new module formats to be registered by simply adding a global function with the right name.

## Usage Examples

### Loading a shared library module
```cpp
Module mod = Module::LoadFromFile("my_model.so");
Optional<Function> f = mod->GetFunction("forward");
if (f.defined()) {
  Any result = (*f)(input_tensor);
}
```

### Importing modules
```cpp
Module host = Module::LoadFromFile("host.so");
Module device = Module::LoadFromFile("device.so");
host->ImportModule(device);

// Now host can resolve functions from device via query_imports=true
auto f = host->GetFunction("device_kernel", /*query_imports=*/true);
```

### Registering a context symbol (from generated code)
```c
// In a compiled kernel library
TVMFFIEnvRegisterContextSymbol("TVMBackendAllocWorkspace", &TVMBackendAllocWorkspace);
// When the library module loads, this address is written into
// the library's __tvm_ffi_library_ctx symbol
```

### System library
```cpp
// Register symbols at link time (e.g., from a static library)
TVMFFIEnvRegisterSystemLibSymbol("my_kernel", &my_kernel_impl);

// Later, retrieve the system library module
Function get_syslib = Function::GetGlobalRequired("ffi.SystemLib");
Module syslib = get_syslib("").cast<Module>();
auto f = syslib->GetFunction("my_kernel");
```

### ADRs to write or update
- `.knowledge/ADRs/011-module-loader-dispatch.md` -- Record the decision to use string-keyed global function dispatch for module loading (`ffi.Module.load_from_file.<ext>` and `ffi.Module.load_from_bytes.<kind>`) rather than a fixed enum or vtable of loaders. Rationale: extensibility -- new module formats can be supported by registering a single global function, with no changes to the Module class itself.
