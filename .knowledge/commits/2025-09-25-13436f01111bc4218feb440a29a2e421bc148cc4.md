# Reorder TVMFFIObject header to put ref counters first, narrow strong_ref_count to u32
## TL;DR
- Reorders the `TVMFFIObject` 24-byte header: `strong_ref_count` (u32) and `weak_ref_count` (u32) are now the first 8 bytes, followed by `type_index` (i32) + `__padding` (u32), then `deleter`. Previously `type_index` was first and `strong_ref_count` was u64.
- Narrows `strong_ref_count` from `uint64_t` to `uint32_t`, enabling future optimization of packing both counters into a single 64-bit atomic (aligned with torch `intrusive_ptr` ABI).
- Breaks the former invariant that `TVMFFIObject` and `TVMFFIAny` share the same `type_index` at offset 0. Removes the `test_c_ffi_abi.cc` test that asserted this.
- Updates all MSVC intrinsics from `_InterlockedIncrement64`/`_InterlockedDecrement64`/`_InterlockedCompareExchange64` to 32-bit equivalents.

## Impact
- API: ABI-breaking change to `TVMFFIObject` field layout. All compiled C/C++ code must be recompiled. The `type_index` field moves from offset 0 to offset 8. `strong_ref_count` narrows from u64 to u32.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **TVMFFIObject header layout** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Modifies the core 24-byte header that all heap objects share.
- **Ref-counting atomic operations** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `IncRef`, `DecRef`, `TryPromoteWeakPtr` all updated to use u32 atomics.

Design elements this commit produces:
- **Packed ref-counter layout**: `strong_ref_count` (u32) at offset 0, `weak_ref_count` (u32) at offset 4. This layout enables a future single-u64 atomic CAS that manipulates both counters simultaneously (torch-style optimization to avoid reading weak count during strong deletion).
- **Broken type_index/Any alignment invariant**: `TVMFFIObject.type_index` is no longer at offset 0, so the previously documented invariant that Object and Any share the type_index at the same offset no longer holds.
