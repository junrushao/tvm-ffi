# Reorder TVMFFIObject fields: refcount-first layout, narrow strong_ref_count to u32
## TL;DR
- Reorders `TVMFFIObject` fields so `strong_ref_count` (u32) and `weak_ref_count` (u32) are packed into the first 8 bytes, followed by `type_index` (i32) + `__padding` (u32), then `deleter` (8 bytes). Total remains 24 bytes.
- Narrows `strong_ref_count` from `uint64_t` to `uint32_t`, enabling future single-u64 atomic CAS optimization combining both counters (technique from torch).
- **Breaking ABI change**: `type_index` is no longer at byte offset 0 in `TVMFFIObject`, removing the shared-offset invariant with `TVMFFIAny`. The ABI test verifying `reinterpret_cast<TVMFFIAny*>(&obj)->type_index` is deleted.

## Key Exports

**Struct `TVMFFIObject`** (24 bytes, new layout):
```c
typedef struct TVMFFIObject {
  uint32_t strong_ref_count;  // offset 0  (was at offset 8, was u64)
  uint32_t weak_ref_count;    // offset 4  (was at offset 4)
  int32_t  type_index;        // offset 8  (was at offset 0)
  uint32_t __padding;         // offset 12 (new, ensures 8-byte alignment)
  union {
    void (*deleter)(struct TVMFFIObject* self, int flags);  // offset 16
    int64_t __ensure_align;
  };
} TVMFFIObject;
```

Previous layout (from commit ca9c3d1):
```c
typedef struct TVMFFIObject {
  int32_t  type_index;        // offset 0
  uint32_t weak_ref_count;    // offset 4
  uint64_t strong_ref_count;  // offset 8
  union { void (*deleter)(...); int64_t __ensure_align; };  // offset 16
} TVMFFIObject;
```

**MSVC atomics in `Object` methods** (signature change from 64-bit to 32-bit intrinsics):
- `use_count()`: `reinterpret_cast<const volatile __int64*>` -> `reinterpret_cast<const volatile long*>`
- `IncRef()`: `_InterlockedIncrement64` -> `_InterlockedIncrement`
- `DecRef()`: `_InterlockedDecrement64` -> `_InterlockedDecrement`
- `TryPromoteWeakPtr()`: `_InterlockedCompareExchange64` -> `_InterlockedCompareExchange`, local variables `uint64_t` -> `uint32_t`

**Cython binding** (`base.pxi`):
```cython
ctypedef struct TVMFFIObject:
    uint32_t strong_ref_count  # new
    uint32_t weak_ref_count    # new
    int32_t type_index
    int32_t __padding          # was ref_counter
    void (*deleter)(TVMFFIObject* self)
```

## Impact
- API: **ABI-breaking**. All language bindings that access `TVMFFIObject` fields by offset must be updated. The `type_index` field moved from offset 0 to offset 8. `strong_ref_count` changed from u64 at offset 8 to u32 at offset 0.
- Behavioral: `strong_ref_count` max value is now 2^32-1 instead of 2^64-1. Practically no impact (no realistic scenario needs > 4 billion strong refs).
- Flags/config: none
- Data formats/schemas: `TVMFFIObject` field layout changed (see Key Exports)

## Design Elements
Design elements this commit consumes:
- **TVMFFIObject struct layout** ([0001-c-abi-layer](../../.knowledge/designs/0001-c-abi-layer.md)): Mutates the field order and `strong_ref_count` width.
- **Object refcount atomics** ([0003-object-system](../../.knowledge/designs/0003-object-system.md)): Updates `IncRef`, `DecRef`, `use_count`, `TryPromoteWeakPtr` to use 32-bit atomics on MSVC.
- **Weak RC ABI design** ([ADR 0015](../../.knowledge/ADRs/0015-weak-rc-abi-design.md)): The u64 strong counter decision is reversed; both counters are now u32.

Design elements this commit produces:
- **Refcount-first object header**: New invariant that `strong_ref_count` and `weak_ref_count` occupy the first 8 bytes, enabling future combined u64 atomic optimization.
- **Broken type_index offset alignment**: `TVMFFIObject.type_index` no longer shares offset 0 with `TVMFFIAny.type_index`. This is an explicit trade-off: refcount ops are more frequent than cross-struct type dispatching, so cache locality for refcount wins.

## Usage Examples
None (this is a layout refactor, not a new API).
