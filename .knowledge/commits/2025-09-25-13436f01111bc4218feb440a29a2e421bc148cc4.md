# TVMFFIObject ABI realignment: ref counts first, strong_ref_count narrowed to u32

## TL;DR
- Reorders `TVMFFIObject` header fields: `strong_ref_count(u32)` and `weak_ref_count(u32)` now occupy the first 8 bytes (packed into one u64), followed by `type_index(i32)` + `__padding(u32)` + `deleter(8 bytes)`. Total size remains 24 bytes.
- Narrows `strong_ref_count` from `uint64_t` to `uint32_t`. This enables packing both ref counts into a single 64-bit word, opening the door to future single-atomic-CAS ref count operations (technique from PyTorch).
- Deliberately breaks the `type_index`-first alignment between `TVMFFIObject` and `TVMFFIAny`. The old test asserting `reinterpret_cast<TVMFFIAny*>(&obj)->type_index == obj.type_index` is removed.

## Key Exports

```python
class TVMFFIObject:
    """C-level object header (24 bytes). All heap objects start with this.
    Field order changed: ref counts first for cache locality and future atomic optimization."""
    # --- New layout (this commit) ---
    strong_ref_count: uint32   # Was uint64. Offset 0.
    weak_ref_count: uint32     # Was at offset 4, now at offset 4 (same relative position to strong).
    type_index: int32          # Was at offset 0, now at offset 8.
    __padding: uint32          # New. Ensures 8-byte alignment for deleter.
    deleter: Callable[[void_ptr, int], None]  # Offset 16, unchanged.
    # Invariant: sizeof == 24, 8-byte aligned (unchanged)
    # Invariant: strong_ref_count + weak_ref_count pack into first u64 word
    # Invariant: type_index is NO LONGER at offset 0 (breaks alignment with TVMFFIAny)
    # Interacts with: Object.IncRef/DecRef/TryPromoteWeakPtr (atomics narrowed to 32-bit)
    # Interacts with: Cython base.pxi (must mirror this layout)

# Object::use_count() — MSVC path changed:
#   Old: reinterpret_cast<const volatile __int64*>(&strong_ref_count)
#   New: reinterpret_cast<const volatile long*>(&strong_ref_count)

# Object::IncRef() — MSVC path changed:
#   Old: _InterlockedIncrement64(reinterpret_cast<volatile __int64*>(&strong_ref_count))
#   New: _InterlockedIncrement(reinterpret_cast<volatile long*>(&strong_ref_count))

# Object::DecRef() — MSVC path changed:
#   Old: _InterlockedDecrement64(reinterpret_cast<volatile __int64*>(&strong_ref_count))
#   New: _InterlockedDecrement(reinterpret_cast<volatile long*>(&strong_ref_count))

# Object::TryPromoteWeakPtr() — CAS loop variable types changed:
#   Old: uint64_t old_count / new_count, _InterlockedCompareExchange64
#   New: uint32_t old_count / new_count, _InterlockedCompareExchange
```

## Impact
- API: ABI break. `TVMFFIObject` field offsets change: `type_index` moves from offset 0 to offset 8. `strong_ref_count` narrows from 8 bytes to 4 bytes. Any code that reads fields by offset (e.g., Cython `base.pxi`, Rust FFI bindings) must be updated.
- Behavioral: `strong_ref_count` capacity reduced from ~18 quintillion to ~4 billion. Acceptable since practical ref counts never approach this limit.
- Flags/config: None.
- Data formats/schemas: None (ref counts are runtime-only, not serialized).

- Weak reference counting two-phase deletion ([`.knowledge/ADRs/0009-weak-reference-counting.md`](../ADRs/0009-weak-reference-counting.md))

Design elements this commit produces:
- **Packed ref-count layout**: `strong_ref_count(u32) + weak_ref_count(u32)` at offset 0 as a single 64-bit word. This is a new ABI convention enabling future single-atomic operations on both counts simultaneously.
- **Broken type_index alignment**: `TVMFFIObject.type_index` is no longer at offset 0 (now offset 8), breaking the `TVMFFIAny`/`TVMFFIObject` shared-first-field convention documented in ADR 0001. The commit message explicitly acknowledges this trade-off: "they optimize for different goals."

## Usage Examples
None -- this is a layout refactor with no new API surface. All callers use the same field names; only offsets and widths change.
