# Reorder TVMFFIObject header fields: ref counters first (u32), type_index moved to offset 8, breaking layout aliasing with TVMFFIAny

## TL;DR
- Reordered `TVMFFIObject` header so `strong_ref_count` (now `uint32`) and `weak_ref_count` (already `uint32`) are the first 8 bytes, enabling future single-`u64` atomic optimization (torch `intrusive_ptr` pattern).
- Narrowed `strong_ref_count` from `uint64` to `uint32`, updating all MSVC interlocked ops from 64-bit (`_InterlockedIncrement64`/`_InterlockedCompareExchange64`) to 32-bit equivalents.
- **Broke** the `type_index` offset-0 aliasing invariant between `TVMFFIObject` and `TVMFFIAny`. `TVMFFIObject.type_index` is now at offset 8 (was offset 0). The test enforcing this aliasing (`test_c_ffi_abi.cc`) was deleted.

## Key Exports

```python
class TVMFFIObject:
    """24-byte object header. ABI reordered: ref counters first for cache-friendly RC ops."""
    # NEW layout (this commit):
    # Offset 0:  strong_ref_count (uint32) -- was at offset 8, was uint64
    # Offset 4:  weak_ref_count   (uint32) -- was at offset 4
    # Offset 8:  type_index       (int32)  -- was at offset 0
    # Offset 12: __padding        (uint32) -- NEW, ensures 8-byte alignment
    # Offset 16: deleter / __ensure_align union (8 bytes) -- unchanged
    # Invariant: sizeof(TVMFFIObject) == 24 (unchanged)
    # Invariant: strong_ref_count + weak_ref_count pack into first u64 (enables future single-atomic CAS)
    # BREAKING: type_index no longer at offset 0 -- aliasing with TVMFFIAny.type_index is gone
    # Interacts with: Object::IncRef(), Object::DecRef(), Object::TryPromoteWeakPtr(), Object::use_count()
    # Interacts with: TVMFFIAny (no longer shares type_index offset)
    # Extension: future u64 atomic combining strong+weak counters (torch technique)

# MSVC atomic ops narrowed from 64-bit to 32-bit:
# Object::IncRef():  _InterlockedIncrement64 -> _InterlockedIncrement (volatile long*)
# Object::DecRef():  _InterlockedDecrement64 -> _InterlockedDecrement (volatile long*)
# Object::use_count(): volatile __int64* -> volatile long*
# Object::TryPromoteWeakPtr(): _InterlockedCompareExchange64 -> _InterlockedCompareExchange
#   local variables: uint64 old_count/new_count -> uint32 old_count/new_count

# Cython binding (base.pxi) updated:
# TVMFFIObject.strong_ref_count: uint32 (NEW field, was absent)
# TVMFFIObject.weak_ref_count:   uint32 (NEW field, was absent)
# TVMFFIObject.type_index:       int32  (moved after counters)
# TVMFFIObject.__padding:        int32  (NEW)
```

## Impact
- API: **ABI-breaking** -- `TVMFFIObject` field order changed. Any code that aliased `TVMFFIObject*` as `TVMFFIAny*` to read `type_index` at offset 0 is broken. The deleted test (`test_c_ffi_abi.cc`) was the only known consumer of this aliasing.
- Behavioral: `strong_ref_count` narrowed from `uint64` to `uint32`, capping max strong references at ~4 billion (sufficient for practical use). All atomic operations narrowed from 64-bit to 32-bit, which may improve performance on some architectures.
- Flags/config: none
- Data formats/schemas: none (header is in-memory only, not serialized)

## Design Elements
Design elements this commit consumes:
- `TVMFFIObject` 24-byte header layout (0007-c-abi.md, 0002-object-system.md)
- `Object::IncRef`/`DecRef`/`TryPromoteWeakPtr` atomic RC protocol (0002-object-system.md)
- Cython `TVMFFIObject` struct declaration (0012-python-bindings)
- torch `intrusive_ptr` combined counter technique (external reference)

Design elements this commit produces:
- **NEW field ordering**: `{strong_ref_count, weak_ref_count, type_index, __padding, deleter}` replaces `{type_index, weak_ref_count, strong_ref_count, deleter}`
- **Narrowed `strong_ref_count`**: `uint32` (was `uint64`), enabling future u64 atomic combining both counters
- **`__padding` field**: explicit 4-byte padding after `type_index` to maintain 8-byte alignment
- **REMOVES invariant**: `TVMFFIObject.type_index` at offset 0 no longer holds; `TVMFFIAny` and `TVMFFIObject` no longer share a layout prefix

## Usage Examples
Before (old layout, deleted test):
```c
TVMFFIObject value;
value.type_index = 10;
// This aliasing WORKED because type_index was at offset 0 in both structs:
EXPECT_EQ(reinterpret_cast<TVMFFIAny*>(&value)->type_index, 10);  // PASSED
```

After (new layout -- aliasing is broken):
```c
TVMFFIObject value;
value.type_index = 10;
// reinterpret_cast<TVMFFIAny*>(&value)->type_index would read strong_ref_count, NOT type_index
// The aliasing test was intentionally deleted.
// Use TVMFFIObjectGetTypeIndex(obj) to read type_index portably.
```
