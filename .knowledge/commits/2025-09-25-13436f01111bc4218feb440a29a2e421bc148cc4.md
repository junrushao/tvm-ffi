# Reorder TVMFFIObject fields to align ABI with torch intrusive_ptr

## TL;DR
- Reorders `TVMFFIObject` fields: ref counters (`strong_ref_count`, `weak_ref_count`) now come first, then `type_index`, then `__padding`, to align with torch `intrusive_ptr` ABI layout.
- Changes `strong_ref_count` from `uint64_t` to `uint32_t` (matching weak_ref_count width).
- Removes `test_c_ffi_abi.cc` which tested the old layout assumption that `type_index` at offset 0 matches `TVMFFIAny.type_index`.

## Key Exports

**Struct layout change** (`TVMFFIObject`, 24 bytes):

| Offset | Before | After |
|--------|--------|-------|
| 0 | `int32_t type_index` | `uint32_t strong_ref_count` |
| 4 | `uint32_t weak_ref_count` | `uint32_t weak_ref_count` |
| 8 | `uint64_t strong_ref_count` | `int32_t type_index` |
| 12 | (part of strong_ref_count) | `uint32_t __padding` |
| 16 | `void (*deleter)(...)` | `void (*deleter)(...)` |

## Impact
- API: `Object::use_count()` now uses 32-bit atomics for `strong_ref_count`.
- ABI: **Breaking**. Field offsets in `TVMFFIObject` changed. The `type_index` is no longer at offset 0 -- code that assumed `TVMFFIObject` and `TVMFFIAny` share the same `type_index` at offset 0 is broken.
- Behavioral: Atomic operations on MSVC switch from `_InterlockedIncrement64`/`__int64` to `_InterlockedIncrement`/`long` for strong ref counter.
- Flags/config: none
- Data formats/schemas: none
