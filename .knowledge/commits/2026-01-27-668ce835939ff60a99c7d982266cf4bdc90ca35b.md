# Fix JSONDecodeError in get_global_func_metadata() when Python-registered functions return empty metadata string

## TL;DR
- `get_global_func_metadata(name)` no longer raises `JSONDecodeError` for Python-registered global functions that return an empty string from `ffi.GetGlobalFuncMetadata`.
- Fix: check for empty/falsy string before calling `json.loads()`; return `{}` for functions without metadata.
- Adds regression test `test_metadata_empty_for_python_func`.

## Key Exports

None — bugfix only.

## Impact
- API: none — `get_global_func_metadata()` return type is unchanged (`dict[str, Any]`).
- Behavioral: Python-registered global functions (which have no C++ metadata) now return `{}` instead of raising `json.JSONDecodeError`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0004-function-system`: `get_global_func` / `ffi.GetGlobalFuncMetadata` — the global function registry lookup that returns empty string for Python-registered functions.
- `0019-type-schema`: Function metadata protocol — C++-registered functions return JSON; Python-registered return empty string.

Design elements this commit produces: None — bugfix only.

## Usage Examples

Before (crashes for Python-registered functions):
```python
@register_global_func("my.func")
def my_func(x): return x

get_global_func_metadata("my.func")  # json.JSONDecodeError: Expecting value: line 1 column 1
```

After:
```python
get_global_func_metadata("my.func")  # Returns {}
```
