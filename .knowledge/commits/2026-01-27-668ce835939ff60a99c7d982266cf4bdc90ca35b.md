# Fix empty metadata handling in get_global_func_metadata
## TL;DR
- Python-registered global functions without C++ metadata caused `JSONDecodeError` when `get_global_func_metadata()` was called, because `ffi.GetGlobalFuncMetadata` returns a falsy value that was passed to `json.loads()`.
- Fix splits the call into an explicit emptiness check, returning `{}` directly for functions without metadata.
- Adds regression test registering a Python function and asserting empty metadata dict.

## Key Exports
None -- no new API surface. The fix changes internal behavior of an existing function.

## Impact
- API: none -- `get_global_func_metadata` signature unchanged
- Behavioral: functions registered from Python (which lack C++ metadata) now correctly return `{}` instead of raising `JSONDecodeError`
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before (raises `JSONDecodeError` for Python-registered functions):
```python
from tvm_ffi import register_global_func, get_global_func_metadata

@register_global_func("my.func")
def my_func(x: int) -> int:
    return x + 1

# BROKEN: json.loads() receives falsy value from FFI, crashes
meta = get_global_func_metadata("my.func")  # JSONDecodeError
```

After (returns empty dict):
```python
from tvm_ffi import register_global_func, get_global_func_metadata

@register_global_func("my.func")
def my_func(x: int) -> int:
    return x + 1

# FIXED: empty metadata returns {} directly
meta = get_global_func_metadata("my.func")  # {}
```
