# Add Docker dev container and C++ CUDA quick-start example
## TL;DR
- New `tests/docker/Dockerfile` based on `nvidia/cuda:12.6.3-devel-ubuntu22.04` providing a full dev toolchain (CMake, Clang, Ninja, Python, CUDA).
- New `examples/quick_start/src/run_example_cuda.cc` demonstrating GPU tensor allocation, CUDA kernel invocation via FFI module loading, and device-to-host copy.
- Build script (`run_example.sh`) and CMakeLists.txt modernized: prefer Ninja generator, use `find_package(CUDAToolkit)` instead of deprecated `find_package(CUDA)`, add `--parallel` flag. Pre-commit hooks switched from `language: system` to `language: python`.

## Usage Examples

End-to-end CUDA example pattern (from `run_example_cuda.cc`):

```cpp
#include <tvm/ffi/container/tensor.h>
#include <tvm/ffi/extra/module.h>
namespace ffi = tvm::ffi;

// 1. Load compiled CUDA module
ffi::Module mod = ffi::Module::LoadFromFile("build/add_one_cuda.so");

// 2. Allocate GPU tensors with custom CUDA allocator
ffi::Tensor x = ffi::Tensor::FromNDAlloc(CUDANDAlloc(), {5}, f32_dtype, cuda_device);

// 3. Copy host data to device, invoke FFI function, copy back
cudaMemcpy(x->data, host_x.data(), nbytes, cudaMemcpyHostToDevice);
ffi::Function add_one_cuda = mod->GetFunction("add_one_cuda").value();
add_one_cuda(x, y);
cudaMemcpy(host_y.data(), y->data, nbytes, cudaMemcpyDeviceToHost);
```

Docker dev environment usage:
```bash
docker build -t tvm-ffi-dev -f tests/docker/Dockerfile tests/docker
docker run --rm -it --gpus all -v "$(pwd)":/workspace/tvm-ffi -w /workspace/tvm-ffi tvm-ffi-dev bash
# Inside container: pip install -ve . && cd examples/quick_start && bash run_example.sh
```
