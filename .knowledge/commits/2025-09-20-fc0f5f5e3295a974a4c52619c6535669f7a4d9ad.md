# Add Docker dev container, CUDA C++ example, and Ninja-enabled build scripts for quick_start

## TL;DR
- Adds `tests/docker/Dockerfile` based on `nvidia/cuda:12.6.3-devel-ubuntu22.04` with CMake (Kitware PPA), Ninja, Clang, and Python toolchain for GPU-capable development environments.
- Adds `examples/quick_start/src/run_example_cuda.cc`, a C++ driver that allocates CUDA tensors, calls `add_one_cuda` via `ffi::Module::LoadFromFile`, and copies results back to host — demonstrating the end-to-end GPU FFI call path from C++.
- Updates `run_example.sh` and `CMakeLists.txt` to prefer Ninja, use `cmake --fresh`, add `--parallel`, switch from deprecated `find_package(CUDA)` to `find_package(CUDAToolkit)`, and conditionally build and run `run_example_cuda` when the CUDA toolkit is present.

## Usage Examples

**End-to-end CUDA FFI call from C++ (from `examples/quick_start/src/run_example_cuda.cc`):**

```cpp
// Load the .so built from add_one_cuda.cu
ffi::Module mod = ffi::Module::LoadFromFile("build/add_one_cuda.so");

// Allocate CUDA tensors
ffi::Tensor x = Empty({5}, f32_dtype, {kDLCUDA, 0});
ffi::Tensor y = Empty({5}, f32_dtype, {kDLCUDA, 0});

// Copy host data to device
cudaMemcpy(x->data, host_x.data(), nbytes, cudaMemcpyHostToDevice);

// Call FFI function — tensors remain on device
ffi::Function add_one_cuda = mod->GetFunction("add_one_cuda").value();
add_one_cuda(x, y);

// Copy result back
cudaMemcpy(host_y.data(), y->data, nbytes, cudaMemcpyDeviceToHost);
```
