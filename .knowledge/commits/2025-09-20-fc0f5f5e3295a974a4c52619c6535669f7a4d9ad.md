# Add Docker support and C++ CUDA example

## TL;DR
- Adds a Docker development container (`tests/docker/Dockerfile`) based on `nvidia/cuda:12.6.3-devel-ubuntu22.04` with the full build toolchain (CMake, Ninja, Clang, Python, CUDA) and optional GPU passthrough for running examples inside a container.
- Adds a new C++ CUDA example (`examples/quick_start/src/run_example_cuda.cc`) that allocates CUDA tensors, invokes the `add_one_cuda` FFI function on-device, and copies results back to host memory.
- Updates the quick-start CMakeLists.txt to build a `run_example_cuda` executable when the CUDA toolkit is detected, migrating from the deprecated `find_package(CUDA)` to `find_package(CUDAToolkit)`.
- Updates build scripts to prefer the Ninja generator for faster incremental builds and adds a `requirements.txt` for Python example dependencies.
- Documents Docker-based development workflow in `CONTRIBUTING.md` and updates `docs/get_started/quick_start.md` with CUDA binary instructions.
- Fixes pre-commit hook `language` settings from `system` to `python` with explicit `language_version: python3` for portability.

## Key Exports

**New files:**

- `tests/docker/Dockerfile` -- Development container image. Base: `nvidia/cuda:12.6.3-devel-ubuntu22.04`. Installs: build-essential, clang, clang-format, clang-tidy, cmake (via Kitware APT), ninja-build, Python 3, git, doxygen, graphviz, pandoc. Provides optional `REPO_URL` build arg to clone a repo during image build. Default command: `/bin/bash`.
- `examples/quick_start/src/run_example_cuda.cc` -- Standalone C++ program that loads `build/add_one_cuda.so` via `ffi::Module::LoadFromFile`, allocates CUDA tensors using a custom `CUDANDAlloc` struct (with `cudaMalloc`/`cudaFree`), copies host data to device, calls the `add_one_cuda` FFI function, copies results back, and prints output. Links against `tvm_ffi_shared` and `CUDA::cudart`.
- `examples/quick_start/requirements.txt` -- Pins `numpy==2.2.6` and `PyYAML==5.4.1` for the Python quick-start example.

**Modified build targets:**

- `examples/quick_start/CMakeLists.txt` -- New `run_example_cuda` executable target (C++17, links `tvm_ffi_shared` and `CUDA::cudart`). CUDA detection migrated from `find_package(CUDA QUIET)` to `find_package(CUDAToolkit QUIET)`. Comments improved throughout.

**Modified scripts:**

- `examples/quick_start/run_example.sh` -- Now auto-detects Ninja vs Unix Makefiles, uses `cmake --fresh -G "$generator"`, runs `cmake --build build --parallel`, installs Python dependencies from `requirements.txt`, and conditionally runs `run_example_cuda` if the binary exists.

## Design Elements
Design elements this commit consumes:
- **Module system** (`ffi::Module::LoadFromFile`): Used in `run_example_cuda.cc` to load the CUDA shared library at runtime and retrieve the `add_one_cuda` function via `mod->GetFunction("add_one_cuda")`.
- **Tensor / NDArray** (`ffi::Tensor`, `ffi::Shape`, `GetDataSize`): Used to create CUDA-resident tensors with custom allocator.
- **Tensor::FromNDAlloc** pattern: The `CUDANDAlloc` struct in the example demonstrates the NDAlloc protocol -- a struct with `AllocData(DLTensor*)` and `FreeData(DLTensor*)` methods passed to `ffi::Tensor::FromNDAlloc`.
- **Function calling convention**: The loaded FFI function is called with `add_one_cuda(x, y)`, exercising the packed calling convention with `Tensor` arguments.
- **Error handling** (`TVM_FFI_ICHECK_EQ`): Used to assert CUDA API success in the example allocator.
- **TVM_FFI_DLL_EXPORT_TYPED_FUNC**: Referenced in documentation as the macro that exposes the `add_one_cuda` function from the `.cu` compilation unit.

Design elements this commit produces:
- **Docker development environment**: A reproducible container setup documented in `CONTRIBUTING.md` that provides the full toolchain (C++17, CUDA 12.6, CMake, Ninja, Python 3) for building the project and running examples. Supports GPU passthrough via `docker run --gpus all` with NVIDIA Container Toolkit.
- **CUDANDAlloc pattern**: A minimal example of implementing the NDAlloc protocol for CUDA memory (`cudaMalloc`/`cudaFree`), demonstrating how to create device-resident `ffi::Tensor` objects outside the core library.
- **Ninja-preferring build script**: The updated `run_example.sh` establishes a pattern of auto-detecting the Ninja generator with fallback to Unix Makefiles.

## Usage Examples

### Building and running the CUDA example
```bash
cd examples/quick_start
cmake --fresh -G Ninja -B build -S .
cmake --build build --parallel
./build/run_example_cuda
```

### Using the Docker development container
```bash
# Build the image
docker build -t tvm-ffi-dev -f tests/docker/Dockerfile tests/docker

# Run with GPU access
docker run --rm -it --gpus all \
    -v "$(pwd)":/workspace/tvm-ffi \
    -w /workspace/tvm-ffi \
    tvm-ffi-dev bash

# Inside the container
pip install -ve .
cd examples/quick_start
bash run_example.sh
```

### Custom CUDA tensor allocation via NDAlloc protocol
```cpp
#include <cuda_runtime.h>
#include <tvm/ffi/container/tensor.h>

struct CUDANDAlloc {
  void AllocData(DLTensor* tensor) {
    cudaMalloc(&tensor->data, tvm::ffi::GetDataSize(*tensor));
  }
  void FreeData(DLTensor* tensor) {
    cudaFree(tensor->data);
    tensor->data = nullptr;
  }
};

// Create a CUDA tensor
DLDataType f32{kDLFloat, 32, 1};
DLDevice cuda0{kDLCUDA, 0};
auto tensor = tvm::ffi::Tensor::FromNDAlloc(CUDANDAlloc(), {1024}, f32, cuda0);
```
