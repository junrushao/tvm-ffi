# Zero the value union when packing None in legacy make_args Cython code path

## TL;DR
- Adds `out[i].v_int64 = 0` when packing a `None` argument in the legacy `make_args` function in `function.pxi`, ensuring the `TVMFFIAny` value union is zeroed rather than left containing stale data.
- Aligns the legacy code path with the newer `TVMFFIPyArgSetterNone_` C helper (in `tvm_ffi_python_helpers.h`) which already correctly zeros `v_int64` for None values.

## Key Exports
No new symbols, no signature changes. This commit modifies only the internal implementation of the existing `make_args` Cython function in `function.pxi`.

**`make_args(tuple py_args, TVMFFIAny* out, list temp_args, ...)` (unchanged signature)**:
- The `arg is None` branch now sets both `out[i].type_index = kTVMFFINone` **and** `out[i].v_int64 = 0`. Previously only `type_index` was set.

## Impact
- API: none -- no public API or function signature changes.
- ABI: none -- the `TVMFFIAny` struct layout is unchanged; this only affects the value written into the union when packing None.
- Behavioral: Prevents the `TVMFFIAny` value union from containing stale/uninitialized data when `type_index` is `kTVMFFINone`. The `TVMFFIAny` struct documentation (`c_api.h` line 296) states that `zero_padding` "must set to zero for values other than small string". While the `type_index` field correctly identifies the value as None, leaving the 8-byte value union uninitialized could cause issues in C++ code that inspects the raw bits (e.g., hashing via `v_uint64`, equality comparisons, or serialization). The fix ensures deterministic zero-valued content for None arguments, matching the behavior of both the newer `TVMFFIPyArgSetterNone_` setter and the `ConstructorCall` / `Function.__call__` code paths which explicitly initialize `result.v_int64 = 0`.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **TVMFFIAny type-erased value struct** (`c_api.h`): The struct has a `type_index` (int32), a `zero_padding`/`small_str_len` union (uint32), and a value union (8 bytes: `v_int64`/`v_float64`/`v_ptr`/`v_dtype`/`v_device`/`v_bytes`/`v_uint64`). The documentation requires `zero_padding` to be zero for non-small-string values. This commit extends that discipline to also zero the value union for None.
- **Legacy `make_args` argument packing** (`function.pxi`): The older Cython function that packs Python arguments into a `TVMFFIAny` array by type-checking each argument and setting the appropriate `type_index` + value fields. This function was the original argument packing path before the `TVMFFIPyArgSetterFactory_` dispatcher pattern was introduced.
- **`TVMFFIPyArgSetterNone_` C helper** (`tvm_ffi_python_helpers.h`): The newer None setter used by the `TVMFFIPyArgSetterFactory_` dispatch path, which already sets `out->type_index = kTVMFFINone; out->v_int64 = 0;`.

Design elements this commit produces:
- None. This is a correctness fix that aligns an existing code path with established conventions.

## Usage Examples
No change in public API usage. The internal fix is:

```cython
# BEFORE: value union left uninitialized for None
elif arg is None:
    out[i].type_index = kTVMFFINone

# AFTER: value union explicitly zeroed for None
elif arg is None:
    out[i].type_index = kTVMFFINone
    out[i].v_int64 = 0
```

This matches the pattern used elsewhere when initializing `TVMFFIAny` for results:
```cython
# In ConstructorCall and Function.__call__:
result.type_index = kTVMFFINone
result.v_int64 = 0
```
