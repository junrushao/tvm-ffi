# Fix uninitialized value union in Cython None argument packing
## TL;DR
- The Cython `make_args` function in `function.pxi` did not zero `v_int64` when packing a Python `None` into a `TVMFFIAny` slot, leaving the value union uninitialized.
- Added `out[i].v_int64 = 0` to match the C++ `TypeTraits<std::nullptr_t>` convention, which requires the full 16-byte `TVMFFIAny` to be deterministic for hashing and equality comparisons.

None

## Impact
- API: None
- Behavioral: `None` values passed through Cython FFI calls now have deterministic hash and equality behavior. Previously, stale bits in the value union could cause non-deterministic `same_as` comparisons or hash mismatches.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **TVMFFIAny struct layout** (`include/tvm/ffi/c_api.h:188-217`): The 16-byte union-based value container. The fix writes to the `v_int64` field of the value union. See [0002-any-value-system.md](../designs/0002-any-value-system.md).
- **None/nullptr invariant** (`include/tvm/ffi/type_traits.h:121-135`): C++ `TypeTraits<std::nullptr_t>` explicitly sets `v_int64 = 0` with comment "invariant: the pointer field also equals nullptr / this will simplify same_as comparisons and hash." The Cython path must uphold the same invariant.
- **TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY macro** (`include/tvm/ffi/base_details.h:122-132`): Documents that `v_int64` must be usable for hash and equality, so padding/unused bits must be zeroed.

Design elements this commit produces:
- None (bug fix only, no new design elements)

## Usage Examples
**Before (bug)**: Cython packed `None` without zeroing the value union:
```cython
elif arg is None:
    out[i].type_index = kTVMFFINone
    # v_int64 left with whatever was in the slot before
```

**After (fix)**: Value union explicitly zeroed:
```cython
elif arg is None:
    out[i].type_index = kTVMFFINone
    out[i].v_int64 = 0  # match C++ TypeTraits<nullptr_t> invariant
```
