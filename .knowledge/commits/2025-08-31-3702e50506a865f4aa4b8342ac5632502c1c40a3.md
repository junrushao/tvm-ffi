# Fix uninitialized v_int64 in Cython make_args when marshaling Python None to kTVMFFINone

## TL;DR

- In `python/tvm_ffi/cython/function.pxi`'s `make_args`, the `None` branch set `out[i].type_index = kTVMFFINone` but left `out[i].v_int64` uninitialized.
- This violates the `TVMFFIAny` invariant that both `type_index` and `v_int64` must be zeroed for `kTVMFFINone` values, potentially exposing garbage data to C++ callers.
- Fix adds `out[i].v_int64 = 0` immediately after setting the type index.

## Key Exports

None — this commit changes no public API; it only restores an invariant in the internal argument-marshaling path.

## Impact

- API: none
- Behavioral: passing Python `None` as a positional argument in any packed function call via Cython now correctly zeroes the 8-byte value union in `TVMFFIAny`, consistent with the invariant enforced everywhere else (`result.type_index = kTVMFFINone; result.v_int64 = 0;`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `TVMFFIAny` wire struct (`0001-c-abi`): specifically the invariant "type_index and v_int64 are ALWAYS zeroed for kTVMFFINone" (design-records/0001-c-abi.md, line 108).
- `kTVMFFINone = 0` type index (`0001-c-abi`): the canonical sentinel for null / Python None.
- `make_args` Cython helper (`python/tvm_ffi/cython/function.pxi`): fills a `TVMFFIAny[]` array from Python positional arguments before dispatching a packed function call.

Design elements this commit produces: None.

## Usage Examples

**Before (broken — v_int64 uninitialized):**
```python
# Python call: func(None)
# In make_args:
out[i].type_index = kTVMFFINone
# v_int64 left at whatever stack garbage was in out[i]
```

**After (correct — union fully zeroed):**
```python
# Python call: func(None)
# In make_args:
out[i].type_index = kTVMFFINone
out[i].v_int64 = 0  # satisfies TVMFFIAny kTVMFFINone invariant
```
