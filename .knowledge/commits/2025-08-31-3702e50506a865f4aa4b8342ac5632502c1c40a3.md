# Fix missing v_int64 zeroing for None in legacy make_args
## TL;DR
- Adds `out[i].v_int64 = 0` to the `None` branch of the legacy `make_args` function in `function.pxi`, ensuring the full 8-byte value union is zeroed when packing a `None` argument.
- Without this fix, on 64-bit platforms the `v_int64` field was left uninitialized for `None` arguments because the platform guard (`if sizeof(void*) != 8`) skips the blanket zeroing. This could cause spurious inequality or hash mismatch downstream.
- The commit title mentions "two migration issues" but only one change is present in this commit; the second issue may have been addressed separately or in a paired PR.

## Impact
- API: None. No signature or behavioral change to public Python APIs.
- Flags/config: None.
- Data formats/schemas: None.
- Risk: Low. The fix is a single-line addition that brings the `None` case in line with how `ConstructorCall` and `FuncCall` already initialize their result `TVMFFIAny` (both set `type_index = kTVMFFINone` and `v_int64 = 0`). The new dispatch-based `TVMFFIPyArgSetterNone_` in `tvm_ffi_python_helpers.h:224-229` was already correct.

## Design Elements
Design elements this commit consumes:

- **Padding-zeroing invariant** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): The `TVMFFIAny` value union must have all unused bytes zeroed. For `kTVMFFINone`, the entire `v_int64` must be zero. This invariant enables `AnyEqual` to use a 16-byte bitwise fast-path comparison and `AnyHash` to produce consistent hashes. The bug was that the `None` branch in `make_args` only set `type_index` without zeroing the value union, violating this invariant on 64-bit platforms where the blanket `v_int64 = 0` guard (`sizeof(void*) != 8`) is skipped.
- **Legacy `make_args` argument packing** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md), section "Argument Packing Priority Order"): The `make_args` function is the legacy code path for converting Python arguments to `TVMFFIAny*`. It has since been superseded by the dispatch-based `TVMFFIPyArgSetterFactory_` mechanism, which uses `TVMFFIPyArgSetterNone_` (defined in `tvm_ffi_python_helpers.h`) and was already correct. This commit patches the legacy path to match.

- None. This is a pure bugfix with no new abstractions.
