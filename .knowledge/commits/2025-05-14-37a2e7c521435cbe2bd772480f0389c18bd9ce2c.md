# Distinguish as (strict) and cast/try_cast (with conversion) in the Any system

## TL;DR
- Splits the previous `as<T>()` method (which performed type conversion) into two distinct operations: `as<T>()` (strict type check only, no conversion) and `try_cast<T>()` / `cast<T>()` (with type conversion).
- Renames the `TypeTraits<T>` protocol methods to match the new semantics: `CheckAnyStorage` -> `CheckAnyStrict`, `CopyFromAnyStorageAfterCheck` -> `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` -> `MoveFromAnyAfterCheck`, `TryConvertFromAnyView` -> `TryCastFromAnyView`.
- Adds `as()` rvalue-ref overload on `Any` for move semantics when strict-checking succeeds.
- Updates all container types (`Array`, `Map`, `Tuple`, `Variant`), `DLDataType`, `TypedFunction`, `RValueRef`, `String`/`Bytes`, and scalar type traits to use the renamed protocol.

## Key Changes

### AnyView API (include/tvm/ffi/any.h)

**Before:** `as<T>()` called `TypeTraits<T>::TryConvertFromAnyView()`, performing type conversion (e.g., `int` -> `double`). `cast<T>()` was identical but threw on failure instead of returning `nullopt`. The `as<Object>()` shortcut returned `const T*`.

**After:** Three distinct methods on `AnyView`:
- `as<T>() -> optional<T>` -- Strict check only via `TypeTraits<T>::CheckAnyStrict` + `CopyFromAnyViewAfterCheck`. Returns `nullopt` if the stored type does not exactly match T (no coercion). For example, `AnyView(1).as<double>()` returns `nullopt`.
- `as<T>() -> const T*` (where T : Object) -- Shortcut unchanged, delegates to `as<const T*>()`.
- `cast<T>() -> T` -- Performs conversion via `TypeTraits<T>::TryCastFromAnyView`, throws `TypeError` on failure.
- `try_cast<T>() -> optional<T>` -- New method. Performs conversion via `TypeTraits<T>::TryCastFromAnyView`, returns `nullopt` on failure.

### Any API (include/tvm/ffi/any.h)

Same three-way split as `AnyView`, plus:
- `as<T>() const&` -- Strict check, copy semantics (lvalue).
- `as<T>() &&` -- New rvalue overload. Strict check via `CheckAnyStrict`, then `MoveFromAnyAfterCheck` for zero-copy extraction.
- `as<const T*>() const&` -- Object pointer shortcut (lvalue only).
- `cast<T>() const&` -- Conversion with copy.
- `cast<T>() &&` -- Conversion with move. Fast path: `CheckAnyStrict` + `MoveFromAnyAfterCheck`. Slow path: `TryCastFromAnyView`.
- `try_cast<T>() const` -- New method, delegates to `TryCastFromAnyView`.

### TypeTraits Protocol Renames (include/tvm/ffi/type_traits.h)

| Old Name | New Name | Semantics Change |
|---|---|---|
| `CheckAnyStorage` | `CheckAnyStrict` | Name only; same behavior (exact type match) |
| `CopyFromAnyStorageAfterCheck` | `CopyFromAnyViewAfterCheck` | Name only; clarifies it works on view data |
| `MoveFromAnyStorageAfterCheck` | `MoveFromAnyAfterCheck` | Name only; clarifies move from owned storage |
| `TryConvertFromAnyView` | `TryCastFromAnyView` | Name only; same behavior (conversion with coercion) |

The protocol documentation block in `type_traits.h` is updated to describe the new names and the distinction between `CheckAnyStrict` (used by `as`) and `TryCastFromAnyView` (used by `cast`/`try_cast`).

### DLTensor* Traits Enhancement (include/tvm/ffi/type_traits.h)

Added `CheckAnyStrict` and `CopyFromAnyViewAfterCheck` to `TypeTraits<DLTensor*>`, which previously only had `TryConvertFromAnyView`. This enables `as<DLTensor*>()` to work via the strict path.

### Internal Callers Updated

- `details::AnyUnsafe` helper methods renamed: `CheckAnyStorage` -> `CheckAnyStrict`, `CopyFromAnyStorageAfterCheck` -> `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` -> `MoveFromAnyAfterCheck`.
- `ArgValueWithContext::operator T()` in `function_details.h` changed from `as<T>()` to `try_cast<T>()` since packed function argument dispatch needs type conversion (e.g., accepting `int` for a `double` parameter).
- `ffi.Shape` global function in `src/ffi/ndarray.cc` changed from `as<int64_t>()` to `try_cast<int64_t>()`.
- Container type traits (`Array<T>`, `Map<K,V>`, `Tuple<Types...>`, `Variant<V...>`) updated all internal calls: storage checks use `CheckAnyStrict`, element conversion uses `try_cast`, and direct extraction uses `CopyFromAnyViewAfterCheck`.
- `AnyHash` and `AnyEqual` use `CopyFromAnyViewAfterCheck` (renamed from `CopyFromAnyStorageAfterCheck`).

### Test Updates

- New `TEST(Any, CastVsAs)` in `tests/cpp/test_any.cc` verifies the semantic split: `AnyView(1).as<int64_t>()` succeeds, `AnyView(1).as<bool>()` fails (strict), `AnyView(1).try_cast<bool>()` succeeds (conversion).
- `test_dtype.cc`: String-to-DLDataType conversion tests changed from `as<DLDataType>()` to `try_cast<DLDataType>()` since string-to-dtype is a conversion, not a strict match.
- `test_string.cc`: All `as<std::string>()` calls changed to `try_cast<std::string>()` since extracting `std::string` from a `String` object requires conversion.
- `test_variant.cc`: Removed `v1.as<float>()` test on `Variant<int, float>` since strict `as` no longer performs cross-variant-member conversion.

## Impact
- API: Breaking change to the semantics of `as<T>()`. Code that relied on `as<T>()` for type conversion (e.g., `any_int.as<double>()`) must switch to `try_cast<T>()` or `cast<T>()`. Code that used `as<T>()` for exact type checking continues to work but now correctly returns `nullopt` for non-exact matches.
- ABI: No ABI change. The C ABI (`TVMFFISafeCallType`, `TVMFFIAny` layout) is unaffected. The renamed methods are all C++ template functions resolved at compile time.
- Behavioral: `as<T>()` is now cheaper (no conversion attempt, just a type index check). `cast<T>()` and `try_cast<T>()` retain the previous conversion behavior.
- TypeTraits implementors: Any custom `TypeTraits<T>` specialization must rename `CheckAnyStorage` -> `CheckAnyStrict`, `CopyFromAnyStorageAfterCheck` -> `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` -> `MoveFromAnyAfterCheck`, `TryConvertFromAnyView` -> `TryCastFromAnyView`.

## Design Elements
Design elements this commit consumes:
- TypeTraits protocol (from root commit 7d34eb8) -- the trait-based conversion system being refactored.
- Any/AnyView duality (from root commit 7d34eb8) -- the owning/non-owning value container pair.
- Container type traits for Array, Map, Tuple, Variant (from root commit 7d34eb8).

Design elements this commit produces:
- **Strict-vs-conversion duality in type access** -- `as<T>()` = strict reinterpret (CheckAnyStrict only), `cast<T>()` / `try_cast<T>()` = conversion-enabled (TryCastFromAnyView). This is a deliberate design choice to make the common "check if this is exactly type T" pattern cheaper and more explicit.
- **Rvalue as() on Any** -- `Any::as<T>() &&` enables move-based extraction when the strict check passes, avoiding a copy for owned values.
- **Renamed TypeTraits protocol** -- `CheckAnyStrict` / `CopyFromAnyViewAfterCheck` / `MoveFromAnyAfterCheck` / `TryCastFromAnyView` replace the older `CheckAnyStorage` / `CopyFromAnyStorageAfterCheck` / `MoveFromAnyStorageAfterCheck` / `TryConvertFromAnyView` names.

## Usage Examples

### Strict check (as) vs conversion (try_cast/cast)
```cpp
AnyView view = 1;  // stores int

// Strict: only matches exact type
auto opt_int = view.as<int64_t>();    // has_value() == true, value == 1
auto opt_bool = view.as<bool>();      // has_value() == false (int != bool)
auto opt_dbl = view.as<double>();     // has_value() == false (int != double)

// Conversion: tries type coercion
auto cast_bool = view.try_cast<bool>();   // has_value() == true, value == true
auto cast_dbl = view.try_cast<double>();  // has_value() == true, value == 1.0
double d = view.cast<double>();           // 1.0 (throws TypeError on failure)
```

### Move extraction from Any
```cpp
Any any = String("hello");
// Rvalue as<T>() moves the string out without copying
auto opt_str = std::move(any).as<String>();  // moves if strict check passes
```

### ADRs to write or update
- `.knowledge/ADRs/005-as-vs-cast-semantics.md` -- New ADR documenting the decision to split `as` (strict) from `cast`/`try_cast` (with conversion). Rationale: (1) `as` is the common fast-path for type checking in containers and pattern matching, making it cheaper by avoiding conversion attempts; (2) explicit API prevents accidental implicit conversions; (3) naming follows the convention that `as` = reinterpret, `cast` = convert.
