# Rename TypeTraits methods to distinguish strict `as` from permissive `cast`/`try_cast`

## TL;DR
- Renames TypeTraits internal methods: `CheckAnyStorage` -> `CheckAnyStrict`, `CopyFromAnyStorageAfterCheck` -> `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` -> `MoveFromAnyAfterCheck`, `TryConvertFromAnyView` -> `TryCastFromAnyView`.
- Redefines the semantics of `AnyView::as<T>()` and `Any::as<T>()` to be strict-only (no type conversion), and `cast<T>()`/`try_cast<T>()` to be the permissive path that runs type conversion.
- Adds new `try_cast<T>()` method on both `AnyView` and `Any` as a non-throwing permissive conversion (returns `optional`).

## Impact
- API: Method renames across the entire TypeTraits protocol and AnyUnsafe helper. All downstream specializations (containers, function, dtype, string, variant, rvalue_ref) updated in this commit. External code specializing TypeTraits must update method names.
- Behavioral: `as<T>()` is now strict-only (no type conversion). Code that previously relied on `as<T>()` for permissive conversion (e.g., `any.as<std::string>()` from a String object, or `any.as<DLDataType>()` from a string) must switch to `try_cast<T>()` or `cast<T>()`. Test updates in test_string.cc and test_dtype.cc confirm this.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- TypeTraits protocol (0005): all 8 method names are consumed and 4 are renamed
- Any/AnyView value system (0001): `as<T>()` and `cast<T>()` semantics redefined
- Container element type enforcement (0006): containers switch from `CheckAnyStorage` to `CheckAnyStrict` and from `as<T>()` to `try_cast<T>()` in slow conversion paths

Design elements this commit produces:
- **Three-tier conversion model**: `as` (strict, no conversion) vs `cast` (permissive, throws) vs `try_cast` (permissive, returns optional). This replaces the former two-tier model where `as` was ambiguously permissive.
- **`Any::as<T>() &&` rvalue overload**: new overload enabling move-out semantics for strict type checks on rvalues.
- **`AnyView::try_cast<T>()` and `Any::try_cast<T>()`**: new non-throwing permissive conversion methods filling the gap between strict `as` and throwing `cast`.

## Usage Examples

**Distinguishing strict `as` from permissive `try_cast`** (from `tests/cpp/test_any.cc`):
```cpp
AnyView view0 = 1;                    // stores int

// as<T>() is strict: int != bool, int != double
auto opt_int = view0.as<int64_t>();    // has_value() == true (exact match)
auto opt_bool = view0.as<bool>();      // has_value() == false (strict: int != bool)
auto opt_dbl = view0.as<double>();     // has_value() == false (strict: int != double)

// try_cast<T>() is permissive: allows int->bool, int->double conversion
auto cast_bool = view0.try_cast<bool>();    // has_value() == true, value == 1
auto cast_dbl = view0.try_cast<double>();   // has_value() == true, value == 1.0
```

**Migrating string conversion code** (from `tests/cpp/test_string.cc`):
```cpp
Any b = String("hello");
// Before: b.as<std::string>()      -- worked because as() was permissive
// After:  b.try_cast<std::string>() -- must use try_cast for String->std::string conversion
//         b.as<String>()            -- strict as() still works for exact type match
```
