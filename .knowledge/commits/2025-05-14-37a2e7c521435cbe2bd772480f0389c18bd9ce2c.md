# Distinguish strict `as` from coercing `cast`/`try_cast` in Any/AnyView and TypeTraits

## TL;DR
- `as<T>()` on `AnyView`/`Any` is redefined as a **strict-check-only** operation: it calls `CheckAnyStrict` with no implicit coercion (e.g., `int` stored as `int` never succeeds as `bool` or `double`).
- New `try_cast<T>()` method introduced on both `AnyView` and `Any` as the optional-returning equivalent of `cast<T>()`, delegating to `TryCastFromAnyView` which may apply coercions.
- All `TypeTraits<T>` protocol method names renamed: `CheckAnyStorage` → `CheckAnyStrict`, `TryConvertFromAnyView` → `TryCastFromAnyView`, `CopyFromAnyStorageAfterCheck` → `CopyFromAnyViewAfterCheck`, `MoveFromAnyStorageAfterCheck` → `MoveFromAnyAfterCheck`.

### Rename mapping table

| Old name | New name |
|---|---|
| `TypeTraits<T>::CheckAnyStorage` | `TypeTraits<T>::CheckAnyStrict` |
| `TypeTraits<T>::TryConvertFromAnyView` | `TypeTraits<T>::TryCastFromAnyView` |
| `TypeTraits<T>::CopyFromAnyStorageAfterCheck` | `TypeTraits<T>::CopyFromAnyViewAfterCheck` |
| `TypeTraits<T>::MoveFromAnyStorageAfterCheck` | `TypeTraits<T>::MoveFromAnyAfterCheck` |
| `AnyUnsafe::CheckAnyStorage<T>` | `AnyUnsafe::CheckAnyStrict<T>` |
| `AnyUnsafe::CopyFromAnyStorageAfterCheck<T>` | `AnyUnsafe::CopyFromAnyViewAfterCheck<T>` |
| `AnyUnsafe::MoveFromAnyStorageAfterCheck<T>` | `AnyUnsafe::MoveFromAnyAfterCheck<T>` |
| `AnyView::as<T>()` (was coercing via `TryConvertFromAnyView`) | `AnyView::as<T>()` (now strict via `CheckAnyStrict` + `CopyFromAnyViewAfterCheck`) |
| `AnyView::cast<T>()` (was via `TryConvertFromAnyView`) | `AnyView::cast<T>()` (now via `TryCastFromAnyView`) — behavior preserved |
| N/A | `AnyView::try_cast<T>()` — new optional-returning coercing variant |
| `Any::as<T>() const` (was coercing) | `Any::as<T>() const&` (now strict) + new `Any::as<T>() &&` (rvalue strict) |
| N/A | `Any::try_cast<T>()` — new optional-returning coercing variant |

## Key Exports

```python
class AnyView:
    """Non-owning 16-byte type-erased value. See design-record 0003-any-anyview."""

    def as(self, T: type) -> Optional[T]:
        """Strict reinterpret — returns nullopt if stored type_index doesn't match T.
        No coercions applied (e.g., AnyView holding int -> as<double>() = nullopt).
        Calls TypeTraits[T].CheckAnyStrict() then CopyFromAnyViewAfterCheck().
        # Interacts with: TypeTraits<T>.CheckAnyStrict, TypeTraits<T>.CopyFromAnyViewAfterCheck
        # Invariant: as<T>() succeeds iff CheckAnyStrict(&data_) is true
        """
        ...

    # Object-pointer shortcut (unchanged semantics, updated implementation)
    def as(self, T: type) -> "const T*":  # T must be Object subclass
        """Returns nullptr on type mismatch. Same as as<const T*>().value_or(nullptr).
        # Interacts with: as<const T*>()
        """
        ...

    def try_cast(self, T: type) -> Optional[T]:
        """Coercing optional cast. May apply implicit conversions (e.g., int→float, int→bool).
        Calls TypeTraits[T].TryCastFromAnyView().
        # Interacts with: TypeTraits<T>.TryCastFromAnyView (coercion logic per type)
        # Invariant: if as<T>() succeeds, try_cast<T>() also succeeds
        """
        ...

    def cast(self, T: type) -> T:
        """Coercing throwing cast. Raises TypeError on failure.
        Uses TryCastFromAnyView (same coercion path as try_cast).
        # Invariant: behavior unchanged from before; only underlying method name updated
        """
        ...


class Any(AnyView):
    """Owning type-erased value. See design-record 0003-any-anyview."""

    def as(self, T: type) -> Optional[T]:  # const& overload
        """Strict reinterpret (copy). Like AnyView.as<T>() but also handles T=Any."""
        ...

    def as(self, T: type) -> Optional[T]:  # && overload (new)
        """Strict reinterpret (move). Enables zero-copy extraction when T=Any."""
        ...

    def try_cast(self, T: type) -> Optional[T]:
        """Coercing optional cast. Delegates to TryCastFromAnyView; handles T=Any specially."""
        ...


class TypeTraits(Generic[T]):
    """Customization-point protocol. See design-record 0008-type-traits.
    Updated method names:
    """
    @staticmethod
    def CheckAnyStrict(data: TVMFFIAny*) -> bool:
        """True iff stored type_index exactly matches T's wire representation.
        No coercion. Used by as<T>() and container element invariant checks.
        # Invariant: consistent with MoveToAny/CopyToAnyView — exactly what they write
        """
        ...

    @staticmethod
    def CopyFromAnyViewAfterCheck(data: TVMFFIAny*) -> T:
        """Extract T from Any view, assuming CheckAnyStrict returned True.
        # Invariant: CheckAnyStrict must pass before calling this
        """
        ...

    @staticmethod
    def MoveFromAnyAfterCheck(data: TVMFFIAny*) -> T:
        """Move T out of Any storage, assuming CheckAnyStrict returned True."""
        ...

    @staticmethod
    def TryCastFromAnyView(data: TVMFFIAny*) -> Optional[T]:
        """Try to convert Any to T with implicit coercions (e.g., int→float).
        Returns None if conversion is impossible.
        Used by try_cast<T>() and cast<T>().
        """
        ...
```

## Impact
- API: `AnyView::as<T>()` behavioral change — callers that relied on `as<T>()` for coercing conversions (e.g., calling `as<double>()` on an `int`-typed AnyView) will now get `nullopt` instead. They must switch to `try_cast<T>()`. Internal callers in `function_details.h` and `ndarray.cc` were updated in this commit.
- Behavioral: `cast<T>()` behavior is unchanged (still coercing + throwing). `as<T>()` is now strictly non-coercing. New `try_cast<T>()` fills the "optional coercing" slot.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit **consumes**:
- `AnyView`/`Any` type-erased value containers (0003-any-anyview)
- `TypeTraits<T>` customization-point protocol (0008-type-traits)
- Container element invariant `CheckAnyStorage` (0007-containers)

Design elements this commit **produces/mutates**:
- **Mutates** `TypeTraits<T>` protocol: renames 4 static methods across every built-in specialization and adds semantic distinction between strict and coercing paths
- **Mutates** `AnyView::as<T>()` and `Any::as<T>()`: changes from coercing to strict-only
- **Produces** `AnyView::try_cast<T>()` and `Any::try_cast<T>()`: new methods for optional coercing conversions
- **Produces** `Any::as<T>() &&`: new rvalue-ref overload for strict move-extraction

## Usage Examples

Before/after showing the behavioral split:
```cpp
// Before this commit: as<T>() was coercing (same as cast but returning optional)
AnyView view = 1;         // stores int
view.as<bool>();          // returned Optional<bool>{true}  -- COERCED
view.as<double>();        // returned Optional<double>{1.0} -- COERCED

// After this commit: as<T>() is strict
view.as<int64_t>();       // Optional<int64_t>{1}  -- OK, exact type match
view.as<bool>();          // std::nullopt           -- no coercion
view.as<double>();        // std::nullopt           -- no coercion

// try_cast<T>() fills the old as<T>() coercing role
view.try_cast<bool>();    // Optional<bool>{true}   -- coercion applied
view.try_cast<double>();  // Optional<double>{1.0}  -- coercion applied

// cast<T>() behavior unchanged: coercing + throws on failure
view.cast<double>();      // 1.0  -- unchanged

// Any rvalue strict extraction (new)
Any any = SomeObject();
auto opt = std::move(any).as<SomeObject>(); // moves without extra ref-count
```

From `tests/cpp/test_any.cc` (new `CastVsAs` test):
```cpp
AnyView view0 = 1;
EXPECT_TRUE(view0.as<int64_t>().has_value());   // strict: succeeds
EXPECT_FALSE(view0.as<bool>().has_value());      // strict: fails
EXPECT_FALSE(view0.as<double>().has_value());    // strict: fails
EXPECT_TRUE(view0.try_cast<bool>().has_value()); // coerce: succeeds
EXPECT_TRUE(view0.try_cast<double>().has_value()); // coerce: succeeds
```
