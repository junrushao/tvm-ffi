# Replace ad-hoc DSO discovery with importlib.metadata-based lookup and reusable load_lib_ctypes API
## TL;DR
- Replaces the ad-hoc `base.py` / `get_dll_directories()` library discovery with `importlib.metadata` RECORD-based lookup as the primary strategy in `_find_library_by_basename()`, falling back to environment/build-directory scanning only when metadata is unavailable.
- Introduces `libinfo.load_lib_ctypes(package, target_name, mode)` as a reusable one-liner for downstream packages to locate and load their DSOs via ctypes.
- Deletes `python/tvm_ffi/base.py` entirely; library loading moves to `__init__.py` via `LIB = libinfo.load_lib_ctypes("apache-tvm-ffi", "tvm_ffi", "RTLD_GLOBAL")`.
- Refactors all `find_*` helpers to use a shared `_resolve_and_validate()` pattern with condition callbacks, replacing inline candidate loops.

## Impact
- API: `find_library_by_basename()` renamed to private `_find_library_by_basename()` with a changed signature `(package, target_name)`. `split_env_var()` and `get_dll_directories()` removed from public API. New public `load_lib_ctypes()` and `find_windows_implib()` added. `tvm_ffi.LIB` exposed as public module attribute (replaces `base._LIB`).
- Behavioral: Primary library discovery now uses `importlib.metadata` RECORD parsing instead of directory scanning. Fallback behavior preserved for dev/PYTHONPATH workflows. `find_cython_lib()` simplified from glob-based search to direct `import tvm_ffi.core`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Packaging / library discovery** ([0013-packaging.md](../designs/0013-packaging.md)): Replaces the `get_dll_directories()` + `find_library_by_basename()` pattern with `importlib.metadata` RECORD-based lookup. All `find_*` helpers are refactored to use `_resolve_and_validate()`.
- **Python bindings init sequence** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): The `__init__.py` import chain changes from `from . import base` (which eagerly loaded the DSO) to explicit `libinfo.load_lib_ctypes()`.

Design elements this commit produces:
- **`load_lib_ctypes()` reusable DSO loader** -- A new public API that downstream packages can call to locate and load their own shared libraries that are co-packaged in pip wheels. This is the key new extension point: any package that ships a `.so`/`.dylib`/`.dll` alongside its Python code and registers it in `RECORD` via pip can use this function.
- **`_resolve_and_validate()` internal pattern** -- Unified path-resolution helper with condition callback, replacing per-function candidate loops. Used by all `find_*` functions.
- **`importlib.metadata` RECORD-based discovery** -- Primary strategy for finding DSOs. Parses the `RECORD` file from `importlib.metadata.distribution(package)` to find library file paths, using `dist._path.parent` as the base directory.

## Usage Examples

Loading tvm_ffi's own DSO (from `__init__.py`):
```python
from tvm_ffi import libinfo

# Load libtvm_ffi.{so,dylib,dll} with RTLD_GLOBAL so symbols are available to Cython
LIB = libinfo.load_lib_ctypes("apache-tvm-ffi", "tvm_ffi", "RTLD_GLOBAL")
```

Downstream package loading its own co-packaged DSO:
```python
# In a downstream package's __init__.py:
import tvm_ffi.libinfo

LIB = tvm_ffi.libinfo.load_lib_ctypes("my-package-name", "my_target", "RTLD_LOCAL")
```
