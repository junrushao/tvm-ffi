# Replace ad-hoc DSO discovery with importlib.metadata-based load_lib_ctypes
## TL;DR
- Introduces `tvm_ffi.libinfo.load_lib_ctypes(package, target_name, mode)` as the primary public API for loading shared libraries, using `importlib.metadata` distribution RECORD files as the first-choice discovery mechanism.
- Deletes `python/tvm_ffi/base.py` entirely; DSO loading moves to `__init__.py` via `LIB = libinfo.load_lib_ctypes("apache-tvm-ffi", "tvm_ffi", "RTLD_GLOBAL")`.
- Refactors all `libinfo.py` path-finding functions to use `_resolve_and_validate()` helper and `_rel_top_directory()`/`_dev_top_directory()` helpers, replacing scattered `Path(__file__).resolve().parent / ...` patterns.

## Impact
- API: **Breaking** -- `base.py` deleted, `_LIB` no longer exists. `split_env_var`, `get_dll_directories`, `find_library_by_basename` removed from public API. Downstream code importing `from tvm_ffi.base import _LIB` or `from tvm_ffi.libinfo import find_library_by_basename` will break. `tvm_ffi.LIB` is the new public symbol.
- Behavioral: Library discovery now uses `importlib.metadata.distribution(package).read_text("RECORD")` as the primary mechanism, falling back to directory search. This is more reliable for pip-installed packages since it uses the wheel's recorded file list rather than scanning directories.
- Flags/config: `find_windows_implib()` moved from `config.py` to `libinfo.py`; `config.py` now calls `libinfo.find_windows_implib()`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python package layout** (`.knowledge/designs/0014-python-package.md`) -- the module import flow and `tvm-ffi-config` CLI are directly affected
- **Library discovery order** -- the existing `get_dll_directories()` + `find_libtvm_ffi()` pipeline
- **`importlib.metadata`** (Python stdlib) -- `PathDistribution`, `RECORD` file parsing

Design elements this commit produces:
- **`load_lib_ctypes` public API** -- reusable by downstream libraries to load their DSOs via the same `importlib.metadata`-based discovery
- **`_resolve_and_validate` pattern** -- centralized path resolution with error-safe condition checking, used by all `find_*` functions
- **`importlib.metadata` RECORD-based library discovery** -- a new primary discovery strategy that replaces directory scanning for installed packages

## Usage Examples

Loading a downstream library's DSO using the new API (from commit message):
```python
import tvm_ffi

# For packages shipped with tvm-ffi, load the shared library:
LIB = tvm_ffi.libinfo.load_lib_ctypes("apache-tvm-ffi", "tvm_ffi", "RTLD_LOCAL")

# Parameters:
# - "apache-tvm-ffi": PyPI package name (used for importlib.metadata lookup)
# - "tvm_ffi": CMake target name (derives platform-specific filename)
# - "RTLD_LOCAL": ctypes dlopen mode
```

The `__init__.py` now uses it directly:
```python
from . import libinfo
LIB = libinfo.load_lib_ctypes("apache-tvm-ffi", "tvm_ffi", "RTLD_GLOBAL")
```
