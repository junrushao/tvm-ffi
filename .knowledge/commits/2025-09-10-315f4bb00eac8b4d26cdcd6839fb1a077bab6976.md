# Fix SystemLibrary symbol lookup to handle names that already contain the prefix

## TL;DR
- `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` now try the prefixed name first, then fall back to the raw name, so callers can pass either fully-qualified or logical symbol names.
- Fixes a regression from the `__tvm_ffi_` symbol prefix refactor (commit 40e8a51) where double-prefixing caused lookup failures when callers passed names that already included the prefix.

## Key Exports

**Methods (behavior changed, signatures unchanged)**:
```cpp
class SystemLibrary final : public Library {
  // Now tries symbol_prefix_ + name first, falls back to name alone
  void* GetSymbol(const String& name) final;
  // Now tries tvm_ffi_symbol_prefix + symbol_prefix_ + name first,
  // falls back to tvm_ffi_symbol_prefix + name alone
  void* GetSymbolWithSymbolPrefix(const String& name) final;
};
```

## Impact
- API: none (no signature changes)
- Behavioral: `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` now succeed for names that already contain the prefix, where previously they would fail by double-prefixing. This is a semantic fix, not a new feature.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): `SystemLibrary`, `SystemLibSymbolRegistry`, `Library::GetSymbol`, `Library::GetSymbolWithSymbolPrefix`, `symbol::tvm_ffi_symbol_prefix`.

Design elements this commit produces:
- **Prefix-idempotent lookup invariant**: `SystemLibrary`'s lookup methods are now idempotent with respect to prefix application. Whether the caller passes `"my_kernel"` or `"prefix_my_kernel"`, the symbol is found if it exists in the registry under either form.

## Usage Examples

**Before (broken)**:
```cpp
// Symbol registered as "my_prefix_my_kernel" in SystemLibSymbolRegistry
SystemLibrary lib("my_prefix_");

// Caller passes name without prefix -> works (prepends "my_prefix_")
lib.GetSymbol("my_kernel");  // looks up "my_prefix_my_kernel" -> found

// Caller passes name WITH prefix -> fails (double-prepends "my_prefix_my_prefix_my_kernel")
lib.GetSymbol("my_prefix_my_kernel");  // looks up "my_prefix_my_prefix_my_kernel" -> nullptr
```

**After (fixed)**:
```cpp
// Same scenario, now both work:
lib.GetSymbol("my_kernel");             // tries "my_prefix_my_kernel" -> found
lib.GetSymbol("my_prefix_my_kernel");   // tries "my_prefix_my_prefix_my_kernel" -> nullptr,
                                         // falls back to "my_prefix_my_kernel" -> found
```
