# Fix SystemLibrary symbol lookup to fall back to unprefixed name
## TL;DR
- `SystemLibrary::GetSymbol` now tries `symbol_prefix_ + name` first, then falls back to `name` alone, fixing cases where the caller already includes the prefix in the name.
- `SystemLibrary::GetSymbolWithSymbolPrefix` similarly tries the fully-prefixed name (`__tvm_ffi_ + symbol_prefix_ + name`) first, then falls back to `__tvm_ffi_ + name`, handling callers that already embed the symbol prefix.

## Key Exports
**Methods (changed behavior, signatures unchanged)**:

- `SystemLibrary::GetSymbol(const String& name) -> void*` -- now performs a two-step lookup: first `symbol_prefix_ + name`, then `name` alone if the first returns `nullptr`.
- `SystemLibrary::GetSymbolWithSymbolPrefix(const String& name) -> void*` -- now performs a two-step lookup: first `tvm_ffi_symbol_prefix + symbol_prefix_ + name`, then `tvm_ffi_symbol_prefix + name` alone if the first returns `nullptr`.

## Impact
- API: none -- no signature changes.
- ABI: none -- internal implementation change only; `Library` has no `_type_key` and is not part of the public ABI.
- Behavioral: Symbols registered with their prefix already included (e.g., registered as `"prefix_foo"` instead of `"foo"` with prefix `"prefix_"`) will now resolve correctly. Previously, lookups would construct the doubled key `"prefix_prefix_foo"` and fail silently (return `nullptr`).
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **SystemLibrary** (`.knowledge/designs/0013-module-system.md` > SystemLibrary) -- the `Library` subclass backed by a static symbol registry with optional prefix matching.
- **SystemLibSymbolRegistry** -- global singleton `Map<String, void*>` used by `SystemLibrary` to resolve symbols.
- **Library::GetSymbolWithSymbolPrefix** (`.knowledge/designs/0013-module-system.md` > Library) -- virtual method with a default implementation that prepends `tvm_ffi_symbol_prefix`; `SystemLibrary` overrides it to handle its own `symbol_prefix_` layered on top.
- **symbol::tvm_ffi_symbol_prefix** (`"__tvm_ffi_"`) -- constant prefix for FFI function symbols (defined in `include/tvm/ffi/extra/module.h:246`).

Design elements this commit produces:
- None new. This commit changes the **contract** of `SystemLibrary::GetSymbol` and `SystemLibrary::GetSymbolWithSymbolPrefix` -- both now tolerate callers that pass names with or without the prefix already included. This is a behavioral relaxation (accepts a superset of inputs), not a new design element.

## Usage Examples
**Before (bug)**: A symbol registered as `"myprefix_my_kernel"` with a `SystemLibrary` created for prefix `"myprefix_"` would fail to resolve:
```cpp
// Registered with full prefixed name
TVMFFIEnvModRegisterSystemLibSymbol("myprefix_my_kernel", &impl);

// Caller passes name that already includes prefix
Module syslib = get_syslib("myprefix_").cast<Module>();
auto f = syslib->GetFunction("myprefix_my_kernel");
// Before fix: looked up "myprefix_myprefix_my_kernel" -> nullptr (FAIL)
```

**After (fix)**: The same lookup succeeds because `GetSymbol` falls back to the unprefixed query:
```cpp
// Same setup as above
auto f = syslib->GetFunction("myprefix_my_kernel");
// After fix: tries "myprefix_myprefix_my_kernel" (miss), then "myprefix_my_kernel" (HIT)
```
