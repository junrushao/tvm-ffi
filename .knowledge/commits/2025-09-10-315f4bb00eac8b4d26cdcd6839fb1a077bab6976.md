# Fix SystemLibrary symbol lookup to try both prefixed and unprefixed names
## TL;DR
- `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` now fall back to looking up the unprefixed name when the prefixed name is not found in the registry.
- Fixes a bug where symbols that were already registered with the prefix baked in would fail lookup because the prefix was doubled.

## Key Exports

```python
class SystemLibrary(Library):
    """Statically-registered symbol table backed by SystemLibSymbolRegistry."""

    def GetSymbol(self, name: str) -> void_ptr:
        """Look up symbol, trying prefixed name first, then raw name."""
        # Before fix: return reg.GetSymbol(symbol_prefix_ + name)
        # After fix:  try reg.GetSymbol(symbol_prefix_ + name), fall back to reg.GetSymbol(name)
        # Invariant: returns first non-null match; callers may pass name with or without prefix
        # Interacts with: SystemLibSymbolRegistry.GetSymbol, LibraryModuleObj.GetFunction
        ...

    def GetSymbolWithSymbolPrefix(self, name: str) -> void_ptr:
        """Look up symbol with tvm_ffi_symbol_prefix, trying full prefix first, then partial."""
        # Before fix: return reg.GetSymbol("__tvm_ffi_" + symbol_prefix_ + name)
        # After fix:  try reg.GetSymbol("__tvm_ffi_" + symbol_prefix_ + name),
        #             fall back to reg.GetSymbol("__tvm_ffi_" + name)
        # Invariant: returns first non-null match; handles names that already embed symbol_prefix_
        # Interacts with: symbol::tvm_ffi_symbol_prefix ("__tvm_ffi_"), LibraryModuleObj.GetFunction
        ...
```

## Impact
- API: None -- no signature changes; behavior is backward-compatible (previously successful lookups still succeed first).
- Behavioral: Symbol lookups that previously failed due to double-prefixing now succeed via the fallback path.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `SystemLibSymbolRegistry` global singleton and its `GetSymbol` method (0011-module-system)
- `Library` abstract interface with `GetSymbol`/`GetSymbolWithSymbolPrefix` virtual methods (0011-module-system)
- `symbol::tvm_ffi_symbol_prefix` constant (`"__tvm_ffi_"`) (0011-module-system)

Design elements this commit produces:
- None -- no new types or interfaces. This tightens the lookup contract on `SystemLibrary` by relaxing its assumption about whether incoming names include the prefix.

## Usage Examples
Before/after pattern showing the bug scenario:

```cpp
// Setup: a symbol registered WITH the prefix already baked in
SystemLibSymbolRegistry::Global()->RegisterSymbol("my_prefix_func_name", some_ptr);

// SystemLibrary created with symbol_prefix_ = "my_prefix_"
auto lib = make_object<SystemLibrary>("my_prefix_");

// BEFORE fix: GetSymbol("func_name") tries "my_prefix_func_name" -> works
//             GetSymbol("my_prefix_func_name") tries "my_prefix_my_prefix_func_name" -> FAILS (nullptr)

// AFTER fix:  GetSymbol("my_prefix_func_name") tries "my_prefix_my_prefix_func_name" -> miss,
//             falls back to "my_prefix_func_name" -> works
```
