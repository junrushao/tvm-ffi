# Fix SystemLibrary symbol lookup to handle pre-prefixed names
## TL;DR
- `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` previously failed when the caller-provided name already contained the symbol prefix, because both methods unconditionally prepended the prefix, producing double-prefixed keys.
- Both methods now try the prefixed form first, then fall back to looking up the name as-is (or with only `tvm_ffi_symbol_prefix` for `GetSymbolWithSymbolPrefix`), making lookup succeed regardless of whether the caller pre-applied the prefix.

## Key Exports
No new public API. Behavioral fix to existing `SystemLibrary` virtual method overrides.

```python
class SystemLibrary(Library):
    """Static symbol table for embedded/AOT scenarios."""
    symbol_prefix_: str  # e.g., "" or "mylib_"

    def GetSymbol(self, name: str) -> Optional[void_ptr]:
        # OLD: return reg.GetSymbol(symbol_prefix_ + name)
        # NEW: try symbol_prefix_ + name first, fall back to bare name
        # Invariant: succeeds whether name is "foo" or "prefix_foo"
        # Interacts with: SystemLibSymbolRegistry.GetSymbol
        ...

    def GetSymbolWithSymbolPrefix(self, name: str) -> Optional[void_ptr]:
        # OLD: return reg.GetSymbol("__tvm_ffi_" + symbol_prefix_ + name)
        # NEW: try "__tvm_ffi_" + symbol_prefix_ + name first, fall back to "__tvm_ffi_" + name
        # Invariant: succeeds whether name already includes symbol_prefix_ or not
        # Interacts with: symbol::tvm_ffi_symbol_prefix ("__tvm_ffi_"), SystemLibSymbolRegistry.GetSymbol
        ...
```

## Impact
- API: None -- no signature changes.
- Behavioral: `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` now succeed for names that already contain the symbol prefix, where they previously returned `nullptr`.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
Before/after pattern showing the incorrect vs corrected behavior:

```cpp
// Scenario: AOT-compiled code registers symbol with full prefix at static init:
//   TVMFFIEnvModRegisterSystemLibSymbol("myprefix_my_func", ptr);
//
// Then SystemLibrary is created with symbol_prefix_ = "myprefix_":
//   auto lib = make_object<SystemLibrary>("myprefix_");

// BEFORE (bug): caller passes name that already includes prefix
// lib->GetSymbol("myprefix_my_func")
//   -> looks up "myprefix_myprefix_my_func" -> nullptr (FAIL)

// AFTER (fix): falls back to bare name
// lib->GetSymbol("myprefix_my_func")
//   -> tries "myprefix_myprefix_my_func" -> nullptr
//   -> falls back to "myprefix_my_func" -> found (OK)

// Similarly for GetSymbolWithSymbolPrefix:
// BEFORE: lib->GetSymbolWithSymbolPrefix("my_func")
//   -> looks up "__tvm_ffi_myprefix_my_func" only
// AFTER:  tries "__tvm_ffi_myprefix_my_func" first,
//         falls back to "__tvm_ffi_my_func" if not found
```
