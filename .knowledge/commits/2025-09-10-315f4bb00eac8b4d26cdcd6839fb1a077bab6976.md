# Fix SystemLibrary symbol lookup to fall back to unprefixed name
## TL;DR
- `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` now try the prefixed name first, then fall back to the unprefixed name if not found.
- Fixes lookups where the caller-provided `name` already includes the `symbol_prefix_` or `tvm_ffi_symbol_prefix`, which previously caused double-prefixing and a failed lookup.

## Key Exports

```python
class SystemLibrary(Library):
    """Static symbol table for ahead-of-time compiled modules."""
    symbol_prefix_: str

    def GetSymbol(self, name: String) -> void_ptr: ...
        # OLD: return reg_.GetSymbol(symbol_prefix_ + name)
        # NEW: try reg_.GetSymbol(symbol_prefix_ + name); if nullptr, try reg_.GetSymbol(name)
        # Invariant: returns non-null if name is registered under either prefixed or unprefixed key
        # Interacts with: SystemLibSymbolRegistry.Global()

    def GetSymbolWithSymbolPrefix(self, name: String) -> void_ptr: ...
        # OLD: return reg_.GetSymbol("__tvm_ffi_" + symbol_prefix_ + name)
        # NEW: try reg_.GetSymbol("__tvm_ffi_" + symbol_prefix_ + name);
        #      if nullptr, try reg_.GetSymbol("__tvm_ffi_" + name)
        # Invariant: returns non-null if name is registered under either fully-prefixed or partially-prefixed key
        # Interacts with: symbol::tvm_ffi_symbol_prefix ("__tvm_ffi_"), SystemLibSymbolRegistry.Global()
```

## Impact
- API: None -- no signature changes, only behavioral.
- Behavioral: `SystemLibrary::GetSymbol` and `GetSymbolWithSymbolPrefix` now succeed in cases where `name` already contains the prefix. Previously these returned nullptr (symbol not found) due to double-prefixing.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
**Before (broken)**: Caller passes `name = "symbol_prefix_foo"` which already contains the prefix. `GetSymbol` constructs `symbol_prefix_ + "symbol_prefix_foo"` = double-prefixed key. Lookup fails, returns nullptr.

**After (fixed)**: `GetSymbol` first tries the double-prefixed key. If that returns nullptr, it tries just `name` as-is. The unprefixed lookup succeeds because `name` already contains the correct prefix.

```cpp
// SystemLibrary with symbol_prefix_ = "mylib_"
// Registry contains: "mylib_compute" -> 0xABCD

// Case 1: name without prefix (works before and after)
lib->GetSymbol("compute");  // tries "mylib_compute" -> found

// Case 2: name already has prefix (broken before, fixed after)
lib->GetSymbol("mylib_compute");  // tries "mylib_mylib_compute" -> nullptr
                                   // then tries "mylib_compute" -> found
```
