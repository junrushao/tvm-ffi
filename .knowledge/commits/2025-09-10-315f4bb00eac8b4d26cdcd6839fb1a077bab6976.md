# Fix SystemLibrary symbol lookup to handle names with or without prefix

## TL;DR
- `SystemLibrary::GetSymbol` and `SystemLibrary::GetSymbolWithSymbolPrefix` now try the prefixed name first, then fall back to the unprefixed name, since callers may or may not already include the symbol prefix.
- Fixes a lookup failure where a symbol registered without the `__tvm_ffi_` prefix was not found by `SystemLibrary`.

## Key Exports

```python
# SystemLibrary::GetSymbol(name: String) -> void*
# Behavior change: tries `symbol_prefix_ + name` first; falls back to `name`.
# Invariant: at least one of the two lookups must succeed for the symbol to be returned.

# SystemLibrary::GetSymbolWithSymbolPrefix(name: String) -> void*
# Behavior change: tries `tvm_ffi_symbol_prefix + symbol_prefix_ + name` first,
# then falls back to `tvm_ffi_symbol_prefix + name`.
# Invariant: ensures __tvm_ffi_ prefix is always tried, but also handles partially-prefixed names.
```

## Impact
- API: None — internal `Library` virtual method implementation change.
- Behavioral: Before: system lib lookup failed if name already included or excluded the prefix. After: both forms accepted.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

Before (broken):
```cpp
// If symbol registered as "my_func" (without __tvm_ffi_ prefix),
// GetSymbol("my_func") with symbol_prefix_="" would try "__tvm_ffi_my_func" only → nullptr.
```
After (fixed):
```cpp
// GetSymbol("my_func") tries "__tvm_ffi_my_func" first, falls back to "my_func" → found.
```
