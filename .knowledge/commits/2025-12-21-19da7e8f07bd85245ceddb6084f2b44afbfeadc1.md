# Revamp Python Packaging documentation, reorganize doc structure, fix Doxygen formatting, and add prefix filtering to stubgen
## TL;DR
- Replaces the Markdown `docs/guides/python_packaging.md` with a comprehensive RST `docs/packaging/python_packaging.rst` covering three checkpoints: exporting C++ to Python (C symbols, functions, classes), building Python wheels (CMake target, pyproject.toml, wheel auditing), and the `tvm-ffi-stubgen` tool (all 8 directive types).
- Reorganizes the doc tree: guides split into Guides (kernel, compiler, language guides), Packaging (python, cpp), Concepts, Reference, and Developer Manual sections. Files renamed with `_lang_guide` suffix and moved to new directories (`docs/dev/`, `docs/packaging/`).
- Fixes ~30 Doxygen `\code` blocks across C++ headers to use `\code{.cpp}` for proper syntax highlighting, removes stale `#include` directives (`<atomic>`, `<memory>`, `<sstream>`, `<string_view>`), and normalizes code example indentation.
- Fixes stubgen `_stage_2` prefix filtering: replaces hardcoded `testing`/`ffi` skip logic with proper `--init-prefix`-based filtering, ensuring only the specified namespace prefix is scaffolded.

## Impact
- API: `--init-path` CLI flag description updated (no longer listed as required alongside `--init-lib` and `--init-prefix`). Stubgen `_stage_2` prefix filtering behavior changed from hardcoded skip list to `--init-prefix`-based filtering.
- Behavioral: Stubgen now correctly filters scaffolded prefixes based on `--init-prefix` instead of skipping all `testing.*` and `ffi.*` prefixes. The `is_root` detection no longer relies on `Path.samefile()` comparison with a constructed path, using string equality with `root_prefix` instead.
- Flags/config: Two new intersphinx sites (`data-api`, `scikit_build_core`). rstcheck config updated to ignore new intersphinx roles. `torch-c-dlpack-ext` install changed from separate section to inline comment (`# compatibility package for torch <= 2.9`).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Packaging workflow** ([0013-packaging.md](../designs/0013-packaging.md)): The new `python_packaging.rst` documents `tvm_ffi_configure_target`, `tvm_ffi_install`, `load_lib_module`, and `init_ffi_api` as the recommended patterns for extension packaging.
- **Reflection system** ([0008-reflection.md](../designs/0008-reflection.md)): The class export section in `python_packaging.rst` documents `ObjectDef<T>`, `def_ro`, `def_rw`, `def`, `def_static`, and `init<>` as the API for registering C++ classes.
- **Module system** ([0011-module-system.md](../designs/0011-module-system.md)): The C symbol export section documents `TVM_FFI_DLL_EXPORT_TYPED_FUNC` and `load_lib_module` as the recommended path for runtime-loaded modules.
- **Stub generation** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): All 8 stubgen directive types are documented in the new RST page. The prefix filtering fix ensures correct behavior with `--init-prefix`.
- **CMake convenience functions** (ccd19f82): `tvm_ffi_configure_target` used throughout the new packaging doc as the recommended CMake integration.

Design elements this commit produces:
- **Reorganized doc structure**: New top-level sections (Guides, Concepts, Packaging, Reference, Developer Manual) in `docs/index.rst`. This establishes the canonical documentation taxonomy going forward.
- **Comprehensive stubgen directive reference**: All 8 directive types (`global/`, `object/`, `import-section`, `export/`, `__all__`, `ty-map`, `import-object`, `skip-file`) documented in a single RST page with inline examples.
- **Prefix-filtered scaffolding invariant**: Stubgen `_stage_2` now enforces that only prefixes matching or nested under `--init-prefix` are scaffolded, replacing the previous ad-hoc skip logic.

## Usage Examples

New `tvm_ffi_configure_target` CMake integration (from `quickstart.rst`):
```cmake
# Before (manual link setup):
target_link_libraries(add_one_cpu PRIVATE tvm_ffi_header)
target_link_libraries(add_one_cpu PRIVATE tvm_ffi_shared)

# After (single call):
tvm_ffi_configure_target(add_one_cpu)
```

Prefix-filtered stub scaffolding (from new test `test_stage_2_filters_prefix_and_marks_root`):
```python
# Only "demo" and "demo.sub" prefixes are scaffolded; "other" is excluded
_stage_2(
    files=[],
    ty_map=_default_ty_map(),
    init_cfg=InitConfig(pkg="demo-pkg", shared_target="demo_shared", prefix="demo."),
    init_path=tmp_path,
    global_funcs={"demo.sub": [...], "demo": [...], "other": [...]},
)
# Result: demo/_ffi_api.py and demo/sub/_ffi_api.py exist; other/_ffi_api.py does not
# Root module (demo/_ffi_api.py) gets LIB = _FFI_LOAD_LIB(...); sub-module does not
```
