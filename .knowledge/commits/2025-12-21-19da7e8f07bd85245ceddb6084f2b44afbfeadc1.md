# Revamp Python packaging docs, reorganize doc structure, fix Doxygen formatting, add intersphinx sites

## TL;DR
- Replaces `docs/guides/python_packaging.md` with a fully rewritten `docs/packaging/python_packaging.rst` (RST format, restructured into three sections: Export C++ to Python, Build Python Wheel, Stub Generation Tool).
- Reorganizes doc tree: moves `build_from_source.md` into `docs/dev/`, renames language guides (`cpp_guide` -> `cpp_lang_guide`, `python_guide` -> `python_lang_guide`, `rust_guide` -> `rust_lang_guide`), moves packaging docs into `docs/packaging/`.
- Fixes Doxygen comment formatting across 10 C++ headers: `\code` -> `\code{.cpp}`, corrects indentation inside code blocks, removes stray blank lines, drops unused `#include` directives (`<atomic>`, `<memory>`, `<sstream>`, `<string_view>`).
- Adds `data-api` and `scikit_build_core` intersphinx mappings in `docs/conf.py`; updates DLPack links from raw URLs to intersphinx cross-references.
- Fixes stubgen `_stage_2` prefix filtering: replaces hardcoded `"testing"/"ffi"` skip logic with proper `prefix_filter` comparison against `init_cfg.prefix`, and simplifies `is_root` detection.

## Key Exports

```python
# stubgen _stage_2 prefix filtering fix (python/tvm_ffi/stub/cli.py)
# Before: hardcoded skip of "testing" and "ffi" prefixes
```

## Impact
- API: None (no public API changes)
- Behavioral: stubgen `_stage_2` now correctly filters prefixes based on `init_cfg.prefix` instead of hardcoded strings. Third-party extensions using `tvm-ffi-stubgen --init-prefix` with custom prefixes will now generate stubs only for matching prefixes.
- Flags/config: None
- Data formats/schemas: None
