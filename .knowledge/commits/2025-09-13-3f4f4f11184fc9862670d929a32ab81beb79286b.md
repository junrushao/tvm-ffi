# Fix strict-aliasing violations in JSON writer/parser fast-math helper functions

## TL;DR
- `json_writer.cc`: Replace `*reinterpret_cast<const uint64_t*>(&x)` with a type-punning union in `FastMathSafeIsNaN` and `FastMathSafeIsInf` to avoid `-Werror=strict-aliasing` errors under `-ffast-math`.
- `json_parser.cc`: Apply the same union-based type-pun fix to `FastMathSafePosInf`, `FastMathSafeNegInf`, and `FastMathSafeNaN`, which construct IEEE 754 doubles from raw 64-bit constants.
- Restores compilation on GCC and other compilers that enforce strict-aliasing when `-ffast-math` (which implies `-fno-signed-zeros` and enables aggressive optimizations) is active.

## Usage Examples

**Before (triggers `-Werror=strict-aliasing` with `-ffast-math`):**
```cpp
// json_writer.cc FastMathSafeIsNaN — old code
uint64_t bits = *reinterpret_cast<const uint64_t*>(&x);  // UB: strict-aliasing violation
```

**After (correct type-pun via union — defined behavior in C99/C++11):**
```cpp
union { double from; uint64_t to; } u;
u.from = x;  // write "from"
uint64_t bits = u.to;  // read "to" — type-punning union is allowed by C standard
```

Same pattern applied symmetrically in `json_parser.cc` for the reverse direction (uint64_t → double):
```cpp
union { uint64_t from; double to; } u;
u.from = 0x7FF0000000000000ULL;
return u.to;  // returns +Inf bit pattern as double
```
