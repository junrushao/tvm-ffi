# Remove kTVMFFISEqHashKindCustomTreeNode enum value and unify custom equal/hash dispatch via TypeAttrColumn lookup
## TL;DR
- Removes the `kTVMFFISEqHashKindCustomTreeNode = 6` enum value from the C ABI (`c_api.h`), eliminating a dedicated dispatch path for custom structural equal/hash. Custom behavior is now detected at runtime by checking whether `__s_equal__`/`__s_hash__` TypeAttrColumn entries are registered, regardless of the `_type_s_eq_hash_kind` setting.
- Adds NaN-aware handling in both `StructEqualHandler::CompareAny` and `StructuralHashHandler::HashAny`: multiple bit representations of NaN are now treated as equal and hash to the same value (using `std::numeric_limits<double>::quiet_NaN()` as canonical form).
- Changes the custom hash callback signature from `(AnyView, bool) -> uint64_t` to `(AnyView, uint64_t, bool) -> uint64_t`, threading `init_hash` through the callback and applying `StableHashCombine` inside the callback rather than requiring the caller to do it.
- Tightens error handling: missing metadata or `kTVMFFISEqHashKindUnsupported` now throws `TypeError` instead of silently falling back to pointer comparison or pointer hash.

## Impact
- API: **Breaking C ABI change** -- `kTVMFFISEqHashKindCustomTreeNode = 6` is removed from `TVMFFISEqHashKind` enum in `c_api.h`. Any downstream code referencing this enum value will fail to compile. The replacement is to set `_type_s_eq_hash_kind = kTVMFFISEqHashKindTreeNode` and register `__s_equal__`/`__s_hash__` via `TypeAttrDef<T>`.
- API: **Custom hash callback signature change** -- `SHash` methods must now accept `(uint64_t init_hash, TypedFunction<uint64_t(AnyView, uint64_t, bool)> hash)` instead of `(uint64_t type_key_hash, TypedFunction<uint64_t(AnyView, bool)> hash)`. The callback now returns the combined hash directly.
- Flags/config: none.
- Data formats/schemas: none.
- Behavioral: Types with `metadata == nullptr` or `_type_s_eq_hash_kind == kTVMFFISEqHashKindUnsupported` that previously silently fell back to pointer-based comparison/hashing now throw `TypeError`. This surfaces configuration errors earlier.

## Design Elements
Design elements this commit **consumes**:

- **TVMFFISEqHashKind enum** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The commit modifies the C ABI enum by removing value `6` (`kTVMFFISEqHashKindCustomTreeNode`). The remaining values `0-5` are unchanged.
- **TypeAttrColumn / TypeAttrDef** (reflection system): The commit relies on `reflection::TypeAttrColumn("__s_equal__")` and `reflection::TypeAttrColumn("__s_hash__")` to dynamically detect whether a type has custom structural equal/hash functions registered. This was introduced in the parent commit chain (`162d600` Introduce TypeAttr, `2ec11f5` Enable custom s_hash/equal).
- **ForEachFieldInfo / ForEachFieldInfoWithEarlyStop** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): Used for the default (non-custom) field-by-field comparison and hashing paths, iterating through the ancestor chain.
- **TVMFFITypeInfo::metadata->structural_eq_hash_kind** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The commit still uses this field to dispatch between `kTVMFFISEqHashKindUniqueInstance`, `kTVMFFISEqHashKindFreeVar`, `kTVMFFISEqHashKindDAGNode`, etc. The change is that `kTVMFFISEqHashKindCustomTreeNode` is no longer a valid value.
- **details::StableHashCombine** (`include/tvm/ffi/reflection/structural_hash.h`): Used in NaN canonicalization and now also inside the custom hash callback.

Design elements this commit **produces**:

- **Unified custom dispatch via TypeAttrColumn**: Instead of a static enum-based dispatch (`_type_s_eq_hash_kind == kTVMFFISEqHashKindCustomTreeNode`), custom structural equal/hash is now detected at runtime: `custom_s_equal[type_info->type_index] != nullptr`. This decouples the "has custom equal/hash" property from the `_type_s_eq_hash_kind` enum, allowing any tree node type to optionally register custom behavior without requiring a separate enum value. This is a new design element not yet documented.
- **NaN canonicalization in structural equal/hash**: A new invariant that `NaN == NaN` for structural equality, and all NaN bit patterns produce the same hash value. This is achieved by checking `std::isnan()` before the POD comparison/hash path and normalizing to `std::numeric_limits<double>::quiet_NaN()` for hashing.
- **Init-hash-threading callback pattern**: The custom hash callback now receives and returns `uint64_t init_hash`, applying `StableHashCombine` internally. This simplifies implementers of `SHash` methods by removing the need to call `StableHashCombine` themselves.

## Key Implementations

### 1. Enum removal (c_api.h)

The `kTVMFFISEqHashKindCustomTreeNode = 6` value and its documentation block (21 lines) are deleted from `TVMFFISEqHashKind`. This is a C ABI surface change.

### 2. NaN handling (structural_equal.cc:55-58, structural_hash.cc:55-61)

In `CompareAny`, when `type_index == kTVMFFIFloat` and `std::isnan(lhs)`, the comparison returns `std::isnan(rhs)` -- bypassing the bitwise `v_int64 == v_int64` comparison that would fail for different NaN representations.

In `HashAny`, a NaN value is canonicalized by copying `src_data` into a local `TVMFFIAny temp` and setting `temp.v_float64 = std::numeric_limits<double>::quiet_NaN()`, then hashing from `temp.v_uint64`. This ensures all NaN bit patterns produce the same hash.

**Invariant enforced**: `StructuralEqual(NaN, NaN) == true` and `StructuralHash(NaN_a) == StructuralHash(NaN_b)` for any two NaN representations.

### 3. Error tightening (structural_equal.cc:98-105, structural_hash.cc:94-103)

Both `CompareObject` and `HashObject` replace silent fallbacks with explicit `TypeError` throws:
- `metadata == nullptr` previously fell back to `same_as()`/`std::hash<const Object*>()` -- now throws.
- `structural_eq_hash_kind == kTVMFFISEqHashKindUnsupported` previously was combined with `kTVMFFISEqHashKindUniqueInstance` -- now throws separately.

**Invariant enforced**: Every object type used in structural equal/hash must have metadata and a non-`Unsupported` kind registered.

### 4. Dynamic custom dispatch (structural_equal.cc:132-133, structural_hash.cc:115-116)

The `TypeAttrColumn` lookup is moved from inside the `else` branch (only reached when `kind == kTVMFFISEqHashKindCustomTreeNode`) to before the branch:

```cpp
static reflection::TypeAttrColumn custom_s_equal = reflection::TypeAttrColumn("__s_equal__");
// ...
if (custom_s_equal[type_info->type_index] == nullptr) {
    // field-by-field comparison
} else {
    // custom comparison
}
```

The `ICHECK` that asserted the attribute was registered is removed because the `nullptr` check now serves as the dispatch condition. If a type has `kTVMFFISEqHashKindTreeNode` but no `__s_equal__` registered, it falls through to the default field iteration.

### 5. Hash callback signature change (structural_hash.cc:139-149, testing_object.h:230-236)

The hash callback now takes three parameters `(AnyView val, uint64_t init_hash, bool def_region)` and returns the combined hash. Previously, `StableHashCombine` was the caller's responsibility. In `TCustomFuncObj::SHash`, this simplifies the implementation:
```cpp
// Before: hash_value = StableHashCombine(hash_value, hash(params, true));
// After:  hash_value = hash(params, hash_value, true);
```

**Extension point**: New custom `SHash` implementations follow the simplified pattern, threading `hash_value` through consecutive `hash()` calls.

## Reflection

### Design docs to write

- **`.knowledge/designs/0009-structural-equal-hash.md`**: Should document the structural equal/hash subsystem as a first-class design element. Content outline: (1) The `TVMFFISEqHashKind` enum values and their dispatch semantics (tree node, DAG node, free var, unique instance, const tree node). (2) The dual-path dispatch: default field iteration via `ForEachFieldInfo` vs custom `__s_equal__`/`__s_hash__` via `TypeAttrColumn`. (3) The NaN canonicalization invariant. (4) The custom callback signatures and the init-hash-threading pattern. This doc would be referenced by future commits that add new types with custom equal/hash, modify the NaN handling, or extend the hash callback signature.

### ADRs to write

- **`.knowledge/ADRs/0011-remove-custom-tree-node-enum.md`**: Decision context: The `kTVMFFISEqHashKindCustomTreeNode` enum value coupled the "has custom equal/hash" property to a static compile-time declaration, requiring each custom type to opt in via both the enum value and the `TypeAttrDef` registration. Alternative considered: keeping the enum value for explicit opt-in (pro: compile-time documentation of intent; con: redundant with the runtime TypeAttrColumn check, and blocks types from optionally having custom behavior). Trade-off: removing the enum simplifies the dispatch logic and makes custom equal/hash purely additive (register the attr and it works), at the cost of losing the compile-time signal.

### Design diagrams to draw

- **Mermaid flowchart**: Structural equal/hash dispatch decision tree. Should depict: `metadata == nullptr` -> TypeError; `kind == Unsupported` -> TypeError; `kind == UniqueInstance` -> pointer compare; `kind in {TreeNode, ConstTreeNode, ...}` -> check `TypeAttrColumn` -> if custom registered, call custom function; else iterate fields via `ForEachFieldInfo`. DAG/FreeVar have separate paths. This diagram would clarify the dispatch logic that is currently only implicit in the code.
