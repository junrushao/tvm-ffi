# Migrate StructuralEqual/Hash dispatch from enum-based to reflection TypeAttrColumn lookup
## TL;DR
- Removes `kTVMFFISEqHashKindCustomTreeNode` (enum value 6) from `TVMFFISEqHashKind` in the C ABI, replacing the enum-dispatch mechanism for custom structural equality/hash with runtime `TypeAttrColumn` lookup of `__s_equal__`/`__s_hash__` attributes.
- Fixes NaN handling in structural equality and hashing: NaN values now compare equal to each other and hash to a canonical representation (`quiet_NaN`), regardless of NaN bit-pattern.
- Changes the `__s_hash__` callback signature from `(AnyView, bool) -> uint64_t` to `(AnyView, uint64_t, bool) -> uint64_t`, making the hash callback responsible for combining with the running hash value.
- Replaces silent fallback behaviors (pointer-equality for missing metadata, identity for unsupported) with explicit `TypeError` throws.

## Key Exports

```python
# === C ABI enum change (c_api.h) ===
class TVMFFISEqHashKind(IntEnum):
    """Structural equality/hash behavior selector per type."""
    kTVMFFISEqHashKindUnsupported = 0
    kTVMFFISEqHashKindTreeNode = 1
    kTVMFFISEqHashKindFreeVar = 2
    kTVMFFISEqHashKindDAGNode = 3
    kTVMFFISEqHashKindConstTreeNode = 4
    kTVMFFISEqHashKindUniqueInstance = 5
    # REMOVED: kTVMFFISEqHashKindCustomTreeNode = 6
    # Invariant: custom eq/hash is now detected via TypeAttrColumn("__s_equal__") != nullptr,
    #   not via this enum.
    # Interacts with: TVMFFITypeMetadata.structural_eq_hash_kind, StructEqualHandler, StructuralHashHandler

# === Custom hash callback signature change ===
# Old: (val: AnyView, def_region: bool) -> uint64_t
# New: (val: AnyView, init_hash: uint64_t, def_region: bool) -> uint64_t
#   The callback now receives and returns the running hash, combining internally
#   via StableHashCombine. Callers no longer manually combine hash results.
# Interacts with: TCustomFuncObj.SHash, any type registering __s_hash__

# === NaN canonicalization (structural_equal.cc, structural_hash.cc) ===
# CompareAny: if type_index == kTVMFFIFloat and isnan(lhs), returns isnan(rhs)
# HashAny: if type_index == kTVMFFIFloat and isnan(src), hashes quiet_NaN() instead
# Invariant: all NaN bit patterns are structurally equal and hash identically
# Interacts with: details::StableHashCombine, TVMFFIAny.v_float64

# === Error behavior change (structural_equal.cc, structural_hash.cc) ===
# Old: missing metadata -> pointer equality (silent fallback)
# New: missing metadata -> TVM_FFI_THROW(TypeError)
# Old: kTVMFFISEqHashKindUnsupported -> pointer comparison
# New: kTVMFFISEqHashKindUnsupported -> TVM_FFI_THROW(TypeError)
# Invariant: types must have metadata and a non-Unsupported eq_hash_kind to participate
```

## Impact
- API: `kTVMFFISEqHashKindCustomTreeNode` (value 6) removed from the C ABI enum. Any C/C++ code setting `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode` must switch to `kTVMFFISEqHashKindTreeNode` and register `__s_equal__`/`__s_hash__` type attributes via reflection.
- Behavioral: (1) Types without metadata or with `kTVMFFISEqHashKindUnsupported` now throw `TypeError` instead of silently falling back to pointer equality. (2) NaN float values are now structurally equal and hash consistently. (3) The `__s_hash__` callback receives an extra `init_hash` parameter and must return the combined hash.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFISEqHashKind` enum in `c_api.h` (see `.knowledge/designs/0001-c-abi.md`) -- removes one variant
- `TypeAttrColumn` from the reflection system (see `.knowledge/designs/0008-reflection.md`) -- used to look up `__s_equal__`/`__s_hash__` per type at runtime instead of dispatching on enum
- `TVMFFITypeMetadata.structural_eq_hash_kind` field -- now checked for `Unsupported` separately from custom-function dispatch
- `details::StableHashCombine` -- now called inside the hash callback rather than by the caller

Design elements this commit produces:
- **Reflection-based custom eq/hash dispatch pattern**: Custom structural equality/hash is now detected by checking `TypeAttrColumn("__s_equal__")[type_index] != nullptr` rather than via a dedicated enum value. This unifies custom eq/hash registration with the general type attribute system.
- **NaN canonicalization invariant**: All NaN bit patterns are treated as structurally equal and hash to `quiet_NaN()`. This is a new invariant for the structural equality/hash system.
- **Hash callback combines running hash**: The `__s_hash__` callback now takes `(val, init_hash, def_region)` and returns the combined hash, encapsulating `StableHashCombine` inside the callback.

## Usage Examples

Before (custom structural eq/hash type):
```cpp
class TCustomFuncObj : public Object {
  // Old: dedicated enum value triggers custom dispatch
  static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode;

  // Old hash callback signature: caller must manually combine hash
  uint64_t SHash(uint64_t type_key_hash,
                 ffi::TypedFunction<uint64_t(AnyView, bool)> hash) const {
    uint64_t hash_value = type_key_hash;
    hash_value = StableHashCombine(hash_value, hash(params, true));
    hash_value = StableHashCombine(hash_value, hash(body, false));
    return hash_value;
  }
};
```

After:
```cpp
class TCustomFuncObj : public Object {
  // New: use TreeNode; custom dispatch detected via __s_hash__ type attr
  static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindTreeNode;

  // New hash callback signature: callback combines internally
  uint64_t SHash(uint64_t init_hash,
                 ffi::TypedFunction<uint64_t(AnyView, uint64_t, bool)> hash) const {
    uint64_t hash_value = init_hash;
    hash_value = hash(params, hash_value, true);
    hash_value = hash(body, hash_value, false);
    return hash_value;
  }
};
```
