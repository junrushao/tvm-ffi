# Migrate StructuralEqual/Hash to reflection-based custom dispatch via TypeAttrColumn
## TL;DR
- Removes the `kTVMFFISEqHashKindCustomTreeNode` enum value (was 6) from the C ABI, replacing the dispatch mechanism with runtime `TypeAttrColumn` lookup of `__s_equal__`/`__s_hash__` attributes.
- Fixes NaN handling in structural equal/hash: all NaN representations now compare equal and hash to the same value.
- Changes custom `__s_hash__` callback signature from `(AnyView, bool) -> uint64` to `(AnyView, uint64, bool) -> uint64`, folding `StableHashCombine` into the callback.
- Replaces silent fallbacks (pointer equality for missing metadata, implicit `same_as` for unsupported) with explicit `TypeError` throws.

## Impact
- API: `kTVMFFISEqHashKindCustomTreeNode` removed from `TVMFFISEqHashKind` enum in `c_api.h`. Any C/C++ code using this enum value will fail to compile. Custom types should now use `kTVMFFISEqHashKindTreeNode` and register `__s_equal__`/`__s_hash__` via `TypeAttrColumn`.
- Behavioral: (1) Types with `kTVMFFISEqHashKindUnsupported` or missing metadata now throw `TypeError` instead of silently falling back to pointer equality/hash. (2) Custom `__s_hash__` callbacks receive an additional `init_hash` parameter and must return the combined hash. (3) NaN float values are now structurally equal regardless of bit representation.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TVMFFISEqHashKind enum** (0007-c-abi): removes value 6, keeps values 0-5.
- **TypeAttrColumn** (0008-reflection): used for runtime lookup of `__s_equal__`/`__s_hash__` functions per type, replacing the enum-driven dispatch.
- **TVMFFITypeInfo.metadata->structural_eq_hash_kind** (0007-c-abi): still used for Unsupported/UniqueInstance/TreeNode dispatch; the custom path is now decoupled.
- **details::StableHashCombine** (ffi internal): now called inside the custom hash callback instead of by the caller.

Design elements this commit produces:
- **Reflection-based custom equal/hash dispatch pattern**: Instead of a dedicated enum value signaling "custom," the handler checks whether a `__s_equal__`/`__s_hash__` TypeAttrColumn entry exists for the type at runtime. This unifies custom handlers with the normal reflection registration pathway.
- **NaN normalization invariant for structural equal/hash**: All NaN bit representations are treated as equal and hash to the same value.

## Usage Examples
Custom hash callback signature change (from test fixture `TCustomFuncObj`):
```cpp
// BEFORE (old callback signature):
uint64_t SHash(uint64_t type_key_hash,
               TypedFunction<uint64_t(AnyView, bool)> hash) const {
    uint64_t hash_value = type_key_hash;
    hash_value = StableHashCombine(hash_value, hash(params, true));
    hash_value = StableHashCombine(hash_value, hash(body, false));
    return hash_value;
}
static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode;

// AFTER (new callback signature -- caller no longer calls StableHashCombine):
uint64_t SHash(uint64_t init_hash,
               TypedFunction<uint64_t(AnyView, uint64_t, bool)> hash) const {
    uint64_t hash_value = init_hash;
    hash_value = hash(params, hash_value, true);
    hash_value = hash(body, hash_value, false);
    return hash_value;
}
static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindTreeNode;
```
