# Unify custom structural-equal/hash dispatch under TypeAttrColumn, remove kTVMFFISEqHashKindCustomTreeNode

## TL;DR
- Removes `kTVMFFISEqHashKindCustomTreeNode` from `TVMFFISEqHashKind`; types that previously used it now set `kTVMFFISEqHashKindTreeNode` and register `__s_equal__`/`__s_hash__` via `TypeAttrDef`.
- Dispatch logic in `StructEqualHandler`/`StructuralHashHandler` is inverted: the custom path triggers when `TypeAttrColumn["__s_equal__"/"__s_hash__"]` is non-null, regardless of `SEqHashKind`, unifying the enum-based and attribute-based registration paths.
- Adds NaN canonicalization in both handlers (`std::isnan` fast-path) and changes the `s_hash_callback_` signature to accept `init_hash` for caller-controlled hash accumulation; also tightens error handling — missing metadata or `kTVMFFISEqHashKindUnsupported` now throws `TypeError` instead of silently falling back to pointer identity.

## Impact
- API: `kTVMFFISEqHashKindCustomTreeNode = 6` removed from `c_api.h` enum — **breaking for any caller that set `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode`** in C++ or read this enum value via the C API. Migration: change to `kTVMFFISEqHashKindTreeNode` and register `__s_equal__`/`__s_hash__` via `TypeAttrDef`.
- Behavioral: (1) NaN floats now have stable structural equality and hash; (2) types with no metadata or `kUnsupported` kind now raise `TypeError` instead of silently using pointer identity/hash; (3) `s_hash_callback_` passes `init_hash` as second argument — custom `__s_hash__` implementations must update their signature.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0001-c-abi` — `TVMFFISEqHashKind` enum, `TVMFFITypeInfo.metadata.structural_eq_hash_kind`
- `0006-reflection` — `TypeAttrColumn`, `TypeAttrDef`, `ObjectDef`; field-level `SEqHashIgnore` and `SEqHashDef` flags

Design elements this commit produces:
- **Unified custom-dispatch protocol for structural equal/hash**: custom functions are now discovered via `TypeAttrColumn("__s_equal__"/"__s_hash__")` lookup at call time, independent of `SEqHashKind`. Any type with `SEqHashKind >= TreeNode` may override default field-reflection-based comparison by registering these attrs. This supersedes `kTVMFFISEqHashKindCustomTreeNode`.
- **Tightened error contract**: both handlers now throw `TypeError` for unknown/unsupported types rather than silently degrading to pointer semantics.
- **NaN equality invariant**: structural equal/hash treat all NaN float values as equivalent.

## Usage Examples

Before (removed pattern — `kTVMFFISEqHashKindCustomTreeNode`):
```cpp
// Old: declare type with CustomTreeNode kind
static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode;

// Old: SHash signature (caller accumulates manually)
uint64_t SHash(uint64_t type_key_hash,
               ffi::TypedFunction<uint64_t(AnyView, bool)> hash) const {
    uint64_t h = type_key_hash;
    h = ffi::details::StableHashCombine(h, hash(params, true));
    h = ffi::details::StableHashCombine(h, hash(body, false));
    return h;
}
```

After (new pattern — `kTVMFFISEqHashKindTreeNode` + `TypeAttrDef`):
```cpp
// New: use TreeNode; __s_equal__/__s_hash__ attrs opt-in to custom dispatch
static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindTreeNode;

// New: SHash signature — callback handles StableHashCombine internally
uint64_t SHash(uint64_t init_hash,
               ffi::TypedFunction<uint64_t(AnyView, uint64_t, bool)> hash) const {
    uint64_t h = init_hash;
    h = hash(params, h, true);   // callback calls StableHashCombine(init_hash, HashAny(val))
    h = hash(body, h, false);
    return h;
}

// Registration
refl::TypeAttrDef<MyObj>()
    .def("__s_equal__", &MyObj::SEqual)
    .def("__s_hash__",  &MyObj::SHash);
```
