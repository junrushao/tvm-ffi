# Cleanup PackedFunc redirections: add TVM_FFI_DLL_EXPORT, TVM_FFI_DLL_EXPORT_TYPED_FUNC, and tvm-namespace Any/AnyView aliases

## TL;DR
- Introduces `TVM_FFI_DLL_EXPORT` macro in `c_api.h` that always marks a symbol as DLL-exported (unlike `TVM_FFI_DLL` which switches between export/import based on `TVM_FFI_EXPORTS`).
- Adds `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function)` macro in `function.h` for exporting typed C++ functions as `extern "C"` symbols using the SafeCallType convention, with automatic argument unpacking.
- Adds `using tvm::ffi::Any; using tvm::ffi::AnyView;` in the `tvm` namespace scope of `any.h`, exposing these core types at the `tvm::` level for downstream usability.

## Key Exports

### `TVM_FFI_DLL_EXPORT` macro (`include/tvm/ffi/c_api.h`)

A new macro defined alongside `TVM_FFI_DLL`. While `TVM_FFI_DLL` conditionally expands to either `dllexport` or `dllimport` on MSVC (depending on `TVM_FFI_EXPORTS`), `TVM_FFI_DLL_EXPORT` always expands to `dllexport` on MSVC, `EMSCRIPTEN_KEEPALIVE` on Emscripten, and `__attribute__((visibility("default")))` on GCC/Clang. This is needed for symbols that must always be exported regardless of whether the translation unit is building the FFI library itself or consuming it.

Platform definitions:
| Platform     | `TVM_FFI_DLL_EXPORT`                        |
|-------------|----------------------------------------------|
| Emscripten  | `EMSCRIPTEN_KEEPALIVE`                       |
| MSVC        | `__declspec(dllexport)` (always, not import) |
| GCC/Clang   | `__attribute__((visibility("default")))`     |

### `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro (`include/tvm/ffi/function.h`)

Exports a typed C++ function or lambda as a `extern "C"` symbol matching `TVMFFISafeCallType` signature. The generated wrapper:

1. Wraps the body in `TVM_FFI_SAFE_CALL_BEGIN()` / `TVM_FFI_SAFE_CALL_END()` for exception-to-error-code translation.
2. Uses `details::FunctionInfo<decltype(Function)>` to deduce return type and argument count.
3. Calls `details::unpack_call<RetType>` to unpack `TVMFFIAny*` args into typed C++ arguments using `TypeTraits`.
4. Marks the symbol with `TVM_FFI_DLL_EXPORT` so it is visible from shared library consumers.

Signature of generated symbol:
```c
int ExportName(void* self, TVMFFIAny* args, int32_t num_args, TVMFFIAny* result);
```

Constraint: `ExportName` and `Function` must be different identifiers (otherwise the macro body would shadow the function with the exported symbol name).

### Namespace using-declarations (`include/tvm/ffi/any.h`)

`Any` and `AnyView` are now accessible as `tvm::Any` and `tvm::AnyView` in addition to their canonical `tvm::ffi::Any` and `tvm::ffi::AnyView` locations. Added via `using tvm::ffi::Any; using tvm::ffi::AnyView;` inside `namespace tvm {}`.

## Impact
- **API**: Adds two new public macros (`TVM_FFI_DLL_EXPORT`, `TVM_FFI_DLL_EXPORT_TYPED_FUNC`) and two namespace aliases (`tvm::Any`, `tvm::AnyView`). No existing API is modified or removed.
- **ABI**: No ABI breakage. The new macros generate new symbols only when used by downstream code; existing symbols are unchanged.
- **Migration path**: This commit is a preparatory step for removing the legacy `TVM_DLL_EXPORT_TYPED_FUNC` macro from the main TVM repository. Downstream bindings can migrate to `TVM_FFI_DLL_EXPORT_TYPED_FUNC` and then the old macro can be deleted.

## Design Elements
Design elements this commit consumes:
- `TVMFFISafeCallType` calling convention (from C ABI layer).
- `details::FunctionInfo<F>` and `details::unpack_call<RetType>` from `function_details.h`.
- `TVM_FFI_SAFE_CALL_BEGIN/END` exception boundary macros.
- `TVM_FFI_DLL` platform-conditional visibility macro.

Design elements this commit produces:
- **`TVM_FFI_DLL_EXPORT`** -- An "always-export" visibility macro, complementing `TVM_FFI_DLL` which is import-or-export. Needed by module/kernel library authors who export symbols from their own shared libraries.
- **`TVM_FFI_DLL_EXPORT_TYPED_FUNC`** -- Macro for exporting typed C++ functions through the C ABI without manually writing the SafeCallType wrapper. Bridges the gap between typed C++ code and the packed calling convention for shared library exports.
- **`tvm::Any` / `tvm::AnyView` aliases** -- Namespace convenience for downstream users who work in `namespace tvm` rather than `namespace tvm::ffi`.

## Usage Examples

### Exporting a typed function from a shared library
```cpp
int AddOne_(int x) {
  return x + 1;
}

// Generates: extern "C" TVM_FFI_DLL_EXPORT int AddOne(void*, TVMFFIAny*, int32_t, TVMFFIAny*)
TVM_FFI_DLL_EXPORT_TYPED_FUNC(AddOne, AddOne_);

// Also works with lambdas:
TVM_FFI_DLL_EXPORT_TYPED_FUNC(SubOne, [](int x) {
  return x - 1;
});
```

### Using tvm::Any directly
```cpp
namespace tvm {
// Before this commit: requires ffi::Any or a using-declaration
// After this commit: tvm::Any is directly available
Any x = 42;
AnyView view = x;
}
```
