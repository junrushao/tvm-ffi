# Auto-wire __init__ from C++ reflection in register_object and stubgen

## TL;DR
- `register_object._register()` now calls `_install_init(cls, enabled=True)` after `_add_class_attrs`, so any class with `__ffi_init__` from C++ gets `__init__` wired automatically — no `@c_class` required.
- New `InitFieldInfo` dataclass and `ObjectInfo.gen_init()` in `stub/utils.py` walk the TypeInfo parent chain to collect `c_init`/`c_kw_only`/`c_has_default` flags and emit typed `__init__` stubs in `TYPE_CHECKING` blocks.
- `_install_init` guard softened: classes without `__ffi_init__` now silently skip (no `TypeError` guard) unless `enabled=False` is explicitly passed.

## Impact
- API: `register_object` now auto-installs `__init__` when `__ffi_init__` exists; previously required `@c_class`. Existing code using `@c_class` is unaffected. Classes without `__ffi_init__` no longer get a TypeError guard (softened behavior).
- Behavioral: `IntPair(1, 2)` works with just `@register_object("...")` now. `_install_init` no longer raises an error for classes that have no `__ffi_init__` (backward-compatible).
- Flags/config: `refl::init()` in C++ ObjectDef still controls whether `__ffi_init__` (and thus auto-`__init__`) is available.
- Data formats/schemas: `TypeField` gains `c_init`, `c_kw_only`, `c_has_default` Python-visible attributes.

- `_parse_type_schema()`: utility for parsing TypeSchema from JSON string or dict
- Extended `TypeField` stub: `c_init`, `c_kw_only`, `c_has_default` attributes now surfaced in Python

## Usage Examples

```python
from tvm_ffi.registry import register_object
from tvm_ffi.core import Object

# After this commit: @register_object is sufficient to get auto-__init__
@register_object("test.MyPair")
class MyPair(Object):
    a: int
    b: int
    # C++ ObjectDef registers refl::init<int, int>() → __ffi_init__ with auto_init=True
    # __init__(a: int, b: int) is now installed automatically

pair = MyPair(1, 2)  # works without @c_class
```
