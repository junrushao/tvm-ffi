# Wire __init__ from C++ reflection in register_object; add InitFieldInfo to stubgen

## TL;DR
- `register_object` now calls `_install_init(cls, enabled=True)` so all FFI-registered objects (not just `@c_class`) get a proper Python `__init__` from C++ reflection metadata.
- `ObjectInfo` in stub/utils gains `init_fields: list[InitFieldInfo]`, `has_auto_init`, `has_c_init` to drive `__init__` stub generation.
- `_parse_type_schema` helper added to `stub/utils.py`.

## Key Exports

```python
# python/tvm_ffi/stub/utils.py
@dataclasses.dataclass
class InitFieldInfo:
    """A field that participates in the auto-generated __init__."""
    name: str
    schema: NamedTypeSchema
    kw_only: bool
    has_default: bool
    # Interacts with: ObjectInfo.init_fields, stub codegen

@dataclasses.dataclass
class ObjectInfo:
    # NEW fields:
    init_fields: list[InitFieldInfo]   # fields in __init__ signature
    has_auto_init: bool                # C++ auto-registered __ffi_init__
    has_c_init: bool                   # explicit refl::init<> registered

# python/tvm_ffi/registry.py
# _install_init now called by register_object (not just c_class)
# Guard message: "cannot be constructed directly. Define __init__ or factory method."
```

## Impact
- API: All `@register_object` decorated classes now get auto-generated `__init__`. Previously only `@c_class` classes had this. Stubs will include `__init__` signatures.
- Behavioral: Non-constructable types get a guard `__init__` with descriptive error.
- Flags/config: none
- Data formats/schemas: none
