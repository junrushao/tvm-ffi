# Make CUDA an optional dependency for the torch C DLPack JIT extension
## TL;DR
- Wraps CUDA-specific C++ code (`#include <c10/cuda/CUDAStream.h>`, CUDA stream retrieval in `TorchDLPackFromPyObject`) behind `#ifdef BUILD_WITH_CUDA` guards in the JIT-compiled torch DLPack extension.
- Conditionally adds CUDA include paths and `-DBUILD_WITH_CUDA` flag only when `torch.cuda.is_available()`, allowing the extension to compile and load on CPU-only systems.
- Converts the `test_load_inline_cuda_with_env_tensor_allocator` test from a CUDA-only test to a CPU-only test (`test_load_inline_with_env_tensor_allocator`), removing the CUDA kernel and replacing it with a simple CPU loop.

## Key Exports
None -- no new public API surface. The existing `TorchDLPackFromPyObject`, `TorchDLPackToPyObject`, and `TorchDLPackTensorAllocator` C++ functions retain their signatures. The conditional compilation is internal to the JIT-compiled extension.

One minor rename:
| Old | New | Location |
|-----|-----|----------|
| `name="to_dlpack"` (inline module name) | `name="c_dlpack"` | `_optional_torch_c_dlpack.py` line 391 |

## Impact
- API: None -- no signature or behavioral changes to public APIs.
- Behavioral: `TorchDLPackFromPyObject` no longer retrieves the CUDA stream when built without CUDA. This is a no-op on CPU-only builds since `tensor.is_cuda()` would always be false. On CUDA-available builds, behavior is unchanged (`BUILD_WITH_CUDA` is defined).
- Flags/config: New compile-time flag `BUILD_WITH_CUDA` controls CUDA codepaths in the JIT extension. Set automatically based on `torch.cuda.is_available()`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Custom DLPack speed-converters protocol** ([0015-python-ffi-call-dispatch.md](../designs/0015-python-ffi-call-dispatch.md)): The `__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__` dunders set on `torch.Tensor` remain unchanged.
- **`libinfo.include_paths()`** ([0014-python-package.md](../designs/0014-python-package.md)): Used to locate TVM FFI headers for JIT compilation.
- **`torch.utils.cpp_extension.load_inline`**: External PyTorch API for JIT-compiling C++ extensions.
- **`TVMFFIEnvGetTensorAllocator` / `TVMFFIEnvGetStream`** (C env APIs): Referenced in the test's inline C++ source for tensor allocation and stream retrieval.

Design elements this commit produces:
- None -- this is a pure refactor to make an existing feature work on more platforms.

## Usage Examples
The conditional CUDA detection pattern introduced:
```python
# In _optional_torch_c_dlpack.py — building the JIT extension
include_paths = libinfo.include_paths()
extra_cflags = ["-O3"]

if torch.cuda.is_available():
    include_paths += cpp_extension.include_paths("cuda")
    extra_cflags += ["-DBUILD_WITH_CUDA"]

mod = cpp_extension.load_inline(
    name="c_dlpack",
    cpp_sources=cpp_source,
    extra_cflags=extra_cflags,
    extra_include_paths=include_paths,
    ...
)
```
