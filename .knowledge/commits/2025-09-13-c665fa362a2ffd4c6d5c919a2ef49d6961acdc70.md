# Make torch DLPack extension compile without CUDA by gating CUDA-specific code behind BUILD_WITH_CUDA
## TL;DR
- Guards CUDA-specific includes (`c10/cuda/CUDAStream.h`) and stream-capture code in the JIT-compiled torch DLPack C++ extension behind `#ifdef BUILD_WITH_CUDA`, so the extension compiles on CPU-only torch installations.
- Conditionally passes `-DBUILD_WITH_CUDA` and CUDA include paths only when `torch.cuda.is_available()` returns `True`.
- Rewrites the `test_load_inline_with_env_tensor_allocator` test from a CUDA-only test (using `cuda_sources` + GPU kernel) to a CPU-only test (using `cpp_sources` + scalar loop), removing the CUDA requirement for testing the environment tensor allocator pattern.

## Key Exports
None -- no new public API surfaces. The changes are internal to the JIT extension build and test infrastructure.

## Impact
- API: None
- ABI: None
- Behavioral: The torch DLPack extension now successfully loads on CPU-only torch installations. Previously it would fail at JIT compilation because `c10/cuda/CUDAStream.h` was unconditionally included.
- Flags/config: The JIT-compiled C++ extension now receives `-DBUILD_WITH_CUDA` only when CUDA is available.
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **DLPack fast-path protocol** (`.knowledge/designs/0018-dlpack-fast-path.md`) -- the `TorchDLPackFromPyObject` C function and the `__c_dlpack_from_pyobject__`/`__c_dlpack_to_pyobject__`/`__c_dlpack_tensor_allocator__` class attribute protocol. The CUDA stream capture within `TorchDLPackFromPyObject` is now conditional.
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`) -- uses `torch.utils.cpp_extension.load_inline` for JIT-compiling the DLPack bridge. The `include_paths` and `extra_cflags` are now conditionally assembled.
- **Environment tensor allocator** (`.knowledge/designs/0018-dlpack-fast-path.md`, "Environment Tensor Allocator" section) -- `TVMFFIEnvGetTensorAllocator()` and `Tensor::FromDLPackAlloc` consumed in the rewritten test.

Design elements this commit produces:
- **Conditional CUDA compilation for torch DLPack bridge** -- the pattern of using `BUILD_WITH_CUDA` preprocessor guards in the JIT-compiled torch extension. This is a new convention internal to `_optional_torch_c_dlpack.py` but establishes the pattern for optional CUDA support in JIT extensions.

## Usage Examples
The conditional build logic in `_optional_torch_c_dlpack.py`:
```python
include_paths = libinfo.include_paths()
extra_cflags = ["-O3"]

if torch.cuda.is_available():
    include_paths += cpp_extension.include_paths("cuda")
    extra_cflags += ["-DBUILD_WITH_CUDA"]

mod = cpp_extension.load_inline(
    name="c_dlpack",
    cpp_sources=cpp_source,
    functions=[...],
    extra_cflags=extra_cflags,
    extra_include_paths=include_paths,
)
```
