# Make torch c_dlpack extension optionally depend on CUDA, enabling CPU-only torch environments

## TL;DR
- Guards CUDA-specific C++ code (`#include <c10/cuda/CUDAStream.h>`, CUDA stream retrieval) behind `#ifdef BUILD_WITH_CUDA` in the torch c_dlpack JIT extension, so the extension compiles on CPU-only torch installs.
- Conditionally adds CUDA include paths and `-DBUILD_WITH_CUDA` flag only when `torch.cuda.is_available()` returns True.
- Converts the `test_load_inline_cuda_with_env_tensor_allocator` test from a CUDA-only test to a CPU-only test (`test_load_inline_with_env_tensor_allocator`), replacing the CUDA kernel with a CPU loop.

## Key Exports

None -- this commit does not introduce new public API. It modifies the internal behavior of `load_torch_c_dlpack_extension()` and an existing test.

```python
# Modified internal function (not new, but behavior changed):
def load_torch_c_dlpack_extension() -> Optional[Module]:
    """JIT-compiles torch c_dlpack extension. Now conditionally includes CUDA support."""
    # Before: always included c10/cuda/CUDAStream.h and CUDA include paths
    # After:  only includes CUDA headers/paths when torch.cuda.is_available()
    # Interacts with: torch.utils.cpp_extension.load_inline, libinfo.include_paths()
    # Invariant: extension always compiles if torch is installed (no longer requires CUDA toolkit)
```

## Impact
- API: None -- no public API changes.
- Behavioral: `load_torch_c_dlpack_extension()` now succeeds on CPU-only torch installations. Previously, compilation would fail due to missing `c10/cuda/CUDAStream.h`. CUDA stream capture in `TorchDLPackFromPyObject` is now a no-op on CPU-only builds (the `env_stream` parameter is ignored).
- Flags/config: New compile-time flag `BUILD_WITH_CUDA` controls CUDA code paths in the JIT-compiled extension.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Torch c_dlpack JIT extension** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): The inline C++ source compiled via `torch.utils.cpp_extension.load_inline` that provides fast DLPack conversion between torch tensors and TVM FFI tensors. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **`load_inline` infrastructure** (via `torch.utils.cpp_extension.load_inline`): Used to JIT-compile the extension. See [0011-module-system.md](../designs/0011-module-system.md) for TVM's own `load_inline`.
- **`libinfo.include_paths()`**: Provides TVM FFI header paths for JIT compilation.

Design elements this commit produces:
- **`BUILD_WITH_CUDA` compile guard convention**: A new preprocessor guard pattern for conditionally including CUDA-dependent code in JIT-compiled extensions. This is a minor convention, not a full design element.

## Usage Examples

Before (fails on CPU-only torch):
```python
# load_torch_c_dlpack_extension() would always try to include CUDA headers,
# failing with compilation errors if CUDA toolkit not installed
import tvm_ffi  # triggers _optional_torch_c_dlpack import -> compilation failure
```

After (works on CPU-only torch):
```python
# load_torch_c_dlpack_extension() detects CUDA availability at runtime
import tvm_ffi  # succeeds even without CUDA
# On CPU-only: extension compiles without CUDA stream support
# On CUDA:     extension compiles with full CUDA stream support (-DBUILD_WITH_CUDA)
```
