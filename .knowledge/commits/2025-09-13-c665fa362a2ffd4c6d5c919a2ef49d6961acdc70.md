# Make torch C DLPack extension optionally depend on CUDA, falling back to CPU-only build

## TL;DR
- `load_torch_c_dlpack_extension()` now gates CUDA include paths and `BUILD_WITH_CUDA` define on `torch.cuda.is_available()`, so it compiles successfully without a CUDA toolkit.
- The C++ source guards `#include <c10/cuda/CUDAStream.h>` and all `at::cuda::` calls with `#ifdef BUILD_WITH_CUDA`.
- Renames the compiled extension from `"to_dlpack"` to `"c_dlpack"`.
- Test file updated to avoid CUDA-specific tests in CPU-only environments.

## Impact
- API: Internal extension name changed from `"to_dlpack"` to `"c_dlpack"` (cache directory may differ).
- Behavioral: Library now builds and loads on machines without CUDA. CUDA stream extraction only active when `BUILD_WITH_CUDA` defined.
- Flags/config: `-DBUILD_WITH_CUDA` compile flag controls CUDA code paths.
