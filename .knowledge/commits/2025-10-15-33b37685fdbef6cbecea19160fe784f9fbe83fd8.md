# Hide libbacktrace symbols from shared library exports via -fvisibility=hidden
## TL;DR
- Adds `-fvisibility=hidden -fvisibility-inlines-hidden` to the `CFLAGS` passed to libbacktrace's autoconf `./configure` when building with GCC, Clang, or AppleClang.
- This prevents libbacktrace's internal symbols from leaking into the public symbol table of `libtvm_ffi.so`, since libbacktrace is statically linked and only used internally.

## Key Exports
None

## Impact
- API: None
- ABI: None. libbacktrace is statically linked into the TVM FFI shared library; hiding its symbols removes them from the dynamic symbol table but does not change any public API or ABI surface.
- Behavioral: On GCC/Clang/AppleClang, libbacktrace symbols (e.g., `backtrace_create_state`, `backtrace_full`) are no longer visible in `nm -D libtvm_ffi.so`. This reduces the risk of symbol collisions when the host application or another library also links libbacktrace.
- Flags/config: None. The change is automatic for the supported compilers; no new CMake option is introduced.
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **libbacktrace build integration** (`cmake/Utils/AddLibbacktrace.cmake`): The existing `ExternalProject_Add` pattern that compiles libbacktrace as a static library via autotools, documented in `.knowledge/designs/error-handling.md` (line 172: `TVM_FFI_USE_LIBBACKTRACE`).
- **Symbol visibility strategy**: The TVM FFI shared library already uses `TVM_FFI_DLL_EXPORT` / `-fvisibility=hidden` for its own C++ code (documented in `.knowledge/designs/c-abi.md`). This commit extends the same discipline to the vendored libbacktrace dependency.

Design elements this commit produces:
- **libbacktrace symbol hiding**: The `AddLibbacktrace.cmake` module now conditionally appends `-fvisibility=hidden -fvisibility-inlines-hidden` to `CFLAGS`, ensuring all libbacktrace symbols are hidden when statically linked into the shared library.
