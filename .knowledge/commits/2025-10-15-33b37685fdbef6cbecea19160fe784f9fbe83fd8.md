# Hide libbacktrace symbols via -fvisibility=hidden in CMake ExternalProject build
## TL;DR
- Adds `-fvisibility=hidden -fvisibility-inlines-hidden` to CFLAGS when compiling the vendored libbacktrace ExternalProject, preventing its internal symbols from leaking into the `tvm_ffi_shared` shared library.
- Compiler-guarded: flags only apply for GCC, Clang, and AppleClang (not MSVC, which already does not build libbacktrace).

## Key Exports
N/A -- infrastructure

## Impact
- API: none
- Behavioral: libbacktrace symbols (e.g., `backtrace_create_state`, `backtrace_full`) are no longer visible in the dynamic symbol table of `libtvm_ffi.so`/`.dylib`. Consumers that previously (accidentally) linked against these symbols through the shared library will no longer find them. This is intentional -- libbacktrace is an internal dependency.
- Flags/config: new CMake variable `symbol_hiding_flags` (local to `_libbacktrace_compile` function scope) conditionally set based on `CMAKE_C_COMPILER_ID`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Error protocol / libbacktrace integration** (`0005-ffi-error-protocol`): libbacktrace is the backtrace capture backend for `TVMFFIBacktrace`. This commit does not change that relationship, only controls symbol visibility of the statically linked library.
- **Packaging / CMake build** (`0013-ffi-packaging-and-distribution`): the `AddLibbacktrace.cmake` module is part of the CMake build infrastructure for the shared library.
