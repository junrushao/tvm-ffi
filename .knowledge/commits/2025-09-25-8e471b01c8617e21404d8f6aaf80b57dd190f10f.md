# Fix Cython read-after-free in _type_info_create_from_type_key by extending ByteArrayArg lifetime
## TL;DR
- Fixes a use-after-free bug in `_type_info_create_from_type_key` (object.pxi) where a temporary `ByteArrayArg` was destroyed before `TVMFFITypeKeyToIndex` could read its data pointer.
- The `ByteArrayArg` wrapping the type key string is now assigned to a named `cdef` local variable, extending its lifetime to cover the entire function scope.
- Bug was detected by AddressSanitizer (ASan): READ of freed 9-byte region inside the `ByteArrayArg`'s backing bytes buffer.

## Key Exports
None. This commit changes no public API surface. It fixes the lifetime of an internal temporary in a single Cython function.

## Impact
- API: None
- ABI: None
- Behavioral: Eliminates a read-after-free that could cause intermittent crashes or silent data corruption during object type registration (`register_object` / `_type_info_create_from_type_key`). The bug was non-deterministic -- it depended on whether the freed memory had been reused.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **`ByteArrayArg` (Cython helper class, `base.pxi:337`)**: Wraps a Python `bytes` object and exposes a `TVMFFIByteArray*` pointer for passing to C API functions. The class stores both `py_data` (to prevent GC) and `cdata` (the C struct with `data` pointer and `size`). The invariant is that the `ByteArrayArg` instance must outlive any use of the pointer returned by `.cptr()`. This commit fixes a violation of that invariant.
- **`TVMFFITypeKeyToIndex` (C API, `c_api.h`)**: Takes a `TVMFFIByteArray*` type key and resolves it to a `int32_t` type index. Reads the byte array's `data` pointer during execution -- the backing memory must remain valid.
- **`_type_info_create_from_type_key` (Cython, `object.pxi:297`)**: Called by `register_object` to resolve a type key, fetch `TVMFFITypeInfo`, and populate Python class attributes via reflection. This is the function fixed by this commit.
- **Cython temporary object lifetime semantics**: In Cython, an anonymous temporary (`ByteArrayArg(c_str(type_key))`) used inline as a function argument may be destroyed immediately after the expression completes, before the C function that received the pointer finishes executing. Assigning to a named `cdef` variable extends the lifetime to the enclosing scope.

Design elements this commit produces:
- None. This is a bugfix that restores the intended invariant (ByteArrayArg outlives pointer usage) rather than introducing new design elements.

## Usage Examples
**Before (buggy)**:
```cython
# The ByteArrayArg temporary is destroyed immediately after .cptr() returns,
# leaving TVMFFITypeKeyToIndex with a dangling pointer.
if TVMFFITypeKeyToIndex(ByteArrayArg(c_str(type_key)).cptr(), &type_index) != 0:
    raise ValueError(f"Cannot find type key: {type_key}")
```

**After (fixed)**:
```cython
# Named variable extends ByteArrayArg lifetime to function scope.
cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))

if TVMFFITypeKeyToIndex(type_key_arg.cptr(), &type_index) != 0:
    raise ValueError(f"Cannot find type key: {type_key}")
```
