# Fix Cython read-after-free in _type_info_create_from_type_key by binding ByteArrayArg temporary to a named variable

## TL;DR

- `ByteArrayArg(c_str(type_key)).cptr()` in `_type_info_create_from_type_key` created a temporary `ByteArrayArg` that Cython's ref-counting destroyed immediately after `.cptr()` returned, causing a read-after-free when `TVMFFITypeKeyToIndex` accessed the dangling `TVMFFIByteArray*` pointer.
- Fix binds the temporary to a `cdef ByteArrayArg type_key_arg` local variable, ensuring it outlives the C call.
- Identical safe pattern already existed in the sibling function `_type_key_to_index` (line 243); this commit brings `_type_info_create_from_type_key` into alignment.

## Key Exports

```python
# No new exports. Invariant restored:
# ByteArrayArg objects MUST be kept alive (assigned to a named cdef variable)
# for the entire duration of any C call that uses their cptr() return value.
#
# Invariant: ByteArrayArg.cptr() returns a raw pointer into self.cdata;
#            the pointer is only valid while the ByteArrayArg instance is alive.
# Interacts with: TVMFFITypeKeyToIndex (C ABI), _type_key_to_index (sibling Cython fn)
```

None (bugfix — no new public API)

## Usage Examples

Before (UAF — ByteArrayArg destroyed before TVMFFITypeKeyToIndex runs):
```cython
# BROKEN: temporary destroyed after .cptr() call
if TVMFFITypeKeyToIndex(ByteArrayArg(c_str(type_key)).cptr(), &type_index) != 0:
    raise ValueError(f"Cannot find type key: {type_key}")
```

After (correct — named variable keeps ByteArrayArg alive through the C call):
```cython
cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))
if TVMFFITypeKeyToIndex(type_key_arg.cptr(), &type_index) != 0:
    raise ValueError(f"Cannot find type key: {type_key}")
```

The same correct pattern is used in `_type_key_to_index` (line 243):
```cython
type_key_arg = ByteArrayArg(c_str(type_key))
if TVMFFITypeKeyToIndex(type_key_arg.cptr(), &tidx) == 0:
    ...
```
