# Fix Cython ByteArrayArg use-after-free in _type_info_create_from_type_key
## TL;DR
- Fixes a read-after-free memory corruption in Cython's `_type_info_create_from_type_key` detected by ASan.
- The bug: `ByteArrayArg(c_str(type_key))` was constructed as a temporary expression argument to `TVMFFITypeKeyToIndex`, so Cython destroyed it before the C function read from the pointer.
- The fix: hoist the `ByteArrayArg` into a named `cdef` local variable so its lifetime spans the entire call.

## Key Exports
None — this is a bugfix with no new public API.

## Impact
- API: none
- Behavioral: eliminates non-deterministic read-after-free crash when registering object types via `_type_info_create_from_type_key`
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **ByteArrayArg** (`python/tvm_ffi/cython/base.pxi:337`): Cython `cdef class` that wraps a Python `bytes` object and produces a `TVMFFIByteArray*` pointer for C API calls. Holds `py_data` to prevent GC of the backing buffer. Documented in 0012-python-bindings.
- **TVMFFITypeKeyToIndex** (C ABI, `c_api.h`): Looks up a type index from a type key byte array. Documented in 0007-c-abi.
- **_type_info_create_from_type_key** (`python/tvm_ffi/cython/object.pxi`): Cython function that retrieves field/method metadata for a registered C++ type, used during Python `@register_object` processing. Documented in 0012-python-bindings.

Design elements this commit produces: none (pure bugfix)

## Usage Examples
**Before** (use-after-free):
```python
# Cython: temporary ByteArrayArg destroyed before TVMFFITypeKeyToIndex reads from it
if TVMFFITypeKeyToIndex(ByteArrayArg(c_str(type_key)).cptr(), &type_index) != 0:
    raise ValueError(...)
# ASan: READ of size 9 at freed region
```

**After** (correct lifetime):
```python
# Cython: named cdef variable keeps ByteArrayArg alive through the call
cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))
if TVMFFITypeKeyToIndex(type_key_arg.cptr(), &type_index) != 0:
    raise ValueError(...)
```
