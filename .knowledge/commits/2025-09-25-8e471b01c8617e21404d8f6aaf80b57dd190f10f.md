# Fix read-after-free in Cython _type_info_create_from_type_key by hoisting ByteArrayArg to named variable

## TL;DR
- `_type_info_create_from_type_key` passed a temporary `ByteArrayArg` expression to `TVMFFITypeKeyToIndex`, producing a read-after-free because Cython's generated C destroyed the temporary before or during the call.
- Fix: declare `cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))` and pass `type_key_arg.cptr()` — the object now lives for the full function scope.
- ASan confirmed the corruption at `__pyx_f_4core__type_info_create_from_type_key` line 17731/17732 (freed then read at the same stack frame).

## Design Elements
Design elements this commit consumes:
- `ByteArrayArg` (python/ffi-bindings) — Cython helper wrapping `TVMFFIByteArray` (C struct with `data` pointer + `size`). Lifetime invariant: the `py_data` bytes object and `cdata` pointer must outlive any C call that holds the pointer. Documented in design record 0012-ffi-python-package.
- `TVMFFITypeKeyToIndex` (ffi/c-api) — C ABI function that maps a type-key byte array to a `TVMFFITypeIndex`. Defined in `c_api.h`. Documented in design record 0001-ffi-c-abi.

Design elements this commit produces: None

## Usage Examples

**Before (incorrect):**
```python
# ByteArrayArg temporary destroyed before/during call — read-after-free
if TVMFFITypeKeyToIndex(ByteArrayArg(c_str(type_key)).cptr(), &type_index) != 0:
    raise ValueError(...)
```

**After (correct):**
```python
# ByteArrayArg lifetime tied to function scope
cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))
if TVMFFITypeKeyToIndex(type_key_arg.cptr(), &type_index) != 0:
    raise ValueError(...)
```

**Invariant being restored:** Any `ByteArrayArg` whose `.cptr()` is passed to a C function must remain alive (un-destructed) until after the C function returns. Named `cdef` variables guarantee this; inline temporaries in expressions do not.
