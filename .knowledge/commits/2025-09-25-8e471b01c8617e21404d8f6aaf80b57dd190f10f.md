# Fix Cython ByteArrayArg use-after-free in _type_info_create_from_type_key
## TL;DR
- Fixed a read-after-free memory corruption in `_type_info_create_from_type_key` (Cython `object.pxi`) where a temporary `ByteArrayArg` was destroyed before `TVMFFITypeKeyToIndex` could read its data pointer.
- The fix stores the `ByteArrayArg` in a named `cdef` local variable, extending its lifetime to the function scope.

## Key Exports
None -- no new API surface; this is a lifetime fix for an existing internal function.

## Impact
- API: None
- Behavioral: Eliminates non-deterministic read-after-free when registering Python object types via `register_object()` or calling `_type_info_create_from_type_key` directly. The bug manifested as ASan reports but could cause silent corruption in production.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `ByteArrayArg` (Cython `base.pxi`): wrapper around `TVMFFIByteArray` that holds a Python `bytes` reference and provides `cptr()` to the C-level struct. Documented in `0012-python-bindings.md` evidence matrix (043d9f6 entry).
- `TVMFFITypeKeyToIndex` (C ABI, `c_api.h`): looks up a type_key string in the global type table and returns its type_index. Documented in `.knowledge/designs/0001-c-abi.md`.
- `_type_info_create_from_type_key` (Cython `object.pxi`): internal function that resolves a type_key to a type_index, then reads `TVMFFITypeInfo` to populate field/method descriptors for Python class registration. Consumed by `register_object` flow (`.knowledge/designs/0012-python-bindings.md`).

Design elements this commit produces: None -- purely a lifetime correctness fix.

## Usage Examples
**Before (buggy)**: temporary `ByteArrayArg` destroyed before `TVMFFITypeKeyToIndex` reads the pointer:
```python
# Cython pseudocode -- INCORRECT
# ByteArrayArg(c_str(type_key)) creates a temporary
# .cptr() returns &cdata, then the temporary is destroyed (Py_DECREF on py_data)
# TVMFFITypeKeyToIndex reads from freed memory
if TVMFFITypeKeyToIndex(ByteArrayArg(c_str(type_key)).cptr(), &type_index) != 0:
    raise ValueError(...)
```

**After (fixed)**: named variable keeps `ByteArrayArg` alive through the function scope:
```python
# Cython pseudocode -- CORRECT
cdef ByteArrayArg type_key_arg = ByteArrayArg(c_str(type_key))
# type_key_arg lives until function returns; py_data stays alive
if TVMFFITypeKeyToIndex(type_key_arg.cptr(), &type_index) != 0:
    raise ValueError(...)
```

## Reflection

### Design docs to write or update
- `.knowledge/designs/0012-python-bindings.md`: Add a contract/invariant entry documenting that `ByteArrayArg` instances must be stored in named `cdef` variables when their `.cptr()` result is passed to C functions, to prevent Cython temporary destruction from invalidating the pointer. This is a recurring pattern (already correctly done in `_object_type_key_to_index` at line 243 but missed in `_type_info_create_from_type_key`).
