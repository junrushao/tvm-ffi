# Fix ffi.cpp.load_inline on Windows: MSVC flags, .dll extension, import-lib linking, and OEM encoding

## TL;DR
- `_generate_ninja_build` now emits correct MSVC flags (`/MD`, `/EHsc`, `/wd*` suppression warnings, MSVC dependency tracking via `deps = msvc`, and `/link … /out:` for the linker) when `IS_WINDOWS` is true, enabling compilation with `cl.exe` rather than `c++`.
- The output shared library is now named `<name>.dll` on Windows and `<name>.so` on Linux/macOS; `load_module` is called with the correct extension and an absolute path.
- `find_libtvm_ffi()` is called at build-generation time to resolve the import library (`.lib`) path, so the compiled DLL links against `libtvm_ffi_shared.lib` automatically.

```python
# python/tvm_ffi/cpp/load_inline.py — internal builder, unchanged public signature

def _generate_ninja_build(
    name: str,
    build_dir: str,
    include_paths: list[str],
    cflags: list[str],
    cuda_cflags: list[str],
    ldflags: list[str],
    with_cuda: bool,

    """Generate ninja.build file content for a single C++/CUDA inline module.

    # Invariant: on Windows, uses 'cl.exe' (via CXX env or default 'cl'), MSVC dep tracking
    #            (deps=msvc / /showIncludes), and /link … /out:$out linker syntax.
    # Invariant: on POSIX, uses 'c++', deps=gcc / -MMD -MF, and $cxx $in $ldflags -o $out.
    # Invariant: output artifact is '<name>.dll' on Windows, '<name>.so' on POSIX.
    # Invariant: Windows default_ldflags always includes /LIBPATH:<dir> and <name>.lib
    #            derived from find_libtvm_ffi() — no manual /LIBPATH required by callers.
    # Invariant: include paths with ':' are escaped as '$:' (ninja variable escape) on all platforms.
    # Interacts with: find_libtvm_ffi() for import-library discovery
    # Interacts with: load_module() which must receive the final .dll / .so absolute path
    """

# IS_WINDOWS constant (module-level):
IS_WINDOWS: bool = sys.platform == "win32"

# Windows default_cflags produced by this commit:
# ["/std:c++17", "/MD", "/wd4819", "/wd4251", "/wd4244", "/wd4267",
#  "/wd4275", "/wd4018", "/wd4190", "/wd4624", "/wd4067", "/wd4068", "/EHsc"]

# Windows ninja 'compile' rule (new, replaces GCC rule on Windows):
# rule compile
#   command = $cxx /showIncludes $cflags -c $in /Fo$out
#   deps = msvc

# Windows ninja 'link' rule (new):
# rule link
#   command = $cxx $in /link $ldflags /out:$out

# Encoding fix in _build_ninja error handler:
encoding: str = "oem" if IS_WINDOWS else "utf-8"
# subprocess stdout/stderr decoded with this encoding to avoid cp65001 mojibake

def load_inline(
    name: str,

    cuda_sources: str | None = None,

    # Invariant (post-fix): works on Linux, macOS, and Windows.

    # Interacts with: _generate_ninja_build, _build_ninja, load_module
    """
```

## Impact
- API: none — `load_inline` public signature is unchanged.
- Behavioral: `load_inline` now succeeds on Windows. Previously it always failed because the ninja build file used GCC flags with MSVC (`cl.exe`) and the output artifact was always named `.so` (not found as `.dll`).
- Flags/config: `CXX` env defaults to `cl` on Windows (was `c++`), but this was already in place before the commit.
- Data formats/schemas: none.

## Usage Examples

**Before (broken on Windows):**
```python
# load_inline would generate:
#   rule compile
#     command = $cxx -MMD -MF $out.d $cflags -c $in -o $out   ← GCC flags with cl.exe
#   build main.o: compile C:/path/to/main.cpp  ← ':' in path breaks ninja
#   build hello.so: link main.o  ← .so not produced by MSVC linker
#
# Then: load_module(".../hello.so")  ← file doesn't exist → FileNotFoundError
```

**After (fixed on Windows):**
```python
import tvm_ffi.cpp

mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="""
    #include <tvm/ffi/function.h>
    TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, [](int x) -> int { return x + 1; });
    """,
    functions=["add_one"],
)
# Now correctly:
#   1. Detects IS_WINDOWS, uses cl.exe + MSVC flags
#   2. Escapes 'C:\\path' → 'C$:\\path' in ninja file
#   3. Produces hello.dll via /link /DLL /LIBPATH:<tvm_dir> tvm_ffi_shared.lib /out:hello.dll
#   4. load_module("C:/abs/path/hello.dll")  ← absolute path, correct extension
import numpy
x = numpy.array([1, 2, 3], dtype=numpy.int32)
y = numpy.empty_like(x)
mod.add_one(x, y)
```
