# Fix ffi.cpp.load_inline to work on Windows by adapting ninja build generation for MSVC toolchain
## TL;DR
- Adapts `_generate_ninja_build` in `load_inline.py` for the MSVC toolchain: adds Windows-specific compiler flags (`/MD`, `/EHsc`, warning suppressions), linker flags (`/DLL`, `/LIBPATH`, lib import), compile/link rules (`deps = msvc`, `/showIncludes`, `/Fo`, `/link /out:`), and ninja path escaping for Windows drive letters (`C:` -> `C$:`).
- Switches output artifact extension from hardcoded `.so` to platform-appropriate `.dll`/`.so` and uses `oem` encoding for MSVC error output on Windows.
- Updates test markers from `xfail(not linux)` to `xfail(not linux and not win32)` to enable tests on Windows.

## Key Exports
No new public API surfaces are introduced. The changes are internal to `_generate_ninja_build`, `_build_ninja`, and `load_inline` in `python/tvm_ffi/cpp/load_inline.py`. The one newly consumed API is `find_libtvm_ffi` from `tvm_ffi.libinfo`.

```python
# No new exports. Key behavioral changes inside existing functions:

# _generate_ninja_build now branches on IS_WINDOWS for:
#   - default_cflags: ["/std:c++17", "/MD", "/wd4819", ..., "/EHsc"]
#     # Invariant: /MD selects multithreaded DLL runtime (must match tvm_ffi.dll's CRT)
#     # Invariant: /EHsc required for C++ exception handling with TVM_FFI_THROW
#   - default_ldflags: ["/DLL", "/LIBPATH:<dir>", "<name>.lib"]
#     # Interacts with: find_libtvm_ffi() from tvm_ffi.libinfo (0013-packaging)
#     # Invariant: links against tvm_ffi import lib so DLL exports resolve at load time
#   - compile rule: "command = $cxx /showIncludes $cflags -c $in /Fo$out" with "deps = msvc"
#     # Invariant: MSVC uses /showIncludes for dep tracking, not gcc's -MMD
#   - link rule: "command = $cxx $in /link $ldflags /out:$out"
#   - output extension: ".dll" instead of ".so"

# _build_ninja now uses "oem" encoding on Windows for subprocess error output
#   # Invariant: MSVC outputs in OEM codepage, not UTF-8

# Ninja path escaping: all os.path.abspath() values passed to ninja build
# statements now call .replace(":", "$:") to escape Windows drive letter colons
#   # Invariant: ninja treats ':' as rule separator; must be escaped as '$:'
```

## Impact
- API: None -- no public signature changes.
- Behavioral: `load_inline` now produces working DLLs on Windows. Previously it would fail at compile (wrong flags), link (missing tvm_ffi import lib, wrong syntax), or load (wrong extension) time.
- Flags/config: New default MSVC compiler flags added for Windows builds. The `CXX` environment variable now defaults to `cl` on Windows (was always `c++`).
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Module system** (`0011-module-system.md`): `load_module` is the final step of `load_inline`, loading the compiled `.dll`/`.so` via `Module::LoadFromFile` -> `DSOLibrary`.
- **Packaging / library discovery** (`0013-packaging.md`): Newly consumes `find_libtvm_ffi()` to locate the TVM FFI shared library for MSVC linker import resolution.
- **Python bindings** (`0012-python-bindings.md`): `load_inline` returns a `Module` object that wraps the loaded shared library.

Design elements this commit produces:
- None -- this is a bugfix making an existing feature work on a new platform.

## Usage Examples
**Before (broken on Windows):**
```python
# On Windows, load_inline would fail:
# 1. Compile error: missing /EHsc, /MD flags
# 2. Link error: cannot find tvm_ffi symbols (no import lib linked)
# 3. Ninja error: "C:" parsed as rule separator
# 4. Load error: looking for "hello.so" instead of "hello.dll"
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="...",
    functions=["my_func"],
)
```

**After (works on Windows):**
```python
# Same API, now generates correct MSVC ninja build with:
# - Proper compiler/linker flags
# - Escaped drive-letter paths
# - .dll output extension
# - tvm_ffi.lib linked for symbol resolution
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="...",
    functions=["my_func"],
)
result = mod.my_func(42)  # Works on both Linux and Windows
```
