# Fix load_inline Windows support: MSVC flags, DLL linking, ninja rules, colon escaping
## TL;DR
- Enables `tvm_ffi.cpp.load_inline()` on Windows by adding MSVC-specific compiler flags, DLL link flags (with `find_libtvm_ffi()` for import library resolution), MSVC-style ninja compile/link rules, and `.dll` output extension.
- Fixes ninja colon escaping in include paths and build target paths (Windows drive letters like `C:` break ninja syntax without `$:` escaping).
- Switches subprocess error output decoding from `utf-8` to `oem` on Windows, and updates test `xfail` markers to allow `win32`.

## Key Exports
None -- this commit does not introduce new public API surface. It fixes the existing `load_inline` function to work on Windows.

## Impact
- API: none -- `load_inline()` signature is unchanged.
- ABI: none -- no C++ or C ABI changes.
- Behavioral: `load_inline()` now produces working builds on Windows. Previously it would fail due to (a) missing MSVC flags, (b) hardcoded `.so` extension, (c) missing DLL import library linkage, (d) unescaped colons in ninja paths, (e) gcc-style dep tracking in ninja rules.
- Flags/config: New MSVC default cflags (`/MD`, `/EHsc`, 10 warning suppressions). New default ldflags on Windows: `/DLL`, `/LIBPATH:<tvm_ffi_lib_dir>`, `<tvm_ffi_lib_name>.lib`.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`): the `_generate_ninja_build`, `_build_ninja`, and `load_inline` functions are the primary targets of this bugfix.
- **`find_libtvm_ffi()`** (`.knowledge/designs/0015-python-packaging.md`): newly imported into `load_inline.py` to locate the TVM FFI shared library for Windows DLL linking. Previously only used by the library loader.
- **Module loading** (`.knowledge/designs/0013-module-system.md`): extension normalization (`dll` -> `so` for loader dispatch) ensures `load_module()` works with `.dll` paths.

Design elements this commit produces:
- **Windows platform support for inline compilation**: Six distinct fixes that collectively establish Windows as a supported platform for `load_inline()`:
  1. MSVC compiler flags (CRT linkage `/MD`, exception handling `/EHsc`, warning suppressions)
  2. DLL import library linking via `find_libtvm_ffi()`
  3. MSVC-style ninja dependency tracking (`deps = msvc` + `/showIncludes` instead of gcc depfiles)
  4. MSVC-style link command (`/link $ldflags /out:$out` instead of `$ldflags -o $out`)
  5. Ninja colon escaping (`path.replace(":", "$:")`) for Windows drive letter paths
  6. Platform-appropriate output extension (`.dll` vs `.so`)

## Usage Examples
No new API -- the usage is identical to the existing `load_inline` examples in `.knowledge/designs/0017-inline-module-compilation.md`. The fix is transparent to callers. On Windows, the generated `build.ninja` now contains:

```ninja
cxx = cl
cflags = /std:c++17 /MD /wd4819 /wd4251 ... /EHsc -IC$:/path/to/include

rule compile
  command = $cxx /showIncludes $cflags -c $in /Fo$out
  deps = msvc

rule link
  command = $cxx $in /link $ldflags /out:$out

build hello.dll: link main.o
default hello.dll
```
