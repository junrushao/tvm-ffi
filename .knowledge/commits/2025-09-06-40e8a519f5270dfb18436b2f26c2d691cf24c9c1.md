# Append __tvm_ffi_ symbol prefix to all FFI-exported DLL functions to prevent symbol conflicts

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC(Name, Func)` now emits a C symbol named `__tvm_ffi_##Name` instead of `Name`, preventing namespace collisions between FFI-convention symbols and non-FFI symbols in the same DSO.
- Well-known library symbols gain an extra `_` separator for internal symbols: `__tvm_ffi__library_ctx`, `__tvm_ffi__library_bin`, `__tvm_ffi__metadata_<name>`. The main entry becomes `__tvm_ffi_main` (was `__tvm_ffi_main__`).
- `Library` base class gains `GetSymbolWithSymbolPrefix(name)` virtual method that prepends `symbol::tvm_ffi_symbol_prefix` before symbol lookup. Python `Module.entry_name` changes from `"__tvm_ffi_main__"` to `"main"` (prefix applied automatically).

## Impact
- API: `TVM_FFI_DLL_EXPORT_TYPED_FUNC` users see no source-level change, but the emitted C symbol name changes (now has `__tvm_ffi_` prefix). Downstream LLVM codegen and library module loaders must be updated to emit/lookup the new prefixed names.
- Behavioral: `LibraryModuleObj.GetFunction` now calls `GetSymbolWithSymbolPrefix` instead of raw `GetSymbol`, transparently adding the prefix. Python `Module.entry_name` is `"main"` (the prefix is applied at the C++ layer).
- Flags/config: none
- Data formats/schemas: Library DSO symbol tables now use `__tvm_ffi_`-prefixed function symbols. Old DSOs with unprefixed symbols are incompatible.

## Design Elements
Design elements this commit consumes:
- **Module system** (0011-module-system): `Library`, `LibraryModuleObj`, `DSOLibrary`, `SystemLibrary`, well-known symbol constants
- **Function system** (0003-function-system): `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro, `TVMFFISafeCallType`

Design elements this commit produces:
- **`symbol::tvm_ffi_symbol_prefix`**: New constant `"__tvm_ffi_"` establishing the naming convention for all FFI function symbols in DSOs
- **`Library::GetSymbolWithSymbolPrefix`**: New virtual method on the Library base class that encapsulates the prefix-prepend-then-lookup pattern
- **Double-underscore convention for internal symbols**: Internal/infrastructure symbols (`library_ctx`, `library_bin`, `metadata_`) now use `__tvm_ffi__` (double underscore after "ffi") to separate them from user function symbols which use `__tvm_ffi_` (single underscore)

## Usage Examples

C++ side -- exporting a typed function (unchanged source, different emitted symbol):
```cpp
// Source code: no change needed
TVM_FFI_DLL_EXPORT_TYPED_FUNC(MyKernel, my_kernel_impl);
// Before: emits symbol "MyKernel"
// After:  emits symbol "__tvm_ffi_MyKernel"
```

Python side -- calling module entry function:
```python
mod = Module.load_from_file("my_lib.so")
# entry resolves "main" -> C++ GetSymbolWithSymbolPrefix("main")
#   -> looks up "__tvm_ffi_main" in the DSO
result = mod.entry(input_data)
```
