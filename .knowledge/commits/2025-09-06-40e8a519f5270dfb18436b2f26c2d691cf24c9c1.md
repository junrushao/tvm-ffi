# Introduce __tvm_ffi_ symbol prefix for DLL-exported functions to prevent symbol conflicts

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Fn)` now emits the C symbol `__tvm_ffi_##ExportName` instead of raw `ExportName`, preventing conflicts between FFI-exported functions and non-FFI symbols of the same name.
- Well-known internal symbols (`library_ctx`, `library_bin`, `metadata_prefix`) are moved to a `__tvm_ffi__` double-underscore namespace to avoid colliding with user function names that acquire the `__tvm_ffi_` prefix.
- A new `Library::GetSymbolWithSymbolPrefix` virtual method centralizes prefix prepending; `LibraryModuleObj::GetFunction` and Python `Module` now operate on logical names (`"main"`) rather than physical symbol names.

## Key Exports

**Constants (changed)**:
```cpp
namespace tvm::ffi::symbol {
  constexpr const char* tvm_ffi_symbol_prefix   = "__tvm_ffi_";        // NEW
  constexpr const char* tvm_ffi_main             = "__tvm_ffi_main";   // was "__tvm_ffi_main__"
  constexpr const char* tvm_ffi_library_ctx      = "__tvm_ffi__library_ctx";  // was "__tvm_ffi_library_ctx"
  constexpr const char* tvm_ffi_library_bin      = "__tvm_ffi__library_bin";  // was "__tvm_ffi_library_bin"
  constexpr const char* tvm_ffi_metadata_prefix  = "__tvm_ffi__metadata_";    // was "__tvm_ffi_metadata_"
}
```

**Macro (changed)**:
```cpp
// Before: extern "C" int ExportName(void* self, TVMFFIAny* args, ...)
// After:  extern "C" int __tvm_ffi_##ExportName(void* self, TVMFFIAny* args, ...)
TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function)
```

**Virtual method (new)**:
```cpp
class Library : public Object {
  virtual void* GetSymbol(const String& name) = 0;           // signature changed: const char* -> const String&
  virtual void* GetSymbolWithSymbolPrefix(const String& name); // NEW: prepends tvm_ffi_symbol_prefix
};
```

**SystemLibrary override (new)**:
```cpp
class SystemLibrary final : public Library {
  void* GetSymbol(const String& name) final;                          // prepends symbol_prefix_ only
  void* GetSymbolWithSymbolPrefix(const String& name) final;          // prepends tvm_ffi_symbol_prefix + symbol_prefix_
};
```

## Impact
- API: **Breaking ABI change** for all downstream users of `TVM_FFI_DLL_EXPORT_TYPED_FUNC` -- the emitted C symbol name changes from `ExportName` to `__tvm_ffi_ExportName`. Any code loading modules by raw dlsym must update. LLVM/codegen backends must emit the `__tvm_ffi_` prefix.
- Behavioral: `LibraryModuleObj::GetFunction("foo")` now looks up `__tvm_ffi_foo` instead of `foo`. Python `Module.entry_func` now uses logical name `"main"` (resolved to `__tvm_ffi_main` in C++).
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): `Library`, `LibraryModuleObj`, `DSOLibrary`, `SystemLibrary`, well-known symbol namespace.
- **Function system** ([0004-function-system.md](../designs/0004-function-system.md)): `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro, `TVMFFISafeCallType` calling convention.

Design elements this commit produces:
- **`tvm_ffi_symbol_prefix` constant**: New `"__tvm_ffi_"` prefix string, centralizing the naming convention so it can be referenced by codegen backends.
- **Two-tier symbol namespace**: User-exported functions get `__tvm_ffi_<name>` (single underscore separator); internal well-known symbols get `__tvm_ffi__<name>` (double underscore separator), preventing collision.
- **`Library::GetSymbolWithSymbolPrefix` virtual method**: Abstraction layer for prefixed symbol lookup, allowing `SystemLibrary` to compose its own prefix with the FFI prefix.

## Usage Examples

**Before (old convention)**: `TVM_FFI_DLL_EXPORT_TYPED_FUNC(AddOne, AddOne_)` emitted C symbol `AddOne`. Module lookup: `lib->GetSymbol("AddOne")`.

**After (new convention)**: Same macro invocation emits C symbol `__tvm_ffi_AddOne`. Module lookup: `mod->GetFunction("AddOne")` internally calls `lib->GetSymbolWithSymbolPrefix("AddOne")` which resolves to `__tvm_ffi_AddOne`.

```cpp
// C++ shared library (producer side)
int AddOne_(int x) { return x + 1; }
TVM_FFI_DLL_EXPORT_TYPED_FUNC(AddOne, AddOne_);
// -> emits: extern "C" int __tvm_ffi_AddOne(void* self, ...)

// C++ consumer side
Module mod = Module::LoadFromFile("my_lib.so");
auto f = mod->GetFunction("AddOne");  // resolves __tvm_ffi_AddOne via GetSymbolWithSymbolPrefix
int result = (*f)(42).cast<int>();    // 43

// Python consumer side
mod = tvm_ffi.load_module("my_lib.so")
result = mod.get_function("AddOne")(42)  # resolves __tvm_ffi_AddOne
entry = mod.entry_func                    # resolves "main" -> __tvm_ffi_main
```
