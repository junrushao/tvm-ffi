# Prefix all FFI-exported DSO symbols with __tvm_ffi_ to prevent naming conflicts

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function)` now generates the C symbol `__tvm_ffi_##ExportName` instead of just `ExportName`, preventing collisions between FFI-convention functions and user-defined C symbols.
- Well-known DSO symbols gain an extra `_` separator: `__tvm_ffi_library_ctx` -> `__tvm_ffi__library_ctx`, `__tvm_ffi_library_bin` -> `__tvm_ffi__library_bin`, `__tvm_ffi_metadata_` -> `__tvm_ffi__metadata_`. The entry point symbol changes from `__tvm_ffi_main__` to `__tvm_ffi_main`.
- The `Library` abstract interface changes `GetSymbol(const char*)` to `GetSymbol(const String&)`, and gains `GetSymbolWithSymbolPrefix(const String&)` to transparently prepend `symbol::tvm_ffi_symbol_prefix` during function lookup.

| Old symbol | New symbol | Role |
|---|---|---|
| `ExportName` (raw) | `__tvm_ffi_ExportName` | DLL-exported packed function |
| `__tvm_ffi_library_ctx` | `__tvm_ffi__library_ctx` | Library context pointer |
| `__tvm_ffi_library_bin` | `__tvm_ffi__library_bin` | Embedded binary import tree |
| `__tvm_ffi_main__` | `__tvm_ffi_main` | Default entry function |
| `__tvm_ffi_metadata_` | `__tvm_ffi__metadata_` | Per-function metadata prefix |

    def GetSymbolWithSymbolPrefix(self, name: str) -> void_ptr: ...

        # Default: return GetSymbol(tvm_ffi_symbol_prefix + name)
        # Interacts with: symbol::tvm_ffi_symbol_prefix ("__tvm_ffi_")
        # Extension: SystemLibrary overrides to prepend its own symbol_prefix too

# --- include/tvm/ffi/function.h: macro change ---

class SystemLibrary(Library):

    symbol_prefix_: str

    def GetSymbolWithSymbolPrefix(self, name: str) -> void_ptr: ...

## Impact
- API: **Breaking** -- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` now emits `__tvm_ffi_`-prefixed symbols. Any external code referencing the old unprefixed symbols by name (e.g., `dlsym(lib, "AddOne")`) will fail. Callers using `LibraryModuleObj.GetFunction("AddOne")` are unaffected because `GetFunction` now calls `GetSymbolWithSymbolPrefix` which adds the prefix automatically.
- API: **Breaking** -- `Library::GetSymbol` signature changed from `const char*` to `const String&`. Any custom `Library` subclass must update its override.
- API: Well-known symbol strings changed (see mapping table above). Code that hardcodes old symbol names must update.
- Behavioral: `SystemLibrary::GetSymbol` no longer falls back to unprefixed lookup -- it always prepends `symbol_prefix_`.
- Behavioral: Python `Module.entry_name` changed from `"__tvm_ffi_main__"` to `"main"` (the prefix is now added by `GetSymbolWithSymbolPrefix` transparently).
- Flags/config: none
- Data formats/schemas: DSO symbol tables must use the new naming convention after this commit

## Design Elements
Design elements this commit consumes:
- `ModuleObj`/`Module` -- function lookup via `GetFunction` (see [0011-ffi-module-system.md](../../.knowledge/design-records/0011-ffi-module-system.md))
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro -- packed function export (see [0013-ffi-packaging-and-distribution.md](../../.knowledge/design-records/0013-ffi-packaging-and-distribution.md))
- `LibraryModuleObj` -- wraps `Library` symbols as `ffi::Function` (see [0011-ffi-module-system.md](../../.knowledge/design-records/0011-ffi-module-system.md))

Design elements this commit produces:
- `symbol::tvm_ffi_symbol_prefix` (`"__tvm_ffi_"`) -- new common prefix constant, the central piece enabling conflict-free symbol namespacing
- `Library::GetSymbolWithSymbolPrefix` -- new virtual method that transparently prepends `tvm_ffi_symbol_prefix` before calling `GetSymbol`

Design elements this commit mutates:
- `Library::GetSymbol` -- signature changed from `const char*` to `const String&`
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` -- macro now emits `__tvm_ffi_##ExportName` instead of raw `ExportName`
- Well-known DSO symbols -- all renamed with extra `_` separator (see mapping table)
- `SystemLibrary::GetSymbol` -- no longer falls back to unprefixed; always prepends `symbol_prefix_`

## Usage Examples

Before/after showing how the prefix convention changes symbol lookup:

```cpp
// Before this commit:
// TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, my_ext::AddOne);
// -> generates: extern "C" int add_one(void* self, TVMFFIAny* args, ...)
// -> Library::GetSymbol("add_one") finds it directly

// After this commit:
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, my_ext::AddOne);
// -> generates: extern "C" int __tvm_ffi_add_one(void* self, TVMFFIAny* args, ...)
// -> LibraryModuleObj::GetFunction("add_one")
//    calls Library::GetSymbolWithSymbolPrefix("add_one")
//    which looks up "__tvm_ffi_add_one"
```

```python
# Python side: entry_name is now the logical name, prefix added internally
mod = tvm_ffi.load_module("my_model.so")
# mod.entry_name == "main"  (was "__tvm_ffi_main__")
# mod.entry_func calls GetFunction("main") -> GetSymbolWithSymbolPrefix("main")
#   -> looks up "__tvm_ffi_main" in the DSO
```
