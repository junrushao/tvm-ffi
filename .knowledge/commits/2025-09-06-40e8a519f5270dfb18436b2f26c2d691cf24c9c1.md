# Prefix all FFI-exported DSO symbols with __tvm_ffi_ to prevent symbol conflicts

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC(Name, Func)` now emits `__tvm_ffi_Name` instead of raw `Name`, preventing symbol conflicts between FFI-convention and non-FFI functions in the same shared library.
- Internal/special library symbols gain a double-underscore separator (`__tvm_ffi__library_ctx`, `__tvm_ffi__library_bin`, `__tvm_ffi__metadata_`) to avoid collision with user-defined FFI symbols.
- A new `Library::GetSymbolWithSymbolPrefix()` virtual method transparently prepends the `__tvm_ffi_` prefix during function lookup, so callers (Python, C++) use logical names (e.g., `"main"`) without knowing the mangled symbol.

## Impact
- API: **ABI-breaking**. All symbols emitted by `TVM_FFI_DLL_EXPORT_TYPED_FUNC` change name. Pre-compiled `.so` libraries must be recompiled. Internal symbols (`library_ctx`, `library_bin`, `metadata_`) also renamed.
- Behavioral: `LibraryModuleObj::GetFunction` now calls `GetSymbolWithSymbolPrefix` instead of `GetSymbol` directly, adding the `__tvm_ffi_` prefix transparently. Python `Module.entry_name` changes from `"__tvm_ffi_main__"` to `"main"` (prefix applied at C++ layer).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system** (`Library`, `LibraryModuleObj`, `DSOLibrary`, `SystemLibrary`) -- see `.knowledge/designs/0011-module-system.md`
- **Function system** (`TVM_FFI_DLL_EXPORT_TYPED_FUNC`, `TVM_FFI_SAFE_CALL_BEGIN/END`) -- see `.knowledge/designs/0004-function-system.md`
- **Symbol naming convention** (`tvm_ffi_library_ctx`, `tvm_ffi_main`, etc.) -- see `.knowledge/designs/0011-module-system.md` (symbol namespace section)

Design elements this commit produces:
- **`symbol::tvm_ffi_symbol_prefix`** -- new constant establishing the canonical `__tvm_ffi_` prefix for all FFI function symbols in shared libraries
- **`Library::GetSymbolWithSymbolPrefix()`** -- new virtual method providing prefix-aware symbol lookup, overridable by subclasses (e.g., `SystemLibrary` composes system prefix + ffi prefix)
- **Two-tier symbol naming convention** -- user FFI functions use single-underscore separator (`__tvm_ffi_name`), internal/special symbols use double-underscore (`__tvm_ffi__name`)

Design elements this commit mutates:
- **`TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro** -- exported symbol name now includes `__tvm_ffi_` prefix
- **`Library::GetSymbol` signature** -- parameter type widened from `const char*` to `const String&`
- **All `symbol::*` constants** -- values changed per new naming convention

## Usage Examples

Before (pre-commit):
```cpp
// C++ exporting a function
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, AddOne);
// Emits: extern "C" int add_one(void*, TVMFFIAny*, int32_t, TVMFFIAny*)

// Python looking up entry function
module.get_function("__tvm_ffi_main__")
```

After (post-commit):
```cpp
// C++ exporting a function
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, AddOne);
// Emits: extern "C" int __tvm_ffi_add_one(void*, TVMFFIAny*, int32_t, TVMFFIAny*)
// Lookup: lib->GetSymbolWithSymbolPrefix("add_one") -> finds "__tvm_ffi_add_one"

// Python looking up entry function -- uses logical name
module.get_function("main")
// C++ layer prepends __tvm_ffi_ to find "__tvm_ffi_main" in the DSO
```
