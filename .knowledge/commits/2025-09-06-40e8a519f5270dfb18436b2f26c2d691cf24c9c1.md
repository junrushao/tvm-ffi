# Append __tvm_ffi_ symbol prefix to all FFI-exported function symbols to prevent DSO symbol collisions

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Fn)` now emits `__tvm_ffi_##ExportName` as the C symbol name instead of the bare `ExportName`, eliminating collisions between FFI-convention symbols and user-defined symbols that happen to share the same name.
- `Library::GetSymbol` signature changes from `const char*` to `const String&`; a new `GetSymbolWithSymbolPrefix` virtual method is added that prepends `__tvm_ffi_` before lookup, used by `LibraryModuleObj::GetFunction`.
- Symbol string constants in `ffi::symbol` are renamed: `tvm_ffi_library_ctx/bin` gain an extra `_` (now `__tvm_ffi__library_ctx/bin`), `tvm_ffi_metadata_prefix` gains an extra `_`, `tvm_ffi_main` loses its trailing `__` (now `__tvm_ffi_main`), and a new `tvm_ffi_symbol_prefix = "__tvm_ffi_"` constant is introduced.

## Key Exports

```python
# ─── include/tvm/ffi/extra/module.h: ffi::symbol namespace ───────────────────

symbol.tvm_ffi_symbol_prefix   = "__tvm_ffi_"        # NEW: canonical prefix for all FFI function symbols
symbol.tvm_ffi_main            = "__tvm_ffi_main"    # CHANGED: was "__tvm_ffi_main__" (trailing __ removed)
symbol.tvm_ffi_library_ctx     = "__tvm_ffi__library_ctx"  # CHANGED: was "__tvm_ffi_library_ctx"
symbol.tvm_ffi_library_bin     = "__tvm_ffi__library_bin"  # CHANGED: was "__tvm_ffi_library_bin"
symbol.tvm_ffi_metadata_prefix = "__tvm_ffi__metadata_"    # CHANGED: was "__tvm_ffi_metadata_"
# Invariant: internal special symbols (ctx, bin, metadata) use double-_ after __tvm_ffi
#            to avoid conflict with user-exported function symbols that use single-_

# ─── src/ffi/extra/module_internal.h: Library abstract interface ─────────────

class Library(Object):
    """Abstract interface over a raw symbol table (DSO or system-lib)."""

    def GetSymbol(self, name: String) -> void*: ...
    # CHANGED: was GetSymbol(const char* name); now takes String& for consistent prefix concat
    # Invariant: returns nullptr if symbol not found

    def GetSymbolWithSymbolPrefix(self, name: String) -> void*: ...
    # NEW: default impl prepends tvm_ffi_symbol_prefix then delegates to GetSymbol
    # Invariant: SystemLibrary overrides to prepend both tvm_ffi_symbol_prefix + user symbol_prefix_
    # Interacts with: LibraryModuleObj::GetFunction (only caller; uses this for all user function lookups)
    # Extension: override in new Library subclasses that have a different prefix scheme

# ─── include/tvm/ffi/function.h: TVM_FFI_DLL_EXPORT_TYPED_FUNC macro ─────────

# TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function)
# Expands to (CHANGED):
# extern "C" {
#   TVM_FFI_DLL_EXPORT int __tvm_ffi_##ExportName(
#       void* self, TVMFFIAny* args, int32_t num_args, TVMFFIAny* result) {
#     TVM_FFI_SAFE_CALL_BEGIN();
#     unpack_call<RetType>(..., Function, args, num_args, result);
#     TVM_FFI_SAFE_CALL_END();
#   }
# }
# CHANGED: symbol name was bare ExportName; now __tvm_ffi_##ExportName
# Invariant: ExportName and Function must differ
# Interacts with: Library::GetSymbolWithSymbolPrefix (prepends __tvm_ffi_ at lookup time)
#                 ffi::symbol::tvm_ffi_symbol_prefix (defines the prefix used here)
```

## Impact
- API: `Library::GetSymbol` virtual method signature changed from `const char*` to `const String&` — all `Library` subclasses (`DSOLibrary`, `SystemLibrary`) must update their override. Breaking change for out-of-tree `Library` subclasses.
- Behavioral: `LibraryModuleObj::GetFunction(name)` now calls `GetSymbolWithSymbolPrefix(name)` which prepends `__tvm_ffi_` before looking up the symbol. Any caller expecting bare `name` symbols in a loaded `.so` will get nullptr. Compiled kernels must use `TVM_FFI_DLL_EXPORT_TYPED_FUNC` so symbols are emitted with the prefix.
- Behavioral: `SystemLibrary::GetSymbol` no longer falls back to the unprefixed name when symbol_prefix_ is non-empty. Fallback path was removed.
- Behavioral: Python `Module.entry_name` is now `"main"` (not `"__tvm_ffi_main__"`); `get_entry_func` looks up `"main"`, which goes through `GetSymbolWithSymbolPrefix` → `"__tvm_ffi_main"`.
- Flags/config: none
- Data formats/schemas: DSO symbol constants renamed — `.so` files with `__tvm_ffi_library_ctx`/`__tvm_ffi_library_bin` are stale; they must be recompiled to emit the new double-underscore variants.

## Usage Examples

**Before/after: exporting a kernel function with `TVM_FFI_DLL_EXPORT_TYPED_FUNC`**

```cpp
// BEFORE: macro emitted bare ExportName symbol
TVM_FFI_DLL_EXPORT_TYPED_FUNC(my_kernel, MyKernelImpl);
// → extern "C" int my_kernel(void*, TVMFFIAny*, int32_t, TVMFFIAny*)
// host lookup: lib->GetSymbol("my_kernel")  ← could conflict with non-FFI "my_kernel"

// AFTER: macro emits prefixed symbol
TVM_FFI_DLL_EXPORT_TYPED_FUNC(my_kernel, MyKernelImpl);
// → extern "C" int __tvm_ffi_my_kernel(void*, TVMFFIAny*, int32_t, TVMFFIAny*)
// host lookup via LibraryModuleObj::GetFunction("my_kernel")
//   → lib->GetSymbolWithSymbolPrefix("my_kernel")
//   → lib->GetSymbol("__tvm_ffi_my_kernel")   ← no collision risk
```

**Before/after: Python module entry function**

```python
# BEFORE
mod = Module.LoadFromFile("kernel.so")
mod._entry = mod.get_function("__tvm_ffi_main__")

# AFTER
mod = Module.LoadFromFile("kernel.so")
mod._entry = mod.get_function("main")
# get_function("main") → GetSymbolWithSymbolPrefix("main") → GetSymbol("__tvm_ffi_main")
```
