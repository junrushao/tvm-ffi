# Add __tvm_ffi_ symbol prefix to DLL-exported functions and restructure internal library symbol constants

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Func)` now emits `__tvm_ffi_##ExportName` instead of `ExportName` as the C symbol, preventing name collisions between FFI-convention functions and non-FFI symbols in the same DSO.
- `Library::GetSymbol` signature changes from `const char*` to `const String&`, and a new `Library::GetSymbolWithSymbolPrefix` virtual method is added to prepend `__tvm_ffi_` when looking up user functions.
- Internal symbol constants are restructured: special symbols (`_library_ctx`, `_library_bin`, `_metadata_`) gain an extra `_` prefix (e.g., `__tvm_ffi__library_ctx`) to avoid collisions with user function names, while `tvm_ffi_main` changes from `__tvm_ffi_main__` to `__tvm_ffi_main`.
- Python `Module.entry_name` changes from `"__tvm_ffi_main__"` to `"main"` because the prefix is now prepended by the library lookup layer.

## Key Exports

**Constants** (changed values in `ffi::symbol` namespace, `include/tvm/ffi/extra/module.h`):

| Constant | Old Value | New Value |
|----------|-----------|-----------|
| `tvm_ffi_symbol_prefix` | *(did not exist)* | `"__tvm_ffi_"` |
| `tvm_ffi_main` | `"__tvm_ffi_main__"` | `"__tvm_ffi_main"` |
| `tvm_ffi_library_ctx` | `"__tvm_ffi_library_ctx"` | `"__tvm_ffi__library_ctx"` |
| `tvm_ffi_library_bin` | `"__tvm_ffi_library_bin"` | `"__tvm_ffi__library_bin"` |
| `tvm_ffi_metadata_prefix` | `"__tvm_ffi_metadata_"` | `"__tvm_ffi__metadata_"` |

**Macros** (changed expansion in `include/tvm/ffi/function.h`):

| Macro | Old Expansion | New Expansion |
|-------|--------------|---------------|
| `TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Func)` | `extern "C" int ExportName(void*, TVMFFIAny*, int32_t, TVMFFIAny*)` | `extern "C" int __tvm_ffi_##ExportName(void*, TVMFFIAny*, int32_t, TVMFFIAny*)` |

**Classes/Methods** (changed/added in `src/ffi/extra/module_internal.h`):

- `Library::GetSymbol(const String& name) -> void*` -- signature changed from `const char*` to `const String&`
- `Library::GetSymbolWithSymbolPrefix(const String& name) -> void*` -- **new** virtual method; default implementation prepends `symbol::tvm_ffi_symbol_prefix` and delegates to `GetSymbol`
- `SystemLibrary::GetSymbolWithSymbolPrefix` -- override that prepends both `tvm_ffi_symbol_prefix` and `symbol_prefix_`

## Impact
- API: `TVM_FFI_DLL_EXPORT_TYPED_FUNC` now emits a different symbol name. All existing users of this macro (including LLVM codegen, `load_inline`, packaging examples) must be recompiled. No source-level change is needed for macro callers, but the emitted binary symbol is different.
- ABI: **Breaking**. Old DSOs that exported `ExportName` directly are incompatible with the new `LibraryModuleObj::GetFunction`, which now calls `GetSymbolWithSymbolPrefix` (prepending `__tvm_ffi_`). Old DSOs must be recompiled. Internal symbol constants (`__tvm_ffi_library_ctx`, `__tvm_ffi_library_bin`, `__tvm_ffi_metadata_`) also change, so old binaries with embedded metadata are incompatible.
- Behavioral: `LibraryModuleObj::GetFunction` now calls `GetSymbolWithSymbolPrefix` instead of `GetSymbol`, transparently adding the prefix. Python `Module.entry_name` changes from raw symbol `"__tvm_ffi_main__"` to logical name `"main"` (the prefix is applied by the lookup layer). `SystemLibrary::GetSymbol` no longer falls back to unprefixed lookup when `symbol_prefix_` is set.
- Flags/config: none
- Data formats/schemas: Embedded library binary format is effectively incompatible because the internal symbol names it depends on (`__tvm_ffi_library_bin`, `__tvm_ffi_library_ctx`) have changed.

## Design Elements

Design elements this commit consumes:
- **Module system** (`.knowledge/designs/0013-module-system.md`) -- `LibraryModuleObj`, `Library`, `DSOLibrary`, `SystemLibrary`, `ContextSymbolRegistry`, `CreateLibraryModule`, symbol constants
- **Function system** (`.knowledge/designs/function-system.md`) -- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro, `TVMFFISafeCallType`
- **C ABI** (`.knowledge/designs/c-abi.md`) -- `TVM_FFI_DLL_EXPORT`, `TVMFFISafeCallType`, `TVMFFIAny`

Design elements this commit produces:
- **FFI symbol prefix convention**: A new naming convention where all user-facing FFI functions exported from DSOs carry the `__tvm_ffi_` prefix. This creates a clear namespace boundary between TVM FFI functions (which follow `TVMFFISafeCallType` calling convention) and non-FFI symbols in the same shared library.
- **Two-tier symbol namespace**: Internal/special symbols use double underscore after the prefix (`__tvm_ffi__library_ctx`) while user functions use single underscore (`__tvm_ffi_main`). This prevents a user function named `library_ctx` from colliding with the context pointer symbol.
- **`Library::GetSymbolWithSymbolPrefix`**: A new virtual method on the `Library` base class that separates "look up a raw symbol" (`GetSymbol`) from "look up an FFI function symbol with the standard prefix" (`GetSymbolWithSymbolPrefix`). This allows `SystemLibrary` to override the prefix chain (prefix + symbol_prefix + name) independently.

## Usage Examples

Before this commit, `TVM_FFI_DLL_EXPORT_TYPED_FUNC(AddOne, AddOne_)` emitted:
```cpp
extern "C" int AddOne(void* self, TVMFFIAny* args, int32_t num_args, TVMFFIAny* result) { ... }
```

After this commit, the same macro emits:
```cpp
extern "C" int __tvm_ffi_AddOne(void* self, TVMFFIAny* args, int32_t num_args, TVMFFIAny* result) { ... }
```

When loading a module and retrieving a function:
```cpp
Module mod = Module::LoadFromFile("my_lib.so");
// Internally calls lib->GetSymbolWithSymbolPrefix("AddOne")
// which looks up "__tvm_ffi_AddOne" in the DSO
auto f = mod->GetFunction("AddOne");
```

Python side, the entry function is now looked up by logical name:
```python
mod = tvm_ffi.load_module("my_lib.so")
# Internally calls get_function("main")
# which resolves to symbol "__tvm_ffi_main" via GetSymbolWithSymbolPrefix
result = mod()
```
