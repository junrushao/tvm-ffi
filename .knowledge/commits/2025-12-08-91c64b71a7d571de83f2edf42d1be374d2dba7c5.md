# Fix int8 (Char) missing from DLPack dtype mapping for torch < 2.6.0

## TL;DR
- Fixed incorrect version guard `TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 6` that failed for torch >= 3.0 (where MINOR resets to 0). Replaced with `(MAJOR > 2) || (MAJOR == 2 && MINOR >= 6)`.
- Moved `ScalarType::Char` (int8) outside the version-guarded block so it is available for all torch versions, not just >= 2.6.0.
- Deduplicated repeated `dtype.code` assignments by grouping related `case` labels with fallthrough.

- Behavioral: `getDLDataTypeForDLPackv1` now correctly maps `ScalarType::Char` (int8) to `kDLInt` for all torch versions, and sub-byte int types (`Int1`-`Int7`) are correctly guarded for torch >= 3.x.

## Usage Examples
Before (bug): torch < 2.6.0 would hit `default: TORCH_CHECK(false, ...)` when converting an int8 tensor via DLPack because `ScalarType::Char` was inside the `#if TORCH_VERSION >= 2.6` block.

After (fix): `ScalarType::Char` falls through to `kDLInt` unconditionally, matching all torch versions.
