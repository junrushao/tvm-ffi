# Fix int8 (ScalarType::Char) missing from DLPack dtype mapping for torch<2.6.0
## TL;DR
- Moves `ScalarType::Char` (int8) out of the `#if TORCH_VERSION >= 2.6` guard so it maps to `kDLInt` on all torch versions.
- Fixes version check macro from `MAJOR >= 2 && MINOR >= 6` (wrong: fails for torch 3.x with MINOR < 6) to `(MAJOR > 2) || (MAJOR == 2 && MINOR >= 6)`.
- Consolidates duplicate `kDLInt`/`kDLFloat` case blocks into grouped fall-through cases.

## Impact
- API: none
- Behavioral: int8 tensors (`ScalarType::Char`) now correctly convert via DLPack on torch < 2.6.0. Previously they fell through to the default case, likely causing a runtime error or incorrect dtype.
