# Fix missing int8 (Char) for torch<2.6.0 and consolidate scalar type mapping in getDLDataTypeForDLPackv1

## TL;DR
- Fixes a bug where `ScalarType::Char` (int8) was inside the `#if TORCH_VERSION >= 2.6` preprocessor guard, making it unreachable on torch < 2.6.0 and causing "Unsupported scalar type" errors when converting int8 tensors via DLPack.
- Moves `ScalarType::Char` out of the `#if`/`#endif` block so it falls through to the unconditional `kDLInt` branch regardless of torch version.
- Consolidates duplicated `kDLInt` and `kDLFloat` case arms: `Char`, `Short`, `Int`, `Long` now share a single `kDLInt` break; `Half`, `Float`, `Double` now share a single `kDLFloat` break.
- Also fixes the version guard itself from `TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 6` to `(TORCH_VERSION_MAJOR > 2) || (TORCH_VERSION_MAJOR == 2 && TORCH_VERSION_MINOR >= 6)`, correcting the same major-version comparison bug fixed for `Float8_e8m0fnu`/`Float4_e2m1fn_x2` in 8dbd281.

## Impact
- API: none
- Behavioral: int8 (`ScalarType::Char`) tensor exchange between PyTorch and TVM FFI now works on torch < 2.6.0. Previously, `Char` was gated behind the torch >= 2.6 preprocessor guard (alongside `Int1`..`Int7` which genuinely require 2.6+), so it was excluded from the DLPack type mapping on older torch versions.
