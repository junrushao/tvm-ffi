# Add TVMFFIHandleInitOnce/TVMFFIHandleDeinitOnce C API for thread-safe static handle initialization
## TL;DR
- Introduces two new C ABI functions for thread-safe one-time initialization and deinitialization of static handles, designed for DSLs (e.g., LLVM-based) that lack C++ `std::call_once` or static initialization support.
- Implementation uses a double-checked locking pattern with platform-specific atomics (GCC `__atomic_*` builtins on Unix, `Interlocked*` on Windows) and a global `std::mutex` for the slow path.

## Key Exports

**C API Functions** (in `c_api.h`):
- `int TVMFFIHandleInitOnce(void** handle_addr, int (*init_func)(void** result))` -- Thread-safe one-time initialization. If `*handle_addr` is nullptr, calls `init_func` to create the handle. Uses acquire/release semantics for the fast-path null check.
  - Contract: `init_func` must return 0 on success and set `*result` to a non-null handle. On error, it should call `TVMFFIErrorSetRaisedFromCStr` and return nonzero.
- `int TVMFFIHandleDeinitOnce(void** handle_addr, int (*deinit_func)(void* handle))` -- Thread-safe one-time deinitialization. Atomically exchanges `*handle_addr` with nullptr, then calls `deinit_func` on the old handle if it was non-null.

**Internal helpers** (anonymous namespace in `init_once.cc`):
- `AtomicLoadHandleAcquire(void**)` -- Platform-specific acquire-semantics atomic load.
- `AtomicStoreHandleRelease(void**, void*)` -- Platform-specific release-semantics atomic store.

## Impact
- API: Additive. Two new C ABI functions exported from `libtvm_ffi`.
- Behavioral: None to existing code.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **C ABI layer** ([0001-c-abi-layer.md](../designs/0001-c-abi-layer.md)): Follows the established C API pattern with `TVM_FFI_DLL` export, `int` return code, and error propagation via `TVMFFIErrorSetRaisedFromCStr`.

Design elements this commit produces:
- **Thread-safe handle initialization API**: A double-checked locking primitive exposed through the C ABI for DSL consumers. Key invariants:
  - Fast path is lock-free (atomic acquire load).
  - Slow path uses a single global mutex (acceptable since init is infrequent).
  - `init_func` returning null is treated as an error.
  - `DeinitOnce` uses atomic exchange (acq_rel) to ensure exactly-once semantics.

## Usage Examples
```c
// DSL-generated code for lazy function handle initialization
static void* g_my_func_handle = NULL;

static int init_my_func(void** result) {
    return TVMFFIFuncGetGlobal("my_namespace.my_func", (TVMFFIObjectHandle*)result);
}

// Called from hot path -- fast path is just an atomic load
int ret = TVMFFIHandleInitOnce(&g_my_func_handle, init_my_func);
if (ret != 0) return ret;
// g_my_func_handle is now guaranteed non-null
```
