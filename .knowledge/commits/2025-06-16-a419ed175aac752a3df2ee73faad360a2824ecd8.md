# Refactor FFI registry to carry complete metadata and remove unordered_map dependency

## TL;DR
- Introduces `TVM_FFI_STATIC_INIT_BLOCK` as the universal static-initialization mechanism and replaces the old `TVM_FFI_REFLECTION_DEF` macro/`ReflectionDef` class with a template-parameterized `ObjectDef<Class>` that deduces type index and type key from the `Class` itself.
- Enriches `TVMFFIFieldInfo` with `size`, `alignment`, and `type_schema` fields (replacing the single `byte_offset` with separate `offset`/`size`/`alignment`), adds `TVMFFITypeExtraInfo` (creator function + total object size), and adds `TVMFFIMethodInfo::type_schema`. Renames enum constants to `kTVMFFI*` prefix convention.
- Removes `std::unordered_map` usage from `TypeTable` and `GlobalFunctionTable`, replacing them with the FFI's own `Map<String, ...>` containers, and converts internal `std::string` keys to `String` objects, eliminating the dependency on `<unordered_map>` in the core registry.

## Impact
- **API (C ABI)**: Breaking changes to C struct layouts and C API surface:
  - `TVMFFIFieldInfo`: `byte_offset` replaced by `offset` + `size` + `alignment`; new `type_schema` field. Any downstream code reading `TVMFFIFieldInfo` directly (Python/Cython bindings, Rust bindings) must be updated.
  - `TVMFFIMethodInfo`: new `type_schema` field added.
  - New C struct `TVMFFITypeExtraInfo` with `doc`, `creator`, `total_size` fields. New C API `TVMFFITypeRegisterExtraInfo`.
  - New C API `TVMFFIFunctionSetGlobalFromMethodInfo` for registering global functions with full method metadata.
  - `TVMFFITypeGetMethod` removed, replaced by `TVMFFITypeRegisterExtraInfo`.
  - `TVMFFIErrorSetRaisedByCStr` renamed to `TVMFFIErrorSetRaisedFromCStr`.
  - `TVMFFITypeInfo`: `fields`/`methods` pointers made `const`; new `extra_info` pointer; `type_key_hash` moved after `type_acenstors`; `TVMFFITypeExtraInfo* extra_info` added.
  - Enum constants renamed: `TVMFFIFieldFlagBitMask*` to `kTVMFFIFieldFlagBitMask*`.
- **API (C++)**: `ReflectionDef` renamed to `ObjectDef<Class>` with `Class` template parameter; `TVM_FFI_REFLECTION_DEF(TypeName)` macro removed in favor of `TVM_FFI_STATIC_INIT_BLOCK({ ObjectDef<TypeName>()... })`.
- **API (GlobalFunctionTable)**: Entries now store `GlobalFunctionTable::Entry` objects (which embed `TVMFFIMethodInfo` metadata) instead of raw `Function*` pointers. This enables richer function metadata (doc strings, type schemas) at the global registry level.
- **Flags/config**: `TVM_FFI_BUILD_REGISTRY` CMake option removed.
- **Data formats/schemas**: `TVMFFIFieldInfo` and `TVMFFIMethodInfo` now include `type_schema` (JSON string) for future type annotation/serialization support.

## Design Elements

Design elements this commit **consumes**:

- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Extends `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, and `TVMFFITypeInfo` C structs. Adds new C API functions and a new struct `TVMFFITypeExtraInfo`.
- **Reflection System** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): Restructures the `ReflectionDef` builder into `ObjectDef<Class>`, changes field offset representation from `byte_offset` to `offset`+`size`+`alignment`, and updates the `FieldGetter`/`FieldSetter` classes to use `field_info_->offset` instead of `field_info_->byte_offset`.
- **Object System** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `TypeTable` internals changed: `std::unordered_map<std::string, int32_t>` replaced with `Map<String, int64_t>`, `type_counter_` widened from `int32_t` to `int64_t`, `Entry::type_key_data` changed from `std::string` to `String`. New `RegisterTypeExtraInfo` method added.
- **Function System** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): `GlobalFunctionTable` redesigned. The old `std::unordered_map<String, Function*>` (intentionally leaked raw pointers) replaced with `Map<String, Any>` holding `GlobalFunctionTable::Entry` objects. `Entry` is a new `Object` subclass embedding `TVMFFIMethodInfo`, enabling metadata-rich function registration.
- **Error Handling** ([`.knowledge/designs/0007-error-handling.md`](../designs/0007-error-handling.md)): `TVMFFIErrorSetRaisedByCStr` renamed to `TVMFFIErrorSetRaisedFromCStr`. Traceback frame exclusion filter updated for the renamed symbol.
- **Container System** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): `Map<String, ...>` now used internally by `TypeTable` and `GlobalFunctionTable`, demonstrating the containers as internal infrastructure, not just user-facing types.

Design elements this commit **produces**:

- **`TVM_FFI_STATIC_INIT_BLOCK` macro** (`include/tvm/ffi/base_details.h`): A general-purpose mechanism for running code during static initialization using a self-invoking lambda assigned to a `static inline` variable. Replaces the macro-per-subsystem pattern (old `TVM_FFI_REFLECTION_REG_VAR_DEF`, old `TVM_FFI_REGISTER_GLOBAL`) with a single, uniform mechanism. This is a **core design element** intended for reuse by all registration patterns.

- **`ObjectDef<Class>` template** (`include/tvm/ffi/reflection/reflection.h`): Replaces `ReflectionDef`. The `Class` template parameter eliminates the need to separately pass `type_index` and `type_key`; they are deduced from `Class::_GetOrAllocRuntimeTypeIndex()` and `Class::_type_key`. This also removes the `Class` template parameter from `def_ro`, `def_rw`, and `GetMethod`, as it is now fixed at the class level.

- **`TVMFFITypeExtraInfo` struct and `TVMFFITypeRegisterExtraInfo` API** (`include/tvm/ffi/c_api.h`, `src/ffi/object.cc`): Enables registering object creation metadata (a `TVMFFIObjectCreator` function pointer and `total_size`) per type index. This is the foundation for reflection-based object construction -- language bindings can call the creator to allocate an empty instance, then use field setters to initialize it.

- **`TVMFFIObjectCreator` typedef** (`include/tvm/ffi/c_api.h`): `int (*)(TVMFFIObjectHandle* result)` -- a C function pointer for creating empty object instances. Part of the `TVMFFITypeExtraInfo` struct.

- **`TVMFFIFunctionSetGlobalFromMethodInfo` API** (`include/tvm/ffi/c_api.h`, `src/ffi/function.cc`): Registers a global function along with its full `TVMFFIMethodInfo` metadata (name, doc, type_schema, flags, function pointer). This enables richer introspection of the global function registry.

- **`GlobalFunctionTable::Entry` class** (`src/ffi/function.cc`): An `Object` subclass that also inherits `TVMFFIMethodInfo`. Stores owned copies of name, doc, type_schema as `String` objects alongside the `Function`. Replaces the old raw `Function*` entries. This means global functions now carry metadata that can be queried at runtime.

- **Enriched `TVMFFIFieldInfo`** (`include/tvm/ffi/c_api.h`): The field metadata struct now carries `size` (field size in bytes), `alignment` (field alignment), and `type_schema` (JSON string describing the field type), in addition to the renamed `offset` field (was `byte_offset`). These enable more precise serialization, memory layout inspection, and code generation from reflection metadata.

## Reflection

### Design docs to write

- **`.knowledge/designs/0008-static-init-registration.md`**: Document the `TVM_FFI_STATIC_INIT_BLOCK` macro pattern, how it replaces per-subsystem registration macros (`TVM_FFI_REFLECTION_DEF`, potentially `TVM_FFI_REGISTER_GLOBAL` in the future), the lambda-in-static-init technique, and the ordering guarantees (or lack thereof) between translation units. This doc helps classify future commits that add new registration patterns or change initialization ordering.
  - Content outline: (1) The `TVM_FFI_STATIC_INIT_BLOCK` mechanism and its implementation via self-invoking lambda, (2) how `ObjectDef<Class>` uses it, (3) ordering constraints and single-threaded init assumption, (4) relationship to existing `TVM_FFI_REGISTER_GLOBAL` which has not yet been migrated.

### ADRs to write

- **`.knowledge/ADRs/0006-global-function-table-entry-redesign.md`**: Records the decision to replace raw `Function*` pointers in `GlobalFunctionTable` with `Object`-based `Entry` nodes holding `TVMFFIMethodInfo` metadata. Context: the old design intentionally leaked raw pointers to avoid Python shutdown issues; the new design uses `Map<String, Any>` with ref-counted entries. The trade-off is that the intentional-leak property documented in `.knowledge/ADRs/0004-global-function-table-leak.md` may need re-evaluation -- the `Map` itself is a ref-counted object, and if it is still allocated via `new` and never deleted, the leak guarantee holds, but the mechanism has changed from raw pointers to ref-counted objects in a leaked container.
  - Decision context: Need richer metadata per global function (doc, type schema) for reflection and tooling.
  - Alternatives: (1) Keep raw `Function*` plus a separate metadata table, (2) store `TVMFFIMethodInfo` alongside `Function*` in a struct without making it an Object.
  - Trade-offs: The new approach unifies metadata storage but changes the memory management model from raw leaked pointers to ref-counted objects in a leaked container.

- **`.knowledge/ADRs/0007-remove-unordered-map-from-registry.md`**: Records the decision to replace `std::unordered_map` with `Map<String, ...>` (the FFI's own container) in `TypeTable` and `GlobalFunctionTable`. Context: reduces dependency on STL containers that may have ABI issues across DLL boundaries; dogfoods the FFI containers internally. Alternatives: keep `std::unordered_map` (simpler), use `absl::flat_hash_map` (better performance). Trade-offs: FFI containers are insertion-order-preserving dense hash tables which may have different performance characteristics than `std::unordered_map`.

### Design diagrams to draw

- **Mermaid: `GlobalFunctionTable::Entry` class hierarchy**. Should depict: `Entry` inheriting both `Object` (for ref-counting) and `TVMFFIMethodInfo` (for metadata), with fields `name_data: String`, `doc_data: String`, `type_schema_data: String`, `func_data: Function`. Show relationship to `Map<String, Any>` table storage.
