# Introduce ShapeView and minimize TensorObj ABI exposure
## TL;DR
- Introduces `ShapeView`, a non-owning lightweight view class for shapes, reducing heap allocations when accessing tensor shape/strides.
- Removes `TensorObj`'s protected cached fields (`shape_data_`, `strides_data_`, `cached_dl_managed_tensor_versioned_`), destructor, and duplicated deleter — the C++ API now depends only on the `DLTensor` field behavior.
- Tensor shape/strides storage moved to inplace allocation after the object struct, eliminating separate managed `Shape` objects and making the ABI more stable.

## Impact
- API: `Tensor::shape()` and `Tensor::strides()` return `ShapeView` instead of `Shape`. Callers that stored the result as `Shape` still work due to `ShapeView(Shape)` implicit conversion and `Shape(ShapeView)` constructor. `Shape::StridesFromShape` signature changed from `(const int64_t*, int64_t)` to `(ShapeView)`. `Tensor::FromNDAlloc` takes `ShapeView` instead of `Shape`.
- Behavioral: `ToDLPackVersioned()` no longer caches the result (each call creates a new `DLManagedTensorVersioned`). `Shape::operator[]` is now unchecked (was bounds-checked); `Shape::at()` is now bounds-checked (was forwarding to unchecked `operator[]`). These are swapped relative to pre-commit behavior.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Object system (`make_object`, `make_inplace_array_object`, `ObjectPtr<T>`, `ObjectRef`) — [0003-ffi-object-system.md](../design-records/0003-ffi-object-system.md)
- `TVMFFIShapeCell` C ABI type — [0001-ffi-c-abi.md](../design-records/0001-ffi-c-abi.md)
- DLPack interop (`DLManagedTensor`, `DLManagedTensorVersioned`) — [0006-ffi-containers.md](../design-records/0006-ffi-containers.md)

Design elements this commit produces:
- `ShapeView`: new non-owning view class for shape data, backed by `TVMFFIShapeCell`. Preferred over `Shape` when ownership is not needed.
- `FillStridesFromShape`: new utility to fill strides into a pre-allocated buffer without creating a `Shape` object.
- Inplace shape/strides storage pattern: tensor subclasses (`TensorObjFromNDAlloc`, `TensorObjFromDLPack`) now store shape and strides as trailing `int64_t` arrays allocated after the struct via `make_inplace_array_object`, removing the need for separate `Shape` objects.
- Unified `DLManagedTensorDeleter<T>` template replacing two separate deleter functions.

Design elements this commit mutates:
- `Tensor::shape()` / `Tensor::strides()` return type changed from `Shape` to `ShapeView`.
- `TensorObj` ABI: removed three protected fields (`shape_data_`, `strides_data_`, `cached_dl_managed_tensor_versioned_`) and the destructor.
- `Shape::operator[]` / `Shape::at()` bounds-checking semantics swapped.

## Usage Examples
Creating and using ShapeView (from test_shape.cc):
```cpp
// Implicit conversion from Shape to ShapeView
Shape shape = Shape({1, 2, 3});
ShapeView view = shape;  // zero-copy, non-owning
assert(view.size() == 3);
assert(view[0] == 1);
assert(view.Product() == 6);

// From raw data
std::vector<int64_t> data = {4, 5, 6};
ShapeView from_data(data.data(), data.size());

// From initializer list
ShapeView from_init = {7, 8, 9};
assert(from_init.Product() == 504);
```

Using new Tensor helpers (from test_tensor.cc):
```cpp
// ShapeView used directly in Empty (implicit conversion from initializer_list)
Tensor nd = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
assert(nd.numel() == 6);       // NEW helper
assert(nd.ndim() == 3);        // NEW helper
assert(nd.data_ptr() == nd->data);  // NEW helper

// shape() and strides() return ShapeView (no heap alloc)
ShapeView s = nd.shape();
ShapeView st = nd.strides();
```
