# Introduce ShapeView non-owning view type and migrate TensorObj layout to inline shape/strides tail allocation

## TL;DR
- Adds `ShapeView`: a lightweight, non-owning wrapper over a `(const int64_t*, size_t)` pair. Supersedes passing `Shape` (heap-allocated `ObjectRef`) in hot paths that only need to read shape data.
- Removes all lazy-cached `shape_data_`/`strides_data_` fields and the `cached_dl_managed_tensor_versioned_` atomic from `TensorObj`. Shape and strides are now stored inline in a tail allocation immediately after the concrete subclass, eliminating two `Optional<Shape>` members and the atomic pointer.
- `Tensor::shape()` and `Tensor::strides()` now return `ShapeView` instead of `Shape`; `Tensor` gains three new accessors: `data_ptr()`, `ndim()`, and `numel()`.

## Key Exports

    Interacts with: TensorObjFromNDAlloc, TensorObjFromDLPack (tail-alloc path)
    Invariant: out_strides must point to a buffer of at least shape.size() int64_t elements
    """

    shape_data_, strides_data_, cached_dl_managed_tensor_versioned_ REMOVED.

    DLManagedTensorDeleter unified into one template: DLManagedTensorDeleter<T>(T*).

## Impact
- API: `Tensor::shape()` and `Tensor::strides()` now return `ShapeView` instead of `Shape`. Callers that assigned the return value into a `Shape` variable still compile (implicit `Shape(ShapeView)` constructor). Callers that held `Shape` for deferred reads after the `Tensor` is destroyed will now have a dangling `ShapeView` — previously they would have held a safe ref-counted `Shape`.
- Behavioral: `ToDLPackVersioned()` no longer returns a cached/shared `DLManagedTensorVersioned`; each call allocates a fresh one and increments the ref-count. The previous atomic CAS caching is removed.
- Flags/config: none
- Data formats/schemas: `TensorObj` C++ ABI changes (fields removed); `kTVMFFITensor` C ABI struct layout unchanged since `DLTensor` is still embedded inline at offset 24. Subclasses (`TensorObjFromNDAlloc`, `TensorObjFromDLPack`) now have a different sizeof() because they use tail allocations.

## Design Elements
Design elements this commit consumes:
- `Shape` / `ShapeObj` (0007-containers): heap-allocated shape, now serves as source for `ShapeView`
- `TensorObj` / `Tensor` (0007-containers): extended with new layout and new accessors
- `make_inplace_array_object<T, Elem>(n, ...)` (0002-object-system, memory.h): used to tail-allocate shape/strides buffers after `TensorObjFromNDAlloc` and `TensorObjFromDLPack`
- `FillStridesFromShape` / `MakeStridesFromShape` (0007-containers): helper utilities refactored to accept `ShapeView`

Design elements this commit produces:
- `ShapeView` — new non-owning view class backed by `TVMFFIShapeCell`; lives in `include/tvm/ffi/container/shape.h`
- `FillStridesFromShape(ShapeView, int64_t*)` — new free function; previously inlined in `MakeStridesFromShape`
- `Tensor::data_ptr()`, `Tensor::ndim()`, `Tensor::numel()` — three new convenience methods on `Tensor`
- Revised `TensorObj` layout invariant: shape/strides are always in tail allocation, never in `Optional<Shape>` fields

## Usage Examples

**ShapeView construction and use in C++** (from `tests/cpp/test_shape.cc`):
```cpp
Shape shape = Shape({1, 2, 3});
ShapeView sv = shape;              // implicit conversion
assert(sv.size() == 3);
assert(sv[1] == 2);
assert(sv.Product() == 6);

// From raw pointer + size (zero-copy view over existing buffer)
std::vector<int64_t> data = {4, 5, 6};
ShapeView view(data.data(), data.size());

// From initializer list (borrowed from temporaries — valid for the statement)
ShapeView init_view = {7, 8, 9};
assert(init_view.Product() == 7 * 8 * 9);
```

**Tensor construction with ShapeView** (from `tests/cpp/test_tensor.cc`):
```cpp
// Before: Tensor::FromNDAlloc accepted ffi::Shape (heap object required)
// After:  accepts ffi::ShapeView — can pass initializer list directly
Tensor nd = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
assert(nd.ndim() == 3);
assert(nd.numel() == 6);
assert(nd.data_ptr() == nd->data);
ShapeView sv = nd.shape();   // non-owning; valid while nd is alive
```
