# Introduce ShapeView non-owning view and eliminate TensorObj managed shape/strides fields via inplace tail allocation
## TL;DR
- Adds `ShapeView`, a lightweight non-owning view over `int64_t*` shape data, with full iteration, indexing, bounds-checking, and `Product()` support.
- Removes `TensorObj::shape_data_`, `TensorObj::strides_data_`, and `TensorObj::cached_dl_managed_tensor_versioned_` fields -- shape and strides are now stored as inplace `int64_t` arrays allocated at the tail of the TensorObj memory block via `make_inplace_array_object`.
- `Tensor::shape()` and `Tensor::strides()` now return `ShapeView` instead of `Shape`, eliminating heap allocation for shape access. `Shape::StridesFromShape` and `details::MakeStridesFromShape` now accept `ShapeView` instead of raw pointer + count.
- Unifies `DLManagedTensorDeleter` and `EmbeddedDLManagedTensorVersionedDeleter` into a single template `DLManagedTensorDeleter<T>`, and removes the atomic caching of `DLManagedTensorVersioned`.

## Impact
- API: `Tensor::shape()` and `Tensor::strides()` return `ShapeView` instead of `Shape`. Callers that assigned to `Shape` still work via implicit conversion. `Shape::operator[]` is no longer bounds-checked; callers relying on bounds-check must use `Shape::at()`. `Shape::StridesFromShape` signature changed from `(const int64_t*, int64_t)` to `(ShapeView)`. `Tensor::FromNDAlloc` shape parameter changed from `Shape` to `ShapeView`.
- Behavioral: `TensorObj::ToDLPackVersioned()` no longer caches the result atomically; each call allocates a new `DLManagedTensorVersioned`. The destructor for `TensorObj` is removed (no cached pointer to clean up). `DLManagedTensorDeleter` is now a template shared by both DLPack v1 and pre-v1 paths.
- Flags/config: version bumped to `0.1.0b10`.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Object system / InplaceArrayBase / `make_inplace_array_object`** (`.knowledge/designs/0002-object-system.md`): Used for tail-allocating shape+strides int64 arrays after TensorObj struct.
- **TVMFFIShapeCell** (`.knowledge/designs/0001-c-abi.md`): `ShapeView` wraps this C ABI struct as its internal storage.
- **DLPack protocol** (`.knowledge/designs/0007-containers.md`): Import/export paths updated but protocol unchanged.

Design elements this commit produces:
- **ShapeView**: New non-owning lightweight view type for shape data, intended as the default parameter and return type when heap allocation is unnecessary.
- **Inplace shape/strides layout for TensorObj**: Shape and strides are now tail-allocated as raw int64_t arrays after the object struct, eliminating the need for separate `Optional<Shape>` fields and their associated heap allocations.
- **FillStridesFromShape**: New utility that writes strides into a caller-provided buffer without allocating.
- **Tensor convenience accessors**: `data_ptr()`, `ndim()`, `numel()`.

## Usage Examples

Creating and using ShapeView (from test_shape.cc):
```cpp
// Implicit conversion from Shape to ShapeView
Shape shape = Shape({1, 2, 3});
ShapeView view = shape;           // implicit via operator ShapeView()
assert(view.size() == 3);
assert(view[0] == 1);
assert(view.Product() == 6);

// Construct from raw data
std::vector<int64_t> data = {4, 5, 6};
ShapeView view2(data.data(), data.size());

// Construct from initializer_list
ShapeView view3 = {7, 8, 9};

// ShapeView as Tensor::FromNDAlloc parameter (no Shape allocation needed)
Tensor t = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
assert(t.numel() == 6);
assert(t.ndim() == 3);
assert(t.data_ptr() == t->data);
```
