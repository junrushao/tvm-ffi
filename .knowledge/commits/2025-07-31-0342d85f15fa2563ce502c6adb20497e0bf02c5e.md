# Fix SmallMapObj::CreateFromRange to deduplicate keys
## TL;DR
- `MapObj::CreateFromRange` for small maps (cap < `kMaxSize=4`) used `SmallMapObj::CreateFromRange`, which bulk-copied input KV pairs via placement-new without checking for duplicate keys. Duplicate keys violated the map's unique-key invariant.
- Fix: for cap >= 2, use `SmallMapObj::Empty` + `InsertMaybeReHash` loop (which checks `find` before inserting). Cap < 2 cannot have duplicates and keeps the fast bulk-copy path.
- The `DenseMapObj` path (cap >= `kMaxSize`) already used `InsertMaybeReHash` and was unaffected.

## Key Exports
None -- no new APIs. The fix changes the internal initialization path of `MapObj::CreateFromRange`.

## Impact
- API: None -- `Map<K,V>` constructor signature unchanged.
- Behavioral: `Map` constructed from a range with duplicate keys now correctly deduplicates (last value wins), matching `DenseMapObj` behavior. Previously, `SmallMapObj` would store all duplicates, leading to `size()` reporting the wrong count and iteration visiting ghost entries.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Map insertion-order invariant** (`0006-ffi-containers`): `SmallMapObj::InsertMaybeReHash` already enforced unique keys on single insertions; the bug was that `CreateFromRange` bypassed it.
- **SmallMapObj / DenseMapObj duality**: Maps below `kMaxSize=4` entries use the linear-scan `SmallMapObj`; larger maps use the hash-table `DenseMapObj`. Both must enforce the same unique-key contract.

Design elements this commit produces:
- None -- restores an existing invariant rather than introducing new design.

## Usage Examples
**Before (buggy)**: constructing a `Map` from a range with duplicate keys produced a corrupted small map.
```cpp
// BEFORE: SmallMapObj::CreateFromRange bulk-copied all 3 entries
std::vector<std::pair<String, int>> data = {{"a", 1}, {"a", 2}, {"a", 3}};
Map<String, int> map(data.begin(), data.end());
// map.size() == 3  (WRONG -- should be 1)
```

**After (fixed)**: duplicate keys are deduplicated, last value wins.
```cpp
// AFTER: SmallMapObj::InsertMaybeReHash deduplicates via find()
std::vector<std::pair<String, int>> data = {{"a", 1}, {"a", 2}, {"a", 3}};
Map<String, int> map(data.begin(), data.end());
// map.size() == 1, map["a"] == 3  (CORRECT)
```
