# Fix SmallMapObj initialization to deduplicate keys when cap >= 2
## TL;DR
- `SmallMapObj::CreateFromRange` did not deduplicate keys, so constructing a small map from an iterator range with duplicate keys produced a map with multiple entries for the same key, violating the map uniqueness invariant.
- The fix routes small-map creation (cap >= 2) through `SmallMapObj::InsertMaybeReHash` instead of `SmallMapObj::CreateFromRange`, matching the deduplication behavior already used by `DenseMapObj`.
- Adds a regression test `Map.DuplicatedKeysInit` that constructs a map with three entries sharing the same key and asserts size == 1 with last-writer-wins semantics.

## Key Exports
None -- no public API changes. The fix is internal to `MapObj::CreateFromRange`.

## Impact
- API: None -- no signature changes.
- Behavioral: `Map<K,V>` constructed from an iterator range with duplicate keys now correctly deduplicates, keeping the last value for each key. Previously, small maps (cap < `SmallMapObj::kMaxSize`) would silently contain duplicate keys.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **MapObj::CreateFromRange** (`include/tvm/ffi/container/map.h`) -- the dispatch point that routes to SmallMapObj or DenseMapObj based on capacity. See `0006-containers`.
- **SmallMapObj::InsertMaybeReHash** -- insert-with-dedup for the small (linear-probe) map representation. Already handled duplicates correctly.
- **SmallMapObj::CreateFromRange** -- bulk-copy construction that does NOT handle duplicates (placement-new loop). Only safe for cap < 2 after this fix.
- **DenseMapObj::InsertMaybeReHash** -- insert-with-dedup for the dense (hash-table) map representation. Was already used in the dense path, so the dense path was not affected by this bug.

Design elements this commit produces:
- None -- no new design elements. The fix tightens the invariant enforcement in an existing code path.

## Usage Examples
**Before (buggy)**: constructing a small map from a range with duplicate keys produced invalid state.
```cpp
// BEFORE: SmallMapObj::CreateFromRange blindly copied all 3 entries
std::vector<std::pair<String, int>> data = {{"a", 1}, {"a", 2}, {"a", 3}};
Map<String, int> map(data.begin(), data.end());
// map.size() == 3  (BUG: should be 1)
// map contained three entries with key "a"
```

**After (fixed)**: deduplication via InsertMaybeReHash ensures last-writer-wins.
```cpp
// AFTER: SmallMapObj::InsertMaybeReHash deduplicates during insertion
std::vector<std::pair<String, int>> data = {{"a", 1}, {"a", 2}, {"a", 3}};
Map<String, int> map(data.begin(), data.end());
// map.size() == 1  (correct)
// map["a"] == 3    (last writer wins)
```
