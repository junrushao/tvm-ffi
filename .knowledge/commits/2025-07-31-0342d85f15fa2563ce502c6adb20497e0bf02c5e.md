# Fix SmallMapObj duplicate key handling in CreateFromRange
## TL;DR
- `MapObj::CreateFromRange` previously passed small-map-sized ranges directly to `SmallMapObj::CreateFromRange`, which bulk-copied entries without deduplication, violating the map key uniqueness invariant when duplicate keys were present.
- The fix routes small maps with `cap >= 2` through `SmallMapObj::Empty` + `SmallMapObj::InsertMaybeReHash` loop (which handles duplicates via overwrite), preserving the fast path for `cap < 2` where duplicates are impossible.
- Added `TEST(Map, DuplicatedKeysInit)` confirming that `Map(data.begin(), data.end())` with repeated keys yields a single entry with the last value.

## Key Exports
None -- no new public API surface. The fix is internal to `MapObj::CreateFromRange`.

## Impact
- API: None -- `Map` constructor signatures unchanged.
- Behavioral: `Map<K,V>` constructed from an iterator range containing duplicate keys now correctly deduplicates, keeping the last value for each key (consistent with `DenseMapObj` behavior and Python `dict` semantics). Previously, the small map path would store all duplicate entries, leading to an oversized `size_` and incorrect lookups.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`MapObj::CreateFromRange`** (`include/tvm/ffi/container/map.h`): The top-level factory that dispatches to `SmallMapObj` or `DenseMapObj` based on capacity. This is the function being fixed.
- **`SmallMapObj::InsertMaybeReHash`** (`include/tvm/ffi/container/map.h`): Insertion method that checks for existing keys and overwrites values on collision. Already existed but was not used in the small-map `CreateFromRange` path.
- **`SmallMapObj::Empty(uint64_t n)`**: Allocates an empty small map with capacity `n`. Used in the new deduplication path.
- **`SmallMapObj::CreateFromRange(uint64_t n, IterType first, IterType last)`**: Bulk-copy constructor that does NOT deduplicate. Still used for `cap < 2` fast path.
- **Map key uniqueness invariant** (documented in [0008-containers.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0008-containers.md)): Each key appears at most once.

Design elements this commit produces:
- None -- no new design elements. The commit restores an existing invariant.

## Usage Examples
**Before (bug)**: Constructing a small map from a range with duplicate keys silently stored all duplicates:
```cpp
std::vector<std::pair<String, int>> data = {{"a", 1}, {"a", 2}, {"a", 3}};
Map<String, int> map(data.begin(), data.end());
// BUG: map.size() == 3, not 1
// BUG: map["a"] behavior undefined (multiple "a" entries in storage)
```

**After (fix)**: Duplicate keys are properly deduplicated, last value wins:
```cpp
std::vector<std::pair<String, int>> data = {{"a", 1}, {"a", 2}, {"a", 3}};
Map<String, int> map(data.begin(), data.end());
// CORRECT: map.size() == 1
// CORRECT: map["a"] == 3 (last value wins)
```
