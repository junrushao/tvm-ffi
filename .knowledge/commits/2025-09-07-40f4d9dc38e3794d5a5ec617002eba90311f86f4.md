# Cleanup tvm_ffi Python API: rename public symbols, extract DLDeviceType enum, remove device convenience wrappers
## TL;DR
- Renames core public API symbols to be more explicit and consistent with PyTorch conventions: `register_func` -> `register_global_func`, `_init_api` -> `init_ffi_api`, `ObjectGeneric` -> `ObjectConvertible`, `device_id` -> `index`, `device_type` property -> `type` (str) + `dlpack_device_type()` (int method).
- Extracts device type constants from `Device` class attributes into a standalone `DLDeviceType(IntEnum)` enum; removes per-device convenience functions (`cpu()`, `cuda()`, `rocm()`, etc.) from tvm_ffi top-level exports.
- Renames internal modules with underscore prefix (`convert.py` -> `_convert.py`, `dtype.py` -> `_dtype.py`, `tensor.py` -> `_tensor.py`), marks internal dict attributes private (`DEVICE_TYPE_TO_NAME` -> `_DEVICE_TYPE_TO_NAME`, `NUMPY_DTYPE_TO_STR` -> `_NUMPY_DTYPE_TO_STR`), removes `String`, `Bytes`, `DataTypeCode`, `ModulePropertyMask` from `__all__`.

### Removed from `tvm_ffi.__all__`

| Symbol | Reason |
|--------|--------|
| `cpu()`, `cuda()`, `rocm()`, `opencl()`, `metal()`, `vpi()`, `vulkan()`, `ext_dev()`, `hexagon()`, `webgpu()` | Convenience wrappers removed; use `device("cuda", 0)` instead |
| `String`, `Bytes` | Moved to `tvm_ffi.core` only |
| `DataTypeCode` | Removed from public exports |
| `ModulePropertyMask` | Removed from public exports (stays in `module.py` internally) |

## Impact
- API: Breaking. All renamed symbols (`register_func`, `_init_api`, `ObjectGeneric`, `Device.device_id`, `Device.device_type`) no longer exist at their old names. All callers using `tvm_ffi.register_func`, `tvm_ffi._init_api`, `Device.device_id`, `Device.device_type`, `tvm_ffi.cpu()`, `tvm_ffi.cuda()`, etc. must update. `tvm_ffi.String` / `tvm_ffi.Bytes` callers must use `tvm_ffi.core.String` / `tvm_ffi.core.Bytes`.
- Behavioral: `Device.__init__` parameter renamed from `device_type_or_name` to `device_type` and `device_id` to `index`. The `device()` function parameter changed from `dev_type, dev_id=0` to `device_type, index=None`. The Device string-parsing path gains suffix annotation stripping (`device_type_or_name.split(" ")[0]`), previously only in the `device()` function.
- Flags/config: None
- Data formats/schemas: None (DLDevice C struct unchanged)

## Design Elements
Design elements this commit consumes:
- **Device / DLDevice wrapper** (designs/0012-python-bindings.md) -- refactors its Python-level API
- **Global function registry** (designs/0004-function-system.md, designs/0012-python-bindings.md) -- renames Python-side registration/init functions
- **Object type conversion** (designs/0012-python-bindings.md) -- renames `ObjectGeneric` to `ObjectConvertible` in make_args dispatch

Design elements this commit produces:
- **DLDeviceType enum** -- new standalone `IntEnum` separating device type constants from the `Device` class; aligns with DLPack specification naming
- **Torch-style Device API** -- `Device.type` (str), `Device.index` (int), `Device.dlpack_device_type()` (int) mirrors `torch.device` interface

## Usage Examples

Before/after showing the calling convention change:

```python
# BEFORE (old API)
import tvm_ffi

@tvm_ffi.register_func("my.echo")
def echo(x): return x

tvm_ffi._init_api("my_pkg", __name__)

dev = tvm_ffi.cuda(0)  # convenience function
assert dev.device_type == tvm_ffi.Device.kDLCUDA
assert dev.device_id == 0

# AFTER (new API)
import tvm_ffi

@tvm_ffi.register_global_func("my.echo")
def echo(x): return x

tvm_ffi.init_ffi_api("my_pkg", __name__)

dev = tvm_ffi.device("cuda", 0)  # explicit construction
assert dev.dlpack_device_type() == tvm_ffi.DLDeviceType.kDLCUDA
assert dev.index == 0
assert dev.type == "cuda"
```
