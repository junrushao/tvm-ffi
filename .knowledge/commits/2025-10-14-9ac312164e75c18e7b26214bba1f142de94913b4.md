# Remove auto-registration side-effect from object macros; require explicit ObjectDef or ReserveDepthOneObjectTypeIndex for all built-in types

## TL;DR
- `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` and `TVM_FFI_DECLARE_OBJECT_INFO` (dynamic) no longer carry a `static inline` field that triggers `_GetOrAllocRuntimeTypeIndex()` at DLL-load time; objects must now be explicitly registered via `reflection::ObjectDef<T>` or an equivalent call.
- `TypeTable` constructor gains explicit `ReserveDepthOneObjectTypeIndex` calls for all 10 built-in depth-1 object types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject), replacing the previous ad-hoc single-call for OpaquePyObject.
- `StaticTypeKey::kTVMFFIError = "ffi.Error"` is added to the static key table so `ErrorObj` references the central constant rather than an inline string literal.

## Key Exports

```python
# TVM_FFI_DECLARE_OBJECT_INFO_STATIC(TypeKey, TypeName, ParentType)
# Contract CHANGE (was):
#   static inline int32_t _register_type_index = _GetOrAllocRuntimeTypeIndex()
#   RuntimeTypeIndex() { return _GetOrAllocRuntimeTypeIndex(); }
# Contract NOW:
#   _GetOrAllocRuntimeTypeIndex() runs lazily (only when called explicitly)
#     - sets tindex [[maybe_unused]] = TVMFFITypeGetOrAllocIndex(...)
#     - returns TypeName::_type_index  (compile-time constant, NOT tindex)
#   RuntimeTypeIndex() { return TypeName::_type_index; }   # compile-time constant
#   static inline _register_type_index field REMOVED
#
# Invariant: for static-index types, _type_index is a compile-time constant;
#   RuntimeTypeIndex() no longer triggers registration as a side-effect.
# Extension: explicit registration required via ObjectDef<T>() or
#   TypeName::_GetOrAllocRuntimeTypeIndex() once per process.

# TVM_FFI_DECLARE_OBJECT_INFO(TypeKey, TypeName, ParentType)   [dynamic variant]
# Contract CHANGE (was):
#   static inline int32_t _type_index = _GetOrAllocRuntimeTypeIndex()
# Contract NOW:
#   _type_index field REMOVED; RuntimeTypeIndex() still calls _GetOrAllocRuntimeTypeIndex()
# Invariant: first call to RuntimeTypeIndex() or _GetOrAllocRuntimeTypeIndex() triggers registration.

class TypeTable:
    """Runtime type index registry; built-in types pre-reserved in constructor."""

    def __init__(self):
        # Previously: only OpaquePyObject was registered explicitly here
        # Now: all 10 depth-1 builtin types are reserved via ReserveDepthOneObjectTypeIndex
        self.ReserveBuiltinTypeIndex(StaticTypeKey.kTVMFFISmallStr, TypeIndex.kTVMFFISmallStr)
        self.ReserveBuiltinTypeIndex(StaticTypeKey.kTVMFFISmallBytes, TypeIndex.kTVMFFISmallBytes)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIStr, TypeIndex.kTVMFFIStr)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIBytes, TypeIndex.kTVMFFIBytes)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIError, TypeIndex.kTVMFFIError)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIFunction, TypeIndex.kTVMFFIFunction)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIShape, TypeIndex.kTVMFFIShape)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFITensor, TypeIndex.kTVMFFITensor)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIArray, TypeIndex.kTVMFFIArray)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIMap, TypeIndex.kTVMFFIMap)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIModule, TypeIndex.kTVMFFIModule)
        self.ReserveDepthOneObjectTypeIndex(StaticTypeKey.kTVMFFIOpaquePyObject, TypeIndex.kTVMFFIOpaquePyObject)

    def ReserveDepthOneObjectTypeIndex(self, type_key: str, static_type_index: int32_t):
        # Interacts with: GetOrAllocTypeIndex with type_depth=1, parent=kTVMFFIObject
        self.GetOrAllocTypeIndex(type_key, static_type_index, depth=1, child_slots=0,
                                 overflow=False, parent=TypeIndex.kTVMFFIObject)

class StaticTypeKey:
    kTVMFFIError: str = "ffi.Error"   # NEW — was previously an inline string literal in error.h
    # Interacts with: ErrorObj._type_key, TypeTable.ReserveDepthOneObjectTypeIndex
```

## Impact
- API: `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` and `TVM_FFI_DECLARE_OBJECT_INFO` macro contracts changed — the hidden `_register_type_index` / `_type_index` static inline fields are removed. Any code that referenced `SomeObj::_type_index` on dynamic objects (which is now gone) will fail to compile. Tests updated from `TIntObj::_type_index` to `TIntObj::RuntimeTypeIndex()`.
- Behavioral: Objects declared via these macros but NOT registered through `ObjectDef<T>` will no longer have their type index populated; `IsA<T>()` and `as<T>()` casts will silently fail or return wrong results for such types. The commit accepts this trade-off: all practically useful `ObjectRef` types must use `ObjectDef`.
- Flags/config: none
- Data formats/schemas: none; `TVMFFIObject` binary layout unchanged

## Usage Examples

Before (auto-registration via static inline field on header include):
```cpp
// In FooObj header (included by any TU):
// TVM_FFI_DECLARE_OBJECT_INFO_STATIC("ns.Foo", FooObj, Object) would expand to:
//   static inline int32_t _register_type_index = _GetOrAllocRuntimeTypeIndex();
// Side-effect: type registered on first DLL that includes the header, even if unused.
```

After (explicit registration required in .cc file):
```cpp
// In foo.cc — must register once explicitly:
TVM_FFI_STATIC_INIT_BLOCK() {
    reflection::ObjectDef<FooObj>()  // this calls _GetOrAllocRuntimeTypeIndex()
      .def_field("name", &FooObj::name);
}
// Without this call, IsA<Foo>(obj) and obj.as<Foo>() won't work correctly.
```
