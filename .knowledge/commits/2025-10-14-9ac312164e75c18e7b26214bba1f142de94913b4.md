# Remove static inline object registration from headers in favor of explicit ObjectDef

## TL;DR
- Removes `static inline int32_t _register_type_index` and `static inline int32_t _type_index` auto-registration from `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` and `TVM_FFI_DECLARE_OBJECT_INFO` macros, eliminating per-DLL binary overhead from unused object types.
- Object types now require explicit registration via `reflection::ObjectDef<T>()` or calling `_GetOrAllocRuntimeTypeIndex()` once in a `.cc` file.
- All builtin depth-1 object types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject) are pre-registered in `TypeTable`'s constructor via new `ReserveDepthOneObjectTypeIndex`.

## Key Exports

**Modified macros** (`object.h`):
- `TVM_FFI_DECLARE_OBJECT_INFO_STATIC(TypeKey, TypeName, ParentType)` -- no longer contains `static inline int32_t _register_type_index`. `_GetOrAllocRuntimeTypeIndex()` now returns `TypeName::_type_index` (the static constant) rather than the dynamically allocated value. The `[[maybe_unused]]` attribute suppresses warnings on the now-unused side-effect variable.
- `TVM_FFI_DECLARE_OBJECT_INFO(TypeKey, TypeName, ParentType)` -- removed `static int32_t _type_index = _GetOrAllocRuntimeTypeIndex()`. Registration must be done explicitly.
- `TVM_FFI_DECLARE_OBJECT_INFO_FINAL(TypeKey, TypeName, ParentType)` -- same removal.

**New constant**: `StaticTypeKey::kTVMFFIError = "ffi.Error"` -- added to complete the set of builtin type keys.

**New method**: `TypeTable::ReserveDepthOneObjectTypeIndex(const char* type_key, int32_t static_type_index)` -- registers a builtin object type at depth 1 with parent `kTVMFFIObject`.

## Impact
- API: **Breaking for downstream** -- any custom `Object` subclass using `TVM_FFI_DECLARE_OBJECT_INFO` that relied on auto-registration must now call `ObjectDef<T>()` or `T::_GetOrAllocRuntimeTypeIndex()` explicitly. Dynamic casting (`Downcast`) won't work without registration.
- Behavioral: Reduces binary size by eliminating per-DLL static initialization for every header-included object type.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit mutates:
- **Object registration contract** -- changes from "auto-registered on header include" to "must be explicitly registered via ObjectDef or _GetOrAllocRuntimeTypeIndex". This is a significant invariant change.
- **Builtin type table initialization** -- all 10 depth-1 builtin types are now pre-registered in the TypeTable constructor, no longer relying on static initializers in their header files.

## Usage Examples

**Before** (auto-registration, now removed):
```cpp
// Just including the header was enough to register the type
#include <tvm/ffi/my_object.h>
// MyObj could be used in Downcast immediately
```

**After** (explicit registration required):
```cpp
// In my_object.cc:
#include <tvm/ffi/my_object.h>
TVM_FFI_STATIC_INIT_BLOCK() {
  tvm::ffi::reflection::ObjectDef<MyObj>()
      .def_ro("field", &MyObj::field, "description");
}
// Or minimally: call MyObj::_GetOrAllocRuntimeTypeIndex() once
```
