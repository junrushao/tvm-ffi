# Remove static-inline object type registration in favor of explicit ObjectDef

## TL;DR
- Removed the `static inline int32_t _register_type_index` / `_type_index = _GetOrAllocRuntimeTypeIndex()` side-effect variables from all three object declaration macros (`STATIC`, `PREDEFINED_TYPE_KEY`, `INFO`/`INFO_FINAL`). Type registration no longer happens automatically at static initialization.
- Registration is now explicit: each type must call `reflection::ObjectDef<T>()` in a `.cc` file (or manually call `_GetOrAllocRuntimeTypeIndex()` once). Built-in types with static indices are pre-registered in `TypeTable::TypeTable()`.
- Added `ReserveDepthOneObjectTypeIndex()` helper and explicit registration calls for all 10 built-in depth-1 object types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject) in the TypeTable constructor.

## Key Exports

```python
# --- Macro changes (object.h) ---

# TVM_FFI_DECLARE_OBJECT_INFO_STATIC now:
#   1. Marks tindex as [[maybe_unused]] (no longer returned)
#   2. Returns TypeName::_type_index (the static constant) instead of tindex
#   3. Removes _register_type_index side-effect variable
#   4. Moves _type_key assignment to end of macro
# Old: static inline int32_t _register_type_index = _GetOrAllocRuntimeTypeIndex()
# New: (removed entirely -- registration is caller's responsibility)

# TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY now:
# Old: static int32_t _type_index = _GetOrAllocRuntimeTypeIndex()
# New: (removed -- caller must trigger _GetOrAllocRuntimeTypeIndex() explicitly)

# --- New StaticTypeKey constant (object.h) ---
class StaticTypeKey:
    kTVMFFIError: str = "ffi.Error"  # NEW -- was only a string literal before
    # Interacts with: ErrorObj declaration, TypeTable::ReserveDepthOneObjectTypeIndex

# --- TypeTable changes (object.cc) ---
class TypeTable:
    def ReserveDepthOneObjectTypeIndex(self, type_key: str, static_type_index: int) -> None:
        """Register a built-in depth-1 Object type in the type table at startup."""
        self.GetOrAllocTypeIndex(
            String(type_key), static_type_index,
            type_depth=1, num_child_slots=0,
            child_slots_can_overflow=False,
            parent_type_index=TypeIndex.kTVMFFIObject
        )
        # Interacts with: TypeTable constructor, TVMFFITypeGetOrAllocIndex
        # Invariant: must be called before any ObjectDef<T> or _GetOrAllocRuntimeTypeIndex for these types
```

## Impact
- API: The macros no longer auto-register types. Any user-defined Object type that relied on implicit static-init registration will need an explicit `reflection::ObjectDef<T>()` call in a `.cc` file. Without it, dynamic casting (`IsInstance`, `as<T>`) will not work for that type.
- Behavioral: `_GetOrAllocRuntimeTypeIndex()` on static-index types now returns the pre-assigned `_type_index` constant directly (instead of the `tindex` from `TVMFFITypeGetOrAllocIndex`). The `tindex` local is marked `[[maybe_unused]]` and its only purpose is the side-effect of populating the type table.
- Flags/config: none
- Data formats/schemas: none

- **`StaticTypeKey::kTVMFFIError`** constant added to `object.h` for the Error type key (previously a raw string literal in `error.h`).

## Usage Examples

Before (implicit registration via static init):
```cpp
// In header -- type was automatically registered when any TU included the header
class MyNodeObj : public Object {
 public:
  TVM_FFI_DECLARE_OBJECT_INFO("test.MyNode", MyNodeObj, Object);
  // Expansion included: static int32_t _type_index = _GetOrAllocRuntimeTypeIndex();
  // Registration happened implicitly at static init
};
```

After (explicit registration required):
```cpp
// In header -- macro no longer triggers registration
class MyNodeObj : public Object {
 public:
  TVM_FFI_DECLARE_OBJECT_INFO("test.MyNode", MyNodeObj, Object);
  // No static-init side effect; must register explicitly
};

// In .cc file -- explicit registration
TVM_FFI_STATIC_INIT_BLOCK() {
  reflection::ObjectDef<MyNodeObj>()
      .def_field("name", &MyNodeObj::name);
  // ObjectDef<T>() calls _GetOrAllocRuntimeTypeIndex() internally
}
```
