# Remove static inline type registration from object macros, requiring explicit ObjectDef registration
## TL;DR
- Removes the `static inline int32_t _register_type_index` / `static inline int32_t _type_index` auto-registration variables from `TVM_FFI_DECLARE_OBJECT_INFO_STATIC`, `TVM_FFI_DECLARE_OBJECT_INFO`, and `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY` macros, eliminating per-DLL static init overhead for unused types.
- Compensates by pre-registering all built-in depth-1 object types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject) in the `TypeTable` constructor via a new `ReserveDepthOneObjectTypeIndex` helper.
- Adds `StaticTypeKey::kTVMFFIError` constant and switches `ErrorObj` to use it instead of a string literal.

## Impact
- API: The `TVM_FFI_REGISTER_STATIC_TYPE_INFO` internal macro is removed. `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` first parameter now expects a `StaticTypeKey` constant instead of a string literal (breaking for any external user of this macro, though it is an internal macro). Dynamic-index macros (`TVM_FFI_DECLARE_OBJECT_INFO`, `TVM_FFI_DECLARE_OBJECT_INFO_FINAL`) no longer auto-register at static init -- callers must ensure `ObjectDef<T>()` or `_GetOrAllocRuntimeTypeIndex()` is called once.
- Behavioral: Without explicit registration via `ObjectDef<T>`, `IsInstance` / dynamic casting for user-defined types will not work. Built-in types are now pre-registered in `TypeTable` constructor, so they work without `ObjectDef`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object type registration macros** (`TVM_FFI_DECLARE_OBJECT_INFO_STATIC`, `TVM_FFI_DECLARE_OBJECT_INFO`, `TVM_FFI_DECLARE_OBJECT_INFO_FINAL`) -- see `.knowledge/designs/0002-object-system.md`
- **StaticTypeKey constants** -- centralized type key strings, see `.knowledge/designs/0002-object-system.md`
- **TypeTable / global type registry** -- runtime type index allocation, see `.knowledge/designs/0002-object-system.md`
- **reflection::ObjectDef<T>** -- the reflection builder that now becomes the required registration path, see `.knowledge/designs/0008-reflection.md`

Design elements this commit produces:
- **`ReserveDepthOneObjectTypeIndex`** -- new TypeTable helper that pre-registers Object-derived types at depth 1 during TypeTable construction (centralizes what was previously scattered across static inits)
- **`StaticTypeKey::kTVMFFIError`** -- new constant for the Error type key
- **Explicit registration contract** -- the invariant that user-defined Object types must call `ObjectDef<T>()` (or manually `_GetOrAllocRuntimeTypeIndex()`) to enable dynamic casting

## Usage Examples
Before (implicit registration -- worked automatically):
```cpp
// Just declaring the macro was enough; static init auto-registered the type
class MyObj : public Object {
 public:
  TVM_FFI_DECLARE_OBJECT_INFO("my.Obj", MyObj, Object);
};
// IsInstance<MyObj> works immediately -- _type_index static init triggered registration
```

After (explicit registration required):
```cpp
// Declaration alone does NOT register the type anymore
class MyObj : public Object {
 public:
  TVM_FFI_DECLARE_OBJECT_INFO("my.Obj", MyObj, Object);
};

// Must explicitly register in a .cc file:
TVM_FFI_STATIC_INIT_BLOCK() {
  tvm::ffi::reflection::ObjectDef<MyObj>();  // triggers _GetOrAllocRuntimeTypeIndex()
}
// Now IsInstance<MyObj> works
```
