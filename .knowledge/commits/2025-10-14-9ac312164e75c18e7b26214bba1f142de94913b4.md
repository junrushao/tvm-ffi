# Remove static inline auto-registration from object macros, require explicit ObjectDef registration
## TL;DR
- Removes `static inline int32_t` auto-registration triggers from `TVM_FFI_DECLARE_OBJECT_INFO_STATIC`, `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY`, and `TVM_FFI_DECLARE_OBJECT_INFO` macros, eliminating per-DLL binary bloat from unused type registrations.
- Pre-registers all depth-1 static object types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject) centrally in TypeTable constructor via new `ReserveDepthOneObjectTypeIndex` helper.
- Dynamic object types now require explicit `reflection::ObjectDef<T>()` or `_GetOrAllocRuntimeTypeIndex()` call in a `.cc` file for runtime type registration.

## Key Exports
```python
# --- Macro changes (include/tvm/ffi/object.h) ---

# TVM_FFI_DECLARE_OBJECT_INFO_STATIC(TypeKey, TypeName, ParentType)
# BEFORE: included `static inline int32_t _register_type_index = _GetOrAllocRuntimeTypeIndex()`
#         which auto-registered at DLL load in every translation unit
# AFTER:  `_GetOrAllocRuntimeTypeIndex()` still exists but its result is [[maybe_unused]]
#         and the function returns TypeName::_type_index (compile-time constant)
#         No static inline variable; registration is NOT triggered by inclusion alone
#         TypeKey parameter now accepts StaticTypeKey::kXxx constants (not just string literals)
# Invariant: requires explicit ObjectDef<T>() or _GetOrAllocRuntimeTypeIndex() call for dynamic casting to work

# TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY(TypeName, ParentType)
# BEFORE: included `static inline int32_t _type_index = _GetOrAllocRuntimeTypeIndex()`
# AFTER:  no static inline variable; RuntimeTypeIndex() still calls _GetOrAllocRuntimeTypeIndex()
# Invariant: same explicit registration requirement

# TVM_FFI_DECLARE_OBJECT_INFO(TypeKey, TypeName, ParentType)
# Changed: inherits the removal from PREDEFINED_TYPE_KEY; adds documentation directing
#          users to call ObjectDef<T>() or _GetOrAllocRuntimeTypeIndex()
# Interacts with: reflection::ObjectDef (0008-reflection)

# TVM_FFI_DECLARE_OBJECT_INFO_FINAL(TypeKey, TypeName, ParentType)
# Changed: same as DECLARE_OBJECT_INFO -- now documents ObjectDef requirement

# --- New helper in TypeTable (src/ffi/object.cc) ---
class TypeTable:
    def ReserveDepthOneObjectTypeIndex(type_key: str, static_type_index: int32) -> None:
        """Pre-register a depth-1 Object type in the type table at init time."""
        # Calls GetOrAllocTypeIndex(type_key, static_type_index, depth=1,
        #   num_child_slots=0, can_overflow=False, parent=kTVMFFIObject)
        # Interacts with: TypeTable constructor, all static Object subclasses

# --- New StaticTypeKey constant (include/tvm/ffi/object.h) ---
class StaticTypeKey:
    kTVMFFIError: str = "ffi.Error"   # NEW
    # Interacts with: ErrorObj._type_key via TVM_FFI_DECLARE_OBJECT_INFO_STATIC

# --- Removed ---
# TVM_FFI_REGISTER_STATIC_TYPE_INFO macro -- fully absorbed into TVM_FFI_DECLARE_OBJECT_INFO_STATIC
```

## Impact
- API: All dynamic object types that previously relied on header-include-driven auto-registration must now explicitly call `ObjectDef<T>()` or `_GetOrAllocRuntimeTypeIndex()` in a `.cc` file. Without this, `IsInstance`/dynamic casting for those types will not work.
- Behavioral: Static object types (indices 64-128) are now always pre-registered via `ReserveDepthOneObjectTypeIndex`, independent of which headers are included. Tests must use `RuntimeTypeIndex()` instead of `_type_index` for dynamic types.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Object system macros and type registration (`.knowledge/design-records/0002-object-system.md`)
- Reflection ObjectDef as explicit registration mechanism (`.knowledge/design-records/0008-reflection.md`)
- TypeTable centralized type index management (`.knowledge/design-records/0002-object-system.md`)
- StaticTypeKey constants (`.knowledge/design-records/0002-object-system.md`)

Design elements this commit produces:
- **Lazy registration model**: Macro declarations no longer trigger registration; `ObjectDef<T>()` becomes the required registration mechanism for dynamic casting to work
- **Centralized depth-1 type pre-registration**: `ReserveDepthOneObjectTypeIndex` in TypeTable constructor replaces per-header static-init registration for all builtin object types
- **`StaticTypeKey::kTVMFFIError`**: New constant for error type key, completing the StaticTypeKey set for all built-in object types
- **Removed `TVM_FFI_REGISTER_STATIC_TYPE_INFO`**: Internal macro eliminated, logic folded into `TVM_FFI_DECLARE_OBJECT_INFO_STATIC`

## Usage Examples
Before this change, including a header was sufficient for type registration:
```cpp
// BEFORE: just including the header registered the type automatically
// because TVM_FFI_DECLARE_OBJECT_INFO had: static inline int32_t _type_index = _GetOrAllocRuntimeTypeIndex()
#include <tvm/ffi/container/array.h>
// ArrayObj type index was now registered in this DLL's copy of the static

// AFTER: header inclusion alone does NOT register the type.
// Registration must happen explicitly in a .cc file:
TVM_FFI_STATIC_INIT_BLOCK() {
  tvm::ffi::reflection::ObjectDef<MyNodeObj>()
      .def_rw("name", &MyNodeObj::name);
  // ObjectDef constructor calls _GetOrAllocRuntimeTypeIndex(), triggering registration
}

// For static types (Str, Error, etc.), registration happens centrally in TypeTable:
// TypeTable::TypeTable() calls ReserveDepthOneObjectTypeIndex for all builtin types
```
