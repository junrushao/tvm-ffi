# Remove static inline object registration in macros; centralize depth-1 type index reservation in TypeTable
## TL;DR
- Removes the `static inline int32_t _register_type_index` / `static inline int32_t _type_index` auto-registration trigger from `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` and `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY` macros, eliminating per-DLL binary overhead for unused object types.
- Adds centralized `ReserveDepthOneObjectTypeIndex` calls in `TypeTable` for all built-in depth-1 object types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject), so their type indices are available without header-triggered static init.
- Adds `StaticTypeKey::kTVMFFIError` constant and updates `ErrorObj` to use it.

## Key Exports

**Constants (`object.h`):**
- `StaticTypeKey::kTVMFFIError = "ffi.Error"` -- new centralized type key constant for `ErrorObj`.

**Macros (changed behavior, `object.h`):**

| Macro | Change |
|-------|--------|
| `TVM_FFI_DECLARE_OBJECT_INFO_STATIC(TypeKey, TypeName, ParentType)` | Removes `static inline int32_t _register_type_index = _GetOrAllocRuntimeTypeIndex()`. `_GetOrAllocRuntimeTypeIndex()` now marks `tindex` as `[[maybe_unused]]` and returns `TypeName::_type_index` directly instead of `tindex`. Registration must be triggered explicitly via `ObjectDef<TypeName>()` or a manual call to `_GetOrAllocRuntimeTypeIndex()`. |
| `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY(TypeName, ParentType)` | Removes `static inline int32_t _type_index = _GetOrAllocRuntimeTypeIndex()`. Registration must be triggered explicitly. |

**Internal method (`object.cc`):**
- `TypeTable::ReserveDepthOneObjectTypeIndex(const char* type_key, int32_t static_type_index)` -- registers a depth-1 object type (parent = `kTVMFFIObject`) at the given static index during `TypeTable` construction.

## Impact
- API: Dynamic casting (`IsInstance<T>()`) for object types no longer works automatically by including the header. Users must ensure `ObjectDef<T>()` or `_GetOrAllocRuntimeTypeIndex()` is called once per type. For all built-in types (Str, Bytes, Error, Function, Shape, Tensor, Array, Map, Module, OpaquePyObject), registration is handled by `TypeTable` construction, so no caller action is needed.
- ABI: None. No C ABI struct layout changes.
- Behavioral: Reduced binary size and init logic for DLLs that include object headers but do not use all declared types. Custom dynamic-index types that previously relied on header-only auto-registration now require explicit `ObjectDef` registration.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object declaration macros** (`.knowledge/designs/object-system.md`) -- modifies the expansion of `TVM_FFI_DECLARE_OBJECT_INFO_STATIC` and `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY`.
- **TypeTable type index reservation** (`.knowledge/designs/object-system.md`, "Type Registration (Runtime)" section) -- extends the centralized reservation approach from non-object builtin types (None, Int, Float, etc.) to depth-1 object types.
- **`ObjectDef<T>` reflection registration** (`.knowledge/designs/reflection.md`) -- becomes the required mechanism for triggering type index registration for custom types.

Design elements this commit produces:
- **Explicit registration contract for dynamic casting** -- Header inclusion alone no longer guarantees `IsInstance<T>()` works. Either `ObjectDef<T>()` must be called (the expected path) or `_GetOrAllocRuntimeTypeIndex()` must be invoked manually. This is documented in the updated Doxygen comments on each macro.
- **Centralized depth-1 object type reservation** -- All 10 built-in depth-1 types are reserved by `TypeTable` construction via `ReserveDepthOneObjectTypeIndex`, removing the need for scattered `static inline` registration triggers across headers.
- **`StaticTypeKey::kTVMFFIError`** -- Error type key joins the other centralized constants.

## Usage Examples

### Before: Type registration triggered automatically by header inclusion
```cpp
// Including the header was sufficient for IsInstance to work
#include <tvm/ffi/container/shape.h>

// ShapeObj's _register_type_index static inline ran at DLL load time
// even if ShapeObj was never used in this DLL
```

### After: Type registration requires explicit ObjectDef or is centralized
```cpp
// Built-in types (Shape, String, Error, etc.) are registered by TypeTable constructor
// No header-include side effect needed

// Custom types must register via ObjectDef:
TVM_FFI_STATIC_INIT_BLOCK() {
  tvm::ffi::reflection::ObjectDef<MyCustomObj>()
      .def_rw("field", &MyCustomObj::field);
  // ^-- This call triggers _GetOrAllocRuntimeTypeIndex() for MyCustomObj
}
```
