**Notable documentation content**: `CONTRIBUTING.md` codifies two important project norms:
1. **C ABI stability is top priority** -- changes should first consider whether they can be built on top of the current mechanism; ABI-breaking changes require RFCs.
2. **Versioning scheme during RFC stage**: `0.X.Y` where `X` bumps indicate C ABI-breaking changes and `Y` indicates other changes. Semantic versioning (`major.minor.patch`) will follow after the RFC stage.
