# Add build_inline utility that compiles without loading
## TL;DR
- Extracts the compilation logic from `load_inline` into a new `build_inline` function that returns the path (`str`) to the compiled shared library instead of a loaded `Module`.
- Reimplements `load_inline` as a thin wrapper: `load_module(build_inline(...))`.
- Adds `build_inline` to the `tvm_ffi.cpp` public API, Sphinx docs, and a dedicated test file.

## Key Exports

**Functions**:
```python
def tvm_ffi.cpp.build_inline(
    name: str,
    *,
    cpp_sources: Sequence[str] | str | None = None,
    cuda_sources: Sequence[str] | str | None = None,
    functions: Mapping[str, str] | Sequence[str] | str | None = None,
    extra_cflags: Sequence[str] | None = None,
    extra_cuda_cflags: Sequence[str] | None = None,
    extra_ldflags: Sequence[str] | None = None,
    extra_include_paths: Sequence[str] | None = None,
    build_directory: str | None = None,
) -> str:
    """Compile and build a C++/CUDA module from inline source code.
    Returns the path to the compiled shared library."""
```

`load_inline` signature is unchanged but its implementation now delegates to `build_inline`:
```python
def load_inline(...) -> Module:
    return load_module(build_inline(...))
```

## Impact
- API: New public function `tvm_ffi.cpp.build_inline`. No changes to existing `load_inline` signature or return type.
- Behavioral: None -- `load_inline` returns the same `Module` as before; `build_inline` exposes the intermediate build artifact path that was previously internal.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): `load_module` is called by `load_inline` to convert the `build_inline` output path into a `Module`.
- **Inline module compilation workflow** ([0014-python-package.md](../designs/0014-python-package.md)): All existing internal functions (`_generate_ninja_build`, `_build_ninja`, `_decorate_with_tvm_ffi`, SHA-256 caching, `FileLock`) are consumed unchanged by `build_inline`.

Design elements this commit produces:
- **`build_inline` public API**: A build-only variant of `load_inline` that returns `str` (path to `.so`/`.dll`). Enables workflows where the user wants to compile once and load later or load in a different process.
- **Two-tier inline compilation API pattern**: `build_inline` (compile-only) + `load_inline` (compile + load) where the higher-level function is a trivial composition of the lower-level one and `load_module`.

## Usage Examples

Build a shared library and load it separately:
```python
import tvm_ffi
import tvm_ffi.cpp

# Step 1: compile only
lib_path: str = tvm_ffi.cpp.build_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(tvm::ffi::Tensor x, tvm::ffi::Tensor y) {
          for (int i = 0; i < x->shape[0]; ++i)
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)

# Step 2: load separately
mod = tvm_ffi.load_module(lib_path)
mod.add_one_cpu(x, y)
```
