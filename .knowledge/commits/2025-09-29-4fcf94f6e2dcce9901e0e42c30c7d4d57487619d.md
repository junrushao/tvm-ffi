# Add `build_inline` utility that returns a library path, refactoring `load_inline` to delegate to it

## TL;DR
- Renames the implementation body of `load_inline` to `build_inline`, which now returns `str` (the path to the compiled `.so`/`.dll`) instead of a loaded `Module`.
- `load_inline` becomes a thin wrapper: `load_module(build_inline(...))` — API-compatible with existing callers.
- Exports `build_inline` from `tvm_ffi.cpp` and documents it in Python guide and API reference.

## Key Exports

```python
# python/tvm_ffi/cpp/load_inline.py

def build_inline(
    name: str,
    *,
    cpp_sources: Sequence[str] | str | None = None,
    cuda_sources: Sequence[str] | str | None = None,
    functions: Mapping[str, str] | Sequence[str] | str | None = None,
    extra_cflags: Sequence[str] | None = None,
    extra_cuda_cflags: Sequence[str] | None = None,
    extra_ldflags: Sequence[str] | None = None,
    extra_include_paths: Sequence[str] | None = None,
    build_directory: str | None = None,
) -> str:
    """Compile a C++/CUDA module from inline source code; return the path to the built .so/.dll.
    # Invariant: same caching and build logic as old load_inline (hash-based, FileLock)
    # Invariant: returned path = str((build_dir / f"{name}{ext}").resolve())
    # Interacts with: _decorate_with_tvm_ffi, _hash_sources, _build_ninja, FileLock
    # Extension: caller controls when/whether to load the library via tvm_ffi.load_module(path)
    """
    ...

def load_inline(
    name: str,
    *,
    cpp_sources: ...,
    cuda_sources: ...,
    functions: ...,
    extra_cflags: ...,
    extra_cuda_cflags: ...,
    extra_ldflags: ...,
    extra_include_paths: ...,
    build_directory: str | None = None,
) -> Module:
    """Compile, build and load a C++/CUDA module from inline source code.
    # Now a thin wrapper: return load_module(build_inline(...))
    # API-compatible with prior callers — return type unchanged (Module)
    # Interacts with: build_inline (compilation), load_module (DSO loading)
    """
    return load_module(build_inline(name=name, ...))

# python/tvm_ffi/cpp/__init__.py
# Old: from .load_inline import load_inline
# New: from .load_inline import build_inline, load_inline
```

## Impact
- API: `build_inline` added as a new public API in `tvm_ffi.cpp`; `load_inline` signature unchanged — existing callers unaffected.
- Behavioral: `load_inline` now internally calls `build_inline` + `load_module`; observable behavior is identical. Callers who previously called `load_inline` can now call `build_inline` to defer loading.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

- `0011-module-system` — `load_module()` called by the new `load_inline` wrapper
- `0013-python-package` — `tvm_ffi.cpp` subpackage `__init__.py` updated to export `build_inline`

Design elements this commit produces:
- `build_inline` — new public API in `tvm_ffi.cpp`: same parameters as `load_inline`, returns `str` (compiled library path) instead of `Module`. Decouples compilation from loading.

Design elements this commit mutates:
- `load_inline` (`0015-load-inline`) — implementation refactored to delegate to `build_inline + load_module`; contract (signature, return type) unchanged but internal structure replaced.

## Usage Examples

**build_inline: compile without loading (from test_build_inline.py)**

```python
import tvm_ffi.cpp
from tvm_ffi.module import Module

# Step 1: build only — returns the .so path
output_lib_path = tvm_ffi.cpp.build_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(tvm::ffi::Tensor x, tvm::ffi::Tensor y) {
            for (int i = 0; i < x->shape[0]; ++i)
                ((float*)y->data)[i] = ((float*)x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)

# Step 2: load separately
mod: Module = tvm_ffi.load_module(output_lib_path)
mod.add_one_cpu(x, y)
```

**Cross-layer trace**: `build_inline` compiles via Ninja to `~/.cache/tvm-ffi/hello_{hash}/hello.so` → `load_module(path)` opens via `DSOLibrary` → `mod.add_one_cpu` dispatches through `Module.GetFunction` → `GetSymbolWithSymbolPrefix("add_one_cpu")` → `GetSymbol("__tvm_ffi_add_one_cpu")`.
