# Add `build_inline` utility that compiles inline C++/CUDA without loading

## TL;DR
- Extracts the build logic from `load_inline` into a new `build_inline` function that compiles C++/CUDA source to a shared library and returns its path (as `str`) instead of a loaded `Module`.
- `load_inline` is refactored into a thin wrapper: `load_module(build_inline(...))`.
- Adds `test_build_inline.py` and Sphinx docs for the new API.

## Impact
- API: Additive. New public function `tvm_ffi.cpp.build_inline` exported from `tvm_ffi.cpp.__init__`. `load_inline` signature and behavior unchanged -- existing callers unaffected.
- Behavioral: `load_inline` now delegates to `build_inline` + `load_module`. Semantically identical to the previous monolithic implementation.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

Build a C++ kernel and load it separately (from `test_build_inline.py`):
```python
import numpy
import tvm_ffi
import tvm_ffi.cpp

# Compile to shared library without loading
lib_path: str = tvm_ffi.cpp.build_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(tvm::ffi::Tensor x, tvm::ffi::Tensor y) {
            for (int i = 0; i < x->shape[0]; ++i)
                static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)

# Load the module from the path separately
mod = tvm_ffi.load_module(lib_path)
x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)
numpy.testing.assert_equal(x + 1, y)
```
