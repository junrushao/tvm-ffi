# Migrate .pyi docstrings into Cython sources for Sphinx autodoc
## TL;DR
- Moved all class/method docstrings from `python/tvm_ffi/core.pyi` into the corresponding Cython `.pxi` files so Sphinx `autodoc` can discover them.
- Added inline type annotations to Cython function/method signatures across all `.pxi` files and set `# cython: annotation_typing=False` to prevent Cython from treating annotations as C types.
- Added a Sphinx `autodoc-skip-member` hook in `docs/conf.py` to force-show selected dunder methods (`__dlpack__`, `__dlpack_device__`, `__device_type_name__`, `__from_extern_c__`, `__from_mlir_packed_safe_call__`).

## Key Exports
None -- no new public API surface. Existing docstrings and type annotations were relocated, not changed.

## Impact
- API: none -- signatures unchanged; only docstring location and annotation syntax moved
- Behavioral: none
- Flags/config: `# cython: annotation_typing=False` added to `core.pyx`; this prevents Cython from interpreting PEP-484 annotations as C type declarations, which is required for the new inline annotations to work safely
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **0012-ffi-python-package**: All Cython classes receiving docstrings (`Object`, `Function`, `Tensor`, `Device`, `DataType`, `Error`, `String`, `Bytes`, `OpaquePyObject`, `PyNativeObject`, `ObjectConvertible`, `ObjectRValueRef`) are defined by this design element.
- **0015-ffi-python-type-system**: `TypeSchema`, `TypeField`, `TypeMethod`, `TypeInfo` classes receive docstring and annotation updates.
- **0018-ffi-stubgen**: The `.pyi` stub file (`core.pyi`) is stripped of docstrings; stubgen-generated inline stubs remain unaffected since they live in separate `.py` files.
