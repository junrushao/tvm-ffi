# Migrate .pyi docstrings into Cython source and add type annotations for Sphinx autodoc

## TL;DR
- Moves all class/method docstrings from `python/tvm_ffi/core.pyi` into the corresponding Cython `.pxi` source files, because Sphinx autodoc does not read `.pyi` files. The `.pyi` file is reduced to bare signatures (`... -> T: ...`) without docstrings.
- Adds Python type annotations (return types, parameter types) to Cython `cdef class` methods and module-level functions across all `.pxi` files (device, dtype, error, function, object, string, tensor, type_info).
- Adds a Sphinx `autodoc-skip-member` hook in `docs/conf.py` to force-show selected dunder methods (`__dlpack__`, `__dlpack_device__`, `__device_type_name__`, `__from_extern_c__`, `__from_mlir_packed_safe_call__`) that Sphinx would otherwise skip.
- Adds `# cython: annotation_typing=False` to `core.pyx` so Cython treats the new annotations as documentation-only, not as Cython type declarations.
- Exports the `cpp` submodule from `tvm_ffi.__init__` and reorders the Sphinx API reference index for `Tensor` section.

## Key Exports

None -- this is a documentation-only migration. No new public API surfaces are introduced or changed. All docstrings and type annotations are documentation metadata, not behavioral code.

## Impact
- API: None -- no signatures, defaults, or behaviors changed. The `.pyi` stub file retains all type signatures (just without docstrings).
- Behavioral: None -- purely documentation and annotation changes.
- Flags/config: `# cython: annotation_typing=False` added to `core.pyx`, preventing Cython from interpreting Python annotations as Cython typed declarations. The `TVM_FFI_BUILD_DOCS` environment variable (pre-existing) gates conditional behavior for docs builds.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python bindings Cython architecture** (`.knowledge/designs/0012-python-bindings.md`): All `.pxi` files modified are the Cython implementation layer documented there. The commit touches every core Cython file (object, function, tensor, device, dtype, error, string, type_info).
- **Sphinx autodoc integration**: The commit addresses a gap where Sphinx autodoc cannot read `.pyi` files, requiring docstrings to live in the actual source files.
- **`annotation_typing` Cython directive**: A Cython compiler directive that controls whether Python annotations are treated as Cython types or ignored.

Design elements this commit produces:
- **Cython annotation documentation convention**: Establishes the pattern that Cython `.pxi` files carry both Python-style type annotations (for Sphinx/IDE) AND docstrings, with `annotation_typing=False` to prevent Cython from misinterpreting them. The `.pyi` file becomes a minimal signature-only stub for type checkers.
- **`_autodoc_always_show` set in `docs/conf.py`**: A curated set of dunder method names that Sphinx autodoc should never skip, enabling documentation of protocol methods like `__dlpack__`.
- **`cpp` submodule export**: `tvm_ffi.cpp` is now exported from `__init__.py` (the `cpp` submodule provides `load_inline` for JIT C++ compilation).

## Usage Examples

N/A -- documentation-only commit. The docstrings and annotations are consumed by Sphinx autodoc and IDEs (type checkers), not by user code. The Sphinx configuration change takes effect automatically when building docs:

```bash
# Docs build will now pick up docstrings from Cython source
cd docs && make html
# Dunders like __dlpack__ will appear in the generated API reference
```
