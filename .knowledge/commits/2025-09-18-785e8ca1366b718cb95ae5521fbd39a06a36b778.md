# Add PEP 484 type stubs for the Cython-generated `core` module and register `.pyi` files with the ASF header linter.

## TL;DR
- Adds `python/tvm_ffi/core.pyi` — a 227-line hand-authored PEP 484 stub file that exposes all public types, functions, and module-level variables exported by the Cython `core` extension module (`Object`, `Function`, `Tensor`, `Device`, `DLDeviceType`, `DataType`, `Error`, `String`, `Bytes`, `PyNativeObject`, `OpaquePyObject`, `ObjectRValueRef`, `ObjectConvertible`, plus helper functions).
- Refactors `_tensor.py` imports from `from . import core` / `core.X` to explicit flat imports (`from .core import X, Y, Z`), eliminating the `core` module attribute access at runtime and aligning with the stub's flat namespace.
- Extends `tests/lint/check_asf_header.py` to enforce the ASF license header on `.pyi` files.

## Impact
- API: None at runtime — `.pyi` stubs are consumed only by static type checkers (Pylance, mypy, pyright). No behavioral change.
- Behavioral: `_tensor.py` now imports `_CLASS_DEVICE`, `PyNativeObject`, `_shape_obj_get_py_tuple` directly from `.core` instead of accessing them as `core.X` attributes. Functionally identical; IDE navigation and type inference improve.
- Flags/config: Pylance users may need `"python.analysis.extraPaths": ["./build/"]` if the Cython `.so` is not on `sys.path`.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- `Object` / `Function` / `Tensor` / `Device` / `DLDeviceType` / `DataType` / `Error` / `String` / `Bytes` — all defined in the Cython `core` extension; documented in [0013-python-package](../design-records/0013-python-package.md) and [0007-containers](../design-records/0007-containers.md).
- `PyNativeObject` — base for Python-built-in subclasses (`Shape`, `String`, `Bytes`); [0013-python-package](../design-records/0013-python-package.md).
- `OpaquePyObject` — arbitrary Python object wrapper; [0014-opaque-pyobject](../design-records/0014-opaque-pyobject.md).
- `_CLASS_DEVICE` late-bound factory pattern and `_shape_obj_get_py_tuple` helper; [0013-python-package](../design-records/0013-python-package.md).
- `TVMFFIPyCallManager` / `release_gil` on `Function`; [0016-py-ffi-call-dispatch](../design-records/0016-py-ffi-call-dispatch.md).
- `_env_set_current_stream` bridge; [0012-env-api](../design-records/0012-env-api.md).

Design elements this commit produces:
- **`core.pyi`** — machine-readable type contract for the Cython `core` extension module. This is the authoritative reference for what Python tooling sees as the public surface of `tvm_ffi.core`. Previously this surface was undocumented at the type level.

## Usage Examples

Adding `core.pyi` enables static type checking for all downstream code:

```python
# Before: Pylance/mypy could not resolve tvm_ffi.core.Object, .Function, etc.
import tvm_ffi
obj: tvm_ffi.core.Object  # red squiggle / Any

# After: types resolve through core.pyi
from tvm_ffi.core import Object, Function, Tensor, Device
obj: Object         # resolves correctly
fn: Function        # resolves correctly; .release_gil property known to type checker

# The import flattening in _tensor.py mirrors what callers should now do:
from tvm_ffi.core import Device, DLDeviceType, PyNativeObject, Tensor, _CLASS_DEVICE, _shape_obj_get_py_tuple, from_dlpack
```
