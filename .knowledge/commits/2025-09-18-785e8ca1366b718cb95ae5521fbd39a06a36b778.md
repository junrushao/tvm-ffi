# Add type stubs (core.pyi) for Cython-generated code
## TL;DR
- Introduces `python/tvm_ffi/core.pyi` (227 lines), a comprehensive type-stub file for the Cython-generated `core` module, enabling Pylance/mypy type checking and IDE autocompletion for `Object`, `Function`, `Tensor`, `Device`, `DataType`, `Error`, `String`, `Bytes`, and all public module-level functions.
- Refactors `_tensor.py` to import symbols directly from `core` rather than through the `core` module namespace, improving import clarity and IDE resolution.
- Extends `check_asf_header.py` to validate `.pyi` files have the Apache license header.

## Impact
- API: none (type stubs only; no runtime behavior change)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python Bindings** (`.knowledge/designs/0014-python-bindings.md`): The stub file mirrors the Cython `core` module's public API surface, including `Object`, `Function`, `Tensor`, `Device`, `DataType`, `Error`, `String`, `Bytes`, `PyNativeObject`, `ObjectRValueRef`, `OpaquePyObject`, and module-level functions like `from_dlpack`, `_register_global_func`, `_get_global_func`.
- **DLPack Exchange Acceleration** (`.knowledge/designs/0020-dlpack-exchange-acceleration.md`): The `DLTensorTestWrapper` class stub exposes `__c_dlpack_from_pyobject__` attribute.

Design elements this commit produces:
- **Type stub for Cython core module**: `python/tvm_ffi/core.pyi` serves as the canonical type annotation source for the Cython-generated module. This is a developer tooling improvement, not a runtime design element.
