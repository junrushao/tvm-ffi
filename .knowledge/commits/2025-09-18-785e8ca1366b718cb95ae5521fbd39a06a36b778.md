# Add type stubs for Cython-generated `core` module and refactor imports for type-checker compatibility
## TL;DR
- Adds `python/tvm_ffi/core.pyi`, a 227-line type stub declaring all classes, functions, and module-level variables exported by the Cython `core` extension, enabling Pylance/pyright/mypy to resolve `tvm_ffi.core` symbols.
- Refactors `python/tvm_ffi/_tensor.py` to use direct symbol imports (`from .core import X`) instead of module-attribute access (`core.X`), making references resolvable by type checkers.
- Extends `tests/lint/check_asf_header.py` to recognize `.pyi` files for ASF license header checking.

## Key Exports

**Type stub: `python/tvm_ffi/core.pyi`**

Declares the public API surface of the Cython `core` extension module. Key types and their signatures:

| `ObjectRValueRef` | class | `obj: Object` |
| `OpaquePyObject` | class (extends Object) | `pyobject() -> Any` |
| `PyNativeObject` | class | `__init_tvm_ffi_object_by_constructor__()` |
| `Error` | class (extends Object) | `kind`, `message`, `traceback` properties; `py_error()`, `update_traceback()` |

**Lint extension: `tests/lint/check_asf_header.py`**

Added `"pyi": header_pystyle` to `FMT_MAP`, so `.pyi` files are validated for Apache 2.0 license headers.

## Impact
- API: None -- no runtime behavior changes. The `.pyi` stub is purely for static analysis tooling.
- Behavioral: None.
- Flags/config: Users may need `"python.analysis.extraPaths": ["./build/"]` in VS Code settings if Pylance still reports missing `core` imports (noted in commit message).
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python package structure** ([.knowledge/designs/0014-python-package.md](../designs/0014-python-package.md)): The `.pyi` stub mirrors the Cython `core` extension's public API surface, including `Object`, `Function`, `Tensor`, `Device`, `Error`, and registration functions.
- **CI and lint pipeline** ([.knowledge/designs/0016-ci-and-lint-pipeline.md](../designs/0016-ci-and-lint-pipeline.md)): Extends `check_asf_header.py`'s `FMT_MAP` to cover the new `.pyi` extension.

Design elements this commit produces:
- **Cython type stub convention**: Establishes that `.pyi` files colocated with Cython `.pyx` modules serve as the type annotation source for static analysis tools. This is a new convention for the project.

## Usage Examples

The `.pyi` stub enables IDE autocomplete and type checking for Cython-generated symbols:

```python
# Before: Pylance/pyright shows "core" as unresolved or its members as Unknown
from tvm_ffi import core
obj: core.Object  # type: Unknown

# After: type checkers read core.pyi and resolve all symbols
from tvm_ffi.core import Object, Function, Tensor
obj: Object  # type: Object, with full method signatures available
```

The import refactoring in `_tensor.py` follows the same pattern -- direct symbol imports instead of module-level attribute access:

```python
# Before (opaque to type checkers):
from . import core
class Shape(tuple, core.PyNativeObject): ...

# After (resolvable via core.pyi):
from .core import PyNativeObject, _shape_obj_get_py_tuple, _CLASS_DEVICE
class Shape(tuple, PyNativeObject): ...
```
