# Add .pyi type stubs for the Cython-compiled core extension module
## TL;DR
- Adds `python/tvm_ffi/core.pyi` (227 lines) providing complete type annotations for all classes and functions exported by the Cython `core` extension module, enabling IDE autocompletion and static analysis (Pylance, mypy, pyright).
- Refactors `_tensor.py` to import symbols directly from `core` (e.g., `from .core import PyNativeObject`) instead of qualified `core.PyNativeObject` access, now that the stub provides proper symbol resolution.
- Extends the ASF license header lint checker to recognize `.pyi` files as Python-style headers.

## Impact
- API: None -- `.pyi` stubs are consumed by type checkers, not at runtime.
- Behavioral: None -- no runtime code changes except import style in `_tensor.py`.
- Flags/config: Users may need `"python.analysis.extraPaths": ["./build/"]` in VS Code settings if Pylance cannot locate the built `core` module.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object system** ([0002-object-system](../designs/0002-object-system.md)) -- `Object`, `ObjectRValueRef` stub signatures mirror the C++ Object hierarchy.
- **Function system** ([0004-function-system](../designs/0004-function-system.md)) -- `Function.__call__`, `release_gil` property documented in stub.
- **Error system** ([0005-error-system](../designs/0005-error-system.md)) -- `Error` class properties (`kind`, `message`, `traceback`), `_convert_to_ffi_error`.
- **Python bindings** ([0012-python-bindings](../designs/0012-python-bindings.md)) -- all exported Cython classes and functions now have type annotations.
- **DLPack protocols** -- `Tensor.__dlpack__`, `from_dlpack`, `DLTensorTestWrapper`.

Design elements this commit produces:
- **Type stub convention** -- Establishes the pattern of hand-written `.pyi` stubs for Cython extensions. This is later superseded by auto-generated stubs via `tvm-ffi-stubgen` (noted in CLAUDE.md).

## Usage Examples
The `.pyi` file is consumed automatically by IDEs and type checkers. No explicit usage code is needed:

```python
# After this commit, Pylance/pyright will resolve types correctly:
from tvm_ffi.core import Object, Function, Tensor, Device

def my_func(t: Tensor) -> Device:
    return t.device  # IDE shows: Device (resolved from core.pyi)
```

The import style change in `_tensor.py` demonstrates the immediate benefit:

```python
# Before: qualified access (no type resolution without stubs)
from . import core
class Shape(tuple, core.PyNativeObject): ...

# After: direct imports (type checker can resolve via core.pyi)
from .core import PyNativeObject, _shape_obj_get_py_tuple, _CLASS_DEVICE
class Shape(tuple, PyNativeObject): ...
```
