# Add .pyi type stubs for Cython core module to enable static type checking
## TL;DR
- Adds `python/tvm_ffi/core.pyi` with 227 lines of type annotations covering all classes and functions exported by the Cython `core.pyx` module (Object, Function, Error, Tensor, Device, DataType, String, Bytes, etc.).
- Refactors `_tensor.py` to use explicit imports from `core` instead of `core.X` attribute access, improving type checker resolution.
- Extends ASF header lint to check `.pyi` files.

## Key Exports

```python
# python/tvm_ffi/core.pyi -- type stubs for Cython-generated core module
# Covers all existing Cython classes; no new runtime behavior introduced.

# Module-level variables
ERROR_NAME_TO_TYPE: dict[str, type]
ERROR_TYPE_TO_NAME: dict[type, str]
_WITH_APPEND_TRACEBACK: Callable[[BaseException, str], BaseException] | None
_TRACEBACK_TO_STR: Callable[[types.TracebackType | None], str] | None
__dlpack_version__: tuple[int, int]
_CLASS_DEVICE: type[Device]

# All existing classes annotated: Object, ObjectConvertible, ObjectRValueRef,
# OpaquePyObject, PyNativeObject, Error, DataType, DLDeviceType, Device,
# Tensor, DLTensorTestWrapper, Function, String, Bytes
# Plus internal functions: _register_global_func, _get_global_func,
# _convert_to_ffi_func, _convert_to_opaque_object, _register_object_by_index,
# _object_type_key_to_index, _add_class_attrs_by_reflection, etc.

# Interacts with: Pylance / mypy / pyright (consumed by IDE type checkers)
# Interacts with: core.pyx (describes the same API surface)
# Invariant: stubs must stay in sync with core.pyx when Cython API changes
```

## Impact
- API: None -- no runtime API changes; stubs are consumed by type checkers only.
- Behavioral: None -- `_tensor.py` import refactor is functionally equivalent.
- Flags/config: Users may need `python.analysis.extraPaths: ["./build/"]` in VS Code for Pylance to resolve the `core` Cython module.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object, Function, Error, Tensor, Device, DataType, String, Bytes** (all from `core.pyx`) -- the stub file annotates their existing signatures. See [0012-ffi-python-package](../design-records/0012-ffi-python-package.md).
- **PyNativeObject** protocol -- consumed by `_tensor.py` (Shape class) via explicit import.
- **DLPack protocol** -- `Tensor.__dlpack__` / `from_dlpack` signatures documented in stubs.

Design elements this commit produces:
- None -- this commit documents existing APIs via `.pyi` stubs without introducing new design elements.

## Usage Examples
The `.pyi` stub file enables IDE autocompletion and type checking. No runtime usage changes. Example of the developer experience improvement:

```python
# Before: Pylance reports "core" as unresolved, no autocompletion on core.Object
from tvm_ffi import core
obj: core.Object  # red squiggly in IDE

# After: with core.pyi in place, Pylance resolves all types
from tvm_ffi.core import Object, Function, Tensor
obj: Object        # autocompletion works, signature hints available
fn: Function       # release_gil property visible in hover
t: Tensor          # shape, dtype, device properties discoverable
```
