# Improve Sphinx autodoc to skip builtin-inherited members and link inherited methods to defining class

## TL;DR
- Sphinx autodoc `_filter_inherited_members` now hides methods inherited from Python builtin types (e.g., `str`, `int`, `tuple`) via a `_py_native_classes` tuple, reducing noise in API docs for subclasses like `DType`.
- New `_link_inherited_members` hook replaces docstrings of inherited non-builtin methods with a clickable cross-reference to the defining base class (e.g., `Tensor.same_as` links to `Object.same_as`).
- `_update_module()` in `tvm_ffi/__init__.py` rewrites `__module__` on all `__all__` exports to `"tvm_ffi"`, ensuring Sphinx renders canonical module paths.
- Doc dependency pins in `pyproject.toml` are relaxed (version constraints removed from 7 Sphinx-related packages).

## Impact
- API: none -- no public Python or C++ API changes
- Behavioral: Sphinx-generated docs will omit ~60+ builtin-inherited methods from classes subclassing `str`, `int`, etc. Inherited non-builtin methods now show a clickable "Defined in BaseClass" link instead of a raw docstring copy.
- Flags/config: `__ffi_init__` added to `_autodoc_always_show` set (doc-only effect)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Python object hierarchy where FFI types like `DType` subclass Python builtins (`str`), causing Sphinx to enumerate all parent methods -- see `.knowledge/designs/0012-python-bindings.md`
- Sphinx `autodoc-skip-member` and `autodoc-process-docstring` event hooks (Sphinx extension API)

Design elements this commit produces:
- `_py_native_classes` tuple: authoritative list of Python builtin types whose inherited members are suppressed in docs
- `_filter_inherited_members` / `_link_inherited_members` pattern: two-hook approach where filtering hides noise and linking adds cross-references for the remaining inherited members
- `_update_module()` pattern: module-attribute patching at import time to ensure Sphinx sees canonical `tvm_ffi` module paths

## Usage Examples

The hooks are registered declaratively in `setup()` and fire automatically during `sphinx-build`. No user-facing call is needed. To add a new dunder that should always appear in docs:

```python
# docs/conf.py
_autodoc_always_show = {
    "__dlpack__",
    "__dlpack_device__",
    "__device_type_name__",
    "__ffi_init__",             # <-- added in this commit
    "__from_extern_c__",
    "__from_mlir_packed_safe_call__",
    "__my_new_dunder__",        # <-- extend here
}
```

To add a new builtin type whose inherited members should be hidden:

```python
_py_native_classes: tuple[type, ...] = (
    str, tuple, list, ...,
    my_new_builtin_type,  # <-- extend here
)
```
