# Improve Sphinx autodoc by hiding builtin-inherited members and linking parent-class methods

## TL;DR
- Sphinx `autodoc-skip-member` hook now filters out methods inherited from Python native types (str, int, tuple, etc.), removing noise from class pages like `tvm_ffi.dtype` which inherits from `str`.
- New `autodoc-process-docstring` hook replaces docstrings of inherited methods with a cross-reference link to the defining base class (e.g., `Tensor.same_as` links to `Object.same_as`).
- `_update_module()` in `tvm_ffi/__init__.py` rewrites `__module__` of all `__all__` exports to `"tvm_ffi"`, ensuring Sphinx displays canonical module paths.

## Key Exports

**Functions (docs/conf.py internal, not public API)**:
- `_filter_inherited_members(app, what, name, obj, skip, options)` -- autodoc-skip-member handler; returns `True` for built-in methods and methods whose `__objclass__` is in `_py_native_classes`.
- `_link_inherited_members(app, what, name, obj, options, lines)` -- autodoc-process-docstring handler; for inherited method/attribute/property, clears original docstring lines and inserts a cross-reference to the defining base class.
- `_defining_class(cls, attr_name) -> type | None` -- walks `cls.__mro__` (reversed) to find the first class whose `__dict__` defines `attr_name`.
- `_import_cls(cls_name) -> type | None` -- imports a class by fully-qualified dotted name.

**Constants (docs/conf.py)**:
- `_py_native_classes: tuple[type, ...]` -- 14 Python built-in types (str, tuple, list, dict, set, frozenset, bytes, bytearray, memoryview, int, float, complex, bool, object) whose inherited members are hidden.
- `_autodoc_always_show` -- expanded with `"__ffi_init__"`.

**Functions (python/tvm_ffi/__init__.py)**:
- `_update_module()` -- iterates `__all__`, sets `obj.__module__ = "tvm_ffi"` for any export whose module doesn't already start with `"tvm_ffi"`.

## Impact
- API: None (all changes are docs-infrastructure or init-module cosmetic).
- ABI: None.
- Behavioral: Sphinx-generated documentation pages for classes subclassing Python builtins (e.g., `dtype(str)`, `DLDeviceType(IntEnum)`) no longer show dozens of irrelevant inherited methods. - Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- Sphinx autodoc event hooks (`autodoc-skip-member`, `autodoc-process-docstring`) -- standard Sphinx extension points.
- Python MRO introspection via `inspect.getmro()` -- used to walk inheritance chains.
- `_autodoc_always_show` allowlist pattern from prior `docs/conf.py` setup -- see `.knowledge/commits/2025-09-01-c695f5f16ab6e54c729fd6338361b555c7daf8b7.md`.
- Python bindings object model where `dtype` subclasses `str` and `DLDeviceType` subclasses `IntEnum` -- see `.knowledge/designs/0014-python-bindings.md`.

Design elements this commit produces:
- **Builtin-member filtering pattern**: A reusable `_py_native_classes` tuple + `__objclass__` check for hiding inherited Python-native methods in Sphinx autodoc.
- **Inherited-member cross-referencing pattern**: MRO-walk + docstring replacement to link inherited members to their defining class in Sphinx output.
- **Module canonicalization pattern**: `_update_module()` ensures all public exports report `__module__ = "tvm_ffi"` regardless of their actual defining submodule, improving Sphinx display consistency.

## Usage Examples

The filtering and linking are transparent to users -- they are Sphinx build hooks. The key user-visible effect is in the generated HTML docs:

Before this commit, `tvm_ffi.dtype` (subclass of `str`) showed `capitalize()`, `casefold()`, `center()`, etc. After this commit, those are hidden.

Before this commit, `Tensor.same_as` (inherited from `Object`) had no docs. After this commit, it shows:
```
*Defined in* Object *as method* Object.same_as.
```

The `_update_module()` usage in `__init__.py`:
```python
# After all imports and __all__ definition:
def _update_module() -> None:
    for name in __all__:
        obj = globals()[name]
        if not getattr(obj, "__module__", "tvm_ffi").startswith("tvm_ffi"):
            try:
                obj.__module__ = "tvm_ffi"
            except (AttributeError, TypeError):
                pass

_update_module()
```
