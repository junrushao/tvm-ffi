# Refactor tensor allocator C API to align with DLPack naming and add TVMFFIEnvTensorAlloc
## TL;DR
- Renames `TVMFFIEnvSetTensorAllocator` to `TVMFFIEnvSetDLPackManagedTensorAllocator` and `TVMFFIEnvGetTensorAllocator` to `TVMFFIEnvGetDLPackManagedTensorAllocator` to align with DLPack naming conventions.
- Introduces a new `TVMFFIEnvTensorAlloc` C API function that allocates a tensor from the environment allocator and returns an `ffi::Tensor` object (not a raw `DLManagedTensorVersioned`), keeping metadata allocation inside `libtvm_ffi` to avoid module unloading order problems.
- Replaces `Tensor::FromDLPackAlloc` with `Tensor::FromEnvAlloc` that takes a simpler function pointer signature `int (*)(DLTensor*, TVMFFIObjectHandle*)`.

| Old Name | New Name |
|---|---|
| `TVMFFIEnvSetTensorAllocator` | `TVMFFIEnvSetDLPackManagedTensorAllocator` |
| `TVMFFIEnvGetTensorAllocator` | `TVMFFIEnvGetDLPackManagedTensorAllocator` |
| `Tensor::FromDLPackAlloc` | `Tensor::FromEnvAlloc` |
| (new) | `TVMFFIEnvTensorAlloc` |

## Key Exports

```python
# --- C ABI (extra/c_env_api.h) ---

# Renamed: TVMFFIEnvSetTensorAllocator -> TVMFFIEnvSetDLPackManagedTensorAllocator
def TVMFFIEnvSetDLPackManagedTensorAllocator(
    allocator: DLPackManagedTensorAllocator,
    write_to_global_context: int,
    opt_out_original_allocator: Optional[DLPackManagedTensorAllocator_ptr]
) -> int: ...
    # Invariant: same semantics as before, only name changed

# Renamed: TVMFFIEnvGetTensorAllocator -> TVMFFIEnvGetDLPackManagedTensorAllocator
def TVMFFIEnvGetDLPackManagedTensorAllocator() -> DLPackManagedTensorAllocator: ...
    # Invariant: same semantics as before, only name changed

# NEW: High-level tensor allocation from environment allocator
def TVMFFIEnvTensorAlloc(prototype: DLTensor_ptr, out: TVMFFIObjectHandle_ptr) -> int: ...
    # Interacts with: TVMFFIEnvSetDLPackManagedTensorAllocator (uses TLS allocator)
    # Invariant: out receives a fully-constructed ffi::Tensor (not raw DLManagedTensorVersioned)
    # Invariant: metadata allocation stays in libtvm_ffi (solves module unloading order problem)
    # Invariant: returns -1 and sets error via TVMFFIErrorSetRaisedFromCStr if no allocator configured
    # Extension: future allocator backends can be added behind this same entry point

# --- C++ API (include/tvm/ffi/container/tensor.h) ---

class Tensor(ObjectRef):
    @staticmethod
    def FromEnvAlloc(
        env_alloc: Callable[[DLTensor_ptr, TVMFFIObjectHandle_ptr], int],
        shape: ShapeView,
        dtype: DLDataType,
        device: DLDevice
    ) -> Tensor: ...
        # Was: FromDLPackAlloc(DLPackManagedTensorAllocator, ShapeView, DLDataType, DLDevice)
        # Interacts with: TVMFFIEnvTensorAlloc (primary env_alloc argument)
        # Interacts with: TVM_FFI_CHECK_SAFE_CALL (error propagation)
        # Interacts with: ObjectUnsafe::ObjectPtrFromOwned (converts raw handle to ObjectPtr)
        # Invariant: simpler signature — no manual ErrorContext, no DLManagedTensorVersioned handling
        # Extension: accepts any function matching the (DLTensor*, TVMFFIObjectHandle*) -> int signature
```

## Impact
- API: Breaking rename of 3 public symbols across C, C++, Python/Cython, and Rust bindings. All callers of `TVMFFIEnvSetTensorAllocator`, `TVMFFIEnvGetTensorAllocator`, and `Tensor::FromDLPackAlloc` must update. Affected callers: `tvm_ffi_python_helpers.h` (Cython), `c_env_api.rs` (Rust), `test_load_inline.py` (Python inline C++).
- Behavioral: `Tensor::FromEnvAlloc` delegates DLPack-to-Tensor wrapping to the C API layer (`TVMFFIEnvTensorAlloc`) instead of doing it inline in the header. This moves `TensorObjFromDLPack` construction and strides handling into `libtvm_ffi`, solving module unloading order issues where a DSL compiler's module might be unloaded before tensors allocated from it are freed. The `FromEnvAlloc` method itself becomes a thin wrapper that calls the function pointer and converts the returned handle.
- Flags/config: none
- Data formats/schemas: Version bump from 0.1.0b18 to 0.1.0b19. Torch test dependency now excludes `win32` platform.

Design elements this commit produces:
- `TVMFFIEnvTensorAlloc` C API function — new high-level tensor allocation entry point that returns an owned `ffi::Tensor` object, keeping metadata allocation in `libtvm_ffi`
- `Tensor::FromEnvAlloc` replacing `Tensor::FromDLPackAlloc` — simplified C++ API with `int (*)(DLTensor*, TVMFFIObjectHandle*) -> int` function pointer signature
- Rename mapping: `TVMFFIEnvSetTensorAllocator` -> `TVMFFIEnvSetDLPackManagedTensorAllocator`, `TVMFFIEnvGetTensorAllocator` -> `TVMFFIEnvGetDLPackManagedTensorAllocator`
- Architectural pattern: separating DLPack-level allocation (caller provides `DLPackManagedTensorAllocator`) from FFI-level tensor construction (`TVMFFIEnvTensorAlloc` does both), allowing the public API to evolve independently of the underlying allocator mechanism

## Usage Examples

Allocating a tensor from the environment allocator in C++ (the canonical pattern after this commit):
```cpp
#include <tvm/ffi/container/tensor.h>
#include <tvm/ffi/extra/c_env_api.h>

// Before (old API):
// ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
//   TVMFFIEnvGetTensorAllocator(), ffi::Shape({x.size(0)}), f32_dtype, x.device());

// After (new API):
ffi::Tensor y = ffi::Tensor::FromEnvAlloc(
  TVMFFIEnvTensorAlloc, ffi::Shape({x.size(0)}), f32_dtype, x.device());
// TVMFFIEnvTensorAlloc is passed as a function pointer, making the dependency
// on extra/c_env_api.h explicit. The tensor metadata (TensorObj wrapper) is
// allocated inside libtvm_ffi, avoiding module unloading order issues.
```

Using the new C API directly for tensor allocation at the C level:
```c
#include <tvm/ffi/extra/c_env_api.h>

// Set up the allocator (usually done by framework integration layer)
TVMFFIEnvSetDLPackManagedTensorAllocator(my_allocator, 0, NULL);

// Allocate via the new high-level API
DLTensor prototype = {0};
prototype.device = (DLDevice){kDLCPU, 0};
prototype.dtype = (DLDataType){kDLFloat, 32, 1};
int64_t shape[] = {3, 4};
prototype.shape = shape;
prototype.ndim = 2;
TVMFFIObjectHandle tensor_out;
int ret = TVMFFIEnvTensorAlloc(&prototype, &tensor_out);
// ret == 0: tensor_out is a valid ffi::Tensor object handle
```
