# Fix schema rendering to use `dtype` instead of `DataType` for Python type annotations
## TL;DR
- Adds `"DataType": "dtype"` mapping to `_TYPE_SCHEMA_ORIGIN_CONVERTER` in `type_info.pxi`, so C++ `DataType` is rendered as `dtype` (the Python user-facing type) in function/field schema annotations.
- Updates test expectations from `DataType` to `dtype` in `test_metadata.py`.

## Key Exports
The schema origin converter gains one new entry. No new public API surface.

```python
# In python/tvm_ffi/cython/type_info.pxi
_TYPE_SCHEMA_ORIGIN_CONVERTER = {
    ...
    "DataType": "dtype",   # NEW: C++ DataType -> Python dtype
    # Interacts with: TypeSchema rendering, get_global_func_metadata(), TypeField/TypeMethod schema
    # Invariant: all C++ type names must map to their Python-facing equivalents
}
```

## Impact
- API: Schema string output changes from `DataType` to `dtype` for all functions/fields typed as `DataType` in C++. Callers that parse or compare schema strings against `"DataType"` must update.
- Behavioral: `get_global_func_metadata()` and field/method schema introspection now render `dtype` where they previously rendered `DataType`.
- Flags/config: none
- Data formats/schemas: Type schema strings change -- e.g., `"Callable[[DataType], DataType]"` becomes `"Callable[[dtype], dtype]"`.

## Usage Examples
Before this fix, introspecting a function typed with `DataType` in C++ would show:
```python
# Before
meta = tvm_ffi.get_global_func_metadata("testing.schema_id_dtype")
print(meta.schema)  # "Callable[[DataType], DataType]"

# After
meta = tvm_ffi.get_global_func_metadata("testing.schema_id_dtype")
print(meta.schema)  # "Callable[[dtype], dtype]"
```
