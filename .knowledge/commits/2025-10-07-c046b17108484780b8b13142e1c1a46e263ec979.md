# Fix DataType schema display to use public `dtype` name instead of internal `DataType`
## TL;DR
- Added `"DataType": "dtype"` to `_TYPE_SCHEMA_ORIGIN_CONVERTER` in `type_info.pxi` so that C++ `DataType` fields/parameters display as `dtype` (the public Python type) in schema strings.
- Updated test expectations in `test_metadata.py` from `DataType` to `dtype` for both global function schemas and field schemas.

## Key Exports
None

## Impact
- API: none -- `dtype` was already the public Python type; this fixes schema string display only.
- Behavioral: Schema strings for functions/fields involving `DataType` now render as `dtype` instead of `DataType` (e.g., `Callable[[dtype], dtype]` instead of `Callable[[DataType], DataType]`).
- Flags/config: none
- Data formats/schemas: `TypeSchema.from_json_obj()` output changes for `DataType`-typed parameters/fields.

## Design Elements
Design elements this commit consumes:
- `_TYPE_SCHEMA_ORIGIN_CONVERTER` dictionary in `type_info.pxi` -- the C++-to-Python type name mapping table used by `TypeSchema.from_json_obj()` (see [0015-ffi-python-type-system.md](../design-records/0015-ffi-python-type-system.md))
- `TypeSchema` class for schema representation and display

Design elements this commit produces: none

## Usage Examples
Before/after for schema display:
```python
# Before: DataType leaked internal C++ name into schema strings
metadata = get_global_func_metadata("testing.schema_id_dtype")
schema = TypeSchema.from_json_str(metadata["type_schema"])
str(schema)  # "Callable[[DataType], DataType]"  <-- wrong

# After: uses the public Python type name
str(schema)  # "Callable[[dtype], dtype]"  <-- correct
```
