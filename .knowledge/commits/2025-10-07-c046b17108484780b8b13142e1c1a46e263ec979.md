# Fix schema type-name mapping: DataType -> dtype in _TYPE_SCHEMA_ORIGIN_CONVERTER

## TL;DR
- Adds `"DataType": "dtype"` entry to `_TYPE_SCHEMA_ORIGIN_CONVERTER` in `python/tvm_ffi/cython/type_info.pxi` so the C++ type name `DataType` is rendered as `dtype` in schema strings.
- Updates the corresponding test expectation in `tests/python/test_metadata.py` from `DataType` to `dtype`.
- `tvm_ffi.dtype` is the public Python API surface; `tvm_ffi.core.DataType` is an internal implementation detail that should not appear in user-visible schema strings.

## Key Exports
None

## Impact
- API: Schema strings for any function that takes/returns `DataType` now show `dtype` instead of `DataType`. Callers that previously matched on `"DataType"` in schema output will need to update to `"dtype"`.
- Behavioral: None — runtime behavior unchanged; only the string representation of type schemas is affected.
- Flags/config: None
- Data formats/schemas: `TypeSchema.origin` for dtype arguments now carries `"dtype"` instead of `"DataType"`.

## Design Elements
Design elements this commit consumes:
- `_TYPE_SCHEMA_ORIGIN_CONVERTER` dict in `python/tvm_ffi/cython/type_info.pxi` — the lookup table that translates C++ type names to Python-facing names for schema strings. Described in 0013-python-package (TypeInfo / TypeField / TypeMethod metadata objects).
- `tvm_ffi.dtype` — the public Python dtype type, contrasted with the internal `tvm_ffi.core.DataType`.

Design elements this commit produces: None

## Usage Examples
Before (incorrect schema string):
```python
# testing.schema_id_dtype had schema "Callable[[DataType], DataType]"
```
After (correct schema string):
```python
# testing.schema_id_dtype now has schema "Callable[[dtype], dtype]"
assert get_schema("testing.schema_id_dtype") == "Callable[[dtype], dtype]"
```
