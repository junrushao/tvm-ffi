# Fix setter error propagation, native parent layout, and setter leak

## TL;DR
- `MakeFieldSetter` now takes raw C function pointer + `void*` type_converter instead of FFI Function, eliminating one allocation per field and packed-call overhead.
- `MakeFFINew` pre-computes `TVMFFITypeInfo*` pointer (stable for process lifetime) instead of per-allocation lookup; removed placement-construction loop (calloc zero-initializes; Any/ObjectRef have valid zero states).
- `_register_fields` returns `list[TypeField]` directly with `TypeField.ty` holding `TypeSchema` reference (prevents GC of converter). Removed `ffi.MakeNew` global function (redundant).

## Key Exports

```python
# C++ changes:
# MakeFieldSetter(f_convert: C_fn_ptr, type_converter: void*) -> Function
#   Was: MakeFieldSetter(convert_fn: Function) -> Function
#   Invariant: eliminates FFI Function allocation per field

# MakeFFINew(type_info: TVMFFITypeInfo*) -> Function
#   Pre-computes pointer; calloc zero-init (no placement loop)

# TypeField.ty: TypeSchema  # NEW — holds schema + prevents GC of converter
# TypeInfo._register_fields() -> list[TypeField]  # instance method with double-reg guard
# TypeInfo._register_methods()  # extracted from _register_fields
```

## Impact
- API: `ffi.MakeNew` global function removed. `MakeFieldSetter` signature changed (C++ internal).
- Behavioral: Field setter dispatch is faster (raw C call vs packed FFI call).
- Flags/config: None.
- Data formats/schemas: None.
