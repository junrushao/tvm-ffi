# Fix setter error propagation, native parent layout, and setter leak

## TL;DR
- `MakeFieldSetter` refactored: takes raw C function pointer (`f_convert`) + opaque `void*` type_converter instead of an FFI `Function`, eliminating one Function allocation per field and packed-call overhead per setter.
- `MakeFFINew` pre-computes `TVMFFITypeInfo*` (stable ptr) instead of per-allocation lookup; drops placement-construction loop (calloc zero-init is sufficient for `Any`/`ObjectRef` states).
- Removes `ffi.MakeNew` global (replaced by `ffi.MakeFFINew`).
- `_register_fields` now returns `list[TypeField]` directly from Cython instead of re-reading from C type table.

## Key Exports

```python
# src/ffi/extra/dataclass.cc — C++ registration:
# ffi.MakeFieldSetter(field_type_index: int32, type_converter_int: int64, f_convert_int: int64) -> Function
#   f_convert: int(void* type_converter, const TVMFFIAny* src, TVMFFIAny* dst)
#   Eliminates Function allocation per field; zero packed-call overhead
# ffi.MakeFFINew(type_index: int32, total_size: int32) -> None
#   Pre-computes TVMFFITypeInfo* stable pointer; uses calloc zero-init

# What invariant was violated before the fix:
# - Setter error propagation: exceptions from f_convert not correctly surfaced
# - MakeFFINew: per-allocation type info lookup (slow); placement loop (unnecessary)
# - Setter: one extra Function heap allocation per field (leak risk on Python side)

# What invariant is restored:
# - Setter exceptions propagate correctly via error return code
# - MakeFFINew: O(1) stable pointer; zero-init covers all valid states
# - One-time allocation per field at registration time, not per set call
```

## Impact
- API: `ffi.MakeNew` removed (use `ffi.MakeFFINew`). `MakeFieldSetter` signature changed (internal to Python field registration).
- Behavioral: Setter error propagation fixed. Improved performance for field setters.
- Flags/config: none
- Data formats/schemas: none
