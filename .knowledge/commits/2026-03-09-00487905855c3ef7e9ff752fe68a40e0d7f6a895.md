# Fix setter error propagation, native parent layout, and setter leak

## TL;DR
- **Critical fix**: `MakeFieldSetter` lambda no longer uses `TVM_FFI_SAFE_CALL` internally — type errors from conversion now propagate to the outer `SafeCall` wrapper instead of being silently swallowed.
- **Setter leak fix**: `MakeFieldSetter` now takes raw C function pointer + opaque `void*` (instead of FFI `Function`) — eliminates one `Function` allocation per field and avoids packed-call overhead on every setter invocation.
- **Parent layout fix**: `TypeInfo.total_size` is now a `cached_property` computing total object size from native metadata or field layout, replacing a broken `_compute_parent_end_offset` function.
- `_register_fields` returns `list[TypeField]` directly (built in Cython); `TypeField.ty` holds a `TypeSchema` reference that also serves as the GC anchor for the raw `void*` converter pointer.

## Key Exports

```python
# python/tvm_ffi/cython/type_info.pxi

class TypeInfo:
    # NEW cached_property replacing _compute_parent_end_offset:
    @cached_property
    def total_size(self) -> int: ...   # total byte size from native metadata or field layout
    # Interacts with: parent_type_info.total_size (recursive), C metadata->total_size

    def _register_fields(self, fields: list[Field]) -> list[TypeField]: ...
    # OLD: None return type, fields built externally
    # NEW: returns list[TypeField] built in Cython; double-registration guard added

    def _register_methods(self) -> None: ...  # NEW: extracted from _register_fields

class TypeField:
    ty: Optional[TypeSchema]  # NEW: holds TypeSchema to anchor void* converter lifetime
    # Invariant: TypeField must outlive the TypeSchema to prevent dangling void*

# src/ffi/extra/dataclass.cc

# MakeFieldSetter signature CHANGED:
# OLD: MakeFieldSetter(int32_t type_index, Function convert_fn)
# NEW: MakeFieldSetter(int32_t type_index, int64_t f_convert_ptr, int64_t type_converter_ptr)
# Interacts with: _f_type_convert Cython callback, _TypeConverter
# Invariant: f_convert_ptr must be a valid _dispatch_fn_t; type_converter_ptr must outlive Field

# ffi.MakeNew global function REMOVED (use MakeFFINew path which registers deleter)
```

## Impact
- API: **BREAKING** — `ffi.MakeFieldSetter` signature changed `(int32, Function) → (int32, int64, int64)`. `ffi.MakeNew` removed. `core._register_fields` return type `None → list[TypeField]`. `core._make_type_converter_fn` removed. `TypeField.ty` added. `TypeInfo.{_register_fields, _register_methods, total_size}` changed.
- Behavioral: Type errors from field setters now propagate correctly instead of being silently swallowed. `Field.default_factory` no longer rejects callables lacking introspectable signatures.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

- `0013-python-package`: `TypeInfo`, `TypeField` Python mirrors; `_register_fields` internal protocol
- `0019-type-schema`: `TypeSchema._converter` (void* GC anchoring via `TypeField.ty`)

Design elements this commit produces:
- `TypeInfo.total_size` cached_property: correct parent layout computation
- `TypeField.ty: Optional[TypeSchema]`: new field serving double duty as type info and GC anchor
- `_f_type_convert` Cython C callback: zero-overhead setter dispatch bypassing Python TypeSchema.convert
- Error propagation fix: setter errors now surface instead of being swallowed

## Usage Examples

Before (silently swallowed setter error):
```python
# MakeFieldSetter lambda used TVM_FFI_SAFE_CALL internally
# → type errors became no-ops, value unchanged
field_setter(obj, "not_an_int")  # silently failed
```

After (error propagates):
```python
field_setter(obj, "not_an_int")  # raises TypeError correctly
```
