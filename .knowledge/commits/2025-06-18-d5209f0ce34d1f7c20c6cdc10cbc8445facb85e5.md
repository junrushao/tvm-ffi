# Optimize Object::DecRef to use release-only atomic with conditional acquire fence

## TL;DR
- Replaces the `ACQ_REL` atomic decrement in `Object::DecRef` with a weaker `RELEASE`-only decrement plus a conditional `ACQUIRE` fence that fires only when the ref count reaches zero (i.e., only when the deleter will run).
- Removes the `AtomicIncrementRelaxed`, `AtomicDecrementRelAcq`, and `AtomicLoadRelaxed` helper functions from `base_details.h`, inlining the platform-specific intrinsics directly into `Object::IncRef`, `Object::DecRef`, and `Object::use_count`.
- Fixes the MSVC `DecRef` return-value comparison to use `== 0` (new value) instead of `== 1` (which was comparing against the old-value semantic of the GCC path), aligning both platform codepaths.

## Key Exports

```python
class Object:
    # ... (existing fields unchanged)

    def use_count(self) -> int32:
        return atomic_load_relaxed(self.header_.ref_counter)
        # Implementation: inlined platform intrinsic (unchanged semantics)

    def IncRef(self):  # private
        atomic_fetch_add_relaxed(self.header_.ref_counter, 1)
        # Implementation: inlined platform intrinsic (unchanged semantics)
        # Interacts with: ObjectPtr copy/assign, AnyView-to-Any conversion

    def DecRef(self):  # private
        # CHANGED: was atomic_fetch_sub(..., ACQ_REL), now split into:
        #   1. atomic_fetch_sub(..., RELEASE) -- no acquire on the hot path
        #   2. atomic_thread_fence(ACQUIRE) -- only when count reaches zero
        old = atomic_fetch_sub_release(self.header_.ref_counter, 1)
        if old == 1:
            atomic_thread_fence_acquire()  # ensure all writes visible before delete
            if self.header_.deleter is not None:
                self.header_.deleter(self.header_)
        # Interacts with: ObjectPtr destructor/reset, Any destructor
        # Invariant: release on every decrement ensures prior writes are published
        # Invariant: acquire fence before deleter ensures all other threads' writes are visible
        # Invariant: on MSVC, _InterlockedDecrement provides full barrier implicitly
```

Removed helpers (previously in `tvm::ffi::details`):
```python
# DELETED: AtomicIncrementRelaxed(ptr) -> int32  (now inlined in IncRef)
# DELETED: AtomicDecrementRelAcq(ptr) -> int32   (now inlined in DecRef with weaker ordering)
# DELETED: AtomicLoadRelaxed(ptr) -> int32        (now inlined in use_count)
```

## Impact
- API: None -- `IncRef`/`DecRef`/`use_count` are private/internal to `Object`. The removed `details::Atomic*` helpers were internal-only (in `details` namespace).
- Behavioral: `DecRef` hot path no longer issues an acquire barrier, reducing memory ordering overhead on architectures with weak memory models (ARM, RISC-V). Semantically equivalent on x86 (where release/acquire map to plain stores/loads with a compiler fence).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object header layout** (`TVMFFIObject.ref_counter`) -- ref counter is the atomic target ([0003-ffi-object-system](../design-records/0003-ffi-object-system.md))
- **Deleter protocol** -- deleter is invoked only after the acquire fence ensures visibility ([0003-ffi-object-system](../design-records/0003-ffi-object-system.md))

Design elements this commit produces:
- **Optimized DecRef memory ordering** -- mutates the existing `DecRef` contract from `ACQ_REL` on every decrement to `RELEASE` + conditional `ACQUIRE` fence. This is the standard pattern used by `std::shared_ptr`, Rust `Arc`, and Boost `intrusive_ptr`. The invariant now has two parts: (1) every decrement publishes prior writes via RELEASE, (2) only the thread that observes count==0 acquires, ensuring all other threads' writes are visible before the deleter runs.

## Usage Examples
No new API surface; the optimization is internal to `Object`. The calling pattern for `ObjectPtr`, `ObjectRef`, and `make_object` is unchanged. The correctness argument is:

```cpp
// Thread A                           // Thread B
obj->field = value;                   obj->other_field = value2;
ptr_a.reset();                        ptr_b.reset();
//  DecRef: fetch_sub(RELEASE)        //  DecRef: fetch_sub(RELEASE)
//  old=2, no fence, return           //  old=1 -> fence(ACQUIRE) -> deleter
                                      //  deleter sees Thread A's write (field=value)
                                      //  because RELEASE in A happens-before ACQUIRE in B
```
