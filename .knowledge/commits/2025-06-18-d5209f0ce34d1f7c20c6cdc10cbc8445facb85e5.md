# Optimize atomic decref in Object by splitting ACQ_REL into RELEASE + conditional ACQUIRE fence

## TL;DR
- Removes three internal atomic helpers (`AtomicIncrementRelaxed`, `AtomicDecrementRelAcq`, `AtomicLoadRelaxed`) from `base_details.h` and inlines their logic directly into `Object`'s private methods.
- The key optimization: `DecRef()` now uses `__ATOMIC_RELEASE` for the fetch-sub and only issues a separate `__atomic_thread_fence(__ATOMIC_ACQUIRE)` when the counter reaches zero, avoiding a full `ACQ_REL` barrier on every decrement.
- On MSVC, `_InterlockedDecrement` already implies a full barrier, so the Windows path is structurally equivalent; the Linux/Clang/GCC path gets the performance benefit.

## Key Exports

```python
class Object:
    """Base heap object with ref-counted lifecycle."""

    def use_count(self) -> int32_t:
        # Relaxed load — only need to observe the counter, no sync
        # Old: return AtomicLoadRelaxed(&header_.ref_counter)
        # New: inlined __atomic_load_n(ptr, __ATOMIC_RELAXED) / volatile long read
        ...

    def IncRef(self) -> None:  # private
        # Relaxed increment — no ordering needed for IncRef
        # Old: AtomicIncrementRelaxed(&header_.ref_counter)
        # New: inlined __atomic_fetch_add(ptr, 1, __ATOMIC_RELAXED)
        ...

    def DecRef(self) -> None:  # private
        # Invariant: release on decrement; acquire fence ONLY on last decrement
        # Old: AtomicDecrementRelAcq (ACQ_REL on every decrement)
        # New: __atomic_fetch_sub(ptr, 1, __ATOMIC_RELEASE); if == 1:
        #        __atomic_thread_fence(__ATOMIC_ACQUIRE); header_.deleter(...)
        # Interacts with: header_.deleter (called only when count hits 0)
        # Invariant: all writes from other threads are visible before deleter runs
        ...

# Removed from base_details.h (no longer exist as standalone symbols):
# details::AtomicIncrementRelaxed(int32_t* ptr) -> int32_t
# details::AtomicDecrementRelAcq(int32_t* ptr) -> int32_t
# details::AtomicLoadRelaxed(const int32_t* ptr) -> int32_t
```

## Impact
- API: None — `use_count()` signature unchanged; `IncRef`/`DecRef` are private; removed helpers were internal to `tvm::ffi::details`.
- Behavioral: `DecRef()` semantics are preserved (deleter still called exactly once when count hits 0, with acquire barrier before the call). The optimization reduces atomic overhead on every non-final decrement by demoting `ACQ_REL` to `RELEASE` on the hot path.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **0002-object-system** (`include/tvm/ffi/object.h`): `Object` class's private `IncRef`/`DecRef` and public `use_count()` — the ref-counting core of the object lifecycle.

Design elements this commit produces:
- **0002-object-system** (mutation): The decref protocol is tightened — the acquire barrier is now a conditional fence rather than part of the atomic operation. The public interface is unchanged, but the internal invariant "acquire fence is issued before every deleter call" now holds via an explicit fence instead of an ACQ_REL op. The `details::AtomicDecrementRelAcq` helper is removed.

## Usage Examples

Before/after pattern showing the optimization:

```cpp
// BEFORE (base_details.h helper, used in object.h):
// ACQ_REL on every decrement:
void DecRef() {
  if (details::AtomicDecrementRelAcq(&header_.ref_counter) == 1) {
    if (header_.deleter) header_.deleter(&header_);
  }
}

// AFTER (inlined in object.h):
// RELEASE on every decrement; ACQUIRE fence only on last decrement:
void DecRef() {
#ifdef _MSC_VER
  if (_InterlockedDecrement((volatile long*)&header_.ref_counter) == 0) {
    // full barrier implicit in InterlockedDecrement
    if (header_.deleter) header_.deleter(&header_);
  }
#else
  if (__atomic_fetch_sub(&header_.ref_counter, 1, __ATOMIC_RELEASE) == 1) {
    __atomic_thread_fence(__ATOMIC_ACQUIRE);  // acquire only on last decrement
    if (header_.deleter) header_.deleter(&header_);
  }
#endif
}
```
