# Optimize atomic DecRef in Object by splitting release/acquire barriers
## TL;DR
- Inlines atomic operations directly into `Object::IncRef()`, `DecRef()`, and `use_count()`, removing the `details::AtomicIncrementRelaxed`, `details::AtomicDecrementRelAcq`, and `details::AtomicLoadRelaxed` helper functions from `base_details.h`.
- Optimizes `DecRef` by replacing `ACQ_REL` on every `fetch_sub` with `RELEASE` on the subtraction plus a separate `ACQUIRE` fence only on the deletion path (refcount reaches zero). This is the standard split-barrier pattern used by Boost intrusive_ptr and Rust `Arc`.
- Aligns the MSVC `_InterlockedDecrement` check to `== 0` (matching its post-decrement return semantics) instead of the previous `== 1` (which matched the GCC `fetch_sub` pre-decrement semantics through the wrapper).

## Key Exports
None -- no new public API. Internal helpers `details::AtomicIncrementRelaxed`, `details::AtomicDecrementRelAcq`, `details::AtomicLoadRelaxed` were removed; their logic was inlined into `Object` methods.

## Impact
- API: None -- `Object::use_count()`, `IncRef()`, `DecRef()` signatures unchanged.
- Behavioral: `DecRef` issues a weaker memory barrier on the non-deleting path (release-only instead of acquire-release). Correct per the C++ memory model; observable only via micro-benchmarks on weakly-ordered architectures (ARM, RISC-V).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object refcounting** ([0003-object-system.md](../designs/0003-object-system.md)) -- `IncRef`/`DecRef`/`use_count` atomic operations on `header_.ref_counter`.
- **TVMFFIObject header** ([0001-c-abi-layer.md](../designs/0001-c-abi-layer.md)) -- `ref_counter` field and `deleter` function pointer.
- **Memory allocation deletion flow** ([0007-memory-allocation.md](../designs/0007-memory-allocation.md)) -- `header_.deleter` invocation when refcount reaches zero.

Design elements this commit produces:
- None (pure optimization of existing internals).

Design elements this commit mutates:
- **DecRef memory ordering contract**: Changed from "ACQ_REL on every decrement" to "RELEASE on decrement, ACQUIRE fence only before deleter". The invariant ("deleter sees all writes from all prior reference holders") is preserved, but the implementation strategy is now split-barrier. This is documented in `0003-object-system.md` line 224 which already says "release-acquire semantics" -- the description remains accurate at the semantic level.

## Usage Examples
**Before** (old `DecRef` via wrapper):
```cpp
// In base_details.h -- ACQ_REL on every decrement
int32_t AtomicDecrementRelAcq(int32_t* ptr) {
  return __atomic_fetch_sub(ptr, 1, __ATOMIC_ACQ_REL);
}
// In object.h
void DecRef() {
  if (details::AtomicDecrementRelAcq(&(header_.ref_counter)) == 1) {
    if (header_.deleter != nullptr) header_.deleter(&(this->header_));
  }
}
```

**After** (split release/acquire):
```cpp
void DecRef() {
  // Release on decrement -- ensures this thread's writes are visible to deleter
  if (__atomic_fetch_sub(&(header_.ref_counter), 1, __ATOMIC_RELEASE) == 1) {
    // Acquire fence only when we actually need to run the deleter
    __atomic_thread_fence(__ATOMIC_ACQUIRE);
    if (header_.deleter != nullptr) header_.deleter(&(this->header_));
  }
}
```
