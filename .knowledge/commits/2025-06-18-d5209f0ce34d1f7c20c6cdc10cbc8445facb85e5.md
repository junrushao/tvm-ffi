# Optimize Object::DecRef to use split release/acquire fence instead of combined ACQ_REL

## TL;DR
- Replaces `__ATOMIC_ACQ_REL` on every `DecRef` fetch_sub with `__ATOMIC_RELEASE` fetch_sub + conditional `__ATOMIC_ACQUIRE` fence only when the deleter must run (counter reaches zero).
- Removes the three `details::Atomic*` helper functions (`AtomicIncrementRelaxed`, `AtomicDecrementRelAcq`, `AtomicLoadRelaxed`) from `base_details.h`, inlining their logic directly into `Object::IncRef`, `Object::DecRef`, and `Object::use_count`.
- On MSVC, uses `_InterlockedDecrement` (which has full barrier semantics) and checks `== 0` instead of the prior pattern of wrapping `_InterlockedDecrement` in a helper that returned pre-decrement value.

## Key Exports

```python
class Object:
    """Base of all ref-counted heap objects."""

    def IncRef(self) -> None: ...
        # Unchanged semantics: relaxed atomic increment
        # Inlined from former details::AtomicIncrementRelaxed

    def DecRef(self) -> None: ...
        # OLD: __atomic_fetch_sub(&ref_counter, 1, __ATOMIC_ACQ_REL) == 1
        # NEW: __atomic_fetch_sub(&ref_counter, 1, __ATOMIC_RELEASE) == 1
        #      then __atomic_thread_fence(__ATOMIC_ACQUIRE) before calling deleter
        # Invariant: acquire fence ensures all prior writes to the object
        #   are visible before the deleter runs
        # Invariant: release on fetch_sub ensures all writes by this thread
        #   are visible to the thread that will call the deleter
        # Interacts with: ObjectPtr copy/move/destruct, header_.deleter

    def use_count(self) -> int32: ...
        # Unchanged semantics: relaxed atomic load
        # Inlined from former details::AtomicLoadRelaxed

# REMOVED from tvm::ffi::details (base_details.h):
#   AtomicIncrementRelaxed(int32_t* ptr) -> int32_t
#   AtomicDecrementRelAcq(int32_t* ptr) -> int32_t
#   AtomicLoadRelaxed(const int32_t* ptr) -> int32_t
```

## Impact
- API: None externally -- `IncRef`/`DecRef`/`use_count` are private/internal to `Object` and `ObjectPtr`. The removed `details::Atomic*` functions were internal helpers not part of the public API.
- Behavioral: `DecRef` fast path (non-deleting case) now uses a weaker memory ordering (`RELEASE` only instead of `ACQ_REL`), reducing memory barrier overhead on architectures with weak memory models (ARM, RISC-V). The slow path (deleter invocation) retains full acquire semantics via an explicit fence.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object system ref-counting** (`.knowledge/designs/0002-object-system.md`): The core `IncRef`/`DecRef` protocol on `Object::header_.ref_counter`.
- **TVMFFIObject header layout** (`.knowledge/designs/0001-c-abi.md`): The `ref_counter` field and `deleter` function pointer in the C ABI header.

Design elements this commit produces:
- None new. This is a performance refinement of the existing DecRef protocol.

Design elements this commit mutates:
- **DecRef memory ordering contract**: Changed from "ACQ_REL on every decrement" to "RELEASE on decrement, ACQUIRE fence only on deletion path." This is the standard split-barrier pattern used by Rust `Arc`, Boost `intrusive_ptr`, and C++ `shared_ptr` implementations.

## Usage Examples
This is a performance commit with no new API surface. The behavioral change is internal to `Object::DecRef`. A before/after pattern illustrating the optimization:

```cpp
// BEFORE (old DecRef via AtomicDecrementRelAcq helper):
void DecRef() {
    // ACQ_REL on EVERY decrement -- unnecessary acquire on non-deleting path
    if (details::AtomicDecrementRelAcq(&header_.ref_counter) == 1) {
        if (header_.deleter) header_.deleter(&header_);
    }
}

// AFTER (split release/acquire):
void DecRef() {
    // RELEASE only on decrement -- cheaper on ARM/RISC-V
    if (__atomic_fetch_sub(&header_.ref_counter, 1, __ATOMIC_RELEASE) == 1) {
        // ACQUIRE fence only when we need to safely call the deleter
        __atomic_thread_fence(__ATOMIC_ACQUIRE);
        if (header_.deleter) header_.deleter(&header_);
    }
}
```
