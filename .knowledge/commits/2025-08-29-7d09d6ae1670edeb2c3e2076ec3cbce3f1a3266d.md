# Revert CMake libbacktrace git URL in favor of git submodule, update submodule to upstream HEAD
## TL;DR
- Reverts the `GIT_REPOSITORY` and `GIT_TAG` directives added to `cmake/Utils/AddLibbacktrace.cmake` in commit b245f1f9 (PR #18246), restoring the submodule-only source resolution for libbacktrace.
- Updates the `3rdparty/libbacktrace` submodule pointer from the TVM fork (`08f7c7e`) to upstream HEAD (`7939218`), which already incorporates the macOS patch previously carried by the fork.
- Motivated by PR #18246 discussion: upstream libbacktrace already includes the required macOS fix, so the fork and the CMake git fetch are both unnecessary.

## Key Exports
None

## Impact
- API: none
- Behavioral: `ExternalProject_Add(project_libbacktrace ...)` no longer has a `GIT_REPOSITORY`/`GIT_TAG` download step. Source resolution relies entirely on the vendored `3rdparty/libbacktrace` submodule via `SOURCE_DIR`. Builds that previously worked without initializing the git submodule (because CMake would auto-fetch via the git URL) will now require `git submodule update --init --recursive` for the `3rdparty/libbacktrace` path.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **libbacktrace build integration** (`cmake/Utils/AddLibbacktrace.cmake`): The `_libbacktrace_compile()` function using CMake `ExternalProject_Add` to build libbacktrace as a static library. See `.knowledge/designs/0006-error-handling.md` for libbacktrace's role in traceback generation.
- **Vendored 3rdparty submodule pattern** (`3rdparty/libbacktrace`): The project convention of vendoring third-party dependencies as git submodules under `3rdparty/`.

Design elements this commit produces:
- None -- this is a revert that restores the prior submodule-only approach.
