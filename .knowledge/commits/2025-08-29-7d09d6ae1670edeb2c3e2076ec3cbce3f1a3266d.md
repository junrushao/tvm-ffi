# Revert cmake-based libbacktrace fetch in favor of git submodule
## TL;DR
- Removes the `GIT_REPOSITORY` and `GIT_TAG` directives that were added to `ExternalProject_Add` in `cmake/Utils/AddLibbacktrace.cmake` by the immediately preceding commit `b245f1f` (#18246), reverting to the git submodule at `3rdparty/libbacktrace` as the sole source for libbacktrace.
- Updates the `3rdparty/libbacktrace` submodule pointer from `08f7c7e` (tlc-pack fork) to `793921876c981ce49759114d7bb89bb89b2d3a2d` (upstream HEAD), because upstream already incorporates the one macOS patch that the fork carried.
## Impact
- API: none
- Flags/config: none. The `TVM_FFI_USE_LIBBACKTRACE` CMake option is unaffected; the change is purely about how the source is obtained.
- Data formats/schemas: none
- Build behavior: Builds that previously relied on the `GIT_REPOSITORY`/`GIT_TAG` fallback in `ExternalProject_Add` now require the submodule to be initialized (`git submodule update --init --recursive`). This is the standard expectation per `CLAUDE.md` prerequisites.
## Design Elements
Design elements this commit consumes:
- **Packaging and Build System** ([`.knowledge/designs/0016-packaging-and-build.md`](../designs/0016-packaging-and-build.md)): The `AddLibbacktrace.cmake` utility that builds libbacktrace as an ExternalProject and creates the `libbacktrace` imported static target. The `_libbacktrace_compile()` function's `ExternalProject_Add` call is the direct site of the change.
- **Cross-Language Traceback System** ([`.knowledge/designs/0015-traceback-system.md`](../designs/0015-traceback-system.md)): libbacktrace is the runtime dependency that powers native stack-frame collection for `TVMFFITraceback` on non-Windows platforms.

Design elements this commit produces:
- None. No new design elements are introduced; this is a revert-and-fixup commit that restores and corrects existing infrastructure.
## Reflection

### Design docs to write
None. The relevant design docs (`0016-packaging-and-build.md`, `0015-traceback-system.md`) already cover libbacktrace's role in the build system and traceback pipeline. The submodule vs. cmake-fetch decision is a build-level detail appropriately captured in the ADR below.

### ADRs to write
- **`.knowledge/ADRs/0023-libbacktrace-source-strategy.md`**
  - Context: libbacktrace source was briefly fetched via `GIT_REPOSITORY`/`GIT_TAG` in CMake (#18246) but immediately reverted to git submodule (#18249). The fork (`tlc-pack/libbacktrace`) carried a single macOS Mach-O patch that upstream has since incorporated.
  - Alternatives: (1) CMake `FetchContent`/`ExternalProject_Add` with git URL -- simpler for CI but breaks offline/air-gapped builds and adds network dependency; (2) Git submodule pointing to upstream -- no network fetch at build time, version pinned by submodule SHA, standard for the repo's `3rdparty/` pattern.
  - Decision: Use git submodule pointing to upstream (`ianlancetaylor/libbacktrace`) since the fork's patch is merged upstream and the submodule approach is the established convention for all vendored dependencies in `3rdparty/`.

### Skill evolution (`/commit-ledger`)
- The procedure handles trivial/chore commits well via the Step 2 shortcut. However, for "revert" commits, it would be helpful to explicitly note in Step 1 guidance that the reverting commit's parent (`git show $COMMIT^`) should be examined to understand what is being undone. This commit was trivial only because I also inspected `b245f1f` to confirm what the `GIT_REPOSITORY`/`GIT_TAG` lines were and why they were added.
## Self-Evolution of Skill /commit-ledger
- **Add "revert commit" heuristic to Step 1**: When the commit message contains "Revert" or explicitly references another commit/PR, the procedure should instruct the agent to also fetch the diff and message of the reverted commit. This gives full context without requiring the agent to infer it. Suggested addition to Step 1: "If the commit message indicates a revert (contains 'Revert', 'revert', or references a prior PR), also run `git show` on the reverted commit to understand the change being undone."
- **Submodule pointer changes deserve a note**: The numstat for submodule changes (`1 1 3rdparty/libbacktrace`) is opaque. Step 1 could suggest running `git diff $COMMIT^..$COMMIT -- '*.gitmodules' 3rdparty/` to surface the old/new submodule SHAs more clearly, since the numstat alone does not reveal the nature of a submodule update.
