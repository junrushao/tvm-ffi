# Force-inline Python FFI helper functions and page-align the call stack
## TL;DR
- Annotates all hot-path Python FFI helper functions (`FuncCall`, `ConstructorCall`, `SetField`, `SetArgument`, and free-function wrappers) with `TVM_FFI_INLINE` (`[[gnu::always_inline]]` / `[[msvc::forceinline]]`) to guarantee inlining and correct register-passing for multi-parameter calls.
- Increases the default thread-local call stack from 64 `TVMFFIAny` slots to `4096 / sizeof(TVMFFIAny)` (256 slots for 16-byte `TVMFFIAny`), making it page-aligned (4 KB).
- Locally redefines `TVM_FFI_INLINE` in `tvm_ffi_python_helpers.h` (guarded by `#ifndef`) to avoid pulling in C++ headers (`base_details.h`) from the Cython compilation unit.

## Key Exports

**Macros**:
- `TVM_FFI_INLINE` (local redefinition in `tvm_ffi_python_helpers.h`): Expands to `[[msvc::forceinline]] inline` on MSVC, `[[gnu::always_inline]] inline` on GCC/Clang. Guarded by `#ifndef TVM_FFI_INLINE` so the canonical definition in `base_details.h` takes precedence if already included.

**Constants** (changed):
- `kDefaultStackSize`: Changed from `32` (interpreted as element count, yielding `32 * 2 = 64` `TVMFFIAny` slots) to `4096` (interpreted as bytes, yielding `4096 / sizeof(TVMFFIAny)` slots). For 16-byte `TVMFFIAny`, this is 256 slots.

**Functions annotated with `TVM_FFI_INLINE`** (previously `inline`):
| Function | Scope |
|----------|-------|
| `TVMFFIPyArgSetter::operator()` | struct member |
| `TVMFFIPyCallManager::FuncCall` | class member |
| `TVMFFIPyCallManager::ConstructorCall` | class member |
| `TVMFFIPyCallManager::SetField` | class member |
| `TVMFFIPyCallManager::SetArgument` | private member |
| `TVMFFIPyFuncCall` | free function |
| `TVMFFIPyConstructorCall` | free function |
| `TVMFFIPyCallFieldSetter` | free function |
| `TVMFFIPyPyObjectToFFIAny` | free function |
| `TVMFFIPyGetDispatchMapSize` | free function |
| `TVMFFIPyPushTempFFIObject` | free function |
| `TVMFFIPyPushTempPyObject` | free function |

## Impact
- API: None. All changes are internal to `tvm_ffi_python_helpers.h`.
- Behavioral: Force-inlining ensures register-passing correctness for functions with many parameters that was previously dependent on compiler optimization level (O3). The 4x larger stack reduces heap-fallback frequency for calls with many arguments.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python FFI call dispatch** ([0015-python-ffi-call-dispatch.md](../designs/0015-python-ffi-call-dispatch.md)): All annotated functions are part of the hot call path described in this design doc.
- **`TVM_FFI_INLINE` macro** (defined canonically in `include/tvm/ffi/base_details.h`): Redefined locally to avoid C++ header dependency in the Cython compilation context.

Design elements this commit produces:
- **Local `TVM_FFI_INLINE` guard pattern**: Establishes a pattern for Cython helper headers to redefine core macros locally when C++ header inclusion is undesirable, using `#ifndef` guards for compatibility.
- **Page-aligned stack sizing invariant**: The temp call stack is now 4 KB (page-aligned), sized in bytes rather than element count, improving memory alignment and reducing page-boundary straddles.

## Usage Examples
None -- this is a performance-only change with no new API surface. The force-inlining is transparent to callers.
