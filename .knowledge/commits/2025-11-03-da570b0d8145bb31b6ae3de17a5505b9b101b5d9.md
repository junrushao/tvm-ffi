# Add GitHub Actions workflow to build and publish torch_c_dlpack_ext wheels to PyPI

## TL;DR
- Adds `.github/workflows/torch_c_dlpack.yml`, a manual-dispatch GitHub Actions workflow that builds the `torch_c_dlpack_ext` addon as Python wheels and publishes them to PyPI.
- The workflow compiles `torch_c_dlpack` shared libraries against PyTorch 2.4 through 2.9 on both x86_64 and aarch64, with CPU and CUDA variants, using manylinux_2_28 Docker containers with CUDA 13.0.2 toolkit.
- Follows the same publish pattern as the existing `publish_wheel.yml` (artifact attestation + `pypa/gh-action-pypi-publish`), but uses a multi-stage pipeline: `build_libs` -> `build_wheels` -> `build_source` -> `upload_pypi`.

## Design Elements
Design elements this commit consumes:
- **torch_c_dlpack_ext addon** (`addons/torch_c_dlpack_ext/`): The addon package this workflow builds and publishes. Uses `tvm_ffi.utils._build_optional_torch_c_dlpack` to compile per-PyTorch-version shared libraries.
- **Publish wheel workflow pattern** (`.github/workflows/publish_wheel.yml`): The `upload_pypi` job mirrors the existing `publish_wheel.yml` pattern -- `pypi` environment, `id-token: write` + `attestations: write` permissions, `attest-build-provenance@v1`, `gh-action-pypi-publish@release/v1` with attestations enabled.
- **manylinux_2_28 container** (`quay.io/pypa/manylinux_2_28_{arch}`): Used for both build stages. Consistent with the main package's cibuildwheel config which also targets manylinux_2_28.
- **auditwheel repair**: Repairs wheels to manylinux compliance while excluding PyTorch's own shared libs (`libtorch.so`, `libtorch_cpu.so`, `libc10.so`, `libtorch_python.so`).

Design elements this commit produces:
- **torch_c_dlpack release pipeline**: A four-stage GitHub Actions workflow (`build_libs` -> `build_wheels` -> `build_source` -> `upload_pypi`). This is the first CI workflow specific to the addons directory. The pipeline produces per-arch, per-Python-version wheels that bundle pre-compiled `.so` files for multiple PyTorch versions.
