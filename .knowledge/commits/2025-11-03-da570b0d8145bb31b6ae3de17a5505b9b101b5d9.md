# Add GitHub Actions workflow to build and publish torch-c-dlpack-ext wheels to PyPI
## TL;DR
- Adds a new GitHub Actions workflow (`.github/workflows/torch_c_dlpack.yml`) that automates the build and release of the `torch-c-dlpack-ext` addon package to PyPI.
- The workflow is manual-trigger only (`workflow_dispatch`), builds native `.so` libs for PyTorch 2.4 through 2.9 across x86_64/aarch64 and Python 3.9-3.13, then packages them into manylinux wheels with `auditwheel repair`.
- The final `upload_pypi` job uses trusted publishing (OIDC `id-token: write`) with build-provenance attestation via `actions/attest-build-provenance@v1`.

## Design Elements
Design elements this commit consumes:

- Python packaging architecture (`.knowledge/designs/0015-python-packaging.md`) -- follows the same trusted-publishing and attestation patterns established in the main `publish_wheel.yml` workflow.
- The `addons/torch_c_dlpack_ext` package introduced in commit f703a0c (#189) -- the wheel build step uses this addon's `pyproject.toml` and `build_backend.py`.

Design elements this commit produces:
- CI workflow for `torch-c-dlpack-ext` PyPI release -- a four-job pipeline: `build_libs` (compile per-torch-version `.so` files in manylinux Docker), `build_wheels` (package `.so` into Python-version-specific wheels with `auditwheel`), `build_source` (sdist), `upload_pypi` (trusted publish).
