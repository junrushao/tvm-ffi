# Add tvm_ffi.libinfo.load_lib_module as a high-level Module-returning library loader

## TL;DR
- Adds `load_lib_module(package, target_name, keep_module_alive=True)` to `tvm_ffi.libinfo`, returning a `ffi.Module` (not a raw `ctypes.CDLL`). Builds on the existing `_find_library_by_basename` path-resolution logic.
- Updates `examples/packaging` to use the new API — `base.py` shrinks from 32 lines to 2, eliminating hand-rolled glob/path/platform logic.
- Removes `set_target_properties(my_ffi_extension PROPERTIES PREFIX "")` from the example CMakeLists so the built library follows standard platform naming (`libmy_ffi_extension.so`), which is what `_find_library_by_basename` expects.

## Impact
- API: New public function `tvm_ffi.libinfo.load_lib_module` — additive, no callers broken.
- Behavioral: Example `base.py` now uses Module-lifetime semantics (default `keep_module_alive=True`) vs. the old ctypes-CDLL approach with no lifetime management. The example is now editable-build-safe.
- Flags/config: `keep_module_alive` parameter controls whether the returned Module is appended to a global hold-list; default `True` prevents accidental unload.
- Data formats/schemas: CMake `PREFIX ""` removed from `my_ffi_extension` target — artifact is now `libmy_ffi_extension.{so,dylib}` (Linux/macOS) not `my_ffi_extension.{so,dylib}`. Callers that hard-coded the prefix-less name will break.

## Design Elements
Design elements this commit consumes:
- `0011-module-system`: `ffi.Module` and `load_module` (Python) are the return type and constructor used by `load_lib_module`. The Module lifetime invariant (Module must outlive all objects whose deleters reside in the `.so`) is the motivation for `keep_module_alive`.
- `0013-python-package`: `_find_library_by_basename(package, target_name)` from `libinfo.py` — generalized platform-aware locator already used by `find_libtvm_ffi()` and `load_lib_ctypes()`. `tvm_ffi.libinfo` submodule accessible via `tvm_ffi.libinfo.*`.
- `0021-build-packaging`: CMake library naming convention (`lib<target>.so` on Linux/macOS, `<target>.dll` on Windows).

Design elements this commit produces:
- **`load_lib_module` convention** — a standard "downstream extension loading" pattern: call `load_lib_module(pip_package, cmake_target)` in `base.py`. Extends `0013-python-package` with a new library-loading entry point at Module level (counterpart to `load_lib_ctypes` at ctypes level).

## Usage Examples

Downstream extension package `base.py` after this commit:

```python
import tvm_ffi

# One-liner: resolves lib path, handles win32 DLL dir, returns Module, keeps it alive
_LIB = tvm_ffi.libinfo.load_lib_module("my-ffi-extension", "my_ffi_extension")
# "my-ffi-extension" = pip package name (used to locate site-packages install path)
# "my_ffi_extension" = CMake target name → derives libmy_ffi_extension.so / my_ffi_extension.dll
```
