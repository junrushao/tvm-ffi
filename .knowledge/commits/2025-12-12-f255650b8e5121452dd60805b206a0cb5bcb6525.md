# Add `load_lib_module` to simplify downstream extension library loading
## TL;DR
- Adds `tvm_ffi.libinfo.load_lib_module(package, target_name, keep_module_alive)` -- a convenience API that combines `_find_library_by_basename` with `load_module`, returning a `Module` directly instead of a `ctypes.CDLL`.
- Replaces the 27-line manual library loading boilerplate in `examples/packaging/python/my_ffi_extension/base.py` with a single 1-line call.
- Removes `set_target_properties(my_ffi_extension PROPERTIES PREFIX "")` from the packaging example's CMake, restoring the default `lib` prefix for the shared library (which `_find_library_by_basename` already expects on Linux/macOS).

## Impact
- API: New public function `tvm_ffi.libinfo.load_lib_module`. No existing API changed or removed.
- Behavioral: The packaging example now produces `libmy_ffi_extension.so` (with `lib` prefix) instead of `my_ffi_extension.so` (without prefix), because the CMake `PREFIX ""` override was removed. This aligns with what `_find_library_by_basename` searches for on Linux/macOS.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`_find_library_by_basename`** (libinfo.py): Reuses the existing library discovery mechanism that searches `importlib.metadata` RECORD then fallback directories. Documented in [0013-packaging.md](../designs/0013-packaging.md).
- **`load_module`** (module.py): Delegates to the existing `Module::LoadFromFile` pipeline to load the discovered library as a `Module`. Documented in [0011-module-system.md](../designs/0011-module-system.md).
- **`load_lib_ctypes`**: The new function mirrors the existing `load_lib_ctypes` pattern (same parameter names, same Windows `add_dll_directory` guard), but returns `Module` instead of `ctypes.CDLL`.

Design elements this commit produces:
- **`load_lib_module`**: New public API for downstream extension packages to load their compiled shared libraries as `Module` objects with a single call, handling platform-specific library naming and discovery automatically.

## Usage Examples
**Context**: Loading a downstream C++ extension library using the new API (replaces 27-line manual boilerplate).

```python
# Before (removed pattern):
import sys
from pathlib import Path
import tvm_ffi

def _load_lib() -> tvm_ffi.Module:
    file_dir = Path(__file__).resolve().parent
    path_candidates = [file_dir, file_dir / ".." / ".." / "build"]
    if sys.platform.startswith("win32"):
        lib_dll_name = "my_ffi_extension.dll"
    elif sys.platform.startswith("darwin"):
        lib_dll_name = "my_ffi_extension.dylib"
    else:
        lib_dll_name = "my_ffi_extension.so"
    for candidate in path_candidates:
        for path in Path(candidate).glob(lib_dll_name):
            return tvm_ffi.load_module(str(path))
    raise RuntimeError(f"Cannot find {lib_dll_name} in {path_candidates}")
_LIB = _load_lib()

# After (new pattern):
import tvm_ffi
_LIB = tvm_ffi.libinfo.load_lib_module("my-ffi-extension", "my_ffi_extension")
```
