# Add `tvm_ffi.libinfo.load_lib_module` for convenient extension library loading

## TL;DR
- Introduces `tvm_ffi.libinfo.load_lib_module(package, target_name, keep_module_alive)` — a high-level API that combines library discovery (`_find_library_by_basename`) with `tvm_ffi.load_module`, returning a `Module` object. Works for both editable and non-editable installs.
- Simplifies the canonical extension loading pattern: `examples/packaging/python/my_ffi_extension/base.py` shrinks from a 27-line `_load_lib()` function to a 2-line call to the new API.
- Removes `set_target_properties(my_ffi_extension PROPERTIES PREFIX "")` from the example CMakeLists.txt — the new API uses `_find_library_by_basename` which handles platform-specific library name prefixes (`lib` on Linux/macOS, none on Windows).

## Impact
- API: New public function `tvm_ffi.libinfo.load_lib_module`. No breaking changes — `load_lib_ctypes` and manual `_load_lib` patterns remain functional.
- Behavioral: Extensions using the new API get automatic platform-specific library name resolution and Windows DLL directory handling, matching the behavior previously only available through `load_lib_ctypes` (for ctypes) or hand-written `_load_lib()` functions.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- [0011-ffi-module-system](../design-records/0011-ffi-module-system.md) — `load_module()` and `Module` type for wrapping shared libraries as FFI module objects.
- [0013-ffi-packaging-and-distribution](../design-records/0013-ffi-packaging-and-distribution.md) — `_find_library_by_basename()` for platform-aware library discovery, the canonical `_load_lib` + `init_ffi_api` extension pattern.
- [0012-ffi-python-package](../design-records/0012-ffi-python-package.md) — `find_library_by_basename()` originally introduced in da7007f.

Design elements this commit produces:
- **`load_lib_module` API** — a new convenience function in `tvm_ffi.libinfo` that becomes the recommended replacement for hand-written `_load_lib()` boilerplate in extension packages. This simplifies the canonical extension pattern from [0013-ffi-packaging-and-distribution](../design-records/0013-ffi-packaging-and-distribution.md).
- **Removal of CMake `PREFIX ""` requirement** — extension CMakeLists no longer need `set_target_properties(... PROPERTIES PREFIX "")` because `_find_library_by_basename` handles platform lib prefixes automatically.

## Usage Examples
Loading a native extension library (the canonical pattern after this commit):
```python
# my_ffi_extension/base.py — entire file after this change
import tvm_ffi

_LIB = tvm_ffi.libinfo.load_lib_module("my-ffi-extension", "my_ffi_extension")
```

For comparison, the previous pattern required a 25+ line `_load_lib()` function with manual platform detection (`win32`/`darwin`/Linux`), path candidate construction, and glob-based library search.
