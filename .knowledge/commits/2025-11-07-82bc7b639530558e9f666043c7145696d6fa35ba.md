# Fix missing static registration for DLTensor* in TypeTable constructor
## TL;DR
- Added the missing `ReserveBuiltinTypeIndex(StaticTypeKey::kTVMFFIDLTensorPtr, TypeIndex::kTVMFFIDLTensorPtr)` call in the `TypeTable` constructor, fixing a gap where type index 7 (`DLTensor*`) was not registered as a builtin POD type.
- Without this registration, `TypeIndexToTypeKey` could not resolve `kTVMFFIDLTensorPtr` to its string name `"DLTensor*"`, causing incorrect or missing type names in error messages (e.g., when a `DLTensor*` is passed to a typed function expecting a different type).
- Added a test verifying that passing `DLTensor*` to a typed `int -> int` function produces a `TypeError` with the correct message including `"DLTensor*"`.

## Key Exports
None -- no new API surface. This commit fixes an omission in the existing `TypeTable` initialization sequence.

## Impact
- API: None
- Behavioral: `TypeIndexToTypeKey(kTVMFFIDLTensorPtr)` now correctly resolves to `"DLTensor*"` at runtime, producing accurate error messages when DLTensor pointers are used in typed function calls with mismatched signatures.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **TypeTable constructor and `ReserveBuiltinTypeIndex`** ([0002-object-system](../designs/0002-object-system.md)) -- the mechanism for pre-registering all built-in POD type indices so that `TypeIndexToTypeKey` can resolve them. Each call maps a `StaticTypeKey` string to a `TypeIndex` integer in the global type table.
- **`StaticTypeKey::kTVMFFIDLTensorPtr` / `TypeIndex::kTVMFFIDLTensorPtr`** ([0001-c-abi](../designs/0001-c-abi.md)) -- the type key `"DLTensor*"` and type index `7` for non-owning DLTensor pointers in the POD range `[0, 64)`.
- **`Function::FromTyped` and typed argument checking** ([0004-function-system](../designs/0004-function-system.md)) -- the test exercises the typed function path where argument type mismatch triggers a `TypeError` with a message derived from `TypeIndexToTypeKey`.

Design elements this commit produces:
- None -- purely fixes an omission in an existing registration list.

## Usage Examples
**Before fix**: Passing a `DLTensor*` to a typed function expecting `int` would produce a `TypeError`, but the error message could not resolve `"DLTensor*"` as the type name because `kTVMFFIDLTensorPtr` was not registered in the type table.

**After fix**: The same scenario produces a correct, informative error message:
```cpp
Function fadd1 = Function::FromTyped([](int x) -> int { return x + 1; });
DLTensor dltensor;
// Throws TypeError with message:
// "Mismatched type on argument #0 when calling: `(0: int) -> int`.
//  Expected `int` but got `DLTensor*`"
fadd1(&dltensor);
```
