# Fix missing static type registration for DLTensor* in TypeTable
## TL;DR
- Adds the missing `ReserveBuiltinTypeIndex(StaticTypeKey::kTVMFFIDLTensorPtr, TypeIndex::kTVMFFIDLTensorPtr)` call in `TypeTable` initialization, so `DLTensor*` has a proper type name for error messages and type checking.
- Adds a C++ test verifying that passing a `DLTensor*` to a typed function expecting `int` produces a clear `TypeError` with the `DLTensor*` type name.

## Key Exports
None (no new public API; this is a registration fix for an existing builtin type index)

## Impact
- API: none
- Behavioral: `DLTensor*` now has a registered type name in the TypeTable, so type mismatch errors display `DLTensor*` instead of an unknown type index. Without this fix, passing `DLTensor*` to a mismatched typed function could produce confusing error messages or fail differently.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeTable` / `ReserveBuiltinTypeIndex` -- the static type registration mechanism in `src/ffi/object.cc` per `.knowledge/designs/0005-type-traits.md`
- `StaticTypeKey::kTVMFFIDLTensorPtr` / `TypeIndex::kTVMFFIDLTensorPtr` -- the builtin type index for DLTensor pointers per `.knowledge/designs/0001-c-abi-layer.md`

Design elements this commit produces: none (restores expected invariant)

## Usage Examples
Before (broken): passing `DLTensor*` to a typed function could produce unclear error message because the type key was not registered.

After (fixed):
```cpp
Function fadd1 = Function::FromTyped([](int x) { return x + 1; });
DLTensor dltensor;
fadd1(&dltensor);
// Throws TypeError: "Mismatched type on argument #0 ... Expected `int` but got `DLTensor*`"
```
