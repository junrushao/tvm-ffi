# Add ObjectCreator class, Shape serialization, and relaxed CreateObjectData return type
## TL;DR
- Introduces `reflection::ObjectCreator` in a new header `include/tvm/ffi/reflection/creator.h`, a reusable helper class that creates objects from a `Map<String, Any>` of field values using reflection metadata. This extracts and formalizes the pattern previously embedded in `MakeObjectFromPackedArgs`.
- Adds `Shape` serialization/deserialization support to `ObjectGraphSerializer` / `ObjectGraphDeserializer` in `src/ffi/extra/serialization.cc`, serializing `Shape` as `{"type": "ffi.Shape", "data": [dim0, dim1, ...]}`.
- Relaxes the return type of `CreateObjectData` from `json::Object` to `json::Value`, allowing `__data_to_json__` type attribute functions to return any JSON value (not just objects). This enables types to serialize their data as arrays, strings, or other non-object JSON forms.

## Impact
- API: `reflection::ObjectCreator` is a new public C++ class in `include/tvm/ffi/reflection/creator.h`. No existing API is broken. The `CreateObjectData` return type change from `json::Object` to `json::Value` is a relaxation that is backward-compatible for existing `__data_to_json__` registrations that already return `json::Object`, since `json::Object` is implicitly convertible to `json::Value`.
- Flags/config: none.
- Data formats/schemas: The JSON serialization format gains a new built-in node type `{"type": "ffi.Shape", "data": [int64...]}`. Previously, `Shape` values would have fallen into the `default` branch and been serialized as generic objects via field-by-field reflection (or thrown if metadata was missing). Now they get a dedicated, compact format.

## Design Elements
Design elements this commit **consumes**:

- **Reflection system** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `ObjectCreator` uses `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`, `TVMFFITypeInfo::metadata->creator`, and `kTVMFFIFieldFlagBitMaskHasDefault` -- all core reflection primitives. The field-setter call in the commit's diff uses `field_info->setter(field_addr, ...)` directly, while the current HEAD version uses the wrapper `CallFieldSetter`.
- **Object system / TypeTable** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `ObjectCreator` calls `TVMFFIGetTypeInfo(TypeKeyToIndex(type_key))` and `ObjectUnsafe::ObjectPtrFromOwned` to allocate and take ownership of a default-constructed object.
- **Container system / Shape** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The serialization code constructs `Array<int64_t>(shape->data, shape->data + shape->size)` for encoding and `ffi::Shape(data)` from `Array<int64_t>` for decoding. This relies on `Shape`'s data/size accessors and its constructor from a range.
- **Extra API tier / Serialization** ([`.knowledge/designs/0011-extra-api-tier.md`](../designs/0011-extra-api-tier.md)): The serialization changes live in `src/ffi/extra/serialization.cc`, an extra-tier source file.
- **TypeAttrColumn** ([`.knowledge/designs/0010-type-attr-columns.md`](../designs/0010-type-attr-columns.md)): `CreateObjectData` uses `TypeAttrColumn("__data_to_json__")` to check for custom serialization hooks.

Design elements this commit **produces**:

- **`reflection::ObjectCreator` class** (`include/tvm/ffi/reflection/creator.h`): A named, reusable abstraction for reflection-based object construction from `Map<String, Any>`. Takes a type key or `TVMFFITypeInfo*` at construction time, validates creator availability, and provides `operator()(Map<String, Any>)` to create an object with field population. This is a clean separation from the packed-args protocol of `MakeObjectFromPackedArgs`, suitable for C++ callers that already have named fields.
- **Shape serialization format**: A new case in the serialization switch for `TypeIndex::kTVMFFIShape`, encoding as `Array<int64_t>` and decoding back via `ffi::Shape(Array<int64_t>)`. This is a compact, non-graph-node format (no index references needed since `int64_t` elements are primitive).

## Key Implementations

### ObjectCreator: Reflection-based construction from Map<String, Any>

`ObjectCreator` at `include/tvm/ffi/reflection/creator.h` implements the same field-population loop as `MakeObjectFromPackedArgs` but with a `Map<String, Any>` input instead of packed args with interleaved key-value pairs.

Protocol:
1. **Construction**: Validates that `type_info->metadata->creator` exists (throws `RuntimeError` otherwise).
2. **`operator()` invocation**: Calls `creator` to allocate an empty object, then iterates fields via `ForEachFieldInfo`. For each field: if present in the map, calls `setter`; if absent but has default, applies default; if absent and required, throws `TypeError`.
3. **Extra-field detection**: After the field loop, if `match_field_count < fields.size()`, iterates the map keys and checks each against registered field names via `ForEachFieldInfoWithEarlyStop`, reporting the first unknown field.

The key invariant is that field names in the map must exactly match registered field names. Unknown fields and missing required fields are both reported as `TypeError`.

Note: The diff introduces the initial version which calls `field_info->setter` directly. The current HEAD version has been updated to use `CallFieldSetter` and `SetFieldToDefault` wrapper functions (likely for safer error handling), and uses `CreateEmptyObject` (which also supports `__ffi_new__` fallback) instead of directly calling `metadata->creator`.

### Shape serialization/deserialization

The `Shape` type gets first-class treatment in the serialization switch:
- **Serialization** (`ObjectGraphSerializer`): `shape->data` / `shape->size` are used to construct `Array<int64_t>`, stored as the `"data"` field of the node.
- **Deserialization** (`ObjectGraphDeserializer`): `node["data"].cast<Array<int64_t>>()` is passed to `ffi::Shape(Array<int64_t>)`.

This avoids the generic `CreateObjectData` path, which would require `Shape` to have full reflection metadata registered. The format `{"type": "ffi.Shape", "data": [1, 2, 3]}` is parallel to how `Array` serializes its data as an array of node indices, but `Shape` data are primitive `int64_t` values rather than graph references.

### CreateObjectData return type relaxation

Changing the return type from `json::Object` to `json::Value` removes an unnecessary constraint. Previously, the `__data_to_json__` hook was forced to return `json::Object`, which would fail if a type's natural serialization is a non-object JSON value (e.g., an array or string). The cast of the result is correspondingly relaxed from `.cast<json::Object>()` to a direct return of the `json::Value`.

### TIntObj default constructor

`tests/cpp/testing_object.h` adds `TIntObj() = default;` to enable default construction. This is required for `ObjectCreator` to work with `TIntObj`, since the reflection-based creator calls `metadata->creator` which invokes the default constructor. Without this, the `ObjectCreator` test would fail at object creation time.

## Reflection

### Design docs to write

- **`.knowledge/designs/0006-reflection.md` -- add ObjectCreator section**: The current reflection design doc covers `MakeObjectFromPackedArgs` but does not mention `ObjectCreator`. The doc should be updated to describe `ObjectCreator` as the C++-ergonomic, `Map<String, Any>`-based alternative to the packed-args protocol. This helps future commits that modify object construction paths by providing a single reference for both creation APIs.

- **`.knowledge/designs/0012-serialization.md` -- new design doc**: No design doc currently covers the JSON object graph serialization system (`ToJSONGraph`/`FromJSONGraph`). A doc should cover:
  - The graph schema (`root_index` + `nodes` array with `type`/`data` fields per node).
  - The dispatch logic: built-in type switches for POD, String, Bytes, Array, Map, List, Dict, Shape, followed by generic object field-by-field serialization.
  - The `__data_to_json__` / `__data_from_json__` extensibility hooks via `TypeAttrColumn`.
  - This helps future commits that add new container types or modify the serialization format.

### ADRs to write

None. The decisions here (dedicated Shape format, relaxed return type) are straightforward extensions of the existing serialization pattern. No significant alternatives were rejected.
