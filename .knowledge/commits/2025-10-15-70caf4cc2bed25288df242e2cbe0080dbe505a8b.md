# Fix Cython `noexcept` → `except -1` annotations on DLPack callback typedefs and restore exception propagation in torch DLPack fallback path

## TL;DR
- Four `ctypedef` function pointer declarations in `base.pxi` (DLPack exchange API callbacks) changed from `noexcept` to `except -1`, enabling Cython to check the -1 return code and propagate pending Python exceptions instead of silently discarding them.
- `TorchDLPackToPyObjectFallback_` in `function.pxi` changed from `noexcept` to `except -1` and its internal `try/except: return -1` swallowing block removed; exceptions now propagate with full tracebacks.
- `make_tensor_from_chandle` in `tensor.pxi` changes `cdef Tensor tensor` → `cdef object tensor` and removes a stale `TODO` comment, allowing the local variable to hold any Python object (e.g. a torch tensor) returned by the DLPack exchange API.

## Key Exports

```python
# Cython ctypedef extern annotations — DLPack exchange API callbacks (base.pxi)
# These are C function pointer types declared in the cdef extern from "dlpack/dlpack.h" block.
# OLD: noexcept  →  NEW: except -1
# Interacts with: DLPackExchangeAPI struct (0016-py-ffi-call-dispatch), TVMFFIPyCallManager

ctypedef int (*DLPackManagedTensorFromPyObjectNoSync)(
    py_object: void*, out: DLManagedTensorVersioned**
) except -1

ctypedef int (*DLPackManagedTensorToPyObjectNoSync)(
    tensor: DLManagedTensorVersioned*, out_py_object: void**
) except -1

ctypedef int (*DLPackCurrentWorkStream)(
    device_type: int, device_id: int32_t, out_current_stream: void**
) except -1

ctypedef int (*DLPackDLTensorFromPyObjectNoSync)(
    py_object: void*, out: DLTensor*
) except -1

# TorchDLPackToPyObjectFallback_ (function.pxi)
# OLD: noexcept + internal try/except swallowing exceptions
# NEW: except -1 + bare code — exceptions propagate naturally
# Interacts with: TVMFFITensorFromDLPackVersioned, make_tensor_from_chandle, torch.from_dlpack
# Invariant: returns 0 on success; any raised Python exception propagates to caller via except -1
cdef int TorchDLPackToPyObjectFallback_(
    dltensor: DLManagedTensorVersioned*, py_obj_out: void**
) except -1: ...

# make_tensor_from_chandle (tensor.pxi)
# OLD: cdef Tensor tensor  (forced narrow Tensor type)
# NEW: cdef object tensor  (allows any Python object from DLPack exchange API callback)
# Interacts with: DLPackExchangeAPI.managed_tensor_to_py_object_no_sync, Py_DECREF lifecycle
cdef object make_tensor_from_chandle(
    chandle: TVMFFIObjectHandle,
    c_ctx_dlpack_api: DLPackExchangeAPI* = NULL
): ...
```

## Impact
- API: None — no public Python API changed.
- Behavioral: Exceptions raised inside DLPack exchange API callbacks (e.g. during `managed_tensor_to_py_object_no_sync`) now propagate correctly to Python callers instead of being silently dropped. `TorchDLPackToPyObjectFallback_` failures now surface full tracebacks.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `DLPackExchangeAPI` / `TVMFFIPyCallManager` dispatch cascade (0016-py-ffi-call-dispatch) — the fixed typedefs are the Cython-side declarations of this protocol's callback signatures.
- `Tensor` / `TensorView` / `make_tensor_from_chandle` (0007-containers) — `make_tensor_from_chandle` is the helper that converts a C handle into a Python tensor object; the type narrowing bug prevented it from holding non-`Tensor` objects returned by exchange API callbacks.

Design elements this commit produces: None — bugfix only, restores existing invariants.

## Usage Examples

```python
# BEFORE: exception in DLPack callback is silently lost
# noexcept on the ctypedef means Cython does not check for pending Python exceptions
# even when the function returns -1; error detail is discarded.

# Also in TorchDLPackToPyObjectFallback_ (BEFORE):
# try:
#     tensor = make_tensor_from_chandle(temp_chandle)
#     torch_tensor = torch.from_dlpack(tensor)
#     ...
#     return 0
# except Exception:
#     return -1   ← traceback swallowed here

# AFTER: exceptions propagate with full tracebacks
# except -1 annotation: Cython checks PyErr_Occurred() when return value is -1
# TorchDLPackToPyObjectFallback_ (AFTER):
#     tensor = make_tensor_from_chandle(temp_chandle)   # raises on error
#     torch_tensor = torch.from_dlpack(tensor)           # raises on error
#     Py_INCREF(torch_tensor)
#     py_obj_out[0] = <void*>(<PyObject*>torch_tensor)
#     return 0
# Any exception from the above propagates naturally up the Cython call stack.
```
