# Fix Cython exception specs and type cast for DLPack callback typedefs
## TL;DR
- Changed 4 DLPack callback `ctypedef` function pointers in `base.pxi` from `noexcept` to `except -1`, enabling Cython to generate proper exception-checking code after invoking these callbacks.
- Changed `TorchDLPackToPyObjectFallback_` from `noexcept` to `except -1` and removed the redundant `try/except` block that was silently swallowing exception details.
- Fixed `make_tensor_from_chandle` to use `cdef object` and `<object>` cast instead of `cdef Tensor` and `<Tensor>` cast, since DLPack `managed_tensor_to_py_object_no_sync` returns framework-native objects (e.g. `torch.Tensor`), not Cython `Tensor`.

## Key Exports
None -- no new public API. The fix is internal to Cython `.pxi` files.

## Impact
- API: None -- no public signature changes.
- Behavioral: Exception propagation from DLPack callbacks now works correctly. Previously, `noexcept` on the callback typedefs caused Cython to ignore exceptions raised inside these callbacks (silently discarding them or crashing). With `except -1`, Cython checks the return value and propagates the Python exception. Additionally, `make_tensor_from_chandle` no longer crashes when the DLPack to-PyObject callback returns a non-`Tensor` Python object.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
**Before (broken)**: `noexcept` on callback typedefs meant Cython would NOT check for Python exceptions after invoking these function pointers. If a callback raised an exception (by returning -1 and setting a Python exception), Cython would ignore it, leading to silent data corruption or segfaults.

```python
# base.pxi (before)
ctypedef int (*DLPackManagedTensorFromPyObjectNoSync)(
    void* py_object,
    DLManagedTensorVersioned** out
) noexcept  # BUG: Cython won't check for exception after call

# function.pxi (before)
cdef int TorchDLPackToPyObjectFallback_(...) noexcept:
    ...
    try:
        ...  # exceptions caught and silently converted to -1
    except Exception:
        return -1  # error details lost

# tensor.pxi (before)
cdef Tensor tensor  # BUG: result may not be a Cython Tensor
tensor = <Tensor>(<PyObject*>py_obj)  # crashes if py_obj is torch.Tensor
```

**After (fixed)**: `except -1` tells Cython to check the return value and propagate exceptions. The `try/except` wrapper becomes unnecessary. The type is widened to `object`.

```python
# base.pxi (after)
ctypedef int (*DLPackManagedTensorFromPyObjectNoSync)(
    void* py_object,
    DLManagedTensorVersioned** out
) except -1  # Cython checks return value, propagates exception

# function.pxi (after)
cdef int TorchDLPackToPyObjectFallback_(...) except -1:
    ...
    # no try/except needed; exception auto-propagates

# tensor.pxi (after)
cdef object tensor  # correct: result is any Python object
tensor = <object>(<PyObject*>py_obj)  # safe cast to generic object
```
