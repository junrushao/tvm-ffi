# Fix Cython type annotations for DLPack callback typedefs and tensor conversion
## TL;DR
- Changed 4 DLPack callback `ctypedef` declarations in `base.pxi` from `noexcept` to `except -1`, enabling Cython to propagate Python exceptions through these C-level callback pointers.
- Changed `TorchDLPackToPyObjectFallback_` in `function.pxi` from `noexcept` to `except -1` and removed the redundant `try/except` wrapper that was swallowing exceptions.
- Fixed `make_tensor_from_chandle` in `tensor.pxi`: changed the local variable type from `cdef Tensor tensor` to `cdef object tensor` and the cast from `<Tensor>` to `<object>`, fixing a type mismatch when the DLPack exchange returns a non-`Tensor` Python object (e.g., `torch.Tensor`).

## Key Exports
None — this commit fixes type annotations on existing internal Cython functions; no new public API is introduced.

## Impact
- API: None — all changes are internal to Cython `.pxi` include files.
- Behavioral: Exception propagation through DLPack callback typedefs now works correctly. Previously, `noexcept` silently discarded Python exceptions raised inside these callbacks, causing silent failures or undefined behavior. After the fix, exceptions propagate via Cython's `except -1` protocol (return -1 signals error, Cython checks `PyErr_Occurred()`). In `TorchDLPackToPyObjectFallback_`, exceptions from `torch.from_dlpack()` are no longer swallowed by the `try/except` block. In `make_tensor_from_chandle`, the `<object>` cast correctly handles the case where the DLPack-to-PyObject callback returns a non-`Tensor` type (e.g., `torch.Tensor`), whereas the previous `<Tensor>` cast would fail at runtime.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DLPackExchangeAPI protocol** ([0012-ffi-python-package](../../.knowledge/design-records/0012-ffi-python-package.md)): The 4 callback typedefs (`DLPackManagedTensorFromPyObjectNoSync`, `DLPackManagedTensorToPyObjectNoSync`, `DLPackCurrentWorkStream`, `DLPackDLTensorFromPyObjectNoSync`) are the C-level function pointer types inside the `DLPackExchangeAPI` struct.
- **`make_tensor_from_chandle` ownership protocol** ([0012-ffi-python-package](../../.knowledge/design-records/0012-ffi-python-package.md)): The three-way ref-count handoff (DLPack creation -> PyObject wrapping -> chandle release) relies on the callback being able to propagate exceptions correctly for the error-path cleanup to work.

Design elements this commit produces: None.

## Usage Examples
**Before (buggy)**: DLPack callback typedefs declared `noexcept` silently swallow exceptions.
```cython
# base.pxi (before)
ctypedef int (*DLPackManagedTensorToPyObjectNoSync)(
    DLManagedTensorVersioned* tensor, void** out_py_object
) noexcept  # BUG: exceptions silently discarded

# function.pxi (before) — redundant try/except to work around noexcept
cdef int TorchDLPackToPyObjectFallback_(...) noexcept:
    try:
        tensor = make_tensor_from_chandle(temp_chandle)
        torch_tensor = torch.from_dlpack(tensor)
        ...
    except Exception:
        return -1  # exception detail lost

# tensor.pxi (before) — wrong cast type
cdef Tensor tensor  # BUG: DLPack may return torch.Tensor, not tvm_ffi.Tensor
tensor = <Tensor>(<PyObject*>py_obj)  # crashes on type mismatch
```

**After (fixed)**: Proper Cython exception declarations and generic object type.
```cython
# base.pxi (after)
ctypedef int (*DLPackManagedTensorToPyObjectNoSync)(
    DLManagedTensorVersioned* tensor, void** out_py_object
) except -1  # exceptions propagate via return code + PyErr_Occurred()

# function.pxi (after) — clean, no try/except needed
cdef int TorchDLPackToPyObjectFallback_(...) except -1:
    tensor = make_tensor_from_chandle(temp_chandle)
    torch_tensor = torch.from_dlpack(tensor)
    ...
    return 0

# tensor.pxi (after) — generic object type
cdef object tensor  # accepts any Python object
tensor = <object>(<PyObject*>py_obj)  # works for torch.Tensor, etc.
```
