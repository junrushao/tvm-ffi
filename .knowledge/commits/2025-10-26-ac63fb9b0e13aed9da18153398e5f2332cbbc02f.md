# Introduce setuptools_scm for dynamic versioning and cross-language version consistency linting

## TL;DR
- Replaces the hardcoded `version = "0.1.0"` in `pyproject.toml` with `dynamic = ["version"]` backed by `setuptools_scm`, which derives version from git tags. Python `__init__.py` now imports `__version__` from an auto-generated `_version.py` with a dev fallback.
- Rewrites `tests/lint/check_version.py` from a simple pyproject-vs-init comparator into a `setuptools_scm`-based cross-language linter with `--cpp` and `--rust` flags that validate C++ macros and Rust Cargo.toml versions against the canonical project version.
- Updates all CI workflows to use `actions/checkout@v5` with `fetch-depth: 0` and `fetch-tags: true` so `setuptools_scm` can derive version from git history. Bumps C++ version macro from 0.1.0 to 0.1.1.

## Impact
- API: `__version_tuple__` is newly exported from `tvm_ffi`. `__version__` semantics unchanged (string), but value is now git-tag-derived instead of hardcoded.
- Behavioral: Version string in installed packages now reflects git distance from last tag (e.g., `0.1.1.dev9+g43f0820f6`) instead of a static `0.1.0`.
- Flags/config: `pyproject.toml` switches from static `version` to `dynamic = ["version"]`. CI checkout steps now require `fetch-depth: 0` and `fetch-tags: true`.
- Data formats/schemas: C++ macro `TVM_FFI_VERSION_PATCH` bumped from 0 to 1.

Design elements this commit consumes:

Design elements this commit produces:
- **setuptools_scm-based dynamic versioning**: Single source of truth for version derived from git tags. Replaces the prior dual-source (pyproject.toml + `__init__.py`) pattern documented in commit `ebea4dc8`.
- **Cross-language version consistency linter** (`tests/lint/check_version.py --cpp --rust`): Enforces that C++ macros and Rust Cargo.toml versions match the canonical `setuptools_scm` version.
- **Auto-generated `_version.py`**: `setuptools_scm` writes `python/tvm_ffi/_version.py` at build time; gitignored but included in sdist.

## Usage Examples
```bash
# Check C++ version consistency (run as pre-commit or standalone)
python tests/lint/check_version.py --cpp

# Check both C++ and Rust (once Rust binding matures)
python tests/lint/check_version.py --cpp --rust

# Output shows canonical version + any mismatches:
# Project version: 0.1.1.dev9+g43f0820f6.d20251021
#   major: 0, minor: 1, micro: 1, ...
# [C++] include/tvm/ffi/c_api.h: Macro version mismatch: found 0.1.0, expected 0.1.1.
```
