# Introduce setuptools_scm for git-based versioning across Python, C++, and Rust
## TL;DR
- Replaces the manually maintained `version = "0.1.0"` in `pyproject.toml` and `__version__ = "0.1.0"` in `__init__.py` with `setuptools_scm`, which derives the version from git tags automatically.
- Rewrites `tests/lint/check_version.py` from a simple pyproject-vs-init consistency check into a multi-language version linter that validates C++ macros and Rust crate versions against the setuptools_scm-derived canonical version.
- Updates all CI workflows to use `fetch-depth: 0` and `fetch-tags: true` so setuptools_scm can compute the version from git history, and bumps C++ patch version to 0.1.1.

## Key Exports
**Functions** (in `tests/lint/check_version.py`):
- `_version_info() -> dict[str, Any]` -- returns a dict of parsed version fields (major, minor, micro, pre, dev, local, etc.) using `setuptools_scm.get_version()` + `packaging.version.Version`.
- `_check_cpp(version_info: dict) -> list[str]` -- scans `include/tvm/ffi/c_api.h` for `TVM_FFI_VERSION_{MAJOR,MINOR,PATCH}` macros and validates they match the canonical version.
- `_check_rust(version_info: dict) -> list[str]` -- reads `rust/tvm-ffi*/Cargo.toml` and validates crate versions match the canonical base version (with optional semver pre-release mapping).
- `_map_pep440_pre_to_semver(pre: tuple[str, int] | None) -> str | None` -- converts PEP 440 pre-release tags (a/b/rc) to semver equivalents (alpha/beta/rc).
- `main() -> int` -- CLI entry point with `--cpp` and `--rust` flags.

**Constants** (in `tests/lint/check_version.py`):
- `RE_MAJOR`, `RE_MINOR`, `RE_PATCH` -- compiled regexes for scanning C++ version macros.

**Python version export** (in `python/tvm_ffi/__init__.py`):
- `__version__` and `__version_tuple__` -- now imported from auto-generated `_version.py` with a fallback to `"0.0.0.dev0"`.

**Build metadata** (in `pyproject.toml`):
- `[tool.setuptools_scm]` -- `version_file = "python/tvm_ffi/_version.py"`, `write_to = "python/tvm_ffi/_version.py"`.
- `[tool.scikit-build] metadata.version.provider` -- set to `"scikit_build_core.metadata.setuptools_scm"`.
- `[project] dynamic = ["version"]` -- replaces the hardcoded `version = "0.1.0"`.

## Impact
- API: `tvm_ffi.__version__` is now dynamically derived from git tags rather than hardcoded. The value changes from a static `"0.1.0"` to a PEP 440 version like `"0.1.1.dev9+g43f0820f6.d20251021"`. Callers that equality-check against `"0.1.0"` will break.
- ABI: None. The C++ macro `TVM_FFI_VERSION_PATCH` is bumped from 0 to 1, but this is a data value change, not a layout change.
- Behavioral: The pre-commit `check-version` hook is renamed to `check-version-consistency` and now requires `setuptools-scm`, `packaging`, and `tomli` as additional dependencies. It no longer auto-fixes `__init__.py` -- it only reports mismatches. The `--rust` flag is not yet enabled in pre-commit (noted as TODO).
- Flags/config: CI workflows now use `fetch-depth: 0` + `fetch-tags: true` everywhere (required for setuptools_scm). The `actions/checkout` is bumped from v4 to v5.
- Data formats/schemas: `python/tvm_ffi/_version.py` is a new auto-generated file (gitignored) containing `__version__` and `__version_tuple__`.

## Design Elements
Design elements this commit consumes:
- Python packaging architecture (`.knowledge/designs/0015-python-packaging.md`) -- the pyproject.toml structure, build-system requires, scikit-build-core integration.
- C ABI version macros (`.knowledge/designs/c-abi.md`) -- `TVM_FFI_VERSION_{MAJOR,MINOR,PATCH}` in `include/tvm/ffi/c_api.h`.
- Rust crate layout (`rust/tvm-ffi*/Cargo.toml`) -- crate version fields.

Design elements this commit produces:
- **Canonical version source**: The single source of truth for the project version is now git tags, accessed via `setuptools_scm.get_version()`. All other version locations (C++ macros, Rust Cargo.toml, Python `_version.py`) are derived or validated against this.
- **Multi-language version linter**: `tests/lint/check_version.py` is now a reusable tool that validates version consistency across Python/C++/Rust boundaries using `--cpp` and `--rust` flags.
- **Auto-generated `_version.py`**: A new build artifact at `python/tvm_ffi/_version.py` that is written by setuptools_scm and imported at runtime.

## Usage Examples
Running the version linter standalone:
```bash
# Check C++ macro versions match the git-derived version
python tests/lint/check_version.py --cpp

# Check both C++ and Rust versions
python tests/lint/check_version.py --cpp --rust

# Output example:
# Project version: 0.1.1.dev9+g43f0820f6.d20251021
#   major: 0
#   minor: 1
#   micro: 1
#   ...
```

How the Python version is resolved at runtime:
```python
import tvm_ffi
print(tvm_ffi.__version__)        # "0.1.1.dev9+g43f0820f6" (from _version.py)
print(tvm_ffi.__version_tuple__)  # (0, 1, 1, "dev9", "g43f0820f6")
```
