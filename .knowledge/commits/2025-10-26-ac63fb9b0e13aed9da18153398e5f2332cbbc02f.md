# Introduce setuptools_scm for git-based versioning across Python, C++, and Rust

## TL;DR
- Replaces static `version = "0.1.0"` in `pyproject.toml` with `setuptools_scm` dynamic versioning derived from git tags.
- Rewrites `tests/lint/check_version.py` from a pyproject-vs-init sync tool into a cross-language version consistency linter that checks C++ macros and Rust `Cargo.toml` against the `setuptools_scm`-derived canonical version.
- Updates all CI workflows to `fetch-depth: 0` + `fetch-tags: true` so `setuptools_scm` can compute versions from git history.

## Key Exports
N/A -- infrastructure.

## Impact
- API: none -- `tvm_ffi.__version__` is still exported, now sourced from auto-generated `_version.py` instead of a hardcoded string. Falls back to `"0.0.0.dev0"` if `_version.py` is absent.
- Behavioral: Python package version is now derived from git tags at build time rather than a static string. Development installs get rich version strings like `0.1.1.dev9+g43f0820f6.d20251021`.
- Flags/config: `pyproject.toml` gains `dynamic = ["version"]`, `tool.setuptools_scm.version_file`, `tool.scikit-build.metadata.version.provider`. Build requires gain `setuptools-scm`, lose `cmake`, `ninja` (moved elsewhere or optional).
- Data formats/schemas: `python/tvm_ffi/_version.py` is now auto-generated (gitignored) containing `__version__` and `__version_tuple__`.

## Design Elements
Design elements this commit consumes:
- C ABI version macros (`TVM_FFI_VERSION_MAJOR/MINOR/PATCH` in `include/tvm/ffi/c_api.h`) -- bumped patch from 0 to 1 to match the `setuptools_scm`-derived `0.1.1` base version. See [0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md).
- Python packaging infrastructure (`pyproject.toml`, scikit-build-core). See [0013-ffi-packaging-and-distribution](../design-records/0013-ffi-packaging-and-distribution.md).
- Rust crate version fields (`rust/tvm-ffi*/Cargo.toml`). See [0017-ffi-rust-bindings](../design-records/0017-ffi-rust-bindings.md).

Design elements this commit produces:
- None -- the versioning scheme is build infrastructure, not a design element.

## Usage Examples
CLI usage of the new version linter (from commit message):

```bash
# Check C++ and Rust version consistency against git-derived canonical version
python tests/lint/check_version.py --cpp --rust
# Output:
# Project version: 0.1.1.dev9+g43f0820f6.d20251021
#   major: 0, minor: 1, micro: 1
# [C++] include/tvm/ffi/c_api.h: Macro version mismatch: found 0.1.0, expected 0.1.1.
# [Rust] rust/tvm-ffi/Cargo.toml: version not compatible...
```

Python version import (new fallback pattern in `__init__.py`):

```python
try:
    from ._version import __version__, __version_tuple__
except ImportError:
    __version__ = "0.0.0.dev0"
    __version_tuple__ = (0, 0, 0, "dev0", "7d34eb8ab.d20250913")
```
