# Introduce setuptools_scm for git-based Python/C++/Rust version management
## TL;DR
- Replaces the hardcoded `version = "0.1.0"` in `pyproject.toml` with `dynamic = ["version"]` driven by `setuptools_scm`, which derives the version from git tags at build time.
- Rewrites `check_version.py` from a simple pyproject-vs-init sync checker into a cross-language version consistency linter that validates C++ macros and Rust `Cargo.toml` versions against the `setuptools_scm`-derived canonical version.
- Updates all CI workflows to use `actions/checkout@v5` with `fetch-depth: 0` and `fetch-tags: true` so that `setuptools_scm` can determine the version from the full git history.

## Key Exports
```python
# python/tvm_ffi/__init__.py — version is now lazy-loaded from _version.py
# generated by setuptools_scm at build time
try:
    from ._version import __version__, __version_tuple__
except ImportError:
    __version__ = "0.0.0.dev0"
    __version_tuple__ = (0, 0, 0, "dev0", "7d34eb8ab.d20250913")

# Invariant: __version__ is always a PEP 440 string;
#            __version_tuple__ is a structured tuple for programmatic access.
# Interacts with: setuptools_scm (build-time), pyproject.toml [tool.setuptools_scm]

# tests/lint/check_version.py — standalone linter
# Usage: python tests/lint/check_version.py [--cpp] [--rust]
def _version_info() -> dict:
    """Return canonical version info from setuptools_scm + packaging.version."""
    ...

def _check_cpp(version_info: dict) -> list[str]:
    """Validate TVM_FFI_VERSION_{MAJOR,MINOR,PATCH} macros in c_api.h."""
    ...

def _check_rust(version_info: dict) -> list[str]:
    """Validate Cargo.toml versions across all Rust crates."""
    ...

# pyproject.toml changes:
# [project] version = "0.1.0"  ->  dynamic = ["version"]
# [build-system] requires now includes "setuptools-scm"
# [tool.scikit-build] metadata.version.provider = "scikit_build_core.metadata.setuptools_scm"
# [tool.setuptools_scm] version_file = "python/tvm_ffi/_version.py"

# include/tvm/ffi/c_api.h — version bump
# TVM_FFI_VERSION_PATCH: 0 -> 1  (now 0.1.1)
```

## Impact
- API: `tvm_ffi.__version__` is no longer hardcoded; it is dynamically derived from git tags. `__version_tuple__` is a new public export. The version string format changes from a simple `"0.1.0"` to PEP 440 dev versions like `"0.1.1.dev9+g43f0820f6"` during development.
- Behavioral: CI checkout steps now fetch full history + tags (`fetch-depth: 0`, `fetch-tags: true`) to support `setuptools_scm` version derivation.
- Flags/config: `pyproject.toml` version field is now `dynamic`, controlled by `[tool.setuptools_scm]`. The pre-commit hook `check-version` is renamed to `check-version-consistency` with additional dependencies (`setuptools-scm`, `packaging`, `tomli`).
- Data formats/schemas: `python/tvm_ffi/_version.py` is a new auto-generated file (gitignored) containing `__version__` and `__version_tuple__`.

## Usage Examples
```bash
# Check version consistency across C++ and Rust:
python tests/lint/check_version.py --cpp --rust
# Output:
# Project version: 0.1.1.dev9+g43f0820f6.d20251021
#   major: 0, minor: 1, micro: 1
#   ...
# [C++] include/tvm/ffi/c_api.h: Macro version mismatch: found 0.1.0, expected 0.1.1.

# In Python:
import tvm_ffi
print(tvm_ffi.__version__)         # e.g., "0.1.1.dev9+g43f0820f6"
print(tvm_ffi.__version_tuple__)   # e.g., (0, 1, 1, "dev9", "g43f0820f6")
```
