# Temporary workaround: revert Array::operator[] return type from T to const T for flashinfer compatibility

## TL;DR

- `Array<T>::operator[](int64_t i) const` return type changed from `T` back to `const T` as a temporary patch for release 0.1.19.
- The 0.1.19 patch had changed `const T` → `T` (more correct semantically), but flashinfer relies on an implicit conversion rule that requires `const T` behavior.
- Marked `[TEMP]` — will be relanded once a matching flashinfer fix is released.

## Key Exports

None

## Impact

- API: `Array<T>::operator[]` return type is `const T` (was `T` after the 0.1.19 patch). Callers that were relying on the non-const `T` return for mutation or implicit conversion will see `const T` again.
- Behavioral: No behavioral change for read-only indexing. Restores flashinfer's implicit-conversion codepath that depends on `const T`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

## Usage Examples

Before (0.1.19 patch, correct but breaks flashinfer):
```cpp
// Array<T>::operator[] returning T (non-const)
T operator[](int64_t i) const { ... }
```

After (this temp fix, reverts to const T):
```cpp
// Array<T>::operator[] returning const T
const T operator[](int64_t i) const { ... }
```
