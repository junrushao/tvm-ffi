# Add DLPack FFI overhead benchmark script for AutoDLPack feature

## TL;DR
- Adds `scripts/benchmark_dlpack.py` (345 LOC), a microbenchmark measuring Python FFI call overhead for DLPack-based tensor argument passing.
- Benchmarks compare `tvm.ffi.nop` with various DLPack import paths (torch, numpy, cupy) against baseline `torch.add`/`numpy.add`, plus `__dlpack__` protocol overhead in isolation.
- **Diff-message misalignment**: the commit message describes the full "AutoDLPack" feature (automatic DLPack import when FFI functions take Tensor arguments), but the actual diff only adds this benchmark script. The feature implementation was landed separately.

## Key Exports

**Script**: `scripts/benchmark_dlpack.py` -- standalone benchmark, not a library export.

Key benchmark functions (not API, but document the intended AutoDLPack usage pattern):

| Function | What it measures |
|----------|-----------------|
| `baseline_torch_add(repeat)` | `torch.add(x, y, out=z)` on CPU and CUDA |
| `baseline_numpy_add(repeat)` | `numpy.add(x, y, out=z)` |
| `baseline_cupy_add(repeat)` | `cupy.add(x, y, out=z)` |
| `tvm_ffi_nop(repeat)` | `tvm_ffi.get_global_func("testing.nop")` with pre-converted NDArray args |
| `bench_ffi_nop_from_dlpack(name, x, y, z, repeat)` | `tvm_ffi.from_dlpack(x)` conversion + nop call per iteration |
| `bench_tvm_ffi_nop_autodlpack(name, x, y, z, repeat)` | **AutoDLPack path**: passes torch/numpy tensors directly to `nop(x, y, z)` without explicit conversion |
| `bench_to_dlpack(x, name, repeat)` | `x.__dlpack__()` protocol overhead |
| `bench_to_dlpack_versioned(x, name, repeat)` | `x.__dlpack__(max_version=(1,1))` overhead |

## Design Elements
Design elements this commit consumes:
- **Global function registry** (`function-system.md`) -- uses `tvm_ffi.get_global_func("testing.nop")` to obtain a registered C++ no-op function.
- **DLPack interop** (`containers.md`, `c-abi.md`) -- uses `tvm_ffi.from_dlpack()` to convert external tensors to TVM NDArray.
- **AutoDLPack** (undocumented) -- the benchmark exercises the auto-conversion path where torch/numpy tensors are passed directly to FFI functions without explicit `from_dlpack` calls. This is the feature described in the commit message but implemented elsewhere.
- **DLPack protocol** -- exercises both legacy `torch.utils.dlpack.to_dlpack` and modern `__dlpack__`/`__dlpack__(max_version=...)` APIs from external frameworks.

## Usage Examples

AutoDLPack usage pattern (the key pattern this benchmark validates):

```python
import torch
from tvm import ffi as tvm_ffi

# Traditional path: explicit DLPack conversion
nop = tvm_ffi.get_global_func("testing.nop")
x = torch.arange(1)
tx = tvm_ffi.from_dlpack(x)  # explicit conversion
nop(tx, tx, tx)

# AutoDLPack path: pass torch tensors directly
nop(x, x, x)  # tvm_ffi auto-imports via DLPack protocol
```
