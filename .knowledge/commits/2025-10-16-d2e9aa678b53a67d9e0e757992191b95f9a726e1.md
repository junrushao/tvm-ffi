# Switch to manylinux2014 wheels and restore Python 3.8 compatibility
## TL;DR
- Configures cibuildwheel to produce `manylinux2014` wheels instead of the default `manylinux_2_28`, enabling installation on older Linux systems with older glibc.
- Restores Python 3.8 compatibility across the Python codebase by switching `collections.abc` imports to version-gated paths and replacing PEP 585 generics (`type[X]`) with `typing.Type[X]`.
- Lowers CI test matrix Python versions to 3.8 (aarch64) and 3.9 (Windows), and guards a newer torch dtype attribute (`float8_e8m0fnu`) behind `hasattr`.

## Key Exports
None -- no new public API surface. This commit is purely about backward compatibility.

## Impact
- API: none
- ABI: none
- Behavioral: Wheels now carry the `manylinux2014` platform tag, extending support to systems with glibc 2.17+. Python 3.8 is again a supported runtime.
- Flags/config: `manylinux-x86_64-image` and `manylinux-aarch64-image` set to `"manylinux2014"` in `pyproject.toml`. `tool.mypy.python_version` changed from `"3.8"` to `"3.9"`.
- Data formats/schemas: none

## Usage Examples
Version-gated import pattern introduced in `python/tvm_ffi/container.py` for Python 3.8 compatibility:
```python
import sys

if sys.version_info >= (3, 9):
    from collections.abc import Sequence, Mapping, Iterator, Iterable
    from collections.abc import ItemsView as ItemsViewBase
    from collections.abc import KeysView as KeysViewBase
    from collections.abc import ValuesView as ValuesViewBase
else:  # Python 3.8
    from typing import Sequence, Mapping, Iterator, Iterable
    from typing import ItemsView as ItemsViewBase
    from typing import KeysView as KeysViewBase
    from typing import ValuesView as ValuesViewBase
```

Guard for newer torch attributes in `tests/python/test_dtype.py`:
```python
if hasattr(torch, "float8_e8m0fnu"):
    _check_dtype(torch.float8_e8m0fnu, 14, 8, 1)
```
