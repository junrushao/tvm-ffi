# Switch wheel distribution to manylinux2014 and fix Python 3.8 compatibility

## TL;DR

- `pyproject.toml` switches `cibuildwheel` images from the default manylinux2_28 to `manylinux2014` for x86_64 and aarch64, broadening binary compatibility for systems with older glibc.
- CI matrix updates the aarch64 test runner from Python 3.10 → 3.8 and Windows from 3.12 → 3.9, and mypy baseline raises from 3.8 → 3.9.
- `container.py`, `dataclasses/_utils.py`, and `dataclasses/c_class.py` fix Python 3.8 runtime compat by using `typing.Type[T]` (subscriptable on 3.8) instead of `type[T]` (PEP 585, Python 3.9+), and branching `collections.abc` imports on `sys.version_info >= (3, 9)`.

## Key Exports

None — no new public API surface introduced; this commit only adjusts build configuration and adds compatibility guards.

## Impact

- API: None — public signatures unchanged; `# noqa: UP006` suppresses ruff's PEP 585 upgrade hints so `typing.Type` is retained on purpose.
- Behavioral: `get_type_hints(type_cls, include_extras=True)` is guarded to only call with `include_extras` on Python 3.9+; on 3.8 falls back to bare `get_type_hints(type_cls)`. This means `Annotated[T, ...]` extras are silently dropped on 3.8.
- Flags/config: `[tool.cibuildwheel]` now sets `manylinux-x86_64-image = "manylinux2014"` and `manylinux-aarch64-image = "manylinux2014"`; `[tool.mypy] python_version` raised from `"3.8"` → `"3.9"`.
- Data formats/schemas: None.

## Usage Examples

Before/after for the Python 3.8 compat guard in `container.py`:

```python
# Before (broke on Python 3.8 — collections.abc generics not subscriptable until 3.9)
from collections.abc import ItemsView as ItemsViewBase
from collections.abc import Iterable, Iterator, Mapping, Sequence
from collections.abc import KeysView as KeysViewBase
from collections.abc import ValuesView as ValuesViewBase

# After
import sys
if sys.version_info >= (3, 9):
    from collections.abc import ItemsView as ItemsViewBase
    from collections.abc import Iterable, Iterator, Mapping, Sequence
    from collections.abc import KeysView as KeysViewBase
    from collections.abc import ValuesView as ValuesViewBase
else:  # Python 3.8
    from typing import ItemsView as ItemsViewBase
    from typing import Iterable, Iterator, Mapping, Sequence
    from typing import KeysView as KeysViewBase
    from typing import ValuesView as ValuesViewBase
```

Before/after for `type[T]` → `Type[T]` in `dataclasses/_utils.py`:

```python
# Before (PEP 585 subscript syntax, Python 3.9+ only)
def type_info_to_cls(
    type_info: TypeInfo,
    cls: type[_InputClsType],
    methods: dict[str, Callable[..., Any] | None],
) -> type[_InputClsType]: ...

# After (typing.Type subscript, backport-safe on 3.8)
from typing import Type
def type_info_to_cls(
    type_info: TypeInfo,
    cls: Type[_InputClsType],           # noqa: UP006
    methods: dict[str, Callable[..., Any] | None],
) -> Type[_InputClsType]: ...           # noqa: UP006
```
