# Switch to manylinux2014 wheels and fix Python 3.8 compatibility issues
## TL;DR
- Configures cibuildwheel to produce `manylinux2014` wheels (instead of default `manylinux2_28`), expanding glibc compatibility to older Linux systems.
- Fixes Python 3.8 compatibility in `container.py` (correct `collections.abc` vs `typing` branching), `c_class.py` (`get_type_hints` without `include_extras` on 3.8), and `_utils.py` (`Type[]` instead of `type[]` for 3.8).
- Updates CI test matrix to exercise Python 3.8 (aarch64) and 3.9 (Windows); reverts mypy target from 3.8 back to 3.9.

## Design Elements
Design elements this commit consumes:
- **Python 3.8 `typing` vs `collections.abc` compatibility** — `Mapping`, `Sequence`, `KeysView`, `ValuesView`, `ItemsView` must come from `typing` on 3.8 (not `collections.abc` which is not subscriptable there). The branching pattern in `container.py` is the canonical workaround.
- **`get_type_hints(cls, include_extras=True)`** — the `include_extras` kwarg was added in Python 3.11 via PEP 655 but backported to 3.9 by `typing_extensions`. On 3.8, calling with `include_extras` on stdlib `get_type_hints` may fail; this commit guards it with a version check.
