# Add documentation for tvm_ffi.cpp.load_inline and include tensor.h by default
## TL;DR
- Adds an "Inline Module" section to the Python guide (`docs/guides/python_guide.md`) with a full end-to-end example showing C++ inline compilation and invocation from Python.
- Adds Sphinx API reference pages for `tvm_ffi.cpp` and `load_inline` (`docs/reference/python/cpp/index.rst`, `docs/reference/python/index.rst`).
- Includes `<tvm/ffi/container/tensor.h>` by default in `_decorate_with_tvm_ffi`, enabling inline modules to use `tvm::ffi::Tensor` out of the box.
- Updates all examples and tests to use `tvm::ffi::Tensor` instead of raw `DLTensor*` in inline module function signatures.
- Improves the `load_inline` docstring formatting (RST backtick quoting, parameter descriptions, adds an inline `Example` section).

## Key Exports
**Functions** (changed default behavior):
- `_decorate_with_tvm_ffi(source, functions) -> str` (internal): Now prepends `#include <tvm/ffi/container/tensor.h>` to the auto-generated header block, making `tvm::ffi::Tensor` available to all inline modules without explicit user includes.

No new public API types, macros, or constants are introduced.

## Impact
- API: None (public `load_inline` signature unchanged).
- Behavioral: Inline modules now implicitly include `<tvm/ffi/container/tensor.h>`. This enables users to write `tvm::ffi::Tensor x` instead of `DLTensor* x` in inline C++/CUDA source. Existing modules using `DLTensor*` remain valid since `tensor.h` does not conflict with existing includes.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): `load_inline` returns a `Module` object; examples call `mod.add_one_cpu(x, y)` using the module function dispatch.
- **Inline module compilation** ([0014-python-package.md](../designs/0014-python-package.md)): The `_decorate_with_tvm_ffi` function generates the boilerplate (includes + `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macros) that make inline modules work.
- **Tensor container** (`tvm::ffi::Tensor`): The commit promotes `Tensor` as the idiomatic function parameter type for inline modules, replacing raw `DLTensor*`.

Design elements this commit produces:
- **Documentation artifact**: New "Inline Module" section in the Python guide establishing `tvm::ffi::Tensor` as the recommended parameter type for inline module functions.
- **Default tensor.h include**: The implicit inclusion of `tensor.h` in `_decorate_with_tvm_ffi` establishes a convention that inline modules have access to the full Tensor API by default.

## Usage Examples
End-to-end inline module with `tvm::ffi::Tensor` (from the new guide section):
```python
import torch
from tvm_ffi import Module
import tvm_ffi.cpp

cpp_source = '''
     void add_one_cpu(tvm::ffi::Tensor x, tvm::ffi::Tensor y) {
       TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
       DLDataType f32_dtype{kDLFloat, 32, 1};
       TVM_FFI_ICHECK(x->dtype == f32_dtype) << "x must be a float tensor";
       for (int i = 0; i < x->shape[0]; ++i) {
         static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
       }
     }
'''

mod: Module = tvm_ffi.cpp.load_inline(
    name='hello', cpp_sources=cpp_source, functions='add_one_cpu'
)
x = torch.tensor([1, 2, 3, 4, 5], dtype=torch.float32)
y = torch.empty_like(x)
mod.add_one_cpu(x, y)
torch.testing.assert_close(x + 1, y)
```
