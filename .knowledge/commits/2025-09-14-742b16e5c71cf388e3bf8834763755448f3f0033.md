# Add documentation for tvm_ffi.cpp.load_inline and migrate examples to tvm::ffi::Tensor
## TL;DR
- Added Sphinx API reference pages for `tvm_ffi.cpp` module and `load_inline` function, plus an inline-module guide section in `docs/guides/python_guide.md`.
- Rewrote `load_inline` docstring with RST formatting, usage example, and corrected parameter descriptions.
- Added `#include <tvm/ffi/container/tensor.h>` to the auto-injected header set in `_decorate_with_tvm_ffi`, and migrated all examples/tests from raw `DLTensor*` to `tvm::ffi::Tensor`.

## Key Exports

The functional code change is the addition of `tensor.h` to the default header set injected by `_decorate_with_tvm_ffi`:

```python
def _decorate_with_tvm_ffi(source: str, functions: Mapping[str, str]) -> str:
    """Prepend standard FFI headers and append TVM_FFI_DLL_EXPORT_TYPED_FUNC calls."""
    # Now includes: tvm/ffi/container/tensor.h (NEW), tvm/ffi/dtype.h, tvm/ffi/error.h,
    #               tvm/ffi/extra/c_env_api.h, tvm/ffi/function.h
    # Interacts with: TVM_FFI_DLL_EXPORT_TYPED_FUNC macro, load_inline() caller
    # Invariant: tensor.h is now always available in inline-compiled code,
    #   so user code can use tvm::ffi::Tensor instead of raw DLTensor*
    ...
```

## Impact
- API: None -- `load_inline` signature unchanged; only docstring and auto-included headers changed.
- Behavioral: Inline-compiled code now has `tvm/ffi/container/tensor.h` available by default, enabling `tvm::ffi::Tensor` usage without explicit `#include`. Existing code using `DLTensor*` still compiles.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
The new guide section and docstring both demonstrate the same canonical pattern:

```python
import torch
from tvm_ffi import Module
import tvm_ffi.cpp

mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(tvm::ffi::Tensor x, tvm::ffi::Tensor y) {
            TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
            for (int i = 0; i < x->shape[0]; ++i)
                static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions="add_one_cpu",
)
x = torch.tensor([1, 2, 3, 4, 5], dtype=torch.float32)
y = torch.empty_like(x)
mod.add_one_cpu(x, y)
torch.testing.assert_close(x + 1, y)
```

Note: the migration from `DLTensor*` to `tvm::ffi::Tensor` in examples/tests is a convention shift. Both work at the C++ level, but `tvm::ffi::Tensor` is the higher-level ref-counted wrapper recommended going forward.
