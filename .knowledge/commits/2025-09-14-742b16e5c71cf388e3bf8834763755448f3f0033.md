# Add documentation for tvm_ffi.cpp.load_inline and migrate inline examples to ffi::Tensor

## TL;DR
- Adds a new "Inline Module" section to `docs/guides/python_guide.md` with a complete example of JIT-compiling C++ from Python via `tvm_ffi.cpp.load_inline`.
- Adds Sphinx API reference pages for `tvm_ffi.cpp` (`docs/reference/python/cpp/index.rst`) and links them from the main Python reference index under a new "Utility" section.
- Improves the docstring of `tvm_ffi.cpp.load_inline` with corrected RST formatting (double backticks for parameter names, proper bullet list formatting) and adds a full inline usage example in the docstring.
- Adds `#include <tvm/ffi/container/tensor.h>` to the auto-prepended headers in `_decorate_with_tvm_ffi`, so user code can use `tvm::ffi::Tensor` without manual includes.
- Migrates all inline C++/CUDA function signatures in examples and tests from `DLTensor*` to `tvm::ffi::Tensor`, following the convention established in commit 6fa40b5.

## Key Exports

**Auto-included headers (in `_decorate_with_tvm_ffi`):**

- `#include <tvm/ffi/container/tensor.h>` -- New auto-included header. Previously only `dtype.h`, `error.h`, `extra/c_env_api.h`, and `function.h` were included. User code in `load_inline` can now use `tvm::ffi::Tensor` directly.

## Impact
- API: Non-breaking. The `load_inline` function signature is unchanged. The added `#include` makes `tvm::ffi::Tensor` available automatically in user code, which is additive.
- ABI: None.
- Behavioral: Inline modules now automatically include `container/tensor.h`, enabling `tvm::ffi::Tensor` type in user function signatures without explicit includes. Existing code using `DLTensor*` continues to work (it was already available via `function.h`).
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

The guide example and docstring example both demonstrate the same pattern:

```python
import torch
from tvm_ffi import Module
import tvm_ffi.cpp

cpp_source = '''
     void add_one_cpu(tvm::ffi::Tensor x, tvm::ffi::Tensor y) {
       TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
       DLDataType f32_dtype{kDLFloat, 32, 1};
       TVM_FFI_ICHECK(x->dtype == f32_dtype) << "x must be a float tensor";
       TVM_FFI_ICHECK(y->ndim == 1) << "y must be a 1D tensor";
       TVM_FFI_ICHECK(y->dtype == f32_dtype) << "y must be a float tensor";
       TVM_FFI_ICHECK(x->shape[0] == y->shape[0]) << "x and y must have the same shape";
       for (int i = 0; i < x->shape[0]; ++i) {
         static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
       }
     }
'''

mod: Module = tvm_ffi.cpp.load_inline(
    name='hello', cpp_sources=cpp_source, functions='add_one_cpu'
)

x = torch.tensor([1, 2, 3, 4, 5], dtype=torch.float32)
y = torch.empty_like(x)
mod.add_one_cpu(x, y)
torch.testing.assert_close(x + 1, y)
```

Note the use of `tvm::ffi::Tensor` rather than the previous `DLTensor*` convention.
