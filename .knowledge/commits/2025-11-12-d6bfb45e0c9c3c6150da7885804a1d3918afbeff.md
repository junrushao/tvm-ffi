# Extend torch_c_dlpack_ext CI and build scripts to support macOS ARM64 wheel builds

## TL;DR
- Adds a `build_wheels_macos` job to `.github/workflows/torch_c_dlpack.yml` targeting macOS 14 (ARM64) across Python 3.9-3.14, and wires it into the `upload_pypi` dependency chain.
- Makes `addons/torch_c_dlpack_ext/build_aot_wheels.sh` OS-aware (Linux vs Darwin): skips CUDA builds on macOS, uses `delocate-wheel` instead of `auditwheel`, adjusts PyTorch install source (PyPI default on macOS vs explicit index URL on Linux), and applies platform-specific wheel tags (`macosx_11_0_arm64`).
- Removes the `darwin`/`dylib` extension check from `build_backend.py`, unifying prebuilt-lib detection to use `.so` on both Linux and macOS (macOS torch_c_dlpack builds produce `.so` files, not `.dylib`).

## Design Elements
Design elements this commit consumes:
- **torch_c_dlpack release pipeline** (`.github/workflows/torch_c_dlpack.yml`): Extends the four-stage workflow introduced in da570b0. The new `build_wheels_macos` job parallels the existing `build_wheels_linux` job but with macOS-specific runners and tooling. See `commits/2025-11-03-da570b0d8145bb31b6ae3de17a5505b9b101b5d9.md`.
- **build_aot_wheels.sh script** (`addons/torch_c_dlpack_ext/build_aot_wheels.sh`): The cross-platform AOT wheel build script. Previously Linux-only, now conditionally handles macOS via `uname -s` detection.
- **delocate** (macOS wheel repair tool): macOS equivalent of `auditwheel`. Fixes shared library references in wheels, excluding PyTorch's own dylibs (`libtorch.dylib`, `libtorch_cpu.dylib`, `libc10.dylib`, `libtorch_python.dylib`).

Design elements this commit produces:
- **macOS ARM64 wheel build path**: A new platform-specific branch in `build_aot_wheels.sh` that: (1) installs torch from default PyPI (no custom index URL), (2) skips CUDA library builds, (3) tags wheels with `macosx_11_0_arm64`, (4) repairs wheels with `delocate-wheel` instead of `auditwheel`. This establishes the pattern for future macOS addon builds.
