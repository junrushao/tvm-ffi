# Extend reflection to support type-level extra info (creator, doc, size) and a global MakeObjectFromPackedArgs factory

## TL;DR
- Introduces `ReflectionDefBase` as a shared helper base class; moves `FieldGetter`, `FieldSetter`, `GetMethod`, and `Apply*InfoTrait` helpers out of `ObjectDef` into it so they can be reused by other builders (e.g., a future `PyObjectDef`).
- Adds `TVMFFITypeExtraInfo` registration to `ObjectDef` constructor: every type now registers `total_size`, a default `creator` (factory via `make_object<T>()` if default-constructible), and an optional doc string.
- Adds `MakeObjectFromPackedArgs` global function registered as `"ffi.MakeObjectFromPackedArgs"`: given a type key and alternating key-value pairs, it creates an object via the registered `creator`, then populates fields from the type's inheritance chain in parent-to-child order using the reflection field table — enabling Python to construct C++ objects purely through reflection.

## Impact
- API: `ObjectDef<T>()` constructor signature changed — now accepts variadic `ExtraArgs` (e.g., doc string). Old zero-argument call still compiles, but now **also calls `TVMFFITypeRegisterExtraInfo` as a side effect** — callers who relied on `ObjectDef` touching only the field registry now also touch the extra-info registry.
- Behavioral: `def_rw` now has a compile-time `static_assert(Class::_type_mutable)` — classes without `_type_mutable = true` can no longer register writable fields (was silently permitted before).
- Flags/config: `Class::_type_mutable` static constexpr must be set to `true` on any class that uses `def_rw`. `TestObjectBase` in testing.cc sets it as an example.
- Data formats/schemas: `TVMFFITypeExtraInfo` struct (total_size, creator, doc) is now registered for every type via `ObjectDef`; previously only field/method info was registered.

## Design Elements

Design elements this commit consumes:
- `ObjectDef` (0006-reflection) — extended with `ReflectionDefBase` parent and `RegisterExtraInfo` step
- `TVMFFIFieldInfo` / `TVMFFIMethodInfo` (0001-c-abi, 0006-reflection) — helpers moved to base class
- `Function.FromTyped` (0004-function-system) — used by `GetMethod` wrappers in `ReflectionDefBase`
- `TVM_FFI_REGISTER_GLOBAL` (0004-function-system) — registers `"ffi.MakeObjectFromPackedArgs"`
- `TVMFFIGetTypeInfo` / `TVMFFITypeKeyToIndex` (0001-c-abi) — queried at runtime in `MakeObjectFromPackedArgs`
- `make_object<T>` (0002-object-system) — used in `ObjectCreatorDefault`

Design elements this commit produces:
- `ReflectionDefBase` — new shared base class for reflection builders; moves helper statics into a reusable location
- `TVMFFITypeExtraInfo` registration protocol — `ObjectDef` now registers `total_size`, `creator`, and `doc` for every type it is instantiated for
- `MakeObjectFromPackedArgs` global function — new cross-layer factory callable from any language via the global function registry
- `String::compare(TVMFFIByteArray)` overload — minor utility addition enabling byte-array key lookup without heap allocation

## Usage Examples

**Registering a mutable type with extra info (C++):**
```cpp
class TestObjectBase : public Object {
 public:
  int64_t v_i64;
  String v_str;
  static constexpr bool _type_mutable = true;
  static constexpr const char* _type_key = "testing.TestObjectBase";
  TVM_FFI_DECLARE_BASE_OBJECT_INFO(TestObjectBase, Object);
};

TVM_FFI_STATIC_INIT_BLOCK({
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<TestObjectBase>()
      .def_rw("v_i64", &TestObjectBase::v_i64, refl::DefaultValue(10), "i64 field")
      .def_rw("v_str", &TestObjectBase::v_str, refl::DefaultValue("hello"));
});
```

**Constructing a C++ object from Python (cross-layer trace):**
```python
# Python side — all through the FFI global registry
make_obj = get_global_func("ffi.MakeObjectFromPackedArgs")
obj = make_obj("testing.TestObjectBase", "v_i64", 42, "v_str", "world")
# C++ side: MakeObjectFromPackedArgs resolves type_key → type_index,
# calls extra_info->creator() → ObjectPtr<TestObjectBase>,
# then calls field.setter for each provided key-value pair.
```
