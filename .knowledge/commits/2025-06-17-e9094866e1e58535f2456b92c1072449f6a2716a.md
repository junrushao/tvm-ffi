# Introduce FFI reflection support in Python: ReflectionDefBase, ObjectCreator, MakeObjectFromPackedArgs
## TL;DR
- Refactors `ObjectDef` to extract shared helper methods (`FieldGetter`, `FieldSetter`, `GetMethod`, `ApplyFieldInfoTrait`, `ApplyMethodInfoTrait`) into a new `ReflectionDefBase` base class, enabling reuse by future reflection definition classes.
- Adds `ObjectCreator` support: `ObjectDef` constructor now calls `RegisterExtraInfo`, which registers a `TVMFFITypeExtraInfo` containing a default-constructible object creator (`ObjectCreatorDefault<T>`) and the type's `sizeof`. This enables reflection-based object instantiation from Python.
- Introduces `MakeObjectFromPackedArgs`, a new global function (`ffi.MakeObjectFromPackedArgs`) that creates objects by type key, then populates fields from packed keyword arguments using the reflection field registry, walking the ancestor chain from parent to child.

## Impact
- API: Adds the `ffi.MakeObjectFromPackedArgs` global function, callable from Python via `_ffi_api.MakeObjectFromPackedArgs(type_key, field1, val1, field2, val2, ...)`. This is the first generic object factory in the FFI -- previously objects could only be created via `make_object<T>()` in C++ or per-type constructors.
- API: `ObjectDef` constructor now accepts variadic `ExtraArgs` (forwarded to `RegisterExtraInfo`), changing from a zero-arg constructor. Existing callers using `ObjectDef<T>()` with no arguments remain valid.
- API: `def_rw` now enforces `static_assert(Class::_type_mutable, ...)` at compile time, requiring classes to explicitly opt into mutable fields. This is a breaking change for any class that used `def_rw` without declaring `_type_mutable = true`.
- API: `String::compare(const TVMFFIByteArray&)` added as a new overload for comparing against raw byte arrays.
- Flags/config: none
- Data formats/schemas: `TVMFFITypeExtraInfo` (with `creator`, `total_size`, `doc` fields) is now populated for every `ObjectDef`-registered type. Previously this metadata was not registered.

## Design Elements
Design elements this commit consumes:
- **Reflection system** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): The commit builds directly on the existing `ObjectDef`/`ReflectionDef` field registration, `TVMFFIFieldInfo` byte-offset scheme, and `TVMFFITypeInfo` type metadata. `MakeObjectFromPackedArgs` reads `type_info->fields`, `type_info->num_fields`, and `type_info->type_acenstors` to walk the type hierarchy.
- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Uses `make_object<T>()` for default construction within `ObjectCreatorDefault<T>`, `ObjectPtr<Object>` for ownership, `ObjectUnsafe::MoveObjectPtrToTVMFFIObjectPtr` / `ObjectUnsafe::ObjectPtrFromOwned` for raw handle conversion. Relies on `type_acenstors` array and `type_depth` for ancestor traversal.
- **Function system** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): `TVM_FFI_REGISTER_GLOBAL("ffi.MakeObjectFromPackedArgs")` registers the factory function in the global function table. `Function::FromTyped` is used by `GetMethod` to wrap member function pointers.
- **Any/AnyView system** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): `MakeObjectFromPackedArgs` receives arguments as `PackedArgs` (array of `AnyView`), casts them via `args[i].cast<T>()`, and uses `field_info->setter` which takes `TVMFFIAny*` values.
- **Container system** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): Test objects (`TestObjectBase`, `TestObjectDerived`) use `Map<Any, Any>` and `Array<Any>` as reflected fields, exercising container-type fields in the reflection pipeline.

Design elements this commit produces:
- **`ReflectionDefBase` base class** (`include/tvm/ffi/reflection/reflection.h`): New base class that centralizes `FieldGetter<T>`, `FieldSetter<T>`, `ObjectCreatorDefault<T>`, `ApplyFieldInfoTrait`, `ApplyMethodInfoTrait`, `ApplyExtraInfoTrait`, and `GetMethod` template overloads. This is an internal design element enabling future reflection definition classes to reuse these helpers without inheriting from `ObjectDef<Class>`.
- **`ObjectCreatorDefault<T>` pattern**: A `TVMFFIObjectCreator`-compatible static function that calls `make_object<T>()` for default-constructible types. Conditionally registered via `if constexpr (std::is_default_constructible_v<Class>)`. This is the mechanism that enables reflection-based object creation from Python.
- **`RegisterExtraInfo` / `TVMFFITypeExtraInfo` registration**: New private method in `ObjectDef` that registers type-level metadata (`total_size`, `creator`, `doc`) via `TVMFFITypeRegisterExtraInfo`. This extends the `TypeTable` entry with information needed for generic object factories.
- **`MakeObjectFromPackedArgs` global function** (`src/ffi/object.cc`): Factory function that implements the packed-keyword-argument object creation protocol: `(type_key, field1, val1, field2, val2, ...) -> Object`. Walks ancestor types in parent-to-child order, sets fields via reflection setters, applies defaults for missing fields, and reports errors for missing required fields or unknown field names.
- **`_type_mutable` compile-time enforcement for `def_rw`**: The `static_assert(Class::_type_mutable, ...)` in `def_rw` codifies the previously informal convention that writable fields require explicit mutable declaration. This is a core invariant now enforced at compile time.

  These additions help future commit mining for any commits that modify the object creation pipeline, add new reflection definition classes, or change how Python constructs C++ objects.

### ADRs to write

- **`.knowledge/ADRs/0006-reflection-based-object-creation.md`**: Records the decision to use reflection metadata for generic object creation (rather than per-type `__init__` functions or code-generated constructors). Context: Python needs to create C++ objects by type key with keyword arguments. Alternatives: (1) register a per-type `__init__` function (manual, N types = N functions), (2) code-generate Python constructors from C++ headers (build complexity), (3) use reflection metadata at runtime (generic but requires default-constructible objects + field setters). Trade-off: the reflection approach requires `_type_mutable` and default constructibility, but eliminates per-type registration boilerplate.

### Design diagrams to draw

- **Mermaid: MakeObjectFromPackedArgs flow**. Should depict: Python caller -> `ffi.MakeObjectFromPackedArgs(type_key, k1, v1, k2, v2)` -> `TVMFFITypeKeyToIndex` -> `TVMFFIGetTypeInfo` -> check `extra_info->creator` -> `creator(&handle)` (default-constructs object) -> walk `type_acenstors[1..depth]` + self type -> for each ancestor: iterate `fields`, match by name, call `setter` or apply default -> return `ObjectRef`.
