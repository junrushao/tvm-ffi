# Introduce FFI reflection support for Python: object creators, mutable field guards, and packed-args construction
## TL;DR
- Introduces `ReflectionDefBase` base class extracting shared helpers (field getter/setter, method wrappers, object creator) from `ObjectDef`, enabling future reuse by other definition builders.
- Adds `TVMFFITypeExtraInfo` registration (creator function, total_size, doc) to `ObjectDef` constructor, enabling reflection-based object instantiation from Python.
- Registers `ffi.MakeObjectFromPackedArgs` global function that creates objects by type key + keyword field assignments, walking the ancestor chain to populate inherited fields.
- Adds `static_assert(Class::_type_mutable, ...)` guard on `def_rw` to enforce at compile time that only mutable classes can have writable fields.
- Replaces deprecated `std::aligned_storage` with a manual `alignas(T)` struct in `SimpleObjAllocator`.
- Adds `String::compare(const TVMFFIByteArray&)` overload for efficient name matching without constructing a `String`.

## Key Exports

**Classes**:
- `ReflectionDefBase` (new) -- Protected base class providing static helpers. Key members:
  - `FieldGetter<T>(void*, TVMFFIAny*) -> int` -- reads typed field into `TVMFFIAny`
  - `FieldSetter<T>(void*, const TVMFFIAny*) -> int` -- writes `TVMFFIAny` into typed field
  - `ObjectCreatorDefault<T>(TVMFFIObjectHandle*) -> int` -- default-constructs `T` via `make_object<T>()`
  - `ApplyFieldInfoTrait<T>`, `ApplyMethodInfoTrait<T>`, `ApplyExtraInfoTrait<T>` -- trait applicators
  - `GetMethod<Class>(name, func)` -- three overloads wrapping member-pointer / const-member-pointer / generic callable into `Function`

- `ObjectDef<Class>` (changed) -- Now inherits `ReflectionDefBase`. Constructor accepts variadic `ExtraArgs` forwarded to `RegisterExtraInfo`.
  - `RegisterExtraInfo(ExtraArgs...)` (new private) -- Populates `TVMFFITypeExtraInfo{total_size, creator, doc}` and calls `TVMFFITypeRegisterExtraInfo`. Auto-sets `creator = ObjectCreatorDefault<Class>` if `Class` is default-constructible.
  - `def_rw` (changed) -- Now includes `static_assert(Class::_type_mutable, "Only mutable classes are supported for writable fields")`.

**Functions**:
- `ffi.MakeObjectFromPackedArgs` (global, new) -- `(type_key: String, field1_name: String, field1_value: Any, ...) -> ObjectRef`. Creates an object via the type's registered `creator`, then walks ancestor types parent-to-child setting fields by name. Requires all non-default fields. Errors on unknown field names.

**Methods**:
- `String::compare(const TVMFFIByteArray&) -> int` (new) -- Compares `String` content against a raw `TVMFFIByteArray` using `Bytes::memncmp`.

**Structs** (changed, not new to this commit but newly populated):
- `TVMFFITypeExtraInfo` -- `{doc: TVMFFIByteArray, creator: TVMFFIObjectCreator, total_size: int64_t}`. Now registered by `ObjectDef` constructor.

**Test classes** (new, in `src/ffi/testing.cc`):
- `TestObjectBase` -- Mutable base with fields `v_i64`, `v_f64`, `v_str` and method `AddI64`.
- `TestObjectDerived` -- Extends `TestObjectBase` with `v_map`, `v_array`.

## Impact
- API: `ObjectDef` constructor signature changed to accept variadic extra args. `def_rw` now requires `Class::_type_mutable == true` at compile time. Existing code defining `def_rw` on immutable classes will fail to compile.
- ABI: None. `TVMFFITypeExtraInfo` struct and `TVMFFITypeRegisterExtraInfo` C API existed before; this commit populates them.
- Behavioral: `ObjectDef` construction now registers extra info (creator, total_size) as a side effect. `MakeObjectFromPackedArgs` provides a new object creation path.
- Flags/config: None.
- Data formats/schemas: None.

Design elements this commit produces:
- **ReflectionDefBase** -- New shared base class for reflection builders, factoring out getter/setter/creator/method-wrapper generation. Not yet documented in `.knowledge/designs/reflection.md`.
- **Object creator registration** -- `ObjectDef` now auto-registers `TVMFFITypeExtraInfo` including a default creator for default-constructible types. Enables reflection-based construction from any language binding.
- **MakeObjectFromPackedArgs protocol** -- Creates objects from `(type_key, field_name, value, ...)` tuples, walking the ancestor chain. This is the Python-facing factory for reflection-created objects.
- **Mutable field compile-time guard** -- `def_rw` enforces `Class::_type_mutable` via `static_assert`, making the mutability contract a compile-time invariant rather than a runtime convention.

## Usage Examples

Defining a reflectable mutable object with fields, defaults, and methods:
```cpp
class MyObj : public Object {
 public:
  int64_t x;
  String name;
  int64_t Add(int64_t other) const { return x + other; }

  static constexpr bool _type_mutable = true;
  static constexpr const char* _type_key = "my.MyObj";
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(MyObj, Object);
};

TVM_FFI_STATIC_INIT_BLOCK({
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<MyObj>()
      .def_rw("x", &MyObj::x, refl::DefaultValue(0))
      .def_rw("name", &MyObj::name, refl::DefaultValue("default"))
      .def("add", &MyObj::Add, "add method");
});
```

Creating an object from packed args (e.g., from Python via FFI):
```cpp
// Equivalent to Python: obj = MyObj(x=42, name="hello")
Function create = Function::GetGlobalRequired("ffi.MakeObjectFromPackedArgs");
ObjectRef obj = create("my.MyObj", "x", 42, "name", "hello");
```
