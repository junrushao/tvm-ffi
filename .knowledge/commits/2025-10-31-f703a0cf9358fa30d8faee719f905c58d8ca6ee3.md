# Add ahead-of-time build and standalone package for PyTorch DLPack C extension
## TL;DR
- Introduce new standalone addon package `addons/torch_c_dlpack_ext/` with a custom PEP 517 build backend that compiles the PyTorch DLPack extension ahead of time and ships prebuilt `.so`/`.dll`/`.dylib` in the wheel.
- Add `load_torch_c_dlpack_extension()` in `torch_c_dlpack_ext/core.py` that loads the prebuilt library, calls `TorchDLPackExchangeAPIPtr`, and patches `torch.Tensor.__c_dlpack_exchange_api__`.
- Update `python/tvm_ffi/_optional_torch_c_dlpack.py` to first try importing the prebuilt `torch_c_dlpack_ext` package before falling back to JIT compilation.

## Key Exports

**Functions**:
- `torch_c_dlpack_ext.core.load_torch_c_dlpack_extension() -> ctypes.CDLL | None` — loads the version-matched prebuilt `.so`, calls `TorchDLPackExchangeAPIPtr()` via ctypes, and sets `torch.Tensor.__c_dlpack_exchange_api__` to the returned pointer. Returns the loaded CDLL handle, or `None` if torch already has the attribute.

**Build Backend** (`addons/torch_c_dlpack_ext/build_backend.py`):
- `get_requires_for_build_wheel(config_settings) -> list[str]` — conditionally adds `apache-tvm-ffi>=0.1.1` if no prebuilt lib found.
- `build_wheel(wheel_directory, config_settings, metadata_directory) -> str` — compiles the torch C DLPack extension via `tvm_ffi.utils._build_optional_torch_c_dlpack` if not prebuilt and torch lacks `__c_dlpack_exchange_api__`.
- `_is_lib_prebuilt() -> bool` — checks if a platform-appropriate shared library exists in the package directory.

**Protocols**: The prebuilt library naming convention is `libtorch_c_dlpack_addon_torch{major}{minor}-{cpu|cuda}.{so|dll|dylib}`.

## Impact
- API: none — backward compatible, opt-in only via installing the `torch_c_dlpack_ext` addon package
- Behavioral: `tvm_ffi._optional_torch_c_dlpack.load_torch_c_dlpack_extension()` now tries importing the prebuilt package first, falling back to JIT build
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack exchange API** (`__c_dlpack_exchange_api__` attribute on `torch.Tensor`, `TorchDLPackExchangeAPIPtr` C symbol) — documented in `.knowledge/ADRs/0021-dlpack-exchange-api-struct.md` and `.knowledge/designs/0017-dlpack-interop.md`.
- **Python FFI call dispatch** — the fallback path in `_optional_torch_c_dlpack.py` is part of `.knowledge/designs/0015-python-ffi-call-dispatch.md`.
- **`tvm_ffi.utils._build_optional_torch_c_dlpack`** — the existing JIT build utility, invoked by the build backend when no prebuilt lib exists.

Design elements this commit produces:
- **Ahead-of-time torch DLPack addon package** (`torch_c_dlpack_ext`) — a new standalone pip-installable package under `addons/` with a custom PEP 517 build backend. This is a new distribution pattern for optional FFI extensions.
- **Prebuilt-first loading strategy** — `_optional_torch_c_dlpack.py` now has a three-tier loading order: (1) check if torch already has `__c_dlpack_exchange_api__`, (2) try prebuilt `torch_c_dlpack_ext`, (3) JIT compile.

## Usage Examples
Installing and using the ahead-of-time extension:
```bash
# Build and install the addon wheel
cd addons/torch_c_dlpack_ext
pip install .

# In Python — the extension is loaded automatically on import
import torch_c_dlpack_ext  # patches torch.Tensor.__c_dlpack_exchange_api__
import torch
assert hasattr(torch.Tensor, "__c_dlpack_exchange_api__")
```

From `tvm_ffi` side, the change is transparent — `load_torch_c_dlpack_extension()` automatically prefers the prebuilt package:
```python
# In tvm_ffi/_optional_torch_c_dlpack.py (simplified)
try:
    import torch_c_dlpack_ext  # prebuilt AOT path
    return None
except ImportError:
    pass
# ... fallback to JIT build
```
