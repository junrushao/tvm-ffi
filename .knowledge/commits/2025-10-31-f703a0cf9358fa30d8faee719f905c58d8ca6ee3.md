# Add standalone AOT-compiled torch_c_dlpack_ext addon package as alternative to JIT compilation
## TL;DR
- Introduces `addons/torch_c_dlpack_ext/`, a new standalone pip-installable package that provides a pre-built (AOT-compiled) shared library for the PyTorch DLPack exchange API, eliminating the need for JIT compilation at `tvm_ffi` import time.
- Modifies `_optional_torch_c_dlpack.py` to try `import torch_c_dlpack_ext` before falling back to the existing JIT compilation path, making this fully backward-compatible and opt-in.
- Establishes the `addons/` directory as a new location for companion packages that extend `tvm_ffi` functionality.

## Impact
- API: None -- additive only. No existing API changed.
- Behavioral: `load_torch_c_dlpack_extension()` in `_optional_torch_c_dlpack.py` now attempts to import the prebuilt `torch_c_dlpack_ext` package before falling through to JIT compilation. Users who install `torch_c_dlpack_ext` avoid the slow first-import JIT compile.
- Flags/config: None -- opt-in via `pip install torch_c_dlpack_ext`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DLPackExchangeAPI struct** (`.knowledge/ADRs/0015-dlpack-exchange-api-struct.md`): The prebuilt shared library exposes `TorchDLPackExchangeAPIPtr()` which returns a pointer to the `DLPackExchangeAPI` struct, same as the JIT-compiled version.
- **`torch.Tensor.__c_dlpack_exchange_api__`** class attribute protocol (`.knowledge/designs/0012-python-bindings.md`, line 37): The addon sets this attribute via `ctypes.CDLL` + `setattr`, identical to the JIT path.
- **`_build_optional_torch_c_dlpack` build script** (`python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`): The build backend invokes this script as a subprocess to compile the shared library when no prebuilt lib is present.
- **Extension packaging pattern** (`.knowledge/designs/0013-packaging.md`): This addon follows the companion wheel pattern (co-located .so/.dylib/.dll shipped in the wheel) but uses a custom PEP 517 build backend rather than scikit-build-core.

Design elements this commit produces:
- **`addons/` directory convention**: First addon package. Establishes `addons/<name>/` as the location for optional companion packages that extend `tvm_ffi` functionality.
- **AOT torch DLPack addon pattern**: A custom PEP 517 build backend (`build_backend.py`) that wraps setuptools, conditionally compiles a native library at wheel build time, and ships it alongside pure Python loading code.
- **Prebuilt-detection guard**: `_is_lib_prebuilt()` checks for existing shared libraries before adding compile-time dependencies, enabling a two-phase workflow: (1) build from sdist compiles locally, (2) prebuilt wheel skips compilation.

## Usage Examples

Install the prebuilt addon to skip JIT compilation:
```python
# Option 1: Install the addon package (eliminates JIT compile at import time)
# $ pip install torch_c_dlpack_ext

# Then, importing tvm_ffi automatically picks up the prebuilt extension:
import tvm_ffi  # _optional_torch_c_dlpack.py tries `import torch_c_dlpack_ext` first
# -> torch.Tensor.__c_dlpack_exchange_api__ is set from prebuilt shared library
# -> no JIT compilation needed

# Option 2: Without the addon, existing JIT fallback still works:
import tvm_ffi  # falls through to JIT compile on first import (slower, but unchanged behavior)
```

Build the addon wheel from source:
```bash
# Build wheel (compiles shared lib during wheel build via tvm_ffi build script)
cd addons/torch_c_dlpack_ext
pip wheel .
# -> produces torch_c_dlpack_ext-0.1.0-py3-none-any.whl containing
#    torch_c_dlpack_ext/libtorch_c_dlpack_addon_torch{major}{minor}-{cpu|cuda}.{so|dylib|dll}
```
