# Add standalone torch_c_dlpack_ext addon package for ahead-of-time DLPack extension builds
## TL;DR
- Introduces a new standalone Python package `torch_c_dlpack_ext` under `addons/torch_c_dlpack_ext/` that can be built and distributed as a wheel containing prebuilt DLPack exchange API shared libraries for PyTorch.
- Adds a custom PEP 517 build backend (`build_backend.py`) that conditionally compiles the extension during wheel build if no prebuilt library is found.
- Modifies `tvm_ffi._optional_torch_c_dlpack.load_torch_c_dlpack_extension()` to first attempt `import torch_c_dlpack_ext` (the prebuilt package) before falling back to the existing JIT compilation path.

## Key Exports

**Packages**: `torch_c_dlpack_ext` -- standalone pip-installable package (name: `torch_c_dlpack_ext`, version `0.1.0`)

**Functions**:
- `torch_c_dlpack_ext.core.load_torch_c_dlpack_extension() -> None` -- loads a prebuilt `.so`/`.dylib`/`.dll` matching the current torch version and device (CPU/CUDA), sets `torch.Tensor.__c_dlpack_exchange_api__` attribute via `ctypes.CDLL`
- `build_backend.get_requires_for_build_wheel(config_settings) -> list[str]` -- returns `["apache-tvm-ffi>=0.1.1"]` as additional build dep when no prebuilt lib is found
- `build_backend.build_wheel(wheel_directory, config_settings, metadata_directory) -> str` -- compiles the extension via `tvm_ffi.utils._build_optional_torch_c_dlpack` if not prebuilt, then delegates to setuptools

**Build Backend**: Custom PEP 517 backend at `addons/torch_c_dlpack_ext/build_backend.py`, wrapping `setuptools.build_meta` with conditional compilation logic.

## Impact
- API: `load_torch_c_dlpack_extension()` in `tvm_ffi` gains a new early-return path via `import torch_c_dlpack_ext`. Backward compatible -- if the package is not installed, falls through to existing JIT path.
- ABI: none
- Behavioral: When `torch_c_dlpack_ext` is installed, the DLPack exchange API library is loaded from the prebuilt wheel instead of JIT-compiled at first use, eliminating the first-call compilation latency.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

### Installing the prebuilt extension package
**Context**: Users can install the addon to avoid JIT compilation latency on first torch tensor FFI call.
```bash
# Build and install the addon wheel (requires torch and apache-tvm-ffi)
cd addons/torch_c_dlpack_ext
pip install .

# Now tvm_ffi automatically uses the prebuilt library
python -c "import tvm_ffi; import torch; x = torch.randn(10); print('fast path active:', hasattr(torch.Tensor, '__c_dlpack_exchange_api__'))"
```

### How the fallback chain works
**Context**: `_optional_torch_c_dlpack.py` load order after this commit.
```python
# In tvm_ffi._optional_torch_c_dlpack.load_torch_c_dlpack_extension():
# 1. If torch.Tensor already has __c_dlpack_exchange_api__ -> skip (native PyTorch)
# 2. Try: import torch_c_dlpack_ext  -> return (prebuilt AOT package)  <-- NEW
# 3. Fallback: JIT compile via _build_optional_torch_c_dlpack  -> existing behavior
```
