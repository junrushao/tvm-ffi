# Fix load_inline on macOS by linking libtvm_ffi on all platforms
## TL;DR
- Move `find_libtvm_ffi()` call and library path/name extraction out of the Windows-only branch so it runs on all platforms.
- Add `-L<lib_path> -ltvm_ffi` to the default Unix linker flags in `_generate_ninja_build`, fixing unresolved symbol errors on macOS.
- Remove `@pytest.mark.xfail` decorators from four `test_load_inline_*` tests that were gated on non-Linux platforms.

## Key Exports
No new public API. The behavioral fix is internal to `_generate_ninja_build`.

```python
# Before (Unix-only path):
#   default_ldflags = ["-shared"]
# After:
#   default_ldflags = ["-shared", "-L<tvm_ffi_lib_dir>", "-ltvm_ffi"]
```

## Impact
- API: none
- Behavioral: `tvm_ffi.cpp.load_inline` now produces working shared libraries on macOS (and continues to work on Linux/Windows). The compiled module correctly links against `libtvm_ffi.dylib`/`libtvm_ffi.so`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Module system (`0011-module-system`): `load_inline` compiles C++ at runtime and loads it via `load_module`.
- Python bindings (`0012-python-bindings`): `find_libtvm_ffi()` from `libinfo.py` locates the installed shared library.

Design elements this commit produces: none

## Usage Examples
Before/after pattern showing the platform-specific failure this commit fixes:

```python
# Before: on macOS, this would fail with unresolved symbol errors
# because the ninja build did not link against libtvm_ffi.dylib.
import tvm_ffi.cpp
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="int add_one(int x) { return x + 1; }",
    functions=["add_one"],
)
# RuntimeError: ninja exited with status 1 (undefined symbols)

# After: works on macOS because -L<path> -ltvm_ffi is added to ldflags.
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="int add_one(int x) { return x + 1; }",
    functions=["add_one"],
)
result = mod["add_one"](42)  # returns 43
```
