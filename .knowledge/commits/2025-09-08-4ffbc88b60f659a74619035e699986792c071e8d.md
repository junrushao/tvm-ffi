# Fix load_inline on macOS by linking libtvm_ffi in the non-Windows linker flags

## TL;DR
- `tvm_ffi.cpp.load_inline` failed on macOS because the non-Windows branch of `_generate_ninja_build` omitted `-ltvm_ffi` and `-L<lib_path>` from the default linker flags, leaving custom module symbols unresolved at dlopen time.
- Fixed by hoisting `find_libtvm_ffi()` path decomposition before the `if IS_WINDOWS` branch, then appending `-L{tvm_ffi_lib_path} -ltvm_ffi` to `default_ldflags` in the `else` branch.
- Four `pytest.mark.xfail` markers that previously excluded macOS and non-Linux platforms from `test_load_inline_*` tests are removed, enabling the tests to run and pass on all supported platforms.

## Key Exports

```python
def _generate_ninja_build(
    name: str,
    build_dir: str,
    with_cuda: bool,
    extra_cflags: Sequence[str],
    extra_cuda_cflags: Sequence[str],
    extra_ldflags: Sequence[str],
    extra_include_paths: Sequence[str],
) -> str:
    """Generate build.ninja content for compiling a custom TVM FFI module."""
    # Before fix (else branch):
    #   default_ldflags = ["-shared"]
    #   tvm_ffi_lib resolved only inside the if IS_WINDOWS block

    # After fix (else branch):
    #   tvm_ffi_lib = find_libtvm_ffi()          # hoisted before if/else
    #   tvm_ffi_lib_path = os.path.dirname(tvm_ffi_lib)
    #   tvm_ffi_lib_name = os.path.splitext(os.path.basename(tvm_ffi_lib))[0]
    #   default_ldflags = ["-shared", "-L{tvm_ffi_lib_path}", "-ltvm_ffi"]

    # Invariant: on macOS, the custom .so MUST link against libtvm_ffi.dylib at build time;
    #   DYLD_LIBRARY_PATH is not set implicitly, unlike LD_LIBRARY_PATH on Linux.
    # Interacts with: find_libtvm_ffi() (libinfo.py), load_module (Module.LoadFromFile)
```

## Impact
- API: None — `load_inline` signature unchanged.
- Behavioral: `load_inline` now succeeds on macOS (and any other POSIX platform beyond Linux). Previously, the compiled `.so` lacked a dynamic dependency on `libtvm_ffi.dylib`, causing symbol resolution failures at `dlopen` time.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

**Before fix (macOS failure pattern):**
```python
import tvm_ffi.cpp

# On macOS: raises RuntimeError from load_module — dlopen fails with
# "symbol not found" because libtvm_ffi.dylib was not linked into hello.so
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="int add_one(int x) { return x + 1; }",
    functions=["add_one"],
)
```

**After fix (works on Linux, macOS, Windows):**
```python
import tvm_ffi.cpp
import numpy

# Compiled hello.so now carries -ltvm_ffi in its dynamic section; loads correctly
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="int add_one(int x) { return x + 1; }",
    functions=["add_one"],
)
x = numpy.array([1, 2, 3], dtype=numpy.int32)
y = numpy.empty_like(x)
mod["add_one"](x, y, x.size)
numpy.testing.assert_equal(x + 1, y)
```
