# Fix load_inline on macOS by linking libtvm_ffi on all Unix platforms
## TL;DR
- Hoist `find_libtvm_ffi()` and library path extraction out of the Windows-only branch in `_generate_ninja_build`, making it available to all platforms.
- Add `-L<tvm_ffi_lib_path> -ltvm_ffi` to `default_ldflags` for non-Windows platforms, fixing link failures on macOS.
- Remove `@pytest.mark.xfail` from all four `test_load_inline_cpp*` tests, enabling them on macOS (previously only passed on Linux/Windows).

## Key Exports
None -- no new public API. The fix changes internal linker flag generation within `_generate_ninja_build`.

## Impact
- API: none
- Behavioral: `tvm_ffi.cpp.load_inline` now works on macOS. Previously it compiled but failed to link because the built `.so` could not resolve `libtvm_ffi` symbols. The ninja-generated link command now includes `-L/path/to -ltvm_ffi` on all Unix platforms (Linux and macOS), matching what was already done for Windows (`/LIBPATH:` + `.lib`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system / `load_inline`** ([0011-module-system.md](../designs/0011-module-system.md)): The `load_inline` function compiles C++ source at runtime via ninja, then loads the resulting `.so`/`.dll` via `load_module`. This commit fixes its linker configuration.
- **`find_libtvm_ffi()`** (`python/tvm_ffi/libinfo.py`): Locates the platform-appropriate shared library (`libtvm_ffi.dylib` on macOS, `libtvm_ffi.so` on Linux, `tvm_ffi.dll` on Windows). Already used by the Windows branch; now used by all platforms.

Design elements this commit produces: none

## Usage Examples
**Before (broken on macOS):** `_generate_ninja_build` produced Unix ldflags as `["-shared"]` only. The compiled module could not resolve `libtvm_ffi` symbols at link time.

**After (fixed):**
```python
# Unix default_ldflags now include the library path and link flag:
default_ldflags = ["-shared", "-L/path/to/tvm_ffi_lib", "-ltvm_ffi"]
```

The `find_libtvm_ffi()` call and path extraction are now shared across all platform branches:
```python
tvm_ffi_lib = find_libtvm_ffi()
tvm_ffi_lib_path = os.path.dirname(tvm_ffi_lib)
tvm_ffi_lib_name = os.path.splitext(os.path.basename(tvm_ffi_lib))[0]
# Then used in both Windows and Unix ldflags
```
