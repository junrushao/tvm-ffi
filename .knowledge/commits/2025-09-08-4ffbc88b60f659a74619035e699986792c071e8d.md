# Fix load_inline on macOS by linking libtvm_ffi for non-Windows platforms
## TL;DR
- Hoist `find_libtvm_ffi()` and lib path/name extraction out of the Windows-only branch so it runs on all platforms.
- Add `-L<lib_path> -ltvm_ffi` to default linker flags for non-Windows (Unix/macOS) targets in `_generate_ninja_build`.
- Remove `@pytest.mark.xfail` from four `test_load_inline_cpp*` tests, enabling them on macOS.

## Key Exports
No new public API. The fix changes internal linker flag construction in `_generate_ninja_build`.

```python
def _generate_ninja_build(
    name: str,
    build_dir: str,
    with_cuda: bool,
    extra_cflags: Sequence[str],
    extra_cuda_cflags: Sequence[str],
    extra_ldflags: Sequence[str],
    extra_include_paths: Sequence[str],
) -> str:
    # Interacts with: find_libtvm_ffi() from tvm_ffi.libinfo
    # Invariant (restored): libtvm_ffi is always linked, not just on Windows.
    #   On Windows: /LIBPATH:<path> <name>.lib
    #   On Unix/macOS: -L<path> -ltvm_ffi
    # Interacts with: load_module() which dlopen's the resulting .so/.dylib
    ...
```

## Impact
- API: none
- Behavioral: `tvm_ffi.cpp.load_inline` now produces correctly linked shared libraries on macOS (and other non-Windows Unix platforms). Previously, the compiled module would fail at load time due to unresolved `libtvm_ffi` symbols.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:

- `load_module()` from `tvm_ffi.module` ([0011-ffi-module-system](../.knowledge/design-records/0011-ffi-module-system.md)) -- loads the compiled `.so`/`.dylib` as a `Module` via `DSOLibrary`.
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro ([0013-ffi-packaging-and-distribution](../.knowledge/design-records/0013-ffi-packaging-and-distribution.md)) -- injected by `_decorate_with_tvm_ffi` into the generated C++ source.

Design elements this commit produces: none

## Usage Examples
**Before (broken on macOS):** `load_inline` compiled a `.so` but omitted `-ltvm_ffi`, causing unresolved symbol errors at `load_module` time.

**After (fixed):**
```python
import tvm_ffi.cpp
from tvm_ffi.module import Module

# Works on Linux, macOS, and Windows
mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="int AddOne(int x) { return x + 1; }",
    functions=["AddOne"],
)
f = mod["AddOne"]
assert f(41) == 42
```
