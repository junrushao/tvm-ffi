# Fix CUDA availability check to use both torch.version.cuda and torch.cuda.is_available()

## TL;DR
- CUDA check was only using `torch.version.cuda is not None` which passes on machines with CUDA-enabled torch but no GPU hardware. Fix adds `torch.cuda.is_available()` as an additional guard.
- Updates `addons/torch_c_dlpack_ext/build_backend.py`, `python/tvm_ffi/_optional_torch_c_dlpack.py`, and tests.
- Also bumps version in `include/tvm/ffi/c_api.h` (1 line).

None

## Impact
- API: none
- Behavioral: Fixes build failure on CUDA-torch-but-no-GPU systems where building with CUDA libs would fail.
- Flags/config: `build_with_cuda = torch.version.cuda is not None and torch.cuda.is_available()` (new condition).
- Data formats/schemas: none

Before:

```python
build_with_cuda = torch.version.cuda is not None  # True even on CPU-only hardware with CUDA torch
```
After:
