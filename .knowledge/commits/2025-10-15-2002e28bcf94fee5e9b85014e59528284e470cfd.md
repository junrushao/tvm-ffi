# Fix Windows build: link Python targets for Cython module and add ARM64 InterlockedAdd64 fallback
## TL;DR
- Explicitly links `tvm_ffi_cython` to `Python::SABIModule` (always on Python 3.12+ non-free-threaded) and `Python::Module` (non-Windows only), fixing missing Python symbols on Windows.
- Adds a preprocessor fallback defining `_InlineInterlockedAdd64` as `InterlockedAdd64` on Windows ARM64 when the compiler intrinsic is unavailable.
- Upgrades CI ARM aarch64 test from Python 3.9 to 3.10.

## Key Exports
None. This commit modifies build configuration and a platform-compatibility macro only.

### Macro: `_InlineInterlockedAdd64` fallback (`include/tvm/ffi/base_details.h`)
```cpp
#if (defined(_M_ARM64) || defined(_ARM64_) || defined(_M_ARM64EC)) && \
    !defined(_InlineInterlockedAdd64)
#define _InlineInterlockedAdd64 InterlockedAdd64
#endif
```
Conditional define only active on Windows ARM64 when the MSVC compiler does not provide the `_InlineInterlockedAdd64` intrinsic. Maps it to the `InterlockedAdd64` Win32 API function.

## Impact
- API: None.
- ABI: None.
- Behavioral: Fixes compilation failures on Windows (missing Python library symbols for the Cython extension module) and on Windows ARM64 (missing `_InlineInterlockedAdd64` intrinsic). No runtime behavioral change on platforms where the build already succeeded.
- Flags/config: CI matrix changes `python_version` for `ubuntu-24.04-arm` from `'3.9'` to `'3.10'`.
- Data formats/schemas: None.
