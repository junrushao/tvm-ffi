# Formalize String/Bytes C API and move nested container conversion into Cython/C++

## TL;DR
- Introduces two new C ABI functions (`TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`) that construct `String`/`Bytes` values from raw byte arrays, replacing the previous `kTVMFFIRawStr`/`kTVMFFIByteArrayPtr` passthrough in argument setters.
- Moves `tuple`/`list`/`dict` argument conversion from Python (`_FUNC_CONVERT_TO_OBJECT`) into dedicated Cython setters that recursively call `ffi.Array`/`ffi.Map` constructors, propagating torch stream/device context through nested calls.
- Fixes a bug in temporary FFI object recycling: uses `TVMFFIObjectDecRef` instead of directly calling the object's deleter, which could skip reference-count bookkeeping.

## Key Exports

**Functions (C ABI)**:
```c
// include/tvm/ffi/c_api.h
int TVMFFIStringFromByteArray(const TVMFFIByteArray* input, TVMFFIAny* out);
int TVMFFIBytesFromByteArray(const TVMFFIByteArray* input, TVMFFIAny* out);
```
Both accept a `TVMFFIByteArray` (data+size) and produce an owned `TVMFFIAny` that is either a small-string inline value or a heap-allocated `StringObj`/`BytesObj`.

**Functions (Cython internal helper)**:
```c
// tvm_ffi_python_helpers.h
int TVMFFIPyConstructorCall(
    TVMFFIPyArgSetterFactory setter_factory,
    void* func_handle,
    PyObject* py_arg_tuple,
    TVMFFIAny* result,
    int* c_api_ret_code,
    TVMFFIPyCallContext* parent_ctx
);
```
Like `TVMFFIPyFuncCall` but designed for nested constructor invocations: does not release GIL, propagates device/stream/DLPack allocator context from child call back to `parent_ctx`.

**Cython setters (new)**:
| Setter | Type dispatched on | Behavior |
|--------|-------------------|----------|
| `TVMFFIPyArgSetterTuple_` | `tuple` | Calls `ffi.Array` constructor recursively |
| `TVMFFIPyArgSetterTupleLike_` | `list` | Converts to tuple, then calls `ffi.Array` |
| `TVMFFIPyArgSetterMap_` | `dict` | Flattens to `(k1,v1,k2,v2,...)` tuple, calls `ffi.Map` |
| `TVMFFIPyArgSetterPyNativeObjectStr_` | `PyNativeObject & str` | Checks `__tvm_ffi_object__` first, falls back to `TVMFFIPyArgSetterStr_` |
| `TVMFFIPyArgSetterPyNativeObjectBytes_` | `PyNativeObject & bytes` | Same pattern for bytes |
| `TVMFFIPyArgSetterPyNativeObjectGeneral_` | `PyNativeObject` (other) | Requires non-None `__tvm_ffi_object__` |
| `TVMFFIPyArgSetterObjectConvertible_` | `ObjectConvertible` | Calls `.asobject()` |

**Removed symbols**:
| Symbol | Location | Reason |
|--------|----------|--------|
| `_FUNC_CONVERT_TO_OBJECT` | `object.pxi` | Replaced by dedicated per-type setters |
| `_set_func_convert_to_object` | `object.pxi` | No longer needed |
| `_STR_CONSTRUCTOR` | `function.pxi`, `string.pxi` | String now constructed via `TVMFFIStringFromByteArray` |
| `_BYTES_CONSTRUCTOR` | `function.pxi`, `string.pxi` | Bytes now constructed via `TVMFFIBytesFromByteArray` |
| `core._set_func_convert_to_object(convert)` call | `_convert.py` | Dead code after removal |

## Impact
- API: Two new C ABI functions added (`TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`). No existing C API signatures changed.
- Behavioral: (1) String arguments are now passed as proper `String`/`Bytes` objects (small or large) instead of `kTVMFFIRawStr` raw pointers. (2) `list`/`tuple`/`dict` arguments are recursively converted in Cython rather than via a Python callback, which preserves torch stream context for nested tensors. (3) Temp FFI object recycling now correctly decrements ref counts.
- Flags/config: Version bump `0.1.0a12` -> `0.1.0a13`.
- Data formats/schemas: None.

## Design Elements

Design elements this commit **consumes**:
- **C ABI calling convention** (`c_api.h` return-code + TLS error protocol) -- the new functions follow the standard `int` return convention. See `.knowledge/designs/0001-c-abi-layer.md`.
- **Small String Optimization** -- `TVMFFIStringFromByteArray` delegates to `TypeTraits<String>::MoveToAny` which dispatches between small (inline) and large (heap) representations. See `.knowledge/designs/0011-small-string-optimization.md`.
- **TVMFFIPyCallManager thread-local call stack** -- the new `ConstructorCall` method reuses the existing `CallStack` allocation and `SetArgument` pipeline. See `.knowledge/designs/0014-python-package.md`.
- **Container constructors** (`ffi.Array`, `ffi.Map`) -- invoked via `_CONSTRUCTOR_ARRAY`/`_CONSTRUCTOR_MAP` handles for recursive container building. See `.knowledge/designs/0008-containers.md`.
- **PyNativeObject protocol** -- `__tvm_ffi_object__` attribute checked for `str`/`bytes` subclasses that wrap FFI objects.

Design elements this commit **produces**:
- **Formal String/Bytes C API** (`TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`) -- a new section in the C ABI for constructing string/bytes values from raw byte arrays, bypassing the `kTVMFFIRawStr` intermediate.
- **Nested constructor call protocol** (`TVMFFIPyConstructorCall` / `ConstructorCall` method) -- a variant of function calling that propagates parent call context (device, stream, DLPack allocator) upward, enabling recursive argument conversion with correct stream synchronization.
- **Per-type Cython setter dispatch for containers** -- `tuple`/`list`/`dict`/`ObjectConvertible` each get dedicated setters in the factory, replacing the generic Python-level `_FUNC_CONVERT_TO_OBJECT` callback.

## Usage Examples

**Nested container passing with torch stream propagation** (from test):
```python
import tvm_ffi

fecho = tvm_ffi.get_global_func("testing.echo")
use_count = tvm_ffi.get_global_func("testing.object_use_count")

# list/dict args are now recursively converted in Cython
obj = tvm_ffi.convert((1, 2, 3))
y = fecho([obj, {"a": 1, "b": obj}])
assert use_count(y) == 1
assert use_count(obj) == 3  # obj referenced in 3 places
```

**C++ side: constructing String from byte array** (from `src/ffi/object.cc`):
```c
TVMFFIByteArray input = {data, size};
TVMFFIAny out;
TVMFFIStringFromByteArray(&input, &out);
// out is now kTVMFFISmallStr (if size <= 7) or kTVMFFIStr (heap-allocated)
```
