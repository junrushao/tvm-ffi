# Introduce formal C API for String/Bytes creation and move nested container conversion into Cython

## TL;DR
- Adds two new C ABI functions (`TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`) that construct owned String/Bytes from raw byte data, replacing the previous pattern of passing `kTVMFFIRawStr`/`kTVMFFIByteArrayPtr` as AnyView-only non-owning pointers through the Python arg setter.
- Introduces `TVMFFIPyConstructorCall` alongside the existing `TVMFFIPyFuncCall`, enabling nested recursive argument conversion (tuple/list/dict) in Cython with proper torch stream context propagation from child calls to parent.
- Refactors `TVMFFIPyArgSetterFactory_` in Cython to handle `tuple`, `list`, `dict`, `ObjectConvertible`, and `PyNativeObject` subtypes (str/bytes/general) with dedicated typed setters, eliminating the Python-side `_FUNC_CONVERT_TO_OBJECT` callback and `_set_func_convert_to_object` registration.

## Impact
- API: Two new C ABI functions `TVMFFIStringFromByteArray`/`TVMFFIBytesFromByteArray` added to `c_api.h`. Additive only for C API consumers. Python-level `_set_func_convert_to_object` removed (was internal).
- Behavioral: String/bytes arguments now pass through C++ `TypeTraits<String>::MoveToAny` / `TypeTraits<Bytes>::MoveToAny` instead of being passed as non-owning `kTVMFFIRawStr`/`kTVMFFIByteArrayPtr`. Nested containers (list, tuple, dict) are now recursively converted in-band via Cython setters instead of calling Python-level `convert()`, with torch stream/device context properly propagated from nested conversions to the parent call.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIAny` value layout and `kTVMFFINone` initialization protocol ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md))
- `TypeTraits<String>::MoveToAny` / `TypeTraits<Bytes>::MoveToAny` for String/Bytes construction ([0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md))
- `TVMFFIPyCallManager` thread-local call stack, `TVMFFIPyArgSetter`/`TVMFFIPyArgSetterFactory` dispatch table ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md))
- `TVMFFIObjectDecRef` for temp object cleanup (replacing direct deleter call) ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md))
- `ffi.Array` and `ffi.Map` global constructors ([0006-ffi-containers](../design-records/0006-ffi-containers.md))

Design elements this commit produces:
- **`TVMFFIStringFromByteArray` / `TVMFFIBytesFromByteArray`**: New C ABI entry points for owning String/Bytes construction from `TVMFFIByteArray`. This shifts string construction from AnyView-only non-owning patterns to proper owned values at the C boundary.
- **`TVMFFIPyConstructorCall` / `TVMFFIPyCallManager::ConstructorCall`**: New constructor call protocol that performs recursive argument conversion with parent-context propagation (device/stream/DLPack allocator). Enables nested container conversion without leaving Cython.
- **Typed Cython setter architecture for containers**: `TVMFFIPyArgSetterTuple_`, `TVMFFIPyArgSetterTupleLike_`, `TVMFFIPyArgSetterMap_`, `TVMFFIPyArgSetterObjectConvertible_` setters that replace the Python-level `_FUNC_CONVERT_TO_OBJECT` callback with in-band recursive Cython conversion.
- **Handle-level conversion helpers**: `_convert_to_ffi_func_handle` and `_convert_to_opaque_object_handle` that create raw handles without wrapping in Python objects, reducing allocation overhead in the setter path.

## Usage Examples

Nested container passing through FFI (from `tests/python/test_function.py`):
```python
import tvm_ffi

fecho = tvm_ffi.get_global_func("testing.echo")
use_count = tvm_ffi.get_global_func("testing.object_use_count")

# list/tuple/dict are now recursively converted in Cython with proper ref counting
obj = tvm_ffi.convert((1, 2, 3))
assert use_count(obj) == 1

# nested container: list containing an Array and a dict
y = fecho([obj, {"a": 1, "b": obj}])
assert use_count(obj) == 3  # held by original + array element + dict value
assert use_count(y[1]) == 2  # dict held by y and internally

# torch stream context propagated through nested container construction:
# mod.return_add_one({"x": [x_cuda]})  # dict -> Map, list -> Array, torch.Tensor detected
```

Bugfix -- temp object recycling now uses `TVMFFIObjectDecRef` instead of direct deleter call:
```python
# Before (broken): direct deleter call could miss two-phase deletion protocol
#   obj->deleter(obj, kTVMFFIObjectDeleterFlagBitMaskBoth)
# After (correct): uses proper C ABI ref counting
#   TVMFFIObjectDecRef(obj)
```
