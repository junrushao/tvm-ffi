# Formalize C API for String/Bytes creation and move nested container conversion into Cython/C++

## TL;DR
- Adds two new C API functions (`TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`) for constructing String/Bytes from raw byte arrays, replacing the previous Python-level `kTVMFFIRawStr`/`kTVMFFIByteArrayPtr` view approach.
- Moves recursive container conversion (list/tuple/dict) from the Python `convert.py` callback (`_FUNC_CONVERT_TO_OBJECT`) into Cython-level setters that call `ffi.Array`/`ffi.Map` constructors directly via a new `TVMFFIPyConstructorCall` path.
- Introduces `TVMFFIPyConstructorCall` -- a nested constructor calling convention that propagates CUDA stream/device context from child conversions to the parent call context.
- Fixes a bug in temp object recycling: `CallStack::~CallStack` now uses `TVMFFIObjectDecRef` instead of directly invoking the deleter, which was incorrect for objects with non-zero weak ref counts.

## Key Exports

**C API Functions** (in `include/tvm/ffi/c_api.h`):
- `int TVMFFIStringFromByteArray(const TVMFFIByteArray* input, TVMFFIAny* out)` -- Creates a String (SmallStr or Str object) from raw bytes. Uses `TypeTraits<String>::MoveToAny`.
- `int TVMFFIBytesFromByteArray(const TVMFFIByteArray* input, TVMFFIAny* out)` -- Creates a Bytes (SmallBytes or Bytes object) from raw bytes. Uses `TypeTraits<Bytes>::MoveToAny`.

**C++ Helper** (in `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`):
- `TVMFFIPyCallManager::ConstructorCall(setter_factory, func_handle, py_arg_tuple, result, c_api_ret_code, parent_ctx)` -- Calls a constructor function with recursive argument setting and propagates stream/device/allocator context to parent.
- `TVMFFIPyConstructorCall(setter_factory, func_handle, py_arg_tuple, result, c_api_ret_code, parent_ctx)` -- Inline wrapper dispatching to `TVMFFIPyCallManager::ThreadLocal()->ConstructorCall(...)`.
- `TVMFFIPyCallManager::FuncCall(...)` -- Renamed from `Call(...)` to disambiguate from `ConstructorCall`.

**Cython Setters** (in `python/tvm_ffi/cython/function.pxi`):
- `TVMFFIPyArgSetterTuple_` -- Converts Python `tuple` by calling `ffi.Array` constructor recursively.
- `TVMFFIPyArgSetterTupleLike_` -- Converts Python `list` (coerced to tuple first) the same way.
- `TVMFFIPyArgSetterMap_` -- Converts Python `dict` by flattening to key-value list and calling `ffi.Map` constructor recursively.
- `TVMFFIPyArgSetterPyNativeObjectStr_` -- Handles `PyNativeObject` subclasses of `str` (checks `__tvm_ffi_object__` first, falls back to `TVMFFIPyArgSetterStr_`).
- `TVMFFIPyArgSetterPyNativeObjectBytes_` -- Same pattern for `bytes` subclasses.
- `TVMFFIPyArgSetterPyNativeObjectGeneral_` -- General `PyNativeObject` handler that requires non-None `__tvm_ffi_object__`.
- `TVMFFIPyArgSetterObjectConvertible_` -- Calls `arg.asobject()` to convert.
- `ConstructorCall(constructor_handle, py_arg_tuple, handle, parent_ctx)` -- Cython-level wrapper for `TVMFFIPyConstructorCall`.
- `_convert_to_ffi_func_handle(pyfunc, out_handle)` -- Lower-level variant of `_convert_to_ffi_func` that returns raw handle (avoids wrapping in Python Object).
- `_convert_to_opaque_object_handle(pyobject, out_handle)` -- Lower-level variant of `_convert_to_opaque_object`.

**Removed/Changed Symbols**:
- `_FUNC_CONVERT_TO_OBJECT` global removed from `object.pxi` -- no longer needed since conversion happens in Cython setters.
- `_STR_CONSTRUCTOR`, `_BYTES_CONSTRUCTOR` removed from `function.pxi` / `string.pxi` -- replaced by direct C API calls.
- `_set_func_convert_to_object()` removed from `object.pxi`.
- `core._set_func_convert_to_object(convert)` call removed from `convert.py`.
- `ByteArrayArg` usage removed from `TVMFFIPyArgSetterBytes_` -- bytes now use `TVMFFIBytesFromByteArray` directly.
- Old `TVMFFIPyArgSetterStr_` no longer uses `kTVMFFIRawStr`; now creates owned String via `TVMFFIStringFromByteArray`.
- Old `TVMFFIPyArgSetterBytes_` no longer uses `kTVMFFIByteArrayPtr`; now creates owned Bytes via `TVMFFIBytesFromByteArray`.

## Impact
- API: No breaking Python API changes. The `_FUNC_CONVERT_TO_OBJECT` internal hook and `_STR_CONSTRUCTOR`/`_BYTES_CONSTRUCTOR` are removed, but these were private internals.
- ABI: Two new C API functions added (`TVMFFIStringFromByteArray`, `TVMFFIBytesFromByteArray`). No existing function signatures changed. Version bumped to 0.1.0a13.
- Behavioral: (1) String/bytes arguments are now passed as owned `String`/`Bytes` objects (SSO-aware) instead of non-owning `kTVMFFIRawStr`/`kTVMFFIByteArrayPtr` views. This changes the type_index seen by C++ callees from `kTVMFFIRawStr` to `kTVMFFISmallStr`/`kTVMFFIStr` for strings, and from `kTVMFFIByteArrayPtr` to `kTVMFFISmallBytes`/`kTVMFFIBytes` for bytes. C++ functions using `cast<String>()` / `cast<Bytes>()` are unaffected since `TypeTraits` handles all representations. (2) Nested list/tuple/dict arguments are recursively converted in Cython instead of calling back to Python. (3) CUDA stream context from nested containers (e.g., a list of torch.Tensor) now propagates to the parent call. (4) Temp object recycling uses `TVMFFIObjectDecRef` instead of direct deleter invocation, fixing correctness for weak-ref-counted objects.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C ABI** (`.knowledge/designs/c-abi.md`): `TVMFFIByteArray`, `TVMFFIAny`, `TVMFFIObjectDecRef`, `TVMFFIFunctionCall`, `TVMFFIFunctionCreate`, `TVMFFIObjectCreateOpaque`, type index constants (`kTVMFFISmallStr`, `kTVMFFIStr`, `kTVMFFISmallBytes`, `kTVMFFIBytes`, `kTVMFFIStaticObjectBegin`).
- **Any/AnyView system** (`.knowledge/designs/any-system.md`): `TypeTraits<String>::MoveToAny`, `TypeTraits<Bytes>::MoveToAny` for SSO-aware String/Bytes construction.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): `TVMFFIPyCallManager`, `TVMFFIPyArgSetter` factory pattern, `TVMFFIPyCallContext` for stream/device propagation, `TVMFFIPyPushTempFFIObject`/`TVMFFIPyPushTempPyObject` for temp lifetime management.
- **Container types** (`.knowledge/designs/containers.md`): `ffi.Array` and `ffi.Map` constructors consumed for recursive tuple/dict conversion.
- **Small string optimization** (`.knowledge/designs/0011-small-string-optimization.md`): SSO is leveraged by `TVMFFIStringFromByteArray`/`TVMFFIBytesFromByteArray` via `TypeTraits<String>::MoveToAny`.
- **Weak reference counting** (`.knowledge/designs/0016-weak-reference-counting.md`): The bugfix to use `TVMFFIObjectDecRef` instead of direct deleter invocation respects the two-phase (strong/weak) deletion protocol.

Design elements this commit produces:
- **C API: String/Bytes construction from byte arrays**: `TVMFFIStringFromByteArray` and `TVMFFIBytesFromByteArray` provide a formal C ABI for creating owned String/Bytes from raw data, complementing the existing `kTVMFFIRawStr`/`kTVMFFIByteArrayPtr` view types.
- **Nested constructor call convention**: `TVMFFIPyConstructorCall` and `TVMFFIPyCallManager::ConstructorCall` define a new calling path for recursive argument conversion that preserves stream/device context propagation. Key invariant: child constructor calls propagate their detected `device_type`, `device_id`, `stream`, `c_dlpack_tensor_allocator`, and `c_dlpack_to_pyobject` to the parent context if the parent has not yet set them.
- **Type-specific Cython setters for containers**: `TVMFFIPyArgSetterTuple_`, `TVMFFIPyArgSetterTupleLike_`, `TVMFFIPyArgSetterMap_` move container conversion from Python into Cython, eliminating the `_FUNC_CONVERT_TO_OBJECT` callback indirection.
- **Handle-returning conversion helpers**: `_convert_to_ffi_func_handle` and `_convert_to_opaque_object_handle` avoid intermediate Python Object wrapper construction when only the raw handle is needed (used by setters that push to `TVMFFIPyPushTempFFIObject`).

## Usage Examples

### String/Bytes passing with SSO
**Context**: Python strings and bytes are now converted to owned String/Bytes objects at the Cython boundary, leveraging small-string optimization.
```python
import tvm_ffi

fecho = tvm_ffi.get_global_func("testing.echo")

# Small string (<= 7 bytes): stored inline as kTVMFFISmallStr
assert fecho("hello") == "hello"

# Large string: allocated as Str object (kTVMFFIStr)
x = "hello" * 100
y = fecho(x)
assert y == x
assert y.__tvm_ffi_object__ is not None  # backed by FFI object
```

### Nested container passing with stream context propagation
**Context**: Lists and dicts containing torch tensors are recursively converted in Cython, with CUDA stream context propagating up to the parent call.
```python
import tvm_ffi

fecho = tvm_ffi.get_global_func("testing.echo")
use_count = tvm_ffi.get_global_func("testing.object_use_count")

obj = tvm_ffi.convert((1, 2, 3))
assert use_count(obj) == 1

# Nested container: list with dict, recursively converted in Cython
y = fecho([obj, {"a": 1, "b": obj}])
assert use_count(y) == 1
assert use_count(obj) == 3   # referenced from two places + original
assert use_count(y[1]) == 2  # dict referenced from y and counted
```
