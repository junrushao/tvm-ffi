# Make Error::what() return message-only, add FullMessage() for formatted output
## TL;DR
- `Error::what()` now returns only `obj->message.data` instead of the full formatted string with traceback and kind. This makes it `noexcept`-safe and conformant with `std::exception::what()` convention.
- New `Error::FullMessage()` method returns the previous `what()` output (traceback + kind + message) as a `std::string`.
- `ErrorBuilder` destructor updated to call `FullMessage()` instead of `what()` for logging, preserving the full diagnostic output on stderr.
- Removes `thread_local std::string what_data` from `what()`, eliminating a TLS dependency from the header and improving compatibility with LLVM JIT.

## Impact
- API: `Error::what()` return value changed from full formatted message to message-only. Callers relying on `what()` containing traceback or kind information must switch to `FullMessage()`. Tests updated in this commit.
- Behavioral: `ErrorBuilder` log-before-throw output unchanged (uses `FullMessage()` now). End-user catch handlers that only inspect `what()` will see shorter messages.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
**Before/after pattern for callers needing the full error output:**

```cpp
// BEFORE: what() returned full formatted string
try { ... } catch (const Error& error) {
    std::string full = error.what();  // included traceback + kind + message
    if (full.find("ValueError") != std::string::npos) { ... }
}

// AFTER: what() returns message-only; use FullMessage() for full output
try { ... } catch (const Error& error) {
    std::string msg = error.what();             // message only
    std::string full = error.FullMessage();      // traceback + kind + message
    if (full.find("ValueError") != std::string::npos) { ... }
}
```
