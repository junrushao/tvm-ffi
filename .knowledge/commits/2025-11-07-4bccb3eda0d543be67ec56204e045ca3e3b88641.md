# Make Error::what() return only message; add FullMessage() for full error output
## TL;DR
- `Error::what()` now returns only `obj->message.data` instead of the full formatted string with traceback and kind, conforming to the `std::exception::what()` contract that `what()` should not throw.
- New `Error::FullMessage()` method returns the previous full output (traceback + kind + message).
- Removes `thread_local std::string` from `what()`, eliminating TLS dependency in the header and improving compatibility with LLVM JIT-compiled C++ objects.

## Key Exports

```python
class Error(ObjectRef, std.exception):
    """Managed error ref. Can be thrown as C++ exception AND stored as FFI object."""

    def FullMessage(self) -> str: ...
        # Returns "Traceback (most recent call last):\n{traceback}\n{kind}: {message}\n"
        # Returns a std::string by value (no TLS, no lifetime concerns)
        # Interacts with: TracebackMostRecentCallLast(), ErrorObj.kind, ErrorObj.message
        # Invariant: equivalent to what the old what() returned

    def what(self) -> "const char*": ...
        # OLD: returned full formatted string via thread_local std::string
        # NEW: returns obj->message.data directly (just the message, no kind/traceback)
        # Invariant: noexcept — must not throw (std::exception contract)
        # Invariant: returned pointer valid for lifetime of the Error object
        # Interacts with: ErrorObj.message (TVMFFIByteArray)

class ErrorBuilder:
    """Stream-style error constructor. Throws Error in destructor."""
    # Changed: destructor now calls error.FullMessage() instead of error.what() for stderr logging
    # Interacts with: Error.FullMessage(), TVM_FFI_THROW macro
```

## Impact
- API: **Breaking** — `Error::what()` return value changed from full formatted error to message-only. Callers using `what()` to get traceback or kind info must switch to `FullMessage()`. New `FullMessage()` method added as replacement.
- Behavioral: `ErrorBuilder` stderr logging now uses `FullMessage()` — output is unchanged since `FullMessage()` produces the same string the old `what()` did. `what()` callers see reduced output (message only).
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

Before/after pattern showing the behavioral change:

```cpp
// BEFORE (what() returned full formatted string):
try {
    TVM_FFI_THROW(ValueError) << "bad input";
} catch (const Error& e) {
    // e.what() => "Traceback (most recent call last):\n  ...\nValueError: bad input\n"
    std::string full = e.what();  // had traceback + kind + message
}

// AFTER (what() returns message only, use FullMessage() for full output):
try {
    TVM_FFI_THROW(ValueError) << "bad input";
} catch (const Error& e) {
    // e.what() => "bad input"  (message only, no traceback, no kind)
    const char* msg = e.what();
    // e.FullMessage() => "Traceback (most recent call last):\n  ...\nValueError: bad input\n"
    std::string full = e.FullMessage();
}
```
