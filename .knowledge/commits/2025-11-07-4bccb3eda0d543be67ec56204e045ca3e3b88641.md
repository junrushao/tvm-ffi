# Change Error.what() to return only message; add FullMessage() for kind+traceback; remove TLS from what()

## TL;DR
- `Error::what()` now returns only `obj->message.data` (the error message string pointer stored in `ErrorObj`), not the full formatted traceback — conforming to the C++ standard that `what()` must not throw.
- New `Error::FullMessage()` returns the full string `"Traceback...\nKind: message\n"` — for use when the full representation is needed (e.g., `std::cerr` in `ErrorBuilder`).
- Removes the `thread_local std::string what_data` TLS variable from `what()`, making the compiled C++ object more LLVM JIT-friendly.

```python
        # After: returns obj->message.data directly — no allocation, noexcept(true)

        # Invariant: returned pointer valid as long as Error object alive
        """

        """Return full error string: 'Traceback...\nKind: message\n'
        # Use for logging/printing; allocates a new std::string on each call
        # Interacts with: TracebackMostRecentCallLast(), ErrorObj.kind, ErrorObj.message
        """
        ...
```

## Impact
- API: `what()` behavior changed — existing code calling `error.what()` expecting kind+traceback now gets only the message. Call `error.FullMessage()` instead for the full representation.
- Behavioral: `std::cerr << error.what()` now prints only the message; `ErrorBuilder` updated to use `error.FullMessage()`.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before:
```cpp
catch (const ffi::Error& e) {
    std::cerr << e.what();  // printed full traceback
}
```
After:
```cpp
catch (const ffi::Error& e) {
    std::cerr << e.what();       // message only
    std::cerr << e.FullMessage(); // full traceback+kind
```
