# Make Error::what() return message-only, add FullMessage() for trace+kind
## TL;DR
- Changes `Error::what()` to return only the error message (conforming to `std::exception::what()` which should not throw)
- Adds `Error::FullMessage()` for the full message with backtrace and error kind
- Removes TLS dependency from the header side, improving compatibility with LLVM JIT

## Key Exports
```python
class Error:
    def what(self) -> str:
        """Return message only (std::exception conformant, no-throw)."""
        # Before: returned full message with trace + kind
        # After: returns message only
        ...

    def FullMessage(self) -> str:  # NEW
        """Return full message with backtrace and kind."""
        # Interacts with: backtrace() (design-record 0004)
        ...
```

## Impact
- API: `Error::what()` now returns message-only (behavioral change for callers relying on trace in what())
- Behavioral: `what()` conforms to std::exception; TLS removed from error.h
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- Error propagation (design-record 0004)

Design elements this commit produces:
- `Error::FullMessage()` as the explicit full-message accessor

## Usage Examples
```cpp
try { /* ... */ } catch (const Error& e) {
    std::cerr << e.what();         // message only (safe, no-throw)
    std::cerr << e.FullMessage();  // full trace + kind (NEW)
}
```
