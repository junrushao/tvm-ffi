# Fix missing pthread and dl link dependencies for libtvm_ffi

## TL;DR
- Adds `find_package(Threads REQUIRED)` and links `Threads::Threads` to both `tvm_ffi_shared` (PRIVATE) and `tvm_ffi_static` (INTERFACE), fixing implicit pthread dependency from `std::mutex` usage in `backtrace.cc`.
- Conditionally links `${CMAKE_DL_LIBS}` (i.e., `-ldl`) when `TVM_FFI_USE_EXTRA_CXX_API` is ON, fixing implicit dl dependency from `dlopen`/`dlsym` usage in `library_module_dynamic_lib.cc`.
- Fixes GitHub issue #344 (link failures on systems where these libraries are not implicitly linked).

## Key Exports
None -- build system change only.

## Impact
- API: none
- Behavioral: none -- fixes link-time failures, no runtime behavior change
- Flags/config: `find_package(Threads REQUIRED)` is now a hard requirement for the CMake build; `CMAKE_DL_LIBS` is linked conditionally on `TVM_FFI_USE_EXTRA_CXX_API`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system / DSOLibrary** ([0011-module-system.md](../designs/0011-module-system.md)): `DSOLibrary` uses `dlopen`/`dlsym`/`dlclose` in `src/ffi/extra/library_module_dynamic_lib.cc`, requiring `-ldl` at link time. The conditional guard (`TVM_FFI_USE_EXTRA_CXX_API`) correctly scopes this to the extra API feature flag that gates `library_module_dynamic_lib.cc` compilation.
- **Backtrace / std::mutex**: `src/ffi/backtrace.cc` uses `std::mutex`, requiring pthread on Linux. This is a core runtime dependency, not optional.
- **CMake build targets**: `tvm_ffi_shared` (PRIVATE linkage for shared lib) and `tvm_ffi_static` (INTERFACE linkage so consumers inherit the dependency).

Design elements this commit produces: none -- purely fixes implicit dependencies.
