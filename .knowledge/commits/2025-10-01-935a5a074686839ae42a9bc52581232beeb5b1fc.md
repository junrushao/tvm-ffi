# Stabilize doc and metadata ABI for functions: rename type_schema to metadata, add GetFunctionDoc to ModuleObj
## TL;DR
- Renames `type_schema` to `metadata` in `TVMFFIFieldInfo` and `TVMFFIMethodInfo` C ABI structs, clarifying the field's purpose as structured JSON metadata (not just type schema).
- Adds `ModuleObj::GetFunctionDoc` virtual method (and `query_imports` overload) alongside existing `GetFunctionMetadata`, separating unstructured docstrings from structured metadata.
- Registers `ffi.ModuleGetFunctionDoc` as a new global function for cross-language access to function docstrings.

**Rename mapping:**

| Location | Old name | New name |
|----------|----------|----------|
| `TVMFFIFieldInfo` (c_api.h) | `type_schema` | `metadata` |
| `TVMFFIMethodInfo` (c_api.h) | `type_schema` | `metadata` |
| Cython `TVMFFIFieldInfo` (base.pxi) | `type_schema` | `metadata` |
| Cython `TVMFFIMethodInfo` (base.pxi) | `type_schema` | `metadata` |
| `GlobalFunctionTable::Entry` (function.cc) | `type_schema_data` | `metadata_data` |
| `GlobalDef` init (registry.h) | `info.type_schema` | `info.metadata` |
| `ObjectDef` init (registry.h) | `info.type_schema` | `info.metadata` |
| `TypeTable` field copy (object.cc) | `field_data.type_schema` | `field_data.metadata` |
| `TypeTable` method copy (object.cc) | `method_data.type_schema` | `method_data.metadata` |

## Key Exports

**Renamed struct fields (C ABI)**:
```c
// TVMFFIFieldInfo — was: TVMFFIByteArray type_schema
TVMFFIByteArray metadata;  // structured metadata in JSON string

// TVMFFIMethodInfo — was: TVMFFIByteArray type_schema
TVMFFIByteArray metadata;  // optional structured metadata in JSON string
```

**New virtual method on `ModuleObj`**:
```cpp
// Default returns std::nullopt; subclasses can override to provide docstrings
virtual Optional<String> GetFunctionDoc(const String& name);
```

**New non-virtual method on `ModuleObj`** (walks import tree):
```cpp
Optional<String> GetFunctionDoc(const String& name, bool query_imports);
```

**New registered global function**:
| Name | Signature | Description |
|------|-----------|-------------|
| `ffi.ModuleGetFunctionDoc` | `(Module, String, bool) -> Optional<String>` | Get function docstring, optionally querying imports |

## Impact
- API: **Breaking C ABI change**. `TVMFFIFieldInfo.type_schema` and `TVMFFIMethodInfo.type_schema` renamed to `metadata`. All downstream language bindings (Cython, Rust) that read these struct fields must update. The Cython binding is updated in this commit. Rust bindings may need a follow-up.
- API: **Breaking C++ ABI change**. `ModuleObj` gains a new virtual method `GetFunctionDoc`, changing vtable layout. Existing `ModuleObj` subclasses compile fine (default returns nullopt) but binary compatibility is broken.
- Behavioral: `GetFunctionDoc(name, query_imports)` walks the import tree the same way `GetFunctionMetadata(name, query_imports)` does — checks self first, then iterates `imports_` recursively.
- Flags/config: none
- Data formats/schemas: The `metadata` field now explicitly stores "structured JSON about extra information", while `doc` stores "unstructured docstring". This separation is a design principle stated in the inline rationale comment.

Design elements this commit produces:
- **Rename**: `type_schema` -> `metadata` across `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, and all C++/Cython code referencing them. Clarifies purpose as general structured metadata, not strictly type schema.
- **New protocol**: `ModuleObj::GetFunctionDoc` — virtual method for per-function docstring retrieval, default returns nullopt. Subclasses (e.g., `LibraryModuleObj`) can override to provide docstrings.
- **New global function**: `ffi.ModuleGetFunctionDoc` — cross-language accessor for function docstrings.
- **Design principle** (inline rationale): Docstrings (unstructured, potentially large) are separated from metadata (structured JSON, compact). This applies to both `TVMFFIMethodInfo` (which has `doc` + `metadata`) and `ModuleObj` (which has `GetFunctionDoc` + `GetFunctionMetadata`).

## Usage Examples

**Querying function docstrings from a module (C++)**:
```cpp
Module mod = Module::LoadFromFile("my_kernels.so");

// Query docstring for a specific function
Optional<String> doc = mod->GetFunctionDoc("my_kernel");
if (doc.defined()) {
  std::cout << "Docstring: " << doc.value() << std::endl;
}

// Query with import walk
Optional<String> doc2 = mod->GetFunctionDoc("helper_func", /*query_imports=*/true);
```

**Cross-language access (Python)**:
```python
get_doc = tvm_ffi.get_global_func("ffi.ModuleGetFunctionDoc")
doc = get_doc(mod, "my_kernel", False)
```
