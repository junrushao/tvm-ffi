# Rename type_schema to metadata in field/method info and add GetFunctionDoc to ModuleObj
## TL;DR
- Renames `type_schema` to `metadata` in `TVMFFIFieldInfo` and `TVMFFIMethodInfo` C ABI structs, and all C++/Cython code that references these fields. The new name better reflects that the field holds arbitrary structured JSON, not just type information.
- Adds `GetFunctionDoc` virtual method to `ModuleObj`, separating unstructured docstrings from structured metadata for module-exported functions. Rationale: docstrings can be large and unstructured, while metadata is focused structured JSON.
- The C++ ABI for `ModuleObj` changes (new virtual method), but Python users are unaffected since they access functions through the packed registry, not the C++ vtable.

### Rename Mapping

| Old Name | New Name | Locations |
|----------|----------|-----------|
| `TVMFFIFieldInfo.type_schema` | `TVMFFIFieldInfo.metadata` | `c_api.h`, `base.pxi`, `registry.h`, `object.cc` |
| `TVMFFIMethodInfo.type_schema` | `TVMFFIMethodInfo.metadata` | `c_api.h`, `base.pxi`, `registry.h`, `function.cc`, `object.cc` |
| `GlobalFunctionTable::Entry::type_schema_data` | `GlobalFunctionTable::Entry::metadata_data` | `function.cc` |

## Impact
- API: Breaking C++ ABI change — `TVMFFIFieldInfo.type_schema` and `TVMFFIMethodInfo.type_schema` renamed to `metadata`. Any C/C++ code accessing these struct fields by name must update. `ModuleObj` gains a new virtual method (`GetFunctionDoc`), shifting the vtable layout.
- Behavioral: None — `metadata` carries the same data as `type_schema` did; only the field name changes.
- Flags/config: None
- Data formats/schemas: The JSON content stored in the field is unchanged; only the field name in the struct definition changes.

## Usage Examples

Before/after for the rename:
```cpp
// Before (accessing field/method metadata):
TVMFFIFieldInfo info;
info.type_schema = TVMFFIByteArray{json_str, len};

// After:
TVMFFIFieldInfo info;
info.metadata = TVMFFIByteArray{json_str, len};
```

New `GetFunctionDoc` API:
```cpp
Module mod = Module::LoadFromFile("model.so");
// Query docstring (separate from metadata)
Optional<String> doc = mod->GetFunctionDoc("forward", /*query_imports=*/true);
// Query structured metadata (as before)
Optional<String> meta = mod->GetFunctionMetadata("forward", /*query_imports=*/true);
```
