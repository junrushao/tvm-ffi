# Stabilize doc and metadata ABI for functions by renaming type_schema to metadata

## TL;DR
- Renames `TVMFFIFieldInfo::type_schema` and `TVMFFIMethodInfo::type_schema` to `metadata` throughout C API, C++ implementation, and Cython bindings. The rationale is that `metadata` is more general-purpose (structured JSON), while `type_schema` was misleadingly narrow.
- Adds `ModuleObj::GetFunctionDoc(name) -> Optional<String>` virtual method separating docstrings from metadata, since docstrings can be large/unstructured while metadata is focused structured data.
- Adds `GetFunctionDoc(name, query_imports)` with import chain traversal.
- Registers `ffi.ModuleGetFunctionDoc` as a global function.

## Key Exports

**Struct field renames**:

| Old | New | Struct |
|-----|-----|--------|
| `TVMFFIFieldInfo::type_schema` | `TVMFFIFieldInfo::metadata` | `c_api.h` |
| `TVMFFIMethodInfo::type_schema` | `TVMFFIMethodInfo::metadata` | `c_api.h` |

**Methods added**:
- `ModuleObj::GetFunctionDoc(const String& name) -> Optional<String>` -- virtual, returns docstring for a function (default: `nullopt`)
- `ModuleObj::GetFunctionDoc(const String& name, bool query_imports) -> Optional<String>` -- traverses import chain

**Global functions registered**:
- `ffi.ModuleGetFunctionDoc(mod, name, query_imports) -> Optional<String>`

## Impact
- API: `type_schema` field renamed to `metadata` in `TVMFFIFieldInfo` and `TVMFFIMethodInfo`. New `GetFunctionDoc` virtual method on `ModuleObj`.
- ABI: **Breaking**. Field rename in C API structs.
- Behavioral: Doc and metadata are now separate concerns on `ModuleObj`.
- Flags/config: none
- Data formats/schemas: none
