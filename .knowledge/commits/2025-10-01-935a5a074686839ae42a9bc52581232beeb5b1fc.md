# Rename type_schema to metadata in TVMFFIFieldInfo/TVMFFIMethodInfo; add GetFunctionDoc to ModuleObj

## TL;DR
- Renames the `type_schema` field to `metadata` in both `TVMFFIFieldInfo` and `TVMFFIMethodInfo` C ABI structs, reflecting a semantic broadening from "type schema" to "structured JSON metadata."
- Adds `ModuleObj::GetFunctionDoc(name)` virtual method and its `query_imports` overload, separating unstructured docstrings from structured metadata in the module function API.
- Updates all consumers: `GlobalFunctionTable::Entry` (`function.cc`), `TypeTable` (`object.cc`), `ObjectDef`/`GlobalDef` (`registry.h`), and Cython declarations (`base.pxi`).

### Rename mapping

| Location | Old name | New name |
|----------|----------|----------|
| `c_api.h` `TVMFFIFieldInfo` | `type_schema` | `metadata` |
| `c_api.h` `TVMFFIMethodInfo` | `type_schema` | `metadata` |
| `base.pxi` `TVMFFIFieldInfo` | `type_schema` | `metadata` |
| `base.pxi` `TVMFFIMethodInfo` | `type_schema` | `metadata` |
| `registry.h` `GlobalDef::def_` | `info.type_schema` | `info.metadata` |
| `registry.h` `ObjectDef::def_ro/def_rw` | `info.type_schema` | `info.metadata` |
| `registry.h` `ObjectDef::def_/def_static` | `info.type_schema` | `info.metadata` |
| `function.cc` `Entry` | `type_schema_data` | `metadata_data` |
| `function.cc` `SyncMethodInfo` | `this->type_schema` | `this->metadata` |
| `object.cc` field registration | `field_data.type_schema` | `field_data.metadata` |
| `object.cc` method registration | `method_data.type_schema` | `method_data.metadata` |

class TVMFFIFieldInfo:
    """Reflection metadata for a single object field."""
    name: TVMFFIByteArray
    doc: TVMFFIByteArray
    metadata: TVMFFIByteArray          # RENAMED from type_schema. Structured JSON metadata.
    # ... (remaining fields unchanged: flags, size, alignment, offset, getter, setter, default_value)
    # Interacts with: TVMFFITypeRegisterField, ObjectDef<T>, TypeTable

class TVMFFIMethodInfo:
    """Reflection metadata for a registered method."""
    name: TVMFFIByteArray
    doc: TVMFFIByteArray
    # Rationale: doc stores unstructured docstrings (potentially large);
    # metadata stores structured JSON (focused, machine-readable).
    metadata: TVMFFIByteArray          # RENAMED from type_schema. Optional structured JSON.
    flags: int64
    method: TVMFFIAny
    # Interacts with: TVMFFITypeRegisterMethod, TVMFFIFunctionSetGlobalFromMethodInfo

# === New virtual method on ModuleObj ===

class ModuleObj(Object):
    def GetFunctionDoc(self, name: str) -> Optional[str]:
        """Get the docstring of a named function, if available. Default: None."""
        # Interacts with: GetFunctionMetadata (parallel API — doc is unstructured, metadata is structured)
        # Extension: override in subclass to provide function-level docstrings

    def GetFunctionDoc(self, name: str, query_imports: bool) -> Optional[str]:
        """Overload: searches self then imports_ if query_imports=True."""
        # Interacts with: imports_ (child modules), same traversal pattern as GetFunctionMetadata

# Registered FFI method:
# "ffi.ModuleGetFunctionDoc" -> lambda mod, name, query_imports: mod.GetFunctionDoc(name, query_imports)
# Interacts with: Module ObjectDef registration block in module.cc

## Impact
- API: **Breaking C++ ABI change** to `TVMFFIFieldInfo.type_schema` -> `metadata` and `TVMFFIMethodInfo.type_schema` -> `metadata`. All C/C++ code accessing these struct fields must update. The commit message notes this changes `ModuleObj` C++ ABI but remains Python ABI-compatible since Python accesses functions through the packed registry, not struct fields directly.
- Behavioral: `ModuleObj::GetFunctionDoc` is a new virtual with default returning `nullopt`, so existing `ModuleObj` subclasses are unaffected (non-breaking additive change).
- Flags/config: None.
- Data formats/schemas: The `metadata` field semantics are broadened from "type schema JSON" to "any structured JSON metadata." Existing type schema content remains valid metadata.

Design elements this commit produces:
- **Doc/metadata separation principle**: Establishes the convention that `doc` stores unstructured free-text docstrings while `metadata` stores structured JSON. This separation applies uniformly to fields (`TVMFFIFieldInfo`), methods (`TVMFFIMethodInfo`), and module functions (`GetFunctionDoc` vs `GetFunctionMetadata`).
- **ModuleObj::GetFunctionDoc** -- new virtual method with `query_imports` overload, following the same traversal pattern as `GetFunctionMetadata`.
- **"ffi.ModuleGetFunctionDoc"** -- new registered FFI method for cross-language doc retrieval.

## Usage Examples

```cpp
// Retrieving function doc from a Module (C++ side)
Module mod = Module::LoadFromFile("my_model.so");
// Get docstring separately from metadata
Optional<String> doc = mod->GetFunctionDoc("forward", /*query_imports=*/true);
Optional<String> meta = mod->GetFunctionMetadata("forward", /*query_imports=*/true);
// doc: unstructured human-readable text
// meta: structured JSON for tooling
```
