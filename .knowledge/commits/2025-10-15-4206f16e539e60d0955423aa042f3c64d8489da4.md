# Use heap-allocated singleton for TypeTable to prevent static destruction order issues
## TL;DR
- Changes `TypeTable::Global()` from a function-local static object to a heap-allocated (deliberately leaked) `new TypeTable()` pointer.
- Prevents potential use-after-free during program shutdown when other static destructors still reference the type table.

## Key Exports
None -- no public API changes. Internal implementation detail of `TypeTable::Global()`.

## Impact
- API: none
- Behavioral: TypeTable memory is no longer freed at program exit; OS reclaims it. This eliminates potential crashes from static destruction order fiasco when dynamically loaded modules or other statics reference type info during shutdown.
- Flags/config: none
- Data formats/schemas: none
