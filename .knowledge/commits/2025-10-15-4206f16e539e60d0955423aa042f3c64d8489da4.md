# Use heap-allocated singleton for TypeTable to prevent shutdown dealloc order issues

## TL;DR
- Changes `TypeTable::Global()` from a stack-allocated `static TypeTable inst` to a heap-allocated `static TypeTable* inst = new TypeTable()`, deliberately leaking the singleton so it outlives all other static destructors during program shutdown.
- Prevents potential crashes when shared-library unloading or static destructor ordering causes code to access the type table after it would have been destroyed.

## Key Exports

None -- no public API change. Internal singleton allocation strategy changed.

## Impact
- API: None
- Behavioral: None at runtime. Prevents potential use-after-destroy during program shutdown when static destruction order causes type table access after the old stack-local singleton would have been destroyed.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **TypeTable singleton** ([0002-object-system.md](../designs/0002-object-system.md)): The global type table is accessed via `TypeTable::Global()` by all type registration and `IsInstance` calls. This commit changes its lifetime strategy.

Design elements this commit produces:
- None -- no new design elements. The singleton pattern is changed from Meyers singleton (stack-allocated `static T`) to intentionally-leaked heap singleton (`static T* = new T()`).
