# Switch TypeTable::Global() from static-local to heap-allocated immortal singleton to prevent de-alloc order issues

## TL;DR
- `TypeTable::Global()` changed from `static TypeTable inst; return &inst;` to `static TypeTable* inst = new TypeTable(); return inst;` — the instance is now intentionally never freed.
- This prevents use-after-free or segfaults during program shutdown when other static/global destructors attempt to call into the type table after it would have been destroyed under the old LIFO destructor order.
- Memory is reclaimed by the OS at process exit rather than by the C++ runtime, which is the standard "immortal singleton" pattern for registries that must outlive all globals.

## Key Exports

```python
class TypeTable:
    """Internal global registry mapping type_key strings to type indices and TVMFFITypeInfo entries.
    Used by every GetOrAllocTypeIndex, IsInstance, and reflection registration call.
    """

    @staticmethod
    def Global() -> TypeTable*:
        # Old (before commit 4206f16):
        #   static TypeTable inst;
        #   return &inst;
        # → destroyed in LIFO order with other statics; could be destroyed before callers
        #
        # New (commit 4206f16):
        #   static TypeTable* inst = new TypeTable();
        #   return inst;
        # → lives forever on the heap; OS reclaims at process exit
        # Invariant: pointer is non-null after first call; never freed by C++ runtime
        # Interacts with: all TVMFFITypeGetOrAllocIndex, TVMFFIObjectGetTypeKey,
        #   TVMFFIObjectIsInstance, TVMFFITypeRegisterField/Method/Metadata/Attr C ABI calls
        ...
```

## Impact
- API: none — `TypeTable::Global()` is an internal C++ static helper; no public API change.
- Behavioral: the `TypeTable` singleton is now never destroyed by the C++ runtime. Shutdown-time calls (e.g., from DSO unloading or global-scope destructors that fire after `TypeTable`'s old static-local destructor) no longer risk a dangling pointer. Memory is leaked intentionally.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TypeTable internal singleton** (`src/ffi/object.cc`) — the process-wide type registry backing `GetOrAllocTypeIndex`, `TVMFFIGetTypeInfo`, `IsInstance`, and all reflection registration entry points. See `.knowledge/design-records/0002-object-system.md`.
- **C ABI registration entry points** (`TVMFFITypeGetOrAllocIndex`, `TVMFFIObjectGetTypeKey`, etc.) — all delegate to `TypeTable::Global()`. See `.knowledge/design-records/0001-c-abi.md`.

Design elements this commit produces:
- **Immortal-singleton pattern for TypeTable** — changes the lifetime model of `TypeTable::Global()`. Previously the static-local had standard LIFO destruction semantics; now it is explicitly heap-allocated and never freed. This is a tightening of the lifetime invariant: the type table is guaranteed to remain valid for the entire process lifetime, including during any global/static destructor that runs at shutdown.

## Usage Examples

Before (could silently crash or corrupt at shutdown):
```cpp
static TypeTable* Global() {
    static TypeTable inst;   // destroyed in LIFO order — may fire before callers
    return &inst;
}
```

After (immortal; safe for shutdown-time callers):
```cpp
static TypeTable* Global() {
    // deliberately create via raw new; memory recycled by OS at exit
    static TypeTable* inst = new TypeTable();
    return inst;
}
```

This follows the same pattern used for other critical singletons in TVM FFI (e.g., the global function registry). Any remaining `Global()` helpers in the codebase that use `static Foo inst; return &inst;` are candidates for the same treatment if they may be accessed during shutdown.
