# Use heap-allocated singleton for TypeTable to prevent static destruction order issues
## TL;DR
- Changes `TypeTable::Global()` from a function-local `static TypeTable inst` (stack-style) to `static TypeTable* inst = new TypeTable()` (intentional leak).
- Prevents undefined behavior when other static destructors access the type table during program shutdown.
- Aligns `TypeTable` with the same pattern already used by `GlobalFunctionTable`, `EnvCAPIRegistry`, `ContextSymbolRegistry`, `SystemLibSymbolRegistry`, and `SystemLibModuleRegistry`.

## Key Exports
None -- internal implementation change only. `TypeTable` is a private class in `src/ffi/object.cc`.

## Impact
- API: none
- ABI: none
- Behavioral: The `TypeTable` singleton now intentionally leaks its memory, which is reclaimed by the OS at process exit. This eliminates potential use-after-free during static destruction when other destructors (e.g., global `ObjectRef` instances) still query the type table.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Object system type hierarchy and `TypeTable` as the runtime type registry (.knowledge/designs/object-system.md)
- Memory management and object lifetime patterns (.knowledge/designs/memory.md)

Design elements this commit produces:
- Establishes that **all** global singleton registries in `src/ffi/` now use the intentional-leak `new` pattern for shutdown safety. The affected singletons are:
  - `TypeTable::Global()` in `src/ffi/object.cc` (this commit)
  - `GlobalFunctionTable::Global()` in `src/ffi/function.cc` (already used `new`)
  - `EnvCAPIRegistry::Global()` in `src/ffi/extra/env_c_api.cc` (already used `new`)
  - `ContextSymbolRegistry::Global()` in `src/ffi/extra/library_module.cc` (already used `new`)
  - `SystemLibSymbolRegistry::Global()` in `src/ffi/extra/library_module_system_lib.cc` (already used `new`)
  - `SystemLibModuleRegistry::Global()` in `src/ffi/extra/library_module_system_lib.cc` (already used `new`)
  - Exception: `EnvContext` in `src/ffi/extra/env_context.cc` uses `static thread_local` (appropriate for TLS).

## Usage Examples
None -- this is a purely internal fix with no API change.

Before (problematic):
```cpp
static TypeTable* Global() {
    static TypeTable inst;  // destroyed during static destruction
    return &inst;
}
```

After (safe):
```cpp
static TypeTable* Global() {
    // deliberately create a new instance via raw new
    // to ensure table lives longer in case unloading
    // still need the table info
    // memory will be recycled by the OS at program exit
    static TypeTable* inst = new TypeTable();
    return inst;
}
```
