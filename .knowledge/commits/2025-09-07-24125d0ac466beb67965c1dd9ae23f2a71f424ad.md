# Initial bringup of C++ API docs via Doxygen/Breathe/Exhale

## TL;DR
- Adds Sphinx-based C++ API documentation infrastructure using Doxygen + Breathe + Exhale, gated behind `BUILD_CPP_DOCS=1`.
- Adds Doxygen comments (`/*! \brief ... */`) to the vast majority of public classes, methods, constructors, and fields across all `include/tvm/ffi/` headers that previously had bare or missing doc comments.
- Makes two non-doc code changes: (1) changes `FObjectDeleter` signature from `void (*)(TVMFFIObject*, int)` to `void (*)(void*, int)`, and (2) moves `SimpleObjAllocator` and `ObjAllocatorBase` into `namespace details`.
- Wraps internal implementation details (type registration macros, `_type_index` constants, iterator helpers, `std::hash` specializations) in `/// \cond Doxygen_Suppress` blocks to hide them from generated API docs.

### Exhale/Doxygen Configuration

Key `exhale_args` in `conf.py`:
```python
exhale_args = {
    "containmentFolder": "reference/cpp/generated",
    "rootFileName": "index.rst",
    "doxygenStripFromPath": "../include",
    "rootFileTitle": "Full API Index",
    "createTreeView": True,
    "exhaleExecutesDoxygen": True,
    "exhaleDoxygenStdin": exhaleDoxygenStdin,  # INPUT=../include, PREDEFINED, EXCLUDE_SYMBOLS
}
```

`EXCLUDE_SYMBOLS` filters out `*details*`, `*TypeTraits*`, `std`, `*use_default_type_traits_v*`, `*is_optional_type_v*`, `*operator*` to keep the public API index clean.

## Concern 2: Doxygen Comment Additions

Adds `/*! \brief ... */` doc comments to previously undocumented or minimally documented members across 26 header files. The pattern is systematic:

- **Constructors/destructors**: Default, copy, move, conversion constructors all get `\brief` + `\param`.
- **Assignment operators**: Copy and move assignment get `\brief` + `\param`.
- **Static constexpr fields**: `_type_index`, `_type_key`, `_type_final`, `_type_mutable`, `_type_child_slots`, `_type_child_slots_can_overflow`, `_type_depth`, `_type_s_eq_hash_kind` all get Doxygen comments.
- **Free functions**: `StringToDLDataType`, `DLDataTypeToString`, `make_object`, `make_inplace_array_object` get full `\brief`/`\tparam`/`\param`/`\return` blocks.
- **Enums**: `AccessKind` values get per-enumerator doc comments.
- **Reflection classes**: `FieldGetter`, `FieldSetter`, `ObjectCreator`, `TypeAttrColumn`, `GlobalDef`, `ObjectDef`, `TypeAttrDef` get class-level and method-level doc comments.

Additionally wraps internal helpers in `/// \cond Doxygen_Suppress` / `/// \endcond` blocks:
- `TVM_FFI_REGISTER_STATIC_TYPE_INFO` macro
- `TVM_FFI_DISPATCH_MAP` macro
- `FunctionObj` internal `_type_index`/`SafeCall` members
- `ArrayObj` static fields and internal `CalcCapacityImpl`/`AgregateImpl`
- `MapObj::iterator`, `MapObj::KVRawStorageType`
- `ReflectionDefBase` (entire base class)
- `FallbackOnlyTraitsBase`, `ObjectRefWithFallbackTraitsBase` internals
- `std::hash<String>` specialization
- `base_details.h` (entire file)
- `optional.h` type traits (`is_optional_type_v`, `use_ptr_based_optional_v`)

## Concern 3: FObjectDeleter Signature Change and SimpleObjAllocator Namespace Move

### FObjectDeleter
**Before**: `typedef void (*FObjectDeleter)(TVMFFIObject* obj, int flags);`
**After**: `typedef void (*FObjectDeleter)(void* obj, int flags);`

The first parameter is widened from `TVMFFIObject*` to `void*`. The `TVMFFIObject.deleter` field in `c_api.h` is changed correspondingly from `void (*deleter)(struct TVMFFIObject* self, int flags)` to `void (*deleter)(void* self, int flags)`. All `SimpleObjAllocator` deleter implementations are updated to accept `void*` and cast via `static_cast<TVMFFIObject*>(objptr)` internally.

This is an **ABI-breaking change** at the C struct level -- the function pointer type in `TVMFFIObject` changes. However, since function pointers to `void*` and `TVMFFIObject*` have the same calling convention on all supported platforms, binary compatibility is likely preserved in practice.

The `TVMFFIObject` and `TVMFFIAny` struct definitions also drop their C tag names (from `typedef struct TVMFFIObject { ... } TVMFFIObject` to `typedef struct { ... } TVMFFIObject`), and `TVMFFITypeInfo` gets `#ifdef __cplusplus` guards to use `struct TVMFFITypeInfo { ... };` in C++ mode vs `typedef struct TVMFFITypeInfo { ... } TVMFFITypeInfo;` in C mode.

### SimpleObjAllocator Namespace Move
**Before**: `SimpleObjAllocator` and `ObjAllocatorBase` are in `tvm::ffi` namespace.
**After**: Both are moved into `tvm::ffi::details` namespace.

The public free functions `make_object` and `make_inplace_array_object` now call `details::SimpleObjAllocator()` instead of `SimpleObjAllocator()`. The public API is unchanged -- `make_object` remains in `tvm::ffi` (and `tvm::` via using-declaration).

## Key Exports

**Types/Classes**: None introduced. Existing classes gain Doxygen documentation but no API changes.

**Functions**: No new functions. `make_object<T>` and `make_inplace_array_object<A,E>` gain improved Doxygen comments but signatures are unchanged.

**Macros**: No new macros.

**Constants/Enums**: No changes.

**Renames**:

| Old | New | Notes |
|-----|-----|-------|
| `FObjectDeleter = void (*)(TVMFFIObject*, int)` | `FObjectDeleter = void (*)(void*, int)` | Parameter type widened |
| `tvm::ffi::SimpleObjAllocator` | `tvm::ffi::details::SimpleObjAllocator` | Moved to details namespace |
| `tvm::ffi::ObjAllocatorBase` | `tvm::ffi::details::ObjAllocatorBase` | Moved to details namespace |

## Impact
- API: `SimpleObjAllocator` and `ObjAllocatorBase` moved to `details` namespace. External code directly using these (unlikely, as they are implementation details) must update to `details::SimpleObjAllocator`. The public `make_object`/`make_inplace_array_object` functions are unaffected.
- ABI: `FObjectDeleter` parameter type changes from `TVMFFIObject*` to `void*`. The `TVMFFIObject::deleter` field pointer type changes correspondingly. Technically ABI-breaking at the type level, though binary-compatible on all supported platforms.
- Behavioral: No behavioral changes. Error messages in `ArrayObj::CopyFrom`/`MoveFrom` are capitalized ("Not enough capacity" vs "not enough capacity").
- Flags/config: New `BUILD_CPP_DOCS` environment variable gates C++ doc generation.
- Data formats/schemas: None.

## Design Elements

Design elements this commit **consumes**:

- **Object system** (`.knowledge/designs/object-system.md`): All `/// \cond Doxygen_Suppress` blocks wrap `_type_index`, `_type_key`, and `TVM_FFI_DECLARE_*_OBJECT_INFO` invocations -- the internal registration machinery of the object system.
- **Memory management** (`.knowledge/designs/memory.md`): `SimpleObjAllocator`, `ObjAllocatorBase`, `make_object`, `make_inplace_array_object` -- the allocator hierarchy and its deleter callbacks.
- **Reflection system** (`.knowledge/designs/reflection.md`): `GlobalDef`, `ObjectDef`, `TypeAttrDef`, `FieldGetter`, `FieldSetter`, `ObjectCreator` gain Doxygen comments.
- **Sphinx docs build** (`docs/conf.py`): Extends the existing Sphinx configuration with Breathe/Exhale/Doxygen integration.

Design elements this commit **produces**:

- **C++ API documentation infrastructure**: New Breathe + Exhale + Doxygen pipeline for auto-generating C++ API reference docs. Gated behind `BUILD_CPP_DOCS=1` to avoid slowing default doc builds. The pipeline reads `include/` headers, filters via `EXCLUDE_SYMBOLS`/`EXCLUDE_PATTERNS`, and generates RST into `docs/reference/cpp/generated/`.
- **Doxygen suppression convention**: Establishes the `/// \cond Doxygen_Suppress` / `/// \endcond` pattern for hiding internal implementation details from the public C++ API docs. Applied consistently to: type registration statics, macro implementations, internal iterators, hash specializations, and type trait internals.
- **`details` namespace boundary for allocators**: `SimpleObjAllocator` and `ObjAllocatorBase` are now in `tvm::ffi::details`, making the public/internal boundary explicit. Only `make_object` and `make_inplace_array_object` remain in `tvm::ffi` as the public allocation API.

## Usage Examples

### Building C++ docs
```bash
# From docs/ directory
BUILD_CPP_DOCS=1 make livehtml
```

### Doxygen suppress pattern (convention for future headers)
```cpp
class MyObj : public Object {
 public:
  /*! \brief A public field. */
  int32_t value;

  /// \cond Doxygen_Suppress
  static constexpr const char* _type_key = "my.Obj";
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(MyObj, Object);
  /// \endcond
};
```
