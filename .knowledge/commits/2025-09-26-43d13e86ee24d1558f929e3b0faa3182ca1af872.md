# Pack strong/weak ref counts into single uint64 combined_ref_count field
## TL;DR
- Merges `strong_ref_count` (uint32) and `weak_ref_count` (uint32) into a single `uint64 combined_ref_count` in `TVMFFIObject`, enabling single-atomic operations for the common deletion fast path.
- Strong count occupies the lower 32 bits, weak count occupies the upper 32 bits; `DecRef` now detects the common case (both counts == 1) with one atomic fetch-sub instead of two separate atomics.
- Cython bindings and docs updated to match the new layout.

## Key Exports

```python
# Constants in tvm::ffi::details namespace
kCombinedRefCountWeakOne: int = 1 << 32      # One weak ref
kCombinedRefCountStrongOne: int = 1           # One strong ref
kCombinedRefCountBothOne: int = (1 << 32) | 1 # Both counts at one
kCombinedRefCountMaskUInt32: int = 0xFFFFFFFF # Lower 32-bit mask

class TVMFFIObject:
    """24-byte object header (C ABI struct)."""
    combined_ref_count: uint64  # lower 32: strong, upper 32: weak
    # Interacts with: Object.IncRef(), Object.DecRef(), Object.IncWeakRef(), Object.DecWeakRef()
    # Invariant: strong_ref_count = combined_ref_count & 0xFFFFFFFF
    # Invariant: weak_ref_count = (combined_ref_count >> 32) & 0xFFFFFFFF
    type_index: int32
    __padding: uint32
    deleter: Callable[[TVMFFIObject, int], None]

class Object:
    def use_count(self) -> uint64: ...
    # Was int32, now uint64 (masked to lower 32 bits)
    # Interacts with: combined_ref_count via atomic load + mask
```

## Impact
- API: `Object.use_count()` return type changed from `int32_t` to `uint64_t` (C++ only, minor).
- Behavioral: Deletion fast path now uses one atomic instead of two for the common case (both counts go to zero simultaneously).
- Flags/config: None
- Data formats/schemas: `TVMFFIObject` ABI change: `{uint32 strong_ref_count, uint32 weak_ref_count}` replaced by `{uint64 combined_ref_count}`. Binary layout is identical on little-endian systems.
