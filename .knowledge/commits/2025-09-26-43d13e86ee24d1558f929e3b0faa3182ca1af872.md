# Pack strong+weak ref counts into single u64 atomic for faster DecRef
## TL;DR
- Replaces the two separate fields `uint32_t strong_ref_count` + `uint32_t weak_ref_count` in `TVMFFIObject` with a single `uint64_t combined_ref_count` where the lower 32 bits store the strong count and the upper 32 bits store the weak count.
- All atomic refcount operations (`IncRef`, `DecRef`, `IncWeakRef`, `DecWeakRef`, `TryPromoteWeakPtr`, `use_count`) are rewritten to operate on the combined u64 field, eliminating a separate atomic read of the weak counter during the common `DecRef` fast path.
- This is the completion of a two-commit sequence: commit `13436f0` rearranged the two u32 fields to be adjacent and packable; this commit merges them into a single atomic u64.

## Key Exports

**Constants** (new, in `namespace tvm::ffi::details`):
```cpp
constexpr uint64_t kCombinedRefCountWeakOne   = static_cast<uint64_t>(1) << 32;  // one weak ref
constexpr uint64_t kCombinedRefCountStrongOne = 1;                                // one strong ref
constexpr uint64_t kCombinedRefCountBothOne   = kCombinedRefCountWeakOne | kCombinedRefCountStrongOne;
constexpr uint64_t kCombinedRefCountMaskUInt32 = (static_cast<uint64_t>(1) << 32) - 1;  // lower-32 mask
```

**Struct change** (`TVMFFIObject` in `c_api.h`):
```c
// Before:
typedef struct {
  uint32_t strong_ref_count;
  uint32_t weak_ref_count;
  int32_t type_index;
  ...
} TVMFFIObject;

// After:
typedef struct {
  uint64_t combined_ref_count;  // strong = lower 32, weak = upper 32
  int32_t type_index;
  uint32_t __padding;
  ...
} TVMFFIObject;
```

**Changed signatures**:
- `Object::use_count() const` return type widened from `int32_t` to `uint64_t` (still returns only the strong count via masking).

**Cython binding update** (`base.pxi`):
- `TVMFFIObject` struct now declares `uint64_t combined_ref_count` instead of two `uint32_t` fields.
- `__padding` type corrected from `int32_t` to `uint32_t`.

## Impact
- API: `TVMFFIObject` struct layout changes (ABI break from prior version). `Object::use_count()` return type widened from `int32_t` to `uint64_t`. Callers reading `strong_ref_count` or `weak_ref_count` directly must use the combined field with masking.
- Behavioral: `DecRef` fast path now requires only one atomic decrement + one comparison (was: atomic decrement + separate atomic load of weak counter). The common case `combined == kCombinedRefCountBothOne` triggers a single-call deleter with `kBoth`.
- Flags/config: none
- Data formats/schemas: Version bumped from `0.1.0b7` to `0.1.0b8` in `pyproject.toml`.

## Design Elements
Design elements this commit consumes:
- **TVMFFIObject header layout** ([0001-c-abi-layer](../designs/0001-c-abi-layer.md)) -- modifies the struct field layout
- **Two-counter refcount system** ([0003-object-system](../designs/0003-object-system.md)) -- the strong/weak counting invariants are preserved but the implementation mechanism changes
- **Bitmask-dispatched deleter** ([0015-weak-rc-abi-design](../ADRs/0015-weak-rc-abi-design.md)) -- the `kStrong`/`kWeak`/`kBoth` flag dispatch is unchanged

Design elements this commit produces:
- **Combined ref count layout**: Strong in lower 32 bits, weak in upper 32 bits of a single `uint64_t`. This is a new internal representation convention with four associated constants (`kCombinedRefCountStrongOne`, `kCombinedRefCountWeakOne`, `kCombinedRefCountBothOne`, `kCombinedRefCountMaskUInt32`).
- **Single-atomic DecRef fast path**: `DecRef` performs one `fetch_sub(kCombinedRefCountStrongOne)` and compares the pre-decrement value against `kCombinedRefCountBothOne` to detect the common case (both counters about to reach zero) without a separate atomic read.

## Usage Examples
**Before** (two separate atomics in DecRef):
```cpp
// Old: two atomic operations on the common deletion path
if (__atomic_fetch_sub(&header_.strong_ref_count, 1, __ATOMIC_RELEASE) == 1) {
  if (__atomic_load_n(&header_.weak_ref_count, __ATOMIC_RELAXED) == 1) {
    // common case: both zero
    header_.deleter(&header_, kBoth);
  } else { /* slow path */ }
}
```

**After** (single atomic tells the whole story):
```cpp
// New: one atomic tells us both strong and weak state
uint64_t count_before = __atomic_fetch_sub(
    &header_.combined_ref_count, kCombinedRefCountStrongOne, __ATOMIC_RELEASE);
if (count_before == kCombinedRefCountBothOne) {
  // fast path: both counters reach zero in one shot
  header_.deleter(&header_, kBoth);
} else if ((count_before & kCombinedRefCountMaskUInt32) == kCombinedRefCountStrongOne) {
  // strong hits zero but weak refs remain
  header_.deleter(&header_, kStrong);
  // then decrement weak portion...
}
```
