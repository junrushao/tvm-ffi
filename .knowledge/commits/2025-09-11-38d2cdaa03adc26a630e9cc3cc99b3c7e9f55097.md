# Refactor Python FFI call mechanism with C++ type-dispatched argument setter for performance
## TL;DR
- Replaces the monolithic `make_args` / `FuncCall` / `FuncCall3` Cython argument-packing pipeline with a C++-based type-dispatched call manager (`TVMFFIPyCallManager` in new file `tvm_ffi_python_helpers.h`), where per-Python-type `TVMFFIPyArgSetter` function pointers are cached in a thread-local `unordered_map<PyTypeObject*, TVMFFIPyArgSetter>` so repeat calls with the same argument types skip the `isinstance`-chain dispatch entirely.
- Introduces a `DLPackPyObjectCExporter` C function-pointer protocol (`__dlpack_c_exporter__` Python attribute) for zero-Python-overhead DLPack tensor conversion, bypassing the Python `__dlpack__` protocol and PyCapsule machinery. A reference implementation is provided for `DLTensorTestWrapper`.
- Adds a cached `DLManagedTensorVersioned` field to `TensorObj` (with atomic CAS for thread safety) so `ToDLPackVersioned()` avoids repeated heap allocation when the same tensor is exported multiple times -- the deleter no longer frees the struct; it only decrements the `TensorObj` ref count.

## Impact
- API: **Internal restructuring** of the Cython call path. The public Python API (`Function.__call__`, `FieldSetter.__call__`, `tvm_ffi_callback`) is unchanged. The C++ helper header `tvm_ffi_python_helpers.h` introduces new internal C-style types (`TVMFFIPyCallContext`, `TVMFFIPyArgSetter`, `TVMFFIPyArgSetterFactory`, `TVMFFIPyCallManager`) that are consumed only by the Cython `.pxi` files. Not a public ABI addition.
- API: New optional Python protocol `__dlpack_c_exporter__`: a Python integer attribute holding a C function pointer for direct tensor export. Not yet documented publicly; exercised only by `DLTensorTestWrapper`.
- API: `TensorObj::ToDLPackVersioned()` now returns a cached `DLManagedTensorVersioned*` owned by `TensorObj` (deleter renamed to `EmbeddedDLManagedTensorVersionedDeleter` and no longer `delete`s the struct). Consumers that called `delete` on the returned pointer externally would now double-free. The standard DLPack consumer protocol (calling the `deleter` function pointer) is unaffected since the embedded deleter only calls `DecRef`.
- API: `testing.nop` global function changed from returning `args[0]` to a true no-op (returns nothing). This is a minor semantic change to the test utility, making benchmarks measure pure call overhead.
- Flags/config: `CMakeLists.txt` adds `target_include_directories(tvm_ffi_cython PRIVATE .../python/tvm_ffi/cython)` so that `#include "tvm_ffi_python_helpers.h"` resolves for the Cython extension build.
- Data formats/schemas: None.

## Design Elements
Design elements this commit **consumes**:

- **Python bindings / Cython argument packing** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The entire `make_args` function and the `FuncCall` / `FuncCall3` call paths are replaced. The argument type priority order is preserved in the new `TVMFFIPyArgSetterFactory_` (Cython function), which is the factory callback responsible for creating setters. The order is: `None` > `Tensor` > `Object` > `ObjectRValueRef` > `__dlpack_c_exporter__` > `torch.Tensor` > `__dlpack__` > `bool` > `Integral` > `Real` > `_CLASS_DTYPE` > `_CLASS_DEVICE` > `str` > `bytes`/`bytearray` > `ctypes.c_void_p` > `callable` > `Exception` > fallback. Notably, `PyNativeObject` handling moved from a dedicated priority slot into three different setters (`TVMFFIPyArgSetterStr_`, `TVMFFIPyArgSetterBytes_`, `TVMFFIPyArgSetterFallback_`), since `PyNativeObject` is always a subclass of `str`, `bytes`, or some other type.
- **C ABI layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The `TVMFFIFunctionCall`, `TVMFFIEnvSetCurrentStream`, `TVMFFIAnyViewToOwnedAny`, `TVMFFIObjectIncRef`, `TVMFFIObjectDecRef`, `TVMFFITensorFromDLPack`, `TVMFFITensorFromDLPackVersioned`, `TVMFFITensorToDLPackVersioned` C API functions are used by the new helpers. `TVMFFIObjectIncRef` is newly exposed in `base.pxi` (though it existed in `c_api.h`).
- **Function system** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): The packed calling convention `(const AnyView* args, int32_t num_args, Any* rv)` is preserved. The new `TVMFFIPyCallManager::Call` method performs the `TVMFFIFunctionCall` invocation with GIL release/re-acquire (`Py_BEGIN_ALLOW_THREADS` / `Py_END_ALLOW_THREADS`), mirroring the old `with nogil` block.
- **Thread-local stream context** ([`.knowledge/ADRs/0020-thread-local-stream-context.md`](../ADRs/0020-thread-local-stream-context.md)): The stream context save/restore pattern (`TVMFFIEnvSetCurrentStream` before call, restore after) is preserved in `TVMFFIPyCallManager::Call`, moved from Cython to C++.
- **`__tvm_ffi_env_stream__` protocol** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The protocol is preserved in `TVMFFIPyArgSetterDLPack_`, which checks for `__tvm_ffi_env_stream__` on non-CPU DLPack objects.

Design elements this commit **produces**:

- **`TVMFFIPyCallManager` / type-dispatched setter architecture** (new, not documented): A C++-based call manager that caches `TVMFFIPyArgSetter` function pointers per `PyTypeObject*` in a thread-local `unordered_map`. On subsequent calls, argument dispatch is O(1) hash-lookup rather than O(n) `isinstance`-chain. The architecture separates three concerns: (1) `TVMFFIPyArgSetterFactory` (Cython callback) handles one-time type classification, (2) `TVMFFIPyArgSetter` (C function pointer) handles per-argument conversion, (3) `TVMFFIPyCallManager` orchestrates stack allocation, GIL management, stream context, and temporary object lifetime. This is a **core performance optimization** for the Python FFI hot path.
- **`TVMFFIPyCallManager::CallStack` RAII** (new): Thread-local pre-allocated stack (`temp_stack_`, default 32 `TVMFFIAny` entries) for packed arguments and temporary object tracking. Falls back to heap for large argument lists. RAII destructor handles cleanup of temporary FFI objects (via `obj->deleter`) and temporary Python objects (via `Py_DecRef`). This replaces the old `temp_args` Python list, eliminating Python list allocation on every FFI call.
- **`DLPackPyObjectCExporter` / `__dlpack_c_exporter__` protocol** (new): A C function pointer type `int (*)(void* py_obj, DLManagedTensorVersioned** out, void** env_stream)` that enables direct C-level tensor export without going through Python's `__dlpack__` protocol and PyCapsule. The Python-side exposes the function pointer as an integer attribute `__dlpack_c_exporter__`. `TVMFFIPyArgSetterDLPackCExporter_` invokes this pointer and calls `TVMFFITensorFromDLPackVersioned` to create the FFI tensor, entirely avoiding Python object creation in the hot path.
- **Cached `DLManagedTensorVersioned` in `TensorObj`** (new): `TensorObj` gains a `mutable std::atomic<DLManagedTensorVersioned*> cached_dl_managed_tensor_versioned_` field. `ToDLPackVersioned()` uses atomic CAS (`compare_exchange_strong` with `release`/`acquire` ordering) to lazily initialize this cache. The destructor `~TensorObj()` acquires and deletes the cached struct. The deleter function (`EmbeddedDLManagedTensorVersionedDeleter`) no longer calls `delete` on the struct -- it only calls `DecRefObjectHandle`. This optimization avoids heap allocation on repeated DLPack exports of the same tensor.
- **`_torch_dlpack_c_exporter_ptr` hook** (new): A module-level Python variable in `function.pxi` that, when set to a non-`None` integer, routes `torch.Tensor` arguments through the `TVMFFIPyArgSetterDLPackCExporter_` fast path instead of the Python-level `torch.utils.dlpack.to_dlpack` path. This is a hook for future integration with a native torch DLPack C exporter extension (like `torch_c_dlpack_ext`).

## Key Implementations

### C++ Call Manager (`tvm_ffi_python_helpers.h`)

The new file (`python/tvm_ffi/cython/tvm_ffi_python_helpers.h`, 447 lines) is the central performance optimization. Key architectural decisions:

1. **Thread-local dispatch map**: `std::unordered_map<PyTypeObject*, TVMFFIPyArgSetter> dispatch_map_` is per-thread, avoiding any locking overhead. The first call with a new argument type invokes the factory (`TVMFFIPyArgSetterFactory_`, a Cython callback); subsequent calls with the same type bypass the factory entirely.

2. **Pre-allocated temp stack**: `TVMFFIPyCallManager::CallStack` inherits from `TVMFFIPyCallContext` and allocates `num_args * 2` `TVMFFIAny` slots: the first `num_args` for packed arguments, the second half reinterpreted as `void**` arrays for temporary FFI and Python object tracking. Falls back to heap (`new TVMFFIAny[requested_count]`) when the thread-local stack is exhausted.

3. **Temporary object lifetime**: Instead of a Python `list` for `temp_args`, the C++ layer tracks temporaries in two arrays: `temp_ffi_objects` (cleaned up by calling `obj->deleter(obj, kTVMFFIObjectDeleterFlagBitMaskBoth)`) and `temp_py_objects` (cleaned up by `Py_DecRef`). This avoids Python list creation/append overhead on every FFI call.

4. **GIL release in C++**: The `TVMFFIPyCallManager::Call` method releases the GIL via `Py_BEGIN_ALLOW_THREADS` / `Py_END_ALLOW_THREADS` around the `TVMFFIFunctionCall` invocation, matching the old Cython `with nogil` behavior.

5. **Predefined C++ setters for POD types**: `TVMFFIPyArgSetterFloat_`, `TVMFFIPyArgSetterInt_`, `TVMFFIPyArgSetterBool_`, `TVMFFIPyArgSetterNone_` are defined as `noexcept` C++ functions using direct CPython API calls (`PyFloat_AsDouble`, `PyLong_AsLongLongAndOverflow`, etc.), avoiding Cython overhead for the most common argument types.

**Invariant**: The `TVMFFIPyArgSetterFactory` callback must produce a setter that is correct for all instances of the given `PyTypeObject*`, not just the specific instance passed. This is a type-level caching invariant: the setter must be a function of the type, not the value. This holds for all the setters defined in this commit since they dispatch on type identity, not value.

**Extension point**: New Python types that need special handling can be supported by adding a branch in `TVMFFIPyArgSetterFactory_`. The dispatch map is automatically extended on first encounter.

**Failure mode**: If a type has subtypes with different FFI semantics (e.g., `str` subclass `DType` needs different handling from plain `str`), the factory must return the correct setter for the specific subtype. The current factory handles this by checking `_CLASS_DTYPE` before `str`, ensuring the `DType` subtype gets `TVMFFIPyArgSetterDType_` and is never cached as plain `str`.

### Cached DLManagedTensorVersioned in TensorObj (`tensor.h`)

The `ToDLPackVersioned()` method now implements lock-free lazy initialization:

```
cached = cached_.load(acquire);
if (cached == nullptr) {
    DLManagedTensorVersioned* ret = new ...;
    if (CAS(&cached_, nullptr, ret, release, acquire)) {
        cached = ret;  // we won the race
    } else {
        delete ret;
        cached = expected;  // another thread won
    }
}
IncRef(from);  // each caller still gets its own ref-counted handle
return cached;
```

**Invariant**: The cached struct is owned by `TensorObj` and freed in `~TensorObj()`. The embedded deleter (`EmbeddedDLManagedTensorVersionedDeleter`) only decrements the `TensorObj` ref count without freeing the struct. This means the `DLManagedTensorVersioned*` returned by `ToDLPackVersioned()` is valid as long as the `TensorObj` is alive (which it is, since each export increments the ref count).

**Thread safety**: Atomic CAS with `memory_order_release` on success (ensures the fully constructed struct is visible) and `memory_order_acquire` on failure/load (ensures the other thread's writes are visible). The `~TensorObj` destructor uses `memory_order_acquire` on the load.

### Refactored Cython Setters (`function.pxi`)

The old monolithic `make_args` is replaced by ~20 individual setter functions (`TVMFFIPyArgSetterTensor_`, `TVMFFIPyArgSetterObject_`, `TVMFFIPyArgSetterDLPackCExporter_`, `TVMFFIPyArgSetterTorch_`, `TVMFFIPyArgSetterDLPack_`, `TVMFFIPyArgSetterDType_`, `TVMFFIPyArgSetterDevice_`, `TVMFFIPyArgSetterStr_`, `TVMFFIPyArgSetterBytes_`, `TVMFFIPyArgSetterCtypesVoidPtr_`, `TVMFFIPyArgSetterObjectRValueRef_`, `TVMFFIPyArgSetterCallable_`, `TVMFFIPyArgSetterException_`, `TVMFFIPyArgSetterFallback_`), plus a factory function `TVMFFIPyArgSetterFactory_`.

Each setter has the signature `int (*)(TVMFFIPyArgSetter* handle, TVMFFIPyCallContext* ctx, PyObject* arg, TVMFFIAny* out) except -1` and is responsible for a single conversion path. Temporary objects are tracked via `TVMFFIPyPushTempFFIObject(ctx, ...)` and `TVMFFIPyPushTempPyObject(ctx, ...)` instead of the old `temp_args.append(arg)`.

The call sites (`Function.__call__`, `ConstructorCall`, `FieldSetter.__call__`, `tvm_ffi_callback`) now delegate to `TVMFFIPyFuncCall`, `TVMFFIPyCallFieldSetter`, or `TVMFFIPyPyObjectToFFIAny` respectively, each of which is a thin C++ inline function that instantiates `TVMFFIPyCallManager::CallStack` and invokes the dispatch loop.

### `_from_dlpack_universal` refactor (`tensor.pxi`)

The `from_dlpack` public function was split: the core logic moved into `_from_dlpack_universal` (Cython `cdef inline` taking `TVMFFIObjectHandle*` out-parameter), and `from_dlpack` becomes a thin wrapper. This enables the setter `TVMFFIPyArgSetterDLPack_` to call `_from_dlpack_universal` directly without constructing a Python `Tensor` object, keeping the conversion in C-land.

Similarly, `_from_dlpack_intptr` was added to accept a raw `void*` DLPack pointer.

### ADRs to write

- **`.knowledge/ADRs/0033-type-dispatched-arg-setter.md`**: Record the decision to move from a Cython `isinstance`-chain (`make_args`) to a C++ type-dispatched call manager.
  - Decision context: The old `make_args` function performed an O(n) `isinstance` chain per argument on every FFI call. For hot paths (e.g., repeated calls with the same argument types), this was measurable overhead.
  - Alternatives considered: (1) Cython-level caching with a Python `dict[type, callable]` -- would still incur Python dict lookup and Python function call overhead. (2) Pure C++ argument packing -- would lose access to Python type checking. (3) Typed function wrappers -- would require per-signature specialization, explosion of wrappers.
  - Trade-offs: The chosen approach requires a C++ header included in the Cython build (new build dependency), moves critical logic from readable Cython to harder-to-debug C++, and requires the type-level caching invariant (setter correctness for all instances of a `PyTypeObject*`) to hold for all current and future types.

- **`.knowledge/ADRs/0034-dlpack-c-exporter-protocol.md`**: Record the decision to introduce `__dlpack_c_exporter__` as a C-level bypass of the Python `__dlpack__` protocol.
  - Decision context: The Python `__dlpack__` protocol involves PyCapsule creation, Python method dispatch, and capsule destruction -- significant overhead for high-frequency tensor passing.
  - Alternatives considered: (1) Optimize PyCapsule path -- limited by CPython overhead. (2) Caching the tensor conversion result -- stale if tensor data changes. (3) C-level DLPack protocol in dlpack.h -- would require upstream dlpack spec changes.
  - Trade-offs: `__dlpack_c_exporter__` is a non-standard extension that only TVM FFI recognizes. It bypasses the standard DLPack protocol, so correctness depends on the exporter correctly managing the `DLManagedTensorVersioned` lifetime. The protocol uses a raw function pointer cast to integer, which is fragile.
