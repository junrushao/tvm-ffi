# Refactor Python FFI call mechanism to use C++ type-dispatch for argument packing
## TL;DR
- Replaces the monolithic `make_args` isinstance-chain and `FuncCall`/`FuncCall3` in Cython with a C++-based type-dispatch system (`TVMFFIPyCallManager` + `TVMFFIPyArgSetter` functors) that caches a setter per Python type in a thread-local `unordered_map`, eliminating repeated isinstance checks on hot paths.
- Introduces `tvm_ffi_python_helpers.h`, a new C++ header compiled into the Cython module, providing `TVMFFIPyCallManager` (thread-local call stack manager), `TVMFFIPyCallContext` (per-call state), and `TVMFFIPyArgSetter` (type-dispatched argument conversion functors).
- Adds a `__dlpack_c_exporter__` C-level protocol for zero-overhead DLPack tensor export, bypassing Python-level `__dlpack__` calls, and caches `DLManagedTensorVersioned` in `TensorObj` with atomic CAS for thread-safe reuse.

## Key Exports

**Types/Classes**:

- `TVMFFIPyCallContext` (C struct, `tvm_ffi_python_helpers.h`): Per-call state holding `packed_args`, `device_type`, `device_id`, `stream`, `temp_ffi_objects[]`, `temp_py_objects[]`.
- `TVMFFIPyArgSetter` (C struct, `tvm_ffi_python_helpers.h`): Dispatch functor with `int (*func)(TVMFFIPyArgSetter*, TVMFFIPyCallContext*, PyObject*, TVMFFIAny*)` and optional `DLPackPyObjectCExporter dlpack_c_exporter`.
- `TVMFFIPyCallManager` (C++ class, `tvm_ffi_python_helpers.h`): Thread-local manager with `Call()`, `SetField()`, `PyObjectToFFIAny()`. Contains `CallStack` RAII helper for stack/heap argument allocation.
- `DLPackPyObjectCExporter` (typedef, `tvm_ffi_python_helpers.h`): `int (*)(void* py_obj, DLManagedTensorVersioned** out, void** env_stream)` -- C function pointer for zero-copy tensor export.

**Functions** (C++ free functions in `tvm_ffi_python_helpers.h`):

- `TVMFFIPyFuncCall(setter_factory, func_handle, py_arg_tuple, result, c_api_ret_code) -> int` -- Main entry point for FFI function calls from Python.
- `TVMFFIPyCallFieldSetter(setter_factory, field_setter, field_ptr, py_arg, c_api_ret_code) -> int` -- Entry point for field setter calls.
- `TVMFFIPyPyObjectToFFIAny(setter_factory, py_arg, out, c_api_ret_code) -> int` -- Convert a single Python object to owned `TVMFFIAny`.
- `TVMFFIPyGetDispatchMapSize() -> size_t` -- Debug: returns thread-local dispatch table size.
- `TVMFFIPyPushTempFFIObject(ctx, handle)` -- Push temp FFI object for post-call cleanup.
- `TVMFFIPyPushTempPyObject(ctx, pyobj)` -- Push temp Python object for post-call Py_DecRef.

**Predefined C++ setters** (in `tvm_ffi_python_helpers.h`):

- `TVMFFIPyArgSetterFloat_`, `TVMFFIPyArgSetterInt_`, `TVMFFIPyArgSetterBool_`, `TVMFFIPyArgSetterNone_` -- POD type setters called directly from dispatch table.

**Cython setters** (in `function.pxi`):

- `TVMFFIPyArgSetterTensor_`, `TVMFFIPyArgSetterObject_`, `TVMFFIPyArgSetterDLPackCExporter_`, `TVMFFIPyArgSetterTorch_`, `TVMFFIPyArgSetterDLPack_`, `TVMFFIPyArgSetterDType_`, `TVMFFIPyArgSetterDevice_`, `TVMFFIPyArgSetterStr_`, `TVMFFIPyArgSetterBytes_`, `TVMFFIPyArgSetterCtypesVoidPtr_`, `TVMFFIPyArgSetterObjectRValueRef_`, `TVMFFIPyArgSetterCallable_`, `TVMFFIPyArgSetterException_`, `TVMFFIPyArgSetterFallback_`

**Cython factory** (in `function.pxi`):

- `TVMFFIPyArgSetterFactory_(PyObject* value, TVMFFIPyArgSetter* out) -> int` -- Creates and returns the appropriate setter for a given Python type. The setter is then cached by `TVMFFIPyCallManager.SetArgument()`.

**Protocols**:

- `__dlpack_c_exporter__` (Python attribute): Returns an `int` (pointer cast) to a `DLPackPyObjectCExporter` function. When present on a Python type, the factory installs `TVMFFIPyArgSetterDLPackCExporter_` which calls the C function directly, bypassing Python-level DLPack protocol.

**C++ changes to `TensorObj`** (`include/tvm/ffi/container/tensor.h`):

- New field: `mutable std::atomic<DLManagedTensorVersioned*> cached_dl_managed_tensor_versioned_` -- atomically cached DLPack versioned export.
- `ToDLPackVersioned()` now returns cached `DLManagedTensorVersioned*` via atomic CAS, avoiding repeated allocation.
- `~TensorObj()` destructor added to delete the cached `DLManagedTensorVersioned`.
- `DLManagedTensorVersionedDeleter` renamed to `EmbeddedDLManagedTensorVersionedDeleter` -- no longer deletes the `DLManagedTensorVersioned` struct (it is owned by TensorObj).

## Impact
- API: None. The Python-level calling interface (`Function.__call__`, `FieldSetter.__call__`) is unchanged. The new `__dlpack_c_exporter__` protocol is opt-in and only affects external tensor types that implement it.
- ABI: None. The changes are in the Cython extension module and a private C++ header compiled into it. `TensorObj` gains a new field (`cached_dl_managed_tensor_versioned_`) which changes its memory layout, but `TensorObj` is not part of the stable C ABI (it is a C++ class).
- Behavioral: (1) Argument packing now uses cached type dispatch instead of per-call isinstance chains -- same semantics, lower overhead. (2) `ToDLPackVersioned()` now returns a cached struct that is NOT deleted by the DLPack consumer's deleter call -- the consumer only decrements the refcount. The struct is deleted when the `TensorObj` is destroyed. This is safe because the struct's `dl_tensor` fields point into the `TensorObj` which is kept alive by the refcount. (3) `testing.nop` changed from returning `args[0]` to returning nothing.
- Flags/config: `CMakeLists.txt` adds `python/tvm_ffi/cython/` to include path for `tvm_ffi_cython` target.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python binding value marshaling** (`.knowledge/designs/0014-python-bindings.md`, `make_args` / `make_ret`) -- the old isinstance-chain dispatch is replaced.
- **Packed calling convention** (`.knowledge/designs/function-system.md`) -- `TVMFFIFunctionCall` is still the underlying C API call.
- **C ABI types** (`.knowledge/designs/c-abi.md`) -- `TVMFFIAny`, `TVMFFIObject`, `TVMFFIFieldSetter` are used throughout.
- **DLPack tensor import** (`.knowledge/designs/0014-python-bindings.md`, tensor.pxi) -- `from_dlpack` / `_from_dlpack_universal` consume DLPack protocol.
- **CUDA stream context** (`.knowledge/designs/0014-python-bindings.md`, CUDA Stream Context section) -- stream capture logic is preserved in the new setters.
- **Cython binding layer** (`.knowledge/ADRs/012-cython-binding-layer.md`) -- the decision to use Cython is extended: POD setters are now in C++ while complex setters remain in Cython.

Design elements this commit produces:
- **C++ type-dispatch argument packing** -- `TVMFFIPyCallManager` + `TVMFFIPyArgSetter` functor pattern. Thread-local dispatch table keyed by `PyTypeObject*`, caching the appropriate setter per type. First call for a given type invokes the factory; subsequent calls skip the isinstance chain entirely.
- **CallStack RAII allocator** -- `TVMFFIPyCallManager::CallStack` manages per-call argument memory. Uses a thread-local stack (`temp_stack_`) for typical call depths; spills to heap for large argument counts. Recycles temp objects (FFI and Python) on destruction.
- **`__dlpack_c_exporter__` protocol** -- New Python dunder-like protocol for C-level DLPack export. Objects implementing this attribute provide a `DLPackPyObjectCExporter` function pointer that converts the object to `DLManagedTensorVersioned*` without going through Python `__dlpack__`.
- **Cached `DLManagedTensorVersioned` in TensorObj** -- Atomic CAS-based caching of the versioned DLPack struct inside `TensorObj`. The cached struct's deleter (`EmbeddedDLManagedTensorVersionedDeleter`) only decrements the TensorObj refcount, not deleting the struct itself.

## Usage Examples

### Type-dispatch argument packing (internal, C++)
**Context**: How the new call path works end-to-end when Python calls an FFI function.
```
# Python: func(tensor, 42, "hello")
# Internally:
# 1. TVMFFIPyFuncCall called with setter_factory=TVMFFIPyArgSetterFactory_
# 2. CallManager.Call() allocates CallStack for 3 args
# 3. For each arg, SetArgument() looks up PyTypeObject* in dispatch_map_
#    - First call: factory creates setter (e.g. TVMFFIPyArgSetterTensor_ for Tensor)
#    - Cached: direct setter call, no isinstance chain
# 4. GIL released, TVMFFIFunctionCall invoked
# 5. GIL reacquired, CallStack destructor recycles temp objects
```

### `__dlpack_c_exporter__` protocol
**Context**: How an external tensor type opts into zero-overhead C-level DLPack export.
```python
class MyTensor:
    # Provide a C function pointer as an int for zero-overhead export
    __dlpack_c_exporter__ = my_c_exporter_func_ptr  # int(void*)

    # The C function signature:
    # int my_exporter(void* py_obj, DLManagedTensorVersioned** out, void** env_stream)
    # - Casts py_obj back to PyObject*, extracts tensor data
    # - Fills *out with DLManagedTensorVersioned
    # - Optionally fills *env_stream with current device stream
    # - Returns 0 on success, -1 on failure

# When MyTensor is passed to an FFI function, the factory detects
# __dlpack_c_exporter__ and installs TVMFFIPyArgSetterDLPackCExporter_
# which calls the C function directly -- no Python __dlpack__ overhead.
```

### Cached DLPack versioned export (C++)
**Context**: `TensorObj::ToDLPackVersioned()` now caches the result.
```cpp
// First call: allocates DLManagedTensorVersioned, caches via atomic CAS
DLManagedTensorVersioned* v1 = tensor->ToDLPackVersioned();
// Second call: returns cached pointer, only increments refcount
DLManagedTensorVersioned* v2 = tensor->ToDLPackVersioned();
// v1 == v2 (same pointer)
// Consumer calls deleter: only decrements refcount, does NOT free the struct
// Struct is freed when TensorObj is destroyed (~TensorObj)
```
