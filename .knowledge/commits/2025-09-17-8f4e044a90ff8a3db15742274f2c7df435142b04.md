# Enable ruff ANN rule and add type annotations to all Python public APIs
## TL;DR
- Enables the `ANN` (flake8-annotations) rule in `pyproject.toml` `[tool.ruff.lint]`, requiring return type and parameter type annotations on all Python public functions.
- Adds `-> ReturnType` and parameter `: Type` annotations to every unannotated public function/method across 37 files (library, tests, examples, docs, lint scripts).
- Fixes a minor context manager protocol bug: `StreamContext.__enter__` and `TorchStreamContext.__enter__` now correctly `return self` instead of returning `None`.

## Key Exports

No new public APIs are introduced. The commit adds type annotations to existing APIs without changing their runtime behavior (except the `__enter__` fix). Representative signature changes:

## Impact
- API: No new APIs. All existing function signatures gain type annotations (additive, non-breaking). The `StreamContext.__enter__` and `TorchStreamContext.__enter__` return-type fix is technically a behavioral change but brings them into compliance with the standard Python context manager protocol.
- Behavioral: `StreamContext.__enter__` and `TorchStreamContext.__enter__` now return `self`, enabling the `with ... as ctx:` pattern. Previously they returned `None`.
- Flags/config: `ANN` rule enabled in `pyproject.toml` ruff config. All future Python code in the repo must include type annotations on public functions.
- Data formats/schemas: None.

## Usage Examples
The `__enter__` fix enables correct use of the `as` clause in context managers:

```python
# Before this commit, `ctx` would be None:
with use_raw_stream(device, stream) as ctx:
    assert ctx is not None  # would fail before this commit

# After this commit, `ctx` is the StreamContext instance:
with use_raw_stream(device, stream) as ctx:
    print(ctx.device_type, ctx.device_id)  # works correctly
```
