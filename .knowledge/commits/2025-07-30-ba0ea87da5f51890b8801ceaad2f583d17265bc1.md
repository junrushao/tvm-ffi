# Improve string equal/hash handling with memequal and aligned StableHashBytes

## TL;DR
- Introduces `Bytes::memequal()` for equality-only string comparisons, replacing `Bytes::memncmp() == 0` in equality paths. `memequal` short-circuits on length mismatch and delegates to `std::memcmp` instead of a byte-by-byte loop.
- Optimizes `details::StableHashBytes()` in `base_details.h` to use direct `uint64_t` loads when the data pointer is 8-byte aligned (little-endian case), avoiding the byte-by-byte union fill.
- Inlines `Bytes::memncmp()` (moved from a standalone definition after the namespace close into the class body) and adds a specialized `String::compare(const char*)` overload that avoids calling `strlen` by scanning the `const char*` inline.
- Updates `operator==` overloads for `String` vs `String`, `String` vs `std::string` to use `Bytes::memequal` instead of `compare() == 0`.
- Adds two new test cases: `String::Compare` (validates `compare(const char*)` and `compare(String)`) and `String::BytesHash` (validates aligned vs unaligned hash consistency).

## Key Exports

**New static method:**
- `Bytes::memequal(const char* lhs, const char* rhs, size_t lhs_count, size_t rhs_count) -> bool` (`include/tvm/ffi/string.h`) -- Equality-specialized comparison: returns `lhs_count == rhs_count && (lhs == rhs || std::memcmp(lhs, rhs, lhs_count) == 0)`. Faster than `memncmp() == 0` because it short-circuits on length mismatch and uses `std::memcmp` (which is typically hardware-optimized) instead of a byte-by-byte loop.

**Changed methods:**
- `Bytes::memncmp()` -- Moved from a standalone inline definition below the namespace close into the `Bytes` class body. Signature and behavior are unchanged.
- `String::compare(const char* other)` -- Reimplemented to scan `other` inline character-by-character, detecting null terminator during comparison rather than calling `strlen` first. This avoids a redundant full scan of `other`.

**Changed internal function:**
- `details::StableHashBytes(const char* data, size_t size) -> uint64_t` (`include/tvm/ffi/base_details.h`) -- Now checks pointer alignment: if data is 8-byte aligned and the platform is little-endian (`TVM_FFI_IO_NO_ENDIAN_SWAP`), loads `uint64_t` values directly via `*reinterpret_cast<const uint64_t*>(it)` instead of filling the union byte-by-byte. The unaligned and endian-swap paths are preserved. The `result = ...` accumulation line, previously shared after the if/else, is now inside each branch.

## Impact
- API: New `Bytes::memequal` static method is public. `Bytes::memncmp` remains available with identical behavior. `String::compare(const char*)` has the same observable behavior but different implementation.
- ABI: No change. All modified code is in headers; no C ABI symbols are affected.
- Behavioral: `operator==` for `String` vs `String` and `String` vs `std::string` is faster (no three-way compare needed). `StableHashBytes` is faster for aligned data on little-endian platforms. Hash values are unchanged (same algorithm, same constants).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`AnyEqual` functor** (`include/tvm/ffi/any.h`): Uses `Bytes::memncmp` (now switched to `Bytes::memequal`) for string/bytes equality in `Any`-keyed containers. Documented in `.knowledge/designs/any-system.md` (line 111).
- **`BytesObjBase`** (`include/tvm/ffi/string.h`): The common base for `StringObj` and `BytesObj` that exposes `data` and `size` fields. Documented in `.knowledge/designs/containers.md` (line 41).
- **`StableHashBytes`** (`include/tvm/ffi/base_details.h`): FNV-1-like stable hash used by `AnyHash` and structural hashing.

Design elements this commit produces:
- **`Bytes::memequal` static method** -- Equality-specialized string comparison that short-circuits on length mismatch and delegates to `std::memcmp`. Used by `AnyEqual` and `String` equality operators.
- **Aligned fast-path in `StableHashBytes`** -- Direct `uint64_t` load optimization for 8-byte-aligned data on little-endian platforms.

## Usage Examples
```cpp
// Using memequal for equality checks (internal to operator== overloads)
bool eq = Bytes::memequal(s1.data(), s2.data(), s1.size(), s2.size());

// Using memncmp for ordering (unchanged)
int cmp = Bytes::memncmp(s1.data(), s2.data(), s1.size(), s2.size());
```
