# Optimize string equality and hash performance in FFI string types

## TL;DR
- Adds `Bytes::memequal` static helper (size-check first, then `std::memcmp`) and rewires `String ==` operators and `AnyEqual` to use it, avoiding the custom byte-by-byte loop for equality.
- Optimizes `StableHashBytes` by dispatching to an aligned load path (`*reinterpret_cast<const uint64_t*>(it)`) when the pointer is 8-byte aligned, avoiding byte-by-byte assembly in the common case.
- Fixes a latent correctness bug in `StableHashBytes`: the `result = (result * kMultiplier + u.b) % kMod` accumulation was outside the endian-swap loop body, meaning only the last chunk contributed to the hash when endian-swap was needed.

## Impact
- API: `Bytes::memequal` is a new public static method on `Bytes`. Additive only.
- Behavioral: `String ==` operators and `AnyEqual` string branch now use `std::memcmp`-based equality (same semantics, faster). `StableHashBytes` now produces the same hash value for all inputs as before (correctness fix: endian-swap path was previously computing wrong hashes).
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `String` and `Bytes` container types (`0006-ffi-containers.md`) — uses `BytesObjBase` data pointer/size fields via `AnyUnsafe::CopyFromAnyViewAfterCheck`.
- `AnyEqual` from `any.h` — equality predicate used by `Dict`/`Map` key comparison (documented in `0002-ffi-any-value-system.md` under `AnyHash` and `AnyEqual`).
- `StableHashBytes` from `base_details.h` — the polynomial hash foundation for `StringHash` and `AnyHash`.

Design elements this commit produces:
- `Bytes::memequal` — new static API for content-equality of byte arrays; now the canonical equality primitive for string types in this layer.
- Aligned fast-path in `StableHashBytes` — new optimization branch; a new invariant: aligned and unaligned inputs with identical content hash identically.

## Usage Examples

**Before/after — equality operator:**
```cpp
// BEFORE: routed through String::compare(), which reads size() and calls memncmp byte-by-byte
bool eq = (s1 == s2);   // String::compare(rhs)==0

// AFTER: size check first, then std::memcmp (avoids compare overhead for differing-length strings)
bool eq = (s1 == s2);   // Bytes::memequal(s1.data(), s2.data(), s1.size(), s2.size())
```

**Before/after — hash aligned fast-path:**
```cpp
// BEFORE: always byte-by-byte assembly even when pointer is 8-byte aligned
// AFTER: aligned data takes fast-path via direct uint64_t* load
std::vector<int64_t> data(10);  // naturally 8-byte aligned
StableHashBytes(reinterpret_cast<char*>(data.data()), 80);  // now uses load path

// Invariant: aligned and unaligned representations of the same bytes hash equally
// (new BytesHash test verifies this by comparing hash of aligned vs unaligned buffer)
```
