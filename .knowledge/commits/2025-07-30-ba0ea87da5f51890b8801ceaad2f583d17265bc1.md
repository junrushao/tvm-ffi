# Optimize string equality checks and hash computation for Bytes/String
## TL;DR
- Adds `Bytes::memequal` for fast equality checks using `std::memcmp`, replacing the slower `memncmp(...) == 0` pattern in `AnyEqual` and `operator==` overloads.
- Optimizes `StableHashBytes` by using direct aligned 8-byte loads when the data pointer is 8-byte aligned, avoiding byte-by-byte copy into the union.
- Inlines `Bytes::memncmp` into the class declaration and rewrites `String::compare(const char*)` to avoid `strlen` overhead.

## Impact
- API: `Bytes::memequal` is a new public static method. `Bytes::memncmp` moved from out-of-class definition to inline in-class definition (no signature change). No breaking changes.
- Behavioral: `String::compare(const char*)` no longer calls `strlen`, so it avoids a full scan of the C-string upfront. Same semantic result. `operator==` overloads for String now use `memequal` (size check + `memcmp`) instead of `compare() == 0` (character-by-character loop), which is faster for inequality cases (early size mismatch exit) and for equality cases (`memcmp` is SIMD-optimized on most platforms).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `AnyEqual` struct in `any.h` -- the string-aware equality functor for `Any` values, used by `Map` for key comparison. Documented in design record `0001-any-anyview-value-system`.
- `BytesObjBase` layout (`data`, `size` fields) -- the common base for String/Bytes object storage. Documented in design record `0006-containers`.
- `StableHashBytes` in `base_details.h` -- the stable cross-platform hash function for byte sequences. Referenced by `AnyHash`.
- `TVM_FFI_IO_NO_ENDIAN_SWAP` compile-time constant -- controls endian-aware byte loading in hash computation.

Design elements this commit produces:
- `Bytes::memequal` -- new static method providing a fast equality-only path that avoids the three-way comparison overhead of `memncmp`. This is now the canonical equality check used by `AnyEqual` and all `String operator==` overloads.

## Usage Examples
From the test additions in this commit (`tests/cpp/test_string.cc`):

**String::compare with const char* (no strlen overhead)**:
```cpp
String s{"hello"};
EXPECT_EQ(s.compare("hello"), 0);       // equal
EXPECT_EQ(s.compare("hallo"), 1);       // 'e' > 'a'
EXPECT_EQ(s.compare("hell"), 1);        // s longer
EXPECT_EQ(s.compare("hello world"), -1); // s shorter
```

**StableHashBytes aligned vs unaligned consistency**:
```cpp
std::vector<int64_t> data1(10);
std::vector<int64_t> data2(11);
// ... fill data1 with 0..9
char* aligned_ptr = reinterpret_cast<char*>(data1.data());        // 8-byte aligned
char* unaligned_ptr = reinterpret_cast<char*>(data2.data()) + 1;  // misaligned
std::memcpy(unaligned_ptr, data1.data(), data1.size() * sizeof(int64_t));
// Both paths must produce the same hash
uint64_t hash1 = details::StableHashBytes(aligned_ptr, data1.size() * sizeof(int64_t));
uint64_t hash2 = details::StableHashBytes(unaligned_ptr, data1.size() * sizeof(int64_t));
EXPECT_EQ(hash1, hash2);
```
