# Add clang-tidy job to PR CI to prevent post-merge failures on main

## TL;DR
- clang-tidy previously ran only on the `main` branch (`ci_mainline_only.yml`), allowing PRs to pass CI but fail after merge
- Added a `clang-tidy` job to `ci_test.yml` (the PR CI workflow) so violations are caught before merge
- The new job is change-set-scoped: a new `prepare` step detects modified C++ files and the `clang-tidy` job is skipped entirely when no C++ files changed

N/A — infrastructure

## Impact
- API: none
- Behavioral: clang-tidy now runs on PRs for changed C++ files (`.c`, `.cc`, `.cpp`, `.cxx`); previously it ran only post-merge on the full `./src/ ./include ./tests` tree
- Flags/config: new `prepare` outputs `cpp_changed` (bool) and `cpp_files` (space-delimited list) drive the conditional job; `ci_mainline_only.yml` retains its own clang-tidy job unchanged (runs on full tree after merge)
- Data formats/schemas: none
