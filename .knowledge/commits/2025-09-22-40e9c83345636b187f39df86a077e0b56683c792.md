# Enable mypy type checking across Python package, tests, and examples
## TL;DR
- Adds mypy v1.17.0 as four separate pre-commit hooks covering `python/`, `tests/`, and three example directories, with `--python-version=3.9` and `--show-error-codes`.
- Adds `[tool.mypy]` config to `pyproject.toml` with `allow_redefinition = true` and `ignore_missing_imports = true`.
- Fixes ~36 files of type annotation issues to pass mypy: replaces `Optional[X]` with `X | None` (via `from __future__ import annotations`), adds explicit type annotations to variables, uses `# type: ignore[...]` for dynamic FFI attributes, restructures optional imports (`torch`, `numpy`) for mypy compatibility, adds a new `_ffi_api.pyi` stub file, and refactors several functions to avoid mypy-incompatible patterns.

## Key Exports

**New file: `python/tvm_ffi/_ffi_api.pyi`** -- Hand-written mypy stub for the `_ffi_api` module (populated by `init_ffi_api` at runtime). Declares 23 functions with `(*args: Any) -> Any` signatures:
```python
def ModuleGetKind(*args: Any) -> Any: ...
def Array(*args: Any) -> Any: ...
def Map(*args: Any) -> Any: ...
def Shape(*args: Any) -> Any: ...
# ... (23 total)
```

**Updated: `python/tvm_ffi/core.pyi`** -- Key signature changes:
- `__init_handle_by_constructor__` and `__init_tvm_ffi_object_by_constructor__`: `fconstructor` parameter type changed from `Function` to `Any` (avoids circular import / forward reference issues with mypy).
- `_env_set_current_stream`: return type and `stream` param now explicitly `int | c_void_p`.
- Added: `_convert_torch_dtype_to_ffi_dtype`, `_convert_numpy_dtype_to_ffi_dtype`, `_CLASS_TENSOR`, `_set_class_tensor`.

**Updated: `python/tvm_ffi/registry.py`** -- `get_global_func` now has `@overload` signatures for `allow_missing: Literal[True]` and `Literal[False]`, enabling callers to get precise return types:
```python
@overload
def get_global_func(name: str, allow_missing: Literal[True]) -> core.Function | None: ...
@overload
def get_global_func(name: str, allow_missing: Literal[False] = False) -> core.Function: ...
```

**Updated: `python/tvm_ffi/registry.py`** -- `register_object` return type narrowed from `Any` to `Callable[[type], type] | type`; internal closure restructured to avoid mypy's inability to narrow captured variables.

**Updated: `python/tvm_ffi/dataclasses/field.py`** -- `Field` class no longer uses `@dataclass(kw_only=True)`. Converted to manual `__init__` + `__slots__` to avoid mypy's issues with `kw_only` dataclasses on Python 3.9.

**Updated: `python/tvm_ffi/dataclasses/c_class.py`** -- `dataclass_transform` import order changed: tries `typing_extensions` first, then `typing`, with a bare `except ImportError: pass` fallback. This ensures compatibility with both old and new Python versions under mypy.

**Updated: `python/tvm_ffi/cython/type_info.pxi`** -- Replaced `X | None` union syntax with `Optional[X]` because Cython `.pxi` files do not support `from __future__ import annotations` and therefore cannot use PEP 604 union syntax.

**Updated: `python/tvm_ffi/utils/lockfile.py`** -- `FileLock.acquire()` return type corrected from `Optional[bool]` to `bool`; `__exit__` return type narrowed from `bool` to `Literal[False]`.

## Impact
- API: `get_global_func` now has `@overload` signatures that provide better type narrowing for callers using `allow_missing=True` vs `allow_missing=False`. No runtime behavior change.
- Behavioral: `_find_cuda_home()` in `load_inline.py` now raises `RuntimeError` instead of returning `""` when CUDA is not found on Windows -- a minor behavioral tightening.
- Flags/config: New `[tool.mypy]` section in `pyproject.toml` with `allow_redefinition = true` (permits re-assigning variables to different types) and `ignore_missing_imports = true` (suppresses errors for untyped third-party packages).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **CI and lint pipeline** ([`.knowledge/designs/0016-ci-and-lint-pipeline.md`](../designs/0016-ci-and-lint-pipeline.md)): Extends the pre-commit hook chain by adding mypy hooks. The design doc's extension points section already listed mypy as a planned addition.
- **Python package** ([`.knowledge/designs/0014-python-package.md`](../designs/0014-python-package.md)): The FFI-backed object pattern (dynamic `_ffi_api` module, `__ffi_init__`, dynamic method/field attachment via reflection) drives most of the `# type: ignore[attr-defined]` annotations and the new `.pyi` stub file.
- **Reflection system** ([`.knowledge/designs/0009-reflection.md`](../designs/0009-reflection.md)): The `_add_class_attrs` function in `registry.py` attaches methods dynamically, which is inherently opaque to static type checkers. The workaround is `# type: ignore[attr-defined]` at call sites.

Design elements this commit produces:
- **mypy pre-commit hooks**: Four hooks in `.pre-commit-config.yaml` covering `python/`, `tests/`, `examples/inline_module`, `examples/packaging`, `examples/quick_start`. Each excludes `_ffi_api.py` files (populated at runtime), targets Python 3.9, and depends on `numpy`, `ml-dtypes`, `pytest`, `typing-extensions`.
- **`_ffi_api.pyi` stub pattern**: A hand-written `.pyi` stub file that declares the runtime-populated `_ffi_api` module's exports, enabling mypy to resolve attribute access. This pattern will need replication for downstream packages that use `init_ffi_api`.
- **mypy config**: `[tool.mypy]` in `pyproject.toml` with `allow_redefinition` and `ignore_missing_imports`.
- **Optional import pattern for mypy**: The pattern `torch: ModuleType | None = None; try: import torch except ImportError: pass` replaces the prior `try: import torch except ImportError: torch = None` to satisfy mypy's type narrowing (the variable must be pre-declared with its union type).

## Usage Examples

**Optional import pattern for mypy compatibility**:
```python
# Before (mypy cannot narrow torch type):
try:
    import torch
except ImportError:
    torch = None

# After (mypy sees torch as ModuleType | None):
from types import ModuleType
torch: ModuleType | None = None
try:
    import torch  # type: ignore[no-redef]
except ImportError:
    pass
```

**`@overload` for `get_global_func`**:
```python
# With allow_missing=False (default), mypy knows result is non-None:
f: tvm_ffi.Function = tvm_ffi.get_global_func("testing.echo")

# With allow_missing=True, mypy knows result may be None:
f_or_none: tvm_ffi.Function | None = tvm_ffi.get_global_func("testing.echo", allow_missing=True)
```
