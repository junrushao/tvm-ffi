# Enable mypy type checking for Python codebase and examples
## TL;DR
- Adds mypy as a pre-commit hook covering `python/`, `tests/`, and three `examples/` directories, with `--python-version=3.9` and `ignore_missing_imports = true`.
- Creates a new `_ffi_api.pyi` stub file declaring all 23 FFI API functions used by the Python package.
- Fixes ~120 type annotation issues across 36 files: adds `from __future__ import annotations`, replaces `Optional[X]`/`Union[X, Y]` with `X | Y`, adds `# type: ignore` suppressions for dynamic FFI attributes, tightens return types, and refactors several functions for mypy compatibility.

## Impact
- API: `register_object` return type narrowed from `Any` to `Callable[[type], type] | type`. `get_global_func` now has `@overload` signatures enabling precise return type narrowing based on `allow_missing`. `_find_cuda_home` now raises `RuntimeError` instead of returning empty string. These are all backward-compatible at runtime but may surface new mypy errors in downstream code.
- Behavioral: `_find_cuda_home` raises on Windows when CUDA not found instead of returning `""`. `register_object(None)` now returns a decorator (was previously calling `__name__` on `None`, which would crash). `_add_class_attrs` attribute assignment order changed for static methods (doc/name set before `staticmethod` wrapping).
- Flags/config: New `[tool.mypy]` section in `pyproject.toml` with `allow_redefinition = true` and `ignore_missing_imports = true`. Four new mypy pre-commit hooks targeting different directory scopes.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python bindings registry** (`0012-python-bindings.md`): `register_object`, `register_global_func`, `get_global_func`, `init_ffi_api` -- all receive type annotation improvements.
- **Reflection system** (`0008-reflection.md`): `TypeField`, `TypeMethod`, `TypeInfo` from `type_info.pxi` -- annotation syntax changed for Cython compatibility.
- **Module system** (`0011-module-system.md`): `load_inline`, `load_module`, `Module` -- type annotations tightened.
- **Stream context** (`0014-stream-and-env-context.md`): `use_torch_stream`, `StreamContext`, `_env_set_current_stream` -- return types updated.
- **Dataclass/c_class decorator** (`0008-reflection.md`): `c_class`, `Field`, `field` -- Field class refactored from dataclass to plain class for mypy compatibility.

Design elements this commit produces:
- **`_ffi_api.pyi` stub pattern**: A new `.pyi` stub file that declares the dynamic FFI API surface, enabling mypy to check calls to `_ffi_api.*` without runtime introspection. This is a new convention for bridging dynamic FFI modules with static type checking.
- **`# type: ignore[attr-defined]` convention for FFI methods**: Establishes the pattern that methods populated by the C++ reflection system at runtime (e.g., `self._root()`, `self._path_equal()`) should be suppressed with `# type: ignore[attr-defined]`.

## Usage Examples

The commit's primary artifact is the mypy pre-commit configuration. Usage:

```yaml
# .pre-commit-config.yaml -- mypy hook for python/ and tests/
- repo: https://github.com/pre-commit/mirrors-mypy
  rev: "v1.17.0"
  hooks:
    - id: mypy
      name: mypy for `python/` and `tests/`
      additional_dependencies: ['numpy >= 1.22', "ml-dtypes >= 0.1", "pytest", "typing-extensions>=4.5"]
      args: [--show-error-codes, --python-version=3.9]
      exclude: ^.*/_ffi_api\.py$   # exclude the runtime-populated module
      files: ^(python/|tests/).*\.py$
```

Pattern for handling optional imports under mypy:

```python
# Before (mypy error: "name 'torch' possibly undefined"):
try:
    import torch
except ImportError:
    torch = None

# After:
from types import ModuleType
torch: ModuleType | None = None
try:
    import torch  # type: ignore[no-redef]
except ImportError:
    pass
```
