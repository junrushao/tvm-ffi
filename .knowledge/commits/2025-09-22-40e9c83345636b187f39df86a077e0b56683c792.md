# Enable mypy type checking across Python sources, tests, and examples

## TL;DR
- Adds `mypy` (v1.17.0) as a pre-commit hook via `pre-commit/mirrors-mypy`, configured with four separate hook entries covering `python/` + `tests/`, `examples/inline_module`, `examples/packaging`, and `examples/quick_start`. All hooks target `--python-version=3.9` and exclude auto-generated `_ffi_api.py` files.
- Adds `[tool.mypy]` configuration in `pyproject.toml` with `allow_redefinition = true` and `ignore_missing_imports = true`.
- Creates a new type stub file `python/tvm_ffi/_ffi_api.pyi` declaring the FFI API functions that are dynamically populated at runtime (e.g., `ModuleGetKind`, `Array`, `Map`, `Shape`, etc.).
- Fixes ~150+ mypy errors across 37 files by: adding `type: ignore` annotations for dynamic attribute access patterns, adding explicit type annotations to variables and class attributes, replacing `Optional[X]` with `X | None` (with `from __future__ import annotations`), converting `object | None` union syntax in Cython `.pxi` files to `Optional[X]` (Cython does not support PEP 604 unions), refactoring `register_object` for type-safe branching, adding `@overload` to `get_global_func`, switching `Field` from `@dataclass` to manual `__slots__` + `__init__`, and more.
- Fixes a latent type narrowing bug in `libinfo.py` where an unused variable `name` shadowed the list `lib_dll_names`, producing a confusing error message.
- Fixes `_find_cuda_home()` to raise `RuntimeError` instead of returning an empty string when no CUDA installation is found on Windows.
- Refactors `load_inline` to use explicit typed local variables (`cpp_source_list`, `cuda_source_list`, `function_map`, etc.) instead of reassigning parameters, satisfying mypy's narrowing requirements.
- Updates `core.pyi` stub: broadens `fconstructor` parameter from `Function` to `Any`, adds `c_void_p` to `_env_set_current_stream` signature, adds `_convert_torch_dtype_to_ffi_dtype`, `_convert_numpy_dtype_to_ffi_dtype`, `_CLASS_TENSOR`, `_set_class_tensor` declarations.
- In `registry.py`, restructures `_add_class_attrs` to set `__doc__` and `__name__` on the underlying function before wrapping with `staticmethod`, since `staticmethod` objects do not support direct attribute assignment.

## Impact
- API: The broadened parameter types on `load_inline` (`cpp_sources`, `cuda_sources`, `functions`) are additive -- callers passing a `Mapping[str, str]` for `functions` or `Sequence[str]` for sources now have correct type annotations. The `Field` class constructor is now explicit (`__init__` with `__slots__`) but has the same interface.
- ABI: None.
- Behavioral: (1) `_find_cuda_home()` now raises `RuntimeError` on Windows when no CUDA is found instead of returning `""`, which would have led to a confusing downstream error. (2) `libinfo.find_libtvm_ffi()` error message now correctly displays the library names instead of a variable that was shadowed. (3) `_optional_torch_c_dlpack.py` uses `setattr()` instead of direct attribute assignment for torch Tensor dunder attributes. (4) `quick_start/run_example.py` now unconditionally imports `torch` (removes the `try/except ImportError` guard), making torch a hard dependency of that example.
- Flags/config: `[tool.mypy]` added to `pyproject.toml`. mypy hooks added to `.pre-commit-config.yaml`. All future Python code must pass mypy.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python binding layer** (`.knowledge/designs/0014-python-bindings.md`): The pure-Python wrapper modules whose type annotations are being corrected and whose dynamic attribute patterns require `type: ignore` comments.
- **Pre-commit as canonical lint entry point** (commit `64e4b7f`): Extends the pre-commit hook set with mypy.
- **Type annotation convention** (commit `8f4e044`): Builds on the ruff `ANN` enforcement added previously, now adding static type-checking enforcement via mypy.
- **FFI API auto-population via `init_ffi_api`** (`.knowledge/designs/0014-python-bindings.md`): The `_ffi_api` modules are dynamically populated at runtime; this commit provides `.pyi` stubs so mypy can reason about them.

Design elements this commit produces:
- **mypy enforcement convention**: mypy is now a required pre-commit hook for all Python code. The `[tool.mypy]` config uses `allow_redefinition = true` (needed for the `try: import torch / except: torch = None` pattern) and `ignore_missing_imports = true` (needed for Cython extension modules). `_ffi_api.py` files are excluded since they are auto-populated.
- **`_ffi_api.pyi` stub pattern**: A hand-maintained `.pyi` stub declares the FFI API functions that are dynamically registered at import time. This pattern can be extended to other `_ffi_api.py` modules in downstream packages.
- **Optional import pattern for mypy**: The pattern for optional imports changes from `try: import X / except: X = None` to a pre-declared `X: ModuleType | None` followed by `try: import X / except: pass`, which allows mypy to properly narrow the type.

## Usage Examples

### Running mypy locally
```bash
# Via pre-commit (recommended)
pre-commit run mypy --all-files

# Direct invocation
mypy --show-error-codes --python-version=3.9 python/ tests/
```

### Optional import pattern (mypy-compatible)
```python
from __future__ import annotations
from types import ModuleType

torch: ModuleType | None = None
try:
    import torch  # type: ignore[no-redef]
except ImportError:
    pass

# Now mypy knows `torch` can be `None`
if torch is not None:
    x = torch.tensor([1, 2, 3])
```

### Type-safe `get_global_func` with overloads
```python
# When allow_missing=False (default), return type is `Function` (never None)
f = tvm_ffi.get_global_func("testing.echo")
f(42)  # no Optional check needed

# When allow_missing=True, return type is `Function | None`
f = tvm_ffi.get_global_func("maybe.missing", allow_missing=True)
if f is not None:
    f(42)
```
