# Fix Linux build of torch C DLPack ext by removing unnecessary Python library linkage
## TL;DR
- On Linux, the torch C DLPack extension no longer links `-lpython3` (and its `-L` path), which caused build failures. The `else` branch that previously handled both macOS and Linux is replaced with an explicit `if IS_DARWIN` guard.
- On Windows, the Python `.lib` search path is corrected from `sysconfig.get_path("include")` to `sys.base_exec_prefix / "libs"`, fixing library discovery on certain Windows Python installations.
- On Windows, `python_lib` (e.g., `python3.lib`) is no longer appended to `ldflags` directly (removed the `ldflags.append(python_lib)` line), since only the `/LIBPATH:` is needed for the linker to find it via `torch_python.lib` transitive dependency.

## Key Exports
None -- this is a build-script fix with no public API changes.

## Impact
- API: None
- Behavioral: Fixes CI build failure on Linux (https://github.com/apache/tvm-ffi/actions/runs/18935308302). No behavioral change to the built extension itself.
- Flags/config: Linker flags for torch C DLPack extension change per-platform:
  - Linux: no longer passes `-L<python-lib-dir> -lpython3`
  - macOS: unchanged (still links `-lpython<version>`)
  - Windows: no longer passes `python3.lib` explicitly; corrects `LIBPATH` discovery to `sys.base_exec_prefix / "libs"`
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Torch C DLPack extension build pipeline** (`python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`): The ninja-based build system that compiles the torch C DLPack addon shared library. Related to [0013-packaging](../../.knowledge/designs/0013-packaging.md) and [ADR-0015](../../.knowledge/ADRs/0015-dlpack-exchange-api-struct.md).
- **Platform detection convention**: `IS_WINDOWS = sys.platform == "win32"`. This commit adds `IS_DARWIN = sys.platform == "darwin"` to enable three-way platform branching (Windows / macOS / Linux-implicit).

Design elements this commit produces:
- **`IS_DARWIN` platform guard**: New module-level constant enabling explicit macOS detection, replacing the previous `else` fallback that covered both macOS and Linux.

## Usage Examples
**Before (broken on Linux):**
```python
# The `else` branch ran on both macOS AND Linux, appending -lpython3 on Linux
if IS_WINDOWS:
    # ... Windows Python lib search ...
    ldflags.append(python_lib)  # appended python3.lib
else:
    # This ran on both macOS and Linux
    python_libdir = sysconfig.get_config_var("LIBDIR")
    if python_libdir:
        ldflags.append(f"-L{python_libdir}")
        py_version = f"python{sysconfig.get_python_version()}"
        ldflags.append(f"-l{py_version}")
```

**After (fixed):**
```python
# Windows: only set LIBPATH, don't append python3.lib explicitly
if IS_WINDOWS:
    # ... Windows Python lib search (corrected path) ...
    break  # no ldflags.append(python_lib)

# macOS only: link Python shared library (Linux skipped entirely)
if IS_DARWIN:
    python_libdir = sysconfig.get_config_var("LIBDIR")
    if python_libdir:
        py_version = f"python{sysconfig.get_python_version()}"
        ldflags.append(f"-L{python_libdir}")
        ldflags.append(f"-l{py_version}")
```
