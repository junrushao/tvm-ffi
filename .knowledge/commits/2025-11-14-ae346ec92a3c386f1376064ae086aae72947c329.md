# Change bool dtype from uint1 to kDLBool/8-bit to align with DLPack standard
## TL;DR
- **Breaking change**: The `"bool"` dtype is now represented as `{code=kDLBool(6), bits=8, lanes=1}` instead of the previous `{code=kDLUInt(1), bits=1, lanes=1}`. This aligns with the DLPack v1 specification where `kDLBool` is a dedicated type code.
- The C++ string parser (`StringViewToDLDataType_`) and printer (`DLDataTypeToString_`) are updated to use `kDLBool` code 6 with 8-bit width.
- Python `DataTypeCode` enum gains `BOOL = 6` entry.
- Bool dtype now supports lanes (e.g., `"boolx4"`) since it follows the standard `<type><bits>x<lanes>` format instead of being special-cased.

## Key Exports
**Constant** (Python): `DataTypeCode.BOOL = 6` -- matches `kDLBool` from DLPack.

**Behavioral change** (C++/Python):
| | Before | After |
|---|--------|-------|
| `tvm_ffi.dtype("bool")` | `{code=1(kDLUInt), bits=1, lanes=1}` | `{code=6(kDLBool), bits=8, lanes=1}` |
| `str(dtype)` roundtrip | `"bool"` -> `uint1` encoding | `"bool"` -> `kDLBool/8` encoding |
| Lanes support | No (`"boolx4"` not possible) | Yes (`"boolx4"` = `{code=6, bits=8, lanes=4}`) |

## Impact
- API: **Breaking** -- any code comparing `dtype.type_code == 1` for bool will break; must use `dtype.type_code == 6` (or `DataTypeCode.BOOL`). Any code checking `dtype.bits == 1` for bool will also break.
- Behavioral: Bool tensor memory layout changes from 1-bit packed to 8-bit per element.
- Flags/config: None
- Data formats/schemas: Serialized dtype strings remain `"bool"` but the underlying `DLDataType` struct encoding changes.

## Design Elements
Design elements this commit consumes:
- **DLDataType string parsing/printing** ([0017-dlpack-interop.md](../designs/0017-dlpack-interop.md)): The `StringViewToDLDataType_` / `DLDataTypeToString_` functions are the central dtype string codec.
- **DataTypeCode Python enum** ([0014-python-package.md](../designs/0014-python-package.md)): Extended with `BOOL = 6`.

Design elements this commit produces:
- **Bool dtype invariant**: `"bool"` is now `{kDLBool, 8, 1}`, not `{kDLUInt, 1, 1}`. This is a new invariant that all dtype consumers must respect.

## Usage Examples
**Before** (broken -- non-DLPack-compliant bool):
```python
dtype = tvm_ffi.dtype("bool")
assert dtype.type_code == 1  # kDLUInt
assert dtype.bits == 1       # 1-bit packed
```

**After** (correct -- DLPack-aligned bool):
```python
dtype = tvm_ffi.dtype("bool")
assert dtype.type_code == 6  # kDLBool
assert dtype.bits == 8       # 8-bit per element

# Lanes now work for bool
dtype_vec = dtype.with_lanes(4)
assert str(dtype_vec) == "boolx4"
```
