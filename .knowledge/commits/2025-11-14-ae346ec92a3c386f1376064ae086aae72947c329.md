# Align bool dtype to DLPack standard: kDLBool code 6, 8 bits instead of kDLUInt code 1, 1 bit
## TL;DR
- Changes bool dtype representation from `{code=kDLUInt(1), bits=1, lanes=1}` to `{code=kDLBool(6), bits=8, lanes=1}` to align with the DLPack specification.
- Updates both C++ parsing/printing (`dtype.cc`) and Python enum (`DataTypeCode.BOOL = 6`) in lockstep.
- Adds Python test verifying `type_code == 6`, `bits == 8`, and vector bool (`boolx4`) round-tripping.

## Key Exports

```python
class DataTypeCode(IntEnum):
    """DLDataTypeCode code in DLTensor."""
    INT = 0
    UINT = 1
    FLOAT = 2
    HANDLE = 3
    BFLOAT = 4
    BOOL = 6       # NEW -- was previously absent; bool was encoded as UINT with bits=1
    Float8E3M4 = 7
    # ... (remaining float8 variants unchanged)
    # Interacts with: DLPack kDLBool constant, dtype.cc StringViewToDLDataType_, DLDataTypeToString_
    # Invariant: BOOL value (6) must match DLPack's kDLBool enum value

# C++ behavioral change (pseudocode):
# OLD: "bool" -> DLDataType{code=kDLUInt, bits=1, lanes=1}
# NEW: "bool" -> DLDataType{code=kDLBool, bits=8, lanes=1}
#
# OLD: DLDataType{code=kDLUInt, bits=1, lanes=1} -> "bool"
# NEW: DLDataType{code=kDLBool, bits=8, lanes=1} -> "bool"
#
# Printing suppresses bit-width suffix for kDLBool with bits=8,
# so "bool" prints as "bool" not "bool8", and "boolx4" prints correctly.
```

## Impact
- API: `DataTypeCode.BOOL` is now exposed as value 6 in the Python enum. Code checking `dtype.type_code == 1` for bool will break; must use `type_code == 6`.
- Behavioral: `tvm_ffi.dtype("bool")` now returns `{code=6, bits=8}` instead of `{code=1, bits=1}`. Any downstream code relying on `dtype.bits == 1` for bool will break.
- Flags/config: none
- Data formats/schemas: Any serialized DLDataType values using the old `{kDLUInt, 1, 1}` encoding for bool are no longer recognized as bool by the new code.

## Design Elements
Design elements this commit consumes:
- **DLPack `kDLBool` type code** (external standard, DLPack spec) -- the commit aligns TVM FFI's internal dtype representation to match this standard constant.
- **`dtype.cc` string-to-DLDataType parser** ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)) -- uses the existing parsing framework (prefix match + scan pointer) to add a new `"bool"` branch.
- **`DataTypeCode` Python enum** ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md)) -- extends the enum with the `BOOL` entry to mirror the C-level change.

Design elements this commit produces:
- None -- this is a correction to match an external standard, not a new design element.

## Usage Examples
Before/after pattern showing the corrected representation:

```python
import tvm_ffi

# BEFORE (old behavior):
# dtype = tvm_ffi.dtype("bool")
# assert dtype.type_code == 1   # kDLUInt
# assert dtype.bits == 1

# AFTER (new behavior, aligned with DLPack):
dtype = tvm_ffi.dtype("bool")
assert dtype.type_code == 6   # kDLBool
assert dtype.bits == 8
assert dtype.lanes == 1

# Vector bool also works:
dtype_vec = dtype.with_lanes(4)
assert dtype_vec == "boolx4"
assert dtype_vec.type_code == 6
assert dtype_vec.bits == 8
assert dtype_vec.lanes == 4
```
