# Align bool dtype parsing to use kDLBool code per DLPack spec
## TL;DR
- Changes bool dtype from `kDLUInt` with 1 bit to `kDLBool` with 8 bits, aligning with DLPack specification
- Adds `BOOL = 6` to Python `DataTypeCode` enum
- Updates C++ `StringViewToDLDataType_` and `DLDataTypeToString_` to handle `kDLBool` code correctly
- Adds Python test for `tvm_ffi.DataType("bool")` parsing

## Key Exports
```python
class DataTypeCode(IntEnum):
    BOOL = 6  # NEW: aligns with kDLBool

# C++ dtype.cc:
# "bool" now parses to {code=kDLBool, bits=8, lanes=1}
# Before: {code=kDLUInt, bits=1, lanes=1}
# Invariant: kDLBool is 8-bit (not 1-bit) per DLPack v1 spec
```

## Impact
- API: `DataType("bool")` now returns `{kDLBool, 8, 1}` instead of `{kDLUInt, 1, 1}`
- Behavioral: Breaking change for code relying on bool being uint1
- Flags/config: None
- Data formats/schemas: DLDataType representation of bool changed
