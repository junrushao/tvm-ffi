# Widen Device index parameter to accept numpy/torch scalars via Integral and .item() protocol
## TL;DR
- `Device.__init__` now accepts `numbers.Integral` (e.g., `numpy.int32`) and objects with `.item()` (e.g., `torch.tensor(1)`) as the `index` argument, matching `torch.device()` behavior.
- Type annotation widened from `Optional[int]` to `Optional[Integral]`.
- Test added for `numpy.int32` device index; torch test present but commented out (dependency not in test environment).

## Key Exports
```python
class Device:
    # Old: def __init__(self, device_type: str | int, index: Optional[int] = None) -> None: ...
    # New: accepts any numbers.Integral or object with .item() -> Integral
    def __init__(self, device_type: str | int, index: Optional[Integral] = None) -> None: ...
    # Invariant: index must be numbers.Integral after coercion; .item() is tried as fallback
    # Invariant: .item() fallback follows numpy/torch scalar protocol (returns Python int)
    # Interacts with: numbers.Integral ABC, numpy ndarray/scalar .item(), torch.Tensor.item()
```

## Impact
- API: `Device.__init__` index parameter widened from `int` to `Integral | .item()-capable`. Fully backward compatible -- `int` is a subclass of `Integral`.
- Behavioral: Objects with `.item()` method (numpy scalars, torch 0-d tensors) are now coerced to Python int before constructing the device.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Device` class from [0012-ffi-python-package](../design-records/0012-ffi-python-package.md) -- the Cython `Device` wrapper around `DLDevice`.
- `numbers.Integral` ABC from Python stdlib -- used as the widened type check.
- `.item()` protocol -- numpy/torch convention for extracting a Python scalar from a 0-d array/tensor.

Design elements this commit produces:
- None -- this is a parameter relaxation within an existing class, not a new design element.

## Usage Examples

import tvm_ffi

# Before: only Python int accepted

# After: numpy scalar accepted
