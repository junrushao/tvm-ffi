# Relax Device.__init__ index type check to accept numpy/torch scalars via numbers.Integral and .item() protocol

## TL;DR

- `Device.__init__` previously rejected any `index` that was not a plain Python `int`; numpy scalar types like `numpy.int32` and torch tensors with a `.item()` method were incorrectly rejected with `TypeError`.
- The fix broadens the type annotation from `Optional[int]` to `Optional[Integral]` (from `numbers` ABC) and adds a `.item()` fallback: if `index` is not already an `Integral` but has a callable `.item()`, call it to unwrap to a native Python int.
- This mirrors `torch.device("cuda", numpy.int32(1))` behavior, making `tvm_ffi.device(...)` a drop-in replacement for `torch.device(...)` in device-construction code.

## Key Exports

```python
class Device:
    """Represents a compute device (type + index)."""
    # Old signature:
    # def __init__(self, device_type: str | int, index: Optional[int] = None) -> None

    def __init__(self, device_type: str | int, index: Optional[Integral] = None) -> None:
        # Invariant: index, after coercion, must satisfy isinstance(index, Integral).
        # Coercion path: if hasattr(index, "item") and callable(index.item): index = index.item()
        # Invariant: .item() must produce an Integral; if not, TypeError is still raised.
        # Interacts with: TVMFFIDLDeviceFromIntPair (C ABI), numbers.Integral ABC
        ...
```

## Impact

- API: `Device.__init__` now accepts any `numbers.Integral` subtype (numpy scalar integers, Python `int`) plus objects with a `.item()` method that returns an `Integral` (torch scalar tensors). Pure `int` arguments continue to work unchanged.
- Behavioral: No change for `int` inputs. New coercion path for numpy integer scalars and framework scalar tensors.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `Device` Cython class (`python/tvm_ffi/cython/device.pxi`) — the existing device constructor and its type-check logic.
- `TVMFFIDLDeviceFromIntPair` (C ABI) — called at the end of `Device.__init__` with the coerced int pair; unchanged.
- `numbers.Integral` ABC (Python stdlib) — already used by `TVMFFIPyArgSetterIntegral_` in the dispatch layer (design record 0016-py-ffi-call-dispatch); this commit adopts the same ABC in the `Device` constructor for consistency.

Design elements this commit produces:
- None — the change is a targeted relaxation of an input-validation invariant; no new design elements are introduced.

## Usage Examples

Before (raises `TypeError` for numpy scalar index):
```python
import numpy
import tvm_ffi

# Before fix:
dev = tvm_ffi.device("cpu", numpy.int32(1))
# => TypeError: Invalid device index: 1  (numpy.int32 is not int)
```

After fix:
```python
import numpy
import tvm_ffi

dev = tvm_ffi.device("cpu", numpy.int32(1))
# => Device("cpu", 1)  — numpy.int32 accepted via numbers.Integral

# torch scalar also works (not tested in CI due to torch dependency):
# import torch
# dev = tvm_ffi.device("cuda", torch.tensor(1, dtype=torch.int32))
# => Device("cuda", 1)  — via .item() coercion
```
