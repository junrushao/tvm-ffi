# Widen Device.__init__ index parameter to accept numpy/torch scalars via Integral and .item() protocol
## TL;DR
- Widens `Device.__init__`'s `index` parameter type from `int` to `numbers.Integral`, accepting numpy integer scalars (e.g., `numpy.int32(1)`) directly.
- Adds a `.item()` fallback for objects that are not `Integral` but expose a `.item()` method (e.g., `torch.tensor(1, dtype=torch.int32)`), matching `torch.device` behavior.
- Adds a test case for numpy scalar device index; torch test case is present but commented out (dependency not available in CI).

## Key Exports

```python
class Device:
    """Thin wrapper around DLDevice in DLPack standard."""
    # Signature change: index widened from Optional[int] to Optional[Integral]
    # Old: def __init__(self, device_type: str | int, index: Optional[int] = None) -> None: ...
    # New:
    def __init__(self, device_type: str | int, index: Optional[Integral] = None) -> None: ...
        # Interacts with: numbers.Integral (ABC check), .item() protocol (numpy/torch scalar coercion)
        # Invariant: after coercion, index must be an Integral; TypeError raised otherwise
        # Extension: any object with a callable .item() returning Integral is accepted
```

## Impact
- API: `Device.__init__` now accepts `numbers.Integral` subclasses and `.item()`-supporting objects as `index`. Previously only `int` was accepted. No existing callers break (int is a subclass of Integral).
- Behavioral: numpy integer scalars and torch integer tensors no longer raise TypeError when passed as device index.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Device property API** (`.knowledge/designs/0012-python-bindings.md`, line 565-575): Uses the existing `Device.__init__` constructor and `TVMFFIDLDeviceFromIntPair` C-level call.
- **numbers.Integral ABC**: Standard library abstract base class; numpy integer types are registered subclasses.
- **`.item()` protocol**: De facto standard across numpy and torch for extracting a Python scalar from a 0-d array/tensor.

Design elements this commit produces:
- **`.item()` coercion fallback in Device.__init__**: A two-phase type coercion pattern: (1) check `isinstance(index, Integral)`, (2) if not, try `index.item()`, (3) re-check `isinstance(index, Integral)`. This pattern could be reused elsewhere if other APIs need to accept numpy/torch scalars.

## Usage Examples
