# Accept numpy/torch scalars as device index in tvm_ffi.device()
## TL;DR
- Widens `Device.__init__` index parameter from `int` to `numbers.Integral`, and adds `.item()` fallback for torch tensor scalars, matching `torch.device` behavior.
- `tvm_ffi.device("cuda", numpy.int32(1))` and `tvm_ffi.device("cuda", torch.tensor(1))` now work.

## Key Exports

**Changed constructor** (`Device.__init__` in `cython/device.pxi`):
```python
def __init__(self, device_type: str | int, index: Optional[Integral] = None) -> None:
    # Was: Optional[int]
    # Now accepts numbers.Integral (numpy integers) and objects with .item() (torch scalars)
```

## Impact
- API: `Device.__init__` index type widened from `int` to `Integral | Any-with-.item()`. Backward-compatible.
- Behavioral: numpy integer types and torch scalar tensors are now accepted as device index without manual `.item()` conversion.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Device** (`cython/device.pxi`) -- `Device.__init__`, `TVMFFIDLDeviceFromIntPair`

Design elements this commit produces:
- **`.item()` fallback convention** for accepting tensor-like scalars as integer parameters. This follows the same pattern as `torch.device`.

## Usage Examples

From the commit message:
```python
import tvm_ffi
import numpy

tvm_ffi.device("cuda", 0)                    # plain int (existing)
tvm_ffi.device("cuda", numpy.int32(1))        # numpy scalar (new)
# tvm_ffi.device("cuda", torch.tensor(1))     # torch scalar via .item() (new)
```
