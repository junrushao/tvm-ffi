# Skip JIT-compiling the torch C DLPack extension when newer PyTorch already provides __c_dlpack_exchange_api__

## TL;DR
- Adds an early-return guard in `load_torch_c_dlpack_extension()`: if `torch.Tensor` already has `__c_dlpack_exchange_api__` set (native support in newer PyTorch), the function returns `None` immediately without triggering the slow JIT C++ compilation.
- The guard is wrapped in a `try/except ImportError` so it is a no-op when `torch` is not installed.
- No change to the `DLPackExchangeAPI` protocol contract; callers that already set the attribute are respected.

## Key Exports

None — no new API surface. The only change is an early-exit guard inside the existing `load_torch_c_dlpack_extension()` function.

## Impact
- API: None — `load_torch_c_dlpack_extension()` signature is unchanged; its return type (`Any | None`) is unchanged.
- Behavioral: On PyTorch versions that ship `__c_dlpack_exchange_api__` natively on `torch.Tensor`, the JIT compile step is skipped entirely; `_mod` will be `None`. The attribute on `torch.Tensor` remains valid (set by torch itself).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`__c_dlpack_exchange_api__` class attribute protocol** ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md)): The guard checks `hasattr(torch.Tensor, "__c_dlpack_exchange_api__")` to determine whether native torch support is present. This relies on the invariant that a truthy `__c_dlpack_exchange_api__` on the class means the 5-function-pointer `DLPackExchangeAPI` struct is already correctly wired.
- **`load_torch_c_dlpack_extension()` stop-gap module pattern** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): The module-level `_mod = load_torch_c_dlpack_extension()` call (keep-alive pattern) is unchanged; `_mod` will simply be `None` when the guard fires.

Design elements this commit produces:
- None.

## Usage Examples

Before (older PyTorch without native support): `load_torch_c_dlpack_extension()` performs full JIT compile and sets `torch.Tensor.__c_dlpack_exchange_api__`.

After (newer PyTorch with native `__c_dlpack_exchange_api__`):
```python
# _optional_torch_c_dlpack.py module init
# torch already ships __c_dlpack_exchange_api__ on torch.Tensor
_mod = load_torch_c_dlpack_extension()
# _mod is None — JIT compile skipped, no slow compilation on first import
assert hasattr(torch.Tensor, "__c_dlpack_exchange_api__")  # still True, set by torch
```
