# Skip loading torch C DLPack extension when __c_dlpack_exchange_api__ already exists
## TL;DR
- Adds an early-return guard in `load_torch_c_dlpack_extension()` that checks `hasattr(torch.Tensor, "__c_dlpack_exchange_api__")` and returns `None` if the attribute already exists, avoiding redundant JIT compilation of the extension on newer PyTorch versions.
- Also returns `None` early if torch is not importable.

## Key Exports
None — no new public API; this is an optimization to the internal DLPack extension loader.

## Impact
- API: none
- Behavioral: On newer PyTorch versions that natively provide `__c_dlpack_exchange_api__`, the JIT extension compilation is skipped entirely, improving import speed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`torch.Tensor.__c_dlpack_exchange_api__`** — a convention (expected to be present in newer PyTorch) that provides the C DLPack capsule exchange API without needing TVM FFI's custom JIT extension. See [0017-dlpack-interop.md](../.knowledge/designs/0017-dlpack-interop.md).
- **`load_torch_c_dlpack_extension()`** — the JIT-compiled C++ extension that patches `torch.Tensor` with DLPack v1 methods. Defined in `python/tvm_ffi/_optional_torch_c_dlpack.py`.
