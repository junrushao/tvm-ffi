# Skip JIT-compiling torch DLPack extension when PyTorch already provides __c_dlpack_exchange_api__
## TL;DR
- Adds an early-return guard to `load_torch_c_dlpack_extension()` that checks `hasattr(torch.Tensor, "__c_dlpack_exchange_api__")` before attempting the expensive JIT C++ extension compilation.
- If a newer version of PyTorch already exposes the `__c_dlpack_exchange_api__` attribute natively, the function returns `None` immediately, avoiding redundant work.
- Also short-circuits with `return None` if `torch` is not importable, moving the ImportError handling to before the docstring and JIT path.

## Key Exports
None. No new public API surface. The existing function `load_torch_c_dlpack_extension() -> Any` retains its signature and semantics.

## Impact
- API: none
- ABI: none
- Behavioral: When PyTorch natively provides `__c_dlpack_exchange_api__` on `torch.Tensor`, the slow JIT compilation of the C++ extension is skipped entirely. The DLPack fast-path protocol still activates because the attribute is already present. When PyTorch does not have the attribute, behavior is unchanged (the extension is JIT-compiled and the attribute is set as before).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- DLPack fast-path protocol and `__c_dlpack_exchange_api__` attribute convention (`.knowledge/designs/0018-dlpack-fast-path.md`)
- PyTorch integration module `_optional_torch_c_dlpack` JIT compilation pattern (`.knowledge/designs/0018-dlpack-fast-path.md`, "PyTorch Integration Module" section)

Design elements this commit produces:
- **Forward-compatibility guard pattern**: When a downstream framework (PyTorch) natively adopts the protocol attribute that was previously monkey-patched, the extension loader detects this and gracefully skips its own setup. This establishes a deprecation glide path for the JIT extension.

## Usage Examples
None. The behavioral change is transparent -- no caller-visible API change. The guard activates automatically when a sufficiently new PyTorch is installed:

```python
import torch
# If torch.Tensor already has __c_dlpack_exchange_api__ (newer PyTorch):
#   load_torch_c_dlpack_extension() returns None immediately, no JIT compilation.
# If not (older PyTorch):
#   JIT compiles C++ extension and sets the attribute, same as before.
import tvm_ffi  # triggers the module-level call
```
