# Skip loading torch C DLPack extension if torch already provides __c_dlpack_exchange_api__

## TL;DR
- `_optional_torch_c_dlpack.py`: `load_torch_c_dlpack_extension()` now checks `hasattr(torch.Tensor, "__c_dlpack_exchange_api__")` before JIT-compiling the C extension; returns `None` early if the attribute already exists.
- Also returns `None` early if `torch` is not importable, preventing unnecessary compilation attempts on systems without torch.
- Supports newer PyTorch versions that natively expose `__c_dlpack_exchange_api__`, making the JIT extension redundant.

## Key Exports

```python
def load_torch_c_dlpack_extension() -> Any:
    """Load (or skip) the torch C DLPack extension.
    Returns None if torch is unavailable or already has __c_dlpack_exchange_api__."""
    # NEW early-exit paths:
    # 1. torch not importable -> return None
    # 2. torch.Tensor has __c_dlpack_exchange_api__ -> return None (newer PyTorch)
    # 3. otherwise: JIT-compile and return the extension module
    # Interacts with: DLPackExchangeAPI protocol (0016-py-ffi-call-dispatch)
    # Invariant: if torch.Tensor.__c_dlpack_exchange_api__ exists, no extension needed
```

## Impact
- API: none — `load_torch_c_dlpack_extension` return type and public signature unchanged.
- Behavioral: On newer PyTorch (with native `__c_dlpack_exchange_api__`), the JIT compilation is skipped entirely, reducing import overhead and avoiding potential build failures.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0016-py-ffi-call-dispatch` — `DLPackExchangeAPI` struct registered on tensor class via `__c_dlpack_exchange_api__`; this commit adds a guard that detects when PyTorch itself already provides that attribute.

Design elements this commit produces:
- Convention: "skip JIT extension if native protocol already present" — a forward-compatibility guard for the `__c_dlpack_exchange_api__` protocol on torch tensors.
