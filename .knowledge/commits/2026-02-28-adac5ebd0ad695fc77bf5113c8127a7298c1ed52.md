# Add cuLaunchKernelEx / cudaLaunchKernelExC support to CubinKernel and unified_api layer for cluster-dimension kernel launches (SM90+).
## TL;DR
- Adds `cuda_api::LaunchKernelEx` and `cuda_api::ConstructLaunchConfig` to `internal/unified_api.h`: two new inline functions covering both Driver API (`cuLaunchKernelEx`) and Runtime API (`cudaLaunchKernelExC`) paths.
- Adds `CubinKernel::LaunchEx(args, config)` to `cubin_launcher.h` as the high-level entrypoint that delegates to `cuda_api::LaunchKernelEx`.
- `cluster_dim=1` in `ConstructLaunchConfig` means no cluster launch attribute is set; `cluster_dim>1` populates `CU_LAUNCH_ATTRIBUTE_CLUSTER_DIMENSION` / `cudaLaunchAttributeClusterDimension` in the caller-managed `attr` storage, enabling SM90+ thread-block cluster launches.

## Key Exports

```python
# ─── include/tvm/ffi/extra/cuda/internal/unified_api.h ──────────────────────
# namespace tvm::ffi::cuda_api  (INTERNAL — include only via cubin_launcher.h)

def LaunchKernelEx(kernel: KernelHandle, args: void**, config: LaunchConfig) -> ResultType:
    """Launch a kernel using the extended API (cuLaunchKernelEx / cudaLaunchKernelExC).
    Enables SM90+ cluster-dimension launches and other attributes in LaunchConfig.
    """
    # Driver path: cuLaunchKernelEx(&config, CUfunction(kernel), args, nullptr)
    # Runtime path: cudaLaunchKernelExC(&config, const void*(kernel), args)
    # Interacts with: CubinKernel::LaunchEx (caller), ConstructLaunchConfig (config builder)
    # Invariant: config must be fully initialized via ConstructLaunchConfig before call
    # Invariant: if config.attrs != nullptr, the pointed-to LaunchAttrType must outlive this call

def ConstructLaunchConfig(
    kernel: KernelHandle,
    stream: StreamHandle,
    smem_size: uint32_t,
    grid: tvm.ffi.dim3,
    block: tvm.ffi.dim3,
    cluster_dim: int,
    config: LaunchConfig,    # out param — populated by this function
    attr: LaunchAttrType,    # out param — storage for cluster attribute; must outlive LaunchKernelEx call
) -> ResultType:
    """Build a LaunchConfig struct with optional cluster dimension attribute.
    cluster_dim=1: no cluster attribute set (config.attrs=nullptr, config.numAttrs=0).
    cluster_dim>1: sets cluster attribute x=cluster_dim, y=1, z=1 in attr; config.attrs=&attr.
    """
    # Driver path: CUlaunchConfig; attr.id = CU_LAUNCH_ATTRIBUTE_CLUSTER_DIMENSION
    # Runtime path: cudaLaunchConfig_t; attr.id = cudaLaunchAttributeClusterDimension
    # Interacts with: LaunchKernelEx (consumer of config), tvm::ffi::dim3 (grid/block)
    # Invariant: attr storage owned by caller; pointer stored in config.attrs — do NOT stack-allocate
    #            if passing config across scope boundaries
    # Invariant: returns kSuccess unconditionally (no CUDA calls made in this function)

# ─── include/tvm/ffi/extra/cuda/cubin_launcher.h ────────────────────────────

class CubinKernel:
    """Existing class — one new method added."""

    def LaunchEx(self, args: void**, config: cuda_api.LaunchConfig) -> cuda_api.ResultType:
        """Launch the kernel using the extended API with a pre-built config.
        Delegates to cuda_api::LaunchKernelEx(kernel_, args, config).
        """
        # Interacts with: cuda_api::LaunchKernelEx (unified_api.h)
        # Interacts with: cuda_api::ConstructLaunchConfig (caller must build config first)
        # Invariant: config must have been populated via ConstructLaunchConfig
        # Extension: caller uses ConstructLaunchConfig for cluster launches, Launch() for standard launches
```

## Impact
- API: Additive — two new functions in `cuda_api` namespace (`LaunchKernelEx`, `ConstructLaunchConfig`) and one new method on `CubinKernel` (`LaunchEx`). No existing signatures changed.
- Behavioral: None to existing callers; new callers can now use cluster-dimension launches on SM90+ hardware.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

**Context**: C++ kernel launcher using `ConstructLaunchConfig` + `LaunchEx` with cluster_dim=1 (no clustering), then called from Python via `load_inline`. Taken from `test_cubin_launcher_launch_ex` in `tests/python/test_cubin_launcher.py`.

```cpp
// C++ inline code (passed to load_inline):
void LaunchAddOneEx(tvm::ffi::TensorView x, tvm::ffi::TensorView y) {
    int64_t n = x.size(0);
    void* x_ptr = x.data_ptr();
    void* y_ptr = y.data_ptr();
    void* args[] = {&x_ptr, &y_ptr, &n};

    tvm::ffi::dim3 grid((n + 1023) / 1024);
    tvm::ffi::dim3 block(1024);
    DLDevice device = x.device();
    auto stream = static_cast<tvm::ffi::cuda_api::StreamHandle>(
        TVMFFIEnvGetStream(device.device_type, device.device_id));

    // Build config + launch (cluster_dim=1 → no cluster attribute)
    tvm::ffi::cuda_api::LaunchConfig config;
    tvm::ffi::cuda_api::LaunchAttrType attr;   // must outlive LaunchKernelEx call
    auto err = tvm::ffi::cuda_api::ConstructLaunchConfig(
        g_kernel->GetHandle(), stream, /*smem_size=*/0,
        grid, block, /*cluster_dim=*/1, config, attr);
    TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR(err);
    auto result = g_kernel->LaunchEx(args, config);
    TVM_FFI_CHECK_CUBIN_LAUNCHER_CUDA_ERROR(result);
}
```
