# Fix use-after-move bug when converting std::tuple to ArrayObj in STL type traits

## TL;DR

- In `CopyToTupleImpl`, the fold expression `std::get<Is>(std::forward<Tuple>(src))` evaluated `std::forward<Tuple>(src)` multiple times, causing a use-after-move when `src` is an rvalue — every element after the first accessed a moved-from tuple. Fixed by switching to `std::apply` to unpack elements into individually-forwarded references before the fold.
- In `TypeTraits<std::vector<T>>::TryCastFromAnyView`, the loop variable and length were `std::size_t` (unsigned), mismatching `ArrayObj::size_` which is `int64_t`; both changed to `int64_t` to eliminate signed/unsigned mismatch.

## Key Exports

None — this commit restores correct behavior in existing internal helpers with no API surface change.

## Impact

- API: none
- Behavioral: `MoveToTuple` (called via `TypeTraits<std::tuple<Args...>>::MoveToAny`) previously silently moved from the source tuple multiple times, leaving all elements after the first in moved-from state when stored into the `ArrayObj`. Now all elements are correctly forwarded exactly once.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `TypeTraits<T>` protocol — `CopyToAnyView`/`MoveToAny`/`TryCastFromAnyView` specialization pattern for STL types (see [0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md))
- `ArrayObj` / `TypeTraits<details::ListTemplate>` — the internal `CopyToTupleImpl` helper that packs heterogeneous tuple elements into an `ArrayObj` (see [0006-ffi-containers](../design-records/0006-ffi-containers.md))

Design elements this commit produces: none — pure bugfix restoring existing invariants.

## Usage Examples

**Before (broken — use-after-move for rvalue tuples):**
```cpp
// MoveToAny on std::tuple<A, B> — elem B accessed after src was moved-from
((::new (dst++) Any(std::get<Is>(std::forward<Tuple>(src))), array->size_++), ...);
//                                  ^^^^^^^^^^^^^^^^^^^^ evaluated N times; moves src on first Is
```

**After (correct — std::apply unpacks before fold):**
```cpp
std::apply(
    [&](auto&&... elems) {
      ((::new (dst++) Any(std::forward<decltype(elems)>(elems)), array->size_++), ...);
    },
    std::forward<Tuple>(src));  // src moved exactly once into apply; each elem forwarded once
```

**Invariant restored:** Every element in the tuple is forwarded into `Any` exactly once, in order, with the correct value category (move for rvalue elements, copy for lvalue elements).
