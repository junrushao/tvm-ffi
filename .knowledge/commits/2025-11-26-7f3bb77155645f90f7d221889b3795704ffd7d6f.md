# Upgrade DLPack exchange API attribute from raw int pointer to PyCapsule, with backward compatibility
## TL;DR
- Changes `torch.Tensor.__c_dlpack_exchange_api__` from a raw integer (cast pointer) to a `PyCapsule` with name `"dlpack_exchange_api"`, which is the safer and more Pythonic way to pass C pointers across the FFI boundary.
- The Cython consumer (`_get_dlpack_exchange_api` in `tensor.pxi`) and both loader paths (AOT addon and JIT fallback in `_optional_torch_c_dlpack.py`) are updated, with full backward compatibility: `int` values are still accepted transparently.
- Secondary concern: adds a CUDA version guard (`>= 13.0`) to CUBIN launcher tests (unrelated infra fix).

## Impact
- API: `torch.Tensor.__c_dlpack_exchange_api__` changes from `int` to `PyCapsule`. Backward compatible -- Cython consumer accepts both types transparently via `_get_dlpack_exchange_api`.
- Behavioral: The AOT addon path (`torch_c_dlpack_ext`) may still set the attribute as `int`. The loader eagerly upgrades it to `PyCapsule` on detection, so downstream consumers always see PyCapsule after `load_torch_c_dlpack_extension()` completes.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack Exchange API struct protocol** ([ADR-0015](../ADRs/0015-dlpack-exchange-api-struct.md)): the `__c_dlpack_exchange_api__` class-level attribute on tensor types, and the `DLPackExchangeAPI` C struct it points to.
- **TVMFFIPyArgSetterFactory_ dispatch chain** ([0012-python-bindings](../designs/0012-python-bindings.md)): the `__c_dlpack_exchange_api__` branch that extracts the struct pointer from the class attribute.
- **Torch DLPack addon loader** ([0017-torch-dlpack-addon](../designs/0017-torch-dlpack-addon.md)): both the AOT (`torch_c_dlpack_ext`) and JIT fallback paths that set the attribute.

Design elements this commit produces:
- **PyCapsule-based DLPack exchange API passing convention**: Changes the transport type for `__c_dlpack_exchange_api__` from `int` (raw pointer cast) to `PyCapsule` with name `"dlpack_exchange_api"`. This is a safer mechanism that prevents accidental misuse of raw integer pointers and follows CPython conventions for cross-extension pointer exchange.
- **`_get_dlpack_exchange_api` Cython helper**: Dual-mode extraction function that transparently handles both `int` (legacy) and `PyCapsule` (new) attribute types.
- **`_create_dlpack_exchange_api_capsule` Python helper**: Utility to wrap a pointer-as-int into the canonical PyCapsule format.

## Usage Examples

**New PyCapsule-based exchange (JIT path)**:
```python
# After this commit, load_torch_c_dlpack_extension() sets PyCapsule:
import tvm_ffi  # triggers load_torch_c_dlpack_extension()
import torch

api_attr = torch.Tensor.__c_dlpack_exchange_api__
# api_attr is now a PyCapsule, not an int

# Cython consumer transparently handles both types:
# _get_dlpack_exchange_api(api_attr, &out_ptr)  -- works for PyCapsule or int
```

**Backward compatibility (AOT addon sets int, loader upgrades)**:
```python
# Before: older torch_c_dlpack_ext sets attribute as int
# torch.Tensor.__c_dlpack_exchange_api__ = 0x7f1234567890  (int)

# After: load_torch_c_dlpack_extension() detects int and upgrades
if isinstance(torch.Tensor.__c_dlpack_exchange_api__, int):
    torch.Tensor.__c_dlpack_exchange_api__ = _create_dlpack_exchange_api_capsule(
        torch.Tensor.__c_dlpack_exchange_api__
    )
# Now it's a PyCapsule
```
