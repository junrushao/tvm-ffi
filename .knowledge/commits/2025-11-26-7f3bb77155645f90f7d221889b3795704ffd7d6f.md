# Upgrade DLPack Exchange API to support capsule-based passing alongside int-based
## TL;DR
- Extends `__c_dlpack_exchange_api__` protocol to accept `PyCapsule` objects in addition to plain integers, for safer passing of the `DLPackExchangeAPI` struct pointer across frameworks.
- Updates both the Cython FFI core and the torch-c-dlpack extension to handle capsule-based API passing.
- Maintains backward compatibility with integer-based API passing.

## Key Exports

```python
# Extended protocol for __c_dlpack_exchange_api__:
# Previously: returns int (raw pointer cast)
# Now: returns int OR PyCapsule("DLPackExchangeAPI", ptr)
# Interacts with: DLPackExchangeAPI struct (0007-c-abi), torch_c_dlpack_ext
# Invariant: capsule name must be "DLPackExchangeAPI"
# Extension: any framework can expose this dunder with either format

# Cython-side detection (function.pxi):
# _try_get_dlpack_exchange_api(obj) now checks:
#   1. PyCapsule with name "DLPackExchangeAPI" -> extract pointer
#   2. int -> use as raw pointer (backward compat)

# Torch extension-side (core.py):
# __c_dlpack_exchange_api__ now returns PyCapsule
# _c_dlpack_exchange_api_capsule() -> PyCapsule
```

## Impact
- API: none (backward compatible extension)
- Behavioral: safer cross-framework DLPack exchange API passing via PyCapsule vs raw int
- Flags/config: none
- Data formats/schemas: PyCapsule with name "DLPackExchangeAPI"

## Design Elements
Design elements this commit consumes:

Design elements this commit produces:
- PyCapsule-based DLPack exchange API passing — extends the existing protocol for safer interop.
