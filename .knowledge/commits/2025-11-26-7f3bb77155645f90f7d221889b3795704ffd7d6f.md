# Upgrade `DLPackExchangeAPI` registration to pass by `PyCapsule` instead of raw integer

## TL;DR
- The `__c_dlpack_exchange_api__` class attribute on tensor types is now a `PyCapsule("dlpack_exchange_api")` instead of a raw `int` pointer.
- On the Cython side, `_get_dlpack_exchange_api()` in `tensor.pxi` handles both `int` (backward-compatible) and `PyCapsule` forms; `function.pxi` updated to call this helper.
- `torch_c_dlpack_ext` addon preserves the old integer assignment for backward compat; `_optional_torch_c_dlpack.py` eagerly upgrades integer values to PyCapsule on import.

## Impact
- API: `__c_dlpack_exchange_api__` class attribute type changed from `int` to `PyCapsule`. Old code that checks `isinstance(..., int)` still works due to backward-compat path in `_get_dlpack_exchange_api`. Python-level test updated to handle both types.
- Behavioral: `DLPackExchangeAPI` pointer is now typed (capsule name-checked) rather than an opaque integer. Reduces risk of silent type confusion.
- Flags/config: none
- Data formats/schemas: PyCapsule name: `b"dlpack_exchange_api"`.

- `0022-torch-dlpack-addon`: `TorchDLPackExchangeAPIPtr` C symbol, `load_torch_c_dlpack_extension`.

Design elements this commit produces:
- **PyCapsule protocol for `__c_dlpack_exchange_api__`**: establishes that the attribute should be `PyCapsule("dlpack_exchange_api")` rather than raw `int`. Backward-compat `int` path retained in `_get_dlpack_exchange_api`.
- **`_create_dlpack_exchange_api_capsule(ptr_as_int)`**: utility for wrapping raw pointers; usable by any tensor library integrating with `DLPackExchangeAPI`.

## Usage Examples

```python
# New: PyCapsule-based registration (preferred)
import ctypes
pythonapi = ctypes.pythonapi
pythonapi.PyCapsule_New.restype = ctypes.py_object
capsule = pythonapi.PyCapsule_New(ctypes.c_void_p(ptr_as_int), b"dlpack_exchange_api", None)
MyTensorClass.__c_dlpack_exchange_api__ = capsule

# Old integer form still accepted (backward compat)
MyTensorClass.__c_dlpack_exchange_api__ = ptr_as_int  # int
```
