# Change type_acenstors from int32_t[] to TVMFFITypeInfo*[] for O(1) parent reflection lookup
## TL;DR
- **Core change**: The ancestor table in `TVMFFITypeInfo` is changed from `const int32_t*` (storing type indices) to `const struct TVMFFITypeInfo**` (storing direct pointers to ancestor `TypeInfo` entries). This eliminates an extra `TVMFFIGetTypeInfo()` table lookup each time parent type information is needed during reflection field traversal and `IsInstance` overflow checks.
- **New utility**: Adds `ForEachFieldInfo()` template in `reflection.h` that walks the ancestor chain and invokes a callback for every field from root to leaf, enabling callers to enumerate inherited fields without manually traversing the ancestor table.
- **Minor cleanups**: `if constexpr` branches in `IsObjectInstance` and `Tuple::TryConvertElements` are restructured with explicit `else` clauses to help compilers eliminate dead branches earlier during template instantiation. A `String(TVMFFIByteArray)` constructor is added for convenience.

## Impact
- API: **Breaking C ABI change** to `TVMFFITypeInfo`. The `type_acenstors` field changes from `const int32_t*` to `const struct TVMFFITypeInfo**`. All language bindings (Python/Cython, Rust) that read `type_acenstors` must be updated to dereference through a pointer-to-`TVMFFITypeInfo` instead of indexing into an integer array. The `TVMFFITypeInfo` typedef also gains a struct tag (`struct TVMFFITypeInfo`) to enable self-referential pointer declarations.
- Flags/config: none
- Data formats/schemas: The in-memory layout of `TypeTable::Entry::type_acenstors_data` changes from `std::vector<int32_t>` to `std::vector<const TVMFFITypeInfo*>`, affecting the runtime representation but not any on-disk format.

## Design Elements
Design elements this commit consumes:
- **Object system / TypeTable** (`.knowledge/designs/0003-object-system.md`): The `TypeTable::Entry` stores ancestor information and is the data structure being changed. The `IsObjectInstance` function uses the ancestor table for the overflow fallback path.
- **Slot-based type allocation / IsInstance** (`.knowledge/ADRs/0003-slot-based-type-allocation.md`): The overflow fallback in `IsInstance` previously read `type_acenstors[depth]` as an `int32_t` index, now reads `type_acenstors[depth]->type_index`. The slot range fast path is unchanged.
- **Reflection system** (`.knowledge/designs/0006-reflection.md`): `MakeObjectFromPackedArgs` previously called `TVMFFIGetTypeInfo(type_info->type_acenstors[i])` to resolve each ancestor's `TypeInfo` for field enumeration. This extra lookup is eliminated.
- **C ABI layer** (`.knowledge/designs/0001-c-abi.md`): `TVMFFITypeInfo` is a foundational C struct. Adding a struct tag and changing the ancestor field type is a breaking ABI change.

Design elements this commit produces:
- **Direct-pointer ancestor table**: A new invariant -- `type_acenstors[i]` is a valid `const TVMFFITypeInfo*` pointing directly to the ancestor's `TypeInfo` entry in the `TypeTable`, not an integer index requiring a table lookup. This enables O(1) field enumeration of inherited fields.
- **`ForEachFieldInfo` utility** (`include/tvm/ffi/reflection/reflection.h`): A new public template function that encapsulates the pattern of iterating ancestor fields from root to leaf, then the type's own fields. This is the canonical way to enumerate all fields (own + inherited) of an object type. Evidence: `reflection.h` addition at line 405+.
- **`String(TVMFFIByteArray)` constructor** (`include/tvm/ffi/string.h`): A convenience constructor allowing direct construction of `String` from the C-level `TVMFFIByteArray` struct without manual `data`/`size` extraction.

### ADRs to write

- **`.knowledge/ADRs/0006-ancestor-pointer-vs-index.md`**
  - **Context**: The ancestor table in `TVMFFITypeInfo` was originally `const int32_t*` (indices into the type table). Reflection and `MakeObjectFromPackedArgs` needed to call `TVMFFIGetTypeInfo(index)` for each ancestor, adding O(depth) table lookups per object construction.
  - **Alternatives considered**: (1) Keep integer indices and cache `TypeInfo*` locally at call sites; (2) Store direct `TypeInfo*` pointers in the ancestor table. Option 2 was chosen because it eliminates the lookup at all call sites uniformly, and `TypeTable` entries are never moved or freed (stable pointers).
  - **Trade-offs**: Direct pointers consume 8 bytes per ancestor entry (vs 4 bytes for `int32_t`), doubling the ancestor table memory. However, the depth of the type hierarchy is typically small (< 10), so the memory cost is negligible. The benefit is eliminating table lookups in hot paths (reflection, object construction, `IsInstance` overflow).

### Design diagrams to draw
