# Fix CMake install() trailing-slash for 3rdparty directories and bump version to 0.1.0b3
## TL;DR
- Adds trailing slashes to the `install(DIRECTORY ...)` source and destination paths for `3rdparty/dlpack/include` and `3rdparty/libbacktrace` in `CMakeLists.txt`, fixing CMake's directory-copy semantics so the contents (not the directory itself) are installed at the correct destination.
- Bumps the Python package version from `0.1.0b2` to `0.1.0b3` in `pyproject.toml`.

## Key Exports
None

## Impact
- API: none
- Behavioral: CMake `install(DIRECTORY src DESTINATION dst)` without trailing slash on `src` copies the directory itself into `dst`, creating `dst/include/include/` or `dst/libbacktrace/libbacktrace/`. Adding trailing slashes ensures directory *contents* are placed directly at `dst`. This corrects packaging of headers and source for downstream consumers of the installed package.
- Flags/config: none
- Data formats/schemas: none
