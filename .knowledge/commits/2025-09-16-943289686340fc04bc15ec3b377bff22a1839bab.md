# Fix CMake 3rdparty install directory paths and bump version to 0.1.0b3
## TL;DR
- Fix CMake `install(DIRECTORY ...)` for `3rdparty/dlpack` and `3rdparty/libbacktrace` by adding trailing slashes to source paths, ensuring only the directory *contents* are installed rather than creating a nested duplicate directory.
- Bump package version from `0.1.0b2` to `0.1.0b3` in `pyproject.toml`.

## Key Exports
None

## Impact
- API: none
- Behavioral: Fixes the installed directory layout for 3rdparty headers and sources in built wheels. Without the trailing slash, CMake `install(DIRECTORY src/ DESTINATION dst/)` copies `src/` itself into `dst/`, creating `dst/include/include/` (for dlpack) and `dst/libbacktrace/libbacktrace/` — breaking downstream `find_package(tvm_ffi)` header discovery when consuming an installed wheel.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Packaging system: CMake install rules for 3rdparty vendored dependencies (see [0013-packaging.md](../designs/0013-packaging.md))
- `tvm-ffi-config` CLI: downstream projects using `--dlpack-includedir` would have received broken paths from wheels built with the old install rules

Design elements this commit produces: none (bugfix to existing packaging)
