# Enable Python 3.8 build support (#145)
## TL;DR
- Lowers the minimum Python version from 3.9 to 3.8 across `pyproject.toml` (requires-python, ruff target, mypy python_version, cibuildwheel build list) and the runtime version check in `base.py`.
- Adds `from __future__ import annotations` to 8 Python files that were missing it, enabling PEP 604 union syntax (`X | Y`) and unquoted forward references on Python 3.8.
- Adds a Python 3.8 compatibility workaround in `container.py` to import `Mapping`, `Sequence`, `KeysView`, `ValuesView`, `ItemsView` from `typing` instead of `collections.abc` on 3.8, and guards torch inline C code with `TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 6` for new `ScalarType` enumerants.

## Key Exports
None -- no new public API surface is introduced.

## Impact
- API: none
- ABI: none
- Behavioral: The package now accepts Python 3.8 at import time (previously raised `Exception` for Python < 3.9). The `cp38-*` wheel is now built by cibuildwheel but excluded from test-skip like cp39-cp311.
- Flags/config: `requires-python` changed from `>=3.9` to `>=3.8`; ruff `target-version` from `py39` to `py38`; mypy `python_version` from `3.9` to `3.8`; ruff `FA` (flake8-future-annotations) rule added.
- Data formats/schemas: none
