# Enable Python 3.8 support across the tvm_ffi package
## TL;DR
- Lowers the minimum Python version from 3.9 to 3.8 in `pyproject.toml`, `base.py`, and all build/lint configuration.
- Adds `from __future__ import annotations` to every Python file that was missing it, enabling PEP 604 (`X | Y`) and PEP 585 (`list[T]`) syntax at runtime on Python 3.8.
- Adds a typing compatibility workaround in `container.py` for `collections.abc` generic aliases unavailable in Python 3.8, and guards torch `ScalarType` members behind `TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 6` in the JIT-compiled DLPack extension.

## Key Exports
None — no new public API. Changes are to build configuration and import-time compatibility.

## Impact
- API: none
- Behavioral: `tvm_ffi` now imports and runs on CPython 3.8+. Previously, importing on 3.8 raised an exception at `base.py`. String annotations in type hints are now evaluated lazily via `from __future__ import annotations` in all affected modules.
- Flags/config: `requires-python` changed from `>=3.9` to `>=3.8`. `ruff` target version changed to `py38`. `mypy` python_version changed to `3.8`. `cibuildwheel` now includes `cp38-*` builds. `flake8-future-annotations` (`FA`) lint rule added to enforce `from __future__ import annotations`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Python bindings packaging conventions (`.knowledge/design-records/0012-python-bindings.md`) — the `base.py` version guard, `pyproject.toml` build matrix, and typing patterns are all defined there.
- Container typing patterns (`.knowledge/design-records/0006-containers.md`) — `Array`/`Map` Python wrappers use `collections.abc.Sequence`/`Mapping` which need workaround imports on 3.8.

Design elements this commit produces:
- **Python 3.8 typing compatibility pattern**: On Python 3.8, `collections.abc.ItemsView`, `KeysView`, `ValuesView`, `Mapping`, `Sequence` are not subscriptable at runtime. The workaround imports from `collections.abc` first (usable but not subscriptable), then conditionally re-imports from `typing` on Python 3.9+ where runtime subscriptability is needed for `Map` typed views.
- **`from __future__ import annotations` convention enforced by lint**: The new `FA` ruff rule ensures every Python file uses `from __future__ import annotations`, allowing PEP 604/585 syntax everywhere regardless of runtime Python version.
- **Torch version guard pattern**: C code in `_optional_torch_c_dlpack.py` uses `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 6` to guard `ScalarType` variants (`Int1`-`Int7`, `Char`) that don't exist in older PyTorch versions.
