# Add C++ dtype_trait<T> template and Python to_cpp_dtype() for mapping DLPack dtypes to vendor-specific C++ types
## TL;DR
- New header `tvm/ffi/extra/dtype.h` provides `dtype_trait<T>` template specializations mapping 25 C++ types (CPU integers/floats, CUDA `__half`/`__nv_*`, HIP `__hip_*`) to `DLDataType` values.
- New Python module `tvm_ffi.cpp.dtype` provides `to_cpp_dtype()` that maps dtype strings (or `torch.dtype` objects) to their C++ type name strings, with backend-aware dispatch (CPU/CUDA/ROCm).
- Exported via `tvm_ffi.cpp.to_cpp_dtype` in the package `__init__.py`.

## Design Elements
Design elements this commit consumes:
- **DLPack DLDataType / DLDataTypeCode** -- the `dlpack/dlpack.h` enum and struct that `dtype_trait` maps to.
- **`tvm_ffi.cpp` module** ([0014-ffi-load-inline](../design-records/0014-ffi-load-inline.md)) -- `to_cpp_dtype` is exported through this package's `__init__.py`.
- **CUDA/HIP vendor type forward declarations** -- `__half`, `__nv_*`, `__hip_*` types are forward-declared (not included), keeping the header standalone.

Design elements this commit produces:
- **`dtype_trait<T>` compile-time type-to-DLDataType mapping** -- a new extensible protocol for converting C++ types to DLPack dtypes. Header-only, no dependency on TVM FFI core. Complements the existing CUDA extras layer.
- **`to_cpp_dtype()` Python dtype-to-C++ name resolver** -- backend-aware (CPU/CUDA/ROCm) string mapping with `torch.dtype` interop. Intended for code generation and JIT compilation workflows.

## Usage Examples

**C++ usage: compile-time dtype lookup for kernel template instantiation**
```cpp
#include <tvm/ffi/extra/dtype.h>

template <typename T>
void register_kernel() {
    DLDataType dt = tvm_ffi::dtype_trait<T>::value;
    // Use dt.code, dt.bits, dt.lanes to select kernel specialization
}

register_kernel<float>();           // -> {kDLFloat, 32, 1}
register_kernel<__nv_bfloat16>();   // -> {kDLBfloat, 16, 1}
register_kernel<__nv_fp4x2_e2m1>(); // -> {kDLFloat4_e2m1fn, 4, 2}
```

**Python usage: dtype string to C++ type name for JIT code generation**
```python
from tvm_ffi.cpp import to_cpp_dtype

cpp_type = to_cpp_dtype("float16")       # -> "__half" (CUDA) or "__half" (ROCm)
cpp_type = to_cpp_dtype("torch.bfloat16") # -> "__nv_bfloat16" (CUDA) or "__hip_bfloat16" (ROCm)
cpp_type = to_cpp_dtype("int32")          # -> "int32_t" (all backends)

# Useful in JIT code generation:
source = f"void kernel({cpp_type}* data) {{ ... }}"
mod = cpp.load_inline("my_mod", cpp_sources=source, functions=["kernel"])
```
