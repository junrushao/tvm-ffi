# Add C++ dtype_trait template and Python to_cpp_dtype mapping for CUDA/HIP/CPU numeric types

## TL;DR
- Adds `tvm_ffi::dtype_trait<T>`, a compile-time C++ trait mapping C++ numeric types (integers, floats, bool, CUDA half/fp8/fp4, HIP bf16/fp8/fp4) to `DLDataType` values. Located in `include/tvm/ffi/extra/dtype.h`.
- Adds `tvm_ffi.cpp.to_cpp_dtype()`, a Python function that converts dtype strings (e.g., `"float32"`, `"bfloat16"`, `torch.float16`) to C++ type name strings (e.g., `"float"`, `"__nv_bfloat16"`, `"__half"`), with backend auto-detection (CUDA/ROCm/CPU) via PyTorch.
- The two layers are complementary: C++ maps `type -> DLDataType`, Python maps `dtype_string -> C++ type name`. Together they enable end-to-end dtype bridging for kernel libraries.

## Usage Examples

**C++ side: Using dtype_trait in a templated kernel wrapper**
```cpp
#include <tvm/ffi/extra/dtype.h>

template <typename T>
DLDataType get_dtype() {
    return tvm_ffi::dtype_trait<T>::value;
}

// get_dtype<float>()       -> {kDLFloat, 32, 1}
// get_dtype<__half>()      -> {kDLFloat, 16, 1}
// get_dtype<__nv_fp8_e4m3>() -> {kDLFloat8_e4m3fn, 8, 1}
```

**Python side: Generating C++ code with correct dtype names**
```python
from tvm_ffi.cpp import to_cpp_dtype

# On a CUDA machine:
to_cpp_dtype("float32")        # -> "float"
to_cpp_dtype("bfloat16")       # -> "__nv_bfloat16"
to_cpp_dtype(torch.float16)    # -> "__half"

# On a ROCm machine:
to_cpp_dtype("bfloat16")       # -> "__hip_bfloat16"
```

**Cross-layer: Python generates C++ source using correct vendor types**
```python
from tvm_ffi.cpp import to_cpp_dtype, load_inline

cpp_type = to_cpp_dtype("bfloat16")  # "__nv_bfloat16" or "__hip_bfloat16"
source = f"""
#include <tvm/ffi/extra/dtype.h>
static_assert(tvm_ffi::dtype_trait<{cpp_type}>::value.bits == 16);
"""
```
