# Fix Web ABI compatibility: pass DLDataType by pointer and add configurable log-before-throw

## TL;DR
- Changes the C API function `TVMFFIDataTypeToString` to accept `const DLDataType*` (pointer) instead of `DLDataType` (by-value), fixing ABI compatibility issues on WebAssembly/Emscripten where passing small C structs by value across the FFI boundary has inconsistent calling conventions.
- Introduces a compile-time flag `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` (default `0`) and wires it into the `TVM_FFI_THROW` macro, allowing all exception throws to optionally log to stderr before throwing -- useful for debugging in environments like WASM where exception backtraces may be lost.

## Impact
- API: **Breaking C ABI change** to `TVMFFIDataTypeToString`. The first parameter changes from `DLDataType` (4-byte struct, pass-by-value) to `const DLDataType*` (pointer). All language bindings calling this C API function must be updated to pass a pointer instead of a value. Affected callers: C++ wrapper `DLDataTypeToString` in `include/tvm/ffi/dtype.h` (updated in this commit), Python/Cython bindings (`python/tvm_ffi/cython/dtype.pxi`), Rust bindings (`rust/tvm-ffi-sys/src/c_api.rs`, `rust/tvm-ffi/src/dtype.rs`).
- Flags/config: New compile-time macro `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` (default `0`). When set to `1`, every `TVM_FFI_THROW` invocation logs the full error message to stderr before throwing. This does not affect `TVM_FFI_LOG_AND_THROW` which always logs regardless.
- Data formats/schemas: none

## Design Elements

Design elements this commit **consumes**:

- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The `TVMFFIDataTypeToString` function is part of the `extern "C"` API surface defined in `c_api.h`. The change modifies one function signature in this surface. The motivation stems from the ABI-level contract: C ABI functions must have portable calling conventions across all target platforms, including WebAssembly/Emscripten, where struct-by-value passing has known ABI inconsistencies (different compilers may pass small structs in registers vs. on the stack differently across the WASM FFI boundary).
- **Error Handling** ([`.knowledge/designs/0007-error-handling.md`](../designs/0007-error-handling.md)): The `TVM_FFI_THROW` macro delegates to `ErrorBuilder` with a `log_before_throw` boolean. Previously this was hardcoded to `false`; now it is controlled by `TVM_FFI_ALWAYS_LOG_BEFORE_THROW`. The `ErrorBuilder` class, `TVM_FFI_LOG_AND_THROW` macro, and the `[[noreturn]]` destructor pattern are all consumed as-is.
- **Safe Call ABI Boundary** ([`.knowledge/ADRs/0005-safe-call-abi-boundary.md`](../ADRs/0005-safe-call-abi-boundary.md)): The `TVMFFIDataTypeToString` implementation uses `TVM_FFI_SAFE_CALL_BEGIN/END` for exception boundary. The change to pointer-based parameter passing does not affect the safe-call mechanism itself but is motivated by the same portability concerns that drive the safe-call design.

Design elements this commit **produces**:

- **Pointer-based struct passing convention for C API**: Establishes the pattern that C API functions receiving small struct types (like `DLDataType`, 4 bytes) should use `const T*` rather than `T` by value for ABI portability. This is specifically motivated by Emscripten/WASM where struct-by-value calling conventions are fragile. The existing `TVMFFIDataTypeFromString` already uses `DLDataType*` for its output parameter; this commit aligns the input parameter convention. Future C API functions that accept `DLDataType`, `DLDevice`, or other small structs should follow this pointer-based convention.
- **`TVM_FFI_ALWAYS_LOG_BEFORE_THROW` debug flag**: A compile-time toggle for environments where exception backtraces are unreliable (e.g., WASM, embedded). When enabled, every `TVM_FFI_THROW` logs the full error message to stderr before throwing, ensuring the error is visible even if the exception is swallowed or the backtrace mechanism is unavailable. This is distinct from `TVM_FFI_LOG_AND_THROW` which is used at specific call sites where logging is always desired.

## Reflection

### Design docs to write
- **Update `.knowledge/designs/0001-c-abi.md`**: Add a subsection under "Contracts, Assumptions and Invariants" documenting the **pointer-based struct passing convention**: C API functions should accept small struct parameters (e.g., `DLDataType`, `DLDevice`) via `const T*` rather than `T` by value, to ensure ABI portability across native, WASM/Emscripten, and other targets. Reference this commit as the motivating evidence. This helps future commit mining when reviewing new C API functions to check whether they follow this convention.
- **Update `.knowledge/designs/0007-error-handling.md`**: Add `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` to the "Key Classes, Fields and Interfaces" section as a compile-time flag, and note its relationship to `TVM_FFI_LOG_AND_THROW` (which always logs). This helps future commit mining for error-handling changes to understand the two logging modes.

### ADRs to write
- **`.knowledge/ADRs/0006-pointer-param-for-struct-in-c-api.md`**: Record the decision to pass small C structs by pointer (not by value) in the `extern "C"` API surface.
  - Context: WebAssembly/Emscripten has inconsistent ABI for passing small structs by value across FFI boundaries; different compilers may lower them differently (register vs. stack).
  - Alternatives: (1) pass by value as before -- simpler but breaks WASM interop; (2) flatten struct fields into scalar parameters -- avoids both pointer indirection and struct ABI issues but changes the API surface more invasively.
  - Trade-offs: Pointer-based passing adds one level of indirection (negligible cost for these utility functions) but ensures consistent calling convention across all platforms. It also aligns with the existing pattern for output parameters.
