# [REFACTOR][FFI][Web] Upgrade Web Runtime to new FFI (#17946)

## TL;DR
- Changes `TVMFFIDataTypeToString` C API to accept `const DLDataType*` instead of `DLDataType` by value, fixing ABI compatibility issues (struct-by-value passing varies across ABIs, especially in WebAssembly/Emscripten).
- Adds a new compile-time flag `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` (default 0) that makes `TVM_FFI_THROW` log errors to stderr before throwing, replacing the previous hardcoded `false` for `log_before_throw`.
- Both changes are motivated by web runtime integration where struct passing semantics and error visibility differ from native environments.

## Key Exports

### Changed C API (`include/tvm/ffi/c_api.h`)

**Signature change (ABI-breaking):**
- `TVMFFIDataTypeToString(DLDataType dtype, TVMFFIObjectHandle* out)` changed to `TVMFFIDataTypeToString(const DLDataType* dtype, TVMFFIObjectHandle* out)`. The `DLDataType` argument is now passed by pointer instead of by value. This avoids ABI issues where passing small structs by value has platform-dependent calling conventions (particularly problematic in WebAssembly where Emscripten may lower struct arguments differently than native compilers).

### New Compile-Time Flag (`include/tvm/ffi/error.h`)

**`TVM_FFI_ALWAYS_LOG_BEFORE_THROW`** (default 0):
- When set to 1, all `TVM_FFI_THROW(ErrorKind)` invocations will log the error message to stderr before throwing.
- This replaces the previous hardcoded `false` passed to `ErrorBuilder`'s `log_before_throw_` parameter.
- Useful for environments like WebAssembly where exceptions may not propagate clearly or where stderr logging provides the only debugging channel.
- `TVM_FFI_LOG_AND_THROW` (existing macro) is unaffected and always logs before throwing regardless of this flag.

### Internal Changes

**`include/tvm/ffi/dtype.h`:**
- `DLDataTypeToString()` inline wrapper updated to pass `&dtype` instead of `dtype` to match the new C API signature.

**`src/ffi/dtype.cc`:**
- `TVMFFIDataTypeToString` implementation updated to accept `const DLDataType* dtype` and dereference it (`*dtype`) when calling the internal `DLDataTypeToString_()`.

## Impact
- ABI: Breaking change to `TVMFFIDataTypeToString` signature. All callers (including Cython bindings, Rust FFI, and web runtime) must update to pass a pointer. Within this repo, the only C++ caller (`DLDataTypeToString` in `dtype.h`) is updated in the same commit.
- Behavioral: No functional change to dtype conversion logic. The `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` flag defaults to 0, so error behavior is unchanged unless explicitly opted in at compile time.
- Flags/config: New `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` compile flag joins the existing `TVM_FFI_USE_LIBBACKTRACE` and `TVM_FFI_BACKTRACE_ON_SEGFAULT` flags.

## Design Elements
Design elements this commit consumes:
- **C ABI contract** (from 7d34eb8) -- The `TVMFFIDataTypeToString` function is part of the dtype utility section of the C ABI.
- **ErrorBuilder** (from 7d34eb8) -- The `log_before_throw_` parameter in `ErrorBuilder::ErrorBuilder` is now driven by a macro rather than a literal.

Design elements this commit produces:
- **Pointer-based struct passing convention** -- Establishes a pattern for C API functions to accept small structs (like `DLDataType`, `DLDevice`) by pointer rather than by value, ensuring consistent ABI behavior across native and WebAssembly targets.
- **Configurable error logging** -- The `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` flag provides a compile-time knob for environments where exception-based error reporting is unreliable.

## Usage Examples

### Using the updated TVMFFIDataTypeToString
```cpp
// Before (pre-076ac23):
DLDataType dtype = {kDLFloat, 32, 1};
TVMFFIObjectHandle out;
TVMFFIDataTypeToString(dtype, &out);

// After (076ac23+):
DLDataType dtype = {kDLFloat, 32, 1};
TVMFFIObjectHandle out;
TVMFFIDataTypeToString(&dtype, &out);
```

### Enabling always-log-before-throw for web builds
```cpp
// In a WebAssembly/Emscripten build configuration:
#define TVM_FFI_ALWAYS_LOG_BEFORE_THROW 1
#include <tvm/ffi/error.h>
// Now all TVM_FFI_THROW() calls will log to stderr before throwing.
```
