# Fix TVMFFIDataTypeToString ABI: pass DLDataType by pointer; add TVM_FFI_ALWAYS_LOG_BEFORE_THROW flag

## TL;DR

- `TVMFFIDataTypeToString` C ABI signature changed from pass-by-value (`DLDataType dtype`) to pass-by-pointer (`const DLDataType* dtype`) to fix struct-by-value ABI incompatibility in Web/Wasm (Emscripten) environments. All call sites updated.
- `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` compile-time flag added (default `0`) so `TVM_FFI_THROW` can be configured to always log to stderr before throwing, useful for environments where exceptions are hard to intercept (e.g., Web runtimes).
- Commit message says REFACTOR but the primary change is a C ABI fix with a behavioral configuration knob.

## Key Exports

```python
# CHANGED (ABI-breaking):
# Old: def TVMFFIDataTypeToString(dtype: DLDataType, out: TVMFFIObjectHandle*) -> int: ...
# New:
def TVMFFIDataTypeToString(dtype: "const DLDataType*", out: "TVMFFIObjectHandle*") -> int: ...
    # Interacts with: DLDataTypeToString() (C++ wrapper in dtype.h calls TVMFFIDataTypeToString(&dtype, &out))
    # Invariant: dtype must be a valid non-null pointer to a DLDataType struct
    # Note: Changed to pointer-passing to avoid struct-by-value ABI differences on Wasm/Web (Emscripten)

# NEW compile-time flag (error.h):
TVM_FFI_ALWAYS_LOG_BEFORE_THROW: int = 0  # default; override at compile time
    # Interacts with: TVM_FFI_THROW macro — controls ErrorBuilder third argument (log_before_throw)
    # Extension: define TVM_FFI_ALWAYS_LOG_BEFORE_THROW=1 in compiler flags to force stderr logging
    #            on every throw, even in production builds. Previously only TVM_FFI_LOG_BEFORE_THROW
    #            (the explicit variant macro) did this.

# TVM_FFI_THROW macro (expanded pseudocode):
# TVM_FFI_THROW(ErrorKind) expands to:
#   ErrorBuilder(kind_str, traceback, TVM_FFI_ALWAYS_LOG_BEFORE_THROW).stream()
# Previously hardcoded `false` for the log_before_throw argument.
```

## Impact

- API: **Breaking** — `TVMFFIDataTypeToString` signature changed in the stable C ABI (`c_api.h`). Any non-C++ binding (Python ctypes, Rust `extern "C"`, Web/JS) calling this function by name must update to pass a pointer. The C++ wrapper `DLDataTypeToString` in `dtype.h` is updated and transparent to C++ callers.
- Behavioral: `TVM_FFI_THROW` now passes `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` (default `0`) instead of hardcoded `false`. No behavioral change at default; opt-in behavior change when the flag is set at compile time.
- Flags/config: New `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` preprocessor define (default `0`). Can be set via compiler `-D` flag.
- Data formats/schemas: None.

## Usage Examples

**Before/after for the ABI-breaking signature change:**

```c
// BEFORE (broke on Web/Wasm due to struct-by-value ABI differences):
DLDataType dtype = {2, 32, 1};  // float32
TVMFFIObjectHandle out = NULL;
int rc = TVMFFIDataTypeToString(dtype, &out);  // passed by value — ABI unsafe on wasm

// AFTER (correct for all platforms including Web/Wasm):
DLDataType dtype = {2, 32, 1};
TVMFFIObjectHandle out = NULL;
int rc = TVMFFIDataTypeToString(&dtype, &out);  // pass pointer — ABI safe everywhere
// C++ callers use the wrapper; only bindings that called the C ABI directly are affected.
```

**Using TVM_FFI_ALWAYS_LOG_BEFORE_THROW (compile-time opt-in):**

```cpp
// Build with -DTVM_FFI_ALWAYS_LOG_BEFORE_THROW=1 to get stderr output before each throw:
// In error.h, this expands TVM_FFI_THROW(ValueError) to:
//   ErrorBuilder("ValueError", TVM_FFI_TRACEBACK_HERE, /*log=*/1).stream()
// Useful for Web runtime where exception stack traces are not always surfaced.
TVM_FFI_THROW(ValueError) << "invalid dtype";
// → logs to stderr AND throws
```
