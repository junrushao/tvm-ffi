# Centralize object creation with CreateEmptyObject/HasCreator helpers

## TL;DR
- Adds `CreateEmptyObject()` and `HasCreator()` inline helpers in `function.h` that unify the two-step "check creator, call creator" pattern, trying native `metadata->creator` fast path first, then falling back to `__ffi_new__` type attribute for Python-defined types.
- Deduplicates four call sites in `creator.h`, `init.h`, `reflection_extra.cc`, and `serialization.cc`.
- Qualifies bare `details::` references to `::tvm::ffi::details::` in reflection headers to prevent ADL/lookup ambiguity.

## Key Exports

**`CreateEmptyObject(int32_t type_index) -> ObjectPtr<Object>`** (`creator.h`):
- Tries `metadata->creator` first, falls back to `__ffi_new__` type attribute.

**`HasCreator(int32_t type_index) -> bool`** (`creator.h`):
- Returns true if either native creator or `__ffi_new__` type attribute exists.

## Impact
- API: New public inline helpers (additive).
- Behavioral: Identical behavior; code deduplication only.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
```cpp
// Check if a type has a creator
if (HasCreator(type_index)) {
    ObjectPtr<Object> obj = CreateEmptyObject(type_index);
    // ... populate fields
}
```
