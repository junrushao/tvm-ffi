# Add TVM_FFI_CHECK macro for user-specified error kinds in condition checks
## TL;DR
- Adds `TVM_FFI_CHECK(ErrorKind, cond)` macro to `error.h`, a generalization of `TVM_FFI_ICHECK(x)` that accepts an arbitrary error kind instead of hardcoding `InternalError`.
- Adds three GoogleTest cases (`ValueError`, `IndexError`, `PassingCondition`) validating the new macro's behavior: correct error kind propagation, message formatting with stringified condition, and no-throw on passing conditions.

## Key Exports

```python
# Macro: TVM_FFI_CHECK(ErrorKind, cond)
# Expands to:
#   if (!(cond)) TVM_FFI_THROW(ErrorKind) << "Check failed: (" #cond << ") is false: "
# Usage: TVM_FFI_CHECK(ValueError, x >= 0) << "x must be non-negative, got " << x;
# Interacts with: TVM_FFI_THROW (error.h), ErrorBuilder pattern
# Extension: supports arbitrary error kinds (ValueError, IndexError, TypeError, etc.)
# Invariant: ErrorKind must be a valid token that TVM_FFI_THROW accepts (unquoted kind name)
# Contrast: TVM_FFI_ICHECK(x) always throws InternalError; TVM_FFI_CHECK lets caller pick the kind
```

## Impact
- API: Additive only. New public macro `TVM_FFI_CHECK` in `include/tvm/ffi/error.h`. No existing macros changed.
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_THROW(ErrorKind)` macro and `ErrorBuilder` pattern ([0005-ffi-error-protocol](../design-records/0005-ffi-error-protocol.md)): the new macro delegates to `TVM_FFI_THROW` for the actual error construction and throw.
- `TVM_FFI_ICHECK(x)` macro ([0005-ffi-error-protocol](../design-records/0005-ffi-error-protocol.md)): the new macro is structurally identical except for the parameterized error kind.
- `Error` class and `error.kind()` accessor ([0005-ffi-error-protocol](../design-records/0005-ffi-error-protocol.md)): tests verify the kind is correctly propagated.

Design elements this commit produces:
- `TVM_FFI_CHECK(ErrorKind, cond)` macro: a new check macro in the error protocol's "Check macros" family. Fills the gap between `TVM_FFI_ICHECK` (always `InternalError`) and raw `TVM_FFI_THROW` (no condition-stringification boilerplate).

## Usage Examples
From the test in the same commit (`tests/cpp/test_error.cc`):
```cpp
// Validate input with a specific error kind
int value = -5;
TVM_FFI_CHECK(ValueError, value >= 0) << "Value must be non-negative, got " << value;
// Throws Error with kind()=="ValueError",
// message contains "Check failed: (value >= 0) is false: Value must be non-negative, got -5"

// Bounds checking with IndexError
int index = 10, array_size = 5;
TVM_FFI_CHECK(IndexError, index < array_size)
    << "Index " << index << " out of bounds for array of size " << array_size;
// Throws Error with kind()=="IndexError"

// Passing condition: no throw
TVM_FFI_CHECK(ValueError, true);  // no-op
```
