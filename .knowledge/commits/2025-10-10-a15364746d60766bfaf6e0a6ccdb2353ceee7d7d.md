# Expose Function.__from_extern_c__ for constructing functions from JIT symbols
## TL;DR
- Adds `Function.__from_extern_c__(c_symbol: int, keep_alive_object=None)` static method in Cython that creates an FFI Function from a raw C function pointer (safe-call convention) with an optional keep-alive closure object.
- Enables JIT execution engines to expose compiled symbols as TVM FFI functions without going through the global registry.

## Impact
- API: New `Function.__from_extern_c__` Python API. C API `TVMFFIFunctionCreate` already existed; this is a Python-level exposure.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Function system** (`.knowledge/designs/0004-function-system.md`): `TVMFFIFunctionCreate` C API with `TVMFFISafeCallType` signature.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): Cython `Function` class, `TVMFFIPyObjectDeleter` for closure ref-counting.

Design elements this commit produces:
- **`Function.__from_extern_c__` JIT integration point**: A Python API that bridges raw C function pointers from JIT engines into the FFI Function object system, with proper ref-count management for the keep-alive closure.
