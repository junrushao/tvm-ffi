# Add Function.__from_extern_c__ Python factory to construct Function from a raw C symbol address

## TL;DR
- Adds `Function.__from_extern_c__(c_symbol: int, keep_alive_object=None) -> Function` as a Cython static method on the Python `Function` class, wrapping the existing `TVMFFIFunctionCreate` C ABI.
- Intended for JIT execution engines (e.g., LLVM JIT) that yield a raw function pointer as an integer; the optional `keep_alive_object` keeps the engine alive for the Function's lifetime via `Py_INCREF`/`TVMFFIPyObjectDeleter`.
- Fixes the Cython `base.pxi` declaration of `TVMFFIObject.deleter` to match the current C ABI signature `void (*deleter)(void* self, int flags)`.

## Key Exports

```python
class Function(Object):
    @staticmethod
    def __from_extern_c__(c_symbol: int, keep_alive_object: object = None) -> Function:
        """Construct a Function from a raw C safe_call pointer and optional closure object.

        c_symbol : int
            Integer representation of a TVMFFISafeCallType function pointer.
            The safe_call ABI: (void* handle, const TVMFFIAny* args, int32_t num_args,
                                TVMFFIAny* result) -> int32_t
            First argument (handle) is ignored by the callee.
        keep_alive_object : object
            Optional Python closure kept alive for the Function's lifetime.
            Py_INCREF'd on successful creation; released via TVMFFIPyObjectDeleter on GC.

        # Interacts with: TVMFFIFunctionCreate (C ABI factory)
        # Interacts with: TVMFFIPyObjectDeleter (Python object ref-count cleanup on Function destroy)
        # Invariant: cpp_call == NULL for all extern-C functions (no C++ fast path)
        # Invariant: if TVMFFIFunctionCreate fails and keep_alive_object is not None, Py_DECREF is called
        # Extension: pass any Python object as keep_alive_object — engine, module, ctypes CDLL, etc.
        """
        ...

# int __add_one_c_symbol(void*, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* ret)
#   → int result = args[0].cast<int>() + 1; ret[0] = result; return 0
#
# "testing.get_add_one_c_symbol" -> int64_t  (returns symbol address as int64 for test use)
# Interacts with: TVMFFISafeCallType convention, TVM_FFI_SAFE_CALL_BEGIN/END

# Cython ABI fix (base.pxi):
# OLD: void (*deleter)(TVMFFIObject* self)
# NEW: void (*deleter)(void* self, int flags)
# Aligns Cython extern-from declaration with current C ABI (0001-c-abi, 0002-object-system)
```

## Impact
- API: New static method `Function.__from_extern_c__` on `tvm_ffi.Function`. No existing public API changed.
- Behavioral: none to existing callers.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- `TVMFFIFunctionCreate` C ABI factory (0001-c-abi, 0004-function-system) — wraps a raw `safe_call` pointer into a `FunctionObj`
- `ExternCFunctionObjImpl` / `ExternCFunctionObjNullHandleImpl` (0004-function-system) — the C++ implementations instantiated by `TVMFFIFunctionCreate`
- `TVMFFIPyObjectDeleter` (0013-python-package, 0014-opaque-pyobject) — Python-side deleter registered for `keep_alive_object` cleanup
- `TVMFFISafeCallType` calling convention (0001-c-abi) — the ABI that `c_symbol` must conform to
- `kTVMFFIFunction` type index (0001-c-abi)

Design elements this commit produces:
- `Function.__from_extern_c__` — new Python-side factory method on the Cython `Function` class, completing the Python exposure of `TVMFFIFunctionCreate` for JIT use cases. Documented in `python/tvm_ffi/core.pyi`.

## Usage Examples

End-to-end trace: C++ test symbol → Python call via `__from_extern_c__`.

```python
import sys
import tvm_ffi

# 1. Get address of C symbol (integer, as if returned by a JIT engine)
add_one_sym = tvm_ffi.get_global_func("testing.get_add_one_c_symbol")()

# 2. Construct Function without keep_alive
fadd_one = tvm_ffi.Function.__from_extern_c__(add_one_sym)
assert fadd_one(1) == 2
assert fadd_one(2) == 3

# 3. Construct Function with keep_alive (simulates holding a JIT execution engine alive)
engine = [1, 2, 3]  # stand-in for e.g. llvmlite.ExecutionEngine
base_rc = sys.getrefcount(engine)
fadd_one = tvm_ffi.Function.__from_extern_c__(add_one_sym, engine)
assert sys.getrefcount(engine) == base_rc + 1  # engine ref incremented
fadd_one = None
assert sys.getrefcount(engine) == base_rc      # ref released when Function GC'd
```

## Reflection

### Design docs / ADRs to write or update
- `.knowledge/design-records/0004-function-system.md` — Add `Function.__from_extern_c__` to the Python-side "Key Classes" section under `Function(ObjectRef)`. The C++ `FromExternC` path is already documented; the Python wrapper should reference it. Add a Python usage example showing the JIT engine keep-alive pattern (matches the new test). A sequence diagram (Mermaid) showing Python int → Cython cast → `TVMFFIFunctionCreate` → `ExternCFunctionObjImpl`/`NullHandleImpl` would clarify the two branches.
- `.knowledge/design-records/0001-c-abi.md` — Confirm the `TVMFFIObject.deleter` signature is listed as `void (*deleter)(void* self, int flags)`. The design-index already reflects this; verify the full record body matches too.

### Stale knowledge references
- `python/tvm_ffi/cython/base.pxi` previously declared `void (*deleter)(TVMFFIObject* self)` — this was a stale Cython mirror of the C ABI. Fixed in this commit. Any `.knowledge/` files that copied the old signature verbatim would be stale, but the design-index already shows the correct `deleter(void*, int flags)` form, so no `.knowledge/` file staleness at `medium`+ severity. Severity: `low`.
