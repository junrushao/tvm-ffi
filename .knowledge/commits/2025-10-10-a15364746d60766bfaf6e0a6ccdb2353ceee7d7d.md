# Expose Python API to construct Function from extern C symbol address
## TL;DR
- Adds `Function.__from_extern_c__(c_symbol, keep_alive_object=None)` static method to the Cython `Function` class, enabling Python code to construct a `Function` from a raw C function pointer (as `int`) and an optional keep-alive object.
- Fixes the Cython `base.pxi` declaration of `TVMFFIObject.deleter` to match the current C ABI signature `void (*deleter)(void* self, int flags)`.
- Adds a C++ test helper `testing.get_add_one_c_symbol` and Python test `test_function_from_c_symbol` to verify the round-trip.

## Key Exports

**Methods**:
- `Function.__from_extern_c__(c_symbol: int, keep_alive_object: object = None) -> Function` -- Static method on the Cython `Function` class. Wraps a raw `TVMFFISafeCallType` function pointer (passed as Python int) into a `Function` object. When `keep_alive_object` is `None`, creates a function with no closure (`self=NULL, deleter=NULL`). When provided, increments the Python object's refcount and uses `TVMFFIPyObjectDeleter` as the deleter.

**Functions (testing)**:
- `testing.get_add_one_c_symbol() -> int` -- Returns the address of `__add_one_c_symbol` as `int64_t`. For testing only.

**Cython declaration fix**:
- `TVMFFIObject.deleter`: `void (*deleter)(TVMFFIObject* self)` changed to `void (*deleter)(void* self, int flags)` in `base.pxi`, aligning with the current C ABI.

## Impact
- API: Additive. New `Function.__from_extern_c__` method exposed in Python. No existing API changed.
- Behavioral: None. Existing behavior unchanged.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **TVMFFIFunctionCreate** C API ([0001-c-abi-layer.md](../designs/0001-c-abi-layer.md)) -- called to create the underlying FunctionObj from `(self, safe_call, deleter)` triple
- **TVMFFISafeCallType** calling convention ([0001-c-abi-layer.md](../designs/0001-c-abi-layer.md)) -- the `c_symbol` parameter must point to a function matching this signature
- **TVMFFIPyObjectDeleter** (Cython helper in `tvm_ffi_python_helpers.h`) -- used as the deleter when `keep_alive_object` is provided, calls `Py_DECREF` on the captured PyObject
- **TVM_FFI_SAFE_CALL_BEGIN/END** macros ([0004-function-system.md](../designs/0004-function-system.md)) -- used in test `__add_one_c_symbol` function
- **Function::FromExternC** C++ API ([0004-function-system.md](../designs/0004-function-system.md)) -- the Python method is the cross-language mirror of this C++ static method

Design elements this commit produces:
- **Function.__from_extern_c__** -- Python-level entry point for constructing Functions from JIT-compiled or externally provided C function pointers. This is the Python binding counterpart to `Function::FromExternC` in C++.

## Usage Examples

**Context**: Constructing a Python `Function` from a JIT engine that provides a C function pointer.

```python
# C++ side registers a test helper that returns a raw function pointer as int64
# testing.get_add_one_c_symbol() -> int (address of a TVMFFISafeCallType function)

import tvm_ffi

# Get raw C function pointer from JIT engine (or test helper)
add_one_c_symbol = tvm_ffi.get_global_func("testing.get_add_one_c_symbol")()

# Construct Function without keep-alive (no closure)
fadd_one = tvm_ffi.Function.__from_extern_c__(add_one_c_symbol)
assert fadd_one(1) == 2

# Construct Function with keep-alive (e.g., JIT engine stays alive)
engine = SomeJITEngine()
fadd_one = tvm_ffi.Function.__from_extern_c__(add_one_c_symbol, engine)
# engine's refcount is incremented; dropping fadd_one decrements it
```

The C function pointer must conform to `TVMFFISafeCallType` signature and ignore the first `self` argument:
```c
int my_func(void* /*unused_self*/, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* ret) {
    TVM_FFI_SAFE_CALL_BEGIN();
    // ... use args, write to ret ...
    TVM_FFI_SAFE_CALL_END();
}
```
