# Expose Python API to construct Function from extern C symbol and optional keep-alive object

## TL;DR
- Adds `Function.__from_extern_c__(c_symbol, keep_alive_object)` static method to the Cython `Function` class, enabling Python code to wrap a raw C function pointer (as an integer) into a first-class `Function` object.
- The optional `keep_alive_object` parameter captures an arbitrary Python object (e.g., a JIT execution engine) whose ref count is incremented and tied to the `Function` lifetime.
- Fixes a stale Cython declaration: `TVMFFIObject.deleter` signature updated from `(TVMFFIObject* self)` to `(void* self, int flags)` to match the C ABI.

## Impact
- API: Adds new `Function.__from_extern_c__` static method to the Python `Function` class. No existing APIs changed.
- Behavioral: None -- purely additive.
- Flags/config: None.
- Data formats/schemas: None.

Side fix: The Cython `TVMFFIObject.deleter` field signature was corrected from `void (*deleter)(TVMFFIObject* self)` to `void (*deleter)(void* self, int flags)`, aligning it with the C ABI change made in commit 24125d0. This is a declaration-only fix (the underlying C struct was already correct); the old declaration was stale but happened not to be called from Cython code directly.

## Design Elements
Design elements this commit consumes:
- `TVMFFIFunctionCreate` C API -- the low-level function for constructing a `FunctionObj` from `(self, safe_call, deleter)` triple ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md), [0004-ffi-function-system](../design-records/0004-ffi-function-system.md))
- `TVMFFISafeCallType` -- the C ABI safe-call signature `int(void*, TVMFFIAny*, int32_t, TVMFFIAny*)` ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md))
- `TVMFFIPyObjectDeleter` -- the Python object deleter callback used when `keep_alive_object` is non-None ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md))
- `ExternCFunctionObjImpl` / `ExternCFunctionObjNullHandleImpl` -- the C++ backing objects selected by `TVMFFIFunctionCreate` depending on whether a closure handle is provided ([0004-ffi-function-system](../design-records/0004-ffi-function-system.md))

Design elements this commit produces:
- `Function.__from_extern_c__` -- new Python-side construction path for `Function` from raw C symbol address. This is the Python counterpart of C++ `Function::FromExternC`, but takes an integer address rather than a typed pointer, and manages Python object lifetimes via `Py_INCREF`/`TVMFFIPyObjectDeleter`.

## Usage Examples
Constructing a Function from a C symbol obtained via JIT or global function lookup:
```python
import tvm_ffi

# Get a C function pointer (e.g., from a JIT engine)
add_one_symbol = tvm_ffi.get_global_func("testing.get_add_one_c_symbol")()

# Wrap as Function with no keep-alive
fadd_one = tvm_ffi.Function.__from_extern_c__(add_one_symbol)
assert fadd_one(1) == 2

# Wrap with a keep-alive object (e.g., the JIT engine)
engine = SomeJITEngine()
fadd_one = tvm_ffi.Function.__from_extern_c__(add_one_symbol, engine)
# engine's ref count is incremented; it stays alive as long as fadd_one exists
assert fadd_one(2) == 3
del fadd_one  # engine's ref count is decremented
```
