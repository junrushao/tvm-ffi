# Fix import issue in torch_c_dlpack_ext addon and improve prebuilt loading
## TL;DR
- Fix `torch_c_dlpack_ext/__init__.py` to use relative import (`from . import core`) instead of bare `import core`, which failed as a top-level import when the package was installed.
- Fix `_optional_torch_c_dlpack.py` to verify that `__c_dlpack_exchange_api__` was actually set after importing the addon (not just that the import succeeded), then fall through to JIT path if not.
- Set `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` env var during build_backend's subprocess call to prevent circular import when building the addon wheel.
- Bump `torch_c_dlpack_ext` version from 0.1.0 to 0.1.1.

## Key Exports
None — no new public API surfaces.

## Impact
- API: none
- Behavioral: Fixes the prebuilt `torch_c_dlpack_ext` package to actually work when pip-installed. Previously the bare `import core` would fail, and even if it succeeded, the loading code didn't verify the attribute was set before returning.
- Flags/config: `TVM_FFI_DISABLE_TORCH_C_DLPACK` env var (used internally during addon build to prevent circular loading)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **torch-c-dlpack-ext addon** — the prebuilt DLPack extension package, introduced in f703a0cf. Relates to `.knowledge/designs/0017-dlpack-interop.md`.
- **Prebuilt-first loading strategy** in `_optional_torch_c_dlpack.py` — the three-tier loading order.

Design elements this commit mutates:
- **Prebuilt-first loading logic** — now verifies `hasattr(torch.Tensor, "__c_dlpack_exchange_api__")` after import succeeds, falling through to JIT path if the attribute was not actually set. Removes dead `todo` comment and ellipsis placeholder.

**Invariant violated before fix**:
1. `import core` (bare) in `__init__.py` only works as an implicit relative import in Python < 3; in Python 3 it fails with `ModuleNotFoundError`.
2. `_optional_torch_c_dlpack.py` returned `None` immediately after a successful `import torch_c_dlpack_ext` without verifying the attribute was actually patched.
3. Building the addon wheel triggered recursive torch DLPack loading during `tvm_ffi` import.

**Invariants restored**:
1. Relative import ensures correct module resolution.
2. Post-import verification ensures the attribute exists before declaring success.
3. `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` env var breaks the circular dependency during build.
