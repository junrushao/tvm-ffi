# Fix import and circular-load bugs in torch_c_dlpack_ext addon
## TL;DR
- Fixed a broken `import core` (bare module import) in `torch_c_dlpack_ext/__init__.py` by changing it to a relative import (`from . import core`), which prevented the prebuilt package from loading correctly.
- Added `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` environment variable to the build subprocess in `build_backend.py`, preventing a circular import loop where building the addon triggers the `_optional_torch_c_dlpack` loader which in turn tries to import the not-yet-built addon.
- Changed the post-import check in `_optional_torch_c_dlpack.py` from an unconditional `return None` after importing `torch_c_dlpack_ext` to a conditional check for `__c_dlpack_exchange_api__`, so the JIT fallback path still runs if the prebuilt package imported but did not actually set the attribute.
- Bumped `torch_c_dlpack_ext` version from 0.1.0 to 0.1.1.

## Key Exports
None -- this is a bugfix with no new public API surface.

## Impact
- API: None
- Behavioral: The prebuilt `torch_c_dlpack_ext` package now loads correctly as a Python package. Previously, `import core` failed at runtime because it resolved as a top-level module rather than the package-local `core` submodule. Additionally, building the addon via `build_backend.py` no longer triggers the circular import of `_optional_torch_c_dlpack` (which would attempt to import the not-yet-built `torch_c_dlpack_ext`).
- Flags/config: `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` environment variable is now set during the build subprocess invocation in `build_backend.py` to break the circular dependency.
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **DLPack Exchange API protocol** ([ADR-0015](../ADRs/0015-dlpack-exchange-api-struct.md)): The `__c_dlpack_exchange_api__` attribute on `torch.Tensor` is the signal that the DLPack C fast-path is available. This commit makes the prebuilt-package path and the JIT-fallback path both check for this attribute correctly.
- **`TVM_FFI_DISABLE_TORCH_C_DLPACK` environment variable**: Module-level guard in `_optional_torch_c_dlpack.py` (line 130) that disables the automatic loader. This commit uses it in the build subprocess to prevent circular loading.
- **torch_c_dlpack_ext addon packaging** ([0013-packaging](../designs/0013-packaging.md)): Custom build backend wrapping setuptools that conditionally compiles the native library during wheel build.

Design elements this commit produces:
- None -- purely a fix to existing loading/packaging logic.

## Usage Examples
**Before (broken)**:
```python
# torch_c_dlpack_ext/__init__.py
import core  # <-- fails: "core" is not a top-level module

# _optional_torch_c_dlpack.py
import torch_c_dlpack_ext  # succeeds (if prebuilt)
return None                # <-- always returns, even if the ext didn't set __c_dlpack_exchange_api__

# build_backend.py
subprocess.run([sys.executable, "-m", "tvm_ffi.utils._build_optional_torch_c_dlpack", ...])
# <-- tvm_ffi.__init__ imports _optional_torch_c_dlpack which tries to import
#     the not-yet-built torch_c_dlpack_ext -> circular failure
```

**After (fixed)**:
```python
# torch_c_dlpack_ext/__init__.py
from . import core  # <-- correct relative import

# _optional_torch_c_dlpack.py
import torch_c_dlpack_ext
if hasattr(torch.Tensor, "__c_dlpack_exchange_api__"):
    return None    # <-- only skip JIT fallback if the attribute was actually set

# build_backend.py
subprocess.run([...], env={**os.environ, "TVM_FFI_DISABLE_TORCH_C_DLPACK": "1"})
# <-- prevents circular import during build
```
