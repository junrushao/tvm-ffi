# Fix CMake include path to use CMAKE_CURRENT_LIST_DIR so builds as subdirectory work correctly

## TL;DR

- `CMakeLists.txt` changed `${CMAKE_SOURCE_DIR}/cmake/Utils/DetectTargetTriple.cmake` to `${CMAKE_CURRENT_LIST_DIR}/cmake/Utils/DetectTargetTriple.cmake`.
- `CMAKE_SOURCE_DIR` always points to the top-level project, so when tvm-ffi is included as a `add_subdirectory(...)` dependency from another CMake project it resolves to the wrong root; `CMAKE_CURRENT_LIST_DIR` resolves relative to the file being processed.
- All other `include(...)` calls in `CMakeLists.txt` already used `CMAKE_CURRENT_LIST_DIR`; this was the one inconsistency.
