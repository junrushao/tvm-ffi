# Fix CMake include path to use CMAKE_CURRENT_LIST_DIR for subdir builds
## TL;DR
- Changed `${CMAKE_SOURCE_DIR}` to `${CMAKE_CURRENT_LIST_DIR}` for the `DetectTargetTriple.cmake` include, fixing builds where tvm-ffi is used as a CMake subdirectory of another project.

## Key Exports
None

## Impact
- API: none
- ABI: none
- Behavioral: When tvm-ffi is consumed via `add_subdirectory()` from a parent CMake project, `CMAKE_SOURCE_DIR` resolves to the parent project's root rather than the tvm-ffi root. This caused the `DetectTargetTriple.cmake` include to fail. `CMAKE_CURRENT_LIST_DIR` always resolves relative to the file containing the `include()` call, which is the correct behavior regardless of build hierarchy.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- CMake best practice: `CMAKE_CURRENT_LIST_DIR` vs `CMAKE_SOURCE_DIR` for relocatable includes
- Adjacent lines already used `CMAKE_CURRENT_LIST_DIR` for `AddLibbacktrace.cmake` and `Library.cmake`, making this an inconsistency fix

Design elements this commit produces:
- Consistent use of `CMAKE_CURRENT_LIST_DIR` across all `include()` directives in the root `CMakeLists.txt`, enabling reliable subdirectory consumption
