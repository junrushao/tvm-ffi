# Widen load_module to accept PathLike objects alongside strings
## TL;DR
- `load_module(path)` now accepts `str | os.PathLike` (e.g., `pathlib.Path`) instead of only `str`.
- Uses `os.fspath()` to normalize the path before forwarding to the C++ `_ffi_api.ModuleLoadFromFile`.
- Docstring updated with examples showing both string and `pathlib.Path` usage.

## Key Exports
```python
# Signature change (old -> new):
# def load_module(path: str) -> Module
def load_module(path: str | PathLike) -> Module:
    """Load module from file. Accepts string or PathLike (e.g., pathlib.Path)."""
    path = fspath(path)  # normalize to str
    return _ffi_api.ModuleLoadFromFile(path)
    # Interacts with: Module (0011), _ffi_api.ModuleLoadFromFile (C++ "ffi.ModuleLoadFromFile")
```

## Impact
- API: `load_module` signature widened from `str` to `str | PathLike`. Fully backward-compatible; existing callers passing `str` are unaffected. New callers can pass `pathlib.Path` directly.
- Behavioral: none (identical runtime behavior after `fspath()` normalization)
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Using `pathlib.Path` with `load_module`:
```python
from pathlib import Path
import tvm_ffi

# String path (existing usage)
mod = tvm_ffi.load_module("path/to/module.so")

# PathLike (new usage enabled by this commit)
mod = tvm_ffi.load_module(Path("path/to/module.so"))

# Any os.PathLike-compatible object works
mod.func_name(*args)
```
