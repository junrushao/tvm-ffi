# Upgrade Python dependency configuration: dev group, Ninja enforcement, torch Windows fix
## TL;DR
- Adds a `dev` dependency-group in `pyproject.toml` with common development tools (ruff, mypy, clang-format, ipdb, pre-commit, etc.) for local development convenience.
- Enforces Ninja as the build generator in scikit-build-core (`ninja.make-fallback = false`), removing the Makefile fallback.
- Re-adds `torch` to the Windows test dependency (previously excluded via `sys_platform != 'win32'`) and adds a preemptive `import torch` hack in `tvm_ffi/__init__.py` to work around a symbol conflict on Windows CI (Python 3.12, torch 2.9.0).

## Impact
- API: None
- Behavioral: `tvm_ffi` now attempts `import torch` at package init time (silently caught if torch is absent). This ensures torch's DLL symbols are loaded before tvm_ffi's Cython extension on Windows, preventing a narrow symbol conflict.
- Flags/config: `ninja.make-fallback = false` in `[tool.scikit-build]` means builds will fail if Ninja is not available, rather than falling back to Make. `ninja` is added to `build-system.requires` to compensate.
