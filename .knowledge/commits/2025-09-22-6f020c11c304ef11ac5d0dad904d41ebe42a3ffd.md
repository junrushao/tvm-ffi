# Rename traceback to backtrace, change storage order to most-recent-call-first, update TVMFFIErrorCreate

## TL;DR
- Renames "traceback" to "backtrace" across the C ABI, C++ API, Cython bindings, and Python error module. The new term is used for the internal storage representation; "traceback" is reserved for the Python-style most-recent-call-last rendering.
- Changes the default backtrace storage order to **most-recent-call-first** (reverse of Python traceback convention). This enables O(1) append when propagating errors up the stack. A new `TracebackMostRecentCallLast()` method reverses lines for display.
- Adds `TVMFFIBacktraceUpdateMode` enum with `kTVMFFIBacktraceUpdateModeReplace` and `kTVMFFIBacktraceUpdateModeAppend` modes.
- Changes `TVMFFIErrorCreate` return type from `TVMFFIObjectHandle` to `int` (0=success, nonzero=failure), with a new `TVMFFIObjectHandle* out` parameter, matching the standard C API error convention.
- Renames `TVMFFITraceback` to `TVMFFIBacktrace` (C ABI function for capturing stack backtraces).
- Renames source files: `traceback.cc` -> `backtrace.cc`, `traceback.h` -> `backtrace_utils.h`, `traceback_win.cc` -> `backtrace_win.cc`.
- This is an ABI-breaking change; version bumped to `0.1.0b4`.

## Impact
- API: Breaking ABI change. `TVMFFIErrorCell.traceback` renamed to `backtrace`, `update_traceback` renamed to `update_backtrace` with new `update_mode` parameter. `TVMFFITraceback` renamed to `TVMFFIBacktrace`. `TVMFFIErrorCreate` signature changed from returning handle to returning error code with out-parameter. C++ `Error::traceback()` renamed to `Error::backtrace()`, `UpdateTraceback` renamed to `UpdateBacktrace`. Python `Error.traceback` property renamed to `Error.backtrace`.
- Behavioral: Backtrace is now stored most-recent-call-first internally. `Error::what()` and Python error rendering both reverse lines before display, so user-visible output is unchanged (still shows "most recent call last"). The `_traceback_to_backtrace_str` Python function now reverses lines before storing. The `_with_append_backtrace`/`_parse_backtrace` Python functions iterate in forward order (no longer `reversed()`) since storage order already matches.
- Flags/config: None new. Version bumped from `0.1.0b3` to `0.1.0b4`.
- Data formats/schemas: The in-memory format of error backtrace strings is reversed. Any code reading `TVMFFIErrorCell.backtrace` directly (not through `Error::what()` or Python rendering) will see most-recent-call-first order.

## Design Elements
Design elements this commit consumes:
- **Error system** (`.knowledge/designs/0005-error-system.md`): ErrorObj, Error, ErrorBuilder, TVMFFIErrorCell, TVM_FFI_THROW macro, TLS error propagation
- **C ABI** (`.knowledge/designs/0001-c-abi.md`): TVMFFIErrorCell layout, TVMFFIErrorCreate, TVMFFITraceback
- **Python bindings** (`.knowledge/designs/0012-python-bindings.md`): Cython Error class, cross-language traceback reconstruction

Design elements this commit produces:
- **Backtrace storage convention**: Backtraces are stored most-recent-call-first to enable O(1) append during error propagation. The display layer (`TracebackMostRecentCallLast`, Python rendering) reverses lines for Python-style output.
- **TVMFFIBacktraceUpdateMode enum**: Explicit mode parameter for replacing vs appending backtrace content, eliminating ambiguity in the update API.
- **Safer TVMFFIErrorCreate**: Returns error code instead of handle, catching `bad_alloc` gracefully. Does not set TLS error on failure (avoids infinite recursion during error object creation).

## Usage Examples

### C++ error throwing (unchanged user experience)
```cpp
TVM_FFI_THROW(ValueError) << "Expected non-negative, got " << x;
// Internally: ErrorBuilder captures TVMFFIBacktrace (was TVMFFITraceback)
// Backtrace stored most-recent-call-first
// Error::what() calls TracebackMostRecentCallLast() for display
```

### Python error propagation (backtrace append)
```python
# When a C++ error crosses back into Python and then re-enters C++:
# 1. C++ throws Error with backtrace (most-recent-call-first)
# 2. Python catches, adds Python frames via update_backtrace
#    (Python frames also stored most-recent-call-first, appended to end)
# 3. py_error() reverses for display via _with_append_backtrace -> _parse_backtrace
```

### TVMFFIErrorCreate (new signature)
```c
TVMFFIByteArray kind = {"ValueError", 10};
TVMFFIByteArray message = {"bad value", 9};
TVMFFIByteArray backtrace = {"", 0};
TVMFFIObjectHandle out = NULL;
int ret = TVMFFIErrorCreate(&kind, &message, &backtrace, &out);
if (ret != 0) {
    // Memory allocation failed -- report MemoryError via logger
}
```
