# Rename traceback→backtrace throughout, flip storage order to most-recent-first, and add append mode for incremental error propagation

## TL;DR
- Renames every `traceback` symbol to `backtrace` across C ABI, C++ headers, Cython bindings, and Python (`TVMFFITraceback` → `TVMFFIBacktrace`, `update_traceback` → `update_backtrace`, `traceback_data_` → `backtrace_data_`, `src/ffi/traceback.*` → `src/ffi/backtrace.*`, etc.).
- Flips the in-memory storage order from most-recent-call-last to **most-recent-call-first**; rendering is unchanged (user-visible output still prints most-recent-call-last) via new `TracebackMostRecentCallLast()` reversal utility.
- Adds `TVMFFIBacktraceUpdateMode` enum (`kReplace=0`, `kAppend=1`) to `update_backtrace` so callers can incrementally append frames without re-allocating; `TVMFFIErrorCreate` signature changes to return `int` (0=ok, -1=OOM) plus `out` parameter.
- Bumps package version `0.1.0b4` → `0.1.0b5` (explicit ABI break acknowledged in commit message).

## Impact
- API: **Breaking ABI change** (version bumped b4→b5). `TVMFFITraceback` → `TVMFFIBacktrace`, `TVMFFIErrorCreate` signature change (return type `int` + output param), `TVMFFIErrorCell::traceback` → `backtrace`, `update_traceback` function pointer signature gains `update_mode` param. All callers of these C symbols must update.
- Behavioral: In-memory backtrace order flipped to most-recent-first; user-visible rendered output unchanged (still Python-style most-recent-last). `update_backtrace` now supports append mode enabling O(1) incremental frame appending without reallocation.
- Flags/config: `TVM_FFI_BACKTRACE_ON_SEGFAULT` cmake option description string updated; env var `TVM_TRACEBACK_LIMIT` (used in `GetBacktraceLimit`) name unchanged.
- Data formats/schemas: Stored backtrace byte string now has reversed line order vs. prior versions; any serialized or cached error objects will have changed line ordering.

## Usage Examples

Cross-layer trace (C++ throw → Python render, unchanged user-visible behavior):

```cpp
// C++ side: throw with backtrace (most-recent-first internally)
TVM_FFI_THROW(ValueError) << "bad input";
// expands to: ErrorBuilder("ValueError", TVMFFIBacktrace(__FILE__,__LINE__,func,0), ...) << "msg"
// TVMFFIBacktrace returns frames most-recent-first

// Error::what() renders via TracebackMostRecentCallLast() -> most-recent-last for user
```

```python
# Python side: catching C++ error (user sees Python-style traceback, unchanged)
try:
    some_ffi_call()
except ValueError as e:
    # e.__traceback__ contains the reversed C++ frames appended before Python frames
    traceback.print_exc()
    # Output format unchanged: "Traceback (most recent call last): ..."
```

Append mode (new capability):

```cpp
// Incrementally append backtrace as error propagates up
Error err(kind, message, initial_backtrace);
// ... propagate across FFI boundary ...
const TVMFFIByteArray* extra = TVMFFIBacktrace(nullptr, 0, nullptr, 0);
err.UpdateBacktrace(extra, kTVMFFIBacktraceUpdateModeAppend);
// backtrace_data_ string gets extra frames appended without realloc
```
