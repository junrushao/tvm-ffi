# Introduce DLPack dtype protocol: __dlpack_data_type__() for dtype argument conversion

## TL;DR
- Any Python object with a `__dlpack_data_type__()` method returning `(type_code, bits, lanes)` is now accepted as a `dtype` argument to TVM FFI packed functions.
- `dtype._tvm_ffi_dtype` slot renamed from `__tvm_ffi_dtype__` (double-underscore mangled) to `_tvm_ffi_dtype` (single-underscore private).
- New `dtype.from_dlpack_data_type(tuple)` static factory method added.

## Impact
- API: New `dtype.from_dlpack_data_type()` static method. Breaking rename: `dtype.__tvm_ffi_dtype__` → `dtype._tvm_ffi_dtype` (was dunder-mangled).
- Behavioral: Any object implementing `__dlpack_data_type__()` is now transparently accepted as a dtype argument in packed function calls.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetterFactory_` dispatch chain (see `.knowledge/design-records/0016-py-ffi-call-dispatch.md`).
- `core.DataType` / `kTVMFFIDataType` type index (see `.knowledge/design-records/0007-containers.md`).

Design elements this commit produces:
- **DLPack dtype protocol**: any object with `__dlpack_data_type__() -> tuple[int, int, int]` is accepted as a dtype argument. Detected via `hasattr(arg_class, "__dlpack_data_type__")` in the setter factory.

## Usage Examples

```python
# Any object implementing __dlpack_data_type__ is accepted as dtype arg:
class DLPackDataTypeProtocol:
    def __init__(self, dlpack_data_type: tuple[int, int, int]) -> None:
        self.dlpack_data_type = dlpack_data_type

    def __dlpack_data_type__(self) -> tuple[int, int, int]:
        return self.dlpack_data_type

fecho = tvm_ffi.get_global_func("testing.echo")
x = DLPackDataTypeProtocol((0, 32, 1))  # float32
y = fecho(x)  # y == tvm_ffi.dtype("float32")
```
