# Add __dlpack_data_type__ protocol support for dtype ingestion from arbitrary types

## TL;DR
- Introduces the `__dlpack_data_type__` protocol: any Python object whose class defines `__dlpack_data_type__() -> tuple[int, int, int]` is now automatically converted to `DLDataType` when passed as an FFI function argument, via a new Cython arg setter `TVMFFIPyArgSetterDLPackDataTypeProtocol_`.
- Adds `dtype.from_dlpack_data_type(tuple[int, int, int]) -> dtype` static factory method for explicit construction of `tvm_ffi.dtype` from a DLPack data type tuple.
- Renames internal slot `dtype.__tvm_ffi_dtype__` to `dtype._tvm_ffi_dtype` (single-underscore private convention) across `_dtype.py`, `dtype.pxi`, and `function.pxi`.

## Key Exports

**Static method**: `dtype.from_dlpack_data_type(dltype_data_type: tuple[int, int, int]) -> dtype`
- Creates a `dtype` from a DLPack data type tuple `(type_code, bits, lanes)`.
- Uses `core._create_dtype_from_tuple` internally.

**Cython arg setter**: `TVMFFIPyArgSetterDLPackDataTypeProtocol_`
- Registered in `TVMFFIPyArgSetterFactory_` for any type whose class has a `__dlpack_data_type__` attribute.
- Calls `arg.__dlpack_data_type__()` to get a `(code, bits, lanes)` tuple and writes them directly into `out.v_dtype`.
- Dispatch priority: after `numpy.dtype` check, before `Exception` check in the factory isinstance chain.

**Protocol**: `__dlpack_data_type__`
- Any Python class implementing `def __dlpack_data_type__(self) -> tuple[int, int, int]` can be passed directly to TVM FFI functions expecting a `DLDataType` argument.

**Rename**: `dtype.__tvm_ffi_dtype__` -> `dtype._tvm_ffi_dtype` (internal slot, not public API)

## Impact
- API: Additive. New static method `dtype.from_dlpack_data_type()` and new protocol `__dlpack_data_type__` for automatic dtype conversion. No breaking changes.
- ABI: None.
- Behavioral: Objects implementing `__dlpack_data_type__` that were previously handled by the fallback setter will now be converted to `DLDataType`. This is a new dispatch path in the arg setter factory, positioned after numpy.dtype and before Exception.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Cython arg setter dispatch system** (`.knowledge/designs/0014-python-bindings.md`): The per-type `TVMFFIPyArgSetter` functor cache and `TVMFFIPyArgSetterFactory_` isinstance chain. This commit adds a new entry for the `__dlpack_data_type__` protocol.
- **dtype class** (`.knowledge/designs/0014-python-bindings.md`): The `dtype(str)` subclass with `_tvm_ffi_dtype` backing field and `core._create_dtype_from_tuple` factory.
- **DLPack dtype representation**: DLDataType struct as `(code, bits, lanes)` tuple -- the standard DLPack interchange representation for data types.
- **Torch/numpy dtype fast paths** (commit d77606a): The existing pattern for external dtype conversion via dedicated arg setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`).

Design elements this commit produces:
- **`__dlpack_data_type__` protocol for dtype ingestion**: A duck-typing protocol where any Python type implementing `__dlpack_data_type__() -> tuple[int, int, int]` is automatically recognized as a dtype argument by the FFI. This generalizes dtype support beyond the hardcoded torch.dtype and numpy.dtype paths to any type that can express itself as a DLDataType tuple. The protocol name aligns with the emerging DLPack dtype standard.
- **`dtype.from_dlpack_data_type` factory**: Explicit construction path for converting a DLPack data type tuple to `tvm_ffi.dtype`, complementing the implicit arg setter dispatch.

## Usage Examples

### Passing a custom dtype object to an FFI function via `__dlpack_data_type__`
**Context**: Any Python object whose class implements `__dlpack_data_type__` is automatically converted to `DLDataType` when passed to a TVM FFI function.
```python
import tvm_ffi

class MyDType:
    def __init__(self, code: int, bits: int, lanes: int) -> None:
        self._code = code
        self._bits = bits
        self._lanes = lanes

    def __dlpack_data_type__(self) -> tuple[int, int, int]:
        return (self._code, self._bits, self._lanes)

fecho = tvm_ffi.get_global_func("testing.echo")
x = MyDType(2, 32, 1)  # float32
y = fecho(x)  # automatically converted to DLDataType via protocol
assert y == tvm_ffi.dtype("float32")
```

### Explicit construction via from_dlpack_data_type
**Context**: When you have a DLPack data type tuple and want to create a `tvm_ffi.dtype` directly.
```python
import tvm_ffi

dtype = tvm_ffi.dtype.from_dlpack_data_type((0, 8, 1))  # int8
assert dtype.type_code == 0
assert dtype.bits == 8
assert dtype.lanes == 1
assert str(dtype) == "int8"
```
