# Add __dlpack_data_type__ protocol for dtype ingestion from arbitrary objects

## TL;DR
- Adds `__dlpack_data_type__` protocol support to the Cython arg setter dispatch: any object implementing `__dlpack_data_type__() -> tuple[int, int, int]` is auto-converted to a `DLDataType` when passed to FFI calls.
- Adds `dtype.from_dlpack_data_type(tuple)` static constructor to create a `tvm_ffi.dtype` from a `(type_code, bits, lanes)` tuple.
- Renames internal slot `__tvm_ffi_dtype__` to `_tvm_ffi_dtype` (single-underscore private convention) across `_dtype.py` and Cython files.

## Impact
- API: Additive. New `dtype.from_dlpack_data_type()` static method. New `__dlpack_data_type__` protocol recognized by arg setter dispatch. The `__tvm_ffi_dtype__` -> `_tvm_ffi_dtype` slot rename is internal and not public API.
- Behavioral: Objects implementing `__dlpack_data_type__()` are now auto-converted to `DLDataType` when passed as FFI function arguments, where previously they would fall through to `OpaquePyObject` wrapping or `ObjectConvertible`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyArgSetterFactory_ dispatch chain** (0012-ffi-python-package): Adds a new branch in the type dispatch cascade, following the established pattern of `hasattr(arg_class, "__protocol__")` checks.
- **`core._create_dtype_from_tuple`** (Cython helper): Used by both the existing `with_lanes()` method and the new `from_dlpack_data_type()` constructor.
- **DLDataType struct** (DLPack spec): The `(type_code, bits, lanes)` tuple maps directly to `DLDataType.{code, bits, lanes}`.

Design elements this commit produces:
- **`__dlpack_data_type__` protocol**: A new duck-typing protocol for dtype exchange. Any class implementing `__dlpack_data_type__() -> tuple[int, int, int]` is auto-recognized by Cython arg dispatch and converted to `DLDataType`. This follows the same pattern as `__tvm_ffi_object__`, `__cuda_stream__`, `__c_dlpack_exchange_api__`, and `__tvm_ffi_opaque_ptr__`.
- **`dtype.from_dlpack_data_type()`**: Python-side constructor for creating `tvm_ffi.dtype` from a DLPack data type tuple, enabling the reverse direction (DLPack -> tvm_ffi.dtype).

## Usage Examples

**Passing an object with `__dlpack_data_type__` protocol to an FFI function:**
```python
import tvm_ffi

class MyDType:
    def __init__(self, type_code: int, bits: int, lanes: int) -> None:
        self._dltype = (type_code, bits, lanes)

    def __dlpack_data_type__(self) -> tuple[int, int, int]:
        return self._dltype

# Any FFI function accepting DLDataType will auto-convert
fecho = tvm_ffi.get_global_func("testing.echo")
x = MyDType(2, 32, 1)  # float32
y = fecho(x)  # y is tvm_ffi.dtype("float32")
assert y == tvm_ffi.dtype("float32")
```

**Constructing dtype from a DLPack data type tuple:**
```python
import tvm_ffi

dt = tvm_ffi.dtype.from_dlpack_data_type((0, 8, 1))  # int8
assert dt.type_code == 0
assert dt.bits == 8
assert dt.lanes == 1
```
