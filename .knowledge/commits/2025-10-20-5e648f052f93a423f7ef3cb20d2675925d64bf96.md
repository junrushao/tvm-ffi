# Introduce dtype protocol via `__dlpack_data_type__`

## TL;DR
- Introduces `__dlpack_data_type__` protocol: any Python object with a `__dlpack_data_type__() -> tuple[int, int, int]` method is automatically converted to a `DLDataType` when passed as an FFI argument, enabling dtype exchange beyond `tvm_ffi.dtype` and `numpy.dtype`.
- Adds `dtype.from_dlpack_data_type(dltype_data_type: tuple[int, int, int]) -> dtype` static factory method for constructing a `tvm_ffi.dtype` from a DLPack data type tuple `(type_code, bits, lanes)`.
- Renames the internal slot `__tvm_ffi_dtype__` to `_tvm_ffi_dtype` (private convention, not a dunder protocol).

## Key Exports

**Protocol**: `__dlpack_data_type__`
- Any class implementing `__dlpack_data_type__(self) -> tuple[int, int, int]` is recognized by the FFI arg setter factory and converted to `DLDataType` via `TVMFFIPyArgSetterDLPackDataTypeProtocol_`.
- Dispatch priority: checked after `numpy.dtype`, before `Exception`.

**Function**: `dtype.from_dlpack_data_type(dltype_data_type: tuple[int, int, int]) -> dtype`
- Static method on `tvm_ffi.dtype`.
- Creates a `dtype` from a raw `(type_code, bits, lanes)` tuple.
- Delegates to `core._create_dtype_from_tuple`.

**Cython setter**: `TVMFFIPyArgSetterDLPackDataTypeProtocol_`
- Signature: `(TVMFFIPyArgSetter* handle, TVMFFIPyCallContext* ctx, PyObject* py_arg, TVMFFIAny* out) -> int`
- Calls `arg.__dlpack_data_type__()`, unpacks the 3-tuple into `out.v_dtype.{code, bits, lanes}`.

**Rename**: `__tvm_ffi_dtype__` -> `_tvm_ffi_dtype` (internal slot on `dtype` class)

## Impact
- API: New protocol `__dlpack_data_type__` enables third-party dtype objects to pass through FFI without explicit conversion. New `dtype.from_dlpack_data_type()` factory method.
- Behavioral: Objects with `__dlpack_data_type__` method are now auto-converted to DLDataType in FFI calls. Previously such objects would fall through to opaque wrapping.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Type-cached FFI arg dispatch** (`function.pxi`, `TVMFFIPyArgSetterFactory_`): The new setter is registered in the dispatch chain. See `.knowledge/designs/0015-python-ffi-call-dispatch.md`.
- **DLDataType struct** (DLPack): The 3-tuple `(code, bits, lanes)` maps directly to `DLDataType.{code, bits, lanes}`.
- **`_create_dtype_from_tuple`** (Cython helper in `dtype.pxi`): Used by `from_dlpack_data_type` to construct `DataType` from components.

Design elements this commit produces:
- **`__dlpack_data_type__` protocol**: A new duck-typing protocol for dtype exchange. Any object implementing this method can pass through FFI as a `DLDataType`. This parallels `__dlpack__`/`__dlpack_device__` for tensor/device exchange.
- **`dtype.from_dlpack_data_type` factory**: Complements the protocol by providing construction from raw tuples.

## Usage Examples

```python
# Protocol usage: pass a custom dtype-like object through FFI
class MyDType:
    def __dlpack_data_type__(self) -> tuple[int, int, int]:
        return (0, 32, 1)  # float32

fecho = tvm_ffi.get_global_func("testing.echo")
result = fecho(MyDType())  # auto-converted to DLDataType, returns dtype("float32")

# Factory usage: construct dtype from DLPack tuple
dt = tvm_ffi.dtype.from_dlpack_data_type((0, 8, 1))
assert str(dt) == "int8"
assert dt.type_code == 0
assert dt.bits == 8
```
