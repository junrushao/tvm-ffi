# Add __dlpack_data_type__ protocol for dtype exchange in FFI arg dispatch
## TL;DR
- Adds `__dlpack_data_type__` protocol support: any Python object implementing `__dlpack_data_type__() -> tuple[int, int, int]` can now be passed as a dtype argument to FFI calls.
- Adds `dtype.from_dlpack_data_type((type_code, bits, lanes))` static factory to construct a `tvm_ffi.dtype` from the DLPack tuple representation.
- Renames internal slot `__tvm_ffi_dtype__` to `_tvm_ffi_dtype` across `_dtype.py`, `dtype.pxi`, and `function.pxi` (private attribute cleanup, no public API change).

## Impact
- API: Additive -- new `dtype.from_dlpack_data_type` static method, new `__dlpack_data_type__` protocol acceptance in FFI arg dispatch. No existing API changed.
- Behavioral: Objects with `__dlpack_data_type__` are now auto-converted to DLDataType in FFI calls instead of falling through to OpaquePyObject/fallback.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetterFactory_` dispatch chain ([0012-python-bindings](../../.knowledge/designs/0012-python-bindings.md)) -- extended with new branch
- `core._create_dtype_from_tuple` -- existing C extension function for creating DataType from components
- `core.DataType` (Cython cdef class) -- the C-level DLDataType wrapper
- `dtype(str)` class pattern -- subclassing `str` with a backing C DataType in a slot
- `DLDataType` struct layout `(code, bits, lanes)` ([0001-c-abi](../../.knowledge/designs/0001-c-abi.md))

Design elements this commit produces:
- **`__dlpack_data_type__` protocol** -- A duck-typing protocol for dtype exchange. Any class implementing `def __dlpack_data_type__(self) -> tuple[int, int, int]` is recognized by the FFI arg dispatch. This aligns with the DLPack data type specification and enables framework-agnostic dtype interop.
- **`dtype.from_dlpack_data_type`** -- Static factory constructor for `dtype` from the DLPack tuple representation.

## Usage Examples

### Passing a custom dtype via `__dlpack_data_type__` protocol
**Context**: Any framework class implementing the protocol is automatically accepted as a dtype argument in FFI calls.

```python
import tvm_ffi

class MyDType:
    def __init__(self, type_code: int, bits: int, lanes: int) -> None:
        self._data = (type_code, bits, lanes)

    def __dlpack_data_type__(self) -> tuple[int, int, int]:
        return self._data

# Pass directly to FFI -- auto-converted via TVMFFIPyArgSetterDLPackDataTypeProtocol_
fecho = tvm_ffi.get_global_func("testing.echo")
x = MyDType(2, 32, 1)  # float32
result = fecho(x)  # returns tvm_ffi.dtype("float32")
assert result == tvm_ffi.dtype("float32")
```

### Constructing dtype from DLPack tuple
```python
import tvm_ffi

# Construct dtype from (type_code=0, bits=8, lanes=1) -> "int8"
dt = tvm_ffi.dtype.from_dlpack_data_type((0, 8, 1))
assert dt.type_code == 0
assert dt.bits == 8
assert dt.lanes == 1
assert str(dt) == "int8"
```
