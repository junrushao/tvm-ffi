# Guard dsymutil behind TVM_FFI_USE_LIBBACKTRACE to prevent unconditional dSYM generation on macOS
## TL;DR
- The `add_dsymutil` CMake function previously ran `dsymutil` on all macOS builds unconditionally. This commit adds a `TVM_FFI_USE_LIBBACKTRACE` guard so dSYM bundles are only generated when libbacktrace support is enabled.
- The commit message references a Metal runtime `GetFunction` fix (#18034), but the actual diff in this repository only contains the CMake guard change. The Metal runtime code likely lives in the upstream TVM repo; this is a partial cherry-pick of the build-system portion.

## Key Exports
None

## Impact
- API: none
- Behavioral: On macOS, `dsymutil` post-build step no longer runs unless `TVM_FFI_USE_LIBBACKTRACE` is ON. Builds without libbacktrace skip dSYM generation, which may slightly speed up build times and avoids potential `dsymutil` failures or `EXC_BREAKPOINT` crashes when the debug symbols are not needed.
- Flags/config: `TVM_FFI_USE_LIBBACKTRACE` CMake option now also controls whether `dsymutil` runs, not just whether libbacktrace is linked.
- Data formats/schemas: none
