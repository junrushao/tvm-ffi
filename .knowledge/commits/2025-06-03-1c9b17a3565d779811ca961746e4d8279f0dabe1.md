# Guard dsymutil post-build step on TVM_FFI_USE_LIBBACKTRACE
## TL;DR
- The `add_dsymutil` CMake function previously ran `dsymutil` on all Apple builds unconditionally. This commit gates it behind `TVM_FFI_USE_LIBBACKTRACE`, so dSYM bundles are only generated when libbacktrace is actually in use.
- **Diff-message discrepancy**: The commit message describes a Metal runtime `GetFunction` fix (PR #18034 from upstream TVM), but the actual diff in this repo only contains the CMake guard change. Analysis is scoped to the actual diff.

## Key Exports
None

## Impact
- API: None
- Behavioral: On macOS builds without `TVM_FFI_USE_LIBBACKTRACE`, `dsymutil` is no longer invoked as a post-build step. This avoids unnecessary dSYM generation and potential build errors when libbacktrace symbols are absent.
- Flags/config: `TVM_FFI_USE_LIBBACKTRACE` now also controls whether `dsymutil` runs, in addition to its existing role controlling libbacktrace compilation.
- Data formats/schemas: None

## Usage Examples
Before (dsymutil runs on all Apple builds):
```cmake
if(APPLE)
  find_program(DSYMUTIL dsymutil)
  ...
endif()
```

After (dsymutil only runs when libbacktrace is enabled):
```cmake
if(APPLE AND TVM_FFI_USE_LIBBACKTRACE)
  find_program(DSYMUTIL dsymutil)
  ...
endif()
```
