# Guard dsymutil invocation on TVM_FFI_USE_LIBBACKTRACE to avoid unnecessary post-build steps
## TL;DR
- Adds `AND TVM_FFI_USE_LIBBACKTRACE` guard to the `add_dsymutil` CMake function so `dsymutil` only runs on Apple when libbacktrace is actually enabled.
- Diff-message alignment note: the commit message describes a Metal runtime `GetFunction` bugfix (upstream PR #18034), but in this repository the only change is the CMake guard. The Metal runtime code does not exist in this repo.

## Key Exports
None

## Impact
- API: none
- Behavioral: On macOS builds without `TVM_FFI_USE_LIBBACKTRACE`, the `dsymutil` post-build step is now skipped, avoiding a needless (and potentially error-prone) debug symbol generation step.
- Flags/config: `TVM_FFI_USE_LIBBACKTRACE` now also gates `dsymutil` invocation in `add_dsymutil()`, not just libbacktrace linkage.
- Data formats/schemas: none
