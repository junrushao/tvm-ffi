# Guard dsymutil post-build step behind TVM_FFI_USE_LIBBACKTRACE on Apple
## TL;DR
- Adds the condition `TVM_FFI_USE_LIBBACKTRACE` to the `add_dsymutil` CMake function's `if(APPLE)` guard, so that `dsymutil` is only run as a post-build step when libbacktrace support is actually enabled.
- This prevents unnecessary (and potentially error-prone) `dsymutil` invocations on Apple platforms when the project is built without libbacktrace, which can cause `EXC_BREAKPOINT` crashes in downstream consumers such as the Metal runtime.

## Impact
- API: None. No public C, C++, or Python API changes.
- Flags/config: The existing CMake option `TVM_FFI_USE_LIBBACKTRACE` (default `ON`, defined in `CMakeLists.txt:22`) now also controls whether `dsymutil` runs as a post-build command on Apple. Previously, `dsymutil` ran unconditionally on all Apple builds regardless of the libbacktrace setting.
- Data formats/schemas: None.

The `dsymutil` step was originally introduced to generate dSYM bundles for libbacktrace-based stack traces on macOS.
- **Error Handling / Backtrace** (`.knowledge/designs/0007-error-handling.md`): The libbacktrace toggle (`TVM_FFI_USE_LIBBACKTRACE`) controls whether native stack traces are captured. The dSYM bundles are specifically needed by libbacktrace to resolve symbols on Apple platforms; without libbacktrace enabled, there is no consumer for the dSYM output.
