# Guard dsymutil invocation behind TVM_FFI_USE_LIBBACKTRACE in cmake/Utils/Library.cmake

## TL;DR

- Tightens the `add_dsymutil` CMake function: `dsymutil` now only runs when both `APPLE` and `TVM_FFI_USE_LIBBACKTRACE` are true, preventing unnecessary symbol-file generation when libbacktrace is disabled.
- No functional change when `TVM_FFI_USE_LIBBACKTRACE` is enabled — behavior is identical to before.

**Note on commit message / diff discrepancy**: The commit message references a Metal runtime `GetFunction` bug (`#18034`), but the actual diff in this repository only modifies `cmake/Utils/Library.cmake`. The CMake guard change is the sole change present in the diff; no Metal runtime files are changed. Analysis is scoped to the diff only.

## Impact

- API: none
- Behavioral: `dsymutil` is no longer invoked on Apple builds where `TVM_FFI_USE_LIBBACKTRACE=OFF`. Previously, it would run on all Apple builds unconditionally, generating dSYM bundles even without a libbacktrace dependency.
- Flags/config: `TVM_FFI_USE_LIBBACKTRACE` CMake option now also gates `dsymutil` invocation.
- Data formats/schemas: none
