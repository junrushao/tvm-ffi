# Fix `add_dsymutil` to only run when libbacktrace is enabled

## TL;DR
- Adds `TVM_FFI_USE_LIBBACKTRACE` guard to the `add_dsymutil` CMake function so that `dsymutil` is only invoked on macOS when libbacktrace support is actually enabled.
- Previously, every macOS build ran `dsymutil` as a post-build step unconditionally, which is unnecessary (and potentially harmful) when libbacktrace is not in use.

## Key Exports
None. This commit changes no public API, ABI, or runtime behavior. It only affects the CMake build system.

## Impact
- API: No change.
- ABI: No change.
- Behavioral: On macOS, `dsymutil` is no longer run as a post-build step unless `TVM_FFI_USE_LIBBACKTRACE` is `ON`. This avoids generating `.dSYM` bundles that serve no purpose when libbacktrace is disabled, reducing build time and disk usage in that configuration.
- Flags/config: The existing `TVM_FFI_USE_LIBBACKTRACE` CMake option now gates the `dsymutil` post-build step in addition to its existing role of enabling the libbacktrace dependency.

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_USE_LIBBACKTRACE` CMake option -- pre-existing flag that controls whether libbacktrace is compiled and linked.
- `add_dsymutil` CMake function (`cmake/Utils/Library.cmake`) -- pre-existing helper that registers a `dsymutil` post-build command for shared library targets on macOS.

Design elements this commit produces:
None. No new design elements are introduced; this is a correctness fix to an existing build-system guard.

## Usage Examples
No usage change. The build commands remain the same:
```bash
cmake . -B build -DTVM_FFI_USE_LIBBACKTRACE=ON   # dsymutil runs on macOS
cmake . -B build -DTVM_FFI_USE_LIBBACKTRACE=OFF   # dsymutil no longer runs on macOS (fixed)
```
