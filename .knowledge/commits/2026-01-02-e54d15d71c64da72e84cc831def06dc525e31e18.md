# Add bounds checking for Tensor::size() and Tensor::stride() methods
## TL;DR
- `Tensor::size(idx)`, `Tensor::stride(idx)`, `TensorView::size(idx)`, and `TensorView::stride(idx)` now throw `IndexError` when the (negative-adjusted) index is out of range `[0, ndim)`.
- Previously, invalid indices caused undefined behavior via out-of-bounds array access on `DLTensor.shape`/`DLTensor.strides`.
- C++ and Python tests added to verify both positive and negative out-of-bounds cases for both `Tensor` and `TensorView`.

## Key Exports

```python
class Tensor(ObjectRef):
    def size(self, idx: int64) -> int64: ...
        # Old: return ptr->shape[idx >= 0 ? idx : (ptr->ndim + idx)]  -- no bounds check
        # New: adjusted_idx = idx >= 0 ? idx : (ndim + idx); check 0 <= adjusted_idx < ndim
        # Invariant: idx in [-ndim, ndim); raises IndexError otherwise
        # Interacts with: TVM_FFI_THROW(IndexError)

    def stride(self, idx: int64) -> int64: ...
        # Same bounds-check pattern as size()
        # Invariant: idx in [-ndim, ndim); raises IndexError otherwise

class TensorView:
    def size(self, idx: int64) -> int64: ...
        # Same bounds-check pattern, applied to tensor_.shape
        # Invariant: idx in [-ndim, ndim); raises IndexError otherwise

    def stride(self, idx: int64) -> int64: ...
        # Same bounds-check pattern, applied to tensor_.strides
        # Invariant: idx in [-ndim, ndim); raises IndexError otherwise
```

## Impact
- API: None -- signatures unchanged; purely behavioral tightening.
- Behavioral: Callers passing out-of-bounds indices that previously caused silent UB will now get an `IndexError` with a descriptive message. This is a correctness improvement but could surface latent bugs in existing code that accidentally passed invalid indices.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `Tensor`/`TensorView` accessor methods (`size()`, `stride()`) from [0006-ffi-containers](../design-records/0006-ffi-containers.md) -- the `idx in [-ndim, ndim)` invariant was already documented but not enforced at runtime.
- `TVM_FFI_THROW(IndexError)` error protocol from [0005-ffi-error-protocol](../design-records/0005-ffi-error-protocol.md).

Design elements this commit produces: None -- it enforces an existing invariant rather than introducing a new design element.

## Usage Examples
**Before** (undefined behavior on out-of-bounds):
```cpp
Tensor t = Empty({2, 3, 4}, float32, cpu);
int64_t bad = t.size(5);   // UB: reads shape[5] past end of 3-element array
int64_t neg = t.size(-10); // UB: reads shape[-7] (negative adjusted index)
```

**After** (clean error):
```cpp
Tensor t = Empty({2, 3, 4}, float32, cpu);
t.size(5);   // throws IndexError: "Index 5 out of bounds for tensor with 3 dimensions"
t.size(-10); // throws IndexError: "Index -10 out of bounds for tensor with 3 dimensions"

// Same behavior for TensorView:
TensorView tv = t;
tv.stride(3);  // throws IndexError
tv.stride(-4); // throws IndexError
```
