# Fix signed-char UB in JSON parser string control-character check

## TL;DR
- `JSONParserContext::NextString` compared `*cur_` (a `char*`) against `' '` (0x20) with a signed comparison; on platforms where `char` is signed, raw UTF-8 continuation and lead bytes (≥ 0x80) are negative, causing any non-ASCII string to be wrongly rejected as "Invalid control character".
- Fix: cast the pointer dereference to `uint8_t` via `*reinterpret_cast<const uint8_t*>(cur_)` at both comparison sites in `json_parser.cc`.
- Regression test added: `TEST(JSONParser, RawUTF8Bytes)` verifies that a raw UTF-8 byte sequence (Chinese characters `\xE4\xB8\xAD\xE6\x96\x87`) round-trips correctly.

## Key Exports

None — no public API change.

```python
# JSONParserContext — internal class in src/ffi/extra/json_parser.cc
# Two comparison sites patched (fast-path and slow-path):

# --- FAST PATH (NextString optimistic scan) ---
# Old: if (*cur_ < ' ' || *cur_ == '\\'):
# New: if (*reinterpret_cast<const uint8_t*>(cur_) < ' ' || *cur_ == '\\'):
#
# --- SLOW PATH (NextStringWithFullHandling loop) ---
# Old: if (*cur_ < ' '):
# New: if (*reinterpret_cast<const uint8_t*>(cur_) < ' '):
#
# Invariant restored: control-character threshold 0x20 must be compared unsigned;
#   signed char on ARM/RISC-V/MSVC defaults to signed — bytes 0x80–0xFF become negative
#   and would pass the < ' ' test, triggering SetErrorInvalidControlCharacter().
# Interacts with: JSONParserContext::SetErrorInvalidControlCharacter(), NextStringWithFullHandling()
```

## Impact
- API: none — internal implementation change only.
- Behavioral: non-ASCII strings (any byte ≥ 0x80) now parse correctly on platforms with signed `char` (ARM, RISC-V, MSVC default). Previously all such strings were rejected.
- Flags/config: none.
- Data formats/schemas: none.

## Usage Examples

Before/after for the broken vs. fixed behavior:

```cpp
// BEFORE (buggy — on signed-char platforms):
// json::Parse("\"中文\"") would call SetErrorInvalidControlCharacter()
// because 0xE4 = 228 is -28 as signed char, which is < ' ' (32)

// AFTER (correct):
// json::Parse("\"\xE4\xB8\xAD\xE6\x96\x87\"").cast<String>()
// → "\xE4\xB8\xAD\xE6\x96\x87"  (the raw UTF-8 bytes for 中文, round-trips correctly)

// Regression test (tests/cpp/extra/test_json_parser.cc):
TEST(JSONParser, RawUTF8Bytes) {
  // Signed-char bug: *cur_ < ' ' is true for any byte >= 0x80 on signed-char platforms
  EXPECT_EQ(json::Parse("\"\xE4\xB8\xAD\xE6\x96\x87\"").cast<String>(),
            "\xE4\xB8\xAD\xE6\x96\x87");
}
```
