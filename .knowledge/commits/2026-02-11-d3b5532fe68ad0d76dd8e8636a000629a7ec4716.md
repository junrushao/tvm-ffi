# Fix JSON parser rejecting UTF-8 strings due to signed char comparison
## TL;DR
- Fixes JSON parser control character check that rejected valid UTF-8 strings on platforms where `char` is signed.
- Casts `*cur_` to `uint8_t` before comparing against `' '` (0x20), preventing bytes >= 0x80 (valid UTF-8 lead/continuation bytes) from being interpreted as negative values.
- Adds regression test with raw Chinese UTF-8 bytes.

## Key Exports
None (internal implementation fix).

## Impact
- API: none
- Behavioral: JSON parser now correctly handles non-ASCII UTF-8 strings on all platforms. Previously, platforms with signed `char` would reject all strings containing non-ASCII characters with "Invalid control character" error.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before (broken on signed-char platforms):
```cpp
// "\xE4\xB8\xAD\xE6\x96\x87" is valid UTF-8 for Chinese characters
json::Parse("\"\xE4\xB8\xAD\xE6\x96\x87\"");  // ERROR: "Invalid control character"
```

After (correct):
```cpp
json::Parse("\"\xE4\xB8\xAD\xE6\x96\x87\"").cast<String>();  // OK: returns Chinese text
```

**Invariant violated**: The comparison `*cur_ < ' '` assumes unsigned char semantics. On signed-char platforms, bytes 0x80-0xFF are negative, satisfying `< ' '` (0x20), causing false positives.

**Invariant restored**: `*reinterpret_cast<const uint8_t*>(cur_) < ' '` ensures the comparison is unsigned, correctly identifying only bytes 0x00-0x1F as control characters.
