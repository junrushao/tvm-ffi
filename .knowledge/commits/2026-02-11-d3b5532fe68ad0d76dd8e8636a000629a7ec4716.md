# Fix JSON parser rejecting non-ASCII UTF-8 strings on signed-char platforms
## TL;DR
- Fixes `src/ffi/extra/json_parser.cc`: two `*cur_ < ' '` comparisons cast to `*reinterpret_cast<const uint8_t*>(cur_) < ' '` to avoid sign-extension of UTF-8 bytes ≥ 0x80 on platforms where `char` is signed.
- Adds regression test `JSONParser.RawUTF8Bytes` that round-trips a raw UTF-8 string (CJK characters `\xE4\xB8\xAD\xE6\x96\x87`).

## Key Exports
None — bugfix restoring existing invariant.

## Impact
- API: none
- Behavioral: `json::Parse` and `json::Stringify` now correctly accept all valid UTF-8 strings including non-ASCII content (CJK, emoji, etc.). Previously these would trigger `SetErrorInvalidControlCharacter()` on signed-char platforms.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `json::Parse` / `json::Stringify` (0010-ffi-json-serialization) — two-layer JSON serialization; this fix restores the invariant that all valid UTF-8 byte sequences in strings are accepted.

Design elements this commit produces: None

## Usage Examples
Before (broken on signed-char platforms):
```cpp
// Would fail: "Invalid control character" error
auto result = json::Parse("\"\xE4\xB8\xAD\"");  // Chinese "中"
```
After (fixed):
```cpp
auto result = json::Parse("\"\xE4\xB8\xAD\xE6\x96\x87\"").cast<String>();
// == "\xE4\xB8\xAD\xE6\x96\x87"  (correctly parses UTF-8)
```
