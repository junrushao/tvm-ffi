# Fix UTF-8 bytes incorrectly rejected as control characters in JSON parser
## TL;DR
- Casts `*cur_` to `unsigned char` (`uint8_t`) before comparing against `' '` (0x20) in two places in `json_parser.cc`
- On platforms where `char` is signed, UTF-8 continuation/lead bytes (>= 0x80) were negative, incorrectly triggering "Invalid control character" errors
- Adds regression test `RawUTF8Bytes` verifying Chinese characters parse correctly

## Key Exports
None -- bugfix only, no new API surface.

## Impact
- API: none
- Behavioral: JSON strings containing non-ASCII UTF-8 text (e.g., CJK characters) now parse correctly on all platforms
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces: none

## Usage Examples
**Before (broken):** `json::Parse("\"中文\"")` throws "Invalid control character" on signed-char platforms.
**After (fixed):** `json::Parse("\"中文\"")` correctly returns the String `"中文"`.
