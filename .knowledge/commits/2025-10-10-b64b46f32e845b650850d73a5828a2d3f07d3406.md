# Enable free-threaded Python build and fix OpaqueObject type registration
## TL;DR
- Adds free-threaded Python (PEP 703 / `Py_GIL_DISABLED`) support: introduces `TVMFFIPyWithGILIfNotFreeThreaded` helper and `TVMFFIPyObjectDeleter` in the C helper header, replacing the Cython `tvm_ffi_pyobject_deleter` that used `with gil`.
- Fixes `OpaqueObject` type registration: was using `ReserveBuiltinTypeIndex` (no parent info), now uses `GetOrAllocTypeIndex` with `parent=kTVMFFIObject` and `type_depth=1`, so `OpaqueObject` is correctly recognized as an Object subtype.
- Simplifies callback return code handling (returns `c_api_ret_code` directly).

## Impact
- API: No new public APIs. Behavioral fix: `OpaqueObject` now passes `isinstance(obj, Object)` checks.
- Flags/config: CI updated to test free-threaded Python. `pyproject.toml` updated for free-threaded build deps.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object system** (`.knowledge/designs/0003-object-system.md`): Type table registration, `type_depth` and parent type index for the type hierarchy.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): Cython callback mechanism, `TVMFFIFunctionCreate` with deleter, `TVMFFIObjectCreateOpaque`.
- **ADR: opaque PyObject fallback** (`.knowledge/ADRs/0026-opaque-pyobject-fallback.md`): OpaqueObject for wrapping arbitrary Python objects.

Design elements this commit produces:
- **`TVMFFIPyObjectDeleter` / free-threaded GIL helper**: A C-level deleter that conditionally acquires the GIL only when not in free-threaded mode, replacing the Cython `with gil` pattern that is incompatible with `Py_GIL_DISABLED`.
- **OpaqueObject proper type hierarchy registration**: Now registered with `parent=kTVMFFIObject`, enabling correct `IsInstance` checks.
