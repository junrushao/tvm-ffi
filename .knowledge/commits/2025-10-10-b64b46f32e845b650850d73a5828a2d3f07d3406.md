# Enable free-threaded Python build and fix OpaqueObject type registration
## TL;DR
- Adds free-threaded Python (3.14t / PEP 703) build support: Cython `freethreading_compatible` directive, CMake detection of `Py_GIL_DISABLED`, conditional Stable ABI bypass, and CI matrix update to test `cp314t`.
- Moves the Python object deleter from a Cython `with gil` callback to a C++ `TVMFFIPyObjectDeleter` that conditionally acquires the GIL only for non-free-threaded builds, using the RAII guard `TVMFFIPyWithGILIfNotFreeThreaded`.
- Fixes OpaqueObject type registration: was registered via `ReserveBuiltinTypeIndex` (type_depth=0, no parent), now registered via `GetOrAllocTypeIndex` with type_depth=1 and parent=`kTVMFFIObject`, so `IsInstance<Object>()` correctly recognizes OpaqueObject.
- Simplifies `tvm_ffi_callback` return path: the old branch on `c_api_ret_code == 0` / `== -2` is replaced by directly returning `c_api_ret_code`, since `raise_existing_error()` is already handled by the caller.

## Impact
- API: None -- no public API signatures changed.
- Behavioral: OpaqueObject is now correctly recognized by `IsInstance<Object>()` in C++ and `isinstance(obj, Object)` in Python. Previously it would fail the child-slot check because it had type_depth=0 and no parent. This fixes `ref_count()` and similar Object-level operations on OpaquePyObject instances.
- Flags/config: New CMake variable `PYTHON_IS_FREE_THREADED` detected at configure time. When true, Stable ABI (`USE_SABI 3.12`) is disabled. cibuildwheel config adds `cp314t-*` to build targets.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object type table and child-slot checking** ([0002-object-system](../designs/0002-object-system.md), [ADR 0003](../ADRs/0003-child-slot-type-checking.md)): The `GetOrAllocTypeIndex` function with `type_depth` / `parent_type_index` parameters is the correct way to register types that should participate in the type hierarchy. `ReserveBuiltinTypeIndex` only reserves an index without hierarchy metadata.
- **OpaquePyObject wrapping** ([0012-python-bindings](../designs/0012-python-bindings.md)): The `_convert_to_opaque_object_handle` and `_convert_to_ffi_func_handle` paths both use a deleter callback to release the Python reference when the FFI object is freed.
- **Stable ABI (abi3)** ([0013-packaging](../designs/0013-packaging.md)): Python >= 3.12 builds use `USE_SABI 3.12` for forward-compatible wheels. Free-threaded Python does not support Stable ABI, requiring conditional bypass.

Design elements this commit produces:
- **Free-threaded Python compatibility pattern**: `TVMFFIPyWithGILIfNotFreeThreaded` RAII guard + `TVMFFIPyObjectDeleter` as the canonical way to release Python objects from non-Python threads (e.g., C++ destructor callbacks). This replaces Cython `noexcept with gil` deleters.

## Usage Examples

**Bugfix: OpaqueObject ref count test now works correctly**

Before this fix, `ref_count(obj0_converted)` could fail because `IsInstance<Object>()` did not recognize `OpaquePyObject` as an Object, so `object_use_count` (which expects an Object) would reject it.

```python
# Before (broken): hardcoded sys.getrefcount base of 2
obj0 = MyObject("hello")
assert sys.getrefcount(obj0) == 2  # fragile: assumes exact refcount
obj0_converted = tvm_ffi.convert(obj0)
# ref_count(obj0_converted) would fail: OpaquePyObject not recognized as Object

# After (fixed): uses relative refcount and FFI ref_count works
obj0 = MyObject("hello")
base_count = sys.getrefcount(obj0)
ref_count = tvm_ffi.get_global_func("testing.object_use_count")
obj0_converted = tvm_ffi.convert(obj0)
assert ref_count(obj0_converted) == 1  # FFI-level ref count works now
assert sys.getrefcount(obj0) == base_count + 1  # relative, free-threaded compatible
```
