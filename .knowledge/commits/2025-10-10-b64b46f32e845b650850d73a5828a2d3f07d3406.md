# Enable free-threaded Python (3.14t) build and fix OpaquePyObject type hierarchy registration
## TL;DR
- Adds support for Python 3.14t (free-threaded / nogil) by disabling Stable ABI (`USE_SABI`) for free-threaded builds, adding `# cython: freethreading_compatible = True` to `core.pyx`, and replacing the Cython `with gil` deleter (`tvm_ffi_pyobject_deleter`) with a C-level `TVMFFIPyObjectDeleter` that conditionally acquires the GIL only when `Py_GIL_DISABLED` is not defined.
- Fixes `OpaquePyObject` type registration: changes from `ReserveBuiltinTypeIndex` (which registered with `type_depth=0`, `parent_type_index=-1`) to `GetOrAllocTypeIndex` with `type_depth=1` and `parent_type_index=kTVMFFIObject`, so `IsInstance<Object>()` correctly returns true for opaque objects.
- Updates CI matrix to test `3.14t` on Linux x86_64 and bumps macOS to `3.13`; conditionally excludes `torch` from test deps on Python >= 3.14.

## Key Exports
**Classes** (C++, `tvm_ffi_python_helpers.h`):
- `TVMFFIPyWithGILIfNotFreeThreaded` -- RAII guard. When `Py_GIL_DISABLED` is defined (free-threaded build), the constructor/destructor are no-ops. Otherwise, constructor calls `PyGILState_Ensure()`, destructor calls `PyGILState_Release()`.

**Functions** (C linkage, `tvm_ffi_python_helpers.h`):
- `extern "C" void TVMFFIPyObjectDeleter(void* py_obj) noexcept` -- Replacement for Cython-level `tvm_ffi_pyobject_deleter`. Acquires GIL via `TVMFFIPyWithGILIfNotFreeThreaded` guard, then calls `Py_DecRef`. Used as the deleter for both `TVMFFIFunctionCreate` and `TVMFFIObjectCreateOpaque` callbacks.

**Cython declarations** (`base.pxi`):
- `void TVMFFIPyObjectDeleter(void* py_obj) noexcept nogil` -- Cython extern declaration of the C helper.

**Build variables** (`CMakeLists.txt`):
- `PYTHON_IS_FREE_THREADED` -- CMake variable set by `execute_process` checking `sysconfig.get_config_var('Py_GIL_DISABLED') == 1`. When true, `USE_SABI 3.12` is not applied to the Cython extension target.

## Impact
- API: None. No public Python or C API signatures changed.
- Behavioral: `OpaquePyObject` instances now pass `IsInstance<Object>()` checks and `use_count()` returns correct values (the object is properly in the type hierarchy as a child of `Object`). Previously, `ReserveBuiltinTypeIndex` registered it as a root type with `type_depth=0`.
- Flags/config: `PYTHON_IS_FREE_THREADED` CMake variable is new. When true, disables Stable ABI (`USE_SABI`) for the Cython extension because Stable ABI is not compatible with free-threaded Python.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **TypeTable registration** (`src/ffi/object.cc`): The `ReserveBuiltinTypeIndex` vs `GetOrAllocTypeIndex` distinction. `ReserveBuiltinTypeIndex` registers with `type_depth=0, parent=-1` (suitable for POD types). `GetOrAllocTypeIndex` with explicit depth and parent is needed for object types that inherit from `Object`. See [0003-object-system.md](../designs/0003-object-system.md).
- **Type index layout** (`kTVMFFIOpaquePyObject = 74`): Static object range `[64, 128)`. See [ADR 0004-type-index-layout.md](../ADRs/0004-type-index-layout.md).
- **IsInstance fast path**: Ancestor table lookup at `type_ancestors[depth]`. With `type_depth=0`, `OpaquePyObject` had no ancestor entry for `Object`, breaking `IsInstance<Object>()`. The fix sets `type_depth=1` with `Object` as parent. See [0003-object-system.md](../designs/0003-object-system.md), IsInstance section.
- **Cython `USE_SABI`**: Python Stable ABI for forward-compatible extension modules. Not compatible with free-threaded Python. See [0014-python-package.md](../designs/0014-python-package.md).
- **Packed function callback convention**: `tvm_ffi_callback` is the Cython-level callback passed to `TVMFFIFunctionCreate`. It uses `noexcept with gil` to safely call Python from C. See [0004-function-system.md](../designs/0004-function-system.md).

Design elements this commit produces:
- **GIL-conditional deleter pattern** (`TVMFFIPyObjectDeleter` + `TVMFFIPyWithGILIfNotFreeThreaded`): A C-level pattern for safely decrementing Python object refcounts from C++ code in both GIL and free-threaded builds. The RAII guard is a no-op when `Py_GIL_DISABLED` is defined (compile-time dispatch). This replaces the Cython `with gil` pattern which is not compatible with free-threaded Python.
- **Free-threaded build detection in CMake**: `execute_process` + `sysconfig.get_config_var('Py_GIL_DISABLED')` pattern to detect free-threaded Python at CMake configure time.

## Usage Examples
**Before** (GIL-based Cython deleter -- incompatible with free-threaded Python):
```cython
# function.pxi (removed)
cdef void tvm_ffi_pyobject_deleter(void* fhandle) noexcept with gil:
    local_pyobject = <object>(fhandle)
    Py_DECREF(local_pyobject)

# Usage:
TVMFFIFunctionCreate(<void*>(pyfunc), tvm_ffi_callback, tvm_ffi_pyobject_deleter, out_handle)
```

**After** (C-level GIL-conditional deleter -- works with both GIL and free-threaded builds):
```c
// tvm_ffi_python_helpers.h (added)
extern "C" void TVMFFIPyObjectDeleter(void* py_obj) noexcept {
  TVMFFIPyWithGILIfNotFreeThreaded gil_state;  // no-op if Py_GIL_DISABLED
  Py_DecRef(static_cast<PyObject*>(py_obj));
}

// Usage in Cython (function.pxi):
TVMFFIFunctionCreate(<void*>(pyfunc), tvm_ffi_callback, TVMFFIPyObjectDeleter, out_handle)
TVMFFIObjectCreateOpaque(<void*>(pyobject), kTVMFFIOpaquePyObject, TVMFFIPyObjectDeleter, out_handle)
```

**OpaquePyObject fix** (type hierarchy registration):
```cpp
// Before: registered as root type (type_depth=0, no parent)
ReserveBuiltinTypeIndex(StaticTypeKey::kTVMFFIOpaquePyObject, TypeIndex::kTVMFFIOpaquePyObject);

// After: registered as child of Object (type_depth=1, parent=kTVMFFIObject)
this->GetOrAllocTypeIndex(StaticTypeKey::kTVMFFIOpaquePyObject,
                          TypeIndex::kTVMFFIOpaquePyObject,
                          /*type_depth=*/1,
                          /*num_child_slots=*/0,
                          /*child_slots_can_overflow=*/false,
                          /*parent_type_index=*/TypeIndex::kTVMFFIObject);
```
