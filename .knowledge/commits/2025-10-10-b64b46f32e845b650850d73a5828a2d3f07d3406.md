# Enable free-threaded Python (3.14t/nogil) build support and fix OpaqueObject type registration

## TL;DR
- Adds `# cython: freethreading_compatible = True` to the Cython module and introduces `TVMFFIPyObjectDeleter` — a C++-side deleter that conditionally acquires the GIL only when not running free-threaded Python — replacing the Cython-level `tvm_ffi_pyobject_deleter` (which always used `with gil`).
- CMake detects free-threaded Python (`Py_GIL_DISABLED`) and skips the `USE_SABI 3.12` stable-ABI path (incompatible with `3.14t`); `pyproject.toml` adds `cp314t-*` to the cibuildwheel build matrix.
- Fixes `kTVMFFIOpaquePyObject` type registration in `TypeTable` — it was registered via `ReserveBuiltinTypeIndex` (which does not set `parent_type_index`), so `IsInstance<Object>` returned false for opaque objects, breaking ref-count tests.

**Concern 1 — Free-threaded Python build (GIL-disabled):**
Affects `.github/workflows/ci_test.yml`, `CMakeLists.txt`, `pyproject.toml`, `python/tvm_ffi/cython/core.pyx`, `python/tvm_ffi/cython/function.pxi`, `python/tvm_ffi/cython/tvm_ffi_python_helpers.h`.

**Concern 2 — OpaqueObject type registration bugfix:**
Affects `src/ffi/object.cc`, `tests/python/test_object.py`.

class TVMFFIPyWithGILIfNotFreeThreaded:

    def __del__(self) -> None: ...    # PyGILState_Release() if GIL build

    Replaces Cython-level tvm_ffi_pyobject_deleter (which always acquired GIL via 'with gil').
    # Invariant: py_obj must be a valid PyObject*; called exactly once per wrapped handle.
    # Interacts with: TVMFFIPyWithGILIfNotFreeThreaded, TVMFFIFunctionCreate, TVMFFIObjectCreateOpaque
    # Extension: no change needed for new opaque types — same deleter is reused.
    """
    ...

# --- Concern 2: OpaqueObject type registration (object.cc TypeTable) ---
# Old (broken):
#   ReserveBuiltinTypeIndex(kTVMFFIOpaquePyObject, TypeIndex::kTVMFFIOpaquePyObject)
#   → did NOT set parent_type_index → IsInstance<Object>() returned false
# New (correct):
#   GetOrAllocTypeIndex(kTVMFFIOpaquePyObject, TypeIndex::kTVMFFIOpaquePyObject,
#                       type_depth=1, num_child_slots=0,
#                       child_slots_can_overflow=False,
#                       parent_type_index=TypeIndex::kTVMFFIObject)
#   → type_depth=1 means direct child of Object; IsInstance<Object>() now returns true
# Invariant: kTVMFFIOpaquePyObject MUST be registered with parent=kTVMFFIObject so that
#            ref-count tests (testing.object_use_count) and IsInstance checks work correctly.

# --- Cython module declaration (core.pyx, top-of-file) ---
# cython: freethreading_compatible = True
# cython: language_level=3
# → Marks the extension module as safe for free-threaded CPython (PEP 703).
# Interacts with: CMake USE_SABI path (disabled for 3.14t), cibuildwheel cp314t-* build target.

## Impact
- API: `TVMFFIPyObjectDeleter` is a new `extern "C"` symbol exported from the Cython extension (via the helpers header). The old Cython-internal `tvm_ffi_pyobject_deleter` is removed — it was never part of the public API, so no external callers affected.
- Behavioral: `kTVMFFIOpaquePyObject` is now a proper child of `kTVMFFIObject` in the type table. `IsInstance<Object>()` on an `OpaquePyObject` handle now returns `true`. Previously it would fail or cause `abort()` in some code paths.
- Flags/config: CMake: new `PYTHON_IS_FREE_THREADED` variable (bool, derived at configure time). `USE_SABI 3.12` is now skipped when `PYTHON_IS_FREE_THREADED=True`. pyproject.toml: `torch` dependency is conditional on `python_version < '3.14'` in the `test` extras.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- `0014-opaque-pyobject` — `TVMFFIObjectCreateOpaque`, `TVMFFIFunctionCreate`, `kTVMFFIOpaquePyObject` type registration, `tvm_ffi_pyobject_deleter` (removed)
- `0002-object-system` — `TypeTable::GetOrAllocTypeIndex` / `ReserveBuiltinTypeIndex`, type index protocol, `IsInstance` type-hierarchy check
- `0013-python-package` — Cython extension build pipeline, `core.pyx` module entry point, `function.pxi` callback/deleter wiring
- `0016-py-ffi-call-dispatch` — `tvm_ffi_callback` Cython function (minor cleanup in same file)

Design elements this commit produces:
- `TVMFFIPyWithGILIfNotFreeThreaded` — new RAII GIL-conditional guard class (C++ header, `tvm_ffi_python_helpers.h`). Pattern: compile-time conditional between no-op and `PyGILState_Ensure/Release` RAII.
- `TVMFFIPyObjectDeleter` — new `extern "C"` deleter replacing Cython `tvm_ffi_pyobject_deleter`. Now lives in C++ header so it can safely call `Py_DecRef` without always needing the GIL.
- Updated type registration invariant for `kTVMFFIOpaquePyObject` — must use `GetOrAllocTypeIndex` with `parent_type_index=kTVMFFIObject`, not `ReserveBuiltinTypeIndex`.

## Usage Examples

**Concern 1 — Free-threaded Python: GIL-conditional deleter (C++ pseudocode)**
```cpp
// When TVMFFIFunctionCreate wraps a Python callable:
CHECK_CALL(TVMFFIFunctionCreate(
    (void*)pyfunc,
    tvm_ffi_callback,
    TVMFFIPyObjectDeleter,   // replaces tvm_ffi_pyobject_deleter
    &out_handle
));
// When the last reference is released, TVMFFIPyObjectDeleter is called:
// extern "C" void TVMFFIPyObjectDeleter(void* py_obj) noexcept {
//     TVMFFIPyWithGILIfNotFreeThreaded gil_state;  // no-op under Py_GIL_DISABLED
//     Py_DecRef((PyObject*)py_obj);
// }
```

**Concern 2 — OpaqueObject type registration bugfix (before/after)**
```python
# BEFORE (broken): OpaquePyObject not recognized as Object
obj = tvm_ffi.convert(MyObject("hello"))
# IsInstance<Object>() → False → abort() or TypeError in certain code paths
ref_count = tvm_ffi.get_global_func("testing.object_use_count")
# ref_count(obj)  ← would fail

# AFTER (fixed): OpaquePyObject is a proper child of Object
obj = tvm_ffi.convert(MyObject("hello"))
assert isinstance(obj, tvm_ffi.core.OpaquePyObject)
ref_count = tvm_ffi.get_global_func("testing.object_use_count")
assert ref_count(obj) == 1   # now works correctly
```
