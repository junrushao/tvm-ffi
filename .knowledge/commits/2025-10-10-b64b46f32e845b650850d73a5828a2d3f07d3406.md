# Enable free-threaded Python (3.14t) build and fix OpaquePyObject type hierarchy

## TL;DR
- Adds free-threaded Python (PEP 703, Python 3.14t) support by replacing the Cython `with gil` deleter with a C++ GIL-conditional deleter (`TVMFFIPyObjectDeleter`), adding `freethreading_compatible = True` to the Cython module, skipping Stable ABI for free-threaded builds, and shipping `cp314t-*` wheels.
- Fixes `OpaquePyObject` type registration: changes from `ReserveBuiltinTypeIndex` (type_depth=0, no parent) to `GetOrAllocTypeIndex` with type_depth=1 and parent=`kTVMFFIObject`, so `OpaquePyObject` is correctly recognized as an `Object` subtype (enabling `isinstance(obj, Object)` checks in C++).
- Updates CI matrix to test Python 3.14t on Linux x86_64 and bumps macOS from 3.10 to 3.13.

## Key Exports

**Classes (C++ helper)**:
- `TVMFFIPyWithGILIfNotFreeThreaded` -- RAII class in `tvm_ffi_python_helpers.h`. No-op when `Py_GIL_DISABLED` is defined (free-threaded); acquires/releases GIL otherwise via `PyGILState_Ensure`/`PyGILState_Release`.

**Functions (C)**:
- `TVMFFIPyObjectDeleter(void* py_obj) -> void` -- `extern "C"` function in `tvm_ffi_python_helpers.h`. Replaces the Cython `tvm_ffi_pyobject_deleter`. Conditionally acquires the GIL (via `TVMFFIPyWithGILIfNotFreeThreaded`) then calls `Py_DecRef`. Used as the destructor for both `TVMFFIFunctionCreate` (Python callback functions) and `TVMFFIObjectCreateOpaque` (opaque Python objects).

**Renames**:

| Old Name | New Name | Location |
|----------|----------|----------|
| `tvm_ffi_pyobject_deleter` (Cython, `function.pxi`) | `TVMFFIPyObjectDeleter` (C++, `tvm_ffi_python_helpers.h`) | Deleter for Python objects stored in FFI handles |

## Impact
- API: none (no public Python/C++ API changes)
- ABI: none (the `TVMFFIPyObjectDeleter` is an internal implementation detail of the Cython extension; `OpaquePyObject` type index was already allocated)
- Behavioral: `OpaquePyObject` is now correctly a child of `Object` in the TypeTable hierarchy (type_depth=1, parent_type_index=kTVMFFIObject). Previously it was registered with type_depth=0 and no parent, meaning C++ `IsInstance<Object>` checks on `OpaquePyObject` values could fail. The `tvm_ffi_callback` return code is now returned directly instead of re-checking for -2, simplifying the callback error path.
- Flags/config: CMake now detects free-threaded Python via `sysconfig.get_config_var('Py_GIL_DISABLED')` and skips `USE_SABI` when detected. The `test` optional dependency now conditionally includes `torch` only for `python_version < '3.14'`.
- Data formats/schemas: none

## Usage Examples

### Free-threaded Python deleter pattern (C++ in tvm_ffi_python_helpers.h)
```cpp
// The deleter works for both GIL and free-threaded Python:
extern "C" void TVMFFIPyObjectDeleter(void* py_obj) noexcept {
  TVMFFIPyWithGILIfNotFreeThreaded gil_state;  // no-op in free-threaded mode
  Py_DecRef(static_cast<PyObject*>(py_obj));
}

// Used when wrapping Python functions for C++ consumption:
TVMFFIFunctionCreate(context, callback, TVMFFIPyObjectDeleter, &handle);

// Used when wrapping arbitrary Python objects as opaque FFI objects:
TVMFFIObjectCreateOpaque(py_handle, kTVMFFIOpaquePyObject, TVMFFIPyObjectDeleter, &handle);
```

### OpaquePyObject ref-counting test (tests/python/test_object.py)
```python
# The test now uses base_count instead of hardcoded 2, supporting
# both GIL and free-threaded Python where sys.getrefcount differs:
obj0 = MyObject("hello")
base_count = sys.getrefcount(obj0)
ref_count = tvm_ffi.get_global_func("testing.object_use_count")
obj0_converted = tvm_ffi.convert(obj0)
assert ref_count(obj0_converted) == 1
assert sys.getrefcount(obj0) == base_count + 1
```
