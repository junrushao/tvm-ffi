# Enable free-threaded Python build and fix OpaqueObject type registration
## TL;DR
- Adds free-threaded (nogil) Python 3.14t build support: CMake detects `Py_GIL_DISABLED`, disables Stable ABI (`USE_SABI`) for free-threaded builds, and Cython module is marked `freethreading_compatible`.
- Replaces the Cython-level `tvm_ffi_pyobject_deleter` (which used `with gil`) with a C++ `TVMFFIPyObjectDeleter` that conditionally acquires the GIL only when not in a free-threaded build.
- Fixes OpaqueObject not being recognized as an Object subtype by changing its TypeTable registration from `ReserveBuiltinTypeIndex` (type_depth=0, no parent) to `GetOrAllocTypeIndex` with `type_depth=1` and `parent_type_index=kTVMFFIObject`.

## Impact
- API: none -- no public API signatures changed
- Behavioral: OpaqueObject now passes `isinstance(obj, Object)` checks at the C++ type system level (fixes `IsInstance<Object>` returning false for opaque Python objects). The Python-level callback error return path in `tvm_ffi_callback` is simplified (returns `c_api_ret_code` directly instead of branching on 0/-2).
- Flags/config: CMake now detects `Py_GIL_DISABLED` via `sysconfig.get_config_var('Py_GIL_DISABLED')` and sets `PYTHON_IS_FREE_THREADED`. When true, `USE_SABI` is disabled (free-threaded Python does not support Stable ABI).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object type hierarchy and IsInstance protocol** ([0003-ffi-object-system](../design-records/0003-ffi-object-system.md)) -- the fix ensures OpaquePyObject participates correctly in the ancestor-table-based IsInstance checks.
- **TVMFFIFunctionCreate / TVMFFIObjectCreateOpaque C ABI** ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)) -- both accept a deleter function pointer; this commit changes which deleter is passed.
- **Cython dispatch and arg packing** ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md)) -- `_convert_to_ffi_func_handle` and `_convert_to_opaque_object_handle` now call `TVMFFIPyObjectDeleter` instead of the old Cython deleter.
- **Stable ABI (USE_SABI) CMake integration** ([0013-ffi-packaging-and-distribution](../design-records/0013-ffi-packaging-and-distribution.md)) -- conditionally disabled for free-threaded builds.

Design elements this commit produces:
- **`TVMFFIPyWithGILIfNotFreeThreaded`** -- new RAII GIL guard with compile-time free-threaded dispatch. Foundational for any future C++-level code that needs to call Python C API from arbitrary threads.
- **`TVMFFIPyObjectDeleter`** -- replaces the Cython `tvm_ffi_pyobject_deleter`; a C-linkage deleter safe for both GIL and free-threaded Python.
- **OpaqueObject as proper Object child** -- changes the type registration contract: OpaquePyObject now has `type_depth=1` and `parent_type_index=kTVMFFIObject`, making it a proper subtype in the type hierarchy.

## Usage Examples
**Bugfix: OpaqueObject ref-count test (before/after)**
```python
# Before: test assumed sys.getrefcount base was always 2 (GIL Python).
# In free-threaded Python, sys.getrefcount() may return different base values.
# After: test uses relative ref-count comparisons.
obj0 = MyObject("hello")
base_count = sys.getrefcount(obj0)           # base, not hardcoded 2
ref_count = tvm_ffi.get_global_func("testing.object_use_count")
obj0_converted = tvm_ffi.convert(obj0)
assert ref_count(obj0_converted) == 1        # FFI-level use_count check
assert sys.getrefcount(obj0) == base_count + 1  # relative, not absolute
```

**Cross-layer: C++ deleter called from free-threaded Python**
```cpp
// tvm_ffi_python_helpers.h -- GIL-conditional deleter
extern "C" void TVMFFIPyObjectDeleter(void* py_obj) noexcept {
  TVMFFIPyWithGILIfNotFreeThreaded gil_state;  // no-op if Py_GIL_DISABLED
  Py_DecRef(static_cast<PyObject*>(py_obj));
}
```
```python
# Cython side (function.pxi) -- passes C++ deleter to FFI creation
CHECK_CALL(TVMFFIFunctionCreate(
    <void*>(pyfunc), tvm_ffi_callback,
    TVMFFIPyObjectDeleter,   # was: tvm_ffi_pyobject_deleter (Cython, `with gil`)
    out_handle))
```
