# Temporarily skip Windows load_inline tests and bump version to 0.1.0a9
## TL;DR
- Marks four `test_load_inline_*` tests in `tests/python/test_load_inline.py` as `@pytest.mark.xfail` on Windows (`sys.platform.startswith("win")`), with reason `"needs to robustify windows support"`.
- Bumps the package version from `0.1.0a8` to `0.1.0a9` in `pyproject.toml`.

## Impact
- **API**: None. No public API changes.
- **Flags/config**: None.
- **Data formats/schemas**: None.

This is a CI/release chore commit. The `xfail` markers allow Windows CI to pass without blocking the release while the underlying `load_inline` Windows support is stabilized. The version bump prepares the next alpha release.

## Design Elements

Design elements this commit **consumes**:

- **Inline Module Compilation / `load_inline`** ([`.knowledge/designs/0017-inline-module-compilation.md`](../designs/0017-inline-module-compilation.md)): The four skipped tests (`test_load_inline_cpp`, `test_load_inline_cpp_with_docstrings`, `test_load_inline_cpp_multiple_sources`, `test_load_inline_cpp_build_dir`) exercise the `tvm_ffi.cpp.load_inline()` JIT compilation pipeline. The Windows failures indicate that the ninja-based compilation pipeline (compiler detection, MSVC flags, DLL linking) is not yet robust on Windows.
- **Packaging and Build** ([`.knowledge/designs/0016-packaging-and-build.md`](../designs/0016-packaging-and-build.md)): The version bump in `pyproject.toml` (`0.1.0a8` -> `0.1.0a9`) follows the existing alpha version progression pattern documented in the packaging design.

Design elements this commit **produces**:

- None. This commit does not introduce new design elements. It is a CI workaround.
