# Enable wheel building on every main commit, restrict PyPI publish to manual dispatch

## TL;DR
- Adds `push: branches: [main]` trigger to `publish_wheel.yml` so wheels are built (but not published) on every commit to `main`.
- Fixes `ref:` expressions in checkout steps to use `inputs.branch` only for `workflow_dispatch`, falling back to `github.ref` for push events.
- Preserves the `if: github.event_name == 'workflow_dispatch'` guard on `upload_pypi` so publishing remains manual-only.

## Design Elements
Design elements this commit consumes:
- CI workflow structure for multi-platform wheel builds (`.github/workflows/publish_wheel.yml`)
- `cibuildwheel` matrix strategy across Linux x86_64/aarch64, macOS arm64, Windows AMD64

Design elements this commit produces:
- **Continuous wheel-build validation**: every push to `main` now triggers the full build_wheels + build_sdist jobs, catching packaging regressions before a manual release.
- **Dual-trigger ref resolution pattern**: `${{ github.event_name == 'workflow_dispatch' && inputs.branch || github.ref }}` as the standard idiom for workflows that support both push and manual dispatch.
