# Enable comprehensive Ruff lint rules and apply them across the Python codebase

## TL;DR

- Replaces `black` + `isort` with a comprehensive `ruff` configuration in `pyproject.toml`, enabling rule sets: `UP` (pyupgrade), `PL` (pylint), `I` (isort), `RUF`, `NPY`, `F` (pyflakes), `PTH` (flake8-use-pathlib), `D` (pydocstyle).
- Applies the new rules mechanically across all Python sources: adds missing module/class/method docstrings, fixes docstring imperative style and trailing-period conventions, migrates `os.path.*` calls to `pathlib.Path`, moves `typing.Sequence`/`typing.Mapping` imports to `collections.abc`, sorts imports.
- Removes two obsolete shell scripts (`tests/lint/git-clang-format.sh`, `tests/scripts/task_lint.sh`) that have been superseded by pre-commit hooks.

None — no public API surface was added or changed.

## Impact

- API: none — all changes are style, docstring wording, and import form; no signature changes.
- Behavioral: `subprocess.run(...)` in `python/tvm_ffi/cpp/load_inline.py` gains `check=False` explicitly (previously implicit default). This is a correctness/clarity fix with no behavioral change.
- Flags/config: `pyproject.toml` drops `[tool.black]` and `[tool.isort]` sections; adds `[tool.ruff]`, `[tool.ruff.lint]`, `[tool.ruff.lint.per-file-ignores]`, `[tool.ruff.lint.pylint]`, `[tool.ruff.format]`. New ignored rules: `PLR2004` (magic-value-comparison), `ANN401` (any-type), `D203`/`D213` (conflicting docstring style choices). Tests additionally exempt `D100`, `D101`, `D103`, `D107`, `D205`.
