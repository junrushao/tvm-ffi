# Rewrite TypeSchema converter to produce CAny via C++ __ffi_convert__ dispatch

## TL;DR
- **BREAKING**: `type_check.pxi` replaced by `type_converter.pxi`; converters return `CAny` directly and signal failure via `_ConvertError` exceptions.
- Object-type conversion delegates to new `__ffi_convert__` TypeAttr registered per-type in C++ (via `CastFromAny`/`CastObjectFromAny` helpers), removing duplicated marshal-path heuristics from Python.
- `ObjectDef` auto-registers `__ffi_convert__` for every reflected type; `.ref<TObjectRef>()` added for ObjectRef wrappers.
- New global functions: `ffi.MakeNew` (uninitialized allocation), `ffi.FunctionFromExternC`.

## Key Exports

```python
# C++ reflection layer:
# ObjectDef<T> auto-registers __ffi_convert__ TypeAttr for T
# .ref<TObjectRef>() registers __ffi_convert__ for ObjectRef wrapper
# CastFromAny<T>(AnyView) -> T*  — cast AnyView to Object pointer
# CastObjectFromAny<T>(AnyView) -> ObjectRef  — cast AnyView to ObjectRef

# Global functions:
def ffi_MakeNew(type_index: int) -> Object: ...
    # Interacts with: CreateEmptyObject (e3333e2)
def ffi_FunctionFromExternC(ptr: c_void_p) -> Function: ...
    # Interacts with: Function::FromExternC

# Python type_converter.pxi:
# - Eager protocol normalization: __tvm_ffi_object__, __tvm_ffi_value__, asobject()
# - Object conversion delegates to __ffi_convert__ C++ functions
# - collections.abc.Callable support in TypeSchema.from_annotation
```

## Impact
- API: `type_check.pxi` -> `type_converter.pxi` rename; `ffi.MakeNew`, `ffi.FunctionFromExternC` added.
- Behavioral: Type conversion now routes through C++ `__ffi_convert__` dispatch.
- Flags/config: None.
- Data formats/schemas: None.
