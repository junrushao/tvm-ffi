# Rewrite TypeSchema converter to use C++ __ffi_convert__ dispatch

## TL;DR
- `type_check.pxi` (1032 lines) deleted and replaced by `type_converter.pxi` (806 lines): converters now return `CAny` directly; failure signals via `_ConvertError` exception (not sentinel objects).
- C++ `reflection::details::CastFromAny<TObjectRef>` / `CastObjectFromAny` helpers and `RegisterConvertTypeAttr<T>()` function added; `ObjectDef::ref<TObjectRef>()` auto-registers `__ffi_convert__` for every reflected ObjectRef wrapper.
- All core types (Object, String, Bytes, Error, Function, Array, List, Map, Dict, Shape, Tensor) register `__ffi_convert__`; Object conversion now delegated to C++ TypeTraits, eliminating Python-side marshal-path heuristics.
- BREAKING: `__tvm_ffi_value__` now takes precedence over `__tvm_ffi_int__`/`__tvm_ffi_float__`/callable dispatch; container conversion always returns FFI container wrapped in `CAny`.

## Impact
- API: `TypeSchema.convert()` now always returns `CAny`; Object conversion via `__ffi_convert__` TypeAttr. `type_check.pxi` removed (internal API). `ObjectDef::ref<TObjectRef>()` new C++ API.
- Behavioral: **BREAKING** — `__tvm_ffi_value__` precedence changed (before `__tvm_ffi_int__`/float/callable). Container types always return FFI container in `CAny`. `ctypes.c_void_p` schema converts `None` to `ctypes.c_void_p(None)`.
- Flags/config: `__ffi_convert__` TypeAttr key name (`type_attr::kConvert`)
- Data formats/schemas: `type_check.py` → `test_type_converter.py` test file rename.

## Usage Examples

C++ registration of `__ffi_convert__` for a new ObjectRef wrapper:
```cpp
ObjectDef<FooObj>("foo.Foo")
    .def_field("x", &FooObj::x)
    .ref<Foo>()  // registers __ffi_convert__ for Foo (ObjectRef wrapping FooObj)
    ;
```

Python usage after registration:
```python
schema = TypeSchema.from_annotation(Foo)
cany = schema.convert(some_value)   # calls __ffi_convert__(some_value) via C++
foo = cany.to_py()                  # → Foo instance
```
