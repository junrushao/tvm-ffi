# Rewrite TypeSchema converter to CAny via C++ __ffi_convert__ dispatch

## TL;DR
- `type_check.pxi` (1068 lines) deleted; replaced by `type_converter.pxi` (806 lines): converters now return `CAny` and signal failure via exceptions.
- New C++ `__ffi_convert__` type attribute registered per reflected type via `ObjectDef::ref<TRef>()` — delegates `AnyView → ObjectRef` conversion to C++.
- `ObjectDef` auto-registers `__ffi_convert__` for all reflected types; core types registered explicitly.
- New `ffi.MakeNew` and `ffi.FunctionFromExternC` global functions.

## Impact
- API: **Breaking**. `type_check.pxi` removed; `type_converter.pxi` is the replacement. Exception-based errors instead of `_ConvertError` sentinel pattern. `TypeSchema.convert` still returns `CAny`.
- Behavioral: Object-type conversion now dispatches through C++ `__ffi_convert__` instead of Python marshal-path heuristics — more accurate, less duplicated code.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

```cpp
// C++: auto-registered by ObjectDef destructor
refl::ObjectDef<MyClass>()
    .def_rw("x", &MyClass::x)
    .ref<MyObj>();  // explicit: register __ffi_convert__ for MyObj ObjectRef

// Python: transparent usage
schema = TypeSchema("my.MyClass")
cany = schema.convert(some_value)   # dispatches through __ffi_convert__
result = cany.to_py()
```
