# Update load_inline API to match torch.utils.cpp_extension.load_inline conventions
## TL;DR
- Renames `cpp_source` to `cpp_sources` and `cuda_source` to `cuda_sources` (now accept `str | Sequence[str]`), aligning with PyTorch's `torch.utils.cpp_extension.load_inline` naming.
- Unifies the separate `cpp_functions` and `cuda_functions` parameters into a single `functions` parameter (accepts `Sequence[str] | Mapping[str, str] | str`). Exported name now equals the C++ function name (no more separate name mapping).
- Adds a `build_directory` parameter to allow explicit build directory specification, bypassing the content-addressable cache.

**Rename mapping:**

| Before | After | Type change |
|--------|-------|-------------|
| `cpp_source: str \| None` | `cpp_sources: str \| Sequence[str] \| None` | Accepts list of sources |
| `cuda_source: str \| None` | `cuda_sources: str \| Sequence[str] \| None` | Accepts list of sources |
| `cpp_functions: Mapping[str, str] \| None` | `functions: Sequence[str] \| Mapping[str, str] \| str \| None` | Unified; mapping values are now docstrings (not source function names) |
| `cuda_functions: Mapping[str, str] \| None` | *(removed, merged into `functions`)* | N/A |
| *(none)* | `build_directory: str \| None` | New parameter |

## Key Exports
**Functions:**
- `tvm_ffi.cpp.load_inline(name: str, *, cpp_sources: str | Sequence[str] | None = None, cuda_sources: str | Sequence[str] | None = None, functions: Sequence[str] | Mapping[str, str] | str | None = None, extra_cflags: Sequence[str] | None = None, extra_cuda_cflags: Sequence[str] | None = None, extra_ldflags: Sequence[str] | None = None, extra_include_paths: Sequence[str] | None = None, build_directory: str | None = None) -> Module` -- JIT-compile inline C++/CUDA and load as Module.
- `_hash_sources(cpp_source: str, cuda_source: str, functions: Sequence[str] | Mapping[str, str], extra_cflags, extra_cuda_cflags, extra_ldflags, extra_include_paths) -> str` -- Internal. Now takes unified `functions` instead of separate `cpp_functions`/`cuda_functions`.

**Behavioral changes to `_decorate_with_tvm_ffi`:**
- Export macros now use `TVM_FFI_DLL_EXPORT_TYPED_FUNC(func_name, func_name)` -- the exported name equals the C++ function name. Previously the first argument was the exported name and the second was the C++ source name, which could differ.
- CUDA functions are no longer exported individually; all function exports are applied only to the C++ source. The CUDA source gets an empty function mapping.

## Impact
- API: **Breaking** for existing callers of `load_inline`. Parameters `cpp_source`, `cuda_source`, `cpp_functions`, `cuda_functions` are renamed/removed. All existing call sites must be updated.
- ABI: None -- this is a Python-only API change. No C/C++ ABI impact.
- Behavioral: (1) Exported function names must now match the actual C++ function name; the old pattern of mapping an exported name to a different source name is no longer supported via the simple list form. (2) CUDA functions must now be declared/forward-declared in `cpp_sources` and exported from there. (3) Multiple source strings can be concatenated via lists.
- Flags/config: None.
- Data formats/schemas: Cache key computation changes (unified `functions` hash), so existing cached builds will not be reused after upgrade.

## Design Elements
Design elements this commit consumes:
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`): The core `load_inline` workflow, source decoration, Ninja build generation, content-addressable caching, and `Module` loading are all reused unchanged.
- **Module system** (`.knowledge/designs/0013-module-system.md`): Return type `Module` and `tvm_ffi.load_module()` for loading the compiled shared library.
- **TVM_FFI_DLL_EXPORT_TYPED_FUNC macro** (`.knowledge/designs/function-system.md`): Used in the generated export stubs, but now both arguments are the same identifier.

Design elements this commit produces:
- **Unified function export convention**: Exported name == C++ function name. This eliminates the separate `cpp_functions`/`cuda_functions` dictionaries and the name-mapping indirection.
- **Multi-source concatenation**: `cpp_sources` and `cuda_sources` accept `Sequence[str]`, joined with `"\n"` before decoration.
- **Explicit build directory**: `build_directory` parameter bypasses the content-addressable cache entirely when set.
- **Function docstring support** (stubbed): When `functions` is a `Mapping[str, str]`, values are docstrings. Currently unused (`_ = func_doc  # todo`), but the API surface is established.

## Usage Examples
**CPU kernel with the new API (from test):**
```python
import tvm_ffi.cpp
import numpy as np

mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) {
            for (int i = 0; i < x->shape[0]; ++i)
                static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)
x = np.array([1, 2, 3], dtype=np.float32)
y = np.empty_like(x)
mod.add_one_cpu(x, y)
```

**Multiple sources and explicit build directory (from test):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=[source_a, source_b],
    functions=["add_one_cpu", "add_two_cpu"],
    build_directory="./build_add_one",
)
```

**Mixed C++/CUDA -- CUDA function must be forward-declared in cpp_sources (from example):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) { /* ... */ }
        void add_one_cuda(DLTensor* x, DLTensor* y);  // forward declaration
    """,
    cuda_sources=r"""
        void add_one_cuda(DLTensor* x, DLTensor* y) { /* CUDA impl */ }
    """,
    functions=["add_one_cpu", "add_one_cuda"],
)
```
