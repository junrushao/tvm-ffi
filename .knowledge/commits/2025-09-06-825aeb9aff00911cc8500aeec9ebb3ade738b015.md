# Update ffi.load_inline interface to match torch.utils.cpp_extension.load_inline
## TL;DR
- Renames `cpp_source` -> `cpp_sources`, `cuda_source` -> `cuda_sources` to match `torch.utils.cpp_extension.load_inline` naming (now accepts `Sequence[str] | str`).
- Unifies `cpp_functions` and `cuda_functions` into a single `functions` parameter that accepts `Sequence[str] | Mapping[str, str] | str`.
- Adds `build_directory` parameter to allow explicit build directory specification instead of always using the hash-based cache path.

### Rename Mapping

| Before | After | Notes |
|--------|-------|-------|
| `cpp_source: str` | `cpp_sources: Sequence[str] \| str` | Now accepts list of sources |
| `cuda_source: str` | `cuda_sources: Sequence[str] \| str` | Now accepts list of sources |
| `cpp_functions: Mapping[str, str]` | `functions: Sequence[str] \| Mapping[str, str] \| str` | Unified; keys were exported_name->source_name, now function name is both |
| `cuda_functions: Mapping[str, str]` | _(removed, merged into `functions`)_ | CUDA functions no longer separately specified |
| _(none)_ | `build_directory: Optional[str]` | New parameter |

## Key Exports

    # Old: cuda_source: str | None = None

    extra_cuda_cflags: Sequence[str] | None = None,

## Impact
- API: **Breaking** -- `cpp_source`, `cuda_source`, `cpp_functions`, `cuda_functions` keyword arguments are removed. All callers must update to `cpp_sources`, `cuda_sources`, `functions`.
- Behavioral: The old API allowed `exported_name != source_function_name` via `cpp_functions={"alias": "RealName"}`. The new `Sequence[str]` form requires the exported name to equal the source function name. The `Mapping[str, str]` form now maps `name -> docstring` (not `name -> source_name`), so the name-aliasing capability is removed.
- Flags/config: None.
- Data formats/schemas: Cache hash changes (different parameters hashed), so existing cached builds will not be reused after this change.

## Design Elements
Design elements this commit consumes:
- **Module system** ([0011-module-system.md](../designs/0011-module-system.md)): `load_module` used to load compiled `.so` at end of pipeline.
- **TVM_FFI_DLL_EXPORT_TYPED_FUNC macro**: Used in `_decorate_with_tvm_ffi` to register functions in the compiled library.
- **Python Module wrapper** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): Return type of `load_inline`.

Design elements this commit produces:
- **Unified `functions` parameter convention**: Single parameter replaces separate cpp/cuda function mappings. Accepts three forms: `str` (single function), `Sequence[str]` (multiple functions, name=name), `Mapping[str, str]` (name->docstring). This is a new API convention for the `load_inline` interface.
- **`build_directory` parameter**: Explicit build directory bypasses hash-based caching, enabling reproducible builds at a known path.
- **Multi-source support**: `cpp_sources`/`cuda_sources` accept `Sequence[str]`, joined with `"\n"` before compilation.

## Usage Examples

**Basic usage with the new API (from test):**
```python
import tvm_ffi

mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) {
          for (int i = 0; i < x->shape[0]; ++i)
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)
mod.add_one_cpu(x, y)
```

**Multiple sources (new capability):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=["void add_one(...) { ... }", "void add_two(...) { ... }"],
    functions=["add_one", "add_two"],
)
```

**Explicit build directory (new capability):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""void add_one_cpu(...) { ... }""",
    functions=["add_one_cpu"],
    build_directory="./build_add_one",
)
```

**Mapping form with docstrings (new semantics):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""void add_one_cpu(...) { ... }""",
    functions={"add_one_cpu": "add two float32 1D tensors element-wise"},
)
```
