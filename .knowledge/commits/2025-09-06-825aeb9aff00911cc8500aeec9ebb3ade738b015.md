# Rename load_inline parameters to match torch.utils.cpp_extension.load_inline interface
## TL;DR
- Rename `cpp_source` -> `cpp_sources`, `cuda_source` -> `cuda_sources` to match torch's `load_inline` interface.
- Unify `cpp_functions` and `cuda_functions` into a single `functions` parameter accepting `Sequence[str] | Mapping[str, str] | str`.
- Add `build_directory` parameter to allow explicit build directory specification (bypasses hash-based cache dir).
- Secondary: `cpp_sources`/`cuda_sources` now accept `Sequence[str]` (list of source fragments) in addition to a single `str`.

### Rename Mapping

| Before | After | Notes |
|--------|-------|-------|
| `cpp_source: str` | `cpp_sources: str \| Sequence[str]` | Now also accepts list of source fragments |
| `cuda_source: str` | `cuda_sources: str \| Sequence[str]` | Now also accepts list of source fragments |
| `cpp_functions: Mapping[str, str]` | `functions: Sequence[str] \| Mapping[str, str] \| str` | Unified; keys=export names, values=docstrings (not source-code names) |
| `cuda_functions: Mapping[str, str]` | *(removed, merged into `functions`)* | CUDA functions now registered via `cpp_sources` forward declarations |
| *(N/A)* | `build_directory: str \| None` | New parameter for explicit build dir |

## Key Exports

```python
def load_inline(
    name: str,
    *,
    cpp_sources: str | Sequence[str] | None = None,     # was: cpp_source: str | None
    cuda_sources: str | Sequence[str] | None = None,     # was: cuda_source: str | None
    functions: Sequence[str] | Mapping[str, str] | str | None = None,  # was: cpp_functions + cuda_functions
    extra_cflags: Sequence[str] | None = None,
    extra_cuda_cflags: Sequence[str] | None = None,
    extra_ldflags: Sequence[str] | None = None,
    extra_include_paths: Sequence[str] | None = None,
    build_directory: str | None = None,                  # NEW
) -> Module: ...
    # Interacts with: Module system (0011), TVM_FFI_DLL_EXPORT_TYPED_FUNC macro, ninja build
    # Invariant: when functions is Sequence[str], exported name == function name in source
    #   (old API required exported name != source name; now they must match)
    # Invariant: CUDA functions must have forward declarations in cpp_sources
    #   (old API: cuda_functions dict registered them from cuda_source directly)
    # Extension: build_directory bypasses cache hashing; useful for reproducible builds
```

Key behavioral change in `_decorate_with_tvm_ffi`: the old API mapped `exported_name -> source_name` (they could differ). The new API uses `TVM_FFI_DLL_EXPORT_TYPED_FUNC(func_name, func_name)` -- the exported name always equals the source function name. When `functions` is a `Mapping`, values are docstrings (not source function names).

## Impact
- API: Breaking -- all callers of `load_inline` must update parameter names (`cpp_source` -> `cpp_sources`, etc.) and replace `cpp_functions`/`cuda_functions` with unified `functions`. The mapping semantics changed: values are now docstrings, not source-code function names.
- Behavioral: CUDA function registration now requires forward declarations in `cpp_sources` (the `cuda_sources` no longer gets `TVM_FFI_DLL_EXPORT_TYPED_FUNC` decorations -- only `cpp_source` does). Exported function names must now match source function names.
- Flags/config: none
- Data formats/schemas: Cache hash computation changed (fewer inputs), so existing caches will not match new builds.

## Design Elements
Design elements this commit consumes:
- **Module system** (`0011-module-system.md`): `load_inline` returns a `Module` loaded via `load_module`, which wraps `LibraryModuleObj`/`DSOLibrary`.
- **`TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro** (`0003-function-system.md`): used in `_decorate_with_tvm_ffi` to export C++ functions as FFI-safe DLL symbols.

Design elements this commit produces:
- None -- this is a parameter rename and unification of an existing function, not a new design element.

## Usage Examples
New calling convention (from updated test):
```python
from tvm_ffi.cpp import load_inline

# Simple: list of function names (exported name == source name)
mod = load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) { /* ... */ }
    """,
    functions=["add_one_cpu"],
)
mod.add_one_cpu(x, y)

# With docstrings: mapping of name -> docstring
mod = load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) { /* ... */ }
    """,
    functions={"add_one_cpu": "add two float32 1D tensors element-wise"},
)

# Multiple source fragments + explicit build directory
mod = load_inline(
    name="hello",
    cpp_sources=["void f1(...) { ... }", "void f2(...) { ... }"],
    functions=["f1", "f2"],
    build_directory="./build_my_module",
)

# CUDA: forward-declare in cpp_sources, implement in cuda_sources
mod = load_inline(
    name="hello",
    cpp_sources="void add_one_cuda(DLTensor* x, DLTensor* y);",
    cuda_sources=r"""
        void add_one_cuda(DLTensor* x, DLTensor* y) { /* CUDA impl */ }
    """,
    functions=["add_one_cuda"],
)
```
