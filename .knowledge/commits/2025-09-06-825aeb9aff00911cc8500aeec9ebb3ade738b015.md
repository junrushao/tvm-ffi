# Rename load_inline parameters to match torch.utils.cpp_extension.load_inline interface
## TL;DR
- Renames `cpp_source` -> `cpp_sources`, `cuda_source` -> `cuda_sources` (now accept `Sequence[str] | str`).
- Merges `cpp_functions` and `cuda_functions` into a single `functions` parameter (now accepts `Sequence[str] | Mapping[str, str] | str`). The exported name now equals the function name in source (no more separate exported-name vs source-name mapping).
- Adds `build_directory` parameter to let the user specify the build output directory directly, bypassing the content-addressed cache.

| Old name | New name | Type change |
|----------|----------|-------------|
| `cpp_source: str \| None` | `cpp_sources: str \| Sequence[str] \| None` | Accepts list of sources |
| `cuda_source: str \| None` | `cuda_sources: str \| Sequence[str] \| None` | Accepts list of sources |
| `cpp_functions: Mapping[str, str] \| None` | *(removed)* | Merged into `functions` |
| `cuda_functions: Mapping[str, str] \| None` | *(removed)* | Merged into `functions` |
| *(new)* | `functions: Sequence[str] \| Mapping[str, str] \| str \| None` | Unified, Mapping values are now docstrings (not source names) |
| *(new)* | `build_directory: str \| None` | New parameter |

## Key Exports

**Functions** (updated signature):
```python
def tvm_ffi.cpp.load_inline(
    name: str,
    *,
    cpp_sources: str | Sequence[str] | None = None,
    cuda_sources: str | Sequence[str] | None = None,
    functions: Sequence[str] | Mapping[str, str] | str | None = None,
    extra_cflags: Sequence[str] | None = None,
    extra_cuda_cflags: Sequence[str] | None = None,
    extra_ldflags: Sequence[str] | None = None,
    extra_include_paths: Sequence[str] | None = None,
    build_directory: str | None = None,
) -> Module
```

Key semantic changes in `functions`:
- **Mapping**: keys = function names to export, values = docstrings (previously values = source-code function names).
- **Sequence/str**: function names to export; exported name = function name in source.
- `_decorate_with_tvm_ffi` now emits `TVM_FFI_DLL_EXPORT_TYPED_FUNC(func_name, func_name)` (same name twice), instead of `(exported_name, source_name)`.

**Renames** (parameter-level):
| Old | New |
|-----|-----|
| `cpp_source` | `cpp_sources` |
| `cuda_source` | `cuda_sources` |
| `cpp_functions` | `functions` |
| `cuda_functions` | `functions` |

## Impact
- API: **Breaking**. All existing callers of `load_inline()` using keyword arguments `cpp_source`, `cuda_source`, `cpp_functions`, or `cuda_functions` will fail. The exported-name != source-name pattern (e.g., `cpp_functions={"add_one_cpu": "AddOne"}`) is no longer supported; callers must name source functions with their desired export name directly.
- Behavioral: `_decorate_with_tvm_ffi` no longer maps exported name to a different source name. CUDA functions are no longer individually registered via `cuda_functions`; all exported functions are declared via `functions` and the FFI export macro is only applied to `cpp_source` (not `cuda_source`). CUDA functions must be forward-declared in `cpp_sources` and defined in `cuda_sources`.
- Flags/config: `build_directory` parameter added. When set, bypasses content-addressed caching entirely (no hash computation, no `TVM_FFI_CACHE_DIR` lookup).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Inline module compilation workflow** ([2025-09-05-83805ec9.md](./2025-09-05-83805ec949227620d05e61358a4ecb4f0c931979.md)): Mutates the `load_inline` public API surface established by that commit.
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): Still uses `load_module()` to load the compiled `.so`. `TVM_FFI_DLL_EXPORT_TYPED_FUNC` usage unchanged but now always with identical exported-name and source-name.
- **Python package** ([0014-python-package.md](../designs/0014-python-package.md)): `load_inline` is part of the documented public API surface in `tvm_ffi.cpp`.

Design elements this commit produces:
- **Simplified function export model**: Functions are now exported by their source name directly. The indirection layer (exported-name != source-name) is removed. Mapping values become docstrings (placeholder `_ = func_doc` TODO in `_decorate_with_tvm_ffi`).
- **Multi-source concatenation**: `cpp_sources` and `cuda_sources` accept lists, which are joined with `"\n".join()` before compilation. This enables composing modules from multiple source fragments.
- **User-specified build directory**: `build_directory` bypasses the content-addressed cache, enabling reproducible builds at known paths (useful for debugging and CI).

## Usage Examples

### Basic usage with the new API
**Context**: Updated calling convention -- function name in source = exported name.
```python
import tvm_ffi.cpp

mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) {
          for (int i = 0; i < x->shape[0]; ++i)
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)
mod.add_one_cpu(x, y)
```

### Before/after migration pattern
**Before** (broken after this commit):
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""void AddOne(DLTensor* x, DLTensor* y) { ... }""",
    cpp_functions={"add_one_cpu": "AddOne"},
)
```
**After**:
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""void add_one_cpu(DLTensor* x, DLTensor* y) { ... }""",
    functions=["add_one_cpu"],
)
```
