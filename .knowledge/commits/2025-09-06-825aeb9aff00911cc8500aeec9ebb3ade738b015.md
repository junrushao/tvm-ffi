# Update load_inline interface to match torch.utils.cpp_extension.load_inline

## TL;DR
- Renames `cpp_source` -> `cpp_sources`, `cuda_source` -> `cuda_sources` to accept `str | Sequence[str]` (matching torch convention for multi-source support).
- Unifies `cpp_functions` + `cuda_functions` into a single `functions` parameter accepting `Sequence[str] | Mapping[str, str] | str`. The mapping form now maps names to docstrings (not source-code identifiers), and the exported name equals the function name in source.
- Adds `build_directory` parameter to allow explicit build path instead of always using the hash-based cache directory.

### Rename mapping

| Before | After | Type change |
|--------|-------|-------------|
| `cpp_source: str` | `cpp_sources: str \| Sequence[str]` | Widened to accept list |
| `cuda_source: str` | `cuda_sources: str \| Sequence[str]` | Widened to accept list |
| `cpp_functions: Mapping[str, str]` | `functions: Sequence[str] \| Mapping[str, str] \| str` | Unified; mapping values now docstrings, not source names |
| `cuda_functions: Mapping[str, str]` | *(removed, merged into `functions`)* | CUDA functions no longer separately registered |
| *(none)* | `build_directory: str \| None` | New parameter |

## Key Exports

```python
def load_inline(
    name: str,
    *,
    cpp_sources: str | Sequence[str] | None = None,  # was: cpp_source: str | None
    cuda_sources: str | Sequence[str] | None = None,  # was: cuda_source: str | None
    functions: Sequence[str] | Mapping[str, str] | str | None = None,  # was: cpp_functions + cuda_functions
    extra_cflags: Sequence[str] | None = None,
    extra_cuda_cflags: Sequence[str] | None = None,
    extra_ldflags: Sequence[str] | None = None,
    extra_include_paths: Sequence[str] | None = None,
    build_directory: str | None = None,  # NEW
) -> Module:
    """Compile and load a C++/CUDA tvm ffi module from inline source code.

    Matches torch.utils.cpp_extension.load_inline interface conventions.
    """
    # Interacts with: _decorate_with_tvm_ffi (adds TVM_FFI_DLL_EXPORT_TYPED_FUNC per function)
    # Interacts with: _hash_sources (cache key generation)
    # Interacts with: Module (return type, from ffi module system)
    # Invariant: functions are only registered in cpp_source, not cuda_source
    #   (cuda_source gets empty function dict: `_decorate_with_tvm_ffi(cuda_source, {})`)
    # Invariant: when functions is a Sequence, exported name == function name in source
    #   (no longer supports exported_name != source_name mapping)
    # Invariant: when build_directory is None, uses TVM_FFI_CACHE_DIR or ~/.cache/tvm-ffi
    # Extension: pass Mapping[str, str] for functions to attach docstrings (future feature, currently stored but unused)
    ...
```

## Impact
- API: **Breaking** -- `cpp_source`, `cuda_source`, `cpp_functions`, `cuda_functions` parameters renamed/removed. All existing callers must update keyword arguments. The old `Mapping[str, str]` semantics for `cpp_functions`/`cuda_functions` (exported_name -> source_name) are replaced; the new `functions` Mapping maps name -> docstring.
- Behavioral: `_decorate_with_tvm_ffi` now generates `TVM_FFI_DLL_EXPORT_TYPED_FUNC(func_name, func_name)` (same name for both), eliminating the previous name-remapping capability. CUDA functions are no longer individually wrapped with `TVM_FFI_DLL_EXPORT_TYPED_FUNC` -- only cpp_source functions are registered.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit produces/mutates:
- **Mutated**: `load_inline` public API contract -- parameter names, types, and function registration semantics all changed. The function now follows torch conventions: plural source parameters accepting lists, unified `functions` parameter, and `build_directory` for explicit output path control.

## Usage Examples

Basic usage with new interface (from test):
```python
import tvm_ffi

mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cpu(DLTensor* x, DLTensor* y) {
            for (int i = 0; i < x->shape[0]; ++i)
                static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    functions=["add_one_cpu"],
)
mod.add_one_cpu(x, y)
```

Before/after calling convention:
```python
# BEFORE (old API):
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source="void AddOne(...) {...}",
    cuda_source="void AddOneCUDA(...) {...}",
    cpp_functions={"add_one_cpu": "AddOne"},        # exported_name -> source_name
    cuda_functions={"add_one_cuda": "AddOneCUDA"},  # exported_name -> source_name
)

# AFTER (new API):
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="void add_one_cpu(...) {...}\nvoid add_one_cuda(DLTensor*, DLTensor*);",
    cuda_sources="void add_one_cuda(...) {...}",
    functions=["add_one_cpu", "add_one_cuda"],  # name == source function name
)
```

Multiple sources and explicit build directory (new capabilities):
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=["void func_a(...) {...}", "void func_b(...) {...}"],
    functions=["func_a", "func_b"],
    build_directory="./build_output",
)
```
