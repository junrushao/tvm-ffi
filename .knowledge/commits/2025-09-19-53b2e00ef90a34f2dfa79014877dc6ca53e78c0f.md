# Introduce Python-side TypeInfo metadata classes and dual-index registry replacing OBJECT_TYPE list

## TL;DR
- Introduces three new Python dataclasses (`TypeInfo`, `TypeField`, `TypeMethod`) in a new `cython/type_info.pxi` that materialize C-level `TVMFFITypeInfo`/`TVMFFIFieldInfo`/`TVMFFIMethodInfo` into Python-accessible metadata objects.
- Replaces the flat `OBJECT_TYPE` list (type_index -> class) with a dual-index registry: `TYPE_INDEX_TO_INFO` (list) and `TYPE_KEY_TO_INFO` (dict), both mapping to `TypeInfo` instances that carry the class, fields, methods, and parent info.
- Moves `_add_class_attrs_by_reflection` from Cython (`function.pxi`) to pure Python (`registry.py`) as `_add_class_attrs`, consuming `TypeInfo` instead of calling C API directly.

## Impact
- API: `_register_object_by_index` signature changes (now returns `TypeInfo`). `_add_class_attrs_by_reflection` removed, replaced by `_lookup_type_info_from_type_key` and `_add_class_attrs`. New public types `TypeInfo`, `TypeField`, `TypeMethod` exported from `tvm_ffi.core`.
- Behavioral: `make_ret_object` now resolves `type_cls` through `TYPE_INDEX_TO_INFO[tindex].type_cls` instead of `OBJECT_TYPE[tindex]`. Functionally equivalent but one extra attribute lookup.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- C-level `TVMFFITypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo` structs -- see [0007-c-abi](../design-records/0007-c-abi.md) and [0008-reflection](../design-records/0008-reflection.md)
- `TVMFFIGetTypeInfo`, `TVMFFITypeKeyToIndex` C API functions -- see [0007-c-abi](../design-records/0007-c-abi.md)
- `kTVMFFIFieldFlagBitMaskWritable`, `kTVMFFIFieldFlagBitMaskIsStaticMethod` flag bits -- see [0008-reflection](../design-records/0008-reflection.md)
- `FieldGetter`/`FieldSetter` Cython cdef classes (moved from `function.pxi` to `type_info.pxi`, added `__dict__`)
- `register_object` registration flow -- see [0012-python-bindings](../design-records/0012-python-bindings.md)

Design elements this commit produces:
- `TypeInfo`/`TypeField`/`TypeMethod` Python dataclasses -- new Python-level metadata model for C++ type reflection
- Dual-index registry (`TYPE_INDEX_TO_INFO` + `TYPE_KEY_TO_INFO`) replacing `OBJECT_TYPE` list
- `_lookup_type_info_from_type_key` -- lazy TypeInfo creation for types not yet registered via `register_object`
- `_type_info_create_from_type_key` -- Cython factory that reads C-level `TVMFFITypeInfo` and materializes Python `TypeInfo`

## Usage Examples

**Registration flow (before vs after):**
```python
# BEFORE: class attrs applied by Cython, no metadata returned
core._add_class_attrs_by_reflection(type_index, cls)
core._register_object_by_index(type_index, cls)

# AFTER: TypeInfo returned, class attrs applied in pure Python
info = core._register_object_by_index(type_index, cls)  # returns TypeInfo
_add_class_attrs(type_cls=cls, type_info=info)

# New: look up type metadata by type_key without registering a class
info = core._lookup_type_info_from_type_key("ffi.Array")
print(info.type_key, info.fields, info.methods)
```
