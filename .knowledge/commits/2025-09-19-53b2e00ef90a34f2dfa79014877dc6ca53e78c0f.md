# Introduce Python-side TypeInfo metadata objects for C++ reflection registry

## TL;DR
- Adds a new `type_info.pxi` Cython fragment that defines Python dataclasses `TypeField`, `TypeMethod`, and `TypeInfo` — a structured mirror of `TVMFFITypeInfo` accessible in pure Python.
- Replaces the old `OBJECT_TYPE` list (type_index → class) with dual registries `TYPE_INDEX_TO_INFO` (list) and `TYPE_KEY_TO_INFO` (dict), keyed by type index and type key respectively, each holding full `TypeInfo` objects.
- Moves class-attribute injection (`_add_class_attrs_by_reflection`) from Cython (`function.pxi`) into pure Python (`registry.py`), taking a `TypeInfo` argument instead of reading directly from the C++ type table.

## Impact
- API: `core._register_object_by_index` now returns `TypeInfo` (was `None`); callers in `registry.py` must accept the return value. `core._add_class_attrs_by_reflection` removed from Cython public API; replaced by Python-side `registry._add_class_attrs(type_cls, type_info)`. `core._lookup_type_info_from_type_key` is a new public function.
- Behavioral: `make_ret_object` now looks up `TYPE_INDEX_TO_INFO[tindex].type_cls` instead of `OBJECT_TYPE[tindex]`; behavior is identical for registered types. `FieldGetter`/`FieldSetter` gain `cdef dict __dict__` (was missing), enabling `__name__`, `__module__`, `__qualname__`, and `__doc__` attributes to be set via `TypeField.as_property()`.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements

Design elements this commit consumes:
- `TVMFFIGetTypeInfo` / `TVMFFITypeKeyToIndex` / `TVMFFIFieldInfo` / `TVMFFIMethodInfo` (C ABI, `.knowledge/design-records/0001-c-abi.md`) — queried to build TypeInfo objects.
- `Object` Cython cdef class with `chandle` pointer (`.knowledge/design-records/0013-python-package.md`) — receiver for FieldGetter/FieldSetter callables.
- `TVMFFIPyCallFieldSetter` / `TVMFFIPyArgSetterFactory_` (`.knowledge/design-records/0016-py-ffi-call-dispatch.md`) — used inside FieldSetter.__call__.
- `kTVMFFIFieldFlagBitMaskWritable` / `kTVMFFIFieldFlagBitMaskIsStaticMethod` (`.knowledge/design-records/0001-c-abi.md`) — flag constants used when constructing TypeField.frozen and TypeMethod.is_static.

Design elements this commit produces:
- `TypeInfo` / `TypeField` / `TypeMethod` — new Python-accessible reflection metadata objects; consumed by `@register_object` and (per PR description) upcoming `py_class` decorator.
- `TYPE_INDEX_TO_INFO` / `TYPE_KEY_TO_INFO` dual registries — replace the single `OBJECT_TYPE` list; now the authoritative Python-side type registry.
- `_lookup_type_info_from_type_key` — new extension point enabling pure-Python inspection of C++ types.
- `_add_class_attrs` in pure Python (`registry.py`) — class-attribute injection is now testable and extensible without recompiling Cython.

## Usage Examples

**Context**: `@register_object` flow after this commit (cross-layer: C++ reflection → Python class wiring).

```python
# C++ side (already registered via TVM_FFI_STATIC_INIT_BLOCK):
#   ObjectDef<MyObj>().def_ro("value", &MyObj::value)

# Python side — @register_object decorator
@tvm_ffi.register_object("my.MyType")
class MyType(tvm_ffi.Object):
    pass
# registry.py calls:
#   type_index = core._object_type_key_to_index("my.MyType")
#   info = core._register_object_by_index(type_index, MyType)
#   # info is TypeInfo(type_cls=MyType, type_index=N, type_key="my.MyType",
#   #                  fields=[TypeField(name="value", ...)], methods=[])
#   registry._add_class_attrs(type_cls=MyType, type_info=info)
#   # MyType.value = property(getter, setter)

# Pure-Python type inspection (new capability):
info = core._lookup_type_info_from_type_key("my.MyType")
print(info.type_key)     # "my.MyType"
print(info.type_index)   # e.g., 75
for f in info.fields:
    print(f.name, f.frozen, f.offset)
```
