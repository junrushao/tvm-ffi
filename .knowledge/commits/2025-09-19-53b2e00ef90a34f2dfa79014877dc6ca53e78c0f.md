# Introduce Python-side TypeInfo metadata for FFI-backed types

## TL;DR
- Introduces Python dataclasses `TypeInfo`, `TypeField`, and `TypeMethod` that surface C-side `TVMFFITypeInfo` reflection data as first-class Python objects, enabling pure-Python introspection of FFI type metadata.
- Replaces the opaque `OBJECT_TYPE` list (type index -> Python class) with dual registries `TYPE_INDEX_TO_INFO` (list) and `TYPE_KEY_TO_INFO` (dict) mapping to `TypeInfo` instances, and moves class attribute decoration from Cython (`_add_class_attrs_by_reflection`) to pure Python (`_add_class_attrs` in `registry.py`).
- Adds `_lookup_type_info_from_type_key` for on-demand TypeInfo creation without requiring a registered Python class.

## Key Exports

**Classes** (in `cython/type_info.pxi`, exported via `core`):

```python
@dataclasses.dataclass(eq=False)
class TypeField:
    name: str
    doc: str | None
    size: int
    offset: int
    frozen: bool          # True if field is read-only
    getter: FieldGetter   # Cython cdef class, callable(Object) -> value
    setter: FieldSetter   # Cython cdef class, callable(Object, value) -> None
    def as_property(self, cls: type) -> property: ...

@dataclasses.dataclass(eq=False)
class TypeMethod:
    name: str
    doc: str | None
    func: object          # FFI Function object
    is_static: bool

@dataclasses.dataclass(eq=False)
class TypeInfo:
    type_cls: type | None           # None for unregistered types
    type_index: int
    type_key: str
    fields: list[TypeField]
    methods: list[TypeMethod]
    parent_type_info: TypeInfo | None  # always None in this commit
```

**Functions** (signature changes):

| Function | Old signature | New signature |
|----------|--------------|---------------|
| `core._register_object_by_index` | `(index: int, cls: type) -> None` | `(type_index: int, type_cls: type) -> TypeInfo` |
| `core._add_class_attrs_by_reflection` | `(type_index: int, cls: type) -> type` | **Removed** |
| `core._lookup_type_info_from_type_key` | N/A (new) | `(type_key: str) -> TypeInfo` |

**Cython internal changes**:

| Symbol | Change |
|--------|--------|
| `FieldGetter` (cdef class) | Moved from `function.pxi` to `type_info.pxi`; gains `cdef dict __dict__` for dunder attribute assignment |
| `FieldSetter` (cdef class) | Moved from `function.pxi` to `type_info.pxi`; gains `cdef dict __dict__` |
| `OBJECT_TYPE` (cdef list) | **Removed** |
| `TYPE_INDEX_TO_INFO` (cdef list) | New; maps type_index -> TypeInfo |
| `TYPE_KEY_TO_INFO` (cdef dict) | New; maps type_key (str) -> TypeInfo |

**Pure Python** (`registry.py`):

```python
def _add_class_attrs(type_cls: type, type_info: TypeInfo) -> type: ...
def _member_method_wrapper(method_func: Callable) -> Callable: ...
```

## Impact
- API: `_register_object_by_index` return type changed from `None` to `TypeInfo`. `_add_class_attrs_by_reflection` removed; replaced by `_lookup_type_info_from_type_key` and `_add_class_attrs`. These are internal APIs (prefixed with `_`), so external impact is minimal.
- Behavioral: Object dispatch (`make_ret_object`) now reads `TYPE_INDEX_TO_INFO[tindex].type_cls` instead of `OBJECT_TYPE[tindex]`. Semantically equivalent but adds one attribute access.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C-side reflection metadata** (`TVMFFITypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`): read via `TVMFFIGetTypeInfo(type_index)` in the new `_type_info_create_from_type_key` Cython function. See [0009-reflection.md](../designs/0009-reflection.md).
- **Object registration pipeline** (`register_object` -> `_object_type_key_to_index` -> `_register_object_by_index`): the existing two-step registration is preserved but the second step now produces a `TypeInfo`. See [0014-python-package.md](../designs/0014-python-package.md).
- **Type-cached dispatch** (`make_ret_object`): the return-value constructor path now dereferences through `TypeInfo.type_cls`. See [0015-python-ffi-call-dispatch.md](../designs/0015-python-ffi-call-dispatch.md).

Design elements this commit produces:
- **Python TypeInfo metadata model** (`TypeInfo`, `TypeField`, `TypeMethod`): a new Python-side data model that mirrors C `TVMFFITypeInfo` and enables pure-Python introspection of FFI type reflection. Not yet documented in `.knowledge/designs/`.
- **Dual type registry** (`TYPE_INDEX_TO_INFO` + `TYPE_KEY_TO_INFO`): replaces the flat `OBJECT_TYPE` list. Enables lookup by both integer index (for dispatch) and string key (for deferred/lazy metadata queries).
- **On-demand TypeInfo creation** (`_lookup_type_info_from_type_key`): creates `TypeInfo` with `type_cls=None` for types that have C reflection data but no registered Python class.

## Usage Examples

Registering a Python object class and inspecting its metadata:
```python
import tvm_ffi
from tvm_ffi.core import TypeInfo

@tvm_ffi.register_object("test.MyObj")
class MyObj(tvm_ffi.Object):
    pass

# _register_object_by_index now returns TypeInfo
# Internally, register_object uses it to decorate the class:
info = tvm_ffi.core._lookup_type_info_from_type_key("test.MyObj")
assert isinstance(info, TypeInfo)
assert info.type_key == "test.MyObj"
for field in info.fields:
    print(f"field: {field.name}, frozen={field.frozen}, size={field.size}")
for method in info.methods:
    print(f"method: {method.name}, static={method.is_static}")
```
