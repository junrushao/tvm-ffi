# Introduce Python-side TypeInfo metadata for type reflection lookup
## TL;DR
- Introduces `TypeInfo`, `TypeField`, and `TypeMethod` dataclasses in a new `type_info.pxi` Cython include file, making C++ reflection metadata (fields, methods, type hierarchy) queryable from pure Python.
- Replaces the flat `OBJECT_TYPE: list[type]` registry with dual-index `TYPE_INDEX_TO_INFO: list[TypeInfo]` and `TYPE_KEY_TO_INFO: dict[str, TypeInfo]`, enabling lookup by both type index and type key.
- Moves `_add_class_attrs_by_reflection` from Cython (`function.pxi`) to pure Python (`registry.py`) as `_add_class_attrs`, now consuming `TypeInfo` objects instead of calling C ABI directly. Removes `_add_class_attrs_by_reflection` from the public API.

## Key Exports

```python

    doc: str | None
    size: int
    offset: int

    setter: FieldSetter          # Cython cdef class, calls TVMFFIFieldSetter C pointer
    # Invariant: getter and setter are always non-None (asserted in __post_init__)
    # Invariant: frozen fields have setter populated but it is not exposed as property fset

    def as_property(self, cls: type) -> property: ...
        # Creates a Python property with fget/fset, setting __name__/__module__/__qualname__
        # on the underlying getter/setter for debuggability
        # Interacts with: FieldGetter, FieldSetter (Cython cdef classes)
        # Extension: can be used by py_class or other class-building decorators

@dataclasses.dataclass(eq=False)
class TypeMethod:
    """Description of a single reflected method on an FFI-backed type."""
    name: str
    doc: str | None
    func: object                 # The FFI Function object (from TVMFFIMethodInfo.method)
    is_static: bool              # True if kTVMFFIFieldFlagBitMaskIsStaticMethod flag set
    # Interacts with: Function (cython/function.pxi)

@dataclasses.dataclass(eq=False)
class TypeInfo:
    """Aggregated type information required to build a proxy class."""
    type_cls: type | None        # The registered Python class, or None for unregistered types
    type_index: int              # C++ runtime type index
    type_key: str                # C++ type key string (e.g. "ffi.Array")
    fields: list[TypeField]      # All reflected fields for this type
    methods: list[TypeMethod]    # All reflected methods for this type
    parent_type_info: TypeInfo | None  # Always None in this commit (placeholder for future)
    # Interacts with: TVMFFIGetTypeInfo (C ABI), TVMFFIFieldInfo, TVMFFIMethodInfo
    # Interacts with: _register_object_by_index, _lookup_type_info_from_type_key
    # Extension: parent_type_info will be populated to support inherited field traversal

# === Changed module-level registries (object.pxi) ===

TYPE_INDEX_TO_INFO: list[TypeInfo | None] = []
    # Replaces: OBJECT_TYPE: list[type]
    # Indexed by C++ type_index; None for unregistered slots
    # Interacts with: make_ret_object (lookup type_cls for return conversion)

TYPE_KEY_TO_INFO: dict[str, TypeInfo] = {}
    # New index: keyed by type_key string
    # Interacts with: _lookup_type_info_from_type_key

# === Changed Cython functions ===

# Old: def _register_object_by_index(index: int, cls: type) -> None
# New:
```

## Impact
- API: `_register_object_by_index` signature changed (returns `TypeInfo` instead of `None`, parameter names changed to `type_index`/`type_cls`). `_add_class_attrs_by_reflection` removed and replaced by `_lookup_type_info_from_type_key`. Both are internal APIs (underscore-prefixed), so external impact is minimal.
- Behavioral: `make_ret_object` now reads `TYPE_INDEX_TO_INFO[tindex].type_cls` instead of `OBJECT_TYPE[tindex]`. Functionally equivalent for all registered types.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C ABI type table** (`TVMFFIGetTypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`) -- the source of field/method metadata. See [0001-c-abi.md](../designs/0001-c-abi.md).
- **C++ reflection system** (`ObjectDef<T>`, field/method registration) -- populates the type table consumed here. See [0008-reflection.md](../designs/0008-reflection.md).
- **Python object registration protocol** (`register_object`, `OBJECT_TYPE`, `make_ret`) -- the existing registration and return-conversion pipeline being refactored. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **FieldGetter/FieldSetter Cython cdef classes** -- moved from `function.pxi` to `type_info.pxi`, now carry `__dict__` for attribute assignment (needed by `TypeField.as_property` which sets `__name__`, `__module__`, `__qualname__`).

Design elements this commit produces:
- **TypeInfo/TypeField/TypeMethod Python metadata** -- new Python-queryable representation of C++ reflection data. Not yet documented in any design doc.
- **Dual-index type registry** (`TYPE_INDEX_TO_INFO` + `TYPE_KEY_TO_INFO`) -- replaces the single `OBJECT_TYPE` list with richer indexing.
- **`_lookup_type_info_from_type_key`** -- new entry point enabling pure-Python code to query reflection metadata without going through object registration. This is the key enabler for future `py_class` / `c_class` decorators.

## Usage Examples
Registration flow using the new TypeInfo-based protocol:

```python
# registry.py register_object() now does:
type_index = core._object_type_key_to_index(type_key)
info = core._register_object_by_index(type_index, cls)  # returns TypeInfo
_add_class_attrs(type_cls=cls, type_info=info)           # pure Python

# Querying type info for an unregistered type (no Python class):
info = core._lookup_type_info_from_type_key("test.Float")
for field in info.fields:
    print(f"{field.name}: frozen={field.frozen}, offset={field.offset}")
for method in info.methods:
    print(f"{method.name}: is_static={method.is_static}")
```
