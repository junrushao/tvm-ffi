# feat: Introduce Python-side TypeInfo Metadata (#30)
## TL;DR
- Introduces a Python-side `TypeInfo` / `TypeField` / `TypeMethod` metadata model (as `dataclasses` in a new `type_info.pxi` Cython include file) that mirrors the C-level `TVMFFITypeInfo` / `TVMFFIFieldInfo` / `TVMFFIMethodInfo` structs.
- Refactors `_register_object_by_index` to return a `TypeInfo` instance and maintain two new global registries: `TYPE_INDEX_TO_INFO` (list) and `TYPE_KEY_TO_INFO` (dict), replacing the flat `OBJECT_TYPE` list.
- Moves `FieldGetter`, `FieldSetter`, and the reflection-based class decoration logic out of `function.pxi` and into `type_info.pxi` (Cython classes) and `registry.py` (pure Python `_add_class_attrs`).
- Removes `_add_class_attrs_by_reflection` (Cython) and replaces it with `_add_class_attrs` (pure Python in `registry.py`) that consumes `TypeInfo`.
- Adds `_lookup_type_info_from_type_key` for lazy lookup of type info by type key without requiring a pre-registered Python class.

## Key Exports

| Symbol | Module | Kind | Signature / Description |
|--------|--------|------|------------------------|
| `TypeField` | `tvm_ffi.core` (via `type_info.pxi`) | dataclass | `name: str, doc: str|None, size: int, offset: int, frozen: bool, getter: FieldGetter, setter: FieldSetter` -- describes a single reflected field |
| `TypeMethod` | `tvm_ffi.core` (via `type_info.pxi`) | dataclass | `name: str, doc: str|None, func: object, is_static: bool` -- describes a single reflected method |
| `TypeInfo` | `tvm_ffi.core` (via `type_info.pxi`) | dataclass | `type_cls: type|None, type_index: int, type_key: str, fields: list[TypeField], methods: list[TypeMethod], parent_type_info: TypeInfo|None` -- aggregated type metadata |
| `TypeField.as_property` | `tvm_ffi.core` (via `type_info.pxi`) | method | `(cls: type) -> property` -- creates a Python property with proper `__name__`, `__module__`, `__qualname__` |
| `_register_object_by_index` | `tvm_ffi.core` (via `object.pxi`) | function | `(type_index: int, type_cls: type) -> TypeInfo` -- now returns `TypeInfo` and populates both index and key registries |
| `_lookup_type_info_from_type_key` | `tvm_ffi.core` (via `object.pxi`) | function | `(type_key: str) -> TypeInfo` -- lazy lookup: returns cached info or creates from C metadata with `type_cls=None` |
| `_add_class_attrs` | `tvm_ffi.registry` | function | `(type_cls: type, type_info: TypeInfo) -> type` -- pure Python function that attaches fields as properties and methods to a class |

## Impact
- API: `_register_object_by_index` signature changes from `(index: int, cls: type) -> None` to `(type_index: int, type_cls: type) -> TypeInfo`. `_add_class_attrs_by_reflection` is removed and replaced by `_lookup_type_info_from_type_key` and the pure-Python `_add_class_attrs`. These are internal/underscore-prefixed APIs.
- ABI: None. No C ABI changes.
- Behavioral: Object return value dispatch in `make_ret_object` now reads `TYPE_INDEX_TO_INFO[tindex].type_cls` instead of `OBJECT_TYPE[tindex]`. Functionally equivalent.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/reflection.md`): The C-level `TVMFFITypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo` structs whose data is read by `_type_info_create_from_type_key` to populate the Python-side `TypeInfo`.
- **Python bindings -- reflection-based class decoration** (`.knowledge/designs/0014-python-bindings.md`): The prior `_add_class_attrs_by_reflection` Cython function is refactored into `_add_class_attrs` (pure Python) consuming the new `TypeInfo` dataclass.
- **Object type registry** (`.knowledge/designs/0014-python-bindings.md`): The `OBJECT_TYPE` list dispatch mechanism in `make_ret_object` is migrated to `TYPE_INDEX_TO_INFO`.

Design elements this commit produces:
- **Python-side TypeInfo metadata model**: `TypeInfo`, `TypeField`, `TypeMethod` dataclasses that provide a Python-native representation of C reflection metadata. This enables pure-Python code to introspect registered types without calling back into Cython/C. The `_lookup_type_info_from_type_key` function supports lazy materialization (types that exist in C but have no registered Python class yet get `type_cls=None`).
- **Dual-registry pattern** (`TYPE_INDEX_TO_INFO` + `TYPE_KEY_TO_INFO`): Replaces the flat `OBJECT_TYPE` list with two registries that support both index-based lookup (for `make_ret_object` fast path) and key-based lookup (for lazy introspection).
- **TypeField.as_property**: A method on `TypeField` that creates a fully-annotated Python `property` with `__name__`, `__module__`, `__qualname__`, and `__doc__` set -- richer than the previous inline property creation in the Cython loop.

## Usage Examples
```python
from tvm_ffi import core

# Look up type info for a registered type by key (no Python class needed)
info = core._lookup_type_info_from_type_key("ffi.Array")
print(info.type_key)     # "ffi.Array"
print(info.type_index)   # integer type index
print(info.type_cls)     # <class 'tvm_ffi.container.Array'> if registered, else None
for field in info.fields:
    print(f"  field: {field.name}, frozen={field.frozen}")
for method in info.methods:
    print(f"  method: {method.name}, is_static={method.is_static}")
```

```python
# TypeField.as_property creates a richly-annotated property
field = info.fields[0]
prop = field.as_property(some_cls)
# prop.__doc__ == "tvm_ffi.container.Array.some_field"
```
