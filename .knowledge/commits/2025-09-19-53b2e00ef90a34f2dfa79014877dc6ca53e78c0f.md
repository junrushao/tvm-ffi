# Introduce Python-side TypeInfo metadata for FFI type reflection
## TL;DR
- Adds `TypeInfo`, `TypeField`, and `TypeMethod` Python dataclasses that mirror C-level `TVMFFITypeInfo`/`TVMFFIFieldInfo`/`TVMFFIMethodInfo`, enabling pure-Python introspection of FFI-registered types.
- Replaces the flat `OBJECT_TYPE` list (type_index -> class) with a richer `TYPE_INDEX_TO_INFO` (type_index -> TypeInfo) and `TYPE_KEY_TO_INFO` (type_key -> TypeInfo) dual registry.
- Moves `FieldGetter`/`FieldSetter` Cython classes and class-attribute decoration logic from `function.pxi` into the new `type_info.pxi` and `registry.py`, separating type metadata from function dispatch.

## Impact
- API: `_register_object_by_index` signature changed from `(int, type) -> None` to `(int, type) -> TypeInfo`. `_add_class_attrs_by_reflection` removed; replaced by `_add_class_attrs` in `registry.py`. New exports: `TypeInfo`, `TypeField`, `TypeMethod`, `_lookup_type_info_from_type_key`.
- Behavioral: `make_ret_object` now reads `TYPE_INDEX_TO_INFO[tindex].type_cls` instead of `OBJECT_TYPE[tindex]`. Functionally equivalent but the lookup goes through TypeInfo.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C-level TVMFFITypeInfo/TVMFFIFieldInfo/TVMFFIMethodInfo** (`.knowledge/design-records/0007-ffi-reflection.md`) -- the C ABI structs that store per-type field/method metadata. This commit reads them via `TVMFFIGetTypeInfo` to populate the new Python TypeInfo.
- **TVMFFIFieldFlagBitMask** (`.knowledge/design-records/0007-ffi-reflection.md`) -- bitmask constants `kTVMFFIFieldFlagBitMaskWritable` and `kTVMFFIFieldFlagBitMaskIsStaticMethod` used to derive `TypeField.frozen` and `TypeMethod.is_static`.
- **Object dispatch table pattern** (`.knowledge/design-records/0012-ffi-python-package.md`) -- the type_index-to-class mapping used by `make_ret_object`, now replaced by TypeInfo-backed registry.

Design elements this commit produces:
- **TypeInfo / TypeField / TypeMethod** -- Python-side metadata dataclasses that enable pure-Python introspection of FFI-registered types. First-class Python representation of the C reflection table.
- **TYPE_INDEX_TO_INFO / TYPE_KEY_TO_INFO** -- Dual-indexed Python-side type registry replacing the flat `OBJECT_TYPE` list. Enables both index-based lookup (for `make_ret_object`) and key-based lookup (for `_lookup_type_info_from_type_key`).
- **type_info.pxi** -- New Cython include file in the `core.pyx` compilation unit, included before `object.pxi`.

## Usage Examples
Registering a type and inspecting its metadata from pure Python:
```python
import tvm_ffi
from tvm_ffi.core import TypeInfo, _lookup_type_info_from_type_key

# Register a C++-defined type
@tvm_ffi.register_object("test.Float")
class TestFloat(tvm_ffi.Object):
    pass

# Introspect from pure Python
info: TypeInfo = _lookup_type_info_from_type_key("test.Float")
assert info.type_key == "test.Float"
assert info.type_cls is TestFloat
for field in info.fields:
    print(f"{field.name}: frozen={field.frozen}, offset={field.offset}")
for method in info.methods:
    print(f"{method.name}: is_static={method.is_static}")
```
