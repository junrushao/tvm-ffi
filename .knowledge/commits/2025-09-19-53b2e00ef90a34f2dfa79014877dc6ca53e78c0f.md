# Introduce Python-side TypeInfo metadata and registry
## TL;DR
- Creates `type_info.pxi` with new Cython-level `TypeInfo`, `TypeField`, `TypeMethod` dataclasses that hold per-type metadata (fields, methods, parent info) in Python-accessible form, replacing the opaque C-only `TVMFFITypeInfo` lookup.
- Replaces the `OBJECT_TYPE` list (index->class) with `TYPE_INDEX_TO_INFO` list and `TYPE_KEY_TO_INFO` dict mapping to `TypeInfo` objects. `_register_object_by_index` now returns a `TypeInfo`.
- Moves `FieldGetter`, `FieldSetter`, `_add_class_attrs_by_reflection`, and `_member_method_wrapper` from `function.pxi` into `type_info.pxi` (Cython) and `registry.py` (pure Python `_add_class_attrs`), separating reflection metadata from function call dispatch.
- Adds `_lookup_type_info_from_type_key` for lazy TypeInfo creation from C-side metadata without requiring a registered Python class.

## Impact
- API: `_register_object_by_index` now returns a `TypeInfo` object. `_add_class_attrs_by_reflection` is removed from the Cython module; replaced by Python-side `_add_class_attrs` in `registry.py`. New exports: `TypeInfo`, `TypeField`, `TypeMethod`, `_type_info_create_from_type_key`, `_lookup_type_info_from_type_key`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection** (`.knowledge/designs/0006-reflection.md`): The C-side `TVMFFITypeInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo` structs are now wrapped into Python dataclasses (`TypeInfo`, `TypeField`, `TypeMethod`) for introspection.
- **Python Bindings** (`.knowledge/designs/0014-python-bindings.md`): The object type registration pipeline (`_register_object_by_index`) is restructured to populate `TypeInfo` instead of a flat class list.

Design elements this commit produces:
- **Python TypeInfo Registry**: Two new lookup tables (`TYPE_INDEX_TO_INFO` by index, `TYPE_KEY_TO_INFO` by key) store `TypeInfo` metadata. This enables pure-Python code to introspect type fields, methods, and parent chain without C API calls. Key extension point for future features like auto-generated dataclass-style constructors and stub generation.
- **TypeInfo / TypeField / TypeMethod dataclasses**: Stable Python-level representation of C++ reflection metadata. `TypeField` includes `FieldGetter`/`FieldSetter` Cython extension types for direct field access.
- **Lazy TypeInfo creation**: `_lookup_type_info_from_type_key` creates `TypeInfo` on demand from C metadata, even for types without a registered Python class (`type_cls=None`).
