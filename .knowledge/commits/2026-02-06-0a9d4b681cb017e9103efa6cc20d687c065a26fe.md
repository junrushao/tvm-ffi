# Add ffi::Expected<T> for exception-free error handling
## TL;DR
- Introduces `Expected<T>` (similar to Rust's `Result<T, Error>` or C++23 `std::expected`) for exception-free error handling in C++ FFI code.
- Adds `Unexpected<E>` wrapper for explicit error construction.
- Adds `Function::CallExpected<T>(args...)` that catches all exceptions from `safe_call` and returns them as `Expected<T>` error values instead of throwing.
- Full `TypeTraits<Expected<T>>` specialization enabling `Expected<T>` to participate in the Any type system (unwraps to either T or Error).
- Functions returning `Expected<T>` can be registered as global FFI functions; the return value is transparently serialized through the ABI (Ok values as the success type, Err values as Error objects).

## Impact
- API: New `Expected<T>` class in `include/tvm/ffi/expected.h`, `Unexpected<E>` wrapper, `Function::CallExpected<T>()` method.
- Error handling: Enables exception-free calling convention alongside existing exception-based convention.
- TypeTraits: `Expected<T>` serializes to `Any` as either T or Error, with `TypeSchema` producing `{"type":"Expected","args":[T_schema, {"type":"ffi.Error"}]}`.
