# Add ffi::Expected<T> for exception-free error handling in C++ FFI

## TL;DR
- Introduces `Expected<T>` (Rust `Result`/C++23 `std::expected` analog) in `include/tvm/ffi/expected.h` with implicit success/error construction, `is_ok()`, `is_err()`, `value()`, `error()`, `value_or()`.
- Adds `Unexpected<E>` wrapper for explicit error construction and a deduction guide.
- Extends `Function::CallExpected<T>()` on the packed-function path as an exception-free alternative to normal `operator()` + exception propagation; also registers functions returning `Expected<T>` transparently via `TypeTraits<Expected<T>>`.

## Key Exports

```python
class Unexpected(Generic[E]):
    """Wrapper to explicitly construct an Expected in the error state."""
    def __init__(self, error: E) -> None: ...
    def error(self) -> E: ...
    # Invariant: E must be Error or a subclass of Error

class Expected(Generic[T]):
    """Exception-free result type; holds T on success or Error on failure."""
    # Implicit constructor from T or Error (no explicit needed)
    def is_ok(self) -> bool: ...
    def is_err(self) -> bool: ...
    def has_value(self) -> bool: ...
    def value(self) -> T: ...          # raises contained Error if is_err()
    def error(self) -> Error: ...      # raises RuntimeError if is_ok()
    def value_or(self, default: T) -> T: ...
    # Invariant: T must not be Error itself (static_assert)
    # Interacts with: Any (data_ field stores T or Error), TypeTraits<Expected<T>>,
    #                 Function::CallExpected
    # Extension: no subclassing needed; TypeTraits specialization below hooks ABI

# TypeTraits<Expected<T>> — allows Expected<T> to flow through Any and Function registration
class TypeTraits_Expected(TypeTraitsBase):
    # CopyToAnyView: unwraps to T-traits or Error-traits path
    # MoveToAny: same
    # CheckAnyStrict: T or Error type check
    # CopyFromAnyViewAfterCheck / MoveFromAnyAfterCheck: reconstruct Expected<T>
    # TryCastFromAnyView: tries T first, then Error
    # Interacts with: TypeTraits<T>, TypeTraits<Error>, AnyView, Any

class Function:
    def CallExpected(self, *args: Any, T=Any) -> Expected[T]:
        """Exception-free call: catches exceptions and returns them as Expected errors."""
        # Interacts with: FunctionObj.safe_call (C ABI, returns int ret_code),
        #                 details::MoveFromSafeCallRaised (unpacks TLS error slot)
        # Invariant: ret_code==0 means success; non-zero means TLS error slot is populated
        # Extension: pass explicit T= to get typed Expected without cast
```

## Impact
- API: Additive only — `Expected<T>`, `Unexpected<E>`, `Function::CallExpected<T>()` are new symbols; no existing API changed. `include/tvm/ffi/tvm_ffi.h` umbrella header now includes `expected.h`.
- Behavioral: Functions that return `Expected<T>` registered via `Function::FromTyped` now propagate errors through the `TypeTraits<Expected<T>>` machinery — a normal `func(...).cast<int>()` call will throw if the function returned an error, preserving exception-based callers.
- Flags/config: none
- Data formats/schemas: `TypeTraits<Expected<T>>::TypeSchema()` emits `{"type":"Expected","args":[<T-schema>,{"type":"ffi.Error"}]}`.

## Usage Examples

**Exception-free FFI call with `Function::CallExpected`:**
```cpp
// Register a function that may fail
auto safe_divide = [](int a, int b) -> Expected<int> {
    if (b == 0) return Error("ValueError", "Division by zero", "");
    return a / b;
};
Function::SetGlobal("test.safe_divide", Function::FromTyped(safe_divide));

// Call without exceptions
Function func = Function::GetGlobalRequired("test.safe_divide");
Expected<int> ok = func.CallExpected<int>(10, 2);
if (ok.is_ok()) {
    int val = ok.value();  // 5
}
Expected<int> err = func.CallExpected<int>(10, 0);
if (err.is_err()) {
    Error e = err.error();  // kind()=="ValueError"
}
```

**Returning `Expected<T>` from a function (inline use):**
```cpp
Expected<int> result = 42;          // success path
Expected<int> bad = Error("TypeError", "bad", "");  // error path
int v = result.value_or(0);         // 42
int d = bad.value_or(-1);           // -1
```
