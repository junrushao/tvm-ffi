# Fix Tuple variadic constructor SFINAE to prevent false match during iterator forwarding
## TL;DR
- Fixed `Tuple<Types...>` variadic constructor (`Tuple(UTypes&&... args)`) to exclude the case where a single `Tuple<Types>` argument would match the forwarding constructor instead of the move/copy constructor, causing compilation failures during `std::vector::insert` from `Array` iterators.
- Added `operator+=` and `operator-=` to `IterAdapter` to satisfy `std::random_access_iterator` requirements needed by `std::vector::insert`.
- Added two regression tests: multi-element and single-element `Tuple` forwarded from `Array` iterators into `std::vector`.

## Key Exports

```python
# --- Fix: Tuple variadic constructor SFINAE tightening ---
# Before (broken):
# template <typename... UTypes>
# explicit Tuple(UTypes&&... args)    # No SFINAE guard; Tuple<T>(Tuple<T>&&) matches this
#   -> static_assert(sizeof...(Types) == sizeof...(UTypes))  # runtime error, not SFINAE

# After (fixed):
# template <typename... UTypes,
#           typename = enable_if_t<
#               sizeof...(Types) == sizeof...(UTypes) &&
#               !(sizeof...(Types) == 1 && is_same_v<remove_cv_t<UTypes>, Tuple<Types>>...)>>
# explicit Tuple(UTypes&&... args)
#   # Invariant: when sizeof...(Types)==1, rejects Tuple<T> itself as the single arg,
#   #   forcing the compiler to select the proper move/copy constructor instead.
#   # Interacts with: move ctor Tuple(Tuple<UTypes...>&&), copy ctor Tuple(const Tuple<UTypes...>&)

# --- Fix: IterAdapter compound assignment operators ---
class IterAdapter:
    """Iterator adapter wrapping TIter with type-converting dereference."""
    # New operators (were missing, required for LegacyRandomAccessIterator):
    def __iadd__(self, offset: int) -> IterAdapter: ...
    #   Invariant: required by std::vector::insert when source is random-access iterator
    def __isub__(self, offset: int) -> IterAdapter: ...
    #   Interacts with: Array::begin()/end() which return IterAdapter over Any*
```

## Impact
- API: None -- additive operators on IterAdapter; Tuple constructor signature is tightened but all valid callers continue to compile.
- Behavioral: `std::vector<Tuple<T>>::insert(pos, Array<Tuple<T>>::begin(), Array<Tuple<T>>::end())` now compiles and works correctly. Previously failed due to: (1) missing `operator+=`/`operator-=` on `IterAdapter`, and (2) the variadic constructor greedily matching `Tuple<T>&&` when `sizeof...(Types)==1`.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
**Before (broken)**: inserting `Array<Tuple<TInt>>` elements into a `std::vector<Tuple<TInt>>` via iterator range failed to compile because:
1. `IterAdapter` lacked `operator+=`/`-=`, violating `LegacyRandomAccessIterator`.
2. `Tuple<TInt>(Tuple<TInt>&&)` matched the variadic `Tuple(UTypes&&...)` instead of the move constructor.

**After (fixed)**:
```cpp
Tuple<TInt> t0(1);
Tuple<TInt> t1(2);
Array<Tuple<TInt>> arr0 = {t0, t1};
std::vector<Tuple<TInt>> vec0 = {t0};
// This now compiles and works correctly:
vec0.insert(vec0.end(), arr0.begin(), arr0.end());
// vec0 == {Tuple(1), Tuple(1), Tuple(2)}
```
