# Fix Tuple variadic constructor hijacking Tuple<T> rvalue and add missing IterAdapter compound-assignment operators

## TL;DR
- `Tuple<T>(UTypes&&... args)` with a single `Tuple<T>&&` argument was matching the variadic element constructor instead of the move constructor, causing UB; an `enable_if_t` SFINAE guard now excludes this case.
- `IterAdapter` was missing `operator+=` and `operator-=`, which are required for random-access iterator completeness (needed by `std::vector::insert(end, arr.begin(), arr.end())`).
- Two regression tests added: multi-element and single-element `Tuple` forwarding through `Array` into `std::vector`.

## Key Exports

```python
# Tuple variadic constructor — before (include/tvm/ffi/container/tuple.h)
# template <typename... UTypes>
# explicit Tuple(UTypes&&... args)  # BUG: matches Tuple<T>&& for single-element case
#   : ObjectRef(MakeTupleNode(std::forward<UTypes>(args)...)) {
#   static_assert(sizeof...(Types) == sizeof...(UTypes), "Tuple size mismatch");
# }

# Tuple variadic constructor — after
class Tuple(ObjectRef):
    """Fixed-size heterogeneous typed sequence."""

    def __init__(self, *args: UTypes) -> None:
        # SFINAE guard (both conditions must hold to enable this overload):
        #   1. sizeof...(UTypes) == sizeof...(Types)  — count match
        #   2. NOT (single arg AND arg type == Tuple<Types>)  — exclude move/copy case
        # If guard fails → compile error (no matching constructor), not silent UB
        # Invariant: args are forwarded to MakeTupleNode, which stores them as Any
        # Interacts with: MakeTupleNode (constructs TupleObj), move constructor (Tuple<UTypes...>&&)
        ...


class IterAdapter(Generic[T]):
    """Random-access iterator adapter over raw pointer/index iterators (container_details.h)."""

    def __iadd__(self, offset: int) -> IterAdapter:  # operator+=, newly added
        self.iter_ += offset
        return self

    def __isub__(self, offset: int) -> IterAdapter:  # operator-=, newly added
        self.iter_ -= offset
        return self

    # Interacts with: std::vector::insert (requires +=/-= for random_access_iterator_tag)
    # Invariant: iterator_category must be random_access_iterator_tag for these to be meaningful
    # Extension: operator+ and operator- were already present; this completes the iterator contract
```

## Impact
- API: None — `Tuple` constructor interface is unchanged from the caller's perspective; SFINAE guard only tightens overload resolution silently.
- Behavioral: Fixes silent UB where `Tuple<T> t = some_tuple_t_rvalue` (single-element) previously forwarded the rvalue into `MakeTupleNode` instead of invoking the move constructor.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `Tuple<Types...>` — typed fixed-size heterogeneous container (`0007-containers.md`); the commit fixes its constructor overload set
- `IterAdapter` — random-access iterator wrapper in `container_details.h` (`0007-containers.md`); the commit extends it with compound-assignment operators
- `MakeTupleNode` — internal factory that stores elements as `Any` in a `TupleObj`; consumed by the corrected constructor

Design elements this commit produces:
- Tightened `Tuple<Types...>` constructor contract: variadic constructor now has an explicit SFINAE exclusion preventing it from matching `Tuple<Types>&&` rvalues (replaces the previous `static_assert` approach).
- Completed `IterAdapter` random-access iterator interface (`operator+=`, `operator-=`).

## Usage Examples

**Before (incorrect — variadic constructor hijacks move)**:
```cpp
Tuple<TInt> t0(1);
Tuple<TInt> t1(2);
Array<Tuple<TInt>> arr = {t0, t1};
std::vector<Tuple<TInt>> vec = {t0};
// BUG: insert calls Tuple<TInt>(Tuple<TInt>&&) via the variadic ctor,
// which passes a Tuple object into MakeTupleNode — wrong element type
vec.insert(vec.end(), arr.begin(), arr.end());
```

**After (correct — move constructor used)**:
```cpp
Tuple<TInt> t0(1);
Tuple<TInt> t1(2);
Array<Tuple<TInt>> arr = {t0, t1};
std::vector<Tuple<TInt>> vec = {t0};
// SFINAE guard on variadic ctor excludes Tuple<TInt>&& → move ctor is selected
vec.insert(vec.end(), arr.begin(), arr.end());
EXPECT_EQ(vec.size(), 3);            // vec[0]=1, vec[1]=1, vec[2]=2
```
