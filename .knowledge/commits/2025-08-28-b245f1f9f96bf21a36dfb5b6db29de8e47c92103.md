# Add GIT_REPOSITORY and GIT_TAG to ExternalProject_Add for libbacktrace

## TL;DR
- Adds `GIT_REPOSITORY` and `GIT_TAG` directives to the `ExternalProject_Add(project_libbacktrace ...)` call in `cmake/Utils/AddLibbacktrace.cmake`, pointing to `https://github.com/ianlancetaylor/libbacktrace.git` at commit `793921876c981ce49759114d7bb89bb89b2d3a2d`.
- Fixes builds where the `3rdparty/libbacktrace` git submodule is not checked out: CMake's `ExternalProject` can now download the source automatically via the `GIT_REPOSITORY`/`GIT_TAG` pair, falling back from the `SOURCE_DIR` local path.

## Key Exports
No new symbols, no signature changes. This commit modifies only CMake build infrastructure.

**Modified file**:
- `cmake/Utils/AddLibbacktrace.cmake` -- two lines added (`GIT_REPOSITORY`, `GIT_TAG`) to the `ExternalProject_Add` invocation, between the `PREFIX` and `SOURCE_DIR` directives.

## Impact
- **API**: None -- no C/C++/Python interface changes.
- **ABI**: None -- no object layout or symbol changes.
- **Behavioral**: When the `3rdparty/libbacktrace` submodule directory is missing or empty, CMake's `ExternalProject_Add` will now clone libbacktrace from GitHub at the pinned commit instead of failing. When the submodule is present, `SOURCE_DIR` still takes precedence.
- **Build**: Enables building without `git submodule update --init --recursive` for the libbacktrace dependency. This is useful for CI environments or tarball-based source distributions that do not include submodules.
- **Note**: This commit was reverted one day later in commit `7d09d6a` (#18249), which removed the `GIT_REPOSITORY`/`GIT_TAG` lines and instead updated the submodule pointer to the same upstream commit (`793921876c981ce49759114d7bb89bb89b2d3a2d`). The revert was motivated by preferring the git submodule approach for consistency and because the upstream libbacktrace already incorporated the needed macOS fix.

## Design Elements

Design elements this commit **consumes**:

- **CMake ExternalProject_Add for libbacktrace**: The existing `AddLibbacktrace.cmake` module uses `ExternalProject_Add` with `SOURCE_DIR` pointing to the vendored `3rdparty/libbacktrace` submodule. The autotools configure/make flow is already in place. This commit adds download directives to the same `ExternalProject_Add` call.
- **libbacktrace vendoring via git submodule**: The `3rdparty/libbacktrace` directory is managed as a git submodule. The submodule was previously pinned to a fork (`tlc-pack/libbacktrace`) with a macOS patch. The `GIT_TAG` in this commit points to upstream libbacktrace which already incorporates that patch.

Design elements this commit **produces**:

- **Dual-source ExternalProject pattern** (short-lived): Combines `GIT_REPOSITORY`/`GIT_TAG` with `SOURCE_DIR` in a single `ExternalProject_Add` call, providing both a remote download fallback and a local source directory. When both are specified, CMake clones into `SOURCE_DIR` if it is empty, or uses the existing contents if already populated. This pattern was reverted in the followup commit `7d09d6a` in favor of the submodule-only approach.

## Usage Examples

No change in user-facing usage. The build command remains:
```bash
cmake . -B build_cpp -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build_cpp --parallel --target tvm_ffi_shared
```

The difference is that this commit allows the build to succeed even when `3rdparty/libbacktrace` has not been initialized via `git submodule update --init`.
