# Relax default alignment and contiguous requirement in DLPack import

## TL;DR

- `from_dlpack` defaults changed: `require_alignment` 8→0 (disabled) and `require_contiguous` True→False, making DLPack import succeed for non-contiguous or unaligned tensors by default.
- New free function `IsDirectAddressDevice(DLDevice)` extracted from inline logic inside `IsAligned`; now callable independently.
- New `Tensor::IsAligned(size_t alignment)` member method exposes alignment check to callers without requiring them to call `tvm::ffi::IsAligned` directly.

## Impact

- API: `from_dlpack` keyword arguments renamed `required_alignment` → `require_alignment`, `required_contiguous` → `require_contiguous`; defaults relaxed (alignment 8→0, contiguous True→False). Callers using default kwargs will now silently accept non-contiguous / unaligned tensors.
- Behavioral: Any code that previously relied on the auto-import alignment check (via `__dlpack_auto_import_required_alignment__`) to reject misaligned external tensors will no longer get that rejection unless they explicitly pass `require_alignment=8`.
- Flags/config: Module-level constant `__dlpack_auto_import_required_alignment__ = 8` removed from `tensor.pxi`; the binding in `function.pxi` and `_convert.py` that referenced it is also removed.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- `0007-containers` — `Tensor`/`TensorObj`, `IsContiguous`, `IsAligned`, `FromDLPack`/`FromDLPackVersioned` C++ API; `TVMFFINDArrayFromDLPack` C ABI (alignment/contiguous parameters already named `require_*` at ABI layer).
- `0013-python-package` — `cython/tensor.pxi` `from_dlpack` Python binding, `cython/function.pxi` make_args dispatch, `_convert.py` auto-conversion.

Design elements this commit produces:
- **`IsDirectAddressDevice(DLDevice)`** — new free function in `include/tvm/ffi/container/tensor.h`. Extracted from inline code in `IsAligned`; makes device-type classification independently callable.
- **`Tensor::IsAligned(size_t alignment)`** — new member method; symmetric partner to the existing `Tensor::IsContiguous()`. Together these form the public utility surface for callers that want to validate a tensor after permissive import.
- **Relaxed-default DLPack import convention** — `from_dlpack` and `Tensor::FromDLPack` now import permissively by default; strict validation is opt-in via explicit parameters.

## Usage Examples

Cross-layer end-to-end — import a PyTorch tensor without strict checks, then validate manually:

```python
import tvm_ffi
import torch

# Default import: no alignment or contiguity check
pt = torch.randn(3, 4)  # contiguous, well-aligned — works
t = tvm_ffi.from_dlpack(pt)

# Non-contiguous tensor — previously would fail with default required_contiguous=True
pt_nc = pt.t()  # transposed, non-contiguous
t_nc = tvm_ffi.from_dlpack(pt_nc)   # now succeeds
print(t_nc.IsContiguous())           # False — user is responsible

# Explicit strict mode (restores old behavior)
t_strict = tvm_ffi.from_dlpack(pt_nc, require_contiguous=True)  # raises RuntimeError
```

C++ side — explicit post-import validation:

```cpp
Tensor t = Tensor::FromDLPack(dlm);  // permissive import
if (!t.IsContiguous()) { /* handle strided */ }
if (!t.IsAligned(16)) { /* handle misaligned */ }
```
