# Relax default alignment and contiguous requirement in DLPack import
## TL;DR
- Changes `from_dlpack` defaults from strict (alignment=8, contiguous=True) to permissive (alignment=0, contiguous=False), allowing DLPack import in more settings without requiring callers to opt out.
- Renames parameters `required_alignment` / `required_contiguous` to `require_alignment` / `require_contiguous` across C++ and Python layers.
- Extracts `IsDirectAddressDevice()` helper and adds `Tensor::IsAligned()` member method so callers can check alignment themselves.

## Impact
- API: Breaking keyword-argument rename (`required_alignment` → `require_alignment`, `required_contiguous` → `require_contiguous`). Any caller using these as keyword arguments will get a TypeError. The `__dlpack_auto_import_required_alignment__` module-level variable is removed.
- Behavioral: Auto-import via `convert()` and Cython `make_args` no longer checks alignment or contiguity by default. Tensors that previously failed import (non-contiguous or misaligned) now succeed silently. Callers must explicitly pass `require_alignment=8` to restore the old behavior.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before (strict defaults — old behavior):
```python
# Old API: auto-import always checked alignment=8 and contiguous=True
tensor = tvm_ffi.from_dlpack(torch_tensor)  # could raise on non-contiguous input

# Explicit relaxation required the old parameter names
tensor = tvm_ffi.from_dlpack(arr, required_alignment=0, required_contiguous=False)
```

After (permissive defaults — new behavior):
```python
# New API: auto-import accepts any tensor without alignment/contiguity checks
tensor = tvm_ffi.from_dlpack(torch_tensor)  # always succeeds

# Callers needing strict checks must opt in explicitly
tensor = tvm_ffi.from_dlpack(arr, require_alignment=8, require_contiguous=True)

# New: check alignment yourself on an existing Tensor
if not tensor.IsAligned(64):
    tensor = realign(tensor)
```
