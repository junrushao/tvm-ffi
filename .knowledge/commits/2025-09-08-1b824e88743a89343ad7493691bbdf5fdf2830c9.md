# Relax default alignment and contiguous requirements in DLPack import

## TL;DR
- Relaxes `from_dlpack` defaults from `require_alignment=8, require_contiguous=True` to `require_alignment=0, require_contiguous=False`, making DLPack import accept tensors regardless of alignment or contiguity by default.
- Extracts `IsDirectAddressDevice()` as a standalone reusable utility and adds `Tensor::IsAligned()` member function so users can check alignment themselves.
- Renames Python parameters from `required_alignment`/`required_contiguous` to `require_alignment`/`require_contiguous` and removes the `__dlpack_auto_import_required_alignment__` module constant.

## Impact
- API: Parameter rename `required_alignment` -> `require_alignment`, `required_contiguous` -> `require_contiguous` in `from_dlpack`. Callers using keyword arguments with the old names will get TypeError.
- Behavioral: DLPack import no longer rejects unaligned or non-contiguous tensors by default. Code that previously relied on the implicit alignment=8 check to catch bad tensors will no longer see RuntimeError on import; they must add explicit `require_alignment=8` or call `Tensor::IsAligned()` themselves.
- Flags/config: Removed `__dlpack_auto_import_required_alignment__` constant from `cython/tensor.pxi` (was `8`).
- Data formats/schemas: none

## Usage Examples

Before (strict defaults -- alignment=8 required, contiguous required):
```python
# Old: implicit alignment=8 and contiguous=True enforced on every DLPack import
tensor = tvm_ffi.from_dlpack(torch_tensor)  # raises RuntimeError if unaligned or non-contiguous
```

After (relaxed defaults -- user opts in to checks):
```python
# New: accepts any tensor by default
tensor = tvm_ffi.from_dlpack(torch_tensor)  # never raises for alignment/contiguity

# User can explicitly check alignment:
# C++: tensor.IsAligned(8)
# Or pass keyword args to enforce at import:
tensor = tvm_ffi.from_dlpack(torch_tensor, require_alignment=8, require_contiguous=True)
```
