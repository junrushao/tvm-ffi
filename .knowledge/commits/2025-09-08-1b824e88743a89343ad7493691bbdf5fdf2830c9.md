# Relax default alignment and contiguity requirements in DLPack import
## TL;DR
- Changes `from_dlpack` default parameters from `required_alignment=8, required_contiguous=True` to `require_alignment=0, require_contiguous=False`, removing automatic alignment and contiguity checks on DLPack import.
- Removes the `__dlpack_auto_import_required_alignment__` global variable and all call sites that passed it.
- Extracts `IsDirectAddressDevice()` as a standalone C++ utility function and adds `Tensor::IsAligned()` method so users can perform alignment checks themselves.

## Key Exports

**Functions (C++)**:
- `inline bool IsDirectAddressDevice(const DLDevice& device)` -- checks if a device uses direct address mapping (where pointer address indicates alignment). Returns `true` for `device_type <= kDLCUDAHost`, `kDLCUDAManaged`, `kDLROCM`, `kDLROCMHost`.

**Methods (C++)**:
- `bool Tensor::IsAligned(size_t alignment) const` -- delegates to `tvm::ffi::IsAligned(*get(), alignment)`.

**Functions (Python/Cython)**:
- `from_dlpack(ext_tensor, *, require_alignment=0, require_contiguous=False)` -- keyword parameters renamed from `required_alignment`/`required_contiguous` to `require_alignment`/`require_contiguous`, defaults changed from `8`/`True` to `0`/`False`.

**Removed**:
- `__dlpack_auto_import_required_alignment__` module-level variable in `tensor.pxi` (was `= 8`).

## Impact
- API: **Breaking** for Python callers using `from_dlpack(tensor, required_alignment=8)` or `from_dlpack(tensor, required_contiguous=True)` as keyword arguments -- the parameter names changed to `require_alignment`/`require_contiguous`. Callers relying on the old default behavior (alignment=8, contiguous=True) will silently get relaxed behavior unless they pass the arguments explicitly.
- ABI: none (C API functions `TVMFFITensorFromDLPack`/`TVMFFITensorFromDLPackVersioned` signatures unchanged; the alignment/contiguity integers are just passed differently).
- Behavioral: DLPack tensors imported via `convert()`, `make_arg` (auto-conversion of `__dlpack__` objects and `torch.Tensor`), and explicit `from_dlpack()` calls no longer enforce alignment=8 or contiguity by default. Non-contiguous and unaligned tensors are now accepted without error.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack import pipeline** (`.knowledge/designs/0014-python-bindings.md`): `from_dlpack` in `tensor.pxi`, consumed by `make_arg` in `function.pxi` and `convert()` in `_convert.py`.
- **`IsAligned` / `IsContiguous` free functions** (`include/tvm/ffi/container/tensor.h`): existing C++ utilities for checking tensor data properties.
- **Direct address device detection** (previously inlined in `IsAligned`): logic for distinguishing direct-address devices (CPU, CUDA, ROCm) from indirect-buffer devices.

Design elements this commit produces:
- **`IsDirectAddressDevice(const DLDevice&)`**: New standalone utility function extracted from `IsAligned`, reusable for any device-type-dependent logic. Lives in `include/tvm/ffi/container/tensor.h`.
- **`Tensor::IsAligned(size_t)`**: New member method on the `Tensor` ObjectRef wrapper, enabling users to check alignment after import rather than having the import reject misaligned tensors.
- **Relaxed-import-by-default convention**: The FFI now accepts any DLPack tensor regardless of alignment/contiguity, shifting the responsibility to the user or downstream kernel to verify these properties when needed.

## Usage Examples

**After this commit**: Users who need alignment/contiguity guarantees must check explicitly.

```python
import tvm_ffi

# Import any DLPack tensor without restrictions (new default)
tensor = tvm_ffi.from_dlpack(external_tensor)

# If alignment is needed, either pass explicit requirements:
tensor = tvm_ffi.from_dlpack(external_tensor, require_alignment=8, require_contiguous=True)

# Or check after import using the C++ Tensor methods:
# (In C++)
# Tensor t = ...;
# if (!t.IsContiguous()) { /* handle */ }
# if (!t.IsAligned(64)) { /* handle */ }
```
