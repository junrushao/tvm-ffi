# Relax default alignment and contiguous requirements in DLPack import to accept tensors unconditionally
## TL;DR
- Changes the Python `from_dlpack()` default parameters from `required_alignment=8, required_contiguous=True` to `require_alignment=0, require_contiguous=False`, removing automatic alignment and contiguity checks during DLPack tensor import.
- Removes the module-level `__dlpack_auto_import_required_alignment__` constant (previously `8`) and all call sites that passed it to `from_dlpack`, so auto-conversion paths (`convert()`, `make_args` for `__dlpack__` objects and `torch.Tensor`) now import tensors without any alignment or contiguity restrictions.
- Extracts the direct-address device check into a reusable `IsDirectAddressDevice()` free function and adds `Tensor::IsAligned()` as a member method, enabling callers to opt in to alignment checking after import rather than having it forced at import time.

## Impact
- **API**: Breaking change to Python `from_dlpack()` signature -- the keyword parameters are renamed from `required_alignment`/`required_contiguous` to `require_alignment`/`require_contiguous`, and their defaults are changed from `8`/`True` to `0`/`False`. Any Python code calling `from_dlpack(tensor, required_alignment=N)` will get a `TypeError` at runtime. The C++ `Tensor::FromDLPack` / `Tensor::FromDLPackVersioned` defaults were already `require_alignment=0, require_contiguous=false`, so this change aligns the Python layer with the C++ layer.
- **Flags/config**: The `core.__dlpack_auto_import_required_alignment__` constant is removed. Code that read this attribute will get an `AttributeError`.
- **Data formats/schemas**: None. The underlying DLPack capsule format is unchanged.

## Design Elements
Design elements this commit **consumes**:

- **Container System / Tensor** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The `Tensor` class wraps `NDArrayObj` which holds a `DLTensor`. The `from_dlpack` Cython function calls the C API `TVMFFITensorFromDLPack` / `TVMFFITensorFromDLPackVersioned` with alignment and contiguity parameters that are checked on the C++ side (`ffi::IsAligned`, `ffi::IsContiguous`). This commit changes the Python-layer defaults so those checks are effectively disabled by default.
- **Python Bindings / DLPack import paths** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): Three Python-side DLPack import paths are affected: (1) `from_dlpack()` direct calls, (2) `convert()` in `_convert.py` for `__dlpack__` objects, and (3) `make_args` in `function.pxi` for `torch.Tensor` and `__dlpack__` arguments. All three previously enforced alignment=8 + contiguous checks; all three now pass no requirements.
- **C ABI / `TVMFFITensorFromDLPack`** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The C API parameters `require_alignment` and `require_contiguous` have the semantics "0 means skip check" for alignment and "false means skip check" for contiguity. The C++ `Tensor::FromDLPack` had already adopted these relaxed defaults; only the Python layer was stricter.

Design elements this commit **produces**:

- **`IsDirectAddressDevice()` utility** (`include/tvm/ffi/container/tensor.h`): A new public inline function that encapsulates the logic for determining whether a `DLDevice` uses direct pointer-based addressing (CPU, CUDA, CUDAHost, CUDAManaged, ROCm, ROCmHost) versus indirect buffer handles. Previously inlined in `IsAligned()`, now reusable by any caller that needs to distinguish these device classes.
- **`Tensor::IsAligned(size_t)` member method** (`include/tvm/ffi/container/tensor.h`): A convenience member on the `Tensor` ref class that delegates to the free function `ffi::IsAligned`. Together with `Tensor::IsContiguous()`, this enables a "check after import" pattern where callers import any tensor and then validate alignment/contiguity as needed.
- **Relaxed DLPack import default policy**: The new convention is that `from_dlpack` accepts any DLPack tensor regardless of alignment or memory layout. Callers who need specific guarantees (e.g., kernel code that requires 8-byte alignment) should call `tensor.IsAligned(8)` and `tensor.IsContiguous()` explicitly after import and handle non-conforming tensors themselves.

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0005-containers.md`**: Add a subsection under NDArray/Tensor documenting the `IsDirectAddressDevice()` utility, the `Tensor::IsAligned()` member method, and the DLPack import default policy (no alignment/contiguity enforcement by default). This is useful because future commits modifying DLPack interop will need to understand the policy and the direct-address device classification. The existing doc mentions `IsContiguous` but not `IsAligned` or the device classification logic.

- **Update `.knowledge/designs/0014-python-bindings.md`**: Document the new `from_dlpack()` parameter names (`require_alignment`, `require_contiguous`) and their relaxed defaults (`0`, `False`). Update the argument packing section (Pattern 2 / `make_args`) to note that `torch.Tensor` and `__dlpack__` objects are now imported without alignment or contiguity enforcement. Future commits that reintroduce import-time validation will need to know these defaults.

### ADRs to write

- **`.knowledge/ADRs/0027-relaxed-dlpack-import-defaults.md`**:
  - **Context**: The Python `from_dlpack()` previously enforced `required_alignment=8` and `required_contiguous=True` by default, which caused `RuntimeError` when importing non-contiguous or misaligned tensors from frameworks like PyTorch. The C++ layer already defaulted to no checks. The previous Python defaults were overly conservative for a general-purpose FFI.
  - **Alternatives**: (1) Keep strict defaults and require callers to opt out per call. (2) Relax defaults and provide utility methods for opt-in validation (chosen). (3) Add a global configuration flag.
  - **Trade-offs**: Relaxing defaults improves interop breadth at the cost of removing an early-detection safety net for alignment issues. Kernels that assume alignment must now check explicitly, shifting the validation burden from import time to use time.

### Skill evolution (`/commit-ledger`)

- The parameter rename (`required_alignment` -> `require_alignment`) is a subtle breaking change that is easy to miss when only looking at default-value changes. Step 3.2 (Producers) could benefit from an explicit sub-step: "Check for parameter renames that break keyword-argument callers, even when the function signature otherwise looks similar." This would help catch API-compatibility issues more systematically.

## Self-Evolution of Skill /commit-ledger
The analysis workflow was straightforward for this commit. One minor improvement: when a commit changes both C++ and Python layers of the same feature, Step 1 could explicitly prompt for comparing the pre-commit defaults in both layers to identify alignment gaps (as was the case here -- C++ already had relaxed defaults, Python did not). Adding a sub-question like "Are the C++ and Python defaults aligned before/after this change?" to Step 3 would surface cross-layer inconsistencies faster.
