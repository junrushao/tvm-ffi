# Add clang-tidy CI workflow running on mainline pushes
## TL;DR
- Adds a new GitHub Actions workflow `ci_mainline_only.yml` that runs clang-tidy on every push to `main` (and on manual dispatch).
- Completes the clang-tidy CI integration started in commit `0d8fec88` (which introduced the `.clang-tidy` config and `clang_tidy_precommit.py` runner but did not wire them into CI).
- The workflow reuses existing composite actions (`detect-skip-ci`, `detect-env-vars`) and the existing `tests/lint/clang_tidy_precommit.py` script.

## Key Exports
N/A -- infrastructure

## Impact
- API: none
- Behavioral: clang-tidy violations in `./src/`, `./include/`, and `./tests/` will now cause CI failures on pushes to `main`. This is a post-merge gate (mainline-only), not a pre-merge gate (PR CI).
- Flags/config: New workflow file `.github/workflows/ci_mainline_only.yml` with trigger on `push` to `main` and `workflow_dispatch`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `.github/actions/detect-skip-ci` -- composite action for CI skip logic (shared with `ci_test.yml`)
- `.github/actions/detect-env-vars` -- composite action that exports `cpu_count` for parallelism
- `tests/lint/clang_tidy_precommit.py` -- clang-tidy runner script (introduced in `0d8fec88`); see `.knowledge/commits/2025-10-07-0d8fec88eca5acaeaa7e771003d183c31711574a.md`
- `astral-sh/setup-uv` action pinned to `v6.7.0` (`b75a909f75acd358c2196fb9a5f1299a9a8868a4`)

Design elements this commit produces:
- **Mainline-only workflow pattern** (`ci_mainline_only.yml`): a CI convention where heavier or noisier checks run post-merge on `main` rather than on every PR. This keeps PR CI fast while still catching regressions before the next release.
