# Add clang-tidy CI job on mainline-only workflow for post-merge static analysis

## TL;DR
- Creates a new GitHub Actions workflow `.github/workflows/ci_mainline_only.yml` that runs clang-tidy on every push to `main` (and on manual `workflow_dispatch`).
- The workflow has a `prepare` job (using the shared `detect-skip-ci` action) followed by a `clang-tidy` job that runs `tests/lint/clang_tidy_precommit.py` with `clang-tidy==21.1.1` via `uv run --no-project` on `./src/`, `./include/`, and `./tests/`.
- This closes the gap noted in commit 0d8fec88 ("clang-tidy not yet added to CI") by promoting clang-tidy from a local-only lint to an automated CI check.

## Design Elements
Design elements this commit consumes:

- **Shared CI actions**: `.github/actions/detect-skip-ci` (skip-ci detection) and `.github/actions/detect-env-vars` (CPU count extraction for `--jobs`).
- **`uv run --no-project`** pattern for running tools without requiring a project install (used in the clang-tidy step).

Design elements this commit produces:
- **Mainline-only CI workflow**: A new workflow tier (`ci_mainline_only.yml`) for checks that run only on pushes to `main`, not on PRs. This establishes a pattern for post-merge-only CI jobs that are too slow or noisy for PR gating.
