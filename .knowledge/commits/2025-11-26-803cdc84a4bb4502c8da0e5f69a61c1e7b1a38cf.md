# Document CUDADeviceGuard RAII pattern in kernel library guide
## TL;DR
- Adds a "Device Guard" section to `docs/guides/kernel_library_guide.rst` documenting the `tvm::ffi::CUDADeviceGuard` class.
- The new section explains the RAII pattern: save current device on construction, restore on destruction via `cudaGetDevice`/`cudaSetDevice`.
- Includes a C++ usage example showing the guard with `ffi::TensorView::device().device_id`.

## Key Exports
None -- documentation-only commit. The `CUDADeviceGuard` class already existed in `include/tvm/ffi/extra/cuda/device_guard.h`.

- API: none
- Behavioral: none

## Design Elements
Design elements this commit consumes:
- `tvm::ffi::CUDADeviceGuard` -- RAII device guard struct from `include/tvm/ffi/extra/cuda/device_guard.h`. Saves current CUDA device index on construction, restores on destruction. Skips `cudaSetDevice` if target == original.
- `ffi::TensorView::device()` -- used in the example to obtain the device id from a tensor argument.
- Stream/env context pattern ([0014-stream-and-env-context.md](../designs/0014-stream-and-env-context.md)) -- the device guard complements the stream context by ensuring the correct CUDA device is active when launching kernels.

Design elements this commit produces:
- None -- purely additive documentation.

## Usage Examples
The commit itself provides the canonical usage example (from the new RST section):

```cpp
void func(ffi::TensorView input, ...) {
  // current device index is original device index
  ffi::CUDADeviceGuard device_guard(input.device().device_id);
  // current device index is input device index
  // ... launch kernels here ...
}
// After func returns, device_guard restores the original device index.
```
