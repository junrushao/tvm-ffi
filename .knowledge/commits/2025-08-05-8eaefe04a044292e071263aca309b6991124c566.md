# Add reflection-based JSON graph serialization/deserialization for Any values
## TL;DR
- Introduces `ToJSONGraph` and `FromJSONGraph` functions in the extra API tier that serialize/deserialize arbitrary `ffi::Any` values to/from a JSON object-graph format. The graph format uses a `nodes` array with `root_index`, preserving object identity (shared references) and supporting all FFI primitive types, containers, and reflection-registered objects.
- Adds a new `base64.h` header with `Base64Encode`/`Base64Decode` utilities for serializing `Bytes` values as base64 strings within the JSON graph.
- Supports custom per-type serialization via `__data_to_json__` / `__data_from_json__` type attribute columns, following the same `TypeAttrColumn` pattern used by structural equal/hash (`__s_equal__` / `__s_hash__`).

## Impact
- API: Two new public C++ functions `ToJSONGraph(const Any&, const Any&) -> json::Value` and `FromJSONGraph(const json::Value&) -> Any`, both marked `TVM_FFI_EXTRA_CXX_API`. Two new global functions registered as `ffi.ToJSONGraph` and `ffi.FromJSONGraph`. Two new type attribute columns `__data_to_json__` and `__data_from_json__` created via `EnsureTypeAttrColumn`.
- Flags/config: none (source file added to existing `TVM_FFI_USE_EXTRA_CXX_API` gate in CMakeLists.txt).
- Data formats/schemas: Defines a new JSON object-graph format: `{"root_index": <int>, "nodes": [{"type": "<key>", "data": ...}, ...], "metadata": <object>}`. Primitive fields with statically known types (bool, int, float, DataType) are inlined directly in the object `data`; dynamic-typed fields use node-index references.

- **JSON parser/writer** (`include/tvm/ffi/extra/json.h`): The commit builds directly on the lightweight JSON value types (`json::Value`, `json::Object`, `json::Array`) introduced in a prior commit (`de541e3`).
- **Object system type resolution** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Serialization uses `value.GetTypeKey()` for type-key-based serialization (stable across processes) rather than `type_index` (runtime-dependent). Deserialization uses `TVMFFITypeKeyToIndex` to resolve type keys back to indices.
- **GlobalDef** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): Registers `ffi.ToJSONGraph` and `ffi.FromJSONGraph` via `reflection::GlobalDef().def(...)`.

Design elements this commit **produces**:

- **JSON object-graph serialization format**: A new data format for serializing arbitrary FFI value graphs. Key design decisions:
  - *Node-indexed graph*: All values are assigned monotonically increasing indices in a flat `nodes` array. Shared references serialize to the same index, preserving object identity.
  - *Type-key-based type encoding*: Each node stores `"type": "<type_key>"` rather than `type_index`, ensuring cross-process/cross-build stability.
  - *Static-type optimization for object fields*: When `field_static_type_index` is a known primitive (bool, int, float, DataType, None), the value is inlined directly in the object's `data` JSON object, avoiding a node-index indirection. Dynamic fields use node-index references.
  - *Base64 for Bytes*: Binary data is encoded as base64 strings, keeping the JSON text-safe.
  - *Custom serialization hooks*: `__data_to_json__` / `__data_from_json__` type attributes allow types to override the default reflection-based serialization (demonstrated by `TIntObj` in tests).
- **Base64 encode/decode utilities** (`include/tvm/ffi/extra/base64.h`): Header-only `Base64Encode(TVMFFIByteArray) -> String` and `Base64Decode(TVMFFIByteArray) -> Bytes` with standard base64 encoding (RFC 4648, `+/` alphabet, `=` padding).
- **Testing object adjustments**: `TVarObj` and `TFuncObj` gain default constructors (required by `FromJSONGraph`'s `metadata->creator` call), and `TFuncObj::comment` changes from `String` to `Optional<String>` (allowing null values in serialization round-trips). `TIntObj` gains `__data_to_json__` / `__data_from_json__` custom hooks as an integration test.

## Key Implementations

### ObjectGraphSerializer: Identity-preserving graph serialization

The serializer (`src/ffi/extra/serialization.cc`) maintains a `Map<Any, int64_t> node_index_map_` that maps previously-seen values to their node index. `GetOrCreateNodeIndex(value)` first checks this map; if the value is already mapped, it returns the existing index. This ensures shared subgraphs serialize as a single node referenced multiple times, preserving the DAG structure.

The main dispatch is a switch on `value.type_index()`:
- POD types (None, bool, int, float, DataType, Device): Serialized directly with type key and data.
- String/Bytes: String content or base64-encoded bytes.
- Array/Map: Recursively serialize elements, storing node indices.
- Objects (`type_index >= kTVMFFIStaticObjectBegin`): Check for custom `__data_to_json__` via `TypeAttrColumn`, otherwise use `ForEachFieldInfo` to enumerate fields and serialize each one.

**Invariant**: The `node_index_map_` uses `AnyEqual` for identity, meaning two `int64_t(42)` values map to the same node. This is value-identity, not pointer-identity.

**Extension point**: The `__data_to_json__` type attribute allows types to fully control their JSON representation. The signature is `(const T*) -> json::Object` (or `Map<String, Any>`).

### ObjectGraphDeserializer: Lazy node decoding

The deserializer maintains a `std::vector<Any> decoded_nodes_` and decodes nodes lazily via `GetOrDecodeNode(index)`. This handles:
- Forward references: Nodes can reference other nodes that appear later in the array (demonstrated by the `ShuffleNodeOrder` test).
- Null deduplication: A special `decoded_null_index_` avoids re-decoding null nodes.

For object types, `DecodeObjectData` creates an empty object via `metadata->creator`, then populates fields using `FieldSetter` with the same static-type optimization as serialization. Missing fields with defaults (`kTVMFFIFieldFlagBitMaskHasDefault`) are populated from `field_info->default_value`. Missing required fields throw `TypeError`.

**Extension point**: `__data_from_json__` allows custom deserialization. The signature is `(json::Value) -> T`.

### Static-type optimization for object fields

The serializer and deserializer both branch on `field_info->field_static_type_index` to decide whether to inline a primitive value or use a node-index reference. This creates a more compact and readable JSON representation for objects with many primitive fields, while still supporting arbitrary recursive structures for dynamic-typed fields.

Supported inline types: `kTVMFFINone`, `kTVMFFIBool`, `kTVMFFIInt`, `kTVMFFIFloat`, `kTVMFFIDataType`.

**Invariant**: The serializer and deserializer must agree on exactly which `field_static_type_index` values get inlined. If one side inlines a type but the other expects a node index, deserialization will fail. This invariant is enforced by using identical switch-case arms in both `CreateObjectData` and `decode_field_value`.

This keeps the extra-tier inventory accurate for future commit classification.

### ADRs to write

- **`.knowledge/ADRs/0015-json-graph-serialization-format.md`**: Decision context: The FFI needs a portable, debuggable, text-based serialization format for arbitrary value graphs. Alternatives considered: (1) binary serialization (more compact but not human-readable, harder to debug), (2) flat JSON without graph structure (cannot preserve shared references), (3) per-type serialization functions without a unified framework (combinatorial explosion, no identity preservation). Trade-off: The node-indexed graph format adds a level of indirection but preserves object identity, handles cycles (via memoization), and produces human-readable JSON suitable for debugging and interchange.
