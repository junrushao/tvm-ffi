# Completely remove DLPack stride normalization in torch C extension
## TL;DR
- Removes the stride normalization workaround in `_optional_torch_c_dlpack.py` that created a new view with normalized strides for 1D shape-[1] tensors.
- The `toDLPackImpl` function now passes through the original tensor's sizes and strides directly, since the framework now handles non-contiguous strides natively.

## Key Exports

```python
# In _optional_torch_c_dlpack.py toDLPackImpl<T>
# Removed: view = src.as_strided(shape, {1}, src.storage_offset()) normalization
# Now: directly uses src.sizes().data() and src.strides().data()
# Interacts with: TensorObj::FromDLPack (C++ side handles strides=nullptr case)
```

## Impact
- API: None
- Behavioral: 1D shape-[1] tensors with stride != 1 are no longer silently normalized during DLPack export. The Tensor C++ side (`TensorObjFromDLPack`) already handles missing strides by computing them.
- Flags/config: None
- Data formats/schemas: None
