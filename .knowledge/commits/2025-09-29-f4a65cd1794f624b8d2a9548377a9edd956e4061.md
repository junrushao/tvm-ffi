# Completely remove DLPack stride normalization from toDLPackImpl

## TL;DR
- Removes the remaining stride normalization logic from the `toDLPackImpl` C++ template in `_optional_torch_c_dlpack.py`. The previous commit (53ffe5e) restricted normalization to 1D scalar tensors; this commit eliminates it entirely.
- The `view` local variable, the `need_normalize_strides` check, and the `as_strided` call are all deleted. The function now directly uses `src` (the original tensor) for all DLPack fields -- `handle`, `data`, `shape`, and `strides`.
- Upstream reference: PyTorch gh-83069 workaround is no longer needed after upstream fixes.

## Key Exports

None -- no new public API. The change modifies internal behavior of the `toDLPackImpl<T>` C++ template function embedded in the JIT-compiled torch extension.

```python
# Modified internal function (behavior change only, no signature change):
# template <class T>
# T* toDLPackImpl(const Tensor& src):
#   Before (53ffe5e): normalized strides for 1D tensors with size(0)==1 and stride(0)!=1
#   After (f4a65cd): no stride normalization at all; uses src directly
#   Interacts with: TorchDLPackFromPyObject (caller), DLManagedTensorVersioned (output)
#   Invariant (new): ALL tensors are exported with their original strides, no exceptions
#   Invariant (removed): 1D scalar tensor stride normalization (was from PyTorch gh-83069 workaround)
```

## Impact
- API: None -- no public API changes.
- Behavioral: 1D scalar-like tensors (shape `[1]`, stride `[N]` where N != 1) are now exported via DLPack with their original stride preserved. Previously these were normalized to stride `[1]` via `as_strided`. This aligns with upstream PyTorch behavior after the gh-83069 workaround was removed.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Torch C DLPack JIT extension** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): The inline C++ source compiled via `torch.utils.cpp_extension.load_inline` that provides fast DLPack conversion between torch tensors and TVM FFI tensors. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **DLPack speed converter protocol**: The three-pointer protocol (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) registered on `torch.Tensor` at import time. `toDLPackImpl` is the core of the export path called via `TorchDLPackFromPyObject`. See [0014-stream-and-env-context.md](../designs/0014-stream-and-env-context.md).

Design elements this commit produces:
- None -- this is a bugfix removing a workaround, not a new design element.

## Usage Examples

Before (53ffe5e behavior -- normalization for 1D scalar tensors):
```python
import torch
t = torch.tensor([42.0]).as_strided([1], [5])  # shape [1], stride [5]
# Old: toDLPackImpl detected dim==1, size(0)==1, stride(0)!=1
# -> called as_strided(shape, {1}, offset) -> DLPack consumer sees stride [1]
```

After (f4a65cd -- no normalization):
```python
import torch
t = torch.tensor([42.0]).as_strided([1], [5])  # shape [1], stride [5]
# New: toDLPackImpl uses src directly
# -> DLPack consumer sees stride [5], matching the original tensor layout
```
