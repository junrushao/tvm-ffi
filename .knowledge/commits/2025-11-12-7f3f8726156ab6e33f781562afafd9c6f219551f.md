# Leverage DLPackExchangeAPI in from_dlpack consumer path
## TL;DR
- Adds `_from_dlpack_exchange_api()` in `tensor.pxi`, enabling `from_dlpack()` to consume tensors via the `DLPackExchangeAPI` struct fast-path (bypassing `__dlpack__` PyCapsule protocol).
- Inserts `__c_dlpack_exchange_api__` as the highest-priority detection in `_from_dlpack_universal()`, ahead of `__dlpack__` and raw PyCapsule paths.
- Fixes a memory leak in both `_from_dlpack_exchange_api()` and `TVMFFIPyArgSetterDLPackExchangeAPI_`: when `TVMFFITensorFromDLPackVersioned` fails, the managed tensor's deleter is now called to recycle the allocation.
- Adds missing `return` statements to all `_from_dlpack*` calls within `_from_dlpack_universal()`, fixing silent fall-through to the error branch.
- Removes dead code `_from_dlpack_intptr()`.

## Impact
- API: none -- `from_dlpack()` public Python signature unchanged; new path is an internal optimization
- Behavioral: frameworks exposing `__c_dlpack_exchange_api__` (e.g., torch with the C DLPack extension) now get the fast-path in `from_dlpack()`, not just in packed function argument conversion. Fallback to `__dlpack__` on `BufferError`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPackExchangeAPI struct** ([ADR-0015](../ADRs/0015-dlpack-exchange-api-struct.md)): the unified struct with `managed_tensor_from_py_object_no_sync` function pointer, previously only consumed in the argument-setter path (`TVMFFIPyArgSetterDLPackExchangeAPI_`), now also consumed in the `from_dlpack` consumer path.
- **DLPack fast-path protocols** ([0012-python-bindings](../designs/0012-python-bindings.md), line 37): the `__c_dlpack_exchange_api__` class-level attribute detection pattern.
- **`TVMFFITensorFromDLPackVersioned`** (C ABI): converts `DLManagedTensorVersioned*` to `TVMFFIObjectHandle`.

Design elements this commit produces:
- **`_from_dlpack_exchange_api()`**: new Cython function bridging the exchange API struct into the `from_dlpack` consumer path. Completes the dual-direction integration of ADR-0015 (producer side was argument setter, consumer side is now `from_dlpack`).
- **Managed tensor leak-safety invariant**: both `_from_dlpack_exchange_api` and `TVMFFIPyArgSetterDLPackExchangeAPI_` now enforce that on conversion failure, the managed tensor deleter is called. This was previously missing.

## Usage Examples
Before this commit, `from_dlpack(torch_tensor)` always went through `__dlpack__()` -> PyCapsule -> `_from_dlpack()`. After:

```python
import torch
import tvm_ffi

# If torch exposes __c_dlpack_exchange_api__ (via _optional_torch_c_dlpack.py),
# from_dlpack now uses the C struct fast-path automatically:
t = torch.randn(4, 4, device="cuda")
x = tvm_ffi.from_dlpack(t)  # uses _from_dlpack_exchange_api() internally
# Falls back to __dlpack__() path on BufferError
```

Bugfix -- before/after pattern for the leak:
```python
# BEFORE: if TVMFFITensorFromDLPackVersioned fails, temp_managed_tensor leaks
# (deleter never called)

# AFTER: failure path calls deleter to recycle
if TVMFFITensorFromDLPackVersioned(temp_managed_tensor, ..., out) != 0:
    if temp_managed_tensor.deleter != NULL:
        temp_managed_tensor.deleter(temp_managed_tensor)  # prevents leak
    raise BufferError(...)
```
