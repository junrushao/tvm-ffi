# Update from_dlpack to prefer DLPackExchangeAPI when available for tensor conversion

## TL;DR
- `cython/tensor.pxi` `from_dlpack` implementation now checks for `__c_dlpack_exchange_api__` first and uses the `DLPackExchangeAPI` path when available, falling back to the legacy `__dlpack__` protocol.
- `cython/function.pxi` dispatch updated consistently.
- Aligns with the `DLPackExchangeAPI` design introduced in 0016-py-ffi-call-dispatch.

## Key Exports

```python
# python/tvm_ffi/cython/tensor.pxi (updated)
def from_dlpack(src: Any) -> Tensor:
    """Convert any DLPack-compatible object to tvm_ffi.Tensor.
    # Before: used __dlpack__() protocol directly
    # After: prefers __c_dlpack_exchange_api__ if present (zero-copy DLPackExchangeAPI path)
    # Falls back to __dlpack__() for objects without exchange API
    # Interacts with: DLPackExchangeAPI struct, TVMFFIPyCallManager setter cache
    # Invariant: exchange API path is faster (no Python object creation); used when torch is patched
    """
    ...
```

## Impact
- API: `from_dlpack` behavior change: prefers exchange API path over legacy `__dlpack__`.
- Behavioral: For torch tensors with patched `__c_dlpack_exchange_api__`, conversion is now faster (uses exchange API path).
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

```python
import tvm_ffi
import torch

# If torch has __c_dlpack_exchange_api__ (patched by torch_c_dlpack_addon):

# If not patched: falls back to __dlpack__() protocol
```
