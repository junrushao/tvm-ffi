# Fix ROCm DLPack current_work_stream and force addon override on HIP

## TL;DR
- `CurrentWorkStream` in the Torch DLPack C extension now uses `c10::hip::getCurrentHIPStreamMasqueradingAsCUDA` on ROCm (not the CUDA path) to return the correct HIP stream.
- On ROCm, even when PyTorch exposes `__dlpack_c_exchange_api__`, the tvm-ffi addon capsule is force-loaded so the corrected stream callback is active.
- Fixes graph-capture stream mismatches seen by SGLang JIT kernels on HIP.

## Key Exports

```python
# What invariant was violated before the fix:
# CurrentWorkStream on ROCm fell through to the CUDA path:
#   at::cuda::getCurrentCUDAStream(device_id).stream()
# — returns the CUDA masquerade stream, not the real HIP stream.

# What invariant is restored after the fix:
# On ROCm, CurrentWorkStream uses:
#   c10::hip::getCurrentHIPStreamMasqueradingAsCUDA(device_id).stream()
# — correct HIP stream returned; kDLCUDA and kDLROCM both handled.

# _optional_torch_c_dlpack.py: force-override logic
# prefer_rocm_override = torch.cuda.is_available() and torch.version.hip is not None
# When True: skip early-return even if __dlpack_c_exchange_api__ already set.
# Interacts with: TorchDLPackExchangeAPI::CurrentWorkStream in C extension
```

## Impact
- API: none (same `CurrentWorkStream` signature)
- Behavioral: On ROCm, `torch.Tensor.__dlpack_c_exchange_api__.current_work_stream()` now returns the HIP stream matching PyTorch's stream pool, fixing HIP graph capture.
- Flags/config: `BUILD_WITH_ROCM` preprocessor flag gates the new code path.
- Data formats/schemas: none

## Usage Examples

```python
# Before fix (ROCm): stream mismatch
stream = torch.Tensor.__dlpack_c_exchange_api__.current_work_stream(device)
# stream != torch.hip.current_stream()  <-- BUG

# After fix (ROCm): stream identity restored
with torch.hip.stream(custom_stream):
    stream = torch.Tensor.__dlpack_c_exchange_api__.current_work_stream(device)
    assert stream == custom_stream.hip_stream  # passes
```
