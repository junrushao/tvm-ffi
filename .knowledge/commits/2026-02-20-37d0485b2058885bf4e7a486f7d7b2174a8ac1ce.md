# Fix ROCm DLPack current_work_stream and force addon override for Torch exchange API

## TL;DR
- Fixes `CurrentWorkStream` in the Torch DLPack C exchange addon to use `HIPStreamMasqueradingAsCUDA` on ROCm builds, returning the correct HIP stream that aligns with PyTorch's internal stream handling.
- Forces loading of the tvm-ffi addon capsule on ROCm even when `torch.Tensor` already has `__dlpack_c_exchange_api__`, ensuring the fixed callback is active.
- Prevents HIP graph empty-capture warnings and stream mismatch issues for downstream callers like SGLang JIT kernels.

## Key Exports

**Behavioral change in `CurrentWorkStream`** (`_build_optional_torch_c_dlpack.py`):
```cpp
// Before (ROCm): at::cuda::getCurrentCUDAStream(device_id).stream()
// After  (ROCm): c10::hip::getCurrentHIPStreamMasqueradingAsCUDA(device_id).stream()
```
New include: `ATen/hip/impl/HIPStreamMasqueradingAsCUDA.h` under `BUILD_WITH_ROCM`.

**Python loading logic change** (`_optional_torch_c_dlpack.py`):
- `prefer_rocm_override = bool(torch.cuda.is_available() and torch.version.hip is not None)`
- When `prefer_rocm_override` is true, skips early return even if `__dlpack_c_exchange_api__` already exists on `torch.Tensor`, forcing the addon to load.

## Impact
- API: none
- Behavioral: ROCm builds now return the correct HIP stream from `CurrentWorkStream`. CUDA path unchanged.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces:

**Invariant violated before fix**: `CurrentWorkStream` on ROCm called `at::cuda::getCurrentCUDAStream`, which returns a CUDA-semantic stream handle instead of the HIP-masquerading-as-CUDA stream that PyTorch internally uses. This caused stream mismatch in HIP graph capture.

**Invariant restored**: `CurrentWorkStream` on ROCm returns the same stream object that PyTorch's HIP runtime uses internally (`HIPStreamMasqueradingAsCUDA`), ensuring stream identity consistency.
