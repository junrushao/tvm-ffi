## Design Elements
Design elements this commit consumes:
- **Global function registry** ([0004-function-system.md](../designs/0004-function-system.md)): The documented pattern registers compiler-specific state accessors as global `tvm::ffi::Function`s (via `TVM_FFI_STATIC_INIT_BLOCK` and `refl.GlobalDef().def(...)`).
- **Module system** ([0011-module-system.md](../designs/0011-module-system.md)): The guide references `GetGlobalRequired()` and `TVMFFIGetGlobalFunction()` for kernel-side state access.
- **C ABI environment functions**: References `TVMFFIEnvGetStream` as an example of common state managed by TVM FFI itself.
- **Reflection system** ([0008-reflection.md](../designs/0008-reflection.md)): The code example uses `tvm::ffi::reflection` and `refl.GlobalDef().def(...)` to register a global function.

Design elements this commit produces:
- **Documented pattern: compiler runtime state via singleton + global function registration**. This is a new documentation artifact describing the recommended architecture for DSL compilers that need their own runtime state alongside TVM FFI kernel modules. Not a code artifact, but a codified design pattern.

## Usage Examples
The commit itself contains the canonical usage example in the new documentation section. Summarized:

```cpp
// 1. Define singleton state
class GlobalState {
  // ... state variables
 public:
  static GlobalState* Global() {
    static auto* inst = new GlobalState();
    return inst;
  }
};

// 2. Register accessor as global function
TVM_FFI_STATIC_INIT_BLOCK() {
  using refl = tvm::ffi::reflection;
  refl.GlobalDef().def("mylang.get_global_state",
    []() -> void* { return GlobalState::Global(); });
}

// 3. From kernels: retrieve state
auto f = GetGlobalRequired("mylang.get_global_state");
void* state = f();
```
