# Add runtime and state management section to compiler integration guide

## TL;DR
- Adds a new "Runtime and State Management for Compilers" section to `docs/guides/compiler_integration.md`, documenting the recommended pattern for DSL compilers that need their own runtime state (singleton global state, global function registration via `TVM_FFI_STATIC_INIT_BLOCK`, and kernel-side state retrieval via `GetGlobalRequired`).
- Adds `docs/_static/custom.css` with a fix for an unnecessary scrollbar in the Sphinx Book Theme sidebar, and wires it into `docs/conf.py` via `html_static_path` and `html_css_files`.
- Adds `css` to the allowed file extensions in `tests/lint/check_file_type.py`.

## Key Exports
None -- this is a documentation and build-configuration-only change. No new C/C++/Python API surface.

## Impact
- API: none
- ABI: none
- Behavioral: none
- Flags/config: `docs/conf.py` now sets `html_static_path = ['_static']` and `html_css_files = ['custom.css']`, enabling custom CSS in the Sphinx documentation build.
- Data formats/schemas: none
- Lint: `css` is now an allowed file extension in `check_file_type.py`, preventing lint failures for `.css` files in the tree.

## Design Elements
Design elements this commit consumes:
- **Global function registry** (`Function::SetGlobal`/`GetGlobalRequired`, `TVMFFIFunctionGetGlobal`): The new documentation section describes using the global function registry as the recommended mechanism for compiler runtimes to expose state accessors.
- **`TVM_FFI_STATIC_INIT_BLOCK` macro**: Referenced in the code example as the recommended way to register runtime functions at shared-library load time. See `.knowledge/designs/function-system.md`.
- **Module system**: The guide sits alongside the existing compiler integration docs that describe `__tvm_ffi_<name>` symbol convention, `load_module`, and `ModuleObj`. See `.knowledge/designs/0013-module-system.md`.
- **`TVMFFIEnvGetStream`**: Referenced as an example of common state managed by TVM FFI itself (as opposed to compiler-specific state).

Design elements this commit produces:
- **Compiler runtime state management pattern**: A documented three-step pattern for DSL compilers: (1) define a singleton `GlobalState` class, (2) register a global function returning a pointer to it via `TVM_FFI_STATIC_INIT_BLOCK`, (3) retrieve the state from kernels via `GetGlobalRequired` (C++) or `TVMFFIGetGlobalFunction` (C). The runtime shared library should be distributed as a Python/C++ package that users import before loading compiled kernels.
- **Common vs. custom state distinction**: Documents the boundary between state managed by TVM FFI (streams, memory allocators via `TVMFFIEnvGetStream` etc.) and state that compiler runtimes should manage themselves via the global function registry.

## Usage Examples
The commit adds this C++ snippet as the recommended runtime state registration pattern:

```cpp
class GlobalState {
  ... // your state variables here
 public:
   GlobalState* Global() {
      static auto *inst = new GlobalState();
      return inst;
   }
};
TVM_FFI_STATIC_INIT_BLOCK() {
  using refl = tvm::ffi::reflection;
  refl.GlobalDef().def("mylang.get_global_state", []()-> void*{ return GlobalState::Global()});
  // other runtime APIs can be registered here
}
```

Kernels retrieve the state via:
```cpp
GetGlobalRequired("mylang.get_global_state")
```
or via the C API:
```c
TVMFFIGetGlobalFunction("mylang.get_global_state", ...)
```
