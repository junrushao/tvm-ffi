# Introduce reflection::init<> helper for simplified __init__ registration
## TL;DR
- Adds `tvm::ffi::reflection::init<T, Args...>`, a function template that constructs an object of type `T` (or its `ContainerType`) via `make_object` and returns it as `ObjectRef`, designed to simplify `__init__` method registration in reflection.
- Migrates the `TestIntPairObj` example from a hand-written `__create__` lambda to `refl::init<TestIntPairObj, int64_t, int64_t>`, establishing `__ffi_init__` as the new conventional name for reflection-registered constructors.
- Adds `[[maybe_unused]]` to `_type_is_nullable` in the two `ObjectRef` method macros, suppressing compiler warnings when the field is unused.

## Key Exports

**Function template**: `tvm::ffi::reflection::init<T, Args...>`
```cpp
template <typename T, typename... Args>
inline ObjectRef init(Args&&... args);
```
- If `T` derives from `Object`, calls `make_object<T>(std::forward<Args>(args)...)` and wraps in `ObjectRef`.
- If `T` derives from `ObjectRef` (i.e., a ref type), extracts `T::ContainerType` and calls `make_object<ContainerType>(...)`.
- Declared in `include/tvm/ffi/reflection/registry.h`.

**Convention**: `__ffi_init__` replaces `__create__` as the method name for reflection-registered constructors. Registered via `def_static("__ffi_init__", refl::init<ObjType, ArgTypes...>)`.

## Impact
- API: Low. Introduces a new convenience function. The `__create__` -> `__ffi_init__` rename on `TestIntPairObj` changes the Python-visible method name from `TestIntPair.__create__` to `TestIntPair.__ffi_init__`, but `TestIntPair` is a testing-only class.
- ABI: None.
- Behavioral: None. The `[[maybe_unused]]` annotation on `_type_is_nullable` is a warning suppression with no semantic effect.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/reflection.md`): Uses `ObjectDef<T>::def_static()` to register the init function as a static method on a type. Uses `reflection::GetMethod` in tests.
- **Object system** (`.knowledge/designs/object-system.md`): Uses `make_object<T>()` for object allocation, `ObjectRef` as the return wrapper, and the dual-class pattern (`FooObj` + `Foo`).
- **`__init_handle_by_constructor__`** (Python Cython binding): Python `TestIntPair.__init__` calls `self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)`.

Design elements this commit produces:
- **`reflection::init<T, Args...>` helper**: A new convenience function template in the reflection namespace that eliminates boilerplate lambdas for constructor registration. Supports both `Object`-derived and `ObjectRef`-derived type parameters via `if constexpr`.
- **`__ffi_init__` naming convention**: Establishes `"__ffi_init__"` as the canonical method name for reflection-registered constructors, replacing the ad-hoc `"__create__"` pattern.

## Usage Examples

**Registering a constructor with `reflection::init`** (C++ side):
```cpp
class MyObj : public Object {
 public:
  int64_t x;
  int32_t y;
  MyObj(int64_t x, int32_t y) : x(x), y(y) {}
  TVM_FFI_DECLARE_OBJECT_INFO("my.MyObj", MyObj, Object);
};

TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<MyObj>()
      .def_static("__ffi_init__", refl::init<MyObj, int64_t, int32_t>)
      .def_ro("x", &MyObj::x)
      .def_ro("y", &MyObj::y);
}
```

**Consuming from Python**:
```python
@register_object("my.MyObj")
class MyObj(Object):
    def __init__(self, x: int, y: int) -> None:
        self.__init_handle_by_constructor__(MyObj.__ffi_init__, x, y)
```

**Using `ObjectRef`-derived type parameter** (derives `ContainerType` automatically):
```cpp
refl::ObjectDef<DerivedObj>()
    .def_static("__ffi_init__", refl::init<DerivedRef, int64_t, int64_t, int64_t>);
```
