# Add `reflection::init<T, Args...>` helper for registering `__ffi_init__` constructors

## TL;DR
- Introduces `tvm::ffi::reflection::init<T, Args...>`, a function template that wraps `make_object<T>` and returns `ObjectRef`, designed as a drop-in for `def_static("__ffi_init__", ...)` registrations.
- Replaces the ad-hoc lambda pattern (previously `def_static("__create__", [](args) -> Ref { ... })`) with a standardized one-liner.
- Adds `[[maybe_unused]]` to `_type_is_nullable` in the `TVM_FFI_DEFINE_OBJECT_REF_METHODS_*` macros to suppress compiler warnings.

## Key Exports

```python
# --- New: reflection::init<T, Args...> function template ---
# Location: include/tvm/ffi/reflection/registry.h

def init(*args: Args) -> ObjectRef:
    """Construct an Object of type T and return it as ObjectRef.

    T may be either an Object subclass (direct construction) or an
    ObjectRef subclass (extracts ContainerType and constructs that).
    """
    # if T derives from Object:
    #   return ObjectRef(make_object<T>(*args))
    # else (T is an ObjectRef subclass):
    #   U = T.ContainerType
    #   return ObjectRef(make_object<U>(*args))
    # Interacts with: ffi::make_object<T>, ObjectDef.def_static()
    # Invariant: T must have a constructor accepting Args...
    # Extension: use with def_static("__ffi_init__", init<MyObj, arg_types...>)
    ...

# --- Naming convention change ---
# Old: def_static("__create__", lambda_returning_Ref)
# New: def_static("__ffi_init__", refl::init<ObjType, arg_types...>)
```

## Impact
- API: The `__create__` static method on `testing.TestIntPair` is renamed to `__ffi_init__`. Python `TestIntPair.__init__` now calls `__ffi_init__` instead of `__create__`. This is an internal testing type, so external impact is minimal.
- Behavioral: none -- the runtime construction behavior is identical.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **ObjectDef<T>.def_static()** -- used to register the `__ffi_init__` static method ([0007-ffi-reflection](../design-records/0007-ffi-reflection.md))
- **make_object<T>()** -- underlying allocation used by `init<T>` ([0003-ffi-object-system](../design-records/0003-ffi-object-system.md))
- **TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE** -- macro modified with `[[maybe_unused]]` ([0008-ffi-object-macros](../design-records/0008-ffi-object-macros.md))
- **__init_handle_by_constructor__** -- Python-side pattern for calling FFI init methods ([0012-ffi-python-package](../design-records/0012-ffi-python-package.md))

Design elements this commit produces:
- **reflection::init<T, Args...>** -- new function template providing a standardized way to register constructors via `def_static("__ffi_init__", refl::init<T, ...>)`. This establishes a naming convention (`__ffi_init__`) and eliminates ad-hoc lambda boilerplate.
- **`__ffi_init__` naming convention** -- replaces the previous `__create__` method name for reflection-registered constructors, aligning with the `__ffi_*` dunder prefix pattern.

## Usage Examples

C++ registration side:
```cpp
// Define an object with a constructor
class MyObj : public Object {
 public:
  int64_t x;
  int64_t y;
  MyObj(int64_t x, int64_t y) : x(x), y(y) {}
  TVM_FFI_DECLARE_OBJECT_INFO("my.MyObj", MyObj, Object);
};

// Register with refl::init instead of a lambda
TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<MyObj>()
      .def_static("__ffi_init__", refl::init<MyObj, int64_t, int64_t>)
      .def_ro("x", &MyObj::x)
      .def_ro("y", &MyObj::y);
}
```

Python consumption side:
```python
@register_object("my.MyObj")
class MyObj(Object):
    def __init__(self, x: int, y: int) -> None:
        self.__init_handle_by_constructor__(MyObj.__ffi_init__, x, y)
```

Also works when `T` is an ObjectRef subclass (extracts `ContainerType` automatically):
```cpp
// T = TestObjRefADerived (an ObjectRef), internally uses TestObjADerived (ContainerType)
refl::ObjectDef<TestObjADerived>()
    .def_static("__ffi_init__", refl::init<TestObjRefADerived, int64_t, int64_t, int64_t>);
```
