# Introduce `tvm_ffi::reflection::init<>` helper for simplified `__init__` registration

## TL;DR
- Adds `tvm_ffi::reflection::init<T, Args...>` function template in `reflection/registry.h` that wraps `make_object<T>` and returns `ObjectRef`, eliminating boilerplate lambdas when registering `__init__` methods via `ObjectDef::def_static`.
- Renames the testing `__create__` static method to `__ffi_init__`, establishing a naming convention for FFI init methods.
- Adds `[[maybe_unused]]` to `_type_is_nullable` in `TVM_FFI_DEFINE_OBJECT_REF_METHODS` macros to suppress compiler warnings.

## Key Exports

```python
# New function template in tvm::ffi::reflection (registry.h)
def init(*args: Args) -> ObjectRef:
    """Construct an object of type T and return as ObjectRef.
    Works with both Object subclasses (direct) and ObjectRef subclasses
    (extracts ContainerType automatically).
    """
    # Interacts with: make_object<T>(), ObjectRef constructor
    # Invariant: T must be Object subclass OR ObjectRef subclass with ContainerType typedef
    # Extension: use with ObjectDef.def_static("__ffi_init__", refl::init<T, Arg1, Arg2, ...>)
    ...

# Python-side usage pattern (testing.py)
class TestIntPair(Object):
    """Test Int Pair."""
    def __init__(self, a: int, b: int) -> None:
        self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)
    # Interacts with: C++ refl::init<TestIntPairObj, int64_t, int64_t> via __ffi_init__
```

## Impact
- API: Additive only. New `refl::init<T, Args...>` helper. No existing API changed.
- Behavioral: `TestIntPair.__create__` renamed to `TestIntPair.__ffi_init__` in testing module; this is an internal testing API, not public.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection ObjectDef builder** (0008-reflection): Uses `ObjectDef::def_static` to register the init function as a type method.
- **Object system make_object** (0002-object-system): `refl::init` delegates to `ffi::make_object<T>()` for actual construction.
- **ObjectRef wrapper pattern** (0002-object-system): Returns `ObjectRef` wrapping the newly created object.
- **Python `__init_handle_by_constructor__`** (0012-python-bindings): Python side uses this pattern to call the registered `__ffi_init__` method.

Design elements this commit produces:
- **`reflection::init<T, Args...>` helper**: New convenience function template that eliminates lambda boilerplate for `__init__` registration. Handles both `Object` and `ObjectRef` template arguments via `if constexpr`.
- **`__ffi_init__` naming convention**: Establishes `__ffi_init__` as the standard method name for FFI constructor registration (replaces ad-hoc `__create__`).

## Usage Examples

**C++ registration (end-to-end from C++ to Python)**:
```cpp
// C++ side: register init via refl::init (no lambda needed)
TVM_FFI_STATIC_INIT_BLOCK() {
  namespace refl = tvm::ffi::reflection;
  refl::ObjectDef<TestIntPairObj>()
      .def_ro("a", &TestIntPairObj::a)
      .def_ro("b", &TestIntPairObj::b)
      .def_static("__ffi_init__", refl::init<TestIntPairObj, int64_t, int64_t>);
}
```
```python
# Python side: use __ffi_init__ to construct
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    def __init__(self, a: int, b: int) -> None:
        self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)

obj = TestIntPair(1, 2)
assert obj.a == 1 and obj.b == 2
```

**ObjectRef argument support** (from C++ test):
```cpp
// refl::init also accepts ObjectRef subclasses -- extracts ContainerType automatically
struct TestObjRefADerived : public ObjectRef {
  TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE(TestObjRefADerived, ObjectRef, TestObjADerived);
};
refl::ObjectDef<TestObjADerived>()
    .def_static("__ffi_init__", refl::init<TestObjRefADerived, int64_t, int64_t, int64_t>)
    .def_ro("z", &TestObjADerived::z);
```
