# Introduce tvm_ffi::reflection::init<> for simplified __init__ registration
## TL;DR
- Adds `tvm_ffi::reflection::init<T, Args...>` template function in `include/tvm/ffi/reflection/registry.h` that wraps `make_object<T>(args...)` and returns an `ObjectRef`, simplifying `__init__` method registration in reflection.
- Supports both `Object`-derived types and `ObjectRef`-derived types (via `ContainerType` alias).
- Adds `[[maybe_unused]]` to `_type_is_nullable` in `TVM_FFI_DEFINE_OBJECT_REF_METHODS` / `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` to suppress compiler warnings.

## Impact
- API: New public template `tvm_ffi::reflection::init<T, Args...>` for reflection-based `__init__` registration. Usage: `refl::ObjectDef<T>().def_static("__init__", refl::init<T, int64_t, int32_t>)`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection** (`.knowledge/designs/0006-reflection.md`): `ObjectDef<T>.def_static("__init__", ...)` pattern for registering constructors.
- **Object System** (`.knowledge/designs/0003-object-system.md`): `make_object<T>` factory, `ObjectRef` wrapper, `ContainerType` alias.

Design elements this commit produces:
- **`reflection::init<T, Args...>`**: A convenience factory function that bridges the gap between C++ constructors and the FFI reflection system. It handles both `Object` and `ObjectRef` template parameter styles, making `__init__` registration a one-liner instead of requiring a lambda.
