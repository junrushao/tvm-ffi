# Introduce reflection::init<T, Args...> for simplified __ffi_init__ registration
## TL;DR
- Adds `tvm::ffi::reflection::init<T, Args...>`, a function template that constructs an object of type `T` (or `T::ContainerType` for ObjectRef types) and returns it as `ObjectRef`. Replaces hand-written lambdas for `__init__`/`__create__` registration.
- Establishes `__ffi_init__` as the conventional method name for object constructors registered via reflection (replacing the previous ad-hoc `__create__` name).
- Adds a Python `TestIntPair` class demonstrating the cross-layer pattern: C++ `def_static("__ffi_init__", refl::init<...>)` + Python `__init_handle_by_constructor__(cls.__ffi_init__, ...)`.

## Key Exports

**Functions**:
```cpp
// include/tvm/ffi/reflection/registry.h
namespace tvm::ffi::reflection {
template <typename T, typename... Args>
inline ObjectRef init(Args&&... args);
// If T derives from Object: calls make_object<T>(forward<Args>(args)...)
// If T derives from ObjectRef: extracts T::ContainerType, calls make_object<U>(forward<Args>(args)...)
// Returns ObjectRef wrapping the new object.
}
```

**Conventions**: `__ffi_init__` replaces `__create__` as the standard method name for constructor registration via `ObjectDef<T>::def_static`.

## Impact
- API: New public function template `reflection::init<T, Args...>` in `reflection/registry.h`. Non-breaking addition. The `__create__` to `__ffi_init__` rename in `TestIntPairObj` is internal to the testing module.
- Behavioral: `[[maybe_unused]]` added to `_type_is_nullable` in `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE` and `_NOTNULLABLE` macros -- suppresses compiler warnings, no semantic change.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system** (`0003-object-system.md`): `make_object<T>(args...)`, `ObjectRef` constructor from `ObjectPtr`, `Object` base class, `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE` macro.
- **Reflection system** (`0009-reflection.md`): `ObjectDef<T>::def_static`, `reflection::GetMethod`, `TVM_FFI_STATIC_INIT_BLOCK`.
- **Python FFI dispatch** (`0014-python-package.md`, `0015-python-ffi-call-dispatch.md`): `__init_handle_by_constructor__`, static method reflection via `registry.py` (`setattr(type_cls, name, staticmethod(method_func))`).

Design elements this commit produces:
- **`reflection::init<T, Args...>`**: A convenience factory template for registering constructors. Eliminates boilerplate lambda wrapping of `make_object` calls. Supports both `Object`-derived and `ObjectRef`-derived template parameters.
- **`__ffi_init__` convention**: Standardized method name for reflection-registered constructors, consumed by Python via `cls.__ffi_init__`.

## Usage Examples

**C++ registration + Python consumption (cross-layer)**:
```cpp
// C++ (src/ffi/extra/testing.cc)
namespace refl = tvm::ffi::reflection;

TVM_FFI_STATIC_INIT_BLOCK() {
  refl::ObjectDef<TestIntPairObj>()
      .def_ro("a", &TestIntPairObj::a)
      .def_ro("b", &TestIntPairObj::b)
      .def_static("__ffi_init__", refl::init<TestIntPairObj, int64_t, int64_t>);
}
```
```python
# Python (python/tvm_ffi/testing.py)
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    def __init__(self, a: int, b: int) -> None:
        self.__init_handle_by_constructor__(TestIntPair.__ffi_init__, a, b)
```

**C++ direct invocation via reflection**:
```cpp
Function int_init = reflection::GetMethod("test.TestObjA", "__ffi_init__");
Any obj = int_init(1, 2);
assert(obj.as<TestObjA>()->x == 1);
```

**ObjectRef-derived template parameter** (uses `T::ContainerType` internally):
```cpp
// init<TestObjRefADerived, ...> extracts TestObjADerived via ContainerType
refl::ObjectDef<TestObjADerived>()
    .def_static("__ffi_init__", refl::init<TestObjRefADerived, int64_t, int64_t, int64_t>);
```
