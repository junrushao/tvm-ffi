# Revert Function.__init__ constructor to unbreak downstream callers

## TL;DR
- Reverts PR #395 (commit 8786670) which added `tvm_ffi.Function.__init__` allowing direct construction from a Python callable.
- The feature broke a downstream use case (specifics not detailed in the message); reverted to restore prior behavior pending redesign.
- Collateral: restores original Doxygen `\cond`/`\endcond` marker positions in `base_details.h` and reverts `TVM_FFI_STATIC_INIT_BLOCK` doc comment that was added in #395.

## Key Exports

The following API surface is **removed** by this revert:

```python
# REMOVED by this revert (was added in 8786670):
# class Function(Object):
#     def __init__(self, func: Callable[..., Any]) -> None: ...
#     # Interacts with: _convert_to_ffi_func_handle (Cython internal)
#     # Interacts with: TVMFFIObjectIncRef (C ABI) for Function-to-Function copy

# REMOVED test:
# test_pyfunc_init() — verified Function(callable) round-trip
```

After this revert, `Function` construction from Python remains available only through:
- `tvm_ffi.convert_to_ffi_func(callable)` (implicit conversion)
- `Function.__from_extern_c__(c_symbol)` (from C symbol)
- `Function.__from_mlir_packed_safe_call__(mlir_symbol)` (from MLIR JIT)

## Impact
- API: `tvm_ffi.Function(callable)` no longer works; callers must use `convert_to_ffi_func` or other existing construction paths.
- Behavioral: none beyond the removed constructor.
- Flags/config: none.
- Data formats/schemas: none.

## Usage Examples

Before revert (broken downstream):
```python
# This worked after PR #395 but broke downstream:
fadd = tvm_ffi.Function(lambda a, b: a + b)
fadd(1, 2)  # -> 3
```

After revert (use existing paths):
```python
# Use implicit conversion through the FFI bridge:
@tvm_ffi.register_global_func("my.add")
def add(a, b):
    return a + b

fadd = tvm_ffi.get_global_func("my.add")
fadd(1, 2)  # -> 3
```
