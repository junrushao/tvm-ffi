# Hide StringObj/BytesObj into details namespace to decouple public API from internal Obj types

## TL;DR
- Moves `BytesObjBase`, `StringObj`, and `BytesObj` into `namespace tvm::ffi::details` in `string.h`, making them internal implementation types.
- Updates all call sites in `any.h`, `structural_equal.cc`, and `structural_hash.cc` to qualify with `details::`.
- Prepares for future SmallStr optimization by decoupling user-facing `String`/`Bytes` refs from their backing Obj types.

| Old name (in `tvm::ffi`) | New name |
|---|---|
| `BytesObjBase` | `details::BytesObjBase` |
| `StringObj` | `details::StringObj` |
| `BytesObj` | `details::BytesObj` |

## Key Exports

```python
# All three types are now in tvm::ffi::details — not directly accessible from tvm::ffi

class details.BytesObjBase(Object, TVMFFIByteArray):
    """Base for both String and Bytes backing objects; holds raw data/size."""
    data: const char*
    size: size_t
    # Interacts with: AnyHash, AnyEqual, StructEqualHandler, StructuralHashHandler
    # Invariant: layout matches TVMFFIByteArray so C ABI inline accessors remain valid

class details.StringObj(details.BytesObjBase):
    """Backing object for String; type_index == kTVMFFIStr."""
    # Interacts with: MakeInplaceBytes<details::StringObj>, BytesObjStdImpl<details::StringObj>

class details.BytesObj(details.BytesObjBase):
    """Backing object for Bytes; type_index == kTVMFFIBytes."""
    # Interacts with: MakeInplaceBytes<details::BytesObj>, BytesObjStdImpl<details::BytesObj>

# Public ref wrappers are unchanged — only internal binding macro argument changes:
# Old: TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS(String, ObjectRef, StringObj)
# New: TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS(String, ObjectRef, details::StringObj)
# Old: TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS(Bytes, ObjectRef, BytesObj)
# New: TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS(Bytes, ObjectRef, details::BytesObj)
```

## Impact
- API: Potentially breaking for any external code that directly referenced `tvm::ffi::BytesObjBase`, `tvm::ffi::StringObj`, or `tvm::ffi::BytesObj` — these are now only accessible as `tvm::ffi::details::*`. The user-facing `String` and `Bytes` ObjectRef classes are unchanged.
- Behavioral: None — identical runtime behavior.
- Flags/config: None.
- Data formats/schemas: None — `TVMFFIByteArray` layout and C ABI accessors are unchanged.

## Design Elements
Design elements this commit consumes:
- `0007-containers` (`String`/`Bytes` container design) — uses `BytesObjBase`/`StringObj`/`BytesObj` as the backing Obj types.
- `0003-any-anyview` — `AnyHash` and `AnyEqual` in `any.h` access `BytesObjBase` for content-based equality/hashing.
- `0001-c-abi` — `TVMFFIByteArray` layout must remain stable; the Obj types implement it.

Design elements this commit produces:
- Encapsulation convention: internal Obj types (`*Obj`, `*ObjBase`) for `String`/`Bytes` now live in `tvm::ffi::details`, establishing a pattern for future Obj types that should not be user-facing.

## Usage Examples

Before (no longer compiles as public code):
```cpp
// Was accessible in tvm::ffi namespace directly:
const BytesObjBase* ptr = AnyUnsafe::CopyFromAnyViewAfterCheck<const BytesObjBase*>(view);
```

After (correct form):
```cpp
// Must now use details:: qualifier:
const details::BytesObjBase* ptr =
    AnyUnsafe::CopyFromAnyViewAfterCheck<const details::BytesObjBase*>(view);
```
