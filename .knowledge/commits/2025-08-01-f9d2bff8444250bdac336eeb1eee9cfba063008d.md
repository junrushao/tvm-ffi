# [FFI][REFACTOR] Hide StringObj/BytesObj into details (#18184)

## TL;DR
- Moves `BytesObjBase`, `BytesObj`, and `StringObj` from `tvm::ffi` into `tvm::ffi::details`, making them implementation details rather than first-class public types.
- Updates all internal references in `any.h`, `structural_equal.cc`, and `structural_hash.cc` to use the `details::` prefix when accessing `BytesObjBase`.
- Updates `String` and `Bytes` ref-type constructors and `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` macros to qualify their Obj types with `details::`.
- Motivation: prepare for future optimizations such as SmallStr support, where the internal representation may change while the public `String`/`Bytes` API remains stable.

## Key Exports

No new public symbols are introduced. The following types move from `tvm::ffi` to `tvm::ffi::details`:

### Moved: `details::BytesObjBase` (`include/tvm/ffi/string.h`)
Base class for bytes and string objects. Inherits from `Object` and `TVMFFIByteArray`. Previously `tvm::ffi::BytesObjBase`.

### Moved: `details::BytesObj` (`include/tvm/ffi/string.h`)
Object class for raw bytes. `_type_index = TypeIndex::kTVMFFIBytes`, `_type_key = StaticTypeKey::kTVMFFIBytes`. Previously `tvm::ffi::BytesObj`.

### Moved: `details::StringObj` (`include/tvm/ffi/string.h`)
Object class for UTF-8 strings. `_type_index = TypeIndex::kTVMFFIStr`, `_type_key = StaticTypeKey::kTVMFFIStr`. Previously `tvm::ffi::StringObj`.

### Unchanged: `String` and `Bytes` (`include/tvm/ffi/string.h`)
The public ref-type wrappers remain in `tvm::ffi`. Their `get()` return types now point to `details::StringObj*` and `details::BytesObj*` respectively, but the user-facing API (`data()`, `size()`, constructors, comparison operators, etc.) is unchanged.

## Impact
- API: `StringObj` and `BytesObj` are no longer directly accessible as `tvm::ffi::StringObj` / `tvm::ffi::BytesObj`. Code that referenced these Obj types directly must now use `tvm::ffi::details::StringObj` / `tvm::ffi::details::BytesObj`. The public `String` and `Bytes` ref types are unaffected.
- ABI: None. The in-memory layout of `StringObj`, `BytesObj`, and `BytesObjBase` is identical. The `_type_index` and `_type_key` values are unchanged.
- Behavioral: None. Pure namespace reorganization.
- Future: Explicitly noted as preparation for SmallStr support, where the internal string representation may change (e.g., small-string optimization) without breaking the `String`/`Bytes` public API.

## Design Elements
Design elements this commit consumes:
- **Object pattern** (`FooObj` + `Foo` ref wrapper) -- The commit leverages the existing separation between data objects and ref wrappers, pushing the data objects into `details` while keeping ref wrappers public.
- **`TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS`** -- Macro that defines `get()`, `operator->()`, etc. on a ref type. Updated to reference `details::StringObj` / `details::BytesObj`.
- **`details::AnyUnsafe::CopyFromAnyViewAfterCheck`** (`any.h`) -- Used in `AnyHash` and `AnyEqual` to extract `BytesObjBase*` from type-erased values; updated to use `details::BytesObjBase*`.
- **`details::MakeInplaceBytes<Base>`** and **`details::BytesObjStdImpl<Base>`** (`string.h`) -- Already in `details` namespace; now their template arguments (`StringObj`, `BytesObj`) are also in `details`.

Design elements this commit produces:
- **Details-only Obj pattern for string/bytes** -- Establishes the convention that `StringObj`/`BytesObj`/`BytesObjBase` are implementation details. Users interact exclusively through the `String`/`Bytes` ref types. This decouples the public API from internal representation, enabling future changes like SmallStr without breaking downstream code.

## Usage Examples
No usage change for consumers of the public API. Code that previously did:
```cpp
// Before: direct Obj access (rare in user code, common in internals)
const BytesObjBase* ptr = ...;
```
must now use:
```cpp
// After: Obj types are in details
const details::BytesObjBase* ptr = ...;
```

The public API remains unchanged:
```cpp
String s("hello");
Bytes b(data, size);
// get() now returns details::StringObj* / details::BytesObj*, but
// users rarely call get() directly
```
