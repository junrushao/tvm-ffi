# Hide StringObj/BytesObj into details namespace to prepare for SmallStr

## TL;DR
- Moves `BytesObjBase`, `BytesObj`, and `StringObj` from `tvm::ffi` into `tvm::ffi::details` namespace, hiding implementation classes behind the public `String`/`Bytes` ref wrappers.
- Updates all internal consumers (`AnyHash`, `AnyEqual`, `StructEqualHandler`, `StructuralHashHandler`) to use `details::` qualified names.
- Prepares for future SmallStr optimization by ensuring the internal object representation is not part of the public API surface.

| Before | After |
|--------|-------|
| `tvm::ffi::BytesObjBase` | `tvm::ffi::details::BytesObjBase` |
| `tvm::ffi::BytesObj` | `tvm::ffi::details::BytesObj` |
| `tvm::ffi::StringObj` | `tvm::ffi::details::StringObj` |

## Key Exports

No new exports. The public API (`String`, `Bytes`) is unchanged. The Obj classes are moved to `details::` and are no longer part of the public API surface.

```python
# Before (public):
# class StringObj(Object): ...   # in tvm::ffi
# class BytesObj(Object): ...    # in tvm::ffi
# class BytesObjBase(Object): ...# in tvm::ffi

# After (internal):
# class details.StringObj(Object): ...    # in tvm::ffi::details
# class details.BytesObj(Object): ...     # in tvm::ffi::details
# class details.BytesObjBase(Object): ... # in tvm::ffi::details

# Public refs remain unchanged:
class String(ObjectRef):
    """Immutable UTF-8 string reference."""
    # Interacts with: details::StringObj (hidden), AnyHash, AnyEqual
    # Invariant: public API unchanged; internal Obj type is now a detail
    # Extension: SmallStr optimization can replace details::StringObj internals
    ...

class Bytes(ObjectRef):
    """Immutable byte buffer reference."""
    # Interacts with: details::BytesObj (hidden), AnyHash, AnyEqual
    ...
```

## Impact
- API: `tvm::ffi::StringObj`, `tvm::ffi::BytesObj`, `tvm::ffi::BytesObjBase` are no longer directly accessible. External code referencing these unqualified names will fail to compile. Users should use `String`/`Bytes` ref wrappers instead.
- Behavioral: none -- no semantic changes
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Object/ObjectRef pattern (0002-object-system) -- `StringObj`/`BytesObj` follow `FooObj` + `Foo` ref wrapper pattern
- Any value system (0001-any-anyview-value-system) -- `AnyHash`/`AnyEqual` use `BytesObjBase` for string hashing/equality
- Container library (0006-containers) -- `String`/`Bytes` are container value types

Design elements this commit produces:
- None -- this is a namespace reorganization, not a new design element. It reinforces the convention that `*Obj` implementation types should live in `details::` when the public ref wrapper is the intended API.

## Usage Examples

Before/after for code that directly referenced the Obj types:

```cpp
// Before: direct access to Obj type (now broken)
const tvm::ffi::BytesObjBase* obj = ...;

// After: must qualify with details::
const tvm::ffi::details::BytesObjBase* obj = ...;

// Preferred: use the public ref wrapper (unchanged)
tvm::ffi::String s("hello");
tvm::ffi::Bytes b("data", 4);
```
