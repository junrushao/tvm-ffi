# Move StringObj/BytesObj into details namespace to hide implementation

## TL;DR
- Moves `BytesObjBase`, `BytesObj`, and `StringObj` from `tvm::ffi` into `tvm::ffi::details`, hiding the Obj classes as implementation details.
- Updates all consumer sites (`any.h`, `structural_equal.cc`, `structural_hash.cc`) to use the `details::` qualified names.
- Prepares the internal layout for future changes such as SmallStr support, by narrowing the public API surface to just the ref wrappers (`String`, `Bytes`).

### Rename mapping

| Before (`tvm::ffi::`) | After (`tvm::ffi::details::`) |
|------------------------|-------------------------------|
| `BytesObjBase` | `details::BytesObjBase` |
| `BytesObj` | `details::BytesObj` |
| `StringObj` | `details::StringObj` |

## Key Exports

No new exports. The public API surface narrows: `String` and `Bytes` ref wrappers remain in `tvm::ffi` as the only public handles. Their underlying Obj types are now implementation details.

```python
# BEFORE: StringObj and BytesObj were public in tvm::ffi
# class StringObj(BytesObjBase): ...   # tvm::ffi::StringObj
# class BytesObj(BytesObjBase): ...    # tvm::ffi::BytesObj

# AFTER: Obj types moved to details namespace
# class details.StringObj(details.BytesObjBase): ...  # tvm::ffi::details::StringObj
# class details.BytesObj(details.BytesObjBase): ...   # tvm::ffi::details::BytesObj

# Public API unchanged:
class String(ObjectRef):
    """Immutable UTF-8 string ref wrapper. Remains in tvm::ffi."""
    # Interacts with: details::StringObj (via TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS)
    # Interacts with: AnyView (kTVMFFIRawStr -> String conversion)
    # Invariant: get() returns details::StringObj*, not directly accessible by users

class Bytes(ObjectRef):
    """Immutable byte array ref wrapper. Remains in tvm::ffi."""
    # Interacts with: details::BytesObj (via TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS)
    # Invariant: get() returns details::BytesObj*, not directly accessible by users
```

## Impact
- API: `StringObj` and `BytesObj` are no longer directly addressable as `tvm::ffi::StringObj`/`tvm::ffi::BytesObj`. Code that directly references these types must add the `details::` qualifier. The ref wrappers `String`/`Bytes` are unaffected.
- Behavioral: none -- purely a namespace relocation.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Object pattern (`XxxObj` + `Xxx` ref wrapper) from [0003-ffi-object-system](../design-records/0003-ffi-object-system.md)
- `BytesObjBase` layout (TVMFFIObject + TVMFFIByteArray) from [0006-ffi-containers](../design-records/0006-ffi-containers.md)
- `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` macro from [0008-ffi-object-macros](../design-records/0008-ffi-object-macros.md)
- `AnyUnsafe::CopyFromAnyViewAfterCheck` from [0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md)

Design elements this commit produces/mutates:
- **Mutates** the visibility of `StringObj`/`BytesObj`/`BytesObjBase`: moved from public namespace `tvm::ffi` to `tvm::ffi::details`. This establishes a convention that Obj data classes for built-in containers can be internal-only, with only the ref wrapper exposed publicly. This prepares the ground for future internal layout changes (e.g., SmallStr) without breaking public API.

## Usage Examples

Before/after pattern for downstream C++ code that directly referenced these types:

```cpp
// BEFORE (compile error after this commit):
const tvm::ffi::BytesObjBase* obj = ...;

// AFTER:
const tvm::ffi::details::BytesObjBase* obj = ...;

// Preferred: Use the public ref wrapper instead of accessing Obj directly
tvm::ffi::String s("hello");
std::string_view sv = s;  // implicit conversion, no Obj access needed
```
