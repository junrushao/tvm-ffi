# Move StringObj/BytesObj/BytesObjBase into details namespace to hide implementation

## TL;DR
- Moves `BytesObjBase`, `BytesObj`, and `StringObj` from `tvm::ffi::` into `tvm::ffi::details::`, hiding the Obj-layer classes from the public API surface.
- All call sites in `any.h`, `structural_equal.cc`, and `structural_hash.cc` are updated to use the `details::` prefix.
- Preparatory refactor for future changes such as SmallStr support (stated in commit message).

### Rename Mapping

| Before | After |
|---|---|
| `tvm::ffi::BytesObjBase` | `tvm::ffi::details::BytesObjBase` |
| `tvm::ffi::BytesObj` | `tvm::ffi::details::BytesObj` |
| `tvm::ffi::StringObj` | `tvm::ffi::details::StringObj` |

## Key Exports

The public API (`String`, `Bytes` ref classes) is unchanged. The Obj classes are now implementation details.

```python
# BEFORE: these were public
# class BytesObjBase(Object, TVMFFIByteArray): ...   # was tvm::ffi::BytesObjBase
# class BytesObj(BytesObjBase): ...                   # was tvm::ffi::BytesObj
# class StringObj(BytesObjBase): ...                  # was tvm::ffi::StringObj

# AFTER: moved into details namespace
# namespace details:
#   class BytesObjBase(Object, TVMFFIByteArray): ...  # now tvm::ffi::details::BytesObjBase
#   class BytesObj(BytesObjBase): ...                  # now tvm::ffi::details::BytesObj
#   class StringObj(BytesObjBase): ...                 # now tvm::ffi::details::StringObj

# Public ref classes remain unchanged:
class Bytes(ObjectRef):
    """Immutable byte array ref. ContainerType is now details::BytesObj."""
    # Interacts with: details::BytesObj, details::MakeInplaceBytes, details::BytesObjStdImpl
    # Invariant: public API unchanged — constructors, operators, memequal all work the same

class String(ObjectRef):
    """Immutable UTF-8 string ref. ContainerType is now details::StringObj."""
    # Interacts with: details::StringObj, details::MakeInplaceBytes, details::BytesObjStdImpl
    # Invariant: public API unchanged
```

## Impact
- API: `BytesObjBase`, `BytesObj`, `StringObj` are no longer accessible as `tvm::ffi::BytesObjBase` etc. External code directly referencing these Obj types must add the `details::` prefix. The `String` and `Bytes` ref classes are unaffected.
- Behavioral: none — pure namespace move, no semantic change.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system** (`.knowledge/designs/0002-object-system.md`): `BytesObjBase`/`BytesObj`/`StringObj` follow the Obj + Ref pattern.
- **Any system** (`.knowledge/designs/0003-any-system.md`): `AnyHash` and `AnyEqual` use `BytesObjBase*` for string/bytes comparison.
- **Containers / String & Bytes** (`.knowledge/designs/0007-containers.md`): Documents `StringObj` and `BytesObj` as public types.

Design elements this commit produces:
- **Convention: Obj classes in `details` namespace**: Establishes the pattern of placing Obj implementation classes in `tvm::ffi::details::` while keeping Ref classes public. This prepares for future internal implementation changes (e.g., SmallStr) without breaking the public Ref API.

## Usage Examples

Before/after for code that references Obj types directly:

```cpp
// BEFORE
const BytesObjBase* str = details::AnyUnsafe::CopyFromAnyViewAfterCheck<const BytesObjBase*>(src);

// AFTER
const details::BytesObjBase* str =
    details::AnyUnsafe::CopyFromAnyViewAfterCheck<const details::BytesObjBase*>(src);

// Public API usage is UNCHANGED:
String s("hello");        // still works
Bytes b("data", 4);      // still works
```
