# Move StringObj/BytesObj/BytesObjBase into details namespace to hide implementation

## TL;DR
- Moves `BytesObjBase`, `BytesObj`, and `StringObj` from `tvm::ffi` into `tvm::ffi::details`, making them implementation details rather than public API.
- Updates all internal consumers (`any.h`, `structural_equal.cc`, `structural_hash.cc`) to use the `details::` qualified names.
- Prepares for future `SmallStr` optimization by reducing the public surface area of the string object hierarchy.

**Rename mapping:**

| Before | After |
|---|---|
| `tvm::ffi::BytesObjBase` | `tvm::ffi::details::BytesObjBase` |
| `tvm::ffi::BytesObj` | `tvm::ffi::details::BytesObj` |
| `tvm::ffi::StringObj` | `tvm::ffi::details::StringObj` |

## Key Exports
The commit does not introduce new types or functions. It changes the namespace of three existing Obj classes:

**Types/Classes (moved to `details`):**
- `details::BytesObjBase` — base class for string/bytes, inherits `Object + TVMFFIByteArray`. Fields: `const char* data`, `size_t size` (from `TVMFFIByteArray`).
- `details::BytesObj` — bytes data object. Static type index: `kTVMFFIBytes`. Final type.
- `details::StringObj` — string data object. Static type index: `kTVMFFIStr`. Final type.

The public-facing ref wrappers `String` and `Bytes` remain in `tvm::ffi` and are unchanged in their API. They now reference `details::StringObj` and `details::BytesObj` in their `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` macro invocations.

## Impact
- API: The Obj types (`StringObj`, `BytesObj`, `BytesObjBase`) are no longer directly accessible as `tvm::ffi::StringObj` etc. Any external code directly referencing these names must add the `details::` qualifier. The ref wrappers `String` and `Bytes` are unaffected.
- Behavioral: None. No functional change.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object system Obj+Ref pattern** ([0003-object-system.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0003-object-system.md)): `BytesObjBase`/`BytesObj`/`StringObj` follow the standard Obj pattern; `Bytes`/`String` follow the Ref pattern.
- **Any value system** ([0002-any-value-system.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0002-any-value-system.md)): `AnyHash` and `AnyEqual` in `any.h` access `BytesObjBase` for string hashing/comparison.
- **details::AnyUnsafe::CopyFromAnyViewAfterCheck** — used to extract `BytesObjBase*` from `AnyView` in hash/equality code.

Design elements this commit produces:
- **Convention: Obj classes as `details` namespace members** — establishes a pattern where the data-bearing Obj classes are implementation details, and only the Ref wrappers constitute the public API. This is a new convention not previously seen in the codebase (previously all Obj classes were in `tvm::ffi` directly).

## Usage Examples
After this commit, code that previously referenced `BytesObjBase` or `StringObj` directly must qualify with `details::`:

```cpp
// Before:
const BytesObjBase* str = details::AnyUnsafe::CopyFromAnyViewAfterCheck<const BytesObjBase*>(src);

// After:
const details::BytesObjBase* str =
    details::AnyUnsafe::CopyFromAnyViewAfterCheck<const details::BytesObjBase*>(src);
```

User-facing code using `String` and `Bytes` ref wrappers is unaffected:
```cpp
// No change needed:
String s("hello");
Bytes b("raw", 3);
```
