# feat: Add overflow check for uint64_t/size_t in TypeTraits<Int>::CopyToAnyView and fix StructuralHash uint64->int64 conversion

## TL;DR
- `TypeTraits<Int>::CopyToAnyView` now throws `OverflowError` when a `uint64_t`/`size_t` value exceeds `int64_t::max()` — prevents silent data loss when storing large unsigned ints in `Any`
- `StructuralHash` functions now explicitly bitcast `uint64_t` → `int64_t` (preserving bit pattern) before returning through FFI boundary, avoiding the new overflow check
- `FFIStructuralHash` wrapper returns `int64_t` (bitcast of hash result) instead of `uint64_t`
- Added 16 C++ test cases; updated `testing_object.h` to use `int64_t` for hash fields

## Impact
- API: Behavioral — storing `uint64_t` > `INT64_MAX` in `Any` now throws `OverflowError` instead of silently truncating/wrapping
- Behavioral: `ffi.StructuralHash` now returns `int64_t` (bitcast) instead of `uint64_t`; callers must reinterpret as `uint64_t` if needed
- Flags/config: none
- Data formats/schemas: none
