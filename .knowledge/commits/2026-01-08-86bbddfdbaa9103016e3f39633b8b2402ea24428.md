# Add overflow check for uint64_t/size_t to int64_t conversion in TypeTraits<Int>::CopyToAnyView

## TL;DR
- Adds a runtime overflow guard in `TypeTraits<Int>::CopyToAnyView` that throws `OverflowError` when an unsigned 64-bit integer exceeds `INT64_MAX`, preventing silent truncation/wrap when storing into the `v_int64` field of `TVMFFIAny`.
- Fixes the `ffi.StructuralHash` FFI wrapper and internal `StructuralHashHandler` to explicitly `static_cast<int64_t>` hash values (which are `uint64_t`) before passing them through `Any`, avoiding the new overflow check triggering on legitimate hash values.
- Updates the `__s_hash__` custom callback signature in test fixtures from `uint64_t` to `int64_t` to match the new calling convention.

## Key Exports

```python
# === Changed: TypeTraits<Int>::CopyToAnyView (type_traits.h) ===
# Before: unconditionally casts src to int64_t (silent wrap for uint64_t > INT64_MAX)
# After:  compile-time guard + runtime check for unsigned types >= 64 bits

class TypeTraits(Generic[Int]):
    @staticmethod
    def CopyToAnyView(src: Int, result: Ptr[TVMFFIAny]) -> None:
        # NEW: if Int is unsigned and sizeof(Int) >= 8, check overflow
        if src > int64_max:
            raise OverflowError(f"Integer value {src} is too large to fit in int64_t.")
        result.type_index = kTVMFFIInt
        result.v_int64 = int64_t(src)
        # Invariant: v_int64 faithfully represents src (no silent wrap)
        # Interacts with: AnyView constructor, Any constructor (via MoveToAny which delegates here)
        # Interacts with: StructuralHash (hash values are uint64_t, must be bitcast before storage)

# === Changed: FFI wrapper for ffi.StructuralHash (structural_hash.cc) ===
# Before: registered StructuralHash::Hash directly (returns uint64_t -> triggers overflow)
# After:  thin wrapper bitcasts uint64_t result to int64_t before returning through Any

def FFIStructuralHash(value: Any, map_free_vars: bool, skip_tensor_content: bool) -> int64_t:
    result: uint64_t = StructuralHash.Hash(value, map_free_vars, skip_tensor_content)
    return int64_t(result)  # explicit bitcast to avoid OverflowError
    # Interacts with: global registry "ffi.StructuralHash", Python tvm_ffi.structural_hash()
    # Invariant: bit pattern preserved; Python callers see a signed int that may be negative

# === Changed: __s_hash__ custom callback signature ===
# Before: (self, init_hash: uint64_t, hash: (AnyView, uint64_t, bool) -> uint64_t) -> uint64_t
# After:  (self, init_hash: int64_t,  hash: (AnyView, int64_t,  bool) -> int64_t)  -> int64_t
# All values are bitcast int64_t representations of uint64_t hashes.
```

## Impact
- API: The FFI-registered `ffi.StructuralHash` now returns `int64_t` (was `uint64_t`). The bit pattern is identical but the sign interpretation changes. Python callers may see negative hash values where they previously saw large positive values.
- Behavioral: `AnyView(uint64_t_value)` where value > `INT64_MAX` now throws `OverflowError` instead of silently wrapping. This is a correctness fix but may surface latent bugs in code that relied on silent wrap.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces:
- **uint64_t overflow invariant on CopyToAnyView**: new invariant that unsigned 64-bit values must not exceed `INT64_MAX` when entering `Any`/`AnyView`. Code that produces `uint64_t` values (like hash functions) must explicitly bitcast to `int64_t` before storing.
- **FFIStructuralHash wrapper**: thin wrapper that bitcasts hash result for safe FFI transport.

## Usage Examples

**Before (silent data corruption):**
```cpp
uint64_t big = static_cast<uint64_t>(std::numeric_limits<int64_t>::max()) + 1;
AnyView view = big;  // silently wraps to negative int64_t — WRONG
```

**After (overflow detected):**
```cpp
uint64_t big = static_cast<uint64_t>(std::numeric_limits<int64_t>::max()) + 1;
// AnyView view = big;  // throws OverflowError

// Correct pattern when bitcast is intentional:
AnyView view = static_cast<int64_t>(big);  // explicit bitcast — caller takes responsibility
```
