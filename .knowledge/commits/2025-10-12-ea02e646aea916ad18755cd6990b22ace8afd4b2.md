# Add tvm-ffi-stubgen CLI for in-place type stub generation from TVM FFI registry metadata

## TL;DR
- Introduces `python/tvm_ffi/stub/stubgen.py` (528 LOC) and the `tvm-ffi-stubgen` CLI entry point: a tool that scans `.py`/`.pyi` files for marker comments and fills enclosed blocks with `TYPE_CHECKING`-guarded stubs derived from TVM FFI's runtime reflection registry.
- Three block kinds: `global/<prefix>` (global function signatures), `object/<type_key>` (fields + methods for an FFI object), `skip-file` (opt-out). `ty_map` directives inside a block rename types in generated output (default: `list -> Sequence`, `dict -> Mapping`).
- Applied the new tool to `_ffi_api.py`, `testing.py`, `access_path.py`, `module.py`, and the packaging example — replacing hand-authored type annotations and `# type: ignore[attr-defined]` suppressions with generated stubs, eliminating annotation drift between C++ and Python.

## Impact
- API: New `tvm-ffi-stubgen` CLI entry point (registered in `pyproject.toml`). New `tvm_ffi.stub` subpackage (`python/tvm_ffi/stub/__init__.py` + `stubgen.py`). Two new public functions consumed from `tvm_ffi.registry`: `list_global_func_names()` and `get_global_func_metadata()`.
- Behavioral: None to runtime — all generated content is inside `if TYPE_CHECKING:` guards, invisible at runtime. `module.py`: `Module.entry_name` changed from a plain class attribute to `ClassVar[str]`; `get_write_formats()` return type broadened from `list[str]` to `Sequence[str]`. `access_path.py`: `AccessPath.to_steps()` return type widened from `list[AccessStep]` to `Sequence[AccessStep]`.
- Flags/config: `--dlls` CLI flag to preload shared libraries before scanning; `--indent` to control indentation inside generated blocks.
- Data formats/schemas: Generated stub blocks are deterministic and stable. Block output format: `if TYPE_CHECKING:\n    # fmt: off\n    <stubs>\n    # fmt: on`. Omitted entirely if no functions/fields match (block is left empty).

## Design Elements
Design elements this commit consumes:
- **0006-reflection** (`TypeInfo`, `TypeField`, `TypeMethod`): `_generate_object()` calls `_lookup_or_register_type_info_from_type_key(type_key)` and iterates `type_info.fields` and `type_info.methods`, reading `field.metadata["type_schema"]` and `method.metadata["type_schema"]` (the structured JSON introduced in commit 935a5a07).
- **0004-function-system** (global registry): `_compute_global_func_tab()` calls `list_global_func_names()`; `_generate_global()` calls `get_global_func_metadata(name)["type_schema"]` to retrieve per-function `TypeSchema`.
- **0013-python-package** (`TypeSchema.from_json_str`, `init_ffi_api`, subpackage pattern): `stubgen.py` imports `TypeSchema` from `tvm_ffi.core` and `get_global_func_metadata`/`list_global_func_names` from `tvm_ffi.registry`. Follows the established subpackage pattern (`tvm_ffi.stub`).

Design elements this commit produces:
- **Stub-block protocol** (`tvm_ffi/stub/stubgen.py`): New convention for annotating `.py`/`.pyi` files with `tvm-ffi-stubgen` marker comments to receive auto-generated stubs. Producers of new FFI types and global functions should add stub blocks to their `_ffi_api.py` and object class bodies.
- **`tvm-ffi-stubgen` CLI** (`pyproject.toml` entry point): new developer workflow step — `uv run tvm-ffi-stubgen <path>` regenerates stubs after C++ reflection changes.

## Usage Examples

**Adding stub blocks to a downstream `_ffi_api.py`** (from `examples/packaging/python/my_ffi_extension/_ffi_api.py`):
```python
from typing import TYPE_CHECKING
import tvm_ffi
from .base import _LIB  # noqa: F401
tvm_ffi.init_ffi_api("my_ffi_extension", __name__)

# tvm-ffi-stubgen(begin): global/my_ffi_extension
if TYPE_CHECKING:
    # fmt: off
    def raise_error(_0: str, /) -> None: ...
    # fmt: on
# tvm-ffi-stubgen(end)
```
Run `tvm-ffi-stubgen examples/packaging/python/my_ffi_extension/_ffi_api.py` to regenerate after C++ changes.

**Object stub block with ty_map** (from `python/tvm_ffi/testing.py`):
```python
@register_object("testing.SchemaAllTypes")
class _SchemaAllTypes:
    # tvm-ffi-stubgen(begin): object/testing.SchemaAllTypes
    # tvm-ffi-stubgen(ty_map): testing.SchemaAllTypes -> _SchemaAllTypes
    if TYPE_CHECKING:
        # fmt: off
        v_arr_int: Sequence[int]
        v_map_str_int: Mapping[str, int]
        def add_int(_0: _SchemaAllTypes, _1: int, /) -> int: ...
        @staticmethod
        def make_with(_0: int, _1: float, _2: str, /) -> _SchemaAllTypes: ...
        # fmt: on
    # tvm-ffi-stubgen(end)
```
