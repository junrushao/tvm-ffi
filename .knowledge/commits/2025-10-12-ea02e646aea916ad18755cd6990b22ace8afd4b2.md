# Introduce tvm-ffi-stubgen CLI for in-place Python type stub generation from FFI registry metadata
## TL;DR
- Adds `tvm-ffi-stubgen`, a new CLI tool (`python/tvm_ffi/stub/stubgen.py`) that generates inline type stubs inside `# tvm-ffi-stubgen(begin/end)` marker blocks in `.py`/`.pyi` files, producing `TYPE_CHECKING`-guarded annotations derived from the TVM FFI runtime registry.
- Replaces the hand-maintained `python/tvm_ffi/_ffi_api.pyi` with auto-generated inline stubs in `python/tvm_ffi/_ffi_api.py`, and adds inline stubs to `testing.py`, `access_path.py`, `module.py`, and `examples/packaging/python/my_ffi_extension/_ffi_api.py`.
- Supports three block types (`global/<prefix>` for global functions, `object/<type_key>` for object fields/methods, `skip-file` to opt out), per-block `ty_map` directives for type remapping, and deterministic/idempotent output.

## Impact
- API: Adds `tvm-ffi-stubgen` CLI entry point. No existing public APIs removed or changed.
- Behavioral: Existing `_ffi_api.pyi` deleted; stubs now live inline in `_ffi_api.py` under `TYPE_CHECKING` guard. `type: ignore[attr-defined]` annotations removed from `access_path.py` method calls (stubs now visible to type checkers). Two `type: ignore[attr-defined]` added in `test_object.py` for `.same_as()` calls on `Sequence` type (which lacks that method).
- Flags/config: New `[project.scripts]` entry `tvm-ffi-stubgen` in `pyproject.toml`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection system** (0008): `_lookup_or_register_type_info_from_type_key()` to retrieve `TypeInfo` with fields/methods for object types; `TypeSchema.from_json_str()` to parse field/method metadata into structured type information; `get_global_func_metadata()` for per-function type schema JSON.
- **Global function registry** (0003/0012): `list_global_func_names()` to enumerate all registered global functions for building the prefix table.
- **Python bindings** (0012): `init_ffi_api` pattern for auto-populating modules; `register_object` for type registration; existing `_ffi_api.pyi` as the predecessor approach.

Design elements this commit produces:
- **Inline stub protocol**: A marker-based DSL (`tvm-ffi-stubgen(begin/end/ty_map/skip-file)`) for embedding auto-generated type stubs inside Python source files, guarded by `TYPE_CHECKING`.
- **`tvm-ffi-stubgen` CLI tool**: Entry point for running stub generation across files/directories, with `--dlls` for preloading native extensions.

## Usage Examples

Running the CLI to generate stubs for the core package:

```bash
# Generate stubs for a single file
tvm-ffi-stubgen python/tvm_ffi/_ffi_api.py

# Recursively scan directories
tvm-ffi-stubgen python/tvm_ffi examples/packaging/python/my_ffi_extension

# Preload native extensions before generation
tvm-ffi-stubgen --dlls build/libtvm_runtime.so python/tvm_ffi
```

Adding stubs to a Python source file:

```python
from typing import TYPE_CHECKING

# tvm-ffi-stubgen(begin): global/my_prefix
# (auto-generated content will appear here after running tvm-ffi-stubgen)
# tvm-ffi-stubgen(end)

@register_object("my.Type")
class MyType(Object):
    # tvm-ffi-stubgen(begin): object/my.Type
    # tvm-ffi-stubgen(ty_map): my.Type -> MyType
    # (auto-generated fields and methods appear here)
    # tvm-ffi-stubgen(end)
```

Programmatic usage from tests:

```python
from tvm_ffi.stub.stubgen import Options, _main
_main(Path("my_file.py"), Options(indent=4, suppress_print=True))
```
