# Introduce tvm-ffi-stubgen CLI for in-place static typing stub generation
## TL;DR
- Adds `tvm-ffi-stubgen`, a CLI tool (`python/tvm_ffi/stub/stubgen.py`, 528 lines) that scans Python files for `tvm-ffi-stubgen(begin/end)` markers and fills blocks with generated type stubs from the FFI registry.
- Supports global functions (`global/<prefix>`), object types (`object/<type_key>`), per-block `ty_map` remapping, and a `skip-file` directive.
- Moves FFI API stubs from `_ffi_api.pyi` to inline blocks in `_ffi_api.py`, and updates `testing.py` and `access_path.py` with object stub blocks.

## Impact
- API: New CLI entry point `tvm-ffi-stubgen`. New module `python/tvm_ffi/stub/`. Removes standalone `_ffi_api.pyi`.
- Flags/config: New `[project.scripts]` entry in `pyproject.toml`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Reflection / TypeSchema** (`.knowledge/designs/0006-reflection.md`): Uses `TypeSchema.repr(ty_map)` and `get_global_func_metadata()` to generate type annotations.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): Reads `TypeInfo`, `TypeField`, `TypeMethod` from registered objects.

Design elements this commit produces:
- **tvm-ffi-stubgen tool**: A marker-driven in-place stub generator that bridges C++ reflection metadata to Python static typing. Key design: deterministic output, `TYPE_CHECKING` guarded, supports `--dlls` for preloading native extensions.
- **Inline stub block convention**: `# tvm-ffi-stubgen(begin): <kind>/<key>` / `# tvm-ffi-stubgen(end)` markers in `.py`/`.pyi` files.
