# Introduce tvm-ffi-stubgen CLI for in-place static type stub generation

## TL;DR
- Adds `tvm-ffi-stubgen`, a CLI tool that scans `.py`/`.pyi` files for marker comments and fills enclosed blocks with `TYPE_CHECKING`-guarded type stubs derived from the TVM FFI runtime registry.
- Supports two block types: `global/<prefix>` for global function stubs and `object/<type_key>` for object field/method stubs, plus `ty_map` directives for type alias remapping.
- Applies generated stubs to `_ffi_api.py`, `testing.py`, `access_path.py`, and `module.py`; removes the old `_ffi_api.pyi` stub file.

## Key Exports

**CLI entry point**: `tvm-ffi-stubgen` (registered in `pyproject.toml` as `tvm_ffi.stub.stubgen:__main__`)

**Module: `python/tvm_ffi/stub/stubgen.py`** (528 lines, new):

**Classes**:
- `Options(dlls: list[str], indent: int, files: list[str], suppress_print: bool)` -- CLI option container
- `StubConfig(name: str, indent: int, lineno: int, ty_map: dict[str, str])` -- per-block configuration, default `ty_map` maps `list -> Sequence`, `dict -> Mapping`

**Functions**:
- `__main__() -> int` -- argparse CLI entry point
- `_main(file: Path, opt: Options, global_func_tab: dict | None) -> None` -- process a single file
- `_compute_global_func_tab() -> dict[str, list[str]]` -- build sorted prefix-to-function-name table from FFI registry
- `_generate_global(stub, global_func_tab, opt) -> list[str]` -- generate global function stub lines
- `_generate_object(stub, opt) -> list[str]` -- generate object field/method stub lines
- `_as_func_signature(schema: TypeSchema, func_name: str, ty_map) -> str` -- render a function signature string from `TypeSchema`
- `_filter_files(paths: list[Path]) -> list[Path]` -- recursively collect `.py`/`.pyi` files

**Marker protocol** (comment-based directives in source files):
- `# tvm-ffi-stubgen(begin): global/<prefix>` / `# tvm-ffi-stubgen(end)` -- global function block
- `# tvm-ffi-stubgen(begin): object/<type_key>` / `# tvm-ffi-stubgen(end)` -- object type block
- `# tvm-ffi-stubgen(ty_map): A.B -> C` -- type alias remapping within a block
- `# tvm-ffi-stubgen(skip-file)` -- opt out of processing
- `__ffi_init__` is renamed to `__c_ffi_init__` in generated stubs to avoid conflicts with Python `__init__`

**Constants**: `STUB_BEGIN`, `STUB_END`, `STUB_TY_MAP`, `STUB_SKIP_FILE`, `DEFAULT_SOURCE_EXTS = {".py", ".pyi"}`

## Impact
- API: New CLI tool `tvm-ffi-stubgen`. Additive, non-breaking.
- Behavioral: `_ffi_api.pyi` removed; stubs are now inline in `_ffi_api.py` under `TYPE_CHECKING`.
- Flags/config: `--dlls` for shared library preloading, `--indent` for indentation control.
- Data formats/schemas: none

- **Stub generation protocol** -- a comment-marker-based convention for declaring where type stubs should be generated, with `ty_map` for alias control. This is a new code-generation convention that downstream FFI extensions can adopt.
- **Inline TYPE_CHECKING stubs pattern** -- replaces separate `.pyi` files with inline `if TYPE_CHECKING:` blocks, keeping stubs co-located with runtime code.

## Usage Examples

**CLI usage** (from commit message):
```bash
# Recursively scan directories
tvm-ffi-stubgen python/tvm_ffi examples/packaging/python/my_ffi_extension

# Preload shared libraries
tvm-ffi-stubgen --dlls build/libtvm_runtime.so my_pkg/_ffi_api.py
```

**Source marker pattern** (from `testing.py`):
```python
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    # tvm-ffi-stubgen(begin): object/testing.TestIntPair
    if TYPE_CHECKING:
        # fmt: off
        a: int
        b: int
        @staticmethod
        def __c_ffi_init__(_0: int, _1: int, /) -> Object: ...
        # fmt: on
    # tvm-ffi-stubgen(end)
```
