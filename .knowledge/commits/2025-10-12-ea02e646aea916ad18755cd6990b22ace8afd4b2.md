# Introduce tvm-ffi-stubgen CLI for in-place type stub generation from FFI metadata

## TL;DR
- Adds `tvm-ffi-stubgen`, a CLI tool (`python/tvm_ffi/stub/stubgen.py`) that scans `.py`/`.pyi` files for special begin/end markers and fills them with `TYPE_CHECKING`-guarded type stubs derived from the TVM FFI runtime registry (global functions, object fields, object methods).
- Replaces the hand-written `_ffi_api.pyi` stub file with inline generated stubs inside `_ffi_api.py`, and retrofits `testing.py`, `access_path.py`, and `module.py` with object-type stub blocks, producing rich typed signatures (e.g., `Sequence`, `Mapping`, `Optional`) instead of `*args: Any`.
- Registers `tvm-ffi-stubgen` as a CLI entry point in `pyproject.toml` and adds comprehensive tests (`test_stubgen.py`) covering skip-file, global/object blocks, ty_map, idempotency, and error cases.

## Impact
- API: New CLI tool `tvm-ffi-stubgen` and new Python subpackage `tvm_ffi.stub`. No changes to existing public APIs. The hand-written `_ffi_api.pyi` is deleted in favor of inline stubs in `_ffi_api.py`.
- Behavioral: `access_path.py` methods lose `# type: ignore[attr-defined]` annotations since reflected methods are now visible to type checkers. `module.py`'s `get_write_formats` return type changes from `list[str]` to `Sequence[str]`. `testing.py`'s `_SchemaAllTypes` gains a full stub body (was `...` placeholder).
- Flags/config: New `[project.scripts]` entry `tvm-ffi-stubgen` in `pyproject.toml`.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/0008-reflection.md`): Uses `_lookup_or_register_type_info_from_type_key` to enumerate fields and methods of registered object types; reads `TypeSchema` from field/method metadata `type_schema` JSON strings.
- **Global function registry** (`.knowledge/designs/0012-python-bindings.md`): Uses `list_global_func_names()` and `get_global_func_metadata()` from `registry.py` to discover and type all registered global functions.
- **TypeSchema** (Cython `type_info.pxi`): Uses `TypeSchema.from_json_str()` and `TypeSchema.repr(ty_map)` to convert JSON type schemas into Python typing strings.
- **init_ffi_api pattern** (`.knowledge/designs/0012-python-bindings.md`): The stub blocks are designed to complement `init_ffi_api`, providing static type information for the dynamically populated module attributes.

Design elements this commit produces:
- **Stub block marker protocol**: A new comment-based directive protocol (`# tvm-ffi-stubgen(begin/end/ty_map/skip-file)`) for embedding auto-generated type stubs in Python source files. This is a new convention affecting how type annotations are managed across the project.
- **tvm-ffi-stubgen CLI tool**: A new developer-facing tool registered as a `pyproject.toml` script entry point.
- **Inline stub pattern** (replacing `.pyi` sidecar pattern): Moves type stubs from separate `.pyi` files into `if TYPE_CHECKING:` blocks within `.py` files, guarded by begin/end markers. Supersedes the `_ffi_api.pyi` convention from commit `40e9c83`.

## Usage Examples

Generating global function stubs in a Python module:
```python
# In my_module/_ffi_api.py:
from typing import TYPE_CHECKING
import tvm_ffi

tvm_ffi.init_ffi_api("my_prefix", __name__)

# tvm-ffi-stubgen(begin): global/my_prefix
# (after running: tvm-ffi-stubgen my_module/_ffi_api.py)
if TYPE_CHECKING:
    # fmt: off
    def my_func(_0: int, _1: str, /) -> bool: ...
    # fmt: on
# tvm-ffi-stubgen(end)
```

Generating object field/method stubs with type remapping:
```python
@register_object("my.MyObj")
class MyObj(Object):
    # tvm-ffi-stubgen(begin): object/my.MyObj
    # tvm-ffi-stubgen(ty_map): my.MyObj -> MyObj
    if TYPE_CHECKING:
        # fmt: off
        field_a: int
        field_b: Sequence[str]
        def method(_0: MyObj, _1: int, /) -> str: ...
        @staticmethod
        def __c_ffi_init__(_0: int, /) -> Object: ...
        # fmt: on
    # tvm-ffi-stubgen(end)
```

CLI invocation:
```bash
# Single file
tvm-ffi-stubgen python/tvm_ffi/_ffi_api.py

# Recursive directory scan
tvm-ffi-stubgen python/tvm_ffi

# With preloaded shared libraries
tvm-ffi-stubgen --dlls build/libtvm_runtime.so python/tvm_ffi
```
