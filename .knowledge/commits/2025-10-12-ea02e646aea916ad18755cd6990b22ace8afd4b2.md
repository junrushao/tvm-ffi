# Add tvm-ffi-stubgen CLI tool for in-place Python type stub generation from FFI registry metadata
## TL;DR
- Introduces `tvm-ffi-stubgen`, a new CLI tool and Python module (`tvm_ffi.stub.stubgen`) that generates in-place, static type stubs inside special marker blocks in `.py`/`.pyi` files, guarded by `if TYPE_CHECKING:`.
- Replaces the hand-maintained `python/tvm_ffi/_ffi_api.pyi` stub file with auto-generated inline stubs in `_ffi_api.py`, and adds inline stubs to `access_path.py`, `module.py`, `testing.py`, and the packaging example.
- Removes `# type: ignore[attr-defined]` annotations throughout the codebase, as the generated stubs make dynamically-populated FFI attributes visible to type checkers.

## Key Exports

**CLI entry point**: `tvm-ffi-stubgen` (registered in `pyproject.toml` as `tvm_ffi.stub.stubgen:__main__`)

**Module**: `tvm_ffi.stub.stubgen`

**Classes**:
- `Options` -- dataclass holding CLI options: `dlls: list[str]`, `indent: int`, `files: list[str]`, `suppress_print: bool`
- `StubConfig` -- dataclass for per-block state: `name: str`, `indent: int`, `lineno: int`, `ty_map: dict[str, str]` (defaults: `list -> Sequence`, `dict -> Mapping`)

**Functions**:
- `__main__() -> int` -- CLI entry point; parses args, preloads DLLs, scans files, returns exit code
- `_main(file: Path, opt: Options, global_func_tab: dict | None) -> None` -- processes a single file
- `_compute_global_func_tab() -> dict[str, list[str]]` -- builds sorted prefix-to-function-names table from global registry
- `_generate_global(stub, global_func_tab, opt) -> list[str]` -- generates function stubs for `global/<prefix>` blocks
- `_generate_object(stub, opt) -> list[str]` -- generates field/method stubs for `object/<type_key>` blocks
- `_as_func_signature(schema: TypeSchema, func_name: str, ty_map) -> str` -- renders a function signature from TypeSchema
- `_filter_files(paths: list[Path]) -> list[Path]` -- recursively collects `.py`/`.pyi` files, sorted and deduplicated
- `_make_type_map(name_map: dict[str, str]) -> Callable[[str], str]` -- creates a type name mapper with last-segment fallback
- `_has_skip_file_marker(lines: list[str]) -> bool` -- checks for `# tvm-ffi-stubgen(skip-file)` directive

**Marker directives** (comment-based DSL):
- `# tvm-ffi-stubgen(begin): global/<prefix>` / `# tvm-ffi-stubgen(end)` -- global function stub block
- `# tvm-ffi-stubgen(begin): object/<type_key>` / `# tvm-ffi-stubgen(end)` -- object field/method stub block
- `# tvm-ffi-stubgen(ty_map): <from> -> <to>` -- per-block type name remapping
- `# tvm-ffi-stubgen(skip-file)` -- skip processing the entire file

**Constants**: `STUB_BEGIN`, `STUB_END`, `STUB_TY_MAP`, `STUB_SKIP_FILE`, `DEFAULT_SOURCE_EXTS`

## Impact
- API: Introduces a new public CLI tool `tvm-ffi-stubgen` and the `tvm_ffi.stub` subpackage. Existing code that used `_ffi_api.pyi` now gets stubs from inline blocks in `_ffi_api.py`. The `_ffi_api.pyi` file is deleted.
- ABI: none
- Behavioral: Generated stubs expose richer type signatures than the old hand-written `.pyi` (e.g., `ArrayGetItem(_0: Sequence[Any], _1: int, /) -> Any` vs the old `def ArrayGetItem(*args: Any) -> Any`). The `Module.get_write_formats()` return type changes from `list[str]` to `Sequence[str]` in the type annotation. `Module.get_function` now has a `cast(core.Function, func)` call.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces:
- **Inline stub generation pattern**: A new code generation approach where type stubs are embedded inline in `.py` files between marker comments, replacing separate `.pyi` stub files. Output is `if TYPE_CHECKING:`-guarded and deterministic.
- **Stub block directive DSL**: A lightweight comment-based directive language (`tvm-ffi-stubgen(begin/end/ty_map/skip-file)`) for controlling stub generation scope and type mappings.

## Usage Examples

### Generating stubs for global functions
**Context**: Adding inline type stubs to a module that uses `init_ffi_api`.
```python
# my_module/_ffi_api.py
from typing import TYPE_CHECKING
import tvm_ffi

tvm_ffi.init_ffi_api("my_prefix", __name__)

# tvm-ffi-stubgen(begin): global/my_prefix
# (auto-generated stubs will appear here after running tvm-ffi-stubgen)
# tvm-ffi-stubgen(end)
```
Then run:
```bash
tvm-ffi-stubgen my_module/_ffi_api.py
```
The block is filled with typed function stubs under `if TYPE_CHECKING:`.

### Generating stubs for object fields and methods with type mapping
**Context**: Adding inline type stubs to a registered object class.
```python
@register_object("testing.SchemaAllTypes")
class _SchemaAllTypes:
    # tvm-ffi-stubgen(begin): object/testing.SchemaAllTypes
    # tvm-ffi-stubgen(ty_map): testing.SchemaAllTypes -> _SchemaAllTypes
    # tvm-ffi-stubgen(end)
```
After running `tvm-ffi-stubgen`, the block is populated with field annotations (`v_int: int`, etc.) and method stubs (`def add_int(_0: _SchemaAllTypes, _1: int, /) -> int: ...`), with type names remapped per the `ty_map` directive.
