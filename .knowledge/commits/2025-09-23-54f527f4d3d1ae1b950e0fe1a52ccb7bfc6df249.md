# Add Array concatenation via `+` operator and widen constructor to accept Iterable
## TL;DR
- Adds `__add__` and `__radd__` dunder methods to `tvm_ffi.Array`, enabling `array1 + array2` concatenation that returns a new `Array`.
- Widens the `Array.__init__` parameter type from `Sequence[T]` to `Iterable[T]`, enabling construction from lazy iterators (needed by `itertools.chain` internally).
- Adds comprehensive parametrized tests covering Array+Array, Array+list, list+Array, Array+tuple, tuple+Array, and empty-array edge cases.

## Key Exports
**Methods (on `tvm_ffi.Array`):**

| Method | Signature | Description |
|--------|-----------|-------------|
| `__add__` | `(self, other: Iterable[T]) -> Array[T]` | Concatenate `self` with `other`, returning a new `Array` |
| `__radd__` | `(self, other: Iterable[T]) -> Array[T]` | Concatenate `other` with `self` (reflected), returning a new `Array` |

**Constructor change:**

| Before | After |
|--------|-------|
| `__init__(self, input_list: Sequence[T])` | `__init__(self, input_list: Iterable[T])` |

## Impact
- API: Additive only. `Array.__init__` now accepts any `Iterable`, which is a strict superset of the previous `Sequence` constraint. No existing callers break.
- ABI: none
- Behavioral: `Array([1,2]) + Array([3,4])` now works (previously raised `TypeError`). `[1,2] + Array([3,4])` also works via `__radd__`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`Array` Python wrapper** (`.knowledge/designs/containers.md`, "Python Container Wrappers" section): The `__add__`/`__radd__` implementations use `type(self)(itertools.chain(...))`, which delegates to the existing `__init__` -> `__init_handle_by_constructor__(_ffi_api.Array, *input_list)` path.
- **`collections.abc.Sequence` protocol** (`.knowledge/designs/0014-python-bindings.md`): The new operators make `Array` behave more like Python's built-in `list`, but `Array` does not (yet) implement the full `MutableSequence` protocol since it is immutable.
- **`itertools.chain`** (stdlib): Used to lazily concatenate iterables before unpacking into the FFI Array constructor.

Design elements this commit produces:
- **Array concatenation protocol**: `Array.__add__` and `__radd__` provide Pythonic `+` operator support. The implementation creates a new `Array` from the chained elements (not in-place mutation), consistent with immutable container semantics.
- **Iterable constructor widening**: `Array.__init__` now accepts any `Iterable[T]`, not just `Sequence[T]`. This is a prerequisite for `itertools.chain` usage and enables construction from generators.

## Usage Examples
**Array concatenation with `+` operator:**
```python
import tvm_ffi

a = tvm_ffi.Array([1, 2, 3])
b = tvm_ffi.Array([4, 5, 6])

# Array + Array
c = a + b
assert tuple(c) == (1, 2, 3, 4, 5, 6)

# Array + list
d = a + [4, 5, 6]
assert tuple(d) == (1, 2, 3, 4, 5, 6)

# list + Array (uses __radd__)
e = [1, 2, 3] + b
assert tuple(e) == (1, 2, 3, 4, 5, 6)
```
