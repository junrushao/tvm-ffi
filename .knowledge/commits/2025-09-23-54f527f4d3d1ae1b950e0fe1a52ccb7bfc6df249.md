# Add Array concatenation via `+` operator and widen `__init__` to accept Iterable
## TL;DR
- Adds `__add__` and `__radd__` dunder methods to `tvm_ffi.Array`, enabling concatenation with other `Array` instances, lists, and tuples via the `+` operator.
- Widens `Array.__init__` parameter type from `Sequence[T]` to `Iterable[T]`, allowing construction from any iterable (including `itertools.chain` results).
- Comprehensive parametrized tests cover Array+Array, Array+list, list+Array, empty arrays, and Array+tuple combinations.

## Key Exports
**Methods added to `tvm_ffi.Array`**:
```python
def __add__(self, other: Iterable[T]) -> Array[T]:
    """Concatenate self with other, returning a new Array."""

def __radd__(self, other: Iterable[T]) -> Array[T]:
    """Concatenate other with self, returning a new Array (enables list + Array)."""
```

**Signature change**:
```python
# Before
def __init__(self, input_list: Sequence[T]) -> None: ...
# After
def __init__(self, input_list: Iterable[T]) -> None: ...
```

## Impact
- API: New `+` operator support for `Array`. Non-breaking; existing callers are unaffected. The `__init__` parameter relaxation from `Sequence` to `Iterable` is backward-compatible.
- Behavioral: `Array` now supports concatenation. The result is always a new `Array` (preserves immutability semantics). `type(self)` is used to construct the result, preserving subclass identity.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`Array` (Python)**: The `ffi.Array` registered object class in `python/tvm_ffi/container.py`. See [0008-containers.md](../designs/0008-containers.md).
- **`_ffi_api.Array` constructor**: The C++ Array creation function, called via `__init_handle_by_constructor__`.
- **`collections.abc.Iterable`**: Newly imported to type the `__init__` and `__add__`/`__radd__` parameters.

Design elements this commit produces:
- **`Array.__add__` / `Array.__radd__`**: Python `+` operator support for Array concatenation. Uses `itertools.chain` for lazy element iteration, then constructs a new Array via `type(self)(...)`. This is a Python-only convenience -- the C++ `Array<T>` does not have a concatenation operator.

## Usage Examples
**Context**: Concatenating `tvm_ffi.Array` with other sequences using the `+` operator.
```python
import tvm_ffi

a = tvm_ffi.Array([1, 2, 3])
b = tvm_ffi.Array([4, 5, 6])

# Array + Array
c = a + b
assert tuple(c) == (1, 2, 3, 4, 5, 6)

# Array + list
c = a + [4, 5, 6]
assert tuple(c) == (1, 2, 3, 4, 5, 6)

# list + Array (uses __radd__)
c = [1, 2, 3] + b
assert tuple(c) == (1, 2, 3, 4, 5, 6)

# Array + tuple
c = a + (4, 5, 6)
assert tuple(c) == (1, 2, 3, 4, 5, 6)
```
