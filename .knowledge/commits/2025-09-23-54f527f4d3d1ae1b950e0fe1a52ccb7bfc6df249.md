# Add __add__/__radd__ concatenation operators to tvm_ffi.Array and widen __init__ to accept Iterable

## TL;DR
- `Array.__add__` and `Array.__radd__` added so `+` concatenation works between `Array` instances and any `Iterable` (list, tuple, generator, etc.).
- `Array.__init__` parameter type widened from `Sequence[T]` to `Iterable[T]`, enabling single-pass iterables as constructor input.
- Tests cover all symmetric combinations: Array+Array, Array+list, list+Array, Array+tuple, tuple+Array, with empty cases.

## Key Exports

```python
class Array(Object, Sequence[T]):
    def __init__(self, input_list: Iterable[T]) -> None: ...
    # Old: input_list: Sequence[T] -> New: input_list: Iterable[T]
    # Invariant: input_list is eagerly consumed at construction time
    #            via __init_handle_by_constructor__(_ffi_api.Array, *input_list)
    # Interacts with: _ffi_api.Array (C-level constructor), core.Object.__init_handle_by_constructor__

    def __add__(self, other: Iterable[T]) -> Array[T]: ...
    # Returns type(self)(itertools.chain(self, other))
    # Invariant: result type is type(self), preserving subclass identity
    # Interacts with: Python operator dispatch — called when left operand is Array

    def __radd__(self, other: Iterable[T]) -> Array[T]: ...
    # Returns type(self)(itertools.chain(other, self))
    # Interacts with: Python operator dispatch — called when left operand's __add__ returns NotImplemented
    #   (e.g., list.__add__(Array) fails; Python then calls Array.__radd__(list))
```

## Impact
- API: Adds `Array.__add__` and `Array.__radd__`; widens `Array.__init__` signature. No behavioral change to existing callers — `Sequence` is a subtype of `Iterable`.
- Behavioral: none to existing functionality; new concatenation operations produce a new `Array` object via `itertools.chain`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:

- `core.Object.__init_handle_by_constructor__` (0013-python-package) — used internally by `Array.__init__` to delegate to the C-level constructor.

Design elements this commit produces:
- `Array.__add__` / `Array.__radd__` — new Python dunder methods enabling `+` concatenation protocol on `Array`. Mutates `Array`'s API surface as documented in 0007-containers.
- `Array.__init__` signature widened: `Sequence[T]` → `Iterable[T]` (type-annotation-only widening).

## Usage Examples

Concatenating two `Array` objects or mixing with plain Python sequences:

```python
import tvm_ffi

a = tvm_ffi.Array([1, 2, 3])
b = tvm_ffi.Array([4, 5, 6])

# Array + Array
c = a + b           # tvm_ffi.Array([1, 2, 3, 4, 5, 6])

# Array + list (left operand determines result type)
c = a + [4, 5, 6]   # tvm_ffi.Array([1, 2, 3, 4, 5, 6])

# list + Array (triggers __radd__ on Array)
c = [1, 2, 3] + b   # tvm_ffi.Array([1, 2, 3, 4, 5, 6])

# Subclass identity preserved
class MyArray(tvm_ffi.Array): pass
ma = MyArray([1, 2])
result = ma + [3, 4]
assert type(result) is MyArray
```
