# Conditionally attach docstrings to reflected fields and methods only when a doc string is actually defined, fixing Sphinx autodoc conflict.

## TL;DR
- `TypeField.as_property()` and `TypeMethod.as_callable()` previously generated a fallback docstring (e.g. `"Property 'x' of class 'Foo'"`) when `self.doc` was empty; this conflicted with Sphinx autodoc which uses `__doc__ is None` to determine when to auto-generate documentation.
- The fix: only set `__doc__` (on the `property`, `fget`, `fset`, and the method callable) when `self.doc` is truthy; otherwise leave `__doc__` unset (`None`).
- `testing.cc` updated to provide explicit doc strings on `TestIntPairObj.a` / `.b` fields, and a new `test_attribute()` test verifies both value access and docstring propagation.

## Key Exports

```python
class TypeField:
    """Reflects a C++ ObjectDef field into Python."""
    doc: str  # May be empty string when no doc was registered in C++ reflection

    def as_property(self, cls: type) -> property:
        # OLD behavior: doc = self.doc or f"{cls.__module__}.{cls.__qualname__}.{name}"
        #               property.__doc__ always set; fget/fset.__doc__ always set
        # NEW behavior: property.__doc__, fget.__doc__, fset.__doc__ only set when self.doc is truthy
        # Interacts with: FieldGetter, FieldSetter (Cython extension types)
        # Invariant: if self.doc is falsy, the returned property has __doc__ == None (Sphinx can auto-fill)
        ...

class TypeMethod:
    """Reflects a C++ ObjectDef method into Python."""
    doc: str  # May be empty string when no doc was registered

    def as_callable(self, cls: type) -> callable:
        # OLD behavior: doc = self.doc or f"Method '{name}' of class '{cls.__qualname__}'"
        #               func.__doc__ always set
        # NEW behavior: func.__doc__ only set when self.doc is truthy
        # Interacts with: _member_method_wrapper (wraps non-static methods with self injection)
        # Invariant: static methods remain wrapped with staticmethod() regardless of doc presence
        ...
```

## Impact
- API: `TypeField.as_property()` and `TypeMethod.as_callable()` now return objects with `__doc__ = None` for undocumented C++ fields/methods, whereas previously they returned a synthetic fallback string. Any code testing `prop.__doc__ is not None` will observe changed behavior.
- Behavioral: Sphinx autodoc `.. autoclass::` directives will now correctly inherit or generate their own documentation for undocumented reflected fields/methods, rather than showing the synthetic fallback strings.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeField` / `TypeMethod` / `as_property()` / `as_callable()` — Cython-level Python wrappers over C++ reflection metadata. Defined in `python/tvm_ffi/cython/type_info.pxi`. Part of design record [0013-python-package](../design-records/0013-python-package.md).
- `ObjectDef<T>.def_ro(name, ptr, doc)` — C++ reflection builder for read-only fields, with optional doc-string argument. Part of design record [0006-reflection](../design-records/0006-reflection.md).

Design elements this commit produces:
- Tightened invariant on `TypeField.as_property()` and `TypeMethod.as_callable()`: **`__doc__` is only attached when `self.doc` is truthy.** This changes the observable contract of the TypeInfo system (0013-python-package) and is therefore a design element mutation.

## Usage Examples

Before (PR #49 behavior — generates fallback):
```python
# C++ side: .def_ro("a", &TestIntPairObj::a)  — no doc string
# Python side:
obj = tvm_ffi.testing.TestIntPair(3, 4)
type(obj).a.__doc__  # => "module.TestIntPair.a"  (synthetic fallback)
```

After (this fix — no fallback):
```python
# C++ side: .def_ro("a", &TestIntPairObj::a, "Field `a`")  — explicit doc
# Python side:
obj = tvm_ffi.testing.TestIntPair(3, 4)
assert obj.a == 3
assert type(obj).a.__doc__ == "Field `a`"  # only set when C++ registered a doc string

# C++ side: .def_ro("x", &FooObj::x)  — no doc string
type(obj_foo).x.__doc__  # => None  (Sphinx can now auto-generate)
```
