# Only attach docstring to reflected fields/methods when explicitly defined
## TL;DR
- Reverts the default docstring generation introduced in PR #49 (0048790) for `TypeField.as_property()` and `TypeMethod.as_callable()`. Fields and methods without an explicit docstring now have no `__doc__` attribute, instead of a synthetic one like `"Property \`a\` of class \`Foo\`"` or `"Method \`m\` of class \`Foo\`"`.
- The synthetic docstrings conflicted with upstream Sphinx `autodoc` generation, which interprets `__doc__` content as rST.
- Adds a test (`test_attribute`) verifying that fields with explicit docstrings (via `def_ro("a", &T::a, "Field \`a\`")`) still surface correctly.

## Key Exports

```python
class TypeField:
    """Reflected field descriptor."""
    name: str
    doc: Optional[str]
    # ...

    def as_property(self, cls: type) -> property:
        """Create a property for this field on cls.
        # Changed: no longer generates synthetic docstring when self.doc is None/empty.
        # Before: doc = self.doc or f"{cls.__module__}.{cls.__qualname__}.{name}"
        #         fget.__doc__ = fset.__doc__ = f"Property `{name}` of class `{cls.__qualname__}`"
        # After:  doc is only set on ret, fget, fset when self.doc is truthy.
        # Invariant: if self.doc is None/empty, property.__doc__ is None (Python default).
        # Interacts with: Sphinx autodoc (reads __doc__ for rST rendering)
        """
        ...

class TypeMethod:
    """Reflected method descriptor."""
    name: str
    doc: Optional[str]
    # ...

    def as_callable(self, cls: type) -> Callable:
        """Create a method attribute for this method on cls.
        # Changed: no longer generates synthetic docstring when self.doc is None/empty.
        # Before: doc = self.doc or f"Method `{name}` of class `{cls.__qualname__}`"
        #         func.__doc__ = doc
        # After:  func.__doc__ is only set when self.doc is truthy.
        # Invariant: if self.doc is None/empty, func.__doc__ is None (Python default).
        # Interacts with: Sphinx autodoc (reads __doc__ for rST rendering)
        """
        ...
```

## Impact
- API: None -- no public API signature changes.
- Behavioral: Fields/methods without C++-side docstrings no longer have `__doc__` set. Sphinx autodoc will no longer emit synthetic docstrings for undocumented reflected attributes. Code that relied on the synthetic `"Property ..."` / `"Method ..."` format will see `None` instead.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

Before/after pattern showing the behavioral change:

```python
# C++ side: field registered WITH explicit docstring
# refl::ObjectDef<TestIntPairObj>()
#     .def_ro("a", &TestIntPairObj::a, "Field `a`")

# Python: explicit docstring is preserved (unchanged behavior)
obj = tvm_ffi.testing.TestIntPair(3, 4)
assert type(obj).a.__doc__ == "Field `a`"  # works in both old and new

# C++ side: field registered WITHOUT docstring
# refl::ObjectDef<SomeObj>().def_ro("x", &SomeObj::x)

# Before (PR #49): synthetic docstring auto-generated
# type(obj).x.__doc__ == "Property `x` of class `SomeObj`"
# -> Sphinx autodoc rendered this as rST, causing formatting issues

# After (this commit): no docstring attached
# type(obj).x.__doc__ is None
# -> Sphinx autodoc uses its default behavior for undocumented attributes
```
