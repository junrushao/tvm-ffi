# Only attach docstring to reflected fields/methods when explicitly defined in C++ registration

## TL;DR
- Reverts default docstring generation in `TypeField.as_property()` and `TypeMethod.as_callable()` (introduced by PR #49) that conflicted with upstream Sphinx doc generation.
- Reflected fields and methods now only have `__doc__` set when the C++ reflection registration provides an explicit docstring string; otherwise `__doc__` is left unset (None).
- Adds explicit docstrings to `TestIntPair` fields in `testing.cc` and a new `test_attribute()` test verifying docstring propagation.

## Key Exports
None. No new public API surface; this is a behavioral fix to existing `TypeField.as_property()` and `TypeMethod.as_callable()`.

## Impact
- API: None -- method signatures unchanged.
- Behavioral: `property.__doc__`, `FieldGetter.__doc__`, `FieldSetter.__doc__`, and method `func.__doc__` are now `None` when C++ registration omits a docstring. Previously they had auto-generated fallback strings.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`0009-reflection.md`) -- `ObjectDef<T>.def_ro()` with optional docstring extra arg. The C++ side already supported optional docstrings; this commit aligns Python-side behavior.
- **Python dataclasses** (`0018-python-dataclasses.md`) -- `TypeField.as_property()` and `TypeMethod.as_callable()` methods that bridge C++ reflection data to Python property/method objects.

Design elements this commit produces:
- None. This commit restores and tightens an existing invariant rather than introducing new design elements.

## Usage Examples
**Before (incorrect)**: Even without a C++ docstring, Python reflected fields/methods had auto-generated `__doc__`:
```python
# C++: .def_ro("a", &TestIntPairObj::a)  -- no docstring
obj = tvm_ffi.testing.TestIntPair(3, 4)
type(obj).a.__doc__  # was "testing.TestIntPair.a" (auto-generated, conflicts with Sphinx)
```

**After (corrected)**: `__doc__` is only set when C++ provides an explicit docstring:
```python
# C++: .def_ro("a", &TestIntPairObj::a, "Field `a`")  -- explicit docstring
obj = tvm_ffi.testing.TestIntPair(3, 4)
type(obj).a.__doc__  # "Field `a`" (from C++ registration)

# C++: .def_ro("x", &FooObj::x)  -- no docstring
type(foo).x.__doc__  # None (not auto-generated)
```
