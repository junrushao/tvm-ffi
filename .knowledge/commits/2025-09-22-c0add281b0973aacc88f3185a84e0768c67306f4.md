# Fix device class override not taking effect in tvm_ffi.device() factory

## TL;DR
- `tvm_ffi.device()` was calling a stale `_CLASS_DEVICE` reference captured at import time, so `_set_class_device()` overrides had no effect on the factory function.
- Fix: change from `from .core import _CLASS_DEVICE` (import-time binding) to `core._CLASS_DEVICE` (call-time attribute lookup), so the factory always uses the current override.
- Adds unit tests for both device and tensor class override via `_set_class_device` / `_set_class_tensor`.

## Key Exports

```python
# No new exports -- this is a bugfix to existing behavior.

# Fixed function (python/tvm_ffi/_tensor.py):
def device(device_type: Union[str, int, DLDeviceType], index: Optional[int] = None) -> Device:
    """Construct a TVM FFI device."""
    # BEFORE (broken): return _CLASS_DEVICE(device_type, index)
    #   _CLASS_DEVICE was a local name bound at import time -- stale after override
    # AFTER  (fixed):  return core._CLASS_DEVICE(device_type, index)
    #   core._CLASS_DEVICE is looked up at call time -- picks up override
    # Interacts with: core._set_class_device(), core._CLASS_DEVICE (Cython global)
    # Invariant: core._CLASS_DEVICE is always a callable that returns a Device-compatible object
    ...
```

## Impact
- API: none -- no signature change
- Behavioral: `tvm_ffi.device()` now correctly returns an instance of the overridden device class after `_set_class_device()` is called. Previously, overrides were silently ignored.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`_CLASS_DEVICE` / `_set_class_device` class override pattern** (Cython global in `core`): A module-level variable that can be swapped to redirect device construction. Same pattern exists for `_CLASS_TENSOR` / `_set_class_tensor`. Documented in [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **`device()` factory function** (`_tensor.py`): Public entry point for constructing `Device` objects from string/int type + index.

Design elements this commit produces:
- None -- this is a bugfix restoring intended behavior, not a new design element.

## Usage Examples
Before/after pattern showing incorrect vs corrected usage:

```python
import tvm_ffi

# Define a custom device subclass
class MyDevice(tvm_ffi.Device):
    pass

# Override the device class
tvm_ffi.core._set_class_device(MyDevice)

# BEFORE fix: returns plain Device (override ignored)
# AFTER  fix: returns MyDevice (override respected)
d = tvm_ffi.device("cuda", 0)
assert isinstance(d, MyDevice)  # passes after fix, failed before

# Same pattern for tensor class override:
class MyTensor(tvm_ffi.Tensor):
    pass

tvm_ffi.core._set_class_tensor(MyTensor)
x = tvm_ffi.from_dlpack(some_dlpack_tensor)
assert isinstance(x, MyTensor)
```
