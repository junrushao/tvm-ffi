# Fix device() to use core._CLASS_DEVICE indirection so subclass overrides take effect

## TL;DR
- `device()` in `_tensor.py` imported `_CLASS_DEVICE` directly (binding the initial class value at import time), making `_set_class_device()` overrides invisible to callers of `device()`.
- Fix: change the import from `from .core import _CLASS_DEVICE` to `import core` and access `core._CLASS_DEVICE` at call time, so the mutable module attribute is always resolved dynamically.
- Added unit tests for both `Device` and `Tensor` class override patterns; bumped version `0.1.0b5` → `0.1.0b6`.

## Key Exports

```python
# No new exports. Existing function signature unchanged.

def device(device_type: Union[str, int, DLDeviceType], index: Optional[int] = None) -> Device:
    """Return a device handle, constructing via core._CLASS_DEVICE (dynamically resolved).

    # Invariant: core._CLASS_DEVICE must be set before first call; defaults to Device.
    # Interacts with: core._CLASS_DEVICE (module-level mutable), core._set_class_device()
    """
    # OLD (broken): captured _CLASS_DEVICE at import time via `from .core import _CLASS_DEVICE`
    # NEW (fixed):  return core._CLASS_DEVICE(device_type, index)
    ...

# Setter in device.pxi (unchanged by this commit, but now actually effective for device()):
def _set_class_device(cls) -> None:
    """Override the class used by device() and internal Cython constructors.
    # Invariant: cls must be a subclass of Device.
    # Interacts with: _CLASS_DEVICE (module global), Device.__new__ paths in device.pxi
    """
    ...
```

## Impact
- API: None — `device()` signature unchanged.
- Behavioral: `tvm_ffi.device(...)` now returns an instance of the overridden subclass when `_set_class_device()` has been called. Previously always returned the base `Device` class regardless of override.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `_CLASS_DEVICE` / `_set_class_device()` in `python/tvm_ffi/cython/device.pxi` — the class-override registration point for `Device`.
- `_CLASS_TENSOR` / `_set_class_tensor()` in `python/tvm_ffi/cython/tensor.pxi` — analogous override point for `Tensor` (tested but not broken by this commit).
- `0013-python-package` — Python package Cython binding layer.

Design elements this commit produces: None — restores an existing invariant only.

## Usage Examples

Before (broken): `device()` ignores override.
```python
# Subclass override was silently ignored
class MyDevice(tvm_ffi.Device):
    pass

tvm_ffi.core._set_class_device(MyDevice)
d = tvm_ffi.device("cuda", 0)
assert isinstance(d, MyDevice)   # FAILED — d was a plain Device
```

After (fixed):
```python
class MyDevice(tvm_ffi.Device):
    pass

old = tvm_ffi.core._CLASS_DEVICE
tvm_ffi.core._set_class_device(MyDevice)
d = tvm_ffi.device("cuda", 0)
assert isinstance(d, MyDevice)   # PASSES
tvm_ffi.core._set_class_device(old)  # restore
```

### Design docs / ADRs to write or update

This is the canonical override mechanism for downstream frameworks that subclass `Device` or `Tensor`.
