# Fix device/tensor class override by using module-level attribute access instead of local name binding
## TL;DR
- Fixed `tvm_ffi.device()` ignoring `_set_class_device()` overrides because `_CLASS_DEVICE` was imported as a local name binding in `_tensor.py`, which captured the value at import time rather than reading the current module-level variable.
- Changed `from .core import _CLASS_DEVICE` to `from . import core` and `core._CLASS_DEVICE(...)` so the attribute is resolved at call time, picking up any override set via `_set_class_device()`.
- Added unit tests for both device and tensor class override (`test_device_class_override`, `test_tensor_class_override`).
- Bumped version from `0.1.0b5` to `0.1.0b6`.

## Key Exports
None. No new public API surfaces were introduced. The fix corrects the runtime behavior of the existing `tvm_ffi.device()` function.

## Impact
- API: none -- `tvm_ffi.device()` signature unchanged; callers now correctly receive subclass instances when `_set_class_device()` has been called.
- ABI: none
- Behavioral: `tvm_ffi.device()` now returns the overridden class type (e.g., `MyDevice`) when `core._set_class_device(MyDevice)` has been called. Previously it always returned the original `Device` class regardless of override.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Class override pattern** (`core._CLASS_DEVICE` / `core._CLASS_TENSOR` + `_set_class_device` / `_set_class_tensor`): A module-level variable in `core` that acts as a factory for `Device` and `Tensor` instances. Downstream code (e.g., TVM proper) can override these to inject framework-specific subclasses. Documented in `.knowledge/designs/0014-python-bindings.md` (Object Type Registry section, extension points).
- **`tvm_ffi.device()` factory function** (`python/tvm_ffi/_tensor.py`): The public API for constructing `Device` instances by string or integer device type.

Design elements this commit produces:
- None. The commit restores the intended behavior of an existing design element rather than introducing new ones.

## Usage Examples
**Before (broken)**: `_tensor.py` imported `_CLASS_DEVICE` as a local binding. Override had no effect on `tvm_ffi.device()`:
```python
# _tensor.py (BEFORE)
from .core import _CLASS_DEVICE  # captured at import time

def device(device_type, index=None):
    return _CLASS_DEVICE(device_type, index)  # always original Device

# User code
class MyDevice(tvm_ffi.Device): pass
tvm_ffi.core._set_class_device(MyDevice)  # updates core._CLASS_DEVICE
d = tvm_ffi.device("cuda", 0)
assert isinstance(d, MyDevice)  # FAILS -- d is plain Device
```

**After (fixed)**: `_tensor.py` accesses `core._CLASS_DEVICE` at call time:
```python
# _tensor.py (AFTER)
from . import core

def device(device_type, index=None):
    return core._CLASS_DEVICE(device_type, index)  # reads current value

# User code
class MyDevice(tvm_ffi.Device): pass
tvm_ffi.core._set_class_device(MyDevice)
d = tvm_ffi.device("cuda", 0)
assert isinstance(d, MyDevice)  # PASSES
```
