# Log to stderr before throwing on duplicate global function registration via TVMFFIMethodInfo
## TL;DR
- Switches the duplicate-registration error in `GlobalFunctionTable::Update(const TVMFFIMethodInfo*, bool)` from `TVM_FFI_THROW` to `TVM_FFI_LOG_AND_THROW`, ensuring the error message is printed to stderr before the exception is thrown.
- Improves the error message with actionable diagnostic text explaining the likely cause (two `GlobalDef().def` registrations for the same function) and a remediation hint.

## Impact
- API: none -- no public API surface changes; this is an internal error path in `GlobalFunctionTable`.
- Flags/config: none.
- Data formats/schemas: none.
- Behavioral: Users who trigger duplicate registration via the `TVMFFIMethodInfo`-based path (typically from `GlobalDef().def` in C++ reflection registration) will now see the error logged to stderr in addition to the exception being thrown. This is important because duplicate registration typically happens during static initialization (shared library load), where exceptions may be swallowed or difficult to observe in some environments (e.g., Python import of a C extension).

## Design Elements
Design elements this commit **consumes**:

- **GlobalFunctionTable** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): The change modifies the `Update(const TVMFFIMethodInfo*, bool)` overload in `GlobalFunctionTable` at `src/ffi/function.cc:94-105`. This is the registration path used by `TVMFFIMethodInfo`-based reflection, as opposed to the `Update(const String&, Function, bool)` overload (line 85-92) which is used by `TVM_FFI_REGISTER_GLOBAL`.
- **TVM_FFI_LOG_AND_THROW macro** ([`.knowledge/designs/0007-error-handling.md`](../designs/0007-error-handling.md)): The macro at `include/tvm/ffi/error.h:400-403` creates an `ErrorBuilder` with the `log_before_throw` flag forced to `true`. This causes the error message to be flushed to stderr before the exception is thrown. By contrast, `TVM_FFI_THROW` uses `TVM_FFI_ALWAYS_LOG_BEFORE_THROW` (a compile-time flag, typically `false`).
- **Duplicate registration invariant** ([`.knowledge/ADRs/0004-global-function-table-leak.md`](../ADRs/0004-global-function-table-leak.md)): The invariant that each global function name is unique (unless `can_override` is true) is enforced by this code path. The commit does not change the invariant -- it only improves the error reporting when the invariant is violated.

Design elements this commit **produces**:

- None. This commit does not introduce new design elements. It is a diagnostic improvement to an existing invariant enforcement path.

## Key Implementations

**Changed function**: `GlobalFunctionTable::Update(const TVMFFIMethodInfo*, bool)` at `src/ffi/function.cc:94-105`.

The behavioral change is:
1. `TVM_FFI_THROW(RuntimeError)` replaced with `TVM_FFI_LOG_AND_THROW(RuntimeError)` -- forces stderr logging before throw.
2. Error message expanded from a terse single-line message (`"Global Function 'X' is already registered"`) to a multi-line diagnostic with cause enumeration and remediation advice.

**Asymmetry note**: The other `Update` overload (`Update(const String&, Function, bool)` at line 85-92) still uses `TVM_FFI_THROW` with the old terse message. This asymmetry is intentional: the `TVMFFIMethodInfo` path is used during static initialization (via `GlobalDef().def`), where exceptions are more likely to be swallowed. The `String`-based path is typically called at runtime (via `Function::SetGlobal` or `TVM_FFI_REGISTER_GLOBAL.set_body_*`), where exception propagation works normally.

**Invariants assumed**: The name uniqueness invariant is unchanged. `can_override == false` means the caller explicitly expects no prior registration.

**Extension point**: If additional causes of duplicate registration emerge (e.g., shared library loaded twice, or two different compilation units defining the same reflected function), the error message can be extended with more bullet points.
