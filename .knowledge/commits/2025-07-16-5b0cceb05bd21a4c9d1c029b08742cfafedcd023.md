# Improve duplicate global function registration error message with logging

## TL;DR
- `GlobalFunctionTable::Set` now uses `TVM_FFI_LOG_AND_THROW` instead of `TVM_FFI_THROW` when a duplicate function name is registered with `can_override=false`.
- The error message is expanded to list a likely cause ("Two `GlobalDef().def` registrations") and a remediation hint ("Please remove the duplicate registration.").
- No API or ABI changes; behavior is identical except that stderr now receives the error message before the exception is thrown.

None

## Impact
- API: none
- Behavioral: duplicate global function registration now logs to stderr before throwing `RuntimeError`. Error message is more descriptive than the prior single-line message.
- Flags/config: none

## Usage Examples

Before (incorrect — silent duplicate registration detection):
```cpp
// Duplicate registration raises RuntimeError with terse message:
// "Global Function `my.func` is already registered"
// (no stderr output)
TVM_FFI_REGISTER_GLOBAL("my.func").set_body(...);
TVM_FFI_REGISTER_GLOBAL("my.func").set_body(...);  // throws silently
```

After (improved diagnostics):
```cpp
// Now logs to stderr then throws RuntimeError with actionable message:
// "Global Function `my.func` is already registered, possible causes:
//  - Two GlobalDef().def registrations for the same function
//  Please remove the duplicate registration."
TVM_FFI_REGISTER_GLOBAL("my.func").set_body(...);
TVM_FFI_REGISTER_GLOBAL("my.func").set_body(...);  // logs + throws
```
