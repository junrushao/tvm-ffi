# Introduce __tvm_ffi_tensor__ protocol for fast tensor extraction from wrapper objects
## TL;DR
- Adds `__tvm_ffi_tensor__` protocol: any Python class implementing `__tvm_ffi_tensor__() -> tvm_ffi.Tensor` can be passed directly to FFI function calls, bypassing DLPack overhead.
- New Cython setter `TVMFFIPyArgSetterFFITensorCompatible_` handles the conversion with ref-count-aware temporary lifetime management.
- Protocol check is inserted in `TVMFFIPyArgSetterFactory_` after `ObjectRValueRef` but before DLPack-based checks, prioritizing direct handle extraction over DLPack exchange.

## Impact
- API: New duck-type protocol `__tvm_ffi_tensor__` -- additive only, no existing callers broken.
- Behavioral: Objects implementing the protocol are now auto-converted to `kTVMFFITensor` during FFI calls instead of falling through to DLPack or fallback paths.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Wrapping `tvm_ffi.Tensor` in a custom class and passing it through FFI calls:
```python
import tvm_ffi
import numpy as np

class MyTensor:
    def __init__(self, tensor: tvm_ffi.Tensor) -> None:
        self._tensor = tensor

    def __tvm_ffi_tensor__(self) -> tvm_ffi.Tensor:
        return self._tensor

data = np.zeros((10, 8, 4, 2), dtype="int32")
x = tvm_ffi.from_dlpack(data)
y = MyTensor(x)
fecho = tvm_ffi.get_global_func("testing.echo")
z = fecho(y)  # y auto-converted via __tvm_ffi_tensor__ protocol
assert z.__chandle__() == x.__chandle__()
```
