# Allow CUDA-only load_inline without cpp_sources forward declarations
## TL;DR
- Relaxes the invariant that CUDA functions must have forward declarations in `cpp_sources`. When `cpp_sources` is not provided (or empty), `TVM_FFI_DLL_EXPORT_TYPED_FUNC` decorations are applied to `cuda_sources` instead.
- Adds a `with_cpp` flag to route function export decorations to the correct source file based on which source type is present.
- Updates the CUDA test to use `cuda_sources` only, without a `cpp_sources` forward declaration.

## Key Exports
No new public API symbols. The change is to the internal routing logic within `load_inline()`.

```python
def load_inline(
    name: str,
    *,
    cpp_sources: str | Sequence[str] | None = None,
    cuda_sources: str | Sequence[str] | None = None,
    functions: Sequence[str] | Mapping[str, str] | str | None = None,
    # ... other params unchanged ...
) -> Module: ...
    # Changed behavior: `functions` export decorations are now routed conditionally:
    #   if cpp_sources provided  -> cpp_source gets exports, cuda_source gets none (unchanged)
    #   if cpp_sources NOT provided -> cuda_source gets exports, cpp_source gets none (NEW)
    # Interacts with: _decorate_with_tvm_ffi(), TVM_FFI_DLL_EXPORT_TYPED_FUNC macro
    # Invariant (updated): exactly one of cpp_source/cuda_source receives function export
    #   decorations, determined by `with_cpp = len(cpp_sources) > 0`
    # Extension: same pattern could be extended for other source languages (HIP, SYCL)
```

## Impact
- API: None -- backward-compatible. Existing callers providing both `cpp_sources` and `cuda_sources` are unaffected (routing still sends exports to `cpp_source`).
- Behavioral: CUDA-only modules can now export functions directly without requiring a `cpp_sources` forward declaration. The `functions` parameter docstring now documents that functions "must be defined in the cuda_sources" when `cpp_sources` is not given.
- Flags/config: None
- Data formats/schemas: None

## Usage Examples
CUDA-only module (new pattern enabled by this commit):
```python
from tvm_ffi.cpp import load_inline

mod = load_inline(
    name="cuda_add",
    cuda_sources=r"""
        __global__ void kernel(float* x, float* y, int n) {
          int i = blockIdx.x * blockDim.x + threadIdx.x;
          if (i < n) y[i] = x[i] + 1;
        }
        void add_one_cuda(DLTensor* x, DLTensor* y) {
          int n = x->shape[0];
          kernel<<<(n+255)/256, 256>>>(
              static_cast<float*>(x->data), static_cast<float*>(y->data), n);
        }
    """,
    functions=["add_one_cuda"],  # exported directly from cuda_sources
)
```

Before this commit, the same function required a `cpp_sources` forward declaration:
```python
mod = load_inline(
    name="cuda_add",
    cpp_sources="void add_one_cuda(DLTensor* x, DLTensor* y);",  # was required
    cuda_sources=r"""...""",
    functions=["add_one_cuda"],
)
```
