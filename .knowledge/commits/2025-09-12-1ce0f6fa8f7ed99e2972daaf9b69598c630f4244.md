# Fix load_inline to export functions from cuda_sources when no cpp_sources provided
## TL;DR
- Previously, `load_inline` always placed `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macros in the C++ source, even when functions were defined only in CUDA sources. This meant CUDA-only modules required a dummy `cpp_sources` with forward declarations.
- The fix introduces a `with_cpp` flag: when `cpp_sources` is non-empty, function exports go into `cpp_source`; otherwise, they go into `cuda_source`.
- The `test_load_inline_cuda` test is simplified to remove the now-unnecessary C++ forward declaration.

## Key Exports

No new public API. Behavioral change to existing `load_inline` internals.

```python
def load_inline(
    name: str,
    *,
    cpp_sources: Sequence[str] | str | None = None,
    cuda_sources: Sequence[str] | str | None = None,
    functions: Mapping[str, str] | Sequence[str] | str | None = None,
    # ... other params unchanged
) -> Module:
    # CHANGED: function export routing logic
    # Old: _decorate_with_tvm_ffi(cpp_source, functions) always; cuda_source got empty {}
    # New: if with_cpp: exports go to cpp_source; else: exports go to cuda_source
    # Invariant: TVM_FFI_DLL_EXPORT_TYPED_FUNC macros are emitted into the source
    #   that defines/declares the exported functions
    # Interacts with: _decorate_with_tvm_ffi (emits export macros)
    # Interacts with: TVM_FFI_DLL_EXPORT_TYPED_FUNC (C++ macro in the compiled source)
```

## Impact
- API: none -- no signature changes, existing callers unaffected
- Behavioral: CUDA-only `load_inline` calls no longer require a `cpp_sources` with forward declarations. Functions can now be exported directly from `cuda_sources` when `cpp_sources` is omitted or empty.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `_decorate_with_tvm_ffi` helper -- prepends TVM FFI headers and appends `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macros for each function ([0011-module-system.md](../designs/0011-module-system.md))
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` C++ macro -- emits `extern "C"` symbol with `__tvm_ffi_` prefix ([0011-module-system.md](../designs/0011-module-system.md))

Design elements this commit produces:
- None -- this is a bugfix to existing routing logic.

## Usage Examples

**Before (required dummy cpp_sources for CUDA-only module):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cuda(DLTensor* x, DLTensor* y);  # forward decl required
    """,
    cuda_sources=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) { ... }
        void add_one_cuda(DLTensor* x, DLTensor* y) { ... }
    """,
    functions=["add_one_cuda"],
)
```

**After (CUDA-only, no cpp_sources needed):**
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_sources=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) { ... }
        void add_one_cuda(DLTensor* x, DLTensor* y) { ... }
    """,
    functions=["add_one_cuda"],
)
```
