# Allow load_inline to register functions in cuda_sources when no cpp_sources given
## TL;DR
- `load_inline` now routes `functions` exports to `cuda_sources` when `cpp_sources` is empty, removing the requirement for a C++ forward-declaration wrapper when writing CUDA-only modules.
- The test `test_load_inline_cuda` drops its `cpp_sources` argument to exercise the new CUDA-only path.

## Key Exports

```python
def load_inline(
    name: str,
    *,
    cpp_sources: str | Sequence[str] | None = None,
    cuda_sources: str | Sequence[str] | None = None,
    functions: Sequence[str] | Mapping[str, str] | str | None = None,
    # ... remaining params unchanged
) -> Module:
    """Compile and load a C++/CUDA tvm_ffi module from inline source code."""
    # Interacts with: _decorate_with_tvm_ffi (routes function dict to the active source layer)
    # Interacts with: load_module (python/tvm_ffi/module.py) for final library load
    # Invariant (CHANGED): functions are registered in cpp_sources when cpp_sources is
    #   non-empty; otherwise registered in cuda_sources. Exactly one source layer gets
    #   the functions dict; the other gets an empty dict.
    # Invariant (NEW): with_cpp = len(cpp_sources) > 0 determines the routing target
    ...
```

## Impact
- API: None -- existing callers with `cpp_sources` see identical behavior.
- Behavioral: CUDA-only callers no longer need a `cpp_sources` forward declaration. `_decorate_with_tvm_ffi` now appends `TVM_FFI_DLL_EXPORT_TYPED_FUNC` calls to the CUDA source when `cpp_sources` is absent.
- Flags/config: None.
- Data formats/schemas: None.

Design elements this commit consumes:

## Usage Examples
CUDA-only module without cpp_sources (the new pattern enabled by this commit):
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_sources=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) {
            int idx = blockIdx.x * blockDim.x + threadIdx.x;
            if (idx < n) y[idx] = x[idx] + 1;
        }
        void add_one_cuda(DLTensor* x, DLTensor* y) {
            int n = x->shape[0];
            AddOneKernel<<<(n+255)/256, 256>>>(
                static_cast<float*>(x->data), static_cast<float*>(y->data), n);
        }
    """,
    functions=["add_one_cuda"],  # registered directly in cuda_sources
)
```

Before this commit, the same CUDA function required a redundant `cpp_sources` forward declaration:
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources="void add_one_cuda(DLTensor* x, DLTensor* y);",  # was required
    cuda_sources=r"""...""",
    functions=["add_one_cuda"],
)
```
