# Allow load_inline to export functions from CUDA-only sources without requiring cpp_sources

## TL;DR
- Fixes `tvm_ffi.cpp.load_inline` so that when only `cuda_sources` is provided (no `cpp_sources`), `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macros are emitted in the CUDA source file instead of the (empty) C++ source file.
- Previously, the `functions` parameter's export macros were always placed in `main.cpp` regardless of whether any C++ source was provided, causing CUDA-only modules to fail to export functions.
- Updates the test `test_load_inline_cuda` to remove the previously-required `cpp_sources` forward declaration stub.

## Key Exports
None -- no new public API surface. The `tvm_ffi.cpp.load_inline()` signature is unchanged. The behavioral fix is internal to how `_decorate_with_tvm_ffi` is dispatched.

## Impact
- API: None -- `load_inline()` signature and parameter types are unchanged.
- Behavioral: When `cpp_sources` is not provided (or empty) and `cuda_sources` is provided, export macros (`TVM_FFI_DLL_EXPORT_TYPED_FUNC`) are now emitted in the `cuda.cu` file instead of the `main.cpp` file. Previously, CUDA-only callers had to provide a forward declaration in `cpp_sources` for the function to be exported.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Inline module compilation workflow** ([0014-python-package.md](../designs/0014-python-package.md), extension points section): Uses the existing Ninja-based build pipeline, `_decorate_with_tvm_ffi`, and `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro mechanism.
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): The loaded `.so` is consumed via `load_module` which wraps it in `LibraryModuleObj`.

Design elements this commit produces:
- **`with_cpp` dispatch logic**: Introduces a `with_cpp = len(cpp_sources) > 0` flag that determines which source file receives the function export macros. This is a new internal invariant: export macros go to `cpp_source` when C++ sources are present, otherwise to `cuda_source`.

## Usage Examples

**Before (broken CUDA-only pattern)**: Required a dummy `cpp_sources` with forward declarations.
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_sources=r"""
        void add_one_cuda(DLTensor* x, DLTensor* y);
    """,
    cuda_sources=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) { ... }
        void add_one_cuda(DLTensor* x, DLTensor* y) { AddOneKernel<<<...>>>(...); }
    """,
    functions=["add_one_cuda"],
)
```

**After (corrected CUDA-only pattern)**: No `cpp_sources` needed; export macros go into `cuda.cu`.
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_sources=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) { ... }
        void add_one_cuda(DLTensor* x, DLTensor* y) { AddOneKernel<<<...>>>(...); }
    """,
    functions=["add_one_cuda"],
)
```
