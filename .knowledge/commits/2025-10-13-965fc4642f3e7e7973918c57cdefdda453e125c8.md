# Add inline C++ tests validating PyTorch DLPackExchangeAPI struct protocol
## TL;DR
- Adds `tests/python/test_dlpack_exchange_api.py` with comprehensive inline C++ tests validating all 5 function pointers in PyTorch's `DLPackExchangeAPI` struct (`managed_tensor_allocator`, `managed_tensor_from_py_object_no_sync`, `managed_tensor_to_py_object_no_sync`, `dltensor_from_py_object_no_sync`, `current_work_stream`).
- Fixes `__dlpack_version__` in `tensor.pxi` to derive from C-level `DLPACK_MAJOR_VERSION`/`DLPACK_MINOR_VERSION` constants instead of hardcoded `(1, 1)`.

## Key Exports
None -- this commit adds tests only. The minor `tensor.pxi` fix changes initialization but not the public symbol.

## Impact
- API: none
- Behavioral: `__dlpack_version__` now tracks the C header constants automatically. Previously hardcoded to `(1, 1)`, now resolves to `(DLPACK_MAJOR_VERSION, DLPACK_MINOR_VERSION)` at Cython compile time. This is a correctness fix -- if the vendored DLPack header is bumped, the Python-visible version tuple will follow.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPackExchangeAPI struct** (`dlpack/dlpack.h`): The C struct-based protocol for fast tensor exchange. The test validates its `header.version`, and all 5 function pointers. Not yet documented in `.knowledge/designs/`.
- **`torch.Tensor.__c_dlpack_exchange_api__`** dunder attribute: Set by `_optional_torch_c_dlpack.py` at import time via `load_inline` JIT compilation. Documented in `.knowledge/designs/0012-python-bindings.md` (line 37).
- **`torch.utils.cpp_extension.load_inline`**: Used to compile inline C++ that calls `THPVariable_Wrap`/`THPVariable_Unpack` directly, avoiding GIL release issues that ctypes-based tests would face.
- **`tvm_ffi.libinfo.include_paths()`**: Provides paths to vendored `dlpack/dlpack.h` header for the inline compilation.
- **`DLPACK_MAJOR_VERSION`/`DLPACK_MINOR_VERSION`** Cython extern constants (`base.pxi` line 28-29): C-level version constants from `dlpack/dlpack.h`, now used to derive `__dlpack_version__`.

Design elements this commit produces:
- None (test-only commit).

## Usage Examples
The test itself serves as a usage example for validating the DLPackExchangeAPI. Key pattern -- accessing the API pointer and exercising it from inline C++:

```python
import torch
import tvm_ffi  # triggers __c_dlpack_exchange_api__ registration on torch.Tensor

api_ptr = torch.Tensor.__c_dlpack_exchange_api__  # int (raw pointer)
tensor = torch.arange(24, dtype=torch.float32).reshape(2, 3, 4)

# Inline C++ validates the struct via torch.utils.cpp_extension.load_inline
# Each API function pointer is called and its return values are checked:
#   api->managed_tensor_allocator(&prototype, &out, nullptr, nullptr)
#   api->managed_tensor_from_py_object_no_sync(py_obj, &out)
#   api->managed_tensor_to_py_object_no_sync(managed, &py_obj_out)
#   api->dltensor_from_py_object_no_sync(py_obj, &dltensor)
#   api->current_work_stream(device_type, device_id, &stream_out)
```
