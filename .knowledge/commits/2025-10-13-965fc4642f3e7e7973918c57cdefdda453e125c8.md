# Add inline C++ tests validating PyTorch's DLPackExchangeAPI struct-based fast tensor exchange protocol
## TL;DR
- Adds a new test file `tests/python/test_dlpack_exchange_api.py` containing comprehensive C++ inline tests that validate all 5 function pointers in PyTorch's `DLPackExchangeAPI` struct (`managed_tensor_allocator`, `managed_tensor_from_py_object_no_sync`, `managed_tensor_to_py_object_no_sync`, `dltensor_from_py_object_no_sync`, `current_work_stream`).
- Fixes `__dlpack_version__` in `tensor.pxi` to use `DLPACK_MAJOR_VERSION`/`DLPACK_MINOR_VERSION` C constants instead of hardcoded `(1, 1)`, preventing version drift.

None (test-only commit with a minor constant fix)

- API: none
- Behavioral: `__dlpack_version__` now dynamically derives from DLPack C header constants instead of hardcoded values; no user-visible change unless the DLPack vendored header is updated.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack exchange protocol** (0012-python-bindings, 0013-load-inline): Tests the `DLPackExchangeAPI` struct established by `_optional_torch_c_dlpack.py` and `torch.Tensor.__c_dlpack_exchange_api__`. The test accesses the API pointer, then calls all 5 functions from inline C++.
- **`torch.utils.cpp_extension.load_inline`** (0013-load-inline): Uses PyTorch's inline C++ compilation to build a test extension that exercises the API, avoiding GIL release issues that occur with ctypes-based testing (since `THPVariable_Wrap` requires the GIL).
- **`tvm_ffi.libinfo.include_paths()`** (0012-python-bindings): Provides DLPack and TVM FFI include paths for the inline C++ compilation.
- **DLPack versioned tensor format** (0006-containers, 0007-c-abi): Tests validate `DLManagedTensorVersioned` fields (version, ndim, shape, dtype, device, data pointer).

Design elements this commit produces:
- None (test-only)

## Usage Examples

The test demonstrates how to validate the `DLPackExchangeAPI` protocol from inline C++:

```python
# Get the API pointer from the class-level dunder attribute
api_ptr = torch.Tensor.__c_dlpack_exchange_api__

# Compile inline C++ that reinterprets the pointer and calls API functions
source = """
#include <torch/extension.h>
#include <dlpack/dlpack.h>

void test_dlpack_api(at::Tensor tensor, int64_t api_ptr_int, bool cuda_available) {
    DLPackExchangeAPI* api = reinterpret_cast<DLPackExchangeAPI*>(api_ptr_int);
    // Test managed_tensor_allocator: allocate a new tensor via prototype
    DLManagedTensorVersioned* out = nullptr;
    int result = api->managed_tensor_allocator(&prototype, &out, nullptr, nullptr);
    // Test managed_tensor_from_py_object_no_sync: convert PyObject* -> DLManagedTensorVersioned*
    PyObject* py_obj = THPVariable_Wrap(tensor);
    result = api->managed_tensor_from_py_object_no_sync(py_obj, &out);
    // ... and so on for all 5 API functions
}
"""
mod = cpp_extension.load_inline(
    name="dlpack_test", cpp_sources=[source],
    functions=["test_dlpack_api"],
    extra_include_paths=libinfo.include_paths(),
)
mod.test_dlpack_api(tensor, api_ptr, torch.cuda.is_available())
```
