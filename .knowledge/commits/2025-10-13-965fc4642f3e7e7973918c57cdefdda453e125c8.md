# Add inline C++ tests for DLPackExchangeAPI protocol and fix hardcoded dlpack version
## TL;DR
- Adds comprehensive inline C++ tests for `torch.Tensor.__c_dlpack_exchange_api__` validating all 5 function pointers in the `DLPackExchangeAPI` struct (allocator, from/to PyObject, dltensor view, stream query).
- Fixes `__dlpack_version__` in `tensor.pxi` from hardcoded `(1, 1)` to `(DLPACK_MAJOR_VERSION, DLPACK_MINOR_VERSION)`, sourced from the `dlpack.h` header constants.

## Key Exports
None -- this commit adds tests only. No new public API surface.

The test exercises the existing `DLPackExchangeAPI` struct protocol:

```python
# Test validates all 5 function pointers in DLPackExchangeAPI:
#   api.managed_tensor_allocator(prototype, &out, nullptr, nullptr)
#   api.managed_tensor_from_py_object_no_sync(py_obj, &out)
#   api.managed_tensor_to_py_object_no_sync(managed, &out)
#   api.dltensor_from_py_object_no_sync(py_obj, &dltensor)
#   api.current_work_stream(device_type, device_id, &stream)
# Interacts with: torch.Tensor.__c_dlpack_exchange_api__, DLPackExchangeAPI (dlpack.h)
# Interacts with: torch.utils.cpp_extension.load_inline, tvm_ffi.libinfo.include_paths()
```

## Impact
- API: none
- Behavioral: `__dlpack_version__` now tracks `dlpack.h` constants instead of being hardcoded. Previously a submodule bump that changed DLPack version would silently desync from the Python-reported version.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`DLPackExchangeAPI` struct** -- the C-level exchange protocol with 5 function pointers and versioned header, introduced in commit `22a78943` (PR #96). See [0012-ffi-python-package](../design-records/0012-ffi-python-package.md).
- **`__c_dlpack_exchange_api__` class attribute protocol** -- set on `torch.Tensor` at `tvm_ffi` import time, pointing to a static `DLPackExchangeAPI` instance.
- **`torch.utils.cpp_extension.load_inline`** -- used instead of ctypes to avoid GIL release issues when calling `THPVariable_Wrap`.
- **`tvm_ffi.libinfo.include_paths()`** -- provides include paths for the DLPack headers needed by the inline C++ compilation.
- **`DLPACK_MAJOR_VERSION` / `DLPACK_MINOR_VERSION`** -- C constants from `dlpack.h`, now used in `tensor.pxi` via Cython `cdef extern`.

Design elements this commit produces: none

## Usage Examples
Test validates the DLPackExchangeAPI round-trip (Python -> inline C++ -> torch C API):

```python
# Python test driver
api_ptr = torch.Tensor.__c_dlpack_exchange_api__  # int ptr set by tvm_ffi
tensor = torch.arange(24, dtype=torch.float32).reshape(2, 3, 4)

mod = cpp_extension.load_inline(
    name="dlpack_test",
    cpp_sources=[C_SOURCE_WITH_TORCH_CHECK_ASSERTIONS],
    functions=["test_dlpack_api"],
    extra_include_paths=libinfo.include_paths(),
)
mod.test_dlpack_api(tensor, api_ptr, torch.cuda.is_available())
```

The inline C++ code validates: (1) API version matches `DLPACK_MAJOR/MINOR_VERSION`, (2) allocator creates tensors from prototypes, (3) `managed_tensor_from_py_object_no_sync` extracts `DLManagedTensorVersioned` from PyTorch tensor, (4) `managed_tensor_to_py_object_no_sync` round-trips back to `torch.Tensor`, (5) `dltensor_from_py_object_no_sync` gets a non-owning `DLTensor` view, (6) `current_work_stream` returns without error.
