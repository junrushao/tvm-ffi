# Add inline C++ tests validating PyTorch's DLPackExchangeAPI struct protocol
## TL;DR
- Adds `tests/python/test_dlpack_exchange_api.py` with comprehensive inline C++ tests exercising all 5 function pointers in PyTorch's `DLPackExchangeAPI` struct: `managed_tensor_allocator`, `managed_tensor_from_py_object_no_sync`, `managed_tensor_to_py_object_no_sync`, `dltensor_from_py_object_no_sync`, and `current_work_stream`.
- Fixes the hardcoded `__dlpack_version__ = (1, 1)` in `tensor.pxi` to use `(DLPACK_MAJOR_VERSION, DLPACK_MINOR_VERSION)` from the vendored dlpack.h header, ensuring the version stays in sync with the C library.

## Key Exports
None -- this commit adds only tests and a minor constant fix.

## Impact
- API: none.
- ABI: none.
- Behavioral: `__dlpack_version__` in the Cython tensor module was previously hardcoded to `(1, 1)` and now derives from the C header macros. If the vendored dlpack is upgraded, the Python-side version will automatically track it.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- `.knowledge/designs/0018-dlpack-fast-path.md` -- the `DLPackExchangeAPI` struct-based fast exchange protocol. The test exercises every function pointer in the struct as exposed by PyTorch's implementation via `__c_dlpack_exchange_api__`.
- `torch.utils.cpp_extension.load_inline` -- used to compile inline C++ test code that calls into the `DLPackExchangeAPI` struct directly (avoiding GIL issues with `THPVariable_Wrap` that ctypes-based tests would encounter).
- `tvm_ffi.libinfo.include_paths()` -- provides the include paths to `dlpack/dlpack.h` needed by the inline C++ extension.

Design elements this commit produces:
- Test pattern for validating `DLPackExchangeAPI` implementations: compile inline C++ via `torch.utils.cpp_extension.load_inline`, cast the API pointer from the class attribute, and exercise each function pointer with `TORCH_CHECK` assertions.

## Usage Examples
The test itself serves as the canonical usage example for validating a `DLPackExchangeAPI` implementation from C++:

```python
# Retrieve the API struct pointer from the class attribute
api_ptr = torch.Tensor.__c_dlpack_exchange_api__

# Pass it to inline C++ that casts and validates each function pointer
mod = cpp_extension.load_inline(
    name="dlpack_test",
    cpp_sources=[source],  # C++ code using DLPackExchangeAPI*
    functions=["test_dlpack_api"],
    extra_include_paths=libinfo.include_paths(),
)
mod.test_dlpack_api(tensor, api_ptr, torch.cuda.is_available())
```

Within the C++ code, the six test sections validate:
1. Struct version matches `DLPACK_MAJOR_VERSION`/`DLPACK_MINOR_VERSION` and all function pointers are non-null.
2. `managed_tensor_allocator` creates a tensor matching a prototype's shape/dtype/device.
3. `managed_tensor_from_py_object_no_sync` exports a `torch.Tensor` PyObject to `DLManagedTensorVersioned`.
4. `managed_tensor_to_py_object_no_sync` round-trips back to a `torch.Tensor` PyObject.
5. `dltensor_from_py_object_no_sync` exports a lightweight `DLTensor` view (no ownership transfer).
6. `current_work_stream` returns a valid stream handle for CPU or CUDA.
