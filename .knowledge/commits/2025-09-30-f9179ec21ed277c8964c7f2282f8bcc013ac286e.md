# Explicitly zero TVMFFIObject.__padding at allocation time in ObjAllocatorBase

## TL;DR
- Adds `ffi_ptr->__padding = 0;` in both `ObjAllocatorBase::make_object<T>` and `make_inplace_array<ArrayType>` immediately after setting `type_index`.
- Ensures every heap-allocated `TVMFFIObject` has deterministic, zero-valued padding bytes at construction, regardless of heap allocator or platform.
- No functional change for existing code paths; purely a memory-determinism / safety hardening fix.

## Key Exports

None

## Impact
- API: none
- Behavioral: `TVMFFIObject.__padding` is now always 0 after construction via `make_object` or `make_inplace_array`. Previously it could hold uninitialized heap garbage.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIObject.__padding` (uint32, offset 12) — documented in `0001-c-abi` and `0002-object-system` as explicit alignment padding between `type_index` and the `deleter` pointer.
- `ObjAllocatorBase` (template CRTP base in `include/tvm/ffi/memory.h`) — the single allocation chokepoint for all `make_object<T>` and `make_inplace_array<T>` calls.

Design elements this commit produces: none

## Usage Examples

Before (implicit — padding field was left uninitialized after allocation):
```cpp
// ObjAllocatorBase::make_object() prior to this commit:
ffi_ptr->combined_ref_count = kCombinedRefCountBothOne;
ffi_ptr->type_index = T::RuntimeTypeIndex();
// ffi_ptr->__padding  <-- uninitialized heap bytes
ffi_ptr->deleter = Handler::Deleter();
```

After (explicit zero):
```cpp
ffi_ptr->combined_ref_count = kCombinedRefCountBothOne;
ffi_ptr->type_index = T::RuntimeTypeIndex();
ffi_ptr->__padding = 0;   // deterministic, matches ABI intent
ffi_ptr->deleter = Handler::Deleter();
```
