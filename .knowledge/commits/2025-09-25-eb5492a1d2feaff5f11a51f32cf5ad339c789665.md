# Fix torch >= 2.8 version guards for Float8_e8m0fnu and Float4_e2m1fn_x2 dtype handling

## TL;DR

- In `_optional_torch_c_dlpack.py`, the `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` preprocessor guard was misplaced: `Float8_e8m0fnu` was outside the guard (causing compile failure on torch < 2.8), and the `lanes != 1` TORCH_CHECK was similarly unguarded. This commit moves both inside the version gate.
- In `cython/dtype.pxi`, `torch.float8_e8m0fnu` was unconditionally accessed; now both `float8_e8m0fnu` and `float4_e2m1fn_x2` are registered into `TORCH_DTYPE_TO_DTYPE` only when `hasattr(torch, ...)` returns True.
- Net effect: TVM FFI now builds and runs correctly with torch <= 2.7 by skipping dtype registrations that don't exist on older torch versions.

## Key Exports

None — this commit fixes existing guard placement; no new API surface is introduced.

## Impact

- API: None — no public API changes.
- Behavioral: On torch < 2.8, `TORCH_DTYPE_TO_DTYPE` no longer includes `float8_e8m0fnu` or `float4_e2m1fn_x2`. Attempting to convert those dtypes will raise `KeyError` rather than `AttributeError` at import time or compile error during C extension build.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

**Bugfix: before/after for torch < 2.8 compatibility**

```python
# BEFORE (parent commit 929effa):
# dtype.pxi — unconditional access causes AttributeError on torch <= 2.7:
TORCH_DTYPE_TO_DTYPE = {
    ...
    torch.float8_e8m0fnu: DLDataType(14, 8, 1),  # AttributeError if torch < 2.8
}
# No float4_e2m1fn_x2 entry at all

# _optional_torch_c_dlpack.py C++ — Float8_e8m0fnu outside version guard:
# case ScalarType::Float8_e4m3fnuz:
#   ...
# case ScalarType::Float8_e8m0fnu:           # <-- compiles on all torch versions
#   ...
# #if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8
# case ScalarType::Float4_e2m1fn_x2:         # guarded
#   ...
# #endif

# AFTER (this commit):
# dtype.pxi — hasattr guards prevent AttributeError:
if hasattr(torch, "float8_e8m0fnu"):
    TORCH_DTYPE_TO_DTYPE[torch.float8_e8m0fnu] = DLDataType(14, 8, 1)
if hasattr(torch, "float4_e2m1fn_x2"):
    TORCH_DTYPE_TO_DTYPE[torch.float4_e2m1fn_x2] = DLDataType(17, 4, 2)

# _optional_torch_c_dlpack.py C++ — both types now inside version guard:
# #if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8
# case ScalarType::Float8_e8m0fnu:
#   dtype.code = DLDataTypeCode::kDLFloat8_e8m0fnu;
#   break;
# case ScalarType::Float4_e2m1fn_x2:
#   dtype.code = DLDataTypeCode::kDLFloat4_e2m1fn;
#   dtype.lanes = 2; dtype.bits = 4;
#   break;
# #endif
```

Note: `float4_e2m1fn_x2` was also missing from `TORCH_DTYPE_TO_DTYPE` in the parent commit; this fix adds it (guarded). Its `DLDataType(17, 4, 2)` encoding matches the `kDLFloat4_e2m1fn` code + bits=4 + lanes=2 from `getDLDataTypeForDLPackv1`.
