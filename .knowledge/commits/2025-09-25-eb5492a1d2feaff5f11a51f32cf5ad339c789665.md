# Fix torch <= 2.8 compatibility by guarding Float8_e8m0fnu and Float4_e2m1fn_x2 dtype entries
## TL;DR
- Extends `TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` preprocessor guards in the JIT-compiled C++ torch DLPack addon (`_optional_torch_c_dlpack.py`) to also cover `Float8_e8m0fnu`, which was previously unguarded and would fail to compile against torch < 2.8.
- Converts `float8_e8m0fnu` and `float4_e2m1fn_x2` entries in the Cython dtype mapping (`dtype.pxi`) from static dict literals to `hasattr`-guarded conditional insertions, preventing `AttributeError` on older torch versions.

## Key Exports
None. This commit does not add, remove, or change any public API surface. It only adjusts compile-time and import-time guards around existing dtype mappings.

## Impact
- API: None.
- Behavioral: The `_optional_torch_c_dlpack` JIT extension now compiles successfully against torch versions prior to 2.8, where `ScalarType::Float8_e8m0fnu` and `ScalarType::Float4_e2m1fn_x2` do not exist. The Cython `TORCH_DTYPE_TO_DTYPE` dict no longer raises `AttributeError` when `torch.float8_e8m0fnu` or `torch.float4_e2m1fn_x2` are absent.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DLPack dtype mapping tables** (in both `_optional_torch_c_dlpack.py` and `cython/dtype.pxi`): The bidirectional mapping between PyTorch `ScalarType`/`torch.dtype` and DLPack `DLDataType` codes, including sub-byte Float8 and Float4 variants. Related: [2025-09-18-929effa0.md](2025-09-18-929effa05c65d52f1608723c96efc9fdd24de746.md) (prior f4 bugfix).
- **Torch version guard convention** (`TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8`): C preprocessor guard pattern used in the inline C++ source to conditionally compile code for newer torch scalar types. Established in commit 4dee97f for `Float4_e2m1fn_x2`.

Design elements this commit produces:
- None new. This is a compatibility fix that extends existing guard patterns to a previously overlooked dtype.

## Usage Examples
Before (broken on torch < 2.8):
```python
# In dtype.pxi, static dict literal:
TORCH_DTYPE_TO_DTYPE = {
    ...
    torch.float8_e8m0fnu: DLDataType(14, 8, 1),  # AttributeError on torch < 2.8
}

# In _optional_torch_c_dlpack.py inline C++:
case ScalarType::Float8_e8m0fnu:  # compile error on torch < 2.8 (no guard)
    dtype.code = DLDataTypeCode::kDLFloat8_e8m0fnu;
    break;
```

After (compatible with torch < 2.8):
```python
# In dtype.pxi, conditional insertion:
TORCH_DTYPE_TO_DTYPE = { ... }  # no e8m0fnu entry
if hasattr(torch, "float8_e8m0fnu"):
    TORCH_DTYPE_TO_DTYPE[torch.float8_e8m0fnu] = DLDataType(14, 8, 1)
if hasattr(torch, "float4_e2m1fn_x2"):
    TORCH_DTYPE_TO_DTYPE[torch.float4_e2m1fn_x2] = DLDataType(17, 4, 2)
```
```cpp
// In _optional_torch_c_dlpack.py inline C++, now guarded:
#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8
    case ScalarType::Float8_e8m0fnu:
      dtype.code = DLDataTypeCode::kDLFloat8_e8m0fnu;
      break;
    case ScalarType::Float4_e2m1fn_x2:
      ...
#endif
```
