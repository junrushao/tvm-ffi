# Guard Float8_e8m0fnu and Float4_e2m1fn_x2 dtype mappings behind torch >= 2.8 checks

## TL;DR
- Moves `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` guard in `_optional_torch_c_dlpack.py` to also cover `Float8_e8m0fnu` (previously only guarded `Float4_e2m1fn_x2`), and adds a matching guard around the lanes-check and reverse-mapping case.
- Replaces unconditional `torch.float8_e8m0fnu` dict entry in `dtype.pxi` with `hasattr` runtime guard; adds similarly guarded `torch.float4_e2m1fn_x2` mapping.

## Key Exports
None -- no new public API. This commit tightens version guards on existing dtype mappings.

## Impact
- API: none
- Behavioral: Prevents `AttributeError` (Python/Cython) and compilation failure (C++ addon) when using tvm_ffi with torch < 2.8.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack dtype exchange protocol** (design-records/0012-python-bindings, design-records/0006-containers): The `TORCH_DTYPE_TO_DTYPE` mapping table and `_optional_torch_c_dlpack.py` C++ source that converts between torch `ScalarType` and `DLDataTypeCode`.

Design elements this commit produces: none -- purely defensive guards on existing mappings.

## Usage Examples
Before (broken on torch < 2.8):
```python
# dtype.pxi -- unconditional access crashes on torch < 2.8
TORCH_DTYPE_TO_DTYPE = {
    ...
    torch.float8_e8m0fnu: DLDataType(14, 8, 1),  # AttributeError!
}
```

After (guarded):
```python
TORCH_DTYPE_TO_DTYPE = {
    ...  # only types available in all supported torch versions
}
if hasattr(torch, "float8_e8m0fnu"):
    TORCH_DTYPE_TO_DTYPE[torch.float8_e8m0fnu] = DLDataType(14, 8, 1)
if hasattr(torch, "float4_e2m1fn_x2"):
    TORCH_DTYPE_TO_DTYPE[torch.float4_e2m1fn_x2] = DLDataType(17, 4, 2)
```
