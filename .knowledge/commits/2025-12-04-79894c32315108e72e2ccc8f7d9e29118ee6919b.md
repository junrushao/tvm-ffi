# Apply gc.collect()+del mod in test_stl to enforce module-lifetime invariant and prevent segfaults

## TL;DR
- `test_stl` in `tests/python/test_stl.py` was missing explicit teardown: after calling `run_check(mod)`, the `mod` handle and any CPython-cyclic references kept the module alive and potentially kept objects alive whose deleters reside inside the loaded `.so`.
- Adds `gc.collect()` + `del mod` after `run_check(mod)` so that all module-created objects are destroyed before `mod`'s ref-count drops to zero and the `.so` is `dlclose`d.
- This restores conformance with the established module-lifetime invariant (documented in `0011-module-system`): Module must outlive all objects whose deleters reside in the loaded `.so`.

## Key Exports
None

## Impact
- API: none
- Behavioral: The test teardown sequence is now deterministic: GC cycle is forced, then `mod` is explicitly released. Previously, object destruction order was determined by CPython's reference-count heuristics and GC scheduling, which could allow the `.so` to be `dlclose`d while some objects' C++ destructors still pointed into the unloaded library, causing a segfault.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module lifetime invariant** (`0011-module-system`): "Module must outlive all objects whose deleters reside in the loaded `.so`." The `run_check` sub-function already ensured temp variables from inside the function were destroyed first; this commit closes the remaining gap for any objects that escape `run_check`'s scope (e.g., via CPython ref cycles) by forcing GC before `del mod`.
- **`tvm_ffi.cpp` / JIT load-inline** (`0015-load-inline`): `tvm_ffi.cpp.build()` + `tvm_ffi.load_module()` are used to compile and load the test `.so` containing STL-exercise functions.

Design elements this commit produces: None

## Usage Examples
Before (potential segfault on some CPython builds):
```python
mod = tvm_ffi.load_module(output_lib_path)
run_check(mod)
# test function returns here; mod goes out of scope at garbage-collection time,
# but CPython may defer dlclose until AFTER cyclic-ref GC runs,
# which can call destructors of module-created objects after the .so is unloaded.
```

After (safe teardown):
```python
mod = tvm_ffi.load_module(output_lib_path)
run_check(mod)
# Force GC to destroy any cyclic references holding module-created objects alive,
# then explicitly drop mod so dlclose happens deterministically last.
gc.collect()
del mod
```
