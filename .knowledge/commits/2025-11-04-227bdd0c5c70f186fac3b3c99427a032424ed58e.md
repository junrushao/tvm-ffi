# Improve error propagation in TVMFFIEnvTensorAlloc and register MemoryError
## TL;DR
- Fix `TVMFFIEnvTensorAlloc` in `env_context.cc` to check the allocator's return code *before* asserting `dlpack_tensor != nullptr`, allowing error messages from the allocator callback to propagate properly instead of being swallowed by an internal check failure.
- Register `MemoryError` in the Python error registry (`error.py`) and update the torch DLPack allocator to report `MemoryError` instead of a custom `TorchDLPackManagedTensorAllocator` error kind.
- Update C++ test to verify the propagated error has kind `MemoryError` and the correct message.

## Key Exports
**Functions** (mutated):
- `TVMFFIEnvTensorAlloc(DLTensor* prototype, TVMFFIObjectHandle* out) -> int` — now checks `ret != 0` before asserting non-null, and uses `TVM_FFI_CHECK` with `RuntimeError` (instead of `TVM_FFI_ICHECK`) for the null check after a successful return.

**Error registration** (new):
- `register_error("MemoryError", MemoryError)` in `python/tvm_ffi/error.py` — maps the C++ error kind string `"MemoryError"` to Python's built-in `MemoryError`.

## Impact
- API: New registered error kind `"MemoryError"` in the cross-language error mapping.
- Behavioral: Allocator failures that return `ret != 0` now propagate the `SetError` message to the caller. Previously, the `TVM_FFI_ICHECK(dlpack_tensor != nullptr)` would fire first, masking the real error.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Error handling / TLS error propagation** — `SetError` callback and return-code checking pattern. Documented in `.knowledge/designs/0006-error-handling.md` and `.knowledge/ADRs/0002-tls-error-propagation.md`.
- **DLPack interop / env tensor allocation** — `TVMFFIEnvTensorAlloc` and the `DLPackManagedTensorAllocator` callback protocol. Documented in `.knowledge/designs/0017-dlpack-interop.md`.
- **Python error registry** — `register_error` mapping C++ error kinds to Python exceptions. Documented in `.knowledge/designs/0006-error-handling.md`.

Design elements this commit mutates:
- **TVMFFIEnvTensorAlloc error ordering contract** — new invariant: check allocator return code first, then validate the output pointer. This ensures the TLS error set by `SetError` is propagated rather than being replaced by an internal assertion.

**Invariant violated before fix**: `TVM_FFI_ICHECK(dlpack_tensor != nullptr)` fired before checking `ret != 0`, replacing the allocator's error message with a generic internal check failure.

**Invariant restored**: Allocator return code is checked first; only if `ret == 0` do we validate the pointer, using `TVM_FFI_CHECK` (user-facing) instead of `TVM_FFI_ICHECK` (internal).

## Usage Examples
```cpp
// Allocator callback that reports a typed error:
int MyAllocator(DLTensor* proto, DLManagedTensorVersioned** out,
                void* error_ctx, void (*SetError)(...)) {
  SetError(error_ctx, "MemoryError", "out of GPU memory");
  return -1;  // error code propagated to caller
}

// Caller now receives MemoryError with the correct message
// instead of an internal check failure
try {
  Tensor::FromEnvAlloc(TVMFFIEnvTensorAlloc, shape, dtype, device);
} catch (const tvm::ffi::Error& e) {
  // e.kind() == "MemoryError"
  // e.message() == "out of GPU memory"
}
```
