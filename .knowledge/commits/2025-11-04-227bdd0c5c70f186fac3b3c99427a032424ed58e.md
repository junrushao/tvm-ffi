# Fix error propagation order in TVMFFIEnvTensorAlloc and register MemoryError kind
## TL;DR
- **Bugfix**: In `TVMFFIEnvTensorAlloc`, the null-pointer check (`TVM_FFI_ICHECK`) ran before the return-code check, masking the allocator's error message with a generic internal assertion. The fix reorders to check `ret != 0` first, then uses `TVM_FFI_CHECK` with a descriptive `RuntimeError` message.
- **Error kind alignment**: The torch DLPack allocator's `SetError` call and the C++ test both switch from a generic/incorrect error kind to `"MemoryError"`, and `MemoryError` is registered in the Python error mapping.

## Key Exports

```python
# TVMFFIEnvTensorAlloc (behavioral change only, signature unchanged):
def TVMFFIEnvTensorAlloc(prototype: Ptr[DLTensor], out: Ptr[TVMFFIObjectHandle]) -> int: ...
    # Interacts with: DLPackManagedTensorAllocator callback (via EnvContext TLS)
    # Interacts with: TVMFFIEnvTensorAllocSetError -> TVMFFIErrorSetRaisedFromCStr (TLS error propagation)
    # Invariant (NEW): allocator return code is checked BEFORE null-pointer assertion,
    #   so allocator-originated errors (e.g., MemoryError) propagate to the caller
    #   instead of being masked by TVM_FFI_ICHECK.
    # Invariant: if allocator returns non-zero, the error is already in TLS via SetError callback

# Python error registry addition:
# register_error("MemoryError", MemoryError)
# Interacts with: core.ERROR_NAME_TO_TYPE, core.ERROR_TYPE_TO_NAME
# Invariant: C++ errors with kind="MemoryError" now map to Python's built-in MemoryError
```

## Impact
- API: None -- no signature changes.
- Behavioral: `TVMFFIEnvTensorAlloc` now correctly propagates error messages from custom allocators (e.g., torch's `ManagedTensorAllocator`) instead of masking them with `TVM_FFI_ICHECK(dlpack_tensor != nullptr)`. The error kind for allocation failures in the torch adapter is now `"MemoryError"` instead of `"TorchDLPackManagedTensorAllocator"`.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **TLS error propagation** (`0005-error-system`, ADR `0002-tls-error-propagation`): The `SetError` callback in the allocator protocol stores errors via `TVMFFIErrorSetRaisedFromCStr`, and the caller propagates them by returning the non-zero `ret` code. The fix relies on the invariant that when `ret != 0`, the error is already in TLS.
- **TVM_FFI_CHECK macro** (`0005-error-system`): Replaces `TVM_FFI_ICHECK` (internal assertion, `InternalError` kind) with `TVM_FFI_CHECK(cond, RuntimeError)`, which throws a user-facing `RuntimeError` with a descriptive message for the null-allocator-result case.
- **DLPackManagedTensorAllocator callback** (`0014-stream-and-env-context`): The allocator must call `SetError` and return -1 on failure. This commit relies on that contract.
- **Python error registry** (`0005-error-system`): `register_error` maps C++ error kind strings to Python exception classes.

Design elements this commit produces:
- **MemoryError as a standard error kind**: Establishes `"MemoryError"` as the canonical error kind for tensor allocation failures, registered in both the Python error map and used by the torch DLPack adapter. Previously, the torch adapter used `"TorchDLPackManagedTensorAllocator"` (not a registered error kind, would cause lookup failure in Python).

## Usage Examples

**Before (incorrect)**: Allocator error masked by internal assertion.
```cpp
// env_context.cc (before fix):
int ret = (*dlpack_alloc)(prototype, &dlpack_tensor, nullptr, TVMFFIEnvTensorAllocSetError);
TVM_FFI_ICHECK(dlpack_tensor != nullptr);  // FIRES FIRST -- throws InternalError
if (ret != 0) return ret;                   // Never reached if allocator set error + returned nullptr
// Result: caller sees "Check failed: dlpack_tensor != nullptr" instead of the allocator's error message
```

**After (correct)**: Allocator error propagates with original kind and message.
```cpp
// env_context.cc (after fix):
int ret = (*dlpack_alloc)(prototype, &dlpack_tensor, nullptr, TVMFFIEnvTensorAllocSetError);
if (ret != 0) return ret;  // Propagate allocator's TLS error (e.g., MemoryError)
TVM_FFI_CHECK(dlpack_tensor != nullptr, RuntimeError)
    << "TVMFFIEnvTensorAlloc: failed to allocate a tensor from the allocator";
// Result: caller sees "MemoryError: TestDLPackManagedTensorAllocatorError" (or torch's message)
```
