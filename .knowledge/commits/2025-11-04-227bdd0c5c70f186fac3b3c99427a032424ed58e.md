# Fix error propagation in TVMFFIEnvTensorAlloc by checking return code before checking dl_tensor

## TL;DR
- In `src/ffi/extra/env_context.cc`: reorders validation to check `ret_code != 0` before asserting `dl_tensor != NULL`; this allows caller error messages to propagate correctly via the TLS error slot.
- Updates `tests/cpp/extra/test_c_env_api.cc` to guard this regression.
- Adds `error.py` line (likely ensures `ErrObject` is importable from Python).

## Key Exports

```python
# C pseudocode — TVMFFIEnvTensorAlloc in src/ffi/extra/env_context.cc
def TVMFFIEnvTensorAlloc(shape, dtype, device, dl_tensor_out) -> int:
    """Allocate a DLTensor via the registered allocator.
    # Before: checked dl_tensor != NULL first — swallowed allocator error message
    # After: checks ret_code != 0 first, propagating allocator's TLS error string
    # Invariant: if ret_code != 0, TLS error slot contains allocator's message
    # Interacts with: TVMFFISetTLSLastError, DLPackManagedTensorAllocator callback
    """
    ret_code = allocator(shape, dtype, device, dl_tensor_out)
    if ret_code != 0:
        return ret_code  # error message already in TLS slot
    if dl_tensor_out == NULL:
        set_error("allocator returned NULL")
        return -1
    return 0
```
