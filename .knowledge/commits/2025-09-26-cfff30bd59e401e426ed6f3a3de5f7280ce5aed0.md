# Fix type-address-reuse bug in Cython FFI dispatch cache by keeping registered types alive

## TL;DR
- Fixes a potential flaky bug where a garbage-collected Python type's memory address could be reused by a new type, causing the C++ `dispatch_map_` to return the wrong `TVMFFIPyArgSetter` for the new type.
- Introduces a module-level `_DISPATCH_TYPE_KEEP_ALIVE` set (guarded by a `threading.Lock`) in `TVMFFIPyArgSetterFactory_` that holds strong references to every type registered through the dispatcher, preventing GC and address reuse.
- Invalidates the prior assumption (documented in designs/0015 and ADRs/0016) that "Python type objects are effectively immortal" -- local/dynamic types can be collected.

## Key Exports
**Module-level Cython variables** (`python/tvm_ffi/cython/function.pxi`):
```cython
cdef _DISPATCH_TYPE_KEEP_ALIVE = set()           # strong refs to registered types
cdef _DISPATCH_TYPE_KEEP_ALIVE_LOCK = threading.Lock()  # thread-safety guard
```

No new public API surface. The fix is internal to the factory function.

## Impact
- API: None -- no public API changes.
- Behavioral: Eliminates a rare but real correctness bug where the wrong argument setter could be dispatched after type GC + address reuse. This manifested as flaky test failures.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Type-cached FFI dispatch** ([0015-python-ffi-call-dispatch.md](../designs/0015-python-ffi-call-dispatch.md)): The `TVMFFIPyCallManager.dispatch_map_` keyed by `PyTypeObject*` pointer. This commit addresses a soundness hole in the cache's key stability assumption.
- **Type-cached dispatch ADR** ([0016-type-cached-ffi-dispatch.md](../ADRs/0016-type-cached-ffi-dispatch.md)): The "no explicit cache invalidation" decision, which this commit partially overrides by preventing key instability rather than invalidating stale entries.

Design elements this commit produces:
- **Type keep-alive invariant**: All types passed through `TVMFFIPyArgSetterFactory_` are kept alive for the process lifetime via `_DISPATCH_TYPE_KEEP_ALIVE`. This ensures `PyTypeObject*` pointer stability for the `dispatch_map_` cache. The set grows monotonically and is bounded by the number of distinct Python types ever used as FFI arguments (expected small in practice).

## Usage Examples
**Before (buggy)**: A local type could be collected and its address reused:
```python
def make_local_type():
    class LocalType:
        pass
    return LocalType()

obj = make_local_type()
func(obj)  # Factory caches PyTypeObject* -> setter for LocalType
del obj    # LocalType may be GC'd; its address freed

# Later, a new type occupies the same address
obj2 = make_another_type()
func(obj2)  # dispatch_map_ returns WRONG setter (the one for LocalType)
```

**After (fixed)**: The factory keeps `type(arg)` alive:
```python
# Same scenario, but now TVMFFIPyArgSetterFactory_ does:
#   _DISPATCH_TYPE_KEEP_ALIVE.add(type(arg))
# LocalType is never GC'd, so its address is never reused.
# dispatch_map_ always returns the correct setter.
```
