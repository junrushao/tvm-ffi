# Fix type dispatch GC race by keeping alive registered Python types
## TL;DR
- Fixes a potential use-after-free in the `TVMFFIPyArgSetterFactory_` type dispatch cache: when a Python type is garbage-collected and a new type reuses the same `PyTypeObject*` address, the dispatcher would incorrectly use the old type's setter. The fix adds a `_DISPATCH_TYPE_KEEP_ALIVE` set (guarded by a threading lock) that prevents registered types from being GC'd.

## Design Elements
Design elements this commit consumes:
- **TVMFFIPyCallManager type-dispatch cache** ([`.knowledge/designs/0019-python-ffi-call-dispatch.md`](../designs/0019-python-ffi-call-dispatch.md)): The `dispatch_map_` uses `PyTypeObject*` as keys, which are non-owning pointers.

Design elements this commit produces:
- **Type liveness invariant for dispatch cache**: Registered types are pinned in `_DISPATCH_TYPE_KEEP_ALIVE` to ensure their `PyTypeObject*` addresses remain valid for the lifetime of the dispatch map.
