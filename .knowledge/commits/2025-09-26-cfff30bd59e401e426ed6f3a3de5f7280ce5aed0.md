# Fix stale PyTypeObject* key hazard in the Cython FFI arg-setter dispatch cache

## TL;DR

- `TVMFFIPyCallManager`'s dispatch cache keyed on `PyTypeObject*` (a raw pointer) could return the wrong setter when a locally-defined Python class was GC'd and a new class was allocated at the same address.
- The fix pins every type that enters the dispatch cache by adding it to a module-level `_DISPATCH_TYPE_KEEP_ALIVE` set, so the `PyTypeObject` is never freed.
- A `threading.Lock` (`_DISPATCH_TYPE_KEEP_ALIVE_LOCK`) guards the set for thread-safety in future free-threaded Python builds.

## Key Exports

```python
# python/tvm_ffi/cython/function.pxi

# Two new module-level cdef singletons introduced by this commit:

_DISPATCH_TYPE_KEEP_ALIVE: set
# Purpose: holds a strong reference to every Python type that has been added
#   to the TVMFFIPyCallManager dispatch cache.
# Invariant: once a type is inserted it is NEVER removed (the map key lives forever).
# Interacts with: TVMFFIPyArgSetterFactory_ — type is inserted before any cache lookup.
# Note: the set holds Python type objects, not instances; memory cost is O(num_distinct_types).

_DISPATCH_TYPE_KEEP_ALIVE_LOCK: threading.Lock
# Purpose: serialises writes to _DISPATCH_TYPE_KEEP_ALIVE.
# Invariant: must be held whenever mutating _DISPATCH_TYPE_KEEP_ALIVE.
# Interacts with: _DISPATCH_TYPE_KEEP_ALIVE (its only guarded resource).
# Note: added in anticipation of free-threaded CPython (PEP 703); currently the GIL
#   makes the lock redundant in practice.

# Usage inside TVMFFIPyArgSetterFactory_ (Cython cdef int):
#   with _DISPATCH_TYPE_KEEP_ALIVE_LOCK:
#       _DISPATCH_TYPE_KEEP_ALIVE.add(type(arg))
#   ... then proceed with normal setter dispatch ...
```

## Impact

- API: None — no Python or C public API changed.
- Behavioral: Eliminates a flaky mis-dispatch (wrong setter invoked) when a Python class created in a local scope is garbage-collected and a new class happens to reuse the same `PyTypeObject*` address.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- `TVMFFIPyCallManager` dispatch map (`unordered_map<PyTypeObject*, TVMFFIPyArgSetter>`) — design record `.knowledge/design-records/0016-py-ffi-call-dispatch.md`, "Contracts, Assumptions and Invariants" section.
- `TVMFFIPyArgSetterFactory_` (Cython `cdef int`) — the factory entry point that builds setters on first encounter of a type; location: `python/tvm_ffi/cython/function.pxi`.

Design elements this commit produces:
- `_DISPATCH_TYPE_KEEP_ALIVE` / `_DISPATCH_TYPE_KEEP_ALIVE_LOCK` — new invariant: every type that enters the dispatch map is kept alive for the lifetime of the module. This mutates the invariant documented in 0016: the previously documented caveat ("types dynamically created and destroyed may cause stale slots") is now actively prevented.

## Usage Examples

**Before (broken — could silently use wrong setter):**

```python
# In a loop or function scope:
for _ in range(N):
    class LocalType:
        pass
    obj = LocalType()
    tvm_ffi_func(obj)
    # After iteration: LocalType may be GC'd; next iteration's new class
    # could reuse the same PyTypeObject* address → wrong setter invoked.
```

**After (fixed — type kept alive):**

```python
# Same loop is now safe:
for _ in range(N):
    class LocalType:
        pass
    obj = LocalType()
    tvm_ffi_func(obj)
    # TVMFFIPyArgSetterFactory_ adds LocalType to _DISPATCH_TYPE_KEEP_ALIVE before
    # caching the setter → PyTypeObject* address is stable for the module lifetime.
    # Downside: O(N) unique types would accumulate in the set; acceptable in practice
    # because the number of distinct types dispatched through FFI is small.
```
