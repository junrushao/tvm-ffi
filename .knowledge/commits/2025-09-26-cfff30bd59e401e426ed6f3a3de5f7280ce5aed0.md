# Fix type-pointer reuse flaky in Cython arg setter dispatcher
## TL;DR
- The C++ `TVMFFIPyCallManager` dispatcher caches `TVMFFIPyArgSetter` per `PyTypeObject*` pointer, but if a locally-defined Python type is garbage collected, a new type can reuse the same memory address, causing the wrong cached setter to be used.
- Introduces `_DISPATCH_TYPE_KEEP_ALIVE` (a `set`) and `_DISPATCH_TYPE_KEEP_ALIVE_LOCK` (a `threading.Lock`) in `function.pxi` to prevent registered types from being garbage collected.
- The fix is applied inside `TVMFFIPyArgSetterFactory_`, which runs once per new type encountered by the dispatcher.

## Key Exports

```python
# --- Internal Cython module-level state (function.pxi) ---

_DISPATCH_TYPE_KEEP_ALIVE: set
    # Holds strong references to every Python type ever registered through
    # TVMFFIPyArgSetterFactory_, preventing GC and pointer reuse.
    # Interacts with: TVMFFIPyCallManager.dispatch_map_ (keyed by PyTypeObject*)
    # Invariant: only grows; types are never removed. Bounded in practice because
    #   the number of distinct argument types is limited.

_DISPATCH_TYPE_KEEP_ALIVE_LOCK: threading.Lock
    # Guards concurrent writes to _DISPATCH_TYPE_KEEP_ALIVE.
    # Invariant: acquired inside TVMFFIPyArgSetterFactory_ before set.add()
    # Extension: prepared for future GIL-free (free-threaded) Python builds
```

## Impact
- API: none
- Behavioral: eliminates a class of flaky dispatch errors where a garbage-collected type's memory address is reused by a new type, causing the C++ dispatcher to apply the wrong setter function
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:

- `TVMFFIPyArgSetterFactory_` -- factory function that classifies each argument type and assigns a setter (documented in [0012-ffi-python-package](../design-records/0012-ffi-python-package.md))

Design elements this commit produces:
- None (implementation-level fix, no new public API or design element)

## Usage Examples
**Before (bug scenario):**
```python
# A locally-defined type is used as an FFI argument
def use_local_type():
    class MyTensor:
        __dlpack__ = ...
    f = tvm_ffi.get_global_func("some.func")
    f(MyTensor())  # TVMFFIPyArgSetterFactory_ caches setter for MyTensor's PyTypeObject*
    # MyTensor goes out of scope -> type object GC'd -> pointer freed

# Later, a new type happens to occupy the same memory address
class AnotherType:
    pass
f(AnotherType())  # BUG: dispatcher uses MyTensor's cached setter for AnotherType
```

**After (fix):**
```python
# Same scenario, but now TVMFFIPyArgSetterFactory_ adds type(arg) to
# _DISPATCH_TYPE_KEEP_ALIVE before returning. MyTensor's type object
# is kept alive, so its pointer is never reused. AnotherType gets a
# fresh pointer and its own correct setter.
```
