# Fix potential flaky issue in Cython dispatcher by keeping registered types alive
## TL;DR
- Fixes a race condition where a Python type registered in the C++ dispatcher could be garbage-collected, and a new type allocated at the same memory address would be mis-dispatched.
- Adds `_DISPATCH_TYPE_KEEP_ALIVE` (set) and `_DISPATCH_TYPE_KEEP_ALIVE_LOCK` (threading.Lock) to retain references to all types registered through the dispatcher.
- The C++ dispatcher uses `TYPE(obj)` pointer as a non-owning key; keeping types alive prevents address reuse.

## Key Exports

```python
# In python/tvm_ffi/cython/function.pxi
_DISPATCH_TYPE_KEEP_ALIVE: set  # Retains strong refs to all types registered in dispatcher
# Invariant: once a type is added, it is never removed
# Interacts with: TVMFFIPyArgSetterFactory_ (C++ dispatcher)

_DISPATCH_TYPE_KEEP_ALIVE_LOCK: threading.Lock  # Thread-safety for the set
```
