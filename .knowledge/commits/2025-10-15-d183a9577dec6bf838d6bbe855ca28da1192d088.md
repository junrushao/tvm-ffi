# Replace runtime load_module of libtvm_ffi_testing with explicit CMake link to control unloading order

## TL;DR
- Replaced Python-side runtime `load_module(find_library_by_basename("tvm_ffi_testing"))` in `testing.py` with compile-time `target_link_libraries(tvm_ffi_cython PRIVATE tvm_ffi_testing)` in CMake.
- Added a `TVMFFITestingDummyTarget()` extern C symbol declaration in Cython helpers and a call in `base.pxi` to force the linker to include the testing library.
- Ensures the OS unloads Cython before `libtvm_ffi_testing`, preventing crashes from global object deallocation ordering.


## Impact
- API: none — no public Python or C++ API changed
- Behavioral: `tvm_ffi.testing` no longer calls `load_module()` at import time; the testing library is instead linked at build time into the Cython extension. Library unloading order is now deterministic (Cython first, then testing).
- Flags/config: none
- Data formats/schemas: none
