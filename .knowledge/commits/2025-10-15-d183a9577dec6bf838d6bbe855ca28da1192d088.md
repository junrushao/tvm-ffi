# Switch libtvm_ffi_testing from runtime dlopen to compile-time linking in the Cython module
## TL;DR
- Replaced the Python-level `load_module(find_library_by_basename("tvm_ffi_testing"))` call in `testing.py` with a direct CMake `target_link_libraries(tvm_ffi_cython PRIVATE tvm_ffi_testing)` link dependency.
- Added a `TVMFFITestingDummyTarget()` extern-C call in `base.pxi` module-init to force the linker to include `libtvm_ffi_testing` and guarantee that the Cython module is unloaded before the testing library during process teardown.
- Removed the `_LIBTVM_FFI_TESTING` module-level variable and the `libinfo`/`load_module` imports from `testing.py`.

## Key Exports
**Functions**: `TVMFFITestingDummyTarget() -> int` -- extern-C dummy symbol declared in `tvm_ffi_python_helpers.h` (already existed in `src/ffi/testing/testing.cc` and `rust/tvm-ffi-sys/src/c_api.rs`; this commit adds the Cython declaration and call).

No new public Python or C++ API surface.

## Impact
- API: none -- the removed `_LIBTVM_FFI_TESTING` was a private implementation detail.
- ABI: none -- `TVMFFITestingDummyTarget` was already exported from `libtvm_ffi_testing`; no signature change.
- Behavioral: the testing library is now loaded as a direct dependency of the Cython `.so` rather than via `dlopen` at Python import time. This guarantees the OS unloads the Cython module first (reverse dependency order), preventing use-after-free of global objects defined in the testing library during shutdown.
- Flags/config: none.
- Data formats/schemas: none.

Design elements this commit consumes:
- Module system `load_module` / `find_library_by_basename` -- the old loading path being replaced (`.knowledge/designs/0013-module-system.md`).

Design elements this commit produces:
- Pattern: prefer explicit link-time dependencies over runtime `dlopen`/`load_module` for libraries needed at import time, to control DLL unloading order during interpreter shutdown.
