# Switch libtvm_ffi_testing from runtime load_module to explicit CMake link for deterministic unloading order
## TL;DR
- Removed runtime `load_module(libinfo.find_library_by_basename("tvm_ffi_testing"))` from `testing.py`; `libtvm_ffi_testing` is now linked at build time via `target_link_libraries(tvm_ffi_cython PRIVATE tvm_ffi_testing)` in CMakeLists.txt.
- Added `TVMFFITestingDummyTarget()` declaration in Cython helpers and an invocation in `base.pxi` to force the linker to include the testing library.
- This ensures deterministic unloading order: Cython module is unloaded before `libtvm_ffi_testing`, preventing dangling global object cleanup issues at process shutdown.

## Key Exports
None -- no new public API introduced. The existing `TVMFFITestingDummyTarget()` C function (already in `src/ffi/testing/testing.cc`) is merely declared and called from Cython to anchor the linker dependency.

## Impact
- API: none -- `tvm_ffi.testing` module keeps the same public surface
- Behavioral: library loading moves from Python runtime to compile-time linking; unloading order becomes deterministic (Cython first, then testing lib)
- Flags/config: none
- Data formats/schemas: none
