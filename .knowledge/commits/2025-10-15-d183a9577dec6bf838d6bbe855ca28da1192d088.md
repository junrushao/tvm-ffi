# Fix Cython-to-libtvm_ffi_testing unloading order via explicit static linking

## TL;DR
- Removes the runtime `load_module(libinfo.find_library_by_basename("tvm_ffi_testing"))` call from `testing.py`, replacing it with a CMake `target_link_libraries(tvm_ffi_cython PRIVATE tvm_ffi_testing)` explicit link-time dependency.
- Adds `TVMFFITestingDummyTarget()` — a no-op symbol defined in `libtvm_ffi_testing` and declared in `tvm_ffi_python_helpers.h` — that is called at Cython module init to force the linker to retain the dependency and guarantee load order.
- Fixes a shutdown-time crash risk: ensures Cython (`tvm_ffi_cython.so`) is unloaded by the OS before `libtvm_ffi_testing.so`, so any global-object destructors in the testing lib run after all Cython references are gone.

## Key Exports

```python
# Declared in python/tvm_ffi/cython/tvm_ffi_python_helpers.h
# Defined in libtvm_ffi_testing (not in this diff — already existed as a symbol)
extern "C" int TVMFFITestingDummyTarget() -> int
# Invariant: always returns a stable value; side-effect-free beyond forcing linker retention.
# Interacts with: Cython module init (__init__ of tvm_ffi_cython.so), CMake tvm_ffi_testing target.

# In CMakeLists.txt (effective change):
# OLD: tvm_ffi_cython links tvm_ffi_header + tvm_ffi_shared only
# NEW: tvm_ffi_cython links tvm_ffi_header + tvm_ffi_shared + tvm_ffi_testing
```

## Impact
- API: none — `TVMFFITestingDummyTarget` is an internal testing-only symbol, not part of the public ABI.
- Behavioral: Cython extension module is now guaranteed to be unloaded before `libtvm_ffi_testing.so`, preventing use-after-free in global destructors at interpreter shutdown.
- Flags/config: none.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- `0013-python-package`: Cython extension build pipeline (`tvm_ffi_cython` CMake target, `base.pxi`, `tvm_ffi_python_helpers.h`). The commit adjusts linking of this target without changing its public interface.
- `0011-module-system` (indirectly): the old code used `load_module` to bring in `libtvm_ffi_testing` at runtime; this dynamic loading path is now replaced by a static linker dependency.

Design elements this commit produces: None — no new design elements. The `TVMFFITestingDummyTarget` symbol is a linker-retention shim, not a design element.

## Usage Examples

Before (Python-level dynamic load, fragile unload order):
```python
# testing.py — OLD
_LIBTVM_FFI_TESTING = load_module(libinfo.find_library_by_basename("tvm_ffi_testing"))
# Result: unloading order at shutdown is non-deterministic; tvm_ffi_testing may unload
# before cython, causing destructors to run against freed memory.
```

After (explicit link-time dependency, deterministic unload order):
```python
# testing.py — NEW (load_module call removed entirely)
# CMakeLists.txt adds: target_link_libraries(tvm_ffi_cython PRIVATE tvm_ffi_testing)
# base.pxi calls TVMFFITestingDummyTarget() at module init to pin the symbol reference.
# Result: OS unloads cython before tvm_ffi_testing, respecting the link-time dependency graph.
```
