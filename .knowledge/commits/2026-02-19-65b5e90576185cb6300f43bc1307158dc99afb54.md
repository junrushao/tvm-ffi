# Add AMD HIP/ROCm backend support to tvm_ffi.cpp extension build system

## TL;DR
- Adds `backend: str | None` parameter to all four public `tvm_ffi.cpp` APIs (`build_inline`, `load_inline`, `build`, `load`), accepting `"cuda"` or `"hip"` with auto-detection when `None`.
- Introduces ROCm home discovery (`_find_rocm_home`), architecture probing (`_get_rocm_target` via `rocm_agent_enumerator`/`rocminfo`), and GPU backend auto-detection (`_detect_gpu_backend` via `TVM_FFI_GPU_BACKEND` env override or ROCm presence).
- The `_generate_ninja_build` internal signature changes from `with_cuda: bool` to `backend: str | None`, and the HIP path uses `hipcc` instead of `nvcc` with a simplified compile rule (no `--generate-dependencies-with-compile`).

## Impact
- API: **additive** — new `backend` keyword argument on `build_inline`, `load_inline`, `build`, `load`. Default `None` is backward-compatible; existing callers see no change.
- Behavioral: On machines where ROCm is present and CUDA is absent, `_detect_gpu_backend()` will now return `"hip"` automatically. CUDA users on dual-stack machines should set `TVM_FFI_GPU_BACKEND=cuda` to override.
- Flags/config: Three new env vars: `TVM_FFI_GPU_BACKEND` (override backend), `TVM_FFI_ROCM_ARCH_LIST` (space-separated arch list e.g. `"gfx90a gfx942"`), `ROCM_HOME`/`ROCM_PATH` (ROCm install path).
- Data formats/schemas: HIP compile rule in Ninja omits `--generate-dependencies-with-compile`/`--dependency-output` (not supported by hipcc); incremental dependency tracking is weaker for HIP builds.

## Usage Examples

**HIP inline module on AMD GPU** (from commit message):
```python
import torch
import tvm_ffi.cpp

cpp_source = '''
#include <hip/hip_runtime.h>
__global__ void add_one_kernel(const float* x, float* y, int64_t n) {
    int64_t i = (int64_t)blockIdx.x * blockDim.x + threadIdx.x;
    if (i < n) y[i] = x[i] + 1.0f;
}
void add_one_hip(tvm::ffi::TensorView x, tvm::ffi::TensorView y) { ... }
'''

# Explicit backend="hip", or omit for auto-detection on AMD hardware
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_sources=cpp_source,   # HIP source passed via cuda_sources param
    functions="add_one_hip",
    backend="hip",
)

x = torch.tensor([1, 2, 3, 4, 5], dtype=torch.float32, device="cuda")
y = torch.empty_like(x)
mod.add_one_hip(x, y)
torch.testing.assert_close(x + 1, y)
```

Note: HIP source is still passed via the `cuda_sources` parameter — the `backend` arg selects the compiler toolchain, not the parameter name.
