# Guard ml_dtypes>=0.5 dtype entries (int2, uint2, float8_e3m4, etc.) behind hasattr check

## TL;DR
- `python/tvm_ffi/cython/dtype.pxi`: dtypes introduced in `ml_dtypes>=0.5` (`int2`, `uint2`, `float8_e3m4`, `float8_e4m3`, `float8_e8m0fnu`, `float6_e2m3fn`, `float6_e3m2fn`, `float4_e2m1fn`) are now registered only when `hasattr(ml_dtypes, "int2")` is true.
- Core always-present dtypes (`int4`, `uint4`, `bfloat16`, and the `float8_e4m3*` variants) remain unconditional.

## Key Exports

```python
# cython/dtype.pxi

# BEFORE: unconditional registration of all ml_dtypes entries
MLDTYPES_DTYPE_TO_DTYPE = {
    numpy.dtype(ml_dtypes.int2): DLDataType(0, 2, 1),  # AttributeError on ml_dtypes<0.5
    ...
}

# AFTER: gated registration
MLDTYPES_DTYPE_TO_DTYPE = {
    numpy.dtype(ml_dtypes.int4): DLDataType(0, 4, 1),  # always present
    ...
}
if hasattr(ml_dtypes, "int2"):  # ml_dtypes >= 0.5.0
    MLDTYPES_DTYPE_TO_DTYPE[numpy.dtype(ml_dtypes.int2)] = DLDataType(0, 2, 1)
    ...
# Interacts with: TVMFFIPyArgSetterDTypeFromNumpy_, NUMPY_DTYPE_TO_DTYPE
```

## Impact
- API: none — `MLDTYPES_DTYPE_TO_DTYPE` is an internal mapping.
- Behavioral: With `ml_dtypes<0.5`, `int2`/`uint2`/float8 variants are no longer registered (instead of `AttributeError` at import time). With `ml_dtypes>=0.5`, all entries are registered as before.
- Flags/config: none
- Data formats/schemas: none
