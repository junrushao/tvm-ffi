# Guard ml_dtypes>=0.5-only dtype entries behind hasattr check for backward compatibility
## TL;DR
- Moves 8 `MLDTYPES_DTYPE_TO_DTYPE` entries that require `ml_dtypes >= 0.5` (`int2`, `uint2`, `float8_e3m4`, `float8_e4m3`, `float8_e8m0fnu`, `float6_e2m3fn`, `float6_e3m2fn`, `float4_e2m1fn`) from the static dict literal into a `hasattr(ml_dtypes, "int2")` guarded block.
- Retains the 6 entries available in `ml_dtypes < 0.5` (`int4`, `uint4`, `bfloat16`, `float8_e4m3b11fnuz`, `float8_e4m3fn`, `float8_e4m3fnuz`, `float8_e5m2`, `float8_e5m2fnuz`) in the unconditional dict literal.

## Key Exports
None (no new API; existing `MLDTYPES_DTYPE_TO_DTYPE` dict's contents now vary by `ml_dtypes` version).

## Impact
- API: none -- the dict is an internal lookup table, not a public API.
- Behavioral: with `ml_dtypes < 0.5`, the 8 newer dtype mappings are silently absent instead of raising `AttributeError` at import time.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **`MLDTYPES_DTYPE_TO_DTYPE` lookup table** (`python/tvm_ffi/cython/dtype.pxi`) -- the static mapping from `numpy.dtype(ml_dtypes.X)` to `DLDataType` values. Documented in [0017-dlpack-interop.md](../designs/0017-dlpack-interop.md) and introduced in commit d77606a.
- **`hasattr`-guarded conditional insertion pattern** -- already used for torch dtype entries in `dtype.pxi` (commit eb5492a). This commit extends the same pattern to `ml_dtypes`.

Design elements this commit produces: none (applies existing pattern to a new case).

None (internal change; no new API to demonstrate).
