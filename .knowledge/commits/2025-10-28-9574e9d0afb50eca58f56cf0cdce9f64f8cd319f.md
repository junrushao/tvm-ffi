# Gate ml_dtypes >= 0.5 dtype entries behind hasattr check for backward compatibility
## TL;DR
- Splits `MLDTYPES_DTYPE_TO_DTYPE` initialization into unconditional entries (available in all ml_dtypes versions) and conditional entries gated behind `hasattr(ml_dtypes, "int2")` (only in ml_dtypes >= 0.5.0).
- Fixes `AttributeError` crash when using `ml_dtypes == 0.4.x` which lacks `int2`, `uint2`, `float8_e3m4`, `float8_e4m3`, `float8_e8m0fnu`, `float6_e2m3fn`, `float6_e3m2fn`, and `float4_e2m1fn`.

## Key Exports
No new public API surface. The `MLDTYPES_DTYPE_TO_DTYPE` dict is an internal lookup table used by the Cython dtype conversion layer.

```python
# Internal dtype mapping (python/tvm_ffi/cython/dtype.pxi)
# Unconditional (all ml_dtypes versions):
MLDTYPES_DTYPE_TO_DTYPE = {
    ml_dtypes.int4:              DLDataType(0, 4, 1),
    ml_dtypes.uint4:             DLDataType(1, 4, 1),
    ml_dtypes.bfloat16:          DLDataType(4, 16, 1),
    ml_dtypes.float8_e4m3b11fnuz: DLDataType(9, 8, 1),
    ml_dtypes.float8_e4m3fn:     DLDataType(10, 8, 1),
    ml_dtypes.float8_e4m3fnuz:   DLDataType(11, 8, 1),
    ml_dtypes.float8_e5m2:       DLDataType(12, 8, 1),
    ml_dtypes.float8_e5m2fnuz:   DLDataType(13, 8, 1),
}
# Conditional (ml_dtypes >= 0.5.0 only, gated by hasattr(ml_dtypes, "int2")):
#   int2, uint2, float8_e3m4, float8_e4m3, float8_e8m0fnu,
#   float6_e2m3fn, float6_e3m2fn, float4_e2m1fn
# Interacts with: NUMPY_DTYPE_TO_DTYPE (merged via **spread), torch dtype table (same hasattr pattern)
```

## Impact
- API: none -- no public API change
- Behavioral: users with `ml_dtypes < 0.5` no longer get `AttributeError` at import time; they simply lack the newer dtype mappings
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- [0012-python-bindings](../.knowledge/design-records/0012-python-bindings.md): static dtype lookup tables, `MLDTYPES_DTYPE_TO_DTYPE` dict pattern

Design elements this commit produces:
- Version-gated dtype registration pattern: use `hasattr(ml_dtypes, "<sentinel_attr>")` to conditionally register dtypes only available in newer library versions. Mirrors the existing `hasattr(torch, ...)` pattern for torch dtypes.

## Usage Examples
Before (crashes with ml_dtypes < 0.5):
```python
import ml_dtypes  # version 0.4.x
import tvm_ffi  # AttributeError: module 'ml_dtypes' has no attribute 'int2'
```

After (works with ml_dtypes < 0.5):
```python
import ml_dtypes  # version 0.4.x
import tvm_ffi  # OK -- int2/uint2/float8_e3m4/etc. silently unavailable
```
