# Add TVMFFIErrorSetRaisedFromCStrParts C API for composable error messages from DSL compilers
## TL;DR
- Introduces new C API `TVMFFIErrorSetRaisedFromCStrParts` that constructs an error message by concatenating an array of C string parts, enabling DSL compilers to reduce storage duplication for common substrings (e.g., function signatures shared across multiple error messages).
- Implementation uses two-pass approach: compute total length, reserve, then append -- skipping NULL parts.
- Bumps package version from 0.1.0b16 to 0.1.0b17.

## Key Exports
Public C API function added to the error handling surface.

```python
# New C API (c_api.h)

                                       message_parts: const_char_ptr_ptr,
                                       num_parts: int32) -> None:
    """Concatenate message_parts into a single error message and store in TLS.

    Each part can be NULL (skipped). Parts are concatenated in order with no separator.
    Captures backtrace internally (same as TVMFFIErrorSetRaisedFromCStr).
    """
    # Interacts with: TVMFFIErrorSetRaisedFromCStr (sibling convenience API)
    # Interacts with: TVMFFIErrorMoveFromRaised (caller retrieves the error from TLS)
    # Interacts with: TVMFFIBacktrace (captures backtrace at call site)
    # Invariant: void return -- follows same TLS-store pattern as TVMFFIErrorSetRaised
    # Invariant: NULL parts are silently skipped, not treated as errors
    # Extension: designed for DSL compiler codegen where error message parts are stored
    #   as separate global strings to avoid duplication of common substrings

# Internal implementation (SafeCallContext)
# SafeCallContext::SetRaisedByCstrParts(kind, message_parts, num_parts, backtrace)
#   Two-pass: strlen sum -> reserve -> append
#   Creates Error(kind, concatenated_message, backtrace) and stores in TLS
```

## Usage Examples
**Context**: A DSL compiler stores error message parts as separate global strings to share common substrings like function signatures across multiple error messages.
```c
// Compiler-generated error reporting code
// The function signature string is shared across multiple error sites
static const char* kFuncSig = "matmul(x: Tensor, y: Tensor)";

// Error site 1: dtype mismatch on arg 1
{
    const char* parts[] = {"Argument 1 mismatch in `", kFuncSig, "`, dtype mismatch"};
    TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts, 3);
    return -1;
}

// Error site 2: shape mismatch on arg 2 (reuses kFuncSig)
{
    const char* parts[] = {"Argument 2 mismatch in `", kFuncSig, "`, shape[0] mismatch"};
    TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts, 3);
    return -1;
}

// NULL parts are silently skipped
{
    const char* parts[] = {"Mismatched", NULL, " got Tensor"};
    TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts, 3);
    // Error message: "Mismatched got Tensor"
    return -1;
}
```
