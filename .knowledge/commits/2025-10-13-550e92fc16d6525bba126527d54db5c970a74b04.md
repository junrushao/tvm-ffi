# Add TVMFFIErrorSetRaisedFromCStrParts C API for concatenated error messages

## TL;DR
- Adds new C API function `TVMFFIErrorSetRaisedFromCStrParts(kind, message_parts, num_parts)` that constructs an error by concatenating multiple C string parts, enabling DSL compilers to reuse common substrings (e.g., function signatures) across multiple error messages.
- Implements the concatenation in `SafeCallContext::SetRaisedByCstrParts` with a two-pass approach (measure total length, then reserve and append), skipping NULL parts.
- Updates docs, examples, backtrace exclusion filter, and bumps version to `0.1.0b17`.

## Design Elements
Design elements this commit consumes:
- **TLS error propagation** ([0005-error-system.md](../designs/0005-error-system.md), [ADR 0002](../ADRs/0002-tls-error-propagation.md)): Uses `SafeCallContext::ThreadLocal()` to store the constructed error in thread-local storage, following the same pattern as `TVMFFIErrorSetRaisedFromCStr`.
- **Error object construction** ([0005-error-system.md](../designs/0005-error-system.md)): Constructs `Error(kind, message, backtrace)` which creates an `ErrorObjFromStd` via `make_object`.
- **Backtrace capture** (`TVMFFIBacktrace`): Captures backtrace at the C API entry point, same as existing `TVMFFIErrorSetRaisedFromCStr`.
- **Backtrace frame exclusion** (`src/ffi/backtrace_utils.h`): Adds `TVMFFIErrorSetRaisedFromCStrParts` to the exclusion list so it doesn't appear in user-visible backtraces.
- **C ABI function conventions** ([0001-c-abi.md](../designs/0001-c-abi.md)): Returns void (not int) following the pattern of `TVMFFIErrorSetRaised` and `TVMFFIErrorSetRaisedFromCStr` -- these are fire-and-forget TLS setters, not fallible operations.

Design elements this commit produces:
- **Multi-part error message construction pattern**: A new C API pattern for DSL compilers to compose error messages from reusable string parts, reducing binary size for error strings with shared substrings (e.g., function signatures repeated across multiple argument-mismatch errors).

## Usage Examples

From the C++ test (`tests/cpp/test_function.cc`):

```cpp
// Construct error from parts -- NULL entries are skipped
const char* message_parts[] = {"Mismatched", nullptr, " got Tensor"};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", message_parts, 3);
// Result: Error with kind="TypeError", message="Mismatched got Tensor"

// Retrieve via standard TLS error protocol
TVMFFIObjectHandle err;
TVMFFIErrorMoveFromRaised(&err);
```

DSL compiler usage pattern (from commit message):
```c
// Shared parts stored as global constants in compiled DSL output
const char* sig = "matmul(x: Tensor, y: Tensor, z: Tensor)";

// Per-callsite error: "Argument 1 mismatch in matmul(...), dtype mismatch"
const char* parts1[] = {"Argument 1 mismatch in ", sig, ", dtype mismatch"};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts1, 3);

// Per-callsite error: "Argument 2 mismatch in matmul(...), shape[0] mismatch"
const char* parts2[] = {"Argument 2 mismatch in ", sig, ", shape[0] mismatch"};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts2, 3);
// The shared `sig` string is stored once in the binary
```
