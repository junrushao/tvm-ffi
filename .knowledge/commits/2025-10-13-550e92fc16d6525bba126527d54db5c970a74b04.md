# Add TVMFFIErrorSetRaisedFromCStrParts C API for multi-part error message construction

## TL;DR

- Adds `TVMFFIErrorSetRaisedFromCStrParts` to `c_api.h` and `error.cc`: accepts `(kind, const char** parts, int32_t num_parts)`, concatenates non-NULL parts, and stores the result in the TLS error slot — identical semantics to `TVMFFIErrorSetRaisedFromCStr` but avoids duplicating repeated substrings (e.g., function signatures) across many error messages.
- Updates backtrace frame filter (`backtrace_utils.h`) to exclude the new function from stack traces, consistent with the existing exclusion of `TVMFFIErrorSetRaisedFromCStr`.
- Bumps version `0.1.0b16` → `0.1.0b17`; updates docs and compiler-integration guide to mention the new API.

## Key Exports

```python
# C ABI (include/tvm/ffi/c_api.h)
def TVMFFIErrorSetRaisedFromCStrParts(
    kind: const char*,          # Error kind string, e.g. "TypeError"
    message_parts: const char**, # Array of C-string parts; NULL entries are skipped
    num_parts: int32_t,
) -> None: ...
# Interacts with: TVMFFIErrorMoveFromRaised (retrieves from TLS slot),
#                 SafeCallContext::SetRaisedByCstrParts (internal impl),
#                 TVMFFIBacktrace (backtrace captured at call site depth)
# Invariant: Caller must retrieve or discard the TLS error slot before the next
#            safe-call boundary; un-retrieved errors are silently overwritten.
# Contrast with: TVMFFIErrorSetRaisedFromCStr — single C-string, no part array

# Internal implementation (src/ffi/error.cc)
class SafeCallContext:
    def SetRaisedByCstrParts(
        self,
        kind: const char*,
        message_parts: const char**,
        num_parts: int32_t,
        backtrace: const TVMFFIByteArray*,
    ) -> None: ...
    # Allocates a single std::string pre-sized via strlen sum, then appends all
    # non-NULL parts. Constructs Error(kind, message, backtrace) and stores in last_error_.
    # Interacts with: SafeCallContext::ThreadLocal() (TLS accessor),
    #                 TVMFFIBacktrace (called at TVMFFIErrorSetRaisedFromCStrParts depth)
```

## Impact

- API: New exported symbol `TVMFFIErrorSetRaisedFromCStrParts` in `c_api.h`. Purely additive — no existing signatures changed.
- Behavioral: None to existing functions. New function writes the TLS error slot identically to `TVMFFIErrorSetRaisedFromCStr` but accepts a variadic string array.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

Compiler integration (from updated `docs/guides/compiler_integration.md` and test `tests/cpp/test_function.cc`):

```c
// C usage: error with reusable function-signature part
const char* parts[] = {
    "Argument 1 mismatch in `matmul(x: Tensor, y: Tensor)`, ",
    "dtype mismatch"
};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts, 2);
return -1;  // signal error to safe-call boundary

// NULL parts are skipped (test verifies this):
const char* message_parts[] = {"Mismatched", NULL, " got Tensor"};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", message_parts, 3);
// result message: "Mismatched got Tensor"
```

The caller then retrieves the error via `TVMFFIErrorMoveFromRaised` at the safe-call boundary (e.g., inside a `TVMFFISafeCallType` wrapper), identical to the existing `TVMFFIErrorSetRaisedFromCStr` pattern.
