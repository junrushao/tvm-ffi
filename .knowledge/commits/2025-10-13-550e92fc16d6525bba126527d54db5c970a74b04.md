# Add TVMFFIErrorSetRaisedFromCStrParts C API for concatenating reusable error message parts
## TL;DR
- Adds new C API function `TVMFFIErrorSetRaisedFromCStrParts` that constructs an error from an array of C string parts, concatenating them into a single message. NULL parts are skipped.
- Motivated by DSL compiler use case: common substrings (e.g., function signatures) can be stored once and reused across many error messages, reducing binary size.
- Version bump to 0.1.0b17, doc updates, and backtrace frame exclusion for the new function.

## Key Exports

```python

    kind: str,                    # Error kind, e.g. "TypeError", "ValueError"
    message_parts: List[str],     # Array of C strings; NULL entries are skipped
    num_parts: int32              # Length of message_parts array
) -> None:

    Concatenates all non-NULL message_parts into a single message string,
    then stores the error in thread-local storage for retrieval via
    TVMFFIErrorMoveFromRaised.
    """
    # Interacts with: SafeCallContext TLS (same slot as TVMFFIErrorSetRaised/TVMFFIErrorSetRaisedFromCStr)
    # Interacts with: TVMFFIBacktrace (captures backtrace at call site)
    # Interacts with: Error/ErrorObj (constructs the same error object)
    # Invariant: NULL entries in message_parts are silently skipped (not treated as empty strings)
    # Invariant: message is pre-reserved to total_len of all parts for single allocation
    # Extension: compilers store error message fragments as global const strings and compose at runtime
    ...

# Internal implementation:
# SafeCallContext::SetRaisedByCstrParts(kind, message_parts, num_parts, backtrace)
#   1. Two-pass: first pass computes total_len via strlen on non-NULL parts
#   2. message.reserve(total_len) -- single allocation
#   3. Second pass appends non-NULL parts
#   4. Constructs Error(kind, message, backtrace) and stores in TLS
```

## Impact

- Behavioral: none -- existing error functions unchanged. Minor doc fix: `TVMFFIErrorSetRaisedFromCStr` Doxygen `\sa` reference corrected from `TVMFFIMoveFromRaised` to `TVMFFIErrorMoveFromRaised`.

## Design Elements
Design elements this commit consumes:
- **Error protocol TLS propagation** ([0005-ffi-error-protocol](../design-records/0005-ffi-error-protocol.md)): uses the same `SafeCallContext` TLS slot and `Error(kind, message, backtrace)` constructor pattern as `TVMFFIErrorSetRaisedFromCStr`.
- **C ABI surface** ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)): follows the established pattern of `TVM_FFI_DLL` exported C functions with Doxygen doc comments.
- **Backtrace exclusion** (`src/ffi/backtrace_utils.h`): uses existing `ShouldExcludeFrame` symbol-prefix check to hide the new function from backtraces.

Design elements this commit produces:
- **`TVMFFIErrorSetRaisedFromCStrParts` C API**: new public C ABI function for part-based error message construction. Extends the error-setting API family (`TVMFFIErrorSetRaised`, `TVMFFIErrorSetRaisedFromCStr`, now `TVMFFIErrorSetRaisedFromCStrParts`).
- **`SafeCallContext::SetRaisedByCstrParts` internal method**: C++ implementation that does two-pass concatenation with pre-reserved buffer.

## Usage Examples
From the test added in this commit (`tests/cpp/test_function.cc`):
```cpp
// Construct error from reusable parts, with NULL entries skipped
const char* message_parts[] = {"Mismatched", nullptr, " got Tensor"};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", message_parts, 3);
// Retrieves: Error(kind="TypeError", message="Mismatched got Tensor")

// DSL compiler use case: reuse common substrings across error messages
const char* sig = "in `matmul(x: Tensor, y: Tensor)`";
const char* parts1[] = {"Arg 1 mismatch ", sig, ", dtype mismatch"};
const char* parts2[] = {"Arg 2 mismatch ", sig, ", shape[0] mismatch"};
TVMFFIErrorSetRaisedFromCStrParts("TypeError", parts1, 3);
// sig stored once in binary, reused in both error messages
```
