# Add FunctionInfo specializations for ObjectRef member function pointers
## TL;DR
- `FunctionInfo<>` lacked specializations for member function pointers where the class derives from `ObjectRef` (as opposed to `Object`), causing compilation failures when downstream code registered `ObjectRef` member functions as global functions via `def_method`.
- Fixed by adding four SFINAE-guarded `FunctionInfo` specializations that dispatch `ObjectRef`-derived classes to by-value self (`Class` / `const Class`) vs. the existing `Object`-derived classes which use by-pointer self (`Class*` / `const Class*`).
- Added a test exercising the new path: `TestIntPair::Sum()` registered as a global function and validated via Python schema introspection.
- Secondary: cmake libbacktrace logging improvement (non-functional).

## Key Exports

```python
# C++ template specializations (function_details.h)
# These are compile-time type traits, not runtime symbols.

# Before (only Object-derived classes handled):
#   FunctionInfo<R (Class::*)(Args...)>        -> FuncFunctorImpl<R, Class*, Args...>        # Object only
#   FunctionInfo<R (Class::*)(Args...) const>  -> FuncFunctorImpl<R, const Class*, Args...>  # Object only
#   FunctionInfo<R (ObjectRefDerived::*)(Args...)>  -> COMPILATION ERROR (no matching specialization)

# After (Object and ObjectRef both handled, SFINAE-disambiguated):
#   FunctionInfo<R (Class::*)(Args...), enable_if<is_base_of<Object, Class>>>
#       -> FuncFunctorImpl<R, Class*, Args...>          # Object: self by pointer
#   FunctionInfo<R (Class::*)(Args...) const, enable_if<is_base_of<Object, Class>>>
#       -> FuncFunctorImpl<R, const Class*, Args...>    # Object const: self by const pointer
#   FunctionInfo<R (Class::*)(Args...), enable_if<is_base_of<ObjectRef, Class>>>
#       -> FuncFunctorImpl<R, Class, Args...>           # ObjectRef: self by value
#   FunctionInfo<R (Class::*)(Args...) const, enable_if<is_base_of<ObjectRef, Class>>>
#       -> FuncFunctorImpl<R, const Class, Args...>     # ObjectRef const: self by const value
# Interacts with: Function.FromTyped (uses FunctionInfo to infer arg types for schema + unpacking)
# Interacts with: GlobalDef.def_method / ObjectDef.def (wraps member function pointers via GetMethod -> Function.FromTyped)
# Invariant: ObjectRef is NOT derived from Object -- they are separate hierarchies. No SFINAE ambiguity.
# Invariant: Self-parameter convention must match GetMethod: ObjectRef by-value, Object by-pointer.

# Primary template also gains a second defaulted void template parameter for SFINAE:
#   template <typename T, typename = void>
#   struct FunctionInfo : FunctionInfoHelper<decltype(&T::operator())> {};
# All existing explicit specializations updated to include the void second parameter.
```

## Impact
- API: None -- no public API signature changes. The fix enables previously-failing template instantiations.
- Behavioral: `ObjectRef` member functions can now be registered as global functions via `def_method`. Their schema metadata correctly reports the `ObjectRef` subclass as the first (self) argument, passed by value (not pointer). Example: `testing.TestIntPairSum` schema becomes `Callable[[testing.TestIntPair], int]`.
- Flags/config: None
- Data formats/schemas: New global functions registered from `ObjectRef` member pointers will produce schema JSON with the ref class (not object class) as the first argument type.

## Design Elements
Design elements this commit consumes:
- `FunctionInfo<T>` / `FuncFunctorImpl<R, Args...>` compile-time type trait chain -- `include/tvm/ffi/function_details.h`. See [0004-ffi-function-system](../design-records/0004-ffi-function-system.md).
- `ReflectionDefBase::GetMethod` dispatching `ObjectRef` by-value vs `Object` by-pointer -- `include/tvm/ffi/reflection/registry.h`. See [0004-ffi-function-system](../design-records/0004-ffi-function-system.md).
- `GlobalDef.def_method` and `ObjectDef.def` which invoke `GetMethod` -> `Function::FromTyped` -> `FunctionInfo` -- see [0007-ffi-reflection](../design-records/0007-ffi-reflection.md).
- `TypeSchema` Python metadata introspection -- see [0015-ffi-python-type-system](../design-records/0015-ffi-python-type-system.md).

Design elements this commit produces: None -- this is a bugfix extending existing specializations to cover a previously unsupported case.

## Usage Examples

**Before (compilation failure):**
```cpp
class TestIntPair : public ObjectRef {
  int64_t Sum() const { return get()->a + get()->b; }
  TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE(TestIntPair, ObjectRef, TestIntPairObj);
};

// This failed to compile -- no FunctionInfo specialization for ObjectRef member pointers:
refl::GlobalDef()
    .def_method("testing.TestIntPairSum", &TestIntPair::Sum, "Get sum of the pair");
```

**After (works, correct schema):**
```cpp
// Same code now compiles. Schema is correct:
refl::GlobalDef()
    .def_method("testing.TestIntPairSum", &TestIntPair::Sum, "Get sum of the pair");
// Schema: Callable[[testing.TestIntPair], int]
// Self parameter is TestIntPair by value (not TestIntPairObj* by pointer)
```

**Python test validating the schema:**
```python
def test_mem_fn_as_global_func() -> None:
    metadata = get_global_func_metadata("testing.TestIntPairSum")
    type_schema = TypeSchema.from_json_str(metadata["type_schema"])
    assert str(type_schema) == "Callable[[testing.TestIntPair], int]"
```

## Reflection

### Design docs / ADRs to write or update
- `0004-ffi-function-system.md` -- The `FunctionInfo` section should document the full SFINAE dispatch: `Object`-derived -> by-pointer self, `ObjectRef`-derived -> by-value self, with the `enable_if` guards. This was flagged in the prior commit (368af824) but remains undocumented.
