# Add SFINAE-based FunctionInfo specializations for ObjectRef member function pointers
## TL;DR
- Fixes a compilation error when registering an `ObjectRef` member function as a global function via `GlobalDef().def_method()`. The prior `FunctionInfo` specializations for member function pointers (added in 28fe3cc) did not distinguish `Object`-derived from `ObjectRef`-derived classes, producing incorrect type schemas and failing downstream compilation.
- Adds four SFINAE-guarded `FunctionInfo` partial specializations: two for `Object`-derived classes (first arg `Class*`/`const Class*`) and two for `ObjectRef`-derived classes (first arg `Class`/`const Class`). Uses `std::enable_if_t<std::is_base_of_v<...>>` as second template parameter.
- Adds a test registering `TestIntPair::Sum` (an `ObjectRef` member function) as a global function and verifying its type schema resolves to `Callable[[testing.TestIntPair], int]`.

## Key Exports

```python
# FunctionInfo partial specializations (function_details.h):
# BEFORE (28fe3cc): no Object/ObjectRef distinction, strips Class entirely:
#   FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Args...>
#   FunctionInfo<R (Class::*)(Args...) const> : FuncFunctorImpl<R, Args...>
#
# AFTER (this commit): SFINAE dispatch based on base class:
#   FunctionInfo<R (Class::*)(Args...), enable_if<is_base_of<Object, Class>>>
#       : FuncFunctorImpl<R, Class*, Args...>
#   FunctionInfo<R (Class::*)(Args...) const, enable_if<is_base_of<Object, Class>>>
#       : FuncFunctorImpl<R, const Class*, Args...>
#   FunctionInfo<R (Class::*)(Args...), enable_if<is_base_of<ObjectRef, Class>>>
#       : FuncFunctorImpl<R, Class, Args...>
#   FunctionInfo<R (Class::*)(Args...) const, enable_if<is_base_of<ObjectRef, Class>>>
#       : FuncFunctorImpl<R, const Class, Args...>
#
# Invariant: ObjectRef is itself derived from Object (through ObjectRef->Object chain),
#   but ObjectRef specialization is more specific due to SFINAE ordering
#   (is_base_of<ObjectRef, Class> is a stricter match than is_base_of<Object, Class>).
# Interacts with: FuncFunctorImpl::TypeSchema() for JSON type schema generation
# Interacts with: GlobalDef::def_method() which calls FunctionInfo<Func>::TypeSchema()
# Interacts with: ReflectionDefBase::GetMethod() which wraps member functions
#   (ObjectRef by value, Object by pointer) -- must match FunctionInfo's convention

# Primary template also gains SFINAE enabler:
# FunctionInfo<T, void> (was: FunctionInfo<T>)
# All existing specializations gain ", void" second param for consistency
```

## Impact
- API: None -- purely additive specializations, existing code unaffected.
- Behavioral: `FunctionInfo` now correctly includes the `self` parameter in type schemas for member function pointers. `ObjectRef` member functions get `Class` (by value) as first arg; `Object` member functions get `Class*` (by pointer). Previously, member function pointer specializations omitted the class argument entirely.
- Flags/config: None.
- Data formats/schemas: Type schemas for global functions registered via `def_method(&Ref::Method)` now correctly include the self parameter. E.g., `TestIntPair::Sum` yields `Callable[[testing.TestIntPair], int]` instead of `Callable[[], int]`.

## Design Elements
Design elements this commit consumes:
- **FunctionInfo / FuncFunctorImpl** ([0004-function-system.md](../designs/0004-function-system.md)): The compile-time type introspection traits that extract return type, argument types, and type schemas from callable types. `FuncFunctorImpl<R, Args...>` provides `TypeSchema()` used by `GlobalDef::def_method`.
- **ReflectionDefBase::GetMethod** ([0008-reflection.md](../designs/0008-reflection.md)): Wraps member functions into `ffi::Function`, dispatching ObjectRef by value vs Object by pointer via `if constexpr`. The `FunctionInfo` specializations must agree with this dispatch convention.
- **GlobalDef::def_method** ([0008-reflection.md](../designs/0008-reflection.md)): Calls `GetMethod` to wrap the function and `FunctionInfo<Func>::TypeSchema()` to extract the schema. Both must agree on the self argument convention.
- **ObjectDef::def** ([0008-reflection.md](../designs/0008-reflection.md)): Uses same `FunctionInfo` + `GetMethod` pipeline when registering instance methods on object types.

Design elements this commit produces:
- **SFINAE-guarded FunctionInfo for member function pointers**: Correctly maps `Object`-derived member functions to `(Class*, Args...)` and `ObjectRef`-derived to `(Class, Args...)`, aligning `FunctionInfo` schema extraction with `GetMethod`'s wrapping convention.

## Usage Examples
**Registering an ObjectRef member function as a global function (C++ + Python):**
```cpp
// C++ side: ObjectRef with a member function
class TestIntPair : public ObjectRef {
  int64_t Sum() const { return get()->a + get()->b; }
  // ...
};

// Register as global function via def_method
refl::GlobalDef()
    .def_method("testing.TestIntPairSum", &TestIntPair::Sum, "Get sum of the pair");
// FunctionInfo<int64_t (TestIntPair::*)() const> resolves to
//   FuncFunctorImpl<int64_t, const TestIntPair>
// TypeSchema: {"type":"ffi.Function","args":[{"type":"int"},{"type":"testing.TestIntPair"}]}
```
```python
# Python side: verify correct type schema
metadata = get_global_func_metadata("testing.TestIntPairSum")
schema = TypeSchema.from_json_str(metadata["type_schema"])
assert str(schema) == "Callable[[testing.TestIntPair], int]"
```

**Before/after pattern (the bug):**
```python
# BEFORE: FunctionInfo stripped Class from member function pointer
# FunctionInfo<int64_t (TestIntPair::*)() const> -> FuncFunctorImpl<int64_t>
# TypeSchema: Callable[[], int]  <-- missing self parameter, compilation error downstream

# AFTER: FunctionInfo correctly includes self
# FunctionInfo<int64_t (TestIntPair::*)() const> -> FuncFunctorImpl<int64_t, const TestIntPair>
# TypeSchema: Callable[[testing.TestIntPair], int]  <-- correct
```
