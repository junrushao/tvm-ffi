# Add `FunctionInfo` SFINAE specializations for `ObjectRef` member function pointers

## TL;DR
- Adds SFINAE-based `FunctionInfo` specializations that distinguish `Object`-derived classes (passing `Class*`/`const Class*`) from `ObjectRef`-derived classes (passing `Class`/`const Class` by value), fixing compilation errors when an `ObjectRef` member function is registered as a global function via `GlobalDef::def_method`.
- Adds a default `void` second template parameter to the primary `FunctionInfo` template and all existing specializations to enable `std::enable_if_t` SFINAE dispatch.
- Adds a `TestIntPair::Sum()` method and a `testing.TestIntPairSum` global function as a test case for `ObjectRef` member functions registered via `def_method`.

## Key Exports

**`FunctionInfo<R (Class::*)(Args...), std::enable_if_t<std::is_base_of_v<ObjectRef, Class>>>`** (`include/tvm/ffi/function_details.h:124-126`)
- New specialization: maps to `FuncFunctorImpl<R, Class, Args...>` -- passes `ObjectRef` subclass by value (not by pointer).

**`FunctionInfo<R (Class::*)(Args...) const, std::enable_if_t<std::is_base_of_v<ObjectRef, Class>>>`** (`include/tvm/ffi/function_details.h:127-130`)
- New specialization: maps to `FuncFunctorImpl<R, const Class, Args...>` -- passes const `ObjectRef` subclass by value.

**`FunctionInfo<R (Class::*)(Args...), std::enable_if_t<std::is_base_of_v<Object, Class>>>`** (`include/tvm/ffi/function_details.h:117-119`)
- Changed from unconditional specialization to SFINAE-guarded: only matches when `Class` derives from `Object` (but not `ObjectRef`).

**`FunctionInfo<R (Class::*)(Args...) const, std::enable_if_t<std::is_base_of_v<Object, Class>>>`** (`include/tvm/ffi/function_details.h:120-122`)
- Changed from unconditional specialization to SFINAE-guarded: only matches when `Class` derives from `Object`.

**`TestIntPair::Sum()`** (`src/ffi/extra/testing.cc`)
- New method on `TestIntPair` (an `ObjectRef` subclass) returning `int64_t` (sum of `a` and `b`).
- Registered as instance method via `ObjectDef::def("sum", ...)` and as global function via `GlobalDef::def_method("testing.TestIntPairSum", ...)`.

**`testing.TestIntPairSum`** -- new global function exposed to Python with schema `Callable[[testing.TestIntPair], int]`.

## Impact
- API: None for existing users. New `testing.TestIntPairSum` global function added for testing only. The SFINAE-based dispatch is an internal template change that only affects downstream code that passes `ObjectRef` member function pointers to `FunctionInfo` (previously this was a compile error).
- ABI: None -- no struct layout or C ABI changes.
- Behavioral: `FunctionInfo` now correctly generates type schemas for `ObjectRef` member functions: the self parameter is the `ObjectRef` type by value (e.g., `testing.TestIntPair`) instead of by pointer. This matches the calling convention in `GetMethod` which wraps `ObjectRef` member function pointers in a lambda taking `Class target` (by value), unlike `Object` member functions which take `const Class*` (by pointer). The distinction is important because `ObjectRef` types participate in the FFI type system directly (they have `TypeTraits` specializations for by-value passing), while `Object` types must be passed by raw pointer.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`FunctionInfo` / `FuncFunctorImpl` template dispatch** (`.knowledge/designs/function-system.md`): The commit extends the dispatch tree with SFINAE guards to handle the `Object` vs `ObjectRef` distinction in member function pointer specializations.
- **`FunctionInfo` vs `FunctionInfoHelper` distinction** (established in commit 368af82): `FunctionInfo` specializations for member pointers include `Class`/`Class*` in the parameter pack; `FunctionInfoHelper` strips it for lambda `operator()` decomposition.
- **`GlobalDef::def_method` and `ReflectionDefBase::GetMethod`** (`.knowledge/designs/reflection.md`): `GetMethod` already had separate code paths for `ObjectRef`-derived vs `Object`-derived classes (by-value vs by-pointer wrapping), but `FunctionInfo` lacked matching specializations, causing `TypeSchema()` to fail to compile for `ObjectRef` member pointers.
- **`ObjectDef::def` for instance methods** (`.knowledge/designs/reflection.md`): `ObjectDef::def("sum", &TestIntPair::Sum)` registers the method on the type, also using `FunctionInfo` for schema generation.

Design elements this commit produces:
- **SFINAE-based `FunctionInfo` dispatch for `Object` vs `ObjectRef`**: Establishes the four-way specialization pattern: `{Object, ObjectRef} x {non-const, const}` member function pointers, where `Object` derivatives map to `Class*`/`const Class*` and `ObjectRef` derivatives map to `Class`/`const Class` by value. The SFINAE guard uses `std::is_base_of_v` with the more-derived `ObjectRef` check winning over the `Object` check due to partial ordering (both `Object` and `ObjectRef` specializations match for `ObjectRef`, but `ObjectRef` is more specialized).

## Usage Examples

Registering an `ObjectRef` member function as both an instance method and a global function:

```cpp
// ObjectRef subclass with a method
class TestIntPair : public ObjectRef {
  int64_t Sum() const { return get()->a + get()->b; }
  TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE(TestIntPair, ObjectRef, TestIntPairObj);
};

// Register as instance method on the type
refl::ObjectDef<TestIntPairObj>()
    .def("sum", &TestIntPair::Sum, "Method to compute sum of a and b");

// Register as a global function (schema: Callable[[testing.TestIntPair], int])
refl::GlobalDef()
    .def_method("testing.TestIntPairSum", &TestIntPair::Sum, "Get sum of the pair");
```

Python-side usage and schema verification:

```python
from tvm_ffi import get_global_func, get_global_func_metadata
from tvm_ffi.cython.type_info import TypeSchema

metadata = get_global_func_metadata("testing.TestIntPairSum")
schema = TypeSchema.from_json_str(metadata["type_schema"])
assert str(schema) == "Callable[[testing.TestIntPair], int]"

# Also accessible as an instance method
pair = TestIntPair(3, 4)
assert pair.sum() == 7
```
