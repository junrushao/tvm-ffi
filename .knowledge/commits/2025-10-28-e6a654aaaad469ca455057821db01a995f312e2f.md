# Extract torch DLPack addon build into standalone script with AOT and JIT caching
## TL;DR
- Extracts the inline C++ source and build logic for `TorchDLPackExchangeAPI` from `_optional_torch_c_dlpack.py` into a new standalone build script `python/tvm_ffi/utils/_build_optional_c_dlpack.py` that supports both AOT (CLI) and JIT (subprocess) usage.
- Replaces the `torch.utils.cpp_extension.load_inline` compilation path with a custom ninja-based build that caches the shared library at `~/.cache/tvm-ffi/torch_c_dlpack_addon/`, loading it via `ctypes.CDLL` instead of the torch extension module system.
- Adds `TVM_FFI_DISABLE_TORCH_C_DLPACK` env var to suppress automatic extension loading, Windows CI support via `VsDevCmd.bat` discovery, and a `setuptools` test dependency.

## Impact
- API: `_build_ninja` renamed to `build_ninja` in `python/tvm_ffi/cpp/load_inline.py` (was private, now public). External callers using the private name will break.
- Behavioral: Extension loading is no longer eager at module import. Gated behind `TVM_FFI_DISABLE_TORCH_C_DLPACK` env var check. Module-level `_mod` variable removed (no keep-alive reference).
- Flags/config: New `TVM_FFI_DISABLE_TORCH_C_DLPACK` env var (default "0"). New `TVM_FFI_CACHE_DIR` env var for cache location.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DLPackExchangeAPI struct** ([ADR-0015](../ADRs/0015-dlpack-exchange-api-struct.md)): The `TorchDLPackExchangeAPI` C++ singleton implements this struct; the build script produces a shared library exporting it.
- **Inline module compilation pipeline** ([0011-module-system.md](../designs/0011-module-system.md)): Reuses `build_ninja()` from `load_inline.py` for the ninja build step, but does NOT use `load_inline`/`build_inline` end-to-end.
- **Python bindings DLPack fast-path** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): `torch.Tensor.__c_dlpack_exchange_api__` attribute is set by the loader.
- **`FileLock`** (`python/tvm_ffi/utils/lockfile.py`): Used for concurrent-build safety.
- **`libinfo.find_dlpack_include_path()`**: Resolves dlpack headers for the build.

Design elements this commit produces:
- **Standalone addon build script pattern**: A new build pattern where the C++ source lives in a `.py` file as a string constant, and is compiled via a standalone script that generates a ninja build file, compiles, and atomically renames. This differs from `build_inline`/`load_inline` in that it runs as a subprocess (not in-process) and does not use TVM FFI source decoration or `TVM_FFI_DLL_EXPORT_TYPED_FUNC`.
- **TVM_FFI_DISABLE_TORCH_C_DLPACK env var**: Import-time feature gate for the torch extension.
- **TVM_FFI_CACHE_DIR env var**: Overridable cache location (default `~/.cache/tvm-ffi`).

## Usage Examples

**AOT build (CLI)**:
```bash
python python/tvm_ffi/utils/_build_optional_c_dlpack.py --build_dir /tmp/addon_build --build_with_cuda
# Produces: /tmp/addon_build/libtorch_c_dlpack_addon.so
```

**JIT build (triggered by import)**:
```python
# On first import of tvm_ffi (with torch installed), if no cached lib:
# 1. subprocess runs _build_optional_c_dlpack.py --build_dir ~/.cache/tvm-ffi/torch_c_dlpack_addon/
# 2. ctypes.CDLL loads the built .so
# 3. torch.Tensor.__c_dlpack_exchange_api__ = lib.TorchDLPackExchangeAPIPtr()

# To disable:
import os
os.environ["TVM_FFI_DISABLE_TORCH_C_DLPACK"] = "1"
import tvm_ffi  # skips torch extension loading
```

