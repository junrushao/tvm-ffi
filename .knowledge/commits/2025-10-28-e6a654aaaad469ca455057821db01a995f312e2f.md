# Add standalone Python script to build torch C DLPack addon shared library, with JIT and AOT usage modes

## TL;DR
- Introduces `python/tvm_ffi/utils/_build_optional_c_dlpack.py` — a standalone Ninja-based build script for `libtorch_c_dlpack_addon.{so,dll}` that patches old PyTorch versions to support DLPack protocol.
- Refactors `_optional_torch_c_dlpack.py` to use subprocess JIT-build via the new utility instead of inlining the C++ source and calling `load_inline`.
- Adds CI workflow step and Windows `vswhere.exe` locator; adds test coverage for AOT and JIT paths.

## Impact
- API: New standalone build script exposed as `python -m tvm_ffi.utils._build_optional_c_dlpack`.
- Behavioral: JIT build now uses subprocess instead of in-process `load_inline`, enabling proper `TVM_FFI_DISABLE_TORCH_C_DLPACK` isolation.
- Flags/config: `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` env var prevents recursive build on import.
- Data formats/schemas: Output library name is `libtorch_c_dlpack_addon.so` (Linux/macOS) or `libtorch_c_dlpack_addon.dll` (Windows).

## Design Elements

- `tvm_ffi.libinfo.find_dlpack_include_path` — locates DLPack headers for compilation
- `tvm_ffi.utils.lockfile.FileLock` — serializes concurrent JIT builds

Design elements this commit produces:

## Usage Examples

AOT usage:
```bash
python python/tvm_ffi/utils/_build_optional_c_dlpack.py \
  --build_dir /tmp/dlpack_build [--build_with_cuda]
# produces: /tmp/dlpack_build/libtorch_c_dlpack_addon.so
```

JIT usage (triggered automatically on import):
```python
import tvm_ffi  # auto-invokes load_torch_c_dlpack_extension() if torch present
# The loaded ctypes library is kept alive via module-level reference
```
