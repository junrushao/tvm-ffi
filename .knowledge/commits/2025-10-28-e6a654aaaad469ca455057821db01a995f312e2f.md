# Refactor torch C DLPack extension from inline JIT to standalone build script
## TL;DR
- Extracts the ~570 lines of inline C++ source and JIT compilation logic from `_optional_torch_c_dlpack.py` into a standalone build script `python/tvm_ffi/utils/_build_optional_c_dlpack.py` that can be invoked both as a CLI tool (AOT) and as a JIT subprocess from the main module.
- The new build script generates its own `build.ninja` (not using `load_inline`) with cross-platform support (Linux/macOS/Windows), file-locking for parallel safety, and a temporary-file-then-rename atomicity pattern.
- Renames `_build_ninja` to `build_ninja` (public) in `load_inline.py` so the build script can reuse it; adds Windows CI support with VsDevCmd.bat discovery; adds `setuptools` to test dependencies.

## Key Exports
**Functions**:
- `tvm_ffi.cpp.load_inline.build_ninja(build_dir: str) -> None` -- renamed from `_build_ninja` to public, runs ninja in the given build directory.
- `python/tvm_ffi/utils/_build_optional_c_dlpack.py:main()` -- CLI entry point: builds `libtorch_c_dlpack_addon.{so,dll}` for the current Python + PyTorch version combination.
- `python/tvm_ffi/utils/_build_optional_c_dlpack.py:_generate_ninja_build(build_dir, libname, source_path, extra_cflags, extra_ldflags, extra_include_paths) -> None` -- generates a `build.ninja` file for compiling the addon.
- `python/tvm_ffi/utils/_build_optional_c_dlpack.py:get_torch_include_paths(build_with_cuda: bool) -> Sequence[str]` -- returns torch include paths, dispatching between old and new `torch.utils.cpp_extension.include_paths` API.

**Environment Variables**:
- `TVM_FFI_DISABLE_TORCH_C_DLPACK` -- when set to `"1"`, disables the torch C DLPack extension loading at import time.
- `TVM_FFI_CACHE_DIR` -- controls where the JIT-built addon is cached (default `~/.cache/tvm-ffi`).

**CI Utilities**:
- `.github/workflows/utils/locate_vsdevcmd_bat.py:main() -> None` -- locates `VsDevCmd.bat` via `vswhere.exe` for Windows CI, prints path to stdout.

## Impact
- API: `_build_ninja` renamed to `build_ninja` (was private, now public). Direct callers of `_build_ninja` (only internal `build_inline`) updated. No external API breakage since the old name was private.
- ABI: none
- Behavioral: The torch C DLPack extension is no longer built inline via `torch.utils.cpp_extension.load_inline`; instead it is built via a subprocess that uses a custom ninja build and loads the result via `ctypes.CDLL`. The `_mod` module-level keep-alive variable is removed; `load_torch_c_dlpack_extension()` no longer returns a module object. The C++ source is identical (moved, not changed). Loading is now gated on `TVM_FFI_DISABLE_TORCH_C_DLPACK != "1"` and no longer runs unconditionally at module import time. The `libinfo` import is removed from `_optional_torch_c_dlpack.py`.
- Flags/config: New env var `TVM_FFI_DISABLE_TORCH_C_DLPACK` to disable torch extension loading.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack fast-path protocol** (`.knowledge/designs/0018-dlpack-fast-path.md`): The `DLPackExchangeAPI` struct and `TorchDLPackExchangeAPI` implementation that this commit relocates from inline C++ to a standalone build script.
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`): The `build_ninja()` function (formerly `_build_ninja`) and `FileLock` utility reused by the new standalone build script.
- **Python packaging / libinfo** (`.knowledge/designs/0015-python-packaging.md`): `find_dlpack_include_path()` used by the new ninja build generator to locate DLPack headers.

Design elements this commit produces:
- **Standalone torch C DLPack build script**: A new pattern for building framework-specific DLPack addon libraries as standalone shared objects (`.so`/`.dll`) loadable via `ctypes.CDLL`, decoupled from `torch.utils.cpp_extension.load_inline` and from tvm_ffi's own `load_inline`. This enables ahead-of-time packaging of prebuilt addons per Python/PyTorch version combination.
- **Subprocess-based JIT build**: The `_optional_torch_c_dlpack.py` module now delegates building to a subprocess (`sys.executable _build_optional_c_dlpack.py`) rather than calling `load_inline` in-process, avoiding import cycles and enabling the build script to set `TVM_FFI_DISABLE_TORCH_C_DLPACK=1` before importing `tvm_ffi`.

## Usage Examples
**AOT build** (building the addon ahead of time for packaging):
```bash
python python/tvm_ffi/utils/_build_optional_c_dlpack.py --build_dir /tmp/addon_build --build_with_cuda
# Produces: /tmp/addon_build/libtorch_c_dlpack_addon.so
```

**JIT build** (transparent, triggered at import time when no prebuilt library exists):
```python
import tvm_ffi  # internally calls load_torch_c_dlpack_extension()
# -> checks ~/.cache/tvm-ffi/torch_c_dlpack_addon/libtorch_c_dlpack_addon.so
# -> if missing, spawns subprocess to build it
# -> loads via ctypes.CDLL, calls TorchDLPackExchangeAPIPtr()
# -> sets torch.Tensor.__c_dlpack_exchange_api__ = <ptr>
```

**Loading the built library manually** (e.g., from a prebuilt package):
```python
import ctypes
lib = ctypes.CDLL("path/to/libtorch_c_dlpack_addon.so")
func = lib.TorchDLPackExchangeAPIPtr
func.restype = ctypes.c_uint64
func.argtypes = []
ptr = func()  # returns pointer to DLPackExchangeAPI struct
```
