# Re-export core ffi container types and utilities into the tvm:: namespace
## TL;DR
- Adds `using ffi::X;` declarations to 9 headers, re-exporting `Array`, `Map`, `Tuple`, `Variant`, `Optional`, `String`, `Bytes`, `Downcast`, `GetRef`, and `make_object` from `tvm::ffi` into the `tvm::` namespace.
- Establishes a convention: commonly used, unambiguous `tvm::ffi` types get a `using` declaration at the bottom of their defining header, just before `} // namespace tvm`.
- Minor doc fix: `Map::Get` return comment changed from `NullOpt` to `std::nullopt`.

## Key Exports

This commit does not introduce new types or functions. It introduces a **namespace aliasing convention** that re-exports existing `tvm::ffi` symbols into `tvm::`.

```python
# Namespace re-export convention (C++ using-declarations added by this commit):
#
# Pattern: at the bottom of each header, after `} // namespace ffi`,
#          add `using ffi::X;` before `} // namespace tvm`
#
# Symbols re-exported:
#   cast.h:       tvm::Downcast, tvm::GetRef
#   array.h:      tvm::Array
#   map.h:        tvm::Map
#   tuple.h:      tvm::Tuple
#   variant.h:    tvm::Variant
#   optional.h:   tvm::Optional
#   string.h:     tvm::String, tvm::Bytes
#   memory.h:     tvm::make_object
#
# Invariant: only types with "no ambiguity" in the tvm:: namespace are re-exported.
# Invariant: the using-declaration is placed in the tvm:: namespace scope,
#            NOT at global scope — still requires `#include` and `using namespace tvm;`
#            or explicit `tvm::Array` qualification.
# Extension: new ffi types that are commonly used and unambiguous should follow
#            this same pattern in their defining header.
```

## Impact
- API: Additive only. Callers can now write `tvm::Array` instead of `tvm::ffi::Array`. Existing `tvm::ffi::Array` references continue to work.
- Behavioral: none
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Array`, `Map`, `Tuple`, `Variant`, `Optional` — container types from [0006-ffi-containers](../design-records/0006-ffi-containers.md)
- `String`, `Bytes` — string types from [0006-ffi-containers](../design-records/0006-ffi-containers.md)
- `Downcast`, `GetRef` — cast utilities from [0003-ffi-object-system](../design-records/0003-ffi-object-system.md)
- `make_object` — allocation factory from [0003-ffi-object-system](../design-records/0003-ffi-object-system.md)

Design elements this commit produces:
- **Namespace re-export convention**: A new structural convention where `tvm::ffi` symbols are lifted into `tvm::` via `using` declarations. This is a naming/structural convention that governs how container headers expose their types. The selection criterion stated in commit comments: "convenience and no ambiguity."

## Usage Examples

Before this commit, callers had to fully qualify container types:
```cpp
// Before: must use tvm::ffi:: prefix
tvm::ffi::Array<int> arr({1, 2, 3});
tvm::ffi::Map<tvm::ffi::String, int> m;
auto ptr = tvm::ffi::make_object<MyNodeObj>();
auto ref = tvm::ffi::Downcast<MyNode>(obj);
```

After this commit, callers can use the shorter `tvm::` prefix:
```cpp
// After: tvm:: prefix works
tvm::Array<int> arr({1, 2, 3});
tvm::Map<tvm::String, int> m;
auto ptr = tvm::make_object<MyNodeObj>();
auto ref = tvm::Downcast<MyNode>(obj);
```
