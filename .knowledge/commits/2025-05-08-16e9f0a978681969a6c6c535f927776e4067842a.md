# Cleanup container redirections and expose core FFI types into tvm namespace

## TL;DR
- Adds `using` declarations at the end of each core FFI header (just before closing `namespace tvm`) to lift commonly used `tvm::ffi::*` types and functions directly into `namespace tvm`, so downstream code can write `tvm::Array<T>` instead of `tvm::ffi::Array<T>`.
- Also fixes a minor doc comment in `Map::Get` (`NullOpt` changed to `std::nullopt`) and adds a blank line before the closing `namespace ffi` in `function.h`.

## Key Exports

### Namespace Aliases (new `using` declarations in `namespace tvm`)

Each file adds one or more `using` declarations between `}  // namespace ffi` and `}  // namespace tvm`:

- `cast.h`: `using ffi::Downcast;` and `using ffi::GetRef;`
- `container/array.h`: `using ffi::Array;`
- `container/map.h`: `using ffi::Map;`
- `container/tuple.h`: `using ffi::Tuple;`
- `container/variant.h`: `using ffi::Variant;`
- `memory.h`: `using ffi::make_object;`
- `optional.h`: `using ffi::Optional;`
- `string.h`: `using ffi::Bytes;` and `using ffi::String;`

After this commit, all of the following are valid in downstream code without qualifying `ffi::`:
```cpp
tvm::Array<int> arr;
tvm::Map<String, int> map;
tvm::String s("hello");
tvm::Bytes b("raw", 3);
tvm::Optional<int> opt;
tvm::Tuple<int, String> t(1, "a");
tvm::Variant<int, String> v = 42;
auto ref = tvm::GetRef<MyNode>(ptr);
auto sub = tvm::Downcast<MyNode>(base);
auto p = tvm::make_object<MyNodeObj>();
```

### Doc Fix

- `container/map.h` line 1399: `Map::Get` return doc changed from `NullOpt if not found` to `std::nullopt if not found`.

## Impact
- API: Adds convenience aliases; `tvm::ffi::X` remains canonical and still works. No existing code breaks since the `using` declarations only introduce names that did not previously exist in `namespace tvm`.
- ABI: No change. No new symbols, no layout changes.
- Behavioral: Pure namespace aliasing; no runtime behavior change.

## Design Elements
Design elements this commit consumes:
- The `namespace tvm { namespace ffi { ... } }` two-level namespace convention established in the root commit.
- All container and utility types defined in the FFI headers (`Array`, `Map`, `String`, `Bytes`, `Optional`, `Tuple`, `Variant`, `Downcast`, `GetRef`, `make_object`).

Design elements this commit produces:
- **Namespace aliasing convention** -- A pattern for lifting `tvm::ffi::X` into `tvm::X` using `using` declarations placed between the `namespace ffi` and `namespace tvm` closing braces. The rationale stated in the code is "convenience and no ambiguity." This establishes the convention that commonly used types with no naming conflict in the `tvm` namespace should be aliased upward.
- **Shortened container header paths** -- The commit message documents the intended header migration from the old `runtime/` paths to the new `ffi/` paths (e.g., `runtime/container/array.h` to `ffi/container/array.h`, `runtime/container/optional.h` to `ffi/optional.h`). This commit is part of that cleanup.

## Usage Examples

### Before this commit
```cpp
#include <tvm/ffi/container/array.h>
tvm::ffi::Array<int> arr;
auto obj = tvm::ffi::make_object<MyObj>();
auto ref = tvm::ffi::GetRef<MyNode>(ptr);
```

### After this commit
```cpp
#include <tvm/ffi/container/array.h>
tvm::Array<int> arr;          // shorter, via using declaration
auto obj = tvm::make_object<MyObj>();
auto ref = tvm::GetRef<MyNode>(ptr);
// tvm::ffi::Array<int> still works
```
