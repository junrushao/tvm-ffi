# Clean up container header redirections and expose key ffi types into tvm namespace
## TL;DR
- Adds `using ffi::X` declarations at the `tvm` namespace level in 9 headers, exposing `Array`, `Map`, `String`, `Bytes`, `Tuple`, `Variant`, `Optional`, `Downcast`, `GetRef`, and `make_object` directly as `tvm::Array`, `tvm::Map`, etc., eliminating the need for callers to write `tvm::ffi::Array`.
- Fixes a minor doc comment in `Map::Get` (`NullOpt` -> `std::nullopt`), and adds a blank line before `}  // namespace ffi` in `function.h` for formatting consistency.
- Part of a larger migration that redirects legacy `runtime/container/*.h` headers to their new `ffi/container/*.h` locations (the redirections themselves are in the parent TVM repo, not this FFI repo).

## Impact
- API: **Additive namespace aliases.** Downstream code that previously wrote `tvm::ffi::Array<T>` can now write `tvm::Array<T>`. No existing code is broken because `tvm::ffi::Array` remains valid. Impacted callers: any C++ consumer that includes these headers and operates in `namespace tvm`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Container system** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The `using` declarations target the container types (`Array`, `Map`, `String`, `Bytes`, `Tuple`, `Variant`, `Optional`) defined in the container design.
- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `make_object`, `Downcast`, and `GetRef` are core object-system utilities being exposed.
- **C++ namespace convention**: The commit relies on the `namespace tvm { namespace ffi { ... } }` two-level nesting to place `using` declarations between the `}  // namespace ffi` and `}  // namespace tvm` closing braces.

Design elements this commit produces:
- **Namespace aliasing convention**: Establishes the pattern of selectively lifting `tvm::ffi::*` symbols into `tvm::*` via `using` declarations placed at the end of each header, just before the outer `namespace tvm` closing brace. The rationale stated in comments is "convenience and no ambiguity." This is a new convention that future headers should follow when their types are commonly used and unambiguous in the `tvm` root namespace.

## Reflection

### Design docs to write

- **`.knowledge/designs/0008-namespace-aliasing.md`**: Document the convention for lifting `tvm::ffi::*` symbols into `tvm::*`. Should cover: which types are currently aliased, the placement pattern (between `}  // namespace ffi` and `}  // namespace tvm`), the "no ambiguity" criterion for selecting types, and the rationale for not using `using namespace ffi` (which would pull everything). This helps future commits that add new types decide whether and where to add a `using` declaration.
  - Why it helps: Any commit adding a new container or utility type will need to decide whether to add a `tvm::` alias. Without a documented convention, reviewers must re-derive the criteria each time.

### ADRs to write

None. The namespace aliasing decision is a minor convention rather than a significant architectural decision. It is better captured in a design doc than a formal ADR.

### Design diagrams to draw

None. The change is purely about C++ namespace scoping and does not alter any component relationships or data flows.
