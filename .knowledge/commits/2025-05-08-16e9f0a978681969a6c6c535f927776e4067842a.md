# Expose core FFI container types and cast helpers into the tvm:: namespace via using declarations

## TL;DR

- Adds `using ffi::X` declarations at the end of each FFI public header so that `tvm::Array`, `tvm::Map`, `tvm::String`, `tvm::Bytes`, `tvm::Optional`, `tvm::Tuple`, `tvm::Variant`, `tvm::Downcast`, `tvm::GetRef`, and `tvm::make_object` are accessible without the `ffi::` qualifier.
- Fixes one doc comment in `map.h`: `NullOpt` → `std::nullopt` (reflects the actual return type).
- The commit message references broader `runtime/` header redirection cleanup (pointing old `runtime/container/` headers to the new `ffi/` paths), but that work is in the upstream TVM monorepo; this repo's diff is limited to the `using` additions and the doc fix.

## Key Exports

The following `using` declarations are injected into the `tvm` namespace by this commit. Each symbol was already defined in `tvm::ffi`; the declarations are purely namespace-alias additions with no ABI changes.

```python
# In include/tvm/ffi/container/array.h — tvm namespace block
# Before: callers wrote tvm::ffi::Array<T>
# After:  callers write tvm::Array<T>
# using ffi::Array;

# In include/tvm/ffi/container/map.h
# using ffi::Map;
#   Also: doc comment corrected: NullOpt -> std::nullopt for Map::Get()

# In include/tvm/ffi/container/tuple.h
# using ffi::Tuple;

# In include/tvm/ffi/container/variant.h
# using ffi::Variant;

# In include/tvm/ffi/optional.h
# using ffi::Optional;

# In include/tvm/ffi/string.h
# using ffi::Bytes;
# using ffi::String;

# In include/tvm/ffi/cast.h
# using ffi::Downcast;
# using ffi::GetRef;

# In include/tvm/ffi/memory.h
# using ffi::make_object;
```

Invariant: all exposed names are unambiguous within the `tvm` namespace (no pre-existing `tvm::Array`, `tvm::String`, etc.).
No new types or functions are defined; this is purely a namespace promotion.

## Impact

- API: Extends the public API surface so that all container types and cast utilities are addressable as `tvm::X` in addition to `tvm::ffi::X`. Callers that include these headers transitively gain the shorter name for free. No removal of old names.
- Behavioral: None — `using` declarations do not change runtime behavior.
- Flags/config: None.
- Data formats/schemas: None. The doc comment fix (`NullOpt` → `std::nullopt`) is non-functional.

## Design Elements

Design elements this commit consumes:
- **0007-containers** (`include/tvm/ffi/container/`) — `Array`, `Map`, `String`, `Bytes`, `Tuple`, `Variant` are the types being promoted.
- **0002-object-system** (`include/tvm/ffi/memory.h`) — `make_object<T>` is the allocation entry point being promoted.
- **0003-any-anyview** / **0002-object-system** (`include/tvm/ffi/cast.h`) — `Downcast` and `GetRef` are the cast utilities being promoted.
- **0004-function-system** (`include/tvm/ffi/function.h`) — minor whitespace cleanup (blank line before closing namespace); no semantic change.

Design elements this commit produces:
- **Namespace promotion convention**: establishes a pattern where `tvm::ffi` symbols that are stable, unambiguous, and commonly used are brought directly into the `tvm` namespace via `using` at the bottom of their defining header. This is a new architectural convention not previously documented.

## Usage Examples

Before this commit, TVM code outside the ffi layer needed:
```cpp
#include "tvm/ffi/container/array.h"
tvm::ffi::Array<tvm::ffi::String> fields = ...;
tvm::ffi::Downcast<MyNode>(obj);
```

After this commit, the same code can write:
```cpp
#include "tvm/ffi/container/array.h"
tvm::Array<tvm::String> fields = ...;
tvm::Downcast<MyNode>(obj);
```

The change is purely syntactic; the types and functions are identical.
