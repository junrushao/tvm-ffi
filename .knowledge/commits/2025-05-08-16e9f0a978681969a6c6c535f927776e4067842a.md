# Cleanup container redirections: expose ffi types into tvm namespace

## TL;DR
- Adds `using` declarations to expose commonly-used `tvm::ffi::*` types and functions into the `tvm::` namespace for convenience: `Array`, `Map`, `Tuple`, `Variant`, `Optional`, `String`, `Bytes`, `Downcast`, `GetRef`, and `make_object`.
- Fixes a minor doc comment in `Map::Get()` (`NullOpt` -> `std::nullopt`).

## Key Exports

```python
# === Namespace re-exports (tvm namespace) ===
# These are `using` declarations at the end of each header file,
# placed inside `namespace tvm { }` but outside `namespace ffi { }`.

# From cast.h:
tvm::Downcast  = tvm::ffi::Downcast   # Downcast ObjectRef to a subtype
tvm::GetRef    = tvm::ffi::GetRef     # Get ObjectRef from raw Object pointer

# From container/array.h:
tvm::Array     = tvm::ffi::Array      # Immutable typed array

# From container/map.h:
tvm::Map       = tvm::ffi::Map        # Immutable insertion-ordered map

# From container/tuple.h:
tvm::Tuple     = tvm::ffi::Tuple      # Fixed-size heterogeneous tuple

# From container/variant.h:
tvm::Variant   = tvm::ffi::Variant    # Type-safe union over ObjectRef subtypes

# From memory.h:
tvm::make_object = tvm::ffi::make_object  # Allocate and construct Object

# From optional.h:
tvm::Optional  = tvm::ffi::Optional   # Optional wrapper for ObjectRef types

# From string.h:
tvm::String    = tvm::ffi::String     # Immutable UTF-8 string
tvm::Bytes     = tvm::ffi::Bytes      # Immutable byte array
```

## Impact
- API: No new types or functionality. Existing `tvm::ffi::*` APIs are now also accessible as `tvm::*`. This is a pure convenience change for downstream code that uses the `tvm` namespace directly.
- Behavioral: No behavioral changes.
- Flags/config: No changes.
- Data formats/schemas: No changes.

## Design Elements

Design elements this commit consumes:
- The existing `tvm::ffi` namespace containing all core FFI types (Array, Map, String, etc.)
- The `ObjectRef` hierarchy and container system from commit 7d34eb8

Design elements this commit produces:
- **tvm namespace re-exports**: A convention where commonly-used `tvm::ffi::*` types are exposed into `tvm::` via `using` declarations at the end of their respective header files. The rationale stated in comments is "convenience and no ambiguity."

## Usage Examples

**Before this commit:**
```cpp
#include <tvm/ffi/container/array.h>
tvm::ffi::Array<int> arr({1, 2, 3});
auto obj = tvm::ffi::make_object<MyNodeObj>();
tvm::ffi::String s("hello");
```

**After this commit (both forms work):**
```cpp
#include <tvm/ffi/container/array.h>
tvm::Array<int> arr({1, 2, 3});         // shorter form via using declaration
auto obj = tvm::make_object<MyNodeObj>(); // shorter form
tvm::String s("hello");                  // shorter form
// tvm::ffi::Array<int> still works    // original form still valid
```
