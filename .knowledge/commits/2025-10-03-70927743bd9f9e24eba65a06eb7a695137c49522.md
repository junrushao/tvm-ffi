# Fix memory leak in Cython tensor return path when DLPack fast-path converts allocated tensors back to framework tensors
## TL;DR
- Fixes a memory leak in `make_tensor_from_chandle` where the original `chandle` (FFI object handle) was not DecRef'd after a successful DLPack-to-PyObject conversion, causing the underlying `TensorObj` refcount to grow unbounded on repeated calls.
- Adds cleanup of the `DLManagedTensorVersioned` struct in the exception fallback path (calls `dlpack.deleter(dlpack)`) to prevent a secondary leak when the `c_dlpack_to_pyobject` call fails.
- Adds a CUDA memory leak regression test (`test_cuda_memory_alloc_noleak`) that allocates tensors via `Tensor::FromDLPackAlloc` in a loop and asserts GPU memory does not grow.
- Version bump: 0.1.0b14 -> 0.1.0b15.

## Key Exports
None -- this is a bugfix to internal Cython code. No new public API symbols are introduced or changed.

## Impact
- API: None
- ABI: None
- Behavioral: Fixes unbounded GPU/CPU memory growth when C++ kernel code returns `ffi::Tensor` objects allocated via `Tensor::FromDLPackAlloc` and the DLPack fast-path converts them to framework tensors (e.g., `torch.Tensor`). Before this fix, each such return leaked one refcount on the underlying `TensorObj`, preventing deallocation. Affects any workflow using `TVMFFIEnvGetTensorAllocator()` + `Tensor::FromDLPackAlloc` with the DLPack return conversion path.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- DLPack fast-path return conversion: `make_tensor_from_chandle` calls `c_dlpack_to_pyobject` to convert `DLManagedTensorVersioned*` back to a framework tensor (`.knowledge/designs/0018-dlpack-fast-path.md`)
- Cached `DLManagedTensorVersioned` on `TensorObj`: `TVMFFITensorToDLPackVersioned` returns a cached struct whose deleter only does `TVMFFIObjectDecRef` (`.knowledge/designs/0018-dlpack-fast-path.md`)
- Intrusive ref-counting: `TVMFFIObjectDecRef` decrements `strong_ref_count`; the object is freed when the count reaches zero (`.knowledge/designs/memory.md`)
- Cython `Object.__dealloc__` calls `TVMFFIObjectDecRef(chandle)` for normal return path (`.knowledge/designs/0014-python-bindings.md`)
- Environment tensor allocator: `Tensor::FromDLPackAlloc(TVMFFIEnvGetTensorAllocator(), ...)` allocates tensors in the caller's framework memory pool (`.knowledge/designs/0018-dlpack-fast-path.md`)

Design elements this commit produces:
- **Ownership transfer invariant for `make_tensor_from_chandle`**: When the DLPack fast-path succeeds, ownership of `chandle` is split into two references: (1) the `DLManagedTensorVersioned` deleter holds a reference (via `TVMFFIObjectIncRef` inside `ToDLPackVersioned`), and (2) the original `chandle` passed in. The framework tensor (e.g., `torch.Tensor`) obtained from `c_dlpack_to_pyobject` will eventually trigger the DLPack deleter, handling reference (1). The fix explicitly calls `TVMFFIObjectDecRef(chandle)` for reference (2), since the returned Python object is the framework tensor, not a Cython `Object` with `chandle` set, so `Object.__dealloc__` would never decref it.
- **Exception path cleanup**: When `c_dlpack_to_pyobject` fails, the `DLManagedTensorVersioned` struct's deleter is called to free the DLPack wrapper (which decrefs the `TensorObj`), and execution falls through to the default path where `chandle` is stored in a new `Tensor` Python object (whose `__dealloc__` will eventually decref it).

## Usage Examples

### Before/after: the leak pattern
**Context**: C++ kernel allocates an output tensor via the environment allocator and returns it. The Cython return path converts via DLPack fast-path.

Before (leaky):
```cython
# In make_tensor_from_chandle, after successful c_dlpack_to_pyobject:
c_dlpack_to_pyobject(dlpack, &py_obj)
tensor = <Tensor>(<PyObject*>py_obj)
Py_DECREF(tensor)
return tensor
# BUG: chandle still holds a ref that is never decremented.
# The returned `tensor` is a torch.Tensor, not a Cython Object,
# so Object.__dealloc__ never fires for chandle.
```

After (fixed):
```cython
# In make_tensor_from_chandle, after successful c_dlpack_to_pyobject:
c_dlpack_to_pyobject(dlpack, &py_obj)
tensor = <Tensor>(<PyObject*>py_obj)
Py_DECREF(tensor)
# decref original handle to prevent leak.
# DLManagedTensor also holds a reference to the tensor
# so we need to decref the original handle if the conversion is successful
TVMFFIObjectDecRef(chandle)
return tensor
```

### Regression test pattern
**Context**: The test verifies GPU memory does not grow when repeatedly calling a C++ function that returns an allocated tensor.
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_sources=r"""
        ffi::Tensor return_tensor(tvm::ffi::TensorView x) {
            ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
                TVMFFIEnvGetTensorAllocator(), x.shape(), x.dtype(), x->device);
            return y;
        }
    """,
    functions=["return_tensor"],
)
x = torch.arange(1024 * 1024, dtype=torch.float32, device="cuda")
current_allocated = torch.cuda.memory_allocated()
for i in range(8):
    mod.return_tensor(x)
    diff = torch.cuda.memory_allocated() - current_allocated
    assert diff <= 1024**2 * 8  # memory must not grow
```
