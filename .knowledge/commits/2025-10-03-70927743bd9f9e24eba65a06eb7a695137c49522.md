# Fix memory leak when a Tensor allocated in an FFI function is returned to Python

## TL;DR
- In `python/tvm_ffi/cython/tensor.pxi`, `make_tensor_from_chandle` now calls `TVMFFIObjectDecRef(chandle)` after a successful DLPack-to-Python conversion to release the original `ObjectHandle` ref (ownership transferred to `DLManagedTensor`).
- On DLPack conversion failure, `dlpack.deleter(dlpack)` is now called to free the intermediate `DLManagedTensor` memory before falling back to the plain Tensor path.
- Adds a CUDA regression test `test_cuda_memory_alloc_noleak` that detects growing allocation across 8 repeated round-trips.

## Key Exports

```python
# python/tvm_ffi/cython/tensor.pxi — make_tensor_from_chandle (internal Cython helper)
# Before (leak path):
#   c_dlpack_to_pyobject(dlpack, &py_obj)   # creates DLManagedTensor + Python capsule
#   tensor = <Tensor>(py_obj)
#   Py_DECREF(tensor)
#   return tensor
#   # BUG: chandle still holds a ref; DLManagedTensor also holds a ref → net +1 leak

# After (fixed path):
#   c_dlpack_to_pyobject(dlpack, &py_obj)
#   tensor = <Tensor>(py_obj)
#   Py_DECREF(tensor)
#   TVMFFIObjectDecRef(chandle)              # ← release original handle ref
#   return tensor

# After (exception path, also fixed):
#   except Exception:
#       dlpack.deleter(dlpack)              # ← free DLManagedTensor on failure
#       pass  # fall through to plain Tensor path

# Invariant (restored): when DLPack conversion succeeds, ownership count for the
# underlying TensorObj is exactly 1 (held by DLManagedTensor's deleter).
# Interacts with: TVMFFIObjectDecRef (C ABI), DLManagedTensor.deleter protocol
```

## Impact
- API: None — `make_tensor_from_chandle` is an internal Cython helper.
- Behavioral: Eliminates reference count leak for Tensor objects allocated inside FFI functions and returned to Python. Without this fix, each such return permanently leaked one ref-count unit, preventing the TensorObj from ever being deallocated.
- Flags/config: Version bump in `pyproject.toml` and `python/tvm_ffi/__init__.py`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `Tensor`/`TensorObj` ref-count lifecycle (0002-object-system, 0006-containers) — `TVMFFIObjectDecRef` is the ref-count decrement API; the bug was a missing call after transferring ownership to DLManagedTensor.
- `DLManagedTensor` deleter protocol (0007-c-abi) — `dlpack.deleter(dlpack)` is the required cleanup for a `DLManagedTensor` that will not be consumed.
- Python Cython bindings `make_tensor_from_chandle` (0012-python-bindings) — internal conversion path from C handle to Python `Tensor` object.

Design elements this commit produces:
- None — fixes an existing path; no new design elements.

## Usage Examples

```python
# Regression test pattern (tests/python/test_load_inline.py):
import torch, tvm_ffi.cpp

mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_sources=r"""
        ffi::Tensor return_tensor(tvm::ffi::TensorView x) {
            return ffi::Tensor::FromDLPackAlloc(
                TVMFFIEnvGetTensorAllocator(), x.shape(), x.dtype(), x->device);
        }
    """,
    functions=["return_tensor"],
)
baseline = torch.cuda.memory_allocated()
for _ in range(8):
    mod.return_tensor(x)  # before fix: memory grew by ~4MB per call
    assert torch.cuda.memory_allocated() - baseline <= 8 * 1024**2  # after fix: stable
```
