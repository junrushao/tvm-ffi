# Fix memory leak in Cython tensor DLPack return path by decrementing original handle after ownership transfer

## TL;DR
- Fixes a reference count leak in `make_tensor_from_chandle` (Cython `tensor.pxi`): when a TVM FFI tensor is successfully converted to a framework tensor via `c_dlpack_to_pyobject`, the original `chandle` was never decremented, causing the underlying tensor memory to never be freed.
- Adds `TVMFFIObjectDecRef(chandle)` on the success path and `dlpack.deleter(dlpack)` on the error path to ensure correct ownership semantics.
- Adds a CUDA memory leak regression test (`test_cuda_memory_alloc_noleak`).

## Key Exports
None. This commit modifies an internal Cython helper function; no new public API is introduced.

## Impact
- API: None. No public API changes.
- Behavioral: `make_tensor_from_chandle` now correctly transfers refcount ownership to `DLManagedTensorVersioned` on successful DLPack conversion, preventing memory leaks for tensors allocated inside FFI functions and returned to Python.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **C ABI refcount management** (`TVMFFIObjectDecRef`): Used to decrement the original handle after ownership is transferred to DLManagedTensor. See [0001-c-abi-layer.md](../designs/0001-c-abi-layer.md).
- **DLPack interop layer** (`make_tensor_from_chandle`, `c_dlpack_to_pyobject`, `TVMFFITensorToDLPackVersioned`): The tensor conversion path where the leak occurred. See [0017-dlpack-interop.md](../designs/0017-dlpack-interop.md).
- **DLManagedTensorVersioned deleter contract**: The DLPack deleter holds its own reference to the tensor. After `c_dlpack_to_pyobject` succeeds, the original `chandle` is a surplus reference that must be released.

Design elements this commit produces:
- None. No new design elements; this is a correctness fix for existing ownership semantics.

## Usage Examples
**Before (incorrect)**: When a C++ FFI function allocates a tensor and returns it to Python, the Cython code creates a DLManagedTensorVersioned and converts it to a framework tensor (e.g., PyTorch). The DLManagedTensor's deleter holds a reference to the underlying TVM tensor. However, the original `chandle` was also alive, resulting in refcount = 2 where only 1 is tracked. The tensor is never freed.

**After (correct)**:
```cython
# In make_tensor_from_chandle, success path:
c_dlpack_to_pyobject(dlpack, &py_obj)
tensor = <Tensor>(<PyObject*>py_obj)
Py_DECREF(tensor)
# NEW: decref original handle -- DLManagedTensor holds its own reference
TVMFFIObjectDecRef(chandle)
return tensor

# In make_tensor_from_chandle, error path:
except Exception:
    # NEW: free DLManagedTensorVersioned since we fall back to raw chandle
    dlpack.deleter(dlpack)
    pass
```

**Regression test pattern** (from `tests/python/test_load_inline.py`):
```python
x = torch.arange(1024 * 1024, dtype=torch.float32, device="cuda")
current_allocated = torch.cuda.memory_allocated()
for i in range(8):
    mod.return_tensor(x)  # allocates tensor in C++, returns to Python
    diff = torch.cuda.memory_allocated() - current_allocated
    assert diff <= 1024**2 * 8  # memory should not grow
```
