# Fix memory leak in Cython tensor DLPack return path by decrefing original chandle
## TL;DR
- Fixed a memory leak in `make_tensor_from_chandle` where `TVMFFIObjectDecRef(chandle)` was missing after successful DLPack-to-PyObject conversion, causing the original object handle's refcount to never drop to zero.
- Added `dlpack.deleter(dlpack)` in the exception path to free the `DLManagedTensorVersioned` struct when `c_dlpack_to_pyobject` fails and the code falls through to chandle-based return.
- Version bump 0.1.0b14 -> 0.1.0b15.

## Key Exports

None -- no new public API. The fix is internal to `make_tensor_from_chandle` in `tensor.pxi`.

## Impact
- API: none
- Behavioral: Tensors allocated inside C++ FFI functions and returned to Python via the DLPack fast-path (e.g., `Tensor::FromDLPackAlloc`) no longer leak memory. Previously, every such return leaked one refcount on the underlying `TensorObj`, preventing the GPU/CPU memory from being reclaimed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack C fast-path protocols** (`c_dlpack_to_pyobject`): The `DLPackToPyObject` function pointer used to convert a `DLManagedTensorVersioned*` into a Python tensor object. Documented in [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **Object refcounting** (`TVMFFIObjectDecRef`): The C ABI refcount decrement. Documented in [0002-object-system.md](../designs/0002-object-system.md) and [0001-c-abi.md](../designs/0001-c-abi.md).
- **`TVMFFITensorToDLPackVersioned`**: C ABI function that creates a `DLManagedTensorVersioned` from a tensor handle, adding a new reference. Documented in [0001-c-abi.md](../designs/0001-c-abi.md).

Design elements this commit produces:
- **Invariant: `make_tensor_from_chandle` ownership transfer protocol** -- When the DLPack conversion succeeds, `chandle` ownership is transferred to the `DLManagedTensorVersioned` (which holds its own IncRef'd reference), so the caller's `chandle` reference must be DecRef'd. When conversion fails, the DLPack struct must be cleaned up via `dlpack.deleter(dlpack)` since the code falls through to use `chandle` directly.

## Usage Examples

**Before (leak):**
```python
# C++ function allocates a tensor and returns it:
#   ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(allocator, shape, dtype, device);
#   return y;
# In Python, each call leaks the tensor's refcount:
for i in range(1000):
    mod.return_tensor(x)  # GPU memory grows unbounded
```

**After (fixed):**
```python
# Same C++ function, but now make_tensor_from_chandle calls
# TVMFFIObjectDecRef(chandle) after successful DLPack conversion.
for i in range(1000):
    mod.return_tensor(x)  # GPU memory stays constant
    # Verified by: torch.cuda.memory_allocated() does not grow
```

Test from commit (`tests/python/test_load_inline.py::test_cuda_memory_alloc_noleak`):
```python
x = torch.arange(1024 * 1024, dtype=torch.float32, device="cuda")
current_allocated = torch.cuda.memory_allocated()
for i in range(8):
    mod.return_tensor(x)
    diff = torch.cuda.memory_allocated() - current_allocated
    assert diff <= 1024**2 * 8  # memory does not grow
```
