# Fix memory leak when tensor allocated in FFI returns to Python via DLPack
## TL;DR
- Fixes a reference count leak in `make_tensor_from_chandle` (Cython): after successfully converting to a DLManagedTensor-backed Python object, the original `chandle` was not DecRef'd, leaking the FFI tensor object.
- Adds cleanup in the exception path: if PyTorch DLPack import fails, the DLManagedTensor deleter is called to free the exported capsule before falling back to the default path.
- Adds a CUDA memory leak regression test that allocates tensors in a loop and asserts memory does not grow.

## Impact
- API: None — behavioral fix only.
- Flags/config: Version bump to 0.1.0b15.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DLPack exchange protocol** (`.knowledge/designs/0020-dlpack-exchange-acceleration.md`): The `c_dlpack_to_pyobject` path that exports a TVM tensor as DLManagedTensor and imports it into a framework (PyTorch). The ownership transfer semantics require the original handle to be released.
- **Python bindings / Cython** (`.knowledge/designs/0014-python-bindings.md`): `make_tensor_from_chandle` is the Cython function that decides how to materialize a returned tensor handle into a Python object.

Design elements this commit produces:
- **Ownership transfer invariant for DLPack return path**: After `c_dlpack_to_pyobject` succeeds, ownership is held by the DLManagedTensor (which itself holds a ref). The original `chandle` must be DecRef'd. On failure, the DLManagedTensor's deleter must be called to avoid a double-hold.
