# Clarify Function ABI: move cpp_call into C struct, remove ImportedFunctionObjImpl and RedirectCallToSafeCall

## TL;DR
- Adds `void* cpp_call` field to the C ABI struct `TVMFFIFunctionCell` alongside `safe_call`, making the dual-path calling convention visible at the C level rather than hidden in the C++ `FunctionObj`.
- Removes `FunctionObj::call` (the C++-only `FCall` field) and `FunctionObj::SafeCall` static method; `CallPacked` now branches on `cpp_call != nullptr` to choose between the C++ fast path and a `safe_call` fallback via `CppCallDedirectToSafeCall`.
- Removes `ImportedFunctionObjImpl`, `RedirectCallToSafeCall<Derived>` CRTP base, and `Function::ImportFromExternDLL`. Cross-DLL functions now rely solely on `cpp_call == nullptr` to force safe_call routing.
- Adds `ExternCFunctionObjNullHandleImpl` as an optimized specialization for raw C function pointers (null handle, null deleter).
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro signature changes: `args` parameter becomes `const TVMFFIAny*` (was `TVMFFIAny*`).

## Impact
- API: **ABI-breaking**. `TVMFFIFunctionCell` gains a new `void* cpp_call` field, changing its size from 8 to 16 bytes. `FunctionObj::call` field removed. `Function::ImportFromExternDLL` removed. `TVM_FFI_DLL_EXPORT_TYPED_FUNC` args becomes `const TVMFFIAny*`.
- Behavioral: `CallPacked` now uses branchless select on `cpp_call` instead of always calling through `call`. Non-C++ functions (external/C callbacks) route through `safe_call` via the fallback. The `ImportFromExternDLL` same-DLL detection heuristic is eliminated entirely.
- Flags/config: none
- Data formats/schemas: none

- **FunctionObj dual call paths** (`.knowledge/designs/0004-function-system.md`) -- restructured from `safe_call`+`call` to `safe_call`+`cpp_call`

- **TVM_FFI_CHECK_SAFE_CALL** (`.knowledge/designs/0004-function-system.md`) -- used in `CppCallDedirectToSafeCall`

Design elements this commit produces:
- **TVMFFIFunctionCell.cpp_call** -- new `void*` field in the C ABI struct, making the C++ fast-path call pointer visible to C-level code
- **ExternCFunctionObjNullHandleImpl** -- lightweight FunctionObj for raw C function pointers without closure
- **CppCallDedirectToSafeCall** -- private fallback in `FunctionObj` for functions without a `cpp_call`

Design elements this commit removes:
- **ImportedFunctionObjImpl** -- previously wrapped cross-DLL functions
- **RedirectCallToSafeCall<Derived>** -- CRTP base for routing `call` through `safe_call`
- **Function::ImportFromExternDLL** -- cross-DLL function wrapping with same-DLL detection heuristic
- **FunctionObj::SafeCall** -- protected static method (now each subclass provides its own SafeCall)
- **FunctionObj::call** -- the `FCall` field (replaced by `cpp_call` void* in C struct)

## Usage Examples
Creating a Function from a C-style exported function (from the new test):

```cpp
// Declare a typed function
int testing_add1(int x) { return x + 1; }

// Export it as a C symbol via TVM_FFI_DLL_EXPORT_TYPED_FUNC
TVM_FFI_DLL_EXPORT_TYPED_FUNC(testing_add1, testing_add1);

// Create a Function from the exported C symbol (null handle, null deleter)
// This uses the new ExternCFunctionObjNullHandleImpl path
Function fadd1 = Function::FromExternC(nullptr, __tvm_ffi_testing_add1, nullptr);
EXPECT_EQ(fadd1(1).cast<int>(), 2);
```
