# Fix metadata/doc string allocation to use libtvm_ffi, avoiding use-after-unload

## TL;DR
- Changes `TVM_FFI_DLL_EXPORT_TYPED_FUNC` and `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` metadata macros to allocate returned strings via `TVMFFIStringFromByteArray` (a C ABI function in libtvm_ffi) instead of constructing `tvm::ffi::String` directly in the DSO's code.
- This ensures the returned metadata/doc String objects are allocated in libtvm_ffi's heap, not the DSO's, preventing use-after-unload when the DSO is `dlclose`d before the string is freed.
- Follows the same pattern previously applied to `TVMFFIEnvTensorAlloc` (f679fe54) and Python string/bytes creation (043d9f6).

## Key Exports

No new public API. The change is internal to two existing macro bodies. The behavioral contract is unchanged (same string content returned), but the allocation ownership shifts.

```python
# TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function):
#   When TVM_FFI_DLL_EXPORT_INCLUDE_METADATA == 1, emits __tvm_ffi__metadata_<ExportName>:
#
#   BEFORE (ac7bf68):
#     tvm::ffi::String str(os.str());                          # String allocated in DSO heap
#     TypeTraits<String>::MoveToAny(std::move(str), result);   # Result holds DSO-allocated string
#
#   AFTER (dcacb98):
#     std::string data = os.str();                             # Temporary in DSO stack
#     TVMFFIByteArray data_array{data.data(), data.size()};    # Points to stack data
#     return TVMFFIStringFromByteArray(&data_array, result);   # String allocated in libtvm_ffi
#   # Invariant: returned String object's memory is owned by libtvm_ffi, survives DSO unload
#   # Interacts with: TVMFFIStringFromByteArray (C ABI, defined in libtvm_ffi/object.cc)
#   # Interacts with: LibraryModuleObj.GetFunctionMetadata (caller that invokes the exported symbol)

# TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC(ExportName, DocString):
#   When TVM_FFI_DLL_EXPORT_INCLUDE_METADATA == 1, emits __tvm_ffi__doc_<ExportName>:
#
#   BEFORE (ac7bf68):
#     tvm::ffi::String str(DocString);                         # String allocated in DSO heap
#     TypeTraits<String>::MoveToAny(std::move(str), result);
#
#   AFTER (dcacb98):
#     std::string_view data(DocString);                        # Points to DSO's .rodata (literal)
#     TVMFFIByteArray data_array{data.data(), data.size()};
#     return TVMFFIStringFromByteArray(&data_array, result);   # String allocated in libtvm_ffi
#   # Invariant: same as above -- string lives in libtvm_ffi heap
#   # Interacts with: TVMFFIStringFromByteArray
#   # Interacts with: LibraryModuleObj.GetFunctionDoc (caller)
```

## Impact
- API: None -- no public API changes. Macro interface unchanged.
- Behavioral: Metadata and doc strings returned by DSO-exported symbols are now allocated in libtvm_ffi's heap instead of the DSO's. This prevents a use-after-unload crash if the caller retains the string after `dlclose` of the DSO.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **TVMFFIStringFromByteArray C ABI function** ([0001-c-abi.md](../designs/0001-c-abi.md)): Used as the allocation mechanism to ensure string memory lives in libtvm_ffi. Introduced in 043d9f6 for Python string/bytes creation.
- **TVM_FFI_DLL_EXPORT_TYPED_FUNC / TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC macros** ([0004-function-system.md](../designs/0004-function-system.md)): The two macro bodies modified by this commit.
- **Module-must-outlive-returned-objects invariant** ([0011-module-system.md](../designs/0011-module-system.md)): The broader pattern that motivates this fix -- objects allocated in DSO code space are invalidated by `dlclose`.
- **TVM_FFI_SAFE_CALL_BEGIN/END boundary** ([0004-function-system.md](../designs/0004-function-system.md)): The metadata/doc exported functions use this safe-call wrapper.

Design elements this commit produces:
- None -- no new design elements. This tightens an existing invariant.

## Usage Examples

Before/after pattern showing the fix:

```cpp
// BEFORE (ac7bf68): String object allocated in DSO heap
// In __tvm_ffi__metadata_MyFunc (compiled into my_lib.so):
//   tvm::ffi::String str(os.str());  // <-- str's backing memory is in my_lib.so's heap
//   TypeTraits<String>::MoveToAny(std::move(str), result);
//
// After dlclose(my_lib.so), the String's destructor address and backing memory are invalid.
// If caller still holds the String -> use-after-unload crash.

// AFTER (dcacb98): String object allocated in libtvm_ffi
// In __tvm_ffi__metadata_MyFunc (compiled into my_lib.so):
//   std::string data = os.str();  // temporary, on stack
//   TVMFFIByteArray data_array{data.data(), data.size()};
//   return TVMFFIStringFromByteArray(&data_array, result);
//   // TVMFFIStringFromByteArray runs in libtvm_ffi, allocates String there.
//   // After dlclose(my_lib.so), the String is still valid -- it lives in libtvm_ffi.
```
