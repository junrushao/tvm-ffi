# Fix metadata string allocation to use libtvm_ffi to avoid use-after-unload

## TL;DR
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` and `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` macros now allocate their returned metadata/doc strings via `TVMFFIStringFromByteArray` (in libtvm_ffi) instead of constructing a local `tvm::ffi::String` and moving it into the result.
- This prevents a use-after-free when the DLL that exported the metadata symbol is unloaded before the returned string is consumed, since the string memory now lives in the long-lived libtvm_ffi allocator.

## Key Exports

```python
# No new public API surfaces. The two macros retain the same external interface:

# TVM_FFI_DLL_EXPORT_TYPED_FUNC(ExportName, Function)
#   -> extern "C" __tvm_ffi__metadata_<ExportName>
#   Old: tvm::ffi::String str(os.str()); TypeTraits<String>::MoveToAny(move(str), result);
#   New: std::string data = os.str(); TVMFFIByteArray arr{data.data(), data.size()}; TVMFFIStringFromByteArray(&arr, result);
#   Invariant: returned String is now allocated in libtvm_ffi heap, outlives the exporting DLL
#   Interacts with: TVMFFIStringFromByteArray (C ABI in libtvm_ffi), LibraryModuleObj::GetFunctionMetadata

# TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC(ExportName, DocString)
#   -> extern "C" __tvm_ffi__doc_<ExportName>
#   Old: tvm::ffi::String str(DocString); TypeTraits<String>::MoveToAny(move(str), result);
#   New: std::string_view data(DocString); TVMFFIByteArray arr{data.data(), data.size()}; TVMFFIStringFromByteArray(&arr, result);
#   Invariant: returned String is now allocated in libtvm_ffi heap, outlives the exporting DLL
#   Interacts with: TVMFFIStringFromByteArray (C ABI in libtvm_ffi), LibraryModuleObj::GetFunctionDoc
```

## Impact
- API: None -- the exported C symbols (`__tvm_ffi__metadata_*`, `__tvm_ffi__doc_*`) retain the same signature and SafeCall convention.
- Behavioral: Metadata/doc strings are now allocated in the libtvm_ffi address space rather than in the exporting DLL's local heap. This fixes a latent use-after-free when DLLs are unloaded while their metadata strings are still referenced.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `TVMFFIStringFromByteArray` C ABI function ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)) -- used to allocate the string in libtvm_ffi's heap.
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro ([0004-ffi-function-system](../design-records/0004-ffi-function-system.md)) -- the metadata export path within this macro is the fix target.
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC_DOC` macro ([0004-ffi-function-system](../design-records/0004-ffi-function-system.md)) -- the doc export path is the other fix target.
- `TVMFFIByteArray` struct ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)) -- used to pass byte data to `TVMFFIStringFromByteArray`.
- Module-object lifetime invariant ([0011-ffi-module-system](../design-records/0011-ffi-module-system.md)) -- the invariant that objects must be destroyed before module unloads is what this fix ensures for metadata strings.

Design elements this commit produces: None -- this is a bugfix that restores an existing invariant.

## Usage Examples
Before (buggy):
```cpp
// Inside TVM_FFI_DLL_EXPORT_TYPED_FUNC metadata symbol:
// String was allocated in the DLL's own heap via tvm::ffi::String constructor.
// If the DLL is unloaded, the string's backing memory becomes invalid.
::tvm::ffi::String str(os.str());
::tvm::ffi::TypeTraits<::tvm::ffi::String>::MoveToAny(std::move(str), result);
```

After (fixed):
```cpp
// String is allocated in libtvm_ffi's heap via TVMFFIStringFromByteArray.
// The string outlives the DLL because libtvm_ffi remains loaded.
std::string data = os.str();
TVMFFIByteArray data_array{data.data(), data.size()};
return TVMFFIStringFromByteArray(&data_array, result);
```
