# Introduce UnsafeInit tag and tighten ObjectRef null safety

## TL;DR
- Introduces `ffi::UnsafeInit` tag struct. All ObjectRef types now construct-from-nullptr exclusively via `explicit RefType(UnsafeInit)` instead of the old `explicit RefType(ObjectPtr<Object>)`.
- The four `TVM_FFI_DEFINE_*_OBJECT_REF_METHODS` macros are updated: nullable types accept `ObjectPtr<ContainerType>` (not `ObjectPtr<Object>`), non-nullable types only accept `UnsafeInit`. This makes it a compile-time error to construct a typed ref from an unrelated `ObjectPtr<Object>`.
- Internal casting sites (`ObjectRef::as`, `Optional::value`, `TypeTraits`, `RValueRef`, `GetRef`, `Tuple`) are migrated to `ObjectUnsafe::ObjectRefFromObjectPtr<T>()` helper, which uses the UnsafeInit path under the hood.

class UnsafeInit:
    """Tag type requesting unsafe initialization (data_ = nullptr).

    Only for controlled scenarios; do not use in normal code."""

        """Construct any ObjectRef T from an ObjectPtr via UnsafeInit + direct data_ assignment."""
        ref = T(UnsafeInit())
        ref.data_ = ptr  # or std::move(ptr)
        return ref

        # Invariant: caller must guarantee ptr's pointee is-a T::ContainerType

## Impact
- API: All ObjectRef subclasses lose the `explicit T(ObjectPtr<Object>)` constructor. Code that constructed a typed ref from `ObjectPtr<Object>` must now use either `ObjectUnsafe::ObjectRefFromObjectPtr<T>()` or construct from `ObjectPtr<ContainerType>`. Breaking for downstream code that relied on the generic constructor.
- Behavioral: `ObjectRef::as<T>()` now internally uses UnsafeInit + direct assignment instead of the removed `T(ObjectPtr<Object>)` constructor. No observable change in behavior.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces:
- `UnsafeInit` tag struct: new construction protocol for ObjectRef types. Replaces the implicit `ObjectPtr<Object>` constructor as the unsafe initialization path.
- `ObjectUnsafe::ObjectRefFromObjectPtr<T>`: new centralized helper for constructing any ObjectRef from an ObjectPtr without requiring T to accept ObjectPtr<Object>.
- `ReflectionDefBase::ObjectCreatorUnsafeInit<T>`: new fallback creator for non-default-constructible types that accept UnsafeInit.
- Typed `ObjectPtr<ContainerType>` constructor in nullable ref macros: tighter type constraint replacing the old `ObjectPtr<Object>` parameter.

Design elements this commit mutates:
- All four `TVM_FFI_DEFINE_*_OBJECT_REF_METHODS` macros: constructor signatures changed.
- `ObjectRef::as<T>()`: internal implementation changed to use UnsafeInit path.
- `RValueRef<T>`: now stores `ObjectPtr<ContainerType>` instead of `ObjectPtr<Object>`.
- `Optional<T>` (ptr-based): constructor changed from `ObjectPtr<Object>` to `UnsafeInit`, value accessors use `ObjectRefFromObjectPtr`.

## Usage Examples

Before (old pattern -- no longer compiles for non-nullable types):
```cpp
// Old: construct typed ref from ObjectPtr<Object> (accepted any pointer)
Error err(ObjectUnsafe::ObjectPtrFromOwned<Object>(handle));
Shape shape(MakeStridesFromShape(ndim, shape_data));

// Old: ObjectRef macro expansion generated:
//   explicit MyRef(ObjectPtr<Object> n) : ObjectRef(n) {}
```

After (new pattern):
```cpp
// New: use ObjectUnsafe helper for internal casting
Error err = ObjectUnsafe::ObjectRefFromObjectPtr<Error>(
    ObjectUnsafe::ObjectPtrFromOwned<Object>(handle));

// New: use static factory for Shape
Shape strides = Shape::StridesFromShape(data, ndim);

// New: UnsafeInit for object types without default constructor
class TIntObj : public TNumberObj {
  TIntObj(int64_t value) : value(value) {}
  explicit TIntObj(UnsafeInit) {}  // replaces TIntObj() = default;
  // ...
};

// New: ObjectRef macro expansion generates:
//   explicit MyRef(ObjectPtr<MyRefObj> n) : ObjectRef(n) {}  // typed
//   explicit MyRef(UnsafeInit tag) : ObjectRef(tag) {}       // unsafe init
```
