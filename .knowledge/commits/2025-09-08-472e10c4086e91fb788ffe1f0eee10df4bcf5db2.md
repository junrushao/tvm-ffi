# Introduce UnsafeInit tag and enhance ObjectRef null safety

## TL;DR
- Introduces `ffi::UnsafeInit`, an empty struct tag type used to explicitly construct ObjectRef-derived types with a null `data_` pointer. This replaces the previous pattern of constructing refs from `ObjectPtr<Object>(nullptr)` or from `ObjectPtr<Object>` in general.
- Removes the `RefType(ObjectPtr<Object>)` constructor from all four ObjectRef macro families (`TVM_FFI_DEFINE_OBJECT_REF_METHODS`, `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS`, `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS`, `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS`). Nullable types now accept `ObjectPtr<ContainerType>` (typed) instead of `ObjectPtr<Object>` (erased). Non-nullable types lose the ObjectPtr constructor entirely.
- Adds `ObjectUnsafe::ObjectRefFromObjectPtr<T>` as the controlled pathway for constructing any ObjectRef from an ObjectPtr, used by cast.h, type_traits.h, optional.h, tuple.h, rvalue_ref.h, function.h, function_details.h, and tensor.cc.
- Adds `UnsafeInit` constructors to `Array<T>`, `Map<K,V>`, `Tuple<Types...>`, and `VariantBase`, and replaces the `ObjectPtr<Object>` constructors they previously had.
- Reflection system gains `ObjectCreatorUnsafeInit<T>` as a fallback creator when `T` is not default-constructible but is constructible from `UnsafeInit`.
- Minor side-fix: `MakeStridesFromShape` parameter order changed from `(ndim, shape)` to `(data, ndim)` with const-qualified pointer; `Shape::StridesFromShape` static method added as the public API for stride computation.

## Impact
- API: **Breaking for C++ downstream** -- any code constructing ObjectRef subtypes via `TypeName(ObjectPtr<Object>(...))` must change. Non-nullable types can no longer be constructed from ObjectPtr at all (except through `ObjectUnsafe`). Nullable types must use `ObjectPtr<ContainerType>` instead of `ObjectPtr<Object>`. The mutable object ref macro also fixes a stale `tvm::runtime` namespace reference to `tvm::ffi`.
- Behavioral: No runtime behavior changes. The UnsafeInit pattern produces identical object states as before; it just enforces intent at the type system level.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **ObjectRef macro family** (`.knowledge/designs/0002-object-system.md`): Rewrites all four macro definitions to use UnsafeInit + typed ObjectPtr.
- **ObjectUnsafe utility class** (`.knowledge/designs/0002-object-system.md`): Extends with `ObjectRefFromObjectPtr` methods.
- **ObjectRefTypeTraitsBase** (`.knowledge/designs/0006-type-traits.md`): All `CopyFromAnyViewAfterCheck`, `MoveFromAnyAfterCheck`, `TryCastFromAnyView` implementations now route through `ObjectRefFromObjectPtr` instead of direct constructor.
- **Optional<T> ptr-based** (`optional.h`): Replaces `ObjectPtr<Object>` constructor with `UnsafeInit`; `value()`, `value_or()`, `operator*()` use `ObjectRefFromObjectPtr`.
- **Reflection ObjectCreator** (`.knowledge/designs/0008-reflection.md`): Adds `UnsafeInit` fallback when `T` is not default-constructible.
- **RValueRef<T>** (`rvalue_ref.h`): Uses typed `ObjectPtr<ContainerType>` instead of `ObjectPtr<Object>`.
- **Container types** (Array, Map, Tuple, Variant): Each gains an `UnsafeInit` constructor.

Design elements this commit produces:
- **UnsafeInit tag type**: New marker struct in `tvm::ffi` namespace for explicit unsafe null initialization.
- **ObjectUnsafe::ObjectRefFromObjectPtr<T>**: New controlled pathway for constructing ObjectRef from ObjectPtr without requiring a public ObjectPtr constructor on the ref type.
- **ObjectCreatorUnsafeInit<T>**: New reflection fallback creator for UnsafeInit-constructible types.
- **Shape::StridesFromShape**: New static method replacing direct use of `details::MakeStridesFromShape`.

## Usage Examples

Before (constructing non-nullable ref from erased ObjectPtr -- now disallowed):
```cpp
// Old: any ObjectRef could be constructed from ObjectPtr<Object>
Shape s(some_object_ptr);  // compiles, but no null check, type-erased
```

After (UnsafeInit for controlled null init, typed ObjectPtr for safe init):
```cpp
// Controlled null init (internal FFI plumbing only)
Shape s(UnsafeInit{});  // explicitly null, caller must fill data_ later

// For nullable types, use typed ObjectPtr
Array<int> arr(make_object<ArrayObj>());  // ObjectPtr<ArrayObj>, not ObjectPtr<Object>

// For non-nullable types, construct via ObjectUnsafe (internal only)
Shape ref = details::ObjectUnsafe::ObjectRefFromObjectPtr<Shape>(some_shape_ptr);
```

Reflection creator fallback for types without default constructor:
```cpp
class MyObj : public Object {
 public:
  int64_t value;
  // No default constructor, but has UnsafeInit constructor
  explicit MyObj(UnsafeInit) {}
  MyObj(int64_t v) : value(v) {}
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(MyObj, Object);
};

// ObjectDef automatically picks ObjectCreatorUnsafeInit<MyObj> as creator
// because !is_default_constructible_v<MyObj> && is_constructible_v<MyObj, UnsafeInit>
TVM_FFI_STATIC_INIT_BLOCK({
  reflection::ObjectDef<MyObj>()
      .def_rw("value", &MyObj::value);
});
```
