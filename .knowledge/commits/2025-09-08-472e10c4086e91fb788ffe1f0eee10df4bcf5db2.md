# Introduce UnsafeInit tag and tighten ObjectRef null safety by removing generic ObjectPtr<Object> constructors

## TL;DR
- Introduces `struct UnsafeInit {}` as an explicit tag for constructing ObjectRef types with null `data_`, replacing the previous implicit `ObjectPtr<Object>` constructor that allowed type-erased initialization.
- All four `TVM_FFI_DEFINE_*_OBJECT_REF_METHODS` macros now accept `ObjectPtr<ContainerType>` (typed) instead of `ObjectPtr<Object>` (erased), and add an `UnsafeInit` constructor for controlled null initialization.
- Adds `ObjectUnsafe::ObjectRefFromObjectPtr<T>()` as the canonical bridge from `ObjectPtr<Object>` to a typed `ObjectRef` subclass, used throughout `type_traits.h`, `cast.h`, `optional.h`, `rvalue_ref.h`, and container headers.
- Secondary change: `Shape::StridesFromShape()` static method replaces direct calls to `details::MakeStridesFromShape` (parameter order also swapped to `(data, ndim)`).

## Impact
- API: Breaking for any C++ code that constructed ObjectRef subtypes via `TypeName(ObjectPtr<Object>(...))`. The new path is either `TypeName(ObjectPtr<ContainerType>(...))` for nullable types, or `ObjectUnsafe::ObjectRefFromObjectPtr<TypeName>(ptr)` for internal bridging.
- Behavioral: `ObjectRef::as<T>()` now uses UnsafeInit + assignment instead of direct ObjectPtr<Object> construction, preserving semantics but improving type safety. `ObjectPtrFromObjectRef` move overload now properly nulls the source pointer.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system** (`0002-object-system.md`): The `ObjectRef`/`ObjectPtr<T>`/`Object` three-layer pattern is the target of this refactor.
- **TypeTraits protocol** (`0005-type-traits-protocol.md`): `ObjectRefTypeTraitsBase` methods (`CopyFromAnyViewAfterCheck`, `MoveFromAnyAfterCheck`, `TryCastFromAnyView`) all changed to use the new bridge.
- **Reflection** (`0008-reflection.md`): `ObjectDef` registration now uses `ObjectCreatorUnsafeInit` as fallback creator.
- **Containers** (`0006-containers.md`): `Array`, `Map`, `Tuple`, `Variant`, `Shape` all gain UnsafeInit constructors.

Design elements this commit produces:
- **`UnsafeInit` tag type** -- new protocol element: every ObjectRef subclass must accept `UnsafeInit` for controlled null initialization. This is enforced by the macros.
- **`ObjectUnsafe::ObjectRefFromObjectPtr<T>()`** -- canonical bridge replacing direct `TypeName(ObjectPtr<Object>)` construction.
- **`ReflectionDefBase::ObjectCreatorUnsafeInit<T>()`** -- fallback object creator for reflection when `T` has no default constructor but accepts `UnsafeInit`.
- **`Shape::StridesFromShape()`** -- public static factory replacing internal `details::MakeStridesFromShape`.

## Usage Examples

Constructing a non-nullable ObjectRef via UnsafeInit in controlled code:
```cpp
// Before: direct construction from type-erased ObjectPtr<Object> (removed)
// Shape s(some_object_ptr);  // was: ObjectPtr<Object> -> Shape

// After: explicit UnsafeInit for internal bridging
Shape ref(UnsafeInit{});       // data_ = nullptr temporarily
ref.data_ = typed_shape_ptr;   // assign typed pointer
// Or use the canonical helper:
Shape ref2 = ObjectUnsafe::ObjectRefFromObjectPtr<Shape>(some_object_ptr);
```

Reflection creating objects without default constructors:
```cpp
// Object type with no default ctor, but accepting UnsafeInit:
class TVarObj : public Object {
  std::string name;
  TVarObj(std::string name) : name(name) {}
  explicit TVarObj(UnsafeInit) {}  // enables reflection-based creation
};
// ObjectDef registration automatically picks ObjectCreatorUnsafeInit<TVarObj>
// when is_default_constructible_v<TVarObj> is false but is_constructible_v<TVarObj, UnsafeInit> is true.
```
