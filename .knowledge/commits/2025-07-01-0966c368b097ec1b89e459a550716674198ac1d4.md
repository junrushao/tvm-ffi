# Formalize namespace for all objects: rename object.* type keys to ffi.*

## TL;DR
- Renames all built-in object type keys from the `object.*` namespace to the `ffi.*` namespace (e.g., `"object.Object"` becomes `"ffi.Object"`, `"object.String"` becomes `"ffi.String"`).
- Adds four new `StaticTypeKey` constants (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) and converts existing inline string literals to use them.
- Ensures no built-in object type sits in a "root" namespace; all are explicitly namespaced under `ffi.`.

## Key Changes

### StaticTypeKey additions (`include/tvm/ffi/object.h`)

Four new `constexpr` constants added to `struct StaticTypeKey`:
- `kTVMFFIObject = "ffi.Object"` (was inline `"object.Object"` in `Object::_type_key`)
- `kTVMFFIFunction = "ffi.Function"` (was inline `"object.Function"` in `FunctionObj::_type_key`)
- `kTVMFFIArray = "ffi.Array"` (was inline `"object.Array"` in `ArrayObj::_type_key`)
- `kTVMFFIMap = "ffi.Map"` (was inline `"object.Map"` in `MapObj::_type_key`)

### Type key renames

| Type | Before | After |
|------|--------|-------|
| `Object` | `"object.Object"` | `"ffi.Object"` (via `StaticTypeKey::kTVMFFIObject`) |
| `ArrayObj` | `"object.Array"` | `"ffi.Array"` (via `StaticTypeKey::kTVMFFIArray`) |
| `MapObj` | `"object.Map"` | `"ffi.Map"` (via `StaticTypeKey::kTVMFFIMap`) |
| `ErrorObj` | `"object.Error"` | `"ffi.Error"` (inline literal) |
| `FunctionObj` | `"object.Function"` | `"ffi.Function"` (via `StaticTypeKey::kTVMFFIFunction`) |
| `BytesObj` | `"object.Bytes"` | `"ffi.Bytes"` (already via `StaticTypeKey::kTVMFFIBytes`) |
| `StringObj` | `"object.String"` | `"ffi.String"` (already via `StaticTypeKey::kTVMFFIStr`) |
| `ShapeObj` | `"object.Shape"` | `"ffi.Shape"` (already via `StaticTypeKey::kTVMFFIShape`) |
| `NDArrayObj` | `"object.NDArray"` | `"ffi.NDArray"` (already via `StaticTypeKey::kTVMFFINDArray`) |

Note: `String`, `Bytes`, `Shape`, and `NDArray` already had `StaticTypeKey` constants from the prior commit but their string values changed from `"object.*"` to `"ffi.*"` here.

### Consolidation of inline literals

`ArrayObj::_type_key`, `MapObj::_type_key`, `FunctionObj::_type_key`, and `Object::_type_key` previously used inline string literals. This commit replaces them with references to `StaticTypeKey` constants, matching the pattern already established for `String`, `Bytes`, `Shape`, and `NDArray`. `ErrorObj::_type_key` remains an inline literal (`"ffi.Error"`).

## Files Changed

- `include/tvm/ffi/object.h` -- Added 4 new `StaticTypeKey` constants; changed `Object::_type_key` from `"object.Object"` to `StaticTypeKey::kTVMFFIObject`.
- `include/tvm/ffi/container/array.h` -- Changed `ArrayObj::_type_key` from `"object.Array"` to `StaticTypeKey::kTVMFFIArray`.
- `include/tvm/ffi/container/map.h` -- Changed `MapObj::_type_key` from `"object.Map"` to `StaticTypeKey::kTVMFFIMap`.
- `include/tvm/ffi/error.h` -- Changed `ErrorObj::_type_key` from `"object.Error"` to `"ffi.Error"`.
- `include/tvm/ffi/function.h` -- Changed `FunctionObj::_type_key` from `"object.Function"` to `StaticTypeKey::kTVMFFIFunction`.

## Impact
- **ABI-breaking**: Type keys are used for runtime type registration via `TVMFFIGetOrAllocTypeIndex` and cross-language lookup via `TVMFFITypeKeyToIndex`. Any code (Python, Rust, or downstream C++) that references built-in types by their string key (e.g., `@register_object("object.String")`) must update to the new `ffi.*` keys.
- **API**: The new `StaticTypeKey` constants (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) are now available for use in downstream C++ code.
- **Behavioral**: No functional change beyond the string key values.

## Design Elements

Design elements this commit consumes:
- `StaticTypeKey` struct (from root commit 7d34eb8) -- The existing pattern of centralizing type key strings as `constexpr` constants.
- Object type registration system (`TVMFFIGetOrAllocTypeIndex`) -- Type keys flow through this system for runtime type table population.

Design elements this commit produces:
- **`ffi.*` namespace convention** -- All built-in FFI object types must use the `ffi.` prefix in their type keys. This is the formalized naming convention going forward. No object should sit in a root namespace or use the deprecated `object.*` prefix.
- **Complete `StaticTypeKey` coverage** -- All built-in object types now have corresponding `StaticTypeKey` constants (except `ErrorObj` which still uses an inline literal).
