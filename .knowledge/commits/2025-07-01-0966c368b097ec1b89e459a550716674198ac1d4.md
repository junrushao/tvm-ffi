# Rename all object type keys from `object.*` to `ffi.*` namespace and centralize key constants in StaticTypeKey

## TL;DR
- Renames all core object `_type_key` strings from the `object.*` prefix to `ffi.*` (e.g., `"object.Object"` -> `"ffi.Object"`, `"object.Array"` -> `"ffi.Array"`).
- Centralizes four new type key constants (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) in `StaticTypeKey` and updates class definitions to reference them instead of inline string literals.
- Also fixes the Visitor style in `TensorMapNode` (mentioned in commit message, but not visible in this diff subset).

## Key Exports

```python
class StaticTypeKey:
    """Centralized string constants for all built-in FFI object type keys."""
    # Pre-existing (renamed prefix):
    kTVMFFIBytes: str = "ffi.Bytes"        # was "object.Bytes"
    kTVMFFIStr: str = "ffi.String"         # was "object.String"
    kTVMFFIShape: str = "ffi.Shape"        # was "object.Shape"
    kTVMFFINDArray: str = "ffi.NDArray"    # was "object.NDArray"
    # New constants (previously inline strings):
    kTVMFFIObject: str = "ffi.Object"      # was "object.Object" (inline)
    kTVMFFIFunction: str = "ffi.Function"  # was "object.Function" (inline)
    kTVMFFIArray: str = "ffi.Array"        # was "object.Array" (inline)
    kTVMFFIMap: str = "ffi.Map"            # was "object.Map" (inline)
    # Interacts with: Object::_type_key, ArrayObj::_type_key, MapObj::_type_key,
    #   FunctionObj::_type_key, ErrorObj::_type_key
    # Invariant: Every built-in FFI type must use `ffi.*` prefix for its type key.
    # Invariant: All core type key strings should reference StaticTypeKey constants
    #   rather than inline literals (ErrorObj is the one exception in this commit).
    # Extension: Add new kTVMFFI* constants here for any new built-in types.
```

## Impact
- API: The `_type_key` strings are part of the cross-language type registration protocol. Any code that matches on the old `"object.*"` keys (Python `@register_object("object.Array")`, serialization formats, string-based type lookups) must be updated to `"ffi.*"`.
- Behavioral: None -- type registration semantics are unchanged; only the key strings differ.
- Flags/config: None.
- Data formats/schemas: Serialized data that stores type keys (e.g., JSON IR) will contain different strings after this change. Old serialized data with `"object.*"` keys would fail to deserialize unless migration is handled.

## Design Elements
Design elements this commit consumes:
- Object type key registration protocol (`_type_key` + `TVM_FFI_DECLARE_STATIC_OBJECT_INFO`) -- see `.knowledge/design-records/0003-ffi-object-system.md` and `.knowledge/design-records/0008-ffi-object-macros.md`
- `StaticTypeKey` struct as the centralized location for built-in type key constants -- see `.knowledge/design-records/0003-ffi-object-system.md`

Design elements this commit produces/mutates:
- **Mutates** the `StaticTypeKey` namespace convention: establishes `ffi.*` as the canonical prefix for all built-in FFI objects (previously `object.*`).
- **Produces** four new `StaticTypeKey` constants: `kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`.
- **Mutates** `ErrorObj::_type_key` from `"object.Error"` to `"ffi.Error"` (uses inline literal rather than a `StaticTypeKey` constant, unlike the other classes).

## Usage Examples
None -- this is a mechanical rename with no new API patterns. The calling convention is identical; only the string values changed.
