# Migrate all built-in object type keys from `object.*` namespace to `ffi.*` namespace

## TL;DR
- All built-in `_type_key` strings for core FFI objects are renamed from the `"object.*"` prefix to the `"ffi.*"` prefix, centralizing them in `StaticTypeKey`.
- Four new `StaticTypeKey` constants are added (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) to complement the existing four (`kTVMFFIBytes`, `kTVMFFIStr`, `kTVMFFIShape`, `kTVMFFINDArray`), which are also migrated.
- `Object`, `ArrayObj`, `MapObj`, `ErrorObj`, and `FunctionObj` now reference these constants instead of inline string literals.

**Diff-message alignment note**: The commit message also mentions "fixes the Visitor style in TensorMapNode", but no `TensorMap`-related changes appear in the actual diff. Analysis is scoped to the actual diff only.

**Rename mapping table:**

| Class | Old `_type_key` | New `_type_key` |
|---|---|---|
| `Object` | `"object.Object"` | `"ffi.Object"` |
| `ArrayObj` | `"object.Array"` | `"ffi.Array"` |
| `MapObj` | `"object.Map"` | `"ffi.Map"` |
| `ErrorObj` | `"object.Error"` | `"ffi.Error"` |
| `FunctionObj` | `"object.Function"` | `"ffi.Function"` |
| `BytesObj` | `"object.Bytes"` | `"ffi.Bytes"` |
| `StringObj` | `"object.String"` | `"ffi.String"` |
| `ShapeObj` | `"object.Shape"` | `"ffi.Shape"` |
| `NDArrayObj` | `"object.NDArray"` | `"ffi.NDArray"` |

## Key Exports

```python
# include/tvm/ffi/object.h — StaticTypeKey additions (previously 4, now 8 constants)
class StaticTypeKey:
    # Previously existed (now with ffi.* prefix):
    kTVMFFIBytes: str = "ffi.Bytes"         # was "object.Bytes"
    kTVMFFIStr: str = "ffi.String"          # was "object.String"
    kTVMFFIShape: str = "ffi.Shape"         # was "object.Shape"
    kTVMFFINDArray: str = "ffi.NDArray"     # was "object.NDArray"
    # Newly added constants:
    kTVMFFIObject: str = "ffi.Object"       # was inline "object.Object"
    kTVMFFIFunction: str = "ffi.Function"   # was inline "object.Function"
    kTVMFFIArray: str = "ffi.Array"         # was inline "object.Array"
    kTVMFFIMap: str = "ffi.Map"             # was inline "object.Map"
    # Interacts with: Object._type_key, ArrayObj._type_key, MapObj._type_key,
    #   FunctionObj._type_key, ErrorObj._type_key — all now reference these constants
    # Invariant: all built-in FFI type keys use the "ffi." prefix; user-defined
    #   types should use their own namespaces (e.g. "tvm.relay.Expr")

class Object:
    _type_key: str = StaticTypeKey.kTVMFFIObject   # = "ffi.Object"; was "object.Object"

class FunctionObj(Object):
    _type_key: str = StaticTypeKey.kTVMFFIFunction  # = "ffi.Function"; was "object.Function"

class ErrorObj(Object):
    _type_key: str = "ffi.Error"                    # = "ffi.Error"; was "object.Error"
    # Note: ErrorObj uses a direct string literal rather than StaticTypeKey

class ArrayObj(Object):
    _type_key: str = StaticTypeKey.kTVMFFIArray     # = "ffi.Array"; was "object.Array"

class MapObj(Object):
    _type_key: str = StaticTypeKey.kTVMFFIMap       # = "ffi.Map"; was "object.Map"
```

## Impact
- API: **Breaking** — `_type_key` strings are used for Python `@register_object(...)` bindings and object type dispatch. Any caller registering or looking up objects by the old `"object.*"` key strings (e.g., `@register_object("object.Array")`) will break.
- Behavioral: Object type checks via `IsInstance<T>` are unaffected (they use `TypeIndex`, not `_type_key`). The `_type_key` change only affects string-based type lookup and Python object registration.
- Flags/config: none
- Data formats/schemas: Serialized object type keys embedded in saved model artifacts using `"object.*"` strings will become invalid with this change.

Design elements this commit produces:
