# Rename built-in object type keys from `object.*` to `ffi.*` namespace and centralize in StaticTypeKey

## TL;DR
- All built-in object `_type_key` strings are renamed from `"object.*"` to `"ffi.*"` (e.g., `"object.Object"` -> `"ffi.Object"`, `"object.Array"` -> `"ffi.Array"`).
- Four new `StaticTypeKey` constants added (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) so all built-in type keys are centralized in the `StaticTypeKey` struct.
- Inline string literals in `ArrayObj`, `MapObj`, `FunctionObj`, and `Object` replaced with `StaticTypeKey::kTVMFFI*` references.
- `ErrorObj` is the only type that uses a direct string literal `"ffi.Error"` instead of a `StaticTypeKey` constant.

### Rename Mapping

| Old `_type_key` | New `_type_key` | Location | Via StaticTypeKey? |
|---|---|---|---|
| `"object.Object"` | `"ffi.Object"` | `object.h` (Object) | Yes (`kTVMFFIObject`) |
| `"object.Array"` | `"ffi.Array"` | `container/array.h` (ArrayObj) | Yes (`kTVMFFIArray`) |
| `"object.Map"` | `"ffi.Map"` | `container/map.h` (MapObj) | Yes (`kTVMFFIMap`) |
| `"object.Function"` | `"ffi.Function"` | `function.h` (FunctionObj) | Yes (`kTVMFFIFunction`) |
| `"object.Error"` | `"ffi.Error"` | `error.h` (ErrorObj) | No (inline literal) |
| `"object.String"` | `"ffi.String"` | `object.h` (StaticTypeKey) | Yes (`kTVMFFIStr`) |
| `"object.Bytes"` | `"ffi.Bytes"` | `object.h` (StaticTypeKey) | Yes (`kTVMFFIBytes`) |
| `"object.Shape"` | `"ffi.Shape"` | `object.h` (StaticTypeKey) | Yes (`kTVMFFIShape`) |
| `"object.NDArray"` | `"ffi.NDArray"` | `object.h` (StaticTypeKey) | Yes (`kTVMFFINDArray`) |

## Key Exports

```python
class StaticTypeKey:
    """Centralized compile-time constants for all built-in object type key strings."""
    # Existing (unchanged):
    kTVMFFIRawStr: str = "const char*"
    kTVMFFIByteArrayPtr: str = "TVMFFIByteArray*"
    kTVMFFIObjectRValueRef: str = "ObjectRValueRef"

    # Renamed (object.* -> ffi.*):
    kTVMFFIBytes: str = "ffi.Bytes"       # was "object.Bytes"
    kTVMFFIStr: str = "ffi.String"         # was "object.String"
    kTVMFFIShape: str = "ffi.Shape"        # was "object.Shape"
    kTVMFFINDArray: str = "ffi.NDArray"    # was "object.NDArray"

    # New constants (previously inline string literals):
    kTVMFFIObject: str = "ffi.Object"      # was "object.Object" inline in Object::_type_key
    kTVMFFIFunction: str = "ffi.Function"  # was "object.Function" inline in FunctionObj::_type_key
    kTVMFFIArray: str = "ffi.Array"        # was "object.Array" inline in ArrayObj::_type_key
    kTVMFFIMap: str = "ffi.Map"            # was "object.Map" inline in MapObj::_type_key
    # Interacts with: TVMFFIGetOrAllocTypeIndex (type registration), TypeTraits::TypeStr()
    # Invariant: these keys are the canonical identifiers used in the global type table
    # Invariant: must match what cross-language bindings (Python, Rust) use for type lookup

# ErrorObj uses inline literal (not centralized):
class ErrorObj(Object):
    _type_key: str = "ffi.Error"  # was "object.Error", not using StaticTypeKey constant
    # Interacts with: TVMFFIGetOrAllocTypeIndex, Python error mapping
```

## Impact
- API: Breaking change to the type registration namespace. Any code that matches on `_type_key` strings (e.g., `register_object("object.Array")` in Python) must be updated to use the `"ffi."` prefix. Affects all cross-language bindings that resolve types by key string.
- Behavioral: None -- the objects themselves are unchanged; only their registration keys differ.
- Flags/config: None
- Data formats/schemas: Any serialized data that includes type keys (e.g., JSON IR, saved models referencing type names) will need updating from `"object.*"` to `"ffi.*"`.

## Design Elements
Design elements this commit consumes:
- `StaticTypeKey` struct (`include/tvm/ffi/object.h`) -- compile-time constant registry for built-in type key strings. See `.knowledge/designs/0002-object-system.md`.
- `_type_key` field convention on Object subclasses -- each object declares a static `_type_key` used for registration. See `.knowledge/designs/0002-object-system.md`.
- `TVM_FFI_DECLARE_STATIC_OBJECT_INFO` macro -- registers built-in types with fixed indices. See `.knowledge/designs/0002-object-system.md`.

Design elements this commit produces:
- Formalized `"ffi.*"` namespace convention: all FFI-layer built-in types now use the `"ffi."` prefix instead of `"object."`, establishing a clear namespace boundary between FFI-layer types and higher-level framework types.
- Centralized `StaticTypeKey` for all built-in types: `Object`, `Function`, `Array`, and `Map` now reference `StaticTypeKey` constants instead of inline literals, making the registry a single source of truth for built-in type keys.

## Usage Examples

Before/after showing the namespace change for type registration:

```cpp
// BEFORE: type keys used "object." prefix with inline strings
class ArrayObj : public Object {
    static constexpr const char* _type_key = "object.Array";  // inline literal
};

// AFTER: type keys use "ffi." prefix via centralized StaticTypeKey
class ArrayObj : public Object {
    static constexpr const char* _type_key = StaticTypeKey::kTVMFFIArray;  // = "ffi.Array"
};

// Python side must also update:
// BEFORE:
// @register_object("object.Array")
// AFTER:
// @register_object("ffi.Array")
```
