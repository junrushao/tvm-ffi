# Rename all core object type keys from `object.*` to `ffi.*` namespace and centralize in StaticTypeKey

## TL;DR
- Renames all core object `_type_key` strings from the `object.*` namespace to `ffi.*` (e.g., `"object.Object"` -> `"ffi.Object"`, `"object.Array"` -> `"ffi.Array"`).
- Adds four new `StaticTypeKey` constants (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) so that `ArrayObj`, `MapObj`, `FunctionObj`, and `Object` reference the centralized constant instead of inline string literals.
- `ErrorObj` is renamed to `"ffi.Error"` but still uses an inline string literal (not a `StaticTypeKey` constant).

### Rename Mapping

| Class | Old `_type_key` | New `_type_key` | Via |
|---|---|---|---|
| `Object` | `"object.Object"` | `"ffi.Object"` | `StaticTypeKey::kTVMFFIObject` |
| `ArrayObj` | `"object.Array"` | `"ffi.Array"` | `StaticTypeKey::kTVMFFIArray` |
| `MapObj` | `"object.Map"` | `"ffi.Map"` | `StaticTypeKey::kTVMFFIMap` |
| `FunctionObj` | `"object.Function"` | `"ffi.Function"` | `StaticTypeKey::kTVMFFIFunction` |
| `ErrorObj` | `"object.Error"` | `"ffi.Error"` | inline literal |
| `StaticTypeKey::kTVMFFIBytes` | `"object.Bytes"` | `"ffi.Bytes"` | constant |
| `StaticTypeKey::kTVMFFIStr` | `"object.String"` | `"ffi.String"` | constant |
| `StaticTypeKey::kTVMFFIShape` | `"object.Shape"` | `"ffi.Shape"` | constant |
| `StaticTypeKey::kTVMFFINDArray` | `"object.NDArray"` | `"ffi.NDArray"` | constant |

## Key Exports

```python
class StaticTypeKey:
    """Centralized compile-time type key constants for all predefined types."""
    # Pre-existing (renamed values):
    kTVMFFIBytes: ClassVar[str] = "ffi.Bytes"       # was "object.Bytes"
    kTVMFFIStr: ClassVar[str] = "ffi.String"         # was "object.String"
    kTVMFFIShape: ClassVar[str] = "ffi.Shape"        # was "object.Shape"
    kTVMFFINDArray: ClassVar[str] = "ffi.NDArray"    # was "object.NDArray"
    # New constants (added by this commit):
    kTVMFFIObject: ClassVar[str] = "ffi.Object"
    kTVMFFIFunction: ClassVar[str] = "ffi.Function"
    kTVMFFIArray: ClassVar[str] = "ffi.Array"
    kTVMFFIMap: ClassVar[str] = "ffi.Map"
    # Interacts with: Object._type_key, ArrayObj._type_key, MapObj._type_key,
    #   FunctionObj._type_key (all reference these constants)
    # Invariant: every core FFI type must use the "ffi.*" namespace prefix
```

## Impact
- API: Type key strings visible to Python/Rust via `register_object("ffi.Object")` and type table lookups change from `"object.*"` to `"ffi.*"`. Any downstream code doing string matching on `_type_key` values must update.
- Behavioral: None -- runtime semantics unchanged; only the string labels for type registration change.
- Flags/config: None.
- Data formats/schemas: Serialized type keys in model artifacts or logs will show `ffi.*` instead of `object.*`.

## Design Elements
Design elements this commit consumes:
- **Object system** (`0002-object-system.md`): The `_type_key` class-level metadata field and `StaticTypeKey` struct.
- **Container system** (`0006-containers.md`): `ArrayObj._type_key` and `MapObj._type_key`.
- **Function system** (`0003-function-system.md`): `FunctionObj._type_key`.
- **Error propagation** (`0004-error-propagation.md`): `ErrorObj._type_key`.

Design elements this commit produces:
- **`StaticTypeKey` centralization pattern**: All core object types now reference `StaticTypeKey` constants instead of inline string literals. This is a formalization of an existing pattern (Bytes/String/Shape/NDArray already used it) extended to Object/Function/Array/Map.
- **`ffi.*` namespace convention**: Establishes that all core FFI types use the `ffi.` prefix in their type keys, replacing the previous `object.` prefix. No root-namespace type keys should exist.

## Usage Examples
None -- this is a rename refactor. The usage pattern for `_type_key` is unchanged; only the string values differ.
