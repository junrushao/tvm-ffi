# Rename all core object type keys from `object.*` to `ffi.*` namespace
## TL;DR
- All core FFI object `_type_key` strings are migrated from `"object.*"` to `"ffi.*"` (e.g., `"object.Object"` -> `"ffi.Object"`, `"object.Array"` -> `"ffi.Array"`).
- Four new `StaticTypeKey` constants are added (`kTVMFFIObject`, `kTVMFFIFunction`, `kTVMFFIArray`, `kTVMFFIMap`) to centralize type key strings and eliminate scattered string literals.
- The `TensorMapNode` Visitor style is also fixed (mentioned in commit message; not visible in diff -- possibly in a file outside the FFI headers).

### Rename mapping

| Old `_type_key`      | New `_type_key`       | Class       | Source file                        |
|----------------------|-----------------------|-------------|------------------------------------|
| `"object.Object"`   | `"ffi.Object"`        | `Object`    | `include/tvm/ffi/object.h`        |
| `"object.Array"`    | `"ffi.Array"`         | `ArrayObj`  | `include/tvm/ffi/container/array.h`|
| `"object.Map"`      | `"ffi.Map"`           | `MapObj`    | `include/tvm/ffi/container/map.h`  |
| `"object.Function"` | `"ffi.Function"`      | `FunctionObj`| `include/tvm/ffi/function.h`      |
| `"object.Error"`    | `"ffi.Error"`         | `ErrorObj`  | `include/tvm/ffi/error.h`         |
| `"object.Bytes"`    | `"ffi.Bytes"`         | (StaticTypeKey) | `include/tvm/ffi/object.h`    |
| `"object.String"`   | `"ffi.String"`        | (StaticTypeKey) | `include/tvm/ffi/object.h`    |
| `"object.Shape"`    | `"ffi.Shape"`         | (StaticTypeKey) | `include/tvm/ffi/object.h`    |
| `"object.NDArray"`  | `"ffi.NDArray"`       | (StaticTypeKey) | `include/tvm/ffi/object.h`    |

## Key Exports

**Constants** -- new `StaticTypeKey` members added:

```cpp
struct StaticTypeKey {
  // Existing (renamed values):
  static constexpr const char* kTVMFFIBytes    = "ffi.Bytes";     // was "object.Bytes"
  static constexpr const char* kTVMFFIStr      = "ffi.String";    // was "object.String"
  static constexpr const char* kTVMFFIShape    = "ffi.Shape";     // was "object.Shape"
  static constexpr const char* kTVMFFINDArray  = "ffi.NDArray";   // was "object.NDArray"

  // New constants (previously inline string literals in each class):
  static constexpr const char* kTVMFFIObject   = "ffi.Object";
  static constexpr const char* kTVMFFIFunction = "ffi.Function";
  static constexpr const char* kTVMFFIArray    = "ffi.Array";
  static constexpr const char* kTVMFFIMap      = "ffi.Map";
};
```

**Classes** -- `_type_key` field value changed in each:
- `Object::_type_key` now uses `StaticTypeKey::kTVMFFIObject` instead of `"object.Object"`.
- `ArrayObj::_type_key` now uses `StaticTypeKey::kTVMFFIArray` instead of `"object.Array"`.
- `MapObj::_type_key` now uses `StaticTypeKey::kTVMFFIMap` instead of `"object.Map"`.
- `FunctionObj::_type_key` now uses `StaticTypeKey::kTVMFFIFunction` instead of `"object.Function"`.
- `ErrorObj::_type_key` changed to `"ffi.Error"` (inline literal, not via StaticTypeKey).

## Impact
- API: **Breaking** for any code that matches or dispatches on the string value of `_type_key` (e.g., `@register_object("object.Array")` in Python, serialization formats storing type keys, Rust bindings doing string-based type matching). All downstream callers using `GetTypeKey()` will now see `"ffi.*"` instead of `"object.*"`.
- Behavioral: Runtime type registration uses the new keys; `GetTypeKey()` returns new strings. `IsInstance` checks are unaffected (they use integer indices, not string keys).
- Flags/config: none
- Data formats/schemas: Any serialized data containing `_type_key` strings (e.g., JSON IR) will need migration from `"object.*"` to `"ffi.*"`.

## Design Elements
Design elements this commit consumes:
- **Object type registration system** (`.knowledge/designs/0003-object-system.md`) -- the `_type_key` static field and `StaticTypeKey` struct are central to how types self-describe.
- **Type index layout** (`.knowledge/ADRs/0004-type-index-layout.md`) -- integer indices are unaffected, but string keys fed to `TVMFFIGetOrAllocTypeIndex` change.

Design elements this commit produces:
- **`ffi.*` namespace convention** -- Establishes that all core FFI object type keys live under the `ffi.` prefix rather than `object.`. This is a naming convention that all future core FFI types should follow.
- **Centralized type key constants** -- `StaticTypeKey` now covers all core types (`Object`, `Function`, `Array`, `Map` were previously inline literals). This reduces string duplication and makes future renames a single-point change.

## Usage Examples
None -- this is a pure rename refactor. The usage pattern is identical; only the string values returned by `GetTypeKey()` change:

```cpp
// Before:
obj->GetTypeKey();  // returns "object.Object"
// After:
obj->GetTypeKey();  // returns "ffi.Object"
```
