# Enhance load_module to accept PathLike objects in addition to str
## TL;DR
- Widens `load_module(path)` parameter type from `str` to `str | PathLike`, enabling `pathlib.Path` and other `os.PathLike` objects as arguments.
- Uses `os.fspath()` to normalize the path to `str` before forwarding to `_ffi_api.ModuleLoadFromFile`.
- Updates docstring and usage examples to document both string and PathLike usage.

## Key Exports

```python
def load_module(path: str | PathLike) -> Module:
    """Load module from file."""
    # Signature change: was (path: str), now (path: str | PathLike)
    # Interacts with: _ffi_api.ModuleLoadFromFile (C++ Module::LoadFromFile)
    # Interacts with: os.fspath() for PathLike -> str normalization
    # Invariant: path is normalized to str via fspath() before FFI boundary crossing
    ...
```

## Impact
- API: `load_module` now accepts `pathlib.Path` and any `os.PathLike` in addition to `str`. Fully backward-compatible -- existing `str` callers are unaffected.
- Behavioral: none -- `os.fspath()` on a `str` returns the same `str`, so behavior for existing callers is identical.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Module system `load_module` / `_ffi_api.ModuleLoadFromFile` ([0011-ffi-module-system](../design-records/0011-ffi-module-system.md)): the function being widened
- Python `os.PathLike` / `os.fspath` protocol (stdlib): used to normalize input before FFI boundary

Design elements this commit produces:
- None -- purely additive type widening of an existing API. No new classes, protocols, or conventions.

## Usage Examples
From the commit's updated docstring:
```python
from pathlib import Path
import tvm_ffi

# String path (existing usage, unchanged)
mod = tvm_ffi.load_module("path/to/module.so")
mod.func_name(*args)

# PathLike object (new usage)
mod = tvm_ffi.load_module(Path("path/to/module.so"))
mod.func_name(*args)
```
