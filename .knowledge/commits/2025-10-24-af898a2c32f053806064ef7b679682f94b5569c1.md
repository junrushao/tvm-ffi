# Enhance load_module to accept PathLike objects

## TL;DR
- Widens the `load_module` parameter type from `str` to `str | PathLike`, enabling `pathlib.Path` and other `os.PathLike` objects to be passed directly.
- Adds `os.fspath()` coercion before forwarding to `_ffi_api.ModuleLoadFromFile`.
- Updates the docstring with `pathlib.Path` usage examples.

## Key Exports

**Functions** (changed signature):
- `load_module(path: str | PathLike) -> Module` -- previously `path: str`. Now accepts any `os.PathLike` object (e.g., `pathlib.Path`). The `os.fspath()` call coerces `PathLike` to `str` before the FFI boundary.

## Impact
- API: The `path` parameter of `tvm_ffi.load_module` is widened from `str` to `str | PathLike`. Fully backward-compatible -- existing string callers are unaffected.
- ABI: None -- the C++ `ModuleLoadFromFile` FFI function still receives a `str`; coercion happens in Python.
- Behavioral: None -- `os.fspath()` on a plain `str` returns it unchanged.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- Module system Python wrapper and `load_module` function (`.knowledge/designs/0013-module-system.md`, "Python Module Wrapper" section)
- `_ffi_api.ModuleLoadFromFile` global function registration (`.knowledge/designs/0013-module-system.md`, "Registered Global Functions" table)

Design elements this commit produces:
- `PathLike` acceptance pattern for Python FFI wrappers that take file paths -- `os.fspath()` coercion at the Python boundary before crossing into C++ FFI.

## Usage Examples

Passing a `pathlib.Path` to `load_module`:
```python
from pathlib import Path
import tvm_ffi

# Both styles now work:
mod1 = tvm_ffi.load_module("path/to/module.so")
mod2 = tvm_ffi.load_module(Path("path/to/module.so"))
mod2.func_name(*args)
```
