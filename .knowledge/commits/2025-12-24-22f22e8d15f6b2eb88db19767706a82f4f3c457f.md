# Suppress latest clang-tidy warnings in overload.h
## TL;DR
- Adds a `// NOLINTNEXTLINE(bugprone-unchecked-optional-access)` suppression to `TypedOverload::CallAux` in `include/tvm/ffi/reflection/overload.h`, where `*std::get<I>(tuple)` dereferences each `std::optional` in the `CaptureTuple` without an explicit `has_value()` guard. The access is intentionally unchecked because `CallAux` is only reached after `TrySetAux` has validated all optionals.
- Adds a Doxygen `/*! \brief The super class */` comment on the `using Super = ObjectDef<Class>` declaration in `OverloadObjectDef` to silence a clang-tidy missing-documentation warning.

## Design Elements
Design elements this commit consumes:
- **`CaptureTuple` / `TypedOverload` overload dispatch** (`.knowledge/designs/0008-reflection.md`) -- `CaptureTuple` is `std::tuple<std::optional<std::decay_t<Args>>...>`, built by `CaptureTupleAux`. Each optional is populated in `TrySetOne` (which returns false on type-mismatch), and only after the fold-expression in `TrySetAux` confirms all succeeded does `CallAux` dereference them. The new NOLINT comment documents this intentional invariant for future readers and the linter.
- **`OverloadObjectDef<Class>`** (`.knowledge/designs/0008-reflection.md`) -- a thin private-inheritance wrapper around `ObjectDef<Class>` that adds overloaded method registration. The `using Super` alias was missing a Doxygen comment expected by clang-tidy documentation checks.
