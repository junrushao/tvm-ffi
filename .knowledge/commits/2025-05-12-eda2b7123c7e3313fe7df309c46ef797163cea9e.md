# [FFI][LLVM] Fix compilation errors with clang20 (#17954)

## TL;DR
- Changes `nullptr_t` to `std::nullptr_t` in the deleted `String` constructor declaration in `include/tvm/ffi/string.h`.
- Fixes a compilation failure when building with Clang 20, which no longer promotes the unqualified `nullptr_t` from the global namespace into scope without the `std::` prefix.

## Key Exports

No new exports. The change is a one-token qualification fix on an already-deleted constructor:

**Before:** `String(nullptr_t) = delete;`
**After:** `String(std::nullptr_t) = delete;`

The deleted constructor exists to prevent implicit construction of `String` from `nullptr`, which would be semantically invalid (String is a non-nullable ObjectRef wrapper). The behavioral contract is unchanged.

## Impact
- API: None. The constructor remains deleted; callers cannot invoke it.
- ABI: None. Deleted functions emit no symbols.
- Behavioral: None beyond restoring compilability on Clang 20.

## Design Elements
Design elements this commit consumes:
- C++11 `std::nullptr_t` (from `<cstddef>`, already included by `string.h`).
- Clang 20 stricter conformance: unqualified `nullptr_t` in class scope is no longer implicitly resolved to `std::nullptr_t`.

Design elements this commit produces:
- None. This is a conformance fix, not a design change.
