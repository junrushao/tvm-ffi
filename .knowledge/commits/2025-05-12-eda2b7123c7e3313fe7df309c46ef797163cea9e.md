# Fix clang20 compilation error by qualifying nullptr_t with std::

## TL;DR
- Changes `nullptr_t` to `std::nullptr_t` in the deleted constructor of `String` (`include/tvm/ffi/string.h`), fixing a compilation error under clang 20 which no longer resolves the unqualified `nullptr_t` in this context.
- One-line, one-file change with no behavioral or ABI impact.

## Impact
- API: none -- the deleted constructor already prevented construction of `String` from `nullptr`; the fix merely qualifies the type name so newer compilers accept it.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit **consumes**:
- **Container System / String** (`.knowledge/designs/0005-containers.md`): The `String` class is a core FFI container. The deleted `std::nullptr_t` constructor enforces the invariant that `String` must always hold valid string data (never null). This commit touches that guard.

Design elements this commit **produces**:
- None. No new design elements are introduced. This is a strictly mechanical compiler-compatibility fix.
