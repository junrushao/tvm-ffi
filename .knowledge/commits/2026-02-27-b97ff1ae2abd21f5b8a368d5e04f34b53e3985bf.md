# Remove Python-side field descriptor infrastructure from c_class, simplify to register_object pass-through

## TL;DR
- Removes the Python-side dataclass field descriptor system (`_utils.py`, `field.py`, complex `c_class.py`) that duplicated C++ reflection metadata. Total: ~555 lines deleted.
- Simplifies `c_class` decorator to a thin wrapper around `register_object(type_key)`, delegating all field/method binding to the existing C++ reflection + `_add_class_attrs` pipeline.
- Fixes `_add_class_attrs` to always override `__c_ffi_init__` per type, preventing inherited base-class constructors from masking derived-class constructors.

## Key Exports

**`c_class` decorator** (simplified signature):
```python
def c_class(type_key: str, **kwargs: Any) -> Callable[[_T], _T]:
    """Thin wrapper around register_object(type_key)."""
    return register_object(type_key)
```

**Removed exports from `tvm_ffi.dataclasses`:**
- `field()`, `Field`, `KW_ONLY`, `MISSING` -- no longer available
- `c_class` parameters `init` and `kw_only` -- removed

**`_add_class_attrs` fix** (`registry.py`):
```python
# New: always override __c_ffi_init__ (like __ffi_shallow_copy__)
elif name == "__c_ffi_init__":
    setattr(type_cls, name, method.as_callable(type_cls))
```

## Impact
- API: Breaking. `field()`, `Field`, `KW_ONLY`, `MISSING` removed from `tvm_ffi.dataclasses`. `c_class` no longer accepts `init` or `kw_only` params.
- Behavioral: `c_class`-decorated classes now use the C++ FFI constructor directly (positional args in field order) instead of Python codegen'd init with keyword-only and default factory support.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- C++ reflection system (`ObjectDef`, `TypeInfo`, `TypeField`) -- [design 0009](../designs/0009-reflection.md)
- `register_object` / `_add_class_attrs` pipeline -- [design 0018](../designs/0018-python-dataclasses.md)

Design elements this commit produces:
- **Simplified c_class = register_object** -- eliminates Python-side field descriptor duplication, establishing convention that C++ reflection is the single source of truth for field metadata
- **`__c_ffi_init__` always-override pattern** in `_add_class_attrs` -- ensures each type gets its own constructor, matching the existing `__ffi_shallow_copy__` pattern

## Usage Examples
```python
# Before (removed):
from tvm_ffi.dataclasses import c_class, field
@c_class("example.MyClass")
class MyClass:
    v_i64: int
    v_f64: float = field(default=0.0)

# After (simplified):
from tvm_ffi.dataclasses import c_class
@c_class("example.MyClass")
class MyClass(Object):
    v_i64: int
    v_f64: float
# __init__ comes from C++ reflection via __c_ffi_init__
obj = MyClass(4, 0.0)  # positional args in field order
```
