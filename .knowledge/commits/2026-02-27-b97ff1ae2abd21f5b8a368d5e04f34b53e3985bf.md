# Remove Python-side field descriptor infrastructure from @c_class

## TL;DR
- Delete `_utils.py` (210 LOC) and `field.py` (169 LOC) — the Python-side `Field`/`KW_ONLY`/`method_init` codegen that duplicated C++ reflection metadata is gone entirely.
- Reduce `c_class.py` from 190 to 36 lines: `@c_class(type_key)` is now a thin pass-through to `register_object`, dropping `init`, `kw_only`, bijection validation, and `fill_dataclass_field` wiring.
- Fix `_add_class_attrs` in `registry.py` to always override `__c_ffi_init__` per type (matching the existing `__ffi_shallow_copy__` override pattern), preventing a derived class from inheriting a base class constructor with the wrong field count.

def _add_class_attrs(type_cls: type, type_info: TypeInfo) -> type:
    for method in type_info.methods:
        name = method.name
        if name == "__ffi_shallow_copy__":
            setattr(type_cls, name, method.as_callable(type_cls))  # always override
        elif name == "__c_ffi_init__":

## Impact
- API: **Breaking.** `field()`, `Field`, `KW_ONLY`, `MISSING` removed from `tvm_ffi.dataclasses`. `c_class(init=...)` and `c_class(kw_only=...)` params removed. `c_class`-decorated classes must now explicitly inherit from `Object`. `__init__` is positional-only (C++ field order).
- Behavioral: `@c_class` no longer validates that Python annotations match C++ fields; the bijection invariant is removed. `__init__` on derived classes now uses C++-direct constructor (positional args); keyword-only args and defaults from `field(default=...)` are no longer supported.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**Before/after for typical c_class usage (class definition)**:

```python
# BEFORE: Python annotations, field() defaults, kw_only, explicit base not required
from tvm_ffi.dataclasses import c_class, field, KW_ONLY

@c_class("testing.TestCxxClassDerived", kw_only=False)
class _TestCxxClassDerived(_TestCxxClassBase):
    v_f64: float
    v_f32: float = 8            # default via Python field assignment

@c_class("testing.TestCxxKwOnly", kw_only=True)
class _TestCxxKwOnly:           # no explicit Object base needed
    x: int
    y: int

# AFTER: No field() defaults, no kw_only, must inherit from Object
from tvm_ffi.dataclasses import c_class
from tvm_ffi.core import Object

@c_class("testing.TestCxxClassDerived")
class _TestCxxClassDerived(_TestCxxClassBase):
    v_f64: float
    v_f32: float                # no default; C++ controls defaults

@c_class("testing.TestCxxKwOnly")
class _TestCxxKwOnly(Object):   # explicit Object inheritance required
    x: int
    y: int
```

**Before/after for instantiation (call site)**:

```python
# BEFORE: keyword arguments supported
obj = _TestCxxClassDerived(v_i64=1, v_i32=2, v_f64=3.5, v_f32=4.5)

# AFTER: positional args only, in C++ field-registration order
obj = _TestCxxClassDerived(1, 2, 3.5, 4.5)
```

**Derived-class constructor masking bug — before/after in registry.py**:

```python
# BEFORE (bug): derived class inherits base __c_ffi_init__ if it exists on base
# Result: DerivedDerived(1,2,3,4,"s",True) calls TestCxxClassDerived's __c_ffi_init__
# with 6 args -> wrong field count -> silent corruption or error
elif not hasattr(type_cls, name):
    setattr(type_cls, name, method.as_callable(type_cls))  # only set if not inherited

# AFTER (fixed): always set __c_ffi_init__ per type
elif name == "__c_ffi_init__":
    setattr(type_cls, name, method.as_callable(type_cls))  # always override
```
