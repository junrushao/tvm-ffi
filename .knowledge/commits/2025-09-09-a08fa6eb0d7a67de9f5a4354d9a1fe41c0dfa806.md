# Rename and consolidate object declaration and ref macros

## TL;DR
- Renames 7 macros in `object.h` to a consistent `TVM_FFI_DECLARE_OBJECT_INFO*` / `TVM_FFI_DEFINE_OBJECT_REF_METHODS*` naming scheme and absorbs `_type_key` into the declare macros as a parameter.
- Eliminates 4 separate mutable/immutable ref macros by using `std::conditional_t<ObjectName::_type_mutable, ...>` to dispatch pointer constness at compile time.
- Adds `_type_mutable = true` to `ModuleObj` (previously handled implicitly by the deleted `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS`).

### Rename mapping

| Old macro | New macro |
|---|---|
| `TVM_FFI_DECLARE_BASE_OBJECT_INFO(T, Parent)` | `TVM_FFI_DECLARE_OBJECT_INFO(Key, T, Parent)` |
| `TVM_FFI_DECLARE_FINAL_OBJECT_INFO(T, Parent)` | `TVM_FFI_DECLARE_OBJECT_INFO_FINAL(Key, T, Parent)` |
| `TVM_FFI_DECLARE_STATIC_OBJECT_INFO(T, Parent)` | `TVM_FFI_DECLARE_OBJECT_INFO_STATIC(Key, T, Parent)` |
| `TVM_FFI_DEFINE_OBJECT_REF_METHODS(T, Parent, Obj)` | `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE(T, Parent, Obj)` |
| `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS(T, Parent, Obj)` | `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NOTNULLABLE(T, Parent, Obj)` |
| `TVM_FFI_DEFINE_MUTABLE_OBJECT_REF_METHODS(T, Parent, Obj)` | *(removed -- absorbed into NULLABLE via `_type_mutable`)* |
| `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS(T, Parent, Obj)` | *(removed -- absorbed into NOTNULLABLE via `_type_mutable`)* |

Additionally, a new internal-only macro `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY(T, Parent)` is introduced for the rare case where `_type_key` is already defined as a class member (used only by `TVM_FFI_DECLARE_OBJECT_INFO_STATIC`).

## Key Exports

**Macros** (all in `include/tvm/ffi/object.h`):

| Macro | Signature | Expansion summary |
|---|---|---|
| `TVM_FFI_DECLARE_OBJECT_INFO(Key, T, Parent)` | 3-arg | Sets `_type_key = Key`, then delegates to `PREDEFINED_TYPE_KEY` for dynamic type index allocation |
| `TVM_FFI_DECLARE_OBJECT_INFO_FINAL(Key, T, Parent)` | 3-arg | Sets `_type_child_slots=0`, `_type_final=true`, then delegates to `DECLARE_OBJECT_INFO` |
| `TVM_FFI_DECLARE_OBJECT_INFO_STATIC(Key, T, Parent)` | 3-arg | Sets `_type_key = Key`, `RuntimeTypeIndex()` returns compile-time `_type_index` |
| `TVM_FFI_DECLARE_OBJECT_INFO_PREDEFINED_TYPE_KEY(T, Parent)` | 2-arg | Same as old `DECLARE_BASE_OBJECT_INFO` -- assumes `_type_key` is already a class member |
| `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE(T, Parent, Obj)` | 3-arg | Default constructor, ObjectPtr constructor, UnsafeInit constructor, `__PtrType` dispatched on `Obj::_type_mutable`, `_type_is_nullable=true` |
| `TVM_FFI_DEFINE_OBJECT_REF_METHODS_NOTNULLABLE(T, Parent, Obj)` | 3-arg | UnsafeInit constructor only, `__PtrType` dispatched on `Obj::_type_mutable`, `_type_is_nullable=false` |

**Key behavioral change in ref macros**: Both `NULLABLE` and `NOTNULLABLE` now use:
```cpp
using __PtrType = std::conditional_t<ObjectName::_type_mutable, ObjectName*, const ObjectName*>;
```
This replaces the previous 4-way split (mutable/immutable x nullable/notnullable) with 2 macros that auto-dispatch constness based on `ObjectName::_type_mutable`.

**New static field on `ModuleObj`** (`include/tvm/ffi/extra/module.h`):
```cpp
static constexpr const bool _type_mutable = true;
```
Previously, `ModuleObj` used `TVM_FFI_DEFINE_MUTABLE_NOTNULLABLE_OBJECT_REF_METHODS` which hardcoded mutable pointer access. Now mutability is encoded in the Obj class itself.

## Impact
- API: **Breaking** for all downstream C++ code that uses any of the 7 renamed/removed macros. Every call site must be migrated to the new names. The declare macros now take `TypeKey` as the first argument (was previously a separate `static constexpr` member).
- Behavioral: `operator->()` and `get()` return type changed from hardcoded `const ObjectName*` or `ObjectName*` to `__PtrType` (a `std::conditional_t`). This is source-compatible but changes the method signature in a way that could affect SFINAE contexts or explicit type annotations.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system** Obj+Ref pattern, `_type_key`, `_type_final`, `_type_mutable`, `_type_child_slots`, `RuntimeTypeIndex()`, `_GetOrAllocRuntimeTypeIndex()` -- [designs/0003-object-system.md](../designs/0003-object-system.md)

Design elements this commit produces:
- **Consolidated macro naming convention**: `TVM_FFI_DECLARE_OBJECT_INFO{,_FINAL,_STATIC}` and `TVM_FFI_DEFINE_OBJECT_REF_METHODS_{NULLABLE,NOTNULLABLE}`. The `_type_key` parameter is now part of the declare macro invocation rather than a separate member.
- **`_type_mutable`-based pointer dispatch**: The `__PtrType = std::conditional_t<ObjectName::_type_mutable, ...>` pattern replaces the mutable/immutable macro split. This means `_type_mutable` on the Obj class is now the single source of truth for pointer constness in the Ref class.

## Usage Examples

### Before (old macros, 2 lines for Obj + separate `_type_key`)
```cpp
class MyObj : public Object {
  static constexpr const char* _type_key = "example.MyObj";
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(MyObj, Object);
};
class My : public ObjectRef {
  TVM_FFI_DEFINE_OBJECT_REF_METHODS(My, ObjectRef, MyObj);
};
```

### After (new macros, 1 line for Obj with embedded key)
```cpp
class MyObj : public Object {
  TVM_FFI_DECLARE_OBJECT_INFO_FINAL("example.MyObj", MyObj, Object);
};
class My : public ObjectRef {
  TVM_FFI_DEFINE_OBJECT_REF_METHODS_NULLABLE(My, ObjectRef, MyObj);
};
```

### Mutable objects (no longer need separate macros)
```cpp
class MutableObj : public Object {
  static constexpr bool _type_mutable = true;
  TVM_FFI_DECLARE_OBJECT_INFO_FINAL("example.MutableObj", MutableObj, Object);
};
class Mutable : public ObjectRef {
  // Same macro as immutable -- mutability detected via _type_mutable
  TVM_FFI_DEFINE_OBJECT_REF_METHODS_NOTNULLABLE(Mutable, ObjectRef, MutableObj);
};
```
