# Add opaque PyObject support for wrapping arbitrary Python objects in the FFI object system
## TL;DR
- Adds `kTVMFFIOpaquePyObject = 74` to the static type index enum, `TVMFFIOpaqueObjectCell` struct, `TVMFFIObjectCreateOpaque` C API function, and `TVMFFIOpaqueObjectGetCellPtr` inline accessor to the C ABI (`c_api.h`).
- Implements `OpaqueObjectImpl` in C++ (`src/ffi/object.cc`) that wraps an arbitrary `void*` handle with a deleter, managed as a ref-counted Object with a post-construction type index override.
- On the Python side, unknown types in `convert()` are now wrapped as `OpaquePyObject` instead of raising `TypeError`. The opaque object retains the Python reference via `Py_INCREF`, and `make_ret` unwraps it back to the original Python object, preserving identity (`y is x`).

Note: The c_api.h diff also includes extensive doc comment grammar polishing (not functional).

## Impact
- API: Adds `kTVMFFIOpaquePyObject = 74`, `TVMFFIOpaqueObjectCell`, `TVMFFIObjectCreateOpaque`, `TVMFFIOpaqueObjectGetCellPtr` to the C ABI. Adds `OpaquePyObject` class and `_convert_to_opaque_object` to Python. Static type index range changes from `[64, 74)` to `[64, 75)`.
- Behavioral: `convert()` no longer raises `TypeError` for unknown types -- it wraps them as opaque objects instead. `make_args` in Cython similarly wraps unknown argument types instead of raising. This is a semantic change for callers that previously relied on `TypeError` to detect unsupported types.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system** (`.knowledge/designs/0002-object-system.md`): Uses `Object` base class, `make_object<T>()`, `ObjectPtr`, and the `TVMFFIObject` header + cell layout pattern.
- **C ABI type index enum** (`.knowledge/designs/0001-c-abi.md`): Extends the static object type index range with a new entry at position 74.
- **C ABI function convention** (`.knowledge/designs/0001-c-abi.md`): Follows the `TVM_FFI_SAFE_CALL_BEGIN/END` pattern, `int` return code, `TVMFFIObjectHandle* out` output parameter.
- **Python bindings make_args/make_ret** (`.knowledge/designs/0012-python-bindings.md`): Extends the argument packing and result conversion dispatch to handle the new type index.
- **Object cell pattern**: Follows the established pattern of `TVMFFIObject` header + type-specific cell struct (`TVMFFIFunctionCell`, `TVMFFIErrorCell`, etc.).

Design elements this commit produces:
- **Opaque object protocol**: A new cross-layer protocol for wrapping arbitrary foreign objects as ref-counted FFI objects. The pattern is: wrap with `TVMFFIObjectCreateOpaque(handle, type_index, deleter)`, unwrap with `TVMFFIOpaqueObjectGetCellPtr(obj)->handle`. The deleter manages the foreign object's lifecycle.
- **`kTVMFFIOpaquePyObject` type index**: A new static type index (74) in the C ABI enum, extending the static object range to `[64, 75)`.
- **Python implicit conversion for unknown types**: `convert()` now has a fallback path that wraps unknown types instead of raising, changing the FFI's boundary behavior.

## Usage Examples

### Wrapping and unwrapping opaque Python objects (from tests)
**Context**: An arbitrary Python object is passed through the FFI boundary via `convert()`, stored in containers, and returned with identity preserved.

```python
import tvm_ffi

class MyObject:
    def __init__(self, value):
        self.value = value

# Direct conversion and identity check
x = MyObject("hello")
x_converted = tvm_ffi.convert(x)  # -> OpaquePyObject
assert isinstance(x_converted, tvm_ffi.core.OpaquePyObject)
assert x_converted.pyobject() is x  # identity preserved

# Passing through FFI function calls (echo round-trip)
fecho = tvm_ffi.get_global_func("testing.echo")
y = fecho(x)
assert y is x  # unwrapped automatically by make_ret

# Storing in FFI containers
a = tvm_ffi.convert([MyObject("hello"), MyObject(1)])
assert isinstance(a[0], MyObject)  # unwrapped from Array
assert a[0].value == "hello"
```

### C++ opaque object creation and lifecycle (from tests)
**Context**: Creating an opaque object from C++ and verifying its ref-counted lifecycle.

```cpp
TVMFFIObjectHandle handle = nullptr;
TVMFFIObjectCreateOpaque(new DummyObj(10), kTVMFFIOpaquePyObject,
                         DummyObj::Deleter, &handle);
auto a = ObjectUnsafe::ObjectPtrFromOwned<Object>(static_cast<Object*>(handle));
assert(a->type_index() == kTVMFFIOpaquePyObject);
assert(static_cast<DummyObj*>(TVMFFIOpaqueObjectGetCellPtr(a.get())->handle)->value == 10);
a.reset();  // triggers deleter
```
