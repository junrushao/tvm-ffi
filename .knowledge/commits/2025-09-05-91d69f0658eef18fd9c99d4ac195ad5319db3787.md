# Add opaque PyObject support to FFI for non-native Python types

## TL;DR
- Introduces `kTVMFFIOpaquePyObject` (type index 74) in the static object range, a new C ABI struct `TVMFFIOpaqueObjectCell`, and `TVMFFIObjectCreateOpaque` C API function to wrap arbitrary Python objects as reference-counted FFI objects.
- On the Python/Cython side, adds `OpaquePyObject` class, `_convert_to_opaque_object()`, and `make_ret_opaque_object()` so that any Python object not natively supported by the FFI is transparently wrapped (instead of raising `TypeError`) and unwrapped back to its original identity on return.
- The convert path (`tvm_ffi.convert`) now falls through to opaque wrapping instead of raising `TypeError`, enabling arbitrary Python objects in FFI containers (`Array`, `Map`) and as function arguments.

## Key Exports

**Constants/Enums**:
- `kTVMFFIOpaquePyObject = 74` -- new entry in `TVMFFITypeIndex` enum (static object range `[64, 128)`). Indicates an opaque Python object whose lifecycle is managed by the FFI object system.

**Types/Classes**:
- `TVMFFIOpaqueObjectCell` (C struct):
  ```c
  typedef struct {
    void* handle;  // opaque resource handle (PyObject* for Python)
  } TVMFFIOpaqueObjectCell;
  ```
- `OpaqueObjectImpl` (C++ internal, `src/ffi/object.cc`): Inherits from both `Object` and `TVMFFIOpaqueObjectCell`. Constructor takes `(void* handle, void (*deleter)(void*))`. Destructor calls deleter. `SetTypeIndex(int32_t)` overrides the type index post-construction.
- `OpaquePyObject` (Cython class, `python/tvm_ffi/cython/object.pxi`): Subclass of `Object`. Single method `pyobject() -> object` extracts the original Python object from the cell handle.

**Functions**:
- `TVMFFIObjectCreateOpaque(void* handle, int32_t type_index, void (*deleter)(void*), TVMFFIObjectHandle* out) -> int` -- C API. Creates a ref-counted opaque object. Currently only `kTVMFFIOpaquePyObject` is accepted; others raise `RuntimeError`.
- `TVMFFIOpaqueObjectGetCellPtr(TVMFFIObjectHandle obj) -> TVMFFIOpaqueObjectCell*` -- inline C accessor. Returns pointer to cell at `obj + sizeof(TVMFFIObject)`.
- `_convert_to_opaque_object(pyobject) -> OpaquePyObject` -- Cython/Python. Py_INCREFs the object, calls `TVMFFIObjectCreateOpaque` with `tvm_ffi_pyobject_deleter`.
- `make_ret_opaque_object(TVMFFIAny result) -> object` -- Cython internal. Wraps the returned FFI value in `OpaquePyObject`, then immediately calls `.pyobject()` to unwrap to the original Python object (identity-preserving).

**Renames**:
- `tvm_ffi_callback_deleter` -> `tvm_ffi_pyobject_deleter` (Cython, `function.pxi`). Generalized from function-only deleter to any Python object deleter. Reused by both `_convert_to_ffi_func` and `_convert_to_opaque_object`.

## Impact
- API: `tvm_ffi.convert()` no longer raises `TypeError` for unknown types; it wraps them as opaque objects. Code relying on `TypeError` from `convert()` for unsupported types will silently succeed instead. Callers that catch `TypeError` to detect unconvertible types need updating.
- Behavioral: FFI function calls (`make_args` in Cython) now accept arbitrary Python objects as arguments instead of raising `TypeError`. On return, opaque objects are automatically unwrapped to the original Python object (identity preserved via `PyObject*` pointer).
- Flags/config: none
- Data formats/schemas: The type index table gains entry 74 (`kTVMFFIOpaquePyObject`). Serialization formats that encode type indices must handle this new index.

## Design Elements
Design elements this commit consumes:
- **C ABI type index layout** ([0001-c-abi-layer](../../.knowledge/designs/0001-c-abi-layer.md), [ADR 0004-type-index-layout](../../.knowledge/ADRs/0004-type-index-layout.md)): Allocates index 74 in the static object range `[64, 128)`, following the established partitioning. `kTVMFFIStaticObjectEnd` moves from 74 to 75.
- **Object system lifecycle** ([0003-object-system](../../.knowledge/designs/0003-object-system.md)): `OpaqueObjectImpl` uses `make_object<T>` + custom deleter pattern. Requires post-construction `SetTypeIndex()` because `RuntimeTypeIndex()` does not apply to opaque types.
- **Static object cell layout convention** ([0001-c-abi-layer](../../.knowledge/designs/0001-c-abi-layer.md)): Follows the `{ TVMFFIObject header, TypeSpecificCell }` pattern with `TVMFFIOpaqueObjectGetCellPtr` accessor at `obj + sizeof(TVMFFIObject)`.
- **Python convert pipeline** ([0014-python-package](../../.knowledge/designs/0014-python-package.md)): Extends the `convert()` fallthrough path from `TypeError` to opaque wrapping.
- **Cython FFI argument marshalling** (`function.pxi`): Extends `make_args` and `make_ret` with new type index branch.

Design elements this commit produces:
- **Opaque PyObject protocol**: A new cross-layer protocol for wrapping non-FFI-native Python objects as ref-counted FFI objects. The object retains its Python identity (same `PyObject*` pointer) through the C++ runtime and back. This enables storing arbitrary Python objects in FFI containers and passing them through FFI function boundaries.
- **`TVMFFIOpaqueObjectCell` struct**: New C ABI cell type for opaque objects, following the established cell pattern.
- **`TVMFFIObjectCreateOpaque` C API**: New C ABI entry point for creating opaque objects.

## Usage Examples

**Python: arbitrary object through FFI echo function**
```python
class MyObject:
    def __init__(self, value):
        self.value = value

# Pass through FFI function -- object identity preserved
fecho = tvm_ffi.get_global_func("testing.echo")
x = MyObject("hello")
y = fecho(x)
assert y is x  # same Python object

# Store in FFI containers
arr = tvm_ffi.convert([MyObject(1), MyObject(2)])
assert isinstance(arr[0], MyObject)
assert arr[0].value == 1
```

**C++ side: opaque object is just an ObjectRef/Any**
```cpp
// C++ sees opaque objects as plain ObjectRef or Any
// The handle can be inspected via TVMFFIOpaqueObjectGetCellPtr
TVMFFIObjectHandle handle;
TVMFFIObjectCreateOpaque(py_obj, kTVMFFIOpaquePyObject, deleter, &handle);
// handle->type_index() == kTVMFFIOpaquePyObject
// TVMFFIOpaqueObjectGetCellPtr(handle)->handle == py_obj
```
