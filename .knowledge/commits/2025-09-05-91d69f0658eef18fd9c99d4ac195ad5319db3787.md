# Add opaque PyObject support to FFI for transparent round-tripping of unrecognized Python types
## TL;DR
- Introduces `kTVMFFIOpaquePyObject = 74` as a new static type index and `TVMFFIOpaqueObjectCell` struct in the C ABI, along with the `TVMFFIObjectCreateOpaque` C API function and the `TVMFFIOpaqueObjectGetCellPtr` inline accessor, enabling language bindings to wrap arbitrary opaque handles (e.g., `PyObject*`) as ref-counted FFI objects.
- On the Python/Cython side, adds `OpaquePyObject` (a Cython `cdef class` extending `Object`) with a `pyobject()` method that recovers the original Python object from the opaque handle. The `make_args` fallback in `function.pxi` now wraps unrecognized Python types as opaque objects (instead of raising `TypeError`), and `make_ret` unwraps them transparently back to native Python objects, enabling full round-trip identity preservation.
- Updates `convert.py` to delegate unknown types to `_convert_to_opaque_object` instead of raising `TypeError`, allowing `Array`/`Map` containers to hold arbitrary Python objects.

## Impact
- **API**:
  - **C ABI**: New enum value `kTVMFFIOpaquePyObject = 74` in `TVMFFITypeIndex`, new struct `TVMFFIOpaqueObjectCell`, new function `TVMFFIObjectCreateOpaque`, new inline accessor `TVMFFIOpaqueObjectGetCellPtr`. These are all additive -- no existing API is broken.
  - **Python**: New Cython class `OpaquePyObject` (accessible as `tvm_ffi.core.OpaquePyObject`). The `make_args` fallback path changes from raising `TypeError` to wrapping as opaque object. `convert()` in `convert.py` no longer raises `TypeError` for unrecognized types; it wraps them as opaque objects. These are behavioral changes: code that previously relied on `TypeError` from `convert()` or `make_args` for unrecognized types will now silently wrap them instead.
  - **C++**: `OpaqueObjectImpl` class in `src/ffi/object.cc` (internal, not in public headers). On C++ side, opaque objects are represented as `ObjectRef` / `Any` -- the C++ code does not need to know the Python type.
- **Flags/config**: None.
- **Data formats/schemas**: None.

## Design Elements

Design elements this commit **consumes**:

- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Extends the `TVMFFITypeIndex` enum with `kTVMFFIOpaquePyObject = 74`, consuming the last available slot before `kTVMFFIStaticObjectEnd`. Follows the Object Cell Layout Convention by placing `TVMFFIOpaqueObjectCell` immediately after the `TVMFFIObject` header (offset 16). Adds `TVMFFIObjectCreateOpaque` and `TVMFFIOpaqueObjectGetCellPtr` following the same patterns as `TVMFFIFunctionCreate`/`TVMFFIFunctionGetCellPtr`.
- **Object System** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `OpaqueObjectImpl` inherits from `Object` (for ref-counting + type system participation) and `TVMFFIOpaqueObjectCell` (for the C ABI cell layout). Uses `make_object<OpaqueObjectImpl>` for allocation, then `SetTypeIndex` to override the type index post-construction (because the constructor happens before `RuntimeTypeIndex()` is set in `make_object`). Uses `ObjectUnsafe::GetHeader` and `ObjectUnsafe::MoveObjectPtrToTVMFFIObjectPtr` for internal operations.
- **Function System** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): The `tvm_ffi_callback_deleter` is renamed to `tvm_ffi_pyobject_deleter` and reused for both callback functions and opaque objects, since both wrap a `PyObject*` with `Py_INCREF`/`Py_DECREF` lifecycle management.
- **Python Bindings** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): Modifies the `make_args` argument packing priority in `function.pxi` to add a new fallback step (position 20): when no known type matches, the object is wrapped via `_convert_to_opaque_object` instead of raising `TypeError`. Modifies `make_ret` to intercept `kTVMFFIOpaquePyObject` before the general object path, calling `make_ret_opaque_object` which unwraps back to the native Python object via `OpaquePyObject.pyobject()`.
- **Container System** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The opaque object support flows through containers via `convert()` in `convert.py`. Lists/tuples/dicts containing arbitrary Python objects are now convertible to `Array`/`Map` because each unrecognized element becomes an opaque object.

Design elements this commit **produces**:

- **Opaque Object Pattern**: A new cross-language object wrapper pattern where arbitrary foreign-language handles are wrapped as ref-counted FFI `Object`s with a deleter callback. Key components:
  - `TVMFFIOpaqueObjectCell { void* handle; }` at the C ABI level
  - `OpaqueObjectImpl : Object, TVMFFIOpaqueObjectCell` at the C++ level (private to `src/ffi/object.cc`)
  - `OpaquePyObject(Object)` at the Python/Cython level
  - `TVMFFIObjectCreateOpaque(handle, type_index, deleter, &out)` as the creation API
  - The pattern is extensible: `type_index` is parameterized, so future opaque types (e.g., `kTVMFFIOpaqueRustObject`) could reuse the same machinery. Currently only `kTVMFFIOpaquePyObject` is accepted (enforced by a runtime check in `TVMFFIObjectCreateOpaque`).
  - **Identity preservation invariant**: when an opaque PyObject round-trips through FFI (Python -> C++ -> Python), `make_ret_opaque_object` returns the original Python object identity (`obj is original_obj`). This is verified by the `test_echo_with_opaque_object` test checking `y is x`.
  - **Ref-count correctness**: `Py_INCREF` on creation, `Py_DECREF` via the deleter on destruction. Tests verify ref-count transitions explicitly.

## Reflection

### Design docs to write

- **`.knowledge/designs/0001-c-abi.md` (update)**: The C ABI design doc's "Object Cell Layout Convention" table and "New static object types" extension point section should be updated to include `TVMFFIOpaqueObjectCell` / `TVMFFIOpaqueObjectGetCellPtr` and note that `kTVMFFIOpaquePyObject = 74` consumes the last static object slot (indices `[75, 127)` remain available). The "extern C API Surface" table should add `TVMFFIObjectCreateOpaque`.
  - Why: Future commits that add new static object types or new opaque object kinds will reference this slot allocation.

- **`.knowledge/designs/0014-python-bindings.md` (update)**: The "Argument Packing Priority Order" section should add step 20 (opaque object fallback). The "Key Classes" section should add `OpaquePyObject`. The behavioral change in `convert()` (no longer raises `TypeError` for unrecognized types) should be documented as a contract change.
  - Why: Any future commit that modifies `make_args` or `convert()` behavior needs to understand the opaque fallback path.

### ADRs to write

- **`.knowledge/ADRs/0023-opaque-pyobject-fallback.md`**: Record the decision to silently wrap unrecognized Python types as opaque objects rather than raising `TypeError`.
  - Context: Previously, passing an unrecognized Python type to an FFI function raised `TypeError`. This was inconvenient for mixed Python/C++ workflows where Python objects need to be stored in containers or passed through callbacks.
  - Alternatives: (1) Keep `TypeError` and require explicit wrapping; (2) Allow a registration mechanism for custom converters. The chosen approach (silent wrapping) is the simplest and enables maximum interoperability, but loses early error detection for genuinely mistyped arguments.
  - Trade-offs: Ease of use vs. error detection. Users who previously relied on `TypeError` as a type-safety guard will not get that signal anymore.

### Design diagrams to draw

- **Mermaid**: An opaque object lifecycle diagram showing: Python object -> `Py_INCREF` -> `TVMFFIObjectCreateOpaque` -> `OpaqueObjectImpl` (ref-counted) -> stored in `Any`/container -> returned to Python -> `make_ret_opaque_object` -> `TVMFFIOpaqueObjectGetCellPtr` -> cast back to `PyObject*` -> original Python identity. The diagram should also show the destruction path: `DecRef` to 0 -> `~OpaqueObjectImpl` -> deleter -> `Py_DECREF`.
