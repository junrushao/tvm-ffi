# Guard `ml_dtypes.float4_e2m1fn` access in `_dtype.py` for `ml_dtypes < 0.5` compat

## TL;DR
- Wraps the `ml_dtypes.float4_e2m1fn` registration in `_dtype.py` with a `hasattr` guard, fixing an `AttributeError` when `ml_dtypes < 0.5` is installed.
- Followup to PR #198 (commit 9574e9d), which applied the same guard pattern in the Cython layer (`dtype.pxi`) but missed this pure-Python counterpart.

## Key Exports
None

## Impact
- API: none
- Behavioral: prevents `AttributeError` at import time when `ml_dtypes < 0.5` is installed (which lacks `float4_e2m1fn`)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `dtype._NUMPY_DTYPE_TO_STR` dict — the numpy-dtype-to-string mapping populated conditionally at module load time (`python/tvm_ffi/_dtype.py:311-320`). Pattern: `try: import optional_dep; register entries; except ImportError: pass`, with inner `hasattr` guards for version-gated attributes. Documented in [0012-ffi-python-package](../design-records/0012-ffi-python-package.md) as "numpy is an optional dependency: `NUMPY_DTYPE_TO_STR` in `dtype.py` is populated inside a `try/except ImportError` block."

Design elements this commit produces: none

## Usage Examples
Before (broken with `ml_dtypes < 0.5`):
```python
# _dtype.py unconditionally accessed ml_dtypes.float4_e2m1fn
dtype._NUMPY_DTYPE_TO_STR[np.dtype(ml_dtypes.float4_e2m1fn)] = "float4_e2m1fn"
# -> AttributeError: module 'ml_dtypes' has no attribute 'float4_e2m1fn'
```

After (guarded):
```python
if hasattr(ml_dtypes, "float4_e2m1fn"):  # ml_dtypes >= 0.5.0
    dtype._NUMPY_DTYPE_TO_STR[np.dtype(ml_dtypes.float4_e2m1fn)] = "float4_e2m1fn"
```
