# Guard `ml_dtypes.float4_e2m1fn` access with `hasattr` for versions < 0.5

## TL;DR
- Wraps `ml_dtypes.float4_e2m1fn` dtype registration in a `hasattr` guard so that `tvm_ffi` does not crash at import time when `ml_dtypes < 0.5.0` is installed.
- Followup to PR #198 (`9574e9d`) which applied the same pattern to other `ml_dtypes`/`torch` attributes but missed this one location.

## Key Exports
None -- no new API surface; single-line guard addition.

## Impact
- API: none
- Behavioral: fixes `AttributeError` on `import tvm_ffi` when `ml_dtypes < 0.5.0` is installed (attribute `float4_e2m1fn` does not exist in older versions)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `dtype._NUMPY_DTYPE_TO_STR` mapping dict: the global numpy-dtype-to-string registry populated at module load time (`python/tvm_ffi/_dtype.py`). See `.knowledge/designs/0012-python-bindings.md`.
- `hasattr` version-guard pattern: conditional registration of dtype entries that only exist in newer library versions, established by PR #198 and the torch dtype guards.

Design elements this commit produces:
- None -- applies an existing guard pattern to a missed location.

## Usage Examples
Before (broken with `ml_dtypes < 0.5`):
```python
# Unconditional access -- raises AttributeError if float4_e2m1fn absent
dtype._NUMPY_DTYPE_TO_STR[np.dtype(ml_dtypes.float4_e2m1fn)] = "float4_e2m1fn"
```

After (fixed):
```python
if hasattr(ml_dtypes, "float4_e2m1fn"):  # ml_dtypes >= 0.5.0
    dtype._NUMPY_DTYPE_TO_STR[np.dtype(ml_dtypes.float4_e2m1fn)] = "float4_e2m1fn"
```
