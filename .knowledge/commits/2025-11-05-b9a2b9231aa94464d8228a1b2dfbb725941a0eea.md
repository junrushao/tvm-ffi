# Guard float4_e2m1fn dtype registration behind ml_dtypes >= 0.5 check
## TL;DR
- Guard `ml_dtypes.float4_e2m1fn` registration in `_dtype.py` behind `hasattr(ml_dtypes, "float4_e2m1fn")` to avoid `AttributeError` on `ml_dtypes < 0.5.0` which does not have this type.
- Followup fix to PR #198.

## Key Exports
None — no API surface changes.

## Impact
- API: none
- Behavioral: Fixes import-time `AttributeError` when `ml_dtypes < 0.5.0` is installed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **dtype system / numpy dtype mapping** (`dtype._NUMPY_DTYPE_TO_STR`) — the registry mapping numpy dtypes to TVM FFI string names. Documented in `.knowledge/designs/0005-type-traits.md`.

Design elements this commit mutates: none (guards an existing registration)

**Invariant violated before fix**: Unconditional access to `ml_dtypes.float4_e2m1fn` assumed all `ml_dtypes` versions expose this attribute. Versions < 0.5.0 do not.

**Invariant restored**: Registration of `float4_e2m1fn` only occurs when the attribute exists, maintaining backward compatibility with older `ml_dtypes` versions.

None — the fix is defensive and requires no caller changes.
