# Apply run_check() scoping pattern to test_stl to fix potential use-after-free
## TL;DR
- Wraps all assertion logic in `test_stl()` inside a nested `run_check(mod)` function to ensure temporary objects (tuples, vectors, maps, functions) returned by the loaded DSO module are destroyed before the `Module` goes out of scope.
- Removes the previous `gc.collect()` / `del mod` cleanup approach, which was insufficient because Python's GC does not guarantee deterministic destruction order.
- Follows the same pattern established in a97b7c6 for `test_load_inline_with_env_tensor_allocator` and `test_cuda_memory_alloc_noleak`.

## Design Elements
Design elements this commit consumes:
- **Module lifetime invariant** ([0011-module-system.md](../designs/0011-module-system.md)): Module must outlive all objects whose deleters reside in the loaded DSO. The nested `run_check()` pattern enforces this by scoping object lifetimes inside the function call.

Design elements this commit produces:
- None -- applies an existing pattern to a missed test.

## Usage Examples
Before/after pattern:

```python
# BEFORE (5a82940^): gc.collect() + del mod -- nondeterministic
def test_stl():
    mod = tvm_ffi.load_module(output_lib_path)
    assert list(mod.test_tuple([1, 2.5])) == [2.5, 1]
    # ... more assertions with temporaries holding DSO deleters ...
    gc.collect()
    del mod

# AFTER (5a82940): nested function scoping -- deterministic
def test_stl():
    mod = tvm_ffi.load_module(output_lib_path)
    def run_check(mod: Module) -> None:
        # Temporaries destroyed when run_check returns
        assert list(mod.test_tuple([1, 2.5])) == [2.5, 1]
        # ...
    run_check(mod)
    # mod destroyed after run_check -> safe
```
