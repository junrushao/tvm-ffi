# Fix test_stl use-after-free by scoping temp objects inside a sub-function so they are deallocated before module unload

## TL;DR
- Wraps all `test_stl` assertions inside a `run_check(mod)` helper function, ensuring intermediate Python objects (returned by STL-typed functions) are reference-counted to zero before `mod` goes out of scope.
- Removes the previous workaround (`import gc` + `gc.collect()` + `del mod` at function end) in favour of Python's deterministic scope-based cleanup.
- Also fixes `== None` → `is None` identity check for the `test_vector(None)` return value.

## Usage Examples
Before (unsafe — intermediate objects from `mod.test_*()` calls may be kept alive by CPython until GC cycle, after `mod` is freed):
```python
assert list(mod.test_tuple([1, 2.5])) == [2.5, 1]
# ... more calls ...
gc.collect()
del mod
```

After (safe — sub-function scope guarantees all intermediates are dropped before `run_check` returns, i.e., before `mod` could be freed):
```python
def run_check(mod: Module) -> None:
    # All temp variables are deallocated when run_check returns,
    # before the caller can release mod.
    assert list(mod.test_tuple([1, 2.5])) == [2.5, 1]
    assert mod.test_vector(None) is None
    # ...

run_check(mod)
```

The key insight: CPython's reference counting is deterministic within a stack frame — when `run_check` returns, all local variables are immediately freed. This guarantees deletion order: intermediates before `mod`.
