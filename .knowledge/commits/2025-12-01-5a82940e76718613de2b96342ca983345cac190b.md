# Fix use-after-free in test_stl by scoping temporaries inside nested function
## TL;DR
- Wraps all STL test assertions in a nested `run_check(mod)` function so that temporary objects (whose deleters reside in the loaded library) are destroyed before the `Module` goes out of scope.
- Removes the prior `gc.collect()` / `del mod` cleanup approach, which was insufficient because Python's local variable destruction order is not guaranteed.
- Minor style fix: `== None` changed to `is None`.

## Design Elements
Design elements this commit consumes:
- **Module-object lifetime invariant** ([0011-ffi-module-system](../design-records/0011-ffi-module-system.md)): Objects returned by module-loaded functions may contain deleters residing in the library's code segment. The module must remain loaded until all such objects are destroyed. This commit enforces that invariant in `test_stl` by using the same nested-function pattern established in commit a97b7c6.

- None. Applies an existing pattern to an additional test file.

## Usage Examples
Before/after pattern showing the incorrect vs. corrected test structure:

```python
# BEFORE (incorrect): gc.collect()/del mod does not guarantee temp destruction order
def test_stl() -> None:
    mod = tvm_ffi.load_module(output_lib_path)
    assert list(mod.test_tuple([1, 2.5])) == [2.5, 1]
    assert mod.test_vector(None) == None  # also: == None style
    # ... more assertions creating temporaries with library-resident deleters ...
    gc.collect()
    del mod
    # Problem: temporaries from assertions may still be alive when mod is deleted

# AFTER (correct): nested function ensures all temporaries are destroyed on return
def test_stl() -> None:
    mod = tvm_ffi.load_module(output_lib_path)
    def run_check(mod: Module) -> None:
        assert list(mod.test_tuple([1, 2.5])) == [2.5, 1]
        assert mod.test_vector(None) is None  # fixed: is None
        # ... all temporaries destroyed when run_check returns ...
    run_check(mod)
    # mod safely destroyed after all temporaries are gone
```
