# Add ffi::Tensor.strides() accessor

## TL;DR
- Adds `Tensor::strides()` method to the `Tensor` ref class, mirroring the existing `Tensor::shape()` accessor, returning a lazily-cached `Shape` from the underlying `DLTensor::strides` pointer.
- Renames the internal protected field `stride_data_` to `strides_data_` (plural) for consistency with the new public accessor name.
- Updates example code (`extension.cc`, `add_one_cpu.cc`, `add_one_cuda.cu`) to accept `ffi::Tensor` instead of `DLTensor*`, demonstrating the preferred typed API.

## Key Exports

**Methods**:
- `Tensor::strides() const -> tvm::ffi::Shape` -- Returns the strides of the tensor as a `Shape` object. Asserts `strides != nullptr` via `TVM_FFI_ICHECK`. Lazily constructs and caches the `Shape` in `strides_data_` on first call.

**Renames**:

| Old name | New name | Location |
|----------|----------|----------|
| `TensorObj::stride_data_` | `TensorObj::strides_data_` | `include/tvm/ffi/container/tensor.h` (protected field) |

## Impact
- API: New public method `Tensor::strides()`. No existing APIs changed or removed.
- ABI: None. The field rename is internal to the protected section of a heap-allocated object accessed only via `ObjectRef`.
- Behavioral: None for existing code. The new accessor follows the same lazy-caching pattern as `shape()`.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Always-populated strides invariant** (established in ca95b41): `strides()` relies on `DLTensor::strides` being non-null after construction. The `TVM_FFI_ICHECK(obj->strides != nullptr)` guard enforces this. See `.knowledge/designs/containers.md` NDArray/Shape/Optional section.
- **Lazy Shape caching pattern** (`Tensor::shape()` / `shape_data_`): The `strides()` method mirrors the existing `shape()` implementation exactly -- check `Optional<Shape>`, construct from raw pointer on first access, cache for subsequent calls.
- **Object/ObjectRef pattern**: `Tensor` (ref) accesses `TensorObj` (obj) internals via `get_mutable()`.

Design elements this commit produces:
- **`Tensor::strides()` accessor**: Completes the Tensor ref class API surface by exposing strides alongside `shape()`, `dtype()`, and `IsContiguous()`. This is a consumer-facing convenience rather than a new design element.
- **Example pattern: `ffi::Tensor` in function signatures**: The example updates demonstrate that library functions should accept `ffi::Tensor` (a ref-counted handle) rather than raw `DLTensor*`, establishing a preferred convention for extension code.

## Usage Examples

### Accessing tensor strides
**Context**: C++ code querying shape and strides of a tensor (from `tests/cpp/test_tensor.cc`).
```cpp
Tensor nd = Empty(Shape({1, 2, 3}), DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
Shape shape = nd.shape();
Shape strides = nd.strides();
// strides = [6, 3, 1] for row-major layout
EXPECT_EQ(strides.size(), 3);
EXPECT_EQ(strides[0], 6);
EXPECT_EQ(strides[1], 3);
EXPECT_EQ(strides[2], 1);
```

### Using ffi::Tensor in library functions (instead of DLTensor*)
**Context**: Extension library function signature (from `examples/packaging/src/extension.cc`).
```cpp
// Before: void AddOne(DLTensor* x, DLTensor* y)
// After:
void AddOne(ffi::Tensor x, ffi::Tensor y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
  // x-> still works because Tensor inherits ObjectRef which dereferences to TensorObj : DLTensor
}
```
