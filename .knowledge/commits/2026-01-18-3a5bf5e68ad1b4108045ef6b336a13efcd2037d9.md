# Add kw_only support for @c_class dataclass init generation
## TL;DR
- Adds `kw_only` parameter to `c_class(type_key, init=True, kw_only=False, repr=True)` and `field(..., kw_only=False)`.
- Introduces `KW_ONLY` sentinel class (like `dataclasses.KW_ONLY`) that marks all subsequent fields as keyword-only when used as a type annotation.
- Updates `method_init()` to generate `*` separator in the `__init__` signature for keyword-only fields.
- Adds test infrastructure: `python/tvm_ffi/testing/testing.py` and `src/ffi/testing/testing.cc` with a `TestKWOnlyObj` test class.

## Key Exports

**Class** added in `python/tvm_ffi/dataclasses/field.py`:
- `KW_ONLY` — sentinel type annotation; all fields after this annotation become keyword-only

**Parameters** added:
- `c_class(type_key, init=True, kw_only=False, repr=True)` — new `kw_only: bool` parameter
- `field(..., kw_only=False)` — new `kw_only: bool` parameter on `Field`

**Function** signature changed:
- `_inspect_c_class_fields(type_cls, type_info) -> tuple[list[TypeField], int | None]` — now returns kw_only sentinel start index
- `fill_dataclass_field(type_cls, type_field, class_kw_only=False, kw_only_from_sentinel=False)` — new keyword args

## Impact
- API: new optional parameters on `c_class()` and `field()`; new `KW_ONLY` sentinel; purely additive
- Behavioral: when `kw_only=True` or `KW_ONLY` sentinel used, generated `__init__` requires keyword arguments
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:

Design elements this commit produces:
- Extends `c_class` protocol with `kw_only` parameter and `KW_ONLY` sentinel, matching Python 3.10+ `dataclasses.KW_ONLY` semantics.

## Usage Examples
```python
from tvm_ffi.dataclasses import c_class, field, KW_ONLY

@c_class("my_ext.Config", kw_only=True)
class Config(Object):
    name: str
    value: int = field(default=0)

cfg = Config(name="test", value=42)  # keyword-only required
```
