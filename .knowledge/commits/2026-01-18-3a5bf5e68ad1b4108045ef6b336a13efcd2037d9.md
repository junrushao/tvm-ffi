# Add kw_only support for dataclass init generation in @c_class
## TL;DR
- Adds `kw_only` parameter to `field()` and class-level `@c_class(kw_only=True)` for keyword-only arguments in generated `__init__`
- Introduces `KW_ONLY` sentinel object (like `dataclasses.KW_ONLY`) — fields after the sentinel become keyword-only
- Splits `method_init` argument collection into four buckets: `pos_no_defaults`, `pos_with_defaults`, `kw_no_defaults`, `kw_with_defaults`
- Adds C++ `testing::ReflectTestCreateWithAny` helper for testing
- Validates that positional-only fields without defaults cannot follow fields with defaults

## Key Exports
```python
# Sentinel for keyword-only boundary:
KW_ONLY = _KW_ONLY_TYPE()

def field(*, kw_only: Any = MISSING, ...) -> Field:
    """Field descriptor with kw_only support."""
    # kw_only resolution: field-level > KW_ONLY sentinel > class-level
    ...

@c_class("type.key", kw_only=False)  # class-level default
class MyClass:
    a: int = field()          # positional
    _: KW_ONLY                # sentinel: fields below are keyword-only
    b: str = field()          # keyword-only
    c: int = field(kw_only=True)  # explicit keyword-only
```

## Impact
- API: `field()` gains `kw_only` parameter; `@c_class` gains `kw_only` class-level parameter; `KW_ONLY` sentinel exported
- Behavioral: generated `__init__` now supports `*, kw_only_arg` syntax in signature
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
```python
from tvm_ffi.dataclasses import c_class, field, KW_ONLY

@c_class("test.Config")
class Config:
    name: str = field()
    _: KW_ONLY
    verbose: bool = field(default=False)
    max_iter: int = field(default=100)

cfg = Config("my_config", verbose=True)  # name is positional, verbose/max_iter are keyword-only
```
