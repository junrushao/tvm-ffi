# Add kw_only support for dataclass init generation in @c_class
## TL;DR
- Adds `kw_only` parameter to `@c_class` decorator and `field()` function, mirroring Python's `dataclasses.KW_ONLY` semantics for keyword-only `__init__` parameters.
- Introduces `KW_ONLY` sentinel class (with Python <3.10 fallback) for annotation-based keyword-only field marking within class bodies.
- Extends `method_init()` code generation to produce proper `*` separator and keyword-only parameter sections in the generated `__init__` signature.

## Impact
- API: Additive -- `c_class(kw_only=...)` and `field(kw_only=...)` are new optional parameters with backward-compatible defaults. `KW_ONLY` sentinel exported from `tvm_ffi.dataclasses`.
- Behavioral: `method_init` now generates `*` separator and keyword-only parameters when `kw_only` fields are present. Existing code without `kw_only` is unaffected.
- Flags/config: none
- Data formats/schemas: none

Design elements this commit produces:
- **`KW_ONLY` sentinel** -- annotation marker for keyword-only field boundary in class bodies, with Python <3.10 fallback
- **`kw_only` parameter on `field()`** -- per-field keyword-only control
- **`kw_only` parameter on `@c_class`** -- class-level keyword-only default
- **Three-tier `kw_only` resolution protocol**: field-level > `KW_ONLY` sentinel > class-level, implemented in `fill_dataclass_field`
- **Four-list signature model in `method_init`**: `pos_no_defaults`, `pos_with_defaults`, `kw_no_defaults`, `kw_with_defaults`

## Usage Examples

### Class-level kw_only with default
**Context**: C++ type `TestCxxKwOnly` registered via `ObjectDef<T>`, all fields made keyword-only at the class level.
```python
from tvm_ffi.dataclasses import c_class, field

@c_class("testing.TestCxxKwOnly", kw_only=True)
class _TestCxxKwOnly:
    x: int
    y: int
    z: int
    w: int = 100  # keyword-only with default

obj = _TestCxxKwOnly(x=1, y=2, z=3)       # w defaults to 100
obj = _TestCxxKwOnly(x=1, y=2, z=3, w=4)  # all keyword-only
# _TestCxxKwOnly(1, 2, 3, 4)  -> TypeError: positional not accepted
```

### Per-field kw_only via field()
**Context**: Mix positional and keyword-only fields on the same class.
```python
@c_class("testing.TestCxxClassBase")
class PyBase:
    v_i64: int              # positional
    v_i32: int = field(kw_only=True)  # keyword-only

obj = PyBase(4, v_i32=8)   # v_i64 positional, v_i32 keyword-only
```
