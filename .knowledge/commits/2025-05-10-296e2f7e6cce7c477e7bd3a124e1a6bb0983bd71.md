# Specialize Variant storage to ObjectRef when all type parameters are ObjectRef subtypes

## TL;DR
- When all types in `Variant<V...>` derive from `ObjectRef`, the variant is now backed by `ObjectRef` (8 bytes) instead of `Any` (16 bytes), halving its memory footprint and enabling direct participation in the `ObjectRef` type hierarchy.
- Introduces a `VariantBase` template with two specializations: the default (backed by `Any`, for mixed POD+object variants) and `VariantBase<true>` (inherits `ObjectRef`, for all-ObjectRef variants).
- Adds `AnyUnsafe::MoveFromAnyStorageAfterCheck<T>` helper and `all_object_ref_v<T...>` compile-time trait. Fixes `TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY` macro hygiene for expression arguments.

## Key Exports

### Compile-time trait

```cpp
// include/tvm/ffi/container/container_details.h
template <typename... T>
inline constexpr bool all_object_ref_v = (std::is_base_of_v<ObjectRef, T> && ...);
```

### VariantBase (details namespace)

```cpp
// include/tvm/ffi/container/variant.h
namespace details {

// Default: backed by Any (for mixed POD+Object variants)
template <bool all_storage_object = false>
class VariantBase {
public:
  bool same_as(const VariantBase& other) const;  // delegates to Any::same_as
protected:
  explicit VariantBase(T other);       // stores into Any data_
  void SetData(Any other_data);
  Any MoveToAny() &&;
  AnyView ToAnyView() const;
  Any data_;
};

// Specialization: backed by ObjectRef (for all-ObjectRef variants)
template <>
class VariantBase<true> : public ObjectRef {
protected:
  explicit VariantBase(const T& other);   // delegates to ObjectRef(other)
  explicit VariantBase(T&& other);        // delegates to ObjectRef(move)
  explicit VariantBase(ObjectPtr<Object>);
  explicit VariantBase(Any other);        // extracts ObjectRef from Any
  void SetData(ObjectPtr<Object> other);
  Any MoveToAny() &&;                     // wraps data_ back into Any
  AnyView ToAnyView() const;             // constructs AnyView from ObjectPtr
};

}  // namespace details
```

When `all_object_ref_v<V...>` is true, `Variant<V...>` inherits from `ObjectRef` (via `VariantBase<true>`), so `sizeof(Variant<V...>) == sizeof(ObjectRef) == 8` and the variant can be used anywhere an `ObjectRef` is accepted.

### AnyUnsafe helper

```cpp
// include/tvm/ffi/any.h  (inside struct AnyUnsafe)
template <typename T>
static T MoveFromAnyStorageAfterCheck(Any&& ref);
```

Companion to the existing `CopyFromAnyStorageAfterCheck` -- enables move semantics when extracting a typed value from `Any` after storage check.

### Macro fix

```cpp
// include/tvm/ffi/base_details.h
#define TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY(result)                    \
  if constexpr (sizeof((result)->v_obj) != sizeof((result)->v_int64)) { \
    (result)->v_int64 = 0;                                              \
  }
```

Parenthesizes `result` in all uses to prevent operator-precedence bugs when the argument is an expression (e.g., `&any_data`).

## Impact
- API: `Variant<V...>` where all `V` are `ObjectRef` subtypes now publicly inherits from `ObjectRef`. This is additive -- existing code continues to compile, and variants gain `ObjectRef` methods (`.defined()`, `.same_as()`, etc.).
- ABI: No breaking change. `Variant` is a header-only template; no C ABI surface is affected.
- Behavioral: `sizeof(Variant<ObjA, ObjB>)` drops from 16 bytes (`Any`) to 8 bytes (`ObjectRef`) when all types are ObjectRef. `GetObjectPtrForHashEqual` now uses `this->data_.get()` (ObjectRef path) instead of `AnyUnsafe::ObjectPtrFromAnyAfterCheck`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- **Object system** (`.knowledge/designs/object-system.md`) -- `ObjectRef`, `ObjectPtr<Object>`, `Object::type_index()`, `ObjectUnsafe::TVMFFIObjectPtrFromObjectPtr` for constructing the AnyView in the specialized path.
- **Any system** (`.knowledge/designs/any-system.md`) -- `Any`, `AnyView`, `AnyView::CopyFromTVMFFIAny`, `AnyUnsafe::MoveAnyToTVMFFIAny`. The default `VariantBase<false>` still delegates entirely to `Any`.
- **TypeTraits protocol** (`.knowledge/designs/type-traits.md`) -- `TypeTraits<T>::CheckAnyStorage`, `MoveFromAnyStorageAfterCheck`, `CopyToAnyView`, `MoveToAny` for the `TypeTraits<Variant<V...>>` specialization.
- **Container details** (`.knowledge/designs/containers.md`) -- `storage_enabled_v`, `all_storage_enabled_v`, `type_contains_v` for variant element checking.

Design elements this commit produces:
- **Variant storage specialization pattern**: Compile-time dispatch on `all_object_ref_v<V...>` to select `Any` vs `ObjectRef` backing storage, using a CRTP-like base class `VariantBase<bool>`. This is a new design element with no existing `.knowledge/` doc.
- **`all_object_ref_v<T...>`**: Compile-time predicate for checking if all types are ObjectRef subtypes. Added to container_details.h alongside `all_storage_enabled_v`.
- **`AnyUnsafe::MoveFromAnyStorageAfterCheck<T>`**: Symmetric move counterpart to `CopyFromAnyStorageAfterCheck<T>`.

## Usage Examples

All-ObjectRef variant (new specialization):
```cpp
// Variant backed by ObjectRef -- 8 bytes, participates in ObjectRef hierarchy
Variant<TInt, Array<TInt>> v = TInt(1);
static_assert(std::is_base_of_v<ObjectRef, decltype(v)>);  // true
assert(sizeof(v) == sizeof(ObjectRef));                      // 8 bytes

// Convert to/from Any seamlessly
Any any = v;
auto v2 = any.cast<Variant<TInt, Array<TInt>>>();
assert(v.same_as(v2));  // identity preserved

// Assignment across variant alternatives
v = Array<TInt>({TInt(2), TInt(3)});
assert(v.get<Array<TInt>>().size() == 2);
```

Mixed POD+Object variant (unchanged behavior):
```cpp
// Variant backed by Any -- 16 bytes, supports POD types
Variant<String, int> v0 = 1;
Variant<String, int> v1 = 1;
assert(v0.same_as(v1));  // POD same_as via Any::same_as
```

## Reflection

### Design docs to write or update
- `.knowledge/designs/containers.md` section "Variant<T...>" -- Update to describe the dual-storage strategy: ObjectRef backing when `all_object_ref_v` is true, Any backing otherwise. Currently says "Stores a single `ObjectRef` internally" which was always inaccurate for POD-containing variants and is now explicitly wrong. Include a Mermaid class diagram showing the `VariantBase<false>` / `VariantBase<true>` inheritance.

### ADRs to write or update
- `.knowledge/ADRs/005-variant-objectref-specialization.md` -- Record the decision to specialize Variant storage to ObjectRef when all types are ObjectRef subtypes, motivated by halving memory footprint (16 -> 8 bytes) and enabling Variant to participate in the ObjectRef type hierarchy. Note the trade-off: more complex `ToAnyView()` in the specialized path (manual TVMFFIAny construction vs delegation to Any).

### Stale knowledge references
- `.knowledge/designs/containers.md` lines 122-126: Describes Variant as "Tagged union of `ObjectRef` types. Stores a single `ObjectRef` internally." This was always slightly inaccurate (Variant could hold PODs via Any) and is now explicitly wrong -- Variant's backing storage is conditionally selected at compile time.
