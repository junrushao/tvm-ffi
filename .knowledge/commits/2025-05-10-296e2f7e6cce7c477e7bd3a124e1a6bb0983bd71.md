# Variant specializes to ObjectRef storage when all types are ObjectRef-derived
## TL;DR
- When every type in `Variant<V...>` derives from `ObjectRef`, the variant now inherits from `ObjectRef` (via a `VariantBase<true>` specialization) instead of wrapping an `Any`. This makes `sizeof(Variant<...>) == sizeof(ObjectRef)` and enables direct use in `ObjectPtrHash`/`ObjectPtrEqual`.
- A new `VariantBase` template (with generic and `<true>` specialization) encapsulates the storage split. The generic path retains the original `Any`-backed storage.
- Supporting changes: new `AnyUnsafe::MoveFromAnyStorageAfterCheck<T>` helper, new `all_object_ref_v` trait, macro parenthesization fix in `TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY`.

## Impact
- API: `Variant<V...>` where all `V` are `ObjectRef` now **is-a** `ObjectRef`. Code that passes such variants to `ObjectRef`-accepting APIs will now compile where it previously did not. Existing code that uses `Variant` with mixed types (POD + ObjectRef) is unchanged.
- Behavioral: `sizeof(Variant<ObjA, ObjB>)` drops from 16 bytes (`Any`) to pointer-size (`ObjectRef`). Hash and equality for all-ObjectRef variants now use direct pointer comparison via `ObjectRef::data_.get()`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Any/AnyView value system** ([0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md)): `VariantBase<false>` delegates to `Any` for storage, `ToAnyView()`, `MoveToAny()`.
- **Object system** ([0003-ffi-object-system](../design-records/0003-ffi-object-system.md)): `VariantBase<true>` inherits `ObjectRef`, uses `ObjectPtr<Object>`, `data_.get()`.
- **TypeTraits protocol** ([0002-ffi-any-value-system](../design-records/0002-ffi-any-value-system.md)): `TypeTraits<Variant<V...>>` updated to route through new `ToAnyView()`/`MoveToAny()` indirection.
- **Container details** ([0006-ffi-containers](../design-records/0006-ffi-containers.md)): `all_storage_enabled_v`, `type_contains_v` used as before.

Design elements this commit produces:
- **`VariantBase` template with ObjectRef specialization**: New CRTP-style base that splits `Variant` storage between `Any` and `ObjectRef` paths. This is a new internal design element not yet documented.
- **`all_object_ref_v` trait**: Compile-time detector for all-ObjectRef type packs.
- **`AnyUnsafe::MoveFromAnyStorageAfterCheck<T>`**: Generic move helper dispatching through `TypeTraits<T>`.

## Usage Examples
From `tests/cpp/test_variant.cc` (`AllObjectRef` test):
```cpp
// All-ObjectRef Variant inherits ObjectRef, so sizeof matches
Variant<TInt, Array<TInt>> v0 = TInt(1);
static_assert(std::is_base_of_v<ObjectRef, decltype(v0)>);
EXPECT_EQ(sizeof(v0), sizeof(ObjectRef));

// Round-trip through Any
Any any0 = v0;
auto v2 = any0.cast<Variant<TInt, Array<TInt>>>();
EXPECT_TRUE(v0.same_as(v2));

// Assignment between alternative types
v0 = Array<TInt>({TInt(2), TInt(3)});
EXPECT_EQ(v0.get<Array<TInt>>().size(), 2);
```

From `tests/cpp/test_variant.cc` (`PODSameAs` test, showing non-ObjectRef path still works):
```cpp
Variant<String, int> v0 = 1;
Variant<String, int> v1 = 1;
EXPECT_TRUE(v0.same_as(v1));  // POD same_as via Any.same_as()
```
