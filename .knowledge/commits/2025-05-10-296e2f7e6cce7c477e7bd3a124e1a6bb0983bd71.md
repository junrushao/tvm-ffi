# Specialize Variant to use ObjectRef storage when all types are ObjectRef
## TL;DR
- Introduces a `VariantBase` class template with a bool specialization: the default (`false`) is backed by `Any`, while the `true` specialization inherits from `ObjectRef`, halving storage from 16 bytes to 8 bytes when all variant types derive from `ObjectRef`.
- `Variant<V...>` now inherits from `details::VariantBase<details::all_object_ref_v<V...>>`, making all-ObjectRef variants first-class `ObjectRef` subclasses that can participate in `ObjectPtrHash`, `ObjectPtrEqual`, and be stored in `Map` keys directly.
- Adds `AnyUnsafe::MoveFromAnyStorageAfterCheck<T>` helper for efficient move-out of `Any` to arbitrary `T`, and `all_object_ref_v<T...>` compile-time trait to detect all-ObjectRef parameter packs. Fixes macro hygiene in `TVM_FFI_CLEAR_PTR_PADDING_IN_FFI_ANY` by adding parentheses around the `result` parameter.

## Impact
- API: `Variant<V...>` where all `V` are `ObjectRef` subtypes now **is-a** `ObjectRef`. This is a behavioral change: `sizeof(Variant<TInt, Array<TInt>>) == sizeof(ObjectRef) == 8` (was `sizeof(Any) == 16`). Code that relied on `Variant` not being an `ObjectRef` may need updates, though this is unlikely since the prior design had no such public contract. `static_assert(std::is_base_of_v<ObjectRef, Variant<TInt, Array<TInt>>>)` now passes.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:

- **Any/AnyView Type Erasure** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): The `VariantBase<false>` (non-ObjectRef) path continues to use `Any` as the backing store with `AnyView` for type-checked access (`as<T>()`, `cast<T>()`). The commit also uses `AnyUnsafe::MoveAnyToTVMFFIAny` and `AnyView::CopyFromTVMFFIAny` in `TypeTraits<Variant<V...>>`.
- **Object System** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): The `VariantBase<true>` specialization inherits from `ObjectRef`, using `ObjectPtr<Object> data_` for storage, `ObjectUnsafe::TVMFFIObjectPtrFromObjectPtr` for raw pointer extraction, and the standard `IncRef`/`DecRef` ref-counting protocol.
- **Container System** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): `Variant<V...>` is a container type. The `all_storage_enabled_v<V...>` trait (pre-existing) guards the `static_assert`. The new `all_object_ref_v<V...>` trait is introduced alongside it in `container_details.h`.
- **TypeTraits Protocol** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): `TypeTraits<Variant<V...>>` methods (`CopyToAnyView`, `MoveToAny`) are updated to call through `ToAnyView()` and `MoveToAny()` on the base class, abstracting over whether the backing store is `Any` or `ObjectRef`.

Design elements this commit produces:

- **`VariantBase<bool>` dual-storage abstraction** (`include/tvm/ffi/container/variant.h:37-94`): A new `details::VariantBase` class template with two specializations:
  - `VariantBase<false>`: holds `Any data_`, provides `SetData(Any)`, `MoveToAny()`, `ToAnyView()`, `same_as()`.
  - `VariantBase<true>`: inherits `ObjectRef`, provides `SetData(ObjectPtr<Object>)`, `MoveToAny()` (wraps `ObjectRef` into `Any`), `ToAnyView()` (manually constructs `TVMFFIAny` from `data_` with proper padding clearing and null handling).
  This is a core design element for the container system: it establishes the pattern of storage specialization based on compile-time type properties of contained types.
- **`all_object_ref_v<T...>` trait** (`include/tvm/ffi/container/container_details.h`): Compile-time fold expression `(std::is_base_of_v<ObjectRef, T> && ...)` that gates the `VariantBase` specialization selection.
- **`AnyUnsafe::MoveFromAnyStorageAfterCheck<T>`** (`include/tvm/ffi/any.h`): A static method that dispatches to `TypeTraits<T>::MoveFromAnyStorageAfterCheck` for non-`Any` types, or `std::move(ref)` for `Any`. Used by `VariantBase<true>` constructor to move an `ObjectRef` out of an `Any` after type checking.

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0005-containers.md`**: The Variant section currently states "Variant<Vs...>: Backed by Any. Stores one of the variant types." This is now incomplete -- Variant may be backed by `ObjectRef` when all types are `ObjectRef`. The doc should describe the `VariantBase` dual-storage pattern, the `all_object_ref_v` selection mechanism, and the consequence that all-ObjectRef variants are `ObjectRef` subclasses. This helps classify future commits that modify Variant storage or add new container specialization patterns.

- **Update `.knowledge/designs/0002-any-system.md`**: Add `MoveFromAnyStorageAfterCheck<T>` to the `AnyUnsafe` documentation. This method is a new entry point in the `AnyUnsafe` internal API that may be used by other container types that need to extract typed values from `Any` storage.

### ADRs to write

- **`.knowledge/ADRs/0006-variant-objectref-specialization.md`**: Records the decision to specialize `Variant<V...>` storage based on whether all types are `ObjectRef`. Context: all-ObjectRef variants waste 8 bytes by storing a full `Any` (16 bytes) when only an `ObjectPtr` (8 bytes) is needed; additionally, they cannot participate in `ObjectPtrHash`/`ObjectPtrEqual` without extracting the object pointer, which requires knowing the variant is all-ObjectRef. Alternatives considered: (1) always use `Any` (simpler, but wasteful and prevents ObjectRef identity), (2) use a union of all concrete ObjectRef types (type-safe but combinatorial explosion). Trade-off: the dual-base approach adds template complexity (`VariantBase` with two specializations, `ToAnyView()` must manually construct `TVMFFIAny` in the ObjectRef path) but achieves both goals (size reduction and ObjectRef identity).

### Design diagrams to draw
