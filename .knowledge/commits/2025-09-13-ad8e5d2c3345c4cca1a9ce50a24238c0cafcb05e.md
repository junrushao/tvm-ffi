# Remove BUILD_WITH_INSTALL_RPATH ON from tvm_ffi_cython target to fix scikit-build-core packaging

## TL;DR
- Removes `BUILD_WITH_INSTALL_RPATH ON` from both macOS and Linux `set_target_properties` calls for `tvm_ffi_cython` in `CMakeLists.txt`.
- `INSTALL_RPATH` alone is retained (`@loader_path/lib` on macOS, `$ORIGIN/lib` on Linux) so the Cython extension can find `libtvm_ffi_shared.so` at runtime.
- Fixes a packaging issue encountered when building wheels via scikit-build-core (follow-up to #18239).

## Impact

- Behavioral: none — RPATH resolution behaviour is unchanged; `BUILD_WITH_INSTALL_RPATH ON` was redundant with how scikit-build-core handles install trees and its removal unblocks correct wheel layout.
- Flags/config: `BUILD_WITH_INSTALL_RPATH` property no longer set on `tvm_ffi_cython` target on macOS and Linux.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- CMake build system convention: `tvm_ffi_cython` shared-extension target with relative RPATH (`@loader_path/lib` / `$ORIGIN/lib`) so the wheel layout `tvm_ffi/<ext>.so` + `tvm_ffi/lib/libtvm_ffi_shared.so` resolves at runtime without `LD_LIBRARY_PATH`.
