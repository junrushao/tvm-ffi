# Fix `self` parameter omitted from type schema of member functions

## TL;DR
- Fixes `FunctionInfo<R (Class::*)(Args...)>` specialization to include `Class*` as the first parameter in `FuncFunctorImpl`, so that `TypeSchema()` and `Sig()` correctly report the full signature `(Class*, Args...) -> R` instead of the incorrect `(Args...) -> R`.
- Relaxes Python `TypeSchema.__post_init__` validation to allow `list` with 0 args and `dict` with 0 args (previously required exactly 1 and 2 respectively).
- Adds a `testing.schema_id_func_typed` test function to verify `TypedFunction<void(int64_t, float, Function)>` schema generation.

## Key Exports
No new public APIs. Two template specializations changed behavior:

**`FunctionInfo<R (Class::*)(Args...)>`** (`include/tvm/ffi/function_details.h:118`)
- Before: `FuncFunctorImpl<R, Args...>` -- omitted `Class*` from parameter list
- After: `FuncFunctorImpl<R, Class*, Args...>` -- includes `Class*` as first parameter

**`FunctionInfo<R (Class::*)(Args...) const>`** (`include/tvm/ffi/function_details.h:120`)
- Before: `FuncFunctorImpl<R, Args...>` -- omitted `const Class*` from parameter list
- After: `FuncFunctorImpl<R, const Class*, Args...>` -- includes `const Class*` as first parameter

**`TypeSchema.__post_init__` validation** (`python/tvm_ffi/cython/type_info.pxi:101-104`)
- `list`: accepts 0 or 1 args (was: exactly 1)
- `dict`: accepts 0 or 2 args (was: exactly 2)

## Impact
- API: None -- no public function signatures change. The schema metadata now correctly reflects the `self` parameter for methods registered via `GlobalDef::def_method`. Consumers of `TVMFFIMethodInfo::metadata` (e.g., Python stub generation, IDE tooling) will see the corrected arity.
- ABI: None -- the `TVMFFIMethodInfo` struct layout is unchanged; only the content of the JSON `type_schema` metadata string changes.
- Behavioral: Method type schemas now include the owning class as the first argument. For example, a method `int MyCls::add(int a)` registered via `def_method("MyCls_add", &MyCls::add)` previously had schema `(int) -> int` but now correctly reports `(MyCls*, int) -> int`. This affects `FuncFunctorImpl::TypeSchema()` and `FuncFunctorImpl::Sig()` outputs for all member function pointers.
- Flags/config: None.
- Data formats/schemas: The JSON `type_schema` for member functions changes. Example: `add_int` method schema goes from `{"type":"ffi.Function","args":[{"type":"int"},{"type":"int"}]}` to `{"type":"ffi.Function","args":[{"type":"int"},{"type":"testing.SchemaAllTypes"},{"type":"int"}]}` (return type, then self, then args).

## Design Elements
Design elements this commit consumes:
- **`FunctionInfo` / `FuncFunctorImpl` template dispatch** (`.knowledge/designs/function-system.md`): The `FunctionInfo` specializations determine how function signatures are decomposed into return type and argument list for schema generation and argument unpacking.
- **`GlobalDef::def_method`** (`.knowledge/designs/reflection.md`): Uses `FunctionInfo<std::decay_t<Func>>::TypeSchema()` to produce the JSON type schema stored in `TVMFFIMethodInfo::metadata`.
- **Python `TypeSchema` dataclass** (`.knowledge/designs/0014-python-bindings.md`): Parses JSON type schemas from C++ and validates structural constraints.

Design elements this commit produces:
- **Correct `FunctionInfo` member-pointer specialization semantics**: Establishes the contract that `FunctionInfo<R (Class::*)(Args...)>` includes `Class*` as the first parameter (matching the actual calling convention where `self` is the first packed argument). This is distinct from `FunctionInfoHelper<R (T::*)(Args...)>` which intentionally omits the class parameter because it decomposes `operator()` for lambda/functor types where the lambda object is an implicit context, not a visible parameter.

## Usage Examples
Before this fix, querying the type schema for a member function method gave an incorrect arity:

```cpp
// C++ class with method
class MyCls : public Object {
  int64_t AddInt(int64_t other) const { return other + 1; }
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(MyCls, Object);
};

// Registration via def (instance method) or def_method
refl::ObjectDef<MyCls>()
    .def("add_int", &MyCls::AddInt);

// Before fix: schema was {"type":"ffi.Function","args":[{"type":"int"},{"type":"int"}]}
//   => Callable[[int], int]  -- missing self parameter
// After fix:  schema is {"type":"ffi.Function","args":[{"type":"int"},{"type":"testing.MyCls"},{"type":"int"}]}
//   => Callable[[testing.MyCls, int], int]  -- self correctly included
```

Python-side schema rendering:

```python
# Before fix
schema = get_global_func_schema("add_int")
repr(schema)  # "Callable[[int], int]"

# After fix
repr(schema)  # "Callable[[testing.MyCls, int], int]"
```
