# Fix member function schema generation to include `self`/`this` as first argument
## TL;DR
- `FunctionInfo` specializations for pointer-to-member functions (`R (Class::*)(Args...)`) were missing the implicit `this` parameter, producing schemas with one fewer argument than the actual calling convention.
- Fixed by adding `Class*` (or `const Class*` for const methods) to the `FuncFunctorImpl` type parameter pack in the C++ `FunctionInfo` template specializations.
- Relaxed Python `TypeSchema` validation for bare `list` and `dict` types (0 args allowed) to accommodate generic container types in schema JSON.

## Key Exports

```python
# C++ template specializations (function_details.h)
# These are compile-time type traits, not runtime symbols.

# Before (broken):
#   FunctionInfo<R (Class::*)(Args...)>    -> FuncFunctorImpl<R, Args...>        # missing Class*
#   FunctionInfo<R (Class::*)(Args...) const> -> FuncFunctorImpl<R, Args...>     # missing const Class*

# After (fixed):
#   FunctionInfo<R (Class::*)(Args...)>    -> FuncFunctorImpl<R, Class*, Args...>
#   FunctionInfo<R (Class::*)(Args...) const> -> FuncFunctorImpl<R, const Class*, Args...>
# Interacts with: Function.FromTyped (uses FunctionInfo to infer arg types for schema generation)
# Interacts with: GlobalDef.def_method (wraps member function pointers via this path)
# Invariant: schema arg list must include self/this as first argument for instance methods

# Python TypeSchema validation (type_info.pxi)
class TypeSchema:
    """Relaxed validation to allow bare list/dict without type args."""
    # list: len(args) in (0, 1)   # was: len(args) == 1
    # dict: len(args) in (0, 2)   # was: len(args) == 2
    # Interacts with: schema JSON parsing from C++ metadata
```

## Impact
- API: None — no public API signature changes. The fix corrects the *metadata* (schema JSON) for already-registered member functions. Callers already pass `self` at the calling convention level; only the reported schema was wrong.
- Behavioral: Method type schemas now correctly report `self` as the first argument. Tools consuming schema JSON (e.g., stub generators, IDE integrations) will see the corrected arity.
- Flags/config: None
- Data formats/schemas: Method schema JSON gains one additional argument entry (the class type) at position 0 for instance methods. E.g., `add_int` schema changes from `(int) -> int` to `(SchemaAllTypes, int) -> int`.

## Usage Examples

**Before (incorrect schema):**
```cpp
class MyCls { void MyFunc(int a); };
refl::GlobalDef().def_method("MyCls_MyFunc", &MyCls::MyFunc);
// Schema produced: {"type":"ffi.Function","args":[{"type":"int"},{"type":"None"}]}
// Missing: no MyCls self argument
```

**After (correct schema):**
```cpp
// Same registration code, now schema is:
// {"type":"ffi.Function","args":[{"type":"None"},{"type":"MyCls"},{"type":"int"}]}
// Python rendering: Callable[[MyCls, int], None]
```

**Python test showing the corrected schema:**
```python
# Instance method schemas now include the class type as first arg
("add_int",      "Callable[[testing.SchemaAllTypes, int], int]"),
("append_int",   "Callable[[testing.SchemaAllTypes, list[int], int], list[int]]"),
# Static methods remain unchanged (no self):
("make_with",    "Callable[[int, float, str], testing.SchemaAllTypes]"),
```

## Reflection

### Design docs / ADRs to write or update

Consider adding a note under `Function.FromTyped` that pointer-to-member function types include `Class*` as the first parameter in the inferred signature.
