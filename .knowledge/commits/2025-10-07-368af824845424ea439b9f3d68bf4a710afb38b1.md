# Fix FunctionInfo member-pointer specializations to include implicit self in schema
## TL;DR
- `FunctionInfo<R (Class::*)(Args...)>` and its `const` variant were deriving from `FuncFunctorImpl<R, Args...>`, omitting the implicit `this` pointer, causing member-function schemas to report `n` arguments instead of `n+1`.
- Fix inserts `Class*` / `const Class*` as the first type parameter of `FuncFunctorImpl`, so the schema correctly includes the receiver object type.
- Secondary fix in `type_info.pxi`: relax `list` and `dict` TypeSchema validation to accept 0 type arguments (in addition to the existing 1 and 2), enabling unparameterized container origins in schema JSON.

## Key Exports

```python
# include/tvm/ffi/function_details.h

# FunctionInfo specializations for pointer-to-member functions.
# Used by the schema/metadata system to derive the argument type list of a registered method.
#
# BEFORE (incorrect):
# struct FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Args...> {};
# struct FunctionInfo<R (Class::*)(Args...) const> : FuncFunctorImpl<R, Args...> {};
#
# AFTER (correct):
# struct FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Class*, Args...> {};
# struct FunctionInfo<R (Class::*)(Args...) const> : FuncFunctorImpl<R, const Class*, Args...> {};
#
# Invariant: first type arg of FuncFunctorImpl is the return type;
#            remaining type args are argument types (including self for member pointers).
# Interacts with: FuncFunctorImpl<R, Args...> (generates arg-type schema list),
#                 GlobalDef::def_method (registers methods with this schema)

# python/tvm_ffi/cython/type_info.pxi

class TypeSchema:
    """Parses and validates the structured metadata JSON for registered functions.
    CHANGED: list and dict origins now accept 0 type arguments (unparameterized containers).
    """
    # origin == "list":  assert len(args) in (0, 1)   # was: assert len(args) == 1
    # origin == "dict":  assert len(args) in (0, 2)   # was: assert len(args) == 2
    # Interacts with: type_info schema JSON produced by FunctionInfo (C++ side)
```

## Impact
- API: None — no public API surface changed.
- Behavioral: Member-function schemas now report the correct arity (n+1 args, with self as arg[0]). Any code that previously relied on the wrong schema count (n args) will see the schema grow by 1 argument. The global `"testing.schema_id_func_typed"` test fixture is also added.
- Flags/config: None.
- Data formats/schemas: Structured schema JSON for methods registered via `GlobalDef::def_method` now includes the class type as the first argument. Example: `add_int` schema changes from `(int) -> int` to `(testing.SchemaAllTypes, int) -> int`.

- None — this is a correctness fix restoring the intended contract of `FunctionInfo` member-pointer specializations.

## Usage Examples

Before/after — incorrect vs. corrected schema for a member function:

```cpp
// C++ registration (unchanged):
class SchemaAllTypes {
  int add_int(int x);
};
refl::ObjectDef<SchemaAllTypes>()
    .def("add_int", &SchemaAllTypes::add_int);

// BEFORE: schema emitted was:
// {"type":"ffi.Function","args":[{"type":"int"},{"type":"int"}]}
// Python: "Callable[[int], int]"   (self omitted — WRONG)

// AFTER: schema emitted is:
// {"type":"ffi.Function","args":[{"type":"int"},{"type":"testing.SchemaAllTypes"},{"type":"int"}]}
// Python: "Callable[[testing.SchemaAllTypes, int], int]"   (self included — CORRECT)
```

Cross-layer: C++ fix drives Python schema parsing fix.

```python
# Python TypeSchema now accepts unparameterized list/dict:
# TypeSchema("list")             → origin="list", args=[]   (previously assertion error)
# TypeSchema("dict")             → origin="dict", args=[]   (previously assertion error)
# TypeSchema("list[int]")        → origin="list", args=["int"]  (unchanged)
# TypeSchema("dict[str,list]")   → origin="dict", args=["str","list"]  (unchanged)
```

## Reflection

### Design docs / ADRs to write or update
- `.knowledge/design-records/0006-reflection.md` — Update the `ReflectionDefBase::GetMethod_` pseudocode and the `def_method` note to document that the schema includes `self` as the first argument type. Also note that `FunctionInfo<R (Class::*)(...) const>` passes `const Class*` (not `Class*`) as first arg. The existing pseudocode in `GetMethod_` says "inserts self as first arg" for execution but does not mention the schema implication — this should be made explicit.
- `.knowledge/design-records/0004-function-system.md` — Add a note under `GlobalDef::def_method` that the generated schema includes `Class*` / `const Class*` as argument[0], consistent with the runtime receiver insertion.
