# Fix missing `self`/`Class*` in FunctionInfo schema for pointer-to-member functions
## TL;DR
- `FunctionInfo` specializations for pointer-to-member functions (`R (Class::*)(Args...)`) were missing the implicit `Class*` first parameter, causing generated type schemas to report one fewer argument than the actual calling convention.
- The fix adds `Class*` (non-const) or `const Class*` (const methods) to the `FuncFunctorImpl` template parameter pack, so schemas for member functions exposed via `GlobalDef().def_method()` now correctly include the receiver as the first argument.
- Python-side `TypeSchema` validation relaxed to accept 0-arg `list` and `dict` origins (previously required exactly 1 or 2 args), fixing a secondary crash when parsing richer schemas containing unparameterized generic containers.

## Key Exports

```python
# BEFORE (buggy): FunctionInfo for pointer-to-member omitted Class*
# template <typename Class, typename R, typename... Args>
# struct FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Args...> {};
#   -> Schema for MyCls::MyFunc(int a) would be (int) -> None  [WRONG: missing self]

# AFTER (fixed): Class* prepended to Args
# template <typename Class, typename R, typename... Args>
# struct FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Class*, Args...> {};
# struct FunctionInfo<R (Class::*)(Args...) const> : FuncFunctorImpl<R, const Class*, Args...> {};
#   -> Schema for MyCls::MyFunc(int a) is now (MyCls, int) -> None  [CORRECT]
# Interacts with: Function.FromTyped (uses FunctionInfo to derive arg count/types for schema)
# Interacts with: GlobalDef.def_method (wraps member funcs, schema reflects self param)
# Interacts with: FuncFunctorImpl::Sig() (generates human-readable signature strings)
# Invariant: FunctionInfo<PMF> arg list MUST match the actual packed calling convention
#            where self/this is always the first packed argument

class TypeSchema:
    """Python-side type schema validation (Cython)."""
    origin: str
    args: tuple[TypeSchema, ...]
    # Relaxed validation:
    #   list: len(args) in (0, 1)   # was: == 1
    #   dict: len(args) in (0, 2)   # was: == 2
    # Invariant: 0-arg form represents an unparameterized generic (e.g. bare `list`, `dict`)
```

## Impact
- API: None -- no public API signatures changed. `FunctionInfo` is an internal template; the fix corrects its behavior for all existing users.
- Behavioral: Type schemas for all member functions registered via `def_method` or `def_`(instance method on `ObjectDef`) now include the receiver type as the first argument. Any downstream code consuming these schemas (e.g., stub generation, IDE tooling) will see the corrected argument lists.
- Flags/config: None
- Data formats/schemas: JSON type schemas for member functions gain an additional first-argument entry for the receiver type. E.g., `add_int` on `SchemaAllTypes` changes from `{"type":"ffi.Function","args":[{"type":"int"},{"type":"int"}]}` to `{"type":"ffi.Function","args":[{"type":"int"},{"type":"testing.SchemaAllTypes"},{"type":"int"}]}`.

## Design Elements
Design elements this commit consumes:
- **`FunctionInfo` / `FuncFunctorImpl`** -- compile-time trait that extracts return type and argument types from a callable, used by `Function::FromTyped` to generate packed call wrappers and type schemas. See [0004-function-system.md](../designs/0004-function-system.md).
- **`GlobalDef.def_method`** -- registers a member function as a global function with self as first arg. See [0008-reflection.md](../designs/0008-reflection.md).
- **`TypeSchema` (Python/Cython)** -- runtime validation and pretty-printing of JSON type schemas on the Python side. See `python/tvm_ffi/cython/type_info.pxi`.

Design elements this commit produces:
- None (bugfix only -- corrects existing behavior, no new design elements).

## Usage Examples
**Before** (incorrect schema):
```cpp
// C++ registration
refl::GlobalDef().def_method("MyCls_MyFunc", &MyCls::MyFunc);
// Generated schema: (int) -> None   <-- WRONG: missing MyCls self parameter
```

**After** (correct schema):
```cpp
// Same C++ registration
refl::GlobalDef().def_method("MyCls_MyFunc", &MyCls::MyFunc);
// Generated schema: (MyCls, int) -> None   <-- CORRECT: self is first arg
```

**Python-side observable change** (from test):
```python
# Method schema for "add_int" on SchemaAllTypes:
# Before: "Callable[[int], int]"
# After:  "Callable[[testing.SchemaAllTypes, int], int]"
```
