# Fix member function schema to include `self` (Class*) as first argument

## TL;DR
- `FunctionInfo<R (Class::*)(Args...)>` specializations in `function_details.h` were missing `Class*` from the parameter pack, causing type schemas for member functions registered via `GlobalDef::def_method` to omit the `self` parameter (wrong arity).
- Fixed by adding `Class*` (non-const) and `const Class*` (const member) to the `FuncFunctorImpl` base, so `TypeSchema()` now correctly includes the object type as the first argument.
- Python-side `TypeSchema.__post_init__` relaxed validation to allow `list` with 0 or 1 args, and `dict` with 0 or 2 args (supporting bare container types in nested schemas like `TypedFunction`).

## Key Exports

**`FunctionInfo` specializations for pointer-to-member** (`include/tvm/ffi/function_details.h`):
```cpp
// Before (bug): Class* omitted from schema
template <typename Class, typename R, typename... Args>
struct FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Args...> {};
template <typename Class, typename R, typename... Args>
struct FunctionInfo<R (Class::*)(Args...) const> : FuncFunctorImpl<R, Args...> {};

// After (fix): Class* included in schema
template <typename Class, typename R, typename... Args>
struct FunctionInfo<R (Class::*)(Args...)> : FuncFunctorImpl<R, Class*, Args...> {};
template <typename Class, typename R, typename... Args>
struct FunctionInfo<R (Class::*)(Args...) const> : FuncFunctorImpl<R, const Class*, Args...> {};
```

**`TypeSchema.__post_init__` validation** (`python/tvm_ffi/cython/type_info.pxi`):
```python
# Before: strict
assert len(args) == 1, "list must have exactly one argument"
assert len(args) == 2, "dict must have exactly two arguments"

# After: relaxed to allow bare container types
assert len(args) in (0, 1), "list must have 0 or 1 argument"
assert len(args) in (0, 2), "dict must have 0 or 2 arguments"
```

## Impact
- API: Schema JSON for member functions now includes the object type as the first argument. Any downstream consumer of `TVMFFIMethodInfo.metadata` (e.g., Python stubgen, IDE tooling) will see the corrected arity.
- Behavioral: `FuncFunctorImpl::TypeSchema()` for member function pointers now produces `{"type":"ffi.Function","args":[return_type, class_type, arg1, ...]}` instead of `{"type":"ffi.Function","args":[return_type, arg1, ...]}`.
- Flags/config: None.
- Data formats/schemas: Method schema JSON gains one additional argument entry (the self/class type) at the front of the args list.

## Usage Examples

**Before (incorrect schema):**
```cpp
class MyCls {
  void MyFunc(int a);
};
refl::GlobalDef().def_method("MyCls_MyFunc", &MyCls::MyFunc);
// Schema: {"type":"ffi.Function","args":[{"type":"None"},{"type":"int"}]}
// Python: Callable[[int], None]  -- WRONG: missing self
```

**After (correct schema):**
```cpp
// Same registration code produces:
// Schema: {"type":"ffi.Function","args":[{"type":"None"},{"type":"MyCls"},{"type":"int"}]}
// Python: Callable[[MyCls, int], None]  -- correct
```
