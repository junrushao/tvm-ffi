# fix: `self` overlooked in schema of member functions (#91)
## TL;DR
- `FunctionInfo` template specializations for pointer-to-member functions (`R (Class::*)(Args...)`) now correctly include `Class*` (or `const Class*`) as the first argument in `FuncFunctorImpl`, so method type schemas include the `self` parameter.
- Python `TypeSchema` validation relaxed: `list` accepts 0 or 1 type args, `dict` accepts 0 or 2 (handles unparameterized generic types).
- New test function `testing.schema_id_func_typed` exercises `TypedFunction` schema generation; existing method schema tests updated to expect `self`.

## Key Exports
```python
# C++ template specializations (include/tvm/ffi/function_details.h)
# These are compile-time constructs, not runtime APIs.

# BEFORE (bug):
# FunctionInfo<R (Class::*)(Args...)>     -> FuncFunctorImpl<R, Args...>         # missing Class*
# FunctionInfo<R (Class::*)(Args...) const> -> FuncFunctorImpl<R, Args...>       # missing const Class*

# AFTER (fix):
# FunctionInfo<R (Class::*)(Args...)>     -> FuncFunctorImpl<R, Class*, Args...>
# FunctionInfo<R (Class::*)(Args...) const> -> FuncFunctorImpl<R, const Class*, Args...>
# Interacts with: FuncFunctorImpl::TypeSchema() for JSON schema generation
# Interacts with: reflection::GlobalDef.def_method() which passes &Class::method
# Invariant: FunctionInfoHelper (for lambdas) still strips this -- only FunctionInfo
#            (for raw member pointers) includes Class*.

# Python TypeSchema validation (python/tvm_ffi/cython/type_info.pxi)
class TypeSchema:
    # Relaxed validation:
    #   list: 0 or 1 args (was: exactly 1)
    #   dict: 0 or 2 args (was: exactly 2)

# New test function (src/ffi/extra/testing.cc)
# "testing.schema_id_func_typed": TypedFunction<void(int64_t, float, Function)> -> same
# Interacts with: FuncFunctorImpl::TypeSchema() for nested function type schema
```

## Impact
- API: Method type schemas now include `self` as the first parameter. Any code parsing method schemas (e.g., stub generators, IDE tooling) will see an additional first argument of the declaring class type. Static methods are unaffected.
- Behavioral: `FuncFunctorImpl::TypeSchema()` and `FuncFunctorImpl::Sig()` for member function pointers now produce a schema/signature with one more argument (the class pointer).
- Flags/config: none
- Data formats/schemas: Method schema JSON changes from `{"type":"ffi.Function","args":[<ret>,<args...>]}` to `{"type":"ffi.Function","args":[<ret>,<class_type>,<args...>]}` for instance methods registered via `def_method`.

## Usage Examples
Before/after showing the corrected behavior:

```cpp
// C++ class with a member function
class MyCls {
  void MyFunc(int a);
};

// Register as global method via reflection
TVM_FFI_STATIC_INIT_BLOCK() {
  reflection::GlobalDef()
      .def_method("MyCls_MyFunc", &MyCls::MyFunc);
}

// BEFORE (bug): schema was (int) -> None -- missing self
// AFTER  (fix): schema is  (MyCls, int) -> None -- correct

// In Python, the method schema now correctly shows:
// "Callable[[MyCls, int], None]"
// instead of the incorrect:
// "Callable[[int], None]"
```
