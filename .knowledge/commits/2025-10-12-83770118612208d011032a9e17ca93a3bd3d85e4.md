# Expose Tensor.strides property in Python Cython binding and bump DLPack to v1.2
## TL;DR
- Adds a `strides` property to the Cython `Tensor` class that reads `DLTensor::strides` directly, with a fallback that computes row-major strides from the shape when the underlying `strides` pointer is NULL.
- Bumps the vendored DLPack submodule from v1.1 to v1.2 (commit `111736618e8d` -> `93c8f2a3c774`).
- Version bump: `0.1.0b15` -> `0.1.0b16` in both `pyproject.toml` and `python/tvm_ffi/__init__.py`.

## Key Exports

**Properties**:
- `Tensor.strides -> tuple[int, ...]` (Python property, in `tensor.pxi`): Returns the strides of the tensor as a tuple of integers. If `DLTensor::strides` is NULL (e.g., compact contiguous tensors from some DLPack producers), computes row-major (C-contiguous) strides from the shape.

**Functions** (module-level helper):
- `_make_strides_from_shape(shape: tuple) -> tuple[int, ...]` (Cython function in `tensor.pxi`): Computes row-major strides from a shape tuple. Iterates dimensions in reverse order, accumulating the product. Used as the NULL-strides fallback path.

## Impact
- API: New `Tensor.strides` property. No existing APIs changed or removed.
- ABI: None. The `DLTensor` struct layout is unchanged; the property reads existing fields.
- Behavioral: Python `Tensor` objects now expose strides. Previously only `shape`, `dtype`, and `device` were accessible from Python.
- Flags/config: None.
- Data formats/schemas: DLPack submodule updated to v1.2. This may introduce new DLPack API symbols but does not change the `DLTensor` struct layout.

## Design Elements
Design elements this commit consumes:
- `DLTensor::strides` field (C-level): the Cython property reads `self.cdltensor.strides` directly, checking for NULL before indexing (`.knowledge/designs/containers.md`, Tensor section)
- C++ `Tensor::strides()` accessor pattern (commit 6fa40b5): the Python property mirrors the C++ accessor added earlier, completing the cross-language surface (`.knowledge/designs/containers.md`, evolution table v14)
- Always-populated strides invariant with zero-dim exception (commits ca95b41, 4fefeb0): for TVM-constructed tensors, strides are always populated; external DLPack tensors may have NULL strides for contiguous layouts
- Python Tensor Cython class (`tensor.pxi`): `cdef class Tensor(Object)` with `cdef DLTensor* cdltensor` (`.knowledge/designs/0014-python-bindings.md`)

Design elements this commit produces:
- NULL-strides fallback pattern in Python: when `DLTensor::strides` is NULL (external compact contiguous tensors), `_make_strides_from_shape` synthesizes row-major strides from the shape. This is a Python-only concern since the C++ side always populates strides for internally-constructed tensors.

## Usage Examples

Accessing tensor strides from Python:
```python
import numpy as np
import tvm_ffi

data = np.zeros((10, 8, 4, 2), dtype="int16")
x = tvm_ffi.from_dlpack(data)

# Row-major (C-contiguous) strides in element counts
assert x.strides == (64, 8, 2, 1)  # 8*4*2, 4*2, 2, 1
assert x.shape == (10, 8, 4, 2)
```

The NULL-strides fallback ensures correctness for DLPack producers that omit strides for contiguous tensors:
```python
# If an external producer sets DLTensor.strides = NULL for a (3, 4) tensor,
# Tensor.strides returns (4, 1) -- computed row-major strides.
```
