# Expose Tensor.strides property in Cython bindings and bump DLPack to v1.2
## TL;DR
- Adds `Tensor.strides` property to the Cython `Tensor` class, returning a tuple of int64 strides. When the underlying `DLTensor.strides` pointer is NULL (compact/contiguous tensor), strides are computed from shape in row-major order.
- Bumps the vendored DLPack submodule from v1.0 (1117366) to v1.2 (93c8f2a).
- Version bump 0.1.0b15 to 0.1.0b16.

## Impact
- API: Additive — new `Tensor.strides` property. No existing API changed.
- Behavioral: None — existing `Tensor.shape`, `Tensor.dtype`, etc. unchanged.
- Flags/config: None.
- Data formats/schemas: DLPack submodule bumped to v1.2. The DLPack v1.2 spec is backward-compatible with v1.0; no ABI break.

## Design Elements
Design elements this commit consumes:
- **DLTensor C struct** (`cdltensor.strides`, `cdltensor.ndim`) — the raw C-level strides pointer from DLPack. See `.knowledge/designs/0007-containers.md` (TensorObj section).
- **Tensor Cython binding pattern** — extends the existing `cdef class Tensor(Object)` in `tensor.pxi` with a new `@property`. See `.knowledge/designs/0012-python-bindings.md`.

Design elements this commit produces:
- **`Tensor.strides` Python property** — exposes the C++ `Tensor::strides()` concept at the Python layer. The C++ side already had `Tensor::strides() -> ShapeView` (documented in `.knowledge/designs/0007-containers.md`); this commit bridges it to Python via Cython.
- **`_make_strides_from_shape` helper** — Cython-level helper computing contiguous strides when DLTensor.strides is NULL. Mirrors the C++ `FillStridesFromShape` logic.

## Usage Examples

**Context**: Accessing strides on a tensor created via DLPack import (from the test in this commit).

```python
import numpy as np
import tvm_ffi

data = np.random.randint(0, 10, size=(10, 8, 4, 2)).astype("int16")
x = tvm_ffi.from_dlpack(data)
assert x.shape == (10, 8, 4, 2)
assert x.strides == (64, 8, 2, 1)  # row-major contiguous strides
```
