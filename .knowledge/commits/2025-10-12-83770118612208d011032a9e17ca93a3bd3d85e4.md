# Expose Tensor.strides in Python Cython bindings and bump DLPack to v1.2

## TL;DR
- Adds `Tensor.strides` property to the Python Cython `Tensor` class, mirroring the existing C++ `Tensor::strides()`. When `DLTensor::strides == NULL` (contiguous tensors), the Python layer computes C-order strides from shape rather than returning null/empty.
- Adds `_make_strides_from_shape()` Cython helper to compute C-order strides (last dim = 1, each earlier dim multiplied by the next dimension size).
- Bumps DLPack submodule from v1.1 to v1.2 and version from `0.1.0b15` to `0.1.0b16`.

## Key Exports

```python
# python/tvm_ffi/cython/tensor.pxi

def _make_strides_from_shape(shape: tuple) -> tuple[int, ...]:
    """Compute C-order (row-major) strides from a shape tuple.
    last dimension stride = 1; strides[i] = strides[i+1] * shape[i+1]
    # Invariant: shape must be a non-empty tuple of ints; for ndim=0, returns ()
    # Interacts with: Tensor.strides (calls this when DLTensor.strides == NULL)
    """
    ...

class Tensor(Object):  # Cython cdef class
    @property
    def strides(self) -> tuple[int, ...]:
        """Strides of this array as a Python tuple of integers.
        # Semantics: if DLTensor.strides == NULL (C-contiguous layout), strides are
        #            computed from shape (C-order). Non-null strides are read directly.
        # Invariant: always returns a usable tuple; never returns None or empty for ndim>0
        # Interacts with: _make_strides_from_shape (null-strides fallback),
        #                 Tensor.shape (used as input to fallback),
        #                 C++ Tensor::strides() which returns ShapeView (may be nullptr for ndim=0)
        # Note: Python semantic diverges from C++: C++ strides() can return ShapeView(nullptr,0)
        #       for ndim==0; Python strides property always returns () for ndim==0 via fallback
        """
        ...
```

The corresponding stub update in `python/tvm_ffi/core.pyi`:
```python
class Tensor(Object):
    @property
    def strides(self) -> tuple[int, ...]:
        """Tensor strides as a tuple of integers."""
```

## Impact
- API: New `Tensor.strides` property added to Python `Tensor`. No existing API changed. Callers using `tvm_ffi.Tensor` can now read strides.
- Behavioral: When a `Tensor` was created from a contiguous allocation (DLPack `strides == NULL`), `Tensor.strides` returns computed C-order strides rather than raising `AttributeError`.
- Flags/config: none
- Data formats/schemas: DLPack submodule updated from v1.1 (commit `111736618`) to v1.2 (commit `93c8f2a3`).

## Usage Examples

From `tests/python/test_tensor.py` (added assertion):
```python
import numpy as np
import tvm_ffi

data = np.zeros((10, 8, 4, 2), dtype="int16")
x = tvm_ffi.from_dlpack(data)
assert x.shape == (10, 8, 4, 2)
assert x.strides == (64, 8, 2, 1)  # C-order: last dim=1, each earlier=product of later dims
```

Cross-layer note: `from_dlpack` calls `Tensor.FromDLPack` at C++ level; the resulting `TensorObj` has `DLTensor.strides == NULL` for contiguous numpy arrays. The Python `Tensor.strides` property detects this and computes via `_make_strides_from_shape`.
