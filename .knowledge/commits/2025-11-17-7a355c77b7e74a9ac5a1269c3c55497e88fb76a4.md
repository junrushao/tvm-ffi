# Replace Ninja with direct compiler invocation for non-Windows torch C DLPack addon JIT builds

## TL;DR

- Splits the unified `_generate_ninja_build()` into two platform-specific functions: `_run_build_on_linux_like()` (Linux/macOS, direct `c++` invocation) and `_generate_ninja_build_windows()` (Windows-only, Ninja retained).
- Removes the `ninja` dependency for non-Windows JIT builds of the torch C DLPack addon; `build_ninja()` is now only imported on Windows.
- Adds `logging.info` for JIT compile start, replaces `subprocess.run(check=True)` with explicit `check=False` + error message capture in both the caller (`_optional_torch_c_dlpack.py`) and the build script.
- Fixes macOS linker flags: uses `-Wl,-rpath,@loader_path` instead of the Linux `-Wl,-rpath,$ORIGIN -Wl,--no-as-needed`.

## Impact

- API: none -- internal build functions renamed but not part of public API.
- Behavioral: Non-Windows JIT builds of the torch C DLPack addon no longer require `ninja` to be installed. macOS builds now use correct platform-specific RPATH (`@loader_path` instead of `$ORIGIN`). Build output is now captured (less noisy).
- Flags/config: `CXX` env var controls compiler for non-Windows direct builds (default `c++`). `-L` flag now passed as separate args (`-L`, `str(lib_dir)`) instead of concatenated (`-L{lib_dir}`).
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- `0012-ffi-python-package` -- the torch DLPack addon JIT build pipeline (`load_torch_c_dlpack_extension`, `_build_optional_torch_c_dlpack.py`).
- `0014-ffi-load-inline` -- `build_ninja()` from `tvm_ffi.cpp.extension`, now only imported on Windows path.
- `0013-ffi-packaging-and-distribution` -- Ninja as build generator; this commit relaxes that requirement for non-Windows torch addon builds.

Design elements this commit produces:
- Platform-split build strategy for torch C DLPack addon: `_run_build_on_linux_like()` (direct compiler) vs `_generate_ninja_build_windows()` (Ninja). This is a new structural convention where non-Windows platforms bypass Ninja entirely for this addon.

## Usage Examples

Before (required ninja on all platforms):
```python
# _build_optional_torch_c_dlpack.py main() always did:
_generate_ninja_build(build_dir=..., libname=..., ...)
build_ninja(build_dir=str(build_dir))  # required ninja binary
```

After (non-Windows uses direct compiler invocation):
```python
# _build_optional_torch_c_dlpack.py main() now branches:
if IS_WINDOWS:
    _generate_ninja_build_windows(build_dir=..., libname=..., ...)
    from tvm_ffi.cpp.extension import build_ninja
    build_ninja(build_dir=str(build_dir))
else:
    _run_build_on_linux_like(build_dir=..., libname=..., ...)
    # No ninja needed -- direct c++ invocation
```
