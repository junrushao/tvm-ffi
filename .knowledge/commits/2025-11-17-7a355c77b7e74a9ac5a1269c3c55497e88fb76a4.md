# Remove ninja dependency on non-Windows when JIT-building optional torch-c-dlpack extension

## TL;DR
- Replaces the ninja-based build path on Linux/macOS with a direct compiler invocation (`_run_build_on_linux_like`), making Ninja a Windows-only dependency for torch-c-dlpack JIT builds.
- Splits the old `_generate_ninja_build` function into `_run_build_on_linux_like` (Linux/macOS) and `_generate_ninja_build_windows` (Windows-only).
- Improves error reporting: subprocess failures now capture and log stdout/stderr instead of propagating raw exit codes; adds `logging` instrumentation.

## Impact
- API: internal build script only; no public API change.
- Behavioral: On Linux/macOS, `ninja` is no longer required for torch-c-dlpack JIT compilation. macOS rpath changed from `@loader_path` (unchanged) but Linux no longer passes `--no-as-needed` linker flag (removed in same refactor).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0022-torch-dlpack-addon`: subprocess-based JIT compilation flow with `FileLock` serialization.
- `0015-load-inline`: `build_ninja()` from `tvm_ffi.cpp.extension` — now only used on Windows path.

Design elements this commit produces:
- **Direct-compiler build path** for Linux/macOS: establishes convention that torch-c-dlpack JIT on non-Windows uses `$CXX` directly, not Ninja. This is now the primary non-Windows build path.

## Usage Examples

```python
# Before: always used Ninja
_generate_ninja_build(build_dir, ...)
build_ninja(build_dir=str(build_dir))

# After: platform-split
if IS_WINDOWS:
    _generate_ninja_build_windows(build_dir, ...)
    build_ninja(build_dir=str(build_dir))
else:
    _run_build_on_linux_like(build_dir, ...)  # compiles in one subprocess call
```
