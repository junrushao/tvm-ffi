# Replace ninja-based JIT build with direct compiler invocation on non-Windows platforms for torch-c-dlpack
## TL;DR
- Splits the single `_generate_ninja_build()` function into two platform-specific paths: `_run_build_on_linux_like()` (Linux/macOS, direct `c++` invocation) and `_generate_ninja_build_windows()` (Windows-only, ninja retained).
- Removes the `ninja` dependency for non-Windows JIT builds of the torch-c-dlpack addon. The `build_ninja` import from `tvm_ffi.cpp.extension` is now deferred and Windows-only.
- Adds `logging` to the loader (`_optional_torch_c_dlpack.py`) and switches the subprocess build call from `check=True` to `check=False` with captured output and explicit error reporting.

## Impact
- API: none -- no public API changes. Internal build function renamed and split.
- Behavioral: (1) Non-Windows JIT builds no longer require `ninja` to be installed. (2) Build subprocess output is captured instead of printed to stdout/stderr, reducing noise. (3) Build failures now produce structured error messages with captured stdout/stderr.
- Flags/config: none -- same env vars (`CXX`, `TVM_FFI_JIT_EXTRA_CFLAGS`, `TVM_FFI_JIT_EXTRA_LDFLAGS`) still work. Linux default ldflags no longer include `--no-as-needed`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Torch DLPack addon JIT build pipeline** (`.knowledge/designs/0017-torch-dlpack-addon.md`): The `_generate_ninja_build()` -> `build_ninja()` flow documented there is refactored by this commit.
- **Module system / `build_ninja` utility** (`.knowledge/designs/0011-module-system.md`): The `build_ninja` function from `tvm_ffi.cpp.extension` is still used but now only on Windows.
- **DLPackExchangeAPI struct** (`.knowledge/ADRs/0015-dlpack-exchange-api-struct.md`): The built shared library implements `TorchDLPackExchangeAPI`, unchanged by this commit.
- **Platform-specific linking conventions** (`.knowledge/designs/0017-torch-dlpack-addon.md`): macOS `-lpython{version}` linking, Linux `-L` flag passing (changed from single arg `-L{dir}` to two-arg `-L {dir}`).

Design elements this commit produces:
- **Two-path build strategy**: Non-Windows uses direct compiler invocation (`_run_build_on_linux_like`); Windows retains ninja (`_generate_ninja_build_windows`). This eliminates the ninja dependency on Linux/macOS for JIT builds.
- **macOS-specific linker flags**: Explicit `IS_DARWIN` branch producing `["-shared", "-Wl,-rpath,@loader_path"]` vs Linux `["-shared", "-Wl,-rpath,$ORIGIN"]`. Previously macOS fell into the else branch which included Linux-only `--no-as-needed`.
- **Captured subprocess error reporting pattern**: `subprocess.run(check=False, capture_output=True)` followed by explicit error assembly from `result.stdout`/`result.stderr`. Used in both `_run_build_on_linux_like` and the loader's subprocess call.

## Usage Examples

### JIT build on Linux/macOS (no ninja needed)
```python
# Before: required ninja installed
# $ pip install ninja  # was implicitly needed

# After: direct compiler invocation, no ninja dependency
import tvm_ffi  # JIT builds torch-c-dlpack using c++ directly
# Build command: c++ -std=c++17 -fPIC -O3 addon.cc -shared -Wl,-rpath,$ORIGIN -o lib.so
```

```python

# After: structured error message with stdout/stderr

# ...
```
