# Remove ninja dependency for non-Windows JIT torch-c-dlpack builds; use direct compiler invocation
## TL;DR
- On Linux/macOS, the JIT build of the torch-c-dlpack addon now invokes the compiler directly (`c++ -std=c++17 ... -shared -o <lib>`) instead of generating a ninja build file and running `build_ninja()`. This eliminates the ninja dependency for the common case.
- On Windows, the existing ninja-based build path is preserved (now in `_generate_ninja_build_windows`).
- The JIT build subprocess output is now captured (not printed to terminal); errors are collected into a structured `RuntimeError` with stdout/stderr. A `logging.getLogger` call is added for `logger.info` on JIT compilation start.
- macOS linker flags fixed: uses `-Wl,-rpath,@loader_path` instead of Linux's `-Wl,-rpath,$ORIGIN` and omits `--no-as-needed` (unsupported on macOS).

## Key Exports
**Function** (internal): `_run_build_on_linux_like(build_dir, libname, source_path, extra_cflags, extra_ldflags, extra_include_paths) -> None` -- replaces `_generate_ninja_build` for non-Windows platforms. Compiles and links in one `subprocess.run` call.

**Function** (internal, renamed): `_generate_ninja_build` -> `_generate_ninja_build_windows` -- Windows-only ninja build file generation.
