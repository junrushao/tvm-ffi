# Prevent integer overflow in GetDataSize on 32-bit platforms (WASM)

## TL;DR
- `GetDataSize(numel, dtype)` intermediate product `numel * dtype.bits * dtype.lanes` now cast to `uint64_t` before multiplication, preventing overflow on 32-bit platforms where `size_t` is 32 bits.
- Fixes zero-byte allocations in WASM/WebLLM with large tensors.

## Key Exports
None

## Impact
- API: none (function signature unchanged)
- Behavioral: `GetDataSize` now returns correct byte count for large tensors on 32-bit platforms.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0006-ffi-containers`: `GetDataSize` helper in `tensor.h`.

Design elements this commit produces: none

## Usage Examples

```cpp
// Before (32-bit, numel=10M, dtype=fp16): numel*16*1 overflows size_t(32-bit)
size_t sz = GetDataSize(10000000, DLDataType{kDLFloat, 16, 1});  // was 0 on WASM

// After: intermediate cast to uint64_t
// (uint64_t(10000000) * 16 * 1 + 7) / 8 = 20000000 bytes — correct
```
