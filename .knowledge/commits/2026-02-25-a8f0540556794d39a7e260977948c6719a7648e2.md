# Fix integer overflow in GetDataSize on 32-bit platforms (WASM)

## TL;DR
- Casts intermediate multiplication in `GetDataSize(size_t numel, DLDataType dtype)` to `uint64_t` to prevent overflow on 32-bit platforms (WASM), where `numel * dtype.bits * dtype.lanes` could overflow `size_t` even when the final byte count fits.

## Key Exports

**Behavioral fix in `GetDataSize`** (`container/tensor.h`):
```cpp
// Before: (numel * dtype.bits * dtype.lanes + 7) / 8
// After:  static_cast<size_t>((static_cast<uint64_t>(numel) * dtype.bits * dtype.lanes + 7) / 8)
```

## Impact
- API: none
- Behavioral: Fixes 0-byte buffer allocations on WASM/32-bit platforms for large tensors.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `GetDataSize` utility function -- [design 0008](../designs/0008-containers.md)

Design elements this commit produces: none

**Invariant violated**: Intermediate product could wrap around `size_t` on 32-bit, producing 0 or incorrect byte count.
**Invariant restored**: Intermediate computation uses `uint64_t`, preventing overflow for tensors up to 2^64 bits.
