# Remove BUILD_WITH_INSTALL_RPATH from Cython target to fix scikit-build-core packaging
## TL;DR
- Removes `BUILD_WITH_INSTALL_RPATH ON` from the `tvm_ffi_cython` CMake target on both macOS and Linux, so that `INSTALL_RPATH` is only applied at install time (not during the build step).
- Fixes a packaging issue encountered during scikit-build-core wheel builds following PR #18239.

## Key Exports
None

## Impact
- API: none
- Behavioral: none -- the installed wheel's RPATH is unchanged (`@loader_path/lib` on macOS, `$ORIGIN/lib` on Linux); only the build-time RPATH behavior changes.
- Flags/config: CMake property `BUILD_WITH_INSTALL_RPATH` is no longer set on `tvm_ffi_cython`. This means the build-tree binary uses CMake's default RPATH (typically the absolute build directory) rather than the install RPATH, which is the standard CMake behavior and avoids conflicts with scikit-build-core's wheel assembly.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python package RPATH layout** ([.knowledge/designs/0014-python-package.md](../designs/0014-python-package.md)): The Cython extension (`core.*.so`) must find `libtvm_ffi.so` via a relative RPATH (`@loader_path/lib` or `$ORIGIN/lib`) in the installed wheel. This commit preserves that install-time RPATH while fixing the build-time behavior.
