# Remove BUILD_WITH_INSTALL_RPATH from tvm_ffi_cython to fix scikit-build-core packaging
## TL;DR
- Removes `BUILD_WITH_INSTALL_RPATH ON` from the `tvm_ffi_cython` CMake target on both macOS (`@loader_path/lib`) and Linux (`$ORIGIN/lib`), fixing RPATH issues encountered during scikit-build-core packaging (follow-up to PR #18239).
- The `INSTALL_RPATH` property is retained; only the premature application of install RPATH during build time is removed, restoring standard CMake RPATH behavior.

## Key Exports
None

## Impact
- API: none
- Behavioral: The `tvm_ffi_cython` shared library no longer bakes the install-time RPATH into the binary during build. Instead, CMake's default behavior applies: build RPATH during build, install RPATH at install time. This is the correct behavior for scikit-build-core which manages the install step.
- Flags/config: `BUILD_WITH_INSTALL_RPATH` property removed from `tvm_ffi_cython` target in `CMakeLists.txt`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Python packaging build system (scikit-build-core, CMake `tvm_ffi_cython` target) -- see `CMakeLists.txt:221`
- RPATH conventions for cross-platform shared library resolution (`@loader_path` on macOS, `$ORIGIN` on Linux)
