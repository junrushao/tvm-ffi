# Remove BUILD_WITH_INSTALL_RPATH from Cython RPATH configuration

## TL;DR
- Removes the `BUILD_WITH_INSTALL_RPATH ON` property from `tvm_ffi_cython` target on both macOS and Linux in `CMakeLists.txt`.
- Keeps `INSTALL_RPATH` settings unchanged (`@loader_path/lib` on macOS, `$ORIGIN/lib` on Linux).
- This is a follow-up fix to the scikit-build-core packaging flow (#18239 / #18251), resolving issues encountered during packaging testing.
- Net effect: -8 lines, +2 lines in `CMakeLists.txt`. Single file changed.

## Key Exports
None. No new symbols, APIs, or configuration options are introduced.

**Changed CMake properties:**

| Target | Property removed | Rationale |
|--------|-----------------|-----------|
| `tvm_ffi_cython` (macOS) | `BUILD_WITH_INSTALL_RPATH ON` | `BUILD_WITH_INSTALL_RPATH` forces the install RPATH to be used during build time, which is incorrect for scikit-build-core packaging where the build layout differs from the install layout. Removing it allows CMake to use its default build RPATH during development builds and only apply `INSTALL_RPATH` at install time. |
| `tvm_ffi_cython` (Linux) | `BUILD_WITH_INSTALL_RPATH ON` | Same reasoning as macOS. |

## Impact
- API: None.
- ABI: None.
- Behavioral: During development builds (non-installed), the Cython extension module `tvm_ffi_cython` will now use CMake's default build RPATH instead of the install RPATH. This means the build-tree binary can find `libtvm_ffi` via CMake's automatic build RPATH rather than the relative `@loader_path/lib` or `$ORIGIN/lib` path (which only exists in the installed/wheel layout). At install time, the `INSTALL_RPATH` is still applied, so wheel packaging behavior is unchanged.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit **consumes**:
- **scikit-build-core wheel packaging** (`.knowledge/commits/2025-08-24-2d41a5115f6a91e2781012a3379f9626bc9e18a1.md`): The `TVM_FFI_BUILD_PYTHON_MODULE` CMake option that gates Cython compilation and the RPATH configuration block. This commit fixes a packaging issue within that block.
- **CMake RPATH model**: CMake distinguishes between build RPATH (automatically set to point at build-tree library locations) and install RPATH (set via `INSTALL_RPATH`). `BUILD_WITH_INSTALL_RPATH ON` overrides the build RPATH with the install RPATH, which breaks the development workflow when the install-time relative path layout does not match the build-tree layout.

Design elements this commit **produces**:
- None. This is a targeted fix removing an incorrect property.
