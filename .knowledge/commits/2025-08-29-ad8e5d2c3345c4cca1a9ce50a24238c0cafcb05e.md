# Remove BUILD_WITH_INSTALL_RPATH from Cython module RPATH setup in CMakeLists.txt
## TL;DR
- Removes `BUILD_WITH_INSTALL_RPATH ON` from `set_target_properties` on the `tvm_ffi_cython` target for both macOS (`@loader_path/lib`) and Linux (`$ORIGIN/lib`) RPATH configurations.
- Changes the platform guard from `elseif(LINUX)` to `elseif(UNIX AND NOT APPLE)` (visible in the current codebase state; the diff shows the intermediate step removing the multi-line formatting and `BUILD_WITH_INSTALL_RPATH`).
- Net effect: RPATH is only set at install time, not at build time. This fixes packaging issues where `BUILD_WITH_INSTALL_RPATH ON` caused the build-tree Cython module to embed the install-time RPATH, breaking the editable-install and in-source-build workflows where the relative path `lib/` does not resolve correctly from the build directory.

## Impact
- API: none
- Flags/config: none
- Data formats/schemas: none
- The change affects only the CMake build configuration for the Cython extension module. The install-time RPATH (`@loader_path/lib` on macOS, `$ORIGIN/lib` on Linux) is preserved, so the packaged wheel continues to work correctly. The build-tree binary no longer has the install RPATH baked in, which means developers running from the build tree use the default CMake RPATH behavior (pointing to the build directory) instead of the install-relative path.
