# Refactor AccessPath from flat Array<AccessStep> to parent-pointing tree for compact multi-path representation

## TL;DR
- Replaces the type alias `using AccessPath = Array<AccessStep>` with a proper `AccessPathObj`/`AccessPath` object pair that uses a parent-pointing tree structure, where each node stores an `Optional<ObjectRef> parent`, an `Optional<AccessStep> step`, and an `int32_t depth`. Multiple paths sharing a common prefix share the same ancestor nodes in memory.
- Renames `AccessKind::kObjectField` to `AccessKind::kAttr` (value 0) and adds `kAttrMissing = 3`, shifting `kArrayItemMissing` to 4 and `kMapItemMissing` to 5. The factory method `AccessStep::ObjectField(...)` is replaced by `AccessStep::Attr(...)` and a new `AccessStep::AttrMissing(...)`.
- Renames `AccessStepObj::_type_key` from `"tvm.ffi.reflection.AccessStep"` to `"ffi.reflection.AccessStep"` and assigns `AccessPathObj` the key `"ffi.reflection.AccessPath"`.
- Moves `AccessStepObj::RegisterReflection()` and `MakeObjectFromPackedArgs` from `src/ffi/object.cc` and `src/ffi/reflection/access_path.cc` into a new `src/ffi/extra/reflection_extra.cc`, consolidating all reflection registrations for `AccessStepObj`, `AccessPathObj`, and `ffi.MakeObjectFromPackedArgs` under the `TVM_FFI_USE_EXTRA_CXX_API` build flag.
- Simplifies `ReflectionDefBase::GetMethod` by removing the unused `Class` template parameter. The overloaded `GlobalDef::GetMethod_` private methods (including member-function-pointer overloads) are replaced by direct calls to the now-simplified `GetMethod`.
- Adds a default constructor `AccessStepObj() = default` to enable auto-serialization.
- Fixes a bug in the Cython method export (mentioned in the commit message but the fix is the simplification of `GetMethod` removing the explicit `Class` template parameter that caused issues).

### New AccessPathObj class (`include/tvm/ffi/reflection/access_path.h`)

```cpp
class AccessPathObj : public Object {
 public:
  Optional<ObjectRef> parent;       // parent node (empty for root)
  Optional<AccessStep> step;        // current step (empty for root)
  int32_t depth;                    // 0 for root

  Optional<AccessPath> GetParent() const;
  AccessPath Extend(AccessStep step) const;
  AccessPath Attr(String field_name) const;
  AccessPath AttrMissing(String field_name) const;
  AccessPath ArrayItem(int64_t index) const;
  AccessPath ArrayItemMissing(int64_t index) const;
  AccessPath MapItem(Any key) const;
  AccessPath MapItemMissing(Any key) const;
  Array<AccessStep> ToSteps() const;
  bool PathEqual(const AccessPath& other) const;
  bool IsPrefixOf(const AccessPath& other) const;

  static constexpr const char* _type_key = "ffi.reflection.AccessPath";
};
```

### Deleted files

- `src/ffi/reflection/access_path.cc` -- its content (reflection registration for `AccessStepObj`) moved to `reflection_extra.cc`.

### Build system change (`CMakeLists.txt`)

- `src/ffi/reflection/access_path.cc` removed from `tvm_ffi_objs_sources` (always-compiled core).

This means `AccessStep`/`AccessPath` type registrations and `MakeObjectFromPackedArgs` are now compiled only when `TVM_FFI_USE_EXTRA_CXX_API` is enabled, moving them from core to extra.

## Impact
- API: `AccessPath` is no longer a type alias for `Array<AccessStep>`. Code constructing `AccessPath` from brace-init lists of steps (e.g., `AccessPath({step1, step2})`) must use `AccessPath::FromSteps({step1, step2})` or the fluent builder pattern `AccessPath::Root()->Attr("x")->ArrayItem(0)`. Code indexing into `AccessPath` with `path[i]` must call `path->ToSteps()` first. `AccessStep::ObjectField(...)` is replaced by `AccessStep::Attr(...)`.
- ABI: Not breaking at the C level. The `AccessKind` enum values changed, but these are C++ enum class values not exposed through the C ABI. The `_type_key` string change from `"tvm.ffi.reflection.AccessStep"` to `"ffi.reflection.AccessStep"` affects type registry lookups.
- Behavioral: `AccessStep`/`AccessPath` reflection registration and `MakeObjectFromPackedArgs` are now compiled only under `TVM_FFI_USE_EXTRA_CXX_API`, not in the core build. This is a regression from the prior state where `access_path.cc` was always compiled. Callers using `MakeObjectFromPackedArgs` or `AccessPath` reflection from Python must have extra APIs enabled.
- Flags/config: `TVM_FFI_USE_EXTRA_CXX_API` now gates additional registrations.

## Design Elements

Design elements this commit consumes:
- **Object/ObjectRef dual-class pattern** (`.knowledge/designs/object-system.md`) -- `AccessPathObj`/`AccessPath` follow the standard `FooObj` + `Foo` pattern with `TVM_FFI_DECLARE_FINAL_OBJECT_INFO` and `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS`.
- **AccessStep** (commit 9445fe7, refined in 3fc0391) -- The existing `AccessStepObj`/`AccessStep` pair is preserved but renamed (`kObjectField` -> `kAttr`).
- **StructuralEqual mismatch diagnostics** (commit 9445fe7) -- `GetFirstMismatch` returns `AccessPathPair` with reverse-path construction, now updated to use `AccessPath::FromSteps` with reverse iterators.
- **Reflection ObjectDef/TypeAttrDef** -- Used in `reflection_extra.cc` to register fields and methods.
- **`Function::FromTyped`** -- The `GetMethod` simplification relies on `FromTyped` handling both free functions and member-function pointers uniformly without needing the `Class` template parameter.

Design elements this commit produces:
- **Parent-pointing AccessPath tree** -- `AccessPathObj` stores `Optional<ObjectRef> parent` and `Optional<AccessStep> step`, forming a singly-linked list from leaf to root. Multiple paths sharing a common prefix (e.g., `root.body[0]` and `root.body[1]`) share the same ancestor nodes. `depth` enables O(1) length queries and efficient `IsPrefixOf` checks by walking the longer path down to the shorter path's depth before comparing.
- **Fluent AccessPath builder** -- `AccessPath::Root()->Attr("body")->ArrayItem(1)` creates paths incrementally. Each call to `Extend`/`Attr`/`ArrayItem`/`MapItem` allocates a new `AccessPathObj` that points back to the current path as parent, returning the extended path.
- **AccessPath equality and prefix checking** -- `PathEqual` walks both paths from leaf to root, comparing steps via `StepEqual` (which uses `AnyEqual` on keys). `IsPrefixOf` first walks the longer path down to the shorter path's depth, then calls `PathEqual` on the aligned suffixes. Both include fast-path pointer equality checks.
- **`kAttrMissing` access kind** -- New enum value for reporting that an attribute field exists on one side but is missing on the other during structural comparison. Complements the existing `kArrayItemMissing` and `kMapItemMissing`.
- **Consolidated reflection_extra.cc** -- All reflection-only registrations (AccessStep, AccessPath, MakeObjectFromPackedArgs) are gathered into a single file under the extra API flag, clarifying the core vs. extra boundary.

## Usage Examples

### Constructing AccessPaths (new fluent API)

```cpp
// Old: AccessPath was Array<AccessStep>
// AccessPath path({AccessStep::ObjectField("body"), AccessStep::ArrayItem(1)});

// New: use Root() + fluent builder or FromSteps
AccessPath path = AccessPath::Root()->Attr("body")->ArrayItem(1);
// or
AccessPath path = AccessPath::FromSteps({AccessStep::Attr("body"), AccessStep::ArrayItem(1)});
```

### Querying path properties

```cpp
AccessPath path = AccessPath::Root()->Attr("x")->ArrayItem(0)->MapItem("key");

// Depth
EXPECT_EQ(path->depth, 3);

// Convert to flat array of steps
Array<AccessStep> steps = path->ToSteps();
EXPECT_EQ(steps.size(), 3);
EXPECT_EQ(steps[0]->kind, AccessKind::kAttr);
EXPECT_EQ(steps[1]->kind, AccessKind::kArrayItem);
EXPECT_EQ(steps[2]->kind, AccessKind::kMapItem);

// Navigate to parent
Optional<AccessPath> parent = path->GetParent();  // root.x[0]
```

### Prefix checking and equality

```cpp
AccessPath short_path = AccessPath::Root()->Attr("x");
AccessPath long_path  = AccessPath::Root()->Attr("x")->ArrayItem(0);

EXPECT_TRUE(short_path->IsPrefixOf(long_path));
EXPECT_FALSE(long_path->IsPrefixOf(short_path));

AccessPath same = AccessPath::Root()->Attr("x");
EXPECT_TRUE(short_path->PathEqual(same));
```

### Shared prefix memory optimization

```cpp
// Both paths share the same root->Attr("body") node in memory
AccessPath base = AccessPath::Root()->Attr("body");
AccessPath child1 = base->ArrayItem(0);
AccessPath child2 = base->ArrayItem(1);
// child1->parent and child2->parent point to the same AccessPathObj
```
