# Refactor AccessPath from flat Array<AccessStep> to parent-pointing tree for compact shared-prefix representation

## TL;DR

- **AccessPath data structure change**: `AccessPath` is transformed from a flat type alias `Array<AccessStep>` into a first-class object (`AccessPathObj`) with a parent-pointing tree structure. Each node stores `parent`, `step`, and `depth`, enabling compact memory sharing when multiple paths share a common prefix.
- **AccessPath and MakeObjectFromPackedArgs relocated**: `AccessPath`/`AccessStep` reflection registration and `MakeObjectFromPackedArgs` are moved from core compilation units (`src/ffi/reflection/access_path.cc`, `src/ffi/object.cc`) to a new extra-tier source file `src/ffi/extra/reflection_extra.cc`, gated behind `TVM_FFI_USE_EXTRA_CXX_API`.
- **Naming rename**: `AccessKind::kObjectField` becomes `kAttr`, `AccessStep::ObjectField` becomes `AccessStep::Attr`, and a new `kAttrMissing` variant is added. The `AccessStepObj` type key changes from `"tvm.ffi.reflection.AccessStep"` to `"ffi.reflection.AccessStep"`.
- **GetMethod template simplification**: The `ReflectionDefBase::GetMethod` template loses its `<Class>` parameter, and `GlobalDef`'s duplicate `GetMethod_` overloads are removed.

## Impact

- **API**: Breaking change to `AccessPath` -- callers that previously constructed `AccessPath` as `Array<AccessStep>` must now use `AccessPath::Root()`, `->Extend(step)`, `->Attr(name)`, etc. The rename of `ObjectField` to `Attr` and `kObjectField` to `kAttr` breaks all existing usage sites. `AccessPathPair` type alias is updated but structurally the same. The flat `Array<AccessStep>` representation is still accessible via `AccessPathObj::ToSteps()`.
- **Flags/config**: `src/ffi/reflection/access_path.cc` is removed from the core build. `src/ffi/extra/reflection_extra.cc` is added to the extra-tier build list, so AccessPath reflection and `MakeObjectFromPackedArgs` now require `TVM_FFI_USE_EXTRA_CXX_API=ON`.
- **Data formats/schemas**: The `AccessStepObj` type key changes from `"tvm.ffi.reflection.AccessStep"` to `"ffi.reflection.AccessStep"`. A new type key `"ffi.reflection.AccessPath"` is introduced for the new `AccessPathObj`.

## Design Elements

Design elements this commit consumes:

- **Reflection system** ([`.knowledge/designs/0006-reflection.md`]): `ObjectDef<T>`, `GlobalDef`, `ReflectionDefBase::GetMethod`, static init registration. The commit registers `AccessPathObj` and `AccessStepObj` fields/methods via `ObjectDef`, and re-registers `MakeObjectFromPackedArgs` via `GlobalDef.def_packed`. The `GetMethod` template parameter simplification touches the core `ReflectionDefBase`.
- **Object system** ([`.knowledge/designs/0003-object-system.md`]): `AccessPathObj` follows the standard `FooObj`/`Foo` pattern with `TVM_FFI_DECLARE_FINAL_OBJECT_INFO`, `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS`, and `make_object<AccessPathObj>(...)`.
- **Structural equal/hash** ([`.knowledge/designs/0009-structural-equal-hash.md`]): `AccessPath` is the mismatch diagnostic output of `StructuralEqual::GetFirstMismatch`. The commit updates the handler's path construction to use the new tree-based `AccessPath::FromSteps` instead of direct `Array<AccessStep>` construction. `kTVMFFISEqHashKindConstTreeNode` is used on `AccessPathObj` for structural comparison.
- **Extra API tier** ([`.knowledge/designs/0011-extra-api-tier.md`]): The reflection registrations and `MakeObjectFromPackedArgs` are moved into the extra tier. This reverses a prior invariant that "`AccessPath` is core" -- the header remains core, but the reflection registrations are now extra-tier.
- **Container system** ([`.knowledge/designs/0005-containers.md`]): `Array<AccessStep>` is still used for `ToSteps()` output and `FromSteps()` input, but is no longer the canonical `AccessPath` representation.

Design elements this commit produces:

- **AccessPath as parent-pointing tree**: A new `AccessPathObj` class with `parent: Optional<ObjectRef>`, `step: Optional<AccessStep>`, `depth: int32_t` fields. This is a linked-list/tree representation where multiple paths sharing a prefix share the same parent chain, reducing allocation when exploring many sibling paths from a common root. This is a new design element not previously documented.
- **AccessPath builder API**: `AccessPath::Root()`, `Extend(step)`, `Attr(name)`, `AttrMissing(name)`, `ArrayItem(i)`, `ArrayItemMissing(i)`, `MapItem(key)`, `MapItemMissing(key)` provide a fluent builder for constructing paths incrementally. `ToSteps()` materializes the flat representation. `FromSteps(...)` reconstructs from a flat array.
- **AccessPath comparison primitives**: `PathEqual(other)` performs deep structural comparison by walking the parent chain. `IsPrefixOf(other)` checks prefix relationships by truncating the longer path and comparing. Both use pointer-equality fast paths.
- **Rename: Field -> Attr terminology**: `kObjectField` becomes `kAttr`, establishing "Attr" as the canonical term for object field access in the access path vocabulary. This aligns with Python attribute access terminology.

## Key Implementations

### Parent-Pointing Tree Structure

The core data model change is in `include/tvm/ffi/reflection/access_path.h`:

```
AccessPathObj {
  Optional<ObjectRef> parent;   // parent node (nullptr for root)
  Optional<AccessStep> step;    // step at this node (nullptr for root)
  int32_t depth;                // depth from root (0 for root)
}
```

**Invariant**: For non-root paths, `parent` is always an `AccessPath` object. The `Optional<ObjectRef>` type is used (rather than `Optional<AccessPath>`) to avoid circular header dependency -- `GetParent()` performs the downcast.

**Invariant**: `depth` is always `parent->depth + 1` for non-root paths. This enables O(1) prefix-length comparison in `IsPrefixOf` without traversing the parent chain.

**Extension point**: The tree structure is designed for future use cases where a structural comparison explores many sibling paths from a common root (e.g., comparing multiple map entries under the same parent object). Each sibling only allocates one new `AccessPathObj` node.

### Reflection Registration Relocation

`MakeObjectFromPackedArgs` is moved verbatim from `src/ffi/object.cc` to `src/ffi/extra/reflection_extra.cc`. The `AccessStepObj::RegisterReflection()` static method is removed from the header and replaced with a free function `AccessStepRegisterReflection()` in the new source file, alongside a new `AccessPathRegisterReflection()` that registers all `AccessPathObj` fields and methods.

**Consequence**: When `TVM_FFI_USE_EXTRA_CXX_API=OFF`, `AccessPath` and `AccessStep` types will exist in the type table (their `_GetOrAllocRuntimeTypeIndex` fires during static init of the header), but their field/method reflection metadata and `MakeObjectFromPackedArgs` will not be registered. This could cause failures in Python bindings if the extra tier is disabled.

### GetMethod Template Simplification

`ReflectionDefBase::GetMethod<Class>` becomes `GetMethod` (no `Class` template parameter). The `Class` parameter was unused -- `Function::FromTyped` already deduces the class from the member function pointer. The redundant `GlobalDef::GetMethod_` private overloads (which existed to handle member function pointers for `def_method`) are removed; the base class `GetMethod` handles all cases now.

### AccessKind Enum Value Shift

The renumbering of `AccessKind` shifts `kArrayItemMissing` from 3 to 4 and `kMapItemMissing` from 4 to 5, inserting `kAttrMissing = 3`. This is a binary-incompatible change to any serialized `AccessStep` values.

## Reflection

### Design docs to write

- **`.knowledge/designs/0006-reflection.md`** -- needs update: The design doc currently states `AccessPath = Array<AccessStep>` (line 104-108). This needs to be updated to reflect the new `AccessPathObj` parent-pointing tree structure, the `AccessPath::Root()` / `Extend()` builder API, `ToSteps()` / `FromSteps()` conversion, and `PathEqual()` / `IsPrefixOf()` comparison methods. Future commits touching mismatch diagnostics or tree traversal would reference this.

- **`.knowledge/designs/0009-structural-equal-hash.md`** -- needs update: The "AccessPath Mismatch Diagnostics" section (line 102-108) describes `AccessPath = Array<AccessStep>` with `AccessStep::Field(name)`. Both the type alias and the factory method name are now outdated. Should be updated to reference `AccessPathObj`, `AccessStep::Attr(name)`, `AccessStep::AttrMissing(name)`, and the `FromSteps()` construction pattern used in `GetFirstMismatch`.

- **`.knowledge/designs/0011-extra-api-tier.md`** -- needs update: The doc states "AccessPath is core" and "`access_path.cc` is always compiled as part of the core build" (line 66, 98). The header is still core, but the reflection registration (formerly `access_path.cc`) has been moved to `reflection_extra.cc` in the extra tier. Additionally, `MakeObjectFromPackedArgs` has also moved to the extra tier. The doc should clarify this header-vs-registration distinction.

### ADRs to write

- **`.knowledge/ADRs/0015-access-path-parent-tree.md`**: The decision to change `AccessPath` from a flat `Array<AccessStep>` to a parent-pointing tree. Context: multiple access paths during structural comparison share common prefixes; the tree representation avoids redundant allocations. Alternatives: keep flat array (simpler but O(n) total memory for n sibling paths), use a trie (more complex, better dedup but harder to integrate with Object system). Trade-off: slightly more complex single-path materialization (`ToSteps()` requires reverse traversal) in exchange for compact memory when many paths share prefixes.

### Design diagrams to draw

- **Mermaid**: A diagram showing the `AccessPathObj` parent-pointing tree structure. Components: `AccessPath::Root()` as the root node, child nodes linked via `parent` pointer, each with a `step` and `depth`. Show how two sibling paths (e.g., `root.body[0]` and `root.body[1]`) share the `root.body` prefix node.
