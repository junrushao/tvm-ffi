# Add yamllint, markdownlint-cli2, and rstcheck pre-commit hooks with doc formatting cleanup

## TL;DR
- Adds three new pre-commit hooks: `yamllint` (v1.35.1), `markdownlint-cli2` (v0.14.0), and `rstcheck` (v6.2.4) with their respective config files.
- Cleans up existing documentation (`.md` files under `docs/` and `examples/`) to comply with the new linters: adds blank lines before/after fenced code blocks, fixes list indentation, normalizes YAML whitespace, and annotates bare code fences with language tags.
- Adds `.cfg` to the allowed file extensions in `tests/lint/check_file_type.py`.

## Key Exports

N/A -- infrastructure change. No public API surface introduced or changed.

## Impact
- API: none
- Behavioral: CI lint job now enforces YAML style (`.yamllint.yaml`), Markdown style (`.markdownlint-cli2.yaml`), and RST validity (`docs/.rstcheck.cfg`) on every PR. Existing YAML files must use single-space after colon (no multi-space alignment). Markdown files must have blank lines around fenced code blocks and properly indented list items. RST files must not have broken references (Sphinx-specific directives/roles are ignored).
- Flags/config: Three new config files: `.yamllint.yaml` (120-char line warning, truthy whitelist), `.markdownlint-cli2.yaml` (MD013 line-length disabled), `docs/.rstcheck.cfg` (ignores automodule/autosummary/toctree/ifconfig directives and ref/cpp:class/cpp:func/py:func roles).
- Data formats/schemas: none
