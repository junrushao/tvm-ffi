# Fix error propagation when DLPack tensor allocator restore overwrites function call error
## TL;DR
- In `TVMFFIPyCallManager::FuncCall`, the DLPack allocator restore path previously overwrote `c_api_ret_code[0]` with its own return code, silently swallowing errors from the called function when tensor arguments were present.
- In `EnvContext::SetDLPackManagedTensorAllocator`, the out-parameter now returns only the cached TLS `dlpack_allocator_` instead of `GetDLPackManagedTensorAllocator()` (which falls through to the global allocator), ensuring restore-after-call restores exactly the prior local state.
- Version patch bumped from 9 to 8 (backport to 0.1.8 branch).

## Key Exports
None -- bugfix only, no new API surface.

## Impact
- API: none
- Behavioral: Functions called with torch tensor arguments (triggering DLPack C exchange path) now correctly propagate errors. Previously, if the called function returned an error code and the allocator restore succeeded, the error was silently lost and the function appeared to succeed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyCallManager::FuncCall` (0012-ffi-python-package) -- the Cython-side function dispatch path that sets up and tears down DLPack allocator context around FFI calls
- `EnvContext::SetDLPackManagedTensorAllocator` (0011-ffi-module-system) -- C++ TLS allocator set/get with global fallback
- `TVMFFIEnvSetDLPackManagedTensorAllocator` C env API (0011-ffi-module-system) -- the C ABI wrapper for the above
- `dlpack_c_exchange_api` protocol (0012-ffi-python-package) -- zero-overhead tensor exchange that triggers the allocator setup path

Design elements this commit produces: none

## Usage Examples
**Before (incorrect):** Error silently swallowed when function raises with tensor arg.
```python
x = torch.arange(128)
def raise_error(x):
    raise ValueError("error XYZ")
f = tvm_ffi.convert(raise_error)
f(x)  # BUG: no exception raised, error lost in allocator restore
```

**After (corrected):** Error propagates correctly.
```python
x = torch.arange(128)
def raise_error(x):
    raise ValueError("error XYZ")
f = tvm_ffi.convert(raise_error)
f(x)  # CORRECT: raises ValueError("error XYZ")
```

Regression test: `tests/python/test_tensor.py::test_tensor_auto_dlpack_with_error`

## Reflection

### Design docs / ADRs to write or update
- `.knowledge/design-records/0011-ffi-module-system.md`: The `EnvContext::SetDLPackManagedTensorAllocator` invariant should note that `opt_out_original_allocator` returns the TLS-only cached value (`dlpack_allocator_`), not the fallback-chain result from `GetDLPackManagedTensorAllocator()`. This distinction matters for correct restore-after-call semantics.

### Stale knowledge references
