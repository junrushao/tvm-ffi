# Refactor cubin extraction to use Triton's returned CompiledKernel directly
## TL;DR
- Removes 6-line cache-lookup pattern in both `benchmark_overhead.py` and `example_triton_cubin.py`
- Now captures `compiled_kernel` directly from the return value of `kernel[grid](...)`
- Eliminates reliance on Triton internal `device_caches` dict, which was fragile

## Key Exports

```python
# Before:
# empty_kernel[1,](a, b, c, n)
# device_caches = empty_kernel.device_caches
# device_id = next(iter(device_caches.keys()))
# compiled_kernel = next(iter(device_caches[device_id][0].values()))

# After:
compiled_kernel = empty_kernel[1,](a, b, c, n)
# Interacts with: Triton JIT return value, cubin_bytes = compiled_kernel.kernel
```

- API: none (example code only)
- Behavioral: cubin extraction is more reliable across Triton versions
