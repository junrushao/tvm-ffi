# Lint torch C DLPack build script: rename file, move globals into main, version-aware library names
## TL;DR
- Renames `python/tvm_ffi/utils/_build_optional_c_dlpack.py` to `_build_optional_torch_c_dlpack.py` for naming consistency with the module it supports.
- Moves top-level imports of `tvm_ffi` internals (`build_ninja`, `find_dlpack_include_path`, `FileLock`) and the `os.environ["TVM_FFI_DISABLE_TORCH_C_DLPACK"]` guard into `main()` to avoid cyclic imports when the file is imported as a module.
- Introduces version-aware and device-aware library naming (`libtorch_c_dlpack_addon_torch{major}{minor}-{cpu|cuda}.so`) with separate `--output-dir` / `--build-dir` / `--libname` CLI arguments, replacing the single `--build_dir` argument.

## Key Exports
**CLI arguments** (in `python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py`):
- `--build-dir` (optional) -- intermediate build directory; defaults to a temp directory if omitted.
- `--output-dir` -- directory for the final library (default: `~/.cache/tvm-ffi`).
- `--build-with-cuda` -- flag (replaces `--build_with_cuda` underscore form).
- `--libname` -- explicit library filename or `"auto"` for auto-generated version-tagged name.

**Internal function changes**:
- `_generate_ninja_build()` -- the `find_dlpack_include_path` import is moved from module-level into this function body (lazy import).
- `main()` -- `build_ninja` and `FileLock` imports are moved from module-level into this function body; `argparse.ArgumentParser` moved from module scope into `main()`; `build_dir` now uses `tempfile.mkdtemp` when not specified; output goes to `output_dir` instead of `build_dir`.

For trivial/chore commits: "None" -- N/A, this commit has behavioral changes.

## Impact
- API: The CLI interface of the build script changes: `--build_dir` is replaced by `--build-dir` + `--output-dir` + `--libname`. The library filename changes from a fixed `libtorch_c_dlpack_addon.so` to a version-tagged `libtorch_c_dlpack_addon_torch{M}{m}-{device}.so`. Callers invoking this script directly (AOT usage) must update their arguments.
- ABI: None.
- Behavioral: The `_optional_torch_c_dlpack.py` loader now produces version-tagged library names, meaning different PyTorch versions get separate cached libraries instead of overwriting a single file. The lock file is now placed in `output_dir` (next to the final library) rather than in `build_dir`. Build intermediates use a temporary directory by default instead of the output directory.
- Flags/config: None.
- Data formats/schemas: Cached library filenames on disk change from `libtorch_c_dlpack_addon.so` to `libtorch_c_dlpack_addon_torch{M}{m}-{cpu|cuda}.so` under `~/.cache/tvm-ffi/`.

## Design Elements
Design elements this commit consumes:
- DLPack fast-path PyTorch integration module (`.knowledge/designs/0018-dlpack-fast-path.md`, "PyTorch Integration Module" section) -- the JIT build flow invoked by `_optional_torch_c_dlpack.py`.
- Inline module compilation (`.knowledge/designs/0017-inline-module-compilation.md`) -- `build_ninja` used by the build script.

Design elements this commit produces:
- **Version-tagged library naming convention**: Libraries are now named `libtorch_c_dlpack_addon_torch{major}{minor}-{cpu|cuda}.{ext}`, allowing multiple PyTorch versions to coexist in the same cache directory.
- **Separate build vs output directory pattern**: Build intermediates go to a temp directory; only the final `.so` is placed in the output directory. This separates ephemeral build artifacts from the cached result.
- **Lazy import pattern for cyclic dependency avoidance**: Module-level `tvm_ffi` imports are deferred into function bodies to prevent the build script from triggering `tvm_ffi` import during `_optional_torch_c_dlpack.py` loading.

## Usage Examples
AOT build with the new CLI (replaces old `--build_dir` pattern):
```bash
# Old (before this commit):
python python/tvm_ffi/utils/_build_optional_c_dlpack.py --build_dir ~/.cache/tvm-ffi/torch_c_dlpack_addon

# New (after this commit):
python python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py \
    --output-dir ~/.cache/tvm-ffi \
    --libname libtorch_c_dlpack_addon_torch214-cuda.so \
    --build-with-cuda
```

JIT invocation from `_optional_torch_c_dlpack.py` (internal):
```python
# The loader now constructs version-tagged library names:
major, minor = torch.__version__.split(".")[:2]
device = "cpu" if not torch.cuda.is_available() else "cuda"
suffix = ".dll" if sys.platform.startswith("win") else ".so"
libname = f"libtorch_c_dlpack_addon_torch{major}{minor}-{device}{suffix}"
# Then invokes the build script with --output-dir and --libname
```
