# Relocate CMake config to share/cmake/tvm_ffi/ for standard find_package discovery, removing manual execute_process boilerplate from examples

## TL;DR
- CMake config files moved from `cmake/` to `share/cmake/tvm_ffi/`, matching CMake's standard search pattern `<prefix>/<name>*/share/cmake/<name>*/`; `find_package(tvm_ffi CONFIG REQUIRED)` now works without manual `tvm_ffi_ROOT` assignment.
- `find_cmake_path()` in `libinfo.py` updated to check `share/cmake/tvm_ffi/` first (standard pip-installed layout) and `../../cmake` second (development-mode fallback).
- `pyproject.toml` gains `editable.rebuild = false` to prevent scikit-build-core from re-triggering C extension builds on every import in editable installs.

## Impact
- API: None — `tvm_ffi.config --cmakedir` CLI interface unchanged; `find_cmake_path()` return value changes for pip-installed layout (now returns `share/cmake/tvm_ffi/` instead of `cmake/`), but callers only use the result as an input to CMake.
- Behavioral: Downstream projects using `find_package(tvm_ffi CONFIG REQUIRED)` no longer need `execute_process(python -m tvm_ffi.config --cmakedir)` boilerplate when Python is found first; CMake discovers config automatically via `sys.prefix`.
- Flags/config: `editable.rebuild = false` added to `pyproject.toml` — editable installs no longer trigger C extension rebuild on each Python import.
- Data formats/schemas: None.

## Usage Examples

Before (examples/packaging/CMakeLists.txt, pre-commit):
```cmake
find_package(Python COMPONENTS Interpreter REQUIRED)
execute_process(
  COMMAND "${Python_EXECUTABLE}" -m tvm_ffi.config --cmakedir
  OUTPUT_STRIP_TRAILING_WHITESPACE
  OUTPUT_VARIABLE tvm_ffi_ROOT
)
find_package(tvm_ffi CONFIG REQUIRED)
```

After (post-commit):
```cmake
find_package(Python COMPONENTS Interpreter REQUIRED)
# tvm_ffi is installed via pip. CMake finds it automatically
# because Python's sys.prefix is added to CMake search paths.
find_package(tvm_ffi CONFIG REQUIRED)
```
