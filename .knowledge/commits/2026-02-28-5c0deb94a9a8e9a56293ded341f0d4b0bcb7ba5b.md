# Skip imports in config mode
## TL;DR
- Refactors `python/tvm_ffi/__init__.py` to detect config-mode invocations (`tvm-ffi-config` CLI or `python -m tvm_ffi.config`) and skip all heavy imports (library loading, Cython extension, object registration, dtype literals, torch pre-import) when in config mode.
- Config mode only needs `libinfo.py` for path discovery, so skipping the full import chain eliminates the native library dependency and reduces startup time for `tvm-ffi-config` queries (e.g., `--includedir`, `--cmakedir`).

## Impact
- **API**: `tvm_ffi` package can now be imported in config-only mode without loading `libtvm_ffi`. All public symbols (`Array`, `Map`, `register_object`, etc.) are only available when not in config mode (or under `TYPE_CHECKING`). This means `from tvm_ffi import Array` will work in normal mode but fail in config mode, which is expected since config mode only needs path queries.
- **Config detection**: `_is_config_mode()` checks two paths:
  1. `sys.argv[0].endswith("tvm-ffi-config")` -- direct CLI entry point.
  2. `sys.orig_argv` (Python 3.10+) for `-m tvm_ffi.config` invocations -- necessary because Python strips the module name from `sys.argv` when using `-m`.
- **TYPE_CHECKING guard**: All imports are wrapped in `if TYPE_CHECKING or not _is_config_mode():`, so type checkers (mypy, pyright) still see all symbols.
- **Flags/config**: None.
- **Data formats/schemas**: None.

Design elements this commit **produces**:

- **Config-mode import bypass**: A new initialization pattern where `__init__.py` detects whether the current invocation is a config CLI query and, if so, skips all heavy imports. This reduces the dependency surface for config queries to just `sys` and `libinfo.py`. The pattern uses `TYPE_CHECKING` to maintain full symbol visibility for static type checkers.
