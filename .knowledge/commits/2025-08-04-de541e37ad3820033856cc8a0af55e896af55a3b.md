# Add lightweight JSON parser/writer to extra module
## TL;DR
- Introduces a minimal JSON parser (`json::Parse`) and writer (`json::Stringify`) in `tvm::ffi::json`, living under the `extra/` module boundary gated by `TVM_FFI_USE_EXTRA_CXX_API`.
- JSON values are represented entirely via existing FFI types: `Any` (scalars/null), `String`, `Array<Any>`, `Map<Any, Any>` -- no new object types are introduced.
- Extends standard JSON with `Infinity`, `-Infinity`, and `NaN` literals (JavaScript semantics) and distinguishes `int64_t` from `double` to preserve round-trip type fidelity.

## Key Exports

**Type aliases** (in `tvm::ffi::json` namespace, `include/tvm/ffi/extra/json.h`):
```cpp
using Value  = Any;                 // any JSON value
using Object = ffi::Map<Any, Any>;  // JSON object (insertion-order-preserving)
using Array  = ffi::Array<Any>;     // JSON array
```

**Functions** (`include/tvm/ffi/extra/json.h`):
```cpp
// Parse JSON string -> Any. Optional error_msg out-param suppresses exceptions.
TVM_FFI_EXTRA_CXX_API json::Value Parse(const String& json_str, String* error_msg = nullptr);

// Serialize Any -> JSON string. Optional indent for pretty-printing.
TVM_FFI_EXTRA_CXX_API String Stringify(const json::Value& value, Optional<int> indent = std::nullopt);
```

**Global function registrations** (via `TVM_FFI_STATIC_INIT_BLOCK` + `reflection::GlobalDef`):
- `"ffi.json.Parse"` -- wraps `json::Parse` (without error_msg parameter)
- `"ffi.json.Stringify"` -- wraps `json::Stringify`

**Internal classes** (not exported, in `.cc` files):
- `JSONParserContext` -- cursor-based lexer with line/column tracking for error messages.
- `JSONParser` -- recursive-descent parser using `JSONParserContext`, with temp stacks for arrays/objects.
- `JSONWriter` -- `back_insert_iterator`-based serializer dispatching on `TypeIndex`.

## Impact
- API: New public header `include/tvm/ffi/extra/json.h` and two global functions. No existing API changed.
- Behavioral: none -- purely additive.
- Flags/config: Gated by existing `TVM_FFI_USE_EXTRA_CXX_API` CMake flag (default ON).
- Data formats/schemas: Defines JSON serialization conventions: floats with integer value print as `X.0`, `int64_t` prints without decimal, `NaN`/`Infinity` supported.

## Design Elements
Design elements this commit consumes:
- **Any/AnyView value system** (`.knowledge/designs/0002-any-value-system.md`): `json::Value` is a type alias for `Any`; the parser writes directly into `Any` output slots using type-index-specific assignment.
- **Containers** (`.knowledge/designs/0008-containers.md`): Uses `Array<Any>` and `Map<Any, Any>` for JSON arrays/objects. Relies on insertion-order preservation of `Map` for deterministic key ordering.
- **Extra API isolation** (`.knowledge/ADRs/0010-extra-api-isolation.md`): All new code placed under `include/tvm/ffi/extra/` and `src/ffi/extra/`, using `TVM_FFI_EXTRA_CXX_API` visibility macro.
- **GlobalDef registration** (`.knowledge/ADRs/0008-globaldef-over-register-global.md`): Both global functions registered via `reflection::GlobalDef().def(...)` inside `TVM_FFI_STATIC_INIT_BLOCK`.
- **Structural equality** (`.knowledge/designs/0010-structural-equal-hash.md`): Tests use `StructuralEqual()` to compare parsed results against expected `Array`/`Object` values.
- **TypeIndex dispatch**: Writer switches on `value.type_index()` using `TypeIndex::kTVMFFI*` constants for None, Bool, Int, Float, SmallStr, Str, Array, Map.
- **String** (`tvm::ffi::String`): Both parser output and writer input use the FFI `String` type rather than `std::string`.

Design elements this commit produces:
- **json namespace and type aliases**: `tvm::ffi::json::{Value, Object, Array}` -- a lightweight convention for representing JSON using existing FFI types, avoiding new Object subclasses.
- **JSON parse/stringify protocol**: The `Parse`/`Stringify` pair with round-trip fidelity for int64/double/bool/null/string/array/object. Extended with `Infinity`/`NaN` support.
- **Error reporting convention**: `Parse` supports an optional `String* error_msg` out-parameter -- when non-null, errors are reported via string rather than exception, following a "no-throw optional" pattern. Error messages include `line:column (char N)` context, modeled after Python's `json.decoder.JSONDecodeError`.

## Usage Examples

Parsing JSON and accessing values:
```cpp
#include <tvm/ffi/extra/json.h>
using namespace tvm::ffi;

// Parse a JSON string
json::Value val = json::Parse(R"({"name": "test", "count": 42, "items": [1, 2, 3]})");
auto obj = val.cast<json::Object>();

// Error-safe parsing (no exception on malformed input)
String err;
json::Value bad = json::Parse("{ invalid }", &err);
// err contains "Expecting property name enclosed in double quotes: line 1 column 3 (char 2)"
```

Serializing values to JSON:
```cpp
json::Object data{{"key", "value"}, {"nums", json::Array{1, 2, 3}}};
String compact = json::Stringify(data);           // {"key":"value","nums":[1,2,3]}
String pretty  = json::Stringify(data, 2);        // pretty-printed with 2-space indent
```

Cross-language access via global functions:
```cpp
// Registered as "ffi.json.Parse" and "ffi.json.Stringify"
// Accessible from Python: tvm_ffi.get_global_func("ffi.json.Parse")(json_str)
```
