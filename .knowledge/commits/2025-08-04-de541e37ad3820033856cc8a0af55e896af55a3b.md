# Add lightweight JSON parser/writer to the extra C++ module
## TL;DR
- Introduces `tvm::ffi::json` namespace with `Parse()` and `Stringify()` functions that convert between JSON text and the existing `Any`/`Array`/`Map` value system.
- Parser supports standard JSON plus JavaScript-style `Infinity`/`NaN` literals and `int64_t` integers; writer produces compact or indented output with roundtrip fidelity for int vs float types.
- Registered as global functions `ffi.json.Parse` and `ffi.json.Stringify` for cross-language access.

## Impact
- API: Additive only -- two new public C++ functions (`json::Parse`, `json::Stringify`) and three type aliases (`json::Value`, `json::Object`, `json::Array`). Two new global FFI functions (`ffi.json.Parse`, `ffi.json.Stringify`). No changes to existing APIs.
- Behavioral: none
- Flags/config: Gated behind `TVM_FFI_USE_EXTRA_CXX_API` CMake option (same gate as structural_equal/structural_hash).
- Data formats/schemas: Defines a JSON dialect that extends RFC 8259 with `Infinity`/`NaN`/`int64`. Roundtrip property: `Parse(Stringify(v))` preserves int vs float type distinction via the `.0` suffix convention.

## Design Elements
Design elements this commit consumes:
- **Any/AnyView system** (`.knowledge/designs/0003-any-system.md`): `json::Value` is a direct alias of `ffi::Any`; parser writes into `Any*` output params, writer dispatches on `type_index()`.
- **Container system** (`.knowledge/designs/0007-containers.md`): Reuses `Array<Any>` and `Map<Any, Any>` for JSON arrays and objects; relies on insertion-ordered Map (ADR `.knowledge/ADRs/0004-insertion-ordered-map.md`) for object key ordering.
- **Reflection/GlobalDef** (`.knowledge/designs/0008-reflection.md`): Uses `TVM_FFI_STATIC_INIT_BLOCK` + `refl::GlobalDef().def(...)` to register `ffi.json.Parse` and `ffi.json.Stringify` as global packed functions.
- **String** (`.knowledge/designs/0007-containers.md`): Uses `ffi::String` for input/output and key storage.
- **Error system** (`.knowledge/designs/0005-error-system.md`): Uses `TVM_FFI_THROW(ValueError)` for parse and serialization errors; `TVM_FFI_ICHECK` for internal assertions.
- **TypeIndex enum** (`.knowledge/designs/0003-any-system.md`): Writer switches on `kTVMFFINone`, `kTVMFFIBool`, `kTVMFFIInt`, `kTVMFFIFloat`, `kTVMFFISmallStr`, `kTVMFFIStr`, `kTVMFFIArray`, `kTVMFFIMap`.
- **TVM_FFI_EXTRA_CXX_API visibility macro** (`include/tvm/ffi/extra/base.h`): Controls symbol export for the extra module.
- **StructuralEqual** (`.knowledge/designs/0009-structural-equal-hash.md`): Used in tests to compare parsed results against expected value trees.

Design elements this commit produces:
- **json namespace and API** (`tvm::ffi::json`): New `Parse`/`Stringify` public API surface for JSON handling. First self-contained utility in the `extra/` module beyond structural equality/hashing.
- **Soft convention: JavaScript-extended JSON dialect**: `Infinity`/`NaN` support and `int64` preservation are extensions beyond standard JSON. This establishes a de-facto dialect for the project.
- **Soft convention: roundtrip int/float distinction**: The `.0` suffix for integer-valued doubles ensures `Stringify -> Parse` preserves the type tag, which is non-standard but critical for FFI value fidelity.

## Usage Examples

C++ usage (from test files in this commit):

```cpp
#include <tvm/ffi/extra/json.h>
using namespace tvm::ffi;

// Parse JSON string into Any value tree
json::Value val = json::Parse("{\"name\": \"Alice\", \"scores\": [95, 87.5]}");
json::Object obj = val.cast<json::Object>();

// Access values
String name = obj["name"].cast<String>();          // "Alice"
json::Array scores = obj["scores"].cast<json::Array>();
int64_t first = scores[0].cast<int64_t>();         // 95 (int64, not double)

// Serialize back to JSON (compact)
String compact = json::Stringify(val);             // {"name":"Alice","scores":[95,87.5]}

// Serialize with pretty-print
String pretty = json::Stringify(val, 2);           // indented with 2 spaces

// Error handling without exceptions
String error_msg;
json::Value bad = json::Parse("{invalid", &error_msg);
// error_msg: "Expecting property name enclosed in double quotes: line 1 column 2 (char 1)"
```
