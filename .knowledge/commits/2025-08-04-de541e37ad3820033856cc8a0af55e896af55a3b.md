# Add lightweight JSON parser/writer to ffi extra component
## TL;DR
- Introduces a minimal JSON parser (`json::Parse`) and writer (`json::Stringify`) under `tvm::ffi::json` namespace, built entirely on existing FFI value types (`Any`, `Array<Any>`, `Map<Any,Any>`, `String`).
- Supports standard JSON plus extensions: `Infinity`, `NaN`, `-Infinity` literals and `int64` integer distinction (not just double).
- Registered as global FFI functions `ffi.json.Parse` and `ffi.json.Stringify` via `reflection::GlobalDef`.

Plus 2 internal classes: `JSONParserContext` (lexer/tokenizer with position tracking, unicode/surrogate-pair handling) and `JSONParser` (recursive descent parser using temp stacks for array/object construction).

## Impact
- API: Additive only -- two new public C++ functions and two new global FFI functions. No changes to existing APIs.
- Behavioral: None -- no changes to existing functions.
- Flags/config: Gated by `TVM_FFI_USE_EXTRA_CXX_API` CMake option (existing flag, sources appended to build list).
- Data formats/schemas: Introduces a JSON text format with extensions (Infinity/NaN/int64). Roundtrip property: `Parse(Stringify(v)) == v` for supported types, including int vs float distinction.

## Design Elements
Design elements this commit consumes:
- `Any`/`AnyView` value system (0001) -- JSON values are stored as `Any`; the parser writes into `json::Value` which is `Any`
- `Array<Any>` and `Map<Any,Any>` containers (0006) -- used as `json::Array` and `json::Object` respectively; relies on insertion-order guarantee of `MapObj`
- `String` (0006) -- input/output type for parse/stringify; also used as map keys
- `Optional<int>` (0005) -- indent parameter for `Stringify`
- `reflection::GlobalDef` (0008) -- registers `ffi.json.Parse` and `ffi.json.Stringify` in global function registry
- `TVM_FFI_THROW(ValueError)` error macro (0004) -- for parse errors when no `error_msg` out-param is provided
- `TVM_FFI_EXTRA_CXX_API` visibility macro -- from `extra/base.h`
- `details::AnyUnsafe::CopyFromAnyViewAfterCheck` -- internal API used by writer to extract typed values from Any without redundant type checks
- `StructuralEqual` (0009) -- consumed in tests only, for comparing parsed results against expected values

Design elements this commit produces:
- `tvm::ffi::json` namespace with `Parse` and `Stringify` functions
- `ffi.json.Parse` and `ffi.json.Stringify` global FFI functions
- JSON format convention: int64 integers preserved (not coerced to double), JS-style Infinity/NaN support

## Usage Examples

Parsing a JSON string (from test_json_parser.cc):
```cpp
#include <tvm/ffi/extra/json.h>
using namespace tvm::ffi;

// Parse primitives
int64_t n = json::Parse("123").cast<int64_t>();         // 123
String s = json::Parse("\"hello\"").cast<String>();      // "hello"

// Parse structured data
json::Object obj = json::Parse("{\"a\": 1, \"b\": [2, 3]}").cast<json::Object>();

// Error handling without exceptions
String error_msg;
json::Value result = json::Parse("invalid", &error_msg);
// result is nullptr, error_msg contains "Expecting value: line 1 column 1 (char 0)"
```

Serializing to JSON (from test_json_writer.cc):
```cpp
// Compact output
json::Object obj{{"name", "test"}, {"count", 42}, {"tags", json::Array{1, 2, 3}}};
String compact = json::Stringify(obj);
// {"name":"test","count":42,"tags":[1,2,3]}

// Pretty-printed output
String pretty = json::Stringify(obj, 2);
// {
//   "name": "test",
//   "count": 42,
//   "tags": [
//     1,
//     2,
//     3
//   ]
// }
```
