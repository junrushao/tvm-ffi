# Add lightweight JSON parser/writer to extra component

## TL;DR
- Adds a minimal JSON parser and JSON writer (serializer) under `tvm::ffi::json`, built on top of the existing FFI type system (`Any`, `Array<Any>`, `Map<Any, Any>`, `String`).
- The parser supports standard JSON plus JavaScript-style `Infinity`/`NaN`/`-Infinity` and int64 integer values (numbers without `.`/`e`/`E` are parsed as `int64_t`, others as `double`).
- The writer serializes `Any` values back to JSON strings, with optional indented pretty-printing. Floats that are exact integers are written with a `.0` suffix to preserve round-trip int/float type distinction.
- Both parser and writer are registered as global functions (`ffi.json.Parse`, `ffi.json.Stringify`) for cross-language access.
- Two new source files and a public header are added under `src/ffi/extra/` and `include/tvm/ffi/extra/`. Comprehensive GoogleTest coverage is included (363+241 lines of tests).

## Key Exports

### Public Header (`include/tvm/ffi/extra/json.h`)

**Type aliases in `tvm::ffi::json`:**
- `json::Value = Any` -- A JSON value is simply a type-erased `Any`.
- `json::Object = ffi::Map<Any, Any>` -- A JSON object. Uses `Map<Any, Any>` (not `Map<String, Any>`) to avoid key-type checking overhead at construction; string keys are validated at read time.
- `json::Array = ffi::Array<Any>` -- A JSON array.

**Free functions:**
- `json::Parse(const String& json_str, String* error_msg = nullptr) -> json::Value` -- Parse a JSON string into an `Any` value. If `error_msg` is non-null, errors are reported via the output parameter (no exception thrown); if null, throws `ValueError` on failure. Returns `nullptr` on parse failure when `error_msg` is provided.
- `json::Stringify(const json::Value& value, Optional<int> indent = std::nullopt) -> String` -- Serialize an `Any` value to a JSON string. If `indent` is provided and non-zero, output is pretty-printed with that many spaces per level.

Both are marked `TVM_FFI_EXTRA_CXX_API` (non-core C++ API, same linkage category as `StructuralEqual`/`StructuralHash`).

### Global Function Registry

- `"ffi.json.Parse"` -- Wraps `json::Parse(json_str)` (no error_msg parameter; throws on failure).
- `"ffi.json.Stringify"` -- Wraps `json::Stringify(value, indent)`.

### Build System (`CMakeLists.txt`)

Two source files added to the `TVM_FFI_USE_EXTRA_CXX_API` conditional block:
- `src/ffi/extra/json_parser.cc`
- `src/ffi/extra/json_writer.cc`

## Impact
- **ABI**: Non-breaking. No changes to `TVMFFIAny`, type indices, or C ABI structs.
- **API**: New public header `include/tvm/ffi/extra/json.h` with `Parse` and `Stringify` functions. Two new global functions registered. All additive.
- **Behavioral**: JSON parsing preserves int64 vs. double distinction for numbers. The writer uses `%.1f` for integer-valued doubles (e.g., `5.0` not `5`) and `%.17g` for non-integer doubles to maintain maximum precision. `NaN`/`Infinity`/`-Infinity` are supported in both directions (non-standard JSON extension matching JavaScript conventions). Objects preserve insertion order (via `Map<Any, Any>` iteration order).
- **Flags/config**: Requires `TVM_FFI_USE_EXTRA_CXX_API=ON` at build time (same gate as structural equal/hash).

## Design Elements

Design elements this commit consumes:
- **Any system** (`.knowledge/designs/any-system.md`) -- `Any`/`AnyView` as the universal value container. JSON values are directly represented as `Any`. The writer dispatches on `type_index()` using `TypeIndex::kTVMFFINone`, `kTVMFFIBool`, `kTVMFFIInt`, `kTVMFFIFloat`, `kTVMFFISmallStr`, `kTVMFFIStr`, `kTVMFFIArray`, `kTVMFFIMap`.
- **Container types** (`.knowledge/designs/containers.md`) -- `Array<Any>` for JSON arrays, `Map<Any, Any>` for JSON objects, `String` for JSON strings. Array and Map are constructed from `std::vector` temporaries using range constructors.
- **Reflection global registry** (`.knowledge/designs/reflection.md`) -- `TVM_FFI_STATIC_INIT_BLOCK` and `refl::GlobalDef().def(...)` pattern for registering `ffi.json.Parse` and `ffi.json.Stringify` as global functions.
- **TVM_FFI_EXTRA_CXX_API** (from 9445fe7) -- Visibility macro for non-core C++ APIs.
- **Structural equality** (from 9445fe7) -- Used in tests to compare parsed JSON values against expected structures.

Design elements this commit produces:
- **JSON value representation** -- JSON values are represented using existing FFI types with no new object classes: `null` -> `nullptr` (kTVMFFINone), `true`/`false` -> `bool`, integers -> `int64_t`, floats -> `double`, strings -> `String`, arrays -> `Array<Any>`, objects -> `Map<Any, Any>`. This is a zero-overhead representation that reuses the FFI type system.
- **JSON parser** -- `JSONParserContext` handles low-level character scanning (strings with full unicode/surrogate-pair support, numbers including `Infinity`/`NaN`). `JSONParser` implements recursive descent with explicit temp stacks (`array_temp_stack_`, `object_temp_stack_`) to batch-construct arrays/objects at precise sizes. Error messages follow Python `json.loads` style with `line:column (char N)` context.
- **JSON writer** -- `JSONWriter` dispatches on `type_index()` to serialize each FFI type. Uses `std::back_insert_iterator<std::string>` for output. Indent tracking via `total_indent_` counter. Float serialization distinguishes integer-valued doubles (printed as `%.1f` for round-trip fidelity) from general doubles (printed as `%.17g` for precision).
- **Integer/float round-trip preservation** -- Numbers without fractional or exponent parts are parsed as `int64_t`; numbers with `.`/`e`/`E` are parsed as `double`. The writer prints integer-valued doubles with `.0` suffix. This enables faithful round-trip of `int64_t` vs `double` through parse/stringify cycles, which is important for ML model serialization where integer shapes and float parameters must be distinguished.

## Usage Examples

### Parsing JSON
```cpp
#include <tvm/ffi/extra/json.h>
using namespace tvm::ffi;

// Parse a JSON object
auto val = json::Parse(R"({"name": "model", "layers": [1, 2, 3]})");
auto obj = val.cast<json::Object>();
// obj["name"] -> String("model"), obj["layers"] -> Array{1, 2, 3}

// Parse with error handling (no exception)
String err;
auto result = json::Parse("invalid json", &err);
// result == nullptr, err == "Expecting value: line 1 column 1 (char 0)"
```

### Serializing to JSON
```cpp
// Compact output
json::Object obj{{"key", 42}, {"arr", json::Array{1, 2.5, "hello"}}};
String compact = json::Stringify(obj);
// -> {"key":42,"arr":[1,2.5,"hello"]}

// Pretty-printed with 2-space indent
String pretty = json::Stringify(obj, 2);
// -> {
//      "key": 42,
//      "arr": [
//        1,
//        2.5,
//        "hello"
//      ]
//    }
```

### Int/float round-trip
```cpp
auto v = json::Parse("42");
assert(v.type_index() == TypeIndex::kTVMFFIInt);  // parsed as int64_t
assert(json::Stringify(v) == "42");

auto f = json::Parse("42.0");
assert(f.type_index() == TypeIndex::kTVMFFIFloat);  // parsed as double
assert(json::Stringify(f) == "42.0");  // preserved with .0 suffix
```
