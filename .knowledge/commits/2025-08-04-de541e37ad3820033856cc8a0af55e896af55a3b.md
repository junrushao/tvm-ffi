# Add lightweight JSON parser/writer to ffi extra component
## TL;DR
- Adds a new `tvm::ffi::json` namespace with `Parse` and `Stringify` functions for round-trippable JSON serialization built on top of the existing `Any`/container system.
- Reuses `ffi::Any` as `json::Value`, `ffi::Map<Any,Any>` as `json::Object`, and `ffi::Array<Any>` as `json::Array` -- no new object types needed.
- Registers two global functions (`ffi.json.Parse`, `ffi.json.Stringify`) for cross-language access. Includes comprehensive GoogleTest coverage.

## Impact
- API: New public header `include/tvm/ffi/extra/json.h` and two global functions. No existing APIs changed.
- Behavioral: none
- Flags/config: Compiled only when `TVM_FFI_USE_EXTRA_CXX_API` is ON (via `CMakeLists.txt`).
- Data formats/schemas: Introduces JSON as a first-class serialization format within the FFI layer. Supports standard JSON plus JS-style `Infinity`/`NaN` and int64 integers.

## Design Elements
Design elements this commit consumes:
- **Any/AnyView value system** (0002-ffi-any-value-system) -- `json::Value` is a direct alias for `Any`; parser/writer dispatches on `type_index()`.
- **Container system** (0006-ffi-containers) -- reuses `Array<Any>`, `Map<Any,Any>`, `String`, `Optional<int>` directly as JSON data model.
- **Function registration** (0004-ffi-function-system) -- uses `TVM_FFI_STATIC_INIT_BLOCK` + `refl::GlobalDef().def(...)` to register `ffi.json.Parse` and `ffi.json.Stringify`.
- **Error protocol** (0005-ffi-error-protocol) -- uses `TVM_FFI_THROW(ValueError)` for parse/write failures.
- **TypeIndex enum** (0001-ffi-c-abi) -- writer dispatches on `TypeIndex::kTVMFFINone/Bool/Int/Float/Str/SmallStr/Array/Map`.
- **Structural equality** (0009-ffi-structural-eq-hash) -- used in tests to compare parsed JSON structures.

Design elements this commit produces:
- **json namespace and API** (`tvm::ffi::json`) -- new `Parse`/`Stringify` public API with type aliases `Value`, `Object`, `Array`. Public header at `include/tvm/ffi/extra/json.h`.
- **JSON ↔ Any roundtrip convention** -- integers that fit int64 are preserved as int64 (not double); integer-like doubles are serialized with `.0` suffix; `NaN`/`Infinity` use JS syntax.

## Usage Examples

Parsing JSON (from test_json_parser.cc):
```cpp
#include <tvm/ffi/extra/json.h>
using namespace tvm::ffi;

// Parse primitives
auto val = json::Parse("42");                    // int64_t
auto arr = json::Parse("[1, \"two\", true]");    // json::Array
auto obj = json::Parse("{\"key\": [1, 2]}");     // json::Object

// Error handling without exceptions
String error_msg;
auto bad = json::Parse("invalid", &error_msg);
// bad == nullptr, error_msg contains line/column info
```

Serializing JSON (from test_json_writer.cc):
```cpp
json::Object data{{"name", "test"}, {"numbers", json::Array{1, 2, 3}}};
String compact = json::Stringify(data);           // {"name":"test","numbers":[1,2,3]}
String pretty  = json::Stringify(data, 2);        // indented with 2 spaces
```
