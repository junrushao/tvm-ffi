# Add sphinx-autodoc-typehints plugin and remove redundant docstring type annotations
## TL;DR
- Adds the `sphinx-autodoc-typehints` Sphinx extension to auto-extract type annotations from Python function signatures into rendered documentation.
- Removes redundant `: TypeName` annotations from Napoleon-style docstrings across 14 Python source files, enforcing the DRY principle (types live in signatures only).
- Configures related Sphinx options (`autodoc_preserve_defaults`, `typehints_defaults`, `always_document_param_types`, `napoleon_use_rtype`).

## Key Exports
None -- documentation tooling change only.

## Impact
- API: none
- Behavioral: none -- runtime code is unchanged; only docstring text and Sphinx config are modified
- Flags/config: New Sphinx config keys in `docs/conf.py`: `always_use_bars_union`, `autodoc_preserve_defaults`, `typehints_defaults`, `always_document_param_types`, `napoleon_use_rtype`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Python type annotations on function/method signatures across `python/tvm_ffi/` -- the plugin reads these to generate docs
- Sphinx Napoleon-style docstrings (NumPy format) used throughout the Python package

Design elements this commit produces:
- Docstring convention: parameter and return type annotations must NOT be duplicated in docstrings; they are auto-extracted from function signatures by `sphinx-autodoc-typehints`. This is a new convention enforced by tooling.

```python
def convert(value: Any) -> Any:
```

```python
    Parameters
    ----------
    value
        The python object to be converted.

    Returns
    -------
    ffi_obj
        The converted TVM FFI object.
    """
```
