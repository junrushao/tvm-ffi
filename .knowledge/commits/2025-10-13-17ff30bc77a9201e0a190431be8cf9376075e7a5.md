# Add sphinx-autodoc-typehints plugin and strip redundant docstring type annotations

## TL;DR
- Adds `sphinx-autodoc-typehints` Sphinx extension to auto-extract type annotations from Python function signatures into rendered documentation.
- Configures complementary Sphinx/Napoleon settings (`autodoc_preserve_defaults`, `typehints_defaults`, `always_document_param_types`, `napoleon_use_rtype`).
- Strips redundant ` : type` suffixes from NumPy-style docstring parameter/return descriptions across 14 Python source files, following DRY principle.

## Key Exports
None -- this commit changes documentation tooling and docstring formatting only. No new public API symbols are introduced or changed.

## Impact
- API: none
- Behavioral: none -- runtime behavior is unchanged; only Sphinx-rendered documentation output changes.
- Flags/config: new Sphinx config keys in `docs/conf.py`: `always_use_bars_union`, `autodoc_preserve_defaults`, `typehints_defaults`, `always_document_param_types`, `napoleon_use_rtype`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- NumPy-style docstring convention used throughout `python/tvm_ffi/` (no design record; project convention via `ruff` + Napoleon).
- Sphinx autodoc configuration in `docs/conf.py`.

Design elements this commit produces: none

## Usage Examples
None -- docstring-only change. The convention going forward is to omit type annotations from docstring parameter lines when the function signature already carries type hints. For example:

Before:
```python
def convert(value: Any) -> Any:
    """Parameters
    ----------
    value : Any
        The python object to be converted.
    """
```

After:
```python
def convert(value: Any) -> Any:
    """Parameters
    ----------
    value
        The python object to be converted.
    """
```
