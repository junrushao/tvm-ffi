# Fix `tvm-ffi-config --sourcedir` by checking `src/` instead of `cmake/` in wheel builds

## TL;DR
- `find_source_path()` in `python/tvm_ffi/libinfo.py` used `(p / "cmake").is_dir()` to validate the source directory, but in wheel installs the `cmake/` directory lives under `share/cmake/`, not at the package root.
- Changed the condition to `(p / "src").is_dir()`, which reliably exists at the same relative path in both dev and wheel layouts.

## Key Exports

None — no new or changed public API surface. The fix is an internal implementation detail of `find_source_path()`.

## Impact
- API: none
- Behavioral: `tvm-ffi-config --sourcedir` now works correctly in wheel installs (was broken, raising `RuntimeError`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Packaging path discovery** (`0013-ffi-packaging-and-distribution`): `find_source_path()` is part of the `tvm_ffi.libinfo` path-discovery utilities used by `tvm_ffi.config` CLI tool.

Design elements this commit produces: none.

## Usage Examples

Before (broken in wheels):
```python
# find_source_path() checks (p / "cmake").is_dir()
# In wheel layout, cmake/ is at <pkg>/share/cmake/, not <pkg>/cmake/
# Result: RuntimeError("Cannot find home path.")
```

After (fixed):
```python
# find_source_path() checks (p / "src").is_dir()
# src/ reliably exists at <pkg>/src/ in both dev and wheel layouts
# Result: returns correct source path
```
