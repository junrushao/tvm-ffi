# Robustify libinfo DLL directory discovery against OSError from inaccessible paths
## TL;DR
- Wraps each path check in `get_dll_directories()` with a try/except OSError guard so that paths from environment variables (PATH, LD_LIBRARY_PATH, DYLD_LIBRARY_PATH) that cannot be stat'd or resolved (e.g., due to permission errors) are silently skipped instead of crashing library discovery.

## Key Exports
None -- no new public API surface. The signature and return type of `get_dll_directories() -> list[str]` are unchanged.

## Impact
- API: None -- `get_dll_directories()` returns the same type with the same semantics.
- ABI: None.
- Behavioral: Paths that previously caused an `OSError` (e.g., from `Path.is_dir()` or `Path.resolve()` on inaccessible directories) are now silently skipped. This means `get_dll_directories()` may return fewer entries than before when the environment contains problematic paths, but it will no longer raise an unhandled exception.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit produces:

## Usage Examples
Before/after pattern showing the fix:

**Before (could crash)**:
```python
# If PATH contains a directory the user cannot access (e.g., /root/bin),
# path.resolve() or path.is_dir() raises OSError and get_dll_directories()
# propagates it, preventing library loading entirely.
import tvm_ffi  # -> OSError: [Errno 13] Permission denied: '/root/bin'
```

**After (gracefully skips)**:
```python
# Inaccessible paths are silently skipped; library discovery continues
# with the remaining valid directories.
import tvm_ffi  # succeeds even if PATH contains inaccessible directories
```
