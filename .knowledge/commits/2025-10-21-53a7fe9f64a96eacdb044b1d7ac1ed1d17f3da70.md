# Robustify libinfo get_dll_directories against OSError on inaccessible paths
## TL;DR
- Wraps `path.is_dir()` and `path.resolve()` in `get_dll_directories()` with a try/except `OSError` block, so directories the process cannot access (permission denied, broken symlinks, etc.) are silently skipped instead of crashing the library discovery process.

## Key Exports
None

## Impact
- API: None -- `get_dll_directories()` return type and contract are unchanged.
- Behavioral: Directories that previously caused an `OSError` (e.g., permission-denied paths in `$PATH` or `$LD_LIBRARY_PATH`) are now silently skipped. Previously, any such path would crash library loading at import time.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Packaging / library discovery** ([0013-packaging](../designs/0013-packaging.md)): `get_dll_directories()` is the search path builder consumed by `find_libtvm_ffi()` and `find_library_by_basename()`.
