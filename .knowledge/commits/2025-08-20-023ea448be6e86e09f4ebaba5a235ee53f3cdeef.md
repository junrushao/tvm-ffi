# Relocate env-specific C APIs from c_api.h/function.cc into the extra/ subsystem and rename module-scoped env functions with Mod prefix

## TL;DR
- `TVMFFIEnvCheckSignals` and `TVMFFIEnvRegisterCAPI` moved out of core `c_api.h`/`src/ffi/function.cc` into `include/tvm/ffi/extra/c_env_api.h` and new `src/ffi/extra/env_c_api.cc`; they are now compiled only when `TVM_FFI_USE_EXTRA_CXX_API` is enabled.
- Three module-scoped env functions renamed with a `Mod` infix: `TVMFFIEnvLookupFromImports` → `TVMFFIEnvModLookupFromImports`, `TVMFFIEnvRegisterContextSymbol` → `TVMFFIEnvModRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol` → `TVMFFIEnvModRegisterSystemLibSymbol`.
- `src/ffi/testing.cc` relocated to `src/ffi/extra/testing.cc` and is now also gated behind `TVM_FFI_USE_EXTRA_CXX_API`; `TVMFFIEnvRegisterCAPI` signature changed from `const TVMFFIByteArray*` to `const char*` for the name parameter (breaking ABI change for that function).

## Rename Mapping Table

| Old name | New name | Location change |
|---|---|---|
| `TVMFFIEnvCheckSignals` | `TVMFFIEnvCheckSignals` (unchanged) | `c_api.h` / `function.cc` → `extra/c_env_api.h` / `extra/env_c_api.cc` |
| `TVMFFIEnvRegisterCAPI(const TVMFFIByteArray*, void*)` | `TVMFFIEnvRegisterCAPI(const char*, void*)` | `c_api.h` / `function.cc` → `extra/c_env_api.h` / `extra/env_c_api.cc`; param type changed |
| `TVMFFIEnvLookupFromImports` | `TVMFFIEnvModLookupFromImports` | `extra/module.cc` (declaration in `extra/c_env_api.h`) |
| `TVMFFIEnvRegisterContextSymbol` | `TVMFFIEnvModRegisterContextSymbol` | `extra/library_module.cc` |
| `TVMFFIEnvRegisterSystemLibSymbol` | `TVMFFIEnvModRegisterSystemLibSymbol` | `extra/library_module_system_lib.cc` |
| `src/ffi/testing.cc` | `src/ffi/extra/testing.cc` | File move; now extra-only |

## Impact
- API: **Breaking** — `TVMFFIEnvRegisterCAPI` parameter type changed from `const TVMFFIByteArray*` to `const char*`; callers using the old ByteArray form must update. Three module-env functions renamed (see table). All callers that linked against the old names will get linker errors.
- Behavioral: None — logic is identical; `EnvCAPIRegistry` code was copy-moved verbatim from `function.cc` to `env_c_api.cc`.
- Flags/config: `TVMFFIEnvCheckSignals`, `TVMFFIEnvRegisterCAPI`, and `testing.cc` are now only compiled when `TVM_FFI_USE_EXTRA_CXX_API=ON`.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **0001-c-abi** (`include/tvm/ffi/c_api.h`) — reorganizes section ordering; removes `TVMFFIEnvCheckSignals`/`TVMFFIEnvRegisterCAPI` from core ABI; moves DLPack, dtype, and Object/Function API declarations earlier in file.
- **0004-function-system** (`src/ffi/function.cc`) — `EnvCAPIRegistry` and two env C-API function implementations removed from this file.
- **extra/ subsystem** (`include/tvm/ffi/extra/c_env_api.h`, `src/ffi/extra/module.cc`, etc.) — extended with new env API declarations and implementations.

Design elements this commit produces:
- **`EnvCAPIRegistry` as an extra/ component** — `src/ffi/extra/env_c_api.cc` is now the canonical home of the Python-callback registry. The `Mod`-prefixed rename convention establishes a naming pattern to scope module-domain vs. general-env APIs within `c_env_api.h`.

## Usage Examples

```c
// Before: caller registered Python callbacks via core c_api.h
// TVMFFIEnvRegisterCAPI(bytearray_ptr_for_name, symbol_ptr);

// After: include extra/c_env_api.h; pass plain C string
#include <tvm/ffi/extra/c_env_api.h>
TVMFFIEnvRegisterCAPI("PyErr_CheckSignals", (void*)PyErr_CheckSignals);
TVMFFIEnvRegisterCAPI("PyGILState_Ensure",  (void*)PyGILState_Ensure);
TVMFFIEnvRegisterCAPI("PyGILState_Release", (void*)PyGILState_Release);

// Checking signals from a long-running kernel (unchanged call site):
if (TVMFFIEnvCheckSignals() != 0) {
  // Python signal raised; let FFI bubble up via -1 return
}
```
