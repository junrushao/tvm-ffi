# Relocate env C API functions to extra/ and rename module-specific symbols with Mod prefix
## TL;DR
- Moves `TVMFFIEnvCheckSignals` and `TVMFFIEnvRegisterCAPI` declarations from core `c_api.h` to `extra/c_env_api.h`, and their implementations from `src/ffi/function.cc` to `src/ffi/extra/env_c_api.cc`.
- Renames three module-context C API functions with a `Mod` infix: `TVMFFIEnvLookupFromImports` -> `TVMFFIEnvModLookupFromImports`, `TVMFFIEnvRegisterContextSymbol` -> `TVMFFIEnvModRegisterContextSymbol`, `TVMFFIEnvRegisterSystemLibSymbol` -> `TVMFFIEnvModRegisterSystemLibSymbol`.
- Changes `TVMFFIEnvRegisterCAPI` parameter from `const TVMFFIByteArray*` to `const char*` and reorders sections within `c_api.h` for clarity.

| Old Name | New Name |
|----------|----------|
| `TVMFFIEnvLookupFromImports` | `TVMFFIEnvModLookupFromImports` |
| `TVMFFIEnvRegisterContextSymbol` | `TVMFFIEnvModRegisterContextSymbol` |
| `TVMFFIEnvRegisterSystemLibSymbol` | `TVMFFIEnvModRegisterSystemLibSymbol` |

## Key Exports

**Renames** (in `include/tvm/ffi/extra/c_env_api.h`):
- `TVMFFIEnvModLookupFromImports(TVMFFIObjectHandle library_ctx, const char* func_name, TVMFFIObjectHandle* out) -> int` (was `TVMFFIEnvLookupFromImports`)
- `TVMFFIEnvModRegisterContextSymbol(const char* name, void* symbol) -> int` (was `TVMFFIEnvRegisterContextSymbol`)
- `TVMFFIEnvModRegisterSystemLibSymbol(const char* name, void* symbol) -> int` (was `TVMFFIEnvRegisterSystemLibSymbol`)

**Signature change** (relocated from `c_api.h` to `extra/c_env_api.h`):
- `TVMFFIEnvRegisterCAPI(const char* name, void* symbol) -> int` — parameter changed from `const TVMFFIByteArray*` to `const char*`

**Relocated without change** (from `c_api.h` to `extra/c_env_api.h`):
- `TVMFFIEnvCheckSignals() -> int`

**File relocations**:
- `src/ffi/function.cc` `EnvCAPIRegistry` class + `TVMFFIEnvCheckSignals`/`TVMFFIEnvRegisterCAPI` impl -> `src/ffi/extra/env_c_api.cc`
- `src/ffi/testing.cc` -> `src/ffi/extra/testing.cc`

## Impact
- API: Breaking. Three C API symbols renamed (link-time breakage for direct callers). `TVMFFIEnvRegisterCAPI` signature changed from `const TVMFFIByteArray*` to `const char*`. `TVMFFIEnvCheckSignals` and `TVMFFIEnvRegisterCAPI` removed from `c_api.h` (callers must include `extra/c_env_api.h`).
- Behavioral: None. All implementations are identical; only locations and names changed.
- Flags/config: `TVM_FFI_USE_EXTRA_CXX_API` CMake option now gates `env_c_api.cc` and `testing.cc` in addition to previously gated files.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Extra API isolation pattern** (ADR `0010-extra-api-isolation.md`): Extends the existing core/extra split to cover env C APIs and testing utilities.
- **C ABI layer** (`0001-c-abi-layer.md`): Reorganizes the section ordering within `c_api.h` — basic object API, function calling API, DLPack support, dtype support, then type reflection — without changing the API surface.
- **EnvCAPIRegistry singleton** (`0004-function-system.md` context): The `EnvCAPIRegistry` class (managing Python signal/GIL callbacks) is unchanged in behavior, just relocated to `extra/`.

Design elements this commit produces:
- **Env C API naming convention**: `TVMFFIEnv` prefix for general env functions (`TVMFFIEnvCheckSignals`, `TVMFFIEnvRegisterCAPI`), `TVMFFIEnvMod` prefix for module-context functions (`TVMFFIEnvModLookupFromImports`, `TVMFFIEnvModRegisterContextSymbol`, `TVMFFIEnvModRegisterSystemLibSymbol`).
- **`c_api.h` section ordering**: Sections now follow a logical dependency order: basic object API -> function calling API -> DLPack -> dtype -> type reflection -> registration -> backend noexcept.
