# Reorganize C API: move env/extra APIs out of c_api.h, rename module-scoped env functions
## TL;DR
- Reorders `c_api.h` declarations into logical sections (Basic object API, Function calling, DLPack, dtype, Type reflection) without adding or removing any core APIs. The user-facing "Section: User APIs" is dissolved into topical sections placed earlier in the file.
- Moves two env-specific C APIs (`TVMFFIEnvCheckSignals`, `TVMFFIEnvRegisterCAPI`) from `c_api.h` to `extra/c_env_api.h` and their implementation from `src/ffi/function.cc` to new `src/ffi/extra/env_c_api.cc`.
- Renames three module-scoped env functions to add a `Mod` infix, clarifying they are module-side (callee) APIs.
- Moves `testing.cc` from core `src/ffi/` to `src/ffi/extra/`, now compiled only under `TVM_FFI_USE_EXTRA_CXX_API`.

### Rename mapping

| Old name | New name | File |
|----------|----------|------|
| `TVMFFIEnvLookupFromImports` | `TVMFFIEnvModLookupFromImports` | `extra/c_env_api.h` |
| `TVMFFIEnvRegisterContextSymbol` | `TVMFFIEnvModRegisterContextSymbol` | `extra/c_env_api.h` |
| `TVMFFIEnvRegisterSystemLibSymbol` | `TVMFFIEnvModRegisterSystemLibSymbol` | `extra/c_env_api.h` |

### Signature change

| Function | Old signature | New signature |
|----------|--------------|---------------|
| `TVMFFIEnvRegisterCAPI` | `int TVMFFIEnvRegisterCAPI(const TVMFFIByteArray* name, void* symbol)` | `int TVMFFIEnvRegisterCAPI(const char* name, void* symbol)` |

## Key Exports
**Functions (renamed)**:
- `TVMFFIEnvModLookupFromImports(TVMFFIObjectHandle library_ctx, const char* func_name, TVMFFIObjectHandle* out) -> int` -- lookup a function from a module's imports (callee-side helper for generated code)
- `TVMFFIEnvModRegisterContextSymbol(const char* name, void* symbol) -> int` -- register a symbol for lazy init when a library is loaded
- `TVMFFIEnvModRegisterSystemLibSymbol(const char* name, void* symbol) -> int` -- register a symbol for system library loading

**Functions (moved to `extra/c_env_api.h`)**:
- `TVMFFIEnvCheckSignals() -> int` -- check for signals in the surrounding env (e.g., Python `PyErr_CheckSignals`)
- `TVMFFIEnvRegisterCAPI(const char* name, void* symbol) -> int` -- register env-specific C API callbacks (now takes `const char*` instead of `const TVMFFIByteArray*`)

**Classes (moved)**:
- `tvm::ffi::EnvCAPIRegistry` -- singleton managing Python env callbacks (`PyErr_CheckSignals`, `PyGILState_Ensure/Release`). Moved from `src/ffi/function.cc` to `src/ffi/extra/env_c_api.cc`.

## Impact
- API: Three function renames are ABI-breaking for any code calling the old symbols. The `TVMFFIEnvRegisterCAPI` signature change (from `const TVMFFIByteArray*` to `const char*`) breaks source compatibility for callers using the old signature.
- ABI: Symbol names changed for 3 functions; 2 functions moved out of the core library object into the "extra" object (only available when `TVM_FFI_USE_EXTRA_CXX_API=ON`). `testing.cc` also moved to "extra".
- Behavioral: None. All implementations are unchanged.
- Flags/config: `TVM_FFI_USE_EXTRA_CXX_API` CMake flag now gates `env_c_api.cc` and `testing.cc` compilation.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **C ABI layer** (`.knowledge/designs/c-abi.md`): Reorganizes the section layout of `c_api.h` declarations. The core/extra split is reinforced.
- **Function system** (`.knowledge/designs/function-system.md`): `EnvCAPIRegistry` was previously co-located with `GlobalFunctionTable` in `function.cc`; now separated.
- **Module system**: The `Mod` infix rename clarifies the module-side (callee) role of these env functions, distinguishing them from host-side env APIs.

Design elements this commit produces:
- **Core/Extra C API boundary**: Strengthens the architectural split between core FFI APIs (in `c_api.h`, always compiled) and extra/optional APIs (in `extra/c_env_api.h`, compiled only with `TVM_FFI_USE_EXTRA_CXX_API`). The `TVMFFIEnvCheckSignals` and `TVMFFIEnvRegisterCAPI` functions are now clearly categorized as "extra" APIs.
- **`Mod` infix convention for module-scoped env functions**: `TVMFFIEnvMod*` naming distinguishes callee-side module management APIs from host-side environment APIs (like `TVMFFIEnvCheckSignals`).
- **Topical section ordering in `c_api.h`**: The header now follows a consistent section order: data structures -> Basic object API -> Function calling API -> DLPack -> dtype -> Type reflection -> Function registration -> Type registration -> Backend noexcept functions.

## Usage Examples
None -- this is a refactoring/rename commit. All usage patterns remain the same but with updated symbol names.

For callers of the renamed functions, the migration is mechanical:
```c
// Before
TVMFFIEnvLookupFromImports(ctx, name, &out);
TVMFFIEnvRegisterContextSymbol(name, ptr);
TVMFFIEnvRegisterSystemLibSymbol(name, ptr);

// After
TVMFFIEnvModLookupFromImports(ctx, name, &out);
TVMFFIEnvModRegisterContextSymbol(name, ptr);
TVMFFIEnvModRegisterSystemLibSymbol(name, ptr);
```
