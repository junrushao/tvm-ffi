# Add py_class decorator for Python-defined FFI dataclasses

## TL;DR
- `@py_class` decorator parses class annotations into FFI fields without requiring a C++ type definition.
- `field()` helper matching `dataclasses.field()` API (default, default_factory, init, repr, hash, compare, kw_only).
- Supports `__post_init__`, deferred forward-reference resolution, automatic init-signature reordering, `KW_ONLY` sentinel, and copy-based `__replace__`.

## Key Exports

```python
@py_class(type_key: str, *, init=True, repr=True, eq=False, order=False, unsafe_hash=False)
def decorator(cls: type) -> type:
    """Register Python-defined FFI dataclass."""
    # 1. Parses class annotations -> FFI fields with type schemas
    # 2. Registers type via C API (TVMFFITypeGetOrAllocIndex, TVMFFITypeRegisterField/Metadata/Attr)
    # 3. Registers __ffi_new__ for reflection-based creation
    # 4. Installs __init__ with KWARGS protocol, __post_init__ wiring
    # 5. Installs structural dunders via _install_dataclass_dunders
    # Interacts with: register_object, _install_init, _install_dataclass_dunders, Field
    # Invariant: user-defined dunders never overwritten
    # Extension: field() for per-field control

def field(*, default=MISSING, default_factory=MISSING, init=True, repr=True,
          hash=None, compare=True, kw_only=False) -> Field:
    """Declare a field with dataclass-style control."""

KW_ONLY: object  # Sentinel for kw-only field section
```

- Behavioral: Python-defined types can now participate in FFI (serialization, cross-language calls).

## Usage Examples

```python
from tvm_ffi.dataclasses import py_class, field

@py_class("my.Point", eq=True, unsafe_hash=True)
class Point(Object):
    x: float
    y: float = field(default=0.0)

p = Point(1.0)        # y defaults to 0.0
assert p.x == 1.0
```
