# Add @py_class decorator for Python-defined FFI dataclasses

## TL;DR
- New `python/tvm_ffi/dataclasses/py_class.py` (459 lines): `@py_class` decorator parses class annotations into FFI fields without requiring a C++ `ObjectDef` definition. Supports `field()` helper, `KW_ONLY` sentinel, `__post_init__`, deferred forward-reference resolution, and automatic init-signature reordering.
- Two-phase registration: Phase 1 allocates C type index (enabling circular references); Phase 2 resolves annotations, validates field ordering, registers fields with Cython layer, installs dunders. Failed Phase 2 from `NameError` defers via `_PENDING_CLASSES` with `_flush_pending` retried after each success.
- `field()` updated with full tri-state hash semantics; `KW_ONLY` re-exported for Python 3.10+.

## Impact
- API: New `@py_class` decorator and `field()` helper in `tvm_ffi.dataclasses`. `KW_ONLY` re-exported. `registry.py` wires `__post_init__` into FFI init path.
- Behavioral: Python-only FFI types now support reflection creation, serialization, `DeepCopy`, `StructuralEqual`/`Hash` (inheriting from `Object`). Forward-reference errors trigger deferred registration (no crash).
- Flags/config: `type_key` defaults to `module.ClassName` if not specified.
- Data formats/schemas: none

## Usage Examples

```python
from tvm_ffi.core import Object
from tvm_ffi.dataclasses import py_class, field, KW_ONLY

@py_class("mymod.Point")
class Point(Object):
    x: float
    y: float = field(default=0.0)
    KW_ONLY
    label: str = field(default="", kw_only=True)

    def __post_init__(self):
        assert self.x >= 0

p = Point(x=1.0)        # y=0.0, label=""
p2 = Point(x=2.0, y=3.0, label="A")

# Mutual references:
@py_class("mymod.Node")
class Node(Object):
    value: int
    next: Optional["Node"]   # forward ref resolved after flush

@py_class("mymod.Leaf")     # triggers _flush_pending(), resolves Node
class Leaf(Node):
    pass
```
