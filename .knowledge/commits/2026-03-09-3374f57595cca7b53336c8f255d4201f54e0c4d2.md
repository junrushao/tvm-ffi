# Add py_class decorator for Python-defined FFI dataclasses
## TL;DR
- Introduces `@py_class` decorator in `tvm_ffi.dataclasses` that allows defining FFI-compatible dataclasses entirely in Python, without C++ counterparts.
- Creates `dataclasses/py_class.py` (459 lines) implementing type key registration, field introspection from type annotations, and integration with the reflection system.
- Renames test file to `test_dataclass_py_class.py` and significantly expands test coverage.

## Key Exports

```python
def py_class(type_key: str, parent: type = Object) -> Callable[[type], type]: ...
    # Interacts with: register_object, _install_init, _install_structural_dunders
    # Invariant: all annotated fields become FFI fields with TypeSchema validation
    # Extension: subclass parent to inherit fields

def field(*, default: Any = MISSING, eq: bool = True) -> Field: ...
    # Interacts with: py_class field introspection
    # Extension: default_factory support planned
```

## Impact
- API: New `@py_class` decorator and `field()` function in `tvm_ffi.dataclasses`.
- Behavioral: Enables pure-Python FFI dataclass definition.
- Flags/config: None
- Data formats/schemas: None

## Usage Examples
```python
from tvm_ffi.dataclasses import py_class, field

@py_class("mylib.Point")
class Point:
    x: float
    y: float

p = Point(x=1.0, y=2.0)
assert p.x == 1.0
```
