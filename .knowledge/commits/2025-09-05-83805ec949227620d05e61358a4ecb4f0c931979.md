# Add load_inline for JIT-compiling C++/CUDA source into a tvm_ffi Module from Python

## TL;DR

- Introduces `tvm_ffi.cpp.load_inline()`: compiles inline C++/CUDA source strings to a shared library via Ninja and loads it as a `Module`, with content-hash-based caching in `~/.cache/tvm-ffi`.
- Adds `FileLock` (cross-platform advisory file lock) in the new `tvm_ffi.utils` subpackage; used to serialize concurrent builds of the same cache entry.
- Exports functions from inline source using `TVM_FFI_DLL_EXPORT_TYPED_FUNC`, injected automatically by `_decorate_with_tvm_ffi`.

## Impact

- API: New public function `tvm_ffi.cpp.load_inline(...)` and new module `tvm_ffi.utils.FileLock`. No existing APIs changed.
- Behavioral: None to existing code. New build-time side effect: Ninja subprocess invoked, `.so` cached under `~/.cache/tvm-ffi` (or `TVM_FFI_CACHE_DIR`).
- Flags/config: `TVM_FFI_CACHE_DIR` (overrides default cache directory), `TVM_FFI_CUDA_ARCH_LIST` (space-separated `major.minor` pairs, e.g. `"8.9 9.0a"`), `MAX_JOBS` (parallelism for ninja), `CXX` (C++ compiler override), `CUDA_HOME`/`CUDA_PATH` (CUDA install path).
- Data formats/schemas: Build cache directory layout: `~/.cache/tvm-ffi/<name>_<hash16>/` containing `main.cpp`, optionally `cuda.cu`, `build.ninja`, `lock`, and `<name>.so`.

## Design Elements

- `find_include_path` / `find_dlpack_include_path` from `tvm_ffi.libinfo` — supply default include directories (.knowledge/design-records/0013-python-package.md).

Design elements this commit produces:
- `load_inline` — a new JIT compilation workflow entry point that bridges inline source strings to `Module`. Not yet tracked in any design record.
- `FileLock` — a new cross-platform advisory lock utility in `tvm_ffi.utils`. Not yet tracked.
- `tvm_ffi.utils` and `tvm_ffi.cpp` — two new Python subpackages establishing subpackage conventions for utilities and C++ tooling.

## Usage Examples

**C++ CPU function exported and called from Python (from `tests/python/test_load_inline.py`)**:

```python
import numpy, tvm_ffi.cpp
from tvm_ffi.module import Module

mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""
        void AddOne(DLTensor* x, DLTensor* y) {
            for (int i = 0; i < x->shape[0]; ++i)
                ((float*)y->data)[i] = ((float*)x->data)[i] + 1;
        }
    """,
    cpp_functions={"add_one_cpu": "AddOne"},  # exported_name -> source_name
)
x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)          # DLTensor conversion handled by Module/Function FFI bridge
numpy.testing.assert_equal(x + 1, y)
```

**Cross-layer trace**: Python string → `_decorate_with_tvm_ffi` injects `TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne)` → Ninja compiles to `hello.so` → `load_module("hello.so")` opens via `DSOLibrary` → `mod.add_one_cpu` dispatches through `Module.GetFunction("add_one_cpu")` → packed call convention.
