# Add inline C++/CUDA module compilation and loading via tvm_ffi.cpp.load_inline
## TL;DR
- Introduces `tvm_ffi.cpp.load_inline()`, a Python API that compiles inline C++ and/or CUDA source code into a shared library at runtime and returns a loaded `Module`.
- Adds a new `tvm_ffi.utils` sub-package with a cross-platform `FileLock` for process-safe build caching.
- Includes an end-to-end example (`examples/inline_module/main.py`) and pytest tests for CPU and CUDA paths.

## Key Exports

**Functions**:
```python
def tvm_ffi.cpp.load_inline(
    name: str,
    *,
    cpp_source: str | None = None,
    cuda_source: str | None = None,
    cpp_functions: Mapping[str, str] | None = None,
    cuda_functions: Mapping[str, str] | None = None,
    extra_cflags: Sequence[str] | None = None,
    extra_cuda_cflags: Sequence[str] | None = None,
    extra_ldflags: Sequence[str] | None = None,
    extra_include_paths: Sequence[str] | None = None,
) -> Module
```
Compiles inline C++/CUDA source to a shared library via Ninja, caches results under `$TVM_FFI_CACHE_DIR` (default `~/.cache/tvm-ffi`), and loads the result via `load_module`.

**Classes**:
```python
class tvm_ffi.utils.FileLock:
    def __init__(self, lock_file_path: str): ...
    def acquire(self) -> bool: ...                       # non-blocking, returns success
    def blocking_acquire(self, timeout=None, poll_interval=0.1) -> bool: ...
    def release(self) -> None: ...
    def __enter__(self) -> FileLock: ...                  # calls blocking_acquire()
    def __exit__(self, *args) -> bool: ...               # calls release()
```
Cross-platform advisory file lock using `fcntl.flock` (Unix) / `msvcrt.locking` (Windows).

**Internal helpers** (not public API but load-bearing):
| Function | Description |
|----------|-------------|
| `_hash_sources(...)` | SHA-256 of all sources, flags, and paths; first 16 hex chars used as cache key |
| `_find_cuda_home()` | Probes `CUDA_HOME`/`CUDA_PATH`, `which nvcc`, platform defaults; `@lru_cache` |
| `_get_cuda_target()` | Reads `TVM_FFI_CUDA_ARCH_LIST` or queries `nvidia-smi`; falls back to `sm_70` |
| `_generate_ninja_build(...)` | Emits `build.ninja` content with `compile`/`compile_cuda`/`link` rules |
| `_decorate_with_tvm_ffi(source, functions)` | Prepends FFI headers and appends `TVM_FFI_DLL_EXPORT_TYPED_FUNC` for each exported function |

**Modules/Packages**:
- `python/tvm_ffi/cpp/` -- new sub-package; `__init__.py` re-exports `load_inline`
- `python/tvm_ffi/utils/` -- new sub-package; `__init__.py` re-exports `FileLock`

## Impact
- API: New public API `tvm_ffi.cpp.load_inline()`. No changes to existing APIs.
- Behavioral: none -- purely additive
- Flags/config: New env vars `TVM_FFI_CACHE_DIR` (build cache location), `TVM_FFI_CUDA_ARCH_LIST` (CUDA arch override), `MAX_JOBS` (ninja parallelism)
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): Uses `load_module()` to load the compiled `.so` into a `Module` object. The compiled library exports functions via `TVM_FFI_DLL_EXPORT_TYPED_FUNC`, which produces `__tvm_ffi_<name>` symbols following the `TVMFFISafeCallType` calling convention.
- **Python package** ([0014-python-package.md](../designs/0014-python-package.md)): Uses `find_include_path()` and `find_dlpack_include_path()` from `libinfo.py` to locate headers. Uses `Module` from `tvm_ffi.module`.
- **C env API**: The CUDA example uses `TVMFFIEnvGetCurrentStream` to obtain the current CUDA stream, enabling torch interop.
- **TVM_FFI_DLL_EXPORT_TYPED_FUNC macro** ([0004-function-system.md](../designs/0004-function-system.md)): The `_decorate_with_tvm_ffi` helper appends this macro for each function mapping entry, converting user-defined C++ functions into FFI-exported packed functions.

Design elements this commit produces:
- **Inline module compilation workflow**: A new JIT-like workflow for compiling and loading C++/CUDA code from Python at runtime. Conceptually similar to PyTorch's `torch.utils.cpp_extension.load_inline` but targeting the TVM FFI ABI.
- **Content-addressed build caching**: Source + flags are SHA-256 hashed; builds are stored under `~/.cache/tvm-ffi/<name>_<hash>/`. A `FileLock` prevents concurrent builds of the same module.
- **`tvm_ffi.utils.FileLock`**: A general-purpose cross-platform file lock utility, usable beyond `load_inline`.

## Usage Examples

### Compiling and calling an inline C++ kernel
**Context**: The primary use case -- write C++ source inline in Python, compile, and call.
```python
import numpy
import tvm_ffi.cpp
from tvm_ffi.module import Module

mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""
        void AddOne(DLTensor* x, DLTensor* y) {
          for (int i = 0; i < x->shape[0]; ++i)
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    cpp_functions={"add_one_cpu": "AddOne"},
)
x = numpy.array([1, 2, 3], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)  # y == [2, 3, 4]
```

### Mixed C++ + CUDA with torch interop
**Context**: Both CPU and CUDA functions in one module, using torch tensors.
```python
import torch
import tvm_ffi.cpp

mod = tvm_ffi.cpp.load_inline(
    name="mixed",
    cpp_source=r"""void CpuOp(DLTensor* x, DLTensor* y) { /* ... */ }""",
    cuda_source=r"""void CudaOp(DLTensor* x, DLTensor* y) { /* ... */ }""",
    cpp_functions={"cpu_op": "CpuOp"},
    cuda_functions={"cuda_op": "CudaOp"},
)
mod.cpu_op(torch.randn(8), torch.empty(8))
mod.cuda_op(torch.randn(8, device="cuda"), torch.empty(8, device="cuda"))
```
