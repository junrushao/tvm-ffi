# Add inline C++/CUDA module compilation via tvm_ffi.cpp.load_inline
## TL;DR
- Introduces `tvm_ffi.cpp.load_inline()`, a Python function that JIT-compiles inline C++ and/or CUDA source code into a shared library and loads it as a `tvm_ffi.module.Module`.
- Adds `tvm_ffi.utils.FileLock`, a cross-platform advisory file lock used to serialize concurrent builds of the same module.
- Compiled modules are cached in a content-addressable directory (`~/.cache/tvm-ffi/<name>_<hash>`) keyed by a SHA-256 hash of sources, functions, and flags.

## Key Exports

**Functions**:
- `tvm_ffi.cpp.load_inline(name, *, cpp_source, cuda_source, cpp_functions, cuda_functions, extra_cflags, extra_cuda_cflags, extra_ldflags, extra_include_paths) -> Module` -- JIT-compiles inline C++/CUDA into a shared library and loads it as a Module. All parameters after `name` are keyword-only.

**Classes**:
- `tvm_ffi.utils.FileLock(lock_file_path)` -- Cross-platform advisory file lock. Methods: `acquire() -> bool` (non-blocking), `blocking_acquire(timeout=None, poll_interval=0.1)` (blocking), `release()`. Supports context manager protocol (`with FileLock(path):`).

**Internal helpers** (not public API but structurally significant):
- `_hash_sources(cpp_source, cuda_source, cpp_functions, cuda_functions, extra_cflags, extra_cuda_cflags, extra_ldflags, extra_include_paths) -> str` -- SHA-256 content hash (truncated to 16 hex chars) for build cache keying.
- `_find_cuda_home() -> Optional[str]` -- LRU-cached CUDA installation discovery (env vars -> `which nvcc` -> platform defaults).
- `_get_cuda_target() -> str` -- Determines `-gencode` flags from `TVM_FFI_CUDA_ARCH_LIST` env var or `nvidia-smi` query, falling back to `compute_70`.
- `_generate_ninja_build(...) -> str` -- Generates `build.ninja` content for C++/CUDA compilation and linking.
- `_decorate_with_tvm_ffi(source, functions) -> str` -- Prepends TVM FFI headers and appends `TVM_FFI_DLL_EXPORT_TYPED_FUNC(exported_name, func_name)` for each function mapping.

**Packages**:
- `tvm_ffi.cpp` -- New subpackage for C++ compilation utilities. Exports `load_inline`.
- `tvm_ffi.utils` -- New subpackage for general utilities. Exports `FileLock`.

## Design Elements
Design elements this commit consumes:
- **Module system** (`.knowledge/designs/0013-module-system.md`): `load_module(path)` from `tvm_ffi.module` to load the compiled `.so` as a `Module`. The `Module.__getattr__` pattern enables `mod.add_one_cpu(x, y)` syntax.
- **`TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro** (`.knowledge/designs/function-system.md`): Used by `_decorate_with_tvm_ffi` to generate `extern "C"` export wrappers in the generated source code. This is the bridge between user-written C++ functions and the FFI packed calling convention.
- **TVM FFI headers** (`tvm/ffi/dtype.h`, `tvm/ffi/error.h`, `tvm/ffi/extra/c_env_api.h`, `tvm/ffi/function.h`): Included in generated source code to provide `DLTensor`, `TVM_FFI_ICHECK`, `TVMFFIEnvGetCurrentStream`, etc.
- **`find_include_path()` / `find_dlpack_include_path()`** from `tvm_ffi.libinfo`: Used to locate TVM FFI and DLPack headers for the compiler include path.

Design elements this commit produces:
- **Inline module compilation workflow**: A new pattern for JIT-compiling C++/CUDA source at runtime, bridging the gap between Python scripting and native kernel development. The workflow is: write source -> hash -> check cache -> generate Ninja build -> compile -> `load_module`.
- **Content-addressable build cache**: Build artifacts are stored in `<cache_dir>/<name>_<hash>/` where the hash covers all inputs (source, functions, flags, include paths). This enables safe concurrent use and avoids recompilation when inputs haven't changed.
- **`FileLock` utility**: Cross-platform file locking using `fcntl.flock` (Unix) or `msvcrt.locking` (Windows). Used to serialize concurrent builds targeting the same cache directory.

## Usage Examples

**JIT-compiling a C++ kernel and calling it from Python** (from `examples/inline_module/main.py`):
```python
import tvm_ffi.cpp
from tvm_ffi.module import Module

mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""
        void AddOne(DLTensor* x, DLTensor* y) {
          for (int i = 0; i < x->shape[0]; ++i) {
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
          }
        }
    """,
    cpp_functions={"add_one_cpu": "AddOne"},
)

import numpy
x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)  # Calls via Module.__getattr__ -> GetFunction
```

**Mixed C++/CUDA compilation** (from `examples/inline_module/main.py`):
```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""void AddOne(DLTensor* x, DLTensor* y) { ... }""",
    cuda_source=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) { ... }
        void AddOneCUDA(DLTensor* x, DLTensor* y) {
          cudaStream_t stream = static_cast<cudaStream_t>(
              TVMFFIEnvGetCurrentStream(x->device.device_type, x->device.device_id));
          AddOneKernel<<<nblock, nthread_per_block, 0, stream>>>(...);
        }
    """,
    cpp_functions={"add_one_cpu": "AddOne"},
    cuda_functions={"add_one_cuda": "AddOneCUDA"},
)
```
