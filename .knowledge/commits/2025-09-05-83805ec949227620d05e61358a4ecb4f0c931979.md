# Add load_inline API to compile and load C++/CUDA modules from inline Python source strings

## TL;DR
- Introduces `tvm_ffi.cpp.load_inline(name, cpp_source, cuda_source, cpp_functions, cuda_functions, ...)` — a Python API that compiles inline C++/CUDA source strings into a shared library and returns it as a `tvm_ffi.Module`.
- Adds `python/tvm_ffi/utils/lockfile.py` with a cross-platform `FileLock` (using `fcntl.flock` on Unix, `msvcrt.locking` on Windows) to serialize concurrent compilations into the same cache directory.
- Compilation uses Ninja as the build driver, with deterministic content-hashing of sources/flags for cache-key computation (`~/.cache/tvm-ffi/<name>_<hash16>/`).

## Impact
- API: New `tvm_ffi.cpp.load_inline(...)` function in the `tvm_ffi.cpp` subpackage (no prior callers — additive only).
- Behavioral: None — no existing APIs changed.
- Flags/config: `TVM_FFI_CACHE_DIR` env var sets compilation cache root (default `~/.cache/tvm-ffi`). `TVM_FFI_CUDA_ARCH_LIST` overrides CUDA `gencode` flags (space-separated `major.minor` values). `MAX_JOBS` controls Ninja `-j` parallelism. `CXX` and `CUDA_HOME`/`CUDA_PATH` are standard env overrides.
- Data formats/schemas: Cache directory layout: `<cache_dir>/<name>_<hash16>/` containing `main.cpp`, optionally `cuda.cu`, `build.ninja`, `lock`, and the output `<name>.so`.

## Design Elements
Design elements this commit consumes:
- `Module` / `load_module` (Python) — result of `load_inline` is a `Module` from `tvm_ffi.module`; see [0011-ffi-module-system.md](../design-records/0011-ffi-module-system.md) and [0012-ffi-python-package.md](../design-records/0012-ffi-python-package.md).
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro — used by `_decorate_with_tvm_ffi` to export typed C++ functions as `extern "C"` ABI-safe symbols; see [0013-ffi-packaging-and-distribution.md](../design-records/0013-ffi-packaging-and-distribution.md).
- `TVMFFIEnvGetCurrentStream` / `c_env_api.h` — included in all decorated sources via `_decorate_with_tvm_ffi`, enabling inline CUDA code to use the FFI stream context; see [0011-ffi-module-system.md](../design-records/0011-ffi-module-system.md).
- `find_include_path` / `find_dlpack_include_path` — used to inject default include paths for tvm_ffi and dlpack headers.

Design elements this commit produces:
- **`load_inline` function** — new high-level compilation+loading entrypoint in `python/tvm_ffi/cpp/load_inline.py`, accessible as `tvm_ffi.cpp.load_inline`.
- **`tvm_ffi.cpp` subpackage** — new `python/tvm_ffi/cpp/__init__.py`; establishes `cpp` as the namespace for Python-accessible C++ compilation utilities.
- **`tvm_ffi.utils` subpackage** — new `python/tvm_ffi/utils/__init__.py`; establishes `utils` as the namespace for general-purpose Python utilities within tvm_ffi.
- **`FileLock`** — cross-platform advisory file locking primitive in `python/tvm_ffi/utils/lockfile.py`.
- **Ninja-based build pipeline** — `_generate_ninja_build` + `_build_ninja` pattern for driving C++ shared-library compilation from Python.

## Usage Examples

**`load_inline` — compile and call a CPU C++ function (from `tests/python/test_load_inline.py`)**

```python
import numpy
import tvm_ffi.cpp
from tvm_ffi.module import Module

mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""
        void AddOne(DLTensor* x, DLTensor* y) {
          for (int i = 0; i < x->shape[0]; ++i)
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
        }
    """,
    cpp_functions={"add_one_cpu": "AddOne"},  # exported_name -> C++ symbol
)

x = numpy.array([1, 2, 3, 4, 5], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)          # DLTensor-based calling convention via Module.__getattr__
numpy.testing.assert_equal(x + 1, y)
```

**`load_inline` — CUDA function using `TVMFFIEnvGetCurrentStream` (from `examples/inline_module/main.py`)**

```python
mod = tvm_ffi.cpp.load_inline(
    name="hello",
    cuda_source=r"""
        __global__ void AddOneKernel(float* x, float* y, int n) { ... }
        void AddOneCUDA(DLTensor* x, DLTensor* y) {
            cudaStream_t stream = static_cast<cudaStream_t>(
                TVMFFIEnvGetCurrentStream(x->device.device_type, x->device.device_id));
            AddOneKernel<<<nblock, 256, 0, stream>>>(...);
        }
    """,
    cuda_functions={"add_one_cuda": "AddOneCUDA"},
)
x_cuda = torch.tensor([...], device="cuda")
y_cuda = torch.empty_like(x_cuda)
mod.add_one_cuda(x_cuda, y_cuda)  # stream context automatically set by autodlpack bridge
```
