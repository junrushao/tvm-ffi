# Add load_inline for JIT-compiling C++/CUDA source into TVM FFI modules from Python
## TL;DR
- Introduces `tvm_ffi.cpp.load_inline()`, a Python API that JIT-compiles inline C++ and/or CUDA source code into a TVM FFI `Module`, using Ninja as the build system and SHA-256-based caching to avoid recompilation.
- Adds `tvm_ffi.utils.FileLock`, a cross-platform advisory file lock (fcntl on Unix, msvcrt on Windows) used to serialize concurrent builds of the same inline module.
- New `tvm_ffi.cpp` and `tvm_ffi.utils` subpackages are introduced as organizational homes for these utilities.

## Impact
- API: Adds new public API `tvm_ffi.cpp.load_inline` and `tvm_ffi.utils.FileLock`. No changes to existing APIs.
- Behavioral: none -- purely additive
- Flags/config: New environment variables respected: `TVM_FFI_CACHE_DIR` (cache dir, default `~/.cache/tvm-ffi`), `TVM_FFI_CUDA_ARCH_LIST` (CUDA arch list), `CUDA_HOME`/`CUDA_PATH`, `CXX` (C++ compiler), `MAX_JOBS` (ninja parallelism).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system** (`.knowledge/designs/0011-module-system.md`): `load_module()` and `Module` class are used to load the compiled `.so` and return a `Module` object. The loaded module follows the standard `DSOLibrary` path.
- **Function export macro** (`TVM_FFI_DLL_EXPORT_TYPED_FUNC`): The decorator `_decorate_with_tvm_ffi` appends this macro per exported function, creating the `__tvm_ffi_<name>` symbol convention expected by `LibraryModuleObj`.
- **C ABI headers**: `c_env_api.h` is included in generated source, enabling inline code to call `TVMFFIEnvGetCurrentStream` and other env functions.
- **libinfo.py**: `find_include_path()` and `find_dlpack_include_path()` provide the `-I` flags needed for the TVM FFI headers.

Design elements this commit produces:
- **Inline module compilation pipeline**: A new pattern for JIT-compiling C++/CUDA into TVM FFI modules from Python, analogous to PyTorch's `torch.utils.cpp_extension.load_inline` but targeting the TVM FFI ABI.
- **`tvm_ffi.cpp` subpackage**: New organizational unit for C++ compilation utilities.
- **`tvm_ffi.utils` subpackage**: New organizational unit for general utilities (currently `FileLock`).
- **`FileLock`**: A standalone cross-platform file lock utility.

## Usage Examples

**Compiling and loading inline C++ code (from test):**

```python
import numpy
import tvm_ffi.cpp
from tvm_ffi.module import Module

mod: Module = tvm_ffi.cpp.load_inline(
    name="hello",
    cpp_source=r"""
        void AddOne(DLTensor* x, DLTensor* y) {
          for (int i = 0; i < x->shape[0]; ++i) {
            static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1;
          }
        }
    """,
    cpp_functions={"add_one_cpu": "AddOne"},
)

x = numpy.array([1, 2, 3], dtype=numpy.float32)
y = numpy.empty_like(x)
mod.add_one_cpu(x, y)  # calls through Module.__getattr__ -> DSOLibrary symbol lookup
```

**End-to-end cross-layer trace:**
1. Python `load_inline()` hashes sources, generates `build.ninja`, runs `ninja`
2. Generated `main.cpp` includes TVM FFI headers + user source + `TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne)`
3. Macro expands to `extern "C" int add_one_cpu(void* self, TVMFFIAny* args, ...)` -- the `__tvm_ffi_<name>` symbol
4. `load_module(path)` calls `Module::LoadFromFile` -> `DSOLibrary` -> `dlopen`
5. `mod.add_one_cpu(x, y)` -> `Module.__getattr__` -> `GetFunction("add_one_cpu")` -> symbol lookup -> packed call
