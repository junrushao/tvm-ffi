# Expose recursive compare functions to Python with comprehensive tests (101 cases)

## TL;DR
- Exposes `RecursiveEq`, `RecursiveLt`, `RecursiveLe`, `RecursiveGt`, `RecursiveGe` to Python via `_ffi_api` typed stubs.
- Adds three new testing dataclasses (`TestCompare`, `TestCustomCompare`, `TestEqWithoutHash`) to `tvm_ffi.testing` for comparison testing.
- Adds `test_dataclass_compare.py` with 101 test cases covering primitives, containers, cycles, ordering laws, custom hooks, and CompareOff flag.

## Key Exports

**Python `_ffi_api` stubs:**
- `RecursiveEq(lhs: Any, rhs: Any) -> bool`
- `RecursiveLt(lhs: Any, rhs: Any) -> bool`
- `RecursiveLe(lhs: Any, rhs: Any) -> bool`
- `RecursiveGt(lhs: Any, rhs: Any) -> bool`
- `RecursiveGe(lhs: Any, rhs: Any) -> bool`
- `GetKwargsObject() -> Object` (sentinel)
- `MakeInit(type_key: str) -> Function`

**Testing classes:**
- `TestCompare(v_i64, v_excluded)` -- field-level `compare(false)` opt-out
- `TestCustomCompare(key, payload)` -- custom `__ffi_eq__`/`__ffi_compare__` hooks
- `TestEqWithoutHash(key)` -- eq-only hook, no hash

## Impact
- API: Python-side bindings for existing C++ `ffi.Recursive*` functions (additive only).
- Behavioral: none (test and binding only)
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `RecursiveEq/Lt/Le/Gt/Ge` from `dataclass.h` (produced by 6b39efb)
- Reflection field flags (`CompareOff`, `HashOff`) from `c_api.h`

Design elements this commit produces: none (exposes existing C++ API to Python)

## Usage Examples
```python
from tvm_ffi._ffi_api import RecursiveEq, RecursiveLt
from tvm_ffi.testing import TestIntPair

a = TestIntPair(v_i64=1, v_i32=2)
b = TestIntPair(v_i64=1, v_i32=3)
assert RecursiveEq(a, a)
assert RecursiveLt(a, b)  # field-by-field comparison
```
