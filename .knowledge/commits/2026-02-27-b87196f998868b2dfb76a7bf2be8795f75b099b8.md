# Expose recursive compare to Python with comprehensive tests
## TL;DR
- Exposes five C++ recursive comparison functions (`RecursiveEq`, `RecursiveLt`, `RecursiveLe`, `RecursiveGt`, `RecursiveGe`) to the Python FFI surface via typed stubs in `_ffi_api.py`.
- Adds three new testing dataclasses (`TestCompare`, `TestCustomCompare`, `TestEqWithoutHash`) to `tvm_ffi.testing` for exercising field exclusion, custom hooks, and hash-guard paths.
- Adds comprehensive `test_dataclass_compare.py` (1272 lines, 101 test cases) covering the full recursive comparison contract from Python end-to-end.

## Impact
- **API**: Five new internal `_ffi_api` symbols (`RecursiveEq`, `RecursiveGe`, `RecursiveGt`, `RecursiveLe`, `RecursiveLt`) plus `GetKwargsObject` and `MakeInit` (from upstream stub regeneration). These delegate to the C++ `ffi.Recursive*` global functions already registered on `main`. No public API changes -- these are internal bindings consumed by `@c_class` dunders (introduced in the follow-up commit `e5f3af7`).
- **Testing infrastructure**: `tvm_ffi.testing` gains `TestCompare` (field-level `Compare(false)` opt-out on `ignored_field`), `TestCustomCompare` (custom `__ffi_eq__`/`__ffi_compare__` hooks comparing only `key`), and `TestEqWithoutHash` (equality without hash -- exercises the hash-guard path where ordering falls back to reflection). All three are `@register_object`-decorated with C++ reflection stubs.
- **Flags/config**: None.
- **Data formats/schemas**: None.

## Design Elements

Design elements this commit **consumes**:

- **Dataclass Operations** ([`.knowledge/designs/0027-dataclass-operations.md`](../designs/0027-dataclass-operations.md)): The C++ `RecursiveEq`, `RecursiveLt/Le/Gt/Ge` functions from `src/ffi/extra/dataclass.cc`, which were previously only accessible from C++. This commit creates the Python-side typed stubs so they can be called cross-language.
- **Reflection System** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): The test fixture classes use `Compare(false)` field flag, `__ffi_eq__`/`__ffi_compare__` custom hooks, and `__ffi_shallow_copy__` -- all registered via `ObjectDef` in the C++ reflection layer.
- **Python Bindings** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The `_ffi_api.py` typed stub pattern and `@register_object` decorator for wiring test fixture classes.

Design elements this commit **produces**:

- **Python-accessible recursive comparison**: The five `_ffi_api.Recursive*` bindings enable Python code to invoke C++ recursive structural comparison. This is consumed by the `@c_class` structural dunders in the follow-up commit `e5f3af7`.

## Test Coverage

101 tests in `test_dataclass_compare.py` covering:
- Primitives (int, float, NaN, bool, string, bytes), special values (None ordering, type mismatch)
- Inline types (DataType, Device), containers (Array, List, Map, Dict, Shape)
- Reflected objects (field-by-field, `Compare(false)` exclusion, custom hooks, cross-type, inherited fields)
- Cycle detection (same-pointer identity, distinct cyclic List/Dict, ordering raises ValueError)
- Ordering laws (trichotomy, derived-operator consistency, antisymmetry, transitivity)
- Advanced (CompareOff inside containers, EqWithoutHash hash guard, Function objects, depth-1000 nesting)
