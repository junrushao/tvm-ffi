# Auto-generate __init__ from __ffi_init__ for registered objects, preventing silent chandle=None segfaults
## TL;DR
- Extends `_add_class_attrs` in `python/tvm_ffi/registry.py` to auto-generate `__init__` when not user-defined: if `__ffi_init__` exists, `__init__` forwards to it; otherwise, `__init__` raises `RuntimeError`.
- Removes the now-redundant explicit `__init__` from `TestIntPair` in `python/tvm_ffi/testing.py`, proving auto-generation works.
- Fixes a latent bug where constructing a registered object without `__init__` silently returned `chandle=None`, causing segfaults on field access.

## Key Exports

**Function mutated (`python/tvm_ffi/registry.py :: _add_class_attrs`):**

New behavior after this commit — for each registered object class:
1. If `__ffi_init__` is a reflected method AND `__init__` is NOT in `cls.__dict__`: sets `cls.__init__ = cls.__ffi_init__`
2. If no `__ffi_init__` AND not a `PyNativeObject` subclass AND `__init__` is NOT in `cls.__dict__`: sets `cls.__init__ = __init__invalid`
3. Otherwise: leaves user-defined `__init__` untouched

**New sentinel function:**
```python
def __init__invalid(self, *args, **kwargs) -> None:
    raise RuntimeError("The __init__ method of this class is not implemented.")
```

## Impact
- API: Objects that previously silently returned `chandle=None` when constructed without `__init__` now raise `RuntimeError`. This is an intentional fix — the old behavior caused segfaults.
- Behavioral: Users of `@register_object` no longer need to write boilerplate `def __init__(self, ...): self.__ffi_init__(...)` when the C++ side registers `refl::init<>`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python package / registry** (`0014-python-package.md`): `register_object`, `_add_class_attrs`, `TypeInfo`
- **Reflection system** (`0009-reflection.md`): `__ffi_init__` method convention, `refl::init<>`
- **Python dataclasses** (`0018-python-dataclasses.md`): `__ffi_init__` -> `__c_ffi_init__` renaming, `Object.__ffi_init__` dispatch

Design elements this commit produces (mutation):
- **`_add_class_attrs` contract** — now guarantees every registered class has an `__init__` (either user-defined, auto-forwarded from `__ffi_init__`, or error-raising sentinel). Previously, missing `__init__` resulted in silent `chandle=None`.

## Usage Examples
Before this commit, users had to write:
```python
@register_object("my.IntPair")
class IntPair(Object):
    def __init__(self, a: int, b: int) -> None:
        self.__ffi_init__(a, b)  # boilerplate
```

After this commit:
```python
@register_object("my.IntPair")
class IntPair(Object):
    pass  # __init__ is auto-generated from __ffi_init__

pair = IntPair(1, 2)  # works, auto-forwards to __ffi_init__
```
