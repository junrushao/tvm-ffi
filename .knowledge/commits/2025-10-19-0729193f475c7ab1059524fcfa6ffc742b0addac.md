# Auto-register __init__ from __ffi_init__ when no __init__ is defined on a registered object class

## TL;DR
- `_add_class_attrs` now automatically sets `__init__ = __ffi_init__` on a class when `__ffi_init__` is present and no `__init__` is defined in `type_cls.__dict__`.
- Classes without a C FFI init and not subclassing `PyNativeObject` get an `__init__invalid` stub that raises `RuntimeError`.
- Removed boilerplate `__init__` wrappers from user-facing classes (e.g., `TestIntPair`).

## Key Exports

```python
# In python/tvm_ffi/registry.py

def _add_class_attrs(type_cls: type, type_info: TypeInfo) -> type:
    """Register fields and methods onto the Python class.

    New behavior: if __ffi_init__ is present and __init__ not in type_cls.__dict__,
    sets type_cls.__init__ = type_cls.__ffi_init__.
    If no C init and not PyNativeObject subclass, sets __init__ = __init__invalid.
    """
    # Invariant: called once per registered type during class decoration
    # Interacts with: TypeInfo.methods, TypeInfo.fields, core.PyNativeObject
    ...

def __init__invalid(self: Any, *args: Any, **kwargs: Any) -> None:
    """Sentinel __init__ for classes without a C init."""
    raise RuntimeError("The __init__ method of this class is not implemented.")
    # Interacts with: register_object decorator, _add_class_attrs
```

## Impact
- API: Classes decorated with `@register_object` that expose `__ffi_init__` no longer need to hand-write a `__init__` wrapper. Existing hand-written `__init__` methods are preserved (guarded by `"__init__" not in type_cls.__dict__`).
- Behavioral: `TestIntPair.__init__` removed; `TestIntPair(1, 2)` now routes through the auto-registered `__ffi_init__`. Type checkers may warn (`type: ignore[call-arg]`) because the stubs do not yet reflect this auto-routing.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeInfo.methods` / `_add_class_attrs` pattern (see `.knowledge/design-records/0013-python-package.md`)
- `__ffi_init__` naming convention for C-level constructors (see `.knowledge/design-records/0017-c-class-dataclasses.md`)
- `PyNativeObject` base class (see `.knowledge/design-records/0013-python-package.md`)

Design elements this commit produces:
- **Auto-`__init__` registration convention**: when `__ffi_init__` is present, `__init__` is synthesized. When absent, a `RuntimeError` stub is injected. New convention for `@register_object` classes.

## Usage Examples

Before this commit, every registered object class needed a boilerplate `__init__`:
```python
# BEFORE
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    def __init__(self, a: int, b: int) -> None:
        self.__ffi_init__(a, b)
```

After this commit, the `__init__` is synthesized automatically:
```python
# AFTER
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    pass  # __init__ auto-wired to __ffi_init__

obj = TestIntPair(1, 2)  # works without any __init__ body
```
