# Auto-generate `__init__` from `__ffi_init__` or install error sentinel when missing

## TL;DR
- `_add_class_attrs` in `registry.py` now auto-generates `__init__` for `@register_object` classes: if `__ffi_init__` is available, `__init__` delegates to it; otherwise an error sentinel `__init__invalid` is installed that raises `RuntimeError`.
- Previously, calling `SomeObject(...)` on a class with no `__init__` silently returned an object with `chandle=None`, leading to segfaults on field access. Now it either works (via `__ffi_init__`) or raises immediately.
- `TestIntPair.__init__` removed from `testing.py` since auto-generation handles it; minor `dict()` -> `.copy()` cleanup in `make_fallback_cls_for_type_index`.

## Impact
- API: `@register_object` classes with C++ `__ffi_init__` no longer need manual `__init__` definitions -- the constructor "just works". Classes without `__ffi_init__` now raise `RuntimeError` instead of silently producing broken objects. `PyNativeObject` subclasses are unaffected.
- Behavioral: Calling an uninitialized `@register_object` class changes from silent `chandle=None` (segfault) to an immediate `RuntimeError`. `TestIntPair(1, 2)` still works but now routes through auto-generated `__init__` instead of the hand-written one.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `Object.__ffi_init__` -- the canonical Python method for invoking C++ constructors (design-records/0016-ffi-python-dataclasses.md)
- `__ffi_init__` -> `__c_ffi_init__` rename convention in `_add_class_attrs` (design-records/0016-ffi-python-dataclasses.md)
- `TypeInfo.methods` iteration and `TypeMethod.as_callable` (design-records/0015-ffi-python-type-system.md)
- `make_fallback_cls_for_type_index` auto-proxy creation (design-records/0015-ffi-python-type-system.md)

Design elements this commit produces:
- **Auto-`__init__` generation in `_add_class_attrs`**: new invariant that every `@register_object` class either has a working `__init__` (from user, `@c_class`, or auto-generated via `__ffi_init__`) or an explicit error sentinel. Eliminates the `chandle=None` silent failure class.
- **`__init__invalid` sentinel function**: module-level function in `registry.py` that replaces the implicit no-op `__init__` with an explicit error.

## Usage Examples

Before (silent failure leading to segfault):
```python
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    pass  # No __init__, no __ffi_init__ auto-wiring

obj = TestIntPair(1, 2)  # Silently returns obj with chandle=None
obj.a                     # Segfault
```

After (auto-generated __init__ from __ffi_init__):
```python
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    pass  # __init__ auto-generated from __ffi_init__

obj = TestIntPair(1, 2)  # Works: delegates to __ffi_init__ -> __c_ffi_init__
assert obj.a == 1
assert obj.b == 2
```

After (error sentinel when no __ffi_init__):
```python
@register_object("some.TypeWithoutInit")
class NoInitType(Object):
    pass

NoInitType()  # Raises: RuntimeError("The __init__ method of this class is not implemented.")
```
