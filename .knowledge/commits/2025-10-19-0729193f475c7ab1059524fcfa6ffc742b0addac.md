# Auto-generate `__init__` from `__ffi_init__` in `_add_class_attrs` to prevent silent None-handle objects
## TL;DR
- When `__init__` is not explicitly defined on a `register_object` class and C++ reflection provides `__ffi_init__`, `_add_class_attrs` now auto-generates `__init__` that delegates to `__ffi_init__`, eliminating the need for boilerplate `__init__` methods on simple classes.
- When no `__ffi_init__` exists and the class is not a `PyNativeObject`, `_add_class_attrs` installs a sentinel `__init__` that raises `RuntimeError`, preventing silent construction of objects with `chandle=None` that would segfault on field access.
- Removes the now-redundant manual `__init__` from `TestIntPair` as a demonstration of the auto-generation.

## Key Exports

```python
# === Modified: _add_class_attrs (registry.py) ===
# New behavior at the end of _add_class_attrs:

def _add_class_attrs(type_cls: type, type_info: TypeInfo) -> type:
    """Attach reflected fields/methods and auto-generate __init__ if missing."""
    # ... existing field/method attachment ...
    # NEW: auto-generate __init__ based on __ffi_init__ availability
    if "__init__" not in type_cls.__dict__:
        if has_c_init:  # __ffi_init__ was found in reflected methods
            setattr(type_cls, "__init__", getattr(type_cls, "__ffi_init__"))
            # Invariant: __ffi_init__ is Object base method that dispatches to __c_ffi_init__
        elif not issubclass(type_cls, core.PyNativeObject):
            setattr(type_cls, "__init__", __init__invalid)
            # Invariant: PyNativeObject subclasses (Shape, etc.) use Python builtins for init
    ...

# === New: __init__invalid sentinel (registry.py) ===

def __init__invalid(self: Any, *args: Any, **kwargs: Any) -> None:
    """Sentinel __init__ for classes without a C++ constructor."""
    raise RuntimeError("The __init__ method of this class is not implemented.")
    # Interacts with: _add_class_attrs (sole installer)
    # Invariant: only installed when no __ffi_init__ AND not PyNativeObject

# === Modified: make_fallback_cls_for_type_index (object.pxi) ===
# dict(cls.__dict__) -> cls.__dict__.copy()
# Minor correctness fix: mappingproxy.copy() avoids potential issues with
# dict() constructor on mappingproxy in some Python versions.
```

## Impact
- API: None -- no public API signature changes. Existing classes with explicit `__init__` are unaffected (`"__init__" not in type_cls.__dict__` guard).
- Behavioral: Classes registered via `register_object` that have `__ffi_init__` reflected from C++ but no Python `__init__` now auto-construct correctly instead of silently producing `chandle=None` objects. Classes without `__ffi_init__` now raise `RuntimeError` instead of silently returning broken objects.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `_add_class_attrs` -- the central function that attaches reflected fields/methods to Python classes during `register_object`. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- `Object.__ffi_init__` -- the unified constructor bridge on the Object base class that dispatches to `type(self).__c_ffi_init__`. See [0015-python-dataclasses.md](../designs/0015-python-dataclasses.md).
- `__ffi_init__` -> `__c_ffi_init__` renaming convention in `_add_class_attrs`. See [0015-python-dataclasses.md](../designs/0015-python-dataclasses.md).
- `PyNativeObject` -- mixin for classes that are simultaneously Python builtins and FFI-backed. See [0012-python-bindings.md](../designs/0012-python-bindings.md).

Design elements this commit produces:
- **Auto-`__init__` generation in `_add_class_attrs`**: New invariant that every `register_object` class gets a meaningful `__init__` -- either user-defined, auto-delegated to `__ffi_init__`, or a sentinel that errors. This closes the gap between `@c_class` (which already synthesized `__init__`) and plain `register_object`.
- **`__init__invalid` sentinel function**: Module-level function installed as `__init__` on classes that lack both a user-defined `__init__` and a C++ `__ffi_init__`.

## Usage Examples

Before (silent failure):
```python
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    # No __init__ defined, __ffi_init__ available from C++ reflection
    pass

obj = TestIntPair(1, 2)  # Silently returns obj with chandle=None
obj.a  # SEGFAULT: accessing field on None handle
```

After (auto-delegated):
```python
@register_object("testing.TestIntPair")
class TestIntPair(Object):
    # No __init__ needed -- _add_class_attrs auto-generates one from __ffi_init__
    pass

obj = TestIntPair(1, 2)  # Works: delegates to __ffi_init__ -> __c_ffi_init__
assert obj.a == 1
```

After (sentinel for classes without `__ffi_init__`):
```python
@register_object("some.TypeWithoutInit")
class SomeType(Object):
    pass

SomeType()  # RuntimeError: The __init__ method of this class is not implemented.
```
