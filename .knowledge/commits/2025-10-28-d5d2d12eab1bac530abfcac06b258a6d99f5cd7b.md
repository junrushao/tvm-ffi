# Fix clang-tidy warnings across headers with NOLINT suppressions and a correctness fix

## TL;DR
- `reflection/registry.h`: changed `auto fwrap = [func](const Class target, ...)` to `const Class&` to avoid unnecessary ObjectRef copy in method wrappers — this is a behavioral correctness improvement.
- `base_details.h`: wrapped `StableHashBytes` loop with `NOLINTBEGIN/END(clang-analyzer-security.ArrayBound)`.
- `c_api.h`: wrapped version macros with `NOLINTBEGIN/END(modernize-macro-to-enum)`.
- `container/array.h`, `reflection/access_path.h`: added per-line `NOLINT(performance-unnecessary-value-param)` on template iterator parameters.
- `src/ffi/testing/testing.cc`: added `NOLINTNEXTLINE` for `bugprone-reserved-identifier` and `bugprone-casting-through-void`.

## Key Exports

```python
# C++ (include/tvm/ffi/reflection/registry.h)

# BEFORE:
# auto fwrap = [func](const Class target, Args... params) -> R { ... }
# AFTER:
# auto fwrap = [func](const Class& target, Args... params) -> R { ... }
# Invariant: ObjectRef passed by const-ref avoids spurious ref-count increment
# Interacts with: ObjectDef::def_method, method pointer dispatch
```

## Impact
- API: None — the change is internal to the method wrapper lambda.
- Behavioral: Calling a reflected C++ method no longer increments/decrements the ObjectRef ref-count for the `target` argument. Minor performance improvement for high-frequency reflection calls.
- Flags/config: none
- Data formats/schemas: none
