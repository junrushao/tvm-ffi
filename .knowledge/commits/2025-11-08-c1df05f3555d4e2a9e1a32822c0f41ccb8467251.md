# Streamline number handling with __tvm_ffi_int__ and __tvm_ffi_float__ protocols
## TL;DR
- Introduces `__tvm_ffi_int__` and `__tvm_ffi_float__` custom protocols for number conversion in FFI arg packing
- Moves `numbers.Integral` and `numbers.Real` handling to a more conservative fallback path
- Adds tests for numpy scalar, sympy, and custom number type conversion

## Key Exports
```python
# New duck-type protocols:
# __tvm_ffi_int__(self) -> int   -- custom int conversion for FFI packing
# __tvm_ffi_float__(self) -> float -- custom float conversion for FFI packing
# Interacts with: TVMFFIPyArgSetter dispatch chain (design-record 0012)
# Invariant: checked before numbers.Integral/Real fallback
```

## Impact
- API: New `__tvm_ffi_int__` and `__tvm_ffi_float__` protocols (duck-type)
- Behavioral: `numbers.Integral`/`numbers.Real` now use conservative fallback path instead of direct conversion
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetter` dispatch (design-record 0012)
- `_convert.py` conversion paths

Design elements this commit produces:
- `__tvm_ffi_int__` and `__tvm_ffi_float__` duck-type protocols for custom number types

## Usage Examples
```python
class MyInt:
    def __tvm_ffi_int__(self):
        return 42

f = tvm_ffi.get_global_func("testing.echo")
result = f(MyInt())  # packs as int 42 via __tvm_ffi_int__
```
