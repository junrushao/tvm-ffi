# Add __tvm_ffi_int__/__tvm_ffi_float__ protocols and safer Integral/Real arg setters
## TL;DR
- Introduces two new Python protocols: `__tvm_ffi_int__()` and `__tvm_ffi_float__()` for custom classes to provide integer/float conversion to FFI calls.
- Adds dedicated `TVMFFIPyArgSetterIntegral_` and `TVMFFIPyArgSetterReal_` Cython setters for `numbers.Integral` and `numbers.Real` subclasses (e.g., `np.int32`, `np.float64`), replacing the previous direct reuse of `TVMFFIPyArgSetterInt_`/`TVMFFIPyArgSetterFloat_` which assumed exact `int`/`float` types.
- Renames `TVMFFIPyArgSetterFFIObjectCompatible_` to `TVMFFIPyArgSetterFFIObjectProtocol_` for naming consistency.
- Extends `convert()` to pass through `__tvm_ffi_int__` and `__tvm_ffi_float__` protocol objects.

## Key Exports
**Protocols** (duck-typing, no base class):
- `__tvm_ffi_int__(self) -> int` -- custom classes implement this to be passed as int to FFI
- `__tvm_ffi_float__(self) -> float` -- custom classes implement this to be passed as float to FFI

**Cython internal functions** (dispatch layer):
- `TVMFFIPyArgSetterIntegral_(handle, ctx, py_arg, out) -> int` -- handles `numbers.Integral` subclasses via Cython `<long long>` cast
- `TVMFFIPyArgSetterReal_(handle, ctx, py_arg, out) -> int` -- handles `numbers.Real` subclasses via Cython `<double>` cast
- `TVMFFIPyArgSetterIntProtocol_(handle, ctx, py_arg, out) -> int` -- calls `arg.__tvm_ffi_int__()` and sets `kTVMFFIInt`
- `TVMFFIPyArgSetterFloatProtocol_(handle, ctx, py_arg, out) -> int` -- calls `arg.__tvm_ffi_float__()` and sets `kTVMFFIFloat`

**Renamed**:
- `TVMFFIPyArgSetterFFIObjectCompatible_` -> `TVMFFIPyArgSetterFFIObjectProtocol_`

## Impact
- API: none (protocols are duck-typed, no import needed)
- Behavioral: `np.int32`, `np.float64`, and other `numbers.Integral`/`Real` subclasses now go through dedicated code paths that handle non-exact int/float types correctly via Cython casts. Custom protocol classes are dispatched via `__tvm_ffi_int__`/`__tvm_ffi_float__`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Cython arg setter dispatch factory (`TVMFFIPyArgSetterFactory_`) per `.knowledge/designs/0015-python-ffi-call-dispatch.md`
- `kTVMFFIInt`, `kTVMFFIFloat` type indices per `.knowledge/designs/0002-any-value-system.md`

Design elements this commit produces:
- `__tvm_ffi_int__` protocol -- a new duck-typed protocol for integer conversion, following the pattern of `__cuda_stream__`, `__dlpack_data_type__`, etc.
- `__tvm_ffi_float__` protocol -- a new duck-typed protocol for float conversion
- Separate Integral/Real setter pattern: the insight that `numbers.Integral` subclasses (like `np.int32`) cannot use the fast `PyLong_AsLongLong` C API path and need Cython-mediated casts

## Usage Examples
```python
import tvm_ffi

class IntProtocol:
    def __init__(self, value: int) -> None:
        self.value = value
    def __tvm_ffi_int__(self) -> int:
        return self.value

echo = tvm_ffi.get_global_func("testing.echo")
result = echo(IntProtocol(10))
assert isinstance(result, int) and result == 10

# numpy integer types now work correctly too
import numpy as np
result = echo(np.int32(1))
assert isinstance(result, int) and result == 1
```
