# Add __tvm_ffi_int__/__tvm_ffi_float__ protocols and dedicated Integral/Real setters
## TL;DR
- Introduces two new dunder protocols (`__tvm_ffi_int__`, `__tvm_ffi_float__`) for custom Python classes to provide integer/float values to the FFI call path without subclassing `numbers.Integral`/`numbers.Real`.
- Adds dedicated Cython setters `TVMFFIPyArgSetterIntegral_` and `TVMFFIPyArgSetterReal_` for `numbers.Integral`/`numbers.Real` subclasses (e.g., `np.int32`, `np.float64`), replacing reuse of the plain `TVMFFIPyArgSetterInt_`/`TVMFFIPyArgSetterFloat_` setters that assumed exact `int`/`float` types.
- Renames `TVMFFIPyArgSetterFFIObjectCompatible_` to `TVMFFIPyArgSetterFFIObjectProtocol_` for naming consistency with the new protocol-based setters.

## Impact
- API: **Additive** -- two new dunder protocols (`__tvm_ffi_int__`, `__tvm_ffi_float__`) allow custom classes to be passed as int/float to FFI calls.
- Behavioral: `numbers.Integral`/`numbers.Real` subclasses (e.g., `np.int32`, `np.float64`) now use dedicated setters that perform `<long long>` / `<double>` Cython casts instead of the plain `int`/`float` setters. This is more conservative and correct for non-exact subclasses.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Cached type dispatch** ([ADR 0011](../ADRs/0011-cached-type-dispatch-ffi-call.md)): `TVMFFIPyArgSetterFactory_` factory pattern for adding new per-type setters.
- **Python bindings arg dispatch** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): The `TVMFFIPyArgSetter` callback signature and `TVMFFIPyCallContext` RAII lifecycle.
- **Dunder protocol convention** (established by `__tvm_ffi_object__` in 8873700, `__tvm_ffi_opaque_ptr__` in 42e0612, `__dlpack_data_type__` in 5e648f0, `__dlpack_device__` in 0f8bf9f): Pattern of using `hasattr(arg_class, "__tvm_ffi_*__")` in the factory to detect protocol-bearing types.
- **`convert()` pass-through list** ([0012-python-bindings.md](../designs/0012-python-bindings.md), `_convert.py`): Objects with recognized protocols are returned as-is, not wrapped as opaque.

Design elements this commit produces:
- **`__tvm_ffi_int__` protocol**: Any class implementing `def __tvm_ffi_int__(self) -> int` can be passed to FFI calls as an integer value. Dispatch occurs late in the factory (after all concrete type checks, after `__dlpack_device__`, before `Exception`).
- **`__tvm_ffi_float__` protocol**: Any class implementing `def __tvm_ffi_float__(self) -> float` can be passed to FFI calls as a float value. Same dispatch position as int protocol.
- **Integral/Real setter separation**: Dedicated `TVMFFIPyArgSetterIntegral_` and `TVMFFIPyArgSetterReal_` replace direct reuse of `TVMFFIPyArgSetterInt_`/`TVMFFIPyArgSetterFloat_` for `numbers.Integral`/`numbers.Real` subclasses.

## Usage Examples

**Custom class with `__tvm_ffi_int__` protocol (from test):**
```python
import tvm_ffi

class IntProtocol:
    def __init__(self, value: int) -> None:
        self.value = value
    def __tvm_ffi_int__(self) -> int:
        return self.value

fecho = tvm_ffi.get_global_func("testing.echo")
y = fecho(IntProtocol(10))
assert isinstance(y, int) and y == 10
```

**Custom class with `__tvm_ffi_float__` protocol (from test):**
```python
class FloatProtocol:
    def __init__(self, value: float) -> None:
        self.value = value
    def __tvm_ffi_float__(self) -> float:
        return self.value

y = fecho(FloatProtocol(3.14))
assert isinstance(y, float) and y == 3.14
```

**NumPy scalar types now handled by Integral/Real setters (from test):**
```python
import numpy as np
y = fecho(np.int32(1))    # dispatched via TVMFFIPyArgSetterIntegral_
assert isinstance(y, int) and y == 1

y = fecho(np.float64(2.0))  # dispatched via TVMFFIPyArgSetterReal_
assert isinstance(y, float) and y == 2.0
```
