# Streamline number handling with custom protocols in Cython FFI
## TL;DR
- Introduces two custom protocols (`__tvm_ffi_as_int__`, `__tvm_ffi_as_float__`) for number conversion in the Cython FFI layer.
- Moves `Integral`/`Real` number handling to a more conservative path, avoiding accidental coercion.
- Adds comprehensive tests for number handling edge cases.

## Key Exports

**Protocols (Python):**
- `__tvm_ffi_as_int__` -- Custom protocol for integer conversion; objects implementing this are treated as integers.
- `__tvm_ffi_as_float__` -- Custom protocol for float conversion; objects implementing this are treated as floats.

## Impact
- API: Objects can now implement `__tvm_ffi_as_int__`/`__tvm_ffi_as_float__` for custom number conversion.
- ABI: none
- Behavioral: `numbers.Integral`/`numbers.Real` subclasses now go through a more conservative conversion path.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Cython function argument conversion pipeline (`function.pxi`)
- Python `numbers` ABC hierarchy

Design elements this commit produces:
- `__tvm_ffi_as_int__` / `__tvm_ffi_as_float__` protocols for custom number types.

## Usage Examples
```python
class MyInt:
    def __tvm_ffi_as_int__(self):
        return 42

f = tvm_ffi.get_global_func("testing.echo")
result = f(MyInt())  # passes 42 as int
```
