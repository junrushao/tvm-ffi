# Add ROCm backend support for PyTorch tensor conversion in torch_c_dlpack addon
## TL;DR
- Replaces `torch.cuda.is_available()` device detection with `torch.version.cuda`/`torch.version.hip` checks across the torch C DLPack addon build system, loader, and tests.
- Adds `--build-with-rocm` CLI flag to the addon build script with mutual exclusion against `--build-with-cuda`.
- Adds ROCm-specific C++ include (`c10/hip/HIPStream.h`) and HIP compiler flags in the inline C++ compilation path.

## Key Exports
No new public API types or functions are introduced. The change extends existing internal build/detection logic.

```python
# _build_optional_torch_c_dlpack.py CLI interface (extended):
# --build-with-cuda  (existing)
# --build-with-rocm  (new, mutually exclusive with --build-with-cuda)
# Invariant: cannot enable both --build-with-cuda and --build-with-rocm simultaneously.

# Device detection pattern (replaces torch.cuda.is_available()):
# if torch.version.cuda is not None -> device = "cuda"
# elif torch.version.hip is not None -> device = "rocm"
# else -> device = "cpu"
# Interacts with: build_backend.py, _optional_torch_c_dlpack.py, test scripts
# Extension: add new backend by checking torch.version.<new_backend>

# Library naming convention (extended):
# libtorch_c_dlpack_addon_torch{major}{minor}-{device}{suffix}
# where device in {"cpu", "cuda", "rocm"}  # "rocm" is new
```

## Impact
- API: none -- no public Python/C++ API changed.
- Behavioral: Tensor conversion between TVM FFI and PyTorch now works on ROCm/HIP devices. Previously, ROCm devices would fall through to the "cpu" path or fail.
- Flags/config: New `--build-with-rocm` CLI flag for the addon build script. `BUILD_WITH_ROCM` C preprocessor define added for conditional HIP stream includes.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- DLPack exchange protocol (`__c_dlpack_exchange_api__`) -- see `.knowledge/design-records/0012-ffi-python-package.md`. The torch C DLPack addon is the primary consumer of this protocol for torch.Tensor conversion.
- torch_c_dlpack addon build system -- the `_build_optional_torch_c_dlpack.py` script that JIT-compiles a C++ extension for fast DLPack conversion. See `.knowledge/design-records/0012-ffi-python-package.md`.
- Device detection pattern -- the convention of naming compiled addon libraries by `{torch_version}-{device}` to cache per-backend builds.

Design elements this commit produces:
- None. This is a purely additive backend extension that follows existing patterns.

## Usage Examples
ROCm tensor round-trip test from `tests/python/test_tensor.py`:

```python
# Requires PyTorch built with ROCm (torch.version.hip is not None)
import tvm_ffi

@tvm_ffi.register_global_func("testing.check_device", override=True)
def _check_device(x: tvm_ffi.Tensor) -> str:
    return x.device.type

# PyTorch uses device name "cuda" for ROCm devices
x = torch.randn(128, device="cuda")
device_type = tvm_ffi.get_global_func("testing.check_device")(x)
assert device_type == "rocm"  # TVM FFI correctly identifies as "rocm"
```
