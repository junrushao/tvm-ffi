# Add ROCm backend support for torch C DLPack tensor conversion
## TL;DR
- Extends the torch C DLPack addon build pipeline and device detection from CUDA-only to CUDA+ROCm, using `torch.version.hip` for compile-time backend detection.
- Adds `--build-with-rocm` CLI flag to the build script, with mutual exclusion against `--build-with-cuda`.
- Changes device detection from runtime `torch.cuda.is_available()` to compile-time `torch.version.cuda`/`torch.version.hip` across build backend, loader, test, and benchmark.

## Key Exports
No new public API. Internal build infrastructure extended with ROCm device variant.

```python
# CLI flag addition (python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py)
# New: --build-with-rocm (action="store_true")
# Invariant: --build-with-cuda and --build-with-rocm are mutually exclusive (ValueError)

# Device detection pattern (applied in 4 files):
# Before: device = "cpu" if not torch.cuda.is_available() else "cuda"
# After:
#   if torch.version.cuda is not None: device = "cuda"
#   elif torch.version.hip is not None: device = "rocm"
#   else: device = "cpu"
# Interacts with: library naming convention libtorch_c_dlpack_addon_torch{M}{m}-{device}.{so|dll}
# Invariant: device in {"cpu", "cuda", "rocm"}

# Library naming convention (extended):
# Before: libtorch_c_dlpack_addon_torch{M}{m}-{cpu|cuda}.{so|dll}
# After:  libtorch_c_dlpack_addon_torch{M}{m}-{cpu|cuda|rocm}.{so|dll}

# Build flags for ROCm (python/tvm_ffi/utils/_build_optional_torch_c_dlpack.py):
# cflags.extend(torch.utils.cpp_extension.COMMON_HIP_FLAGS)
# cflags.append("-DBUILD_WITH_ROCM")
# Interacts with: #ifdef BUILD_WITH_ROCM in inline C++ source -> #include <c10/hip/HIPStream.h>

# Benchmark HIP stream support (tests/scripts/benchmark_dlpack.py):
# When torch.version.hip is not None, uses at::hip::HIPStream / at::hip::getCurrentHIPStream
# instead of at::cuda::CUDAStream / at::cuda::getCurrentCUDAStream
```

## Impact
- API: New `--build-with-rocm` internal CLI flag. No public Python API change.
- Behavioral: Device detection switched from runtime (`torch.cuda.is_available()`) to compile-time (`torch.version.cuda`/`torch.version.hip`). On CUDA-compiled PyTorch without a GPU present, the library name now uses `"cuda"` instead of `"cpu"`. On ROCm PyTorch, tensors on `"cuda"` device (PyTorch naming) map to TVM FFI `"rocm"` device type.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
From the test added in this commit (`tests/python/test_tensor.py`):
```python
import torch
import tvm_ffi

@tvm_ffi.register_global_func("testing.check_device", override=True)
def _check_device(x: tvm_ffi.Tensor) -> str:
    return x.device.type

# On ROCm PyTorch, "cuda" device is the ROCm GPU
x = torch.randn(128, device="cuda")
device_type = tvm_ffi.get_global_func("testing.check_device")(x)
assert device_type == "rocm"  # PyTorch "cuda" -> TVM FFI "rocm"
```
