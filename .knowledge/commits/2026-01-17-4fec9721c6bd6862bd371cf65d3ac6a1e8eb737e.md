# Guard newer PyTorch dtypes (uint16/32/64, float8, float4) with hasattr checks for older PyTorch compat

## TL;DR
- Moves `torch.uint16`, `torch.uint32`, `torch.uint64`, `torch.float8_*`, `torch.float4_*` dtype registrations from unconditional dict entries to `hasattr`-guarded dynamic insertions.
- Enables `import tvm_ffi` to succeed with PyTorch 1.10+/1.14+/2.0 (verified by author) without `AttributeError`.
- Single file change: `python/tvm_ffi/cython/dtype.pxi`.

## Key Exports

None — bugfix/compat change, no new public API.

## Impact
- API: none
- Behavioral: `TORCH_DTYPE_TO_DL_DATA_TYPE` no longer raises `AttributeError` at module load time on PyTorch versions lacking newer dtype constants. Missing dtypes are simply omitted from the map.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `0027-dtype-trait`: `TORCH_DTYPE_TO_DL_DATA_TYPE` — the Cython dict mapping PyTorch dtypes to `DLDataType`; this commit makes the registration of newer dtypes conditional on availability.

Design elements this commit produces: None — bugfix only.

## Usage Examples

Before (fails on PyTorch < 2.0 that lacks uint16/float8):
```python
TORCH_DTYPE_TO_DL_DATA_TYPE = {
    ...
    torch.uint16: DLDataType(1, 16, 1),  # AttributeError on old PyTorch
    torch.float8_e4m3fn: DLDataType(10, 8, 1),  # AttributeError on old PyTorch
    ...
}
```

After (safe on all PyTorch versions >= 1.10):
```python
extra_types = [
    ("uint16", DLDataType(1, 16, 1)),
    ("float8_e4m3fn", DLDataType(10, 8, 1)),
    ...
]
for attr_name, dl_dtype in extra_types:
    if hasattr(torch, attr_name):
        TORCH_DTYPE_TO_DL_DATA_TYPE[getattr(torch, attr_name)] = dl_dtype
```
