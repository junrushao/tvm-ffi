# Add enum TypeTraits and relax reflection field pointer to accept base-class members
## TL;DR
- Adds a `TypeTraits<IntEnum>` specialization so C++ `enum class` types with integral underlying types can be stored in / extracted from `Any`/`AnyView`, treating them as `kTVMFFIInt` POD values.
- Relaxes `ObjectDef::def_ro`, `def_rw`, and `RegisterField` to accept pointer-to-members declared in a base class (`T BaseClass::*`) rather than requiring `T Class::*`, with a `static_assert(std::is_base_of_v<BaseClass, Class>)` guard.
- Adds a GoogleTest (`TEST(Any, Enum)`) exercising round-trip `AnyView` construction, type-index check, and `cast<ENum>()` for the new enum trait.
## Impact
- API: New implicit conversion path for all `enum class` types with integral underlying type. Any call site that passes an enum to a function expecting `Any`/`AnyView` now compiles without manual `static_cast`. Downstream callers of `def_ro`/`def_rw` that register inherited fields (e.g., `VisitAttrs` migration in tir/ir_builder/meta_schedule per the commit message) no longer need to cast field pointers.
- Flags/config: none
- Data formats/schemas: Enums are stored as `kTVMFFIInt` with no new type index; no ABI change.
## Design Elements
Design elements this commit consumes:
- **TypeTraits protocol** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): The new `TypeTraits<IntEnum>` follows the exact same protocol (`CopyToAnyView`, `MoveToAny`, `CheckAnyStrict`, `CopyFromAnyViewAfterCheck`, `MoveFromAnyAfterCheck`, `TryCastFromAnyView`, `TypeStr`) established for integers, bools, and floats. It reuses `kTVMFFIInt` storage, keeping the type-index partition unchanged.
- **Reflection field registration** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `RegisterField` invokes `GetFieldByteOffsetToObject<Class, T>(field_ptr)` to compute the byte offset from `Object*`. The change leverages C++ implicit pointer-to-member covariance: `T BaseClass::*` converts to `T Class::*` at the call site, so the offset calculation remains correct (relative to `Class`, not `BaseClass`).
- **SFINAE-based TypeTraits dispatch** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): The enum specialization uses `std::enable_if_t<std::is_enum_v<IntEnum> && std::is_integral_v<std::underlying_type_t<IntEnum>>>` to be mutually exclusive with the integral specialization (`std::is_integral_v<Int>` is false for enum types). No SFINAE ambiguity arises because `std::is_integral_v` returns false for enum types in C++17.

Design elements this commit produces:
- **Enum-to-Int TypeTraits specialization** (`include/tvm/ffi/type_traits.h:277-318`): A new TypeTraits specialization that maps C++ `enum class` (with integral underlying type) to `kTVMFFIInt`. Key invariants: `CheckAnyStrict` matches on `kTVMFFIInt` only (consistent with `MoveToAny`); `TryCastFromAnyView` accepts both `kTVMFFIInt` and `kTVMFFIBool` (lenient, same as integer TypeTraits). This enables enums to participate transparently in packed function calls and container storage.
- **Base-class field pointer support in reflection** (`include/tvm/ffi/reflection/reflection.h:165,184,242`): `def_ro`, `def_rw`, and `RegisterField` now accept `T BaseClass::*field_ptr` where `BaseClass` is any ancestor of `Class`. The `static_assert(std::is_base_of_v<BaseClass, Class>)` at line 245 enforces the inheritance relationship at compile time. This is essential for the VisitAttrs migration where `ObjectDef<DerivedObj>` needs to register fields inherited from `ParentObj`.
