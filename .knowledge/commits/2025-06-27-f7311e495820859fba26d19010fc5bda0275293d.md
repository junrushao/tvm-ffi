# [REFACTOR] Transition VisitAttrs to new reflection mechanism in tir/ir_builder/meta_schedule (#18096)

## TL;DR
- Adds a new `TypeTraits` specialization for C++ `enum class` types with integral underlying types, enabling enums to be transparently stored/retrieved in `Any`/`AnyView` as integers.
- Generalizes `ObjectDef::def_ro`, `def_rw`, and `RegisterField` to accept member pointers to fields declared in base classes (not just the `Class` itself), with a `static_assert` enforcing the inheritance relationship.
- Adds a GoogleTest case (`TEST(Any, Enum)`) validating round-trip conversion of `enum class` values through `AnyView`.

## Key Exports

### New `TypeTraits<IntEnum>` specialization (`include/tvm/ffi/type_traits.h`)

A partial specialization enabled when `std::is_enum_v<IntEnum> && std::is_integral_v<std::underlying_type_t<IntEnum>>`:

- `field_static_type_index = TypeIndex::kTVMFFIInt` -- Enums map to the integer type index.
- `CopyToAnyView` / `MoveToAny` -- Stores the enum value as `v_int64` with `type_index = kTVMFFIInt`.
- `CheckAnyStrict` -- Returns true when `type_index == kTVMFFIInt`.
- `CopyFromAnyViewAfterCheck` / `MoveFromAnyAfterCheck` -- Casts `v_int64` back to the enum type.
- `TryCastFromAnyView` -- Accepts both `kTVMFFIInt` and `kTVMFFIBool` sources (matching the integer TypeTraits convention).
- `TypeStr()` -- Returns `"int"`.

This follows the same pattern as the existing integral `TypeTraits<Int>`, mapping the enum to its integer representation. The specialization is guarded by `std::is_enum_v` so it does not conflict with the `std::is_integral_v` specialization for plain integers.

### Generalized reflection field registration (`include/tvm/ffi/reflection/reflection.h`)

**Before:** `def_ro`, `def_rw`, and `RegisterField` required a pointer-to-member of exactly the `Class` type being defined:
```cpp
template <typename T, typename... Extra>
ObjectDef& def_ro(const char* name, T Class::*field_ptr, Extra&&... extra);
```

**After:** They accept a pointer-to-member of any `BaseClass` that `Class` inherits from:
```cpp
template <typename T, typename BaseClass, typename... Extra>
ObjectDef& def_ro(const char* name, T BaseClass::*field_ptr, Extra&&... extra);
```

A `static_assert(std::is_base_of_v<BaseClass, Class>)` enforces the relationship at compile time. This enables registering inherited fields directly (e.g., `&ParentObj::some_field` when defining reflection for `ChildObj`) without needing to redeclare or alias them.

## Impact
- API: `TypeTraits` now covers enum types automatically. Downstream code can pass `enum class` values directly to `AnyView`/`Any` and use `.cast<MyEnum>()` without manual conversion. The reflection `def_ro`/`def_rw` API is backward-compatible (existing code where `BaseClass == Class` continues to compile with the same template deduction).
- ABI: None. Enum values are stored as `kTVMFFIInt` in `TVMFFIAny`, which is the same wire representation as plain integers. No new C ABI symbols.
- Behavioral: Enums now round-trip through `Any`/`AnyView` as integers. `TryCastFromAnyView` accepts both `kTVMFFIInt` and `kTVMFFIBool` sources, matching the existing integer conversion semantics.

## Design Elements
Design elements this commit consumes:
- `TypeTraits` protocol (from root commit) -- The new enum specialization implements the full trait interface (`CopyToAnyView`, `MoveToAny`, `CheckAnyStrict`, `CopyFromAnyViewAfterCheck`, `MoveFromAnyAfterCheck`, `TryCastFromAnyView`, `TypeStr`).
- `TypeIndex::kTVMFFIInt` -- Enums reuse the integer type index, not a new one.
- `ObjectDef<Class>` reflection builder -- The generalized template parameter is a refinement of the existing reflection registration mechanism.
- C++17 `std::is_enum_v`, `std::underlying_type_t`, `std::is_base_of_v` type traits.

Design elements this commit produces:
- **Enum-to-integer mapping convention** -- All C++ `enum class` types with integral underlying types are automatically representable as `kTVMFFIInt` in the FFI layer. This sets the convention that enums do not get distinct type indices; they are integers at the ABI level.
- **Base-class field registration pattern** -- Reflection definitions can now reference inherited member pointers directly, enabling composition of reflection across class hierarchies without repeating field declarations at each level.
