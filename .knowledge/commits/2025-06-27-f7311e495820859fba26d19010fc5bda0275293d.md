# Generalize reflection def_ro/def_rw to accept inherited fields and add enum TypeTraits

## TL;DR
- Generalizes `ObjectDef::def_ro`, `def_rw`, and `RegisterField` to accept member pointers from base classes (`T BaseClass::*` instead of `T Class::*`), with a `static_assert(is_base_of_v<BaseClass, Class>)` guard.
- Adds a new `TypeTraits<IntEnum>` specialization for C++ enum types with integral underlying types, enabling enums to be stored/extracted through `Any`/`AnyView` as `kTVMFFIInt`.
- Adds a `TEST(Any, Enum)` test covering enum round-trip through `AnyView`.

## Key Exports

```python
# --- Mutated: ObjectDef<Class>::def_ro / def_rw / RegisterField ---
# Previously accepted only T Class::* (direct member pointers).
# Now accepts T BaseClass::* where BaseClass is any ancestor of Class.

class ObjectDef(Generic[Class]):
    # Old signature: def def_ro(name: str, field_ptr: MemberPointer[Class, T], *extra) -> ObjectDef
    # New signature:
    def def_ro(self, name: str, field_ptr: MemberPointer[BaseClass, T], *extra) -> ObjectDef:
        """Register a read-only field, including fields inherited from base classes."""
        # Invariant: static_assert(is_base_of_v<BaseClass, Class>)
        self.RegisterField(name, field_ptr, readonly=True)
        return self

    # Old signature: def def_rw(name: str, field_ptr: MemberPointer[Class, T], *extra) -> ObjectDef
    # New signature:
    def def_rw(self, name: str, field_ptr: MemberPointer[BaseClass, T], *extra) -> ObjectDef:
        """Register a read-write field, including fields inherited from base classes."""
        # Invariant: static_assert(is_base_of_v<BaseClass, Class>)
        # Invariant: Class._type_mutable must be true
        self.RegisterField(name, field_ptr, readonly=False)
        return self

    def RegisterField(self, name: str, field_ptr: MemberPointer[BaseClass, T], writable: bool, *extra):
        """Internal: compute byte offset and register getter/setter."""
        # Invariant: static_assert(is_base_of_v<BaseClass, Class>)
        # Interacts with: GetFieldByteOffsetToObject, TVMFFIRegisterTypeField
        # Extension: BaseClass parameter enables registering parent fields in child type reflection

# --- Produced: TypeTraits<IntEnum> specialization ---
class TypeTraits_IntEnum(Generic[IntEnum]):
    """TypeTraits specialization for C++ enum types with integral underlying type."""
    # Enabled when: is_enum_v<IntEnum> and is_integral_v<underlying_type_t<IntEnum>>
    field_static_type_index: int = TypeIndex.kTVMFFIInt

    @staticmethod
    def CopyToAnyView(src: IntEnum, result: TVMFFIAny) -> None:
        result.type_index = TypeIndex.kTVMFFIInt
        result.v_int64 = int(src)

    @staticmethod
    def MoveToAny(src: IntEnum, result: TVMFFIAny) -> None:
        # POD: same as CopyToAnyView
        ...

    @staticmethod
    def CheckAnyStrict(src: TVMFFIAny) -> bool:
        return src.type_index == TypeIndex.kTVMFFIInt
        # Invariant: strict -- only matches kTVMFFIInt, not kTVMFFIBool

    @staticmethod
    def TryCastFromAnyView(src: TVMFFIAny) -> Optional[IntEnum]:
        if src.type_index in (TypeIndex.kTVMFFIInt, TypeIndex.kTVMFFIBool):
            return IntEnum(src.v_int64)
        return None
        # Extension: allows implicit bool->enum conversion on extraction (lenient)

    @staticmethod
    def TypeStr() -> str:
        return "int"
    # Interacts with: AnyView implicit constructor, Any.cast<IntEnum>(), container storage
```

## Impact
- API: `def_ro`/`def_rw` template signature changed from `T Class::*` to `T BaseClass::*`. Existing callers passing `&Class::field` are unaffected (template deduction picks `BaseClass=Class`). Callers can now pass `&ParentClass::field` where previously they could not.
- Behavioral: Enum types can now participate in `Any`/`AnyView` conversions. Previously, passing a C++ enum to `AnyView` would fail at compile time.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeTraits<T>` protocol (0002-ffi-any-value-system) -- new enum specialization follows the existing 8-method protocol
- `ObjectDef<Class>` reflection builder (0007-ffi-reflection) -- mutated to accept base-class member pointers
- `TypeIndex::kTVMFFIInt` (0001-ffi-c-abi) -- enums reuse the integer type index

Design elements this commit produces:
- `TypeTraits<IntEnum>` specialization -- enables all C++ enum types with integral underlying type to participate in FFI value system
- Inherited-field reflection pattern -- `def_ro`/`def_rw` now accept `T BaseClass::*` with `is_base_of_v` guard, enabling child types to register parent fields without casting

## Usage Examples

Enum round-trip through AnyView (from the test added in this commit):
```cpp
enum class ENum : int { A = 1, B = 2 };

// Store enum in AnyView (implicit conversion via TypeTraits<IntEnum>)
AnyView view = ENum::A;
assert(view.CopyToTVMFFIAny().type_index == TypeIndex::kTVMFFIInt);
assert(view.CopyToTVMFFIAny().v_int64 == 1);

// Extract enum back
ENum v = view.cast<ENum>();
assert(v == ENum::A);
```

Registering inherited fields (motivating use case for the reflection change):
```cpp
class BaseObj : public Object {
 public:
  int64_t base_field;
};
class DerivedObj : public BaseObj {
 public:
  String extra;
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(DerivedObj, BaseObj);
};

// Before this commit: &BaseObj::base_field would fail (T Class::* requires Class=DerivedObj)
// After this commit: works because T BaseClass::* with is_base_of_v<BaseObj, DerivedObj>
ObjectDef<DerivedObj>(type_index)
    .def_ro("base_field", &BaseObj::base_field)   // inherited field
    .def_ro("extra", &DerivedObj::extra);          // own field
```
