# Add enum TypeTraits specialization and generalize reflection to accept base-class member pointers
## TL;DR
- Adds a generic `TypeTraits<IntEnum>` specialization (SFINAE on `std::is_enum_v`) so all C++ enum classes with integral underlying types automatically participate in the Any/AnyView value system without per-enum boilerplate.
- Generalizes `ObjectDef::def_ro`, `def_rw`, and `RegisterField` to accept member pointers to base classes (`T BaseClass::*`) instead of only the exact `Class`, with a `static_assert(std::is_base_of_v<BaseClass, Class>)` guard. This enables reflection registration of inherited fields.
- Adds a C++ test (`TEST(Any, Enum)`) validating enum round-trip through AnyView.

> **Diff-message discrepancy**: The commit message references "tir/ir_builder/meta_schedule" transitions, but the actual diff only contains FFI core changes (`type_traits.h`, `reflection.h`, `test_any.cc`). Analysis is scoped to the actual diff.

# Previously each enum required a manual TypeTraits<MyEnum> specialization (see 0005 usage example).
# Now any `enum class Foo : int { ... }` works automatically.
class TypeTraits[IntEnum]:
    """Auto-specialization for C++ enum classes with integral underlying types."""

    @staticmethod
    def CopyToAnyView(src: IntEnum, result: TVMFFIAny_ptr) -> None:
        """Store as kTVMFFIInt with int64 cast."""
        # result.type_index = kTVMFFIInt; result.v_int64 = int64(src)

    @staticmethod
    def CheckAnyStrict(src: TVMFFIAny_ptr) -> bool:
        """Strict: requires kTVMFFIInt."""
        # Invariant: consistent with MoveToAny (stores as kTVMFFIInt)

    @staticmethod
    def TryCastFromAnyView(src: TVMFFIAny_ptr) -> Optional[IntEnum]:
        """Permissive: accepts kTVMFFIInt or kTVMFFIBool."""
        # Interacts with: AnyView.cast<IntEnum>(), AnyView.as<IntEnum>()

    @staticmethod
    def TypeStr() -> str:
        return StaticTypeKey.kTVMFFIInt
    # Interacts with: Any/AnyView constructors, Function::FromUnpacked argument conversion
    # Extension: covers all enum classes automatically; no per-enum specialization needed

# CHANGED: ObjectDef reflection methods now accept base-class member pointers
class ObjectDef[Class]:
    # OLD: def def_ro(name: str, field_ptr: MemberPointer[Class, T]) -> ObjectDef
    # NEW: def def_ro(name: str, field_ptr: MemberPointer[BaseClass, T]) -> ObjectDef
    #      where static_assert(is_base_of_v<BaseClass, Class>)
    def def_ro(self, name: str, field_ptr: "MemberPointer[BaseClass, T]") -> "ObjectDef[Class]": ...
        # Invariant: BaseClass must be a base class of Class

    # OLD: def def_rw(name: str, field_ptr: MemberPointer[Class, T]) -> ObjectDef
    # NEW: def def_rw(name: str, field_ptr: MemberPointer[BaseClass, T]) -> ObjectDef
    def def_rw(self, name: str, field_ptr: "MemberPointer[BaseClass, T]") -> "ObjectDef[Class]": ...
        # Invariant: BaseClass must be a base class of Class
        # Invariant: Class._type_mutable must be true

    # PRIVATE CHANGED:
    # OLD: def RegisterField(name, field_ptr: MemberPointer[Class, T], ...)
    # NEW: def RegisterField(name, field_ptr: MemberPointer[BaseClass, T], ...)
    #      + static_assert(is_base_of_v<BaseClass, Class>)
    # Interacts with: TVMFFIRegisterTypeField, GetFieldByteOffsetToObject

## Impact
- API: Template signature change for `def_ro`/`def_rw`/`RegisterField` from `T Class::*` to `T BaseClass::*`. Existing callers passing `&Class::field` are unaffected (BaseClass deduced as Class). Callers passing `&ParentClass::field` now work where they previously failed to compile.
- Behavioral: Enum types can now be stored in `Any`/`AnyView` and passed through FFI without manual `TypeTraits` specializations. `TryCastFromAnyView` for enums accepts both `kTVMFFIInt` and `kTVMFFIBool` (more permissive than the `CheckAnyStrict` which only accepts `kTVMFFIInt`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Any/AnyView value system** (0001) -- enum values are stored as `kTVMFFIInt` in the Any tagged union
- **TypeTraits protocol** (0005) -- follows the 8-method pattern; uses `TypeTraitsBase`, `TypeIndex::kTVMFFIInt`, `StaticTypeKey::kTVMFFIInt`
- **Reflection system** (0008) -- `ObjectDef`, `RegisterField`, `TVMFFIFieldInfo`

Design elements this commit produces:
- **Generic enum TypeTraits** -- SFINAE specialization covering all `enum class` types with integral underlying type. Eliminates per-enum boilerplate. Note: uses `CheckAnyStrict`/`TryCastFromAnyView` method names (not `CheckAnyStorage`/`TryConvertFromAnyView` from the original protocol), indicating the API surface has evolved.
- **Base-class member pointer support in reflection** -- `def_ro`/`def_rw` now accept `T BaseClass::*field_ptr` with `static_assert(is_base_of_v<BaseClass, Class>)`. Enables registering inherited fields directly.

## Usage Examples

From the test added in this commit (`tests/cpp/test_any.cc`):
```cpp
enum class ENum : int { A = 1, B = 2 };

// Enum -> AnyView (automatic, no TypeTraits specialization needed)
AnyView view1 = ENum::A;
// Stored as kTVMFFIInt
assert(view1.CopyToTVMFFIAny().type_index == TypeIndex::kTVMFFIInt);
assert(view1.CopyToTVMFFIAny().v_int64 == 1);

// AnyView -> Enum (via cast)
ENum v1 = view1.cast<ENum>();
assert(v1 == ENum::A);

// Optional extraction returns nullopt for empty AnyView
AnyView empty_view;
Optional<ENum> opt = empty_view.as<ENum>();
assert(!opt.has_value());
```

Base-class member pointer usage (pseudocode, no test in commit):
```cpp
class ParentObj : public Object {
 public:
  String shared_name;  // field defined in parent
};
class ChildObj : public ParentObj { ... };

// Previously failed to compile; now works:
TVM_FFI_REFLECTION_DEF(ChildObj)
  .def_ro("shared_name", &ParentObj::shared_name);  // BaseClass=ParentObj, Class=ChildObj
```
