# Extend TVMFFIPyArgSetterFactory and convert() to accept torch.dtype, numpy.dtype, and ml_dtypes dtypes as FFI DLDataType inputs

## TL;DR

- Adds `TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE` lookup tables in `dtype.pxi`, mapping framework dtypes to `DLDataType(code, bits, 1)`.
- Wires two new Cython arg-setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) into `TVMFFIPyArgSetterFactory_` so `torch.dtype` and `numpy.dtype` objects can be passed directly as FFI call arguments.
- Extends `convert()` in `_convert.py` to also handle `torch.dtype` and `numpy.dtype` objects via `core._convert_torch_dtype_to_ffi_dtype` / `core._convert_numpy_dtype_to_ffi_dtype`.

## Impact

- API: New optional branches in `convert()` and `TVMFFIPyArgSetterFactory_`. No existing callers broken; all additions are guarded by `isinstance` checks that only trigger when torch/numpy objects are passed.
- Behavioral: `torch.dtype`, `numpy.dtype`, and `ml_dtypes` dtype objects can now be passed as FFI function arguments without manual conversion. The dispatch path goes through the same O(1) `TVMFFIPyCallManager` cache as other types.
- Flags/config: `TVM_FFI_BUILD_DOCS=1` suppresses torch/numpy/ml_dtypes imports in `dtype.pxi` (same guard already present in `function.pxi`).
- Data formats/schemas: `DLDataType` encoding for `torch.bool` is `(code=6, bits=8, lanes=1)` — `kDLBool=6`. The `dtype.h` bugfix adds `kDLBool` to `DLDataTypeCodeAsCStr` so `str(dtype)` on a bool dtype works correctly.

## Design Elements

Design elements this commit consumes:
- **0016-py-ffi-call-dispatch**: `TVMFFIPyArgSetterFactory_`, `TVMFFIPyCallManager` dispatch cache, `TVMFFIPyArgSetter` function pointer pattern, `TVMFFIAny.v_dtype`/`type_index = kTVMFFIDataType`.
- **0013-python-package**: `dtype.pxi` Cython fragment (extends it), `_convert.py` `convert()` function, `TVM_FFI_BUILD_DOCS` guard pattern.
- **0001-c-abi**: `DLDataType` struct `(code, bits, lanes)`, `kTVMFFIDataType` type index, `kDLBool` enum value.
- **0007-containers**: `DataType` Python wrapper type (lives in `dtype.pxi`).

Design elements this commit produces:
- **dtype conversion tables** (`TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE`): module-level Cython dicts mapping framework dtype objects → `DLDataType`. These are the canonical dtype-to-DLDataType mapping for the Python layer.
- **`_convert_torch_dtype_to_ffi_dtype` / `_convert_numpy_dtype_to_ffi_dtype`**: public-internal helpers exposed from `core` (dtype.pxi) into `_convert.py`; part of the `convert()` protocol.
- **`TVMFFIPyArgSetterDTypeFromTorch_` / `TVMFFIPyArgSetterDTypeFromNumpy_`**: new setter functions registered in the `TVMFFIPyArgSetterFactory_` dispatch table; extend the O(1) per-type dispatch cache to cover framework dtype types.
- **`kDLBool` branch in `DLDataTypeCodeAsCStr`**: minor C++ fix making `DLDataType{6,8,1}` stringify as `"bool"`.

## Usage Examples

End-to-end cross-layer trace (Python → Cython → C ABI):

```python
import torch
import numpy as np
import tvm_ffi

# Route 1: direct FFI call argument (uses TVMFFIPyArgSetterFactory_ dispatch)
echo = tvm_ffi.get_global_func("testing.echo")
result = echo(torch.float32)       # TVMFFIPyArgSetterDTypeFromTorch_ fires
assert result.type_code == 2       # kDLFloat
assert result.bits == 32

result = echo(np.dtype(np.float16))  # TVMFFIPyArgSetterDTypeFromNumpy_ fires
assert result.type_code == 2
assert result.bits == 16

# Route 2: explicit convert() path
dtype = tvm_ffi.convert(torch.bfloat16)
assert dtype.type_code == 4       # kDLBfloat
assert dtype.bits == 16

# ml_dtypes integration (via numpy.dtype wrapper)
import ml_dtypes
dtype = tvm_ffi.convert(np.dtype(ml_dtypes.float8_e4m3fn))
assert dtype.type_code == 10      # kDLFloat8_e4m3fn
assert dtype.bits == 8
```
