# Add dtype converters for torch.dtype, numpy.dtype, and ml_dtypes as direct FFI inputs

## TL;DR
- Extends `TVMFFIPyArgSetterFactory_` dispatch with two new setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) so `torch.dtype` and `numpy.dtype` objects can be passed directly as FFI arguments and are converted to `DLDataType`.
- Adds static lookup tables (`TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE`) mapping ~25 torch dtypes and ~11 numpy/11 ml_dtypes dtypes to their `DLDataType(code, bits, lanes)` equivalents.
- Fixes a missing `kDLBool` case (`"bool"`) in `DLDataTypeCodeAsCStr` in `include/tvm/ffi/dtype.h`.

## Impact
- API: Additive — `core._convert_torch_dtype_to_ffi_dtype` and `core._convert_numpy_dtype_to_ffi_dtype` are new internal symbols on `core` module; `convert()` extended with two new branches (fully backward-compatible).
- Behavioral: `torch.dtype` and `numpy.dtype` values can now be passed directly as arguments to any FFI function expecting a `DLDataType`. Previously this would have fallen through to the `Exception` or `Fallback` setter and likely raised a `TypeError`.
- Flags/config: Optional libraries guarded by `TVM_FFI_BUILD_DOCS` env var — when set to `"1"`, all three (`torch`, `numpy`, `ml_dtypes`) are set to `None` to avoid import-time failures during doc builds.
- Data formats/schemas: The DLDataType integer code mapping is now canonical for torch/numpy in the codebase. Any future dtype additions must update these tables consistently.

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyArgSetterFactory_` dispatch chain (0012-python-bindings.md) — new setters appended after `Callable` in the existing dispatch order
- `TVMFFIPyArgSetter` + `TVMFFIPyCallManager` calling convention (0012-python-bindings.md) — setters populate `out.type_index = kTVMFFIDataType`, `out.v_dtype` directly
- `TVMFFIAny.v_dtype` / `kTVMFFIDataType` type index (0001-any-anyview-value-system.md) — DLDataType is a POD value stored inline
- `DLDataType` struct and `DLDataTypeCode` enum (0007-c-abi.md, DLPack) — the canonical dtype wire format
- `_convert.py::convert()` extension pattern (0012-python-bindings.md) — new dtype branches follow existing pattern for `__dlpack__`, `Exception`

Design elements this commit produces:
- Static dtype lookup tables `TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE` in `dtype.pxi` — canonical torch/numpy/ml_dtypes → DLDataType mapping tables for the Python layer
- `_convert_torch_dtype_to_ffi_dtype` / `_convert_numpy_dtype_to_ffi_dtype` — public internal conversion functions on `core` module (usable by callers of `convert()`)

## Usage Examples

**Context**: Direct torch dtype FFI round-trip through `testing.echo` and `tvm_ffi.convert`.

```python
import torch
import numpy as np
import tvm_ffi

_fecho = tvm_ffi.get_global_func("testing.echo")

# torch.dtype passed directly as FFI argument -> returned as DataType
dtype = _fecho(torch.float32)
assert dtype.type_code == 2  # kDLFloat
assert dtype.bits == 32
assert dtype.lanes == 1

# numpy.dtype round-trip (ml_dtypes via numpy.dtype wrapper)
dtype = _fecho(np.dtype(np.int8))
assert dtype.type_code == 0  # kDLInt
assert dtype.bits == 8

# Also works via tvm_ffi.convert()
converted = tvm_ffi.convert(torch.bfloat16)
assert converted.type_code == 4  # kDLBfloat
assert converted.bits == 16
```
