# Enable torch/numpy/ml_dtypes dtype objects as FFI input by adding lookup-table-based conversion to DLDataType

## TL;DR
- Adds three static lookup tables (`TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE`) in Cython that map external dtype objects to `DLDataType` values, covering int/uint/float/bfloat/bool/float8/float6/float4 variants.
- Registers two new Cython arg setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) in the type-cached dispatch factory, enabling O(1) dtype conversion on FFI calls.
- Adds a Python-level fallback path in `_convert.py` for non-Cython code paths, plus a `kDLBool` case in the C++ `DLDataTypeCodeAsCStr` function.

## Key Exports

**Functions (Cython, `dtype.pxi`)**:
- `_convert_torch_dtype_to_ffi_dtype(torch_dtype) -> DataType` -- Looks up `torch.dtype` in `TORCH_DTYPE_TO_DTYPE`, returns a `DataType` wrapper around the corresponding `DLDataType`.
- `_convert_numpy_dtype_to_ffi_dtype(numpy_dtype) -> DataType` -- Looks up `numpy.dtype` in `NUMPY_DTYPE_TO_DTYPE` (which includes `MLDTYPES_DTYPE_TO_DTYPE` entries), returns a `DataType` wrapper.

**Functions (Cython, `function.pxi`)**:
- `TVMFFIPyArgSetterDTypeFromTorch_(handle, ctx, py_arg, out) -> int` -- Cython arg setter that writes `DLDataType` directly into `TVMFFIAny.v_dtype` for torch dtype args.
- `TVMFFIPyArgSetterDTypeFromNumpy_(handle, ctx, py_arg, out) -> int` -- Cython arg setter that writes `DLDataType` directly into `TVMFFIAny.v_dtype` for numpy/ml_dtypes dtype args.

**Constants (Cython, `dtype.pxi`)**:
- `TORCH_DTYPE_TO_DTYPE: dict[torch.dtype, DLDataType]` -- 25 entries covering `int8..int64`, `uint8..uint64`, `float16..float64`, `bfloat16`, `bool`, `float8_e4m3fn`, `float8_e4m3fnuz`, `float8_e5m2`, `float8_e5m2fnuz`, `float8_e8m0fnu`.
- `NUMPY_DTYPE_TO_DTYPE: dict[numpy.dtype, DLDataType]` -- 11 standard numpy entries (`int8..int64`, `uint8..uint64`, `float16..float64`) merged with `MLDTYPES_DTYPE_TO_DTYPE`.
- `MLDTYPES_DTYPE_TO_DTYPE: dict[numpy.dtype, DLDataType]` -- 16 entries for `ml_dtypes` sub-byte and exotic float types (`int2`, `int4`, `uint2`, `uint4`, `bfloat16`, `float8_e3m4`, `float8_e4m3`, `float8_e4m3b11fnuz`, `float8_e4m3fn`, `float8_e4m3fnuz`, `float8_e5m2`, `float8_e5m2fnuz`, `float8_e8m0fnu`, `float6_e2m3fn`, `float6_e3m2fn`, `float4_e2m1fn`).

**C++ (`dtype.h`)**:
- `DLDataTypeCodeAsCStr`: Added `case kDLBool: return "bool";` (previously missing, would hit the `default` unreachable path).

## Impact
- API: New implicit conversion from `torch.dtype` and `numpy.dtype` to `DLDataType` when passed as FFI function arguments or through `tvm_ffi.convert()`. Previously these types would fall through to `OpaquePyObject` wrapping or raise errors.
- Behavioral: `tvm_ffi.convert(torch.float32)` now returns `DataType("float32")` instead of wrapping as an opaque object. Same for numpy dtypes.
- Flags/config: `TVM_FFI_BUILD_DOCS` environment variable gates the optional imports in `dtype.pxi` (torch, numpy, ml_dtypes are set to `None` when building docs to avoid import failures).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Type-cached FFI dispatch** ([0015-python-ffi-call-dispatch.md](../designs/0015-python-ffi-call-dispatch.md)): Extends `TVMFFIPyArgSetterFactory_` with two new setter registrations for `torch.dtype` and `numpy.dtype` types, following the established pattern of type -> setter mapping.
- **DLDataType / DataType** (C ABI `DLDataType` struct + Cython `DataType` wrapper): The lookup tables map to `DLDataType(code, bits, lanes)` tuples; the conversion functions construct `DataType` objects from these.
- **`kTVMFFIDataType` type index** (C ABI): Used by both new setters to tag the `TVMFFIAny.type_index` field when writing dtype values.
- **`convert()` function** ([0014-python-package.md](../designs/0014-python-package.md)): The Python-level `_convert.py` is extended to handle `torch.dtype` and `numpy.dtype` as a fallback path for non-Cython contexts.

Design elements this commit produces:
- **External dtype lookup tables** (`TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE`): A new pattern for mapping third-party type objects to DLPack-standard values at module load time. These tables are `cdef` module-level dicts populated conditionally on library availability.
- **Dtype arg setters** (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`): Two new entries in the Cython setter catalog, extending the type-cached dispatch system.

## Usage Examples

Passing torch/numpy dtypes directly to FFI functions (from the test):
```python
import tvm_ffi
import torch
import numpy as np

fecho = tvm_ffi.get_global_func("testing.echo")

# torch.dtype -> DLDataType (via type-cached setter, O(1) after first call)
result = fecho(torch.float32)
assert result.type_code == 2  # kDLFloat
assert result.bits == 32

# numpy.dtype -> DLDataType
result = fecho(np.dtype(np.int64))
assert result.type_code == 0  # kDLInt
assert result.bits == 64

# Also works through convert()
dt = tvm_ffi.convert(torch.bfloat16)
assert dt.type_code == 4  # kDLBfloat
assert dt.bits == 16
```
