# Enable torch/numpy/ml_dtypes dtype as FFI input
## TL;DR
- Adds Cython-level argument setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) that convert `torch.dtype` and `numpy.dtype` (including `ml_dtypes`) directly to `DLDataType` without Python-level conversion, integrated into the `TVMFFIPyArgSetterFactory_` dispatch chain.
- Builds comprehensive dtype mapping tables (`TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE`) in `dtype.pxi` covering standard int/uint/float types plus Float8 variants, Float6, Float4, and bfloat16.
- Extends `_convert.py` and adds `_convert_torch_dtype_to_ffi_dtype` / `_convert_numpy_dtype_to_ffi_dtype` for the explicit `convert()` path.
- Adds `kDLBool` case to `DLDataTypeCodeAsCStr` in C++ `dtype.h`.

## Impact
- API: `torch.dtype` and `numpy.dtype` values are now accepted as FFI function arguments (automatically converted to `DLDataType`). Previously these would fall through to the fallback setter and fail.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python FFI Call Dispatch** (`.knowledge/designs/0019-python-ffi-call-dispatch.md`): New setter functions are registered in the `TVMFFIPyArgSetterFactory_` type-dispatch chain for `torch.dtype` and `numpy.dtype`.
- **Any System** (`.knowledge/designs/0002-any-system.md`): The setters output `kTVMFFIDataType` type-index values into `TVMFFIAny`, extending the type-erased value system to accept framework dtype objects.
- **Python Bindings** (`.knowledge/designs/0014-python-bindings.md`): The `convert()` function in `_convert.py` is extended with framework dtype branches.

Design elements this commit produces:
- **Framework dtype mapping tables**: Comprehensive lookup tables from `torch.dtype`/`numpy.dtype` to `DLDataType` in `dtype.pxi`. These are module-level constants initialized at import time (conditionally based on framework availability).
- **Dtype setter pattern**: `TVMFFIPyArgSetterDTypeFromTorch_` / `TVMFFIPyArgSetterDTypeFromNumpy_` demonstrate the pattern for adding new type-specific argument setters that bypass the generic `convert()` path.
