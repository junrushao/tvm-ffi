# Enable torch/numpy/ml_dtypes dtype as FFI input

## TL;DR
- Adds automatic conversion of `torch.dtype`, `numpy.dtype`, and `ml_dtypes` dtype values into TVM FFI `DLDataType` values, enabling these external dtype objects to be passed directly as arguments to FFI function calls and through `tvm_ffi.convert()`.
- Implements two Cython fast-path arg setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) in the arg setter factory, plus module-level lookup tables mapping external dtype constants to `DLDataType` structs.
- Adds a `kDLBool` case to the C++ `DLDataTypeCodeAsCStr` switch in `dtype.h` (previously missing, causing a potential error when stringifying bool dtypes).
- Adds Python-level `_convert_torch_dtype_to_ffi_dtype` and `_convert_numpy_dtype_to_ffi_dtype` helpers used by the `convert()` function as a fallback path.

## Key Exports

**C++ (header change only):**
- `DLDataTypeCodeAsCStr(kDLBool)` now returns `"bool"` -- previously fell through to the error default.

**Python / Cython (new module-level objects in `dtype.pxi`):**
- `TORCH_DTYPE_TO_DTYPE: dict[torch.dtype, DLDataType]` -- Maps 24 torch dtypes (int8 through float8_e8m0fnu, plus bool) to their DLDataType equivalents.
- `NUMPY_DTYPE_TO_DTYPE: dict[numpy.dtype, DLDataType]` -- Maps 11 standard numpy dtypes (int8/16/32/64, uint8/16/32/64, float16/32/64) plus any ml_dtypes entries to DLDataType.
- `MLDTYPES_DTYPE_TO_DTYPE: dict[numpy.dtype, DLDataType]` -- Maps 16 ml_dtypes dtypes (int2/4, uint2/4, bfloat16, various float8/float6/float4 variants) to DLDataType.
- `_convert_torch_dtype_to_ffi_dtype(torch_dtype) -> DataType` -- Looks up torch dtype in `TORCH_DTYPE_TO_DTYPE` and returns a `DataType` wrapper.
- `_convert_numpy_dtype_to_ffi_dtype(numpy_dtype) -> DataType` -- Looks up numpy dtype in `NUMPY_DTYPE_TO_DTYPE` and returns a `DataType` wrapper.

**Python / Cython (new arg setters in `function.pxi`):**
- `TVMFFIPyArgSetterDTypeFromTorch_` -- Cython cdef function; sets `out.type_index = kTVMFFIDataType` and `out.v_dtype` directly from the lookup table. Registered in `TVMFFIPyArgSetterFactory_` for `torch.dtype` instances.
- `TVMFFIPyArgSetterDTypeFromNumpy_` -- Cython cdef function; same pattern for `numpy.dtype` instances.

**Python (`_convert.py` changes):**
- `convert()` now handles `torch.dtype` and `numpy.dtype` values, dispatching to `core._convert_torch_dtype_to_ffi_dtype` / `core._convert_numpy_dtype_to_ffi_dtype`.

## Impact
- API: External `torch.dtype` and `numpy.dtype` objects can now be passed directly to any TVM FFI function call. Previously they would fall through to the opaque-object fallback path and not be interpreted as data types.
- ABI: No ABI changes. The C++ header change only adds a case to an inline switch statement.
- Behavioral: The Cython arg setter factory (`TVMFFIPyArgSetterFactory_`) now recognizes `torch.dtype` and `numpy.dtype` instances and routes them through dedicated fast-path setters that perform a dictionary lookup and directly write the `DLDataType` into the `TVMFFIAny` output. This avoids the overhead of the string-based `DataType("float32")` path. The `torch.dtype` and `numpy.dtype` checks are positioned after `callable()` and before `Exception` in the factory ordering.
- Flags/config: The `TVM_FFI_BUILD_DOCS` environment variable gates the import of `torch`, `numpy`, and `ml_dtypes` in `dtype.pxi` (set to `"0"` to skip imports, matching the existing pattern in `function.pxi`).
- Data formats/schemas: No changes.

## Design Elements
Design elements this commit consumes:
- **DLDataType struct and type code constants** (`kDLInt=0`, `kDLUInt=1`, `kDLFloat=2`, `kDLBfloat=4`, `kDLBool=6`, `kDLFloat8_e3m4=7` through `kDLFloat4_e2m1fn=17`): The DLPack data type codes used to construct `DLDataType(code, bits, lanes)` values in the mapping tables.
- **TVMFFIPyArgSetter / TVMFFIPyArgSetterFactory_ pattern**: The existing Cython arg-setter dispatch mechanism where a factory function inspects the Python type of an argument and assigns a type-specific setter function pointer. See `function.pxi`.
- **DataType Cython class** (`dtype.pxi`): Used to create return values from the conversion functions. Wraps a `DLDataType` C struct.
- **`tvm_ffi.convert()` dispatch chain** (`_convert.py`): The Python-level conversion function that maps Python objects to FFI-compatible values.

Design elements this commit produces:
- **External dtype lookup tables**: Three module-level dictionaries (`TORCH_DTYPE_TO_DTYPE`, `NUMPY_DTYPE_TO_DTYPE`, `MLDTYPES_DTYPE_TO_DTYPE`) that provide O(1) mapping from external framework dtype objects to `DLDataType` C structs. The numpy table incorporates ml_dtypes entries via dict unpacking (`**MLDTYPES_DTYPE_TO_DTYPE`).
- **Dual-path dtype conversion**: FFI function calls go through the fast Cython arg setter path (dictionary lookup, direct `DLDataType` write); `tvm_ffi.convert()` goes through the Python `_convert_*_dtype_to_ffi_dtype` path that returns a `DataType` wrapper object.
- **DLDataType code mapping for torch**: Establishes the canonical mapping between PyTorch dtype constants and DLPack type codes (e.g., `torch.bfloat16 -> DLDataType(4, 16, 1)`, `torch.bool -> DLDataType(6, 8, 1)`, `torch.float8_e4m3fn -> DLDataType(10, 8, 1)`).

## Usage Examples

### Passing torch dtype to an FFI function
```python
import torch
import tvm_ffi

f = tvm_ffi.get_global_func("testing.echo")
result = f(torch.float32)  # returns dtype("float32")
assert result.type_code == 2
assert result.bits == 32
```

### Passing numpy dtype to an FFI function
```python
import numpy as np
import tvm_ffi

f = tvm_ffi.get_global_func("testing.echo")
result = f(np.dtype(np.float16))  # returns dtype("float16")
assert result.type_code == 2
assert result.bits == 16
```

### Using convert() with ml_dtypes
```python
import numpy as np
import ml_dtypes
import tvm_ffi

dt = tvm_ffi.convert(np.dtype(ml_dtypes.bfloat16))
assert dt.type_code == 4  # kDLBfloat
assert dt.bits == 16
```
