# Add torch.dtype, numpy.dtype, and ml_dtypes dtype as FFI input with automatic DLDataType conversion
## TL;DR
- Adds automatic conversion of `torch.dtype`, `numpy.dtype`, and `ml_dtypes` dtype objects to `DLDataType` when passed as FFI function arguments or through `tvm_ffi.convert()`.
- Registers two new Cython arg setters (`TVMFFIPyArgSetterDTypeFromTorch_`, `TVMFFIPyArgSetterDTypeFromNumpy_`) in the `TVMFFIPyArgSetterFactory_` dispatch chain, plus three static lookup tables mapping framework dtypes to `DLDataType` structs.
- Fixes missing `kDLBool` case in C++ `DLDataTypeCodeAsCStr` (returns `"bool"`).

## Impact
- API: Two new internal functions (`core._convert_torch_dtype_to_ffi_dtype`, `core._convert_numpy_dtype_to_ffi_dtype`) added; no public API change.
- Behavioral: `torch.dtype` and `numpy.dtype` values now auto-convert to `DLDataType` when passed as FFI function args (previously would fall through to `OpaquePyObject` or `TVMFFIPyArgSetterFallback_`). `tvm_ffi.convert()` also handles these types.
- Flags/config: `TVM_FFI_BUILD_DOCS` env var gates optional imports in `dtype.pxi` (torch/numpy/ml_dtypes set to `None` during doc builds).
- Data formats/schemas: none

## Usage Examples
Passing a torch dtype directly as an FFI function argument (from test):
```python
import torch
import tvm_ffi

# torch.dtype auto-converts to DLDataType through the setter dispatch
fecho = tvm_ffi.get_global_func("testing.echo")
result = fecho(torch.float32)  # returns DataType("float32")
assert result.type_code == 2  # kDLFloat
assert result.bits == 32

# Also works through convert()
converted = tvm_ffi.convert(torch.bfloat16)
assert converted.type_code == 4  # kDLBfloat
```

Passing a numpy dtype or ml_dtypes dtype:
```python
import numpy as np
import ml_dtypes

fecho = tvm_ffi.get_global_func("testing.echo")
result = fecho(np.dtype(np.float16))
assert result.type_code == 2 and result.bits == 16

result = fecho(np.dtype(ml_dtypes.float8_e4m3fn))
assert result.type_code == 10 and result.bits == 8
```
