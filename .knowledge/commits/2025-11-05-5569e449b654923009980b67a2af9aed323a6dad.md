# Add C++17 structured binding and ADL get support to Tuple
## TL;DR
- Adds `std::tuple_size` and `std::tuple_element` specializations in `namespace std` so `Tuple<Types...>` supports C++17 structured bindings (`auto [a, b, c] = t;`).
- Adds ADL-friendly free `get<I>()` functions (const lvalue and rvalue overloads) in `namespace tvm::ffi`, enabling idiomatic `using std::get; get<0>(t);` patterns.
- Adds an rvalue-qualified `get() &&` member that moves out the element when the tuple has unique ownership, falling back to copy otherwise.
- Adds a CTAD deduction guide: `Tuple{1, 2.0f, String{"hello"}}` deduces `Tuple<int, float, String>`.

## Impact
- API: Additive. The `get() const` to `get() const&` ref-qualification is technically a signature change, but all existing const lvalue call sites continue to compile identically. Rvalue temporaries now dispatch to the move overload, which is a behavioral change (move vs copy) but safe due to the uniqueness check.
- Behavioral: Calling `get<I>()` on a temporary/rvalue `Tuple` now moves the element out if the tuple is uniquely owned. Previously this would copy. The uniqueness guard ensures shared tuples still copy.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**Structured bindings (lvalue and rvalue):**
```cpp
// CTAD deduction guide: deduces Tuple<int, float, String>
auto t = Tuple{1, 2.0f, String{"hello"}};

// Structured binding (lvalue, copies elements)
auto [a, b, c] = t;
// a: int=1, b: float=2.0f, c: String="hello"

// Structured binding (rvalue, moves elements if unique)
auto [x] = Tuple{Array<int>{0}};
// x.use_count() == 1 (moved, not copied)
```

**ADL-friendly get:**
```cpp
auto p = Tuple{Array<int>{0}};
// ADL resolves tvm::ffi::get without explicit using-declaration
const auto q = get<0>(p);         // copy (lvalue)
const auto r = get<0>(std::move(p));  // move (rvalue, unique)
```
