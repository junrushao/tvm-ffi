# Fix missing FunctionInfo specialization for lvalue-reference function types R(&)(Args...)

## TL;DR
- Added a missing `FunctionInfo` template specialization for lvalue-reference-to-function types (`R (&)(Args...)`), alongside the existing pointer-to-function (`R (*)(Args...)`) and plain function type (`R(Args...)`) specializations.

## Key Exports

```python
# C++ (include/tvm/ffi/function_details.h)

# FunctionInfo specializations — before:
# FunctionInfo<R(Args...), void>      -> FuncFunctorImpl<R, Args...>
# FunctionInfo<R(*)(Args...), void>   -> FuncFunctorImpl<R, Args...>

# FunctionInfo specializations — after (adding):
# FunctionInfo<R(&)(Args...), void>   -> FuncFunctorImpl<R, Args...>
# Invariant: all three specializations delegate to FuncFunctorImpl
# Interacts with: reflection::ObjectDef::def_method, Function::FromTyped
```

## Impact
- API: None — additive template specialization. Fixes a compile error when passing a named function reference (rather than a function pointer or lambda) to `reflection` or `Function::FromTyped`.
- Behavioral: Passing a named free function as an lvalue reference now compiles without error.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `FunctionInfo` SFINAE dispatch in `function_details.h` (see `.knowledge/design-records/0004-function-system.md`, `0008-type-traits.md`)

Design elements this commit produces:
- Extended `FunctionInfo` coverage: lvalue-reference-to-function is now a valid specialization.

## Usage Examples

```cpp
// BEFORE: compile error
void my_func(int x) { ... }
reflection::GlobalDef().def("name", my_func);  // error: no FunctionInfo for R(&)(Args...)

// AFTER: compiles fine
void my_func(int x) { ... }
reflection::GlobalDef().def("name", my_func);  // ok
```
