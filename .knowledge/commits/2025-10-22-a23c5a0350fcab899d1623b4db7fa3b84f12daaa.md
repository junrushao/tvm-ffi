# Fix missing function ref in type traits

## TL;DR
- Adds a missing `FunctionInfo<R(&)(Args...), void>` partial specialization to handle function *reference* types.
- Previously, `TVM_FFI_DLL_EXPORT_TYPED_FUNC(name, (func))` or `TVM_FFI_DLL_EXPORT_TYPED_FUNC(name, ref)` (where `ref` is `auto& ref = fn`) would fail to compile or crash because `decltype((func))` / `decltype(ref)` yields `R(&)(Args...)`, which had no `FunctionInfo` specialization.

## Key Exports

**Template specialization** (`include/tvm/ffi/function_details.h`):
```cpp
template <typename R, typename... Args>
struct FunctionInfo<R (&)(Args...), void> : FuncFunctorImpl<R, Args...> {};
```
This completes the set alongside the existing `R(Args...)` and `R(*)(Args...)` specializations.

## Impact
- API: None (adds missing template specialization; no signature changes).
- Behavioral: `TVM_FFI_DLL_EXPORT_TYPED_FUNC` now works correctly when the second argument is a parenthesized function name `(func)` or a `constexpr auto&` reference to a function. Before this fix, such usage caused compilation failure or runtime crash.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`FunctionInfo<F>` trait** (`function_details.h`): The compile-time introspection trait that extracts return type and argument types from callable types. See `.knowledge/designs/0005-type-traits.md`.
- **`FuncFunctorImpl<R, Args...>`**: The base providing the typed-to-packed calling convention adapter.
- **`TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro** (`function.h`): The macro that uses `decltype` on its second argument to select the `FunctionInfo` specialization.

Design elements this commit produces: None (completes an existing design element's coverage).

## Usage Examples

Before (crash or compilation failure):
```cpp
void AddOne(TensorView x, TensorView y) { /* ... */ }
// Extra parens cause decltype to yield R(&)(Args...) -- no specialization matched
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (AddOne));

// constexpr ref also yields R(&)(Args...)
static constexpr auto& func = AddOne;
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_1, func);
```

After (works correctly):
```cpp
// Both forms now resolve through FunctionInfo<R(&)(Args...), void>
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (AddOne));       // OK
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_1, func);         // OK
```
