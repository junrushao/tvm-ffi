# Fix missing FunctionInfo specialization for function lvalue references
## TL;DR
- Adds a `FunctionInfo<R (&)(Args...), void>` partial specialization in `function_details.h`, fixing a compile-time crash when `decltype(Function)` resolves to a function lvalue reference type (e.g., from extra parentheses in `TVM_FFI_DLL_EXPORT_TYPED_FUNC` or from `constexpr auto&` bindings).

## Key Exports
**Template specialization**: `FunctionInfo<R (&)(Args...), void>` -- maps function lvalue reference types to `FuncFunctorImpl<R, Args...>`, completing the set of function-type decomposition specializations alongside `R(Args...)` (bare function type) and `R (*)(Args...)` (function pointer).

## Impact
- API: none -- no public API signature changes
- ABI: none -- template specialization only, no binary layout changes
- Behavioral: previously, passing a function reference (via extra parentheses or `constexpr auto&`) to `TVM_FFI_DLL_EXPORT_TYPED_FUNC` would fail to compile because `decltype(Function)` produced `R (&)(Args...)` which had no matching `FunctionInfo` specialization. Now it compiles correctly.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `FunctionInfo` template family for function signature decomposition (`.knowledge/designs/function-system.md`, section "FunctionInfo vs FunctionInfoHelper")
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro which uses `decltype(Function)` to extract the function signature (`.knowledge/designs/function-system.md`, section "TVM_FFI_DLL_EXPORT_TYPED_FUNC")

Design elements this commit produces:
- Extends `FunctionInfo` specialization coverage to handle function lvalue reference types `R (&)(Args...)`

## Usage Examples
**Context**: The fix handles two patterns that previously caused compile errors in `TVM_FFI_DLL_EXPORT_TYPED_FUNC`.

```cpp
// Pattern 1: Extra parentheses cause decltype to produce R(&)(Args...) instead of R(*)(Args...)
void AddOne(TensorView x, TensorView y) { /* ... */ }
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (AddOne));  // decltype((AddOne)) = void (&)(...)

// Pattern 2: constexpr reference binding
static constexpr auto& func = AddOne;
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_alias, func);  // decltype(func) = void (&)(...)
```

Both now compile correctly because `FunctionInfo<R (&)(Args...)>` resolves to `FuncFunctorImpl<R, Args...>`.
