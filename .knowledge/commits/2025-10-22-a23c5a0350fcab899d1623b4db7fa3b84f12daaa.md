# Fix missing FunctionInfo specialization for function reference types
## TL;DR
- `FunctionInfo<T>` lacked a template specialization for function reference types `R (&)(Args...)`, causing compilation failures when `TVM_FFI_DLL_EXPORT_TYPED_FUNC` received a parenthesized function name or a `constexpr auto&` function reference.
- Fixed by adding `FunctionInfo<R (&)(Args...), void>` specialization that delegates to `FuncFunctorImpl<R, Args...>`, matching the existing patterns for bare function types and function pointers.

## Key Exports

```python
# FunctionInfo SFINAE dispatch table (function_details.h)
# Existing specializations:
#   FunctionInfo<R(Args...), void>       -> FuncFunctorImpl<R, Args...>   # bare function type
#   FunctionInfo<R (*)(Args...), void>   -> FuncFunctorImpl<R, Args...>   # function pointer
#   FunctionInfo<T, void> (primary)      -> FunctionInfoHelper<decltype(&T::operator())>  # lambda/functor
#
# NEW specialization added by this commit:
#   FunctionInfo<R (&)(Args...), void>   -> FuncFunctorImpl<R, Args...>   # function reference
#
# Interacts with: TVM_FFI_DLL_EXPORT_TYPED_FUNC (line 875: decltype(Function)),
#                 Function::FromTyped (infers arg count/types via FunctionInfo),
#                 details::unpack_call (compile-time arg unpacking)
# Invariant: decltype of a parenthesized function name or constexpr auto& yields R(&)(Args...),
#            which must be handled distinctly from R(*)(Args...) and R(Args...)
# Extension: any new callable type that decltype can produce needs a corresponding FunctionInfo specialization
```

## Impact
- API: none -- additive specialization, no existing signatures changed
- Behavioral: fixes compilation failure when `TVM_FFI_DLL_EXPORT_TYPED_FUNC` is invoked with a parenthesized function expression `(func)` or a `constexpr auto&` function reference
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `FunctionInfo<T>` / `FuncFunctorImpl<R, Args...>` compile-time type trait chain -- `include/tvm/ffi/function_details.h`. See [0004-ffi-function-system](../design-records/0004-ffi-function-system.md).
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro -- uses `decltype(Function)` to feed into `FunctionInfo`, defined in `include/tvm/ffi/function.h`. See [0013-ffi-packaging-and-distribution](../design-records/0013-ffi-packaging-and-distribution.md).

Design elements this commit produces:
- New `FunctionInfo<R (&)(Args...), void>` specialization extending the SFINAE dispatch table to cover function reference types.

## Usage Examples

Before (fails to compile):
```cpp
void AddOne(tvm::ffi::TensorView x, tvm::ffi::TensorView y) { /* ... */ }

// Extra parentheses: decltype yields void (&)(TensorView, TensorView)
// -> no FunctionInfo match -> compilation error
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (AddOne));

// constexpr auto&: decltype yields void (&)(TensorView, TensorView)
static constexpr auto& func = AddOne;
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_alt, func);
```

After (compiles correctly):
```cpp
void AddOne(tvm::ffi::TensorView x, tvm::ffi::TensorView y) { /* ... */ }

// Both forms now work -- FunctionInfo<R (&)(Args...)> matches
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (AddOne));

static constexpr auto& func = AddOne;
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_alt, func);
```
