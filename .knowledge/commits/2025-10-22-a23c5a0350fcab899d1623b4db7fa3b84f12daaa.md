# Fix missing FunctionInfo specialization for function reference types R(&)(Args...)
## TL;DR
- Adds `FunctionInfo<R (&)(Args...), void>` partial specialization to `function_details.h`, fixing crashes when `TVM_FFI_DLL_EXPORT_TYPED_FUNC` is used with parenthesized function names or `constexpr auto&` references.
- Before this fix, `decltype((func))` or `decltype(ref)` yields `R(&)(Args...)` which had no matching `FunctionInfo` specialization, falling through to the primary template that tries `decltype(&T::operator())` on a function reference -- causing a compile-time or runtime crash.

## Key Exports

```python
# FunctionInfo partial specializations (function_details.h, line 110-117):
# Existing:
#   FunctionInfo<R(Args...), void>         : FuncFunctorImpl<R, Args...>   # bare function type
#   FunctionInfo<R (*)(Args...), void>     : FuncFunctorImpl<R, Args...>   # function pointer
# NEW (this commit):
#   FunctionInfo<R (&)(Args...), void>     : FuncFunctorImpl<R, Args...>   # function reference
#   Interacts with: TVM_FFI_DLL_EXPORT_TYPED_FUNC macro (uses decltype(Function))
#   Interacts with: details::unpack_call (consumes FunctionInfo::RetType and num_args)
#   Invariant: all three forms (bare, pointer, reference) must resolve identically to FuncFunctorImpl<R, Args...>
```

## Impact
- API: None -- no public API change; this is an internal template specialization addition.
- Behavioral: Fixes crash when `TVM_FFI_DLL_EXPORT_TYPED_FUNC(Name, (namespace::Func))` uses extra parentheses or when `constexpr auto& func = Func; TVM_FFI_DLL_EXPORT_TYPED_FUNC(Name, func)` uses a reference binding. Both patterns now correctly resolve `FunctionInfo`.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `FunctionInfo<T>` SFINAE dispatch table ([0004-function-system.md](../designs/0004-function-system.md), "FunctionInfo SFINAE Specializations" section) -- the existing specialization set for bare function types and function pointers.
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro ([0004-function-system.md](../designs/0004-function-system.md)) -- uses `decltype(Function)` to extract type info, which triggers the bug when `Function` is parenthesized or a reference.
- `FuncFunctorImpl<R, Args...>` -- base CRTP providing `RetType`, `num_args`, and `TypeSchema()`.

Design elements this commit produces:
- `FunctionInfo<R (&)(Args...), void>` specialization -- completes the function type coverage to handle all three C++ callable type forms (bare, pointer, reference).

## Usage Examples

**Before (crash):**
```cpp
// Extra parentheses cause decltype to yield R(&)(Args...) instead of R(*)(Args...)
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (my_ns::AddOne));
// -> decltype((my_ns::AddOne)) is void(&)(TensorView, TensorView)
// -> No matching FunctionInfo specialization -> falls through to primary template
// -> Tries decltype(&T::operator()) on a function reference -> crash

// Similarly, constexpr auto& binding:
static constexpr auto& func = my_ns::AddOne;
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, func);
// -> decltype(func) is void(&)(TensorView, TensorView) -> same crash
```

**After (fixed):**
```cpp
// Both forms now match FunctionInfo<R (&)(Args...), void> : FuncFunctorImpl<R, Args...>
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one, (my_ns::AddOne));        // works
static constexpr auto& func = my_ns::AddOne;
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_alias, func);             // works
```
