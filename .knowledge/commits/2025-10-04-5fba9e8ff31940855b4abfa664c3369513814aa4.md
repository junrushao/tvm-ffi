# Fix TypeTraits enum specialization to compile on GCC 8.x by extracting is_integral_enum_v helper

## TL;DR
- GCC 8.x rejects `std::underlying_type_t<T>` inside `std::enable_if_t` when `T` is not yet known to be an enum, causing a hard error during template instantiation.
- Fix: extract a two-phase `is_integeral_enum_v<T>` variable template (primary `= false`, specialization for `is_enum_v<T> == true` checks `underlying_type_t`) to avoid the undefined-behavior-prone nested expression.
- Replaces the inline `std::enable_if_t<std::is_enum_v<IntEnum> && std::is_integral_v<std::underlying_type_t<IntEnum>>>` with `std::enable_if_t<is_integeral_enum_v<IntEnum>>`.

## Key Exports

```python
# include/tvm/ffi/type_traits.h — internal helper, not public API

# Before:
# template <typename IntEnum>
# struct TypeTraits<IntEnum, std::enable_if_t<
#     std::is_enum_v<IntEnum> && std::is_integral_v<std::underlying_type_t<IntEnum>>>>
#     : public TypeTraitsBase { ... };

# After (conceptual pseudocode):
is_integeral_enum_v: bool  # = false by default
# specialization: is_integeral_enum_v<T> = True iff is_enum_v<T> and underlying_type is integral
# Interacts with: TypeTraits<IntEnum> SFINAE specialization

class TypeTraits_IntEnum:  # TypeTraits<IntEnum, enable_if_t<is_integeral_enum_v<IntEnum>>>
    """Unchanged behavior; same as before for all enum types with integral underlying type."""
    field_static_type_index = TypeIndex.kTVMFFIInt
    # CopyToAnyView, CheckAnyStrict, CopyFromAnyViewAfterCheck: identical to before
```
