# Fix GCC 8.x compile error in enum TypeTraits SFINAE condition
## TL;DR
- Fixes a compile error on GCC 8.x caused by `std::underlying_type_t<T>` being instantiated for non-enum types in a conjunctive `enable_if_t` condition.
- Introduces a two-phase variable template `is_integeral_enum_v<T>` that guards `underlying_type_t` behind `is_enum_v`, avoiding undefined behavior.
- The `TypeTraits<IntEnum>` specialization's contract and behavior are unchanged; only the SFINAE guard is restructured.

## Key Exports

```python
# New helper trait (C++ variable template, shown as pseudocode):
# Guards underlying_type_t behind is_enum_v to avoid UB on non-enum types
# Primary: is_integeral_enum_v<T> = false (for non-enums)
# Specialization: is_integeral_enum_v<T> = is_integral_v<underlying_type_t<T>> (for enums)
# Interacts with: TypeTraits<IntEnum> SFINAE condition
# Invariant: underlying_type_t<T> is never instantiated when is_enum_v<T> is false

# TypeTraits<IntEnum> SFINAE condition change:
# Old: enable_if_t<is_enum_v<IntEnum> && is_integral_v<underlying_type_t<IntEnum>>>
# New: enable_if_t<is_integeral_enum_v<IntEnum>>
```

## Usage Examples
Before (broken on GCC 8.x):
```cpp
// GCC 8.x instantiates underlying_type_t<T> for ALL T, not just enums,
// causing "T is not an enumeration type" error
template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<
    std::is_enum_v<IntEnum> &&
    std::is_integral_v<std::underlying_type_t<IntEnum>>>>
    : public TypeTraitsBase { ... };
```

After (compiles on GCC 8.x+):
```cpp
// Two-phase check: underlying_type_t only instantiated when is_enum_v is true
template <typename T, bool = std::is_enum_v<T>>
constexpr bool is_integeral_enum_v = false;

template <typename T>
constexpr bool is_integeral_enum_v<T, true> =
    std::is_integral_v<std::underlying_type_t<T>>;

template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<is_integeral_enum_v<IntEnum>>>
    : public TypeTraitsBase { ... };
```
