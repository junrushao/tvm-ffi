# Fix GCC 8.x compile error in enum TypeTraits SFINAE guard
## TL;DR
- Refactors the enum `TypeTraits` partial specialization's SFINAE guard to avoid `std::underlying_type_t` on non-enum types, which causes a compile error on GCC 8.x.
- Introduces a two-phase helper trait `is_integeral_enum_v<T>` that first checks `std::is_enum_v<T>`, and only evaluates `std::underlying_type_t<T>` in the `true` specialization.
- No behavioral or ABI change; this is a pure portability fix.

## Key Exports
**Helper trait (internal)**:
```cpp
template <typename T, bool = std::is_enum_v<T>>
constexpr bool is_integeral_enum_v = false;

template <typename T>
constexpr bool is_integeral_enum_v<T, true> = std::is_integral_v<std::underlying_type_t<T>>;
```
This is an implementation detail (suppressed from Doxygen via `\cond`), not a public API export. The `TypeTraits<IntEnum>` specialization's SFINAE condition changes from a compound expression to `is_integeral_enum_v<IntEnum>`.

## Impact
- API: none -- no signature or behavior changes.
- ABI: none -- same binary layout, same type indices.
- Behavioral: none -- identical semantics; only the SFINAE evaluation order changes.
- Flags/config: none.
- Data formats/schemas: none.
