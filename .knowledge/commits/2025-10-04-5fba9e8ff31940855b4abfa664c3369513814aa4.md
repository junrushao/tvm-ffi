# Fix GCC 8.x compilation error in enum TypeTraits SFINAE constraint
## TL;DR
- GCC 8.x fails to compile the `TypeTraits<IntEnum>` partial specialization because it eagerly evaluates `std::underlying_type_t<T>` for non-enum types in the `enable_if` conjunction, which is undefined behavior.
- Introduces a two-phase helper trait `is_integeral_enum_v<T>` that gates `underlying_type_t` behind `is_enum_v`, avoiding UB on non-enum types.
- The SFINAE condition on the enum `TypeTraits` specialization is simplified from a compound conjunction to a single `is_integeral_enum_v<IntEnum>` check.

## Key Exports

```python
# New helper variable template (C++ constexpr bool):
# is_integeral_enum_v<T>
#   Primary template: False for all T (default bool param = is_enum_v<T>)
#   Partial specialization for is_enum_v<T> == True:
#     is_integeral_enum_v<T, true> = is_integral_v<underlying_type_t<T>>
#   Interacts with: TypeTraits<IntEnum> enable_if guard
#   Invariant: underlying_type_t<T> is only evaluated when T is already known to be an enum

# TypeTraits<IntEnum> (MODIFIED SFINAE constraint):
#   Old: enable_if_t<is_enum_v<IntEnum> && is_integral_v<underlying_type_t<IntEnum>>>
#   New: enable_if_t<is_integeral_enum_v<IntEnum>>
#   Interacts with: Any/AnyView enum conversion, all enum types used across FFI
```

## Impact
- API: None -- no change to public API signatures or behavior.
- Behavioral: None -- identical runtime semantics; only the SFINAE evaluation order changes.
- Flags/config: None.

## Design Elements
Design elements this commit consumes:
- **TypeTraits protocol** ([0006-type-traits.md](../designs/0006-type-traits.md)): The enum `TypeTraits` partial specialization is a core specialization of the protocol.
- **Generic enum TypeTraits auto-derivation**: Documented in 0006-type-traits.md as "A partial specialization auto-derives TypeTraits for any enum class with integral underlying type."

Design elements this commit produces:
- **`is_integeral_enum_v<T>` helper trait**: A two-phase constexpr bool variable template that safely checks whether `T` is an enum with integral underlying type without triggering UB on non-enum types. This is an internal implementation detail, not part of the public API.

## Usage Examples
**Before (broken on GCC 8.x):**
```cpp
// GCC 8.x eagerly evaluates underlying_type_t<T> for ALL T during
// template instantiation, even when is_enum_v<T> is false.
// This is undefined behavior per the standard.
template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<std::is_enum_v<IntEnum> &&
                                            std::is_integral_v<std::underlying_type_t<IntEnum>>>>
```

**After (safe on GCC 8.x):**
```cpp
// Two-phase check: underlying_type_t<T> is only reached
// in the true-specialization where T is guaranteed to be an enum.
template <typename T, bool = std::is_enum_v<T>>
constexpr bool is_integeral_enum_v = false;

template <typename T>
constexpr bool is_integeral_enum_v<T, true> = std::is_integral_v<std::underlying_type_t<T>>;

template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<is_integeral_enum_v<IntEnum>>>
```
