# Fix GCC 8.x compile error in enum TypeTraits SFINAE guard
## TL;DR
- GCC 8.x fails to compile the enum `TypeTraits` specialization because `std::underlying_type_t<T>` is instantiated for non-enum types, causing a hard error instead of SFINAE failure.
- Introduces a two-phase helper variable template `is_integeral_enum_v<T>` that guards `underlying_type_t` behind `std::is_enum_v<T>`, ensuring the trait is only evaluated for actual enum types.
- The `TypeTraits<IntEnum>` partial specialization's `enable_if` condition is simplified to use the new helper.

## Key Exports
**Helper trait** (new, internal):
```cpp
// Primary: non-enums short-circuit to false
template <typename T, bool = std::is_enum_v<T>>
constexpr bool is_integeral_enum_v = false;

// Partial specialization: only instantiated for enums
template <typename T>
constexpr bool is_integeral_enum_v<T, true> = std::is_integral_v<std::underlying_type_t<T>>;
```

**Changed SFINAE guard** on `TypeTraits<IntEnum>`:
```cpp
// Before (GCC 8.x hard error):
template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<std::is_enum_v<IntEnum> &&
                                            std::is_integral_v<std::underlying_type_t<IntEnum>>>>

// After (two-phase safe):
template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<is_integeral_enum_v<IntEnum>>>
```

## Impact
- API: None -- no public API change; internal SFINAE mechanism only.
- Behavioral: None -- identical runtime behavior; purely a compile-time fix.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **TypeTraits protocol** ([0005-type-traits.md](../../.knowledge/designs/0005-type-traits.md)): The enum `TypeTraits<IntEnum>` specialization that auto-registers all integral-underlying enums with the FFI value system.
- **TypeTraitsBase**: Inherited by the enum specialization.

Design elements this commit produces:
- **`is_integeral_enum_v<T>`**: A two-phase variable template that safely checks whether `T` is an enum with an integral underlying type, avoiding `underlying_type_t` instantiation for non-enum types. Internal helper, not part of the public API, but critical for compiler compatibility.

## Usage Examples
**Before (broken on GCC 8.x):**
```cpp
// When the compiler evaluates enable_if for a non-enum type T,
// std::underlying_type_t<T> is instantiated, causing a hard error on GCC 8.x.
// This is technically undefined behavior per the C++ standard.
```

**After (correct):**
```cpp
// is_integeral_enum_v<int> -> primary template with is_enum_v<int>=false -> false
//   underlying_type_t<int> is never instantiated
// is_integeral_enum_v<MyEnum> -> partial spec with is_enum_v<MyEnum>=true
//   -> std::is_integral_v<std::underlying_type_t<MyEnum>> evaluated safely
enum class MyEnum : int32_t { A = 0 };
Any val = MyEnum::A;  // Works on GCC 8.x now
```
