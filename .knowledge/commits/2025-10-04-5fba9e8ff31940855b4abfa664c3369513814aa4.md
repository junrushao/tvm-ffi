# Fix GCC 8.x compile error in enum TypeTraits SFINAE
## TL;DR
- Fixes a compilation failure under GCC 8.x where `std::underlying_type_t<T>` was instantiated for non-enum types within SFINAE context, causing hard errors instead of substitution failures.
- Introduces a two-phase `is_integeral_enum_v` trait that first checks `is_enum_v` before accessing `underlying_type_t`, avoiding undefined behavior.

## Impact
- API: None — no behavioral change for correctly-compiling toolchains.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Any/AnyView type-erasure system** (`.knowledge/designs/0002-any-system.md`): The `TypeTraits<IntEnum>` specialization for enum types that converts enums to/from `kTVMFFIInt` in `AnyView`.

Design elements this commit produces:
- **`is_integeral_enum_v` helper trait**: A two-phase SFINAE-safe check for integral enums, replacing the direct conjunction `is_enum_v && is_integral_v<underlying_type_t>` that is not safe on older compilers.
