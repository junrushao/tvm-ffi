# Fix compile error for TypeTraits<IntEnum> under GCC 8.x by introducing a two-step is_integeral_enum_v helper trait

## TL;DR
- GCC 8.x fails to compile `TypeTraits<IntEnum>` because it eagerly instantiates `std::underlying_type_t<T>` on non-enum types inside `enable_if_t`, triggering UB/hard error before SFINAE can reject the specialization.
- Introduces a two-step helper trait `is_integeral_enum_v<T>` that gates `underlying_type_t<T>` behind a `bool = std::is_enum_v<T>` partial-specialization, ensuring the inner trait is only instantiated for actual enum types.
- The public API surface and semantics of `TypeTraits<IntEnum>` are unchanged; this is a pure implementation fix.

## Usage Examples
Before (GCC 8.x compile error):
```cpp
// enable_if_t forces eager instantiation of underlying_type_t<T> for every T,
// even non-enum T, which is undefined behavior / hard error in GCC 8.x.
template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<std::is_enum_v<IntEnum> &&
                                            std::is_integral_v<std::underlying_type_t<IntEnum>>>>
    : public TypeTraitsBase { ... };
```

After (compiles on GCC 8.x):
```cpp
// Two-step: underlying_type_t<T> only instantiated in the true-branch specialization.
template <typename T, bool = std::is_enum_v<T>>
constexpr bool is_integeral_enum_v = false;  // primary: non-enum types

template <typename T>
constexpr bool is_integeral_enum_v<T, true> = std::is_integral_v<std::underlying_type_t<T>>;  // enum types only

template <typename IntEnum>
struct TypeTraits<IntEnum, std::enable_if_t<is_integeral_enum_v<IntEnum>>>
    : public TypeTraitsBase { ... };
```
