# Swap TVM_FFI_CHECK argument order to condition-first (cond, ErrorKind)

## TL;DR

- `TVM_FFI_CHECK(ErrorKind, cond)` renamed to `TVM_FFI_CHECK(cond, ErrorKind)` — condition is now the first argument.
- Aligns with C `assert(expr)` convention and the existing `TVM_FFI_ICHECK(x)` macro style.
- Breaking API change: any caller using the old `(ErrorKind, cond)` form will silently mis-compile (ErrorKind becomes an unevaluated bool expression; `cond` becomes the thrown error type).

## Key Exports

```python
# Old signature (removed):
# TVM_FFI_CHECK(ErrorKind, cond)  →  if (!(cond)) TVM_FFI_THROW(ErrorKind) << ...

# New signature (this commit):
# TVM_FFI_CHECK(cond, ErrorKind)  →  if (!(cond)) TVM_FFI_THROW(ErrorKind) << ...
# Invariant: cond is evaluated first; ErrorKind must be a valid error-kind identifier.
# Interacts with: TVM_FFI_THROW, TVM_FFI_ICHECK (companion macro with hardcoded InternalError)
# Note: TVM_FFI_ICHECK(x) was NOT changed — it keeps single-arg form.
```

## Impact

- API: **Breaking** — all callers of `TVM_FFI_CHECK` must swap their arguments. At this commit the only caller is `tests/cpp/test_error.cc` (2 test cases + 2 no-throw cases), all updated in the same commit.
- Behavioral: None — the macro expands identically; only parameter binding changes.
- Flags/config: None
- Data formats/schemas: None

## Usage Examples

Before/after pattern (bugfix-style, since this is a signature-breaking refactor):

```cpp
// BEFORE (old signature — ErrorKind first):
TVM_FFI_CHECK(ValueError, value >= 0) << "Value must be non-negative, got " << value;
TVM_FFI_CHECK(IndexError, index < array_size) << "Index out of bounds";

// AFTER (new signature — condition first, matching C assert convention):
TVM_FFI_CHECK(value >= 0, ValueError) << "Value must be non-negative, got " << value;
TVM_FFI_CHECK(index < array_size, IndexError) << "Index out of bounds";
```
