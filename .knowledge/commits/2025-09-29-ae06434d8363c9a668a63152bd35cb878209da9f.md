# Swap TVM_FFI_CHECK parameter order to place condition before error kind
## TL;DR
- Reorders `TVM_FFI_CHECK` macro parameters from `(ErrorKind, cond)` to `(cond, ErrorKind)`, aligning with `TVM_FFI_ICHECK(cond)` convention where the condition comes first.
- Updates all call sites in `tests/cpp/test_error.cc` to match the new parameter order.

## Key Exports

```python
# Macro: TVM_FFI_CHECK(cond, ErrorKind)
# Old signature: TVM_FFI_CHECK(ErrorKind, cond)
# New signature: TVM_FFI_CHECK(cond, ErrorKind)
# Expands to:
#   if (!(cond)) TVM_FFI_THROW(ErrorKind) << "Check failed: (" #cond << ") is false: "
# Interacts with: TVM_FFI_THROW, ErrorBuilder
# Invariant: condition is evaluated first (short-circuit); ErrorKind is a bare identifier (not a string)
# Extension: append << "message" after the macro invocation for custom error messages
```

## Impact
- API: Breaking change to `TVM_FFI_CHECK` macro parameter order. All callers must swap arguments.
- Behavioral: none -- identical runtime behavior after argument swap.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVM_FFI_THROW(ErrorKind)` macro (error protocol, see `.knowledge/design-records/0005-ffi-error-protocol.md`)
- `ErrorBuilder` streaming pattern

Design elements this commit produces:
- Mutates `TVM_FFI_CHECK` macro signature: `(ErrorKind, cond)` -> `(cond, ErrorKind)`, establishing condition-first convention consistent with `TVM_FFI_ICHECK(cond)`.

## Usage Examples

Before (old parameter order):
```cpp
TVM_FFI_CHECK(ValueError, value >= 0) << "Value must be non-negative, got " << value;
```

After (new parameter order):
```cpp
TVM_FFI_CHECK(value >= 0, ValueError) << "Value must be non-negative, got " << value;
```
