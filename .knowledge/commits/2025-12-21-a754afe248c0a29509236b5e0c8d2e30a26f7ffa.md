# Add CI job to run examples on main-branch commits and fix Windows multi-config build
## TL;DR
- Adds an `examples` job to `ci_mainline_only.yml` that builds and runs all three example directories (quickstart, stable_c_abi, packaging) on Linux, macOS, and Windows.
- Introduces `set_flat_output_dirs()` CMake helper in quickstart and stable_c_abi to fix multi-config generator (MSVC) output directory issues on Windows.
- Consolidates `run_example.py` (packaging) to run all three demo flows unconditionally instead of requiring a CLI argument, and adds Windows `.bat` runner scripts for quickstart and stable_c_abi.

N/A -- infrastructure

## Impact
- API: none
- Behavioral: `run_example.py` no longer requires a subcommand argument; it runs all examples sequentially. `raise_error` demo now catches the exception instead of propagating it.
- Flags/config: Fixed `cmake.build-type` typo in `examples/packaging/pyproject.toml` (`RelWithDebugInfo` -> `RelWithDebInfo`).
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system / `__tvm_ffi_` symbol convention** (`.knowledge/designs/0011-module-system.md`) -- the examples use `__tvm_ffi_add_one_cpu` as the entry point loaded by `load_module`.
- **C ABI visibility macros** (`.knowledge/designs/0001-c-abi.md`) -- `TVM_FFI_DLL_EXPORT` is used in `add_one_cpu.c`; this commit corrects the macro from `TVM_FFI_DLL` to `TVM_FFI_DLL_EXPORT` in the stable_c_abi example, aligning with the intended semantics (always-export for kernel shared libraries, vs. `TVM_FFI_DLL` which is dllimport on consumer side on MSVC).
- **Packaging workflow** (`.knowledge/designs/0013-packaging.md`) -- the packaging example exercises `scikit-build-core` + `tvm_ffi` CMake integration.

Design elements this commit produces:
- **`set_flat_output_dirs()` CMake helper** -- a local CMake function duplicated in `examples/quickstart/CMakeLists.txt` and `examples/stable_c_abi/CMakeLists.txt` that forces all output directories (RUNTIME, LIBRARY, ARCHIVE) for all configurations to `${CMAKE_BINARY_DIR}`. This works around MSVC multi-config generators placing binaries in per-config subdirectories (`build/Release/`, `build/Debug/`), which breaks the scripts that expect flat `build/` layout.
- **CI `examples` job** -- a new GitHub Actions job in `ci_mainline_only.yml` that runs on `{ubuntu-latest, macos-14, windows-latest}` x `{Python 3.12-3.14}`, exercising all example directories end-to-end.
- **Windows `.bat` runner scripts** -- `examples/quickstart/run_all_cpu.bat` and `examples/stable_c_abi/run_all.bat` providing Windows-native equivalents of the existing POSIX shell scripts.
