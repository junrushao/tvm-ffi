# Apply clang-tidy: add `.clang-tidy` config and lint script; apply modernize/perf/correctness fixes across C++ headers and sources

## TL;DR

- Adds `.clang-tidy` configuration and `tests/lint/clang_tidy_precommit.py` runner script to make clang-tidy runnable (though not yet in CI).
- Applies a broad sweep of clang-tidy-suggested fixes across 61 existing C++ files: C++17 type-trait `_v`/`_t` suffixes, `using` over `typedef`, `noexcept` on move operations, `std::move` for pass-by-value parameters, `static_cast` over C-style casts, range-based for loops, and `= default` constructors.
- Fixes one correctness bug: `AnyUnsafe::MoveTVMFFIAnyToAny` signature changed from `TVMFFIAny&&` to `TVMFFIAny*` to prevent a dangling-reference UB when the rvalue argument was zeroed after the function returned.

## Impact

- API: None — all changes are internal; no public API signatures changed (the `MoveTVMFFIAnyToAny` change is `details::AnyUnsafe`, an internal utility).
- Behavioral:
  - `Object()` constructor now zero-initializes all header fields (`type_index`, `__padding`, `__ensure_align`) instead of only `deleter`. Eliminates uninitialized-memory reads in debug/sanitizer builds.
  - `AnyUnsafe::MoveTVMFFIAnyToAny(TVMFFIAny*)` zeroes the source struct in-place; old rvalue version had a theoretical dangling-reference window.
  - `GlobalFunctionTable::Entry::SyncMethodInfo` now assigns `this->method = AnyView(func_data).CopyToTVMFFIAny()` — previously the method TVMFFIAny was left unset in the `Entry(String, Function)` constructor path.
  - `names.reserve(len)` added in `Function::ListGlobalNames` avoids repeated reallocations.
  - `size_t`-to-`int64_t` narrowing casts in `structural_equal.cc` loop indices and `AccessStep` arguments now use `static_cast<int64_t>` (fixes sign-compare warnings).
- Flags/config: New `.clang-tidy` config at repo root controls which checks run. `tests/lint/check_file_type.py` whitelist updated to allow `.clang-tidy`.
- Data formats/schemas: None.
