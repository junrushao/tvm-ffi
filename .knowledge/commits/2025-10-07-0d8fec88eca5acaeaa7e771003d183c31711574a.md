# Address clang-tidy warnings with style modernizations, perf improvements, and correctness fixes

## TL;DR
- Introduces `.clang-tidy` config and `tests/lint/clang_tidy_precommit.py` runner script for the project; applies all suggested fixes across 56 files.
- **Style modernizations**: `typedef` -> `using`, `std::is_base_of<T,U>::value` -> `std::is_base_of_v<T,U>`, raw string literals for JSON schemas, `= default` for trivial constructors, range-based for loops.
- **Performance**: pervasive `std::move` for pass-by-value parameters captured into members; `names.reserve()` before loops; `const&` for read-only `ObjectPtr`/`String` parameters.
- **Correctness fixes**: (1) `JSONParser` dangling pointer -- `json_str` parameter was destroyed before `ctx_` used its data; now stored as `storage_` member. (2) `GlobalFunctionTable::Entry` -- method-from-name constructor path now calls `SyncMethodInfo` which sets `this->method` from `func_data`, fixing a missing method pointer. (3) `Object` constructor now zeroes all header fields (`type_index`, `__padding`, `__ensure_align`), not just `combined_ref_count` and `deleter`. (4) `MoveTVMFFIAnyToAny` signature changed from rvalue-ref `TVMFFIAny&&` to pointer `TVMFFIAny*` to avoid UB on moved-from struct. (5) `ObjAllocatorBase` constructor made private with `friend Derived` (CRTP enforcement).

## Impact
- API: Internal C++ API only. `MoveTVMFFIAnyToAny` signature changed from `TVMFFIAny&&` to `TVMFFIAny*` (callers must pass address). `ProcessLibraryBin` second parameter changed from `ObjectPtr<Library>` to `const ObjectPtr<Library>&`. `AccessPath::FromSteps` parameter changed from `Array<AccessStep>` to `const Array<AccessStep>&`. All are internal symbols not part of the C ABI surface.
- Behavioral: `noexcept` on move constructors/assignments enables compiler optimizations and changes exception propagation (e.g., `std::vector` resize now uses moves instead of copies). `Object` zero-initialization prevents uninitialized reads of `type_index`/`__padding`. JSONParser dangling pointer fix prevents potential UB on string parsing. `Entry::SyncMethodInfo` fix ensures method pointer is always populated.
- Flags/config: New `.clang-tidy` config with `WarningsAsErrors: '*'`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Any/AnyView value system (0002-ffi-any-value-system): `noexcept` on move ops, `MoveTVMFFIAnyToAny` signature fix
- Object system (0003-ffi-object-system): header zero-init, `ObjectRef` noexcept moves, `ObjAllocatorBase` CRTP enforcement
- Function system (0004-ffi-function-system): `std::move` in `FromTyped`/`FromPacked`, `typedef` -> `using`, `TypedFunction` default ctor `= default`
- Error protocol (0005-ffi-error-protocol): `std::move` for string params in `ErrorObjFromStd`, `ErrorBuilder`; renamed `__tvm__log__err` -> `__tvm_ffi_log_err` in macro
- Containers (0006-ffi-containers): `static_cast<uint8_t>` for map slot constants, `static_assert` modernization, macro argument parenthesization in `TVM_FFI_DISPATCH_MAP`
- Reflection (0007-ffi-reflection): `std::move` throughout `AccessStep`/`AccessPath` factories
- JSON serialization (0010-ffi-json-serialization): dangling pointer fix in `JSONParser`, `static_cast<char>` for UTF-8 encoding
- Module system (0011-ffi-module-system): `const ObjectPtr<Library>&` for read-only params, `static_cast<unsigned char>` for binary parsing

Design elements this commit produces:
- Clang-tidy configuration (`.clang-tidy`): project-wide lint policy for C++ code quality. Enabled check groups define the contract for what warnings are treated as errors.
- `ObjAllocatorBase` private constructor pattern: CRTP enforcement preventing direct instantiation of the allocator base.
- `noexcept` contract on all `ObjectRef` move operations (via `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` macro): all ObjectRef-derived types now guarantee noexcept moves.
