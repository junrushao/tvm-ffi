# Introduce clang-tidy infrastructure and apply its suggested fixes across the C++ codebase
## TL;DR
- Adds `.clang-tidy` configuration and `tests/lint/clang_tidy_precommit.py` runner script for offline clang-tidy linting (not yet in CI).
- Applies mechanical C++ modernizations across ~55 files: `_v`/`_t` type trait suffixes, `using` over `typedef`, `= default` constructors, raw string literals (`R"(...)"`), `std::move` on by-value parameters, `noexcept` on move operations.
- Fixes correctness issues: `static_cast` for narrowing conversions, explicit CRTP base constructors, dangling pointer fix in `AnyUnsafe::MoveTVMFFIAnyToAny` (now takes `TVMFFIAny*` instead of `TVMFFIAny&&`), dead code removal in `StableHashBytes`.

## Key Exports

### New files

**`.clang-tidy`** -- Project-wide clang-tidy configuration enabling `clang-diagnostic-*`, `clang-analyzer-*`, `modernize-*`, `bugprone-*`, `performance-*`, `portability-*`, `google-*` checks with selected exclusions (`modernize-use-trailing-return-type`, `modernize-concat-nested-namespaces`, `modernize-use-auto`, `modernize-use-nodiscard`, `modernize-return-braced-init-list`, `modernize-avoid-c-arrays`, `bugprone-easily-swappable-parameters`, `google-build-using-namespace`, `performance-enum-size`, `clang-analyzer-unix.Malloc`, `performance-avoid-endl`). `WarningsAsErrors: '*'`. Header filter: `(include/tvm/ffi|src/ffi)/.*\.h$`.

**`tests/lint/clang_tidy_precommit.py`** -- CLI script (`clang-tidy-precommit`) that:
- Accepts `--build-dir`, `--jobs`, `--fix`, and positional file/directory arguments.
- Auto-generates `compile_commands.json` via CMake if absent.
- Runs `clang-tidy` in parallel via `ThreadPoolExecutor`.
- On macOS, wraps via `xcrun`.
- Signature: `main(argv: Sequence[str] | None = None) -> int`.

### Signature changes

**`AnyUnsafe::MoveTVMFFIAnyToAny`** (`include/tvm/ffi/any.h`):
- Before: `static Any MoveTVMFFIAnyToAny(TVMFFIAny&& data)`
- After: `static Any MoveTVMFFIAnyToAny(TVMFFIAny* data)`
- Motivation: Fixes dangling-pointer risk flagged by clang-tidy -- rvalue ref to a POD struct was misleading; a pointer makes the mutation explicit.

### noexcept additions

Move constructors and move assignment operators gained `noexcept` across these core types:
- `AnyView(AnyView&&)`, `AnyView::operator=(AnyView&&)` (`any.h`)
- `Any(Any&&)`, `Any::operator=(Any&&)` (`any.h`)
- `ObjectRef(ObjectRef&&)`, `ObjectRef::operator=(ObjectRef&&)` (`object.h`)
- `BytesBaseCell::operator=(BytesBaseCell&&)` (`string.h`)
- `Optional<T>::Optional(Optional&&)`, `Optional<T>::operator=(Optional&&)` (`optional.h`)
- `TVM_FFI_DEFINE_DEFAULT_COPY_MOVE_AND_ASSIGN` macro now emits `noexcept` on move operations (`base_details.h`)

### ObjectRef move semantics change

`ObjectRef` move constructor and move assignment were previously `= default`. They are now explicit and null out the source:
```cpp
ObjectRef(ObjectRef&& other) noexcept : data_(std::move(other.data_)) { other.data_ = nullptr; }
ObjectRef& operator=(ObjectRef&& other) noexcept {
  data_ = std::move(other.data_);
  other.data_ = nullptr;
  return *this;
}
```

### Object constructor initialization

`Object::Object()` now zero-initializes `type_index`, `__padding`, and `__ensure_align` in addition to `combined_ref_count` (previously only set `combined_ref_count` and `deleter`).

### CRTP base class hardening

`ObjAllocatorBase` and `InplaceArrayBase` gained private default constructors with `friend Derived`/`friend ArrayType`, preventing accidental direct instantiation.

### typedef to using conversions

| Old | New | File |
|-----|-----|------|
| `typedef void (*FObjectDeleter)(...)` | `using FObjectDeleter = void (*)(...)` | `memory.h` |
| `typedef void (*FCall)(...)` | `using FCall = void (*)(...)` | `function.h` |
| `typedef std::string (*FGetFuncSignature)()` | `using FGetFuncSignature = std::string (*)()` | `function_details.h` |

### Macro rename

`__tvm__log__err` renamed to `__tvm_ffi_log_err` in `TVM_FFI_ICHECK_BINARY_OP` macro (`error.h`) to avoid reserved identifier pattern.

## Impact
- API: `AnyUnsafe::MoveTVMFFIAnyToAny` signature changed from rvalue-ref to pointer. All internal call sites updated. This is an internal/unsafe API not exposed cross-language, but any C++ code directly calling it must update.
- Behavioral: `ObjectRef` move operations now explicitly null the source pointer (was relying on `ObjectPtr` default move which also nulls, so no observable behavior change). `Object` constructor now zero-initializes more header fields.
- Flags/config: New `.clang-tidy` configuration file governs which checks are enabled project-wide.
- Data formats/schemas: None.
