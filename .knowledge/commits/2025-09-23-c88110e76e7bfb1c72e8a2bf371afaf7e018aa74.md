# Fix DenseMapObj::At() to throw KeyError instead of IndexError so Map.get() returns None for missing keys

## TL;DR
- `DenseMapObj::At()` was throwing `IndexError` on missing keys; corrected to `KeyError` to match `SmallMapObj::at()` and Python dict semantics.
- The mismatch caused `Map.get(key)` to propagate an `IndexError` instead of returning `None`, because `Map.get()` only catches `KeyError`.
- Adds `test_large_map_get` to verify `Map.get()` returns `None` for an absent key in a 100-entry (dense-path) map.

## Key Exports

```python
# DenseMapObj::At() — internal C++ method, call chain: Map.__getitem__ → ffi.MapGetItem → MapObj::at() → DenseMapObj::At()
# Old: TVM_FFI_THROW(IndexError) << "key is not in Map"
# New: TVM_FFI_THROW(KeyError) << "key is not in Map"
# Invariant: both SmallMapObj::at() and DenseMapObj::At() now raise KeyError uniformly.
# Interacts with: Map.__getitem__ (container.py), Map.get() (container.py), ffi.MapGetItem global func (src/ffi/container.cc)
```

## Impact
- API: None — `Map.__getitem__` contract (raise `KeyError` on missing key) is now correct and was broken before.
- Behavioral: `Map.get(key)` now returns `None` for absent keys on large (dense-path) maps; previously raised `IndexError`. `Map.__getitem__` for a missing key now raises `KeyError` instead of `IndexError` for large maps.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **0007-containers** (`Map`, `DenseMapObj`, `SmallMapObj`): the two-variant Map implementation (small-path `SmallMapObj` vs dense-path `DenseMapObj`). `SmallMapObj::at()` already used `KeyError`; this commit aligns `DenseMapObj::At()`.
- **0005-error-system** (`TVM_FFI_THROW`, error-kind string → Python exception mapping via `register_error`): the `"KeyError"` kind string maps to Python `KeyError`; `"IndexError"` maps to `IndexError`. These mappings are the root cause of why the wrong error type breaks `Map.get()`.

Design elements this commit produces: None — no new design elements; restores an existing invariant.

## Usage Examples

Before (broken — raises `IndexError` for large maps):
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})  # >8 entries → DenseMapObj path
result = amap.get(101)  # ← raised IndexError, not returning None
```

After (correct):
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})
assert amap.get(101) is None   # returns None for absent key
assert amap.get(3) == 9        # returns value for present key
```
