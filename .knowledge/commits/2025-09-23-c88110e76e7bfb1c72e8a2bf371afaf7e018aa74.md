# Fix Map.get by correcting DenseMapObj::At to throw KeyError instead of IndexError
## TL;DR
- `DenseMapObj::At` in `map.h` threw `IndexError` on missing key; changed to `KeyError`.
- This fixes `Map.get()` in Python, which catches `KeyError` to return a default value -- the wrong exception type caused it to propagate instead.
- Added `test_large_map_get` test verifying `Map.get` returns `None` for absent keys and correct values for present keys.

## Key Exports
No new APIs introduced. One behavioral correction to an existing method:

```python
class DenseMapObj:
    def At(self, key: key_type) -> mapped_type:
        """Look up key or raise on missing."""
        # OLD: TVM_FFI_THROW(IndexError) << "key is not in Map"
        # NEW: TVM_FFI_THROW(KeyError) << "key is not in Map"
        # Interacts with: Python Map.get() which catches KeyError
        # Interacts with: Python Map.__getitem__() via MapGetItem FFI func
        # Invariant: missing-key access raises KeyError (matches Python dict semantics)
        ...
```

## Impact
- API: None -- no signature changes.
- Behavioral: `DenseMapObj::At` now throws `KeyError` instead of `IndexError`. This changes the exception type seen by all callers across all language bindings (C++, Python, Rust). Python `Map.get()` was broken before this fix because it caught only `KeyError`.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DenseMapObj::At** (0006-ffi-containers): the map lookup method whose error type is corrected.
- **TVM_FFI_THROW macro** (0005-ffi-error-protocol): used to throw typed errors; this commit changes the type argument from `IndexError` to `KeyError`.
- **Python Map.get()** (`python/tvm_ffi/container.py:290-310`): relies on `try/except KeyError` to return default on missing key.

Design elements this commit produces:
- None -- purely restores the correct invariant.

## Usage Examples
Before/after pattern showing the bug:

```python
import tvm_ffi

m = tvm_ffi.convert({0: 0, 1: 1, 2: 4})

# BEFORE (broken): Map.get() propagated IndexError because except KeyError didn't match
m.get(99)        # raised IndexError("key is not in Map")

# AFTER (fixed): Map.get() catches KeyError and returns None
m.get(99)        # returns None
m.get(99, -1)    # returns -1
m.get(2)         # returns 4
```

## Reflection

### Design docs / ADRs to write or update
- `0006-ffi-containers.md`: The design record documents `Map` extensively but does not specify the error type for missing-key access. Consider adding an invariant: "Missing-key lookup raises `KeyError` (not `IndexError`) to match Python dict semantics and enable `Map.get()`."
