# Fix DenseMapObj::At to throw KeyError instead of IndexError, restoring Map.get() behavior
## TL;DR
- `DenseMapObj::At` incorrectly threw `IndexError` when a key was missing; changed to `KeyError` to match `SmallMapObj::at` and Python `dict` semantics.
- This fix restores `Map.get()` in Python, which catches `KeyError` specifically -- with `IndexError`, `Map.get()` would propagate the exception instead of returning `None`/default for maps with >4 entries.
- Adds `test_large_map_get` confirming `Map.get(absent_key)` returns `None` and `Map.get(present_key)` returns the correct value.

## Key Exports

```python
class DenseMapObj(MapObj):
    """Open-addressing hash map for maps with >4 entries."""
    def At(self, key: key_type) -> mapped_type:
        """Search for key, raise on miss."""
        # OLD: TVM_FFI_THROW(IndexError) << "key is not in Map"
        # NEW: TVM_FFI_THROW(KeyError) << "key is not in Map"
        # Invariant: error kind matches SmallMapObj::at (both throw KeyError)
        # Interacts with: MapObj::at -> ffi.MapGetItem -> Python Map.__getitem__ -> Map.get()
        ...
```

## Impact
- API: None -- no signature changes.
- Behavioral: `DenseMapObj::At` now throws `KeyError` instead of `IndexError` on missing key. This changes the exception type observed by callers of `Map.__getitem__` for dense maps (>4 entries). Python `Map.get()` now correctly returns `None`/default for absent keys on dense maps.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
**Before (broken)**:
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})  # >4 entries -> DenseMapObj
amap.get(101)  # RAISES IndexError instead of returning None
# Because: DenseMapObj::At throws IndexError, Map.get() catches KeyError only
```

**After (fixed)**:
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})
amap.get(101)  # Returns None (DenseMapObj::At now throws KeyError, caught by Map.get)
amap.get(3)    # Returns 9
```
