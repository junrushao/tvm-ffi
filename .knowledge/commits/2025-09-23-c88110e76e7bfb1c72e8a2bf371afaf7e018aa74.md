# Fix Map.get to return None for missing keys by changing DenseMapObj::At to throw KeyError instead of IndexError
## TL;DR
- `DenseMapObj::At` in `map.h` was throwing `IndexError` when a key was not found; changed to `KeyError` for consistency with `SmallMapObj::at` and Python dict semantics.
- Python `Map.get(key)` was broken for `DenseMap`-backed maps because `Map.get` catches `KeyError` but `IndexError` was being thrown, causing uncaught exceptions instead of returning `None`.
- Added `test_large_map_get` test exercising `Map.get` with a 100-entry map (which triggers `DenseMap` path) to confirm correct behavior.

## Key Exports
None -- no new public API. The fix corrects the exception type of an existing internal method.

```python
# DenseMapObj::At (C++ internal, not directly exported)
# Before: TVM_FFI_THROW(IndexError) << "key is not in Map"
# After:  TVM_FFI_THROW(KeyError) << "key is not in Map"
# Interacts with: Map.__getitem__ -> _ffi_api.MapGetItem -> DenseMapObj::At
# Interacts with: Map.get() catches KeyError to return default value
```

## Impact
- API: none -- no signature change
- Behavioral: `Map.get(missing_key)` now correctly returns `None` (or the default) for maps with >4 entries (DenseMap path). Previously it would raise an uncaught `IndexError`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Map MSB tag protocol** (0006-containers): SmallMap (<=4 entries) vs DenseMap (>4 entries) dispatch. The bug only affected DenseMap because SmallMap's `at()` already threw `KeyError`.
- **Error propagation** (0004-error-propagation): `TVM_FFI_THROW(Kind) << msg` pattern for raising typed errors across FFI boundary.
- **Python Map.get** (0012-python-bindings): `Map.get()` in `container.py` uses `try: self[key] / except KeyError: return default` pattern, which requires the C++ layer to throw `KeyError` specifically.

Design elements this commit produces:
- None -- purely corrective.

## Usage Examples
**Before (broken)**: `Map.get` on a DenseMap-backed map (>4 entries) raises instead of returning default:
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})  # >4 entries => DenseMap
amap.get(101)  # RAISED IndexError instead of returning None
```

**After (fixed)**: `Map.get` correctly returns `None` for missing keys:
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})
assert amap.get(101) is None   # correctly returns None
assert amap.get(3) == 9        # existing key still works
```
