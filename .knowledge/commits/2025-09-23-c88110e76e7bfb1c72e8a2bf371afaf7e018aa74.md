# Fix Map.get to return default instead of throwing on missing key
## TL;DR
- Changed exception kind in `DenseMapObj::At` from `IndexError` to `KeyError` when a key is missing from a Map.
- This fixes `Map.get` in Python, which catches `KeyError` to return a default value -- previously the `IndexError` propagated uncaught.
- Added a Python test (`test_large_map_get`) confirming `Map.get` returns `None` for absent keys and the correct value for present keys.

## Key Exports
**Functions (mutated)**:
```cpp
// DenseMapObj::At — error kind changed from IndexError to KeyError
mapped_type& DenseMapObj::At(const key_type& key) const;
// Throws: TVM_FFI_THROW(KeyError) << "key is not in Map"  (was IndexError)
```

## Impact
- API: None (C++ `At` signature unchanged; Python `Map.get` signature unchanged).
- Behavioral: `DenseMapObj::At` now throws `KeyError` instead of `IndexError` on missing key. Any C++ or Python caller catching `IndexError` from `Map::at`/`Map.__getitem__` must update to catch `KeyError`. Python `Map.get` now correctly returns the default value instead of throwing.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Map container** ([0008-containers](../designs/0008-containers.md)): `DenseMapObj::At` is the C++ lookup-or-throw method used by Python's `Map.__getitem__`.
- **Error handling** ([0006-error-handling](../designs/0006-error-handling.md)): `TVM_FFI_THROW(ErrorKind)` macro with string-based error kinds that map to Python exception types via `ERROR_NAME_TO_TYPE` in `error.pxi`.
- **Cross-layer error mapping**: The error kind string `"KeyError"` maps to Python's `KeyError` in `error.pxi:74` (`ERROR_NAME_TO_TYPE.get(self.kind, RuntimeError)`), which is then caught by `Map.get`'s `except KeyError:` handler in `container.py:309`.

Design elements this commit produces: None.

## Usage Examples
**Before (broken)**: `Map.get` threw `IndexError` on missing key because the C++ side raised `IndexError`, which Python's `except KeyError:` did not catch:
```python
amap = tvm_ffi.convert({1: 1, 2: 4})
amap.get(999)  # THREW IndexError instead of returning None
```

**After (fixed)**: `Map.get` returns `None` (or the provided default) because C++ now raises `KeyError`, matching the `except KeyError:` handler:
```python
amap = tvm_ffi.convert({k: k**2 for k in range(100)})
assert amap.get(101) is None   # correct: returns None
assert amap.get(3) == 9        # correct: returns value
```
