# Fix Windows Ninja builds by running in MSVC Developer Command Prompt
## TL;DR
- On Windows, `_build_ninja` now invokes Ninja through `_run_command_in_dev_prompt`, which discovers the VS installation via `vswhere.exe` and sources `VsDevCmd.bat -arch=x64` before executing the build command.
- Four `test_load_inline` tests had their `@pytest.mark.xfail` (win32) markers removed, confirming the fix enables Windows CI.

## Impact
- API: none -- `_run_command_in_dev_prompt` is internal; `load_inline` public API unchanged.
- Behavioral: On Windows, Ninja builds now succeed without the user manually launching a Developer Command Prompt. `cl.exe`, `link.exe`, and MSVC environment variables are automatically available.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
**Before (broken)**: On Windows, `load_inline` called `subprocess.run(["ninja", "-v"], ...)` directly. If the user was not already in a Developer Command Prompt, `cl.exe` was not on PATH and the Ninja build failed with "cl not found" or link errors.

**After (fixed)**: `_build_ninja` detects `IS_WINDOWS` and routes through `_run_command_in_dev_prompt`, which auto-discovers Visual Studio and sources `VsDevCmd.bat`:
```python
# Internal call chain (not user-facing):
# _build_ninja("C:/Users/user/.cache/tvm-ffi/hello_abc123/")
#   -> _run_command_in_dev_prompt(["ninja", "-v"], cwd=..., capture_output=True)
#     -> discovers VS via vswhere.exe
#     -> runs: cmd.exe /c "C:\...\VsDevCmd.bat -arch=x64 & ninja -v"
```
