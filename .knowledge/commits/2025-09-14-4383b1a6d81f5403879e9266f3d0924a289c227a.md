# Fix Windows ninja build by running it inside the MSVC developer environment

## TL;DR
- On Windows, `ninja` must run inside a MSVC developer environment (VsDevCmd.bat) so that `cl.exe` and linker tools are on PATH; bare `subprocess.run` was failing.
- Adds `_run_command_in_dev_prompt()` helper that locates Visual Studio via `vswhere.exe` and wraps the command as `cmd.exe /c VsDevCmd.bat -arch=x64 & <command>`.
- Removes 4 `@pytest.mark.xfail(sys.platform.startswith("win"), ...)` markers from `test_load_inline.py`, indicating these tests are now expected to pass on Windows.

## Usage Examples

**Before (broken on Windows):**
```python
# _build_ninja would fail on Windows because cl.exe not on PATH:
status = subprocess.run(args=["ninja", "-C", build_dir], cwd=build_dir, capture_output=True)
# returncode != 0 -> raises RuntimeError("ninja exited with status 1")
```

**After (fixed on Windows):**
```python
# _build_ninja dispatches to MSVC-aware helper on Windows:
if IS_WINDOWS:
    status = _run_command_in_dev_prompt(args=["ninja", "-C", build_dir], cwd=build_dir, capture_output=True)
else:
    status = subprocess.run(args=["ninja", "-C", build_dir], cwd=build_dir, capture_output=True)
# VsDevCmd.bat sources cl.exe into PATH before ninja runs
```
