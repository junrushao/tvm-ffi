# Fix Windows load_inline by running ninja build inside MSVC developer environment
## TL;DR
- On Windows, the `ninja` build step in `load_inline` failed because `cl.exe` (MSVC compiler) requires the Visual Studio Developer Command Prompt environment variables to be set. This commit adds `_run_command_in_dev_prompt()` which discovers the VS installation via `vswhere.exe`, sources `VsDevCmd.bat`, and chains the build command.
- Removes `@pytest.mark.xfail` from all four `test_load_inline_cpp*` tests on Windows, confirming the fix.
- Removes unused `import sys` from the test file.

## Impact
- API: none -- `_run_command_in_dev_prompt` is a private helper, not public API.
- Behavioral: `_build_ninja` on Windows now succeeds when MSVC environment variables are not pre-set in the calling shell. Previously, `ninja` would invoke `cl.exe` which would fail to find headers/libs without the VS developer environment.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system / `load_inline` build pipeline** ([0011-module-system.md](../designs/0011-module-system.md)): The `_build_ninja` function is the build step in the `load_inline` pipeline. This commit patches its Windows path to wrap the `ninja` invocation in the MSVC developer environment.
- **IS_WINDOWS platform flag** in `load_inline.py`: Used to gate the developer-prompt wrapping.

Design elements this commit produces:
- **`_run_command_in_dev_prompt` helper**: A new internal function that discovers the Visual Studio installation via `vswhere.exe` and runs arbitrary commands inside the `VsDevCmd.bat` environment. This is a reusable pattern for any future Windows subprocess calls that need MSVC toolchain access.

## Usage Examples

Before (broken on Windows -- `cl.exe` cannot find headers/libs without VS environment):
```python
# _build_ninja called subprocess.run directly:
status = subprocess.run(args=["ninja", "-v"], cwd=build_dir, capture_output=True)
# Result: ninja invokes cl.exe, which fails because INCLUDE/LIB/PATH are not set
```

After (fixed -- ninja runs inside MSVC developer environment):
```python
# _build_ninja now wraps via VsDevCmd.bat on Windows:
if IS_WINDOWS:
    status = _run_command_in_dev_prompt(args=["ninja", "-v"], cwd=build_dir, capture_output=True)
    # Internally: cmd.exe /c "VsDevCmd.bat -arch=x64 & ninja -v"
else:
    status = subprocess.run(args=["ninja", "-v"], cwd=build_dir, capture_output=True)
```
