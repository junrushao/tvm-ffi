# Enhance DLPack exchange speed with DLPackPyObjectExporter/Importer/TensorAllocator and optional GIL release
## TL;DR
- Introduces three new function pointer types (`DLPackPyObjectExporter`, `DLPackPyObjectImporter`, `DLPackTensorAllocator`) to accelerate cross-framework tensor conversion, enabling C-level bidirectional DLPack exchange and environment-driven tensor allocation without Python overhead.
- Adds a thread-local `DLPackTensorAllocator` context (`TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator`) in the extra-tier `EnvContext`, unifying stream and allocator context into a single TLS class (replacing the old `StreamContext`). This enables C++ functions to allocate tensors using the caller's framework allocator (e.g., `torch.empty` via `FromDLPackAlloc`).
- Converts the `Function` class from a Python `class` to a Cython `cdef class` with a `release_gil` property (defaulting to `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var), allowing per-function opt-out of GIL release for short-running functions to avoid the GIL release/acquire overhead.
- Renames `TVMFFIEnvSetCurrentStream`/`TVMFFIEnvGetCurrentStream` to `TVMFFIEnvSetStream`/`TVMFFIEnvGetStream` and renames the DLPack exporter protocol from `__dlpack_c_exporter__` to `__c_dlpack_exporter__` with new `__c_dlpack_importer__` and `__c_dlpack_tensor_allocator__` class attributes.

## Impact
- **API (C ABI)**: New `DLPackTensorAllocator` typedef added to `c_api.h`. New `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator` C functions in `c_env_api.h`. **Breaking rename**: `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream`, `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream`. Any downstream kernel code calling these stream APIs must update.
- **API (Python)**: `DLPackPyObjectCExporter` renamed to `DLPackPyObjectExporter`. New `DLPackPyObjectImporter` type. Protocol attribute renamed from `__dlpack_c_exporter__` to `__c_dlpack_exporter__`. New `__c_dlpack_importer__` and `__c_dlpack_tensor_allocator__` class-level attributes. `Function` is now a `cdef class` with `release_gil` property. When torch is available, returned `Tensor` values are auto-converted back to `torch.Tensor` via the importer. `DLTensorTestWrapper` protocol attribute renamed accordingly.
- **API (C++)**: `Tensor::FromDLPackAlloc` static method added to `include/tvm/ffi/container/tensor.h`, consuming a `DLPackTensorAllocator` function pointer.
- **Flags/config**: New environment variable `TVM_FFI_RELEASE_GIL_BY_DEFAULT` (default "1") controls whether FFI function calls release the GIL. New `TVM_FFI_SKIP_C_DLPACK_EXPORTER` env var to disable the C DLPack exporter path.
- **Data formats/schemas**: No change to on-disk formats.
- **Files restructured**: `src/ffi/extra/stream_context.cc` deleted and replaced by `src/ffi/extra/env_context.cc` which consolidates both stream and allocator TLS. New file `python/tvm_ffi/_optional_torch_c_dlpack.py` (403 lines) JIT-compiles a C++ extension for fast PyTorch DLPack export/import/allocate. New files `licenses/LICENSE.pytorch.txt` and `licenses/NOTICE.pytorch.txt` for the vendored PyTorch code.
- **GIL behavior change**: DLPack tensor operations (`TVMFFITensorFromDLPack`, `TVMFFITensorToDLPack`, etc.) no longer release the GIL in Cython (`with nogil` blocks removed from `tensor.pxi`), because they are fast in-process operations where GIL release overhead exceeds computation cost.

## Design Elements

Design elements this commit consumes:
- **Thread-local stream context** ([`.knowledge/ADRs/0020-thread-local-stream-context.md`](../ADRs/0020-thread-local-stream-context.md)): Extended from stream-only `StreamContext` to a combined `EnvContext` holding both stream table and DLPack allocator. The `SetStream`/`GetStream` contract is preserved; the class is renamed and gains allocator fields.
- **Extra API tier** ([`.knowledge/designs/0011-extra-api-tier.md`](../designs/0011-extra-api-tier.md)): `env_context.cc` is compiled under `TVM_FFI_USE_EXTRA_CXX_API`. The new `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator` follow the same `extern "C"` pattern as the stream APIs.
- **C ABI** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): `DLPackTensorAllocator` typedef added to `c_api.h` using the established error-propagation callback pattern (`SetError(error_ctx, kind, message)`).
- **Python bindings argument packing** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The `TVMFFIPyArgSetter` and `TVMFFIPyCallContext` structs are extended with `c_dlpack_importer` and `c_dlpack_tensor_allocator` fields. The call manager now threads allocator/importer through the call context.
- **Tensor container** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): `Tensor::FromDLPackAlloc` creates tensors via an external allocator, wrapping the result in `TensorObjFromDLPack<DLManagedTensorVersioned>`.
- **Generic stream exchange protocol** ([`.knowledge/ADRs/0030-generic-stream-exchange-protocol.md`](../ADRs/0030-generic-stream-exchange-protocol.md)): The `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream` rename reverses the rename done in commit `db98729`, returning to the shorter name for alignment with CUDA API style.
- **Inline module compilation** ([`.knowledge/designs/0017-inline-module-compilation.md`](../designs/0017-inline-module-compilation.md)): The `_optional_torch_c_dlpack.py` module uses `torch.utils.cpp_extension.load_inline` (PyTorch's JIT mechanism) with `libinfo.include_paths()` to compile the C++ DLPack extension.
- **DLPack import defaults** ([`.knowledge/ADRs/0031-relaxed-dlpack-import-defaults.md`](../ADRs/0031-relaxed-dlpack-import-defaults.md)): The relaxed defaults remain; this commit builds on them.

Design elements this commit produces:
- **`DLPackTensorAllocator` C ABI type** (`include/tvm/ffi/c_api.h`): A C-style function pointer for allocating DLPack tensors from a prototype. Uses the error-propagation callback pattern. This is a new stable ABI surface used by both C++ (`Tensor::FromDLPackAlloc`) and Python (via `TVMFFIEnvSetTensorAllocator`).
- **`DLPackPyObjectExporter` / `DLPackPyObjectImporter` Python-level types** (`python/tvm_ffi/cython/tvm_ffi_python_helpers.h`): Renamed and expanded from `DLPackPyObjectCExporter`. The importer enables automatic conversion of returned tensors back to the caller's framework tensor type.
- **`EnvContext` unified TLS class** (`src/ffi/extra/env_context.cc`): Replaces `StreamContext`. Holds both `stream_table_` and `dlpack_allocator_` per thread. The allocator has a two-tier lookup: TLS first, then global static (for cases where the allocator is set once globally).
- **`Tensor::FromDLPackAlloc`** (`include/tvm/ffi/container/tensor.h`): Static factory method that uses a `DLPackTensorAllocator` to create tensors. Error propagation uses an inner `ErrorContext` struct with a static `SetError` callback.
- **`Function.release_gil` property** (`python/tvm_ffi/cython/function.pxi`): `Function` is now `cdef class` with a `c_release_gil` C-level field. Defaults from `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var. Passed through `TVMFFIPyFuncCall` -> `TVMFFIPyCallManager::Call` which conditionally wraps the function call in `Py_BEGIN_ALLOW_THREADS`/`Py_END_ALLOW_THREADS`.
- **Return-path DLPack importer** (`python/tvm_ffi/cython/function.pxi`, `tensor.pxi`): When a function call returns a `Tensor` and an importer is available (from the argument setter), `make_tensor_from_chandle` converts the result to the framework's tensor type (e.g., `torch.Tensor`) before returning to Python.
- **`_optional_torch_c_dlpack` module** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): JIT-compiled C++ extension that provides `TorchDLPackPyObjectExporter`, `TorchDLPackPyObjectImporter`, and `TorchDLPackTensorAllocator`. Sets `torch.Tensor.__c_dlpack_exporter__`, `torch.Tensor.__c_dlpack_importer__`, and `torch.Tensor.__c_dlpack_tensor_allocator__` as class-level integer attributes (function pointers cast to `int64_t`).
- **`libinfo.include_paths()`** (`python/tvm_ffi/libinfo.py`): New convenience function combining `find_include_path()`, `find_python_helper_include_path()`, and `find_dlpack_include_path()`. Also exposes `find_python_helper_include_path()` for finding `tvm_ffi_python_helpers.h`.
- **Allocator context save/restore** (`python/tvm_ffi/cython/tvm_ffi_python_helpers.h`, `TVMFFIPyCallManager::Call`): The call manager now saves/restores `DLPackTensorAllocator` around function calls, similar to the existing stream context save/restore pattern.

## Reflection

### Design docs to write

- **`.knowledge/designs/0019-dlpack-exchange-acceleration.md`**: Should cover the `DLPackTensorAllocator`, `DLPackPyObjectExporter`, `DLPackPyObjectImporter` types, their C ABI contracts, the `EnvContext` unified TLS, the `__c_dlpack_exporter__`/`__c_dlpack_importer__`/`__c_dlpack_tensor_allocator__` Python protocol, and the `_optional_torch_c_dlpack` JIT module. This is a major new subsystem that touches C ABI, C++ API, Cython bindings, and framework integration -- currently it has no design doc. Future commits involving framework tensor interop, allocator providers, or DLPack performance work would reference it.

### ADRs to write

- **`.knowledge/ADRs/0033-env-allocator-two-tier-lookup.md`**: The `EnvContext::GetDLPackTensorAllocator()` uses a two-tier lookup (TLS first, then global static). This decision trades simplicity for flexibility: the global allocator is convenient for single-framework deployments, but the TLS allocator enables per-call framework switching. The alternative of TLS-only (simpler) was presumably rejected because of the overhead of setting TLS on every function call in the common single-framework case. The alternative of global-only would break multi-framework or multi-thread scenarios.
- **`.knowledge/ADRs/0034-optional-gil-release.md`**: The decision to make GIL release optional per function (via `release_gil` property, default from env var) rather than always releasing. Context: for short-running FFI functions, the cost of `Py_BEGIN_ALLOW_THREADS`/`Py_END_ALLOW_THREADS` (~50ns on typical platforms) can be a significant fraction of total call time. Alternatives: (1) always release (was the status quo, suboptimal for fast calls), (2) never release (blocks Python threads during long calls), (3) heuristic auto-detection (too complex). Trade-off: user must opt-in to no-GIL for performance-sensitive short calls.
- **`.knowledge/ADRs/0035-stream-api-rename-to-short-form.md`**: `TVMFFIEnvSetCurrentStream`/`TVMFFIEnvGetCurrentStream` renamed to `TVMFFIEnvSetStream`/`TVMFFIEnvGetStream`. This reverses the rename from commit `db98729` (which went the other direction). The rationale is alignment with CUDA API naming (`cudaStreamCreate` not `cudaSetCurrentStream`). This is an ABI-breaking change for any downstream code calling the C functions. The ADR should document why the final short form was chosen and the breaking change implications.

### Design diagrams to draw

- **Mermaid sequence diagram**: DLPack round-trip flow for torch.Tensor argument passing and return conversion. Should depict: Python caller passes `torch.Tensor` -> `TVMFFIPyArgSetterDLPackCExporter_` calls `TorchDLPackPyObjectExporter` -> Cython packs as `kTVMFFITensor` + sets importer/allocator on `TVMFFIPyCallContext` -> `TVMFFIPyCallManager::Call` sets stream and allocator via env APIs -> C++ function executes, optionally calls `Tensor::FromDLPackAlloc(TVMFFIEnvGetTensorAllocator())` -> return path: `make_ret` -> `make_tensor_from_any` -> `make_tensor_from_chandle` with importer -> `TorchDLPackPyObjectImporter` converts back to `torch.Tensor` -> Python caller receives `torch.Tensor`.
