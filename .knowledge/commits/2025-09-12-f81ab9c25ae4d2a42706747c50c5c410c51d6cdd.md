# Enhance DLPack exchange speed and behavior with new exporter/importer/allocator function pointers
## TL;DR
- Introduces three new C-level function pointer types (`DLPackPyObjectExporter`, `DLPackPyObjectImporter`, `DLPackTensorAllocator`) and a class-attribute protocol (`__c_dlpack_exporter__`, `__c_dlpack_importer__`, `__c_dlpack_tensor_allocator__`) to speed up DLPack exchange between frameworks (especially PyTorch) and TVM FFI. When PyTorch is available, a JIT-compiled C++ extension (`_optional_torch_c_dlpack.py`) sets these attributes on `torch.Tensor`, enabling direct C-level conversion without going through Python's DLPack capsule protocol.
- Renames `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream` and `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream` (reverting the db98729 rename to align with CUDA API style).
- Adds `TVMFFIEnvSetTensorAllocator` and `TVMFFIEnvGetTensorAllocator` C APIs for managing a thread-local + global `DLPackTensorAllocator` in the env context.
- Adds `Tensor::FromDLPackAlloc` C++ static method for creating tensors via an environment-provided allocator.
- Converts `Function` from a Python `class` to a Cython `cdef class` with a `release_gil` property (default controlled by `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var, defaulting to 1).
- Removes `with nogil` blocks from individual DLPack conversion calls in `tensor.pxi` (GIL release is now handled at the `Function.__call__` level).
- Renames the source file `src/ffi/extra/stream_context.cc` -> `src/ffi/extra/env_context.cc`, expanding `StreamContext` to `EnvContext` which holds both stream table and tensor allocator state.
- Installs `tvm_ffi_python_helpers.h` to the include directory and adds `libinfo.include_paths()` / `libinfo.find_python_helper_include_path()` for downstream C++ extensions.

## Key Exports

**New C type** (in `c_api.h`):
- `DLPackTensorAllocator` -- C function pointer typedef: `int (*)(DLTensor* prototype, DLManagedTensorVersioned** out, void* error_ctx, void (*SetError)(void*, const char*, const char*))`. Error propagation uses a callback pattern rather than TLS.

**New C APIs** (in `c_env_api.h`):
- `TVMFFIEnvSetTensorAllocator(DLPackTensorAllocator allocator, int write_to_global_context, DLPackTensorAllocator* opt_out_original_allocator) -> int` -- Set thread-local (and optionally global) tensor allocator.
- `TVMFFIEnvGetTensorAllocator() -> DLPackTensorAllocator` -- Get current allocator (global first, then TLS fallback).

**Renamed C APIs** (in `c_env_api.h`):
- `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream`
- `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream`

**New C++ method** (in `container/tensor.h`):
- `static Tensor Tensor::FromDLPackAlloc(DLPackTensorAllocator allocator, ffi::Shape shape, DLDataType dtype, DLDevice device)` -- Create a Tensor by calling an external allocator. Intended for use with `TVMFFIEnvGetTensorAllocator()`.

**New C++ types** (in `tvm_ffi_python_helpers.h`):
- `DLPackPyObjectExporter` -- `int (*)(void* py_obj, DLManagedTensorVersioned** out, void** env_stream)`. Exports a Python tensor to DLManagedTensorVersioned at C level.
- `DLPackPyObjectImporter` -- `int (*)(DLManagedTensorVersioned* tensor, void** py_obj_out)`. Imports a DLManagedTensorVersioned back to a Python tensor at C level.
- `TVMFFIPyCallContext` gains `c_dlpack_importer` and `c_dlpack_tensor_allocator` fields.
- `TVMFFIPyArgSetter` gains `c_dlpack_exporter`, `c_dlpack_importer`, `c_dlpack_tensor_allocator` fields (replaces old `dlpack_c_exporter`).
- `TVMFFIPyFuncCall` and `TVMFFIPyCallManager::Call` gain `release_gil` and `out_dlpack_importer` parameters.

**New Python module**:
- `tvm_ffi._optional_torch_c_dlpack` -- JIT-compiles a C++ extension via `torch.utils.cpp_extension.load_inline` that provides `TorchDLPackPyObjectExporter`, `TorchDLPackPyObjectImporter`, and `TorchDLPackTensorAllocator`. Sets `torch.Tensor.__c_dlpack_exporter__`, `torch.Tensor.__c_dlpack_importer__`, `torch.Tensor.__c_dlpack_tensor_allocator__` class attributes.

**New Python API** (`tvm_ffi.libinfo`):
- `find_python_helper_include_path() -> str` -- Locate `tvm_ffi_python_helpers.h`.
- `include_paths() -> list[str]` -- Return all include paths needed for FFI-related C++ compilation.

**Changed Python API**:
- `Function` is now a `cdef class` (was `class`). Gains `release_gil` property (bool, default from `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var).
- `make_ret(result, c_dlpack_importer)` -- gains second parameter; when a `DLPackPyObjectImporter` is available, returned tensors are automatically converted back to the caller framework (e.g., `torch.Tensor`).

**Renamed Python protocol attributes**:
- `__dlpack_c_exporter__` -> `__c_dlpack_exporter__`
- New: `__c_dlpack_importer__`, `__c_dlpack_tensor_allocator__`

**New env var**:
- `TVM_FFI_RELEASE_GIL_BY_DEFAULT` -- Controls default GIL release behavior (1 = release, 0 = hold). Default: 1.
- `TVM_FFI_SKIP_C_DLPACK_EXPORTER` -- If "1", skip the fast C DLPack exporter path.

**Renamed internal C++ class**:
- `StreamContext` -> `EnvContext` (in `env_context.cc`). Gains `DLPackTensorAllocator` TLS + global management alongside the existing stream table.

## Impact
- API: **Breaking** -- `TVMFFIEnvSetCurrentStream` and `TVMFFIEnvGetCurrentStream` are renamed to `TVMFFIEnvSetStream` and `TVMFFIEnvGetStream`. The old names no longer exist. Any C/C++ code calling the old names must update. The Python attribute `__dlpack_c_exporter__` is renamed to `__c_dlpack_exporter__`.
- ABI: **Breaking** -- The stream context C API symbols changed names. `TVMFFIPyArgSetter` struct layout changed (field renamed and new fields added). `TVMFFIPyFuncCall` signature changed.
- Behavioral: When PyTorch is installed and `_optional_torch_c_dlpack` loads successfully, DLPack conversion bypasses Python's capsule protocol entirely, using direct C-level function pointers. Return values of type `Tensor` are automatically converted back to `torch.Tensor` when a `DLPackPyObjectImporter` is available. The GIL release is now controlled per-function via `Function.release_gil` rather than being unconditional. Individual DLPack conversion calls in `tensor.pxi` no longer release the GIL (it is released at the `Function.__call__` level instead).
- Flags/config: `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var controls default GIL behavior. `TVM_FFI_SKIP_C_DLPACK_EXPORTER` env var can disable fast path.
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **Thread-local stream context** (`.knowledge/designs/c-abi.md` > Extra C Env API > Stream Context APIs) -- the 2D `vector<vector<void*>>` thread-local stream table, previously in `StreamContext`. Now subsumed into `EnvContext`.
- **DLPack interop** (`.knowledge/designs/c-abi.md` > `TVMFFITensor{From,To}DLPack{,Versioned}`) -- existing C ABI for DLPack tensor conversion, used by the new allocator and importer paths.
- **Packed calling convention** (`.knowledge/designs/function-system.md` > Python Calling Convention) -- `TVMFFIPyFuncCall` / `TVMFFIPyCallManager::Call` which marshals args, manages stream context, and calls `TVMFFIFunctionCall`.
- **`TensorObjFromDLPack`** (`.knowledge/designs/containers.md` or tensor internals) -- template class used by `Tensor::FromDLPackAlloc` to wrap the allocated `DLManagedTensorVersioned`.
- **`libinfo.py` discovery** (`.knowledge/designs/0015-python-packaging.md`) -- header/library path discovery, extended with `find_python_helper_include_path()` and `include_paths()`.
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`) -- `load_inline` used by the PyTorch extension JIT compilation in `_optional_torch_c_dlpack.py`.

Design elements this commit produces:
- **DLPack fast path protocol** -- A new C-level protocol for bypassing Python DLPack capsule overhead. Framework tensors expose `__c_dlpack_exporter__` (int pointer to `DLPackPyObjectExporter`), `__c_dlpack_importer__` (int pointer to `DLPackPyObjectImporter`), and `__c_dlpack_tensor_allocator__` (int pointer to `DLPackTensorAllocator`) as class attributes. The arg setter detects these and uses direct C function calls instead of Python's `__dlpack__` protocol.
- **Environment tensor allocator** -- A two-tier (TLS + global) allocator mechanism via `TVMFFIEnvSetTensorAllocator` / `TVMFFIEnvGetTensorAllocator`. The allocator is set in the Python call context when `__c_dlpack_tensor_allocator__` is detected on an argument, enabling kernel code to allocate output tensors in the caller's framework (e.g., `torch.empty`) via `Tensor::FromDLPackAlloc(TVMFFIEnvGetTensorAllocator(), ...)`.
- **Automatic return-value framework conversion** -- When a `DLPackPyObjectImporter` is captured during argument packing, `make_ret` uses it to convert returned `Tensor` objects back to the caller framework's tensor type (e.g., `ffi::Tensor` -> `torch.Tensor`).
- **Per-function GIL control** -- `Function.release_gil` property allows per-function control over whether the GIL is released during the C call. Default is controlled by `TVM_FFI_RELEASE_GIL_BY_DEFAULT` (default 1).
- **EnvContext** -- Replaces `StreamContext`. Thread-local singleton holding both the stream table and `DLPackTensorAllocator`. Has a static `GlobalTensorAllocator()` for cross-thread allocator sharing.

## Usage Examples

**Using the fast DLPack path (automatic when PyTorch is installed)**:
```python
import tvm_ffi
import torch

# _optional_torch_c_dlpack auto-loads and sets class attributes on torch.Tensor
x = torch.randn(1024, device="cuda")
fecho = tvm_ffi.get_global_func("testing.echo")
y = fecho(x)  # Fast C-level export -> call -> C-level import back to torch.Tensor
assert isinstance(y, torch.Tensor)
assert y.data_ptr() == x.data_ptr()
```

**Using the environment tensor allocator in C++ kernel code**:
```cpp
#include <tvm/ffi/container/tensor.h>

ffi::Tensor my_kernel(DLTensor* x) {
    DLDataType f32{kDLFloat, 32, 1};
    // Allocates via torch.empty when called from Python with torch tensors
    ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
        TVMFFIEnvGetTensorAllocator(), ffi::Shape({x->shape[0]}), f32, x->device);
    // ... fill y ...
    return y;  // Automatically converted back to torch.Tensor by the importer
}
```

**Controlling GIL release**:
```python
func = tvm_ffi.get_global_func("my_short_func")
func.release_gil = False  # Don't release GIL for very short functions
result = func(arg)
```
