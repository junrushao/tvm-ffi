# Introduce DLPack exchange acceleration (exporter/importer/allocator), rename SetCurrentStream to SetStream, add GIL release control
## TL;DR
- Introduces three new C-style function pointer types (`DLPackPyObjectExporter`, `DLPackPyObjectImporter`, `DLPackTensorAllocator`) enabling fast, zero-copy DLPack tensor exchange between Python frameworks (especially PyTorch) and the TVM FFI, plus a thread-local tensor allocator context.
- Renames `TVMFFIEnvSetCurrentStream`/`TVMFFIEnvGetCurrentStream` to `TVMFFIEnvSetStream`/`TVMFFIEnvGetStream`; renames `stream_context.cc` to `env_context.cc` (which now also hosts the allocator context); renames `DLPackPyObjectCExporter` to `DLPackPyObjectExporter` and `__dlpack_c_exporter__` to `__c_dlpack_exporter__`.
- Adds `release_gil` property on `Function` (default `True`, configurable per-function or via `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var) to optionally skip GIL release for short-running functions.

| Old Name | New Name |
|---|---|
| `TVMFFIEnvSetCurrentStream` | `TVMFFIEnvSetStream` |
| `TVMFFIEnvGetCurrentStream` | `TVMFFIEnvGetStream` |
| `DLPackPyObjectCExporter` | `DLPackPyObjectExporter` |
| `__dlpack_c_exporter__` | `__c_dlpack_exporter__` |
| `_torch_dlpack_c_exporter_ptr` | (removed -- replaced by per-class attrs) |
| `stream_context.cc` | `env_context.cc` |
| `StreamContext` (C++) | `EnvContext` (C++) |
| `TVMFFIPyArgSetterTorch_` | `TVMFFIPyArgSetterTorchFallback_` |

## Impact
- API: Breaking rename of `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream` and `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream` in `c_env_api.h`. Python dunder protocol renamed `__dlpack_c_exporter__` -> `__c_dlpack_exporter__`. `DLPackPyObjectCExporter` renamed to `DLPackPyObjectExporter`. `Function` is now a `cdef class` (from `class`), gaining `release_gil` property. Constructor calls now use `release_gil=False` (no GIL release for short constructor calls).
- Behavioral: Tensor return values from FFI calls can now be auto-converted back to the caller's framework type (e.g., `torch.Tensor`) via `DLPackPyObjectImporter`. DLPack import functions (`_from_dlpack`, `_from_dlpack_versioned`, `_to_dlpack`, `_to_dlpack_versioned`) no longer release GIL (`with nogil:` blocks removed).
- Flags/config: `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var (default `"1"`) controls default GIL behavior. `TVM_FFI_SKIP_C_DLPACK_EXPORTER` env var (default `"0"`) disables fast DLPack C exporter dispatch.
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **C ABI (0007)**: Adds `DLPackTensorAllocator` typedef to `c_api.h`, adds `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator` to `c_env_api.h`, renames stream functions.
- **Container/Tensor (0006)**: Adds `Tensor::FromDLPackAlloc` static method using the new allocator callback pattern.
- **Module system (0011)**: Renames `StreamContext` -> `EnvContext`, extends it with allocator support, replaces `stream_context.cc` with `env_context.cc`.
- **Python bindings (0012)**: Extends Cython call manager (`TVMFFIPyCallManager::Call`) with `release_gil` and `optional_out_dlpack_importer` parameters. Converts `Function` from Python class to `cdef class`.

Design elements this commit produces:
- **DLPack exchange protocol**: Three C function pointer types (`DLPackPyObjectExporter`, `DLPackPyObjectImporter`, `DLPackTensorAllocator`) that form a protocol for fast cross-framework tensor exchange. Detected via `__c_dlpack_exporter__`, `__c_dlpack_importer__`, `__c_dlpack_tensor_allocator__` dunder attributes on Python objects.
- **Env tensor allocator context**: Thread-local + global `DLPackTensorAllocator` stored in `EnvContext`, set/get via `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator`. Enables C++ library code to allocate tensors using the caller's framework allocator.
- **GIL release control**: Per-function `release_gil` property on `Function`, defaulting from `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var.
- **Torch C DLPack extension** (`_optional_torch_c_dlpack.py`): JIT-compiled C++ extension that provides `TorchDLPackPyObjectExporter`, `TorchDLPackPyObjectImporter`, `TorchDLPackTensorAllocator` for PyTorch, patched onto `torch.Tensor` as dunder attributes.

## Usage Examples

C++ library code allocating a tensor through the environment allocator, then Python calling it with PyTorch tensors and getting a `torch.Tensor` back:

```cpp
// C++ kernel library (compiled via load_inline)
ffi::Tensor return_add_one(DLTensor* x) {
  // Allocate output using env allocator -- redirects to torch.empty when called from PyTorch
  ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
    TVMFFIEnvGetTensorAllocator(), ffi::Shape({x->shape[0]}), f32_dtype, x->device);
  // Get current stream (set by PyTorch context)
  cudaStream_t stream = static_cast<cudaStream_t>(
    TVMFFIEnvGetStream(x->device.device_type, x->device.device_id));
  AddOneKernel<<<nblock, nthread, 0, stream>>>(x->data, y->data, n);
  return y;
}
```

# Python caller -- torch.Tensor flows in and out via DLPack exchange

y_cuda = mod.return_add_one(x_cuda)
assert isinstance(y_cuda, torch.Tensor)  # auto-converted back to torch.Tensor
