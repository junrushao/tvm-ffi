# Enhance DLPack exchange speed with DLPackPyObjectExporter/Importer/TensorAllocator and add GIL release control
## TL;DR
- Introduces three C-style function pointer types (`DLPackPyObjectExporter`, `DLPackPyObjectImporter`, `DLPackTensorAllocator`) for fast cross-framework DLPack tensor conversion, bypassing Python-level `__dlpack__`/`from_dlpack` overhead.
- Adds a `DLPackTensorAllocator`-based tensor creation path (`Tensor::FromDLPackAlloc`) enabling C++ code to allocate tensors via the host environment's allocator (e.g., `torch.empty`), with thread-local/global allocator context managed by new `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator` C APIs.
- Renames `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream` and `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream` (reverting the earlier rename from commit db98729).
- Adds per-function `release_gil` control on Python `Function` objects, defaulting to `True` (controllable via `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var).
- Adds optional JIT-compiled torch C DLPack extension (`_optional_torch_c_dlpack.py`) that sets `__c_dlpack_exporter__`/`__c_dlpack_importer__`/`__c_dlpack_tensor_allocator__` on `torch.Tensor`.

## Key Exports

**C typedef** (in `c_api.h`):
```c
typedef int (*DLPackTensorAllocator)(
    DLTensor* prototype, DLManagedTensorVersioned** out, void* error_ctx,
    void (*SetError)(void* error_ctx, const char* kind, const char* message)
);
```
Error is propagated via the `SetError` callback, not via return code semantics alone.

**C typedefs** (in `tvm_ffi_python_helpers.h`):
```c
typedef int (*DLPackPyObjectExporter)(void* py_obj, DLManagedTensorVersioned** out, void** env_stream);
typedef int (*DLPackPyObjectImporter)(DLManagedTensorVersioned* tensor, void** py_obj_out);
```
Both return 0 on success, -1 on failure with `PyErr` set.

## Impact
- API: **Breaking C ABI rename** -- `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream`, `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream`. All C callers of the old symbols must update. Two new C API functions (`TVMFFIEnvSetTensorAllocator`, `TVMFFIEnvGetTensorAllocator`). New `DLPackTensorAllocator` typedef in core `c_api.h`.
- Behavioral: (1) Torch tensors returned from FFI calls are now auto-converted back to `torch.Tensor` (via `c_dlpack_importer`) instead of `tvm_ffi.Tensor`. (2) DLPack conversion for `__c_dlpack_exporter__` objects is significantly faster (bypasses Python `__dlpack__` protocol). (3) `nogil` blocks removed from several DLPack conversion paths in Cython (tensor.pxi) since GIL release is now controlled at the function call level. (4) `Function` class changed from `class` to `cdef class` in Cython for attribute support.
- Flags/config: `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var (default "1"). `TVM_FFI_SKIP_C_DLPACK_EXPORTER` env var (default "0") to disable fast path.
- Data formats/schemas: `tvm_ffi_python_helpers.h` is now installed to `include/` via CMake `install()`, enabling JIT compilation against it.

- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): `load_inline` test exercises the new tensor allocator path end-to-end.

Design elements this commit produces:
- **DLPack exchange protocol** (three function pointer types: `DLPackPyObjectExporter`, `DLPackPyObjectImporter`, `DLPackTensorAllocator`): A C-level fast path for cross-framework tensor conversion, bypassing Python's `__dlpack__`/`from_dlpack`. Objects opt in via dunder attributes (`__c_dlpack_exporter__`, `__c_dlpack_importer__`, `__c_dlpack_tensor_allocator__`).
- **Environment tensor allocator context**: Thread-local + global allocator stored in `EnvContext`, accessible via `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator`. Enables C++ kernel code to allocate tensors using the host framework's allocator.
- **GIL release control**: Per-function `release_gil` property on `Function`, with global default via env var.
- **`EnvContext` class**: Replaces `StreamContext`, combining stream table and tensor allocator in a single TLS singleton.

## Usage Examples

### C++ kernel allocating via environment tensor allocator
**Context**: A CUDA kernel returns a new tensor allocated by the host environment (e.g., torch.empty).
```cpp
#include <tvm/ffi/container/tensor.h>

ffi::Tensor return_add_one(DLTensor* x) {
  ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
      TVMFFIEnvGetTensorAllocator(),       // queries TLS, then global
      ffi::Shape({x->shape[0]}),
      DLDataType{kDLFloat, 32, 1},
      x->device);
  // ... launch kernel writing into y ...
  return y;
}
```
When called from Python with a `torch.Tensor` argument that has `__c_dlpack_tensor_allocator__` set, the returned tensor is automatically a `torch.Tensor`.

### Controlling GIL release
**Context**: For short-running FFI functions, holding the GIL avoids acquire/release overhead.
```python
func = tvm_ffi.get_global_func("testing.nop")
func.release_gil = False  # don't release GIL for short calls
func()
```
