# Introduce DLPack exchange function pointers, env tensor allocator, GIL release control, and torch C DLPack extension

## TL;DR
- Adds three C-level function pointer types (`DLPackTensorAllocator`, `DLPackPyObjectExporter`, `DLPackPyObjectImporter`) to enable fast DLPack exchange and environment-driven tensor allocation, with a new `Tensor::FromDLPackAlloc` C++ factory and thread-local allocator context in `EnvContext`.
- Renames stream API from `SetCurrentStream`/`GetCurrentStream` to `SetStream`/`GetStream`, and refactors `StreamContext` into a broader `EnvContext` class that also manages the DLPack tensor allocator (TLS + global fallback).
- Converts Cython `Function` from a Python class to a `cdef class` with a `release_gil` property (default true, overridable via `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var), and adds result-path DLPack import support so returned tensors auto-convert back to `torch.Tensor` when a C DLPack importer is active.

### Rename mapping

| Old name | New name |
|---|---|
| `TVMFFIEnvSetCurrentStream` | `TVMFFIEnvSetStream` |
| `TVMFFIEnvGetCurrentStream` | `TVMFFIEnvGetStream` |

## Impact
- API: Renames `TVMFFIEnvSetCurrentStream` -> `TVMFFIEnvSetStream` and `TVMFFIEnvGetCurrentStream` -> `TVMFFIEnvGetStream` (breaking for callers of old names). Adds `TVMFFIEnvSetTensorAllocator`, `TVMFFIEnvGetTensorAllocator`, `DLPackTensorAllocator` typedef. Python protocol `__dlpack_c_exporter__` -> `__c_dlpack_exporter__`, new `__c_dlpack_importer__`, `__c_dlpack_tensor_allocator__`.
- Behavioral: Returned `ffi::Tensor` values now auto-convert to `torch.Tensor` when a `DLPackPyObjectImporter` is active (set by torch C DLPack extension). DLPack `from_dlpack` operations no longer release GIL (removed `with nogil:` blocks). `Function.__call__` passes `release_gil` and `out_dlpack_importer` through the call chain.
- Flags/config: `TVM_FFI_RELEASE_GIL_BY_DEFAULT` env var (default `"1"`) controls default GIL release. `TVM_FFI_SKIP_C_DLPACK_EXPORTER` env var (default `"0"`) disables fast C DLPack path.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **C ABI surface** (`c_api.h`) — extends with `DLPackTensorAllocator` typedef. See [0001-ffi-c-abi.md](../design-records/0001-ffi-c-abi.md).
- **Tensor container** — `Tensor::FromDLPackAlloc` factory added alongside existing `FromNDAlloc`/`FromDLPack`/`FromDLPackVersioned`. See [0006-ffi-containers.md](../design-records/0006-ffi-containers.md).
- **C env API** — renamed stream functions, added allocator functions. See [0011-ffi-module-system.md](../design-records/0011-ffi-module-system.md).
- **Error protocol** — `Tensor::FromDLPackAlloc` uses `ErrorContext::SetError` callback pattern for C-compatible error propagation. See [0005-ffi-error-protocol.md](../design-records/0005-ffi-error-protocol.md).
- **Python FFI bindings** — `Function` class, arg setter factory, DLPack protocol. See [0012-ffi-python-package.md](../design-records/0012-ffi-python-package.md).
- **load_inline** — tests updated to use renamed stream API. See [0014-ffi-load-inline.md](../design-records/0014-ffi-load-inline.md).

Design elements this commit produces:
- **DLPack function pointer protocol** — Three C-level function pointer types (`DLPackTensorAllocator`, `DLPackPyObjectExporter`, `DLPackPyObjectImporter`) that enable pluggable, zero-overhead tensor exchange between frameworks without Python round-trips.
- **Environment tensor allocator** — Thread-local + global allocator context (`EnvContext::dlpack_allocator_`) allowing C++ library code to allocate tensors via the caller environment's allocator (e.g., `torch.empty`).
- **GIL release control** — `Function.release_gil` property enabling per-function GIL management, useful for short-running FFI calls where GIL release overhead dominates.
- **Result-path DLPack import** — When a C DLPack importer is active, returned `ffi::Tensor` values auto-convert to the caller's tensor type (e.g., `torch.Tensor`), eliminating a Python-level `from_dlpack` round-trip.
- **`_optional_torch_c_dlpack.py`** — JIT-compiled PyTorch extension that sets `__c_dlpack_exporter__`, `__c_dlpack_importer__`, `__c_dlpack_tensor_allocator__` on `torch.Tensor` class at import time.

## Usage Examples

**C++ allocator-driven tensor creation via env context (from test `test_load_inline_cuda_with_env_tensor_allocator`)**

```cpp
// Inside a CUDA kernel library function:
ffi::Tensor return_add_one(DLTensor* x) {
  DLDataType f32_dtype{kDLFloat, 32, 1};
  // Allocate using env allocator — redirected to torch.empty when called from Python+torch
  ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
    TVMFFIEnvGetTensorAllocator(), ffi::Shape({x->shape[0]}), f32_dtype, x->device);
  cudaStream_t stream = static_cast<cudaStream_t>(
    TVMFFIEnvGetStream(x->device.device_type, x->device.device_id));
  AddOneKernel<<<nblock, nthread_per_block, 0, stream>>>(
    static_cast<float*>(x->data), static_cast<float*>(y->data), n);
  return y;
}
```
