# Rename DLPack speed converter functions from Exporter/Importer to FromPyObject/ToPyObject
## TL;DR
- Renames the DLPack "speed converter" C function pointer typedefs and all corresponding Python/Cython symbols from `DLPackPyObjectExporter`/`DLPackPyObjectImporter` to `DLPackFromPyObject`/`DLPackToPyObject`, and renames related struct fields, Python dunder attributes (`__c_dlpack_exporter__` -> `__c_dlpack_from_pyobject__`, `__c_dlpack_importer__` -> `__c_dlpack_to_pyobject__`), and the environment variable from `TVM_FFI_SKIP_C_DLPACK_EXPORTER` to `TVM_FFI_SKIP_c_dlpack_from_pyobject`.
- Adds `#if TORCH_VERSION_MAJOR >= 2 && TORCH_VERSION_MINOR >= 8` guards around the `Float4_e2m1fn_x2` DLPack dtype case to fix compilation with PyTorch versions older than 2.8.
- Bumps package version from `0.1.0a11` to `0.1.0a12`.

## Impact
- API: **Breaking** for any downstream code that references the old dunder attribute names (`__c_dlpack_exporter__`, `__c_dlpack_importer__`) or the old environment variable (`TVM_FFI_SKIP_C_DLPACK_EXPORTER`). The `torch_c_dlpack_ext` addon in `_optional_torch_c_dlpack.py` sets these attributes on `torch.Tensor`, so external code reading those attributes must use the new names. The C typedef names in `tvm_ffi_python_helpers.h` are also renamed, affecting any out-of-tree Cython code that imports them.
- Flags/config: Environment variable renamed from `TVM_FFI_SKIP_C_DLPACK_EXPORTER` to `TVM_FFI_SKIP_c_dlpack_from_pyobject`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Python bindings / DLPack speed converter protocol** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The speed converter mechanism allows external tensor frameworks (e.g., PyTorch) to register C function pointers on their tensor classes for fast DLPack conversion, bypassing the slower `__dlpack__` Python protocol. The Cython argument setter (`TVMFFIPyArgSetterFactory_`) checks for `__c_dlpack_from_pyobject__` (formerly `__c_dlpack_exporter__`) and `__c_dlpack_to_pyobject__` (formerly `__c_dlpack_importer__`) attributes on the argument type, loads the function pointers, and stores them in `TVMFFIPyArgSetter` and `TVMFFIPyCallContext` structs.
- **C helper struct layout** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): `TVMFFIPyArgSetter` and `TVMFFIPyCallContext` in `tvm_ffi_python_helpers.h` carry the function pointers through the call pipeline. Fields renamed: `c_dlpack_exporter` -> `c_dlpack_from_pyobject`, `c_dlpack_importer` -> `c_dlpack_to_pyobject`.
- **Generic stream exchange protocol** ([`.knowledge/ADRs/0030-generic-stream-exchange-protocol.md`](../ADRs/0030-generic-stream-exchange-protocol.md)): The `__tvm_ffi_env_stream__` protocol was introduced alongside the DLPack speed converter; this commit only renames the converter-related symbols, not the stream protocol.
- **Torch C DLPack extension** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): The JIT-compiled C++ extension that implements `TorchDLPackFromPyObject` and `TorchDLPackToPyObject` (formerly `TorchDLPackPyObjectExporter`/`TorchDLPackPyObjectImporter`), registered on `torch.Tensor` as class-level attributes.

Design elements this commit produces:
- **Naming convention alignment for DLPack converters** (incremental, not a new element): The new names `DLPackFromPyObject` / `DLPackToPyObject` describe the data flow direction (`From` = Python object to DLManagedTensorVersioned, `To` = DLManagedTensorVersioned to Python object) rather than using the role-based `Exporter`/`Importer` naming, which could be confusing because "export" might be interpreted from the perspective of either the source or the target framework.
