# Patch torch.cuda.Stream with __cuda_stream__ protocol for older torch versions
## TL;DR
- Adds `patch_torch_cuda_stream_protocol()` to `_optional_torch_c_dlpack.py` that monkey-patches `torch.cuda.Stream.__cuda_stream__` when the method is absent (older torch versions).
- The patched method returns `(0, self.cuda_stream)` matching the protocol expected by `TVMFFIPyArgSetterCUDAStream_` in `function.pxi`.
- Executed at module import time; silently skipped if torch is unavailable or CUDA is not available.

## Key Exports

```python

    # Interacts with: TVMFFIPyArgSetterFactory_ (function.pxi:622) which dispatches on hasattr(__cuda_stream__)
    # Invariant: only patches if torch.cuda.is_available() AND __cuda_stream__ is missing
    # Invariant: patched method returns (version: int, stream_handle: int) tuple
    # Extension: N/A -- will become unnecessary as older torch versions age out
```

## Impact
- API: none
- Behavioral: `torch.cuda.Stream` objects can now be passed as FFI arguments on older torch versions that lack native `__cuda_stream__` support. Without this patch, passing a `torch.cuda.Stream` to an FFI function on older torch would fail to dispatch through the CUDA stream arg-setter path.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `__cuda_stream__` protocol: duck-typed protocol consumed by `TVMFFIPyArgSetterCUDAStream_` in `function.pxi:290-301`. The protocol returns `(version, stream_handle)` tuple. Not currently documented in `.knowledge/designs/`.
- `TVMFFIPyArgSetterFactory_` dispatch chain (`function.pxi:622`): dispatches on `hasattr(arg_class, "__cuda_stream__")` to route to CUDA stream setter.

Design elements this commit produces:
- `patch_torch_cuda_stream_protocol()`: module-level compatibility shim in `python/tvm_ffi/_optional_torch_c_dlpack.py`. Not a design element per se, but a compatibility bridge ensuring the `__cuda_stream__` protocol is available on `torch.cuda.Stream` regardless of torch version.

## Usage Examples
None -- the patch is auto-applied at import time. No user action required.
