# Fix IterAdapter/ReverseIterAdapter to conform to InputIterator requirements
## TL;DR
- Fix `IterAdapter` and `ReverseIterAdapter` in `container_details.h` so that `reference` and `pointer` type aliases are `const`-qualified, and `operator*` returns `reference` instead of `const value_type`.
- This corrects a violation of the C++ InputIterator named requirement where the dereferenced iterator's return type must match the `reference` type alias, enabling correct behavior with STL algorithms like `std::make_move_iterator`.

## Key Exports
**Types** (mutated):
- `IterAdapter<Converter, TIter>`:
  - `pointer` changed from `ResultType*` to `const ResultType*`
  - `reference` changed from `ResultType&` to `const ResultType` (value, not reference — matches converter's by-value return)
  - `operator*() const` return type changed from `const value_type` to `reference`
- `ReverseIterAdapter<Converter, TIter>`: identical changes as above.

## Impact
- API: Public header change in `include/tvm/ffi/container/container_details.h`. The type aliases `pointer` and `reference` on both iterator adapters change. Code that explicitly depended on `IterAdapter::reference` being a non-const lvalue reference type would be affected, but this is unlikely since the converter returns by value.
- Behavioral: `operator*` now formally returns the `reference` typedef, fixing UB when STL components inspect iterator traits.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Container iterator adapters** (`IterAdapter`, `ReverseIterAdapter`) — internal building blocks for container iterators in `.knowledge/designs/0008-containers.md`.

Design elements this commit mutates:
- **IterAdapter/ReverseIterAdapter iterator traits contract** — the `reference` and `pointer` type aliases now correctly reflect const semantics, aligning with C++ InputIterator named requirements.

**Invariant violated before fix**: `IterAdapter::reference` was `ResultType&` (mutable lvalue reference) but `operator*` returned `const value_type` (const prvalue). This mismatch violates the InputIterator requirement that `*it` returns `reference`.

**Invariant restored**: `reference` is `const ResultType` and `operator*` returns `reference`, so `decltype(*it)` matches the `reference` typedef.

## Usage Examples
```cpp
// Before: std::make_move_iterator with IterAdapter could cause UB
// because iterator_traits<IterAdapter>::reference was ResultType& (non-const)
// but operator* returned const value_type (mismatch).

// After: reference = const ResultType, operator* returns reference — consistent.
auto begin = std::make_move_iterator(container.begin());
auto end = std::make_move_iterator(container.end());
// Now safe to use with STL algorithms
```
