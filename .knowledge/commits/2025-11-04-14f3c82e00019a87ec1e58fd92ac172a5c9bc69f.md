# Fix IterAdapter/ReverseIterAdapter type aliases to conform to C++ LegacyInputIterator requirements
## TL;DR
- Fixed `pointer` and `reference` type aliases in `IterAdapter` and `ReverseIterAdapter` to add `const` qualification, conforming to C++ LegacyInputIterator named requirements.
- Changed `operator*()` return type from `const value_type` to `reference`, aligning the actual return type with the declared `reference` alias.
- Prevents undefined behavior when using these iterators with STL components like `std::make_move_iterator`.

## Key Exports

```python
# IterAdapter and ReverseIterAdapter type alias fix (container_details.h)
# These are internal iterator adapters used by Array<T>.

# Before (broken):
#   pointer   = ResultType*          (non-const)
#   reference = ResultType&          (non-const lvalue ref -- impossible for temporaries)
#   operator*() -> const value_type  (prvalue, inconsistent with reference alias)

# After (fixed):
#   pointer   = const ResultType*    (const-qualified)
#   reference = const ResultType     (const value -- correct for converter-produced temporaries)
#   operator*() -> reference         (uses the alias, consistent)

# Interacts with: Array<T>::iterator, Array<T>::reverse_iterator (array.h)
# Interacts with: STL algorithms (std::make_move_iterator, std::copy, etc.)
# Invariant: operator*() return type must match the reference type alias per C++ InputIterator
```

## Impact
- API: None -- internal iterator infrastructure, no public API signature change.
- Behavioral: Fixes potential undefined behavior when `IterAdapter`/`ReverseIterAdapter` are used with STL algorithms that rely on iterator type traits (e.g., `std::make_move_iterator`).
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `IterAdapter` / `ReverseIterAdapter` in `container_details.h` -- the converting iterator adapters used by `Array<T>` containers. See [0006-ffi-containers](../design-records/0006-ffi-containers.md).

Design elements this commit produces: None -- purely a conformance fix.

## Usage Examples
Before (incorrect -- could cause UB with STL):
```cpp
// IterAdapter::reference was ResultType& but operator*() returned const value_type
// This mismatch meant std::iterator_traits<Iter>::reference != decltype(*iter)
// std::make_move_iterator relies on reference type to decide move vs copy
auto it = array.begin();
auto move_it = std::make_move_iterator(it);  // UB: reference type mismatch
```

After (correct):
```cpp
// IterAdapter::reference is now const ResultType, matching operator*() return
// std::iterator_traits correctly reflects the actual dereference behavior
auto it = array.begin();
auto move_it = std::make_move_iterator(it);  // Well-defined: types are consistent
```
