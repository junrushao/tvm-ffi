# Fix IterAdapter/ReverseIterAdapter to comply with LegacyInputIterator by making reference type const

## TL;DR
- Fixes `IterAdapter` and `ReverseIterAdapter` iterator trait typedefs to satisfy the C++ `LegacyInputIterator` named requirement: `reference` must match the return type of `operator*()`.
- Before: `pointer` was `ResultType*`, `reference` was `ResultType&`, but `operator*()` returned `const value_type` -- a mismatch that caused undefined behavior with STL components like `std::make_move_iterator`.
- After: `pointer` is `const ResultType*`, `reference` is `const ResultType`, and `operator*()` returns `reference` -- all three are now consistent.

## Key Exports

```python
# IterAdapter iterator trait typedefs (container_details.h)
# Before:
#   pointer = ResultType*
#   reference = ResultType&
#   operator*() -> const value_type  # MISMATCH: return != reference
#
# After:
#   pointer = const ResultType*
#   reference = const ResultType
#   operator*() -> reference         # CONSISTENT: return == reference

class IterAdapter(Generic[Converter, TIter]):
    """Iterator adapter that converts TIter elements via Converter."""
    # Changed typedefs:
    pointer: Type    # const Converter.ResultType*  (was: Converter.ResultType*)
    reference: Type  # const Converter.ResultType   (was: Converter.ResultType&)
    # Changed operator:
    def __deref__(self) -> reference: ...  # was: const value_type
    # Invariant: reference type == return type of operator*() (LegacyInputIterator requirement)
    # Invariant: pointer == reference* (consistency)
    # Interacts with: Array::iterator (typedef IterAdapter<ValueConverter, const Any*>)
    # Interacts with: std::make_move_iterator, std::copy, and other STL algorithms
    # Interacts with: std::iterator_traits<IterAdapter> (deduces types from these typedefs)

class ReverseIterAdapter(Generic[Converter, TIter]):
    """Reverse iterator adapter with same fix applied."""
    pointer: Type    # const Converter.ResultType*  (was: Converter.ResultType*)
    reference: Type  # const Converter.ResultType   (was: Converter.ResultType&)
    def __deref__(self) -> reference: ...  # was: const value_type
    # Same invariants and interactions as IterAdapter
```

## Impact
- API: The iterator `pointer` and `reference` typedefs gain `const` qualification. Code that explicitly depended on non-const `pointer` or `reference` types would need updating, but this is unlikely since `operator*()` always returned const values.
- Behavioral: `std::make_move_iterator` and other STL algorithms that inspect `reference` type via `std::iterator_traits` now see a type consistent with what `operator*()` actually returns. This eliminates undefined behavior in STL interop.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `IterAdapter` / `ReverseIterAdapter` iterator adapters (`include/tvm/ffi/container/container_details.h`) -- used by `Array::iterator` and `Array::reverse_iterator` to convert raw `Any*` iteration into typed element access.
- C++ named requirement `LegacyInputIterator` (cppreference) -- requires `*it` return type to be convertible to `reference`.

Design elements this commit produces:
- None new. This is a bugfix to existing elements to enforce C++ standard compliance.

## Usage Examples

Before (broken): `std::make_move_iterator` deduces `reference` as `ResultType&` but `operator*()` returns `const ResultType` -- type mismatch causes undefined behavior:
```cpp
Array<int> arr({1, 2, 3});
auto begin = std::make_move_iterator(arr.begin());
// UB: std::move_iterator uses iterator_traits<T>::reference for its reference type
// which was ResultType& (non-const lvalue ref) but operator*() returns const value_type
```

After (fixed): `reference` is `const ResultType`, matching `operator*()` return type:
```cpp
Array<int> arr({1, 2, 3});
auto begin = std::make_move_iterator(arr.begin());
// OK: std::move_iterator::reference == const ResultType, matches operator*() return
// STL algorithms correctly see const values and do not attempt to move from them
```
