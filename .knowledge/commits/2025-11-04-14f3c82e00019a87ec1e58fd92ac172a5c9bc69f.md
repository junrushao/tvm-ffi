# Fix IterAdapter/ReverseIterAdapter to satisfy LegacyInputIterator by aligning reference/pointer type aliases with operator* return type
## TL;DR
- Changes `IterAdapter::pointer` and `ReverseIterAdapter::pointer` from `T*` to `const T*`, and `reference` from `T&` to `const T`, to match the actual const-returning `operator*()`.
- Changes `operator*()` return type from `const value_type` to `reference` (now `const typename Converter::ResultType`), aligning the declared `reference` typedef with the actual dereference return type as required by LegacyInputIterator.
- Prevents potential undefined behavior when the iterator is used with STL components (e.g., `std::make_move_iterator`) that rely on `reference` being the return type of `operator*`.

## Key Exports
**Types/Classes** (modified, not new):

`IterAdapter<Converter, TIter>` (`include/tvm/ffi/container/container_details.h`):
- `using pointer = const typename Converter::ResultType*;` (was non-const)
- `using reference = const typename Converter::ResultType;` (was `ResultType&`)
- `reference operator*() const;` (was `const value_type operator*() const`)

`ReverseIterAdapter<Converter, TIter>` (`include/tvm/ffi/container/container_details.h`):
- Same three changes as `IterAdapter`.

## Impact
- API: None -- the actual runtime behavior of `operator*()` is unchanged (always returned by value). Only the type aliases and declared return type are corrected.
- ABI: None -- iterator adapters are header-only templates, instantiated per TU. No symbol table changes.
- Behavioral: Fixes potential UB when STL components inspect `reference` typedef for dispatch (e.g., `std::make_move_iterator` deduces its `reference` from the wrapped iterator's `reference` typedef).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **IterAdapter** (`include/tvm/ffi/container/container_details.h`) -- the random-access iterator adapter used by `Array::begin()`/`end()`. See `.knowledge/designs/containers.md`.
- **C++ LegacyInputIterator named requirement** -- `reference` must be the return type of `operator*()`.

Design elements this commit produces:
- **IterAdapter / ReverseIterAdapter** (corrected) -- now fully satisfy LegacyInputIterator/LegacyForwardIterator requirements. The `reference` typedef matches `operator*()` return type and `pointer` is const-qualified.

## Usage Examples
Before (incorrect -- `reference` is `T&` but `operator*` returns `const T`):
```cpp
// std::make_move_iterator relies on iterator_traits<It>::reference
// to determine its own reference type. With the old mismatch,
// move_iterator would deduce reference = T& (non-const), potentially
// causing UB when attempting to move from a const value.
auto it = arr.begin();
auto mit = std::make_move_iterator(it);  // deduces reference = T& (wrong)
```

After (correct -- `reference` is `const T`, matching `operator*`):
```cpp
auto it = arr.begin();
auto mit = std::make_move_iterator(it);  // deduces reference = const T (correct)
```
