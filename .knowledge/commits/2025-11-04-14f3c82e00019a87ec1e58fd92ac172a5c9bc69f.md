# Fix IterAdapter reference/pointer types to conform to InputIterator named requirement

## TL;DR
- In `IterAdapter` and `ReverseIterAdapter` (container_details.h): changes `reference` typedef from `ResultType&` to `const ResultType` (value semantics, not reference), and `pointer` from `ResultType*` to `const ResultType*`.
- `operator*()` return type now matches `reference` typedef exactly, enabling correct behavior with STL algorithms like `std::make_move_iterator`.
- Root cause: `IterAdapter` stored converted values by value (temporary), so returning a `ResultType&` was UB — the reference would dangle.

## Key Exports

```python
# C++ pseudocode — IterAdapter in include/tvm/ffi/container/container_details.h
class IterAdapter:
    """Adapts an inner iterator by applying Converter::convert on dereference."""
    # Before:
    #   reference = ResultType&     # BUG: dangling ref to temporary
    #   pointer = ResultType*
    # After:
    #   reference = const ResultType  # value semantics — copy on dereference
    #   pointer = const ResultType*
    # Invariant: convert() returns a new value each call (not a stored reference)
    # Interacts with: Array, Map, Tuple iterators; any STL algorithm requiring InputIterator

    def __deref__(self) -> const ResultType: ...  # returns by value
```

## Impact
- API: `IterAdapter::reference` typedef changes from `T&` to `const T`; may affect code that relied on the non-const reference (non-const callers now get a copy).
- Behavioral: Fixes UB with `std::make_move_iterator` and other STL components.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before (UB):
```cpp
auto it = arr.begin();
const Array<String>::value_type& ref = *it;  // dangling ref — UB
```
After (correct):
```cpp
auto val = *it;  // copy — safe
```
