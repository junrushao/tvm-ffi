# Add compiler integration guide documenting kernel/graph compiler and custom module patterns
## TL;DR
- New `docs/guides/compiler_integration.md` (140 lines) covering three integration paths: kernel language compilers, graph compilers, and custom `ModuleObj` subclasses.
- Minor comment improvements: `TVM_FFI_DLL_EXPORT_TYPED_FUNC` Doxygen now explicitly states "follows the FFI ABI" and notes the `__tvm_ffi_<ExportName>` symbol name; `ProcessLibraryBin` layout comment updated to use `[val: bytes]` bracket notation showing the value is conditional on the key.

- **`TVMFFISafeCallType` packed calling convention** (`.knowledge/designs/function-system.md`): The C code example in the guide implements the `int(void* handle, TVMFFIAny* args, int32_t num_args, TVMFFIAny* result)` signature directly.
- **`TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro** (`.knowledge/designs/function-system.md`): Referenced as the recommended C++ path for kernel generators.

- **`TVMFFIEnvGetStream`**: Used in the C code example for CUDA stream retrieval.
- **`TVMFFIErrorSetRaisedFromCStr`**: Used in the C code example for error reporting.

## Usage Examples
The guide itself is the usage example. The key end-to-end C code pattern for kernel compilers:

```c
#include <tvm/ffi/c_api.h>
#include <tvm/ffi/extra/c_env_api.h>

// FFI function following the ABI convention
int __tvm_ffi_add_one(
  void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result
) {
  // Extract DLTensor args, get stream, compute, return 0 on success
  void* stream = TVMFFIEnvGetStream(a->device.device_type, a->device.device_id);
  return 0;
}
```

Graph compiler integration pattern:
```python
# Direct call via call_tvm_ffi primitive
Op.call_tvm_ffi("my_func", *args)
# Or load module and invoke
mod = tvm_ffi.load_module("model.so")
mod["forward"](*args)
```
