# Specify `--module-name` when building Cython, removing runtime `__module__` patching

## TL;DR
- Adds `--module-name "tvm_ffi.core"` to the Cython transpilation command in `CMakeLists.txt`, so the compiled extension natively reports its module as `tvm_ffi.core` instead of a bare filename-derived name.
- Removes the `_update_module()` workaround in `python/tvm_ffi/__init__.py` (introduced by PR #177) that patched `__module__` at import time -- this was unreliable on older Python/Cython versions.
- Adds `.replace("tvm_ffi.core.", "tvm_ffi.")` in `docs/conf.py` so Sphinx cross-references render as `tvm_ffi.X` rather than `tvm_ffi.core.X`.
- Pins `cython>=3.0` in both `[build-system].requires` and `[project.optional-dependencies].dev` (previously unpinned).
- Secondary: reformats docstrings across several Python/Cython files to use Sphinx `:class:`/`:py:meth:` cross-references and external hyperlinks instead of double-backtick literals.

## Impact
- API: none -- no public API signatures changed.
- Behavioral: Cython-compiled classes now natively report `__module__ = "tvm_ffi.core"` instead of relying on runtime patching. The `_update_module()` function is removed. Sphinx docs now strip the `tvm_ffi.core.` prefix from inherited-member cross-references.
- Flags/config: Cython build command gains `--module-name "tvm_ffi.core"`. Cython dependency pinned to `>=3.0` (was unpinned). The `--module-name` flag requires Cython 3.0+.
- Data formats/schemas: none.
