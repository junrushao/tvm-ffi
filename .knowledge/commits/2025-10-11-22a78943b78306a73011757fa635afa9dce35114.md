# Unify DLPack exchange into a single DLPackExchangeAPI struct with non-owning conversion and explicit stream query

## TL;DR
- Replaces the three separate class-level function-pointer attributes (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) with a single `__c_dlpack_exchange_api__` attribute pointing to a `DLPackExchangeAPI` struct, aligning with the DLPack proposal [175](https://github.com/dmlc/dlpack/issues/175).
- Adds `dltensor_from_py_object_no_sync` for non-owning DLTensor conversion (no ref-count overhead) and `current_work_stream` for explicit device stream querying, removing the implicit stream-via-from-pyobject coupling.
- All DLPack conversion functions renamed to `*_no_sync` to signal that stream synchronization is now the caller's responsibility via `current_work_stream`.

### Rename mapping (secondary rename shape)

| Old name | New name |
|---|---|
| `__c_dlpack_from_pyobject__` (class attr) | `__c_dlpack_exchange_api__` (class attr, int ptr to struct) |
| `__c_dlpack_to_pyobject__` (class attr) | Absorbed into `DLPackExchangeAPI.managed_tensor_to_py_object_no_sync` |
| `__c_dlpack_tensor_allocator__` (class attr) | Absorbed into `DLPackExchangeAPI.managed_tensor_allocator` |
| `TorchDLPackFromPyObject` | `TorchDLPackManagedTensorFromPyObjectNoSync` |
| `TorchDLPackToPyObject` | `TorchDLPackManagedTensorToPyObjectNoSync` |
| `TorchDLPackTensorAllocator` | `TorchDLPackManagedTensorAllocator` |
| `TorchDLPackFromPyObjectPtr` / `ToPyObjectPtr` / `TensorAllocatorPtr` | `TorchDLPackExchangeAPIPtr` (single entry point) |
| `TVMFFIPyArgSetterDLPackCExporter_` | `TVMFFIPyArgSetterDLPackExchangeAPI_` |
| `TVMFFIPyCallContext.c_dlpack_to_pyobject` | `TVMFFIPyCallContext.c_dlpack_exchange_api` |
| `TVMFFIPyCallContext.c_dlpack_tensor_allocator` | Absorbed into `c_dlpack_exchange_api->managed_tensor_allocator` |
| `TVMFFIPyArgSetter.c_dlpack_from_pyobject` / `.c_dlpack_to_pyobject` / `.c_dlpack_tensor_allocator` | `TVMFFIPyArgSetter.c_dlpack_exchange_api` |

## Impact
- API: Breaking -- removes `__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__` class attributes. Any external code checking for these attributes must switch to `__c_dlpack_exchange_api__`. The test in `test_load_inline.py` demonstrates the migration.
- Behavioral: Stream querying is now decoupled from tensor conversion. `managed_tensor_from_py_object_no_sync` no longer accepts an `env_stream` out-parameter; stream must be queried separately via `current_work_stream`. This is a semantic change.
- Flags/config: `TVM_FFI_SKIP_c_dlpack_from_pyobject` env var still works but now gates the `__c_dlpack_exchange_api__` check.
- Data formats/schemas: `3rdparty/dlpack` submodule bumped to `1117366` (incorporates `DLPackExchangeAPI` struct definition).

## Design Elements
Design elements this commit consumes:
- `TVMFFIPyCallManager` call dispatch pipeline (0012-ffi-python-package) -- the struct is threaded through the existing `TVMFFIPyCallContext` -> `TVMFFIPyArgSetter` -> `FuncCall` -> `make_ret` chain
- `TVMFFIEnvSetTensorAllocator` C env API (0011-ffi-module-system) -- allocator field extracted from the struct and plugged in during `FuncCall`
- `Tensor` / DLPack conversion functions `TVMFFITensorFromDLPackVersioned`, `TVMFFITensorToDLPackVersioned` (0006-ffi-containers)

Design elements this commit produces:
- **`DLPackExchangeAPI` struct** -- new C-level protocol for DLPack tensor exchange, bundling 5 function pointers with a versioned header and `prev_api` chain for forward compatibility
- **`__c_dlpack_exchange_api__` class attribute protocol** -- replaces the previous 3-attribute protocol; checked on `type(arg)` (class-level, not instance)
- **Non-owning `DLTensor` conversion** (`dltensor_from_py_object_no_sync`) -- zero-allocation path for read-only tensor access
- **Explicit stream query** (`current_work_stream`) -- decouples stream discovery from tensor conversion, enabling `_no_sync` semantics

## Usage Examples

Registering DLPackExchangeAPI on a custom tensor class (from `tensor.pxi` test wrapper):
```python
# Cython pseudocode showing how to implement and register the API
cdef DLPackExchangeAPI my_exchange_api

def _init_exchange_api():
    my_exchange_api.header.version.major = DLPACK_MAJOR_VERSION
    my_exchange_api.header.version.minor = DLPACK_MINOR_VERSION
    my_exchange_api.header.prev_api = NULL
    my_exchange_api.managed_tensor_from_py_object_no_sync = my_from_pyobject
    my_exchange_api.managed_tensor_to_py_object_no_sync = my_to_pyobject
    my_exchange_api.current_work_stream = my_current_stream
    # dltensor_from_py_object_no_sync and managed_tensor_allocator can be NULL

class MyTensor:
    __c_dlpack_exchange_api__ = <int_ptr>&my_exchange_api
    # Checked on class, not instance -- type(arg).__c_dlpack_exchange_api__
```

Torch integration (from `_optional_torch_c_dlpack.py`):
```python
# After JIT-compiling the C++ extension:
mod = torch.utils.cpp_extension.load(name="c_dlpack", cpp_sources=...,
    functions=["TorchDLPackExchangeAPIPtr"])
# Single attribute replaces three:
torch.Tensor.__c_dlpack_exchange_api__ = mod.TorchDLPackExchangeAPIPtr()
```
