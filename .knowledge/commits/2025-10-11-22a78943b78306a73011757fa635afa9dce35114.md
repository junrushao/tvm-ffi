# Replace separate DLPack function pointers with unified DLPackExchangeAPI struct
## TL;DR
- Replaces the three separate class attributes (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) with a single `__c_dlpack_exchange_api__` attribute pointing to a `DLPackExchangeAPI` struct, as specified in DLPack proposal #175.
- Separates stream querying from tensor export: stream is now obtained via `current_work_stream` function pointer in the struct instead of being piggybacked on the export call.
- Adds `DLPackDLTensorFromPyObjectNoSync` for non-owning `DLTensor` conversion (fills a pre-allocated `DLTensor` without reference counting).
- Updates the `3rdparty/dlpack` submodule to incorporate the new `DLPackExchangeAPI` struct definition (PR #174).

## Impact
- API: Breaking change -- frameworks using `__c_dlpack_from_pyobject__` / `__c_dlpack_to_pyobject__` / `__c_dlpack_tensor_allocator__` must migrate to `__c_dlpack_exchange_api__`. The `TVM_FFI_SKIP_c_dlpack_from_pyobject` env var now checks for `__c_dlpack_exchange_api__` instead.
- ABI: Breaking -- `TVMFFIPyCallContext` and `TVMFFIPyArgSetter` struct layouts changed (fields replaced). `DLPackFromPyObject` typedef signature changed (stream parameter removed from the export path). New function pointer types defined in `dlpack.h`.
- Behavioral: Stream querying is now decoupled from tensor export. Previously `c_dlpack_from_pyobject` took a `void** env_stream` out-parameter; now stream is queried separately via `current_work_stream` after export. The non-owning `DLTensor` path (`dltensor_from_py_object_no_sync`) avoids refcount overhead for read-only tensor access.
- Flags/config: `TVM_FFI_SKIP_c_dlpack_from_pyobject` env var still works but now gates `__c_dlpack_exchange_api__` detection.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- DLPack fast-path protocol for C-level tensor exchange bypass (`.knowledge/designs/0018-dlpack-fast-path.md`)
- `TVMFFIPyCallManager.FuncCall` dispatch with setter factory and context propagation (`.knowledge/designs/0018-dlpack-fast-path.md`, `.knowledge/designs/0014-python-bindings.md`)
- `TVMFFIEnvSetTensorAllocator` / `TVMFFIEnvGetTensorAllocator` for environment tensor allocator (`.knowledge/designs/0018-dlpack-fast-path.md`)
- `DLManagedTensorVersioned` and `DLPackVersion` from DLPack standard (`3rdparty/dlpack/include/dlpack/dlpack.h`)
- Cython binding layer patterns for Cython `cdef extern` declarations (`.knowledge/ADRs/012-cython-binding-layer.md`)

Design elements this commit produces:
- `DLPackExchangeAPI` struct-based protocol: replaces three separate function pointers with a single versioned struct, aligning with DLPack standard proposal #175. The struct includes version negotiation via `prev_api` chaining.
- `__c_dlpack_exchange_api__` Python class attribute protocol: single entry point for framework DLPack exchange discovery (checked on CLASS, not instance).
- Decoupled stream querying via `DLPackCurrentWorkStream`: stream is no longer coupled to tensor export, enabling explicit stream management.
- Non-owning `DLTensor` export path via `DLPackDLTensorFromPyObjectNoSync`: fills a stack-allocated `DLTensor` without DLManagedTensorVersioned allocation or refcounting, for use cases that only need read access to tensor metadata.
- Fallback exchange API pattern (`GetTorchFallbackExchangeAPI`): creates a partial `DLPackExchangeAPI` with only `managed_tensor_to_py_object_no_sync` populated, for the `torch.from_dlpack` fallback path.

## Usage Examples

Framework integration with the new `DLPackExchangeAPI` struct (C++ side, from the torch extension):
```cpp
struct TorchDLPackExchangeAPI : public DLPackExchangeAPI {
  TorchDLPackExchangeAPI() {
    header.version.major = DLPACK_MAJOR_VERSION;
    header.version.minor = DLPACK_MINOR_VERSION;
    header.prev_api = nullptr;
    managed_tensor_allocator = TorchDLPackManagedTensorAllocator;
    managed_tensor_from_py_object_no_sync = TorchDLPackManagedTensorFromPyObjectNoSync;
    managed_tensor_to_py_object_no_sync = TorchDLPackManagedTensorToPyObjectNoSync;
    dltensor_from_py_object_no_sync = TorchDLPackDLTensorFromPyObjectNoSync;
    current_work_stream = TorchDLPackCurrentWorkStream;
  }
  static const DLPackExchangeAPI* Global() {
    static TorchDLPackExchangeAPI inst;
    return &inst;
  }
};
```

Python-side discovery (from `function.pxi` setter factory):
```python
# Checked on the CLASS, not the instance
arg_class = type(arg)
if hasattr(arg_class, "__c_dlpack_exchange_api__"):
    out.func = TVMFFIPyArgSetterDLPackExchangeAPI_
    temp_ptr = arg_class.__c_dlpack_exchange_api__
    out.c_dlpack_exchange_api = <const DLPackExchangeAPI*>(<long long>temp_ptr)
```

Stream querying decoupled from export (from `function.pxi` setter):
```cython
# Export tensor (no stream arg)
api.managed_tensor_from_py_object_no_sync(arg, &temp_managed_tensor)

# Query stream separately
if temp_managed_tensor.dl_tensor.device.device_type != kDLCPU:
    if ctx.device_type == -1 and api.current_work_stream != NULL:
        api.current_work_stream(
            temp_managed_tensor.dl_tensor.device.device_type,
            temp_managed_tensor.dl_tensor.device.device_id,
            &current_stream)
```
