# Adopt DLPackExchangeAPI struct for unified DLPack speed exchange and stream handling
## TL;DR
- Replaces previous separate function pointers (`__c_dlpack_from_pyobject__`) with a unified `DLPackExchangeAPI` struct following the DLPack proposal #175, exposed via `__c_dlpack_exchange_api__` attribute.
- All conversions switched to `_no_sync` variants; stream synchronization is now explicit via `current_work_stream` callback.
- Adds non-owning `DLTensor` conversion path (`dltensor_from_py_object_no_sync`) for PyTorch tensors, avoiding unnecessary ref-counting.
- Updates 3rdparty/dlpack submodule to latest.

## Impact
- API: Breaking change to the DLPack exchange protocol: `__c_dlpack_from_pyobject__` replaced by `__c_dlpack_exchange_api__`. All internal function signatures renamed with `_no_sync` suffix.
- Flags/config: None.
- Data formats/schemas: New `DLPackExchangeAPI` C struct with versioned header, function pointers for managed/non-owning tensor exchange and stream query.

## Design Elements
Design elements this commit consumes:
- **DLPack exchange acceleration** (`.knowledge/designs/0020-dlpack-exchange-acceleration.md`): The entire C-level DLPack exchange protocol.
- **ADR: DLPack C-level exchange protocol** (`.knowledge/ADRs/0034-dlpack-c-level-exchange-protocol.md`): Previous function pointer approach.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): Cython tensor conversion paths.

Design elements this commit produces:
- **DLPackExchangeAPI struct protocol**: A versioned struct with function pointers for `managed_tensor_from_py_object_no_sync`, `managed_tensor_to_py_object_no_sync`, `dltensor_from_py_object_no_sync`, `managed_tensor_allocator`, and `current_work_stream`. Replaces previous ad-hoc function pointer registration.
- **Non-owning DLTensor conversion**: `toDLPackNonOwningImpl` fills a caller-owned `DLTensor` struct with direct pointers to PyTorch tensor storage, avoiding managed tensor overhead.
- **Explicit stream handling**: `current_work_stream` callback decouples stream queries from tensor conversion, enabling no-sync exchange.
