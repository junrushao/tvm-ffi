# Apply perfect forwarding to Function/TypedFunction construction and FunctionObjImpl
## TL;DR
- Applies `std::forward<TCallable>` (perfect forwarding) throughout the `Function` and `TypedFunction` construction chain: `Function(TCallable&&)`, `Function::FromPacked(TCallable&&)`, `Function::FromTyped(TCallable&&)`, `Function::FromPackedInternal(TCallable&&)`, and `TypedFunction` constructors/assignment operators.
- `FunctionObjImpl<TCallable>` now enforces via `static_assert` that `TCallable` is a non-const, non-reference type. It provides separate rvalue and lvalue constructors instead of by-value-then-move. Removes the `TStorage` alias (was `std::remove_cv_t<std::remove_reference_t<TCallable>>`), using `TCallable` directly since the static_assert guarantees it is already a clean value type.
- `FromPackedInternal` and `FromTyped` now use `std::decay_t<TCallable>` when instantiating `FunctionObjImpl`, ensuring the template parameter is a value type regardless of how the callable was forwarded.
- Adds SFINAE guards (`!std::is_same_v<std::decay_t<TCallable>, Function>` and `!std::is_same_v<std::decay_t<FLambda>, TSelf>`) to prevent forwarding constructors from hijacking copy/move construction.
- Minor: `TypedFunction(Function packed)` now uses `std::move(packed)` in its initializer.

## Key Exports
**Template class** (mutated contract): `FunctionObjImpl<TCallable>` -- `TCallable` must now be a decayed value type (no cv-qualifiers, no references). Two constructors:
```cpp
explicit FunctionObjImpl(TCallable&& callable);       // rvalue
explicit FunctionObjImpl(const TCallable& callable);  // lvalue copy
```

**Function methods** (signature change):
| Method | Before | After |
|--------|--------|-------|
| `Function(TCallable)` | by-value | `Function(TCallable&&)` with SFINAE guard |
| `Function::FromPacked(TCallable)` | by-value | `FromPacked(TCallable&&)` |
| `Function::FromTyped(TCallable)` | by-value | `FromTyped(TCallable&&)` |
| `Function::FromPackedInternal(TCallable)` | by-value | `FromPackedInternal(TCallable&&)` |

## Impact
- API: Source-compatible for callers (forwarding references accept both lvalues and rvalues). Binary ABI may differ due to template instantiation changes.
- Behavioral: Avoids unnecessary copies of callable objects when constructing Functions. Particularly beneficial for large captures in lambdas.
- Flags/config: None
- Data formats/schemas: None
