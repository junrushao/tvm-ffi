# Temporarily skip load_inline tests on non-Linux and add ninja to optional dependencies
## TL;DR
- Marks all four `test_load_inline_*` test functions with `@pytest.mark.xfail` on non-Linux platforms (`not sys.platform.startswith("linux")`), acknowledging that the `load_inline` JIT compilation pipeline does not yet work on macOS or Windows.
- Adds `ninja` as an explicit optional dependency in `pyproject.toml` under the `torch`, `test`, and a new `cpp` dependency group, making the build tool requirement discoverable via `pip install apache-tvm-ffi[cpp]` or `[test]`.

## Impact
- API: None. No functional code changes; only test expectations and packaging metadata are modified.
- Flags/config: Adds a new optional dependency group `cpp = ["ninja"]` in `pyproject.toml`. The existing `torch` and `test` groups now also include `ninja`.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Inline module compilation pipeline** ([`.knowledge/designs/0017-inline-module-compilation.md`](../designs/0017-inline-module-compilation.md)): The `load_inline` tests exercise the full JIT compilation pipeline (source decoration, ninja build, `load_module`). The `xfail` markers acknowledge that this pipeline has a platform gap -- its ninja build generation (`_generate_ninja_build()`) currently produces Unix-specific flags and linker invocations that do not work on macOS (likely RPATH / library extension issues) or Windows (MSVC vs. GCC/Clang flag differences). The design doc's stated goal of "cross-platform support (Linux, macOS, Windows)" is not yet met.
- **Packaging and build system** ([`.knowledge/designs/0016-packaging-and-build.md`](../designs/0016-packaging-and-build.md)): The `pyproject.toml` optional dependency groups are part of the packaging surface. This commit extends them to make `ninja` explicit rather than relying on `ninja` being pre-installed on `$PATH`.

Design elements this commit produces:
- None. This is a test-skip and dependency-metadata commit with no new design elements.

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0017-inline-module-compilation.md`** to add a "Platform Support Status" section documenting that `load_inline` is currently Linux-only, with macOS and Windows support pending. The section should enumerate the known platform-specific issues (e.g., shared library extension, RPATH, compiler flag differences, linker behavior). This helps future commit miners quickly classify follow-up commits that extend `load_inline` to new platforms.

None. The decision to temporarily skip tests rather than fix platform support is a pragmatic short-term choice that does not warrant a formal ADR.
