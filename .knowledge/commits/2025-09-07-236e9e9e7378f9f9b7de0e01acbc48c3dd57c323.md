# Temporarily skip load_inline tests on non-Linux and add ninja to optional deps
## TL;DR
- Marks all `test_load_inline_cpp*` tests with `@pytest.mark.xfail` on non-Linux platforms (macOS, Windows) because `load_inline` does not yet fully support them.
- Adds `ninja` as an explicit Python dependency in `pyproject.toml` under the `torch`, `test`, and a new `cpp` optional-dependency group.

## Key Exports
None

## Impact
- API: none
- ABI: none
- Behavioral: none -- tests that previously failed on non-Linux now report `xfail` instead of hard failure.
- Flags/config: New `[project.optional-dependencies] cpp = ["ninja"]` group in `pyproject.toml`. The `torch` and `test` groups now also include `ninja`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`): The `load_inline` function requires `ninja` in PATH. This commit makes that requirement explicit in packaging metadata rather than relying on users having it pre-installed.
- **Module system** (`.knowledge/designs/0013-module-system.md`): Tests exercise `tvm_ffi.load_module` via `load_inline`.

Design elements this commit produces:
- **`cpp` optional-dependency group**: New `pip install tvm-ffi[cpp]` extras group that installs `ninja`. This is a lightweight packaging convention, not a code-level design element.
