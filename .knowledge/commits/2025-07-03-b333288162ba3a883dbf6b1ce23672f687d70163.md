# Introduce reflection::GlobalDef for unified global function registration
## TL;DR
- Introduces `reflection::GlobalDef`, a new builder class in `include/tvm/ffi/reflection/reflection.h` that provides `def()`, `def_packed()`, and `def_method()` for registering global functions. It replaces the existing `TVM_FFI_REGISTER_GLOBAL("name").set_body_typed(...)` pattern with a reflection-aligned fluent API: `refl::GlobalDef().def("name", lambda)`.
- Migrates all existing `TVM_FFI_REGISTER_GLOBAL` call sites in `src/ffi/container.cc`, `src/ffi/function.cc`, `src/ffi/ndarray.cc`, `src/ffi/object.cc`, and `src/ffi/testing.cc` to use the new `GlobalDef` API within `TVM_FFI_STATIC_INIT_BLOCK` blocks. The old `TVM_FFI_REGISTER_GLOBAL` macro is not removed, but its usage is replaced throughout the core FFI source.
- Enhances `ReflectionDefBase::GetMethod` to support both `ObjectRef`-derived and `Object`-derived class method pointers, dispatching by `if constexpr (std::is_base_of_v<ObjectRef, Class>)` to pass by value (ObjectRef) vs. by const pointer (Object).

## Impact
- API: `GlobalDef` is a new public class in the reflection header. It uses `TVMFFIFunctionSetGlobalFromMethodInfo` (existing C API) to register functions with metadata (`TVMFFIMethodInfo` including name, doc, type_schema, flags). This means functions registered via `GlobalDef` carry richer metadata than those registered via the old `TVM_FFI_REGISTER_GLOBAL` path, which only stored name and function pointer. Downstream consumers that enumerate global functions via `TVMFFIMethodInfo` (e.g., stubgen, Python introspection) will see metadata for all migrated functions.
- Flags/config: none.
- Data formats/schemas: The test in `tests/cpp/test_function.cc` updates an expected error message from `object.Function` to `ffi.Function`, reflecting a type key rename that occurred in a prior commit. This is a test-only change.

## Design Elements

Design elements this commit **consumes**:

- **Function system / GlobalFunctionTable** ([`.knowledge/designs/0004-function-system.md`](../designs/0004-function-system.md)): `GlobalDef::RegisterFunc` ultimately calls `TVMFFIFunctionSetGlobalFromMethodInfo`, which delegates to `GlobalFunctionTable::Update(const TVMFFIMethodInfo*, bool)`. This is the metadata-aware overload that stores `TVMFFIMethodInfo` (name, doc, type_schema, flags, method function) in the global table entry, as opposed to the plain `Update(String, Function, bool)` used by `TVM_FFI_REGISTER_GLOBAL`.
- **Reflection system / ReflectionDefBase** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `GlobalDef` inherits from `ReflectionDefBase`, reusing its `GetMethod` template for method-pointer-to-Function conversion and `ApplyMethodInfoTrait` for processing extra arguments (docstrings, etc.). The `TVMFFIMethodInfo` struct (from the C API) is the registration payload.
- **C ABI / TVMFFIFunctionSetGlobalFromMethodInfo** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The C API function `TVMFFIFunctionSetGlobalFromMethodInfo` was already declared but only used by `ObjectDef::def_method` in the existing reflection registry. `GlobalDef` reuses this same C API entry point for all global function registrations.
- **TVM_FFI_STATIC_INIT_BLOCK** (in `include/tvm/ffi/base_details.h`): All migrated registration sites now use `TVM_FFI_STATIC_INIT_BLOCK({...})` which expands to `__attribute__((constructor))` on GCC/Clang or a variable-trick on other compilers. This replaces the `static inline Registry&` pattern used by `TVM_FFI_REGISTER_GLOBAL`.

Design elements this commit **produces**:

- **`reflection::GlobalDef` class** (`include/tvm/ffi/reflection/reflection.h`): A new builder class for global function registration. Provides three registration methods:
  - `def(name, func, extra...)` -- typed function via `Function::FromTyped`
  - `def_packed(name, func, extra...)` -- packed function via `Function::FromPacked`
  - `def_method(name, member_func_ptr, extra...)` -- member function pointer with automatic first-argument injection via `GetMethod_`
  All methods are chainable (return `GlobalDef&`). The private `RegisterFunc` method constructs a `TVMFFIMethodInfo` with name, doc, type_schema, flags, and the function packed as `AnyView(func).CopyToTVMFFIAny()`, then calls `TVMFFIFunctionSetGlobalFromMethodInfo`.

- **Enhanced `ReflectionDefBase::GetMethod` with ObjectRef support** (`include/tvm/ffi/reflection/reflection.h`): The `GetMethod` template now has two `if constexpr` branches:
  - `ObjectRef`-derived class: wraps the method pointer in a lambda that takes the class **by value** (e.g., `[func](Class target, Args... params) -> R { return (target.*func)(...); }`). This is correct because `ObjectRef` subclasses are cheap ref-counted handles (16 bytes, copy = IncRef).
  - `Object`-derived class: wraps in a lambda that takes `const Class*` pointer (the prior behavior). This distinction enables `def_method` in `GlobalDef` to correctly handle both `ObjectRef` methods and raw `Object*` methods.

## Reflection

### Design docs to write

- **`.knowledge/designs/0006-reflection.md` (update)**: The existing reflection design doc covers `ReflectionDef` for field registration and `ObjectDef` for per-type field/method registration. It should be updated to document `GlobalDef` as the new standard API for global function registration. The doc should cover:
  - The `def`/`def_packed`/`def_method` registration methods
  - How `GlobalDef` uses `TVMFFIMethodInfo` to carry metadata (doc, type_schema, flags) into the `GlobalFunctionTable`
  - The relationship between `GlobalDef` and the older `TVM_FFI_REGISTER_GLOBAL` macro (both work, but `GlobalDef` attaches richer metadata)
  - This helps future commit mining classify commits that add/modify global function registrations.

- **`.knowledge/designs/0004-function-system.md` (update)**: The `GlobalFunctionTable` section should note the two `Update` overloads: `Update(String, Function, bool)` (simple, used by `TVM_FFI_REGISTER_GLOBAL`) and `Update(const TVMFFIMethodInfo*, bool)` (metadata-rich, used by `GlobalDef`). The `Entry` type now extends `TVMFFIMethodInfo` and stores additional metadata. This matters for future commits that expose function metadata to Python stubgen or documentation tooling.

### ADRs to write

- **`.knowledge/ADRs/0006-globaldef-over-register-global.md`**: Records the decision to introduce `GlobalDef` as the preferred global function registration mechanism over `TVM_FFI_REGISTER_GLOBAL`.
  - Context: `TVM_FFI_REGISTER_GLOBAL` uses a `static inline Registry&` pattern that stores only name + function. The reflection system needs richer metadata (docstrings, type schemas, flags) for Python stub generation and IDE tooling.
  - Alternatives: (1) Extend `TVM_FFI_REGISTER_GLOBAL` to carry metadata -- adds complexity to the macro and the `Registry` class. (2) Keep separate mechanisms for simple and metadata-rich registration -- maintenance burden of two divergent APIs. (3) New `GlobalDef` builder -- consistent with `ObjectDef` style, extensible, uses the existing `TVMFFIMethodInfo` C API.
  - Trade-off: Migration cost (all `TVM_FFI_REGISTER_GLOBAL` call sites need updating) vs. unified metadata pipeline. The commit message indicates this is a multi-PR migration, so the old macro is not yet removed.

### Design diagrams to draw

- **Mermaid: GlobalDef registration flow**. Should depict: `GlobalDef().def("name", fn)` -> `Function::FromTyped(fn)` -> `RegisterFunc` -> construct `TVMFFIMethodInfo` -> `TVMFFIFunctionSetGlobalFromMethodInfo` -> `GlobalFunctionTable::Update(method_info)` -> `Entry(method_info)` stored in table. Compare with the old path: `TVM_FFI_REGISTER_GLOBAL("name").set_body_typed(fn)` -> `Function::Registry(name).set_body_typed(fn)` -> `Function::SetGlobal(name, func)` -> `TVMFFIFunctionSetGlobal` -> `GlobalFunctionTable::Update(name, func)` -> `Entry(name, func)` stored in table.

### Skill evolution (`/commit-ledger`)

- **Migration commit pattern recognition**: This commit is a "migration" pattern -- it introduces a new API (`GlobalDef`) and simultaneously migrates existing call sites from the old API (`TVM_FFI_REGISTER_GLOBAL`). The skill should recognize this pattern and explicitly note: (1) what the old API is, (2) what the new API is, (3) whether the old API is deprecated/removed, (4) how many call sites were migrated vs. remain. In this case, the old macro is not removed and downstream code outside `src/ffi/` may still use it. Future commits in this migration series should be tagged with the same scope.
