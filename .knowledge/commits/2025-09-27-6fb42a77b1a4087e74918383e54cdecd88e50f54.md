# Replace new/delete with raw aligned alloc in SimpleObjAllocator for tighter inplace array packing

## TL;DR
- Introduces `details::AlignedAlloc<align>(size)` and `details::AlignedFree(data)` as platform-portable aligned memory primitives (MSVC `_aligned_malloc`/`_aligned_free`, POSIX `malloc`/`posix_memalign`/`free`).
- Replaces `new StorageType()` / `delete` allocation in `SimpleObjAllocator::Handler<T>` with `AlignedAlloc<alignof(T)>(sizeof(T))` + placement new, and `delete[]` in `ArrayHandler` with `AlignedAlloc<align>(aligned_size)` + placement new.
- Removes the `StorageType` wrapper structs (both `alignas(T) char data[sizeof(T)]` in `Handler` and `std::aligned_storage` in `ArrayHandler`), enabling exact-size allocations instead of rounding up to `StorageType` multiples -- reducing memory waste for inplace arrays.

## Impact
- API: None -- `AlignedAlloc`/`AlignedFree` are `details::` internal, and `make_object`/`make_inplace_array_object` signatures are unchanged.
- Behavioral: Inplace array allocation now allocates `ceil(header + N*elem, alignof(ArrayType))` bytes instead of `ceil(header + N*elem, sizeof(ArrayType)) * sizeof(ArrayType)` bytes. For arrays where `sizeof(ArrayType)` is much larger than `sizeof(ElemType)`, this can significantly reduce memory waste. For scalar objects, allocation is the same size.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Object allocator CRTP pattern** ([.knowledge/designs/0002-object-system.md](../designs/0002-object-system.md)): `ObjAllocatorBase<Derived>` with `Handler<T>::New`/`Deleter` and `ArrayHandler<ArrayType, ElemType>::New`/`Deleter` -- unchanged structurally.
- **Two-phase deletion protocol** ([.knowledge/ADRs/0009-weak-reference-counting.md](../ADRs/0009-weak-reference-counting.md)): `kStrong`/`kWeak`/`kBoth` flag dispatch in `Deleter_` -- unchanged in semantics.
- **Placement new pattern**: The existing convention of allocating raw storage then placement-constructing the object -- preserved, but the raw storage source changes from `operator new` to `AlignedAlloc`.

Design elements this commit produces:
- **`AlignedAlloc<align>(size)` / `AlignedFree(data)`**: Platform-portable aligned memory primitives in `details::` namespace. These are the new canonical allocation/deallocation entry points for all object memory in `SimpleObjAllocator`.
- **Exact-size inplace array allocation**: The `ArrayHandler::New` now computes `(header + N*elem)` rounded up to alignment, instead of rounding up to `StorageType` (which was `sizeof(ArrayType)`-sized). This changes the allocation granularity from "multiples of the array header struct size" to "multiples of the array header alignment".

## Usage Examples
No new user-facing APIs. The change is transparent to callers of `make_object<T>()` and `make_inplace_array_object<ArrayType, ElemType>()`.

Before (old allocation for inplace array of 3 int32 elements with ArrayType size=48, align=8):
```cpp
// Old: StorageType = aligned_storage<48, 8>, unit = 48
// requested_size = 48 + 3*4 = 60
// num_storage_slots = ceil(60/48) = 2
// allocated = 2 * 48 = 96 bytes  (36 bytes wasted)
```

After (new allocation):
```cpp
// New: size = 48 + 3*4 = 60, align = 8
// aligned_size = (60 + 7) & ~7 = 64 bytes  (4 bytes wasted)
```
