# Improve documentation of TVMFFIFieldInfo.field_static_type_index and expand serialization test coverage

## TL;DR
- Rewrites the `field_static_type_index` doc-comment in `TVMFFIFieldInfo` (`c_api.h`) to clearly distinguish compile-time static type vs. runtime type, adds two `\warning` blocks, and mirrors the update in the Rust `c_api.rs` binding.
- Adds 40 C++ serialization tests (`tests/cpp/extra/test_serialization.cc`) and 58 Python serialization tests (`tests/python/test_serialization.py`) covering integer/float/string edge cases, DataType, Device, Array, Map, Shape, object round-trips, JSON structure validation, metadata, and error cases.
- Introduces two new test-only reflected objects (`TAllFieldsObj`, `TWithDefaultsObj`) in `tests/cpp/testing_object.h` to exercise all POD field types and default-value deserialization paths.

**Diff-message alignment note**: The commit message claims "Restore `TypeToFieldStaticTypeIndex` and `TypeToRuntimeTypeIndex` templates" — the actual diff in `type_traits.h` only removes a blank line. Both templates were already present in the file; no restoration occurred in this commit.

None — this commit adds no new public API symbols; all changes are documentation, tests, and test helpers.

- API: None — `TVMFFIFieldInfo.field_static_type_index` field itself is unchanged; only its doc-comment is updated.

## Usage Examples

**Context**: How `field_static_type_index` drives POD field inlining during serialization.

```python
# The serializer in src/ffi/extra/serialization.cc uses this logic per field:
#
# switch (field_info->field_static_type_index) {
#     case kTVMFFINone:     data["field"] = nullptr           # inlined
#     case kTVMFFIBool:     data["field"] = bool_value        # inlined
#     case kTVMFFIInt:      data["field"] = int64_value       # inlined
#     case kTVMFFIFloat:    data["field"] = float_value       # inlined
#     case kTVMFFIDataType: data["field"] = dtype_str         # inlined
#     default:              data["field"] = node_index        # → nodes[] ref
# }
#
# Invariant: field_static_type_index is kTVMFFIAny (-1) for fields declared as Any,
# even if the runtime value is int. Those go through node_index path (not inlined).
# Invariant: field_static_type_index is kTVMFFIArray for Array<int>, not int;
# element types are not reflected.

# Python round-trip (new test file: tests/python/test_serialization.py):
from tvm_ffi.serialization import from_json_graph_str, to_json_graph_str

result = from_json_graph_str(to_json_graph_str(42))
assert result == 42

# Verify POD fields are inlined (not node references):
class TestJSONStructure:
    def test_object_pod_fields_are_inlined(self):
        # A reflected object with int field → that field appears inline in "data" dict,
        # not as a node index.
        ...
```

**Context**: New test fixture showing all supported POD field types.

```cpp
// tests/cpp/testing_object.h — TAllFieldsObj
class TAllFieldsObj : public Object {
 public:
  bool v_bool; int64_t v_int; double v_float;
  DLDataType v_dtype; DLDevice v_device;
  String v_str; Optional<String> v_opt_str;
  Array<Any> v_array; Map<String, Any> v_map;
  // Registered via ObjectDef<TAllFieldsObj>().def_ro("v_bool", ...) etc.
  // Invariant: all 9 fields cover every serialization path in ObjectGraphSerializer
  TVM_FFI_DECLARE_OBJECT_INFO_FINAL("test.AllFields", TAllFieldsObj, Object);
};

// TWithDefaultsObj — tests deserialization with missing fields
class TWithDefaultsObj : public Object {
 public:
  int64_t required_val;          // no default
  int64_t default_int;           // refl::DefaultValue(42)
  String default_str;            // refl::DefaultValue("default")
  bool default_bool;             // refl::DefaultValue(true)
  TVM_FFI_DECLARE_OBJECT_INFO_FINAL("test.WithDefaults", TWithDefaultsObj, Object);
};
```
