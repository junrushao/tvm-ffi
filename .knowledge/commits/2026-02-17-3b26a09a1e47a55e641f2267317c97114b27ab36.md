# Expand TVMFFIFieldInfo.field_static_type_index documentation and add comprehensive serialization tests

## TL;DR

- Rewrites the `field_static_type_index` Doxygen block in `TVMFFIFieldInfo` (`include/tvm/ffi/c_api.h`) to clearly distinguish compile-time static type vs. runtime type, and document the serializer's POD-inlining contract.
- Adds 40 C++ serialization tests (`tests/cpp/extra/test_serialization.cc`) covering integer/float edge cases, string edge cases, object round-trips, and DAG/default-field semantics.
- Adds 58 Python serialization round-trip tests (`tests/python/test_serialization.py`) with class-based structure, covering primitives, containers, nested objects, structural equality, and default values.

## Key Exports

None — no new public API surface introduced; all changes are documentation or tests.

## Impact

- API: None — `TVMFFIFieldInfo.field_static_type_index` field signature unchanged.
- Behavioral: None — only documentation rewritten.
- Flags/config: None.
- Data formats/schemas: Documentation now explicitly states the serializer inlines POD values (None, Bool, Int, Float, DataType) directly when `field_static_type_index` identifies them as POD, routing everything else through the node graph.

## Design Elements

Design elements this commit consumes:

- **`TVMFFIFieldInfo.field_static_type_index`** (0001-c-abi): The compile-time static type index field on `TVMFFIFieldInfo`. This commit adds thorough documentation explaining the compile-time-vs-runtime distinction and the `\warning` that it must not be used for runtime type checking.
- **`TypeToFieldStaticTypeIndex<T>` / `TypeToRuntimeTypeIndex<T>`** (0008-type-traits): Templates in `include/tvm/ffi/type_traits.h` that map C++ types to their static/runtime type indices. Referenced in the commit message as "restored"; the actual diff only removes a blank line — both templates were already present.
- **`ToJSONGraph` / `FromJSONGraph`** (0010-json-serialization): Object-graph serialization helpers. The new tests exercise these heavily with all field types.
- **`ObjectDef<T>.def_ro()`** (0006-reflection): Used in `TAllFieldsObj::RegisterReflection()` and `TWithDefaultsObj::RegisterReflection()` to register test objects with the reflection system.
- **`StructuralEqual`** (0009-structural-eq-hash): Used in C++ serialization tests to verify round-trip fidelity.

Design elements this commit produces:

- **`TAllFieldsObj` / `TAllFields`** (test fixture): New test object in `tests/cpp/testing_object.h` with all POD + container field types (`bool`, `int64_t`, `double`, `DLDataType`, `DLDevice`, `String`, `Optional<String>`, `Array<Any>`, `Map<String,Any>`). Used to exercise serialization of every field kind.
- **`TWithDefaultsObj` / `TWithDefaults`** (test fixture): New test object with mix of required and default-valued fields, exercising deserialization when fields are absent.

## Usage Examples

End-to-end round-trip for a C++ object with all field types (from `tests/cpp/extra/test_serialization.cc`):

```cpp
// Register TAllFieldsObj and TWithDefaultsObj via RegisterReflection()
// then:
TAllFields obj(true, -7, 2.5, dtype, device, String("hello"), String("opt"), arr, map);
json::Value serialized = ToJSONGraph(obj);
Any deserialized = FromJSONGraph(serialized);
TAllFields result = deserialized.cast<TAllFields>();
EXPECT_EQ(result->v_bool, true);
EXPECT_EQ(result->v_int, -7);
```

Python equivalents from `tests/python/test_serialization.py`:

```python
from tvm_ffi.serialization import from_json_graph_str, to_json_graph_str

def _roundtrip(obj):
    return from_json_graph_str(to_json_graph_str(obj))

assert _roundtrip(True) is True
assert _roundtrip(42) == 42
assert _roundtrip(-1) == -1
```
