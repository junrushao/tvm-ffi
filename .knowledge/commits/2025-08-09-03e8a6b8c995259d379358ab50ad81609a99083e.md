# Use MSB tag in MapObj::slots_ to distinguish SmallMap vs DenseMap layout
## TL;DR
- Introduces a MSB (bit 63) tag in `MapObj::slots_` to indicate whether a map uses the SmallMap layout, replacing the previous heuristic of comparing `slots_` against `SmallMapObj::kMaxSize`.
- Adds `MapObj::IsSmallMap()`, `MapObj::kSmallTagMask`, per-subclass `NumSlots()` accessors, and private `SetSlotsAndSmallLayoutTag`/`SetSlotsAndDenseLayoutTag` setters that encapsulate the tag encoding.
- Refactors all dispatch sites (`TVM_FFI_DISPATCH_MAP`, `InsertMaybeReHash`, `CopyFrom`, probing, load-factor checks) to use the new tag-based API instead of raw `slots_` comparisons.

## Key Exports

**Constants (MapObj)**:
```cpp
static constexpr uint64_t kSmallTagMask = static_cast<uint64_t>(1) << 63;
```

**Methods (MapObj)**:
```cpp
bool IsSmallMap() const;  // returns (slots_ & kSmallTagMask) != 0
```

**Methods (SmallMapObj)**:
```cpp
uint64_t NumSlots() const;  // returns slots_ & ~kSmallTagMask
```
```cpp
// private
void SetSlotsAndSmallLayoutTag(uint64_t n);  // slots_ = (n & ~kSmallTagMask) | kSmallTagMask
```

**Methods (DenseMapObj)**:
```cpp
uint64_t NumSlots() const;  // returns slots_ (identity -- MSB is always clear for dense maps)
```
```cpp
// private
void SetSlotsAndDenseLayoutTag(uint64_t n);  // asserts MSB clear, then slots_ = n
```

## Impact
- API: `MapObj::IsSmallMap()` and subclass `NumSlots()` are new public methods. No existing public API signatures changed.
- ABI: **Breaking.** The encoding of `MapObj::slots_` changed -- SmallMap instances now have bit 63 set. Any binary compiled against the old layout interprets `slots_` differently and will misidentify map type.
- Behavioral: The SmallMap-to-DenseMap transition logic in `InsertMaybeReHash` is restructured. Previously it used three flat branches (`slots_ < kMaxSize`, `slots_ == kMaxSize`, else). Now it uses a two-level structure: `IsSmallMap() -> (NumSlots() < kMaxSize, NumSlots() == kMaxSize)` vs `else DenseMap`. Semantics are equivalent but the new structure enables future changes to `kMaxSize` without changing the dispatch condition.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Map two-tier layout** (SmallMapObj / DenseMapObj dispatch) -- `.knowledge/designs/containers.md` MapObj section
- **Container data indirection** (`void* data_`, `data_deleter_`) -- `.knowledge/ADRs/007-container-data-indirection.md`

- **Debug state marker** (`TVM_FFI_DEBUG_WITH_ABI_CHANGE`, `state_marker++` in `InsertMaybeReHash`)

Design elements this commit produces:
- **MSB-tagged slots_ encoding** -- `kSmallTagMask` (bit 63) in `MapObj::slots_` distinguishes SmallMap from DenseMap. This replaces the value-range heuristic (`slots_ <= kMaxSize`) with a structural tag, decoupling the small/dense boundary from the slot count.
- **Tag-aware accessor protocol** -- `IsSmallMap()` for dispatch, `NumSlots()` for slot count (masks off tag), `SetSlotsAnd{Small,Dense}LayoutTag()` for construction. All raw `slots_` access in dispatch/resize/copy/probe is replaced by these accessors.

## Usage Examples

**Dispatching on map layout (before vs after this commit):**
```cpp
// BEFORE: heuristic based on slot count value
uint64_t slots = base->slots_;
if (slots <= SmallMapObj::kMaxSize) {
    // SmallMap path
} else {
    // DenseMap path
}

// AFTER: explicit tag check
if (base->IsSmallMap()) {
    // SmallMap path -- use static_cast<SmallMapObj*>(base)->NumSlots() for slot count
} else {
    // DenseMap path -- use static_cast<DenseMapObj*>(base)->NumSlots() for slot count
}
```

**Constructing a SmallMapObj (internal):**
```cpp
ObjectPtr<SmallMapObj> p = make_inplace_array_object<SmallMapObj, KVType>(n);
p->data_ = p->AddressOf(0);
p->size_ = 0;
p->SetSlotsAndSmallLayoutTag(n);  // was: p->slots_ = n;
```
