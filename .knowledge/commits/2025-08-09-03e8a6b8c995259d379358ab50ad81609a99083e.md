# Use MSB tag in MapObj::slots_ to distinguish SmallMap vs DenseMap layout
## TL;DR
- Introduces a 1-bit MSB tag (`kSmallTagMask = 1ULL << 63`) in `MapObj::slots_` to indicate whether a map instance uses the small-map or dense-map layout, replacing the previous convention of comparing `slots_` against `SmallMapObj::kMaxSize` to dispatch.
- Adds `MapObj::IsSmallMap()`, `SmallMapObj::NumSlots()`, `DenseMapObj::NumSlots()`, `SmallMapObj::SetSlotsAndSmallLayoutTag()`, and `DenseMapObj::SetSlotsAndDenseLayoutTag()` as the sole access points for reading/writing `slots_`, encapsulating the tag-bit protocol.
- Restructures `MapObj::InsertMaybeReHash` to use explicit `IsSmallMap()` dispatch and a nested conditional on `NumSlots()` vs `kMaxSize`, eliminating the implicit three-way branch on raw `slots_` values.

## Impact
- API: **ABI-compatible but semantically breaking** -- the `slots_` field now has a different bit-level interpretation (MSB is a tag, not part of slot count). Any code that reads `slots_` directly (outside the official API) will see incorrect values for SmallMap instances. All in-tree access sites are updated. No new public methods are added to the `Map<K,V>` user-facing API.
- Flags/config: none.
- Data formats/schemas: The in-memory value of `MapObj::slots_` changes for `SmallMapObj` instances: the MSB is now set. For `DenseMapObj` instances, `slots_` is unchanged (MSB stays clear, verified by `SetSlotsAndDenseLayoutTag` assertion). This is an ABI change to the runtime representation of small maps.

## Design Elements
Design elements this commit **consumes**:

- **Container system -- Map dual-layout dispatch** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The commit directly modifies the `SmallMapObj`/`DenseMapObj` dispatch mechanism. Previously, the `TVM_FFI_DISPATCH_MAP` macro read `slots_` and compared against `SmallMapObj::kMaxSize` to determine layout type. The commit replaces this with `IsSmallMap()` which checks the MSB of `slots_`.
- **Container data indirection** ([`.knowledge/ADRs/0009-container-data-indirection.md`](../ADRs/0009-container-data-indirection.md)): The `data_`, `size_`, `slots_`, `data_deleter_` field layout in `MapObj` is preserved. The semantic change is confined to the `slots_` field's bit-level encoding.
- **DenseMapObj slot semantics** (established in commit `7e0a4b3`): The commit preserves the modulo-probing convention (`% slots_`) but wraps all access through `NumSlots()` to mask off the tag bit. `DenseMapObj::NumSlots()` is an identity function (MSB is always clear), so dense-map probing behavior is unchanged.

Design elements this commit **produces**:

- **MSB tag protocol for Map layout discrimination**: A new invariant: the MSB of `MapObj::slots_` is set for `SmallMapObj` and clear for `DenseMapObj`. This replaces the previous "value range" convention (`slots_ <= kMaxSize` implies small map). The new protocol is strictly more robust because it decouples layout discrimination from the slot count value, enabling future changes to `kMaxSize` without breaking dispatch logic.
- **Encapsulated slot access via `NumSlots()` / `SetSlots*Tag()`**: `SmallMapObj::NumSlots()` returns `slots_ & ~kSmallTagMask`, masking off the tag. `DenseMapObj::NumSlots()` returns `slots_` directly (identity, since MSB is always clear, guarded by assertion). `SetSlotsAndSmallLayoutTag(n)` writes `(n & ~kSmallTagMask) | kSmallTagMask`. `SetSlotsAndDenseLayoutTag(n)` asserts `(n & kSmallTagMask) == 0` and writes `n` directly. These four methods are the only write/read points for `slots_`.
- **Restructured `InsertMaybeReHash` dispatch**: The previous three-way branch (`slots_ < kMaxSize`, `slots_ == kMaxSize`, else dense) is replaced by a two-level dispatch: first `IsSmallMap()`, then within the small-map branch, `NumSlots() < kMaxSize` vs `NumSlots() == kMaxSize`. This is semantically equivalent but structurally cleaner and decoupled from the raw `slots_` value.

## Key Implementations

### MSB tag encoding

The core mechanism is `MapObj::kSmallTagMask = 1ULL << 63` and `MapObj::IsSmallMap()`:
- `SmallMapObj::Empty(n)` calls `SetSlotsAndSmallLayoutTag(n)` which sets `slots_ = (n & ~kSmallTagMask) | kSmallTagMask`.
- `DenseMapObj::Empty(fib_shift, n_slots)` calls `SetSlotsAndDenseLayoutTag(n_slots)` which asserts `(n_slots & kSmallTagMask) == 0` and writes `slots_ = n_slots`.
- All reads of slot count go through `NumSlots()` which masks off the tag for `SmallMapObj` and is identity for `DenseMapObj`.

**Invariants assumed**:
- `DenseMapObj` slot counts never exceed `2^63 - 1` (trivially true for practical hash tables).
- `SmallMapObj` slot counts never exceed `2^63 - 1` (trivially true since `kMaxSize = 4`).
- No code path reads `slots_` directly after this commit -- all go through `IsSmallMap()`, `NumSlots()`, or `SetSlots*Tag()`.

**Invariants enforced**:
- `SetSlotsAndDenseLayoutTag` asserts `(n & kSmallTagMask) == 0`, catching accidental tag corruption.
- `SetSlotsAndSmallLayoutTag` masks off the MSB before OR-ing the tag, making it idempotent.

### Dispatch macro change

`TVM_FFI_DISPATCH_MAP` / `TVM_FFI_DISPATCH_MAP_CONST` previously:
```cpp
uint64_t slots = base->slots_;
if (slots <= SmallMapObj::kMaxSize) { /* SmallMapObj path */ }
else { /* DenseMapObj path */ }
```

Now:
```cpp
if (base->IsSmallMap()) { /* SmallMapObj path */ }
else { /* DenseMapObj path */ }
```

The `slots` local variable is eliminated, removing a coupling between dispatch logic and slot count magnitude.

### InsertMaybeReHash restructuring

Before (three-way branch on raw `slots_`):
1. `slots_ < kMaxSize` -> small insert
2. `slots_ == kMaxSize && size_ < slots_` -> small insert
3. `slots_ == kMaxSize && size_ >= slots_` -> promote to dense
4. else -> dense insert

After (two-level dispatch):
1. `IsSmallMap()` -> cast to `SmallMapObj*`, then:
   - `NumSlots() < kMaxSize` -> small insert
   - `NumSlots() == kMaxSize`:
     - `size_ < NumSlots()` -> small insert
     - else -> promote to dense
2. else -> dense insert

The restructuring also replaces `TVM_FFI_ICHECK_GT(map_node->slots_, SmallMapObj::kMaxSize)` with the more semantic `TVM_FFI_ICHECK(!map_node->IsSmallMap())` in `DenseMapObj::InsertMaybeReHash`.

### Extension point

The commit message notes this "opens doors for future changes to small map boundary switch." By decoupling dispatch from `kMaxSize`, future commits can change `SmallMapObj::kMaxSize` (e.g., from 4 to 8) without touching the dispatch macro or `InsertMaybeReHash` logic -- only the `SmallMapObj::Empty()` and `SmallMapObj::InsertMaybeReHash` growth logic need to change.

**Common failure modes**:
- If a new code path reads `slots_` directly without going through `NumSlots()`, it will get a value with MSB set for small maps, causing incorrect slot counts (off by `2^63`). The encapsulation via `NumSlots()` is the defense.
- If `DenseMapObj` is accidentally constructed with MSB set in `n_slots`, the `SetSlotsAndDenseLayoutTag` assertion catches it.

## Reflection

### Design docs to write

- **`.knowledge/designs/0005-containers.md` -- update Map dispatch mechanism**: The current design doc describes `MapObj` fields including `int64_t slots_` as "Actual slot count" and notes "Probing uses `% slots_`". This commit changes `slots_` to carry a tag bit in the MSB. The doc should be updated to:
  - Document the `kSmallTagMask` bit protocol and `IsSmallMap()` predicate.
  - Change the description of `slots_` from "actual slot count" to "actual slot count with MSB tag for layout discrimination."
  - Document the `NumSlots()` / `SetSlots*Tag()` encapsulation.
  - This helps future commits that modify `kMaxSize`, add new map layouts, or change the dispatch mechanism.

### ADRs to write

- **`.knowledge/ADRs/0015-map-msb-layout-tag.md`**: Decision context: The previous Small/Dense map dispatch compared `slots_` against `SmallMapObj::kMaxSize`, coupling dispatch logic to the slot count value and preventing changes to the small-map size threshold without updating dispatch code. Alternatives considered: (1) Add an explicit `bool is_small_map_` field to `MapObj` (adds 8 bytes of padding per map instance due to alignment). (2) Use a virtual method `IsSmall()` (adds vtable overhead and breaks POD-layout-compatible C ABI). Trade-off: Stealing the MSB of `slots_` is zero-overhead (no extra storage, branch cost identical) and decouples dispatch from the `kMaxSize` constant, at the cost of slightly more complex slot access (`NumSlots()` masking) and a 2^63 maximum slot count (never a practical limitation).

### Design diagrams to draw
