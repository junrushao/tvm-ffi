# Update Map ABI to use MSB tag in slots_ for SmallMap/DenseMap discrimination
## TL;DR
- Introduces MSB (bit 63) of `MapObj::slots_` as a tag to distinguish SmallMap from DenseMap layout, replacing the previous heuristic of comparing `slots_` against `SmallMapObj::kMaxSize`.
- Adds `MapObj::IsSmallMap()`, `SmallMapObj::NumSlots()`, `DenseMapObj::NumSlots()`, and private setter methods (`SetSlotsAndSmallLayoutTag`, `SetSlotsAndDenseLayoutTag`) to encapsulate the tag bit manipulation.
- Updates all dispatch macros (`TVM_FFI_DISPATCH_MAP`, `TVM_FFI_DISPATCH_MAP_CONST`) and internal call sites to use `IsSmallMap()` and `NumSlots()` instead of raw `slots_` comparisons, decoupling the SmallMap/DenseMap boundary from the slot count value.

## Impact
- API: No public API changes. `IsSmallMap()` and `NumSlots()` are new public methods but are internal-facing (not part of the user-visible `Map<K,V>` API).
- Behavioral: SmallMap/DenseMap discrimination now uses an explicit tag bit instead of a slot-count threshold comparison. This decouples the discrimination mechanism from the actual `kMaxSize` value, enabling future changes to the SmallMap/DenseMap boundary without ABI implications.
- Flags/config: none
- Data formats/schemas: `slots_` field now has bit 63 reserved as a layout tag. SmallMap objects will have bit 63 set. This is an ABI change for any code that reads `slots_` directly.

## Design Elements
Design elements this commit consumes:
- **MapObj / SmallMapObj / DenseMapObj** (0006-containers): The existing two-tier map layout with small linear-probe and dense Robin Hood hash table.
- **TVM_FFI_DISPATCH_MAP macros** (0006-containers, commit `7e0a4b35`): The dispatch macros that downcast `MapObj*` to the correct subclass.
- **Container data pointer pattern** (commit `7e0a4b35`): `data_`, `data_deleter_` fields on MapObj.

Design elements this commit produces:
- **MSB tag protocol for MapObj::slots_**: Bit 63 of `slots_` encodes layout type (1=SmallMap, 0=DenseMap). Usable slot count accessed exclusively through `NumSlots()` methods. This replaces the implicit threshold-based discrimination (`slots_ <= kMaxSize`).
- **Encapsulated slot accessors**: `IsSmallMap()`, `SmallMapObj::NumSlots()`, `DenseMapObj::NumSlots()`, and private setters ensure all `slots_` access goes through tag-aware methods.

## Usage Examples
Before (threshold-based dispatch):
```cpp
// Old: dispatch by comparing raw slots_ against kMaxSize
uint64_t slots = base->slots_;
if (slots <= SmallMapObj::kMaxSize) {
    // SmallMap path
} else {
    // DenseMap path
}

// Old: InsertMaybeReHash used raw slots_ comparisons
if (base->slots_ < kSmallMapMaxSize) { ... }
else if (base->slots_ == kSmallMapMaxSize) { ... }
```
After (tag-based dispatch):
```cpp
// New: dispatch by checking MSB tag
if (base->IsSmallMap()) {
    SmallMapObj* sm = static_cast<SmallMapObj*>(base);
    // use sm->NumSlots() for actual slot count
} else {
    DenseMapObj* dm = static_cast<DenseMapObj*>(base);
    // dm->NumSlots() returns slots_ directly (MSB always clear)
}

// New: InsertMaybeReHash uses IsSmallMap() + NumSlots()
if (base->IsSmallMap()) {
    SmallMapObj* sm = static_cast<SmallMapObj*>(base);
    if (sm->NumSlots() < SmallMapObj::kMaxSize) { ... }
    else if (sm->NumSlots() == SmallMapObj::kMaxSize) { ... }
}
```
