# Fix Rust docs build by deferring copy to Sphinx build-finished event
## TL;DR
- Fixes Rust documentation integration by moving the `shutil.copytree` from `_build_rust_docs()` (config-init time) to a new `_copy_rust_docs_to_output()` handler connected to the Sphinx `build-finished` event.
- The old code copied Rust docs to a hardcoded source-tree path (`docs/reference/rust/generated/`), which was incorrect because Sphinx outputs to a separate build directory. The fix uses `app.outdir` to copy to the correct HTML output directory.
- Removes the `_RUST_OUTPUT_DIR` module-level constant and adds `from __future__ import annotations`.

## Key Exports
**Functions** (internal to `docs/conf.py`, not public API):
- `_copy_rust_docs_to_output(app: sphinx.application.Sphinx, exception: Exception | None) -> None` -- Sphinx `build-finished` event handler that copies `rust/target/doc/` to `{app.outdir}/reference/rust/generated/`. Skips copy if `exception is not None` or `build_rust_docs` is false.

## Impact
- API: None.
- ABI: None.
- Behavioral: Rust API documentation now appears in the correct location in the built Sphinx HTML output. Previously, docs were copied to the wrong directory (`docs/reference/rust/generated/` in the source tree) and would not appear in the final built site.
- Flags/config: None. The existing `build_rust_docs` config flag continues to control whether Rust docs are built.
- Data formats/schemas: None.
