# TypeSchema now emits Array/List/Map/Dict origins instead of collapsing to list/dict, enabling correct MutableSequence/MutableMapping annotations in generated stubs.

## TL;DR

- **Concern 1 — Type schema origins**: `_TYPE_SCHEMA_ORIGIN_CONVERTER` in `type_info.pxi` now maps `ffi.Array`→`Array`, `ffi.List`→`List`, `ffi.Map`→`Map`, `ffi.Dict`→`Dict` instead of collapsing all sequences to `list` and all mappings to `dict`. `TypeSchema` validation updated to accept `Array`/`List` and `Map`/`Dict` as equivalent to `list`/`dict` for arity checks; backward compat preserved for raw `list`/`dict` origins.
- **Concern 2 — Stub codegen fixes**: `TY_MAP_DEFAULTS` updated to emit `Sequence`/`MutableSequence` for `Array`/`List` and `Mapping`/`MutableMapping` for `Map`/`Dict`. `_type_suffix_and_record` in `codegen.py` gains collision-avoidance for function-name/type-name shadowing (adds `_Suffix` alias). Ruff `D105` (undocumented magic method) added to global ignore list so generated dunder stubs no longer require inline `# noqa`.
- **Concern 3 — Containers concept page**: New `docs/concepts/containers.rst` documents all five container types (Array, List, Tuple, Map, Dict), their mutability semantics, thread safety, and usage guidance. Updated `any.rst`, `cpp_lang_guide.md`, and `python_lang_guide.md` with List/Dict sections.

## Impact

- API: `TypeSchema` origin values for container types changed from `"list"`/`"dict"` to `"Array"`/`"List"`/`"Map"`/`"Dict"`. Code calling `TypeSchema.from_json_str(...)` and then inspecting `.origin` to distinguish `Array` from `List` can now do so. Code that directly compared `.origin == "list"` will miss `Array`/`List` origins — must update to `origin in ("list", "Array", "List")`.
- Behavioral: Generated stubs for `List`/`Dict` parameters now emit `MutableSequence`/`MutableMapping` instead of `Sequence`/`Mapping`, correctly conveying mutability. `StructuralKey` return type in `_ffi_api.py` narrowed from `Any` to `_StructuralKey`. `GetInvalidObject` return type narrowed from `Any` to `Object`.
- Flags/config: `D105` added to ruff `ignore` list in `pyproject.toml`. No behavioral change to runtime code.
- Data formats/schemas: `TypeSchema.repr()` docstring example updated from `{"type":"dict",...}` to `{"type":"ffi.Map",...}` — the wire format from C++ is unchanged; only the Python-side converter now keeps distinct names.

## Usage Examples

**Concern 1 — Distinguishing Array vs List origins from schema JSON:**

```python
from tvm_ffi.core import TypeSchema

# Before: both ffi.Array and ffi.List would produce origin="list"
s_arr = TypeSchema.from_json_str('{"type":"ffi.Array","args":[{"type":"int"}]}')
assert s_arr.origin == "Array"   # was "list" before this commit
assert s_arr.repr() == "Array[int]"

s_list = TypeSchema.from_json_str('{"type":"ffi.List","args":[{"type":"str"}]}')
assert s_list.origin == "List"   # was "list" before this commit

# Mapping through TY_MAP_DEFAULTS (what stubgen does):
from tvm_ffi.stub.consts import TY_MAP_DEFAULTS
# Array -> "collections.abc.Sequence"
# List  -> "collections.abc.MutableSequence"
```

**Concern 2 — Collision avoidance in codegen:**

```python
# If a function named "Foo" is generated in the same block as a type "Foo",
# the type import uses alias "_Foo" to avoid shadowing:
#   from somepkg import Foo as _Foo    (TYPE_CHECKING only)
#   def Foo(_0: _Foo, /) -> _Foo: ...  # function stub uses alias
```
