# Use distinct container type origins in type schema and stub generation
## TL;DR
- Refactors type schema and stub generation to use distinct Python-native container type origins (`list`, `dict`, `tuple`) for `Array`, `Map`, `Tuple` in generated stubs.
- Adds comprehensive container docs page (`docs/concepts/containers.rst`) and updates language guides.
- Adds devtools skill and stubgen tests.

## Key Exports

```python
# Type mapping changes in stub generation:
# Array<T> -> list[T] (was tvm_ffi.Array[T])
# Map<K,V> -> dict[K, V] (was tvm_ffi.Map[K, V])
# Tuple<T...> -> tuple[T, ...] (was tvm_ffi.Tuple[T, ...])
# Interacts with: stub codegen, type_info.pxi type schema
```

## Impact
- API: Generated stubs now use Python-native types for containers.
- Behavioral: None at runtime.
- Flags/config: None
- Data formats/schemas: None
