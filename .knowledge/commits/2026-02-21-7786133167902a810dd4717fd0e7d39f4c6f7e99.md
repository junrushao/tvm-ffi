# Use distinct container type origins (Array/List/Map/Dict) in TypeSchema and stub generation

## TL;DR
- `_TYPE_SCHEMA_ORIGIN_CONVERTER` now maps `ffi.Array→Array`, `ffi.List→List`, `ffi.Map→Map`, `ffi.Dict→Dict` (was collapsing to `list`/`dict`).
- `TY_MAP_DEFAULTS` in stub codegen maps `Array→Sequence`, `List→MutableSequence`, `Map→Mapping`, `Dict→MutableMapping`, preserving immutable vs mutable semantics in generated type stubs.
- Adds `docs/concepts/containers.rst` documenting all five containers with mutability semantics and thread safety.

## Impact
- API: `TypeSchema` origin strings for containers changed. Any code doing `schema.origin == "list"` or `"dict"` must be updated; backward compat retained for parsing only.
- Behavioral: Generated `.pyi` stubs now use `Sequence`/`MutableSequence`/`Mapping`/`MutableMapping` instead of uniform `list`/`dict`. Type checkers will enforce correct mutability contracts.
- Flags/config: none
- Data formats/schemas: `type_schema` JSON keys `"ffi.Array"`, `"ffi.List"`, `"ffi.Map"`, `"ffi.Dict"` now produce distinct Python origin strings.

## Usage Examples

```python
# Before: both Array and List schema => "list"
schema = TypeSchema.from_json_str('{"type":"ffi.Array","args":[{"type":"int"}]}')
assert schema.origin == "list"   # old behavior

# After: distinct origins
schema = TypeSchema.from_json_str('{"type":"ffi.Array","args":[{"type":"int"}]}')
assert schema.origin == "Array"
assert schema.repr() == "Array[int]"

# Generated stubs now use correct ABC:
# def my_fn(data: collections.abc.Sequence[int]) -> ...   # for Array param
# def my_fn(data: collections.abc.MutableMapping[str, Any]) -> ...  # for Dict param
```
