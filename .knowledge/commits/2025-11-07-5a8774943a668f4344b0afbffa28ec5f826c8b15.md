# Improve torch fallback, dtype conversion, and convert() protocol coverage
## TL;DR
- **Torch fallback bug fix**: Fixes `TVMFFIPyArgSetterTorchFallback_` to check `ctx.device_type == -1` (was `!= -1`), so CUDA device/stream info is only captured on first use.
- **dtype return type fix**: Refactors dtype conversion to consistently return `tvm_ffi.dtype` (the Python str-subclass) instead of raw `DataType` Cython objects. Introduces `make_dtype_from_dl_data_type()` helper and renames internal maps from `*_DTYPE_TO_DTYPE` to `*_DTYPE_TO_DL_DATA_TYPE` for clarity.
- **convert() protocol coverage**: Extends `tvm_ffi.convert()` to handle `__dlpack_data_type__`, `__tvm_ffi_object__`, `__cuda_stream__`, `__tvm_ffi_opaque_ptr__`, `__dlpack_device__`, and `ctypes.c_void_p` objects, preventing them from being wrapped as opaque Python objects.
- Renames `_create_dtype_from_tuple` to `_create_cdtype_from_tuple` and adds `DataType.__hash__`.

### Concern 1: Torch fallback device tracking bug
The condition `ctx.device_type != -1` was inverted -- it should be `== -1` to mean "device not yet set". This caused the stream/device info to be skipped on the first call and overwritten on subsequent calls.

### Concern 2: dtype return type consistency
`_convert_torch_dtype_to_ffi_dtype` and `_convert_numpy_dtype_to_ffi_dtype` now use `make_dtype_from_dl_data_type()` which returns a proper `_CLASS_DTYPE` (tvm_ffi.dtype) str-subclass instance.

### Concern 3: convert() protocol awareness
`tvm_ffi.convert()` now recognizes protocol objects and returns them as-is (or converts dtype protocols), rather than wrapping them as opaque Python objects.

## Key Exports
**Renamed function**:
- `_create_dtype_from_tuple` -> `_create_cdtype_from_tuple` (in `core.pyi` and `dtype.pxi`)

**New Cython helper**:
- `make_dtype_from_dl_data_type(DLDataType) -> dtype` -- creates a `tvm_ffi.dtype` from a `DLDataType`

**New method on `DataType`**:
- `DataType.__hash__() -> int` -- hashes `(code, bits, lanes)` tuple

**Renamed internal Cython variables**:
- `TORCH_DTYPE_TO_DTYPE` -> `TORCH_DTYPE_TO_DL_DATA_TYPE`
- `NUMPY_DTYPE_TO_DTYPE` -> `NUMPY_DTYPE_TO_DL_DATA_TYPE`
- `MLDTYPES_DTYPE_TO_DTYPE` -> `MLDTYPES_DTYPE_TO_DL_DATA_TYPE`
- `TorchDLPackToPyObjectFallback_` -> `TorchManagedTensorToPyObjectNoSyncFallback_`

**Renamed env var**:
- `TVM_FFI_SKIP_c_dlpack_from_pyobject` -> `TVM_FFI_SKIP_C_DLPACK_EXCHANGE_API`

## Impact
- API: `_create_dtype_from_tuple` renamed to `_create_cdtype_from_tuple` (internal but exposed in `core.pyi`); env var `TVM_FFI_SKIP_c_dlpack_from_pyobject` renamed
- Behavioral: `tvm_ffi.convert()` now correctly returns `tvm_ffi.dtype` for dtype inputs and handles protocol objects instead of wrapping them as opaque; torch fallback correctly captures device info on first use
- Flags/config: env var rename `TVM_FFI_SKIP_c_dlpack_from_pyobject` -> `TVM_FFI_SKIP_C_DLPACK_EXCHANGE_API`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Cython arg setter dispatch factory per `.knowledge/designs/0015-python-ffi-call-dispatch.md`
- DLPack exchange API per `.knowledge/designs/0017-dlpack-interop.md`
- dtype/DataType system -- the Cython `DataType` cdef class and `_CLASS_DTYPE` str-subclass pattern

Design elements this commit mutates:
- `convert()` function now has awareness of FFI protocols (`__dlpack_data_type__`, `__tvm_ffi_object__`, `__cuda_stream__`, `__tvm_ffi_opaque_ptr__`, `__dlpack_device__`) -- previously these fell through to opaque object wrapping
- dtype construction path unified through `make_dtype_from_dl_data_type()`

## Usage Examples
```python
import tvm_ffi

# convert() now returns tvm_ffi.dtype for protocol objects
class MyDType:
    def __dlpack_data_type__(self):
        return (2, 32, 1)  # float32

result = tvm_ffi.convert(MyDType())
assert isinstance(result, tvm_ffi.dtype)
assert result == "float32"
```
