# Fix dtype conversion return type, torch fallback device detection, and rename internal symbols
## TL;DR
- Fixes `convert()` to return proper `tvm_ffi.dtype` for `__dlpack_data_type__` protocol objects and pass through protocol-bearing objects (`__tvm_ffi_object__`, `__cuda_stream__`, `__tvm_ffi_opaque_ptr__`, `__dlpack_device__`) instead of wrapping as opaque.
- Fixes a logic inversion bug in torch CUDA fallback setter: `ctx.device_type != -1` was wrong; corrected to `ctx.device_type == -1` so stream/device context is captured on the first CUDA tensor, not skipped.
- Renames internal Cython symbols for clarity: `_create_dtype_from_tuple` -> `_create_cdtype_from_tuple`, `TORCH_DTYPE_TO_DTYPE` -> `TORCH_DTYPE_TO_DL_DATA_TYPE` (and similar for numpy/mldtypes), `TorchDLPackToPyObjectFallback_` -> `TorchManagedTensorToPyObjectNoSyncFallback_`, env var `TVM_FFI_SKIP_c_dlpack_from_pyobject` -> `TVM_FFI_SKIP_C_DLPACK_EXCHANGE_API`.
- Adds `DataType.__hash__` and refactors `make_ret_dtype` into a reusable `make_dtype_from_dl_data_type` helper.

## Impact
- API: `_create_dtype_from_tuple` renamed to `_create_cdtype_from_tuple` in Cython and stub. Any out-of-tree code calling the old name will break. Env var `TVM_FFI_SKIP_c_dlpack_from_pyobject` renamed to `TVM_FFI_SKIP_C_DLPACK_EXCHANGE_API`.
- Behavioral: (1) `convert()` now returns `tvm_ffi.dtype` for objects with `__dlpack_data_type__` protocol, and passes through objects with `__tvm_ffi_object__`, `__cuda_stream__`, `__tvm_ffi_opaque_ptr__`, or `__dlpack_device__` instead of wrapping as opaque. (2) Torch CUDA fallback now correctly captures device context on first CUDA tensor (was previously never capturing due to inverted condition). (3) `DataType` is now hashable. (4) `_create_cdtype_from_tuple` no longer passes string to `cls.__new__` (was `cls.__new__(cls, str(cdtype))`, now `cls.__new__(cls)`).
- Flags/config: Environment variable `TVM_FFI_SKIP_c_dlpack_from_pyobject` renamed to `TVM_FFI_SKIP_C_DLPACK_EXCHANGE_API`.
- Data formats/schemas: none

## Usage Examples

**Bugfix -- torch CUDA device detection (before/after):**

```python
# BEFORE (bug): device_type != -1 means "skip if NOT already set",
# so CUDA context was never captured on the first tensor.
if is_cuda and ctx.device_type != -1:   # BUG: always false on first tensor
    ctx.device_type = temp_dltensor.device.device_type

# AFTER (fix): device_type == -1 means "capture if NOT yet set"
if is_cuda and ctx.device_type == -1:   # CORRECT: captures on first tensor
    ctx.device_type = temp_dltensor.device.device_type
```

**New convert() behavior -- __dlpack_data_type__ protocol:**

```python
import tvm_ffi

class DLPackDataTypeProtocol:
    def __init__(self, dlpack_data_type):
        self._dlpack_data_type = dlpack_data_type
    def __dlpack_data_type__(self):
        return self._dlpack_data_type

dtype = tvm_ffi.dtype("float32")
x = DLPackDataTypeProtocol((dtype.type_code, dtype.bits, dtype.lanes))
converted = tvm_ffi.convert(x)
assert isinstance(converted, tvm_ffi.dtype)
assert converted == dtype
```
