# Add TensorView non-owning tensor view and migrate examples/docs to prefer it over Tensor
## TL;DR
- Introduces `ffi::TensorView`, a non-owning lightweight view over `DLTensor` data, analogous to `ShapeView` for `Shape`. It stores a `DLTensor` by value (copied from the source), without retaining a ref-counted reference.
- Provides a `TypeTraits<TensorView>` specialization mapping to `kTVMFFIDLTensorPtr`, with `TryCastFromAnyView` accepting both raw `DLTensor*` and owned `Tensor` (extracting the underlying `DLTensor*`). Deliberately disables `storage_enabled` and `MoveToAny`/`MoveFromAny` since TensorView does not own data.
- Migrates all example code, docs, and inline-compilation tests from `ffi::Tensor` to `ffi::TensorView` as the recommended FFI function parameter type, establishing the convention that kernel ops should accept `TensorView` to support both owning and non-owning tensor inputs.
- Bumps version from `0.1.0b12` to `0.1.0b13`.

    Analogous to ShapeView for Shape. Added in 1ec6236."""

    def __init__(self, tensor: Tensor) -> None: ...

    def __init__(self, tensor: Ptr[DLTensor]) -> None: ...
        # Implicit conversion from raw DLTensor pointer.
        # Invariant: tensor must be non-null. Asserted via TVM_FFI_ICHECK.

    # Copy/move constructors and assignment: default
    # Move from Tensor: DELETED (prevents accidental ownership loss)
    #   TensorView(Tensor&&) = delete
    #   operator=(Tensor&&) = delete

    def shape(self) -> ShapeView: ...                 # ShapeView(tensor_.shape, tensor_.ndim)

    # Interacts with: ShapeView (shape() and strides() return ShapeView)
    # Interacts with: TypeTraits<TensorView> (FFI type conversion)
    # Interacts with: TVM_FFI_DLL_EXPORT_TYPED_FUNC (recommended parameter type for exported kernel ops)
    # Invariant: non-owning -- caller must keep underlying tensor data alive for the lifetime of TensorView
    # Invariant: API mirrors Tensor for easy substitution (shape, strides, data_ptr, ndim, numel, dtype, IsContiguous)

## Impact
- API: New `ffi::TensorView` class added. No existing API removed. All example/doc/test function signatures changed from `ffi::Tensor` to `ffi::TensorView` (non-breaking: `Tensor` implicitly converts to `TensorView`).
- Behavioral: FFI functions declared with `TensorView` parameters now accept both owning `Tensor` and non-owning `DLTensor*` inputs without requiring the caller to construct an owning reference. This broadens the input types kernel ops can handle.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**Context**: Defining an FFI-exported kernel op that accepts both owning Tensor and non-owning DLTensor* inputs.

```cpp
#include <tvm/ffi/container/tensor.h>

// Recommended: use TensorView for FFI function parameters
void AddOne(ffi::TensorView x, ffi::TensorView y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
  int64_t n = x.shape()[0];
  for (int64_t i = 0; i < n; ++i) {
    static_cast<float*>(y.data_ptr())[i] =
        static_cast<float*>(x.data_ptr())[i] + 1.0f;
  }
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne);

// C++ test: TensorView from Tensor, then round-trip through AnyView
Tensor tensor = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
TensorView view = tensor;                    // implicit conversion
AnyView any_view = view;                     // kTVMFFIDLTensorPtr
TensorView view2 = any_view.as<TensorView>().value();  // round-trip
```
