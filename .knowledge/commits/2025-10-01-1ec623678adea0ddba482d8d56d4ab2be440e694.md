# Introduce TensorView non-owning view for DLTensor data in FFI function signatures

## TL;DR
- Adds `ffi::TensorView`, a non-owning lightweight view over a `DLTensor`, for use in FFI function signatures where the caller may not hold an owning `Tensor` reference.
- Provides `TypeTraits<TensorView>` specialization mapping to `kTVMFFIDLTensorPtr` type index, with `TryCastFromAnyView` supporting both `DLTensor*` and `Tensor` sources (but no `MoveToAny`/`MoveFromAny` -- deliberately non-owning).
- Migrates all example/doc/test kernel signatures from `ffi::Tensor` to `ffi::TensorView` as the recommended argument type for exported ops.

## Key Exports

```python
class TensorView:
    """Non-owning view of a DLTensor. Stores a shallow copy of the DLTensor struct.
    The caller must ensure the underlying data (including shape/strides memory) outlives this view."""

    def __init__(self, tensor: Tensor): ...
        # Invariant: tensor.defined() must be true
        # Copies the DLTensor struct (not the data) from the Tensor's underlying TensorObj
    def __init__(self, tensor: DLTensor_ptr): ...
        # Invariant: tensor must not be nullptr
        # Copies the DLTensor struct (not the data) from the pointer

    # Explicitly deleted: TensorView(Tensor&&) and operator=(Tensor&&)
    # Rationale: moving an owning Tensor into a non-owning view would drop the refcount

    def shape(self) -> ShapeView: ...
        # Interacts with: ShapeView (from DLTensor.shape + DLTensor.ndim)
    def strides(self) -> ShapeView: ...
        # Invariant: DLTensor.strides must not be null
        # Interacts with: ShapeView (from DLTensor.strides + DLTensor.ndim)
    def data_ptr(self) -> void_ptr: ...
    def ndim(self) -> int32: ...
    def numel(self) -> int64: ...
        # Interacts with: ShapeView.Product()
    def dtype(self) -> DLDataType: ...
    def IsContiguous(self) -> bool: ...
        # Interacts with: tvm::ffi::IsContiguous() free function

# TypeTraits specialization:
# TypeTraits<TensorView>:
#   storage_enabled = False  (cannot be stored in Any -- non-owning)
#   field_static_type_index = kTVMFFIDLTensorPtr
#   CopyToAnyView: stores pointer as kTVMFFIDLTensorPtr in TVMFFIAny.v_ptr
#   TryCastFromAnyView: accepts kTVMFFIDLTensorPtr (direct) OR kTVMFFITensor (via TVMFFITensorGetDLTensorPtr)
#   No MoveToAny/MoveFromAny -- deliberately non-owning
#   Interacts with: AnyView (implicit conversion TensorView -> AnyView)
#   Interacts with: Function::FromTyped (enables TensorView as FFI function parameter type)

# StaticTypeKey addition:
# StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"
#   Interacts with: TypeTraits<TensorView>::TypeStr()
```

## Impact
- API: New `ffi::TensorView` class in `include/tvm/ffi/container/tensor.h`. New `StaticTypeKey::kTVMFFIDLTensorPtr` in `include/tvm/ffi/object.h`. All example kernel functions change signature from `ffi::Tensor` to `ffi::TensorView` (documentation, examples, tests).
- Behavioral: FFI functions using `TensorView` can now accept both owning `Tensor` and non-owning `DLTensor*` arguments transparently via `TryCastFromAnyView`. Previously `ffi::Tensor` required an owning reference.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TypeTraits<T>` protocol ([0002-ffi-any-value-system.md](../design-records/0002-ffi-any-value-system.md)) -- specializes `CopyToAnyView`, `CheckAnyStrict`, `CopyFromAnyViewAfterCheck`, `TryCastFromAnyView` for `TensorView`.
- `ShapeView` non-owning view ([0006-ffi-containers.md](../design-records/0006-ffi-containers.md)) -- reused for `TensorView::shape()` and `TensorView::strides()` return types. `TensorView` follows the same "non-owning lightweight view" pattern established by `ShapeView`.
- `DLTensor` C ABI struct, `TypeIndex::kTVMFFIDLTensorPtr`, `TVMFFITensorGetDLTensorPtr` -- pre-existing C ABI types.
- `TVM_FFI_DLL_EXPORT_TYPED_FUNC` macro ([0013-ffi-packaging-and-distribution.md](../design-records/0013-ffi-packaging-and-distribution.md)) -- used in examples to export kernel functions with `TensorView` params.
- `StaticTypeKey` struct ([0001-ffi-c-abi.md](../design-records/0001-ffi-c-abi.md)) -- extended with `kTVMFFIDLTensorPtr`.

Design elements this commit produces:
- `ffi::TensorView` class -- a new non-owning view type for DLTensor data, establishing the convention that kernel ops should prefer `TensorView` over `Tensor` for broader input compatibility.
- `TypeTraits<TensorView>` -- a `storage_enabled = false` TypeTraits specialization (first of its kind among the view types -- `ShapeView` does not have a TypeTraits specialization). Sets the pattern for non-storable view types in the FFI type system.
- Recommended practice: use `ffi::TensorView` (not `ffi::Tensor`) as the argument type for exported FFI kernel functions.

## Usage Examples

C++ kernel function using `TensorView` as recommended argument type:
```cpp
#include <tvm/ffi/container/tensor.h>
namespace ffi = tvm::ffi;

void AddOne(ffi::TensorView x, ffi::TensorView y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
  float* x_data = static_cast<float*>(x.data_ptr());
  float* y_data = static_cast<float*>(y.data_ptr());
  for (int i = 0; i < x.shape()[0]; ++i) {
    y_data[i] = x_data[i] + 1.0f;
  }
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne);
```

C++ test showing TensorView <-> AnyView round-trip:
```cpp
Tensor tensor = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
TensorView view = tensor;           // implicit conversion from owning Tensor
AnyView any_view = view;            // CopyToAnyView: stores as kTVMFFIDLTensorPtr
TensorView view2 = any_view.as<TensorView>().value();  // TryCastFromAnyView
assert(view2.ndim() == 3);
```
