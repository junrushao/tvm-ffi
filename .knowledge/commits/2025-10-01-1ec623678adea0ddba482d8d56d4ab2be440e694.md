# Introduce TensorView as a non-owning tensor view for FFI functions
## TL;DR
- Adds `ffi::TensorView`, a lightweight non-owning view over a `DLTensor`, as the new recommended parameter type for FFI-exported kernel functions.
- Includes a `TypeTraits<TensorView>` specialization that maps to `kTVMFFIDLTensorPtr` (view-only, no `MoveToAny`/`MoveFromAny`), with `TryCastFromAnyView` accepting both `kTVMFFIDLTensorPtr` and `kTVMFFITensor`.
- Updates all examples, docs, and tests to use `ffi::TensorView` instead of `ffi::Tensor` for function parameters, establishing `TensorView` as the preferred interface type for kernel ops.

## Key Exports

**Types/Classes**:
- `tvm::ffi::TensorView` -- non-owning DLTensor view class
  - Key fields: `DLTensor tensor_` (private, stored by value)
  - Constructors: `TensorView(const Tensor&)`, `TensorView(const DLTensor*)`, copy, move (default)
  - Deleted: `TensorView(Tensor&&)` (prevents binding to rvalue owning tensors)
  - `operator=(const Tensor&)` -- assigns from owning Tensor
  - `operator=(Tensor&&) = delete` -- prevents move-assignment from owning Tensor
  - `const DLTensor* operator->() const` -- access underlying DLTensor
  - `ShapeView shape() const` -- returns shape view
  - `ShapeView strides() const` -- returns strides view (asserts non-null)
  - `void* data_ptr() const` -- raw data pointer
  - `int32_t ndim() const` -- number of dimensions
  - `int64_t numel() const` -- total number of elements
  - `DLDataType dtype() const` -- data type
  - `bool IsContiguous() const` -- contiguity check

**TypeTraits specialization**:
- `TypeTraits<TensorView>` (inherits `TypeTraitsBase`)
  - `storage_enabled = false` (cannot be stored in `Any`; view-only)
  - `field_static_type_index = TypeIndex::kTVMFFIDLTensorPtr`
  - `CopyToAnyView` -- stores as `kTVMFFIDLTensorPtr` with pointer to internal `DLTensor`
  - `CheckAnyStrict` -- matches `kTVMFFIDLTensorPtr` only
  - `CopyFromAnyViewAfterCheck` -- constructs from `DLTensor*`
  - `TryCastFromAnyView` -- accepts `kTVMFFIDLTensorPtr` directly OR `kTVMFFITensor` (extracts `DLTensor*` via `TVMFFITensorGetDLTensorPtr`)
  - No `MoveToAny`/`MoveFromAny` (deliberately, since TensorView does not own data)

**Constants**:
- `StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"` -- new static type key string (added to `object.h`)

## Impact
- API: `ffi::TensorView` is now the recommended parameter type for FFI kernel functions. All examples and docs changed from `ffi::Tensor` to `ffi::TensorView`. Existing code using `ffi::Tensor` continues to work unchanged.
- ABI: none (new type only; no changes to existing types or layouts)
- Behavioral: `TryCastFromAnyView<TensorView>` accepts both `kTVMFFIDLTensorPtr` (raw DLTensor pointers from DLPack) and `kTVMFFITensor` (owned Tensor objects), allowing TensorView parameters to accept the broadest range of tensor inputs.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Any/AnyView system** (`.knowledge/designs/any-system.md`): `kTVMFFIDLTensorPtr` is already documented as a view-only type index. TensorView provides a typed C++ wrapper for values stored under this type index.
- **TypeTraits protocol** (`.knowledge/designs/type-traits.md`): The `TypeTraits<TensorView>` specialization follows the standard protocol, using `TypeTraitsBase` as the base, setting `storage_enabled = false` for view-only semantics.
- **Tensor container** (`.knowledge/designs/containers.md`): `TensorView` is constructed from `Tensor` (owning) or `DLTensor*` (raw). The `TryCastFromAnyView` path uses `TVMFFITensorGetDLTensorPtr` to extract from owned tensors.
- **DLPack fast-path** (`.knowledge/designs/0018-dlpack-fast-path.md`): DLPack export produces `kTVMFFIDLTensorPtr` values, which TensorView can directly consume.

Design elements this commit produces:
- **TensorView as preferred kernel parameter type**: Replaces the prior recommendation of `ffi::Tensor` (established in 742b16e) with `ffi::TensorView` for FFI-exported functions. The rationale is that kernel ops should accept non-owning views for maximum flexibility, since callers may not always be able to provide an owning reference.

## Usage Examples

### C++ kernel using TensorView
**Context**: Writing an FFI-exported function that accepts any tensor input (owned or non-owning).
```cpp
#include <tvm/ffi/container/tensor.h>

namespace ffi = tvm::ffi;

void AddOne(ffi::TensorView x, ffi::TensorView y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
  int n = x->shape[0];
  float* xd = static_cast<float*>(x->data);
  float* yd = static_cast<float*>(y->data);
  for (int i = 0; i < n; ++i) {
    yd[i] = xd[i] + 1.0f;
  }
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne);
```

### C++ test: TensorView from Tensor and AnyView round-trip
**Context**: Demonstrating TensorView construction and AnyView interop (from the test added in this commit).
```cpp
Tensor tensor = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
TensorView tensor_view = tensor;  // implicit conversion from Tensor

// Access shape, dtype
EXPECT_EQ(tensor_view.shape().size(), 3);
EXPECT_EQ(tensor_view.dtype().code, kDLFloat);

// Round-trip through AnyView
AnyView result = tensor_view;  // stored as kTVMFFIDLTensorPtr
TensorView tensor_view2 = result.as<TensorView>().value();
EXPECT_EQ(tensor_view2.shape()[0], 1);
```
