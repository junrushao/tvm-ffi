# Introduce TensorView as a non-owning lightweight view of a Tensor for FFI function signatures

## TL;DR
- Adds `ffi::TensorView`, a non-owning, non-ObjectRef view wrapping a raw `DLTensor` struct, enabling FFI-exported functions to accept tensor data without requiring ownership.
- Provides a `TypeTraits<TensorView>` specialization that maps to `kTVMFFIDLTensorPtr`, with `storage_enabled = false` (cannot be stored in `Any`, only passed through `AnyView`), and supports coercion from both `DLTensor*` and owning `Tensor`.
- Updates all examples, docs, and inline-module templates to use `TensorView` instead of `Tensor` as the recommended parameter type for kernel ops.

## Key Exports

**Class `TensorView`** (`include/tvm/ffi/container/tensor.h`):
```cpp
class TensorView {
public:
  TensorView(const Tensor& tensor);       // implicit from owning Tensor (asserts defined)
  TensorView(const DLTensor* tensor);      // implicit from raw DLTensor* (asserts non-null)
  TensorView(const TensorView&) = default;
  TensorView(TensorView&&) = default;
  TensorView& operator=(const Tensor& tensor);
  TensorView(Tensor&& tensor) = delete;           // prevents accidental rvalue capture
  TensorView& operator=(Tensor&& tensor) = delete; // prevents accidental rvalue capture

  const DLTensor* operator->() const;  // access underlying DLTensor fields
  ShapeView shape() const;
  ShapeView strides() const;           // asserts strides != nullptr
  void* data_ptr() const;
  int32_t ndim() const;
  int64_t numel() const;               // shape().Product()
  DLDataType dtype() const;
  bool IsContiguous() const;
private:
  DLTensor tensor_;  // shallow copy of the DLTensor struct (pointers, not data)
};
```

**TypeTraits specialization** (`TypeTraits<TensorView>`):
```cpp
template<>
struct TypeTraits<TensorView> : public TypeTraitsBase {
  static constexpr bool storage_enabled = false;  // cannot be stored in Any
  static constexpr int32_t field_static_type_index = TypeIndex::kTVMFFIDLTensorPtr;
  // CopyToAnyView: stores DLTensor* in v_ptr with kTVMFFIDLTensorPtr type_index
  // CheckAnyStrict: type_index == kTVMFFIDLTensorPtr
  // TryCastFromAnyView: accepts kTVMFFIDLTensorPtr OR kTVMFFITensor (coercion from owning Tensor)
  // No MoveToAny/MoveFromAny (non-owning by design)
};
```

**Constant** `StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"` (`include/tvm/ffi/object.h`).

## Impact
- API: `TensorView` is now the recommended parameter type for FFI-exported kernel functions. `Tensor` remains valid but is no longer idiomatic for function parameters that only need to read tensor data. All examples, docs, and inline module templates updated.
- Behavioral: `TryCastFromAnyView` accepts both `kTVMFFIDLTensorPtr` (raw pointer) and `kTVMFFITensor` (owning Tensor object), so existing callers that pass `Tensor` arguments to `TensorView`-typed functions work without changes.
- Flags/config: none
- Data formats/schemas: none

## Design Elements

Design elements this commit consumes:
- **TypeTraits protocol** ([0005-type-traits.md](../designs/0005-type-traits.md)): `TypeTraits<TensorView>` follows the standard specialization pattern with `TypeTraitsBase`, implementing `CopyToAnyView`, `CheckAnyStrict`, `CopyFromAnyViewAfterCheck`, `TryCastFromAnyView`, and `TypeStr`. Notably sets `storage_enabled = false` and omits `MoveToAny`/`MoveFromAny`.
- **Tensor container** ([0008-containers.md](../designs/0008-containers.md)): `TensorView` wraps the same `DLTensor` struct that `TensorObj` inherits from. Constructor copies the struct from `Tensor::operator->()`.
- **Any/AnyView value system** ([0002-any-value-system.md](../designs/0002-any-value-system.md)): Uses `kTVMFFIDLTensorPtr` type index for AnyView transport. The `storage_enabled = false` constraint means TensorView can only live in `AnyView` slots, never in `Any` (which would require ownership).
- **ShapeView** ([0008-containers.md](../designs/0008-containers.md)): Accessor methods return `ShapeView` (non-owning), consistent with `Tensor`'s API.
- **StaticTypeKey** ([0003-object-system.md](../designs/0003-object-system.md)): Adds `kTVMFFIDLTensorPtr = "DLTensor*"` to the static type key registry.

Design elements this commit produces:
- **TensorView class**: A new non-owning tensor view pattern -- the first non-ObjectRef, non-POD type in the container layer that participates in the TypeTraits system with `storage_enabled = false`. Establishes the convention for "view types" in the FFI.
- **Recommended kernel parameter convention**: The commit message and updated examples establish that `ffi::TensorView` (not `ffi::Tensor`) is the idiomatic parameter type for FFI-exported kernel ops, since callers may not always hold an owning reference.

## Usage Examples

C++ kernel function using TensorView (from `examples/quick_start/src/add_one_cpu.cc`):
```cpp
void AddOne(tvm::ffi::TensorView x, tvm::ffi::TensorView y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
  DLDataType f32_dtype{kDLFloat, 32, 1};
  TVM_FFI_ICHECK(x->dtype.code == f32_dtype.code && x->dtype.bits == f32_dtype.bits)
      << "x must be a float32 tensor";
  int n = x->shape[0];
  for (int i = 0; i < n; ++i) {
    static_cast<float*>(y->data)[i] = static_cast<float*>(x->data)[i] + 1.0f;
  }
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(add_one_cpu, AddOne);
```

C++ test showing TensorView <-> AnyView round-trip (from `tests/cpp/test_tensor.cc`):
```cpp
Tensor tensor = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
TensorView view = tensor;                   // implicit conversion from Tensor
AnyView av = view;                           // CopyToAnyView -> kTVMFFIDLTensorPtr
TensorView view2 = av.as<TensorView>().value();  // TryCastFromAnyView
```
