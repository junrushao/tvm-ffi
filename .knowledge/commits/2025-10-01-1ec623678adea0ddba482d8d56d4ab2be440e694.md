# Introduce TensorView for non-owning tensor access in FFI
## TL;DR
- Adds `ffi::TensorView`, a non-owning wrapper around `DLTensor` that can be constructed from `Tensor` or `DLTensor*` but never promotes to an owning `Tensor`.
- Registers `TypeTraits<TensorView>` using `kTVMFFIDLTensorPtr` type index so it participates in the AnyView dispatch (CopyToAnyView, TryCastFromAnyView) without owning storage.
- Updates all docs, examples, and quick-start guides to recommend `TensorView` over `Tensor` for kernel function arguments.

## Impact
- API: New public type `ffi::TensorView` in `include/tvm/ffi/container/tensor.h`. Existing `Tensor` API unchanged. Examples and docs migrate function signatures from `ffi::Tensor` to `ffi::TensorView`.
- Flags/config: Version bump to 0.1.0b13.
- Data formats/schemas: New `StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"` constant in `object.h`.

## Design Elements
Design elements this commit consumes:
- **Any/AnyView type-erasure system** (`.knowledge/designs/0002-any-system.md`): `TensorView` integrates via `TypeTraits<TensorView>` specialization with `CopyToAnyView` and `TryCastFromAnyView`, deliberately omitting `MoveToAny`/`MoveFromAny` to enforce non-owning semantics.
- **Container system / Tensor** (`.knowledge/designs/0005-containers.md`): `TensorView` wraps `DLTensor` inline (value-semantic copy of the struct, not the data), complementing the existing `TensorObj`-based owning `Tensor`.
- **C ABI layer** (`.knowledge/designs/0001-c-abi.md`): Uses `TypeIndex::kTVMFFIDLTensorPtr` for the type index, consistent with DLTensor pointer passing at the C boundary.

Design elements this commit produces:
- **TensorView non-owning view pattern**: A new design element where a non-owning view type pairs with an owning ObjectRef type. Key invariants: (1) move-from-owned is deleted to prevent dangling, (2) `storage_enabled = false` prevents storing in `Any`, (3) `TryCastFromAnyView` supports both `kTVMFFIDLTensorPtr` and `kTVMFFITensor` sources.
- **StaticTypeKey::kTVMFFIDLTensorPtr**: New static type key for DLTensor pointers, extending the type key registry in `object.h`.

## Reflection

* **Design docs to write**:

  - Reason: Future commits adding similar non-owning views (e.g., for Shape or String) would reference this pattern.

* **ADRs to write**:
  - `.knowledge/ADRs/0043-tensor-view-non-owning.md`: Context: kernel FFI functions often receive DLTensor pointers from external frameworks that do not provide owning references. Decision: introduce `TensorView` as a value-semantic wrapper with deleted move-from-Tensor to prevent accidental lifetime extension. Alternative considered: accepting raw `DLTensor*` directly (rejected because it loses type-safe dispatch through AnyView).

* **Design diagrams to draw**:
