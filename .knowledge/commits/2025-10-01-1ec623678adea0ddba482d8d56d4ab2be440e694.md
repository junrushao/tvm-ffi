# Introduce TensorView, a non-owning DLTensor view type for use in kernel op signatures

## TL;DR

- Adds `ffi::TensorView`, a stack-allocated non-owning wrapper over `DLTensor` (stores a value copy of the struct, not a pointer to it).
- Adds `TypeTraits<TensorView>` that maps to `kTVMFFIDLTensorPtr`; accepts both `kTVMFFIDLTensorPtr` and `kTVMFFITensor` in `TryCastFromAnyView` — coercion from owned `Tensor` is supported for compatibility.
- Updates all example kernel functions (`AddOne`, `AddOneCUDA`, `add_one_cpu`, `add_one_cuda`) to use `TensorView` instead of `Tensor`, establishing it as the recommended signature for ops that do not need to retain ownership.

## Key Exports

```python
class TensorView:
    """Non-owning view of a DLTensor; stores a by-value copy of the DLTensor struct."""
    # Invariant: underlying data (tensor elements, shape, strides) must outlive this view.
    # Invariant: tensor_ is always a valid DLTensor (checked at construction).
    # NOT promotable to an owning Tensor — MoveToAny/MoveFromAny are intentionally absent.
    # Interacts with: Tensor (implicit conversion source), DLTensor (raw pointer source),
    #                 AnyView (CopyToAnyView stores v_ptr to internal tensor_),
    #                 TypeIndex.kTVMFFIDLTensorPtr (wire type index)

    def __init__(self, tensor: Tensor) -> None: ...           # ICHECK(tensor.defined())
    def __init__(self, tensor: "DLTensor*") -> None: ...      # ICHECK(tensor != nullptr)
    # Move from owned Tensor is explicitly deleted (Tensor&&) = delete

    def shape(self) -> ShapeView: ...
    def strides(self) -> ShapeView: ...   # ICHECK(tensor_.strides != nullptr)
    def data_ptr(self) -> "void*": ...
    def ndim(self) -> int: ...
    def numel(self) -> int: ...           # shape().Product()
    def dtype(self) -> DLDataType: ...
    def IsContiguous(self) -> bool: ...   # delegates to tvm::ffi::IsContiguous(tensor_)


# TypeTraits<TensorView> specialization:
# storage_enabled = False  — cannot be stored in Any (no MoveToAny)
# field_static_type_index = TypeIndex.kTVMFFIDLTensorPtr
#
# TryCastFromAnyView coercion table:
#   kTVMFFIDLTensorPtr  → TensorView(static_cast<DLTensor*>(src.v_ptr))
#   kTVMFFITensor       → TensorView(TVMFFITensorGetDLTensorPtr(src.v_obj))
#   otherwise           → nullopt
#
# Interacts with: TypeTraits protocol (0008-type-traits), AnyView.as<TensorView>(),
#                 TVMFFITensorGetDLTensorPtr (C ABI helper to extract DLTensor* from TensorObj)


# New StaticTypeKey added to object.h:
# StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"
# Interacts with: 0001-c-abi, 0003-any-anyview type_index checks
```

## Impact

- API: New type `ffi::TensorView` in `include/tvm/ffi/container/tensor.h`. Existing `ffi::Tensor` is unchanged. Example/doc kernel signatures changed from `Tensor` → `TensorView`; this is a source-level (non-ABI) change to *example* code, not to any public library interface.
- Behavioral: `TensorView` accepts both `DLTensor*` (raw pointer) and owned `Tensor` at FFI call sites — broadens the set of callers that can invoke ops registered with `TensorView` arguments without first constructing an owning `Tensor`.
- Flags/config: none
- Data formats/schemas: New `StaticTypeKey::kTVMFFIDLTensorPtr = "DLTensor*"` string constant in `object.h`.

## Design Elements

Design elements this commit consumes:
- **0007-containers** (`Tensor`, `ShapeView`, `TensorObj`) — `TensorView` wraps `Tensor`'s underlying `DLTensor` and reuses `ShapeView` for `shape()`/`strides()` returns.
- **0008-type-traits** (`TypeTraits<T>` customization point, `storage_enabled`/`convert_enabled` flags) — implements `TypeTraits<TensorView>` with `storage_enabled = false`.
- **0003-any-anyview** (`AnyView`, `TypeIndex::kTVMFFIDLTensorPtr`) — `CopyToAnyView` stores `v_ptr` as `DLTensor*`; `TryCastFromAnyView` handles both wire types.
- **0001-c-abi** (`TypeIndex::kTVMFFIDLTensorPtr`, `StaticTypeKey`) — new type-key string constant `"DLTensor*"` registered in `StaticTypeKey`.

Design elements this commit produces:
- **`ffi::TensorView`** — stack-allocated non-owning DLTensor view class; recommended argument type for kernel ops that do not need to retain tensor ownership. (No design record yet; see Reflection.)

## Usage Examples

Kernel op using `TensorView` (from `examples/quick_start/src/add_one_cpu.cc`):

```cpp
// C++ side: register kernel using TensorView — accepts both raw DLTensor* and owned Tensor
void AddOne(tvm::ffi::TensorView x, tvm::ffi::TensorView y) {
  TVM_FFI_ICHECK(x->ndim == 1) << "x must be a 1D tensor";
  DLDataType f32_dtype{kDLFloat, 32, 1};
  // ... element-wise operation on x->data / y->data
}
TVM_FFI_DLL_EXPORT_TYPED_FUNC(__tvm_ffi_AddOne, AddOne);
```

```python
# Python side: call site unchanged — tvm_ffi.Tensor (owning) is implicitly coerced
import tvm_ffi
mod = tvm_ffi.load_module("add_one_cpu.so")
add_one = mod["AddOne"]
add_one(x_tensor, y_tensor)   # Tensor coerced via kTVMFFITensor → TensorView path
```

Round-trip through `AnyView` (from `tests/cpp/test_tensor.cc`):

```cpp
Tensor tensor = Empty({1, 2, 3}, DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
TensorView tv = tensor;                             // implicit conversion
AnyView av = tv;                                    // CopyToAnyView → kTVMFFIDLTensorPtr
TensorView tv2 = av.as<TensorView>().value();       // CopyFromAnyViewAfterCheck
EXPECT_EQ(tv2.shape()[0], 1);
```
