# Refactor Torch DLPack exchange API to static member functions and fix Py_DECREF usage
## TL;DR
- Refactored the Torch DLPack exchange API implementation from free functions to static member functions of `TorchDLPackExchangeAPI` struct, which now inherits from `DLPackExchangeAPI` and initializes all function pointers in its constructor.
- Replaced `Py_DECREF` (macro) with `Py_DecRef` (function) in tests, enabling use as a function pointer (e.g., with `std::unique_ptr` custom deleter).

## Key Exports

**`TorchDLPackExchangeAPI`** (struct, refactored -- `python/tvm_ffi/_optional_torch_c_dlpack.py` inline C++):

Previously: free functions `TorchDLPackDLTensorFromPyObjectNoSync`, `TorchDLPackManagedTensorFromPyObjectNoSync`, `TorchDLPackManagedTensorToPyObjectNoSync`, `TorchDLPackManagedTensorAllocator`, `TorchDLPackCurrentWorkStream`.

Now: all are `private static` member functions of `TorchDLPackExchangeAPI`: `DLTensorFromPyObjectNoSync`, `ManagedTensorFromPyObjectNoSync`, `ManagedTensorToPyObjectNoSync`, `ManagedTensorAllocator`, `CurrentWorkStream`. Constructor wires them into the `DLPackExchangeAPI` base struct fields. `Global()` returns the singleton.
