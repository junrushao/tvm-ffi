# Fix Py_DECREF macro usage and encapsulate DLPack exchange functions as static members
## TL;DR
- Replace `Py_DECREF` (CPython macro, not addressable as function pointer) with `Py_DecRef` (C function) in test code using `std::unique_ptr` deleters.
- Move five free DLPack exchange functions into `TorchDLPackExchangeAPI` struct as `private static` members, improving encapsulation without changing external behavior.

## Key Exports
No new public API surface. Internal reorganization only.

The five functions moved from free functions to static members:
```python
# Before (free functions at namespace scope in _optional_torch_c_dlpack.py inline C++):
#   TorchDLPackDLTensorFromPyObjectNoSync(...)
#   TorchDLPackManagedTensorFromPyObjectNoSync(...)
#   TorchDLPackManagedTensorToPyObjectNoSync(...)
#   TorchDLPackManagedTensorAllocator(...)
#   TorchDLPackCurrentWorkStream(...)
#
# After (private static members of TorchDLPackExchangeAPI):
#   TorchDLPackExchangeAPI::DLTensorFromPyObjectNoSync(...)
#   TorchDLPackExchangeAPI::ManagedTensorFromPyObjectNoSync(...)
#   TorchDLPackExchangeAPI::ManagedTensorToPyObjectNoSync(...)
#   TorchDLPackExchangeAPI::ManagedTensorAllocator(...)
#   TorchDLPackExchangeAPI::CurrentWorkStream(...)
# Interacts with: DLPackExchangeAPI struct (0007-c-abi), TorchDLPackExchangeAPIPtr() (0013-load-inline)
```

## Impact
- API: none (TorchDLPackExchangeAPIPtr() return value unchanged; function pointers in struct unchanged)
- Behavioral: none (same logic, same function pointer assignments)
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
Before/after pattern for the Py_DECREF fix in test code:

```cpp
// BEFORE (broken with some compilers — Py_DECREF is a macro, not addressable):
std::unique_ptr<PyObject, decltype(&Py_DECREF)> py_obj(THPVariable_Wrap(tensor), &Py_DECREF);

// AFTER (correct — Py_DecRef is a C function, always addressable):
std::unique_ptr<PyObject, decltype(&Py_DecRef)> py_obj(THPVariable_Wrap(tensor), &Py_DecRef);
```
