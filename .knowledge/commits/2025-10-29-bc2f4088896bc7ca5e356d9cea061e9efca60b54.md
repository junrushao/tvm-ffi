# Fix shared library lifetime by keeping a module-level reference to loaded torch C DLPack extension
## TL;DR
- `load_torch_c_dlpack_extension()` was missing `return lib`, so the `ctypes.CDLL` handle was immediately garbage-collected after loading.
- The return value is now stored in module-level `_LIB`, keeping the shared library alive for the lifetime of the process.
- Fixes a latent use-after-free: `__c_dlpack_exchange_api__` held a raw pointer into a library whose handle could be reclaimed.

- Behavioral: prevents potential segfault when calling `__c_dlpack_exchange_api__` after the ctypes CDLL handle was garbage-collected

## Design Elements

Design elements this commit produces: none

## Usage Examples
Before (bug): `load_torch_c_dlpack_extension()` loaded the library and set the API pointer, but did not return the handle. The call site discarded the return value, allowing GC to reclaim the CDLL object.

After (fix):
```python
# load_torch_c_dlpack_extension() now returns the CDLL handle
_LIB = load_torch_c_dlpack_extension()  # module-level keeps library alive
```
