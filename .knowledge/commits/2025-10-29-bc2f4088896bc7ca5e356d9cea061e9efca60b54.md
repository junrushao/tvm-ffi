# Fix use-after-unload bug by retaining a reference to the JIT-compiled torch C DLPack shared library

## TL;DR
- `load_torch_c_dlpack_extension()` loaded a shared library via `ctypes.CDLL` and extracted a function pointer, but did not return the `lib` handle. After the function returned, `lib` could be garbage-collected, calling `dlclose` and leaving a dangling function pointer on `torch.Tensor.__c_dlpack_exchange_api__`.
- Fix: return `lib` from the function and store it in module-level `_LIB` to keep the shared library loaded for the process lifetime.
- This is the same "module must outlive returned objects" invariant documented in the Module system design.

## Key Exports
None -- no new API surface. The fix is internal to `_optional_torch_c_dlpack.py`.

## Impact
- API: none
- Behavioral: Prevents potential segfault when `torch.Tensor.__c_dlpack_exchange_api__` was used after GC collected the `ctypes.CDLL` handle. The function pointer stored on the class would dangle after `dlclose`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Shared library lifetime management**: The invariant that a loaded shared library must outlive any function pointers or objects derived from it. Documented in [0011-module-system.md](../designs/0011-module-system.md) under "Module must outlive returned objects."
- **DLPackExchangeAPI singleton pattern**: The `TorchDLPackExchangeAPI` struct pointer is set as a class attribute on `torch.Tensor`. Documented in [ADR-0015](../ADRs/0015-dlpack-exchange-api-struct.md).
- **`_optional_torch_c_dlpack.py` JIT build pipeline**: The module JIT-compiles a C addon via subprocess, loads it with `ctypes.CDLL`, and extracts `TorchDLPackExchangeAPIPtr`. Introduced in PR #192 (e6a654a).

Design elements this commit produces:
- None -- purely a bugfix to existing code.

## Usage Examples
Before (buggy):
```python
# load_torch_c_dlpack_extension() did not return lib
# After function returns, lib is GC'd -> dlclose -> dangling pointer
load_torch_c_dlpack_extension()
# torch.Tensor.__c_dlpack_exchange_api__ now points to unmapped memory
```

After (fixed):
```python
# Function returns lib, caller stores it at module level
_LIB = load_torch_c_dlpack_extension()
# _LIB keeps the shared library alive for the process lifetime
# torch.Tensor.__c_dlpack_exchange_api__ remains valid
```
