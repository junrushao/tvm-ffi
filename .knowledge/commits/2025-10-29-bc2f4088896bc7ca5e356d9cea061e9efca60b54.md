# Fix shared library lifetime by keeping a module-level reference to the loaded ctypes.CDLL

## TL;DR
- `load_torch_c_dlpack_extension()` now returns the `ctypes.CDLL` handle on success, and the caller stores it in the module-level `_LIB` variable.
- Without this fix, the `lib` local variable was discarded at function exit, allowing Python's garbage collector to finalize the `ctypes.CDLL` object and potentially unload the shared library. This could cause use-after-free crashes when the `TorchDLPackExchangeAPIPtr` function pointer (stored on `torch.Tensor.__c_dlpack_exchange_api__`) was later dereferenced.

## Key Exports
None. No new public API surface. The existing function `load_torch_c_dlpack_extension() -> Any` now returns the `ctypes.CDLL` handle instead of implicitly returning `None` on success. The module-level `_LIB` variable is private.

## Impact
- API: none -- `load_torch_c_dlpack_extension` is a private function; its return value was previously unused.
- ABI: none
- Behavioral: Prevents potential use-after-free / segfault when the GC collects the `ctypes.CDLL` handle and unloads `libtorch_c_dlpack_addon.so`. The function pointer stored in `torch.Tensor.__c_dlpack_exchange_api__` now remains valid for the lifetime of the process.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack fast-path PyTorch integration** (`.knowledge/designs/0018-dlpack-fast-path.md`, "PyTorch Integration Module" section): The `_optional_torch_c_dlpack` module loads a shared library that provides `TorchDLPackExchangeAPIPtr`, whose return value is installed as `torch.Tensor.__c_dlpack_exchange_api__`.
- **Shared library lifetime requirement**: `ctypes.CDLL` objects must remain reachable to prevent the OS from unloading the `.so`/`.dll`, since the DLPack exchange API struct lives in the library's data segment.

Design elements this commit produces:
- **Module-level `_LIB` anchor pattern**: Establishes the convention that `ctypes.CDLL` handles loaded at import time are stored in module-level variables to prevent premature unloading. This is a well-known Python/ctypes pattern but was missing after PR #192 (e6a654a) refactored from `torch.utils.cpp_extension.load_inline` (which managed lifetime internally) to raw `ctypes.CDLL`.

## Usage Examples
Before (broken -- `lib` goes out of scope, GC may unload the shared library):
```python
def load_torch_c_dlpack_extension() -> Any:
    ...
    lib = ctypes.CDLL(str(lib_path))
    func = lib.TorchDLPackExchangeAPIPtr
    func.restype = ctypes.c_uint64
    setattr(torch.Tensor, "__c_dlpack_exchange_api__", func())
    # lib goes out of scope -> GC may unload -> dangling pointer on torch.Tensor
    ...

load_torch_c_dlpack_extension()
```

After (fixed -- `_LIB` keeps the handle alive at module level):
```python
def load_torch_c_dlpack_extension() -> Any:
    ...
    lib = ctypes.CDLL(str(lib_path))
    func = lib.TorchDLPackExchangeAPIPtr
    func.restype = ctypes.c_uint64
    setattr(torch.Tensor, "__c_dlpack_exchange_api__", func())
    return lib  # <-- NEW: return the handle
    ...

_LIB = load_torch_c_dlpack_extension()  # keep a reference to the loaded shared library
```
