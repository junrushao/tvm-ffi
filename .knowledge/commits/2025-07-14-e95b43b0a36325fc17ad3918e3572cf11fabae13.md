# Modularize reflection into registry.h (registration) and accessor.h (runtime access)
## TL;DR
- Splits the monolithic `include/tvm/ffi/reflection/reflection.h` (571 lines) into two focused headers: `registry.h` (414 lines, registration-side: `ObjectDef`, `GlobalDef`, `ReflectionDefBase`, field/method registration) and `accessor.h` (198 lines, access-side: `FieldGetter`, `FieldSetter`, `GetFieldInfo`, `GetMethodInfo`, `GetMethod`, `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`).
- Updates all include directives across 7 source/test files from `reflection/reflection.h` to `reflection/registry.h`. The test file `test_reflection.cc` additionally includes `reflection/accessor.h` since it uses both registration and access APIs.
- No functional or behavioral changes; all code in the new files is identical to the original modulo the header guard macro name and file-level doc comment.

## Impact
- API: Header path changes from `tvm/ffi/reflection/reflection.h` to `tvm/ffi/reflection/registry.h` (for registration) and `tvm/ffi/reflection/accessor.h` (for access). Any downstream code including the old header will fail to compile. The old `reflection.h` is deleted (renamed to `registry.h`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection System** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): This commit operates entirely within the reflection subsystem, splitting its single header into two cohesive modules. All classes (`ReflectionDefBase`, `ObjectDef`, `GlobalDef`, `FieldGetter`, `FieldSetter`, `GetFieldInfo`, `GetMethodInfo`, `ForEachFieldInfo`) are unchanged in behavior.
- **Object System** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): The accessor.h module depends on `Object`, `ObjectPtr<Object>`, `ObjectRef`, and `TypeInfo`/`TVMFFITypeInfo` for its field-access logic. The registry.h module depends on `Object` subclass patterns (`_GetOrAllocRuntimeTypeIndex`, `_type_key`, `_type_mutable`) for type registration.

Design elements this commit produces:
- **Reflection module boundary (registry vs. accessor)**: Establishes a clear separation of concerns within the reflection subsystem:
  - `registry.h` is the **write-path**: used by `.cc` files that register type metadata during static initialization (e.g., `src/ffi/container.cc`, `src/ffi/object.cc`, `src/ffi/function.cc`). It contains `ObjectDef<Class>`, `GlobalDef`, `ReflectionDefBase`, `DefaultValue`, `GetFieldByteOffsetToObject`.
  - `accessor.h` is the **read-path**: used by code that queries reflection metadata at runtime (field lookup, method dispatch, field iteration). It contains `GetFieldInfo`, `GetMethodInfo`, `GetMethod`, `FieldGetter`, `FieldSetter`, `ForEachFieldInfo`, `ForEachFieldInfoWithEarlyStop`.
  - This split reduces include-time compile cost for consumers that only need one side: registration-only files (most `.cc` implementation files) avoid pulling in the accessor utilities, and access-only consumers avoid pulling in the heavyweight registration templates (`ObjectDef`, `GlobalDef`). Evidence: all 5 changed `.cc` files only need `registry.h`; only `test_reflection.cc` needs both.

This helps future commit mining correctly attribute changes to the right sub-module.
