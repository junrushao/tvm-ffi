# Auto-create Python proxy classes for unregistered C++ types using reflection metadata
## TL;DR
- Replaces the `UserWarning` + `Object` fallback for unregistered C++ types with automatic Python class generation: `make_ret_object` now calls `make_fallback_cls_for_type_index` to recursively build a class hierarchy with reflection-derived fields, methods, and docstrings.
- Renames `type_acenstors` to `type_ancestors` across the entire C ABI, C++ implementation, Cython bindings, and tests (typo fix).
- Adds `type_ancestors` (list of parent type indices) to `TypeInfo`, enabling `__post_init__` to auto-resolve `parent_type_info` from the ancestor chain without manual Python-side parent lookup.

## Key Exports

**Functions (renamed)**:
- `_lookup_or_register_type_info_from_type_key(type_key: str) -> TypeInfo` -- renamed from `_lookup_type_info_from_type_key`. Now also registers the TypeInfo into `TYPE_INDEX_TO_INFO` and `TYPE_KEY_TO_INFO` via `_update_registry`.
- `_set_type_cls(type_info: TypeInfo, type_cls: type) -> None` -- signature changed from `(type_index: int, type_cls: type)` to `(type_info: TypeInfo, type_cls: type)`. Validates that the type_info is already in the registry.

**Functions (new)**:
- `make_fallback_cls_for_type_index(type_index: int32_t) -> object` (Cython cdef) -- auto-generates a Python class for an unregistered C++ type. Recursively ensures parent classes exist, creates a subclass of the parent's Python class, populates fields (via `TypeField.as_property`), methods (via `TypeMethod.as_callable`), and sets `__name__`, `__qualname__`, `__module__`, `__doc__`.
- `TypeMethod.as_callable(cls: type) -> Callable` -- creates a Python method attribute for a reflected method on a class. Instance methods are wrapped with `_member_method_wrapper`; static methods are wrapped with `staticmethod()`.
- `TypeInfo.prototype_py() -> str` -- declared in `core.pyi` stub (implementation not in this diff).
- `_update_registry(type_index, type_key, type_info, type_cls)` (Cython cdef) -- factored-out helper that updates all three registries (`TYPE_INDEX_TO_INFO`, `TYPE_KEY_TO_INFO`, `TYPE_INDEX_TO_CLS`) atomically.
- `_member_method_wrapper(method_func) -> Callable` -- moved from `registry.py` to `type_info.pxi`.

**Types/Classes (changed)**:
- `TypeInfo` gains `type_ancestors: list[int]` field and `__post_init__` that auto-resolves `parent_type_info` from the last ancestor index.
- `_type_info_create_from_type_key` changed from `def` to `cdef` (no longer callable from Python, Cython-internal only). Now populates `type_ancestors` from `TVMFFITypeInfo.type_ancestors`.

**C ABI rename**:
- `TVMFFITypeInfo.type_acenstors` -> `TVMFFITypeInfo.type_ancestors` (typo fix, breaking ABI change)
- `TypeTable::Entry::type_acenstors_data` -> `type_ancestors_data` (internal)

**C++ test types (changed)**:
- `TestUnregisteredObject` now inherits from `TestUnregisteredBaseObject` (new) instead of `Object`. Both types have reflection registration with fields (`v1`, `v2`), methods (`get_v1_plus_one`, `get_v2_plus_two`), and `__ffi_init__`.

## Impact
- API: **Breaking** -- `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key`. `_set_type_cls` signature changed from `(int, type)` to `(TypeInfo, type)`. Both are internal APIs (underscore-prefixed). External callers of `@c_class` are unaffected.
- API: **Breaking C ABI** -- `TVMFFITypeInfo.type_acenstors` renamed to `type_ancestors`. All C/C++/Cython code reading this field must update.
- Behavioral: Unregistered C++ types returning through FFI now get auto-generated Python proxy classes with fields and methods, instead of falling back to bare `Object` with a warning. The fallback class is cached so the slow path runs only once per unregistered type.
- Behavioral: `_lookup_or_register_type_info_from_type_key` now also registers the TypeInfo into the index-based registry, not just the key-based one (fixes a prior inconsistency).
- Behavioral: `TypeInfo.__post_init__` auto-resolves `parent_type_info` from `type_ancestors`, removing the need for `get_parent_type_info()` Python-side parent walking.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**End-to-end: C++ type with reflection but no Python `@register_object`, accessed from Python**:
```cpp
// C++ side -- reflection-registered but NO Python @register_object
class TestUnregisteredBaseObject : public Object {
 public:
  int64_t v1;
  int64_t GetV1PlusOne() const { return v1 + 1; }
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestUnregisteredBaseObject", ...);
};
// ObjectDef registers v1, __ffi_init__, get_v1_plus_one

class TestUnregisteredObject : public TestUnregisteredBaseObject {
 public:
  int64_t v2;
  int64_t GetV2PlusTwo() const { return v2 + 2; }
  TVM_FFI_DECLARE_OBJECT_INFO("testing.TestUnregisteredObject", ...);
};
// ObjectDef registers v1, v2, __ffi_init__, get_v2_plus_two
```
```python
# Python side -- no @register_object needed
obj = tvm_ffi.testing.make_unregistered_object()  # returns auto-generated class
assert obj.v1 == 41
assert obj.v2 == 42
assert obj.get_v1_plus_one() == 42
assert obj.get_v2_plus_two() == 44
assert type(obj).__name__ == "TestUnregisteredObject"
assert "Auto-generated fallback class" in type(obj).__doc__
```
