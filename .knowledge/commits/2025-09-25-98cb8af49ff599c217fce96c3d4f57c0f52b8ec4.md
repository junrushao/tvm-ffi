# Auto-create Python proxy classes for C++ object types that lack explicit register_object bindings
## TL;DR
- When a C++ object with an unregistered Python class is returned to Python, the system now auto-generates a stub Python class with reflection-derived fields, methods, and parent chain -- replacing the old behavior of issuing a warning and falling back to bare `Object`.
- `TypeInfo` gains a `type_ancestors` field (list of ancestor type indices) and `__post_init__` auto-resolves `parent_type_info` from the ancestor chain, enabling recursive parent class creation.
- Renames `type_acenstors` -> `type_ancestors` across the entire C ABI, C++ headers, Cython bindings, and C++ implementation (typo fix).

`type_acenstors` -> `type_ancestors`

| Old name | New name |
|----------|----------|
| `TVMFFITypeInfo.type_acenstors` | `TVMFFITypeInfo.type_ancestors` |
| `type_acenstors_data` (C++ internal) | `type_ancestors_data` |
| `_lookup_type_info_from_type_key` | `_lookup_or_register_type_info_from_type_key` |
| `_set_type_cls(type_index, type_cls)` | `_set_type_cls(type_info, type_cls)` |

## Impact
- API: `_set_type_cls` signature changed from `(int, type)` to `(TypeInfo, type)` -- callers in `c_class.py` updated. `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key` -- callers in `c_class.py` and `_utils.py` updated.
- Behavioral: Returning an unregistered C++ object to Python no longer emits a warning or returns a bare `Object`. Instead it returns a fully functional auto-generated proxy class with fields/methods populated from reflection. This is a semantic change: tests that checked for `UserWarning` must change.
- Flags/config: none
- Data formats/schemas: `TVMFFITypeInfo.type_acenstors` renamed to `type_ancestors` -- ABI-level field name change (binary layout unchanged since it is a pointer field at the same offset).

## Design Elements
Design elements this commit consumes:
- **Object system** (`TVMFFITypeInfo`, `type_index`, `type_depth`, ancestor chain) -- [0003-ffi-object-system](../design-records/0003-ffi-object-system.md)
- **Reflection system** (`ObjectDef<T>`, `def_ro`/`def_rw`/`def_`/`def_static`, `ForEachFieldInfo`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`) -- [0007-ffi-reflection](../design-records/0007-ffi-reflection.md)
- **Python dispatch table** (`TYPE_INDEX_TO_CLS`, `TYPE_INDEX_TO_INFO`, `_register_object_by_index`) -- [0012-ffi-python-package](../design-records/0012-ffi-python-package.md)

Design elements this commit produces:
- **PRODUCED: `make_fallback_cls_for_type_index`** -- new protocol for auto-creating Python proxy classes from reflection metadata. Recursive parent resolution. One-time slow path per unregistered type.
- **PRODUCED: `TypeMethod.as_callable`** -- method on `TypeMethod` that creates a properly wrapped Python callable (instance or static) with correct `__module__`, `__name__`, `__qualname__`, `__doc__`.
- **PRODUCED: `TypeInfo.type_ancestors`** -- new field on the Python-side `TypeInfo` dataclass holding ancestor type indices.
- **PRODUCED: `TypeInfo.__post_init__`** -- auto-resolution of `parent_type_info` from ancestor chain via `_lookup_or_register_type_info_from_type_key`.
- **MUTATED: `_lookup_type_info_from_type_key` -> `_lookup_or_register_type_info_from_type_key`** -- now also registers the TypeInfo into the global tables (not just the key-based cache).
- **MUTATED: `_set_type_cls`** -- takes `TypeInfo` instead of `int type_index`, adds assertion that `type_info` is the canonical registered instance.
- **MUTATED: `TVMFFITypeInfo.type_acenstors` -> `type_ancestors`** -- typo fix across C ABI, C++ implementation, Cython bindings.
- **MUTATED: `_member_method_wrapper`** -- moved from `registry.py` to `type_info.pxi` (Cython).

## Usage Examples
**Context**: C++ defines an object type with reflection but no Python `@register_object` class. When returned to Python, the auto-generated proxy exposes fields and methods.

```python
# C++ side (testing.cc):
# class TestUnregisteredObject : public TestUnregisteredBaseObject {
#   int64_t v2;
#   int64_t GetV2PlusTwo() const { return v2 + 2; }
# };
# Registered with ObjectDef but no @register_object in Python.

import tvm_ffi

obj = tvm_ffi.testing.make_unregistered_object()
# Auto-generated fallback class is created on first return
assert type(obj).__name__ == "TestUnregisteredObject"
assert obj.v1 == 41          # inherited field from base
assert obj.v2 == 42          # own field
assert obj.get_v1_plus_one() == 42  # inherited method
assert obj.get_v2_plus_two() == 44  # own method
assert "Auto-generated fallback class" in type(obj).__doc__
```
