# Auto-generate fallback Python classes for unregistered C++ object types instead of warning and returning bare Object

## TL;DR

- When `make_ret_object` encounters a type index not yet registered via `@register_object`, it now auto-generates a Python class (with fields, methods, correct `__name__`/`__module__`/`__qualname__`) instead of issuing a `UserWarning` and returning a raw `Object`.
- `TypeInfo` gains a `type_ancestors: list[int]` field; its `__post_init__` auto-resolves `parent_type_info` by walking the ancestor chain, removing the manual `get_parent_type_info` helper from `_utils.py`.
- `type_acenstors` (misspelled) renamed to `type_ancestors` across C ABI struct, C++ source, Cython binding, and all call sites (secondary rename concern).

## Impact
- API: `_set_type_cls(type_index, cls)` → `_set_type_cls(type_info, cls)` — callers must pass the `TypeInfo` object instead of the raw integer index. Only internal caller: `c_class.py`.
- API: `_lookup_type_info_from_type_key` removed; replaced by `_lookup_or_register_type_info_from_type_key`. Downstream callers (`_utils.py`, `c_class.py`) updated.
- API: `TypeInfo` gains required field `type_ancestors: list[int]` — any code constructing `TypeInfo` manually must be updated.
- API: `TypeMethod.as_callable()` added; `_member_method_wrapper` moved from `registry.py` to `type_info.pxi` — registry module no longer exports it.
- Behavioral: `make_ret_object` no longer emits `UserWarning` on unregistered types; returns a class with full field/method access. Tests updated to assert fields are accessible instead of checking for the warning.
- Behavioral: `_register_object_by_index(kTVMFFIObject, Object)` added in `string.pxi`; `Object` class is now explicitly registered at type index 0, ensuring the recursive fallback has a valid root.
- Flags/config: none
- Data formats/schemas: `TVMFFITypeInfo.type_acenstors` field renamed to `type_ancestors` in C ABI header — **ABI breaking for any consumer that accesses the struct by field name**. Binary layout is unchanged (same field, same position).

## Design Elements

Design elements this commit consumes:
- `TVMFFITypeInfo` / `TVMFFIGetTypeInfo` / `type_depth` — 0001-c-abi, 0002-object-system, 0006-reflection: reads ancestor chain to recursively build fallback classes.
- `TYPE_INDEX_TO_CLS` / `TYPE_INDEX_TO_INFO` / `TYPE_KEY_TO_INFO` (Python-side Cython globals) — 0013-python-package: the three-list registration registry.
- `ObjectDef<T>.def_ro/.def_static/.def` reflection builder — 0006-reflection: used in `testing.cc` to add fields/methods to the two new `TestUnregistered*` objects.
- `TypeField.as_property()` — 0013-python-package: attached to auto-generated class attributes.
- `ForEachFieldInfo` / `ForEachFieldInfoWithEarlyStop` — 0006-reflection: `accessor.h` updated for rename.

Design elements this commit produces:
- **`make_fallback_cls_for_type_index`** — new Cython cdef that generates proxy classes on demand; eliminates the "fallback to Object" warning pattern. Key addition to the Python binding layer.
- **`_update_registry` (extracted cdef)** — factored out of `_register_object_by_index`; now the single write point for all three global type registries.
- **`TypeInfo.type_ancestors`** — new field on `TypeInfo` dataclass; enables `__post_init__` auto-resolution of `parent_type_info` without caller assistance.
- **`TypeMethod.as_callable()`** — symmetric to existing `TypeField.as_property()`; encapsulates method attribute construction in one place.
- **`_lookup_or_register_type_info_from_type_key`** — extends the old `_lookup_type_info_from_type_key`; the new version also updates all three registries on cache miss.

## Usage Examples

End-to-end trace: C++ unregistered type → Python auto-fallback class

```python
# C++ side (testing.cc): types registered in C++ reflection but NOT via @register_object in Python
# refl::ObjectDef<TestUnregisteredObject>()
#     .def_ro("v1", ...).def_ro("v2", ...)
#     .def_static("__ffi_init__", refl::init<TestUnregisteredObject, int64_t, int64_t>)
#     .def("get_v2_plus_two", &TestUnregisteredObject::GetV2PlusTwo, "Get (v2 + 2)...")

# Python side (tests/python/test_object.py):
import tvm_ffi
obj = tvm_ffi.testing.make_unregistered_object()  # returns TestUnregisteredObject(41, 42)

# Auto-generated class is used — no warning emitted:
assert type(obj).__name__ == "TestUnregisteredObject"
assert type(obj).__module__ == "testing"
assert obj.v1 == 41 and obj.v2 == 42       # fields accessible via as_property()
assert obj.get_v2_plus_two() == 44          # methods accessible via as_callable()
assert "Auto-generated fallback class" in type(obj).__doc__

# Idempotency: second call uses fast path (TYPE_INDEX_TO_CLS already populated)
for _ in range(5):
    obj2 = tvm_ffi.testing.make_unregistered_object()
    assert type(obj2) is type(obj)          # same class object reused
```
