# Auto-create Python fallback classes for unregistered C++ objects with full reflection
## TL;DR
- When `make_ret` receives an object whose C++ type has no registered Python class, it now **auto-generates a fallback Python class** with reflected fields, methods, and parent hierarchy instead of warning and returning a bare `Object`. The fallback class is created once per type and cached for all subsequent returns.
- **Rename**: `type_acenstors` -> `type_ancestors` across the entire codebase (C ABI header, C++ source, Cython bindings, tests). Fixes a longstanding typo.
- `TypeInfo` gains a `type_ancestors` field (list of ancestor type indices) and auto-resolves `parent_type_info` in `__post_init__`. `TypeMethod` gains `as_callable()` and `TypeField.as_property()` is refactored. `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key` (now also inserts into registry). `_set_type_cls` signature changed from `(int, type)` to `(TypeInfo, type)`.

### Rename mapping

| Before | After |
|---|---|
| `TVMFFITypeInfo.type_acenstors` (C ABI) | `TVMFFITypeInfo.type_ancestors` |
| `type_acenstors_data` (C++ internal) | `type_ancestors_data` |
| `_lookup_type_info_from_type_key()` | `_lookup_or_register_type_info_from_type_key()` |
| `_set_type_cls(type_index, type_cls)` | `_set_type_cls(type_info, type_cls)` |
| `_member_method_wrapper` (in `registry.py`) | moved to `type_info.pxi` |
| `get_parent_type_info()` (in `_utils.py`) | removed; `TypeInfo.__post_init__` handles parent resolution |

## Impact
- API: `TVMFFITypeInfo.type_acenstors` renamed to `type_ancestors` in C ABI header. All downstream consumers must update. `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key`. `_set_type_cls` signature changed from `(int, type)` to `(TypeInfo, type)`.
- Behavioral: Unregistered C++ objects returned to Python now have full field/method access via auto-generated fallback classes instead of being bare `Object` instances with a warning. The slow path (class creation) runs once per type; subsequent returns use the cached class.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system type hierarchy** ([0002-object-system.md](../designs/0002-object-system.md)): `type_ancestors` array for parent chain traversal; `IsObjectInstance` ancestor-depth fallback.
- **Reflection system** ([0008-reflection.md](../designs/0008-reflection.md)): `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, `ForEachFieldInfo`, `_type_info_create_from_type_key` to populate TypeInfo for unregistered types.
- **Python bindings registry** ([0012-python-bindings.md](../designs/0012-python-bindings.md)): `TYPE_INDEX_TO_CLS`, `TYPE_INDEX_TO_INFO`, `TYPE_KEY_TO_INFO` global registries; `_add_class_attrs` for method/field attachment; `register_object` / `_register_object_by_index`.
- **C ABI TVMFFITypeInfo** ([0001-c-abi.md](../designs/0001-c-abi.md)): `type_ancestors` (renamed), `type_depth`, `type_key`, field/method arrays.

Design elements this commit produces:
- **Fallback class auto-creation** (`make_fallback_cls_for_type_index`): New mechanism that bridges unregistered C++ types to Python with full reflection access. This is a behavioral change to the Python bindings' object return path.
- **TypeInfo.type_ancestors field**: Exposes ancestor chain at the Python level, enabling parent_type_info resolution without going back through C ABI.
- **TypeMethod.as_callable()**: Encapsulates method wrapping (static vs instance, metadata) in a reusable method on TypeMethod, replacing inline logic in `_add_class_attrs`.
- **_update_registry()**: Centralizes registry mutation logic, used by both `_register_object_by_index` and the new fallback creation path.

## Usage Examples

**C++ type with no Python registration, returned to Python with full reflection access:**

```cpp
// C++ side: define a type WITHOUT registering a Python class
class MyNodeObj : public Object {
 public:
  int64_t value;
  TVM_FFI_DECLARE_OBJECT_INFO("my.Node", MyNodeObj, Object);
};
TVM_FFI_STATIC_INIT_BLOCK() {
  refl::ObjectDef<MyNodeObj>()
      .def_ro("value", &MyNodeObj::value)
      .def_static("__ffi_init__", refl::init<MyNodeObj, int64_t>);
}
```

```python
# Python side: receive unregistered object -- auto-creates fallback class
obj = some_ffi_func_that_returns_my_node()
# Previously: warning + bare Object (no field access)
# Now: auto-generated class with reflected fields/methods
assert obj.value == 42
assert type(obj).__name__ == "Node"
assert type(obj).__qualname__ == "my.Node"
assert "Auto-generated fallback class" in type(obj).__doc__
# Second return reuses the cached class (no warning, no re-creation)
obj2 = some_ffi_func_that_returns_my_node()
assert type(obj) is type(obj2)
```
