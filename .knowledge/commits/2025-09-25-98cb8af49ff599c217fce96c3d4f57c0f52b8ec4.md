# Auto-create Python fallback classes for unregistered C++ types and fix type_acenstors typo

## TL;DR
- Renames `type_acenstors` to `type_ancestors` across C API, C++ implementation, Cython bindings, and tests (typo fix, ABI-breaking field rename).
- Introduces `make_fallback_cls_for_type_index` in Cython: when `make_ret_object` encounters an unregistered type, it auto-creates a Python proxy class with fields/methods from C++ reflection instead of falling back to bare `Object` with a warning.
- Refactors type registration: `_lookup_type_info_from_type_key` -> `_lookup_or_register_type_info_from_type_key` (ensures TypeInfo is always in global registry), `_set_type_cls` now takes `TypeInfo` instead of `int`, `TypeInfo` gains `type_ancestors` field and auto-resolves `parent_type_info` in `__post_init__`.

## Key Exports

**Rename mapping** (ABI-breaking):

| Old name | New name | Location |
|----------|----------|----------|
| `TVMFFITypeInfo::type_acenstors` | `TVMFFITypeInfo::type_ancestors` | `include/tvm/ffi/c_api.h` |
| `TypeTable::Entry::type_acenstors_data` | `TypeTable::Entry::type_ancestors_data` | `src/ffi/object.cc` |

**Functions (Python/Cython)**:

- `make_fallback_cls_for_type_index(type_index: int32_t) -> object` -- Cython cdef function. Recursively creates Python stub classes for unregistered types using C++ reflection metadata. Sets `__tvm_ffi_type_info__`, `__name__`, `__qualname__`, `__module__`, `__doc__`, fields (as properties), and methods (as callables).
- `_lookup_or_register_type_info_from_type_key(type_key: str) -> TypeInfo` -- replaces `_lookup_type_info_from_type_key`. Same lazy lookup, but now always registers the TypeInfo into `TYPE_INDEX_TO_INFO`/`TYPE_KEY_TO_INFO` via `_update_registry`.
- `_set_type_cls(type_info: TypeInfo, type_cls: type) -> None` -- signature changed from `(type_index: int, type_cls: type)`. Now takes TypeInfo directly, validates it's already in the registry.
- `_update_registry(type_index: int, type_key: str, type_info: TypeInfo, type_cls: type) -> None` -- new cdef helper that centralizes registry updates to `TYPE_INDEX_TO_INFO`, `TYPE_INDEX_TO_CLS`, `TYPE_KEY_TO_INFO`.
- `TypeMethod.as_callable(cls: type) -> Callable` -- new method on `TypeMethod`. Creates a properly wrapped Python method (with `_member_method_wrapper` for instance methods, `staticmethod` for static ones) with `__module__`, `__name__`, `__qualname__`, `__doc__` set.
- `TypeInfo.__post_init__()` -- new. Auto-resolves `parent_type_info` from `type_ancestors[-1]` by calling `_lookup_or_register_type_info_from_type_key`.

**Fields added**:

- `TypeInfo.type_ancestors: list[int]` -- list of ancestor type indices from root to parent (mirrors `TVMFFITypeInfo::type_ancestors`).

## Impact
- API: `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key`. `_set_type_cls` signature changes from `(int, type)` to `(TypeInfo, type)`. Internal/underscore-prefixed APIs.
- ABI: `TVMFFITypeInfo::type_acenstors` field renamed to `type_ancestors`. All cross-boundary code reading this field must update.
- Behavioral: Unregistered C++ types no longer produce a warning and fall back to bare `Object`. Instead, a full proxy class is auto-created with fields, methods, and proper `__name__`/`__module__`/`__doc__`. The slow path triggers only once per unregistered type.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Object system type hierarchy** (`.knowledge/designs/object-system.md`): uses `TVMFFITypeInfo.type_depth`, `type_ancestors` for ancestor traversal
- **Python TypeInfo/TypeField/TypeMethod model** (`.knowledge/designs/0014-python-bindings.md`): the `TypeInfo`, `TypeField`, `TypeMethod` dataclasses that represent C++ reflection metadata in Python
- **C++ reflection system** (`.knowledge/designs/reflection.md`): `ObjectDef<T>` registration provides the fields/methods that the fallback class creation reads
- **c_class decorator** (`.knowledge/designs/0019-c-class-decorator.md`): `_lookup_or_register_type_info_from_type_key` replaces `_lookup_type_info_from_type_key` in the decorator flow

Design elements this commit produces:
- **Auto-fallback Python class creation**: a new mechanism in `make_ret_object` that auto-generates typed Python proxy classes for C++ types that lack explicit `@register_object` registration. This replaces the previous warning+bare-Object fallback.
- **Centralized registry update** via `_update_registry`: single function ensuring `TYPE_INDEX_TO_INFO`, `TYPE_INDEX_TO_CLS`, `TYPE_KEY_TO_INFO` are always in sync.
- **TypeInfo self-resolving parent chain**: `TypeInfo.__post_init__` automatically resolves `parent_type_info` from `type_ancestors`, enabling recursive parent class creation.

## Usage Examples

```python
# Before: unregistered C++ objects triggered a warning and returned as bare Object
import tvm_ffi
obj = tvm_ffi.testing.make_unregistered_object()
# type(obj) was tvm_ffi.Object, no fields accessible

# After: auto-generated fallback class with fields and methods
obj = tvm_ffi.testing.make_unregistered_object()
assert obj.v1 == 41          # field access works
assert obj.v2 == 42          # field access works
assert obj.get_v1_plus_one() == 42   # method call works
assert type(obj).__name__ == "TestUnregisteredObject"
assert "Auto-generated fallback class" in type(obj).__doc__
```
