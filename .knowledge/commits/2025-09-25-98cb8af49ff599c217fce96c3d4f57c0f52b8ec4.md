# Auto-create Python fallback classes for unregistered C++ object types
## TL;DR
- Replaces the warning-based fallback (returning a bare `Object`) for unregistered C++ types with auto-generated Python proxy classes that expose reflected fields/methods, inherit from the correct parent class, and are cached for future lookups.
- Renames `type_acenstors` to `type_ancestors` throughout C ABI, C++ headers, Cython bindings, and implementation files (typo fix, API-breaking field rename).
- Refactors reflection metadata wiring: `TypeInfo` now auto-resolves `parent_type_info` from the C-level `type_ancestors` array; `_lookup_type_info_from_type_key` is renamed to `_lookup_or_register_type_info_from_type_key` with side-effect registration; `_set_type_cls` changes signature from `(type_index, type_cls)` to `(type_info, type_cls)`; `_member_method_wrapper` moves from `registry.py` to `type_info.pxi`; `TypeMethod.as_callable()` and `TypeField.as_property()` are introduced as encapsulated attribute builders.

## Impact
- API: The `TVMFFITypeInfo.type_acenstors` field is renamed to `type_ancestors` in `c_api.h`, `object.h`, `accessor.h`, `base.pxi`. Any external code referencing the old name breaks. Cython declaration in `base.pxi` also corrected from `const int32_t*` to `const TVMFFITypeInfo**`.
- API: Python-visible functions `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key`; `_set_type_cls` signature changes from `(int, type)` to `(TypeInfo, type)`. `_member_method_wrapper` removed from `registry.py`. `TypeInfo` gains `type_ancestors` field.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Object system type hierarchy** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Uses `TVMFFITypeInfo.type_ancestors` and `type_depth` to walk the parent chain and recursively create fallback classes for each unregistered ancestor.
- **Reflection system** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): Reads `TVMFFITypeInfo.fields` and `methods` via `_type_info_create_from_type_key` to populate auto-generated proxy classes with `property` descriptors and bound methods.
- **Python bindings make_ret_object** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The `make_ret_object` function is the entry point that triggers fallback class creation when `TYPE_INDEX_TO_CLS[type_index]` is `None`.
- **C ABI TVMFFITypeInfo struct** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The `type_ancestors` pointer array is read from Cython to derive parent type indices.

Design elements this commit produces:
- **Fallback class auto-generation protocol**: New `make_fallback_cls_for_type_index` function in `object.pxi` that recursively creates Python proxy classes for C++-only types. The protocol guarantees: (1) parent classes are created before children, (2) each class inherits from the parent's fallback or registered class, (3) reflected fields/methods are attached, (4) the class is registered via `_update_registry` so the slow path fires only once per type.
- **Encapsulated attribute builders**: `TypeField.as_property(cls)` and `TypeMethod.as_callable(cls)` centralize the logic for creating `property`/method objects from reflection metadata, replacing the scattered inline logic in `registry.py._add_class_attrs`.
- **Self-resolving TypeInfo parent chain**: `TypeInfo.__post_init__` automatically resolves `parent_type_info` by reading `type_ancestors[-1]` from C and calling `_lookup_or_register_type_info_from_type_key`, ensuring parent `TypeInfo` is always populated before children.
- **Unified _update_registry helper**: Extracted from `_register_object_by_index` to share registry update logic between explicit registration and auto-generated fallback classes.

## Reflection

### Design docs to write
- **`.knowledge/designs/0014-python-bindings.md` update**: The "Pattern 1: `@register_object`" section should be extended to document the fallback class auto-generation path (`make_fallback_cls_for_type_index`), including the recursive parent resolution, the `__doc__` warning text, and the one-shot caching guarantee. This helps future commit mining for any changes to how unregistered types appear in Python.

### ADRs to write
- **`.knowledge/ADRs/0039-auto-fallback-python-class.md`**: Record the decision to auto-create proxy classes instead of warning-and-return-Object. Context: returning bare `Object` loses all reflected fields/methods, making debugging hard. Alternatives: (a) keep warning + bare Object (simpler but unusable), (b) require explicit registration (safe but breaks cross-language workflows where Python doesn't know about all C++ types). Trade-off: auto-creation is more complex but provides full reflected API on-the-fly.

### Design diagrams to draw
- **Mermaid flowchart**: Depict `make_ret_object` dispatch: fast path (registered class) vs slow path (`make_fallback_cls_for_type_index` -> recursive parent creation -> `_update_registry`). Show data flow from `TVMFFITypeInfo.type_ancestors` through `_type_info_create_from_type_key` to Python class hierarchy.
