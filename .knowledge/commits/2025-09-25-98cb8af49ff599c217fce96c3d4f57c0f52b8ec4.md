# Auto-create Python fallback classes for unregistered C++ object types

## TL;DR
- When a C++ object type is returned to Python without a registered Python class, the runtime now auto-generates a fallback class with reflection-derived fields, methods, and correct inheritance hierarchy instead of warning and falling back to `Object`.
- Renames `type_acenstors` to `type_ancestors` across the entire C ABI, C++ impl, and Cython bindings (typo fix).
- Refactors type registration internals: `_set_type_cls` now takes `TypeInfo` instead of `type_index`, `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key`, `TypeInfo` gains `type_ancestors` list and auto-resolves `parent_type_info` in `__post_init__`.

### Rename mapping (typo fix)
| Before | After |
|--------|-------|
| `TVMFFITypeInfo.type_acenstors` | `TVMFFITypeInfo.type_ancestors` |
| `type_acenstors_data` (C++ internal) | `type_ancestors_data` |
| `_lookup_type_info_from_type_key` | `_lookup_or_register_type_info_from_type_key` |
| `_set_type_cls(type_index, cls)` | `_set_type_cls(type_info, cls)` |

## Impact
- API: `TVMFFITypeInfo.type_acenstors` renamed to `type_ancestors` in `c_api.h` -- any external C/C++ code directly reading this field must update. `_set_type_cls` signature changed from `(int, type)` to `(TypeInfo, type)`. `_lookup_type_info_from_type_key` renamed to `_lookup_or_register_type_info_from_type_key`. `TypeInfo` dataclass gains required `type_ancestors` field.
- Behavioral: Returning an unregistered C++ object to Python no longer warns and returns `Object`; instead it silently auto-generates a typed fallback class with fields/methods from reflection. The slow path runs once per unregistered type_index.
- Flags/config: none
- Data formats/schemas: `TVMFFITypeInfo` C struct field renamed (`type_acenstors` -> `type_ancestors`)

## Design Elements
Design elements this commit consumes:
- **Object system** (`.knowledge/design-records/0002-object-system.md`): type hierarchy, `TVMFFITypeInfo`, `type_ancestors`, `IsInstance` ancestor lookup
- **Reflection** (`.knowledge/design-records/0008-reflection.md`): `TypeField`, `TypeMethod`, `FieldGetter`/`FieldSetter`, `TVMFFIFieldInfo`, `TVMFFIMethodInfo`, `ForEachFieldInfo` ancestor traversal
- **Python bindings** (`.knowledge/design-records/0012-python-bindings.md`): `make_ret_object`, `_register_object_by_index`, `TYPE_INDEX_TO_CLS`/`TYPE_INDEX_TO_INFO`/`TYPE_KEY_TO_INFO` registries, `_add_class_attrs`

Design elements this commit produces:
- **Fallback class auto-creation** (`make_fallback_cls_for_type_index`): new slow path in `make_ret_object` that recursively creates Python stub classes from reflection metadata
- **TypeInfo.type_ancestors**: new field providing the ancestor type_index chain, enabling `__post_init__` auto-resolution of `parent_type_info`
- **TypeMethod.as_callable**: new method consolidating method-to-Python-attribute conversion (previously inline in `_add_class_attrs` in `registry.py`)
- **_update_registry**: centralized registry mutation helper, reducing duplication between `_register_object_by_index`, `_lookup_or_register_type_info_from_type_key`, and `make_fallback_cls_for_type_index`

## Usage Examples

**Context**: C++ defines an object type with reflection but no Python `@register_object` class. The fallback auto-creation ensures Python can still access fields and methods.

```python
# C++ side (testing.cc):
# class TestUnregisteredBaseObject : public Object {
#   int64_t v1;
#   int64_t GetV1PlusOne() const { return v1 + 1; }
# };
# class TestUnregisteredObject : public TestUnregisteredBaseObject {
#   int64_t v2;
#   int64_t GetV2PlusTwo() const { return v2 + 2; }
# };
# Both registered with ObjectDef but NO Python @register_object.

import tvm_ffi

# Previously: UserWarning + fallback to bare Object (no field access)
# Now: auto-generated class with fields and methods from reflection
obj = tvm_ffi.testing.make_unregistered_object()  # returns TestUnregisteredObject

assert obj.v1 == 41                     # reflection-derived property
assert obj.v2 == 42                     # reflection-derived property
assert obj.get_v1_plus_one() == 42      # inherited method
assert obj.get_v2_plus_two() == 44      # own method
assert type(obj).__name__ == "TestUnregisteredObject"
assert "Auto-generated fallback class" in type(obj).__doc__
```
