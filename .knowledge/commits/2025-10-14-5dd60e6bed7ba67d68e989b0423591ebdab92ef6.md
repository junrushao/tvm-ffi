# Fix tvm_ffi_testing RPATH for wheel packaging and correct Linux platform guard
## TL;DR
- Adds `INSTALL_RPATH` to the `tvm_ffi_testing` CMake target (`@loader_path` on macOS, `$ORIGIN` on Linux) so it can locate `libtvm_ffi.so` via relative path when installed inside a wheel.
- Fixes the `tvm_ffi_cython` platform guard from `elseif (LINUX)` to `elseif (UNIX AND NOT APPLE)`, since `LINUX` is not a built-in CMake variable and would silently skip the RPATH on Linux unless explicitly set upstream.

## Key Exports

None -- no new public API. This commit modifies CMake target properties only.

## Impact
- API: none
- Behavioral: `tvm_ffi_testing.so`/`.dylib` can now find `libtvm_ffi` at runtime when co-located in the same directory (wheel install layout). Previously, the testing library had no install RPATH, causing `dlopen` failures when loaded from an installed wheel. The `tvm_ffi_cython` RPATH guard is also corrected to actually apply on Linux.
- Flags/config: `INSTALL_RPATH` property added to `tvm_ffi_testing` target. `tvm_ffi_cython` platform guard corrected from `LINUX` to `UNIX AND NOT APPLE`.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- RPATH convention for relative library resolution in wheels (documented in `.knowledge/designs/0013-packaging.md`, "RPATH convention" invariant). The `tvm_ffi_testing` target now follows the same pattern already established for `tvm_ffi_cython`.
- CMake platform detection idiom (`APPLE`, `UNIX AND NOT APPLE`) -- the canonical way to distinguish macOS from Linux in CMake, since `LINUX` is not a built-in variable.

Design elements this commit produces:
- None -- this is a corrective fix applying an existing convention to a target that was missing it.

## Usage Examples

**Before (broken)**: After wheel install, loading `tvm_ffi_testing.so` fails because it cannot find `libtvm_ffi.so` -- no RPATH tells the dynamic linker where to look.

**After (fixed)**: `tvm_ffi_testing.so` uses `@loader_path` (macOS) or `$ORIGIN` (Linux) to resolve `libtvm_ffi.so` from the same directory, matching the wheel install layout where both libraries are co-located.

Additionally, the `tvm_ffi_cython` RPATH on Linux was silently not being set due to the `LINUX` variable not being defined. After the fix, `UNIX AND NOT APPLE` correctly matches Linux systems.
