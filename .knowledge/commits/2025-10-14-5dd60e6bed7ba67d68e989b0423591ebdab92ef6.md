# Fix tvm_ffi_testing RPATH and Cython RPATH portability in wheel packaging

## TL;DR
- Adds `INSTALL_RPATH` to the `tvm_ffi_testing` shared library so it can find `libtvm_ffi.so` via relative path (`@loader_path` on macOS, `$ORIGIN` on Linux) when installed inside a wheel.
- Fixes the Cython extension's RPATH guard from `elseif (LINUX)` to `elseif (UNIX AND NOT APPLE)` for broader Unix portability (the `LINUX` variable is only available in CMake 3.25+).

## Key Exports
None -- this commit changes only CMake build configuration properties; no new public API, types, functions, or macros are introduced.

## Impact
- API: None
- ABI: None
- Behavioral: `libtvm_ffi_testing.so`/`.dylib` can now locate `libtvm_ffi.so` at runtime when both are installed side-by-side in a wheel package, without requiring `LD_LIBRARY_PATH`/`DYLD_LIBRARY_PATH`. Previously, loading `tvm_ffi_testing` from an installed wheel would fail with a dynamic linker error.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- RPATH configuration pattern for wheel-installed shared libraries (`.knowledge/designs/0015-python-packaging.md`, "RPATH configuration" contract)
- `tvm_ffi_testing` target introduced in commit da7007f (split of `testing.cc` into separate shared library)

Design elements this commit produces:
- Extends the RPATH contract: `tvm_ffi_testing` now follows the same RPATH pattern as `tvm_ffi_cython`, using `@loader_path` (macOS) / `$ORIGIN` (Linux) for relative library discovery. This is additive to the existing pattern documented in `.knowledge/designs/0015-python-packaging.md`.
- Portability fix: the `UNIX AND NOT APPLE` idiom replaces the CMake 3.25+-only `LINUX` variable, ensuring correct RPATH on all Unix platforms regardless of CMake version.
