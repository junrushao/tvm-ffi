# Introduce generic __tvm_ffi_env_stream__ protocol and rename TVMFFIEnvSetStream to TVMFFIEnvSetCurrentStream
## TL;DR
- Renames the C API function `TVMFFIEnvSetStream` to `TVMFFIEnvSetCurrentStream` across the C header (`c_env_api.h`), C++ implementation (`stream_context.cc`), and all Cython call sites (`base.pxi`, `function.pxi`), aligning its name with the existing `TVMFFIEnvGetCurrentStream` for symmetry.
- Introduces the `__tvm_ffi_env_stream__` Python protocol: any object implementing `__dlpack__` can also expose `__tvm_ffi_env_stream__()` to provide a stream handle for automatic stream context exchange when passed as an FFI argument.
- Adds DLPack device type constants from `dlpack/dlpack.h` to the Cython declarations (`base.pxi`) and restructures the extern block ordering (DLPack structs before TVM FFI structs) to make the device type enum available for the new stream protocol logic.

## Impact
- API: **Breaking rename** of `TVMFFIEnvSetStream` to `TVMFFIEnvSetCurrentStream` in the C ABI surface (`c_env_api.h`). All callers of the old symbol must update. The Cython bindings are updated in this commit; external callers of the C symbol need to be migrated.
- API: New optional Python protocol `__tvm_ffi_env_stream__()` for DLPack-compatible objects. Objects that do not implement it are unaffected (existing behavior preserved).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit **consumes**:

- **Thread-local stream context** ([`.knowledge/ADRs/0020-thread-local-stream-context.md`](../ADRs/0020-thread-local-stream-context.md)): The rename from `TVMFFIEnvSetStream` to `TVMFFIEnvSetCurrentStream` is a cosmetic evolution of this design element. The underlying `StreamContext` class and thread-local 2D vector storage are unchanged. The `opt_out_original_stream` RAII save/restore pattern is preserved.
- **Extra API tier** ([`.knowledge/designs/0011-extra-api-tier.md`](../designs/0011-extra-api-tier.md)): The stream context API remains in `include/tvm/ffi/extra/c_env_api.h`, gated under `TVM_FFI_USE_EXTRA_CXX_API`. The `TVM_FFI_DLL` visibility macro continues to be used (not `TVM_FFI_EXTRA_CXX_API`) because the function is `extern "C"`.
- **C ABI layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The renamed function retains the C ABI conventions: `extern "C"`, POD parameters (`int32_t`, `void*`), `int` return code, `TVM_FFI_DLL` visibility.
- **Python bindings / Cython argument packing** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The new `__tvm_ffi_env_stream__` protocol is integrated into `make_args` in `function.pxi`, specifically in the `__dlpack__` handling branch (priority item 4 in the argument packing order). The protocol extends the existing pattern where `torch.Tensor` auto-detects CUDA streams (priority item 3) to any DLPack-compatible object that can provide its stream handle.
- **DLPack device types**: The commit adds `kDLCPU`, `kDLCUDA`, etc. from `dlpack/dlpack.h` as Cython-level constants. These are needed to check `temp_dltensor.device.device_type != kDLCPU` when deciding whether to query the stream protocol.

Design elements this commit **produces**:

- **`__tvm_ffi_env_stream__` protocol**: A new Python-level duck-typing protocol for stream exchange. Any Python object that implements both `__dlpack__` and `__tvm_ffi_env_stream__()` can provide a stream handle (as a Python integer representing a `void*`) when passed as an FFI argument. The protocol is only queried for non-CPU devices and only when no prior argument has already set the stream context (`ctx_dev_type[0] == -1`). This generalizes the torch-specific CUDA stream detection to any framework.
- **`DLTensorTestWrapper`** (`tensor.pxi`): A Cython test helper class that wraps a `Tensor` and exposes `__dlpack__`, `__dlpack_device__`, and `__tvm_ffi_env_stream__` (which returns the current FFI stream for the tensor's device). This is used in benchmarks and testing to exercise the new protocol without a real GPU framework dependency.

## Key Implementations

### C API rename (`c_env_api.h`, `stream_context.cc`)

The rename from `TVMFFIEnvSetStream` to `TVMFFIEnvSetCurrentStream` is a pure symbol rename with no behavioral change. The function signature, error handling (`TVM_FFI_SAFE_CALL_BEGIN/END`), and `StreamContext::SetStream` delegation are identical. The motivation is naming symmetry: the getter was already named `TVMFFIEnvGetCurrentStream`, and the setter lacked the `Current` infix.

**Invariants preserved**: All contracts from ADR 0020 remain unchanged. The function still operates on thread-local storage, accepts `(device_type, device_id, stream, opt_out_original_stream)`, and returns `int` error codes.

### `__tvm_ffi_env_stream__` protocol in `make_args` (`function.pxi`)

The new protocol is integrated in the `hasattr(arg, "__dlpack__")` branch of `make_args`:

```
elif hasattr(arg, "__dlpack__"):
    ffi_arg = from_dlpack(arg)
    ...
    if (temp_dltensor.device.device_type != kDLCPU and
        ctx_dev_type != NULL and
        ctx_dev_type[0] == -1):
        if hasattr(arg, "__tvm_ffi_env_stream__"):
            ctx_dev_type[0] = temp_dltensor.device.device_type
            ctx_dev_id[0] = temp_dltensor.device.device_id
            temp_ptr = arg.__tvm_ffi_env_stream__()
            ctx_stream[0] = <TVMFFIStreamHandle>temp_ptr
```

Key design decisions:
- **Non-CPU guard**: The stream protocol is only queried when the DLTensor device is not CPU (`kDLCPU`). CPU tensors do not have stream semantics.
- **First-writer-wins**: The `ctx_dev_type[0] == -1` check ensures only the first non-CPU DLPack argument with stream info sets the context. This is consistent with the existing torch.Tensor stream handling pattern.
- **Variable rename**: The local variable for the converted tensor was renamed from `arg` to `ffi_arg` to preserve the original `arg` for calling `__tvm_ffi_env_stream__()` on it. Previously `arg` was rebound to the converted `Tensor`, losing access to the original object's protocol methods.
- **Opt-in**: The protocol is entirely optional. Objects without `__tvm_ffi_env_stream__` are handled exactly as before (DLPack conversion only, no stream context exchange).

**Invariant**: The `__tvm_ffi_env_stream__()` method must return a Python integer that can be cast to `TVMFFIStreamHandle` (`void*`). This is the raw stream pointer (e.g., `cudaStream_t`).

**Extension point**: Future frameworks beyond PyTorch (e.g., JAX, CuPy) can implement `__tvm_ffi_env_stream__()` on their tensor types to participate in automatic stream context exchange with TVM FFI.

### Cython DLPack device type declarations (`base.pxi`)

The `base.pxi` file was restructured: the `dlpack/dlpack.h` extern block (containing `DLDataType`, `DLDevice`, `DLTensor`, `DLManagedTensorVersioned`) was moved before the `tvm/ffi/c_api.h` extern block, and the DLPack device type enum constants (`kDLCPU`, `kDLCUDA`, etc.) were added. These constants were previously unavailable in Cython and are now needed for the `temp_dltensor.device.device_type != kDLCPU` check.

### DLTensorTestWrapper (`tensor.pxi`)

A test-only Cython class that wraps a `Tensor` and implements the new protocol. Its `__tvm_ffi_env_stream__()` calls `TVMFFIEnvGetCurrentStream` for the wrapped tensor's device, effectively echoing back whatever stream is currently set in the FFI thread-local context. This enables testing the round-trip: set a stream -> pass wrapper as arg -> protocol queries stream -> FuncCall sets stream from protocol result.

### Benchmark updates (`scripts/benchmark_dlpack.py`)

- Adds `tvm_ffi_nop_autodlpack_from_dltensor_test_wrapper` benchmark for both CPU and CUDA devices, measuring the overhead of the new `__tvm_ffi_env_stream__` protocol path.
- Fixes a bug in `tvm_ffi_nop` where the inner loop was calling `tvm_ffi.from_dlpack(x)` instead of `nop(x, y, z)`, making it measure DLPack conversion rather than NOP call overhead.
- Reorders benchmark execution: moves `tvm_ffi_nop` to after the DLPack benchmarks.
- Widens output format columns from 40 to 60 characters to accommodate longer benchmark names.

### ADRs to write

- **`.knowledge/ADRs/0027-generic-stream-exchange-protocol.md`**: Record the decision to introduce a Python duck-typing protocol (`__tvm_ffi_env_stream__`) for stream context exchange, rather than: (1) requiring each framework to call `TVMFFIEnvSetCurrentStream` directly (places burden on framework authors), (2) using a registry of framework-specific stream query functions (maintains framework-specific code in TVM FFI), (3) passing streams as explicit FFI arguments (breaking ABI change).
  - Decision context: As more ML frameworks adopt DLPack, each has its own stream management. The protocol enables zero-coupling stream exchange.
  - Trade-offs: Duck-typing means no compile-time enforcement of the protocol contract; the return value must be a raw pointer as integer, which is fragile. The protocol is opt-in, so non-implementing objects silently skip stream exchange.
