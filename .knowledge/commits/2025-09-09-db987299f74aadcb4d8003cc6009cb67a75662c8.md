# Introduce __tvm_ffi_env_stream__ protocol for generic DLPack tensor stream exchange
## TL;DR
- Renames `TVMFFIEnvSetStream` to `TVMFFIEnvSetCurrentStream` across C header, C++ implementation, and all Cython call sites for naming consistency with the existing `TVMFFIEnvGetCurrentStream`.
- Introduces the `__tvm_ffi_env_stream__` Python dunder protocol: any object that implements `__dlpack__` can also expose `__tvm_ffi_env_stream__()` to supply the device stream for FFI calls, extending stream context capture beyond torch tensors to arbitrary DLPack-compatible frameworks.
- Adds `DLTensorTestWrapper` Cython class for testing the new protocol and updates `benchmark_dlpack.py` accordingly.
- Reorganizes `base.pxi` to declare DLPack device type enums (`kDLCPU`, `kDLCUDA`, etc.) from `dlpack/dlpack.h` for use in stream context detection.

## Key Exports

**Functions (renamed)**:
- `TVMFFIEnvSetCurrentStream(int32_t device_type, int32_t device_id, TVMFFIStreamHandle stream, TVMFFIStreamHandle* opt_out_original_stream) -> int` -- renamed from `TVMFFIEnvSetStream`. Same semantics: sets thread-local current stream for a device, optionally returns previous stream. Uses `TVM_FFI_SAFE_CALL_BEGIN/END`.

**Protocols**:
- `__tvm_ffi_env_stream__() -> int` -- Python dunder protocol. When present on an object that also has `__dlpack__`, the Cython `make_args` function calls it to obtain the stream handle (as an integer) for the source framework. The stream is then set via `TVMFFIEnvSetCurrentStream` before the FFI call and restored afterward. This allows any DLPack-compatible tensor library to participate in stream context exchange without requiring explicit stream setup through `TVMFFIEnvSetCurrentStream`.

**Types/Classes**:
- `DLTensorTestWrapper` (Cython cdef class in `tensor.pxi`) -- Test-only wrapper around `Tensor` that implements `__tvm_ffi_env_stream__`, `__dlpack__`, and `__dlpack_device__`. Returns the current FFI stream for the tensor's device via `TVMFFIEnvGetCurrentStream`.

**Constants/Enums (newly declared in Cython)**:
- DLPack device type constants from `dlpack/dlpack.h` declared in `base.pxi`: `kDLCPU=1`, `kDLCUDA=2`, `kDLCUDAHost=3`, `kDLOpenCL=4`, `kDLVulkan=7`, `kDLMetal=8`, `kDLVPI=9`, `kDLROCM=10`, `kDLROCMHost=11`, `kDLExtDev=12`, `kDLCUDAManaged=13`, `kDLOneAPI=14`, `kDLWebGPU=15`, `kDLHexagon=16`, `kDLMAIA=17`, `kDLTrn=18`. These are used in `make_args` to detect non-CPU devices for stream context capture.

**Renames**:

| Old Name | New Name |
|----------|----------|
| `TVMFFIEnvSetStream` | `TVMFFIEnvSetCurrentStream` |

## Impact
- API: `TVMFFIEnvSetStream` renamed to `TVMFFIEnvSetCurrentStream`. All callers of this C API function must update. The Python/Cython layer is updated in this commit; external C/C++ callers would need to rename.
- ABI: Breaking -- the exported C symbol name changes from `TVMFFIEnvSetStream` to `TVMFFIEnvSetCurrentStream`. Shared libraries linked against the old symbol will fail to resolve.
- Behavioral: Objects implementing `__dlpack__` now also have their `__tvm_ffi_env_stream__` checked during argument packing, enabling automatic stream context propagation from arbitrary frameworks (not just torch). This happens only for non-CPU devices when no prior stream context has been set in the current `make_args` call.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Thread-local stream context** (`.knowledge/designs/c-abi.md`, Extra C Env API section) -- the stream set/get API that records weak stream references per `(device_type, device_id)` in a TLS 2D table.
- **DLPack auto-conversion in make_args** (`.knowledge/designs/0014-python-bindings.md`, make_arg dispatch table) -- the `hasattr(arg, "__dlpack__")` branch in `make_args` that converts DLPack objects to FFI tensors.
- **CUDA stream context capture for torch** (`.knowledge/designs/0014-python-bindings.md`, CUDA Stream Context section) -- the existing pattern where `make_args` captures the torch CUDA stream and sets it via the stream API before/after function calls.
- **DLPack protocol** (`dlpack/dlpack.h`) -- `__dlpack__`, `__dlpack_device__` Python dunder methods for zero-copy tensor exchange.

Design elements this commit produces:
- **`__tvm_ffi_env_stream__` protocol** -- A new Python dunder protocol for generic stream exchange. Any object with `__dlpack__` can additionally implement `__tvm_ffi_env_stream__() -> int` to provide the stream handle. This generalizes stream context capture from torch-specific to framework-agnostic.
- **DLPack device type enum declarations in Cython** -- `base.pxi` now declares the `kDL*` device type constants directly from `dlpack/dlpack.h` via `cdef extern`, enabling Cython-level device type comparisons (specifically `kDLCPU` for filtering out CPU devices from stream capture).

## Usage Examples

### Using the `__tvm_ffi_env_stream__` protocol
**Context**: A custom tensor wrapper implements the protocol so that FFI function calls automatically capture its device stream.
```python
class MyFrameworkTensor:
    """Tensor from a third-party framework with its own stream management."""
    def __dlpack__(self, **kwargs):
        return self._inner.__dlpack__(**kwargs)

    def __dlpack_device__(self):
        return self._inner.__dlpack_device__()

    def __tvm_ffi_env_stream__(self):
        # Return the framework's current stream as an integer (void* cast)
        return self._framework_get_current_stream()

# When passed to an FFI function, stream context is automatically set:
ffi_func(my_tensor)  # make_args detects __tvm_ffi_env_stream__, sets stream
```

### Before/after: stream context capture for DLPack objects
**Before**: Only `torch.Tensor` objects triggered stream context capture in `make_args`. Generic `__dlpack__` objects were converted but no stream was captured.

**After**: Any `__dlpack__` object that also implements `__tvm_ffi_env_stream__` triggers stream capture. The check is: (1) device is not CPU, (2) no prior stream context captured in this call, (3) `hasattr(arg, "__tvm_ffi_env_stream__")`.
