# Fix mypy type inference for `dataclasses.field(...)` in `c_class` definitions

## TL;DR
- Changed `field()` return type from `-> Field` to `-> _FieldValue` (via `TypeVar` + `cast`) so mypy infers the declared field type instead of reporting `Field` vs annotation mismatch.
- Added `_MISSING_TYPE` union to `field()` parameter types for correct sentinel typing.
- Added `typing-extensions` as a runtime dependency in `pyproject.toml`.

## Key Exports

```python
_FieldValue = TypeVar("_FieldValue")

def field(
    *,
    default: _FieldValue | _MISSING_TYPE = MISSING,
    default_factory: Callable[[], _FieldValue] | _MISSING_TYPE = MISSING,
) -> _FieldValue:
    """Return type uses TypeVar so mypy infers the annotated field type."""
    # Old signature: def field(*, default: Any = MISSING, default_factory: Any = MISSING) -> Field
    # New signature: -> _FieldValue (via cast)
    # Interacts with: c_class decorator (consumes Field instances from class body)
    # Invariant: at runtime still returns a Field object; cast is purely for type-checker benefit
    ...

class Field:
    """Unchanged at runtime. __init__ parameter types updated for consistency."""
    default_factory: Callable[[], _FieldValue] | _MISSING_TYPE  # was: Callable[[], Any]
    # Interacts with: c_class decorator reads .default_factory during class registration
    ...
```

## Impact
- API: none -- runtime behavior unchanged; only type-checker annotations affected
- Behavioral: none
- Flags/config: `typing-extensions` added as a new runtime dependency in `pyproject.toml`
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `field()` / `Field` class in `python/tvm_ffi/dataclasses/field.py` -- the dataclass-style default mechanism for `c_class` proxies
- `c_class` decorator -- consumes `Field` instances from class bodies (see [0007-ffi-reflection](../design-records/0007-ffi-reflection.md) for the C++ reflection system it maps to)

Design elements this commit produces: none -- this is a type-annotation-only fix with no contract changes.

## Usage Examples

Before (mypy error):
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # type: ignore[assignment]
    #                                                        ^^^^^^^^^^^^^^^^^^^^^^^^
    #  Required because field() returned `Field`, not `str`
```

After (no suppression needed):
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # OK: field() -> str via TypeVar
```
