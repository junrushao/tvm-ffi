# Fix mypy type-checking warnings for `field()` in `c_class` by returning `_FieldValue` via TypeVar + cast
## TL;DR
- `field()` return type changed from `Field` to `_FieldValue` (a `TypeVar`) via `cast()`, eliminating mypy `[assignment]` errors when `field(default_factory=...)` is used as a class-level default in `c_class` definitions.
- `Field.__init__` parameter `default_factory` now accepts `_MISSING_TYPE` sentinel to match `dataclasses` conventions.
- `typing-extensions` added as a runtime dependency in `pyproject.toml`.

## Key Exports

```python
_FieldValue = TypeVar("_FieldValue")

class Field:
    """Descriptor placeholder returned by field()."""
    __slots__ = ("default_factory", "name")

    def __init__(
        self,
        *,
        name: str | None = None,
        # Changed: was Callable[[], Any], now accepts _MISSING_TYPE sentinel
        default_factory: Callable[[], _FieldValue] | _MISSING_TYPE = MISSING,
    ) -> None: ...
    # Interacts with: c_class decorator (consumes Field instances during class construction)

# Old: def field(*, default: Any = MISSING, default_factory: Any = MISSING) -> Field
# New:
def field(
    *,
    default: _FieldValue | _MISSING_TYPE = MISSING,
    default_factory: Callable[[], _FieldValue] | _MISSING_TYPE = MISSING,
) -> _FieldValue:
    """Returns cast(_FieldValue, Field(...)) so mypy sees the annotated type, not Field."""
    # Interacts with: c_class decorator, dataclasses.MISSING sentinel
    # Invariant: exactly one of default/default_factory may be specified (ValueError otherwise)
    ...
```

## Impact
- API: Return type annotation of `field()` changed from `Field` to `_FieldValue`. Runtime behavior unchanged (still returns a `Field` object at runtime; `cast()` is a no-op). Callers using `isinstance(x, Field)` are unaffected.
- Behavioral: none -- purely a static typing improvement.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `c_class` decorator from `tvm_ffi.dataclasses` (the `field()` helper is designed to integrate with it; see `0008-reflection` and `0012-python-bindings`)
- `dataclasses.MISSING` / `dataclasses._MISSING_TYPE` sentinel protocol from the Python stdlib

Design elements this commit produces:
- `_FieldValue` TypeVar pattern: the same technique used by `dataclasses.field()` in typeshed stubs to make the return type match the annotated field type for type-checker consumption.

## Usage Examples
**Before (mypy error):**
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # type: ignore[assignment]
    #                                                        ^^^ needed to suppress mypy
```

**After (clean):**
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # no suppression needed
```
