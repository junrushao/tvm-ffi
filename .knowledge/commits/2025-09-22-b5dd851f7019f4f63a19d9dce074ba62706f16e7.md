# Fix mypy warnings on `dataclasses.field(...)` in c_class definitions

## TL;DR
- Fixes a mypy type-checking error where `field(default_factory=...)` returned `Field` but was assigned to a typed annotation like `str`, causing `Incompatible types in assignment` warnings.
- Changes the return type of `tvm_ffi.dataclasses.field()` from `-> Field` to `-> _FieldValue` (a `TypeVar`), using `typing.cast` internally to satisfy the type checker while still returning a `Field` object at runtime.
- Adds `typing-extensions` as a runtime dependency in `pyproject.toml`.
- Removes now-unnecessary `# type: ignore[assignment]` suppression comments from `testing.py`.

## Key Exports
No new public APIs. The signature of `field()` changes at the type-checking level only:

| Module | Function | Before | After |
|--------|----------|--------|-------|
| `dataclasses/field.py` | `field()` | `-> Field` | `-> _FieldValue` (TypeVar) |
| `dataclasses/field.py` | `Field.__init__` | `default_factory: Callable[[], Any]` | `default_factory: Callable[[], _FieldValue] \| _MISSING_TYPE` |

## Impact
- **API**: No runtime behavior change. `field()` still returns a `Field` instance at runtime; only the static type signature changes.
- **ABI**: None.
- **Dependencies**: `typing-extensions` is added as a runtime dependency (`dependencies = ["typing-extensions"]` in `pyproject.toml`). Previously there were no runtime dependencies.
- **Type checking**: Users no longer need `# type: ignore[assignment]` when using `field()` in `c_class` definitions. The `TypeVar` `_FieldValue` allows mypy to infer the declared field type from the annotation context.

## Design Elements
Design elements this commit consumes:
- **Python `c_class` / dataclasses system** (`.knowledge/designs/0014-python-bindings.md`): The `field()` helper and `Field` descriptor class that integrate with the `c_class` decorator to express dataclass-style defaults on FFI proxy classes.

Design elements this commit produces:
- **TypeVar-based `field()` return type pattern**: The `_FieldValue = TypeVar("_FieldValue")` + `cast(_FieldValue, ret)` pattern mirrors how `dataclasses.field` is typed in typeshed (returning the declared field type rather than `Field`). This eliminates assignment-type conflicts in mypy without requiring type-ignore comments.

## Usage Examples
Before this fix, c_class definitions using `field()` required type-ignore comments:

```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # type: ignore[assignment]
```

After this fix, the type-ignore is no longer needed:

```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")
```
