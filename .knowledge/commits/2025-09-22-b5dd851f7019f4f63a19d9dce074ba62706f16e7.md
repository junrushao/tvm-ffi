# Fix mypy type-checking warnings on `dataclasses.field(...)` in `c_class` definitions
## TL;DR
- Changed the return type of `tvm_ffi.dataclasses.field()` from `Field` to a generic `_FieldValue` TypeVar, matching the pattern used by `dataclasses.field()` in typeshed, so mypy no longer reports "Incompatible types in assignment" when `field()` is used as a default in `c_class` definitions.
- Widened `Field.__init__` parameter `default_factory` to accept `_MISSING_TYPE` sentinel alongside callables, aligning with dataclasses semantics.
- Added `typing-extensions` as a runtime dependency in `pyproject.toml`.

## Key Exports
**Function** (signature changed):
```python
_FieldValue = TypeVar("_FieldValue")

def field(
    *,
    default: _FieldValue | _MISSING_TYPE = MISSING,      # type: ignore[assignment]
    default_factory: Callable[[], _FieldValue] | _MISSING_TYPE = MISSING,  # type: ignore[assignment]
) -> _FieldValue: ...
```
Previously returned `Field`; now returns `_FieldValue` (via `cast()`). Runtime behavior unchanged -- still returns a `Field` instance.

**Class** (constructor signature changed):
```python
class Field:
    def __init__(
        self,
        *,
        name: str | None = None,
        default_factory: Callable[[], _FieldValue] | _MISSING_TYPE = MISSING,
    ) -> None: ...
```
Previously `default_factory: Callable[[], Any]` with no default. Now accepts `_MISSING_TYPE` and defaults to `MISSING`.

## Impact
- API: Return type annotation of `field()` changed from `Field` to `_FieldValue`. Runtime return value unchanged (still `Field`). No callers break.
- Behavioral: None. `cast()` is a no-op at runtime.
- Flags/config: `typing-extensions` added as a new runtime dependency (previously zero dependencies).
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- `c_class` decorator (`tvm_ffi.dataclasses`) -- processes `Field` instances from class bodies to register default factories. Not yet documented in `.knowledge/`.
- `Field` class (`tvm_ffi.dataclasses.field`) -- placeholder object that `c_class` inspects during class registration.
- Python `dataclasses.MISSING` / `_MISSING_TYPE` sentinel pattern -- reused from stdlib to indicate "no default provided."

Design elements this commit produces:
- `_FieldValue` TypeVar -- enables mypy to infer that `field()` returns the same type as the annotated field, eliminating false-positive assignment errors.
- `typing-extensions` dependency -- first runtime dependency for the `tvm_ffi` package.

## Usage Examples
**Before** (mypy error, required suppression):
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # type: ignore[assignment]
```

**After** (clean, no suppression needed):
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")
```
