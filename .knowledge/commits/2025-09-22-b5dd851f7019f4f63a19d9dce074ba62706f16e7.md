# Fix mypy type-annotation mismatch on field() return type in c_class definitions

## TL;DR

- `field()` previously declared its return type as `Field`, causing mypy to flag `v_str: str = field(...)` as an incompatible assignment. Fixed by making `field()` return `_FieldValue` (TypeVar) and using `cast()` internally.
- `_MISSING_TYPE` imported from `dataclasses` private API to properly annotate `default`/`default_factory` parameters (avoids `Any`-widening).
- `typing-extensions` added as a formal runtime dependency in `pyproject.toml` (it was already consumed by `c_class.py` via `dataclass_transform`).

## Key Exports

```python
_FieldValue = TypeVar("_FieldValue")

class Field:
    """Internal descriptor for a c_class field with a default factory."""
    name: str | None
    default_factory: Callable[[], Any] | _MISSING_TYPE
    # Invariant: default_factory is always set before Field is used at class-build time
    # Interacts with: c_class decorator (reads .default_factory to build ObjectCreator args)

def field(
    *,
    default: _FieldValue | _MISSING_TYPE = MISSING,         # type: ignore[assignment]
    default_factory: Callable[[], _FieldValue] | _MISSING_TYPE = MISSING,  # type: ignore[assignment]
) -> _FieldValue:
    # Old signature: -> Field
    # New signature: -> _FieldValue  (mypy sees it as returning the declared attribute type)
    # Invariant: exactly one of default / default_factory may be set
    # Interacts with: c_class decorator, Field.__init__, _make_default_factory
    # Implementation detail: returns cast(_FieldValue, Field(...)) at runtime
    ...
```

## Impact

- API: `field()` return type changed from `Field` to `_FieldValue` in annotations. At runtime the returned object is still a `Field` instance; the cast is purely a mypy hint. Callers that introspect the return type via `isinstance(x, Field)` are unaffected.
- Behavioral: None — runtime behavior is identical; only type-checker behavior changes.
- Flags/config: `typing-extensions` added as a declared runtime dependency (`pyproject.toml`). Was previously an undeclared transitive dep consumed by `c_class.py`.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- `Field` / `field()` from `python/tvm_ffi/dataclasses/field.py` — the dataclass-field descriptor for `c_class`-decorated types (no design record exists yet; see Reflection).
- `c_class` decorator (`python/tvm_ffi/dataclasses/c_class.py`) — consumes `Field.default_factory`; unmodified by this commit.
- `dataclasses.MISSING` / `_MISSING_TYPE` sentinel pattern from stdlib.

Design elements this commit produces:
- Strengthened return-type contract for `field()`: now `_FieldValue` (TypeVar), enabling mypy to validate attribute assignments in `c_class` bodies without suppression comments.
- `_MISSING_TYPE`-typed parameters on `Field.__init__` and `field()` (previously typed `Any`).

## Usage Examples

**Before (required suppression comment):**
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")  # type: ignore[assignment]
```

**After (no suppression needed):**
```python
@c_class("testing.TestCxxClassDerivedDerived")
class _TestCxxClassDerivedDerived(_TestCxxClassDerived):
    v_str: str = field(default_factory=lambda: "default")
    v_bool: bool  # type: ignore[misc]  # Suppress: Attributes without a default cannot follow attributes with one
```
