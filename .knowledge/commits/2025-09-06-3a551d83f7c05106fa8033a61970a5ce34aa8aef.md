# Rename NDArray to Tensor across the entire codebase to align with ML ecosystem terminology
## TL;DR
- Renames the core tensor container from `NDArray`/`NDArrayObj` to `Tensor`/`TensorObj` across all layers: C ABI enum (`kTVMFFINDArray` -> `kTVMFFITensor`), C API functions (`TVMFFINDArray*` -> `TVMFFITensor*`), C++ headers/source (`ndarray.h` -> `tensor.h`), Python bindings (`NDArray` -> `Tensor`, `ndarray.py` -> `tensor.py`), Cython bindings (`ndarray.pxi` -> `tensor.pxi`), tests, and documentation.
- Also renames the `skip_ndarray_content` parameter in `StructuralEqual::Equal`/`GetFirstMismatch` and `StructuralHash::Hash` to `skip_tensor_content`, and updates the internal comparison method from `CompareNDArray`/`HashNDArray` to `CompareTensor`/`HashTensor`.
- Includes two incidental changes: (1) simplifies `Module.__call__` to use `self.main` instead of the cached `entry_func` property and removes `__new__`/`entry_func`, (2) adds a `clean` target to `docs/Makefile`, (3) guards the `import torch` in Cython `function.pxi` behind `TVM_FFI_BUILD_DOCS` env var.

## Impact
- **API**: Breaking rename of public C++ classes (`NDArray` -> `Tensor`, `NDArrayObj` -> `TensorObj`), C ABI enum value (`kTVMFFINDArray` -> `kTVMFFITensor`), C API functions (`TVMFFINDArrayFromDLPack` -> `TVMFFITensorFromDLPack`, etc.), inline C accessor (`TVMFFINDArrayGetDLTensorPtr` -> `TVMFFITensorGetDLTensorPtr`), Python public symbol (`tvm_ffi.NDArray` -> `tvm_ffi.Tensor`), and the `StaticTypeKey` constant (`kTVMFFINDArray` -> `kTVMFFITensor` with value `"ffi.Tensor"`). All downstream callers in C++, Python, Cython, and Rust that reference the old names must update. The type index numeric value (70) is unchanged.
- **Flags/config**: None.
- **Data formats/schemas**: The type key string changes from `"ffi.NDArray"` to `"ffi.Tensor"`. Any serialized data (JSON, etc.) that stores type keys will need migration. Registered object lookups using the old key will fail.

## Design Elements

Design elements this commit **consumes**:

- **Container System / NDArray** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The entire NDArray subsection of the container design is the target of this rename. The `NDArrayObj` class structure, `shape_data_`/`stride_data_` ownership pattern, DLPack import/export, `TensorObjFromNDAlloc`/`TensorObjFromDLPack` template helpers, and the `IsContiguous`/`IsAligned`/`GetDataSize` free functions are all carried over structurally unchanged.
- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The type index `kTVMFFINDArray = 70` in the static object range `[64, 128)` is renamed to `kTVMFFITensor = 70`. The cell-at-offset-24 convention for the `DLTensor` accessor is preserved but the function name changes.
- **Structural Equal/Hash** ([`.knowledge/designs/0009-structural-equal-hash.md`](../designs/0009-structural-equal-hash.md)): The NDArray comparison/hash dispatch branches in `StructEqualHandler` and `StructuralHashHandler` are renamed but functionally identical.
- **Python Bindings** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The Cython `NDArray` class, `make_ndarray_from_any`/`make_ndarray_from_chandle` helpers, and Python-level `NDArray`/`ndarray.py` module are all renamed.

Design elements this commit **produces**:

- **Tensor naming convention**: Establishes `Tensor`/`TensorObj` as the canonical name for the DLPack-backed n-dimensional array container throughout the codebase. This aligns with `torch.Tensor` and `DLTensor` naming in the broader ML ecosystem. The rename is purely nominal -- no behavioral, layout, or ABI numeric changes (type index remains 70, cell offset remains 24).
- **Module simplification** (incidental): `Module.__call__` now calls `self.main` directly (presumably a reflected method from the C++ side) instead of maintaining a cached `_entry` function reference and `entry_func` property. The `Module.__new__` override is removed.
- **Docs build improvement** (incidental): `docs/Makefile` gains a `clean` target and its `.PHONY` declaration. The torch import in Cython is now gated by `TVM_FFI_BUILD_DOCS` to avoid import issues during documentation builds.

## Reflection

### Design docs to write

- **Update `.knowledge/designs/0005-containers.md`**: All references to `NDArray`/`NDArrayObj` must be updated to `Tensor`/`TensorObj`. The class diagram, key classes section, invariants section, and evidence matrix all use the old names. This is critical because future commit mining will look for `Tensor` references and find stale `NDArray` terminology.
  - Scope: Rename `NDArrayObj` -> `TensorObj` in the class diagram, `NDArray: Explicit Strides Invariant` section heading -> `Tensor: Explicit Strides Invariant`, all class/field references, and the "NDArray strides are always non-null" invariant text.
  - Why: Every future commit touching the tensor container will reference this design doc, and mismatched terminology will cause confusion in commit mining.

- **Update `.knowledge/designs/0001-c-abi.md`**: Rename `kTVMFFINDArray` to `kTVMFFITensor` in the type index diagram, the object cell layout table, and the `extern "C"` API surface table. Update function names (`TVMFFINDArrayFromDLPack` -> `TVMFFITensorFromDLPack`, etc.) and the accessor function name.
  - Why: The C ABI design doc is the authoritative reference for symbol names. Stale names will mislead future ABI-focused analysis.

- **Update `.knowledge/designs/0009-structural-equal-hash.md`** (if it references `skip_ndarray_content`): Rename the parameter reference to `skip_tensor_content`.
  - Why: Parameter naming is part of the public API contract documented in the design.

### Skill evolution (`/commit-ledger`)

- **Large rename commits**: This commit touches 30+ files but the semantic content is a mechanical rename plus two small incidental changes. The current procedure spends equal effort on all files, which is wasteful for renames. Consider adding a heuristic in Step 2: if `git show --stat` reveals that >80% of changes are file renames (detected by `git diff --diff-filter=R`) and the remaining changes are identifier substitutions, classify as "rename/migration" and fast-path Step 3/4 to focus only on (a) what names changed, (b) which ABI/serialization contracts are affected, and (c) any incidental non-rename changes bundled in the commit.
- **Incidental changes in rename commits**: This commit bundles the Module simplification and docs/Makefile changes alongside the NDArray->Tensor rename. The procedure should explicitly prompt: "Are there any non-rename changes bundled in this commit? List them separately as incidental changes." This helps avoid burying behavioral changes inside what appears to be a mechanical rename.

## Self-Evolution of Skill /commit-ledger

- The procedure works well for this commit type but could benefit from a "rename detection" fast path. When `git diff --diff-filter=R --summary` shows many renames and the commit message contains "Rename" or "rename", the skill could skip deep code reading of renamed files and instead focus on: (1) enumerating all old->new name pairs, (2) checking which knowledge base docs reference the old names, and (3) identifying any non-rename changes. This would cut analysis time roughly in half for commits like this one.
