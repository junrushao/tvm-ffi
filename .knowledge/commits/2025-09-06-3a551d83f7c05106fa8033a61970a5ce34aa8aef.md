# Rename NDArray to Tensor across entire FFI stack (C ABI, C++, Python/Cython, docs, tests)
## TL;DR
- Renames all `NDArray`/`NDArrayObj` types and symbols to `Tensor`/`TensorObj` across every layer: C ABI enums and functions, C++ headers and sources, Cython bindings, pure Python, docs, examples, and tests.
- The type key changes from `"ffi.NDArray"` to `"ffi.Tensor"` and the enum constant from `kTVMFFINDArray` to `kTVMFFITensor` (value stays 70).
- Secondary changes: removes `Module.entry_func` property / `Module.__new__` in favor of `Module.main` attribute access; adds `TVM_FFI_BUILD_DOCS` env-var guard for torch import in Cython; bumps version `0.1.0a7` to `0.1.0a8`; adds docs `clean` target and `.gitignore` for generated RST.

## Key Exports

**Renames** (see mapping table above). The API surface is unchanged in structure; only names differ.

**Types/Classes**:
- `TensorObj` -- `class TensorObj : public Object, public DLTensor` (was `NDArrayObj`). Static type index `kTVMFFITensor = 70`, type key `"ffi.Tensor"`.
- `Tensor` -- `class Tensor : public ObjectRef` (was `NDArray`). Methods: `shape() -> Shape`, `dtype() -> DLDataType`, `IsContiguous() -> bool`, `FromNDAlloc<T>(...) -> Tensor`, `FromDLPack(DLManagedTensor*, ...) -> Tensor`, `FromDLPackVersioned(DLManagedTensorVersioned*, ...) -> Tensor`, `ToDLPack() -> DLManagedTensor*`, `ToDLPackVersioned() -> DLManagedTensorVersioned*`.

**C ABI functions** (renamed, same signatures):
- `TVMFFITensorFromDLPack(DLManagedTensor*, int32_t, int32_t, TVMFFIObjectHandle*) -> int`
- `TVMFFITensorToDLPack(TVMFFIObjectHandle, DLManagedTensor**) -> int`
- `TVMFFITensorFromDLPackVersioned(DLManagedTensorVersioned*, int32_t, int32_t, TVMFFIObjectHandle*) -> int`
- `TVMFFITensorToDLPackVersioned(TVMFFIObjectHandle, DLManagedTensorVersioned**) -> int`
- `TVMFFITensorGetDLTensorPtr(TVMFFIObjectHandle) -> DLTensor*` (inline)

**Parameters renamed**:
- `StructuralEqual::Equal(..., skip_ndarray_content)` -> `skip_tensor_content`
- `StructuralEqual::GetFirstMismatch(..., skip_ndarray_content)` -> `skip_tensor_content`
- `StructuralHash::Hash(..., skip_ndarray_content)` -> `skip_tensor_content`

## Impact
- API: **Breaking ABI change**. All C ABI symbols containing `NDArray` are renamed to `Tensor`. Any compiled code, language binding, or FFI caller that references the old symbols (`TVMFFINDArray*`, `kTVMFFINDArray`) must be updated. The Python public API changes `tvm_ffi.NDArray` to `tvm_ffi.Tensor`. The `Module.entry_func` property is removed (callers should use `Module.main` or `Module.__call__`).
- Behavioral: No semantic changes to tensor operations. The `TVM_FFI_BUILD_DOCS` environment variable now gates torch import in Cython (prevents import failure during doc builds).
- Flags/config: `TVM_FFI_BUILD_DOCS=1` suppresses torch import in Cython `function.pxi`.
- Data formats/schemas: The type key string changes from `"ffi.NDArray"` to `"ffi.Tensor"`. Serialized data containing the old type key will not deserialize without migration.

Design elements this commit consumes:
- **Object system** (`TVM_FFI_DECLARE_STATIC_OBJECT_INFO`, `TVM_FFI_DEFINE_OBJECT_REF_METHODS`, `ObjectRef`, `Object`) -- standard Obj/Ref pattern applied to `TensorObj`/`Tensor`. See [0003-object-system.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0003-object-system.md).
- **C ABI layer** (`TVMFFITypeIndex` enum, DLL export macros, `TVM_FFI_SAFE_CALL_BEGIN/END`) -- the DLPack C API functions follow standard C ABI wrapping pattern. See [0001-c-abi-layer.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0001-c-abi-layer.md).
- **Static type index layout** (`kTVMFFITensor = 70` remains in the "simple C ABI" range). See [ADR 0004-type-index-layout.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/ADRs/0004-type-index-layout.md).
- **Type key namespace** (`"ffi.Tensor"` follows `ffi.*` prefix convention). See [ADR 0007-ffi-type-key-namespace.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/ADRs/0007-ffi-type-key-namespace.md).
- **Container design** (DLPack interop, `FromNDAlloc` allocator pattern, strides invariant). See [0008-containers.md](/Users/junrus/Projects/tvm-ffi-knowledge/.knowledge/designs/0008-containers.md).

Design elements this commit produces:
- **NDArray-to-Tensor naming convention**: Establishes `Tensor` as the canonical name for the DLPack-backed n-dimensional array container, aligning with `torch.Tensor` and `DLTensor` naming.
- **`TVM_FFI_BUILD_DOCS` environment variable**: New convention for gating heavy optional imports (torch) during documentation builds.
- **`Module.main` attribute access** (replaces `Module.entry_func` property): Simplifies `Module.__call__` to delegate to `self.main` directly, removing the `__new__` override and cached `_entry` field.

## Usage Examples

**C++ -- creating and using a Tensor (renamed from NDArray)**:
```cpp
#include <tvm/ffi/container/tensor.h>

ffi::Shape shape = {1, 2, 3};
DLDataType dtype = {kDLFloat, 32, 1};
DLDevice device = {kDLCPU, 0};
ffi::Tensor tensor = ffi::Tensor::FromNDAlloc(CPUNDAlloc(), shape, dtype, device);
// DLPack round-trip
DLManagedTensorVersioned* dlpack = tensor.ToDLPackVersioned();
ffi::Tensor tensor2 = ffi::Tensor::FromDLPackVersioned(dlpack);
```

**Python -- using the renamed Tensor class**:
```python
import numpy as np
import tvm_ffi

x = tvm_ffi.from_dlpack(np.arange(10, dtype="int32"))
assert isinstance(x, tvm_ffi.Tensor)  # was tvm_ffi.NDArray
assert x.shape == (10,)
```
