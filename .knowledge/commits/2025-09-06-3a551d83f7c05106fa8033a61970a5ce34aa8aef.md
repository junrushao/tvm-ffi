# Rename NDArray to Tensor across the entire codebase

## TL;DR
- Renames `NDArray`/`NDArrayObj` to `Tensor`/`TensorObj` across all C++ headers, source files, Python bindings, Cython code, docs, examples, and tests.
- Renames all C API symbols from `TVMFFI*NDArray*` to `TVMFFI*Tensor*` (functions, type index enum, inline accessors).
- Renames the type key from `"ffi.NDArray"` to `"ffi.Tensor"` and the type index enum from `kTVMFFINDArray` to `kTVMFFITensor` (still value 70).
- Renames files: `ndarray.h` -> `tensor.h`, `ndarray.cc` -> `tensor.cc`, `ndarray.pxi` -> `tensor.pxi`, `ndarray.py` -> `tensor.py`, `test_ndarray.cc` -> `test_tensor.cc`, `test_ndarray.py` -> `test_tensor.py`.
- Renames the structural equal/hash parameter `skip_ndarray_content` to `skip_tensor_content`.
- Simplifies `Module.__call__` to call `self.main(*args)` directly, removing the `_entry` cache and `entry_func` property.
- Bumps package version from `0.1.0a7` to `0.1.0a8`.
- Minor docs infra changes: adds `TVM_FFI_BUILD_DOCS` env var guard around torch import, adds `clean` target to docs Makefile, adds `**/generated/*.rst` to docs `.gitignore`.

## Key Exports

**Renames (C++ classes)**:
- `NDArrayObj` -> `TensorObj` (in `include/tvm/ffi/container/tensor.h`)
- `NDArray` -> `Tensor` (ObjectRef wrapper in `include/tvm/ffi/container/tensor.h`)
- `details::NDArrayObjFromNDAlloc<T>` -> `details::TensorObjFromNDAlloc<T>`
- `details::NDArrayObjFromDLPack<T>` -> `details::TensorObjFromDLPack<T>`

**Renames (C API functions)**:

- `TVMFFINDArrayToDLPackVersioned` -> `TVMFFITensorToDLPackVersioned`
- `TVMFFINDArrayGetDLTensorPtr` -> `TVMFFITensorGetDLTensorPtr`

**Renames (C API enum)**:
- `kTVMFFINDArray` -> `kTVMFFITensor` (value remains 70)

**Renames (type key)**:
- `StaticTypeKey::kTVMFFINDArray = "ffi.NDArray"` -> `StaticTypeKey::kTVMFFITensor = "ffi.Tensor"`

**Renames (Python/Cython)**:
- `NDArray` class -> `Tensor` class (in `tensor.pxi`, exported via `tvm_ffi.Tensor`)
- `_CLASS_NDARRAY` -> `_CLASS_TENSOR`
- `_set_class_ndarray` -> `_set_class_tensor`
- `make_ndarray_from_any` -> `make_tensor_from_any`

- `tvm_ffi.NDArray` -> `tvm_ffi.Tensor` in `__init__.py` and `__all__`
- Module `tvm_ffi.ndarray` -> `tvm_ffi.tensor`

**Renames (structural equal/hash)**:
- Parameter `skip_ndarray_content` -> `skip_tensor_content` in `StructuralEqual::Equal`, `StructuralEqual::GetFirstMismatch`, `StructuralHash::Hash`
- Internal field `skip_ndarray_content_` -> `skip_tensor_content_` in `StructEqualHandler` and `StructuralHashHandler`
- Method `CompareNDArray` -> `CompareTensor` in `StructEqualHandler`
- Method `HashNDArray` -> `HashTensor` in `StructuralHashHandler`

**Renames (files)**:
- `include/tvm/ffi/container/ndarray.h` -> `include/tvm/ffi/container/tensor.h`
- `src/ffi/ndarray.cc` -> `src/ffi/tensor.cc`
- `python/tvm_ffi/cython/ndarray.pxi` -> `python/tvm_ffi/cython/tensor.pxi`
- `python/tvm_ffi/ndarray.py` -> `python/tvm_ffi/tensor.py`
- `tests/cpp/test_ndarray.cc` -> `tests/cpp/test_tensor.cc`
- `tests/python/test_ndarray.py` -> `tests/python/test_tensor.py`

**Module simplification**:
- Removes `Module.__new__` (which set `entry_name` and `_entry = None`)
- Removes `Module.entry_func` property (which cached `self.get_function("main")`)
- Adds class-level `entry_name = "main"` constant
- Changes `Module.__call__` from using the `_entry` cache to directly calling `self.main(*args)`

## Impact
- **API**: All public C++ types renamed (`NDArray` -> `Tensor`, `NDArrayObj` -> `TensorObj`). All public C API function names renamed. Python public API renames `tvm_ffi.NDArray` -> `tvm_ffi.Tensor`, module `tvm_ffi.ndarray` -> `tvm_ffi.tensor`. The structural equal/hash functions rename their `skip_ndarray_content` parameter to `skip_tensor_content`. The type key changes from `"ffi.NDArray"` to `"ffi.Tensor"`, affecting `register_object` and type dispatch.
- **ABI**: Breaking. C API symbol names change (e.g., `TVMFFINDArrayFromDLPack` -> `TVMFFITensorFromDLPack`). Type key string changes from `"ffi.NDArray"` to `"ffi.Tensor"`. Enum name changes (though the numeric value 70 is preserved). Any downstream code compiled against the old symbols will fail to link.
- **Behavioral**: Functionally equivalent. The rename is purely cosmetic -- no logic changes to the tensor/ndarray implementation itself. The `Module.__call__` simplification removes the entry function cache but achieves the same result via `self.main` attribute access.
- **Flags/config**: New `TVM_FFI_BUILD_DOCS` environment variable (set in `docs/conf.py`) suppresses torch import during doc builds.
- **Version**: Package version bumped from `0.1.0a7` to `0.1.0a8`.

## Design Elements

Design elements this commit **consumes**:

- **Object system** (`.knowledge/designs/object-system.md`): `TensorObj` (formerly `NDArrayObj`) inherits from `Object` + `DLTensor`, using the multi-inheritance layout pattern where DLTensor fields follow the TVMFFIObject header. Uses `TVM_FFI_DECLARE_STATIC_OBJECT_INFO` and `TVM_FFI_DEFINE_OBJECT_REF_METHODS`.
- **C ABI** (`.knowledge/designs/c-abi.md`): The Tensor type index `kTVMFFITensor = 70` occupies the same slot as the former `kTVMFFINDArray`. The cell-after-header layout for DLTensor access (`TVMFFITensorGetDLTensorPtr`) is unchanged.
- **Type traits** (`.knowledge/designs/type-traits.md`): `TypeTraits<DLTensor*>::TryCastFromAnyView` dispatches on `kTVMFFITensor` (formerly `kTVMFFINDArray`) to extract `DLTensor*` from the object header.
- **Cython bindings** (`.knowledge/designs/0014-python-bindings.md`): The `make_arg`/`make_ret` dispatch tables and tensor construction helpers follow the established patterns, just with new names.
- **Structural equal/hash** (`.knowledge/designs/0010-structural-equal-hash.md`): Tensor comparison and hashing follows the same pattern as before, just with renamed types and parameters.

Design elements this commit **produces**:

- **`Tensor` as the canonical name**: Establishes `Tensor`/`TensorObj` as the canonical name for the managed n-dimensional array type across the entire codebase, replacing the previous `NDArray`/`NDArrayObj`. The motivation is alignment with `torch.Tensor` and `DLTensor` naming conventions that are dominant in the ML ecosystem.
- **`"ffi.Tensor"` type key**: The registered type key is now `"ffi.Tensor"`, which is the string used for cross-language type dispatch and `register_object`. The former key `"ffi.NDArray"` is no longer valid.
- **Simplified Module entry dispatch**: `Module.__call__` now delegates directly to `self.main` (attribute lookup on the module), removing the cached `_entry` property. This is cleaner and relies on the module's `__getattr__` mechanism for function resolution.

## Usage Examples

### Creating a Tensor in C++
```cpp
#include <tvm/ffi/container/tensor.h>

struct CPUNDAlloc {
  void AllocData(DLTensor* tensor) { tensor->data = malloc(GetDataSize(*tensor)); }
  void FreeData(DLTensor* tensor) { free(tensor->data); }
};

ffi::Shape shape = {1, 2, 3};
DLDataType dtype = {kDLFloat, 32, 1};
DLDevice device = {kDLCPU, 0};
ffi::Tensor tensor = ffi::Tensor::FromNDAlloc(CPUNDAlloc(), shape, dtype, device);
```

### DLPack conversion in C++
```cpp
DLManagedTensorVersioned* dlpack = tensor.ToDLPackVersioned();
ffi::Tensor tensor2 = ffi::Tensor::FromDLPackVersioned(dlpack);
```

### Python Tensor usage
```python
import tvm_ffi
import numpy as np

x = tvm_ffi.from_dlpack(np.zeros((2, 3), dtype="float32"))
assert isinstance(x, tvm_ffi.Tensor)
assert x.shape == (2, 3)
```

### Structural comparison with skip_tensor_content
```cpp
bool equal = StructuralEqual::Equal(lhs, rhs, /*map_free_vars=*/false,
                                    /*skip_tensor_content=*/true);
```
