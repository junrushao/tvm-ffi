# Rename NDArray to Tensor across entire FFI stack (C ABI, C++, Python, Cython)
## TL;DR
- Renames `NDArray` to `Tensor` at every layer: C ABI enum, C API functions, C++ classes/headers, Python module/class, Cython bindings, tests, and docs. Motivated by alignment with `torch.Tensor` and `DLTensor` naming conventions in the ML ecosystem.
- All file renames: `ndarray.h` -> `tensor.h`, `ndarray.cc` -> `tensor.cc`, `ndarray.py` -> `tensor.py`, `ndarray.pxi` -> `tensor.pxi`, `test_ndarray.cc` -> `test_tensor.cc`, `test_ndarray.py` -> `test_tensor.py`.
- Secondary: simplifies `Module.__call__` to use `self.main` directly (removing `entry_func` property and `__new__` override); guards torch import behind `TVM_FFI_BUILD_DOCS` env var in Cython.

## Impact
- API: **ABI-breaking** symbol rename. All C API function names changed (`TVMFFINDArray*` -> `TVMFFITensor*`). All C++ header includes must change (`container/ndarray.h` -> `container/tensor.h`). Python public API changes `tvm_ffi.NDArray` -> `tvm_ffi.Tensor`. The C++ `StructuralEqual::Equal` and `StructuralHash::Hash` parameter `skip_ndarray_content` renamed to `skip_tensor_content` (keyword-argument callers break). No backward compatibility aliases provided.
- Behavioral: None -- pure rename with no semantic changes. Type index numeric value (70) is preserved.
- Flags/config: `TVM_FFI_BUILD_DOCS` environment variable added to suppress torch import during doc builds (secondary change in `function.pxi`).
- Data formats/schemas: The type key string changes from `"ffi.NDArray"` to `"ffi.Tensor"` in `StaticTypeKey`. Any serialized data referencing `"ffi.NDArray"` as a type key would need updating.

- **C ABI type index enum** (`.knowledge/designs/0001-c-abi.md`) -- `kTVMFFITensor` occupies slot 70 in the static object range.
- **Type traits** (`.knowledge/designs/0006-type-traits.md`) -- `TypeTraits<DLTensor*>` references `kTVMFFITensor` for conversion.
- **Structural equality/hashing** (`.knowledge/designs/0009-structural-equal-hash.md`) -- Parameter rename from `skip_ndarray_content` to `skip_tensor_content`.
- **Container suite** (`.knowledge/designs/0007-containers.md`) -- `Tensor` is part of the container suite.
- **Python bindings** (`.knowledge/designs/0012-python-bindings.md`) -- Cython `make_ret`/`make_args` dispatch on the type index.

Design elements this commit produces:
- None new -- this is a pure rename. The `Tensor` name replaces `NDArray` everywhere as the canonical name for the managed DLTensor wrapper.

## Usage Examples

Before (C++):
```cpp
#include <tvm/ffi/container/ndarray.h>
NDArray arr = NDArray::FromDLPack(managed, 8, true);
```

After (C++):
```cpp
#include <tvm/ffi/container/tensor.h>
Tensor tensor = Tensor::FromDLPack(managed, 8, true);
```

Before (Python):
```python
from tvm_ffi import NDArray, from_dlpack
arr = from_dlpack(numpy_array)  # returns NDArray
```

After (Python):
```python
from tvm_ffi import Tensor, from_dlpack
tensor = from_dlpack(numpy_array)  # returns Tensor
```
