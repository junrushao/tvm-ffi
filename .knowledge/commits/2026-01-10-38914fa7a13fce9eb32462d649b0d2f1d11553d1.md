# Add TypeStr support for Any and AnyView rvalue references in reflection Init
## TL;DR
- Adds `Type2Str<Any&&>` and `Type2Str<AnyView&&>` specializations so rvalue-reference constructors can be registered via `reflection::init<Any>()` and `reflection::init<AnyView>()`
- Adds forward declaration of `class Any` in `type_traits.h` to resolve include-order issues
- Tests verify that `ObjectDef<T>().def(init<Any>())` and `def(init<AnyView>())` work correctly for constructors accepting type-erased values

## Key Exports
```python
# New Type2Str specializations (enables reflection::init<Any>() and reflection::init<AnyView>()):
# Type2Str<Any&&>.v() -> "Any"
# Type2Str<AnyView&&>.v() -> "AnyView"
# Interacts with: reflection::init<T>(), ObjectDef<T>.def(init<Args...>())
```

## Impact
- API: none (additive specializations)
- Behavioral: fixes inability to register constructors taking `Any` or `AnyView` via reflection
- Flags/config: none
- Data formats/schemas: none

## Usage Examples
```cpp
struct TestObjWithAny : public Object {
  Any value;
  explicit TestObjWithAny(Any value) : value(std::move(value)) {}
  TVM_FFI_DECLARE_OBJECT_INFO_FINAL("test.TestObjWithAny", TestObjWithAny, Object);
};
TVM_FFI_STATIC_INIT_BLOCK() {
  reflection::ObjectDef<TestObjWithAny>()
    .def(reflection::init<Any>())
    .def_ro("value", &TestObjWithAny::value);
}
```
