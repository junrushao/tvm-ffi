# Rename TVMFFISafeCallType parameter from `self` to `handle`

## TL;DR
- Renames the first parameter of the `TVMFFISafeCallType` function pointer typedef from `self` to `handle` in both the Doxygen comment and the C declaration in `include/tvm/ffi/c_api.h`.
- This is a documentation-and-naming-only change; it does not alter the ABI, binary layout, or any runtime behavior. The function pointer signature remains `int (*)(void*, const TVMFFIAny*, int32_t, TVMFFIAny*)`.

## Key Exports
None. The `TVMFFISafeCallType` typedef is unchanged at the binary level. Only the formal parameter name in the declaration and the `\param` Doxygen tag are updated.

## Impact
- API: No change. The function pointer type is identical; only the parameter name visible in the header differs.
- ABI: No change. Parameter names in C typedefs have no effect on the ABI.
- Behavioral: No runtime behavior change.
- Documentation: The Doxygen `\param` tag for the first argument of `TVMFFISafeCallType` now reads `handle` instead of `self`. This aligns the documentation with the intended semantics: the first `void*` argument is an opaque handle to external state (not necessarily a C++ `this` pointer or a Python `self`). In particular, `TVMFFISafeCallType` is used in library module loading (`LibraryModuleObj::GetFunction`) where `nullptr` is passed as the handle, and in `TVMFFIFunctionCreate` where the handle is an arbitrary resource pointer. The name `handle` better reflects this general purpose.

## Design Elements
Design elements this commit consumes:
- `TVMFFISafeCallType` -- the C calling convention for type-erased safe function calls, established in the root commit.

Design elements this commit produces:
- **Naming convention for safe call handle** -- Establishes `handle` (rather than `self`) as the canonical parameter name for the first `void*` argument of `TVMFFISafeCallType`. This clarifies that the parameter is a generic opaque handle, not necessarily tied to object-oriented "self" semantics. The commit message notes the goal of stabilizing names in preparation for bringing module support into the FFI layer.

## Usage Examples
No usage change. The typedef is consumed identically before and after:
```c
// Before: parameter was named "self" in the header
typedef int (*TVMFFISafeCallType)(void* self, const TVMFFIAny* args, int32_t num_args,
                                  TVMFFIAny* result);

// After: parameter is named "handle"
typedef int (*TVMFFISafeCallType)(void* handle, const TVMFFIAny* args, int32_t num_args,
                                  TVMFFIAny* result);
```
