# Rename TVMFFISafeCallType first-parameter from `self` to `handle` in c_api.h

## TL;DR

- Renames the first parameter of `TVMFFISafeCallType` from `self` to `handle` in `include/tvm/ffi/c_api.h` (both the Doxygen comment and the typedef).
- Motivation: stabilize module-related naming to prepare for bringing the module system into the FFI layer; `handle` is the preferred term in the C ABI vocabulary.
- No ABI or behavioral change — this is a pure doc-comment + parameter-name rename in a C typedef.

| Old name | New name | Location |
|----------|----------|----------|
| `void* self` (1st param of `TVMFFISafeCallType`) | `void* handle` | `include/tvm/ffi/c_api.h` line ~278 |
| `\param self` (Doxygen) | `\param handle` (Doxygen) | `include/tvm/ffi/c_api.h` line ~254 |

## Key Exports

```python
# TVMFFISafeCallType — C function pointer typedef (stable C ABI boundary)
# Old signature:
#   typedef int (*TVMFFISafeCallType)(void* self, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result);
# New signature:
TVMFFISafeCallType = Callable[
    [void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result], int32_t
]
# Invariant: first arg is an opaque pointer to the owning FunctionObj; caller must not dereference it.
# Interacts with: FunctionObj::safe_call field (0004-function-system), TVMFFIFunctionCreate (c_api.h)
# Note: parameter name change only — binary ABI is identical.
```

## Impact

- API: Doc-level only. The C typedef parameter name change does not affect compiled ABI. Callers implementing `TVMFFISafeCallType`-compatible functions that named the first parameter `self` in their own C code are unaffected.
- Behavioral: None.
- Flags/config: None.
- Data formats/schemas: None.
