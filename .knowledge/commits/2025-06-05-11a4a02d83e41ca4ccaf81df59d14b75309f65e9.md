# Rename TVMFFISafeCallType parameter from 'self' to 'handle' for naming consistency
## TL;DR
- Renames the first parameter of `TVMFFISafeCallType` from `self` to `handle` in both the Doxygen comment and the typedef signature in `include/tvm/ffi/c_api.h`.
- This is a documentation/naming-only change with zero functional impact -- the parameter name in a C function pointer typedef has no effect on ABI or compiled code.
- Aligns the naming with the "library module" terminology mentioned in the commit message, preparing for a future where `TVMFFISafeCallType` is used more broadly beyond `FunctionObj` (e.g., by opaque module handles).

## Impact
- API: none -- the C ABI is unchanged. `TVMFFISafeCallType` retains the same signature `int(*)(void*, const TVMFFIAny*, int32_t, TVMFFIAny*)`. Parameter names in typedefs are not part of the ABI.
- Flags/config: none
- Data formats/schemas: none

**Note on naming inconsistency**: After this commit, `TVMFFISafeCallType` uses `handle` while `TVMFFIFunctionCreate` (line 603) still uses `void* self` for its first parameter and `void (*deleter)(void* self)` for its deleter. The `TVMFFIObject.deleter` field (line 268) also uses `void* self`. This creates a mild naming inconsistency within the same header -- the rename was targeted at the typedef only, not all uses of `self` in the C API.

## Design Elements
Design elements this commit **consumes**:
- **C ABI Layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): The change touches `TVMFFISafeCallType`, the core C function pointer type for cross-language function calls.
- **Safe call ABI boundary** ([`.knowledge/ADRs/0005-safe-call-abi-boundary.md`](../ADRs/0005-safe-call-abi-boundary.md)): The renamed parameter is the opaque context pointer passed through the safe call convention.

Design elements this commit **produces**:
- None. This is a pure naming/documentation change. No new design elements are introduced.

**Semantic signal**: The rename from `self` (which implies an object-oriented "this pointer" tied to `FunctionObj`) to `handle` (which is more generic, implying any opaque context) suggests a design direction where `TVMFFISafeCallType` may be reused for non-function contexts, such as the "library module" system mentioned in the commit message.
