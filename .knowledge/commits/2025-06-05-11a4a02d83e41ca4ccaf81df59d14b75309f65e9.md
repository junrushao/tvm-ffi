# Rename TVMFFISafeCallType first parameter from self to handle for module generalization
## TL;DR
- Renames the first parameter of `TVMFFISafeCallType` from `self` to `handle` in both the Doxygen comment and the typedef signature in `c_api.h`.
- Motivated by a design direction to generalize `TVMFFISafeCallType` beyond function objects to also serve as the calling convention for library modules.
- Not ABI-breaking: C parameter names do not affect binary compatibility.

| Symbol | Old | New |
|--------|-----|-----|
| `TVMFFISafeCallType` 1st param name | `self` | `handle` |

## Key Exports
**Renames**:

| Location | Old signature | New signature |
|----------|--------------|---------------|
| `c_api.h` `TVMFFISafeCallType` typedef | `int (*)(void* self, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result)` | `int (*)(void* handle, const TVMFFIAny* args, int32_t num_args, TVMFFIAny* result)` |

Note: callers such as `TVMFFIFunctionCreate`, `ExternCFunctionObjImpl`, and `Function::FromExternC` still use `self` as their own parameter name for the opaque pointer. Only the typedef's parameter name was updated.

## Impact
- API: None -- parameter names in C typedefs are not part of the ABI. No callers need updating.
- Behavioral: None -- no semantic change.
- Flags/config: None.
- Data formats/schemas: None.
