# Refactor map/array containers: extract MapBaseObj, remove InplaceArrayBase, add clear()

## TL;DR
- Extracts map internals into a new base class hierarchy (`MapBaseObj` / `DenseMapBaseObj` / `SmallMapBaseObj`) in `map_base.h`, decoupling the map implementation from `MapObj`'s FFI type index so future map subclasses can share the same hash-map machinery.
- Removes `InplaceArrayBase` CRTP template from `container_details.h`; `ArrayObj` now directly computes its inplace data pointer via `reinterpret_cast<char*>(p.get()) + sizeof(ArrayObj)`.
- Adds `clear()` method to `MapBaseObj` and `DenseMapBaseObj`, and templatizes `Empty`, `CreateFromRange`, `InsertMaybeReHash`, `CopyFrom` on `MapObjType` to support polymorphic map subtypes.

## Key Exports

**Types/Classes:**

| Name | Role | Key change |
|------|------|-----------|
| `MapBaseObj` (`map_base.h`) | New abstract base for all map objects (no FFI type index) | Extracted from `MapObj`; holds `data_`, `size_`, `slots_`, `data_deleter_`, iterators, and all public map operations (`size`, `count`, `at`, `find`, `erase`, `clear`, `begin`, `end`) |
| `DenseMapBaseObj` (`map_base.h`) | Dense hash-map implementation (renamed from `DenseMapObj`) | Now inherits `MapBaseObj` instead of `MapObj`; adds `clear()` method |
| `SmallMapBaseObj` (`map_base.h`) | Small linear-scan map (renamed from `SmallMapObj`) | Now inherits `MapBaseObj` instead of `MapObj`; adds `clear()` and templatized factory methods |
| `MapObj` (`map.h`) | Concrete FFI-registered map (type index `kTVMFFIMap`) | Now inherits `MapBaseObj` instead of `Object`; body is nearly empty (just type info + friend decl) |
| `ArrayObj` (`array.h`) | Array object | No longer inherits `InplaceArrayBase`; directly computes inplace data address |

**Removed types:**
- `InplaceArrayBase<ArrayType, ElemType>` (`container_details.h`) -- CRTP template for inplace-array address computation and element access. Functionality inlined or delegated to `SeqBaseObj`.

**New methods:**
- `MapBaseObj::clear()` -- dispatches to `SmallMapBaseObj::clear()` or `DenseMapBaseObj::clear()` via `TVM_FFI_DISPATCH_MAP`
- `DenseMapBaseObj::clear()` -- destroys all items, resets `size_` / `iter_list_head_` / `iter_list_tail_` without deallocating blocks
- `SmallMapBaseObj::clear()` -- destroys all items, resets `size_` without deallocating

**Templatized static methods (on `MapObjType`):**
```cpp
template <typename MapObjType> static ObjectPtr<Object> MapBaseObj::Empty();
template <typename MapObjType, typename IterType> static ObjectPtr<Object> MapBaseObj::CreateFromRange(IterType, IterType);
template <typename MapObjType> static void MapBaseObj::InsertMaybeReHash(KVType&&, ObjectPtr<Object>*);
template <typename MapObjType> static ObjectPtr<Object> MapBaseObj::CopyFrom(MapBaseObj*);
```
These allow `SmallMapBaseObj::Empty<MapObjType>()` to set the type index to `MapObjType::RuntimeTypeIndex()` via `p->header_.type_index = MapObjType::RuntimeTypeIndex()`, enabling future map subtypes that share `SmallMapBaseObj`/`DenseMapBaseObj` storage but have distinct FFI type indices.

**Macros (internal, `#undef`ed at end of `map_base.h`):**
- `TVM_FFI_DISPATCH_MAP(base, var, body)` -- dispatch to `SmallMapBaseObj*` or `DenseMapBaseObj*`
- `TVM_FFI_DISPATCH_MAP_CONST(base, var, body)` -- const version

## Impact
- API: `MapObj` is now a thin subclass of `MapBaseObj`. All public methods (`size`, `count`, `at`, `find`, `erase`, `begin`, `end`) still exist with same signatures but are now defined on `MapBaseObj`. `Map<K,V>` call sites updated to pass `<MapObj>` template argument (e.g., `MapObj::Empty<MapObj>()`, `MapObj::CreateFromRange<MapObj>(...)`).
- Behavioral: `clear()` is newly available on map objects. `ArrayObj` inplace data pointer calculation is unchanged in effect (same offset, now explicit `sizeof(ArrayObj)` instead of `InplaceArrayBase::AddressOf(0)`).
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Object system (`Object`, `ObjectRef`, `ObjectPtr`) -- `MapBaseObj` inherits from `Object`
- Inplace array allocation (`make_inplace_array_object`) -- still used for `SmallMapBaseObj::Empty` and `ArrayObj::Empty`
- `SeqBaseObj` base class for sequences -- `ArrayObj` now relies solely on this instead of dual-inheriting `InplaceArrayBase`
- Map layout tag invariant (MSB of `slots_` for SmallMap/DenseMap dispatch) -- [ADR 0012](../ADRs/0012-msb-tag-map-layout.md)
- Container data pointer convention -- [ADR 0006](../ADRs/0006-container-data-pointer.md)

Design elements this commit produces:
- **MapBaseObj hierarchy** -- new 3-class hierarchy (`MapBaseObj` -> `DenseMapBaseObj`/`SmallMapBaseObj`) that is transparent to the FFI type system (no own type index), enabling future map subtypes (e.g., `Dict`) to reuse the same hash-map machinery with distinct type indices
- **Templatized map factory pattern** -- `Empty<MapObjType>()` / `CreateFromRange<MapObjType>(...)` / `InsertMaybeReHash<MapObjType>(...)` / `CopyFrom<MapObjType>(...)` set `header_.type_index` to `MapObjType::RuntimeTypeIndex()`, decoupling storage layout from FFI type identity
- **`MapBaseObj::clear()` method** -- new public API for clearing map entries without destroying the map object

## Usage Examples
```cpp
// Creating a Map (unchanged API, but internals now route through MapBaseObj)
Map<String, int> m;
m.Set("key", 42);

// New: clear all entries
MapObj* obj = static_cast<MapObj*>(m.data_.get());
obj->clear();  // destroys all entries, size becomes 0

// Future extensibility: a new Dict type could reuse the same base
// class DictObj : public MapBaseObj { ... _type_index = kTVMFFIDict; };
// Map::Empty<DictObj>() would create a SmallMapBaseObj with DictObj's type index
```
