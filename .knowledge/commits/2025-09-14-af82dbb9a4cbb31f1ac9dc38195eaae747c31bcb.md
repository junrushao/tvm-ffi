# Fix: always set method_pyfunc.__name__ in reflection-based class attr registration
## TL;DR
- Fixed an indentation bug in `_add_class_attrs_by_reflection` where `method_pyfunc.__name__ = name` was incorrectly nested inside the `if doc is not None:` block, causing methods without docstrings to lack a `__name__` attribute.

## Key Exports
None

## Impact
- API: none
- Behavioral: Methods registered via reflection that lack docstrings now correctly have their `__name__` set. Previously, only methods with docstrings received a `__name__`, which could cause confusing tracebacks or repr output.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `_add_class_attrs_by_reflection` in `python/tvm_ffi/cython/function.pxi` — the Cython function that populates Python classes with methods discovered via C++ reflection metadata (see `.knowledge/design-records/0012-ffi-python-package.md`).
- Reflection method info struct (`FieldInfo.methods`) providing `name`, `doc`, and `flags` per method (see `.knowledge/design-records/0007-ffi-reflection.md`).

Design elements this commit produces: none

## Usage Examples
Before (bug): `method_pyfunc.__name__` only set when `doc is not None`:
```python
if doc is not None:
    method_pyfunc.__doc__ = doc
    method_pyfunc.__name__ = name  # skipped for methods without docstrings
```

After (fix): `method_pyfunc.__name__` always set:
```python
if doc is not None:
    method_pyfunc.__doc__ = doc
method_pyfunc.__name__ = name  # always executed
```
