# Fix: always set method_pyfunc.__name__ regardless of docstring presence

## TL;DR
- Fixed an indentation bug in `_add_class_attrs_by_reflection` where `method_pyfunc.__name__ = name` was nested inside the `if doc is not None` block, causing methods without docstrings to retain a generic `__name__` instead of the reflected method name.

## Key Exports
None

## Impact
- API: None -- no public API signature changes.
- Behavioral: Methods registered via reflection without a docstring now correctly have their `__name__` attribute set to the reflected method name. Previously, only methods with a docstring had `__name__` set. This affects introspection (e.g., `repr()`, `help()`, error messages referencing the method name).
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- **Reflection system** ([`.knowledge/designs/0009-reflection.md`](../designs/0009-reflection.md)): `TVMFFIMethodInfo.name` and `TVMFFIMethodInfo.doc` fields used by `_add_class_attrs_by_reflection` to populate Python method attributes.
- **Python package / Cython bindings** ([`.knowledge/designs/0014-python-package.md`](../designs/0014-python-package.md)): `_add_class_attrs_by_reflection` in `function.pxi` is the bridge that attaches reflected C++ methods to Python classes.

Design elements this commit produces:
- None -- this is a one-line indentation fix, no new design elements.

## Usage Examples
**Before** (buggy): methods without a docstring had a generic `__name__`:
```python
# C++ method registered without doc: refl::ObjectDef<T>().def("my_method", &T::MyMethod)
obj = MyClass(...)
print(obj.my_method.__name__)  # prints generic name, not "my_method"
```

**After** (fixed): all reflected methods get the correct `__name__`:
```python
obj = MyClass(...)
print(obj.my_method.__name__)  # prints "my_method"
```
