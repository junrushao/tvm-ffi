# fix: Always specify `method_pyfunc.__name__` for reflection-attached methods
## TL;DR
- Fixes a bug in `_add_class_attrs_by_reflection` (Cython, `function.pxi`) where `method_pyfunc.__name__` was only set when the method had a docstring. De-indents the `__name__` assignment so it always executes, regardless of whether `doc is not None`.

## Key Exports
None -- no new public API. This is a bugfix to existing reflection-based class decoration.

## Impact
- API: none
- ABI: none
- Behavioral: Previously, reflection-attached methods without a docstring would retain the generic wrapper function name (e.g., `_member_method_wrapper.<locals>.wrapper`) instead of the intended C++-reflected method name. After this fix, `method_pyfunc.__name__` is always set to the method's registered name from `TVMFFIMethodInfo`, which improves error messages, debugging output, `repr()`, and introspection for all reflection-attached methods.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Reflection system** (`.knowledge/designs/reflection.md`): The `TVMFFIMethodInfo` struct provides the method name, doc, and flags that `_add_class_attrs_by_reflection` uses to populate Python classes.
- **Python bindings -- reflection-based class decoration** (`.knowledge/designs/0014-python-bindings.md`): The `_add_class_attrs_by_reflection` function is the target of this fix. It reads `TVMFFITypeInfo` for a type index and auto-populates the Python class with properties (fields) and methods.

Design elements this commit produces:
- None. This is a one-line indentation bugfix with no new design elements.

## Usage Examples
None -- the fix is transparent. Any `c_class` or `register_object`-decorated class that has C++-reflected methods without docstrings will now correctly report the method name via `method.__name__`.
