# Fix method_pyfunc.__name__ always set in reflection class attr binding
## TL;DR
- `method_pyfunc.__name__ = name` was incorrectly nested inside `if doc is not None:`, causing method names to be unset when docstrings were absent.
- De-indented the assignment so `__name__` is always set for every reflected method.

## Key Exports
None -- no new API surface. Single-line indentation fix in existing Cython code.

## Impact
- API: none
- Behavioral: Methods registered via `_add_class_attrs_by_reflection` that lacked docstrings previously had missing/incorrect `__name__` attributes. After this fix, all reflected methods always have their `__name__` set to the C++ reflection name. This affects introspection, error messages, and any code that reads `method.__name__`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- Reflection system (`_add_class_attrs_by_reflection` in `python/tvm_ffi/cython/function.pxi`) -- see [0008-reflection](../design-records/0008-reflection.md) and [0012-python-bindings](../design-records/0012-python-bindings.md)
- The method-info loop pattern: iterates `info.methods`, creates `method_pyfunc` (either `staticmethod` or `_member_method_wrapper`), sets `__doc__` and `__name__`, then attaches to class via `setattr`.

Design elements this commit produces: None

## Usage Examples
Before (bug): `__name__` only set when docstring exists:
```python
# In _add_class_attrs_by_reflection loop:
if doc is not None:
    method_pyfunc.__doc__ = doc
    method_pyfunc.__name__ = name  # BUG: skipped when doc is None
```

After (fix): `__name__` always set:
```python
if doc is not None:
    method_pyfunc.__doc__ = doc
method_pyfunc.__name__ = name  # FIXED: always executes
```
