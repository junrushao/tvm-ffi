# Fix: always set method_pyfunc.__name__ in reflection attribute binding
## TL;DR
- Fixes a bug in `_add_class_attrs_by_reflection` where `method_pyfunc.__name__` was only set when a docstring was present; now it is always set regardless of whether `doc is not None`.

## Impact
- API: Methods added to Python classes via C++ reflection now always have their `__name__` attribute set correctly. Previously, methods without docstrings would have a generic or missing `__name__`, causing confusing error messages and repr output.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit **consumes**:
- **Reflection** (`.knowledge/designs/0006-reflection.md`): The `_add_class_attrs_by_reflection` function is the Python-side consumer of the C++ `ObjectDef<T>` reflection metadata, binding fields and methods onto Python classes by type index.
- **Python bindings** (`.knowledge/designs/0014-python-bindings.md`): The Cython `function.pxi` file implements the Python FFI dispatch layer.
