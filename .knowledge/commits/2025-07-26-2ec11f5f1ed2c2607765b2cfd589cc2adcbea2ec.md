# [FFI][REFACTOR] Enable custom s_hash/equal (#18165)

## TL;DR
- Adds a new `kTVMFFISEqHashKindCustomTreeNode = 6` enum value to `TVMFFISEqHashKind` in `c_api.h`, enabling object types to provide fully custom structural equality and hash implementations via TypeAttr callbacks instead of the default reflection-based field-by-field comparison.
- When an object type declares `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode`, the structural equal/hash handlers look up `__s_equal__` and `__s_hash__` type attributes (registered via `TypeAttrDef<T>`) and delegate to those functions.
- Restructures the `CompareObject` and `HashObject` methods so that FreeVar and DAGNode post-processing (equality map recording, free var counter, graph node counter) runs unconditionally after content comparison, regardless of whether the content comparison was field-based or custom. This fixes a subtle issue where custom comparison could bypass FreeVar/DAG bookkeeping.
- Fixes a bug in `TypeTable::RegisterTypeAttr` (`src/ffi/object.cc`) where re-registering an attribute to an existing column name silently created a duplicate column instead of reusing the existing one (the `else` branch was missing).
- Marks `TVarObj::name` as `SEqHashIgnore` since the restructured FreeVar logic now runs field comparison before FreeVar-specific handling; ignoring name prevents false mismatches when mapping free variables.
- Makes the reflection source files (`access_path.cc`, `structural_equal.cc`, `structural_hash.cc`) conditionally compiled behind the new `TVM_FFI_USE_EXTRA_CXX_API` CMake option, and moves their tests into a `tests/cpp/extra/` subdirectory that is only compiled when the option is enabled.
- Registers `__s_equal__` and `__s_hash__` columns at static init via `EnsureTypeAttrColumn` so the TypeAttrColumn lookups succeed even when no types have registered custom implementations.

## Key Exports

**New C ABI enum value:**
- `kTVMFFISEqHashKindCustomTreeNode = 6` (`include/tvm/ffi/c_api.h`) -- Declares that a type provides custom `__s_equal__` and `__s_hash__` functions through the TypeAttr system. Object types opt in by setting `static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode`.

**New CMake option:**
- `TVM_FFI_USE_EXTRA_CXX_API` (default `ON`) -- Controls whether `src/ffi/reflection/` source files (access_path, structural_equal, structural_hash) and their corresponding tests are compiled into the shared library.

**No new C++ classes or functions.** The custom equal/hash support is wired through the existing `TypeAttrDef<T>` and `TypeAttrColumn` infrastructure introduced in commit 162d600.

## Impact
- API: Types can now declare `kTVMFFISEqHashKindCustomTreeNode` and register `__s_equal__`/`__s_hash__` type attributes. This is a new opt-in capability; no existing API is changed.
- ABI: The `TVMFFISEqHashKind` enum gains value 6. This is a C ABI extension (additive). Existing enum values are unchanged.
- Behavioral: (1) FreeVar types now run field comparison (or custom comparison) before the FreeVar mapping logic, rather than short-circuiting. This changes the order of operations but preserves semantics since FreeVar fields were already compared for content equality. The `TVarObj::name` field is now explicitly marked `SEqHashIgnore` to compensate. (2) The `TypeTable::RegisterTypeAttr` bug fix means that registering multiple attributes under the same column name now correctly updates the same column instead of silently creating duplicates.
- Flags/config: New `TVM_FFI_USE_EXTRA_CXX_API` CMake option.

## Design Elements
Design elements this commit consumes:
- **`TypeAttrDef<T>`** (from commit 162d600) -- Builder for registering per-type attributes. Used here to register `__s_equal__` and `__s_hash__` methods on custom types.
- **`TypeAttrColumn`** (from commit 162d600) -- Runtime accessor for type attribute columns. Used by `StructEqualHandler` and `StructuralHashHandler` to look up custom functions by type index.
- **`EnsureTypeAttrColumn`** (from commit 162d600) -- Ensures a TypeAttr column exists in the system even if no types have registered values for it. Called at static init for `__s_equal__` and `__s_hash__`.
- **`ForEachFieldInfo` / `ForEachFieldInfoWithEarlyStop`** (`accessor.h`) -- Field iteration used for the default (non-custom) structural comparison path.
- **`AttachFieldFlag::SEqHashIgnore`** / **`AttachFieldFlag::SEqHashDef`** (from commit 9445fe7) -- Field flag annotations controlling structural equal/hash behavior per field.

Design elements this commit produces:
- **`kTVMFFISEqHashKindCustomTreeNode` protocol** -- A new structural equal/hash dispatch kind. When a type sets this kind, the equal/hash handlers delegate to `__s_equal__` and `__s_hash__` TypeAttr callbacks instead of walking fields reflectively. The callback signatures are:
  - `__s_equal__`: `bool(ObjectRef self, ObjectRef other, Function cmp)` where `cmp` is `TypedFunction<bool(AnyView lhs, AnyView rhs, bool def_region, AnyView field_name)>`
  - `__s_hash__`: `uint64_t(ObjectRef self, uint64_t type_key_hash, Function hash)` where `hash` is `TypedFunction<uint64_t(AnyView val, bool def_region)>`
  The `def_region` parameter enables free variable mapping within the callback, equivalent to the `SEqHashDef` field flag.
- **Restructured FreeVar/DAG post-processing** -- FreeVar equality-mapping and DAG graph-counter logic is now factored out of the field-comparison branch, running unconditionally after content comparison. This enables custom comparisons to participate correctly in FreeVar and DAG semantics without reimplementing the bookkeeping.
- **`TVM_FFI_USE_EXTRA_CXX_API` build flag** -- Allows disabling the extra C++ API (reflection access_path, structural_equal, structural_hash) for minimal builds.

## Usage Examples

### Defining a type with custom structural equal/hash
**Context**: A type where only certain fields participate in structural comparison, and the comparison logic is non-trivial (e.g., ignoring a comment field, treating params as a definition region).

```cpp
class TCustomFuncObj : public Object {
 public:
  Array<TVar> params;
  Array<ObjectRef> body;
  String comment;

  TCustomFuncObj(Array<TVar> params, Array<ObjectRef> body, String comment)
      : params(params), body(body), comment(comment) {}

  // Custom structural equality: compare params (def region) and body, skip comment
  bool SEqual(const TCustomFuncObj* other,
              ffi::TypedFunction<bool(AnyView, AnyView, bool, AnyView)> cmp) const {
    if (!cmp(params, other->params, true, "params")) return false;
    if (!cmp(body, other->body, false, "body")) return false;
    return true;
  }

  // Custom structural hash: hash params (def region) and body, skip comment
  uint64_t SHash(uint64_t type_key_hash,
                 ffi::TypedFunction<uint64_t(AnyView, bool)> hash) const {
    uint64_t h = type_key_hash;
    h = tvm::ffi::details::StableHashCombine(h, hash(params, true));
    h = tvm::ffi::details::StableHashCombine(h, hash(body, false));
    return h;
  }

  static void RegisterReflection() {
    namespace refl = tvm::ffi::reflection;
    // Standard field registration (still needed for runtime access/serialization)
    refl::ObjectDef<TCustomFuncObj>()
        .def_ro("params", &TCustomFuncObj::params)
        .def_ro("body", &TCustomFuncObj::body)
        .def_ro("comment", &TCustomFuncObj::comment);
    // Register custom structural equal/hash via TypeAttr
    refl::TypeAttrDef<TCustomFuncObj>()
        .def("__s_equal__", &TCustomFuncObj::SEqual)
        .def("__s_hash__", &TCustomFuncObj::SHash);
  }

  static constexpr const char* _type_key = "test.CustomFunc";
  static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode;
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(TCustomFuncObj, Object);
};
```
