# Enable custom structural equality/hash via TypeAttr and kTVMFFISEqHashKindCustomTreeNode

## TL;DR

- Adds a new `kTVMFFISEqHashKindCustomTreeNode = 6` enum variant to the C ABI, enabling object types to provide custom `__s_equal__` and `__s_hash__` functions registered through the `TypeAttrColumn` mechanism, instead of relying on automatic field-level structural comparison.
- Refactors `StructEqualHandler` and `StructuralHashHandler` to support the new custom dispatch path, while also fixing the interaction between `kTVMFFISEqHashKindFreeVar` and the DAG/graph node counter logic by moving free-var and DAG-node bookkeeping out of the main field-iteration branch into post-processing steps.
- Introduces `TVM_FFI_USE_EXTRA_CXX_API` CMake option (default ON), gating the structural equal/hash and access_path compilation units behind it, and moves the structural-equal/hash test file into `tests/cpp/extra/` to match.
- Fixes a bug in `TypeTable::RegisterTypeAttr` where `column_index` was not assigned in the `else` branch when a column already existed.

## Impact

- **API**: New public C ABI enum value `kTVMFFISEqHashKindCustomTreeNode = 6` in `TVMFFISEqHashKind`. Object types can opt into custom comparison by setting `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode` and registering `__s_equal__`/`__s_hash__` type attributes via `TypeAttrDef<T>`. This is a new extension point; no existing callers are broken.
- **Flags/config**: New CMake option `TVM_FFI_USE_EXTRA_CXX_API` (default ON) controls whether `src/ffi/reflection/structural_equal.cc`, `structural_hash.cc`, and `access_path.cc` are compiled into the shared library. When OFF, these files are excluded, producing a smaller core library. Tests in `tests/cpp/extra/` are similarly gated.
- **Data formats/schemas**: none

## Design Elements

Design elements this commit **consumes**:

- **C ABI layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Extends `TVMFFISEqHashKind` enum with a new variant. The enum is part of the stable C ABI and downstream language bindings (Rust, Cython) will need to pick up the new value.
- **Object system** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): Consumes `_type_s_eq_hash_kind` static constexpr field on `Object` subclasses, which was previously documented as a reserved extension point for structural comparison. This commit activates that extension point with a new enum value.
- **Reflection system** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): Uses `ForEachFieldInfo`/`ForEachFieldInfoWithEarlyStop` for the non-custom code path, and `TypeAttrColumn`/`TypeAttrDef` for the custom code path. `EnsureTypeAttrColumn` is called during static init to guarantee columns exist even before any type registers an attribute.
- **TypeAttrColumn** (no dedicated design doc): The `reflection::TypeAttrColumn` class wraps `TVMFFIGetTypeAttrColumn` to provide per-type-index attribute lookup. The `TypeAttrDef<Class>` builder registers function-valued attributes via `TVMFFITypeRegisterAttr`. This commit is a significant consumer of both.

Design elements this commit **produces**:

- **Custom structural equality/hash protocol**: A new protocol where types set `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode` and register `__s_equal__`/`__s_hash__` type attributes. The `__s_equal__` function receives `(self, other, cmp_callback)` where `cmp_callback(lhs, rhs, def_region, field_name)` delegates back to the handler. The `__s_hash__` function receives `(self, type_key_hash, hash_callback)` where `hash_callback(val, def_region)` delegates back. The `def_region` parameter controls whether free-variable mapping is enabled during recursive comparison/hashing.
- **Build modularity via `TVM_FFI_USE_EXTRA_CXX_API`**: The structural equal/hash and access_path sources can now be excluded from the core shared library, enabling downstream projects that only need the core FFI (object system, containers, packed functions) to produce a smaller binary.
- **Bug fix: `TypeTable::RegisterTypeAttr` `column_index` assignment** (`src/ffi/object.cc`): Previously, when a column already existed (the `else` branch), `column_index` remained 0 instead of being set to the existing column's index. This would cause all attribute registrations on pre-existing columns to silently corrupt column 0.

## Reflection

### Design docs to write

- **`.knowledge/designs/0009-structural-equal-hash.md`**: Should cover the full `TVMFFISEqHashKind` enum taxonomy, the reflection-based automatic field comparison path, the new custom `__s_equal__`/`__s_hash__` protocol, the `def_region` semantics for free-variable scoping, and the `AccessPath`-based mismatch reporting. This doc helps future commit mining for any changes to structural comparison, IR normalization, or type attribute dispatch.

- **`.knowledge/designs/0010-type-attr-columns.md`**: Should document the `TypeAttrColumn` storage model (per-type-index column arrays in `TypeTable`), the `TypeAttrDef<T>` registration builder, `EnsureTypeAttrColumn` for pre-creating columns, and the `TVMFFITypeRegisterAttr`/`TVMFFIGetTypeAttrColumn` C API. This is a cross-cutting mechanism used by structural equal/hash, serialization, and potentially dataclass features. Future commits touching type-level metadata dispatch would reference it.

### ADRs to write

- **`.knowledge/ADRs/0011-custom-sequal-shash-via-typeattr.md`**: Context: The reflection system handles most types via automatic field enumeration, but certain types (e.g., IR variables, types with semantic aliases) need custom comparison logic. Alternatives considered: (1) virtual method override (rejected: breaks C ABI, requires vtable); (2) per-type registered global functions (rejected: naming convention burden, no structured protocol); (3) TypeAttr-based dispatch (chosen: leverages existing `TypeAttrColumn` infrastructure, function signatures are documented in the C ABI enum, integrates with `def_region` free-variable scoping). Trade-off: adds indirection through packed function calls for custom types, slightly slower than direct C++ virtual dispatch, but maintains ABI stability.

### Design diagrams to draw

- **Mermaid flowchart: Structural equal/hash dispatch**. Should depict the branching logic in `StructEqualHandler::SEqualObj` and `StructuralHashHandler::SHashObj`: from `structural_eq_hash_kind` switch through `kTVMFFISEqHashKindTreeNode` (field enumeration), `kTVMFFISEqHashKindCustomTreeNode` (TypeAttr dispatch), `kTVMFFISEqHashKindFreeVar` (free-var mapping), `kTVMFFISEqHashKindDAGNode` (graph counter), `kTVMFFISEqHashKindConstTreeNode` (content hash only), and `kTVMFFISEqHashKindUniqueInstance` (pointer equality). Show how free-var and DAG bookkeeping are now post-processing steps applied after the main comparison/hash.

### Skill evolution (`/commit-ledger`)

- The procedure should note that when a commit introduces a new C ABI enum variant, the ledger should explicitly call out which downstream language bindings (Rust `c_api.rs`, Cython `base.pxi`) need updating, since ABI enum additions are a common source of cross-language desync. Consider adding a checklist item in Step 4 for "ABI surface changes: check language binding parity."
- Step 3.2 (Producers) could benefit from a sub-bullet specifically for "bug fixes that are incidental to the main feature." In this commit, the `column_index` bug fix in `object.cc` is a significant correctness fix but is not mentioned in the commit message. The procedure should prompt for silent fixes.
