# Add kTVMFFISEqHashKindCustomTreeNode for user-defined structural equal/hash via TypeAttr

## TL;DR
- Adds `kTVMFFISEqHashKindCustomTreeNode = 6` to the `TVMFFISEqHashKind` C ABI enum, enabling Object types to provide custom `__s_equal__` and `__s_hash__` implementations via `TypeAttrDef` rather than relying on reflection-driven field iteration.
- Refactors `StructEqualHandler` and `StructuralHashHandler` to dispatch to custom callbacks when `_type_s_eq_hash_kind == kTVMFFISEqHashKindCustomTreeNode`, and restructures `FreeVar`/`DAGNode` post-processing to run after both standard and custom comparison paths.
- Introduces `TVM_FFI_USE_EXTRA_CXX_API` CMake option that gates the reflection source files (`access_path.cc`, `structural_equal.cc`, `structural_hash.cc`) and a new `tests/cpp/extra/` directory for tests that depend on them.
- Fixes a bug in `TypeTable::RegisterTypeAttr` where an existing column was not reused (missing `else` branch), causing duplicate column creation.

## Impact
- API: New enum value `kTVMFFISEqHashKindCustomTreeNode = 6` added to `TVMFFISEqHashKind` in `c_api.h`. Additive change; existing callers unaffected.
- Behavioral: `FreeVar` handling in `StructEqualHandler` is restructured -- free-var content comparison now runs through the standard/custom field iteration path first, then the identity/mapping check runs after success. Previously, `FreeVar` skipped field comparison entirely and only checked `same_as`. This enables custom `__s_equal__` implementations to compare var content before the free-var mapping decision. Similarly, `DAGNode` graph-counter combination in hash is now applied after the field/custom hash, not inside the field loop.
- Behavioral: `TypeTable::RegisterTypeAttr` bugfix -- previously, registering a second attribute into an existing column would silently create a duplicate column instead of appending to the existing one.
- Flags/config: New CMake option `TVM_FFI_USE_EXTRA_CXX_API` (default `ON`) gates inclusion of reflection source files in the shared library build.
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFISEqHashKind` enum ([0001-ffi-c-abi](../design-records/0001-ffi-c-abi.md)) -- extended with value 6
- `TypeAttrDef<T>` and `TypeAttrColumn` (commit `162d6009`) -- used to register and dispatch `__s_equal__`/`__s_hash__` per-type functions
- `EnsureTypeAttrColumn` (commit `162d6009`) -- called at static init to pre-create columns
- `ForEachFieldInfoWithEarlyStop` / `ForEachFieldInfo` (reflection accessor) -- existing field iteration used for non-custom kinds
- `ffi::Function::FromTyped` ([0004-ffi-function-system](../design-records/0004-ffi-function-system.md)) -- wraps the lambda callback as a `Function`
- `AccessStep::ObjectField` ([0007-ffi-reflection](../design-records/0007-ffi-reflection.md)) -- mismatch path tracing
- `details::StableHashCombine` -- hash composition primitive

Design elements this commit produces:
- **`kTVMFFISEqHashKindCustomTreeNode`**: New dispatch kind enabling Object types to define custom structural equality/hashing logic via TypeAttr callbacks instead of reflection-driven field iteration.
- **`__s_equal__` / `__s_hash__` TypeAttr protocol**: Convention that types with `_type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode` must register `__s_equal__` and `__s_hash__` functions via `TypeAttrDef`. The functions receive a `cmp`/`hash` callback from the handler to recursively compare/hash sub-fields.
- **`TVM_FFI_USE_EXTRA_CXX_API` CMake option**: Build-time toggle for including reflection implementation files in the shared library.
- **`tests/cpp/extra/` directory**: Test directory gated by `TVM_FFI_USE_EXTRA_CXX_API` for tests depending on extra C++ APIs.

## Usage Examples

Defining a type with custom structural equal/hash (from test `TCustomFuncObj`):

```cpp
class TCustomFuncObj : public Object {
 public:
  Array<TVar> params;
  Array<ObjectRef> body;
  String comment;   // deliberately excluded from equality

  // Custom equality: compare params (def region) and body, skip comment
  bool SEqual(const TCustomFuncObj* other,
              TypedFunction<bool(AnyView, AnyView, bool, AnyView)> cmp) const {
    if (!cmp(params, other->params, /*def_region=*/true, "params")) return false;
    if (!cmp(body, other->body, /*def_region=*/false, "body")) return false;
    return true;
  }

  // Custom hash: hash params (def region) and body, skip comment
  uint64_t SHash(uint64_t type_key_hash,
                 TypedFunction<uint64_t(AnyView, bool)> hash) const {
    uint64_t h = type_key_hash;
    h = details::StableHashCombine(h, hash(params, /*def_region=*/true));
    h = details::StableHashCombine(h, hash(body, /*def_region=*/false));
    return h;
  }

  static void RegisterReflection() {
    refl::ObjectDef<TCustomFuncObj>()
        .def_ro("params", &TCustomFuncObj::params)
        .def_ro("body", &TCustomFuncObj::body)
        .def_ro("comment", &TCustomFuncObj::comment);
    // Register custom equal/hash via TypeAttr
    refl::TypeAttrDef<TCustomFuncObj>()
        .def("__s_equal__", &TCustomFuncObj::SEqual)
        .def("__s_hash__", &TCustomFuncObj::SHash);
  }

  static constexpr const char* _type_key = "test.CustomFunc";
  static constexpr TVMFFISEqHashKind _type_s_eq_hash_kind = kTVMFFISEqHashKindCustomTreeNode;
  TVM_FFI_DECLARE_FINAL_OBJECT_INFO(TCustomFuncObj, Object);
};
```
