# Suppress false-positive clang-tidy NewDeleteLeaks warning in unpack_call and force GC before module deletion in test_stl to workaround CI segfaults

## TL;DR
- Adds `// NOLINTNEXTLINE(clang-analyzer-cplusplus.NewDeleteLeaks)` comment at the closing brace of `unpack_call` in `include/tvm/ffi/function_details.h` to silence a false-positive clang-tidy warning introduced after PR #228.
- Adds `gc.collect()` + `del mod` at the end of `test_stl` in `tests/python/test_stl.py` to force CPython GC and deterministic module teardown, addressing a CI segfault that appeared when Python's GC left the loaded `Module` alive past interpreter shutdown.

- API: none
- Behavioral: `test_stl` now explicitly releases the loaded `Module` and collects garbage before returning; avoids non-deterministic segfaults during test teardown.

## Design Elements
Design elements this commit consumes:
- `0011-module-system`: Module lifetime invariant — "Module must outlive all objects whose deleters reside in the loaded `.so`". The `gc.collect(); del mod` pattern enforces this invariant explicitly before the test scope exits rather than relying on CPython reference-counting order.
- `0004-function-system`: `unpack_call` template in `function_details.h` is the unpacking adapter for typed callables into the packed calling convention.

Design elements this commit produces: None

## Usage Examples

Before (implicit GC ordering, prone to segfault):
```python
def test_stl() -> None:
    mod = tvm_ffi.load_module(output_lib_path)
    # ... assertions ...
    # mod is released by CPython refcount at function exit — order is non-deterministic
```

After (explicit GC + deletion):
```python
def test_stl() -> None:
    mod = tvm_ffi.load_module(output_lib_path)
    # ... assertions ...
    gc.collect()   # flush any cycles keeping mod alive
    del mod        # deterministic teardown before test returns
```
