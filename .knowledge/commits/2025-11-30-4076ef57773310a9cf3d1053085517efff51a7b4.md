# Workaround segfaults in test_stl via explicit GC and suppress clang-tidy false positive in unpack_call

## TL;DR
- Adds `gc.collect()` and `del mod` at the end of `test_stl` to work around intermittent segfaults observed in CI after PR #228. The segfaults appeared across multiple platforms (Linux x86_64, aarch64, macOS arm64) and were linked to module cleanup ordering.
- Adds a `// NOLINTNEXTLINE(clang-analyzer-cplusplus.NewDeleteLeaks)` suppression in `details::unpack_call` to silence a false-positive clang static analyzer warning about leaked memory in the packed return value path.

None

## Impact
- API: none
- Behavioral: `test_stl` now deterministically releases the loaded `Module` and triggers Python GC before test teardown, reducing the window for use-after-free during interpreter shutdown.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Module system** ([0011-module-system.md](../designs/0011-module-system.md)): `tvm_ffi.load_module` loads a `DSOLibrary`-backed `Module`; the segfault likely involves the Module destructor racing with Python GC during test cleanup.
- **Function system / unpack_call** ([0004-function-system.md](../designs/0004-function-system.md)): `details::unpack_call` is the core argument-unpacking template in `function_details.h`; the NOLINTNEXTLINE suppresses a false positive in the `*rv = R(...)` return path.
