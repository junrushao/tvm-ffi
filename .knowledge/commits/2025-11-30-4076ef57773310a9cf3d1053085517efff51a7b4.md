# Workaround CI segfaults in STL tests with explicit GC and suppress clang-tidy false positive
## TL;DR
- Adds `gc.collect()` and `del mod` at the end of `test_stl()` to work around segfaults appearing in CI after the STL support merge (PR #228). The explicit GC ensures the loaded module's shared library is unloaded before Python process teardown, avoiding use-after-free in atexit handlers.
- Adds a `NOLINTNEXTLINE(clang-analyzer-cplusplus.NewDeleteLeaks)` suppression in `function_details.h` to silence a false-positive clang static analyzer warning in `unpack_call`.

None (no new API surface).

## Impact
- API: None.
- Behavioral: Test cleanup order changed -- module object is now explicitly destroyed before test function returns, preventing segfaults caused by atexit-order-dependent library unloading.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Module system** ([0013-module-system.md](../designs/0013-module-system.md)): The `tvm_ffi.load_module` result holds a handle to a dynamically loaded `.so`. Python's garbage collection timing for this handle is non-deterministic, causing crashes when the library is unloaded during process teardown after FFI globals are already torn down.
- **Function packed calling** ([0004-function-system.md](../designs/0004-function-system.md)): The `unpack_call` template in `function_details.h` receives the clang-tidy suppression.

- None (workaround, not a new pattern).
