# Add Python stream context API for environment stream management
## TL;DR
- Adds `python/tvm_ffi/stream.py` with `StreamContext` (low-level `with`-based context manager wrapping `TVMFFIEnvSetStream`), `use_raw_stream(device, stream)` for raw stream handles, and `use_torch_stream(context)` for torch CUDA stream/graph contexts.
- Exposes `_env_set_current_stream` Cython wrapper in `base.pxi` that calls `TVMFFIEnvSetStream` and returns the previous stream handle for save/restore semantics.
- Adds comprehensive tests for nested stream contexts, torch stream integration, and torch CUDA graph integration.

## Impact
- API: New public API surface: `tvm_ffi.StreamContext`, `tvm_ffi.use_raw_stream`, `tvm_ffi.use_torch_stream` -- all exported from `tvm_ffi.__init__`.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit **consumes**:
- **C ABI / extra API** (`.knowledge/designs/0011-extra-api-tier.md`): Uses `TVMFFIEnvSetStream` and `TVMFFIEnvGetStream` from `c_env_api.h` for the thread-local stream context.
- **Thread-local stream context** (`.knowledge/ADRs/0020-thread-local-stream-context.md`): The ADR documents the thread-local stream design; this commit is the Python-side consumer that exposes it as a context manager.
- **Inline module compilation** (`.knowledge/designs/0017-inline-module-compilation.md`): Tests use `tvm_ffi.cpp.load_inline` to compile a C++ helper `check_stream` that verifies stream state from the C++ side.

Design elements this commit **produces**:
- **Python stream context management**: Establishes the save/restore pattern for environment streams via Python context managers. `StreamContext.__enter__` saves the previous stream and sets the new one; `__exit__` restores. `TorchStreamContext` composes torch's own context manager with the FFI stream context.
- Key invariant: stream context is nestable -- each `__enter__` saves the previous stream, and `__exit__` restores it, forming a stack discipline.
