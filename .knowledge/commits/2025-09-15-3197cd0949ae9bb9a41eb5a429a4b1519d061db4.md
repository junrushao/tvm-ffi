# Add Python-level stream context managers for FFI env stream

## TL;DR
- Introduces `StreamContext`, `TorchStreamContext`, `use_raw_stream()`, and `use_torch_stream()` in `python/tvm_ffi/stream.py`, providing Python `with`-statement context managers that save/restore the FFI thread-local device stream via `TVMFFIEnvSetStream`.
- Adds Cython wrapper `_env_set_current_stream` in `base.pxi` to expose the C `TVMFFIEnvSetStream` to Python, returning the previous stream handle for restore.
- Adds comprehensive tests (`tests/python/test_stream.py`) covering raw stream nesting, torch stream nesting, implicit current-stream capture, and CUDA graph integration.

## Design Elements
Design elements this commit consumes:
- **TVMFFIEnvSetStream / TVMFFIStreamHandle** (C ABI, `c_env_api.h`) -- the underlying C function that sets the per-thread, per-device stream in TLS. See [0001-c-abi.md](../designs/0001-c-abi.md) lines 358-365.
- **Device / device()** (`python/tvm_ffi/_tensor.py`) -- used to resolve device type and index for stream context. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **Cython `CHECK_CALL` macro** (`base.pxi`) -- standard error-checking wrapper for C ABI calls.

Design elements this commit produces:
- **StreamContext** -- Python-level save/restore context manager for the FFI thread-local stream. First explicit Python abstraction over `TVMFFIEnvSetStream` (previously only Cython `tvm_ffi_python_helpers.h` managed streams implicitly during packed function calls).
- **TorchStreamContext / use_torch_stream()** -- bridge between torch CUDA stream/graph contexts and FFI env stream, enabling explicit user control of stream propagation (complements the implicit propagation in `make_args`).
- **use_raw_stream()** -- lower-level API for non-torch stream handles.
- **_env_set_current_stream** (Cython) -- Python-callable wrapper for `TVMFFIEnvSetStream` returning the previous stream handle.

## Usage Examples

**Raw stream context nesting** (from `tests/python/test_stream.py`):
```python
import tvm_ffi

device = tvm_ffi.device("cuda:0")
stream_1 = 123456789  # raw stream handle
stream_2 = 987654321

with tvm_ffi.use_raw_stream(device, stream_1):
    # FFI env stream is now stream_1
    with tvm_ffi.use_raw_stream(device, stream_2):
        # FFI env stream is now stream_2
        pass
    # FFI env stream restored to stream_1
# FFI env stream restored to original
```

**Torch stream context** (from commit message):
```python
import torch
import tvm_ffi

stream = torch.cuda.Stream()
with tvm_ffi.use_torch_stream(torch.cuda.stream(stream)):
    # Both torch and FFI see `stream` as current
    pass

# CUDA graph capture:
graph = torch.cuda.CUDAGraph()
with tvm_ffi.use_torch_stream(torch.cuda.graph(graph)):
    pass

# Implicit current stream:
with torch.cuda.stream(stream):
    with tvm_ffi.use_torch_stream():
        # FFI picks up torch's current stream automatically
        pass
```
