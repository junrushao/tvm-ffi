# Add Python stream context wrappers for FFI environment stream management

## TL;DR
- Adds a new `python/tvm_ffi/stream.py` module with `StreamContext`, `TorchStreamContext`, `use_raw_stream()`, and `use_torch_stream()` -- Python context managers for setting the FFI thread-local stream via `TVMFFIEnvSetStream`/`TVMFFIEnvGetStream`.
- Exposes `core._env_set_current_stream()` in Cython `base.pxi` as the Python-callable bridge to `TVMFFIEnvSetStream`, returning the previous stream handle for save/restore semantics.
- Exports `StreamContext`, `use_raw_stream`, `use_torch_stream` from `tvm_ffi.__init__` and adds Sphinx autodoc entries in `docs/reference/python/index.rst`.

## Key Exports

**Classes:**

- `StreamContext(device: Device, stream: Union[int, c_void_p])` -- Context manager. On `__enter__`, calls `core._env_set_current_stream(device_type, device_id, stream)` and caches the returned previous stream. On `__exit__`, restores the previous stream. Fields: `device_type: int`, `device_id: int`, `stream: Union[int, c_void_p]`, `prev_stream: int` (set on enter).

- `TorchStreamContext(context: Optional[Any])` -- Context manager wrapping an optional `torch.cuda.stream(...)` or `torch.cuda.graph(...)` context. On `__enter__`, enters the torch context (if provided), reads `torch.cuda.current_stream()`, creates a `StreamContext` with the stream's device and `cuda_stream` handle, and enters it. On `__exit__`, exits both the FFI and torch contexts. Only defined when `torch` is importable.

**Functions:**

- `use_torch_stream(context: Optional[Any] = None) -> TorchStreamContext` -- Factory returning a `TorchStreamContext`. When `context=None`, captures the current torch CUDA stream. Raises `ImportError` if torch is unavailable.

- `use_raw_stream(device: Device, stream: Union[int, c_void_p]) -> StreamContext` -- Factory returning a `StreamContext`. Validates that `stream` is `int` or `c_void_p`.

- `core._env_set_current_stream(device_type: int, device_id: int, stream: uint64) -> uint64` -- Cython function in `base.pxi`. Calls `TVMFFIEnvSetStream(device_type, device_id, <void*>stream, &prev_stream)` and returns `prev_stream` as `uint64`. This is the only new Cython-level export.

## Impact
- API: New public API surface (`StreamContext`, `use_raw_stream`, `use_torch_stream`) added to `tvm_ffi` namespace. No existing API changed.
- ABI: None. No C/C++ changes. Only a new Cython wrapper around the existing `TVMFFIEnvSetStream` C API.
- Behavioral: None for existing code. New functionality only.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **`TVMFFIEnvSetStream` / `TVMFFIEnvGetStream` C APIs** (`.knowledge/designs/c-abi.md` > Extra C Env API > Stream Context APIs) -- The thread-local stream table management functions. `StreamContext` wraps `TVMFFIEnvSetStream` for save/restore.
- **`EnvContext` thread-local stream table** (`.knowledge/designs/0018-dlpack-fast-path.md` > EnvContext) -- The C++ `EnvContext` singleton with its 2D `vector<vector<void*>>` table, which these Python wrappers drive.
- **Cython `base.pxi` extern declarations** (`.knowledge/designs/0014-python-bindings.md` > Cython Layer) -- The existing `TVMFFIEnvSetStream` extern declaration in `base.pxi` (lines 241-245 before this commit) that the new `_env_set_current_stream` function calls.
- **`Device` class and `device()` factory** (`.knowledge/designs/0014-python-bindings.md`) -- Used to construct `Device` from string (e.g., `"cuda:0"`) in `StreamContext` and tests.
- **`tvm_ffi.cpp.load_inline`** (`.knowledge/designs/0017-inline-module-compilation.md`) -- Used in tests to compile inline C++ that calls `TVMFFIEnvGetStream` to verify stream state.

Design elements this commit produces:
- **Python stream context protocol** -- A save/restore pattern for the FFI thread-local stream, expressed as Python context managers (`with` statement). The pattern is: (1) on enter, call `_env_set_current_stream` to set new stream and save previous, (2) on exit, call `_env_set_current_stream` with saved stream to restore. Supports nesting.
- **Torch interop layer for streams** -- `TorchStreamContext` bridges torch's `torch.cuda.stream()` / `torch.cuda.graph()` context managers with the FFI stream table, enabling mixed torch+FFI workloads to share the same CUDA stream. The optional `context` parameter allows capturing the current torch stream without an explicit torch context manager.

## Usage Examples

Setting a raw stream handle on a device:
```python
import tvm_ffi

device = tvm_ffi.device("cuda:0")
stream_handle = 0x12345678  # raw cudaStream_t as int
with tvm_ffi.use_raw_stream(device, stream_handle):
    # FFI env stream for cuda:0 is now stream_handle
    # Any FFI function call here sees this stream via TVMFFIEnvGetStream
    pass
# Stream is restored to previous value
```

Forwarding a torch CUDA stream to FFI:
```python
import torch
import tvm_ffi

stream = torch.cuda.Stream()
with tvm_ffi.use_torch_stream(torch.cuda.stream(stream)):
    # Both torch and FFI see `stream` as the current CUDA stream
    pass

# Using current torch stream (no explicit context):
with torch.cuda.stream(stream):
    with tvm_ffi.use_torch_stream():
        # FFI picks up whatever torch.cuda.current_stream() returns
        pass
```

Nesting (verified by `test_raw_stream`):
```python
device = tvm_ffi.device("cuda:0")
with tvm_ffi.use_raw_stream(device, stream_1):
    # stream_1 active
    with tvm_ffi.use_raw_stream(device, stream_2):
        # stream_2 active
    # stream_1 restored
# original stream restored
```
