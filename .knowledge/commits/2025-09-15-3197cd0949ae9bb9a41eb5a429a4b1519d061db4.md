# Add Python stream context API (StreamContext, use_raw_stream, use_torch_stream)

## TL;DR
- Adds `python/tvm_ffi/stream.py` with `StreamContext`, `TorchStreamContext`, `use_raw_stream`, and `use_torch_stream` as the Python-facing stream context API.
- Adds `_env_set_current_stream` Cython function in `base.pxi` as the bridge from Python `int` stream handles to `TVMFFIEnvSetStream` (C ABI).
- Exports all three public symbols (`StreamContext`, `use_raw_stream`, `use_torch_stream`) from `tvm_ffi.__init__`.

## Key Exports

# ─── python/tvm_ffi/stream.py ────────────────────────────────────────────────

class StreamContext:
    """Python context manager for managing the FFI environment stream.
    On __enter__: saves the previous stream handle and sets the new one.
    On __exit__: restores the saved previous stream handle.
    """
    device_type: int   # DLPack device type int (e.g. 2 = CUDA)
    device_id: int
    stream: int        # Stream handle as Python int (uint64 cast of void*)
    prev_stream: int   # Captured on __enter__; undefined before __enter__ is called

    def __enter__(self) -> None:
        # Calls core._env_set_current_stream(device_type, device_id, stream)
        # Stores return value in self.prev_stream
        # Invariant: __exit__ must only be called after __enter__
        # Interacts with: _env_set_current_stream → TVMFFIEnvSetStream (c_env_api.h)

    def __exit__(self, *args) -> None:
        # Restores prev_stream via core._env_set_current_stream
        # Invariant: this restores the thread-local stream table entry for (device_type, device_id)


class TorchStreamContext:
    """Wraps a torch stream/graph context and a StreamContext together.
    Conditionally defined (only if torch is importable).
    On __enter__: enters the torch context first (if provided), then reads
    torch.cuda.current_stream() and sets FFI stream accordingly.
    On __exit__: exits the torch context, then restores the FFI stream.
    """
    torch_context: Optional[Any]   # torch.cuda.stream() or torch.cuda.graph() context
    ffi_context: StreamContext     # Created lazily in __enter__

    # Invariant: ffi_context is created at __enter__ time, not __init__ time
    # (so the stream binding reflects the torch context state at entry)
    # Interacts with: torch.cuda.current_stream(), StreamContext


def use_torch_stream(context: Optional[Any] = None) -> TorchStreamContext:
    """Factory: create a TorchStreamContext from a torch stream/graph context.
    If context is None, captures the torch current stream at __enter__ time.
    Raises ImportError if torch is not installed.
    # Interacts with: TorchStreamContext.__enter__ → torch.cuda.current_stream()
    """


def use_raw_stream(device: core.Device, stream: Union[int, c_void_p]) -> StreamContext:
    """Factory: create a StreamContext from a device and a raw stream handle.
    Only accepts int or c_void_p; raises ValueError for torch.cuda.Stream or similar.
    # Interacts with: StreamContext, Device.dlpack_device_type(), Device.index
    """

def _env_set_current_stream(device_type: int, device_id: int, stream: int) -> int:
    """Cython bridge: set the current FFI stream for (device_type, device_id).
    Returns the previous stream handle as a Python int (uint64 cast of void*).
    Calls TVMFFIEnvSetStream from c_env_api.h with CHECK_CALL error propagation.
    # Interacts with: TVMFFIEnvSetStream (opt_out_original_stream used for prev)
    # Invariant: stream=0 (NULL) is valid — resets the entry to no stream

## Impact
- API: New public symbols `StreamContext`, `use_raw_stream`, `use_torch_stream` added to `tvm_ffi` top-level namespace. No existing APIs changed.
- Behavioral: FFI environment stream can now be managed from Python using context managers, enabling CUDA stream-aware kernel dispatch from Python code.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TVMFFIEnvSetStream` / `TVMFFIEnvGetStream` (C ABI) — see `.knowledge/design-records/0012-env-api.md`; the RAII swap via `opt_out_original_stream` is the mechanism that `StreamContext.__enter__`/`__exit__` relies on.
- `Device.dlpack_device_type()` / `Device.index` — Python `Device` API from design record `.knowledge/design-records/0013-python-package.md`.
- `tvm_ffi.cpp.load_inline` — used in tests to compile inline C++ that calls `TVMFFIEnvGetStream` for assertion; see `.knowledge/design-records/0015-load-inline.md`.

Design elements this commit produces:
- `StreamContext` — Python RAII context manager over the FFI thread-local stream table.
- `TorchStreamContext` — torch-aware wrapper that synchronizes torch stream context with FFI stream context.
- `use_raw_stream` / `use_torch_stream` — public factories (2 entry points for raw vs. torch handles).
- `_env_set_current_stream` — Cython bridge function (internal; accessible via `tvm_ffi.core`).

## Usage Examples

**End-to-end trace: C++ definition → Python `with` statement**

The test in `tests/python/test_stream.py` shows the full cross-layer pattern:

```python
# C++ side (via load_inline): reads the FFI stream and asserts equality
mod = tvm_ffi.cpp.load_inline(
    name="check_stream",
    cpp_sources="""
    void check_stream(int device_type, int device_id, uint64_t stream) {
        uint64_t cur = reinterpret_cast<uint64_t>(TVMFFIEnvGetStream(device_type, device_id));
        TVM_FFI_ICHECK_EQ(cur, stream);
    }
    """,
    functions=["check_stream"],
)

# Python side: set stream via use_raw_stream, verify via C++ function
device = tvm_ffi.device("cuda:0")
stream_1, stream_2 = 123456789, 987654321
with tvm_ffi.use_raw_stream(device, stream_1):
    mod.check_stream(device.dlpack_device_type(), device.index, stream_1)
    with tvm_ffi.use_raw_stream(device, stream_2):
        mod.check_stream(device.dlpack_device_type(), device.index, stream_2)
    mod.check_stream(device.dlpack_device_type(), device.index, stream_1)  # restored

# Torch stream variant: synchronizes both torch and FFI contexts
with tvm_ffi.use_torch_stream(torch.cuda.stream(stream_1)):
    # torch.cuda.current_stream() == stream_1 AND FFI stream == stream_1.cuda_stream
    mod.check_stream(device_type, device_id, stream_1.cuda_stream)
```
