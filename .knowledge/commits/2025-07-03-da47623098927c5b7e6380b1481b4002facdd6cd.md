# [REFACTOR][FFI] Phase out old VisitAttrs mechanism (#18106)

## TL;DR
- Removes the `_type_has_method_visit_attrs` static constexpr field from the `Object` base class in `include/tvm/ffi/object.h`.
- This is the final cleanup step in a multi-commit migration from the legacy `VisitAttrs` attribute-visiting mechanism to the new FFI reflection system (`ObjectDef<T>` / `TVMFFIFieldInfo`).

## Key Exports
None. The removed field was a compile-time boolean constant (`static constexpr const bool _type_has_method_visit_attrs = true`) used by legacy plug-in code to detect whether a type supported the old `VisitAttrs` pattern. No runtime symbol, ABI surface, or public API is affected.

## Impact
- API: The `_type_has_method_visit_attrs` static field is no longer available on `Object` or its subclasses. Any downstream code that reads this field via `T::_type_has_method_visit_attrs` will fail to compile. This is intentional -- all such code was already migrated in predecessor commits.
- ABI: No change. The field was `static constexpr` (compile-time only) and never contributed to object layout or exported symbols.
- Behavioral: No runtime behavior change.

## Design Elements
Design elements this commit consumes:
- `Object` base class (`include/tvm/ffi/object.h`) -- the root of the TVM object hierarchy, which previously carried `_type_has_method_visit_attrs` as a plug-in extension point.
- The new reflection system (`ObjectDef<T>`, `TVMFFIFieldInfo`, `TVMFFIRegisterTypeField`) -- the replacement mechanism that made `VisitAttrs` obsolete. Introduced in prior commits (#18062, #18065, #18083, #18091, #18095, #18096).

Design elements this commit produces:
- None. This is purely a removal of a deprecated extension point. The `Object` class retains the sibling fields `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce` (at the time of this commit), which serve the structural equality and structural hash plug-in protocols respectively.

## Usage Examples
No usage change. Code that previously relied on `_type_has_method_visit_attrs` should use the new reflection system instead:

```cpp
// Old pattern (removed):
// if constexpr (T::_type_has_method_visit_attrs) { node->VisitAttrs(&v); }

// New pattern (use FFI reflection):
// Fields are registered via ObjectDef<T> and accessed through TVMFFIFieldInfo.
```
