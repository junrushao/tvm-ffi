# Remove _type_has_method_visit_attrs flag from Object base class

## TL;DR
- Removes the single line `static constexpr const bool _type_has_method_visit_attrs = true;` from `Object` base class in `include/tvm/ffi/object.h`.
- This capability flag was used by the old `VisitAttrs` reflection mechanism, which is being phased out in favor of the new `ReflectionDef`/`RegisterReflection` system.
- After this commit, `_type_has_method_visit_attrs` has no remaining references anywhere in the codebase; the flag is fully retired.

## Key Exports

None

## Impact
- API: The `_type_has_method_visit_attrs` static constexpr field is removed from `Object`. Any subclass that relied on inheriting or checking `Object::_type_has_method_visit_attrs` at compile time will now fail to compile. In practice, this flag was only declared in `Object` (base) and never checked within this repo's post-migration state.
- Behavioral: None — no runtime behavior changes. The flag was a compile-time marker only.
- Flags/config: None
- Data formats/schemas: None

## Design Elements
Design elements this commit consumes:
- `0002-object-system` — the `Object` base class capability flags (`_type_has_method_*`). This commit mutates that design element by removing one of the three flags.

Design elements this commit produces:
- `0002-object-system` — updated: `_type_has_method_visit_attrs` is no longer part of the `Object` metaclass protocol. The remaining capability flags are `_type_has_method_sequal_reduce` and `_type_has_method_shash_reduce`.
