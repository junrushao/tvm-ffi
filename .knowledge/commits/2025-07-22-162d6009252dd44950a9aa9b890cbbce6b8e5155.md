# Introduce TypeAttr for extensible per-type attribute registration and rename TypeExtraInfo to TypeMetadata
## TL;DR
- Introduces `TypeAttr`, a new column-oriented per-type attribute system (`TVMFFITypeAttrColumn`, `TypeAttrDef<T>`, `TypeAttrColumn`) that allows registering arbitrary named attributes (functions or constants) on types, stored in column arrays indexed by `type_index` for O(1) lookup.
- Renames `TVMFFITypeExtraInfo` to `TVMFFITypeMetadata` and `TVMFFITypeRegisterExtraInfo` to `TVMFFITypeRegisterMetadata` throughout the C ABI, C++ implementation, and reflection consumers (structural equal/hash), improving naming clarity.
- Adds two new C API functions (`TVMFFITypeRegisterAttr`, `TVMFFIGetTypeAttrColumn`) and corresponding C++ wrappers (`TypeAttrDef<T>`, `TypeAttrColumn`, `EnsureTypeAttrColumn`).

## Impact
- API: **Breaking rename** -- `TVMFFITypeExtraInfo` renamed to `TVMFFITypeMetadata`; `TVMFFITypeRegisterExtraInfo` renamed to `TVMFFITypeRegisterMetadata`; `TVMFFITypeInfo::extra_info` field renamed to `TVMFFITypeInfo::metadata`. All downstream callers that directly reference these C ABI symbols must update. Within this repo, `structural_equal.cc`, `structural_hash.cc`, and `object.cc` are updated.
- Flags/config: none.
- Data formats/schemas: New C struct `TVMFFITypeAttrColumn { data, size }` added to `c_api.h`. New C API functions `TVMFFITypeRegisterAttr` and `TVMFFIGetTypeAttrColumn` added to the ABI surface.
- Behavioral: The `TypeAttr` system enables extensible metadata registration that was not previously possible. For example, structural equality/hashing behavior could be registered as a type attribute rather than being hardcoded in `TVMFFITypeMetadata`. The test demonstrates registering both a method (`test.GetValue`) and a constant (`test.size`) as type attributes on `TIntObj`.

## Design Elements
Design elements this commit **consumes**:

- **Reflection registration flow** ([`.knowledge/designs/0006-reflection.md`](../designs/0006-reflection.md)): `TypeAttrDef<T>` follows the same `TVM_FFI_STATIC_INIT_BLOCK` pattern as `ObjectDef<T>`, deducing `type_index` from `Class::RuntimeTypeIndex()` and `type_key` from `Class::_type_key`. It reuses `ReflectionDefBase::GetMethod<Class>` for wrapping member function pointers into `Function` objects.
- **TypeTable singleton** ([`.knowledge/designs/0003-object-system.md`](../designs/0003-object-system.md)): `TypeAttr` storage is added directly to the `TypeTable` as new member fields (`type_attr_columns_`, `type_attr_name_to_column_index_`). Column data is stored in `std::vector<Any>` and exposed via the C ABI through `TVMFFITypeAttrColumn`.
- **C ABI layer** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md)): Two new `extern "C"` functions are added (`TVMFFITypeRegisterAttr`, `TVMFFIGetTypeAttrColumn`). The `TVMFFIGetTypeAttrColumn` function returns a raw pointer to the column struct (not wrapped in safe_call), following the pattern of `TVMFFIGetTypeInfo`.
- **Any/AnyView system** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): `TypeAttrColumn::operator[]` reinterprets `const TVMFFIAny*` as `const AnyView*` for zero-copy access, relying on the layout compatibility invariant (`sizeof(AnyView) == sizeof(TVMFFIAny)`).

Design elements this commit **produces**:

- **TypeAttr column storage model**: A new column-oriented storage pattern where each named attribute has its own `std::vector<Any>` indexed by `type_index`. This is fundamentally different from the row-oriented `TVMFFITypeMetadata` (which stores a fixed set of fields per type). The column model allows unbounded extensibility without changing the `TVMFFITypeMetadata` struct.
- **TypeAttrDef<T> registration builder** (`include/tvm/ffi/reflection/registry.h`): New class template for registering type attributes. Provides `def(name, func)` for function-valued attributes and `attr(name, value)` for constant-valued attributes. Registered during static initialization.
- **TypeAttrColumn accessor** (`include/tvm/ffi/reflection/accessor.h`): Read-path class for looking up a named attribute column and indexing into it by `type_index`. Returns `AnyView()` (null) for unregistered types, enabling sparse storage.
- **EnsureTypeAttrColumn utility** (`include/tvm/ffi/reflection/registry.h`): Ensures a named column exists in the system by registering with `type_index = kTVMFFINone`, which triggers column creation but skips value insertion. This is useful for pre-declaring columns before type registrations run.
- **TVMFFITypeExtraInfo -> TVMFFITypeMetadata rename**: A naming clarification that distinguishes fixed per-type metadata (creator, total_size, doc, structural_eq_hash_kind) from extensible per-type attributes.

## Key Implementations

**Column storage in TypeTable** (`src/ffi/object.cc`):

The `TypeAttrColumnData` struct extends `TVMFFITypeAttrColumn` and owns a `std::vector<Any> data_`. When a new attribute is registered via `RegisterTypeAttr`, the column is resized to `max(current_size, type_index + 1)`, with unset slots initialized to `Any(nullptr)`. The `TVMFFITypeAttrColumn::data` pointer and `size` are updated after each resize, keeping the C-visible struct synchronized with the underlying vector. This design means the column pointer returned by `TVMFFIGetTypeAttrColumn` remains valid but the `data` pointer within it may change on subsequent registrations -- this is safe because registration only happens during static initialization (single-threaded).

Key invariants:
- Column name -> column index mapping is stored in `Map<String, int64_t> type_attr_name_to_column_index_`, consistent with the pattern used for `type_key2index_`.
- Duplicate registration guard: `column->data_[type_index] != nullptr` throws `RuntimeError`, preventing silent overwrites.
- `type_index == kTVMFFINone` is a sentinel that creates the column but inserts no value (the `EnsureTypeAttrColumn` mechanism).

**TypeAttrDef<T> builder** (`include/tvm/ffi/reflection/registry.h`):

The `def(name, func)` method wraps the function using `GetMethod<Class>`, which generates a fully qualified name (`type_key + "." + name`) and handles member-function-to-Function conversion. It then converts the result to `TVMFFIAny` via `AnyView(ffi_func).CopyToTVMFFIAny()` before calling the C API. The `attr(name, value)` method does the same conversion for arbitrary values.

**TypeAttrColumn reader** (`include/tvm/ffi/reflection/accessor.h`):

The `operator[](int32_t type_index)` performs bounds checking (`tindex >= column_->size` returns null `AnyView`), then reinterprets the `TVMFFIAny*` data array as `AnyView*`. This avoids any copy -- the returned `AnyView` is a lightweight non-owning view into the column's `Any` storage.

**Structural equal/hash update** (`src/ffi/reflection/structural_equal.cc`, `structural_hash.cc`):

Mechanical rename: `type_info->extra_info` -> `type_info->metadata` and `type_info->extra_info->structural_eq_hash_kind` -> `type_info->metadata->structural_eq_hash_kind`. No behavioral change.

**Extension points**:
- New attribute columns can be added by any code that calls `TypeAttrDef<T>().attr("new_attr", value)` or `TypeAttrDef<T>().def("new_attr", func)` during static initialization.
- The column model could support future use cases such as per-type serialization hints, custom equality/hashing dispatch, or per-type code generation metadata.
- `EnsureTypeAttrColumn` provides forward-declaration of columns, allowing read-side code to obtain the column pointer before any type has registered values.

- **`.knowledge/designs/0006-reflection.md` update**: The existing reflection design doc needs to be updated to document the TypeAttr subsystem. It should add:
  - A new subsection "TypeAttr: Extensible Per-Type Attributes" covering the column storage model, `TypeAttrDef<T>`, `TypeAttrColumn`, and `EnsureTypeAttrColumn`.
  - The `TVMFFITypeExtraInfo` -> `TVMFFITypeMetadata` rename (all references to `extra_info` should become `metadata`).
  - Update the registration flow diagram to include `TypeAttrDef` as a parallel registration path alongside `ObjectDef`.
  - Why this helps: future commits adding new type attributes will reference this section to understand the registration and lookup patterns.

- **`.knowledge/designs/0001-c-abi.md` update**: The C ABI design doc references `TVMFFITypeExtraInfo` and `TVMFFITypeRegisterExtraInfo` throughout. It should be updated to:
  - Rename all `TVMFFITypeExtraInfo` references to `TVMFFITypeMetadata` and `TVMFFITypeRegisterExtraInfo` to `TVMFFITypeRegisterMetadata`.
  - Add `TVMFFITypeAttrColumn` struct documentation.
  - Add `TVMFFITypeRegisterAttr` and `TVMFFIGetTypeAttrColumn` to the extern "C" API surface table.
  - Why this helps: any commit touching the C ABI will reference this doc for the authoritative API surface listing.

### ADRs to write
- **`.knowledge/ADRs/0011-column-vs-row-type-metadata.md`**: This commit introduces a fundamental architectural choice: column-oriented type attribute storage alongside the existing row-oriented `TVMFFITypeMetadata`. The ADR should document:
  - Context: Fixed metadata fields (creator, total_size, doc, structural_eq_hash_kind) work well as a struct per type, but extensible attributes (like custom equality, serialization hints) need a different model.
  - Alternatives: (1) Keep adding fields to `TVMFFITypeMetadata` -- breaks ABI for each addition; (2) Use a per-type `Map<String, Any>` -- O(log n) lookup per access; (3) Column arrays indexed by type_index -- O(1) lookup, sparse, ABI-stable.
  - Trade-off: Column storage wastes some space (vectors sized to max type_index) but provides cache-friendly sequential access when iterating over all types for a given attribute.

### Design diagrams to draw
- **Mermaid diagram: TypeAttr registration and lookup flow**: Should depict the relationship between `TypeAttrDef<T>` -> `TVMFFITypeRegisterAttr` -> `TypeTable::RegisterTypeAttr` -> `TypeAttrColumnData`, and the read path `TypeAttrColumn` -> `TVMFFIGetTypeAttrColumn` -> `TypeTable::GetTypeAttrColumn` -> `TVMFFITypeAttrColumn`. This would complement the existing registration flow diagram in the reflection design doc.
