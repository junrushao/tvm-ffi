# Rename TVMFFIEnvSetTensorAllocator → TVMFFIEnvSetDLPackManagedTensorAllocator and introduce TVMFFIEnvTensorAlloc + Tensor::FromEnvAlloc

## TL;DR
- **Rename**: `TVMFFIEnvSetTensorAllocator` → `TVMFFIEnvSetDLPackManagedTensorAllocator` and `TVMFFIEnvGetTensorAllocator` → `TVMFFIEnvGetDLPackManagedTensorAllocator` across C++, Rust, and Python layers to align with DLPack standard naming.
- **New C ABI function**: `TVMFFIEnvTensorAlloc(DLTensor* prototype, TVMFFIObjectHandle* out)` — a higher-level allocator entry point that wraps the DLPack callback internally in `libtvm_ffi`, producing a `ffi::Tensor` directly (type `kTVMFFITensor`) without exposing `DLManagedTensorVersioned**` to callers.
- **New C++ static method**: `Tensor::FromEnvAlloc(env_alloc, shape, dtype, device)` replaces `Tensor::FromDLPackAlloc(allocator, shape, dtype, device)`; the new form takes a simple `int(*)(DLTensor*, TVMFFIObjectHandle*)` function pointer instead of a full `DLPackManagedTensorAllocator`, eliminating the error-context callback pattern from call sites.

### Rename Mapping Table

| Old name | New name | Layer |
|---|---|---|
| `TVMFFIEnvSetTensorAllocator` | `TVMFFIEnvSetDLPackManagedTensorAllocator` | C ABI, `c_env_api.h` |
| `TVMFFIEnvGetTensorAllocator` | `TVMFFIEnvGetDLPackManagedTensorAllocator` | C ABI, `c_env_api.h` |
| `TVMFFIEnvSetTensorAllocator` | `TVMFFIEnvSetDLPackManagedTensorAllocator` | Rust, `tvm-ffi-sys/src/c_env_api.rs` |
| `TVMFFIEnvGetTensorAllocator` | `TVMFFIEnvGetDLPackManagedTensorAllocator` | Rust, `tvm-ffi-sys/src/c_env_api.rs` |
| `TVMFFIEnvSetTensorAllocator` | `TVMFFIEnvSetDLPackManagedTensorAllocator` | C++ (Cython helper), `tvm_ffi_python_helpers.h` |
| `Tensor::FromDLPackAlloc` | `Tensor::FromEnvAlloc` | C++ `tensor.h` |
| `TestDLPackManagedTensorAllocator` | `TestEnvTensorAllocator` (different signature too) | C++ test `test_tensor.cc` |

## Impact
- API: **Breaking rename** for C, C++, Rust, and Python callers of `TVMFFIEnvSetTensorAllocator`/`TVMFFIEnvGetTensorAllocator`. All call sites in this repo are updated in the same commit. External callers must migrate. `Tensor::FromDLPackAlloc` is removed; callers must switch to `Tensor::FromEnvAlloc(TVMFFIEnvTensorAlloc, ...)`.
- Behavioral: `TVMFFIEnvTensorAlloc` now owns metadata allocation inside `libtvm_ffi`, fixing module-unloading-order problems where the TensorObj could be freed by a module-owned allocator before `libtvm_ffi` had processed it. The old `Tensor::FromDLPackAlloc` allocated shape/strides inline arrays from within the caller's address space.
- Flags/config: none
- Data formats/schemas: none

## Usage Examples

**Context**: C++ caller allocating a tensor from the env allocator (e.g., DSL compiler producing output tensor from `torch.empty` via Python-registered allocator).

```cpp
// Before (removed):
// ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
//     TVMFFIEnvGetTensorAllocator(), shape, dtype, device);

// After:
#include <tvm/ffi/container/tensor.h>
#include <tvm/ffi/extra/c_env_api.h>

ffi::Tensor y = ffi::Tensor::FromEnvAlloc(
    TVMFFIEnvTensorAlloc,   // function pointer; resolves to env allocator
    ffi::Shape({x.size(0)}),
    f32_dtype,
    x.device()
);
// Invariant: TVMFFIEnvSetDLPackManagedTensorAllocator must have been called prior
// (typically done by TVMFFIPyCallManager during Python → C++ dispatch)
```

**Context**: C++ test registering a custom allocator and verifying round-trip through new API.

```cpp
// Set allocator
auto old = TVMFFIEnvGetDLPackManagedTensorAllocator();
TVMFFIEnvSetDLPackManagedTensorAllocator(TestDLPackManagedTensorAllocator, 0, nullptr);

// Allocate via new C ABI (TVMFFIEnvTensorAlloc absorbs DLPack error-ctx complexity)
Tensor tensor = Tensor::FromEnvAlloc(TVMFFIEnvTensorAlloc, {1, 2, 3},
                                     DLDataType({kDLFloat, 32, 1}), DLDevice({kDLCPU, 0}));
EXPECT_EQ(tensor.shape().size(), 3);

// Restore
TVMFFIEnvSetDLPackManagedTensorAllocator(old, 0, nullptr);
```
