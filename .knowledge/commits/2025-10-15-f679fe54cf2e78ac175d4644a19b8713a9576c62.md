# Rename TVMFFIEnvTensorAllocator APIs to DLPack-aligned names and introduce TVMFFIEnvTensorAlloc

## TL;DR
- Renames `TVMFFIEnvSetTensorAllocator` -> `TVMFFIEnvSetDLPackManagedTensorAllocator` and `TVMFFIEnvGetTensorAllocator` -> `TVMFFIEnvGetDLPackManagedTensorAllocator` across C++, Python/Cython, and Rust to align with DLPack naming conventions.
- Introduces `TVMFFIEnvTensorAlloc` as a new C ABI function that allocates a `ffi::Tensor` (not a raw `DLManagedTensorVersioned*`) from the env allocator, moving DLPack-to-TensorObj wrapping logic from the header into `libtvm_ffi` to avoid module unloading order issues.
- Replaces `Tensor::FromDLPackAlloc` with `Tensor::FromEnvAlloc`, which takes a function pointer matching `TVMFFIEnvTensorAlloc`'s signature (`int (*)(DLTensor*, TVMFFIObjectHandle*)`) instead of the raw `DLPackManagedTensorAllocator` callback.
- Version bump: 0.1.0b18 -> 0.1.0b19; torch test dependency excluded on Windows.

### Rename Mapping

| Before | After | Layer |
|--------|-------|-------|
| `TVMFFIEnvSetTensorAllocator` | `TVMFFIEnvSetDLPackManagedTensorAllocator` | C ABI, Cython, Rust |
| `TVMFFIEnvGetTensorAllocator` | `TVMFFIEnvGetDLPackManagedTensorAllocator` | C ABI, Rust |
| `Tensor::FromDLPackAlloc` | `Tensor::FromEnvAlloc` | C++ header |

## Key Exports

```python
# C ABI (include/tvm/ffi/extra/c_env_api.h)

# Renamed: TVMFFIEnvSetTensorAllocator -> TVMFFIEnvSetDLPackManagedTensorAllocator
def TVMFFIEnvSetDLPackManagedTensorAllocator(
    allocator: DLPackManagedTensorAllocator,
    write_to_global_context: int,
    opt_out_original_allocator: Ptr[DLPackManagedTensorAllocator]
) -> int: ...
    # Interacts with: EnvContext::SetDLPackManagedTensorAllocator (TLS)
    # Invariant: write_to_global_context=1 also sets the process-wide fallback

# Renamed: TVMFFIEnvGetTensorAllocator -> TVMFFIEnvGetDLPackManagedTensorAllocator
def TVMFFIEnvGetDLPackManagedTensorAllocator() -> DLPackManagedTensorAllocator: ...
    # Interacts with: EnvContext (TLS first, global fallback)

# NEW: TVMFFIEnvTensorAlloc — allocates a Tensor object, not a raw DLManagedTensorVersioned
def TVMFFIEnvTensorAlloc(prototype: Ptr[DLTensor], out: Ptr[TVMFFIObjectHandle]) -> int: ...
    # Interacts with: TVMFFIEnvGetDLPackManagedTensorAllocator (reads TLS allocator)
    # Interacts with: TensorObjFromDLPack<DLManagedTensorVersioned> (wrapping happens inside libtvm_ffi)
    # Invariant: allocator must have been set via TVMFFIEnvSetDLPackManagedTensorAllocator, else returns -1
    # Invariant: out receives an owned TVMFFIObject* of type kTVMFFITensor
    # Extension: future implementations may support allocators beyond DLPackManagedTensorAllocator

# C++ API (include/tvm/ffi/container/tensor.h)

class Tensor(ObjectRef):
    @staticmethod
    def FromEnvAlloc(
        env_alloc: Callable[[Ptr[DLTensor], Ptr[TVMFFIObjectHandle]], int],
        shape: ShapeView, dtype: DLDataType, device: DLDevice
    ) -> Tensor: ...
        # Renamed from: Tensor::FromDLPackAlloc
        # Interacts with: TVMFFIEnvTensorAlloc (canonical env_alloc argument)
        # Interacts with: TVM_FFI_CHECK_SAFE_CALL (error propagation)
        # Interacts with: ObjectUnsafe::ObjectPtrFromOwned (converts raw handle to ObjectPtr)
        # Invariant: env_alloc must follow the (DLTensor*, TVMFFIObjectHandle*) -> int signature
        # Extension: any function matching the signature can be used, not just TVMFFIEnvTensorAlloc

# Rust FFI (rust/tvm-ffi-sys/src/c_env_api.rs)
# TVMFFIEnvSetTensorAllocator -> TVMFFIEnvSetDLPackManagedTensorAllocator
# TVMFFIEnvGetTensorAllocator -> TVMFFIEnvGetDLPackManagedTensorAllocator
# (TVMFFIEnvTensorAlloc not yet declared in Rust bindings)
```

## Impact
- API: **Breaking** — three C ABI symbols renamed (`TVMFFIEnvSetTensorAllocator`, `TVMFFIEnvGetTensorAllocator`, `Tensor::FromDLPackAlloc`). All callers in C++, Cython, Rust, and inline C++ tests must update. One new C ABI symbol added (`TVMFFIEnvTensorAlloc`).
- Behavioral: `Tensor::FromEnvAlloc` no longer performs DLPack-to-TensorObj wrapping in the caller's module. The wrapping now happens inside `libtvm_ffi` via `TVMFFIEnvTensorAlloc`, avoiding module unloading order issues where destructors ran after the calling shared library was unloaded. Error handling for null allocator moved from the header to `TVMFFIEnvTensorAlloc` in `env_context.cc`, using `TVMFFIErrorSetRaisedFromCStr` instead of `TVM_FFI_THROW`.
- Flags/config: torch test dependency now excluded on Windows (`sys_platform != 'win32'`).
- Data formats/schemas: none.

## Design Elements
Design elements this commit consumes:
- **EnvContext** (TLS singleton, `0014-stream-and-env-context`): reads the TLS DLPack allocator inside `TVMFFIEnvTensorAlloc`.
- **DLPackManagedTensorAllocator** callback type (`0001-c-abi`, `0014-stream-and-env-context`): the underlying allocator invoked by `TVMFFIEnvTensorAlloc`.
- **TensorObjFromDLPack** template (`0007-containers`, `0012-inplace-tail-allocation-for-tensor-metadata`): wraps `DLManagedTensorVersioned*` into a TVM `TensorObj`.
- **TVM_FFI_SAFE_CALL / TVM_FFI_CHECK_SAFE_CALL** macros (`0001-c-abi`, `0005-error-system`): C ABI error propagation boundary.
- **ObjectUnsafe** utilities (`0002-object-system`): `MoveObjectPtrToTVMFFIObjectPtr` and `ObjectPtrFromOwned` for raw handle <-> ObjectPtr conversion.

Design elements this commit produces:
- **TVMFFIEnvTensorAlloc** (new C ABI function): abstracts the "allocate tensor via env allocator" pattern into a single C ABI entry point, decoupling callers from DLPack wrapping details and fixing module unload ordering.
- **Tensor::FromEnvAlloc** (renamed + contract change): now takes a generic `int (*)(DLTensor*, TVMFFIObjectHandle*)` function pointer instead of a `DLPackManagedTensorAllocator`. This shifts the allocation/wrapping responsibility to the callee (`libtvm_ffi`).

## Usage Examples

**Before (old API, removed by this commit):**
```cpp
// Caller had to get the raw allocator and pass it directly
ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
    TVMFFIEnvGetTensorAllocator(),
    ffi::Shape({x.size(0)}), f32_dtype, x.device());
```

**After (new API, introduced by this commit):**
```cpp
// Caller passes TVMFFIEnvTensorAlloc as a function pointer
// DLPack wrapping happens inside libtvm_ffi, not in the caller's module
ffi::Tensor y = ffi::Tensor::FromEnvAlloc(
    TVMFFIEnvTensorAlloc,
    ffi::Shape({x.size(0)}), f32_dtype, x.device());
```

**End-to-end with the C ABI (from new test `test_c_env_api.cc`):**
```cpp
// 1. Set up an allocator
TVMFFIEnvSetDLPackManagedTensorAllocator(MyAllocator, 0, nullptr);
// 2. Allocate a tensor via the env alloc function
Tensor t = Tensor::FromEnvAlloc(TVMFFIEnvTensorAlloc, {1, 2, 3},
                                DLDataType({kDLFloat, 32, 1}),
                                DLDevice({kDLCPU, 0}));
// 3. Tensor is fully constructed with data allocated
assert(t.data_ptr() != nullptr);
```
