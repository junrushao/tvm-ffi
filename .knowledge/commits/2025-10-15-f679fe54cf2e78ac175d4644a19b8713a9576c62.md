# Refactor tensor allocator C API to align with DLPack naming and introduce TVMFFIEnvTensorAlloc
## TL;DR
- Renames the tensor allocator C API functions to include "DLPackManagedTensor" in the name: `TVMFFIEnvSetTensorAllocator` -> `TVMFFIEnvSetDLPackManagedTensorAllocator`, `TVMFFIEnvGetTensorAllocator` -> `TVMFFIEnvGetDLPackManagedTensorAllocator`.
- Introduces a new `TVMFFIEnvTensorAlloc(DLTensor* prototype, TVMFFIObjectHandle* out)` C API that allocates a `ffi::Tensor` (not a raw `DLManagedTensorVersioned*`) directly, moving DLPack-to-Object wrapping into `libtvm_ffi` to avoid module unloading order problems.
- Replaces `Tensor::FromDLPackAlloc` with `Tensor::FromEnvAlloc` which takes the new simplified function pointer signature, delegating all DLPack allocator interaction and error handling to the `TVMFFIEnvTensorAlloc` implementation.

## Key Exports

**Functions**:
- `TVMFFIEnvSetDLPackManagedTensorAllocator(DLPackManagedTensorAllocator allocator, int write_to_global_context, DLPackManagedTensorAllocator* opt_out_original_allocator) -> int` -- Set thread-local DLPack managed tensor allocator (renamed from `TVMFFIEnvSetTensorAllocator`).
- `TVMFFIEnvGetDLPackManagedTensorAllocator() -> DLPackManagedTensorAllocator` -- Get current DLPack managed tensor allocator (renamed from `TVMFFIEnvGetTensorAllocator`).
- `TVMFFIEnvTensorAlloc(DLTensor* prototype, TVMFFIObjectHandle* out) -> int` -- New. Allocates a tensor from the environment's DLPack allocator, wraps it as a `TensorObj` within `libtvm_ffi`, and returns an owned `TVMFFIObjectHandle`. Uses `TVM_FFI_SAFE_CALL_BEGIN/END` error propagation. Error from the underlying DLPack allocator is routed through `TVMFFIErrorSetRaisedFromCStr` via a static helper `TVMFFIEnvTensorAllocSetError`.

**C++ Static Methods**:
- `Tensor::FromEnvAlloc(int (*env_alloc)(DLTensor*, TVMFFIObjectHandle*), ShapeView shape, DLDataType dtype, DLDevice device) -> Tensor` -- Replaces `Tensor::FromDLPackAlloc`. Takes a simplified function pointer (matching `TVMFFIEnvTensorAlloc` signature) instead of the full `DLPackManagedTensorAllocator`. Uses `TVM_FFI_CHECK_SAFE_CALL` for error propagation.

**Renames**:

| Old Name | New Name |
|----------|----------|
| `TVMFFIEnvSetTensorAllocator` | `TVMFFIEnvSetDLPackManagedTensorAllocator` |
| `TVMFFIEnvGetTensorAllocator` | `TVMFFIEnvGetDLPackManagedTensorAllocator` |
| `Tensor::FromDLPackAlloc` | `Tensor::FromEnvAlloc` |

## Impact
- API: Breaking. `Tensor::FromDLPackAlloc` is removed; callers must switch to `Tensor::FromEnvAlloc(TVMFFIEnvTensorAlloc, ...)`. The C API symbols `TVMFFIEnvSetTensorAllocator` and `TVMFFIEnvGetTensorAllocator` are removed.
- ABI: Breaking. Two C symbols are renamed and one new symbol is added. Any binary linking against the old symbol names will fail at load time. Rust FFI declarations in `c_env_api.rs` are updated accordingly.
- Behavioral: `Tensor::FromEnvAlloc` no longer directly interacts with the `DLPackManagedTensorAllocator` callback or its error context. Instead, `TVMFFIEnvTensorAlloc` within `libtvm_ffi` handles the DLPack allocator invocation and DLPack-to-TensorObj wrapping, ensuring that metadata allocation (the `TensorObjFromDLPack` object) occurs inside `libtvm_ffi`. This prevents dangling object references when the calling module (DSO) is unloaded before the tensor is freed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- DLPack fast-path protocol and environment tensor allocator two-tier dispatch (TLS + global); see `.knowledge/designs/0018-dlpack-fast-path.md`
- `TensorObjFromDLPack<DLManagedTensorVersioned>` for wrapping DLPack tensors as TVM objects, with strides-at-tail inplace array optimization; see `.knowledge/designs/0018-dlpack-fast-path.md`
- `TVM_FFI_SAFE_CALL_BEGIN/END` and `TVM_FFI_CHECK_SAFE_CALL` error propagation macros; see `.knowledge/designs/error-handling.md`
- `ObjectUnsafe::ObjectPtrFromOwned` and `ObjectUnsafe::MoveObjectPtrToTVMFFIObjectPtr` for raw handle <-> ObjectPtr conversions; see `.knowledge/designs/object-system.md`
- Cython Python call manager `TVMFFIPyCallManager` that sets/restores the tensor allocator around FFI calls; see `.knowledge/designs/0014-python-bindings.md`

Design elements this commit produces:
- `TVMFFIEnvTensorAlloc` as the canonical C API for DSL-compiled code to allocate environment-managed tensors. This is a higher-level API than the raw `DLPackManagedTensorAllocator` -- it encapsulates DLPack allocator lookup, invocation, error routing, and DLPack-to-TensorObj wrapping. The key design choice is to perform object construction inside `libtvm_ffi` rather than in the calling module, avoiding module unloading order issues.
- `Tensor::FromEnvAlloc` as the C++ convenience wrapper that accepts any function with signature `int (*)(DLTensor*, TVMFFIObjectHandle*)`, maintaining explicit dependency on the env API header.

## Usage Examples
Allocating a tensor from a C++ kernel using the environment allocator (the canonical pattern after this commit):

```cpp
#include <tvm/ffi/container/tensor.h>
#include <tvm/ffi/extra/c_env_api.h>

ffi::Tensor my_kernel(ffi::TensorView x) {
    // TVMFFIEnvTensorAlloc is a function pointer, passed explicitly
    // to maintain the header dependency
    ffi::Tensor y = ffi::Tensor::FromEnvAlloc(
        TVMFFIEnvTensorAlloc, ffi::Shape({x.size(0)}),
        DLDataType{kDLFloat, 32, 1}, x.device());
    // ... compute ...
    return y;
}
```

Before this commit, the equivalent code was:
```cpp
ffi::Tensor y = ffi::Tensor::FromDLPackAlloc(
    TVMFFIEnvGetTensorAllocator(), ffi::Shape({x.size(0)}),
    DLDataType{kDLFloat, 32, 1}, x.device());
```
