# Refactor tensor allocation API: rename env functions and introduce TVMFFIEnvTensorAlloc
## TL;DR
- Renamed `TVMFFIEnvSetTensorAllocator` -> `TVMFFIEnvSetDLPackManagedTensorAllocator` and `TVMFFIEnvGetTensorAllocator` -> `TVMFFIEnvGetDLPackManagedTensorAllocator` across C API, Python Cython helpers, and Rust bindings.
- Introduced `TVMFFIEnvTensorAlloc(DLTensor* prototype, TVMFFIObjectHandle* out) -> int` -- a new C API that allocates a `ffi::Tensor` using the TLS allocator with metadata allocation inside libtvm_ffi, avoiding module unloading order bugs.
- Replaced `Tensor::FromDLPackAlloc(DLPackManagedTensorAllocator, ...)` with `Tensor::FromEnvAlloc(int (*)(DLTensor*, TVMFFIObjectHandle*), ...)` -- a simpler interface that delegates DLPack wrapping to the C API.
- Version bump `0.1.0b18` -> `0.1.0b19`.

## Key Exports

**C API** (`include/tvm/ffi/extra/c_env_api.h`):

| Function | Signature |
|----------|-----------|
| `TVMFFIEnvSetDLPackManagedTensorAllocator` | `int (DLPackManagedTensorAllocator allocator, int write_to_global_context, DLPackManagedTensorAllocator* opt_out)` |
| `TVMFFIEnvGetDLPackManagedTensorAllocator` | `DLPackManagedTensorAllocator ()` |
| `TVMFFIEnvTensorAlloc` | `int (DLTensor* prototype, TVMFFIObjectHandle* out)` -- **new** |

**C++ method** (`include/tvm/ffi/container/tensor.h`):

| Method | Signature | Notes |
|--------|-----------|-------|
| `Tensor::FromEnvAlloc` | `static Tensor FromEnvAlloc(int (*env_alloc)(DLTensor*, TVMFFIObjectHandle*), ShapeView shape, DLDataType dtype, DLDevice device)` | Replaces `FromDLPackAlloc` |

**Removed**:
- `Tensor::FromDLPackAlloc(DLPackManagedTensorAllocator, ShapeView, DLDataType, DLDevice)` -- replaced by `FromEnvAlloc`
- `TVMFFIEnvSetTensorAllocator` -- renamed
- `TVMFFIEnvGetTensorAllocator` -- renamed

## Impact
- API: **Breaking** -- Three C API functions renamed/replaced. `Tensor::FromDLPackAlloc` removed.
- Behavioral: Tensor metadata (TensorObj wrapper around DLManagedTensorVersioned) is now allocated inside libtvm_ffi rather than the calling module, preventing use-after-unload when the calling module is unloaded before the tensor is destroyed.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **DLPack interop** ([0017-dlpack-interop.md](../designs/0017-dlpack-interop.md)): `DLPackManagedTensorAllocator`, `DLManagedTensorVersioned`
- **C ABI layer** ([0001-c-abi-layer.md](../designs/0001-c-abi-layer.md)): C API function conventions, `TVM_FFI_SAFE_CALL_BEGIN/END`
- **Object system** ([0003-object-system.md](../designs/0003-object-system.md)): `ObjectUnsafe::ObjectPtrFromOwned`, `MoveObjectPtrToTVMFFIObjectPtr`

Design elements this commit produces/mutates:
- **TVMFFIEnvTensorAlloc**: New C API entry point that centralizes tensor allocation from TLS allocator. The key architectural decision is that DLPack-to-TensorObj wrapping happens inside libtvm_ffi, not in the caller's module.
- **Tensor::FromEnvAlloc**: Simplified C++ wrapper that takes a function pointer matching `TVMFFIEnvTensorAlloc`'s signature.

## Usage Examples

```cpp
// New pattern (from tests/python/test_load_inline.py inline C++):
#include <tvm/ffi/extra/c_env_api.h>

ffi::Tensor y = ffi::Tensor::FromEnvAlloc(
    TVMFFIEnvTensorAlloc, ffi::Shape({x.size(0)}), f32_dtype, x.device());
```
