# Add TYPE_INDEX_TO_CLS fast-path list in Cython make_ret_object to eliminate TypeInfo attribute dereference on FFI return hot path

## TL;DR
- `make_ret_object` (Cython hot path for FFI object returns) now reads `TYPE_INDEX_TO_CLS[tindex]` directly instead of first loading `TYPE_INDEX_TO_INFO[tindex]` and then accessing `.type_cls`, eliminating one attribute dereference per FFI call that returns an `Object`.
- A new parallel `cdef list TYPE_INDEX_TO_CLS` is maintained length-synchronized with `TYPE_INDEX_TO_INFO`; both `_register_object_by_index` and the new `_set_type_cls` keep them in sync.
- `_set_type_cls(type_index, type_cls)` is introduced as a new Cython-level API allowing late binding of a Python class to an already-registered type index (where `TypeInfo` slot exists but `.type_cls` is still `None`).

## Impact
- API: `_set_type_cls(type_index, type_cls)` is a new public Cython function exposed in `core.pyi`. No existing signatures changed.
- Behavioral: `make_ret_object` semantically unchanged for callers; only the internal lookup mechanism is faster.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `TYPE_INDEX_TO_INFO` (`cdef list`) — existing type registry indexed by `type_index`; still populated and kept synchronized
- `TypeInfo.type_cls` — still set by `_set_type_cls`, but no longer read in the hot path
- `make_ret_object` — the hot-path Cython inline for object return; described in `0013-python-package.md` (object.pxi section)
- `PyNativeObject` — subclass check path unchanged

Design elements this commit produces:
- `TYPE_INDEX_TO_CLS` (`cdef list`) — new direct type-class index parallel to `TYPE_INDEX_TO_INFO`; enables O(1) list index read in `make_ret_object` without attribute traversal
- `_set_type_cls(type_index, type_cls)` — new Cython API for late-binding a Python type class to an already-registered type slot
