# Eliminate indirection in Cython make_ret_object by adding direct type_index-to-class list
## TL;DR
- Adds a parallel `TYPE_INDEX_TO_CLS` cdef list alongside the existing `TYPE_INDEX_TO_INFO` list, storing the `type_cls` directly for O(1) class lookup by type index.
- Rewrites `make_ret_object` to read `TYPE_INDEX_TO_CLS[tindex]` instead of `TYPE_INDEX_TO_INFO[tindex].type_cls`, eliminating one Python attribute access on every FFI object return.
- Introduces `_set_type_cls(type_index, type_cls)` for deferred type class registration after a TypeInfo slot already exists.

## Impact
- API: Additive -- new `_set_type_cls` function exposed in `core.pyi`. No changes to existing public API signatures.
- Behavioral: `make_ret_object` performs one fewer Python attribute access per call. The dispatch logic (PyNativeObject branch vs regular Object branch) is unchanged.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **TYPE_INDEX_TO_INFO registry** (`.knowledge/design-records/0012-ffi-python-package.md`) -- the existing type_index-to-TypeInfo mapping. This commit keeps it but removes its role as the hot-path class lookup.
- **PyNativeObject protocol** -- the `__from_tvm_ffi_object__` dispatch branch in `make_ret_object` is preserved.
- **Object dispatch table pattern** (`.knowledge/design-records/0012-ffi-python-package.md`, "Dispatch table" section) -- the type_index-based class lookup that `make_ret_object` uses.

Design elements this commit produces:
- **TYPE_INDEX_TO_CLS** -- a new cdef list providing direct type_index-to-class mapping, kept in lockstep with TYPE_INDEX_TO_INFO. This is a performance-motivated denormalization of the dispatch table.
- **`_set_type_cls` API** -- enables two-phase type registration: create TypeInfo with `type_cls=None` first, bind the class later. No callers in this commit; surface exposed for future use.

## Usage Examples
The change is internal to the Cython dispatch layer and not directly user-facing. The performance benefit is automatic for all FFI object returns.

**Before** (one extra attribute access per return):
```python
# In make_ret_object (old):
type_info = TYPE_INDEX_TO_INFO[tindex]      # list index
cls = type_info.type_cls                     # attribute access
```

**After** (direct list lookup):
```python
# In make_ret_object (new):
cls = TYPE_INDEX_TO_CLS[tindex]              # list index only
```

**Deferred registration (new API, no callers yet):**
```python
# Phase 1: register TypeInfo without a class
info = _type_info_create_from_type_key(None, "my.Type")
# Phase 2: bind the class later
_set_type_cls(type_index, MyTypeCls)
```
