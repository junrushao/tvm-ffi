# Improve critical path perf in Cython `make_ret_object` by direct type_index-to-class mapping

## TL;DR
- Introduces a parallel `TYPE_INDEX_TO_CLS` list in `object.pxi` that maps `type_index` directly to the Python `type_cls`, eliminating one indirection through the `TypeInfo` object on the hot return path of `make_ret_object`.
- Adds a new `_set_type_cls(type_index, type_cls)` Cython function (and corresponding `.pyi` stub) for updating the class mapping independently of full type-info registration.
- Rewrites `make_ret_object` to look up `TYPE_INDEX_TO_CLS[tindex]` instead of `TYPE_INDEX_TO_INFO[tindex].type_cls`, removing two attribute accesses (`type_info` lookup, then `.type_cls`) from the critical path.

## Key Exports

**New Cython-level function:**

| Module | Function | Signature |
|--------|----------|-----------|
| `core` (via `object.pxi`) | `_set_type_cls` | `(type_index: int, type_cls: type) -> None` |

**New Cython-level data:**

| Module | Symbol | Type | Description |
|--------|--------|------|-------------|
| `object.pxi` | `TYPE_INDEX_TO_CLS` | `cdef list` | Parallel list to `TYPE_INDEX_TO_INFO`, mapping `type_index` directly to the Python class (or `None`). Kept in sync with `TYPE_INDEX_TO_INFO` via assertions in `_register_object_by_index` and `_set_type_cls`. |

**Updated Cython-level function:**

| Module | Function | Change |
|--------|----------|--------|
| `object.pxi` | `_register_object_by_index` | Now also extends and populates `TYPE_INDEX_TO_CLS` alongside `TYPE_INDEX_TO_INFO`. Asserts length parity between the two lists. |

**New stub:**

| File | Added |
|------|-------|
| `core.pyi` | `def _set_type_cls(type_index: int, type_cls: type) -> None: ...` |

## Impact
- API: Adds `_set_type_cls` as a new internal API. This is a private Cython function (underscore-prefixed), not a public user-facing API.
- ABI: None. No C/C++ changes.
- Behavioral: `make_ret_object` is faster on the critical path because it performs a single list index lookup (`TYPE_INDEX_TO_CLS[tindex]`) instead of a list lookup followed by two Python attribute accesses (`TYPE_INDEX_TO_INFO[tindex]` then `.type_cls`). The functional behavior is identical -- the same class is resolved for the same type index.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements

Design elements this commit consumes:
- **Object Type Registry** (`.knowledge/designs/0014-python-bindings.md` > Object Type Registry): The existing `TYPE_INDEX_TO_INFO` list and `_register_object_by_index` registration flow, which maps type indices to `TypeInfo` objects containing the Python class.
- **`make_ret_object` return path** (`.knowledge/designs/0014-python-bindings.md` > C-to-Python: `make_ret`): The existing return-value dispatch that looks up `OBJECT_TYPE[tindex]` to find the Python class to instantiate.
- **Unregistered object fallback** (commit `d68c8d8`): The fallback path in `make_ret_object` that warns and returns a base `Object` when the type index is not registered.

Design elements this commit produces:
- **Split type-index lookup tables**: Establishes the pattern of maintaining a parallel `TYPE_INDEX_TO_CLS` list alongside `TYPE_INDEX_TO_INFO`, optimized for the hot path. `TYPE_INDEX_TO_CLS` stores only the bare Python `type` object (cheap to access), while `TYPE_INDEX_TO_INFO` stores the full `TypeInfo` with fields, methods, etc. (used only during registration/reflection). The two lists are kept in sync by assertions in `_register_object_by_index` and `_set_type_cls`.
- **Deferred class registration via `_set_type_cls`**: Provides a way to set the Python class for a type index after the `TypeInfo` has already been registered (with `type_cls=None`). This supports scenarios where type info is created from the type key before the Python class is available, and the class is bound later.

## Usage Examples

The optimization is internal to the Cython layer and transparent to users. The `_set_type_cls` function is used internally for deferred registration:

```python
# Internal usage pattern (not user-facing):
# 1. Register type info without a class
info = core._register_object_by_index(type_index, SomeClass)

# 2. Later, set the class for a type_index whose TypeInfo was created with type_cls=None
core._set_type_cls(type_index, SomeClass)
```

The performance improvement is visible in any code path that returns FFI objects from packed function calls, e.g.:

```python
import tvm_ffi

# Every return from an FFI function call that returns an Object
# goes through make_ret_object, which is now faster:
arr = tvm_ffi.Array([1, 2, 3])
item = arr[0]  # make_ret_object called here -- one fewer indirection
```
