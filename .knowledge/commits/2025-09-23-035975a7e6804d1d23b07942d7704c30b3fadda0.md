# Improve critical path perf in Cython make_ret_object with direct class lookup
## TL;DR
- Adds `TYPE_INDEX_TO_CLS` list as a parallel lookup table to `TYPE_INDEX_TO_INFO`, enabling `make_ret_object` to look up the Python class directly by type index without going through the `TypeInfo` indirection.
- Adds `_set_type_cls` function for deferred class registration (setting the class on an already-existing TypeInfo entry).
- Both `TYPE_INDEX_TO_CLS` and `TYPE_INDEX_TO_INFO` are kept in sync with an assertion.

## Impact
- API: New internal function `_set_type_cls` for deferred type class binding. `make_ret_object` hot path is now one list lookup instead of two attribute accesses.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Python Bindings** (`.knowledge/designs/0014-python-bindings.md`): `TYPE_INDEX_TO_INFO` registry, `make_ret_object` critical path.
- **Python FFI Call Dispatch** (`.knowledge/designs/0019-python-ffi-call-dispatch.md`): Return value construction path.

Design elements this commit produces:
- **`TYPE_INDEX_TO_CLS` fast-path table**: A parallel `cdef list` for O(1) type index to Python class lookup, eliminating `TypeInfo` attribute access in the hot path. Invariant: `len(TYPE_INDEX_TO_CLS) == len(TYPE_INDEX_TO_INFO)` and `TYPE_INDEX_TO_CLS[i] == TYPE_INDEX_TO_INFO[i].type_cls` when both are non-None.
