# Eliminate TypeInfo indirection in Cython make_ret_object by adding direct type_index-to-class list
## TL;DR
- Introduces `TYPE_INDEX_TO_CLS` (cdef list), a parallel array to `TYPE_INDEX_TO_INFO` that maps `type_index` directly to the Python `type_cls`, eliminating the `TYPE_INDEX_TO_INFO[tindex].type_cls` attribute dereference on the critical return path.
- Rewrites `make_ret_object` to look up `TYPE_INDEX_TO_CLS[tindex]` instead of going through `TypeInfo`, saving one Python attribute access per FFI return of an object.
- Adds `_set_type_cls(type_index, type_cls)` for deferred class registration (setting `type_cls` after `TypeInfo` is already created with `type_cls=None`).

## Key Exports
**Module-level data** (Cython, `object.pxi`):
- `TYPE_INDEX_TO_CLS: cdef list` -- parallel to `TYPE_INDEX_TO_INFO`, maps `int type_index -> type | None`. Always kept in sync: `len(TYPE_INDEX_TO_CLS) == len(TYPE_INDEX_TO_INFO)`.

**Functions**:
- `_set_type_cls(type_index: int, type_cls: type) -> None` -- Sets the class for a type index whose `TypeInfo` was previously registered with `type_cls=None`. Asserts that `type_cls` was not already set. Updates both `TYPE_INDEX_TO_INFO[type_index].type_cls` and `TYPE_INDEX_TO_CLS[type_index]`.

**Type stub** (in `core.pyi`):
- `def _set_type_cls(type_index: int, type_cls: type) -> None: ...`

## Impact
- API: Adds `_set_type_cls` as a new internal API. Not a breaking change; `_register_object_by_index` signature and behavior unchanged.
- Behavioral: `make_ret_object` is faster due to one fewer Python attribute access (`type_info.type_cls` eliminated). Semantic behavior unchanged -- same dispatch logic, same fallback path for unregistered types.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- **Dual type registry** (`TYPE_INDEX_TO_INFO` + `TYPE_KEY_TO_INFO`): The existing registry from [0014-python-package](../designs/0014-python-package.md) and referenced in commit `53b2e00`. This commit adds a third parallel structure (`TYPE_INDEX_TO_CLS`) but keeps the existing two intact.
- **`make_ret_object` dispatch path**: The Cython fast path for converting `TVMFFIAny` return values into Python objects, documented in [0015-python-ffi-call-dispatch](../designs/0015-python-ffi-call-dispatch.md).
- **`TypeInfo` dataclass**: Specifically its `type_cls` field, which is the Python class corresponding to a registered object type.
- **`PyNativeObject` protocol**: The `issubclass(cls, PyNativeObject)` check and `__from_tvm_ffi_object__` dispatch remain unchanged.

Design elements this commit produces:
- **`TYPE_INDEX_TO_CLS` parallel array**: A new cdef list that denormalizes `type_cls` out of `TypeInfo` for O(1) direct list indexing on the return path. This is a performance-oriented data duplication -- the authoritative source remains `TypeInfo.type_cls`, but `TYPE_INDEX_TO_CLS` is the one read on the hot path.
- **`_set_type_cls` deferred registration API**: Enables a two-phase registration pattern where `TypeInfo` is created first (with `type_cls=None`) and the actual Python class is set later. This supports lazy/deferred class creation.

## Usage Examples
**Before (parent commit)** -- `make_ret_object` with TypeInfo indirection:
```python
# Hot path in make_ret_object (Cython pseudo-code):
if tindex < len(TYPE_INDEX_TO_INFO):
    type_info = TYPE_INDEX_TO_INFO[tindex]       # list index
    if type_info is not None:
        cls = type_info.type_cls                   # <-- attribute access (eliminated)
        if cls is not None:
            obj = cls.__new__(cls)
            ...
```

**After (this commit)** -- direct list lookup:
```python
# Hot path in make_ret_object (Cython pseudo-code):
if tindex < len(TYPE_INDEX_TO_CLS):
    cls = TYPE_INDEX_TO_CLS[tindex]               # <-- direct list index, no attribute access
    if cls is not None:
        obj = cls.__new__(cls)
        ...
```

**Deferred class registration via `_set_type_cls`**:
```python
# Phase 1: register TypeInfo without a class
info = _register_object_by_index(type_index, None)  # type_cls=None in TypeInfo

# Phase 2: later, set the class
_set_type_cls(type_index, MyClass)  # updates both TypeInfo.type_cls and TYPE_INDEX_TO_CLS
```
