# Restrict DLPack stride normalization to 1D scalar tensors

## TL;DR
- Fixes a bug in `toDLPackImpl` (inline C++ in `_optional_torch_c_dlpack.py`) where stride normalization was incorrectly applied to multi-dimensional tensors with size-1 dimensions. The old code walked all dimensions and normalized any size-1 dimension's stride to 1, which corrupts the memory layout for sliced/viewed tensors with non-contiguous strides on size-1 axes (e.g., shape `[1, N]` from a row slice of a 2D tensor).
- The fix restricts normalization to the only safe case: 1D tensors where `size(0) == 1 && stride(0) != 1` -- i.e., scalar-like 1D tensors with a non-unit stride artifact.
- Upstream reference: [pytorch/pytorch#163274](https://github.com/pytorch/pytorch/issues/163274).

## Key Exports

None -- no new public API. The change modifies internal behavior of the `toDLPackImpl<T>` C++ template function embedded in the JIT-compiled torch extension.

```python
# Modified internal function (behavior change only, no signature change):
# template <class T>
# T* toDLPackImpl(const Tensor& src):
#   Before: normalized strides for ALL size-1 dimensions across any ndim
#   After:  normalizes strides ONLY for 1D tensors with size(0)==1 and stride(0)!=1
#   Interacts with: TorchDLPackFromPyObject (caller), DLManagedTensorVersioned (output)
#   Invariant (new): multi-dim tensors are exported with original strides intact
#   Invariant (preserved): 1D scalar tensors still get stride normalization to avoid
#     downstream consumers seeing misleading stride values
```

## Impact
- API: None -- no public API changes.
- Behavioral: Multi-dimensional torch tensors with size-1 dimensions (e.g., slices producing `[1, N]`, unsqueezed tensors) are now exported via DLPack with their original strides preserved. Previously, those strides were silently rewritten to 1, which could produce incorrect memory access patterns in downstream consumers (TVM FFI Tensor, other DLPack consumers).
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **Torch C DLPack JIT extension** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): The inline C++ source compiled via `torch.utils.cpp_extension.load_inline` that provides fast DLPack conversion between torch tensors and TVM FFI tensors. See [0012-python-bindings.md](../designs/0012-python-bindings.md).
- **DLPack speed converter protocol**: The three-pointer protocol (`__c_dlpack_from_pyobject__`, `__c_dlpack_to_pyobject__`, `__c_dlpack_tensor_allocator__`) registered on `torch.Tensor` at import time. `toDLPackImpl` is the core of the export path called via `TorchDLPackFromPyObject`.

Design elements this commit produces:
- None -- this is a bugfix tightening an existing invariant, not a new design element.

## Usage Examples

Before (incorrect for multi-dim tensors):
```python
import torch
# A 2D tensor sliced to shape [1, 5] with stride [5, 1]
t = torch.arange(10).reshape(2, 5)[0:1, :]  # shape [1, 5], stride (5, 1)
# Old code: toDLPackImpl normalized stride[0] from 5 to 1 because size[0]==1
# DLPack consumer sees strides [1, 1] -- INCORRECT, data aliasing with next row
```

After (correct):
```python
import torch
t = torch.arange(10).reshape(2, 5)[0:1, :]  # shape [1, 5], stride (5, 1)
# New code: ndim != 1, so no stride normalization
# DLPack consumer sees strides [5, 1] -- CORRECT, preserves original layout
```
