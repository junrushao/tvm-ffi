# Restrict DLPack stride normalization to 1D tensors on export to fix multi-dim corruption
## TL;DR
- Fixes `toDLPackImpl` in `_optional_torch_c_dlpack.py` to only normalize strides for 1D tensors with `size(0) == 1 && stride(0) != 1`, preventing incorrect stride rewriting on multi-dimensional tensors.
- The old code iterated over all dimensions and set `strides[i] = 1` for any dimension with `shape[i] < 2`, which could produce wrong memory layouts for tensors with broadcasting or non-contiguous views.
- References upstream PyTorch issue [pytorch/pytorch#163274](https://github.com/pytorch/pytorch/issues/163274).

## Key Exports
None -- no new types, functions, or API surface. This is a behavioral fix to the existing `toDLPackImpl<T>` template.

## Impact
- API: None -- function signatures unchanged.
- Behavioral: `toDLPackImpl<T>` no longer normalizes strides for multi-dimensional tensors with size-1 dimensions. Only 1D scalar-like tensors (shape=[1], stride != 1) get stride normalization. This fixes data corruption when exporting higher-rank tensors with size-1 dimensions via DLPack.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **DLPack fast-path exchange protocol** ([0015-python-ffi-call-dispatch.md](../designs/0015-python-ffi-call-dispatch.md)): The `toDLPackImpl<T>` function is the C++ core of `TorchDLPackFromPyObject`, which backs `torch.Tensor.__c_dlpack_from_pyobject__`. The stride normalization bug affected all torch-to-TVM tensor transfers via this path.
- **PyTorch `as_strided` API**: Used to create a view with corrected strides; the call is retained but now only invoked for the 1D case.

Design elements this commit produces:
- None -- no new design elements introduced.

## Usage Examples
**Before (incorrect):** For a tensor with shape `[3, 1, 4]` and strides `[4, 4, 1]`, the old code would detect `size(1) == 1` with `stride(1) != expected` and set `strides[1] = 1`, producing `[4, 1, 1]`. This changes the memory layout semantics -- dimension 1 is no longer seen as sharing stride with dimension 0.

**After (correct):** The same tensor passes through `toDLPackImpl` with strides unchanged (`[4, 4, 1]`), preserving the original memory layout. Only a truly 1D tensor like shape `[1]` with stride `[N]` (where N != 1) gets normalized to stride `[1]`.

```cpp
// Before: applied to any tensor
bool need_normalize_strides = false;
int64_t expected_stride = 1;
for (int i = src.dim() - 1; i >= 0; i--) {
  if (src.stride(i) != expected_stride && src.size(i) == 1) {
    need_normalize_strides = true; break;
  }
  expected_stride *= src.size(i);
}
// ... then rewrote ALL size-1 dims to stride 1

// After: only 1D scalar-like tensors
bool need_normalize_strides = src.ndim() == 1 && src.size(0) == 1 && src.stride(0) != 1;
// ... then uses as_strided(shape, {1}, offset)
```
