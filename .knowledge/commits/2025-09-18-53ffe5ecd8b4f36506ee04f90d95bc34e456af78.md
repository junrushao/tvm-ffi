# Fix stride normalization in toDLPackImpl to only apply to 1D scalar tensors

## TL;DR
- Restricts stride normalization in `toDLPackImpl` (torch DLPack export) to 1D tensors with a single element, fixing incorrect DLPack exports for multi-dimensional tensors with size-1 dimensions.
- Addresses PyTorch issue pytorch/pytorch#163274.

## Key Exports

No new API surface. The fix modifies the internal behavior of `toDLPackImpl<T>` in `_optional_torch_c_dlpack.py`.

```python
# toDLPackImpl stride normalization (C++ inside JIT-compiled extension)
# Before: normalized strides for ANY dimension where size==1 across all ndim
# After:  only normalizes when ndim==1 AND size(0)==1 AND stride(0)!=1
#
# Invariant: stride normalization must only apply to 1D scalar tensors.
#   Multi-dimensional tensors with size-1 dimensions must preserve their
#   original strides, even if non-contiguous, to correctly represent
#   broadcasting/slicing semantics in DLPack.
# Interacts with: TorchDLPackFromPyObject, TorchDLPackTensorAllocator,
#   __c_dlpack_from_pyobject__ protocol on torch.Tensor
```

## Impact
- API: None -- no signature changes.
- Behavioral: `toDLPackImpl` no longer normalizes strides on multi-dimensional tensors with size-1 dimensions. Previously, a tensor like `torch.zeros(1, 3, 1, 5)` could have its strides rewritten during DLPack export, potentially causing data misinterpretation by the consumer. Now only true 1D scalars (`shape=[1]`) get stride normalization.
- Flags/config: None.
- Data formats/schemas: DLPack tensors exported from multi-dimensional PyTorch tensors with size-1 dimensions now preserve their original strides, which is a correctness fix for the DLPack wire format.

## Design Elements
Design elements this commit consumes:
- **Torch C DLPack extension** (`python/tvm_ffi/_optional_torch_c_dlpack.py`): JIT-compiled C++ extension for fast DLPack conversion. See [0012-ffi-python-package](../design-records/0012-ffi-python-package.md).
- **`__c_dlpack_from_pyobject__` protocol**: The function pointer protocol on `torch.Tensor` that routes through `TorchDLPackFromPyObject` -> `toDLPackImpl`. See [0012-ffi-python-package](../design-records/0012-ffi-python-package.md).

Design elements this commit produces: None -- pure bugfix.

## Usage Examples

Before/after pattern for stride normalization behavior:

```python
import torch
# A multi-dim tensor with size-1 dims and non-contiguous strides
t = torch.zeros(3, 5)[:, :1]  # shape=(3, 1), strides=(5, 1)

# BEFORE fix: toDLPackImpl would detect stride(1) for size-1 dim,
# potentially rewrite strides, producing incorrect DLPack metadata.

# AFTER fix: only 1D tensors with shape=[1] get stride normalization.
# Multi-dim tensors preserve original strides through DLPack export.
# The fix ensures: ndim==1 && size(0)==1 && stride(0)!=1
```
