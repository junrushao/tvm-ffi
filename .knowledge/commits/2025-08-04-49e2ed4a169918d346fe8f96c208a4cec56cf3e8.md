# Introduce small string/bytes optimization: store short strings inline in TVMFFIAny

## TL;DR
- Adds a small-string optimization (SSO) to TVM FFI: strings up to 7 bytes are stored inline in the 16-byte `TVMFFIAny` value, avoiding heap allocation and ref-counting entirely.
- Introduces two new type index entries: `kTVMFFISmallStr = 11` and `kTVMFFISmallBytes = 12` in the POD range `[0, 64)`.
- Redesigns `String` and `Bytes` from `ObjectRef` subclasses to value types backed by `details::BytesBaseCell`, a private wrapper around `TVMFFIAny` that transparently dispatches between inline (small) and heap-allocated (large) storage.
- Updates `TVMFFIAny` layout: the `small_len` field becomes a union `{ uint32_t zero_padding; uint32_t small_str_len }`. All non-small-string code paths must now set `zero_padding = 0` to maintain equality/hash invariants.
- `AnyHash` and `AnyEqual` are rewritten to handle cross-representation equality: a small string with type `kTVMFFISmallStr` correctly compares equal to a heap-allocated `kTVMFFIStr` with the same content, and similarly for bytes.
- Custom `TypeTraits<String>` and `TypeTraits<Bytes>` replace the previous `ObjectRefWithFallbackTraitsBase`-based specializations, with `field_static_type_index = kTVMFFIAny` (since the runtime type can be either small or large).
- `Optional<String>` and `Optional<Bytes>` get a dedicated template specialization using `BytesBaseCell(std::nullopt)` as the null sentinel.

## Key Exports

### C ABI Changes (`include/tvm/ffi/c_api.h`)

**New type index entries:**
- `kTVMFFISmallStr = 11` -- Small string stored inline on stack.
- `kTVMFFISmallBytes = 12` -- Small bytes stored inline on stack.

**TVMFFIAny layout change:**
- The `int32_t small_len` field at offset 4 is replaced by a union:
  ```c
  union {  // 4 bytes
      uint32_t zero_padding;    // must be 0 for non-small-string types
      uint32_t small_str_len;   // length of small string (max 7)
  };
  ```
- The `v_bytes` field in the 8-byte union is used to store small string content inline, starting at offset 8. Max capacity is `sizeof(int64_t) - 1 = 7` bytes (the last byte is reserved for null terminator compatibility).

**New inline accessor:**
- `TVMFFISmallBytesGetContentByteArray(const TVMFFIAny* value) -> TVMFFIByteArray` -- Extracts the content of a small string/bytes as a `TVMFFIByteArray`.

**Changed C API signature:**
- `TVMFFIDataTypeToString(const DLDataType* dtype, TVMFFIAny* out)` -- Return type changed from `TVMFFIObjectHandle*` to `TVMFFIAny*` to support returning small strings directly.

### C++ String/Bytes Redesign (`include/tvm/ffi/string.h`)

**`String` and `Bytes` are no longer `ObjectRef` subclasses.** They are now value types with a private `details::BytesBaseCell data_` member:

```cpp
class String {
  // No longer inherits from ObjectRef
  details::BytesBaseCell data_;
public:
  const char* data() const noexcept;
  const char* c_str() const noexcept;
  size_t size() const noexcept;
  // ...
};
```

**`details::BytesBaseCell`** -- New private helper class wrapping a `TVMFFIAny`. Manages the dual representation:
- Small strings (`small_str_len <= 7`): content stored inline in `v_bytes`, type index is `kTVMFFISmallStr`/`kTVMFFISmallBytes`.
- Large strings: content stored in a heap-allocated `BytesObjBase`-derived object, type index is `kTVMFFIStr`/`kTVMFFIBytes`.
- Null state: `type_index == kTVMFFINone`, used by `Optional<String>`.
- Provides `data()`, `size()`, `MoveToAny()`, `CopyToTVMFFIAny()`, `CopyFromAnyView()`, `MoveFromAny()`.
- `InitSpaceForSize<LargeObj>(size, small_type_index, large_type_index)` -- Returns a `char*` pointer to writable storage; chooses inline or heap based on `size <= 7`.

**Deleted macros from `String` and `Bytes`:**
- `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` is no longer used -- these types no longer participate in the ObjectRef hierarchy.

**New operator deletions on `String`:**
- All comparison operators with `std::nullptr_t` are `= delete` (`<`, `>`, `<=`, `>=`, `==`, `!=`), preventing accidental null comparisons since `String` is no longer nullable.

**`Bytes::memequal` signature change:**
- Parameters changed from `const char*` to `const void*` for broader applicability.

### TypeTraits Changes (`include/tvm/ffi/type_traits.h`, `string.h`)

**`TypeTraits<String>` (new custom specialization):**
- `field_static_type_index = kTVMFFIAny` (not `kTVMFFIStr`, since the runtime type may be `kTVMFFISmallStr` or `kTVMFFIStr`).
- `CheckAnyStrict`: accepts both `kTVMFFISmallStr` and `kTVMFFIStr`.
- `TryCastFromAnyView`: converts from `kTVMFFIRawStr`, `kTVMFFISmallStr`, or `kTVMFFIStr`.
- Replaces the prior `ObjectRefWithFallbackTraitsBase<String, const char*>`.

**`TypeTraits<Bytes>` (new custom specialization):**
- `field_static_type_index = kTVMFFIAny` (not `kTVMFFIBytes`, since the runtime type may be `kTVMFFISmallBytes` or `kTVMFFIBytes`).
- `CheckAnyStrict`: accepts both `kTVMFFISmallBytes` and `kTVMFFIBytes`.
- `TryCastFromAnyView`: converts from `kTVMFFIByteArrayPtr`, `kTVMFFISmallBytes`, or `kTVMFFIBytes`.
- Replaces the prior `ObjectRefWithFallbackTraitsBase<Bytes, TVMFFIByteArray*>`.

**`zero_padding = 0` invariant:**
- Every `CopyToAnyView` and `MoveToAny` for non-small-string types now explicitly sets `result->zero_padding = 0`. This ensures `AnyEqual`'s fast-path 16-byte comparison works correctly and `AnyHash` produces consistent results.
- Affected: `TypeTraits<std::nullptr_t>`, `TypeTraits<bool>`, `TypeTraits<StrictBool>`, `TypeTraits<Int>`, `TypeTraits<IntEnum>`, `TypeTraits<Float>`, `TypeTraits<void*>`, `TypeTraits<DLDevice>`, `TypeTraits<DLDataType>`, `TypeTraits<DLTensor*>`, `TypeTraits<char[N]>`, `TypeTraits<const char*>`, `TypeTraits<TVMFFIByteArray*>`, `TypeTraits<std::string>`, `ObjectRefTypeTraitsBase`, `TypeTraits<TObject*>`, `TypeTraits<RValueRef<T>>`, `Variant::as()`.

### Optional<String> / Optional<Bytes> (`include/tvm/ffi/optional.h`)

New template specialization for `Optional<T>` where `T` is `String` or `Bytes`:
- Uses `BytesBaseCell(std::nullopt)` (which sets `type_index = kTVMFFINone`) as the null sentinel.
- `sizeof(Optional<String>) == sizeof(String)` -- zero overhead.
- Supports `value()`, `value_or()`, `has_value()`, `operator bool()`, comparison operators.

### AnyHash / AnyEqual Changes (`include/tvm/ffi/any.h`)

**`AnyHash::operator()`:**
- For `kTVMFFISmallStr`: hashes using `StableHashSmallStrBytes` combined with `kTVMFFIStr` (not `kTVMFFISmallStr`) to ensure equal hashes for equivalent small and large strings.
- For `kTVMFFISmallBytes`: same pattern with `kTVMFFIBytes`.

**`AnyEqual::operator()`:**
- Fast path: compares the two 16-byte `TVMFFIAny` values as two `int64_t`s.
- Cross-type equality: `kTVMFFISmallStr` vs `kTVMFFIStr`, `kTVMFFISmallBytes` vs `kTVMFFIBytes` are handled by extracting content from each representation and calling `Bytes::memequal`.

**`Any::same_as()`:**
- Now compares `zero_padding` in addition to `type_index` and `v_int64`, since small strings use the padding field for length.

### Hashing Helpers (`include/tvm/ffi/base_details.h`)

- `StableHashBytes(const char*, size_t)` signature changed to `StableHashBytes(const void*, size_t)`.
- New: `StableHashSmallStrBytes(const TVMFFIAny*)` -- Fast path for hashing small strings. On little-endian systems, directly hashes `v_uint64 % kMod`.

### Static Type Keys (`include/tvm/ffi/object.h`)

- `StaticTypeKey::kTVMFFISmallStr = "ffi.SmallStr"` -- type key for small strings.
- `StaticTypeKey::kTVMFFISmallBytes = "ffi.SmallBytes"` -- type key for small bytes.

### Type Table Registration (`src/ffi/object.cc`)

- `kTVMFFISmallStr` and `kTVMFFISmallBytes` are registered as builtin type indices.
- `TypeTable::CopyString` changed to use explicit `MakeInplaceString` (raw `ObjectPtr<StringObj>`) instead of `String(...)`, avoiding the small-string path for the type-table string pool where stable pointers are needed.

### Structural Hash/Equal (`src/ffi/extra/structural_hash.cc`, `src/ffi/extra/structural_equal.cc`)

- Both handle `kTVMFFISmallStr` / `kTVMFFISmallBytes` with cross-representation comparison and hashing.
- POD equality now includes `zero_padding` comparison.

### Include Dependency Changes

- `type_traits.h` no longer includes `optional.h` (String is now defined in `string.h` without needing Optional).
- `cast.h` now includes `optional.h`.
- `optional.h` now includes `string.h` (for the `Optional<String>` specialization).

### Minor Changes

- `reflection/accessor.h`: Error message improved: adds backticks around field name.
- `dtype.h`: `StringToDLDataType` creates a `TVMFFIByteArray` from `str.data()/str.size()` instead of calling `str.get()` (since `String` no longer has `get()`). `DLDataTypeToString` uses `TypeTraits<String>::MoveFromAnyAfterCheck`.
- `std::hash<String>` and `std::hash<Bytes>`: Changed from `StableHashBytes` to `std::hash<std::string_view>` for performance (stable hashing is only needed for cross-run determinism in `AnyHash`).
- Two `test_rvalue_ref.cc` test cases commented out (not directly related to small string, likely deferred fix).

## Impact
- **ABI**: Breaking. `TVMFFIAny` layout changes (`small_len` -> `zero_padding`/`small_str_len` union). `TVMFFIDataTypeToString` signature changes. Two new type indices `kTVMFFISmallStr`/`kTVMFFISmallBytes`. All language bindings must be updated to handle the new type indices and the `zero_padding` invariant.
- **API**: `String` and `Bytes` are no longer `ObjectRef` subclasses. Code that relied on `String::get()`, `String::use_count()`, `Downcast<String>(objectref)`, or treating `String`/`Bytes` as `ObjectRef` must be updated. `Downcast<String>(Any)` still works via `TypeTraits`.
- **Behavioral**: Short strings (<=7 bytes) avoid heap allocation entirely. This is a significant performance optimization for common cases like type keys, field names, and short attribute strings. Hash and equality semantics are preserved across small/large representations.
- **Flags/config**: None.

## Design Elements

Design elements this commit consumes:
- `TVMFFIAny` 16-byte layout (from 7d34eb8).
- `BytesObjBase : Object, TVMFFIByteArray` base class (from f9d2bff which hid StringObj/BytesObj into details).
- `TypeTraits<T>` protocol (from 7d34eb8).
- `ObjectRefWithFallbackTraitsBase` (from 7d34eb8, now removed for String/Bytes).
- `make_inplace_array_object` for large string allocation (from 7d34eb8).
- `StableHashBytes` for content hashing (from ba0ea87 which improved string hash handling).
- `AnyHash`/`AnyEqual` functors (from 7d34eb8).

Design elements this commit produces:
- **Small string/bytes optimization** -- Strings up to 7 bytes are stored inline in `TVMFFIAny.v_bytes` with `type_index = kTVMFFISmallStr`/`kTVMFFISmallBytes` and length in `small_str_len`. Avoids heap allocation and ref-counting for short strings.
- **`zero_padding` invariant** -- All non-small-string `TVMFFIAny` values must have `zero_padding = 0`. This enables the fast-path 16-byte equality check in `AnyEqual` and ensures hash consistency.
- **`BytesBaseCell` dual-storage wrapper** -- A private class that transparently manages inline vs heap storage for strings/bytes. Serves as the backing cell for both `String` and `Bytes`.
- **Cross-representation hash/equality** -- `AnyHash` and `AnyEqual` normalize small and large strings to the same hash/equality bucket (using `kTVMFFIStr`/`kTVMFFIBytes` as the canonical type index for hashing).
- **String/Bytes as non-ObjectRef value types** -- `String` and `Bytes` are no longer part of the `ObjectRef` hierarchy. They are self-contained value types that embed a `TVMFFIAny` directly. This decouples their lifecycle from the object ref-counting system for the small-string case.
- **`Optional<String>`/`Optional<Bytes>` specialization** -- Zero-overhead optional for string types using `kTVMFFINone` as the null sentinel in the same `TVMFFIAny` cell.

## Usage Examples

### Small string creation (no heap allocation)
```cpp
String s = "hello";   // 5 bytes <= 7, stored inline
Any a = s;
assert(a.type_index() == kTVMFFISmallStr);

String long_s = "this is a long string";  // > 7 bytes, heap allocated
Any b = long_s;
assert(b.type_index() == kTVMFFIStr);
```

### Cross-representation equality
```cpp
Any a = "a1";                      // small string
Any b = String(std::string("a1")); // forces heap allocation
assert(AnyEqual()(a, b));          // true: same content
assert(AnyHash()(a) == AnyHash()(b)); // same hash
```

### Optional<String> with zero overhead
```cpp
Optional<String> opt;               // null
assert(!opt.has_value());
opt = "hello";                      // small string
assert(opt.value() == "hello");
static_assert(sizeof(Optional<String>) == sizeof(String)); // 16 bytes
```
