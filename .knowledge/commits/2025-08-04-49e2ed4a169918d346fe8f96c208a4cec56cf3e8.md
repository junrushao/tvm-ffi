# Introduce small-string/bytes optimization: String and Bytes become value types backed by BytesBaseCell

## TL;DR

- `String` and `Bytes` are refactored from `ObjectRef` subclasses into standalone value types. Their backing storage is now a new `details::BytesBaseCell`, which holds a `TVMFFIAny` union internally. Strings up to 7 bytes (sizeof(int64_t) − 1) are stored on-stack without any heap allocation; longer strings continue to use heap-allocated `StringObj`/`BytesObj`.
- Two new type indices — `kTVMFFISmallStr = 11` and `kTVMFFISmallBytes = 12` — are added to `TVMFFITypeIndex` in the on-stack POD range [0, 64). The `TVMFFIAny.small_len` field is replaced by a proper union `{ uint32_t zero_padding; uint32_t small_str_len }`, activating the reserved small-string layout.
- `TypeTraits<String>` and `TypeTraits<Bytes>` are fully rewritten: `field_static_type_index` is now `kTVMFFIAny` (because the type may be either small or heap-allocated in any given `TVMFFIAny`), and the `CheckAnyStrict` method accepts both the small and large type indices. `AnyHash`, `AnyEqual`, `StructEqualHandler`, and `StructuralHashHandler` are updated to treat `kTVMFFISmallStr`/`kTVMFFISmallBytes` equivalently to their heap counterparts for equality and hashing.

## Impact

- API: **Breaking** for callers of `TVMFFIDataTypeToString` — the second parameter type changes from `TVMFFIObjectHandle*` to `TVMFFIAny*`. Any C/Python binding that calls this function must update its call site.
- API: **Breaking** for code that uses `String`/`Bytes` as `ObjectRef` subclasses — `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` is removed. Code that calls `ObjectRef::defined()`, `get()`, or `as<SomeObj>()` directly on a `String` must be updated. `Downcast<String>(r)` from an `ObjectRef` no longer works directly; wrap in `Any` first.
- API: `TypeTraits<String>::field_static_type_index` is now `kTVMFFIAny` (was `kTVMFFIStr`). Reflection columns for `String` fields will now reflect `kTVMFFIAny` as the schema type index. This may affect Python type-stub generation.
- Behavioral: `Any a = String("hello")` now produces `a.type_index() == kTVMFFISmallStr` (not `kTVMFFIStr`) for short strings. Code that checks for `kTVMFFIStr` exclusively must also handle `kTVMFFISmallStr`. `CheckAnyStrict` in the updated `TypeTraits<String>` handles both.
- Behavioral: `AnyEqual` is updated to return `true` when comparing a heap `kTVMFFIStr` with an on-stack `kTVMFFISmallStr` containing the same content — equality is content-based regardless of storage form.
- Behavioral: `std::hash<String>` is changed to use `std::hash<std::string_view>` instead of `StableHashBytes`; the structural hash (used in `AnyHash`) normalizes small/large forms to the same bucket.
- Flags/config: `zero_padding` must now be set to 0 in every `TypeTraits<T>::CopyToAnyView` write path. This is a new invariant enforced systematically across all specializations in `type_traits.h` and `string.h`.
- Data formats/schemas: The `TVMFFIAny` wire struct's bytes 4–7 (`small_len → zero_padding`/`small_str_len` union) now carry semantically significant data for small strings. Any serializer/deserializer that assumed those bytes were always zero must now preserve them.

## Design Elements

Design elements this commit consumes:
- `TVMFFIAny` wire struct and `TVMFFITypeIndex` enum (`0001-c-abi.md`) — uses the reserved `small_len`/`v_bytes` fields that were "reserved for future compact" to implement the actual optimization.
- `TypeTraits<T>` customization-point protocol (`0008-type-traits.md`) — specializes `TypeTraits<String>` and `TypeTraits<Bytes>` using the full protocol (all five static methods).
- `Optional<T>` specialization for `ObjectRef` types (`optional.h`) — was reused for String/Bytes; this commit adds a dedicated specialization since `String`/`Bytes` are no longer `ObjectRef`.
- `AnyHash`/`AnyEqual`/`StructEqualHandler`/`StructuralHashHandler` (`0003-any-anyview.md`, `0009-structural-eq-hash.md`) — extended to handle the two new type indices.
- `details::BytesObjBase`, `details::StringObj`, `details::BytesObj` (`0007-containers.md`) — still used for the large (heap) path inside `BytesBaseCell`.

Design elements this commit produces:
- **`details::BytesBaseCell`** — new internal value-type cell backing both `String` and `Bytes`. Encapsulates the dual small/large dispatch behind a uniform `data()`/`size()` interface. Tracks nullopt state via `kTVMFFINone` type index (enabling optional semantics without a separate bool).
- **`kTVMFFISmallStr = 11` / `kTVMFFISmallBytes = 12`** — two new static type indices occupying positions 11–12 in the on-stack POD range. Registration added to `TypeTable::InitBuiltinTypes()` in `object.cc`.
- **`TVMFFIAny.zero_padding` / `TVMFFIAny.small_str_len` layout** — activates the previously "reserved" second word of `TVMFFIAny`. All write paths that set `type_index` must zero `zero_padding`.
- **`Optional<String>` / `Optional<Bytes>` specialization** — adds a third `Optional` specialization (alongside `std::optional` fallback and `ObjectRef`-based pointer-null). Uses the `kTVMFFINone` sentinel inside `BytesBaseCell` to avoid a separate null flag.
- **`StableHashSmallStrBytes`** — new hash helper in `base_details.h` that hashes the 8-byte `v_uint64` directly on little-endian (fast path) or falls back to byte hashing on big-endian.
- **Normalization invariant for string equality/hash** — small-form and large-form strings with identical content are equal and hash-equal (normalized canonical form). Codified in `AnyHash`, `AnyEqual`, `StructEqualHandler`, `StructuralHashHandler`.

## Usage Examples

**Small string path — on-stack allocation:**
```cpp
// "hello" is 5 bytes ≤ 7 → stored on-stack
String s = "hello";
Any a = s;
assert(a.type_index() == TypeIndex::kTVMFFISmallStr);
assert(a.as<String>().value() == "hello");

// Long string → heap-allocated StringObj
Any b = "long string very long";
assert(b.type_index() == TypeIndex::kTVMFFIStr);
```

**Optional<String> null check:**
```cpp
Optional<String> opt = std::nullopt;
assert(!opt.has_value());
opt = String("abc");
assert(opt.has_value());
assert(opt.value() == "abc");
```

**AnyEqual cross-form comparison:**
```cpp
// heap-allocated "hello" and on-stack "hello" compare equal
Any heap = String(std::string("hello"));   // kTVMFFIStr (>7? no: 5 bytes so SmallStr)
// Actually, "hello" would be SmallStr because 5 ≤ 7.
// Use a 9-char string to demonstrate cross-form equality:
std::string long_key = "hello_key";       // 9 bytes → heap kTVMFFIStr
Any a1 = String(long_key);               // kTVMFFIStr
Any a2 = AnyView(long_key.c_str());      // AnyView → promoted to Any → kTVMFFIStr
AnyEqual eq;
assert(eq(a1, a2));                      // equal by content, not pointer
```

**TypeTraits field_static_type_index change impact:**
```cpp
// OLD behavior: TypeTraits<String>::field_static_type_index == kTVMFFIStr
// NEW behavior: TypeTraits<String>::field_static_type_index == kTVMFFIAny
// Impact: reflection field schema for String fields reports kTVMFFIAny
static_assert(TypeTraits<String>::field_static_type_index == TypeIndex::kTVMFFIAny);
```
