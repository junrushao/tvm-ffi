# Introduce small string/bytes optimization storing short strings inline in TVMFFIAny
## TL;DR
- Implements small string optimization (SSO) for `String` and `Bytes`: strings up to 7 bytes are stored inline in the 8-byte `v_bytes` union field of `TVMFFIAny`, using new POD type indices `kTVMFFISmallStr = 11` and `kTVMFFISmallBytes = 12`. Longer strings continue to use heap-allocated `StringObj`/`BytesObj`.
- Fundamentally restructures `String` and `Bytes` from `ObjectRef` subclasses backed by a single `ObjectPtr<StringObj>` to value types backed by a new `details::BytesBaseCell` that holds a `TVMFFIAny` internally, enabling dual representation (inline POD or heap object) behind a uniform interface.
- Updates `AnyHash`, `AnyEqual`, structural equality/hash, `Optional<String>`, `Optional<Bytes>`, `InplaceConvertAnyViewToAny`, `TypeTraits<String>`, `TypeTraits<Bytes>`, and all `CopyToAnyView`/`MoveToAny` call sites to consistently zero the new `zero_padding` field (formerly `small_len`) and handle cross-representation comparisons between small and heap-allocated strings.

## Impact
- API: **Breaking** -- `String` and `Bytes` are no longer `ObjectRef` subclasses. Code that assigns a `String` to an `ObjectRef` variable, calls `String::use_count()`, `String::get()`, `String::defined()`, or uses `Downcast<String>(ObjectRef)` will fail to compile. The `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` macro usage is removed from both classes. The `TVMFFIDataTypeToString` C API signature changes from `TVMFFIObjectHandle*` out-param to `TVMFFIAny*` out-param.
- Flags/config: none.
- Data formats/schemas: The `TVMFFIAny` C struct layout changes: the `small_len` field (offset 4, 4 bytes) is replaced by a union of `zero_padding` (uint32_t) and `small_str_len` (uint32_t). The `v_bytes` union member (char[8]) is added at offset 8 for inline string storage. New type index values `kTVMFFISmallStr = 11` and `kTVMFFISmallBytes = 12` are added in the POD range.
- Performance: Short strings (up to 7 bytes) avoid heap allocation entirely. This is significant because many FFI type keys, field names, and error kinds are short. `AnyEqual` gains a fast path comparing the full 16-byte `TVMFFIAny` as two `int64_t` values.

## Design Elements
Design elements this commit **consumes**:

- **TVMFFIAny C struct and type index partitioning** ([`.knowledge/designs/0001-c-abi.md`](../designs/0001-c-abi.md), [`.knowledge/ADRs/0002-type-index-partitioning.md`](../ADRs/0002-type-index-partitioning.md)): The commit allocates two new POD type indices (`kTVMFFISmallStr = 11`, `kTVMFFISmallBytes = 12`) from the available range `[11, 63)`. It activates the previously reserved `small_len` field (documented in `0002-any-system.md` as a non-goal: "Small-string optimization (the `small_len` field is reserved but not yet used)").
- **Any/AnyView type erasure** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): The commit modifies `InplaceConvertAnyViewToAny` to delegate to `TypeTraits<String>::MoveToAny` / `TypeTraits<Bytes>::MoveToAny` instead of manually setting `type_index` and `v_obj`. It introduces a `zero_padding` zeroing invariant throughout all `CopyToAnyView` and `MoveToAny` implementations.
- **Container system / String and Bytes** ([`.knowledge/designs/0005-containers.md`](../designs/0005-containers.md)): The commit fundamentally changes `String` and `Bytes` from `ObjectRef`-based wrappers to value types. This removes them from the `ObjectRef` hierarchy while preserving their content-addressable semantics.
- **TypeTraits protocol** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): `TypeTraits<String>` and `TypeTraits<Bytes>` are rewritten from `ObjectRefWithFallbackTraitsBase` specializations to fully custom implementations that handle the dual small/heap representation. `CheckAnyStrict` now returns true for both the small and heap type indices.
- **AnyHash / AnyEqual** ([`.knowledge/designs/0002-any-system.md`](../designs/0002-any-system.md)): Both functors are extended with cross-representation comparison logic: small string hashes use `kTVMFFIStr` as the type key (not `kTVMFFISmallStr`) to ensure hash consistency with heap strings.

Design elements this commit **produces**:

- **Small string optimization (SSO) for String/Bytes**: A new dual-representation pattern where strings up to 7 bytes are stored as POD values in `TVMFFIAny.v_bytes[8]` with `type_index = kTVMFFISmallStr/kTVMFFISmallBytes` and `small_str_len` recording the length. Strings longer than 7 bytes fall back to heap-allocated `StringObj`/`BytesObj` with `type_index = kTVMFFIStr/kTVMFFIBytes`. The threshold constant `kMaxSmallBytesLen = sizeof(int64_t) - 1 = 7` is embedded in `BytesBaseCell::InitSpaceForSize`.
- **BytesBaseCell**: A new internal class (`include/tvm/ffi/string.h`) that serves as the unified backing storage for both `String` and `Bytes`. It holds a `TVMFFIAny data_` member and provides ref-counting for heap objects, data/size accessors that branch on `type_index < kTVMFFIStaticObjectBegin`, and move/copy operations for `Any`/`AnyView` interop.
- **zero_padding invariant**: Every `CopyToAnyView`, `MoveToAny`, `reset()`, default constructor, and move constructor now explicitly sets `data_.zero_padding = 0`. This makes the `zero_padding` field a mandatory-zero region for all non-small-string values, enabling the 16-byte fast-path equality check in `AnyEqual` and the extended `Any::same_as` comparison.
- **Cross-representation equality/hash contract**: `AnyHash` uses `kTVMFFIStr` (not `kTVMFFISmallStr`) as the hash type key for small strings, and `kTVMFFIBytes` for small bytes. `AnyEqual` performs 8 combinations of cross-representation comparisons (small-str vs heap-str, heap-str vs small-str, small-bytes vs heap-bytes, heap-bytes vs small-bytes). Structural equality/hash handlers in `src/ffi/extra/` mirror this logic.
- **Optional<String> / Optional<Bytes> specialization**: A new `Optional` partial specialization for `String` and `Bytes` that uses the `BytesBaseCell(std::nullopt)` sentinel (setting `type_index = kTVMFFINone`) rather than wrapping in `std::optional`. This ensures `sizeof(Optional<String>) == sizeof(String) == 16`.

## Key Implementations

### BytesBaseCell: The dual-storage engine

`details::BytesBaseCell` at `include/tvm/ffi/string.h` is the core implementation. Key design decisions:

- **Storage**: A single `TVMFFIAny data_` member (16 bytes). When `data_.type_index < kTVMFFIStaticObjectBegin`, the string content lives inline in `data_.v_bytes[0..small_str_len-1]`. When `data_.type_index >= kTVMFFIStaticObjectBegin`, the string is heap-allocated and `data_.v_obj` points to a `StringObj`/`BytesObj`.
- **InitSpaceForSize**: The allocation decision point. If `size <= 7`, writes to `data_.v_bytes` directly. Otherwise, allocates via `make_inplace_array_object` (same as before). Returns a `char*` to the writable destination.
- **Ref-counting**: Copy constructor calls `IncRef` only when `type_index >= kTVMFFIStaticObjectBegin`. Destructor calls `DecRef` only in that case. Move constructor steals the data and sets the source to `kTVMFFINone`.
- **Null sentinel**: `BytesBaseCell(std::nullopt)` sets `type_index = kTVMFFINone`, used by `Optional<String>` to represent nullopt without a separate boolean flag.

### zero_padding invariant enforcement

The former `small_len` field is replaced by a union of `zero_padding` and `small_str_len`. For non-small-string values, `zero_padding` must be zero. This is enforced at every write site in `type_traits.h`, `any.h`, `rvalue_ref.h`, `variant.h`, `dtype.h`, and `string.h` -- a total of ~25 call sites adding `result->zero_padding = 0`. This enables:
- `Any::same_as` to compare `zero_padding` in addition to `type_index` and `v_int64`.
- `AnyEqual` to use a 16-byte bitwise fast path: `lhs_as_int64[0] == rhs_as_int64[0] && lhs_as_int64[1] == rhs_as_int64[1]`.

### Hash consistency across representations

`AnyHash` uses the canonical heap type index (`kTVMFFIStr` / `kTVMFFIBytes`) when hashing small strings, so that `AnyHash(String("ab")) == AnyHash(String(std::string("ab")))` holds even when one is stored inline and the other is heap-allocated. The small-string hash uses `StableHashSmallStrBytes`, which on little-endian platforms (the common case) hashes the raw `v_uint64` modulo a prime, bypassing the per-byte `StableHashBytes` loop.

### TypeTable bootstrap changes

In `src/ffi/object.cc`, the `TypeTable` constructor now registers `kTVMFFISmallStr` and `kTVMFFISmallBytes` as reserved POD type indices via `ReserveBuiltinTypeIndex`. The `CopyString` helper is changed to use explicit `MakeInplaceString` (a local static helper) instead of constructing a `String` -- because `String` no longer guarantees an `ObjectRef` result for short strings, and the `TypeTable` needs stable `TVMFFIByteArray` pointers into heap-allocated string objects.

### C API changes

- `TVMFFIDataTypeToString` signature changes from `TVMFFIObjectHandle* out` to `TVMFFIAny* out`, reflecting that the output may be a small string (POD) rather than a heap object.
- New inline accessor `TVMFFISmallBytesGetContentByteArray(const TVMFFIAny*)` returns a `TVMFFIByteArray` view of the inline content.
- `TVMFFIAny.small_len` renamed to a union of `zero_padding` / `small_str_len`.

### Commented-out RValueRef tests

Two test cases in `tests/cpp/test_rvalue_ref.cc` are commented out. This is because `String` is no longer an `ObjectRef`, so it cannot be wrapped in `RValueRef<String>` (which requires an `ObjectRef` type parameter). This is a known regression noted in the test file.

## Reflection

### Design docs to write

- **`.knowledge/designs/0005-containers.md` -- update String/Bytes section**: The current design doc describes `String` and `Bytes` as `ObjectRef` subclasses backed by `BytesObjBase`. This commit fundamentally changes their representation. The doc should be updated to describe:
  - The `BytesBaseCell` dual-storage pattern (inline POD vs heap object).
  - The SSO threshold (`kMaxSmallBytesLen = 7`).
  - The cross-representation equality/hash invariant.
  - The fact that `String` and `Bytes` are no longer part of the `ObjectRef` hierarchy.
  - This helps future commit mining by grounding any changes to String/Bytes behavior, container storage, or `TypeTraits` specializations.

- **`.knowledge/designs/0002-any-system.md` -- update small_len / zero_padding**: The current doc lists small-string optimization as a non-goal and notes `small_len` is "reserved for future use." This commit activates it. The doc should be updated to:
  - Replace the non-goal statement with the actual SSO design.
  - Document the `zero_padding` invariant (must be zero for all non-small-string values).
  - Add `kTVMFFISmallStr` and `kTVMFFISmallBytes` to the type index layout.
  - Document the cross-representation hash consistency contract (small strings hash with the canonical heap type index).
  - This helps future commits that touch `AnyHash`, `AnyEqual`, `Any::same_as`, or any `CopyToAnyView`/`MoveToAny` implementation.

### ADRs to write

- **`.knowledge/ADRs/0011-small-string-optimization.md`**: Decision context: Short strings (type keys, field names, dtype strings) are the most common string values in the FFI. Alternatives considered: (1) keep all strings heap-allocated (simpler, but every short string incurs `make_inplace_array_object` + ref-counting overhead), (2) use a separate `SmallString` type (avoids breaking `ObjectRef` hierarchy, but doubles the API surface and requires conversion at every boundary). Trade-off: The chosen approach changes `String`/`Bytes` from `ObjectRef` to value types, breaking downstream code that treats them as `ObjectRef`, but unifies the representation and avoids heap allocation for the common case. The 7-byte threshold is derived from `sizeof(int64_t) - 1` (one byte reserved for null terminator compatibility).

### Design diagrams to draw

- **Mermaid**: A diagram showing the dual-storage layout of `BytesBaseCell`:
  - When `type_index < kTVMFFIStaticObjectBegin`: `[type_index 4B] [small_str_len 4B] [v_bytes[0..6] + \0]`
  - When `type_index >= kTVMFFIStaticObjectBegin`: `[type_index 4B] [zero_padding=0 4B] [v_obj -> StringObj/BytesObj]`
  - The diagram should also show how `AnyHash` maps both representations to the same hash bucket using the canonical heap type index.
