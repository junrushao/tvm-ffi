# Introduce small string/bytes optimization (SSO)
## TL;DR
- `String` and `Bytes` are no longer `ObjectRef` subclasses. They are standalone value types backed by a new `details::BytesBaseCell` which holds a `TVMFFIAny` directly, enabling inline storage for strings <=7 bytes without heap allocation.
- Two new C ABI type indices `kTVMFFISmallStr` (11) and `kTVMFFISmallBytes` (12) are added to the POD range `[0, 64)`. The `small_len` field in `TVMFFIAny` is replaced by a `zero_padding`/`small_str_len` union, and a `v_bytes[8]` member is added to the value union.
- All `TypeTraits<String>` and `TypeTraits<Bytes>` specializations are rewritten from `ObjectRefWithFallbackTraitsBase` to standalone custom traits. `AnyHash`/`AnyEqual` and structural equal/hash are updated to treat small and heap-allocated strings as semantically equivalent.

## Impact
- API: **Breaking** -- `String` and `Bytes` no longer inherit `ObjectRef`. Code that assigns `String` to `ObjectRef`, calls `.get()`, `.use_count()`, or uses `TVM_FFI_DEFINE_NOTNULLABLE_OBJECT_REF_METHODS` on these types will fail to compile. `TVMFFIDataTypeToString` C signature changes from `TVMFFIObjectHandle*` to `TVMFFIAny*`.
- Behavioral: Small strings (<=7 bytes) no longer heap-allocate. Hash/equality semantics are preserved across small vs heap representations. `Any::same_as` now also compares `zero_padding` field.
- Flags/config: none
- Data formats/schemas: `TVMFFIAny.small_len` is renamed to `zero_padding`/`small_str_len` union. All `CopyToAnyView` implementations now explicitly set `zero_padding = 0`.

Design elements this commit produces:
- **`BytesBaseCell`** -- new internal cell class enabling dual-representation (inline vs heap) for String/Bytes
- **`kTVMFFISmallStr` / `kTVMFFISmallBytes`** type indices -- new POD type indices in C ABI
- **`zero_padding` / `small_str_len`** union -- replaces `small_len` in `TVMFFIAny`
- **`v_bytes[8]`** union member in `TVMFFIAny` -- inline byte storage
- **`TVMFFISmallBytesGetContentByteArray`** -- new C API inline helper

## Usage Examples

Small string is stored inline (no heap allocation); large string falls back to heap:
```cpp
// Small string (<=7 bytes) -- stored inline in TVMFFIAny
String s = "hello";  // type_index = kTVMFFISmallStr, data in v_bytes
assert(sizeof(s) == 16);  // same size as TVMFFIAny

// Large string (>7 bytes) -- heap-allocated as before
String large = "this is a long string";  // type_index = kTVMFFIStr, v_obj points to heap

// Hash/equality is representation-transparent
Any a = "a1";                         // kTVMFFISmallStr
Any b = String(std::string("a1"));    // kTVMFFIStr (forced heap via std::string move)
assert(AnyHash()(a) == AnyHash()(b)); // same hash
assert(AnyEqual()(a, b));             // equal

// Optional<String> has zero overhead
Optional<String> opt;                 // uses kTVMFFINone sentinel
assert(!opt.has_value());
opt = "hello";
assert(opt.value() == "hello");
static_assert(sizeof(Optional<String>) == sizeof(String));
```
