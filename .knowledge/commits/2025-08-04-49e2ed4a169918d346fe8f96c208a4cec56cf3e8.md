# Introduce small string/bytes optimization for String and Bytes

## TL;DR
- `String` and `Bytes` are no longer `ObjectRef` subclasses; they now use a `details::BytesBaseCell` wrapper around `TVMFFIAny` that stores strings <= 7 bytes inline on the stack (no heap allocation).
- Two new type indices `kTVMFFISmallStr` (11) and `kTVMFFISmallBytes` (12) in the POD range distinguish inline strings from heap-allocated ones (`kTVMFFIStr`/`kTVMFFIBytes`).
- `TVMFFIAny.small_len` is renamed to a `zero_padding`/`small_str_len` union. All `TypeTraits::CopyToAnyView`/`MoveToAny` call sites now explicitly zero `zero_padding` to maintain the comparison invariant.

## Impact
- API: `String` and `Bytes` no longer inherit `ObjectRef`. Code using `ObjectRef r = String("hello")` must change to `Any r = String("hello")`. `TVMFFIDataTypeToString` C API signature changed (output param is `TVMFFIAny*` not `TVMFFIObjectHandle*`).
- Behavioral: Short strings (<= 7 bytes) are stored inline without heap allocation. `AnyHash` and `AnyEqual` now treat `SmallStr`/`SmallBytes` as equivalent to their heap-allocated counterparts. `String(nullptr)` comparisons are now deleted at compile time.
- Flags/config: none
- Data formats/schemas: `TVMFFIAny` layout changed: `small_len` field renamed to `zero_padding`/`small_str_len` union. All code writing `TVMFFIAny` must zero `zero_padding` for non-small-string types.

## Design Elements
Design elements this commit consumes:
- `TVMFFIAny` 16-byte layout ([0001-ffi-c-abi](../../.knowledge/design-records/0001-ffi-c-abi.md)) -- extends the union with `v_bytes`/`v_uint64` and renames `small_len`
- `TypeTraits<T>` protocol ([0002-ffi-any-value-system](../../.knowledge/design-records/0002-ffi-any-value-system.md)) -- rewrites String/Bytes traits
- `ObjectRef` pattern ([0003-ffi-object-system](../../.knowledge/design-records/0003-ffi-object-system.md)) -- String/Bytes depart from this pattern
- `BytesObjBase` / inplace allocation ([0006-ffi-containers](../../.knowledge/design-records/0006-ffi-containers.md)) -- large strings still use `BytesObjStdImpl` and `make_inplace_array_object`
- `StructuralEqual`/`StructuralHash` ([0009-ffi-structural-eq-hash](../../.knowledge/design-records/0009-ffi-structural-eq-hash.md)) -- extended for small string types

Design elements this commit produces:
- **`kTVMFFISmallStr` / `kTVMFFISmallBytes` type indices**: New POD-range type discriminators for inline strings. Requires cross-type equality/hashing with `kTVMFFIStr`/`kTVMFFIBytes`.
- **`BytesBaseCell`**: New internal wrapper class that holds a `TVMFFIAny` and dispatches `data()`/`size()` between small (inline) and large (heap) paths. Used by both `String` and `Bytes`.
- **`zero_padding` invariant**: The `small_len` field is now a union of `zero_padding`/`small_str_len`. All `TypeTraits<T>::CopyToAnyView`/`MoveToAny` must zero `zero_padding` to ensure `same_as()` and `AnyEqual` correctness.
- **Non-ObjectRef String/Bytes**: `String` and `Bytes` are now value types backed by `BytesBaseCell`, not `ObjectRef` subclasses. This is a fundamental design change.
- **`Optional<String>` / `Optional<Bytes>` specialization**: New `Optional` specialization using `BytesBaseCell(std::nullopt)` to represent nullopt (type_index == kTVMFFINone). `sizeof(Optional<String>) == sizeof(String)`.
- **`TVMFFISmallBytesGetContentByteArray`**: New C API inline accessor for reading small string content as `TVMFFIByteArray`.
- **`StableHashSmallStrBytes`**: New hash function for inline small string data with endian-aware fast path.
- **Deleted `nullptr` comparison operators**: `String` comparison with `nullptr` is now a compile-time error.

## Usage Examples

**Small string stored inline, no heap allocation:**
```cpp
// Short string: stored inline in TVMFFIAny (type_index = kTVMFFISmallStr)
String s{"hello"};  // 5 bytes <= 7, inline
Any a = s;
assert(a.type_index() == TypeIndex::kTVMFFISmallStr);

// Long string: heap-allocated (type_index = kTVMFFIStr)
Any c = String("long string very long");
assert(c.type_index() == TypeIndex::kTVMFFIStr);

// Cross-type equality: small and large strings with same content are equal
Any small_str = "a1";                     // kTVMFFISmallStr
Any large_str = String(std::string("a1")); // kTVMFFIStr
assert(AnyEqual()(small_str, large_str));
assert(AnyHash()(small_str) == AnyHash()(large_str));
```

**Optional<String> with zero overhead:**
```cpp
Optional<String> opt_str;
assert(!opt_str.has_value());
assert(opt_str.value_or("default") == "default");

opt_str = "hello";
assert(opt_str.value() == "hello");
static_assert(sizeof(Optional<String>) == sizeof(String));  // no overhead
```
