# Reimplement c_class as register_object + structural dunders

## TL;DR
- `@c_class` rewritten from thin `register_object` pass-through to a `dataclass`-style decorator with `init`, `repr`, `eq`, `order`, `unsafe_hash` boolean flags controlling which structural dunders are installed.
- `_install_dataclass_dunders` installs `__eq__`/`__ne__`/`__hash__`/`__lt__`/`__le__`/`__gt__`/`__ge__` delegating to C++ `RecursiveEq`/`RecursiveHash`/`RecursiveLt` etc.; user-defined dunders never overwritten.
- `_install_init` extracted from `_add_class_attrs` into a standalone call (no longer auto-called by `_add_class_attrs`); `register_object` no longer auto-installs init — `c_class` and `register_object` now control init separately.

## Impact
- API: `@c_class` gains 5 keyword params; default behavior preserved (init+repr only). `_install_init` no longer called by `_add_class_attrs`.
- Behavioral: `@c_class(eq=True, unsafe_hash=True, order=True)` now works for structural comparison.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples

```python
@c_class("my.Point", eq=True, unsafe_hash=True, order=True)
class Point(Object):
    x: float
    y: float

p1 = Point(1.0, 2.0)
p2 = Point(1.0, 2.0)
assert p1 == p2
assert hash(p1) == hash(p2)
```
