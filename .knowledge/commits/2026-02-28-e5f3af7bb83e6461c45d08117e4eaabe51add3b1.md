# Reimplement c_class as register_object + structural dunders

## TL;DR
- Rewrites `@c_class` from thin `register_object` pass-through into a dataclass-style decorator that installs structural dunders (`__init__`, `__repr__`, `__eq__`/`__ne__`, `__hash__`, `__lt__`/`__le__`/`__gt__`/`__ge__`) delegating to C++ recursive operations.
- Adds `@dataclass_transform` decorator for IDE/type-checker support.
- Migrates all test objects in `tvm_ffi.testing` to use `@c_class`.

## Key Exports

**`c_class` decorator** (`dataclasses/c_class.py`):
- Combines `register_object` with auto-installation of structural dunders
- Parameters: `type_key`, `eq` (default True), `order` (default False), `repr` (default True), `hash` (default: auto from eq), `init` (default True)
- Decorated with `@dataclass_transform`

**Structural dunders installed:**
- `__eq__` / `__ne__` -> `RecursiveEq`
- `__hash__` -> `RecursiveHash`
- `__lt__` / `__le__` / `__gt__` / `__ge__` -> `RecursiveLt` / `RecursiveLe` / `RecursiveGt` / `RecursiveGe`
- `__repr__` -> `ReprPrint`
- `__init__` -> `_make_init` (from reflection)

## Impact
- API: `@c_class` now auto-installs dunders. `@register_object` remains the low-level registration without dunders.
- Behavioral: `c_class`-decorated objects now support `==`, `hash()`, `<`, `>` out of the box.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `RecursiveEq/Hash/Lt/Le/Gt/Ge` from `dataclass.h`
- `_make_init` from `registry.py`

Design elements this commit produces:
- **c_class = register_object + structural dunders** pattern -- establishes convention that `@c_class` is the recommended decorator for reflected types needing Python dataclass semantics

## Usage Examples
```python
@c_class("testing.MyClass")
class MyClass(Object):
    v_i64: int
    v_f64: float

a = MyClass(1, 2.0)
b = MyClass(1, 2.0)
assert a == b
assert hash(a) == hash(b)
assert not a < b
```
