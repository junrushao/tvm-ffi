# Reimplement c_class as register_object + structural dunders
## TL;DR
- Rewrites the `@c_class` decorator from a thin `register_object` pass-through into a `dataclass`-style decorator that combines FFI type registration with structural dunder methods derived from C++ reflection metadata.
- `@c_class` now installs `__init__`, `__repr__`, `__eq__`/`__ne__`, `__hash__`, and ordering operators (`__lt__`, `__le__`, `__gt__`, `__ge__`) -- all delegating to the corresponding C++ recursive operations (`RecursiveEq`, `RecursiveHash`, `RecursiveLt`, etc.).
- Adds `@dataclass_transform` decorator for IDE/type-checker support (pyright, mypy).
- Introduces `_install_dataclass_dunders` in `registry.py` as the core dunder-installation function.
- Migrates all test objects in `tvm_ffi.testing` from `@register_object` to `@c_class`.
- Moves init installation from `_add_class_attrs` (in `@register_object`) to `_install_dataclass_dunders` (in `@c_class`), making `@register_object` no longer auto-install `__init__`.

## Impact
- **API**: `@c_class(type_key, *, init, repr, eq, order, unsafe_hash)` -- new keyword arguments. Old usage `@c_class("key")` continues to work with sensible defaults (`init=True`, `repr=True`, others off). The `eq`, `order`, `unsafe_hash` parameters default to `False` to avoid breaking existing code. No breaking changes.
- **Type checker support**: `@dataclass_transform(eq_default=False, order_default=False)` on `c_class` enables pyright/mypy to understand `@c_class`-decorated classes as dataclass-like, providing autocomplete and type checking for the `__init__` signature.
- **Behavioral separation**: `@register_object` no longer installs `__init__` automatically -- that is now the responsibility of `_install_dataclass_dunders` (called by `@c_class`). This means bare `@register_object` classes that relied on auto-init must either switch to `@c_class` or define their own `__init__`.
- **Registration order change**: In `@register_object`, `_add_class_attrs` now runs before `__tvm_ffi_type_info__` is set (reversed from the previous commit `b1abaea`). This is because `_add_class_attrs` no longer calls `_install_init`, so it does not need `__tvm_ffi_type_info__`.
- **Flags/config**: None.
- **Data formats/schemas**: None.

## Design Elements

Design elements this commit **consumes**:

- **Dataclass Operations** ([`.knowledge/designs/0027-dataclass-operations.md`](../designs/0027-dataclass-operations.md)): The C++ `RecursiveEq`, `RecursiveHash`, `RecursiveLt/Le/Gt/Ge` functions exposed to Python via `_ffi_api` (from commits `b87196f` and `5796ff4`).
- **Auto-Generated `__ffi_init__` from Reflection** ([`.knowledge/ADRs/0068-auto-init-from-reflection.md`](../ADRs/0068-auto-init-from-reflection.md)): The `_install_init` / `_make_init` machinery (from commit `b1abaea`).
- **Python Bindings** ([`.knowledge/designs/0014-python-bindings.md`](../designs/0014-python-bindings.md)): The `@register_object` decorator and `_add_class_attrs` flow.

Design elements this commit **produces**:

- **`_install_dataclass_dunders`**: Central function in `registry.py` that installs structural dunders on a class. Parameters: `init`, `repr`, `eq`, `order`, `unsafe_hash`. Each dunder delegates to the corresponding C++ recursive operation. User-defined dunders in `cls.__dict__` are never overwritten. The `_is_comparable` guard checks bidirectional `isinstance` before delegating to C++, returning `NotImplemented` for unrelated types (following Python data model conventions).
- **`@c_class` as `register_object` + `_install_dataclass_dunders`**: The decorator first calls `register_object(type_key)(cls)` to register the type, then calls `_install_dataclass_dunders(cls, ...)` to install structural dunders. This two-phase approach keeps `register_object` lightweight while `c_class` adds the dataclass-style conveniences.
- **Test fixture migration**: All `tvm_ffi.testing` classes now use `@c_class` instead of `@register_object`. Some gain explicit `eq=True, order=True, unsafe_hash=True` for test purposes (e.g., `_TestCxxClassDerived`). `_TestCxxNoAutoInit` uses `init=False`.
