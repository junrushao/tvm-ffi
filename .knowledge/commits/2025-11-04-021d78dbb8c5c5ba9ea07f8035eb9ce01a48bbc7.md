# Add tests for FileLock utility and harden re-entrancy behavior
## TL;DR
- Adds comprehensive pytest suite for `FileLock` covering basic acquire/release, context manager, re-entrancy, exception safety, and multi-process concurrent access (16 workers).
- Hardens `acquire()` to return `False` if the lock is already held by the same instance, and `blocking_acquire()` to raise `RuntimeError` — fixing inconsistent cross-platform behavior on re-entrant calls.
- Improves docstrings to NumPy-style RST with explicit `Returns`/`Raises` sections.

## Key Exports
The commit does not add new public API. It tightens the contract of existing methods:

```python

    # Interacts with: tvm_ffi.cpp.build_inline (concurrent build serialization)

        # Invariant: idempotent per instance — second call returns False without side effects
        ...

        # NEW: raises RuntimeError("Lock is already held by this instance.") if _file_descriptor is not None

        # Invariant: raises RuntimeError before polling if already held
        ...
```

## Impact
- API: None — no new symbols. Behavioral tightening of existing methods.
- Behavioral: `acquire()` now returns `False` on re-entrant call instead of platform-dependent behavior. `blocking_acquire()` raises `RuntimeError` on re-entrant call instead of looping.
- Flags/config: None.
- Data formats/schemas: None.

## Usage Examples
From `tests/python/utils/test_filelock.py` — basic lock lifecycle and re-entrancy guard:
```python
from tvm_ffi.utils.lockfile import FileLock

# Context manager usage (blocking)
with FileLock("/tmp/test.lock") as lock:
    assert lock._file_descriptor is not None
# Lock released on exit

# Re-entrancy guard
lock = FileLock("/tmp/test.lock")
assert lock.acquire() is True   # first call succeeds
assert lock.acquire() is False  # second call returns False (not re-entrant)
lock.release()
```
