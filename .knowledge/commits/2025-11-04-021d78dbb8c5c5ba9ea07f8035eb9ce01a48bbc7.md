# Add tests for FileLock utility and harden re-entrant acquisition guard
## TL;DR
- Adds comprehensive pytest suite for `FileLock` covering basic acquire/release, context manager, re-entrant guard, exception safety, and cross-process concurrency (16 workers).
- Hardens `FileLock.acquire()` and `blocking_acquire()` with an explicit re-entrant guard: if `_file_descriptor is not None`, `acquire()` returns `False` and `blocking_acquire()` raises `RuntimeError`.
- Improves docstrings to NumPy-style with explicit Returns/Raises sections and clarifies that the lock is advisory and not re-entrant within the same process.

## Key Exports

```python
class FileLock:
    """Cross-platform advisory file lock (not re-entrant within same instance)."""
    lock_file_path: str
    _file_descriptor: int | None  # None when unlocked

    def acquire(self) -> bool: ...
        # Changed: returns False immediately if _file_descriptor is not None
        # Invariant: after successful acquire, _file_descriptor is set; after failure, it is None
        # Interacts with: fcntl.flock (Unix), msvcrt.locking (Windows)

    def blocking_acquire(self, timeout: float | None = None, poll_interval: float = 0.1) -> bool: ...
        # Changed: raises RuntimeError if _file_descriptor is not None (already held)
        # Interacts with: acquire() in polling loop
        # Invariant: caller must not hold the lock; use release() first

    def release(self) -> None: ...
        # Unchanged
```

## Impact
- API: `acquire()` now returns `False` (instead of undefined behavior) when called on an already-held lock instance. `blocking_acquire()` now raises `RuntimeError` instead of potentially deadlocking when called on an already-held instance.
- Behavioral: Prevents accidental double-acquisition on the same `FileLock` instance. Previously, calling `acquire()` twice without `release()` would attempt to re-open and re-lock the file, leading to platform-dependent behavior.
- Flags/config: none
- Data formats/schemas: none

## Design Elements
Design elements this commit consumes:
- `FileLock` (`python/tvm_ffi/utils/lockfile.py`) -- cross-platform advisory file lock used by `build_module` to serialize concurrent builds (see `.knowledge/designs/0011-module-system.md`)

Design elements this commit produces:
- Re-entrant guard pattern: check `_file_descriptor is not None` before acquisition to provide deterministic behavior on double-acquire
- Cross-process concurrency test pattern using subprocess workers (`filelock_worker.py`) and a shared counter file

## Usage Examples

Basic lock lifecycle and re-entrant guard behavior (from `test_filelock.py`):

```python
from tvm_ffi.utils.lockfile import FileLock

lock = FileLock("/tmp/my.lock")

# First acquire succeeds
assert lock.acquire() is True

# Second acquire on same instance returns False (re-entrant guard)
assert lock.acquire() is False

lock.release()

# Context manager usage (calls blocking_acquire/release)
with FileLock("/tmp/my.lock") as lock:
    # critical section
    pass
```

Cross-process concurrency test pattern (from `test_filelock.py`):

```python
import subprocess, sys
from pathlib import Path

# Launch N workers that each acquire lock, read-increment-write a counter
num_workers = 16
processes = [
    subprocess.Popen([sys.executable, "filelock_worker.py", str(i), lock_path, counter_file])
    for i in range(num_workers)
]
for p in processes:
    p.wait(timeout=60.0)
# counter_file should contain num_workers (no race conditions)
```
