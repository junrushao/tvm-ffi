# Add tests for FileLock utility and harden its re-entrance semantics

## TL;DR
- Adds a comprehensive pytest suite (`tests/python/utils/test_filelock.py`) covering basic acquire/release, context manager usage, double-acquire guard, exception-safe release, and multi-process concurrent access with 16 subprocess workers.
- Hardens `FileLock.acquire()` to return `False` immediately when the lock is already held by the same instance (previously would attempt to re-open/re-lock the file, leaking the existing file descriptor).
- Hardens `FileLock.blocking_acquire()` to raise `RuntimeError` when the lock is already held by the same instance (previously would spin indefinitely since `acquire()` would always succeed on POSIX due to `fcntl.flock` being reentrant within a process).
- Updates docstrings of `acquire()`, `blocking_acquire()`, and the class-level docstring to use NumPy-style parameter/return/raises sections and to document the same-process re-entrance limitation.

## Key Exports

**Classes (modified)**:
- `tvm_ffi.utils.FileLock`:
  - `acquire() -> bool` -- now returns `False` when `_file_descriptor is not None` (lock already held by this instance), instead of attempting re-acquisition.
  - `blocking_acquire(timeout, poll_interval) -> bool` -- now raises `RuntimeError("Lock is already held by this instance.")` when `_file_descriptor is not None`.
  - Class docstring updated: notes that the lock does not prevent the same process from acquiring it multiple times; caller responsibility to manage this.

**New test files**:
- `tests/python/utils/test_filelock.py` -- 5 test functions: `test_basic_lock_acquire_and_release`, `test_context_manager`, `test_multiple_acquire_attempts`, `test_exception_in_context_manager`, `test_concurrent_access`.
- `tests/python/utils/filelock_worker.py` -- standalone subprocess worker for the concurrent access test.

## Impact
- API: `acquire()` now returns `False` for double-acquire on the same instance instead of undefined behavior (potential fd leak or silent success on POSIX). `blocking_acquire()` now raises `RuntimeError` for double-acquire instead of spinning indefinitely. Both changes are behavioral tightening of previously undefined edge cases.
- ABI: None.
- Behavioral: Code that previously called `acquire()` twice on the same `FileLock` instance without an intervening `release()` will now get `False` instead of platform-dependent behavior. Code that called `blocking_acquire()` twice will now get `RuntimeError` instead of an infinite loop.
- Flags/config: None.
- Data formats/schemas: None.

## Design Elements
Design elements this commit consumes:
- **`FileLock` utility** (`.knowledge/commits/2025-09-05-83805ec949227620d05e61358a4ecb4f0c931979.md`): The original `FileLock` class introduced with `load_inline`. This commit adds tests and hardens its behavior.
- **Advisory file locking convention** (`.knowledge/designs/0017-inline-module-compilation.md`): `FileLock` is used by `load_inline` to serialize concurrent builds targeting the same cache directory. The tests validate cross-platform correctness of this mechanism.

Design elements this commit produces:
- **FileLock re-entrance guard**: Establishes the invariant that a single `FileLock` instance cannot be acquired twice without an intervening `release()`. `acquire()` returns `False`; `blocking_acquire()` raises `RuntimeError`. This prevents fd leaks and infinite loops.
- **Multi-process lock correctness test pattern**: The `test_concurrent_access` test spawns 16 subprocesses via `subprocess.Popen`, each acquiring the same lock, reading a shared counter file, sleeping (to amplify race conditions), incrementing, and writing back. The final counter must equal `num_workers`, proving mutual exclusion across processes.

## Usage Examples

### Testing double-acquire guard
```python
from tvm_ffi.utils.lockfile import FileLock

lock = FileLock("/tmp/my.lock")
assert lock.acquire() is True   # First acquire succeeds
assert lock.acquire() is False  # Second acquire returns False (already held)
lock.release()
```

### Multi-process mutual exclusion (from test)
```python
# filelock_worker.py (run as subprocess)
from tvm_ffi.utils.lockfile import FileLock

with FileLock(lock_path):
    # Critical section: read-modify-write a shared counter file
    with open(counter_file) as f:
        current_value = int(f.read().strip())
    time.sleep(random.uniform(0.01, 0.1))  # Simulate work
    with open(counter_file, "w") as f:
        f.write(str(current_value + 1))
```
